## Background

The project's documents and outputs follow a small normative vocabulary, and several of its rules are mechanical
enough to check on every change. Without a check they decay: a number loses its label, a tested result gets
called "verified", a formula arrives in a markup the reader's terminal cannot render.

Five labels say what kind of statement a sentence is (DESIGN; the labels are the project's own):

| Label | Meaning | Who may change it |
|---|---|---|
| FACT | Observed in a sibling repository, on a named machine, or in a cited public source. Code facts cite `repo/path`; web facts cite an entry of the source register | New evidence only |
| DESIGN | A decision of this project, carrying its reason | An architecture decision record (ADR) |
| HYPOTHESIS | Believed, not established; names the test that would confirm or kill it | The named test |
| TARGET | A number we intend to hit; not a measurement until a gate records the measured value | The gate that measures it |
| OPEN | Undecided; has an owner, a deadline expressed as the gate it blocks, and a fail-closed default | The owner |

MUST, MUST NOT, SHOULD and MAY carry their RFC 2119 meanings. Three rules govern numbers from outside the
repository: (1) an external number is a FACT about its source, not about this system, and is registered in the
source register with its URL or path, the version or tag it was read at, how it was read (raw text, a rendered
figure read by eye, or a derivation from published inputs) and the flag "to be re-read from the primary source
before a gate cites it"; (2) a reported defect in a foundation that this program has not reproduced at a pinned
commit is written "FACT (to recheck)" and becomes an admission test and an upstream work item before anything
depends on it; (3) no number is written as a result: a ratio, rate or coverage figure describing this system is
a TARGET, or a HYPOTHESIS with the range the evidence supports, and headline multipliers do not appear.

Two wording rules complete the set. The word "verified" is not used for results anywhere, in documents or in
product output: a result is proved, certified, tested or estimated, and says which. Mathematics is written in
Unicode, never LaTeX, and every symbol is defined in the conventions document or the mathematics compendium.

Rejected alternative: a style guide with no check. An optimizing agent will find any path by which a statistical
result can be reported as a proof, and a rule that lives only in prose is such a path. Rejected alternative: a
seventh `xtask` subcommand; `xtask` has a hard scope of six checks, so the lint is an ordinary test.

## Scope

In: one test binary with six lints and their allow-list file; the fixtures that prove each lint can fail. This
bead owns the one static scan for the banned word (L-VERIFIED) over every string the product can emit that is
known before run time, including the generated verb help, the output schemas and `robot-docs`; and the one
detector of FACT statements that name an outside source (L-SOURCE), which checks only that a citation is
present.

Out, and where it is:
- resolving a citation against `registries/sources.toml`, and grading it (does the source exist, may its
  reading be cited by a gate, has a plan-time check been reproduced): the citation lint NAB-10, which consumes
  the list of sites that L-SOURCE exports and depends on this bead;
- the two Proof wordings and their single formatter, the receipt check INV-LEMMA-01 on exports, the non-claims
  scope block, and the dynamic scan for the banned word over captured end-to-end output of the prove cluster:
  N12-08, which uses this bead's matcher and adds no second pattern;
- the permitted wordings of the seven claims in reports (N00-25); the differentiator wordings and withdrawn
  claims (N00-15); the `reality:` line (BD-139); the ten-section contract check (`xtask check-contracts`,
  N34-08).

## Technical approach

Test binary `crates/frob-conformance/tests/doc_lints.rs`, run by `cargo test -p frob-conformance --test
doc_lints`. Inputs, in two sets. Project prose: every `CONTRACT.md`, `README.md`, and the files under `docs/`
(except `docs/derivations/` raw transcripts and `docs/delivery/`). Product strings (everything the product can
emit that is known statically): the report templates of `frob-verbs`, the message strings of
`registries/refusals.toml`, the verb help and descriptions generated from `registries/verbs.toml`, the
descriptions and examples of every output schema, the `robot-docs` output, and the `--help` text snapshot of
every binary. Allow-list: `crates/frob-conformance/lints/allow.toml`, each entry with file, line pattern, lint
id and a one-line reason; an entry that matches nothing is itself an error (no dead exemptions).

1. **L-LABEL (numbers carry labels).** For each numeric literal with a unit, a percentage, a ratio written `n×`
   or a count above 12 in prose: pass if the enclosing sentence or its table header carries one of FACT, DESIGN,
   HYPOTHESIS, TARGET, OPEN, or the paragraph opens with a label that scopes it ("Labels: thresholds here are
   TARGETs"), or the token is inside a code block, an identifier, a version, a date, a section number or a
   schema name. Otherwise report file, line, the token and the nearest header.
2. **L-RESULT (no number written as a result).** In sentences whose subject is this system (matches of `frob`,
   `FrankenRobotics`, "our", "we" with a performance verb), a number labelled FACT must cite a gate record
   identifier (`registries/gates.toml` row with status `pass`); otherwise the label must be TARGET or
   HYPOTHESIS. Headline multipliers ("10x faster", "an order of magnitude faster") without a gate record are
   errors.
3. **L-SOURCE (external figures carry a citation).** Every FACT that names an external product, paper or
   benchmark must carry a citation in a form the citation lint recognises (`[SRC-…]` or `[SRC-…#figure]` after
   the statement in prose; a `sources` field in a registry record). L-SOURCE checks presence and form only, and
   reports a site with no citation token. It exports `fact_sites(tree) -> Vec<FactSite>` (file, line, the
   statement, its citation tokens), the single detector of such statements. Whether a cited id exists in
   `registries/sources.toml`, and whether a source whose `reread_before_gate` flag is still true is being cited
   from a row of `registries/gates.toml` (it may be cited in prose and by a hypothesis, not by a recorded gate),
   are findings of the citation lint NAB-10 (`cite.unknown-source`, `cite.needs-reading`,
   `cite.pass-on-unread`), which reads `fact_sites`; they are not reported here (DESIGN: one place grades
   citations, so that a gate row is never refused by two lints under two rules).
4. **L-VERIFIED (the banned word).** The one pattern for the rule, used by every scan for it (DESIGN):
   case-insensitive match of the word stem `verif` used of a result ("verified", "verification passed",
   "verifies that"). It runs over both input sets. Exempt by construction, because they are different tokens:
   the binary name `frob-verify`, the verb `prove.verify`, the sibling command `verify-capsule`, and other
   identifiers; in project prose only, the phrase "is not used" in the rule's own statement. In product strings
   the whole word "verified" has no permitted occurrence, not even in a negation, and no allow-list entry may
   exempt one (the allow-list loader rejects an `L-VERIFIED` entry whose file is in the product-string set).
   The fix offered in the message is the permitted vocabulary: proved, certified, tested, estimated. The
   matcher is exported as `banned_word::find(text) -> Vec<Match>` so that the dynamic scan over captured
   end-to-end output (N12-08) applies the same pattern. Rejected: a second test that matches only the whole
   word "verified" (drafted beside this lint, withdrawn): it misses "verification passed", and two scans with
   two patterns would disagree about one rule.
5. **L-UNICODE (no LaTeX).** Reject `$…$`, `\(`, `\[`, `\frac`, `\sum`, `\mathbb` and similar control sequences
   outside code blocks. Report the Unicode replacement where a table exists (`\alpha` → α, `\le` → ≤).
6. **L-TORECHECK.** Every occurrence of "FACT (to recheck)" must name an admission gate (`INT-…`) or an upstream
   work item (`FD-…`) in the same paragraph.

Output: one diagnostic per finding as `path:line: lint-id: message`; exit non-zero on any finding not in the
allow-list. Determinism class D0 (pure text processing; files visited in sorted order). The lint writes nothing
to the ledger; its result is a test result.

## Acceptance criteria

- [ ] `cargo test -p frob-conformance --test doc_lints` passes on the clean tree and fails on each of the six
      planted fixtures below, naming the right lint and line.
- [ ] The lint reads the `--help` snapshot of every binary target of the workspace graph, the set taken from
      `cargo metadata` and not from a list written here (at M0 `frob`, `frobd`, `frob-mcp` and `frob-verify`;
      `frob-tui` from the day it exists), the verb help generated from `registries/verbs.toml`, the output
      schemas' descriptions and examples and the `robot-docs` output, so that tool output is covered and not only
      documents; a binary target with no snapshot fails the test, so a binary added later cannot escape it.
- [ ] L-VERIFIED finds zero occurrences across verbs, schemas, refusals, `robot-docs` and `frob-verify --help`;
      a planted occurrence in a refusal text is caught, and an allow-list entry that tries to exempt it is
      rejected.
- [ ] L-SOURCE reports only a missing citation; a FACT that cites an unknown source id passes this test and
      fails the citation lint (NAB-10).
- [ ] The allow-list has no entry that matches nothing.
- [ ] The whole run takes at most 5 s on a warm tree (TARGET), so that it is run and not skipped.
- [ ] The honesty clause of the definition of done can cite this test for "the word verified describes no
      result".

## Test plan

### Unit tests
In `doc_lints.rs`, on fixture files under `crates/frob-conformance/lints/fixtures/` (labelled `synthetic`):
`label_missing_on_throughput_number` ("runs 8,192 worlds at 2.5 M steps/s" with no label → L-LABEL);
`label_from_table_header_accepted` (a column headed "Threshold (TARGET)"); `result_without_gate_record`
("FACT: frob trains in 300 s" with no gate id → L-RESULT); `headline_multiplier_rejected` ("10x faster than
MuJoCo"); `external_fact_without_citation` (→ L-SOURCE); `fact_sites_lists_citation_tokens` (a FACT citing
`[SRC-PUB-027#mixed-batch-ratio]` is exported with that token and is not a finding here);
`verified_in_report_template` ("status: verified" → L-VERIFIED); `planted_word_in_refusal_text_is_caught`;
`product_string_allow_entry_rejected`; `negated_use_in_schema_description_is_caught` ("not verified" in an
output schema's description); `frob_verify_binary_name_exempt` (with `prove.verify` and `verify-capsule`); `latex_fraction_rejected` (`\frac{1}{1-s}` → L-UNICODE, suggesting 1/(1 − s));
`to_recheck_without_gate`; `dead_allow_entry_is_error`.

### End-to-end script and logging
`scripts/e2e/doc_lints.sh` builds the help snapshots with the real binaries, runs the test, then copies the tree
to a scratch directory, applies each planted defect in turn and asserts a non-zero exit with the expected lint
id. Logged per STD-E2E: one `cmd` line per run with exit code and wall time; one `assert` line per plant with
lint id, file and line; a `summary` with plants caught out of six.

### Known answers and negative controls
Negative controls (registered in the control registry against this test): the six planted fixtures; a mutant
lint whose `verif` pattern is anchored to whole-word "verified" only, which must miss "verification passed" and
therefore fail the fixture; a document whose only label sits in a different section, which must not be accepted
as scoping. Determinism: twice on one machine and on Linux and macOS, identical diagnostics.

## Considerations

- False positives are the main risk; the allow-list with reasons is the release valve, and its size is printed
  on every run so growth is visible.
- The lint checks form, not truth: a wrongly labelled number passes. Truth is the business of gates.
- Imported text (scene names, design comments) is data, not project prose, and is outside the lint.
