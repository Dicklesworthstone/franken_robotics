## Background

Agents coordinate through identifiers: a gate number in a commit message, a refusal code in a script, a
known-answer number in a test name. If an identifier is ever renumbered or reused, every record that cited it
silently changes meaning. The rule is therefore absolute: identifiers are never renumbered; a retired identifier
is tombstoned, not reused; new identifiers continue each series.

`frob-core` (identities and hashing, evidence classes, the claim-product type, refusals, schema versions, units
glue) belongs to no subsystem and sits under all of them. `frob-units` exists only if the toolchain admission
gate forces it. `surface/frob-mcp` is a member of the core workspace; `spark/`, `derive/`, `bindings/`,
`viewer/` and `lean/` are separate workspaces or projects.

## Scope

In: the two tables as data, the lint that enforces append-only identifiers with tombstones, and the check that
every workspace crate maps to exactly one subsystem (or to none, for `frob-core`, `frob-units` and `xtask`
support code). Out: the content of any registry; layer rules (`xtask check-layers`); the register-versus-chapter
threshold lint.

## Technical approach

1. **Data.** `registries/identifiers.toml`: the prefix table (`prefix`, `meaning`, `registry` = the file that is
   authoritative for the series, `pattern` = a regular expression) and a `[[tombstone]]` list (`id`, `retired`,
   `reason`, `replaced_by`). `registries/subsystems.toml`: `name`, `context`, `crates`, `gate_code`. Readers: the
   lint below, the `robot-docs` generator (which prints the subsystem table for agents) and the bead label
   vocabulary. If those readers go away the files are deleted.
2. **Append-only lint** (`crates/frob-conformance/tests/identifiers.rs`). For every series whose registry is a
   file in the repository (gates, admission and kill gates; known answers; counterexamples; controls; refusal
   codes; formats; verbs):
   a. load the identifiers at `HEAD` and at the merge base with the main branch (`git show`), keyed by
      identifier with a digest of the record's defining fields (for a gate: claim and subsystem; for a refusal:
      meaning; for a known answer: case and truth);
   b. an identifier present before and absent now must appear in the tombstone list, else error `removed`;
   c. an identifier whose defining digest changed must carry a dated amendment note in its record, else error
      `redefined`;
   d. a new identifier must not equal a tombstoned one, else error `reused`;
   e. every identifier must match its series pattern, and gate codes must come from the subsystem table.
3. **Crate map check.** Parse the workspace manifests; every member crate appears in exactly one subsystem's
   `crates` list or in the `no-subsystem` list; a crate in two lists or none is an error.
4. **Citations resolve.** A scan of `docs/`, contracts and registries for tokens matching any series pattern;
   each must exist in its registry or tombstone list. A citation of a tombstoned identifier prints a warning
   with `replaced_by`.

Determinism D0; files and identifiers visited in sorted order.

## Acceptance criteria

- [ ] Both registries validate; the prefix table has the 28 series above; the subsystem table has 23 rows.
- [ ] Removing a gate record without a tombstone, changing a refusal's meaning without an amendment note, and
      reintroducing a tombstoned known-answer number each fail the lint with `removed`, `redefined`, `reused`.
- [ ] A workspace crate missing from the subsystem map fails the check.
- [ ] A document citing `GATE-SPARK-99` (unregistered) fails with the file and line.
- [ ] The test runs in at most 5 s on a warm tree (TARGET).

## Test plan

### Unit tests
`removed_without_tombstone`; `tombstoned_removal_passes`; `redefinition_needs_amendment`;
`reuse_of_tombstoned_id_rejected`; `gate_code_not_in_subsystem_table` (`GATE-FOO-01`);
`crate_in_two_subsystems_rejected`; `unresolved_citation_reported`; `series_numbers_may_have_gaps_but_not_swaps`
(two known-answer rows exchanged → `redefined` twice).

### End-to-end script and logging
`scripts/e2e/identifiers.sh` creates a scratch clone, applies each planted change as a commit, runs the test and
asserts the expected error class. Logged per STD-E2E: the commit under test, the command, exit code, the
identifier and error class per `assert` line, and a `summary` with plants caught out of five.

### Known answers and negative controls
Controls: the five plants above; a mutant lint that compares identifier sets but not defining digests, which
must miss the swap of two rows and so fail `series_numbers_may_have_gaps_but_not_swaps`. Determinism: identical
on Linux and macOS.

## Considerations

- The lint needs repository history; in an export without history it runs in "snapshot" mode (patterns, crate
  map and citations only) and says so.
- An amendment to a gate's threshold is legitimate only as a dated change made before the measurement it
  governs; the lint enforces the note, the exit review enforces the timing.
- Names are handles, not architecture: the crate map and layer rules live with the workspace checks.
