## Background

An earlier draft of the design listed eight "fossils" of robot simulation: things incumbents supposedly could
not do. The incumbent audit showed that several described incumbents wrongly. What is kept is narrower and
sourced: only what an incumbent's own documentation states as absent or limited, quoted or cited, with what this
project does about it and the condition that must hold before the project may say so. A second, weaker list
holds what was simply not found after a bounded search; each such item is an absence of evidence, none is
called a gap in an incumbent, and each gets a line in the M0 audit that tries again with the software installed.

**Documented as absent or limited (each row a FACT about its source).**

| Stage | What incumbents document as absent or limited | Where | What this project does, and the condition on claiming it |
|---|---|---|---|
| Replay | Bitwise agreement between a CPU run and a GPU run. **Not found after a bounded search (eleven items; absence of evidence only).**

1. Checked certificates attached to the kernels of a GPU engine, or enclosures of simulated quantities.
2. Pre-simulation design analyses built into an engine (static sizing toolkits for serial arms exist outside
   engines).
3. A promotion rule between solvers or tiers, or a cross-tier disagreement ledger.
4. A generator for manufacturing plants or for commercial kitchens.
5. An integrated GPU tool for rare-event or adversarial failure search (research methods exist).
6. Structural analysis, topology optimization or fatigue inside an agent's design loop (one co-design framework
   has an automated finite-element filter).
7. A published latency from a topology edit to the first GPU step.
8. A published end-to-end phase ledger of a design loop on the late-2026 software stack.
9. A published rank agreement between a shared policy and per-design specialists.
10. A published ten-fold gain in end-to-end time to a qualified legged-robot design against a comparable
    baseline.
11. A rigid-body throughput figure for the one Metal-capable incumbent on Apple silicon.

## Scope

In: the two lists as data, and the re-audit procedure that turns each row into an executed check or a second
documented search with its date. Out: the phase-ledger measurements themselves (BD-040, BD-142, BD-143); the
incumbent harness (BD-039).

## Technical approach

1. Records in `crates/frob-conformance/registry/incumbent_audit.toml` (the file of N00-13):
   `[[documented_absence]]` (`id` `DA-01` … `DA-12`, `stage`, `quote`, `sources`, `versions`, `our_mechanism`,
   `claim_condition` as gate identifiers, `binds`) and `[[not_found]]` (`id` `NF-01` … `NF-11`, `item`,
   `search` = where and how the search was bounded, `date`).
2. **Re-audit with execution** (one script per row under `tools/oracle/audit/`, run on `trj` through the
   incumbent harness at the pinned releases; results appended as `m0_record`):
   - DA-01: run one batch on the incumbent's CPU device and on CUDA with its determinism mode on; record whether
     per-world state digests agree, and the first divergence step if not.
   - DA-02: run one world alone and inside batches of 2, 64 and 4,096; record the maximum state difference.
   - DA-03: run the same batch twice on the engine documented as non-deterministic; record whether digests
     differ.
   - DA-04: attempt a heterogeneous batch on each incumbent that documents one, with its deterministic solver
     where available; record whether it runs, and whether two runs agree bitwise.
   - DA-05: read the incumbent's energy outputs on a constrained bounce; record the unaccounted residual.
   - DA-06 and NF-11: install the Metal-capable incumbent on the Mac and measure rigid-body throughput on the
     reference quadruped workload under the disclosure block.
   - DA-07 to DA-12: re-read the documentation at the installed version and record the quote and its location,
     or the change.
   - NF-01 to NF-10: repeat the search against the installed packages (API listing, documentation search) and
     the literature index, record the query set and the result. NF-07 and NF-08 are closed by measurement: the
     edit-to-first-step latency and the end-to-end phase ledger are measured by the baseline beads and their
     records are linked here.
3. **Outcome rule.** A row whose re-audit contradicts it (the incumbent does the thing) is marked `withdrawn`
   and every differentiator wording that leaned on it is corrected through N00-15 before M0 exits. A row that
   stands keeps its claim condition. A `not_found` item that is found becomes a row of the capability register
   (N00-13). "Not found" never becomes "absent" in any text.
4. The third candidate differentiator for mixed batches (run-to-run replay and forks inside a mixed batch) may
   be claimed only after DA-04 has run the incumbent's deterministic solvers on a heterogeneous batch and found
   them unable to do it.

## Acceptance criteria

- [ ] Twelve documented-absence records and eleven not-found records load with sources and dates.
- [ ] After M0, each of the 23 records carries an `m0_record` (an execution record or a dated second search)
      and a status of `stands`, `withdrawn` or `not-executable` with the reason.
- [ ] Every withdrawn row has a matching correction in the wording registry in the same change.
- [ ] GATE-TENFOLD-01's rival-audit part is evaluable: the audit is complete when no record lacks its
      `m0_record`.
- [ ] No document in the tree states a not-found item as a gap of a named incumbent (claims lint).

## Test plan

### Unit tests
`crates/frob-conformance/tests/incumbent_absences.rs`: `twelve_and_eleven_records`;
`claim_condition_names_existing_gates` (DA-01 → GATE-SPARK-01, GATE-SPARK-02);
`withdrawn_row_requires_wording_change`; `not_found_stated_as_gap_is_flagged` (planted sentence "Newton has no
promotion rule" → NF-03); `mixed_batch_replay_claim_blocked_until_da04_record`.

### End-to-end script and logging
`scripts/e2e/incumbent_reaudit.sh` (on `trj`, and on the Mac for DA-06 and NF-11) runs each audit script
through the harness and appends its record. Logged per STD-E2E: row id, incumbent, release pin and container
digest, command, exit code, the measured quantity with unit (digest equality, maximum difference, throughput
with its disclosure block), status; `summary` with stands, withdrawn and not-executable counts and gate
GATE-TENFOLD-01.

### Known answers and negative controls
Expected documentary anchors: the batch-independence tolerance 10⁻⁵–10⁻⁴ (DA-02); the quoted non-determinism
answer (DA-03). Negative controls: a re-audit script that reports `stands` without running the incumbent (the
record must carry a process exit code and a container digest, else it is rejected); a planted differentiator
sentence that leans on a withdrawn row.

## Considerations

- The re-audit needs the incumbents installed under their licences on `trj`; a row whose incumbent cannot be
  installed is `not-executable` and its claim condition is not met.
- Documentation and behaviour can disagree in both directions; the executed result governs, and the quote stays
  in the record as history.
- Hardware differs from some published rows; such rows are re-measured on the RTX 4090 and recorded as a new
  figure, never silently substituted.
