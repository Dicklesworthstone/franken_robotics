## Background

After the incumbent audit, thirteen claimed differentiators were withdrawn and thirteen were reworded with
their conditions. What remains is a short list in which each wording is the most the audited evidence supports,
and it is the only wording the project's documents, the product's documentation and any public description may
use. A condition in brackets appears with the claim until the named gate has passed. The capabilities of the
mission engine, the adversary, the debugger, the reality lane and the workshop lane are claimed as functions of
the product and not as firsts; their only comparative claim is N13.

**Withdrawn claims (not to be stated anywhere; the reason for each is the audit row that contradicts it).**

1. Deterministic GPU replay as such. Two incumbents document opt-in bitwise run-to-run determinism.
2. "The CPU version is a different code base." One kernel compiler emits CPU and CUDA code from one source, and
   one engine runs on its CPU device.
3. Different robot topologies in one GPU batch, as a capability. One environment suite and two solvers of one
   engine document it.
4. The combination of mixed topologies, determinism and articulated contact as an incumbent gap. One
   experimental solver documents all three, and its tests exercise the combination on small chains.
5. Electrical and thermal actuator modelling as a novelty.
6. "No training needed" for baseline control.
7. Anytime-valid comparison as a novelty of the field.
8. One kernel source for several backends, and simulation on several tiers, as novelties.
9. Apple-GPU support as a first.
10. Interior scenes for homes, kitchens, retail stores and warehouses as a novelty.
11. An agent interface to a simulator as such.
12. An earlier humanoid throughput target as parity, and its note that no absolute incumbent figure was found.
    Published figures exist and the target was about five times below one of them.
13. Any ten-fold claim that rests on per-step throughput, on sampling control as the evaluator, or on a
    published ten-fold in time to a qualified design. None is supported.
14. "Morphology is fixed before the simulator starts." State-preserving recompilation on the CPU contradicts it.
15. That an imported model with an impossible inertia "loads without complaint" everywhere. One incumbent's
    compiler rejects physically impossible inertias.
16. That an incumbent loop teaches an agent its mistake "six hours later". Published training takes about seven
    minutes for a flat-ground quadruped task, under 15 to 30 minutes for humanoids, and about an hour for a
    default rough-terrain humanoid run.

## Scope

In: `registries/claims_wording.toml` with both lists, the generator that renders the permitted wordings (with
or without their bracketed condition, from gate status) into the README and `robot-docs`, and the lint. Out: the
seven claim kinds and report wordings (N00-25); the hypothesis register's banned strong forms (N00-10).

## Technical approach

1. **Data.** `[[differentiator]]`: `id`, `title`, `wording` (the exact sentence), `condition` (text),
   `condition_gates` (gate identifiers; all must be `pass`, or the associated bet `held`, for the bracket to
   drop), `prior_art` (the concession that must accompany the claim), `binds`, `requires_number` (N10, N11: the
   claim is rendered only with the measured values and their disclosure block). `[[withdrawn]]`: `n`,
   `statement`, `patterns` (regular expressions catching paraphrases), `contradicted_by` (rows of N00-13 or
   N00-14).
2. **Rendering.** `fn render(id, gates) -> String` returns the wording followed by its bracketed condition while
   any condition gate is not `pass`; for a killed gate it returns the fallback wording recorded in the kill
   decision (for N6 under KILL-D1: the bit-for-bit sentence is withdrawn for the affected device family and
   replaced by "the CPU run is a tolerance replay"); for `requires_number` with no record it returns nothing.
   The README's comparison section and the first page of `robot-docs` are generated only through this function
   (`xtask check-generated`).
3. **Lint** (`crates/frob-conformance/tests/claims_wording.rs`), over documents, help text, report templates and
   release notes:
   a. a sentence matching a withdrawn pattern is an error, with the withdrawn item quoted;
   b. a comparative sentence (matches of "first", "only", "unlike", "no other", "novel", a named incumbent with
      "cannot" or "does not") must be a rendering of a registered differentiator, verbatim, with its concession
      and its current bracket;
   c. a differentiator rendered without its bracket while a condition gate is not `pass` is an error;
   d. the words "no training needed" are an error everywhere.
4. **Change rule.** A wording changes only by appending a new version with the audit or gate record that
   justifies it; the previous wording stays in the file's history list.

## Acceptance criteria

- [ ] Thirteen differentiators and sixteen withdrawn claims load; every `condition_gates` entry exists in the
      gate registry.
- [ ] At M0 the README renders N5, N6, N7, N8 and N13 with their brackets, and N10 and N11 are absent (no
      numbers yet).
- [ ] Each of the sixteen withdrawn statements, pasted into a scratch document, is flagged.
- [ ] A comparative sentence that is not a registered rendering is flagged.
- [ ] When a scratch gate registry marks GATE-SPARK-01, -02 and -15 `pass`, N6 renders without its bracket; when
      it marks KILL-D1 fired for the Metal family, N6 renders the tolerance-replay sentence for that family.

## Test plan

### Unit tests
`claims_wording.rs`: `thirteen_and_sixteen`; `n6_bracket_until_three_gates_pass`; `n6_under_kill_d1`;
`n10_absent_without_measurement`; `n7_never_says_no_training_needed`; `withdrawn_1_to_16_each_flagged` (sixteen
fixtures); `unregistered_first_claim_flagged` ("the first simulator with an MCP interface" → withdrawn 11 and
rule b); `concession_must_accompany_n1` (N1 without "prior art (Warp, Genesis)" is flagged).

### End-to-end script and logging
`scripts/e2e/claims_wording.sh` generates the README section from three scratch gate registries (all open; the
N6 gates passed; KILL-D1 fired) and diffs the renderings against expected text, then runs the lint over planted
documents. Logged per STD-E2E: differentiator id, gate statuses read, the rendered sentence digest, findings
with file and line; `summary` with renderings checked and plants caught.

### Known answers and negative controls
Negative controls: the sixteen withdrawn sentences; a README edited by hand to drop the N5 bracket; a mutant
renderer that drops brackets when any (rather than every) condition gate passes. No numeric known answers.

## Considerations

- The registry governs public description as well as internal documents; marketing text is in scope.
- N11's two numbers are meaningful only against a named incumbent configuration measured on `trj`; the
  rendering includes that configuration.
- If the composed incumbent ties on a stratum, N13 is rendered with that statement for the stratum (BET-14).
