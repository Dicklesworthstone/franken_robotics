## Background

After the incumbent audit, thirteen claimed differentiators were withdrawn and thirteen were reworded with
their conditions. What remains is a short list in which each wording is the most the audited evidence supports,
and it is the only wording the project's documents, the product's documentation and any public description may
use. A condition in brackets appears with the claim until the named gate has passed. The capabilities of the
mission engine, the adversary, the debugger, the reality lane and the workshop lane are claimed as functions of
the product and not as firsts; their only comparative claim is N13.

**Withdrawn claims (not to be stated anywhere; the reason for each is the audit row that contradicts it).**

1. Deterministic GPU replay as such. Two incumbents document opt-in bitwise run-to-run determinism.
2. "The CPU version is a different code base." One kernel compiler emits CPU and CUDA code from one source, and
   one engine runs on its CPU device.
3. Different robot topologies in one GPU batch, as a capability. One environment suite and two solvers of one
   engine document it.
4. The combination of mixed topologies, determinism and articulated contact as an incumbent gap. One
   experimental solver documents all three, and its tests exercise the combination on small chains.
5. Electrical and thermal actuator modelling as a novelty.
6. "No training needed" for baseline control.
7. Anytime-valid comparison as a novelty of the field.
8. One kernel source for several backends, and simulation on several tiers, as novelties.
9. Apple-GPU support as a first.
10. Interior scenes for homes, kitchens, retail stores and warehouses as a novelty.
11. An agent interface to a simulator as such.
12. An earlier humanoid throughput target as parity, and its note that no absolute incumbent figure was found.
    Published figures exist and the target was about five times below one of them.
13. Any ten-fold claim that rests on per-step throughput, on sampling control as the evaluator, or on a
    published ten-fold in time to a qualified design. None is supported.
14. "Morphology is fixed before the simulator starts." State-preserving recompilation on the CPU contradicts it.
15. That an imported model with an impossible inertia "loads without complaint" everywhere. One incumbent's
    compiler rejects physically impossible inertias.
16. That an incumbent loop teaches an agent its mistake "six hours later". Published training takes about seven
    minutes for a flat-ground quadruped task, under 15 to 30 minutes for humanoids, and about an hour for a
    default rough-terrain humanoid run.

## Scope

In: `registries/claims_wording.toml` with both lists, the generator that renders the permitted wordings (with
or without their bracketed condition, from gate status) into the README and `robot-docs`, the lint, and the
list of rule sets that other beads register to run on the same documents. Out: the seven claim kinds and
report wordings (N00-25); the hypothesis register's banned strong forms (N00-10); the rules for where the word
"ten-fold" and a ratio of times against a rival may appear (ten rules keyed to the verdict of a cited report
cell), the citation syntax `[tenfold:<gate>/<stratum>/<regime>]`, the tool `frob-tenfold lint-wording` and the
limits block that every report of the ten-fold test prints (N39b-15, M3, which depends on this bead and is
registered here as the rule set `tenfold-wording`). This bead's lint decides which comparative sentences may
exist at all (registered differentiators, withdrawn claims); that rule set decides which words a measured
ten-fold result has earned. Neither repeats the other's rules.

## Technical approach

1. **Data.** `[[differentiator]]`: `id`, `title`, `wording` (the exact sentence), `condition` (text),
   `condition_gates` (gate identifiers; all must be `pass`, or the associated bet `held`, for the bracket to
   drop), `condition_rows` (re-audit row identifiers of N00-14 whose record must read `stands` before the part
   of the wording they guard is rendered: N11's third candidate, run-to-run replay and forks inside a mixed
   batch, is rendered only once DA-04 stands with a record showing the incumbent's deterministic solvers unable
   to do it; its two numbers need GATE-PHYLUM-03's record), `prior_art` (the concession that must accompany the
   claim), `binds`, `requires_number` (N10, N11: the claim is rendered only with the measured values and their
   disclosure block). `[[withdrawn]]`: `n`, `statement`, `patterns` (regular expressions catching paraphrases),
   `contradicted_by` (identifiers of the rows that contradict it: `IA-nn` of the capability register N00-13,
   `DA-nn` or `NF-nn` of N00-14, or a key of `registries/sources.toml` where neither register has a row). The
   initial mapping (DESIGN; the plan names the contradicting rows only in aggregate): 1 → IA-03; 2 → IA-11;
   3 → IA-04; 4 → IA-03, IA-04; 5 → IA-10; 6 → IA-08; 7 → IA-13; 8 → IA-11, IA-12; 9 → IA-15; 10 → IA-16;
   11 → IA-17; 12 → IA-02; 13 → IA-02, IA-08, IA-19, NF-10; 14 → IA-06; 15 → the source key of the incumbent
   compiler documentation that rejects physically impossible inertias (no register row covers it); 16 → IA-01.
   When N00-14 marks a row `withdrawn`, the items citing it are reviewed under the change rule (step 4).
   Order of work (DESIGN): the `DA-` and `NF-` tables are written into the same file by N00-14, which corrects
   wordings through this registry and therefore depends on this bead, not the reverse. Until those tables exist
   an identifier with one of those two prefixes resolves as `pending` (a warning naming N00-14), and the guarded
   part of a wording (`condition_rows`) is not rendered; the M0 exit treats a `pending` reference as an error,
   so the two beads are both done before M0 exits. An `IA-` reference never reads `pending`.
   `[[conditioned_phrase]]` (DESIGN): a phrase that may appear only under a recorded decision. Fields: `id`,
   `owner` (the bead that enters the row), `patterns` (regular expressions for the phrase and its paraphrases),
   `reader` (a command that prints the decision in force as one JSON object), `field` (the key read from it),
   `allowed` (the values under which the phrase may appear), `also_gates` (gate identifiers that must also be
   `pass`), and `scoped_form` (optional: a sentence template with `{…}` fields filled from the reader's object,
   allowed under the values the row lists for it). The registry holds the rows; their owners enter them: the
   two rows for the repository-visibility decision (N41-05, M0) and the two for the adjudication record (N41-06,
   M2). A row whose `reader` is absent or fails is treated as the least permissive value: the phrase is
   refused.
   `[[rule_set]]` (DESIGN): `id`, `owner` (the bead that defines the rules), `command` (what the
   wording check runs), `paths` (the documents it scans), `since` (the milestone from which it must run). A
   rule set is a second lint with its own rules that the wording check runs on the same documents; the registry
   holds its registration, not its rules. The first is `tenfold-wording` (owner N39b-15, command
   `frob-tenfold lint-wording`, since M3). From its `since` milestone a registered rule set whose command is
   missing fails the check.
2. **Rendering.** `fn render(id, gates) -> String` returns the wording followed by its bracketed condition while
   any condition gate is not `pass`; for a killed gate it returns the fallback wording recorded in the kill
   decision (for N6 under KILL-D1: the bit-for-bit sentence is withdrawn for the affected device family and
   replaced by "the CPU run is a tolerance replay"); for `requires_number` with no record it returns nothing.
   The README's comparison section and the first page of `robot-docs` are generated only through this function
   (`xtask check-generated`).
3. **Lint** (`crates/frob-conformance/tests/claims_wording.rs`), over documents, help text, report templates and
   release notes:
   a. a sentence matching a withdrawn pattern is an error, with the withdrawn item quoted;
   b. a comparative sentence (matches of "first", "only", "unlike", "no other", "novel", a named incumbent with
      "cannot" or "does not") must be a rendering of a registered differentiator, verbatim, with its concession
      and its current bracket;
   c. a differentiator rendered without its bracket while a condition gate is not `pass` is an error;
   d. the words "no training needed" are an error everywhere.
   e. every registered rule set is run on its paths, and its refusals are reported with this lint's.
   f. a match of a `[[conditioned_phrase]]` pattern is an error naming the row, unless the value its `reader`
      prints for `field` is one of `allowed` and every gate of `also_gates` is `pass`, or the sentence is the
      row's `scoped_form` rendered from the reader's object under a value the row lists for it;
   g. a sentence for which N00-13's `prior_art::presented_as_new` names a record (a topic already solved
      elsewhere, presented as new) is an error naming that `[[prior_art]]` record and its sources.
   One text is read by both this lint and the rule set `tenfold-wording`, and the two must agree on it
   (DESIGN): the bracket of N13, "[Hypothesis until the ten-fold report.]", contains a term that rule set
   refuses in a claim before the word is earned. A sentence that is byte-identical to a current rendering of a
   registered differentiator (its wording, concession and current bracket, as `render` returns it) is
   registered text: the rule set skips it, reading the list of current renderings from this registry. The
   bracket says the claim is not yet earned, which is the opposite of the claim the rule set guards against.
   Any other sentence containing those terms is judged by the rule set, and withdrawn claim 13 still applies
   to a ten-fold sentence that rests on per-step throughput, with or without a citation.
4. **Change rule.** A wording changes only by appending a new version with the audit or gate record that
   justifies it; the previous wording stays in the file's history list.

## Acceptance criteria

- [ ] Thirteen differentiators and sixteen withdrawn claims load; every `condition_gates` entry exists in the
      gate registry; every `contradicted_by` entry resolves to an `IA-`, `DA-` or `NF-` record of
      `incumbent_audit.toml` or to a source key, and no withdrawn item has an empty `contradicted_by`. Before
      N00-14's tables exist a `DA-` or `NF-` reference reads `pending` and the load passes with a warning; in
      exit mode a `pending` reference fails (`FROB_EXIT=M0 cargo test -p frob-conformance --test
      claims_wording`, the mode the M0 exit review runs; an environment variable, since a test target rejects an
      option it does not know).
- [ ] The registry loads with its `[[conditioned_phrase]]` table (empty until N41-05 enters its rows). With a
      `synthetic` row (pattern "plugh confirmed", a scratch reader printing `{"option": "A"}`, `allowed =
      ["C"]`): the phrase is flagged; with the reader printing `C` it is not; with `also_gates` naming an open
      gate it is flagged again; with the reader missing it is flagged; its `scoped_form` is accepted only under
      the value listed for it.
- [ ] With DA-04 not yet `stands`, N11 renders (when its numbers exist) without the mixed-batch replay sentence;
      with a scratch record setting DA-04 `stands`, the sentence appears.
- [ ] At M0 the README renders N5, N6, N7, N8 and N13 with their brackets, and N10 and N11 are absent (no
      numbers yet).
- [ ] Each of the sixteen withdrawn statements, pasted into a scratch document, is flagged.
- [ ] A comparative sentence that is not a registered rendering is flagged.
- [ ] The registry loads with its `[[rule_set]]` table (empty at M0); a scratch registry with the rule set
      `tenfold-wording` registered and a stub command present runs it on its paths, and with the command
      absent at or after its `since` milestone the check fails. The current renderings, N13's with its
      bracket among them, are exported as the list of registered text that a rule set skips.
- [ ] When a scratch gate registry marks GATE-SPARK-01, -02 and -15 `pass`, N6 renders without its bracket; when
      it marks KILL-D1 fired for the Metal family, N6 renders the tolerance-replay sentence for that family.

## Test plan

### Unit tests
`claims_wording.rs`: `thirteen_and_sixteen`; `n6_bracket_until_three_gates_pass`; `n6_under_kill_d1`;
`n10_absent_without_measurement`; `n7_never_says_no_training_needed`; `withdrawn_1_to_16_each_flagged` (sixteen
fixtures); `unregistered_first_claim_flagged` ("the first simulator with an MCP interface" → withdrawn 11 and
rule b); `concession_must_accompany_n1` (N1 without "prior art (Warp, Genesis)" is flagged);
`rule_set_registered_and_run` (a `synthetic` rule set that refuses the word "plugh" is run on a scratch document
and its refusal appears in the report; a rule set past its `since` milestone with no command fails);
`registered_renderings_exported` (the exported list contains N13's sentence with its bracket while
GATE-TENFOLD-06 and -07 are open, and the same sentence with no bracket once both pass);
`contradicted_by_resolves` (sixteen items, each resolving; a planted `IA-99` fails);
`da_nf_pending_until_absence_tables_exist` (with no `[[documented_absence]]` and `[[not_found]]` tables, `NF-10`
and `DA-04` read `pending`, the plain load warns and passes, `FROB_EXIT=M0` fails; with the tables present both
resolve); `conditioned_phrase_follows_reader` (the five states of the acceptance criterion);
`conditioned_phrase_reader_failure_refuses`; `prior_art_presented_as_new_flagged` (a scratch document saying
"the first anytime-valid sequential comparison" is flagged under rule g with the prior-art record named);
`n11_property_needs_da04`
(scratch GATE-PHYLUM-03 record with two numbers: the replay sentence absent while DA-04 is `documented`,
present when DA-04 is `stands`).

### End-to-end script and logging
`scripts/e2e/claims_wording.sh` generates the README section from three scratch gate registries (all open; the
N6 gates passed; KILL-D1 fired) and diffs the renderings against expected text, then runs the lint (`cargo test
-p frob-conformance --test claims_wording`) over planted documents. Logged per STD-E2E (every line with the exact command, exit code and wall time): differentiator id,
gate and re-audit row statuses read, the rendered sentence digest, findings with file and line; on a rendering
mismatch the first differing byte offset, the expected and actual text and the scratch gate registry path;
`summary` with renderings checked and plants caught.

### Known answers and negative controls
Negative controls: the sixteen withdrawn sentences; a README edited by hand to drop the N5 bracket; a mutant
renderer that drops brackets when any (rather than every) condition gate passes; a mutant lint that reads a
missing or failing `reader` as permission, so that a conditioned phrase passes when its decision cannot be
read. No numeric known answers.

## Considerations

- The registry governs public description as well as internal documents; marketing text is in scope.
- N11's two numbers are meaningful only against a named incumbent configuration measured on `trj`; the
  rendering includes that configuration.
- If the composed incumbent ties on a stratum, N13 is rendered with that statement for the stratum (BET-14).
