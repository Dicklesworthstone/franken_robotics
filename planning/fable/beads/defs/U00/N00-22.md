## Background

The goals say what the finished product must be able to do. GOAL-01 to GOAL-20 come from the first version of
the design, with wording corrected wherever the incumbent audit showed the old wording claimed too much;
GOAL-21 onward were added with the ten-fold thesis. A tier tag on a goal is the tier of its least certain
mechanism; a goal with no tag is Solid. This bead keeps the goals as data and checks that each one traces to a
gate that measures it and to beads that build it, so that no goal is quietly dropped and none is claimed beyond
its gate.

## Scope

In: `registries/goals.toml` with the 43 records and their trace fields, and the traceability test. Out: the
goals' mechanisms; non-goals and anti-goals (N00-23, N00-24).

## Technical approach

1. **Record.** `[[goal]]`: `id`, `text`, `tier`, `subsystems`, `gates` (the gate identifiers whose pass
   demonstrates the goal), `scenarios` (North-Star identifiers), `bets`, `first_milestone`, `status` (computed:
   `open`, `met`, `met-by-fallback(<kill gate>)`, `withdrawn(<ADR>)`). Initial traces (DESIGN; each owning unit
   may extend its row): GOAL-01 → GATE-KIN-01, -02, -04; GOAL-02 → GATE-SPARK-03, -04, GATE-KIN-03;
   GOAL-06 → GATE-HAB-02, NS-04; GOAL-09 → GATE-TETHER-01, -13, NS-06; GOAL-10 → GATE-SPARK-01, -02, -15,
   GATE-CHRON-01, -02, NS-02; GOAL-11 → GATE-CHRON-03; GOAL-13 → GATE-REFLEX-01, -02; GOAL-14 → GATE-CORTEX-01,
   -03, -05; GOAL-15 → GATE-ATEL-04, NS-03; GOAL-16 → GATE-FID-02, -05, GATE-CORTEX-04, NS-09; GOAL-17 →
   GATE-LEMMA-01, NS-11; GOAL-18 → GATE-TETHER-02, -03; GOAL-20 → GATE-SPARK-15, -16; GOAL-21 → GATE-AUGUR-02,
   -03, -05, NS-13, NS-22; GOAL-22 → GATE-PHYLUM-02, -03, NS-14; GOAL-23 → GATE-CORTEX-11, -12, -13, NS-19;
   GOAL-24 → GATE-QUAL-01, -02, NS-17; GOAL-25 → GATE-ARENA-03, -09; GOAL-26 → GATE-NEMESIS-02, -03, NS-15;
   GOAL-27 → GATE-NEMESIS-04; GOAL-28 → GATE-AUTOPSY-03, NS-16; GOAL-29 → GATE-ATEL-11, GATE-AUGUR-12;
   GOAL-32 → GATE-HAB-10, -11, NS-18; GOAL-33 → GATE-TRAC-05, GATE-HAB-06; GOAL-34 → GATE-SHIELD-01, -03,
   NS-23; GOAL-35 → GATE-GAIT-01, -03; GOAL-37 → GATE-GROUND-06, -10, NS-21; GOAL-38 → GATE-FOUNDRY-08, -09,
   -10, NS-20; GOAL-39 → GATE-SAFE-01, -08, GATE-LEMMA-04; GOAL-40 → GATE-TENFOLD-06, -07, GATE-CORTEX-16,
   NS-24; GOAL-41 → GATE-SPARK-13; GOAL-42 → GATE-TETHER-14.
2. **Traceability test** (`crates/frob-conformance/tests/goals.rs`): every goal has at least one gate that
   exists in the gate registry; every listed gate's milestone is at or after the goal's `first_milestone`;
   every goal is named in the `plan_refs` or body of at least one open or closed bead in the tracker export; no
   Frontier or Moonshot goal lacks a kill gate reachable from its gates' mechanisms.
3. **Status.** Computed from gate statuses: `met` when all listed gates are `pass`; `met-by-fallback` when a
   listed gate is `killed: fallback adopted` (the goal's text is then printed with the fallback's name);
   otherwise `open`. The README status table prints one line per goal from this computation (`xtask
   check-generated`).
4. **Wording guard.** Goals that concede parity (GOAL-02, GOAL-06, GOAL-12) keep their concession sentence in
   every rendering; the claims lint (N00-15) checks it.

## Acceptance criteria

- [ ] 43 goal records load; counts by tier: 31 with a Solid tier in whole or in part, 12 purely Frontier or
      Frontier-and-Moonshot (GOAL-21, -23, -26, -31, -32, -34, -35, -36, -37, -38, -41, -43).
- [ ] The traceability test passes: every goal has a gate and a bead; a goal with no gate fails with its id.
- [ ] The README prints goal statuses from gate statuses only; at M0 every goal is `open`.
- [ ] A goal whose gate was killed prints under the fallback's name.

## Test plan

### Unit tests
`goals.rs`: `forty_three_goals`; `goal_without_gate_fails`; `goal_gate_must_exist`;
`goal_without_bead_fails` (synthetic tracker export missing GOAL-30); `status_met_requires_all_gates_pass`;
`status_met_by_fallback_names_kill_gate` (GOAL-23 with KILL-FAMILY fired → "specialists with inheritance from
the nearest parent"); `parity_concession_kept_in_rendering` (GOAL-12).

### End-to-end script and logging
`scripts/e2e/goal_register.sh` runs the test against the live gate registry and tracker export and prints the
status table. Logged per STD-E2E: goal id, tier, gates with statuses, bead count, computed status; `summary`
with open, met, met-by-fallback and withdrawn counts.

### Known answers and negative controls
The goals state no numeric known answers. Negative controls: a registry with GOAL-27's gates emptied; a goal
record whose status was typed in by hand (unknown field); a README line for a goal edited by hand.

## Considerations

- A goal is not a claim: until its gates pass it is described as a goal, and after a kill gate fires it is
  described by the fallback.
- The initial traces are a floor; the owning units' beads are the authority for which gate measures what.
- GOAL-43 is deliberately off the critical path; its status never affects a milestone exit before M6.
