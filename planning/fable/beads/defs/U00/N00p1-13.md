## Background

A known answer that nothing can fail validates nothing: a row that states no negative control is an obligation,
not a test, and is not counted toward GATE-GAUNT-02 (N00-KA's rule; the count of uncounted rows due by M3 must be
zero by M3). Seven rows of the North-Star fixtures state no control: the stance family (KA-019 inner set,
KA-020 exclusion, KA-021 the admitted cell at b = 1/4 m) and the docking family (KA-023 the identifying probe,
KA-024 the tolerable sensor error, KA-025 the late packet, KA-026 the third gain). Their controls mutate the
stance classifier (BD-130), the docking solver (BD-129), the late-packet witness (BD-134), the three-gain
amendment handler (N25c-21) and the offline auditor's mission proof kinds (BD-132, with bundles written by
BD-133), all of which arrive at M1. This bead was split from N00-33 (round 1 of polishing), which keeps the seven
thesis controls and the four tolerances at M0, so that no M0 bead waits on M1 code.

The rule for a control (DESIGN, inherited from N00-33 and enforced by N38b-28): it is a defect, not a boundary.
"The boundary cell is excluded" tests the boundary; the control is the build in which the strict inequality
became non-strict. Each control below is a mutation of the implementation, a mutated bundle, or a planted input
that makes the row's own test fail.

## Scope

In: seven control records (with two second controls, for KA-019 and KA-021), their registration against the
mission and auditor gates, the recorded runs showing each caught and the clean build passing, and the closure of
the registry's obligation list for KA-001 to KA-032 (zero rows owed after this bead).

Out, with the bead that has it: the control rule, the five kinds and the control loader (N38b-28, N38b-04); the
thesis controls and the four tolerances (N00-33); the rows themselves (N00-KA); the stance and docking
mechanisms (BD-130, BD-129, BD-134, N25c-21); the auditor's checkers (BD-132); the mission mutation corpus of
60+ cases, its format and runner, and the per-kind checker-independence campaign (BD-136, N38b-11), to which
this bead appends its two bundle mutations as shared cases, not duplicates; the gate runs of GATE-AUGUR-02 and GATE-AUGUR-03 (N25a-21, N25c-22).

## Technical approach

**Controls** (registered against GATE-AUGUR-02 for the stance rows, GATE-AUGUR-03 for the docking rows, and
GATE-LEMMA-03 and GATE-LEMMA-04 for the two that the auditor catches; all also against GATE-GAUNT-02):

| Row | Truth | Control | Why it is caught |
|---|---|---|---|
| KA-019 | Inner set b ≥ 3/14 m with witness (160, 130, 110, 0) N | `planted-input`, a mutated bundle (the fixture file offered to the auditor): the witness allocation changed to (160, 130, 105, 5) N (still sums to 400 N, moment balance broken), re-hashed so every hash is consistent | The auditor's exact moment check fails; and a second control, `planted-design`: b = 3/14 − 1/1000 offered as inner must be rejected |
| KA-020 | Exclusion for b < 3/14 m by a dual vector; 165 N at b = 0.20 m | `planted-input`, a mutated bundle: one dual multiplier perturbed (1/2 → 51/100), re-hashed | The Farkas identity no longer holds exactly; the auditor rejects |
| KA-021 | b = 1/4 m admitted with (155, 135, 105, 5) N | `mutation`: a classifier that applies the upper force bound as 140 N | Rejects the admitted cell (at b = 1/4 m the heaviest foot cannot go below 150 N while the lightest stays non-negative), so the row's equality with the truth fails; and a second control, the reverse mutant (bound 170 N), wrongly admits b = 0.20 m, contradicting KA-020 |
| KA-023 | U = 3/4: first command 1/4 identifies the gain; both worlds dock exactly | `mutation`: a docking solver that applies the command bound to the first two ticks only | Admits U = 1/2 with probe 1/4, where gain 1 needs a third command of −3/4; the exact replay of the plan violates \|u₃\| ≤ U |
| KA-024 | Feasible exactly when ε < (U + 1/2)/4; 1/8 → 5/16 | `mutation`: the strict inequality replaced by ≤ | At U = 3/4 the cell ε = 5/16 is admitted; the boundary cell must be excluded (nine boundary cells of the 561-cell grid are excluded) |
| KA-025 | Packet late: no causal controller docks both worlds | `planted-input`: a clairvoyant controller (it reads the gain before the first command) offered as a witness | The causality check rejects the witness with FROB-REF-881 (evidence for the easier quantifier order) |
| KA-026 | Third gain 33/32: aliases with gain 1 at error radius 1/64; every feasible label reverses | `mutation`: an amendment handler that keeps certificates whose hypothesis support changed | A cell certified for gains {1, 2} is still reported feasible for {1, 33/32, 2}; the revalidation test finds the stale label |

**Records.** Each control becomes a `[[control]]` record in the format of N00-33 (`id`, `seed` = the KA number,
`gate`, `kind`, `target`, `defect`, `expect`, and `feature` or `fixture` by kind, BD-025's loader rule). The four
`mutation` controls (KA-021 and its reverse, KA-023, KA-024, KA-026) are `cfg(feature = "nc-<nnnn>")` branches at
their target sites in `frob-mission`, each feature declared in that crate's manifest, never in the
`gauntlet-mutations` umbrella, and run by the control runner of N38b-04 one control per build, rebuilding the
row's tier target with `--features gauntlet-mutations,frob-mission/nc-<nnnn>`. The two mutated bundles, the
clairvoyant witness and the planted design are fixtures under `crates/frob-conformance/tests/fixtures/` with the
`synthetic` header, offered through the checker or verb. A control is accepted only after a recorded run in which
the mutant build, mutated bundle or planted input made the row's test fail with the value in the last column, and
the clean build passed. The KA-019 and KA-020 bundle mutations are also cases of the mission mutation corpus of BD-136:
this bead appends them to that corpus's fixed cases, in its case format, each carrying this record's `id`
(they are not among BD-136's nine stance mutations A1 to A9, which reorder feet, pass the moment as a torque,
change a tag, a quantifier, a side condition, a kind, a rational's form or a cell's end, and none of which
changes one witness force or one dual multiplier). The record is registered once (DESIGN: one record shared, so
a corpus change cannot silently drop the row's control). N38b-11's generated per-kind corpus may produce
equivalent mutants; they are its own cases and do not replace these two.

**Closure.** When the seven records are accepted, the registry's obligation list for KA-001 to KA-032 is empty
and the controls of the seven rows read `registered` (replacing `none stated`, with a dated note naming this
bead).

## Acceptance criteria

- [ ] Seven control records exist, plus the second controls of KA-019 and KA-021, each with a recorded run
      showing `caught = true` and a clean run showing a pass.
- [ ] The two bundle mutations are rejected by `frob-verify` alone, built from an empty environment, with the
      first failing rule named (the moment check for KA-019, the Farkas identity for KA-020), and their
      unmutated bundles are accepted.
- [ ] The clairvoyant witness of KA-025 is refused with FROB-REF-881.
- [ ] No row of KA-001 to KA-032 remains `none stated` or `to set`; the obligation counter for these rows reads
      zero.
- [ ] Each of the two shared corpus cases names this bead's record, and the record is registered once.
- [ ] Each code mutant is an `nc-<nnnn>` feature branch of `frob-mission`; a build with it and without
      `gauntlet-mutations`, or under the release profile, is a compile error (N38b-04's guard), and
      `cargo tree -e features` shows no `nc-*` feature in any product binary.

## Test plan

### Unit tests
`crates/frob-conformance/tests/ka_controls_ns_fixtures.rs`, one test per control, each applying its control
through the control runner of N38b-04 (for a `mutation`, the rebuild with `--features
gauntlet-mutations,frob-mission/nc-<nnnn>`; otherwise the mutated bundle or planted fixture offered to the
checker or verb), running the row's own assertion and requiring it to fail with the value in the "why it is
caught" column (outcome `caught`, not `caught-unexpected`), then running the clean variant and requiring a pass: `control_ka019_moment_broken_is_caught`;
`control_ka019_planted_inner_below_boundary_rejected` (b = 3/14 − 1/1000); `control_ka020_perturbed_dual_is_caught`;
`control_ka021_bound_140_rejects_admitted_cell`; `control_ka021_bound_170_admits_0_20_contradicting_ka020`;
`control_ka023_bound_on_two_ticks_admits_u_half` (u₃ = −3/4 against U = 1/2);
`control_ka024_non_strict_admits_boundary` (at U = 3/4, ε = 5/16 admitted; the clean build excludes the nine
boundary cells of the 561); `control_ka025_clairvoyant_witness_refused_881`;
`control_ka026_stale_support_is_caught`. Registry tests: `no_obligation_rows_left_in_001_to_032`;
`shared_corpus_cases_point_to_one_record` (a planted duplicate record for KA-020 is a load error);
`kinds_name_feature_or_fixture` (the four mutations name a declared `frob-mission/nc-<nnnn>` feature, the five
others a fixture with its `synthetic` header).

### End-to-end script and logging
`scripts/e2e/ka_controls_ns_fixtures.sh` runs the clean `g1_known_answers` target on the seven rows and the
control runner once per control (each `mutation` in its own build), then drives the real binaries on the M1
fixtures: `frob mission synthesize stance.fmission --key nc-1 --json` and
`frob prove bundle <answer> --out stance.frobcert --key nc-2 --json`; `frob-verify stance.frobcert` (accepted);
the script writes the KA-019 and KA-020 mutated copies (re-hashed so every hash is consistent) and runs
`frob-verify` on each (rejected, first failing rule named); then `frob mission synthesize docking.fmission
--set U=3/4 --set eps=5/16 --key nc-3 --json` (the boundary cell is excluded on the clean build). Logged per
STD-E2E: per control an `assert` line with the row, the control kind, the mutant, the expected truth, the
mutant's value, the clean value and `caught`; per binary call the command, exit code, wall time, refusal code and
the auditor's first failing rule; one `obligation` line for the registry (rows owed: 0); a `cargo tree -e
features` line for the product binaries (`nc-*` features found: 0);
`summary` with nine of nine caught and gates GATE-GAUNT-01, GATE-GAUNT-02, GATE-AUGUR-02, GATE-AUGUR-03,
GATE-LEMMA-03 and GATE-LEMMA-04.

### Known answers and negative controls
Hand checks of the controls: 160 + 130 + 105 + 5 = 400 (the mutated witness keeps the force sum and breaks only
the moment); (U + 1/2)/4 = 5/16 at U = 3/4 and 1/8 at U = 0; with U = 1/2 the third command of gain 1 is −3/4,
|−3/4| > 1/2; 33/32 − 1 = 1/32, so the alias radius is 1/64. A control that errs on the safe side at the
fixture's values (it makes the test pass for the wrong reason or never reaches the assertion) is rejected and
replaced.

## Considerations

- If a mutant turns out to be indistinguishable on the fixture, the fixture is extended, never the truth
  loosened.
- Until this bead closes, the seven rows are uncounted: a gate run of GATE-AUGUR-02 or GATE-AUGUR-03 that cites
  them reports them as not supported (fail-closed); the M1 exit review sees the obligation count.
- The bundle mutations are re-hashed on purpose: a mutation caught only by a hash mismatch tests the hashing,
  not the auditor's arithmetic.
- The code mutants live behind `nc-*` features that only the control runner enables, one per build; the
  compile-time guard and the feature tree of the product binaries are the checks, not a convention.
