## Background

**Before.** World 1,337 of 4,096 produces NaNs on the GPU. Where an incumbent's deterministic mode is on, the
same batch can be re-run on the same GPU; none documents a bitwise re-run of that one world on a CPU (FACT
about incumbent documentation at pinned versions).

**After.** `frob sim replay --world 1337 --tier batch-cpu` reproduces that world alone on the CPU from its
address (seed, world, episode), stops at the first step whose digest differs from the GPU's or at the first
refusal, and reports the contact that started it. Where the device reaches determinism class D1 (the same bits
on the CPU reference, CUDA and Metal) the digests agree to the end, and the report says which class applied.

**What it demonstrates.** A world is addressed, not stored: every random draw depends on its address alone, a
world's trajectory does not depend on the batch it ran in, and each step leaves a digest in a chain. So any
world can be pulled out of a batch and re-run on the trusted CPU reference ("teleported"), and a divergence
between tiers is localized to a step and a kernel stage instead of being argued about.

## Scope

In: the demo inputs, `demos/ns-02/demo.yaml`, the device-lane script and the reduced CPU lane. Out: digests,
replay, teleport, the first-divergence search, the backends.

## Technical approach

1. **Actors.** A training agent debugging a failed batch.
2. **Inputs.** A reference quadruped on a terrain scene; a run of 4,096 worlds for 500 steps on CUDA with a
   **planted** fault: a test-only build feature perturbs one kernel stage (the contact cone evaluation) of
   world 1,337 at step 212 by one unit in the last place of one output (DESIGN; the plant makes the story
   deterministic).
3. **Steps and what the agent sees.**
   a. `frob sim run … --worlds 4096 --tier cuda --json` → a run handle; per-world digest chains in the ledger.
   b. `frob sim replay --run <id> --world 1337 --json` on the same backend → identical digests to the end
      (the batch can be reproduced on its own tier).
   c. `frob sim replay --run <id> --world 1337 --tier batch-cpu --json` → the envelope reports the class that
      applied (`D1` exact, or `D3` tolerance replay), `first_divergence = {step: 212, stage: "K-cone-eval"}`,
      the two digests, and the contact (bodies, world position, normal force) at which the stage's outputs
      differ; exit code 2.
   d. `frob telemetry divergence <gpu-run> <cpu-replay> --json` → the same step and stage by the digest-chain
      search, in exact mode under D1 or tolerance mode under D3.
   e. Without the plant: step (c) reports digests equal to the end under D1, or inside the envelope under D3
      with the label `tolerance replay`.
   f. Co-tenancy check: the same world replayed alone, in a batch of 64 and among different neighbours gives
      the same digests.
4. **Lanes.** `device`: as above on the Linux host (and on Metal on the Mac). `cpu` (reduced, under 60 s): 64
   worlds for 100 steps on `batch-cpu` in single precision as the "fast" run, replayed in the `strict` profile,
   with the same plant at world 13, step 40; the demo file's commands are this lane.
5. **Under the no-GPU variant of M2 or a fired determinism kill gate** the device half is `not demonstrated`
   (or demonstrated as a tolerance replay, under that name), and the index says which.

## Acceptance criteria

- [ ] The planted divergence is localized to step 212 and the right stage by both `sim.replay --tier` and
      `telemetry.divergence`.
- [ ] Without the plant the replay agrees to the end and the report names the class that applied.
- [ ] The world's digests are identical alone, in another batch size and among other co-tenants.
- [ ] The reduced CPU lane passes from a clean checkout in under 60 s; CLI and MCP digests agree.
- [ ] The envelope never claims bit equality under class D3.

## Test plan

### Unit tests
`demos.rs`: `ns02_demo_yaml_valid`; `ns02_address_fields` (seed, world, episode present in the replay request);
`ns02_expected_divergence_record` (step 40, stage name, in the reduced lane's expected fragment);
`ns02_class_label_required` (an expected fragment without `determinism` fails validation).

### End-to-end script and logging
`scripts/e2e/ns_02.sh --lane cpu|device`. Logged per STD-E2E: run and replay identifiers, the address, backend
fingerprints, determinism class, the digest chain's first differing step and stage with both digests, the
contact record, co-tenancy digest comparisons; `summary` naming GATE-CHRON-01 and GATE-CHRON-02.

### Known answers and negative controls
Gate thresholds (TARGETs): 1,000 random worlds from a GPU run replay with identical digests on the same backend
and inside the class on `batch-cpu`; teleport localizes a planted single-kernel divergence to the right step
and stage in 100 of 100 trials. Negative controls: the planted perturbation (must be found); a build with a
planted read of a neighbour world's row (the co-tenancy check must fail); a replay request with a wrong seed
(must not reproduce, and must say the address does not match the run).

## Considerations

- The plant is a test-only feature and must be absent from release builds (symbol scan).
- "NaN on the GPU" in the story is one kind of first refusal; the script also covers a refusal as the stopping
  event.
