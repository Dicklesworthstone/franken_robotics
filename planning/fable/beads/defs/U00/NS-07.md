## Background

**The story.** Importing a public humanoid description yields a loss report: which fields were dropped, which
inertias fail the physical-consistency test, and which actuator limits were absent and filled from a card
marked `assumed`.

**What it demonstrates.** An anti-goal made visible: inertial parameters are never accepted on faith, and
nothing is dropped or filled in silence. A robot description in a common exchange format carries less than a
design needs (often no actuator model beyond an effort limit) and sometimes carries things that are physically
impossible (an inertia tensor whose principal moments violate the triangle inequality, or a mass distribution
that cannot fit inside the link's geometry). The importer reports all of it: a field-coverage diff of what the
source had and the design keeps; a physical-consistency verdict per link; and, for each value it had to supply,
a card field whose provenance is `assumed`, so that every result built on it is at best Estimated and names
that field as its weakest input.

A rigid body's inertia is physically consistent exactly when its 4 × 4 *pseudo-inertia* matrix is positive
semidefinite; for the principal moments I₁, I₂, I₃ this implies the triangle inequalities I₁ + I₂ ≥ I₃ (and
permutations).

## Scope

In: demo inputs, `demos/ns-07/demo.yaml`, the script. Out: the readers, the importer, the inertia test, cards.

## Technical approach

1. **Actors.** A design agent bringing an existing robot into the studio.
2. **Inputs.** `g1.urdf` (a public 29-degree-of-freedom humanoid description, with its licence: the 38-link
   Unitree G1 description upstream of the sibling's G1 builder, which BD-065 vendors with its `PROVENANCE.toml`)
   and two mutated copies: one with a link whose principal moments are (0.010, 0.010, 0.025) kg·m² (violates
   I₁ + I₂ ≥ I₃), one containing an unsupported element.
3. **Steps and what the agent sees.**
   a. `frob design import g1.urdf --name g1 --key ns07-imp-1 --json` (a mutate verb: the registered form
      carries an idempotency key) → exit 2; a new `DesignId`; `loss_report` with: `dropped` (every
      source field with no place in the design, by path); `inertia` (per link: consistent or not, with the
      smallest eigenvalue of the pseudo-inertia); `filled` (every value supplied by the importer, each with the
      card and field it came from and provenance `assumed`: for example continuous torque, torque-speed curve,
      rotor inertia, thermal resistance); and the entry "no contact law declared" (the importer infers no end
      effector and no contact law).
   b. `frob actuator show <card> --json` → the filled fields with `assumed` on each.
   c. `frob design check <id> --json` → exit 3, FROB-REF-121 at stage 1 (contact law missing), the import's own
      truth shown once: nothing was invented for the feet. The first ranked repair is applied from
      `next_actions`: `frob design edit <id> set-contact-law … --expected-parent <id> --key ns07-ed-0 --json`
      (`foot-patch` with torsion radius 0 on both feet) → a new `DesignId`. `frob design check <id′> --json` →
      runs, and its evidence block has class Estimated with `weakest` pointing at an assumed card field.
   d. `frob design import g1-bad-inertia.urdf --name g1-bad --key ns07-imp-2 --json` → exit 2; the loss
      report's `inertia` section marks the link inconsistent with the smallest eigenvalue of its pseudo-inertia
      and the proposed repair (every import produces a loss report, and an inertia that fails C-03 is reported
      there with its repair). The same contact-law edit (key `ns07-ed-0b`) clears stage 1, because stages run in
      order and stop at the first refusal; then `frob design check <id> --json` → exit 3, refusal FROB-REF-104
      at stage 2 (inertia not physically consistent), naming the link and reporting the smallest eigenvalue;
      ranked repairs (recompute from geometry and density; project to the nearest consistent inertia).
   e. The first repair applied as a typed edit from `next_actions` (`frob design edit <id> … --expected-parent
      <id> --key ns07-ed-1 --json`) → a new `DesignId` whose lineage records the repair with the before and
      after values; `frob design check` on it no longer raises FROB-REF-104.
   f. `frob design import g1-unsupported.urdf --strict --name g1-u --key ns07-imp-3 --json` → refusal
      FROB-REF-122, exit 3; without `--strict` (key `ns07-imp-4`) the element appears under `dropped` with its
      file and line.
   g. `frob design export <id> --format urdf --json` → a reverse loss report listing what the exchange format
      cannot carry (actuator cards, port contracts, sensor timing).
4. **Demo file.** Claims: the claim identifier of GATE-SKEL-01; all commands are CPU-tier and exact;
   `fresh_agent: true`.

## Acceptance criteria

- [ ] The loss report lists every dropped field found by an independent field-coverage diff of the source file
      against the design (no silent drop).
- [ ] The import declares no contact law: the first check refuses with FROB-REF-121 at stage 1, and the ranked
      repair `set-contact-law`, applied as a typed edit, clears it.
- [ ] The inconsistent inertia is listed in the import's loss report with its proposed repair, and the check
      refuses it with FROB-REF-104 and exit code 3; the repaired design records the repair with before and
      after values and passes stage 2.
- [ ] Every filled actuator value is marked `assumed`, and a downstream result names such a field as its
      weakest input with class Estimated.
- [ ] The strict import refuses the unsupported element with FROB-REF-122.
- [ ] Forward kinematics of the imported model matches the oracle within 10⁻⁹ m and 10⁻⁹ rad over 10⁴
      configurations (gate TARGET), and a fresh agent completes the scenario from its brief.

## Test plan

### Unit tests
`demos.rs`: `ns07_demo_yaml_valid`; `ns07_bad_inertia_fixture_violates_triangle` (0.010 + 0.010 < 0.025);
`ns07_expected_loss_report_sections` (`dropped`, `inertia`, `filled`); `ns07_field_coverage_diff_matches_dropped`
(an independent XML walk of the fixture lists the same paths as the expected `dropped` section).

### End-to-end script and logging
`scripts/e2e/ns_07.sh`. Logged per STD-E2E: file digests, counts of dropped, filled and inconsistent items, the
refusal codes and exit codes, the smallest pseudo-inertia eigenvalue, the evidence block with its weakest-input
path, the forward-kinematics parity residuals; `summary` naming GATE-SKEL-01.

### Known answers and negative controls
The triangle inequality on the mutated link. Negative controls: an importer build that drops an unknown field
without listing it (the coverage diff must catch it); a filled value marked `datasheet` with no source (the
card admission check refuses it); the imported text containing an instruction-like comment (it must be echoed
as untrusted data and never acted on).

## Considerations

- The reference description's licence governs redistribution; if it cannot be shipped, the script fetches it
  at a pinned revision and verifies its digest.
- "Tells the truth" includes saying what was not checked: geometry-against-inertia consistency needs meshes or
  primitives, and the report states which it had.
