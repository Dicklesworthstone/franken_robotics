## Background

**Before.** An agent given a failed episode orders the anomalies by time and guesses.

**After.** The debugger forks the snapshot taken before the fall under twelve typed interventions, singly and
in pairs, on identical random streams. The placebo fork replays the failure bit for bit. The report says that
lifting the knee torque limit prevents the fall in 94% of perturbed forks against a placebo flip rate of 3%, so
it is a but-for cause, and that restoring nominal friction does so in 8%, so it is not. The gear-ratio
intervention is re-run from the episode start, because winding temperature depends on the whole history.
Attribution runs in double precision, and the first-ranked repair comes back as a typed edit. An episode whose
placebo flip rate is high is labelled `chaotic: unattributable` and is given no cause. The percentages are
illustrative values of the story's instance.

**What it demonstrates.** Explanation by experiment. An *intervention* changes one thing in a forked copy of
the world (a limit, a coefficient, a delay) while every random stream stays identical. The *null fork* (the
empty intervention) changes nothing and must reproduce the original bit for bit; this is what the story above
calls "the placebo fork replays the failure bit for bit". *Placebo forks* in the sense the verbs use (no
intervention, one state coordinate perturbed at round-off scale) measure how often the outcome flips by
chance: the placebo flip rate. A factor is a *but-for cause* when intervening on it prevents
the failure far more often than the placebo flips. Interventions on quantities with memory over the whole
episode (a design parameter, thermal state) cannot be applied mid-episode and are re-run from the start.

## Scope

In: demo inputs (a planted single cause), `demos/ns-16/demo.yaml`, the script. Out: forks, interventions,
contrasts, the decision model, re-runs, the repair workflow.

## Technical approach

1. **Actors.** A design agent holding a failed episode's address.
2. **Inputs.** A quadruped descending a step, with a **planted single cause**: the knee actuator's torque limit
   is set just below what the landing needs; friction is slightly below nominal as a decoy; a second fixture
   episode on a known chaotic system for the abstention check: one of the planted chaotic episodes of the
   abstention registry (N27a-14, reached through BD-282: a real episode whose binding atom is the doubling-map
   probe, addressed by its handle `fixture:host/doubling-map-40:<seed>`; the Autopsy verbs accept it only in a
   build with the `conformance` feature). The demo file's commands are steps (a) to (f), which a release build
   runs (the demo file has no key that marks a command as needing another build, and a demo runs on the binary
   a user gets, N00-29); `ns_16.sh --lane cpu` runs step (g) itself after the executor, on a binary built with
   the `conformance` feature, and logs it under that build.
3. **Steps and what the agent sees.**
   a. `frob run fork <run> --world <w> --before failure --dt <s> --key ns16-fk-1 --json` (the registered form:
      the run positional, the checkpoint named relative to the failure) → a fork handle, its class,
      the earliest valid tick, and the null-replay result (`null_replay: "bitwise"`).
   b. `frob autopsy intervene <fork> --do '<intervention>' … (the twelve, one `--do` each) --placebo 64
      --replicates 100 --coalitions pairs --lane f64 --key ns16-aut-1 --json` → runs the null fork, the
      placebo forks, the replicates and the coalitions (the verb has no `--precision` option: where the forks
      run is the lane, and `f64` asks for double precision; 78 coalitions × 100 + 64 + 1 = 7,865 forks before
      the 10⁻⁷ series, which the `cpu` lane reduces with `--replicates 8` to 689).
   c. `frob autopsy attribute <fork> --json` → per factor: the prevention rate over perturbed forks (the
      rescue rate), the placebo flip rate, the contrast with its exact test against its level, both flip
      rates, and a label on the wire (`but-for`, `contributing`, or `none` for a factor that is not a
      cause); the planted factor ranked first; pairs labelled joint or alternative where relevant.
   d. The gear-ratio intervention requested on the fork (`frob autopsy intervene <fork> --do 'regear *.knee
      <ratio>' --key ns16-aut-2 --json`) → listed under `refused` with FROB-REF-581 (a design-parameter
      intervention at a mid-episode tick), the earliest valid fork tick (the episode start) and the forcing
      field (the winding's thermal history), and `next_actions` naming the `autopsy.rerun` command, which the
      script runs as given: `frob autopsy rerun <run> --edit 'regear *.knee <ratio>' --worlds failing,sample:64
      --key ns16-rr-1 --json` → a paired re-run from the episode start, with its outcome.
   e. `frob autopsy repair <fork> --key ns16-rep-1 --json` → the result keeps two things apart (a diagnostic
      intervention is never a repair): the torque-limit factor, which is diagnostic, appears under
      `locating_sets` with the typed design edits it suggests (`swap-actuator` or `regear` on `*.knee`, or
      `set-param` on the limit), and `repair_sets` holds only buildable factors. The demo takes the first
      suggestion as the first-ranked repair, writes it as a typed edit that `frob design edit` accepts
      verbatim, and tests it from the episode start with `frob autopsy rerun <run> --edit '<that edit>'
      --worlds failing,sample:64 --key ns16-rr-2 --json`.
   f. `frob autopsy show <fork> --budget 600 --json` → the session transcript, token-budgeted.
   g. On the chaotic fixture: step (c) returns `chaotic: unattributable` and names no factor.
4. **Lanes.** `cpu` is the whole scenario at reduced replicate counts (double precision on `batch-cpu`), within
   60 s for the demo file; `device`: forks from a GPU run with attribution escalated to double precision.
5. **Under the autopsy kill gate** the scenario shows single-factor paired re-runs from the episode start with
   first-anomaly ordering labelled Estimated.

## Acceptance criteria

- [ ] The null fork replays the failure bit for bit (the story's "placebo fork").
- [ ] The planted factor ranks first with label `but-for`; the decoy's label is `none` (not a cause); rates
      and flip rates are printed with their replicate counts.
- [ ] The mid-episode design-parameter intervention is refused and its re-run from the episode start completes.
- [ ] The first-ranked repair is a typed edit that applies cleanly, and its paired re-run from the episode
      start removes the failure on the failing world; the diagnostic torque-limit factor appears in no repair
      set.
- [ ] The chaotic fixture names no factor (gate TARGET: 100 of 100 for planted chaotic and no-cause failures);
      planted single causes rank first in at least 90% of 200 (gate TARGET).

## Test plan

### Unit tests
`demos.rs`: `ns16_demo_yaml_valid`; `ns16_twelve_interventions_listed`; `ns16_expected_label_for_planted_factor`
(`but-for`); `ns16_expected_refusal_for_midepisode_regear`; `ns16_chaotic_fixture_expected_unattributable`.

### End-to-end script and logging
`scripts/e2e/ns_16.sh --lane cpu|device`. Logged per STD-E2E: each command line with its key, exit code and
wall time, fork class, null-fork digest equality, per factor
the prevention rate, flip rate, contrast and label, precision used, the refusal code of the mid-episode
request, the repair edit and the post-repair outcome; `summary` naming GATE-AUTOPSY-03, -05 and -06.

### Known answers and negative controls
The doubling map x ↦ 2x mod 1 doubles any perturbation per step, so a perturbation of 2⁻⁵² reaches order one
after 52 steps: a failure defined after that horizon is unattributable. The Shapley identity: factor values sum
to v(all) − v(none). Negative controls: a checkpoint with its packet queue stripped (refused); a null fork that
does not replay bitwise (the session stops with FROB-REF-583 and the first differing tick); a replicate
series whose perturbation is a no-op at the run's precision (recorded as not run at that precision, never as
zero flips: a series with no fresh draw must not read as a stable one).

## Considerations

- Attribution needs a controlled determinism class with batch-composition invariance current; otherwise it is
  refused, not approximated.
- A cause named on a planted failure is not a guarantee on natural ones; every attribution carries its
  stability figure.
