## Background

Two doctrine rules govern verdicts.

- **D-13, answers are two-sided, and unknown is a verdict.** A set-valued answer is an inner set, an outer
  set and the unresolved remainder between them. A point answer carries a witness or a refutation of matching
  scope. A solver failure, a timeout or an unenclosed branch yields `unknown`; it never yields failure and
  never success.
- **D-18, a strict decision is computed exactly.** Predicates with strict comparators, digests and
  certificate arithmetic run in an exact-integer kernel class, in exact rationals, or in guarded single
  precision with an exact fallback. FACT (planning pilot, to be re-run in this repository before a gate cites
  it): an unguarded `f32` screen of 65,536 boundary cases produced 452 false admissions and 23,438 false
  exclusions, and a guarded or integer kernel produced none.

Why they need a check. A tool that reports "infeasible" when its solver timed out teaches an agent to discard
designs that work; a tool that reports "feasible" on an unenclosed branch issues false certificates. And two
back ends that agree to the last bit but one on a limit test still disagree about whether the limit is
active, after which the two worlds are different worlds. Both failures are silent unless something plants
them and looks.

Tier: Solid. The mechanisms are owned elsewhere (mission sets, clearance complexes, predicate classes, exact
kernels); this bead is the cross-cutting battery.

## Scope

In: a schema walk for answer shape (`d13_*`); fault injection that forces solver failure, timeout and

## Technical approach

**D-13: answer shape.**

1. Verdict vocabularies are closed enumerations that include an undecided member. Set-valued outputs
   (a mission's design set, a clearance answer, a certified root list, a paving of a parameter box) carry
   three parts: `inner` (members proved in), `outer` (members not proved out), and `unresolved` (outer minus
   inner), with I ⊆ F ⊆ O for the true set F. A union of proved inner cells is inner; a cell leaves the outer
   set only by a proof that it contains no member; infeasible sample points do not eliminate their cell.
2. Point answers carry `witness` (for a positive verdict: the object that demonstrates it, such as a path, an
   allocation, a root box) or `refutation` (for a negative verdict: a dual vector, a separating certificate,
   a disconnection), each with a `scope` equal to the claim's scope; or the verdict is `unknown` with a
   `reason` from a closed list (`solver-failure`, `timeout`, `budget-stop`, `unenclosed-branch`,
   `numerical-guard`).
3. The walk: every verb output whose schema has a verdict field is checked for (a) an undecided member in its
   enumeration, (b) the three-part shape if set-valued, (c) the witness-or-refutation rule if point-valued.
4. Fault injection (real components, real faults): the cone-program solver is run with an iteration budget
   of one on a feasible program and on an infeasible program; an interval paving is stopped at depth zero; a
   time budget of zero is given to a mission query. In every case the verb must return `unknown` with its
   reason and the partial two-sided answer computed so far (complete cells and the unresolved remainder), and
   must not return either definite verdict.
5. Only a strict certificate decides. For conic infeasibility the witness y must satisfy the dual conditions
   strictly (Mᵀ·y in the dual cone and rᵀ·y < 0); a witness that meets them only to rounding is `unknown`.

**D-18: exact strict decisions.**

1. Every predicate that selects between outcomes differing at the boundary is declared with its comparator
   (strict, non-strict or equality) and its arithmetic class: `Exact` (integers, rationals and field elements
   on the host), `Guarded` (single precision with a certified error bound and an exact integer fallback on the
   same stored inputs), or `Plain` (single precision, allowed only where the two arms agree at the boundary,
   such as a clamp or a maximum). The audit reads the kernel manifest and the requirement and mission schemas
   and fails any strict or equality predicate of class `Plain`, any digest or certificate arithmetic outside
   the exact classes, and any predicate with no declared comparator.
2. The guarded evaluation, as the rule this check assumes: evaluate p̂ in single precision and a bound
   E = c·u·S (S the sum of absolute values of the terms, u the unit round-off, c a constant derived from the
   straight-line program by forward error analysis); if |p̂| > E the sign is decided; otherwise evaluate p
   exactly on the stored inputs as an integer computation in 32-bit limbs with widening multiplies. A
   predicate whose exact evaluation would exceed 256 bits is refused at build time (FROB-REF-215).
3. Boundary screens the audit requires to exist and pass, with their controls: the 65,536-row screen (the
   unguarded comparison must show its errors; the guarded and exact kernels must show none, with identical
   bytes on every back end); the single-precision cone case below.
4. Strictness is semantics, not tolerance: a strict requirement is evaluated with its declared comparator; a
   uniform positive margin is a separate, stronger request and is never substituted silently.

Determinism: the audits are D0; the fault-injection tests are deterministic given the injected budget.

## Acceptance criteria

- [ ] `cargo test -p frob-conformance --test g0_doctrine -- d13 d18` passes on the verbs and kernels present at
      M1, and is re-run at each milestone exit.
- [ ] Every verdict enumeration in a verb schema has an undecided member; every set-valued output has inner,
      outer and unresolved parts; every definite point verdict carries a witness or refutation of matching
      scope.
- [ ] Fault injection: in each of the injected cases the verdict is `unknown` with its reason; zero definite
      verdicts.
- [ ] Predicate audit: zero strict or equality predicates of class `Plain`; every predicate has a comparator.
- [ ] Boundary screen: 65,536 rows; unguarded `f32` shows 452 false admissions and 23,438 false exclusions
      (the control); guarded and exact kernels show zero errors.
- [ ] Negative controls caught: a verb that maps a solver timeout to `infeasible`; a verb that maps an
      unenclosed branch to `feasible`; a set-valued output with no unresolved part; a positive verdict with
      no witness; a strict predicate evaluated in plain single precision; a strict requirement evaluated with
      a non-strict comparator; a near-degenerate dual witness accepted.

## Test plan

### Unit tests

- `d13_enum_has_unknown`: synthetic schemas (labelled `synthetic`), with and without the undecided member.
- `d13_three_part_sets`: a set answer missing `unresolved` fails; `inner ⊄ outer` fails.
- `d13_fault_solver_budget`: the real cone-program solver with one iteration on (a) a feasible two-variable
  program and (b) an infeasible one → `unknown` both times, reason `budget-stop`.
- `d13_fault_paving_depth0`: an interval paving of the constraint x² + y² ≤ 1 on the box [0, 2]² at depth
  zero → the whole box unresolved; at depth six the inner and outer sets sandwich the quarter disc.
- `d13_strict_witness_only`: a dual witness with rᵀ·y = −10⁻¹⁷ computed in floating point is not accepted;
  the same witness in exact rationals with rᵀ·y < 0 is.
- `d18_audit_classes`: a manifest with a strict `Plain` predicate fails; a clamp of class `Plain` passes.
- `d18_cone_case`: the single-precision numbers nearest 0.3, 0.4 and 0.5 as x, y, z in the test
  x² + y² ≤ z²: in single precision the two sides are equal, so the plain test reports "inside"; the exact
  value of x² + y² − z² on those stored numbers is +1.19 × 10⁻⁸, so the point is outside; the guarded
  predicate returns the exact sign.
- `d18_strictness`: on the docking fixture at actuator bound ¾ and sensor error 5/16 the residual is exactly
  zero and the strict predicate fails; a non-strict comparator passes it and is caught. On the set
  0 < w ≤ 1 every realization has w > 0 although the infimum is 0: a decision by infimum fails.

### End-to-end script and logging

`scripts/e2e/doctrine_verdicts.sh`. Sources the STD-E2E helper. Steps: the two families; the fault-injection
cases through the real binary where a verb exposes a budget (`frob --json mission synthesize … --budget 0`
must return an `unknown` verdict with reason `budget-stop`, carrying the complete cells and the unresolved
remainder, and must not return an error or a definite verdict); `frob --json spark probe` on each present device to run the boundary corpus and the
strict-predicate case, asserting identical bytes across back ends for the guarded and exact kernels and
logging the guarded kernel's fallback fraction. Log `target/e2e-logs/doctrine_verdicts/<utc>.ndjson` with
transcript: commands, exit codes, wall times, verdicts and reasons, counts of false admissions and exclusions
per kernel class against their expected values, the evidence block (determinism class per device), digests,
and on failure the first row or verb at fault. Final `summary` line.

## Considerations

- Kill gate KILL-MARROW-GUARD (M2): if the guarded fallback rate exceeds 10⁻² on the contact battery on
  either GPU back end, or the exact path cannot be made bit-identical across back ends, strict predicates are
  evaluated exactly only on the strict CPU profile and the referee, and GPU tiers mark worlds that came
  within the bound of a boundary for re-running. The audit then accepts the marking scheme in place of the
  guarded class on GPU tiers; the doctrine rule is unchanged.
- "Exact" is exact with respect to the stored inputs. It makes two back ends with bit-equal inputs take the
  same branch; it says nothing about how well the inputs approximate real quantities.
- `unknown` has a cost: an agent may be tempted to treat it as failure. Reports therefore print the
  unresolved remainder and the cheapest action that would resolve it.
- The pilot figures (452 and 23,438) are FACT from outside this repository until the M0 exact-kernel bead
  reproduces them.
