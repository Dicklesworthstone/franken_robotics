## Background

Construction C-18 (assumptions form a lattice and verdicts have polarity; core in SPEC-C-18) has a second
reading. The same relation "this closed loop handles this world" that orders certificates under amendments also
pairs sets of designs with sets of worlds: the worlds all of a set of closed loops handle, and the closed
loops that handle all of a set of worlds. The two maps form an antitone Galois connection, and its closed
pairs are exactly the robust families and the world families they are robust on. From it follows a query an
engineer wants: for two candidate designs, the **nearest admitted world on which they receive different
verdicts** (`mission.separate`). That world is the dual of the minimal design repair, ships as a regression
fixture, and is often more informative than the maximum simulated reward. Tier: Frontier [F]; crate
`frob-mission`; the first gate that needs it is at milestone M3.

Terms. *Closed loop* c = (d, π): a design with a **fixed** controller. *c R w*: every admitted execution of c
in world w is accepted. *Galois connection (antitone)*: two order-reversing maps between two power sets such
that V ⊆ X↑ exactly when X ⊆ V↓. *Closed pair*: (X, V) with X↑ = V and V↓ = X. *Authored units*: the units in
which a world's parameters are written by their author (an edit is one change to one authored field).

Rejected alternatives: ranking two designs by maximum or mean simulated reward (it hides the world on which
the preference reverses); reporting any world on which they differ (an arbitrary far-away world is not a
useful regression); mixing priors over worlds into admissibility (a likelihood is not a membership test).

## Technical approach

### 1. Statements (status HYPOTHESIS; class once the route has run)

| Id | Statement | Class and route |
|---|---|---|
| C-18.S6 | For a set X of closed loops let X↑ = { w : c R w for every c ∈ X }, and for a set V of worlds let V↓ = { c : c R w for every w ∈ V }. Then V ⊆ X↑ exactly when X ⊆ V↓ (an antitone Galois connection) | `Certified` on finite relations by exhaustive check; the general statement is a two-line argument on file |
| C-18.S7 | The closed pairs of the connection are the robust families and the world families they are robust on; X ⊆ X↑↓, V ⊆ V↓↑, and X↑↓↑ = X↑ | `Certified` on finite relations |
| C-18.S8 | For two closed loops the separating set is S(c_A, c_B) = { w : c_A R w differs from c_B R w }; `mission.separate` returns the admitted world in S nearest to nominal, where nearest means fewest edits in authored units and then least normalized physical distance | `Tested` |
| C-18.S9 | Priors over worlds stay distinct from admissibility of worlds; the separating world is the dual of the minimal design repair | Reporting rule and non-claim |

Argument for S6: V ⊆ X↑ says every w ∈ V is handled by every c ∈ X, which is the same sentence as "every
c ∈ X handles every w ∈ V", that is X ⊆ V↓. Both maps reverse inclusion.

Scope note. The connection is stated for closed loops with a **fixed** controller. For designs with an
existential controller the per-world answers do not intersect to the joint answer (statement C-18.S4); the
duality must not be applied to designs with the controller quantified away.

### 2. The order on worlds (S8, made precise; DESIGN where the source leaves a choice)

A world is the nominal world plus a set of typed edits. The distance of a world from nominal is the pair
(number of edits, normalized physical distance), compared lexicographically. Normalized physical distance of
an edit is |value − nominal|/scale with the scale declared for that field (the same declared scales that
normalize requirement atoms); the distance of a world is the largest normalized distance among its edits
(DESIGN: the maximum, so that one large change is not hidden among small ones). Ties are broken by the stable
order of edit identifiers, so the answer is deterministic. If S contains no admitted world the answer is
"no separating world in the admitted set", which is itself a result (the two designs are equivalent on W under
these controllers).

### 3. Worked fixture (exact; reference model of the docking fixture, N10b-08)

Two closed loops on the docking family at U = ¾, differing only in the first command: c_A probes with p = ¼,
c_B with p = 5/8. With the packet on time, c_A succeeds exactly for ε < 1/8 and c_B exactly for ε < 5/16.
Worlds are indexed by the read-error bound ε = j/64, j = 0 … 32, nominal j = 0. Then
S(c_A, c_B) = { j : 8 ≤ j ≤ 19 } (c_B succeeds and c_A fails); the nearest separating world is j = 8, ε = 1/8,
one edit, attained because equality is excluded for c_A. X = {c_A, c_B} gives X↑ = { j ≤ 7 }, and
(X↑)↓ contains both loops: the pair ({c_A, c_B}, { j ≤ 7 }) is closed within this two-loop universe.

- `s6_galois_exhaustive`: the acceptance values. `s7_closure_identities`: X ⊆ X↑↓, V ⊆ V↓↑, X↑↓↑ = X↑,
  V↓↑↓ = V↓ on the same relations.
- `s7_closed_pairs_are_robust_families`: for each closed pair (X, V), every loop of X handles every world of V
  and neither side can be enlarged.

- `s8_lexicographic_order`: of two separating worlds, one with one large edit (normalized distance 3) and one
  with two small edits (0.1 each), the one-edit world is returned.

- `s9_prior_is_not_admissibility`: changing the weights of worlds changes no answer of `up`, `down` or
  `separate`.

Further controls (mutants): a `separate` that returns the *farthest* separating world; one that counts

relations: exchanging the two loops leaves S unchanged; adding a world on which both loops agree leaves the
answer unchanged; enlarging X can only shrink X↑. Determinism: exact arithmetic, class D0; twice on one
machine, debug and release.

## Considerations

- "Nearest" depends on declared scales. A world field without a declared scale cannot enter the distance; the
  query refuses it by naming the field, and never invents a scale.
- The separating world returned by a simulator-backed search is 1-minimal under the tested edit relation, not
  a proven minimum; the contract says so, as the counterexample-world construction does.
- The fixed-controller scope is easy to forget. Each result of the query names the two controllers it was
  computed for.
