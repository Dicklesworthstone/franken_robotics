## Background

Construction C-19 (information has a clock) has a Solid core and three Frontier parts: witness *search*, the
label count and schedule exploration. Every Frontier mechanism runs a paper-scale pilot with a written
falsifier before its work is funded, and names the generic method it must not lose to (doctrine rules D-10 and
D-17). This bead is that pilot. It has two halves. The first checks that the specialized closed form of the
docking family and an **independently written** scenario-tree linear program give the same answer on a grid:
if a generic solver answers the same question, the plan says so and claims no exclusivity. The second plants
one stale-read race and checks that schedule-class enumeration finds it.

Terms. *Docking family*: a unit mass with hidden gain g ∈ {1, 2}, three one-second ticks, command bound U, one
velocity reading with error bound ε; a robust causal policy exists with the packet on time exactly when
ε < (U + ½)/4 and never when it is late. *Scenario tree*: the tree of possible readings; a linear program
over it has one copy of the later commands per distinguishable reading history and shared copies where
histories coincide (non-anticipativity). *Stale-read race*: an estimator read that may run before or after a
packet delivery at nearly the same instant; in one order the estimator uses a stale value.

## Scope

In: the frozen protocol of the construction's pilot; the grid comparison with both arms (the closed form, and
a standalone scenario-tree program written for the pilot in `tools/pilots/c19/`); the evaluation of both
falsifier clauses; the ceiling; the record `PILOT-C-19`.

Out, with the bead that has it:

- The scenario-tree program as product code in `frob-mission`, its 51 solves, its proof objects and its exact

  pilot is a separate program and shares no code with either; where N25c-20's M1 record exists its cell

- The re-run of the plan-time reproduction bundle (BD-041, a prerequisite whose result this pilot cites);
  witness search at scale (BD-240); the schedule-race mechanism (N20a-10) and the decision KILL-SCHED (N20a-11).

## Technical approach

**Protocol (frozen before execution).**

1. *Grid.* U = ½ + i/32 for i = 0 … 16 and ε = j/64 for j = 0 … 32 (561 cells), for both packet timings
   (on time: arrival before the second decision; late: arrival after the third command is committed): 1,122
   verdicts.
2. *Arm A (the mechanism).* The closed form of the fixture as implemented by the reference model of N10b-08.
3. *Arm B (the generic comparator), written independently* by a session that has not read arm A's code: for
   each cell, a feasibility linear program in exact rationals. Variables: the first command p and, for each
   node of the reading tree, the remaining commands. The reading tree for a candidate p has three leaves when
   the reading sets [p − ε, p + ε] and [2p − ε, 2p + ε] overlap (g = 1 only, g = 2 only, either) and two when
   they are disjoint; because the overlap pattern depends on p, the program is solved on the finite set of
   candidate probes k/64 inside [−U, U] and on the breakpoints p = 2ε, with strict disjointness tested exactly.
   Constraints: terminal state (1, 0) in every scenario; |u_k| ≤ U; equal commands in scenarios that share a
   reading history. For the late timing all scenarios share all commands. Solver: exact rational simplex (the
   second linear-program solver admitted for mission work, or a 60-line exact Fourier–Motzkin elimination;
   either is acceptable, both are recorded).
4. *Race.* The fixture and the explorer are N20a-09's (its one-pair fixture: a six-event schedule on the
   deterministic lab runtime with capture, delivery, estimator read, watchdog expiry, actuator commit and one
   unrelated timer, in which the one conflicting pair, delivery and estimator read, is planted so that the
   order read-before-delivery commits a command computed from a stale value; the explorer enumerates one
   representative per schedule class and compares commit digests). This pilot's protocol freezes the
   reference to that fixture by its digest, re-runs it through N20a-09's command, and reads the result.
5. *Measures.* Number of cells where arms A and B disagree; whether the planted race is reported with its
   two orderings and digests.

**Falsifier.** One grid cell where the two arms disagree, or the planted race missed.

**Ceiling.** A witness ends a futile policy search; it does not speed a search that can succeed. The gain is
therefore counted in trainings avoided, not in a speed ratio, and nothing is claimed against the generic
comparator: FACT (plan-time pilot, re-run by BD-041) a scenario tree and 51 linear programs matched the closed
form on this family.

**Fallback.** Witnesses are checked when supplied and not searched for. Kill gates this pilot informs:
KILL-ALIAS (one false witness from the searched lane; fallback: structural, enumerated and declared witnesses
only), KILL-SCHED (the race check misses a planted race; fallback: the fixed total order with no enumeration),
KILL-AUGUR-LABELS.

**The six parts of a method experiment.** Ceiling (above); competing arms (A, B, and the fallback); potency
control (arm B run on a deliberately wrong boundary, the non-strict ε ≤ (U + ½)/4, must disagree with arm A on
exactly the nine boundary cells; an A/A comparison must agree on all 1,122); paired comparison (cells are
paired by identity; the reported quantity is the disagreement count, with exact arithmetic on both sides);
pre-declared fallback (above); reachability (both verdicts are reachable: a single disagreement falsifies).

**Record.** `PILOT-C-19` in `frob-conformance/registry/pilots.toml`: mechanism and tier, protocol hash,
falsifier, ceiling, fallback and kill gates, cost (CPU minutes), tools and pins (the linear-program solver,
the lab runtime commit), then the result. Evidence class `Estimated`: the comparison and the falsifier evaluator
run in a standalone program outside the product, which is neither a checker, the verification harness nor the
study runner (N00-26's creation rule), and a pilot is evidence for funding, never for a gate of the product
(N38a-09). Fixtures labelled `synthetic`.

## Acceptance criteria

- [ ] The record's protocol, falsifier, ceiling and fallback are committed before its result.
- [ ] Arm A and arm B agree on 1,122 of 1,122 verdicts (TARGET); the counts 344 admitted, 217 excluded, 9 on
      the boundary and 561 late exclusions are printed by both arms.
- [ ] The potency control shows exactly nine disagreements, all on boundary cells.
- [ ] The planted race is reported by N20a-09's one-pair fixture, re-run here: two schedule classes, two
      different commit digests, the stale value named; the record cites that pilot's record by content hash.
- [ ] The un-planted schedule of the same fixture (the pair made independent in fact, by reading after a
      barrier) reports one digest across all classes.
- [ ] Verdict `funded` or `fallback` recorded; no Frontier bead of C-19 starts before it (GATE-GAUNT-08).

## Test plan

### Unit tests

In the pilot's standalone program (`tools/pilots/c19/`):
- `lp_feasible_cell`: U = ¾, ε = 1/8, on time: feasible with p = 5/8 (any p in (¼, 5/8] works); the solution's
  commands reach (1, 0) in both scenarios.
- `lp_boundary_cell`: U = ¾, ε = 5/16: infeasible (strict); `lp_late_cell`: infeasible for U = 1, ε = 0.
- `lp_nonanticipativity`: removing the equal-command constraint for shared histories makes every late cell
  feasible (the clairvoyant relaxation), which the test asserts as the reason the constraint exists.
- (The count for the race fixture, six events with one conflicting pair giving 2 classes of 360 orderings
  each, is tested with the fixture in N20a-09, `one_pair_two_classes_of_360`.)
- `falsifier_evaluator`: synthetic tables: zero disagreements and race found → `funded`; one disagreement →
  `fallback`; race missed → `fallback`.
- `race_clause_reads_sched_pilot_record`: the evaluator takes the stale-read result from a record of N20a-09's
  schema; a record whose fixture digest differs from the frozen one is rejected.

### End-to-end script and logging

`scripts/e2e/pilot_c19.sh` (idempotent; seed 1910 printed; refuses to overwrite a record with a result): runs
arm A, arm B, the potency control and the race (the last by `FROB_TEST_SEED=1910 cargo test -p frob-conformance
--test pilot_sched_race -- one_pair` on the one-pair fixture, N20a-09's command; the Gauntlet has no `frob` verb,
ADR-GAUNT-01); validates the record with `cargo test -p frob-conformance --test pilot_register` (the register's
schema tests over the real file, N38a-09; `g0` is not a target name, and the six tier targets hold no pilot
check); reads `pilots.toml` and `gates.toml` read-only; `frob --json doctor`. Sources the STD-E2E helper; writes `target/e2e-logs/pilot_c19/<utc>.ndjson` and a
transcript; one `metric` line per disagreement (cell i, j, timing, both verdicts) and per schedule class
(representative ordering, digest); `assert` lines for the two falsifier clauses and the potency control; each
line has `ts`, `script`, `bead` (`N10b-10`), `step`, `event`, command, exit code, wall time, evidence block
(class Estimated, tier host, determinism D0, tool pins, seed). Final `summary`: counts, verdict, gate GATE-GAUNT-08.

### Known answers and negative controls

Known answers: KA-108 to KA-111 (docking), KA-115 (schedule classes; here the one-pair variant: 2 classes, held
with the fixture in N20a-09). Negative controls: the non-strict boundary (nine disagreements expected); the
clairvoyant relaxation; and, in N20a-09 with the explorer, a race explorer that orders same-instant events by
arrival and therefore explores one ordering only (it must miss the race, and the pilot's check must report
that miss as a failure of that explorer). Determinism: both arms in
exact rationals; the lab runtime is seeded and replayable; the script runs twice with identical tables.

## Considerations

- Independence of arm B matters more than its sophistication: it is written from the model statement, not from
  the closed form, and its author is recorded.
- A tie between the arms is the expected and acceptable outcome. It funds the *interface* (a witness as a
  checkable artifact), not a claim of exclusive expressivity.
- If the lab runtime is not yet admitted when the pilot runs, the race half runs on the small hand scheduler
  N20a-09 writes for that case, and the result is recorded as `partial` until repeated on the runtime (the
  rule is stated once, in N20a-09; this pilot's verdict is then `partial` on its second clause too).
