## Background

In a design study most new designs are small edits of an existing one: a longer shank, a different gear ratio,
an added sensor. Training the child from scratch throws away the parent's controller. Construction C-23 (core
in SPEC-C-23) defines how the parent's policy **initializes** the child's: a typed edit declares how the frames,
actuator roles, sensor channels, contact roles and phase clocks of the child correspond to the parent's, and
that correspondence defines a transport of policies. An edit is not an isomorphism (the robot really changes),
so the transport does not promise the child's policy is good; it promises a principled starting point with two
checkable laws: a zero edit changes nothing, and commuting edits give the same start in either order.

Tier: Frontier [F]. Crate: `frob-learn` (verbs `train.inherit`, `policy.apply`). It serves BET-16
(inheritance); its gate is GATE-CORTEX-13 and its kill gate KILL-INHERIT; the pilot is N10b-15.

Terms. *Edit* e: d → d′: a typed change of a design with declared preconditions and inverse. *Correspondence*:
a declared pairing of a role of the parent with a role of the child, with the rule for moving quantities
across it. *Role*: a named channel or frame by function (the left-front hip actuator), never by position in a
list. *Head*: the output layer attached to one token. *Recurrent state*: memory a policy carries between
steps. *Ad and its dual*: the maps that move twists (Ad_g) and wrenches (Ad_g⁻ᵀ) between frames related by a
rigid transform g. *Matched token*: a token of the child that corresponds to a token of the parent.

Rejected alternatives: a raw-checkpoint warm start (weights copied by index: it silently pairs the wrong
channels after any structural edit, and the gate requires transport to beat it); retraining from the class
prior for every edit (the fallback).

## Technical approach

### 1. Statements (status HYPOTHESIS; class once the route has run)

| Id | Statement | Class and route |
|---|---|---|
| C-23.T1 | An edit e: d → d′ is not an isomorphism. It declares a correspondence between parent and child frames, actuator roles, sensor channels, contact roles and phase clocks, and that correspondence defines a transport T_e: Π_d → Π_d′ that initializes the child | Definition |
| C-23.T2 | Matched tokens keep their features and heads | `Tested` |
| C-23.T3 | References and errors move by Ad and its dual (a twist-valued reference by Ad_g, a wrench-valued one by Ad_g⁻ᵀ, for the transform g between corresponding frames) | `Tested` |
| C-23.T4 | New tokens start with zero-initialized heads, and unmatched recurrent state is reset | `Tested` |
| C-23.T5 | Transport composes on matched tokens: T_{e₂∘e₁} = T_{e₂}∘T_{e₁} | `Tested` (relation MR-24) |
| C-23.T6 | On isomorphisms transport equals the group action (the re-description action of statement C-23.S5) | `Tested` |

Consequences used as known answers: an edit whose parameter change is zero gives a child whose first action
equals the parent's (KA-129); two commuting edits give the same initialization in either order (KA-130).

### 2. Type sketch (DESIGN: fixes intent, not signatures)

```rust
pub enum Transport { Adjoint, AdjointDual, GroupElement(GroupElem), Zero, Reset }
pub struct Correspondence { from: Role, to: Role, transport: Transport }
pub struct InheritanceMap {
    donor: PolicyId, child: DesignId, edit_path: Vec<EditId>,
    correspondences: Vec<Correspondence>,   // frames, actuator roles, sensors, contact roles, phase clocks
    unmatched: Vec<Role>,                   // new channels start at zero; unmatched recurrent state is reset
    depth: u8,                              // a lineage resets on a schedule (default k = 5)
}
```

Channels are matched by role, never by position or name order. A mapping that cannot be built is a refusal,
not a guess: FROB-REF-531 (a policy's mapping table does not match the design, or cannot be built for an edit;
exit code 3; repairs: declare the missing correspondence on the edit; train the child from the class prior).

### 3. The transport, as steps

1. Read the edit path from parent to child and collect the declared correspondences. Refuse (FROB-REF-531) if a
   role of the child that the policy must drive has neither a correspondence nor the status "new".
2. For each matched token: copy the token's static-feature encoder and head from the parent (T2). Static
   features themselves are recomputed from the child design, in dimensionless form.
3. For each matched channel that carries a frame-typed quantity whose frame moved by a rigid transform g under
   the edit: insert the fixed map Ad_g (twists) or Ad_g⁻ᵀ (wrenches) between the channel and the network (T3).
   A channel related by a signed permutation uses that group element.
4. For each new token: create its head with zero weights and zero bias, so that at initialization the new
   actuator's action is zero; and give its outgoing message (its term in its parent's pooling, or its key and
   value in attention) a scalar gate initialized to 0, so that the outputs of matched tokens are unchanged by
   its presence in the sum (T4). DESIGN, with reason: a zero head alone silences the new token's own action
   but leaves its encoder output in its neighbours' sums, which would change matched actions; the gate is an
   ordinary trainable weight after initialization.
5. Reset recurrent state attached to unmatched roles; keep the rest.
6. Record the inheritance map in the child's checkpoint, with the lineage depth incremented. A lineage that
   reaches the reset depth (DESIGN default: 5) is re-initialized from the class prior (loss of plasticity).

Composition (T5) holds by construction when correspondences compose as functions on roles and the frame maps
compose as Ad(g₂·g₁) = Ad(g₂)·Ad(g₁); the law test checks it rather than assuming it.

### 4. Honest limits

FACT (source register, to be re-read): inheritance from a class prior costs about 2 to 25% of a from-scratch
run; the one published parent-to-child figure is about 50%; no source measures a small typed parameter edit;
single-limb topology edits cost 33 to 100%. Edits that change support discontinuously (a mirrored pair, a
removed limb, a wheel exchanged for a foot) are not covered by the default and have their own gate. The
transport says nothing about the child's return.

### 5. Law suite and registry (DESIGN)

`crates/frob-learn/tests/laws_c23_transport.rs`, generic over `C23TransportSubject { fn transport(&self, parent:
&Policy, map: &InheritanceMap) -> Result<Policy, Refusal>; fn first_action(&self, p: &Policy, d: &DesignData,
obs: &Obs) -> Action }`. `tests/support/c23_transport_ref.rs`: the synthetic corpus and reference policy of the
core suite; typed edits on it (parameter edit, add a link, add a sensor, move a frame by a rational rigid
transform). `tests/support/c23_transport_mutants.rs`: mutants under the crate's cargo feature `conformance` (BD-025; the umbrella `gauntlet-mutations` enables it). Registry:
KA-129, KA-130; relation MR-24; derivation file `docs/derivations/policy-transport.md`. Gate that measures it
(recorded by BD-322): GATE-CORTEX-13 (on 12 parent–child edit pairs, 4 blind: median adaptation samples for
parameter edits at most 20% of a from-scratch run stopped at 95% of its final return, and fewer than a
raw-checkpoint warm start needs; the inherited child more than 5% worse in at most 20% of edits; a chain of 10
edits shows no decline under scheduled resets). Kill gate KILL-INHERIT (decided at M4): median parameter-edit
cost above 60% of from-scratch steps, or the inherited arm more than 5% worse in over 20% of edits; fallback:
every child trains from the class prior or from scratch, and the mapping table is kept for loading policies.

## Considerations

- Zero-initialized heads make the child's initial behaviour that of the parent with the new actuator passive;
  whether that is a good start for a given edit is exactly what the pilot measures.
- Chained inheritance loses plasticity; the reset schedule is a design rule and its default depth is a DESIGN
  value to be confirmed by the ten-edit chain of the gate.
- Shared lineage biases a population toward designs that are easy to steer; reports name the donor so that the
  bias is visible.
- A typed edit that cannot state its correspondences (a topology change of the support) is outside this
  contract and is refused, not approximated.
