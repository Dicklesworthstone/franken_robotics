## Background

Instance certificates (this kernel, this model, this cell) are `Certified`: a checker accepted them. `Proved` is
reserved for statements accepted by a Lean kernel. Kernel reflection is the one route from an instance to a proof.
A reflected checker is a function `check : Input → Bool` defined in Lean together with a soundness theorem
`check x = true → Spec x`. The theorem is proved once, in stock Lean with Mathlib tactics, and re-checked by
FrankenLean like any other theorem (T-35). An instance is then proved by the kernel itself evaluating `check x` to
`true`, which needs no tactic at checking time and no compiled evaluator. That matters because FrankenLean does
not elaborate tactic proofs today; evaluation of a closed term is something a kernel does.

ADR-LEMMA-05: reflection promotes selected instance certificates and is never the default; instances are checked
by kernel evaluation, never by a compiled evaluator, which keeps the trusted base at the kernel and the soundness
theorems. Tier: Frontier. Ceiling, stated before any measurement: reflection relabels a few instance certificates
from `Certified` to `Proved`; by itself it changes no design decision and no speed. Every cost of kernel
evaluation on large rationals is a HYPOTHESIS until this pilot has run. Four reflectors are planned in this order:
Farkas, rational LDLᵀ, polynomial normal-form equality, rewrite-trace replay. This bead is the pilot on the first
two; it must run before the work package is funded further (the other two reflectors are bead N12-28 and exist
only if KILL-REFLECT does not fire, decision bead N12-32).

Rejected alternatives: `native_decide` (adds the compiler to the trusted base and is excluded from capsules);
stating the LDLᵀ specification with `Matrix.PosDef` (pulls analysis modules into the closure; the specification
is stated in elementary form instead, OPEN-LEMMA-2).

## Scope

In: the Lean definitions `farkas` and `ldltPos`; their soundness theorems compiled by stock Lean, re-checked by
`fln` and sealed; the two specimens proved by kernel evaluation; the measurements (module closure, peak memory of
the re-check, kernel evaluation time); the verb `prove.reflect` restricted to the two reflectors; the record of
GATE-LEMMA-05 and the measurement handed to KILL-REFLECT.
Out: the closure audit that precedes proof writing (N12-26); the cost sweep beyond specimen size and the budget
table (N12-27); reflectors three and four and the general admission rule (N12-28); the decision (N12-32); the
gate run of GATE-LEMMA-05 and its record (N12-38). This bead's own end-to-end script is In. The registered statement of Farkas soundness (`lean/Frob/Statements/T21.lean`) is written by
CARD-T-21, a dependency: the Farkas capsule also seals `T21_proof : Frob.Statements.T21.Statement`, derived in one
step from the soundness theorem, and its capsule hash moves that card's general route. The specification of
positive definiteness, the soundness template `SoundFor`, the registered text of each reflector's `Statement`
line and the enabling rule are CARD-T-35's (`lean/Frob/Statements/T35.lean`), also a dependency: this bead
appends the two lines for `farkas` and `ldltPos` to that file once the functions exist, proves
`T35_farkas_sound` and `T35_ldltPos_sound` against them, records each reflector's definition hash in its sub-entry
when sealed, and its `prove.reflect` applies the rule and passes that card's law tests.

## Technical approach

```lean
-- DESIGN: statements fix intent. Proofs are written and compiled in stock Lean with Mathlib; FrankenLean
-- re-checks the compiled declarations. No `sorry`, no added axiom, no `native_decide`.
-- The propositions below are what the registered constants of CARD-T-35 unfold to; the sealed theorems
-- prove the constants and never restate them (binding rule of N12-24).

/-- Farkas witness check over ℚ (lean/Frob/Reflect/Farkas.lean). The conclusion is stated for x over every
    linearly ordered field K that contains ℚ (ℝ in particular), with M and r cast into K; forces are real. -/
def farkas {m n : ℕ} (M : Matrix (Fin m) (Fin n) ℚ) (r y : Fin m → ℚ) : Bool := …
-- Frob.Statements.T35.farkas.Statement unfolds to: for all m n M r y and every K [LinearOrderedField K],
--   farkas M r y = true →
--     ¬ ∃ x : Fin n → K, (∀ j, 0 ≤ x j) ∧ (M.map (Rat.cast : ℚ → K)).mulVec x = fun i => (r i : K)
theorem T35_farkas_sound : Frob.Statements.T35.farkas.Statement := …   -- the plan's `farkas_sound`
theorem T21_proof : Frob.Statements.T21.Statement := …                  -- one step from T35_farkas_sound

/-- Exact LDLᵀ over ℚ with positive pivots (lean/Frob/Reflect/LdltPos.lean). The specification is stated
    without `Matrix.PosDef`, to keep the dependency closure inside algebra, and for x over every linearly
    ordered field K that contains ℚ. -/
def ldltPos {n : ℕ} (A : Matrix (Fin n) (Fin n) ℚ) : Bool := …
-- Frob.Statements.T35.ldltPos.Statement unfolds to: for all n and A with A.IsSymm, every K [LinearOrderedField K],
--   ldltPos A = true → ∀ x : Fin n → K, x ≠ 0 → 0 < x ⬝ᵥ (A.map (Rat.cast : ℚ → K)).mulVec x
theorem T35_ldltPos_sound : Frob.Statements.T35.ldltPos.Statement := …  -- the plan's `ldltPos_sound`

-- An instance is a closed term that the kernel evaluates:
example : farkas M₀ r₀ y₀ = true := by decide
```

1. `farkas M r y` returns true exactly when every entry of Mᵀy is ≥ 0 and rᵀy < 0, computed in ℚ. Soundness: if
   x ≥ 0 and M·x = r then rᵀy = (Mᵀy)ᵀx ≥ 0, a contradiction; the proof casts into K and uses ordered-field
   arithmetic only. This is the general half of card T-21.
2. `ldltPos A` runs the exact elimination d₁ = a₁₁, then Schur complements, returning true exactly when every
   pivot is positive. Soundness: with A = L·D·Lᵀ, L unit lower triangular and D positive diagonal,
   xᵀA·x = Σ dᵢ·(Lᵀx)ᵢ² > 0 for x ≠ 0.
3. Specimens. Farkas: the stance exclusion at half-width b = 1/5 m in standard form with slack variables. Unknowns
   are four foot forces f and four slacks s, all ≥ 0; rows are Σ f = 400, f₁ + f₂ − f₃ − f₄ = 180,
   f₁ − f₂ + f₃ − f₄ = 150, and fᵢ + sᵢ = 160 for i = 1..4. The witness y = (0, −½, −½, 1, 0, 0, 0) gives
   Mᵀy = (0, 0, 0, 1 | 1, 0, 0, 0) ≥ 0 and rᵀy = −90 − 75 + 160 = −5 < 0. LDLᵀ: one 4×4 pseudo-inertia with 64-bit
   numerators (a synthetic fixture built from a rational mass, first moment and second moment so that it is
   positive definite; a second fixture with one negative pivot is the negative control).
4. Instance files (DESIGN): `lean/Frob/Reflect/Instances/<digest>.lean`, generated from the bundle payload by
   `frob-lemma`, containing the literals and the line `example : farkas M₀ r₀ y₀ = true := by decide`; `decide`
   here is kernel reduction of a decidable proposition and introduces no axiom. An `lp-farkas` bundle is in box
   form (A·f = w, 0 ≤ f ≤ c, dual y, accepted when yᵀw > Σᵢ max(0, (Aᵀy)ᵢ)·cᵢ); `farkas` is in standard form. The
   generator converts exactly, in ℚ: unknowns (f, s) with slacks s = c − f; M = [[A, 0], [I, I]]; r = (w, c);
   y_std = (−y, t) with tᵢ = max(0, (Aᵀy)ᵢ). Then Mᵀy_std = (t − Aᵀy, t) ≥ 0 entry by entry, and
   rᵀy_std = Σᵢ tᵢ·cᵢ − yᵀw < 0 exactly when the box-form check accepts, so the two checks agree on every input.
   On the specimen, y = (0, ½, ½) and Aᵀy = (1, 0, 0, −1) give t = (1, 0, 0, 0) and y_std = (0, −½, −½, 1, 0, 0, 0)
   (step 3).
5. Measurements recorded per reflector: the module closure of the soundness theorem and whether it avoids every
   blocked module; peak resident memory and wall time of the `fln` re-check of the soundness theorem; kernel
   evaluation time of the specimen under stock Lean and under `fln`.
6. Verb `prove.reflect` (kind `run`, tier F, first milestone M5): promote an instance certificate through a
   reflected checker. Input schema `frob.prove.reflect.in/1` (DESIGN): `certificate` (bundle hash of kind
   `lp-farkas` or `rational-ldlt`), `reflector` (`farkas` | `ldlt-pos`; DESIGN: the CLI and MCP values are
   kebab-case like proof-kind names and map to the Lean definitions `farkas` and `ldltPos`; N12-28 adds `poly-eq`
   → `polyEq` and `replay` → `replay`), `idempotency_key`, `budget`. It generates
   the instance file, runs the pipeline on the Linux host as a job (exit code 8 while running), and returns
   `frob.prove.reflect.out/1`: the soundness capsule hash, the instance capsule hash, the evaluation time, and
   evidence of class `Proved` whose receipts are both capsule hashes and both checker identities. The refusals
   follow the `prove.reflect` row of VERBS-prove, which owns them: a certificate whose kind does not map to the
   named reflector (`lp-farkas` → `farkas`, `rational-ldlt` → `ldlt-pos`), or whose payload does not match the
   reflector's input type, is FROB-REF-823 (a kind with no enabled reflector; exit 3); a certificate the auditor
   does not `accept` is refused before any instance is generated, with the auditor's own code for its first failing
   rule, the code `prove.verify` prints for it (826, 829, 833 or 834, or 823 for an unknown kind; the row lists all
   five); a first failing rule that has no code (an arithmetic failure of the witness or a hash mismatch, a plain
   `reject` on `prove.verify`) is refused with FROB-REF-834, the rule named in the message and `pointer` =
   `certificate` (DESIGN: promoting a certificate that no checker accepts would present a result as `Proved`
   without an accepting checker's identity, which is 834's meaning, and 834 is in the row's list, so the verb
   still returns no code its row lacks); an instance beyond the evaluation budget is FROB-REF-701 and stays
   `Certified` (Considerations).
   Before generating an instance, the verb applies the enabling rule of CARD-T-35: the reflector's sub-entry must
   be `checked`, and the function named in the sealed theorem, the function the instance file evaluates (read from
   the instance capsule's constant list) and the recorded definition hash must agree; a reflector whose sub-entry
   is not `checked`, a look-alike function in another namespace, an edited definition or a capsule containing
   `native_decide` is refused with FROB-REF-724 (exit 5; the row's "a reflector whose sub-entry is not `checked`";
   DESIGN: a built function that is not the one proved sound is a reflector not in this build), with the
   `mechanism` field naming the reflector and the message naming the failing hash. A `false` evaluation is not a
   refusal: the job completes, no `Proved` evidence is issued and the certificate stays `Certified`.
   The output envelope carries the three no-authorization flags, all false. A `--sync-wait-ms` that elapses
   returns exit 8 with the job handle (the common rule of `run` verbs); the CLI default waits to completion.
7. Falsifier of the pilot: a closure that cannot avoid a blocked module, or a specimen that the kernel does not
   evaluate within 60 s (TARGET).
8. Pilot register row (N38a-09's record in `crates/frob-conformance/registry/pilots.toml`, schema
   `frob.gauntlet.pilot/1`, registered with status `registered` before the first specimen is evaluated):
   `id = "PILOT-LEMMA-03"` (DESIGN: the next free identifier of the set after N12-22's `PILOT-LEMMA-01` and
   N12-23's `PILOT-LEMMA-02`), `mechanism` = "kernel reflection: instance certificates promoted to `Proved` by
   kernel evaluation of a reflected checker (`prove.reflect`)", `tier = "F"`, `owner = "§12.4"`,
   `bead = "BD-382"`, `work_package = "WP-72"`, `protocol` = `docs/pilots/lemma-reflection.md` (the two specimens,
   the measurements of step 5, the host, the pins and the 60 s threshold) with its BLAKE3, freeze date and ledger
   sequence, `falsifier` = "the finished soundness theorem of either pilot reflector has a closure that cannot avoid
   a blocked module (intersection > 0 in every form tried), or either specimen's kernel evaluation under `fln`
   exceeds 60 s" (the plan's falsifier, read per reflector), `ceiling` = `none on speed` with
   the reason "reflection relabels a few instance certificates from Certified to Proved; it changes no design
   decision and no speed", `fallback` = { ships = "instance certificates stay `Certified` (the `lp-farkas` and
   `rational-ldlt` checkers of `frob-cert`)", kill_gate = "KILL-REFLECT" }, `tool` = stock Lean and `fln` with
   their build hashes, site `host`, and `plan_time_records = []`. The run appends one `[[pilot.result]]` with the
   measured values of step 5 and the verdict (`falsifier-rejected` or `falsifier-holds`); the decision N12-32

## Considerations

- KILL-REFLECT. Trigger: GATE-LEMMA-05 fails after one repair cycle, or no reflector's closure avoids the blocked
  modules. Fallback: instance certificates stay `Certified`, and reflection is parked in the killed-idea register.
- OPEN-LEMMA-2 (closures of the soundness theorems): default, specifications are stated in elementary form
  without analysis modules. OPEN-LEMMA-3 (cost of kernel evaluation on exact rationals): default, reflection is
  limited to specimens that fit the budget.
- Kernel evaluation of rational arithmetic on 64-bit numerators grows quickly with dimension; the pilot's numbers
  bound what `prove.reflect` may accept (N12-27).
- The expected-value register scores reflection low (kept because it is the one route from an instance to
  `Proved`); it is never on the critical path.
- Refusal codes (DESIGN; the Lemma table defines none for these two cases, so they are the Tether registry's,
  N32-REF, appended to the row by the rule of its kind): an instance beyond the evaluation budget is refused with
  FROB-REF-701 (the estimate's upper end exceeds the remaining budget; the estimate is attached; exit 4) before any
  job is planned, and its class stays `Certified` (N12-28 adds the table-based form: outside the reflection budget
  table for the pinned checker, reason `over reflection budget` with the cell missed); before M5, once
  KILL-REFLECT has fired (`reason = "killed: KILL-REFLECT"`), or for a reflector that fails the enabling rule,
  `prove.reflect` is refused with FROB-REF-724 (not in this build; exit 5). Neither is a new code and neither is
  raised by the auditor. The chapter code 823 is the Lemma registry's (N12-REF).
