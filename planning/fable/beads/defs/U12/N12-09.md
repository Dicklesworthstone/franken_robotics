## Background

A certificate is only as good as the independence of what checks it. If the checker shares a parser, a hash
implementation, an arithmetic library or a units crate with the code that produced the bundle, one defect can make
both agree. The smallest case that shows it: a canonicalization defect in the producer's hashing that drops a
field before hashing would be reproduced by a checker that reuses that hashing, and a bundle whose statement
differs from the one the proposer evaluated would pass; with two implementations the hashes disagree and the
bundle is rejected.

INV-LEMMA-05 states the invariant: `frob-cert` depends on the standard library only, and producers do not call its
decision code to build witnesses. "A producer never calls the auditor's decision code to construct a witness, so
the two share a format and nothing else." The first half is structural and is enforced by the workspace check
`xtask check-deps` (layer rule L-9: `frob-cert` has an empty dependency table, and only `frob-verbs`, `frob-cli`
and `frob-conformance` may depend on it), whose auditor rules, including the shared-source and source-escape scans,
are N34-25's and run on every commit from M0. The second half needs more than a dependency listing: `frob-verbs` is
allowed to link the checker in order to run it before an answer returns, and nothing in a dependency listing stops
code reachable from a producer from calling a checker function while it searches for a witness. This bead reads
the structural facts from that check, adds the call-graph lint, the near-copy similarity scan and the dropped-field
test, and records the invariant test. Tier: Solid. Rejected alternative:
trusting review (the shortcut "let the solver ask the checker whether this candidate passes" is exactly what a
search loop wants, and it turns the checker's blind spots into the producer's target).

## Scope

In: the invariant test, which reads the facts and findings of `cargo xtask check-deps --json` for the structural
half; the call-graph lint over the workspace; the token-similarity scan for near copies; the dropped-field test;
registration of the call-graph lint and the similarity scan as negative-controlled tests.
Out: `check-deps` itself and rule L-9 (BD-003); the auditor rules of `check-deps` with their plants, namely the
dependency-count fact, `cert.writer-links-reader` (reverse edges), `cert.shared-source` (identical files and runs
of 40 or more identical code lines) and `cert.source-escape` (`include!`, `#[path]`, symbolic links, `build.rs`)
(N34-25, one owner per rule); the system-call trace of the auditor (BD-026, GATE-WS-03); the seeded-fault
independence campaign with at least 200 mutants per kind (BD-136, BD-294).

## Technical approach

1. Structural half, read from `check-deps`. The test runs `cargo xtask check-deps --json` and asserts, from its
   report: `facts.frob_cert.dependency_count` = 0 (so `cargo tree -p frob-cert` prints one line); no finding of
   `cert.writer-links-reader` (so the reverse edges of `frob-cert` are only `frob-verbs`, `frob-cli` and
   `frob-conformance`, and no proposer crate, among them `frob-lemma`, `frob-mission`, `frob-synth`,
   `frob-shield`, `frob-opt`, `derive/frob-derive` and any crate that emits a proof object, appears); no finding of
   `cert.shared-source` or `cert.source-escape`. It does not re-implement those rules: a second implementation
   would report one defect from two checks.
2. Call-graph lint (DESIGN). `frob-verbs` links both sides, so the lint works on symbols, not crates:
   - `frob-cert` exposes its decision code behind one public entry, `frob_cert::audit(bytes) -> Report`, and marks
     every per-kind checker `pub(crate)`.
   - In `frob-verbs`, the only call site of `frob_cert::audit` is the function `run_checker_before_return`, which
     takes a finished, serialized bundle and returns the report; a source scan asserts that the symbol appears
     nowhere else in the workspace outside `frob-cli` (the `prove verify` command) and `frob-conformance`.
   - No function in `frob-verbs` passes the report back into a producer API: the lint checks that
     `run_checker_before_return` is called only from the answer-finalization path, after the proof search has
     returned, and that its result is used only to return, withhold or downgrade.
3. Shared source: zero shared source files is the pass condition, read in step 1 from `cert.shared-source` and
   `cert.source-escape`, which catch identical files after blank and comment lines are removed, shared runs of 40
   or more identical code lines, and escapes from the crate directory.
4. Vendored-copy check, for what an identity scan cannot see: a token-level similarity scan between `frob-cert`'s arithmetic modules and the producer's
   rational and interval code flags near-copies above a threshold (DESIGN: 80% identical token 5-grams per file,
   a number chosen for this lint and reported, not a gate). A flagged pair is a review item, because a copied file
   shares defects as surely as a linked one.
5. Negative controls kept in the test tree: a fixture source in which a search loop calls `frob_cert::audit` (the
   lint must fail); a fixture proposer file that is an auditor file with every identifier renamed (the identity
   scan of N34-25 does not see it; the similarity scan must report it above the threshold). The dependency and
   identical-file plants (a `frob-cert` dependency in `frob-lemma`; a pasted 60-line function) are N34-25's; this
   test reads their verdicts from the check's own self-test run rather than planting them a second time.

## Acceptance criteria

- [ ] INV-LEMMA-05's structural half holds as reported by `cargo xtask check-deps --json`: dependency count 0;
      no `cert.writer-links-reader`, `cert.shared-source` or `cert.source-escape` finding (reverse edges exactly
      `frob-verbs`, `frob-cli`, `frob-conformance`; zero shared source files).
- [ ] The call-graph lint passes on the workspace and fails on the planted search-loop fixture.
- [ ] The similarity scan reports the renamed-identifier fixture and prints its highest pair on the workspace.
- [ ] The dropped-field test rejects the patched producer's bundle with a `hash.*` rule.
- [ ] The checks run in the `smoke` battery and the negative controls of the call-graph lint and the similarity
      scan are registered in the negative-control registry.
- [ ] The result (dependency closure `std`; zero shared source files) is in the receipt of this bead's script; the
      gate that cites it, GATE-AUGUR-06, is recorded by BD-136 (M1) and BD-294 (M3) from their own runs, and this
      bead writes no gate record.
- [ ] `scripts/e2e/lemma_independence.sh` passes and its log ends with a `summary` line.

## Test plan

### Unit tests

`crates/frob-conformance/tests/auditor_independence.rs`: `check_deps_dependency_count_zero` (reads
`facts.frob_cert.dependency_count`); `check_deps_no_writer_links_reader`; `check_deps_no_shared_source_or_escape`;
`check_deps_plants_caught` (reads the verdicts of N34-25's self-test plants: the `frob-lemma` dependency and the
pasted function); `audit_symbol_call_sites` (expects exactly the allowed sites);
`checker_result_not_fed_to_producer`; `fixture_search_loop_is_caught`; `fixture_renamed_copy_is_flagged`;
`similarity_scan_reports` (prints the highest similarity pair and its score);
`dropped_field_hash_mismatch_rejects` (the canonicalization counterexample realized: the producer's writer is
patched in the test to drop `definitions.frame` before hashing; the auditor, hashing with its own implementation,
rejects the bundle with a `hash.*` rule); `run_checker_before_return_after_search` (the lint's ordering rule: a
fixture that calls it inside the proof-search loop is caught).

### End-to-end script and logging

This bead's own script, `scripts/e2e/lemma_independence.sh` (header `bead=N12-09 milestone=M1
labels=lemma,frob-cert seed=0 needs=cpu`; sources the STD-E2E helper, idempotent, writes only under `target/`),
runs `cargo xtask check-deps --json`, `cargo tree -p frob-cert` and `cargo tree -p frob-cert --invert`, then
`cargo test -p frob-conformance --test auditor_independence`, and runs the call-graph lint and the similarity scan
once more on the fixture tree alone through `e2e_expect_caught` (the search-loop fixture and the renamed copy
must each be caught); it logs the dependency listing, the reverse-dependency listing and
the shared-file count as `metric` lines with thresholds 1, 3 and 0. The directory-driven script of N12-34, which
depends on this bead, runs it as its step 2. The NDJSON lines (`target/e2e-logs/lemma_independence/<utc>.ndjson`,
transcript beside it) carry `ts`, `script`, `bead` ("N12-09"), `step` (`independence/deps`,
`independence/rdeps`, `independence/shared-source`, `independence/audit-call-sites`), `event`, the exact command
line (`cargo xtask check-deps --json` for the first three, the lint or scan for the others), exit code, wall time,
the observed value against its threshold (dependency count: 0; `cert.writer-links-reader` findings: 0, with the
reverse edges listed; `cert.shared-source` and `cert.source-escape` findings: 0; call sites of `frob_cert::audit`
outside the allowed ones: 0), the highest token-similarity pair with its score, whether each planted fixture was caught, and on a failure the
offending crate, file, rule or call site; the `summary` line counts assertions passed and failed and names
`gates: []`.

### Known answers and negative controls

Known answer: `cargo tree -p frob-cert` prints one line (read as the dependency-count fact 0). Negative controls:
the two fixtures above, and N34-25's plants read from its self-test. The
canonicalization counterexample (a dropped field hashed identically by a shared implementation) is kept as a
written case in the test's documentation and realized by the mutation "drop one field before hashing in the
producer", which the independent auditor must reject by hash mismatch. Determinism: not applicable.

## Considerations

- RISK-36 (the proposer and the checker share a defect): early signals are a source file shared between
  `frob-cert` and a proposer and a checker dependency beyond the standard library. If one auditor is judged not
  enough, a second independent checker is added (OPEN-LEMMA-4, bead N12-29).
- A FrankenSymPy-based re-check of the same bundles runs in `frob-conformance` as a second opinion; it is an
  oracle for the auditor and never a part of it (N12-10).
- The lint must stay small: `xtask` has six checks by rule, so these live as tests in `frob-conformance`, not as a
  seventh `xtask` subcommand.
- One owner per rule: the dependency, reverse-edge, shared-source and source-escape rules are N34-25's and run on
  every commit from M0; this bead reads their report, so a defect is reported once, and adds only what a
  dependency or identity scan cannot see (calls from a search loop, renamed copies, the dropped field).
