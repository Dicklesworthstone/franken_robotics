## Background

The seven claims of the system (Proof, Known answer, Parity, Fidelity, Design comparison, Reality, Performance)
are kinds of evidence, and a result that rests on two of them is their product. The weakest input wins by
construction, and nothing converts a product into a proof. The rule is a type and not prose, because an optimizing
agent will find any path by which a statistical result can be reported as a proof:

```rust
// DESIGN: fixes intent, not signatures.
#[derive(PartialEq, Eq, PartialOrd, Ord, Clone, Copy)]
pub enum Class { Estimated, Tested, Certified, Proved }          // ordered, weakest first

pub struct Evidence<K> {              // K: a zero-sized marker for one of the seven claims
    class: Class,                     // private; set only by the checker that produced the evidence
    scope: Scope,                     // model, tier, domain, quantifier prefix
    assumptions: AssumptionSet,       // each with its polarity
    receipts: Vec<ReceiptId>,         // certificate hashes, checker identities, study receipts
    flags: NoAuthorization,           // a constant
    kind: core::marker::PhantomData<K>,
}
pub struct ClaimProduct<A, B>(Evidence<A>, Evidence<B>);
impl<A, B> ClaimProduct<A, B> {
    pub fn class(&self) -> Class { self.0.class.min(self.1.class) }   // the weakest input wins
}
// No From or Into leads from ClaimProduct<A, B> to Evidence<A> or Evidence<B>. No constructor of
// Evidence<Proof> exists outside frob-lemma.
```

The pair is the two-input case of the general `ClaimProduct::combine(kind, parts)` owned by `frob-core`, in which
class, tier and determinism take the weakest, scope takes the intersection and conditions take the union.

Every exported artifact (a report, a bundle, a skill, a build packet, a tool response) carries three
machine-readable fields, and no code path sets any of them to true:
`{ "execution_authorized": false, "hardware_safety_signoff": false, "sim_to_real_certified": false }`. They say
what no result of this project is: permission to run on hardware, a safety sign-off, or a statement about a
physical robot (the last is a Reality claim, made only through the calibration lane). A build packet carries a
fourth field of the same kind, `fabrication_released`, also always false. In code the flags are one type with a
single value: `False` is a unit type that serializes as the JSON literal false, and no constructor, setter or
deserializer yields `true`.

GATE-LEMMA-06 is the M0 gate on both mechanisms. This bead is the gate's test: it does not build the types
(BD-005 owns them in `frob-core`; BD-021 owns the sole constructor of Proved evidence in `frob-lemma`); it proves
by compile-fail tests and an export sweep that the escape paths do not exist. Tier: Solid.

## Scope

In: the compile-fail tests; the property tests of the class order and the minimum; the sweep that collects every
artifact exported by the conformance suite and checks the flags; the gate record; the end-to-end script.
Out: the types and their serialization (BD-005, BD-021); flags on every exporting verb at M3 (BD-303, GATE-SAFE-01);
the claim product at the tool boundary (BD-308, GATE-SAFE-08); the auditor's flag rule (N12-03).

## Technical approach

1. Compile-fail tests (`trybuild`-style, each a tiny crate that must fail to compile with an expected diagnostic),
   in `crates/frob-core/tests/compile_fail/` and `crates/frob-lemma/tests/compile_fail/`:
   - `product_into_factor.rs`: `let e: Evidence<Proof> = product.into();` — no conversion from a claim product to a
     factor.
   - `product_from_factor.rs`: `Evidence::<Proof>::from(product)`.
   - `construct_proved_outside_lemma.rs`: a crate other than `frob-lemma` calling any constructor of
     `Evidence<Proof>` (or building the struct literally: private fields).
   - `set_class.rs`: assigning to `class` or calling a setter (none exists).
   - `ctor_with_class_argument.rs`: a public constructor that takes a `Class` argument (none exists).
   - `flag_true.rs`: constructing `NoAuthorization` with any field other than `False`; `False` has no value that
     serializes as true.
   - `deserialize_true.rs` is a run-time companion: deserializing `{"execution_authorized": true, …}` returns an
     error, never a value.
2. Property tests: `Class` is totally ordered `Estimated < Tested < Certified < Proved`; `ClaimProduct::class` is
   the minimum for all 16 ordered pairs; `combine` over n parts equals the fold of `min`; combining never raises a
   class (INV-LEMMA-02: the class of a combined result is the minimum of its inputs' classes; no interface raises
   a class).
3. Export sweep. The conformance suite (`frob-conformance`, battery `smoke` at M0) runs every exporting verb that
   exists at the milestone and writes its artifacts under `target/conformance/exports/`. The sweep walks that
   directory, classifies each file by format (envelope JSON, `.frobcert`, report, and later skill, build packet,
   HTML replay), locates the flags object under its format's spelling (`authorization` in an envelope and a
   bundle listing, `flags` in the bundle type, `no_authorization` in a verdict or receipt), and asserts: the
   object is present; it has exactly the three fields (four for a build packet); each is the JSON literal false.
   A file kind with no registered locator fails the sweep, so a new exporter cannot be missed
   (INV-LEMMA-03: every exported artifact carries the three flags, false).
4. Schema check for INV-LEMMA-01 during the same sweep: no artifact carries `Proved` or `Certified` without a
   certificate hash and a checker identity.
5. Gate record: counts of compile-fail cases (expected failures observed), exported artifacts inspected by kind,
   violations (must be zero), written to `registries/gates.toml` for GATE-LEMMA-06.
6. The sweep is milestone-aware: it re-runs at every milestone exit on the exporters that exist then.

## Acceptance criteria

- [ ] GATE-LEMMA-06 (TARGET, M0, claim Known answer): compile-fail tests show no conversion from a claim product
      to a factor and no constructor of `Proved` evidence outside `frob-lemma`; every artifact exported by the
      conformance suite carries the three flags, all false. Recorded with counts.
- [ ] All seven compile-fail cases fail to compile for the intended reason (the diagnostic names the private field,
      the missing impl or the missing constructor), not for an unrelated error.
- [ ] Negative controls: a fixture exporter that omits the flags object, one that writes a flag as `true`, and one
      that writes `"false"` as a string are each caught by the sweep; a fixture crate with a planted
      `impl From<ClaimProduct<A, B>> for Evidence<A>` makes `product_into_factor` compile and therefore fails the
      suite.
- [ ] A bundle with `execution_authorized` set to true, and one with a flag missing, are rejected by
      `frob-verify` (FROB-REF-833).
- [ ] An exact argument combined with an `Estimated` material card field has class `Estimated`.

## Test plan

### Unit tests

Named above, plus `crates/frob-core/tests/claim_product.rs`: `class_order_total`; `product_class_is_min_all_pairs`;
`combine_never_raises`; `estimated_card_caps_exact_argument`; `flags_serialize_false`; `flags_deserialize_true_errors`;
`flags_absent_is_error_not_false`. And `crates/frob-conformance/tests/export_sweep.rs`:
`sweep_catches_missing_flags_object`; `sweep_catches_true_flag`; `sweep_catches_string_false` (`"false"` is not
the literal); `sweep_catches_extra_or_missing_field` (two or four fields where three are expected);
`build_packet_needs_four_fields` (a packet without `fabrication_released` fails); `sweep_unknown_file_kind_fails`
(a file with no registered locator fails the sweep); `sweep_catches_certified_without_receipt` (INV-LEMMA-01,
step 4); `planted_from_impl_fails_suite` (the fixture crate with `impl From<ClaimProduct<A, B>> for Evidence<A>`
makes `product_into_factor` compile, and the compile-fail runner reports the suite failed);
`sweep_result_identical_debug_release`.

### End-to-end script and logging

`scripts/e2e/lemma_flags_claims.sh`: runs `cargo test -p frob-core -p frob-lemma --test compile_fail`, then the
conformance `smoke` battery, then the export sweep, then `frob-verify` on the two flag mutants of the M0
certificates. It logs one `assert` line per compile-fail case (expected diagnostic, observed), one `metric` line
per artifact kind (count inspected, violations, threshold 0), the two `refusal` lines with code FROB-REF-833 and
rule `flags.true` or `flags.missing`, and a `summary` naming GATE-LEMMA-06. Logs carry no scene data. Every
NDJSON line (STD-E2E helper) carries `ts`, `script`, `bead` ("N12-11"), `step` (`compile-fail/<case>`,
`smoke`, `sweep/<artifact-kind>`, `verify/<mutant>`), `event`, the exact command line, exit code, wall time, the
expected and observed diagnostic (error code and item name) for each compile-fail case, per artifact kind the
count inspected and the violations with each offending file's path, field path and observed value, the BLAKE3 of
each flag mutant, and the gate record written to `registries/gates.toml`; the `summary` line gives cases, artifacts,
violations (0) and the gate verdict. At M1 the script gains steps written by other beads, which depend on this
one: N12-07 adds the not-decidable refusal step and N12-08 adds the receipt check and the banned-word scan over
this script's own transcript; each logs under its own bead key.

### Known answers and negative controls

KA-214 (bundle with `execution_authorized` true → `reject`), KA-216 (a flag missing → `reject`), KA-221 (class of
a combined result is the minimum; compile-fail tests show no conversion and no outside constructor). CX-109 (an
exact argument does not yield a `Certified` result over `Estimated` inputs), CX-115 (an artifact with no
authorization fields is not neutral). Determinism lanes: the sweep result is identical in debug and release and
across platforms.

## Considerations

- A reader that meets `true`, or an artifact without the fields, treats it as foreign and refuses it; absence is
  never read as false.
- Compile-fail tests are sensitive to compiler diagnostics; the expected output is matched on the error code and
  the item name, not the full text, so a toolchain move does not make the gate flaky.
- The sweep's locator table is the list of exporters; it must grow with every new exporting verb (BD-303 extends
  it at M3).
- RISK-11 and the safety chapter's rule "nothing authorizes" both rest on this gate.
