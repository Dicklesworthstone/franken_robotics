## Background

Kernel reflection promotes selected instance certificates from `Certified` to `Proved`: a checker function
defined in Lean with a soundness theorem lets the Lean kernel prove an instance by evaluating the function. Four
reflectors are planned, in this order: the Farkas witness check, exact LDLᵀ with positive pivots, normal-form
equality of polynomial expressions with rational coefficients, and replay of a class-E rewrite trace on
straight-line programs. The first two are the pilot (BD-382, GATE-LEMMA-05). This bead is the remaining two and
the general, budgeted form of the verb `prove.reflect`.

It exists on one branch only. KILL-REFLECT (decision bead N12-32) fires if GATE-LEMMA-05 fails after one repair
cycle or if no reflector's closure avoids the blocked Mathlib modules; its fallback is that instance certificates
stay `Certified` and reflection is parked in the killed-idea register. If it fires, this bead is closed as not
built (`superseded`, citing the decision record). ADR-LEMMA-05 binds the design: reflection is never the default, and instances are checked by kernel
evaluation, never by a compiled evaluator, so the trusted base stays at the kernel and the soundness theorems.
Tier: Frontier. Ceiling: more kinds of instance certificate can be relabelled `Proved` (kernel identities through
`polyEq`, accepted rewrites through `replay`); no design decision and no speed changes by that alone.

## Scope

In: the Lean definitions `PolyExpr`, `polyEq`, `Slp`, `Trace`, `replay`; their soundness theorems, sealed; one
specimen each proved by kernel evaluation; generation of instance files from `poly-identity` and `rewrite-trace`
bundles; the admission rule of `prove.reflect` from the budget table; refusals; the budget rows of the two new
reflectors, measured with N12-27's harness.
Out: the first two reflectors and the verb's skeleton (BD-382); the budget table's schema, harness and the rows
of `farkas` and `ldlt-pos` (N12-27); the auditor's own `rewrite-trace` checker (N12p2-02); statement binding
(N12-24).

0. Registration before proof (CARD-T-35's rule): before any proof of these two theorems is written, this bead
   appends to `lean/Frob/Statements/T35.lean` the specifications `PolySpec` and `ReplaySpec` over `PolyExpr`,
   `Slp` and `Trace` in the form N12-26 recorded as clean (or clean in its alternative form), and the two lines
   `Frob.Statements.T35.polyEq.Statement` and `Frob.Statements.T35.replay.Statement`, byte-equal to the text
   CARD-T-35 registered for them; it records their definition hashes in the `poly-eq` and `replay` sub-entries
   (status `hypothesis`). The sealed receipts then move those sub-entries to `checked`, with both checker
   identities and each function's definition hash, by CARD-T-35's law tests run against this bead's code.

1. `PolyExpr` is an inductive type of polynomial expressions over variables indexed by ℕ with constants in ℚ
   (constant, variable, sum, product, negation, natural power). `polyEq` normalizes both sides to a canonical
   sparse form (a sorted list of monomials with nonzero rational coefficients) and compares the lists. Soundness:
   normalization preserves evaluation in every commutative ℚ-algebra, by structural induction; equal normal
   forms evaluate equally.
2. `Slp` is a straight-line program over +, −, ×, ÷, √ and literals; `Trace` is a list of class-E steps from the
   closed table (commutation of + and ×, common-subexpression elimination, dead-code elimination, scaling by a
   power of two, scheduling, and the exact simplifications). `replay` applies each step, checking its syntactic
   precondition, and returns the resulting program or `none`. Soundness: every rule preserves the denotation
   over ℝ (with division and square root given total denotations in the usual Lean convention, and the trace
   valid only where the source's side conditions hold; those conditions are hypotheses of the registered
   statement if the closure analysis of N12-26 required moving off ℝ). `Slp` deliberately omits the
   operations of the kernel IR that the auditor's `rewrite-trace` checker also handles (select, compare, min,
   max, abs) and with them the rule "select with a constant predicate": a `rewrite-trace` bundle whose program
   uses one of them is not reflectable, and admission refuses it as `kind not reflectable` with FROB-REF-823 (the
   row's "a kind with no enabled reflector"; DESIGN: a payload the reflector's input type cannot express is
   treated as that kind; exit 3; its class stays `Certified`).
3. Specimens: `polyEq` on the Cayley orthogonality identity of the M0 kernel (the cleared-denominator form in the
   three entries of ω); `replay` on a three-step trace (commutation, common-subexpression elimination,
   power-of-two scaling) of a small program. Negative specimens: a polynomial pair differing in one coefficient
   (evaluates to `false`); a trace containing a reassociation, which is not a constructor of `Trace` at all, so
   the instance file fails to elaborate, and a trace whose step has a false precondition (returns `none`).
4. Instance generation: from a `poly-identity` bundle, `frob-lemma` emits the two `PolyExpr` literals; from a
   `rewrite-trace` bundle, the `Slp` and `Trace` literals; the binding check requires the generated literals to
   hash to the bundle payload.
5. Admission in `prove.reflect` (kind `run`, tier F): given a certificate, (a) the auditor's verdict on it must
   be `accept` (otherwise the auditor's own code for the first failing rule, as in BD-382); (b) its kind must map
   to an enabled reflector (`lp-farkas` → `farkas`; `rational-ldlt` → `ldlt-pos`; `poly-identity` → `poly-eq`;
   `rewrite-trace` → `replay`), otherwise FROB-REF-823, and the reflector must pass CARD-T-35's enabling rule,
   otherwise FROB-REF-724 (exit 5); (c) its size and bit measures must fall inside the reflection budget table
   `registries/reflection-budget.toml` of N12-27 for the pinned checker; otherwise the job is refused before any
   Lean process starts with FROB-REF-701 (exit 4) and the certificate stays `Certified` with the reason
   `over reflection budget` and the cell it missed; a table whose pins differ from the running checker's is stale
   and has no cell for the running checker, so every instance is refused the same way, the message naming the
   stale pin (the fail-closed default of OPEN-LEMMA-3); (d) the job
   runs with a wall limit of twice the table's time; a timeout returns `unknown` for the promotion and never a
   failure of the certificate.
6. Output: evidence of class `Proved` with receipts (soundness capsule hash, instance capsule hash, stock Lean
   and `fln` builds); the theorem-card registry row of T-35 lists the enabled reflectors.
7. Budget rows for `poly-eq` and `replay` (N12-27 measured `farkas` and `ldlt-pos` only, and step 5(c) admits
   nothing for a reflector with no rows). With N12-27's harness (`tools/pilots/reflect_cost/`, same method: true
   instances generated from a seed, three repetitions under stock Lean and under `fln`, a hard stop at 600 s, cells
   admitted at half the 60 s budget), this bead sweeps (DESIGN) `poly-eq` over variables v ∈ {3, 6, 12, 18},
   total degree d ∈ {2, 4, 8} and coefficient bits b ∈ {8, 32, 64}, and `replay` over program nodes
   {8, 64, 512} and trace steps {3, 30, 300}, and appends the rows to `registries/reflection-budget.toml` with
   the pins and host fingerprint. False instances (a coefficient changed; a step with a false precondition) are
   the sweep's controls, as in N12-27.

## Acceptance criteria

- [ ] The `PolySpec` and `ReplaySpec` specifications and the two `Statement` lines are in `T35.lean`, byte-equal to
      CARD-T-35's registered text, with a commit date earlier than the first proof commit of either theorem.
- [ ] `T35_polyEq_sound` and `T35_replay_sound` are compiled by stock Lean, re-checked by `fln`, bound to their
      registered statements and sealed; no `sorry`, no axiom outside the whitelist, no `native_decide`; CARD-T-35's
      law tests (`crates/frob-lemma/tests/cards/t35.rs`, `lean/tests/reflect/`) pass for the `poly-eq` and `replay`
      sub-entries, which move from `hypothesis` to `checked`.
- [ ] `registries/reflection-budget.toml` holds measured rows for `poly-eq` and `replay` at the current pins;
      both specimens fall inside an admitted cell.
- [ ] Each proves its specimen by kernel evaluation within the budget recorded for its table cell.
- [ ] Negative controls: the one-coefficient mutant evaluates to `false`; a reassociation cannot be expressed as
      a `Trace` step; a trace with a false precondition returns `none`; in each case no `Proved` evidence is
      produced.
- [ ] `prove.reflect` refuses an over-budget instance before starting a job and leaves its class `Certified`; it
      refuses a certificate the auditor does not accept; a timeout yields `unknown`.
- [ ] The differential test agrees: on 1,000 random polynomial pairs and 1,000 random traces (programs and steps
      drawn from the subset `Slp` and `Trace` express) the Lean function (run at development time) and the
      auditor's `poly-identity` and `rewrite-trace` checkers return the same verdicts; a program with a select is
      refused by admission as not reflectable.
- [ ] If KILL-REFLECT fired, this bead is closed with the typed reason `superseded` and the identifier of the
      decision record `docs/adr/ADR-KILL-REFLECT-M5.md` (N41-17's rule 5 for a dependent that needs the killed
      capability), and nothing is built.

### End-to-end script and logging

This bead writes and runs the second phase of `scripts/e2e/lemma_reflect.sh` (the script and its phase 1 are bead
N12-38's, which closes without waiting for this phase): it runs
`frob prove reflect --certificate <hash> --reflector poly-eq --key rf-p2-polyeq --json` and the same with
`--reflector replay --key rf-p2-replay`, then one over-budget instance, one `rewrite-trace` bundle whose program
uses a select, and one certificate the auditor rejects (each with its own key). Its NDJSON lines (STD-E2E helper,
the script's log file) carry `ts`, `script`, `bead` ("N12-28"), `step` (`phase2/<reflector>/<case>`), `event`, the
exact command line, exit code (8 while a job runs under `--sync-wait-ms`, then the final code), wall time, the
envelope's `evidence` block (class `Proved` or `Certified`, tier F, both capsule hashes and checker identities),
the admission decision with the budget-table cell and the table's BLAKE3, a `metric` line per specimen with the
kernel evaluation time against the cell's budget, a `refusal` line per refused case with its code (701, 823, the
auditor's code) and exit code, and on a failure the first differing value and the instance file path. The phase
adds its counts to the script's `summary` line.

### Known answers and negative controls

KA-211 (the Cayley identity's certificate accepts; one changed coefficient rejects) is the instance behind the
`polyEq` specimen; KA-212 (a reassociation filed as class E is rejected) is the instance behind the `replay`
negative control; the single-precision witness (a = 10⁸, b = −10⁸, c = 1: (a + b) + c = 1, a + (b + c) = 0) shows
why reassociation is excluded. Determinism: capsule hashes reproducible on the pins.

## Considerations

- `replay_sound` states equality over ℝ; bit-exactness of class E in floating point is a test, not this theorem,
  and reports must not blur the two.
- Normalizing large polynomials inside a kernel is expensive; the budget table for `poly-eq` may admit only
  small identities, in which case most kernel identities stay `Certified`.
- OPEN-LEMMA-2 and OPEN-LEMMA-3 defaults apply: elementary specifications; specimens that fit the budget.
- Refusal codes, as the `prove.reflect` row of VERBS-prove lists them: FROB-REF-823 (chapter code, N12-REF: a
  kind with no enabled reflector, here also a payload the reflector's type cannot express; exit 3); FROB-REF-701
  (appended, N32-REF: an instance outside the reflection budget table for the pinned checker, refused before any
  Lean process starts; the certificate stays `Certified` with the reason `over reflection budget` and the cell it
  missed; exit 4); FROB-REF-724 (appended: the verb or a reflector not in this build, after KILL-REFLECT or for a
  reflector that fails the enabling rule; exit 5). None is a new code and none is raised by the auditor.
