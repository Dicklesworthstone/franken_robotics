## Background

Kernel reflection promotes selected instance certificates from `Certified` to `Proved`: a checker function
defined in Lean with a soundness theorem lets the Lean kernel prove an instance by evaluating the function. Four
reflectors are planned, in this order: the Farkas witness check, exact LDLᵀ with positive pivots, normal-form
equality of polynomial expressions with rational coefficients, and replay of a class-E rewrite trace on
straight-line programs. The first two are the pilot (BD-382, GATE-LEMMA-05). This bead is the remaining two and
the general, budgeted form of the verb `prove.reflect`.

It exists on one branch only. KILL-REFLECT (decision bead N12-32) fires if GATE-LEMMA-05 fails after one repair
cycle or if no reflector's closure avoids the blocked Mathlib modules; its fallback is that instance certificates
stay `Certified` and reflection is parked in the killed-idea register. If it fires, this bead is closed as not
built. ADR-LEMMA-05 binds the design: reflection is never the default, and instances are checked by kernel
evaluation, never by a compiled evaluator, so the trusted base stays at the kernel and the soundness theorems.
Tier: Frontier. Ceiling: more kinds of instance certificate can be relabelled `Proved` (kernel identities through
`polyEq`, accepted rewrites through `replay`); no design decision and no speed changes by that alone.

## Scope

In: the Lean definitions `PolyExpr`, `polyEq`, `Slp`, `Trace`, `replay`; their soundness theorems, sealed; one
specimen each proved by kernel evaluation; generation of instance files from `poly-identity` and `rewrite-trace`
bundles; the admission rule of `prove.reflect` from the budget table; refusals.
Out: the first two reflectors and the verb's skeleton (BD-382); the budget table (N12-27); the auditor's own
`rewrite-trace` checker (N12-18); statement binding (N12-24).

## Technical approach

```lean
-- DESIGN: statements fix intent. No `sorry`, no added axiom, no `native_decide`.

/-- Normal-form equality of polynomial expressions with rational coefficients. -/
def polyEq (p q : PolyExpr) : Bool := …
theorem polyEq_sound (p q : PolyExpr) :
    polyEq p q = true → ∀ (R : Type) [CommRing R] [Algebra ℚ R] (ρ : ℕ → R), p.eval ρ = q.eval ρ := …

/-- Replay of a class-E rewrite trace on straight-line programs. Equality is over ℝ; bit-exactness of
    class E in floating point is a test, not this theorem. -/
def replay (src : Slp) (t : Trace) : Option Slp := …
theorem replay_sound (src tgt : Slp) (t : Trace) :
    replay src t = some tgt → ∀ ρ : ℕ → ℝ, src.denote ρ = tgt.denote ρ := …
```

1. `PolyExpr` is an inductive type of polynomial expressions over variables indexed by ℕ with constants in ℚ
   (constant, variable, sum, product, negation, natural power). `polyEq` normalizes both sides to a canonical
   sparse form (a sorted list of monomials with nonzero rational coefficients) and compares the lists. Soundness:
   normalization preserves evaluation in every commutative ℚ-algebra, by structural induction; equal normal
   forms evaluate equally.
2. `Slp` is a straight-line program over +, −, ×, ÷, √ and literals; `Trace` is a list of class-E steps from the
   closed table (commutation of + and ×, common-subexpression elimination, dead-code elimination, scaling by a
   power of two, scheduling, and the exact simplifications). `replay` applies each step, checking its syntactic
   precondition, and returns the resulting program or `none`. Soundness: every rule preserves the denotation
   over ℝ (with division and square root given total denotations in the usual Lean convention, and the trace
   valid only where the source's side conditions hold; those conditions are hypotheses of the registered
   statement if the closure analysis of N12-26 required moving off ℝ).
3. Specimens: `polyEq` on the Cayley orthogonality identity of the M0 kernel (the cleared-denominator form in the
   three entries of ω); `replay` on a three-step trace (commutation, common-subexpression elimination,
   power-of-two scaling) of a small program. Negative specimens: a polynomial pair differing in one coefficient
   (evaluates to `false`); a trace containing a reassociation, which is not a constructor of `Trace` at all, so
   the instance file fails to elaborate, and a trace whose step has a false precondition (returns `none`).
4. Instance generation: from a `poly-identity` bundle, `frob-lemma` emits the two `PolyExpr` literals; from a
   `rewrite-trace` bundle, the `Slp` and `Trace` literals; the binding check requires the generated literals to
   hash to the bundle payload.
5. Admission in `prove.reflect` (kind `run`, tier F): given a certificate, (a) the auditor's verdict on it must
   be `accept`; (b) its kind must map to an enabled reflector (`lp-farkas` → `farkas`; `rational-ldlt` →
   `ldlt-pos`; `poly-identity` → `poly-eq`; `rewrite-trace` → `replay`); (c) its size and bit measures must fall
   inside the reflection budget table for the pinned checker; otherwise the job is refused before any Lean
   process starts and the certificate stays `Certified` with the reason `over reflection budget` and the cell it
   missed; (d) the job runs with a wall limit of twice the table's time; a timeout returns `unknown` for the
   promotion and never a failure of the certificate.
6. Output: evidence of class `Proved` with receipts (soundness capsule hash, instance capsule hash, stock Lean
   and `fln` builds); the theorem-card registry row of T-35 lists the enabled reflectors.

## Acceptance criteria

- [ ] `polyEq_sound` and `replay_sound` are compiled by stock Lean, re-checked by `fln`, bound to their registered
      statements and sealed; no `sorry`, no axiom outside the whitelist, no `native_decide`.
- [ ] Each proves its specimen by kernel evaluation within the budget recorded for its table cell.
- [ ] Negative controls: the one-coefficient mutant evaluates to `false`; a reassociation cannot be expressed as
      a `Trace` step; a trace with a false precondition returns `none`; in each case no `Proved` evidence is
      produced.
- [ ] `prove.reflect` refuses an over-budget instance before starting a job and leaves its class `Certified`; it
      refuses a certificate the auditor does not accept; a timeout yields `unknown`.
- [ ] The differential test agrees: on 1,000 random polynomial pairs and 1,000 random traces the Lean function
      (run at development time) and the auditor's `poly-identity` and `rewrite-trace` checkers return the same
      verdicts.
- [ ] If KILL-REFLECT fired, this bead is closed with the typed reason "killed: fallback adopted" and nothing is
      built.

## Considerations

- `replay_sound` states equality over ℝ; bit-exactness of class E in floating point is a test, not this theorem,
  and reports must not blur the two.
- Normalizing large polynomials inside a kernel is expensive; the budget table for `poly-eq` may admit only
  small identities, in which case most kernel identities stay `Certified`.
- OPEN-LEMMA-2 and OPEN-LEMMA-3 defaults apply: elementary specifications; specimens that fit the budget.
- Refusal codes (DESIGN; the Lemma table defines none for these two cases, so they are the Tether registry's,
  N32-REF): an instance beyond the evaluation budget is refused with FROB-REF-701 (the estimate's upper end exceeds
  the remaining budget; the estimate is attached; exit 4) before any job is planned, and its class stays
  `Certified`; once KILL-REFLECT has fired, `prove.reflect` is refused with FROB-REF-724 (the verb is not
  implemented in this build; exit 5). Neither is a new code and neither is raised by the auditor.
