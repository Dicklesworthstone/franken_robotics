## Background

Kernel reflection is the one route from an instance certificate to class `Proved`: a checker function defined in
Lean with a soundness theorem lets the kernel prove an instance by evaluating the function. It is Frontier, and
its expected value was scored low at plan time; it was kept as a pilot because it is the only such route. Its
ceiling is stated in advance: reflection relabels a few instance certificates from `Certified` to `Proved`; by
itself it changes no design decision and no speed.

The pilot (BD-382) builds the Farkas and rational LDLᵀ reflectors and measures GATE-LEMMA-05: both soundness
theorems compiled by stock Lean and re-checked by `fln`, and each specimen proved by kernel evaluation within
60 s (TARGET). KILL-REFLECT is the kill gate. Trigger: GATE-LEMMA-05 fails after one repair cycle, or no
reflector's closure avoids the blocked Mathlib modules. Fallback, named in advance: instance certificates stay
`Certified`, and reflection is parked in the killed-idea register. Decided at M5. This bead records the decision
as an ADR. The second half of the trigger can be met early: if the closure audit (N12-26) finds every reflector's
statement blocked, the decision is taken without waiting for proofs.

## Scope

In: reading the pilot record and the closure audit; evaluating both halves of the trigger; the ADR; applying the
branch, including the entry in the killed-idea register if the gate fires.
Out: the pilot (BD-382); the cost sweep (N12-27); the further reflectors (N12-28), which exist only if this gate
does not fire.

## Technical approach

1. Inputs, each read with its receipt hash: GATE-LEMMA-05's record, written by the end-to-end run of N12-38
   (`scripts/e2e/lemma_reflect.sh`, its `summary` receipt); the pilot record `PILOT-LEMMA-03` in
   `crates/frob-conformance/registry/pilots.toml` with its appended result (BD-382); the closure audit's table for
   all four planned reflectors (N12-26); the answer to OPEN-LEMMA-3 and the budget table (N12-27). From them, for
   each of the two pilot reflectors: whether its soundness theorem compiled under stock Lean, whether `fln`
   re-checked it, its module closure and blocked intersection, the specimen's kernel evaluation time under both
   checkers, peak memory, and the negative controls' outcomes; the repair cycle's description if one was used
   (N40-03's reading: one bounded attempt opened by a log line naming the failed receipt and closed by a
   re-measurement on the same fixture with the same threshold; for example restating a specification in a more
   elementary form, or changing the rational representation to cut evaluation time).
2. Trigger evaluation.
   - Half A: GATE-LEMMA-05 fails after one repair cycle. The gate needs both reflectors; one reflector passing
     and the other failing is a failed gate.
   - Half B: no reflector's closure avoids the blocked modules (all four `blocked` in the closure audit, or both
     pilot theorems' finished closures blocked).
   - The gate fires if A or B holds.
3. Branches.
   - Fires: `prove.reflect` is removed from the verb registry's enabled set (the registry row stays with status
     `parked`, so the name is not reused); instance certificates stay `Certified` everywhere; card T-35's
     registry route moves to `parked`; the reflectors' Lean files are kept under `lean/Frob/Reflect/` but
     excluded from the build; a row is added to the killed-idea register with the calculation that killed it
     (the measured evaluation times, or the blocking modules) and the condition that would reopen it (upstream
     item FD-FLN-01 landing, or a measured kernel-evaluation cost within budget on a later pin); N12-28 is closed
     as not built (typed reason `superseded` with this ADR's identifier, N41-17's rule 5); GATE-LEMMA-05 takes
     status `killed` with detail `KILL-REFLECT: instance certificates stay Certified` (N40-03's propagation).
     Farkas soundness (card T-21's general half) may still be sealed as an ordinary Lean theorem if its closure
     permits: parking reflection does not park the theorem.
   - Does not fire: `prove.reflect` stays enabled for the two reflectors within the budget table (N12-27);
     N12-28 is unblocked.
4. Partial outcome rule (DESIGN, to remove ambiguity): if exactly one reflector meets the gate's conditions after
   the repair cycle, the gate has failed and the kill fires as written; the surviving reflector is recorded in the
   killed-idea register as the evidence for reopening, and no partial reflection ships. A different treatment
   needs a dated amendment before the measurement.
5. The record follows N40-03's decision format at `docs/adr/ADR-KILL-REFLECT-M5.md` (the one directory for
   decision records): the kill gate; the milestone; the trigger as registered and the amendments applied (or their
   absence); each measured value with its receipt hash set beside the trigger's number (60 s; blocked
   intersection 0); which half fired, if any; the outcome from N40-03's closed set (`fired`, `not-fired`, or
   `deferred` with `deferred_to` and the reason when a second repair cycle is funded, which N40-03 counts as a
   deferral); the fallback now in force and
   the name the capability carries ("instance certificates: Certified; reflection parked"); the beads re-read
   (N12-28, the T-35 and T-21 card rows, the `prove.reflect` row), each "stands on the fallback" or "superseded by
   this ADR"; what changes downstream; and the session that recorded it, which is not a session that implemented
   BD-382 or ran its pilot. The KILL-REFLECT row of `registries/gates.toml` gets its
   `decision = { outcome, adr, date, session, receipts }`, `receipts` holding the hashes of GATE-LEMMA-05's
   receipt and of the closure and budget records under `receipts/gates/` (at least one, as N40-03 requires for
   `not-fired`); no other bead writes that row. The pilot record's last result is cited by its receipt, never
   copied.

## Acceptance criteria

- [ ] `docs/adr/ADR-KILL-REFLECT-M5.md` exists at M5 with every field N40-03 requires and both halves of the
      trigger evaluated against the recorded measurements, each with its receipt hash.
- [ ] The gate register rows are consistent: GATE-LEMMA-05 is `pass` or `killed` with the KILL-REFLECT detail;
      the KILL-REFLECT row's `decision` carries outcome, ADR path, date, session and receipts, and the register's
      check refuses the record if the session implemented BD-382 or if a `not-fired` entry cites no receipt.
- [ ] On the fired branch: `frob prove reflect` returns the verb-parked refusal (FROB-REF-724); no artifact
      carries `Proved` obtained by reflection; the killed-idea register has the new row with the killing
      calculation and the reopening condition; N12-28 is closed with a typed reason.
- [ ] On the surviving branch: the two reflectors are enabled only inside the budget table.
- [ ] Negative control of the decision procedure: on three synthetic records (both pass; one passes and one takes
      75 s after repair; all closures blocked) it returns not-fired, fired by half A, fired by half B.

## Test plan

### Unit tests

`crates/frob-lemma/tests/kill_reflect.rs`: `both_pass_does_not_fire`; `one_slow_after_repair_fires`
(75 s > 60 s); `all_closures_blocked_fires_without_proofs`; `fired_branch_parks_verb_and_card`;
`farkas_soundness_theorem_survives_parking` (the general theorem's capsule, if sealed, remains listed under
T-21).

### End-to-end script and logging

`scripts/e2e/lemma_reflect.sh` (bead N12-38, a dependency) ends by printing the trigger evaluation from the pilot
record. This bead adds `scripts/e2e/decide_kill_reflect.sh` (sources the STD-E2E helper; NDJSON at
`target/e2e-logs/decide_kill_reflect/<utc-timestamp>.ndjson` with a transcript): it reads the GATE-LEMMA-05
`summary` receipt of `lemma_reflect.sh`, the `PILOT-LEMMA-03` result, the closure table of N12-26 and the budget
table of N12-27; recomputes both halves of the trigger; asserts that they agree with the ADR and with the
`decision` of the KILL-REFLECT row; and prints the branch. On the fired branch it runs
`frob prove reflect --certificate <stance bundle> --reflector farkas --key kr-parked-1 --json` and asserts
FROB-REF-724, exit 5, `reason = "killed: KILL-REFLECT"`, then `frob prove list --json` and asserts that the T-35
row is `parked` and that the T-21 general route, if sealed, is still listed; on the surviving branch it asserts that
an instance outside the budget table is refused with 701. Every line carries `ts`, `script`, `bead` ("N12-32"),
`step`, `event`, the exact command line, exit code, wall time, the envelope's `evidence` block where a verb runs,
the digests of the four inputs, each half of the trigger with its measured value and threshold (60 s; blocked
intersection 0), and on failure the first differing value and the input paths; a final `summary` line gives the
outcome and `gates: ["KILL-REFLECT", "GATE-LEMMA-05"]`.

### Known answers and negative controls

KA-227 states the pilot's pass condition (each specimen evaluates to `true` in the kernel within 60 s) and its
falsifier (a closure that cannot avoid a blocked module, or a specimen not evaluated within 60 s). The three
synthetic records are the controls of the decision procedure. Determinism: a pure function of the record.

## Considerations

- A kill gate is never quietly re-scoped: raising the 60 s threshold after seeing 75 s is an amendment that must
  be dated before the measurement.
- Parking costs little: the class of instance certificates stays `Certified`, which every gate that matters
  accepts; no design decision depends on `Proved` instances.
- If the pilot passes, OPEN-LEMMA-3's budget table still limits reflection to instances that fit.
- Refusal codes (DESIGN; the Lemma table defines none for these two cases, so they are the Tether registry's,
  N32-REF): an instance beyond the evaluation budget is refused with FROB-REF-701 (the estimate's upper end exceeds
  the remaining budget; the estimate is attached; exit 4) before any job is planned, and its class stays
  `Certified`; once KILL-REFLECT has fired, `prove.reflect` is refused with FROB-REF-724 (the verb is not
  implemented in this build; exit 5). Neither is a new code and neither is raised by the auditor.
