## Background

A capability that emits a certificate about a family of designs is implemented only when the certificate travels
in a `.frobcert` bundle and the independent offline auditor accepts it on a machine with neither the agent nor a
GPU, and rejects the registered mutations of it. GATE-LEMMA-04 (claim Proof; M1, repeated at M4) is that
condition for the first mission slice: the slice ships its inner cells and its exclusions as bundles; a re-check
on a second machine accepts every one; the seeded-defect suite yields zero accepted false certificates. One
accepted false certificate fails the gate.

The first mission slice at M1 has three families on the CPU: the stance family (400 N on four point feet at
(±1/3, ±b) m, centre of mass anywhere in a rectangle of half-sizes 150 mm and 75 mm, each foot commanding a force
in [0, 160] N, half-width b free: every b ≥ 3/14 m is inner with the corner allocation (160, 130, 110, 0) N as
witness and every b < 3/14 m is excluded by a dual vector), the docking family (a unit mass, three unit ticks,
hidden gain 1 or 2, one velocity packet with read error at most ε: with the packet on time a robust causal policy
exists exactly when ε < (U + ½)/4, with the packet late none exists), and the pusher battery. This bead is the
end-to-end script that drives the path a user takes (ask the mission, bundle the answer, carry it to another
machine, check it there) and seeds defects to show that the check can fail. The same script, with the profile
`m4`, measures the gate again on the family answers at scale (BD-364).

## Scope

In: `scripts/e2e/lemma_second_machine.sh` with profiles `m1` and `m4`; the transfer package; the second-machine
runner; the seeded-defect driver; the gate record at M1.
Out: the mission solvers and the bundle writer (BD-128 to BD-135); the per-kind mutation corpus (N12-34) and the
200-mutant campaign (BD-136); the M4 writer and gate record (BD-364).

## Technical approach

Roles: machine A produces (the development machine at M1; the GPU host at M4); machine B checks (any second
machine reachable by `ssh`, named by `FROB_E2E_SECOND_HOST`; with no second host configured the script falls back
to an isolated container on A and records the gate as `not run` for the second-machine clause, which is not a
pass).

Steps (plain shell, sources the STD-E2E helper, seed-explicit, idempotent):
1. `start` on A: commit, host fingerprints of A and B, profile.
2. Produce on A through the real binary: `frob mission synthesize` on each family fixture of the profile
   (`--json`, explicit idempotency keys and budgets), then `frob prove bundle` for each answer and
   `frob prove list --json`; assert the in-tree check reports `accept` for every entry and that each answer cites
   one Merkle root.
3. Package: copy the `.frobcert` files and a copy of `crates/frob-cert` (source only) into a transfer directory;
   record every bundle's BLAKE3 on A.
4. On B: build `frob-verify` from the copied crate with its own stable toolchain and no network; assert the
   machine has no project checkout on its path and (profile `m4`) no GPU is used; run the binary on every bundle
   under `env -i`; re-serialize each and record digests on B.
5. Assert, per bundle: verdict on B is `accept`; digest on B equals digest on A; the class reported equals the
   class the answer claimed; the three authorization flags are false.
6. Known-answer assertions on the content (profile `m1`): the stance inner cell begins at b = 3/14 m with witness
   (160, 130, 110, 0) N; the exclusion at b = 1/5 m carries the dual value 165 N against 160 N; the docking cell
   (U, ε) = (¾, ¼) with the packet on time is inner; every late-packet cell is excluded.
7. Seeded-defect suite. Bundle-level defects, applied to copies of the shipped bundles with all digests
   recomputed: a changed coefficient; reordered quantifiers; a missing side condition; a wrong frame or unit (the
   first moment (60, 30) written where the torque (30, −60, 0) N·m belongs); a fabricated kind; a flag set to
   true; a boundary opened or closed (the end 3/14 certified as excluded, or the open docking bound 5/16 claimed
   as attained). Producer-level defects, using producer builds with planted lowering defects selected by a test
   feature: a swapped foot order; an omitted force floor; an authority tag written as independent when the
   mission says passive; an enclosure narrowed in the last place. For every seeded defect: assert B's verdict is
   `reject` (or, for producer-level defects caught earlier, that the verb withheld the answer and downgraded the
   cell). A false certificate is a seeded-defect bundle that B accepts: the count must be zero.
8. Amendment step (exercises polarity, N12-05): amend the docking read error and log, per certificate, the
   recorded polarity, the predicted survival and the fresh verdict; amend the stance authority to passive equal
   springs and assert that the inner cell at b = ¼ m is withdrawn (active allocation (155, 135, 105, 5) N; springs
   deliver (175, 115, 85, 25) N against the 160 N rating).
9. Decision-effect read-out (N12-12): `frob prove list --effects --json`; log the counts.
10. `summary`: bundles shipped, accepted on B, digest matches, seeded defects, false accepts (threshold 0), wall
    time of the full re-check on B, gates touched; write the gate record.

Logging: newline-delimited JSON under `target/e2e-logs/lemma_second_machine/<utc-timestamp>.ndjson` plus a
transcript; every line has `ts`, `script`, `bead` (`N12-35`), `step`, `event`, the exact command line (with the
host it ran on), exit code, wall time, the envelope's `evidence` block, measured values and thresholds, both
digests where state is compared, and on failure the first differing value and the artifact paths. Logs never
contain private-scene data; the mission fixtures are synthetic and labelled so.

## Acceptance criteria

- [ ] The script exits 0 with a second host configured and non-zero on any failed assertion; with no second host
      it exits with the distinct `not run` status for the gate.
- [ ] GATE-LEMMA-04 at M1 (TARGET): the first mission slice ships its inner cells and its exclusions as bundles;
      the re-check on the second machine accepts every one; zero accepted false certificates. Recorded with the
      counts; one accepted false certificate fails the gate.
- [ ] Bundle digests are identical on A and B; the re-check of the whole slice on B is timed (the companion
      mission gate asks for under 10 s in total; the measured value is logged).
- [ ] Every seeded defect is rejected or withheld, each logged with its first failing rule.
- [ ] The amendment step's predictions match fresh evaluation.
- [ ] The log validates against the shared schema and ends with a `summary` line naming GATE-LEMMA-04.

## Test plan

### Unit tests

Script self-tests under `scripts/e2e/tests/`: `second_machine_selftest_false_accept.sh` (a checker build on B
with the typed-field rule disabled accepts the moment-as-torque defect; the script must fail and report one false
accept); `second_machine_selftest_digest_drift.sh` (a bundle altered in transit is detected by digest mismatch);
`second_machine_selftest_no_host.sh` (records `not run`).

### End-to-end script and logging

This bead is the script; steps and logging as above.

### Known answers and negative controls

KA-207, KA-208, KA-209, KA-210, KA-219 (zero accepted false certificates; a second machine accepts every shipped
bundle), KA-224 (polarity on the docking and stance fixtures). The seeded defects are the negative controls;
the self-tests are the negative controls of the script. CX-045 (one policy per world offered for one policy for
all worlds), CX-077, CX-108, CX-114. Determinism lanes: bundle bytes identical twice on A, across worker counts
on A, and between A and B (class D0).

## Considerations

- A truthful unresolved cell is never a false certificate.
- The second machine must not share a filesystem cache or a build directory with A; the script checks that the
  auditor binary on B was built on B.
- OPEN-LEMMA-4 (a second independent checker) is decided before the M4 measurement (N12-29).
- If the mission slice is delayed, the script can be exercised on the checked-in specimens alone, but the gate is
  recorded only on bundles produced by the verbs.
