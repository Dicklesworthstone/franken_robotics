## Background

GATE-LEMMA-01 (M5, claim Proof) measures the bet that proof-carrying kernels are affordable: at least 80% of
derived kernels carry a replayable instance certificate for each identity their manifest declares. Its control
requires that mutated kernels (a flipped sign, a dropped term) have certificates that fail to check. The
North-Star scenario attached to it, NS-11 "a kernel with a certificate": `frob prove kernel K-cay-step` returns a
certificate that the update stays on the group and conserves spatial momentum in free flight, checked by
FrankenSymPy's proof kernel, with a Lean capsule re-checked by FrankenLean where the theorem's dependencies allow;
the certificate says nothing about floating-point results, and its text says so. Every demonstration runs from a
clean checkout through `frob --json`.

This bead is the end-to-end script that performs the coverage run, the offline replay of every certificate, the
control and the demonstration, with structured logs, and writes the gate record that the kill-gate decision
(N12-31) reads.

## Scope

In: `scripts/e2e/lemma_coverage.sh`; its fallback-configuration mode; the gate record. Out: the pipeline and
catalogue (N12-20); the coverage computation and report (BD-379); randomized identity tests (N12-21); the
decision (N12-31).

## Technical approach

Steps (plain shell, sources the STD-E2E helper, idempotent, seed-explicit):
1. `start`: commit, host fingerprint, tool pins (FrankenSymPy, and the Lean and `fln` builds if present), the
   proof-tool registry revision.
2. Regenerate all instance certificates for the kernel library (the producer pipeline); log per (kernel,
   identity): status (`certified`, `budget-exceeded` with the cap, `not-polynomial`, `tested-only`), route,
   operation count, basis size where applicable, wall time, peak memory, certificate and bundle digests.
3. `frob prove list --coverage --json`: assert the schema; recompute the fraction from the rows and assert it
   equals the reported one; log covered, derived and the fraction against thresholds 0.80 (gate) and 0.50 (kill
   trigger).
4. Offline replay: build `frob-verify` from a copy of its crate; run it on every bundle counted as covering;
   assert `accept` for each; a counted certificate that does not replay is subtracted and the run fails.
5. Hash binding: for a sample of kernels, assert that the certificate's embedded kernel hash equals the kernel's
   `KernelId`, and that a certificate swapped in from another kernel is not counted.
6. Control: for at least ten kernels chosen by a seeded draw, derive two mutants each (a flipped sign; a dropped
   term), run the pipeline, and assert that no certificate is produced; forge a certificate for each mutant by
   reusing the original's payload with the mutant's hash and assert that the auditor rejects it.
7. Randomized tests: for every (kernel, identity) with status `budget-exceeded`, run the exact-rational
   randomized identity test and log degree bound, sample-set description, the error bound and the verdict; assert
   class `Tested` in the evidence block.
8. NS-11: `frob prove kernel K-cay-step --json`; assert that the output lists the group-membership identity and
   the free-flight momentum identity, each with certificate hash and checker identity; that a Lean capsule hash
   is present if and only if the card's Lean route is `checked`; and that the floating-point non-claim sentence
   and the six `not_claimed` strings are present; assert the flags are false.
9. Repeatability: run step 2 a second time and assert byte-identical certificates.
10. Trigger read-out: print coverage after the recorded repair cycle against 50%; with `--fallback-config`,
    re-run steps 3 and 8 under the identity-tests configuration and assert that no kernel manifest or
    `prove.kernel` output contains the word "certificate".
11. `summary`: coverage, replayed count, mutants caught, randomized tests run, gates touched; write the gate
    record with the measured fraction.

Logging: newline-delimited JSON under `target/e2e-logs/lemma_coverage/<utc-timestamp>.ndjson` and a transcript;
each line carries `ts`, `script`, `bead` (`N12-36`), `step`, `event`, the command line, exit code, wall time,
the `evidence` block of each verb response, measured values with thresholds, digests, and on failure the first
differing value and artifact paths.

## Acceptance criteria

- [ ] The script exits 0 when all assertions hold (it does not require the coverage threshold to be met in order
      to complete: the fraction is recorded and the gate status follows from it) and non-zero when an assertion
      about consistency, replay, binding or the control fails.
- [ ] GATE-LEMMA-01 is recorded with the measured fraction, commit, command, output and receipt hash; the status
      is `pass` at or above 80%, otherwise `fail`.
- [ ] Every counted certificate replays offline; every mutant yields no certificate and its forged certificate is
      rejected.
- [ ] NS-11 is demonstrated from a clean checkout and its output carries the non-claim text.
- [ ] Certificates are byte-identical across two runs.
- [ ] The log validates against the shared schema and ends with a `summary` naming GATE-LEMMA-01 and KILL-LEMMA.

## Test plan

### Unit tests

Script self-tests under `scripts/e2e/tests/`: `coverage_selftest_inflated_fraction.sh` (a report whose fraction
disagrees with its rows fails the script); `coverage_selftest_unreplayable_counted.sh` (a counted certificate
that the auditor rejects fails the script); `coverage_selftest_mutant_certified.sh` (a producer build that
certifies a flipped-sign mutant fails the script and logs the kernel).

### End-to-end script and logging

This bead is the script; steps and logging as above.

### Known answers and negative controls

KA-211, KA-220. The mutated kernels are the gate's negative controls; the three self-tests are the script's.
CX-112 (the certificate is not a statement about floating-point output). Determinism lanes: twice on one machine
(identical bytes); the Mac and the Linux host for replay (identical verdicts).

## Considerations

- The run can be long (one symbolic job per identity); jobs are budgeted individually and the script reports
  which ran out, so a slow tool cannot stall the measurement.
- The script must be run once before and once after the single repair cycle; both records are kept.
- If FrankenLean is not admitted at the time, NS-11 is demonstrated without the capsule and says so.
