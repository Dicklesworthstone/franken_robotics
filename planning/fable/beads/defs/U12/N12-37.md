## Background

GATE-LEMMA-02 (M5, claim Proof): at least three Lean theorem cards compiled by stock Lean, re-checked by `fln`,
and sealed; the capsule verifies from an empty environment. It is the gate of the Lean lane: theorems are written
in stock Lean 4 with Mathlib, compiled by stock Lean, re-checked by FrankenLean's independent kernel
(`check-olean`), sealed (`seal-capsule`) and verified offline (`verify-capsule --require-semantic`). A sealed
capsule has no `sorry`, no axiom outside the pinned whitelist and no `native_decide` (INV-LEMMA-06), and it proves
the registered statement, never a weakened one. Lean work runs on a Linux host, because FrankenLean's suite lock
certifies only `x86_64-unknown-linux-gnu`.

This bead is the end-to-end script that performs the gate's run on the first three cards (the rational gear law
T-15, the level series T-26, Kleene iteration on finite orders T-12), exercises the negative controls, checks the
`lean-capsule` bundle with the offline auditor, and records the gate.

## Scope

In: `scripts/e2e/lemma_lean_capsule.sh`, with BD-381's `scripts/e2e/lemma_lean_seal.sh` as its pipeline stage;
the empty-environment container definition; the gate record.
Out: the pipeline and the proofs (BD-381); binding (N12-24); the closure measurement (N12-23); reflection
(N12-38).

## Technical approach

Steps (plain shell on the Linux host, sources the STD-E2E helper, idempotent):
1. `start`: commit, host fingerprint, Lean version (v4.32.0), Mathlib commit, `fln` build, the whitelist digest.
2. *Stage: the pipeline.* Run `scripts/e2e/lemma_lean_seal.sh` (BD-381) as a stage, with this run's seed: for
   T-15, T-26 and T-12, `lake build Frob.Cards.T<nn>` with stock Lean, `fln check-olean`, `fln seal-capsule`,
   then N12-24's binding check `lean/tools/frob-statement-gen check-binding --capsule target/lean/T<nn>.flncap
   --expect Frob.Statements.T<nn>.Statement` (exit 3 discards the capsule, which is then not counted), and `fln
   verify-capsule --require-semantic` in an empty container; its planted controls; its bundles and their
   verdicts. Its summary is read, its failures fail this script, and its receipt is cited by this run's gate
   record. Every further card present under `lean/Frob/Cards/` (and the one card of the per-card stage below)
   goes through the same five commands in the same order, run by this script, since BD-381's script covers its
   three cards only.
3. For each card, from the stage's `compile` and `check-olean` lines or this script's own run: log the module
   closure (count, bytes, blocked intersection with threshold 0), build wall time and peak memory, and `fln
   check-olean`'s verdict, wall time and peak memory.
4. For each capsule kept after `check-binding`: log capsule path, size and BLAKE3; assert the manifest carries the
   five hashes (translation, environment, kernel binary, definitions, proof) and the axiom list is inside the
   whitelist. A card whose capsule the binding check discarded is not counted as sealed.
5. Empty environment: start a container image that contains only the `fln` binary and the capsule files (no Lean
   toolchain, no Mathlib checkout, no network); run `fln verify-capsule --require-semantic` on each; assert exit 0.
6. Bundle: `frob prove bundle --card T-<nn> --capsule target/lean/T<nn>.flncap --out target/lean/bundles/
   --key llc-T<nn>-<run> --json` for each card (proof kind `lean-capsule`; the card form BD-381 adds); in a
   second empty container holding
   only `frob-verify` (built from its crate alone), the bundle and the capsule file, run `frob-verify`; assert
   `accept`, the trusted-base block naming the FrankenLean kernel, and identical bundle digests inside and
   outside the container. Run `frob-verify` on the bundle without the capsule file and assert `unsupported`.
7. `frob prove list --json`: assert the three cards show a `checked` Lean route with class `Proved`, capsule hash
   and both checker identities (stock Lean build, `fln` build).
8. Negative controls, each asserted to be refused with its reason logged: a card file containing `sorry`; one
   adding an axiom outside the whitelist; one proved with `native_decide`; one importing a blocked module
   (`Mathlib.Analysis.Normed.Algebra.MatrixExponential`); the gear law with a sign mutated (fails to compile);
   the gear law with an added hypothesis r = 1 (compiles, fails the binding check); the gear law stated over ℚ
   only (fails the binding check); a kernel identity proved about definitions transcribed from a different kernel
   hash (fails the binding check); a theorem that restates the proposition instead of naming the constant (fails
   the binding check); N12-24's `SoundFor` fixture with the converse implication (fails the binding check); a
   capsule with one flipped byte (rejected by `verify-capsule` and by the bundle's hash check); a bundle whose
   statement was edited after sealing (rejected by the auditor's query-match rule).
9. Repeatability: seal each card a second time (`fln seal-capsule`, then `check-binding`) and compare its capsule
   hash with the first seal's; a difference is logged with the differing input hash.
10. `summary`: cards sealed (threshold 3), capsules verified from the empty environment, negative controls
    refused, gates touched; the run's receipt, from which this bead, the one measurer of GATE-LEMMA-02, records
    the gate with capsule hashes, closure sizes and peak memory by `cargo run -p frob-conformance --example
    record_gate -- --gate GATE-LEMMA-02 --receipt <hash>` (the script itself writes no gate row).

**Further cards (the per-card stage).** `--card T-<nn>` runs steps 1 to 7 and 9 for one card whose module
exists under `lean/Frob/Cards/` (step 2 on that card alone, without BD-381's stage), without re-recording the
gate. Beads that add a Lean card after this one run
that stage as their end-to-end script and depend on this bead: CARD-T-08 (`psd_congr` and the sum lemma) and
N12-39 (the general statements of T-01, T-03, T-23 and, if admitted, T-24). A full run seals the three cards of
the gate and every further card present at the time; the gate counts sealed cards, so further cards can only
raise the count.

**Lines per theorem card.** The lines of the steps that exercise a card carry `bead` = the card's key
(`CARD-T-12`, `CARD-T-15`, `CARD-T-26`, `CARD-T-08`; `N12-39` for the general statements it seals) and `step`
`T<nn>/<stage>` with stage one of `compile`, `check-olean`, `seal`, `check-binding`, `verify-capsule`, `bundle`,
`frob-verify`, `list` or `control/<name>`; the lines of the binding controls carry `bead` `N12-24` and step
`binding/<control>`; the stage keeps its own log with `bead` `BD-381`; every other line carries `bead` `N12-37`.

Logging: newline-delimited JSON under `target/e2e-logs/lemma_lean_capsule/<utc-timestamp>.ndjson` with a
transcript; each line has `ts`, `script`, `bead`, `step`, `event` (`start`, `cmd`, `assert`, `metric`,
`refusal`, `end`), the exact command line, exit code, wall time in seconds, peak resident memory in GiB, the
module count of the closure and its blocked intersection (threshold 0), the capsule BLAKE3 and bundle digest, the
Lean, Mathlib and `fln` identities, the whitelist digest, the `evidence` block of verb responses (claim Proof,
class, checker identities), the expected and observed verdict of each control with its refusal reason, and on
failure the first differing value (or the `fln` diagnostic) and the card source, capsule and bundle paths needed
to reproduce.

## Acceptance criteria

- [ ] The script exits 0 on the Linux host from a clean checkout and non-zero on any failed assertion; on a host
      without the Lean toolchain it reports the gate `not run`.
- [ ] GATE-LEMMA-02 (TARGET, M5): at least three theorem cards compiled by stock Lean, re-checked by `fln`, and
      sealed; each capsule verifies from an empty environment. Recorded with hashes and measurements.
- [ ] All twelve negative controls are refused for the stated reason.
- [ ] The `lean-capsule` bundles are accepted by `frob-verify` with the capsule file and are `unsupported`
      without it; the report names the FrankenLean kernel in the trusted base.
- [ ] No build output of Lean or `fln` is left in the repository tree after the run (the script checks
      `git status` is clean outside `target/`).
- [ ] The log validates against the shared schema and ends with a `summary` naming GATE-LEMMA-02.
- [ ] `--card T-15` runs the per-card stage alone, writes lines whose `bead` is `CARD-T-15`, and leaves the gate
      record unchanged.

## Test plan

### Unit tests

Script self-tests under `scripts/e2e/tests/`: `lean_capsule_selftest_environment_leak.sh` (a container image that
still contains a Mathlib checkout is detected and the run refuses to count it as an empty environment);
`lean_capsule_selftest_two_cards.sh` (only two sealed cards → the gate assertion fails);
`lean_capsule_selftest_card_stage.sh` (the per-card stage on T-15 writes `bead` `CARD-T-15` lines and does not
call `record_gate`).

### End-to-end script and logging

This bead is the script; steps and logging as above.

### Known answers and negative controls

KA-226 (the level series: Σᵢ α/[i·(i + 1)] = α·m/(m + 1)), the gear identity e₁·f₁ + e₂·f₂ = 0, and the Kleene
statement are the three theorems; the twelve refusals and the three self-tests are the negative controls.
Determinism: capsule hashes identical across two seals on the pins.

## Considerations

- OPEN-LEMMA-1's measurement (N12-23) must exist before the cards are counted; the script checks for the record.
- Fallback if `fln` is unavailable: stock Lean alone, recorded as a single-kernel check; the gate then stays
  `not run`, because it requires the re-check.
- The container images are part of the test fixtures and are pinned by digest.
