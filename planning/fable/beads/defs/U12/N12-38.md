## Background

GATE-LEMMA-05 (M5, claim Proof): the Farkas and rational LDLᵀ reflectors have soundness theorems compiled by
stock Lean and re-checked by `fln`, and each proves its specimen by kernel evaluation within 60 s. A reflector is
a checker function defined in Lean with a soundness theorem; an instance is proved by the kernel evaluating the
function on literals, with no tactic at checking time and no compiled evaluator. The verb is `prove.reflect`
(kind `run`, first milestone M5: promote an instance certificate through a reflected checker). The two specimens:
the Farkas reflector on the stance exclusion at half-width 1/5 m, and the LDLᵀ reflector on one 4×4
pseudo-inertia with 64-bit numerators.

This bead is the end-to-end script for that capability: it runs the verb as a user would, waits on the job,
checks both capsules from an empty environment, times the kernel evaluation, exercises the negative controls and
records the gate, whose result the kill-gate decision KILL-REFLECT (N12-32) reads.

## Scope

In: `scripts/e2e/lemma_reflect.sh` with phase 1 (the two pilot reflectors) and the hook for phase 2 (a step list
that is empty until N12-28 adds to it); the gate record. Phase 2 (the other two reflectors and the admission
cases) is written and run by N12-28 as its own end-to-end test, because N12-28 exists only if KILL-REFLECT does
not fire and that decision (N12-32) reads this bead's gate record: closing this bead never waits for phase 2.
Out: the reflectors and the verb (BD-382, N12-28); the cost sweep (N12-27); the decision (N12-32).

## Technical approach

Steps, phase 1 (plain shell on the Linux host, sources the STD-E2E helper, idempotent, explicit idempotency
keys):
1. `start`: commit, host fingerprint, Lean version, Mathlib commit, `fln` build.
1a. *Stage: the pilot.* Run `scripts/e2e/lemma_reflect_pilot.sh` (BD-382) as a stage, with this run's seed: the
   `PILOT-LEMMA-03` row, the capsule pipeline on both soundness theorems, `frob prove reflect` on both specimens
   and the repeat with the same key, the 823 and 724 controls, the `false` evaluations, and CARD-T-35's law tests.
   Its summary is read and its failures fail this script, except a soundness theorem that does not seal or a
   specimen that is not proved: those are measured values of the gate, logged with their diagnostics and carried
   to step 10.
2. Soundness theorems: build `T35_farkas_sound` (with `T21_proof`) and `T35_ldltPos_sound` (the plan's
   `farkas_sound` and `ldltPos_sound`, named by the binding rule of N12-24) with stock Lean; `fln check-olean`;
   seal; verify each capsule from an empty container; log closure module counts and the blocked intersection
   (threshold 0), wall time and peak memory of the re-check; assert no `sorry`, no axiom outside the whitelist, no
   `native_decide`, and that each theorem is bound to its registered `Frob.Statements.T35.<check>.Statement`. A
   theorem that does not compile, re-check or seal (for example a closure that meets a blocked module) is logged
   with its diagnostic as the gate's measured value; steps 4 to 6 are then logged `not run` for that reflector
   with the reason.
2a. Enabling rule (CARD-T-35): for each reflector log the registered `Statement` hash, the hash of the function
   named in the sealed theorem, the hash of the function the instance file evaluates and the recorded definition
   hash, and assert that the last three agree and the sub-entry is `checked`. Its four negative controls, each on
   a `synthetic` fixture capsule committed by CARD-T-35, must be refused by the verb with FROB-REF-724 (exit 5),
   the message naming the failing hash: a reflector whose soundness capsule is missing; one whose capsule's
   statement hash differs from the registered `Statement` (a weakened theorem); an instance file that evaluates a
   function other than the one in the soundness theorem (`Frob.Other.farkas`); a capsule containing
   `native_decide`.
3. Obtain the two instance certificates. The stance exclusion through the product, as a user would:
   `frob mission synthesize <stance fixture>.fmission --key rf-e2e-stance-<run> --json` (BD-135) and
   `frob prove bundle a:<answer> --out target/e2e/reflect/ --key rf-e2e-stance-b-<run> --json` (BD-133), keeping
   the `lp-farkas` exclusion entry at b = 1/5 m, whose payload must equal BD-132's KA-208 specimen; the
   `rational-ldlt` bundle is BD-382's pseudo-inertia fixture (no `prove.bundle` form writes an inertia bundle
   before the full form). Assert `frob-verify` accepts both.
4. `frob prove reflect --certificate <hash> --reflector farkas --key rf-e2e-farkas --sync-wait-ms 1000 --json` and
   the same with `--reflector ldlt-pos --key rf-e2e-ldlt`: the verb returns a job handle with exit code 8 when the
   bounded wait elapses; `frob job wait <handle> --sync-wait-ms 30000 --json` until done; assert the result has
   class `Proved`, both capsule hashes (soundness and instance), both checker identities, and the three flags
   false.
5. Timing: log the recorded kernel evaluation time of each specimen under `fln` as a `metric` against 60 s
   (TARGET), and the time under stock Lean beside it. A time above 60 s is the gate's measured value, not a
   script failure.
6. Verify the instance capsules from an empty container; assert the instance file's literals equal the bundle's
   rationals (the standard-form system for the stance exclusion: Σ f = 400; f₁ + f₂ − f₃ − f₄ = 180;
   f₁ − f₂ + f₃ − f₄ = 150; fᵢ + sᵢ = 160; witness y = (0, −½, −½, 1, 0, 0, 0) with rᵀy = −5).
7. Negative controls: a perturbed Farkas witness (y = (0, −½, −⅓, 1, 0, 0, 0), rᵀy = 20) and a matrix with a
   non-positive pivot: the auditor rejects the first bundle, so the verb refuses it with the auditor's code before
   any instance file is written; an instance file built from the raw perturbed literals evaluates to `false` and
   its `example` fails to check; in every case no `Proved` evidence is produced; a `rational-ldlt` certificate
   with `--reflector farkas` is FROB-REF-823 (exit 3); repeating step 4 with the same `--key` returns the same
   job and stored result, while a second run with a distinct key re-evaluates and must give the same capsule
   hashes; cancelling a running job with `frob job cancel <handle> --json` (request, drain, finalize) leaves no
   process and no partial capsule.
8. Trigger read-out for KILL-REFLECT: print both halves of the trigger from the measurements.
9. Parked configuration: in a scratch copy of the workspace under `target/` whose gate register's KILL-REFLECT row
   carries a `synthetic` `fired` decision (the real decision is N12-32's, which depends on this bead; the
   committed register is never edited), `frob prove reflect`
   is refused with FROB-REF-724, exit 5, `reason = "killed: KILL-REFLECT"`, and `frob prove list --json` shows the
   T-35 row as `parked`.
10. `summary`: reflectors sealed (against 2), specimens proved within 60 s (against 2), negative controls
   refused, gates touched; the gate value is recorded with
   `cargo run -p frob-conformance --example record_gate -- --gate GATE-LEMMA-05 --receipt <summary receipt hash>`,
   with the measured values and status `pass` when both counts reach 2 and `fail` otherwise.

Phase 2 (added by N12-28): `poly-eq` and `replay` specimens; an over-budget instance refused before any job
starts with the table cell it missed (FROB-REF-701); a timeout reported as `unknown`.

Logging: newline-delimited JSON under `target/e2e-logs/lemma_reflect/<utc-timestamp>.ndjson` with a transcript;
each line has `ts`, `script`, `bead` (`N12-38`), `step` (`<reflector>/<stage>`), `event`, the exact command line,
exit code, wall time, the `evidence` block of each verb response (claim Proof, class, tier F, determinism, the
certificate hash, both capsule hashes, checker identities), a `metric` line per specimen with the kernel
evaluation time in seconds against 60 s under each checker and the re-check's peak memory in GiB, the four
enabling-rule hashes per reflector, a `refusal` line per negative control with its expected and observed code and
exit code, digests and capsule hashes, the KA identifiers asserted (KA-208, KA-227), and on failure the first
differing value, the `fln` diagnostic, the first blocked module met and the instance file path.

## Acceptance criteria

- [ ] The script exits 0 on the Linux host when the measurement is complete, whether or not the gate's
      thresholds are met (a theorem that does not seal and a specimen over 60 s are measured values), and
      non-zero when an assertion about integrity, binding, the controls, idempotency or cancellation fails;
      without the Lean toolchain it reports the gate `not run`.
- [ ] GATE-LEMMA-05 (TARGET, M5): both reflectors' soundness theorems compiled by stock Lean and re-checked by
      `fln`; each specimen proved by kernel evaluation within 60 s. Recorded with times, closures and memory,
      `pass` or `fail` as the measurement falls. This bead closes when the record is on file, whichever way it
      falls: the decision N12-32 depends on it and must be able to fire.
- [ ] The negative controls produce no `Proved` evidence; idempotency and cancellation behave as stated; the four
      enabling-rule controls are refused with 724 and the three hashes agree for both pilot reflectors.
- [ ] Under the parked configuration (a scratch register with a `synthetic` fired KILL-REFLECT decision) the
      script asserts that `frob prove reflect` is refused with 724 and that the theorem-card listing shows the
      reflection card as `parked`.
- [ ] GATE-LEMMA-05's value is recorded by `record_gate` from this run's `summary` receipt, with the host
      fingerprint.
- [ ] The log validates against the shared schema and ends with a `summary` naming GATE-LEMMA-05 and
      KILL-REFLECT.

## Test plan

### Unit tests

Script self-tests under `scripts/e2e/tests/`: `reflect_selftest_slow_specimen.sh` (a fixture reflector that
sleeps past 60 s: the run completes, logs the measured time against 60 s, and its receipt carries the gate's
status `fail`); `reflect_selftest_compiled_evaluator.sh`
(an instance file that uses `native_decide` is refused at sealing and the script fails at step 6).

### End-to-end script and logging

This bead is the script; steps and logging as above.

### Known answers and negative controls

KA-227 (each `check x` evaluates to `true` in the kernel, with no tactic at checking time and no compiled
evaluator; within 60 s per specimen, TARGET; a closure that cannot avoid a blocked module, or a specimen not
evaluated within 60 s, falsifies the pilot), KA-208. The perturbed witness, the non-positive pivot and the two
self-tests are the negative controls. Determinism: capsule hashes identical across two runs on the pins; timings
logged with three repetitions.

## Considerations

- Timing depends on the host; the gate's record names the host fingerprint, and the threshold is a TARGET until a
  measurement is on file.
- The script must not use a compiled evaluator anywhere in the instance path; `#eval` is allowed only in the
  development-time differential test, which is not part of this script.
- Reflection is never on the critical path; a `not run` here blocks nothing except the reflection work itself.
