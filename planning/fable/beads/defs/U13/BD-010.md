## Background
Marrow is the algebraic core of FrankenRobotics: the layer-1 crates `frob-lie` and `frob-algebra`, which every crate above them uses to say "pose", "twist", "wrench", "group" and "sign". `frob-lie` owns the Lie-theoretic vocabulary: the `LieGroup` and `LieAlgebra` traits, the groups SO(2), SO(3), SE(2), SE(3), SE₂(3), SE₂₊ₖ(3) and products, joint subgroups, two retractions with derivatives, frame-typed transforms, the reflection type and the predicate classes. This bead creates the crate and its first two groups. Tier: Solid.

Decision ADR-MARROW-01 (reuse `fs-ga` as the host representation). FACT (FrankenSim at `483d09c682f2`, read 2026-11-21): `fs-ga` provides `So3`, `Se3`, `Twist`, `Wrench` and `Mat6`, with deterministic elementary functions routed through `fs_math::det`; `fs_ga::Twist::new(angular, linear)` and `fs_ga::Wrench::new(torque, force)` fix the component order; `Se3::{compose, inverse, adjoint, coadjoint}`, `Twist::{transform_by, bracket, ad}` and `Wrench::{pairing, transform_by}` exist in `frankensim/crates/fs-ga/src/lie.rs`; `Se3::coadjoint` is documented as Ad⁻ᵀ. FACT: FrankenSim already has two vector vocabularies, because `fs-mbd` defines its own `Vec3`, `UnitQuaternion` and `Pose` beside `fs-ga`'s. Reason for the decision: FrankenRobotics must not add a third. Rejected: (a) our own vector and quaternion structs (a third vocabulary, and a second place where order and sign can drift); (b) wrapping `fs-mbd`'s types (they are volatile and reachable only through the airlock crate `frob-fsim`; `fs-ga` is on the bedrock-direct list, so any crate may name its types). `frob-lie` therefore adds only what `fs-ga` lacks: traits, the missing groups, frame typing, and the infinitesimal coadjoint.

Because the host representation is borrowed, the conventions must be shown equal, not assumed. That is proof obligation PO-MARROW-01: `frob-lie` conventions equal `fs-ga` conventions (quaternion order, sign rule, twist order, adjoint direction, bracket, group coadjoint), verified by a fixture of 1,000 transforms produced by `fs-ga` and consumed by `frob-lie`, compared bit for bit. A single transposed adjoint or swapped component order in this crate would corrupt every dynamics kernel, controller and certificate above it, and energy tests would not notice (see BD-011).

## Scope
In: the `frob-lie` crate skeleton (manifest, `CONTRACT.md`, `contract.toml`, module layout); the two traits; SO(3) and SE(3) group and algebra types over `fs-ga` storage with compose, inverse, action, Ad, the group coadjoint, bracket, ad, the infinitesimal coadjoint `coad` and the power pairing; the generic reference implementation over a scalar; the PO-MARROW-01 fixture, its capture tool and its test.
Out: retractions cay/exp/log and their derivatives, and the law gate (BD-011); the law-test harness (N13-08); SO(2) (BD-012); SE(2), SE₂(3), SE₂₊ₖ(3), products (BD-045); joint subgroups (BD-046); frame typing and the three typed maps (BD-047); reflections (N13-02); predicate classes and exact arithmetic (N13-10); the conventions battery (N13-01).

## Technical approach

Dependencies: `frob-core` and the bedrock-direct crates `fs-ga`, `fs-math`, `fs-ad` (dev and reference path). Modules (DESIGN): `traits.rs`, `so3.rs`, `se3.rs`, `reference.rs` (generic scalar code), later `so2.rs`, `se2.rs`, `extended.rs`, `product.rs`, `retraction.rs`, `differential.rs`, `frame.rs`, `maps.rs`, `isometry.rs`, `subgroup.rs`, `connection.rs`, `predicate.rs`, `exact/`, `layout.rs`. `tests/conformance.rs`, `tests/po_marrow_01.rs`.

**Traits (DESIGN, intent not final signatures).**
```rust
pub trait LieGroup: Copy {
    type Algebra: LieAlgebra;
    const DIM: usize;
    fn identity() -> Self;
    fn compose(self, rhs: Self) -> Self;
    fn inverse(self) -> Self;
    fn exp(x: Self::Algebra) -> Self;      // deterministic elementary functions (BD-011)
    fn log(self) -> Self::Algebra;         // partial: refuses at a chart cut (BD-011)
    fn cay(x: Self::Algebra) -> Self;      // +, −, ×, ÷, √ only (BD-011)
    fn cay_inv(self) -> Self::Algebra;
    fn adjoint(self) -> <Self::Algebra as LieAlgebra>::Operator;   // Ad_g
}
pub trait LieAlgebra: Copy {
    type Dual: Copy;                        // 𝔤*: momenta, wrenches
    type Operator;                          // linear maps on 𝔤
    fn bracket(self, rhs: Self) -> Self;
    fn ad(self) -> Self::Operator;
    fn coad(self, mu: Self::Dual) -> Self::Dual;   // ad*_x μ = (ad_x)ᵀ μ, no minus sign
    fn pair(self, mu: Self::Dual) -> Power;        // ⟨μ, x⟩ in watts
}
```
In this bead `exp`, `log`, `cay`, `cay_inv` for SO(3) and SE(3) are declared and delegated to BD-011 (the trait compiles with `exp`/`log` forwarding to `fs-ga`; `cay` lands in BD-011).

**Conventions implemented (normative).** g = (R, p) is `a_from_b` and acts as x_a = R·x_b + p; composition reads left to right by cancelling inner names. A twist is ξ = (ω, v), angular first, body frame by default (ξ = g⁻¹ġ), perturbations on the right. A wrench is w = (τ, f), torque first; a body momentum is μ = (π, ℓ). Rotation is stored as a unit quaternion in FrankenSim's component order and sign rule, whatever the fixture shows them to be; this crate never re-orders or re-signs what `fs-ga` returns. The double cover is resolved at the one place a representative is needed: q and −q compare equal as rotations, and a requested canonical representative has its first non-zero component in stored order positive (DESIGN; stored state is not canonicalized, see N13-09).

**Formulas in components.**
- Ad_g(ω, v) = (R·ω, R·v + p × R·ω): a twist in b to a twist in a.
- Group coadjoint Ad*_g := (Ad_g)⁻ᵀ: Ad*_g(τ, f) = (R·τ + p × R·f, R·f), so that ⟨Ad*_g w, Ad_g ξ⟩ = ⟨w, ξ⟩. Equals `fs_ga::Se3::coadjoint`.
- Bracket ad_ξ η = [ξ, η] = (ω × η_ω, ω × η_v + v × η_ω). Equals `fs_ga::Twist::bracket`. On SO(3) the bracket is the cross product.
- Infinitesimal coadjoint ad*_ξ := (ad_ξ)ᵀ, defined by ⟨ad*_ξ μ, η⟩ = ⟨μ, ad_ξ η⟩: ad*_ξ(π, ℓ) = (π × ω + ℓ × v, ℓ × ω). FACT: `fs-ga` offers `Twist::ad` and `Se3::coadjoint` and no infinitesimal coadjoint, so `coad` is new code here. The map −(ad_ξ)ᵀ is the generator of the group coadjoint and is never named ad* (ADR-MARROW-05; tests in BD-011).
- Pairing ⟨w, ξ⟩ = τ·ω + f·v, power in watts.

**Reference implementation.** Every operation is also written once as a function generic over a scalar S satisfying `fs-ad`'s `Real` contract (`reference.rs`). The `f64` host types call `fs-ga` (bit parity); the generic code is instantiated at dual numbers for derivative laws, at `f32` inside tests for the single-precision rows of GATE-MARROW-01, and is the algebraic description `frob-kir` lowers (ADR-MARROW-04: there is no `Se3f32` struct; see N13-12). A test asserts the generic `f64` instantiation agrees with the `fs-ga` path within the ulp bounds of GATE-MARROW-01.

**PO-MARROW-01 fixture.** `tools/oracle/marrow_fsga_capture` is a small binary that links `fs-ga` and not `frob-lie`. With seed 0x4D41_5252_4F57_0001 (drawn through `fs-rand` Philox) it writes `tests/fixtures/oracle/marrow/po_marrow_01.frobfix` with a header (FrankenSim commit, `fs-ga` version, date, seed, record count 1,000) and, per record, the raw IEEE-754 bit patterns of: two transforms g, h (quaternion components in stored order, translation); a twist ξ, a second twist η, a wrench w; and the `fs-ga` outputs g·h, g⁻¹, Ad_g ξ (`Twist::transform_by`), Ad*_g w (`Se3::coadjoint` / `Wrench::transform_by`), Ad*_{g⁻¹} w (the pull-back), [ξ, η], ⟨w, ξ⟩. Records 0 to 63 are the boundary set: identity, rotations by π about each axis, angles 2⁻³⁰ and 2⁻⁵², translations of 10⁶ m, and pairs q, −q. The fixture is committed and never regenerated from `frob-lie`. `tests/po_marrow_01.rs` reads it, runs the `frob-lie` operations on the inputs and compares every output bit for bit (the first four rows of the §13.3 table: adjoint, group coadjoint, pull-back, bracket; plus compose, inverse, pairing). The pull-back in this test is computed as the push-forward of g⁻¹ through the same `fs-ga` calls, so that bit equality is meaningful.

**Determinism and evidence.** Class D2 per platform by design, aiming at FrankenSim's cross-ISA class through `fs_math::det`. Outputs are values with no claim attached; the fixture test is a G2 parity test on `host`. Nothing is written to the ledger.

## Test plan
### Unit tests
- `po_marrow_01_bit_parity`: as above; reports the first differing record, field and bit pattern.
- `coad_is_transpose_of_ad`: for ξ, η, μ with integer components in [−8, 8], the two sides of ⟨ad*_ξ μ, η⟩ = ⟨μ, [ξ, η]⟩ are equal as `f64` (integers are exact).
- `coad_components`: μ = ((1, 2, 0), (0, 0, 0)), ξ = ((1, 1, 0), (0, 0, 0)) gives ad*_ξ μ = ((0, 0, −1), (0, 0, 0)) (KA-229).
- `wrench_pushforward_moment_arm`: R = I, p = (1, 0, 0) m, w = (0, (0, 0, 1) N) gives torque (0, −1, 0) N·m and the same force (KA-193).
- `pairing_invariant_small`: ⟨Ad*_g w, Ad_g ξ⟩ = ⟨w, ξ⟩ for the 64 boundary records, within 64 ulp.
- `generic_matches_fsga`: reference code at `f64` against the `fs-ga` path on the fixture inputs, at most 64 ulp.
- `no_private_vector_types`: API scan.
### End-to-end script and logging
`scripts/e2e/marrow_po01.sh`: (1) runs the capture tool into a temporary file and asserts its BLAKE3 equals the committed fixture's (the oracle is reproducible from `fs-ga` alone); (2) runs `cargo test -p frob-lie --test po_marrow_01`; (3) runs `frob doctor --json` and asserts `fs-ga` is listed as admitted with the pinned commit. Logging per `STD-E2E`: NDJSON at `target/e2e-logs/marrow_po01/<utc>.ndjson` plus a transcript; every line has ts, script, bead, step, event, the command line, exit code, wall time, the envelope's evidence block where a verb ran, digests of the fixture, and on failure the first differing record index, field name, both bit patterns and the fixture path; a final summary line counts assertions and names PO-MARROW-01.
### Known answers and negative controls
KA-256 (bit parity on 1,000 transforms), KA-193, KA-229 (coad components). Controls: the four planted mutations above; each must fail `po_marrow_01_bit_parity`. Determinism lanes: the test twice on one machine and in debug and release give identical bytes; a cross-platform run is recorded against FrankenSim's own class (FD-FSIM-07 concerns `fs-mbd`, not `fs-ga`).
