## Background
A known answer is an analytic or hand-checkable truth with a number, a tolerance, an execution tier and, where one exists, a negative control: a planted defect that must make the test fail. The known-answer suite is tier G1 of the verification program (with G0 for laws and exact identities), and its rows are registered in `frob-conformance` so that no enumerable truth is lost between the chapters that state it and the tests that check it. A capability counts as implemented only when its known-answer tests pass against a pinned oracle that was never regenerated from the candidate.

This bead is the registry for the conventions: the sixteen rows KA-191 to KA-206. Each row below carries its case, its truth with the formula or value, its tolerance, its tier and site, its negative control, and the bead whose test implements it. Mechanism beads cite these numbers and restate the values they need; this bead makes the list itself an artifact and checks that every row has a live test. Tier of the content: Solid.

## Scope
In: the sixteen registry rows and their derivation files; the completeness check (every row names the test that checks it; every test that claims a KA number has a row); tolerances marked `to set` tracked until set.
Out: the row schema, loader, five rules and printout (N38a-12); running rows on tiers and the gate's accounting (N38a-13); the tests themselves (owners in the last column); the counterexample registry (N11-CX); the seeding that writes the controls named by the rows into `controls.toml` and fills each row's `control.nc` (N38b-05; this bead writes no row of `controls.toml`).

## Technical approach
**Registry form.** One `[[ka]]` row per KA in `crates/frob-conformance/registry/known_answers.toml`, in the row schema that N38a-12 owns with its loader and five rules: `id`, `section`, `fixture`, `same_as`, `case`, `truth`, `tolerance` (`exact`, `abs`, `rel`, `printed-digits`, `gate` or `to-set`), `tier`, `sites`, `control` (`text` and the `nc` identifiers of the negative-control registry), `derivation` (`docs/derivations/<fixture>.md`), `label` (DESIGN for hand derivations), `due`, `printed`. The columns below map as: "Stated in" → `section`; "Tier · site" → `tier`, `sites`; "Negative control" → `control`; "Test owner" → the derivation file, whose front matter lists the KA ids it serves and, for each, the test that checks it (crate and test name) and the owning bead. This bead writes the sixteen rows and their derivation files. A row is `eligible` only with a derivation, a tolerance and a registered control (N38a-12); a `to-set` row stays `obligation: tolerance` until its value is recorded. Results are reported per site by the runner (N38a-13), not stored in the row. A meta-test fails if a derivation file names a test that does not exist once its owning bead has closed (before that the row is listed as pending on that bead), if a test tagged with one of these numbers has no row, or if a tolerance is still `to-set` when its owning gate is recorded.
**The rows.** Notation: g = (R, p) = `a_from_b`; ξ = (ω, v) a twist; μ = (π, ℓ) a momentum; w = (τ, f) a wrench.

These are recorded in the row's `control.text` with the note "supplied by the test bead"; N38b-05's seeding turns each into a control with `seed = "KA-nnn"` (reusing the control of CX-104 or CX-105 where the plant and target are the same) and fills `control.nc`.

## Acceptance criteria
- [ ] Sixteen rows, KA-191 to KA-206, exist in `known_answers.toml` with every field of the N38a-12 schema filled and validate under its loader; each has a derivation file under `docs/derivations/` that lists it.
- [ ] The meta-test passes: each row's derivation file names its test and owning bead, the test exists for every owning bead that has closed (the others are listed as pending), and each test tagged with one of these numbers has a row.
- [ ] No tolerance is `to set` at the time the gate or battery that owns the row is recorded (KA-191, KA-194, KA-197, KA-200 are the rows to settle; their values are recorded with the conventions battery and GATE-MARROW-01).
- [ ] Every row has a negative control recorded, either the stated one or the one supplied by its test bead, and that control is present in the negative-control registry.
- [ ] The registry's count for this chapter is 16, matching the suite's coverage table (16 known answers, of which 6 have no stated control and 4 have a tolerance to set).

## Test plan
### Unit tests
`crates/frob-conformance/tests/ka_conventions.rs` (host, exact rationals; the real registry and scratch copies, no mocks): `ka_registry_conventions_complete` (16 ids, contiguous, all schema fields present, loader accepts); `ka_registry_tests_exist` (each test named in a derivation file resolves to a test function once its owner has closed); `ka_registry_no_unset_tolerance_at_gate` (run in gate mode: a scratch gate record for GATE-MARROW-01 with KA-191 still `to-set` fails naming the row); `ka_registry_controls_registered` (the ten stated and six supplied controls each resolve to an `NC-` record after seeding); `ka_conventions_arithmetic` (the printed numbers recomputed exactly: KA-193 (1, 0, 0) × (0, 0, 1) = (0, −1, 0) and the twist-map mutant's zero torque; KA-197 the shell ratio I/(m·r²) = (2/5)·(1 − (1 − t/r)⁵)/(1 − (1 − t/r)³), 0.604443 at t/r = 1/10 and tending to 2/3, against 2/5 for the ball, and the box 64.8 kg and 3.45 kg (ratio 18.8); KA-200 [e_x, e_y] = e_z, so −[𝔸₁, 𝔸₂] = −e_z and the mutant's prediction differs by 2·da; KA-201 lcm(400, 100, 30) = 1,200, periods 3, 12, 40, hyperperiod lcm(3, 12, 40) = 120 units = 0.1 s, the policy tick at 40 between physics boundaries 39 and 42; KA-202 ⌊(n − φ)/N⌋ + 1 against brute-force counting for all n ≤ 1,200 and φ < N; KA-204 0.2 N·s / 0.010 s = 20 N).
### End-to-end script and logging
This bead owns `scripts/e2e/ka_conventions.sh` (header: `bead=N11-KA milestone=M1 labels=marrow,registry gates=GATE-GAUNT-02 plants=unset-tolerance-at-gate,missing-row,unknown-test`). It sources the STD-E2E helper and runs `cargo test -p frob-conformance --test ka_conventions`, N38a-12's loader test, and then the sixteen rows by number through their tier targets (`FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test <tier> -- <row>`, `<tier>` = `g0_laws`, `g1_known_answers`, `g3_metamorphic` or `g5_determinism`), logging each row's per-site outcome as the runner reports it; a row whose test owner has not landed is `unbound`, never passed. It then plants, on scratch copies under `target/e2e-scratch/ka_conventions/`, a gate record citing KA-191 while it is `to-set`, the row KA-202 deleted while its test stays tagged with the number, and a derivation file naming a test that does not exist, and requires each to be caught. Log to `target/e2e-logs/ka_conventions/<utc>.ndjson` with a human transcript: every line with `ts`, `script`, `bead`, `step`, `event`, the exact command line, exit code and wall time; one `assert` line per KA (id, eligibility, status per site, measured, expected, tolerance, tier, sites, owner); the SHA-256 of `known_answers.toml`; on failure the first differing field and the scratch path; a final `summary` with rows passed, failed, unbound and not run. The conventions battery script `scripts/e2e/conventions.sh` belongs to N13-01 (extended by N13-06 for the clock rows and by N13-07 for all tiers at M2); it may run this script as a stage and prints the measured values of these rows after the battery.
### Known answers and negative controls
The sixteen rows above, with their controls. Determinism: the registry is data; the meta-tests are exact.

## Considerations
- Rows marked "all tiers" are measured on the host or referee at M1 and on every tier at M2; the runner reports the outcome per site (N38a-13), and the row stores no status.
- A known answer is never edited to match the candidate; a correction to a row is a dated amendment with its derivation.
- The docking-fixture row depends on the mission slice's fixture; if that fixture is late the row stays `not run`, never removed.
