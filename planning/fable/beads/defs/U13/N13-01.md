## Background
A robotics code base fails quietly at its conventions: which way a transform maps, whether a twist is (ω, v) or (v, ω), where the minus sign of the coadjoint goes, whether a window includes its end. The rule of this project is **one convention per concept, converted at exactly one boundary each**, and the conventions table is normative: every crate, kernel, card, file format and certificate uses it, and anything foreign (an imported URDF, a sibling library with another habit) is converted once, at a named boundary, by a tested function. The table's sign- and transpose-sensitive rows are checked against `fs-ga` at M0 (PO-MARROW-01, BD-010), because `fs-ga` is the host representation.

A table in a planning document protects nothing. This bead turns it into two artifacts that live in the repository: the normative text, and a conformance battery in which every row has a named test and a named conversion boundary. At M0 the rows Marrow implements must pass; the rows other subsystems implement are registered with their owner and report `not run` until the owner lands them (N13-07 closes the battery at M2). Tier: Solid.

## Scope
In: `docs/conventions.md` (the table below, verbatim in substance, with the hand checks); the `conventions` battery in `frob-conformance` with one test per row; the row-to-boundary-to-owner map; the M0 tests of rows 2 to 8.
Out: the mechanisms themselves (owners named per row); the time and instant rows' detailed tests (N13-06); the every-tier run (N13-07).

**Formulas the document carries for row 5** (g = (R, p) = `a_from_b`, ξ = (ω, v), μ = (π, ℓ)):
```text
Ad_g    = [[ R, 0 ], [ p̂·R, R ]]     (ω, v) ↦ (R·ω, R·v + p × R·ω)                twists, b to a
Ad_g⁻ᵀ  = [[ R, p̂·R ], [ 0, R ]]     (τ, f) ↦ (R·τ + p × R·f, R·f)                wrenches, b to a
ad_ξ    = [[ ω̂, 0 ], [ v̂, ω̂ ]]      ad_ξ η = [ξ, η] = (ω × η_ω, ω × η_v + v × η_ω)
ad*_ξ   = ad_ξᵀ                       ad*_ξ μ = (π × ω + ℓ × v, ℓ × ω)
μ̇       = ad*_ξ μ + w                 π̇ = π × ω + ℓ × v + τ,   ℓ̇ = ℓ × ω + f
```
The algebra coadjoint is the dual map, defined by ⟨ad*_ξ μ, η⟩ = ⟨μ, [ξ, η]⟩; in coordinates it is the transpose of ad_ξ with no minus sign. The map ξ ↦ −ad_ξᵀ, which some texts call the coadjoint action, is never written ad*; where it is needed it is written −ad_ξᵀ. The group coadjoint is the inverse transpose Ad_g⁻ᵀ, as `fs_ga::Se3::coadjoint` documents (FACT).

**The battery.** `crates/frob-conformance/tests/conventions.rs` holds a table of the 21 row ids; each maps to a test function `conv_NN_<name>` and to its boundary function. A meta-test fails if a row has no test or no boundary. A row whose owner has not landed is an ignored test carrying the owner bead and milestone; the battery's report prints `pass`, `fail` or `not run` per row and never prints `pass` for an ignored row. M0 tests:
- `conv_02_transform_names`: composing `a_from_b` with `b_from_c` gives the action of `a_from_c` on 10³ points; a pose acts as R·x + p (the inverse reading fails).
- `conv_03_twist_order` and `conv_04_wrench_order`: the PO-MARROW-01 fixture fields decode as (angular, linear) and (torque, force); the pairing of w = ((0, 0, 2) N·m, (3, 0, 0) N) with ξ = ((0, 0, 5) rad/s, (7, 0, 0) m/s) is 31 W.
- `conv_05_adjoint_coadjoint`: the five formulas on integer inputs; ⟨ad_ξᵀ μ, η⟩ = ⟨μ, [ξ, η]⟩; the Euler–Poincaré checks (π̇ = (0, 0, −1) for inertia diag(1, 2, 3), ω = (1, 1, 0); d(R·v)/dt = 0 for a force-free body).
- `conv_06_reflection` (after N13-02): the sagittal-mirror axis images.
- `conv_07_rotation_storage`: quaternion component order and sign rule equal those recorded in the fixture header; `same_rotation(q, −q)`; and the stored representatives of q and −q are bit-identical under FrankenSim's rule (FACT, `fs-ga` `So3` at `95a7fba8e8`: negate when w < 0, or when w = 0 and the first non-zero of (x, y, z) is negative; every −0 written +0), checked on (0, −1, 0, 0) → (0, 1, 0, 0) and (−0.5, 0.5, 0.5, 0.5) → (0.5, −0.5, −0.5, −0.5).
- `conv_08_revolute_coordinate`: no public state type exposes a raw angle field (API scan); `from_angle`/`lifted_angle` are the only conversions.
- A grep test: the token `ad*` or `coad` never appears bound to a negated transpose in `frob-*` sources (the forbidden reading has no spelling in the code).

**Determinism and evidence.** Tests are G0 or G1 on `host`, D0 where integer inputs make them exact.

## Acceptance criteria
- [ ] `docs/conventions.md` exists with all 21 rows, the row-5 formulas, the hand checks of each sign-sensitive row, and for every row its conversion boundary and owner.
- [ ] The `conventions` battery has 21 registered rows; the meta-test fails when a row loses its test or boundary.
- [ ] Rows 2, 3, 4, 5, 7, 8 pass at M0; row 6 passes when N13-02 lands (M1); every other row reports `not run` with its owner, not `pass`.
- [ ] Negative controls caught: (i) twist order swapped in a planted decoder fails rows 3 and 5; (ii) the reading x_b = R·x_a + p fails row 2; (iii) a planted −ad_ξᵀ fails row 5 on the free-body value; (iv) a planted raw-angle field in a state struct fails row 8.
- [ ] No second conversion boundary exists for rows 2 to 8: a scan finds no function outside the named boundary that builds a twist, wrench or rotation from foreign component orders.

## Test plan
### Unit tests
The `conv_NN_*` tests above, with the stated inputs and values; `conventions_table_is_total` (the meta-test); `conventions_report_never_passes_ignored_rows` (an ignored row is reported `not run`).
### End-to-end script and logging
`scripts/e2e/conventions.sh --milestone m0`: runs `cargo test -p frob-conformance --test conventions -- --include-ignored --nocapture` in report mode, parses the per-row status table and asserts the M0 rows pass. `STD-E2E` NDJSON at `target/e2e-logs/conventions/<utc>.ndjson` with a transcript: one `assert` line per row (row id, status, owner bead, boundary function), the command line, exit code, wall time, commit; on failure the row, the first differing value and the test name to rerun; a summary line with rows passed, failed and not run. The same script, with `--milestone m2`, is the body of N13-07.
### Known answers and negative controls
KA-191, KA-192 (row 5), KA-193 and KA-194 (rows 4 and 5, with BD-047), KA-195 and KA-196 (row 6); CX-098, CX-099, CX-100. Controls: the four planted defects above, registered against the battery. Determinism: identical report bytes twice on one machine and across platforms for the D0 rows.

## Considerations
- The document is the reference a future contributor reads instead of the plan; when a convention changes it changes there first, by an ADR, and the battery changes with it in the same commit.
- The table deliberately contains rows Marrow does not implement; they stay here so that there is one list. Their detailed rules are stated in the owner's beads; this bead only requires that each has a test and a boundary.
- OPEN-SUITE-4 (which unit aliases `frob_core::qty` exposes; default: the quantities used by Marrow through Traction) affects row 12 only.
- The `fs-mbd` wrench (world-frame force with body-frame torque in one value) is a convention hazard at the airlock, not an exception to row 4: it is converted there by exactly two constructors.
