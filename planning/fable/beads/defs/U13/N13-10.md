## Background
A predicate, in this project's vocabulary, is the sign of an expression where the sign selects between outcomes that differ at the boundary: is the joint limit active, did the contact close, is the point inside the friction cone, did the turn counter advance. ADR-MARROW-08: a strict inequality that decides a discrete outcome is evaluated exactly, either in exact arithmetic on the host or in guarded single precision with an exact integer fallback. Reason: two backends that agree to the last bit but one on a limit test will still disagree about whether the limit is active, and after that the two worlds are different worlds. Rejected: a tuned epsilon (it moves the boundary instead of deciding it, and it carries no dimension); plain single precision (counterexample below); double precision on devices (not uniformly available and still not exact).

Counterexample (FACT, recomputed here by emulating IEEE binary32 against exact rationals). Take the single-precision numbers nearest 0.3, 0.4 and 0.5 as x, y, z and test x² + y² ≤ z². In single precision the two sides are equal, so the plain test reports the point as inside the cone. For those stored numbers, x = 10,066,330·2⁻²⁵, y = 13,421,773·2⁻²⁵, z = 16,777,216·2⁻²⁵, and x² + y² − z² = 13,421,773·2⁻⁵⁰ ≈ +1.19 × 10⁻⁸: the point is outside. A backend that contracts the expression into a fused multiply-add evaluates yet another rounding sequence, one reason contraction is off everywhere. The smallest integer case: 16,777,216 < 16,777,217 is true in integers and false in `f32`, where the second number rounds to the first.

`frob-lie` and `frob-kir` classify every predicate into one of three classes, and the class is part of the kernel manifest:

| Class | Arithmetic | Where it is used |
|---|---|---|
| `Exact` | Integers, rationals and field elements on the host (determinism class D0) | Group closure; bracket closure and Hervé class; the sign of an LDLᵀ pivot of a pseudo-inertia given in rationals; mobility rank at rational sample points; canonical orderings and digests |
| `Guarded` | Single precision with a certified error bound, and an exact integer fallback on the same stored inputs | Joint-limit activation on t = s/(1 + c); the turn-counter branch; the gap sign that activates a contact at commit; cone membership ‖γₜ‖ ≤ μ·γₙ for stick or slip; event guards of the transactional step; tie-breaks in sort keys; the Cayley admission bound, tested as (ω·ω)·h² ≤ 0.04 |
| `Plain` | Single precision | A select whose two arms agree at the boundary (clamp, max, a Huber kink), where a wrong sign moves the result continuously and changes no discrete outcome |

This bead builds the part `frob-lie` owns: the class vocabulary, the exact arithmetic the `Exact` class runs on, and the reference evaluator against which every `Guarded` kernel is judged. Tier: Solid. The kernel side (error-bound derivation, the select lint, emitted fallbacks) is BD-053 in `frob-kir`; the device measurement is BD-182.

## Scope
In: `PredicateClass`, `Comparator`, `PredicateSpec`; `exact::{Int, Rational}` and exact linear algebra; exact conversion from stored floats; the exact sign of a polynomial on stored inputs; the bit-budget rule; a host reference of the guarded evaluation; the host half of FROB-REF-215; the Predicates law on the host.
Out: derivation of the error constant from a straight-line program, the lint, kernel emission (BD-053); the Marrow-owned predicate instances (N13-11); cyclotomic field elements (N13-13); the 10⁹-input device gate (BD-182); the limb-width question (N13-31).

## Technical approach
**Vocabulary (DESIGN).** `enum PredicateClass { Exact, Guarded, Plain }`; `enum Comparator { Less, LessEq, Equal }` (strict, non-strict and equality are declared per predicate, never implied); `struct PredicateSpec { id, polynomial, inputs: [InputRange], comparator, class, outcome: &'static str }` where `InputRange` declares for each input a magnitude interval [2^lo, 2^hi] (zero is always admitted).

**Exact kernel, `crates/frob-lie/src/exact/`.**
- `Int`: signed integers on 32-bit limbs with widening 32×32→64 multiplies, the same limb scheme the device fallback uses, so a host oracle and a kernel run the same integer program.
- `Rational`: a reduced pair of integers with a positive denominator (the artifact convention), with +, −, ×, ÷, comparison, and exact parsing of the design language's decimals and ratios.
- `linalg`: row reduction, rank, nullspace, linear solve, determinant, and LDLᵀ with pivot signs, over any exact field (generic, so N13-13's cyclotomic elements reuse it).
- `from_f32`/`from_f64`: every finite float is an integer of at most 24 (or 53) bits times a power of two; conversion is exact; NaN and infinities are rejected.
- `sign_exact(spec, stored_inputs) -> Sign`: evaluates the polynomial on the stored numbers as an integer computation. This is the oracle of the law "a `Guarded` predicate returns the sign of its exact evaluation on the stored inputs, for every input".

**The guarded evaluation** (reference implementation on the host; kernels follow the same four steps):
1. Evaluate p̂ in single precision, and in the same pass a bound E = c·u·S, where S is the sum of the absolute values of the terms, u = 2⁻²⁴ is the unit round-off and c is a constant derived from the straight-line program by forward error analysis and stored in the manifest (derived by `frob-kir`; the host reference uses the conservative c = 2·k for k floating operations).
2. If |p̂| > E the sign of p̂ is the sign of p, and the predicate is done.
3. Otherwise evaluate p exactly on the stored inputs: an integer computation carried out in 32-bit limbs with widening multiplies, which exist identically on the CPU, on CUDA and on Metal; it belongs to the exact-integer kernel class.
4. The bit budget of step 3 is computed at derivation time from the declared ranges of the inputs. A predicate whose budget exceeds 256 bits is refused at build time (FROB-REF-215), which is a signal to rescale it (DESIGN: the cap keeps the fallback a fixed, small integer program on every backend).

**Bit-budget rule (DESIGN).** Input i with declared magnitude range [2^loᵢ, 2^hiᵢ] is, at its lowest exponent, an integer of at most wᵢ = 24 + (hiᵢ − loᵢ) bits. A monomial with degrees d needs Σᵢ dᵢ·wᵢ bits plus the bits of its coefficient; monomials are aligned to the lowest scale of the polynomial; the budget is the largest aligned monomial width plus ⌈log₂(number of monomials)⌉ plus one sign bit. Example: x² + y² − z² with inputs between 2⁻¹⁰ and 2¹⁰ has w = 44 and a budget of 2·44 + 2 + 1 = 91 bits, three limbs.
**Out-of-range inputs (DESIGN).** An input outside its declared range cannot be handled by the fixed-size program. On the host and on `batch-cpu` the evaluation falls through to `sign_exact` with unbounded `Int`, which is always correct; a device kernel raises the world's `predicate-range` flag and the evaluation is counted separately from the ordinary fallback rate (N13-11 states the ranges of the Marrow-owned predicates).

**Host size budgets and FROB-REF-215.** Each exact host computation declares a cap on the bit length of any numerator or denominator (DESIGN default 4,096 bits; a computation states its own in its contract). Exceeding it returns FROB-REF-215 (exit code 3) with the expression, the input ranges and the budget. Ranked repairs: 1. rescale the expression or its units; 2. narrow the declared input ranges; 3. split the predicate into factors of lower degree; 4. for a host computation, declare a larger size with its reason, or take the tolerance route and label the result `Tested`.

**What exactness means.** The exact result is exact with respect to the stored single-precision inputs. That is what makes two backends with bit-equal inputs take the same branch. It says nothing about how well the inputs approximate real quantities; under determinism class D3, where inputs differ within a tolerance, two tiers may still legitimately take different branches near a boundary, and the decision-level equivalence test counts those.

**Determinism and evidence.** `Exact` results are D0; the decisions of guarded evaluations are D0. Law tier G0, site `host`.

## Acceptance criteria
- [ ] `Int`, `Rational` and exact linear algebra exist with the invariants above; `Rational` is always reduced with a positive denominator (property test over 10⁶ operations).
- [ ] The 0.3, 0.4, 0.5 fixture: `sign_exact` returns positive (outside) with exact value 13,421,773·2⁻⁵⁰; the reference guarded evaluation returns the same sign through its fallback; a `Plain` evaluation reports equality.
- [ ] The Predicates law on the host: for five polynomial shapes (x² + y² − z², a·b − c·d, the limit polynomial s·(1 + c′) − s′·(1 + c), (x² + y² + z²)·h² − κ, x − y), 10⁷ adversarial inputs each placed within 4 ulp of the zero set: the guarded reference agrees with `sign_exact` on every input; zero errors.
- [ ] Bit budgets computed by the rule are upper bounds: on 10⁶ random in-range inputs per shape the exact computation never exceeds its budget; a predicate declared with ranges that give 300 bits is refused with FROB-REF-215 and its payload.
- [ ] A host computation that exceeds its declared rational size returns FROB-REF-215, not a truncated value.
- [ ] Negative controls caught: (i) the plain predicate on the 0.3, 0.4, 0.5 fixture; (ii) an error constant c ten times too small produces sign errors on the adversarial set; (iii) an `Int` multiply that drops the top limb fails the budget test; (iv) a non-reduced `Rational` fails the invariant test.

## Considerations
- Where the exact kernel lives is a DESIGN choice made here: `frob-lie` owns the predicate classes, so it owns the arithmetic they run on, and `frob-algebra` (a later row of the same layer) depends on it. If the layer rules are read as forbidding that edge, the kernel moves to `frob-core` unchanged.
- The auditor (`frob-cert`) has its own exact arithmetic by design and never shares this code; a differential test between the two belongs to the auditor's beads.
- OPEN-MARROW-3 (64-bit integers where a backend offers them) defaults to 32-bit limbs everywhere (N13-31).
- The default host size cap of 4,096 bits is not fixed by any gate; it is recorded with GATE-MARROW-02 when the group computations report their peak sizes.
