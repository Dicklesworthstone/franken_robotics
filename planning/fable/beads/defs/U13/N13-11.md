## Background
Three of the predicates listed for the `Guarded` class belong to Marrow itself, because they read the Lie-group coordinates Marrow defines: joint-limit activation on the half-angle tangent t = s/(1 + c); the turn-counter branch of the unit-complex revolute coordinate; and the Cayley admission bound, tested as (ω·ω)·h² ≤ 0.04. Each decides a discrete outcome (a limit row becomes active, the integer turn count changes, a step is refused), so a wrong sign makes two backends diverge permanently. BD-012 implements their semantics on the host in double precision; this bead states each as a predicate polynomial with declared input ranges, a comparator, a bit budget and a manifest entry, so that `frob-kir` (BD-053) can derive its error bound and emit the guarded kernel form, and so that the device gate (BD-182) has concrete Marrow predicates to measure. Tier: Solid.

The other guarded predicates (the gap sign at commit, cone membership, event guards, sort tie-breaks) are owned by the chapters that own those mechanisms; they follow the same pattern and are not specified here.

## Scope
In: the three `PredicateSpec`s with ranges, comparators and budgets; their reference evaluations; their adversarial tests; the manifest entries; the documented outcome of each sign.
Out: error-constant derivation and kernel emission (BD-053); device runs (BD-182); joint hard-stop rows that consume the limit predicate (BD-155); state layout of the turn count (N13-35).

## Technical approach
**1. Joint-limit activation.** State (c, s, k) with a limit (c_lim, s_lim, k_lim) as in BD-012. The question "θ ≤ θ_lim" is decided lexicographically: by the integers k and k_lim when they differ (exact), otherwise by the sign of
```text
p_lim(c, s; c_lim, s_lim) = s·(1 + c_lim) − s_lim·(1 + c)        comparator: p_lim ≤ 0  ⟺  t ≤ t_lim
```
which is t ≤ t_lim cross-multiplied by the non-negative factors (1 + c) and (1 + c_lim); t = s/(1 + c) = tan(φ/2) is monotone in the branch angle φ ∈ (−π, π]. Special case decided before the polynomial: 1 + c = 0 as stored (the point φ = π) is the largest angle of its branch. Expanded, p_lim = s + s·c_lim − s_lim − s_lim·c: four monomials of degree at most two. Declared ranges: every component has magnitude zero or in [2⁻⁴⁰, 1] (span 40, w = 64 bits). Budget: 2·64 + 2 + 1 = 131 bits, five limbs. Outcome: the lower and upper limit rows of the joint become active or inactive; a limit is "active" when the state is at or beyond it (non-strict), and the manifest records which side is closed.
**2. Turn-counter branch.** Rule of BD-012: with (c₀, s₀) before and (c₁, s₁) after the update, k increases by one if c₁ < 0, s₀ ≥ 0 and s₁ < 0; decreases by one if c₁ < 0, s₀ < 0 and s₁ ≥ 0. These are signs of stored numbers, so the error bound is zero and no fallback ever runs; the predicate is still registered as `Guarded` with E = 0 and implemented as tests on the IEEE sign and zero bits (negative zero is zero), so that the `Plain` lint does not reject its select and its manifest states why it is exact. Outcome: an exact ±1 update of the integer k; with the Cayley bound at most one crossing can occur per substep.
**3. Cayley admission bound.** The step is admitted when
```text
p_cay(ω, h) = (ω_x² + ω_y² + ω_z²)·h² − κ ≤ 0          κ = the stored constant nearest 0.04
```
(for a planar joint, (ω·h)² − κ). In `f32`, κ = 10,737,418·2⁻²⁸ = 0.039999999105930328; the manifest records the bit pattern, because "0.04" is not representable and the stored constant is the convention. No square root is taken. Declared ranges: |ω_i| zero or in [2⁻²⁰, 2¹⁰] rad/s (w = 54); h in [2⁻¹⁴, 2⁻⁴] s (w = 34). Budget: 2·54 + 2·34 + 2 + 1 = 179 bits, six limbs. Outcome: when p_cay > 0 the substep is refused with FROB-REF-212 and the returned substep count is ⌈‖ω‖·h/0.2⌉, computed on the host for the message (the count is advisory; admission of each proposed substep is again this predicate).
**Manifest entry** (one per predicate, in the kernel manifest of every kernel that contains it): id, class, polynomial, comparator, input ranges, bit budget, error constant c (filled by BD-053's derivation), constant bit patterns, outcome description, and the range-guard policy of N13-10 (an out-of-range input raises `predicate-range`).
**Reference evaluations.** `frob_lie::predicate::{limit_active, turn_branch, cayley_admitted}` on stored `f32` or `f64` inputs, built on N13-10's `sign_exact` and guarded reference; kernels are compared against these.
**Determinism and evidence.** Decisions are D0 on every backend given bit-equal inputs. Tests are G0 (law) and G1 (fixtures) on `host`; device rows belong to BD-182.

## Acceptance criteria
- [ ] The three specs exist, with budgets 131, 0 (sign bits only) and 179 bits, all under the 256-bit cap, and appear in the manifest schema with every field filled except c, which BD-053 supplies.
- [ ] Limit predicate: on 10⁷ adversarial (state, limit) pairs constructed within 4 ulp of p_lim = 0 (including limits at φ = 0, ±π/2, ±3π/4 and the branch edge π), the reference decision equals the exact rational decision on the stored numbers: zero errors; the plain single-precision decision errs on a measurable fraction (recorded).
- [ ] Limit ordering is monotone: for 10⁶ random triples θ₁ < θ₂ < θ₃ spanning ±6 turns, converted to stored states, "θ₁ ≤ limit θ₂" is true and "θ₃ ≤ limit θ₂" is false whenever the stored states differ.
- [ ] Turn branch: for the 2¹⁶ sign patterns and boundary values (including ±0 and denormals) of (c₁, s₀, s₁) the bit-test implementation equals the definition; k never changes when c₁ ≥ 0.
- [ ] Cayley bound: on 10⁷ adversarial (ω, h) within 4 ulp of p_cay = 0 the reference equals the exact decision; ‖ω‖·h = 0.1875 is admitted, 0.25 is refused with substep count 2.
- [ ] Negative controls caught: (i) limit test on the raw value of s instead of p_lim (wrong beyond ±π/2); (ii) limit test that divides (t computed as s/(1 + c) in `f32`, then compared) errs near the branch edge and on the adversarial set; (iii) turn branch that treats −0 as negative; (iv) Cayley bound computed with a square root and compared with 0.2 errs on the adversarial set; (v) κ written as a decimal literal re-rounded differently on one backend (simulated by using the `f64` nearest 0.04 in an `f32` kernel) changes decisions and is caught by the constant-bit-pattern check.

## Test plan
### Unit tests
- `limit_predicate_adversarial_exact`, `limit_predicate_monotone`, `limit_at_branch_edge` (states at π − 2⁻²³·k for k = 0..8 against a limit at π).
- `turn_branch_bit_tests_exhaustive`, `turn_branch_negative_zero`.
- `cayley_bound_adversarial_exact`, `cayley_bound_constant_bits` (κ's bit pattern is 0x3D23D70A), `cayley_bound_substep_count`.
- `budgets_match_rule`: 131 and 179 bits recomputed from the declared ranges; an attempt to widen ω's range to [2⁻⁶⁰, 2²⁰] gives 2·104 + 2·34 + 3 = 279 bits and is refused with FROB-REF-215.
- `out_of_range_flag`: s = 2⁻⁶⁰ with the declared floor 2⁻⁴⁰ still decides correctly on the host and sets `predicate-range`.
### End-to-end script and logging
`scripts/e2e/marrow_predicates.sh --site host --suite marrow`: runs the three adversarial suites; `STD-E2E` NDJSON at `target/e2e-logs/marrow_predicates/<utc>.ndjson` with a transcript: per predicate a `metric` line (inputs, sign errors against threshold 0, fallback fraction, plain-arithmetic error fraction, peak bits against budget), `assert` lines for the controls, `refusal` lines for the FROB-REF-212 and FROB-REF-215 cases with payloads, seed, commit; on failure the stored inputs in hex, the residual, the bound and the exact value; summary with counts. When the batched step exists the same script runs `frob sim run` on a single-joint limit fixture on each tier and compares the limit-activation step index across tiers (BD-182).
### Known answers and negative controls
KA-253 (the law), KA-257 (turn counter), KA-052 (Cayley bound); the 0.3, 0.4, 0.5 fixture of KA-236 as the general control. Controls (i) to (v). Determinism: decisions identical on every platform, debug and release.

## Considerations
- The magnitude floors (2⁻⁴⁰ for unit-complex components, 2⁻²⁰ rad/s for rates) are DESIGN choices that keep budgets under the cap; a unit complex number produced by the normalized Cayley update has components that are exact zeros or far above 2⁻⁴⁰ in practice. The count of `predicate-range` events is reported beside the fallback rate; any non-zero count on the contact battery is a finding.
- If OPEN-MARROW-3 admits 64-bit integers on some backends, budgets do not change; only the limb count per budget does.
- The joint-limit predicate decides activation; the limit row's impulse is the solver's (joint rows on batched tiers). A hard stop that activates one step apart on two tiers is the divergence this predicate exists to prevent.
