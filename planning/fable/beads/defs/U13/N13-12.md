## Background
The batched tiers run on packed single-precision buffers, structure-of-arrays, generated for CPU, CUDA and Metal from one kernel description. The host works in double precision on `fs-ga` types wrapped with compile-time frame names. Two things can go wrong at the seam, and each has a decision and a proof obligation.

ADR-MARROW-04: packed single-precision layouts are generated, not typed. There is no `Se3f32` struct. `frob-kir` emits structure-of-arrays layouts from the same algebraic description, so the host type and the kernel layout cannot disagree. Reason: a hand-written single-precision twin of every group is a second definition of component order, quaternion sign rule and field meaning, maintained by hand, and the first place a convention drifts; a generated layout has one source. Rejected: `Se3<f32>` as a public type (invites host code to compute in single precision outside the generated, certified kernels); a hand-maintained table of buffer offsets.

PO-MARROW-02: frame typing has zero run-time cost in batched kernels; verification: emitted kernel source contains no frame identifiers. Frames are phantom types on the host and are checked for model-indexed frames once at model compile time; none of that may leak into a kernel as a tag column, an argument or a branch. Tier: Solid.

## Scope
In: the layout descriptor in `frob-lie`; the pack and unpack reference between host values and layout slots; the scan that forbids hand-written single-precision group structs; the PO-MARROW-02 test over emitted sources, including a renaming metamorphic test.
Out: the kernel IR and emitters (`frob-kir`, BD-018); the kernels themselves (derivation BD-019, articulated kernels BD-157); the packed model lowering (BD-148); anchored positions (the device form of a translation, owned by the numerics work); device buffer management.

## Technical approach
**Descriptor (DESIGN), `crates/frob-lie/src/layout.rs`.** For each algebraic object a constant `GroupLayout { name, slots: &[Slot] }`, `Slot { name, role, dimension, scalar: F32 | I32 }`:
| Object | Slots, in order | Dimension recorded in the buffer schema |
|---|---|---|
| Rotation (SO(3)) | the four quaternion components in FrankenSim's stored order (taken from the PO-MARROW-01 fixture header, not restated) | dimensionless |
| Pose (SE(3)) | rotation slots, then translation x, y, z | dimensionless; metres |
| Revolute coordinate | c, s (`f32`); k (`i32`) | dimensionless; turns |
| Twist | ω_x, ω_y, ω_z, v_x, v_y, v_z (angular first) | rad/s; m/s |
| Wrench | τ_x, τ_y, τ_z, f_x, f_y, f_z (torque first) | N·m; N |
| Momentum | π then ℓ | N·m·s; N·s |
| Extended pose, N columns | rotation slots, then N vectors | per column |
The descriptor is data: `frob-kir` reads it to allocate one array per slot per batch and to write the buffer schema (each raw `f32` buffer records its dimension there, as the units convention requires). The host types implement `HasLayout` with `pack(&self, out: &mut [SlotValue])` and `unpack`, the only functions that move a value between the `f64` host representation and layout slots; packing rounds each component to nearest `f32` once.
**No typed single-precision groups.** A test scans the public and private items of every `frob-*` crate (through the workspace's syntax-level scan used by `xtask check-generated`, or a `cargo doc` JSON listing) for a struct whose fields are single-precision scalars and whose name or field set matches a group in the table; generated files under `kernels/` are exempt because they are the generated layouts. A hit fails the test with the item path.
**PO-MARROW-02.** For every kernel in the kernel registry with a Marrow object in its signature (at M1: `K-cay-step`, `K-normalize`; later the articulated kernels), the test:
1. emits the Rust symbol source and the shared-dialect source for CUDA and Metal;
2. asserts that none contains a frame identifier: no name of a `Frame` marker type declared in the workspace, no `FrameTag`, no `PhantomData`, and no slot or argument whose role is a frame;
3. asserts the kernel's argument list equals the layout slots plus its declared scalars, nothing else;
4. metamorphic check: recompiles the same model with every frame renamed and with the static frames replaced by tagged frames; the emitted sources and the kernel digest are byte-identical.
**Quaternion sign in layout state.** Host values are canonical (w ≥ 0, FrankenSim's rule, BD-010 FACT), so `pack` always writes a canonical quaternion. The generated group updates (`K-cay-step`, `K-normalize`, BD-019) never apply a sign select: under the default of OPEN-MARROW-1 (N13-09, option N) state held in a layout stays continuous in time and may leave the w ≥ 0 hemisphere. `unpack` goes through the fallible `fs-ga` constructor and therefore returns the canonical host value. Every comparison between a layout quaternion and a host quaternion is made after `canonical_representative()` (N13-09) or on unpacked values, never on raw slot bytes. If N13-09 records option Y, the sign select is added to the generated update by a follow-up bead and the no-flip test below is inverted.
**Host and layout agreement.** For 10⁶ random host values, `unpack(pack(x))` equals x with each component rounded to `f32` (the round trip can change sign only when rounding takes a positive w below the smallest `f32` subnormal to zero and the first non-zero of (x, y, z) is negative; the test counts such cases and asserts the result is the canonical image of the rounded value); for the PO-MARROW-01 fixture records, packing then running the generated `K-cay-step` on `batch-cpu` and unpacking agrees with the host `cay` step within the single-precision bound of GATE-MARROW-01 (16 ulp for single operations), compared after canonicalization.
**Determinism and evidence.** Descriptor and scans are D0. The agreement test is G2-style parity on `host` and `batch-cpu`.

## Acceptance criteria
- [ ] `GroupLayout` descriptors exist for the seven objects; the quaternion slot order is read from the fixture header and a test fails if the two ever differ.
- [ ] No hand-written single-precision group struct exists in `frob-*` (scan passes); a planted `struct Se3f32 { q: [f32; 4], p: [f32; 3] }` in a scratch crate fails the scan.
- [ ] PO-MARROW-02 holds for every registered kernel that carries a Marrow object: zero frame identifiers in the emitted Rust, CUDA and Metal sources; arguments equal the layout slots.
- [ ] Renaming every frame of a model, or switching static frames to tagged frames, changes no byte of the emitted sources and leaves the `KernelId` unchanged.
- [ ] Pack and unpack round-trip on 10⁶ values; the generated Cayley step agrees with the host step within 16 ulp in `f32` on the fixture records, compared after `canonical_representative()`.
- [ ] Layout state is never sign-flipped by a generated update: a 4π spin in 10⁴ `K-cay-step` steps on `batch-cpu` keeps every componentwise step change below 2·sin(h‖ω‖/2) + 16 ulp (`f32`), while the unpacked host values of the same run are canonical at every step.
- [ ] Negative controls caught: (i) a kernel generator patched to pass a frame-tag column fails step 2 and step 3; (ii) a layout with linear-first twist slots fails the agreement test against the host; (iii) a descriptor whose quaternion order is permuted fails the fixture-header comparison.

## Test plan
### Unit tests
- `layout_descriptors_complete`: seven objects, slot counts 4, 7, 3, 6, 6, 6, 4 + 3N.
- `quaternion_slot_order_matches_fixture_header`.
- `pack_unpack_roundtrip_f32`: 10⁶ random values per object.
- `no_typed_f32_groups_scan` and `planted_se3f32_is_found`.
- `po_marrow_02_no_frame_identifiers`: per kernel and per emitted dialect.
- `po_marrow_02_frame_renaming_is_invisible`: byte equality of sources and equal `KernelId`.
- `generated_cay_matches_host_on_fixture`: 1,000 fixture records, at most 16 ulp after canonicalization.
- `layout_state_no_sign_flip`: the 4π spin of the acceptance line; with a planted sign select in the generated update the step change reaches about 2 at two steps and the test fails.
- `raw_slot_comparison_rejected`: comparing a layout quaternion with a host quaternion by raw slot bytes is not offered by the API (the comparison helper takes canonical values only); a doc test shows q and −q in slots compare equal through it.
### End-to-end script and logging
`scripts/e2e/marrow_layouts.sh`: regenerates the kernels with `xtask check-generated` (which must report no diff), runs the tests above and logs the worst step change of the no-flip spin against its bound, then, once the verb exists (`frob spark check`, BD-176 at M2; N13-07 re-runs this script there) and where devices exist, `frob spark check --json` and asserts that the buffer schema of `K-cay-step` lists the slots of the pose layout with their dimensions and no frame field. `STD-E2E` NDJSON at `target/e2e-logs/marrow_layouts/<utc>.ndjson` with a transcript: `cmd` lines with exit codes and wall time, `assert` lines per kernel and dialect (frame identifiers found: 0), digests of emitted sources before and after renaming with the first differing byte offset on failure, `metric` lines for the worst ulp of the agreement test against 16, the envelope evidence block of `spark check`; summary with counts and PO-MARROW-02.
### Known answers and negative controls
No numbered known answer; the obligation is PO-MARROW-02. Controls (i) to (iii), registered. Metamorphic: frame renaming and static-to-tagged substitution leave emitted bytes unchanged; reordering unrelated kernels in the registry leaves each kernel's bytes unchanged. Determinism: emitted sources are identical twice and across platforms (generated files are never edited by hand).

## Considerations
- At M1 only the M0 kernels exist; the test is written against the kernel registry, so every kernel added later is covered without editing the test, and the M2 conventions closure (N13-07) re-runs it on the full kernel set.
- Device translations are stored as anchored positions (cell index plus centred offset); the pose layout's translation slots are the pre-anchoring host view, and the anchoring kernel owns that conversion as its single boundary.
- A consumer that genuinely needs single-precision host arithmetic (a reference for a kernel test) instantiates the generic reference code of BD-010 at `f32` inside the test; it does not declare a type.
