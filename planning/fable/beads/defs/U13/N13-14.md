## Background
Before an agent ties policy weights under a symmetry group, or reads a block-diagonal modal analysis, it should know what the group buys: how each channel space (joint positions, actions, observation terms) splits into irreducible pieces, and how many free parameters an equivariant linear map between two such spaces has. For real representations ρ_in on ℝ^{d_in} and ρ_out on ℝ^{d_out} of a finite group Γ, the equivariant linear maps are the W with ρ_out(g)·W = W·ρ_in(g) for all g. Over the reals an irreducible representation has one of three types, read from the Frobenius–Schur indicator ι(χ) = |Γ|⁻¹·Σ_g χ(g²) of a complex irreducible character χ:

| ι(χ) | Real type | Real irreducible built from χ | Equivariant maps between m_in and m_out copies | Free parameters |
|---|---|---|---|---|
| +1 | Real | χ itself, dimension d_χ | Θ ⊗ I with Θ any real m_out × m_in matrix | m_out·m_in |
| 0 | Complex | χ and its conjugate together, dimension 2·d_χ | blocks [[a, −b], [b, a]] ⊗ I: a complex m_out × m_in matrix | 2·m_out·m_in |
| −1 | Quaternionic | none | refused (FROB-REF-214) | none |

So dim Hom_Γ(V_in, V_out) = Σᵢ cᵢ·mᵢ^out·mᵢ^in with cᵢ = 1 for real type and 2 for complex type. Every irreducible representation of C₂, C₂ × C₂, the dihedral groups and S₄ is of real type. Complex type occurs for the cyclic groups Cₙ with n ≥ 3, which are the symmetry groups of radial designs without a mirror plane: a tri-wheel cluster with handed wheels, a hexapod whose legs are all the same chirality. The verb `algebra.irreps` reports the decomposition, the type of each constituent and the free-parameter count for a given pair of channel spaces. Worked scale (illustrative): a quadruped whose closed loop has C₂ × C₂ and layers of width 256 (64 copies of the regular representation) has 16,384 weights per equivariant layer instead of 65,536.

ADR-MARROW-07 (part): a representation of quaternionic type is refused, because no group that arises here has one, so meeting one means the group computation is wrong. Tier: Solid for the decomposition and count. The block bases that realize the parameterization, and their use in learning, are BD-325.

## Scope

## Technical approach
**Registry entry.** The row in `registries/verbs.toml` is written by the cluster's registry bead VERBS-algebra, which this bead depends on and does not restate field by field: name `algebra.irreps`; cluster `algebra`; kind `read`; tier S; capability `algebra:read`; schemas `frob.algebra.irreps.in/1` and `frob.algebra.irreps.out/1`; idempotent; the registry's static cost model; first milestone M1; task cluster `symmetry`; owner `frob-algebra`; example `frob algebra irreps C2xC2 --rep permutation:4 --json`; MCP tool `algebra_irreps`. Its refusal list carries FROB-REF-214 and FROB-REF-215 (the verb returns 215 when its exact arithmetic exceeds the declared size, N13-10's rule for every exact host computation); the verb raises no other chapter code, and `refusal_lists` of the registry fails if the implementation and the row ever differ. The implementation meets the registry's own checks (`kinds_milestones_tiers`, `schemas_and_scopes`, `refusal_lists`, `mcp_names_one_to_one`, and the registry example parsing against the generated CLI).
**Input.** A group source, one of: (a) `generators`: signed permutations on a defining set (lists of `u16` images and `i8` signs); (b) `family`: one of C1…C12, D1…D12, each optionally `xC2`, or S4, with its standard action, given positionally (`C2xC2`, as in the registry example) or by `--family` (the form N13-20's gate loop uses), both forms building the same input document; (c) `design` and `task` identifiers, in which case the group is the stored Γ_obs (or, with `--group mech`, Γ_mech, labelled as not licensed for tying). And two channel spaces, `--in` and `--out`, each either explicit signed permutations per generator, a named standard space (`natural` for the presentation's own defining signed-permutation action, which the gate loop of N13-20 uses; `permutation:n` for n slots under the group's standard action; `regular`, `regular*k` for k copies), or a named channel space of the bound model (joint positions, joint velocities, actions, an observation term); `--rep <space>` sets both to the same space (the registry example's form). With a design, the group is computed for the bound model by the symmetry code of N13-15 and N13-16 (Γ_obs by default), and read from the stored result of `analyze.symmetry` (BD-102) when one exists for the same `ModelId` and task.
**Algorithm.**
1. Build the group and its character table (BD-048).
2. For each irreducible character compute ι(χ) = |Γ|⁻¹·Σ_g χ(g²), exactly; it is +1, 0 or −1. Pair each character with ι = 0 with its complex conjugate (the pair forms one real irreducible of dimension 2·d_χ). If any constituent of either channel space has ι = −1, refuse with FROB-REF-214, returning the character and its indicator.
3. For each channel space compute the multiplicity mᵢ of each real irreducible (for a complex pair, the multiplicity of χ in the complexification).
4. Report dim Hom = Σᵢ cᵢ·mᵢ^out·mᵢ^in, the unconstrained count d_out·d_in, their ratio, and the bias count (the multiplicity of the trivial character in the output space, since biases are restricted to the fixed subspace of ρ_out).
5. Cross-check, always on: the exact rank of the Reynolds projection on Hom(ℝ^{d_in}, ℝ^{d_out}), computed as the number of orbits-with-sign of Γ on index pairs (i, j) that are not forced to zero, must equal the formula's count; a mismatch is an internal error (exit 9), never a reported number.
**Output** (inside the standard envelope): group order, generators, class sizes, the character table as exact strings, for each space a list of constituents {character index, degree, type: `real` or `complex`, conjugate index, multiplicity, real dimension}, `free_parameters`, `unconstrained_parameters`, `bias_parameters`, `reynolds_rank`, and `group_kind` (`obs`, `mech`, `declared` or `family`). Evidence block: class `Tested` (or `Certified` when the orthogonality certificate is attached), tier `static`, determinism `exact`, the model identity when a design was given, no seed. `next_actions` points to `analyze.symmetry` when a design was given without a task (so the caller sees which group is licensed).
**Refusals.**
| Code | Trigger | Returned | Ranked repairs |
|---|---|---|---|
| FROB-REF-214 | a constituent of quaternionic type (ι = −1), or a symmetry group outside the supported families (order above 256, or generators that do not close inside the cap) | the character and its indicator; the group's order and generators | ranked per trigger, as N13-REF's record ranks them. Quaternionic constituent: 1. re-run `analyze.symmetry` and report the group computation as defective if the group came from a design (`retry: never` for the same input); 2. restrict to a supported subgroup named in the reply; 3. declare the symmetry by construction (`radial`), or take the tolerance route labelled `Tested`; 4. use augmentation without tying. Group outside the supported families: 1. build the symmetry by construction (`mirror` or `radial`); 2. take the tolerance route, labelled `Tested`; 3. restrict to a supported subgroup named in the reply; 4. use augmentation without tying |
| FROB-REF-215 | exact arithmetic over its declared size | `expression`, `ranges` (here the sizes of the request: group order, copies and channels), `budget_bits`, `cap_bits` | the record's four repairs in order; for this verb repair 2, narrowing the declared input, reads "reduce the number of copies or channels", and repair 4 "declare a larger size with its reason in the contract, or take the tolerance route labelled `Tested`" |
Both exit with code 3; malformed input is a protocol error with the envelope and exit 3. The returned fields and ranked repairs are those of N13-REF's records, in its order, and `refusal_envelope_shape` of N13-REF runs against this verb when it closes.
**Cost and caching.** The decomposition costs O(d³) once per model and channel space and is cached by `ModelId` (a pure cache keyed by identity; explicit-generator requests are keyed by the digest of the request).
**Determinism.** D0.

## Acceptance criteria
- [ ] `frob algebra irreps … --json` returns one envelope with the fields above; the verb is generated on the CLI and as the MCP tool `algebra_irreps` from the registry, with schemas under `schemas/`.
- [ ] C₃ on three legs, in = out = `permutation:3`: constituents trivial (real, m = 1) and one complex pair (m = 1); `free_parameters` 3, `unconstrained_parameters` 9, `reynolds_rank` 3.
- [ ] C₂ × C₂, in = out = `regular*64`: four real constituents of multiplicity 64; `free_parameters` 16,384; unconstrained 65,536.
- [ ] D₆ on `permutation:6`: four real constituents of multiplicity one; `free_parameters` 4. C₆ on `permutation:6`: two real and two complex constituents; `free_parameters` 6.
- [ ] The regular representation of the quaternion group Q₈ (given by generators) is refused with FROB-REF-214, returning the degree-two character and indicator −1; exit 3.
- [ ] For every group of GATE-MARROW-02 and 100 random pairs of signed-permutation channel spaces each, `free_parameters` equals `reynolds_rank` (the count half of PO-MARROW-05, measured early; the containment half is BD-325).
- [ ] With `--design` and no task the envelope carries `group_kind: "mech"` and a warning that the mechanical group does not license tying.
- [ ] `frob algebra irreps C2xC2 --rep permutation:4 --json` (the registry example) returns four real constituents of multiplicity one and `free_parameters` 4.
- [ ] Negative controls caught: (i) a complex-type block counted as real gives 2 for C₃ and fails against the Reynolds rank; (ii) the indicator computed with χ(g)² instead of χ(g²), which equals ⟨χ, χ̄⟩ and so agrees with ι on every real and complex character and differs only on quaternionic ones, labels Q₈'s degree-two character real (indicator +1) and fails the Q₈ refusal test; (iii) a complex pair's multiplicity taken as m(χ) + m(χ̄) (each pair counted twice) gives 17 instead of 5 for C₅ on `permutation:5` and fails against the Reynolds rank.

## Considerations
- The count is reported to the agent before training; it is one of the three reasons the blocks exist (the others: optimization on exactly the free parameters, and block-diagonal linearized dynamics).
- The ceiling of the benefit is the order of Γ_obs: 2 for a robot with a forward sensor suite, 4 for a blind fore-aft-symmetric quadruped, 12 for a blind radial hexapod; augmentation already recovers much of it. The verb reports the factor and makes no learning claim.
- Only the observation-preserving group may tie weights; a request bound to a design defaults to Γ_obs and labels anything else.
