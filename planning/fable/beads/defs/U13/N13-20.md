## Background
GATE-MARROW-02 (claim: Known answer; M1; TARGET): character tables and isotypic projectors correct for Cₙ and Dₙ with n ≤ 12, their products with C₂, and S₄, against tables on file. The mechanism is BD-048 and the user-visible capability is the verb `algebra.irreps` (N13-14). A capability counts as implemented only when it is reachable through `frob --json` with a documented schema and exit code and its gate has a recorded pass carrying measured values in a receipt that names the commit, the hardware fingerprint and the seed. This bead is the end-to-end script that drives the real binary over the whole gate set and produces the receipt from which that record is made. Tier: Solid. It is a test bead; a session that did not implement BD-048 or N13-14 runs it for the record.

Why an end-to-end run in addition to library tests: the verb adds parsing, schema, exact-number serialization (field elements travel as strings), caching and the envelope; a character table that is right in memory and wrong on the wire (a cyclotomic element flattened to a float) would pass every unit test and mislead every agent.

## Scope
In: `scripts/e2e/algebra_irreps.sh`; the comparison of verb output with the oracle tables; the known-answer commands; the refusal runs; the MCP parity check for this verb; the receipt from which the gate row is recorded.
Out: the mechanism and the verb (BD-048, N13-14); the oracle generator (BD-048).

## Technical approach
The script is plain shell driving `frob` (and `frob-mcp` for one parity step), idempotent, exact (no seed), exits non-zero on any failed assertion.
1. `frob doctor --json` and `frob capabilities --json`: record the build, and assert `algebra.irreps` is listed.
2. **Gate loop.** For each of the 49 presentations F in {Cₙ, Dₙ, Cₙ × C₂, Dₙ × C₂ : 1 ≤ n ≤ 12} ∪ {S₄}: `frob algebra irreps --family F --in natural --out natural --json`. Assert: exit 0; `ok: true`; the group order equals the expected order (n, 2n, 2n, 4n, 24); the number of classes equals the expected count; the character table in the envelope equals `tests/fixtures/oracle/characters/F.json` after matching rows and classes (exact string comparison of field elements in canonical form); the multiplicities and projector ranks of the natural representation equal the oracle's; every constituent's type equals the oracle's (`real` or `complex`).
3. **Isomorphic presentations agree.** The tables for C₆ and C₃ × C₂, for D₂ and C₂ × C₂, and for D₆ and D₃ × C₂ are equal after matching.
4. **Known answers.** `--family C3 --in permutation:3 --out permutation:3` → `free_parameters` 3 with one complex pair; `--family C2xC2 --in regular*64 --out regular*64` → 16,384; `--family D6 --in permutation:6 --out permutation:6` → 4; `--family C6 --in permutation:6 --out permutation:6` → 6.
The registry's published example for the verb (read from `frob schema` or `registries/verbs.toml`, not hard-coded; at the time of writing `frob algebra irreps C2xC2 --rep permutation:4 --json`) is run as a fifth known answer: four real constituents, `free_parameters` 4.
5. **Refusals.** The quaternion group Q₈ by generators → exit 3, FROB-REF-214 with the character and indicator −1; generators that close to more than 256 elements → exit 3, FROB-REF-214 with the order reached and the generators; the oversize request of N13-14's `oversize_refused_215` (its input saved as `tests/fixtures/irreps/oversize.json`, so the script and the unit test use the same bytes) → exit 3, FROB-REF-215 with the expression, sizes and budget; a malformed generator list → exit 3 with a protocol refusal and the envelope.
6. **Determinism.** Every command of step 2 is run twice; the two envelopes are byte-identical apart from the `cost` block.
7. **Surface parity.** For three presentations the same request through `frob-mcp` (tool `algebra_irreps`) returns structured content equal to the CLI envelope.
8. **Receipt.** The script runs the gate's tier entry, `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g1_known_answers --features gauntlet-mutations -- GATE-MARROW-02` (KA-258's row over the same 49 presentations and oracle files, the computation being exact so the seed only names the run, with the gate's registered controls in the same run), logs the receipt hash with the measured values it carries (presentations compared 49, disagreements 0, peak rational bit length, wall time) and ends by printing it; the script writes no gate row. **Record:** a session that did not implement BD-048 or N13-14 enters the row from that receipt with `cargo run -p frob-conformance --example record_gate -- --gate GATE-MARROW-02 --receipt <hash>` (N38b-19, the one writer of gate rows): status `pass` with the measured values, commit, hardware fingerprint, command and receipt hash; on any disagreement `fail` with the first differing table entry.
9. **Negative controls.** The script also re-runs step 2 against a build with each registered control active (the conjugate missing in the projector; a swapped sign in a degree-two row of D₅; a corrupted multiplication-table byte) and asserts that each makes the comparison fail; a control that is not caught fails the script, and in the tier run of step 8 it is reported `missed`, so the recorder refuses `pass` (`control-not-caught`).

## Acceptance criteria
- [ ] The script exits 0 on a correct build and prints the receipt of the gate's `g1_known_answers` run; GATE-MARROW-02 is recorded from that receipt with `record_gate` (never by the script) with measured values: 49 presentations, zero disagreements.
- [ ] Field elements cross the wire exactly: the envelope's character entries are strings in the canonical exact form and compare equal to the oracle as strings; no entry is a JSON floating number.
- [ ] The four known answers (3; 16,384; 4; 6), the registry example (4) and the four refusals (two FROB-REF-214, one FROB-REF-215, one protocol) are observed with the stated exit codes and payloads.
- [ ] Repeated runs give byte-identical results; the MCP result equals the CLI envelope for the three sampled presentations.
- [ ] Each of the three negative controls is caught by the comparison in step 2 (the script fails under each).
- [ ] The log satisfies the logging standard below and contains no private data (the fixtures are synthetic groups).
- [ ] The gate record is written by a session that did not implement BD-048 or N13-14, and the bead's closing reason cites this script's log.

## Test plan
### Unit tests
Not applicable to a script bead beyond `shellcheck`-clean shell and a dry-run mode (`--dry-run` prints the command list without running), which a unit test of the script harness exercises.
### End-to-end script and logging
`scripts/e2e/algebra_irreps.sh`, sourcing the `STD-E2E` helper. NDJSON at `target/e2e-logs/algebra_irreps/<utc>.ndjson` with a human-readable transcript beside it. Every line has ts, script, bead (`N13-20`), step, event; `cmd` events carry the exact command line, exit code and wall time; each envelope's evidence block is copied (claim kind, class, tier `static`, determinism `exact`, identities); `assert` events carry the presentation, the quantity compared and both values on failure (the first differing table entry, row and class, as exact strings) with the paths of the saved envelope and the oracle file; `metric` events carry counts and peak bit lengths with their budgets; `refusal` events carry code, message and returned payload; the final `summary` line gives assertions passed and failed and the gate touched (GATE-MARROW-02).
### Known answers and negative controls
KA-258 (tables and projectors on file), KA-231 (3), KA-232 (16,384). Controls: the three planted defects of step 9, drawn from the registry entries of BD-048. Metamorphic: isomorphic presentations agree; relabelling the points of a presentation leaves the table unchanged. Determinism lanes: twice on one machine; macOS and Linux builds give identical envelopes (class D0).

## Considerations
- The oracle tables are produced by an independent generator from closed forms and are never regenerated from the candidate; if the oracle and the candidate disagree, the first suspect is whichever is younger, and the disagreement is resolved by hand on the smallest group that shows it.
- The whole loop should take seconds (TARGET: under 2 minutes including process start-up 49 times); a slower run is logged as a finding, not a failure.
- The M1 exit review reads this gate row; the same script joins the smoke battery with a reduced loop (n ≤ 6).
