## Background
A kill gate names its trigger and its fallback in advance and is never quietly re-scoped. Its decision is recorded as an ADR at the milestone the gate register names. A trigger, a threshold or a fallback changes only by a dated amendment to the register, with its reason, made before the measurement it governs. A kill gate that fires is not a failure of the program: the fallback is the plan.

**KILL-MARROW-BLOCKS** (decided at M4; owner: Marrow).
- Trigger: GATE-MARROW-04 fails after one repair cycle, or the exact field arithmetic for n ≤ 12 exceeds its bit budget.
- Fallback: equivariant layers are produced by Reynolds projection in `f64` with an idempotence test, classed `Tested`; the free-parameter count is reported from the projection's rank.
GATE-MARROW-04 (Known answer, M4): proof obligation PO-MARROW-05 (the block parameterization spans exactly the commutant) holds exactly for every group of GATE-MARROW-02 on 100 random pairs of channel spaces each, and all eight planted Marrow mutations are caught by at least three fixtures each. The mechanism under decision is BD-325. The gate sits behind two bets: symmetry buys sample efficiency (whose own kill gate, on the learning side, reduces symmetry to augmentation and metamorphic testing), and the right group is Γ_obs.

Why the fallback is acceptable: the Reynolds operator W ↦ |Γ|⁻¹·Σ_g ρ_out(g)·W·ρ_in(g)⁻¹ projects any matrix onto the equivariant maps for every type of representation, and with signed-permutation representations it costs |Γ|·d_out·d_in operations, which is small. What is lost with the blocks: optimization on exactly the free parameters (the fallback projects after every optimizer step instead), an exact parameter count before training (the fallback reports a numerical rank), and the finer block-diagonalization of linearized dynamics (isotypic projectors remain). What is lost in evidence: exactness. A floating-point projection with an idempotence test is `Tested`, never `Certified`.

## Scope
In: the decision, its measurement inputs, the ADR, the gate-register row, and the downstream switch if the gate fires.
Out: the measurement (BD-325); the fallback path's code, which already exists as BD-325's Reynolds reference path and only changes role.

## Technical approach
**Inputs (all produced by BD-325's run and its log).**
1. The GATE-MARROW-04 result: per presentation, failures of containment or rank over 100 pairs; the mutation matrix (catches per mutation).
2. Whether a repair cycle was used. One repair cycle means: one diagnosed defect, one fix, one full re-run; a second failing run fires the gate.
3. Exact-arithmetic budget: the peak bit length of any numerator or denominator in the field computations for each n ≤ 12 (orders m = lcm(n, 4) up to 44, field degree up to 20), against the declared budget.
**Decision procedure.**
1. If GATE-MARROW-04 passed (first run or after exactly one repair cycle) and no computation exceeded its bit budget: record "not fired". Blocks are the mechanism; evidence class `Certified` where the PO-MARROW-05 check is attached, else `Tested`.
2. If GATE-MARROW-04 failed after one repair cycle, or any n ≤ 12 exceeded the budget: record "fired"; adopt the fallback.
3. Mixed case (the block clause holds for some families and fails for others, for example only for the degree-20 field at n = 11): the gate is one gate and fires; an amendment that narrows the supported families must be proposed, dated and approved before any re-measurement, never applied silently.
**Record.** An ADR in `docs/adr/` with the inputs, the decision, the date and the commit; the row of KILL-MARROW-BLOCKS in `registries/gates.toml` with status `not fired` or `killed: fallback adopted`; the review log entry.
**What changes downstream if it fires.**
- `frob-algebra`: `EquivariantLinear` is constructed by the Reynolds path: parameters are a dense W, projected by the Reynolds operator in `f64` after initialization and after every optimizer step; each projection is followed by the idempotence test ‖R(R(W)) − R(W)‖_∞ ≤ 64 ulp·‖W‖_∞ and the equivariance residual max_g ‖ρ_out(g)·W − W·ρ_in(g)‖_∞ within the same bound; a violation is a refusal of the step, not a warning. The `frontier-blocks` feature is removed from default documentation and the capability is described by the fallback's name.
- `algebra.irreps`: `free_parameters` is reported from the numerical rank of the projection (singular values above a recorded threshold) and labelled `Tested`; the exact formula's value is shown beside it as a cross-check, not as the claim.
- The three-arm equivariance experiment (learning chapter) uses projected layers for its equivariant arm; its own kill gate is unchanged.
- Nested (wreath-product) tying (N13-26) uses Reynolds projection over the nested group.
- The modal analysis keeps isotypic projectors (exact, from BD-048), which were never under this gate.
- Evidence: every result that depended on block exactness drops from `Certified` to `Tested`.
**What stays the same either way.** Groups, characters and projectors (GATE-MARROW-02); Γ_mech and Γ_obs (GATE-MARROW-03); augmentation and metamorphic tests; the type barrier that only Γ_obs ties weights.

## Acceptance criteria
- [ ] The ADR exists at the M4 exit with the three inputs, the decision and its date; the gate register row shows `not fired` or `killed: fallback adopted`, citing BD-325's log by receipt hash.
- [ ] If not fired: nothing downstream changes, and the ADR says so.
- [ ] If fired: the Reynolds-path layer passes its idempotence and equivariance tests on every gate group; `algebra.irreps` reports the rank-based count with class `Tested`; N13-26 and the learning experiment are notified by a dependency note; the capability table names the fallback.
- [ ] No trigger, threshold or fallback was changed after the measurement; any amendment carries a date earlier than the run it governs.
- [ ] The decision is made by the Marrow lead and reviewed by a session that did not implement BD-325.

## Test plan
### Unit tests
For the fired branch (kept runnable in both branches, because the Reynolds path is the oracle): `reynolds_f64_idempotent` (‖R(R(W)) − R(W)‖_∞ within 64 ulp on 10⁴ random W per gate group); `reynolds_f64_equivariant`; `numerical_rank_equals_formula` (on the gate set the rank found in `f64` equals Σ cᵢ·mᵢ^out·mᵢ^in); `projected_step_stays_in_subspace` (a gradient step followed by projection satisfies the equivariance residual bound).
### End-to-end script and logging
`scripts/e2e/marrow_blocks.sh --decide`: reads BD-325's gate log, evaluates the trigger mechanically, prints the decision inputs and the branch, and fails if the ADR file is missing or disagrees with the mechanical evaluation. `STD-E2E` NDJSON at `target/e2e-logs/marrow_blocks/<utc>.ndjson`: `metric` lines for gate failures, repair cycles used and peak bits against budget; an `assert` line for "ADR matches inputs"; summary naming KILL-MARROW-BLOCKS and its status.
### Known answers and negative controls
Under either branch the C₃ case must give three parameters (KA-231) and the C₂ × C₂ case 16,384 (KA-232). Negative control for the fallback's test: a Reynolds operator that omits one group element fails idempotence or equivariance and must be caught. Determinism: the `f64` projection is D2 per platform; the count is identical on every platform.

## Considerations
- The second trigger (bit budget) is about cost, not correctness: if cyclotomic arithmetic of degree 20 makes exact bases too large, the honest move is the fallback, not a larger budget granted after the fact.
- OPEN-MARROW-2 (exact route beyond n = 12) defaults to no and is independent of this decision.
- Firing this gate does not weaken the claim that the groups are right; it weakens only the claim that the parameterization is exact.
