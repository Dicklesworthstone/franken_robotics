## Background
A revolute coordinate is stored as a unit complex number (c, s) and an integer turn count k (BD-012); no raw angle is stored in state. That raises a question the angle representation hid: which physical laws depend only on where the joint points, and which depend on how far it has turned? The rule (Solid; a subsection added late, with no earlier work item):

A law is `periodic` if it reads only the unit complex number, and `lifted` if it reads the angle θ = atan2(s, c) + 2π·k. These are different state spaces, and using the circle where a law is lifted loses state.

Counterexample. A joint has a linear torsion spring of 0.5 N·m/rad with rest angle 0. Held stationary at θ = 0 and at θ = 2π it has identical link poses and zero velocity. At 2π the spring stores ½ × 0.5 × (2π)² = π² J, which is 9.8696 J, and exerts −π N·m. A state without the turn count cannot tell the two apart, and a replay from it creates or loses π² J.

Owners: `frob-lie` (coordinate and counter), `frob-model` (declarations), `frob-actuate` (springs). This bead is the typing rule and its enforcement; the turn count as simulator state is N13-35; the gate's end-to-end measurement is N13-36 and N13-37. Rejected alternatives: always storing a raw angle (reintroduces wrap handling and resolution loss in every periodic law and every policy observation); always reading the lifted angle (forces a turn count into the state of every wheel, where it is physically meaningless and only costs memory and digest stability); deciding per law by convention in comments (the defect this rule exists to remove).

## Scope
In: the access type in `frob-lie`; the declaration field on every element that reads a revolute coordinate; the classification of the element catalogue; derivation of which joints need turn state; the stage-1 refusal and its registry entry; the spring element's lifted evaluation; unit tests.
Out: the turn count in state layouts, snapshots and digests (N13-35, N13-37); the alias witness for encoders (the sensing work; exercised by N13-36); device kernels for springs.

Order of work. The refusal is raised inside stage 1 of the compile pipeline, so this bead follows the stage-1 check (the Skeleton unit's N14a-08) and the `design.check` stage runner (BD-110), and adds its rule to them. The Skeleton beads N14a-08 and N14a-09 state the same check and the same derivation of which joints need the count from their side; they keep this bead as `related`, so there is one direction and no loop: stage 1 and the runner first, then this rule and its refusal, then the end-to-end bead N13-36.

## Technical approach
**Access types (`frob-lie`, DESIGN).** `enum AngleAccess { Periodic, Lifted }`. A periodic law is written against `&UnitComplex` (the (c, s) part only) and cannot name k: the type it receives has no turn count. A lifted law is written against `&Revolute` (with k) and may use `lifted_angle()` on the host, or (k, c, s) directly in kernels (for a linear spring the kernel form is θ = φ(c, s) + 2π·k with φ the branch angle from a guarded half-angle evaluation; the lifted angle itself never needs to be stored). The compiler therefore sees misuse as a type error inside this workspace; declarations cover elements that arrive as data (cards, imported models).
**Declarations (`frob-model`, cards in `frob-actuate`).** Every element that reads a revolute coordinate declares `angle_access: "periodic"` or `"lifted"` in its card or constructor; there is no default (no physics field has a silent default). Classification of the catalogue:
- Lifted: linear torsion springs; cable and hose wrap; multi-turn travel limits; lead screws; tether winding; any element whose potential, force or geometry is a non-periodic function of the angle.
- Periodic: wheel rolling; gravity and inertial coupling through link pose; cogging and ripple torques; single-turn absolute encoders; any element that is a function of (c, s) alone.
A lifted element's parameters that are angles (a rest angle, a wrap offset, a travel limit) are stored as lifted values (k, c, s) or as exact rationals of a turn in the design, never as a float reduced modulo one turn.
**Which joints carry turn state.** The model compiler derives `needs_turn_state(joint)` = some lifted element reads the joint. A joint may also declare `turns: "tracked"` (a task wants the count in observations) or `turns: "untracked"`. The declaration is an assertion that is checked: `untracked` together with a lifted element is the refusal below; nothing is defaulted silently, the derived value is written into the compiled model with provenance `derived`.
**Stage-1 refusal.** `design.check` stage 1 refuses a lifted law on a joint whose state omits the turn count. The rule names this refusal by its condition ("lifted law on a joint without turn state"), and no code has been assigned to it. DESIGN: a new code in the design-and-model family (candidate FROB-REF-128, to be confirmed by the owner of the refusal registry, since codes are never reused; FROB-REF-127 is already proposed by the Skeleton registry N14-REF for an import refusal), registered in `registries/refusals.toml` with: meaning "a lifted law reads a joint whose state omits the turn count"; trigger as above; returned: the joint path, the element and its card field, the joint's `turns` declaration; ranked repairs as typed edits: 1. set the joint's `turns` to `tracked`; 2. replace the element by a periodic one if the physics allows (a spring with a hard travel stop inside one turn is still lifted; a cogging model is periodic); 3. remove the element. Exit code 3. The same check runs on import: an imported continuous joint with a spring is compiled with turn state and the loss report says so.
**Torsion spring (`frob-actuate`).** `TorsionSpring { stiffness κ, rest θ₀ (lifted) }`, declared lifted: energy E = ½·κ·(θ − θ₀)², torque τ = −κ·(θ − θ₀), with θ − θ₀ = (φ − φ₀) + 2π·(k − k₀) formed from the two branch angles and the integer difference so that large turn counts lose no precision. Port-energy accounting treats E as stored energy.
**Observation consequence (stated here, built by the sensing work).** An encoder that reports the angle modulo one turn does not observe k. For a joint with a lifted law, the worlds k = 0 and k = 1 at rest deliver identical observations and need holding torques that differ by π N·m in the example, so the alias search returns an alias witness. The remedies it lists are a multi-turn encoder, a homing move and a torque reading.
**Determinism and evidence.** The classification and the refusal are D0 static checks; results carry the claim product of a static analysis.

## Acceptance criteria
- [ ] Every element type in the M1 catalogue that reads a revolute coordinate has an `angle_access` declaration; a test enumerates the catalogue and fails on a missing declaration.
- [ ] Inside the workspace a periodic law cannot read k (compile-fail test: a function taking `&UnitComplex` that tries to access the turn count does not compile).
- [ ] `frob design check` on a design with a torsion spring on a joint declared `turns: "untracked"` returns the refusal (exit 3) with the joint, the element and the three repairs; with `turns` derived or `tracked` it passes.
- [ ] `needs_turn_state` is true exactly for joints read by a lifted element or declared tracked, on the M1 archetypes and on 1,000 generated designs.
- [ ] Spring values: at (c, s, k) = (1, 0, 0) energy 0 J and torque 0 N·m; at (1, 0, 1) energy π² = 9.869604401089358 J and torque −π = −3.141592653589793 N·m, to 10⁻¹² relative in double precision; at k = 10⁶ the difference θ − θ₀ for a rest angle at k₀ = 10⁶ − 1 is 2π to 4 ulp.
- [ ] The refusal code is registered (or the candidate replaced by the registry owner's choice) and an unknown-code load error does not occur.
- [ ] Negative controls caught: (i) a spring evaluated on the branch angle alone reads 0 J at θ = 2π and fails the value test; (ii) a rest angle stored modulo one turn gives the wrong torque for θ₀ = 3π and fails; (iii) an element with no declaration fails the catalogue test; (iv) a design that sets `untracked` on a sprung joint and is accepted fails the refusal test.

### Known answers and negative controls
The §13.11 known answers: energy 0 and π² J; torque 0 and −π N·m. Control stated by the rule itself: a wheel with only periodic laws replays bit-identically from a state with k dropped (measured in N13-36), which shows the rule binds only lifted laws. Controls (i) to (iv). Determinism: static checks D0; spring values identical on every platform to the stated tolerance.

## Considerations
- Travel limits: a limit is a lifted quantity (it distinguishes θ = 170° from θ = 170° + 360°); a joint that has limits therefore has turn state, and the limit comparison is the lexicographic test of BD-012.
- Lead screws and tether winding couple a revolute coordinate to a length; their card states the lead per turn as an exact rational so that length = lead·(k + φ/2π) is exact in k.
- The count of joints with turn state is reported by the model compiler, because each costs one integer slab on device tiers.
