## Background

`frob-io` (layer 2, tier Solid) is Skeleton's import and export crate. Reference robots, public models used
as parity fixtures and benchmark baselines, are mostly published as MJCF, MuJoCo's XML model format: the
Unitree Go1, Go2, A1, H1 and G1, ANYmal B and C, Spot, Cassie, Stretch 3, TIAGo, and for import parity only
Booster T1, Apptronik Apollo, Fourier N1, OP3, TALOS and Barkour (all from MuJoCo Menagerie under BSD-3, MIT
or Apache-2.0 licences, to be re-checked at admission). The URDF importer and the in-house XML reader
(elements and attributes; no entities or DTDs, so no third-party parser enters the core) are BD-065. This
bead adds the MJCF importer on the same reader and closes the seed's second half by integrating export
(N14a-25).

Rules that every importer follows:

- Every import produces a loss report: fields dropped, defaults filled, contact parameters that have no
  exact equivalent, inertias that fail the consistency test with the proposed repair, actuator limits absent
  and filled from a card marked `assumed`. The supported subset is documented, and every element outside it
  is echoed in the loss report with its file and line.
- Imported bodies get `fill: declared` with the source's inertial values; the mass-support bound is applied
  to them only where the source states a mass Region, and is otherwise reported as not checked.
- Macros are expanded outside. `frob-io` executes no script found in a model, accepts the expanded document
  and records its hash and the name of the tool the user says produced it.
- Round trips compare meaning, not bytes: forward kinematics, mass properties and the map of identifiers.

Why a loss report and not a best-effort converter: a converter that drops what it does not understand yields
a plausible wrong robot. RISK-13 names it: reference-robot imports hide lossy contact mappings; its leading
indicator is a field missing from a loss report in the field-coverage diff; its mitigation is the loss
report and the contact mapping labelled parity-only. Rejected alternative: linking MuJoCo's own parser (a C
library in the core graph, and a second source of truth for what a model means).

## Scope

In: the MJCF subset and its mapping to a design term; default-class and include resolution; orientation and
size conventions; inertia inferred from geoms; the MJCF path of the verb `design.import`; the loss-report
entries specific to MJCF; forward-kinematics parity on the MJCF reference robots (the MJCF rows of
GATE-SKEL-01); integration of export.

Out: the XML reader and URDF (BD-065); the loss-report schema, field-coverage diff, `--strict` machinery and
round-trip comparator (their own bead); folding and reduced models (their beads); export (N14a-25); oracle
capture (BD-067); fuzzing (BD-307); SDF and OpenUSD import.

## Technical approach

Layout (DESIGN): `crates/frob-io/src/mjcf/{resolve.rs, map.rs, geom.rs, inertia.rs, actuators.rs,
constraints.rs}`.

Steps:

1. Read the document with the in-house reader under the import limits. Resolve `include` files inside the
   import root only (a path outside it is refused; nothing is fetched), recording each file's hash.
2. Resolve `compiler` settings that change meaning (`angle`: degree by default, or radian; `eulerseq`;
   `autolimits`; `inertiafromgeom`; `meshdir`) and the `default` class tree with `childclass`. Each resolved
   attribute keeps the file and line of the element that supplied it, so the loss report and the
   field-coverage diff work on the resolved document.
3. Map by the table below, converting each convention exactly once at this boundary.
4. Emit the design term, the identifier map (source name ↔ instance identifier; names are untrusted text),
   and the loss report.
5. Canonicalize; the result is a normal design with a `DesignId`.

Mapping table (DESIGN; the documented subset):

| MJCF | Design term | Notes and loss-report entries |
|---|---|---|
| `mujoco@model` | `name` | Untrusted text; the identifier is a sanitized copy |
| `body` (`pos`, `quat`, `euler`, `axisangle`, `xyaxes`, `zaxis`) | A body and the placement of its joints | Orientation forms converted once; `mocap` bodies are unsupported and listed |
| A top-level body with `freejoint` or a `free` joint | The root on its floating base | A top-level body with no free joint is welded to the world; a design's root floats, so this is listed (and refused under `--strict`) |
| `joint` `type` hinge (the default), slide, ball, free | Classes `R`, `P`, `S`, `free` | `pos` and `axis` give the screw in the body frame; several joints on one body become a product with massless intermediate bodies |
| `joint@range` with `limited` or `autolimits` | `limits` | An unlimited hinge or slide is written `unbounded` and listed as default-filled |
| `joint@damping`, `frictionloss` | Joint-side `damping`, `friction` | |
| `joint@armature` | An override of the bound actuator card's rotor inertia | On a passive joint there is no equivalent: listed, severity high (it changes dynamics) |
| `joint@stiffness`, `springref` | Not mapped | A joint spring has no field in the design format: listed, severity high |
| `joint@ref`, a keyframe named `home` | `home` | Other keyframes are listed |
| A body with no joint | A `fixed` joint to its parent | Folded into the parent on request by the fold rule; each folded link is listed |
| `inertial` (`pos`, `quat`, `mass`, `diaginertia` or `fullinertia`) | `fill: declared` with `mass_properties`, provenance `datasheet`, source file and line | The inertia is rotated by `quat`; `mass-support: not checked` unless the body also has mass-bearing geoms |
| No `inertial` | `fill: declared`, with values computed from the body's geoms as the source's own rule does (solid geoms at `mass`, or at `density`, default 1000 kg/m³) | Source noted as "inferred from geoms"; the Region is the union of those geoms, so the mass-support bound applies; a default density is listed as default-filled |
| `geom` sphere, capsule, cylinder, box, ellipsoid, mesh | `collision` (when it collides) or `visual` | MJCF sizes are half-sizes: a box's edges are twice `size`, a capsule's or cylinder's length twice its half-length; `fromto` gives placement and length |
| `geom` plane, hfield, sdf; world geoms | Not mapped | World geometry belongs to a scene: listed |
| `geom@friction`, `solref`, `solimp`, `condim`, `margin`, `gap` | An interface card under the lossy parity-only mapping of soft-contact parameters | Always listed as lossy; no end effector and no contact law is inferred, so the report says "no contact law declared" and stage 1 refuses (`FROB-REF-121`) until one is declared by edit |
| `site` | A named port frame | |
| `actuator` motor, position, velocity, general (`joint`, `gear`, `ctrlrange`, `forcerange`) | An `actuator` reference to a generic card marked `assumed`, with overrides for the limits the source states; `gear` as a transmission ratio | Servo gains (`kp`, `kv`) are controller assumptions: listed |
| `equality` joint (linear), fixed `tendon` | A `coupling` transmission row | Non-linear polynomials and spatial tendons are unsupported and listed |
| `equality` connect, weld | A `closure` (class `S`, or fixed) | |
| `contact` exclude, pair | Not mapped | The design format has no collision-filter field: listed |
| `sensor` | Not mapped | The source states no rate and no clock, and a sensor without them is refused; each is listed with the card that would fit |
| `asset` mesh | A mesh blob by content hash | Textures and materials are visual only |
| `option`, `size`, `visual`, `statistic`, `custom`, `extension`, plugins | Not mapped | Simulation settings are not part of a design: listed |
| Any element or attribute not above | Not mapped | Echoed with file and line; refused under `--strict` (`FROB-REF-122`) |

MJCF is unitless; the importer reads lengths as metres, masses as kilograms and time as seconds and records
that assumption in the report.

The verb. `frob design import <file> --format mjcf --name <design name> [--strict] [--expanded-by <tool>]
[--fold-fixed] [--reduced <profile>] --key <idempotency-key> --json` (the same verb line as BD-065's and the
verb registry's); kind `mutate`; output as for URDF: the new `DesignId`,
the source hashes, the loss report's identifier, counts (mapped, default-filled, dropped, unsupported,
repaired-proposed) and the identifier map. Evidence: class `Tested`, tier `static`, determinism D0 (bit-identical
on every platform); a
parity result against the oracle is a Parity claim and never a Reality claim. Refusals: `FROB-REF-122` (an
unsupported element under `--strict`), `FROB-REF-832` (an import over a size, depth or element limit,
registered by N37-REF; the limits by profile and their crafted corpus are N37-05, which hardens this importer
after it lands), `FROB-REF-734` (an `include` or a mesh file that resolves outside the import root, exit 5;
the path jail of N37-11), the mass-dropped refusal of the reduced-model rule (ledger slug
`import-mass-dropped`, family `1xx`, raised by N14b-34 under the number N35x-02's run assigns); `FROB-REF-828`
(a document whose leading bytes are an executable, script, pickle or archive signature, refused by the verb
dispatcher's sniff of N37-03 before this reader runs); `FROB-REF-103` and `FROB-REF-125` (bug guards: the produced
term fails the design reader's field or schema-version check), as the verb registry's row lists them; an inertia
that fails consistency is imported as declared, listed with its proposed repair, and refused later at stage 2
(`FROB-REF-104`).

Parity measurement. For each MJCF reference robot: import; for each of 10⁴ seeded configurations of the
tree's joint coordinates inside limits, compute world poses of every body on the host reference
(forward kinematics of BD-061) and compare with the pinned oracle fixture: position difference in metres and
the angle of the relative rotation in radians. Fixtures are captured out of process at a pinned oracle
version and are never regenerated from this code. Order of work: the fixture-capture bead follows this one
in the bead graph (it needs an importer to name the bodies it captures), so this bead closes on the parity
test harness passing against a small fixture set captured by hand for two robots; the full MJCF rows of the
gate are measured and logged by the end-to-end bead N14a-31 once all fixtures exist, and the gate is entered
once by its one recorder, N14b-24, from the receipt of its `g2_parity` tier run (convention 9).

## Acceptance criteria

- [ ] GATE-SKEL-01 (TARGET), seed condition: each reference robot imports with forward-kinematics parity
      against the oracle within 10⁻⁹ m and 10⁻⁹ rad over 10⁴ configurations, and its loss report lists every
      dropped field found by a field-coverage diff. This bead supplies the MJCF rows' mechanism and closes when
      the parity harness passes on the hand-captured fixtures of two MJCF robots (one quadruped, one humanoid),
      with the measured maxima logged per robot with commit and seed; the rows for every MJCF reference robot
      are measured and logged by N14a-31 once BD-067 has captured all fixtures, and N14b-24 records the gate.
- [ ] For every MJCF fixture the field-coverage diff is empty: each element and attribute of the resolved
      document is mapped or present in the loss report.
- [ ] A box geom of `size="0.1 0.05 0.02"` imports with edges 0.2, 0.1 and 0.04 m; a capsule of
      `size="0.03 0.1"` with radius 0.03 m and length 0.2 m.
- [ ] A body with no `inertial` and one box geom at the default density imports with mass 1000 × its volume
      and is listed as default-filled; the same body with `inertial` imports the stated values.
- [ ] `angle="radian"` and the default degree setting import the same joint range from equivalent files.
- [ ] A `default` class value and an explicit attribute resolve as the source's rule says (explicit wins),
      and the report cites the line of whichever supplied the value.
- [ ] A linear joint equality becomes a `coupling` row; a `connect` equality becomes a `closure`; a spatial
      tendon is listed as unsupported and refuses under `--strict` (`FROB-REF-122`).
- [ ] An `include` that points outside the import root is refused with `FROB-REF-734` and nothing is read.
- [ ] The same bytes give the same `DesignId` and report hash on Linux and macOS.
- [ ] Export (N14a-25) is integrated: a design imported from MJCF exports to MJCF and re-imports with equal
      forward kinematics and mass properties. The MJCF re-import round trips of the exporter live here, because
      they need this importer and N14a-25 is its dependency: the worked design `quad-a` exported to MJCF and
      re-imported gives forward kinematics equal within 10⁻¹² m and 10⁻¹² rad at 100 seeded configurations, mass
      properties equal within 10⁻¹² relative and a bijective identifier map; a design with a closure round-trips
      its `equality connect` to a `closure`.

## Test plan

### Unit tests

`cargo test -p frob-io mjcf`. Real files; hand-written minimal models are labelled `synthetic`.

- `mjcf_half_sizes`: the box and capsule cases above.
- `mjcf_inertia_from_geoms`: a 0.2 × 0.1 × 0.04 m box at density 1000 kg/m³ gives 0.8 kg and
  diag(0.8·(0.01 + 0.0016)/12, 0.8·(0.04 + 0.0016)/12, 0.8·(0.04 + 0.01)/12) kg·m².
- `mjcf_inertial_rotation`: `diaginertia="1 2 3"` with a quarter turn about z imports as diag(2, 1, 3).
- `mjcf_angle_units`, `mjcf_default_class_resolution`, `mjcf_include_path_jail`.
- `mjcf_joint_types`: hinge, slide, ball, free map to `R`, `P`, `S`, `free`; two hinges on one body become a
  product with a massless intermediate body.
- `mjcf_unlimited_hinge_is_unbounded_and_listed`.
- `mjcf_equality_and_tendon`: the three cases of the acceptance list.
- `mjcf_armature_on_passive_joint_listed_high`.
- `mjcf_no_contact_law_invented`: the report says "no contact law declared".
- `mjcf_fk_parity_<robot>`: one test per fixture; maxima against 10⁻⁹ m and 10⁻⁹ rad.
- `mjcf_planted_dropped_field`: an unknown attribute at a known line appears in the report with that line.
- `mjcf_roundtrip_quad_a` (moved here from N14a-25): export `quad-a` to MJCF, import, compare with N14b-20's
  comparator at the thresholds of the acceptance list; the exporter mutant that prints 6 significant digits fails.
- `prop_export_import_meaning_mjcf`: 10² `synthetic` designs from the generator through MJCF export and import;
  meaning equal (the URDF half of the property is N14a-25's).

### End-to-end script and logging

`scripts/e2e/skel_import_mjcf_export.sh` (bead N14a-31) drives `frob design import --format mjcf`, `frob
design check --stages 1-2`, the parity comparison and the export round trip from the CLI. Per step it logs
the command line, exit code, wall time, the envelope's `evidence` block, the report counts, the source
hashes, the largest position and angle errors with their thresholds, and on failure the first body and
configuration that differ with the fixture path. Imported names appear only inside the untrusted field.

### Known answers and negative controls

- KA-290: forward-kinematics parity within 10⁻⁹ m and 10⁻⁹ rad over 10⁴ configurations; the loss report
  lists every dropped field found by a field-coverage diff (tier G2, host). The appendix states no negative
  control; this bead registers the three below.
- Negative control 1 (planted): half-sizes read as full sizes. Masses inferred from geoms are off by a
  factor of 8 for boxes, and the inertia test fails; forward kinematics alone would not notice, which is why
  the mass test exists.
- Negative control 2 (planted): an importer that silently drops `armature`. The field-coverage diff reports
  an attribute that is neither mapped nor listed.
- Negative control 3 (planted): `euler` read with the wrong `eulerseq`. Parity fails on the first robot whose
  model uses Euler angles.
- KA-277: an imported inertia that violates the triangle inequalities is listed and later refused at stage 2.
- Metamorphic: reordering sibling elements changes neither the `DesignId` nor the report's entry set.
- Determinism lanes: twice; debug and release; Linux and macOS.

## Considerations

- Import parity is geometry and mass. Contact parity is not claimed: the soft-contact mapping is lossy,
  labelled parity-only, and always listed.
- The humanoid archetype's import parity is judged against the 38-link source, not against a reduced
  builder that omits welded masses; a reduction must be declared, and an import that drops a body of nonzero
  mass without one is refused.
- Hostile input: the reader allocates under limits, follows no reference outside the import root and
  executes nothing; the MJCF mapper is a fuzz target.
- Licences: fixtures carry a licence manifest and only permissively licensed sources are vendored.
- Open point (DESIGN, to confirm with the Skeleton lead): mapping `armature` on an actuated joint to an override
  of the card's rotor inertia. Until it is confirmed, the importer applies the override and also lists the entry
  in the loss report with severity high, so the choice is never silent; if the lead rejects the mapping, the
  entry becomes a dropped field (severity high) and no override is written.
