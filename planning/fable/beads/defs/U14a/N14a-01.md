## Background

A FrankenRobotics design is a term stored as canonical JSON (schema `frob.design/1`, extension `.fbot`), and
its identity `DesignId` is the BLAKE3 hash of the canonical bytes. For a hash to be an identity, every value
must have exactly one byte representation. Numbers are where that most often fails: `0.42 m`, `420 mm` and
`42.0 cm` are one length; a binary64 parser may read `0.1` and `0.30000000000000004` in ways that differ
between libraries; a client that decodes JSON numbers as doubles merges 2⁵³ and 2⁵³ + 1. This bead builds the
number layer under the design term: the quantity atom, its canonical form, and the parameter record every
design parameter carries.

It implements four of the seven canonical-form rules of the design format (the other three, key order,
written-out defaults and unexpanded constructors, are in BD-054):

- Rule 2. A quantity is a string of an exact decimal and a unit token (`"0.42 m"`), or an object with that
  string and its provenance, uncertainty and source. A bare quantity string means provenance `designed`.
- Rule 3. The canonical unit is the coherent SI unit, and the canonical decimal is the shortest that equals
  the exact rational value. A value with no terminating decimal is written as a ratio (`"1/3 m"`).
- Rule 4. An angle given in degrees or turns is kept as an exact rational of a turn (`"1/8 turn"`); an angle
  given in radians keeps its decimal. Both are exact records of what the author wrote, which is what the exact
  symmetry computation needs (a 45° roller angle must compare equal to 1/8 turn in ℚ, not approximately).
- Rule 5. Integers above 2⁵³, content hashes and rationals travel as strings, so a client that parses numbers
  as binary64 cannot merge two of them.

DESIGN reasons. Exact decimals: a design is authored in decimals and must hash the same on Linux and macOS, so
no value may pass through a float parser on its way to the canonical bytes. Coherent SI: one unit per
dimension removes the `mm`/`m` duplicate. Rejected alternatives: storing binary64 with shortest round-trip
printing (the value an author wrote is then not what is hashed, and rational symmetry tests need exact
angles); keeping the author's unit (two files for one design would hash differently, and every memoized
analysis of the first would miss on the second).

Unit tokens and their parsing are not written here. FACT: FrankenSim's `fs-qty` parses SI unit tokens
(`frankensim/crates/fs-qty/src/parse.rs`); this project reaches it only through the `frob_core::qty` module.

## Scope

In: the `Qty` atom (exact rational magnitude, dimension, canonical unit); parsing and canonical printing of
quantity strings and quantity objects; the angle rule; currency tokens; the wide-integer and rational string
rule; the `Provenance` enum; the `Param` record (unit, bounds, manifold kind, provenance, uncertainty, prior);
dimension checking against a field's declared dimension (`FROB-REF-102`).

Out: object key order, duplicate keys and whole-document canonicalization (BD-054; the raw-byte reader is
`frob-core`'s); the S-expression spelling of atoms such as `0.42m` (BD-057, which reuses this bead's parser
for the magnitude and the unit); lever semantics on manifolds (N14a-06).

## Technical approach

Module layout (DESIGN): `crates/frob-design/src/qty/{atom.rs, parse.rs, print.rs, angle.rs, param.rs}`.

```rust
// DESIGN sketch: intent, not signatures.
// `Ratio` is `frob_lie::exact::Rational` (a reduced pair of arbitrary-precision integers with a positive
// denominator), the host exact-arithmetic kernel of N13-10 in layer 1; `frob-design` adds no rational type.
pub struct Qty { mag: Ratio, dim: Dimension, kind: QtyKind }        // mag is in the coherent SI unit
pub enum QtyKind { Si, AngleTurn, AngleRad, Currency(Iso4217), Dimensionless }
pub enum Provenance { Designed, Datasheet, Measured, Assumed, Default }
pub struct Annotated { value: Qty, provenance: Provenance, uncertainty: Option<Qty>, source: Option<String> }
pub enum Manifold { R, RPlus, S1, S2, Se3, InertiaCone, Finite }
pub struct Param { value: Annotated, bounds: Option<(Qty, Qty)>, manifold: Manifold, prior: Option<Prior> }
```

Parsing a quantity string, as numbered steps:

1. Split at the first space: magnitude text, unit token. A string with no unit token is legal only for a field
   whose declared dimension is dimensionless (a gear ratio `"1.55"`).
2. Magnitude grammar: `[+-]? digits ('.' digits)? ([eE] [+-]? digits)?` or `[+-]? digits '/' digits` with a
   non-zero denominator. Convert to a `Ratio` exactly: a decimal with f fraction digits and exponent e is
   n·10^(e−f). No float is constructed. Not-a-number and infinity are not representable.
3. Resolve the unit token through `frob_core::qty` to a dimension and an exact rational scale to the coherent
   SI unit (`mm` → 1/1000 m). Multiply. An unknown token refuses with `FROB-REF-102`.
4. Angles. `deg` → magnitude/360 turn; `turn` → as written; both become `AngleTurn`. `rad` → `AngleRad`, kept
   as the written decimal. The two angle kinds are never converted into each other in canonical form, because
   π is irrational; they compare unequal as terms even when numerically close.
5. Currency: an upper-case ISO 4217 code (`USD`) is an opaque unit with dimension `currency(code)`.
6. Check the dimension against the field's declared dimension; a mismatch refuses with `FROB-REF-102`, naming
   the field path, the observed dimension and the required one.

Canonical printing:

1. Magnitude in the coherent SI unit as the shortest decimal that equals the rational: no exponent, no leading
   `+`, no trailing fraction zeros, one leading zero before a point, `-0` printed `0`. A rational whose reduced
   denominator has a prime factor other than 2 or 5 is printed `p/q` reduced, with the sign on p.
2. `AngleTurn` is always printed as a reduced ratio of a turn (`"1/8 turn"`, `"-4/9 turn"`, `"1 turn"`,
   `"0 turn"`), also when the decimal terminates. DESIGN: the format's own example writes `1/8 turn`, and the
   symmetry code reads numerator and denominator directly.
3. One space, then the canonical unit token: the token `frob_core::qty` prints for the dimension. A golden
   table of the dimensions the schema uses (length, mass, time, angle, frequency, voltage, current, power,
   energy, temperature, thermal conductance W/K, density, force, torque, pressure, currency) pins the spelling.
4. An `Annotated` value with provenance `designed` and no uncertainty and no source prints as the bare string.
   Otherwise it prints as the object `{"provenance": …, "source": …, "uncertainty": …, "value": …}` with keys in
   code-point order and absent members omitted.

Rule 5. In a design document a JSON number is legal only where the schema type is a small integer (an index, a
count, an axis component) and its magnitude is at most 2⁵³ − 1. Larger integers, content hashes (`b3:` followed
by 64 hexadecimal digits) and non-integer exact numbers outside a quantity are strings. A bare JSON
floating-point number where a quantity is expected refuses with `FROB-REF-102` (a number without a unit).

Refusals issued here (exit code 3, class Domain; the envelope's `refusal` block carries `pointer`, `observed`,
`required`, `unit`):

| Code | Meaning | Trigger here | Ranked repairs |
|---|---|---|---|
| `FROB-REF-102` | Unit or dimension error | Unknown unit token; dimension differs from the field's; a bare number where a quantity is required; a zero denominator; an angle unit on a length field | 1. `set-param` with the same magnitude in a unit of the required dimension, offered only when the magnitude is plausible in it; 2. the list of accepted unit tokens for the field |

Determinism class D0 (exact): parsing and printing are integer arithmetic. Evidence: values carry their
provenance; nothing here emits a claim.

## Acceptance criteria

- [ ] `"420 mm"`, `"42 cm"`, `"0.42 m"`, `"0.420 m"` and `"4.2e-1 m"` all canonicalize to the bytes `"0.42 m"`.
- [ ] `"2.5 mm"` → `"0.0025 m"`; `"1/3 m"` → `"1/3 m"`; `"0.333 m"` is a different value from `"1/3 m"`.
- [ ] `"45 deg"` and `"0.125 turn"` → `"1/8 turn"`; `"-160 deg"` → `"-4/9 turn"`; `"150 deg"` → `"5/12 turn"`;
      `"1.5708 rad"` stays `"1.5708 rad"` and is not equal to `"1/4 turn"`.
- [ ] `"4000 USD"` round-trips; `"4000 usd"` and `"4000 XYZ1"` refuse with `FROB-REF-102`.
- [ ] A prismatic limit written `"12 deg"` and a revolute limit written `"12 mm"` each refuse with
      `FROB-REF-102`, naming the field path and both dimensions.
- [ ] A JSON integer above 2⁵³ − 1 refuses; the same value as a string is accepted where the schema allows it.
- [ ] Canonicalization is idempotent: print(parse(print(parse(s)))) = print(parse(s)) on 10⁶ random quantity
      strings, and the bytes are identical on Linux and macOS.
- [ ] No floating-point type appears in `crates/frob-design/src/qty/` outside a `#[cfg(test)]` oracle.
- [ ] The golden unit-token table test fails if the sibling's printing of any listed dimension changes.

## Test plan

### Unit tests

In `crates/frob-design/src/qty/` (inline) and `crates/frob-design/tests/qty.rs`; run with
`cargo test -p frob-design qty`.

- `parse_equivalent_spellings`: the five spellings of 0.42 m above yield equal `Qty` and equal bytes.
- `shortest_decimal`: 1/8 → `0.125`; 1/3 → `1/3`; 1/40 → `0.025`; 7/6 → `7/6`; 3/1 → `3`; −0 → `0`.
- `angle_turn_ratio`: 45 deg → `1/8 turn`; 360 deg → `1 turn`; 0 deg → `0 turn`; −30 deg → `-1/12 turn`.
- `radian_keeps_decimal`: `"1.5708 rad"` prints unchanged and has kind `AngleRad`.
- `annotated_canonical_form`: `{"value":"0.42 m","provenance":"designed"}` prints as `"0.42 m"`; with
  `"provenance":"measured","uncertainty":"1 mm"` prints the object with keys in code-point order and the
  uncertainty as `"0.001 m"`.
- `dimension_mismatch_refuses`: each of the mismatches in the acceptance list returns `FROB-REF-102` with the
  pointer set to the field path.
- `wide_integer_rule`: 9007199254740993 as a JSON number refuses; `"9007199254740993"` parses exactly.
- `prop_idempotent_print_parse` (property, 10⁶ cases): random rationals with random admissible unit tokens.
- `prop_order_preserving`: for random pairs, the order of two `Qty` of one dimension equals the order of their
  rationals (bounds checks rely on it).

### End-to-end script and logging

No script of its own. The layer is exercised from the user's side by `scripts/e2e/skel_author_compile.sh`
(N14a-27), which feeds one design in three unit spellings and asserts one `DesignId`, and by
`scripts/e2e/skel_view_roundtrip.sh` (N14a-28). Both log, per assertion, the input bytes digest, the canonical
bytes digest and the first differing byte offset on failure, in the shared NDJSON form.

### Known answers and negative controls

- KA-278 (rejection fixture, joint): a prismatic travel in millimetres read as radians must refuse at stage 1
  with `FROB-REF-102`. The unit half of that fixture is tested here; the stage-level half in N14a-08.
- Negative control 1 (planted): a parser that routes the magnitude through binary64. It must be caught by
  `"0.1 m" + "0.2 m"`-style fixtures: `"0.30000000000000004 m"` and `"0.3 m"` are different values and the
  mutant merges them.
- Negative control 2 (planted): degrees converted through radians in binary64. `"45 deg"` then fails to equal
  `"1/8 turn"` exactly.
- Negative control 3 (planted): canonical printing that keeps the author's unit. The equivalent-spellings test
  fails.
- Metamorphic: scaling a magnitude by 1000 and moving the unit from `m` to `mm` leaves the bytes unchanged.
- Determinism lanes: twice on one machine; debug and release; Linux and macOS; all bit-identical (class D0).

## Considerations

- The spelling of derived SI unit tokens is the sibling's. If `fs-qty` changes it, the golden table fails and
  the change is a canonicalization-revision bump handled by the migration bead (N14a-18), never a silent
  change of every `DesignId`.
- If the toolchain admission forces the `frob-units` escape hatch, only the import path of the unit table
  changes; the grammar and the canonical form stay.
- DESIGN decision recorded here because the format text leaves it open: a turn angle is always a ratio. If a
  reviewer prefers the shortest-decimal rule for turns too, it is one printing branch and a revision bump.
- One exact rational type. The drafted fallback was a private `frob_design::exact::Ratio` in case no shared
  type existed. One does: `frob_lie::exact::{Int, Rational}` (N13-10), with the same invariant and with exact
  parsing of the design language's decimals and ratios, in a crate `frob-design` already depends on for joint
  classes. This bead uses it, so that a quantity, an inertia and a group element compare without conversion.
  Its 4,096-bit size budget and the refusal `FROB-REF-215` are the kernel's; the cap stated below is that budget.
- Exponent notation is accepted on input and never emitted. A quantity such as `1e400 m` is legal and exact;
  the size of numerator and denominator is capped at 4,096 bits (TARGET) and a larger one refuses.
- Security: quantity strings come from imported files; the parser allocates at most proportional to the input
  length and is a fuzz target of the format reader.
