## Background

Before anything is simulated a design is checked. ADR-SKEL-08 (DESIGN): preflight is `design check`. There
is one verb, with eight stages in a fixed order, each able to refuse the next. Stages 1 to 6 need only the
design; stages 7 and 8 also need a task and a scene. Reason: check before you simulate, and a second
pre-simulation gate with a second name would be two sources of truth.

Stage 1 is called Form, and it is the compile itself: parse either view; canonicalize; expand constructors
and modules; unit and dimension algebra; fills; levers and locks. Inside the compiler the corresponding step
is **validate**, which comes after elaborate: it checks ports, units, bounds and fills on the expanded tree
and returns the same tree, or a refusal (memo key: the subterm hash). The standing rule of the subsystem is
refusals instead of repairs in silence: an invalid design is refused with a stable code, a message, and
ranked repairs expressed as typed edits, which become the `next_actions` of the answer.

The single checks are written in the beads that own each block (N14a-01 to N14a-05, BD-055, the module
format). What no single block owns is the stage: the order in which checks run, the rule for stopping, the
report, the time budget, and the proof that the stage refuses what it must and nothing else. That is this
bead. It also supplies stage 1's share of the seeded-defect corpus that the preflight's gate is measured on.

## Scope

In: the validate step of `frob-model`; the function that runs stage 1 end to end and returns a stage report;
the fixed check order; first-refusal and `--all` modes; the `undecided` outcome; ranked repairs; the stage-1
seeded defects and the stage-1 first rejection fixtures; the false-positive run on valid designs.

Out: each individual check (its block's bead); the verb, the runner for stages 1 to 8, per-stage timing
across stages and the gate records (BD-110); stages 2 to 8 (the analysis beads); design lints (BD-064).

## Technical approach

Layout (DESIGN): `crates/frob-model/src/{validate.rs, stage1.rs}`; fixtures under
`crates/frob-model/tests/fixtures/stage1_defects/` with `manifest.toml` (file, expected stage, expected code,
expected pointer).

What stage 1 refuses, with the owner of each check:

| Code | Refused | Check written in |
|---|---|---|
| `FROB-REF-103` | Unknown, misspelt or duplicate field | BD-054 (document), N14a-03, N14a-04, N14a-05, BD-055 (blocks) |
| `FROB-REF-102` | Unit or dimension error | N14a-01 |
| `FROB-REF-101` | Port type mismatch | N14a-02 (stated joins), N14a-07 (`attach` to a missing port) |
| `FROB-REF-105` | Missing fill, or a solid written as a shell | BD-055 |
| `FROB-REF-111` | A lever out of bounds, or a locked field | BD-055, N14a-06 |
| `FROB-REF-114` | Module digest or port-signature mismatch | The module format bead |
| `FROB-REF-121` | Missing or incompatible contact law | N14a-05 |
| `FROB-REF-126` | A sensor without frame, rate or clock | BD-055 |
| `FROB-REF-130`, `FROB-REF-134` | A card that fails its own checks (not passive; no current convention) | The card catalog bead |
| `FROB-REF-125` | Unsupported schema version | BD-054 |

Run order (fixed, so that the first refusal of a design is the same on every machine):

1. Read: raw-byte validation, parse from either view, schema typing, canonical form, `DesignId`.
   Refusals 103, 125, 102, and the required-physics-field refusals 105, 121, 126 and missing limits.
2. Elaborate (N14a-07): refusals 101 (attach), 114 (module), 111 (bind), 103 (identifier collision).
3. Validate on the expanded tree, in this order:
   a. ports: every stated join is kind-correct (101);
   b. units: quantities bound through module parameters or `scale` still have the dimension their field
      requires (102);
   c. fills on instances: shell thickness against the instance's Region after any `scale` (105);
   d. end effectors on instances: the contact rules of N14a-05 after `replace` and `use` (121);
   e. levers and locks: every lever path resolves in the expanded tree, its value is inside its domain, and
      no lever sits under a lock (111);
   f. cards: every card an instance names passes its own admission checks (130, 134); a joint override that
      makes a card fail is reported at the joint;
   g. turn state: an element with a lifted law (a linear torsion spring, a multi-turn travel limit, a lead
      screw) on a revolute joint whose state omits the turn count refuses with that rule's code.
4. Report.

Stopping. By default the stage stops at the first refusal. With `--all` it collects every finding of the
three steps that can still run: a failure of step 1 ends the stage, because nothing after it has a term to
read.

The report (DESIGN; schema fragment `frob.design.check.stage/1`):

```
{ "stage": 1, "name": "form", "verdict": "pass" | "refuse" | "undecided",
  "findings": [ { "code": "FROB-REF-105", "message": "…", "pointer": "/root/fill",
                  "observed": "…", "required": "…", "unit": "m",
                  "repairs": [ { "edit": "set-fill", "args": {…}, "predicted": {…} } ] } ],
  "timing_ms": 41, "bound": { "design": "b3:…" },
  "evidence": { "class": "Tested", "tier": "static", "determinism": "exact" } }
```

Every stage returns an evidence class and an identity; at stage 1 the identity is the `DesignId` (a model
does not exist until the compile finishes). Repairs are ranked by the owning block's rule and are typed edits
an agent can apply as written; a repair is never applied by the stage.

Time budget. TARGET: 100 ms at the 95th percentile for any of the eighteen archetypes on the reference host
with an empty memo graph. The figure is a budget, not a prediction. A stage that exhausts its budget returns
`undecided` with what it had established; `undecided` is never a pass and never a refusal.

Determinism class D0: every check is exact, and the order is fixed.

## Acceptance criteria

- [ ] `frob_model::stage1::run` returns `pass` for the worked designs `quad-a` and `quad-tray` and for every
      archetype available at the time, with zero findings.
- [ ] The stage-1 seeded-defect set holds at least two defects per code in the table (at least 22 files), and
      every one is refused by stage 1 with the code and pointer its manifest names. This is stage 1's share of
      GATE-SKEL-04 (TARGET for the whole gate: of 100 seeded defects for stages 1 to 6, at least two per
      refusal code, all 100 refused and at least 95 by the stage and code that own them; zero refusals on the
      eighteen archetypes and on 10³ random valid designs).
- [ ] Zero refusals on 10³ random valid designs from the generator of the open modular class.
- [ ] The three stage-1 first rejection fixtures are refused: joint (a prismatic travel in millimetres read
      as radians, 102), foot (a torsion radius above the contact radius, 121), sensor (no timestamp source or
      an unknown frame, 126).
- [ ] The first refusal of a design with three planted defects is the same finding on Linux and macOS, in
      debug and release, with 1 and 36 threads; `--all` returns all three in the fixed order.
- [ ] Every finding carries at least one repair that is a well-formed typed edit, and applying the first
      repair of each seeded defect yields a design that passes the check that refused it.
- [ ] A budget of 0 ms returns `undecided`, with exit status that is neither pass nor refusal.
- [ ] The measured median and 95th percentile of stage 1 on each available archetype are recorded.

## Test plan

### Unit tests

`cargo test -p frob-model stage1 validate`.

- `archetypes_pass_stage1`: zero findings on the worked designs and available archetypes.
- `seeded_defects_refused_by_owner`: iterates the manifest; asserts stage, code and pointer per file.
- `first_refusal_is_deterministic`: the three-defect design; the first finding is the one earliest in the
  run order (a misspelt field before a missing contact law before a lever out of bounds).
- `all_mode_collects_in_order`.
- `repairs_are_applicable`: for each seeded defect apply repair 1 through the edit engine and re-run.
- `undecided_on_exhausted_budget`.
- `scale_changes_shell_verdict`: a shell of 3 mm on a link that `scale(1/2, …)` shrinks to d_min = 5 mm is
  refused on the instance (105) although the unscaled subterm passes.
- `override_fails_card_at_joint`: an override that sets a forward efficiency of 1.2 is reported with the
  joint's pointer and `FROB-REF-130`.
- `prop_valid_designs_pass` (10³ `synthetic` designs).

### End-to-end script and logging

Exercised by `scripts/e2e/skel_author_compile.sh` (N14a-27), which runs
`frob design check <file> --stages 1 --json` over the seeded-defect directory and the valid designs. For each
file it asserts the exit code (3 for a refusal, 0 for a pass), the code, the stage and the first repair, and
logs one NDJSON line with the command line, exit code, wall time, the envelope's `evidence` block, the
finding (`code`, `pointer`, `observed`, `required`, `unit`), the stage's `timing_ms` against its 100 ms
budget, and on failure the expected and actual finding with the fixture path. The `summary` line counts
refused-by-owner, refused-by-other and not-refused, and names `GATE-SKEL-04`.

### Known answers and negative controls

- KA-291: 100 seeded defects for stages 1 to 6, at least two per refusal code: all refused, at least 95 by
  the stage and code that own them; zero refusals on the eighteen archetypes and on 10³ random valid designs.
  The seeded defects are the controls.
- KA-278, KA-283, KA-284: the first rejection fixtures of the joint, foot and sensor families, refused at
  stage 1 with 102, 121 and 126. A check that lets its fixture through is broken, whatever else it reports.
- Negative control 1 (planted): a validate step that skips step 3c. The scaled-shell fixture is admitted and
  the test fails.
- Negative control 2 (planted): a run order that depends on map iteration. The determinism test fails.
- Negative control 3 (planted): a stage that reports `pass` when its budget is exhausted. The `undecided`
  test fails.
- Metamorphic: reordering members of the input, or supplying the S-expression view, changes no finding.

## Considerations

- Ownership of a refusal by a stage is part of the gate ("by the stage and code that own them"). The
  empty-range refusal (107), the class-and-basis disagreement (101 at stage 3), inconsistent inertia (104)
  and mass support (106) belong to later stages and must not be raised here even where stage 1 could see
  them, except for a missing `limits` member, which is a reading failure.
- The repair for a missing physics field proposes a value and never applies it.
- A defect corpus written by the implementer of the checks tests what the implementer thought of. Half of the
  stage-1 defects are therefore written from the field reference alone, before the checks exist, and the
  corpus is frozen with a manifest hash.
- Stage 1 is the only stage that runs on every edit; its cost with a warm memo graph is the cost of the
  edited subterm.
