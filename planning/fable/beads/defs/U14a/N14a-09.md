## Background

`frob-model` compiles a design into an immutable `RobotModel` through five functors (construction C-12).
BD-061 builds the kinematic one and BD-062 the geometric one. This bead builds the third: the binding
functor, which maps the expanded tree to the channels through which a robot is driven and observed. The
pipeline's own words: actuator and sensor binding, including the joint rows. Product: actuator and sensor
channels; row descriptors. Memo key: the joint hash with the card versions.

Why it is a functor of its own. A joint in a design names an actuator card, perhaps with overrides, and a
transmission; a sensor names a card, a parent, a rate and a clock. None of that is geometry and none of it
is kinematics, but the simulator needs it as flat, indexed tables: which channel drives which coordinate
through which signed ratio, which card instance governs it, which bus and sink it sits on, which rows the
solve must carry for its friction and backlash, and at which exact rate each sensor fires. Keeping this
apart from kinematics is what lets an edit such as `regear` or `swap-actuator` recompute the binding and
leave frames untouched, and what lets `retime` (a sensor rate change) touch only the clock plan.

Two rules from other chapters are enforced at this point because this is where the facts meet. The actuator
card decides the friction model, and its stiction and backlash become rows of the same solve as ground
contact: the functor emits the row descriptors, it does not solve them. And a revolute coordinate is stored
as a unit complex number plus an integer turn count: a law that reads the angle itself (a linear torsion
spring, a multi-turn travel limit, a lead screw) is `lifted` and needs the turn count in the state, while a
`periodic` law reads only the unit complex number. A joint whose state omits the turn count may not carry a
lifted law.

## Scope

In: actuator channels; instance card hashes; transmission binding and coupling maps; bus and sink
membership tables; sensor channels and their exact rates; contact bindings of end effectors; joint row
descriptors collected per joint; the turn-state declaration per revolute coordinate; the binding section of
`RobotModel` and its digest.

Out: card contents and card checks (BD-069); the row laws and their kernels (BD-084); transmissions' loss
laws (BD-074); bus physics (BD-075); sensor models and the clock scheduler (the sensing beads); the
observation-preserving symmetry group, which reads this section (N14a-11); memoization (BD-063).

## Technical approach

Layout (DESIGN): `crates/frob-model/src/bind/{actuators.rs, sensors.rs, rows.rs, contact.rs, turn.rs}`.

```rust
// DESIGN sketch: intent, not signatures.
pub struct ActuatorChannel { id: InstanceId, joint: JointIdx, coord: u8,
                             card: CardInstanceHash,           // card content hash with canonical overrides
                             transmission: TransmissionBinding,// kind, signed ratio, loss law ref, backlash, compliance
                             sign: i8,                         // coordinate sign from the parity rule times gear direction
                             bus: BusIdx, sink: SinkIdx, control_rate: Ratio, latency: Qty }
pub struct SensorChannel { id: InstanceId, card: CardHash, parent: BodyIdx, body_from_sensor: ExactIsometry,
                           rate: Ratio /* hertz */, clock: ClockId, fov: Option<Fov>, latency: Option<Qty> }
pub struct JointRows { joint: JointIdx, limits: Vec<LimitRow>, stiction: Option<StictionRow>,
                       backlash: Option<BacklashRow>, damping: Option<Qty> }
pub struct ContactBinding { end_effector: BodyIdx, law: LawSelector, interface: CardHash, params: LawParams }
pub struct TurnState { coord: CoordIdx, laws: Vec<(LawRef, Periodicity)>, needs_turn_count: bool }
pub struct Binding { actuators: Vec<ActuatorChannel>, coupling: Vec<CouplingMap>, sensors: Vec<SensorChannel>,
                     rows: Vec<JointRows>, contacts: Vec<ContactBinding>, turn: Vec<TurnState>, digest: Blake3 }
```

Steps:

1. Read the expanded tree through the tracked view. Channels are numbered in the tree's instance order, so
   channel indices are deterministic and stable under edits that do not touch the tree's shape.
2. Actuators. For each joint coordinate that names an actuator, resolve the card to its content hash and
   form the instance hash from the card hash and the canonical override object. Bind the transmission:
   kind and parameters; the ratio is signed. The channel's `sign` is the product of the coordinate sign the
   reflection parity rule assigns to the instance (+1 when a mirrored rotation axis is its axial image
   det(P)·P·a, which is what `mirror` emits; −1 when a design writes the mirrored axis as +P·a) and the gear
   direction, so that the same command means the mirrored motion on a mirrored limb. A joint with no
   actuator is passive and gets no channel.
3. Couplings. A `coupling` transmission over several joints yields a `CouplingMap`: the matrix C with
   q = C·θ, θ the motor coordinates, and its transpose for torques. It is stored exactly.
4. Bus and sink. Assign each channel to its bus by the expanded `members`, and to the bus's sink. Every
   actuator must be on exactly one bus.
5. Sensors. For each sensor instance record the card hash, the parent body, the exact mount frame, the rate
   as an exact rational in hertz, the clock identifier, field of view and latency. The set of periods is
   what the clock contract turns into integer periods on a base unit of 1/L seconds, L the least common
   multiple of the periods' denominators.
6. Contact bindings. For each end effector record the law selector, the interface card hash and the law
   parameters (N14a-05).
7. Row descriptors. Per joint, call the actuation crate's function on the card instance and the joint-side
   overrides (`damping`, `friction`, `backlash`) and collect: one limit row per bounded coordinate (hard
   stops), a stiction row when the card has a friction model (Coulomb level, breakaway level, Stribeck
   velocity and shape, load coefficient, regularization speed), backlash rows when a gap is declared (gap β,
   ratio N), and damping. A backlash row on a card level with no rotor degree of freedom refuses with
   `FROB-REF-241`; the repair is to raise the card level.
8. Turn state. For each revolute coordinate collect the laws that read it and their declared periodicity:
   hard stops whose interval is narrower than one turn are `periodic`; an interval wider than one turn, a
   linear torsion spring, a lead screw, cable wrap and tether winding are `lifted`. Set `needs_turn_count`
   if any is lifted. The model's state layout carries the turn count for exactly those coordinates plus any
   the task requests; a lifted law on a coordinate whose state would omit it is the stage-1 refusal of
   N14a-08.
9. Store the section with its digest, memo key (joint hash with the card versions) and read set. The digest
   enters `ModelId`: a sensor's rate and clock rule are part of the model's identity.

Refusals issued here (exit code 3): `FROB-REF-241` (no rotor state for backlash rows); an actuator on no bus
or on two (`FROB-REF-108`, the copied or missing power port); a card that does not resolve (the card
catalog's refusal). Repairs: raise the card level; `set-bus` membership; the nearest card identifiers.

Determinism class D0. Evidence: the section is data; card fields keep their provenance, and a channel whose
card has a required field of provenance `assumed` is marked so that `--strict-data` can refuse later.

## Acceptance criteria

- [ ] The worked design `quad-a` binds 12 actuator channels (8 of card `qdd-m` driven directly and 4 knees of
      `qdd-m` through a belt of ratio 1.55), one bus `main` with 12 members and one sink, 18 sensor instances
      (1 imu at 500 Hz, 12 encoders at 1,000 Hz, 4 foot-contact sensors at 500 Hz, 1 lidar at 10 Hz), and 4
      contact bindings (`foot-patch`, `rubber-60a/default`, torsion radius 8 mm).
- [ ] The base unit implied by those rates is 1/1,000 s, with integer periods 2, 1, 2 and 100.
- [ ] Channel signs follow the parity rule: the four hip-abduction channels of `quad-a` (axes emitted as
      axial images) all have sign +1, and a fixture that writes one mirrored hip axis as +P·a has sign −1 on
      that channel.
- [ ] An override on one knee's card gives that channel a different instance hash and no other.
- [ ] A new revision of card `qdd-m` changes the memo key of every channel that names it and of no other
      product.
- [ ] A reversed gear (ratio −1.55 on one knee) changes that channel's sign and the section digest.
- [ ] A joint with limits wider than one turn, or a declared torsion spring, has `needs_turn_count = true`;
      a wheel joint with `unbounded` limits and only periodic laws has `false`.
- [ ] Backlash on a card without rotor state refuses with `FROB-REF-241`.
- [ ] `retime` of the encoder from 1,000 Hz to 2,000 Hz changes the sensor rows and the clock inputs and
      leaves actuator channels, rows and contact bindings bit-identical.

### Known answers and negative controls

- Known answer from the conventions (hand-checkable): physics at 400 Hz, an IMU at 100 Hz and a policy at
  30 Hz give L = 1,200 and integer periods 3, 12 and 40; nothing is rounded to a multiple of the physics step.
- Known answer for turn state: a joint with a linear torsion spring of 0.5 N·m/rad held at θ = 0 and at
  θ = 2π has identical link poses; at 2π the spring stores ½ × 0.5 × (2π)² = π² J = 9.8696 J. The functor
  must mark that coordinate `needs_turn_count`.
- Negative control 1 (planted): a channel key that omits the card version. A card bump then serves the old
  channel; the key test fails.
- Negative control 2 (planted): channel sign taken from parity alone. The reversed-gear fixture keeps its
  sign and the test fails.
- Negative control 3 (planted): rates stored as binary64. 29.97 Hz then has no exact period and the
  base-unit test on `2997/100` fails.
- Determinism lanes: twice; 1 and 36 threads; debug and release; Linux and macOS: bit-identical (class D0).

## Considerations

- Channel order is an interface: policies, telemetry and the symmetry representations index by it. It follows
  tree order, and an edit that changes the tree's shape changes indices and is reported as doing so.
- The functor gathers row descriptors and never evaluates a friction law; whether a tier carries a row
  option is the tier's admission question.
- A sensor's `latency` and `fov` default to the card's values and are written out in the canonical design, so
  the binding never consults a default of its own.
- Coupled ankle and waist transmissions of the humanoid archetype are the first real use of `CouplingMap`.
