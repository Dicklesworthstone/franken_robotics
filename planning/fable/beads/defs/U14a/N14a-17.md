## Background

Edits are the morphisms of the design category: a design is never modified in place, and every change is a
typed edit that takes one immutable design to another. Each edit kind has preconditions, an inverse where one
exists, a declared effect on both symmetry groups (the mechanical group Γ_mech and its observation-preserving
subgroup Γ_obs), and a scope of invalidation. A design's history is a path of edits in a content-addressed
lineage graph.

The edit engine itself (preconditions, inverses, the verb `design.edit`) is BD-058. Two columns of the edit
table are predictions about other machinery: the symmetry effect is computed by the symmetry functor
(N14a-11), and the invalidation scope is computed from influence records by the memo graph (BD-063). The
format's own wording is that the invalidation scope is what the compile pipeline computes and the table
predicts. A prediction that is never compared with the computation drifts: an edit declared "preserved" that
breaks a symmetry lets a learner keep tying weights under a group that is gone, and an edit declared to
invalidate less than it does serves stale results.

This bead keeps the full table as data and tests every row against the computed truth. The rule on
disagreement is fixed in advance: a disagreement is a finding against the table, never against the recorded
read sets or the computed groups.

## Scope

In: the catalogue as the one printed table of the 22 rows of the specification's edit table, plus row 23
(`extract-module`, DESIGN, whose kind and row N41p2-01 adds), and the vocabularies of its two prediction columns;
ownership of the catalogue file once the engine has created it: the `fixture` of each row (one fixture edit per
row on a fixed base design) and every correction of a row; the conformance test (declared symmetry effect
against computed; predicted scope against computed invalidation set); the report of rows whose prediction is
too wide; the inverse law on the catalogue's fixtures through to bit-identical products.

Out: implementing the edits, their preconditions and inverses, the verb `design.edit`, the creation of
`registries/edits.toml` with its loader and the entry of `row`, `kinds`, `example`, `symmetry_effect` and
`scope` for every row as transcribed from the table below, the resolution of a row's `symmetry_effect` to the
declared effect of one edit, and the inverse law on identifiers over generated edits (BD-058, a dependency:
the engine is built first and reads the file; this bead then completes, tests and corrects it); patches
(BD-059); module substitution's classification (BD-077); migration's certificate (N14a-18); the invalidation
machinery (BD-063); lineage queries (BD-113).

## Technical approach

File (DESIGN; the schema is the same in BD-058, which creates the file): `registries/edits.toml`, one
`[[edit]]` per row with `row` (1 to 23), `kinds` (the operation names the row groups: one for most rows,
several for rows 4, 7, 8, 14, 16, 17 and 19), `example`, `symmetry_effect`, `scope`, `fixture`. The engine's
own registry of edit kinds must equal the union of the `kinds` values here (a missing or extra kind fails the
test). An earlier draft named the field `kind`; a row that groups several kinds cannot hold them in one name,
and the set comparison needs all 33 (the table's 32 and `extract-module`).

The specification's twenty-two rows hold 32 edit kinds (rows 4, 7, 8, 14, 16, 17 and 19 group several). Row 23
is not in the specification's table: the format registry and the worked module require extraction of a module by
a typed edit, and its effect differs from every listed row (DESIGN, carried by N41p2-01, which enters the row, its
kind and its fixture together). 23 rows, 33 kinds at M1.

Row 24 joins at M3 with N31b-41, which adds the kind to the engine and the row to the file in one change, as every
later kind does: `resolve-sized` (input `--loads statics | measured:<batch>`); example: the lower-leg links'
`{shell: sized}` resolved to concrete walls under `--loads statics`; symmetry effect `preserved` (walls are
resolved per symmetry class); scope `body-inertia` and `whole-robot-sums` (the resolved version is the authored
one with its sized fills set to concrete walls by `set-fill`); no inverse (the authored version stays the parent);
fixture: the two-pass fixture of N31b-41's unit tests (walls 2.0 mm and 1.5 mm). In the same change row 9's
`set-fill` also accepts the value `{shell: sized}`. The tests below are generated from the file, so row 24 is
tested by them as it lands; the catalogue then holds 24 rows and 34 kinds.

Machine-readable form of the two prediction columns (DESIGN):

- `symmetry_effect` ∈ {`none`, `preserved`, `preserved-under-constructor`, `reported`, `grows`,
  `mech-preserved-obs-recomputed`, `both-recomputed`}. Meaning: `none` and `preserved` assert both groups are
  unchanged; `preserved-under-constructor` asserts unchanged when the edit's target lies under a `mirror` or
  `radial` and applies to all instances, and `reported` otherwise; `grows` asserts the new group contains the
  old one; `reported` and the two recomputed values assert nothing about the outcome and require the edit's
  result to carry the before and after groups. These seven are the values of a row. The effect the engine
  declares for one edit is one of four (`none`, `preserved`, `grows`, `reported`, the last with a qualifier
  `obs` or `both` for the two recomputed values), resolved from the row and the edit's target by the mapping
  BD-058 states; the test below checks the resolved value of each fixture edit as well as the row.
- `scope` is a set of product classes: `subterm`, `kinematics-below`, `body-geometry`, `body-inertia`,
  `whole-robot-sums`, `actuator-binding`, `sensor-binding`, `contact-binding`, `clock-plan`,
  `symmetry`, `electrical-thermal`, `analyses:<name>`, `rollouts`, `stage:<n>`, `global`, `none`.

The conformance test, as numbered steps:

1. Base design: the worked quadruped (`quad-a`), and for rows that need them a variant with limbs as modules,
   one with a closure, and one with box feet of 0.10 × 0.06 × 0.02 m (for `pad`, which a sphere foot does not
   admit).
2. For each row apply its fixture edit through the edit engine, twice where the row distinguishes cases
   (under a constructor to all instances; to one instance).
3. Symmetry. Compute both groups before and after with the symmetry functor. Assert the declared effect:
   unchanged where the row says `none` or `preserved`; changed and reported where the one-instance case is
   declared to break; for `grows`, containment of the old group; for the reporting kinds, that the edit's
   result carries both groups and that they equal the computed ones.
4. Invalidation. Take the computed invalidation set of the edit from the memo graph and map each invalidated
   product to its class. Assert predicted ⊇ computed: every computed class is in the row's `scope`. A
   computed class outside the prediction fails the row (the table promised less than happened).
5. Width. Report, without failing, the predicted classes that the computation never invalidated on the
   fixtures (the table promised more than happened); these are candidates for narrowing the row.
6. Inverse. Where the engine declares an inverse, apply the edit and its inverse and assert the original
   `DesignId` and bit-identical products.

## Acceptance criteria

- [ ] `registries/edits.toml` holds the 23 rows above, and the set of its edit kinds (33) equals the edit
      engine's registry; with N31b-41's row 24 (M3) the same tests pass on 24 rows and 34 kinds, with row 24's
      fixture leaving both groups unchanged and its computed classes within {`body-inertia`,
      `whole-robot-sums`}.
- [ ] Splitting both mirrors of `quad-a` without changing a value compiles to bit-identical kinematic and inertial
      sections (`split_alone_compiled_identical`; BD-058 asserts only the equal elaborated tree, since the
      functors are later beads).
- [ ] `cargo test -p frob-design --test edit_catalogue` passes: for every row the declared symmetry effect
      matches the computed groups, and the predicted scope contains the computed invalidation classes.
- [ ] The rows that distinguish "under a constructor" from "one instance" (in the table: 1, 3, 6, 9, 10, 11
      and 12) are all seven tested in both cases: `swap-actuator` at all knees preserves C₂ × C₂ and at one
      knee reports a smaller group.
- [ ] Row 12's fixture is legal on its base: `quad-a`'s feet are spheres, on which `pad` refuses
      (`FROB-REF-121`, N14a-05), so the fixture is `foot-patch` → `skid` on `quad-a`, and the table's own
      example (`foot-patch` → `pad`) runs on the box-foot variant of the base.
- [ ] `rename` invalidates nothing and leaves `ModelId` unchanged; `set-budget` invalidates stage 6 findings
      only; `assert-symmetry` invalidates the stage 5 comparison only.
- [ ] `move-sensor` of the lidar leaves Γ_mech unchanged and reports Γ_obs before and after.
- [ ] The width report is written to the test log with one line per row.
- [ ] A planted wrong row (below) fails the test.

## Test plan

### Unit tests

`crates/frob-design/tests/edit_catalogue.rs`; `cargo test -p frob-design --test edit_catalogue`.

- `catalogue_matches_engine_registry`: kind sets equal.
- `row_<n>_symmetry` and `row_<n>_scope` for every row of the file (n = 1 … 23 at M1, 24 from N31b-41's
  change), generated from the file. Examples with expected
  values: row 1 (`set-param`, thigh 0.21 → 0.24 m on all legs): groups unchanged, computed classes within
  {subterm, body-geometry, body-inertia, whole-robot-sums, kinematics-below, analyses}; row 15 (`retime`,
  encoder 1,000 → 2,000 Hz): groups unchanged, computed classes = {sensor-binding, clock-plan}; row 21
  (`rename`): computed set empty; row 23 (`extract-module` of `quad-a`'s leg): groups unchanged, computed set
  empty, `ModelId` unchanged.
- `split_alone_compiled_identical`: split both mirrors of `quad-a` by an instance-scoped edit that writes the
  value already there; compile parent and child; the kinematic section (every `parent_from_joint`, screw axis and
  pitch, limits, home) and the inertial section (per-body mass, centre of mass, pseudo-inertia, and the roll-up)
  are bit-identical, body paired with body by placement; only identifiers, source sets and the parity record may
  differ. Planted control: a split that writes a mirrored axis as P·a (polar) fails on the hip-abduction axes.
- `one_instance_breaks_symmetry`: rows 1, 3, 6, 9, 10, 11 and 12 applied to one leg (row 12: one foot) only
  report a group of order 2 or 1 where the base has order 4 (a change to the front-left leg alone is moved by
  all three non-identity elements, so order 1 is expected for each of these fixtures).
- `row_12_fixture_is_legal`: `foot-patch` → `pad` on a sphere foot of `quad-a` is refused by the engine with
  `FROB-REF-121` before any group is computed; the row's fixtures (`skid` on `quad-a`, `pad` on the box-foot
  variant) are accepted.
- `inverse_round_trip`: for every kind with a declared inverse.
- `width_report_emitted`.

### End-to-end script and logging

Exercised by `scripts/e2e/skel_patch.sh` (N14a-29, step 9), which applies the `fixture` edit of each row
through `frob design edit … --key <k> --json` (a mutate: one seed-derived key per call, distinct per row) and
asserts that the answer's declared symmetry effect, computed groups and computed invalidation set agree with
this catalogue. Each step logs the edit kind, the row number, the groups before and after, the invalidated
product classes, the predicted classes, and on failure the first computed class outside the prediction.

### Known answers and negative controls

- KA-286 (first rejection fixture of the passive-part family): swapping a payload that leaves the assembly
  inertia unchanged must be caught by INV-SKEL-06; here row 16's fixture includes a payload swap whose
  computed invalidation set must contain the whole-robot sums even when the numbers happen not to change the
  centre of mass.
- Counterexample, forward sensor: a symmetric quadruped has Γ_mech = C₂ × C₂; one forward lidar gives
  Γ_obs = C₂. Row 14's fixture must report exactly that pair.
- Negative control 1 (planted): row 21 (`rename`) changed to scope `global`; the width report flags it, and
  a planted row 9 with scope `none` fails `row_9_scope` (computed classes are not empty).
- Negative control 2 (planted): row 3 declared `preserved` unconditionally; the one-knee case fails.
- Determinism: the computed sets are class D0; the test gives identical results twice, in debug and release.

## Considerations

- The table lists scopes in prose; the class vocabulary above is this bead's proposal for making them
  testable, and an entry such as "envelope analyses" maps to the analysis classes that exist at the time.
  Rows whose scope names analyses not yet built are tested for the classes that exist and re-tested as the
  others land.
- "Global" rows are trivially supersets; their value is in the width report.
- A future edit kind enters the engine only with a row here; the registry-equality test enforces it.
