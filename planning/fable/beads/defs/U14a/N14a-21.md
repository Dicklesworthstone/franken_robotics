## Background

Every capability of FrankenRobotics reaches an agent as a verb: one registry entry from which the command
line, the daemon protocol, the MCP tool definitions, the schemas and the documentation are generated, so that
the surfaces cannot drift. A capability counts as implemented only when it is reachable through `frob --json`
with a documented schema and exit code. The design cluster has ten verbs; this bead builds the two that open
and read a design and that no other bead owns: `design.new` (kind `mutate`) and `design.show` (kind `read`),
both first available at M1. Their registry description: create from a template or a mission cell; show.

They are the first thing an agent touches, and the place where the compile pipeline of Skeleton becomes
visible: `design.show` is how the canonical term, the expanded instances, the frames, the mass roll-up, the
channels, the budgets and the shape summary of a model are read, each as a section with the claim product
attached. No naked numbers reach an agent: every answer is one envelope carrying its evidence block (the
class of evidence, the tier, the determinism class, the model identity) and the immutable identifiers every
mutable name was resolved to.

DESIGN choices. `design.new` stores any document that has a canonical form, also one that the validate step
would refuse, and returns the stage-1 findings with it. Reason: a design with an over-thick shell must be
storable so that it can be repaired by a typed edit with a lineage; refusing to store it would push agents
to fix files by hand outside the edit history. A document with no canonical form (an unknown field, a missing
physics field, a unit error) is refused and nothing is stored. `design.show` never computes anything
expensive: it reads compile products, compiling on a miss.

## Scope

In: both verbs' registry entries, schemas, executors, exit codes and refusals; the three sources of
`design.new`; the sections of `design.show`; name resolution to immutable identifiers.

Out: templates and `design.templates` (BD-109); mission cells (the mission beads); `design.view` (BD-057);
`design.edit` and `design.patch` (BD-058, BD-059); `design.check` (BD-110); `design.import` and
`design.export` (the import and export beads); `design.diff` and `design.blame` (BD-113).

## Technical approach

Registry entries (DESIGN, in `registries/verbs.toml`):

```toml
[[verb]]
name = "design.new"
cluster = "design"
kind = "mutate"
tier = "S"
capabilities = ["design:write"]
input_schema = "frob.design.new.in/1"
output_schema = "frob.design.new.out/1"
refusals = ["FROB-REF-102", "FROB-REF-103", "FROB-REF-105", "FROB-REF-111", "FROB-REF-121", "FROB-REF-125", "FROB-REF-126", "FROB-REF-803", "FROB-REF-805"]
idempotent = true
first_milestone = "M1"
examples = ["frob design new quad-a --template quad-mammal --key k1 --json"]

[[verb]]
name = "design.show"
cluster = "design"
kind = "read"
tier = "S"
capabilities = ["design:read"]
input_schema = "frob.design.show.in/1"
output_schema = "frob.design.show.out/1"
refusals = ["FROB-REF-102", "FROB-REF-103", "FROB-REF-125"]
idempotent = true
cost_model = "static: one compile on a memo miss"
first_milestone = "M1"
examples = ["frob design show quad-a --section mass --json"]
```

`design.new`. CLI: `frob design new <name> (--file <path|-> | --template <archetype> [--preset <ref>]
[--set id=value]… | --from-cell <cell-ref>) --key <idempotency-key> --json`. Steps:

1. Bind the idempotency key with the canonical request digest in one transaction (same key and content:
   return the stored answer with `idempotent_replay: true`; same key, other content: `FROB-REF-803`, exit 7;
   no key: `FROB-REF-805`).
2. Obtain the document: from a file or standard input in either view (JSON or S-expression, detected by the
   first non-space byte); from a template by substituting `--set` values for its parameters (a value outside
   a parameter's bounds refuses with `FROB-REF-111`); or from a mission cell, taking the centre of the named
   inner cell and writing `meta.source` as the query and cell identifiers.
3. Canonicalize. No canonical form: refuse with the reader's code (exit 3); nothing is stored.
4. Store the version, create the named design in the caller's namespace with its head at the new
   `DesignId`. A name that already exists refuses as a conflict (exit 7) and returns the existing head.
5. Run stage 1 (N14a-08) and attach its report. Exit code 0 with no findings, 2 with findings.
6. Answer: `result.design` (the `DesignId`), `result.name`, `result.source`, `result.stage1` (the stage
   report), `bound.design`.

`design.show`. CLI: `frob design show <design-or-file> [--section <name>]… [--at <config>] [--tier
host|referee] [--no-memo] --json`. With no `--section` it returns `summary`. Each section also has a shorthand
flag of its own name (`--mass` for `--section mass`, `--frames`, `--instances`, …). Sections:

| Section | Content | Produced by |
|---|---|---|
| `summary` | Name, `DesignId`, `ModelId`, counts of bodies, joints, actuators, sensors, end effectors; total mass with provenance; Γ_mech and Γ_obs names; budget status | All functors |
| `term` | The canonical JSON bytes of the design | BD-054 |
| `instances` | The expanded instance list with identifiers, kinds, parents and exact placements | N14a-07 |
| `frames` | World poses of named frames at a configuration (`--at home` or a joint map), on the host reference or on the referee | BD-061 |
| `mass` | Per-body mass, centre of mass, inertia, fill, material, provenance, any moment bound; the roll-up | BD-062, N14a-13, N14a-14 |
| `collision` | Collision primitives per body with fitting errors | N14a-14 |
| `channels` | Actuator channels, sensor channels with exact rates, contact bindings, joint row descriptors | N14a-09 |
| `budget` | Subtree summaries, envelope, cost per currency, the budget graph | N14a-10 |
| `symmetry` | Both groups with generators, representations and breakers | N14a-11 |
| `shape` | The shape summary and limb view hashes | N14a-12 |
| `products` | Every compile product with kind, digest, memo key and whether it was served or computed | BD-063 |

A section that needs a compile product compiles on a miss. `--no-memo` compiles from an empty memo graph (the
reference against which incremental compilation is compared). A design that stage 1 refuses still shows
`term` and `instances` where they exist, and the other sections answer with the stage-1 refusal.

Envelope and exit codes. Both verbs return one envelope (`frob.envelope/1`): `ok`, `exit`, `result`,
`evidence` (class `Tested`; tier `static`, or `referee` for `frames --tier referee`; determinism `exact`;
`model_id` when a model exists; `claims` empty; `reality` `no-claim`), `bound` (the `DesignId` behind every
name), `cost`, `warnings`, `next_actions` (the first repairs of any findings, as commands). Exit 0 completed;
2 completed with findings; 3 refused input; 7 conflict; exit 1 is never emitted on purpose.

Quantities in results are strings with units; integers above 2⁵³ and hashes are strings.

## Acceptance criteria

- [ ] `frob design new quad-a --file quad-a.fbot --key k1 --json` returns exit 0, a `DesignId`, and a stage-1
      report with verdict `pass`; the same file as an S-expression gives the same `DesignId`.
- [ ] Repeating the call with the same key returns the same answer with `idempotent_replay: true`; the same
      key with another file refuses with `FROB-REF-803` and exit 7; no key refuses with `FROB-REF-805`.
- [ ] A file with a misspelt field refuses with `FROB-REF-103`, exit 3, and stores nothing (a following
      `frob design show quad-a` reports an unknown name).
- [ ] A file with an over-thick shell is stored, exit 2, with the `FROB-REF-105` finding and its repair in
      `next_actions`.
- [ ] `--template <archetype> --set <param>=<value>` with a value outside the parameter's bounds refuses with
      `FROB-REF-111` (tested with a `synthetic` template until the catalog lands).
- [ ] `frob design show quad-a` returns the summary with 17 bodies, 12 actuators, 18 sensor instances, 4 end
      effectors, both group names and a `model_id` in the evidence block.
- [ ] Each of the eleven sections returns its content with the evidence block, and `--section frames --tier
      referee` reports tier `referee`.
- [ ] Both verbs appear in the generated CLI help, the schema directory and the MCP tool list, and the
      generated-surface check passes.
- [ ] A read with a session that lacks `design:read` is refused as a capability failure (exit 5).

## Test plan

### Unit tests

`cargo test -p frob-verbs design_new design_show`.

- `new_from_json_and_sexpr_same_id`; `new_idempotent_replay`; `new_key_conflict`; `new_missing_key`.
- `new_refuses_without_canonical_form_and_stores_nothing`.
- `new_stores_with_findings_exit_2`.
- `new_from_template_out_of_bounds_refuses` (a `synthetic` template with one bounded parameter).
- `new_existing_name_conflicts`.
- `show_summary_counts`; `show_each_section_schema_valid` (every section validated against its schema).
- `show_refused_design_degrades`: `term` is returned; `mass` answers with the stage-1 refusal.
- `envelope_has_evidence_and_bound`: no answer lacks `evidence` or `bound.design`.
- `wide_values_are_strings`: no JSON number above 2⁵³ − 1 in any answer.

### End-to-end script and logging

`scripts/e2e/skel_author_compile.sh` (bead N14a-27) is the script of these verbs: it creates the worked
design from a file in three spellings, shows every section, and runs the planted refusals. Each step logs
the exact command line, exit code, wall time, the envelope's `evidence` block, the `DesignId`, the measured
values with units and thresholds, and on failure the first differing value with the paths of the input file
and the answer.

### Known answers and negative controls

- KA-261 through the `mass` section: the worked torso reports 22.68 kg solid and 1.9227375 kg as a 2.5 mm
  shell.
- Counting known answers through `summary`: 17 bodies, 12 actuated joints, 18 velocity coordinates.
- Negative control 1 (planted): an executor that stores before canonicalizing. The misspelt-field test finds
  a stored design.
- Negative control 2 (planted): an answer with a bare number for mass. The envelope test fails on the
  missing unit and evidence.
- Negative control 3 (planted): `design.new` that resolves a template parameter by clamping to its bounds.
- Determinism lanes: the same file gives the same `DesignId` and section digests twice, in debug and release,
  on Linux and macOS.

## Considerations

- Imported and authored names are untrusted text: `name` and `meta` are echoed only in fields that carry the
  untrusted mark, and never interpolated into `next_actions` commands unquoted.
- `design.show` on a large design returns sections on request only; the summary stays small so that an
  agent's context is not filled by a term it did not ask for.
- The flags `--template` and `--from-cell` depend on catalogs owned elsewhere; until they land the verb
  answers them with a capability refusal (exit 5) that names the missing catalog, never with a guess.
- A design's name is mutable (its head moves with each edit); every answer says which immutable version it
  describes.
