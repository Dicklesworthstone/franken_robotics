## Background

Every capability of FrankenRobotics reaches an agent as a verb: one registry entry from which the command
line, the daemon protocol, the MCP tool definitions, the schemas and the documentation are generated, so that
the surfaces cannot drift. A capability counts as implemented only when it is reachable through `frob --json`
with a documented schema and exit code. The design cluster has twelve verbs (VERBS-design); this bead builds the
two that open and read a design and that no other bead owns: `design.new` (kind `mutate`) and `design.show`
(kind `read`), both first available at M1. Their registry purposes: create a design from a template, a file or
a mission cell; show a design and its compiled sections.

They are the first thing an agent touches, and the place where the compile pipeline of Skeleton becomes
visible: `design.show` is how the canonical term, the expanded instances, the frames, the mass roll-up, the
channels, the budgets and the shape summary of a model are read, each as a section with the claim product
attached. No naked numbers reach an agent: every answer is one envelope carrying its evidence block (the
class of evidence, the tier, the determinism class, the model identity) and the immutable identifiers every
mutable name was resolved to.

DESIGN choices. `design.new` stores any document that has a canonical form, also one that the validate step
would refuse, and returns the stage-1 findings with it. Reason: a design with an over-thick shell must be
storable so that it can be repaired by a typed edit with a lineage; refusing to store it would push agents
to fix files by hand outside the edit history. A document with no canonical form is refused with the reader's
code and nothing is stored: an unknown, misspelt or duplicate field or a missing required member (`FROB-REF-103`),
a unit or dimension error (`FROB-REF-102`), an unsupported schema version (`FROB-REF-125`), a JSON integer outside
±(2⁵³ − 1) (`FROB-REF-808`, N14a-01's rule 5). A document that has a
canonical form and fails stage 1 is stored and answered with exit 2: its stage-1 codes, among them a body without
a fill or a solid written as a shell (`FROB-REF-105`), a contact law missing or incompatible (`FROB-REF-121`) and
a sensor without a parent frame, a rate or a clock (`FROB-REF-126`), are findings of this verb, not refusals. The
one refusal of `design.new` beyond the reader's is `FROB-REF-111` for a `--set` value outside a template
parameter's bounds (nothing is stored). `design.show` never computes anything expensive: it reads compile
products, compiling on a miss.

## Scope

In: both verbs' schemas, executors, exit codes and refusals, true to their registry rows (VERBS-design writes the
rows); the three sources of
`design.new`; the sections of `design.show`; name resolution to immutable identifiers.

Out: templates, the instantiation function and `design.templates` (BD-109, which depends on this bead and
replaces the synthetic template this verb is tested with); mission cells (the mission beads); the fourth source
`--from <address>`, a fork of a design content address into the caller's namespace (N32b-03, M3, which adds it to
this verb's row); `design.view` (BD-057);
`design.edit` and `design.patch` (BD-058, BD-059); `design.check` (BD-110); `design.import` and
`design.export` (the import and export beads); `design.diff` and `design.blame` (BD-113).

## Technical approach

Registry entries. The rows of record are VERBS-design's; this bead implements them and does not write a second
copy. As they stand there (`refusals` is the chapter list; the generator appends the surface-wide codes by kind
and field: 720, 723, 724 and 802 for every verb; 725, 803, 804 and 805 for a `mutate`; 734 and 828 for each
parameter that accepts a path to a file, here `--file` of `design.new` and the design file and `--at @<path>` of
`design.show`):

```toml
[[verb]]
name = "design.new"
cluster = "design"
kind = "mutate"
tier = "S"
capabilities = ["design:write"]
input_schema = "frob.design.new.in/1"
output_schema = "frob.design.new.out/1"
refusals = ["FROB-REF-102", "FROB-REF-103", "FROB-REF-111", "FROB-REF-125", "FROB-REF-808"]
idempotent = false

first_milestone = "M1"
task_clusters = ["author"]

[[verb]]
name = "design.show"
cluster = "design"
kind = "read"

input_schema = "frob.design.show.in/1"
output_schema = "frob.design.show.out/1"
refusals = ["FROB-REF-102", "FROB-REF-103", "FROB-REF-125", "FROB-REF-808"]
idempotent = true
cost_model = "static: one compile on a memo miss"
first_milestone = "M1"
task_clusters = ["author"]
examples = ["frob design show quad-a --json"]
owner = "frob-design"
purpose = "Show a design and its compiled sections"
```

The template name of the registry example, `quadruped-12dof`, is the alias that N14bx-03 registers for
`quad-mammal` with the studio preset; until the archetype catalog and that alias are linked the example answers
`FROB-REF-724` (below), and this bead's own tests use a `synthetic` template. The stage-1 codes 105, 121 and 126
are not in `design.new`'s list because they are findings of this verb (exit 2, the design stored).

`design.new`. CLI: `frob design new <name> (--file <path|-> | --template <archetype> [--preset <ref>]
[--set id=value]… | --from-cell <cell-ref>) --key <idempotency-key> --json`. Steps:

1. Bind the idempotency key with the canonical request digest in one transaction (same key and content:
   return the stored answer with `idempotent_replay: true`; same key, other content: `FROB-REF-803`, exit 7;
   no key: `FROB-REF-805`).
2. Obtain the document: from a file (a `frob.path/1` argument through the path jail; outside the roots is `FROB-REF-734`, exit 5) or standard input in either view (JSON or S-expression, detected by the
   first non-space byte); from a template by substituting `--set` values for its parameters (a value outside
   a parameter's bounds refuses with `FROB-REF-111`); or from a mission cell, taking the centre of the named
   inner cell and writing `meta.source` as the query and cell identifiers.
3. Canonicalize. No canonical form: refuse with the reader's code (102, 103, 125 or 808; exit 3); nothing is
   stored.
4. Store the version, create the named design in the caller's namespace with its head at the new
   `DesignId`, through BD-058's design store (`Store::create`: a compare-and-swap of the head from absent, the
   version row and an edit record of kind `new`, in the admission transaction of step 1). A name that already exists refuses as a conflict with `FROB-REF-804`, exit 7, and returns the
   existing head (DESIGN: a create is a `mutate` whose expected parent is "no lineage", so an existing head
   is a stale parent; the code's first repair, `design diff`, and its second, fork under a new name, both
   apply).
5. Run stage 1 (N14a-08) and attach its report. Exit code 0 with no findings, 2 with findings (every stage-1
   code is a finding here: the version is already stored and the findings' first repairs are typed edits in
   `next_actions`).
6. When stage 1 passes, compile through the symmetry functor (N14a-11) and attach the computed groups;
   when it refuses, `result.symmetry` is absent with `reason: "stage-1-refused"`.
7. Answer: `result.design` (the `DesignId`), `result.name`, `result.source`, `result.params` (the parameter
   point: the template's parameters after `--set`, the cell centre for a mission cell, absent for a file),
   `result.symmetry` (Γ_mech and Γ_obs with names and orders), `result.stage1` (the stage report),
   `bound.design`. These are the outputs the verb registry's row lists (VERBS-design).

Argument errors (an unknown archetype for `--template`, an unknown design name, a malformed `--set`) are
`FROB-REF-802`, exit 3, with the nearest valid value. `--template` before the archetype catalog (BD-109) is
linked, and `--from-cell` before the mission catalog is, refuse with `FROB-REF-724`, exit 5, naming the
missing catalog; this is the code N32-REF assigns to a capability not present in the build.

`design.show`. CLI: `frob design show <design-or-file> [--section <name>]… [--at <config>] [--tier
host|referee] [--no-memo] --json`. `--at` takes `home`, a joint map, or `@<path>`: a file (a `frob.path/1`
argument, resolved by the path jail of N37-11; a path outside the session's roots is `FROB-REF-734`, exit 5) of
configurations, one joint map per line, at most 10⁵ lines (more is `FROB-REF-802`); with a file,
`frames` returns one frame set per configuration in file order, from one compile, so that a parity run of 10⁴
configurations is one invocation. With no `--section` it returns `summary`. Each section also has a shorthand
flag of its own name (`--mass` for `--section mass`, `--frames`, `--instances`, …). Sections:

| Section | Content | Produced by |
|---|---|---|
| `summary` | Name, `DesignId`, `ModelId`, counts of bodies, joints, actuators, sensors, end effectors; total mass with provenance; Γ_mech and Γ_obs names; budget status | All functors |
| `term` | The canonical JSON bytes of the design | BD-054 |
| `instances` | The expanded instance list with identifiers, kinds, parents and exact placements | N14a-07 |
| `frames` | World poses of named frames at a configuration (`--at home` or a joint map), on the host reference or on the referee | BD-061 |
| `mass` | Per-body mass, centre of mass, inertia, fill, material, provenance, any moment bound; the roll-up | BD-062, N14a-13, N14a-14 |
| `collision` | Collision primitives per body with fitting errors | N14a-14 |
| `channels` | Actuator channels, sensor channels with exact rates, contact bindings, joint row descriptors | N14a-09 |
| `budget` | Subtree summaries, envelope, cost per currency, the budget graph | N14a-10 |
| `symmetry` | Both groups with generators, representations and breakers | N14a-11 |
| `shape` | The shape summary and limb view hashes | N14a-12 |
| `levers` | The declared levers with path, domain, manifold and prior; the locks; the dimension of the free lever set | N14a-06 |
| `products` | Every compile product with kind, digest, memo key and whether it was served or computed | BD-063 |
| `packed` | Packed counts, depth-level starts, path capacity, layout and content digests (M2) | BD-148, which registers it |

The sections are a table in code (`design_show::SECTIONS`: name, shorthand flag, producer, printer, schema), so a
later producer registers its own section without editing the executor. This bead registers the twelve sections
above `packed`; `packed` is registered by BD-148 (M2, which depends on this bead) together with its printer and
schema. Before that bead is linked, `--section packed` refuses with `FROB-REF-724`, exit 5, naming the missing
producer, never with an empty section.

A section that needs a compile product compiles on a miss. `--no-memo` compiles from an empty memo graph (the
reference against which incremental compilation is compared); it is the common input NJL-01 generates from the
row's `memo = true` (variation 14), the field BD-111 sets on this row at M1, and the row declares no `no_memo` of
its own. A design that stage 1 refuses still shows
`term` and `instances` where they exist, and the other sections answer with the stage-1 refusal.

Envelope and exit codes. Both verbs return one envelope (`frob.envelope/1`): `ok`, `exit`, `result`,
`evidence` (tier `static`, or `referee` for `frames --tier referee`; determinism `exact`; `model_id` when a
model exists; `claims` empty; `reality` `no-claim`; class as follows), `bound` (the `DesignId` behind every
name), `cost`, `warnings`, `next_actions` (the first repairs of any findings, as commands). Exit 0 completed;
2 completed with findings; 3 refused input; 7 conflict; exit 1 is never emitted on purpose.

Evidence class. `design.new` is *static* in the verb registry: class `Tested`. `design.show` is
*pass-through*: each section carries the evidence of the product it reads (a symmetry section with the
algebra's certificate is `Certified`, one on the tolerance route `Tested`; a mass section in which a body
carries a non-zero `MomentBound` lowers that share to `Estimated`, N14a-14), and the envelope's class is the
weakest of the sections returned.

Quantities in results are strings with units; integers above 2⁵³ and hashes are strings.

## Acceptance criteria

- [ ] `frob design new quad-a --file quad-a.fbot --key k1 --json` returns exit 0, a `DesignId`, and a stage-1
      report with verdict `pass`; the same file as an S-expression gives the same `DesignId`.
- [ ] Repeating the call with the same key returns the same answer with `idempotent_replay: true`; the same
      key with another file refuses with `FROB-REF-803` and exit 7; no key refuses with `FROB-REF-805`.
- [ ] A file with a misspelt field refuses with `FROB-REF-103`, exit 3, and stores nothing (a following
      `frob design show quad-a` refuses with `FROB-REF-802`, exit 3, unknown name).
- [ ] `frob design new quad-a …` a second time with a new key and another file refuses with `FROB-REF-804`,
      exit 7, and the answer names the existing head.
- [ ] `design.new` of the worked design returns `result.symmetry` with Γ_mech `C2xC2` (order 4) and Γ_obs `C2`
      (order 2); from a template it returns `result.params` with every parameter's value.
- [ ] A file with an over-thick shell is stored, exit 2, with the `FROB-REF-105` finding and its repair in
      `next_actions`; a file with a body that has no `fill`, and one with a sensor that has no `clock`, are
      stored likewise, exit 2, with the `FROB-REF-105` and `FROB-REF-126` findings; none of the three is a
      refusal.
- [ ] `--template <archetype> --set <param>=<value>` with a value outside the parameter's bounds refuses with
      `FROB-REF-111` (tested with a `synthetic` template until the catalog lands).
- [ ] `frob design show quad-a` returns the summary with 17 bodies, 12 actuators, 18 sensor instances, 4 end
      effectors, both group names and a `model_id` in the evidence block.
- [ ] `--section packed` without BD-148 linked refuses with `FROB-REF-724`, exit 5, naming the producer; a
      section registered in a test build through `design_show::SECTIONS` is returned with no change to the
      executor.
- [ ] Each of the twelve sections returns its content with the evidence block, and `--section frames --tier
      referee` reports tier `referee`; the envelope's evidence class is the weakest of the sections returned
      (a design with one quadrature-bounded body reports `Estimated` for `mass`).
- [ ] Both verbs appear in the generated CLI help, the schema directory and the MCP tool list, and the
      generated-surface check passes.
- [ ] Both registry entries name their capability (`design:write`, `design:read`) and the registry lint
      accepts them. The scope check itself is the token check of N32b-01 (M2, `FROB-REF-720`, exit 5), whose
      tests cover every registered verb; at M1, with no tokens, it is not asserted here.
- [ ] `--template` with no archetype catalog linked refuses with `FROB-REF-724`, exit 5, naming the catalog.

## Test plan

### Unit tests

`cargo test -p frob-verbs -- design_new design_show` (several filters go after `--`).

- `new_from_json_and_sexpr_same_id`; `new_idempotent_replay`; `new_key_conflict`; `new_missing_key`.
- `new_refuses_without_canonical_form_and_stores_nothing`: a misspelt field (103) and a JSON integer of 2⁵³ in a
  count field (808), each exit 3 with nothing stored.
- `new_stores_with_findings_exit_2`: the over-thick shell, the body with no `fill` and the sensor with no
  `clock` are each stored with exit 2 and their finding (105, 105, 126); a `--set` outside bounds stores nothing.
- `registry_rows_match`: the two generated entries equal VERBS-design's rows field for field (`design.new`
  `idempotent = false` with chapter codes 102, 103, 111, 125, 808; `design.show` with 102, 103, 125, 808; 734
  and 828 appended by the field rule on both).
- `new_from_template_out_of_bounds_refuses` (a `synthetic` template with one bounded parameter).
- `new_existing_name_conflicts` (`FROB-REF-804`, exit 7, existing head in the answer).
- `new_reports_params_and_groups`: `result.params` from the `synthetic` template; `result.symmetry` orders 4
  and 2 for the worked design; absent with `stage-1-refused` for the over-thick shell.
- `new_without_catalog_is_724`; `show_unknown_name_is_802`; `show_packed_without_producer_is_724`;
  `show_registered_section` (a test-only section added to the table is served, schema-checked and listed in the
  help).
- `show_levers_section`: the worked design's levers and locks with their domains.
- `show_frames_at_file`: a file of three configurations returns three frame sets in order, equal to three
  single-configuration calls; a file of 10⁵ + 1 lines is `FROB-REF-802`.
- `show_evidence_is_weakest_section`.
- `show_summary_counts`; `show_each_section_schema_valid` (every section validated against its schema).
- `show_refused_design_degrades`: `term` is returned; `mass` answers with the stage-1 refusal.
- `envelope_has_evidence_and_bound`: no answer lacks `evidence` or `bound.design`.
- `wide_values_are_strings`: no JSON number above 2⁵³ − 1 in any answer.

### End-to-end script and logging

`scripts/e2e/skel_author_compile.sh` (bead N14a-27) is the script of these verbs: it creates the worked
design from a file in three spellings, shows every section, and runs the planted refusals. Each step logs
the exact command line, exit code, wall time, the envelope's `evidence` block, the `DesignId`, the measured
values with units and thresholds, and on failure the first differing value with the paths of the input file
and the answer.

### Known answers and negative controls

- KA-261 through the `mass` section: the worked torso reports 22.68 kg solid and 1.9227375 kg as a 2.5 mm
  shell.
- Counting known answers through `summary`: 17 bodies, 12 actuated joints, 18 velocity coordinates.
- Negative control 1 (planted): an executor that stores before canonicalizing. The misspelt-field test finds
  a stored design.
- Negative control 2 (planted): an answer with a bare number for mass. The envelope test fails on the
  missing unit and evidence.
- Negative control 3 (planted): `design.new` that resolves a template parameter by clamping to its bounds.
- Determinism lanes: the same file gives the same `DesignId` and section digests twice, in debug and release,
  on Linux and macOS.

## Considerations

- Imported and authored names are untrusted text: `name` and `meta` are echoed only in fields that carry the
  untrusted mark, and never interpolated into `next_actions` commands unquoted.
- `design.show` on a large design returns sections on request only; the summary stays small so that an
  agent's context is not filled by a term it did not ask for.
- The flags `--template` and `--from-cell` depend on catalogs owned elsewhere; until they land the verb
  answers them with `FROB-REF-724` (exit 5) naming the missing catalog, never with a guess.
- A design's name is mutable (its head moves with each edit); every answer says which immutable version it
  describes.
