## Background

A design has one canonical form (JSON, schema `frob.design/1`) and one optional second view, an
S-expression text of the same term (BD-057). The view exists because agents edit nested terms more reliably
in a syntax with one bracket kind and quantity atoms such as `0.42m`. It is worth keeping only if it is
exactly lossless. INV-SKEL-04: the JSON and S-expression views of a design have the same `DesignId`, and
converting between them is the identity on canonical forms. PO-SKEL-01: canonicalization is idempotent and
both views parse to the same typed term.

The gate that measures this is GATE-SKEL-05 (TARGET): INV-SKEL-04 and PO-SKEL-01 hold on 10⁴ random designs;
a JavaScript client's round trip of every wide integer and hash matches the native decoder. The kill gate
that reads it is KILL-SKEL-SEXPR: if INV-SKEL-04 cannot be held after one repair cycle the view is removed
and JSON is the only syntax.

This script measures the gate from the user's side, through the verb `design.view`, and produces the log
that the kill-gate decision (N14a-20) cites.

## Scope

In: one script, its fixtures, its assertions, its log, and the gate receipt. Out: the view itself (BD-057);
the decision (N14a-20); the format registry's own round-trip gate for all formats.

## Technical approach

Script: `scripts/e2e/skel_view_roundtrip.sh --seed <s> [--count 10000]`. It sources the shared end-to-end
helper and works in a scratch directory.

Steps and assertions:

| # | Commands | Asserts |
|---|---|---|
| 1 | `frob design view quad-a.fbot --as sexpr --json` then `frob design view <that text> --as json --json` | The final text equals the canonical JSON bytes of `quad-a`; `bound.design` is the same in both answers; `result.canonical` is true |
| 2 | The same starting from the format's own S-expression example | The `DesignId` equals that of the JSON example |
| 3 | `frob design view quad-a.fbot --as sexpr --pretty --json`, then back | `result.canonical` false for the pretty text; the round trip still returns the canonical JSON |
| 4 | For each archetype available: json → sexpr → json and sexpr → json → sexpr | Byte identity on canonical forms in both directions |
| 5 | Generate `--count` random valid designs with the seeded generator; for each, both round trips and a double canonicalization | Zero `DesignId` mismatches between views; zero non-identity round trips; canon(canon(x)) = canon(x) for all |
| 6 | Inputs with comments, re-indentation and reordered keyword pairs | `DesignId` unchanged |
| 7 | Designs whose `name` is `"0.42m"`, `"R+"`, `"(x)"`, `"true"` | Round trip preserves the name byte for byte |
| 8 | The JavaScript client: decode each canonical JSON of a 10³-design corpus that contains integers at 2⁵³ − 1, 2⁵³, 2⁵³ + 1 and 64-digit hashes; re-encode; report every wide integer and hash | Every reported value equals the native decoder's |
| 9 | `frob design view <sexpr> --as json` offered to a verb that requires an identity (a cache-key position) | Refused with the view-is-not-identity refusal: only canonical JSON bytes are hashed |

Gate receipt. On success the script writes `GATE-SKEL-05` to the gate record with: designs tried, archetypes
tried, mismatches (0), non-identity round trips (0), wide fields compared and differing (0), the commit, the
hardware fingerprint and the seed. On failure it writes the counts and the first failing design's files.

Logging. NDJSON to `target/e2e-logs/skel_view_roundtrip/<utc-timestamp>.ndjson` with a transcript beside it.
Every line has `ts`, `script`, `bead: "BD-057"`, `step`, `event`, the exact command line, exit code, wall
time, the envelope's `evidence` block (class, tier, determinism, identities, seed), the digests of input and
output text, the `DesignId` on each side, and on failure the first differing byte offset with twenty bytes
of context from each side and the paths of the two files. Step 5 logs one `metric` line per thousand designs
(tried, failed) so that a long run shows progress with a denominator. The `summary` line gives assertions
passed and failed, the counts above, and `gates: ["GATE-SKEL-05", "KILL-SKEL-SEXPR"]`.

## Acceptance criteria

- [ ] The script exists, is plain shell, is seed-explicit, idempotent, and exits non-zero on any failure.
- [ ] Steps 1 to 9 pass on Linux and on macOS with the default count of 10⁴.
- [ ] The gate record of GATE-SKEL-05 carries measured values (designs tried, mismatches, round trips, wide
      fields), the commit, the fingerprint and the seed.
- [ ] Each of the three planted defects of BD-057 makes the script fail at the expected step: a free string
      printed bare (step 7), keyword pairs in insertion order (step 1 or 4), a wide integer written as a
      number (step 8).
- [ ] On a host without the JavaScript runtime step 8 is logged `not run` and the gate is not recorded PASS.
- [ ] The log of a failing run is sufficient to reproduce the failure: it names the seed, the design index
      and both files.

## Test plan

### Unit tests

The script is the test. A shell self-test runs it with `--count 10` against a binary built with one planted
defect and checks the non-zero exit and the failure line.

### End-to-end script and logging

As above: `scripts/e2e/skel_view_roundtrip.sh`, driving `frob design view` in both directions, logs under
`target/e2e-logs/skel_view_roundtrip/`.

### Known answers and negative controls

- KA-288: the JSON and S-expression views give the same `DesignId`; conversion is the identity on canonical
  forms; canonicalization is idempotent, on 10⁴ random designs and the archetypes (exact, hash; tier G3).
- Hand-checkable atoms inside step 1: the 2.5 mm shell prints `0.0025m`; −45° prints `-1/8turn`.
- Wide-integer fact behind step 8: a decoder that reads numbers as doubles returns 9,007,199,254,740,992 for
  2⁵³ + 1 = 9,007,199,254,740,993.
- Negative controls: the three planted defects of the acceptance list.
- Determinism lanes: the script's outputs (identities and text digests) are identical twice on one machine,
  with debug and release binaries, and on Linux and macOS.

## Considerations

- 10⁴ designs through a process per call would be slow; the script batches conversions through one
  `frob` invocation reading a file list, which the verb supports for read-only work, and still uses the real
  binary.
- If the kill gate fires, this script is replaced by a one-step check that `design.view` is no longer a
  registered verb.
- The random designs come from a generator owned elsewhere; its seed and version are logged, because a
  change of generator changes the population the gate was measured on.
