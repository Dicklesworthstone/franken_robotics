## Background

Reference robots enter FrankenRobotics by import, and most are published as MJCF. The MJCF importer
(BD-066) maps a documented subset of the format to a design term and reports everything else in a loss
report, with file and line; exporters (N14a-25) write URDF and MJCF with the report in reverse. The rule for
both directions: round trips compare meaning, not bytes: forward kinematics, mass properties and the map of
identifiers.

GATE-SKEL-01 (TARGET, claim type Parity): each reference robot imports with forward-kinematics parity
against the oracle within 10⁻⁹ m and 10⁻⁹ rad over 10⁴ configurations, and its loss report lists every
dropped field found by a field-coverage diff. The risk behind the second clause (RISK-13): reference-robot
imports hide lossy contact mappings; the leading indicator is a field missing from a loss report in the
field-coverage diff.

This script exercises the MJCF importer and both exporters from the command line and produces the MJCF rows
of the gate. The oracle is a set of fixtures captured out of process from the reference simulator at a
pinned version (body poses at seeded configurations), with pin and date, never regenerated from this code.

## Scope

In: one script, its fixtures, assertions, log and the MJCF rows of the gate receipt. Out: the importer and
exporters (their beads); URDF import's script; fixture capture (BD-067); fuzzing (BD-307).

## Technical approach

Script: `scripts/e2e/skel_import_mjcf_export.sh --seed <s> [--configs 10000] [--robots <list>]`. Fixtures:
the MJCF reference robots on file with their licence manifest (Unitree Go1, Go2, A1, H1, G1; ANYmal B, C;
Spot; Cassie; Stretch 3; TIAGo; and, for import parity only, Booster T1, Apptronik Apollo, Fourier N1, OP3,
TALOS, Barkour), each with its oracle pose fixture; small `synthetic` MJCF files for the convention checks.

Steps and assertions, per robot unless stated:

| # | Commands | Asserts |
|---|---|---|
| 1 | `frob design import <robot>.xml --format mjcf --key … --json` | Exit 0 or 2; a `DesignId`; a loss report identifier; counts of mapped, default-filled, dropped, unsupported, repaired-proposed |
| 2 | The field-coverage diff on the resolved source against the importer's mapped set and the loss report | Empty: every element and attribute is mapped or listed |
| 3 | For `--configs` seeded configurations of the tree's joint coordinates: `frob design show <d> --frames --at <q> --tier host --json` (batched through one invocation) against the oracle fixture | Largest position error ≤ 10⁻⁹ m and largest rotation-angle error ≤ 10⁻⁹ rad over all bodies and configurations |
| 4 | `frob design show <d> --mass --json` against the source's inertials | Mass, centre of mass and inertia of every body with an `inertial` equal the source values after the stated rotation |
| 5 | `frob design check <d> --stages 1-2 --json` | Stage 1 refuses with `FROB-REF-121` (no contact law is inferred) until end effectors are declared; after a scripted `set-contact-law` on the feet it passes stage 1; stage 2 reports any inconsistent inertia as listed in the loss report |
| 6 | `frob design import <robot>.xml --format mjcf --strict` on a robot with an unsupported element | Exit 3, `FROB-REF-122`, naming the element with file and line |
| 7 | `synthetic` convention files: half-sizes; inertia from geoms at the default density; `angle="radian"` against degrees; default-class resolution; an `include` outside the import root | The values of BD-066's acceptance list; the path-jail refusal |
| 8 | A model whose link is named with an instruction-like string | The name appears only in fields marked untrusted; nothing else changes |
| 9 | `frob design export <d> --format mjcf --json`, re-import, and the round-trip comparator; the same with `--format urdf` | Forward kinematics equal within 10⁻¹² m and 10⁻¹² rad at 100 configurations; mass properties equal within 10⁻¹² relative; identifier map a bijection; the reverse loss report present; the `authorization` block's three flags `false` |
| 10 | Export of the worked design `quad-a` in both formats | The torso's exported mass is 1.9227375 kg; the reverse loss report lists the bus, sensors, levers, budgets, symmetry assertions, contact laws and expanded constructors |
| 11 | Import of one robot on Linux and on macOS | The same `DesignId` and report hash |

Gate receipt. The script writes the MJCF rows of `GATE-SKEL-01`: per robot, configurations tried, largest
position and angle error, field-coverage diff size (0), the fixture's pin and capture date, commit,
hardware fingerprint and seed. A robot whose licence was not re-checked or whose fixture is missing is
recorded `not run` with the reason, never passed.

Logging. NDJSON to `target/e2e-logs/skel_import_mjcf_export/<utc-timestamp>.ndjson` with a transcript beside
it. Every line has `ts`, `script`, `bead` (`BD-066`, or `N14a-25` for steps 9 and 10), `step`, `event`, the
exact command line, exit code, wall time, the envelope's `evidence` block (a parity result is labelled as a
Parity claim; `reality` is `no-claim`), the source hashes, the report counts, the largest errors with their
thresholds and units, and on failure the first body and configuration that differ with both poses and the
fixture path. Imported names are logged only inside the untrusted field. The `summary` line gives assertions
passed and failed, robots passed, failed and not run, and `gates: ["GATE-SKEL-01"]`.

## Acceptance criteria

- [ ] The script exists, is plain shell, seed-explicit and idempotent, and exits non-zero on any failure.
- [ ] Every MJCF reference robot with a fixture on file passes steps 1 to 5; the convention files pass
      step 7; export round trips pass steps 9 and 10.
- [ ] The MJCF rows of GATE-SKEL-01 are recorded with measured maxima, the oracle pin and date, commit,
      fingerprint and seed.
- [ ] With the planted defect "half-sizes read as full sizes" the script fails at step 7 (and at step 4 for
      robots without inertials); with "`armature` silently dropped" it fails at step 2; with a wrong Euler
      sequence it fails at step 3.
- [ ] With the planted exporter defect "inertials derived from collision geometry" the script fails at
      step 10.
- [ ] No fixture is regenerated by the script: it only reads the oracle files, and a missing fixture is
      `not run`.

## Test plan

### Unit tests

The script is the test. A shell self-test runs step 7 against a binary with the half-size defect and checks
the non-zero exit and the failure line.

### End-to-end script and logging

As above: `scripts/e2e/skel_import_mjcf_export.sh`, driving `frob design import`, `frob design show`,
`frob design check` and `frob design export`; logs under `target/e2e-logs/skel_import_mjcf_export/`.

### Known answers and negative controls

- KA-290: forward-kinematics parity within 10⁻⁹ m and 10⁻⁹ rad over 10⁴ configurations; the loss report
  lists every dropped field found by a field-coverage diff (tier G2, host).
- Hand-checkable convention answers (step 7): a box geom `size="0.1 0.05 0.02"` has edges 0.2, 0.1,
  0.04 m and, at 1000 kg/m³, mass 0.8 kg; `diaginertia="1 2 3"` rotated a quarter turn about z is
  diag(2, 1, 3).
- KA-261 through export (step 10): 1.9227375 kg for the shell torso, where the solid block is 22.68 kg.
- Negative controls: the four planted defects of the acceptance list.
- Metamorphic: reordering sibling elements of a source file changes neither the `DesignId` nor the report's
  entry set.
- Determinism lanes: identities and report hashes identical twice, with debug and release binaries, on Linux
  and macOS.

## Considerations

- Parity here is geometry and mass. Nothing in this script supports a claim about contact behaviour or
  about reality: the soft-contact mapping is lossy and labelled parity-only.
- The humanoid's parity is judged against the full source, including welded links; a reduced model must be
  declared, and an import that drops a body of nonzero mass without a declaration is refused.
- Cassie-like models have closed loops; forward-kinematics parity is taken on the tree's joint coordinates,
  and the closures are checked as constraints listed in the import.
- The run over all robots at 10⁴ configurations is minutes, not seconds; a `--robots` subset keeps the
  per-change run short, and the full run is the gate.
