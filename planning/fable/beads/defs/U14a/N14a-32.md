## Background

Each of the seven interior archetypes (home, apartment, office, warehouse, manufacturing plant, retail
store, commercial kitchen) has a hazard registry, `registries/hazards/<archetype>.toml` (BD-227). A hazard is
a feature of a place that causes a specific robot failure; a row has a name, a dimension range with units, a
distribution, the mechanism that represents it, the failure it provokes, and a provenance field. At plan
time every dimension is `assumed`: generic values chosen to make scenes valid, with no building code,
regulation or standard read for them. A scene pack counts the `assumed` dimensions it used
(`dimensions_assumed` in its manifest), and a report that claims a scene is representative of real buildings
is refused while that count is non-zero (`FROB-REF-312`).

The capability a user sees is three things: read a registry (`frob scene hazards`), see how many assumed
dimensions went into a generated scene, and be stopped from claiming realism on assumptions. This script
drives all three with the real binary.

## Scope

In: one script, its assertions and its log. Out: the registries and the check (BD-227); the calling side of
the realism claim (the request field `claims_realism`, the flag `--claims-realism`, the rule that every verb
able to carry the claim routes through BD-227's function) and the promotion of a dimension against the source
register (N19a-39, a dependency); scene generation and acceptance (their beads); the report verbs (BD-302).

## Technical approach

Script: `scripts/e2e/scene_hazards.sh --seed <s>` (header: `bead=N14a-32 milestone=M3
labels=habitat,scene,verb:scene.hazards seed=7 needs=cpu,second-host plants=skip-claim-check,ignore-task-rows`;
it sources `scripts/e2e/lib.sh`). It works in the harness's scratch root and calls `e2e_registries_scratch`
(STD-E2E) before step 1: the helper copies `registries/` into the run's `registries/` and exports
`FROB_REGISTRIES_ROOT` at that copy, which is the only copy the script edits (the repository's registries are
never touched; `frob` has no `--root` option, STD-E2E's isolation rule). The run is then marked
`registries: "override"` and `gates_claimable: false`, which suits a script that claims no gate. It uses only
generated scenes (no private or imported place). `$S` is the seed. Every call works on the run's own state root
`FROB_STATE`, which `e2e_init` exports empty, so the reference quadruped `quad-a` that steps 6, 8 and 9 run is
created there first, before step 6: `frob design new quad-a --template quad-mammal --key sh-des-1 --json`
(BD-109's archetype through N14a-21's verb; exit 0 or 2); without it `sim.run` finds no design of that name.

Logging. NDJSON to `target/e2e-logs/scene_hazards/<utc-timestamp>.ndjson` with a transcript beside it. Every
line has `ts`, `script`, `bead: "N14a-32"` (the bead that owns the script), `step`, `event`, the exact command
line, exit code, wall time, the envelope's `evidence` block (claims, class, tier, determinism, identities,
seed; `reality: no-claim`), the row and provenance counts, the manifest's `dimensions_assumed`, the `SceneId`,
the refusal payload for `FROB-REF-312` (`code`, `pointer`, the lists of assumed rows per scene and per run,
`repairs` in rank order) and for the registry-load refusal, and on failure the first row or count that differs
with the registry path and the pack path. The `summary` line gives assertions passed and failed, refusals
expected and unexpected, and controls caught; the script claims no gate. Only generated scenes are used, so no
private-scene data can reach the log.

## Acceptance criteria

- [ ] The script exists, is plain shell, seed-explicit and idempotent, and exits non-zero on any failure.
- [ ] Steps 1 to 10 pass on Linux and on macOS.
- [ ] Step 1's counts are (10, 5, 7, 10, 8, 8, 11) and 59.
- [ ] Step 6 is refused with `FROB-REF-312` and exit 3, and step 7 succeeds.
- [ ] Step 9 is refused with `FROB-REF-312` although the pack's count is zero, and the refusal names the row
      the task drew.
- [ ] With the planted defect `skip-claim-check` (the report path skips the realism check) the script fails at
      step 6; with `ignore-task-rows` (the claim check reads only the packs' counts) it fails at step 9. Both
      are run by `run-all.sh --verify-plants`.
- [ ] Every `run` verb call carries its own `--key`; no call returns a stored receipt in place of a result the
      script compares.
- [ ] The log contains the count and the refusal payloads, validates against `frob.e2elog/1`, and names no
      private scene.

## Test plan

### Unit tests

The script is the test. Two shell self-tests (`scripts/e2e/scene_hazards.sh --self-test`):
- `selftest_missing_row`: step 1 against a scratch registry directory with one row removed from `office.toml`
  exits 1, and the failed assertion names `office` with observed 6 and expected 7.
- `selftest_same_key_detected`: step 5 run with the key of step 4 is reported as a failed assertion (the
  second call then returns the first call's stored receipt; the script compares the receipt identities of the
  two envelopes and fails when they are equal), so that a later edit cannot make the determinism step vacuous.

### End-to-end script and logging

As above: `scripts/e2e/scene_hazards.sh`, driving `frob scene hazards`, `frob scene gen`, `frob scene show`,
`frob sim run` and `frob report run`; logs under `target/e2e-logs/scene_hazards/`.

### Known answers and negative controls

- Counting known answer: 59 hazards in seven archetypes (10, 5, 7, 10, 8, 8, 11), every one `assumed`.
- Row known answers (step 2): wet floor, water film 0.1 to 2 mm; swing door, closing torque 5 to 20 N·m;
  hot liquid in a pot or tray, fill 30 to 80%.
- Negative controls: the two planted defects of the acceptance list; the uncited norm of step 10; the family
  name of step 3.
- Determinism lanes: `SceneId`, registry digests and counts identical twice, with debug and release
  binaries, on Linux and macOS.

## Considerations

- Every verb the script calls is carried by a dependency (`scene.hazards` and the task source kind
  `registry:hazards` BD-227, `scene.gen` for interiors BD-225, `scene.show` BD-163, `sim.run` with a scene and
  with `--task` through BD-302's chain, `report.run` BD-302, the claim's calling side and the promotion path
  N19a-39), so no step is skipped for a missing verb; a step that cannot run is a failure, never a pass.
  `e2e_scene_ready` is the harness's own helper: it runs `scene.accept` once that verb exists and logs a skip
  before, so the script needs no dependency on the acceptance bead.
- The consolidated-index bead (NEG-28) adds one step to this script after step 1: the seven outputs
  concatenated and compared row by row with `registries/hazards/INDEX.toml`. It depends on this bead; this bead
  leaves the step number 1b free for it.
- The claim flag's spelling (`--claims-realism`) is N19a-39's; if that bead renames it, this script follows,
  and the assertion stays the behaviour (a claim of representativeness is refused while the count is
  non-zero).
- When cited norms are recorded for some rows, step 1's "every dimension assumed" assertion is replaced by
  the recorded counts by provenance; the refusal step stays as long as any assumed dimension is drawn.
