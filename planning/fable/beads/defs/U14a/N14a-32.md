## Background

Each of the seven interior archetypes (home, apartment, office, warehouse, manufacturing plant, retail
store, commercial kitchen) has a hazard registry, `registries/hazards/<archetype>.toml` (BD-227). A hazard is
a feature of a place that causes a specific robot failure; a row has a name, a dimension range with units, a
distribution, the mechanism that represents it, the failure it provokes, and a provenance field. At plan
time every dimension is `assumed`: generic values chosen to make scenes valid, with no building code,
regulation or standard read for them. A scene pack counts the `assumed` dimensions it used
(`dimensions_assumed` in its manifest), and a report that claims a scene is representative of real buildings
is refused while that count is non-zero (`FROB-REF-312`).

The capability a user sees is three things: read a registry (`frob scene hazards`), see how many assumed
dimensions went into a generated scene, and be stopped from claiming realism on assumptions. This script
drives all three with the real binary.

## Scope

In: one script, its assertions and its log. Out: the registries and the check (BD-227); scene generation and
acceptance (their beads); the report verbs.

## Technical approach

Script: `scripts/e2e/scene_hazards.sh --seed <s>`. It works in a scratch namespace and uses only generated
scenes (no private or imported place).

Steps and assertions:

| # | Commands | Asserts |
|---|---|---|
| 1 | `frob scene hazards <archetype> --json` for the seven archetypes | Row counts 10, 5, 7, 10, 8, 8, 11 (59 in all); every dimension's provenance is `assumed`; counts by provenance are reported |
| 2 | `frob scene hazards commercial-kitchen --slug wet-floor --json`, `--slug swing-door`, `--slug hot-liquid` | Each resolves: film thickness 0.1 to 2 mm; closing torque 5 to 20 N·m; fill 30 to 80%; each with its mechanism and the failure it provokes |
| 3 | `frob scene hazards office --json` | The glass door row names the optical class `glass`; rows with a Frontier mechanism list a Solid alternative beside it |
| 4 | `frob scene gen kitchen-commercial/galley --seed $S --json`, then `frob scene show <scene> --json` | The manifest's `provenance.dimensions_assumed` is positive and equals the number of distinct assumed dimensions listed among the pack's resolved draws |
| 5 | The same generation again with the same seed, and on the other platform | The same `SceneId` and the same count |
| 6 | A report on a run in that scene with a realism claim (`frob report run <run> --claim representative --json`) | Exit 3, `FROB-REF-312`; the refusal lists the assumed dimensions used; repairs "record a norm or a measurement" and "drop the claim" |
| 7 | The same report without the claim | Exit 0 or 2; the report states that scene dimensions are assumed |
| 8 | A `synthetic` registry in which every dimension is `measured: test-set`, with `test-set` in a test source register; generate, then the claimed report | `dimensions_assumed = 0`; the report is produced |
| 9 | A `synthetic` registry with `provenance = "norm: uncited"` | The registry is refused at load |

Logging. NDJSON to `target/e2e-logs/scene_hazards/<utc-timestamp>.ndjson` with a transcript beside it. Every
line has `ts`, `script`, `bead: "BD-227"`, `step`, `event`, the exact command line, exit code, wall time,
the envelope's `evidence` block (class, tier, determinism, identities, seed; `reality: no-claim`), the row
and provenance counts, the manifest's `dimensions_assumed`, the `SceneId`, the refusal payload for
`FROB-REF-312` (`code`, `pointer`, the list of assumed dimensions, `repairs`), and on failure the first row
or count that differs with the registry path. The `summary` line gives assertions passed and failed. Only
generated scenes are used, so no private-scene data can reach the log.

## Acceptance criteria

- [ ] The script exists, is plain shell, seed-explicit and idempotent, and exits non-zero on any failure.
- [ ] Steps 1 to 9 pass on Linux and on macOS.
- [ ] Step 1's counts are (10, 5, 7, 10, 8, 8, 11) and 59.
- [ ] Step 6 is refused with `FROB-REF-312` and exit 3, and step 7 succeeds.
- [ ] With the planted defect "report path skips the realism check" the script fails at step 6; with "draws
      made through a task file are not counted" it fails at step 4 on a task-driven generation.
- [ ] The log contains the count and the refusal payload, and names no private scene.

## Test plan

### Unit tests

The script is the test. A shell self-test runs step 1 against a registry directory with one row removed and
checks the non-zero exit and the failure line naming the archetype.

### End-to-end script and logging

As above: `scripts/e2e/scene_hazards.sh`, driving `frob scene hazards`, `frob scene gen`, `frob scene show`
and a report verb; logs under `target/e2e-logs/scene_hazards/`.

### Known answers and negative controls

- Counting known answer: 59 hazards in seven archetypes (10, 5, 7, 10, 8, 8, 11), every one `assumed`.
- Row known answers (step 2): wet floor, water film 0.1 to 2 mm; swing door, closing torque 5 to 20 N·m;
  hot liquid in a pot or tray, fill 30 to 80%.
- Negative controls: the two planted defects of the acceptance list; the uncited norm of step 9.
- Determinism lanes: `SceneId`, registry digests and counts identical twice, with debug and release
  binaries, on Linux and macOS.

## Considerations

- The script depends on verbs that land in the same milestone from other beads; a missing verb is logged as
  `skip` with its name and is never counted as a pass.
- The claim flag's spelling belongs to the report verb; the script asserts the behaviour (a claim of
  representativeness is refused while the count is non-zero), not the spelling.
- When cited norms are recorded for some rows, step 1's "every dimension assumed" assertion is replaced by
  the recorded counts by provenance; the refusal step stays as long as any assumed dimension is drawn.
