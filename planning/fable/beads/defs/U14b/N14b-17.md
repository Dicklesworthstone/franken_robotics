## Background

Preflight stage 8 of `design.check` searches for two admitted worlds with the same observation transcript and
disjoint safe actions. The search is a pairwise comparison, so it needs a finite set of worlds. A task, however,
usually admits a continuum: a friction coefficient in a range, a doorway width in a range, a payload mass in a
range. The plan leaves open how such a task declares the finite family the stage searches:

- **OPEN-SKEL-3.** How a task with continuous world parameters declares the finite family stage 8 searches.
  Default: the task's own randomization grid, with the grid recorded in the witness. Owner: Arena lead. Decide
  before stage 8 is funded.

The question matters because the family determines what a result means. A witness found on a grid is a true
statement about two worlds of that grid. A pass on a grid is only "no alias found on this grid": an alias
between grid points is missed. If the family is declared carelessly, stage 8 either refuses real missions on
artefacts of quantization or reassures agents about missions it never examined.

## Scope

In: the decision, with its options, the criteria, the fail-closed default that holds until it is made, and the
changes to the task schema and the witness record that follow; the family's accessor and its index order; the
`sim.run` input `--family-world <i>` (VERBS-sim's row names this bead its owner, M3), which runs one world of the
declared family and is how BD-244's hand-built-policy check and N14b-13 run a policy in each world of a witness.
Out: implementing stage 8 (N14b-13), the witness engine (BD-240), and the rest of `sim.run` with `--task`
(N16ap4-01, N16b-25).

## Technical approach

**The fail-closed default (holds until the decision is recorded).** The family is the task's own randomization
grid: for each randomized parameter, the discrete values or the quantization the task's randomization block
already declares for training and evaluation. The grid (parameter names, values, the task's version) is recorded
in every witness and in every stage record. A pass reads "no alias found on the declared grid". A task with a
continuous parameter and no grid makes stage 8 return `undecided` with the reason `family not finite`; it never
samples a grid of its own.

**Options to decide between.**

| Option | What the task declares | What a pass means | Cost | Risk |
|---|---|---|---|---|
| A (default) | Nothing new; the randomization grid is reused | No alias on the training and evaluation grid | Nil in schema; search cost is the grid's size squared in the worst case | The grid was chosen for learning, not for distinguishing worlds; it may be coarse exactly where aliases live |
| B | An explicit `alias_family` block: a list of worlds, or a per-parameter quantization with a stated resolution | No alias on a family the author chose for this purpose | One schema addition; authors must think about it | Authors omit it; then fall back to A or to `undecided` |
| C | Parameter ranges only; the stage refines adaptively around candidate pairs and returns a region statement | No alias in a region, with a certificate, where one can be produced | Needs interval reasoning over transcripts; much larger work | A Frontier mechanism inside a Frontier stage; no pilot exists for it |

**Criteria (to be applied by the Arena lead with the Skeleton lead).**
1. Soundness of a refusal: every option keeps it, because a witness is two concrete worlds.
2. Honesty of a pass: A and B state the grid; C could state a region.
3. Author burden: A none, B small, C none.
4. Search cost against the stage's 10 s default budget.
5. Interaction with qualification: the family must not reveal sealed confirmation worlds; whatever is declared
   is drawn from the task's open specification only.

**Recommendation recorded here for the owner's use (not a decision).** Adopt B with A as its fallback: the task
may declare `alias_family`; if it does not, the randomization grid is used and the stage record carries the
note `family: randomization-grid (default)`. Defer C until stage 8 has survived its kill gate and a pilot for
region statements exists.

**What changes when it is decided.**
- The task schema gains (under B) an optional `alias_family` block; the format registry and the task checker
  are updated in the task-file bead's crate.
- The witness record's `family` field carries the block's digest or the grid's.
- The stage's documentation states what a pass means in the adopted option, in one sentence, verbatim in the
  envelope's `warnings` whenever the default grid was used.
- The planted stage-8 cases declare their families under the adopted option.

**Index order and the run input `--family-world <i>`.** These hold under every option, the default included.
1. Index order (DESIGN: an index must name the same world on every machine and after any reformatting of the
   task file, because witnesses, logs and runs cite worlds by index). For a grid, or a block that quantizes
   parameters: the Cartesian product of the parameters taken in byte order of their names, each parameter's
   values in ascending order, the last parameter varying fastest. For a block that lists worlds: the order of the
   list. World i carries its index, its name (`w<i>`, or the name the block gives it) and its parameter values
   with units; `Task::alias_family()` returns the worlds in this order and its digest covers it.
2. `frob sim run <design> --task <t> --family-world <i> --key <k> …` (VERBS-sim's row): only with `--task`. The
   verb resolves `Task::family_world(i)` (in `frob-spec`) on the admitted task and sets each parameter of the
   family to world i's value before the task's randomization plan is compiled (BD-200), so a parameter of the
   family is fixed in every world of the run and is not drawn, while a randomized parameter outside the family
   keeps the task's own draw by world address. It acts on the task before any environment exists, so it holds on
   every tier that admits `--task`; the wiring sits beside `--task` in
   `crates/frob-verbs/src/verbs/sim_run/referee_task.rs` (N16ap4-01's module).
3. Identity: the input is written into the run manifest as `family_world = { index, name, family_digest,
   values }`, so it enters `RunId`; the envelope's `bound` echoes the family digest and the world's values.
4. Refusals, each `FROB-REF-802` (exit 3) before any world is created, `pointer` `/family_world`: the input
   without `--task`; an index outside [0, size − 1], naming the family's size; a task whose family is
   `NotFinite`, naming its parameters, with the repairs "declare a grid in the task's randomization block" and,
   under option B, "declare an `alias_family` block".

## Acceptance criteria

- [ ] A decision record exists at `docs/adr/ADR-OPEN-SKEL-3.md` (naming the option adopted, the owner, the date
      and the reasons against the others), made before the stage-8 mechanism bead starts.
- [ ] The record states the fail-closed default as the rule that holds under every option (grid reused and
      recorded; `family not finite` when a continuous parameter has neither a grid nor a declared family; no
      self-chosen sampling). The stage's behaviour under it is implemented and tested by N14b-13, which depends on
      this bead; this bead implements the task side.
- [ ] The task crate exposes the family: `Task::alias_family()` in `frob-spec` returns `Finite { source: grid |
      block, worlds, digest }` (worlds in index order) or `NotFinite { parameters }`, and `frob task check --json`
      reports it as `alias_family: {source, size, digest}` or `alias_family: {not_finite: [...]}`. Under option B
      the optional `alias_family` block is in the task schema, the format registry and the task checker.
- [ ] After the decision, the task schema, the witness record's `family` field and the documentation match the
      adopted option, and the planted stage-8 cases (BD-244) are written under it.
- [ ] The decision does not let stage 8 read sealed qualification worlds.
- [ ] `frob sim run <design> --task T --family-world i --key k --json` runs world i of the declared family in the
      index order above, with the family's parameters fixed to its values and recorded as `family_world` in the
      manifest, and answers 802 without `--task`, for an index outside the family and for a task whose family is
      not finite (naming the parameters), as VERBS-sim's row states.

## Test plan

### Unit tests

- `default_family_is_randomization_grid`: a task with μ ∈ {0.3, 0.5, 0.8} and door width ∈ {0.70, 0.80, 0.90} m
  yields `Finite` with source `grid`, 9 worlds in index order, recorded with names and values.
- `continuous_without_grid_is_not_finite`: a task with μ ∈ [0.3, 0.8] and no grid → `NotFinite` naming μ; no
  world is sampled (the stage's `undecided` with `family not finite` is N14b-13's test).
- `family_digest_canonical`: the same grid written with its parameters in another order has the same digest; a
  changed value changes it.
- `alias_family_overrides_grid` (after the decision, if B): an explicit two-world `alias_family` block yields
  `Finite` with source `block` and those two worlds instead of the grid.
- `sealed_worlds_not_readable`: a task whose confirmation worlds are sealed exposes none of them through the
  accessor.
- `family_index_order`: on the grid `door_width` ∈ {0.70, 0.80, 0.90} m, `mu` ∈ {0.3, 0.5, 0.8}: world 0 is
  (0.70 m, 0.3), world 1 (0.70 m, 0.5), world 5 (0.80 m, 0.8), world 8 (0.90 m, 0.8); the same grid written with
  `mu` first, or with the values in another order, gives the same worlds at the same indices.
- `family_world_fixes_parameters`: `Task::family_world(5)` on that task sets `door_width` 0.80 m and `mu` 0.8; the
  compiled randomization plan draws neither, and a third randomized parameter outside the family takes the same
  value at a given world address as it does without the input.
- `family_world_refusals`: index 9 → 802 naming the size 9; the continuous task → 802 naming `mu`; the input
  without `--task` → 802; in each case no world is created.

### End-to-end script and logging

`scripts/e2e/skel_stage8_family.sh`: `frob task check --json` on three small tasks (a gridded one, a continuous
one with no grid, and one with an explicit family once the option exists). Asserts the family's source, size and
digest, and `not_finite` with the parameter named for the continuous one. Then the run input, on the archetype
design the three tasks are written for (`frob design new af-cart --template diff-drive --key af-des-<run-id>
--json`, settled for the gridded task with `frob task settle <gridded> --model <ModelId> --key af-settle-<run-id>
--json`; the fixture tasks have a 0.1 s horizon): `frob sim run af-cart --task <gridded> --family-world 5 --tier
referee --seed 1 --key af-fw5-<run-id> --json` exits 0 with `family_world.index = 5`, `door_width` 0.80 m and
`mu` 0.8 in the manifest; the same with `--family-world 4 --key af-fw4-<run-id>` gives another `RunId`;
`--family-world 9` exits 3 with 802 naming the size 9; `--family-world 0` with the continuous task exits 3 with
802 naming `mu`; `--family-world 0` without `--task` exits 3 with 802. The stage-8 rows on the same three
tasks (`frob design check --task T --scene S --stages 8 --json`: the `undecided` reason and the pass wording) are
added to this script by N14b-13 once stage 8 exists. NDJSON per step (STD-E2E): command, exit code, wall time,
`evidence`, the family's description, source and digest, and on failure the first differing field. Declared
plant (`E2E_PLANT_FAILURE`): `sample-continuous` (an accessor that samples 100 worlds from the range), which the
continuous-task step must catch. Summary: assertions passed and failed.

### Known answers and negative controls

- A grid of 3 × 3 values has 9 worlds and 36 unordered pairs.
- Negative control: an accessor that silently samples 100 random worlds from a continuous range must fail the
  `continuous_without_grid_is_not_finite` test.
- Negative control (specified here, run by N14b-13's `pass_message_names_family` once stage 8 exists): a coarse
  grid that misses a planted alias between grid points must produce a pass whose
  message names the grid; the test asserts the wording, because the wording is the only protection the default
  offers.

## Considerations

- This is an owner decision: the Arena lead decides, because the family is part of what a task is. The Skeleton
  lead is consulted because the preflight's meaning depends on it.
- The default is safe against false refusals and weak against false reassurance. That asymmetry is acceptable
  only because the pass message says so.
- If KILL-SKEL-ALIAS fires, this decision still matters for the witness engine's explicit queries and should
  not be dropped.
- Priority is one step above the milestone's default because the stage-8 mechanism waits on it.
