## Background

`frob-io` imports URDF and MJCF and exports them. Neither direction is lossless: URDF has no power bus, no
sensor clocks, no fills and no contact law in the sense of this project, and this project's design term has no
place for a vendor plugin. A converter that silently drops what it cannot map produces a plausible wrong robot,
which is the failure this chapter is organized against. The rule is therefore: **every import produces a loss
report**, and export produces the same report in reverse.

The gate that holds the rule: each reference robot imports with forward-kinematics parity against the oracle
within 10⁻⁹ m and 10⁻⁹ rad over 10⁴ configurations, and its loss report lists every dropped field found by a
field-coverage diff. The second clause is the important one for this bead. A loss report written by the
importer's author lists what the author thought of. A field-coverage diff is independent of that: it enumerates
every field of the source and asks, for each, whether the importer consumed it or reported it. RISK-13
(reference-robot imports hide lossy contact mappings) names its leading indicator as exactly this: a field
missing from a loss report in the field-coverage diff.

The second rule: **round trips compare meaning, not bytes**: forward kinematics, mass properties and the map of
identifiers. Byte comparison is the wrong test because import followed by export legitimately reorders,
renames and re-expresses; and it is too weak a test because two files can match where both are wrong.

## Scope

In: the loss-report schema and writer used by every importer and exporter; the field-coverage diff; the
`--strict` refusal (FROB-REF-122); the meaning comparator. Out: the importers and exporters that fill the report
(BD-065 URDF import; BD-066 MJCF import and both exports); folding and reduced models, which add entry classes
(N14b-33, N14b-34); fixtures and oracle captures (BD-067); the end-to-end gate run (N14b-24).

## Technical approach

**Schema `frob.lossreport/1` (DESIGN), canonical JSON.**

```
{ "schema": "frob.lossreport/1", "direction": "import" | "export",
  "source": { "format": "urdf" | "mjcf" | "fbot", "hash": "b3:…", "file": "…", "expanded_by": "…" | null },
  "target": { "format": "…", "design": "d:…" | null },
  "entries": [ { "class": "…", "source_path": "…", "file": "…", "line": 212, "col": 5,
                 "target_path": "…" | null, "detail": "…", "severity": "info" | "high",
                 "value": { "x-frob-untrusted": "…" } } ],
  "coverage": { "source_fields": 1834, "consumed": 1790, "reported": 44, "unaccounted": 0 },
  "counts": { "<class>": n, … }, "identifier_map": [ ["source name", "design identifier"], … ] }
```

**Entry classes.** Import: `dropped` (a field with no place in the design); `default-filled` (a value the source
left out and the importer wrote, with the value); `no-exact-equivalent` (a contact or solver parameter mapped
approximately, or not at all, with what was done; an imported contact law is labelled parity-only);
`repair-proposed` (an inertia that fails physical consistency, with the offending pivot and the nearest
consistent matrix; nothing is changed); `assumed-card` (an actuator limit absent and filled from a card marked
`assumed`); `unsupported` (an element outside the documented subset, echoed with file and line);
`not-checked` (the mass-support bound where the source states no mass Region); `folded` and `omitted` (added by
the fold and reduced-model beads). Export, in reverse: closed loops; transmissions and couplings; sensor latency
and clocks; contact laws; the power bus; fills (the export writes explicit inertials); levers; budgets; symmetry
assertions; controller assumptions. Each of these has no full equivalent in URDF or MJCF and is listed once per
occurrence with its design path.

**The field-coverage diff.**
1. The reader gives every element and attribute of the source a node with a position. For export the "source"
   is the design term and the nodes are its fields.
2. The mapper reads the source only through accessors that mark a node `consumed`.
3. After mapping, every node is in exactly one of three sets: consumed, reported (some entry's `source_path`
   names it or an ancestor whose whole subtree the entry covers), or unaccounted.
4. `coverage.unaccounted` must be zero. A non-zero value is an importer defect, not a fault of the input, so it
   is not a 1xx refusal: the verb aborts as an integrity fault (exit 9, failure class integrity, §32.4; DESIGN),
   raised as the internal fault `FROB-REF-990` of N32a-03 (a defect of the engine, `retry: never`, the one code
   outside every verb's list), commits no design, and its envelope's refusal carries the kind
   `importer-coverage-defect` and names the first unaccounted node with its file and line. It is never
   downgraded to a warning.
5. The diff is computed by code that shares nothing with the mapper except the node tree, so that a mapper that
   forgets a field cannot also forget to report it.

**`--strict`.** With `--strict`, any `unsupported` or `dropped` entry turns the import into the refusal
FROB-REF-122 (an unsupported element in an import under `--strict`), whose payload carries the entries and the
repair "remove or map the element; or import without `--strict` and read the report".

**The meaning comparator (`frob_io::roundtrip`).**

```rust
pub struct MeaningDiff { fk_max_pos_m: f64, fk_max_rot_rad: f64, worst_config: Option<ConfigId>,
                         mass: Vec<MassDelta>, identifiers: IdentifierDiff }
pub fn compare(a: &RobotModel, b: &RobotModel, map: &IdentifierMap, cfg: &CompareConfig) -> MeaningDiff;
```

1. *Identifiers.* The map must be a bijection between the retained names of the two models; a name with no
   partner is listed.
2. *Forward kinematics.* N configurations (10⁴ for the gate) drawn inside joint limits by addressed streams,
   always including the reference pose and each joint at each of its limits. For each mapped frame, compare
   `world_from_frame`: position difference in metres; rotation difference as the angle of the relative rotation
   in radians. Thresholds 10⁻⁹ m and 10⁻⁹ rad (TARGET).
3. *Mass properties.* Per mapped body, or per folded group where a fold or a reduction applies: total mass,
   first moment and the 4×4 pseudo-inertia (second moment, first moment and mass in one matrix), compared
   exactly where both sides are rational and to 10⁻¹² relative in double precision otherwise.
4. *Named attachments.* Sensor frames, collision shapes, contact sites and port frames resolve to the same world
   pose at the sampled configurations.
5. The result names the worst configuration and frame so that a failure reproduces.

**Where the report goes.** It is an artifact in the artifact store; `design.import` and `design.export` return
its identifier and counts in their envelopes. Imported strings appear only inside fields marked
`x-frob-untrusted`.

## Acceptance criteria

- [ ] The report writer, the node-tree interface and the test helper `frob_io::loss::assert_complete(report,
      tree)` exist; the importers and the exporter (BD-065, BD-066, N14a-25, each of which depends on this bead)
      call the helper in their own tests, which is how every import and export in the workspace comes to write a
      validating `frob.lossreport/1` with `coverage.unaccounted` equal to zero.
- [ ] A planted importer defect on a synthetic URDF-shaped node tree with source positions (a mapper that
      ignores `mimic`) is caught by the diff, which names the node, its file and its line, and the verb-level
      outcome is the integrity fault of step 4 (`FROB-REF-990`, exit 9, no design committed).
- [ ] `--strict` turns a report with one `unsupported` (or `dropped`) entry into FROB-REF-122 with the entries in
      its payload, and leaves a report with none unchanged.
- [ ] The ten reverse classes are in the schema's class enumeration, and a test mapper that reports each of the
      ten features of one design term (a closure, a coupling, a sensor clock, a contact law, a power bus, a
      shell fill, a lever, a budget, a symmetry assertion and a controller assumption) produces one entry per
      class and zero unaccounted; the exporter (N14a-25) is tested against the same design term.
- [ ] The comparator reports zero difference for a model against itself and the planted difference for each
      mutant below, on models built directly through `frob-model` (BD-061). The 10⁻⁹ m and 10⁻⁹ rad thresholds on
      an import-export-import round trip of the reference fixtures are measured by N14b-24 (GATE-SKEL-01).
- [ ] The schema has a format-registry row and a round-trip test of its own.

## Test plan

### Unit tests

- `coverage_partition`: on a 20-node synthetic source (labelled `synthetic`), consumed + reported + unaccounted
  equals 20.
- `diff_catches_silent_drop`: on a tree containing `<mimic joint="j1" multiplier="2" offset="0.1"/>`, a mapper
  that skips `mimic` → `unaccounted = 4` (the element and its three attributes, each a node), first node the
  element at its line and column.
- `strict_refuses_122`; `non_strict_reports`.
- `export_classes_listed`: the ten reverse classes each appear once; a mapper that omits the controller
  assumption leaves one unaccounted node and fails.
- `repair_proposed_not_applied`: principal moments (1, 1, 3) kg·m² are unchanged in the design and present in the
  entry with a proposed matrix.
- `comparator_identity`: every delta is zero.
- `comparator_detects_axis_flip`: one revolute axis negated (limits −1.2 to 0.8 rad) → the relative rotation of
  its child frame at configuration q has angle 2·|q|, so the worst configuration is the limit −1.2 rad with
  2.4 rad, and it is named; the reference pose alone (q = 0) shows no difference, which is why the limits are
  sampled.
- `comparator_detects_mass_shift`: one body's centre of mass moved 1 mm → first-moment delta m·0.001 kg·m.
- `comparator_limits_sampled`: each joint appears at both limits among the configurations.
- `untrusted_values_marked`.

### End-to-end script and logging

Exercised through the binary by `scripts/e2e/skel_import_export.sh` (N14b-24, which runs once the importers
exist): `frob design import`, `frob artifact read <report>`, `frob design export`, re-import, and the comparator
through the conformance tool. This bead supplies the assertions on the report (validity, zero unaccounted, class
counts) and on the comparator's output that script uses. Before then, the bead's own integration test
`crates/frob-io/tests/lossreport_e2e.rs` runs the synthetic tree, the planted `mimic` mapper, the `--strict`
conversion, the ten-class export report and the comparator mutants end to end through the public API, and
writes STD-E2E NDJSON lines to `target/e2e-logs/lossreport/<utc>.ndjson`: case, coverage numbers (source,
consumed, reported, unaccounted), class counts, the refusal or integrity outcome, the maximum position and
rotation differences with their thresholds, and on failure the worst configuration and frame and the first
unaccounted node with file and line.

### Known answers and negative controls

- KA-290: forward-kinematics parity within 10⁻⁹ m and 10⁻⁹ rad over 10⁴ configurations, and a loss report that
  lists every dropped field found by a field-coverage diff. The appendix states no negative control; registered
  here: the silent-drop mapper, and a comparator that samples only the reference pose (it misses an axis flip
  that leaves the reference pose unchanged).
- A report-level control: a report whose entries are deleted after mapping must fail the diff.
- Metamorphic: reordering sibling elements in the source changes neither the entry set nor the coverage
  numbers; importing the export of an import yields the same design meaning as the first import.

## Considerations

- Structural-chapter cross-check: mass, centre of mass and inertia must agree within 10⁻⁶ relative among the
  model the evidence used, the mass file of a build packet, values recomputed from geometry exports, and the
  URDF and MJCF exports. The comparator is the tool for the last pair.
- The diff makes the importer honest about fields; it cannot make it right about semantics. A consumed field
  that is mis-mapped is caught by the kinematic and mass comparison, or not at all; that is why the gate has both
  clauses.
- A loss report can be long. It is paginated like every long answer and never truncated silently.
- Text in a report is hostile input: length-capped, stripped of control characters and confined to marked
  fields.
