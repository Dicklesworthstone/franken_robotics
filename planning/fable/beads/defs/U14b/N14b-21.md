## Background

Export in `frob-io` has two purposes. URDF and MJCF export lets a design be used elsewhere, with a loss report
for everything those formats cannot carry. The third export is for looking at a robot: glTF, in its binary GLB
container, for the viewer, for stills and for anything else that only needs to draw the body. The plan states
how it is done: glTF export for visuals goes through FrankenSim's GLB exporter (FACT: `fs-geom` exports GLB).
The reason is the workspace rule that no third-party parser or writer enters the core, and that a sibling which
already owns a capability is consumed through the airlock crate (`frob-fsim`) instead of being rewritten.

A design keeps three geometries apart: the mass Region (all of a body's mass lies inside it), the collision
proxy, and the visual mesh. The exported GLB is a presentation asset. Physics, sensors and stills that count as
evidence read the collision geometry, never the visual mesh; the visual can be replaced without changing a
digest. The export therefore makes no physical claim and must say so.

## Scope

In: the GLB writer in `frob-io` (`crates/frob-io/src/export/glb.rs`) and its admission through the airlock;
`design.export --format glb`; the `--visuals glb` path of a URDF or MJCF export, which writes the GLB files those
exports refer to and returns their hashes; the scene-graph mapping from a compiled model to GLB nodes; the loss
report for this direction; determinism and identity of the output; the export rule that refuses a research-only
or private visual asset.

Out: the verb `design.export` itself, the URDF and MJCF writers and their reverse loss report (N14a-25, a
dependency: this bead adds one format and one option to that verb; BD-066 integrates export with import); the
loss-report schema (N14b-20); the viewer; any import of GLB as a mass or collision source (meshes enter a design
by content hash through the body's `region` or `visual` fields, which is the design language's work).

## Technical approach

1. **Admission first.** The exporter is reached through the airlock's `geometry` feature group. Admission is
   never inherited: this bead's first step is the admission test of the GLB export path at the current pin
   (export a unit cube; read it back with the sibling's reader; compare vertex positions bit for bit and the
   bounding box exactly), recorded as an admission row. If admission fails, the interim posture is: no GLB
   export; `design.export --format glb` (and `--visuals glb`) returns the capability refusal `FROB-REF-724`
   (exit 5), and an upstream work item is
   opened in the sibling's repository under its rules.
2. **What is exported.** For each body of the compiled model, in topological order: one node named by the
   body's instance identifier (for example `leg.fl.thigh`), with the transform `parent_from_body` at the
   reference configuration; its visual mesh if the design has one, otherwise a tessellation of its collision
   proxy at a stated chord tolerance (default 0.5 mm; recorded). Joint frames are exported as empty child nodes
   named `<joint>.frame`, so that a viewer can animate the tree from a telemetry stream. Sensor mounts and port
   frames are exported as named empties when `--frames` is given.
3. **Units and axes.** Metres; right-handed with z up in the project, converted once, at this boundary, to
   glTF's y-up convention by a fixed matrix that the report records. No scale factors on nodes.
4. **Materials.** One flat material per design material card (a colour from the card if present, else a
   deterministic colour from the card's hash). No textures unless the visual mesh carries them.
5. **Loss report (reverse).** `frob.lossreport/1` with direction `export`: joints, limits, inertias, fills,
   actuators, transmissions, sensors, contact laws, the power bus, levers, budgets and symmetry assertions are
   not carried by the file and are listed once each as classes with counts. The report also records the
   tessellation tolerance and which bodies were tessellated from collision proxies.
6. **Identity.** The output bytes are a pure function of the model, the options and the exporter's version. The
   envelope returns the file's BLAKE3 hash, the exporter's pin and the admission record's identifier.
7. **The verb.** `frob design export <design> --format glb [--frames] [--chord <length>] [--out <dir>] --json`,
   kind `read`: a third value of `--format` on the verb that N14a-25 registers; `--out` is the directory under
   the session's export root that N14a-25's row defines (a path outside the roots is `FROB-REF-734`, exit 5), and
   the written file's path and hash are returned in the output. As a verb that exports an
   artifact, its envelope carries the three no-authorization flags, all `false`. Evidence: no claim; class
   `Tested`; tier `static`.
8. **Visuals of the text formats.** `frob design export <design> --format urdf|mjcf --visuals glb` calls the same
   writer once per body with a visual, writes the files beside the exported text, and returns each file's hash
   in the verb's output; the URDF `visual/mesh` and MJCF `asset/mesh` elements name those files. Until this bead
   lands that option returns `FROB-REF-724` (exit 5, N14a-25's row), which this bead removes.
9. **Licences of visual assets.** A GLB that embeds a mesh leaves the machine as an export, so the export rule of
   the safety chapter applies, with the codes of its division (the division DESIGNed with the scene chapter and
   checked end to end by NEGp1-51): FROB-REF-310 belongs to the pack export check of scene packs only; every
   other export, a design export included, is decided at the one export door (N37-18, M3) from the licence join
   over lineage (N37-17, M3): FROB-REF-731 (exit 5) for a private mark, checked first, then FROB-REF-733 (exit 5)
   when the licence set forbids the export (`research-only`, `proprietary` or `unknown`, the last being the most
   restrictive). At M2, before the door exists, the GLB writer applies the same rule to the licence entry carried
   by each visual mesh (a mesh imported with a reference robot carries that robot's entry, NEG-15; a mesh with no
   entry is `unknown`), refuses with FROB-REF-733 naming the mesh's content hash and its entry, and writes
   nothing; 731 cannot arise before the private root (BD-305, M3). When N37-18 lands, this verb is routed through
   the door and the writer's own check is removed, so that one site decides every export.

## Acceptance criteria

- [ ] The admission row for the GLB export path exists at the pin in use, or the verb returns the capability
      refusal and the upstream work item is on file.
- [ ] Exporting the `quad-mammal` archetype yields a GLB whose node count equals bodies plus joint frames, whose
      node names equal the instance identifiers, and whose bounding box equals the collision geometry's at the
      reference pose within the chord tolerance.
- [ ] The file's hash is identical across two runs, across debug and release, and on Linux and macOS.
- [ ] The reverse loss report lists every class of information the file does not carry, with zero unaccounted
      design fields.
- [ ] No code path reads an exported or imported visual mesh into a mass, collision or sensor computation.
- [ ] The envelope carries the no-authorization flags; the verb is in the registry with its schema.
- [ ] `--format urdf --visuals glb` and `--format mjcf --visuals glb` write one GLB per body with a visual, the
      exported text refers to each by name, and the output lists their hashes; a visual asset whose licence entry
      is `research-only` (or a mesh with no entry, `unknown`) is refused with FROB-REF-733 (exit 5), naming the
      asset and its licence entry, and no file is written; FROB-REF-310 is never raised by this verb (it is the
      pack check's); the private case (FROB-REF-731, exit 5, at the door) is exercised from M3 by NEGp1-51.

## Test plan

### Unit tests

- `glb_cube_roundtrip` (the admission test): a 1 m cube → 8 distinct positions, 12 triangles, bounding box
  [−0.5, 0.5]³ exactly.
- `axis_conversion_fixed`: the point (1, 2, 3) in the project's frame maps to (1, 3, −2) in glTF's.
- `node_names_are_instance_identifiers`.
- `tessellation_tolerance_respected`: a sphere of radius 22 mm at 0.5 mm chord: every vertex at radius 22 mm
  within round-off, and the maximum sagitta at most 0.5 mm.
- `no_visual_falls_back_to_collision`.
- `reverse_loss_report_complete`.
- `visual_never_enters_physics`: swapping the visual mesh of a body leaves `ModelId` and every compile product
  unchanged.
- `restricted_visual_refused_733`: a body whose visual mesh's licence entry is `research-only`, and one whose
  mesh has no entry (`unknown`) → FROB-REF-733, exit 5, naming the asset; nothing written to `--out`; a mesh
  whose entry is `attribution` is written and its notice listed.
- `export_never_raises_310`: the refusal above carries code 733, never 310 (the mutant that reuses the pack
  check's code fails).
- `visuals_option_names_files`: `--format urdf --visuals glb` on a two-body design with visuals writes two GLB
  files, and each URDF `visual/mesh` element names one of them by the hash-derived file name.

### End-to-end script and logging

`scripts/e2e/skel_export_glb.sh`, sourcing the STD-E2E helper and writing
`target/e2e-logs/skel_export_glb/<utc>.ndjson` with a transcript beside it: `frob design new quad-glb --template
quad-mammal --key glb-new-1 --json`, `frob design export quad-glb --format glb --out DIR --json` twice (the path
read from each envelope), a comparison of the two files' hashes, and a read-back through the sibling's reader
(the helper `scripts/e2e/tools/glb_readback`, written by this bead over the airlock's reader, the same path as
`glb_cube_roundtrip`) to count nodes and compute the bounding box; then `frob design export --format
urdf --visuals glb` and `--format mjcf --visuals glb` on a design with visual meshes (asserting one GLB per body
with a visual, each named in the text and its hash listed), and the negative step (`e2e_expect_caught`) on
`fixtures/skel/restricted-visual.fbot` (a visual mesh whose entry is `research-only`), which must refuse with
FROB-REF-733, exit 5, and write nothing. NDJSON per step:
command, exit code, wall time, `evidence` (including the three no-authorization flags), `ModelId`, the file
hash, node and triangle counts, the bounding box against the expected one with the tolerance, the exporter's
pin and admission record, and the first differing value on failure. Declared plant (`E2E_PLANT_FAILURE`):
`double-axis-conversion`, which the bounding-box step must catch. Summary: assertions passed and failed.

### Known answers and negative controls

- The cube: 8 vertices, 12 triangles, exact bounding box. The axis map: (x, y, z) → (x, z, −y).
- Negative controls: an export that applies the axis conversion twice (the bounding box's extents are permuted);
  an export that names nodes by index (the name test fails); a build in which the model reads the visual mesh
  for inertia (the swap test changes `ModelId`).
- Metamorphic: exporting a mirrored design gives a file whose bounding box is the mirror image.

## Considerations

- The exporter is a sibling's code at a pin; a change of pin re-runs admission. The output hash is expected to
  change with the pin, which is why the pin is part of the recorded identity.
- Licence: a visual mesh with a restrictive licence must not be exported into a file that leaves the machine;
  the export checks the mesh's licence entry and refuses to embed a research-only, proprietary, unknown or
  private asset, with the door's codes (733; 731 from M3), so that a user meets one code per situation on every
  export verb.
- Size: tessellating collision proxies is cheap; large visual meshes are passed through, under the importer
  limits on polygon count.
- The file is for eyes. A report or a comparison never cites it as evidence.
