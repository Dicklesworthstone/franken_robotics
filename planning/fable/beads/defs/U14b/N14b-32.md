## Background

Capability tables and the composed quasi-static screen are reached by an agent through two verbs:
`module.characterize`, which builds a module's table, and `design.check`, whose stage 6 composes tables for an
assembly and returns an exclusion with a certificate, an admission with a witness, or nothing new. Their first
gate is a Known-answer claim due at M3 (GATE-SKEL-09): the two stance cases and the trot counterexample exactly;
inner ⊆ outer on 10⁴ random directions per archetype module; an edit inside one module re-characterizes one
table and no other.

This bead is the script that runs those three clauses through the real binary, and the bead under which the
gate is entered. Unit
tests in the crates cover the mathematics; the script covers what only the outside can show: that the verb
returns a job handle or a result correctly, that the memo graph serves the untouched tables, that the
certificate leaves the process and is accepted by the independent auditor, and that the envelope carries the
verdict's type and the load-sharing model.

## Scope

In: `scripts/e2e/skel_capability_screen.sh`; the gate's tier test `GATE-SKEL-09` in `g1_known_answers`; and
the entry of GATE-SKEL-09 (one part, M3) through the gate recorder. Out: the tables, the fixture module `leg-1r`,
the inner-in-outer checker `capability_check` and the script `scripts/e2e/module_characterize.sh` (N14b-28); the
screen, the fixture designs `centred` and `shifted`, the task fixtures `trot-stance` and `froude-0.8` and the
script `scripts/e2e/skel_composed_screen.sh` (N14b-29); the 200-assembly experiment (N14b-30).

## Technical approach

**Fixtures.** N14b-28's `leg-1r` and N14b-29's four-leg designs and task fixtures, in
`tests/fixtures/capability/four-leg/` (all `synthetic`), and the modules of every archetype available at M3
(BD-246, a dependency).

**Steps.**

1. *Stage: the tables.* Run `scripts/e2e/module_characterize.sh` (N14b-28) as a stage, with this run's seed:
   the one-joint leg's 40 N down and 0 N up, the key replay, `--strict-data` (113), the digest mismatch (114)
   and cancellation. Its summary is read and its failures fail this script.
2. *Stage: the screen.* Run `scripts/e2e/skel_composed_screen.sh` (N14b-29) as a stage: the centred `inner`
   witness (39.24 N per foot), the shifted `outer` exclusion (`FROB-REF-124`, the certificate accepted by
   `frob prove verify` and by `frob-verify`, the corrupted copy rejected), the trot exclusion beside the
   four-foot admission, `unresolved` with `outside-validity` at a Froude number of 0.8, and the screen's timing.
3. *Inner in outer.* For each module of each archetype available: `frob module characterize <module> --key
   cap-<run>-<module> --json`, then `cargo run -p frob-analyze --example capability_check -- --table <id>
   --directions 10000 --seed <s>` (N14b-28's checker), which draws 10⁴ random directions per pose cell from the
   recorded seed and asserts that the inner support never exceeds the outer support.
4. *Edit locality.* On a four-leg archetype: characterize all leg modules (four memo misses or one, by content);
   `frob design edit <id> set-param <leg path>.<field> <value> --expected-parent <DesignId> --key
   loc-<run>-set --json` inside one leg; run `frob design check <new id> --stages 6 --json`; assert from the
   envelope's memo record that exactly one table was re-characterized and the others were hits with unchanged
   digests. Repeat with `regear` and `swap-actuator` (keys `loc-<run>-regear`, `loc-<run>-swap`, each against
   the version the previous edit returned).
5. *Timing.* Record the wall time of one characterization of each archetype leg module against the stated
   seconds.
6. *The two routes.* Run the gate's tier run, `e2e_tier g1_known_answers GATE-SKEL-09 --mutations`; assert from
   its receipt that the three forces, the directions tested with zero violations and the tables re-characterized
   per edit equal this script's values, and that controls (a) to (c) are `caught`; log the receipt's hash.

## Acceptance criteria

- [ ] The script measures the three clauses of GATE-SKEL-09 (TARGET): the three stance results exact; inner ⊆
      outer with zero violations over 10⁴ directions per archetype module; one table re-characterized per
      in-module edit and no other.
- [ ] The gate is entered through the gate recorder (N38b-19) from the receipt of its tier run,
      `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g1_known_answers --features
      gauntlet-mutations -- GATE-SKEL-09` (a Known-answer gate; the test drives the same fixtures, modules and
      seed and catches controls (a) to (c) in the same run), by `cargo run -p frob-conformance --example
      record_gate -- --gate GATE-SKEL-09 --receipt <hash>`, from a session that implemented neither the tables
      nor the screen. Status `pass` only with all three clauses met; the measured values are the three forces,
      the directions tested with the violations found, and the tables re-characterized per edit. This script's
      log is the evidence the receipt cites, and the script itself writes no gate row.
- [ ] The certificate of the shifted case is accepted by the offline auditor on its own, and the corrupted copy
      is rejected.
- [ ] The trot result and the four-foot result coexist for the same assembly, each bound to its stance.
- [ ] The script exits non-zero on any failed assertion, is idempotent and seed-explicit, and its controls are
      caught on every run.

## Test plan

### Unit tests

For N14b-28's `capability_check` as this script uses it: `inner_point_outside_outer_detected` (a synthetic
table with one inner vertex moved 1% outward is reported); `seed_reproducible`. For the script's helpers:
`memo_record_parser` (hits and misses are counted from the envelope, not inferred from timing);
`stage_summary_read` (a stage script whose summary has one failed assertion fails this script and names it);
`routes_compared` (a receipt whose re-characterization count differs from the script's fails step 6 and names
the edit).

### End-to-end script and logging

`scripts/e2e/skel_capability_screen.sh`, sourcing the shared helper of STD-E2E and writing
`target/e2e-logs/skel_capability_screen/<utc-timestamp>.ndjson` with a transcript beside it. Every line has
`ts`, `script`, `bead: "N14b-32"`, `step`, `event`, the exact command, exit code, wall time, the envelope's
`evidence` (claim `known-answer`, class, tier `static`, determinism, `ModelId`, table identifiers, seed for the
direction draws), the verdict and its type, the load-sharing model, forces in newtons against their expected
values, the certificate identifier and the auditor's result, memo hits and misses, directions tested and
violations, and timings against their targets. On failure: the first differing value, the cell and direction or
the foot, and the paths of the table, the envelope and the bundle. The final `summary` line gives assertions
passed and failed, controls caught and `gates: ["GATE-SKEL-09"]`.

### Known answers and negative controls

- Four identical one-joint legs, each a horizontal link of 0.25 m with a torque limit of 10 N·m, can each press
  with at most 40 N. Under a 16 kg body (156.96 N) on a square stance with feet at (±0.2, ±0.2) m: centred,
  39.24 N per foot, admitted; centre of mass 0.05 m forward, the front pair must carry 0.625 × 156.96 = 98.1 N
  > 2 × 40 N, excluded for every force distribution, the certificate being the vertical force balance plus the
  pitch moment balance; in a trot two diagonal feet carry 78.48 N each against 40 N.
- Controls run every time: (a) a build flag that makes the screen ignore the stance set must admit the trot case
  (the script must then fail); (b) a table with one outer row tightened by 5% must violate inner ⊆ outer; (c) a
  memo key without the module hash must show zero re-characterizations after an edit (the locality assertion
  must fail).
- Determinism lanes: table digests and verdicts equal twice on one machine, in debug and release; cross-platform
  digests compared and the result recorded with the determinism class the table claims.

## Considerations

- The gate is entered by a session that did not implement the tables or the screen; the recorder refuses
  `self-certified`, and it refuses a pass whose controls were not caught in the same run.
- The fixtures are synthetic by design: the known answers need round numbers. The inner-in-outer and locality
  clauses run on real archetype modules.
- If the screen is later restricted by its kill gate, the shifted and trot cases of the screen stage change their
  expected exit from a refusal to a finding labelled `suspended: prune-soundness`; N14b-29's script reads the
  screen's configuration (`exclusion_refuses`, set from the decision record) and asserts accordingly.
