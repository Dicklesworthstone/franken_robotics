## Background

The design chapter ships eighteen archetypes, designs with parameters listed by `design.templates`. The first
is `quad-mammal`: a dog-like quadruped with three joints per leg, twelve actuated coordinates. That name is
used by the archetype table, the reference-robot table, the known answers on symmetry, the gate for baseline
controllers and the worked artifacts (`"family": "template:quad-mammal@1"`).

The surface chapter's worked studio session, the transcript that the generated agent documentation reproduces
and that the fresh-agent test follows, begins:

```
$ frob design new quad-a --template quadruped-12dof --json     # exit 0, design d:41aa…
$ frob design check quad-a --json                              # exit 2: knee undersized (A-11)
$ frob design edit quad-a swap-actuator --joints '*.knee' --to qdd-l   # new version, symmetry preserved
$ frob design check quad-a --json                              # exit 0: closes at 15.1 kg
```

(the transcript's numbers are illustrative). No archetype is called `quadruped-12dof`. The archetype bead
(BD-109) registers `quad-mammal`; the script bead for the session (N32b-15) and the documentation bead
(BD-313) use the session's name and need "the archetype template `quadruped-12dof` and an actuator card small
enough that the knee's continuous torque demand in crouch exceeds it". As drafted, the first command of the
project's own tutorial fails with an unknown template.

The two names mean one thing, and the session also needs something the bare archetype does not promise: a
starting design whose first `check` finds an undersized knee. DESIGN: `quad-mammal` stays the one canonical
name; `quadruped-12dof` becomes a registered **alias** that resolves to `quad-mammal` with a named **preset**
(`studio`) whose knee actuators are the medium generic class. Rejected alternatives: renaming the archetype
(five chapters and the worked artifacts use `quad-mammal`); editing the session to say `quad-mammal` and
dropping the other name (an agent that has read the transcript will type it; and the undersized-knee start
would still need a home); a nineteenth archetype (the catalogue is eighteen, and this is the same body).

## Scope

In: the alias table and its rules; the preset `studio` of `quad-mammal`; alias resolution in `design.new` and
its echo; aliases in `design.templates`; a lint against dead or shadowing aliases; the fixture that pins the
session's first four steps. Out: the archetype itself and the catalogue verb (BD-109); the verb `design.new`
(N14a-21); the session script and the documentation (N32b-15, BD-313); the actuator catalogue (BD-069); the
envelope analysis A-11 and the closure A-10 (BD-103); the verbs `design.check` (runner and verb N28ap1-01,
with the analyses assembled by BD-110, which depends on it) and `design.edit` with
its `swap-actuator` edit (BD-058), which the session's steps 1 to 3 call and which are therefore dependencies.

## Technical approach

1. **Alias table (DESIGN).** `assets/archetypes/aliases.toml`, loaded with the catalogue:

   ```toml
   [[alias]]
   name = "quadruped-12dof"
   template = "quad-mammal"
   preset = "studio"
   reason = "the worked studio session of the surface chapter"
   ```

   Rules, checked at build time: an alias name is not a canonical archetype name and not a variant name; alias
   names are unique; an alias points at a canonical name (no chains); its preset exists; every alias has a
   `reason` and is referenced by at least one test or generated document (a dead alias fails the lint).
2. **Resolution.** `design.new --template <name>` looks up canonical names first, then aliases. With an alias
   it instantiates the target with the alias's preset; explicit `--set` parameters still apply on top. The
   envelope's result carries `template: "quad-mammal"`, `preset: "studio"`, `alias_used: "quadruped-12dof"`,
   and the design's recorded family is `template:quad-mammal@1`, so identities, lineage and every downstream
   table see the canonical name only. Two calls, one with the alias and one with
   `--template quad-mammal --preset studio`, produce the same `DesignId`.
3. **Unknown names.** A name that is neither canonical nor an alias is refused as `design.new` already refuses
   an unknown template (bead N14a-21), with the nearest canonical names and aliases offered as repairs; this
   bead adds aliases to the suggestion list and no new code.
4. **`design.templates`.** Each entry gains `aliases: [{ name, preset, reason }]` (output schema
   `frob.design.templates.out/1`, additive). `design.templates --name quadruped-12dof` returns the
   `quad-mammal` entry with the alias marked.
5. **The preset `studio`.** The archetype's default parameters with every knee actuator bound to the generic
   class `qdd-m` (medium quasi-direct-drive) and hips and abductors as the archetype's default. Its defining
   property is behavioural and is what the tests pin: at the crouch operating point the envelope analysis
   A-11 reports the knee's continuous torque demand above the continuous rating of `qdd-m` (a finding, exit
   code 2, with the ranked repair `swap-actuator` to `qdd-l` first), and after that swap `design check`
   passes and the co-design closure reports a closing mass. If, with the catalogue's cards as built, the knee
   on `qdd-m` is not undersized, the preset's knee belt ratio is lowered inside the archetype's declared
   bounds until the property holds, once, and the value is frozen in the preset with a note (the preset
   exists to start a tutorial at a finding; it is not a recommended design). The transcript's figures
   (15.1 kg and the others) are illustrative and are not asserted; the measured closing mass is recorded as
   the preset's golden value when the archetype lands.
6. **Layout.** `crates/frob-design/src/templates/alias.rs`; the preset in
   `assets/archetypes/quad-mammal/presets/studio.toml`; fixtures under `fixtures/design/templates/`.

## Acceptance criteria

- [ ] `frob design new quad-a --template quadruped-12dof --key d1 --json` exits 0; the result names
      `quad-mammal`, the preset and the alias; the family is `template:quad-mammal@1`.
- [ ] The same design created with `--template quad-mammal --preset studio` has the same `DesignId`.
- [ ] `frob design check quad-a --json` exits 2 with an A-11 finding on the knees whose first repair is
      `swap-actuator` to `qdd-l`; after `frob design edit quad-a swap-actuator --joints '*.knee' --to qdd-l
      --key d2 --json` (symmetry preserved; `design.edit` refuses a call without `--key` with FROB-REF-805,
      BD-058) it exits 0 and reports the closing mass.
- [ ] `frob design templates --json` lists eighteen entries, with the alias under `quad-mammal`;
      `--name quadruped-12dof` returns that entry.
- [ ] `--template quadruped-12` (a typo) is refused with `quadruped-12dof` and `quad-mammal` among the
      suggestions.
- [ ] The lint rejects: an alias named `humanoid`; an alias of an alias; an alias with an unknown preset; an
      alias no test or document references.
- [ ] N32b-15's steps 0 to 3 and BD-313's first transcript run against this alias unchanged.

## Test plan

### Unit tests

`crates/frob-design/tests/template_alias.rs`; `cargo test -p frob-design template_alias`.
- `alias_resolves_to_canonical_with_preset`; `alias_and_explicit_preset_same_design_id`.
- `canonical_name_wins`: a planted alias equal to a canonical name fails the build-time check.
- `no_alias_chains`; `unknown_preset_rejected`; `dead_alias_rejected`.
- `templates_lists_alias`; `suggestions_include_aliases`.
- `studio_preset_knee_undersized`: A-11 utilization above 1 on each knee with `qdd-m` at the crouch point,
  at most 1 with `qdd-l`; hips and abductors at most 1 in both.
- `swap_preserves_symmetry`: Γ_mech is C₂ × C₂ before and after the swap on all four knees.
- `set_overrides_apply_after_preset`.

### End-to-end script and logging

`scripts/e2e/design_template_alias.sh` (sources the STD-E2E helper; NDJSON to
`target/e2e-logs/design_template_alias/<utc>.ndjson` with a transcript): the four commands of the session's
opening with an idempotency key; `frob --json design templates`; the typo; the explicit-preset twin. Lines
carry `ts`, `script`, `bead`, `step`, `event`, command, exit code, wall time, the evidence block (claim,
class, tier `static`, determinism, identities); `assert` lines for exit codes 0, 2, 0, 0; `metric` lines for
the knee utilization before and after the swap and for the closing mass with its unit; the two `DesignId`s
(equal); `refusal` line for the typo with its suggestions; on failure the first differing field of the
result with the command that produced it. Declared plants (`E2E_PLANT_FAILURE`): `alias-bare-archetype` (the
alias ignores its preset; the first `check` exits 0 and the exit-2 assertion must catch it) and
`alias-family-name` (the family recorded as `template:quadruped-12dof@1`; the family assertion must catch it).
`summary`: assertions passed and failed, plants caught; `gates: []`.

### Known answers and negative controls

Known answers: Γ_mech of `quad-mammal` as built is C₂ × C₂ (the archetype table), preserved by a swap applied
to all knees and broken if applied to one leg (the control: swapping one knee only is reported as symmetry
broken). The verdict sequence 0, 2, 0 of the session's opening. Negative controls: an alias that instantiates
the bare archetype (the first `check` passes and the tutorial's first finding never appears); an alias that
records its own name as the family (the lineage and the worked artifacts would then disagree); a shadowing
alias. Determinism: D0; identical `DesignId` twice, in debug and release, on both host platforms.

## Considerations

- Aliases are a convenience for names that already circulate. The lint against dead aliases and the rule
  that identities carry only canonical names keep them from becoming a second catalogue.
- The preset is a deliberately flawed starting point. Its manifest says so, and benchmark or corpus designs
  must not be instantiated from it.
- If the surface chapter's transcript is later amended to use `quad-mammal --preset studio`, the alias stays
  for one release with a deprecation note in `design.templates`, then is removed with its tests.
