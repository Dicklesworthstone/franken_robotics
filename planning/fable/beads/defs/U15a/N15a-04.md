## Background

An actuator can be modelled at several depths, and a result is only meaningful with the depth named. Sinew therefore
has a ladder of five levels. Each level is a Component with shaft, electrical and thermal ports (N15a-01), and the
level is part of `ModelId`, the content identity of a compiled model: two runs of the same design at different
levels are runs of different models and can never be confused in a comparison, a memo lookup or a replay.

| Level | Contents | Tier |
|---|---|---|
| L0 | Ideal torque source. Used only by mathematical tests. | Solid |
| L1 | Torque–speed envelope from the bus: i ≤ min(I_max, (V_lim − k_e·N·ω)/R); output torque η·N·k_t·i minus friction; reflected inertia N²·J_rotor added to the joint; first-order delay; position–velocity loop at the driver rate. Friction enters as the stiction row. V_lim is the bus voltage for a DC machine and the modulation limit for a three-phase machine. | Solid |
| L2 | Winding current dynamics; resistance and flux as functions of winding temperature; a two-node thermal network with torque derating; the voltage limit in the dq plane with field weakening; bus voltage from the two-RC battery; state of charge. | Solid |
| L3 | The rotor as its own coordinate, with backlash rows (Solid); series elasticity as an added degree of freedom and cable and belt compliance (Frontier). | Solid / Frontier |
| L4 | Hydraulic actuation. | Moonshot |

Symbols: i winding current; I_max current limit; V_lim voltage limit; k_e back-EMF constant; k_t torque constant;
N gear ratio (ω_motor = N·ω_joint); ω joint speed; R winding resistance; η transmission efficiency; J_rotor rotor
inertia.

Two options sit beside the ladder and are also part of `ModelId`: battery ageing between episodes (Frontier), and a
rotor port for flight, a lumped element with thrust c_T·ρ·A·(Ω·r)² (thrust coefficient c_T, air density ρ, disc
area A, rotor speed Ω, tip radius r) and a reaction torque about its axis (Moonshot, off the critical path, used
only by the aerial–terrestrial hybrid variant of the archetype catalog).

DESIGN: L1 is the default for training. Reasons: the sim-to-real literature says armature, joint friction and delay
are the minimum that transfers; and reflected inertia also conditions the contact solve, because N²·J_rotor adds to
the diagonal of the matrix A of the convex contact problem (v = argmin ½·(v − v*)ᵀ·A·(v − v*) + Σ ℓ_c(J_c·v)).
Rejected as default: L0 (precise about the wrong thing), L2 (its thermal and electrical states cost kernel time
that most training runs do not need; it is selected when an envelope or thermal claim is made).

## Scope

In: the `ActuatorLevel` type and the two options; their encoding in `ModelId`; the level-by-tier capability table
and FROB-REF-136; the default level per use; the L1 screening flag. Out: the implementation of each level (seeds
BD-070 for L0 and L1, BD-071 for L2, both owned by the other Sinew unit; N15a-09 for the rotor coordinate of L3;
N15a-19 and N15a-21 for the Frontier and Moonshot levels; seed BD-419 for the rotor port; battery ageing with its
kill gate KILL-SINEW-AGE in the other unit).

## Technical approach

1. **Types (DESIGN sketch).**
   ```rust
   pub enum ActuatorLevel { L0Ideal, L1Envelope, L2Electrothermal, L3Rotor { compliance: bool }, L4Hydraulic }
   pub struct LadderOptions { pub battery_ageing: bool, pub rotor_port: bool }
   pub struct ActuationModel { pub level: ActuatorLevel, pub options: LadderOptions }   // hashed into ModelId
   ```
   The level is chosen per model (one level for all actuated joints of a model at M1; per-joint levels are a later
   extension that would only add entries to the same hashed structure).
2. **Identity.** `ActuationModel` is serialized canonically into the model's content; `ModelId` changes when the
   level or an option changes. A test asserts that the five levels and four option combinations give distinct
   identities for one design and that nothing else about the model changes.
3. **Defaults.** Training and sweeps: L1. `actuator.envelope` and `actuator.thermal` evaluate the L2 laws
   statically whatever the simulation level (the static thermal check uses the temperature-dependent law at every
   level). Mathematical tests: L0 on request only; a run at L0 carries the flag `ideal-actuators` and its results
   cannot be cited for a design comparison.
4. **Capability table.** A row option is a feature of the joint rows or of the level that a tier may or may not
   carry. The table is data (`ladder::CAPABILITY`), printed by `actuator.show --capabilities`:

   | Option | `referee` | `batch-cpu` strict | `batch-cpu` lockstep | `gpu-*` |
   |---|---|---|---|---|
   | L0, L1, L2 | yes | yes | yes | yes |
   | Stiction, set-valued (ε = 0) | yes | yes (located events) | no (convex, ε > 0) | no (convex, ε > 0) |
   | Backlash, hard with restitution | yes | yes | no (compliant) | no (compliant) |
   | Exact voltage hexagon | yes | no (inscribed circle) | no (inscribed circle) | no (inscribed circle) |
   | Gaussian Stribeck shape | yes | yes | card-selectable; rational is the default | rational only unless the kernel class admits an exponential |
   | L3 compliance, L4, rotor port, ageing | only after their pilots and kill-gate decisions | same | same | same |

   Rows marked DESIGN where the plan gives the rule in prose (the referee solves the set-valued law with ε = 0 and
   hard backlash with the card's restitution; the convex tiers are compliant; the batched tiers use the inscribed
   circle and the rational shape).
5. **FROB-REF-136.** "A row option the requested tier does not carry." Raised when a request names an option and a
   tier whose cell is "no", for example hard backlash on `gpu-cuda`. Returned with the refusal: the tiers that
   carry it. Ranked repairs: run on a listed tier; accept the tier's regularized form (which sets a flag on the
   result); change the card option. Exit code 3, `retry: after-change`. A request never silently falls back.
6. **The L1 screen.** L1 neglects the reactive voltage drop ω_e·L_q·i_q (ω_e electrical speed, L_q q-axis
   inductance). A card on which L_q·I_max exceeds one tenth of the flux linkage λ is flagged
   `l1-reactive-drop-not-negligible` (DESIGN: a screening threshold), and envelope claims for it require L2: an
   `actuator.envelope` request at L1 semantics for such a card, or a comparison whose verdict cites an L1 envelope,
   is answered with the L2 envelope and the flag, and a run at L1 on such a card marks its speed-saturation
   findings `Estimated: L1 screen`.

## Acceptance criteria

- [ ] For one design, the five levels and the option combinations produce pairwise distinct `ModelId`s, and the
      level is recoverable from a result's evidence block.
- [ ] Requesting hard backlash on a GPU tier refuses with FROB-REF-136 and lists `referee` and `batch-cpu` strict.
- [ ] The capability table printed by the verb equals the table compiled into the crate (one source).
- [ ] The illustrative card with λ = 0.010 V·s, L = 100 µH, I_max = 40 A has L·I_max = 0.004 V·s, which exceeds
      λ/10 = 0.001 V·s: the card is flagged, and an L1 envelope claim for it is answered at L2 with the flag.
- [ ] A card with L·I_max = 0.0009 V·s is not flagged.
- [ ] A run at L0 carries `ideal-actuators`, and a design comparison citing it is refused by the claim product.
- [ ] The rows of GATE-SINEW-01 are measured on the level they belong to (stall torque and no-load speed at L1;
      time constants and thermal rise at L2), with the level printed beside each measured value.

## Test plan

### Unit tests
- `level_in_model_id`: distinct identities as above; equal identities for equal `ActuationModel`.
- `capability_refusal`: each "no" cell of the table refuses with FROB-REF-136 and returns exactly the tiers whose
  cell is "yes" for that option.
- `l1_screen_threshold`: the two cards of the acceptance criteria; the boundary L·I_max = λ/10 exactly is not
  flagged (the rule is "exceeds").
- `l1_default_for_training`: a training request with no level resolves to L1 and records the default in the
  envelope's `bound` field.
- `l0_flag`: an L0 run's evidence carries `ideal-actuators`.

### End-to-end script and logging
`scripts/e2e/sinew_referee_dynamics.sh` (N15a-24) runs one fixture at L0, L1 and L2 and asserts three distinct
`ModelId`s; `scripts/e2e/sinew_cards.sh` (N15a-25) requests the capability table. Logged per step: the level, the
`ModelId`, the flag set, the refusal code and the tiers returned with it.

### Known answers and negative controls
The L1 formulas give the known answers that GATE-SINEW-01 measures at 1%: stall torque η·N·k_t·min(I_max, V_lim/R)
(KA-329) and no-load speed V_lim/(k_e·N) (KA-330). CX-139: a torque–speed envelope without the voltage ellipse is
wrong above base speed (at 1.5 times base speed the illustrative card delivers 59% of peak torque with field
weakening and none without it); the L1 screen is the rule that keeps an L1 claim from being made there. Negative
controls: a level left out of the identity hash (two levels collide; the identity test fails); a capability table
that silently falls back (the refusal test fails); a screen with the threshold at λ instead of λ/10 (the flagged
card passes unflagged).

## Considerations

- KILL-SINEW-ROTOR (trigger: the hover known answer or the port balance fails, or the hybrid variant has no
  consumer when frontier physics is funded, M6; fallback: the rotor port and the variant are withdrawn) and
  KILL-SINEW-AGE (trigger: the ageing law fails its pilot, or no card with ageing coefficients better than
  `assumed` exists when lifecycle work is funded; fallback: capacity fade and resistance growth are user-set
  constants) remove option values from `LadderOptions`; the type keeps the variants so that old identities stay
  readable.
- KILL-SINEW-ROWS (N15a-13) changes the stiction cells of the two lockstep columns to "regularized force, flagged".
- The table is the single place a new tier or option is registered; a tier added without a column fails a test.
