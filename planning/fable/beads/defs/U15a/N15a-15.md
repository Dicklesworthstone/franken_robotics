## Background

Thermal time constants are minutes and episodes are seconds. In 20 s from cold at 20 A the winding of the worked
card (R₀ = 0.20 Ω, α = 0.00393 K⁻¹, G = 0.80 W/K, C = 120 J/K) rises by 164.7·(1 − e^(−20/247)) = 12.8 K, against
an equilibrium rise of 164.7 K. A policy trained and evaluated on episodes that start at ambient never meets
derating, and a design whose actuators would overheat in ten minutes of real work looks fine in every episode
(counterexample CX-138: "episodes that start at ambient temperature test the thermal limits of a design" is false).

ADR-SINEW-08 decides: thermal state starts from a duty history, not from ambient. Reason: an episode that starts
cold never meets the limit that decides the design. Thermal state is therefore initialized from a declared duty
history: `cold`, `soaked(T)`, or `steady(task)`, the equilibrium for the task's mean loss from the closed form.
Evaluation defaults to `steady(task)`; training draws from the three.

Rejected: simulating the warm-up (minutes of simulated time per episode for a state that a closed form gives
exactly); a fixed warm temperature for all designs (it would be wrong for every design but one and would hide which
designs run hot).

## Scope

In: the `ThermalStart` type and its three values; computing `steady(task)` per actuator from the task's mean loss;
the default per use; the training mixture drawn by address; recording the resolved start in the episode; identity
and refusals. Out: the closed forms (N15a-14); the thermal model (N15a-06, seed BD-071, BD-072); the task-file
field and the reset path that carry the declaration (other subsystems, named in `needs`).

## Technical approach

1. **Type (DESIGN sketch).**
   ```rust
   pub enum ThermalStart { Cold, Soaked(Qty<Kelvin>), Steady(DutyRef) }
   pub struct DutyRef { pub task: TaskId, pub source: DutySource }   // which mean loss was used
   pub enum DutySource { ReferenceRun(RunId), NominalGait(AnalysisId) }
   pub struct ThermalInit { pub t_winding: Qty<Kelvin>, pub t_housing: Qty<Kelvin>, pub derate_band: u8 }
   ```
2. **`cold`.** Every node at the scene's ambient temperature.
3. **`soaked(T)`.** Every node of every actuator at T (a robot that has been standing in a hot room or has just
   finished a shift). T must lie between ambient and the lowest `t_max` of the model; otherwise the request is
   refused as out of range (FROB-REF-132, since the declared start is already above a limit).
4. **`steady(task)`.** For each actuator: take the mean copper loss of the task as a root-mean-square current
   I_rms, and other mean losses assigned to its nodes, from the duty source; compute the equilibrium of the
   temperature-dependent law with N15a-14 (one node: T = T_amb + P_amb/(G − s) with s = I_rms²·R₀·α; two nodes:
   the 2×2 solve); initialize the nodes there. The duty source is, in order of preference: a recorded reference
   run of this design on this task (mean losses read from its energy ledger); otherwise the nominal-gait
   operating points of analysis A-11. The source's identity is stored, so the start is a pure function of
   (`ModelId`, `TaskId`, source identity) and replays exactly.
5. **When no steady state exists.** If s ≥ G, or the equilibrium exceeds a limit, the design cannot sustain the
   task: `steady(task)` refuses with FROB-REF-132, returning the equilibrium or the margin to the tangency and the
   largest sustainable load. An evaluation never silently substitutes `cold`.
6. **Defaults.** Evaluation (`eval.run`, comparisons, qualification): `steady(task)`. Training: a mixture over the
   three declared in the task; DESIGN default where a task declares none: equal thirds, with the `soaked`
   temperature drawn uniformly between ambient and the `steady(task)` temperature. Draws are by world address
   (the same address gives the same start in any batch). Mathematical known-answer tests declare `cold`
   explicitly.
7. **Recording and identity.** The declaration is part of the task's content (so two evaluations with different
   starts are different tasks to the comparison machinery); the resolved `ThermalInit` per actuator is stored with
   each episode's resolved randomization values, so a failure replays and can be attributed. Derating state at
   t = 0 follows from the initial temperature: an episode may begin inside a derating band.
8. **Batched tiers.** The initial temperatures are per-world parameters written at reset; no kernel change.

## Acceptance criteria

- [ ] Worked card, I_rms = 18 A: `steady(task)` initializes the winding at a rise of 64.8/(0.80 − 0.2547) =
      118.8 K above a 25 °C ambient (143.8 °C), within 0.5%.
- [ ] Worked card, I_rms = 20 A: `steady(task)` refuses with FROB-REF-132 (equilibrium 190 °C above the 155 °C
      limit) and returns 18.6 A as the largest sustainable current.
- [ ] An evaluation request with no thermal start resolves to `steady(task)` and records the duty source; a
      training request draws all three values across 10³ addresses with the declared weights (within binomial
      bounds) and the same value for a repeated address.
- [ ] The planted case: a design whose knee runs at I_rms = 18 A (3% inside its 18.6 A rating) completes a 20 s
      episode from `cold` with no thermal event; from `steady(task)` it starts at 143.8 °C, inside the 0.6
      derating band, and a derating event is recorded at the first step, so the torque shortfall is met inside
      the episode.
- [ ] The resolved start is in the episode record, and replay from the record reproduces the temperatures bit for
      bit.
- [ ] `soaked(T)` above a limit is refused.

## Test plan

### Unit tests
- `steady_matches_closed_form`: the 18 A row; and the two-node variant against the 2×2 solve.
- `steady_refuses_without_equilibrium`: 20 A (above the limit) and 35 A (no equilibrium; growth rate
  0.00136 s⁻¹ reported).
- `cold_rise_in_20s_ka312`: stepping the model for 20 s at 20 A from `cold` gives a rise of 12.8 K within 1%.
- `default_for_evaluation`, `training_mixture_by_address`, `same_address_same_start`.
- `initial_band_from_temperature`: a start at 143.8 °C with bands (120 °C, 1.0), (140 °C, 0.6), (155 °C, 0)
  begins in the 0.6 band.
- `start_changes_task_identity`: the same task with `cold` and with `steady(task)` has two identities.
- `replay_reproduces_start`: bit-identical node temperatures from the stored record.

### End-to-end script and logging
`scripts/e2e/sinew_referee_dynamics.sh` (N15a-24) runs the undersized-knee fixture twice through `frob eval run`
(or `frob sim run` with the start flag at M1): once with `--thermal-start cold`, once with the default. It asserts
no thermal event in the first and a derating event at the first step of the second, and that the default run's
envelope names `steady(task)` and its duty source; a third run of a design at I_rms = 20 A asserts the
FROB-REF-132 refusal of the default start. Logged: the declared and resolved start per actuator with temperatures
in kelvin, the duty source identity, the first derating event time, failure class, digests, seed.

### Known answers and negative controls
KA-312 (20 s from cold at 20 A: rise 12.8 K; control: an evaluation that starts every episode at ambient and so
never meets derating). KA-304 (the equilibrium used by `steady`). CX-138. Negative controls: an evaluator whose
default is `cold` (the planted case passes and the test fails); `steady(task)` computed with the
constant-resistance law (118.8 K becomes 81.0 K; the 20 A case is admitted at 125 °C); a silent fallback to `cold`
when no equilibrium exists. Metamorphic relation: raising ambient by ΔT raises a `steady` start by more than ΔT
when T₀ is fixed (P_amb grows with ambient). Determinism: starts are a pure function of identities and addresses
and are compared exactly across runs, batch sizes and platforms.

## Considerations

- `steady(task)` assumes the task repeats long enough to reach equilibrium; for a task that is a single short
  burst after rest the honest declaration is `cold` or `soaked`, and the task author says which. The default errs
  toward the case that decides the design.
- The duty source from a reference run is circular for a design that fails the task; the nominal-gait source of
  the analysis crate breaks the circle and is always available.
- The counterfactual debugger refuses mid-episode interventions on design parameters partly because actuator
  thermal state depends on the whole history; this bead is what makes that state explicit at tick 0.
