## Background

Every numeric input to a model lives on a card (`.fcard`, schema `frob.card/1`, canonical JSON, identity
`CardId` = BLAKE3 of the canonical bytes), and every field carries a provenance and an uncertainty. The
calibration chapter writes the result of identification back as **a new card version**: "every identified
field gets provenance `measured`, the dataset hash, the cell and its marginal uncertainty. The card also stores
the joint covariance of the identified fields", because armature and friction estimates are correlated and
randomization that samples the marginals independently is wider than the evidence in some directions and
narrower in others. It adds that one robot calibrates one robot: a per-unit posterior describes that unit, and
a class card carries a class mean and a unit-to-unit spread.

The beads that write those versions (N30a-27 for a unit version, N30a-30 for class cards) put five things on
a card that the card schema (BD-069) does not know: a block `[covariance]`, a `delay_set` on an identified
delay, a top-level `parent`, the provenance class `measured-class`, and per-field hierarchical values
(`class_mean`, `class_mean_sd`, `unit_spread`, `spread_dof`, `units_measured`). The container refuses unknown
fields (FROB-REF-103), so as specified a measured version could not be loaded, and `actuator.show` would have
nothing to print.

Why at M1 although the writers land at M5 (DESIGN): the schema's own rule is that "an unknown field is a form
error, so each name is known to the schema from M1", which is how it already admits the Frontier and Moonshot
groups read by later beads. A reader that learned these names only at M5 would make two incompatible readers
under one schema version. Adding optional names changes no existing `CardId`. Rejected alternative: a schema
bump to `frob.card/2` at M5 (every stored card reference and every model identity bound to a card would then
need a migration for a change that touches no existing card).

## Scope

In: the schema, typing, validation and canonical form of the five additions; the reader API for them; what
`actuator.show` and `actuator.check` do with them; the rule that status is not a card field; fixtures.

Out: producing the numbers (identification, floors, shrinkage: N30a-27, N30a-30, BD-391); admission of a
candidate version and the frozen-prediction rule (the calibration beads); correlated sampling and the lint
against independent sampling of a card with a covariance block (the randomization compiler, BD-200, with
N30a-27); revalidation of results bound to the old identity.

## Technical approach

**1. `parent`** (top level): `"parent": "b3:<hash>"`, the `CardId` of the version this one was derived from.
Absent on a root card. It is part of the canonical bytes, so two versions with the same field values and
different parents are different cards. Rule: with `parent` present, `revision` ≥ 2; the reader does not
require the parent to be present in the store (a card must be loadable alone), and `actuator.show` prints the
chain as far as the store has it, marking a missing ancestor `not in store`.

**2. `covariance`** (top level block):

```json
"covariance": { "fields": ["friction.coulomb", "friction.viscous", "j_rotor"],
                "lower": ["4.0e-4", "1.2e-5", "1.0e-6", "0", "0", "9.0e-12"] }
```

`fields` are paths of fields of this card, sorted ascending (the canonical order; a writer sorts, and a
permutation of the same data yields the same bytes). `lower` is the lower triangle row by row, as decimal
strings in the product of the fields' card units. Validation at load:
- every path exists, appears once, and its field has provenance `measured` or `measured-class`;
- the triangle has n·(n + 1)/2 entries;
- each diagonal entry equals the square of that field's stated standard deviation (`unc` of kind `normal`),
  to 10⁻⁹ relative; a field in the block must use `normal`;
- the matrix is positive semidefinite by the same rule the writer uses: smallest eigenvalue at least −10⁻¹²
  times the largest;
- a field carrying `delay_set` is not in the block.
A violation is a form error (FROB-REF-103 with the pointer `covariance.<what>`); the card is not loaded.
Reader API: `card.covariance() -> Option<CovBlock>` with `correlation()` (ρᵢⱼ = cᵢⱼ/√(cᵢᵢ·cⱼⱼ)).

**3. `delay_set`** (inside a time-valued field such as the driver `latency`): the set of grid delays inside
the 95% likelihood-ratio bound of an identified delay: `"delay_set": {"step": "0.001 s", "members": [3, 4, 5]}`
(integers are multiples of `step`). Rules: members strictly increasing, the field's `value` is a member, and
the field's `unc` is `interval` with ends equal to the smallest and largest member times `step`. A delay is
discrete, which is why it is not in the covariance block.

**4. Provenance class `measured-class`**: `{"class": "measured-class", "units": [...], "versions": [...],
"cells": [...]}`, with at least one unit; `versions` are `CardId`s of the unit versions pooled. The existing
`measured` class keeps its required dataset hash and calibration cell; an optional `"origin": "synthetic"`
beside the dataset hash marks a rehearsal dataset, and such a field counts as guessed in the share of guessed
fields that reports print.

**5. Hierarchical fields** (inside a field of provenance `measured-class`): `class_mean`, `class_mean_sd`,
`unit_spread` (the unit-to-unit standard deviation), `spread_dof`, `units_measured`. Rules: `unit_spread` ≥ 0
and `class_mean_sd` ≥ 0 in the field's unit; `units_measured` ≥ 1; `spread_dof` = `units_measured` − 1;
`value` = `class_mean`; and the field's `unc` is `normal` with σ² = `unit_spread`² + `class_mean_sd`² (the
predictive distribution of a unit not yet measured), to 10⁻⁹ relative. A covariance block on a class card is
the between-unit covariance and obeys item 2.

**6. Unit scope.** `card::scope(&Card) -> Option<UnitScope { unit, instance }>` is read from the calibration
cell of the measured fields; mixed scopes inside one card are a form error. Refusing to bind a unit version to
another unit or instance is the model compiler's rule; the reader only exposes the scope.

**7. Status is not a card field (DESIGN).** A version is `candidate` until a frozen prediction made with it
has been scored on sealed data and covered; then it is `admitted`. That transition must not change the
`CardId`, so the status lives in the calibration record of the ledger, keyed by `CardId`. `actuator.show`
prints it from the record and prints `unknown (no record)` when the record is absent.

**8. `actuator.show`** (output schema `frob.actuator.show.out/1`, additive fields): for a measured version,
the identified fields with value, σ, dataset hash and cell; the correlation matrix with its field order; the
`delay_set` in seconds; the parent chain; the scope; the status and record identifier; for a class card, per
hierarchical field the class mean with its standard deviation, the unit spread with its degrees of freedom,
the units pooled and the predictive σ. The human-readable form prints the correlation matrix to three decimals
and flags any |ρ| above 0.9.

**9. `actuator.check`** on a card with these additions runs the three standing checks on the card's values
(constants agree; losses nonnegative in four quadrants; ratings reachable) and the validations above; a
measured version that fails a standing check is refused like any card (FROB-REF-130, -131, -132).

**10. Layout.** `crates/frob-actuate/src/card/{covariance.rs, delay_set.rs, lineage.rs, class.rs}`; fixtures
`fixtures/cards/measured/*.fcard`; the format-registry row is unchanged (same extension, same schema name).

## Acceptance criteria

- [ ] A unit version with `parent`, a three-field covariance block and a `delay_set` loads, round-trips
      canonically and has a `CardId` different from its parent's; the generic catalog's `CardId`s are
      unchanged by this bead (golden hashes).
- [ ] The same covariance written with its fields in another order canonicalizes to identical bytes.
- [ ] Correlation: variances 0.04 and 0.01 with covariance 0.012 give ρ = 0.6; `actuator.show` prints it.
- [ ] Refused with FROB-REF-103 and a pointer: covariance 0.03 for the same variances (ρ = 1.5, not
      semidefinite); a diagonal that disagrees with the field's σ (0.05 against σ = 0.2); a path that is not a
      field; a field of provenance `assumed` in the block; a `delay_set` whose members do not contain the
      value; a delay field listed in the block; `spread_dof` ≠ `units_measured` − 1; a predictive σ that is
      not √(`unit_spread`² + `class_mean_sd`²).
- [ ] Class card known answer: `unit_spread`² = 0.0275, `class_mean_sd`² = 0.0125, `units_measured` = 3,
      `spread_dof` = 2: predictive σ = √0.04 = 0.20 is accepted and 0.25 is refused.
- [ ] `actuator.show --json` returns the additive fields; the status comes from the ledger record and the
      card bytes contain no status.
- [ ] A measured field without a dataset hash or cell is refused (the standing rule), and
      `origin: "synthetic"` is printed and counted as guessed.
- [ ] `actuator.check` passes on the fixtures and refuses a measured version whose efficiency is 1.2.

## Test plan

### Unit tests

`crates/frob-actuate/tests/card_measured_blocks.rs`; `cargo test -p frob-actuate card_measured_blocks`.
- `parent_changes_card_id`; `revision_rule_with_parent`.
- `covariance_roundtrip_sorted`: property test over permutations of the field list.
- `correlation_point_six`; `non_psd_refused`; `diagonal_must_match_sigma`; `block_field_must_be_measured`.
- `delay_set_rules`: members [3, 4, 5] at 1 ms with value 4 ms and interval [3 ms, 5 ms] accepted; value 6 ms
  refused.
- `class_fields_consistency`: the 0.0275 and 0.0125 case; `k_equals_one` (`spread_dof` = 0 accepted).
- `scope_read_from_cell`; `mixed_scope_refused`.
- `status_not_in_bytes`: changing the ledger status leaves the `CardId` unchanged.
- `catalog_hashes_unchanged`.
- `synthetic_origin_counts_as_guessed`.

### End-to-end script and logging

`scripts/e2e/sinew_measured_card.sh` (sources the STD-E2E helper; NDJSON to
`target/e2e-logs/sinew_measured_card/<utc>.ndjson` with a transcript): `frob --json actuator show` on the prior
card, the unit version and the class card; `frob --json actuator check` on each; `frob --json actuator list` over
a store holding the three (the unit version and the class card listed under the prior's actuator class, with their
provenance shares; `measured` and `measured-class` counted as such); each invalid fixture. Lines carry `ts`,
`script`, `bead`, `step`, `event`, command, exit code, wall time, the evidence block (claim, class, tier `static`,
determinism, identities); `metric` lines for ρ, the predictive σ and the delay interval against their expected
values; the `CardId` of each card and of its parent; `refusal` lines with code, pointer and first repair; on
failure the first differing canonical line. `summary`: assertions passed and failed; `gates: []`.

### Known answers and negative controls

Known answers: ρ = 0.6; predictive σ = 0.20 from 0.0275 and 0.0125 (the class-card row of the calibration
beads); the delay interval [3 ms, 5 ms]. Negative controls: a reader that accepts ρ = 1.5; a writer that edits
the prior card in place (the content-address test fails); a status written into the card (the `CardId`
changes on admission, caught by `status_not_in_bytes`); a covariance block whose field order follows insertion
order (two byte forms for one card, caught by the permutation test). Determinism: D0; canonical bytes identical
twice, in debug and release, on both host platforms.

## Considerations

- The semidefiniteness tolerance is shared with the writer on purpose: an exact test on rounded decimal
  strings would refuse matrices that are semidefinite before rounding.
- Cross-block covariance between smoothly identified parameters and an ensemble-estimated pair is not stored
  by the writer; the block then understates correlation in some directions, and `actuator.show` prints the
  writer's flag for it.
- Privacy: a calibration cell names a physical unit. Export rules for cards (which provenance details leave
  the machine) belong to the safety chapter and apply to these fields as to every measured field.
- Other card kinds (battery, interface, sensor) use the same container, so their measured versions get these
  blocks without further schema work.
