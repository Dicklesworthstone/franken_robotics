## Background

A robot design in this system is a term: leaves are components (bodies, joints, actuators, transmissions,
batteries, sensors, wheels, feet) and inner nodes are constructors. A **module** is a design subterm with open
ports, parameters and a contract, stored on its own and referenced by content hash, for example
`"std/leg-3r-qdd.fmodule@b3:9a4e…"`. Modules exist so that a leg, an arm or a wheel unit can be reused and
swapped, and so that an edit recomputes only what it touched.

Decision ADR-SKEL-05: modules are referenced by content hash and carry contracts; a substitution reuses
exactly what the contract covers and invalidates the rest by rule. Reason: reuse without a stated boundary is
how a stale certificate survives an edit. Rejected alternative: reuse licensed by a matching hash alone,
because reuse across an edit is licensed by an implication (the contract), not by a hash. Construction C-12
("a robot is a composition over typed ports") supplies the mathematics: components expose typed ports,
interconnection is power-conserving, and a module carries its port signature, its local inertia and passivity
results, and a boundary descriptor. Tier: Solid [S] for the format and the port contract. Crate: `frob-design`
(layer 2). Format registry row `FMT-FMODULE`: extension `.fmodule`, schema `frob.module/1`, canonical, written
by `frob-design`, read by `frob-design` (composition) and `frob-model`.

## Scope

In: the schema and canonical form; port, parameter, body and contract types; the content hash and the
contract digest; the per-module checks (`check_module`); elaboration of a `use` import in a `.fbot`; the
admission-only rule for peak-only bus contracts; the catalog directory. Out: joining ports of a module to the
rest of a design and solving junction causality (N15b-01); the three verbs (N15b-02); `module.substitute` and
the leaf-local reuse table (BD-077); the limb port packet [F] and capability tables [F] (owned by the design
chapter's other beads); extracting a module from a design by a typed edit (`extract-module`, row 23 of the
edit catalogue, N41p2-01, which depends on this bead); format-registry round trips (BD-141); the joint bus
schedule A-23 (BD-108).

## Technical approach

**File.** Canonical JSON under the seven canonical-form rules of the design language (UTF-8, keys sorted by
code point, no insignificant white space, duplicate key refuses; quantities as exact decimal plus unit token
strings such as `"0.21 m"`; coherent SI units; integers above 2⁵³, hashes and rationals as strings; every
field the compiler reads is present; constructors unexpanded). The S-expression view is the same term. The
reference specimen:

```json
{ "schema": "frob.module/1", "name": "leg-3r-qdd",
  "ports": [ {"id": "mount", "kind": "mech",    "frame": "hip_mount", "power": "into-module"},
             {"id": "bus",   "kind": "elec",    "nominal": "22.2 V",  "power": "into-module"},
             {"id": "sink",  "kind": "thermal", "power": "into-module"},
             {"id": "state", "kind": "signal",  "msg": "joint-state/3", "rate": "1000 Hz", "latency_max": "1 ms"},
             {"id": "sole",  "kind": "contact", "law": "foot-patch"} ],
  "params": [ {"id": "thigh", "unit": "m", "default": "0.21 m", "bounds": ["0.15 m", "0.30 m"]},
              {"id": "knee_card", "kind": "card:actuator", "default": "qdd-l"} ],
  "body": { "chain": [ "three links with joints, actuators, a belt transmission of ratio 2.35, and a foot" ] },
  "contract": {
    "guarantees": { "mass": ["1.6 kg", "2.4 kg"], "port_inertia": "sym-psd-6",
                    "bus_demand": {"peak": "38 A", "profile": "per-task, time-resolved"},
                    "heat_to_sink": {"continuous_max": "60 W"} },
    "assumes": { "bus_voltage": ["18 V", "25.2 V"], "sink_conductance_min": "0.4 W/K" },
    "digest": "b3:…" } }
```

The body is the leg of the worked design `quad-tray`: hip and thigh on `qdd-m`, the knee on `qdd-l` behind the
belt of ratio 2.35, a 0.022 m rubber foot; the full text of the specimen is the golden fixture of ART-L2. DESIGN:
the chapter's abridged copy prints `knee_card` with default `qdd-m`, which belongs to the leg of the smaller
design `quad-a` (knee `qdd-m`, belt ratio 1.55); the full worked artifact prints `qdd-l` with ratio 2.35. One
module reference cannot name both, and a default must equal the value it describes in the body (below), so
this bead and ART-L2 use the full artifact's values.

**Ports.** One sign convention: power is positive into the module. Kinds and what each carries:

| Kind | Effort and flow | Notes |
|---|---|---|
| `mech` | Wrench and twist at a named frame | `frame` must name a mount frame of a body in `body` |
| `shaft` | Torque and angular velocity | |
| `elec` | Voltage and current | `nominal` voltage required |
| `thermal` | Temperature and heat rate | |
| `signal` | A typed message with a rate and a latency bound | `msg`, rational `rate` in hertz, `latency_max`; one producer, any number of consumers; carries no power |
| `contact` | Not a port to join: names an end effector that meets the world, with its contact law | Listed because a module's effect on the robot cannot be summarized at its mount port alone |

**Types (DESIGN).**
```rust
pub struct Module { name: Name, ports: Vec<PortDecl>, params: Vec<ParamDecl>, body: Term, contract: Contract }
pub enum PortKind { Mech, Shaft, Elec, Thermal, Signal, Contact }
pub struct PortDecl { id: Ident, kind: PortKind, frame: Option<FrameRef>, nominal: Option<Qty>,
                      msg: Option<MsgType>, rate: Option<RationalHz>, latency_max: Option<Qty>,
                      law: Option<ContactLawName>, power: PowerSign /* only IntoModule is admitted */ }
pub struct ParamDecl { id: Ident, kind: ParamKind /* Quantity{unit, bounds} | Card{family} */,
                       default: Value, path: Option<TermPath> }
pub struct Contract { guarantees: Guarantees, assumes: Assumptions, digest: Blake3 }
pub struct BusDemand { peak: Qty, profile: Option<ProfileRef> }   // None means admission only
```

**Two hashes.** The *module reference* is the BLAKE3 hash of the whole canonical file. The *contract digest*
covers exactly: the port signature (ids, kinds, frames, signs, message types and rates), the parameter
schema, the hash of the body term, the versions of the cards the body names, and the module's local
certificates: inertia consistency of every body over the parameter box (structural for geometry-derived
inertia) and passivity of every element. A stored digest that differs from the recomputed one refuses with
FROB-REF-114.

**`check_module`, in order.**
1. Schema version known (FROB-REF-125 otherwise); canonical form; unknown, misspelt or duplicate field
   refuses (FROB-REF-103).
2. Port ids unique; kind known; kind-specific fields present; `frame` resolves; a contact entry names a law
   compatible with its end effector (FROB-REF-121).
3. Sign convention: `power` must be `into-module`. Any other value is a reversed port sign and refuses with
   FROB-REF-108.
4. Parameters: unit and bounds present; default inside bounds (FROB-REF-111); a card-kind parameter names a
   card of the stated family in the catalog; each parameter binds a target in `body`, and the value at that
   target equals the default (FROB-REF-103; below).
5. Guarantees are recomputed, not trusted: the mass roll-up is evaluated in exact rational arithmetic at the
   default and at every corner of the parameter box, and each value must lie in the stated `mass` range;
   `port_inertia` is the type tag `sym-psd-6` (symmetric positive semidefinite 6 × 6, never claimed
   definite); local certificates are re-run.
6. Digest recomputed and compared (FROB-REF-114).

**Import.** A `.fbot` imports a module with `use`: `module` (the reference), `at` (the port it mounts on),
`bind` (parameter values) and `rename` (identifier renames). Elaboration loads the file by hash, verifies
the hash, runs `check_module`, substitutes bindings (each inside its bounds), applies renames and splices the
body at the mount port. The elaborated subtree's memo key is the subterm hash with the digests of the
modules and cards it names.

**A contract that carries only peaks can admit and cannot exclude.** `bus_demand` without a time-resolved
profile is typed admission-only: `BusDemand::can_exclude()` is false, and no consumer may prune a design by
adding peaks. Worked case: two fingers share a bus limited to one unit of current, each with peak demand one
unit; adding peaks gives two units and would prune the design, yet one finger draws at the first tick and
the other at the second, so the schedule is feasible. For the specimen leg, four legs at 38 A add to 152 A
against a 60 A bus limit, and that sum excludes nothing.

**How a parameter names its target.** OPEN (the specimen writes defaults in place and does not say).
Fail-closed default (DESIGN): a parameter carries a `path` in the grammar a lever of a `.fbot` uses, a JSON
pointer from the root of the module document (as a lever is from the root of the design), so every target
starts with `/body/` (the specimen's `thigh` is `/body/chain/1/body/region/capsule/1`, `knee_card` is
`/body/chain/2/actuator`); a parameter with no resolvable target refuses at step 4. The body writes each
default in place: the value at a parameter's path must equal its `default`, because a module whose body and
default disagree has two readings and two hashes for one meaning (FROB-REF-103 at `params[i].default`, naming
both values). Owner: Skeleton lead.

**Catalog.** `assets/modules/std/*.fmodule`, indexed by name and hash (DESIGN path; archetypes ship in
`assets/archetypes/`).

**Evidence.** A module's local certificates are instance-level exact checks (class Certified where a checker
accepts them, otherwise Tested); guarantees inherit the weakest provenance of the card fields they read.
Determinism class D0 (exact rational arithmetic).

## Acceptance criteria

- [ ] `crates/frob-design/src/module/` implements the types, canonical reader and writer, both hashes,
  `check_module` and `use` elaboration; `CONTRACT.md` of `frob-design` gains the module section in its ten
  parts.
- [ ] A module with a reversed port sign refuses with FROB-REF-108 (seed done-condition; a row of
  GATE-SKEL-06).
- [ ] A module whose stored digest does not match refuses with FROB-REF-114 (seed done-condition), for a
  change to any one of: a port kind, a parameter bound, the body, a named card's version.
- [ ] A contract check that adds peak currents fails the shared-bus fixture (seed done-condition): the
  planted mutant `mutant-contract-sum-peaks` prunes the two-finger design and the test catches it.
- [ ] The specimen `leg-3r-qdd` parses in both views with the same hash and passes `check_module`.
- [ ] JSON → term → JSON and JSON → S-expression → JSON are the identity on canonical forms over 10⁴ random
  modules.
- [ ] `check_module` returns, for every refusal above, the typed payload the verb layer wraps (code, JSON
  pointer, message, ranked repairs as typed edits) and, on success, the evidence fields (class, determinism
  D0, the two hashes); the CLI and MCP surface `frob module check … --json` is N15b-02's, which depends on
  this bead, and its end-to-end script is N15b-33's.

## Test plan

### Unit tests
`crates/frob-design/tests/module_format.rs`, real files, no mocks; generated modules are labelled `synthetic`.
- `specimen_round_trip`: the specimen's canonical bytes hash identically after both round trips.
- `reversed_sign_refuses`: `"power": "out-of-module"` on `bus` gives FROB-REF-108 with pointer `ports[1].power`.
- `digest_mismatch_refuses`: four mutations (port kind, bound, body, card version) each give FROB-REF-114.
- `guarantee_recomputed`: thigh at 0.30 m with a mass range narrowed to ["1.6 kg", "1.7 kg"] refuses because
  a corner mass lies outside.
- `default_out_of_bounds`: default `"0.35 m"` against bounds [0.15, 0.30] m gives FROB-REF-111.
- `default_disagrees_with_body`: `knee_card` default `"qdd-m"` while `/body/chain/2/actuator` is `"qdd-l"`
  gives FROB-REF-103 at `params[1].default`; `param_path_unresolved`: a `path` of `/body/chain/7/actuator`
  refuses at step 4.
- `peak_only_is_admission_only`: a `bus_demand` with no profile returns `can_exclude() == false`.
- `two_finger_bus_not_pruned`: the fixture is admitted; with the mutant feature on it is pruned and the test
  fails.
- `unknown_field_refuses`: a misspelt `"gaurantees"` gives FROB-REF-103.
- `use_binds_and_renames`: a `.fbot` importing the leg four times with distinct renames elaborates to four
  subtrees with distinct identifiers and equal body hashes.
- Property `canonical_idempotent` over 10⁴ random modules.

### End-to-end script and logging
`scripts/e2e/module_verbs.sh` (bead N15b-33) drives `frob module list`, `frob module show` and `frob module
check` on the catalog and on the three refusing fixtures, asserting exit codes 0 and 3 and the refusal
payloads; it logs NDJSON lines with command, exit code, wall time, evidence block and digests to
`target/e2e-logs/module_verbs/<utc-timestamp>.ndjson`.

### Known answers and negative controls
KA-271 (two fingers on a one-unit bus drawing at different ticks: feasible; the peak-adding rule excludes
it), KA-080 (the same fixture stated for C-12: no one-tick schedule, two two-tick schedules, the task is not
pruned). Counterexample CX-128. Negative controls: the peak-summing mutant; a checker that skips step 6 must
be caught by `digest_mismatch_refuses`. Determinism: hashes identical twice on one machine, in debug and
release, and across the two host platforms (class D0).

## Considerations

- A wide-integer or hash field parsed as binary64 by a client would merge two modules; hashes travel as
  strings.
- Imported text (names, descriptions) is data and carries the untrusted mark when echoed.
- Kill gate KILL-SKEL-SUBST (leaf-local reuse differs from a recompile, or saves under 20% of compile time)
  changes what substitution reuses, not this format: the fallback keeps subterm reuse by content hash.
- An unmet contract assumption has no code of its own in the refusal registry; N15b-01 states the fail-closed
  default.
- Line budget: `frob-design` has a scope cap of 18 thousand lines for all its duties.
