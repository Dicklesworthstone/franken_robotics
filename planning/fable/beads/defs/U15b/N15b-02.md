## Background

Every capability reaches agents through verbs that are generated from one registry, `registries/verbs.toml`,
owned by `frob-verbs`: the CLI, the daemon protocol, the MCP tool definitions, the schemas and the agent
guide all come from it, so the surfaces cannot drift. A capability counts as implemented only when it is
reachable through `frob --json` with a documented schema and exit code. The module format (BD-060) and the
port-junction checks (N15b-01) are library code until these three read verbs exist. The fourth module verb,
`module.substitute` (kind `mutate`), belongs to seed bead BD-077.

Registry meanings, fixed by the plan: `module.check` checks a module's ports, parameter schema, local
certificates and contract digest; `module.list` lists the modules in the catalog by content hash;
`module.show` returns a module's ports, parameters, guarantees and assumptions. All three are kind `read`
(they return stored or cheaply computed facts and change nothing), first milestone M1.

## Scope

In: the behaviour behind three registry rows: the contents of the input and output schemas the rows name; the
handlers in `frob-verbs` that call `frob-design`; which condition raises which refusal; the envelope and its
evidence; the measured figure behind the cost-model line.
Out, with the bead that has it: the three registry entries themselves in `registries/verbs.toml` (name, cluster,
kind, tier, capability scope, schema names, refusal list, task cluster, examples, MCP tool names) are written by
the registry bead of the cluster, VERBS-module, on which this bead depends, together with the parity, snapshot
and conformance checks of the cluster; this bead writes no entry and must not leave one that differs. If a
handler here needs a refusal the row does not list, the row is amended in VERBS-module in the same commit. MCP
tool generation for the M1 verbs (BD-138) and the complete M1 schema sweep (BD-137), which consume the entries;
the end-to-end script (N15b-33).

## Technical approach

**The registry rows these handlers serve (entered by VERBS-module; shown as that bead registers them, so that
the handlers can be read against them).**

```toml
[[verb]]
name = "module.check"
cluster = "module"
kind = "read"
tier = "S"
capabilities = ["module:read"]
input_schema = "frob.module.check.in/1"
output_schema = "frob.module.check.out/1"
refusals = ["FROB-REF-101", "FROB-REF-103", "FROB-REF-108", "FROB-REF-111", "FROB-REF-114", "FROB-REF-121", "FROB-REF-125"]
idempotent = true
cost_model = "static: under 100 ms for a limb-sized module"
first_milestone = "M1"
task_clusters = ["modules"]
examples = ["frob module check std/leg-3r-qdd --json"]
owner = "frob-design"
purpose = "Check a module's ports, parameter schema, local certificates and contract digest"
```

The module reference of `module.check` and `module.show` may be a file path, so it is declared in the row's
`params` (N34-24) and the generator appends FROB-REF-891, -734 and -828 to both rows; the module reader raises
the design language's own codes for a version or an unknown field (125, 103), never 891, as N34-REF's rule
for an owner with its own codes says.

`module.list` and `module.show` follow the same shape with their own schema names
(`frob.module.list.in/1`, `frob.module.list.out/1`, `frob.module.show.in/1`, `frob.module.show.out/1`) and
refusal lists (`module.list`: none beyond protocol errors; `module.show`: FROB-REF-114, FROB-REF-125). MCP
tool names are derived by replacing `.` with `_`: `module_list`, `module_show`, `module_check`. No verb has a
second spelling. The capability scope is `module:read` (the registry's rule of one scope family per cluster;
`design:read` is not used for these verbs), and the task cluster is `modules`.

**Which condition raises which refusal (this bead's part of the row's refusal list).** `module.check`: a port
whose kind does not match what it is joined to, or a joint class that disagrees with its screw basis, 101; an
unknown, misspelt or duplicate field in the module file, 103; a reversed power sign, a copied power port or an
algebraic loop, 108; a `--bind` value outside a parameter's bounds, 111; a stored digest or port signature that
does not match the recomputed one, 114, and with `--in-design` an unmet contract assumption, raised by N15b-01's
join check as 114 with `detail = "module-assumption-unmet"` (the interim code of that ledger slug, told apart
from a digest mismatch by the `detail`); a contact port with no contact law or one incompatible with its end
effector, 121; a schema version the reader does not support, 125. `module.show`: 114 when a `name@b3:hash`
reference does not match the file's bytes, 125 for an unsupported schema version. `module.list` raises none of
its own.

**Inputs and outputs.**

| Verb | Input | Result |
|---|---|---|
| `module.list` | Optional name prefix, port-kind filter, page cursor | Rows of `{name, ref (name@b3:hash), port_signature (kind per port id), tier, card_families}`; paginated against a committed frontier, never cut silently |
| `module.show` | A module reference: a name, a `name@b3:hash`, or a file path inside the caller's namespace | Ports with kind and kind-specific fields; parameters with unit, default, bounds; guarantees; assumptions; contract digest; whether `bus_demand` can exclude (false when it has no time-resolved profile) |
| `module.check` | A module reference; optional `--bind id=value` to check at a parameter point; optional `--in-design <design> --at <port>` to also run the junction checks of N15b-01 against that mount (the only way 101 for a join, a copied port, a loop or an unmet assumption can arise here) | `{ports_ok, params_ok, certificates: [{kind, status, evidence_class}], digest: {stored, recomputed, match}, joins: [{port, kind, verdict}] (with `--in-design`), findings[]}`; on failure the envelope's `refusal` with pointer and ranked repairs |

A name without a hash resolves to the catalog entry and the envelope's `bound` field reports the immutable
hash it resolved to. A hash that does not match the file's bytes is FROB-REF-114.

**Envelope.** One `frob.envelope/1` object per call. `evidence` is a claim product: class the weakest among
the module's certificates and the provenance of the card fields its guarantees read (a card field marked
`assumed` makes the result Estimated and names that field as the weakest input); tier `static`; determinism
`exact`; `reality: no-claim`. Exit 0 when clean, 2 with findings, 3 on a refusal.

**Handlers.** `crates/frob-verbs/src/handlers/module.rs` (DESIGN path) parses input against the schema, calls
`frob_design::module::{list, load, check_module}` and N15b-01's join check when `--in-design <design> --at
<port>` is supplied, and builds the envelope. No handler holds state; all three are idempotent and cacheable
by the module hash and the binding.

**Cancellation.** The verbs are short, but they accept the cancellation context like every verb; a cancelled
call returns without partial output.

## Acceptance criteria

- [ ] The three entries in `registries/verbs.toml` are the ones VERBS-module entered, unchanged by this bead
  (scope `module:read`, task cluster `modules`, the refusal lists above); `frob schema
  frob.module.check.out/1` prints the schema with a minimal example.
- [ ] `frob module list --json` returns every file in `assets/modules/std/` with its hash; the hash of each
  row equals BLAKE3 of the file's canonical bytes.
- [ ] `frob module show std/leg-3r-qdd --json` returns five ports, two parameters, the guarantees and
  assumptions of the specimen, and `bus_demand.can_exclude = true` (it has a profile).
- [ ] `frob module check` exits 0 on the specimen; exits 3 with FROB-REF-108 on the reversed-sign fixture
  and with FROB-REF-114 on the digest-mismatch fixture.
- [ ] A verb that raises a code missing from its `refusals` array fails the registry lint.
- [ ] The served MCP tool list contains `module_list`, `module_show`, `module_check` once BD-138 lands, with
  schemas identical to the CLI's.
- [ ] Every output carries the claim product; no naked number crosses the boundary.
- [ ] The cost-model line is measured: `module check` on the specimen has a 95th-percentile wall time under
  100 ms over 100 runs on the reference machine, recorded with the median (TARGET).

## Test plan

### Unit tests
`crates/frob-verbs/tests/module_verbs.rs`, driving the real handlers:
- `list_matches_catalog`: row count equals the number of catalog files; hashes verified.
- `show_specimen_fields`: exact field-by-field comparison with the specimen.
- `check_clean_exit_0`, `check_reversed_sign_exit_3`, `check_digest_exit_3`.
- `name_resolves_to_bound_hash`: `bound.module` equals the catalog hash.
- `evidence_weakest_input`: a module whose `knee_card` default is a `generic` card reports class Estimated
  and names the card field.
- `pagination_is_stable`: two pages over a catalog of 50 synthetic modules cover each row exactly once.
- `schema_validates_examples`: each registry example validates against its input schema.
- `check_in_design_runs_joins`: `--in-design quad-tray --at hip_fl` on the specimen returns five join rows,
  four admitted and `sole` unjoined; the same call against a design whose bus port is reversed refuses with 108.
  `quad-tray.fbot` (a quadruped importing the specimen four times with `use` at `hip_fl`, `hip_fr`, `hip_rl`,
  `hip_rr`, bus nominal 22.2 V, shared sink 1.6 W/K) and `quad-reversed-port.fbot` are committed by this bead
  under `assets/fixtures/modules/`; N15b-33's script reuses them.
- `show_refusals`: `module show` of `std/leg-3r-qdd@b3:` followed by a hash that is not the file's refuses
  with 114 (stored and recomputed hashes in the payload); a copy of the specimen with
  `"schema": "frob.module/9"` refuses with 125; `module.list` raises neither.
- `check_cost_within_model`: 100 calls on the specimen, 95th percentile under 100 ms (recorded, not a unit
  failure on a loaded CI host; the end-to-end script asserts it).

### End-to-end script and logging
`scripts/e2e/module_verbs.sh` (N15b-33) runs the three verbs through the real `frob` binary and asserts the
criteria above; NDJSON lines carry `ts`, `script`, `bead`, `step`, `event`, command, exit code, wall time,
evidence block, digests and thresholds.

### Known answers and negative controls
The specimen's field values are the known answer. Negative controls: a handler that returns `match: true`
without recomputing the digest (`mutant-module-check-trusts-digest`) is caught by `check_digest_exit_3`; a
handler that omits the evidence block is caught by the envelope schema test. Determinism: identical bytes
of the `result` object twice on one machine and in debug and release.

## Considerations

- File-path inputs are confined to the caller's namespace by the path jail of the capability model; a path
  outside it is the capability refusal FROB-REF-734 (`path-outside-roots`, exit 5), and a file whose leading
  bytes are code is FROB-REF-828 (exit 3), not module refusals.
- The cluster name `module` is the registry's; the task cluster of the three verbs is `modules`, as VERBS-module
  registers it (at most seven tools per task cluster); BD-138 generates the MCP tools from the rows.
- `module.characterize` (capability tables, M3) and `module.substitute` join the same cluster later.
