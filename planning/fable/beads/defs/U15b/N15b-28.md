## Background

The battery model has two resistor-capacitor polarization pairs, which give the fast and slow parts of
voltage sag and recovery. The referee tier is built on FrankenSim through the airlock crate `frob-fsim`,
and FrankenSim's battery element has one pair (FACT: `frankensim/crates/fs-phs/src/circuit/battery.rs`: a
series resistance, one polarization pair, a bus capacitor, a bounded state of charge that refuses on
exhaustion). How the second pair is obtained on the referee is an open question:

| Field | Value |
|---|---|
| Identifier | OPEN-SINEW-4 |
| Question | Whether the second polarization pair on the referee is composed from existing FrankenSim circuit elements or needs an upstream change |
| Default until decided (fail closed) | Open the upstream work item FD-FSIM-21 and use an in-house `f64` reference until it lands |
| Owner | Airlock lead |
| Decide at | The admission test for `fs-phs` |

The upstream work item, as registered: FD-FSIM-21, repository frankensim, "a second polarization pair for
the battery element of `fs-phs`", priority P3, interim posture "an in-house `f64` reference until it lands",
switch-over rule "re-run GATE-SINEW-07 against the sibling element". A plan rule governs such items:
sibling repositories are the owner's and this program changes them, in the sibling's repository, under its
own agent instructions, gates and conventions, as an upstream work item mirrored as a bead in the sibling's
tracker; every upstream item carries an interim posture and a switch-over rule, so no milestone waits on a
sibling change landing.

## Scope

In: the admission experiment that tells whether composition works; the decision; keeping the interim
posture honest; the switch-over test. Out: the in-house reference and the composition seam (N15b-03); the
upstream change itself (the work item FD-FSIM-21, carried out in the sibling repository under its rules);
opening upstream items as beads (BD-037).

## Technical approach

**Experiment at the `fs-phs` admission test.**
1. With the pinned sibling commit, try to compose the sibling battery (one pair) in series with a further
   RC element built from the sibling's own circuit elements through `interconnect_mapped`, so that the
   composite has the terminal law V = OCV(z) − R₀·I − V₁ − V₂ with dVₖ/dt = −Vₖ/(Rₖ·Cₖ) + I/Cₖ.
2. Check four things on the composite: (a) the current-step response shows the immediate drop I·R₀ and the
   two time constants R₁·C₁ and R₂·C₂ within 1%; (b) the discrete power identity holds per step to 10⁻⁹
   relative; (c) exhaustion still refuses and the state of charge is never clipped; (d) the composite's
   state is fully captured by the airlock's checkpoint (the second pair's voltage survives snapshot and
   restore).
3. Compare with the in-house reference on 10³ random load profiles: terminal voltage within 10⁻⁹ relative.

**Decision rule (DESIGN).**
- If 1 to 3 pass: composition is admitted; FD-FSIM-21 stays open as a convenience item (a native second
  pair) at its priority P3; the referee switches to the composed element after GATE-SINEW-07 is re-run
  against it.
- If composition fails (for example the series connection needs a constrained interconnection the sibling
  defers, or the checkpoint cannot see the extra state): the in-house reference remains the referee's
  battery; FD-FSIM-21 is raised with the failing fixture attached; the switch-over waits for it.
- In both cases the choice is written as an architecture decision record and the stack-lock digest carried
  by memoized referee results reflects which battery implementation ran.

**Interim posture, kept honest.** While the in-house element is in use, every result that involved the
battery records `battery_element: in-house` in its identities, and the foundation ledger lists the item
with its switch-over rule. The in-house element is not a fork of the sibling: it lives in `frob-actuate`,
uses no sibling type, and is the same code the batched kernels are checked against.

**Switch-over test.** `GATE-SINEW-07` re-run with the sibling element selected: step response drop and both
time constants within 1%; ceiling and voltage at a given power within 0.1%; brownout in 100 of 100
above-ceiling trials; exhaustion refuses. Digests of battery-involving fixtures are re-baselined once, in
one reviewed change.

## Test plan

### Unit tests
`crates/frob-fsim/tests/battery_composition.rs` and `crates/frob-actuate/tests/battery_seam.rs`:
- `composed_step_response`: OCV 50 V, R₀ = 0.05 Ω, pairs (0.02 Ω, 500 F) and (0.03 Ω, 4,000 F), 40 A step:
  drop 2.0 V; time constants 10 s and 120 s within 1%.
- `composed_power_identity`, `composed_exhaustion_refuses`, `composed_checkpoint_round_trip`.
- `in_house_vs_composed_agree` (10³ profiles, 10⁻⁹ relative).
- `result_records_battery_element`.

### End-to-end script and logging
`scripts/e2e/sinew_battery_switchover.sh` runs the battery and bus rows of GATE-SINEW-07 twice, with
`--battery-element in-house` and `--battery-element sibling` (the second skipped with a logged reason when
composition is not admitted), compares the two, and logs each row's measured value with its threshold, the
element used, and a summary naming GATE-SINEW-07. It sources the shared helper of STD-E2E.

### Known answers and negative controls
KA-327 (current step: drop I·R₀, then two exponentials with R₁·C₁ and R₂·C₂, within 1%). Negative control:
a composite with the two RC elements wired in parallel instead of series fails the step-response test (one
effective time constant), which shows the experiment can fail.

## Considerations

- A sibling change is the owner's to accept; the program's work never waits on it and never patches the
  sibling from this repository.
- If the sibling later adds ageing, thermal drift or hysteresis laws, the question reopens for those laws
  under the same rule.
- Priority P3 upstream means it may land late; the in-house element must be maintained as first-class code
  until then.
