## Background

An invalid design or request is refused with a stable code, a message and ranked repairs expressed as typed
edits; nothing is repaired in silence. The actuator subsystem owns seven codes, written out in full in the
registry bead N15-REF. A refusal is only as good as what an agent can do with it, so this bead tests each
code the way an agent meets it: through the real `frob` binary, reading the envelope's `refusal` object
(`code`, `message`, `pointer`, `observed`, `required`, `unit`, `affected_claims`, `retry`, `repairs`),
applying the first repair, and checking that the refusal is gone. Each component family also has a first
rejection fixture in the negative-control registry, and a check that lets its fixture through is broken
whatever else it reports; three of those fixtures are Sinew's (the transmission that produces free energy in
reverse drive, the actuator with stall torque available indefinitely at high speed, the empty battery that
keeps supplying commanded power).

The preflight's defect gate (GATE-SKEL-04: of 100 seeded defects for stages 1 to 6, with at least two per
refusal code, all 100 are refused and at least 95 by the stage and code that own them) needs two seeded
defects for each Sinew code raised in stages 1 to 6. This bead supplies and exercises them.

The seven codes, their meanings, and what each returns:

| Code | Refused | Returned with the refusal |
|---|---|---|
| FROB-REF-130 | A card or transmission that is not passive: loss negative in some quadrant, efficiency above one, or torque and back-EMF constants inconsistent beyond the stated uncertainty | The quadrant and the power created |
| FROB-REF-131 | A required operating point outside the torque, speed and voltage envelope | The point, the envelope boundary, and the gear-ratio or card edit that admits it |
| FROB-REF-132 | No stable thermal equilibrium at a required operating point, or an equilibrium above a limit | The equilibrium or the margin to the tangency; the largest sustainable load |
| FROB-REF-133 | Peak demand above the bus ceiling E²/(4·R) | The ceiling, the demand, and the battery or harness edit that admits it |
| FROB-REF-134 | A card without a current convention, or with conventions that disagree | The fields in conflict |
| FROB-REF-135 | Power requested from an exhausted battery, or state of charge driven outside its bounds | The step and the energy short |
| FROB-REF-136 | A row option the requested tier does not carry | The tiers that carry it |

## Scope

In: fourteen fixtures (two per code); the script; payload assertions; the repair loop; registration of the
seeded defects. Out, with the bead that has each: the registry rows (N15-REF); the mechanisms that detect
each condition; the card verbs' script and its rejection cards (N15a-25); the static sizing script on the
worked cards (N15a-26); stage 6 through `design.check` (N15b-34).

## Technical approach

**Fixtures** (`synthetic`, `assets/fixtures/sinew/refusals/`), two per code:
- 130: `gear-single-eta` (η = 0.8 in all quadrants, N = 10; witness 10 N·m at 1 rad/s back-driven: 2.5 W
  created); `kt-ke-mismatch` (torque constant quoted per RMS phase ampere against a back-EMF constant in
  power-invariant coordinates, a factor √(3/2) beyond the stated uncertainty).
- 131: `stall-at-speed` (stall torque asked above the no-load speed); `crouch-over-envelope` (a crouch
  torque 20% above the envelope at the crouch speed).
- 132: `hold-20a` (the thermal worked card, R₀ = 0.20 Ω at 25 °C, α = 0.00393 K⁻¹, G = 0.80 W/K, limit
  155 °C: equilibrium 190 °C); `hold-35a` (above I_crit = 31.9 A: no equilibrium).
- 133: `bus-8kw` (E = 48 V, R = 0.08 Ω, demand 8,000 W against a ceiling of 7,200 W);
  `quad-bus-undersized` (a nominal-gait peak above the ceiling).
- 134: `no-convention` (a three-phase card with `current_convention` absent); `convention-conflict`
  (`current_convention: dc` with `pole_pairs: 7` and `modulation: svm-linear`).
- 135: `empty-battery` (a request for 100 W after exhaustion); `overcharge` (a charge request at the upper
  state-of-charge bound).
- 136: `convex-row-on-referee` (the regularized stiction row requested on the referee, which solves the
  row set-valued); `backlash-option-missing` (a restitution value requested for backlash rows on a tier
  whose rows are compliant). The Gaussian Stribeck shape on a lockstep tier is exercised at M2 by the
  kernel bead's own test.

**Script `scripts/e2e/sinew_refusals.sh`** (plain shell; sources the shared helper of STD-E2E; idempotent):
1. For each fixture run the verb that owns the check: `frob actuator check` (130, 134), `frob design check`
   (131, 132, 133 at stage 6; 130 and 134 at stage 1 for a design that binds the bad card), `frob actuator
   bus` (133, 135), `frob sim run --tier referee` (135 as a world event; 136 at step-plan admission).
2. Assert `ok: false`, exit 3, the code, `retry: "after-change"`, a `pointer` that names the field or part,
   and the payload values: 2.5 W and `back-driven`; 190 °C (within 0.5%) and largest sustainable current
   18.6 A; for `hold-35a` "no equilibrium" with the margin to the critical current; ceiling 7,200 W and
   demand 8,000 W; the conflicting field names; the step index and the energy short in joules; the list of
   tiers.
3. Repair loop for the static codes (130, 131, 132, 133, 134): apply `refusal.repairs[0]` with `frob design
   edit` or by writing the repaired card, re-run the same verb, and assert the refusal is gone.
4. Inside a batch: `frob sim run --tier referee empty-battery --seed 3 --json` completes with exit 2 and the
   world's event `battery-exhausted`; the run-time refusal appears as the world's outcome, not as a failed
   verb.
5. MCP parity when the M1 tool surface exists: the same call through `frob-mcp` returns a tool result with
   `isError: true` whose structured content is the same envelope (skipped with a logged reason before
   then).
6. Register the fourteen fixtures as seeded defects for the preflight's defect battery, each tagged with
   the stage and code expected to refuse it.

**Logging.** NDJSON to `target/e2e-logs/sinew_refusals/<utc-timestamp>.ndjson` with a transcript: `ts`,
`script`, `bead` ("N15b-38"), `step`, `event` (`start`, `cmd`, `refusal`, `assert`, `end`), exact command,
exit code, wall time, the envelope's `evidence` block, the full `refusal` object, the repair applied and
the identifiers before and after, the first differing payload field on failure with the artifact paths,
and a `summary` with counts of refusals seen, repairs that worked, and the gate touched.

## Acceptance criteria

- [ ] Fourteen refusals observed, two per code, each with exit 3, the right code and a pointer.
- [ ] Payload values match the hand values above.
- [ ] For the five static codes the first repair removes the refusal in every fixture.
- [ ] The run-time refusal inside a batch is an event with exit 2, never a silent continuation.
- [ ] The fixtures are registered as seeded defects with their owning stage and code.
- [ ] No fixture produces exit code 1, and no refusal lacks ranked repairs.

### Known answers and negative controls
KA-320 (130), KA-279 (the reverse-drive fixture refused by the card check), KA-280 (131), KA-313 and KA-305
(132; 190 °C), KA-308 (I_crit = 31.9 A), KA-324 and KA-325 (133), KA-326 and KA-285 (135). Negative

`mutant-thermal-const-r`, `mutant-bus-clip-demand`, `mutant-battery-clip-soc`) must turn the corresponding
step red. Determinism: refusal payloads identical twice and in debug and release (class D0 for the
rational fields).

## Considerations

- The repair ranking is advice and DESIGN; the test checks only that the first repair works, not that it is
  the best.
- A refusal never weakens its inputs to proceed; the script fails if any verb returns `ok: true` with a
  warning in place of a refusal for these fixtures.
- Payloads echo field paths and numbers only; imported free text is not echoed without its untrusted mark.
