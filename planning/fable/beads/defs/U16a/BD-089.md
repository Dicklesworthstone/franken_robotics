## Background

GATE-KIN-02 (claim: Parity; earliest milestone M1; TARGET): contact-free forward dynamics of each reference robot
against the pinned oracle, with joint accelerations within 10⁻⁹ relative in `f64`.

Why it exists. The known-answer battery tests small mechanisms whose truth is a formula. A reference robot has
thirty links, real inertias and a floating base; no formula gives its accelerations, but an independent,
widely used engine does. Agreement with that engine at 10⁻⁹ relative shows that the import, the model compiler,
the referee lowering and the dynamics recursion compute the same rigid-body equations. It is **Parity** and is
never reported as Reality: agreement with an oracle transfers none of the oracle's own agreement with hardware.

The oracle (DESIGN; FACT about the rule): MuJoCo C in double precision at an exact release recorded with the
fixture. It is a development-time oracle, run out of process, never linked into the product and never a
dependency of any crate. A fixture is captured by a script under `tools/oracle/`, stored with its pin and date,
and never regenerated from the candidate. Two oracles that disagree are a finding filed with both pins, and the
candidate is not tuned toward either until the disagreement has an explanation in a derivation file.

Reference robots are imported public models used as parity fixtures (licences recorded per model): for the
archetypes that land at M1 these are the quadrupeds Unitree Go1, Go2, A1, ANYmal B and C and Spot; the humanoids
Unitree H1 and G1; the Stretch 3 base (`diff-drive`); the TIAGo omni base (`mecanum`); and FrankenSim's own G1
(29 degrees of freedom) and KUKA iiwa 7 from `fs-mbd::robot_models`.

## Scope

In: the state sampler, the oracle capture inputs and their conversion, the comparison on the referee tier, the
error metric, the controls, and the gate record. Out: the capture scripts and fixture storage themselves
(BD-067); import and its loss report (BD-065, BD-066); the same comparison for the batched kernels against
`fs-mbd` (GATE-KIN-03, beads N16a-17, BD-150, BD-159); contact.

## Technical approach

1. **States.** For each reference robot, 10⁴ states (DESIGN: the gate text fixes no count; 10⁴ matches the
   sibling parity gates) drawn from a counter-based stream keyed by (robot, index): joint positions uniform
   inside limits; joint velocities uniform in ± the card speed limit (or ± 5 rad/s where the model has none);
   applied joint torques uniform in ± the card torque limit; base orientation a uniform unit quaternion; base
   twist uniform in ± 2 rad/s and ± 2 m/s; gravity (0, 0, −9.81) m/s². Contacts disabled on both sides. The
   sample file (`states.bin` with a JSON header: robot, model digest, stream key, count) is an input of both
   the capture script and the test.
2. **Oracle capture (through BD-067).** The script loads the same model file the importer read, sets
   `qpos`, `qvel` and `qfrc_applied`, zeroes controls, disables contact and every feature the import loss
   report lists as dropped, calls the engine's forward dynamics and writes `qacc`. The fixture records the
   engine release, the model file digest, the option flags used and the date.
3. **What "contact-free forward dynamics" includes on both sides.** Rigid-body terms, gravity, joint damping,
   rotor (armature) inertia and passive joint springs where the model declares them and the importer kept them.
   Excluded on both sides, by disabling them in the capture and asserting they are absent or zero after import:
   dry joint friction, tendons, equality constraints, fluid forces, actuator dynamics, contact. A field the
   importer dropped that changes `qacc` makes the robot ineligible until the loss report and the capture agree.
4. **Convention conversion** (the place parity tests usually fail). This project: body-frame twist ξ = (ω, v),
   angular part first; a free base's velocity coordinates are its body twist. The oracle's free joint: linear
   velocity in the world frame, angular velocity in the body frame, linear part first; quaternion as (w, x, y,
   z). Mapping for the base, with R the base rotation: v_world = R·v_body; and for accelerations
   a_world = R·(v̇_body + ω × v_body), ω̇ unchanged. Joint coordinates map one to one for one-axis joints; a
   revolute coordinate stored here as a unit complex number plus a turn count converts to an angle only at
   this boundary. The conversion is one function in `frob-conformance`, with its own test (item 6).
5. **Candidate.** For each state, call the referee's forward dynamics through the airlock
   (`RefereeDynamics`: FrankenSim's `fs-mbd` articulated forward dynamics for a floating base) on the model
   lowered by the compiler, and convert the result to the oracle's convention.
6. **Metric (DESIGN).** Per state, e = max_i |a_i − a_i°| / max(1, max_i |a_i°|), accelerations in SI units
   (rad/s² and m/s²), with a° the oracle value. The floor of 1 keeps a state with tiny accelerations from
   dominating; it is stated in the gate record. Pass per robot: max over the 10⁴ states of e ≤ 10⁻⁹. Reported:
   the maximum, the 99th percentile, the state index of the maximum and the coordinate at fault.
7. **Recording.** One row per robot in the gate registry with the measured maximum, the oracle pin, the model
   digest and the count of states; the gate passes when every eligible reference robot passes and the controls
   were caught.

## Acceptance criteria

- [ ] Seed done-condition: GATE-KIN-02 recorded with the measured maximum relative error per reference robot,
      each at most 10⁻⁹ in `f64`, on 10⁴ states.
- [ ] The oracle fixture for every robot has its pin, date and model digest, and the path that would regenerate
      a fixture from the candidate does not exist (the capture script cannot read workspace build products).
- [ ] The three planted defects below each raise the error above the threshold on at least one robot.
- [ ] The conversion function round-trips: converting a twist and an acceleration to the oracle convention and
      back is the identity to round-off on 10⁵ random samples.
- [ ] Each robot's loss report and capture options agree: no field that affects `qacc` is present on one side
      only (asserted by a field-coverage check).
- [ ] The result carries claim "Parity", class `Tested`, tier `referee`, and `reality: no-claim`.

## Test plan

### Unit tests

- `parity::convention_roundtrip`: 10⁵ random (R, ω, v, ω̇, v̇) through the mapping of item 4 and back.
- `parity::free_body_closed_form`: a single free body with a known inertia: forward dynamics equals Euler's
  equation I·ω̇ = (I·ω) × ω + τ and v̇ = v × ω + f/m in the body frame, and equals the oracle after conversion.
- `parity::two_link_arm_energy`: a two-joint arm's accelerations equal those from an independently
  differentiated energy to 10⁻¹⁰ (the admission fixture of the articulated dynamics, reused).
- `parity::metric_floor`: a state with all accelerations below 1 is measured absolutely; one with large
  accelerations relatively.
- `parity::per_robot_gate` (one test per reference robot, generated from the fixture directory): the comparison
  of items 5 and 6.
- `parity::ineligible_robot_reported`: a model with an equality constraint is reported `ineligible: dropped
  field affects qacc` and is not counted as a pass.

### End-to-end script and logging

`scripts/e2e/kin_parity_oracle.sh`: for each robot, `frob design import <model file> --json` (asserting the
loss report), then the conformance binary's parity run on the stored fixture
(`cargo run -p frob-conformance --bin frob-parity -- kin-fd --robot <name> --json`, an existing-harness entry,
not an `xtask` subcommand), then assertions on the JSON summary. Log lines: `cmd` with the command and exit
code; `metric` with `robot`, `states`, `max_rel_error`, `p99_rel_error`, `threshold: 1e-9`, the oracle pin and
the model digest; `assert` per control with `control_caught`; `summary` with `gates: ["GATE-KIN-02"]`. On
failure the line names the state index, the coordinate, both values and the path of the state file, so the case
can be replayed alone.

### Known answers and negative controls

- KA-359: contact-free forward dynamics of each reference robot against the pinned oracle; joint accelerations
  agree within 10⁻⁹ relative in `f64`; tier G2 on the referee. The suite states no negative control for this
  row; this bead registers three:
  1. the velocity-product (Coriolis and centrifugal) term dropped: invisible at zero velocity, so the sampler's
     non-zero velocities must expose it;
  2. one link's inertia about the wrong point (centre of mass used where the frame origin is declared);
  3. a wrench moved between frames with the twist map instead of the wrench map: with R = I and
     p = (1, 0, 0) m, a force (0, 0, 1) N must produce the torque (0, −1, 0) N·m and the twist map gives zero.
- Live-dependency proof: perturbing one link mass by 10⁻⁶ relative changes the measured error above 10⁻⁹.
- Metamorphic: a rigid change of world frame (translation and yaw) applied to every state leaves joint
  accelerations unchanged on both sides.
- Determinism lanes: the comparison is run twice on one machine and in debug and release; the referee lane is
  not compared across platforms.

## Considerations

- The referee's joint classes are fixed, revolute, prismatic and helical; spherical, universal and planar
  joints are lowered to products of one-axis joints. When FrankenSim gains those classes (upstream work item
  FD-FSIM-01) this gate is re-run, as that item's switch-over rule says.
- Menagerie models carry engine-specific fields (armature, joint damping, friction loss, gravity
  compensation). The loss report is the contract for which of them survive import; anything dropped must be
  disabled in the capture, or the comparison measures the importer's omissions instead of the dynamics.
- 10⁻⁹ relative across two independent implementations in `f64` leaves room for roughly six decimal digits of
  accumulated round-off on a 30-link chain; a robot that lands between 10⁻⁹ and 10⁻⁷ is a finding to explain in
  a derivation file, not a tolerance to widen.
- Licences: each model file is used under its recorded licence and is not redistributed outside the fixture
  directory's manifest.
