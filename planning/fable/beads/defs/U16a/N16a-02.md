## Background

FrankenRobotics computes one model on three tiers and keeps a ledger of their disagreement (ADR-KIN-01: a fast
answer is useful only if its distance from a trusted answer is a measured number, and the CPU reference is
permanent so that a GPU world can always be re-run where it can be inspected).

| Tier | Purpose | Arithmetic | Foundation | Worlds |
|---|---|---|---|---|
| `referee` | The most trusted answer we can compute. Adjudicates the others. | `f64`, deterministic elementary functions, exact Coulomb friction, certified collision queries | FrankenSim's `fs-mbd`, `fs-contact`, `fs-time`, `fs-query` through the airlock `frob-fsim`, driven by the transactional step | One to a few dozen |
| `batch-cpu` | The permanent reference for the batched algorithm. Runs anywhere, including where there is no GPU. Debugging target for a teleported world. | `f64` or `f32`; the same derived kernels and the same stage order as the GPU | `frob-kernels` in Rust on `fs-exec` tiles | Hundreds to thousands |
| `gpu-cuda`, `gpu-metal` | Throughput for training and for design sweeps. | `f32` | The same kernels in the shared dialect | Thousands to tens of thousands per device |

The referee is **not** called ground truth. Its outputs carry the evidence class FrankenSim's contracts give them,
and Reality is a separate claim that only measured data can support.

A tier runs under a **step profile**, which is a promise about what the step did and is part of the step-plan
identity every result carries beside its `ModelId`.

| Profile | Tiers | Step discipline | Law | Use |
|---|---|---|---|---|
| `lockstep` | `batch-cpu`, `gpu-cuda`, `gpu-metal` | Fixed step h, ten stages, a fixed number of Newton iterations under masks | CL-1 (linear compliant normal with a dissipation time, regularized Coulomb friction) by default; CL-2 (Hunt–Crossley) and CL-H (hard contact) as Frontier options | Training, sweeps, design populations. On `batch-cpu` it is the bit-level reference for the GPU. |
| `strict` | `batch-cpu` only | The transaction per accepted interval, in `f64`, one world at a time per worker, events located | CL-1 with located events; CL-H once its gate GATE-TRAC-09 passes | Adjudication where the referee cannot complete; the "step" and "law" arms of model-form checks; debugging |
| `referee` | `referee` only | The transaction with certified queries | Exact Coulomb through FrankenSim's solve, specified as CL-H | Adjudication |

A request for `strict` or `referee` on a GPU tier is refused with `FROB-REF-222`. DESIGN, reason: a profile is a
promise about what the step did, and a GPU cannot keep this one without giving up fixed shapes (ADR-KIN-02: adaptive
splitting would destroy the static launch graph). The alternative rejected is a silent downgrade to `lockstep`,
which would return a result under a profile the caller did not ask for.

## Scope

In: the `Tier` and `StepProfile` types; the admission function for (tier, profile, law, precision); the refusal
`FROB-REF-222` with its repair; the evidence fields a tier contributes to the claim product; the wiring into the
request validation of `sim.run`, which at M1 means that `frob sim run --tier referee --profile referee` is
accepted and every other pair is refused (the M2 form of the verb, with `--law` and per-world slots on all
tiers, is N16b-25). Out: the step implementations (BD-081 and BD-161 for the transactional profiles,
BD-159 for `lockstep`); `StepPlanId` (N16a-03); admission of a contact law on a tier, which is `frob-contact`'s
refusal `FROB-REF-246`; the registry row of the verb flags.

## Technical approach

```rust
// DESIGN. Names are the plan's; the wire spellings are the tier names of the conventions table.
pub enum Tier { Referee, BatchCpu, GpuCuda, GpuMetal }           // "referee" | "batch-cpu" | "gpu-cuda" | "gpu-metal"
pub enum StepProfile { Lockstep, Strict, Referee }               // "lockstep" | "strict" | "referee"
pub enum Precision { F64, F32 }
pub struct Admitted { tier: Tier, profile: StepProfile, law: LawId, precision: Precision }   // only built by admit()

pub fn admit(tier: Tier, profile: Option<StepProfile>, law: Option<LawId>, precision: Option<Precision>)
    -> Result<Admitted, Refusal>;
```

Admission rules, applied in this order:

1. Default profile when none is given: `Referee` on `referee`; `Lockstep` on every other tier.
2. Matrix. Allowed pairs: (`referee`, `Referee`); (`batch-cpu`, `Lockstep`); (`batch-cpu`, `Strict`);
   (`gpu-cuda`, `Lockstep`); (`gpu-metal`, `Lockstep`).
3. `Strict` or `Referee` on `gpu-cuda` or `gpu-metal`: refuse `FROB-REF-222` "Profile not available on tier", with
   `pointer = "profile"`, `observed` the pair, `required` the allowed profiles for the tier, `retry =
   "after-change"` and the ranked repair "run on `batch-cpu`" (as a ready command with `--tier batch-cpu`).
4. The remaining disallowed pairs (`Referee` on `batch-cpu`; `Lockstep` or `Strict` on `referee`) are refused
   under the same code, with the repair naming the profile that exists on that tier. DESIGN of this bead: the
   plan's refusal text names the GPU case; these pairs are equally outside the table and get the same code so
   that no pair is silently remapped.
5. Precision: `referee` and `Strict` are `f64` only; `gpu-*` are `f32` only; `batch-cpu` under `Lockstep` is `f64`
   or `f32` (default `f32`, the bit-level reference for the GPU; `f64` is the parity configuration).
6. Law defaults: CL-1 on `Lockstep` and `Strict`; CL-H (through FrankenSim's solve) on `Referee`. Which law
   `strict` runs by default once CL-H is admitted is OPEN-KIN-4 (default: CL-1 with located events, CL-H as a
   named variant; blocks nothing; decided with GATE-TRAC-09). A law not admitted on the pair is `frob-contact`'s
   refusal, not this bead's.

Exit code: `FROB-REF-222` is a refusal of the request (the 2xx family), so the envelope has `ok: false` and the
process exits 3.

Evidence. Every result of a step carries `evidence.tier` (the tier name), `evidence.profile`, the determinism
class of the pair, and, for a fast-tier result, the label `provisional`. Combination across inputs takes the lowest
tier (claim product). The string "ground truth" appears in no output of this crate; a lint over message catalogues
enforces it. A result on the `referee` tier carries the evidence class FrankenSim's contract gives it and
`reality: no-claim`.

Determinism class by pair (DESIGN, from the numerics rules): `lockstep` is D2 (bitwise per backend, and across batch
size, slot, co-tenants, capacity and shard count); `strict` is D2 on `batch-cpu`; `referee` claims same-platform
determinism only, because `fs-mbd` calls platform `sqrt`, `sin` and `cos` (FACT at the pinned FrankenSim commit;
upstream work item FD-FSIM-07 adds deterministic elementary functions).

Surface. `sim.run` and every verb that takes `--tier` call `admit` before any allocation; the admitted triple is
echoed in the envelope's `bound` block so that a caller sees which defaults were applied.

## Acceptance criteria

- [ ] `admit` returns `Admitted` for exactly the five allowed pairs and a refusal for the other seven.
- [ ] `strict` and `referee` on `gpu-cuda` and `gpu-metal` return `FROB-REF-222` with the repair "run on
      `batch-cpu`", exit code 3, and nothing is allocated (checked by an allocation counter in the test backend).
- [ ] Defaults are echoed: `frob sim run … --tier batch-cpu --json` reports `profile: "lockstep"`, `law: "CL-1"`.
- [ ] No message of the crate contains "ground truth" (lint test).
- [ ] A fast-tier result carries `provisional`; the claim product of a referee result and a `gpu-cuda` result has
      tier `gpu-cuda`.
- [ ] The `CONTRACT.md` refusal section lists `FROB-REF-222` with its repairs.

## Test plan

### Unit tests

- `tier::matrix_exhaustive`: all 4 × 3 pairs against the table above (5 admitted, 7 refused).
- `tier::gpu_strict_refused`: (`GpuCuda`, `Strict`) → code `FROB-REF-222`, first repair `--tier batch-cpu`.
- `tier::defaults`: (`Referee`, None) → `Referee`; (`BatchCpu`, None) → `Lockstep`.
- `tier::precision_rules`: (`BatchCpu`, `Strict`, `F32`) refused; (`GpuMetal`, `Lockstep`, `F64`) refused;
  (`BatchCpu`, `Lockstep`, `F64`) admitted.
- `tier::wire_names_roundtrip`: the four tier names and three profile names parse and print unchanged.
- `evidence::lowest_tier_wins`: property test over random pairs of products.
- `messages::no_ground_truth`: scan of the refusal and label catalogues.

### End-to-end script and logging

Exercised in `scripts/e2e/kin_transaction_referee.sh` (N16a-10) and `scripts/e2e/kin_lockstep_batch.sh`
(N16a-18). Steps contributed: `frob sim run <fixture> --tier gpu-cuda --profile strict --json` must exit 3 with
`refusal.code = "FROB-REF-222"`; the log line has `event: "refusal"`, the command line, the exit code, the
refusal code and its first repair. Where no device exists the same assertion still runs, because admission
precedes device discovery. A second step runs the repaired command and asserts success.

### Known answers and negative controls

- Negative control (planted defect): a build in which rule 3 maps (`gpu-*`, `strict`) to `lockstep` instead of
  refusing; the test `tier::gpu_strict_refused` and the e2e step must both fail on it.
- Live-dependency proof: changing only `--profile` changes `StepPlanId` (asserted with N16a-03).

## Considerations

- OPEN-KIN-4 (owner: Kinesis lead; fail-closed default: CL-1 with located events on `strict`, CL-H named
  explicitly) is recorded here because the default law is chosen by `admit`.
- The matrix is deliberately closed: a new tier or profile is an ADR and a new `StepPlanId` field value, never a
  flag.
- Interaction with the referee's limits: a referee request that FrankenSim cannot complete is not a profile
  refusal; it is a capacity or scope refusal handled by the adjudicator routing of N16a-05.
- Until N16-REF's registry entry lands, the code is registered in `registries/refusals.toml` by this bead with
  the chapter's wording, since an unknown code is a load-time error.
