## Background

The transactional step (used by the `referee` profile and the `strict` profile) advances each world by one
transaction per accepted physics interval and locates events inside it. For a located event to mean the same
thing on a retry, on a replay and on another machine, time itself must be exact and the places where an interval
may be cut must not depend on the state.

Time in FrankenRobotics is rational: an unsigned 64-bit count of quanta of 1/Q seconds, Q being the least common
multiple of the denominators of every period in the run (admission refuses Q above 2⁴⁰). Every clock (sensor,
link, estimator, controller, actuator channel) is a phase accumulator in integer arithmetic.

DESIGN of this mechanism: the physics grid (multiples of the step h) and the clock boundaries of the clock
contract together cut time into **base intervals** [t0, t1) of length ℓ₀ ≤ h. That partition is fixed by the
schedule and never by the state. Inside a base interval, sub-intervals are **dyadic**: a split may fall only at
t0 + ℓ₀·k/2ᴸ for a level L ≤ L_max. DESIGN constants: L_max = 16, which at ℓ₀ = 2 ms resolves
2 ms / 2¹⁶ = 31 ns, so an approach at 3 m/s is located to within 0.1 µm (known answer KA-343). An event that
cannot be bracketed without exceeding L_max, or more than E_max = 64 events inside one base interval, ends the
transaction with `FROB-REF-220` instead of an approximation: this is the guard against accumulation points of
impacts (a ball whose bounces shrink geometrically reaches infinitely many impacts in finite time). L_max and
E_max are OPEN-KIN-5 (decision bead N16a-09); the fail-closed default is refusal.

Why dyadic and schedule-fixed (reasons, with the alternatives rejected):

- A free floating-point split time would make the set of sub-intervals depend on rounding, so a retry could cut
  differently from a first attempt and a noise increment defined over an interval would have no stable address.
  On the dyadic tree every sub-interval has an integer address (level, index), which is what the refinement law
  for random inputs keys its draws by.
- Cutting base intervals at state-dependent times (for example at each located event) would make the partition,
  and with it every clock boundary and every noise address, a function of the trajectory. Then two worlds that
  differ by one bit would no longer share a time grid and could not be paired.
- Under a transactional profile every clock boundary is an exact sub-interval boundary, because clock boundaries
  are themselves base-interval boundaries: t1 = min(t0 + h, next clock boundary).

## Scope

In: the base-interval iterator, the `Dyadic` time type with exact arithmetic, the work-queue operations on
sub-intervals, the level and event-count limits with their refusal, and conversion of an exact duration to the
floating-point `dt` handed to dynamics. Out: finding the event time (BD-082); the clock contract and its phase
accumulators (BD-078); the noise tree addressed by (base interval, level, index) (BD-083).

## Technical approach

```rust
// DESIGN. All arithmetic is integer; nothing here is floating point except to_seconds_f64().
pub struct BaseInterval { pub id: u64, pub t0: Quanta, pub t1: Quanta }       // half-open [t0, t1), ℓ₀ = t1 − t0 ≤ h
pub struct Dyadic { pub level: u8, pub index: u32 }                            // the node t0 + ℓ₀·index/2^level
pub struct SubInterval { pub a: Dyadic, pub b: Dyadic }                        // a < b, both in one base interval
pub struct TxnTimeLimits { pub l_max: u8 /* 16 */, pub e_max: u8 /* 64 */ }
```

1. **Base-interval iterator.** Input: the physics step h in quanta and the clock schedule (every phase
   accumulator of the run). `next(t0)`: let g be the next physics-grid point strictly after t0 (grid points are
   n·h_quanta) and c the earliest clock event strictly after t0; then t1 = min(g, c), so ℓ₀ = t1 − t0 ≤ h. The
   id is the ordinal of the interval within the episode, starting at 0. The sequence depends only on the
   schedule; a test asserts it is identical for two different initial states.
2. **Dyadic nodes.** A node is normalized so that `index` is odd or `level = 0` (index 0 or 1 at level 0 denote
   t0 and t1). Comparison: cross-multiply to a common level (a.index·2^(L−a.level) against b.index·2^(L−b.level)
   with L the larger level, in u64). Midpoint of (a, b): raise both to level L+1 and average; it is refused if
   L+1 > l_max.
3. **Exact sum check.** The committed sub-intervals of a transaction, in order, must satisfy first.a = (0, 0),
   last.b = (0, 1) and each b equal to the next a. This is the law "sub-intervals sum to (t0, t1) exactly"; it is
   an integer identity, not a tolerance.
4. **Work queue.** `VecDeque<SubInterval>` initialized to [(t0, t1)]. `split(front, t*)` replaces the front
   (a, b) by (a, t*) and pushes (t*, b) behind it at the front of the queue, where t* is a dyadic node strictly
   inside (a, b).
5. **Limits.** `split` returns `FROB-REF-220` "Event refinement limit" when t* would need level > l_max, and the
   event counter returns it when a 65th event is recorded in one base interval. The refusal carries
   `observed` (the level or the count), `required` (≤ 16, ≤ 64), the bracket reached, the pair or guard involved
   and the ranked repairs: report the accumulation; switch law; shorten h. Exit code 3. The transaction ends;
   the world is `Faulted` with cause `numerical-fault` (BD-081).
6. **Floating-point duration.** `SubInterval::dt_seconds() -> f64` computes ℓ₀·(b − a) as an exact rational
   (numerator in u128) over Q·2^L and rounds once to nearest. Dynamics receive this `dt`; no code path adds
   floating-point durations to obtain a time.
7. **Resolution arithmetic** (printed by `sim.estimate` and the contract): cell = ℓ₀/2^l_max; at ℓ₀ = 2 ms and
   l_max = 16 it is 30.52 ns; position resolution at approach speed v is v·cell (3 m/s → 91.6 nm).
8. **Lockstep contrast.** On the lockstep tiers a clock period that is not a multiple of h is served by its
   phase accumulator with the quantization recorded (`hold` realizes an event at the first boundary at or after
   its nominal instant, lateness always less than h). This module is not used there; it provides only the shared
   `Quanta` conversions.

## Acceptance criteria

- [ ] For physics at 400 Hz, an inertial sensor at 100 Hz and a policy at 30 Hz (Q = 1,200; periods 3, 12 and 40
      quanta), the base intervals over one 120-quanta cycle are cut at every multiple of 3 and at 40 and 80, and
      the pattern repeats exactly; every interval has ℓ₀ ≤ 3 quanta.
- [ ] The partition is identical for two worlds with different states (property test).
- [ ] Sub-interval sums are exact for 10⁶ random split sequences (integer equality).
- [ ] A split beyond level 16 and a 65th event both return `FROB-REF-220` with the three repairs.
- [ ] `dt_seconds` is correctly rounded: equal to a 256-bit rational evaluation on 10⁵ random sub-intervals.
- [ ] The printed resolution at ℓ₀ = 2 ms is 31 ns and 0.1 µm at 3 m/s (KA-343).

## Test plan

### Unit tests

- `time::base_intervals_400_100_30`: boundaries in quanta over [0, 120]: 0, 3, 6, …, 39, 40, 42, …, 78, 80, 81,
  …, 120; interval count 42 (40 physics steps plus the two extra cuts at 40 and 80).
- `time::partition_is_state_free`: two random states, same schedule, equal sequences.
- `time::dyadic_midpoint_and_order`: midpoint of ((0,0),(0,1)) is (1,1); of ((1,1),(0,1)) is (2,3); ordering
  (2,1) < (1,1) < (2,3).
- `time::sum_exact` (property): random valid split sequences reassemble to (t0, t1).
- `time::level_limit`: sixteen successive halvings succeed; the seventeenth returns `FROB-REF-220`.
- `time::event_limit`: 64 events recorded; the 65th returns `FROB-REF-220`.
- `time::dt_correctly_rounded`: against exact rational arithmetic.
- `time::resolution_ka343`: 2 ms / 65,536 = 30.517578125 ns exactly; × 3 m/s = 91.552734375 nm.

### Known answers and negative controls

- KA-343: 2 ms / 2¹⁶ = 31 ns; 3 m/s is located to within 0.1 µm. Tolerance: exact arithmetic to the printed
  digits. The row has no stated negative control in the suite; this bead registers one: a grid built with
  l_max = 12 prints 488 ns and must fail the row.
- G0 law of the transactional step: sub-intervals sum to the base interval exactly. Planted defect: a split that
  stores the midpoint as a rounded `f64` fraction; the exact-sum test fails after a few thousand splits.
- Determinism lanes: all tests are integer (class D0) and run twice on one machine, in debug and release, and
  on both platforms.

## Considerations

- A known tension, recorded for the owner: the gate row "impact time within 10⁻⁹ s" is finer than one grid cell
  (31 ns at the defaults). The grid fixes where an interval may be cut; the reported event time is a refined
  estimate inside the final cell (BD-082 defines it). Raising L_max to 21 would bring the cell to 0.95 ns at
  ℓ₀ = 2 ms; that is part of OPEN-KIN-5.
- The u64 products in comparisons are bounded by 2³²·2¹⁶; the u128 path in `dt_seconds` covers Q up to 2⁴⁰.
- A base interval shorter than h (cut by a clock) has a finer absolute cell; resolution is always relative to
  ℓ₀.
- If the refusal rate of `FROB-REF-220` on the M1 fixtures leaves the door-sill fixture without a completed run,
  the milestone's stop decision re-plans the referee (decision bead N16a-09).
