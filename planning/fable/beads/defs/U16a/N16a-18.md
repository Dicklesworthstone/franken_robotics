## Background

At M2 the batched step exists on `batch-cpu`: ten stages in a fixed order, a lockstep Newton solve under masks,
fixed-shape buffers whose overflow is flagged, and padding rules that make a world's bits independent of its
batch. Unit tests cover each piece in its crate. This bead is the proof from the outside: a shell script that
drives the real `frob` binary and records, in structured logs, that a quadruped drops, stands and walks, that an
overflow is flagged and never silent, that one world's digests are the same alone and in any batch, and that the
kernels agree with the pinned oracle. It covers the `batch-cpu` rows of three gates:

- GATE-KIN-03 (Parity): `batch-cpu` in `f64` against `fs-mbd`: kinematics, inverse dynamics, forward dynamics
  and mass matrix within 10⁻¹⁰ relative on 10⁴ states per reference robot.
- GATE-KIN-05 (Known answer, determinism): 1,000 episodes with identical digests solo and in 100 random
  co-tenancies, capacities and slot assignments, per back end; the path-table Jacobian gives the same digests as
  the dense one.
- GATE-KIN-07 (Known answer): `Degraded` world-steps at most 10⁻⁴ of world-steps per class on the standard
  battery; every forced overflow flagged; capacities printed in every disclosure block.

## Scope

In: the script, its fixtures, assertions, logs and the gate rows it can record on `batch-cpu`. Out: device rows
(the device beads re-run the same script with `--tier gpu-cuda` and `--tier gpu-metal`); the battery-wide
`Degraded` rate (recorded with the frozen standard battery); parameter variants (N16a-19).

## Technical approach

Script: `scripts/e2e/kin_lockstep_batch.sh`. Plain shell; sources the shared helper of STD-E2E; idempotent;
seeds explicit; exits non-zero on failure after writing the summary. A `--smoke` mode shrinks counts for the
`smoke` battery; the default mode is the gate run.

Steps:

1. `admission`: `frob sim run quad-mammal --tier batch-cpu --json` echoes `profile: "lockstep"`, `law: "CL-1"`,
   `precision: "f32"`; `--tier gpu-cuda --profile referee` exits 3 with `FROB-REF-222`.
2. `estimate`: `frob sim estimate quad-mammal --worlds 8192 --tier batch-cpu --json` reports C = 32, R = 160,
   31 kB per world from the byte model (about 35 kB with state), the `step_plan_id`, and never runs physics
   (wall time under one second; no run id created).
3. `drop`: `frob sim run quad-mammal --scene plane --worlds 64 --seconds 2 --tier batch-cpu --seed 7
   --init drop=0.1m --json` → no `Faulted` world; final base height within 1 cm of the standing height; energy
   ledger closes within the single-precision residual bound.
4. `stand`: 10 s under the baseline controller → base height drift under 1 cm, zero `Degraded`.
5. `walk`: 20 s at the baseline's commanded speed → at least 5 m of forward displacement in every world;
   results labelled `provisional`; `integrator: "semi-implicit-euler"`, `h: 1/500`, `decimation: 10`.
6. `determinism`: step 5 repeated, and repeated with `--workers 1`, `8` and `24` → identical per-world digests.
7. `identities`: the same fixture at `--worlds 1`, `256` and `4096` → equal `step_plan_id`; with
   `--newton-iterations 8` → a different `step_plan_id` and equal `model_id`.
8. `batch-independence`: world address 1337 run solo and inside `--worlds 4096` at `--capacity contacts=32`,
   `64` and `128`, in 100 random slot assignments and co-tenancies drawn from seed 11 (1,000 episodes in the
   gate run, 20 in smoke) → identical digest chains. Control build `NC-kin-capacity-tree` (a reduction tree
   shaped by capacity) → at least one chain differs and the step records `control_caught: true`.
9. `path-table`: the same batches with `--jacobian dense` and `--jacobian path-table` → identical digests;
   bytes per world reported for both.
10. `overflow`: the forced-overflow fixture (40 simultaneous contact candidates at C = 32) under
    `--on-overflow refuse` → exit 5, `FROB-REF-722`, repairs listing "raise capacity (new StepPlanId)", "reset",
    "continue-flagged"; under `reset` → the world resets and the episode is recorded as capacity-ended; under
    `continue-flagged` → the run completes with exit 2, `degraded.contact_overflow = 1` and the flag on every
    result of that world. Control build `NC-kin-silent-truncation` → the flag is absent and the assertion
    fails as required.
11. `cayley-bound`: a spinning-body fixture with `--step 20ms` → `FROB-REF-212` with the repairs "substep; use
    the exponential".
12. `parity`: the conformance binary's four rows for each reference robot (kinematics, inverse dynamics, mass
    matrix, forward dynamics) → maximum relative error at most 10⁻¹⁰ in `f64`.
13. `fence`: `frob telemetry query <run> --fields batch_epoch --json` while a long run is in progress (bounded
    wait, then job handle) → every row read belongs to a completed batch.
14. `cancel`: a 60 s run cancelled after 2 s with `frob job cancel` → the receipt reports the last committed
    batch per world; re-running to the same point gives the same digests.
15. `disclosure`: the envelope's disclosure block contains contact capacity, row capacity, mean active contacts
    per world, `Degraded` and `Faulted` counts, profile, precision profile, step and decimation.
16. `replay`: `frob sim replay --world 1337 --tier batch-cpu --json` reproduces the digest chain of world 1337
    from step 5.
17. `gate-record`: writes the measured rows to the bead log `docs/delivery/logs/N16a-18.ndjson` for recording
    by a session that did not implement the work.

Logging. Newline-delimited JSON to `target/e2e-logs/kin_lockstep_batch/<utc-timestamp>.ndjson` and a transcript
beside it. Every line: `ts`, `script`, `bead` ("N16a-18"), `step`, `event` (`start`, `cmd`, `assert`, `metric`,
`refusal`, `end`), the exact command line, exit code, wall time, the envelope's `evidence` block (claim, class,
tier, determinism, identities, seed), measured values with units and thresholds, digests where state is
compared, and on failure the first differing value (step, stage, buffer, world) with the artifact paths and the
replay command. The final `summary` line: assertions passed and failed, controls caught, and
`gates: ["GATE-KIN-03", "GATE-KIN-05", "GATE-KIN-07"]` with the rows touched.

## Acceptance criteria

- [ ] The script exits 0 on a clean build; each of the two control builds makes its step fail.
- [ ] `metric` lines exist for: forward displacement (m, ≥ 5), base height drift (m, ≤ 0.01), digest-chain
      mismatches (count, = 0) for determinism, batch independence and path table, parity errors per robot and
      row (≤ 10⁻¹⁰), degraded counts by reason.
- [ ] Every refusal step logs code, exit code and first repair: `FROB-REF-222` (3), `FROB-REF-722` (5),
      `FROB-REF-212` (3).
- [ ] The log validates against the STD-E2E schema; no private-scene data appears (fixtures are synthetic).
- [ ] The smoke mode completes in under five minutes on eight cores (TARGET).
- [ ] Re-running gives identical digests and metrics.

## Test plan

### Unit tests

Shell-level tests of the script's helpers under the STD-E2E harness: `extracts_digest_chain`,
`compares_chains_reports_first_diff`, `parses_disclosure_block`, `fails_when_control_not_caught`.

### End-to-end script and logging

This bead is the script (Technical approach). Lanes: twice on one machine; worker counts 1, 8 and 24; debug and
release; and, in the device beads, `gpu-cuda` and `gpu-metal` each against its determinism class (bit equality
where the cross-backend class has been attained, the decision-level equivalence test otherwise).

### Known answers and negative controls

| Row | Truth | Tolerance | Control that must fail |
|---|---|---|---|
| KA-344 | Identical digests at capacities 32, 64 and 128 and in any co-tenancy; path table equals dense | exact | A reduction tree shaped by capacity |
| KA-349 | Every forced overflow flagged `Degraded` or refused (`FROB-REF-722`) | exact for the flag | A silent truncation of the contact set |
| KA-360 | `batch-cpu` `f64` against `fs-mbd` on 10⁴ states per reference robot | 10⁻¹⁰ relative | The planted candidates of the parity harness |
| KA-348 | Bytes per world from the byte model (Q: 31 kB at C 32, R 160) | to the kilobyte | The Jacobian term computed with links instead of coordinates |

Metamorphic relations exercised: permuting world indices permutes the results and changes nothing else; adding
inactive worlds or unused capacity changes no active world's digest; splitting a rollout at a snapshot and
resuming equals running it whole (step 14).

## Considerations

- The gate run of step 8 (1,000 episodes × 101 runs) is hours of `batch-cpu` time; it runs in the gate lane and
  its count is recorded, while smoke keeps the mechanism under test on every change.
- If no device family holds batch-composition invariance, M2 can still exit on `batch-cpu`: this script is
  then the record for the Known answer and Parity gates, and device gates are recorded `not run` with the
  reason.
- Flag spellings that the verb registry does not yet fix (`--on-overflow`, `--capacity`, `--jacobian`,
  `--init`, `--workers`) are DESIGN here and are settled with the M2 verb registration.
