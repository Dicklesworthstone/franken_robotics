## Background

The batched step runs ten stages in a fixed order on every world. Stage 5, contact compaction, turns the
narrow-phase candidates of a world into its contact rows by count, exclusive scan and write, inside a capacity
fixed at environment creation. Which contacts are active after compaction, and (after the solve of stage 8)
whether each one sticks, slips or separates, is the world's contact mode for that step.

Three later mechanisms need to ask "did the contact mode of this world change at this step, and is it the same
as that world's": the family lanes of the body-family chapter, which keep a world on a static layout only while
its active rows equal the lane's (a guard test every world-step); the paired-difference estimator, which records
for each pair the first step at which the active contact sets of its two worlds differ (the divergence step) and
truncates there; and the stride-map Jacobian by tangent worlds, which matches events between a nominal world and
its perturbed columns by "the hash of the active contact set with a stick or slip state per contact". Each of
those beads (N17a-12, N17b-22, N22a-30) derives its own signature, one from stage-5 buffers, one from contact-set
digests, one from telemetry events. Three definitions of one fact will disagree at exactly the steps that matter
(a contact made and broken inside one step; a manifold point reordered; a stick-to-slip flip with the set
unchanged), and a divergence reported by one tool will not be reproducible with another.

This bead defines the fact once, computes it in the step, and publishes it. Tier Solid. Rejected alternatives:
letting each consumer hash the buffers itself (the present state); deriving the signature from T1 events after
the fact (events are "contacts made and broken", which loses a contact that is made and broken within one step
and cannot be read inside the step by the lane guard).

## Scope

In: the identity of a contact row (`ContactKey`); the type `ContactSetSig`; the kernel `K-contact-sig` after
stages 5 and 8; the per-world output buffer; the T1 event field and the two T0 counters; the read surface in
`telemetry.query`; the rule for when a consumer may rely on signature equality; tests.

Out: the consumers (family-lane guard N17a-12 and lane key BD-356; divergence step N17b-22; event matching
N22a-30; derivative labels N16b-24), which switch to this type in their own beads; the compaction kernel
(N21a-08); telemetry on devices (BD-207); limit, closure and stiction rows (a lane's full mode signature adds
them in BD-356; this bead is the contact part).

## Technical approach

**1. ContactKey (DESIGN).** A 32-bit identity that does not depend on the order in which candidates were
produced this step: `kind` (2 bits: sample against scene field; primitive pair; thin primitive), `a` (13 bits:
the robot-side sample or primitive index in the model slot's lists), `b` (13 bits: the counterpart primitive
index, or the scene feature class for a field contact), `point` (4 bits: index of the point within a manifold).
The capacities of a shape class fit these widths (13 bits index 8,192 samples or primitives, 0 to 8,191; a
model with more is outside every size bucket; the compile fails loudly if a width would overflow, never
truncates).

**2. ContactSetSig (DESIGN).**

```rust
#[repr(C)]
pub struct ContactSetSig {   // 40 bytes per world
    pub n_active: u32,       // rows after compaction (saturates at capacity; overflow has its own flag)
    pub flags: u32,          // bit 0: capacity overflow this step; bit 1: set changed since previous step;
                             // bit 2: mode changed since previous step
    pub set: [u64; 2],       // identities only
    pub mode: [u64; 2],      // identities with the per-contact state after the solve
}
```

`set[j] = Σ_c mix64(key_c ⊕ SEED_j)` and `mode[j] = Σ_c mix64((key_c ‖ state_c) ⊕ SEED_j)`, sums wrapping in
`u64`, j ∈ {0, 1} with two fixed seeds; `state_c` ∈ {stick, slip, separating} (2 bits) is read from the cone
evaluation of stage 8. `mix64` is the SplitMix64 finalizer (z ^= z >> 30; z *= 0xBF58476D1CE4E5B9; z ^= z >> 27;
z *= 0x94D049BB133111EB; z ^= z >> 31), defined once in `frob-kernels`. A wrapping integer sum is commutative, so
the value does not depend on row order, needs no floating-point atomics and is identical on every tier for the
same set. The empty set has `set = mode = [0, 0]`.

**3. Kernel.** `K-contact-sig`, two entry points: after stage 5 it reads the compacted key column and writes
`n_active`, `set` and flag bits 0 and 1 (comparing with the previous step's `set`, kept in the world's state);
after stage 8 it writes `mode` and flag bit 2. Worlds × contact capacity, integer only, no cross-world data.
Registered in the kernel library with its exactness class (exact integer).

**4. Exact form for decisions that must be sound.** Equality of two signatures is a filter with a stated
collision bound (two independent 64-bit sums: for N comparisons a false equality has probability at most about
N/2¹²⁷ under the mixing assumption). A consumer whose correctness depends on equality (the family-lane guard,
which would otherwise run a world on a layout built for another mode) confirms with the exact form:
`active_keys(world) -> &[ContactKey]`, the compacted key column sorted ascending by a fixed-capacity sorting
network in the same kernel family, compared element-wise. A consumer that only labels or truncates (the
divergence step; event matching) may use the signature and says so in its result.

**5. In the step outputs.** One `ContactSetSig` per world in a buffer of the step plan, valid from the end of
stage 5 (`set`) and the end of stage 8 (`mode`) until the next step. It is a pure function of buffers that the
stage digests already cover, so it is not added to the state digest; the previous step's `set` and `mode`, which
the flags compare against, are world state and are snapshotted and restored.

**6. In telemetry.** T1 (every world): the existing contact events gain the fields `sig_set` and `sig_mode`
(hex), `n_active`, and an event `contact-mode-changed` is emitted when flag bit 2 is set with bit 1 clear (a
stick or slip flip with the set unchanged, which "contacts made and broken" does not show). T0 (per episode):
integer counters `contact_set_changes` and `contact_mode_changes`. T2 (sampled worlds): the sorted key list per
control tick. `frob telemetry query <run> --stream contact --channels n_active,sig_set,sig_mode` reads them
(`telemetry.query` takes a stream and channels; it has no `--events` or `--fields`); the first-divergence report
prints both runs' signatures at the diverging step.

**7. Contract for consumers (stated in `frob-dyn/CONTRACT.md`).** "Active contact set" means the rows after
compaction of stage 5, which on lockstep tiers include candidates inside the speculative margin; it is a
property of (tier, precision, step plan), not of the physics alone. Two tiers may legitimately differ. Under
`strict` the signature is written at each committed sub-interval boundary and the per-step value is that of the
last sub-interval, with `contact_set_changes` counting every change.

**8. Cost.** One pass over at most the contact capacity per world with integer arithmetic; counted inside the
T0-and-T1 budget of 3% of step time (GATE-CHRON-13) and reported as its own line in the stage ledger.

## Acceptance criteria

- [ ] `K-contact-sig` is registered and runs on `batch-cpu` in both precisions and on both device backends when
      they exist; its outputs are bit-identical across tiers for an identical compacted key column.
- [ ] Permuting the candidate order of a world (a conformance hook that reverses the narrow-phase list) leaves
      `set` and `mode` unchanged; adding or removing one key changes `set`; flipping one contact from stick to
      slip changes `mode` and not `set`.
- [ ] Trot fixture of the reference quadruped with four samples per foot: `n_active` alternates between 8
      (diagonal support) and 16 (double support), `contact_set_changes` equals the number of support changes in
      the episode, and flag bit 1 is set at exactly those steps.
- [ ] A contact made and broken within one step (a grazing sample inside the margin for a single step) appears
      as two set changes on consecutive steps in T0 and T1, not zero.
- [ ] Snapshot at step k and restore reproduces flags and counters from k + 1 on; a world's signatures are
      identical solo and among co-tenants.
- [ ] `telemetry.query` returns the fields; the first-divergence report prints them.
- [ ] The exact form agrees with the signature on 10⁶ random key sets (no false inequality), and a planted pair
      of different sets constructed to collide in `set[0]` alone is still distinguished by `set[1]` or by the
      exact compare.
- [ ] The cost line exists in the stage ledger and the telemetry-cost gate's budget is unchanged.
- [ ] `frob-dyn/CONTRACT.md` carries the definition and the consumer rule of items 4 and 7.

## Test plan

### Unit tests

`crates/frob-dyn/tests/contact_sig.rs` and `crates/frob-kernels/tests/k_contact_sig.rs`; real kernels, no
mocks.
- `empty_set_is_zero`; `single_key_value` (a pinned expected value for key 0x0001_0002 under both seeds, written
  down when the constants are frozen).
- `order_independent` (property test over random key multisets and permutations).
- `one_key_changes_set`; `state_flip_changes_mode_only`.
- `manifold_points_distinct`: four points of one box face have four keys and contribute four terms.
- `capacity_overflow_flag`: capacity 16 with 17 candidates sets flag bit 0 and the world is `Degraded`.
- `width_overflow_fails_compile`: a model with 8,193 samples is rejected at lowering naming the field `a`;
  one with 8,192 samples lowers and its last sample's key carries `a` = 8,191.
- `strict_subinterval_counts`: two events inside one base interval give two set changes.
- `strict_retry_no_double_count`: a forced retry of that interval (attempt 1 commits) leaves
  `contact_set_changes` at two and the previous-step signature equal to a clean run's.
- `exact_form_sorted`: `active_keys` is ascending and equals the multiset of the compacted column.
- `snapshot_restores_previous_sig`.

### End-to-end script and logging

`scripts/e2e/kinesis_contact_sig.sh` (sources the STD-E2E helper; NDJSON to
`target/e2e-logs/kinesis_contact_sig/<utc>.ndjson` with a transcript): `frob --json sim run` on the trot
fixture (seed 0, 1,024 worlds, `batch-cpu`, both precisions; the device tiers when present), every run with a
key of its own (`--key kcs-<step>-<precision>-<tier>`, KNOWN_DRIFTS 5); `frob --json telemetry query <run>
--stream contact --channels n_active,sig_set,sig_mode`; a run with the reversed-candidate hook; a paired run that
differs by one ulp in one world and `frob --json telemetry divergence <run a> <run b>` (the run on `batch-cpu`
with `--worlds` is N16b-25's form, `--precision f32|f64` N35-04's, `telemetry.divergence` BD-206's). Lines carry `ts`, `script`, `bead`, `step`, `event`,
command, exit code, wall time, the evidence block (claim, class, tier, determinism, identities, seed); `metric`
lines for `n_active` at the first eight support changes, the change counts against the fixture's expected
count, and the kernel's share of step time; state digests where runs are compared; on failure the first step
whose signature differs and the two key lists. `summary`: assertions passed and failed; `gates: []`.

### Known answers and negative controls

Known answers: 8 and 16 active contacts on the trot fixture; an empty signature of zero; the pinned single-key
value. Negative controls (planted, each must be caught): an order-dependent hash (a rolling hash over the
compacted column) fails `order_independent` under the reversed hook; an XOR in place of the sum makes two equal
keys cancel and fails `manifold_points_distinct` when two points are given the same key; a signature read from
T1 made-and-broken events misses the one-step grazing contact; a kernel that reads a neighbouring world's column
fails the co-tenant digest test. Determinism lanes: twice on one machine; 1 and 8 workers; debug and release;
across tiers, equal signatures whenever the compacted key columns are equal (asserted by teleporting a device
world to the CPU and comparing).

## Considerations

- The signature describes the solver's active set, margin included. A user reading "8 contacts" must not read
  "8 touching points"; the contract and the field documentation say so.
- Consumers were drafted against their own definitions. The four named above (N17a-12, BD-356, N17b-22,
  N22a-30, all M4) now depend on this bead and use the type; each carries in its own tests the check that its
  decisions change at the same steps as this signature on the trot and grazing fixtures, since a test here
  cannot reach code written later. The fixed-mode derivative labels of N16b-24 (M3) still define a
  `ModeSignature` of their own (active set plus each row's law region); composing it from this signature plus
  the row-law bits, as BD-356 does for lanes, is requested of that bead.
- Under `strict` (BD-161) the signature is written by the transaction at each committed sub-interval
  boundary, never from a candidate interval, so a retried attempt changes no counter.
- 40 bytes per world per step in the output buffer; nothing is stored per step outside T1 change events and the
  sampled T2 key lists.
- Limit, closure and stiction rows are not contacts; a lane's mode signature composes this signature with its
  own bits for those rows.
