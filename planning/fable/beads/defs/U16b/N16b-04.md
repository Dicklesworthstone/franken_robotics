## Background

Every number FrankenRobotics hands an agent carries a statement of how far it may be trusted. For results that
come out of a simulation tier, that statement is the **trust label**. A design score or a policy return computed
on a fast tier is `provisional`. It becomes `established` only after a sample of its episodes has been
re-evaluated on a higher tier and found inside the frozen envelope (promotion, BD-263). The pattern is "speculate
low, verify high", with a guard against an optimizer that learns to exploit the fast tier.

DESIGN, reason for making this a type and not a convention: an optimizing agent will find any path by which a
provisional number can be reported as established, and a rule that lives in a style guide is such a path. The
claim product of `frob-core` already takes the weakest evidence class, tier and determinism class among a
result's inputs and joins condition flags by union; this bead adds the trust-ladder status to it and makes
"cite as established" a function that can fail.

ADR-KIN-06 governs the adjudicator: the referee's law is specified in the plan (hard contact with exact Coulomb
friction) and FrankenSim is the implementation consumed through the airlock; where FrankenSim's limits bind, the
system refuses by name and routes the adjudication to the `strict` profile of `batch-cpu`, recording which
adjudicator answered. Reason: sibling limits are facts at a pinned commit, and a result must say which engine
vouched for it.

## Scope

In: the label type, its combination rule, the citation check with `FROB-REF-820`, the adjudicator rule and its
reporting consequence, serialization in the envelope's evidence block, the property test of INV-KIN-08.
Out: deciding a label (promotion: BD-263; model-form: BD-266; energy audit: N16b-14; capacity bias: BD-168).

## Technical approach

**Types (DESIGN sketch, `frob-core::trust`).**

```rust
pub enum Adjudicator { Referee, BatchCpuStrict }          // printed `referee`, `batch-cpu:strict`

pub enum TrustStatus {
    Provisional,                                          // every fast-tier result before promotion
    Established { adjudicators: BTreeSet<Adjudicator> },  // non-empty; set by promotion only
}

pub enum Condition {                                      // members of the claim product's FlagSet
    TierSensitive,        // failed promotion: printed `provisional: tier-sensitive`, both numbers reported
    RefereeUnavailable,   // no adjudicator can complete the stratum: `provisional: referee-unavailable`
    ModelConditional,     // a ranking that flips under a model-form variant
    EnergyCreated,        // created energy over the bound in some window
    CapacityBiased,       // arms differ by more than one percentage point of Degraded or capacity-refused worlds
    ExperimentalExecution // an execution option not yet qualified on this back end
}
```

Labels the plan names and how they print: `provisional`; `established` with the adjudicator named;
`provisional: tier-sensitive`; `model-conditional`; `energy-created`; `capacity-biased`. The positive result of
the model-form check, `model-robust`, is carried as a record on the ranking, not as a condition.

**Combination (INV-KIN-08: the label of a result is the weakest label among its inputs).** Inside
`ClaimProduct::combine`:
1. Status: `Provisional` if any input is `Provisional`; otherwise `Established` with the union of adjudicators.
2. Conditions: the union over inputs. A consumer cannot drop a condition.
3. Blocking: a product whose conditions include `TierSensitive`, `ModelConditional`, `EnergyCreated`,
   `CapacityBiased`, `RefereeUnavailable` or `ExperimentalExecution` has status `Provisional` whatever its inputs'
   status. In particular a result flagged `energy-created` cannot be `established`, and a ranking that contains
   one such result is `model-conditional`.
4. Only `frob-opt`'s promotion (BD-263) can construct `Established`: the constructor is crate-private to
   `frob-core` and exposed through a sealed capability type that promotion alone receives.

**Citation.** `fn cite_as_established(&ClaimProduct) -> Result<EstablishedRef, Refusal>` is the only source of an
`EstablishedRef`. Any verb executor whose contract requires established evidence takes an `EstablishedRef`
argument, so the check cannot be skipped. On failure it returns:

| Code | Name | Raised when | Ranked repairs | Exit |
|---|---|---|---|---|
| `FROB-REF-820` | Label misuse | A result that is not `established` is cited as established, or a `model-conditional` ranking is used to authorize spend | 1. Promote (`frob eval promote <result>`). 2. Run the settling experiment named in the result's `next_actions` | 3 |

The refusal body carries `observed` (the label and conditions), `required` (`established` with no blocking
condition), `affected_claims`, `retry: after-change`. Precedence (DESIGN): when the misuse is a
`model-conditional` result offered for promotion, a build packet or prototype budget, the more specific
`FROB-REF-830` is the code and 820 is not also raised; a `capacity-biased` comparison cited as a verdict raises
`FROB-REF-822`. `FROB-REF-820` covers every other citation of a non-established result.

**The adjudicator rule.** `established` always names its adjudicator. In a class where the referee completes
fewer than 90% of the standard-battery scenarios (TARGET; the threshold of BET-34, read from the coverage report
of BD-213), two further things hold: every report line for that class prints the adjudicator beside the label,
and a comparison between classes whose results have different adjudicators says so in its first line. The
envelope's `evidence` block gains `"trust": { "status", "adjudicators", "conditions" }`.

**Wording.** A provisional result is printed with the word `provisional` beside every number derived from it.
The Fidelity claim's permitted wording is unchanged; nothing in this bead authorizes anything (the three
no-authorization flags stay false).

## Acceptance criteria

- [ ] `TrustStatus`, `Condition` and `Adjudicator` exist in `frob-core`, with no public constructor of
      `Established` outside the promotion capability (a compile-fail test pins it).
- [ ] `ClaimProduct::combine` implements rules 1 to 3; the property test of INV-KIN-08 passes over 10⁵ random
      derivation trees.
- [ ] `cite_as_established` returns `FROB-REF-820` with both repairs for every non-established input, and
      returns 830 or 822 in the two specific cases.
- [ ] Every `sim.run` result on a fast tier serializes `"status": "provisional"`.
- [ ] A report over a class with coverage below 90% prints the adjudicator, and a cross-adjudicator comparison
      states the difference in its first line (golden-text test).
- [ ] Negative control caught: a mutation of `combine` that takes the strongest status makes the property test
      fail.
- [ ] `frob-core/CONTRACT.md` lists the label algebra under invariants and `FROB-REF-820` under refusals.

## Test plan

### Unit tests

`crates/frob-core/tests/trust_label.rs`:
- `weakest_status_wins`: combine(established{referee}, provisional) = provisional.
- `adjudicators_union`: combine(established{referee}, established{batch-cpu:strict}) = established with both.
- `conditions_union_and_block`: combine(established{referee}, established{referee} + energy-created) has
  condition energy-created and status provisional.
- `inv_kin_08_random_derivations`: 10⁵ random trees of depth up to 6 over random leaf labels; the root label
  equals the fold of the rule over the leaves, independent of tree shape and child order.
- `cite_refuses_provisional`: `FROB-REF-820`, exit 3, repairs in order (promote; settling experiment).
- `cite_model_conditional_spend_is_830`, `cite_capacity_biased_is_822`.
- `no_public_established_constructor`: compile-fail (trybuild) on `TrustStatus::Established { .. }` from a
  foreign crate.
- `adjudicator_in_first_line`: golden text of a two-class comparison with coverage 0.95 and 0.60.

### End-to-end script and logging

`scripts/e2e/kinesis_surface.sh` (N16b-35): runs `frob sim run` on `batch-cpu` and asserts `provisional` in the
envelope; from M3, when the first verb that requires established evidence exists, it feeds the result to that
verb and asserts `FROB-REF-820` with exit 3.
Logged: the command line, exit code, the full `evidence.trust` block, the refusal body.

### Known answers and negative controls

- INV-KIN-08 as stated; checked type-level by the claim product and by the property test.
- CX-151 (the referee can adjudicate every scenario): a humanoid crawl exceeds the referee's 21-contact cap; the
  result must be `established{batch-cpu:strict}` at best, never `established{referee}`.
- Negative controls: strongest-status mutation; a consumer that strips conditions (must not compile, since the
  flag set has no removal method).
- Determinism: pure data; identical on every platform.

## Considerations

- The plan's counterexample catalogue and risk register print 80% as the coverage threshold in two places, while
  the gate (GATE-FID-03), BET-34 and the chapter text say 90%. The gate register governs: 90%.
- `provisional: referee-unavailable` comes from the tier-correction ledger's rule for a stratum the referee
  cannot complete; it is included here so that one type carries every label.
- The overlap between 820 ("a model-conditional ranking used to authorize spend") and 830 is resolved by the
  precedence rule above, which is a DESIGN choice of this bead; the model-form gate requires that 830 fires.
- Security: labels are part of the content-hashed evidence block, so an edited label changes the hash and the
  offline auditor rejects it.
- Revisit if a third adjudicator appears (for example the hard-contact batch law); the set type already allows it.
