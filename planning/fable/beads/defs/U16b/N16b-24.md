## Background

Two limits of what the dynamics subsystem claims are stated as rules so that no surface can blur them.

**Derivatives.** A derivative through a step is offered only where it exists: fixed-mode derivatives on smooth
kernels. Near a grazing contact, an ambiguous simultaneity or a changing active set the request is refused with
the offending state, and a one-sided estimate, a generalized derivative or a smoothed surrogate each carry their
own label. Two design rules stand behind this. D-8: every kernel either has a derivative program or a recorded
reason it does not, with the estimator that replaces it. D-15: every derivative that leaves a kernel or an
analysis says whether it is smooth, a saltation composite, a fixed-mode conditional, one-sided, generalized,
smoothed or a finite difference, and a query near grazing or an ambiguous event order is refused by name.
Reason: at make and break of contact the step is not differentiable, and a silently returned number there is a
biased gradient that an optimizer will follow. Design gradients by paired differences belong to the families
subsystem (BD-353); gradients through the converged contact solve are a non-goal of the rigid core before M6 and
have their own Moonshot bead and kill gate elsewhere in this chapter.

**No real-time claim.** Nothing in the dynamics subsystem claims real-time or hardware-in-the-loop behaviour.
Interactive viewing runs one world at presentation rate with physics unchanged. The related non-goal: physics
fidelity is never lowered silently to keep a frame rate or a throughput figure.

Tier: Solid.

## Scope

In: the derivative request interface on a step, the label set, the mode test with its guard, the refusal with
its payload, the labelled alternatives, the kernel-manifest check; the pacing rule for interactive viewing and
its test.
Out: derivative programs of individual kernels (produced by the derivation toolchain per kernel); saltation and
return-map derivatives (the gait beads, BD-334); paired finite differences (BD-353); the step adjoint (Moonshot,
M6).

## Technical approach

**Interface (DESIGN sketch).**

```rust
pub enum DerivLabel { Smooth, FixedMode, OneSided, Generalized, Smoothed, FiniteDifference }
pub struct LabelledDerivative { label: DerivLabel, value: Jacobian, mode: ModeSignature,
                                min_margin: f64, guard: f64, step_plan: StepPlanId }
pub fn step_derivative(world: &WorldState, action: &Action, wrt: Wrt, policy: DerivPolicy)
    -> Result<LabelledDerivative, Refusal>;
```

`DerivPolicy` is `Strict` (refuse off-domain), or an explicit request for one alternative
(`OneSidedBoth`, `Generalized`, `Smoothed { width }`, `FiniteDifference { step }`).

**Mode signature.** For the state at the start of the step, the active set and the region of every row's law:
for a contact row open, stick or slip; for a joint limit, inactive or active; for a stiction row, stuck or
moving. The signature is recorded with every derivative.

**Normalized margin.** For each row, the distance of its deciding quantity from the boundary of its region,
divided by the row's scale (for stick against slip: (μ·fₙ − ‖f_t‖)/(μ·fₙ); for open against closed: gap over the
contact margin; for a limit: distance to the limit over the joint range). `min_margin` is the minimum over rows.
The guard g is a registered numerical parameter (DESIGN default 10⁻³), recorded in the result.

**Rules.**
1. All kernels on the differentiation path must have a derivative program in the kernel manifest. If one does
   not, the request is refused with the kernel's recorded reason and its replacing estimator (D-8).
2. `min_margin > g` and the solve converged: differentiate the smooth kernels with the active set held fixed.
   Label `Smooth` if every row is strictly inside one region over the whole step (no row changed region between
   the start and the end of the step); label `FixedMode` if the derivative is taken with active sets frozen
   while a region change occurred inside the step or the caller asked for a conditional derivative.
3. `min_margin ≤ g` (grazing or a row on a boundary), two or more events in the same finest time cell that no
   symmetry of the nominal motion ties (ambiguous simultaneity), a changing active set across the step under
   `Strict`, or frictional degeneracy: refuse with `FROB-REF-263`. The refusal body carries the offending state
   (world address, step, the rows at fault with their margins) and the directions in which the modes differ.
   Ranked repairs: request `OneSidedBoth`; request a finite difference; move the operating point.
4. Alternatives, each under its own label and never returned unless asked for: `OneSided` (both one-sided values
   returned with their mode signatures), `Generalized` (an element of the generalized derivative, with the set
   of active selections), `Smoothed` (the derivative of a declared smoothed surrogate, with the smoothing
   width, which is a numerical parameter), `FiniteDifference` (central differences at a declared step, with
   both evaluations' mode signatures).
5. A step whose solve did not converge has no derivative: the residual premise fails. It is refused, not
   approximated.
6. A `FixedMode` derivative in stick with respect to a tangential input is exactly zero and is reported with
   the note `uninformative: stick`; a consumer that receives it takes a derivative-free step.
7. The label of a derivative over K steps is the weakest label on its path (order from strongest:
   Smooth, FixedMode, OneSided, Generalized, Smoothed, FiniteDifference), reported with the number of steps
   under each label.

**Refusal row.** `FROB-REF-263`: a derivative is requested near grazing, at an ambiguous event order, across a
change of active set or at frictional degeneracy; the reply carries the offending state and directions; exit 3.

**No real-time rule.** The interactive viewer and any verb option that paces output run one world with the same
`StepPlanId` as a batch run and wait between control intervals to match presentation rate; pacing never changes
h, the iteration count, substeps or tolerance. If the machine cannot keep up, presentation runs slower than
wall-clock and says so; the physics is not altered. Documentation, verb descriptions and reports do not use the
words "real-time" or "hardware-in-the-loop" as claims; a lint over generated docs and verb registry text enforces
it. Performance figures are stated as multiples of real time only as measurements with their disclosure block.

## Acceptance criteria

- [ ] `step_derivative` returns a label, a mode signature, `min_margin` and the guard with every value.
- [ ] Scalar known answer: for Φ(v; z) = ½·m·(v − z)² + ½·g_c·v² the derivative dv₊/dz is m/(m + g_c): 1/4 with
      m = 2, g_c = 6 (label `Smooth`); 1 with the contact open; at the boundary `Strict` refuses with
      `FROB-REF-263` and `OneSidedBoth` returns 1 and 1/4 under the label `OneSided`.
- [ ] Block known answer: a 1 kg block on a floor with μ = 0.5 pushed with force u for one step of 0.01 s
      (breakaway 4.905 N): at u = 4 N, v₊ = 0 and dv₊/du = 0 with the note `uninformative: stick`; at u = 6 N,
      v₊ = 0.01095 m/s and dv₊/du = 0.01 s/kg.
- [ ] A request across a planted change of active set is refused, and the refusal lists the rows and margins.
- [ ] A kernel without a derivative program causes a refusal that names its recorded reason and replacing
      estimator.
- [ ] A world stepped under viewer pacing has the same digests as the same world stepped unpaced, including
      when the machine is artificially slowed.
- [ ] The documentation lint finds no real-time or hardware-in-the-loop claim in generated text.
- [ ] Negative controls caught: a build that returns the fixed-mode value at a boundary without refusing; a
      viewer that drops substeps to hold frame rate (digests change).

## Test plan

### Unit tests

`crates/frob-dyn/tests/step_derivative.rs`:
- `scalar_implicit_function`: 1/4, 1, and the boundary case (refusal; one-sided pair (1, 1/4)).
- `block_stick_and_slip`: 0 with note at u = 4 N; 0.01 s/kg at u = 6 N; v₊ = 0.01·(6 − 4.905) = 0.01095 m/s.
- `refusal_payload`: the body contains world address, step, rows at fault, margins and directions; code 263;
  exit 3; three repairs in order.
- `weakest_label_over_path`: a 16-step path with 15 `Smooth` and one `FixedMode` reports `FixedMode` with counts
  (15, 1).
- `unconverged_has_no_derivative`.
- `fd_agrees_on_smooth_cases`: on 80 random smooth cases the derivative's cosine against central differences is
  at least 0.95 (reported; the threshold belongs to the gates of the gradient beads).
- `kernel_without_program_refused`.

`crates/frob-dyn/tests/presentation_pacing.rs`:
- `paced_equals_unpaced`: digest equality over 10 s of the reference quadruped, with pacing at 1×, 0.25× and
  with a forced 50 ms stall per interval.

### End-to-end script and logging

`scripts/e2e/kinesis_surface.sh` (N16b-35) includes a pacing step: `frob sim run … --present` against the same
run without pacing, comparing final digests; and a lint step over `frob robot-docs` output. Logged: both
digests, the wall-clock ratio, the lint's findings.

### Known answers and negative controls

- The scalar and block cases above (hand-checkable; the regularized-friction variant has a stick derivative of
  0.01/(1 + 49.05) ≈ 2.0 × 10⁻⁴ s/kg at a stiction speed of 1 mm/s, 50 times smaller than in slip, set by a
  numerical parameter, which is why a fixed-mode stick gradient is reported as uninformative).
- A grazing control: a ball whose apex touches a ceiling returns a refusal, not a matrix.
- Negative controls: the two mutations listed in the acceptance criteria.
- Determinism: derivative values are a deterministic function of state; identical twice and across worker
  counts.

## Considerations

- The guard value is a DESIGN default written here; the plan states only that a guard exists. It is a numerical
  parameter and is recorded with every derivative so that its influence can be audited.
- Consumers at M3 and M4: the sensitivity analysis and gait gradients; both must handle a refusal by falling
  back to their own labelled estimators.
- Simultaneous touchdowns that a symmetry of the nominal motion ties (trot, bound, pronk) are ordinary inputs to
  the step, but a derivative across them is still a mode change and follows rule 3.
- The pacing rule interacts with the daemon's scheduler: a paced world may be preempted; preemption must not
  alter its trajectory either, which the batch-composition invariance tests already cover.
