## Background

Two limits of what the dynamics subsystem claims are stated as rules so that no surface can blur them.

**Derivatives.** A derivative through a step is offered only where it exists: fixed-mode derivatives on smooth
kernels. Near a grazing contact, an ambiguous simultaneity or a changing active set the request is refused with
the offending state, and a one-sided estimate, a generalized derivative or a smoothed surrogate each carry their
own label. Two design rules stand behind this. D-8: every kernel either has a derivative program or a recorded
reason it does not, with the estimator that replaces it. D-15: every derivative that leaves a kernel or an
analysis says whether it is smooth, a saltation composite, a fixed-mode conditional, one-sided, generalized,
smoothed or a finite difference, and a query near grazing or an ambiguous event order is refused by name.
Reason: at make and break of contact the step is not differentiable, and a silently returned number there is a
biased gradient that an optimizer will follow. Design gradients by paired differences belong to the families
subsystem (BD-353); gradients through the converged contact solve are a non-goal of the rigid core before M6 and
have their own Moonshot bead and kill gate elsewhere in this chapter.

**No real-time claim.** Nothing in the dynamics subsystem claims real-time or hardware-in-the-loop behaviour.
Interactive viewing runs one world at presentation rate with physics unchanged. The related non-goal: physics
fidelity is never lowered silently to keep a frame rate or a throughput figure.

Tier: Solid.

## Scope

In: the derivative request interface on a step; the assignment of a label of the one label set to every step
derivative this bead returns; the mode test with its guard (the margin form of the grazing condition, for
tiers that locate no events); raising the refusal `FROB-REF-263` with the registered payload and repairs; the
labelled alternatives; the kernel-manifest check; the pacing rule for interactive viewing, the input `--present`
of `sim.run` with its one-world rule, and their tests.
Out, with the bead that has each: the label set itself, the meaning and payload of each of its nine labels,
the four refusal causes, the symmetric-tie exception, the registry record of `FROB-REF-263` (payload fields,
five ranked repairs) and the law suite `laws_c16_labels` (N10b-01, the C-16 specification part; it lands at
M4, after this bead, so it is `related` and not a dependency, and this bead's production types are bound to
its subject trait and must pass its unchanged suite when it lands); the one declaration of the type
`DerivativeLabel` and `Labeled<D>` and the order of labels in a composite (N10a-04, M2, a dependency: this

return-map derivatives (the gait beads, BD-334); paired finite differences (BD-353); the step adjoint (Moonshot,
M6).

## Technical approach

**Interface (DESIGN sketch).**

```rust
// The label type is the workspace's one declaration (N10a-04, after the C-16 contract of N10b-01):
// DerivativeLabel { Smooth, Saltation, DiscreteStep, FixedMode, OneSided, Generalized, Smoothed,
//                   FiniteDifference, Refused }, each with the payload the contract lists.
pub struct LabelledDerivative { label: DerivativeLabel, value: Jacobian, mode: StepModeSignature,
                                min_margin: f64, guard: f64, step_plan: StepPlanId }
pub struct StepModeSignature { contact: ContactSetSig,          // N16ax-01: the one contact-mode signature
                               rows: Vec<(RowKey, RegionBits)> } // limit, closure and stiction rows, sorted
pub fn step_derivative(world: &WorldState, action: &Action, wrt: Wrt, policy: DerivPolicy)
    -> Result<LabelledDerivative, Refusal>;
```

`DerivPolicy` is `Strict` (refuse off-domain), or an explicit request for one alternative
(`OneSidedBoth`, `Generalized`, `Smoothed { width }`, `FiniteDifference { step }`).

DESIGN (the conflict settled, stated in N10b-01 as well). An earlier draft of this bead declared its own enum
`DerivLabel` with six labels and labelled the ordinary step derivative `Smooth`. The plan's rule is that every
derivative carries one label of the set of doctrine D-15 and construction C-16 and that no producer defines a
set of its own, and it maps producers onto the set: "compliant-tier Jacobians with an unchanged active set are
`discrete-step`". So: the label type is `DerivativeLabel`; an `Ok` value of `step_derivative` never carries
`Refused`; a refusal with `FROB-REF-263` is the `Refused` label of the contract (`into_labeled()` maps
`Ok` to `Labeled { value: Some(…), label }` and that refusal to `Labeled { value: None, label: Refused { cause,
state, directions } }`); and the labels this bead can return are `discrete-step`, `fixed-mode`, `one-sided`,
`generalized`, `smoothed`, `finite-difference` and, for a step whose island has no row with more than one
region (no contact, limit or stiction row: nothing can change mode), `smooth`. `saltation` belongs to
event-located derivatives and is never produced here.

**Mode signature.** For the state at the start of the step, the active set and the region of every row's law:
for a contact row open, stick or slip; for a joint limit, inactive or active; for a stiction row, stuck or
moving. The signature is recorded with every derivative. It defines no contact mode of its own: the contact part
is the step's published `ContactSetSig` (N16ax-01, M2), whose `set` identifies the active contacts by
`ContactKey` and whose `mode` adds each contact's state after the solve (stick, slip, separating; "open" here is
`separating`); the non-contact part, which this bead adds, is the sorted list of active limit, closure and
stiction rows with their region bits, as BD-356 composes a lane's key (the type is named `StepModeSignature`
because the lane key's `ModeSignature` of frob-phylum leaves stick and slip out). A change of region over the
step is read from the signature's flag bits (bit 1: set changed; bit 2: mode changed) and the row list; because
the label and the `active-set-change` refusal depend on equality, equality is confirmed with the exact form
(`active_keys(world)` compared element-wise, and the per-row region column that the margin pass already
evaluates), never on the 128-bit sums alone (N16ax-01's rule for consumers whose correctness rests on
equality).

**Normalized margin.** For each row, the distance of its deciding quantity from the boundary of its region,
divided by the row's scale (for stick against slip: (μ·fₙ − ‖f_t‖)/(μ·fₙ); for open against closed: gap over the
contact margin; for a limit: distance to the limit over the joint range). `min_margin` is the minimum over rows.
The guard g is a registered numerical parameter (DESIGN default 10⁻³), recorded in the result.

**Rules.**
1. All kernels on the differentiation path must have a derivative program in the kernel manifest. If one does
   not, the request is refused with the kernel's recorded reason and its replacing estimator (D-8).
2. `min_margin > g` and the solve converged: differentiate the smooth kernels with the active set held fixed.
   Label `discrete-step`, with its payload count of active-set changes equal to 0, if every row is strictly
   inside one region over the whole step (no row changed region between the start and the end of the step);
   label `smooth` only in the rowless case named above; label `fixed-mode` (payload: the frozen mode
   signature) if the derivative is taken with active sets frozen
   while a region change occurred inside the step or the caller asked for a conditional derivative.
3. `min_margin ≤ g` (grazing or a row on a boundary), two or more events in the same finest time cell that no
   symmetry of the nominal motion ties (ambiguous simultaneity), a changing active set across the step under
   `Strict`, or frictional degeneracy: refuse with `FROB-REF-263`. The refusal body carries the offending state
   (world address, step, the rows at fault with their margins) and the directions in which the modes differ,
   in the registered payload of the code (N10b-01's record): `cause` (one of `grazing`, `ambiguous-order`,
   `active-set-change`, `frictional-degeneracy`), the offending state and the perturbation directions. For the
   cause `grazing` the contract's test is the transversality number ν against ν_min, which needs a located
   event; the lockstep tiers locate none, so here the cause is decided by `min_margin` at or below `g`, and
   the payload carries `min_margin` and `g` in the place of ν and ν_min (DESIGN, recorded in N10b-01's payload
   row). Ranked repairs, the five of the registered record: (1) ask for a `one-sided` derivative on a named
   side (`OneSidedBoth` returns both); (2) ask for `finite-difference`; (3) ask for a `smoothed` surrogate with
   a declared parameter; (4) move the operating point away from the boundary; (5) take a derivative-free step.
   Two events tied by a symmetry of the nominal motion are not refused (the contract's symmetric-tie
   exception): the derivative is ordinary on the symmetric subspace and `generalized` off it.
4. Alternatives, each under its own label and never returned unless asked for: `OneSided` (both one-sided values
   returned with their mode signatures), `Generalized` (an element of the generalized derivative, with the set
   of active selections), `Smoothed` (the derivative of a declared smoothed surrogate, with the smoothing
   width, which is a numerical parameter), `FiniteDifference` (central differences at a declared step, with
   both evaluations' mode signatures).
5. A step whose solve did not converge has no derivative: the residual premise fails. It is refused, not
   approximated.
6. A `FixedMode` derivative in stick with respect to a tangential input is exactly zero and is reported with
   the note `uninformative: stick`; a consumer that receives it takes a derivative-free step.
7. The label of a derivative over K steps is the weakest label on its path, in the one composite order of the
   workspace (N10a-04's, from strongest: `smooth`, `saltation`, `discrete-step`, `fixed-mode`, `one-sided`,
   `smoothed`, `generalized`, `finite-difference`; an earlier draft of this bead had `generalized` before
   `smoothed`), reported with the number of steps
   under each label.

**Refusal row.** `FROB-REF-263`: a derivative is requested near grazing, at an ambiguous event order, across a
change of active set or at frictional degeneracy; the reply carries the offending state and directions; exit 3.

**The input `--present` of `sim.run`** (this bead is its owner in VERBS-sim, first milestone M3): a flag that
runs one world paced at presentation rate, physics unchanged, written into the manifest and into no physics
identity (`StepPlanId` and the state digests are those of the unpaced run). With more than one world (`--worlds`
above 1, or `--designs` with more than one slot) it is `FROB-REF-802`, exit 3, `pointer` at `/present`. It is added
to the M2 handler of N16b-25 (a dependency) in this bead's change; before it, the flag is an unknown parameter
(802).

**No real-time rule.** The interactive viewer and any verb option that paces output run one world with the same
`StepPlanId` as a batch run and wait between control intervals to match presentation rate; pacing never changes
h, the iteration count, substeps or tolerance. If the machine cannot keep up, presentation runs slower than
wall-clock and says so; the physics is not altered. Documentation, verb descriptions and reports do not use the
words "real-time" or "hardware-in-the-loop" as claims; a lint over generated docs and verb registry text enforces
it. Performance figures are stated as multiples of real time only as measurements with their disclosure block.

## Acceptance criteria

- [ ] `step_derivative` returns a label, a mode signature, `min_margin` and the guard with every value.
- [ ] Scalar known answer: for Φ(v; z) = ½·m·(v − z)² + ½·g_c·v² the derivative dv₊/dz is m/(m + g_c): 1/4 with
      m = 2, g_c = 6 (label `discrete-step`, zero active-set changes); 1 with the contact open; at the boundary `Strict` refuses with
      `FROB-REF-263` and `OneSidedBoth` returns 1 and 1/4 under the label `OneSided`.
- [ ] Block known answer: a 1 kg block on a floor with μ = 0.5 pushed with force u for one step of 0.01 s
      (breakaway 4.905 N): at u = 4 N, v₊ = 0 and dv₊/du = 0 with the note `uninformative: stick`; at u = 6 N,
      v₊ = 0.01095 m/s and dv₊/du = 0.01 s/kg.
- [ ] A request across a planted change of active set is refused, and the refusal lists the rows and margins.
- [ ] A kernel without a derivative program causes a refusal that names its recorded reason and replacing
      estimator.
- [ ] A world stepped under viewer pacing has the same digests as the same world stepped unpaced, including
      when the machine is artificially slowed; `--present` with more than one world is `FROB-REF-802`, exit 3.
- [ ] The documentation lint finds no real-time or hardware-in-the-loop claim in generated text.
- [ ] Negative controls caught: a build that returns the fixed-mode value at a boundary without refusing; a
      viewer that drops substeps to hold frame rate (digests change).

## Test plan

### Unit tests

`crates/frob-dyn/tests/step_derivative.rs`:
- `scalar_implicit_function`: 1/4, 1, and the boundary case (refusal; one-sided pair (1, 1/4)).
- `block_stick_and_slip`: 0 with note at u = 4 N; 0.01 s/kg at u = 6 N; v₊ = 0.01·(6 − 4.905) = 0.01095 m/s.
- `refusal_payload`: the body contains `cause`, world address, step, rows at fault, margins (`min_margin` and
  `g` in place of ν and ν_min for `grazing`) and directions; code 263; exit 3; the five registered repairs in
  order (one-sided, finite-difference, smoothed, move the operating point, derivative-free step).
- `refusal_causes`: a planted grazing row gives `grazing`; two untied events in one finest cell give
  `ambiguous-order`; a changing active set under `Strict` gives `active-set-change`; μ·fₙ = 0 with a tangential
  input gives `frictional-degeneracy`.
- `symmetric_tie_not_refused`: a pronk whose four touchdowns are tied by the symmetry of the nominal motion
  returns an ordinary derivative on the symmetric subspace and `generalized` off it.
- `rowless_step_is_smooth`, `saltation_never_produced`: a flight step is labelled `smooth`; no input yields
  `saltation`.
- `grazing_ball_refused`: a ball whose apex touches a ceiling returns `FROB-REF-263`, cause `grazing`, not a
  matrix.
- `alternatives_only_on_request`: under `Strict` no `one-sided`, `generalized`, `smoothed` or
  `finite-difference` value is ever returned; each is returned under its own label when asked for, with its
  payload (both mode signatures; selection set; smoothing width; difference step).
- `no_private_label_enum`: `step_derivative` returns `frob_dyn::DerivativeLabel` and the crate declares no other label enum; `refusal_maps_to_refused_label` (`into_labeled()` of a `FROB-REF-263` refusal has no value and the cause).
- `weakest_label_over_path`: a 16-step path with 15 `discrete-step` and one `fixed-mode` reports `fixed-mode` with counts
  (15, 1).
- `unconverged_has_no_derivative`.
- `mode_signature_composes_contact_set_sig`: on the trot fixture the contact part of every derivative's
  `StepModeSignature` equals the step's `ContactSetSig` byte for byte, and a stick-to-slip flip with the set
  unchanged (flag bit 2 set, bit 1 clear) labels the derivative `fixed-mode`, not `discrete-step`; two worlds whose
  `set` sums are forced equal while their key columns differ are told apart by the exact comparison (no
  `discrete-step` label on the forced collision).
- `fd_agrees_on_smooth_cases`: on 80 random smooth cases the derivative's cosine against central differences is
  at least 0.95 (reported; the threshold belongs to the gates of the gradient beads).
- `kernel_without_program_refused`.

`crates/frob-dyn/tests/presentation_pacing.rs`:
- `paced_equals_unpaced`: digest equality over 10 s of the reference quadruped, with pacing at 1×, 0.25× and
  with a forced 50 ms stall per interval.
- `slow_presentation_says_so`: with the forced stall the presentation reports its wall-clock ratio below 1 and
  the step plan is unchanged (h, iterations, substeps, tolerance).
- `present_needs_one_world` (added to N16b-25's `crates/frob-verbs/tests/sim_run_options.rs`): a `sim.run`
  request with `worlds = 2, present = true`, and one with a two-slot `designs` list, is refused with
  `FROB-REF-802`, exit 3, `pointer` `/present`; with one world the `StepPlanId` equals the unpaced run's.

`crates/frob-dyn/tests/no_realtime_claim.rs`:
- `lint_flags_planted_claim`: the lint over generated docs and verb registry text flags a planted "runs in
  real time" and "hardware-in-the-loop" sentence, and accepts "3.2 times real time (measured; disclosure
  block)".

### Known answers and negative controls

- The scalar and block cases above (hand-checkable; the regularized-friction variant has a stick derivative of
  0.01/(1 + 49.05) ≈ 2.0 × 10⁻⁴ s/kg at a stiction speed of 1 mm/s, 50 times smaller than in slip, set by a
  numerical parameter, which is why a fixed-mode stick gradient is reported as uninformative).
- A grazing control: a ball whose apex touches a ceiling returns a refusal, not a matrix.
- Negative controls: the two mutations listed in the acceptance criteria.
- Determinism: derivative values are a deterministic function of state; identical twice and across worker
  counts.

## Considerations

- The guard value is a DESIGN default written here; the plan states only that a guard exists. It is a numerical
  parameter and is recorded with every derivative so that its influence can be audited.
- Consumers at M3 and M4: the sensitivity analysis and gait gradients; both must handle a refusal by falling
  back to their own labelled estimators.
- Simultaneous touchdowns that a symmetry of the nominal motion ties (trot, bound, pronk) are ordinary inputs to
  the step, but a derivative across them is still a mode change and follows rule 3.
- The pacing rule interacts with the daemon's scheduler: a paced world may be preempted; preemption must not
  alter its trajectory either, which the batch-composition invariance tests already cover.
