## Background

`sim.run` is the verb that runs worlds. It exists from M0 for the referee tier on a built-in robot (BD-024). At
M2 the batched step lands on `batch-cpu` and the device tiers, and the verb must let a caller say which step
discipline, which contact law and which design each world runs, and must label what comes back.

One model runs on three tiers under a **step profile**, and the profile is part of the step-plan identity that
every result carries beside its model identity:

| Profile | Tiers | Step discipline | Law | Use |
|---|---|---|---|---|
| `lockstep` | `batch-cpu`, `gpu-cuda`, `gpu-metal` | Fixed step h, ten stages, a fixed number of Newton iterations under masks | CL-1 by default; CL-2 and CL-H as Frontier options | Training, sweeps, design populations. On `batch-cpu` it is the bit-level reference for the GPU. |
| `strict` | `batch-cpu` only | One transaction per accepted interval in `f64`, one world at a time per worker, events located | CL-1 with located events; CL-H once its gate (GATE-TRAC-09) passes | Adjudication where the referee cannot complete; the "step" and "law" arms of model-form checks; debugging |
| `referee` | `referee` only | The transaction with certified queries | Exact Coulomb through FrankenSim's solve, specified as CL-H | Adjudication |

ADR-KIN-02 is the decision behind the table: two step disciplines, chosen by tier. Where a result adjudicates
another, a controller must never observe a half-step and a tunnelled contact must be a detected refusal; where
throughput is the purpose, adaptive splitting would destroy the static launch graph and the fixed shapes that
make batches fast. A request for `strict` or `referee` on a GPU tier is refused (`FROB-REF-222`): a profile is a
promise about what the step did, and a GPU cannot keep this one without giving up fixed shapes.

## Scope

In: the inputs of `sim.run` whose owner VERBS-sim names as this bead at M2 (the positional design on every tier,
`--scene`, `--task` with the construction of the task's environment, `--worlds`, the run length `--seconds`,
`--steps` or `--intervals`, `--episodes`, `--init`, `--controller`, `--tier` beyond `referee`, `--profile` on
every tier, `--on-overflow`, `--fail-fast`), their validation matrix, the admission of `--law` on every tier and
its place in the step plan, the routing of `--designs` to the step on every tier, the label on results, the
identities and capacity disclosure in the result.
Out: the steps themselves (BD-159, BD-161, the referee beads); the per-world slot mechanism behind `--designs`
(BD-169, BD-170); the input `--law` with its law-admission table (N18b-28, M1) and the M1 form of `--profile`
(N16a-02); the vectorized environment itself (BD-192, which owns
`--reset-mode`); the purpose input `--purpose` and the thermal start it selects (N15a-30, which depends on this
bead); the randomization plan compiled at `--task` admission (BD-200, which depends on this bead); `--policy`
(N23a-13); `--present` and the no-real-time rule (N16b-24, M3); the options `--solve-queues`, `--decouple` and
`--solve-path` (later subsections of this chapter, other beads); the referee forms of `--task`, `--controller`
and `--init` at M1 (N16ap4-01, a dependency), whose rules this bead keeps on every tier; the inputs
`--determinism` and `--precision` with the determinism and precision profiles (N35-04, which depends on this bead
and wires its shared admission step into this handler as into BD-024's; the two inputs enter the schema in
N35-04's change, so a build without it answers either as an unknown parameter, `FROB-REF-802`, by VERBS-sim's
rule for an input whose owner has not landed).

Order. The device capstones (BD-172, BD-174) and the chunk and cancellation protocol (N21b-22) run their scripts
through `frob sim run --tier gpu-*`, the tier input this bead extends; so this bead depends on no device bead,
and on a device tier it validates the request and routes it to the backend's step plan.

## Technical approach

**Registry entry.** `sim.run`, kind `run`, first milestone M0 (referee), M2 (all tiers); idempotency key and
budget; bounded synchronous wait, otherwise a job handle with exit 8. Task cluster `simulate`.

**Options of this bead** (the spellings, domains and defaults of VERBS-sim's input tables, which are the
authority; every input enters the run manifest and so `RunId`, and the identity column names the narrower identity
an input also enters).

| Input | Domain; default | Identity | Rules |
|---|---|---|---|
| `design` (positional) | A design path, `DesignId`, design name or catalog model | `ModelId` | Exclusive with `--designs` and `--fixture` (802); at M2 every tier accepts any design (BD-024's M0 form took `g1` only) |
| `--scene <scene>` | A scene identity or name | manifest | |
| `--task <task>` | The task whose environment the run creates | manifest | Builds the environment below; at admission, before any world exists, N24a-16's settled-pose check (no cache for the `ModelId` and task is `FROB-REF-529`, exit 3), as on the referee (N16ap4-01) |
| `--worlds <n>` | Positive integer; default 1 | manifest | Exclusive with `--worlds-per-design` (802) |
| `--seconds <s>` \| `--steps <n>` \| `--intervals <n>` | Exactly one; `--seconds` an exact rational whose product with the step rate is whole (never rounded), `--steps` physics steps, `--intervals` control intervals; with none given, a run with `--task` runs each episode to the task's horizon (N16ap4-01's rule) and a run without a task runs `--seconds 2` (BD-024) | manifest | Two or more are 802 (`pointer` at the second); the manifest records the resolved step count and not the form typed (DESIGN), so the three forms of one length give one `RunId` |
| `--episodes <n>` | Episodes per world; default 1 | manifest | N19c-22 (M3) extends it with the scene schedule |
| `--init <name>[=<value>]` | A named initial condition that the design or fixture declares (`A`, `B`, `free-flight`, `drop=0.1m`) | `ModelId` | An undeclared name, or a value outside the declaration's domain, is 802 naming the declared conditions. With `--task` it is admitted on every tier (DESIGN; N16ap4-01 refuses the pair on the referee at M1 with 802): `EnvRequest.init` names the condition the task's reset starts each episode from, and since the condition enters `ModelId` the settled-pose check runs on that `ModelId` |
| `--controller <c>` | A `ControllerId` or a registered controller name; default `baseline` (the design's baseline controller for the task); the prefixed forms (`fixture:`, `open-loop:`, `baseline+residual:`, `backup`) are their owners' | `ControllerId` | Exclusive with `--policy` (802, from the build that carries N23a-13); an unknown name is 802 |
| `--tier referee \| batch-cpu \| gpu-cuda \| gpu-metal` | Existing at M0 for `referee`; all four from M2 | placement | Planner prefixes and card forms are their owners' (BD-178, N21b-29, N36-31) |
| `--profile lockstep \| strict \| referee` | Default `referee` on the referee tier, `lockstep` elsewhere (N16a-02's M1 input, extended here to every tier) | `StepPlanId` | Matrix below |
| `--law <law>` | N18b-28's input (M1), admitted here on every tier: a row of its law table, spelled as the table spells it: `CL-1`, `CL-2`, `CL-H`, `CL-M`, `CL-1R`, and the film, soil, belt and tyre rows; default by profile as in the table above | `StepPlanId` (the law is part of the step plan, plan §16.6) | 246 when not admitted; a lowercase spelling (`cl-h`) is 802. CL-M (the mapping of an external engine's soft-contact parameters) is for parity runs only and labels its results so |
| `--on-overflow refuse \| reset \| continue-flagged` | What a world does when it exceeds its contact or row capacity; default `continue-flagged` | manifest | `refuse` raises `FROB-REF-722` (exit 5) on `batch-cpu`; on `gpu-cuda` and `gpu-metal` the same trigger raises `FROB-REF-610` (exit 6), from the device fault bead N21b-23 |
| `--fail-fast` | Flag | manifest | A world-level refusal (220, 221, 224, 721 under the continue policies) fails the whole run instead of being reported per world |

- `--designs <list or file>` (owners BD-169 and BD-170; this bead routes it to the step on every tier): per-world
  slots. Each world carries a `model_slot`, a `scene_slot`, a `task_slot` and an optional parameter row. Worlds
  whose slots point at models with the same tree and different parameter values run in one batch with no masks
  and no padding; models with different trees run inside padded capacities where that mechanism is admitted.

**The task's environment (`--task`; DESIGN, the wiring the verb needs).** With `--task`, the handler builds the
run through the vectorized environment of BD-192 (`frob-learn`'s `VecEnv`, the one interface through which
training, evaluation and `sim.run` step batches of worlds): it compiles the task, resolves the controller of
`--controller` (or the policy of `--policy` once N23a-13 lands), and calls the environment constructor with
`EnvRequest { task, designs or design, scene, worlds, episodes, tier, step_plan, reset_mode, purpose, init }`.
`reset_mode` carries `--reset-mode explicit|autoreset-masked` (BD-192's input and domain, default `explicit`),
forwarded unchanged; `purpose` is a field of the request with the default `evaluation`, which the input
`--purpose` of N15a-30 sets when that bead lands (N15a-30 depends on this bead and replaces its earlier
`--mode train|eval` with that input, VERBS-sim). The construction lives in the verb handler's composition code in
`frob-verbs`, which may link `frob-learn`; `frob-dyn` (layer 3) stays below it and holds no environment, scheduler
or estimator. Without `--task` the run steps worlds from their initial condition under the controller with no
reward, termination or reset rules. The randomization block that `--task` adds to the output is BD-200's, compiled
on this admission path before any world exists.

**Validation matrix.**

| Request | Answer |
|---|---|
| `strict` or `referee` profile on `gpu-cuda` or `gpu-metal` | `FROB-REF-222` "Profile not available on tier"; repair: run on `batch-cpu`; exit 3 |
| `lockstep` or `strict` on the referee tier; `referee` profile on `batch-cpu` | `FROB-REF-802` (arguments fail the schema: the pair is outside the registered matrix), with the nearest valid pair as repair; exit 3 |
| a law not admitted on the tier or profile (its gate has not passed, or it is not built) | `FROB-REF-246` "Law not admitted" (read from the law-admission table of N18b-28), naming the gate and the admitted laws; exit 3 |
| two or more of `--seconds`, `--steps`, `--intervals`; `--controller` with `--policy`; an unknown controller name; an undeclared `--init` name; a lowercase `--law`; `--worlds` with `--worlds-per-design`; a positional design with `--designs` or `--fixture` | `FROB-REF-802`; exit 3 |
| a job-submitting run without `--key` | `FROB-REF-805`; exit 3 |
| `--task` on a model with no settled-pose cache for the task | `FROB-REF-529` (N24a-16's check), zero worlds created; exit 3 |

**Result.** Schema `frob.sim.run.out/1`. Per run: `model_id`s, `step_plan_id`, tier, profile, law, h, world-steps
per control interval, Newton iterations and tolerance; capacities (C, R) per shape class; counts of `Degraded`
world-steps by reason; counts of worlds by outcome kind, with numerical faults reported apart from physical
failures; digests; `referee_coverage` (share zero when no background referee ran); and the trust block: every
result from a fast tier (anything but the referee, and `strict` when it is not acting as adjudicator in a
promotion) carries `"status": "provisional"`. With `--task`, the result carries each episode's verdict record
`frob.verdict/1` on every tier (N24c-02's evaluator, as on the referee, N16ap4-01). The `evidence` block is the claim product: class set by the
weakest input, tier, determinism class, model identity, seed; the three no-authorization flags false.

**Refusals this verb can return (registry list).** `FROB-REF-212` (Cayley bound: ‖ω‖·h > 0.2 in a substep;
repairs: substep, use the exponential), `220` (event refinement limit), `221` (transaction exhausted; the world
is `Faulted` with `numerical-fault`), `222`, `223` (no refinement law for a stochastic driver under a
transactional profile), `224` (indeterminate contact), `721` (referee capacity: an island exceeds the referee's
contact cap, or FrankenSim's fixed-witness gate refuses; repairs: patch reduction with its fixture,
`--profile strict`), `722` (capacity overflow, refused), `246` (law not admitted), `529` (no settled-pose cache
for the model and task, N24a-16's check at `--task` admission). World-level refusals (220, 221, 224, 721 under
continue policies) are reported per world in the result and do not fail the whole run unless every world is
affected or the caller asked for `--fail-fast`. The verb's registry row also lists codes that other subsystems
raise through this verb and whose tests are theirs: `247` (determinism class not attainable on the placement,
§35), `601` (device unavailable or lost), `602` (memory estimate above the device budget at admission) and `610`
(capacity overflow under the `refuse` policy on a device tier, N21b-23). This bead's test asserts that each
listed code reaches the caller through `sim.run` unchanged (code, exit, repairs).

**Units.** Rates in any output are stated in world-steps per second or env-steps per second with the decimation
beside them; the two are never mixed. A world-step is one physics step of one world; an env-step is one control
interval of one world.

**Cancellation.** Request, drain to the next commit fence, finalize; published chunks stay, nothing partial is
published as a result.

## Acceptance criteria

- [ ] `frob sim run <design> --tier batch-cpu --profile lockstep --key s-1 --json` returns
      `status: provisional`, the identities and capacities; `--profile strict` returns located-event results with
      the strict rate printed.
- [ ] `--tier gpu-cuda --profile strict` and `--tier gpu-metal --profile referee` return `FROB-REF-222` with the
      repair "run on `batch-cpu`" and exit 3.
- [ ] `--law CL-2` changes the `StepPlanId` and nothing else in the identities.
- [ ] `frob sim run <design> --task <t> --tier batch-cpu --worlds 64 --steps 500 --key s-task --json` builds the
      task's environment through BD-192's `VecEnv` (the manifest names the task and the resolved step count 500),
      `--reset-mode autoreset-masked` reaches the environment, and the result carries BD-200's `randomization`
      block; the same run with `--seconds 1` at h = 2 ms has the same `RunId`. With no length input each
      episode runs to the task's horizon and carries its `frob.verdict/1`; a model with no settled-pose cache for
      the task is `FROB-REF-529`, exit 3, zero worlds created; `--init` with `--task` is admitted.
- [ ] `--episodes`, `--init` and `--controller` behave as their table rows state (defaults 1 and `baseline`;
      undeclared `--init` and two length inputs are 802).
- [ ] `--designs` with 256 parameter variants of one tree runs in one batch and each world's digests equal its
      homogeneous run's.
- [ ] The three overflow policies behave as specified on a forced overflow; `refuse` gives `FROB-REF-722` with
      exit 5 on `batch-cpu`, and the device tiers' `FROB-REF-610` reaches the caller unchanged.
- [ ] Numerical faults are counted apart from physical failures in the result and in the exit summary.
- [ ] The verb is reachable through `frob --json` and `frob-mcp` with the schema above; cancellation is tested
      on `referee` and `batch-cpu` with no leaked worker or buffer. (On `gpu-cuda` and `gpu-metal` the drain with
      no leaked device memory is N21b-22's protocol, asserted by its script through this verb.)
- [ ] Negative control caught: a build that accepts `--profile strict` on a GPU tier and silently runs
      `lockstep` is detected by the profile recorded in `step_plan_id`.

## Test plan

### Unit tests

`crates/frob-verbs/tests/sim_run_options.rs`:
- `profile_tier_matrix`: all 12 (tier, profile) pairs; 5 accepted, 4 refused with 222, 3 refused by schema.
- `default_profile_by_tier`.
- `law_changes_only_step_plan`: identities compared field by field.
- `provisional_on_fast_tiers`: `batch-cpu` lockstep, `gpu-*` → provisional; referee → not provisional.
- `overflow_policies`: on `batch-cpu`, refuse → 722 with exit 5; reset → the world resets and is counted;
  continue-flagged → `Degraded`; the default with no option is continue-flagged.
- `numerical_fault_not_physical`: a forced `FROB-REF-221` world appears under `numerical`.
- `units_never_mixed`: the output schema has separate fields with the decimation.
- `law_not_admitted_246`: `--law CL-H` on `batch-cpu` lockstep before GATE-TRAC-09 returns `FROB-REF-246`, exit 3,
  naming the gate; `--law CL-M` on a non-parity run is labelled `parity-only` in every result.
- `schema_refusals_802`: `--tier referee --profile lockstep`, `--tier referee --profile strict`,
  `--tier batch-cpu --profile referee`, `--seconds 2 --steps 1000`, `--steps 10 --intervals 1`, `--law cl-h` and
  `--init nosuch` on a design that declares `A` and `B` each return `FROB-REF-802` with exit 3.
- `length_forms_resolve`: at h = 2 ms and 10 world-steps per control interval, `--seconds 2`, `--steps 1000` and
  `--intervals 100` record 1,000 steps in the manifest and give one `RunId`; `--seconds 1/3` (not a whole number
  of steps at 500 Hz) is 802 with `pointer` at `/seconds`.
- `task_builds_vecenv`: `--task flat-velocity` on 64 `batch-cpu` worlds constructs one `VecEnv` with the request's
  fields (task, worlds 64, tier, step plan, `reset_mode = explicit`, `purpose = evaluation`, episodes 1);
  `--reset-mode autoreset-masked` is forwarded unchanged; without `--task` no environment is built and no
  randomization block is printed.
- `controller_default_and_named`: no `--controller` binds the design's baseline controller (`ControllerId` in
  the result); a registered controller name binds that one and changes `ControllerId` and nothing in `ModelId`;
  an unknown name is 802.
- `init_named_condition`: `--init drop=0.1m` on a design that declares `drop` changes `ModelId` and the initial
  height by 0.1 m; the same run without it has the design's default condition.
- `task_runs_to_horizon_with_verdict`: on `batch-cpu`, a task of horizon 2 s with no length input runs 2 s per
  episode and each episode carries one `frob.verdict/1`; the same design with no task and no length runs 2 s by
  BD-024's default.
- `task_settled_pose_529`: a model with no settled-pose cache for the task is `FROB-REF-529`, exit 3, zero
  worlds created, on `batch-cpu` as on the referee.
- `init_with_task_admitted`: `--init A --task <t>` on `batch-cpu` reaches `EnvRequest.init`, each episode's reset
  starts from condition A, and the `ModelId` equals that of `--init A` without a task.
- `episodes_per_world`: `--episodes 3` on 4 worlds commits 12 episodes, each with its own world address (episode
  index 0 to 2 within each world), and the default commits one per world.
- `fail_fast_stops_run`: one world of 8 forced to `FROB-REF-221` under `continue-flagged`: without `--fail-fast`
  the run completes with that world reported `Faulted` and seven results; with `--fail-fast` the run fails with
  `FROB-REF-221` and its exit, and no result is published.
- `scene_in_manifest`: `--scene <name>` records the scene identity in the manifest and changes `RunId`, and
  nothing in `ModelId` or `StepPlanId`.
- `missing_key_805`.
- `foreign_codes_pass_through`: 247, 601, 602 and 610, each planted at the boundary where its raiser returns to
  the handler (N35-04's admission step; the device backend's admission and step), reach the `sim.run` caller with
  code, exit and repairs unchanged.
- `cancel_drains_to_fence`: a cancel mid-run on `batch-cpu` stops at the next commit fence; published chunks
  remain, no result is published, and no worker or buffer is leaked (counted).

### End-to-end script and logging

`scripts/e2e/kinesis_surface.sh` (N16b-35) drives every row of the validation matrix and the overflow policies
through the real binary. Logged per command: the command line, exit code, wall time, evidence block, identities,
trust status, capacities, `Degraded` counts, and the refusal body where one is expected.

### Known answers and negative controls

- KA-347: a batch of P parameter variants of one tree equals P homogeneous runs bit for bit on one back end
  (control: the parameter row read after its first use in the step).
- CX-150: a world whose solver gave up is not scored as a failed episode.
- Negative control: the silent-profile-downgrade mutation above.
- Determinism lanes: twice on one machine; across worker counts; debug and release; across back ends, each
  against its class.

## Considerations

- (tier, profile) arithmetic: 4 tiers × 3 profiles = 12 pairs; accepted are referee/referee, batch-cpu/lockstep,
  batch-cpu/strict, gpu-cuda/lockstep, gpu-metal/lockstep.
- The `strict` profile's rate is reported with every strict result; there is no throughput target for it.
- A `strict` result is itself provisional unless it was produced as the adjudicating run of a promotion; the
  label follows the promotion, not the profile.
- OPEN-KIN-1 (default h = 2 ms and 4 Newton iterations with warm start, decided by the fidelity–throughput
  frontier measured at M2) changes defaults printed here, not the interface.
- One trigger, two codes split by tier, as the refusal registries keep them (N16-REF, N21-REF): `FROB-REF-722`
  (capacity overflow, refused; exit 5) on `batch-cpu`, raised by the batched step BD-159, and `FROB-REF-610`
  (capacity overflow under the `refuse` policy; exit 6) on the device tiers, raised by N21b-23 through the same
  function with the same pointer and needed count. The verb's registry row lists both; neither is dropped.
