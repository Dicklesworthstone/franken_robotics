## Background

Every surface of the system (the CLI, the daemon protocol, the MCP tool definitions, the schemas, the refusal
table and the agent documentation) is generated from one registry, `registries/verbs.toml`, owned by
`frob-verbs`, so the surfaces cannot drift. A verb exists for an agent only if its registry entry exists with a
name, a kind, a capability list, input and output schemas, a refusal list, a cost model, a first milestone, task
clusters and examples.

The dynamics chapter owns nine rows of the verb table: three existing verbs that gain options or outputs
(`sim.run`, `sim.estimate`, `eval.promote`) and the `fidelity` cluster. This bead writes those registry entries
and the lints that keep them honest; the executors behind them are other beads. It also carries one question to
the owner, because the plan names one of these verbs in two ways.

Kinds: `read` returns stored or cheaply computed facts and changes nothing; `run` spends compute, takes an
idempotency key and a budget, accepts the bounded synchronous wait and otherwise returns a job handle with exit
8; `admin` cancels, stops, evicts or deletes and needs a capability scope.

## Scope

In: the registry entries, schema stubs with names, refusal lists, task-cluster assignment, examples, the
"not implemented yet" behaviour, the cluster rule, the naming decision record.
Out: executors (the beads named per row below); the M2 and M3 roll-up of all verbs (BD-222, BD-312).

## Technical approach

**Entries (name · kind · first milestone · what it returns · executor bead).**

| Verb | Kind | First | Returns | Executor |
|---|---|---|---|---|
| `sim.run` | run | M0 (referee), M2 (all tiers) | Existing verb. Gains `--profile` (`lockstep`, `strict` or `referee`), `--law`, and per-world slots through `--designs`. Fast-tier results are `provisional`. | N16b-25 |
| `sim.estimate` | read | M2 | Existing verb. Reports capacities, bytes per world, the expected `Degraded` rate and the expected referee coverage for the class. Never runs physics. | N16b-26 |
| `eval.promote` | run | M3 | Existing verb. Applies the label rule and the tier correction; `--method` is `paired`, `dr`, `multilevel` or `segment`. Prints ρ and the higher-tier-only count it replaced. | BD-263, BD-264, N16b-08 |
| `fidelity.ledger` | read | M2 | Ledger rows for a class, quantity and tier pair, with envelopes and their freeze date. | BD-212 |
| the tier-pair rank verb | run | M3 | The rank-agreement record for a design set and tier pair, with the permitted use per stratum. | BD-265 |
| `fidelity.modelform` | run | M3 | `model-robust` or `model-conditional` for a ranking, with the variant that flipped it. | BD-266 |
| `fidelity.energy` | read | M2 | Created-energy totals per world and contact mode for a run, with the worlds that crossed the bound. | BD-208 (data contract in N16b-14) |
| `fidelity.coverage` | read | M2 | Both coverage figures (the referee's own, and the background share) for a run or a class. | BD-213, BD-214 |
| `fidelity.shadow` | admin | M3 in the verb table; delivered M2 | Start, stop and configure the background referee for a job; reports its cost. | BD-214 |

**Entry shape (per verb).** `name`, `cluster`, `kind`, `tier` (S or F), `capabilities` (DESIGN:
`fidelity:read` for the read verbs, `fidelity:run` for run verbs, `fidelity:admin` for `fidelity.shadow`),
`input_schema` and `output_schema` (`frob.<verb>.in/1`, `frob.<verb>.out/1`), `refusals`, `idempotent`,
`cost_model`, `first_milestone`, `task_clusters`, `examples` (at least one `frob … --json` line each).

**Refusal lists (from the chapter's refusal table).** `sim.run`: 212, 220, 221, 222, 223, 224, 721, 722.
`eval.promote`: 820, 821, 811, 830, 721. `fidelity.ledger`: none beyond the protocol class. The tier-pair rank
verb: 537, 721. `fidelity.modelform`: 830 (raised by consumers), 722. `fidelity.shadow`: the scope refusal of
admin verbs. The registry loader rejects an unknown refusal code at load time.

**Task clusters.** A registry cluster is a namespace; what an agent lists at a time is a task cluster of at most
seven tools. The task cluster `fidelity` holds the five `fidelity.*` verbs of the starting assignment
(`fidelity_ledger`, `fidelity_energy`, `fidelity_coverage`, `fidelity_modelform`, `fidelity_shadow`) with
`eval_promote` and `eval_rank_agreement`: seven. `fidelity_modelform` also sits in `inherit`; `sim_run` and
`sim_estimate` in `simulate`; `eval_promote` in `compare`. The limit of seven applies to task clusters, the tools
one agent session lists at a time, and not to registry clusters.

**Not yet implemented.** An entry whose executor has not landed answers `FROB-REF-724` (the verb is not
implemented in this build; exit 5) and is listed by `capabilities` as planned with its first milestone, so the
registry is complete from M2 while verbs arrive through M3.

**The naming question (owner decision, fail-closed default).** The chapter's verb table and one row of the
registry appendix name the tier-pair rank measurement `fidelity.rank` and count six verbs in the `fidelity`
cluster. The registry appendix's one-name-per-verb table, its task-cluster assignment ("its five verbs") and the
seed beads register the rank-agreement record "for rungs and for tier pairs" under `eval.rank-agreement`, and
state that the registry holds no alias and that a lint refuses a second spelling of a registered verb. Both
cannot be registered for one mechanism. Default until the owner decides: register `eval.rank-agreement` only,
accepting a rung pair or a tier pair (`--pair tier:<lo>,<hi>`), first milestone M3 for tier pairs and M4 for
rungs; `fidelity.rank` is not a verb; the `fidelity` registry cluster then has five verbs. If the owner chooses
`fidelity.rank`, it becomes a sixth entry with the same executor and `eval.rank-agreement` is restricted to rung
pairs. The decision is recorded in `docs/adr/ADR-VERB-rank-name.md`; the default costs nothing to reverse
because the executor (BD-265) is the same.

**Second note for the same record.** `fidelity.shadow` prints first milestone M3 in the verb table, while the
M2 exit list and the seed bead deliver the sampled referee and the command at M2. Default: the registry entry
says M2, behind the feature `frontier-shadow`.

**Lints (run by the registry check).** One name per verb; every verb in at least one task cluster; no task
cluster above seven; every refusal code exists; every entry has an example; kinds match behaviour (a `read` verb
takes no idempotency key).

## Acceptance criteria

- [ ] `registries/verbs.toml` contains the eight or nine entries above (per the naming decision) with all
      fields, and loads.
- [ ] `frob capabilities --json` lists them with first milestones; an unlanded verb answers `FROB-REF-724`,
      exit 5.
- [ ] The MCP `tools/list` for the task cluster `fidelity` shows seven tools plus the three base tools, and the
      served list equals the registry (the surface-drift gate's diff is empty for these rows).
- [ ] The lints pass; a planted second spelling of one verb fails the one-name lint; a planted eighth tool in
      the `fidelity` task cluster fails the size lint.
- [ ] The naming ADR exists, states the default in force and what would change, and is cited in the registry
      entry's comment.
- [ ] Every refusal listed for a verb is produced by at least one test of its executor bead (cross-checked by a
      registry test that reads the executor crates' refusal tests).

## Test plan

### Unit tests

`crates/frob-verbs/tests/registry_fidelity.rs`:
- `entries_present_and_complete`: each entry has every required field.
- `kinds_match`: read verbs have `idempotent = true` and no budget; run verbs take a key and a budget; the admin
  verb requires `fidelity:admin`.
- `task_cluster_fidelity_has_seven`.
- `one_name_lint`: adding `fidelity.rank` as a second name for the same executor while `eval.rank-agreement`
  accepts tier pairs fails.
- `unknown_refusal_code_rejected`: a planted `FROB-REF-999` in a list fails the load.
- `not_implemented_answers_724`.

### End-to-end script and logging

`scripts/e2e/kinesis_surface.sh` (N16b-35): `frob capabilities --json`, `frob schema fidelity.ledger --json`,
and an MCP `tools/list` under `session_focus {cluster: "fidelity"}`. Logged: the entries found, the tool count
against seven, the exit codes of unlanded verbs.

### Known answers and negative controls

- The count of tools in the `fidelity` task cluster: seven.
- Negative controls: the second-spelling plant; the eighth-tool plant; the unknown refusal code.
- Determinism: the generated surfaces are byte-identical across two generations (the generated-files check).

## Considerations

- This is the bead where a contradiction in the plan is turned into a decision with a default; nothing else in
  the unit depends on which name wins.
- The refusal table of the chapter also lists the Cayley-bound refusal 212 as an existing code of the algebra
  subsystem; it appears in `sim.run`'s list and is not redefined here.
- Capability scope names are DESIGN defaults to be reconciled with the capability chapter's scope table when
  the full MCP surface lands at M3.
