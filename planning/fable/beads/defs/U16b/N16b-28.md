## Background

The dynamics chapter states eight invariants. An invariant is a property the system must hold in every state,
and the plan's rule is that every invariant has a property test and that every such test has a planted violation
it must catch. The mechanisms the invariants constrain are spread over several beads (the transaction, the retry
ladder, the batched step, parameter variants, labels, the energy audit). This bead is the register: one named
property test per invariant in the conformance harness, each with its planted violation recorded in the
negative-control registry, so that the list of invariants cannot silently lose a member when a mechanism is
refactored.

It does not replace the unit tests inside the mechanism beads; it runs the real components end to end at the
invariant's stated sample size and is the thing a release checks.

## Scope

In: eight property tests with their sample sizes, hooks, planted violations and registry records.
Out: the mechanisms. For INV-KIN-07 the model-form half (a step variant or a tolerance variant leaves physical
parameters unchanged) is asserted by the variant builder (N16b-13, M3), which depends on this bead and registers
`inv_kin_07::digest_before_after_variant` with its planted violation in this register. This bead registers the
retry half; the register lists a registered half with no run as `not run`, never as a pass.

## Technical approach

One test module per invariant under `crates/frob-conformance/tests/inv_kin/`, each registered in the harness
with its tier and execution site.

| ID | Statement | How it is checked here | Planted violation |
|---|---|---|---|
| INV-KIN-01 | No reader observes uncommitted state: every read names a `commit_epoch`. | 10⁵ faults injected between the checks and the commit of a transaction, on the referee and on `strict`, while readers (a controller, a sensor sampler, telemetry, a snapshot) poll; a reader that sees a candidate interval fails the test. Expected count of uncommitted reads: zero. | A reader given a reference to the candidate state |
| INV-KIN-02 | A retry restores the whole restore set. A transaction that commits on attempt k from checkpoint S yields the same digest as a run that started from S with plan k. | Forced retries on 10⁴ random intervals; digests compared. | Packet queues, or warm starts, omitted from the restore set |
| INV-KIN-03 | A random input is a function of its address and interval. It is never redrawn. | The redraw fixture; split, rejoin, reject and migrate on one noise path: the increments over any interval are identical after each operation. | Redraw on rejection: with a fair sign rejected when negative and redrawn once, P(positive) = ½ + ½·½ = ¾ |
| INV-KIN-04 | A world's digests depend on its address and identities only: not on its slot, its co-tenants, the capacity of its buffers or the world count. Determinism class D2. | 1,000 episodes solo and in 100 random co-tenancies and capacities, per back end. | A reduction tree shaped by capacity |
| INV-KIN-05 | Capacity overflow is flagged or refused. No contact is ever dropped silently. | Forced overflow at every capacity; the count identity admitted + not admitted = found holds on every step. | Silent truncation of the contact set |
| INV-KIN-06 | Energy created by the simulator is recorded per step, and a result over the bound is labelled. | The two planted exploits (position-level penetration recovery; pyramid cone): created energy recorded per step, results labelled. | The residual folded into contact dissipation |
| INV-KIN-07 | Physical parameters are unchanged by a retry, a step variant or a tolerance variant. | Parameter digests before and after 10⁴ forced retries (retry half); variant half by N16b-13. | A retry plan that halves a contact stiffness with the sub-interval |
| INV-KIN-08 | The label of a result is the weakest label among its inputs. | Type-level, by the claim product; a property test over 10⁵ random derivations. | `combine` taking the strongest status |

**The restore set** (what INV-KIN-02's digest covers): the physical state (q, v); actuator, thermal and battery
states; contact memory (witness pairs, contact frames, tangential memory, the warm-start impulses and the active
set); per-contact film thickness; clock phases and packet queues; controller and estimator states; the ordinals
of every sample-stamped random draw; terrain edits; the accumulators of the energy ledger; event counters; and
the command cursor. Omitting any of these makes a retried interval differ from a first attempt.

**The noise path of INV-KIN-03.** A driver that acts over an interval is defined on the dyadic tree of the base
interval: the root increment over length ℓ₀ is S = √ℓ₀·Z₀; a node with increment S over length ℓ gives its left
child S/2 + √(ℓ/4)·Z and its right child S minus that, with Z a standard normal keyed by
`(WorldAddr, base_interval, stream_id, level, index)`. The test reads the path, splits it to depth 6, rejoins,
simulates a rejection and a retry, and migrates the world to another slot and back end; every read of the same
node returns the same bits.

**Registry.** Each planted violation is a record in `crates/frob-conformance/registry/controls.toml` (kind `mutation`,
with `seed` naming its counterexample entry where one exists: CX-144 for the redraw, CX-146 for the
capacity-shaped reduction, CX-147 for the energy exploit), attached to the gate that measures the invariant
(GATE-KIN-04 for 01 to 03, GATE-KIN-05 for 04, GATE-KIN-07 for 05, GATE-FID-06 for 06).

**Scale-down.** Each test takes its sample size from an environment variable with the stated value as default,
so that a per-change run uses a tenth and the release run the full count; the count used is logged.

## Acceptance criteria

- [ ] Eight tests exist, named `inv_kin_01` to `inv_kin_08`, registered in the harness with tier (G4 for 01 and
      05, G5 for 02 and 04, G3 or G1 for the others) and site.
- [ ] Each passes at its stated sample size on the referee and `strict` (01 to 03), on `batch-cpu` and each
      admitted device back end (04, 05, 06), and on the host (08).
- [ ] Each planted violation is caught by its test, and the registry records `caught = true`.
- [ ] INV-KIN-01: zero uncommitted reads in 10⁵ injected faults.
- [ ] INV-KIN-02: digest equality on 10⁴ random intervals for every committing attempt index 0 to 3.
- [ ] INV-KIN-04: 1,000 episodes × 100 co-tenancies with identical digests per back end.
- [ ] The harness report lists the eight invariants with their last run, count and result; a missing invariant
      fails the report.

## Test plan

### Unit tests

The eight property tests are the content. Named cases inside them:
- `inv_kin_01::fault_between_check_and_commit`: fault kinds: panic in publish, cancellation request, device
  loss, each at 10⁵/3 injections.
- `inv_kin_02::commit_on_attempt_k_equals_plan_k`: for k = 1 (largest sub-interval halved, bisection forced),
  k = 2 (tolerance tightened by ten, iteration cap doubled, warm start cleared), k = 3 (island solver switched).
- `inv_kin_03::split_rejoin_reject_migrate`.
- `inv_kin_04::solo_vs_cotenancy`, with capacities 32, 64 and 128.
- `inv_kin_05::overflow_every_capacity`.
- `inv_kin_06::planted_exploits_recorded_and_labelled`.
- `inv_kin_07::digest_before_after_retry`; the variant half `inv_kin_07::digest_before_after_variant` is
  N16b-13's test, registered by that bead.
- `register_completeness`: removing one of the eight modules, or one planted control, fails the harness report
  with the invariant's identifier; a `not run` invariant is listed as such and never counted as a pass.
- `inv_kin_08::random_derivations`.

### End-to-end script and logging

`scripts/e2e/kinesis_surface.sh` (N16b-35) runs the suite through the conformance harness
(`cargo test -p frob-conformance --test inv_kin`, with the harness's structured report enabled) at the
scaled-down counts and asserts eight passes and eight caught controls. Logged per invariant: the
identifier, sample size, wall time, result, the control's identifier and whether it was caught, and on failure
the first counterexample (address, interval, digest pair).

### Known answers and negative controls

- KA-341 (forced retry: digest equals the clean run with the same plan), KA-342 (zero uncommitted reads in 10⁵
  injected faults), KA-340 with CX-144 (redraw gives ¾), KA-344 with CX-146 (padding and co-tenancy: identical
  digests at capacities 32, 64 and 128; in `f32` with a = 10⁸, b = −10⁸, c = 1, (a + b) + c = 1 and
  a + (b + c) = 0), KA-349 (overflow flagged or refused), KA-354 with CX-147 (0.125 J per event).
- Each invariant's planted violation is listed in the table above.
- Determinism lanes: the suite itself is run twice and across worker counts; results and counterexamples are
  identical.

## Considerations

- Several of these tests duplicate assertions inside mechanism beads by design: the register is the release's
  view, and a refactor that deletes a mechanism test still leaves the invariant checked.
- Full counts are expensive on the referee (10⁵ faults); the harness schedules them nightly and per release.
- A control that has never failed its test in any recorded run is suspect and is reviewed at each milestone
  exit.
- If a planted violation cannot be built because the hook is absent, the invariant is reported `not run`, which
  is not a pass.
