## Background

Promotion is the capability an agent uses to turn a `provisional` fast-tier result into an `established` one, or
to learn that it is tier-sensitive, and to obtain a higher-tier estimate with an interval. It is North-Star
scenario NS-09 ("the exploit is caught") when the result is a planted exploit. This bead is the end-to-end script
for the whole capability: the label rule, the corrected number, the refusals, the kill-gate fallback and the
adversarial procedures that must not succeed. It is the reduced-scale rehearsal of GATE-FID-02 and GATE-FID-08.

## Scope

In: one script with its assertions and logging.
Out: the mechanisms (BD-263, BD-264, N16b-05, N16b-08) and plants (N16b-06).

## Technical approach

**Script.** `scripts/e2e/promotion.sh`; sources the STD-E2E helper; scratch store under
`target/e2e/promotion/`; non-zero exit on failure; idempotent; `--seed 17`.

**Steps.**
1. `table`: print the promotion table in force for the stratum. Assert promote at (n, k) = (16, 0), (22, 1),
   (29, 2); continue at (15, 0), (21, 1), (28, 2); reject at (2, 2), (3, 2); continue at (4, 2).
2. `honest`: `frob sim run` the honest control on `batch-cpu` (assert `provisional`), then
   `frob eval promote r:… --tier referee --method paired --json`. Assert `established` with an adjudicator
   named, n ≥ 16, the receipt's schedule hash present and written before the first higher-tier episode.
3. `planted-policy`: the planted tier-sensitive policy on its fast configuration, then promote. Assert the label
   `provisional: tier-sensitive`, both numbers present with units, exit 2.
4. `cite-provisional`: feed the unpromoted result to a verb that requires established evidence. Assert
   `FROB-REF-820`, exit 3, repairs "promote" then "run the settling experiment".
5. `unfrozen`: promote in a stratum without an envelope. Assert `FROB-REF-821`.
6. `dr`: `--method dr` on the honest comparison. Assert an estimate with interval, ρ printed, `replaced_count`
   printed, `p_min = 0.05`, every audit probability logged before dispatch.
7. `dr-all-audited`: force every pᵢ = 1. Assert the estimate equals the paired mean exactly (string equality of
   the canonical number).
8. `planted-reversal`: `--method dr` on the tier-reversal pair. Assert the comparison "B beats A" is not
   returned as `established`.
9. `adversaries`: (a) edit the envelope after pairs exist, then promote: assert no promotion; (b) run the
   harness mode that picks audited addresses after reading fast outcomes: assert the estimator refuses the
   round (audit design not persisted before dispatch).
10. `resume`: start a promotion, kill the daemon after five pairs, restart, wait. Assert the receipt equals an
    uninterrupted run's decision fields.
11. `kill-dr-off`: with the tier-correction switch forced off in a scratch policy, `--method dr` returns the
    label with `estimate: null` and the reason `KILL-DR`.
12. `variants` (only when built with the variants feature): `--method multilevel` prints the level table;
    `--method segment` leaves the trust status unchanged and exits 2.
13. `refusal-811`: request a corrected estimate across two kernel versions. Assert `FROB-REF-811`.

**Logging.** NDJSON to `target/e2e-logs/promotion/<utc-timestamp>.ndjson` plus a transcript. Every line carries
`ts`, `script`, `bead`, `step`, `event`, the exact command line, exit code, wall time, the `evidence` block,
measured values with units and thresholds (n and k against the table; θ̂ with its interval; ρ; the
effective-sample share against 0.30), digests where state is compared (schedule hash, receipt digest), and on
failure the first differing value and the paths needed to reproduce. The final `summary` line counts assertions
and names GATE-FID-02 and GATE-FID-08. No private-scene data.

## Acceptance criteria

- [ ] The script passes on `batch-cpu` with `batch-cpu:strict` or the referee as the higher tier, on a machine
      with no GPU.
- [ ] Steps 3, 8 and 9 fail the script if the corresponding protection is removed from the product (checked
      once by running against the registered mutations).
- [ ] Every refusal step logs a `refusal` event with code, exit code and the ranked repairs.
- [ ] The log validates against the STD-E2E schema and names both gates in its summary.
- [ ] Two consecutive runs give identical schedule hashes and receipt digests.

## Test plan

### Unit tests

None of its own. Shell lint and the dry-run mode run per change.

### End-to-end script and logging

As above. Commands: `frob sim run`, `frob eval promote` with each method, `frob cores show dc-01 --json` when
available, `frob fidelity ledger`, daemon stop and start through the STD-E2E helper.

### Known answers and negative controls

- KA-350 (16; 22; two exceedances in the first three reject), KA-364 (the planted policy is caught and labelled
  with both numbers), KA-351 (equal to the paired mean at pᵢ = 1; a planted reversal is not established).
- Negative controls exercised: envelope chosen after the outcomes; audit bits chosen after seeing fast-tier
  failures (CX-324); the planted policy; the planted reversal.
- Determinism lanes: twice; across worker counts; the nightly lane adds debug against release.

## Considerations

- The 10⁴-run null calibrations of the gates are not in this script; they are test binaries of BD-264 and
  N16b-05. The script checks the wiring and the user-visible behaviour.
- Step 10 needs the daemon; in the CLI-only configuration it kills and restarts the CLI process instead and
  resumes by idempotency key.
