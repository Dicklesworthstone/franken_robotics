## Background

Promotion is the capability an agent uses to turn a `provisional` fast-tier result into an `established` one, or
to learn that it is tier-sensitive, and to obtain a higher-tier estimate with an interval. It is North-Star
scenario NS-09 ("the exploit is caught") when the result is a planted exploit. This bead is the end-to-end script
for the whole capability: the label rule, the corrected number, the refusals, the kill-gate fallback and the
adversarial procedures that must not succeed. It is the reduced-scale rehearsal of GATE-FID-02 and GATE-FID-08.

## Scope

In: one script with its assertions and logging.
Out: the mechanisms (BD-263, BD-264, N16b-05, N16b-08) and plants (N16b-06).

## Technical approach

**Script.** `scripts/e2e/promotion.sh`; sources the STD-E2E helper; scratch store under
`target/e2e/promotion/`; non-zero exit on failure; idempotent; seed 17 (`--seed 17` on `sim.run`; `eval.run`'s
battery form takes no seed, its items carrying their own addresses, VERBS-eval; `eval.promote` draws its audit
from the result's addresses and takes no seed). The planted steps
need a conformance build of `frob`; the script checks for it as N16b-33's does and logs those steps `not run`
with the reason when it is absent.

**Steps.**
1. `table`: `frob cores show dc-01 --stratum <the honest control's stratum> --rows --json` (BD-309) prints the
   promotion table in force for the stratum. Assert promote at (n, k) = (16, 0), (22, 1), (29, 2); continue at
   (15, 0), (21, 1), (28, 2); reject at (2, 2), (3, 2); continue at (4, 2); log the table hash and parameters.
2. `honest`: `frob sim run` the honest control on `batch-cpu` (assert `provisional`), then
   `frob eval promote r:… --tier referee --method paired --key pr-2 --json` (every promotion in this script
   carries its own `--key pr-<step>`; a promotion without one is `FROB-REF-805`, asserted once in this step).
   Assert `established` with an adjudicator
   named, n ≥ 16, the receipt's schedule hash present and written before the first higher-tier episode.
3. `planted-policy`: the planted tier-sensitive policy on its fast configuration, then promote. Assert the label
   `provisional: tier-sensitive`, both numbers present with units, exit 2.
4. `cite-provisional`: cite the unpromoted result as evidence in a report, `frob report run <the honest
   control's run> --cite <the unpromoted result> --json` (BD-302: a cited result must stand as established).
   Assert `FROB-REF-820`, exit 3, repairs "promote" then "run the settling experiment"; after step 2's
   promotion the same citation of the promoted result is admitted.
5. `unfrozen`: promote in a stratum without an envelope. Assert `FROB-REF-821`, exit 3, with the first repair
   naming the freeze action (`frob eval run <design> --battery standard --class <c> --tier <slow tier>
   --freeze-envelopes --key <k>`, N16bp1-01).
6. `dr`: `--method dr` on the honest comparison. Assert an estimate with interval, ρ printed, `replaced_count`
   printed, `p_min = 0.05`, every audit probability logged before dispatch.
7. `dr-all-audited`: force every pᵢ = 1. Assert the estimate equals the paired mean exactly (string equality of
   the canonical number).
8. `planted-reversal`: `--method dr` on the tier-reversal pair. Assert the comparison "B beats A" is not
   returned as `established`.
9. `adversaries`: (a) edit the envelope after pairs exist, then promote: assert no promotion, refused with
   `FROB-REF-821` carrying the detail `envelope-hash-mismatch` and both hashes; (b) run the
   harness mode that picks audited addresses after reading fast outcomes: assert the estimator refuses the
   round (audit design not persisted before dispatch).
10. `resume`: start a promotion, kill the daemon after five pairs, restart, wait. Assert the receipt equals an
    uninterrupted run's decision fields.
11. `kill-dr-off`: with the tier-correction switch forced off in a scratch policy, `--method dr` returns the
    label with `estimate: null` and the reason `KILL-DR`.
12. `variants` (only when built with the variants feature): `--method multilevel` prints the level table;
    `--method segment` leaves the trust status unchanged and exits 2. If the pilot PILOT-KIN-01 (N16b-09)
    returned `falsifier-holds`, `segment` is no longer a value of `--method` (N16b-08): the step then asserts the
    schema refusal `FROB-REF-802` for it and logs the pilot's verdict as the reason.
13. `refusal-811`: `--method dr` on the honest result in a scratch ledger whose round is offered background
    outcome pairs recorded under another kernel version (the result's own exceedance pairs are clean, so admission
    passes). Assert `FROB-REF-811`, exit 3, with the repair "referee episodes alone"; and `--method dr` on a round
    with no audited address: `FROB-REF-811` again, the case N29-REF's script also triggers.
14. `refusal-825`: promote a result whose determinism class is D4 (a device run under `mixed-allowed` with an
    uncontrolled reduction order) or unrecorded. Assert `FROB-REF-825`, exit 3, with the repair "re-run under a
    controlled class" (N35-07's Promotion licence, raised by BD-263, and from M3 first by N37-28's evidence
    boundary), and no higher-tier episode dispatched. (The refusal of a `model-conditional` result with `FROB-REF-830` is asserted by
    `scripts/e2e/rank_and_modelform.sh`, N16b-32; the `blocked_by: energy-created` exit 2 is asserted here in
    step 16, and again by `scripts/e2e/created_energy_gate.sh` (N16b-33) once its M3 half runs.)
15. `table-fallback`: in a scratch stratum whose DC-01 table file is removed, `frob eval promote r:… --key
    pr-15a --json` completes on the fixed 30-pair fallback: assert `rule: "fallback"` in the receipt and
    `FROB-REF-871` in `warnings`; the same request with `--require-rule table` under key `pr-15b`: assert
    `FROB-REF-871`, exit 3, and no higher-tier episode dispatched (the ledger's episode count unchanged).
16. `energy-created` (conformance build): run the honest control's task for one episode on `batch-cpu` with
    N16b-15's mutation M1 (position-level penetration recovery: `--conformance-plant
    crates/frob-conformance/fixtures/exploits/plant/penetration-recovery.json`) under key `pr-16a`; the result carries the
    condition `energy-created` (N16b-14). If its stratum has no frozen envelope in the scratch store, freeze one
    first with step 5's repair under key `pr-16f` (the scratch profile holds `fidelity:admin`, which the freeze
    needs, N16bp1-01). Then `frob eval promote r:… --key pr-16 --json`. Assert exit 2,
    `blocked_by: ["energy-created"]`, status `provisional` with the label unchanged, and no higher-tier episode
    dispatched (the ledger's episode count unchanged).
17. `refusal-548`: promote a result in a scratch stratum whose promotion ledger holds exceedance pairs under two
    effort profiles (one row set re-keyed by a changed profile). Assert `FROB-REF-548`, exit 3, `observed` naming
    the differing field and both values, the repair "restart the ledger rows in the new identity", and no
    higher-tier episode dispatched.
18. `adjudicator-and-law`: `frob eval promote r:<the honest result> --adjudicator batch-cpu:strict --key pr-18a
    --json`. Assert a new round with its own schedule hash, the label of that round naming
    `batch-cpu:strict/CL-1`, and step 2's label unchanged. Then `--adjudicator batch-cpu:strict --law CL-H` under
    `pr-18b`: when N18b-28's law table does not admit CL-H on the strict cell, assert `FROB-REF-246`, exit 3,
    naming the gate; when it does, assert a round labelled with `batch-cpu:strict/CL-H` (the log records which
    branch ran). Then `--adjudicator referee --law CL-1` under `pr-18c`: assert `FROB-REF-802`, exit 3.
19. `rounds-*` (the audit rounds of N29b-08 from the user's side): (a) `rounds-dr`: `frob eval promote
    r:<a result of a small stratum> --method dr --key rounds-dr --json` opens a round; log its identifier,
    frontier, g_hash, p_min and n_audited, and assert the referee outcomes are recorded only for audited
    addresses; (b) `rounds-late`: a second process, started after (a) has committed its outcomes, tries to
    register an audit set chosen from the fast-tier failures through the only available path, opening a round
    over addresses of (a) whose outcomes now exist (`frob eval promote r:<the same result> --method dr --key
    rounds-late --json`): assert `FROB-REF-811`, exit 3, `detail` `outcome-before-assignment`, the repair
    "referee episodes alone", and no higher-tier episode dispatched; (c) `rounds-store`: run N29b-08's
    `scripts/e2e/tier_rounds.sh` as a stage and assert exit 0 with its `summary` line logged.

**Logging.** NDJSON to `target/e2e-logs/promotion/<utc-timestamp>.ndjson` plus a transcript. Every line carries
`ts`, `script`, `bead`, `step`, `event`, the exact command line, exit code, wall time, the `evidence` block,
measured values with units and thresholds (n and k against the table; θ̂ with its interval; ρ; the
effective-sample share against 0.30), digests where state is compared (schedule hash, receipt digest), and on
failure the first differing value and the paths needed to reproduce. The final `summary` line counts assertions
and names GATE-FID-02 and GATE-FID-08. No private-scene data.

## Acceptance criteria

- [ ] The script passes on `batch-cpu` with `batch-cpu:strict` or the referee as the higher tier, on a machine
      with no GPU.
- [ ] Steps 3, 8 and 9 fail the script if the corresponding protection is removed from the product (checked
      once by running against the registered mutations).
- [ ] Step group 19 passes: the round of `rounds-dr` is stored with its audit bits, the late round is refused
      with `FROB-REF-811` and `detail` `outcome-before-assignment`, and N29b-08's `tier_rounds.sh` exits 0.
- [ ] Every refusal step logs a `refusal` event with code, exit code and the ranked repairs.
- [ ] The log validates against the STD-E2E schema and names both gates in its summary.
- [ ] Two consecutive runs give identical schedule hashes and receipt digests.

## Test plan

### Unit tests

None of its own. Shell lint and the dry-run mode run per change.

### End-to-end script and logging

As above. Commands: `frob sim run … --seed 17 --key pr-<step>` (with `--conformance-plant <file>` for the plants:
N16b-15's mutation files, and N16b-06's fixtures that build on them),
`frob eval run <design> --battery standard --class <c> --tier <slow tier> --freeze-envelopes --key pr-16f --json`
(step 16, only when the stratum is unfrozen), `frob eval promote r:… --method
paired|dr|multilevel|segment [--adjudicator auto|referee|batch-cpu:strict] [--law CL-1|CL-H] [--require-rule
table] --key pr-<step> --json`, `frob cores show dc-01 --stratum <s> --rows --json` (BD-309),
`frob report run <run> --cite <result> --json` (BD-302), `frob fidelity ledger --class <c> --tier-pair
batch-cpu,referee --json`, daemon stop and start through the STD-E2E helper, and N29b-08's
`scripts/e2e/tier_rounds.sh` (step 19c).

### Known answers and negative controls

- KA-350 (16; 22; two exceedances in the first three reject), KA-364 (the planted policy is caught and labelled
  with both numbers), KA-351 (equal to the paired mean at pᵢ = 1; a planted reversal is not established).
- Negative controls exercised: envelope chosen after the outcomes; audit bits chosen after seeing fast-tier
  failures (CX-324); the planted policy; the planted reversal.
- Determinism lanes: twice; across worker counts; the nightly lane adds debug against release.

## Considerations

- The 10⁴-run null calibrations of the gates are not in this script; they are test binaries of BD-264 and
  N16b-05. The script checks the wiring and the user-visible behaviour.
- Step 10 needs the daemon; in the CLI-only configuration it kills and restarts the CLI process instead and
  resumes by idempotency key.
