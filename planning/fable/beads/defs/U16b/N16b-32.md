## Background

Two user-visible capabilities answer the question "does the order of designs survive?": the rank-agreement
measurement between physics tiers, which decides per stratum what a fast tier may be used for, and the
model-form rank check, which types a ranking of finalists as `model-robust` or `model-conditional`. An agent
running a design campaign meets both: the first before it trusts a fast tier to discard designs, the second
before it spends prototype budget on a winner. This bead is their end-to-end script, the reduced-scale rehearsal
of GATE-FID-04 and GATE-FID-05, including the planted winners that must be caught.

## Scope

In: one script, assertions, logging.
Out: the mechanisms (BD-265, BD-266, N16b-13) and plants (N16b-15).

## Technical approach

**Script.** `scripts/e2e/rank_and_modelform.sh`; STD-E2E helper; scratch store under
`target/e2e/rank_and_modelform/`; non-zero exit on failure; idempotent; `--seed 17`.

**Part A, rank agreement.**
1. `draw`: draw 40 designs of the quadruped class from the corpus by keyed stream. Assert the list hash is in
   the ledger before any score.
2. `score-and-measure`: run the tier-pair rank verb
   (`frob eval rank-agreement --designs <set> --pair tier:batch-cpu,batch-cpu:strict --class quadruped
   --episodes-per-design 16 --json`; the strict profile stands in for the referee at reduced scale). Assert the
   record has τ, top-weighted τ, top-10 recall, their intervals, ρ, and `permitted_use` per stratum.
3. `planted-population`: load synthetic score tables (labelled `synthetic`) with planted rank correlation 0.8,
   0.6 and 0.3. Assert `permitted_use` is `select` (given recall ≥ 0.8), `discard-only` and `not-for-ranking`.
4. `lost-winner`: a planted winner the fast tier scores poorly. Assert recall drops and the report names it.
5. `refuse-order`: ask a campaign step to derive a survivor set from a `not-for-ranking` stratum. Assert
   `FROB-REF-537`.
6. `promote-only-default`: force the class default `promote-only` (N16b-12) in a scratch policy. Assert the
   campaign plan charges every candidate at the higher tier and says so.

**Part B, model-form check.**
7. `variants`: print the variant table for the base configuration. Assert five families, each variant differing
   in exactly one identity component, parameter digests equal for the step and tolerance arms, clocks fixed in
   seconds for the step arm.
8. `genuine`: `frob fidelity modelform --ranking <R_genuine> --k 8 --json`. Assert `model-robust`, overlaps
   ≥ 7 under every admitted variant, energy audit clean, cost share ≤ 0.10, exit 0.
9. `cone-winner`: on R_cone. Assert `model-conditional` with `flipped_by` containing `cone`, both orders
   printed, a settling experiment in `next_actions`, exit 2.
10. `energy-winner`: on R_energy. Assert `model-conditional` with `flipped_by` containing `energy-audit`.
11. `spend-refused`: `frob eval promote` on the conditional result. Assert `FROB-REF-830`.
12. `skipped-check-control`: run the same campaign summary with the check skipped (conformance switch). Assert
    that the planted exploit is then reported as the winner, which shows the check is what removes it.
13. `not-run-arm`: disable the second contact law. Assert the law family is reported `not-run` with its reason
    and that the verdict says which arms ran.

**Logging.** NDJSON to `target/e2e-logs/rank_and_modelform/<utc-timestamp>.ndjson` plus a transcript; every line
with `ts`, `script`, `bead`, `step`, `event`, command line, exit code, wall time, the `evidence` block, measured
values with units and thresholds (τ against 0.7 and 0.5, recall against 0.8, overlap against k − 1, cost share
against 0.10), digests (design-list hash, variant identities), and on failure the first differing value (for
example the first design whose rank crossed the top-k boundary) with artifact paths. The `summary` line names
GATE-FID-04 and GATE-FID-05. No private-scene data.

## Acceptance criteria

- [ ] The script passes on a machine with no GPU.
- [ ] Steps 3, 4, 9, 10 and 12 demonstrate the planted cases; removing the corresponding rule from the product
      makes the script fail.
- [ ] Refusal steps log code, exit code and repairs (`FROB-REF-537`, `FROB-REF-830`).
- [ ] The log validates against the STD-E2E schema; the summary names both gates.
- [ ] Two consecutive runs give identical design-list hashes, records and verdicts.

## Test plan

### Unit tests

None of its own. Shell lint and dry-run per change.

### End-to-end script and logging

As above. Commands: `frob eval rank-agreement` (or `frob fidelity rank` if the naming decision of N16b-27 goes
that way; the script reads the registered name from `frob capabilities`), `frob fidelity modelform`,
`frob eval promote`, `frob opt cascade --plan-only` for the campaign-plan wording.

### Known answers and negative controls

- KA-353 (the two planted winners return `model-conditional`; a genuine winner returns `model-robust`; cost at
  most 10%).
- The permitted-use table on planted populations (0.8 → select, 0.6 → discard-only, 0.3 → not-for-ranking).
- CX-148 and KA-055 (the pyramid grants √2·μ along its diagonals) through R_cone.
- MR-39 (a ranking survives the variants with overlap at least k − 1, or is typed `model-conditional`).
- Negative controls exercised: the lost planted winner; the skipped-check campaign; the planted populations.
- Determinism lanes: twice; across worker counts.

## Considerations

- At reduced scale the strict profile stands in for the referee; the nightly lane uses the referee where it
  completes the scenarios and logs the adjudicator.
- The gate-scale runs (40 designs × 256 episodes per reference class) are BD-265's record; this script checks
  the capability's behaviour and wiring.
