## Background

Two user-visible capabilities answer the question "does the order of designs survive?": the rank-agreement
measurement between physics tiers, which decides per stratum what a fast tier may be used for, and the
model-form rank check, which types a ranking of finalists as `model-robust` or `model-conditional`. An agent
running a design campaign meets both: the first before it trusts a fast tier to discard designs, the second
before it spends prototype budget on a winner. This bead is their end-to-end script, the reduced-scale rehearsal
of GATE-FID-04 and GATE-FID-05, including the planted winners that must be caught.

## Scope

In: one script, assertions, logging.
Out: the mechanisms (BD-265, BD-266, N16b-13) and plants (N16b-15).

## Technical approach

**Script.** `scripts/e2e/rank_and_modelform.sh`; STD-E2E helper; scratch store under
`target/e2e/rank_and_modelform/`; non-zero exit on failure; idempotent; seed 17 as the key of step 1's draw
(`eval.rank-agreement`, `fidelity.modelform`, `eval.promote` and `report.design` take no seed input, so none is
passed to them; each run verb carries its own `--key`).

**Part A, rank agreement.**
1. `draw`: draw 40 designs of the quadruped class from the corpus by keyed stream. Assert the list hash is in
   the ledger before any score.
2. `score-and-measure`: run the tier-pair rank verb
   (`frob eval rank-agreement --designs <set> --pair tier:batch-cpu,batch-cpu:strict --class quadruped
   --episodes-per-design 16 --key ra-2 --json`; the strict profile stands in for the referee at reduced scale).
   Assert the record has τ, top-weighted τ, top-10 recall, their intervals, ρ, and per stratum `mode` with its
   `mode_reason` (the vocabulary shared with the rung ledger, BD-265).
3. `planted-population`: the planted populations of BD-265's certifier check, registered by BD-265 as named
   fixtures and read through the row's `--fixture` input (N23b-35's fixture form: it runs nothing, tier
   `static`, every output labelled `synthetic`): `frob eval rank-agreement --fixture tier-pair-planted-0.8
   --class quadruped --key ra-3a --json`, and the same with `tier-pair-planted-0.6` (`--key ra-3b`) and
   `tier-pair-planted-0.3` (`--key ra-3c`). Assert `mode` is `selective` (given recall ≥ 0.8, calibration valid
   and the planted winner kept), `discard-only` and `uninformative`, with `mode_reason = measured`, that the
   planted τ lies inside each bootstrap interval, and that each output is labelled `synthetic`.
4. `lost-winner`: `frob eval rank-agreement --fixture tier-pair-winner-lost --class quadruped --key ra-4 --json`
   (the planted population whose winner the fast tier scores poorly). Assert recall drops, the report names it,
   and the stratum is `uninformative` with `mode_reason = winner-lost`.
5. `refuse-order`: the consumer side is driven through the consumer's own tests on the records of step 2:
   `cargo test -p frob-opt --test rank_agreement -- refusal_537_on_unmeasured refusal_545_select_on_discard_only
   refusal_548_pooling_two_identities` (BD-265's tests, run here against the ledger of this scratch store).
   Assert: a survivor set derived from an `uninformative` stratum is refused with `FROB-REF-537`; a top-k
   (select) on a `discard-only` stratum with `FROB-REF-545`; pooling the records of two design-set identities into
   one stratum with `FROB-REF-548`; each body logged with its exit code and repairs. The same codes from the
   campaign verb `opt.cascade` (M4) are asserted by that verb's bead BD-352 (its script steps 2 and 5 and its test
   `finalists_from_non_selective_545`), not here.
6. `promote-only-default`: force the class default `promote-only` (N16b-12) in a scratch policy. Assert the
   policy reader returns `promote-only` for the class and refuses a survivor set from fast-tier scores
   (`cargo test -p frob-opt --test kill_rank_tier_reading -- promote_only_blocks_population_order`,
   `FROB-REF-537`). The campaign plan that charges every candidate at the higher tier on such a class is
   `opt.cascade --plan-only`'s, asserted by BD-352 (test `plan_only_promote_only_charges_higher_tier`).

**Part B, model-form check.**
7. `variants`: read the `variants` array of the model-form record that step 8's call returns (issued once, before
   this step's assertions; each entry carries every field of N16b-13's `ModelFormVariant`, BD-266), and log it
   as the variant table of the base configuration. Assert five families, each variant differing
   from the base in exactly one declared component with derived components following their rules (the step
   arm's decimation doubles; the stiffness arms keep τ_d = c/k), parameter digests equal for the step and
   tolerance arms, clocks fixed in seconds for the step arm.
8. `genuine`: `frob fidelity modelform --ranking <R_genuine> --k 8 --budget-share 0.10 --key mf-8 --json` (each
   later model-form call carries its own `--key mf-<step>`). Assert `model-robust`, overlaps
   ≥ 7 under every admitted variant, energy audit clean, cost share ≤ 0.10, exit 0.
9. `cone-winner`: on R_cone. Assert `model-conditional` with `flipped_by` containing `cone`, both orders
   printed, a settling experiment in `next_actions`, exit 2.
10. `energy-winner`: on R_energy. Assert `model-conditional` with `flipped_by` containing `energy-audit`.
11. `spend-refused`: `frob eval promote r:… --key mf-11 --json` on the conditional result. Assert
    `FROB-REF-830` and that `FROB-REF-820` is not also raised (one code per request, N16b-04).
11b. `present-without-condition`: `frob report design <R_cone winner> --json` prints the `model-conditional`
    result with its condition (the flipping variant) and both orders of the ranking (report.design's row; it
    has no option that drops the condition). The refusal side is driven through its test: `cargo test -p
    frob-core --test trust_label -- present_model_conditional_without_condition_is_557` (N16b-04). Assert
    `FROB-REF-557`, exit 3, repairs "run the rank-robustness analysis A-19" then "report the condition", and
    that 820 is not also raised. (The CLI form of the refusal, `report.campaign --compact` dropping the
    condition columns, arrives with that verb at M4.)
12. `skipped-check-control`: the campaign without the check is the ranking as delivered, so no switch is needed
    (no row offers one): read the base order that the model-form records of steps 9 and 10 print beside the
    variant orders, and assert that it puts the planted exploit first, while the verdict of the same record is
    `model-conditional`; this shows the check is what removes it. The product side of the control (a build
    whose check is removed reports the exploit as the winner) is BD-266's negative control. Once
    `opt.cascade` is present (M4), the campaign form of the control is the cascade's (BD-346's) and is not
    asserted here.
13. `not-run-arm`: (a) `frob fidelity modelform --ranking <R_genuine> --k 8 --budget-share 0.005 --key mf-13
    --json`: assert the arms that do not fit are reported `not-run: budget` in the fixed drop order (tolerance
    first, the cone arm last), that the verdict says which arms ran, and exit 2; (b) an unadmitted law arm is
    driven through its test, `cargo test -p frob-opt --test modelform_check -- not_run_arm_reported`. Assert the
    law family is reported `not-run` with its reason.
14. `overflow-policy`: `frob fidelity modelform --ranking <R_genuine> --on-overflow reset --key mf-14 --json` is
    `FROB-REF-802`, exit 3 (`reset` is not offered by the row); the refusals of the overflow itself are driven
    through the verb's tests, `cargo test -p frob-opt --test modelform_check -- overflow_policy
    refusal_list_matches_row`: `FROB-REF-722`, exit 5, on `batch-cpu` under `refuse` (the default), and
    `FROB-REF-610`, exit 6, on a device tier (logged `not run` without the device); each body logged with its
    exit code and repairs.

**Logging.** NDJSON to `target/e2e-logs/rank_and_modelform/<utc-timestamp>.ndjson` plus a transcript; every line
with `ts`, `script`, `bead`, `step`, `event`, command line, exit code, wall time, the `evidence` block, measured
values with units and thresholds (τ against 0.7 and 0.5, recall against 0.8, overlap against k − 1, cost share
against 0.10), per stratum the `mode`, `mode_reason` and the calibration martingale against 20, digests (design-list hash, variant identities), and on failure the first differing value (for
example the first design whose rank crossed the top-k boundary) with artifact paths. The `summary` line names
GATE-FID-04 and GATE-FID-05. No private-scene data.

## Acceptance criteria

- [ ] The script passes on a machine with no GPU.
- [ ] Steps 3, 4, 9, 10 and 12 demonstrate the planted cases; removing the corresponding rule from the product
      makes the script fail.
- [ ] Refusal steps log code, exit code and repairs (`FROB-REF-537`, `FROB-REF-545`, `FROB-REF-548`,
      `FROB-REF-830`, `FROB-REF-557`, `FROB-REF-722`, and `FROB-REF-610` where a device is present;
      `FROB-REF-802` for `--on-overflow reset`).
- [ ] Steps 3 and 4 run on BD-265's four registered fixtures through `--fixture` and every output they print is
      labelled `synthetic`; no step calls a verb outside this bead's dependencies.
- [ ] The log validates against the STD-E2E schema; the summary names both gates.
- [ ] Two consecutive runs give identical design-list hashes, records and verdicts.

## Test plan

### Unit tests

None of its own. Shell lint and dry-run per change.

### End-to-end script and logging

As above. Commands: `frob eval rank-agreement` (or `frob fidelity rank` if the naming decision of N16b-27 goes
that way; the script reads the registered name from `frob capabilities`), `frob fidelity modelform`,
`frob eval rank-agreement --fixture <name>` for the planted populations, `frob eval promote`, `frob report
design` (BD-302), and the tests named in steps 5, 6, 11b, 13 and 14 through `cargo test`.

### Known answers and negative controls

- KA-353 (the two planted winners return `model-conditional`; a genuine winner returns `model-robust`; cost at
  most 10%).
- The mode table on planted populations (0.8 → `selective`, 0.6 → `discard-only`, 0.3 → `uninformative`).
- CX-148 and KA-055 (the pyramid grants √2·μ along its diagonals) through R_cone.
- MR-39 (a ranking survives the variants with overlap at least k − 1, or is typed `model-conditional`).
- Negative controls exercised: the lost planted winner; the skipped-check campaign; the planted populations.
- Determinism lanes: twice; across worker counts.

## Considerations

  completes the scenarios and logs the adjudicator.

  the capability's behaviour and wiring.
