## Background

A kill gate is a decision named in advance, with its trigger, its milestone, the measurement that decides it, its
fallback, and what changes downstream. Each is recorded as an architecture decision record when decided, by a
bead of the unit that owns the mechanism (the rule of the fallback ledger N40-23, followed by N40-24).

The variants table lists a continuum arm, "a rod as a generalized joint", at tier Moonshot, item 8 of the
Moonshot queue, which waits for the rod of item 2 (the coupled multiphysics islands, funded only if KILL-LIVING
does not fire, N19b-20). The plan names no kill gate for it. The gate register carries one all the same:
**KILL-CONTINUUM**, entered by N40-24 through an `introduce` amendment, so that the pilot `PILOT-KIN-06`
(N16bx-03) has a stop rule to name. As registered:

| Field | Value |
|---|---|
| Trigger | The continuum-arm pilot's falsifier holds (item 5 of its protocol) |
| Decided at | M8, mode `pilot-before-funding`: due when the Moonshot slot asks to fund the joint class, and at the latest at the M8 exit |
| Measurement (`reads`) | The record `PILOT-KIN-06` in `crates/frob-conformance/registry/pilots.toml`: the quarter-circle tip error at one segment, the small-force deflections per n against δ·(1 − 1/(4·n²)), the large-deflection tip error and the ω₁ error at n = 8, coordinates per arm for the joint and the proxy at equal error, the verdict |
| Fallback | The labelled serial-chain proxy stays the only form of the variant |
| Downstream if it fires | No joint class `rod-segment` is planned; the variant template keeps `proxy: serial chain` and status `proxy`; the status table names the fallback |

No mechanism bead exists: a `not-fired` decision allows the short plan filed with the pilot record to be proposed
by a dated plan amendment, under the cap of four active Moonshot items. Without this bead the row has no decider
and the M8 exit reads it as missing once funding is requested (N40-30). Tier: Moonshot [M].

## Scope

In: reading the pilot record; evaluating the falsifier's four clauses exactly as registered; the decision record
`docs/adr/ADR-KILL-CONTINUUM-M8.md`; the row's `decision` entry and the owner declaration; the variant template's
status. Out: running the pilot (N16bx-03); any mechanism work; the funding decision under the Moonshot cap
(N10a-02, OPEN-PROG-5).

## Technical approach

**Procedure.**
1. Read `PILOT-KIN-06` (N16bx-03): the measured table per arm and n, the verdict, the reviewer, the receipt, the
   tool pin of the sibling's rod statics and the `protocol_blake3`, which must equal the registered hash. A
   missing result is not a pass: step 3 decides it.
2. Evaluate the four clauses of item 5 from the record alone, each separately: (i) the quarter-circle tip
   position at one segment is off (0.318310, 0.318310) m by more than 10⁻⁹ m; (ii) some small-force deflection
   ratio δₙ/δ differs from 1 − 1/(4·n²) by more than 10⁻⁶ relative, for n in {1, 2, 4, 8}; (iii) at n = 8 the
   large-deflection tip error exceeds 1% of L (5 mm) or the ω₁ error exceeds 5% of 1.06012 rad/s; (iv) the
   16-link proxy reaches the joint's errors at no more coordinates than the joint with 8 segments. Check the
   recorded verdict against the evaluation; a disagreement stops the bead and is reported to the pilot's owner.
3. Name the outcome in N40-03's four: `fired` if any clause holds; `not-fired` if the pilot has a result and none
   holds; `not-reached` if the slot never asked for funding by the M8 exit, including when item 2 was not funded
   because KILL-LIVING fired (the arm is not built without item 2); `deferred` only through an ADR naming the
   later exit and its reason.
4. Write `docs/adr/ADR-KILL-CONTINUUM-M8.md` with N40-03's fields: the kill gate; the milestone; the trigger as
   registered and the `introduce` amendment; each input with its receipt hash beside the clause it decides; the
   outcome and which clause decided; the fallback in force and the variant's name from now on ("continuum arm:
   serial-chain proxy"); the beads re-read, each with N40-03's status (N14b-05, the template: "stands on the
   fallback" on every outcome, since a `not-fired` decision funds no mechanism and the template stays `proxy`);
   the recording session, which did not run the pilot.
5. Registry: the `decision` entry of the row in `registries/gates.toml` (N40-03's form; for this
   `pilot-before-funding` row `receipts` holds the `receipt` hash of the `[[pilot.result]]` read in step 1,
   committed at `receipts/pilots/<hash>.json` by N38a-09's rule, and is empty only on `not-reached`) and the owner
   declaration
   (`[[gate]]`, `role = "owner"`, the ledger's current fields copied, `decision` with each measured value citing
   its receipt) in `frob-dyn`'s `contract.toml`.
6. If `fired` or `not-reached`: the template manifest's pending-decision field names the ADR, and the status table
   row reads "continuum arm: fallback (KILL-CONTINUUM)". If `not-fired`: the ADR records that the short plan may
   be proposed by a dated plan amendment, and the template stays `proxy` until a mechanism lands.

**Fail-closed default until decided.** Every result whose design uses the continuum template carries `proxy:
serial chain` in its evidence labels (N16bx-03, item 8).

**Who decides.** The Dynamics lead prepares the record; a fresh-context session that did not run the pilot
reviews and records it.

## Test plan

### Unit tests
`crates/frob-conformance/tests/kill_gates.rs`:
- `kill_continuum_record_complete`: trigger, inputs, outcome, date and session present; the ADR's path is
  `docs/adr/ADR-KILL-CONTINUUM-M8.md`.
- `kill_continuum_rule`: on synthetic records: every clause inside its bound → `not-fired`; a small-force ratio
  at n = 2 of 0.9375·(1 + 2·10⁻⁶) → `fired` by (ii); 0.9375·(1 + 5·10⁻⁷) → not by (ii); an ω₁ of 1.0011 rad/s
  (5.6% low) → `fired` by (iii); a 16-link proxy reaching the joint's errors at as many coordinates as the joint
  at n = 8 → `fired` by (iv), and at one coordinate more → not by (iv); no result and no funding request at the M8 exit → `not-reached`.

### End-to-end script and logging
`scripts/e2e/kill_continuum.sh` (header `# e2e: bead=N16bp4-03 milestone=M8 labels=kinesis,kill-gate
gates=KILL-CONTINUUM seed=0 needs=cpu plants=not-fired-with-proxy-cheaper`) re-derives the outcome from the
stored record, compares it with the ADR and the gate row, and runs `cargo test -p frob-conformance --test
kill_ledger` (asserting no failure names KILL-CONTINUUM) and `cargo test -p frob-conformance --test kill_gates --
kill_continuum`. It exits non-zero on disagreement. It sources `scripts/e2e/lib.sh` (STD-E2E) and writes
`target/e2e-logs/kill_continuum/<utc>.ndjson`; every line carries `ts`, `script`, `bead`, `step`, `event`, the
exact command line, exit code and wall time; it logs the record's digest, per clause the measured value against
its threshold, the derived and recorded outcomes, and a `summary` naming KILL-CONTINUUM. It writes nothing to the
registry.

### Known answers and negative controls
From N16bx-03's fixture: tip (1/π, 1/π) m; δ = 8.4883 mm with ratios 3/4, 15/16, 63/64, 255/256 for n = 1, 2, 4,
8; ω₁ = 1.06012 rad/s. Negative control (plant `not-fired-with-proxy-cheaper`): an entry `not-fired` while the
stored record shows clause (iv) holding makes the script fail, and `kill_ledger` reports
`outcome-contradicts-measurement`.

## Considerations

- Clause (iv) compares coordinate counts at equal error, as the record states them per arm, not at equal n; the
  counts are read from the record and never recomputed here.
- A `not-fired` decision funds nothing by itself: the arm still needs a free slot under the cap and item 2.
