## Background

Kinesis (crate `frob-dyn`) advances state in time. On the referee tier and on the `strict` profile of `batch-cpu` each world advances by one **transaction per accepted physics interval**: a checkpoint of the whole restore set is taken, a candidate interval is built beside the committed state, a list of checks runs, and the interval either commits in one step (the `commit_epoch` advances) or leaves no trace. The restore set and the commit fence are bead BD-081; event location on the dyadic grid and the coupled impulse per island are BD-082. This bead supplies what happens when the checks fail: the **retry ladder**.

A candidate interval can fail its checks for reasons that have nothing to do with the robot: a Newton solve that did not reach tolerance, an event bracket that was too coarse, a warm start that led the solver into a bad basin. The transaction then restores the checkpoint and tries again under a different **numerical plan**. Three rules make this safe, and each has a rejected alternative behind it.

1. **Retries change numerical parameters only (ADR-KIN-05).** Physical parameters (masses, inertias, lengths, gear ratios, contact stiffness, dissipation time, friction coefficients, actuator-card parameters, clock periods) and numerical parameters (sub-interval length, event-location method, solver tolerance, iteration cap, warm start, solver choice) are declared separately. Reason: a smaller time step must not silently stiffen a fitted foot spring; a stiffness that scales with h is a numerical parameter disguised as a physical one and makes step-halving tests meaningless. Rejected: "make the step easier" by softening contact or shrinking friction on retry, which would change the physics that the result claims.
2. **A retry restores everything and redraws nothing.** A retried interval must equal a first attempt made under the same plan (INV-KIN-02), and a random input is a function of its address and interval, never redrawn (INV-KIN-03). Rejected: redrawing noise on a rejected step. Hand-checkable counterexample (CX-144): let the input be a fair sign and reject the step whenever it is negative, then redraw once; the accepted sign is positive with probability ½ + ½·½ = ¾. Rejection that redraws biases the law.
3. **A numerical failure is not a physical failure.** A world that exhausts the ladder is `Faulted` with cause `numerical-fault`; it is never scored as a fall, slip or collision (CX-150), and summaries state how many worlds were excluded for this cause. Rejected: counting a solver give-up as a failed episode, which would let a design lose (or a rival win) on solver behaviour.

The ladder is a deterministic function of state, so a replay repeats the same attempts. Tier: Solid [S]. It serves the Fidelity claim: the referee adjudicates other tiers only if its own steps are reproducible and its refusals are named. The `strict` profile (BD-161, M2) reuses this ladder unchanged.

## Scope

In: the `NumericalPlan` type and the four-rung ladder; the retry loop (steps T2, T3, T7 of the transaction); the physical/numerical parameter partition with its digest check (INV-KIN-07); the attempt index in the committed result; terminal handling (`Faulted`, `numerical-fault`, `FROB-REF-221`); the fault-injection seam for forced retries; integration of the dyadic refinement law (N16c-01) so that a retry re-reads the same noise path; the three referee rows of GATE-KIN-04 named in the seed (forced-retry digests, refinement statistics, the redraw mutation).

## Technical approach

**Types (DESIGN; fixes intent, not signatures).** Module `crates/frob-dyn/src/transaction/retry.rs`.

```rust
pub enum IslandSolver { SemismoothNewton, FixedPointCone }
pub enum WarmStart { Keep, Clear }
pub struct NumericalPlan {
    pub max_subinterval_level: u8,   // largest admitted sub-interval is ℓ₀ / 2^level
    pub force_bisection: bool,       // event location by bisection on the dyadic grid only
    pub solver_tol: ImpulseTol,      // typed: N·s for impulses, N for forces; never one number for both (C-14)
    pub iter_cap: u32,
    pub warm_start: WarmStart,
    pub island_solver: IslandSolver,
}
pub struct RetryLadder { pub n_retry: u8 /* 3, OPEN-KIN-5 */ }
impl RetryLadder { pub fn plan(&self, attempt: u8, declared: &NumericalPlan) -> NumericalPlan; }
pub enum StepOutcome {
    Committed { epoch: u64, attempt: u8, events: Vec<EventRecord>, checks: CheckReport },
    Faulted { refusal: Refusal },    // FROB-REF-220, -221 or -224; nothing from the interval is published
}
```

**The ladder (DESIGN).** `attempt` runs 0 ..= N_retry with N_retry = 3.

| Attempt | Plan | Failure it addresses |
|---|---|---|
| 0 | The declared plan | — |
| 1 | Halve the largest admitted sub-interval (`max_subinterval_level + 1`) and force bisection for event location | A missed or badly bracketed event; a sub-interval too long for the active-set assumption |
| 2 | Tighten the solver tolerance by ten, double the iteration cap, clear the warm start | A solve stopped short; a warm start in a bad basin |
| 3 | Switch the island solver from semismooth Newton to the fixed-point cone iteration | A Newton failure on a degenerate island |

The plan text lists what each attempt changes and does not say whether the changes accumulate. This bead fixes: **they accumulate** (attempt 2 keeps attempt 1's halving and bisection; attempt 3 keeps both). Reason: each rung cures a different cause, and dropping an earlier repair can reintroduce the failure it cured. The choice is written in `CONTRACT.md` and the ladder's constants are hashed into the step-profile part of the `StepPlanId`, so two ladders never share an identity.

**The fixed-point cone iteration (attempt 3).** For an island with contact velocity u = (uₙ, u_T), friction coefficient μ and impulse λ in the cone 𝒦_μ = {‖λ_T‖ ≤ μ·λₙ}: (1) set s = μ·‖u_T‖ from the pre-event state; (2) solve the convex cone program for λ with the shifted velocity û = (uₙ + s, u_T), s held fixed; (3) recompute s from the solution; (4) stop when the natural-map residual ‖λ − Π_𝒦(λ − û)‖ is at most the plan's tolerance (TARGET 10⁻⁶ for evaluation), or fail the attempt at `iter_cap` passes. The term s is what makes hard Coulomb friction non-associated; holding it fixed makes each pass convex.

**The loop.** Numbered as in the transaction.

1. T1: `S ← checkpoint(X_committed)`; record `ParamDigest` = BLAKE3 over the canonical bytes of the world's physical parameters (model, interface cards, clock periods).
2. T2: for `attempt` in 0 ..= N_retry: `plan ← ladder.plan(attempt, declared)`.
3. T3: `X ← restore(S)` (the whole restore set: (q, v); actuator, thermal and battery states; contact memory with witness pairs, frames, tangential memory, warm-start impulses and active set; film thickness; clock phases and packet queues; controller and estimator states; ordinals of sample-stamped draws; terrain edits; energy-ledger accumulators; event counters; the command cursor). `WarmStart::Clear` zeroes the warm-start impulses after the restore, as a plan action.
4. T4 runs under `plan` (BD-082). Interval-acting noise is read from the refinement law by address (N16c-01): a finer sub-interval reads children of the same tree nodes, so attempt 1 refines the path the earlier attempt saw.
5. T5 checks: sub-intervals sum to (t0, t1) exactly; solver residuals; joint limits and closures inside tolerance; group-membership error; energy-ledger residual; path admission (no missed contact on the swept path, inside ε_g); loads and currents inside admitted domains; event count.
6. T6: all pass → commit; `attempt` is published with state, impulses, sensor inputs and diagnostics. Assert `ParamDigest` unchanged (INV-KIN-07).
7. T7: after the last attempt, `restore(S)`; mark the world `Faulted`, cause `numerical-fault`, refusal `FROB-REF-221`; publish nothing from the interval.

**Terminal refusals that do not consume attempts.** `FROB-REF-220` (an event cannot be bracketed within L_max = 16, or more than E_max = 64 events fall in the base interval) and `FROB-REF-224` (no solution, or several distinct post-event motions) end the transaction at once through the same restore: a finer plan cannot cure an accumulation point or an indeterminate configuration. `FROB-REF-221` — meaning: every numerical plan failed its checks; repairs, ranked: teleport the world to `batch-cpu` and inspect; accept the `Faulted` world as excluded. Exit code 3 when it is the envelope's refusal; inside a multi-world run it is a per-world record and the envelope exits 2 with the count.

**Determinism.** The ladder reads no clock, thread identity or worker count; `plan(attempt, declared)` is pure. Outputs are class D2 on the referee (same-platform determinism; cross-ISA waits on upstream work item FD-FSIM-07 in FrankenSim's repository).

**Evidence and ledger.** Every committed interval records `attempt`; a run's envelope carries the attempt histogram and `faulted.numerical_fault` (count and world addresses). Outcome kind is `numerical`: the verdict is unknown, the world stays in the denominator and is listed as excluded (a summary that omits it is refused by `FROB-REF-865`).

**Fault-injection seam.** Compiled only under the `chaos` cargo feature: `ForceRetry { world, base_interval, fail_attempts_below: k }` makes T5 report failure for attempts < k. A plan floor `start_attempt = k` runs the ladder from rung k. Both are used only by tests.

## Acceptance criteria

- [ ] `frob-dyn` contains the ladder, plan type and loop; `CONTRACT.md` (ten sections) states the four rungs, their accumulation, N_retry = 3 and the parameter partition.
- [ ] Forced-retry digests equal (GATE-KIN-04 row; INV-KIN-02): on 10⁴ random intervals a transaction that commits on attempt k from checkpoint S has the same state digest as a run started from S with plan k, for k = 1, 2, 3. TARGET: zero mismatches.
- [ ] Refinement statistics inside 3σ at 10⁶ draws under forced retries (GATE-KIN-04 row; PO-KIN-04): half-interval variance ℓ/2, zero covariance, halves sum to the parent.
- [ ] The redraw mutation is caught (GATE-KIN-04 row; INV-KIN-03): the planted redraw-on-reject build fails the fair-sign fixture with P(positive) = ¾.
- [ ] The restore-set mutations are caught: omitting packet queues, and omitting warm starts, each changes a forced-retry digest.
- [ ] Physical-parameter digests are equal before and after every attempt on 10⁴ forced retries (INV-KIN-07); a planted retry that scales contact stiffness with the sub-interval fails.
- [ ] A world that fails all four plans is `Faulted` with `numerical-fault` and `FROB-REF-221`, publishes nothing, is absent from every physical failure class and present in the excluded count.
- [ ] The same run replayed commits on the same attempt at every interval (attempt histograms equal).
- [ ] `frob sim run --tier referee --json` exposes the attempt histogram and the numerical-fault count; cancellation between attempts leaves the committed epoch unchanged.
- [ ] The three rows are recorded in `registries/gates.toml` under GATE-KIN-04 (referee) with measured values, by a session that did not implement the bead.

## Test plan

### Unit tests

`cargo test -p frob-dyn`, no mocks; fixtures labelled `synthetic` are two sliders, a ball and a wall.

- `ladder_plans_are_pure_and_cumulative`: `plan(1)` has level + 1 and bisection; `plan(2)` has tolerance ÷ 10, cap × 2, `Clear`, and keeps rung 1; `plan(3)` has `FixedPointCone` and keeps rungs 1 and 2.
- `forced_retry_digest_equals_clean_plan_k` (property, 10⁴ intervals, seeds explicit): digests equal for k = 1, 2, 3.
- `retry_replays_same_attempts`: two runs of a fixture with naturally failing intervals give equal attempt sequences.
- `param_digest_invariant` (property): `ParamDigest` equal across attempts; mutant `stiffness ∝ 1/ℓ` detected.
- `exhaustion_is_numerical_fault`: a fixture whose checks cannot pass ends `Faulted`, `FROB-REF-221`; committed epoch and state digest equal the checkpoint.
- `refusal_220_and_224_are_terminal`: an accumulation fixture (a ball with restitution bouncing to rest inside one base interval) ends with `FROB-REF-220` after exactly one attempt.
- `noise_path_refined_not_redrawn`: with a Brownian driver, the increment over the base interval is identical on attempts 0 and 1, and attempt 1's two half-increments sum to it.
- `tolerance_units_typed`: a force tolerance passed where an impulse tolerance is required fails to compile (compile-fail test).

### End-to-end script and logging

`scripts/e2e/kin_retry_refinement.sh` (bead N16c-02) runs `frob sim run --tier referee --profile referee --json` on the slider and ball fixtures with and without forced retries, compares digests, and logs per the STD-E2E helper: one NDJSON line per command and assertion with the command line, exit code, wall time, the envelope's evidence block, the attempt histogram, digests and, on failure, the first differing field and the snapshot paths.

### Known answers and negative controls

- KA-341: forced retry digest equals the clean run with the same plan, 10⁴ intervals, exact. Controls: packet queues omitted from the restore set; warm starts omitted.
- KA-340: dyadic refinement, child variance ℓ/2, halves uncorrelated, sum equals the parent, 3σ at 10⁶ draws. Control (CX-144): redraw on rejection gives P(positive) = ¾ against ½.
- CX-150: a world whose solver gave up is not a failed episode; test `exhaustion_is_numerical_fault`.
- Metamorphic: a retry equals a clean run with the same plan; splitting an interval and rejoining leaves the noise increment unchanged.
- Determinism lanes: twice on one machine; debug and release; 1 and 24 workers; each against class D2.

## Considerations

- OPEN-KIN-5 owns N_retry, L_max and E_max (defaults 3, 16, 64; decided by the refusal rate on the M1 fixtures; fail-closed default is refusal). Changing N_retry changes the ladder identity.
- OPEN-KIN-4: which law `strict` runs once the hard-contact law is admitted does not change the ladder; rung 3's solver exists for both.
- Risk: a ladder that hides a real modelling defect behind retries. The attempt histogram is reported so that a fixture needing rung 3 on most intervals is visible.
- Risk (RISK-31): the referee cannot complete scenes where decisions are made; exhaustion and capacity refusals feed the referee coverage figure, and the `strict` profile is the named alternative adjudicator.
- Performance: a retry costs one more interval; no throughput claim is made for the referee.
- Revisit if: forced-retry digests cannot be made equal because FrankenSim's solve keeps hidden state across calls (then the airlock must expose and checkpoint it, an upstream work item).
