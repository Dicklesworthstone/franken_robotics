## Background

Kinesis (crate `frob-dyn`) advances state in time. On the referee tier and on the `strict` profile of `batch-cpu` each world advances by one **transaction per accepted physics interval**: a checkpoint of the whole restore set is taken, a candidate interval is built beside the committed state, a list of checks runs, and the interval either commits in one step (the `commit_epoch` advances) or leaves no trace. The restore set and the commit fence are bead BD-081; event location on the dyadic grid and the coupled impulse per island are BD-082. This bead supplies what happens when the checks fail: the **retry ladder**.

A candidate interval can fail its checks for reasons that have nothing to do with the robot: a Newton solve that did not reach tolerance, an event bracket that was too coarse, a warm start that led the solver into a bad basin. The transaction then restores the checkpoint and tries again under a different **numerical plan**. Three rules make this safe, and each has a rejected alternative behind it.

1. **Retries change numerical parameters only (ADR-KIN-05).** Physical parameters (masses, inertias, lengths, gear ratios, contact stiffness, dissipation time, friction coefficients, actuator-card parameters, clock periods) and numerical parameters (sub-interval length, event-location method, solver tolerance, iteration cap, warm start, solver choice) are declared separately. Reason: a smaller time step must not silently stiffen a fitted foot spring; a stiffness that scales with h is a numerical parameter disguised as a physical one and makes step-halving tests meaningless. Rejected: "make the step easier" by softening contact or shrinking friction on retry, which would change the physics that the result claims.
2. **A retry restores everything and redraws nothing.** A retried interval must equal a first attempt made under the same plan (INV-KIN-02), and a random input is a function of its address and interval, never redrawn (INV-KIN-03). Rejected: redrawing noise on a rejected step. Hand-checkable counterexample (CX-144): let the input be a fair sign and reject the step whenever it is negative, then redraw once; the accepted sign is positive with probability ½ + ½·½ = ¾. Rejection that redraws biases the law.
3. **A numerical failure is not a physical failure.** A world that exhausts the ladder is `Faulted` with cause `numerical-fault`; it is never scored as a fall, slip or collision (CX-150), and summaries state how many worlds were excluded for this cause. Rejected: counting a solver give-up as a failed episode, which would let a design lose (or a rival win) on solver behaviour.

The ladder is a deterministic function of state, so a replay repeats the same attempts. Tier: Solid [S]. It serves the Fidelity claim: the referee adjudicates other tiers only if its own steps are reproducible and its refusals are named. The `strict` profile (BD-161, M2) reuses this ladder unchanged.

## Technical approach

**Types (DESIGN; fixes intent, not signatures).** Module `crates/frob-dyn/src/transaction/retry.rs`. The plan
type is N16a-04's `NumericalPlan` (part of `StepPlanId`); its fields are restated here so the ladder can be read
alone, and this bead adds no field to it.

```rust
// Owned by N16a-04 (params.rs); restated.
pub struct NumericalPlan {
    pub h: Ratio,                      // physics step; never changed by a rung
    pub max_subinterval: Dyadic,       // largest admitted sub-interval of a base interval, ℓ₀ / 2^k
    pub event_location: EventMode,     // ConservativeAdvance | ForcedBisection (bisection on the dyadic grid only)
    pub solver_tolerance: TypedTol,    // typed per row unit: N·s for impulses, N for forces; never one number for both (C-14)
    pub iteration_cap: u16,
    pub warm_start: bool,
    pub island_solver: IslandSolver,   // SemismoothNewton | FixedPointCone
    pub stiction_speed: Qty<Speed>,    // never changed by a rung
}
pub struct RetryLadder { pub n_retry: u8 /* 3, OPEN-KIN-5 */ }
impl RetryLadder { pub fn plan(&self, attempt: u8, declared: &NumericalPlan) -> NumericalPlan; }
pub enum StepOutcome {
    Committed { epoch: u64, attempt: u8, events: Vec<EventRecord>, checks: CheckReport },
    Faulted { refusal: Refusal },    // FROB-REF-220, -221, -224 or -721; nothing from the interval is published
}
```

**The ladder (DESIGN).** `attempt` runs 0 ..= N_retry with N_retry = 3.

| Attempt | Plan | Failure it addresses |
|---|---|---|
| 0 | The declared plan | — |
| 1 | Halve the largest admitted sub-interval (`max_subinterval` ÷ 2) and force bisection for event location (`event_location = ForcedBisection`) | A missed or badly bracketed event; a sub-interval too long for the active-set assumption |
| 2 | Tighten the solver tolerance by ten (`solver_tolerance` ÷ 10, each unit), double the iteration cap (`iteration_cap` × 2, saturating at `u16::MAX`), clear the warm start (`warm_start = false`) | A solve stopped short; a warm start in a bad basin |
| 3 | Switch the island solver from semismooth Newton to the fixed-point cone iteration (`island_solver = FixedPointCone`) | A Newton failure on a degenerate island |

No rung touches `h` or `stiction_speed`, and no rung touches a physical parameter.

The plan text lists what each attempt changes and does not say whether the changes accumulate. This bead fixes: **they accumulate** (attempt 2 keeps attempt 1's halving and bisection; attempt 3 keeps both). Reason: each rung cures a different cause, and dropping an earlier repair can reintroduce the failure it cured. The choice is written in `CONTRACT.md` and the ladder's constants are hashed into the step-profile part of the `StepPlanId`, so two ladders never share an identity.

**The fixed-point cone iteration (attempt 3).** Implemented in N16a-07 as the second implementation of the island solver trait; this bead selects it and passes the plan's tolerance and pass cap. Its definition, restated so that the rung can be read alone: for an island with contact velocity u = (uₙ, u_T), friction coefficient μ and impulse λ in the cone 𝒦_μ = {‖λ_T‖ ≤ μ·λₙ}: (1) set s = μ·‖u_T‖ from the pre-event state; (2) solve the convex cone program for λ with the shifted velocity û = (uₙ + s, u_T), s held fixed; (3) recompute s from the solution; (4) stop when the natural-map residual ‖λ − Π_𝒦(λ − û)‖ is at most the plan's tolerance (TARGET 10⁻⁶ for evaluation), or fail the attempt at `iter_cap` passes. The term s is what makes hard Coulomb friction non-associated; holding it fixed makes each pass convex.

**The loop.** Numbered as in the transaction.

1. T1: `S ← checkpoint(X_committed)`; record `ParamDigest`, the digest of the world's physical parameter set as N16a-04 defines it (BLAKE3 over the canonical bytes of model, interface cards and clock periods).
2. T2: for `attempt` in 0 ..= N_retry: `plan ← ladder.plan(attempt, declared)`.
3. T3: `X ← restore(S)` (the whole restore set: (q, v); actuator, thermal and battery states; contact memory with witness pairs, frames, tangential memory, warm-start impulses and active set; film thickness; clock phases and packet queues; controller and estimator states; ordinals of sample-stamped draws; terrain edits; energy-ledger accumulators; event counters; the command cursor; the interval-extremum folds `dyn.extremum-folds` of N24a-44: the twelve rows of BD-081's registry). `warm_start = false` zeroes the warm-start impulses after the restore, as a plan action.
4. T4 runs under `plan` (BD-082). Interval-acting noise is read from the refinement law by address (N16c-01): a finer sub-interval reads children of the same tree nodes, so attempt 1 refines the path the earlier attempt saw.
5. T5 checks: sub-intervals sum to (t0, t1) exactly; solver residuals; joint limits and closures inside tolerance; group-membership error; energy-ledger residual; path admission (no missed contact on the swept path, inside ε_g); loads and currents inside admitted domains; event count.
6. T6: all pass → commit; `attempt` is published with state, impulses, sensor inputs and diagnostics. Assert `ParamDigest` unchanged (INV-KIN-07).
7. T7: after the last attempt, `restore(S)`; mark the world `Faulted`, cause `numerical-fault`, refusal `FROB-REF-221`; publish nothing from the interval.

**Terminal refusals that do not consume attempts.** `FROB-REF-220` (an event cannot be bracketed within L_max = 16, or more than E_max = 64 events fall in the base interval) and `FROB-REF-224` (no solution, or several distinct post-event motions) end the transaction at once through the same restore: a finer plan cannot cure an accumulation point or an indeterminate configuration. `FROB-REF-721` (a capacity refusal of N16a-05, or the sibling's fixed-witness refusal that persists at the finest dyadic cell after attempt 1, BD-093) ends it the same way, with exit code 5; the sibling's fixed-witness refusal before the finest cell counts as a failed attempt, so rung 1 can cure it. `FROB-REF-221` — meaning: every numerical plan failed its checks; repairs, ranked: teleport the world to `batch-cpu` and inspect; accept the `Faulted` world as excluded. Exit code 3 when it is the envelope's refusal; inside a multi-world run it is a per-world record and the envelope exits 2 with the count.

**Determinism.** The ladder reads no clock, thread identity or worker count; `plan(attempt, declared)` is pure. Outputs are class D2 on the referee (same-platform determinism; cross-ISA waits on upstream work item FD-FSIM-07 in FrankenSim's repository).

**Evidence and ledger.** Every committed interval records `attempt`; a run's envelope carries the attempt histogram and `faulted.numerical_fault` (count and world addresses). Outcome kind is `numerical`: the verdict is unknown, the world stays in the denominator and is listed as excluded (a summary that omits it is refused by `FROB-REF-865`).

**Fault-injection seam.** Compiled only under the `chaos` cargo feature: `ForceRetry { world, base_interval, fail_attempts_below: k }` makes T5 report failure for attempts < k. A plan floor `start_attempt = k` runs the ladder from rung k. Both are used only by tests.

**The seam's run inputs (DESIGN; chaos build only, absent from release and conformance builds, where they are the unknown-parameter refusal 802).** This bead owns the two `sim.run` inputs that reach the seam; their VERBS-sim rows name it the owner, and `--chaos` stays BD-081's:

- `--chaos-plan <file>`: a TOML file, schema `frob.chaos.retry/1`, holding a list of entries `{ world, base_interval, fail_attempts_below = k }` with 1 ≤ k ≤ N_retry; each entry is one `ForceRetry`. An entry naming a world or interval the run does not have, or k outside 1 ..= N_retry, is 802 with `pointer` at the entry.
- `--numerical-plan-floor <k>`: only with `--chaos-plan`; the listed intervals start the ladder at rung k (`start_attempt = k`) and no check is forced to fail, so the run is the clean plan-k run the forced run is compared with. Without `--chaos-plan` it is 802.

The file's digest is recorded in the manifest, so a forced run and its plan-k twin are two runs with distinct `RunId`s and distinct idempotency keys.

**What a caller reads.** Each committed interval's T1 record on the `solver` stream carries `attempt` beside `commit_epoch`, `checks` and `physical_params_digest`, and `state_digest`, the BLAKE3 hash of the committed snapshot of the restore set; `frob telemetry query <run> --stream solver --channels attempt,state_digest,physical_params_digest --json` (N24a-36) returns them per base interval.

## Acceptance criteria

- [ ] `frob-dyn` contains the ladder, plan type and loop; `CONTRACT.md` (ten sections) states the four rungs, their accumulation, N_retry = 3 and the parameter partition.
- [ ] Forced-retry digests equal (GATE-KIN-04 row; INV-KIN-02): on 10⁴ random intervals a transaction that commits on attempt k from checkpoint S has the same state digest as a run started from S with plan k, for k = 1, 2, 3. TARGET: zero mismatches.
- [ ] Refinement statistics inside 3σ at 10⁶ draws under forced retries (GATE-KIN-04 row; PO-KIN-04): half-interval variance ℓ/2, zero covariance, halves sum to the parent.
- [ ] The redraw mutation is caught (GATE-KIN-04 row; INV-KIN-03): the planted redraw-on-reject build fails the fair-sign fixture with P(positive) = ¾.
- [ ] The restore-set mutation is caught: omitting warm starts changes a forced-retry digest. The second control of KA-341, omitting packet queues, needs the queues of BD-098 in the restore set and is registered and run by N16c-03.
- [ ] Physical-parameter digests are equal before and after every attempt on 10⁴ forced retries (INV-KIN-07); a planted retry that scales contact stiffness with the sub-interval fails.
- [ ] A world that fails all four plans is `Faulted` with `numerical-fault` and `FROB-REF-221`, publishes nothing, is absent from every physical failure class and present in the excluded count.
- [ ] The same run replayed commits on the same attempt at every interval (attempt histograms equal).
- [ ] `frob sim run --tier referee --key <k> --json` exposes the attempt histogram and the numerical-fault count; cancellation between attempts leaves the committed epoch unchanged.
- [ ] In a chaos build `--chaos-plan` and `--numerical-plan-floor` behave as specified, including their 802 cases; a release build answers both with 802.
- [ ] `scripts/e2e/retry_ladder.sh` exits 0 on a chaos build. (The three GATE-KIN-04 rows are measured at gate size by N16c-02's script, whose receipt N16a-10 records; this bead records nothing in `registries/gates.toml`.)

## Test plan

### Unit tests

`cargo test -p frob-dyn`, no mocks; fixtures labelled `synthetic` are two sliders, a ball and a wall.

- `ladder_plans_are_pure_and_cumulative`: `plan(1)` has `max_subinterval` halved and `ForcedBisection`; `plan(2)` has `solver_tolerance` ÷ 10, `iteration_cap` × 2, `warm_start = false`, and keeps rung 1; `plan(3)` has `FixedPointCone` and keeps rungs 1 and 2; `h` and `stiction_speed` equal the declared plan's on every rung; two calls with the same arguments return equal `NumericalPlan::digest()` values.
- `forced_retry_digest_equals_clean_plan_k` (property, 10⁴ intervals, seeds explicit): digests equal for k = 1, 2, 3.
- `retry_replays_same_attempts`: two runs of a fixture with naturally failing intervals give equal attempt sequences.
- `param_digest_invariant` (property): `ParamDigest` equal across attempts; mutant `stiffness ∝ 1/ℓ` detected.
- `exhaustion_is_numerical_fault`: a fixture whose checks cannot pass under any rung (the tied sliders with a declared impulse tolerance of 10⁻²⁰ N·s, below `f64` resolution at impulses of order 1 N·s; not an inconsistent configuration, which is `FROB-REF-224` and terminal) ends `Faulted`, `FROB-REF-221`, after exactly four attempts; committed epoch and state digest equal the checkpoint.
- `refusal_220_and_224_are_terminal`: an accumulation fixture (a ball with restitution bouncing to rest inside one base interval) ends with `FROB-REF-220` after exactly one attempt; the Painlevé rod of KA-396 (μ = 1.5, tan θ = 2, inside the paradox region μ > (tan²θ + 4)/(3·tan θ) = 4/3 at tan θ = 2, where no post-event motion is unique) ends with `FROB-REF-224` after exactly one attempt; in both cases the state digest equals the checkpoint's and nothing is published.
- `noise_path_refined_not_redrawn`: with a Brownian driver, the increment over the base interval is identical on attempts 0 and 1, and attempt 1's two half-increments sum to it.
- `tolerance_units_typed`: a force tolerance passed where an impulse tolerance is required fails to compile (compile-fail test).

### End-to-end script and logging

`scripts/e2e/retry_ladder.sh [--seed S]` (owned by this bead; chaos build; default seed 16083; idempotent; every run under its own key). It uses two fixtures this bead registers in N24b-03's fixture registry: `kin/tied-sliders` (the design `crates/frob-conformance/fixtures/kin/tied-sliders.fbot` of BD-082 with its scene `wall`) and `kin/unsolvable-island` (the same with the declared impulse tolerance of 10⁻²⁰ N·s of `exhaustion_is_numerical_fault`), both `synthetic`; N16c-02 reuses them. Steps:

1. `build`: `frob doctor --json`; the build identity and the `chaos` feature (absent: the script logs `not-run` with the reason and exits 77).
2. `ladder`: for k = 1, 2, 3, `frob sim run --fixture kin/tied-sliders --tier referee --profile referee --seconds 1 --seed $SEED --chaos-plan retry-k<k>.toml --key rl-forced-k<k>-$SEED --json` (20 chosen intervals) and the twin `… --chaos-plan retry-k<k>.toml --numerical-plan-floor <k> --key rl-floor-k<k>-$SEED --json`; then `frob telemetry query <run> --stream solver --channels attempt,state_digest,physical_params_digest --json` on both. Assert: `attempt` = k on the chosen intervals and 0 elsewhere in the forced run; `state_digest` equal between the twins on every interval; `physical_params_digest` constant across attempts.
3. `exhaustion`: `frob sim run --fixture kin/unsolvable-island --tier referee --profile referee --seconds 1 --seed $SEED --key rl-exhaust-$SEED --json`: the world is `Faulted` with `numerical-fault` and `FROB-REF-221` after exactly four attempts, with the repairs in order, nothing published from the interval, the world in the excluded count and in no physical failure class; the exit code follows the rule above (3 as the envelope's refusal, 2 with the count in a multi-world run).
4. `replay`: the k = 2 forced run again under `rl-forced-k2-$SEED-r`: equal attempt histogram and digests.
5. `release`: the release binary answers `--chaos-plan retry-k1.toml` with 802.

It sources the STD-E2E helper and writes `target/e2e-logs/retry_ladder/<utc>.ndjson` with a transcript beside it; every line carries `ts`, `script`, `bead` (`BD-083`), `step`, `event` (`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact command line, exit code and wall time; per run the envelope's evidence block (claim, class, tier, profile, determinism, identities, seed) and the attempt histogram; per compared interval both digests; refusal lines with code, repairs and exit; on failure the first differing interval and field with the run identifiers, the chaos-plan file and its digest; a `summary` with assertions passed and failed, naming GATE-KIN-04. The gate-size rows (10⁴ forced intervals, the refinement statistics, the controls) are N16c-02's script, which may run this one as a stage.

### Known answers and negative controls

- KA-341: forced retry digest equals the clean run with the same plan, 10⁴ intervals, exact. Controls: packet queues omitted from the restore set; warm starts omitted.
- KA-340: dyadic refinement, child variance ℓ/2, halves uncorrelated, sum equals the parent, 3σ at 10⁶ draws. Control (CX-144): redraw on rejection gives P(positive) = ¾ against ½.
- CX-150: a world whose solver gave up is not a failed episode; test `exhaustion_is_numerical_fault`.
- Metamorphic: a retry equals a clean run with the same plan; splitting an interval and rejoining leaves the noise increment unchanged.
- Determinism lanes: twice on one machine; debug and release; 1 and 24 workers; each against class D2.

## Considerations

- OPEN-KIN-5 (decision bead N16a-09) owns N_retry, L_max and E_max (defaults 3, 16, 64; decided by the refusal rate on the M1 fixtures; fail-closed default is refusal). Changing N_retry changes the ladder identity.
- OPEN-KIN-4: which law `strict` runs once the hard-contact law is admitted does not change the ladder; rung 3's solver exists for both.
- Risk: a ladder that hides a real modelling defect behind retries. The attempt histogram is reported so that a fixture needing rung 3 on most intervals is visible.
- Risk (RISK-31): the referee cannot complete scenes where decisions are made; exhaustion and capacity refusals feed the referee coverage figure, and the `strict` profile is the named alternative adjudicator.
- Performance: a retry costs one more interval; no throughput claim is made for the referee.
- Revisit if: forced-retry digests cannot be made equal because FrankenSim's solve keeps hidden state across calls (then the airlock must expose and checkpoint it, an upstream work item).
