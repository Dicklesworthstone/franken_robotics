## Background

GATE-KIN-04 is the known-answer gate of the transactional step: "the transactional rows pass on the referee and on `strict`: impact time within 10⁻⁹ s; tied sliders exact to 10⁻¹² N·s; zero observed uncommitted reads in 10⁵ injected faults; forced-retry digests equal; refinement statistics inside 3σ at 10⁶ draws; the redraw mutation caught" (TARGET thresholds; earliest M1 on the referee, M2 on `strict`). Three of those rows belong to the retry ladder and the refinement law (BD-083, N16c-01). This bead is their end-to-end script: it drives the real `frob` binary from the user's side, on real fixtures, and proves that what the unit tests assert inside `frob-dyn` is also what a caller observes through the verb surface, the telemetry and the evidence block.

Why a separate script. A gate is recorded from the outside: the harness calls the verbs as an agent would, writes a hash-named receipt, and a session that did not implement the work enters the row in `registries/gates.toml`. A row that passes only inside the crate that implements it is self-certification.

Terms. A *forced retry* is a transaction whose checks are made to fail for attempts below k by the fault-injection seam of the `chaos` build, so that it commits on attempt k. A *clean run with plan k* starts the ladder at rung k. A *digest* is the BLAKE3 hash of the committed snapshot (state, contact memory, clock phases and packet queues, energy accumulators).

## Scope

In: the script, its fixtures, its assertions and its log; the three rows (forced-retry digests, refinement statistics, the redraw mutation) on `--tier referee`; the `FROB-REF-221` and `FROB-REF-223` paths as seen by a caller. Out: the impact-time, tied-slider and uncommitted-read rows (the end-to-end scripts of BD-081 and BD-082, owned by the unit that drafts those beads); the `strict` repeat at M2 (BD-161 re-runs this script with `--tier batch-cpu --profile strict`; the script takes the tier and profile as parameters for that purpose).

## Technical approach

**Script.** `scripts/e2e/kin_retry_refinement.sh [--tier referee|batch-cpu] [--profile referee|strict] [--seed N]`. Plain shell, idempotent, seed-explicit (default seed 16083), exit non-zero on the first failed assertion after logging it. It sources the shared helper from STD-E2E.

**Fixtures** (all `synthetic`, built in, no private scene data):

| Fixture | Content | Used for |
|---|---|---|
| `fixture:kin/two-sliders-wall` | Two 1 kg sliders joined by a rigid tie approaching a wall at 1 m/s | A step with one located event and a coupled impulse; retried under plans 1 to 3 |
| `fixture:kin/ball-drop` | A sphere dropped from z₀ = 1 m on a plane, restitution 0.5 | Several base intervals with one event each |
| `fixture:kin/quad-stand-noise` | The reference quadruped standing, with a Brownian base-force driver of intensity 5 N/√Hz registered as `BrownianDyadic`, and packet queues for its IMU | Noise under retry; restore-set members |
| `fixture:kin/noise-unregistered` | The same with the driver's law removed | `FROB-REF-223` |
| `fixture:kin/unsolvable-island` | An island whose checks cannot pass under any plan (two rigid ties with inconsistent prescribed speeds) | `FROB-REF-221` |

**Steps.**

1. `frob doctor --json`; record build identity, features (`chaos` required) and the fingerprint digest.
2. Clean reference: `frob sim run --fixture <f> --tier referee --profile referee --seed $SEED --steps 500 --json` for the first three fixtures; store digests per base interval (`frob telemetry summary --run <id> --json`).
3. Forced retry, k = 1, 2, 3: the same command with `--chaos-plan retry-k<k>.toml`, which fails the checks of 200 chosen intervals for attempts below k. In the same call a second world runs the clean plan-k variant (`--numerical-plan-floor <k>` on the chosen intervals). Assert: per-interval digests equal between the forced world and the plan-k world; the committed `attempt` equals k on the chosen intervals and 0 elsewhere.
4. Noise under retry: on `quad-stand-noise`, read the per-interval noise increments from T1 telemetry for the clean run and for the k = 1 forced run. Assert: increments over each base interval are bit-equal; on retried intervals the two half-increments sum to the base increment.
5. Refinement statistics: `cargo test -p frob-conformance --test g1 -- GATE-KIN-04::refinement --nocapture` (10⁶ parents, ℓ = 2 ms). Parse its receipt: sample variance of each half within a relative 4.24 × 10⁻³ of ℓ/2; correlation within 3 × 10⁻³ of zero; sum identity. Log the three measured values with their bounds.
6. Redraw mutation: run the same conformance row against the build with the planted `redraw-on-reject` mutant. Assert the row **fails** and the measured P(positive) on the fair-sign fixture lies within 1.5 × 10⁻³ of 0.75.
7. Restore-set mutations: repeat step 3 for k = 1 against the mutants `restore-omit-packet-queues` and `restore-omit-warm-starts`. Assert at least one digest differs for each, and log the first differing interval and field.
8. Refusals as a caller sees them: `noise-unregistered` returns `ok: false`, code `FROB-REF-223`, exit 3, repairs listing "register the law" then "move the draw to a sample instant"; `unsolvable-island` returns a world `Faulted` with `numerical-fault`, `FROB-REF-221`, zero published state from the failed interval, and the world listed under `excluded.numerical_fault` in the summary, absent from `fall`, `slip` and `collision`.
9. Replay: `frob sim replay --run <id> --json` on the natural-retry run; assert equal attempt sequences and digests.
10. Emit the `summary` line and the receipt path for the recording session.

**Logging.** NDJSON at `target/e2e-logs/kin_retry_refinement/<utc-timestamp>.ndjson` with a human transcript beside it. Every line: `ts`, `script`, `bead` ("N16c-02"), `step`, `event` (`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact command line, exit code, wall time, the envelope's `evidence` block (claim, class, tier, determinism, identities, seed), measured values with units and thresholds, digests where state is compared, and on failure the first differing value and the artifact paths (run identifier, snapshot, chaos plan) needed to reproduce. The final `summary` line gives assertions passed and failed and `gates: ["GATE-KIN-04"]`.

## Test plan

### Unit tests

The script's own helpers are tested by `scripts/e2e/tests/kin_retry_refinement.bats` (or the harness's equivalent): digest comparison reports the first differing interval on a hand-made pair of telemetry files; the statistics parser rejects a receipt with a missing bound.

### End-to-end script and logging

This bead is the script. It asserts the ten steps above and logs as specified. Run time TARGET under 5 minutes on the CPU tier with the statistics row included.

### Known answers and negative controls

- KA-341 (forced retry digest equals the clean run with the same plan; exact). Controls: packet queues omitted; warm starts omitted.
- KA-340 (child variance ℓ/2, zero covariance, sum equals the parent; 3σ at 10⁶ draws). Control CX-144: redraw on rejection, P(positive) = ½ + ½·½ = ¾.
- CX-150: an exhausted world is `numerical-fault`, not a failed episode.
- Determinism lanes: the script is run twice on one machine, in debug and release, and with 1 and 24 workers; digests are compared against class D2.

## Considerations

- The `chaos` feature must never be present in a release build; step 1 fails the script if the release channel reports it.
- The mutant builds are produced by the negative-control registry's build flags (`mutants` feature); they are never published and their binaries are named so that they cannot be confused with the real one.
- If FrankenSim's contact step keeps state the airlock does not expose, step 3 fails with a digest mismatch; that is an upstream work item, and the gate row stays open until it lands.
- Logs contain fixture names, digests and statistics only.
