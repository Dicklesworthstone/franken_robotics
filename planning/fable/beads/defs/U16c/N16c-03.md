## Background

The Kinesis chapter closes with a table of ten known answers, each paired with "the mutation that must fail". The rule behind the pairing is the Gauntlet's: every gate is registered with its failing control before its passing test is written, because a gate that no deficient model can fail validates nothing. The mechanisms behind the rows are built by other beads; what no mechanism bead owns is the **set of ten mutants as registered, buildable defects**, and one battery that runs each known answer against the correct build and against its mutant. This bead delivers the five rows that exist at M1 (the transactional step on the referee and the free-body variational step). Bead N16c-04 delivers the five rows of the lockstep tiers and the trust ladder.

A *mutant* is a planted defect selected by a cargo feature of the crate that owns the mechanism (`--features mutants` plus a selector), compiled into a separately named test binary, never shipped. The battery asserts two things per row: the correct build reproduces the truth inside the tolerance, and the mutant build fails the same assertion. Both outcomes are recorded; a row whose mutant passes is a failed row.

The chapter also states that the rows of GATE-KIN-01 (pendulum period, symmetric-top precession, free-flight momentum, the ballistic invariants of the Euler–Poincaré construction C-04) are unchanged by this table; they belong to the dynamics known-answer battery (BD-088).

## Scope

In: registry entries (`frob-conformance/registry/known_answers.toml` rows and `controls.toml` rows) for the five M1 rows; the five mutants; the battery test target rows; one end-to-end script. Out: implementing the mechanisms; the rows of GATE-KIN-01 other than the free-body step; the M2 and M3 rows (N16c-04); the `strict` repeat (BD-161).

**Registry entries (DESIGN).** Each known answer row carries: `ka`, `section`, `case`, `truth` (formula and value), `tolerance`, `tier` (`G1` for rows 1, 2, 3, 10; `G5` for row 4), `site` (`referee`; `strict` added at M2), `derivation` (a file under `docs/derivations/kinesis/`), `control` (the control identifier) and `gate`. Each control row carries: `id`, `mutant_feature`, `owner_crate` (`frob-dyn` for rows 1 to 4; `frob-lie` or `frob-dyn` for row 10, wherever BD-087 put the step), `expected_failure` (the observable above), `cx` (CX-144 for row 3, CX-145 for row 2) and `gates`.

**Battery rows.** Test targets of `frob-conformance` (the Gauntlet has no agent verb and no `xtask` subcommand): `cargo test -p frob-conformance --test g1 -- kinesis::ka338` and so on; row 4 under `--test g5`. Each row function runs the fixture through the verb surface exactly as an agent would (`sim.run --tier referee --profile referee`), reads the result envelope and telemetry, and compares with the truth. A `--mutant <id>` selector points the row at the mutant binary and inverts the expectation.

**Derivation files.** One per row, Unicode mathematics, hand-checkable: row 1, z(t) = z₀ − ½·g·t², zero at t* ; row 2, momentum balance p_wall = (m₁ + m₂)·v = 2 N·s, and the sequential error 1 kg·m/s ÷ 2 kg = 0.5 m/s; row 3, Var(S/2 ± √(ℓ/4)·Z) = ℓ/4 + ℓ/4 and Cov = ℓ/4 − ℓ/4; row 4, the definition of the restore set; row 10, the symmetric composition argument for order 2 and reversibility.

## Acceptance criteria

- [ ] Five known-answer rows and six control rows are present in the registry files, each with a derivation file; the registry check that refuses a gate without a control passes.
- [ ] Each row passes on the correct build on `referee` with its measured value recorded against its tolerance: impact time error ≤ 10⁻⁹ s; wall impulse within 10⁻¹² N·s of 2; refinement statistics inside 3σ; zero digest mismatches in 10⁴ intervals; halving factor in [3.6, 4.4], momentum drift ≤ 10⁻¹² relative over 10⁶ steps.
- [ ] Each of the six mutants makes its row fail, with the mutant's observable matching the table (0.452 s; 1 N·s and 0.5 m/s; ¾; a differing digest; at least one failed property of the free-body step).
- [ ] The mutants compile only under `--features mutants`; a release build contains none (checked by symbol search in the script).
- [ ] The battery rows call the public verbs, not crate internals, for rows 1, 2 and 4.
- [ ] Results are written as a hash-named receipt that a recording session can cite for GATE-KIN-04 (rows 1 to 4) and for the variational row of GATE-KIN-01 (row 10).

## Test plan

### Unit tests

- `registry_rows_parse_and_link`: every KA row names an existing control and derivation file.
- `ka338_ballistic_drop`, `ka339_tied_sliders`, `ka340_refinement`, `ka341_forced_retry`, `ka355_free_body_step`: the truths above.
- `mutant_<id>_is_caught` × 6: the inverted expectation.
- `ka338_closed_form_self_check`: the fixture's constants reproduce t* = 0.4515236 s from z₀ and g in exact rationals times a certified square root bound, so that the truth is not a copied literal.

### End-to-end script and logging

`scripts/e2e/kinesis_known_answers.sh --rows m1` runs the five rows and the six mutants through the `frob` binary and the conformance targets, and writes NDJSON to `target/e2e-logs/kinesis_known_answers/<utc-timestamp>.ndjson` with a transcript: per row an `assert` line with the measured value, unit, threshold, tier and evidence block, and a second `assert` line for the mutant with `expected: "fail"` and the observed defect; digests where compared; on failure the first differing value and the run and snapshot paths; a `summary` line with counts and `gates: ["GATE-KIN-04", "GATE-KIN-01"]`. The script exits non-zero if any correct-build row fails or any mutant passes.

### Known answers and negative controls

KA-338, KA-339, KA-340, KA-341, KA-355 with the values in the table; CX-144 (redraw) and CX-145 (sequential impulse). Metamorphic relations: the drop from 4·z₀ doubles t*; mirroring the slider fixture leaves the impulse magnitude unchanged; a retry equals a clean run with the same plan. Determinism lanes: twice on one machine, debug and release, 1 and 24 workers, against class D2.

## Considerations

- One fixture identity per physical case: where the Euler–Poincaré construction's own test and this battery state the same case, they are one fixture with two rows (mathematics on the host, subsystem on its tier), so the constants cannot disagree.
- KA numbers are never reused or renumbered; if N16-KA assigns different numbers, the registry file is the authority and this bead's table is corrected to it.
- Risk: a mutant that fails for an unrelated reason (does not compile, crashes). Each control row records the expected observable, and a mutant that fails differently is a failed control.
- The endpoint-only mutant on a half-space only mis-times the impact; on a thin plate it misses it entirely. The thin-barrier case is Traction's fixture.
