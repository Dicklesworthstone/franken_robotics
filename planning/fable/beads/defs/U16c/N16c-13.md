## Background

On the lockstep tiers the constraint-row stage (stage 7) and the solve stage (stage 8) run over every world at the row capacity R for a fixed number of Newton iterations under masks. A **row-class solve queue** regroups worlds by the work they need: worlds with few active contacts run under a small loop bound, and worlds that have converged drop out of later iterations, so that an execution group of 32 lanes holds worlds with similar active row counts that are still iterating. This bead builds the kernels: the assignment kernel `K-queue-assign` and the variants of the stage 7 and 8 kernels that take a world index list and a class loop bound. It is funded only if the pilot (N16c-12) does not falsify the mechanism, that is, when the point-A decision of KILL-ROWQUEUE (N16cp3-01) releases it.

The design constraint that shapes everything: **no digest may change**. A world's trajectory must be a function of its address and identities only, not of its slot, co-tenants, capacities or world count (architecture decision ADR-KIN-03, tested as invariant INV-KIN-04, determinism class D2). The argument that queues satisfy it:

1. a world's arithmetic reads its own rows only;
2. the loop bound of its class is at least its active count, and inactive rows are identity rows that follow every active row (trailing padding with the neutral element);
3. the per-world `done` test is unchanged;
4. reductions inside a world are pairwise trees anchored at index 0 over power-of-two blocks, whose shape does not depend on a bound.

So queue membership, order inside a queue and co-tenants enter no result.

Why assignment is per step and not per episode (hand-checkable counterexample). A trotting quadruped with four samples per foot has 8 active contacts in diagonal support and 16 in double support. With C = 24 the class bounds are 6, 12 and 24, so the world crosses a class boundary twice per stride. A sort made at reset leaves it in the wrong class for part of every stride: either the loop bound is below its active count, which drops contacts and is forbidden (capacity overflow is flagged or refused, never a truncation), or it sits in the largest class and nothing is saved.

Rejected alternatives: moving world state into compacted buffers (state would move; snapshots and digests would depend on placement); dynamic launch counts (would break the static launch graph); sorting worlds by contact count (a sort key across worlds is needless: classes need only count, scan, write).

## Scope

In: `K-queue-assign`; index-list variants of `K-jac-rows`, `K-joint-rows`, `K-cone-setup`, `K-scale-diag` (N18b-25), `K-hess`, `K-chol`, `K-linesearch`, `K-cone-eval`; the general masked lane; CPU reference implementations; kernel-level determinism tests. Out: the step plan that launches them and its generations (N16c-14); the verb surface (N16c-15); the gate measurement (N16c-16); the index-list entry point of `K-film`, the film-friction row kernel, which does not exist at M2 (it lands with the film law, BD-230, at M3) and gains its entry point there under the same signature and the same bit-equality test. Until it has one, the step plan keeps queues off for any plan whose stage 7 contains film rows (N16c-14).

## Technical approach

**Classes (DESIGN).** After contact compaction each world has an active contact count c_w ≤ C. Three row classes are fixed fractions of capacity: class 0, c_w ≤ C/4; class 1, c_w ≤ C/2; class 2, c_w ≤ C. Class k's row loop bound is R_k = round-up-to-8(4·C_k + joint rows) with C_k = C/4, C/2, C. Class k has a queue of world indices with logical capacity Q_k, stored in the step-plan header; the index buffers are allocated once at N entries per class, so no buffer changes shape.

**`K-queue-assign` (exact-integer kernel class).** Input: c_w, the `done` mask, Q_0..Q_2. Output: three index lists with their lengths, and a general-lane mask.

1. Class indicator: for a world that is not done, k(w) = the smallest k with c_w ≤ C_k; a done world has no class.
2. For k = 0, 1, 2 in order: (a) count the worlds with k(w) = k; (b) exclusive scan of the indicator in ascending world order gives each world its rank; (c) a world with rank < Q_k writes its index at position rank of queue k; (d) a world with rank ≥ Q_k is demoted: k(w) ← k + 1.
3. Worlds demoted out of class 2 set their bit in the general-lane mask. The general masked lane holds every world and therefore always fits.

Count, scan, write only; integer arithmetic; no floating-point atomics; lists are in ascending world order by construction, which makes the output a pure function of (c, done, Q).

**Class-bounded stage kernels.** Each stage 7 and 8 kernel gains an entry point `(index_list, len, row_bound)`: lane i processes world `index_list[i]` and loops rows 0 … row_bound − 1, reading and writing that world's rows **in place**. No state moves. Rows at or beyond the world's active count are identity rows with zero right-hand side and are either inside the bound (processed, neutral) or beyond it (untouched, already neutral). The per-world reductions (line-search sums, residual norms) keep their anchored trees over the full power-of-two block; entries beyond the row bound are read as the neutral element −0.0 by a select, not skipped by reshaping the tree.

**Regrouping live worlds.** After every second Newton iteration (DESIGN default) `K-queue-assign` is launched again on the current `done` masks, so later iterations run over the live prefix of each queue. A launch over an empty prefix returns at once.

**The general lane.** One masked launch of each kernel over all worlds at the full bound R, selecting only worlds whose general-lane bit is set; with no bit set it returns at once.

**CPU reference.** `batch-cpu` implements the same entry points in Rust on the tile program; it is the bit-level reference for both devices.

**Kernel manifest.** Each new entry point declares its stage signature, its exactness class (`K-queue-assign`: exact integer, D0; the stage kernels: floating, D2), the statement "reads and writes rows of world `index_list[i]` only", and the dimension typing of its arguments.

## Acceptance criteria

- [ ] `K-queue-assign` and the index-list entry points exist in the shared dialect, on `batch-cpu`, CUDA and Metal, with manifests; the dialect lint passes (no built-in transcendental, no fused multiply-add, no floating-point atomic).
- [ ] For 10⁴ random (c, done, Q) inputs the kernel's lists equal a host reference: ascending order, every live world in exactly one queue or the general lane, class bound ≥ c_w for every placed world, |queue k| ≤ Q_k.
- [ ] Stage outputs through index lists equal the masked path's outputs bit for bit for every world, on each backend, over 1,000 random contact states per reference robot, for random queue capacities including Q_k = 0 and Q_k = N.
- [ ] The trot fixture (8 and 16 contacts alternating, C = 24) is assigned to class 1 and class 2 on alternate phases, step by step.
- [ ] Negative controls caught: `reset-time-sort` (assignment only at reset) raises a truncation flag or shows zero saving; `class-sized-reduction` (a tree sized by the class bound) changes a digest; `unsorted-queue` (indices written in arrival order) is detected by the host-reference comparison.
- [ ] An empty queue's launch performs no row arithmetic (counter of processed rows is zero).
- [ ] Cancellation at a kernel-batch boundary between a regroup and the next iteration leaves committed state untouched.

## Test plan

### Unit tests

`cargo test -p frob-kernels queue::` on `batch-cpu`, and the device harness for CUDA and Metal.

- `assign_matches_host_reference` (property, 10⁴ cases).
- `assign_overflow_cascades`: N = 8 worlds all in class 0 with Q = (2, 3, 2): worlds 0–1 in queue 0, 2–4 in queue 1, 5–6 in queue 2, world 7 in the general lane.
- `assign_skips_done_worlds`.
- `class_bound_never_below_active_count` (property).
- `stage_outputs_equal_masked_path` (bit equality, per kernel).
- `regroup_after_two_iterations_runs_live_prefix`.
- `trot_fixture_follows_8_16`.
- Mutants: `reset_time_sort_caught`, `class_sized_reduction_caught`, `unsorted_queue_caught`.

### End-to-end script and logging

Kernel-level behaviour is exercised from the user's side by `scripts/e2e/kin_rowqueue_gate.sh` (bead N16c-16). This bead's own script, `scripts/e2e/kin_rowqueue_kernels.sh`, runs `frob spark check --kernel K-queue-assign --backend <b> --reference batch-cpu --key rqk-K-queue-assign-<b> --json` and the same CPU-versus-device check for each new entry point (`--kernel <entry point>`, key `rqk-<entry point>-<b>`; `spark.check` is a run verb, so every call carries its own key), for `<b>` each of `gpu-cuda` and `gpu-metal` present (an absent device logged `not-run`), and logs NDJSON to `target/e2e-logs/kin_rowqueue_kernels/<utc-timestamp>.ndjson` with a transcript: command, exit code, wall time, evidence block (class D0 or D2, backend, fingerprint digest), per-kernel digests on each backend, the first differing world and row on a mismatch, and a `summary` line.

### Known answers and negative controls

The overflow cascade case; the trot alternation; the `f32` grouping case that makes a class-sized tree visible (a = 10⁸, b = −10⁸, c = 1 gives 1 or 0 by grouping). Counterexample rows K1 to K3 of the Kinesis counterexample registry. Determinism lanes: twice on one machine; 1 and 24 workers on `batch-cpu`; debug and release; each device against class D2, and `K-queue-assign` against D0 across all three backends.

## Considerations

- On Metal every dispatch of a chunk is encoded serially into one command buffer, and the cost of an added dispatch there is unmeasured; the kernels are built for both families but admission is per backend.
- Gathers through an index cost memory traffic; the row arithmetic saved must exceed it, which only the gate's paired measurement shows.
- If KILL-ROWQUEUE fires after this bead, the entry points are removed and the live-fraction counters are kept.
