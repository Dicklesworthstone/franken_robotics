## Background

Row-class solve queues regroup worlds of a lockstep batch by the work their constraint solve needs (kernels: N16c-13; step plan: N16c-14). This bead is the user-visible part: how a caller turns the option on, what a planner tells them beforehand, what a receipt says afterwards, and what label a result carries while the option is unqualified.

Four surfaces are named for the mechanism:

1. the option `--solve-queues` of `sim.run` (run worlds under a profile, a law and per-world designs) and of `phylum.sweep` (run a population of designs in mixed batches);
2. `phylum.plan` (a read verb that never runs physics: buckets, padding overhead, bytes, the machine that fits a population) prints the speedup bound of the mechanism for the population in hand;
3. the placement receipt (`frob.placement/1`, one row per stage with requested and actual backend) records whether queues ran;
4. until GATE-KIN-08 has passed on a backend, a run with queues carries the label `experimental-execution` and is refused as promotion evidence ("execution option not yet qualified on this backend").

The reason for the label: the claim that queues change no digest is exactly what the gate tests. Until it has passed on a backend, a result produced with queues there has not earned the determinism class that pairing, promotion and attribution rely on, so it may be looked at but not cited.

## Scope

In: the option on both verbs with its schema; the `phylum.plan` bound; receipt and disclosure fields; the label and the refusal; `sim.estimate` printing whether queues would be used. Out: kernels and the step plan; the gate run (N16c-16); arm E of the mixed-batch head-to-head (run in N16c-16).

## Technical approach

**Option (DESIGN).** `--solve-queues <mode>` with `off` (default until the gate passes on the backend, and after a kill), `auto` (planner capacities from the previous chunk's histogram), or `q0,q1,q2` (explicit capacities, multiples of 32, each at most the world count). Input schema field `execution.solve_queues`; verb registry rows in `registries/verbs.toml` for `sim.run` and `phylum.sweep` gain the option, and the command-line and tool surfaces are generated from the registry. On a tier where the option has no meaning (`referee`, or `batch-cpu` under `strict`) the option is refused as an invalid argument for that profile, not ignored: the generated input schema admits `execution.solve_queues` only together with `profile = lockstep`, so the request fails the schema with `FROB-REF-802` (arguments fail the schema), pointer `execution.solve_queues`, `required` "profile lockstep", repair "drop the option or run under `--profile lockstep`", exit 3, retry `after-change`.

**Two more surfaces the gate needs (DESIGN).** GATE-KIN-08 measures its overflow clause on the standard battery and its digest clause under 100 co-tenancies, so the option reaches two more verbs. (1) `eval.run` forwards `--solve-queues` to the run's step plan as it forwards `--solve-path` (N16bp2-01's forwarding, same spelling and values, same 802 outside `--profile lockstep`); because the option is outside `StepPlanId` it does not make a new stratum, and the receipt records it (VERBS-eval's `eval.run` row carries `solve_queues` in this form). (2) The invariance harness of `spark.check --invariance` (BD-181, a dependency through BD-222) gains the axis `solve-queues`: each co-tenancy of the run is repeated with queues on at capacities drawn by an address-keyed stream from {0, 32, …, N} (a fresh draw per co-tenancy, recorded), and every world's digest chain is compared with its masked `alone` run (VERBS-spark's `spark.check` row lists the axis; `--axes cotenancy,solve-queues`).

**`phylum.plan` output (read; never runs physics).** For the population in hand it prints:

- f, the solve share of step time, from the most recent profile for this shape class and fingerprint (or `unmeasured`);
- ℓ, the active-and-live share of launched lane-time, from the live-fraction counters of the most recent run of this class (or `unmeasured`);
- h, the added relative overhead: (added launches × measured launch cost) ÷ (worlds × time per world-step);
- the bound 1/(1 − f + f·ℓ + h), with the statement of which inputs are measured and which are hypotheses, and the batch size at which the bound crosses 1.15 if any.

Known values the printout must reproduce from inputs: f = 0.47 with ℓ = 0.5 and h = 0.07 gives 1.20; ℓ = 0.25 and h = 0.15 gives 1.25; at 65,536 worlds with h = 0.009, ℓ = 0.25 gives 1.52. With any input unmeasured the bound is printed as a range over the documented hypothesis interval and marked HYPOTHESIS.

**Placement receipt.** The rows for stages 7 and 8 gain `execution: "masked" | "queued"`, `queue_capacities`, `generation`, `class_world_steps[3]`, `general_lane_world_steps`, `regroup_every`; the header gains `execution_qualified: true | false` for this backend (true only if the gate row for this backend is `pass` under the current fingerprint).

**Disclosure block.** Adds the live fraction per Newton iteration index and the active-contact class occupancy whenever a performance figure is quoted for a run, with queues on or off (these counters are kept even if the mechanism is killed).

**Label and refusal.** A result envelope of a queued run on an unqualified backend carries `labels: ["experimental-execution"]` in its evidence block. By the claim product the label propagates to anything derived from it (the weakest label among a result's inputs is the label of the result). Offering such a result to `eval.promote`, or citing it as established, is refused: message "execution option not yet qualified on this backend", pointer to the run and the backend, repairs ranked (1) re-run on the masked path, (2) qualify the backend (pass GATE-KIN-08 there). Code `FROB-REF-820` (label misuse) with `detail: "solve-queues-unqualified"` (N16-REF's ledger slug for this refusal, `held` in the `8xx` block and therefore raised on 820 with the slug), behind one named constant, the option and the backend in the payload; exit 3; retry `after-change`.

**`sim.estimate`.** Reports for the class whether queues are qualified on the backend, the bound, and the expected general-lane share, as one added group `solve_queues` (`qualified`, `bound` with the same measured-or-HYPOTHESIS marking as `phylum.plan`, `general_lane_share` from the counters of the most recent run of the class, or `unmeasured`) beside the base record of BD-219 and the Kinesis groups; the verb still runs no physics.

## Acceptance criteria

- [ ] `frob sim run <design> --solve-queues auto --key <k> --json` and `frob phylum sweep --designs <set> --task <t> --solve-queues auto --key <k> --json` run on `batch-cpu` and on each device with queues, and their receipts show `execution: "queued"` for stages 7 and 8 with capacities and generation.
- [ ] `frob eval run <design> --battery standard --solve-queues auto --key <k> --json` forwards the option (receipt `execution: "queued"`, the stratum unchanged); `frob spark check --invariance --backend <b> --workload Q --axes cotenancy,solve-queues --episodes 10 --cotenancies 4 --key <k> --json` reports zero mismatches on a correct build.
- [ ] With the option absent, receipts show `masked` and results are bit-identical to those of a queued run of the same addresses.
- [ ] `frob phylum plan` prints f, ℓ, h and the bound, reproduces the three known values from their inputs, never runs physics (no world-step counter moves), and marks unmeasured inputs.
- [ ] A queued run on a backend without a passed GATE-KIN-08 carries `experimental-execution`, and the label propagates to derived results; the promotion-evidence check this bead supplies (`execution_qualified(result)`, called on every result offered as established) returns the refusal with both repairs; after the gate row is `pass` for that backend and fingerprint the label is absent. (`eval.promote` arrives at M3 with BD-263, which calls this check and asserts the refusal through the verb.)
- [ ] A changed fingerprint (driver or compiler change) returns the backend to unqualified until the gate is re-run.
- [ ] `frob sim estimate <design> --tier gpu-cuda --worlds 8192 --json` carries the `solve_queues` group (qualified or not, the bound with its marking, the general-lane share or `unmeasured`, never zero without a record) and moves no world-step counter.
- [ ] `--solve-queues` under `--profile strict` or `--tier referee` is refused with `FROB-REF-802`, pointer `execution.solve_queues`, exit 3, on both the CLI and the MCP surface.
- [ ] Schemas, examples and the refusal list for the option are in the verb registry; `frob schema sim.run` shows the field.
- [ ] `scripts/e2e/sim_solve_queues.sh` exits 0 on `batch-cpu` (device steps logged `not-run` where the device is absent).

## Test plan

### Unit tests

- `solve_queues_option_parses`: `off`, `auto`, `64,32,32`; rejects `33,0,0` (not a multiple of 32) and capacities above the world count.
- `plan_bound_known_values`: the three values above; and with ℓ unmeasured, the printed range for ℓ ∈ [0.25, 0.5].
- `receipt_records_execution`.
- `label_propagates_by_claim_product`: a scorecard derived from a labelled run is labelled.
- `promotion_refuses_experimental_execution` (negative control: a build that drops the label on derived results must fail the test).
- `fingerprint_change_unqualifies_backend`.
- `eval_run_forwards_solve_queues`: the option reaches the step plan's `execution` block; `StepPlanId` and the stratum key are unchanged; with `--profile strict` it is 802.
- `invariance_axis_solve_queues`: the axis draws one capacity triple per co-tenancy from the address-keyed stream (two runs give the same triples), and a planted digest difference in one queued world is reported as a mismatch on that axis.
- `estimate_reports_solve_queues`: with no gate row and no prior run the group reads `qualified: false`, the bound as a HYPOTHESIS range and `general_lane_share: unmeasured`; after a planted gate row and a run with counters it reads the recorded values; the engine's step counter stays at zero.

### End-to-end script and logging

`scripts/e2e/sim_solve_queues.sh [--seed S]` (owned by this bead; default seed 16150; idempotent; every run under its own key) calls the verbs from the user's side on `batch-cpu` and on each present device: `option`, `frob sim run quad-a --tier <b> --profile lockstep --seconds 2 --seed $SEED --solve-queues auto --key ssq-auto-<b>-$SEED --json` and the same with `--solve-queues 64,32,32` and without the option (keys `ssq-explicit-…`, `ssq-masked-…`), asserting the receipt's stage rows and `frob telemetry divergence <queued run> <masked run> --mode exact --json` with no divergence; `forwarding`, `frob eval run quad-a --battery standard --tier <b> --profile lockstep --solve-queues auto --key ssq-eval-<b>-$SEED --json` (the battery form takes no seed) and `frob phylum sweep --designs quad-a,humanoid --task stairs-0.15 --worlds-per-design 16 --tier <b> --solve-queues auto --key ssq-sweep-<b>-$SEED --json`; `invariance`, `frob spark check --invariance --backend <b> --workload Q --axes cotenancy,solve-queues --episodes 10 --cotenancies 4 --key ssq-inv-<b>-$SEED --json`; `plan`, `frob phylum plan --designs quad-a --worlds-per-design 8192 --json` (f, ℓ, h, the bound and the HYPOTHESIS marking; the three known values from planted inputs; no world-step counter moved); `estimate`, `frob sim estimate quad-a --worlds 8192 --tier <b> --json` (the `solve_queues` group); `label`, the label on the queued run of an unqualified backend and the promotion-evidence check's refusal (code, message, both repairs, exit 3); `refusal`, `--solve-queues auto` with `--profile strict` and with `--tier referee` (802, pointer `execution.solve_queues`, exit 3). It sources the STD-E2E helper and writes `target/e2e-logs/sim_solve_queues/<utc>.ndjson` with a transcript beside it; every line carries `ts`, `script`, `bead` (`N16c-15`), `step`, `event` (`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact command line, exit code and wall time; per run the evidence block including `labels`, the receipt's stage rows, digests compared; the bound with its inputs and marking; refusal lines with code and repairs; on failure the differing field with the run identifiers; a `summary` with assertions passed and failed, naming GATE-KIN-08. The gate's four clauses at size are N16c-16's script.

### Known answers and negative controls

The bound's known values; the label-dropping mutant; a planted receipt that reports `masked` for a queued run must be caught by comparing the receipt with the step plan's launch count. Determinism: `phylum.plan` is class D0 given its inputs.

## Considerations

- A label that is easy to shed is worthless: qualification is per backend and per fingerprint, and is read from the gate registry, never from a flag on the command line.
- `FROB-REF-820` is raised here with `detail: "solve-queues-unqualified"`, so a caller, and the refusal list that `frob --json schema` prints, tell this use apart from 820's other label misuses.
- After KILL-ROWQUEUE the option stays in the schema, as every input whose mechanism sits behind a kill gate does (VERBS-sim): `auto` and explicit capacities answer `FROB-REF-724`, exit 5, the reason naming `docs/adr/ADR-KILL-ROWQUEUE-M2.md`, while `off` (the masked path) stays accepted; `phylum.plan` stops printing the bound.
