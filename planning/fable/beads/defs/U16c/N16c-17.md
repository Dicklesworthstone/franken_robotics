## Background

A kill gate is a condition written in advance under which a mechanism is abandoned for a named fallback, so that the decision is made by a measurement and not by attachment to work already done. ✖ KILL-ROWQUEUE governs row-class solve queues: the Frontier mechanism that regroups lockstep worlds by the work their constraint solve needs (three row classes by active contact count, reassigned every step and regrouped on the `done` masks every second Newton iteration), exposed as `--solve-queues` on `sim.run` and `phylum.sweep`.

**Trigger** (any one):

1. the pilot's falsifier holds: the predicted bound 1/(1 − f + f·ℓ + h) is below 1.15 at every batch size the design campaigns use (f the solve's share of step time, ℓ the share of launched lane-time that is an active row of a live world, h the added relative overhead);
2. the measured 95% lower bound of the paired whole-step ratio against the masked path is below 1.15;
3. h ≥ f·(1 − ℓ) on the measured profile (the overhead eats the whole saving: the bound is then at most 1);
4. a digest mismatch against the masked path survives one repair cycle.

**Fallback.** The masked lockstep solve alone, with the live-fraction counters kept in the disclosure block.

**Milestone.** M2, the milestone of GATE-KIN-08 (a kill gate with no milestone of its own is decided at the milestone of the gate beside it). It is decided one step more urgently than its milestone's default because three mechanism beads exist only on its "keep" branch.

The decision has two points. Point A, after the pilot (N16c-12): if trigger 1 holds, the kill fires before any kernel is written. Point B, after the gate run (N16c-16): triggers 2, 3 and 4.

## Scope

In: evaluating the four triggers on recorded numbers; the ADR; closing or keeping the dependent beads; setting the default of the option. Out: producing the measurements.

## Technical approach

**Inputs (all from records, none re-measured here).** The pilot record `kin-rowqueue` (f, ℓ, h, predicted bounds per batch size, verdict); the GATE-KIN-08 receipt per backend (digest mismatches, general-lane share, mixed-cohort ratio, paired lower bound with its n, mean and standard deviation, and f, ℓ, h measured on the same runs); the repair-cycle log if a digest mismatch occurred.

**Procedure.**

1. Point A: read the pilot verdict. If falsified → kill; go to step 4.
2. Point B, per backend: evaluate triggers 2, 3, 4. "One repair cycle" means one bounded attempt to find and fix the cause of a mismatch, with its own re-run of clause 1; a second mismatch fires the trigger.
3. Outcome per backend: `keep` (all four clauses of the gate pass and no trigger fires), `kill` (any trigger fires on CUDA, the first backend), or `not-admitted` (Metal with unmeasured dispatch cost, or a backend where the gate's performance clause fails while CUDA passes: queues stay off there and the option reports "not qualified on this backend").
4. Record an ADR (proposed identifier ADR-KIN-14) with the numbers, the trigger that fired or the statement that none did, and the per-backend outcome.

**What changes downstream.**

- On `kill`: beads N16c-13, N16c-14 and N16c-15 close with reason `fallback` (if finished) or `superseded` (if not started), naming the masked solve; the `--solve-queues` option is removed from the verb registry; `phylum.plan` stops printing the bound; the live-fraction counters and the active-contact class occupancy stay in the disclosure block; arm E is withdrawn from the head-to-head record with a note; the counterexample rows of the mechanism stay in the registry as a killed-idea record with the calculation.
- On `keep`: `--solve-queues auto` may become the default on the qualified backend only by a separate, explicit change of default recorded in the same ADR; the `experimental-execution` label no longer applies there; the interaction with design-family lanes is measured each alone and both together when lanes exist, and the simpler configuration that reaches the larger measured gain is kept.

## Acceptance criteria

- [ ] The ADR exists at M2 exit, cites the pilot record and the gate receipts by hash, and states for each of the four triggers whether it fired, with the deciding numbers.
- [ ] If any trigger fired: the option is absent from `frob schema sim.run`; a run with the option is rejected as an unknown argument; the counters remain in the disclosure block; dependent beads are closed with typed reasons.
- [ ] If none fired: the gate row for each qualified backend is `pass`; the label is absent on those backends; the default is recorded.
- [ ] The decision was recorded by a session that did not implement the mechanism.
- [ ] The row for KILL-ROWQUEUE in `registries/gates.toml` carries the ADR identifier.

## Test plan

### Unit tests

- `kill_rule_is_pure`: the outcome is a function of the two records. Cases: predicted bounds all below 1.15 → kill at point A; measured bound 1.14 → kill; (f, ℓ, h) = (0.47, 0.5, 0.24) → h ≥ f·(1 − ℓ) = 0.235 → kill; one mismatch repaired and clean on re-run → no trigger; mismatch on re-run → kill; all clear → keep.
- `fallback_removes_option`: with the kill flag set in the registry the verb schema lacks the option.

### End-to-end script and logging

`scripts/e2e/kin_rowqueue_decision.sh` reads the pilot record and the gate receipts (`frob artifact read`), evaluates the rule, prints the decision table and verifies the downstream state (`frob schema sim.run`, a disclosure block from a fresh run). NDJSON at `target/e2e-logs/kin_rowqueue_decision/<utc-timestamp>.ndjson` with a transcript: the inputs with their hashes, one `assert` line per trigger with measured value and threshold, the outcome per backend, the commands that verify the fallback or the kept state with exit codes, and a `summary` line with `gates: ["KILL-ROWQUEUE", "GATE-KIN-08"]`.

### Known answers and negative controls

The inequality of trigger 3 is the bound's break-even: 1/(1 − f + f·ℓ + h) ≤ 1 exactly when h ≥ f·(1 − ℓ). Negative control: a planted record with a digest mismatch and a passing speed ratio must produce `kill`, not `keep` (speed never buys back determinism).

## Considerations

- The expected outcome is uncertain by design: predicted bounds at 8,192 worlds straddle 1.15. Either outcome is a result.
- Sunk-cost guard: the rule is evaluated on records by a fresh session; no threshold is renegotiated after the numbers exist.
- If the measured gain is real only at batch sizes no campaign uses, trigger 1's wording (every batch size the campaigns use) decides: kill.
