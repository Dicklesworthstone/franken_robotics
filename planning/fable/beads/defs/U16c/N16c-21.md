## Background

GATE-KIN-09 is the known-answer gate of decoupled stepping of separated robots in one world (the Moonshot mechanism that steps each robot as its own single-robot world while a certificate shows it cannot touch, message or sense another robot before the next synchronization point). Threshold (TARGET), earliest M8, with the multi-robot work of the mission chapter:

> On the two-carrier handoff fixture and a 16-robot sparse warehouse: zero contacts, message arrivals or sensor returns from another island inside a certified tile over 10⁶ robot-steps; every robot's digests equal those of the reference that steps the same islands in one world with island-wise solves on `batch-cpu`; the four controls behave as stated; the certified share is reported.

The four controls are the mechanism's known answers: the two hand cases of the separation bound; a planted message whose latency is shorter than the tile, which must end the tile at its arrival; a lidar that can see the other robot, which must end the tile at its sample instant; a thrown prop, whose island must merge before impact.

The gate's first clause is a soundness statement about certificates ("nothing happened inside a tile that was certified quiet"). It needs an independent witness. Inside a certified tile the decoupled islands cannot see each other, so a missed interaction leaves no trace in the decoupled run itself. The witness is the reference of the second clause (N16c-20's `--decouple reference` mode): the same planner decisions and the same profiles, every island inside one world with island-wise solves, plus an interaction witness that, at every world-step, runs the cross-island broad and narrow phase, casts every exteroceptive sensor's rays against the other islands, and tracks every message, recording each inter-island event with its exact time and applying no response. Because the second clause asserts that the reference's trajectories equal the decoupled run's bit for bit, the witness's events are events of the decoupled trajectories. A coupled run under `strict` (the fallback mode without `--decouple`) is not a witness: its trajectories differ from the decoupled ones from the first tile, so its event times say nothing about the decoupled run.

## Scope

In: the script; the fixtures of the table below other than the three made by N16c-20 (`rest-gap-0p10`, `head-on-3m`, `warehouse-16-sparse`, reused here unchanged), and the variant `rest-gap-0p10-5hz`; the audit of certified tiles against the coupled reference; digest comparison; the four controls; the certified share; the receipt. Out: the kill decision (N16c-22).

## Technical approach

**Script.** `scripts/e2e/kin_decouple_gate.sh [--seed S]`; sources the STD-E2E helper; idempotent; default seed 16200.

**Fixtures** (fleet scenes `frob.scene.fleet/1` of N25cx-01 under `fixtures/fleet/`, named `fleet/<name>` as N25cx-01's are and run as `--scene fleet/<name>`; each fixture made here is built on the pack, geometry and roster of N25cx-01's nearest fixture).

| Fixture | Content |
|---|---|
| `fleet/two-carrier-handoff` | N25cx-01's `fleet/two-carrier` (two carriers, one counter, one door, one directed channel; the latched payload in carrier A's island at spawn), with two material states and policies for a single handoff: the robots approach, hand over the payload and separate |
| `fleet/warehouse-16-sparse` (made by N16c-20) | Sixteen robots on the warehouse archetype's route graph with dwell points, one lidar each, one shared message channel |
| `fleet/rest-gap-0p10` (made by N16c-20) | Two robots at rest, 0.10 m between bounding spheres, acceleration caps 5 m/s², both commanded toward each other at the cap from t = 0 (contact at √0.02 = 0.1414 s), controller at 50 Hz (20 ms tiles) |
| `fleet/rest-gap-0p10-5hz` | The same with the controller at 5 Hz, so that the tile is 0.2 s (DESIGN: `sim.run` has no option that forces a tile length; the tile follows the control period of the scene) |
| `fleet/head-on-3m` (made by N16c-20) | Two robots approaching head-on at speed caps 1.5 m/s from a 3.0 m gap |
| `fleet/short-latency-message` | Robot A sends to robot B on a channel whose minimum latency (5 ms) is shorter than the 20 ms tile |
| `fleet/lidar-in-view` | Robot B inside robot A's lidar range and field of view; lidar sampled every 15 ms |
| `fleet/thrown-prop` | A robot throws a prop toward a second robot 2 m away |

**Steps.**

1. Build identity, fingerprint, features.
2. Reference with witness: `frob sim run --scene <fixture> --tier batch-cpu --decouple reference --key kdg-ref-<fixture>-<seed> --json` (the same planner and profiles as step 3; all islands in one world with island-wise solves; the interaction witness on). Record per robot the digest chain at every control tick, and the witness's event log: every contact between islands, every message arrival between islands, every sensor return that hits another island, each with its exact time and the tile it fell in.
3. Decoupled run: `frob sim run --scene <fixture> --tier batch-cpu --decouple --key kdg-dec-<fixture>-<seed> --json` (a key distinct from the reference's, so that neither returns the other's stored receipt); read the tile ledger (`frob telemetry summary <decoupled run> --table tile-ledger --json`).
4. Clause 1, audit: for every tile whose ledger row marks an island as decoupled, assert that the reference's event log has no inter-island contact, arrival or return involving that island strictly inside the tile. Accumulate robot-steps until at least 10⁶ have been audited over the two main fixtures (longer shifts or more seeds as needed). Assert zero violations.
5. Clause 2, digests: every robot's digest chain in the decoupled run equals the reference's at every control tick (`frob telemetry divergence <decoupled run> <reference run> --mode exact --json`). Assert zero differences.
6. Clause 3, controls: `rest-gap-0p10`: the first 20 ms tile is certified with γ = 0.098 m in the ledger; on `rest-gap-0p10-5hz` (0.2 s tiles) the first tile is not certified (γ = 0.10 − 0.20 < 0). `head-on-3m`: exactly 49 consecutive certified 20 ms tiles (starting at 0 to 0.96 s), then a merge recorded with clause `PossibleContact` at the tile starting at 0.98 s, where the gap is 0.06 m and γ = 0 (the strict predicate; the plan's "fifty" counts this tile). `short-latency-message`: the tile ends at the message's arrival instant with clause `MessageArrival`. `lidar-in-view`: the tile ends at the lidar's sample instant with clause `SensorInstant`. `thrown-prop`: the prop's island is merged with the target's group in a tile that starts before the impact time found by the reference.
7. Mutants: against the build with the `velocity-only-bound` mutant the audit of step 4 on `rest-gap-0p10-5hz` must find a contact inside a certified tile; against `ignore-message-clause` the message fixture must show an arrival inside a certified tile. The script fails if a mutant passes the audit.
8. Clause 4: report the certified share of robot-time per fixture (required to be reported; the kill gate reads the warehouse value against 0.5).
9. Gauntlet rows and receipt: `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g1_known_answers -- GATE-KIN-09` (and with `--features gauntlet-mutations`, under which the control runner builds the two mutants of step 7 and must report each `caught`). The script emits the receipt path and records nothing; the gate value is recorded from it by the reviewing session, which did not implement the mechanism, with `cargo run -p frob-conformance --example record_gate -- --gate GATE-KIN-09 --receipt <hash>` (one recorder per gate; a script that recorded would record for whoever ran it).

**Logging.** NDJSON at `target/e2e-logs/kin_decouple_gate/<utc-timestamp>.ndjson` with a transcript. Every line: `ts`, `script`, `bead` ("N16c-21"), `step`, `event`, the exact command line, exit code, wall time, the evidence block (claim Known answer, class, tier, profile, determinism, identities, seed), measured values with thresholds (robot-steps audited ≥ 10⁶; violations = 0; digest differences = 0; certified share with no threshold in the gate and 0.5 in the kill gate), digests compared, and on failure the first violating tile with its certificate and the reference event (kind, time, islands), and the run and snapshot paths. `summary`: counts and `gates: ["GATE-KIN-09"]`. The fixtures are generated proxies; no private scene data is logged.

## Acceptance criteria

- [ ] At least 10⁶ robot-steps audited across the handoff and warehouse fixtures with zero inter-island contacts, message arrivals or sensor returns inside a certified tile.
- [ ] Every robot's digests equal the coupled reference's on `batch-cpu` for both main fixtures.
- [ ] The four controls behave as stated, with the ledger values quoted in the log (γ = 0.098 m; 49 tiles, and γ = 0 at the tile starting at 0.98 s; clause names).
- [ ] Both mutants are caught by the audit.
- [ ] The certified share is reported per fixture.
- [ ] The receipt is cited in `registries/gates.toml` for GATE-KIN-09 by a session that did not implement the mechanism.

## Test plan

### Unit tests

Script helpers: `audit_tile_against_events` flags an event strictly inside a tile and accepts one exactly at a boundary; `count_robot_steps` sums world-steps over robots; `ledger_parse` rejects a row without an ending clause.

### End-to-end script and logging

This bead is the script. Run time TARGET: the 10⁶ audited robot-steps are about 2,000 simulated seconds for one robot at 2 ms, or about two simulated minutes of the 16-robot warehouse; the coupled reference under `strict` dominates wall time and the bead names its compute budget before running.

### Known answers and negative controls

The two hand cases; the message, lidar and thrown-prop controls; the two mutants. Metamorphic: relabeling robots permutes the ledger; a world translated by a whole number of anchor cells gives the same certificates. Determinism lanes: the decoupled and reference runs are each executed twice and compared against class D2; 1 and 24 workers.

## Considerations

- The gate is measured on `batch-cpu`, where digest equality is exact. A device-tier run is reported as a tolerance comparison with the decision-level test unless bit equality between device and CPU has been attained.
- The handoff fixture belongs to the mission chapter's multi-robot epic; if that epic's stop rule fires and the fixture is reduced, the gate runs on the reduced fixture and says so.
- A single violation is a wrong trajectory that looked plausible; it starts the one permitted repair cycle of KILL-INTERACT.
