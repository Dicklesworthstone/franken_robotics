## Background

In the design language a kinematic loop is written with the constructor `closure(port_a, port_b)`; the compiler (`frob-model`) lowers a design to a kinematic tree plus loop closures. By default a closure becomes a constraint row: a compliant equality row on the lockstep tiers, a bilateral row under the transactional profiles. The Frontier mechanism "closed-form elimination" removes a closure from the constraint system at compile time when the loop is a planar four-bar, replacing its dependent joints by closed-form functions of one input angle (kernels: N16c-31; dynamics: N16c-32).

This bead is the compile-time half. It decides **which** closures are eliminated, **which assembly branch** the mechanism is on, and **where elimination must be refused**, and it reports the verdict through `design.check` (the verb that runs the preflight stages and the analyses marked for it and returns findings with ranked repairs). It is funded only if the pilot (N16c-29) does not falsify the mechanism.

Three hazards shape it, each with a hand-checkable case.

1. **The wrong root.** The loop equation has two solutions. Parallelogram a = c = 1, b = d = 2 at θ = 90°: the open branch gives φ = 90°; the crossed branch gives φ = −143.13° with the coupler end at (1.2, −0.6). A solver that returns the crossed root for a knee assembled open has folded the leg the other way. So the branch is fixed by the design's reference pose and recorded in the model.
2. **The toggle.** Where coupler and output link line up, the argument of the arccosine reaches ±1, the branches meet and the transmission ratio is unbounded. The parallelogram at θ = 0 is such a change point: all four links are collinear. So elimination is refused near a toggle anywhere in the declared joint range, and the loop stays a row.
3. **Shared links.** Two loops that share a link are not independent one-degree-of-freedom mechanisms; only a closure whose loop shares no link with another closure is eligible.

## Scope

In: the recognizer; the branch determination and its refusal; the toggle test over the declared range; the model record of an eliminated loop; the `design.check` finding. Out: emitted kernels (N16c-31); the reduced embedding in the step (N16c-32); spatial and multi-loop mechanisms (they stay rows).

## Technical approach

**Recognition rule.** At compile time a `closure` is marked eliminable when all hold:

1. it closes exactly one independent loop of four revolute joints with parallel axes (parallelism tested exactly on the rational axis directions of the design, after the tree placement; a guarded predicate, never a float tolerance);
2. the mobility analysis A-01 (rank of the constraint Jacobian at exact rational sample points) reports one degree of freedom for the loop;
3. no other closure shares a link with it;
4. the toggle test below passes over the declared joint range;
5. the branch is determinable at the reference pose.

Everything else stays a row.

**Geometry extraction.** From the four joint axes (parallel) project the four joint centres onto the plane normal to the axes: O₁ (input crank on ground), A (crank–coupler), B (coupler–output), O₂ (output on ground). Link lengths a = |O₁A|, b = |AB|, c = |O₂B|, d = |O₁O₂|, as exact rationals or certified square roots. "Ground" is the loop link nearest the tree root; the input crank is the loop joint on the root side that carries an actuator or, failing that, the lower-numbered one; the choice is recorded. Angles θ (crank) and φ (output) are measured from the ground link direction O₁→O₂.

**Branch.** With (k_x, k_y) = (d − a·cos θ, −a·sin θ) and R = ‖k‖, the two roots are φ± = atan2(k_y, k_x) ± arccos((b² − c² − R²)/(2·c·R)). Evaluate both at the reference pose's θ₀ and compare with the reference pose's φ₀: the branch is the sign whose root equals φ₀ (within the exact-arithmetic tolerance of the design's pose). If the two roots coincide at the reference pose within that tolerance (the reference pose is at a change point), or neither matches (the design does not close), the compile **refuses**: message "closure branch cannot be determined at the reference pose", pointer to the closure, observed both roots and φ₀, repairs ranked (1) move the reference pose off the change point, (2) declare the branch explicitly in the closure. This is a design-and-model refusal (exit 3); a non-closing loop is the existing over-constraint or assembly refusal of preflight.

**Toggle test.** The transmission angle μ between coupler and output link satisfies cos μ(θ) = (b² + c² − a² − d² + 2·a·d·cos θ)/(2·b·c) (law of cosines on the triangle A, B, O₂ with |AO₂|² = a² + d² − 2·a·d·cos θ). Elimination is refused when sin μ falls below 0.17 (about 10°, DESIGN) anywhere in the declared range of θ, that is when |cos μ(θ)| > √(1 − 0.17²) = 0.98544 for some θ in the range. Because cos μ is affine in cos θ, it suffices to test the extreme values of cos θ over the range (the end points, and θ = 0 or π if inside). A refused loop stays a row and the report says `row: transmission angle below 10° at θ = …`. This is not an error.

**Model record (DESIGN).**

```rust
pub struct EliminatedLoop {
    pub closure: ClosureId,
    pub input: JointId,                 // θ
    pub dependents: [JointId; 2],       // the output joint φ and the coupler's tree joint
    pub lengths: [Exact; 4],            // a, b, c, d
    pub ground_dir: PlaneFrame,         // plane and zero direction for θ and φ
    pub branch: Branch,                 // Open (+) | Crossed (−), from the reference pose
    pub theta_range: (Angle, Angle),
    pub min_sin_transmission: f64,      // over the range, ≥ 0.17
}
```

The record is part of the compiled model and of the `ModelId`'s content: flipping the branch or changing a length is a different model.

**`design.check` finding.** For each closure: `eliminated { input, branch, min_sin_transmission }` or `row { reason }`, with reasons `not-planar-four-bar`, `mobility-not-one`, `shares-link`, `near-toggle`, `spatial`, `multi-loop`. Repairs where they exist are typed edits (for `near-toggle`: narrow the joint range; change a link length).

## Acceptance criteria

- [ ] The recognizer marks the parallelogram, the crank-rocker (1, 3, 2.5, 3) and the parallel-knee archetype as eliminable, and leaves as rows: a five-bar, a spatial (non-parallel-axis) loop, two four-bars sharing a link, and a four-bar whose range includes a toggle.
- [ ] The branch is recorded from the reference pose: the same linkage assembled open and crossed compiles to two different `ModelId`s with branches `Open` and `Crossed`.
- [ ] The parallelogram with reference pose θ₀ = 0 refuses to compile with the branch refusal and both repairs; the parallelogram with range including θ = 0 but reference pose at 90° compiles with the loop reported `row: near-toggle`.
- [ ] The toggle test agrees with a brute-force scan of sin μ over 10⁴ points of the range for 10³ random linkages.
- [ ] `frob design check --json` reports every closure as `eliminated` or `row` with its reason.
- [ ] Recognition is exact: perturbing one axis by one unit in the last place of its rational representation (a planted non-parallel axis) yields `row: not-planar-four-bar`, never a tolerance-based acceptance.
- [ ] The recognizer's share of matched closures over the archetype library is printed (the kill gate reads it against one half).

## Test plan

### Unit tests

`cargo test -p frob-model closure_elim::`

- `recognizes_parallelogram`, `recognizes_crank_rocker`, `rejects_five_bar`, `rejects_spatial_loop`, `rejects_shared_link`.
- `branch_from_reference_pose`: parallelogram at θ₀ = 90° with φ₀ = 90° → `Open`; with φ₀ = −143.13° → `Crossed`.
- `branch_refused_at_change_point`: θ₀ = 0.
- `toggle_test_values`: parallelogram: cos μ(θ) = cos θ, so sin μ < 0.17 for |θ| < 9.79°; crank-rocker at 90°: cos μ = 0.35, sin μ = 0.9367.
- `toggle_test_matches_scan` (property).
- `planted_nonparallel_axis_is_row` (negative control).
- `model_id_depends_on_branch`.

### End-to-end script and logging

`scripts/e2e/kin_loopelim_gate.sh` (N16c-33) calls `frob design check --json` on the fixture designs and asserts the per-closure findings, the branch refusal's code, message, repairs and exit code, and the matched share over the archetype library. Log lines carry the command, exit code, wall time, the evidence block (class `Tested`, tier `static`, determinism exact), each closure's verdict and reason, and on failure the differing field.

### Known answers and negative controls

The four known answers of the mechanism (parallelogram open φ = θ; crossed root at 90°; crank-rocker both branches; the change point at θ = 0, refused). Counterexample rows K9 and K10 of the Kinesis registry. Negative controls: the planted non-parallel axis; a recognizer that ignores the branch (always `Open`) must fail on the crossed assembly. Determinism: compile products are class D0; two compiles give identical bytes.

## Considerations

- Kill gate KILL-LOOPELIM's second trigger is this bead's number: a recognizer that matches fewer than half of the closures in the archetype library ends the mechanism; fallback, rows everywhere.
- Which loop joint is the "input" changes nothing physically but changes which coordinate survives; the choice is deterministic and recorded so that digests are stable.
- Linkage transmissions of the actuator chapter state that a position-dependent ratio is a closure and its Jacobian is the transformer modulus; for an eliminated loop that modulus is n(θ) exactly, and the actuator model must read it from the same record.
- Loops produced by the bounded exact linkage synthesis lane (parallel ankles, delta arms) are spatial or multi-loop in general and stay rows.
