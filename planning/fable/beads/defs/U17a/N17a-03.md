## Background

A cohort is a set of model slots and worlds running under one step plan (ADR-PHYLUM-01: the unit of batching is a
cohort of distinct designs, not one model). Each model slot holds one read-only model table; each world is a row
of indices (model, scene, task, job) plus its world address. This bead builds that structure on the host from a
population and a bucket plan, and fixes the one rule that makes mixed cohorts trustworthy: results are keyed by
world address and `ModelId`, never by slot, cohort or arrival order (ADR-PHYLUM-03). The reason is INV-KIN-04: a
world's digests depend on its address and identities only, not on its slot, its co-tenants, the capacity of its
buffers or the world count (determinism class D2), so any world can be replayed on `batch-cpu` with its own model
alone, and the CPU never needs the cohort. The alternative rejected is the incumbent convention of returning
results indexed by batch slot: it makes a result's meaning depend on who else was in the batch.

Padding inside a cohort is exact, not approximate. Padding links are identity transforms with zero inertia,
appended after the real links and masked out of every sum; padded degrees of freedom get identity rows with zero
right-hand side. Two proof obligations of the batched step carry this: PO-KIN-02 (the leading block of a padded
Cholesky factor equals the unpadded factor, because a factor's leading block does not depend on later rows) and
PO-KIN-03 (a power-of-two-aligned pairwise sum with trailing −0.0 entries equals the sum over the real prefix for
every capacity; with +0.0 entries it fails when the prefix sums to −0.0). The cohort builder's duty is to hand the
kernels tables that satisfy the preconditions of both: real entries in a prefix, padding trailing.

Worlds of one model are laid out contiguously in runs of 16 or 32, so that one warp or SIMD group holds one model
and the per-level loop over the tree does not diverge inside it. Contact counts still differ inside a run, which
is why the contact and solve stages are compacted and masked per world: homogeneity by morphology is not
homogeneity by work.

## Technical approach

Types (DESIGN: intent and layout, not signatures). `ModelTable` and `WorldSlots` are restated because the
builder and the validator are written against them; their definitions are BD-148's and BD-169's, which govern
where a restatement differs. `Cohort` and `ResultKey` are defined here:

```rust
pub struct ModelTable {           // frob_model (BD-148); one per model slot; read-only in a rollout; about 192 bytes per link
    pub model: ModelId,
    pub level_start: Vec<u16>,    // links sorted by depth; ranges per level
    pub parent: Vec<u16>,         // parent index, less than the link's own; padding links are roots of nothing
    pub placement: Vec<Se3Packed>,            // parent_from_joint
    pub screw: Vec<[f32; 18]>,    // screw basis S in ℝ^(6×3)
    pub screw_cols: Vec<u8>,      // k = 0 (padding), 1, 2 or 3 active columns: joint classes are data
    pub inertia: Vec<[f32; 10]>,  // zero for padding links
    pub limits: Vec<JointLimits>,
    pub actuator_slot: Vec<u16>,
    pub sample_range: Vec<(u16, u16)>,
}
pub struct WorldSlots { pub model: u32, pub scene: u32, pub task: u32, pub job: u32, pub addr: WorldAddr }  // frob_dyn (BD-169)
pub struct Cohort { class: ShapeClass, device: DeviceId, run_len: u8, models: Vec<ModelTable>,
                    worlds: Vec<WorldSlots>, real: BitVec /* false for padding worlds */ }
pub struct ResultKey { pub addr: WorldAddr, pub model: ModelId }   // WorldAddr = (run_seed, world, episode)
```

Joint classes are data: a joint is its screw basis with a column count, k = 1 for revolute, prismatic and helical
joints, 2 for cylindrical and universal, 3 for spherical and planar. The joint map τ(θ₁S₁)·τ(θ₂S₂)·τ(θ₃S₃), with
masked columns as the identity, is one derived kernel with no branch on joint kind. The builder therefore never
sorts or groups by joint kind.

Algorithm `form_cohorts(population, bucket_plan, device) -> Vec<Cohort>`:

1. For each design entry (`DesignId`, `ModelId`, worlds W, scene, task, job, addresses) fit its model to a class
   of the bucket plan (N17a-02). Two designs that lower to one `ModelId` share one model slot.
2. Group entries by `(ShapeClassId, device)`. Within a group order model slots by `ModelId` bytes and worlds by
   world address: the layout is a pure function of the population (class D0). Nothing downstream may rely on this
   order; it exists so that two runs of the builder agree.
3. Validate every model table against the class before admitting it (the padding contract): `parent[i] < i` for
   real links; real links occupy a prefix sorted by depth with `level_start` consistent; every index at or above
   the real link count has `screw_cols = 0`, zero inertia and identity placement; `screw_cols ∈ {0, 1, 2, 3}`;
   `sample_range` within the class's sample capacity; `actuator_slot` below the class's actuator capacity. A table
   that fails is an internal integrity fault (it would void PO-KIN-02 and PO-KIN-03), never silently repaired.
4. Lay out worlds: the W worlds of a model occupy ⌈W / run_len⌉ consecutive runs. Lanes left over in a model's
   last run are padding worlds: `real = false`, state at the neutral reset, masked in every kernel, in rewards and
   in gradient accumulation, absent from every result. `run_len` is 32 on CUDA and the device's reported execution
   width on Metal (the default of OPEN-PHYLUM-2); 16 is the alternative under measurement.
5. Set `single_structure` from the structure hashes (P-A when all equal; then no padding links exist).
6. Emit one `WorldSlots` row per lane. The `job` index is what lets several jobs share a cohort (N17a-09).
7. Record world-padding and link-padding counts per cohort for the planner's waste figure and the disclosure block
   of any performance number (buckets, variants per bucket, padding fraction).

Result rule (INV-PHYLUM-01): every result record of a cohort carries `ResultKey` and the `StepPlanId`; no record
carries a slot index, a cohort id or an arrival sequence number. Envelopes list results sorted by address. The
schema of every Phylum output is checked by a lint for the absence of slot-like fields.

## Acceptance criteria

- [ ] For 512 designs × 16 worlds in three classes the builder emits cohorts whose real worlds number 8,192, whose
      model slots equal the distinct `ModelId`s, and whose runs each hold one model.
- [ ] World padding is reported: at W = 16 and `run_len = 32` half of the lanes are padding worlds; at
      `run_len = 16` none are.
- [ ] INV-PHYLUM-01: permuting model slots, world lanes and co-tenant jobs leaves the result envelope equal after
      sorting by address (KA-376): at this bead on envelopes assembled from one recorded set of per-world result
      records; on a stepped `batch-cpu` cohort in BD-170's test target; on each device family when BD-183 lands.
- [ ] A model table with a real link after a padding link, with non-zero inertia on a padding link, or with
      `parent[i] ≥ i`, is rejected by the validator before any buffer is written.
- [ ] The cohort layout is byte-identical across two runs, across debug and release, and on Linux and macOS.
- [ ] No Phylum output schema contains a slot, cohort-position or arrival field (schema lint), and the planted
      control that adds `slot` to a result record fails the permutation test.
- [ ] Padding worlds contribute to no scorecard, reward sum or count (checked at this bead by a non-finite value
      planted in a padding lane of the result buffers: no envelope field changes; and on a stepped cohort in
      BD-170's test target: no real world's digest changes).

## Test plan

### Unit tests

- `cohort_counts`: 512 × 16 worlds, classes 18, 24, 36 in the ratio 300 : 150 : 62; asserts real-world totals
  4,800, 2,400 and 992, model-slot counts, and one model per run.
- `run_layout_padding`: W = 16, run 32 → 16 padding lanes per model; W = 40, run 32 → 2 runs, 24 padding lanes;
  W = 64, run 32 → 0.
- `shared_model_slot`: two `DesignId`s with one `ModelId` (a rename edit) occupy one slot and keep two result
  groups distinguished by address.
- `table_validator_rejects`: the three malformed tables above, plus `screw_cols = 4` and an out-of-range
  `sample_range`.
- `layout_is_pure` (property): any permutation of the input population yields the same cohorts.
- `result_key_only` (property, INV-PHYLUM-01): assemble envelopes from one recorded set of per-world result
  records of a small cohort under 100 random permutations of slots and co-tenants; envelopes compare equal after
  sorting by address. The same property on a cohort actually stepped on `batch-cpu` is `results_keyed_by_address`
  of BD-170, which needs the lowering and the gather kernel.
- `padding_world_inert`: a NaN planted in a padding lane of the result buffers changes no envelope field; on a
  stepped cohort (BD-170's test of the same name) it changes no real world's digest either.

### End-to-end script and logging

Covered by `scripts/e2e/phylum_cohort_invariance.sh` (bead N17a-10), which runs `frob phylum sweep` on a mixed
population twice with different slot permutations and co-tenants and compares envelopes after sorting by address.
This bead contributes the steps `cohort.form` and `cohort.permute`; each logs the cohort count, model slots, run
length, world- and link-padding fractions as `metric` events with units, the envelope digests as `assert` events,
and on failure the first differing address with the two records and the snapshot paths needed to replay that
world alone on `batch-cpu`.

### Known answers and negative controls

KA-376: slots and co-tenants permuted; envelopes equal after sorting by world address; slot, cohort and arrival
order appear in no result (exact; tier G3 on lockstep, CUDA and Metal). Negative controls: a slot index written
into a result record (the DESIGN control registered for KA-376); a model table with padding ahead of a real link;
+0.0 used as the padding value of a summed quantity (must change a digest when the real prefix sums to −0.0, which
is the stated failure of PO-KIN-03's precondition). Metamorphic relations: MR-01 (a world's digests are identical
alone, in any batch, slot, co-tenancy and bucket capacity) and MR-02 (a world of a mixed cohort equals the same
world in a homogeneous batch). Determinism lanes: layout twice on one machine, across worker counts, debug and
release, Linux and macOS (D0); results per back end against class D2.

## Considerations

- OPEN-PHYLUM-2 (owner: Phylum lead; measured on the M2 profile by bead N17a-06 and decided in bead N17b-11): run
  length 16 or 32. Fail-closed
  default: 32 on CUDA, the reported execution width on Metal. At 16 worlds per design the default wastes half the
  lanes, which is exactly the regime the cohort exists for, so the measurement is not optional.
- World padding is part of padding waste and must be reported beside link padding; a planner that hides it
  overstates occupancy.
- The builder runs on the warm admission path (median target 0.1 s from an accepted edit to the first committed
  step), so it must be incremental: adding one model to an existing cohort touches one slot and W lanes.
- A cohort's layout order is deterministic but not part of any contract; code outside this module that depends on
  it is a defect the permutation test is designed to find.
- Security and privacy: `WorldSlots` rows carry indices and addresses only; scene and task identities stay behind
  their slots, so a cohort table from a private scene contains no private data.
