## Background

`phylum.plan` is the read verb an agent calls before it spends compute on a population. For a population it
returns: the buckets, the padding overhead per stage exponent, bytes per world and in total, the machine that fits
it, expected throughput and expected edit-to-first-step latency. It never runs physics. Its purpose is to make the
ceiling visible before any speed test: what padding costs, whether a finer bucket pays for its launches, what
mixing designs can gain against running them one after another, and whether the population fits a card at all. The
verb is one of the seven of the `families` cluster (seven is the limit for one cluster); it first ships at M2.

The verb's executor is wired by seed bead BD-171 from three Phylum libraries: the padding arithmetic (N17a-04),
the bucket planner (N17a-05) and the population memory model (N17a-07), with shape-class fitting (N17a-02)
underneath. This bead is the end-to-end test of the capability as a user sees it: one script that drives the real
`frob` binary on fixture populations and checks every figure the verb is specified to return against the pinned
known answers, and every refusal against its code, repairs and exit code. One script per capability, not one per
mechanism; the mechanism beads name the steps they contribute.

## Scope

In: the script, its fixture population files, its assertions and its structured log; the statement of the verb's
output contract that the assertions enforce. This is the one bead for `scripts/e2e/phylum_plan.sh`: the device
unit's draft of the same script, N21b-27, is superseded by it, and the steps, known answers, negative controls
and tests that draft had and this one lacked are folded in below. Out: the executor and schema registration
(BD-171, BD-222); running any population (`phylum.sweep`); the decisions that consume the plan's output
(N21b-18, N21b-19); the
libraries (N17a-02, -04, -05, -07); measured cost inputs (N17a-06); lines that later mechanisms add to the verb's
output (the row-class solve-queue bound and the limb-archetype coverage are asserted by their own end-to-end
beads).

## Technical approach

Output contract the script enforces (DESIGN field names; schema `frob.phylum.plan.out/1`):

- `buckets[]`: per bucket its capacity row (degree-of-freedom size, links, depth, samples, contacts, rows,
  actuators), member designs and worlds, run length, Ω₁, Ω₂, Ω₃ as exact fractions and three-figure decimals, the
  stage-mix Ω, padding waste (Ω₁ − 1 and 1 − r), world-padding fraction, and the fit state of the class on the
  target (`resident`, `known`, `new`).
- `plan`: bucket count (never above eight), mode (`registered` or `population`), step-cost estimate, the
  one-bucket and unconstrained alternatives, the crossover world count N* = (B − 1)·c_L/(τ·(Ω − Ω_b)), and the
  mixing ratio D·(c_L + W·τ)/(c_L + Ω·D·W·τ) against design-by-design execution.
- `memory`: bytes per padded world per bucket, model-table bytes, rollout storage when `--training`, totals, and
  the verdict per placement (one RTX 4090, two cards split with per-shard bytes, the M5 Ultra) with the memory-only
  caveat for the M5 Ultra.
- `expected`: throughput in world-steps per second and edit-to-first-step latency per path (warm, cool, cold),
  quoted from the time estimator as the planner bead BD-171 specifies: with a calibration for the current
  hardware fingerprint each is an interval labelled `estimated`; with none each reads
  `unavailable: not calibrated on this fingerprint`; a point value for time is never returned, and cold is never
  averaged with warm or cool. (An earlier draft of this contract had these fields always present with a
  HYPOTHESIS label; the planner's rule governs.)
- `inputs`: τ, c_L, stage shares, waste limit, bucket cap, each with its evidence label and source.
- `evidence`: class `Tested` for the arithmetic fields and `Estimated` for the time fields when they are
  present; the exact fields are marked exact; determinism `exact`; tier `static`; no seed; identities of the design set.
- `cost`: `gpu_s` equal to 0 always. The verb never runs physics and allocates no device memory.

Fixtures (all `synthetic` population descriptors, committed under `fixtures/phylum/plan/`): `half-18-35`,
`mix-90-10`, `mix-89-10-1` (the three padding populations); `card-8192`, `card-512`, `card-128` (the worked card);
`spread-30-sizes` (fragmentation: the thirty sizes round(12 + 54·k/29), k = 0 … 29, that is 12, 14, 16, 18, 19,
21, 23, 25, 27, 29, 31, 32, 34, 36, 38, 40, 42, 44, 46, 47, 49, 51, 53, 55, 57, 59, 60, 62, 64, 66, equal worlds per
size); `split-14-26` (equal worlds at 14 and 26 degrees of freedom, so that Ω₁ = 26/20 = 1.3 exactly) and
`mix-14-26-x512` (the same two sizes, 256 designs each: the mixing-ratio population); `tracked-vs-wheeled` (contact axis); `oversize-70dof` (no shape class); the
eleven memory shapes; `nowhere` (4,096 designs × 2,048 rollouts at 64); and, folded from the superseded draft:
`registered-six` (sizes 10, 13, 19, 25, 37, 49); `nine-sizes` (sizes 6, 8, 11, 15, 20, 26, 34, 45, 59, each with
30 times the worlds of the next larger); `placement-18` (256 designs × 16 worlds in the 18 bucket),
`placement-36` (8,192 designs × 32 worlds in the 36 bucket), `placement-64` (256 designs × 2,048 worlds in the
64 bucket); `exceeds-device` (16,384 designs × 2,048 worlds in the 64 bucket). DESIGN: fixtures are committed
files with a `synthetic` label and a content hash in the header (the superseded draft built them inline in a
scratch directory; committed files can be hashed and shared with the planner's unit tests).

Script `scripts/e2e/phylum_plan.sh`, plain shell, idempotent, seed-explicit (the verb takes no seed; the script
passes none and asserts none is reported):

1. `frob capabilities --json` and `frob schema phylum.plan --json`: the verb exists, kind `read`, cluster
   `families`, refusal list contains `FROB-REF-160`, `-740`, `-741`.
2. `frob phylum plan --designs @fixture:half-18-35 --worlds-per-design 16 --json` and the two other padding
   populations: assert the nine Ω fractions, the bounds and r on the plan record's one-bucket alternative
   (`plan.alternatives.one_bucket`); then once more each in one bucket (`--buckets exact --max-buckets 1
   --waste-limit 3`: the cap lowered to one, and a limit above the 89/10/1 population's one-bucket waste of 2.27
   so that the planner does not refuse), asserting that the single bucket row equals the alternative and that
   the envelope prints mode `population`. To three figures: half at 18 and half at 35: r = 0.757; Ω₁ = 1.32, Ω₂ = 1.58, Ω₃ = 1.76; bounds
   1/r = 1.32 and r⁻³ = 2.30. 90% at 18 and 10% at 35: r = 0.563; Ω = 1.78, 2.96, 4.50; bounds 1.78 and 5.61.
   89% at 18, 10% at 35 and 1% at 66: r = 0.306; Ω = 3.27, 9.59, 23.3; bounds 3.27 and 35.0.
3. The worked card at 8,192, 512 and 128 worlds with `--buckets population`, passing the inputs explicitly
   (`--tau 0.5us --launch 0.45ms --shares 0.2,0.3,0.5`, each labelled `given` in `inputs`) so that the known
   answers do not move when the HYPOTHESIS defaults are replaced by measurements: assert the exact step costs
   14.75/5.00, 1.344/1.156, 0.673/0.964 ms (one bucket at 35 with the exact stage mix Ω = 3.4908 against two
   buckets, to four significant figures) and the crossover 361.3 worlds. The card's printed figures 14.8, 1.35,
   0.67 ms and 360 are the same formulas with Ω rounded to 3.5 first; they are N17a-04's unit known answer and
   are not what the verb prints. Under the default 25% waste limit the one-bucket plan (waste Ω₁ − 1 = 0.777) is
   infeasible, so the plan chooses two buckets at all three world counts, and at 128 worlds, where one bucket is
   cheaper, attaches it (0.673 ms) as the repair "raise the waste limit knowingly" (the planner's rule, N17a-05).
   Repeated with `--waste-limit 1.0`, the plan chooses two buckets at 8,192 and 512 and one bucket at 128.
3a. Break-even of a split through the verb: `split-14-26` with `--buckets population --shares 1,0,0 --tau 0.5us`
   and `--launch 0.3ms`, then `0.6ms`: the one boundary's crossover prints 2,000 and 4,000 worlds, with the form
   `general` (N·τ·(Ω − Ω_b) > (B − 1)·c_L, Ω = 1.3, Ω_b = 1, B = 2) and the unit cost `tau` (unpadded) named in
   the envelope. The single-split form's 2,600 and 5,200 worlds (KA-548, the same 0.5 µs read as the padded cost
   t) is arithmetic the verb does not print, asserted by N17a-04's `break_even_single_split`.
3b. Registered buckets: `registered-six` (equal worlds per size) with `--buckets registered --waste-limit 0.45`
   chooses 12, 18, 24, 36, 48, 64, the smallest registered capacity at or above each size, and reports the worst
   in-bucket ratio 36/25 = 1.44. The limit is passed because under the default 25% most of these singletons are
   infeasible (13 in 18 wastes 38%, 25 in 36 wastes 44%) and the planner would fall back to population mode; at
   0.45 every singleton is feasible and every merge is not (37 with 49 in 64 wastes 48.8%, 13 with 19 in 24 wastes
   50%), so six buckets is the only plan. The same fixture at the default limit asserts the fallback to mode
   `population` with the flag set. The registered
   set is read from the registry and the expected buckets are recomputed from it, so the step survives a revision
   of the set by the OPEN-SPARK-3 decision.
3c. KILL-BUCKET report: `nine-sizes` returns `buckets_needed: 9` for Ω₃ ≤ 2 with `trigger: true` and a finding
   naming KILL-BUCKET; exit 2.
4. Mixing ratio: `mix-14-26-x512` (512 designs) with `--buckets population --max-buckets 1 --waste-limit 0.3
   --shares 1,0,0 --tau 0.5us --launch 0.45ms`, so that the plan is one bucket at 26 with Ω = 1.3 exactly (waste
   0.3, at the limit), at 16, 64, 256, 1,024 and 2,048 worlds per design: the envelope's mixing ratio prints 40.6,
   11.3, 3.46, 1.44, 1.11.
5. The eleven memory shapes: bytes and the three verdicts per row; `--training` variants 8.9, 6.1, 14.8, 142 GB.
   Three placement rows by name: `placement-18` is 0.14 GB and fits one RTX 4090 and the M5 Ultra;
   `placement-36` is 22.3 GB, does not fit one card, fits two at 11.1 GB each, and fits the M5 Ultra;
   `placement-64` is 117 GB and fits only the M5 Ultra, in one buffer under 167 GiB.
6. Refusals: `oversize-70dof` → `FROB-REF-160`, exit 3, three repairs in order; `nowhere` → `FROB-REF-740`, four
   repairs; `spread-30-sizes` with `--waste-limit 0.08` → `FROB-REF-741`, `observed` 9 buckets needed and waste
   achieved at eight 2/23 = 8.70%, three repairs. For each, exactly one envelope on stdout with `ok: false`,
   `refusal.code`, `observed`, `required`, `retry`, ranked `repairs`. The same `spread-30-sizes` at
   `--waste-limit 0.10` is a boundary case that must plan in exactly eight buckets and not refuse (an even spread
   from 12 to 66 needs eight buckets at 10%).
   Two further cases with their repairs in order: `nine-sizes` with `--waste-limit 0.05` → `FROB-REF-741`
   (stratify the generator; raise the waste limit knowingly; split the campaign); `exceeds-device` →
   `FROB-REF-740` (fewer worlds per design; split across cards; the path-table Jacobian; the M5 Ultra).
6a. Two imported robots, checked against the data their asset beads recorded at M1 (read from
   `assets/robots/<name>/validation.json`, never re-typed into the script):
   - TALOS (ROBOT-talos): `frob phylum plan --designs asset-talos-<source hash> --worlds-per-design 16 --buckets
     registered --waste-limit 1.0 --json` (the limit is raised so that the registered capacity is used whatever
     the measured n_v; at the default 25% an n_v below 39 would fall back to population mode). Assert the bucket
     equals the manifest's expected bucket (the smallest registered capacity at or above n_v: 48 for the expected
     n_v of 38 to 45) and Ω₁, Ω₂, Ω₃ equal (capacity/n_v)ᵖ for p = 1, 2, 3 as recorded, exactly as fractions.
   - Apollo (ROBOT-apollo): the same command on `asset-apollo-<source hash>`. If the manifest's n_v is at most 64,
     assert the bucket and the three overheads as for TALOS. If it exceeds 64, assert `FROB-REF-160` (no shape
     class: one design that exceeds the largest admitted capacity), exit 3, `observed` n_v, `required` 64, unit
     `dof`, and that the envelope does not carry `FROB-REF-741` (fragmentation is a property of a population
     needing more than eight buckets, never of one design that fits none).
   Both are logged as `metric` lines carrying the manifest path and its digest beside the envelope's values.
7. Never runs physics: assert `cost.gpu_s == 0`, and that `frob spark place --json` reports no arena lease taken
   by the call. Then repeat one padding step and the worked card under a wrapper that denies access to every
   device and to the batched-step library: both complete, which proves the verb opens no backend.
8. Determinism: run steps 2 to 6 twice and compare envelope digests byte for byte; run once under the debug build
   and once under release.
9. Label switch: with no cost-model file, `inputs` are HYPOTHESIS; with a `synthetic` cost-model file for the
   current fingerprint they are measured; with a file for another fingerprint they stay HYPOTHESIS. In the same
   three situations the `expected` time fields read `unavailable: not calibrated on this fingerprint`, intervals
   labelled `estimated`, and `unavailable` again; no situation yields a point value for time.

Numeric assertions compare to the printed precision of the known answers (three significant figures, or the
stated rounding for milliseconds and gigabytes) and exactly where the envelope carries a fraction. The verb is of
kind `read`: the script passes no seed and no idempotency key (the superseded draft passed both; the verb takes
neither).

Logging: the script sources the shared helper of `STD-E2E` and writes newline-delimited JSON to
`target/e2e-logs/phylum_plan/<utc-timestamp>.ndjson` and a human-readable transcript beside it. Every line has
`ts`, `script`, `bead`, `step`, `event` (`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact command
line, exit code, wall time, the envelope's `evidence` block (claim, class, tier, determinism, identities, seed),
measured values with units and their pinned values or thresholds, envelope digests where two runs are compared,
and on failure the first differing value with the fixture path and the saved envelope needed to reproduce. A final
`summary` line gives assertions passed and failed and the known answers and refusal codes touched. The fixtures
are synthetic, so the log holds no private-scene data.

## Acceptance criteria

- [ ] `scripts/e2e/phylum_plan.sh` exits 0 on a correct build and non-zero on any failed assertion.
- [ ] All figures of KA-368, KA-370, KA-371 and KA-372 are asserted against the envelope, as exact fractions where
      the envelope carries them.
- [ ] The eleven memory rows and their training variants are asserted with their verdicts.
- [ ] The three refusals are asserted with code, repairs in rank order and exit codes (3 for 160; the registry's
      exit for 740 and 741).
- [ ] The run proves the verb ran no physics (`cost.gpu_s == 0`; no arena lease).
- [ ] Two consecutive runs produce byte-identical envelopes; debug and release agree.
- [ ] The log validates against the `STD-E2E` line schema and ends with a `summary` line.
- [ ] Each negative control below makes the script fail when the planted defect is enabled through the test hook.
- [ ] The break-even pair through the verb (2,000 and 4,000 worlds, general form, on `split-14-26`), the six
      registered buckets with ratio 1.44, the three named placement rows and the KILL-BUCKET finding on the
      nine-size population (exit 2) are asserted.
- [ ] The worked card is asserted at its exact values (14.75, 5.00, 1.344, 1.156, 0.673, 0.964 ms; crossover
      361.3), and `spread-30-sizes` refuses at 8% and plans in eight buckets at 10%.
- [ ] TALOS plans into the bucket and overheads its manifest records; Apollo plans likewise or, above 64 degrees
      of freedom, is refused with `FROB-REF-160` by name.
- [ ] The time fields are intervals labelled `estimated` with a calibration and `unavailable` without one.
- [ ] The verb completes with every backend denied.

## Test plan

### Unit tests

The script's own helpers are tested in shell: `assert_fraction_eq` (compares "350/197" strings exactly),
`assert_ms_3sf` (three significant figures, round-half-even), `assert_repairs_order`. The fixture loader is tested
by `cargo test -p frob-phylum fixtures_plan_parse`: each descriptor parses, sums of weights are one, sizes are in
range. Further: `e2e_log_schema_phylum_plan`; `fixtures_are_labelled_synthetic` (every fixture header carries the
label and its content hash); `expected_values_table_is_single_source` (the script reads its expected values from
one table shared with BD-171's unit tests, so the two cannot drift).

### End-to-end script and logging

As specified above: path `scripts/e2e/phylum_plan.sh`; commands `frob capabilities`, `frob schema`, `frob phylum
plan`, `frob spark place`; log at `target/e2e-logs/phylum_plan/`.

### Known answers and negative controls

Known answers asserted: KA-368 (Ω table: 1.32, 1.58, 1.76; 1.78, 2.96, 4.50; 3.27, 9.59, 23.3), KA-370 (1.25 and
1.95; eight buckets), KA-371 (worked card, at the exact stage mix: crossover 361.3; the rounded reading 360 is
N17a-04's unit answer), KA-372 (mixing ratio), and the memory table. Negative
controls, each a build-time test hook that plants one defect and must turn the script red: E[L]ᵖ for E[Lᵖ]; the
launch term dropped from the planner; a split counted as one pooled budget; nine buckets returned; a refusal
emitted with exit code 1 (exit code 1 is never emitted on purpose, so 1 always means an unhandled failure); the
planner made to return one bucket always (the worked card fails); capacities taken from the mean size instead
of the maximum (the bound check Ω₁ ≥ 1/r fails); a placement table computed with the 18-bucket bytes for a
64-bucket population (the 117 GB row fails). Also asserted: KA-547 (padding overhead Ω_p = L_max^p / E[L^p] with
1/r ≤ Ω_p ≤ r⁻ᵖ; the 90-to-10 mix gives 1.8, 3.0 and 4.5) and KA-548 (break-even of an extra bucket at
Ω = 1.3 and launch overheads of 300 and 600 µs: through the verb in the general form, 2,000 and 4,000 worlds at
τ = 0.5 µs; the single-split form's 2,600 and 5,200 at t = 0.5 µs is asserted in N17a-04's unit test).
Counterexamples exercised: CX-160, CX-161, CX-162. Determinism lanes: twice on one machine; debug and release;
Linux and macOS (the script is run on both hosts and the envelope digests are compared across them, class D0).

## Considerations

- The exit code of refusals 740 and 741: the exit table names the 70x budget codes (exit 4) and the 72x and 73x
  capability codes (exit 5) explicitly and is silent on 74x. The script reads the expected exit from the refusal
  registry rather than hard-coding it, so that the registry stays the one source of truth.
- The expected-throughput and expected-latency fields are estimates; the script asserts their presence, units and
  labels, never their values, until measured values exist.
- If KILL-PHYLUM fires, `phylum.plan` remains (it then plans per-family templates and parameter variants); the
  script's padding and memory steps stay valid and the bucket steps are re-pinned to the template regime.
- The script must stay fast (seconds): it is part of the smoke battery that every change to the crate runs, in
  continuous integration, with no device.
