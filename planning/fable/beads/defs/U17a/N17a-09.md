## Background

**Edit-to-first-step latency** is the wall time from an accepted `design.edit` (a new `DesignId`) to the first
committed world-step of the new design on a GPU. It is a first-class target with its own gate (GATE-PHYLUM-04,
measured by seed bead BD-184), because it is one of the two measured differentiators left to mixed-topology
batching and because an agent's turn is bounded by it. Three paths exist:

| Path | Phases | TARGET, 50th / 95th / 99th percentile |
|---|---|---|
| Warm: the design fits a shape class of a running cohort | Compile with memoized subterms; lower to a model table; copy tens of kilobytes into a free slot at the next reset under masks; first committed step | 0.1 s / 0.5 s / 2 s |
| Cool: a new shape class, kernels cached | The above, plus buffers and one launch-graph capture | 1 s / 5 s / 10 s |
| Cold: empty kernel cache | The above, plus kernel compilation | Reported separately; never averaged with the others |

FACT, for context (to be re-read at its primary source): an incumbent's cold kernel compile has been reported at
about 96 s and its cached start at about 0.9 s; a model edit there needs a host compile, a model upload and a new
graph capture; and no incumbent publishes an edit-to-first-step latency. The comparison number therefore does not
exist until it is measured on the pinned incumbents on the Linux host, which happens before anything is claimed.

The warm path is possible only if a new design can enter a cohort that is already running. **Slot-level dispatch
[Frontier]** provides that: one persistent environment exists per device and shape class; a slot that ends an
episode takes its next episode from any admitted job at its reset; model, scene, task and job are per-world slots.
A 96-pair comparison then occupies 192 of 8,192 slots beside other work instead of owning a launch. Results are
keyed by world address, dispatch is a pure function of queue state, and by INV-KIN-04 digests are the same under
any co-tenancy. The alternative, one environment per job, is the fallback: it idles most of a device for small
jobs and pays environment creation on every call. The scheduling policy (which job gets the next free slot)
belongs to the daemon; this bead is the Phylum-side mechanism the daemon drives.

## Scope

In: the per-cohort slot table (model slots and world lanes) and its state machine; admission of a model table
into a free model slot (`admit_model`); the pure function `plan_resets` that assigns lanes to episodes at masked
resets by writing `WorldSlots`; release; the budgeted-mode limits (job cap and reserve) as checks of the table;
the shape-change result; the fallback switch and the two measurements it reads; the two instants only the slot
table knows (`table_written`, `first_assigned`), which it hands to the admission record.

Out: the admission controller that drives this table from a run request (compile, choice of shape class, the
warm, cool and cold paths with their observed classification, the wait for a chunk boundary) and the admission
record with its phase timestamps, schema `frob.phylum.admission/1` (N17b-05, which depends on this bead: one
record exists, and it is that bead's); the dispatch policy and queues (BD-295); device-side writes under an
epoch-fenced lease and the launch graph (BD-183, BD-173); the latency gate over 1,000 edits and the incumbent
measurement (BD-184, BD-040); the co-tenancy digest gate (N17a-10).

## Technical approach

State (DESIGN):

```rust
pub enum ModelSlot { Free, Loading { model: ModelId }, Live { model: ModelId, lanes: u32, jobs: u16 } }
pub enum Lane { Padding, Idle, Running { job: JobId, addr: WorldAddr }, ResetPending { next: Option<Assignment> } }
pub struct Assignment { model: u32, scene: u32, task: u32, job: u32, addr: WorldAddr }   // becomes a WorldSlots row
pub struct SlotTable { class: ShapeClassId, models: Vec<ModelSlot>, lanes: Vec<Lane>, reserve_lanes: u32,
                       jobs: BTreeMap<JobId, JobUse>, max_jobs: u16 }
// The six instants of an admission: edit_accepted, compiled, lowered, table_written, first_assigned,
// first_committed. They are fields of the one admission record, `AdmissionRecord` of bead N17b-05 (there named
// t_accept, t_compiled, t_lowered, t_slot_written, t_first_assigned, t_first_commit). This module stamps the two
// it alone observes: table_written and first_assigned.
pub struct SlotInstants { table_written: Tick, first_assigned: Tick }
```

Operations:

1. `admit_model(table) -> Result<slot>`: fit the model (N17a-02). If the class of this environment does not fit,
   return `ShapeChange`: no shape change ever enters a running environment (refusal `FROB-REF-611` at the device
   layer); the caller, the admission controller of N17b-05, opens or waits for another environment (the cool or
   cold path), and answers `FROB-REF-611` itself only when the request was pinned to this environment. This
   module never issues the write, so the device layer's refusal is unreachable from here. Otherwise validate the table
   (the padding contract of cohort formation), take a `Free` model slot, and hand the rows to the back end, which
   writes them between chunks under a host-write lease. A model already `Live` under the same `ModelId` is shared.
   With no free model slot the admission queues; it never evicts a live model.
2. `plan_resets(free_lanes, assignments)`: a pure function. Given the lanes whose episodes ended this chunk and the
   ordered list of assignments the dispatcher chose, it writes each assignment into the lowest-indexed eligible
   lane of the model's runs (worlds of one model stay contiguous in runs of the cohort's run length; a model that
   needs a new run takes a whole free run). The output is a list of `(lane, WorldSlots)` writes applied at the
   masked reset. Lane choice may depend on queue state only, never on device timing or arrival jitter.
3. `release(job)`: when a job's last episode commits, its lanes become `Idle`; a model slot with no lanes and no
   queued work becomes `Free` at the next chunk boundary.
4. Budgeted mode (DESIGN defaults, recalibrated at M2): at most 64 jobs per environment; 5% of lanes reserved for
   short jobs (410 of 8,192); beyond either limit the admission queues with `FROB-REF-703` (admission guard,
   `retry: backoff`).
5. Fallback switch: on any invariance failure (a digest that differs between co-tenant and solo runs) or a
   99th-percentile step time more than 10% above the same job run alone, the environment is drained and the daemon
   reverts to one environment per job (`frobd --dispatch=per-job`). The decision of record is the daemon's kill
   gate KILL-SLOT; this module exposes the two measurements and honours the switch.
6. Instants: for every admission this module stamps `table_written` (the chunk boundary at which the model rows
   were handed to the back end) and `first_assigned` (the masked reset at which the first lane took the new
   model) with the monotonic clock of the daemon host, and returns them to the controller. The other four
   instants, the path taken (`warm`, `cool`, `cold`) and the rule that cold is never merged into the other two
   distributions belong to the admission record of N17b-05.

Arithmetic that motivates it (DESIGN arithmetic on a batch of 8,192 worlds, no measurement): a mission cell probe
of 16 worlds is 0.2% of the batch; a fixed-n study of 30 pairs 0.7%; an anytime-valid comparison at its cap of 96
pairs 192 slots, 2.3%; a 2,048-world run 25%. With the 5% reserve held, 40 such comparisons fit in one
batch-episode with 102 slots to spare. Ceiling, stated before any speed test: the gain over one environment per
job is at most min(k, 1/fill) for k concurrent small jobs, so at most about 42-fold for 192-slot jobs and nothing
for a single agent running one job at a time, who gains only the removal of environment creation from each call.

Determinism: slot choice is class D0 given the queue state; results are D2 per back end and independent of slot
(INV-KIN-04, INV-PHYLUM-01). Evidence: outputs of jobs sharing an environment carry the same claim product as when
run alone; until the co-tenancy gate has passed on a back end, shared runs carry the label
`experimental-execution`.

## Acceptance criteria

- [ ] A model that fits a running cohort's class is admitted into a free model slot and its worlds start at the
      next reset without a kernel compile, a buffer allocation or a launch-graph capture (counters are zero).
- [ ] A model that does not fit is never written into the running environment; the caller receives `ShapeChange`
      and the device layer's `FROB-REF-611` is unreachable from this path.
- [ ] Capacities are read, not compiled: opening an environment for a new bucket size whose kernels are cached (the
      cool path) performs zero kernel compiles, only buffer allocation and one launch-graph capture.
- [ ] `plan_resets` is a pure function: identical queue state gives identical writes across runs, worker counts and
      platforms; a planted dependence on arrival time is caught by the replay test.
- [ ] Worlds of one model remain contiguous in runs after any sequence of 10⁴ random admissions and releases
      (property test), and no lane is double-assigned.
- [ ] Budgeted mode: the 65th job queues; the reserve of 5% is never consumed by a job of the non-interactive
      class; both limits are configuration, recorded in the envelope.
- [ ] A 96-pair comparison admitted beside a 2,048-world run yields, for every world of both jobs, digests equal to
      the solo runs on `batch-cpu` (and per device family when BD-183 lands).
- [ ] The fallback switch drains and reverts on a planted digest difference and on a planted 15% step-time
      inflation; it does not trip at 5%.
- [ ] Every admission returns `table_written` and `first_assigned`, with `table_written ≤ first_assigned`, and
      the admission record of N17b-05 carries them between its lowering and first-commit instants; cold
      admissions are reported in their own distribution there.
- [ ] Cancellation of a job during admission releases its model slot and lanes with no leaked device resource.

## Test plan

### Unit tests

- `admit_warm_no_compile`: admit into a class-18 cohort; asserts compile, allocation and capture counters are 0.
- `admit_shape_change_refused`: a 35-DoF model against a class-18 environment returns `ShapeChange`.
- `plan_resets_pure` (property): random queue states replayed twice and under permuted arrival order of
  equal-priority requests resolved by the dispatcher's own total order; writes are identical.
- `runs_stay_contiguous` (property): 10⁴ random admit and release steps; invariant checked after each.
- `reserve_and_job_cap`: 64 jobs admitted, the 65th queued with `FROB-REF-703`; reserve lanes untouched by a batch
  job, usable by an interactive one.
- `slot_arithmetic`: 192/8,192 = 2.3%; reserve 410; 40 comparisons leave 102 lanes.
- `slot_instants_ordered`: over 1,000 random admissions, `table_written ≤ first_assigned`, and both lie on chunk
  boundaries. (`ledger_paths_separate`, the test that warm, cool and cold samples land in three distributions, is
  a test of the admission record and lives in N17b-05.)
- `cancel_releases`: request, drain, finalize during `Loading`; slot returns to `Free`.

### End-to-end script and logging

Covered by `scripts/e2e/phylum_cohort_invariance.sh` (bead N17a-10) for digests under co-tenancy, and by the
latency script of BD-184 for the three paths (`scripts/e2e/phylum_admission.sh` of N17b-05 exercises the
controller on top of this table). This bead contributes the steps `admit.warm`, `admit.cotenant` and
`admit.fallback`: each logs the path, the six instants of the admission record as `metric` events in milliseconds
beside the target percentiles, the compile, allocation and capture counters, the per-world digests compared with the solo
run as `assert` events, and on failure the first differing world address with the snapshot paths needed to replay
it alone.

### Known answers and negative controls

Known answers: the slot arithmetic above (exact); KA-375's co-tenancy clause (identical digests under slot
dispatch with 100 random co-tenancies) is measured by N17a-10. Negative controls: (1) a dispatch that reads
arrival time; (2) a batch-wide observation normalizer (two worlds observing 1 and 3 normalized by their batch mean
see −1 and +1; the first alone sees 0: a neighbour changes its trajectory); (3) a shape-changing write into a
running environment; (4) a lane assigned twice. Metamorphic relations: MR-01 (digests identical alone and in any
co-tenancy) and slot permutation permutes results. Determinism lanes: `plan_resets` twice on one machine, across
worker counts, debug and release, Linux and macOS (D0); results per back end (D2).

## Considerations

- Tier and funding: slot-level dispatch is Frontier within a shape class across model variants. Its pilot (a queue
  trace replayed on `batch-cpu` with and without sharing) and its kill gate KILL-SLOT are owned by the device and
  daemon chapters; this bead must not be funded past the `batch-cpu` shadow until that pilot is on record. Rollout:
  shadow on `batch-cpu` first, running each job both ways and comparing digests; rollback is per-job dispatch.
- The gain against a right-sized environment per job is the measured ratio of step time at 8,192 worlds to step
  time at the job's own size, unknown until the M2 profile; no ratio is quoted before then.
- The warm path's median target of 0.1 s leaves no room for device allocation; all work in `admit_model` is a host
  write of tens of kilobytes plus table validation.
- Fairness, priorities and preemption are the daemon's; a starvation bug there must not be patched here.
- If KILL-PHYLUM fires, slot dispatch survives unchanged for parameter variants within one tree (level P-A).
