## Background

Two designs that the mission cannot tell apart should be evaluated once. Orbit representatives catch designs
related by a symmetry; the **mission-observable digest** (Frontier) catches designs that differ only in things
nothing reads. Two designs that lower to the same model tables, under the same task, scenes, policy, kernels,
tier and profile, are the same experiment. The digest is the hash of exactly what the step plan and the task
read: the lowered tables in canonical link order, the sensor poses and the task-visible fields. Results are
memoized on it in the memo graph.

Two rules make it sound and useful.

- *Structural, not proved.* "Equal digests imply identical traces" is a statement about the simulator and is not
  dischargeable in a proof kernel. It holds by construction, because the kernels read nothing but the tables, and
  it is checked by replay: sampled pairs inside a class must produce identical digests (class `Tested`,
  determinism D2). It is never offered to a proof checker as an obligation.
- *Exact lowering.* Welded sub-assemblies are rolled up in exact rational arithmetic from the design's rational
  parameters and rounded once, so designs that are equal in exact arithmetic lower to equal bits.

The factor is reported, not promised. On the ballast fixture (eight identical slugs in 24 collinear slots)
735,471 placements fall into 24,546 classes, a reduction of 30.0, because rigid-body dynamics reads the placement
only through the count, Σx and Σx². The factor is a property of that fixture: adding a placement-dependent hot
spot, a harness length or a collision shape to what the mission reads enlarges the digest and splits classes,
down to singletons. The kill gate KILL-QUOTIENT fires if one false quotient survives a repair cycle, or if digest
classes save less than 5% of dispatches on the campaign corpus; the fallback keeps the digest as a cache key with
no claim.

The failure this design guards against is on file: a memo key written by hand from the inputs its author
remembered omitted one dependency and returned a stale promotion in an executed test. Keys are therefore derived
from declared inputs, never written by hand. The alternative rejected is a hand-maintained list of "fields that
matter".

## Scope

## Technical approach

Types (DESIGN: intent, not signatures):

```rust
pub struct MissionView<'a> {            // exactly what the step plan and the task read; nothing else
    tables: &'a ModelTable,             // in canonical link order, as lowered single-precision bits
    samples: &'a [CollisionSample],     // collision sample lists and primitives (the hull the narrow phase reads)
    actuation: &'a [ActuatorRow],       // actuator-card and transmission parameter rows
    bus: &'a BusView,                   // shared electrical bus and thermal sink: topology, limits, coupling
    sensors: &'a [SensorPose],          // sensor poses and layout (what is visible to the mission)
    task_fields: Vec<(FieldPath, Bytes)>,  // design fields the task's observation, reward and requirement terms read
}
pub struct MissionDigest(Blake3);
pub struct ExperimentKey { digest: MissionDigest, task: TaskId, scenes: SceneSetId, policy: PolicyId,
                           kernels: KernelSetId, tier: Tier, profile: ProfileId }
pub struct DigestClass { digest: MissionDigest, members: Vec<DesignId>, representative: DesignId }
```

1. **Read set, derived.** The step plan's read set is the union of the table columns named in the stage
   signatures of its kernels (parents, level ranges, placements, screw bases and column counts, inertias, limits,
   actuator slots, sample ranges, sample lists, parameter rows, interface-card rows). The task's read set is the
   list of design fields its terms declare. The mission view is built by iterating that union; there is no
   hand-written field list. Names, labels, visual meshes, provenance and comments are in no read set and never
   enter the view.
2. **Canonical link order.** Links are ordered by depth level and, within a level, by the canonical form of the
   rooted subtree (the same canonical tree form the symmetry analysis computes), so two descriptions of one tree
   give the same tables whatever order the author wrote the limbs in.
3. **Exact lowering (required of the lowering path, tested here).** A link behind a fixed joint is folded into
   its parent by the exact rational sum 𝖯_parent + G·𝖯_child·Gᵀ of pseudo-inertias (G the fixed transform); the
   result is rounded to single precision once, to nearest with ties to even. No intermediate sum is formed in
   floating point.
4. **Hash.** `MissionDigest` = BLAKE3 over the canonical byte serialization of the view: each component with a
   domain tag, lengths, and the raw bits of every number (so −0.0 and +0.0 differ and no value is reprinted).
5. **Classes.** For a design set, group by digest; each class's representative is its least `DesignId`. Report
   class count, sizes, the dispatch reduction (designs over classes) and singleton share.
6. **Split report.** For two designs in different classes, `explain_split(a, b)` lists the mission-view
   components and field paths whose bytes differ (for example `tables.inertia[3]`, `samples[12..15]`,
   `bus.limit`), mapped back to source design fields through the compile influence records. This is "the fields
   that split them".
7. **Memoization.** Episode and summary results are memoized under `ExperimentKey` plus the world address. The
   key is generated from the declared inputs of the node kind and obeys the store policy: a property test perturbs
   every declared input and requires the key to change; a live-dependency test perturbs every field the
   computation reads (found by running on `batch-cpu` with an access-recording table wrapper) and requires the
   key to change or the output to stay the same; hits are bit-identical or not served; one hit in 64, chosen by
   key hash, is recomputed in shadow, and one mismatch stops serving that node kind until it is explained
   (`FROB-REF-162`: reuse without a dependency digest, or a shadow recompute that disagreed; repairs: recompute;
   quarantine the node kind).
8. **Replay sampler.** `sample_pairs(classes, n, seed)` draws n pairs of distinct members inside classes by keyed
   hash, weighted toward large classes, for the replay check (two designs, same addresses, digest chains compared
   bit for bit on a stated tier).
9. **Fallback mode.** With the flag `mission-digest` off, or after KILL-QUOTIENT fires, steps 5 and 6 are not
   reported as deduplication and no class-level claim is made; the digest remains a memo key under the ordinary
   store policy.

Determinism: the digest is class D0 given the lowered bits, which are themselves a pure function of the design,
the compiler version and the card versions. Evidence: a result served through a digest class is `Tested` at most
and carries the class id and the fact that it was shared.

## Acceptance criteria

- [ ] Ballast fixture: 735,471 placements give 24,546 digest classes that coincide with the (Σx, Σx²) classes
      (KA-367); the two placements with Σx = 5 and Σx² = 17 against 13 are in different classes.
- [ ] Enlarging what the mission reads splits classes: with a per-slug collision sample added, the same placements
      give 735,471 singleton classes; with a task term reading one slot's occupancy, classes split by that slot.
- [ ] An edit to a field no read set contains (a label, a visual mesh) leaves the digest unchanged; an edit to any
      field in the read set changes it (property test over every declared input).
- [ ] Live-dependency test: for every table entry the `batch-cpu` step actually reads, a perturbation changes the
      digest or leaves every output bit unchanged; a planted kernel that reads an undeclared column is caught.
- [ ] Exact lowering: 10³ random welded assemblies, each lowered under 20 random orders of its fixed joints, give
      identical bits per assembly; the planted floating-point roll-up does not.
- [ ] Two descriptions of one tree with limbs written in different orders give one digest.
- [ ] Coupled-bus control: two designs whose modules have identical local summaries, one with both fingers on a
      shared bus limited to one unit of current and one with separate buses, have different digests.
- [ ] `explain_split` names the differing fields for the equal-Σx pair (the inertia entries of the carrier) and
      maps them to the slot placements in the source design.
- [ ] Memo keys built on the digest pass the key-derivation property test; a shadow mismatch stops serving within
      one hit and raises `FROB-REF-162`.
- [ ] With the flag off, no class report is produced and results are identical to a build without this bead.

## Test plan

### Unit tests

- `ballast_small_classes`: three slugs in eight slots → 54 classes from 56 placements, {1, 5, 6} and {2, 3, 7}
  merged (Σx = 12, Σx² = 62); four in twelve → 395 from 495.
- `equal_sum_unequal_square_split`: {1, 4} against {2, 3} with six common slugs → different digests.
- `unread_field_invariant` (property): random edits to names, labels and visual meshes keep the digest.
- `declared_input_sensitivity` (property): flipping one bit of any view component changes the digest.
- `signed_zero_distinguished`: a table differing only in −0.0 against +0.0 has a different digest.
- `canonical_link_order`: permuting the authoring order of four identical legs gives one digest.
- `exact_rollup_order_free` (property): fold order does not change lowered bits.
- `bus_enters_digest`: shared against separate buses → different digests.
- `explain_split_paths`: returns `tables.inertia[..]` and the source slot fields for the equal-Σx pair.
- `key_derivation_property`: every declared input of the episode node kind perturbs `ExperimentKey`.
- `shadow_mismatch_quarantines`: a planted wrong cached result is caught on its sampled shadow recompute and the
  node kind stops serving.

### Known answers and negative controls

KA-367 (735,471 placements, 24,546 classes, reduction 30.0) with its control (equal Σx, different Σx² merged);
KA-378 as a control on what the digest must contain (the coupled bus: two fingers with identical local summaries
on a bus limited to one unit of current have no feasible one-tick schedule and two feasible two-tick schedules, so
a key built from local peak-demand summaries is unsound). Counterexamples: CX-154 (same first moment is not the
same experiment), CX-157 (equal digests do not prove identical traces; the rule is structural, checked by
replay), CX-158 (a memo key written by hand omitted a dependency and returned a stale promotion), CX-159 (exact
reuse after an edit is not a speed lever: at most about a tenth of compute after a dynamics-affecting edit).
Metamorphic
relation MR-05 with its negative control, a digest that omits the second moment. Planted defects: a kernel
reading an undeclared column; a digest that reprints floats as decimal text; a roll-up in floating point.
Determinism lanes: twice on one machine; debug and release; Linux and macOS (the digest of a fixture design is
byte-identical across platforms because the lowered bits are).

## Considerations

- INV-PHYLUM-03, second half: equal mission digests mean equal lowered tables. It is true by definition of the
  digest; what can fail is the step reading something outside the tables, which the live-dependency test and the
  replay audit exist to catch.
- Exact reuse is hygiene, not a speed lever: an edit that touches any mass or geometry of a robot in contact
  invalidates every episode-level result of that design, and exact reuse after a dynamics-affecting edit is at
  most about a tenth of compute (FACT). Expect small factors on real briefs.
- The digest depends on the kernel set's read set; a kernel version that reads a new column changes the view and
  therefore every digest, which is correct and is why the kernel set is part of the experiment key.
- Private designs: the digest is a hash of tables and reveals nothing by itself, but the split report names
  fields; it is subject to the same private-scope rules as any design read.
