## Background

The batched physics step runs ten stages (kinematics, collision geometry, broad phase, narrow phase, contact
compaction, dynamics terms, constraint rows, solve, integration, sensing and resets) as named kernels over all
worlds of a batch, with no data-dependent control flow across worlds. At variation level P-A every world of a batch
has the same tree and only parameter values differ. At level P-B (model variants, tier Frontier) worlds of one batch
have different trees, joint classes, collision sample lists and actuator counts. The design decision (ADR-PHYLUM-02)
is that morphology is table data inside padded capacities: no interpreter and no kernel compile per design. Kernels
are compiled per shape class (the set of capacities one static step plan is built for) and per kernel version; they
read capacities from the step-plan header. The reason given is that the step is memory-bandwidth-bound at these
state sizes, so a table read costs bytes, not branches, and size buckets bound the bytes. The rejected alternatives
were an interpreter over a per-design program (branches diverge inside an execution group) and a compiled kernel per
design (a compile on every edit; it survives only as a gated option for long-running survivors).

This bead is the kernel-side half of P-B in crate `frob-kernels` (layer 3): the one kernel through which a world's
model slot is turned into addresses of its model table, and the mask rules that make padding exact. The table type
is BD-148's in crate `frob-model` and the per-world row `WorldSlots` is BD-169's in `frob-dyn`; lowering a model into
a table is BD-170 and the cohort assembly N17a-03, both in crate `frob-phylum`.

The plan names `K-variant-gather` in the utility kernel family and in the title of BD-170 and gives it no further
specification. The definition below is DESIGN at bead level; what binds an implementation is the contract and the
tests, not the layout.

## Scope

In: `K-variant-gather` with its manifest and CPU reference; the per-world `VariantView`; the mask predicates and
their neutral elements; the masked joint map from a screw basis with a column count; the unit tests on tier
`batch-cpu` in `f64` and `f32`.
Out: the model table type (BD-148) and the `WorldSlots` row (BD-169), both read here and restated below;
lowering (BD-170) and cohort assembly (N17a-03); device back ends and the captured launch graph
(BD-183); the level kernels themselves (BD-149, BD-150); the batch-composition invariance test at large (BD-181);
the command-line run of a two-model batch through `frob sim run --designs`, which needs BD-170's lowering on the
`sim.run` path and is therefore a stage of BD-170's script (stage 4a), with the fixtures and expected values given
below.

## Technical approach

**Data the kernel reads (DESIGN sketches; intent, not signatures; `ModelTable` and `WorldSlots` are restated from
BD-148 and BD-169, which govern where they differ; `VariantView` is this bead's).**

```rust
// frob_model (BD-148). One per model slot of a bucket; read-only during a rollout; about 192 bytes per link.
pub struct ModelTable {
    pub model: ModelId,
    pub level_start: Vec<u16>,   // links sorted by depth; ranges per level
    pub parent: Vec<u16>,        // parent index, less than the link's own
    pub placement: Vec<Se3Packed>,
    pub screw: Vec<[f32; 18]>,   // screw basis S in ℝ^(6×3)
    pub screw_cols: Vec<u8>,     // k = 0 (padding), 1, 2 or 3 active columns
    pub inertia: Vec<[f32; 10]>, // zero for padding links
    pub limits: Vec<JointLimits>,
    pub actuator_slot: Vec<u16>,
    pub sample_range: Vec<(u16, u16)>,
}
pub struct WorldSlots { pub model: u32, pub scene: u32, pub task: u32, pub job: u32, pub addr: WorldAddr }

// Written by K-variant-gather, read by every stage kernel. 24 bytes of fields (3 × u32, 5 × u16, 2 × u8),
// stored at a 32-byte stride per world (DESIGN: aligned 128-bit loads on both GPU families; the 8 tail bytes are
// zero and never read).
pub struct VariantView {
    pub table_base: u32,     // first row of this world's model in the bucket's variant slab
    pub level_base: u32,     // first entry of its level_start array
    pub model_epoch: u32,    // epoch of the table rows the view was built from
    pub links_real: u16, pub nv_real: u16, pub actuators_real: u16,
    pub sample_lo: u16, pub sample_hi: u16,
    pub depth_real: u8, pub flags: u8,   // bit 0: slot occupied; bit 1: single_structure
}
```

**Contract of `K-variant-gather`.**

1. For every world w, `view[w]` is a function of `slots[w].model` and of the header of that one model table, and of
   nothing else. No other world's row is read or written (the project's invariant that no kernel reads or writes
   another world's rows).
2. It is the only kernel whose manifest lists `WorldSlots.model` in its read footprint. Every stage kernel addresses
   the variant slab as `table_base + j` for link index j and never reads the slot itself. A lint over kernel
   manifests enforces this.
3. It is launched once per control tick, before stage 1 of the first physics step of the tick, with a fixed grid
   size, so the launch graph stays static. The view is therefore constant within a physics step; a slot rewritten at
   a masked reset takes effect at the next tick. This closes the failure "a table row read after its first use in
   the step".
4. An unoccupied world slot receives the null view (`links_real = 0`, occupied bit clear): every mask is false, the
   world does no work and contributes only neutral elements.
5. Class: exact-integer (index arithmetic and copies only). Determinism class D0 on every back end. The manifest
   records read and write footprints per buffer as index ranges in terms of capacities, no aliasing, element types
   and strides, the ownership epoch it reads (the table rows committed at the last chunk boundary) and writes, and
   the symbol of its CPU reference.
6. With `single_structure = true` in the shape class (level P-A: one tree) the launch is omitted from the step plan
   and stage kernels take the unmasked path; that path's digests are the reference for parameter variants.

**Mask predicates (all selects, never multiplications).** `link_real(w, j) = j < links_real`;
`dof_real(w, i) = i < nv_real`; `col_active(w, j, c) = c < screw_cols[table_base + j]`;
`sample_real(w, s) = sample_lo ≤ s < sample_hi`; `act_real(w, a) = a < actuators_real`. A masked lane yields the
neutral element of its consumer: −0.0 for sums, 1.0 for products, +∞ and −∞ for minimum and maximum, the identity
transform for a pose, zero inertia for a link, and an identity row with zero right-hand side in the factorization.
The reason masks are selects: an arithmetic mask computes 0·∞ = NaN. The reason the neutral zero is −0.0: with +0.0
padding, the sum of the single active element −0.0 becomes +0.0, the values compare equal, the bits differ and a
digest over bits changes with capacity.

**Joint classes are data.** A joint is its screw basis S ∈ ℝ^(6×3) with a column count k: k = 1 for revolute,
prismatic and helical joints, 2 for cylindrical and universal, 3 for spherical and planar, 0 for a padding link. The
joint transform is τ(θ₁S₁)·τ(θ₂S₂)·τ(θ₃S₃), where τ is the group retraction the integrator uses and Sᶜ is column c;
a column with `col_active` false contributes the identity by select. This is one derived kernel with no branch on
joint kind. Padding links are identity transforms with zero inertia, appended after the real links.

**Why padding is exact (the two obligations this bead tests).** PO-KIN-02: padded degrees of freedom get identity
rows and a zero right-hand side, and the leading block of a Cholesky factor does not depend on later rows, so the
real block of the padded factor equals the unpadded factor bit for bit. PO-KIN-03: reductions over a padded axis use
pairwise trees aligned to powers of two with the real entries in a prefix; any subtree of trailing −0.0 padding sums
to −0.0 and x + (−0.0) = x for every x, so the tree over capacity P reduces to the tree over the smallest power of
two that holds the real entries, whatever P is.

**Layout.** Rust reference and manifest in `crates/frob-kernels/src/variant/` (`gather.rs`, `view.rs`, `masks.rs`);
the dialect source beside the other utility kernels; the kernel registered in the library with its stage signature.

## Acceptance criteria

- [ ] `K-variant-gather` exists with a manifest (class exact-integer, D0, footprints, CPU reference) and passes the dialect lint.
- [ ] The manifest lint proves that no other kernel reads `WorldSlots.model`.
- [ ] On `batch-cpu` in `f64` and `f32`, for random trees padded to capacities 32, 64 and 128, the real-link outputs of kinematics and of the dynamics terms are bit-identical to the unpadded computation (PO-KIN-02, PO-KIN-03).
- [ ] The masked joint map returns the exact identity for k = 0 whatever the masked coordinate holds, including NaN and ∞.
- [ ] One-, two- and three-column joints agree with the joint-subgroup maps of `frob-lie` in the `f64` reference.
- [ ] Both planted defects below are caught.
- [ ] `CONTRACT.md` of `frob-kernels` documents the view, the masks and the neutral elements.
- [ ] Reachable from the command line: `frob spark check --action list` lists `K-variant-gather` with its family, class and status, and `frob spark check --kernel K-variant-gather --backend batch-cpu --reference batch-cpu` attains class exact (zero differing lanes); cancellation between chunks leaks nothing (`cancel_between_chunks_releases_views`). The two-model `frob sim run --designs` run is BD-170's stage 4a (convention: a check that needs a later bead belongs to it).

## Test plan

### Unit tests (`cargo test -p frob-kernels variant`)

- `gather_exact_headers`: 64 random model tables, 4,096 worlds with random slots; every view field equals the table header field (integers, exact).
- `gather_reads_only_own_model`: perturb every row of every other model; `view[w]` is byte-identical.
- `gather_null_slot`: an unoccupied slot yields the null view and the world's digest contribution is the empty-world digest at every capacity.
- `view_constant_within_step`: rewrite `slots[w].model` between stage 6 and stage 7 of a step (test hook); the step's outputs equal those of the old model, and the next tick uses the new one.
- `mask_select_no_nan`: masked lanes hold ∞ and NaN; outputs of real lanes are finite and unchanged.
- `joint_map_k0_identity_bits`: k = 0 with q ∈ {0, 1e30, NaN}; the result has the bits of the identity transform.
- `joint_classes_as_data`: revolute (S = (ω; 0)), prismatic (S = (0; v)), helical (pitch 0.05 m per turn), cylindrical and universal (k = 2), spherical and planar (k = 3); the map equals the joint-subgroup reference within 4 ulp in `f64`, and the masked kernel equals the same-k unmasked kernel bit for bit.
- `padding_cholesky_leading_block` (PO-KIN-02): a random symmetric positive definite 18 × 18 system padded to 24, 36 and 64 with identity rows; the leading 18 × 18 block of the factor has identical bits.
- `padding_sum_tree` (PO-KIN-03): 13 real entries padded to 16, 32, 64, 128 with −0.0; the sum has identical bits; with the real prefix summing to −0.0 it stays −0.0.
- Property test `padded_link_changes_no_real_digest`: random trees of 2 to 30 links and depth up to 8, random padding and random position among models of a bucket; the digest of the real links is invariant.
- `view_layout_stride`: `size_of::<VariantView>()` is 24 and the view buffer's stride is 32 bytes; the tail bytes of every entry are zero after a gather.
- `cancel_between_chunks_releases_views`: a two-model `batch-cpu` run of 10 chunks cancelled after chunk 2 drains the chunk in flight, finalizes a `cancelled` envelope, and returns the allocator's live-buffer count for the variant slab and the view buffer to its value before the run.

### End-to-end script and logging

`scripts/e2e/kernel_variant_gather.sh` (sources the helper of `STD-E2E`; log
`target/e2e-logs/kernel_variant_gather/<utc>.ndjson`), built only on this bead's dependencies (the kernel library
index of N21a-04 and the `spark.check` verb of N21b-32): (1) `frob spark check --action list --json` lists
`K-variant-gather` with family utility, class exact-integer and its CPU reference symbol; (2) `frob spark check
--kernel K-variant-gather --backend batch-cpu --reference batch-cpu --seed 7 --lanes 4096 --key vgather-<run>-1
--json` (4,096 seeded slot rows over 64 seeded model tables) asserts attained class `exact` and zero differing
lanes; (3) the same with `--workers 1` and `--workers 24` under keys `vgather-<run>-2` and `-3`, the receipts'
output digests equal (class D2 across worker counts; the gather itself D0). `spark.check` is a run verb: each call
carries its own key (`<run>` names this invocation; a call without a key is `FROB-REF-805`), and every envelope must
show `idempotent_replay: false`, since a replayed envelope would compare a check with itself. Each command is a
`cmd` event with exit code, wall time and the envelope's `evidence` block (class, tier, determinism, identities,
seed); each comparison an `assert` event with the digests and, on failure, the first differing lane and field;
the `summary` names GATE-PHYLUM-02 (kernel level). The two-model run through `frob sim run` (quad-12 and
hexapod-18, 32 worlds each, 200 steps, seed 7, at three capacities and each design alone, every world's digest
chain equal across the four runs) is stage 4a of BD-170's `scripts/e2e/phylum_model_variants_cpu.sh`.

### Known answers and negative controls

- KA-345 (leading block of a padded Cholesky factor, exact bits), KA-346 (power-of-two pairwise sum with trailing −0.0, exact bits), KA-375 (mixed against homogeneous: identical digests per world).
- Negative control 1 (CX-146): a planted reduction whose tree is shaped by the buffer capacity. In `f32` with a = 10⁸, b = −10⁸, c = 1: (a + b) + c = 1 and a + (b + c) = 0. The capacity sweep must report a digest difference.
- Negative control 2: padding with +0.0 in place of −0.0; `padding_sum_tree` must fail on the −0.0 prefix case.
- Negative control 3 (metamorphic relation MR-02): a stage kernel that reads the model slot directly after a mid-step rewrite; `view_constant_within_step` and the manifest lint must both fail.
- Determinism lanes: twice on one machine; across worker counts 1, 8 and 24; debug and release; Linux and macOS for `batch-cpu` (class D2 per back end; the gather itself D0 everywhere).

## Considerations

- The view costs 32 bytes per world and one launch per control tick. If the M2 profile shows the indirection `table_base + j` as a bandwidth cost, the alternative is to place worlds of one model in contiguous runs and hoist the base per run; the contract above does not change.
- Run length per model (16 or 32 worlds) is an open question decided by the M2 profile (OPEN-PHYLUM-2, default 32 on CUDA and the device's reported execution width on Metal); this kernel must be correct for any run length, including 1.
- A design whose tree does not fit the bucket's depth or link capacity never reaches this kernel: it is refused at lowering with `FROB-REF-160`.
- Kinematic loops and rolling constraints are rows of the coupled solve, not table entries; nothing here represents them.
- Pilot dependency: the Frontier part of this work is funded only if the pilot N17b-01 does not meet its falsifier.
