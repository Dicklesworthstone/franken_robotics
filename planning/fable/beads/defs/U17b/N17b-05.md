## Background

Two measured numbers and one property are what remain to distinguish Phylum's mixed batches from incumbent practice:
throughput, the time from an edit to the first GPU step, and replay of any one world outside its batch. The second
number exists because an agent's turn is bounded by it: after an agent edits a design, nothing useful happens until
the new design takes its first step on a device. **Edit-to-first-step latency** is the wall time from an accepted
`design.edit` (a new `DesignId`) to the first committed world-step of the new design on a GPU.

FACT, for context (to be re-read at the sources): an incumbent's cold kernel compile has been reported at about 96 s
and its cached start at about 0.9 s; a model edit there needs a host compile, a model upload and a new graph
capture; no incumbent publishes an edit-to-first-step latency.

Phylum's answer is that, because morphology is table data inside padded capacities, a new design that fits a shape
class of a running cohort needs no kernel compile and no graph capture: its table is a few tens of kilobytes written
into a free slot. This bead builds the mechanism that performs that write and that records, phase by phase, where
the time went. The gate that measures the latency is seed bead BD-184.

Terms. A *shape class* is the set of capacities one static step plan is built for; a *cohort* is the model slots and
worlds under one step plan; a *chunk* is the unit between two host synchronizations of a device run; the *commit
fence* is the point at which a world-step's results become the committed state.

## Scope

In: the admission controller in `frob-phylum`, which takes a run request for a design from compile to its first
committed step; the three paths and their observed classification; the one admission record with phase
timestamps (schema `frob.phylum.admission/1`); the wait for a chunk boundary and the request for the slot write;
the rule that admission changes no other world's digest, tested on `batch-cpu`; the controller's refusals and the
queueing case.
Out: the slot table the controller drives: model-slot and lane states, `admit_model`, the pure reset planner
`plan_resets`, release, the job cap and the reserve of budgeted mode, the fallback switch (N17a-09, a
dependency; it stamps the instants `table_written` and `first_assigned` into this bead's record); the
prediction of the path from a fit (`FitState` of N17a-02; here the path is observed); the device-side write into
a free slot and its digest test on devices (BD-183); the dispatcher's policy and KILL-SLOT (BD-295); the latency
campaign and the gate (BD-184); the digest gate under 100 co-tenancies (N17a-10).

## Technical approach

**The three paths and their targets (TARGET; 50th / 95th / 99th percentile).**

| Path | When | Phases | Target |
|---|---|---|---|
| Warm | The design fits a shape class of a running cohort | Compile with memoized subterms; lower to a model table; copy tens of kilobytes into a free slot at the next reset under masks; first committed step | 0.1 s / 0.5 s / 2 s |
| Cool | A new shape class is needed; kernels are cached | The above, plus buffers and one launch-graph capture | 1 s / 5 s / 10 s |
| Cold | The kernel cache is empty | The above, plus kernel compilation | Reported separately; never averaged with the others |

**Record (DESIGN).**

```rust
pub enum AdmissionPath { Warm, Cool, Cold }
pub struct AdmissionRecord {
    pub design: DesignId, pub model: ModelId, pub class: ShapeClassId, pub path: AdmissionPath,
    pub t_accept: Tick,          // the ledger event that committed the new DesignId
    pub t_submitted: Tick,       // the run request reached the controller
    pub t_compiled: Tick, pub t_lowered: Tick,
    pub t_kernels_ready: Option<Tick>,   // cold only
    pub t_env_ready: Option<Tick>,       // cool and cold: buffers allocated, graph captured
    pub t_slot_written: Tick,    // table rows and world rows written at a chunk boundary (`table_written` of N17a-09)
    pub t_first_assigned: Tick,  // the masked reset at which the first lane took the new model (`first_assigned` of N17a-09)
    pub t_first_commit: Tick,    // completion receipt of the first committed world-step of this model
    pub kernel_compiles: u32, pub graph_captures: u32, pub bytes_copied: u64, pub waited_for_slot: Tick,
}
```

All ticks are readings of the daemon host's monotonic clock. The path is *observed*, never predicted:
`Cold` if `kernel_compiles > 0`; else `Cool` if a new environment was created (`graph_captures > 0`); else `Warm`.

**Algorithm (numbered).**

1. A run request names a design. If the design was minted by a `design.edit`, `t_accept` is that event's time;
   otherwise it equals `t_submitted`.
2. Compile with memoized subterms to the immutable model.
3. Choose the shape class. Among the classes of cohorts already running on the target device, take the smallest
   one the model fits: this is the warm case. If none fits, take the class the planner assigns from the registered
   bucket set, run the memory preflight (`FROB-REF-740` if no placement admits it), allocate buffers and capture one
   launch graph; kernels come from the binary cache, and a cache miss compiles them (cold).
4. Lower the model into a model table of that class (about 192 bytes per link).
5. Reserve one free model slot and the requested world slots through the slot table of N17a-09 (`admit_model`,
   then `plan_resets` at the reset). A slot is free when unoccupied or when its episode has ended. If none is
   free, or the table's job cap (64 jobs per environment) or reserve (5% of lanes for short jobs) is reached, the
   request waits in the dispatcher's queue under the daemon's budgeted mode; the wait is part of the latency and
   is recorded in `waited_for_slot`.
6. At the next chunk boundary take an epoch-fenced host-write lease on the variant slab, write the table rows into
   the free model slot, write the world rows so that the reserved worlds reset into the new model at the next
   masked reset, and release the lease. Nothing is written inside a chunk.
7. At the next control tick the gather kernel rebuilds the per-world views and the first world-step of the new
   model runs. `t_first_commit` is taken from the device's completion receipt for that step's commit, never from
   the time the step was enqueued.
8. Append the record to the ledger and return it in the envelope's `execution.admission`.

**Rules.**

- No shape change enters a running environment: the static launch graph forbids it. The slot table answers
  `ShapeChange` and issues no write; this controller then takes the cool path into another environment, and a
  caller that insists on the running one gets `FROB-REF-611` from the controller, before anything reaches a
  device.
- Admission changes no other world's digest. The written slot was free, no kernel reads another world's rows, and
  the views of other worlds are rebuilt to the same values.
- Results of the admitted design are keyed by world address and `ModelId` like any other.
- Fallback, named in advance: on any invariance failure, or a 99th-percentile step time more than 10% over the
  same job run alone, the system falls back to one environment per job. The policy and the kill gate are the
  daemon's.

**What bounds the warm path.** The wait for the next chunk boundary is at most one chunk, and the chunk length is
the shorter of one rollout segment and the number of control intervals that fit the cancellation latency target
(250 ms at the 99th percentile, TARGET). The median target of 0.1 s therefore requires that compile and lowering
of a memoized edit take a few tens of milliseconds and that chunks be short; the record's phase split shows which
of the two a miss comes from.

**Layout.** `crates/frob-phylum/src/admit.rs`; the record schema `frob.phylum.admission/1`.

## Acceptance criteria

- [ ] A design that fits a running cohort is admitted with `kernel_compiles = 0` and `graph_captures = 0` and is classified `Warm`.
- [ ] A design that needs a new class with a warm kernel cache is classified `Cool` with exactly one graph capture; with an empty cache it is `Cold`.
- [ ] Timestamps are monotone: `t_accept ≤ t_submitted ≤ t_compiled ≤ t_lowered ≤ t_slot_written ≤ t_first_assigned ≤ t_first_commit`.
- [ ] Warm, cool and cold admissions are kept in three distributions; a cold sample is never merged into the other two.
- [ ] The slot write occurs only at a chunk boundary (a mid-chunk request is deferred, never written).
- [ ] On `batch-cpu`, admitting a design into a running cohort leaves the digest chain of every pre-existing world byte-identical to a run without the admission, over 100 random admission times.
- [ ] `t_first_commit` equals the completion receipt of the commit, and a planted enqueue-time stamp is caught.
- [ ] With no free slot the request queues and `waited_for_slot` is positive; with no admissible placement the refusal is `FROB-REF-740`; a forced shape change is `FROB-REF-611`.
- [ ] `CONTRACT.md` of `frob-phylum` documents the paths, the record and the fallback.

## Test plan

### Unit tests (`cargo test -p frob-phylum admit`)

- `path_truth_table`: (compiles, captures) = (0, 0) → Warm; (0, 1) → Cool; (3, 1) → Cold; (2, 0) → Cold.
- `timestamps_monotone`: 1,000 admissions with randomized phase durations; the order above holds.
- `write_only_at_chunk_boundary`: a request arriving 3 ms into a 50 ms chunk is written at 50 ms.
- `admission_changes_no_other_digest`: a cohort of three models and 96 worlds on `batch-cpu`; a fourth model admitted at a random tick; the first 96 worlds' digests equal the control run (INV-KIN-04).
- `warm_picks_smallest_fitting_class`: running classes 24 and 36; a 20-degree-of-freedom design goes to 24, a 30 to 36, a 40 takes the cool path.
- `no_free_slot_queues`: all model slots occupied; the request is admitted after the first episode end and `waited_for_slot` equals that interval.
- `shape_change_refused`: a request pinned to a running environment of another class → `FROB-REF-611`.
- `record_roundtrip`: the record serializes to `frob.phylum.admission/1` and back without loss.
- `ledger_paths_separate`: warm, cool and cold samples land in three distributions; a planted merge of cold into cool is caught.

### End-to-end script and logging

`scripts/e2e/phylum_admission.sh` sources the helper of `STD-E2E`; log
`target/e2e-logs/phylum_admission/<utc>.ndjson`. Steps: start a sweep of 16 designs on tier `batch-cpu` under the
daemon; issue `frob design edit <parent> set-param …` then `frob phylum sweep --designs <child> …` (expected warm);
issue an `add-limb` edit that crosses a bucket (expected cool); clear the kernel cache and repeat one edit on a
device tier where available (expected cold). For each: `cmd` events with the exact commands, exit codes and wall
time; `metric` events for every phase duration in milliseconds with the target beside it; `assert` events for the
observed path, the compile and capture counters and the digest equality of pre-existing worlds (with the first
differing world address on failure); the envelope's `evidence` block. The `summary` lists assertions; no gate is
claimed by this script.

### Known answers and negative controls

- The path classification and the counter values are the known answers (exact integers): warm (0, 0), cool (0, 1).
- Negative controls: a planted timer that stops at enqueue must fail the receipt comparison; a planted write of a model slot inside a chunk must fail `write_only_at_chunk_boundary`; a planted admission that reuses an occupied slot must change another world's digest and fail the digest test.
- Metamorphic relation: admitting designs in a different order leaves every world's digests unchanged.
- Determinism lanes: the digest tests twice on one machine and across worker counts (class D2); timing fields are excluded from digest comparison.

## Considerations

- The warm targets are TARGETs with no measurement behind them; the incumbents' figure does not exist until it is measured on the pinned incumbents, which happens before the plan claims anything about this number.
- Memoized compilation helps only as far as the edit leaves subterms untouched; a global edit (a limb added) recompiles most of the model and may dominate the warm path.
- KILL-PHYLUM: if per-family templates become the engine, admission survives as the preview path on `batch-cpu` and for parameter variants.
- Slot-level dispatch is itself a Frontier mechanism with its own kill gate in the daemon; this controller must work in the fallback (one environment per job), where every admission is cool or cold by construction.
