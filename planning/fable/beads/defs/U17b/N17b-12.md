## Background

Every capability of the project reaches agents through one registry, `registries/verbs.toml`, owned by crate
`frob-verbs`. The command-line tool, the daemon protocol, the MCP tool definitions, the schemas, the refusal table
and the agent documentation are generated from it, so the surfaces cannot drift; a gate diffs the served tool list
against the registry. A verb belongs to a cluster (a namespace), and a cluster holds at most seven verbs, because
agents choose badly among long tool lists. Verb kinds: `read` returns stored or cheaply computed facts and changes
nothing; `run` spends compute, takes an idempotency key and a budget, accepts a bounded synchronous wait and
otherwise returns a job handle with exit code 8.

Phylum's cluster is `phylum`, with exactly seven verbs: the limit. The chapter's rule that follows from the limit:
specialization of survivors is an option of `phylum.sweep`, not a verb, and stays off until its gate to fund passes.
The seven verbs land over three milestones and are implemented by different beads; this bead owns the cluster as a
whole: the seven registry entries, their schema names, their refusal lists, the options, and the tests that keep
the cluster at seven and its surfaces consistent.

## Scope

In: the seven registry entries; schema identifiers; refusal lists; options and their gating; the not-yet-implemented
behaviour; MCP names; the cluster tests.
Out: the behaviour of each verb (named per row); generation machinery and the served tool list (surface beads);
`opt.archive`, which lives in the `opt` cluster (N17b-18).

Order of work. This is a registry bead: it is data entry that can be done as soon as the registry skeleton
(BD-022) and the refusal rows (N17-REF) exist, and it depends on no verb's implementation. Every entry exists
from M2 with the not-implemented answer, so the beads that implement the verbs (BD-171, N17b-04, BD-287, BD-285,
N17b-14, BD-353, N17b-18) depend on this bead and fill their entries in; this bead never waits for them. Its
end-to-end script accepts either a result or the not-implemented refusal for each verb, according to the
capability report, and so passes at every stage.

## Technical approach

**The seven verbs.**

| Verb | Kind | First milestone | What it returns | Implemented by | Chapter refusals it may raise |
|---|---|---|---|---|---|
| `phylum.plan` | read | M2 | For a population: buckets, padding overhead per stage exponent, bytes per world and in total, the machine that fits it, expected throughput and expected edit-to-first-step. Never runs physics. | BD-171 | 160, 740, 741 |
| `phylum.sweep` | run | M2 | Runs a population (`--designs`, `--worlds-per-design`, `--task`, `--tier`); one envelope with a provisional scorecard per design, cohort count, padding overhead, the map delta of the quality-diversity map, and the referee coverage figures. | N17b-04 | 160, 740, 741 |
| `phylum.generate` | read | M3 | Samples designs from a generator with derivations and log-probabilities; `--locate` tests support; `--report` gives rejection rates and the bucket histogram. | BD-287 | 541 |
| `phylum.quotient` | read | M3 | Orbit representatives under the observation-preserving group with the orbit count, and mission-digest classes for a design set, with the fields that split them. | BD-285 | 161 |
| `phylum.reuse` | read | M3 | For an edit: which cached results survive, which are invalidated, and the field that forced each invalidation. | N17b-14 | 162 |
| `phylum.gradient` | run | M4 | The paired finite-difference gradient with intervals, per-pair divergence steps and the `truncated-horizon` label where it applies. | BD-353 | 540 |
| `phylum.map` | read | M4 | The quality-diversity map of a campaign or one dispatch; merge of maps. | N17b-18 | — |

**One registry entry (the form every entry takes).**

```toml
[[verb]]
name = "phylum.sweep"
cluster = "phylum"
kind = "run"
tier = "F"
capabilities = ["design:read", "sim:run"]
input_schema = "frob.phylum.sweep.in/1"
output_schema = "frob.phylum.sweep.out/1"
refusals = ["FROB-REF-160", "FROB-REF-740", "FROB-REF-741"]
idempotent = false
cost_model = "estimated by sim.estimate from the bucket plan"
first_milestone = "M2"
task_clusters = ["populate"]
examples = ["frob phylum sweep --designs @archive:gen-14 --task stairs-0.15 --worlds-per-design 16 --tier gpu-cuda --json"]
```

Schema identifiers follow `frob.phylum.<verb>.in/1` and `frob.phylum.<verb>.out/1` for all seven. Surface-wide
refusals (budget, capability, protocol) are appended by the generator and are not repeated per verb. The capability
scope names are placeholders to be aligned with the scope registry of the surface when it exists.

**Options registered with the cluster.**

| Option | On | Meaning | Until its gate passes |
|---|---|---|---|
| `--limb-kernels` | `phylum.sweep` | Run kinematics and dynamics terms through limb-archetype kernels, bit-identical to the table-driven kernel | Refused with the capability refusal `FROB-REF-724` |
| `--solve-queues` | `phylum.sweep` | Regroup worlds by solver work in row-class queues, bit-identical to the masked path | Refused the same way |
| `--specialize-survivors` | `phylum.sweep` | Per-design specialized kernels for long-running survivors (the promotion mechanism is N17a-16) | Off and refused until the gate that funds specialization passes |
| `--quotient` | `phylum.sweep` | Dispatch one representative per orbit and per mission-digest class and expand the results afterwards (wired by BD-285, M3) | Refused with `FROB-REF-724` until BD-285 lands; under the fallback of the quotient kill gate it dispatches orbit representatives only |
| `--family-lanes` | `phylum.sweep` (and `sim.run`) | Run worlds that share tree, sensor graph and contact mode in design-family lanes, bit-identical to the general masked lane (BD-356, M4) | Refused with `FROB-REF-724` until the lanes land; rejected again if the family-lane kill gate fires |
| `--capacity-step` | `phylum.sweep` | Test option of the digest gate: place every design in a larger bucket than its native one (N17a-10) | — |
| `--method adjoint` | `phylum.gradient` | A Moonshot alternative through the converged contact solve; the paired finite-difference method stays the reference | Refused |
| `--locate`, `--report` | `phylum.generate` | Support test (N17a-20); rejection rates and bucket histogram (N17a-18) | — |
| `--stratify` | `phylum.generate` | Stratified sampling by shape class with quotas (N17a-18) | — |
| `--merge` | `phylum.map` | Merge two or more maps of one specification | — |

`phylum.plan` additionally prints, for the population in hand, the memory table by machine, the bound of the
row-class solve queues and the limb-archetype coverage; those fields are added by the beads that own the
mechanisms and are optional in the schema until then.

**Before a verb is implemented.** All seven entries exist from M2 with their `first_milestone`. A verb whose
milestone has not come answers `FROB-REF-724` ("not implemented in this build", exit 5) with one envelope, on both
surfaces; `frob capabilities` lists it as absent. This is what lets agent documentation and the tool list be
generated once and stay stable.

**MCP names.** The tool name is the verb name with `.` and `-` replaced by `_`: `phylum_plan`, `phylum_sweep`,
`phylum_generate`, `phylum_quotient`, `phylum_reuse`, `phylum_gradient`, `phylum_map`. No registry name contains an
underscore, so the map is one-to-one.

## Acceptance criteria

- [ ] `registries/verbs.toml` holds exactly seven entries with `cluster = "phylum"`, each with name, kind, tier, schemas, refusals, first milestone and at least one example.
- [ ] A lint fails the build if an eighth verb is added to the cluster or if a `phylum` verb gains a second spelling.
- [ ] `frob schema phylum.<verb>` prints both schemas for all seven; the generated refusal table lists the chapter's seven codes on the verbs above.
- [ ] Each verb not yet implemented answers `FROB-REF-724` with exit 5 and one envelope; each implemented verb passes its own bead's tests through the generated surface.
- [ ] Every gated option answers `FROB-REF-724` until its gate is recorded PASS, and no option exists as a separate verb.
- [ ] The MCP tool names are the seven above and the served tool list equals the registry for this cluster.
- [ ] The agent documentation generated from the registry contains the table of this bead's seven verbs with kinds and milestones.

## Test plan

### Unit tests (`cargo test -p frob-verbs phylum_cluster`)

- `cluster_has_exactly_seven`: the registry loader counts seven; a fixture registry with eight fails with the cluster-limit error.
- `kinds_and_milestones`: plan, generate, quotient, reuse, map are `read`; sweep and gradient are `run`; milestones M2, M2, M3, M3, M3, M4, M4 in the table's order.
- `schemas_named`: each verb's schema identifiers match `frob.phylum.<verb>.(in|out)/1`.
- `refusal_lists`: plan and sweep list 160, 740, 741; generate 541; quotient 161; reuse 162; gradient 540.
- `mcp_names_one_to_one`: the seven names above; no collision with any other cluster.
- `unimplemented_answers_724`: with the gradient capability absent, `phylum.gradient` returns `ok: false`, code `FROB-REF-724`, exit 5.
- `options_gated`: `--limb-kernels`, `--solve-queues`, `--specialize-survivors`, `--quotient` and `--family-lanes` on `phylum.sweep` and `--method adjoint` on `phylum.gradient` → `FROB-REF-724`; an unknown option → the schema refusal, exit 3 (a misspelt parameter is a refusal, not a default).

### End-to-end script and logging

`scripts/e2e/phylum_verb_cluster.sh` sources the helper of `STD-E2E`; log
`target/e2e-logs/phylum_verb_cluster/<utc>.ndjson`. It runs `frob capabilities --json`, `frob schema phylum.<verb>
--json` for the seven verbs, each verb once with a minimal valid input on tier `batch-cpu` (expecting a result or
`FROB-REF-724` according to the capability report), one call with a misspelt parameter, and, where the MCP server
is present, lists tools and calls `phylum_plan`. Each call is a `cmd` event with the exact command, exit code, wall
time and the `evidence` block; `assert` events check one envelope per call, the exit code against the capability
report, and equality of the CLI and MCP envelopes for `phylum.plan`. The `summary` lists assertions; no gate is
claimed.

### Known answers and negative controls

- Known answer: seven verbs, the limit for one cluster.
- Negative controls: a registry with a `phylum.specialize` verb must fail the limit lint; a verb answering with two envelopes or with exit 1 must fail the surface test; an option accepted silently before its gate must fail `options_gated`.
- Determinism: generated schemas and tool lists are byte-identical across runs and platforms.

## Considerations

- The limit of seven is a surface rule, not a Phylum rule: if a later mechanism needs a new population verb, it has to become an option of an existing one or go to another cluster.
- If the kill gate on mixed batches fires, the verbs and schemas stay; `phylum.plan` reports template coverage and `phylum.sweep` forms cohorts by exact tree.
- If the kill gate on paired gradients fires, `phylum.gradient` remains registered and returns the stencil as a sensitivity report, with its claim reduced accordingly.
- Capability scope names here are provisional and must be reconciled with the surface's scope registry.
