## Background

The project memoizes everything downstream of a compiled model in one content-addressed graph: subterm compiles,
analyses, controller synthesis, step plans, kernel binaries, scene compiles, episodes, comparisons. Phylum adds a
rule for reusing such results after a design edit and across designs, the invalidation contract (seed bead BD-286):
every memoized result records the digest of the fields it read, and after an edit a result is reused exactly when
that digest is unchanged. A reuse rule is only as sound as its keys, and the plan has a counterexample on file:
in an executed test a dependency omitted from a key returned a stale promotion (four edit states of a two-scene
fixture; a key that omitted packet delivery time kept a stale result at the fourth state). Two measures follow, and
this bead builds them for cross-design reuse:

- *Keys are derived from declared inputs, never written by hand.*
- *Calibration.* One hit in 64, chosen by key hash, is recomputed in shadow. One mismatch stops serving that kind of
  node until it is explained.

The refusal that makes the measures visible is `FROB-REF-162`, "reuse without a dependency digest": raised when a
cached result has no recorded dependency digest, or the shadow recompute disagreed; repairs: recompute; quarantine
the node kind. The invariant is INV-PHYLUM-04: a memoized result is served only when its dependency digest is
unchanged.

Why the trip-wire and not trust: a stale result served is a false accept of evidence, which the project prices at
100 units against the GPU-seconds of a needless recomputation (a DESIGN ratio recorded in the memo policy).

## Scope

In: the requirement that a node carry a dependency digest before it may be reused across an edit or across designs;
the deterministic shadow sample; byte comparison; quarantine of a node kind with its persistence and its lift; the
refusal; the property tests that keys are derived and complete.
Out: the memo store, eviction and budget (the memo graph beads); the reuse rule itself, orbit transport and the
gate (BD-286); the verb (N17b-14).

## Technical approach

**Dependency digest (DESIGN).** For a result ρ of node kind k, `dep_digest(ρ)` is BLAKE3 over, in canonical path
order, the pairs (field path, canonical value bytes) of every design field ρ read, followed by the identities of
its non-design inputs as declared for kind k (for an episode: scene, task, controller or policy, world address,
tier, kernel versions, effort profile, device family; for an analysis: analysis version and parameters). The read
set comes from the compiler's influence records, which store for each product the source paths it read at field
granularity. A node created without a digest is storable and is never offered for reuse across an edit.

**Derived keys.** Each node kind declares its inputs once, in a table the key function is generated from. Two
property tests exist per kind: (a) perturbing any declared input changes the key; (b) perturbing any field the
computation actually reads either changes the key or leaves the output bytes unchanged (the live-dependency test).
Test (b) is what finds a dependency the author forgot to declare.

**Shadow sample.** A hit with key K is shadowed iff the six low bits of BLAKE3(K ‖ "shadow/1") are zero: one hit in
64, a pure function of the key, so the same hits are shadowed on every machine and a replay shadows the same ones.
The rate is a configuration value recorded in the memo policy's contract; 1/64 is the default.

**Shadow procedure (numbered).**

1. Serve the hit as usual (the caller is not delayed).
2. Recompute the node from its inputs in the background, on the same back end and fingerprint for episodes
   (reuse of a memoized episode is admitted only inside determinism class D2 on the same back end; analyses are
   class D0).
3. Compare output bytes. Equal: record `shadow_ok`. Unequal: record a determinism violation with both digests and
   the inputs, then quarantine.

**Quarantine.** One mismatch stops serving every node of that kind: the kind's state in the ledger becomes
`quarantined { since, mismatch_id }`; every later hit of the kind is treated as a miss and recomputed; any verb
that would have reported a reuse of that kind raises `FROB-REF-162` with `pointer` = the kind and the mismatch
record. The quarantine is lifted only by a record that names the cause and the fix and that re-runs the mismatching
node to equal bytes; it is never lifted by a restart.

**Refusal.** `FROB-REF-162` (exit 3, `retry: after-change`): `pointer` the node kind and key; `observed`
`dep_digest: absent` or the two digests; repairs in order: recompute; quarantine the node kind.

**Layout.** `crates/frob-phylum/src/reuse/calibrate.rs`; key declarations beside each node kind; state in the
ledger of `frob-chronicle`.

## Acceptance criteria

- [ ] A node without a dependency digest is never reported as reusable; the attempt raises `FROB-REF-162`.
- [ ] Exactly the hits selected by the key-hash rule are shadowed, identically on Linux and macOS; over 64,000 synthetic keys the count is within 1,000 ± 100.
- [ ] A planted stale node (output bytes altered) that falls in the shadow sample quarantines its kind at the first shadowed hit; later hits of the kind recompute.
- [ ] Quarantine persists across process restarts and is lifted only by an explanation record whose re-run matches.
- [ ] Every node kind that takes part in cross-design reuse has both property tests, and the planted omitted-dependency key is caught by the live-dependency test.
- [ ] Shadowing adds no latency to the served hit (the comparison is asynchronous) and its cost is reported per kind.
- [ ] `CONTRACT.md` of `frob-phylum` states the shadow rate, the loss ratio of 100 to 1 and the quarantine rule.

## Test plan

### Unit tests (`cargo test -p frob-phylum reuse::calibrate`)

- `dep_digest_canonical_order`: the same read set presented in two path orders gives one digest; one changed value gives another.
- `dep_digest_absent_refuses`: a node stored without a digest → `FROB-REF-162`, `observed: dep_digest: absent`.
- `shadow_selection_rate`: 64,000 keys → about 1,000 selected; the selected set is a pure function of the keys.
- `shadow_mismatch_quarantines_kind`: analysis kind A with one altered node in the sample → state `quarantined`; a different kind B keeps serving.
- `quarantine_survives_restart`: reopen the ledger; kind A is still quarantined.
- `quarantine_lift_requires_matching_rerun`: an explanation record whose re-run still mismatches is rejected.
- `derived_key_declared_inputs` (per kind): each declared input perturbed → key changes.
- `live_dependency` (per kind): each read field perturbed → key changes or output bytes unchanged.
- `episode_shadow_same_backend_only`: an episode recorded on another fingerprint is neither served nor used as a shadow reference.

### End-to-end script and logging

`scripts/e2e/phylum_reuse_calibration.sh` sources the helper of `STD-E2E`; log
`target/e2e-logs/phylum_reuse_calibration/<utc>.ndjson`. Steps: populate analyses and short `batch-cpu` episodes for
a fixture design (`frob design check`, `frob sim run`); repeat the calls and log hits and shadowed hits (`metric`
events with counts and the expected rate); run with the test feature that alters one cached analysis node whose key
is in the shadow sample, then call `frob phylum reuse --edit @fixture:rename-body --json` and assert exit 3 with
`FROB-REF-162` naming the kind; verify `frob store status --json` shows the quarantine; apply the explanation
record and assert serving resumes. Every command is a `cmd` event with exit code, wall time and the `evidence`
block; digests compared are logged; on failure the first differing byte offset and the node key are logged. The
`summary` lists assertions; no gate is claimed here (the gate is recorded by BD-286).

### Known answers and negative controls

- Known answer: the decision-reuse fixture. Two scenes whose decisions commit at ticks 2 and 4; a camera packet arrives at tick 1; four states (initial; a display label renamed; delivery delayed to tick 2; delivery delayed to tick 3). A correctly keyed graph evaluates 2, 0, 0, 1 scene pairs and recomputes the verdict 1, 0, 0, 1 times, and every verdict matches a fresh replay.
- Negative control (CX-158): the same fixture with delivery time omitted from the key keeps a stale promotion at the fourth state; the live-dependency test and the shadow sample must each catch it.
- Negative control: a shadow rule keyed by arrival count instead of key hash selects different hits on a second run; the selection test must fail.
- Determinism lanes: selection and digests are exact (class D0) and identical across platforms; episode shadows are compared inside class D2 on one back end.

## Considerations

- A rate of 1 in 64 detects a kind-wide key defect quickly and a rare, input-specific one slowly; it is a trip-wire, not a proof. The property tests are the first line.
- Quarantine of the episode kind makes every campaign recompute; that is the intended cost of a broken invariant.
- The ceiling of the benefit is small by the plan's own arithmetic (exact reuse after a dynamics-affecting edit is at most about a tenth of compute), so nothing here is tuned for speed.
- Cited evidence is pinned in the ledger and does not depend on the cache: deleting the memo store loses no result a claim cites.
