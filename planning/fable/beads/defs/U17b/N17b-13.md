## Background

The project memoizes everything downstream of a compiled model in one content-addressed graph: subterm compiles,
analyses, controller synthesis, step plans, kernel binaries, scene compiles, episodes, comparisons. Phylum adds a
rule for reusing such results after a design edit and across designs, the invalidation contract (seed bead BD-286):
every memoized result records the digest of the fields it read, and after an edit a result is reused exactly when
that digest is unchanged. A reuse rule is only as sound as its keys, and the plan has a counterexample on file:
in an executed test a dependency omitted from a key returned a stale promotion (four edit states of a two-scene
fixture; a key that omitted packet delivery time kept a stale result at the fourth state). Two measures follow, and
this bead builds them for cross-design reuse:

- *Keys are derived from declared inputs, never written by hand.*
- *Calibration.* One hit in 64, chosen by key hash, is recomputed in shadow. One mismatch stops serving that kind of
  node until it is explained.

The refusal that makes the measures visible is `FROB-REF-162`, "reuse without a dependency digest": raised when a
cached result has no recorded dependency digest, or the shadow recompute disagreed; repairs: recompute; quarantine
the node kind. The invariant is INV-PHYLUM-04: a memoized result is served only when its dependency digest is
unchanged.

Why the trip-wire and not trust: a stale result served is a false accept of evidence, which the project prices at
100 units against the GPU-seconds of a needless recomputation (a DESIGN ratio recorded in the memo policy).

## Scope

In: the requirement that a node carry a dependency digest before it may be reused across an edit or across designs;
the registration of the cross-design node kinds with the memo graph, with derived keys and both property tests per
kind; routing every cross-design hit through the memo graph's shadow sample; quarantine of a node kind as seen from
Phylum (its persistence, its explanation precondition for lifting, and its surfacing as `FROB-REF-162`); the
refusal.
Out: the memo graph's machinery, which this bead uses and does not restate: keys, the node-kind registry and the
two generated key tests (N28b-37); the one shadow selector, the recomputation and byte comparison, the per-kind
stop latch (the `Disabled` disposition) and the one lift rule `Memo::reenable` (N28b-38, M1, reached through
BD-111); eviction, byte accounting and the budget (N33c-18, N33c-19); the wiring of analysis kinds (BD-111) and of
episode kinds (BD-220). This bead contains no second selector, no second stop-serving state and no second lift
rule. The reuse rule itself, orbit transport and the gate (BD-286); the verb (N17b-14), which depends on this bead
and is the first command-line surface of `FROB-REF-162`.

## Technical approach

**Dependency digest (DESIGN).** For a result ρ of node kind k, `dep_digest(ρ)` is BLAKE3 over, in canonical path
order, the pairs (field path, canonical value bytes) of every design field ρ read, followed by the identities of
its non-design inputs as declared for kind k (for an episode: scene, task, controller or policy, world address,
tier, kernel versions, effort profile, device family; for an analysis: analysis version and parameters). The read
set comes from the compiler's influence records, which store for each product the source paths it read at field
granularity. A node created without a digest is storable and is never offered for reuse across an edit.

**Derived keys.** Each node kind declares its inputs once, in a table the key function is generated from. Two
property tests exist per kind: (a) perturbing any declared input changes the key; (b) perturbing any field the
computation actually reads either changes the key or leaves the output bytes unchanged (the live-dependency test).
Test (b) is what finds a dependency the author forgot to declare.

**Shadow sample (the memo graph's, used as is).** The rule of the chapter is one hit in 64, deterministic and
reading no clock, recomputed in shadow. Every cross-design hit is served through the memo graph's `lookup`, so it is
shadowed exactly when N28b-38's one selector fires for that node: each node has a durable hit ordinal n (incremented
in the serve transaction, so it survives restarts and concurrent processes never share one), its phase is p = the
low six bits of BLAKE3(kind ‖ kind version ‖ key), and a hit is shadowed when (n + p) mod 64 = 0. Every window of
64 consecutive hits of one node therefore holds exactly one shadowed hit, and among keys hit once one in 64 is
chosen by key hash, as the chapter says. frob-phylum adds no selector, because two selectors over one store would
shadow different hits and leave each other's blind spots. The rate 1/64 is a DESIGN constant of the memo policy;
changing it is a new policy version (N28b-38). A shadowed hit is recomputed on the same back end and fingerprint
for episodes (a memoized episode is served only inside determinism class D2 on the same back end; analyses are
class D0), its bytes are compared and the recomputed result is returned; a mismatch writes the memo graph's
determinism-violation record with both digests, the key, the declared inputs and the read set.

**Quarantine (the memo graph's stop latch, seen from Phylum).** One mismatch sets N28b-38's latch for that node
kind: no further hit of the kind is served by any session, the memo graph answers `Disabled` and executes every
later lookup. Phylum's view of that state, `quarantined { since, mismatch_id }`, is read from the latch record,
never kept separately; the reuse check `reuse::calibrate::reusable(node)`, which every verb that reports a reuse
calls (`phylum.reuse`, N17b-14, is the first), returns `FROB-REF-162` with `pointer` = the kind and the mismatch
record. The latch persists across restarts (it is a ledger record). It is lifted only by N28b-38's lift rule,
`Memo::reenable(kind, explanation)`: the explanation names the violation, the cause and the fix and carries a re-run
of the mismatching node under the fixed code equal to the fresh result byte for byte twice (the chapter's "until it
is explained"); a restart, a store deletion or a bare version bump does not lift it. This bead adds nothing to that
rule; its tests check that the cross-design kinds it registers obey it.

**Refusal.** `FROB-REF-162` (exit 3, `retry: after-change`): `pointer` the node kind and key; `observed`
`dep_digest: absent` or the two digests; repairs in order: recompute; quarantine the node kind.

**Layout.** `crates/frob-phylum/src/reuse/calibrate.rs`; key declarations beside each node kind; state in the
ledger of `frob-chronicle`.

## Acceptance criteria

- [ ] A node without a dependency digest is never reported as reusable; the attempt raises `FROB-REF-162`.
- [ ] Cross-design hits are shadowed exactly when N28b-38's selector fires (no selector exists in `frob-phylum`; a search of the crate finds none), identically on Linux and macOS for the same hit sequence; 64,000 interleaved hits on 100 nodes of one kind, 640 per node, give exactly 1,000 shadowed hits, one in every 64 consecutive hits of each node.
- [ ] A planted stale node (output bytes altered) quarantines its kind at its first shadowed hit, which comes within 64 of that node's hits; later hits of the kind recompute.
- [ ] Quarantine persists across process restarts and is lifted only by `Memo::reenable` with an explanation record whose re-run matches twice.
- [ ] Every node kind that takes part in cross-design reuse has both property tests, and the planted omitted-dependency key is caught by the live-dependency test.
- [ ] Shadowing adds no latency to a served (unshadowed) hit; a shadowed hit costs one recomputation, since the recomputed result is what it returns, and that cost is reported per kind.
- [ ] `CONTRACT.md` of `frob-phylum` states the shadow rate, the loss ratio of 100 to 1 and the quarantine rule.

## Test plan

### Unit tests (`cargo test -p frob-phylum reuse::calibrate`)

- `dep_digest_canonical_order`: the same read set presented in two path orders gives one digest; one changed value gives another.
- `dep_digest_absent_refuses`: a node stored without a digest → `FROB-REF-162`, `observed: dep_digest: absent`.
- `shadow_uses_memo_selector`: 64,000 cross-design hits of one kind on 100 nodes, 640 each, interleaved → the shadowed hits are exactly those N28b-38's selector reports for the same sequence, exactly 1,000 of them, ten per node and one in every 64 consecutive hits of each node; two cross-design keys requested alternately 6,400 times each are shadowed 100 times each; replaying the sequence shadows the same hits.
- `shadow_mismatch_quarantines_kind`: analysis kind A with one altered node, hit until its first shadowed hit (at most 64 hits) → the memo graph answers `Disabled` for A, Phylum reports `quarantined` and `reuse::calibrate::reusable` returns `FROB-REF-162` for A; a different kind B keeps serving.
- `quarantine_survives_restart`: reopen the ledger; kind A is still quarantined.
- `quarantine_lift_requires_matching_rerun`: `Memo::reenable` for kind A after a restart alone, without an explanation record, or with one whose re-run still mismatches, is rejected; with a re-run matching twice it is accepted, one `memo-reenable` record is in the ledger and A serves again.
- `derived_key_declared_inputs` (per kind): each declared input perturbed → key changes.
- `live_dependency` (per kind): each read field perturbed → key changes or output bytes unchanged.
- `episode_shadow_same_backend_only`: an episode recorded on another fingerprint is neither served nor used as a shadow reference.

### End-to-end script and logging

`scripts/e2e/phylum_reuse_calibration.sh` sources the helper of `STD-E2E`; log
`target/e2e-logs/phylum_reuse_calibration/<utc>.ndjson`. Steps: populate analyses and short `batch-cpu` episodes for
a fixture design (`frob design check`, `frob sim run`; `sim.run` is a run verb, so every call of it carries its own
key, `--key rcal-<run>-<i>`, `<run>` naming this invocation, and must show `idempotent_replay: false`, since a
replayed envelope is returned without touching the memo graph and would count no hit); repeat the calls and log
hits and shadowed hits (`metric`
events with counts and the expected rate, which for a check repeated 64 times is exactly one shadowed hit per
node); run with the test feature that alters one cached analysis node, repeat `frob design check` on it until a
shadow fires (at most 64 repeats; the step fails if none fires), and assert that the next call recomputes
(`memo.served` false) and that `frob store status --json` shows the kind latched with the mismatch record id; start
a fresh process and assert the latch is still shown. The refusal and the lift are asserted in-process by
`cargo test -p frob-phylum -- shadow_mismatch_quarantines_kind quarantine_lift_requires_matching_rerun`, run by
the script and logged as one `assert` event per test, because
`phylum.reuse` (N17b-14) depends on this bead and `Memo::reenable` has no command-line surface (N28b-38, OPEN,
fail-closed); the same refusal through the verb is a step of N17b-14's script. Every command is a `cmd` event with
exit code, wall time and the `evidence` block; digests compared are logged; on failure the first differing byte
offset and the node key are logged. The `summary` lists assertions; no gate is claimed here (the gate is recorded by
BD-286).

### Known answers and negative controls

- Known answer: the decision-reuse fixture. Two scenes whose decisions commit at ticks 2 and 4; a camera packet arrives at tick 1; four states (initial; a display label renamed; delivery delayed to tick 2; delivery delayed to tick 3). A correctly keyed graph evaluates 2, 0, 0, 1 scene pairs and recomputes the verdict 1, 0, 0, 1 times, and every verdict matches a fresh replay.
- Negative control (CX-158): the same fixture with delivery time omitted from the key keeps a stale promotion at the fourth state; the live-dependency test and the shadow sample must each catch it.
- Negative control: a second selector planted in `frob-phylum` (shadowing cross-design hits on its own rule) must make `shadow_uses_memo_selector` fail; a planted quarantine flag kept in `frob-phylum` apart from the memo graph's state must make `quarantine_survives_restart` or `shadow_mismatch_quarantines_kind` fail.
- Determinism lanes: selection and digests are exact (class D0) and identical across platforms; episode shadows are compared inside class D2 on one back end.

## Considerations

- A rate of 1 in 64 detects a kind-wide key defect quickly and a rare, input-specific one slowly; it is a trip-wire, not a proof. The property tests are the first line.
- The selector is settled in one place, N28b-38, and its choice is why the tests above are exact. The key alone ("low six bits of the key's hash", one reading of "chosen by key hash") would leave 63 of 64 nodes never shadowed however often they are reused; one ordinal per kind would starve one of two cross-design keys requested alternately; the per-node durable ordinal with a phase from the key bounds detection to 64 hits of the stale node and replays exactly from the ledger. Should the memo graph change its rule, this bead's tests follow it, because they compare against the selector and do not copy it.
- Quarantine of the episode kind makes every campaign recompute; that is the intended cost of a broken invariant.
- The ceiling of the benefit is small by the plan's own arithmetic (exact reuse after a dynamics-affecting edit is at most about a tenth of compute), so nothing here is tuned for speed.
- Cited evidence is pinned in the ledger and does not depend on the cache: deleting the memo store loses no result a claim cites.
