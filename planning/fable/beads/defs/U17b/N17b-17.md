## Background

A population dispatch returns a map, not a winner. Phylum's quality-diversity map is a MAP-Elites grid, or a
centroidal tessellation, over behaviour descriptors such as mass, speed, energy per metre and footprint; each cell
holds the best design seen with that behaviour (its *elite*), and the map as a whole shows an agent many different
good designs instead of one optimum. This bead builds the map as a data type in crate `frob-phylum` with one
property above all: maps from two cards or two agents combine in any order.

The merge rule (from the chapter): a cell keeps the maximum under a total order (score, then `DesignId`), so merging
maps is commutative, associative and idempotent (PO-PHYLUM-03). The reason the order must be total is a FACT about
the suite's archive crate (`frankensim/crates/fs-archive/src/lib.rs`, to be re-read at the pinned revision): its
`MapElites::add` replaces an elite only on strict improvement, so on equal fitness the first arrival stays, and the
result depends on who synchronized first. The same file shows two further limits: `add` asserts a non-negative,
finite fitness, and an elite's solution is a vector of floats, not a design identity. Phylum therefore keeps its own
cell store and uses that crate only to cross-check cell geometry.

The second property is honesty about what a map means. A population scored under one shared policy drifts toward
designs that policy steers easily. The map therefore reports descriptor coverage beside quality, and elites stay
`provisional` until the rank-agreement record permits selection in their stratum.

## Scope

In: `MapSpec`, entries, cells, the map, cell assignment for grids and centroidal tessellations, the total order,
merge, canonical serialization, the delta between two maps, coverage and quality summaries, strata and the
selection standing read from the rank-agreement ledger.
Out: storing maps per campaign and the two read verbs (N17b-18); updating a map from a sweep and the gate
(BD-342); the optimizer that draws parents from a map.

## Technical approach

**Types (DESIGN).**

```rust
pub struct MapSpec {                    // content-hashed: MapSpecId
    pub descriptors: Vec<DescriptorDef>,   // name, unit, source metric, quantization step, lo, hi
    pub tessellation: Tessellation,        // Grid { bins: Vec<u16> } | Centroidal { centroids: Vec<Vec<i64>> }
    pub score: MetricRef,                  // higher is better
    pub task: TaskId,
    pub strata: StrataDef,                 // a partition of cells into blocks
}
pub struct Entry {                      // one evaluated design
    pub design: DesignId, pub eval: EvalId,     // EvalId: the identity of the dispatch that scored it
    pub descriptor: Vec<i64>, pub score: i64,   // quantized integers, in units of each quantization step
    pub standing: Standing,                     // always Provisional when written by a sweep
}
pub struct Cell { pub elite: Entry, pub members: BTreeSet<(DesignId, EvalId)> }   // count = members.len()
pub struct QdMap { pub spec: MapSpecId, pub cells: BTreeMap<CellIndex, Cell>, pub clamped: u64 }
```

**Cell assignment is exact.** Descriptor values and scores are quantized once to integers in units of the declared
step (for example 1 g, 1 mm/s, 0.01 J/m), by round-half-even, before any comparison. Grid: bin index
⌊(d − lo)/width⌋ in integer arithmetic, clamped into [0, bins − 1]; clamped entries are counted in `clamped` so
that out-of-range behaviour is visible. Centroidal: the nearest centroid by squared Euclidean distance in step
units, in integer arithmetic, ties to the lowest centroid index. No floating-point comparison decides a cell.

**The total order.** Entries compare by the tuple (score, `DesignId` bytes, `EvalId` bytes), lexicographically; a
cell's elite is the maximum. Scores are integers, so there is no NaN and no signed zero to order.

**Merge (numbered).** `merge(A, B)`: 1. require `A.spec == B.spec`, else refuse (an argument refusal carrying both
identities; two maps over different descriptors or bins have no common cells). 2. For each cell index present in
either map: `members` is the union of the two member sets and `elite` is the maximum of the two elites under the
total order. 3. `clamped` is recomputed from the union of clamped members. The result is commutative, associative
and idempotent because set union and maximum under a total order each are, cell by cell (PO-PHYLUM-03). A count per
cell is the size of a set, never a sum of counters, which is what keeps `merge(A, A) = A`.

**Canonical bytes.** A map serializes as canonical JSON (schema `frob.phylum.map/1`): cells in ascending index
order, members in ascending order, integers as integers. Equal maps have equal bytes, so `merge(A, B)` and
`merge(B, A)` are byte-identical and a map has a content address (`MapId`).

**Delta.** `delta(before, after)` lists the cells whose elite or member count changed, with the old elite (if
any), the new elite and the count, plus the summaries below for `after`.

**Summaries.** Coverage of descriptor space = filled cells / total cells; quality = the sum of elite scores;
per-stratum coverage; `clamped`. Coverage is always printed beside quality.

**Strata and standing.** `StrataDef` partitions cells into blocks; the same blocks key the rank-agreement ledger.
Each elite carries `standing: provisional` and, per stratum, a `selection` value read from the ledger for the
(morphology class, task family, rung pair, stratum): `select` when the lower interval bound of top-weighted rank
agreement is at least 0.7 and top-10 recall at least 0.8; `discard-only` between 0.5 and 0.7; `not-ranked` below
0.5; `unmeasured` when no row exists, which is treated as not permitted. The map never promotes an elite.

**Layout.** `crates/frob-phylum/src/map/{spec.rs, cell.rs, merge.rs, canon.rs, delta.rs}`.

## Acceptance criteria

- [ ] The types exist with the schema `frob.phylum.map/1` and a round trip through canonical JSON is byte-stable.
- [ ] PO-PHYLUM-03 holds as property tests over random maps: merge is commutative, associative and idempotent, with byte equality of the canonical forms.
- [ ] On equal score the elite is decided by `DesignId` and not by insertion order, for every insertion permutation of a test set.
- [ ] Cell assignment is identical on Linux and macOS and in debug and release for 10⁶ random descriptors, for both tessellations.
- [ ] Merging maps of different specifications is refused, never coerced.
- [ ] Delta, coverage, quality and `clamped` are correct on the fixtures below.
- [ ] Elites written by a sweep are `provisional`; the `selection` value follows the ledger thresholds and is `unmeasured` without a row.
- [ ] Where the suite's archive crate is admitted, grid cell indices agree with its `cell_of` on 10⁵ in-range descriptors that are not within one quantization step of a bin edge.
- [ ] `CONTRACT.md` records the two-line proof of PO-PHYLUM-03 and the reason for the total order.

## Test plan

### Unit tests (`cargo test -p frob-phylum map`)

- `merge_commutative`, `merge_associative`, `merge_idempotent`: property tests over random maps of up to 200 entries in a 5 × 5 grid; compare canonical bytes.
- `tie_broken_by_design_id`: entries (score 7, design `d:aa…`) and (score 7, design `d:bb…`) in one cell; every insertion order and every merge order yields the elite `d:bb…`.
- `count_is_set_cardinality`: merging a map with itself leaves every count unchanged; merging two maps sharing three members in a cell counts them once.
- `grid_cell_exact`: lo 0, hi 10 kg, 10 bins, step 1 g: 999 g → bin 0; 1,000 g → bin 1; 10,000 g → bin 9 (clamped, `clamped` incremented); −5 g → bin 0 (clamped).
- `cvt_tie_lowest_index`: a descriptor equidistant from centroids 2 and 5 goes to 2.
- `quantize_half_even`: 0.5 step → 0; 1.5 → 2; 2.5 → 2.
- `delta_lists_changed_cells`: adding one better entry and one entry in a new cell reports exactly two cells.
- `spec_mismatch_refused`: maps with 10 and 12 bins on one axis → refusal naming both `MapSpecId`s.
- `selection_from_ledger`: bounds (0.72, 0.85) → `select`; (0.6, any) → `discard-only`; (0.4, any) → `not-ranked`; no row → `unmeasured`.
- `canonical_bytes_stable`: serialize, parse, serialize: identical bytes; the `MapId` of a fixture equals a committed value.

### Known answers and negative controls

- KA-386: merge of quality-diversity maps, each cell keeping the maximum under the total order (score, then `DesignId`), is commutative, associative and idempotent (exact).
- Negative controls: an arrival-order rule (replace only on strict improvement) must fail `tie_broken_by_design_id` under a permuted insertion; a per-cell integer counter in place of the member set must fail `count_is_set_cardinality`; a floating-point bin computation must be caught by the cross-platform cell test on edge values or, failing that, by a planted edge fixture (a descriptor of exactly 1,000 g).
- Determinism lanes: all operations are integer and exact (class D0): twice on one machine, both platforms, debug and release.

## Considerations

- Descriptors computed from device runs are floats under a per-back-end determinism class; quantization makes cell assignment stable inside a class, and a descriptor within half a step of a boundary can still land in different cells on different back ends. Maps from different device families are therefore merged with that caveat printed, and the entry keeps its evaluation identity so the origin is traceable.
- The member sets grow with every dispatch. At a million evaluated designs a map holds about 64 MB of identities; a campaign's map is content-addressed and old versions are collectable.
- The quantization steps and bin counts are part of the specification's identity: changing them makes a new map, never a rebinned old one.
- The same design scored by two dispatches appears twice in a cell's members by design: the map records evaluations, and the maximum over them inherits the bias the chapter warns about, which is why elites stay provisional.
