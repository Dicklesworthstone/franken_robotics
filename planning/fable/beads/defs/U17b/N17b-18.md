## Background

The quality-diversity map (type in bead N17b-17) is what a population dispatch returns in place of a winner: per
behaviour cell the best design seen, with a provisional score, a count and the coverage of descriptor space. Agents
reach it through two read verbs, registered in two clusters for two uses:

- `phylum.map` (cluster `phylum`, read, first milestone M4): the quality-diversity map of a campaign or of one
  dispatch; merge of maps.
- `opt.archive` (cluster `opt`, read, first milestone M4): the quality-diversity archive of a campaign, the view
  the optimization chapter gives an agent ("a map of different good designs instead of one optimum"); the campaign
  optimizer draws its parents from the same object.

There is one stored object and two surfaces, never two archives: the plan's rule is that no mechanism has a second
spelling. Merging matters because several agents, or the two cards of one machine, work on one campaign: lineages
and archives from several agents merge as grow-only sets of versions and per-cell maxima under a total order
(score, then `DesignId`), so the result does not depend on who synchronized first.

## Scope

In: the two verbs with schemas, pagination and evidence, reading from the map store; the merge surface; the
end-to-end script of the map capability.
Out: the map type and its laws (N17b-17); the map store (content-addressed map artifacts, dispatch records and the
campaign head) and producing a map from a sweep (N17b-29, the first writer, on which this bead depends); the gate on
rounds (BD-342); the optimizer and racing (BD-341); lineage merge (its own bead).

## Technical approach

**Storage (read side; the store is N17b-29's).** A map is an immutable artifact addressed by `MapId` (the hash of
its canonical bytes) in the ledger. Each dispatch that produces a map records `(dispatch id → MapId)`. A campaign's
map is *defined* as the merge of the maps of all its dispatches; because merge is commutative, associative and
idempotent, the campaign map is a pure function of the set of dispatches, and the ledger keeps a `campaign → MapId`
head that is advanced by merging and can always be rebuilt from the dispatch records. Nothing is ever removed from a
map. These verbs read the head and the artifacts and never advance a head; the merge verb writes only a new
content-addressed artifact through the same store.

**`phylum.map` (kind read).** Input (`frob.phylum.map.in/1`): one of `{ campaign }`, `{ dispatch }`, `{ map }`
(a `MapId`), or `{ merge: [refs…] }`; optional `cells` filter (a stratum, an index range), `top` (elites per
stratum), pagination. Output (`frob.phylum.map.out/1`):

```json
{ "map": "map:…", "spec": {"descriptors": ["mass", "speed", "energy_per_metre", "footprint"],
                           "tessellation": "grid", "bins": [10, 10, 10, 5], "task": "stairs-0.15"},
  "coverage": {"filled": 412, "total": 5000, "share": 0.0824, "clamped": 3},
  "quality": {"sum_elite_score": "…", "unit": "task score"},
  "cells": [ {"index": [3, 7, 2, 1], "count": 9,
              "elite": {"design": "d:…", "score": "0.61", "standing": "provisional", "eval": "e:…"},
              "stratum": "s:12", "selection": "unmeasured"} ],
  "strata": [ {"id": "s:12", "filled": 40, "total": 250, "selection": "unmeasured"} ],
  "sources": {"dispatches": 14, "agents": 2} }
```

With `merge`, the verb computes the merge of the referenced maps, writes the merged map as a content-addressed
artifact (idempotent: the same inputs give the same address) and returns it. It does not move any campaign's head:
as a read verb it changes no named object. A merge of maps with different specifications is refused with the
argument refusal `FROB-REF-802` (exit 3, `retry: after-change`), `pointer` = the first `merge[i]` whose
specification differs, `observed` = its `MapSpecId` and the differing specification fields (descriptor, unit,
quantization step, bins, task, strata), `required` = the `MapSpecId` of `merge[0]`. DESIGN: the plan names no
chapter code for this case; it is a constraint between the call's own arguments, fixed by changing the call, which
is what the surface's argument refusal means, so no new code is minted. Scores are printed with the quantization of the
specification. A long cell list is paginated against a committed frontier and says so.

**`opt.archive` (kind read).** Input: `{ campaign }`, optional `top`, `stratum`. Output
(`frob.opt.archive.out/1`): the campaign map's elites in a form meant for choosing what to do next: per elite its
cell, descriptors with units, provisional score, selection standing, lineage link (the edit path from the campaign's
root design), and the generation it entered; plus the same coverage and quality summaries. It contains no number
that `phylum.map` on the same campaign does not; a test compares the two.

**Evidence.** Both verbs return `evidence = { class: "Tested", tier: <the weakest tier among the entries>,
determinism: <the weakest class among them>, standing: "provisional" }`. An elite is never shown as established by
these verbs; promotion is another chapter's verb.

**Bias statement in the envelope.** Each answer carries a `warnings` entry when the map's entries were scored under
one shared policy: coverage is printed beside quality, and elites stay provisional until the rank-agreement record
permits selection in their stratum.

**Examples.**

```text
frob phylum map --campaign stairs-q3 --top 3 --json
frob phylum map --merge map:9f2c… map:41aa… --json     # the merged map's address; order of arguments is irrelevant
frob opt archive --campaign stairs-q3 --stratum s:12 --json        # a single-kind read verb: no action word
```

**Layout.** `crates/frob-phylum/src/map/verb.rs` (the store, `map/store.rs`, is N17b-29's); the `opt.archive`
executor in `frob-opt` calls the same store.

## Acceptance criteria

- [ ] Both verbs exist through the generated surface with their schemas; each call writes exactly one envelope.
- [ ] A campaign's map read through `phylum.map` equals the merge of its dispatch maps read one by one through the same verb, and is answered identically after the head is rebuilt from the dispatch records.
- [ ] `phylum.map --merge A B` and `--merge B A` return the same `MapId` and byte-identical artifacts; merging a map with itself returns the same `MapId`.
- [ ] `opt.archive` and `phylum.map` on one campaign agree on every elite, count, coverage and quality figure.
- [ ] A merge across specifications is refused; nothing is coerced or rebinned.
- [ ] No answer shows an elite as other than `provisional`; `selection` is present for every stratum.
- [ ] Pagination covers every cell exactly once at a fixed frontier.
- [ ] The same calls through MCP (`phylum_map`, `opt_archive`) return the same envelopes.

## Test plan

### Unit tests (`cargo test -p frob-phylum map::store map::verb`)

- `campaign_map_is_merge_of_dispatches`: three dispatch maps recorded in two different orders give one campaign `MapId` through the verb, equal to `--merge` of the three dispatch maps.
- `answer_survives_head_rebuild`: delete the head and rebuild it with the store of N17b-29; the verb's answer is byte-identical before and after.
- `merge_verb_order_independent`: arguments (A, B, C) in all six orders → one `MapId`.
- `merge_verb_changes_no_head`: campaign heads before and after a merge call are equal.
- `archive_equals_map`: the set of (cell, elite, score, count) from `opt.archive` equals that from `phylum.map`.
- `spec_mismatch_refused_by_verb`: maps with 10 and 12 bins on one axis → `FROB-REF-802`, exit 3, `pointer` `merge[1]`, both specification identities in `observed` and `required`, and the differing field `bins` named; no artifact is written.
- `pagination_partition`: pages of 50 cells over 412 filled cells: 9 pages, no cell twice, none missing.
- `provisional_only`: a fixture map with a hand-written `established` elite is rejected at load.
- `other_namespace_needs_scope`: a session of agent A without the read scope of agent B's namespace asks for B's campaign map → the surface's scope refusal `FROB-REF-720`, exit 5, with no cell, count or identity of B's map in the envelope; with the scope granted the same call answers.

### End-to-end script and logging

`scripts/e2e/phylum_map.sh` sources the helper of `STD-E2E` and writes
`target/e2e-logs/phylum_map/<utc>.ndjson` with a transcript. Steps: two agents (two namespaces) each run
`frob phylum sweep --designs @fixture:gen-a|gen-b --task flat-stand --worlds-per-design 8 --tier batch-cpu --seed
1|2 --campaign stairs-q3 --key map-<run>-<a|b> --json` (`phylum.sweep` is a `run` verb: each dispatch carries its
own key, `<run>` naming this invocation, a call without one is `FROB-REF-805`, and both envelopes must show
`idempotent_replay: false`, since a replayed dispatch would add no map to the campaign and the merge assertions
would hold vacuously); then `frob phylum map --dispatch <each> --json`,
`frob phylum map --merge <A> <B> --json`, `frob phylum map --merge <B> <A> --json`,
`frob phylum map --campaign stairs-q3 --json` and `frob opt archive --campaign stairs-q3 --json`. Asserts: the
two merge calls return one `MapId` and byte-identical artifacts (`frob artifact read` on both, digests logged); the
campaign map equals the merged map; `opt.archive` agrees with `phylum.map`; every elite is `provisional`. Then
`frob phylum map --merge <A> @fixture:map-12-bins --json` must exit 3 with `FROB-REF-802` naming `bins` (a
`refusal` event with the whole block), and `frob phylum map --campaign stairs-q3 --limit 50 --json` followed
through every `--cursor` (NJL-01's common properties of a paginated read) must list every filled cell exactly once (cell count and duplicates as `metric` events). Each
command is a `cmd` event with exit code, wall time and the `evidence` block; `metric` events give coverage, filled
cells and counts; on failure the first differing cell index and both elites are logged with the artifact paths.
The `summary` lists assertions; the gate on rounds is recorded by BD-342.

### Known answers and negative controls

- KA-386 through the surface: merging two agents' archives in both orders gives identical bytes.
- Negative controls: a store that appends dispatch maps in arrival order without merging by the total order must give two different heads for two arrival orders and fail the first test; a `merge` that advances a campaign head must fail `merge_verb_changes_no_head`; an `opt.archive` implementation with its own copy of the elites must drift from `phylum.map` under a planted extra dispatch and fail `archive_equals_map`.
- Determinism lanes: map artifacts are exact (class D0 given their entries); the script is run twice and the `MapId`s must match.

## Considerations

- Two agents merging maps over different tasks or descriptor definitions is the common mistake; the refusal names the differing specification fields so the agent can see why.
- Reading another agent's campaign map needs the capability scope for that namespace; without it the verb refuses with the surface's scope refusal and reveals nothing.
- Maps built from private scenes inherit the private mark; the envelope carries it and exported artifacts obey the licence join.
- If the gate on fewer serial rounds fails, both verbs remain as reporting surfaces with their claims unchanged, because neither verb asserts anything about rounds.
