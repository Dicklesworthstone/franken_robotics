## Background

Phylum's quality-diversity map (the type of N17b-17) holds, per cell, the best design seen with a given behaviour
(its *elite*). A population scored under one shared policy drifts toward designs that policy steers easily, so an
elite is a *provisional* result: the plan says that elites stay `provisional` until the rank-agreement record
permits selection in their stratum (§17.12, with the record of §16.9 or §28). The map type keeps every elite
`provisional` and partitions its cells into strata (`StrataDef`, the blocks that also key the rank-agreement
ledger). This bead adds the other half: for each stratum, a `selection` value that says what the record permits,
read from the rank-agreement ledger (N28b-22) and never more permissive than the mode the evaluation ladder has in
force for the same key (decision core DC-03's mode automaton, N28b-23). The map verbs (N17b-18), the sweep's map
delta (N17b-29) and the rounds gate (BD-342) print or use this value; the map never promotes an elite.

It was split from N17b-17 so that the map type, which uses nothing of the ladder, can be built before the ladder's
mode automaton exists.

## Scope

In: the `Selection` value and the function that computes it per stratum from the ledger row and the ladder mode;
the thresholds; the cap by mode; the reading at a pinned ledger frontier with the row version cited; its unit
tests and end-to-end script.
Out: the map type, `StrataDef` and the standing `provisional` (N17b-17); the ledger rows and their measures
(N28b-22); the mode automaton and its inputs (N28b-23); the definition of a stratum (N28c-27, OPEN-ATEL-2);
printing the value in envelopes (N17b-18, N17b-29); using it to choose candidates for confirmation (BD-342).

## Technical approach

**The value (DESIGN names).** `pub enum Selection { Select, DiscardOnly, NotRanked, Unmeasured }`, serialized
`select`, `discard-only`, `not-ranked`, `unmeasured`. `pub fn selection(spec: &MapSpec, stratum: StratumId,
key: LadderKey, frontier: LedgerFrontier) -> SelectionReading`, where `LadderKey` is (morphology class, task
family, rung pair, stratum) and `SelectionReading` carries the value, the ledger row version it read (or none) and
the mode it was capped by.

**From the ledger row.** The latest row version of the key at the pinned frontier (N28b-22's read rule: a replay at
the same frontier reads the same version):
1. no row, or a row whose τ is `insufficient` → `unmeasured`, which is treated as not permitted;
2. lower interval bound of top-weighted rank agreement at least 0.7 and top-10 recall at least 0.8 → `select`;
3. lower bound at least 0.5 (and the `select` condition not met) → `discard-only`;
4. lower bound below 0.5 → `not-ranked`.

**The cap by the ladder mode.** For a row of a rung pair the value is never more permissive than the mode
N28b-23's automaton has in force for the same key at the same frontier: a stratum whose mode is `discard-only`
reads at most `discard-only`, and one whose mode is `uninformative` (a lost planted winner, an invalid
calibration, an audit not passed, an unmeasured stratum) reads `not-ranked` whatever its τ and recall, unless rule 1
already gave `unmeasured`. A mode of `selective` leaves the value of the row. So the map and the ladder never give
two answers to whether a stratum may select. The order of permissiveness is `select` > `discard-only` >
`not-ranked` = `unmeasured` (both not permitted).

**What does not change.** Every elite stays `standing: provisional`; the value is reported per stratum beside the
elite and never changes the map's bytes, its `MapId` or a merge.

**Layout.** `crates/frob-phylum/src/map/selection.rs`; the example `crates/frob-phylum/examples/map_selection.rs`.

## Acceptance criteria

- [ ] `selection` returns the four values by the thresholds above and `unmeasured` without a row; its reading cites the row version and the mode.
- [ ] The value is never more permissive than the ladder's mode for the key; `uninformative` gives `not-ranked`.
- [ ] Two readings at the same ledger frontier are identical; a row appended after the frontier does not change the reading.
- [ ] Computing selections leaves every elite `provisional` and the map's canonical bytes and `MapId` unchanged.

## Test plan

### Unit tests (`cargo test -p frob-phylum map::selection`)

- `selection_from_ledger`: bounds (0.72, 0.85) → `select`; (0.6, any) → `discard-only`; (0.4, any) → `not-ranked`; no row → `unmeasured`; (0.72, 0.79) → `discard-only` (recall below 0.8).
- `selection_band_edges`: lower bound 0.70 with recall 0.80 → `select`; 0.6999 → `discard-only`; 0.50 → `discard-only`; 0.4999 → `not-ranked`.
- `selection_capped_by_mode`: bounds (0.72, 0.85) in a stratum whose ladder mode is `discard-only` → `discard-only`; the same bounds with mode `uninformative` (planted winner lost) → `not-ranked`; with mode `selective` → `select`.
- `selection_pinned_frontier`: a row version appended after the frontier is not read; the reading cites the version at the frontier.
- `selection_leaves_map_unchanged`: the `MapId` of a fixture map is the same before and after computing all its strata's selections; every elite is `provisional`.

### End-to-end script and logging

`scripts/e2e/phylum_map_selection.sh` sources the helper of `STD-E2E`; log
`target/e2e-logs/phylum_map_selection/<utc>.ndjson`. It runs `cargo test -p frob-phylum map::selection`, then
`cargo run -p frob-phylum --example map_selection -- --ledger <scratch dir> --map @fixture:qd-5x5-four-strata --json`,
which writes four keys into a scratch ledger (rows (0.72, 0.85), (0.6, 0.9), (0.4, 0.9) and none, with the
ladder modes produced by N28b-23's transition function from fixture inputs, one of them `uninformative` by a lost
planted winner) and prints the reading per stratum. `cmd` events carry the commands, exit codes and wall time;
`assert` events compare each stratum's value, row version and mode with the expected ones and the fixture map's
`MapId` before and after; the `summary` lists assertions and `gates: []`.

### Known answers and negative controls

- Known values: the threshold table above; `unmeasured` without a row; the cap table (`discard-only` caps `select`; `uninformative` gives `not-ranked`).
- Negative controls: a planted reading that ignores the mode must fail `selection_capped_by_mode`; a planted reading of the point estimate in place of the lower bound (point 0.74, lower bound 0.61) must give `select` and fail; a planted reading of the latest row rather than the row at the frontier must fail `selection_pinned_frontier`; a planted write of the value into the elite must change the `MapId` and fail `selection_leaves_map_unchanged`.
- Determinism lanes: integer and table logic over pinned ledger reads (class D0); twice on one machine, both platforms.

## Considerations

- The value is advisory to the map's readers and binding on BD-342's choice of candidates for confirmation: an elite in a stratum that does not read `select` is re-scored on the higher rung before confirmation.
- If the ladder's program-level kill switch (KILL-RANK) is set, every shared-policy rung is `uninformative` and every stratum reads `not-ranked`; the map keeps working as a reporting surface.
- The thresholds are those of §28.10 and §16.9; a change of threshold is a new ledger decision, not an edit here.
