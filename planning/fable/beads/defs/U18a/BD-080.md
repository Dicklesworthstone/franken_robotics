## Background

The **referee** is the most trusted tier: `f64`, exact Coulomb friction, certified collision queries, one to a few
dozen worlds. It adjudicates the fast tiers; it is not called ground truth. At M1 it is built from what FrankenSim
has at the pinned commit `483d09c682` (FACT, read 2026-11-21, each re-checked by an admission test before a gate
cites it): `fs-mbd` gives floating-base forward dynamics and a contact step
`articulated_contacts::step::step_articulated_frictional_contacts`, first-order kick-contact-drift, which **takes
the contact set from the caller** and states that "independent endpoint gap checks are not continuous collision
detection". A 29-DoF G1 rollout at 480 Hz with Hunt–Crossley feet and `fs-tribo` friction already runs in
FrankenSim. So the M1 referee is: FrankenSim's articulated dynamics and contact solve, plus contact sets that
`frob-contact` generates from `fs-query` convex separation and signed-distance queries, plus (in BD-081/BD-082) the
transaction around them, plus an audit with certified continuous collision detection on sampled windows.

This bead is the first of those joins: one referee physics step with contact, before the transaction exists.

Limits of the sibling that bind this bead (each has an upstream work item and an interim posture):

| Limit | Posture here |
|---|---|
| At most 21 contacts in one solve (`fs-contact/src/sustained/solve.rs`: `MAX_CONTACTS = 21`). One robot is one island because every foot couples through the floating body: eight samples per sole fit when standing (16) and overflow in a fall; a tracked robot overflows in normal driving | A named capacity refusal `FROB-REF-721`, never a truncated contact set (FD-FSIM-13) |
| No persistent contact time stepper; `solve_frictional_contacts` is an event solve | Time stepping, warm starts, friction memory and the commit fence are ours (FD-FSIM-02) |
| Fixed material witnesses and a fixed contact frame in the sustained step; tangentially separating witnesses are refused | Witnesses are migrated between calls (N18a-14, BD-093); if the sibling still refuses, the refusal is surfaced and the `strict` profile adjudicates (FD-FSIM-12) |
| Contact set supplied by the caller; endpoint gap checks only | `frob-contact` generates sets; `fs-contact::certified_ccd` audits the path (FD-FSIM-03) |
| Joint classes limited to fixed, revolute, prismatic, helical | Others are lowered to products of one-axis joints (FD-FSIM-01) |
| Platform `sqrt`, `sin`, `cos` | The referee claims same-platform determinism only (FD-FSIM-07) |

Why removing contacts to fit the cap is forbidden (ADR-TRAC-08): it biases exactly the comparison a design studio
exists to make, because a tracked robot's set overflows where a point-foot robot's does not.

## Scope

In: the `RefereeContact` adapter in `frob-fsim` and its use from `frob-dyn`; per-step contact-set generation by
`frob-contact`; compliant feet; the capacity check at model compile and at run time; the surfaced sibling refusals;
the sampled certified-CCD audit count; stand and drop fixtures.

Out: the restore set and commit fence (BD-081); event location and coupled impulses (BD-082); witness migration in
the transaction (BD-093, algorithm in N18a-14); the known-answer battery (BD-085); joint stiction and backlash rows
(BD-084); the written law the referee is checked against (N18a-21).

## Technical approach

**Adapter rules (binding).** `frob-fsim` is the only crate that names FrankenSim's volatile types. The adapter (1)
converts and never reinterprets: a FrankenSim refusal becomes a typed referee refusal carrying the upstream reason
and is never retried with weakened inputs; (2) does not cache across pins: every memoized referee result carries the
stack-lock digest in its key; (3) exposes capacities as data: the 21-contact limit is a field of `RefereeContact`.

```rust
// DESIGN: names fix intent, not signatures.
pub trait RefereeContact {
    fn max_contacts(&self) -> usize;                       // 21 at the pin; read from the sibling constant
    fn step(&mut self, state: &mut RefereeState, set: &ContactSet, h: Seconds)
        -> Result<StepReport, RefereeRefusal>;             // RefereeRefusal carries the upstream reason
}
pub struct ContactSet { contacts: Vec<Contact> }           // from frob-contact, order is canonical
pub struct Contact { pair: (BodyId, BodyId), witness: (Point3, Point3), // body coordinates
                     frame: ContactFrame, gap: Metres, eps_g: Metres, material_pair: InterfaceId }
```

**One referee step (this bead; the transaction wraps it later).**
1. Forward kinematics of the model at the committed state (through `RefereeDynamics`, BD-007).
2. `frob-contact` generates the candidate set: primitive against primitive by `fs-query` certified convex
   separation; primitive samples against static geometry by signed-distance queries (N18a-10); the self-collision
   filter removes excluded pairs (N18a-11). Each contact carries its gap error bound ε_g (N18a-02).
3. Canonical order: contacts are sorted by (body pair, primitive index, sample index), so a replay gives the same
   set in the same order.
4. Capacity: if the island's count exceeds `max_contacts()`, return `FROB-REF-721` (referee capacity; exit code
   5) with the count, the cap and the ranked repairs "patch reduction with its qualification fixture" and
   "`--profile strict`". Nothing is solved on a truncated set.
5. Call the sibling step with the set and h. A sibling refusal (fixed-witness gate, indeterminate solve) is
   converted with its reason; the fixed-witness refusal also maps to `FROB-REF-721`.
6. Sampled audit: on windows chosen by an address-keyed stream (DESIGN default 1 window in 64), run
   `fs-contact::certified_ccd` over the step's swept poses and count contacts that the endpoint set missed; the
   count is reported per run and is never used to alter the trajectory.

**Capacity is checked twice.** At model compile, from the static maximum of simultaneously active samples (a design
whose standing pose already exceeds the cap is reported before any rollout); and at run time in step 4.

**Compliant feet.** At M1 foot contact uses FrankenSim's Hunt–Crossley normal law with `fs-tribo` friction, the
combination the sibling's G1 rollout already exercises. Foot parameters (stiffness, dissipation, friction) are
physical parameters read from the interface card of the foot and floor materials; a step-size change never alters
them (ADR-KIN-05).

**Identity and evidence.** Results carry tier `referee`, profile `referee`, the model identity, the stack-lock
digest and determinism class D2 on one platform. The evidence class is the one FrankenSim's contracts give the
solve; Reality stays `no-claim`.

## Acceptance criteria

- [ ] Stand: the reference quadruped (16 foot samples) stands on a plane for 2 s of simulated time; after 0.5 s of settling the base height drifts by less than 1 mm and no contact is added or lost (TARGET).
- [ ] Drop: a rigid box released from 0.5 m lands at the step that brackets √(2·z₀/g) = 0.3193 s and total mechanical energy never increases afterwards.
- [ ] A contact set of 22 contacts returns `FROB-REF-721` with count 22 and cap 21, exit code 5; no solve ran (the seed done-condition: a typed refusal, never a truncated solve).
- [ ] The truncation mutant (keep the first 21 contacts) is caught by a test.
- [ ] The static capacity check flags a design whose rest pose needs more than 21 contacts at model compile.
- [ ] A sibling fixed-witness refusal reaches the caller as a typed refusal with the upstream reason.
- [ ] The run is reachable as `frob sim run --tier referee --json`, the envelope carries the evidence block, and cancellation between steps leaves no partial state.
- [ ] `crates/frob-contact/CONTRACT.md` and `crates/frob-fsim/CONTRACT.md` list the limits table above under "known gaps".

## Test plan

### Unit tests
- `referee_stand_quadruped`: 1,000 steps at h = 2 ms; asserts drift < 1 mm and a constant active set after settling.
- `referee_drop_box_energy_monotone`: asserts the impact step index is ⌈0.3193/h⌉ or its neighbour and E(k+1) ≤ E(k) + 10⁻⁹ J for every post-impact step.
- `referee_capacity_22_refuses`: a `synthetic` body with 22 sample spheres resting on a plane; asserts `FROB-REF-721`, the fields `observed = 22`, `required = 21`, and that the sibling solve was not called.
- `referee_no_truncation_mutant`: a feature-gated mutant that truncates the set must fail `referee_capacity_22_refuses`.
- `referee_contact_order_canonical`: the same state with bodies inserted in two orders gives byte-identical `ContactSet`.
- `referee_refusal_passthrough`: a wheel poised on a riser edge (the sibling's fixed-witness gate) returns a typed refusal whose `upstream_reason` is non-empty.
- `referee_capacity_field_matches_sibling`: `max_contacts()` equals the sibling constant at the pinned commit (fails loudly if the sibling changes it).

### End-to-end script and logging
Covered by `scripts/e2e/traction_referee.sh` (bead N18a-35), steps `stand`, `drop`, `capacity_refusal`. Each step
logs per STD-E2E: the `frob sim run --tier referee` command line, exit code, wall time, the evidence block (tier
`referee`, determinism, model identity, seed), the metrics `base_drift_mm`, `impact_time_s`, `energy_max_increase_j`,
`contacts_max`, `missed_contacts_audit` with their thresholds, the run digest, and on failure the first offending
step and the path of the `.frun` episode.

### Known answers and negative controls
KA-392 (a dropped body under an inelastic law never gains mechanical energy; exact in sign). Capacity fixture: 22
contacts refuse (admission test INT-FSIM-04 at the pin). Negative controls: the truncation mutant; an endpoint-only
tunnelling case is counted by the sampled audit (a thin plate between two clear endpoint poses must raise
`missed_contacts_audit` above zero). Determinism lanes: twice on one machine (equal digests); debug and release;
no cross-platform bit claim on the referee.

## Considerations

- RISK-31: the referee cannot complete the scenes where decisions are made (cap 21, fixed witnesses). The share of scenarios it completes is a reported figure with its own gate (GATE-FID-03), and the `strict` profile (BD-161) is the named adjudicator where it cannot.
- The sibling's API moves; the adapter isolates the change to one crate, and KILL-FSIM's fallbacks (a pinned worker process, then a minimal lift) stay written down.
- Switch-over: when FD-FSIM-13 lands, re-run the capacity fixtures; when FD-FSIM-12 or FD-FSIM-02 land, re-baseline the fidelity ledger once.
- Performance is not a goal here; the referee runs one world per core at below real time.
