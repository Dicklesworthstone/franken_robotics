## Background

On GPU tiers static geometry is a distance field and thin features are analytic thin primitives. A thin feature
that fits no primitive (a curved thin shell, a perforated cover) has only a triangle-patch route, which at M3
exists on CPU tiers alone. This epic would bring a bounding-volume hierarchy traversal into the batched device
step so those scenes can run on GPUs. It is Frontier, it is a coverage feature with no speed ceiling to claim, and
it exists only on the branch of KILL-MESHGPU where the gate did not fire at M3 (N18a-05). The milestone text keeps
"the mesh path on devices" among the M6 epics only where its M3 pilot kept it.

## Scope

In (as children): a short plan; a device re-measurement of the pilot's two quantities on CUDA and on Metal; the
traversal kernel in the shared dialect; the admission change; the CPU-versus-device differential check; the kill
decision if the device measurement fails. Out: the CPU hierarchy (BD-232); thin primitives (BD-166).

## Technical approach

1. **Short plan** before any work: scope, the device pilot with its falsifier, ceiling (none on speed), kill rule,
   acceptance story.
2. **Device re-measurement.** The fixed stack depth D and visit budget V chosen by the M3 pilot are run on one
   CUDA device and on Metal over the thin-feature corpus. Falsifier (the trigger of KILL-MESHGPU): traversal breaks
   the fixed launch shape, or adds more than 15% to the step. If it fires, the gate is recorded as fired at M6 and
   the fallback applies: GPUs see thin geometry as analytic primitives only; meshes stay on CPU tiers.
3. **Kernel.** One narrow-phase kernel beside `K-np-sdf` and `K-np-thin`, class `float`, with literal loop bounds
   (D, V), a fixed-size stack per candidate, selects instead of cross-world branches, and an overflow flag that
   marks the world `Degraded` (never a silent truncation). The hierarchy arrays are pack-owned device buffers
   addressed by digest; movers refit under explicit epochs, and the kernel reads a named epoch.
4. **Admission.** Once the gate record exists, a pack whose thin feature has a `mesh-cpu` route is admitted on the
   GPU tier; before it, admission returns `FROB-REF-320`.
5. **Determinism.** The traversal order is fixed by the tree, so results are class D2 per backend; a comparison
   against `batch-cpu` uses the class each backend claims.

## Acceptance criteria

- [ ] A short plan exists and the device re-measurement has run, with numbers recorded against the 15% bound and the shape criterion.
- [ ] Either the kernel passes its differential check against the CPU hierarchy on the corpus (same contacts, gaps inside the declared bound) on both device families, or the epic is closed with KILL-MESHGPU recorded as fired and the fallback in force.
- [ ] Forced visit-budget overflow flags the world `Degraded`; no contact is dropped silently.
- [ ] The step plan identity includes D and V; changing either changes the identity.
- [ ] A thin barrier that fits no primitive, lying between two clear endpoint poses, is detected on the device tier within the speculative margin's guarantee.

## Test plan

### Unit tests
Carried by the children: traversal kernel against the CPU query on 10⁵ candidates; overflow flag; epoch check;
static-shape resource metadata.

### End-to-end script and logging
`scripts/e2e/mesh_hierarchy_gpu.sh` (written by the kernel child): compiles a scene with a mesh-only thin feature,
runs it on `batch-cpu` and on each device, and compares contact sets. Logged per STD-E2E: commands, exit codes,
evidence block with tier and fingerprint, `stage_overhead_ratio` against 1.15, `overflow_rate` against 0, the
divergence ledger entry on any mismatch, and a summary with the gate's state.

### Known answers and negative controls
The thin-barrier case (both endpoints clear, a collision enclosed) on a mesh-only feature. Negative controls: a
traversal with an early exit that changes the launch shape (rejected by the kernel lint); a stale hierarchy epoch
(rejected by the query).

## Considerations

- Metal's per-function argument limits and synchronous batches constrain how the hierarchy buffers are bound; the device re-measurement must include them.
- If funded late or not at all, nothing on the critical path changes: scenes with mesh-only thin features keep running on CPU tiers.
- OPEN-PROG-5: the funding order of M6 epics is an owner decision.
