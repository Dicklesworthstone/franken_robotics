## Background

The referee and the `strict` profile advance each world by one transaction per accepted physics interval, cut into
sub-intervals at located events. In each sub-interval (a, b) the transaction's detection step asks Traction two
things: a **broad phase on bounds swept over the sub-interval**, and a **narrow phase at a** that returns, per
candidate pair, the features, the normal, the witnesses, the material pair, the signed gap g and its error bound
ε_g. From these the transaction finds the earliest time at which a guard may change sign (touchdown, lift-off,
stick to slip) by conservative advancement on gap divided by a bounded approach speed, then bisection.

Why swept bounds and not endpoint tests: a pair discarded in the broad phase never reaches the narrow phase, so a
bound that does not enclose the motion is a missed contact with no later chance of detection (the thin-barrier
counterexample: both endpoints clear, a collision enclosed). This bead defines the record and the interface; the
geometry of a bound that encloses the arc of a rotating link is the swept-arc bead of the other Traction unit.

## Scope

In: the `NarrowHit` record; the swept broad-phase interface and its contract; the quantities conservative
advancement needs; the path-admission check used when a transaction's checks run. Out: the transaction and event
location (BD-081, BD-082); the swept-arc construction; witness migration (N18a-14); the batched kernels (BD-158,
BD-166).

## Technical approach

```rust
// DESIGN: names fix intent.
pub struct NarrowHit {
    pub pair: (PrimitiveId, PrimitiveId),      // or (sample, scene region)
    pub features: (FeatureId, FeatureId),      // face, edge, vertex, cap, side; field region for static geometry
    pub normal: UnitVector<World>,             // from the second party to the first
    pub witnesses: (Point3<BodyA>, Point3<BodyB>),   // one point on each body, in body coordinates
    pub material_pair: InterfaceId,            // selects the interface card (materials and condition)
    pub gap: Gap,                              // signed gap g with its bound eps_g
}
pub trait SweptDetect {
    /// Candidates whose swept bounds over [a, b] overlap. Never misses a pair that touches inside [a, b].
    fn broad_swept(&self, state_a: &State, motion: &MotionBound, a: Rational, b: Rational) -> Vec<Candidate>;
    /// Narrow phase at time a for the given candidates, in canonical order.
    fn narrow_at(&self, state_a: &State, cands: &[Candidate]) -> Vec<NarrowHit>;
    /// An upper bound on the closing speed of a candidate over [a, b].
    fn approach_speed_bound(&self, cand: &Candidate, motion: &MotionBound) -> MetresPerSecond;
}
```

**Contract of `broad_swept`.** For every pair of primitives (or sample and static geometry) whose true gap reaches
zero at some time in [a, b] under any motion consistent with `MotionBound`, the pair is returned. `MotionBound`
carries, per moving link, a bound on the path of each sample over the sub-interval (from joint-speed limits and
lever arms, or from the start speed plus the largest change the actuator and load limits allow). A model that
supplies no speed bound for a link is refused at admission by the swept-arc bead's refusal. Bounds are inflated
by ε_g. The output order is canonical (ascending pair identifiers).

**Conservative advancement (what the transaction does with the record).** With gap g, bound ε_g and closing-speed
bound s̄ > 0, no contact can occur before a + (g − ε_g)/s̄. The transaction advances to the smallest such time over
all candidates, re-queries, and switches to bisection on the dyadic grid once the remaining gap is within ε_g.
This bead guarantees the two inputs: g − ε_g never overestimates the true gap, and s̄ never underestimates the
closing speed.

**Path admission (the transaction's check before commit).** `path_admitted(interval, hits_committed) -> bool`:
re-runs `broad_swept` over the committed motion of each sub-interval and verifies that every returned candidate
either stayed separated by more than ε_g throughout (by the advancement bound) or is in the committed active set.
"No missed contact on the swept path, inside ε_g" is this predicate; a failure sends the transaction to its retry
ladder.

**Feature identifiers** are stable across calls for unchanged geometry (they index faces, edges and vertices of a
primitive, or a region and overlay of the scene), because witness migration classifies changes by comparing them.

Outputs are `f64`, deterministic on one platform (class D2); the candidate and hit order is a function of the
world only.

## Acceptance criteria

- [ ] `broad_swept` returns the plate candidate in the thin-barrier case (sphere radius 2 mm, 5 m/s, sub-interval 2 ms, 2 mm plate 1 mm ahead), where the endpoint-only bound does not.
- [ ] On 10⁵ random straight and rotating motions with a planted obstacle on the path, the obstacle is always among the candidates (rotating cases through the swept-arc construction).
- [ ] The advancement bound is safe: on 10⁵ random approaches the first true contact time is never earlier than a + (g − ε_g)/s̄.
- [ ] `narrow_at` returns all six fields for every primitive-type pair and for sample-against-field hits; feature identifiers are equal across two calls on unchanged geometry.
- [ ] `path_admitted` rejects a committed interval from which one enclosed contact was removed (planted).
- [ ] Candidate and hit order is canonical and independent of insertion order.

## Test plan

### Unit tests
- `swept_thin_barrier_candidate_present`; `endpoint_bound_mutant_misses_it`.
- `swept_random_obstacle_on_path`: straight and single-joint rotating sweeps.
- `advancement_bound_is_safe`: analytic sphere-against-plane approaches with known contact time t = g/v.
- `approach_speed_bound_dominates`: s̄ ≥ the true closing speed over the interval on random motions.
- `narrow_hit_fields_complete`: every pair type.
- `feature_ids_stable`.
- `path_admission_catches_missing_contact`.
- `hit_order_canonical`.

### End-to-end script and logging
Exercised by `scripts/e2e/traction_referee.sh` (bead N18a-35), steps `thin_barrier` and `sill`, which run the
transaction over this interface. Logged per STD-E2E for those steps: the number of swept candidates, the number of
advancement and bisection iterations, `missed_hits` (threshold 0), and the path-admission verdict per interval.

### Known answers and negative controls
KA-408 (thin barrier). Hand case: a sphere 10 mm above a plane approaching at 2 m/s with ε_g = 0 has no contact
before 5 ms; the bound returns 5 ms. Negative controls: the endpoint-only bound (CX-169); a speed bound taken from
the start-of-interval speed alone under acceleration (the safety test fails on an accelerating approach).
Determinism: twice on one machine; debug and release.

## Considerations

- Over-wide swept bounds cost candidates, not correctness; the candidate count per sub-interval is logged so the cost is visible.
- The record carries the material pair because friction belongs to an interface (a pair of surface materials and their condition), not to one material.
- The same record is what the lockstep narrow-phase kernels produce in packed form; keeping one definition lets a teleported world be re-run under `strict` from a batched snapshot.
