## Background

Unit tests show that pieces work; an end-to-end script shows that a user or an agent driving the real `frob`
binary gets the same answers, with the evidence attached, and that failures are reported in a form someone can
act on. This script covers the first user-visible Traction capability: contact stepping on the transactional
tiers. It drives `frob sim run --tier referee` (M1) and, with one parameter, `--tier batch-cpu --profile strict`
(M2, when BD-161 lands), on real fixtures, with no mocks. It is the script the referee rows of GATE-TRAC-01 and
GATE-TRAC-06 are recorded from.

A closed bead is not acceptance: the gate records cite this script's log, which carries measured values, the
commit, the hardware fingerprint and the seed.

## Scope

In: one script with the steps below, its structured log, its negative controls, its idempotence and seed handling.
Out: the fixtures and mechanisms themselves (their beads); batched-tier scripts (N18a-36).

## Technical approach

**Path and invocation.** `scripts/e2e/traction_referee.sh [--profile referee|strict] [--long]`. Plain shell; exits
non-zero on any failed assertion; idempotent (it writes only under `target/e2e-logs/traction_referee/` and a
scratch store it creates and removes); every random input is named by an explicit seed printed in the log.

**Steps (each a `step` value in the log).**
1. `laws`: `frob contact laws --json`; assert four laws with tiers; then `frob sim run --tier batch-cpu --law cl-h
   --json` and assert refusal `FROB-REF-246`, exit code 3 (skipped once the law is admitted).
2. `gap_budget`: `frob contact probe` on two states; assert the known true gap lies in [g − ε_g, g + ε_g] and the
   four budget terms are printed with units.
3. `samples` and `pairs`: `frob contact probe` on the standing quadruped; assert 16 active foot samples, the
   static maximum 24, and the planted-interference pair listed as tested.
4. `stand`: 2 s on a plane; assert base drift below 1 mm after settling.
5. `drop`: box from 0.5 m; assert the impact step brackets 0.3193 s and energy never increases.
6. `capacity_refusal`: 22 contacts; assert `FROB-REF-721`, exit code 5, `observed = 22`, `required = 21`.
7. `battery`: the referee battery; one assertion per known-answer row (incline threshold within 1% of μ, sphere
   acceleration within 0.5% of (5/7)·g·sin α, disk v = ω·r within 0.1%, drop energy, ring on a cone, Painlevé rod
   refused with `FROB-REF-224`), and one `refusal` event per row recorded as not expressible.
8. `clh_conformance`: maximum natural-map residual per row at most 10⁻⁶.
9. `thin_barrier`: 10⁴ seeded crossings by default, 10⁶ with `--long`; assert zero missed hits and the canonical
   touchdown at 0.2 ms within one dyadic cell.
10. `sill`: the wheel over a sharp sill at h, h/2, h/4; assert the feature sequence flat, edge, top, work and
    impulse within 1% of the h/4 values, no couple above 10⁻⁹ N·m, and every reset present as an event.
11. `negative_controls`: with the test-only mutant flags `endpoint-only`, `keep-memory`, `truncate-contacts`, the
    corresponding steps must **fail**; the script asserts the failure and records it as a passed control.

**Logging (the standard of the shared helper from STD-E2E).** The script sources the helper and writes
newline-delimited JSON to `target/e2e-logs/traction_referee/<utc-timestamp>.ndjson` and a human-readable
transcript beside it. Every line has `ts`, `script`, `bead`, `step`, `event` (`start`, `cmd`, `assert`, `metric`,
`refusal`, `end`), the exact command line, exit code, wall time, the envelope's `evidence` block (claim, class,
tier, profile, adjudicator, determinism, identities, seed), measured values with units and their thresholds,
digests where state is compared, and on failure the first differing value and the artifact paths needed to
reproduce (the `.frun` episode, the fixture file, the seed and index). A final `summary` line gives counts of
assertions passed and failed, controls caught, and the gates touched (GATE-TRAC-01 referee rows, GATE-TRAC-06
referee rows). Logs contain no private-scene data (fixtures only).

## Acceptance criteria

- [ ] The script exists, is executable, and passes on a clean checkout at M1 with `--profile referee`; with `--profile strict` once BD-161 lands.
- [ ] Every step emits `start`, at least one `cmd`, its `assert` events and `end`; the `summary` line's counts equal the number of assertions executed.
- [ ] Each of the three mutants makes its step fail and the script records the control as caught; with a mutant silently ineffective the script itself fails.
- [ ] Running the script twice gives identical run digests for every step (determinism lane: twice on one machine).
- [ ] The gate records for GATE-TRAC-01 and GATE-TRAC-06 (referee rows) cite a log file of this script by path and digest.
- [ ] Cancelling the script mid-run leaves no partial store and no orphaned job.

## Test plan

### Unit tests
- `e2e_log_schema_traction_referee`: a log produced by the script validates against the STD-E2E line schema (every required key present on every line).
- `e2e_script_idempotent`: two consecutive runs leave the working tree unchanged outside `target/`.
- `e2e_summary_counts_match`: the summary's pass and fail counts equal the counted `assert` events.

### End-to-end script and logging
This bead is the script; its own check is the self-test `scripts/e2e/traction_referee.sh --self-test`, which runs
steps 1, 5 and 6 only and validates the log schema.

### Known answers and negative controls
KA-387, KA-388, KA-389, KA-392, KA-395, KA-396 (battery); KA-408 (thin barrier); KA-409 (sill); the capacity
fixture of 22 contacts. Negative controls: the three mutants above (counterexamples CX-169, CX-183 and the
capacity-truncation rule). Determinism lanes: twice on one machine; debug and release builds of `frob`.

## Considerations

- The `--long` lane (10⁶ crossings) is run for gate records and nightly, not on every change.
- The script must not hide a refusal as a skip: a row that the referee refuses is logged as a `refusal` event with its code and reason.
- When the list of referee-expressible rows changes (an upstream item lands), the expected-refusal list in the script is updated in the same change as the gate record.
