## Background

Unit tests show that pieces work; an end-to-end script shows that a user or an agent driving the real `frob`
binary gets the same answers, with the evidence attached, and that failures are reported in a form someone can
act on. This script covers the first user-visible Traction capability: contact stepping on the transactional
tiers. It drives `frob sim run --tier referee` (M1) and, with one parameter, `--tier batch-cpu --profile strict`
(M2, when BD-161 lands), on real fixtures, with no mocks. It drives from the user's side the referee rows of
GATE-TRAC-01 and GATE-TRAC-06 and logs the receipts of their Gauntlet runs; it records no gate. The rows are
recorded by their one recorder each: GATE-TRAC-01's referee rows by BD-085, GATE-TRAC-06's thin-barrier rows by
BD-086 and its sill rows by N18b-38.

A closed bead is not acceptance: this script's log carries measured values, the commit, the hardware fingerprint
and the seed, and names each receipt hash beside its step, so a gate record and a user-side run can be matched.

## Scope

In: one script with the steps below, its structured log, its negative controls, its idempotence and seed handling.
Out: the fixtures and mechanisms themselves (their beads); batched-tier scripts (N18a-36).

## Technical approach

**Path and invocation.** `scripts/e2e/traction_referee.sh [--profile referee|strict] [--long]`. Plain shell; exits
non-zero on any failed assertion; idempotent (it writes only under `target/e2e-logs/traction_referee/` and a
scratch store it creates and removes); every random input is named by an explicit seed printed in the log.

**Steps (each a `step` value in the log).** Every `frob sim run` below passes `--key
traction-referee-<step>-<seed>` and `--json`: a run verb without an idempotency key is refused with
`FROB-REF-805`, exit 3 (N32a-09), so a step that omitted it would assert the wrong refusal.
1. `laws`: `frob contact laws --json`; assert the laws CL-1, CL-2, CL-H and CL-M with their tiers (a law added
   later, such as CL-1R at M4, is an extra row and does not fail the step), and every batched row whose admitting
   gate has no record `pending` or `not-built` (all of them at M1);
   then the admission check for (CL-H, `batch-cpu`, `lockstep`) through `FROB_TEST_SEED=<seed> cargo test -p
   frob-contact --test law_registry -- refuse_not_admitted` (N18b-28), asserting `FROB-REF-246` with its repairs
   in rank order. The command-line form `frob sim run … --law CL-H --tier batch-cpu` waits for the `batch-cpu`
   tier of `sim.run` (N16b-25, M2; `--law` itself is N18b-28's at M1, VERBS-sim) and is asserted by N18b-30, not
   here.
2. `gap_budget`: `frob contact probe --design <fixture> --gap-budget --scene <fixture scene> --pose <state>
   --json` (the model branch of N18b-29) at two stated poses; assert the known true gap lies in
   [g − ε_g, g + ε_g] and the five budget terms of N18a-02 (`field`, `fit_a`, `fit_b`, `routine`,
   `registration`) are printed in metres.
3. `samples` and `pairs`: `frob contact probe --design <reference quadruped> --samples --json` and `--pairs
   --json`, then `--gap-budget --scene <plane fixture scene> --pose <standing pose> --json` (the model branch
   requires both, VERBS-contact); assert 16 active foot samples, the static maximum 24 against
   the cap 21, every sample with its provenance, and on the planted-interference design the shank pair listed as
   tested.
4. `stand`: `frob sim run --tier referee --fixture traction/referee_stand --seed <s> --key
   traction-referee-stand-<s> --json` (BD-080's fixtures and form), 2 s on a plane; assert base drift below 1 mm
   after settling.
5. `drop`: `--fixture traction/referee_drop`, box from 0.5 m; assert the impact step brackets 0.3193 s and energy
   never increases.
6. `capacity_refusal`: `--fixture traction/referee_capacity_22`, 22 contacts; assert `FROB-REF-721`, exit code 5,
   `observed = 22`, `required = 21`.
7. `battery`: the referee battery in the Gauntlet's cargo form, `FROB_TEST_SEED=<seed> cargo test -p
   frob-conformance --test g1_known_answers -- GATE-TRAC-01/referee` (BD-085's runner; ADR-GAUNT-01: there is no
   `frob conformance` command), logging the hash of the receipt it writes; and from the user's side each row's
   fixture through `frob sim run --tier referee --fixture traction/<row> --seed <s> --key
   traction-referee-<row>-<s> --json` (BD-085's form). One assertion per known-answer row (incline threshold within 1%
   of μ, sphere acceleration within 0.5% of (5/7)·g·sin α, disk v = ω·r within 0.1%, drop energy, ring on a cone,
   Painlevé rod refused with `FROB-REF-224`), and one `refusal` event per row recorded as not expressible.
8. `clh_conformance`: maximum natural-map residual per row at most 10⁻⁶.
9. `thin_barrier`: `frob sim run --tier referee --fixture thin-barrier --count 10000 --seed <s> --key
   traction-referee-thin_barrier-<s> --json` (BD-086's `--count`; `--count 1000000` with `--long`); assert the
   `draws` block (`valid` equal to the count, `missed_hits = 0`, `refused_220 = 0`, `discarded` logged) and the
   canonical touchdown at 0.2 ms within one dyadic cell. The step also runs `FROB_TEST_SEED=<seed> cargo test -p
   frob-conformance --test g1_known_answers -- GATE-TRAC-06/referee/thin-barrier` and logs its receipt hash
   beside BD-086's record of those rows.
10. `sill`: a regression at the registry constants, not a gate measurement (the sill rows are N18b-38's): `frob
    sim run --tier referee --fixture wheel-over-lip --step <h> --seed <s> --key traction-referee-sill-<h>-<s>
    --json` at h = 2, 1 and 0.5 ms, with witness migration in the transaction (BD-093); assert the feature
    sequence flat, edge, top, work and impulse within 1% of the h/4 values, no couple above 10⁻⁹ N·m, and every
    reset present as a `witness-reset` event, against the values and tolerances of KA-409 read from
    `registry/known_answers.toml` and never typed in the script.
11. `negative_controls`: a mutant is a build feature, never a run-time flag (N38b-04's `mutation` kind: a
    `cfg(feature = "nc-<nnnn>")` branch, built only with `gauntlet-mutations`; a release build with it is a
    compile error). The step reruns each gate under its control build, `FROB_TEST_SEED=<seed> cargo test -p
    frob-conformance --features gauntlet-mutations,frob-contact/nc-<nnnn> --test g1_known_answers --
    <gate>/referee`, for `endpoint-only` (CX-169, GATE-TRAC-06: a missed hit) and `keep-memory` (CX-183,
    GATE-TRAC-06: a couple above 10⁻⁹ N·m), with the `NC-` numbers read from `registry/controls.toml` by their
    catalogue entries and never typed in the script; and BD-080's `truncate-contacts` mutant under its feature
    against `referee_capacity_22_refuses` (a truncated solve of 21 instead of `FROB-REF-721`). Each must
    **fail** for its stated reason; the script asserts the failure and records it as a caught control, and a
    control build that passes is a missed control and fails the script.

**Logging (the standard of the shared helper from STD-E2E).** The script sources the helper and writes
newline-delimited JSON to `target/e2e-logs/traction_referee/<utc-timestamp>.ndjson` and a human-readable
transcript beside it. Every line has `ts`, `script`, `bead`, `step`, `event` (`start`, `cmd`, `assert`, `metric`,
`refusal`, `end`), the exact command line, exit code, wall time, the envelope's `evidence` block (claim, class,
tier, profile, adjudicator, determinism, identities, seed), measured values with units and their thresholds,
digests where state is compared, and on failure the first differing value and the artifact paths needed to
reproduce (the `.frun` episode, the fixture file, the seed and index). A final `summary` line gives counts of
assertions passed and failed, controls caught, and the gates touched (GATE-TRAC-01 referee rows, GATE-TRAC-06
referee rows). Logs contain no private-scene data (fixtures only).

## Acceptance criteria

- [ ] The script exists, is executable, and passes on a clean checkout at M1 with `--profile referee`; with `--profile strict` once BD-161 lands.
- [ ] Every step emits `start`, at least one `cmd`, its `assert` events and `end`; the `summary` line's counts equal the number of assertions executed.
- [ ] Each of the three mutants makes its step fail and the script records the control as caught; with a mutant silently ineffective the script itself fails.
- [ ] Running the script twice gives identical run digests for every step (determinism lane: twice on one machine).
- [ ] The script writes no gate record (one recorder per gate: GATE-TRAC-01's referee rows by BD-085, GATE-TRAC-06's thin-barrier rows by BD-086, its sill rows by N18b-38, each with `cargo run -p frob-conformance --example record_gate -- --gate <id> --receipt <hash>`); the log names the receipt hashes of the Gauntlet runs of steps 7 and 9 beside their steps, so a record and a script run can be matched, and the `sill` step passes at the registry constants.
- [ ] No step calls `frob sim run` without `--key`, and no step uses a `frob conformance` command (the lint `no_conformance_command` of BD-025 passes on the script).
- [ ] Cancelling the script mid-run leaves no partial store and no orphaned job.

## Test plan

### Unit tests
- `e2e_log_schema_traction_referee`: a log produced by the script validates against the STD-E2E line schema (every required key present on every line).
- `e2e_script_idempotent`: two consecutive runs leave the working tree unchanged outside `target/`.
- `e2e_summary_counts_match`: the summary's pass and fail counts equal the counted `assert` events.

### End-to-end script and logging
This bead is the script; its own check is the self-test `scripts/e2e/traction_referee.sh --self-test`, which runs
steps 1, 5 and 6 only and validates the log schema.

### Known answers and negative controls
KA-387, KA-388, KA-389, KA-392, KA-395, KA-396 (battery); KA-408 (thin barrier); KA-409 (sill); the capacity
fixture of 22 contacts. Negative controls: the three mutant builds above (counterexamples CX-169, CX-183 and
BD-080's capacity-truncation mutant). Determinism lanes: twice on one machine; debug and release builds of `frob`.

## Considerations

- The `--long` lane (10⁶ crossings) is run for gate records and nightly, not on every change.
- The script must not hide a refusal as a skip: a row that the referee refuses is logged as a `refusal` event with its code and reason.
- When the list of referee-expressible rows changes (an upstream item lands), the expected-refusal list in the script is updated in the same change as the gate record.
