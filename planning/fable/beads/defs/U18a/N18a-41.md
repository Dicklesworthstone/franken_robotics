## Background

Generated scenes cross machines as seeds and identities, never as voxels: each machine compiles what it needs and
checks the `SceneId`. That only works if the same (family, parameters, seed, compiler version) gives the same
`SceneId` on Linux and on macOS. A unit test on one machine cannot show that; an end-to-end script run on both
machines against one pinned table can. This script drives the real `frob scene gen` verb for the terrain families
(flat, slope, stairs, step, gap, stepping-stones, rough, rubble, ramp, curb, mixed-route) and is the evidence for
the done-condition of the terrain-generator bead (BD-165).

## Scope

In: one script, the pinned identity table, logging, negative controls. Out: the generators (BD-165); interior
archetypes (their identity row closes at M3 with the interior gate).

## Technical approach

**Invocation.** `scripts/e2e/scene_gen_terrain.sh [--record] [--seeds N]`. Plain shell, non-zero exit on failure,
idempotent (it writes to a scratch store and to `target/e2e-logs/`), seed-explicit. Default N = 3 seeds per
family and difficulty; the gate-quality lane uses N = 1,000 per family.

**Pinned table.** `tests/fixtures/scene_ids/terrain.tsv`: rows of (family, difficulty, seed, compiler version,
`SceneId`). It is written once with `--record` on one platform, reviewed and committed, and thereafter only
compared; it is regenerated only with a recorded reason (a compiler-version change alters every identity by
design).

**Steps.**
1. `gen_all`: for each family, difficulty ∈ {0, 0.5, 1} and each seed: `frob scene gen --family <f> --difficulty
   <d> --seed <s> --json`; assert exit code 0 (or 8 followed by `frob job wait` to completion), an envelope with
   the evidence block, and a manifest of schema `frob.scene/1`.
2. `compare_ids`: assert each `scene_id` equals the pinned table's value for this compiler version.
3. `repeat`: generate one scene per family a second time in a fresh store; assert byte-identical manifests.
4. `show`: `frob scene show <scene_id> --json`; assert the family, seed, resolved randomized quantities with
   provenance, and `dimensions_assumed` equal to the count of `assumed` entries.
5. `difficulty_monotone`: for stairs, read the resolved rise at d = 0, 0.5, 1; assert 0.05, 0.14 and 0.23 m.
6. `grid`: generate a 4 × 3 curriculum grid; assert one pack, bit-identical heights on shared tile edges, and a
   spawn region and goal per tile.
7. `out_of_range`: `--difficulty 1.2`; assert a refusal with exit code 3 naming the field.
8. `cancel`: cancel a large grid job; assert no partial pack remains in the store.
9. `negative_controls`: test-only generator mutants `wall-clock-seed` and `platform-sin`; step 2 or step 3 must
   fail for each.

**Logging.** NDJSON to `target/e2e-logs/scene_gen_terrain/<utc-timestamp>.ndjson` through the STD-E2E helper,
with a transcript. Each line: `ts`, `script`, `bead`, `step`, `event`, the command line, exit code, wall time,
the `evidence` block (class, tier `static`, determinism `exact`, identities, seed), the `scene_id`, the manifest
digest, the expected identity, counts of overlays and regions, the platform triple, and on a mismatch the first
differing manifest field with the paths of both manifests. The `summary` line lists assertions, controls caught
and the platform. Generated terrain only: no private-scene data.

## Acceptance criteria

- [ ] The script passes on Linux and on macOS against one committed pinned table.
- [ ] The 1,000-seed lane passes on both platforms and its two logs are cited in the close reason of BD-165.
- [ ] Both generator mutants are caught.
- [ ] Refusal and cancellation steps behave as asserted.
- [ ] Two runs on one machine produce identical manifests.

## Test plan

### Unit tests
- `e2e_log_schema_scene_gen_terrain`: the log validates against the STD-E2E line schema.
- `pinned_table_wellformed`: the table has one row per (family, difficulty, seed) and no duplicate identity.

### End-to-end script and logging
This bead is the script. Self-test: `--self-test` runs steps 1 to 3 for the `stairs` family only.

### Known answers and negative controls
KA-464 (scene identity across platforms). Stairs rise at three difficulties. Negative controls: the two generator
mutants. Determinism lanes: twice on one machine; debug and release; Linux and macOS.

## Considerations

- The pinned table couples to the compiler version; the script prints the version and refuses to compare across versions.
- Runtime at 1,000 seeds per family is minutes of CPU; that lane is run for the bead's close and nightly.
