## Background

A kill gate is a decision named in advance, with its trigger, its milestone, the measurement that decides it, its
fallback, and what changes downstream. Each is recorded as an architecture decision record when decided, by a
bead of the unit that owns the mechanism (the rule of the fallback ledger N40-23, followed by N40-24).

The plan's Frontier table gives convex-hull collision primitives a pilot and a fallback and names no kill gate.
The gate register carries one all the same: **KILL-HULL**, entered by N40-24 through an `introduce` amendment, so
that the pilot (N18a-07) has a stop rule to name and the pilot register (N38a-09) can accept its record. As
registered:

| Field | Value |
|---|---|
| Trigger | The convex-hull pilot's falsifier holds, or the hull parity lane of the mechanism fails after one repair cycle |
| Decided at | M6, mode `pilot-before-funding`: due when WP-74 asks to fund N18a-08, and at the latest at the M6 exit |
| Measurement (`reads`) | The pilot record of N18a-07 in `crates/frob-conformance/registry/pilots.toml` (per-N error and cost tables, fitting-error ratios, verdict); if the mechanism was funded, the parity-lane receipts of N18a-08 |
| Fallback | Primitive unions with their recorded fitting error |
| Downstream if it fires | N18a-08 is closed with reason `fallback`; hulls return to "not offered"; the model compiler keeps emitting primitive unions with the fitting term in ε_g; the status table names the fallback |

The trigger has a clause read from the built mechanism, so this bead depends on N18a-08 and records the decision
once both clauses can be read; funding is read from the pilot record alone (`pilots fundable --bead N18a-08`,
N38a-09), which is the exception of N40-30's step 2, rule 7. Without this bead the row has no decider and the M6
exit finds no owner declaration (`owner-declaration-missing`). Tier: Frontier [F].

## Scope

In: reading the pilot record and, if the mechanism was built, its parity-lane receipts; evaluating both clauses
exactly as registered; the decision record `docs/adr/ADR-KILL-HULL-M6.md`; the row's `decision` entry and the
owner declaration; the status table. Out: the pilot (N18a-07); the mechanism and its repair cycle (N18a-08);
entering the row (N40-24).

## Technical approach

**Procedure.**
1. Read N18a-07's record: per N ∈ {4, 8, 16, 32} the share of near-touching cases whose residual exceeds 0.5 mm,
   the cost per pair in box–box tests at the smallest passing N, the fitting-error ratio per corpus link, the
   verdict, the reviewer, the receipt and the `protocol_blake3`, which must equal the registered hash.
2. Clause 1, the falsifier holds, from the record alone: at N = 16 more than 1% of near-touching cases have a
   residual above 0.5 mm; or the cost at the smallest passing N exceeds eight box–box tests per pair; or no corpus
   link has its fitting error reduced by a factor of two or more. Check the recorded verdict against it; a
   disagreement stops the bead and is reported to the pilot's owner.
3. Clause 2, read only if N18a-08 was funded: the parity lane (10⁶ random hull pairs; the true error never above
   the reported residual; 10⁻⁹ m in `f64` when N is raised) failed on a run made after one repair cycle. N18a-08
   closes with reason `fallback` when its lane still fails after that cycle, citing both receipts; a first failure
   with no repair is not a reading of clause 2, and N18a-08 stays open for its repair.
4. Name the outcome in N40-03's four: `fired` if clause 1 holds, or clause 2 holds; `not-fired` if clause 1 fails
   and N18a-08 closed with its lane passing; `not-reached` if WP-74 never asked to fund N18a-08 and the pilot has
   no result by the M6 exit; `deferred` only through an ADR naming the later exit and its reason.
5. Write `docs/adr/ADR-KILL-HULL-M6.md` with N40-03's fields: the kill gate; the milestone; the trigger as
   registered and the `introduce` amendment; each input with its receipt hash beside the clause it decides; the
   outcome and which clause decided; the fallback in force and the capability's name from now on ("convex hulls:
   primitive unions with recorded fitting error"); the beads re-read (N18a-08); the recording session, which
   neither ran the pilot nor implemented N18a-08.
6. Registry: the `decision` entry of the row in `registries/gates.toml` (N40-03's form) and the owner declaration
   (`[[gate]]`, `role = "owner"`, the ledger's current fields copied, `decision` with each measured value citing
   its receipt) in `frob-contact`'s `contract.toml`. On `fired`, the status table row reads "convex hulls:
   fallback (KILL-HULL)" and N18a-08 is closed `fallback` if it is not already.

**Fail-closed default until decided.** No hull primitive is offered: the model compiler emits primitive unions
with their recorded fitting error.

**Who decides.** The Traction lead prepares the record; a fresh-context session that neither ran the pilot nor
implemented the mechanism reviews and records it.

## Test plan

### Unit tests
`crates/frob-conformance/tests/kill_gates.rs`:
- `kill_hull_record_complete`: trigger, inputs, outcome, date and session present; the ADR's path is
  `docs/adr/ADR-KILL-HULL-M6.md`.
- `kill_hull_rule`: on synthetic records: 0.4% of near-touching cases above 0.5 mm at N = 16, cost 6 box–box
  tests, foot ratio 2.6, parity passing → `not-fired`; 1.3% above 0.5 mm → `fired` by clause 1; cost 9 → `fired`;
  every link's ratio below 2.0 (best 1.8) → `fired` (primitives suffice); clause 1 failing and the parity lane
  failing after the repair cycle → `fired` by clause 2; a parity failure with no repair recorded → no decision
  (the rule refuses to read clause 2); no result and no funding request at the M6 exit → `not-reached`.

### End-to-end script and logging
`scripts/e2e/kill_hull.sh` (header `# e2e: bead=N18ap4-01 milestone=M6 labels=traction,kill-gate
gates=KILL-HULL seed=0 needs=cpu plants=not-fired-with-primitives-sufficing`) re-derives the outcome from the
stored records, compares it with the ADR and the gate row, and runs `cargo test -p frob-conformance --test
kill_ledger` (asserting no failure names KILL-HULL) and `cargo test -p frob-conformance --test kill_gates --
kill_hull`. It exits non-zero on disagreement. It sources `scripts/e2e/lib.sh` (STD-E2E) and writes
`target/e2e-logs/kill_hull/<utc>.ndjson`; every line carries `ts`, `script`, `bead`, `step`, `event`, the exact
command line, exit code and wall time; it logs the record's digest, per clause the measured values against their
thresholds, the derived and recorded outcomes, and a `summary` naming KILL-HULL. It writes nothing to the
registry.

### Known answers and negative controls
The thresholds are the pilot's: 0.5 mm in 1% of near-touching cases at N = 16; eight box–box tests per pair; a
fitting-error factor of two on some corpus link. Negative control (plant `not-fired-with-primitives-sufficing`):
an entry `not-fired` while the stored record shows no link reaching a factor of two makes the script fail, and
`kill_ledger` reports `outcome-contradicts-measurement`.

## Considerations

- Until FD-FSIM-03 lands, the parity lane's oracle is the independent `frob-conformance` reference (N18a-08); the
  ADR names which oracle the clause-2 receipts used.
- A fired gate costs fitting accuracy, not a capability: primitive unions answer every collision query, with the
  fitting term carried in ε_g.
