## Background

North-Star scenario NS-08, "tracks on rubble": a tracked robot climbs stairs and crosses rubble; on soft soil
the sinkage model is active and labelled Frontier in the evidence. The scenario is the user-visible proof that
wheeled, tracked and hybrid bodies are simulated by contact physics (slip, scrub, traction limits, sinkage) and
that the system says honestly which parts of that physics are Solid and which are Frontier.

This bead is the end-to-end script for the capability "simulate and inspect wheeled, tracked and hybrid robots".
It drives the real `frob` binary on real fixtures the way an agent would, covers the rigid-ground legs (stairs,
rubble) and the soft-soil leg, and leaves a structured log. One script for the capability, not one per law.

## Scope

In: one shell script with stages (`wheel`, `tyre`, `belt`, `hybrid`, `ns08-rigid`, `ns08-soil`), its fixtures and
its log. Out: the mechanisms (N18b-01 to N18b-06, BD-365, BD-366); the soil verb's own script (N18b-19).

## Technical approach

**Script.** `scripts/e2e/wheels_tracks_ns08.sh`, plain shell, sourcing the shared helper of the end-to-end
harness; stages selectable with `--stage`; idempotent (explicit idempotency keys per step); `SEED` explicit
(default 1337); non-zero exit on failure after the summary line. A stage whose law fell back at its pilot runs
against the fallback and asserts the fallback's name in the evidence.

**Stages and assertions.**

1. `wheel`: `frob design templates --json` → `diff-drive`, `mecanum`; `frob sim run --tier batch-cpu` rolling
   disc → v = ω·r within 0.1% (time-averaged); mecanum sideways → yaw below 1°.
2. `tyre`: `frob contact laws --design <ackermann variant> --json` → the tyre law and card with provenance;
   a cornering run on `--profile strict` → lateral force at the measured slip angle within 2% of the law; an
   out-of-range slip query → exit 3, `FROB-REF-243`.
3. `belt`: `frob contact capacity tracked-flipper --json` → the belt class against the referee cap (does not
   fit) and the lockstep class (fits); turn in place on `strict` → scrub work per turn within 2% of
   2π·μ_lat·W·L/4; drawbar stall at μ_long·W; `frob sim run --tier referee` on the same base → exit 5,
   `FROB-REF-721`.
4. `hybrid`: the `wheel-leg` archetype with legs locked → rolling digests equal the plain wheel's; with the
   axle braked → holds an incline below the friction threshold; `tri-wheel-stair` climbs the step its geometry
   admits.
5. `ns08-rigid`: the `tracked-flipper` archetype under its baseline controller climbs the stair scene and
   crosses the rubble scene on `--tier batch-cpu` (and on each device tier present): assert task success, a
   non-zero scrub energy on the turn segments, the belt law named with tier label Frontier in the `evidence`
   block, the `Degraded` share printed, and promotion or labelling against `strict` for a sample of episodes.
6. `ns08-soil`: the same robot on a soft-soil patch bound to a soil card: assert that the sinkage model is
   active (non-zero sinkage reported in telemetry), that the evidence labels it Frontier and class `Estimated`
   for an `assumed` card, and that thrust falls with slip as the shear law predicts (drawbar pull at 20% slip
   within 2% of the closed form on `strict`).
7. Determinism: stages 1 and 5 repeated → identical digests; a second worker count → identical digests.
8. MCP parity for one run verb and one read verb used above.

**Logging.** Newline-delimited JSON to `target/e2e-logs/wheels_tracks_ns08/<utc-timestamp>.ndjson` and a
human-readable transcript beside it. Every line: `ts`, `script`, `bead` (`N18b-09`), `step`, `event` (`start`,
`cmd`, `assert`, `metric`, `refusal`, `end`), the exact command line, exit code, wall time, the envelope's
`evidence` block (claim, class, tier, determinism, identities, seed), measured values with units and thresholds
(speed ratio, yaw in degrees, forces in N, scrub work in J, sinkage in mm, success, `Degraded` share), digests
where state is compared, and on failure the first differing value and artifact paths (run identity, world
address, replay command). A final `summary` line gives assertion counts and the gates touched (GATE-TRAC-08).
Fixtures are public synthetic scenes; no private-scene data is logged.

## Acceptance criteria

- [ ] The script exists, sources the shared helper and passes on a clean checkout with `batch-cpu` only; device
      steps are skipped with a logged reason when no device is present.
- [ ] NS-08 is demonstrated: stairs and rubble on rigid ground, and the soft-soil leg with the sinkage model
      active and labelled Frontier in the evidence.
- [ ] Each stage logs at least one `assert` with measured value and threshold; refusals `FROB-REF-243` and
      `FROB-REF-721` are observed with their exit codes (3 and 5).
- [ ] A stage whose law fell back reports the fallback's name; the script does not fail for a fallback, it
      fails if the evidence hides it.
- [ ] Repeat runs reproduce digests; exit code 1 never appears.
- [ ] A self-test shows the script fails when an expected value is altered.

## Test plan

### Unit tests

None of its own. Harness self-test: altering the expected scrub work by 10% makes stage `belt` fail.

### End-to-end script and logging

As specified: `scripts/e2e/wheels_tracks_ns08.sh` driving `frob design templates`, `frob contact laws`,
`frob contact capacity`, `frob sim run`, the promotion verb and `frob-mcp`.

### Known answers and negative controls

KA-389 (v = ω·r), KA-394 (mecanum yaw), KA-417 (tyre force), KA-418 (no-slip yaw zero), KA-416 (track thrust at
20% slip: 293 N for the illustrative card), KA-282 (zero scrub work caught). Planted failures the script must
catch (run by CI with mutant builds): a no-slip tracked base that turns for free; a belt row without the
sprocket column; a soil run whose evidence omits the Frontier label. Determinism lanes: twice on one machine;
two worker counts; debug and release.

## Considerations

- The stair and rubble scenes depend on scene generators and on the tracked baseline controller; a failure
  there is reported with its first cause so that a controller defect is not booked as a contact defect.
- Run time target: under twenty minutes on `batch-cpu` (TARGET); the NS-08 stages use the `smoke` episode count
  and are not a statistical claim.
- The scenario demonstrates capability and labelling. It makes no claim about a physical tracked robot.
