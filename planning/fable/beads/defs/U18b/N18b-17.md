## Background

Soft soil sinks under a wheel or a track and, in reality, stays sunk: the next pass meets a rut. The soil rows
of the step (N18b-13) give sinkage while a contact is loaded; when the contact leaves, that model's ground is
flat again. **Persistent deformation** keeps it: ruts and footprints live in a per-world mutable buffer over
shared static tiles. It is a Moonshot whose ceiling is coverage of repeated-pass tasks, and whose fallback is
"off; terrain resets each episode".

The requirement that shapes everything is isolation. A rut made in one episode must have no effect on another;
reset and checkpoint fixtures detect the leak. Rule (invariant INV-HAB-03): a film tile wetted or a rut made in
one world or one episode has no effect on any other world or any later episode unless the task declares
persistence across episodes, and then only for that world address. The soil-track-tyre gate carries the
measurable form: rut leak zero over 10³ resets.

This bead is the M4 form of the mechanism: correct, isolated, on `batch-cpu` and under the transactional
profile. Batch-scale memory, device pools and the question of whether ruts change design decisions belong to
the M6 epic "soft soil at scale". Funded only after the pilot N18b-16; if the pilot's falsifier held, this bead
closes on the fallback and the gate's rut row is recorded against it.

## Scope

In: the rut field (data layout, read path, write rule, reset, snapshot, restore, fork, declared persistence);
its coupling to the soil normal law; the rut-isolation row of GATE-TRAC-08. Out: device back ends and batch
scale (the M6 epic); lateral soil flow, berms and slip-sinkage (not specified, not built); visual rendering of
ruts.

## Technical approach

**Data layout (DESIGN).** Static scene tiles are immutable and shared. Per world:

- a **rut directory**: a fixed-capacity open-addressed table from static tile index to rut tile slot, empty at
  episode start;
- a **rut pool**: fixed capacity T_rut slots (a field of the shape class, so it is part of `StepPlanId`), each
  an 8 × 8 array of `f32` offsets Δz ≤ 0 in metres at the scene's fine resolution, zeroed on allocation.

Bytes per world: T_rut·(64·4 + directory entry). At T_rut = 64 that is about 17 kB, of the same order as a
quadruped's whole state, which is why the capacity is explicit and reported by `sim.estimate`.

**Read path.** Ground height queries for contacts on a soil region return static height + Δz(world, cell),
with Δz = 0 where the directory has no entry (bilinear in Δz across cells, with the stated interpolation bound
added to the gap error ε_g). Sensors that read terrain height read the same function, so a height scan sees
the rut. A world with no rut tiles is bit-identical to the mechanism being off.

**Write rule.** After a step commits (never inside a candidate interval): for each soil contact k with
committed sinkage z_k and cell (i, j), Δz(i, j) ← min(Δz(i, j), −(1 − ρ_e)·z_k), where ρ_e is the card's
elastic rebound fraction (default 0: fully plastic). Writes within a step are applied in a deterministic order
(sorted by cell index; min is order-independent, so the result is too). Under a transactional profile the
write is part of the commit; a retried interval restores the pre-interval rut state ("terrain edits" are in the
restore set). Soil state inside the rut: a later contact at a cell with Δz < 0 starts from the rut surface; the
soil normal law's reference surface is the rutted height and its unloading depth is the stored Δz, so a second
pass over a rut sinks further only if its pressure exceeds what made the rut.

**Reset.** At episode reset the directory is cleared and slots are returned to the pool; slots are zeroed on
allocation, so stale offsets cannot reappear. With `persistence: across-episodes` declared by the task, reset
keeps the directory and pool for that world address only; the declaration is part of the task identity and is
printed in the evidence.

**Snapshots, restore, forks.** The directory and the used slots are part of every snapshot, of the restore set
and of fork copies; a fork copies them by index into the fork's own pool. Digests cover them, so first-
divergence search localizes a rut difference like any other state.

**Capacity.** Pool exhaustion marks the world `Degraded: rut-capacity` with the tile that could not be
allocated; the write is not applied to any other tile and the world's later results carry the flag. It is
never undefined behaviour and never a silent drop. Unequal `Degraded` shares between arms of a comparison are
subject to the capacity-bias label like any other capacity.

**Evidence.** Results with ruts enabled carry the tier label Moonshot and class `Estimated`; the envelope
states whether persistence across episodes was declared.

## Acceptance criteria

- [ ] The pilot N18b-16 is on record with a positive result, or this bead closes on the fallback "off; terrain
      resets each episode" and says so in the gate record.
- [ ] Rut isolation: a rut made in one episode is absent from every other; leak zero over 10³ resets on
      `batch-cpu` (TARGET; the rut row of GATE-TRAC-08), across worlds, co-tenancies, checkpoint and restore,
      and forks.
- [ ] A world with no rut writes is bit-identical to the same run with the mechanism off.
- [ ] A second pass along a rut at the same load sinks no further; at a higher load it deepens the rut to the
      new closed-form sinkage within 2%.
- [ ] Forced retry of a transaction that wrote a rut yields the digest of a clean run with the same plan.
- [ ] Declared persistence keeps the rut for that world address only.
- [ ] Pool exhaustion is flagged `Degraded: rut-capacity`; the planted leaks of the pilot remain caught by the
      retained fixture.

## Test plan

### Unit tests

`crates/frob-contact/tests/ruts.rs`.

- `write_min_rule`: sinkages 10 mm then 6 mm at one cell leave Δz = −10 mm; 6 mm then 10 mm leave −10 mm.
- `order_independent`: the same contacts applied in two orders give identical bits.
- `read_bilinear_bound`: the interpolated Δz differs from the cell values by at most the stated bound.
- `second_pass_same_load`: no further sinkage; `second_pass_heavier`: deepens to (p/k)^(1/n).
- `reset_zeroes_on_allocation`: a slot reused after reset reads 0 before any write.
- `snapshot_restore_fork`: round trips and independent divergence.
- `retry_restores_ruts`: forced-retry digest equality; omitting the rut pool from the restore set is caught.
- `persistence_scoped`: with persistence declared, address A keeps its rut across reset and address B does not
  see it.
- `no_writes_is_off`: digest equality with the mechanism disabled.

### End-to-end script and logging

Covered by `scripts/e2e/contact_soil.sh` (bead N18b-19), stage `ruts`: `frob sim run --tier batch-cpu` on the
leak scene with explicit seeds, 10³ resets, digest comparison against fresh worlds, and a two-pass run. NDJSON
lines carry command, exit code, wall time, the `evidence` block (Moonshot, `Estimated`, persistence flag),
leak count against 0, reset count, sinkage of the first and second pass, digests, and on failure the first
differing digest with world address, episode and step.

### Known answers and negative controls

KA-419 (rut isolation; leak zero over 10³ resets; tier: chaos on lockstep). Negative controls (retained from
the pilot): a rut buffer indexed by tile only; reset that reuses dirty tiles; a snapshot without the rut pool;
allocation by arrival order. Metamorphic: a world of a mixed batch equals the same world alone; slot
permutation permutes results. Determinism lanes: twice on one machine; worker counts; debug and release;
capacities and co-tenancies.

## Considerations

- Priority 4 by the Moonshot rule, with an M4 gate row attached; if unfunded when the soil work closes, the
  gate row is recorded against the fallback, which is named in advance and is not a failure.
- The M6 epic "soft soil at scale" extends this to device pools and batch scale with the same zero-leak
  criterion; nothing here may assume shared memory between worlds.
- Memory: rut capacity competes with contact and row capacity for the per-world budget; the epic owns the
  trade-off.
- A rut changes scene geometry seen by the clearance complex and by sensors mid-episode; static clearance
  certificates are computed on the undeformed scene and say so.
