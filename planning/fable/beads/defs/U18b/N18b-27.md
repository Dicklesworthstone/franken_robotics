## Background

A proposal considered for the contact solve was to factor the per-world Hessian H in half precision on matrix
accelerators (tensor cores) and recover accuracy by iterative refinement in single precision. The proposal is
rejected (decision ADR-TRAC-07; hypothesis H-15, refuted), and the rejection is recorded as a calculation so that
nobody rebuilds it. A killed idea stays on the page with the arithmetic that killed it, and that arithmetic is
part of the known-answer suite.

The refuting calculation has three parts.

1. *Conditioning.* Half precision has unit round-off u₁₆ = 2⁻¹¹ ≈ 4.9·10⁻⁴. Refinement on a low-precision factor
   contracts only if κ·u₁₆ < 1. Take a rank-one contact operator W with the proximal shift ρ = 10⁻²·tr(W)/48 for
   16 contacts (48 rows): the largest eigenvalue of W is tr(W), so κ(W + ρ·I) = (tr(W) + ρ)/ρ = 1 + 48/0.01 =
   4,801 and κ·u₁₆ = 2.34. FACT (emulated in software on three reference models; to be re-run before a gate cites
   it): after unit-diagonal scaling, κ·u₁₆ ≥ 1 in 37 to 64% of sampled contact states, and a half-precision
   factor with single-precision refinement fails outright in 9 to 18% of them.
2. *Cost.* A single-precision Cholesky costs n³/3 flops and each refinement step about 3n², so k steps cost
   9k/n times the factor they replace: 2.3 at n = 27 with seven steps, 1.5 at n = 35 with six, 3.0 at n = 18
   with six. Refinement alone costs more than the factorization it was meant to cheapen; with six steps the
   ratio falls below a quarter only above 216 unknowns.
3. *Hardware.* Matrix accelerators speed large products. A per-world matrix of 18 to 64 rows is smaller than one
   panel, and Apple GPUs have no such units. The published four- to five-fold gains were measured against double
   precision at about 22,000 unknowns, and theory promises at most a factor of two against a single-precision
   baseline (FACT about the published source, to be re-read).

Nothing about contact solves survives. What is used instead: single precision in power-of-two scaled variables
(BD-156, N18b-25), with admission by scaled κ·u (N18b-26). Matrix accelerators are likewise not adopted for
policy networks of a few hundred units: learner and inference together are about 13% of training wall-clock on
one incumbent stack, so their removal gains at most 1.15.

## Technical approach

**Where the refusal fires (DESIGN).** Three entry points can carry a precision request and each validates it
against a closed enumeration:

- the step plan: the resolved arithmetic pins of N35-04 carry a width (`f32 | f64`) and a precision profile
  (`default | stiff`), and the tier's element type is `f32` on devices and `f32` or `f64` on `batch-cpu`. A
  16-bit width is unrepresentable in the type;
- the surface: `frob sim run --precision <p>` and the corresponding field of every `run` verb that creates an
  environment. The option and its admitted values are N35-04's, one enumeration that selects both width and
  profile, `--precision {default|stiff|f32|f64}`, resolved per tier (`f64` on the referee and `batch-cpu` only,
  `FROB-REF-604` elsewhere). N35-04 also builds the enumeration's list of *recognized and refused* values (listed
  in the generated schema with `x-frob-refused: <code>`, so they pass schema validation on the CLI and on MCP
  alike and are refused at admission step 1 with that code); this bead enters in that list the five
  half-precision spellings `f16`, `half`, `fp16`, `mixed` and `mixed-f16` (a mixed-precision factor is a
  half-precision factor with single-precision refinement, the proposal refuted below), each annotated
  `x-frob-refused: FROB-REF-245` and parsed to a `RequestedPrecision`, and owns that refusal, its message, its
  empty repair list and its tests. A misspelt or unknown value is the generic schema refusal (`FROB-REF-802`),
  not this one: the half-precision spellings are recognized on purpose so that the caller learns why;
- the kernel manifest: a manifest whose element type for a solve or state slab is a 16-bit float fails
  registration with the same code at build time.

**The refusal.** Code `FROB-REF-245`, name "Half precision", raised when a half-precision solve or state buffer
is requested. Exit code 3. `retry` = `never`. Ranked repairs: none; the capability is not offered. The message
cites the calculation: "κ·u₁₆ ≥ 1 on 37 to 64% of sampled contact states; refinement costs 9k/n times the factor
it replaces". `pointer` names the field that carried the request.

**The calculation as code (DESIGN).** `frob-conformance/registry/known_answers.toml` rows with one derivation
file `docs/derivations/half-precision.md`; a host test evaluates each number in exact rational arithmetic where
it is rational (κ = 4,801; the cost ratios 63/27, 54/35, 54/18; the break-even 36·k) and in `f64` otherwise
(κ·u₁₆ = 4,801/2,048 = 2.344).

**Emulation fixture (DESIGN; one type and one fixture for this bead, the card GB-22 and N21c-25).** A software
half-precision type (round-to-nearest-even conversion of each operation result to 11 significand bits,
exponent range of IEEE binary16) in the test-support module `frob_conformance::half16`, used only by tests of
the conformance crate (the tests in `frob-contact` cover the refusal and need no emulation).
The whole factorization runs in that type, operation by operation. Rounding the entries of a factor that was
computed exactly is not an emulation of a half-precision factorization and is not used: the rounded exact
factor is a small relative perturbation of the true one, and refinement on it contracts (see the control
below).

The rank-one fixture: n = 48 (three rows for each of 16 contacts), A = w·wᵀ + ρ·I with ‖w‖² = tr(w·wᵀ) = 48
and ρ = 0.01 (the shift ρ = 10⁻²·tr(W)/48), so the eigenvalues are 48.01 once and 0.01 forty-seven times and
κ = 4,801; w is a random direction from an explicit seed, and the fixture is the 200 seeds 0 to 199. The same
matrix scaled to tr(W) = 1 and ρ = 10⁻²/48 has the same κ and may be used where a unit trace is convenient.
Procedure per seed: factor A in the emulated type; solve for a seeded right-hand side; run ten refinement
steps with the residual in `f64` and the correction from two triangular solves with the low-precision factor;
record the relative error against the known solution after each step.

What "does not contract" means on this fixture (DESIGN, the same statement in GB-22 and N21c-25). The theory
says only that convergence is not assured when κ·u₁₆ ≥ 1, so the assertion is over the 200 seeds and not on
every step of one seed: (a) in at least 90% of seeds the error after ten steps is at least 10⁻² of the error
before refinement; (b) in at least half of the seeds it is at least the error before refinement; (c) with a
single-precision factor of the same matrix (κ·u₃₂ = 4,801·2⁻²⁴ = 2.9·10⁻⁴) every seed contracts by at least
10³ at the first step and reaches a relative error below 10⁻⁶ within two steps. A plan-time check with a small
program (FACT to re-run by this fixture, which then replaces these figures) gave 99% for (a), 68.5% for (b), a
median growth of about 4 over the ten steps, and for (c) a worst first-step ratio of 2·10⁻⁶; a stricter reading,
"the error ratio is at least 1 at every one of the ten steps", held in only about a third of the seeds and is
therefore not asserted. The thresholds in (a) and (b) are TARGETs set with margin below the checked values.

On sampled contact states of the reference robots (the matrices N38a-11's `export_contact_hessians` writes) the
same type measures the share of states with κ·u₁₆ ≥ 1 and the share where refinement from the emulated factor
fails outright (N38a-11's criterion: the factorization breaks down, or the residual does not fall below its
start in ten steps). The re-run of record of both FACT shares is N38a-11's (rows 19 and 20, M0, by containment
against 37 to 64% and 9 to 18%); this bead reads that pilot result, logs its own emulated shares beside it, and
replaces the figures in the refusal message, the derivation file and CX-176's catalogue row by N38a-11's
measured shares. It replaces only the figures: CX-176's `rerun` pair is N18-CX's, entered from the pilot record
`PILOT-PT-19` and always equal to that record's `pilots::rerun_status` (`rerun = true` with the record's receipt
where it reads `reproduced`, otherwise `rerun = false`; a pair that disagrees is the load error
`rerun-disagrees-with-pilot`, N38b-05), so this bead never sets it.

The counterexample CX-176 is carried here as the plant `N18b-27:cx-176` (kind `planted-input`, N18-CX): a test-only
build with the `FROB-REF-245` check removed (`removed_check`), under which a half-precision factor is requested,
the emulated refinement runs and does not contract by clauses (a) and (b); the refusal test must fail under the
plant and pass without it.

## Acceptance criteria

- [ ] `frob sim run --precision f16 --key <k> --json` (and `half`, `fp16`, `mixed`, `mixed-f16`) returns one
      envelope with `ok: false`, `FROB-REF-245`, exit code 3, `retry: never`, an empty repair list and the pointer
      to the field; the generated schema of `--precision` lists the five spellings under `x-frob-refused:
      FROB-REF-245`, so MCP validation passes them to admission; `--precision default`, `stiff`, `f32` and `f64`
      are unaffected (each still resolved per tier by N35-04).
- [ ] No type in `frob-kernels`, `frob-contact` or the device annexes can express a 16-bit float solve or state
      slab; a manifest that tries is rejected at registration (compile-fail or load-fail test).
- [ ] The known-answer rows reproduce: κ = 4,801; κ·u₁₆ = 2.34; cost ratios 2.3, 1.5, 3.0; break-even at 216
      unknowns for six steps.
- [ ] The emulation fixture shows non-contraction on the rank-one case by the three clauses (a), (b) and (c)
      over the 200 seeds, records the measured shares, and reports the measured share of sampled contact states
      with κ·u₁₆ ≥ 1 with its sample identity.
- [ ] The emulated type and the fixture are exported from one test-support module; GB-22's and N21c-25's
      demonstrations import them, and no second half-precision emulation exists in the workspace.
- [ ] `registries/refusals.toml` carries the code with its meaning and "repairs: none". The derivation file
      `docs/derivations/half-precision.md` exists and is what the two registers cite: the row for half precision
      in `registries/rejected_mechanisms.toml` (written by N21c-25) and the entry KI-01 of the killed-idea
      register (written by NAB-33).

## Test plan

### Unit tests

`crates/frob-contact/tests/half_precision.rs` and `crates/frob-conformance/tests/` (host).

- `kappa_rank_one`: W = w·wᵀ with ‖w‖² = tr(W) = 48, ρ = 0.01: eigenvalues of W + ρ·I are 48.01 and 0.01;
  κ = 4,801 exactly in rationals.
- `kappa_u16`: 4,801·2⁻¹¹ = 4,801/2,048 = 2.34423828125 exactly (reported as 2.34); assert the exact value and
  that it exceeds 1. Also `u16_is_2_pow_minus_11`: 4.8828125·10⁻⁴.
- `cost_ratios`: 9·7/27 = 7/3 ≈ 2.33; 9·6/35 ≈ 1.54; 9·6/18 = 3; assert each within 0.05 of 2.3, 1.5, 3.0.
- `break_even`: the least n with 9·6/n < ¼ is 217 (ratio equals ¼ at n = 216).
- `refine_does_not_contract`: the emulated binary16 factorization of the rank-one fixture over seeds 0 to 199;
  clauses (a) at least 90% of seeds with the ten-step error at least 10⁻² of the initial error and (b) at
  least half with it at least the initial error; the measured shares are logged.
- `single_precision_factor_contracts`: clause (c) on the same 200 matrices.
- `rounded_exact_factor_is_not_an_emulation` (control of the fixture itself): a factor computed in `f64` and
  then rounded entry by entry to 11 significand bits contracts on every seed, so a fixture built that way would
  fail clause (a); the test asserts that it does, which pins the choice of per-operation emulation.
- `refusal_spellings`: each of the five spellings yields `FROB-REF-245`; `--precision f31` yields the misspelt-
  parameter refusal (`FROB-REF-802`) instead; `default`, `stiff`, `f32` and `f64` parse; the generated schema's
  recognized-and-refused list holds exactly the five spellings, each annotated `x-frob-refused: FROB-REF-245`.
- `manifest_rejects_f16`: a manifest fixture declaring a binary16 state slab fails registration.

### End-to-end script and logging

`scripts/e2e/half_precision_refusal.sh` (helper of STD-E2E): issues the five refused requests through `frob
--json` (`frob sim run <design> --tier batch-cpu --precision <spelling> --key hp-<spelling> --json`, a distinct
key per request) and one through `frob-mcp` (`isError: true`), asserts exit code 3, `retry: never`, the empty
repair list and the pointer on each; issues `--precision f31` and asserts `FROB-REF-802`, not 245; then runs the
host known-answer target `FROB_TEST_SEED=<s> cargo test -p frob-conformance --test g1_known_answers -- KA-423`
(tier G1, the tier of KA-423) and the emulation fixture over the 200
seeds. Each NDJSON line carries `ts`, `script`, `bead`, `step`, `event`, the command, exit code, wall time, the
refusal block and, for the known-answer steps, each computed value against its expected value and the measured
shares of clauses (a), (b) and (c) against their thresholds; on failure the first differing value and artifact
paths. `summary` counts assertions. Exit code 1 never appears.

### Known answers and negative controls

KA-423 (κ = 4,801, κ·u₁₆ = 2.34, the three cost ratios, the refusal). CX-176 (the shortcut "a half-precision
factor with single-precision refinement cheapens the contact solve") with its numbers. Negative control: a
planted permissive parser that maps `f16` to `f32` silently must fail the refusal test (a misspelt or
unsupported parameter is a refusal, never a default). Negative control for the arithmetic: a mutant unit
round-off u = 2⁻¹⁰ must make `kappa_u16` fail on its exact value (it gives 4.688, still above 1, so only the
value assertion catches it). The plan's KA-552 (Cholesky operation counts 1,944 and 14,292 and the ratio 9k/n
as the device chapter prints it) is tested in N21c-25 and is not repeated here.

## Considerations

- The emulated shares (37 to 64%, 9 to 18%) are a recorded FACT from a small program; N38a-11 re-runs them
  (rows 19 and 20) before any document cites them as this project's measurement, and this bead then replaces
  the figures it prints.
- What would reopen the decision: contact systems above about 200 unknowns per world solved as one dense block
  (not in scope: the dense path is capped at 64 degrees of freedom), or a device with fast correctly rounded
  half-precision panels smaller than 64 rows. Neither exists in the target hardware.
- Bet BET-08 (single precision is adequate on the GPU given anchored coordinates, group-preserving updates,
  diagonal scaling and guarded comparisons) is the positive statement this refusal protects.
