## Background

Which contact law produced a number decides what the number means. Penetration is an error under the hard-
contact law and a state under the compliant laws; creep below the friction threshold is zero under one law and
bounded by a stiction speed under another; an evaluator must be told which law produced a gap. The law is
therefore part of the identity every result carries (`StepPlanId`), and an agent needs one place to ask which
laws exist, where each may run, and with which parameters.

The laws (each a named law of the contact solve):

| Law | Contents | Tier |
|---|---|---|
| CL-1 | Linear compliant normal with a dissipation time; regularized Coulomb friction with a stated stiction speed | Solid; default on lockstep tiers |
| CL-2 | Hunt–Crossley normal law and regularized friction in convex form | Frontier |
| CL-M | A mapping of an incumbent engine's soft-contact parameters, for importing reference models; lossy, and the loss report says so | Solid; parity only |
| CL-H | Hard contact: Signorini complementarity on the normal, Coulomb friction with maximum dissipation on the four-dimensional cone, non-associated | Solid as the referee's written specification; Frontier as a batch law |

Every law except CL-H is a convex potential ℓ_c whose negative gradient is the impulse; CL-H is a
complementarity problem and says so. Further laws attach to the same table as they land: the film-friction row,
tyre laws, the belt law, soil laws.

A law is **admitted** on a (tier, profile) pair only after its gate has passed there. Requesting a law where it
is not admitted is a refusal (`FROB-REF-246`), not a silent substitution of the default law, because a silent
substitution would return a result under an identity the caller did not ask for. `contact.laws` is the read
verb that prints the table. Tier Solid.

## Scope

In: the law registry and admission table; the refusal; invariant INV-TRAC-01 as a registration rule with its
tests; the verb at M1 (referee) with the growth path to later tiers. Out: the laws' mathematics and kernels;
interface cards (BD-167 adds the cards in use to the verb's output at M2); the probe verb (N18b-29).

## Technical approach

**Registry (DESIGN).** `registries/contact_laws.toml`, loaded by `frob-contact`; an unknown law name is a
load-time error.

```toml
[[law]]
id = "CL-1"
kind = "convex-potential"          # or "complementarity" (CL-H only)
tier = "S"
parameters = [
  { name = "stiffness",        class = "physical",  unit = "N/m" },
  { name = "dissipation_time", class = "physical",  unit = "s" },
  { name = "mu",               class = "physical",  unit = "1" },
  { name = "stiction_speed",   class = "numerical", unit = "m/s" },
]
admission = [
  { tier = "batch-cpu", profile = "lockstep", gate = "GATE-TRAC-01", status = "pending" },
  { tier = "batch-cpu", profile = "strict",   gate = "GATE-TRAC-01", status = "pending" },
  { tier = "gpu-cuda",  profile = "lockstep", gate = "GATE-TRAC-01", status = "pending" },
  { tier = "gpu-metal", profile = "lockstep", gate = "GATE-TRAC-01", status = "pending" },
]
```

Parameter classes: **physical** (stiffness, dissipation time, friction coefficients, restitution, film and soil
parameters), which come from cards and are never changed by a retry, a step variant or a tolerance variant; and
**numerical** (the stiction speed of a regularized law, regularization rates, pass counts, residual
tolerances), which are reported and belong to the step plan. Tiers: `referee`, `batch-cpu`, `gpu-cuda`,
`gpu-metal`. Profiles: `referee`, `strict` (transactional, `batch-cpu` only), `lockstep`.

**Admission status.** `status` is derived, not hand-edited: a row is `admitted` when `registries/gates.toml`
holds a recorded PASS for the row's gate restricted to that tier and profile; otherwise `pending` (gate not yet
measured), `failed` (gate measured and not passed), `fallback` (the law's kill gate fired and the named fallback
applies) or `not-built`. Initial rows and their gates: CL-1 on every lockstep tier and on `strict` by
GATE-TRAC-01; CL-H as the referee's specification on `referee` (admitted with the referee itself); CL-H on
`strict` and as a batch law on `batch-cpu` by GATE-TRAC-09 (GPU rows at a later milestone); CL-2 on `batch-cpu`
after its pilot and a recorded pass of the battery rows under it; CL-M on the tiers of CL-1, labelled
parity-only; the film row by GATE-TRAC-05; soil, belt and tyre laws by GATE-TRAC-08.

**Refusal.** Any verb that creates an environment with `--law <id>` (for example `sim.run`) checks the table.
Not admitted → `FROB-REF-246`, "Law not admitted", exit code 3, `observed` = (law, tier, profile, status),
`required` = the gate that must pass, `retry` = `after-change`, ranked repairs: (1) the admitted law for that
tier and profile; (2) `--profile strict` on `batch-cpu` where the law is admitted there. A law of status
`fallback` names the fallback in the message.

**INV-TRAC-01 as a registration rule.** "Every law on a lockstep tier is a convex potential, or is CL-H and
reports its residual." Enforced three ways: (1) a law of kind `convex-potential` must supply a potential whose
Hessian block is positive semidefinite by construction (a sum of positive semidefinite terms; theorem card
T-08), with a property test over its parameter range; (2) a law of kind `complementarity` must write its
natural-map residual ‖λ − Π_𝒦(λ − û)‖ into every step receipt, and a receipt without it fails schema
validation; (3) the registry loader rejects a lockstep admission row for a law that is neither.

**Verb (DESIGN).** `contact.laws`, kind `read`, first milestone M1, cluster `contact`, capability
`design:read`, idempotent, static cost.

- Input `frob.contact.laws.in/1`: optional `tier`, `profile`, `law`, `design` (to show the laws and cards a
  design's end effectors bind).
- Output `frob.contact.laws.out/1`: per law its kind, tier label, parameters by class with units; per (tier,
  profile) the status, the gate and the receipt of its PASS; the default law per (tier, profile); for a design,
  per end effector the bound law, r_eff source and (from M2) the interface cards with provenance; the
  stiffness-admission figure where one exists.
- At M1 the table has the referee rows populated and every batched row `not-built` or `pending`; the verb's
  shape does not change later.
- Evidence: class `Tested`, determinism D0, tier `static`.

## Acceptance criteria

- [ ] `frob contact laws --json` lists the four laws with parameters split into physical and numerical, and the
      admission table per tier and profile with gate and status.
- [ ] `frob sim run --law CL-H --tier batch-cpu --profile lockstep` before GATE-TRAC-09 has a recorded PASS
      returns `FROB-REF-246` with exit 3 and both repairs; after a PASS is recorded in a fixture registry the
      same request is admitted.
- [ ] Status is computed from the gate registry: editing a status by hand in the law registry has no effect and
      is flagged by the loader.
- [ ] INV-TRAC-01: the property test passes for every registered convex law; a planted non-convex potential
      (a friction term with a negative curvature region) fails registration; a CL-H receipt without a residual
      fails schema validation.
- [ ] The law identity appears in `StepPlanId`: two runs differing only in `--law` have different plan
      identities.
- [ ] The verb is in `registries/verbs.toml`, served by CLI and MCP from that entry, with examples and its
      refusal list.

## Test plan

### Unit tests

`crates/frob-contact/tests/law_registry.rs`.

- `registry_loads`, `unknown_law_is_load_error`.
- `status_derived_from_gates`: with a fixture gate registry holding PASS for (GATE-TRAC-01, `batch-cpu`,
  `lockstep`) CL-1 is `admitted` there and `pending` on `gpu-cuda`.
- `refuse_not_admitted`: (CL-2, `gpu-metal`, `lockstep`) → `FROB-REF-246`; repairs list CL-1 first.
- `fallback_named`: with the kill-gate fixture for the hard-contact batch law fired, (CL-H, `batch-cpu`,
  `lockstep`) reports status `fallback` and names "fixed-iteration island solvers with a residual flag".
- `convex_law_hessian_psd`: 10⁴ random contact velocities and parameter rows per convex law; the smallest
  eigenvalue of each Hessian block is at least −10⁻¹² relative.
- `complementarity_reports_residual`: schema check on a CL-H receipt.
- `parameter_classes`: stiction speed is `numerical`; stiffness, dissipation time, μ are `physical`; a retry
  ladder fixture changes no physical parameter (digest before and after).

### End-to-end script and logging

Covered by `scripts/e2e/contact_laws_probe.sh` (bead N18b-30). At M1 a reduced script
`scripts/e2e/contact_laws_m1.sh` (helper of STD-E2E) runs `frob contact laws --json`, a refused `sim.run
--law`, and the admitted one on the referee, logging command, exit code, wall time, the `evidence` block, the
refusal block and the table digest.

### Known answers and negative controls

CX-181 (the convex associated model is not Coulomb friction: dropping μ·‖u_T‖ gives a sliding contact a
separation velocity μ·‖u_T‖; CL-1 has that artifact in compliant form), which is why the law identity must
travel with every result. Negative controls: silent substitution of the default law for a refused one; a
hand-edited `admitted` status; the non-convex planted law.

## Considerations

- OPEN-KIN-4: which law the `strict` profile runs by default once CL-H is admitted (default CL-1 with located
  events, CL-H as a named variant); the table's default column is where that decision lands.
- KILL-CONTACT changes the default law of the lockstep tiers to CL-2 at a published lower throughput (N18b-33);
  the default column and every `StepPlanId` built from it change with it, and that is recorded as an ADR.
- The registry is read by a verb and checked by a refusal, which is the condition for a registry to exist at
  all; it holds no data that the gate registry already holds.
