## Background

`contact.laws` and `contact.probe` are how an agent inspects the contact model without running physics: which
laws exist and where each is admitted, which cards a design's end effectors use and with what provenance, and
what a law, a cone or a film does at one stated contact state. The same two verbs surface the precision posture
of the contact solve: the stiffness-admission figure, the refusal of cards too stiff for single precision, and
the refusal of half precision.

This bead is the end-to-end script for that inspection capability. It drives the real `frob` binary and the MCP
surface on real fixtures and leaves a structured log. It exists because unit tests can pass while the verb is
unreachable, mis-registered, returns a naked number without its evidence block, or maps a refusal to the wrong
exit code; none of those is visible below the surface.

## Scope

In: one shell script, its fixtures and its log, covering the two verbs, the missing-pair refusal, the cone and
precision refusals. Out: the mechanisms; the gate records (BD-156, BD-167); the capacity and audit script
(N18b-24).

## Technical approach

**Script.** `scripts/e2e/contact_laws_probe.sh`, plain shell, sourcing the shared helper of the end-to-end
harness; idempotent; `SEED` explicit (default 1337, printed); non-zero exit on failure after the summary line.

**Fixtures.** Public synthetic: the `quad-mammal`, `mecanum` and `diff-drive` archetypes; an interface-card set
`cards/e2e/` with rubber-on-concrete dry (μ = 0.8), rubber-on-concrete wet (μ = 0.25, with film parameters),
steel-on-concrete dry, a roller card (μ₁ = 0.8, μ₂ = 0.02), one invalid card (μ = −0.1), one near-rigid card
(stiffness raised until the admission figure is 0.06) and no rubber-on-ice card (the missing pair).

**Steps.** Four beads own a script each, written and passed when the bead landed: `contact_laws_m1.sh`
(N18b-28), `contact_probe_m1.sh` (N18b-29), `stiffness_admission.sh` (N18b-26) and `half_precision_refusal.sh`
(N18b-27). This script runs them first as stage 0, reads the `assert`, `refusal` and `summary` lines of their
logs (a called script that exits 0 with a failed `assert` line fails the stage), and then adds the steps below,
which need the cards of BD-167, the cone kernels and the batched tiers of M2; it contains no second copy of the
called scripts' commands.

1. `frob doctor --json`; record build identity and fingerprint.
2. `frob contact laws --json` → exit 0; assert four laws, each parameter tagged physical or numerical, the
   stiction speed tagged numerical, an admission row per (tier, profile) with its gate, now including the
   batched rows, and the cards in use.
3. `frob contact laws --design quad-mammal --json` → assert each end effector's law, r_eff with its source
   (`geometry: 2a/3` by default), and the interface cards with provenance per field.
4. `frob contact laws --design mecanum --json` → assert the roller angle ±45° per wheel and (μ₁, μ₂).
5. *Missing pair.* `frob sim run quad-mammal --scene fixtures/e2e/ice-patch.fscene --tier batch-cpu --key
   mp-ice --json` (the scene's ice region meets the rubber feet; the card lookup at plan admission finds no
   rubber-on-ice card) → the refusal of the allocation ledger's row `interface-pair-missing` (family `2xx`, numbered at the ledger's
   M0 run, so this M2 script asserts the number from the generated hand-off page `docs/generated/refusal_round2.md`
   and N18-REF's table; never a generic error), naming the (mover, substrate, condition) triple; exit 3; repairs "add a card" and "choose a material
   that has one".
6. *Invalid cone.* `frob contact probe --card cards/e2e/invalid.fcard ...` → exit 3, `FROB-REF-240`.
7. *Law not admitted on a batched tier* (`--law` is N18b-28's at M1, whose script in stage 0 asserts the referee
   forms: `--law CL-2 --tier referee` → 246 with `not-built`, a misspelt `--law CL-9` → 802; the `batch-cpu` tier
   arrives with N16b-25 at M2, so this form is here). `frob sim run quad-mammal --law CL-H --tier batch-cpu
   --profile lockstep --key cl-h --json` → exit 3, `FROB-REF-246` with status `pending` (GATE-TRAC-09 unrecorded)
   or `fallback`, repairs naming the admitted law and `--profile strict`. Every run-kind call of this script
   carries its own `--key`.
8. *Probe, incline, on the batched law* (the referee form is stage 0's, N18b-29). The same two states with
   `--tier batch-cpu --profile lockstep`: tan α = 0.49 and 0.51 at μ = 0.5 → regimes `stick` and `slip`.
9. *Probe, cone* (`frob contact probe --cone`, N18b-29's selector, at the states below). μ = 0.6, N = 100 N,
   a = 30 mm, uniform pressure: assert r_eff = 20 mm; pure sliding 60 N; pure
   spin 1.2 N·m; at v = r_eff·ω, 42.4 N and 0.85 N·m within 0.5%; diagonal traction μ·N within 0.5%.
10. *Probe, sweep.* A sweep of ω at fixed v returns a paginated curve whose tangential force is monotone
    decreasing in ω; assert pagination fields and the monotonicity.
11. *Probe, film.* Not in this script (convention 7: the film branch lands at M3 with BD-230, which this M2 bead
    does not depend on). `scripts/e2e/traction_film.sh` of N18a-37 (on BD-230) owns it through `frob contact
    probe --film`: the three squeeze times 0.038 s, 2.3 s and 0.76 s within 2%, h₀ = 0 returning the dry
    coefficient bit for bit, `--strict-data` outside the calibrated range → exit 3, `FROB-REF-242`, and
    `extrapolated` without the flag. Before BD-230 a `--film` probe answers `FROB-REF-724`, which stage 0
    (N18b-29's script) asserts.
12. *Stiffness admission at the command line* (needs the batched step, so it is here and not in N18b-26's
    script). `frob sim run <design with the near-rigid card> --tier batch-cpu --precision f32 --key sa-cpu
    --json` (N35-04's `--precision {default|stiff|f32|f64}`, which selects the width and the precision profile
    in one value) → exit 3, `FROB-REF-244`, observed 0.06 and required 0.05, repairs "`batch-cpu` in `f64`" and
    "a softer qualified card"; the repair command taken verbatim from the envelope's `next_actions` (`--tier
    batch-cpu --precision f64` with a fresh key) succeeds and its envelope states width `f64`; the same with
    `--tier gpu-cuda --precision f32` and `--tier gpu-metal --precision f32` (own keys) on each device tier
    present (skipped with
    a logged reason when absent), whose repair also names `batch-cpu`, since `--precision f64` on a device tier is
    `FROB-REF-604`; `frob sim estimate --json` on the default card set prints the admission figure, the bound and
    the sample identity.
13. *Half precision.* Asserted by `half_precision_refusal.sh` in stage 0 (`frob sim run --precision f16` and the
    other four spellings → exit 3, `FROB-REF-245`, no repairs); this step repeats it once on each device tier
    present (`gpu-cuda`, `gpu-metal`, with its own `--key`; skipped with a logged reason when absent).
14. *Evidence.* Every successful envelope has the `evidence` block with claim product fields and, for a card
    with an `assumed` field, class `Estimated`.
15. *MCP parity.* `contact_laws` and `contact_probe` through `frob-mcp` with the arguments of steps 2 and 9;
    assert the structured content equals the CLI envelope apart from transport fields; a refused probe returns
    `isError: true` with the same envelope.
16. *Determinism.* Steps 2, 3 and 9 repeated; identical result digests.

**Logging.** Newline-delimited JSON to `target/e2e-logs/contact_laws_probe/<utc-timestamp>.ndjson` with a
human-readable transcript beside it. Every line: `ts`, `script`, `bead` (`N18b-30`), `step`, `event` (`start`,
`cmd`, `assert`, `metric`, `refusal`, `end`), the exact command line, exit code, wall time, the envelope's
`evidence` block (claim, class, tier, determinism, identities, seed), measured values with units and thresholds
(forces in N, moments in N·m, times in s, coefficients dimensionless), digests where outputs are compared, and
on failure the first differing value and the artifact paths. A final `summary` line gives assertion counts and
the gates touched. Logs contain no private-scene data.

## Acceptance criteria

- [ ] The script exists, sources the shared helper, and passes on a clean checkout with `batch-cpu` only;
      device steps are skipped with a logged reason when no device is present, and no step waits on a bead of a
      later milestone (the film probe is N18a-37's).
- [ ] Each of the refusal codes 240, 244, 245, 246 and the missing-pair refusal is observed with exit code 3
      and its ranked repairs.
- [ ] The cone known answers are asserted from the verb's output with thresholds logged.
- [ ] MCP parity holds for the two verbs, including the refused case.
- [ ] Exit code 1 never appears; a second run reproduces the same digests.
- [ ] A self-test shows the script fails when one expected value is altered.

## Test plan

### Unit tests

None of its own. A harness-level self-test alters the expected coupled force from 42.4 N to 60 N and asserts
that the script fails at step 9, and makes a called script of stage 0 log a failed `assert` while exiting 0
and asserts that stage 0 fails.

### End-to-end script and logging

As above: `scripts/e2e/contact_laws_probe.sh` running the four owned scripts of stage 0 and driving `frob
contact laws`, `frob contact probe`, `frob sim run` (for refusals), `frob sim estimate` and the same tools
through `frob-mcp`.

### Known answers and negative controls

KA-387, KA-398, KA-399, KA-401 (cone and incline through the probe); KA-404 and KA-406 (film) are N18a-37's; KA-422
(cards over the bound refuse with FROB-REF-244); KA-423 (half precision refuses with FROB-REF-245). Planted
failures the script must catch: a default card silently substituted for the missing pair; a verb that returns
a number without an evidence block; the altered expected value of the self-test. Determinism: twice on one
machine; debug and release in CI.

## Considerations

- The script must not assert on gate status values that change as milestones close; it asserts on structure
  (a gate is named and a status is present) and on refusals at fixed fixture registries.
- Run time target: under two minutes (TARGET); every step is a read verb or a refused admission.
- When KILL-CONTACT fires the default law changes; the script reads the default from `contact.laws` and does
  not hard-code CL-1.
