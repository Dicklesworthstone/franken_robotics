## Background

`contact.response` is the `run` verb for response batches: at a converged contact step it reuses the factor of
the Hessian to answer many "what if" right-hand sides (counterfactual impulses, adjoint columns, the columns
of a design stencil), each with a certified error bound and a guard that reroutes any column whose answer
would cross a stick, slip or open boundary to the full solve. It is a Frontier diagnostic query, not a
stepping path.

Its gate is GATE-TRAC-11 (known answer, TARGET, earliest M4): the three fixtures reproduce and the λ = 3
mutation is caught. On 10⁴ battery contact states with 64 random columns each, solved in `f32` and compared
with a full `f64` re-solve of every column: zero accepted columns whose true error exceeds the attached bound,
and zero accepted columns whose re-solve has a different active set or stick label. The rerouted share is
reported per robot class. A batch requested against a changed anchor is refused.

Its kill gate, KILL-RESPONSE, has two triggers: (1) the mode guards reroute more than half the columns on
battery states (then the mechanism answers too few queries to be worth keeping); (2) a bound violation or a
false mode acceptance that survives one repair cycle (then its answers cannot be trusted). The fallback for
both is the same: full solves per query. Trigger 1 is evaluated with the mechanism's pilot; this bead measures
the gate and evaluates trigger 2.

This bead is also the end-to-end script for the capability: it drives the real verb from the command line and
leaves a structured log.

## Scope

In: the conformance run that measures GATE-TRAC-11 at gate size; the re-run after at most one repair cycle and
the counts from which the second trigger of KILL-RESPONSE is read; the end-to-end script
`scripts/e2e/contact_response.sh`. This is the only end-to-end bead of `contact.response`: an earlier draft of
the same script under the name `traction_response.sh` (N18a-39) is superseded by this bead and its steps are
folded in here.

Out: the mechanism (BD-367 with its components N18b-39, N18b-40 and N18b-41); the pilot and the first reading
of the first trigger (N18a-25); applying the two triggers and writing the ADR (the decision bead N18a-26,
which depends on this bead).

## Technical approach

**The gate run.** `FROB_TEST_SEED=<s> cargo test -p frob-conformance --test g1_known_answers -- GATE-TRAC-11`
(the Gauntlet has no agent verb, ADR-GAUNT-01; the seed is recorded so that the repair re-run uses the same
one; the planted mutations run with `--features gauntlet-mutations`), which calls the verb as an agent would.
The measured values are recorded with `cargo run -p frob-conformance --example record_gate -- --gate
GATE-TRAC-11 --receipt <hash>`.

1. *Fixtures.* (a) Residual margin: single precision, H = 3, b = 1 → x̂ = 0.33333334, computed residual 0, true
   error 9.9·10⁻⁹, ρ = 2.4·10⁻⁷, bound 7.9·10⁻⁸. (b) Bound at equality: H = [[2, 1], [1, 2]], b = (3, 3),
   x̂ = (1.01, 0.99): residual norm 0.01414 equals the true error with λ_lo = 1; the mutation that divides by
   λ = 3 claims 0.00471 and must be caught. (c) Mode guard: a block with μ·N = 5 N anchored in stick; a 4 N
   tangential load is accepted, a 6 N load is rerouted and the full solve slides under a net 1 N. Also the flop
   arithmetic: 313,344 flops per full solve at n = 96; 20,054,016 for 64 columns; 1,474,560 with one factor;
   ratio 13.6.
2. *Battery sweep.* 10⁴ contact states sampled by address from the battery (stance, gait, turning, stairs,
   slope, low-friction patch, payload; wheeled and tracked classes with their own rows), each a converged step
   on `batch-cpu` in `f32`. For each state, 64 random columns b drawn by address: half as impulses at contact
   rows with magnitudes log-uniform between 10⁻³ and 10 times the row's current impulse, half as generalized
   impulses on actuated joints. Each column is solved by the response batch in `f32`, and independently by a
   full re-solve of the step in `f64` with b applied (the reference). For every **accepted** column: the true
   error ‖x̂ − x_ref‖₂ in the scaled variables is compared with the attached bound, and the reference's active
   set and stick labels are compared with the anchor's. Counts: accepted, rerouted, bound violations (must be
   0), false mode acceptances (must be 0). The rerouted share is reported per robot class.
3. *Anchor clause.* After advancing a world, a batch requested against the old anchor with refactoring
   disallowed is refused.

The reference solve's own error is controlled: it runs to a gradient norm 10⁻⁶ times the lockstep tolerance in
`f64`, and a column is counted as a bound violation only if the excess is larger than the reference's own
certified error.

**Second trigger of KILL-RESPONSE.** If the sweep finds a bound violation or a false mode acceptance, one
repair cycle is allowed: a bounded fix of the identified cause (for example the ρ formula, a guard predicate, a
mode-label mismatch between anchor and guards), then one re-run of the same sweep with the same seeds and
unchanged thresholds. If either count is still non-zero, trigger 2 is met and the fallback (full solves per
query) is recorded. The outcome, either way, is handed with the measured counts to the decision bead N18a-26,
which applies both triggers and writes the KILL-RESPONSE record; the gate's PASS is recorded only with both
counts at zero.

**If the kill gate fires.** `contact.response` remains a verb whose every column is a full solve (it reports
`method: full-solve`, every column has status `full-solve`, there is no factor reuse and the cost model
reports the full cost); anchors, acceptance and certificates are removed; consumers
(finite-difference design gradients at one state, the step-adjoint epic, counterfactual attribution) are
re-read against full solves, whose cost is the flop ratio above.

**End-to-end script.** `scripts/e2e/contact_response.sh [--long] [--self-test]`, plain shell, sourcing the
shared helper of the end-to-end harness; non-zero exit on failure; idempotent; `SEED` explicit. `--self-test`
runs the `fixtures` stage alone, with no simulation.

Stages 0 to 3 and 5 run scripts the mechanism beads own and passed when they landed, reading the `assert`,
`refusal` and `summary` lines of each log (a called script that exits 0 with a failed `assert` line fails the
stage), and contain no second copy of the called scripts' commands: the component scripts
(`response_anchor.sh` of N18b-39, `response_acceptance.sh` of N18b-40, `lambda_lo.sh` of N18b-41) and the
verb-level script `response_verb.sh` of BD-367 (stages `fixtures`, `anchor`, `columns`, `lambda`, `cli`,
`job`). What each stage stands for:

0. `fixtures`: `response_verb.sh --stage fixtures`: the 2 × 2 fixture (residual norm 0.01414, true error norm
   0.01414, λ_lo = 1, bound at least the true error); the rounding case in single precision (H = 3, b = 1:
   computed residual 0, ρ = 2.4·10⁻⁷, bound 7.9·10⁻⁸ at least the true error 9.9·10⁻⁹); the flop counts at
   n = 96 and 64 columns (313,344 per full solve, 1,474,560 for the batch, ratio 13.6), with the envelope
   printing the ceiling statement (ratio 1 against a baseline that also factors once).
1. `anchor`: `response_anchor.sh`, then `response_verb.sh --stage anchor`: a converged stance; `--describe`
   prints the anchor digest; a call by run, world and step returns an anchor identity and results; the same
   call with `--anchor <id>` is served; after the world advances, `--on-stale refuse` → exit 3 with the
   stale-anchor refusal naming the first differing component, whose code is the one N18-REF entered for the
   allocation ledger's row `response-batch-stale-anchor`, checked against `registries/refusals.toml` (the verb
   does not ship while that row has no registered number); `--on-stale refactor` → served under a new anchor.
2. `columns`: `response_acceptance.sh`, then `response_verb.sh --stage columns`: the block fixture with 4 N and
   6 N loads through the verb → `accepted` with slack 1 N·h and `rerouted` with the failed predicate; each
   accepted column prints bound, residual norm, ρ, λ_lo and its class.
3. `lambda`: `lambda_lo.sh`, then `response_verb.sh --stage lambda`; this script then asserts that the
   certificate hash the verb reported for an anchor equals the one `lambda_lo.sh` produced for the same state.
4. `sweep` (this script's own): for each robot class c of the battery, `frob eval run <reference design of c>
   --battery <the standard battery of c> --tier batch-cpu --profile lockstep --precision f32 --run-seed $SEED
   --key cr-sweep-<c> --json` (a battery is `eval.run`'s population input, not a `sim.run` option; `--run-seed`
   is its one seed spelling), whose runs supply the converged states sampled by address, then `frob contact
   response <run> --world <addr> --columns
   <seeded columns> --key cr-sweep-<state> --json` per state: 100 battery states × 64 columns by default, the
   gate's 10⁴ states with `--long` → zero bound violations, zero false mode acceptances, the rerouted share
   printed per class against the 50% threshold of the kill gate. The `--long` log is the one the gate record
   cites.
5. `job`: `response_verb.sh --stage job` (exit 8 with a handle, `job.wait`, cancellation and recovery by
   idempotency key; a batch cancelled mid-run reports no column as accepted without its bound and leaves no
   orphaned job), plus `frob job find` on the cancelled key to assert no orphan.
6. MCP parity for `contact_response`; determinism (identical anchor digests, accepted sets and result digests
   on repeat and across worker counts).
7. `negative-controls`: the plants of N18-CX's late entries, built by N18b-40, `N18b-40:trac-lambda` (λ = 3),
   `N18b-40:trac-mode` (the mode guard off: the sticking-slack test removed) and `N18b-40:trac-resid` (the bound
   without ρ), and N18b-39's test-only mutant `anchor-by-world-step`, each on the build `--features
   gauntlet-mutations,frob-contact/nc-<nnnn>` (numbers read from the control registry, never typed); stages 0,
   2, 0 and 1 respectively must fail under them, and a plant build under which its stage passes fails the
   script.

**Logging.** Newline-delimited JSON to `target/e2e-logs/contact_response/<utc-timestamp>.ndjson` with a
human-readable transcript beside it. Every line: `ts`, `script`, `bead` (`N18b-42`), `step`, `event` (`start`,
`cmd`, `assert`, `metric`, `refusal`, `end`), the exact command line, exit code, wall time, the envelope's
`evidence` block (claim, class, tier, determinism, identities, seed), measured values with thresholds (counts
of accepted and rerouted columns, bound violations against 0, false mode acceptances against 0, rerouted share
per class, per-column bound and true error), anchor identities, certificate hashes, digests, and on failure
the first violating column with world address, step, column index and the artifact paths. A final `summary`
line gives assertion counts and the gates touched (GATE-TRAC-11, KILL-RESPONSE). No private-scene data.

## Acceptance criteria

- [ ] GATE-TRAC-11 recorded with measured values: the three fixtures reproduce; the λ = 3 mutation is caught;
      on 10⁴ states × 64 columns, zero accepted columns exceed their bound and zero accepted columns have a
      different active set or stick label in the `f64` re-solve; the rerouted share is reported per robot
      class; a batch against a changed anchor is refused.
- [ ] The second trigger of KILL-RESPONSE is evaluated on those counts, with at most one recorded repair cycle
      on unchanged seeds and thresholds, and the outcome is added to the decision record.
- [ ] The script exists, sources the shared helper, passes on a clean checkout with `batch-cpu` only, and logs
      every stage with measured values and thresholds; exit codes 0, 3 and 8 are observed and 1 never is.
- [ ] Planted mutations fail the gate: the bound without ρ (`N18b-40:trac-resid`); division by a
      non-lower-bound eigenvalue (`N18b-40:trac-lambda`); a guard with the sticking-slack test removed
      (`N18b-40:trac-mode`); an anchor keyed by (world, step) only.
- [ ] If the kill gate fired, the verb reports `method: full-solve` with status `full-solve` on every column,
      and the script asserts that instead of the batch-specific fields.
- [ ] The GATE-TRAC-11 record cites the `--long` log by path and digest, and the rerouted share per robot
      class appears in both.
- [ ] Two runs give identical anchor digests and identical accepted sets.
- [ ] The stale-anchor refusal carries a registered code, and the rejection of a tampered certificate is
      demonstrated.

## Test plan

### Unit tests

In `crates/frob-conformance/tests/g1_known_answers.rs`: `gate_trac_11_fixtures`, `gate_trac_11_sweep` (reduced to 10² states
for fast runs, full size under the gate flag), `gate_trac_11_anchor`. `column_generator_by_address` checks that
columns are a function of (world address, step, column index) only. `reference_error_controlled` checks that
the `f64` reference's certified error is below 10⁻³ of the smallest attached bound in the sweep.
`e2e_log_schema_contact_response` validates the script's log against the line schema of the end-to-end
harness; `e2e_columns_seeded` reproduces the random columns from the printed seed. A harness-level self-test
makes a called script of stages 0 to 3 and 5 log a failed `assert` while exiting 0 and asserts that the stage
fails.

### End-to-end script and logging

As specified above: `scripts/e2e/contact_response.sh` driving the scripts of N18b-39, N18b-40, N18b-41 and
BD-367, and directly `frob sim run`, `frob contact response`, `frob job find` and `frob-mcp`.

### Known answers and negative controls

The four hand computations of the mechanism (residual margin; bound at equality; mode guard; flop count) and
the late known-answer row for the residual bound in single precision. Negative controls: the four planted
mutations. Determinism lanes: twice on one machine; worker counts 1, 8, 24; debug and release.

## Considerations

- Zero observed violations in 6.4·10⁵ columns bounds the violation rate near 5·10⁻⁶ at 95%; the record states
  the count so that zero is read as what it is.
- The rerouted share is a cost figure, not a correctness figure; it is the first trigger's quantity and is
  reported here again per class because the sweep measures it at scale.
- The gate has no row in the consolidated gate tables at the time of writing; its defining text above governs
  its threshold, and its milestone is M4.
