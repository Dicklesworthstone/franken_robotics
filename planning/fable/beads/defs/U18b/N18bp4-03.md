## Background

A kill gate is a decision named in advance, with its trigger, its milestone, the measurement that decides it, its
fallback, and what changes downstream. Each is recorded as an architecture decision record when decided, by a
bead of the unit that owns the mechanism (the rule of the fallback ledger N40-23, followed by N40-24).

The plan's pilot table gives granular media under legs a pilot and a fallback and names no kill gate. The gate
register carries one all the same: **KILL-GRANULAR**, entered by N40-24 through an `introduce` amendment, so that
the pilot (N18b-14) has a stop rule to name and the pilot register (N38a-09) can accept its record. As
registered:

| Field | Value |
|---|---|
| Trigger | The granular-media pilot's falsifier holds (error above 20% against the published curve at any of the at least five compared depths on either fixture), or the mechanism's force rows fail after one repair cycle |
| Decided at | M6, mode `pilot-before-funding`: due when WP-74 asks to fund N18b-15, and at the latest at the M6 exit |
| Measurement (`reads`) | The pilot record of N18b-14 in `crates/frob-conformance/registry/pilots.toml` (the sources with their reading marks, the per-depth errors on both fixtures, the potency control, the verdict); if the mechanism was funded, the force-row receipts of N18b-15 |
| Fallback | The soft-soil law with a card labelled `assumed` |
| Downstream if it fires | N18b-15 is closed with reason `fallback`; legs on loose ground use the soft-soil law with a card labelled `assumed`; the status table names the fallback |

The trigger has a clause read from the built mechanism, so this bead depends on N18b-15 and records the decision
once both clauses can be read; funding is read from the pilot record alone (`pilots fundable --bead N18b-15`,
N38a-09), the exception of N40-30's step 2, rule 7. Without this bead the row has no decider and the M6 exit finds
no owner declaration (`owner-declaration-missing`). Tier: Frontier [F].

## Scope

In: reading the pilot record and, if the mechanism was built, its force-row receipts; evaluating both clauses
exactly as registered; the decision record `docs/adr/ADR-KILL-GRANULAR-M6.md`; the row's `decision` entry and the
owner declaration; the status table. Out: the pilot (N18b-14); the mechanism and its repair cycle (N18b-15);
entering the row (N40-24).

## Technical approach

**Procedure.**
1. Read N18b-14's record: per fixture (plate drag, intrusion) and compared depth the model's force, the published
   value and the relative error; the sources' entries in `registries/sources.toml` with their reading marks; the
   potency control's outcome; the verdict (`falsifier-holds`, `falsifier-rejected` or `inconclusive`); the
   reviewer, the receipt and the `protocol_blake3`, which must equal the registered hash.
2. Clause 1, the falsifier holds, from the record alone: on either fixture some compared depth has an error above
   20%. A record with fewer than five compared depths on a fixture is not a result of the protocol and is refused
   as input; a record whose curves could not be read from a primary source is `inconclusive` and decides nothing.
   Check the recorded verdict against the evaluation; a
   disagreement stops the bead.
3. Clause 2, read only if N18b-15 was funded: its force rows failed on a run made after one repair cycle. N18b-15
   closes with reason `fallback` when its rows still fail after that cycle, citing both receipts; a first failure
   with no repair is not a reading of clause 2.
4. Name the outcome in N40-03's four: `fired` if clause 1 or clause 2 holds; `not-fired` if clause 1 fails and
   N18b-15 closed with its force rows passing; `not-reached` if WP-74 never asked to fund N18b-15, or the pilot is
   `inconclusive` at the M6 exit (an inconclusive pilot funds nothing); `deferred` only through an ADR naming the
   later exit and its reason (for an inconclusive pilot, the primary source that would make it decisive).
5. Write `docs/adr/ADR-KILL-GRANULAR-M6.md` with N40-03's fields: the kill gate; the milestone; the trigger as
   registered and the `introduce` amendment; each input with its receipt hash beside the clause it decides (the
   worst per-depth error against 20%, per fixture); the outcome and which clause decided; the fallback in force and
   the capability's name from now on ("granular media: soft-soil law, card `assumed`"); the beads re-read
   (N18b-15); the recording session, which neither ran the pilot nor implemented N18b-15.
6. Registry: the `decision` entry of the row in `registries/gates.toml` (N40-03's form) and the owner declaration
   (`[[gate]]`, `role = "owner"`, the ledger's current fields copied, `decision` with each measured value citing
   its receipt) in `frob-contact`'s `contract.toml`. On `fired` or `not-reached`, the status table row reads
   "granular media: fallback (KILL-GRANULAR)".

**Fail-closed default until decided.** No granular law exists in the release binary; loose ground under legs uses
the soft-soil law with a card labelled `assumed`.

**Who decides.** The Traction lead prepares the record; a fresh-context session that neither ran the pilot nor
implemented the mechanism reviews and records it.

## Test plan

### Unit tests
`crates/frob-conformance/tests/kill_gates.rs`:
- `kill_granular_record_complete`: trigger, inputs, outcome, date and session present; the ADR's path is
  `docs/adr/ADR-KILL-GRANULAR-M6.md`.
- `kill_granular_rule`: on synthetic records with five depths per fixture: worst errors 14% (drag) and 18%
  (intrusion), force rows passing → `not-fired`; one intrusion depth at 23% → `fired` by clause 1; an error of
  exactly 20% → not by clause 1 ("above"); four depths on one fixture → refused as input, naming the fixture; an
  `inconclusive` record (no primary source read) → `not-reached` at the exit; clause 1 failing and the force rows failing after the repair cycle → `fired` by clause 2; a force-row
  failure with no repair recorded → the rule refuses to read clause 2.

### End-to-end script and logging
`scripts/e2e/kill_granular.sh` (header `# e2e: bead=N18bp4-03 milestone=M6 labels=traction,kill-gate
gates=KILL-GRANULAR seed=0 needs=cpu plants=not-fired-with-error-above-20`) re-derives the outcome from the stored
records, compares it with the ADR and the gate row, and runs `cargo test -p frob-conformance --test kill_ledger`
(asserting no failure names KILL-GRANULAR) and `cargo test -p frob-conformance --test kill_gates --
kill_granular`. It exits non-zero on disagreement. It sources `scripts/e2e/lib.sh` (STD-E2E) and writes
`target/e2e-logs/kill_granular/<utc>.ndjson`; every line carries `ts`, `script`, `bead`, `step`, `event`, the
exact command line, exit code and wall time; it logs the record's digest, per fixture and depth the error against
20%, the force-row status, the derived and recorded outcomes, and a `summary` naming KILL-GRANULAR. It writes
nothing to the registry.

### Known answers and negative controls
The pilot's potency control (constant stress with no depth dependence) fails the drag fixture's quadratic growth;
the rule reads its recorded outcome and never reruns it. Negative control (plant `not-fired-with-error-above-20`):
an entry `not-fired` while the stored record shows a depth above 20% makes the script fail, and `kill_ledger`
reports `outcome-contradicts-measurement`.

## Considerations

- A published curve read from a summary or a secondary plot does not count (N18b-14); a pilot that could read no
  primary source is `inconclusive` and leaves the fallback in force.
- A positive decision covers only the depths, angles and media the pilot compared; N18b-15's validity ranges
  carry that limit.
