## Background

Habitat is the subsystem that owns every part of a simulated world that is not the robot. Its owner crate is
`frob-scene`, at layer 2 of the workspace (layers run 0 to 6; a crate may depend only on lower layers, or on an
earlier row of the same layer). It defines two formats: the scene pack `.fscene` (schema `frob.scene/1`) and the
clearance complex `.fclear` (schema `frob.clearance/1`). The format registry owns schema names; an older spelling
`frob.fscene/1` is not used.

This bead exists because thirteen verbs (the cluster `scene` of VERBS-scene: the chapter's eleven rows of the verb
table, `scene.list` and `scene.show` sharing one, and `scene.purge` of the safety chapter; the twelve handlers of
the chapter's verbs live here, while that of `scene.purge` lives in `frob-verbs`, over the store functions of
`frob-chronicle`, N37-19), ten kinds of object and six other subsystems meet in this crate, and without
a written boundary each neighbour will grow its own copy of scene logic. The boundary is:

- Habitat **owns**: static geometry as distance fields; analytic overlays for features smaller than a voxel;
  articulated fixtures, movable objects and moving surfaces; the assignment of a contact interface card and of an
  optical card to every surface region; optical volumes such as steam; the state of living matter in a world (films,
  sloshing payloads, cords, rugs); semantic labels, spawn regions, goals and route graphs; clearance complexes; the
  retrofit catalog; ingestion of real places; scene splits; and the world bank that keeps compiled scenes resident
  on a device.
- Habitat **does not own**: contact laws and cones (Traction, `frob-contact`); ray kernels and sensor models
  (Sensorium, `frob-sense`); task and requirement definitions (Arena); mission queries (Augur); adversarial search
  over scenes (Nemesis); calibration against measurement (Ground). It supplies the objects those subsystems read
  and the typed scene edits they apply.

Alternative rejected: letting each consumer parse the pack itself. Reason: the pack is content-addressed and one
reader must decide what a field means, otherwise two subsystems can disagree about the same `SceneId`.

Label convention inherited by every Habitat bead: default values (spacings, capacities, tile sizes) are DESIGN
choices with their reason; a worked example is a derivation from stated premises, not a measurement; every
dimension of a place is `assumed` until a cited norm or a measurement is recorded; thresholds in gate tables are
TARGETs; statements about sibling code or public sources are FACT with their source.

## Scope

In: the crate skeleton and module layout, its layer metadata, its feature flags, the typed read interface per
object, `CONTRACT.md`, the machine-readable `contract.toml`, `tests/conformance.rs`, and the tests that hold the
boundary. Out: the pack format and bricks (BD-162), the compiler
(BD-163 and N19a-10 to N19a-20), every mechanism behind the modules (their own beads), the verb roster (N19a-02),
the decision records (N19a-03).

## Technical approach

1. Create `crates/frob-scene/` with `[package.metadata.frob] layer = 2` and its rank inside layer 2. It may depend
   on `frob-core` (identities, hashing, evidence classes, refusals, `qty`), `frob-fsim` (the airlock to FrankenSim,
   layer 0), `frob-lie` and `frob-algebra` (layer 1). It links no crate above layer 2. Work that needs a higher
   service (a referee settle, a ray probe, a policy rerun) reaches it through a trait that `frob-scene` defines and
   a higher crate implements (the standing inversion rule of the workspace), or is driven by the verb executor in
   `frob-verbs`.
2. Module layout (DESIGN): `pack` (manifest, `SceneId`, canonical JSON), `field` (bricks, directory, CPU sampler),
   `overlay`, `maps` (interface, optical, semantic, unknown), `fixture`, `movable`, `living`, `compile` (the eleven
   stages), `accept`, `gen::terrain`, `gen::interior`, `hazard`, `clear`, `retrofit`, `ingest`, `split`, `bank`.
3. Feature flags: every Frontier [F] or Moonshot [M] mechanism in this mixed crate sits behind a named feature that
   is off by default (`frontier-clearance`, `frontier-retrofit`, `frontier-ingest`, `frontier-dressing`,
   `frontier-actors` (the kinematic actors of `scene.gen --actors`, N38a-33, M6, under KILL-DRESSING),
   `frontier-advected-film`, `frontier-slosh`, `frontier-proxies`, `moonshot-islands`, `moonshot-farfield`; names
   DESIGN). No default build enables one.
4. The object catalogue, one typed accessor per row (Rust names DESIGN; signatures fixed by the owning beads):

| Object | Type or format | Read by |
|---|---|---|
| Scene pack | `ScenePack`, manifest `.fscene`, identity `SceneId` | Every subsystem that touches a world |
| Distance bricks, brick pool, variant directory | Device buffers described by the manifest | Traction (narrow phase), Sensorium (ray kernels), clearance |
| Analytic overlays | Typed primitive list with a spatial index | The same consumers as the bricks |
| Interface map and optical map | Region table with two independent card references per region | Traction reads the interface card; Sensorium reads the optical card |
| Fixtures, movables, moving surfaces | Articulated models and rigid bodies compiled by Skeleton | Kinesis, Traction |
| Living-world state | Film patches and tiles, payload modules, cord and rug proxies | Traction (film friction), Kinesis (proxies), Sensorium (specular wet floors) |
| Clearance complex | `.fclear` | Atelier's maneuverability analysis, Augur, Nemesis, the retrofit search |
| Retrofit catalog | `registries/retrofits.toml`, typed scene edits with prices | Nemesis, Augur, `scene.retrofit` |
| Scene split | `SceneSplit` with group identifiers | Arena, Cortex, the qualification lane |
| World bank | Resident set of compiled packs with an admission ledger | Spark's placement planner |

5. `CONTRACT.md` with the ten sections every crate ships: purpose, inputs, outputs, invariants (INV-HAB-01 to -10,
   each with the bead that tests it), refusals (`FROB-REF-301` to `-317`), determinism class (the compiler and the
   exact analyses are D0 or D2 per backend; device fields inherit the class of their kernels), evidence class of
   outputs, validity domain, oracles, known gaps. No public signature above layer 1 takes a bare `f64` physical
   quantity; lengths, forces and angles are `frob_core::qty` types.
   Beside it, `crates/frob-scene/contract.toml` in the record schema that `check-contracts` validates (N34-08):
   `[crate]` name, `layer = 2`, its rank, `plane = "compute"`, `determinism` (the strongest class the crate claims:
   D0 for the CPU compiler and the exact analyses), `evidence` (`Tested`; `Certified` outputs are named per
   verb), `gates` (GATE-HAB-01 to -16 as they land), `refusals` (`FROB-REF-301` to `-317`, and the late Habitat rows
   once N19c-42 enters them, each under the number the allocation ledger assigned: the scene-family rows it
   proposes as 318, 319, 322, 324, 325 and 327 and those it files without a proposal, and the two integrity
   rows `scene-pack-identity-mismatch` and `scene-split-count-mismatch`, which are `9xx` rows with exit 9; and
   the five rows N19-REF enters under their ledger numbers, `hazard-registry-invalid`, `scan-profile-absent`,
   `asset-source-not-default-pipeline`, `scene-edit-invalid` and `import-articulation-interpenetrates`, all raised
   in this crate); `[budgets]` per verb as the owning beads fix them; `[safe_mode]`
   (`on_budget` refuses by name, never returns a partial pack marked complete); `[features]` one row per
   `frontier-*`/`moonshot-*` flag with its tier, its kill gate (KILL-FCLEAR, KILL-RETROFIT, KILL-INGEST,
   KILL-DRESSING, KILL-ADVECT, KILL-SLOSH, KILL-PROXY, KILL-LIVING, KILL-FARFIELD) and its pilot record. A
   `tests/conformance.rs` runs the crate's laws as they land (the invariant tests named in `CONTRACT.md`).
6. Library crates do not print; the crate emits no per-iteration JSON.

## Acceptance criteria

- [ ] `crates/frob-scene` exists with layer 2 metadata; `cargo xtask check-layers` passes, and a planted dependency
      on `frob-contact` fails it.
- [ ] `CONTRACT.md` has the ten sections and lists INV-HAB-01 to INV-HAB-10 and `FROB-REF-301` to `-317`;
      `contract.toml` names layer 2, every feature flag with its tier, kill gate and pilot; `cargo xtask
      check-contracts` passes, and a feature row without its kill gate fails it.
- [ ] `tests/conformance.rs` exists and runs under `cargo test -p frob-scene`.
- [ ] Every row of the object catalogue has a public typed accessor or a documented stub that returns the refusal
      "capability not implemented" (exit 5) until its bead lands; none returns a default value.
- [ ] `cargo build -p frob-scene` with default features compiles no `frontier-*` or `moonshot-*` code.
- [ ] No bare `f64` physical quantity in a public signature (the workspace lint passes).

## Test plan

### Unit tests

- `layer_is_two`: reads the crate manifest; asserts `layer = 2`.
- `upward_edge_is_rejected` (negative control): a fixture manifest that adds `frob-contact` as a dependency makes
  `check-layers` exit non-zero and name the edge.
- `contract_sections_complete`: parses `CONTRACT.md`; asserts the ten headings in order and that each of the ten
  invariant identifiers and seventeen refusal codes appears once.
- `catalogue_is_total`: a table-driven test enumerating the ten objects; each resolves to an accessor symbol.
- `default_features_are_solid_only`: `cargo metadata` shows no `frontier-*`/`moonshot-*` feature in the default set.
- `feature_rows_name_kill_gates`: every `frontier-*`/`moonshot-*` feature of the manifest has a `contract.toml`
  row with tier, kill gate and pilot; a scratch copy with the `frontier-dressing` row's `kill` removed makes
  `check-contracts` exit non-zero naming the row (negative control).
- `stub_refuses_not_defaults`: calling an accessor whose bead has not landed returns a typed refusal, never an
  empty object.

### End-to-end script and logging

`scripts/e2e/habitat_crate_boundary.sh` (sources the STD-E2E helper; log to
`target/e2e-logs/habitat_crate_boundary/<utc>.ndjson`): runs `cargo xtask check-layers`, `cargo xtask
check-contracts` and `frob --json doctor`; asserts exit codes; logs one `cmd` and one `assert` event per step with
the command line, exit code and wall time, and a `summary` line. No private-scene data is touched.

### Known answers and negative controls

No numeric known answer. Negative controls: the planted upward edge; a `CONTRACT.md` with one section removed must
fail `check-contracts`. Determinism: the checks are exact (D0) and run twice with identical output.

## Considerations

- The crate's scope cap is 28 thousand lines of Rust including tests (DESIGN); reaching 115% of it triggers a scope
  conversation, not a silent split.
- Risk: acceptance and compile stages need the referee and ray kernels, which live above layer 2. The inversion
  traits must be defined here early, or consumers will import upward.
- The three FrankenSim representation crates the compiler uses carry the toolchain risk tested at
  INT-TOOLCHAIN-01; `frob-scene` names none of their types directly.
