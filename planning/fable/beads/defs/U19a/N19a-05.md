## Background

A scene that cannot say where it came from cannot support a claim. Four later checks read facts that must be frozen
into the pack when it is made: the licence check at export (a pack that would export a research-only or private
asset is refused), the realism check (a report claiming a scene is representative of real buildings is refused
while the pack used any `assumed` dimension), the split check (a scene group never straddles a train and test
split), and the audit of randomization (what value was actually drawn). This bead defines the provenance block of
the manifest that holds those facts, and the code that fills it at compile and generation time.

Because the block is inside the manifest, it is inside the `SceneId`: provenance cannot be edited after the fact
without producing a different scene.

## Scope

In: the block's schema, how each field is produced, the counting rule for `dimensions_assumed`, and validation.
Out: the licence manifest behind the `licences` digest and its pack-time export check (N19b-02); the group rule that
fills `group` (N19c-11); enforcement that consumes the fields: the licence join and private-mark inheritance (BD-305), the
no-authorization flag type (owned by `frob-core`; exporting verbs in BD-303), the realism refusal (BD-227,
N19a-39), the split refusal (BD-235).

## Technical approach

Fields (DESIGN layout; the names in the manifest example are binding where shown). Placement follows the
manifest's field table, owned by BD-162: the `provenance` object holds `generator`, `licences`, `resolved`,
`dimensions_assumed`, `scale` and `private`; `group` and `authorization` are top-level manifest fields (as in the
manifest example, where `group` sits beside `seed`). This bead fills and validates all eight as the pack's
provenance facts; it does not move them.

| Field | Content | Produced by |
|---|---|---|
| `generator` | Generator name and version, for example `"frob-scene 0.3 kitchen"`; for an import, the importer name, version and source package identity | `scene.gen`, `scene.import`, `scene.compile` |
| `licences` | Digest of the licence manifest: one entry per asset with its licence class (`redistributable`, `attribution`, `research-only`, `proprietary`, `unknown`; `unknown` is treated as the most restrictive), its source and any restriction on redistribution | The compiler, from each asset's manifest entry; a procedural scene has the single entry "this project's" |
| `resolved` | Digest of the table of resolved values: every randomized quantity the generator drew, by name, with the value drawn, its unit, the distribution and the address of the draw; beside the draws, records with no value: a hazard row recorded `excluded` (BD-227's exclusion hook, set by N19a-38's `hazards.exclude`) or `not-represented` (a row whose only mechanism is not built, recorded by the archetype bindings N19a-31 to N19a-37 and by N19a-38), each with its row identifier | The generator; nothing is redrawn at load |
| `dimensions_assumed` | The count of distinct dimensions used by this pack whose provenance is `assumed` | Counted at generation (rule below) |
| `scale` | `generated` for a generated scene; for an ingested scene one of `relative-only`, `estimated`, `witnessed`, `surveyed` | Generator or importer |
| `group` | The group identifier used by splits: a base scene and everything derived from it share one (mirrored layouts, clutter variants, retrofit variants, variants sharing its brick pool, every scan of one building) | The generator for a base scene; inherited by every derivation |
| `private` | `true` for a pack built from a scan of a real place or derived from one; otherwise `false` | Importer; inherited as the join over lineage |
| `authorization` | The three no-authorization flags, each the constant `false`: `execution_authorized`, `hardware_safety_signoff`, `sim_to_real_certified` | The single-valued flag type of `frob-core` |

Counting rule for `dimensions_assumed`. Every dimension a generator draws comes from a registry row (a hazard row,
a fixture parameter, a grammar constraint, a route-graph transition) that carries a provenance field: `assumed`,
`norm: <citation>` or `measured: <dataset>`. The generator records, per draw, the row identifier and its
provenance. The count is the number of distinct row identifiers with provenance `assumed` among the draws that
contributed geometry, a card or a fixture parameter to this pack. A row used many times counts once. A dimension
fixed by the caller (an explicit parameter override) counts as `assumed` unless the caller supplies a provenance.
Only entries of the resolved-value table with a drawn or used value count: an `excluded` or `not-represented`
record is a record, not a draw, and never counts, whatever its row's provenance; the loader's recount applies the
same rule. The region label `hazard:<row identifier>` that ties a drawn hazard row to the region carrying it is
written by the archetype bindings (N19a-31 to N19a-37), not by this bead.

Derivation rules. A scene derived from another (a mirror, a clutter variant, a retrofit, a re-compile at another
spacing) keeps `group`, takes `private` and the licence set as the join over its inputs (neither can decrease along
a derivation), and extends `resolved` with the new draws; it never drops an entry.

Validation. `private: true` with an absent `scale` label is refused; a licence manifest with zero entries is
refused; `authorization` missing or not all `false` makes the pack foreign and unreadable (`FROB-REF-816`);
`dimensions_assumed` must equal a recount from `resolved` (the loader recounts). The first, second and fourth of
these are refused with `FROB-REF-303`, the pack reader's code for a pack that cannot be decoded as written (N19-REF
lists the triggers), with `pointer` naming the field and, for the recount, `observed` and `required` carrying the
two counts.

## Acceptance criteria

- [ ] Every compiled or generated pack carries the eight fields; a pack missing one fails to load.
- [ ] `dimensions_assumed` equals an independent recount from the resolved-value table on 1,000 generated scenes.
- [ ] A derived pack (the same terrain recompiled at another fine spacing; a mirror built through the library's
      derivation API) has a different `SceneId` and the same `group` as its base. The group rule for whole
      lineages, mirror canonical forms and buildings is N19c-11's (M3); this bead supplies the inheritance.
- [ ] A derived pack's licence set and private mark equal the joins of its inputs (property test over random
      derivation graphs).
- [ ] The resolved-value table reproduces the scene: regenerating from (family, parameters, seed) yields the same
      table and the same `SceneId`.
- [ ] `frob --json scene show <id>` prints the block; a private pack is shown only with the private scope.

## Test plan

### Unit tests

- `provenance_fields_complete`: the fixture pack exposes all eight fields.
- `assumed_count_is_distinct_rows`: a synthetic generator that uses hazard row `home.threshold` three times and
  `home.hallway` once reports `dimensions_assumed = 2`.
- `caller_override_counts_as_assumed`: an explicit `--param door_width=0.82` with no provenance adds one.
- `norm_row_not_counted`: a synthetic registry row with `norm: <test citation>` (labelled `synthetic`) adds zero.
- `records_not_counted`: a synthetic resolved-value table with `home.threshold` drawn and two further `assumed`
  rows recorded, one `excluded` and one `not-represented`, gives `dimensions_assumed = 1`, and the loader's recount
  agrees; a mutant recount that counts records gives 3 and the pack fails to load naming both counts.
- `recount_mismatch_refused` (negative control): a mutant generator that writes `dimensions_assumed: 0` with a
  non-empty assumed set (so the `SceneId` is consistent with the wrong count) produces a pack that fails to load,
  the error naming both counts.
- `mirror_keeps_group`: base and mirror share `group`, differ in `scene_id`.
- `join_is_monotone` (property test): over random derivation graphs the private mark and licence class never
  decrease.
- `flags_true_is_foreign`: a manifest with `execution_authorized: true` is refused with `FROB-REF-816`.

### End-to-end script and logging

`scripts/e2e/scene_provenance.sh` (sources the `STD-E2E` helper): `frob --json scene gen --family terrain/stairs
--difficulty 0.5 --seed 7 --key sp-1`, `frob --json scene show <id>`; asserts the eight fields in their manifest
places and `dimensions_assumed` equal to the count of `assumed` rows in the printed resolved table; regenerates with
the same seed under a new key (`--key sp-2`; a call that repeats a key would return the first call's stored receipt
and prove nothing) and asserts identical `scene_id` and `resolved` digest; regenerates with seed 8 (`--key sp-3`)
and asserts a different `scene_id`; then edits the stored manifest of the first pack in the run's own store (under
the state root `FROB_STATE` that `e2e_init` exports, never the user's store), setting `dimensions_assumed` to 0 and
leaving `scene_id` as written, and expects `frob --json scene show <id>` (the registry's form: `scene.show` takes a
`scene_id`, not a manifest path) to exit 9 with the integrity refusal `scene-pack-identity-mismatch` (row 4 of
N19c-42; an edited provenance block is an identity mismatch before it is a miscount). Every line carries the
charter fields (`ts`, `script`, `bead`, `step`,
`event`, exact command line, exit code, wall time, the envelope's `evidence` block); `assert` lines carry the
field name and value; the digests compared; on failure the first differing resolved entry and the seed. Final
`summary` with counts.

### Known answers and negative controls

Known answer: the counting example above (2). Negative controls: the edited count; a derivation that drops the
private mark must be rejected by the join property test. Determinism: the resolved table is identical on Linux and
macOS for the same seed (INV-HAB-10).

## Considerations

- Until cited norms are recorded (open question OPEN-HAB-1, owner: project lead), every generated interior has a
  non-zero count and realism claims are refused; validity is unaffected.
- Policy weights trained in a private scene inherit the mark by default (open question OPEN-SAFE-2); that is
  enforced by the lineage join, not here.
- Risk RISK-11 (asset licences restrict what can ship): the licence manifest is the mitigation and must be filled
  even for procedural scenes so that the join is total.
- The resolved table can be large for cluttered scenes; it is a blob addressed by digest, not inline.
