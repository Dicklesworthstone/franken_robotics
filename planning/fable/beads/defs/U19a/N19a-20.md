## Background

A scene's identity is how two machines agree they hold the same place without sending it to each other. Generated
scenes cross machines as seeds and identities, never as voxels: each machine compiles what it needs and checks the
`SceneId` (ADR-HAB-12; reason: the division of labour between the large-memory machine that holds the world bank
and the GPU cards that train, and the privacy rule for real places). That only works if the identity covers
everything that can change a result and nothing that legitimately differs between machines. This bead is the last
compiler stage, freeze: it defines exactly what is hashed, makes the pack immutable, collects the receipts each of
the ten earlier stages wrote, and scopes device resources.

Two invariants are held here. INV-HAB-01: a `ScenePack` is immutable; any change produces a new `SceneId`.
INV-HAB-10: the same family, parameters, seed and compiler version give the same `SceneId` on every supported
platform.

## Scope

In: what the compiler must have written into the manifest before the identity is taken (the composition), table
canonicalization, the freeze, the receipt chain in the acceptance report, device resource scoping, and the
determinism tests of the identity. Out: the manifest schema, the canonical JSON writer, the hashing rule of
`SceneId` and its check on every read (BD-162); the content of each receipt (its stage's bead);
the acceptance fixtures (BD-228); the brick pool's content addressing (BD-164); world-bank admission (BD-236).

## Technical approach

1. **What is hashed.** `SceneId` is defined by the manifest bead BD-162: the BLAKE3 hash (printed `b3:…`), under
   the domain string `frob.scene/1`, of the canonical bytes of the manifest with `scene_id` and `presentation`
   removed. This stage makes that body complete before the hash is taken. It must contain, as values or as blob
   hashes: the compiler version and settings (spacings, truncation, overlay capacity, import profile digest,
   settle rule, lattice steps, tolerances); units; brick contents (through the pool and directory digests);
   overlays; maps (interface, optical, semantic, unknown); fixture tables; movable tables with their settled
   poses; and the identity part of the acceptance report.
2. **What is not hashed.** Wall times, host names, the device that will load the pack, the visual GLB (it is
   referenced by its own digest and can be replaced without changing the identity; the deviation report then has
   to be recomputed), and any measurement that depends on the platform or backend. DESIGN: the acceptance report
   has two parts. The **identity part** holds verdicts and bounds computed by the CPU reference path in exact or
   reproducible arithmetic (brick bounds, registration verdicts, gauge verdicts on enclosures, feasibility tag);
   its digest is the manifest's `acceptance` field. The **measurement part** holds values measured on tiers and
   devices (ripple on each backend, silhouette overlap, timings) and is stored beside the pack, keyed by
   `SceneId` and hardware fingerprint. Without this split a report measured on Metal and one measured on CUDA
   would give one scene two identities.
3. **Canonicalization.** Tables are sorted by stable keys before hashing; floating-point values in the manifest are
   written in a canonical shortest round-trip form; set-like lists are sorted; no map iteration order reaches the
   bytes.
4. **Freeze.** After the hash is computed the pack directory is sealed: files are written to a temporary root,
   fsynced, renamed into `<store>/scenes/<scene_id>/`, and never modified. A second compile that yields the same
   identity finds the directory present and verifies it instead of rewriting it. An attempt to mutate a loaded
   `ScenePack` does not compile (no mutable accessors); a typed scene edit produces a new pack.
5. **Receipts.** Each stage 1 to 10 appends a receipt (stage number, name, inputs' digests, outputs' digests,
   counts, findings, refusals, wall time). The chain is stored in the acceptance report; each receipt's
   identity-relevant fields are in the identity part and its timings in the measurement part. `scene.compile`
   returns the receipts in its result.
6. **Device resources.** Device buffers (pool segments, directories, overlay tables, maps) are allocated by the
   worker that loads the pack and are scoped to its manifest: they are released when the pack is evicted, and a
   buffer is never shared between packs except through the content-addressed pool.
7. **Verification on load.** A worker that receives (family, parameters, seed) or a pack directory recomputes the
   identity and compares; a mismatch is an integrity fault, not a warning: the refusal
   `scene-pack-identity-mismatch` (exit 9, retry `never`; row 4 of N19c-42, a `9xx` row numbered by the allocation
   ledger and named here through the constant `frob_scene::refusal::late::IDENTITY_MISMATCH`).

## Acceptance criteria

- [ ] Flipping any single input (one brick sample, one overlay parameter, one card reference, one fixture
      parameter, one compile setting) changes the `SceneId`.
- [ ] Changing only wall time, host or the device that measures acceptance does not change it.
- [ ] Replacing the GLB changes the pack's visual reference and not the physics identity fields it should not
      touch (the field, overlays, maps digests are unchanged).
- [ ] The same (family, parameters, seed) gives the same `SceneId` on Linux and macOS for every fixture family.
- [ ] A sealed pack cannot be modified through any public interface; tampering with a file on disk is detected on
      load.
- [ ] `scene.compile` returns eleven receipts; a cancelled compile leaves no sealed directory.

## Test plan

### Unit tests

- `id_sensitivity_matrix`: a table-driven test with one mutation per hashed component; each changes the identity.
- `id_insensitivity`: wall time, host name and device label mutations leave it unchanged.
- `row_order_irrelevant`: permuting table rows before canonicalization leaves it unchanged.
- `float_canonical_form`: 0.1 + 0.2 and 0.30000000000000004 serialize identically; −0.0 is normalized as stated
  in the canonical-form rule.
- `tamper_detected`: one byte flipped in a brick blob; load fails with the integrity refusal `scene-pack-identity-mismatch` (exit 9), `blob` naming the reference and both hashes present.
- `no_mutable_accessor`: a compile-fail test.
- `second_compile_verifies`: compiling twice writes once and verifies once.
- `unhashed_setting_mutant` (negative control): a build that omits the overlay capacity from the hash fails
  `id_sensitivity_matrix`.
- `measurement_part_excluded`: two acceptance measurement parts with different ripple values share one identity.

### End-to-end script and logging

`scripts/e2e/scene_identity.sh` (sources the `STD-E2E` helper): `frob --json scene gen --family terrain/stairs
--difficulty 0.5 --seed 11` (the generator verb of BD-165) twice on one machine, in debug and release, and with
compile worker counts 1 and 16 (`--workers 1`, `--workers 16`); compares `scene_id`; `frob --json scene compile
fixtures/scenes/analytic-set.src` and `fixtures/scenes/closed-mesh.glb` the same way; every one of these calls
carries its own idempotency key (`--key sid-<fixture>-<lane>`), because a repeated key returns the stored receipt
of the first call and two runs under one key would compare a pack with itself; then reads
`fixtures/identity/expected_ids.json` (identities recorded on the other platform for every fixture family) and
compares; `frob --json scene show <id> --receipts` asserts eleven receipts in order with timings only in the
measurement part; then compiles the same source with `--overlay-capacity 12` under a new key (a different
`scene_id`); last, flips one byte of a brick blob of the first sealed pack inside the run's own store (under the
state root `FROB_STATE` that `e2e_init` exports, never the user's store; last, because the pool is content
addressed and a later compile could meet the altered blob) and runs `frob --json scene show <id>` on that pack
(the registry's form: `scene.show` takes a `scene_id`, not a directory), expecting exit 9, the integrity refusal
`scene-pack-identity-mismatch` with `stated`, `recomputed` and the blob named. Every line carries the
charter fields (`ts`, `script`, `bead`, `step`, `event`, exact command line, exit code, wall time, the envelope's
`evidence` block); the identities compared with platform, compiler version and build profile; the refusal block
of the tamper step; on failure the first differing component digest (manifest, bricks, overlays, maps, fixtures,
report) and the two pack paths. Final `summary` with counts.

### Known answers and negative controls

KA-464 (identity across platforms; the same family, parameters, seed and compiler version give the same `SceneId`
on Linux and macOS). Negative control: the unhashed-setting mutant. Determinism lanes: twice on one machine;
across worker counts of the compile job; debug and release; Linux and macOS.

## Considerations

- Anything floating-point that enters the identity must be reproducible across platforms: constructive-solid
  evaluation and brick sampling use the deterministic elementary functions; settled poses are rounded to a grid
  (N19a-18). The first cross-platform mismatch is expected to come from one of these, and the script's
  per-component digest is there to localize it.
- The compiler version is in the identity, so a compiler upgrade invalidates cached packs; world-bank eviction and
  recompute cost account for that.
- Private real places never cross machines unless exported with an explicit flag; their identity is still computed
  so that derived artifacts can cite it.
