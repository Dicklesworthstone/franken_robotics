## Background

Generated interiors use dimensions (door widths, threshold heights, closer torques) chosen to make scenes valid.
Validity needs no source; a claim that a scene is representative of real buildings does. The decision
(ADR-HAB-11) is that every dimension a generator draws carries provenance, and its provenance is `assumed` until a
cited norm or a measurement is recorded. Today every one of the 59 hazard rows is `assumed`: no building code,
workplace regulation or product standard has been read for them, and none is cited.

Two mechanisms follow. First, a pack counts the `assumed` dimensions it used (`dimensions_assumed` in the
manifest), and a report that claims a scene is representative of real buildings is refused while that count is
non-zero. Second, there must be exactly one controlled way for a row to stop being `assumed`: a row's provenance
changes to `norm: <citation>` or `measured: <dataset>` only when the source is recorded in the source register.
The count and the refusal are the hazard-registry seed bead's done-condition (BD-227); this bead builds the
promotion path and the report-side check, so that nobody can "fix" a refused report by editing a string.

The pre-mortem names the failure this guards: "interiors were toy boxes and results did not transfer to real
places", watched through the share of dimensions labelled `assumed`.

## Scope

In: the provenance value grammar, the source-register check, the promotion procedure and its record, the effect of
a promotion on scene identities, the realism-claim check that reports call, and the `--strict-data` behaviour.
Out: the registry schema, the count and the verb (BD-227); the provenance block of the manifest (N19a-05); report
rendering (BD-302); finding and reading the norms, which is the owner decision OPEN-HAB-1.

## Technical approach

1. **Provenance grammar.** `assumed` | `norm: <source-id> [<clause>]` | `measured: <dataset-id>`. `<source-id>` is
   an identifier in the source register (`registries/sources.toml`), which records for each source its title,
   publisher, edition or date, where it was read, the date it was read and a digest or location of the copy read.
   `<dataset-id>` is the identity of a dataset admitted through the ground-data admission path.
2. **Load check.** The hazard registry loader resolves every `norm:` and `measured:` reference; an unresolved
   reference is a load error. A source whose register entry lacks a read date is not usable ("to be re-read
   before a gate cites it" is enforced as: no read date, no promotion).
3. **Promotion procedure.** A promotion is a registry change with a record: the row identifier, the old range and
   distribution, the new range and distribution as stated by the source, the source reference and clause, who
   made the change and when. The new values come from the source, never from the old range relabelled: a
   promotion whose record shows an unchanged range must state that the source confirms it.
4. **Effect on identities.** The registry version is part of the generator version and therefore of every
   `SceneId`. Promoting a row changes the scenes generated afterward; packs generated earlier keep their count and
   their identity. No pack's `dimensions_assumed` is ever edited after the fact.
5. **Mixed scenes.** A pack's count is the number of distinct `assumed` rows among its draws (rule in the
   provenance-block bead). A scene whose doors are from a norm and whose thresholds are assumed has a non-zero
   count and remains refused for realism claims.
6. **The realism-claim check.** A report or verb that asserts representativeness of real buildings (a field
   `claims_realism: true` on a report request, or the wording of a Reality-flavoured statement about places)
   calls `frob_scene::realism_check(scenes)`. If any cited scene has `dimensions_assumed > 0`, the result is
   `FROB-REF-312` "A realism claim cites a scene with `assumed` dimensions". Ranked repairs: record a norm or a
   measurement; drop the claim. Exit 3. The refusal lists the scenes and, per scene, the assumed row identifiers.
7. **Strict data.** Under `--strict-data` a verb that would return a verdict depending on an `assumed` dimension
   says so in its findings; this bead supplies the per-scene list of assumed rows that the flag reads.
8. **Reports without the claim.** A report that makes no realism claim is not refused; it prints the count
   ("23 dimensions assumed") beside every scene it cites.

## Acceptance criteria

- [ ] A registry row with `norm: <id>` loads only when `<id>` is in the source register with a read date; an
      unknown or undated source is a load error.
- [ ] A report request with a realism claim over a scene with a non-zero count is refused with `FROB-REF-312`
      listing the assumed rows; the same request without the claim succeeds and prints the count.
- [ ] After a (synthetic, test-only) promotion of every row an archetype uses, a newly generated scene has count
      zero and the realism claim is admitted; a previously generated pack still has its old count.
- [ ] Editing a pack's manifest to set the count to zero is detected (the recount on load fails).
- [ ] Every promotion has a record with old and new ranges and the source reference.
- [ ] The repository at M3 contains no `norm:` or `measured:` provenance without a register entry (lint).

## Test plan

### Unit tests

- `provenance_grammar_parses`: the three forms; a malformed form is rejected.
- `norm_requires_register_entry`; `norm_requires_read_date`.
- `realism_claim_refused_312`: scene with count 23; refusal lists 23 row identifiers; exit 3.
- `no_claim_no_refusal`: the same scene, no claim; success; output shows "23 dimensions assumed".
- `promotion_record_required`: a registry diff with a provenance change and no record fails the lint.
- `relabel_without_source_mutant` (negative control): a row changed from `assumed` to `norm: fake` with no
  register entry fails the load.
- `old_packs_keep_count`: generate, promote (synthetic), regenerate: old pack count unchanged, new pack count
  lower, identities differ.
- `mixed_scene_still_refused`: one assumed row left gives count 1 and a refusal.
- `count_edit_detected`.

### End-to-end script and logging

`scripts/e2e/scene_realism_claim.sh`: `frob --json scene gen --family home --seed 3`; `frob --json report run
<run> --claims-realism` expecting exit 3 with code 312; the same without the flag expecting exit 0 or 2 and the
count in the output; then, against a test registry overlay in which the home rows carry a `synthetic` source
(clearly labelled, never shipped), regenerate and expect the claim to pass. Logs commands, exit codes, the
`refusal` block with the assumed rows, the counts, and a `summary`.

### Known answers and negative controls

Known answer: at plan time 59 hazards in seven archetypes, every one `assumed`, so every generated interior has a
non-zero count. Negative controls: the relabel mutant; the edited count. Determinism: checks are exact (class D0).

## Considerations

- Open question OPEN-HAB-1: which published building and workplace norms supply the dimension distributions.
  Default: generic ranges labelled `assumed`, and realism claims refused. Owner: project lead. It blocks the
  interior gate for claims of realism, not for validity. The companion question on retrofit prices and legality
  (OPEN-HAB-4) is handled the same way: prices `assumed`, constraints marked unchecked in every report, no claim
  about cost in a published report.
- Norms differ by country and building type; a promotion records which norm, so two registries for two
  jurisdictions are two registry versions, not one row with a wider range.
- A norm states what is permitted, not what is common; using a norm as a distribution is itself an assumption and
  the record must say which reading was taken.
- The synthetic source used by tests must be impossible to ship: the release lint rejects any register entry
  labelled `synthetic`.
