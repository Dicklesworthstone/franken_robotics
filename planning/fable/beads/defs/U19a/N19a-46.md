## Background

Habitat (crate `frob-scene`, workspace layer 2) owns every part of a world that is not the robot. Its verb table
gives `scene.import` two first milestones: M3 for **assets** and M5 for **real places**, and one result for both: "a
pack with a loss report, a scale label and an unknown mask". The real-place lane (a walkthrough or drone
reconstruction of a home, registered by four landmarks, private by default) is Frontier work at M5 and is built on
top of an importer that must already exist. This bead is that importer: the asset lane, tier Solid, at M3.

An **asset** here is one object or one furnished fragment made outside the project: a scanned household object, a
kitchen fixture, a shelf unit from an external generator, or a file a user supplies from a research collection. The
compiler driver already turns source geometry into a **scene pack** (the compiled, immutable form of a place, with
manifest `.fscene` and identity `SceneId`) through eleven stages with receipts. What the driver does not do is decide
what an outside file may be trusted for. Importing adds four things the driver alone does not give:

1. a named **import profile** (`asset-default` unless the caller names another) and an explicit source declaration,
   so that the limits are those of a recorded profile and the licence class is chosen by the caller and recorded,
   never defaulted;
2. a **loss report**: everything the import dropped, converted, repaired or assumed, so that the pack can say what it
   is not;
3. a **licence entry** that travels with the pack (risk RISK-11: asset licences restrict what can ship);
4. honest physical properties: interface and optical cards are `assumed` unless the caller supplies measured cards;
   nothing is estimated from textures.

Who needs it. Asset-populated interiors (M5) admit every asset "through the import path"; the real-place lane (M5)
"adds the real-place lane on that pipeline"; agents use it at M3 to bring one object into a fixture scene. Rejected
alternatives: letting generators read raw asset files (bypasses decode limits, licence entries and the deviation
check); one importer written at M5 for both lanes (the M3 row of the verb table would have no implementation, and the
real-place work would start by building this); material estimation from appearance (a glossy tile can be grippy and a
matte one slick: an appearance model would fabricate a physical property and the pack would cite it).

## Scope

In: the asset lane of the verb `scene.import` (kind `run`); the request and result schemas; the pipeline that calls
the compiler stages for one asset; what import adds (source declaration, cards marked `assumed`, movable or static
classification, the scale declaration record, unknown regions from explicit repair); the loss report schema
`frob.scene.import.loss/1` and its asset rows; the licence entry written through the licence manifest; refusals;
job behaviour; the end-to-end script.

Out: the compiler driver and its stages (BD-163, N19a-10 to N19a-13, N19a-16, N19a-17, N19a-18); the licence
manifest type, the asset-source register, the default-pipeline filter and the export check `FROB-REF-310` (N19b-02);
the collision-to-visual deviation measure and `FROB-REF-317` (N19a-23); the region table and card references
(BD-229); scene acceptance (BD-228), which the caller runs on the result; the real-place lane, with registration,
adapters, the unknown mask's consumers and scale labels by authority (BD-398, N19c-02, N19c-03, N19c-04, N19a-21);
the per-asset catalogue and the population of interiors (BD-399); the private root and `scene.purge` (BD-305,
which this bead depends on so that the research-only lane is tested against a real root);
fuzzing of the decoder with hostile inputs (BD-307); the registry row of the verb (VERBS-scene, the only bead
that enters rows of the cluster; this bead is named there as the extension that gives the row its `asset` form)
and Habitat's handler map behind it (N19a-02); the values of each source's register row and the
source-specific import profiles (NEG-17 to NEG-27, which use the inputs defined here).

## Technical approach

**1. Verb.** `scene.import --kind asset` (kind `run`; long tool with `sync_wait_ms`, idempotency key and budget;
capability scope `scene:import`; a call without `--key` is `FROB-REF-805`, exit 3). Example: `frob --json scene
import --kind asset assets/in/mug.glb --source frob-scene --profile asset-default --behaviour free --key imp-1`
(a repository-authored `synthetic` file is declared with the source key `frob-scene`, the only default-pipeline
row at M3; the three permissive third-party rows become default-pipeline rows only after their admission
reading at M5, so an example that names `google-scanned-objects` is refused by the filter until then; this is the
example of VERBS-scene's row). The schemas carry the names the registry row fixes by rule: input
`frob.scene.import.in/1`, output `frob.scene.import.out/1` (an earlier text of this bead called them
`…request/1` and `…result/1`, which no registry row names). Inputs (DESIGN spellings):

| Input | Flag | Meaning |
|---|---|---|
| `kind` | `--kind asset\|place` | Required. `asset` is this lane; `place` is the M5 lane and answers `FROB-REF-724` ("not implemented in this build"), exit 5, until BD-398 lands; no value, or another value, is `FROB-REF-802` |
| `path` | positional | The file or directory, inside the caller's permitted roots (outside them: `FROB-REF-734`); a foreign-file parameter, so every file its reader opens is sniffed first (`FROB-REF-828`) |
| `source` | `--source <key>` | Required. A key of the asset-source register, or the literal `user-supplied` for a file that comes from no registered source |
| `user_supplied` | `--user-supplied` | The caller states that they hold the file themselves under the source's terms. Required for every row with `default_pipeline = false`, and implied by `--source user-supplied`; without it such a row is refused by N19b-02's default-pipeline filter with the worded refusal `asset-source-not-default-pipeline` (exit 3, nothing written; raised behind N19b-02's constant `ASSET_SOURCE_NOT_DEFAULT`, whose code this bead, its tests and its script assert, never a literal) |
| `licence_ack` | `--licence-ack <file>` | The caller's copy of the terms or their acceptance statement; hashed into the licence entry, never copied into the pack or a log. Required with `--user-supplied` when the row's class is `research-only` or `proprietary` |
| `licence_class` | `--licence-class <class>` | The class the caller declares for `--source user-supplied`; absent means `unknown`. Given with a registered row it can make the entry more restrictive than that row and never less (N19b-02's rule: naming a row accepts the project's reading of that source) |
| `object_licence`, `object_origin`, `attribution` | `--object-licence <SPDX id or "unknown">`, `--object-origin <URL>`, `--attribution <text>` | For a row whose class is `per-object` (NEG-26): the object's own stated licence and origin, and the attribution text an attribution licence needs; the class is resolved from the stated licence by that row bead's table |
| `profile` | `--profile <name>` | Import profile, a named record of `registries/import-profiles.toml` (N19a-10): `asset-default` here, the default when none is named; the row beads add `scene-collection` (NEG-22), `scan-store` (NEG-23), `articulated-object` (NEG-24) and `generic` (NEG-25) at M3, and `populated-interior` (NEG-18), `small-rigid` (NEG-19), `kitchen-fixture` and `kitchen-layout` (NEG-20) at M5; another name is `FROB-REF-802`. The scan profile `hm3d-scan` (NEGp1-52) is the `place` form's |
| `behaviour` | `--behaviour static\|articulated\|free\|prescribed` | Required for anything that can move |
| `unit` | `--unit <unit>` | Only when the format declares none |
| `scale` | `--scale <factor>` or `--target-dimension <axis>=<length>` | For a source whose objects are normalized (NEG-24): the caller's declared size, recorded with the scale declaration as `user-declared`; a normalized object without it is refused |
| `measured_cards` | `--card <region>=<card>` (repeatable) | Optional measured cards |
| `repair` | `--repair none\|fill` | Default `none`; `fill` requests the explicit repair pipeline (BD-163's values for the same stage-4 pipeline, which `scene.compile` uses; an earlier text spelled it `explicit`) |

A flag that a row does not use is refused when given for it (`--object-licence` on a row that is not
`per-object`, `--licence-class` that would weaken a row's class): `FROB-REF-802`, naming the flag and the row.
Output: `scene_id`, the manifest summary, the stage receipts, the loss report, the licence entry, the acceptance
status (`incomplete` until `scene.accept` has run), the evidence block. Exit 0; 2 when the pack was written with
findings (assumed cards, repaired holes, parts tagged `optical-only`); 8 when still running.

**2. Pipeline, as numbered steps (`frob_scene::ingest::import_asset`).**
1. Check the source declaration against the asset-source register: in default mode only rows with
   `default_pipeline = true` are accepted; a user-supplied import needs `--user-supplied` beside the source it names
   and is classed by N19b-02's rule: for a registered row, the more restrictive of the row's class and the class
   declared; for `--source user-supplied`, the class declared, or `unknown` when nothing is declared. A research-only or unknown-class asset is
   imported only into the private root; until that root exists the import is refused (fail-closed).
2. Decode under the import profile's limits (bytes, nesting depth, polygon, texture and material counts); relative
   references must resolve inside the asset directory (`FROB-REF-303`).
3. Build the metric transform graph and bake scales; check winding against the determinant (`FROB-REF-302` when the
   transform class is not established). Record the unit the format declares and the conversion applied. A format
   with no unit and no `unit` in the request is refused, not guessed.
4. Tag parts (support, keep-out, movable, jointed, optical-only, transparent, deformable-by-proxy, unknown). A part
   that can move and has no declared behaviour is refused (`FROB-REF-315`).
5. Check watertightness and orientation; a failing collidable part refuses the import (`FROB-REF-301`) unless
   `--repair fill` is requested, in which case each closed hole is recorded and its neighbourhood becomes an
   unknown region of the pack.
6. Static parts go through brick and overlay emission; movable parts are compiled as rigid bodies with fitted
   collision primitives and a recorded fitting error (the model-compiler path of the fixture stage); no settle is
   run for a single asset.
7. Cards. A region with a measured card supplied in the request gets it with provenance `measured`. Every other
   region gets an interface card and an optical card of class `assumed` (the generic catalog's interval for the
   declared material class, or the widest interval when none is declared), and the pack counts them. No region is
   left without an optical card (`FROB-REF-316` is never answered by a silent `diffuse`).
8. Measure the collision-to-visual deviation of every collidable region; above the pack threshold with no waiver the
   import is refused (`FROB-REF-317`; repairs: correct the collision model, tag the part `optical-only`, waive with a
   reason).
9. Write the licence entry (asset content hash, source key, licence, class, redistribution, notice, date read) into
   the pack's licence manifest, and the loss report into the pack; freeze. The pack's `group` is its own; a pack
   placed into a scene later takes that scene's group.

**3. The loss report** (`frob.scene.import.loss/1`; canonical JSON; part of the pack and of its identity). Rows, each
with a count and, where it applies, an area or a list of part names: elements dropped or not representable
(animations, skins, lights, cameras, unsupported extensions); unit and axis conversions; parts with no collision
counterpart (tagged `optical-only`); holes repaired, with receipts; regions with `assumed` cards (count and area);
movable parts with their fitting error; articulation supplied or not per jointed part; the unknown fraction of the
bounding volume; the scale declaration (unit, who declared it: the format or the caller). The real-place lane adds
its own rows (landmarks and residuals, transform class, the scale record) to the same schema without changing these.
A profile's validation rows also go into this report: the schema admits, beside the per-part articulation row,
one `joint_sweep` row per jointed part written by a profile that sweeps its joints (`articulated-object` of
NEG-24 and `kitchen-fixture` of NEG-20), with the fields `part`, `joint`, `range` (lower and upper limit),
`step` (at most 1° or 5 mm), `min_clearance` (metres) and `result` (`passed`; a sweep that fails refuses the
import with `import-articulation-interpenetrates`, naming the part and the joint value, and writes no pack), so
that the import envelope carries every sweep; the `asset-default` profile writes none, and the schema test
accepts both.

**4. Scale and unknown, for an asset.** An asset's size is a declaration by its source, not a measurement of a real
object: its dimensions count as `assumed` in the pack's provenance, and no metric claim about the real object
follows from the pack. When scale labels by authority exist (M5) the declaration record maps to the label those
rules give a scale with no witness. Unknown regions arise only from explicit repair at M3; the mask's treatment by
each consumer arrives with the real-place lane.

**5. Evidence and classes.** Geometry: Known answer against the source mesh at the recorded brick bounds, class
`Tested`. Pack bytes and the loss report are D0. Every envelope carries the claim product and the three
no-authorization flags, all `false`. Imported strings (node names, material names) are echoed only under the
untrusted-text mark.

**6. Layout.** `crates/frob-scene/src/ingest/{asset.rs, loss.rs}` (the real-place lane adds its files beside them);
verb handler `crates/frob-verbs/src/scene/import.rs`.

## Acceptance criteria

- [ ] `frob --json scene import --kind asset` is reachable through the CLI and `frob-mcp` with the schemas above; `--kind place` answers "not implemented" with exit 5 until its lane lands.
- [ ] A redistributable synthetic asset imports to a pack with stage receipts, a loss report with every row present (zero counts included) and one licence entry; the pack's `SceneId` is the same on Linux and macOS and under 1 and 16 workers.
- [ ] Every region of an imported pack has an interface card and an optical card; regions without a supplied measured card are `assumed` and counted; swapping the asset's textures changes no card and no physics digest.
- [ ] Each refusal is raised on its fixture with ranked repairs and exit 3: 301 (open mesh), 302 (winding against determinant), 303 (over-limit file; reference outside the directory), 315 (movable with no behaviour), 317 (deviation above threshold); applying the first repair makes the same request succeed.
- [ ] A file with no unit and no declared unit is refused; with `unit` declared the loss report records who declared it.
- [ ] In default mode a source that is not a default-pipeline row is refused; a user-supplied research-only asset needs `--user-supplied` and `--licence-ack`, is written only under the private root (or refused when none is configured) with the acknowledgement's hash in its licence entry, and exporting its pack is refused with `FROB-REF-310`.
- [ ] Every input of the table in step 1 is in the input schema `frob.scene.import.in/1` and in the help-schema snapshot; a declared licence class can make an entry more restrictive than its register row and never less; the per-object and scale inputs are refused on rows that do not use them.
- [ ] Explicit repair records each closed hole and the pack's unknown fraction is non-zero; without `--repair fill` the same file is refused.
- [ ] Cancellation during any stage leaves no partial pack and no temporary blob; a repeated request with the same idempotency key returns the same `scene_id`.
- [ ] `crates/frob-scene/CONTRACT.md` describes the asset lane, the loss report schema and what an imported pack may not be cited for.

## Test plan

### Unit tests
`crates/frob-scene/tests/import_asset.rs`; real compiler and airlock; assets labelled `synthetic`.
- `mug_imports_with_loss_report`: a closed synthetic mug (one handle, two materials): pack written; loss rows all present; `assumed` regions = 2; licence entry class `redistributable`.
- `textures_do_not_move_cards`: the same geometry with a glossy and a matte texture gives identical interface and optical cards and identical brick digests.
- `unit_required`: an OBJ-style file with no unit → refused; with `unit = mm` the bounding box is 1,000 times smaller in metres and the loss report shows `unit: mm, declared_by: caller`.
- `open_mesh_refused_then_repaired`: an open bowl → 301; with `--repair fill` one hole receipt and a non-empty unknown region.
- `movable_needs_behaviour`: a movable part with no behaviour → 315; with `behaviour = free` a rigid body with a recorded fitting error.
- `deviation_gate`: a collision hull 30 mm larger than the visual → 317; tagged `optical-only` the import succeeds and the part is listed in the loss report.
- `default_mode_filter`: source `test-research` (a `synthetic` research-only row of a test register; the real rows are entered by their own beads, which depend on this one) in default mode refused; with `--user-supplied` and `--licence-ack` written under the private root with `redistribution = Forbidden` and the hash of the acknowledgement in the entry; with `--user-supplied` and no `--licence-ack`, `FROB-REF-802`.
- `user_supplied_inputs`: `--source user-supplied` with no `--licence-class` gives class `unknown`; with `--licence-class attribution` and no notice text the entry is treated as `unknown` at export (N19b-02); `--licence-class redistributable` on a row whose class is `research-only` is refused (a declaration cannot weaken a row); `--object-licence` on a row that is not `per-object` is refused; a `synthetic` normalized object without `--scale` or `--target-dimension` is refused, and with `--scale 0.4` the loss report records the scale as `user-declared`.
- `schema_names_follow_the_registry`: the handler's schemas are `frob.scene.import.in/1` and `frob.scene.import.out/1`; a call without `--key` is 805 and without `--kind` 802.
- `idempotent_by_key`, `cancel_leaves_nothing`, `id_stable_across_workers`.
- `loss_schema_admits_joint_sweep`: a loss report holding one `joint_sweep` row (a `synthetic` hinged part: range
  0 to 90°, step 1°, minimum clearance 0.004 m, `passed`) validates against `frob.scene.import.loss/1` beside its
  articulation row, the mug's report with no such row validates too, and a row of an unknown kind fails.
- `appearance_estimator_mutant` (negative control): a build that sets friction from albedo must fail `textures_do_not_move_cards`.

### Known answers and negative controls
- Known answer: a unit cube of side 0.10 m declared in millimetres imports with a bounding box of 0.10 m per side and a field that is exact to the brick bound at 10⁴ surface samples.
- Negative controls: the appearance-estimator mutant; an importer that writes `diffuse` for a region with no card (the assumed count then disagrees with the region count); an importer that resolves a reference outside the asset directory (the path-escape fixture must be refused with 303).
- Metamorphic: rotating the asset by 90° about the vertical before import permutes bricks and changes no card, count or loss row; renaming nodes changes no digest.
- Determinism lanes: twice on one machine; 1 and 16 workers; debug and release; Linux and macOS (class D0 for pack bytes).

## Considerations

- Scanned assets are rarely watertight. Explicit repair makes the neighbourhood of every filled hole unknown, which is acceptable for clutter and not for a floor; the loss report's unknown fraction is what a consumer reads.
- Security: an asset is hostile input. Decode limits, the path check and the untrusted-text mark are enforced here from the first version; the fuzz corpus and its campaign are the importer-hardening bead's. External generators run offline, outside the workspace; only their output files are imported and no interpreter is embedded.
- Licence classes are facts about declared inputs, not legal opinions; a user who declares a wrong class owns that declaration, and the report says "licence as declared".
- The asset lane makes no claim of realism: every dimension of an imported asset counts as `assumed`.
- Performance envelope: none is stated in the plan; receipts record wall time per stage so that one can be set. Memory is bounded by the import profile.
- What would make us revisit: the real-place lane needing a different loss-report schema (it should extend this one), or the population step needing batched import of thousands of assets (then a batch form of the same pipeline, not a second importer).
