## Background

Habitat is the subsystem that owns every part of a world that is not the robot. Its crate is `frob-scene` (layer 2 of the
workspace; it may link only layers 0 to 2). A **scene pack** (`ScenePack`) is the compiled, immutable form of one place:
distance bricks, analytic overlays, an interface map, an optical map, semantic labels, fixtures, movables, moving surfaces,
living-world declarations, spawn regions and route graphs, an acceptance report and provenance. Every other subsystem that
touches a world reads a pack. This bead defines the pack's on-disk identity: the `.fscene` manifest (format identifier
`FMT-FSCENE`, schema `frob.scene/1`), its canonical bytes, the content identity `SceneId`, and the rule that a numeric
field with a stated range is refused when a value falls outside it and is never silently clipped. It is Solid tier and is
the first Habitat bead of M2: the scene compiler, the brick pool, terrain generators and the field kernels all build on it.

Decisions that govern the format, with their reasons and the alternatives rejected:

- **ADR-HAB-01.** Static geometry is a truncated signed-distance field in bricks, sampled by manual trilinear interpolation
  written in kernel source. A distance field answers "how far, and which way" in constant time for any point, which is what
  thousands of worlds need. Rejected: hardware texture filtering, whose fixed-point weights differ between vendors and break
  the determinism classes; and one 16-bit quantization over the whole scene (counterexample CX-188: 16 bits over ±10 m
  resolve 20 m / 65,536 ≈ 0.31 mm, a force step of about 30 N at a contact stiffness of 10⁵ N/m; over ±8 cm the step is
  about 2.4 µm and the ripple about 0.12 N per contact sample).
- **ADR-HAB-04.** The visual mesh (GLB) is read by the viewer only. Physics, sensors and stills read the collision field.
  A presentation asset can therefore be replaced without changing a digest, so it must stay outside `SceneId`.
- **ADR-HAB-12.** Generated scenes cross machines as seeds and identities, never as voxels: each machine compiles what it
  needs and checks the `SceneId`. Private real places do not cross at all without an explicit export flag.
- **ADR-WS-03** (format registry). Every artifact format has one identifier, one schema name with a major version, one owner
  crate and one canonical encoding; everything else is a view. The owner crate holds the schema, the canonicalization rule,
  the reference reader and the version refusal, and no other crate parses the bytes. The schema name is `frob.scene/1`
  (some chapter prose wrote `frob.fscene/1`; the format registry owns schema names).
- **INV-HAB-01.** A `ScenePack` is immutable; any change produces a new `SceneId`.
- **INV-HAB-10.** The same family, parameters, seed and compiler version give the same `SceneId` on every supported platform.

## Technical approach

**1. A pack on disk (DESIGN).** One canonical JSON manifest, `manifest.fscene`, plus derived blobs addressed by BLAKE3 hash
in the content store (bricks pool, directory, coarse lattice, heightfield, overlay list and overlay index, region table,
the four maps, fixture and movable tables, route graphs, the acceptance report, the licence manifest, and the GLB). The
manifest is canonical; cooked bricks and meshes are derived blobs. A manifest never embeds a path of the machine that wrote it.

**2. Fields.** Every field is required unless marked optional; an unknown field is refused.

| Field | Type | In identity | Meaning |
|---|---|---|---|
| `schema` | string | yes | Exactly `frob.scene/1` |
| `scene_id` | `b3:` hash | no (it is the result) | Checked against a recomputation on every read |
| `family`, `seed`, `group` | string, hex string, string | yes | Generator family, seed (hex, never a JSON number above 2⁵³), split group identifier. For a pack that `scene.compile` builds from a source no generator produced (DESIGN, so that the three required members are never left to the implementer): `family` is `authored` for a constructive-solid document and `imported/<format>` for an asset, `seed` is `0x0`, and `group` is the group the source declares or, if it declares none, `src:` followed by the BLAKE3 hash of the source bytes under the domain `frob.group/1` (every pack has a group; the keys of generated scenes and of buildings are N19c-11's) |
| `frame` | string | yes | Exactly `right-handed, z up, metres` |
| `compiler` | object | yes | `frob-scene` version, compile settings, units, tolerances |
| `field.fine_m`, `field.coarse_m` | number | yes | Fine spacing s (default 0.02) and coarse spacing S = 8·s (default 0.16) |
| `field.truncation_m`, `field.bits` | number, 16 | yes | The stated range ±T of stored fine distances (default T = 4·s = 0.08) |
| `field.coarse_truncation_m` | number | yes | The stated range of 16-bit coarse samples (DESIGN default 5.12, see Considerations) |
| `field.pool`, `field.directory`, `field.coarse` | hashes | yes | Brick pool, per-variant directory, coarse lattice |
| `field.band_bricks`, `field.bound_m` | integer, number | yes | Count of band bricks; the largest recorded per-brick error bound |
| `field.heightfield` | object, optional | yes | Hash, spacing and stated z-range of an open-terrain heightfield |
| `overlays`, `regions`, `fixtures`, `movables`, `optical_volumes` | objects | yes | Count and blob hash of each table |
| `maps` | array | yes | Subset of `interface`, `optical`, `semantic`, `unknown`, each with its hash |
| `living` | array | yes | Living-world declarations (kind, tier, region, parameters); semantics in N19b-03 |
| `spawn`, `goals`, `task_regions`, `route_graphs` | objects | yes | Hashes |
| `feasibility` | object | yes | `footprint`, `tag` (`witnessed`, `impossible: intended`, `impossible: incidental`, `unresolved`, or `not-computed` while the clearance stage that writes the tag has not run, which is every pack before BD-234 lands at M3), `fclear` hash (absent exactly when the tag is `not-computed`) |
| `ingest` | object, optional | yes | Scale label (`relative-only`, `estimated`, `witnessed`, `surveyed`), registration residual, per-region confidence hash |
| `provenance` | object | yes | `generator`, `licences` hash, `scale` (`generated` or a scale label), `dimensions_assumed`, `private`, resolved randomized values hash |
| `authorization` | object | yes | The three no-authorization flags, all `false`: `execution_authorized`, `hardware_safety_signoff`, `sim_to_real_certified` |
| `acceptance` | hash | yes | The identity part of the acceptance report (reproducible verdicts and bounds, no timings), as BD-228 and N19a-20 define it; the per-tier measurement part is stored beside the pack, outside the identity |
| `presentation` | object, optional | **no** | The GLB hash and thumbnails, read by the viewer only (ADR-HAB-04) |

**3. Types (DESIGN sketch).**

```rust
pub struct SceneId(Blake3);                       // identity type from frob-core
pub struct BlobRef { hash: Blake3, bytes: u64 }   // never a path
pub struct Ranged<Q> { value: Q, lo: Q, hi: Q }   // constructor returns Err(OutOfStatedRange) and never clamps
pub struct FieldSpec { fine: Length, coarse: Length, truncation: Length, coarse_truncation: Length, bits: u8,
                       pool: BlobRef, directory: BlobRef, coarse_lattice: BlobRef, band_bricks: u64, bound: Length }
pub struct SceneManifest { /* the fields of the table, typed with frob_core::qty quantities */ }
pub struct ScenePack { manifest: SceneManifest, id: SceneId /* blobs are opened lazily by hash */ }
```

**4. Canonical bytes and identity.** Canonical JSON is produced by the project's own writer from the typed value: members
sorted by code point, no insignificant whitespace, integers as JSON integers up to 2⁵³ and as strings above, no NaN or
infinity, and every floating-point field that bears identity written as the shortest decimal that round-trips the `f64`
(the one number rule of this format; produced by the project's writer, never by a library formatter). `SceneId` is the
BLAKE3 hash, under the domain string `frob.scene/1`, of the canonical bytes of the manifest with `scene_id` and
`presentation` removed. Because that body contains the hash of every blob physics and sensors read, plus compiler version,
settings, units and tolerances, `SceneId` covers manifest, brick contents, overlays, maps and fixture tables.

**5. The ranged-field rule (the seed's done-condition).** Every quantized or bounded numeric field states its range in the
manifest: fine distances ±`truncation_m`; coarse samples ±`coarse_truncation_m`; heightfield z-range; latents such as
wetness in [0, 1]; film thickness within the film model's validity; region identifiers below the region count; pool slots
below the pool size; palette selectors below the palette length. The writer refuses a value outside its stated range with
`pointer`, `observed`, `required` and `unit`, and writes nothing. Truncation of the distance field is not clipping by the
format: it is a named, recorded operation of the compiler (clamp(φ, −T, +T) with T in the manifest), and the sampler of
N19b-01 reports saturation so that no consumer reads a clamped value as a distance. The reader applies the same checks to
blobs and refuses a code outside the declared range.

**6. Reader admission order.** (a) Validate raw bytes before any map is built: a member name repeated after escape decoding
is refused before any digest is computed, as `FROB-REF-891` with `observed` of `duplicate-member:<name>` (the format
registry's mapping for an owner that has no code of its own for a duplicate field). (b) Schema name and major version:
unknown major version or unknown required field is `FROB-REF-891` (`format-version-unsupported`); there is no best-effort
parse. (c) Required fields and types: a required member that is missing, or a value of the wrong JSON type, is
`FROB-REF-303` with `pointer` naming the member and `observed` of `missing-member` or the type found (DESIGN: 303 is this
reader's one code for "the pack cannot be decoded as written", the same choice as step (e); the registry row in N19-REF
lists these triggers); the three authorization flags are the exception: a flag that is missing or not the literal `false`
is `FROB-REF-816` (`authorization-flags-missing-or-not-false`), the code every artifact reader of this system uses for
it. (d) Every blob reference resolves and its size is within the import profile's decode limits, else `FROB-REF-303`
(repairs: raise the limit in the import profile; supply the asset). (e) Range checks of step 5, also `FROB-REF-303` with
the field named. (f) Recompute `SceneId` and compare with `scene_id`; a mismatch is an integrity fault raised through
`frob-core`: the refusal `scene-pack-identity-mismatch` (family `9xx`, exit 9, retry `never`; its row is entered by
N19c-42 with the number the allocation ledger assigns, and this reader names it only through the constant
`frob_scene::refusal::late::IDENTITY_MISMATCH`; an earlier text proposed `FROB-REF-323`, which the exit rule of the
registry does not admit, because a `3xx` code exits 3). A view offered
where an identity is required is `FROB-REF-892`; a `.fscene` that reaches a verb without passing this reader is
`FROB-REF-893`. Refusals 3xx and 8xx named here exit with code 3.

**7. Migration.** Adding an optional field keeps the major version. A migration is a typed edit that produces a new artifact
linking the old identity; the old `SceneId` stays valid for citing old evidence.

**8. Classes.** Determinism D0: bytes and hashes are exact. An identity names bytes and carries no verdict.

## Acceptance criteria

- [ ] `registries/formats.toml` has the `FMT-FSCENE` row (`.fscene`, `frob.scene/1`, owner `frob-scene`); `schemas/` regenerates it unchanged.
- [ ] 10,000 seeded round trips canonical → value → canonical give zero byte differences.
- [ ] A numeric value outside its stated range is refused, not clipped, by the writer and by the reader (seed done-condition).
- [ ] Every one of 10,000 single-byte mutations of a fixture manifest either fails to parse or changes the identity.
- [ ] `{"b":1,"a":2}`-style key reorderings of one manifest have one `SceneId`; swapping the GLB leaves `SceneId` unchanged; flipping one byte of any identity-bearing blob changes it (INV-HAB-01).
- [ ] The same typed manifest yields byte-identical canonical output and `SceneId` on Linux and macOS, in debug and release.
- [ ] Unknown major version and unknown required field return `FROB-REF-891`; a duplicate member is refused before any digest is computed (`FROB-REF-891`, `observed` `duplicate-member:<name>`); a missing required member or a wrong type returns `FROB-REF-303` naming the member; a missing or `true` authorization flag returns `FROB-REF-816`; a recomputed identity that differs exits 9 with the `scene-pack-identity-mismatch` refusal.
- [ ] `crates/frob-scene/CONTRACT.md` exists with its ten sections and names D0 for this format.
- [ ] A fuzz target for the reader exists and runs in CI without panics (10⁵ executions in the commit lane; the 10⁷-execution clause of GATE-WS-02 for this format is measured before the M2 release by N34p1-01, and the thirteen-format record at M5 is BD-410's).

## Test plan

### Unit tests
`crates/frob-scene/tests/manifest.rs`, run with `cargo test -p frob-scene manifest`; real reader and writer, fixtures labelled `synthetic`.
- `roundtrip_seeded_10k`: 10,000 manifests generated from seeds; canonical bytes equal after value round trip.
- `key_order_one_identity`: two member orders, one `SceneId`.
- `duplicate_member_refused`: `{"seed":"0x1","seed":"0x2"}` (also with an escaped spelling of the name) is refused with `FROB-REF-891` and `observed` `duplicate-member:seed`, before any digest is computed.
- `missing_member_and_wrong_type_303`: a manifest without `frame`, and one whose `field.bits` is the string `"16"`, each return `FROB-REF-303` with the pointer of the member and `observed` `missing-member` or `string`.
- `out_of_range_refused_not_clipped`: a fine distance of 0.0801 m with T = 0.08 handed to the writer returns `OutOfStatedRange` with observed 0.0801 and required [−0.08, 0.08]; no file is produced and no value 0.08 appears.
- `latent_and_index_ranges`: wetness 1.2, region identifier equal to the region count, pool slot equal to the pool size: each refused with `FROB-REF-303`.
- `unknown_major_and_unknown_required_891`; `view_is_not_identity_892`; `owner_bypass_893`.
- `glb_swap_keeps_id`, `blob_byte_flip_changes_id`, `scene_id_mismatch_is_integrity_fault` (a manifest whose `scene_id` was edited: exit 9, the `scene-pack-identity-mismatch` refusal with `stated` and `recomputed` both present).
- `numbers`: 2⁵³ + 1 travels as a string; NaN and infinity cannot be written; `0.1` round-trips as `0.1`.
- `authorization_flags_required_false`: a manifest with a missing or `true` flag is refused with `FROB-REF-816`.

### End-to-end script and logging
`scripts/e2e/fscene_roundtrip.sh` (sources the STD-E2E helper; NDJSON to `target/e2e-logs/fscene_roundtrip/<utc>.ndjson` plus a transcript). Steps: `frob schema frob.scene/1 --json` (schema present, digest logged); this bead's own format tests, run by name (`cargo test -p frob-scene --test manifest -- roundtrip_seeded_10k key_order_one_identity duplicate_member_refused missing_member_and_wrong_type_303 out_of_range_refused_not_clipped unknown_major_and_unknown_required_891`: the round-trip, key-order, duplicate-member, missing-member, out-of-range and version cases, one `assert` line per test with its expected refusal code; there is no `frob conformance` command, and the gate clauses of GATE-WS-02 for `FMT-FSCENE` are run by N34p1-01 through `scripts/e2e/format_registry.sh --formats fscene`); then `frob scene compile <synthetic box room> --key fsr-1 --json` (a run verb carries its idempotency key) followed by `frob scene show <id> --json` twice, asserting identical `scene_id` and envelope digests, and `frob scene show <planted SceneId> --json` on a planted pack (a copy of the compiled pack in the run's store with one ranged manifest value outside its stated range, a region identifier equal to the region count, and its `scene_id` recomputed so that only the range check fails; the verb takes a `<scene_id>`, not a file) asserting exit 3 with `FROB-REF-303` and the field named. The verbs `scene.compile` and `scene.show` are BD-163's, which depends on this bead: until BD-163 is closed these three steps are logged with `e2e_skip "needs BD-163"` (an `assert` with `status: "skip"`, never counted as a pass), and BD-163's acceptance requires this script to run them and pass. Each line logs `ts`, `script`, `bead`, `step`, `event`, the command, exit code, wall time, the envelope's evidence block, digests compared, and on failure the first differing byte offset and the fixture path. The summary line counts assertions and names no gate (this bead measures none).

### Known answers and negative controls
- Format known answers: one identity for reordered keys; hash-the-file-as-written is a counterexample (key order and whitespace would make two scenes).
- CX-188 and KA-427 (stated range): step 0.16 m / 65,535 ≈ 2.44 µm over ±8 cm against 0.31 mm over ±10 m; asserted in N19b-01 and cited here as the reason `truncation_m` is identity-bearing.
- Negative controls registered: a reader built with key-order canonicalization disabled must fail `roundtrip_seeded_10k`; a writer build that clamps instead of refusing must fail `out_of_range_refused_not_clipped`; a build that includes `presentation` in the identity must fail `glb_swap_keeps_id`.
- Determinism lanes: twice on one machine; debug and release; Linux and macOS; each must give identical bytes (D0).

## Considerations

- **OPEN-HAB-3** (default spacings 2 cm and 16 cm with T = 8 cm against 1 cm interiors; owner Habitat lead; decided with measured memory and the fidelity ledger at M3; default as stated). Spacings and truncation are manifest values, so the decision needs no schema change.
- **OPEN-HAB-2** (whether bricks carry a one-sample apron, which removes neighbour lookups and costs (9/8)³ − 1 = 42% more memory; owner Spark lead; decided by the M2 profile; default no apron). DESIGN: the brick layout version lives in `compiler` settings, so an apron is a new setting, not a new schema.
- `coarse_truncation_m` is a DESIGN completion: the plan states 16-bit coarse samples but not their range. The default 5.12 m (32 coarse cells, step about 0.16 mm) is to be confirmed with the ray kernels (BD-187) and the pool (BD-164).
- The acceptance report must have a canonical form without wall-clock fields, or `SceneId` would differ between machines; timings belong in a receipts sidecar outside the identity.
- JSON library features unify across the build graph (`preserve_order`, `arbitrary_precision`), which is why no canonical byte may come from a library map or number.
- Privacy: a private pack lives under the private root outside the repository; logs of the e2e script carry digests, never scene content.
