## Background

A scene can contain assets made by other people: scanned objects, kitchen fixtures, whole interiors from an external
generator, or a research dataset a user supplies. What may be shipped depends on each asset's licence, and one
research-only object inside a pack makes the whole pack unshippable. RISK-11 states the exposure ("asset licences restrict
what can ship"; likelihood medium; signal: a pack whose licence join is not redistributable; owner Habitat lead) and its
mitigation: procedural generators first, licence manifests enforced at pack time, and GATE-SAFE-05.

The policy (DESIGN, with the licences as FACT from a research pass dated 2026-11-21, to be re-checked at admission):

- **Only permissively licensed assets enter the default pipeline**: the fully procedural generators of `frob-scene`;
  Infinigen Indoors (BSD-3) as an offline external generator; Google Scanned Objects (CC-BY 4.0) for household clutter;
  RoboCasa (code MIT, assets CC BY 4.0) for kitchen fixtures and layouts.
- **Research-only collections are supported as user-supplied imports and are never redistributed**: HM3D (academic,
  non-commercial), HSSD (CC BY-NC 4.0), PartNet-Mobility (non-commercial research terms), BEHAVIOR-1K (its own agreement;
  not used, import only).
- **Not used by default or reference only**: Objaverse-XL (licence per object); ProcTHOR (code Apache-2.0, dataset licence
  not verified: generator reference only); RoboBenchMart, MarketGen and the Isaac Sim 6.2.0 Warehouse Creator (licences
  not read: prior art only). An asset whose licence was not read is marked so and stays outside the default pipeline.
- **The starter pack ships only synthetic and redistributable fixtures.**

The reason for enforcing this in the pack format and not in a style guide: a licence that travels with the bytes cannot be
forgotten when a scene variant, a replay or a report is derived from the pack. Rejected alternative: a project-level list
of "allowed datasets" checked by review, which says nothing about a pack once it has been copied.

This bead is Habitat's half. Section 37 of the plan owns the general rule (licence classes, the join over any derivation
graph, the export refusal `FROB-REF-733`, the private mark and `scene.purge`), carried by BD-305. Asset-populated interiors
themselves arrive at M5 (BD-399); this bead makes the manifest and the refusal exist first, at M3, when `scene.import`
first admits assets.

## Scope

In: the per-pack licence manifest (the blob behind `provenance.licences` in `.fscene`); the asset-source register with the
rows above; the admission re-check; the default-pipeline filter; the pack-time export check that raises `FROB-REF-310`;
propagation of entries to derived scene variants; the starter-pack check.

Out: the lineage join for non-scene artifacts, `FROB-REF-733`, the private root, the path jail and `scene.purge` (BD-305);
importing one asset through the compiler, which writes its entry through this manifest (verb `scene.import`, asset lane,
N19a-46); the per-asset catalogue and the population of interiors (BD-399); the provenance block that holds the manifest's
digest (N19a-05); importer limits and fuzzing (BD-307).

## Technical approach

**1. Licence classes** (the five of the safety chapter, ordered from least to most restrictive for the join):
`redistributable` < `attribution` < `research-only` < `proprietary` < `unknown`. `unknown` is treated as the most
restrictive. The class of a set is the maximum of its members.

**2. The licence manifest (DESIGN).** Canonical JSON, schema `frob.scene.licences/1`, hashed into `SceneId` through the
manifest. One entry per asset contained in the pack:

```rust
pub struct LicenceEntry {
    asset: AssetId,                 // content hash of the asset as imported
    source: SourceKey,              // key into the asset-source register, or "user-supplied"
    licence: String,                // e.g. "BSD-3-Clause", "CC-BY-4.0", "CC-BY-NC-4.0"
    class: LicenceClass,
    redistribution: Redistribution, // Allowed | AllowedWithNotice | Forbidden | NotRead
    notice: Option<String>,         // attribution text carried into exported reports
    read_on: Date, admission: Option<AdmissionId>,
}
pub struct LicenceManifest { entries: Vec<LicenceEntry>, class: LicenceClass /* the join, recomputed on read */ }
```

Procedural content has one entry with source `frob-scene` and class `redistributable`. The entry travels with every pack
that contains the asset: a scene variant derived from a base (a clutter variant, a retrofit variant, a mirrored layout)
copies the base's entries and adds its own.

**3. The asset-source register.** `assets/licences/sources.toml` (DESIGN location; the repository keeps licence manifests
under `assets/`), one row per source: key, licence, class, `default_pipeline` (true only for the four permissive sources
and the project's own generators), `redistribute` (`never` for the research-only collections), `read` (false for sources
whose licence text was not read), source-register citation, and the date read. A registry loader refuses an unknown key.

**4. Admission re-check.** Before a source's first use at a milestone, its licence text is re-read from the primary source
and the row's date and digest of the text are updated in the dependency-admission record. A row with `read = false` or a
date older than the admission of the consuming milestone cannot be used by a generator in the default pipeline; a
user-supplied import of it is still possible and is classed by what the user declares, with `unknown` when nothing is declared.

**5. Default-pipeline filter.** Generators and `scene.import` in default mode draw only from rows with
`default_pipeline = true`. A user-supplied import requires an explicit flag naming the source, and its entries are written
with `redistribution = Forbidden` when the source is research-only.

**6. The pack-time export check.** `ScenePack::export_check(&self, target: ExportTarget) -> Result<Notices, Refusal>`:
1. Recompute the join of the entries; a stored `class` that differs from the recomputation is refused as a corrupt manifest.
2. If the pack is marked `private`, or any entry is `research-only`, `proprietary`, `unknown` or `NotRead`, refuse with
   `FROB-REF-310` ("a pack or report would export a research-only or private asset"), naming each offending asset, its
   source and class. Ranked repairs: remove the asset; keep the pack local. Exit code 3.
3. Otherwise return the attribution notices to be embedded in the export.
Every verb that writes a pack, or a report quoting pack content, outside the local store calls this check first. The
general artifact-level refusal `FROB-REF-733` (BD-305) applies to everything derived from the pack.

**7. Starter pack.** A check, run in CI and by `check-contracts`, that every fixture under the starter pack has a licence
manifest whose join is `redistributable` or `attribution` and whose entries are procedural (`synthetic`) or from a
`default_pipeline` source.

**8. Classes.** D0 (set arithmetic on declared data). The licence class is a fact about declared inputs, not a legal
opinion; reports say "licence as declared".

## Acceptance criteria

- [ ] Every compiled pack carries a licence manifest; a pack with no manifest is refused by the reader of BD-162.
- [ ] The register holds the rows of the policy above, with the four permissive sources and the project generators as the only `default_pipeline` rows.
- [ ] A pack containing one research-only asset is refused at export with `FROB-REF-310`, names the asset, and exports once the asset is removed.
- [ ] A private pack is refused at export with `FROB-REF-310` regardless of its licences.
- [ ] `unknown` and not-read sources are treated as most restrictive; a default-mode generator cannot draw from them.
- [ ] A derived variant carries every entry of its base (property test over random derivation chains).
- [ ] The starter-pack check passes and fails when a planted research-only fixture is added.
- [ ] Exports of `attribution` assets embed the notices.

## Test plan

### Unit tests
`crates/frob-scene/tests/licence.rs`, `cargo test -p frob-scene licence`; real manifests; stand-in assets labelled `synthetic`.
- `join_is_max`: {redistributable, attribution} → attribution; adding research-only → research-only; adding unknown → unknown.
- `export_refused_310_names_asset`: three assets, one `CC-BY-NC-4.0` research-only: refusal lists exactly that asset.
- `private_refused_310`.
- `notices_embedded`: two CC-BY assets yield two notices in the export.
- `default_pipeline_filter`: a generator configured with an HM3D-keyed asset in default mode is refused; with the user-supplied flag the entry is written `Forbidden`.
- `not_read_is_outside_default`: a row with `read = false` cannot be drawn.
- `variant_inherits_entries`: 1,000 random chains of derived variants; the entry set of each descendant is a superset of its ancestors'.
- `stored_class_must_match_recompute`: a manifest whose stored class is weaker than its entries is refused.
- `starter_pack_only_redistributable`.

### End-to-end script and logging
`scripts/e2e/scene_licences.sh` (STD-E2E helper; NDJSON under `target/e2e-logs/scene_licences/`). Steps: compile a synthetic room with two procedural props and one stand-in asset declared research-only; `frob scene show <id> --json` (asserts the manifest lists three entries and class `research-only`); `frob artifact export <id> --to <tmp> --json` (asserts exit 3, refusal code `FROB-REF-310`, the asset named, repairs present); recompile without the asset and export again (exit 0, notices array present). Each line logs the command, exit code, wall time, the evidence block, the refusal code with its pointer, digests of the manifests, and on failure the first differing entry. No asset content is logged.

### Known answers and negative controls
- KA-832: over random derivation graphs the licence set equals the join of the inputs and a research-only asset cannot enter an exported report or pack (exact; the graph-wide form is GATE-SAFE-05, measured by BD-305; this bead supplies the scene-pack rows).
- KA-827: a private, research-only scene, a replay of it and a still of the replay are private and research-only at every step (exact; BD-305).
- Negative controls: a build whose export check reads the stored class without recomputing must fail `stored_class_must_match_recompute`; a build that treats `unknown` as permissive must fail `join_is_max`.
- Determinism: results are set arithmetic; twice on one machine and across platforms give identical refusals.

## Considerations

- OPEN-SAFE-2 (whether policy weights trained in a private or research-only scene inherit its mark and licence set; default: they inherit both; owner: project owner) is decided outside this bead; the manifest type must be reusable for policy artifacts.
- The licences in the register are FACT from a dated reading and are re-checked at admission; a changed upstream licence is a register change with a new date, never an edit in place of history.
- Legal judgement is out of scope: the tool enforces declared classes and refuses on doubt.
- The research-only import path must not write asset bytes into any shared cache; storage under the private root is BD-305's.
- What would make us revisit: a need to ship a populated demo scene, which would require an `attribution`-only populated archetype built from the permissive sources.
