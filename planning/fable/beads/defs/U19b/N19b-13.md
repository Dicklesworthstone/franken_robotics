## Background

A carried liquid is modelled by the standard equivalent mechanical model: a rigid mass fixed in the container plus, for
each retained mode n, a mass m_n on a spring k_n = m_n·ω_n² and a damper, sliding horizontally at a fixed height. For a
rectangular container of length L along the motion filled to depth h the antisymmetric modes have
ω_n² = ((2n − 1)·π·g / L)·tanh((2n − 1)·π·h / L), n = 1, 2, 3 (FACT: linear sloshing theory, to be re-read from a primary
source before a gate cites it). The model is a payload module with prismatic sprung masses, which are ordinary joints and
passive elements, so it runs on every tier and inside every determinism class. Owner: `frob-scene` supplies the payload
module; the model compiler lowers it. Tier Frontier, feature `frontier-slosh`, child of the epic BD-414, funded only if
the pilot N19b-12 passes. Outputs are `Estimated`; the modal frequency is a Known answer.

Why this and not a fluid: one cubic metre of lattice fluid at 5 mm costs 1.22 GB and thousands of sub-steps per simulated
second (N19b-04). Why not rigid ballast alone: ballast has no resonance, and the first mode of an everyday container
(1.43 Hz for L = 0.30 m, h = 0.10 m) sits in the step-frequency band of walking robots. Rigid ballast remains the Solid
alternative and the KILL-SLOSH fallback.

## Scope

In: the slosh fields of the payload card; admission on the CPU; the module (bodies, joints, springs, dampers) handed to
the model compiler; per-world fill variation; the small-amplitude validity flag; telemetry channels; substitution by rigid
ballast on builds without the feature; the `slosh-tip` monitor and the switch of its failure-class row to `available`
(N24a-38); wave 4 of GATE-CHRON-08's fixture list and its recording (N29b-06 item 10).

Out: the frequency gate (N19b-14); the carried-container battery, the spill metric of the fallback and the kill decision
(N19b-15); the generic card schema (BD-069) and model compiler (BD-061).

## Technical approach

**1. Card fields (DESIGN).** A `.fcard` of kind `payload`, model `slosh-rect`, every field with provenance (`measured`,
`datasheet`, `assumed`):

| Field | Meaning |
|---|---|
| `inner_m` = (L_x, L_y, H) | Inner lengths along the two horizontal axes and the container height |
| `fill` or `depth_m` | Fill fraction of H, or liquid depth h = fill·H |
| `density` | Liquid density ρ; liquid mass m_l = ρ·L_x·L_y·h |
| `modes` | Retained modes per horizontal axis, 1 to 3 |
| `modal_mass[axis][n]`, `modal_height[axis][n]` | m_n and the height z_n at which mode n slides, in the container frame |
| `damping_ratio[axis][n]` | ζ_n; the damper is c_n = 2·ζ_n·m_n·ω_n |
| `fixed_mass`, `fixed_height`, `fixed_inertia` | The rigid part m₀ = m_l − Σ m_n, its height z₀ and its moment of inertia |
| `amp_limit` | Validity limit: the fraction of L beyond which a modal displacement is outside the model |
| `spill_disp[axis]` | The mode-1 displacement at which the liquid reaches the rim along that axis (the payload's spill amplitude, read by the `slosh-tip` predicate); when absent, `amp_limit`·L_a marked `assumed` (DESIGN) |
| `container` | Dry mass, centre of mass and inertia of the container itself |

**2. Admission on the CPU, as numbered steps** (hyperbolic functions are evaluated here, never in a batched kernel):
1. For each axis with length L and each retained n compute ω_n from the formula above with the deterministic elementary
   functions, and set k_n = m_n·ω_n².
2. Check the card: Σ_n m_n ≤ m_l on each axis; m₀ ≥ 0; 0 < h ≤ H; 0 < amp_limit ≤ ½; ζ_n ≥ 0; every field has provenance.
   A violation is a card refusal with the field named.
3. If modal masses are absent, compute candidates from m_n/m_l = 8·tanh((2n − 1)·π·h/L) / ((2n − 1)³·π³·(h/L)) and mark
   them `assumed`. (HYPOTHESIS: this expression is recalled from linear sloshing theory and is not printed in the plan;
   it must be confirmed against the primary source before any card cites it. Its sanity checks are part of the tests: the
   fractions sum to 1 as h/L → 0 and to ½ at h/L = ½, and the first mode carries 0.604 of the liquid at h/L = ⅓.)
4. If modal heights are absent, use z_n = h/2 (the liquid's centre height) marked `assumed`, and list the resulting error
   in overturning moment as a known gap in the contract.
5. Emit the module and record its identity; it enters the model identity like any payload.

**3. The module (DESIGN).** In the container frame: one rigid body for the container plus the fixed liquid mass (m₀ at
z₀ with `fixed_inertia`); for each horizontal axis a and retained mode n, a prismatic joint along a at height z_{a,n}
carrying a body of mass m_{a,n}, with a linear spring k_{a,n} centred at zero and a linear damper c_{a,n}; joint range
±L_a/2 (the liquid cannot leave the container). Each modal body is a thin slab with a small declared inertia so that its
pseudo-inertia is positive definite and passes the model compiler's inertia check; the slab inertias are subtracted from
`fixed_inertia` at admission so the total is unchanged. One to three masses per axis means two to six added degrees of
freedom, which sit in the robot's own tree (the payload is mounted on the robot) and therefore count toward its padded
capacities and size bucket.

**4. Fill as a world parameter.** A task or an adversarial edit may change the fill (for example from 0.50 to 0.80). The
admission step is re-run on the CPU for each distinct fill; masses, spring constants and heights are then per-world
parameter rows, so one batch can hold many fills with one compiled model shape.

**5. Validity.** Small amplitude. When |x_{a,n}| exceeds `amp_limit`·L_a the world emits a validity event
`slosh-amplitude` with the axis, mode and time, and every result that depends on the payload after that instant is
flagged outside the validity domain. The model does not pretend to predict a wave that breaks.

**6. Telemetry and failure class.** Modal displacements and velocities are T2 channels this bead declares in the
`kinematics` stream (N24a-36's nine streams; the modal bodies ride prismatic joints of the robot's tree): `slosh_disp`
(kind State, unit m) and `slosh_vel` (kind State, unit m/s), one column per axis and mode, read with `frob telemetry
query <run> --stream kinematics --channels slosh_disp --json`. The failure class `slosh-tip` is N24a-38's row, entered
there as `pending: N19b-13`; its predicate is that row's, not a second one: the payload's spill event (|x_{a,1}| reaches
`spill_disp[a]`), or the tipping margin going negative within two slosh periods (2·2π/ω_{a,1}) of |x_{a,1}| exceeding
half of `spill_disp[a]`, over the channels the row reads (payload slosh state; balance margin). This bead lands the
monitor beside the other world-class monitors in `frob-chronicle`, behind `frontier-slosh` (it reads the channels
above, so the chronicle does not name `frob-scene`), and switches the row's `status` to `available`; a build without
the feature computes the row `unavailable`, and rule (a) of N24a-38 applies.

**6a. GATE-CHRON-08, wave 4 (N29b-06 item 10 names this bead its recorder).** The bead adds one row to
`fixtures/e2e/chron08/list.toml` with `wave = 4`: class `slosh-tip`, N24a-38's planted fixture (a tray payload at 80%
fill on a walking carrier whose step frequency is the tray's f₁) and its clean control (the same payload frozen), as a
64-world batch with 8 planted addresses like the list's other rows (N29b-05). It runs `scripts/e2e/gate_chron_08.sh`
as a stage of its own (the whole list as it then stands, so every earlier class is proved again), which ends with the
tier run `e2e_tier g1_known_answers GATE-CHRON-08 --mutations` and logs its receipt; then a session that did not
implement the monitor re-records the gate's one part from that receipt with `cargo run -p frob-conformance --example
record_gate -- --gate GATE-CHRON-08 --receipt <hash> --part M2`, its `measured` naming the classes covered,
`slosh-tip` among them.

**7. Tiers, determinism, evidence.** The module is joints, masses, springs and dampers: it runs on the referee, `strict`,
`batch-cpu` and the device tiers under the classes those tiers already hold. Outputs `Estimated`; Reality `no-claim`.
On a build without `frontier-slosh`, or after KILL-SLOSH fires, the declaration's Solid alternative (rigid ballast of the
same total mass at the liquid's centre) is used and the substitution is recorded (N19b-03).

**8. Layout.** `crates/frob-scene/src/living/slosh/{card.rs, admit.rs, module.rs}`.

## Test plan

### Unit tests
`crates/frob-scene/tests/slosh.rs`, `cargo test -p frob-scene --features frontier-slosh --test slosh`.
- `omega_table`: (L, h) = (0.30, 0.10) → ω₁, ω₂, ω₃ = 8.956, 17.523, 22.663 rad/s; (0.30, 0.05) → 7.026; (0.30, 0.15) → 9.707.
- `spring_from_mass`: k_n = m_n·ω_n² exactly as computed; the module's small-oscillation frequency √(k/m) equals ω_n.
- `modal_mass_candidates`: h/L = ⅓ → (0.6043, 0.0286, 0.0062); the infinite-mode sum tends to 1 as h/L → 0 (0.989 at 0.01) and to 0.500 at h/L = ½.
- `card_refusals`: Σ m_n > m_l refused; h > H refused; missing provenance refused.
- `pseudo_inertia_positive`: every body of the lowered module passes the exact inertia check.
- `fill_change_is_parameter_only`: fill 0.5 → 0.8 changes rows, keeps the shape class.
- `validity_event`: a driven oscillation that crosses `amp_limit`·L emits one event at the crossing step.
- `two_axes_independent`: excitation along x leaves the y masses at rest.
- `free_decay`: with ζ = 0.05 the amplitude ratio per cycle is exp(−2π·ζ/√(1 − ζ²)) = 0.730 within 1%.
- `slosh_tip_predicate` (`crates/frob-chronicle/tests/failure_world_classes.rs`, N24a-38's file, with `--features frontier-slosh`): a trace whose |x₁| crosses ½·`spill_disp` and whose balance margin goes negative 1.5 periods later is `slosh-tip`; the same margin crossing 2.5 periods later is not; |x₁| reaching `spill_disp` is `slosh-tip` with the margin positive; a monitor that ignores the two-period window fails the second case.

### Known answers and negative controls
- KA-446: ω₁ = 8.96 rad/s (1.43 Hz) for L = 0.30 m, h = 0.10 m; control: halving the fill must lower the frequency.
- Planted defects: the deep-water formula (tanh dropped, 10.14 rad/s) must fail `omega_table` at all three depths; a spring computed with f instead of ω (missing 4π²) must fail `spring_from_mass`.
- Metamorphic: scaling L and h by λ scales ω by 1/√λ; rotating the container by 90° swaps the axes' mode sets.
- Determinism lanes: twice on one machine; across worker counts; debug and release; across backends (the module adds no new kernel).

## Considerations

- Capacity: extra degrees of freedom can move a robot to a larger size bucket; report the cost and let a task choose one mode per axis by default.
- Round pots are not covered by the rectangular formula; they need card-entered frequencies marked `assumed` or a later model.
- The gait-resonance claim is only as good as the damping ratio, which is `assumed`; the kill decision must vary it.
- KILL-SLOSH: the frequency gate fails after one repair cycle, or sprung masses change no ranking on the carried-container battery; fallback rigid ballast with a spill metric.
