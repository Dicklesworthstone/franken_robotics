## Background

Every Frontier and Moonshot mechanism needs a paper-scale pilot with a falsifier before it is funded: small enough for a
CPU in a day, hand-checkable, registered before it runs, with an outcome not known in advance. For the Frontier sensor
models the plan adds a funding rule: each is funded only when a registered task needs it, and names one analytic fixture
as its pilot. The epic "RGB and splat scenes" (BD-420) has no pilot written in the plan, so the short plan (N19b-23)
defines one and this bead runs it. It follows the shape the plan uses for scene dressing: list the failure classes of the
hazard registry and mark which the new capability could provoke or expose that the existing model cannot; if the list is
empty, the tier is not funded.

Terms. Mask-only model: the Solid sensor model, in which cameras return geometry-correct depth, timing, labels and
validity masks computed from the collision field and the optical map, with optical classes (diffuse, glass, mirror,
specular floor, retroreflector, absorber, emitter) deciding dropouts. Radiometric RGB: pixel values with shot and read
noise, glare and lens distortion. Gaussian primitive: one oriented, coloured blob of a splat scene.

## Scope

In: registration; Part A, the census and its falsifier; Part B, analytic fixtures with hand-checkable answers that any
later implementation must reproduce; Part C, a paper cost estimate; the record.

Out: any renderer or kernel; the kill-gate text (N19b-23); the recommendation and the owner's funding decision
(N19bp2-01, which reads this pilot's record). Priority 2, above the M6 default: the owner decision waits on it.

## Technical approach

**1. Registration (before execution).** In `crates/frob-conformance/registry/pilots.toml` (schema
`frob.gauntlet.pilot/1`, owner N38a-09), two records, because the register holds one tier per record: mechanism "RGB
cameras for policies" (tier `F`) and "splat scenes" (tier `M`), both pointing at the same protocol, by digest equal to
the one printed in the short plan's pilot section; the falsifier; the ceiling
("none on speed; it changes what a perception policy must tolerate and which optics retrofits a pixel-reading policy can
use"); fallback and kill gate (the mask-only model; the kill gate registered by N19b-23); cost (under two engineer-days);
tool and pin.

**2. Part A, the census.** One row for each of the 59 hazards of the seven archetype registries (10 home, 5 apartment,
7 office, 10 warehouse, 8 plant, 8 retail, 11 kitchen), each optics amendment of the retrofit catalog, and each registered
task family. Columns: the failure it provokes or the decision it informs; the sensor channels of the mask-only model that
expose it (depth, lidar range and intensity, labels, validity masks, optical class effects); whether a policy would need
colour or texture from pixels to perceive it; the evidence for that judgement (a sentence, reviewable). Two reviewers
who did not write the short plan fill the "needs pixels" column independently; disagreements are listed, not averaged.
**Falsifier:** if no row needs pixels (the agreed list is empty), RGB exposes no failure class and informs no decision
beyond the mask-only model, and the epic is not funded. Otherwise the rows that need pixels become the battery named in
the kill gate.

**3. Part B, analytic fixtures (hand-checkable; they bind any later implementation).**
1. *Pixel statistics.* A uniform diffuse plane giving a mean signal of S electrons with read noise σ_r: the pixel variance
   is S + σ_r². For S = 1,000 and σ_r = 5: standard deviation √1,025 = 32.02 electrons, signal-to-noise 31.2. For S = 100:
   √125 = 11.18, signal-to-noise 8.94.
2. *Rolling-shutter skew* (shared with the Solid camera model, so RGB cannot diverge from depth): focal length 600 pixels,
   readout 16 ms, yaw 2 rad/s: a vertical edge near the axis skews by 600 × 2 × 0.016 = 19.2 pixels first row to last.
3. *Lens distortion.* Radial model x_d = x·(1 + k₁·r²) in normalized image coordinates: at r = 0.5 with k₁ = −0.2 the
   factor is 0.95, so a point at 300 pixels from the centre (focal 600) lands at 285.
4. *One Gaussian primitive.* An isotropic primitive with standard deviation 0.05 m on the optical axis at depth 2 m, focal
   length 600 pixels: its image is a Gaussian with standard deviation f·σ/z = 15 pixels (first-order projection). At depth
   4 m it is 7.5 pixels.
5. *Compositing order.* Front primitive opacity 0.6 (colour A), back primitive opacity 0.5 (colour B): front-to-back
   compositing gives 0.6·A + 0.4 × 0.5·B = 0.6·A + 0.2·B with transmittance 0.2 left. In the wrong order it gives
   0.5·B + 0.3·A. The two differ, so the depth order must be a deterministic total order: this is the negative control a
   later implementation must catch.

**4. Part C, paper cost.** For the reference camera of the task battery, count rays per frame and the texture lookups or
primitives composited per ray under the short plan's design, against the depth-only ray stage; state the largest K
primitives per ray compatible with the 25% added-cost rule under the stated per-operation costs. This is DESIGN
arithmetic with every assumption listed; it is superseded by the `batch-cpu` probe the kill gate names.

**5. Record.** The census table, the fixture values and the cost estimate as canonical JSON with digests in the pilot
register; the result, including a negative one, in the delivery log; the short plan's recommendation section updated.

## Acceptance criteria

- [ ] The pilot is registered, with a protocol digest equal to the short plan's, before any result exists (commit order).
- [ ] The census covers all 59 hazard rows, the optics amendments and the registered task families; both reviewers' columns and their disagreements are on record.
- [ ] The falsifier's verdict is recorded: the agreed "needs pixels" list, or "empty: not funded".
- [ ] The five analytic fixtures are computed by a small exact program and match the values above.
- [ ] The paper cost estimate lists every assumption and the resulting bound on primitives per ray.
- [ ] The verdict is appended to both records as a `[[pilot.result]]` (`falsifier-holds` if the agreed list is empty,
      `falsifier-rejected` otherwise) and handed to N19bp2-01, which closes BD-420 with reason `fallback` (the mask-only
      model) if the falsifier holds.

## Test plan

### Unit tests
In the pilot program (`tools/pilots/rgb_need/`):
- `pixel_std`: (1000, 5) → 32.016; (100, 5) → 11.180.
- `skew`: 600 × 2 × 0.016 = 19.2.
- `distortion`: 300 → 285 at k₁ = −0.2, f = 600.
- `gaussian_footprint`: 600 × 0.05/2 = 15; at 4 m, 7.5.
- `compositing`: (0.6, 0.5) → weights (0.6, 0.2), transmittance 0.2; reversed → (0.3, 0.5).
- `census_complete`: the table has 59 hazard rows with the per-archetype counts 10, 5, 7, 10, 8, 8, 11, and a refusal if a row is missing.

### End-to-end script and logging
`scripts/e2e/pilot_rgb_need.sh` (header `# e2e: bead=N19b-24 milestone=M6 labels=habitat,sensorium,pilot seed=0 needs=cpu plants=census-all-exposed,census-one-fiducial,reversed-compositing`; sources `scripts/e2e/lib.sh` of STD-E2E; NDJSON under `target/e2e-logs/pilot_rgb_need/<utc>.ndjson` with a transcript): verifies registration precedes results (the protocol digest of both records equals the plan's, and the kill-gate row's amendment date precedes the result), runs the pilot program, compares output digests with the register, and asserts that the recorded verdict equals the verdict recomputed from the census table (empty or non-empty list). The same ordering assertions are added as step `pilot_order` to `scripts/e2e/rgb_splat_preparation.sh` (owned by N19b-23). Every line carries `ts`, `script`, `bead`, `step`, `event`, the exact command line, exit code and wall time; lines log the count of rows, the count that need pixels per reviewer and agreed, each fixture value as a `metric` with its hand value, and on failure the first differing row and the census file path. A final `summary` counts assertions. A pilot runs outside the product: no `frob` simulation verb is driven.

### Known answers and negative controls
- The five fixtures above are the known answers; the rolling-shutter skew of 19.2 pixels is shared with the Solid camera model's own known answers.
- Control for the census: a planted census in which every row is exposed by depth and labels must return "empty: not funded"; a planted census with one fiducial-reading task must return a non-empty list.
- Control for compositing: the reversed-order result must differ from the correct one (it does, 0.3·A + 0.5·B against 0.6·A + 0.2·B).
- Determinism: exact arithmetic; identical output bytes on every platform.

## Considerations

- The census is a judgement, which is why two independent reviewers and a visible list of disagreements are required; a single author's census cannot fail and would not be a pilot.
- A non-empty list funds nothing by itself: the owner still decides, and the kill gate still applies.
- The fixtures deliberately include one that is shared with the Solid tier (the skew), so that an RGB path is forced to reuse the existing camera timing model.
- Captured appearance is private; the pilot uses no captured data at all.
