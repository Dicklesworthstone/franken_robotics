## Background

Given the cells of a clearance complex with their one-sided clearances c_lo and c_hi (N19b-26), this bead produces the
answers. ADR-HAB-08: a clearance question has three answers, a feasibility witness, an impossibility cut that names the
bottleneck, or `unresolved`. Reason: a single traversability bit for a nominal footprint cannot be trusted for a
rectangular or articulated body and cannot say why a body does not fit. Construction C-33 states the sandwich
𝒞_in ⊆ 𝒞_free ⊆ 𝒞_out: a connected path in the inner complex is a feasibility witness for every robot whose swept
footprint fits the envelope; disconnection of start and goal in the outer complex is an impossibility certificate; for a
margin between the two critical values the answer is `unknown`, and that band is the stated resolution of the
certificate. One union-find pass over the margin filtration answers every margin at once and names the bottleneck cell,
a doorway or a corridor. Payoff: a two-sided answer with a named bottleneck, reused across many width queries, and a
refusal that says which doorway to change, which is the input of the retrofit search. Tier Frontier; crate `frob-scene`.

## Scope

In: face connectivity with periodic heading; the witness search; the cut labelling; the margin sweep giving the certified
margin w_in and the impossibility margin w_out with their bottleneck cells; mapping a bottleneck to a named feature; the
answer type; parity against the sibling's cubical persistence on small fixtures; proof obligation PO-HAB-03.

Out: cell values (N19b-26); refinement of `unresolved` answers (N19b-29); slabs, transitions and labels of the witness
(N19b-30); certificate objects and checkers (N19b-31); the verb (N19b-32).

## Technical approach

**1. The three answers for a margin w, a start cell and a set of goal cells.**
1. A face-connected path of inner cells (c_lo > w) from the start cell to a goal cell is a **feasibility witness**: the
   polyline through cell centres and shared faces stays inside boxes that are entirely free.
2. If the start and every goal cell lie in different components of the outer complex (c_hi > w), no collision-free path
   exists for margin w: an **impossibility cut**. Face adjacency suffices for this direction because the cells are
   closed: a free configuration on a shared edge or corner makes every cell that contains it an outer cell, and those
   cells are face-connected round that edge.
3. Otherwise the answer is `unresolved`, and the cells between the two verdicts are returned for refinement.
A start or goal cell that is not itself inner (for a witness) is `unresolved` at best; a start or goal cell that is not
outer is an immediate cut with that cell as bottleneck.

**2. The sweep (one pass answers every margin).** Sort cells by c_lo in decreasing order (a counting sort on the 16-bit
key is linear) and add them one at a time to a union-find structure, uniting each new cell with its already-added face
neighbours (six neighbours: ±x, ±y, ±ψ with ψ periodic; mixed refinement levels through the neighbour function of the
format). The value at which the start's component first contains a goal cell is **w_in**, the largest certified margin:
a witness exists for every w < w_in. The cell whose insertion merged them is the **inner bottleneck**. The same sweep on
c_hi gives **w_out**, the margin at and above which passage is impossible, and the **outer bottleneck**. Always
w_in ≤ w_out; the interval [w_in, w_out) is the unresolved band. This is zero-dimensional persistence of the clearance
filtration. FACT: the sibling `fs-topo::cubical` implements zero-dimensional persistence for voxel fields, with chart
voxelization capped at 10⁶ cells and no periodic axis, so `frob-scene` implements the sweep itself and uses `fs-topo` as a
parity oracle on small fixtures (headings restricted to less than a full turn so that no periodic adjacency is needed).

**3. Extracting the objects.**
- Witness for a given w < w_in: breadth-first search in the inner complex from the start, visiting neighbours in a fixed
  order (so the path is deterministic), returning the list of cell addresses from start to goal.
- Cut for a given w ≥ w_out: label the components of the outer complex (cells with c_hi > w) by breadth-first search in
  index order; return the labelling (a label per outer cell), the start's label and the goals' labels, all different from
  the start's.
- Unresolved: return w_in, w_out, both bottleneck cells and the frontier: outer cells with c_lo ≤ w < c_hi that separate
  the start's inner component from the goals within the start's outer component.

**4. Naming the bottleneck.** The bottleneck cell is mapped through the scene's semantic labels to a named feature: take
the configuration at the cell centre, find the obstacle regions nearest to the placed footprint, and report the labelled
feature they belong to (a door, an aisle, a threshold zone) with the room it joins. The answer then reads "door D3,
certified to 31 mm of margin, impossible at 46 mm", not a cell index. Where no label exists the answer carries the
world-frame position of the cell and says the feature is unlabelled.

**5. Answer type (DESIGN).**

```rust
pub enum FitVerdict { Witnessed, Impossible, Unresolved }
pub struct FitAnswer {
    verdict: FitVerdict, margin: Length,
    w_in: Length, w_out: Length,                     // certified margin; impossibility margin
    bottleneck_in: Option<Bottleneck>, bottleneck_out: Option<Bottleneck>,
    witness: Option<Vec<CellAddr>>, cut: Option<CutLabels>, frontier: Vec<CellAddr>,
}
pub struct Bottleneck { cell: CellAddr, pose: [f64; 3], feature: Option<FeatureName>, clearance_mm: (i16, i16) }
```

**6. PO-HAB-03.** A face-connected inner path is collision-free, and separation in the outer complex excludes every path.
Written proof on file (`docs/proofs/po-hab-03.md`): the first half because each box on the path is entirely free and
consecutive boxes share a face, so the polyline never leaves free boxes; the second because any continuous free path
visits a sequence of closed outer cells in which consecutive cells share at least a point, and cells sharing a point that
is free are face-connected through outer cells round that point. Verification also by exhaustive comparison with a
brute-force grid at four times the resolution on small fixtures (the gate's battery, N19b-35).

**7. Determinism.** Integer keys, fixed insertion and visiting orders: D0; identical answers on every platform.
Complexity: linear in cells for the sort and near-linear for union-find; 1.2 million cells in well under a second.

## Acceptance criteria

- [ ] On the right-angle corridor (a = 0.90 m, b = 0.60 m): a witness for a 1.30 m body and a cut for a 1.40 m body once the band is narrow enough; never a witness above 1.346 m nor a cut below it at any resolution.
- [ ] w_in ≤ w_out on every query; a witness exists exactly for margins below w_in and a cut exactly for margins at or above w_out (checked by direct search at 100 margins per fixture).
- [ ] The bottleneck of a doorway fixture is reported as the labelled door with both margins.
- [ ] Every witness path is face-connected, starts at the start cell, ends in a goal cell and visits only cells with c_lo > w; every cut labelling leaves no outer cell unlabelled and gives start and goals different labels.
- [ ] Parity with `fs-topo` zero-dimensional persistence on the small non-periodic fixtures: equal merge values.
- [ ] PO-HAB-03's proof is on file; answers are bit-identical across platforms.

## Test plan

### Unit tests
`crates/frob-scene/tests/clearance_answers.rs`, `cargo test -p frob-scene --features frontier-fclear clearance_answers`.
- `chain_of_three_cells`: synthetic complex with c_lo = (50, 20, 50) mm and c_hi = (60, 35, 60) mm along the only route: w_in = 20 mm, w_out = 35 mm, bottleneck the middle cell; margin 10 → `Witnessed`; 25 → `Unresolved`; 35 → `Impossible` (the boundary is inclusive for impossibility); 40 → `Impossible`.
- `two_routes_takes_wider`: two parallel routes with bottlenecks 20 mm and 45 mm: w_in = 45 mm.
- `psi_wrap_route`: a route that exists only through the heading seam is found.
- `corner_contact_not_adjacent`: two inner cells that share only an edge are not connected by the witness search.
- `cut_closedness`: the outer complex treats edge-sharing cells as connected through their common face neighbours when those are outer; a fixture where they are not outer yields a cut.
- `start_not_outer_is_cut`: bottleneck is the start cell.
- `multi_goal`: the nearest reachable goal cell ends the witness.
- `corridor_closed_form`: at Δ = 12.5 mm, 128 headings, L = 1.30 m → `Witnessed` or `Unresolved`, never `Impossible`; L = 1.40 m → `Impossible` or `Unresolved`, never `Witnessed`. The limit is not typed in: it is read from the compendium's oracle for the swept right-angle corner (N12-43, row "Swept right-angle corner", L ≤ 2√2·a for a rod, 2√2·a − 2b for a rectangle), which implementations never regenerate.
- `sandwich_against_oracle`: on the synthetic doorway of the compendium's "Clearance sandwich" row (N12-43), the inner critical margin lies below and the outer above the opening's half-margin by at most the reported band, and closing the gap by one cell flips the outer verdict to a cut.
- `fs_topo_parity_small`.
- `deterministic_path`: the same query twice returns the identical cell list.

### Known answers and negative controls
- KA-448: the corridor closed form L ≤ 2√2·a − 2b, 1.346 m at a = 0.90 m and b = 0.60 m; the complex returns a witness below the limit minus its band and a cut above the limit plus its band; control: inscribed and circumscribed disc tests are both wrong. CX-193.
- KA-689: a doorway narrower than every orientation of the footprint returns an impossibility cut that names the doorway; widened past the footprint it returns a witness path; control: a clearance test on a bounding ball for a rectangular footprint.
- Planted wall: closing a gap by one cell flips the outer verdict.
- Negative controls: a witness search that allows diagonal steps (must be caught by `corner_contact_not_adjacent`); a sweep without the periodic heading neighbour (must fail `psi_wrap_route`); a cut that ignores closedness is caught by the brute-force comparison of the gate.
- Metamorphic (MR-29): a finer grid only narrows the band; both complexes shrink as the margin grows (w_in and w_out are the same for every query margin, and verdicts are monotone in w).
- Determinism lanes: twice on one machine; debug and release; across platforms.

## Considerations

- The witness is geometric: a polyline of poses with positive clearance. Whether a particular base can follow it (and how many manoeuvres that takes) is the label logic of N19b-30; it is never a statement about dynamics, traction or control.
- The band [w_in, w_out) follows from cell size and heading width and is reported, never assumed; near fits need refinement (N19b-29).
- One false witness or false cut that survives a repair cycle fires KILL-FCLEAR.
- Bottleneck naming depends on semantic labels existing; a generated scene always has them, a scan may not.
