## Background

`scene.fit` is the user-visible surface of clearance complexes. The verb table of the scene chapter and the verb registry
define it: kind `run`, first milestone M3, returns "a feasibility witness, an impossibility cut or `unresolved` for a
footprint family and a route". It lets an agent ask, before any rollout, whether a body can get from here to there in a
place, and get back either a path, or the named feature that blocks it with the margins ("door D3, certified to 31 mm of
margin, impossible at 46 mm"), or an honest "not decided at this resolution". It serves GOAL-32 (make the world a design
variable: clearance complexes that return a route witness or an impossibility cut) and feeds the retrofit search, the
place stage of design preflight, mission queries and the solvability oracle of the adversarial search.

The verb is Frontier (feature `frontier-fclear`). Layering: `frob-scene` (layer 2) owns the mechanism; the verb
implementation lives in `frob-verbs` (layer 6) and adds what a library cannot: the envelope with its claim product,
refusals with ranked repairs, the job protocol, memoization by identity, and the cross-verb rule that a standing
impossibility cut refuses runs on that route.

`FROB-REF-309`: a run is requested on a route that has a standing impossibility cut for this footprint. Ranked repairs:
read the cut; edit the design; run `scene.retrofit`; pass an explicit diagnostic override. Reason for the rule: training
or evaluating a body on a route geometry proves it cannot traverse spends compute to rediscover the cut as "the policy
failed".

## Scope

In: the handler for the `scene.fit` row (the row itself is entered only by the cluster registry bead VERBS-scene, a
dependency; this bead enters no row), the input and output schemas, examples and refusal list it implements; the executor (complex cache, refinement,
route verdict, checks, bundle hand-off); the envelope; long-running behaviour (bounded synchronous wait, job handle,
cancellation); the standing-cut index and the admission refusal `FROB-REF-309` with its override; MCP exposure through the
generated tool.

Out: the mechanism beads it calls; the end-to-end gate battery (N19b-35); `scene.probe-request` (N19c-05); `scene.retrofit`
(BD-369 and its children); use on real places (BD-398).

## Technical approach

**1. The registry row it implements** (entered in `registries/verbs.toml` by VERBS-scene; restated so the handler can be
written against it). name `scene.fit`; kind `run` (spends compute, takes an idempotency key and a budget, accepts the
bounded synchronous wait and otherwise returns a job handle with exit code 8); tier `F`; capability scope `scene:run`
(the registry's scope for every `run` verb of the cluster; plus `private:read` for a private scene); schemas
`frob.scene.fit.in/1` and `frob.scene.fit.out/1`; chapter refusals `FROB-REF-304`, `-305`, `-308` and the format
refusal `-891` (for a stored `.fclear`) beside the generic input refusals; `idempotent = false` (a `run` verb: a
repeated key returns the stored envelope, a missing key is `FROB-REF-805`); first milestone M3; task cluster
`places-check`; examples `frob scene fit --design quad-a --scene s:kitchen-17 --route galley --key fit-1 --json` (the
registry's) and `frob scene fit --scene home-0042 --footprint rect:0.60x1.30 --margin 0.02 --from hall --to bedroom-2
--key fit-2 --json`. The MCP tool name is `scene_fit`. The registry row lists 303 (the `.fclear` reader of N19b-27: a
stored complex whose blob does not resolve or has the wrong length; and the pack reader's undecodable pack, BD-162),
304, 305, 308 and 891 as chapter codes, and by slug the integrity row `scene-pack-identity-mismatch` (N19c-42 row 4,
raised by the `.fclear` reader of N19b-27) and `scan-profile-absent` (a scan pack imported without its scan profile,
raised by NEG-23's acceptance check), their numbers entered from the ledger when those rows are registered
(VERBS-scene's `refusal_lists` test); the handler's refusal-list test asserts the same set. The row also carries the
optional `fallback` input that N19b-36 adds (`none` by default, or `heuristic`: the KILL-FCLEAR fallback's route-graph
check, labelled heuristic); this bead's input schema leaves room for it as an additive field.

**2. Input.**

| Field | Meaning |
|---|---|
| `scene` | A scene name or `SceneId`; mutable names are resolved to identities and echoed in `bound` |
| `footprint` or `design` | A footprint family (outline, reference point; ρ is computed) or a design from which the footprint, envelope and capabilities are derived |
| `margin_m` | The margin w to decide (default 0); the answer always reports w_in and w_out, which cover every margin |
| `envelope`, `capabilities` | Top and step-over heights; step height, slope limit, gap limit, push torque and force, reversal |
| `route` | A named path of the scene's route graph, or a start pose or region and one or more goal regions |
| `modes` | Fixture-mode assignment or `as-declared`; doors may be `open`, `closed`, `openable` |
| `refine` | `max_level` (default 4), `max_cells`, or `none` |
| `require_label` | Optional: `kinematic` |
| `emit` | Whether to keep the `.fclear` artifacts and whether to write a certificate bundle; CLI `--emit fclear`, `--emit bundle` or `--emit fclear,bundle` (DESIGN spelling, pinned by the help-schema snapshot); default neither |
| `idempotency_key`, `budget`, `sync_wait_ms` | Standard for `run` verbs: CLI waits to completion by default; MCP waits 5,000 ms by default and at most 30,000 |

**3. Execution, as numbered steps.**
1. Resolve identities; refuse an ingested scene whose scale label is `relative-only` (`FROB-REF-304`: scale authority is
   below what the task requires; repairs: add a scale witness; choose a non-metric task). For `estimated` scale, proceed
   and widen u_reg to the stated scale interval, so near fits come back `unresolved`.
2. Decompose the route into planar segments and transitions (N19b-30); raise `FROB-REF-308` for an out-of-domain query.
   If the route must pass through `unknown` space and the caller requires a decided route, raise `FROB-REF-305` (repairs:
   emit a probe request for the named box; choose another route).
3. For each (slab, modes): look up the complex in the memo store by its derived identity; build it if absent (N19b-26,
   N19b-27). One complex serves every margin and every start and goal in its slab.
4. Sweep, refine and decide each segment (N19b-28, N19b-29); evaluate transition predicates; form the route verdict and
   the witness label (N19b-30).
5. For every `Witnessed` or `Impossible` segment, run the recomputation check and the connectivity check (N19b-31);
   only then is the verdict released. On request write the bundle.
6. If the route verdict is `impossible` by a checked cut, record a standing cut (step 5 below).
7. Assemble the envelope.

**4. Output and envelope.** `verdict` (`witnessed`, `impossible`, `unresolved`); per segment: verdict, `w_in_m`, `w_out_m`,
band, bottleneck (feature name, pose, both margins), refinement record and stop rule; per transition: predicate, the two
compared values with units; the witness as a pose polyline with its label, or the cut summary (components, the separating
feature); artifact identities (`fclear`, certificates), each with the store digest that `artifact.read` and
`artifact.export` take; the treatment of unknown space; `next_actions`: for `impossible`,
`frob scene retrofit …` and the design edits that would enlarge the margin; for `unresolved` at a registration floor,
`frob scene probe-request …`. Evidence block: claim `Proof`, class `Certified`, scope "relative to compiled scene ⟨id⟩ and
its stated bounds" for decided verdicts; no claim for `unresolved`; tier `static`; determinism D0; identities of scene,
footprint and complex; `reality: no-claim`. Exit codes: 0 for `witnessed`; 2 for `impossible` or `unresolved` (completed
with findings); 3 for refusals; 8 for an accepted job still running.

**5. Standing cuts and `FROB-REF-309`.** A checked cut for (scene, route, footprint family) is indexed in the ledger with
its impossibility margin w_out and its certificate claim. Any run verb whose task binds that scene and route, for a design
whose footprint margin relative to that family is at least w_out, is refused at admission with `FROB-REF-309`, pointing to
the cut and listing the four repairs: read the cut; edit the design; run `scene.retrofit`; pass an explicit diagnostic
override. The rule is the admission check `habitat.standing-cut` of N32ax-01, declared in `registries/verbs.toml`
(owner `frob-scene`; verbs `sim.run`, `eval.run`, `train.start`, `opt.start`, `study.submit`; refusal `FROB-REF-309`;
override `standing-cut`; basis `scene_standing_cuts`; first milestone M3) and evaluated in stage A, before any budget is
estimated; this bead links its implementation and owns the index, incrementing the index's version in
`admission_basis` in the same transaction that records or retires a cut. The override (`--diagnostic-override
standing-cut`) is recorded as `diagnostic_overrides` in the job row and the run manifest, the envelope carries the
warning `diagnostic-run: standing-cut` and an empty `claims` list; `--estimate` reports the cut under
`result.admission.would_refuse` with exit 2. A cut stops standing when its scene identity is not the one bound (any
scene edit gives a new identity).
Monotonicity makes the rule sound: if F(w_out) cannot pass, no larger body of the family can.

**6. Cancellation and idempotency.** The executor polls the job context between headings and between refinement passes;
on cancel it drains, finalizes the job record and frees memory; a repeated request with the same key returns the stored
envelope with `idempotent_replay: true`.

## Acceptance criteria

- [ ] `frob scene fit … --json` returns exactly one envelope with the schema `frob.scene.fit.out/1` for witnessed, impossible, unresolved and refused cases, with the exit codes above.
- [ ] The corridor example returns `witnessed` for a 1.30 m body and `impossible` for a 1.40 m body (a = 0.90 m, b = 0.60 m) with the bottleneck named and both margins reported.
- [ ] A second query at a different margin on the same scene and footprint reuses the complex (memo hit recorded) and returns in a fraction of the first time.
- [ ] Decided verdicts carry claim `Proof`, class `Certified` and the scope string; `unresolved` carries no claim and a stated reason.
- [ ] `FROB-REF-304`, `-305` and `-308` are raised on their fixtures with ranked repairs; `FROB-REF-309` refuses `sim.run` on a route with a standing cut and the override admits it with the diagnostic label.
- [ ] Over MCP the tool `scene_fit` returns the same envelope; a job that exceeds the wait returns a handle and is recoverable by key.
- [ ] Cancellation is tested: request, drain, finalize, no leaked resources.
- [ ] The `scene.fit` steps that earlier beads' scripts log as `e2e_skip "needs N19b-32"` (`scripts/e2e/clearance_cells_smoke.sh` of N19b-26, extended by N19b-28 and by N19b-29's cancellation section, `scripts/e2e/fclear_roundtrip.sh` of N19b-27, and `scripts/e2e/clearance_certs.sh` of N19b-31) now run and pass, and the verb-surface section this bead adds to `clearance_cells_smoke.sh` passes.

## Test plan

### Unit tests
`crates/frob-verbs/tests/scene_fit.rs`, `cargo test -p frob-verbs --features frontier-fclear --test scene_fit`; real executor on `synthetic` compiled fixtures.
- `schema_roundtrip`: example inputs validate; an unknown field is refused.
- `envelope_shapes`: the four outcome kinds each produce the documented fields.
- `exit_codes`: 0, 2, 3, 8 as specified.
- `memo_reuse`: two margins, one complex build.
- `scale_labels`: `relative-only` → 304; `estimated` → proceeds with widened u_reg and `unresolved` on a near fit.
- `unknown_route`: 305 with the box named.
- `standing_cut_index`: after an `impossible`, `sim.run` on the same scene, route and a body at least as large → 309; a narrower body below w_in → admitted; a different scene identity → admitted.
- `override_labels_run`: the override is recorded (`diagnostic_overrides` in the manifest, warning `diagnostic-run: standing-cut`, empty `claims`) and the run is labelled diagnostic; `--estimate` on the same request returns `would_refuse` with 309, exit 2, and no job row.
- `basis_version_bumped`: recording a cut increments `admission_basis(scene_standing_cuts)` in the same transaction; a `sim.run` whose stage A read the earlier version is re-admitted from stage A and refused with 309.
- `checks_before_release`: with a planted producer fault the verb returns a fault, not a verdict.
- `idempotent_replay` and `cancel_drains`.

### End-to-end script and logging
`scripts/e2e/scene_fit_gate.sh` (N19b-35) is the capability's end-to-end script and gate. N19b-35 depends on this bead, so at this bead's close the end-to-end evidence is the three earlier scripts whose `scene.fit` steps were skipped (`clearance_cells_smoke.sh`, `fclear_roundtrip.sh`, `clearance_certs.sh`), each now run in full with no `skip` line, plus a verb-surface section added to `clearance_cells_smoke.sh`: one call per outcome kind, `FROB-REF-304`, `-305` and `-308` on their fixtures, a memo hit, `--sync-wait-ms 0` with `frob job cancel` and `frob job status`, and the same query through `frob-mcp` with envelope digests compared. This bead also contributes its verb-surface cases to the gate script: each outcome kind on the CLI and over `frob-mcp`, the four refusals, the memo hit, the job handle and cancellation. Logging follows the standard: one NDJSON line per step with the exact command, exit code, wall time, the envelope's evidence block (claim, class, tier, determinism, identities, seed), `w_in_m`, `w_out_m`, the refusal code with pointer and repairs, envelope digests where the CLI and MCP answers are compared, and the first differing field on failure.

### Known answers and negative controls
- KA-448 (corridor, 1.346 m), KA-451 (unresolved under 149 mm before refinement), KA-689 (a doorway narrower than every orientation returns a cut that names it; widened, a witness).
- Negative controls: a verb build that releases a verdict before the checks (caught by `checks_before_release`); a standing-cut rule keyed by scene name instead of identity (caught by the edited-scene case, which must be admitted); a verb that reports `unresolved` as `impossible` (caught by the doorway near-fit case).
- Determinism: two invocations give byte-identical result payloads apart from job identifiers and timings.

## Considerations

- The verb's first milestone is M3 on generated scenes; real places arrive at M5, where scale labels and unknown masks start to matter in practice.
- If KILL-FCLEAR fires, the verb remains but answers from the fallback (the route-graph traversability check for a nominal footprint), labelled heuristic, with the feasibility tag reduced to `unresolved` wherever the heuristic and a fine brute-force grid disagree; it then emits no certificate and no standing cuts.
- Private scenes: answers, complexes and bundles inherit the private mark; the bottleneck's feature name is scene content and is never written to shared logs.
- The diagnostic override exists because a geometric cut is not a dynamic one for transitions; for planar cuts it should be rare, and its use is counted.
