## Background

The retrofit catalog `registries/retrofits.toml` (Frontier, milestone M4; crate `frob-scene`) makes the
building a design variable with prices, so that "add a ramp" and "fit larger wheels" are compared in one
budget. An entry is a typed scene edit with its parameters, the hazards it applies to, a price with
provenance, an install class (`renter-safe`, `landlord`, `contractor`), constraints on its parameters and
the aspects of the scene it changes. That is enough for `scene.retrofit`, which asks one question: which
cheapest kit flips a failing verdict.

The facility co-design query of the mission layer (Moonshot, milestone M8) asks more of the same entries.
It gives its optimizer "a priced world-edit grammar: a removable ramp, a sensor fiducial, a change of
docking pose, a wheel or sole swap, a repositioned handoff surface, where the brief permits them, each
with **installation time, access constraints, floor availability, calibration, part tolerances and future
maintenance** (the retrofit catalog)". Editing the floor and editing the robot enter the same budget, and
the answer is a lower bound plus feasible alternatives, the remaining gap and the intervention that removes
it. The grammar bead (N25c-31) carries a `Price` with parts, installation time, calibration, maintenance,
access constraints and tolerance references, and names the catalog as their source.

The catalog bead (N19b-38) deliberately left these out of version 1: "an entry may carry an optional
`facility` table for them, ignored by `scene.retrofit`, so that adding them later is an additive change
and not a new format version". Nothing defines that table. This bead does.

DESIGN decisions. (1) The six properties are data on the catalog entry, with per-field provenance, not
numbers invented inside the mission layer: the entry is where a cited source or a measurement can later
replace an assumption, and where the owner decision on price and legality sources (OPEN-HAB-4) already
applies. (2) An entry without the table is *unpriced* for a facility query; it is never given zeros.
Rejected: defaults of zero time and zero upkeep (every world edit would beat every robot edit for free);
a separate facility catalog keyed by entry id (two files that can disagree about one amendment). Tier: the
table is plain data, but it exists only for a Moonshot consumer, so it carries that tier and priority.

## Scope

In: the schema of `[retrofit.facility]`; validation; as-installed tolerance bands on edit parameters and
the band-extreme rule for constraints; the export `facility_terms`; conversion to the mission layer's
`Price` fields; tables for the sixteen first amendments (all `assumed`); the `facility` block of
the catalog resource and of the `scene.retrofit --apply` report.

Out: the catalog, kits, constraints, install classes and FROB-REF-313 (N19b-38); the search and the verb
(N19b-39, N19b-40); the priced-edit grammar, its search, bounds and refusals (N25c-31); schedules and
occupancy across robots (N25c-30); robot-side prices from part cards (the module catalogue); sources for
prices and legality (N19b-43).

## Technical approach

**1. Schema (DESIGN; an optional table per entry; catalog schema version unchanged).**

```toml
[retrofit.facility]
install     = { time = "0.25 h", crew = 1, tools = ["hand"], provenance = "assumed" }
access      = [ { kind = "clear-floor", radius = "1.0 m", duration = "0.25 h" },
                { kind = "door-out-of-service", duration = "0.25 h" } ]
floor       = { blocks = "route-edge", duration = "0.25 h", window = "any" }
calibration = { required = false }
tolerances  = [ { param = "rise_m", plus = "0.002 m", minus = "0.002 m", provenance = "assumed" },
                { param = "run_m",  plus = "0.005 m", minus = "0.005 m", provenance = "assumed" } ]
upkeep      = { interval = "12 mo", time = "0.1 h", parts = { value = 0, currency = "USD" },
                life = "5 y", provenance = "assumed" }
```

| Field | Meaning | Validation |
|---|---|---|
| `install.time`, `crew`, `tools` | Working time on site and the people and tool class it needs (`hand`, `power`, `lift`, `electrical`) | time > 0; crew ≥ 1; the tool class must be consistent with the install class (`renter-safe` admits `hand` only) |
| `access` | Conditions that must hold while installing: `clear-floor` (a disc about the target), `door-out-of-service`, `aisle-closed`, `power-off`, `ladder-height` (with a height), `permit` (a named authority) | A closed set of kinds; every duration ≤ `install.time`·crew or stated separately |
| `floor` | What the installation makes unavailable to robots and for how long: `route-edge`, `region`, `dock`, `none`; `window` = `any`, `off-shift`, or an interval | `blocks` must name a kind the scene's route graph or regions can resolve at the target |
| `calibration` | Whether anything must be re-measured after installation: `required`, `what` (`fiducial-survey`, `dock-pose`, `sensor-extrinsics`, `floor-friction`), `time`, `accuracy`, and `invalidates` (identifiers of measurement kinds the edit puts in question) | If `required`, time and accuracy are mandatory; `invalidates` names registered measurement kinds |
| `tolerances` | The as-installed interval of each edit parameter: nominal −minus to nominal +plus | Every parameter of the entry's edit has a row, or the entry states `exact = ["param"]` for parameters with no installation error (a card swap) |
| `upkeep` | Recurring work (interval, time, parts; all three absent when there is none) and the service life after which the amendment is replaced | interval > 0 where present; life ≥ interval, or `life = "permanent"` |

Every sub-table carries `provenance` (`assumed`, `datasheet` with a citation, `measured`). All shipped
tables are `assumed` until the owner decision on sources is recorded.

**2. Tolerance bands and constraints.** An instantiated amendment with tolerances is a box in parameter
space. A catalog constraint (for example `run_m >= 12 * rise_m`) must hold on the **whole box**, checked in
exact rationals at the box's vertices (constraints are sums and products of parameters and literals, and
each is monotone in each parameter over a positive box; a constraint that is not is checked by interval
evaluation and refused if undecided). `kit_valid_as_installed` returns the violating vertex. The scene
variant used for a verdict is built at the nominal values; the mission layer additionally asks for the
variants at the vertices the constraint check marks as worst (the band-extreme variants), so a verdict can
be stated for the installed range and not only the drawing.

**3. Export (DESIGN; `crates/frob-scene/src/retrofit/facility.rs`).**

```rust
pub struct FacilityTerms { pub install_time: Duration, pub crew: u8, pub access: Vec<AccessCondition>,
    pub floor: FloorBlock, pub calibration: Option<CalibrationNeed>, pub tolerances: Vec<ParamBand>,
    pub upkeep_parts_per_year: Money, pub upkeep_time_per_year: Duration, pub life: Life,
    pub weakest_provenance: Provenance }
pub fn facility_terms(entry: &RetrofitEntry, inst: &Instantiation) -> Result<FacilityTerms, Unpriced>;
pub struct Unpriced { pub entry: RetrofitId, pub missing: Vec<&'static str> }
```

Annualization: `upkeep_parts_per_year` = parts × (1 year / interval) + (entry cost) × (1 year / life) when
the life is finite; `upkeep_time_per_year` = time × (1 year / interval). Durations and money are exact
rationals. The mission layer maps these to its price: parts from the entry's `cost`; installation time =
`install_time` × `crew` (person-time) and elapsed time = `install_time`; calibration time; maintenance
money per year; access conditions; tolerance references. How they combine into one budget is the caller's
recorded scalarization, never decided here.

**4. Unpriced entries.** `facility_terms` on an entry without the table, or with a missing sub-table,
returns `Unpriced` listing what is missing. A facility query then omits the edit and records the
disposition "unpriced world edit" for it (the mission layer requires a disposition for every omitted
option). `scene.retrofit` ignores the table entirely and is unaffected.

**5. Evidence.** A price built from `assumed` tables is `Estimated`; the weakest provenance is carried in
`FacilityTerms` and printed wherever a facility price is printed. No physical installation is checked; the
Reality cell stays `no-claim`. Determinism exact.

**6. Surface.** No new verb. The catalog resource `frob://catalog/retrofits` (the `retrofits` kind of N32a-25's
catalog resource, whose handler is N19b-38's and returns each entry as the registry holds it), read through `frob-mcp`
with `resources/read` (`artifact.read` takes a store digest and has no form for a resource URI), carries each entry's
`facility` table. `frob scene retrofit --apply <entry>:<params> --at <target>
--facility --json` adds to the application report the as-installed band check (with the violating vertex)
and the annualized terms; without `--facility` the report is unchanged.

## Acceptance criteria

- [ ] The sixteen first amendments carry a `facility` table that validates; each sub-table has provenance `assumed`.
- [ ] An entry without the table loads, works in `scene.retrofit` exactly as before (byte-identical kit reports), and returns `Unpriced` from `facility_terms`.
- [ ] Threshold-ramp hand case: nominal rise 20 mm, run 240 mm, tolerances ±2 mm and ±5 mm, constraint run ≥ 12·rise: the nominal point satisfies it (240 ≥ 240) and the band fails at the vertex (rise 22 mm, run 235 mm; 235 < 264); the smallest nominal run on a millimetre grid that passes is 269 mm.
- [ ] Annualization hand case: anti-slip tape, cost 8 USD, life 6 months, no interval upkeep: 16 USD per year; a floor mat at 40 USD, life 5 years, cleaned monthly for 0.1 h: 8 USD and 1.2 h per year.
- [ ] A `renter-safe` entry declaring tool class `power` is refused at load; a `calibration.required = true` without accuracy is refused.
- [ ] The band-extreme variants named by the check compile to scene variants whose lineage records the base and the edit at the vertex values.
- [ ] The catalog resource is reachable through `frob-mcp` (`resources/read` of `frob://catalog/retrofits`) and the `--facility` report through `frob --json`; the catalog's `CONTRACT.md` section states that zeros are never substituted for missing facility data.

## Test plan

### Unit tests
`crates/frob-scene/tests/retrofit_facility.rs`; the real catalog loader; entries labelled `synthetic` where planted.
- `facility_schema_roundtrip`: every field; unknown access kind refused.
- `absent_table_is_unpriced`, `partial_table_lists_missing`.
- `retrofit_search_ignores_facility`: kit enumeration and prices equal with and without the tables.
- `band_vertex_check_ramp`: the hand case, with the violating vertex returned.
- `band_minimum_nominal_run`: 269 mm.
- `non_monotone_constraint_interval_fallback`: a planted constraint `a_m * b_m >= a_m + 1` is decided by interval evaluation or refused as undecided, never accepted on vertices alone.
- `annualization_exact`: the two hand cases in exact rationals.
- `install_class_tool_consistency`.
- `weakest_provenance_propagates`: one `assumed` sub-table makes the terms `assumed`.
- `calibration_invalidates_registered_kinds`: an unknown measurement kind is refused.

### End-to-end script and logging
`scripts/e2e/scene_retrofit_facility.sh` (sources the STD-E2E helper; idempotent):
1. `resources/read` of `frob://catalog/retrofits` through `frob-mcp`: assert the `facility` table of `threshold-ramp` and its provenance.
2. `frob scene retrofit --apply threshold-ramp:rise_m=0.02,run_m=0.24,width_m=0.9 --at door:D1 --scene s:threshold-20mm --facility --key rf-1 --json` (`s:threshold-20mm` is the synthetic 20 mm threshold fixture of N19b-40): assert `as_installed: violated` with the vertex (0.022, 0.235); with `run_m=0.269` and `--key rf-2`: `as_installed: ok`; the same call without `--facility` (`--key rf-3`): the report is byte-identical to N19b-40's `--apply` report.
3. `frob scene retrofit --evidence <failing verdict> --permit landlord --key rf-4 --json` on the shipped catalog, which carries the facility tables: assert the kit report carries no `facility` block and prices each kit from the entries' `cost` alone (the comparison with a catalog without the tables is step 4's).
4. The two catalog copies (one without the tables; one with a planted entry whose `upkeep` sub-table is removed, `synthetic`) are run as the unit tests `retrofit_search_ignores_facility` and `partial_table_lists_missing` by name (`cargo test -p frob-scene --features frontier-retrofit --test retrofit_facility -- <name>`, one `assert` line each, the second asserting `Unpriced { missing: ["upkeep"] }`, never zeros), because `registries/retrofits.toml` is an embedded registry (N32ax-03's class for a file whose owner states none) that no scratch registries root reaches through the binary. The facility query's own check that every world edit in an answer carries facility terms and that an unpriced entry appears among the omitted options with its disposition belongs to the grammar bead N25c-31, which depends on this one; this bead supplies the planted-unpriced catalog copy as a fixture for it.
Logged per STD-E2E: command, exit code, wall time, evidence block, catalog version, the band vertices
with both sides of the constraint, annualized values with units, and on failure the first differing field.

### Known answers and negative controls
- The ramp band: 12 × 22 mm = 264 mm > 235 mm; minimum nominal run 12 × 22 + 5 = 269 mm.
- Annualization: 8 USD × (12 / 6) = 16 USD per year; 40 USD / 5 = 8 USD per year and 12 × 0.1 h = 1.2 h per year.
- Negative controls: a converter that substitutes zero for a missing table (the unpriced test fails); a band check at the nominal point only (the ramp case passes wrongly); annualization that ignores service life (the tape returns 0 USD per year).
- Metamorphic: scaling every duration by a factor scales every time term by it and no money term; shrinking every tolerance to zero makes the band check equal the nominal check.
- Determinism: exact (D0) across platforms, debug and release.

## Considerations

- The work exists only if the facility query is funded: the kill gate KILL-AUGUR-FACILITY decides between the multi-room shift and single-robot world edits only; on the second branch the table is still read (single-robot world edits are priced edits), so this bead survives both, and falls away only if the mission layer drops world edits altogether.
- If KILL-RETROFIT fired at M4 the search verb was withdrawn but the catalog remains as an edit vocabulary; the facility table attaches to that vocabulary unchanged. The `--facility` report goes with the verb: the script's `scene retrofit` steps then assert `FROB-REF-724` with `reason: killed: KILL-RETROFIT`, and the band check and the terms are exercised by this bead's unit tests and through `facility_terms` by the facility query (N25c-31).
- Access and floor conditions are inputs to a schedule, not costs; pricing downtime is the caller's scalarization.
- Tolerances here are installation tolerances of the building amendment. Part tolerances of robot edits come from the robot's own cards and the manufacturing subsystem.
- All numbers are `assumed` and local to a market; the owner decision on sources applies to this table as it does to prices.
