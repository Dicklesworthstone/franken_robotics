## Background

Habitat (crate `frob-scene`, workspace layer 2) owns every part of a world that is not the robot. A **scene pack**
(`ScenePack`, manifest `.fscene`, identity `SceneId`) is the compiled, immutable form of one place. The **scene compiler**
turns source geometry (constructive solids from a generator, or an imported mesh scene) into a pack. It is a CPU job with
eleven fixed stages, each of which writes a **receipt** into the pack's acceptance report, so that every pack can say
how it was made and what was lost or assumed. This bead is the compiler's driver, the stage that emits distance
bricks, and the three verbs through which an agent compiles and reads packs. It is Solid tier and the first runnable
Habitat capability: terrain generators, interiors, the brick pool, contact kernels and ray kernels all consume its output.

Decisions that govern it (each with its reason and the rejected alternative):

- **ADR-HAB-01.** Static geometry is a truncated signed-distance field φ (metres, positive outside solids) stored in
  bricks and sampled by manual trilinear interpolation written in kernel source. Reason: a distance field answers "how
  far, and which way" in constant time for any query point, which thousands of worlds need. Rejected: hardware texture
  filtering (fixed-point weights differ between vendors and break bitwise determinism).
- **ADR-HAB-02.** A feature smaller than a voxel is an analytic overlay, never a voxel. Thresholds, rug edges, cable
  covers and grate slots are millimetres to centimetres; a 2 cm lattice cannot represent them, and they decide missions.
- **ADR-HAB-04.** The visual mesh (GLB) is read by the viewer only; physics, sensors and stills read the collision
  field (INV-HAB-02: no code path carries visual-mesh data into a result).
- **Scales are baked at compile time.** The compiler bakes every instance scale before it computes a field, so a
  compiled pack is in world metres. Rejected: carrying scaled instances to query time, where a local distance d only
  bounds the world distance to [σ_min(A)·d, σ_max(A)·d] for the instance's linear part A.
- **The airlock.** FrankenSim (sibling repository `frankensim`, pinned at `483d09c682f2`) supplies the distance
  machinery. FACT: `fs-rep-sdf` provides `TiledSdf` (dense Morton-tiled grids with a constructed error enclosure and
  sphere-traced raycasts), `VdbGrid` (a sparse tile tree with deterministic iteration order), `NarrowBand` and
  `AdaptiveSdf`; `fs-rep-mesh` provides generalized winding numbers (exact, and an octree approximation with measured
  error), a BVH mesh chart with watertight ray tests and a repair pipeline with receipts; `fs-rep-frep` provides
  constructive solids as a DAG with value, gradient, a Lipschitz bound and an interval range; `fs-topo` provides
  manifold and self-intersection certificates. These crates depend on FrankenSim's unit crate `fs-qty` only through
  their evidence manifests, so they carry the toolchain risk tested at INT-TOOLCHAIN-01. All FrankenSim code is reached
  only through one crate, `frob-fsim` (the airlock), which converts types at the boundary and can run the sibling in
  process or in a worker process; no FrankenSim type appears in `frob-scene`'s public surface.

## Technical approach

**1. The eleven stages (fixed order; each returns `Result<StageReceipt, Refusal>`).**
1. Decode under limits (bytes, instance nesting depth, polygon, texture and material counts bounded by the import
   profile; relative references resolve inside the pack; missing assets and unit conversions recorded; `FROB-REF-303`).
2. Build the metric transform graph (explicit axis, handedness and unit matrix per source format; negative and
   non-uniform scales baked before any support map or mass property; winding checked against the sign of the
   determinant; transform class established or `FROB-REF-302`).
3. Tag each part: support, keep-out, movable, jointed, optical-only, transparent, deformable-by-proxy or unknown; a
   door leaf is split from its static jamb with hinge limits, friction and swept volume.
4. Check watertightness and orientation, then compute signed distance through the airlock; a failing scene is refused
   (`FROB-REF-301`), not patched; explicit repair records each closed hole (`derived: hole-fill`) and makes its
   neighbourhood an unknown region.
5. Emit bricks, the directory and the pool, with a recorded error bound per brick (this bead, item 3).
6. Emit analytic overlays for every part tagged sharp or thinner than two fine voxels, and the overlay index (0.64 m
   cells, eight slots each; over capacity is `FROB-REF-306`).
7. Emit the region table and the maps: interface, optical, semantic, and for ingested scenes the unknown mask.
8. Compile fixtures and movables through the model compiler, settle the movables on the referee until kinetic energy
   falls below a threshold, and store the settled poses so a reset does not start with falling clutter.
9. Check spawn poses for interference and tip-over; compute the clearance complex for the nominal footprint; write the
   feasibility tag.
10. Run the acceptance fixtures.
11. Freeze: `SceneId` is the hash of the manifest, the compiler version and settings, units, tolerances, brick
    contents, overlays, maps and fixture tables. Device resources are allocated later, by the worker that loads the pack.

**2. Driver (DESIGN sketch).**

```rust
pub struct CompileRequest { source: SourceRef, settings: CompileSettings, profile: ImportProfile, repair: RepairMode }
pub struct CompileSettings { fine: Length /*0.02*/, coarse: Length /*0.16*/, truncation: Length /*0.08*/,
                             overlay_cell: Length /*0.64*/, overlay_slots: u8 /*8*/, brick_layout: u16 }
pub trait Stage { fn id(&self) -> StageId; fn run(&self, cx: &mut CompileCx, job: &dyn JobContext) -> Result<StageReceipt, Refusal>; }
pub struct StageReceipt { stage: StageId, inputs: Vec<Blake3>, outputs: Vec<Blake3>, counts: BTreeMap<String, u64>,
                          bounds: BTreeMap<String, f64>, notes: Vec<Note>, wall_ms: u64 /* sidecar, not identity */ }
pub fn compile(req: &CompileRequest, sink: &mut dyn BrickSink, svc: &dyn SceneServices, job: &dyn JobContext)
    -> Result<ScenePack, Refusal>;
```

`SceneServices` is a trait defined in `frob-scene` and supplied by the verb executor for the stages that need crates
above layer 2 (the referee for stage 8, ray kernels and batched tiers for stage 10); `frob-scene` links nothing above
its layer. Stages and parts of stages that have not landed at M2 (the optical map and the shared latents of stage 7,
which are BD-229's; stage 8; the clearance complex and feasibility tag of stage 9; stage 10) write a receipt
`skipped: not-yet-landed`, the manifest's feasibility tag reads `not-computed`, and the pack is marked `acceptance:
incomplete`. Until the acceptance check lands at M3 (BD-228) no run verb reads the report, so M2 runs bind such
packs; from M3 the check refuses any pack whose report is incomplete (`FROB-REF-318`), no flag skips it, and a
fixture pack gets past it the way every pack does, by being accepted (`scene.accept`, which the script helper
`e2e_scene_ready` calls). Stage 11 is never skipped, because without it there is no `SceneId`: until the freeze
bead N19a-20 lands (it depends on this bead), the driver's own freeze takes the identity by BD-162's rule over the
manifest as written and publishes the pack directory by one atomic rename; N19a-20 adds the check that every
hashed component is present before the hash is taken, the sealing of the directory and the rule that a second
compile with the same identity verifies the sealed pack instead of rewriting it. Progress is reported as stages
completed of eleven. Cancellation is honoured at stage boundaries and inside stage 5 between coarse slabs: the
driver drains, removes its temporary blobs and publishes nothing (no partial pack is ever visible).

**3. Stage 5: brick emission, as numbered steps.**
1. Lay the dense **coarse** lattice of spacing S (default 16 cm indoors) over the scene's bounding box, origin snapped
   to a multiple of S so that repeated modules land on the lattice.
2. For every coarse node evaluate the source chart's signed distance through the airlock (`fs-rep-frep` value for
   constructive solids; the BVH mesh chart with generalized-winding sign for meshes). Store the coarse sample in 16
   bits over the manifest's coarse range.
3. Mark as **band** every coarse cell within the truncation distance T (default 4 fine voxels = 8 cm) of a surface:
   a cell is in the band if any of its corners has |φ| ≤ T + (√3/2)·S (a conservative test using the unit Lipschitz
   constant; the over-inclusion is the "brick rounding" counted in the memory model).
4. For each band cell sample 8³ fine nodes at spacing s = S/8 (default 2 cm), node-registered at the cell origin plus
   (i, j, k)·s; apply the named truncation clamp(φ, −T, +T); quantize to 16 bits with step 2T/65,535 (2.44 µm at
   T = 8 cm); build the region palette (at most four region identifiers, a two-bit selector per sample; a brick that
   touches more than four regions is recorded and uses the nearest-region rule).
5. Record the brick's bound = ε_chart (the airlock's enclosure of the source chart) + ε_tri (trilinear interpolation
   error on the brick lattice) + half a quantization step. Until the verification bead N19a-14 tightens ε_tri per brick,
   the driver records for ε_tri the a-priori Lipschitz value (√3/2)·s (the trilinear interpolant of any 1-Lipschitz
   function differs from it by at most the half-diagonal of a fine cell, 17.3 mm at s = 2 cm) for a brick that contains
   a sharp feature of the source (an edge or a vertex of the surface), and for every other brick the measured residual
   at the fine-cell centres, labelled `Tested` in the receipt until N19a-14 replaces it with a derived bound. PO-HAB-01 is the obligation the bound must meet: the
   device field differs from the source chart by at most the bound everywhere in the brick.
6. Hand each brick to the `BrickSink` and write, per coarse cell, a directory entry: a 32-bit pool slot, or one of the
   two sentinels "far outside" and "deep inside". This bead's sink writes one private pool per pack, every band brick
   in emission order with no sharing; the content-addressed sink (BD-164, which depends on this bead) implements the
   same trait and replaces it as the default when it lands, which is a compiler-version change and therefore changes
   every `SceneId`, as any compiler change does.
7. Emit the receipt: band-brick count, sentinel counts, the largest and the 99th-percentile bound, bricks with
   palette overflow, bytes written.
Iteration is in lexicographic (z, y, x) cell order and parallel work is merged in that order, so output bytes do not
depend on worker count (class D0 for pack bytes).

## Considerations

- Toolchain risk: the representation crates may not build on the one toolchain; the fallback is the worker-process mode of the airlock, exercised before it is needed. Compile time then includes process start and serialization.
- The band test over-includes by up to one coarse cell; the measured band width (8 to 20 voxels including rounding) feeds the memory model and KILL-POOL.
- OPEN-HAB-2 (brick apron) and OPEN-HAB-3 (default spacings) change `CompileSettings`, not the driver.
- Stage 8 stores poses from a dynamics run; cross-platform identity then depends on the referee's determinism (handled in the stage-8 and freeze beads).
- A pack with `acceptance: incomplete` is not runnable once the acceptance check exists: the refusal is `FROB-REF-318` (the row entered by N19c-42), raised by the check BD-228 lands at M3, and it cannot be skipped by any flag, for a fixture no more than for any other pack. Before M3 there is no check, and the M2 scripts run on unaccepted packs; BD-228 converts them to accept their packs first (`e2e_scene_ready`) in the change that switches the refusal on.
- Performance envelope: no compile-time target is stated; the receipt records wall time per stage so that one can be set.
