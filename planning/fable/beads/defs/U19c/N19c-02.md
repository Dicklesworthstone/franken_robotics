## Background

A scan or a video reconstruction has shape before it has size. A simulation is metric: forces, clearances and speeds
are in SI units, so a scene whose size is unknown cannot carry a metric task. Habitat therefore gives every ingested
scene a **scale label**, one of four values ordered by authority. The vocabulary matches the reconstruction project's
own (FACT: `fdgr-scale` in `franken_drone_geometry_reconstruction` defines `relative_only`, `estimated`, `witnessed`,
`surveyed`; its `scale_model` schema records a scale authority with residuals in parts per million).

| Label | Meaning | What a task may do with it |
|---|---|---|
| `relative-only` | Shape without a metric scale | Viewing only; every metric task is refused (`FROB-REF-304`) |
| `estimated` | Scale inferred from priors such as typical door heights | Exploratory runs; clearance verdicts are `unresolved` within the stated scale interval |
| `witnessed` | Scale fixed by an object of known size or a measured baseline in the capture | Metric tasks, with the witness's uncertainty in u_reg |
| `surveyed` | Scale and registration from an independent survey | Metric tasks at survey accuracy |

Reason for a label instead of a number: a number without its authority is read as a measurement. The label travels
with the pack, bounds what any task may claim, and is the quantity the kill gate of ingestion reads (the real-place
gate must pass with `witnessed` or better). Rejected alternatives: silently assuming metres (a 3% scale error turns a
0.80 m door into 0.776 m, enough to reverse a fit); refusing everything below `surveyed` (no walkthrough capture would
ever be usable). Tier Frontier; first needed at M5 with the first real place, and by `scene.fit` on ingested scenes.

## Scope

In: the `ScaleLabel` type and its order; the scale record in the manifest; how a label is established; the mapping
from the upstream vocabulary; the task-side requirement and `FROB-REF-304`; how scale uncertainty enters clearance
bounds; what reports may say. Out: registration by four landmarks (N19a-21); the unknown mask (N19c-03); the importer
(N19c-04, BD-398); the clearance complex itself (N19b-26 onward).

## Technical approach

**1. Types (DESIGN sketch).**

```rust
#[derive(PartialOrd, Ord)]                     // authority order: RelativeOnly < Estimated < Witnessed < Surveyed
pub enum ScaleLabel { RelativeOnly, Estimated, Witnessed, Surveyed }
pub enum ScaleAuthority { Generated, Ingested(ScaleRecord) }          // a generated scene is metric by construction
pub struct ScaleRecord { label: ScaleLabel, factor: f64 /* source units to metres */,
                         rel_interval: (f64, f64) /* c_lo/c, c_hi/c */, witness: Option<ScaleWitness>,
                         survey: Option<SurveyRef>, prior: Option<PriorRef>, source_status: String }
pub struct ScaleWitness { kind: WitnessKind /* KnownObject | MeasuredBaseline */, true_size: Length,
                          measured_in_capture: f64, uncertainty: Length, feature_id: String }
```

The manifest's optional `ingest` block stores the record; `provenance.scale` is `generated` or the label.

**2. Establishing a label (first rule that applies; the evidence is recorded with the pack).**
1. `surveyed`: an independent survey supplies scale and registration (a survey reference with instrument and date).
2. `witnessed`: at least one object of known size or one measured baseline appears in the capture, with a stated
   uncertainty; the relative half-width is ε_c = uncertainty / true_size (plus the capture's own reprojection term
   when the upstream record gives one, in parts per million).
3. `estimated`: scale inferred from priors (typical door heights, counter heights); the prior and its interval are
   recorded; DESIGN default interval ±5% when the prior gives none, and the pack counts the dimension as `assumed`.
4. `relative-only`: none of the above.
A label is never raised in place: adding a witness is a new import and a new `SceneId` (packs are immutable).
Upstream mapping: `relative_only → RelativeOnly`, `estimated → Estimated`, `witnessed → Witnessed`, `surveyed →
Surveyed`; any other or missing status is `RelativeOnly` (fail-closed). A geometry generation whose scale status is
not metric is refused for physics use.

**3. The task side.** A task declares the scale authority it requires. DESIGN defaults: any task whose requirement or
reward has a dimensional predicate (length, force, speed, energy) requires `witnessed`; a task marked `exploratory`
accepts `estimated`; a pure viewing or topology task accepts `relative-only`. Binding a task to a scene whose label is
below the requirement is `FROB-REF-304` "Scale authority is below what the task requires": block `observed` (the
scene's label and record), `required` (the task's level); ranked repairs: add a scale witness; choose a non-metric
task. Exit 3. The check runs at task binding, at `sim.run` admission and in `scene.fit`.

**4. Scale uncertainty in clearance bounds.** The cell error of a clearance complex is
e = (Δ/2)·√2 + ρ·(δ/2) + ε_field + u_reg, with Δ the translation edge, δ the heading width, ρ the footprint's reference
radius, ε_field the field bound and u_reg the registration uncertainty of an ingested scene. This bead supplies the
scale part of u_reg. Derivation (DESIGN): scaling the scene by a factor (1 + ε) about a footprint's reference point
moves an obstacle point at distance r by ε·r; the nearest obstacle lies within ρ + c of the reference point when the
clearance is c ≥ 0; so the clearance changes by at most ε·(ρ + c). Hence

  u_scale(q) = ε_c·(ρ + max(c(q), 0)),   u_reg = r_landmark + u_scale,

where r_landmark is the largest residual of the four-point registration. For `witnessed` and `surveyed` the witness's
or the survey's ε_c is used and verdicts are metric. For `estimated` the same formula is applied with the prior's
interval, which is what makes a clearance verdict `unresolved` inside the stated scale interval; a verdict that
survives it may be reported as exploratory only. Worked numbers: a witness of 0.800 m known to ±4 mm gives ε_c = 0.5%;
with ρ = 0.40 m and a 30 mm clearance, u_scale = 0.005 × 0.43 = 2.2 mm. An `estimated` scale of ±5% gives 21.5 mm,
which swallows most doorway fits.

**5. Reports.** Every report on an ingested scene prints the label. A Reality claim about the place requires
`witnessed` or better and whatever the Reality lane requires besides; with `estimated` the Reality cell is `no-claim`.

**6. Layout.** `crates/frob-scene/src/ingest/scale.rs`; the refusal is raised by `frob-scene` and by the task binder
through one function `require_scale(scene, level)`.

## Acceptance criteria

- [ ] The four labels order by authority and round-trip through the manifest; an unknown upstream status maps to `relative-only`.
- [ ] A metric task bound to a `relative-only` pack is refused with `FROB-REF-304` (exit 3) at binding, at run admission and in `scene.fit`; adding a witness (a re-import) makes the same binding succeed.
- [ ] On an `estimated` pack a doorway fit whose margin is inside ε_c·(ρ + c) returns `unresolved`; the same geometry labelled `witnessed` with ε_c = 0.5% returns a witness.
- [ ] The scale term enters u_reg of every clearance cell of an ingested scene and is recorded in the `.fclear` manifest.
- [ ] A label cannot be changed without changing `SceneId`.
- [ ] Reports on ingested scenes print the label; a realism or Reality statement on an `estimated` scene is `no-claim`.
- [ ] `CONTRACT.md` carries the label table and the u_scale derivation.

## Test plan

### Unit tests
`crates/frob-scene/tests/scale_label.rs`; fixtures `synthetic`.
- `label_order`: `RelativeOnly < Estimated < Witnessed < Surveyed`.
- `upstream_mapping`: the four upstream strings map as stated; `"metric"`, `""` and a missing field map to `RelativeOnly`.
- `witness_epsilon`: true 0.800 m, uncertainty 0.004 m → ε_c = 0.005.
- `u_scale_values`: ε_c = 0.005, ρ = 0.40, c = 0.03 → 2.15 mm; ε_c = 0.05 → 21.5 mm; c < 0 uses ρ only.
- `u_scale_bound_holds` (property): for random convex obstacles and footprints, recompute clearance after scaling the scene by 1 ± ε about random origins; |Δc| ≤ ε·(ρ + c) + round-off.
- `metric_task_refused_on_relative_only`: `FROB-REF-304` with the label in `observed`.
- `exploratory_task_admits_estimated`; `viewing_task_admits_relative_only`.
- `label_change_changes_scene_id`.
- `estimated_default_interval_counts_assumed`: a prior without an interval records ±5% and increments `dimensions_assumed`.

### End-to-end script and logging
`scripts/e2e/scene_scale_labels.sh` (STD-E2E helper): on a synthetic "as-captured" room exported at an unknown scale,
(1) import with no witness and bind a navigation task: expect exit 3, `FROB-REF-304`; (2) import with a prior: run
`frob --json scene fit` on a 0.80 m door with a 0.70 m base and expect `unresolved` with the scale interval named;
(3) import with a witness: expect a witness path and `u_reg` in the certificate. Each NDJSON line has the command,
exit code, wall time, evidence block, the label, ε_c, `u_reg_m` with its components, and the verdict; logs under
`target/e2e-logs/scene_scale_labels/`. The real private place is exercised by the gate script (N19c-07).

### Known answers and negative controls
- Known answers: the table's four behaviours; the two worked u_scale values (2.2 mm, 21.5 mm).
- Negative controls: a build that treats `estimated` as metric must fail step (2); a build that omits u_scale from the cell error must return a witness where `unresolved` is expected.
- Metamorphic: rescaling the source by k and the witness's true size by k leaves every verdict unchanged.
- Determinism: labels, records and refusals are data (D0).

## Considerations

- The ±5% default for an unstated prior interval is a DESIGN proposal to be confirmed with the first real place.
- A witness far from the region of interest can have a larger effective error (lens distortion, drift); the upstream record's per-region uncertainty, where present, overrides the single ε_c.
- OPEN-HAB-5 (which reconstruction package and version is the import contract; default the walkthrough twin package, the drone route when it publishes geometry) decides where the scale record comes from; this type is independent of the choice.
- KILL-INGEST reads this label: the real-place gate must pass at `witnessed` or better, or the place is authored as a surveyed proxy.
- Private data: a scale record names features of a private place and inherits the private mark.
