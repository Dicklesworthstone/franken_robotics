## Background

Real-place ingestion [F] lets a candidate be evaluated in one particular place: a walkthrough or a scan becomes a
private scene pack. It adds nothing to decision speed; it is the precondition for any Reality claim about that place
(North-Star scenario: a walkthrough video becomes a private scene pack through the owner's reconstruction pipeline, a
home robot is evaluated in it, scale is labelled, unseen surfaces are treated conservatively and listed as a re-scan
request, and the scan never leaves the machine).

**Sources (FACT).** Two pipelines exist in the owner's projects. (1) A route from walkthrough video to an agent-built
Blender twin with stable feature identifiers and a GLB export, with an accepted plan for a **twin package** that links
visual, geometric and traversability representations (`franken_surveillance_system/BLENDER_TWIN_INTEGRATION_PLAN.md`).
(2) `franken_drone_geometry_reconstruction` (at `db45703afc5e`), a reference workspace for drone video whose chain
today runs from media custody through clocks, calibration, scale witnesses, keyframes, correspondences and relative
pose to an audited relative bundle problem; its own status file says it does not yet optimize cameras, emit metres or
publish geometry. DESIGN: `scene.import` consumes the twin package first, and the drone route when that project
publishes geometry (OPEN-HAB-5). Changes to either are upstream work items in their own repositories under their own
rules (FD-FSS-01 for the twin package; FD-FDGR-01 for the drone route), never edits made from here.

**Materials are not inferred from appearance.** An unprobed surface gets an interface card of class `assumed` with a
wide friction interval, which the adversarial search explores. No friction, compliance or optical value is estimated
from an image. Reason: a glossy tile can be grippy and a matte one slick; an appearance model would fabricate a
physical property and the pack would cite it. Rejected: learned material estimation from images, in any tier.

## Scope

In: the source adapters' common intermediate form; the import pipeline for a real place on top of the compiler; what
import adds (registration, cards marked `assumed`, articulation when supplied, the unknown mask, the scale label); the
loss report; the private-pack rule. Out: the verb registration and the suite admission test (BD-398); four-point
registration itself (N19a-21); scale labels (N19c-02); the unknown mask (N19c-03); probe requests (N19c-05); the asset
lane of `scene.import` and the loss report schema, which this bead extends with its real-place rows (N19a-46);
populated interiors (BD-399).

## Technical approach

**1. Intermediate form (DESIGN sketch).** Every adapter produces one value; nothing downstream knows the source.

```rust
pub struct IngestSource { geometry: MeshScene /* with stable feature ids */, frame: SourceFrame,
                          landmarks: Vec<Landmark /* id, source xyz, scene xyz */>, scale: Option<ScaleEvidence>,
                          coverage: Option<CoverageField>, articulation: Vec<HingeHint /* axis, limits, leaf id */>,
                          measured_cards: Vec<(FeatureId, CardRef)>, package_digest: Blake3 }
pub trait IngestAdapter { fn read(&self, root: &PrivateDir, profile: &ImportProfile) -> Result<IngestSource, Refusal>; }
```

Adapters: `TwinPackageAdapter` (first; the walkthrough route); `DroneGeometryAdapter` (a schema adapter only, with no
crate dependency on the sibling: it reads the published `geometry_generation` record, whose required fields are
`coordinate_frame`, `scale_status`, `representations`, `uncertainty_root`, `coverage_root`, `publication_stage`, and
the `scale_model` record; it is enabled when the sibling publishes geometry, then driven as a subprocess); and the
fallback `MeshOperatorAdapter` (a mesh or point cloud with the scale declared by the operator; the result is labelled
`reality: no-claim`).

**2. Pipeline, as numbered steps (`frob_scene::ingest::import_place`).**
1. Read the package inside the private root under the import profile's decode limits (`FROB-REF-303`).
2. Establish the transform class by four-point registration: four non-coplanar correspondences determine the affine
   map; its linear part L must satisfy LᵀL = c²·I within tolerance and det L > 0, c must match the scale evidence, and
   the landmark tetrahedron must have a volume of at least 1% of the cube of the largest separation
   (`FROB-REF-302` otherwise; three landmarks accept a mirrored room).
3. Run the compiler's stages on the registered geometry: metric transform graph, tagging, watertightness (explicit
   repair only; each closed hole recorded and its neighbourhood made unknown), bricks, overlays.
4. **Cards.** For each surface region: a measured card supplied by the package is attached with provenance
   `measured`; otherwise the region gets an interface card and an optical card of class `assumed`. The assumed
   interface card's friction interval is the union of the generic catalog's intervals for indoor floor materials over
   all conditions (DESIGN; wide by construction), flagged for adversarial search. The pack counts assumed regions.
5. **Articulation.** Where a hinge axis and limits are supplied for a door, drawer or cabinet leaf, the part is split
   from its jamb and compiled as an articulated fixture with the supplied limits and `assumed` closer, latch and
   friction parameters. Where none is supplied the part is static and the loss report says `articulation: not supplied`.
6. **Unknown mask** from coverage, unseen undersides and hole fills (N19c-03).
7. **Scale label** from the scale evidence (N19c-02).
8. Feature identifiers of the package become semantic labels, so a bottleneck can be named "door D3".
9. Acceptance (the scene acceptance report), then freeze as a **private** pack.

**3. The loss report** (`frob.scene.import.loss/1`, the schema defined with the asset lane in N19a-46; part of the pack;
the landmark, transform-class and scale rows are added here): elements dropped or not
representable, unit and axis conversions, parts with no collision counterpart (tagged `optical-only`), holes repaired
with receipts, landmarks used with residuals, the transform class, regions with `assumed` cards (count and area),
articulation supplied or not per movable part, the unknown fraction of the bounding volume, the scale record.

**4. Privacy.** A pack built from a real home or workplace is marked `private`, stored under the configured private
root outside the repository, absent from catalogs without the private scope, and everything derived from it (stills,
replays, reports, fixtures, policy weights) inherits the mark by lineage. Private scans do not cross machines; a job
that needs one runs where it lives. Logs carry digests, never content.

**5. Evidence.** Geometry: Known answer against the package's mesh at the recorded bounds, class `Tested`. Anything
about the real place: `no-claim` unless the Reality lane has data. The three no-authorization flags are `false`.

**6. Layout.** `crates/frob-scene/src/ingest/{source.rs, twin.rs, drone_schema.rs, mesh_operator.rs, place.rs, loss.rs}`.

## Acceptance criteria

- [ ] A synthetic twin package (labelled `synthetic`, shaped like the real one) imports end to end to a private pack with a loss report, a scale label and an unknown mask.
- [ ] The mirrored variant of that package is refused by four-point registration (`FROB-REF-302`); with only three landmarks the import is refused, not accepted.
- [ ] Every region without a measured card has interface and optical cards of class `assumed`; no card value is derived from pixel data (code audit plus a test that changing every texture leaves all cards unchanged).
- [ ] A door with a supplied hinge axis and limits is an articulated fixture; without them it is static and listed in the loss report.
- [ ] The pack is written only under the private root; `scene.list` without the private scope does not show it; a derived still inherits the mark.
- [ ] The drone schema adapter validates the published schema fixtures and refuses a non-metric scale status.
- [ ] `CONTRACT.md` states the sources, the postures, and "materials are not inferred from appearance" as an invariant.

## Test plan

### Unit tests
`crates/frob-scene/tests/ingest_place.rs`; all fixtures synthetic.
- `twin_adapter_reads_intermediate_form`: landmarks, scale evidence, coverage and one hinge hint are populated.
- `registration_rejects_mirror`: source mirrored in z; residual at the fourth landmark 2.0 m for the unit tetrahedron; `FROB-REF-302`.
- `three_landmarks_refused`.
- `assumed_cards_everywhere`: 40 regions, 3 with measured cards: 37 assumed interface cards and 37 assumed optical cards; `dimensions_assumed` and the assumed-region count match.
- `textures_do_not_move_cards`: replacing all textures with noise changes no card and no physics digest.
- `assumed_interval_contains_catalog`: the assumed friction interval contains every floor card of the generic catalog.
- `hinge_supplied_articulates`, `hinge_missing_static_and_reported`.
- `loss_report_complete`: every category present, counts consistent with the pack.
- `private_root_only`: an output path outside the private root is refused by the path jail.
- `drone_schema_non_metric_refused`: `scale_status: relative_only` is refused for physics use.

### End-to-end script and logging
`scripts/e2e/scene_import_place_synthetic.sh` (STD-E2E helper): `frob --json scene import --kind place
fixtures/ingest/synthetic-twin/ --private-root $TMP/private`; `frob --json scene show <id> --loss`; `scene list`
without and with the private scope; the mirrored package (expect exit 3). NDJSON lines: command, exit code, wall
time, evidence block, landmark residuals, the scale label, assumed-region counts, unknown fraction, digests; on
failure the first failing stage receipt. Logs under `target/e2e-logs/scene_import_place_synthetic/`. The run on the
owner's real place is the gate script (N19c-07) and logs digests only.

### Known answers and negative controls
- KA-429 and CX-184 (mirror through the plane of three landmarks; residual 2 m). CX-185 (a gravity witness is not a fourth point).
- Negative controls: an importer that estimates friction from albedo must fail `textures_do_not_move_cards`; one that writes `diffuse` silently for a region with no card must fail the assumed-count check; one that writes the pack to the project tree must fail `private_root_only`.
- Determinism: the same package and settings give the same `SceneId` on Linux and macOS.

## Considerations

- OPEN-HAB-5 (owner Habitat lead; blocks the real-place gate): which reconstruction package and version is the import contract. Fail-closed default: the walkthrough twin package; the drone route when it publishes geometry.
- KILL-INGEST: if the real-place gate cannot pass with a scale label of `witnessed` or better after one repair cycle, the place is authored as a surveyed proxy in the interior grammar (N19c-06).
- The twin package's format may change upstream; the adapter pins a package version and refuses others.
- The wide assumed friction interval makes most slip-sensitive verdicts unresolved on purpose; the remedy is a probe request, not a narrower guess.
- Policy weights trained in a private scene inherit its mark by default (an open safety question asks whether that is stricter than wanted).
