## Background

An ingested place is known only as well as it was captured. When an answer about it cannot be decided, the studio does
not guess. It says what to measure. Verb: `scene.probe-request`. When a clearance verdict is `unresolved` because of
registration or scale uncertainty, when the inner and outer answers of a mission query differ because of an unknown
region, or when a decision reverses inside the interval of an `assumed` card, the studio emits a request that names the
three-dimensional box to rescan or the surface to probe, the quantity needed and the accuracy that would settle the
decision ("the clear width of door D3 to ±5 mm"). **The request is the output; nothing is assumed in its place.**

Why this design: the alternative, picking the nominal value and running, turns an unknown into a silent assumption that
later reads as a result. A request converts uncertainty into the cheapest next action for a person with a tape measure
or a phone. It is the scene-level form of the rule that a measurement is asked for when, and only when, it can change a
decision: measuring the target directly at mission conditions is always an admitted probe, whereas designing an
instrument that separates competing mechanisms is the separate verb `mission.distinguish`. This verb designs nothing;
it names the quantity. Tier Frontier, first milestone M5, kind `read`.

Why it also sits beside probe design: it is the scene-side twin of `mission.distinguish`. That verb designs an
instrument to separate mechanisms; this one names the survey that separates worlds. Both follow the same rule
(partition by the decision each possibility implies, and ask only for what can change the decision), and both
feed `experiment.suggest` as `measure` proposals. Materials are never inferred from appearance: an unprobed
surface carries a card of class `assumed` with a wide friction interval, and a request is the way to narrow it.

The verb lands at M5 with real-place ingestion. The request record it returns is produced earlier, inside
unresolved mission answers (as the `NeedsMeasurement` explanation), so authored scenes with `assumed` cards can
already yield requests through `mission.distinguish` and `experiment.suggest` at M3 and M4.

One bead for the verb. The mission chapter drafted the same verb a second time (N25c-19); that bead is
superseded by this one and its content is folded in: the record's multiple thresholds, the `settles` list and
the text line, the algorithm that finds the quantity from the dependency support of the competing answers, the
threshold-gap rule and the instrument ladder for the accuracy, the merge of requests on one quantity, the
hand-off from unresolved mission cells, and its fixtures and controls.

## Scope

In: the request record and its schema, defined once; the three triggers and the function each calls; the algorithm
from an unresolved item to a request (the quantity, its thresholds, the accuracy, the location, merging and
ordering); the accuracy rule; standing requests per scene and their closure; the hand-off from unresolved mission
cells; the verb, its envelope and its privacy handling. Out: probe and instrument design (`mission.distinguish`,
BD-291); deciding clearance (N19b-32, BD-233) and mission answers; ingestion, scale labels and the unknown mask
themselves (BD-398, N19c-02, N19c-03, N19c-04); the retrofit catalogue (BD-369); performing or importing a
measurement (a re-import through N19c-04, or the Reality lane).

## Technical approach

**1. The record** (`frob.scene.probe-request/1`; one layout).

```json
{ "schema": "frob.scene.probe-request/1", "id": "pr:b3:…", "scene": "b3:9c1e…", "private": true,
  "trigger": "clearance-unresolved",
  "target": { "kind": "box", "feature": "door D3", "box_m": [[4.10, 2.00, 0.00], [5.10, 2.30, 2.10]] },
  "quantity": "clear_width", "unit": "m",
  "current": { "nominal": "0.812", "interval": ["0.790", "0.834"], "limited_by": ["u_reg", "scale"] },
  "thresholds": [ { "value": "0.800", "below": "impossibility cut at door D3", "above": "witness" } ],
  "accuracy": "0.005", "settles": ["ref to the unresolved answer"],
  "text": "the clear width of door D3 to ±5 mm", "status": "open" }
```

DESIGN, settling the two drafts of this record. (a) The type is defined once, in `frob-core` (`ProbeRequest`,
with `Box3`, `SurfaceRef`, `QuantityRef`, `Interval`, `DecisionRef` and `VerdictRef` as its field types), because
both `frob-mission` (unresolved cells, from M3) and `frob-scene` (clearance and cards) emit it and neither
depends on the other for it; the derivation functions live in `frob-scene`. (b) `thresholds` is a list: each
entry is a value at which a decision changes, with what is decided on each side; the single `threshold` and
`decides` of the first draft are the one-entry case. (c) `settles` is a list of the unresolved cells or verdicts
the measurement would close. (d) `trigger` is one of `clearance-unresolved`, `unknown-region`,
`assumed-card-reversal`; whether an unresolved clearance is limited by registration or by scale is carried in
`current.limited_by` (the second draft's four reasons are these three triggers with that field). (e) `text` is
the one-line form a person reads. `current.nominal` is absent when the answer has only an interval.

`target.kind` is `box` (rescan this volume; the box is in the scene's gravity frame, in metres) or `surface`
(probe this region, for a card quantity). Quantities (closed list, extensible by
registry): `clear_width`, `clear_height`, `step_height`, `gap_width`, `occupancy` (rescan), `scale` (add a witness),
`friction` with a condition, `compliance`, an optical-card field, a fixture parameter (closer torque, latch force).

**2. The three triggers.**
1. **Clearance unresolved by registration or scale.** After local refinement, a clearance answer stays `unresolved`
   when the band cannot shrink below the floor 2·(ε_field + u_reg) (about 2 mm in a generated scene, tens of
   millimetres in a scan). The fit code then calls `request_for_clearance(answer)`: the target is the bottleneck's
   named feature and its bounding box; the quantity is the dimension the bottleneck cell constrains (clear width for a
   doorway, step height for a threshold); if the limiter is the scale interval the quantity is `scale`.
2. **Mission answers differ because of unknown space.** When a mission query's inner answer (unknown treated as
   blocked) and outer answer (unknown treated as free) differ, `request_for_unknown(region)` names the unknown box
   that separates them, quantity `occupancy`, with the coverage and resolution a rescan must reach.
3. **A decision reverses inside an assumed card's interval.** When a comparison, a verdict or a mission answer takes
   both values as a card field ranges over its `assumed` interval, `request_for_assumed(region, field, interval,
   reversal)` names the surface, the field, the reversal value and what each side decides.
A refusal `FROB-REF-305` (a required route, spawn or contact in unknown space) carries a request of kind 2 as its
first repair.

**From an unresolved item to a request (the algorithm all three triggers share).**
1. Collect the unresolved items for the scene or the answer: clearance verdicts whose inner and outer complexes
   disagree; cells of a mission answer whose inner and outer sets differ and whose explanation is
   `NeedsMeasurement` or names an unknown region; decisions that reverse inside an `assumed` card's interval.
2. For each, find the scene quantity the disagreement depends on (the actionable residual): the one width,
   height, gap or card field on which the two candidate answers differ. It is read from the dependency support
   of the two competing certificates or witnesses; a request that names a quantity on which the competing
   answers do not differ is rejected by this check.
3. Compute the decision thresholds of that quantity inside its current interval: the values at which some cell
   changes verdict or some design ordering reverses.
4. Compute the requested accuracy (rule below).
5. Locate the measurement: the bounding box of the unknown or uncertain geometry in the gravity frame, or the
   surface patch for a card quantity.
6. Merge requests that name the same quantity (one record, all the cells in `settles`); order the list by the
   number of verdicts each request would settle.

**Rules.** An unseen gap beneath a shelf has possible geometry, not assumed geometry: the request, not a default
value, is returned. A scene with scale label `relative-only` yields a scale request before any other. No
friction, compliance or optical value is estimated from an image.

**Hand-off from mission answers.** An unresolved cell of a mission answer carries the request inside its
`NeedsMeasurement` explanation, produced by the same functions; `mission.distinguish` and `experiment.suggest`
list it as a `measure` proposal. This is how authored scenes yield requests before the verb exists.

**3. The accuracy rule (DESIGN; the plan gives the example "to ±5 mm" and no formula. Two drafts of this verb
gave two formulas, one from the nominal slack and one from the gaps between thresholds; they answer different
cases and are combined here into one rule, so that one request never has two accuracies).** Let [lo, hi] be the
current interval, T the thresholds inside it, x̂ the nominal value where the answer has one, and ε_irr the error
the model cannot remove by measurement of this quantity (the field bound, the complex's finest cell; zero for a
card field).

1. *Slack candidates.* Where a nominal value exists, each threshold t gives a_t = |x̂ − t|/2 − ε_irr: a
   measurement to ±a_t of a truth at the nominal value leaves t outside the measured interval.
2. *Gap candidate.* With two or more thresholds, a_gap = (the smallest gap between adjacent thresholds)/2 − ε_irr:
   no reading to that accuracy can straddle two thresholds.
3. *One threshold and no nominal value.* The declared margin of the predicate that reads the quantity, if one is
   declared; otherwise (hi − lo)/20, so that at most a tenth of the prior interval stays ambiguous. (The second
   draft took one tenth of the width here; the stricter twentieth is kept.) This is also the rule for an assumed
   card interval with a reversal value r, and r is printed.
4. The raw accuracy is the smallest applicable candidate. If it is not positive the request is marked
   `threshold-tie`: no measurement is promised to settle it, and the record says that a design change which
   moves the threshold is the alternative.
5. *Instrument ladder.* The requested accuracy is the raw value rounded down to the ladder 1, 2, 5, 10, … in the
   quantity's unit, and capped by the current half-width (hi − lo)/2. Rounding down never asks for less than
   what settles the decision.
6. The request states that a reading within the accuracy of a threshold leaves that decision unresolved.

For `occupancy` the accuracy is a coverage threshold and a spatial resolution equal to the margin in question.

Worked cases. (i) Door D3, nominal clear width 0.812 m, one threshold at 0.800 m (the body needs it), ε_irr =
1 mm: 12/2 − 1 = 5 mm, the "±5 mm" of the example. (ii) Door D3 known only to [795, 825] mm; design A needs at
least 812 mm and design B at least 800 mm: thresholds 800 and 812, half the gap 6 mm, ladder ±5 mm. (iii) A
sill height known to [10, 16] mm with a crossing limit of 12 mm and a declared margin of 1 mm: ±1 mm; with no
declared margin, 6/20 = 0.3 mm, ladder ±0.2 mm. (iv) Friction of an `assumed` card in [0.2, 1.0] with a
reversal at 0.45: 0.8/20 = 0.04, ladder ±0.02; in [0.3, 0.9] with a reversal at 0.5: 0.03, ladder ±0.02.

**4. Standing requests.** Packs are immutable, so requests live in the ledger keyed by `SceneId`, deduplicated by
(target, quantity, threshold). A new pack that records the measurement closes the request: requests on the old pack
whose target and quantity the new record covers are closed with a link to the new `SceneId`. There is no scene edit
verb; a measurement reaches a pack in one of two ways (DESIGN, settling the "scene edit verbs" of the drafts, which
no registry row has). For an ingested place, a re-import whose operator declaration (`--declare <file>`, BD-398's
input table) lists the answered request: its id, the two named features or the surface, the measured value, its
uncertainty and the method; a measured length between two named features is also a scale witness (N19c-02, rule
2). For an authored scene, a recompile (`scene.compile`) of the edited source in which the dimension or the card
carries the measured value with provenance `measured` naming the request it answers (`measured: pr:…`, so that the
ledger can find the request on the old pack, whose `SceneId` and catalog name the new pack does not share). Requests inherit the privacy mark of their scene.

**5. The verb.** `frob scene probe-request <ref> [--cell c:…] [--status open|closed|all] --json`, kind `read`,
capability `scene:read`. `<ref>` is positional, as in the verb registry's example (`frob scene probe-request
a:0e51 --cell c:0204 --json`). An answer reference (`a:…`) returns the requests derived from that unresolved
answer, computing them if absent (a read that derives is idempotent and writes only the request record);
`--cell` narrows a mission answer to one cell. A scene reference lists the standing requests of that scene,
filtered by `--status`. (The two drafts spelled this `--scene <id>` with `--for <answer-ref>`, and `<scene>
--answer a:…`; neither spelling is used.) The result is the list of requests in the registry's output schema
`frob.scene.probe-request.out/1`, each element a `frob.scene.probe-request/1` record. Exit 0 with requests, and
0 with an empty list for a scene with nothing unresolved; an answer reference that is not unresolved returns
exit 2 with a finding "nothing to settle". For a private pack the result is stored under the private root and
the envelope carries the privacy mark. Evidence: a request is a statement
about the model's uncertainty, class `Certified` relative to the stated bounds where the limiting answer is a
certificate, otherwise `Estimated`; Reality `no-claim`.

**6. Layout.** The record type in `frob-core`; the derivation functions (`request_for_clearance`,
`request_for_unknown`, `request_for_assumed`, the accuracy rule, merging) in `crates/frob-scene/src/ingest/probe.rs`;
the hand-off from unresolved cells in `frob-mission`; verb handler `crates/frob-verbs/src/scene/probe_request.rs`.

## Acceptance criteria

- [ ] Each of the three triggers yields a request with target, quantity, unit, current interval, thresholds, accuracy and what each side decides.
- [ ] The record type is defined once in `frob-core` and emitted by `frob-mission` (unresolved cells) and `frob-scene` (clearance, cards); the verb is in the registry at M5 with schema, examples and refusals.
- [ ] The two-design doorway fixture returns one request: quantity "clear width of door D3", thresholds 800 mm and 812 mm, accuracy ±5 mm, with the box of the doorway, and both cells in `settles`.
- [ ] The friction fixture returns a request for the floor patch's friction coefficient with the reversal threshold.
- [ ] A scene with nothing unresolved returns an empty list with exit 0; a `relative-only` scene returns a scale request first.
- [ ] Logs and envelopes for a private pack contain no private-scene data beyond identifiers.
- [ ] The door example returns "clear width of door D3 to ±0.005 m" from nominal 0.812 m, threshold 0.800 m, ε_irr 0.001 m.
- [ ] A clearance answer limited by the scale interval yields a `scale` request ("add a scale witness"), not a width request.
- [ ] `FROB-REF-305` carries a request for the unknown box as repair 1, and the box equals the one in the refusal.
- [ ] No code path substitutes a nominal value for an unresolved quantity: after a request is emitted the originating answer is still `unresolved`, and a mission answer keeps the cell unresolved until a measurement is admitted.
- [ ] A new pack that records the measurement closes the request with a link to the new `SceneId`, and the same query then resolves: at this bead's close on the authored friction fixture (a recompile with the measured card) through the verbs, and on `synthetic` ingested packs in `closure_on_reimport`; the same closure through a real re-import runs in the place-lane steps of the script once BD-398 lands.
- [ ] `frob --json scene probe-request` is reachable with its schema and through `frob-mcp`; private requests need the private scope.
- [ ] The values the ingestion gate's probe-request clause reads are in the envelope (the request count per scene with `--status open`, and each request's target, quantity and accuracy); the clause itself, at least one request for the real place, is asserted by the gate script N19c-07, which depends on this bead.

### Known answers and negative controls
- Known answers: the door example (±5 mm, by the slack rule) and the four `synthetic` fixtures (±5 mm by the gap rule; ±1 mm; ±0.2 mm; threshold 0.5 with ±0.02).
- Negative controls: a build that resolves the fit by taking the nominal width must fail `originating_answer_stays_unresolved`; a build that asks for an accuracy looser than the rule's value a (for example |x̂ − t| instead of |x̂ − t|/2 − ε_irr, ±12 mm for door D3) must fail a check that the measured interval at the nominal truth excludes the threshold; a request without a threshold must be rejected by the schema; a mutant that fills the unknown door width with the interval's midpoint (810 mm) and returns a verdict instead of a request must be caught (the mission answer would then wrongly exclude design A or admit it without a measurement); a request that names a quantity on which the competing answers do not differ (a different door) is rejected by the dependency-support check.
- Determinism: the same answer yields the same request identifier (content hash).

## Considerations

- The accuracy rule and the 1/20 default are DESIGN proposals (the plan gives the example, not a formula); the first real place will show whether requests are actionable with ordinary tools (tape, caliper, a pull test). If field use shows the rule asks for too much or too little, it changes by an amendment to the verb's contract.
- A request can be unanswerable on site (the gap really is inaccessible). Then the cell stays unresolved and the mission carries the uncertainty; the retrofit catalogue may offer an edit that removes the dependence.
- Upstream: if the twin package lacks the landmarks or scale witness the import needs, the first deliverable is an upstream work item, and this verb serves authored scenes only (the ingestion fallback, KILL-INGEST).
- A request can be unanswerable by measurement (`threshold-tie`); saying so is the honest output.
- Probe synthesis is conditional on the admitted mechanisms and is Frontier work of the mission subsystem; this verb only asks for direct measurements, which are always admitted.
- Requests name features of a private place; they are private and never appear in shared catalogs.
- If the ingestion kill gate fires and places are authored as surveyed proxies, requests still apply: a survey is a list of answered requests.
