## Background

Real-place ingestion reads a capture produced by another project. Two candidates exist in the owner's projects (FACT):
the walkthrough route, from video to an agent-built Blender twin with stable feature identifiers and a GLB export, with
an accepted plan for a twin package linking visual, geometric and traversability representations; and
`franken_drone_geometry_reconstruction` (at `db45703afc5e`), whose chain today ends at an audited relative bundle
problem and which, by its own status file, does not yet optimize cameras, emit metres or publish geometry (its schemas
for what it will publish exist: a geometry generation with `coordinate_frame`, `scale_status`, `representations`,
`uncertainty_root`, `coverage_root`, `publication_stage`, and a scale model with residuals in parts per million).

**OPEN-HAB-5.** Which reconstruction package and version is the import contract. **Default (fail-closed, in force
until decided):** the walkthrough twin package; the drone route when it publishes geometry. **Owner:** Habitat lead,
with the project owner's input (the M5 milestone lists it under "owner input wanted"). **Blocks:** GATE-HAB-03, since
the private lane of that gate cannot run until a package and version are pinned.

Why it needs a decision and not just a default: an importer pinned to a package version refuses others, the package's
format is still moving upstream, and the choice determines which upstream work item is on the critical path (FD-FSS-01
adds four non-coplanar landmarks, a scale witness and coverage per region to the twin package, conditional on the
pilot finding them missing; FD-FDGR-01 makes the drone route publish geometry in metres with a scale witness, coverage
and uncertainty per region).

## Scope

In: preparing the decision (evidence, options, consequences), recording the owner's ruling, pinning the contract in
the importer's configuration and the stack lock. Out: the importer (N19c-04, BD-398); the upstream changes themselves
(made in the sibling repositories under their own rules).

## Technical approach

1. **Evidence pack for the owner.** The pilot record (N19c-01): which of the three required items the twin package
   exports today; the drone project's status file and schema versions at its pinned commit; the state of FD-FSS-01
   and FD-FDGR-01.
2. **Options, with consequences.**
   - (a) *Twin package at a pinned version* (the default). Consequence: the adapter reads that version only; if the
     pilot found items missing, FD-FSS-01 is on the path and surveyed proxies serve meanwhile.
   - (b) *Drone geometry generation at a pinned schema version.* Not available until the sibling publishes geometry;
     then driven as a subprocess with the schema adapter; INT-FDGR-01 (schema fixtures validate; a non-metric scale
     status is refused; coverage masks become the unknown-space label; privacy inheritance applies) must pass first.
   - (c) *Both, twin package first* (the default's second clause): the common intermediate form of the importer makes
     this an addition, not a rewrite.
   - (d) *Operator-declared mesh only* (the fallback of the drone lane): scale declared by the operator and
     `reality: no-claim`; never sufficient for GATE-HAB-03 at `witnessed`.
3. **Record.** An entry in the open-questions ledger (`docs/open/OPEN-HAB-5.md`, DESIGN path) with the ruling, the
   package name, version or commit, the schema digests, the date and who ruled; the importer's contract file
   `registries/ingest_contract.toml` (DESIGN) lists the admitted (adapter, package version, schema digest) triples;
   the sibling pin goes into the stack lock.
4. **Enforcement.** The importer refuses a package whose version or schema digest is not in the contract file
   (`FROB-REF-303`, "reference does not resolve", with the admitted versions as the repair), so a silent format
   drift cannot produce a pack.
5. **Until decided.** The default holds: the adapter for the twin package at the version the pilot inspected is the
   only admitted source; the drone adapter validates schema fixtures only.

## Acceptance criteria

- [ ] The evidence pack exists and cites the pilot record and the sibling commits by hash.
- [ ] The owner's ruling is recorded with package, version or commit and schema digests; or, absent a ruling by M5, the record states that the default is in force and names what it blocks.
- [ ] `registries/ingest_contract.toml` lists exactly the admitted triples, and the importer refuses any other version.
- [ ] The stack lock pins the sibling revision the contract refers to.
- [ ] GATE-HAB-03's private lane names the contract row it ran under.

## Test plan

### Unit tests
`crates/frob-scene/tests/ingest_contract.rs`:
- `admitted_version_accepted`: a synthetic package stamped with the admitted version imports.
- `other_version_refused`: version bumped by one → `FROB-REF-303` with the admitted versions listed as the repair.
- `schema_digest_mismatch_refused`: same version string, altered schema → refused.
- `contract_file_and_lock_agree`: the sibling revision in the contract equals the one in the stack lock.

### End-to-end script and logging
`scripts/e2e/ingest_contract.sh` (STD-E2E helper): `frob --json scene import --kind place` on the admitted synthetic
package (exit 0 or 2) and on the version-bumped one (exit 3); logs the command, exit code, the contract row matched or
the refusal block, and a summary; logs under `target/e2e-logs/ingest_contract/`.

### Known answers and negative controls
- Known answer: the two fixtures above.
- Negative control: an importer with the version check removed must accept the bumped package and fail the script.

## Considerations

- A decision bead blocks others, so it is one step more urgent than its milestone.
- The twin package and the drone project are the owner's own; choosing one does not retire the other.
- If KILL-INGEST fires, the contract file stays (viewing-grade imports still use it) and the decision is recorded as moot for metric use.
- Related open question OPEN-HAB-6 (contact with unknown space) is decided with the first real place and has its own bead.
