## Background

An **invariant** is a property that must hold in every state the system can reach; a **proof obligation** is a
mathematical statement the design relies on, with a stated way of verifying it. The Habitat chapter (scenes, living
worlds, clearance, retrofits; crate `frob-scene`) states ten invariants and seven proof obligations. Each is enforced
by a mechanism that some bead builds, and those beads are spread over three drafting units and four milestones. The
rule of the project is that every law, invariant and proof obligation has a property test, a certificate or a proof,
and that one which no mechanism bead carries gets its own test. This bead is the ledger that keeps the seventeen from
being lost: the statements, how each is verified, which bead carries the verification, and a mechanical audit that a
live test exists for each. It also owns the two invariants that are properties of the whole crate and so belong to
no single mechanism (INV-HAB-01 and INV-HAB-02).

## Scope

In: the seventeen rows as registry data; the binding audit; the crate-wide tests for INV-HAB-01 and INV-HAB-02; the
report of obligations whose verification is not yet in the class the plan asks for. Out: the mechanism-level tests
(each row names its bead); known answers (N19-KA); counterexamples (N19-CX); refusals (N19-REF).

## Technical approach

1. **File.** `crates/frob-conformance/registry/invariants/habitat.toml` (DESIGN path): `id`, `statement`,
   `verification` (kind: `property-test`, `structural`, `certificate`, `written-proof`, `symbolic`,
   `interval-evaluation`, `exhaustive`), `class` (`Certified`, `Tested`), `tests` (symbols), `beads`,
   `first_milestone`.
2. **Invariants.**

| ID | Invariant | Verified by | Carried by |
|---|---|---|---|

| INV-HAB-02 | Physics, sensors and stills read only the collision field, the overlays and the maps. No code path carries visual-mesh data into a result | Structural: the GLB reader is linked only by the viewer (dependency check); property: swapping the visual mesh leaves every physics digest, ray output and still unchanged | this bead; N19a-23, BD-163 |

| INV-HAB-04 | `unknown` is never changed to free or occupied without a recorded observation or a recorded, named assumption | Property test over random compile, repair and resolve sequences; a lint forbidding writes to the mask outside one module | N19c-03 |

3. **Proof obligations.**

| ID | Statement | Verification (as the plan requires) | Carried by |
|---|---|---|---|
| PO-HAB-01 | The recorded brick bound holds: the device field differs from the source chart by at most the bound everywhere in the brick | Derivation on file (unit Lipschitz constant, trilinear interpolation error, half a quantization step); interval evaluation against the constructive-solid range for generated scenes (`Certified`); 10⁶ samples for meshes (`Tested`) | N19a-14; N19b-01 (formula), BD-163 (emission) |
| PO-HAB-02 | Over a cell of a clearance complex, clearance varies from its centre value by at most e | A written proof from the two Lipschitz facts (a distance function has Lipschitz constant one; a point at radius at most ρ moves at most ρ·abs(Δψ) under a rotation), as a theorem card; a randomized check | N19b-26 |
| PO-HAB-03 | A face-connected inner path is collision-free, and separation in the outer complex excludes every path | Written proof; exhaustive comparison with a brute-force grid at four times the resolution on small fixtures | N19b-28, N19b-35 |
| PO-HAB-04 | The film-thickness update is exact for a load constant over the step | Symbolic identity checked by FrankenSymPy (`Certified`) | N19b-05 |
| PO-HAB-05 | The face-flux film update conserves total volume exactly in exact arithmetic | Telescoping identity on file; compensated-sum audit in every run | N19b-09 |
| PO-HAB-06 | Each overlay primitive returns the exact distance outside its solid | Interval evaluation against `fs-rep-frep` for each primitive, including the periodic bar pattern | N19a-16 |
| PO-HAB-07 | An affine map that fixes four non-coplanar points is the identity, so four correspondences determine the registration | Linear-algebra card | N19a-21 |

4. **The audit** (`habitat_invariants_bound`): for each row, every listed test symbol exists in the workspace's test
   list, or the row is `pending` and its `first_milestone` has not been reached. At a milestone exit the audit fails
   on any pending row whose milestone has passed. For proof obligations the audit also checks that the artifact of
   the stated kind exists: a derivation or proof file under `docs/math/habitat/`, a certificate in the bundle
   registry, or an interval-evaluation test. An obligation verified in a weaker class than stated (for example
   PO-HAB-01 only `Tested` on generated scenes) is reported as a downgrade and is not silently accepted.
5. **Crate-wide tests owned here.**
   - INV-HAB-01: compile-fail tests that no public API of `ScenePack` or its blobs takes `&mut self` or exposes
     interior mutability; a property test that mutating one random byte of a random identity-bearing blob of 1,000
     fixture packs either fails the reader or changes the `SceneId`.
   - INV-HAB-02: a dependency test that the GLB decoding module is reachable only from the viewer's crate graph
     (`xtask check-deps` rule plus a test over `cargo metadata`); a digest test on a fixture scene with two
     different visual meshes: physics digests, ray-kernel outputs and stills are bit-identical.
6. **Evidence.** The ledger itself is data (D0). The audit's result is part of every milestone exit review.

## Acceptance criteria

- [ ] The registry holds exactly INV-HAB-01 to -10 and PO-HAB-01 to -07 with statements identical to the tables above.
- [ ] Every row is bound to at least one existing test, proof file or certificate, or is `pending` before its milestone; the audit fails otherwise.
- [ ] INV-HAB-01 and INV-HAB-02 have the crate-wide tests of item 5, each with a negative control that fails.
- [ ] Each proof obligation's verification artifact is of the kind and class the table states, or a downgrade is listed in the audit's report.
- [ ] The audit runs in the conformance battery and its report is attached to the M2, M3, M4 and M6 exit reviews (the milestones at which Habitat rows come due).

## Test plan

### Unit tests
`crates/frob-conformance/tests/habitat_invariants.rs` and `crates/frob-scene/tests/crate_invariants.rs`.
- `ledger_rows_complete`: the seventeen identifiers, no others.
- `habitat_invariants_bound`: the audit of item 4.
- `pack_has_no_mutators` (compile-fail tests via trybuild).
- `identity_changes_on_any_byte`: 1,000 packs × one random byte.
- `glb_reachable_only_from_viewer`: a planted `use` of the GLB module in `frob-scene`'s field code makes the dependency test fail (negative control).
- `visual_mesh_swap_changes_no_result`: digests equal across two visual meshes.
- `downgrade_is_reported`: a row whose artifact is a sampling test where interval evaluation is required appears in the report.

### End-to-end script and logging
`scripts/e2e/habitat_invariants_audit.sh` (STD-E2E helper): `frob --json conformance run --registry
invariants/habitat`; logs one `assert` event per row with its identifier, verification kind, class, the tests found
and their results, and `pending` or `downgrade` flags; the `summary` gives rows bound, pending, downgraded and failed.
Logs under `target/e2e-logs/habitat_invariants_audit/`.

### Known answers and negative controls
- Each invariant's negative control is the one its carrying bead registers (a pool indexed without the world address for INV-HAB-03; a split by `SceneId` for INV-HAB-09; the masked non-conservative film update for INV-HAB-07; a generator reading an unseeded source for INV-HAB-10). The audit checks that each row names at least one control.
- This bead's own controls: the planted GLB import; a pack API with a setter (must fail `pack_has_no_mutators`); a registry row pointing at a non-existent test (must fail the audit).

## Considerations

- PO-HAB-02 and PO-HAB-07 are to be theorem cards; until the Lemma unit assigns numbers they are written proofs on file, and the audit reports them as "card pending".
- PO-HAB-03's "separation in the outer complex excludes every path" relies on cells being closed sets (a free configuration on a shared edge makes every cell containing it an outer cell); the written proof must state that.
- Several rows come due late (INV-HAB-07 at M6, INV-HAB-08 at M4); the ledger exists from M2 so that they cannot be forgotten.
- An invariant without a negative control is not accepted as tested.
