## Background

A ray query against instanced geometry is usually done in each instance's local coordinates: the ray is transformed
by the inverse of the instance transform, intersected with the unscaled shape, and a hit parameter comes back. If the
instance transform scales, that parameter is not a distance along the world ray unless care is taken. The rule
(DESIGN), with A the linear part of the instance transform, local to world: **for a unit world direction d the local
direction is A⁻¹·d. If the primitive renormalizes it, the hit parameter is in local units and s_W = s_L/‖A⁻¹·d‖. The
conversion happens before hits are sorted, clipped to a range gate, or used as optical depth.**

**Counterexample.** Two planes facing one ray. An opaque foreground plane at 2 m belongs to an instance of scale 1/2
and reports a local parameter of 4. A background plane at 3 m belongs to an instance of scale 3 and reports 1.
Sorting by the local parameter returns the occluded plane, and a range gate of 2.5 m applied to the local values
discards the foreground and keeps the background. A depth camera would see through a wall; a lidar would report a
phantom; a pick in the viewer would select the wrong object.

FACT (`franken_threed/crates/f3d-math/src/ray.rs:487–490` and `vector3.rs:708–719` at `bf7abe16367e`, read
2026-11-21): the sibling's `Ray::apply_matrix4` transforms its direction with `Vector3::transform_direction`, which
normalizes the result, as the scene-graph method it mirrors does. An adapter over it converts by the rule. This is a
recorded convention hazard of the sibling (not a defect: both conventions are legitimate, and mixing them is the bug).

Where the rule binds. A compiled scene pack is in world metres (the compiler bakes scales), so the batched ray
kernels marching a compiled field need no conversion. The rule binds on three paths: ray queries against a pack that
is inspected before compilation (acceptance and import previews), the viewer's picking rays (the viewer draws the
visual scene graph, which keeps instance transforms), and any adapter over a sibling's ray primitive. Tier Solid.

## Scope

In: the conversion function and its typed result; the host ray path over instanced, uncompiled geometry; the
ordering rule (convert, then sort, gate and accumulate); the adapter over the sibling ray primitive; the contract the
viewer's pick must meet, with a reference implementation and test vectors. Out: distance and normal rules (N19c-38);
batched ray kernels over compiled fields (the ray-kernel bead); the viewer's code (the viewer beads); the gate
script (N19c-40).

## Technical approach

1. **Types (DESIGN sketch).**

```rust
pub struct LocalRayParam(f64);                         // not a length; cannot be compared across instances
pub struct WorldRayParam(Length);
pub struct LocalRay { origin: Point3, dir: Vec3, dir_was_normalized: bool, inv_dir_norm: f64 /* ‖A⁻¹·d‖ */ }
pub fn to_local(ray: &WorldRay, inst: &ScaledInstance, normalize: bool) -> LocalRay;
pub fn to_world_param(s_local: LocalRayParam, local: &LocalRay) -> WorldRayParam;
```

   Two conventions exist and the type records which was used. If the local direction is **not** renormalized
   (dir = A⁻¹·d), a hit at local parameter s is at world parameter s, since A·(o_L + s·A⁻¹·d) = o_W + s·d. If it
   **is** renormalized (dir = A⁻¹·d/‖A⁻¹·d‖), then s_W = s_L/‖A⁻¹·d‖. `to_world_param` applies the factor that
   matches the flag. `LocalRayParam` has no ordering against other instances' parameters, so sorting hits before
   conversion does not compile.
2. **Order of operations in every multi-instance ray routine.** (1) For each candidate instance transform the ray,
   intersect, and convert each hit to a `WorldRayParam` immediately. (2) Only then sort hits, apply the range gate
   [s_min, s_max] in metres, pick the first opaque hit, and accumulate optical depth through volumes (extinction
   integrates over world length). Hit normals are converted by A⁻ᵀ and renormalized before any optical response.
3. **Host ray path over uncompiled geometry** (`frob_sense::host_rays::cast_instanced`): used by acceptance previews
   and import inspection; follows item 2; returns hits with world parameter, world point, world normal, instance and
   region. Its results on a scene must agree with rays cast against the compiled pack to within the brick bound.
4. **Adapter over the sibling ray primitive.** A thin function `f3d_ray_hit_world(ray_world, instance, shape)` that
   calls the sibling's ray transform (which normalizes) and its intersection, then converts by s_W = s_L/‖A⁻¹·d‖.
   The sibling is never a Cargo dependency of the core; the adapter lives with the renderer route and is exercised
   through that route's admission test. Until the route is admitted (M3) the adapter's arithmetic is tested against
   this crate's own normalizing transform, which reproduces the sibling's convention, and the row of the gate that
   runs through the real sibling is recorded as pending admission.
5. **The viewer's pick.** The viewer builds a world ray from a screen point and must return the first surface along
   it in world metres. Contract handed to the viewer: per instance, transform the ray, intersect, convert by the
   rule, then choose the minimum world parameter; the pick result carries the world parameter and world point. This
   bead supplies the reference implementation in Rust, a table of test vectors (ray, instances, expected hit and
   distance) exported as JSON for the viewer's own test runner, and the two-plane fixture.
6. **Evidence and determinism.** Host results are exact to round-off (`f64`, fixed operation order: D0 on the host).
   Depth against analytic shapes under scaled instances is a Known answer.
7. **Layout.** `crates/frob-sense/src/host_rays/{instanced.rs, param.rs}`; test vectors under
   `fixtures/rays/scaled_instances.json`; the adapter under the renderer route's annex.

## Acceptance criteria

- [ ] The two-plane fixture returns the foreground at 2 m through the host ray path over uncompiled geometry, and a range gate of 2.5 m keeps the foreground and discards the background.
- [ ] The mutant that sorts local parameters returns the background plane and fails; the mutant that gates local parameters discards the foreground and fails.
- [ ] Both conventions are covered: with a non-normalized local direction the local parameter equals the world parameter; with a normalized one the conversion factor is 1/‖A⁻¹·d‖; mixing them (normalized direction, no conversion) fails the fixture.
- [ ] Sorting or gating `LocalRayParam` values from different instances does not compile.
- [ ] The adapter's conversion reproduces 2 m and 3 m from the sibling-convention parameters 4 and 1 on the fixture; the row through the real sibling primitive is run when the renderer route is admitted and recorded separately.
- [ ] The viewer's test vectors exist, and the reference implementation passes them; the viewer's pick passes the same vectors (asserted in the gate script).
- [ ] On 10³ random instances with anisotropic scales in [0.25, 4], depth against an analytic plane through the host path equals the closed form to 10⁻⁹ m; through the compiled pack it is within 1 mm plus the brick bound (measured in the gate script).

## Test plan

### Unit tests
`crates/frob-sense/tests/scaled_rays.rs`.
- `two_planes_local_params`: scale 1/2, plane at 2 m: A⁻¹ = 2·I, ‖A⁻¹·d‖ = 2, normalized-convention local parameter 4; scale 3, plane at 3 m: ‖A⁻¹·d‖ = 1/3, local parameter 1.
- `two_planes_world_order`: converted parameters 2 m and 3 m; first opaque hit is the foreground.
- `range_gate_in_metres`: gate 2.5 m keeps 2 m, drops 3 m.
- `sort_local_mutant_returns_background`, `gate_local_mutant_drops_foreground` (negative controls).
- `non_normalized_convention_needs_no_factor`: with dir = A⁻¹·d the hit parameters are 2 and 3 directly.
- `anisotropic_direction_dependence`: A = diag(2, 0.5, 1): ‖A⁻¹·d‖ is 0.5 for d = x, 2 for d = y, and √((0.5·cos θ)² + (2·sin θ)²) in between; a plane hit along a 30° ray converts correctly.
- `optical_depth_uses_world_length`: an extinction volume of σ = 0.5 m⁻¹ crossed over 2 m of world length inside an instance of scale 4 transmits exp(−1.0), not exp(−0.25).
- `normals_converted_before_response`.
- `local_params_not_comparable` (compile-fail test).
- `host_matches_compiled`: 10³ random rays against a scaled-instance scene, host path against the compiled pack: differences within the brick bound.

### End-to-end script and logging
The gate script is N19c-40. This bead's `scripts/e2e/scaled_rays.sh` (STD-E2E helper): `frob --json scene accept

### Known answers and negative controls
- Known answers: the two-plane fixture (foreground at 2 m); conversion factors for the anisotropic instance; exp(−1.0) transmission.
- Negative controls: the two mutants above; an adapter that omits the conversion (returns 4 and 1); a pick that sorts by local parameter (selects the background).
- Metamorphic: scaling an instance and its shape reciprocally (the same world geometry) changes no world hit; rotating the whole scene changes no world parameter.
- Determinism: host results identical in debug and release and across platforms.

## Considerations

- The hazard is silent: nothing crashes, depth images look plausible, and only occlusion order and ranges are wrong. That is why the fixture is in the gate and the types forbid cross-instance comparison.
- Batched ray kernels over compiled packs are unaffected; if a later design marches instanced geometry on a device (not planned), the same rule applies in the kernel and the fixture extends to it.
- The viewer is JavaScript; the contract is enforced by shared test vectors and by the gate script, not by Rust types.
- The sibling's convention was read at a pinned commit; if the sibling changes it, the adapter's admission row fails, which is the intended alarm.
