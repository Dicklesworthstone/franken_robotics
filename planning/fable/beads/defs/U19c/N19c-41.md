## Background

Agents reach Habitat through verbs of the `frob` command line and the MCP server. Two of them are the everyday read
surface of scenes:

- `scene.list` (kind `read`, first milestone M2): the scene catalog, which is also exposed as an MCP resource.
- `scene.show` (kind `read`, first milestone M2): a manifest, the hazards drawn, and the feasibility tag.

A **scene pack** is the compiled, immutable form of a place, identified by its content hash `SceneId`. Its
**manifest** (`.fscene`, schema `frob.scene/1`) names the family, seed and split group, the field settings (fine and
coarse spacing, truncation, band-brick count, the largest brick bound), the counts of overlays, regions, fixtures and
movables, the maps, living-world declarations, the feasibility tag for the family's nominal footprint (`witnessed`,
`impossible: intended`, `impossible: incidental`, `unresolved`), provenance (generator, licences, scale, the count of
`assumed` dimensions, the private mark) and the hash of the acceptance report. The **hazards drawn** are the rows of
the archetype's hazard registry that the generator instantiated in this scene, with the value drawn for each and its
provenance.

The verbs are implemented with the compiler (BD-163). This bead is their end-to-end test: every user-visible
capability gets a script that drives the real binary, and read verbs are where an agent first notices a lie (a
catalog that lists a private scan, a manifest whose identity does not match, a page that changes under a concurrent
write).

## Scope

In: the script for `scene.show` and `scene.list` on both surfaces, its fixtures, assertions and structured log. Out:
the verbs' implementation (BD-163); the verb-family registry test (N19a-02); the compile stages' script (N19a-42).

## Technical approach

**1. Script.** `scripts/e2e/scene_show_list.sh --seed 0x5eed0041`, plain shell driving `frob` (and `frob-mcp` for
the resource rows), idempotent (it works in a fresh store directory), non-zero exit on a failed assertion.

**2. Fixtures.** Twelve scenes created in the script: ten terrain scenes from `scene.gen` (two families, five seeds),
one constructive-solid room and one mesh room through `scene.compile`. At M3, when present: two interior scenes with
hazards drawn and feasibility tags, and one private pack (a synthetic "as-captured" room imported under a private
root).

**3. Steps and assertions.**
1. **Empty catalog.** `frob --json scene list` in the fresh store: exit 0, zero rows, a valid envelope with the
   evidence block.
2. Create the fixtures; collect their `scene_id`s from the creating verbs' envelopes.
3. **List.** `frob --json scene list`: assert exactly the created public packs, each row carrying `scene_id`,
   family, seed (a hex string, never a JSON number), group, fine and coarse spacing, band-brick count, bytes,
   feasibility tag (or `not-computed` at M2), scale label (`generated`), `dimensions_assumed`. Assert the rows are
   in a stable, documented order and that two calls return byte-identical data blocks.
4. **Pagination.** `frob --json scene list --limit 5`: follow the cursor to the end; assert 5 + 5 + 2 rows with no
   duplicates or gaps. Between the first and second page, compile one more scene; assert the remaining pages still
   describe the frontier the first page was pinned to (the new scene is absent), and that a fresh listing shows 13.
5. **Filters.** `--family <f>`, `--group <g>`: assert the subsets.
6. **Show.** For each fixture, `frob --json scene show <id>`: assert the manifest validates against `frob.scene/1`;
   the `scene_id` in the manifest equals the requested one and equals a recomputation by `frob --json artifact
   read`-style digest check; `field.fine_m = 0.02`, `coarse_m = 0.16`, `truncation_m = 0.08`, `bits = 16` for default
   settings; the three no-authorization flags are present and `false`.
7. **Show, receipts.** `scene show <id> --receipts`: assert eleven stage receipts (with `skipped: not-yet-landed`
   where a stage has not landed) and that the pack is marked `acceptance: incomplete` in that case.
8. **Show, probe.** `scene show <room id> --probe x,y,z` at three points with known answers for the box room: a
   point 0.05 m from a wall (inside the band): assert 0.05 m within the brick bound; a point 0.03 m inside a wall:
   assert −0.03 m within the bound; a point 0.50 m from every surface (beyond T = 0.08 m): assert
   `saturated: far-outside`, never a bare 0.08.
9. **Show, bytes.** `scene show <id> --bytes`: assert dense bytes equal 2 × volume/s³ for the box room and that
   pooled bytes ≤ band bytes ≤ dense bytes.
10. **Hazards and feasibility (M3 rows).** For an interior scene: assert every hazard row lists the drawn value, unit
    and provenance, that the count of `assumed` rows equals `dimensions_assumed`, and that the feasibility tag is one
    of the four values with a cut reference when `impossible`.
11. **Unknown identifier.** `scene show b3:<64 zeros>`: assert exit 3 with a structured refusal naming the
    identifier (not an unhandled error; exit 1 is never emitted on purpose).
12. **Private packs (M3 rows).** Without the private scope: the private pack is absent from `scene list`, and `scene
    show <its id>` exits 5 with the private-scope refusal. With the scope: both succeed. The MCP resource for the
    catalog lists the same public rows as the command line and never the private one.
13. **MCP parity.** Call the `scene_list` and `scene_show` tools through `frob-mcp` for two fixtures: assert the
    data blocks equal the command line's, byte for byte after canonicalization.
14. **Determinism.** Rerun the whole script in a second fresh store with the same seed: assert the same `scene_id`s
    and identical `scene show` data blocks.

**4. Logging.** The script sources the STD-E2E helper and writes NDJSON to
`target/e2e-logs/scene_show_list/<utc>.ndjson` with a transcript. Every line has `ts`, `script`, `bead`, `step`,
`event` (`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact command, exit code, wall time, the
envelope's evidence block (claim, class, tier, determinism, identities, seed), measured values with units and
thresholds (row counts, probe distances against their truths and the brick bound, byte figures), digests of the
compared data blocks, and on failure the first differing field with the pack path. The `summary` line gives
assertions passed and failed; this script claims no gate.

## Acceptance criteria

- [ ] `scene list` returns exactly the public packs with the documented columns, in a stable order, identically on two calls.
- [ ] Pagination is pinned to a committed frontier: a scene compiled between pages does not appear in the remaining pages and does appear in a fresh listing.
- [ ] `scene show` returns a manifest that validates, whose identity recomputes, with the default field settings and the three no-authorization flags `false`.
- [ ] `--receipts`, `--probe` and `--bytes` return the stated content; a saturated probe is flagged, never returned as a distance.
- [ ] An unknown identifier is a structured refusal with exit 3; a private pack is absent without the scope and readable with it (rows pending until the private-places bead lands).
- [ ] The MCP tools and the catalog resource return the same data as the command line.
- [ ] Two runs with the same seed produce identical identities and data blocks, on Linux and macOS.

## Test plan

### Unit tests
Helpers of the script (`scripts/e2e/tests/scene_show_list.bats`): `cursor_walk_detects_duplicate` (a planted
duplicate row across pages is reported); `canonical_compare` (two JSON blocks differing only in key order compare
equal; differing in one number do not); `seed_is_string` (a row whose seed is a JSON number fails the column check).

### End-to-end script and logging
This bead is the script (section above).

### Known answers and negative controls
- Known answers: the box-room probes (0.05 m in the band; −0.03 m inside a wall; `saturated: far-outside` at 0.50 m from every surface, since stored values are clamped to ±T = 0.08 m and a clamped value is not a distance); dense bytes of a 4 × 3 × 2.4 m room at 2 cm: 7.2 MB.
- Negative controls (planted builds or fixtures the script must catch): a list that includes the private pack; a pager that re-reads the live catalog per page (the scene compiled between pages appears); a `scene show` that returns a manifest whose `scene_id` was edited (the identity check fails); a probe that returns 0.08 as a distance for a far point.
- Determinism lanes: twice on one machine; debug and release; Linux and macOS.

## Considerations

- At M2 the hazards and feasibility columns are empty for terrain scenes; the M3 rows of the script activate when interiors exist, and the script reports which rows ran.
- The catalog is a read path that agents poll; its cost should not grow with the bytes of the packs (it reads manifests only). The script records wall time per call so that a regression is visible.
- Integers above 2⁵³ (seeds) travel as strings on both surfaces; the column check enforces it.
- Imported text in manifests (asset names from a source file) is data, not instruction: `scene show` carries it under the untrusted-text mark; the script checks the mark on the mesh-room fixture.
