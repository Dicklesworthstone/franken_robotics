## Background

Habitat (crate `frob-scene`, layer 2) states two invariants that are properties of the whole crate rather than of one
mechanism:

- **INV-HAB-01.** A `ScenePack` (the compiled, immutable, content-addressed form of one place; manifest `.fscene`,
  identity `SceneId`, the hash of the canonical manifest, which carries the hash of every blob) is immutable; any change
  produces a new `SceneId`.
- **INV-HAB-02.** Physics, sensors and stills read only the collision field, the analytic overlays and the maps. No
  code path carries visual-mesh data (the GLB file drawn by the viewer) into a result. This enforces ADR-HAB-04: the
  visual mesh is read by the viewer only, so that one authority for geometry sits inside the model identity and a
  presentation asset can be replaced without changing a digest. Rejected alternative: letting sensors or stills sample
  the GLB, which would let a floor that exists only in the renderer reach a result.

The invariant ledger N19c-27 records both rows and audits that live tests are bound to them. This bead writes the
structural tests that hold them across the crate graph: the type-level guarantee that a pack has no mutating API, the
property that every identity-bearing byte is covered by the identity, and the dependency rule that keeps the GLB decoder
out of every crate except the viewer's. It was split from the ledger in polishing round 1 so that the ledger, a
registry bead, depends on no mechanism. Tier Solid, milestone M2, where the pack format (BD-162) and the compiler
(BD-163) first exist.

## Scope

In: compile-fail tests over the public API of `ScenePack` and its blob readers; the random-byte identity property over
1,000 fixture packs; the dependency rule for the GLB decoding module (an `xtask check-deps` rule and a test over
`cargo metadata`); the bindings of these tests into the ledger rows of INV-HAB-01 and INV-HAB-02.

Out: the byte-flip acceptance case of the manifest reader and its refusal (BD-162; the refusal code is row 4 of
N19c-42); the brick-level GLB-swap check of the compiler (BD-163); the consumer-level GLB-swap digest test over physics,
ray kernels and stills with the deviation map (N19a-23, M3); `SceneId` composition (N19a-20).

## Technical approach

1. **No mutators (INV-HAB-01, structural).** Compile-fail tests (`trybuild`) in `crates/frob-scene/tests/ui/`:
   each case tries one mutation through the public API and must fail to compile: assigning a field of `ScenePack`,
   calling a method that takes `&mut self` on `ScenePack`, `BlobRef` or a field reader, obtaining `&mut [u8]` to a blob,
   and constructing a `ScenePack` from parts without going through the reader or the freeze stage. A companion test
   walks the crate's public items with `rustdoc --output-format json` and asserts that no public method of these types
   takes `&mut self` and that none holds `Cell`, `RefCell`, `UnsafeCell`, an atomic or a `Mutex` (interior
   mutability). The list of checked types is data (`tests/ui/immutable_types.txt`), so a new public pack type is added
   to it in the change that creates it.
2. **Identity on every byte (INV-HAB-01, property).** For 1,000 fixture packs (synthetic: box rooms, a rack aisle,
   terrain tiles, compiled by BD-163 from seeds 0 to 999), pick one identity-bearing blob and one byte uniformly with a
   recorded seed, flip one bit, and reopen the pack. Required: the reader refuses (row 4 of N19c-42, exit 9), or the
   recomputed `SceneId` differs from the stated one. Never: the pack opens with the stated identity. The set of
   identity-bearing blobs is read from the manifest schema (every blob the manifest hashes), not hard-coded, so a new
   blob kind is covered without a test change. The GLB blob is excluded by the schema and checked separately: flipping
   a GLB byte leaves `SceneId` unchanged (ADR-HAB-04).
3. **GLB only in the viewer (INV-HAB-02, structural).** The GLB decoding module lives in one crate (the viewer's asset
   module, DESIGN). An `xtask check-deps` rule fails the build if any crate other than the viewer and its tests has a
   path, direct or transitive, to that module, and a test reruns the rule over `cargo metadata` of the workspace so
   that it runs in `cargo test`. The rule's allow-list is one entry; widening it needs an ADR.
4. **Ledger binding.** The ledger rows of INV-HAB-01 and INV-HAB-02 (N19c-27) gain the test symbols below and the
   controls of the last section; their status moves from `pending` to `bound` in the same change.
5. **Evidence.** These tests are `Tested` structural checks with class D0 outputs (verdicts and digests). They hold for
   every tier because they constrain code paths, not numbers.

## Acceptance criteria

- [ ] Every compile-fail case of item 1 fails to compile, and the rustdoc walk finds no `&mut self` method and no interior mutability on the listed types.
- [ ] 1,000 of 1,000 random single-bit flips in identity-bearing blobs are either refused by the reader with exit 9 or change `SceneId`; a GLB flip changes nothing.
- [ ] `xtask check-deps` passes on the workspace and fails, naming the path, when the planted import of the GLB module is present.
- [ ] The ledger audit of N19c-27 reports INV-HAB-01 and INV-HAB-02 as `bound` with these tests and their controls.
- [ ] `scripts/e2e/habitat_crate_invariants.sh` passes, with its negative controls caught.

## Test plan

### Unit tests
`crates/frob-scene/tests/crate_invariants.rs` and `crates/frob-scene/tests/ui/*.rs`; real packs compiled from
`synthetic` fixtures; no mocks.
- `pack_has_no_mutators`: the trybuild cases of item 1 all fail to compile with the expected error (E0616 for
  assigning a private field, E0594 or E0596 for assignment and borrow through a shared reference, E0599 for a
  missing method).
- `no_interior_mutability_in_pack_types`: the rustdoc walk over the listed types finds none.
- `identity_changes_on_any_byte`: the property of item 2 over 1,000 packs (seed recorded; a failure prints pack, blob,
  byte offset and both hashes).
- `glb_flip_keeps_identity`: one bit flipped in the GLB of 100 packs; `SceneId` unchanged and every brick, overlay and
  map digest unchanged.
- `glb_reachable_only_from_viewer`: the dependency rule passes on the workspace.

### End-to-end script and logging
`scripts/e2e/habitat_crate_invariants.sh` sources the STD-E2E helper and runs: `frob --json scene compile` of three
fixtures (each call with its own idempotency key, `--key hci-1` to `--key hci-3`); `frob --json scene show <id>` on
each; for each, a copy with one flipped bit in a brick blob opened with `frob --json scene show` (expect exit 9 and
row 4 of N19c-42, the integrity refusal `scene-pack-identity-mismatch`, with both hashes in its block); a copy with one flipped GLB byte (expect exit 0 and the
same `scene_id`); `cargo xtask check-deps` on the workspace, then on a scratch copy with the planted import (expect
failure naming the path). Every NDJSON line carries `ts`, `script`, `bead`, `step`, `event`, the exact command, exit
code, wall time, the envelope's evidence block, the stated and recomputed `SceneId`, the blob and byte offset flipped,
and on failure the first differing value and the paths needed to reproduce. A final `summary` line counts assertions
passed and failed and names INV-HAB-01 and INV-HAB-02. Logs under `target/e2e-logs/habitat_crate_invariants/`.

### Known answers and negative controls
- Known answers: flipping any identity-bearing byte changes `SceneId` or is refused (exact, 1,000 of 1,000); flipping
  a GLB byte changes nothing (exact).
- Negative controls (each must be caught): a planted `pub fn set_seed(&mut self, …)` on `ScenePack` fails
  `pack_has_no_mutators`; a reader that skips the hash of one blob kind (the overlay blob) fails
  `identity_changes_on_any_byte` within the 1,000 trials; a planted `use` of the GLB module in `frob-scene`'s field
  code fails `glb_reachable_only_from_viewer`; a manifest schema that wrongly lists the GLB as identity-bearing fails
  `glb_flip_keeps_identity`.
- Determinism: the property run with a fixed seed selects the same blobs and bytes and gives the same verdicts twice on
  one machine and on Linux and macOS.

## Considerations

- The compile-fail tests depend on compiler error codes; they pin the expected codes, and a toolchain train that
  changes a message updates the expected output in the same change (the code numbers are stable).
- The random-byte property can miss a blob kind with few bytes; item 2 therefore draws the blob kind first, uniformly,
  and the byte second, so that every kind is hit about 1,000 / k times for k kinds.
- If a later feature needs to read the visual mesh outside the viewer (a deviation heat map is drawn by the viewer, so
  none is known), it must go through an ADR that amends ADR-HAB-04; the dependency rule is the enforcement.
- Privacy: fixtures are synthetic; no private pack is used, and logs never contain private paths.
