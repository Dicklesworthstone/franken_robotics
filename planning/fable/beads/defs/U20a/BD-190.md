## Background

**The docking fixture: a known answer with a closed-form boundary.** One small model exercises the clock contract, strict comparison, the alias witness and exact arithmetic together. Position is in metres and time in seconds. Owner: `frob-sense` with `frob-conformance`. Nothing about a real docking device follows from it.

**Model.** Three ticks of one second. x₀ = v₀ = 0. During tick k the acceleration is g·u_k, with a hidden gain g ∈ {1, 2} fixed for the episode and a command |u_k| ≤ U, for U in [½, 1]. The mission is (x₃, v₃) = (1, 0) exactly. The only informative packet is a reading of v₁ with additive error in [−ε, +ε].

**If the packet arrives before the second command.** Write p = u₀. The terminal conditions force u₁ = 1/g − 2p and u₂ = p − 1/g (from v₃ = g·(p + u₁ + u₂) and x₃ = g·(2p + u₁)). The command limits in both worlds leave 1 − U ≤ p ≤ (U + ½)/2. The reading lies in [p − ε, p + ε] if g = 1 and in [2p − ε, 2p + ε] if g = 2; the two required values of u₁ differ by ½, so the intervals must be disjoint, which is ε < p/2. Choosing the largest admissible p gives the exact boundary **ε < (U + ½)/4, equality excluded** (PO-SENS-06; theorem card T-23). With U = ¾ and p = ¼ the commands are (¼, ½, −¾) for g = 1 and (¼, 0, −¼) for g = 2, both reaching (1, 0), and the tolerable error is below 1/8. With p = 5/8 it is below 5/16: the first command is a probe, and a bolder probe buys a sensor two and a half times worse. At ε = 5/16 exactly, both worlds can report 15/16 while requiring u₁ = −¼ and u₁ = −¾: the strict predicate fails at equality (CX-213).

**If the packet arrives after the third command is committed.** A causal controller issues one command vector in both worlds; the final position g·(2p + u₁) cannot equal 1 for both gains. Every case is excluded.

**Grid known answer.** On U = ½ + i/32 for i = 0…16 and ε = j/64 for j = 0…32, the boundary admits a cell exactly when 2j < 32 + i: 344 of 561 cells are admitted, 217 excluded, and nine lie exactly on the boundary (the even i). All 561 cells are excluded when the packet is late.

**A hypothesis set widened by a hair.** Admit a third gain, 33/32. At U = ¾ and ε = 1/64 the reading (65/64)·p is possible for g = 1 and for g = 33/32 under every first command, so both worlds receive the same remaining commands; their final positions are c and 33c/32, and the smallest achievable worst error is 1/65 m, at c = 64/65. The rule this fixture enforces everywhere: a verdict is bound to the declared support of the hidden parameters, the delivery deadline, the error units and the target tolerance, and a change to any of them invalidates it (CX-214).

**Arithmetic.** The fixture is evaluated in exact integer arithmetic (class D0) and, as a control, in single precision. FACT (an executed boundary-screen experiment on this machine's Metal device and on both RTX 4090 cards, listed in the source register and to be re-read before a gate cites it): on the dense grid of 65,536 cases, one of the two grids of the boundary corpus, unguarded single precision gave 452 false admissions and 23,438 false exclusions; a guard band with exact fallback gave no final errors; an exact integer kernel gave none and produced identical bytes on every device. The fixture is therefore also the first test of the exact-integer kernel class and of guarded single precision. Tier: Solid.

## Scope

In: the device form of the docking fixture: the three predicates (exact, guarded, unguarded) evaluated in kernels on the 561-cell grid and on the 65,536-case screen, on `batch-cpu`, CUDA and Metal, compared byte for byte with the host fixture; the late-packet variant and the third-gain amendment re-evaluated on every backend; the gate's script and record. This bead is the capstone of GATE-SENS-13: it depends on the host fixture beads and adds the backends.

Out: the host fixture in exact rationals with its registered rows, constructive witnesses, grid, equality and late-packet cases (N20b-13); the three-gain amendment's exact enumeration, the verdict-binding record and the host-side single-precision controls (N20b-14); the kernels themselves (the exact-kernel probe, BD-030); the mission-side game and comparator (BD-129, N25c-20); the alias witness (BD-134).

## Technical approach

**1. Integer form.** With U = (16 + i)/32 and ε = j/64, the predicate 4ε < U + ½ is 2j < 32 + i. On the dense screen the inputs are multiples of 2⁻²⁸: U = a·2⁻²⁸, ε = e·2⁻²⁸ with unsigned integers a and e, and the predicate is 4e < a + 2²⁷, evaluated by `K-x-pred` on 32-bit words (4e ≤ 2²⁹ for ε ≤ ½, so no overflow).

**2. Three arithmetics.**
- *Exact:* the integer comparison above; class D0; the output byte per case must be identical on every backend.
- *Guarded:* the single-precision residual r̂ = (U + 0.5) − 4·ε with the certified bound on its rounding error (5·2⁻²⁵ for this conversion-and-addition sequence, below the deferral threshold 2⁻²¹); if |r̂| exceeds the threshold the sign decides, otherwise the case is deferred to the exact kernel. Final labels must equal the exact labels; the fallback fraction is recorded.
- *Unguarded (the control):* the sign of r̂ alone. It must mislabel cases near the boundary; the planning pilot's counts on the dense screen are 452 false admissions and 23,438 false exclusions.

**3. The late-packet variant.** The same grid with the packet's arrival after the third command is committed: the predicate is constant false; all 561 cells are excluded. It runs through the clock contract (a link latency above 1 s) on every tier, so that the result depends on the packet queue and the boundary rule and not on a flag.

**4. The third-gain amendment.** With the gain set {1, 33/32, 2}: gains 1 and 33/32 are separable only if the reading intervals [p − ε, p + ε] and [33p/32 − ε, 33p/32 + ε] are disjoint, that is ε < p/64, and p ≤ (U + ½)/2 ≤ ¾ gives ε < 3/256, which is below the grid's smallest positive error 1/64. So every admitted cell with ε > 0 is reversed: 327 of the 344. The 17 cells of the column ε = 0 remain admitted (an exact reading separates any two gains for a non-zero probe, and the command limits leave the same range 1 − U ≤ p ≤ (U + ½)/2). The fixture also checks the worked value: at U = ¾, ε = 1/64 the smallest worst-case final error is 1/65 m at c = 64/65.

**5. Oracle.** The closed form in exact rationals on the host, cross-checked on all 561 cells against two independent formulations: the docking family's scenario-tree comparator (from the raw state transition) and the docking-boundary oracle of the mathematics compendium (N12-46, `frob_conformance::compendium::d6`: feasible first commands 1 − U ≤ p ≤ (U + ½)/2, robust causal policy exactly when ε < (U + ½)/4 with the packet on time, none with it late). The oracles are never regenerated from the candidate kernels.

**6. GATE-SENS-13** (known answer, M2): 344, 217 and 9 in exact arithmetic on `batch-cpu`, CUDA and Metal with identical bytes; guarded single precision with fallback gives zero final errors; the third-gain amendment reverses every admitted cell.

- [ ] The unguarded single-precision kernel mislabels at least one case of the dense screen on every backend (the control), and its false-admission and false-exclusion counts are recorded beside the planning pilot's 452 and 23,438.
- [ ] All 561 cells are excluded with the late packet on every tier.
- [ ] Third-gain amendment: every admitted cell with ε > 0 (327 cells) is excluded; the 17 cells with ε = 0 stay admitted; the worst-error value 1/65 m at c = 64/65 is reproduced in rationals. The gate record states this reading of "reverses every admitted cell" (see Considerations).
- [ ] The nine boundary cells are excluded by the strict predicate and admitted by the non-strict mutant, which is thereby caught.
- [ ] The worked cases reproduce exactly: (¼, ½, −¾) and (¼, 0, −¼) reach (1, 0); at U = ¾, ε = 5/16, p = 5/8 both worlds can report 15/16.
- [ ] The host oracle agrees with the scenario-tree comparator and with the compendium's D.6 docking oracle on 561 of 561 cells.

Every line carries `ts`, `script`, `bead`, `step`, `event`, the command, exit code, wall time, the evidence block (determinism `exact` for the exact kernel, device fingerprint), measured counts against expected counts, label-buffer digests, and on failure the first differing cell (i, j). Summary: `gates: ["GATE-SENS-13"]`.

## Considerations

- **A statement in the plan that does not hold on the whole grid.** The plan says that under the three-gain amendment "every cell admitted under the two-gain mission is wrong", and the gate says the amendment "reverses every admitted cell". On the 561-cell grid that is true for the 327 admitted cells with positive error and false for the 17 cells with ε = 0, where an exact reading still separates the gains. (The planning pilot's statement that all 34,590 feasible labels reverse concerns its 65,536-row grid.) This bead tests what is true (327 reversed, 17 retained) and records the discrepancy for the lead; the gate's wording should become "every admitted cell with positive error".
- The pilot's counts (452 and 23,438) are FACT about a planning experiment; the gate cites this repository's re-measurement and reports both.
- The planning pilot also found that for a small host-resident job the host integer loop is faster than any device; the fixture runs on devices to test determinism classes, not for speed.
- Mission-side continuation: with a continuous gain interval and a finite position tolerance the amended game has its own closed form (least guaranteed tolerance (√1745 − 41)/32 m, about 24.2 mm, at U = ¾ and ε = 1/64), which belongs to the mission chapter.
