## Background

A sensor model is useful to a designer in proportion to the failures it shares with the instrument. Each failure mode is a parameter on the sensor card with provenance, a reason code in the validity mask or a flag on the packet, and a first independent check. Parameter values are `assumed` until a card records a datasheet or a measurement.

This bead is the capstone for sensor cards: one card schema per sensor kind that carries every failure mode of the table below; a provenance report for every field; the gate that says each Solid failure mode has its first check passing; and the refusal that stops a Reality claim from resting on a number nobody measured. It serves GOAL-19. Tier: Solid. The models themselves are separate beads (last column).

A card is a `.fcard` (the project's card format, with per-field provenance `measured`, `datasheet` or `assumed`, as for actuator and interface cards). Alternatives rejected: sensor parameters as free fields of the design file (no provenance, no reuse); a single "noise level" per sensor (the practice this subsystem replaces).

## Scope

In: card kinds and their failure-mode fields; card self-checks; the provenance report in `sense.profile`; the failure-mode register with first checks and owners; the card-side rule behind refusal `FROB-REF-447` (which fields are `assumed`, and the predicate over a set of card fields that the guard calls); the GATE-SENS-14 battery and record; the generic catalogue of `assumed` cards. This bead is the capstone of GATE-SENS-14: it depends on the model beads that own the rows and gathers their first checks.

Out: each model's implementation (owner beads); the guard that computes a result's dependency set and raises `FROB-REF-447` where a Reality claim is requested or attached, with its envelope and end-to-end script (N20b-18, which depends on this bead: the statement of the refusal in section 5 and its acceptance line and unit tests below are met here on a synthetic field set through the predicate, and from a verb by N20b-18); the calibration self-check that is the first check of the extrinsic-bump row (N20b-06); which real parts get datasheet or measured cards (N20a-32); optical cards of scene regions (the scene chapter; their fields feed the same refusal).

## Technical approach

**1. The failure-mode register** (the table of the chapter, with the card parameter, the mask reason or flag, and the owner).

**2. Card kinds** (`sensor.encoder`, `sensor.imu`, `sensor.readout`, `sensor.contact-switch`, `sensor.force-torque`, `sensor.depth`, `sensor.lidar`, `sensor.camera`, `link`, and the device-clock block every kind embeds). Each field has a value, a unit and a provenance: `measured` (with the measurement record's identity), `datasheet` (with the document reference and page), or `assumed` (with the range it was chosen from). A card has an identity (content hash) that is part of the observation service identity.

**3. Card self-checks** (run by the card check and by preflight): required fields present; units right; ordering constraints (`f_on` > `f_off`, `range_min` < `range_max`, `latency_min` ≤ `latency_max`); the reorder window consistent with latency bounds and period; `p_miss` only on incremental encoders; a probabilistic dropout cause declared `per-region-episode`; a `global-instantaneous` shutter labeled as an idealization.

**4. Provenance in `sense.profile`.** For every sensor of a design and task: the card identity, each field with value, unit and provenance, the share of fields in each provenance class, the failure modes the card enables with the status of each first check (`pass`, `fail`, `not run`, `not modeled (fallback)`), and the Frontier models requested with their status.

**5. Refusal `FROB-REF-447`** ("a Reality claim rests on a sensor or optical card field of class `assumed`"; exit code 3). Raised when a result asks for a Reality claim (anything other than `no-claim` in the claim product's reality field) and any sensor card field, link card field or optical card field read by the runs behind the result is `assumed`. `pointer`: the card and field; `affected_claims`: the Reality claim; ranked repairs: record a datasheet or a measurement; drop the claim. With the default catalogue every sensor result is therefore Reality `no-claim`.

**6. Generic catalogue.** One `assumed` card per sensor kind and class (for example a generic 1 kHz industrial IMU, a generic 30 Hz projected-pattern depth camera, a generic 10 Hz spinning lidar), with ranges stated, so that designs can be written before any real part is admitted.

**7. GATE-SENS-14** (known answer, M3): every failure mode marked Solid has its first check passing, and every card field reports its provenance.

## Acceptance criteria

- [ ] GATE-SENS-14 recorded with measured values (seed done-condition): for each row of the register except the Frontier flying-pixel clause, the first check passes on the tiers its owner names; the record lists each check's measured value against its expectation.
- [ ] Every field of every card kind reports a provenance; a card with a field lacking provenance fails to load; the profile's provenance shares sum to one.
- [ ] `FROB-REF-447` is raised for a result that requests a Reality claim with any `assumed` sensor, link or optical field, with exit code 3 and both repairs; the same request with all fields `datasheet` or `measured` (a synthetic card) is not refused by this rule.
- [ ] Card self-checks reject each of six malformed cards (missing field, wrong unit, `f_on` ≤ `f_off`, understated reorder window, `p_miss` on an absolute encoder, `per-sample` dropout).
- [ ] `sense.profile` lists, per sensor, the failure modes with first-check status and marks a fallen-back Frontier model as `not modeled (fallback)`.
- [ ] A change to any card field changes the card identity and the observation service identity.
- [ ] The negative control of the gate is caught: a card kind whose saturation is silently disabled (the drop test passes through the true value) fails its row.

## Test plan

### Unit tests
`crates/frob-sense/tests/cards.rs`; `cargo test -p frob-sense cards`.
- `every_kind_roundtrips`: each card kind serializes and loads with identical identity.
- `provenance_required`; `provenance_shares_sum`.
- `self_check_rejections`: the six malformed cards.
- `ref_447_on_assumed`: a synthetic result requesting a Reality claim over the generic catalogue is refused naming the first assumed field; `ref_447_not_on_measured`.
- `profile_lists_failure_modes`: 20 register rows map to card fields; each sensor kind shows its rows.
- `card_identity_sensitivity`.
- `register_complete`: every row has an owner bead and a registered first-check test; a row with no test fails the meta-test.
- `fallback_status_shown`.

### End-to-end script and logging
`scripts/e2e/sense_optical_failures.sh` (N20a-46) has a sensor-card half: `frob sense profile <design> --task <task> --json` (asserting provenance on every field and the failure-mode list); the first-check fixtures of each register row through `frob sim run` and `frob telemetry query`; the gate's harness rows in their cargo form, `cargo test -p frob-conformance --test g1_known_answers -- GATE-SENS-14` (the Gauntlet has no `frob` verb, ADR-GAUNT-01), with the receipt's per-row results logged; and a refusal stage in which a result is requested with `--claim reality` and must return exit code 3 with code 447. Lines log each row's measured value, expectation and tolerance, provenance shares, and the refusal envelope; summary gate `GATE-SENS-14`.

### Known answers and negative controls
KA-510 to KA-522 (the first checks of the register rows, each with its owner), KA-475, KA-479 to KA-485 (rows shared with other gates). Negative controls: a field without provenance; the disabled-saturation card; a Reality claim over assumed fields. Determinism: card identities are content hashes, equal on Linux and macOS.

## Considerations

- OPEN-SENS-4 (owner: project lead; blocks any Reality claim that depends on sensing): which sensor and optical cards ship with datasheet or measured fields. Fail-closed default: all `assumed`, Reality `no-claim`, enforced by refusal 447. The decision package is N20a-32.
- Several first checks have tolerances the known-answer registry still lists as "to set"; each owner bead proposes one, and the gate cannot be recorded as passed for a row until its tolerance is registered.
- A datasheet value is a claim by a vendor; the provenance class says so, and calibration against measurement may later replace it.
- Licences of datasheets and measured tables are recorded with the card; a card whose source licence forbids redistribution is marked private.
