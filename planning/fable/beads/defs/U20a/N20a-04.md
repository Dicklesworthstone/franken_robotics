## Background

**ADR-SENS-10: noise streams are keyed by logical identity** (world address, sensor, sample index, component), never by draw order. Reason: adding a sensor must not change what the others read. **INV-SENS-06: adding, removing or reordering sensors does not change what the others read.**

The shortcut this replaces (CX-215): a generator that hands out draws in call order. The smallest case: a sequential stream r₀, r₁, r₂. Design A draws a push (r₀) and a friction value (r₁). Design B has one more leg and draws a per-leg value first, so its push is r₁ and its friction r₂. The seeds are equal and the two designs were pushed differently. For sensors: add a camera, and the IMU's noise in every later step is a different sequence, so a paired comparison of two sensor suites compares different worlds.

FACT (sibling code): FrankenSim's `fs-rand` provides counter-based Philox streams keyed by `(WorldAddr, step, stream_id)`; there is no generator state on a device. DESIGN rules already fixed for the project: Philox is 32-bit integer arithmetic, so a draw is determinism class D0 on every backend; a uniform single-precision value in [0, 1) is (x ≫ 8)·2⁻²⁴, which is exact; a normal variate built from deterministic elementary functions is class D2 per backend and D1 across backends only where the cross-backend gate passes; a draw depends on nothing but its key (not on slot, bucket, variant index, shard, device or batch size); `stream_id` names a purpose in a registry, and adding a stream changes no draw of any other stream; a sensor's noise is keyed by the hash of its port name.

## Scope

In: the key scheme for every random quantity Sensorium draws; registration of sensor streams; the correlated-noise process type (bias random walk) with its state in the checkpoint; the draw-order negative control.

Out: the generator itself; per-sensor noise parameters (sensor beads); the link model's use of the keys (N20a-08); region latents (N20a-24); the noninterference battery on every tier (BD-215).

## Technical approach

**1. Key scheme** (DESIGN). A draw is `philox(world_address, stream_id, counter)`, where the world address is the conventions' `WorldAddr = (run_seed, world, episode)`: the episode is part of the address, so a sensor's sample index may restart at each episode without repeating its noise, and a fork's child has its own address. The stream identifier and counter are:

| Purpose | `stream_id` | `counter` |
|---|---|---|
| White measurement noise of a sensor | hash(sensor port name, "noise") | (sample index, component index) |
| Increment of a correlated process | hash(sensor port name, "process", process name) | (process step index, component index) |
| Link model | hash(sensor port name, "link") | (sequence number, component ∈ {latency, loss, duplication, reorder}) |
| Phase redraw at an episode reset | hash(clock name, "phase") | (episode index) |
| Region latent | hash(region identifier, latent name) | (episode index) |

The sample index is the sensor's own sequence number, so the k-th sample of a sensor draws the same noise whether or not other sensors exist, whatever order kernels run in, and whatever slot the world occupies. A multi-component sample (a pixel grid, a beam set) indexes components by their position in the sensor's own pattern.

**2. Registration.** Each sensor registers its streams at environment creation; the registry records name, purpose, distribution and parameters, and is part of the observation service identity. A collision of two port-name hashes is a registration error (names are unique within a design, and the hash is 64 bits with a collision check).

**3. Correlated noise processes.** A bias random walk b with rate density σ_b (in units of b per √s, from the card; for a gyro bias in rad/s, σ_b is in rad/s/√s) advances at each sample of period Δt by

  b_{k+1} = b_k + σ_b·√Δt·n_k,

with n_k a unit normal drawn by key (process step k, component). Because b is a running sum, it is state: it lives in a per-world, per-sensor slab, and that slab is part of every checkpoint (the clock contract's rule that clocks, open exposures, queues and noise-process states are in every checkpoint). √Δt is a constant computed once at admission from the rational period. A first-order Gauss–Markov process (correlation time τ) uses b_{k+1} = a·b_k + s·n_k with a = exp(−Δt/τ) and s = σ·√(1 − a²), both admission-time constants.

**4. Retries.** On the referee a step may be retried with a smaller sub-interval; process increments for an interval are defined on the dyadic tree of the base interval, so a retry refines the path it already drew and cannot redraw it.

**5. The negative control.** A feature-gated test generator `DrawOrderRng` hands out draws from one sequential stream in call order. The sensor-set test must fail with it. Its feature is the `frob-sense` mutation feature `draw-order-noise`, the control that N20-CX names for CX-215 and that BD-215 runs as GATE-SENS-03's control, so the program has one plant of this defect. As BD-025 and N38b-04 set the rule, it implies the crate's `conformance` feature, is never a default and is never in the `gauntlet-mutations` umbrella. The control runner builds it alone (`--features gauntlet-mutations,frob-sense/draw-order-noise`), and this bead's `draw_order_control_fails` runs as `cargo test -p frob-sense --features draw-order-noise draw_order`.

## Acceptance criteria

- [ ] On a fixture with an IMU and an encoder, adding a second IMU, removing the encoder, or swapping the declaration order leaves every remaining sensor's noise bytes unchanged over 10⁴ samples (INV-SENS-06, unit level).
- [ ] The same key gives the same draw alone, in a batch of 8,192 and in any slot on the host at M1; on every backend (integer draws bit-equal; normal variates inside their class) once the batched sensor kernels exist, which N20b-44 checks at M2 against this bead's host draws.
- [ ] The bias-walk state is serialized in the checkpoint; a restore mid-run continues the same walk byte for byte; a checkpoint with the state stripped does not.
- [ ] With `DrawOrderRng` the sensor-set test fails (the control is caught).
- [ ] The stream registry is part of the observation service identity; a hash collision is refused at registration.
- [ ] No sensor code path calls a stateful generator (a lint over the crate forbids the type outside the test control).

## Test plan

### Unit tests
`crates/frob-sense/tests/noise.rs`; `cargo test -p frob-sense --test noise`.
- `key_independence_add_sensor`, `key_independence_remove_sensor`, `key_independence_reorder`: byte equality of the unaffected sensor's 10⁴ noise samples.
- `key_independent_of_slot_and_batch`: world address 311 alone, at slot 0 and slot 4,095 of a batch.
- `uniform_conversion_exact`: (x ≫ 8)·2⁻²⁴ for x = 0, 255, 256, 2³² − 1 gives 0, 0, 2⁻²⁴, 1 − 2⁻²⁴.
- `bias_walk_variance`: over 4,096 worlds and 1,000 steps the sample variance of b is within 5% of σ_b²·t (synthetic; a statistical check with a fixed seed set).
- `bias_walk_checkpoint_roundtrip`: restore at step 500, compare steps 501 to 1,000 byte for byte.
- `gauss_markov_constants`: a and s for Δt = 0.01 s, τ = 1 s equal exp(−0.01) and σ·√(1 − exp(−0.02)) to the last bit of the deterministic functions.
- `draw_order_control_fails`: with `DrawOrderRng`, `key_independence_add_sensor` fails.
- `hash_collision_refused`: two synthetic port names forced to one hash are rejected.

### End-to-end script and logging
Exercised by the noninterference script of BD-215 (sensor-set row) and by `scripts/e2e/sense_clock_contract.sh` (N20a-44), which runs one world with and without an extra unconsumed sensor and asserts equal delivered-observation digests, logging both digests and the first differing packet on failure.

### Known answers and negative controls
KA-507 (sensor-set noninterference; control: a sensor added to a draw-order generator). CX-215. The fifth planted leak of the causal-policy test (a noise stream keyed so that a hidden parameter shifts the draws of a visible sensor) is the same defect class and is caught by BD-119. Metamorphic: permuting sensor declaration order permutes nothing in any sensor's stream. Determinism lanes: twice on one machine; across worker counts; debug and release; across backends (integer draws D0).

## Considerations

- Normal variates are only as portable as the deterministic elementary functions; where cross-backend bit equality has not been shown, noise is class D2 per backend and comparisons across backends are tolerance comparisons. The integer draws underneath are exact everywhere.
- Renaming a sensor port changes its noise. That is intended (a port name is the identity of the physical entity), and the design diff reports it.
- Memory: process state is a few floats per sensor per world.
- Revisit if a sensor needs spatially correlated noise across samples of one pattern (speckle): that is a keyed field over pattern coordinates, still without draw order.
