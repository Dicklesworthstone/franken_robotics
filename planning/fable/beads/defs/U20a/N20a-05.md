## Background

**ADR-SENS-03: seven instants are distinct fields.** Sample, exposure, timestamp, arrival, decision, command and actuation are stored separately on every packet and command, and none is inferred from another. Reason: each pair that is conflated hides a class of real failure: stale data (arrival taken for sample), mis-stamped data (timestamp taken for sample), a command applied before it could have been computed (decision taken for actuation). Construction C-19 states the same object: every datum that crosses from physics to a controller passes these seven instants, and a causal policy may use only packets that have arrived.

| # | Instant | Definition | Set by |
|---|---|---|---|
| 1 | **Sample** | The sensor's clock fires: the nominal trigger and the start of its exposure | The sensor's clock |
| 2 | **Exposure** | The close of the half-open window [open, close) over which the instrument integrates. Zero length for an instantaneous sensor; one window per row for a rolling shutter | Exposure and readout fields of the sensor card |
| 3 | **Timestamp** | The time the device writes on the packet, in its own clock with its own offset and drift, at a declared point of the exposure (start, middle or end) | The device-clock model |
| 4 | **Arrival** | The packet becomes readable by its consumer, after transport latency, jitter, loss, duplication and reordering | The link model |
| 5 | **Decision** | An estimator or controller tick reads its inputs | The consumer's clock |
| 6 | **Command** | The tick's output is issued, after compute latency | The controller card |
| 7 | **Actuation** | The command takes effect at the actuator, after bus and driver latency, and holds over the following open interval | The actuator card |

Order constraints: sample ≤ exposure ≤ arrival; a packet is used by a decision at t only if its arrival is at or before t; decision ≤ command ≤ actuation. The timestamp is deliberately unconstrained: it is what the device believes, and an estimator that trusts timestamps over arrival order is exposed to the errors a real one has.

Alternatives rejected: one `time` field per message (the common practice; it cannot say whether the time is a trigger, a stamp or a receipt); deriving arrival from sample plus a constant (hides jitter, loss and reordering); forcing timestamps to be causal (hides clock offset, the commonest calibration fault).

## Scope

In: the packet and command types with their instant fields; constructors that enforce the order constraints; the device-clock model; observation age; the flags `late` and `held`; the first check of the "clock offset and drift, wrong timestamp point" failure mode.

Out: how arrival is drawn (N20a-08); the order of work at a boundary (N20a-06); lateness under each intra-step policy (N20a-07); queues and checkpoints (BD-098).

## Technical approach

**1. Types** (DESIGN; every time is an integer count of quanta of 1/Q seconds).

```rust
pub enum Instant { Sample, Exposure, Timestamp, Arrival, Decision, Command, Actuation }
pub struct DeviceTime(pub i64);                       // device ticks; signed, because an offset can be negative
pub struct Packet {
    sensor: SensorId, seq: u32,
    t_sample: Quanta, t_exposure: Quanta, t_stamp: DeviceTime, t_arrival: Quanta,
    lateness: Quanta, mask: MaskRef, payload: BufRef,
}
pub struct Command { t_decision: Quanta, t_command: Quanta, t_actuation: Quanta, payload: BufRef }
pub struct Age(pub Quanta);                           // decision − sample
```

A packet carries the first four instants; the consumer's tick supplies the decision instant; a command carries the last three. `Packet::new` refuses (a typed error, and a debug assertion in kernels) unless `t_sample ≤ t_exposure ≤ t_arrival`; `Command::new` unless `t_decision ≤ t_command ≤ t_actuation`. No constructor fills one instant from another by default: each must be supplied.

**2. Where each field comes from.** `t_sample`: the nominal firing instant from the phase accumulator (plus lateness under `hold`: the realized instant is `t_sample + lateness`, and both are stored). `t_exposure`: `t_sample` plus the exposure length from the card (per row for a rolling shutter: the packet stores the close of the last row; per-row instants are derivable from the card's row time). `t_arrival`: `t_exposure` plus the link's transport latency. `t_command`: `t_decision` plus the controller card's compute latency (a rational in the lattice). `t_actuation`: `t_command` plus the actuator card's bus and driver latency. A latched command acts over the open interval that follows its actuation instant.

**3. The device-clock model.** Each device has `offset` (rational seconds), `rate_error` ε_dev (rational; 50 parts per million is 1/20,000), `tick` (the resolution of its timestamp, a rational) and `stamp_point` ∈ {start, middle, end} of the exposure. With t_p the true instant of the stamp point (start = `t_sample`, end = `t_exposure`, middle = their midpoint),

  t_stamp = ⌊ (offset + (1 + ε_dev)·t_p) / tick ⌋  device ticks,

computed in exact rational arithmetic at admission-time scaling (the per-sample work is integer multiply, add and divide). Two devices with different rate errors drift apart at the declared rate; a wrong `stamp_point` on a card shifts every stamp by half or all of the exposure.

**4. Age.** Every observation exposes its age, decision minus sample, as an integer count of quanta. Telemetry always records it. A policy receives it only if its observation schema declares it (OPEN-SENS-3). A held value (re-presented because no newer packet has arrived) is never presented as fresh: its age keeps growing and the `held` flag is set once the age exceeds one period of the sensor.

## Acceptance criteria

- [ ] Every packet and command in a run carries all of its instants; a schema check over a recorded episode finds none missing and none equal by construction to another (the fixture uses non-zero exposure, latency and compute delay so that all seven differ).
- [ ] Constructing a packet with arrival before exposure, or a command with actuation before command, is a typed error.
- [ ] A device clock with a negative offset produces timestamps earlier than the sample instant, and the packet is accepted (the timestamp is unconstrained).
- [ ] Two sensors whose device clocks differ by 50 parts per million stamp simultaneous samples 1 ms apart after 20 s, exactly (to the tick resolution).
- [ ] Changing `stamp_point` from start to end on a 10 ms exposure moves every timestamp by exactly 10 ms; to middle by 5 ms (device with ε_dev = 0 and a tick of 1 ms; with a rate error the shift is (1 + ε_dev) times as large, floored to the tick, and the test checks that value too).
- [ ] Age equals decision minus sample for every delivered observation in telemetry; a held value's age grows by the decision period at each tick and carries `held`.

## Test plan

### Unit tests
`crates/frob-sense/tests/instants.rs`; `cargo test -p frob-sense --test instants`.
- `packet_order_enforced`: (sample 10, exposure 5) and (exposure 20, arrival 15) are refused; equal instants are accepted (an instantaneous sensor on a zero-latency link).
- `command_order_enforced`: decision 40, command 39 refused.
- `all_seven_distinct_fixture`: on the fixture (exposure 10 ms, link 4 ms, a 100 Hz controller of phase 0, compute 2 ms, actuation 1 ms, device offset −3 ms) the seven values are pairwise different and equal the hand-computed set for the first packet: sample 0, exposure 10 ms, stamp −3 ms (start point), arrival 14 ms, decision 20 ms (the first controller tick at or after 14 ms; the controller's period is chosen so that no tick falls on 14 ms, which would make decision equal arrival), command 22 ms, actuation 23 ms.
- `device_clock_ppm`: stamps of two devices, ε = 0 and ε = 1/20,000, at true time 20 s differ by 1 ms.
- `stamp_point_shift`: start, middle, end on a 10 ms exposure give stamps 0, 5, 10 ms after the offset.
- `timestamp_unconstrained`: stamp earlier than sample accepted.
- `age_integer`: decision 42 quanta, sample 40 quanta gives age 2 quanta.
- `held_never_fresh`: with the sensor stopped, successive decisions report ages increasing by the decision period and the `held` flag.
- Property: for random admissible cards, sample ≤ exposure ≤ arrival and decision ≤ command ≤ actuation hold for every generated packet and command.

### End-to-end script and logging
Exercised by `scripts/e2e/sense_clock_contract.sh` (N20a-44): it runs the seven-instant fixture, queries the telemetry packet stream, asserts the seven values of the first packet and command, and logs them as `metric` lines in quanta and in seconds as rationals.

### Known answers and negative controls
KA-473 (50 parts per million gives 1 ms after 20 s; control: a floating-point accumulator drifts from this). Negative controls: a build that copies `t_sample` into `t_stamp` (the device-offset test must fail); a build that sets arrival = sample (the seven-distinct fixture must fail). Determinism: class D0; all fields are integers.

## Considerations

- OPEN-SENS-3 (owner: Sensorium lead; decided at M3 with the first tasks that randomize latency): whether age is a default policy input. Fail-closed default: always in telemetry; to a policy only when its schema declares it.
- An estimator that uses timestamps will be wrong under offset and drift; that is the point. The comparator estimator and the calibration tools exist to detect it.
- The plan's conventions chapter defines the same seven instants with one difference in wording for the sample instant ("emission of a ray, start of an exposure, latch of an encoder"); the definitions agree. The half-open window convention differs between the two chapters; the owner decision N20a-49 rules it and N20a-06's `window_contains` implements the ruling (the exposure field here stores the close instant either way).
- Storage: 4 integers per packet and 3 per command; negligible beside payloads.
