## Background

Several events can share one instant: a sample closes, a packet arrives, an estimator ticks, a watchdog fires, a command latches. The boundary ordering rule fixes the order between stages; within a stage it fixes a stable logical order, and the result must not depend on that order where the events are independent. A *schedule race* is a pair of same-instant events whose relative order changes the result and which the rule does not order. The schedule-race check (a Frontier mechanism, N20a-10) looks for such pairs by enumerating one representative of each equivalence class of orderings and comparing digests. Two orderings are equivalent when they differ only by swapping independent events.

Every Frontier mechanism has a paper-scale pilot with a falsifier that runs before its work is funded, and states the ceiling of its benefit before any speed test. This bead is that pilot.

**Ceiling of the benefit:** a correctness guard with no speed benefit. It can only prevent a class of timing defects in the simulator and in controllers attached to it; it makes nothing faster.

**Falsifier:** plant one stale read and one watchdog-against-latch race in a fixture; the check is funded beyond the fixture only if it finds both. **Kill gate:** KILL-SCHED (one planted race missed); **fallback:** the fixed total order of the boundary rule with no enumeration.

FACT (sibling code): `asupersync` has a deterministic laboratory runtime (`asupersync/src/lab/runtime.rs`, `LabRuntime`) in which such schedules can be driven.

## Scope

In: the frozen protocol; the hand-checkable six-event fixture; the two planted races; the one-pair stale-read fixture that the pilot of construction C-19 also needs; a throwaway enumerator written for the pilot (it may later become the mechanism); the pilot record with its result.

Out: the production mechanism and its wiring into the conformance tiers (N20a-10); the decision (N20a-11); the pilot of construction C-19 (N10b-10, record `PILOT-C-19`, which depends on this bead): its docking-grid half is its own, and its second falsifier clause, "the planted race missed", is evaluated on the one-pair fixture of this bead, re-run through this bead's command and cited by this record's content hash. This bead is the only place where a planted stale read and the enumerator that must find it are built; N10b-10 builds neither.

## Technical approach

**1. The six-event fixture** (the known answer). Six same-instant events in three pairs: (a₁, a₂), (b₁, b₂), (c₁, c₂). The two events of a pair conflict (one writes what the other reads); events of different pairs are independent (disjoint read and write sets). There are 6! = 720 orderings. Swapping two adjacent independent events does not change the class, so a class is determined by the relative order inside each pair: 2³ = 8 classes. The enumerator must visit exactly 8 representatives and every one of the 720 orderings must map to one of them.

**2. The planted races.**
- *Stale read.* An estimator tick and a packet delivery for the sensor it reads are placed in the same stage with a shared "latest value" cell: the delivery writes it, the tick reads it. If the tick runs first it reads the previous sample. The boundary rule itself orders delivery before decisions; the plant is a consumer that bypasses the delivered set and reads the cell.
- *Watchdog against latch.* A watchdog that fires at t when no command has been latched since t − T_w, and a command that latches at exactly t. If the watchdog is evaluated first it trips the safe stop; if the latch is first it does not.

Each plant changes the run digest in exactly the classes where its pair is ordered the wrong way.

**3. Protocol, frozen in the pilot record before execution.**
1. Write the fixture as tasks on the deterministic laboratory runtime: one task per event, with declared read and write sets.
2. Enumerate one representative per class by canonical ordering (among equivalent orderings, the lexicographically least under a fixed event numbering).
3. Run each representative from the same initial state; compute a digest of the final state and of every delivered observation and latched command.
4. Report every pair of classes whose digests differ, and reduce each difference to a single adjacent swap (the racing pair).
5. Controls: (i) the clean fixture, in which the three conflicting pairs are ordered by stage and no same-stage conflict exists, must report no race; (ii) the fixture with only the stale read planted must report exactly that pair; (iii) with only the watchdog plant, exactly that pair; (iv) with both, both; (v) the one-pair fixture (the form in which construction C-19 states its pilot, moved here from N10b-10): six same-instant events named capture, delivery, estimator read, watchdog expiry, actuator commit and one unrelated timer, with a single conflicting pair, delivery and estimator read, so that the 720 orderings fall in 2 classes of 360 each. Planted, the order read-before-delivery commits a command computed from a stale value: the two class representatives must give two different commit digests and the report must name the stale value. Un-planted (the pair made independent in fact, by reading after a barrier), all classes give one digest.
6. Record wall time and the number of runs (8 per fixture against 720 exhaustive).

**4. Reachable verdicts.** `pass` (both plants found in (ii) to (iv), none reported in (i), 8 classes counted; in (v) 2 classes counted, the planted pair found and the un-planted schedule clean); `falsified` (a plant missed, or a false race reported on a clean fixture, or a class count other than 8, or 2 in (v)). The result of (v) is recorded as its own block of the record, with the fixture's digest, because `PILOT-C-19` cites it.

**5. Record.** One record of N38a-09's pilot register (`crates/frob-conformance/registry/pilots.toml`, schema `frob.gauntlet.pilot/1`), entered with status `registered` before the first run: an identifier of the set `SENSE` (`PILOT-SENSE-<nn>`, the next free number the register assigns, as N20a-18 does), `mechanism` = "schedule-race check", `tier = "F"`, `owner = "§20.4.7"`, `bead = "N20a-09"`, `work_package = "WP-40"`, `gated_beads = ["N20a-10"]`, `protocol` = `docs/pilots/sense-sched-race.md` (the protocol of item 3) with its BLAKE3, freeze date and ledger sequence, `falsifier` = "one planted race missed, a race reported on a clean fixture, or a class count other than 8 (2 on the one-pair fixture)", `ceiling` = { statement = "a correctness guard", value = "none on speed" }, `fallback` = { ships = "the fixed total order of the boundary ordering rule, with no enumeration", kill_gate = "KILL-SCHED" }, `cost`, `tool` = { name = "asupersync LabRuntime", pin = the workspace's pinned version, site = "host" }. The result is an appended `[[pilot.result]]` with the protocol's BLAKE3, the command, the class counts and the eight digests per fixture as `values`, the one-pair fixture's entries with that fixture's digest (which `PILOT-C-19` cites), and the verdict: `pass` is recorded `falsifier-rejected` and `falsified` is recorded `falsifier-holds` (N38a-09's vocabulary).

## Test plan

### Unit tests
`crates/frob-conformance/tests/pilot_sched_race.rs`; `cargo test -p frob-conformance --test pilot_sched_race`.
- `six_events_eight_classes`: class count 8; `all_720_map_to_8`.
- `clean_fixture_no_race`: 8 equal digests.
- `stale_read_found`: digests split into two groups of four; the reported pair is (delivery, estimator tick).
- `watchdog_latch_found`: the reported pair is (watchdog, latch).
- `both_found`: four distinct digests; both pairs reported.
- `reduction_to_adjacent_swap`: for each reported difference, two orderings that differ by one adjacent swap reproduce it.
- `one_pair_two_classes_of_360`: six events with one conflicting pair: 2 classes of 360 orderings each (the one-pair variant of KA-115).
- `one_pair_stale_read_found`: two digests; the reported pair is (delivery, estimator read); the stale value is named.
- `one_pair_barrier_one_digest`: with the read placed after a barrier, one digest across both classes.
- `arrival_order_explorer_misses`: an explorer that orders same-instant events by arrival explores one ordering only and misses the planted stale read; the pilot's check reports that miss as a failure of that explorer.

### End-to-end script and logging
`scripts/e2e/pilot_sched_race.sh` (sources the STD-E2E helper): runs the four fixtures and the one-pair fixture (planted and un-planted) through the pilot's command, `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test pilot_sched_race` (the Gauntlet has no `frob` verb, ADR-GAUNT-01; the same command is written in the result's `commands` field, and `--test pilot_sched_race -- one_pair` runs the one-pair fixture alone, as N10b-10 calls it), reads the appended result of this bead's record in `crates/frob-conformance/registry/pilots.toml` read-only and asserts that the protocol digest was frozen before the first run, asserts the verdict and the class counts, and writes NDJSON to `target/e2e-logs/pilot_sched_race/<utc>.ndjson`: per fixture a `metric` line with `classes`, `runs`, `distinct_digests`, the reported pairs, and wall time; the summary names `KILL-SCHED`.

### Known answers and negative controls
KA-478 (720 orderings in 2³ = 8 classes; both planted races must be found); KA-115 (the same count for construction C-19, whose pilot plants one stale-read race: the one-pair fixture, 2 classes). The planted races are the negative controls of the mechanism; the controls of the pilot itself are a deliberately blinded enumerator (it skips classes in which the watchdog precedes the latch) that must be reported `falsified`, and the arrival-order explorer above, which must be reported as missing the stale read. Determinism: the laboratory runtime replays each ordering identically; digests are equal twice on one machine.

## Considerations

- The pilot is deliberately small and exhaustive-checkable. Passing it says the enumeration and the reduction are right on a known structure; it does not say that the declared independence relation of real kernels is right. The mechanism therefore also samples orderings inside a class (N20a-10).
- If the laboratory runtime cannot express the fixture at the pinned version, or is not yet admitted when the pilot runs, the pilot runs on a small hand scheduler written for it (a deterministic event loop of 50 to 100 lines) and the record says so and is marked `partial` until the run is repeated on the runtime; the falsifier is unchanged. (One rule for this bead and N10b-10, which had stated it as 100 lines and `partial`, against 50 lines and no mark here; DESIGN: the size is a bound, and `partial` is kept because a hand scheduler is not the runtime the mechanism will run on.)
- Cost: seconds. There is no reason to skip it.
