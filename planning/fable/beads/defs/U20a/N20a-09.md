## Background

Several events can share one instant: a sample closes, a packet arrives, an estimator ticks, a watchdog fires, a command latches. The boundary ordering rule fixes the order between stages; within a stage it fixes a stable logical order, and the result must not depend on that order where the events are independent. A *schedule race* is a pair of same-instant events whose relative order changes the result and which the rule does not order. The schedule-race check (a Frontier mechanism, N20a-10) looks for such pairs by enumerating one representative of each equivalence class of orderings and comparing digests. Two orderings are equivalent when they differ only by swapping independent events.

Every Frontier mechanism has a paper-scale pilot with a falsifier that runs before its work is funded, and states the ceiling of its benefit before any speed test. This bead is that pilot.

**Ceiling of the benefit:** a correctness guard with no speed benefit. It can only prevent a class of timing defects in the simulator and in controllers attached to it; it makes nothing faster.

**Falsifier:** plant one stale read and one watchdog-against-latch race in a fixture; the check is funded beyond the fixture only if it finds both. **Kill gate:** KILL-SCHED (one planted race missed); **fallback:** the fixed total order of the boundary rule with no enumeration.

FACT (sibling code): `asupersync` has a deterministic laboratory runtime (`asupersync/src/lab/runtime.rs`, `LabRuntime`) in which such schedules can be driven.

## Scope

In: the frozen protocol; the hand-checkable six-event fixture; the two planted races; a throwaway enumerator written for the pilot (it may later become the mechanism); the pilot record with its result.

Out: the production mechanism and its wiring into the conformance tiers (N20a-10); the decision (N20a-11).

## Technical approach

**1. The six-event fixture** (the known answer). Six same-instant events in three pairs: (a₁, a₂), (b₁, b₂), (c₁, c₂). The two events of a pair conflict (one writes what the other reads); events of different pairs are independent (disjoint read and write sets). There are 6! = 720 orderings. Swapping two adjacent independent events does not change the class, so a class is determined by the relative order inside each pair: 2³ = 8 classes. The enumerator must visit exactly 8 representatives and every one of the 720 orderings must map to one of them.

**2. The planted races.**
- *Stale read.* An estimator tick and a packet delivery for the sensor it reads are placed in the same stage with a shared "latest value" cell: the delivery writes it, the tick reads it. If the tick runs first it reads the previous sample. The boundary rule itself orders delivery before decisions; the plant is a consumer that bypasses the delivered set and reads the cell.
- *Watchdog against latch.* A watchdog that fires at t when no command has been latched since t − T_w, and a command that latches at exactly t. If the watchdog is evaluated first it trips the safe stop; if the latch is first it does not.

Each plant changes the run digest in exactly the classes where its pair is ordered the wrong way.

**3. Protocol, frozen in the pilot record before execution.**
1. Write the fixture as tasks on the deterministic laboratory runtime: one task per event, with declared read and write sets.
2. Enumerate one representative per class by canonical ordering (among equivalent orderings, the lexicographically least under a fixed event numbering).
3. Run each representative from the same initial state; compute a digest of the final state and of every delivered observation and latched command.
4. Report every pair of classes whose digests differ, and reduce each difference to a single adjacent swap (the racing pair).
5. Controls: (i) the clean fixture, in which the three conflicting pairs are ordered by stage and no same-stage conflict exists, must report no race; (ii) the fixture with only the stale read planted must report exactly that pair; (iii) with only the watchdog plant, exactly that pair; (iv) with both, both.
6. Record wall time and the number of runs (8 per fixture against 720 exhaustive).

**4. Reachable verdicts.** `pass` (both plants found in (ii) to (iv), none reported in (i), 8 classes counted); `falsified` (a plant missed, or a false race reported on the clean fixture, or the class count is not 8).

**5. Record.** A row in `frob-conformance/registry/pilots.toml`: mechanism "schedule-race check", tier [F], protocol digest, falsifier, ceiling ("no speed benefit"), fallback and kill gate (KILL-SCHED), cost, tool and pin (asupersync at the workspace's pinned version), result with the eight digests per fixture.

## Acceptance criteria

- [ ] The pilot record exists with the protocol's digest dated before the first run.
- [ ] The enumerator visits exactly 8 class representatives on the six-event fixture and maps all 720 orderings onto them (an exhaustive cross-check run once).
- [ ] The clean fixture reports no race; each single-plant fixture reports exactly its planted pair; the double-plant fixture reports both.
- [ ] The verdict (`pass` or `falsified`) is recorded with the digests and is cited by the KILL-SCHED decision (N20a-11).
- [ ] If the verdict is `falsified`, N20a-10 is not started and the fallback is recorded.

## Test plan

### Unit tests
`crates/frob-conformance/tests/pilot_sched_race.rs`; `cargo test -p frob-conformance pilot_sched_race`.
- `six_events_eight_classes`: class count 8; `all_720_map_to_8`.
- `clean_fixture_no_race`: 8 equal digests.
- `stale_read_found`: digests split into two groups of four; the reported pair is (delivery, estimator tick).
- `watchdog_latch_found`: the reported pair is (watchdog, latch).
- `both_found`: four distinct digests; both pairs reported.
- `reduction_to_adjacent_swap`: for each reported difference, two orderings that differ by one adjacent swap reproduce it.

### End-to-end script and logging
`scripts/e2e/pilot_sched_race.sh` (sources the STD-E2E helper): runs the four fixtures through `frob gauntlet pilot run sched-race --json`, asserts the verdict and the class counts, and writes NDJSON to `target/e2e-logs/pilot_sched_race/<utc>.ndjson`: per fixture a `metric` line with `classes`, `runs`, `distinct_digests`, the reported pairs, and wall time; the summary names `KILL-SCHED`.

### Known answers and negative controls
KA-478 (720 orderings in 2³ = 8 classes; both planted races must be found). The planted races are the negative controls of the mechanism; the control of the pilot itself is a deliberately blinded enumerator (it skips classes in which the watchdog precedes the latch) that must be reported `falsified`. Determinism: the laboratory runtime replays each ordering identically; digests are equal twice on one machine.

## Considerations

- The pilot is deliberately small and exhaustive-checkable. Passing it says the enumeration and the reduction are right on a known structure; it does not say that the declared independence relation of real kernels is right. The mechanism therefore also samples orderings inside a class (N20a-10).
- If the laboratory runtime cannot express the fixture at the pinned version, the pilot runs on a 50-line hand scheduler and the record says so; the falsifier is unchanged.
- Cost: seconds. There is no reason to skip it.
