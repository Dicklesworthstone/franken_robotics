## Background

The boundary ordering rule fixes the order of work between its seven stages. Within a stage it fixes a stable logical order, and the result must not depend on that order where the events are independent. If it does, there is a race: a same-instant pair whose order matters and which the rule does not order. Such a defect is invisible to ordinary tests, because the simulator always runs its one stable order; it shows up when a kernel is reordered, a backend changes, or a controller is ported to hardware with a different scheduler.

The check (Frontier tier; construction C-19 calls the objects *schedule classes*: the orderings of capture, delivery, estimator read, watchdog expiry and actuator commit modulo commutation of independent events; a timing race is explored once per class and not once per ordering) enumerates one representative of each equivalence class of orderings and compares digests. Hand-checkable size: six events with three independent conflicting pairs have 720 orderings in 2³ = 8 classes.

It is built only if its pilot found both planted races (N20a-09) and KILL-SCHED did not fire (N20a-11). Ceiling of the benefit: a correctness guard with no speed benefit. Fallback: the fixed total order with no enumeration. Owner: `frob-conformance`.

## Scope

In: the declaration of read and write sets for boundary events; the class enumerator; the replay driver on the deterministic laboratory runtime; the digest comparison and reduction to a racing pair; sampling inside classes to test the independence declarations; the registration of the relation in the metamorphic tier; fixtures.

Out: fixing races it finds (the owning kernel's bead); the pilot; the decision.

## Technical approach

**1. Event model** (DESIGN). At a boundary, each unit of work is an event `{ id, stage, reads: Set<Cell>, writes: Set<Cell> }`, where a cell is a named piece of per-world state (a sensor's ring, a consumer's delivered set, an estimator's state, a command latch, a watchdog timer, an exposure accumulator). Kernels and host-side components declare their cells in their manifests.

**2. Conflict and independence.** Two events conflict if one writes a cell the other reads or writes. Otherwise they are independent. Events in different stages are ordered by the rule and are never permuted. The check works on the events of one stage at one instant.

**3. Enumeration** (numbered steps).
1. Build the conflict graph of the stage's events.
2. For every conflicting pair, both relative orders are candidate classes; a class is an acyclic orientation of the conflict graph.
3. Enumerate acyclic orientations; for each, emit its canonical linear extension (the lexicographically least under event identifier order).
4. If the number of classes exceeds the budget (default 4,096 per boundary), sample classes by keyed draws and report the coverage fraction; never report "no race" for an unexplored stage without that fraction.

**4. Replay.** For each representative: restore the Sensorium checkpoint taken just before the stage (BD-098), run the stage's events in that order on the laboratory runtime, then run the remainder of the boundary and a fixed number of following steps (default 16) under the normal order, and take the digest of physical state, delivered observations and latched commands.

**5. Verdict.**
- All representatives give one digest: the stage has no order dependence at this instant.
- Digests differ: for two representatives with different digests, walk a chain of adjacent swaps between them and report the first swap that changes the digest. That pair is the race; the report names the two events, the cell they share, both digests and a replay address.
- Expected state for the simulator's own kernels: no conflicting pair inside a stage at all (conflicts belong to different stages). A same-stage conflict that the stable logical order resolves is reported as `order-dependent`, with the order that the rule imposes, so that it is a recorded decision and not an accident.

**6. Testing the declarations.** Independence is declared, so it is tested: for each class, a keyed sample of other linear extensions of the same class (default 8) must give the representative's digest. A mismatch means a read or write set is wrong; it is reported as `undeclared-dependence` with the pair.

**7. Where it runs.** As a G3 metamorphic relation ("independent same-instant events commute") on the clock-contract fixtures and on the standard battery's first 100 boundaries with at least two same-stage events, on the referee and on `batch-cpu`; device tiers are covered through their kernel manifests' declared cells and the batch-cpu replay.

## Acceptance criteria

- [ ] On the six-event fixture the enumerator emits 8 representatives; with the stale read and the watchdog-against-latch race planted, both are found and reduced to their pairs (the pilot's result, reproduced inside the workspace).
- [ ] On the clock-contract fixtures and the sampled battery boundaries, zero races and zero undeclared dependences are reported, or each report is linked to a fix or to a recorded `order-dependent` decision.
- [ ] A kernel manifest with a deliberately omitted write cell is reported as `undeclared-dependence` (the declaration test has a negative control).
- [ ] When the class budget is exceeded the report states the coverage fraction.
- [ ] The relation is registered in the metamorphic tier and its status is visible through `frob gauntlet status`.

Summary gate: `KILL-SCHED`.

### Known answers and negative controls
KA-478. Negative controls: the two planted races; the omitted write cell; a blinded enumerator (skips one orientation) must fail `acyclic_orientations_three_pairs`. Determinism: representatives and digests are identical twice on one machine and across worker counts.

## Considerations

- The number of classes is exponential in the number of conflicting pairs; at real boundaries the conflict graph inside a stage should be empty or tiny, and a large one is itself a finding.
- The check validates the simulator's same-instant semantics, and can validate a controller's (its tasks declare cells too). It does not explore interleavings across different instants; the clock lattice makes those deterministic.
- If KILL-SCHED fired, this bead closes with reason `fallback`: the fixed total order is the only guard, and the six-event fixture remains as an exhaustive 720-ordering unit test.
- Performance: each representative costs a restore and 16 steps of one world; it is a conformance job, not part of any step.
