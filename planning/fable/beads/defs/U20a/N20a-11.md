## Background

KILL-SCHED governs the Frontier mechanism "schedule-race check" (N20a-10): the enumeration of one representative per equivalence class of same-instant event orderings, with digests compared. A kill gate names its trigger and its fallback in advance and is never quietly re-scoped; its decision is recorded as an ADR at the milestone the gate register names; a kill gate that fires is not a failure, because the fallback is a mechanism the plan already contains.

**Trigger:** the race check misses a planted race (one of the two planted in the pilot fixture: a stale read, and a watchdog-against-latch race). **Fallback:** the fixed total order of the boundary ordering rule, with no enumeration. **Decided:** M2.

Why this trigger. The check's whole value is that it finds order dependence that ordinary tests cannot see. A check that misses a race it was shown is worse than none, because its silence would be read as assurance. Its benefit ceiling is a correctness guard with no speed benefit, so there is nothing to trade against a miss.

The decision is one step more urgent than its milestone because the M2 exit of the clock contract on every tier (BD-189) records it.

## Scope

In: applying the rule frozen in the pilot's protocol; reading the pilot record; the ADR; the decision entry on the kill row; the owner declaration N40-30 compares with the ledger; what changes downstream on each branch.

Out: the pilot's execution and any repair cycle of its enumerator (N20a-09); the mechanism (N20a-10); the KILL-SCHED row itself in `registries/gates.toml` with its trigger, fallback, decided, mode and reads (the fallback ledger N40-24, a dependency; N20b-21 writes nothing in a kill record: this bead records the decision and its ADR against that row, and BD-189 cites the outcome in its gate record).

## Technical approach

**1. The fallback, defined first.** The boundary ordering rule orders the seven stages; within a stage, events are processed in the stable logical order (clock or sensor identifier, sequence number). Under the fallback this order is the only protection against same-instant order dependence: it guarantees one deterministic result per tier and across tiers, and it does not show whether another order would have given a different result. The six-event fixture remains as an exhaustive unit test of 720 orderings.

**2. The rule, frozen before data.** It is the rule of the pilot's protocol (N20a-09 items 3 and 4 and its record's `falsifier`), frozen with its digest and date before the pilot's first run; this bead starts only after the pilot has run, so it verifies the digest and applies the rule unchanged: the two plants; "missed" means the plant's racing pair is absent from the check's report on a fixture that contains it; a false race reported on a clean fixture, or a class count other than the fixture's (8 on the six-event fixture, 2 on the one-pair fixture), also makes the pilot `falsified` (N20a-09's verdict) and is recorded with the same consequence, because an enumerator that miscounts classes cannot be trusted to visit the class that holds a race; one repair cycle of the pilot enumerator is allowed for a defect in the pilot's own harness (not in the idea), in N40-03's form (step 5: opened and closed by the measuring bead, N20a-09, before it closes, and recorded as a second `[[pilot.result]]`), and the re-run uses the same frozen fixtures. Reachable verdicts: `not fired`, `fired: planted race missed`, `fired: pilot falsified` (a false race or a wrong class count that survived the repair cycle). This keeps the decision and the pilot's own rule ("if the verdict is `falsified`, N20a-10 is not started") from disagreeing.

**3. Decide** (numbered steps).
1. Read the pilot record of N20a-09.
2. If it shows both plants found on the three planted fixtures with 8 classes counted, the planted stale read found on the one-pair fixture (2 classes, two commit digests, the stale value named; the fixture that the construction pilot `PILOT-C-19` cites), and no race on either clean form (the clean six-event fixture and the un-planted one-pair fixture), that is, the pilot's verdict is `pass`: `not fired`.
3. Otherwise read the result of the pilot's one repair cycle, if it took one (the later `[[pilot.result]]`). If a plant is still missed: `fired: planted race missed`; if every plant is found but a false race or a wrong class count remains: `fired: pilot falsified`.
4. Write the decision record `docs/adr/ADR-KILL-SCHED-M2.md` with the fields N40-03 requires (the kill gate; the milestone; the trigger as registered and any amendment; each measured value with its receipt hash beside the trigger; the outcome; the fallback in force and the capability's name from now on; the beads re-read, N20a-10 among them; what changes downstream; the recording session, which did not implement the mechanism), with the verdict, the pilot's digests and the consequence below. On the KILL-SCHED row of `registries/gates.toml` write the decision entry `decision = { outcome, adr = "docs/adr/ADR-KILL-SCHED-M2.md", date, session, receipts }` with one of N40-03's registered outcomes: `not-fired` for the verdict `not fired`, `fired` for either `fired` verdict (the form, `planted race missed` or `pilot falsified`, is stated in the ADR). Write the owner declaration in the block N40-30 compares with the ledger (N20b-21 item 3: the deciding bead writes it): `[[gate]] id = "KILL-SCHED"`, `role = "owner"`, `trigger` and `fallback` carrying N40-24's text ("The race check misses a planted race"; "The fixed total order, with no enumeration"), `decided = "M2"`, `mode = "exit"`, `reads` naming the pilot record, with `decision = { outcome, adr = "ADR-KILL-SCHED-M2", measured = [plants found on each fixture, false races on the clean forms, the class counts, each with value, unit and receipt] }`. The status `killed` and the fallback's name are derived from the row's entry by N40-03's `apply_decisions`; this bead never writes a status by hand.
5. The trigger stays armed after M2: if the production check (N20a-10) later misses a newly planted race in its own negative controls, the gate fires then, with the same fallback.

**4. Downstream.**
- `not fired`: N20a-10 proceeds; the relation "independent same-instant events commute" is checked by enumeration on the clock-contract fixtures and the sampled battery boundaries; BD-189's gate record cites the outcome `not-fired`.
- `fired` (either form): N20a-10 closes with reason `fallback`; the metamorphic relation is checked only by the exhaustive six-event unit test; the contract of `frob-sense` states that same-instant order independence is not explored beyond the fixed order; the row's status `killed: fallback adopted` is derived from the decision entry (N40-03), and BD-189's gate record cites the outcome `fired`. Nothing on the critical path changes: every tier already runs the fixed order.

## Test plan

### Unit tests
`crates/frob-conformance/tests/kill_sched_rule.rs`; `cargo test -p frob-conformance --test kill_sched_rule`.
- `verdict_from_record_pass`: a synthetic pilot record with both plants found and a clean fixture gives `not fired`.
- `verdict_from_record_missed`: a synthetic record with the watchdog plant missing gives `fired: planted race missed`.
- `false_race_on_clean_counts`: a synthetic record reporting a race on the clean fixture gives `fired: pilot falsified`.
- `wrong_class_count_counts`: a synthetic record with both plants found but 7 classes counted on the six-event fixture gives `fired: pilot falsified`; after one repair cycle with 8 counted it gives `not fired`.
- `one_pair_plant_missed_counts`: a synthetic record in which the three-pair fixtures pass but the one-pair fixture's planted stale read is not reported gives `fired: planted race missed`.
- `rule_frozen_before_run`: the decision function refuses a record whose protocol date is later than its first run.

### End-to-end script and logging
`scripts/e2e/kill_sched_decide.sh` (STD-E2E helper; NDJSON under `target/e2e-logs/kill_sched_decide/`). The pilot register and the gate register have no `frob` verb (ADR-GAUNT-01: there is no `frob gauntlet` or `frob gates` command), so the script reads N20a-09's record in `crates/frob-conformance/registry/pilots.toml` and the KILL-SCHED row of `registries/gates.toml` read-only; runs `FROB_TEST_SEED=0 cargo test -p frob-conformance --test kill_sched_rule` (the decision function on the six synthetic records above); reads the funding verdict that follows from the pilot record, `cargo run -p frob-conformance --example pilots -- fundable --bead N20a-10 --json` (N38a-09; the crate has no default binary), and the package line of `-- fundable --package WP-40 --json`; runs N40-03's read-only `scripts/e2e/kill_gate_records.sh --live --ids` on KILL-SCHED (one complete kill row, its decision entry valid) and `cargo test -p frob-conformance --test kill_ledger` (the owner declaration against the ledger); reads KILL-SCHED's recorded outcome and receipt from the M2 exit report, `cargo test -p frob-conformance --test exit -- report --milestone M2` (`gate-report.json`, read through the register's one loader, N40-04); and drives `frob --json evidence trace <claim_id>` on the claim the row's receipt cites (the closure's hashes must recompute). It asserts that the row's outcome equals the verdict recomputed from the pilot record, that `fundable` answers `Fundable` for N20a-10 only when the outcome is `not-fired`, and that the ADR path exists. Lines log the verdict, the pilot digests, the receipt hash and each command's exit code and wall time; the summary names `KILL-SCHED`.

### Known answers and negative controls
KA-478 (the fixture and its two plants). Negative control for the decision itself: a pilot record edited after the fact to add a missing plant has a digest that no longer matches its receipt, and the decision refuses it.

## Considerations

- The gate decides funding of a guard, not of a capability a user sees; either branch leaves `frob` behaving identically on every tier.
- A `not fired` verdict at M2 is evidence about the enumerator on a small fixture. The production check keeps its negative controls for that reason.
- No owner decision is needed beyond recording the verdict; the rule is mechanical.
