## Background

Sensorium names five Frontier sensor models that are on no task's path before M5: tactile arrays, event cameras, radiometric RGB, retroreflector bloom, and backscatter from optical volumes. The rule for each: it is funded only when a registered task needs it, names one analytic fixture as its pilot when it is, has no speed benefit to claim, and falls back to the mask-only model under the same cost rule as exposure integration (more than 25% added to the stage it joins). Tactile arrays and radiometric RGB have their own pilot beads (N20a-18, and the RGB epic's pilot). This bead holds the pilots of the other three.

A Frontier mechanism may not be funded without a paper-scale pilot whose falsifier is frozen before execution, and it states the ceiling of its benefit first. For all three the ceiling is the same: none on speed; each changes what a perception policy or an estimator must tolerate, and its value is bounded by the share of a registered task's failures that the model produces and the Solid models do not. That share is unknown until a task exists.

The plan fixes what each model is and leaves the fixture to be named at funding time. The fixtures below are DESIGN proposals so that the naming is not left to the moment of need; the owner of the registering task may replace one before its protocol is frozen.

## Scope

In: one analytic fixture, one falsifier and one fallback per model; the frozen-protocol record for each, created when its task registers. Run outside the workspace with plain arithmetic.

Out: the mechanisms (N20a-30).

## Technical approach

**1. Event camera** (asynchronous stream of log-brightness changes).
- *Fixture.* A step edge between intensities I₁ and I₂ = ρ·I₁ sweeps across a pixel row at v pixels per second. A pixel with contrast threshold C fires events while |ln I − ln I_ref| ≥ C, moving I_ref by C per event. Crossing the edge changes ln I by ln ρ, so each pixel fires N = ⌊ln ρ / C⌋ events of one polarity (positive when brightening), and pixel k fires them at time k/v (to the time resolution). With ρ = 4 and C = 0.2: ln 4 = 1.386, N = 6. Over a row of 100 pixels: 600 events, in pixel order, spaced 1/v apart.
- *Falsifier.* Not funded if, for the registered task's motion range, the event stream carries no decision-relevant information beyond frames at the camera's frame rate (measured on the fixture as: the edge's position reconstructed from events between two frames is no more accurate than linear interpolation of the frames), or if the estimated cost exceeds 25% of the ray stage.
- *Fallback (mask-only).* A per-pixel "changed since last frame" mask at frame instants.

**2. Retroreflector saturation and bloom.**
- *Fixture.* A retroreflective target of gain G at range d on a dark diffuse background, seen by a lidar with saturation level S_sat. Return strength S = G·(d_ref/d)². For S ≤ S_sat the Solid rule applies (a return with gain). For S > S_sat the target's samples saturate and neighbouring beams within an angular radius θ_b report corrupted ranges. The pilot fixes the law to test (proposal: θ_b = θ₀·√(S/S_sat − 1), capped; neighbours inside θ_b are masked with a reason `bloom` or pulled to the target's range, per the card) and checks it against the one measured or datasheet card available at the time; without a measured card the pilot cannot run, because a bloom law with every parameter `assumed` has nothing to be falsified against.
- *Falsifier.* Not funded if no measured or datasheet card supplies the bloom extent, or if on the fixture the bloom region at the registered task's ranges is smaller than one beam spacing (then the Solid `saturated` flag already says everything), or cost above 25%.
- *Fallback (mask-only).* The `saturated` flag on the target's own samples, no effect on neighbours.

**3. Backscatter from optical volumes.**
- *Fixture.* A homogeneous slab of extinction σ and backscatter albedo ω between an active sensor and a wall. To first order (single scattering), the strength returned from a range gate [s, s + Δ] inside the slab is S_b(s) = ω·σ·Δ·exp(−2σ·(s − s₀))·(d_ref/s)², with s₀ the range at which the ray enters. A false near return appears at the first gate where S_b ≥ S_min; the wall's own return is S_wall·exp(−2σ·L). Worked case: σ = 2 m⁻¹, ω = 0.5, Δ = 0.1 m, slab entered at s₀ = 1 m with d_ref = 1 m, S_min = 0.05: at the first gate S_b = 0.5 × 2 × 0.1 × 1 × 1 = 0.10 ≥ 0.05, so the sensor reports a false surface at about 1 m, in front of the true wall.
- *Falsifier.* Not funded if, at the σ and ω of every optical volume in the registered task's scenes, S_b stays below S_min at every gate (then extinction alone, the Solid model, is the whole effect), or cost above 25%.
- *Fallback (mask-only).* The Solid extinction model: returns beyond the threshold depth masked `attenuated`, never a false near point.

**4. Records.** One row per model in the pilot register, created when its task registers: mechanism, tier [F], protocol digest, falsifier, ceiling, fallback, cost, tool and pin, the registering task, result and verdict (`fund` or `fallback`).

## Acceptance criteria

- [ ] No pilot runs, and no mechanism of N20a-30 starts, before a registered task names the model; the bead records "not due" until then.
- [ ] When a pilot runs: its protocol digest predates execution; its fixture's closed-form values are reproduced (600 events in order for the event fixture; S_b = 0.10 at the first gate for the backscatter fixture; the saturation threshold range for the bloom fixture); its verdict follows the frozen falsifier.
- [ ] Each record names its fallback and the 25% cost rule.
- [ ] A fixture replaced by the registering task's owner is recorded with the reason, before the protocol is frozen.

## Test plan

### Unit tests
`crates/frob-conformance/tests/pilot_frontier_sensors.rs`; `cargo test -p frob-conformance pilot_frontier_sensors`.
- `event_count_step_edge`: ρ = 4, C = 0.2 gives 6 events per pixel; ρ = 1.2 gives 0 (ln 1.2 = 0.182 < 0.2).
- `event_times_in_pixel_order`: pixel k at k/v.
- `event_polarity`: brightening positive, darkening negative.
- `backscatter_first_gate`: 0.10; `backscatter_decay`: at s − s₀ = 0.5 m, S_b = 0.10·exp(−2)·(1/1.5)² = 0.0060 (below threshold).
- `backscatter_below_threshold_case`: ω = 0.1 gives 0.02 at the first gate: no false return.
- `bloom_threshold_range`: with G = 50, S_sat = 10 and d_ref = 1 m the target saturates for d < √5 = 2.236 m.
- `falsifier_rule_tables`: each model's verdict function on synthetic inputs.

### End-to-end script and logging
`scripts/e2e/pilot_frontier_sensors.sh` (STD-E2E helper; NDJSON under `target/e2e-logs/pilot_frontier_sensors/`): for each model, `frob gauntlet pilot run <model> --json` if a task is registered, otherwise one `assert` line "not due: no registered task"; when run, it logs the fixture's measured and expected values, the cost estimate against 25% and the verdict; summary `gates: []`.

### Known answers and negative controls
The three closed forms above. Negative controls: an event model that fires one event per crossing regardless of contrast (fails `event_count_step_edge`); a backscatter model with one-way extinction (gives 0.10·exp(−1)·(1/1.5)² = 0.0164 at 0.5 m instead of 0.0060 and fails `backscatter_decay`).

## Considerations

- Proposed fixtures and laws are labeled as proposals; nothing here is a claim about a device.
- The bloom pilot depends on OPEN-SENS-4 (which cards ship with datasheet or measured fields): with all cards `assumed` it cannot be run, and the model stays at its mask-only fallback.
- These pilots are cheap; the constraint is not effort but the rule that a Frontier sensor model is built only for a task that needs it.
