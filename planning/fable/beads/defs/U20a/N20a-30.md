## Background

"The other Frontier sensor models named in this chapter (tactile arrays, event cameras, radiometric RGB, retroreflector bloom, backscatter from optical volumes) are on no task's path before M5. Each is funded only when a registered task needs it, names one analytic fixture as its pilot when it is, has no speed benefit to claim, and falls back to the mask-only model under the same cost rule."

This bead specifies the three models that have no bead of their own (tactile arrays are N20a-19; radiometric RGB is N20a-28): event cameras, retroreflector saturation and bloom, and backscatter from optical volumes. Each is built only on a funding verdict of its pilot (N20a-29: verdict `falsifier-rejected` in `crates/frob-conformance/registry/pilots.toml`). The register that enforces the rule for all five, its pre-funding check and the `frontier_models` block of `sense.profile` are N20ap3-01's (split from this bead in polishing round 3, so that they exist whether or not any model is ever funded); this bead moves its three rows there from `funded` to `built` or `fallback`.

Why these models are deferred: every task before M5 is served by proprioception, depth, lidar, height scans and labels with the Solid failure modes. A sensor model that no task consumes has no gate that could fail and no user who would notice a defect.

## Scope

In: the model specification of the three; their mask-only fallbacks; cost measurement against the 25% rule; the three rows' transitions in N20ap3-01's register; the close when no task is due.

Out: pilots (N20a-29, N20a-18); tactile and RGB mechanisms; the register `registries/frontier_sensors.toml`, its status rule and pre-funding check, and the `frontier_models` block of `sense.profile` (N20ap3-01, a dependency); the decision about which late epics are active.

## Technical approach

**1. Funding and the register.** A model of this bead is started only when its row in N20ap3-01's register reads `funded` (its pilot record of N20a-29 holds the result `falsifier-rejected` and a kill-gate row exists for it); the bead writes no other row. When a model lands, this bead records its measured `cost_fraction` with the receipt, which moves the row to `built` (at most 0.25) or `fallback` (above), and `sense.profile`'s `frontier_models` block (N20ap3-01) then reports it. The three models and their fallbacks:

| Model | First check or fixture | Mask-only fallback |
|---|---|---|
| Event cameras | Step edge: ⌊ln ρ / C⌋ events per pixel, in order | "Changed since last frame" mask at frame instants |
| Retroreflector bloom | Saturating target on a dark background | `saturated` flag on the target's own samples |
| Volume backscatter | Homogeneous slab, first range gate | Extinction only: `attenuated`, never a false near point |

**2. Event camera.** State per pixel: reference log-intensity L_ref. The camera's brightness input is the same linear intensity a frame camera would integrate (so it depends on an intensity image source: the label and albedo channels shaded simply for a depth-only scene, or the RGB model's irradiance when that exists). Between two boundaries the intensity at a pixel is sampled at the sub-instants of the segmented pose history (the same sampler as rolling shutter); for each pixel, while |ln I − L_ref| ≥ C: emit an event (pixel, polarity = sign, time), with the time found by linear interpolation of ln I between the two sub-instants, and move L_ref by ±C. Refractory period and a per-pixel threshold mismatch (keyed, per pixel, fixed for the episode) are card fields. Events are packets with their own instants; the stream's capacity per boundary is fixed (events beyond it set a `truncated` flag with the count). State L_ref is in the checkpoint.

**3. Retroreflector saturation and bloom.** After the Solid rule computes S = `retro_gain`·(d_ref/d)²: if S exceeds the sensor's saturation level, the target's samples carry `saturated`, and samples within the bloom extent (from the card's measured or datasheet law; the pilot's proposal is an angular radius θ₀·√(S/S_sat − 1)) are either masked with reason `bloom` or have their range replaced by the target's, as the card states. Implemented as a second pass over a sensor's pattern with a fixed neighbourhood radius, so the launch shape is fixed.

**4. Volume backscatter.** Along each segment inside a volume, range gates of length Δ (the sensor's range resolution) are evaluated in order: S_b = ω·σ·Δ·exp(−2·τ(s))·(d_ref/s)², with τ(s) the optical depth accumulated to s. The first gate with S_b ≥ S_min produces a return at that range (a false near point) which, for a single-echo sensor, replaces the surface return if it is stronger; a multi-echo sensor reports both. The number of gates per ray is bounded by a card maximum (fixed shape).

**4a. Registry rows.** The mask reason `bloom` and the packet flag `truncated` are new names: the bead that builds the model adds them to `registries/mask_reasons.toml` (closed and versioned; an unknown code is a load-time error, and codes are never reused), with the meaning stated here, in the same commit as the model.

**5. Cost rule.** Each model's added cost is measured as a fraction of the stage it joins on the registering task; above 25% the model's status becomes `fallback` and its mask-only form is what ships.

**6. When no task is due.** If no registered task names a model by the M6 exit candidate, its pilot record is `withdrawn` with the reason "not due: no registered task" (N20a-29, step 5) and its mask-only fallback is in force; with all three so, this bead closes `withdrawn` with a pointer to WP-74 (N41-17: never counted as work done), as N20a-19 does for tactile arrays. The M6 exit review (BD-427) depends on this bead, so it must close either way; a model funded later is a new bead under the same rule.

## Acceptance criteria

- [ ] No mechanism code for a model lands before its row in N20ap3-01's register reads `funded`; the register's check (N20ap3-01) rejects it otherwise. With no registered task for any of the three by the M6 exit candidate, the bead closes `withdrawn` with a pointer to WP-74 (step 6).
- [ ] Event camera (when built): the step-edge fixture yields exactly ⌊ln ρ / C⌋ events per pixel with the right polarity, in pixel order, with times within one sub-instant spacing of k/v; a static scene yields none; L_ref survives checkpoint and restore.
- [ ] Bloom (when built): below saturation no neighbour is affected; above it, the affected set matches the card's law within one beam.
- [ ] Backscatter (when built): the slab fixture returns a false near point at the first gate when ω·σ·Δ ≥ S_min at entry, and none when below; extinction of the wall's return is unchanged from the Solid model.
- [ ] Each built model's measured cost fraction is recorded in its register row with the receipt; above 25% the fallback is in force and the capability is named by the fallback; `frob sense profile` then reports the row's status.

## Test plan

### Unit tests
`crates/frob-sense/tests/frontier_sensors.rs` (per-model feature flags); `cargo test -p frob-sense --features frontier-event,frontier-bloom,frontier-backscatter --test frontier_sensors`.
- `cost_fraction_moves_row`: a measured fraction of 0.19 with its receipt moves a `funded` row to `built`, 0.31 to `fallback` (the register and its rule are N20ap3-01's).
- `event_step_edge_count_order_polarity`: 6 events per pixel for ρ = 4, C = 0.2.
- `event_static_scene_silent`; `event_capacity_truncation_flag`; `event_state_checkpoint_roundtrip`.
- `bloom_none_below_saturation`; `bloom_extent_matches_card`.
- `backscatter_false_near_return`: 0.10 at the first gate with σ = 2, ω = 0.5, Δ = 0.1; `backscatter_none_at_low_albedo`.
- `backscatter_does_not_change_extinction`.
- `fixed_launch_shape_each_model`.

### End-to-end script and logging
`scripts/e2e/sense_frontier_models.sh` (header `# e2e: bead=N20a-30 milestone=M6 labels=sensorium,frontier seed=0 needs=cpu plants=no-threshold-event,no-range-squared`; STD-E2E helper; NDJSON under `target/e2e-logs/sense_frontier_models/<utc>.ndjson` with a transcript). Steps: `register` (reads the three rows of `registries/frontier_sensors.toml` and their `PILOT-SENSE-<nn>` records read-only, through `cargo run -p frob-conformance --example pilots -- fundable --bead N20a-30 --json`, and asserts that each row's status agrees with its pilot's verdict and cost fraction); `profile` (`frob sense profile <fixture design requesting the model> --task <registering task> --json` per built model, asserting the status `built` or `fallback` in the `frontier_models` block); for each built model, `fixture` (`frob sim run <the model's fixture design> --scene <fixture scene> --tier batch-cpu --seconds <fixture length> --seed 0 --key sfm-<model> --json`, asserting the closed-form values of N20a-29: event count, order and polarity; the bloom set within one beam; the backscatter gate and the unchanged wall extinction) and `cost` (the model's stage time against the stage without it on the registering task, paired, keys `sfm-cost-<model>-<on|off>-<rep>`, against 0.25); `plants` (the two negative controls on the test build must be caught). Every line carries `ts`, `script`, `bead`, `step`, `event`, the exact command line, exit code and wall time, the evidence block, measured and expected values with units, cost fractions against 0.25, the pilot row identifier, and on failure the first differing pixel, beam or gate. Before any model is funded the script asserts that none of the three rows is `funded` and that no model feature is built, and exits 0 with a `summary` saying so (the five-row check and the `silent-solid` plant are N20ap3-01's script, `scripts/e2e/sense_frontier_register.sh`).

### Known answers and negative controls
The pilots' closed forms (N20a-29). Negative controls (a design requesting an unbuilt model and silently receiving Solid output is N20ap3-01's `silent-solid` plant): an event camera that reads true intensity without the threshold fires on every change and fails the count (plant `no-threshold-event`); a backscatter model that omits the range-squared factor fails the decay check. Determinism: event times and counts exact where intensity inputs are exact; otherwise in the physics' class.

## Considerations

- A capability that fell back is described by the name of the fallback, in the register and everywhere else (N20ap3-01).
- Event cameras need an intensity source; before RGB exists they can only see albedo and label edges under simple shading, which may be enough for the registering task or may not, and the pilot must say which.
- All parameters are `assumed` until a card records a datasheet or a measurement; the bloom model cannot be built on assumed parameters at all.
