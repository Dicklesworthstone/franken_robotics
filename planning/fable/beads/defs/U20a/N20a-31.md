## Background

Three rows of the sensor failure-mode table are faults that happen to a sensor during a run, not properties of its normal operation:

| Sensor | Failure mode | Model | First check |
|---|---|---|---|
| Any | Extrinsic bump after an impact | A step change of the mount transform | The calibration pose graph's self-check |
| Any | Stuck value, dead sensor | Fault injection available to the adversarial search | The causal-policy harness sees the mask |

A robot that only ever sees healthy sensors in simulation has no reason to notice an unhealthy one. The adversarial search (Nemesis) looks for worlds that break a design, and a stuck encoder or a camera knocked 2° off its mount is such a world. This bead gives it, and any task author, a small, typed, deterministic fault vocabulary. Tier: Solid.

The design rule is that a fault is part of the world definition: scheduled, keyed, recorded and checkpointed like everything else. Alternative rejected: mutating sensor outputs from outside the simulation (a test harness that overwrites a buffer), which makes the fault invisible to replay, forks and the causal-policy test.

## Scope

In: the fault specification type and the schedule that carries faults as world events (this bead is the fault-injection interface that the adversarial search and the calibration beads use); the three fault kinds and their semantics on packets, masks and flags; for the extrinsic bump, the event itself (at the trigger the true mount is composed with the declared increment; the believed mount is untouched); triggers (at an instant, or after an impact above a threshold); fault state in the checkpoint; link-level faults as parameter edits; the first checks of the stuck and dead rows, and for the bump row the check that the event changed the true mount by exactly the declared increment.

Out: the true-versus-believed mount pair as model state, the robot's calibration self-check after an impact and its `extrinsics-suspect` flag (N20b-06, which depends on this bead for the bump event); recovery and attribution of a planted bump by the pose graph, which is the bump row's first independent check (N20b-06 and BD-242, recorded under GATE-SENS-14 by BD-238); the search that chooses faults and the legality bounds on them (the adversarial-search chapter); estimator fault detection.

## Technical approach

**1. Specification** (DESIGN; part of the world's definition and therefore of its address and identity).

```rust
pub struct FaultSpec { sensor: SensorId, kind: FaultKind, trigger: Trigger, duration: Option<Quanta> }
pub enum FaultKind {
    Stuck { annunciated: bool },                 // repeats the last pre-fault value
    Dead  { silent: bool },                      // every sample masked, or no packets at all
    ExtrinsicBump { delta: Twist6 },             // step change of the mount transform, applied on the right
}
pub enum Trigger { At(Quanta), AfterImpact { body: BodyId, min_impulse: f32 } }
```

**2. Semantics.**
- *Stuck.* From the trigger, the sensor's payload is frozen at the last value sampled before it; packets keep their fresh instants and sequence numbers (the device believes it is working). If `annunciated`, each packet carries the flag `fault: stuck`; if not, nothing in the measurement namespace reveals the fault, and only the truth-side fault log does. The frozen payload is state and is in the checkpoint.
- *Dead.* If `silent`, the sensor emits no packets from the trigger (consumers see ages grow and the `held` flag); otherwise it emits packets whose every sample is masked with reason `fault: dead`. A masked value never appears as a number.
- *Extrinsic bump.* At the trigger the true mount transform becomes T_mount·exp(δ). Everything the sensor reports afterwards comes from the bumped pose (rays, lever arms, row and beam poses). The nominal extrinsics in the model, which estimators and the policy's observation assembly use, are unchanged: the robot does not know. The true mount is truth-namespace state in the checkpoint. With `AfterImpact`, the trigger fires at the first committed impact on the named body whose impulse magnitude is at least `min_impulse`.

**3. Recording.** Every fault activation is an event in telemetry (sensor, kind, instant, parameters) in the truth namespace. The delivered-observation digests naturally differ from a fault-free twin from the first affected packet onward, which is how the causal-policy harness "sees" the fault: in a twin pair that differs only by a fault scheduled after a decision instant, digests and commands agree up to that instant and the harness reports the first decision at which the delivered bytes differ.

**4. Link faults** are edits of link-card parameters over an interval (a latency step, a loss burst) expressed with the same `Trigger` and `duration`; they need no new mechanism.

**5. Determinism.** A fault has no randomness of its own; where a search wants a random fault time it draws the instant by key before the run and writes it into the specification.

## Acceptance criteria

- [ ] Stuck: after the trigger every packet's payload equals the last pre-fault payload byte for byte, while instants and sequence numbers advance; with `annunciated` the flag is present on every such packet and absent before.
- [ ] Dead: non-silent packets have every sample masked `fault: dead` and no numeric read path returns a value; silent mode delivers nothing and consumers' observation age grows by the decision period per tick with `held` set.
- [ ] The causal-policy harness sees the mask (GATE-SENS-14 row, exact): in a twin pair differing only by a dead-sensor fault at instant t_f, delivered-observation digests agree at every decision before t_f and differ at the first decision whose delivered set includes an affected packet; the reference actor passes the causality test on the pair.
- [ ] Extrinsic bump: a bump of 2° about the vertical axis and 15 mm along x on a lidar changes the reported range to a wall at 5 m by the analytic amount for each beam; nominal extrinsics in the model are unchanged; the true mount is restored exactly from a checkpoint.
- [ ] `AfterImpact` fires at the first committed impact above the threshold and not on a retried, uncommitted attempt.
- [ ] Faults are part of the world address: two runs with and without a fault have different world identities; replay of a faulted run reproduces it bit for bit.

## Test plan

### Unit tests
`crates/frob-sense/tests/fault.rs`; `cargo test -p frob-sense fault`.
- `stuck_payload_frozen_instants_fresh`; `stuck_annunciated_flag`; `stuck_silent_no_flag`.
- `dead_masks_every_sample`; `dead_silent_no_packets_age_grows`.
- `bump_changes_rays`: a lidar beam along +x toward a wall at 5 m, after a yaw bump of 2°, reads 5/cos(2°) = 5.00305 m; after the 15 mm bump along +x it reads 15 mm less.
- `bump_nominal_extrinsics_unchanged`.
- `after_impact_trigger_committed_only`: a forced retry of the impact interval does not fire the fault twice or early.
- `fault_in_world_identity`.
- `checkpoint_roundtrip_fault_state`: stuck payload and bumped mount.
- `duration_ends`: a 0.5 s dead fault ends and valid samples resume.
- `causal_harness_sees_dead_sensor`: digests agree before t_f and differ after.

### End-to-end script and logging
Exercised by `scripts/e2e/sense_optical_failures.sh` (N20a-46, the sensor-card half): `frob sim run` of a twin pair with and without a dead-sensor fault; `frob sense causal-test` on the pair; `frob telemetry query` for the fault event and the masks; the script asserts the first differing decision instant equals the first decision after the first affected arrival and logs both digests, the fault event and the mask counts.

### Known answers and negative controls
KA-522 (a stuck value or dead sensor injected as a fault: the causal-policy harness sees the mask; exact; chaos tier). KA-496 (the bumped-sensor calibration case: 2° and 15 mm recovered and attributed) is measured by the calibration bead using this bead's bump. Negative controls: a dead sensor implemented by writing zeros (numbers, not masks) must fail `dead_masks_every_sample`; a bump applied to the nominal extrinsics (so the robot "knows") must fail `bump_nominal_extrinsics_unchanged`. Determinism: faults are exact events; replay bit for bit on the tier that ran them.

## Considerations

- A silent stuck sensor is the hard case for estimators, and deliberately so; whether a design survives it is a result, not a defect of the model.
- The legality set bounds what the adversarial search may inject (for example, at most one sensor at a time, bumps within a declared envelope); this bead does not police plausibility.
- An extrinsic bump changes the true observation geometry; any symmetry analysis that assumed the nominal mounts still holds for the model and no longer for the world, which is a finding the calibration self-check surfaces.
- Faults on private scenes inherit the scene's privacy class in telemetry.
