## Background

The observability Gramian answers "which directions of state error can this sensor suite not see over a window of motion". Its two computations exist as mechanisms (linearized, BD-120; empirical, BD-239). This bead makes it the capability a designer uses: the verb `sense.observability` (kind `run`, first milestone M3), which returns the Gramian spectrum along a route, with named weak directions.

**What it reports.** The dimension of the null space against the declared gauge; the smallest eigenvalue outside the gauge, after a declared scaling of the error coordinates; and the corresponding eigenvector in named coordinates ("translation along the corridor axis"). It is computed along a route, so the result is a profile: where on the route the estimate degrades, and in which direction.

**Uses.** A warning in the design check when a route has a stretch whose smallest eigenvalue falls below a threshold; an input to the assumption monitors of runtime shields; and a score for sensor placement (Frontier, N20a-36). Atelier lists it among its analyses beside sensor coverage, as A-17, and labels Gramian conditioning a screening signal: it may discard under the ladder's rules and may not establish a comparison.

Payoff (from the construction): a map of where a design is blind; feature-starved corridors and repetitive aisles show as a collapsing index before any estimator drifts.

## Scope

In: the verb's request and response; stations along a route; choice of form and tier; the profile and its summary; the weak-stretch finding for `design check`; the export consumed by shield monitors; memoization; job behaviour (budget, cancellation, idempotency).

Out: the two computations; placement optimization; the alias witness (reported by `sense.alias`, linked from this verb's output when the ambiguity flag is set).

## Technical approach

**1. Registry entry** (`registries/verbs.toml`). The row of record is the cluster registry's (VERBS-sense, a dependency); this bead implements it and does not redefine it. The row as that bead writes it:

```toml
[[verb]]
name = "sense.observability"
cluster = "sense"
kind = "run"
tier = "S"
capabilities = ["sense:run"]
input_schema = "frob.sense.observability.in/1"
output_schema = "frob.sense.observability.out/1"
refusals = ["FROB-REF-440", "FROB-REF-441"]
idempotent = false
cost_model = "estimated: `--estimate` returns CPU core-seconds, GPU seconds, memory and disk with a conformal interval"
first_milestone = "M3"
task_clusters = ["sensing"]
examples = ["frob sense observability quad-a --task aisle-delivery --route r3 --key ob-1 --json"]
owner = "frob-sense"
purpose = "The Gramian spectrum along a route, with named weak directions"
wait = { cli = "to-completion", mcp_ms = 5000, mcp_max_ms = 30000 }
```

The two refusals are those of the worlds it runs (the clock lattice and the history buffers); the verb has none of its own. As a `run` verb it takes an idempotency key (a call without one is `FROB-REF-805`) and a budget, accepts the bounded synchronous wait, and otherwise returns a job handle with exit code 8. The `--estimate` figure for the empirical form is (2n + 1)·stations worlds (twice that with the half-step check) × window steps; the structural-rank form is static. The MCP tool name is `sense_observability`.

**2. Request.** Design; task (which fixes sensors, clocks and links); scene and route (or a recorded run to analyse in place); window length N (`--window <N>`) and station spacing (`--spacing <metres>`, DESIGN spelling; default 0.5 m); form ∈ {`linearized`, `empirical`, `both`} (`--form`); tier; scaling override; gauge override (default: the gauge the estimator declares for the suite); threshold λ_warn for the weak-stretch finding (`--lambda-warn <value>`, DESIGN spelling; default from the estimator's acceptable drift, see Considerations). The VERBS-sense row lists both spellings, `--spacing <metres>` and `--lambda-warn <value>`, with a non-positive value of either `FROB-REF-802`.

**3. Computation** (numbered steps).
1. Resolve the route to a nominal motion: run the baseline controller along it on the requested tier (or read the recorded run) and place stations at the requested spacing.
2. At each station compute W̃ over the window by the requested form(s), then the gauge check, the restricted spectrum, λ_min and its named eigenvector, and the global-ambiguity flag on declared pairs.
3. Assemble the profile: per station {arc length, time, null dimension, extra null directions, λ_min, the weak direction's name and components, flags (`step-sensitive`, `nonsmooth`, `mask-flips`), ambiguity}.
4. Summarize: the minimum of λ_min along the route and where; contiguous stretches with λ_min < λ_warn, each with its dominant weak direction and length; stations where the null space exceeds the gauge.
5. If both forms ran: the per-station relative disagreement, and a `forms-disagree` flag above 5%.

**4. Response.** The profile and summary above; `label: "screening"`; the evidence block (class `Tested`, tier, determinism class of the tier, model identity including the observation service identity, seed and world address); `next_actions` suggestions (for example, "run `frob sense alias` on stretch 2: locally weak and globally repetitive").

**5. Design-check finding.** When a task binds a scene and route, the preflight information stage (stage 8 of `design.check`, BD-244) calls this bead's library entry (DESIGN name `observability::route_finding(design, task, scene, route, budget)`, the same code path as the verb with the structural-rank form at every station and the linearized form at a coarse spacing); wiring that call into stage 8 and surfacing its finding in the design-check envelope is BD-244's, which depends on this bead. A weak stretch yields a finding (severity by how far below λ_warn) with ranked repairs as typed edits: move or tilt a sensor (`move-sensor`), add a fiducial or door-frame feature within range (a retrofit of the scene), widen a sensor's range or field of view (swap card). In the corridor example the repair names an end wall, door frame or fiducial within range: in an infinite corridor no beam direction observes x, and one end wall, door frame or fiducial restores it.

**6. Shield input.** The profile is exported as a function of route position: (λ_min, weak direction). A shield's assumption monitor that relies on the estimate along some direction reads whether that direction is weak at the current stretch.

**7. Memoization.** The result is a memo node keyed by the model identity restricted to the fields it reads (sensor suite, cards, mounts, clocks, links, the estimator's error definition), the scene and route identity, and its parameters; an edit that touches none of them recomputes nothing.

## Acceptance criteria

- [ ] `frob sense observability` on the corridor-with-end-wall route returns a profile in which λ_min is zero (to tolerance) on the stretch out of range of the end wall and positive within range, names the weak direction as translation along the corridor axis, and lists one weak stretch with its length.
- [ ] On a route through two identical aisles the profile shows full local rank and the ambiguity flag, with a `next_actions` entry pointing to `sense.alias`.
- [ ] `observability::route_finding` returns the finding for a route with a weak stretch, with at least one typed repair; with the end wall brought within range it returns none (its appearance in `frob design check` is accepted in BD-244).
- [ ] With `--form both` the per-station disagreement is reported and stays within 5% on the gate fixtures.
- [ ] The verb is reachable through `frob --json` and the MCP surface with its schemas; a long request returns exit code 8 with a job handle; cancellation drains and finalizes with no leaked device resources; a repeat with the same idempotency key returns the stored answer.
- [ ] Every response is labeled `screening`, and an attempt to cite it as a comparison between two designs is refused by the comparison verb.
- [ ] A design edit that does not touch sensing fields leaves the memo node valid; moving a sensor invalidates it.

## Test plan

### Unit tests
`crates/frob-sense/tests/observability_verb.rs`; `cargo test -p frob-sense --test observability_verb`.
- `profile_corridor_end_wall`: stations beyond range have λ_min below tolerance; within range, above λ_warn.
- `weak_stretch_segmentation`: two disjoint weak stretches are reported as two, with lengths.
- `aisle_route_ambiguity_flag`.
- `finding_has_typed_repairs`: `route_finding` on the corridor route returns one finding whose repairs are typed edits (`move-sensor`, a scene retrofit, a card swap); with the end wall within range it returns none.
- `spacing_and_lambda_warn_inputs`: `--spacing 0.25` doubles the station count of the default; `--lambda-warn` above every λ_min of the end-wall route reports the whole route as one weak stretch; a non-positive value of either is 802.
- `forms_disagree_flag`: a planted wrong Jacobian in a test sensor raises the flag.
- `memo_key_sensitivity`: sensor move invalidates; a leg-length edit that changes no sensing field does not.
- `schema_roundtrip`: request and response validate against their schemas.
- `label_screening_present`.
- `budget_refused_at_admission`: a request whose world count exceeds the budget is refused before any work with a budget refusal and exit code 4.
- `key_required_and_bound`: a call without `--key` is refused with FROB-REF-805 (exit 3); the same key with a different route is FROB-REF-803 (exit 7); the same key and parameters return the stored envelope byte for byte.

### End-to-end script and logging
`scripts/e2e/sense_observability.sh` (N20a-47 owns the script; its stages 10 to 12 log `not due` until this bead lands) drives the verb on the corridor, end-wall and twin-aisle routes on each tier, each call with its own `--key` (a `run` verb; the repeat that checks idempotent replay reuses one key on purpose), with `--form both` and the job behaviour (`--sync-wait-ms 0`, cancellation); the `frob design check` leg that asserts the finding and its repair runs once BD-244 surfaces it, and logs `not due` until then; it logs per station λ_min with units, the weak direction's name, flags, the job's wall time and world count, and the evidence block.

### Known answers and negative controls
KA-487 and KA-488 through the verb. CX-205 (full rank is not localization) through the twin-aisle route. Negative controls: a verb build that drops the ambiguity field (the aisle test fails); a profile computed at the wrong stations (arc lengths do not match the route's, caught by `profile_corridor_end_wall`). Determinism: a repeated request on one tier returns identical bytes; across tiers, inside the class.

## Considerations

- λ_warn has no value in the plan; it is a declared parameter with a default proposed from the estimator's acceptable drift over the window, recorded with each result. Its calibration against observed estimator drift is part of the placement pilot (N20a-35).
- The profile depends on the nominal motion: standing still observes less than moving. The request records which motion was analysed.
- A weak direction that does not matter to the task (drift along a corridor whose goal is a door at its end, found by contact) should not block a design; the finding is a warning, and the task's requirement decides relevance.
- Private scenes: route geometry in the response inherits the scene's privacy class.
