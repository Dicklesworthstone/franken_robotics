## Background

Every integrating sensor (a force-torque sensor, an integrating accelerometer, a camera row) reads a functional of the physical history over an exposure window. Two neighbouring windows share one instant, and an impulse that falls exactly on that instant must be counted in exactly one of them: counted in both it is doubled, counted in neither it is lost. The specification states the rule twice, and the two statements disagree.

| Where | Statement | Rows that test it |
|---|---|---|
| The conventions chapter (table row "Windows", and the rules after the boundary order) | Windows are half-open, (a, b]: an event at instant b belongs to the window that ends at b; an impact at exactly a belongs to the previous window | KA-204, CX-104; the conventions battery (N13-06, row 4) |
| The Sensorium chapter (the seven instants, the boundary ordering rule, the sampled-readings subsection) | The exposure is the close of the half-open window [open, close); an impulse exactly at t belongs to the window that opens at t | KA-475, CX-201, GATE-SENS-04 (impulse row), GATE-SENS-18 (rebound window); N20a-06, N20a-16, N20b-28, N20b-39 |

Both agree on everything except the shared instant: an impact of 0.2 N·s strictly inside one 10 ms exposure contributes 20 N to that window's average and nothing to its neighbour, and a closed-closed window is wrong. They cannot both hold at the boundary, and a conventions-battery row written for (a, b] would test a `frob-sense` accumulator built for [open, close) against the opposite answer.

Evidence for each reading, from the rest of the specification (FACT about the text; no measurement exists):

- For (a, b]. Inside a base interval the transactional referee step locates events as "the earliest time in (a, b] at which a guard may change sign", so an impact at exactly the end b of a base interval is resolved inside the step that ends at b. The boundary procedure at an instant t then runs after that step: it closes the exposures that end at t before it opens the exposures that start at t and advances physics. An impulse resolved at exactly t has therefore already been applied when the window ending at t is closed, and it is not seen again by the window that opens at t.
- For [open, close). The Sensorium chapter states it three times (the exposure instant, the consequences of the ordering rule, and the half-open convention cited by the sampled-readings subsection), with two registry rows; the transactional step's base intervals are written [t0, t1), a piece of rational time that owns its start and not its end; a sample taken at t informs a command that acts just after t, and a latched command acts over the open interval that follows t, which reads naturally as "what happens at t belongs to what starts at t"; and the boundary procedure opens the exposures that start at t as its last stage before physics advances, so an exposure that opens at t sees everything physics does from t on.

**Placement.** The ruling must exist before the compendium's exposure oracle (N12-42), the clock schedule built on it, the window membership function (N20a-06), the accumulators and the conventions battery (N13-06), because all of them are written against one side; so it cannot wait for the referee those beads build. The deciding experiment is therefore run here on an executable exact-rational model of the two procedures as the specification states them, and the same experiment is repeated on the real referee in both builds by N20ap1-51, which re-applies this bead's frozen rule if any cell of the measured table differs from the model's.

**Fail-closed default (DESIGN):** the Sensorium convention [open, close), implemented behind one membership function (`window_contains(open, close, t)` in `frob-sense`, built by N20a-06) that every accumulator calls. It is the rule in force whenever the ruling is open: before this record exists for any bead started out of order, and while N20ap1-51 has reopened it. A second implementation of window membership anywhere in the workspace is a defect. The default is chosen because every Sensorium bead and its registry rows are written against it; it is not a claim that it is right.

Owners: the Sensorium lead and the conventions (Marrow) lead; the project lead rules if they disagree. Decided at M1, before GATE-SENS-04's CPU rows and the time rows of the conventions battery are recorded, because both include the boundary case. Tier: Solid.

## Scope

## Technical approach

**1. The two candidates as one function (specified here; built by N20a-06).** `window_contains(open, close, t) -> bool` over exact rational instants, with a compile-time constant `WINDOW_RULE` taking one of two values: `OpensAt` (true when open ≤ t < close) or `ClosesAt` (true when open < t ≤ close). Every window in the workspace (exposures, the action-interval reward windows of the gym, telemetry sliding windows that cite this rule) calls this function; a lint in `xtask check-contracts` rejects a second definition (a grep for comparisons of an instant against both ends of a window outside the function, with an allow-list holding the compendium's independent oracle (N12-42) and this bead's model below, both test code written independently of `frob-sense`).

**2. The deciding experiment, on a model of the stated procedures.** `crates/frob-conformance/tests/window_rule_model.rs` (the conformance crate exists from M0) implements, in exact rationals and with no dependency on `frob-dyn` or `frob-sense`:
- the transactional step's event location as the text states it: an event is located at the earliest time in (a, b] of the step's base interval [a, b) at which its guard may change sign, and its impulse is committed in that step;
- the boundary procedure at a clock instant t in its stated order: close the exposures that end at t, deliver, decide, latch, open the exposures that start at t, then advance physics, with `split` placing a step boundary at every clock event that is not one already;
- an accumulator that tags each committed impulse with its instant and assigns it by the candidate rule (so that an impulse committed in the step ending at t can still be deferred to the window opening at t), and, as a second variant, a per-step accumulator of the kind a device tier under `hold` runs, which adds the step's impulse to whichever window is open while the step runs.

A 0.2 N·s impact is placed at exactly a sensor-clock boundary t with back-to-back 10 ms exposures [t − 10 ms, t) and [t, t + 10 ms) under `OpensAt` and (t − 10 ms, t], (t, t + 10 ms] under `ClosesAt`. Recorded for both rules and both accumulator variants: the transaction that commits the impulse (the step ending at t or the step starting at t), the order of the boundary stages around it, which window's average receives J/T (20 N) and which reads 0 N. Repeated with the impact one quantum before and one quantum after t (both rules must agree there), and with a second sensor whose window boundary is not a step boundary under `split`. The resulting table, with its digest, is the **model table** of the record.

**3. Decision rule (frozen before the experiment, committed with a date and digest).**
1. If the model commits an impulse located at exactly t inside the step that ends at t, and the boundary procedure closes exposures before it opens them (both expected from the text), then under `OpensAt` the accumulator must defer an already-committed impulse to the next window. If the tagging accumulator does so, `OpensAt` survives this item for that variant; whether the per-step variant can too is item 2's question, and the choice between two surviving rules is item 3's, not a fresh judgement (the owners record their reading of the text beside the verdict, but it does not change it).
2. If either rule cannot be implemented without counting an impulse twice or losing it under either accumulator variant (for example because the per-step accumulator of a device tier cannot defer), that rule is rejected.
3. If both survive, the default `OpensAt` stands unless the conventions lead shows a consumer outside Sensorium that depends on `ClosesAt`; a tie is recorded as "default confirmed".
4. The rule is applied again, unchanged, by N20ap1-51 to the table measured on the real referee if any of its cells differs from the model table, and by the M2 rerun of the clock-contract script on device tiers if the impulse stage fails there; it is never rewritten after the first run.

Reachable verdicts: `OpensAt` (the conventions rows are amended), `ClosesAt` (the Sensorium rows are amended), and `OpensAt, default confirmed`.

**4. Amendments on each branch.**
- `OpensAt`: the conventions table row "Windows" reads "[a, b): an event at instant a belongs to the window that opens at a"; KA-204 and CX-104 are restated to match KA-475 and CX-201; row 4 of the conventions battery (N13-06) asserts that an impact at exactly a belongs to the window opening at a and at exactly b to the next window.
- `ClosesAt`: `WINDOW_RULE` is specified as `ClosesAt` for N20a-06; KA-475, CX-201, the impulse row of GATE-SENS-04 and the rebound-window row of GATE-SENS-18 are restated ("an impulse exactly at t belongs to the window that closes at t"); the Sensorium chapter's exposure instant is described as the close of (open, close]; N20a-06, N20a-16, N20b-28 and N20b-39 change one sentence each and no code beyond the constant.
- Either way the rows marked `unreconciled` in the known-answer registry (N20-KA) lose the mark, and the record states that event location on (a, b] and window membership are two separate rules that need not share a bracket.

**5. Record.** An architecture decision record in the Sensorium series, `docs/adr/ADR-SENS-WINDOW-RULE.md` (the one directory for decision records, KNOWN_DRIFTS 4; DESIGN name: the ruling has no OPEN or KILL identifier, so the file is named for what it rules), co-signed by the conventions lead, with the experiment's model table and its digest, the verdict, the list of amended rows, and a field for the confirmation by N20ap1-51 (filled by that bead); `docs/CONVENTIONS.md` and its tested table cite it. The model table is committed beside it as `docs/adr/ADR-SENS-WINDOW-RULE.model.toml`, the file whose BLAKE3 is the digest the record states and which N20ap1-51 reads and compares cell by cell. The amended registry rows are those of N20-KA and N20-CX (KA-475, CX-201) or of N11-KA and N11-CX (KA-204, CX-104), all dependencies, so the rows exist when this bead amends one side and reads both back.

## Acceptance criteria

- [ ] The record specifies `window_contains`, `WINDOW_RULE` with both values, the selector and the single-definition lint with its allow-list precisely enough that N20a-06 builds them without a further decision.
- [ ] The model's protocol and the decision rule are committed, with a date and digest, before the first run; the model reports, for an impact at exactly t, the committing transaction, the stage order and the receiving window under each rule and each accumulator variant.
- [ ] One quantum before and one quantum after t, both rules give the same window in the model; at exactly t, each rule assigns the impulse to exactly one window and the two rules differ (the control that the experiment can tell them apart).
- [ ] In the model, the closed-closed mutant (both ends inclusive) counts the boundary impulse twice (20 N in each 10 ms window, 40 N summed, for 0.2 N·s) and is caught; the open-open mutant loses it (0 N in both) and is caught.
- [ ] The decision record `docs/adr/ADR-SENS-WINDOW-RULE.md` exists with one of the three verdicts and the digest of the model table beside it; the losing side's registry rows and text are amended in the same change, and no row of the known-answer registry stays `unreconciled`. The conventions battery's boundary row is not amended here: N13-06, which depends on this bead and on N20ap1-51, writes it once on the ruled side, and the record states the form it takes.
- [ ] The record states the fail-closed default `OpensAt` as the rule in force while the ruling is open, and that the conventions battery's boundary row is marked `pending N20a-49` during a reopening instead of asserting either side.

## Test plan

### Unit tests
`crates/frob-conformance/tests/window_rule_model.rs`; `cargo test -p frob-conformance --test window_rule_model`.
- `opens_at_membership`: open = 0, close = 1/100 s: t = 0 is inside, t = 1/100 is outside.
- `closes_at_membership`: the same window: t = 0 is outside, t = 1/100 is inside.
- `adjacent_windows_partition`: property test over random rational window chains and instants: under either rule every instant belongs to exactly one window of a back-to-back chain.
- `event_location_on_closed_end`: a guard that changes sign at exactly b of [a, b) is located at b in that step, not in the next.
- `boundary_stage_order`: the model's stage trace at t is close, deliver, decide, latch, open, advance.
- `boundary_impact_table`: the four cells (rule × accumulator variant) at exactly t give 20 N in one window and 0 N in the other, with the receiving window recorded.
- `off_boundary_rules_agree`: one quantum before and after t.
- `split_boundary_sensor_same_assignment`: the second sensor's window boundary, made a step boundary by `split`, gives the same assignment as a step-aligned one.
- `per_step_accumulator_deferral`: under `OpensAt` the per-step variant either defers the impulse committed in the step ending at t or is reported as unable to (the input to decision item 2).
- `closed_closed_mutant_double_counts`, `open_open_mutant_loses`: the two planted mutants on a boundary impulse.
- `decision_rule_table`: the rule maps (both implementable, no outside consumer) to `OpensAt, default confirmed`; (`ClosesAt` not implementable) to `OpensAt`; (`OpensAt` not implementable) to `ClosesAt`.

### End-to-end script and logging
`scripts/e2e/window_rule_decide.sh` (sources the STD-E2E helper; NDJSON under `target/e2e-logs/window_rule_decide/<utc>.ndjson` with a transcript beside it): checks that the protocol and decision rule digest predate the first model run (from the repository history), runs `cargo test -p frob-conformance --test window_rule_model -- --nocapture` in report mode and parses the model table, applies the decision function to it, checks that the record exists with the table digest, and reads back the conventions "Windows" row and the KA-475/KA-204 and CX-201/CX-104 registry rows to assert that they state the same side and that none is `unreconciled`. It logs each command with exit code and wall time, the protocol digest and date, a `metric` line per cell of the model table (rule, accumulator variant, impact instant as an exact rational, committing transaction, stage order, receiving window, averages against 20 N and 0 N), the mutants' outcomes, the verdict, the amended row identifiers, and a summary naming the rule in force and `gates: ["GATE-SENS-04"]`. The same experiment on the real referee is N20ap1-51's `scripts/e2e/window_rule_boundary.sh`.

### Known answers and negative controls
KA-475 and CX-201 (Sensorium form) and KA-204 and CX-104 (conventions form): the same 0.2 N·s in 10 ms reading 20 N and 0 N, differing only in the owner of the shared instant. Negative controls: the closed-closed and open-open mutants; a decision run whose protocol digest postdates the first model run is refused by the script. Determinism: exact rational instants; the model run twice gives an identical table and digest.

## Considerations

- The risk if this is left undecided is not a wrong number in one sensor; it is two test suites asserting opposite answers about the same accumulator, one of which will be "fixed" by whoever sees it fail first.
- Event location on (a, b] is a rule about where a step ends; window membership is a rule about which window owns an instant. The decision record must say so, or the next reader will try to unify them.
- A model of the text is not the simulator: if the referee is built to place events or order the boundary stages differently, the model table is wrong for it. That is why the ruling is confirmed on the referee (N20ap1-51) and on device tiers at M2, and why both re-apply this frozen rule instead of deciding afresh. A reopening costs a constant and one sentence per bead, by design of the one function.
- Device tiers under `hold` realize clock events on step boundaries, so every exposure boundary there is a step boundary and the boundary case is the common case, not a corner; the per-step accumulator variant of the model exists for that reason.
- The gym's reward windows and the telemetry windows are consumers of the same function; if either chapter wants the other rule for its own windows, that is a second rule and needs its own name, not a silent exception.
