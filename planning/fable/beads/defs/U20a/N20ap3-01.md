## Background

"The other Frontier sensor models named in this chapter (tactile arrays, event cameras, radiometric RGB, retroreflector bloom, backscatter from optical volumes) are on no task's path before M5. Each is funded only when a registered task needs it, names one analytic fixture as its pilot when it is, has no speed benefit to claim, and falls back to the mask-only model under the same cost rule."

This bead records that rule as an enforced register, so that none of the five is built speculatively and none is forgotten, and it reports the status of each model to the user through `sense.profile`. It was split from N20a-30 in polishing round 3: the three models of N20a-30 close `withdrawn` when no registered task needs them by the M6 exit candidate (the close N20a-18 uses for tactile arrays), while the register and the profile block must exist on either branch, because `sense.profile` reports `not due` for every model until a task registers (its VERBS-sense row) and the guard against an unfunded model is needed most when none is funded. Tier: Solid; the register is plain data and a check, and it builds no model.

The register is itself a guard against false progress: "implemented" for an upper-tier capability requires its pilot and its kill or fallback decision on record, and a capability that fell back is described by the name of the fallback.

## Scope

In: `registries/frontier_sensors.toml` with five rows and their status; the status rule read from the pilot register and the decisions; the finding for a design that requests a model that is not built; the conformance check that rejects mechanism code landing before its pilot's funding verdict; the `frontier_models` block of `sense.profile`; tests and script.

Out: the pilots (N20a-18 for tactile arrays, N20a-29 for the other three, N19b-24 for radiometric RGB with the owner's decision N19bp2-01); the models themselves (N20a-19, N20a-28, N20a-30), each of which moves its own row from `funded` to `built` or `fallback` with its measured cost fraction; the rest of `sense.profile` (N20b-16, a dependency); the decision about which late epics are active (N41-09).

## Technical approach

**1. The register** (`registries/frontier_sensors.toml`, DESIGN). One row per model: `name`, `tier = "F"`, `task` (the registered task that needs it; empty until one exists), `pilot` (the pilot record's identifier in `crates/frob-conformance/registry/pilots.toml`, `PILOT-SENSE-<nn>`, or for RGB the epic's pilot and the owner's decision; the verdict is read from there, never copied), `fallback` (the mask-only model), `mechanism_bead`, `cost_fraction` (measured; empty until built), `status` ∈ {`not due`, `pilot frozen`, `funded`, `fallback`, `built`}.

| Model | Mechanism bead | Pilot | First check or fixture | Mask-only fallback |
|---|---|---|---|---|
| Tactile arrays | N20a-19 | N20a-18 | Resultant load equals the sum over taxels | Contact mask per taxel |
| Event cameras | N20a-30 | N20a-29 | Step edge: ⌊ln ρ / C⌋ events per pixel, in order | "Changed since last frame" mask at frame instants |
| Radiometric RGB | N20a-28 | N19b-24, N19bp2-01 | Photon-transfer line on a grey card | Mask-and-label image without radiometry |
| Retroreflector bloom | N20a-30 | N20a-29 | Saturating target on a dark background | `saturated` flag on the target's own samples |
| Volume backscatter | N20a-30 | N20a-29 | Homogeneous slab, first range gate | Extinction only: `attenuated`, never a false near point |

**2. The status rule** (a pure function of the row and the registers it points to; numbered steps).
1. No registered task, or the pilot record `withdrawn` with the reason "not due: no registered task": `not due`.
2. A pilot record `registered` or `running` with its protocol frozen (ledger sequence present): `pilot frozen`.
3. A pilot result `falsifier-rejected` (for RGB: the owner's decision `fund`): `funded`.
4. A pilot result `falsifier-holds` (for RGB: `drop`): `fallback`. After `funded`, where the model's kill row in `registries/gates.toml` carries a decision in force (tactile arrays: KILL-TAXEL, decided by N38ap3-01, which reads the lower bound of the cost fraction and does not fire on bounds that straddle 0.25), that decision governs: `fired` gives `fallback`; otherwise a measured `cost_fraction` above 0.25 gives `fallback`.
5. A `cost_fraction` recorded by the mechanism bead with its receipt and, where the model's kill row carries a decision in force, that decision `not-fired` (otherwise the fraction at or below 0.25): `built`. A row with a recorded fraction whose kill decision is not yet in force stays `funded`.
A stored `status` that differs from the function's value fails the registry load, naming the row and both values.

**3. Unbuilt models give the fallback and a finding.** A design whose sensor requests a model whose status is not `built` receives the model's mask-only fallback and a finding `frontier-model-not-built` naming the model, its status and the fallback (DESIGN name; a warning, not a refusal), so that Solid output is never delivered silently in place of a requested model.

**4. Pre-funding check.** `crates/frob-conformance/tests/frontier_register.rs` reads the register and the workspace: a mechanism module of a model (the feature flags `frontier-event`, `frontier-bloom`, `frontier-backscatter`, `frontier-tactile`, `frontier-rgb` of `frob-sense`, each declared in the row's `mechanism_bead`) present in the tree while the row's status is `not due` or `pilot frozen` fails the check, naming the row and the feature; a row whose status is `built` without a `cost_fraction` and its receipt fails too.

**5. The `frontier_models` block of `sense.profile`** (the extension the VERBS-sense row lists from M6; additive over N20b-16's sections): per sensor of the design, the Frontier models it requests, each with `status`, `pilot`, `fallback` and, where the fallback is in force, the finding of item 3. With no model requested the block is an empty list; with no task registered every requested model reports `not due`.

## Acceptance criteria

- [ ] The register exists with five rows, each `not due` until a task registers, and its load recomputes every status by the rule of item 2.
- [ ] `frob sense profile <design> --json` carries the `frontier_models` block; a design requesting an event camera before it is built reports `not due`, receives the "changed since last frame" fallback, and carries the finding `frontier-model-not-built`.
- [ ] A mechanism feature present in the tree before its row reaches `funded` is rejected by `cargo test -p frob-conformance --test frontier_register`.
- [ ] A pilot record `withdrawn` with "not due: no registered task" keeps the row `not due`; a `falsifier-holds` result or a cost fraction above 0.25 gives `fallback`, and the block then names the capability by its fallback.
- [ ] The bead closes on the register, the check and the block whatever the pilots' outcomes; it builds no model.

## Test plan

### Unit tests
`crates/frob-sense/tests/frontier_register.rs` (`cargo test -p frob-sense --test frontier_register`) and `crates/frob-conformance/tests/frontier_register.rs` (`cargo test -p frob-conformance --test frontier_register`).
- `register_five_rows_not_due`.
- `status_rule_table`: each of steps 1 to 5 on a synthetic row (a withdrawn record gives `not due`; a frozen protocol `pilot frozen`; `falsifier-rejected` `funded`; `falsifier-holds` `fallback`; cost 0.31 `fallback`; cost 0.19 with a receipt `built`; for tactile arrays a fraction 0.27 with bounds (0.23, 0.31) stays `funded` until KILL-TAXEL's decision, then `built` on its `not-fired` and `fallback` on `fired`).
- `stored_status_mismatch_fails_load`.
- `unbuilt_model_gives_fallback_and_finding`.
- `profile_block_lists_requested_models`: two sensors requesting event camera and bloom give two entries with their statuses; a design requesting none gives an empty list.
- `mechanism_before_funding_rejected` (conformance): a synthetic tree with the `frontier-event` feature while the row is `not due` fails, naming both.
- `built_without_cost_rejected` (conformance).

### End-to-end script and logging
`scripts/e2e/sense_frontier_register.sh` (header `# e2e: bead=N20ap3-01 milestone=M6 labels=sensorium,registry seed=0 needs=cpu plants=silent-solid`; sources the STD-E2E helper; NDJSON under `target/e2e-logs/sense_frontier_register/<utc>.ndjson` with a transcript). Steps: `register` reads `registries/frontier_sensors.toml` and the pilot records read-only (`cargo run -p frob-conformance --example pilots -- fundable --all --json`) and asserts that every status equals the rule's value; `check` runs `cargo test -p frob-conformance --test frontier_register`; `profile` runs `frob sense profile <fixture design requesting each model> --task <task> --json` per model and asserts the reported status and, for an unbuilt model, the fallback with its finding; `plants` runs the plant `silent-solid` (a build that hands Solid output to a design requesting an unbuilt model without the finding) and must see it caught. Every line carries `ts`, `script`, `bead`, `step`, `event`, the exact command line, exit code and wall time, the envelope's evidence block, per row the status read and recomputed and the pilot identifier; a final `summary` counts assertions and gives `gates: []`. Before any model is funded the script asserts five `not due` rows and exits 0 with a summary saying so.

### Known answers and negative controls
Known answers: five rows, each `not due` with no task; the status table of item 2. Negative controls: the `silent-solid` plant (a requested unbuilt model answered with Solid output and no finding); a register whose stored status was edited by hand to `built` without a cost fraction (fails the load). Determinism: the register and the block are pure functions of the files read; byte-identical output on repeat.

## Considerations

- The rows for tactile arrays and RGB point at beads of other units; the register reads their records and decisions and never copies a verdict, so that a pilot re-run or an owner's re-decision changes one place.
- A model that fell back is described by its fallback's name everywhere (profile, cards, reports), as for kill-gate fallbacks.
- At most four late epics are active at once under the program's rule; the register reserves no slot.
