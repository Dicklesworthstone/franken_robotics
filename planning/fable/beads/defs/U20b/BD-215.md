## Background
Sensorium's first decision is that observations come only from a deterministic observation service that is part of the model identity, never from a renderer, a viewer, presentation timestamps or level-of-detail state (ADR-SENS-01), because a result must not depend on whether someone was watching. Decisions like that are easy to state and easy to break in a refactor. Noninterference is how they are kept: five properties, each tested by changing one thing and comparing digests.

| Property | Change | Must be unchanged |
|---|---|---|
| Presentation | Turn the viewer, stills or the telemetry level on or off | Every physics digest and every delivered observation |
| Truth | Change simulator truth behind a sensor that is disconnected, masked or not yet delivered | The actor's inputs and commands |
| Sensor set | Add, remove or reorder sensors that no controller consumes | The outputs of every other sensor, and physics |
| Batch | Run the same world address alone, in a batch of 8,192, and beside worlds with different sensor suites | That world's delivered observations |
| Optics against contact | Change an optical card, or an interface card | Physics digests, or ray outputs, respectively |

The sensor-set property is what ADR-SENS-10 buys (noise streams keyed by logical identity: world address, sensor, sample index, component). A generator that hands out draws in call order fails it the first time a sensor is added. The smallest case of that failure: a sequential stream r₀, r₁, r₂; design A draws a push (r₀) and a friction (r₁); design B has one more leg and draws a per-leg value first, so its push is r₁ and its friction r₂; the seeds are equal and the two designs were pushed differently.

The seed bead pairs noninterference with "the causal-policy test on every tier": the truth property *is* the causal test seen from the environment's side, and the gate GATE-SENS-12 needs its every-tier record at M2. Tier: Solid. Invariants carried: INV-SENS-01 (no observation depends on presentation state: viewer, stills, telemetry level or wall clock), INV-SENS-06 (adding, removing or reordering sensors does not change what the others read), INV-SENS-09 (a world's delivered observations do not depend on the batch it ran in).

## Scope
In: the noninterference harness; the five properties as tests on the standard battery on every tier; a planted control per property (the gate names the draw-order control; the others are added here so that no property is uncontrolled); asserting the presentation-state clause of refusal FROB-REF-442 on every tier, on the CLI and over MCP (the clause is raised by the observation service at task or environment registration, N20a-01; this bead tests that the forbidden request path stays refused once viewers, stills and devices exist); the G3 and G5 receipts of GATE-SENS-03 per tier (the gate is recorded once, by N20b-15, from its user-side run); the M2 (every-tier) part of GATE-SENS-12, recorded by this bead from the receipts of N20b-11's script run with each batched tier on N20b-12's form (its M1 part is N20b-11's record); this bead's own script.
Out: the causal test's mechanics (BD-119, N20b-12); the user-side noninterference script over the battery and the GATE-SENS-03 record (N20b-15, which depends on this bead); the general batch-invariance gate of the numerics chapter; the optics-against-contact gate of the scene chapter (this bead runs the property on sensing outputs and cites that gate for the scene side).

## Technical approach
**Harness (DESIGN, `crates/frob-sense/src/nonint/`, driven by the `nonint_*` rows of the conformance test targets `g3_metamorphic` (presentation, truth, sensor set, optics) and `g5_determinism` (batch): `crates/frob-conformance/tests/g3_metamorphic.rs` and `g5_determinism.rs`).**
```rust
// DESIGN. Fixes intent, not signatures.
pub enum Property { Presentation, Truth, SensorSet, Batch, OpticsVsContact }
pub struct Change { property: Property, describe: String, apply: fn(&mut RunSpec) }
pub struct Invariant { digests: Vec<DigestKind> }  // which digest streams must be byte-equal
pub fn check(base: &RunSpec, change: &Change, inv: &Invariant) -> NonintReport;  // first differing (world, tick, stream, value) or Equal
```
Digest streams: per-stage physics digests and the per-world state digest at the commit fence (the in-kernel integer digests of the chronicle); the delivered-observation digest per world and decision (the causal recorder's chained digest); per-sensor output digests (every packet of one sensor); the command digest. On devices all are `K-x-digest` words; the host confirms a reported difference with BLAKE3 over the recorded bytes. Runs use the frozen standard battery and its world addresses.

**The five properties, as numbered procedures.**
1. *Presentation.* Base: viewer detached, no stills requested, telemetry level T0. Changes, one at a time: viewer attached and reading snapshots; `telemetry.stills` (BD-191) and `telemetry.inspect-pixel` (N24a-40) called during the run; telemetry level T1 and T2. Invariant: every physics digest and every delivered-observation digest. The viewer reads immutable snapshots and never feeds anything back; this test is what detects a violation. Added control (synthetic): a camera implemented by asking the viewer for its latest frame, the design the chapter forbids; the property must fail, and the request path must be refused: asking the observation service for an observation whose source is presentation state returns **FROB-REF-442** ("an observation is requested from presentation state, or an actor schema names a privileged channel"; repair: use the observation service; exit 3), raised by the observation service's registration check (N20a-01) and asserted here on every tier.
2. *Truth.* Changes: alter simulator truth behind a sensor that is (a) disconnected (declared in the design, consumed by nobody, link down), (b) masked for the whole run, (c) not yet delivered (the delayed-measurement twin). Invariant: the actor's input digests and command digests. Implemented with the twin constructors and the recorder of the causal test; the planted leaks of that test are this property's controls.
3. *Sensor set.* Changes: add a sensor no controller consumes; remove one; reorder the sensor list in the design file. Invariant: the output digests of every other sensor, and all physics digests. Gate control (the one the gate names): the build feature `draw-order-noise` replaces addressed noise with a sequential per-world generator; adding a sensor then shifts the others' draws and the property must fail.
4. *Batch.* Run world address A alone; in a batch of 8,192; and in a batch whose other worlds have different sensor suites (a mixed batch of three body plans or sensor variants). Invariant: A's delivered-observation digests. Added control (synthetic): observation normalization by the batch mean (two worlds observing 1 and 3 normalized by their batch mean see −1 and +1; the first alone sees 0), which must fail.
5. *Optics against contact.* Change an optical card of a region (class `diffuse` to `glass`, or `r0`): every physics digest unchanged. Change an interface card (dry to wet): every ray output digest unchanged. Control: the build that derives friction from `r0`.

**Every tier.** Each property runs on the referee (where the batch property is trivial and is recorded as not applicable), `batch-cpu`, CUDA and Metal. Equality is within one tier and backend: the same run with and without the change, on the same placement. Nothing here compares across backends.

**GATE-SENS-12 on every tier.** With N20b-12 in place, the causal script of N20b-11 (`scripts/e2e/sense_causal_test.sh --tier batch-cpu|gpu-cuda|gpu-metal`) is run with each tier, including its learned-actor step, and the M2 part is recorded from its G3 receipts by this bead's session; this bead owns the completed every-tier record, N20b-11 the M1 (CPU) part.

**Evidence.** Reports are class `Tested`, tier G3 (metamorphic) for presentation, truth, sensor set and optics; G5 (determinism) for batch.

## Considerations
- A device family that fails batch-composition invariance fails the batch property by construction; the fallback named by the milestone is to drop that family or run it at a weaker class, and the row is recorded as failed with that reason, not waived.
- Telemetry at T2 changes memory traffic and may change scheduling; it must not change bits. If it does, the defect is in a kernel that reads uninitialized or shared state.
- The presentation property is the regression guard for the stills and viewer work; every new presentation feature adds a change to its list.
- Batch-size 8,192 with full sensor suites needs device memory; the row may use the height-scan suite and is recorded with its suite.
