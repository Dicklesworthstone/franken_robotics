## Background
A counterexample is the smallest case in which a tempting shortcut gives the wrong answer. The counterexample catalogue seeds the negative-control registry (`crates/frob-conformance/registry/controls.toml`): each shortcut becomes a planted defect that some gate's test must catch, because a gate that nothing can fail validates nothing. A CX number is never reused and never renumbered; new rows append. Mechanism beads cite CX numbers in their test plans and state the values they need inline; this bead is the chapter's registry, so that the sixteen numbered entries and the shortcuts of the three late subsections exist as data with an owner test each.

## Scope
In: the sixteen catalogue rows of the Sensorium chapter with the shortcut, the case with its numbers and the rule protected; the mapping of each to a registered control and to the test that must catch it; the four late shortcuts as pending rows; a registry check. Out: the tests themselves.

**Registry check.** `cargo test -p frob-conformance --test g0 -- sensorium_cx_registry`: each of the sixteen CX numbers and four pending slots has a control entry with a build feature or fixture, a catching test path and an owner; the latest recorded run of each catching test against its control failed as required; a control whose catching test passes is reported as a defect in the test.

## Acceptance criteria
- [ ] `controls.toml` holds twenty entries for this chapter (sixteen numbered, four pending) with shortcut, case, protected rule, feature or fixture name, catching test and owner.
- [ ] The registry check passes when every catching test has failed against its control, and fails if an entry is removed, has no catching test, or its catching test passes.
- [ ] Each mechanism bead that owns a catching test cites the CX number (or slot) and states the values inline.
- [ ] The four pending slots are reported to the catalogue owner for numbering; no existing number is reused.
- [ ] The two cross-catalogue identities are recorded: CX-203 ≡ CX-052 and CX-214 ≡ CX-049 (one fixture identity per physical case).
- [ ] The three entries for which the catalogue says "no numeric case is given" (CX-202, CX-212, CX-215) carry the numeric case their owner bead supplies, or are marked as qualitative with the test that exercises them.

## Test plan
### Unit tests
(`cargo test -p frob-conformance --test g0 -- sensorium_cx`)
- `sixteen_numbered_entries_present` (CX-200 to CX-215).
- `four_pending_slots_present`.
- `each_entry_has_catching_test_and_owner`.
- `control_must_fail_its_test`: a synthetic entry whose catching test passes is rejected.
- `cross_catalogue_identities_recorded`.
- Arithmetic spot checks of the numbers quoted (so a transcription error in the registry is caught): 400/13 rounds to 30.77; ⌈8,000/13⌉ = 616; 616/600 − 1 = 2.67%; 27/32, 459/512, 3,807/4,096 by exact enumeration of majorities with p = 3/4; ln(20)/4 = 0.7489 m; 9.5 + 9.5 + 10 = 29; 200 × 0.001/0.020 = 10; 0.4 × 0.5/0.2 = 1.0; 100 − 2 × 9.81 = 80.38 and −2 × (9.81 + 2) = −23.62.
### End-to-end script and logging
Run inside the chapter battery (`scripts/e2e/sensorium_known_answers.sh`, N20b-20), which executes each known answer against its control build; this registry supplies the control names. The battery's log records, per control, "failed as required" or the defect, in the STD-E2E format, and its summary counts controls caught out of twenty.
### Known answers and negative controls
The table is the content. Determinism: registry data; the arithmetic spot checks are exact or to four significant figures.

## Considerations
- Milestones differ by row (clock rows at M1; optics at M3; visibility at M3); the registry is written at M1 so that every gate can be registered with its failing control before its passing test, and entries are enabled as their mechanisms land.
- Controls are build features or fixtures in `frob-conformance` only; none may be compiled into a release binary.
- Rows whose catching test belongs to the other Sensorium unit are listed with "other unit"; the lead resolves the owner keys when both units' beads are loaded.
