## Background
A refusal in this system has a stable code, a message and ranked repairs. Three standing rules: refuse, never truncate; a budget stop publishes nothing partial as a result; a misspelt parameter is a refusal, not a default. Codes are never reused; the machine-readable registry is `registries/refusals.toml` and an unknown code is a load-time error. Families: `1xx` design and model; `2xx` numerics and integrator admission; `3xx` scene; `4xx` control and estimation; `5xx` learning and evaluation protocol; `6xx` backend and device; `7xx` budget and capability; `8xx` evidence and protocol; `9xx` internal. Every refusal that reaches a caller travels in the standard envelope with `ok: false` and a `refusal` object: `code`, `message`, `pointer` (the field or part at fault), `observed`, `required`, `unit`, `affected_claims`, `retry` (`never`, `after-change`, `backoff`) and ranked `repairs`. A refused input or question in families `1xx` to `5xx` exits with code 3 (Domain failure class); over MCP it is a tool result with `isError: true` whose structured content is the same envelope.

The Sensorium chapter defines seven codes, FROB-REF-440, -441, -442, -443, -445, -446 and -447 (FROB-REF-444 belongs to the control chapter: a transported skill does not refine its specification). This bead is the chapter's refusal registry: it carries each code with its meaning, trigger, ranked repairs and exit code, names the bead whose mechanism raises it, and owns the registry rows and the test that every code can be triggered and is raised by nothing else. The chapter governs the meaning and the repairs; the consolidated appendix is compiled from it.

## Scope
In: the seven registry rows; the trigger fixtures; a conformance test that triggers each code from the user's side and checks the envelope; the list of code-less refusals found in the chapter's late subsections, with their fail-closed interim handling.
Out: the mechanisms that raise the codes (each named below).

**442 and 524 (DESIGN; the plan gives both codes to an actor schema that touches a privileged channel and does not divide them).** They are divided by raising site, so that one event has one code. `FROB-REF-524` is the learner's: `frob-learn` raises it when one of its components asks to read, as the actor, a channel that the task classifies `critic-only` or `evaluation-only` (a network specification; a checkpoint's schema checked against the current task; a host caller's request for an actor view). That check runs before any schema is frozen, so such a request never reaches the freeze. `FROB-REF-442`, second clause, is the freeze's: `freeze_actor_schema` in `frob-sense` raises it, for whatever caller, when a channel offered for an actor schema is privileged by source (the truth namespace; a belief or measurement channel whose producer had privileged inputs; a task or curriculum parameter; a reward or termination signal) or is not of actor access. A learner's request that passed the class check and is still privileged by source (a task that classifies a truth channel as `actor`) is therefore 442. The same text stands in N20a-03, N23a-03 and the learning registry N23-REF; the row's message and repairs above are unchanged by it.

Reserved slots are registered names whose number is `pending`. Each is a ledger row of the second allocation round (N35x-02: `sens-peak-load-ungraded` and `sens-lead-too-short` in `4xx`, `causal-receipt-missing` in `5xx`; `FROB-REF-448` is not available, being a printed code of another chapter), whose run assigns the number by N35-33's rule; the decision N20b-45 writes the assigned numbers into these rows, and into the refusal lists of the verbs that raise them, before the M2 and M3 verbs list them.

**Conformance test.** `crates/frob-conformance/tests/g1_known_answers.rs` rows `refusal_sens_44x`: for each code a minimal fixture that triggers it through the real verb, asserting the code, the family, exit 3, `retry`, that `repairs` are present in the stated order, and that `pointer` names the offending field. A second test (`refusal_sens_exclusive`) runs the chapter's known-answer battery and asserts that none of the seven codes appears on a passing case. The fixtures: (440) a design with a sensor rate whose period makes Q = 2⁴¹; a clock with period 0; (441) a link latency bound of 2 s on a 200 Hz sensor with a queue capacity of 8; (442a) a task file naming a viewer buffer as an observation; (442b) an actor schema naming `truth.base_velocity`; (443) augmentation under the fore-aft mirror on a forward-camera quadruped; (445) `train start` on the T-junction mission with its witness on file; (446a) a rig with no anchor; (446b) localization on a tree rig; (447) a Reality claim over default cards.

## Acceptance criteria
- [ ] `registries/refusals.toml` holds the seven rows with message, family, defining chapter and repairs; the loader accepts them and rejects an unknown code in a verb's list (load-time error). The fixture's unknown code is computed at test time as the lowest `4xx` number absent from both the loaded registry and the allocation ledger, so a later allocation (449 is proposed for `sens-lead-too-short`) can never make it known.
- [ ] Each code whose raising bead has landed is triggered by its fixture through `frob --json` and through MCP, with exit 3 and the repairs in order; a trigger whose raising bead has not landed (the verb it drives is absent from `frob capabilities --json` or answers FROB-REF-724) is logged `e2e_skip 'needs <bead>'` and never counted as passed. A registry does not depend on the mechanisms that raise its codes, so this bead closes on the rows and the triggers available; the script is re-run at each milestone exit, and by M3 all ten triggers run.
- [ ] No code is raised on any passing case of the chapter's battery.
- [ ] Every code maps to exactly one exit code (the surface chapter's parity requirement for this family).
- [ ] The three reserved slots are registered, listed in the output of `frob schema --refusals`, and flagged `number: pending`.
- [ ] Each mechanism bead named in the table lists this registry as the source of its code's message and repairs (no bead carries a divergent message).
- [ ] Negative control: a build in which FROB-REF-441 is replaced by silently dropping the oldest packet passes no test that expects the refusal (the fixture detects truncation), confirming "refuse, never truncate" is tested.

## Test plan
### Unit tests
(`cargo test -p frob-core refusals`, `cargo test -p frob-conformance --test g1_known_answers -- refusal_sens`)
- `seven_codes_registered_family_4xx`.
- `unknown_code_is_load_time_error`.
- `each_code_has_ordered_repairs`.
- `division_442_524`: a task that classifies a truth channel as `actor` and is offered to the freeze yields 442; a learner request for a `critic-only` channel as actor is not 442 (it never reaches the freeze; 524 is the learner registry's, asserted there).
- `trigger_441_fork_ring` (run with N20ax-01, M2): a fork whose new link law raises the 200 Hz sensor's latency bound beyond the ring capacity fixed at launch → 441 with `observed` the allocated capacity and `required` the new figure, and no child started.
- `trigger_440_q_above_limit`, `trigger_440_zero_period`, `trigger_441_history`, `trigger_442_presentation`, `trigger_442_privileged`, `trigger_443_outside_obs`, `trigger_445_standing_witness`, `trigger_446_no_anchor`, `trigger_446_tree_localize`, `trigger_447_assumed_field`.
- `codes_not_raised_on_passing_battery`.
- `reserved_slots_pending`.
- `unknown_code_fixture_absent_from_ledger`.
### End-to-end script and logging
`scripts/e2e/sense_refusals.sh` (sources the STD-E2E helper): first `frob --json schema --refusals` (the seven rows and the three reserved slots, asserted against the table); then the ten trigger fixtures on the CLI and through the MCP server, each guarded by `frob capabilities --json` so that a trigger whose raising bead has not landed is an `e2e_skip 'needs <bead>'` line (440: BD-078; 441: BD-098; 442a: N20a-01; 442b: N20a-03; 443: N20b-02; 445: N20a-41; 446: N20b-04, N20b-05 and BD-242; 447: N20b-18); asserts code, exit 3, repairs and surface parity; logs to `target/e2e-logs/sense_refusals/<utc>.ndjson` with a transcript: each `cmd` with its exact command line, exit code and wall time; a `refusal` line per trigger with code, pointer, observed, required and repairs; an `assert` per check; a summary with the number of codes exercised out of 7, the triggers skipped with their reasons, and the reserved slots seen. Planted failure (`E2E_PLANT_FAILURE=truncate`): the silent-truncation build of the 441 control, which the script must report as a failed assertion.
### Known answers and negative controls
KA-474 (a lattice with common denominator above 2⁴⁰ is refused with FROB-REF-440; at the limit a run of 10⁶ s stays below 2⁶⁰ quanta), KA-496's control (a tree refuses localization, FROB-REF-446), CX-206 (the T-junction mission behind FROB-REF-445), CX-209 (behind FROB-REF-443). Control: the silent-truncation build. Determinism: refusals are functions of the request; identical envelopes across platforms.

## Considerations
- Milestones: the codes arrive with their mechanisms (440 and 441 at M1, 441's fork trigger at M2, 442 at M1 and M2, 443, 446 and 447 at M3, 445 at M3); the registry rows are written at M1 so that verbs can list them from the start, and a trigger test is enabled when its mechanism lands.
- A code's repairs are ranked: the first is the one the chapter expects to be right most often; agents read them in order.
- FROB-REF-445 has an override for diagnosis; an overridden run is labelled and its results cannot be cited, which must be visible in the evidence block.
