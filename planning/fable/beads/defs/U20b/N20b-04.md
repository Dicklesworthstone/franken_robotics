## Background
Extrinsic calibration of a sensor rig is weighted least squares on a graph, and the studio names it as such: no special theory, a pose graph. Nodes are sensor frames and the base. The unknowns are corrections δ_v in the Lie algebra 𝔰𝔢(3) to each sensor's mount transform, with the base anchored at zero to remove the six-dimensional gauge (moving every sensor and the base together changes no relative measurement). Edges are pairwise relative-pose measurements (camera to IMU, lidar to odometry, hand to eye), each with a residual r_e in 𝔰𝔢(3) and a 6 × 6 weight W_e, the inverse of its covariance.

This bead is the core solver in `frob-sense`. Its consumers are: the simulated robot's own self-check after an impact; fault injection (an "extrinsic bump", a step change of a mount transform, N20b-06); the verb `sense.calibrate` (BD-242); and Ground, which runs the same solver on logs from a real rig (N20b-08). One solver for simulation and for real logs is a DESIGN choice: the code that diagnoses a simulated bump is the code that will diagnose a real one, so the simulation exercises it thousands of times before a real log arrives. Tier: Solid.

The one place this computation goes wrong in practice is the frame of the adjoint on the tail of an edge. The chapter fixes it and plants the wrong choice as a mutant, and a late known answer gives a single edge on which the two differ in sign.

## Technical approach
**Types (DESIGN, `crates/frob-sense/src/calib/graph.rs`).**
```rust
// DESIGN. Fixes intent, not signatures. Frames are typed by frob-lie's frame-typed transforms.
pub struct PoseGraph { nodes: Vec<Node>, edges: Vec<Edge>, anchor: NodeId }
pub struct Node { id: NodeId, kind: NodeKind /* Base | Sensor(SensorId) */, mount: Se3 /* pose of the node frame in the base frame, current estimate T̂_v */ }
pub struct Edge { tail: NodeId, head: NodeId, measured: Se3 /* T_th: pose of the head frame in the tail frame */,
                  weight: Sym6 /* W_e = Σ_e⁻¹, positive definite */, source: EdgeSource }
pub struct Solution { corrections: Vec<Twist6>, mounts: Vec<Se3>, covariance: SymMat, iterations: u32, converged: bool }
```
**Conventions.** Corrections are applied on the right of each mount transform: T_v = T̂_v·τ(δ_v), with τ the retraction (the exponential, or the Cayley map; the choice is recorded). For an edge from sensor 1 (tail) to sensor 2 (head), the predicted relative pose is T̂₁₂ = T̂₁⁻¹·T̂₂ and the measured one is T₁₂. The residual is
  r₁₂ = log(T̂₁₂⁻¹·T₁₂).
Substituting T₁ = T̂₁·exp(δ₁), T₂ = T̂₂·exp(δ₂): T₁₂ = exp(−δ₁)·T̂₁₂·exp(δ₂) = T̂₁₂·exp(−Ad(T̂₁₂⁻¹)·δ₁)·exp(δ₂), so to first order
  r₁₂ ≈ δ₂ − Ad(T̂₂₁)·δ₁, with T̂₂₁ = T̂₁₂⁻¹.
Ad is the adjoint of SE(3) in `frob-lie`'s convention, acting on twists; with a twist written (angular, linear), rotation R and translation p of the transform, Ad(T)·(ω, v) = (R·ω, p × (R·ω) + R·v). **Using Ad(T̂₁₂) on the tail is the planted frame mutant.**

**Linear system.** Stack the residuals: r = B·δ + noise, where B is the block incidence matrix of the graph: for edge e from tail t to head h, the block row has +I₆ in the columns of h and −Ad(T̂_ht) in the columns of t; the anchor's columns are removed (δ_anchor = 0). With W = blockdiag(W_e), the Gauss–Newton step solves the normal equations
  (Bᵀ·W·B)·δ = Bᵀ·W·r,
and the update T̂_v ← T̂_v·τ(δ_v) is applied on the group.

**Algorithm.**
1. Structural check: the anchor exists and every node is connected to it through edges. Otherwise refuse with FROB-REF-446 ("a calibration request exceeds what the graph supports: no anchor …"; repair "anchor the base", or for a disconnected component "add pairwise measurements" naming the component). A singular or numerically indefinite Bᵀ·W·B after anchoring is the same refusal, never a pseudo-inverse.
2. Compute every r_e and B at the current estimate.
3. Factor N = Bᵀ·W·B by dense Cholesky in `f64` (dimension 6·(n − 1) for n nodes; rigs have at most a few tens of nodes) and solve for δ.
4. Apply the retraction per node.
5. Repeat from 2 until the W-norm of the step, (δᵀ·N·δ)^½, is below 10⁻¹² (DESIGN, dimensionless since W whitens) or 20 iterations elapse; `converged` records which.
6. Covariance of the corrections: Σ_δ = N⁻¹ at the solution (valid when each W_e is the inverse of the edge's covariance).
The residual used after convergence, and the block structure B, are handed to N20b-05.

**Units.** Rotations are in radians and translations in metres; they have different scales, and W is what makes the problem well posed. No Euclidean norm of a mixed twist is ever taken; every norm in this crate is a W-norm or a per-part norm with its unit.

**Determinism and evidence.** Host computation in `f64`, fixed elimination order: bitwise repeatable on one platform (class D2 on the host). Outputs are `Tested`; from simulated measurements they are labelled as coming from a `synthetic` front end where that applies (BD-242).

**Known answer for one edge (late fixture row; gate GATE-GAUNT-11).** Predicted pose of sensor 2 in sensor 1: a pure translation of (1, 0, 0) m. Sensor 1's mount is off by a rotation of 0.01 rad about z (δ₁ = (angular (0, 0, 0.01), linear 0)); sensor 2's is exact. Then T̂₂₁ is the translation (−1, 0, 0), Ad(T̂₂₁)·δ₁ = ((0, 0, 0.01), (−1, 0, 0) × (0, 0, 0.01)) = ((0, 0, 0.01), (0, 0.01, 0)), and r₁₂ = −Ad(T̂₂₁)·δ₁ has angular part (0, 0, −0.01) rad and linear part (0, −0.01, 0) m: sensor 2 appears at (1, −0.01, 0) m, which is what rotating sensor 1's frame by +0.01 rad about z does to a point at (1, 0, 0). The mutant with Ad(T̂₁₂) on the tail gives a linear part of (0, +0.01, 0) m.

## Acceptance criteria
- [ ] `frob-sense::calib` builds the graph, solves and returns corrections, updated mounts and covariance; `CONTRACT.md` states the right-correction convention, the residual definition and the tail-adjoint rule in formulas.
- [ ] The one-edge known answer reproduces: angular (0, 0, −0.01) rad, linear (0, −0.01, 0) m: the linearized tail block times δ₁ exactly, and the logarithm of the nonlinear relative transform within the tolerance the registered row carries (10⁻⁴ m and 10⁻⁶ rad; KA-849, N38b-42); the solver recovers δ₁ = 0.01 rad about z when node 2 is the anchor.
- [ ] The frame mutant (Ad(T̂₁₂) on the tail) yields (0, +0.01, 0) m and fails the test; it also fails recovery on a random three-dimensional rig.
- [ ] On 1,000 random rigs (4 to 8 nodes, connected, random corrections up to 5° and 50 mm, exact measurements) the solve converges and recovers the planted corrections to 10⁻⁹ rad and 10⁻⁹ m.
- [ ] A graph with no anchor, and a graph with a component disconnected from the anchor, are refused with FROB-REF-446 and the matching repair (the solver returns the typed refusal with its family, pointer and repairs; exit 3 through `sense.calibrate` is asserted by BD-242, which depends on this bead).
- [ ] The covariance equals the inverse normal matrix and matches the sample covariance of the estimate over 2,000 noisy draws within 5%.
- [ ] No Euclidean norm of a mixed rotation-translation vector appears in the crate (a lint or a grep test in CI).
- [ ] The wrong-adjoint mutant exists for the Gauntlet to plant: it is the plant `N38b-42:cx-398` of CX-398 (KA-849's control), the Cargo feature `cx-398` of `frob-sense`, enabled only under `gauntlet-mutations` and never in a release build.

### Known answers and negative controls
The one-edge row (angular (0, 0, −0.01) rad; linear (0, −0.01, 0) m; control: Ad(T̂₁₂) on the tail gives (0, +0.01, 0) m). Metamorphic relations: re-anchoring at another node changes the corrections by the gauge and leaves relative mounts unchanged; relabelling nodes permutes the solution; scaling all weights by a constant leaves the estimate unchanged and scales the covariance inversely. Determinism: twice on one machine, debug and release, Linux and macOS (bitwise on each; cross-platform within 4 ulp until deterministic elementary functions are admitted).

## Considerations
- The first-order Jacobian is adequate because iterations re-linearize; for corrections above about 10° the convergence test may need the exact right-Jacobian inverse of the logarithm. The 20-iteration cap reports non-convergence rather than returning a partial answer.
- A time offset on one sensor pair looks like a faulty edge whose residual depends on motion; with one axial velocity it is not separable from a mount translation (the alias that Ground's exposure-delay analysis states). The solver does not estimate time offsets; N20b-05 and N20b-08 say how the alias is reported.
- Weights must come with provenance: an edge whose covariance is `assumed` propagates `assumed` to the covariance of the corrections.
