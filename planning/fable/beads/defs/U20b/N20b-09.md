## Background
A policy is causal if its command at a decision instant depends only on the observations delivered to it by then, its past actions and its own random draws. The simulator can violate this on the policy's behalf in many small ways (a privileged channel, a sensor read at its current value instead of from its delivered packet, a noise stream whose draws shift with a hidden parameter), and the causal-policy test catches them without reading the policy's code. Its procedure: run a world and a **twin** that differs only in something the policy cannot yet know; record at every decision instant a digest of the bytes delivered so far and a digest of the command; wherever the delivered-observation digests of the two runs agree, the command digests must agree.

The test is only as good as its twins. A twin that differs in something already visible proves nothing (the delivered digests differ at once and no comparison is made); a twin whose construction itself perturbs unrelated draws creates false alarms. This bead builds the twin constructors as a small library with fixtures, before the test itself (BD-119), so that the test has definite inputs. The four kinds the chapter names:

1. terrain beyond every sensor's reach, or changed after the decision time;
2. the friction of a surface not yet touched;
3. a measurement whose packet is delayed past the decision;
4. a randomization parameter of a later phase.

They correspond to the metamorphic relation "two worlds that differ only in something not yet delivered give equal command digests; an out-of-order arrival never changes a past decision" and to the environment rule that histories with identical delivered observations, past actions and policy random draws up to a decision instant yield the same command, tested by perturbing future terrain, hidden friction and measurements not yet delivered, one at a time. Tier: Solid. Owner: `frob-sense`, with fixtures in `frob-conformance`.

## Scope
In: the `TwinSpec` type and four constructors; the guarantee that a twin changes nothing but the named hidden thing (same world address, same seeds, no shifted draws); the declared or computed `knowable_from` instant; the truth-differs check; fixtures for the M1 baseline controllers on the referee.
Out: the digest recorder and comparison (BD-119); the planted leaks (N20b-10); batched-tier twins as paired worlds in one batch (N20b-12); the search for witnesses of unsolvability, which is a different object (the alias witness).

## Technical approach
**Types (DESIGN, `crates/frob-sense/src/causal/twin.rs`; fixtures under `crates/frob-conformance/fixtures/sensorium/causal/`).**
```rust
// DESIGN. Fixes intent, not signatures.
pub enum TwinKind { TerrainBeyondReach, TerrainAfter(Quanta), UntouchedFriction, DelayedMeasurement, LaterPhaseParameter }
pub struct TwinSpec { kind: TwinKind, hidden: HiddenChange, knowable_from: Knowable, episodes: EpisodeSet /* All | Only(k) */ }
pub enum HiddenChange { Value(FieldPath, Value) /* rule 2 */, Retile(RegionId, TilePlan) /* rule 2, exception */, /* open */ }
pub enum Knowable { At(Quanta), FirstContactWith(RegionId), FirstRayInto(RegionId), ArrivalOf(SensorId, u32),
                    FirstOf(Vec<Knowable>) /* the earliest of the listed events */ }
pub struct TwinPair { a: WorldSpec, b: WorldSpec, spec: TwinSpec, truth_digest_a: Digest, truth_digest_b: Digest }
pub fn make_twin(base: &WorldSpec, spec: &TwinSpec) -> Result<TwinPair, TwinError>;
```
**Common rules for every constructor.**
1. World b has the same world address, design, task, controller and seeds as world a. Only the hidden change differs.
2. The hidden change is applied through the scene, card or link layer as a *value* change of an existing field, never by adding or removing an entity, so that addressed noise and randomization streams (keyed by logical identity) are untouched. A constructor asserts this by comparing the stream registries of the two worlds. One exception (DESIGN), `HiddenChange::Retile(R, plan)`: the tiling of an interface-map region R that the robot has not touched is changed (a patch with a different number of tiles), so that R's own streams are added or removed; it is admitted only when every stream that differs between the two registries belongs to R, and every stream outside R is identical (checked by the same registry comparison, restricted). Under a correct build keyed by logical identity this changes nothing that any visible sensor draws; under the keyed-by-order leak (N20b-10, leak 5) it shifts the visible sensor's noise, which is how that leak is exposed. A change that alters an existing key or a stream outside R is still `TwinError::ShiftsStreams`.
3. `truth_digest_a ≠ truth_digest_b` is asserted at construction (the worlds really differ); a twin with equal truth is a `TwinError::NoDifference`.
4. `knowable_from` is the earliest event after which delivered bytes are allowed to differ. The test uses it for the premature-delivery check (delivered digests that differ before it are a failure of the environment, BD-119), for the vacuity guard (the test needs decisions before it) and for reporting; the causality condition itself (equal information, equal command) never depends on it.
5. *Episode scope.* `episodes: All` applies the hidden change in every episode of the run; `episodes: Only(k)` applies it in episode k alone, so that the two worlds are identical again from the reset that starts episode k + 1. `knowable_from` is stated per episode (none in an episode without the change). The reset-mask leak is exposed by an `Only(k)` twin.

**The four constructors.**
- *Terrain beyond reach* (`TerrainBeyondReach`): choose a scene region R such that no ray of any ranging sensor can intersect geometry depending on R and no contact with R can occur before a computed earliest time t_R: R lies outside the union of sensor range gates and of the body's collision geometry swept along the reachable set of the base up to t_R (reachable set bounded by the maximum base speed v_max times time). With d_R the distance from the base's initial position to R, r the largest range gate of any ranging sensor and ρ the largest distance from the base origin to any collision geometry, t_R = min((d_R − r)/v_max, (d_R − ρ)/v_max), only the contact term when the design has no ranging sensor. R is admitted only if at least 100 decision instants precede t_R. Change R's geometry (a step raised by 5 cm, a box added inside an already-occupied overlay slot's bounds as a size change). `knowable_from = FirstOf([FirstRayInto(R), FirstContactWith(R)])`, never earlier than t_R. Every M1 archetype is blind to terrain (ranging sensors arrive at M2 with BD-187), so at M1 the event is the first contact: a twin keyed on the first ray alone would never become knowable, and its first contact would be reported as a premature delivery. *Terrain after the decision* (`TerrainAfter(t)`): a scheduled scene change (a fixture moves, a door opens, a step changes height) at instant t, chosen for a blind archetype among geometry the robot touches after t, so the twin is not inert; `knowable_from = At(t)`.
- *Untouched friction* (`UntouchedFriction`): change the interface condition or the friction coefficient of a surface region the robot has not yet contacted (dry to wet on a tile 3 m ahead). Optical cards are left unchanged (the optical map and the interface map are separate, so friction is invisible to rays). `knowable_from = FirstContactWith(R)`. A variant uses `Retile` (the same untouched patch split into a different number of tiles, with the same friction per tile or a changed one) for the keyed-noise leak.
- *Delayed measurement* (`DelayedMeasurement`): pick a sensor s and a sequence number n whose packet the link's loss draw does not drop; in both worlds the link model's latency for packet n is set to a value that puts its arrival after decision d (an explicit per-packet override in the link card, part of the world specification); the two worlds differ in the truth that packet n alone carries: a sensor-level value confined to sample n (an encoder offset, or a bias value, that applies at sample n's instant and reverts at sample n + 1), so that no other packet's bytes and no physics differ. Sample n is taken at a decision instant d₀ ≤ d (so it is the latest sample of s at d₀, and a read of the sensor's current value at d₀, leak 3 of N20b-10, sees the changed value). A persistent change (an offset step that stays) would also be carried by packets n + 1, n + 2, … arriving on time, before packet n, and the twin would be visible before its `knowable_from`. Before the arrival, delivered bytes agree. `knowable_from = ArrivalOf(s, n)`. The link card of N20a-08 offers latency laws only (`fixed`, `uniform`, `table`), so this bead adds the test-only field `latency_override` (a list of (sequence number, latency in quanta)) to the link card: stage 3 uses the listed latency in place of the drawn one for those packets, the other draws of the packet (loss, duplication) are unchanged, the field is part of the world identity, and an override counts toward `latency_max` when BD-098 sizes the ring, so admission stays sound.
- *Later-phase parameter* (`LaterPhaseParameter`): a task with phases (walk, then carry a payload from t = 5 s; or a push at t = 3 s). Change the parameter that only takes effect in the later phase (payload mass, push magnitude, the curriculum level of the next phase). `knowable_from = At(phase start)`. With `episodes: Only(k)` on a run of at least two episodes, this is the twin that exposes history crossing a reset.

**M1 fixtures (referee).** For each baseline controller available at M1 (the legged controller on `quad-mammal` and `humanoid`; the wheeled controller on `diff-drive` and `mecanum`, from `control.synth`, BD-118), one twin of each kind on a flat scene with a step or a tile ahead: sixteen twin pairs, each with a horizon of 6 s and at least 100 decision instants before `knowable_from`. Two further pairs per archetype serve the leak fixtures of N20b-10: a two-episode later-phase twin with `episodes: Only(1)`, and an untouched-friction `Retile` twin. The fixture tasks and scenes are committed with the pairs (`causal-<archetype>` tasks), so the end-to-end script names them rather than a general task.

**Determinism.** Construction is exact bookkeeping (D0). Worlds run in the class of their tier.

## Acceptance criteria
- [ ] `make_twin` implements the four kinds (five enum cases) with the common rules; `CONTRACT.md` section "twins" states rule 2 and why.
- [ ] For every fixture pair: truth digests differ; stream registries are identical; delivered-observation digests of the two runs are equal at every decision before `knowable_from` (this is a property of the twin, checked with a correct build of the observation service) and differ at some decision after it (the twin is not inert).
- [ ] At least 100 decision instants precede `knowable_from` in every fixture.
- [ ] A deliberately bad twin is rejected: a "hidden" change inside a sensor's range gate, or within body reach of the base before the compared decisions end, fails the reach computation; a change made by adding an entity is rejected with `TwinError::ShiftsStreams`; a delayed-measurement twin whose change persists past sample n fails the fixture check (delivered digests differ before `knowable_from`).
- [ ] The sixteen M1 fixture pairs and the eight leak-exposing pairs (two per archetype) are committed with their digests and tasks.
- [ ] A `Retile` twin is admitted only when every differing stream belongs to the retiled region; an `Only(k)` twin's two worlds have equal truth digests from the start of episode k + 1.
- [ ] Negative control for the library: a constructor variant that draws the hidden value from a new sequential stream makes the delivered digests differ before `knowable_from` and is caught by the acceptance check above.
- [ ] `scripts/e2e/sense_twins.sh` exits 0, with every pair's digests logged and every bad twin and the planted constructor caught.

## Test plan
### Unit tests
(`cargo test -p frob-sense causal::twin`)
- `terrain_beyond_reach_is_unreachable`: lidar range 8 m, base speed bound 1.5 m/s, horizon 2 s: a region 12 m ahead qualifies, a region 10 m ahead does not (8 + 1.5 × 2 = 11 m).
- `terrain_beyond_reach_blind_uses_contact`: no ranging sensor, body reach ρ = 0.6 m, v_max = 1.0 m/s, horizon 2 s: a region 3 m ahead qualifies (t_R = 2.4 s), 2.5 m ahead does not (t_R = 1.9 s); `knowable_from` resolves to the first contact with R, and the pair's delivered digests are equal before it and differ after it on the referee.
- `untouched_friction_leaves_optics`: optical-map digests equal across the pair.
- `delayed_measurement_arrival_after_decision`: packet n arrives one quantum after decision d: not visible to d; visible to d + 1.
- `delayed_measurement_change_confined_to_packet`: a 1 kHz encoder read by a 100 Hz controller, packet n delayed past decision d: a one-sample offset leaves every other delivered packet byte-equal and the delivered digests equal before `ArrivalOf(s, n)`; a persistent offset step (the planted bad twin) makes them differ at the arrival of packet n + 1, earlier, and fails the fixture check.
- `latency_override_sizes_ring`: an override of 80 ms on a link with `latency_max` 30 ms raises the ring capacity BD-098 computes to cover 80 ms; the other packets' drawn latencies are unchanged.
- `later_phase_parameter_inert_before_phase`.
- `twin_keeps_stream_registry`; `twin_truth_differs`; `twin_adding_entity_rejected`.
- `retile_admitted_only_with_region_streams`: a retiling whose added streams all belong to R is admitted; one that also renames a stream outside R is `ShiftsStreams`.
- `episode_only_twin_identical_after_reset`.
- `delivered_digests_equal_until_knowable` over the sixteen fixtures and the eight leak-exposing pairs (episode-scoped digests).
- `sequential_stream_constructor_caught` (the planted failure below): the delivered digests differ before `knowable_from`.
### End-to-end script and logging
`scripts/e2e/sense_twins.sh` (this bead's own script; sources the STD-E2E helper; it calls only cargo targets of this bead and its dependencies, because the verb that consumes the twins, BD-119, depends on this bead). Steps: (1) `cargo test -p frob-sense causal::twin`; (2) the fixture check over the sixteen M1 pairs and the eight leak-exposing pairs on the referee (`delivered_digests_equal_until_knowable`), each pair writing `target/conformance/twins/<archetype>-<kind>.json` (kind, hidden change, episode scope, `knowable_from` resolved to an instant in quanta, decisions before it, both truth digests, the two stream-registry digests, and the delivered-observation digests at the last decision before `knowable_from` and the first after it), which the script logs as `metric` lines and asserts: truth digests differ, registry digests equal (or, for `Retile`, differ only in the retiled region's streams), decisions before `knowable_from` ≥ 100, delivered digests equal before and different after; (3) the bad twins (`e2e_expect_caught` each: a change inside a sensor's range gate, an added entity, a persistent offset step) and the planted sequential-stream constructor. Log: `target/e2e-logs/sense_twins/<utc>.ndjson` with a transcript; each `cmd` with the exact command line, exit code and wall time; on failure the pair, the first decision at which the delivered digests differ too early and the fixture path needed to reproduce; a `summary` with pairs checked, assertions passed and failed and `gates: ["GATE-SENS-12"]` (touched, never recorded). The pairs are then run through the verb by BD-119's script and, on every archetype and tier, by N20b-11's.
### Known answers and negative controls
KA-497 (the causal-policy test's known answer uses these twins); metamorphic relation MR-18 (control: a policy that reads truth behind an undelivered sensor); KA-476 (a packet arriving at t is visible at t; one quantum later it is not), which the delayed-measurement twin relies on. Planted failure: the sequential-stream constructor. Determinism: twin construction identical across platforms; each pair's runs twice on one machine.

## Considerations
- The reach computation for the first kind is conservative; if it cannot certify a region as unreachable it refuses to build the twin instead of guessing.
- Some controllers never look at certain channels; a twin kind that cannot matter to a controller still must produce at least 100 compared decisions, or the test reports that kind as vacuous for that controller.
- The delayed-measurement twin needs per-packet latency overrides, which the link model's laws do not offer; the `latency_override` field is test-only and recorded in the world identity, so a run that uses it is never mistaken for one under the plain card.
- The reach computation for terrain uses ranging sensors only where a design has them; when BD-187 brings lidar and height scans at M2, the same fixtures gain a ray term and are rebuilt, and `FirstOf` keeps the knowable event correct for both kinds of design.
- The actor's wider information contract (rewards, `info` fields, masks, termination flags delivered to an actor) adds twin needs later; the `HiddenChange` enum is open for them.
