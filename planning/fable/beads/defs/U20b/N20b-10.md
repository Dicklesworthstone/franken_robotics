## Background
The causal-policy test (BD-119) claims to detect any way in which the simulator hands a policy information it could not yet have. A test like that needs negative controls: defects planted on purpose that it must catch, because a gate that nothing can fail validates nothing. The chapter names five, and every one is a defect that has occurred in real learned-control stacks:

1. a **privileged state channel** wired into the actor's input;
2. a **reset mask** that lets history cross an episode boundary;
3. a **sensor read at its current value** instead of from its delivered packet;
4. a **curriculum parameter** passed as an observation;
5. a **noise stream keyed so that a hidden parameter shifts the draws** of a visible sensor.

The same section fixes the rule the leaks violate. Truth, measurements, belief and policy observations are four namespaces with declared access (ADR-SENS-09), "the commonest silent defect in learned control is a leak of simulator truth". An asymmetric critic may read privileged state during training under a schema marked training-only. **The actor's inference schema is frozen, and the test runs with the privileged channels physically absent, not zeroed.** Absent means the buffers are not allocated or bound for the run, so a read fails by construction; zeroed would let a leak hide (a policy that multiplies a zeroed channel by a weight behaves the same, and a wiring that reads the real channel in production would never be seen). Invariant INV-SENS-07: the actor's inference input contains no privileged channel. Refusal FROB-REF-442 covers an actor schema that names a privileged channel.

Tier: Solid. Owner: `frob-sense`, with the fixtures in `frob-conformance`.

## Scope
In: the leak registry; the five leaks as defective actors or defective environment wirings, each selectable by a conformance feature; for each leak the twin kind that exposes it and the expected report; the absent-channel runner (the conformance harness that executes an actor under the frozen schema with the privileged buffers not allocated); the fixtures that trigger the schema-time refusal FROB-REF-442 (privileged-channel half).
Out: the namespace types, the `ActorSchema` type with `freeze_actor_schema`, the absent execution mode of the observation service and the definition of the schema-time refusal (N20a-03, a dependency; the type sketch in the Technical approach below restates them for the reader, and N20a-03 governs wherever the two differ); the test procedure and verb (BD-119); the twins (N20b-09); the four extra leaks of the actor's information contract, `leak.cortex.1` to `leak.cortex.4` (previous reward wired into the actor, an `info` field carrying a hidden parameter, an action mask computed from hidden state, a termination flag delivered before its instant), built by N23b-32 under the same feature `conformance-leaks`, selected through the same `--control` option and measured by GATE-CORTEX-19, whose four control records the seeding tool of N38b-05 writes from N23-CX's catalogue entry (this bead writes no row for them); the presentation-state half of FROB-REF-442 (raised at registration by the observation service, N20a-01; asserted on every tier by BD-215).

## Technical approach
**Namespaces and the frozen schema (restated from N20a-03, which owns and implements them in `frob-sense`; this bead adds only the runner type `ActorRun`, in `frob-conformance`).**
```rust
// DESIGN. Fixes intent, not signatures. Namespace, ChannelId, ActorSchema and freeze_actor_schema are N20a-03's.
pub enum Namespace { Truth, Measurement, Belief, PolicyObs }
pub struct ActorSchema { channels: Vec<ChannelId>, digest: Digest }           // frozen: built once, content-addressed
pub fn freeze_actor_schema(/* N20a-03 */) -> Result<ActorSchema, Refusal>;
pub struct ActorRun<'a> { schema: &'a ActorSchema, bound: BoundBuffers }      // this bead: only channels of the schema are bound
```
`freeze_actor_schema` refuses with **FROB-REF-442** (second clause, "an actor schema names a privileged channel"; exit 3) when a channel offered for the actor schema is privileged by source (the truth namespace; a belief or measurement channel whose producer had privileged inputs; a task or curriculum parameter; a reward or termination signal) or is not of actor access; ranked repairs from N20-REF: use the observation service (name the delivered-packet channel instead); move the channel to the training-only schema. `ActorRun` is the absent-channel runner: it builds the actor's environment through N20a-03's physically-absent execution mode and binds exactly the buffers of the schema's channels; no handle to any other buffer exists in the actor's context, on any tier. The schema digest is part of the policy identity, so a policy cannot be evaluated under a different schema than it was frozen with. This bead's fixtures (below and in the tests) exercise that refusal; they do not define it.

**Leak registry (`crates/frob-conformance/registry/controls.toml`, five records, open for more).** Each leak is one `[[control]]` record of BD-025's schema, whose loader accepts only identifiers `NC-` plus four digits, append-only: an `NC-nnnn` identifier allocated at registration; `gate = ["GATE-SENS-12"]`; `seed = "KA-497"`; `kind = "mutation"`; `feature = "conformance-leaks"` (the Cargo feature that builds it); `target = "sense.causal-test --control leak.sens.N"`, where `leak.sens.1` … `leak.sens.5` is the handle the verb's `--control` option accepts (BD-119, N20b-11); `defect` (the planting below); `expect` (the exposing twin kinds, the expected failure kind and channel, the invariant violated). The control runner (N38b-04) applies a leak by running the verb on a build with that feature, with `--control` and the exposing twin, and records `caught` only when the report matches `expect`.

| Leak | How it is planted (DESIGN) | Exposed by twin | Expected report | Violates |
|---|---|---|---|---|
| L1 privileged channel | A baseline controller variant whose input vector has extra elements bound to privileged truth that depends on the hidden quantity itself, obtained through a test-only back door that bypasses `freeze_actor_schema`: the true friction coefficient of the untouched patch ahead, and a privileged true height map of unlimited range. (True base velocity or the friction under the foot would not do: they differ between the twins only at or after first contact, which is `knowable_from`, so the leak would never act before it.) | Untouched friction (the friction element); terrain beyond reach (the height-map element) | failure kind `causality`; channel `truth.*`; a decision before `knowable_from` | INV-SENS-07 |
| L2 reset mask | The controller keeps an observation-history buffer (or recurrent state) that the reset path fails to clear for worlds that ended, so episode k + 1 starts with episode k's history | Later-phase parameter with `episodes: Only(k)` (N20b-09): the two worlds differ only in episode k and are identical in episode k + 1; caught because the test's digests restart at each reset (BD-119) | failure kind `causality`; channel `policy-state`; first decision of episode k + 1 | INV-SENS-02 (a decision depends only on what was delivered in its own episode's history) |
| L3 current-value read | The observation map reads a sensor's latest sample buffer instead of the queue of delivered packets, so latency and loss are bypassed | Delayed measurement | failure kind `causality`; the channel of that sensor; the decision at which the undelivered packet's value first appears (before its arrival, which is `knowable_from`) | INV-SENS-02 |
| L4 curriculum parameter | The task's difficulty level (or a randomization parameter such as payload mass) is appended to the observation vector | Later-phase parameter; untouched friction | failure kind `causality`; channel `task.curriculum`; a decision before `knowable_from` | INV-SENS-07 |
| L5 keyed-by-order noise | The noise of a visible sensor is drawn from a sequential per-world stream that a hidden parameter's own draw precedes, so the hidden value's presence or the number of draws it consumes shifts the visible sensor's noise | Untouched friction built as a `Retile` twin (N20b-09): the untouched patch has a different number of tiles, so the number of draws changes | failure kind `premature-delivery` (the delivered bytes themselves differ before `knowable_from`; the actor is not at fault); the visible sensor's channel, from its first sample | INV-SENS-06; ADR-SENS-10 |

Each leak is a small, real component (a controller wrapper or an alternate observation map), compiled only under `--features conformance-leaks`, never present in a release binary; a build check asserts the feature is off in release profiles.

**Reference behaviour without leaks.** The unmodified baseline controllers are the reference actors at M1: with no leak selected, every twin gives equal command digests wherever delivered digests agree.

**Why absent, tested.** A fixture policy `reads_zeroed_channel` multiplies a declared-but-privileged channel into its output. Under a zeroing runner it passes; under the absent-channel runner it cannot be constructed (FROB-REF-442). The fixture exists to show the difference and to keep the zeroing shortcut from returning.

## Acceptance criteria
- [ ] `ActorRun` exists in `frob-conformance` on N20a-03's absent execution mode; this bead's fixture schemas (a truth channel, a training-only channel, a curriculum parameter) are refused by N20a-03's `freeze_actor_schema` with FROB-REF-442 and both repairs in order (unit tests below); the user-side leg, exit 3 through `sense.causal-test --actor-schema`, is step 5 of BD-119's script, since BD-119 depends on this bead.
- [ ] No API in the actor's context can obtain a buffer outside its schema (a compile-fail test and a runtime test on the referee).
- [ ] The five leaks are registered in `controls.toml` as `NC-` records that pass BD-025's loader validation, each naming its `leak.sens.N` handle in `target`, its feature, exposing twins and expected report; each builds and runs on the referee.
- [ ] Each leak is shown to be real directly on digests (episode-scoped, as BD-119 records them), before the test is judged on it: for L1, L3 and L4 the delivered-observation digests of the exposing twin agree before `knowable_from` while the command digests differ at some such decision; for L2 the delivered digests of episode k + 1 agree from its first decision while the command digests differ at that decision; for L5 the delivered-observation digests differ before `knowable_from` (the leak changes what is delivered), and with the leak off they agree.
- [ ] With no leak selected, command digests agree on all sixteen twin fixtures.
- [ ] The release-profile check fails the build if `conformance-leaks` is enabled.
- [ ] The zeroed-channel fixture is constructible only under the (test-only) zeroing runner and refused under the real one.
- [ ] `CONTRACT.md` states INV-SENS-07 and ADR-SENS-09 and lists the registry.
- [ ] `scripts/e2e/sense_leaks.sh` exits 0, with the five leak findings logged against their `expect` and the release build with the feature caught.

## Test plan
### Unit tests
(`cargo test -p frob-conformance leaks::schema_fixtures`, `cargo test -p frob-conformance --features conformance-leaks leaks::`)
- `fixture_truth_channel_refused_442`; `fixture_training_only_channel_refused_442`; `fixture_curriculum_param_refused_442`: the fixture schemas through N20a-03's freeze (N20a-03's own unit tests cover the freeze itself).
- `actor_run_binds_only_schema_channels`.
- `leak1_privileged_changes_command_before_knowable`, `leak3_current_value_changes_command_before_knowable`, `leak4_curriculum_changes_command_before_knowable`: on their exposing twins.
- `leak1_reads_hidden_quantity_itself`: the privileged elements differ between the twins at decision 0.
- `leak5_keyed_noise_changes_delivery_before_knowable`: on the `Retile` twin, the visible sensor's first delivered packet differs.
- `no_leak_commands_agree_all_twins`; `no_leak_deliveries_agree_before_knowable` (including the `Retile` and `Only(k)` twins).
- `leak2_needs_two_episodes`: the difference appears at the first decision of the second episode and not before; with the reset path fixed, the second episode's commands agree.
- `leak5_fires_only_when_draw_count_changes`: with a hidden change that keeps the draw count, the sequential stream does not shift and the fixture is inert (documents the fixture's construction).
- `release_profile_rejects_leak_feature`.
- `leak_records_pass_control_loader`: the five records load through `frob_conformance::controls::validate` with no error; a record written with the identifier `leak.sens.1` instead of an `NC-` number is rejected.
- `zeroing_hides_leak_absent_refuses`.
### End-to-end script and logging
`scripts/e2e/sense_leaks.sh` (this bead's own script; sources the STD-E2E helper; it calls only cargo targets of this bead and its dependencies, because the verb that applies a leak, BD-119, depends on this bead). Steps: (1) `cargo test -p frob-conformance leaks::schema_fixtures` (the three fixture schemas refused with 442 through N20a-03's freeze); (2) `cargo test -p frob-conformance --features conformance-leaks leaks::` on the referee: each leak is real on episode-scoped digests on its exposing twin, and the no-leak runs agree; each test writes its finding to `target/conformance/leaks/<leak>.json` (twin kind, hidden change, episode, the first decision index at which command digests differ or, for L5, the first differing delivered packet's sensor and sequence number, `knowable_from`, the digests of both worlds), which the script logs as `metric` lines against the registry's `expect`; (3) the five `NC-` records load through BD-025's validator (`leak_records_pass_control_loader`) and the planted record with identifier `leak.sens.1` is rejected; (4) the release-profile check: `cargo build -p frob --release --features frob-conformance/conformance-leaks` must fail with the check's message (`e2e_expect_caught release-with-leaks`). Log: `target/e2e-logs/sense_leaks/<utc>.ndjson` with a transcript: each `cmd` with the exact command line, exit code and wall time; per leak the expected and observed failure kind, channel, episode and decision index; on a mismatch the leak, the two digests and the fixture path needed to reproduce; a `summary` with assertions passed and failed and `gates: ["GATE-SENS-12"]` (touched, never recorded). The verb-level form, `frob sense causal-test --control leak.sens.N`, is run by BD-119's script and, on every archetype and tier, by N20b-11's.
### Known answers and negative controls
KA-497's control: each of the five planted leaks fails the causal-policy test. These fixtures *are* the negative controls of GATE-SENS-12; their own control is the no-leak run, which must pass. CX-215 (a noise generator that hands out draws in call order) is leak 5 in another setting. Determinism: each leak's failing decision instant is the same on repeated runs with the same seed.

## Considerations
- The registry is open: the learning chapter's information-contract rule adds four leaks (reward, `info`, action mask, early termination flag) as `leak.cortex.1` to `leak.cortex.4` (N23b-32, GATE-CORTEX-19); they use the same record format, the same feature, the same `--control` option and the same runner, and their handles never reuse the `leak.sens.` prefix.
- The test-only back door of leak 1 is itself a hazard; it lives in `frob-conformance`, not in `frob-sense`, and the layer check forbids any other crate from depending on it.
- A learned policy at M2 replaces the baseline controllers as the reference actor; the leaks are then applied to the policy's observation map rather than to a controller wrapper, with the same registry identifiers.
