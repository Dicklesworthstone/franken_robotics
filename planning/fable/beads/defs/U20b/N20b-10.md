## Background
The causal-policy test (BD-119) claims to detect any way in which the simulator hands a policy information it could not yet have. A test like that needs negative controls: defects planted on purpose that it must catch, because a gate that nothing can fail validates nothing. The chapter names five, and every one is a defect that has occurred in real learned-control stacks:

1. a **privileged state channel** wired into the actor's input;
2. a **reset mask** that lets history cross an episode boundary;
3. a **sensor read at its current value** instead of from its delivered packet;
4. a **curriculum parameter** passed as an observation;
5. a **noise stream keyed so that a hidden parameter shifts the draws** of a visible sensor.

The same section fixes the rule the leaks violate. Truth, measurements, belief and policy observations are four namespaces with declared access (ADR-SENS-09), "the commonest silent defect in learned control is a leak of simulator truth". An asymmetric critic may read privileged state during training under a schema marked training-only. **The actor's inference schema is frozen, and the test runs with the privileged channels physically absent, not zeroed.** Absent means the buffers are not allocated or bound for the run, so a read fails by construction; zeroed would let a leak hide (a policy that multiplies a zeroed channel by a weight behaves the same, and a wiring that reads the real channel in production would never be seen). Invariant INV-SENS-07: the actor's inference input contains no privileged channel. Refusal FROB-REF-442 covers an actor schema that names a privileged channel.

Tier: Solid. Owner: `frob-sense`, with the fixtures in `frob-conformance`.

## Scope
In: the leak registry; the five leaks as defective actors or defective environment wirings, each selectable by a conformance feature; for each leak the twin kind that exposes it and the expected report; the absent-channel runner (the conformance harness that executes an actor under the frozen schema with the privileged buffers not allocated); the fixtures that trigger the schema-time refusal FROB-REF-442 (privileged-channel half).
Out: the namespace types, the `ActorSchema` type with `freeze_actor_schema`, the absent execution mode of the observation service and the definition of the schema-time refusal (N20a-03, a dependency; the type sketch in the Technical approach below restates them for the reader, and N20a-03 governs wherever the two differ); the test procedure and verb (BD-119); the twins (N20b-09); the four extra leaks of the actor's information contract (registered here by the learning unit, measured by its own gate); the presentation-state half of FROB-REF-442 (BD-215).

## Technical approach
**Namespaces and the frozen schema (DESIGN, `crates/frob-sense/src/causal/schema.rs`).**
```rust
// DESIGN. Fixes intent, not signatures.
pub enum Namespace { Truth, Measurement, Belief, PolicyObservation }
pub enum Access { Actor, TrainingOnly /* critic-only */, EvaluationOnly }
pub struct ChannelDecl { id: ChannelId, namespace: Namespace, access: Access, source: ChannelSource /* packet of sensor s | estimator output | task term */ }
pub struct ActorSchema { channels: Vec<ChannelId>, digest: Digest }           // frozen: built once, content-addressed
pub fn freeze_actor_schema(decls: &[ChannelDecl], wanted: &[ChannelId]) -> Result<ActorSchema, Refusal>;
pub struct ActorRun<'a> { schema: &'a ActorSchema, bound: BoundBuffers }      // only channels of the schema are bound
```
`freeze_actor_schema` refuses with **FROB-REF-442** if any wanted channel has `namespace: Truth` or `access` other than `Actor`: "an actor schema names a privileged channel"; ranked repairs: use the observation service (name the delivered-packet channel instead); move the channel to the training-only schema. Exit 3. `ActorRun` binds exactly the buffers of the schema's channels; no handle to any other buffer exists in the actor's context, on any tier. The schema digest is part of the policy identity, so a policy cannot be evaluated under a different schema than it was frozen with.

**Leak registry (`crates/frob-conformance/registry/controls.toml`, entries `leak.sens.1` … `leak.sens.5`, open for more).** Each entry: identifier, description, the conformance feature that builds it, the twin kinds that expose it, the expected failing channel in the test report, and the invariant it violates.

| Leak | How it is planted (DESIGN) | Exposed by twin | Expected report | Violates |
|---|---|---|---|---|
| L1 privileged channel | A baseline controller variant whose input vector has one extra element bound to true base velocity (or true friction under the foot), obtained through a test-only back door that bypasses `freeze_actor_schema` | Untouched friction; terrain beyond reach | channel `truth.*`; first decision after the hidden value influences the truth channel | INV-SENS-07 |
| L2 reset mask | The controller keeps an observation-history buffer (or recurrent state) that the reset path fails to clear for worlds that ended, so episode k + 1 starts with episode k's history | Later-phase parameter, arranged so the two worlds differ only in episode k and are identical in episode k + 1 | channel `policy-state`; first decision of episode k + 1 | INV-SENS-02 (a decision depends only on what was delivered in its own episode's history) |
| L3 current-value read | The observation map reads a sensor's latest sample buffer instead of the queue of delivered packets, so latency and loss are bypassed | Delayed measurement | the channel of that sensor; the decision at which the undelivered packet's value first appears | INV-SENS-02 |
| L4 curriculum parameter | The task's difficulty level (or a randomization parameter such as payload mass) is appended to the observation vector | Later-phase parameter; untouched friction | channel `task.curriculum` | INV-SENS-07 |
| L5 keyed-by-order noise | The noise of a visible sensor is drawn from a sequential per-world stream that a hidden parameter's own draw precedes, so the hidden value's presence or the number of draws it consumes shifts the visible sensor's noise | Untouched friction built so that the hidden change alters the number of draws (a patch with a different number of tiles) | the visible sensor's channel, from the first sample | INV-SENS-06; ADR-SENS-10 |

Each leak is a small, real component (a controller wrapper or an alternate observation map), compiled only under `--features conformance-leaks`, never present in a release binary; a build check asserts the feature is off in release profiles.

**Reference behaviour without leaks.** The unmodified baseline controllers are the reference actors at M1: with no leak selected, every twin gives equal command digests wherever delivered digests agree.

**Why absent, tested.** A fixture policy `reads_zeroed_channel` multiplies a declared-but-privileged channel into its output. Under a zeroing runner it passes; under the absent-channel runner it cannot be constructed (FROB-REF-442). The fixture exists to show the difference and to keep the zeroing shortcut from returning.

## Acceptance criteria
- [ ] `freeze_actor_schema` and `ActorRun` exist; an actor schema naming a truth or training-only channel is refused with FROB-REF-442 and both repairs; exit 3 through any verb that builds a schema.
- [ ] No API in the actor's context can obtain a buffer outside its schema (a compile-fail test and a runtime test on the referee).
- [ ] The five leaks are registered in `controls.toml` with feature names, exposing twins and expected reports; each builds and runs on the referee.
- [ ] With each leak selected, the delivered-observation digests of its exposing twin still agree before `knowable_from` (the leak does not change what was delivered) while the command digests differ at some such decision: the property the test must detect, asserted here directly on digests so that the fixture is known to be a real leak before the test is judged on it.
- [ ] With no leak selected, command digests agree on all sixteen twin fixtures.
- [ ] The release-profile check fails the build if `conformance-leaks` is enabled.
- [ ] The zeroed-channel fixture is constructible only under the (test-only) zeroing runner and refused under the real one.
- [ ] `CONTRACT.md` states INV-SENS-07 and ADR-SENS-09 and lists the registry.

## Test plan
### Unit tests
(`cargo test -p frob-sense causal::schema`, `cargo test -p frob-conformance --features conformance-leaks leaks::`)
- `actor_schema_refuses_truth_channel_442`; `actor_schema_refuses_training_only_channel_442`.
- `actor_run_binds_only_schema_channels`.
- `leak1_privileged_changes_command_before_knowable` … `leak5_keyed_noise_changes_command_before_knowable`: five tests, one per leak, each on its exposing twin.
- `no_leak_commands_agree_all_twins`.
- `leak2_needs_two_episodes`: the difference appears at the first decision of the second episode and not before.
- `leak5_fires_only_when_draw_count_changes`: with a hidden change that keeps the draw count, the sequential stream does not shift and the fixture is inert (documents the fixture's construction).
- `release_profile_rejects_leak_feature`.
- `zeroing_hides_leak_absent_refuses`.
### End-to-end script and logging
Run from `scripts/e2e/sense_causal_test.sh` (N20b-11) with `frob sense causal-test --control leak.sens.N` on a binary built with the conformance feature; the log records per leak the expected and reported channel and decision instant, in the STD-E2E format.
### Known answers and negative controls
KA-497's control: each of the five planted leaks fails the causal-policy test. These fixtures *are* the negative controls of GATE-SENS-12; their own control is the no-leak run, which must pass. CX-215 (a noise generator that hands out draws in call order) is leak 5 in another setting. Determinism: each leak's failing decision instant is the same on repeated runs with the same seed.

## Considerations
- The registry is open: the learning chapter's information-contract rule adds four leaks (reward, `info`, action mask, early termination flag) with their own gate; they use the same entry format and the same runner.
- The test-only back door of leak 1 is itself a hazard; it lives in `frob-conformance`, not in `frob-sense`, and the layer check forbids any other crate from depending on it.
- A learned policy at M2 replaces the baseline controllers as the reference actor; the leaks are then applied to the policy's observation map rather than to a controller wrapper, with the same registry identifiers.
