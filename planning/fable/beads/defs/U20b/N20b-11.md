## Background
GATE-SENS-12 (Known answer; TARGET): "Causal-policy test: the reference actor and every baseline controller pass; each of the five planted leaks fails." The gate register places it at M1 on the CPU and at M2 on every tier, because the first mission slice at M1 reasons about what a controller can know and must be able to trust that its controllers are causal.

The causal-policy test runs a world and a twin that differs only in something the policy cannot yet know (terrain beyond every sensor's reach or after the decision time; the friction of a surface not yet touched; a measurement whose packet is delayed past the decision; a randomization parameter of a later phase), records at every decision instant a digest of the bytes delivered so far and a digest of the command, and requires the command digests to agree wherever the delivered digests agree. The five planted leaks that must each fail: a privileged state channel wired into the actor's input; a reset mask that lets history cross an episode boundary; a sensor read at its current value instead of from its delivered packet; a curriculum parameter passed as an observation; a noise stream keyed so that a hidden parameter shifts the draws of a visible sensor.

This bead is the user-side script that measures the gate through the real `frob` binary. It takes the tier as an argument so that the same script records the M1 referee rows and, once the batched form exists (N20b-12, BD-215), the rows for `batch-cpu`, CUDA and Metal. One script for all tiers is a DESIGN choice: the gate says "every tier", and two scripts would be two chances to test different things.

## Scope
In: the script, its assertions, its structured log, the gate receipt. Out: the test, twins and leaks themselves.

## Technical approach
**Script.** `scripts/e2e/sense_causal_test.sh [--tier referee|batch-cpu|cuda|metal] [--archetypes quad-mammal,humanoid,diff-drive,mecanum] [--seed 1200] [--min-compared 100]`. Plain shell, real binary, idempotent, seed-explicit, non-zero exit on any failed assertion. The leak steps need the binary built with the conformance feature; the script checks `frob doctor --json` for the feature and fails with a clear message if a leak step is requested on a release build.

**Steps.**
1. For each archetype: `frob control synth <design> --json` (the baseline controller identity), then `frob sense causal-test <design> --controller <id> --task flat-velocity --twins all --tier <tier> --seed <seed> --json`. Assert: exit 0, `verdict: "pass"`, every twin kind has `decisions_compared ≥ 100` and `failures: 0`.
2. For each leak N in 1…5: `frob sense causal-test <design> --controller <id> --control leak.sens.N --twins all --tier <tier> --seed <seed> --json`. Assert: exit 2, `verdict: "fail"`, the reported channel equals the registry's expected channel for leak N (`truth.*`; `policy-state`; the delayed sensor's channel; `task.curriculum`; the visible sensor's channel), and the failing decision precedes the twin's `knowable_from`.
3. Vacuity: run with a twin whose hidden change is immediately visible (a fixture built for this) and assert `verdict: "vacuous"`, exit 2.
4. Schema refusal: `frob sense causal-test … --actor-schema fixtures/…/names_truth_channel.json`: assert `ok: false`, FROB-REF-442, exit 3, both repairs present.
5. Recorder neutrality: run one baseline world with and without `--record-causal` and assert equal physics digests and equal delivered-observation digests (`frob telemetry summary --json` digests).
6. At M2 and later, when `--tier` is not `referee`: additionally run the reference learned actor (`--policy <id>` of the reference quadruped task) and assert `pass`.

**Gate record.** A hash-named receipt under `target/e2e-logs/sense_causal_test/`: tier, controllers and policies tested, twin kinds, decisions compared per kind, leaks failed (must be 5 of 5), vacuity check, commit, fingerprint, seed. The recording session enters it in `registries/gates.toml` under GATE-SENS-12, one row per tier. `cargo test -p frob-conformance --test g3 -- gate_sens_12` wraps the script.

**Logging (STD-E2E).** `target/e2e-logs/sense_causal_test/<utc>.ndjson` plus a transcript. Every line: `ts`, `script`, `bead` (`N20b-11`), `step`, `event`. `cmd`: exact command line, exit code, wall time, the envelope's evidence block (claim, class, tier, determinism, identities, seed). `metric`: per twin kind the pairs run and decisions compared against the threshold 100; for leaks the failing decision index, instant (quanta and seconds) and channel against the expected channel. `refusal`: code FROB-REF-442, pointer, repairs. `assert`: expected and observed. On failure: the first unexpected verdict, both command digests, and the two episode paths needed to reproduce. `summary`: assertions passed and failed; `gates: ["GATE-SENS-12"]`; the tier.

## Acceptance criteria
- [ ] The script runs to exit 0 on a correct conformance build on the referee for the four M1 archetypes.
- [ ] All baseline controllers pass non-vacuously; each of the five leaks fails with its expected channel; the vacuous fixture reports `vacuous`; the privileged schema is refused with FROB-REF-442.
- [ ] The recorder-neutrality step shows identical digests.
- [ ] Running the script against a build in which the test's comparison is disabled (a conformance feature `causal-compare-off`) makes step 2 fail the script: the script's own negative control.
- [ ] The referee row of GATE-SENS-12 is recorded with measured counts; later tiers add rows through the same script.
- [ ] The same seed gives identical `metric` lines on a second run.

### Known answers and negative controls
KA-497 (exact; control: each of five planted leaks fails). KA-476 underlies the delayed-measurement twin. Metamorphic relation MR-18. Planted failures: the five leaks; the comparison-off build. Determinism lanes: the script's metrics twice on one machine; on batched tiers across worker counts and, for the verdicts, across backends (verdicts and failing decision indices are integers and must be equal on every tier).

## Considerations
- The leak fixtures exist only in conformance builds; the gate receipt records the build's feature set so nobody mistakes a release build's "pass on baselines" for the whole gate.
- On a tier with a `hold` intra-step policy the decision instants are realized at boundaries; the failing decision index of a leak is the same integer across tiers because decisions are counted, not timed.
- Runtime (TARGET): under three minutes on the referee for the M1 set.
