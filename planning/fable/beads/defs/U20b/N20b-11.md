## Background
GATE-SENS-12 (Known answer; TARGET): "Causal-policy test: the reference actor and every baseline controller pass; each of the five planted leaks fails." The gate register places it at M1 on the CPU and at M2 on every tier, because the first mission slice at M1 reasons about what a controller can know and must be able to trust that its controllers are causal.

The causal-policy test runs a world and a twin that differs only in something the policy cannot yet know (terrain beyond every sensor's reach or after the decision time; the friction of a surface not yet touched; a measurement whose packet is delayed past the decision; a randomization parameter of a later phase), records at every decision instant a digest of the bytes delivered so far and a digest of the command, and requires the command digests to agree wherever the delivered digests agree. The five planted leaks that must each fail: a privileged state channel wired into the actor's input; a reset mask that lets history cross an episode boundary; a sensor read at its current value instead of from its delivered packet; a curriculum parameter passed as an observation; a noise stream keyed so that a hidden parameter shifts the draws of a visible sensor.

This bead is the user-side script that measures the gate through the real `frob` binary. It takes the tier as an argument so that the same script records the M1 referee rows and, once the batched form exists (N20b-12, BD-215), the rows for `batch-cpu`, CUDA and Metal. One script for all tiers is a DESIGN choice: the gate says "every tier", and two scripts would be two chances to test different things.

## Scope
In: the script, its assertions, its structured log, the gate receipt. Out: the test, twins and leaks themselves.

## Technical approach
**Script.** `scripts/e2e/sense_causal_test.sh [--tier referee|batch-cpu|gpu-cuda|gpu-metal] [--archetypes quad-mammal,humanoid,diff-drive,mecanum] [--seed 1200] [--seeds 1] [--min-compared 100]` (`--seed` is the helper's seed and the `FROB_TEST_SEED` of step 8; `--seeds` is passed to the verb, whose row has `--seeds <n>` and no `--seed`). Plain shell, real binary, idempotent, seed-explicit, non-zero exit on any failed assertion. The leak steps need the binary built with the conformance feature; the script checks `frob doctor --json` for the feature and fails with a clear message if a leak step is requested on a release build.

**Steps.**
0. On the referee: BD-119's own script `scripts/e2e/sense_causal_test_verb.sh` as a stage (the verb's default form, one leak per localization outcome, vacuity, the 442, 440 and 441 refusals, `--no-record`, the MCP wait, the release-build refusal); its `summary` must report zero failed assertions, and its log path is logged here.
1. For each archetype: `frob control synth <design> --key ct-ctl-<archetype> --json` (the baseline controller identity; `control.synth` is a `run` verb), then `frob sense causal-test <design> --controller <id> --task causal-<archetype> --twin-fixtures crates/frob-conformance/fixtures/sensorium/causal/<archetype>/ --tier <tier> --seeds <n> --key ct-<archetype>-<tier> --json` (the committed fixture tasks and twin pairs of N20b-09, including the two-episode and `Retile` pairs). Assert: exit 0, `verdict: "pass"`, every twin kind has `decisions_compared ≥ 100` and no failure of either kind. Then the registry's own example form, `frob sense causal-test <design> --task causal-<archetype> --key ct-d-<archetype> --json` (default controller, `--twins all`): assert it resolves the same controller and passes.
2. For each leak N in 1…5: `frob sense causal-test <design> --controller <id> --task causal-<archetype> --twin-fixtures … --control leak.sens.N --tier <tier> --seeds <n> --key ct-L<N>-<archetype>-<tier> --json`. Assert: exit 2, `verdict: "fail"`, and the reported failure kind and channel equal the registry's expectation for leak N: L1 `causality` on `truth.*`, L3 `causality` on the delayed sensor's channel and L4 `causality` on `task.curriculum`, each at a decision before the twin's `knowable_from`; L2 `causality` on `policy-state` at the first decision of the episode after the one in which the worlds differ; L5 `premature-delivery` on the visible sensor's channel, before `knowable_from`.
Steps 3 to 6 run on tiers other than the referee, where stage 0 covers them.
3. Vacuity: run with a twin whose hidden change is immediately visible (a fixture built for this) and assert `verdict: "vacuous"`, exit 2.
4. Schema refusal: `frob sense causal-test … --actor-schema fixtures/…/names_truth_channel.json`: assert `ok: false`, FROB-REF-442, exit 3, both repairs present.
5. Recorder neutrality: run one baseline twin pair with and without the recorder (`--no-record`, BD-119) and assert equal physics digests and equal delivered-observation digests (from the two envelopes, and from `frob telemetry summary <run> --json` for the recorded run).
6. Release-build check: on a binary without the conformance feature, `frob sense causal-test … --control leak.sens.1` is refused with FROB-REF-802 (unknown parameter), exit 3. Skipped with `e2e_skip` when only a conformance build is available.
7. At M2 and later, when `--tier` is not `referee`: additionally run the reference learned actor (`--policy <id>` of the reference quadruped task) and assert `pass`.
8. Conformance row: KA-497 is a G3 row on every tier, and the Gauntlet has no `frob` verb (ADR-GAUNT-01), so the script runs `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --features conformance-leaks --test g3_metamorphic -- KA-497` (tiers and hash-named receipts N38a-02; the five registered leak controls applied by the control runner N38b-04 in the same run) and asserts on its receipt under `target/gauntlet/receipts/`: the row `pass`, and each of the five `NC-` leak controls `caught`. The verb-level counts of steps 1 and 2 are logged beside the receipt's.

**Gate record.** A hash-named summary under `target/e2e-logs/sense_causal_test/`: tier, controllers and policies tested, twin kinds, decisions compared per kind, leaks failed (must be 5 of 5), vacuity check, the step-8 receipt hash, commit, fingerprint, seed. The recording session enters GATE-SENS-12 in `registries/gates.toml` from the step-8 receipt (`cargo run -p frob-conformance --example record_gate -- --gate GATE-SENS-12 --receipt <hash>`, N38b-19) for the M1 (CPU) part, citing this script's log. The M2 (every-tier) part is recorded by BD-215 from the receipts of this same script run with `--tier batch-cpu|gpu-cuda|gpu-metal` once N20b-12 exists (one recorder per part).

**Logging (STD-E2E).** `target/e2e-logs/sense_causal_test/<utc>.ndjson` plus a transcript. Every line: `ts`, `script`, `bead` (`N20b-11`), `step`, `event`. `cmd`: exact command line, exit code, wall time, the envelope's evidence block (claim, class, tier, determinism, identities, seed). `metric`: per twin kind the pairs run, episodes and decisions compared against the threshold 100; for leaks the failure kind, episode, failing decision index, instant (quanta and seconds) and `knowable_from`, and the channel against the expected channel. `refusal`: code FROB-REF-442, pointer, repairs. `assert`: expected and observed. On failure: the first unexpected verdict, both command digests, and the two episode paths needed to reproduce. `summary`: assertions passed and failed; `gates: ["GATE-SENS-12"]`; the tier.

## Acceptance criteria
- [ ] The script runs to exit 0 on a correct conformance build on the referee for the four M1 archetypes.
- [ ] All baseline controllers pass non-vacuously; each of the five leaks fails with its expected failure kind and channel; the vacuous fixture reports `vacuous`; the privileged schema is refused with FROB-REF-442.
- [ ] The recorder-neutrality step shows identical digests.
- [ ] Running the script against a build in which the test's comparison is disabled (a conformance feature `causal-compare-off`) makes step 2 fail the script: the script's own negative control.
- [ ] The G3 run of KA-497 passes with its five leak controls `caught` on the receipt, and no step calls a `frob gauntlet …` or `frob gates …` command (ADR-GAUNT-01).
- [ ] The M1 (CPU) part of GATE-SENS-12 is recorded from that receipt with measured counts; later tiers produce their receipts through the same script, from which BD-215 records the M2 part.
- [ ] The same seed gives identical `metric` lines on a second run.

### Known answers and negative controls
KA-497 (exact; control: each of five planted leaks fails). KA-476 underlies the delayed-measurement twin. Metamorphic relation MR-18. Planted failures: the five leaks; the comparison-off build. Determinism lanes: the script's metrics twice on one machine; on batched tiers across worker counts and, for the verdicts, across backends (verdicts and failing decision indices are integers and must be equal on every tier).

## Considerations
- The leak fixtures exist only in conformance builds; the gate receipt records the build's feature set so nobody mistakes a release build's "pass on baselines" for the whole gate.
- On a tier with a `hold` intra-step policy the decision instants are realized at boundaries; the failing decision index of a leak is the same integer across tiers because decisions are counted, not timed.
- Runtime (TARGET): under three minutes on the referee for the M1 set.
