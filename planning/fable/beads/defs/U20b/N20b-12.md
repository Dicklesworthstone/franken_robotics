## Background
The causal-policy test (BD-119) runs on the referee at M1. Two statements in its definition are not yet met after M1. First, the gate GATE-SENS-12 is recorded on every tier at M2 (the gate register: "M1 (CPU); M2 (every tier)"): `batch-cpu`, CUDA and Metal as well as the referee. Second: "It runs on every policy before its first evaluation is recorded, and on the baseline controllers." Learned policies appear at M2 with the vectorized environment and on-device training; from then on a leak pays off in reported returns, which is exactly when the test must be mandatory and not something a careful agent remembers to run.

On batched tiers three things differ from the referee. Observations and commands are device buffers, so digests are computed in kernels. Worlds run in batches, so a twin pair can be two worlds of one batch, which is cheap and which relies on the property that a world does not depend on the batch it ran in. And decision instants are realized at step boundaries under the tier's intra-step policy, so "the decision at t" is a boundary index. Tier: Solid.

## Scope
In: device-side digests of delivered bytes, past commands and commands per world per decision; twin pairs as batch neighbours; the reference learned actor under test; the receipt store and the admission rule for evaluation; rows of GATE-SENS-12 for the batched tiers (recorded through the script of N20b-11, with BD-215 holding the every-tier record).
Out: the test's logic (BD-119); twins and leaks (N20b-09, N20b-10); the information-contract leaks of the learning chapter (its own gate); noninterference (BD-215).

## Technical approach
**Digests on device.** The exact-integer digest kernel `K-x-digest` folds raw bit patterns of a world's slabs into four `u32` words in slab order. The causal recorder applies it, per world and per decision, to: the delivered-observation slab of the actor (packets delivered at this boundary, in the total order arrival, sensor identifier, sequence number, with instants and masks), chained with the previous digest (the previous four words are folded first); the command slab; the per-channel actor-input slabs for localization. Digest words are per-world rows; no kernel reads another world's rows. The kernel is class `exact`, so its output is D0 on every backend: the same delivered bytes give the same digest on CPU, CUDA and Metal. The device digest is a tripwire classed `Tested`; on a reported failure the host recomputes BLAKE3 over the two worlds' recorded packets and commands to confirm before the verdict is `fail` (a digest collision must not produce a false failure, and a host confirmation costs two short replays).

**Twin pairs in a batch.** A batch of 2·P worlds holds P twin pairs: worlds 2i and 2i + 1 share a world address for every addressed stream that the hidden change does not touch, and differ in the hidden field (a scene variant slot, a parameter-row entry, a link-latency override, a later-phase parameter). Addresses are the pairing key, not slot indices, so the pairing survives compaction and sharding. Pairs with different twin kinds share one batch.

**Decision instants.** The recorder fires at stage 5 of the boundary ordering on every tier. Under `hold`, a decision whose nominal instant falls inside a step is realized at the first boundary at or after it, with lateness recorded; the comparison is by decision index, and both twins have the same clock lattice, so indices align exactly.

**The reference learned actor.** The policy trained on the reference quadruped's flat velocity task. Its frozen actor schema (N20b-10) is bound with privileged channels absent; the asymmetric critic's training-only channels are not allocated in the test run. The five leaks are applied to this policy's observation map with the same registry identifiers as at M1.

**Receipts and the admission rule (DESIGN).** A passing run writes a receipt to the ledger: key (actor identity: `ControllerId` or `PolicyId`; actor schema digest; `TaskId`; interface digest: sensor suite, cards, clocks, link models; tier), value (twin kinds run, decisions compared per kind, seeds, the run's evidence block, the verdict). Rule: **an evaluation record for a policy is not written unless a passing receipt exists for the same actor identity, schema digest, task and interface.** The evaluation verbs look up the receipt at admission. If none exists they run the test first when the caller's budget allows (`--auto-causal`, default on) and otherwise refuse. If the receipt's verdict is `fail` or `vacuous`, evaluation is refused, the failing channel is returned, and the repairs are: fix the observation wiring; move the channel to the training-only schema; add a twin kind for which the test is not vacuous. The refusal has no code in the chapter; until the registry owner assigns one in the evaluation-protocol family, the implementation uses a reserved registry slot named `causal-receipt-missing` and the load-time check that rejects unknown codes is satisfied by registering it (flagged in the unit's coverage file).
A receipt is invalidated by any change to its key: retraining (new `PolicyId`), a schema change, a sensor edit, a link-latency change, a task change.

**Baseline controllers.** They are tested once per controller identity and interface, and the receipt is cited by every run that uses the controller.

## Acceptance criteria
- [ ] On `batch-cpu`, CUDA and Metal the test's verdicts and failing decision indices equal the referee's for the M1 baseline set and the five leaks (integers, exact).
- [ ] The reference learned actor passes on every tier; each of the five leaks applied to its observation map fails with the expected channel.
- [ ] Device digests of identical delivered bytes are identical words on the three backends; a reported failure is confirmed by the host hash before the verdict is written.
- [ ] A world's digests are the same whether its twin pair runs alone (batch of 2) or inside a batch of 8,192 worlds.
- [ ] An evaluation of a policy with no receipt runs the test first or refuses; with a failing receipt it refuses and returns the channel; with a passing receipt it proceeds and cites the receipt identifier in its evidence block.
- [ ] Changing a link latency by one quantum invalidates the receipt.
- [ ] A training run may read training-only channels in the critic; the test run of the same policy has those buffers unallocated (asserted by inspecting the run's buffer manifest).
- [ ] Negative control: a build whose device digest omits the mask bytes passes a leak that differs only in masks on the device and is caught by the host confirmation step run in audit mode.
- [ ] Batched-tier rows of GATE-SENS-12 recorded through the script of N20b-11.

## Test plan
### Unit tests
(`cargo test -p frob-sense causal::batched`; device tests behind the backend features)
- `device_digest_matches_cpu_reference_words`: 10⁴ random packet slabs.
- `twin_pairs_by_address_survive_compaction`.
- `decision_indices_align_under_hold`: 400 Hz physics, 30 Hz policy: decisions realized at boundaries 0, 14, 27, 40 in both twins.
- `verdicts_equal_referee_each_backend`.
- `batch_size_independence_of_digests`: 2 against 8,192.
- `receipt_required_for_evaluation`; `failing_receipt_blocks_evaluation`; `receipt_invalidated_by_interface_change`.
- `critic_channels_unallocated_in_test_run`.
- `host_confirmation_catches_digest_omission`.
### End-to-end script and logging
`scripts/e2e/sense_causal_test.sh --tier batch-cpu|cuda|metal` (owned by N20b-11) for the gate rows, and `scripts/e2e/eval_requires_causal_receipt.sh` (this bead; sources the STD-E2E helper): trains or loads the reference policy, requests an evaluation with `--auto-causal off` and asserts the refusal, runs `frob sense causal-test`, requests the evaluation again and asserts success with the receipt cited, then edits a link latency and asserts the evaluation is refused again. Logs to `target/e2e-logs/eval_requires_causal_receipt/<utc>.ndjson` with a transcript: commands, exit codes, wall times, evidence blocks, `refusal` lines with the reserved code and repairs, the receipt identifier as a `metric`, and a summary naming GATE-SENS-12.
### Known answers and negative controls
KA-497 on all tiers (tier G3). KA-471 for the decision boundaries (0, 14, 27, 40). The batch property KA-508 (a world's delivered observations do not depend on its batch). Planted failures: the five leaks on the learned actor; the mask-omitting digest. Determinism lanes: twice on one machine; across worker counts; across backends for the integer outputs.

## Considerations
- If a device family cannot hold a controlled determinism class, twins as batch neighbours are still valid within one run, but cross-run comparison is not; the test then runs both twins in one batch always.
- The admission rule adds a short run before a policy's first evaluation; the receipt makes it once per policy and interface.
- `fast-training` runs (determinism class D4) produce weights only; the causal test runs on the re-evaluation profile, never inside such a run.
- The refusal code gap is a registry matter; the behaviour is fixed here.
