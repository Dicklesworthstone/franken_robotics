## Background
One small model exercises the clock contract, strict comparison, the alias witness and exact arithmetic together. It is the chapter's known answer with a closed-form boundary, and four other beads build on it: the finite game over causal histories in the mission chapter (BD-129), the late-packet alias witness (BD-134), the exact-integer kernel probe (BD-030) and the fixture on every backend at M2 (BD-190). This bead writes the fixture's product-side evaluator once, on the host, in exact rational arithmetic (determinism class D0), so that every consumer shares one definition (one fixture identity per physical case). The specification side (the derivation file, a reference model that calls no code under test, and the law suite generic over a `DockingSubject`) is the spec part N10b-08; this evaluator is that suite's first subject. Nothing about a real docking device follows from it.

**Model.** Position in metres, time in seconds. Three ticks of one second. x₀ = v₀ = 0. During tick k the acceleration is g·u_k, with a hidden gain g ∈ {1, 2} fixed for the episode and a command |u_k| ≤ U, for U in [½, 1]. The mission is (x₃, v₃) = (1, 0) exactly. The only informative packet is a reading of v₁ (the velocity after the first tick) with additive error in [−ε, +ε].

**If the packet arrives before the second command.** Write p = u₀. From v₃ = g·(p + u₁ + u₂) = 0 and x₃ = g·(2p + u₁) = 1, the terminal conditions force u₁ = 1/g − 2p and u₂ = p − 1/g. The command limits in both worlds leave 1 − U ≤ p ≤ (U + ½)/2. The reading lies in [p − ε, p + ε] if g = 1 and in [2p − ε, 2p + ε] if g = 2; the two required values of u₁ differ by ½, so the intervals must be disjoint, which is ε < p/2. Choosing the largest admissible p gives the exact boundary **ε < (U + ½)/4, equality excluded** (PO-SENS-06).

The inequality is a hardware design statement: tolerable sensor error is bought with actuator authority at a rate of one quarter, because the first command is also a probe. With U = ¾ and p = ¼ the commands are (¼, ½, −¾) for g = 1 and (¼, 0, −¼) for g = 2, both reaching (1, 0), and the tolerable error is below 1/8. With p = 5/8 it is below 5/16: a bolder probe buys a sensor two and a half times worse. At ε = 5/16 exactly, both worlds can report 15/16 while requiring u₁ = −¼ and u₁ = −¾: the strict predicate fails at equality.

**If the packet arrives after the third command is committed.** A causal controller issues one command vector in both worlds. The final position of a common vector is g·(2p + u₁), which cannot equal 1 for both gains. Every case is excluded. This is an alias witness whose cause is timing, not the absence of a sensor.

**Grid known answer.** On U = ½ + i/32 for i = 0…16 and ε = j/64 for j = 0…32, the boundary admits a cell exactly when 2j < 32 + i: 344 of 561 cells are admitted, 217 excluded, and nine lie exactly on the boundary (the even i). All 561 cells are excluded when the packet is late.

Tier: Solid. Owner: `frob-sense` with `frob-conformance`.

## Technical approach
**Layout.** `crates/frob-conformance/fixtures/docking/` (the grid definition and expected labels as data, generated by a script committed beside them and never regenerated from the code under test); `crates/frob-sense/src/fixtures/docking.rs` (the evaluator, usable by other crates' tests; it implements the trait `DockingSubject` of N10b-08's law suite); `docs/derivations/docking-fixture.md`, sections "Integer form" and "Timing rows". DESIGN: one derivation file per fixture. N10b-08 writes `docs/derivations/docking-fixture.md` with the model and the derivations of the boundary; an earlier draft of this bead put the same derivation in a second file, `docs/derivations/po_sens_06_docking_boundary.md`, which is not written: PO-SENS-06's derivation on file is that one file, and this bead adds to it only what the spec part does not state.

**Dynamics, exactly.** With unit ticks and piecewise-constant acceleration a_k = g·u_k: v_{k+1} = v_k + a_k and x_{k+1} = x_k + v_k + a_k/2. Hence v₁ = g·p, x₁ = g·p/2, v₂ = g·(p + u₁), x₂ = g·(3p/2 + u₁/2), v₃ = g·(p + u₁ + u₂), x₃ = g·(5p/2 + 3u₁/2 + u₂/2); imposing v₃ = 0 gives u₂ = −p − u₁ and x₃ = g·(2p + u₁). All quantities are rationals (`Ratio` over arbitrary-precision or `i128` integers; the grid needs only small denominators).

**Admission predicate in integers.** For U = a/b and ε = c/d with positive denominators, ε < (U + ½)/4 ⟺ 8·b·c < d·(2a + b). On the grid (a/b = (16 + i)/32, c/d = j/64) this is 2j < 32 + i. The comparison is strict; an implementation with ≤ admits the nine boundary cells and is the planted mutant.

**Limits, derived.** g = 1: |1 − 2p| ≤ U and |p − 1| ≤ U; g = 2: |½ − 2p| ≤ U and |p − ½| ≤ U; and |p| ≤ U. For U ∈ [½, 1] the binding ones are p ≥ 1 − U (from |p − 1| ≤ U) and p ≤ (U + ½)/2 (from |½ − 2p| ≤ U). The interval is non-empty exactly when U ≥ ½.

**Witness for an admitted cell (constructive).** Take p = (U + ½)/2. Decision rule on the reading y: if y < 3p/2 then g = 1 else g = 2 (the midpoint between p and 2p separates the intervals because p + ε < 3p/2 < 2p − ε when ε < p/2). Then issue u₁ = 1/g − 2p, u₂ = p − 1/g. The evaluator simulates both worlds at the interval end points and midpoint of the reading (the rule is piecewise constant, so end points suffice) and asserts (x₃, v₃) = (1, 0) exactly and |u_k| ≤ U.

**Exclusion for an excluded cell (packet on time).** For every p in [1 − U, (U + ½)/2], ε ≥ p/2, so y* = p + ε lies in both reading intervals; a policy maps y* to one u₁, and the two worlds need values differing by ½; and for p outside the interval some world violates a limit. The evaluator checks this by exact enumeration over a lattice of p with the cell's denominators and by the interval argument (both, so that neither is trusted alone).

**Timing, in the clock contract's terms.** Decisions at t = 0, 1, 2 s issue u₀, u₁, u₂; the v₁ sample is taken at t = 1 s. With arrival at or before t = 1 s the packet is delivered before the estimator and controller ticks of that boundary (a zero-latency loop is legal: a packet arriving exactly at the decision instant is visible). With arrival one quantum after t = 1 s it cannot influence u₁. A derived row, stated here and tested: with arrival after the second command and before the third, the mission is still excluded, because v₃ = 0 forces u₂ = −p − u₁ in both worlds and then x₃ = g·(2p + u₁) cannot be 1 for both gains; the informative packet is useful only if it precedes the second command. With arrival after the third command is committed all 561 cells are excluded.

**Outputs.** `Verdict::{Admitted{witness}, Excluded{reason}}` per cell and timing; the 561 labels as a byte vector in row-major order (i outer, j inner) with a BLAKE3 digest, which is the byte-identity target that device kernels must reproduce at M2.

**Two recorded runs for the boundary comparator (DESIGN).** The evaluator exports two runs in FMT-FRUN (`frob.run/1`, BD-090's writer), committed with the generator that wrote them as `crates/frob-conformance/fixtures/docking/runs/docking-u34-e516.frun` (U = 3/4, ε = 5/16) and `docking-u34-e14.frun` (U = 3/4, ε = 1/4), packet on time, gain g = 1, probe p = (U + ½)/2 = 5/8, reading at the interval end point y = p + ε (15/16 and 7/8), commands from the witness's decision rule (at ε = 5/16 the reading 15/16 sits exactly on the rule's midpoint 3p/2, the equality case, and the run misses (1, 0); at ε = 1/4 it reaches it). Channels on the fixture's 1 s clock (period 1 s, three ticks): `x`, `v` (m, m/s), `u` (the command), `y` (the reading, from t = 1 s), and `separation` (m), the gap (2p − ε) − (p + ε) = p − 2ε between the two worlds' reading intervals, constant over the run: exactly 0 at ε = 5/16 and exactly 1/8 at ε = 1/4. Every channel is a quantized `i64` column with the rational scale 1/64 m (or 1/64 m/s), so each value is an exact rational in the file; the manifest carries `origin = "synthetic"`, determinism class D0 and the cell (U, ε) as rationals. These are the files N24a-42's fixture table names `runs/docking-u34-e516.frun` and `runs/docking-u34-e14.frun`; the task `docking-boundary.ftask.sexp` with its atom `(> separation 0)` is N24a-42's, and the verdicts (`violated` with the boundary flagged and re-evaluated in rational arithmetic; `satisfied`) are N24a-10's to assert. The `separation > 0` criterion is the fixture's own disjointness condition ε < p/2, so the two runs agree with the grid labels of cells (i, j) = (8, 20) (on the boundary, excluded) and (8, 16) (admitted).

## Acceptance criteria
- [ ] The derivation of ε < (U + ½)/4 is on file in `docs/derivations/docking-fixture.md` (N10b-08) with every step above, this bead's two sections included, and the evaluator reproduces each intermediate identity symbolically on random rational inputs.
- [ ] The evaluator passes the law suite of N10b-08 as a `DockingSubject` (`cargo test -p frob-conformance --test laws_c19_docking`, subject `frob_sense::fixtures::docking`), and its verdicts equal the reference model's on all 1,122 (cell, timing) pairs.
- [ ] The committed grid definition equals the grid constant of N10b-08's reference model (17 values of U, 33 of ε), and the 561 committed labels equal that model's closed form: three routes agree (the generating script's integer rule, the reference model, the evaluator's witnesses).
- [ ] PO-SENS-06: exact rational evaluation on the 561-cell grid gives 344 admitted, 217 excluded, 9 on the boundary (the cells with even i and j = 16 + i/2), all 9 excluded.
- [ ] Every admitted cell's witness reaches (1, 0) exactly in both worlds for every admissible reading; every excluded cell has no witness under exhaustive lattice search.
- [ ] Worked commands at U = ¾: p = ¼ gives (¼, ½, −¾) and (¼, 0, −¼), tolerates ε < 1/8; p = 5/8 tolerates ε < 5/16; at ε = 5/16 both worlds can report 15/16 while requiring u₁ = −¼ and −¾.
- [ ] Late packet: all 561 cells excluded when the packet arrives after the third command; also when it arrives after the second command (derived row); a packet arriving exactly at t = 1 s is on time and one quantum later is late.
- [ ] Negative controls caught: the non-strict comparator admits 353 cells; a closed-interval disjointness test (≤ in place of <) changes the nine boundary labels; a model that omits the a/2 term in the position update fails the worked commands.
- [ ] The label vector and its digest are committed; the expected labels come from the generating script's integer rule, not from the evaluator.
- [ ] Results are class D0: identical bytes on every platform.
- [ ] The two recorded runs are committed and read back by BD-090's reader: `separation` is exactly 0 in `docking-u34-e516.frun` and exactly 1/8 in `docking-u34-e14.frun`, the other channels equal the evaluator's step-by-step values, and their bundle hashes are stable across a regeneration.

## Considerations
- The closed form is a scalar model. With bounded probes and positive read error a non-degenerate interval of hidden gains always contains an indistinguishable pair, so an exact guarantee fails for a continuum of gains and a finite tolerance must be declared; that is the subject of a separate mission-chapter fixture and of the amendment in N20b-14.
- The fixture is the first test of the exact-integer kernel class; the host evaluator here is the oracle those kernels are compared with, so it must stay free of floating point.
- The same counts appear in the mission chapter's gate for the docking family; the label vector committed here is the single source both use.
