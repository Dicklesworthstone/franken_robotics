## Background
GATE-SENS-03 (Known answer; TARGET; M2): "Noninterference: all five properties hold on the standard battery; the draw-order control fails." The five properties each change one thing and require named digests to stay byte-equal: presentation (viewer, stills, telemetry level on or off: every physics digest and every delivered observation unchanged); truth (simulator truth changed behind a sensor that is disconnected, masked or not yet delivered: the actor's inputs and commands unchanged); sensor set (sensors that no controller consumes added, removed or reordered: the outputs of every other sensor, and physics, unchanged); batch (the same world address alone, in a batch of 8,192, and beside worlds with different sensor suites: that world's delivered observations unchanged); optics against contact (an optical card changed: physics digests unchanged; an interface card changed: ray outputs unchanged).

The properties protect the decisions that make results independent of who is watching and of what else is in the batch: observations come only from the deterministic observation service; noise streams are keyed by logical identity, never by draw order. A generator that hands out draws in call order fails the sensor-set property the first time a sensor is added, and that failing build is the gate's named control.

This bead is the user-side script through the real `frob` binary, on real fixtures, per tier.

## Scope
In: the script, its assertions, its structured log, the gate receipt. Out: the harness and the properties' implementation (BD-215).

## Technical approach
**Script.** `scripts/e2e/sense_noninterference.sh [--tier referee|batch-cpu|gpu-cuda|gpu-metal] [--battery standard] [--worlds 64] [--seed 3100]`. Plain shell, real binary, idempotent, seed-explicit, non-zero exit on failure. Control steps need control builds: the `frob` binary built with `--features gauntlet-mutations` plus the one control's own feature (BD-215's `draw-order-noise` and the others of step 6; a per-control feature is never in the umbrella, BD-025); the script checks `frob doctor --json` for the feature and fails the control step with a clear message on a build without it.

**Fixtures** (`crates/frob-conformance/fixtures/sensorium/nonint/`, committed pairs, because scene editing verbs arrive after this milestone and a pair of files is the more exact statement of "change one thing" anyway): `nonint-disconnected` and `nonint-masked` designs, each with a scene pair `truth-a.fscene` / `truth-b.fscene` that differ only in a region that the disconnected or masked sensor alone sees; `optics-base.fscene` / `optics-glass.fscene` (one region's optical class `diffuse` against `glass`, interface map identical); `interface-dry.fscene` / `interface-wet.fscene` (one region's interface condition, optical map identical); the design `D` with variants `D-plus-imu` (an unconsumed IMU added), `D-minus-sensor` and `D-reordered` (the sensor list reordered in the file); `obs_from_viewer.ftask`.

**Steps.** Each step runs a base and a changed run and compares digests obtained with `frob telemetry summary <run> --digests --json` (the digest table of BD-187: per-stage physics digests, per-world state digests, delivered-observation digests, per-sensor output digests, command digests). Every run verb carries `--key`, and the two runs of a pair carry distinct keys (`ni-<step>-base-<tier>`, `ni-<step>-<change>-<tier>`), so that a changed run is never answered from the base run's idempotency record.
1. *Presentation.* Base: `frob sim run <battery item> --telemetry T0 --tier <tier> --seed <seed> --key ni-pres-base-<tier> --json`. Changed: the same with `--telemetry T1` (key `ni-pres-t1-<tier>`), then `T2` (`ni-pres-t2-<tier>`); then a run (`ni-pres-stills-<tier>`) during which `frob telemetry stills <run> --world 0 --at t=<s> --json` and `frob telemetry inspect-pixel <run> --world 0 --at t=<s> --pixel <x>,<y> --json` (the still is named by run, world and instant) are issued while the job runs; then a run (`ni-pres-viewer-<tier>`) with the viewer of N32b-10 attached to the job in live mode through its headless test entry (`window.__frobViewerTest` under the pinned headless launcher of `viewer/build/test.mjs`), polling snapshots every 100 ms for the whole run. Assert physics and delivered-observation digests equal in every pair.
2. *Truth.* `frob sense causal-test <design> --task causal-<archetype> --twins delayed-measurement --tier <tier> --seeds 1 --key ni-truth-ct-<tier> --json` (the verb's row has `--seeds <n>`, not `--seed`) and the two fixture pairs for a disconnected and a masked sensor (`frob sim run nonint-disconnected --scene truth-a.fscene --tier <tier> --seed <seed> --key ni-truth-disc-a-<tier> --json` against `--scene truth-b.fscene --key ni-truth-disc-b-<tier>`, and the same for `nonint-masked`). Assert the actor's input and command digests equal.
3. *Sensor set.* Base design D. Changed: `D-plus-imu` (equivalently `frob design edit <scratch copy of D> add-sensor … --expected-parent <id> --key ni-edit-<tier> --json`, which the script also runs once to show the verb path gives the same digests), `D-minus-sensor`, and `D-reordered`. Assert every other sensor's output digest and all physics digests equal.
4. *Batch.* World address A is world 0 of a run with seed s: `frob sim run D --worlds 1 --seed s --key ni-batch-1-<tier>`, `--worlds 8192 --key ni-batch-8192-<tier>`, and `--designs D,D-alt1,D-alt2 --worlds-per-design 2048 --seed s --key ni-batch-mixed-<tier>` (6,144 worlds; A is world 0, the first of D's slots, and the other slots carry different suites or body plans; `--worlds` with `--designs` is FROB-REF-802 on `sim.run`'s row, so the mixed batch is sized by `--worlds-per-design`). Assert A's delivered-observation digests equal. On the referee this step logs `not applicable`.
5. *Optics against contact.* `--scene optics-glass.fscene` against `optics-base.fscene`: assert physics digests equal. `--scene interface-wet.fscene` against `interface-dry.fscene`: a region no foot touches before the horizon is not enough, so the pair changes a region the robot does stand on, and the script asserts every ray output digest equal while physics digests are allowed to differ.
6. *Controls.* Rerun step 3 on the `draw-order-noise` control build: assert the property **fails** and log the first differing sample. Likewise BD-215's viewer-fed camera control (step 1), batch-mean normalization (step 4), friction derived from `r0` (step 5), and one planted leak (step 2, `--control leak.sens.1`). A control that does not fail fails the script.
7. *Refusal.* `frob task check fixtures/…/obs_from_viewer.ftask --json`: assert FROB-REF-442, exit 3.
8. *Conformance rows* (the Gauntlet has no `frob` command, ADR-GAUNT-01). The gate's rows span two tier targets, KA-505, KA-506, KA-507 and KA-509 in G3 and KA-508 in G5, so the script runs `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --features gauntlet-mutations --test g3_metamorphic -- GATE-SENS-03` and the same with `--test g5_determinism`, at one commit; each run covers every execution site (an unavailable device site is `Skipped` with its reason, counted and never a pass). It asserts on the two hash-named receipts under `target/gauntlet/receipts/` that every run entry is `pass` and that each property's control, the draw-order control among them, is `caught`, and logs both hashes.

**Gate record.** The script writes no record. The recording session, one that did not implement the harness, enters GATE-SENS-03 in `registries/gates.toml` from the two step-8 receipts, `cargo run -p frob-conformance --example record_gate -- --gate GATE-SENS-03 --receipt <g3-hash> --receipt <g5-hash>` (N38b-19: one receipt per tier target, both of one commit), citing this script's log for the user-side values: per property and tier the worlds, ticks and digests compared and the verdict; the controls caught (5 of 5, the draw-order control marked as the gate's named control); commit, fingerprint, seed.

**Logging (STD-E2E).** `target/e2e-logs/sense_noninterference/<utc>.ndjson` and a transcript. Lines carry `ts`, `script`, `bead` (`N20b-15`), `step`, `event`; `cmd` with exact command line, exit code, wall time and the envelope's evidence block (claim, class, tier, determinism, identities, seed); `metric` with counts of digests compared and equal; `assert` with the property, the change, expected `equal` or `differs`, observed; on a difference the first differing world address, tick, digest stream and both values, and the two run paths; `refusal` for step 7; `summary` with assertions passed and failed and `gates: ["GATE-SENS-03"]`. The log contains digests and identifiers only, never scene geometry, so it is safe for private scenes.

## Acceptance criteria
- [ ] The script runs to exit 0 on a correct conformance build for each available tier.
- [ ] All five properties hold on the standard battery items it runs (at least one legged and one wheeled item, 64 worlds, the battery's horizon).
- [ ] The draw-order control fails the sensor-set property; the other four controls fail their properties.
- [ ] FROB-REF-442 is returned for the viewer-sourced observation, exit 3.
- [ ] GATE-SENS-03 is recorded once, from the step-8 G3 and G5 receipts of one commit, with measured counts; a tier that could not run is `Skipped` with its reason in those receipts and logged by the script.
- [ ] A second run with the same seed logs identical digests.

### Known answers and negative controls

Determinism lanes: each comparison within one tier; twice on one machine; the batch step across worker counts.

## Considerations
- Step 5's interface change legitimately changes physics; only ray outputs are compared there. The fixture keeps the robot's pose trajectory prescribed (a kinematic playback) so that ray origins do not move when friction changes; otherwise ray outputs would differ for a legitimate reason.
- The 8,192-world step needs device memory; on a machine without a device it runs on `batch-cpu` with the height-scan suite and says so.
- Runtime (TARGET): under ten minutes per tier.
