## Background
Every capability of the studio is reached through a verb, and every verb is one entry in `registries/verbs.toml`, owned by `frob-verbs`. The command line, the daemon protocol, the MCP tool definitions, the schemas, the refusal table and the generated agent documentation are produced from that file, so the surfaces cannot drift; a gate diffs the served tool list against it. A capability is not implemented until it is reachable through `frob --json` with a documented schema and exit code and, where exposed to agents, through the MCP server.

The Sensorium chapter owns a cluster of verbs. Its table:

| Verb | Kind | First milestone | Returns |
|---|---|---|---|
| `sense.profile` | read | M2 | The sensor suite, cards with provenance, clocks, link models and queue capacities of a design and task |
| `sense.schedule` | read | M2 | The exact boundary schedule over one repeat of the clock lattice, with lateness per event |
| `sense.causal-test` | run | M2 | Pass, or the first decision instant and channel at which causality fails |
| `sense.observability` | run | M3 | The Gramian spectrum along a route, with named weak directions |
| `sense.alias` | run | M3 | An alias witness with its class and the priced separating changes, or "none found" |
| `sense.symmetry` | read | M3 | Γ_obs, the elements of Γ_mech it excludes and the sensor or task that excludes each |
| `sense.calibrate` | run | M3 in simulation, M5 on imported logs | Extrinsic corrections with covariance, the consistency residual per edge, and a fault attribution where the graph supports one |
| `sense.visibility` | run | M3 | Visibility of each sensor along a nominal motion, with the robot's own limbs and payload as occluders |
| `telemetry.stills`, `telemetry.inspect-pixel` | read | M2 | Contact sheets drawn with the ray kernels plus an identifier buffer; a pixel mapped to a link, fixture, region or contact |

`telemetry.export-html` belongs to the telemetry cluster of the chronicle chapter, and the viewer it packages to the surface chapter; they are named here only to say they are not Sensorium's.

Each verb is implemented by its own bead. What no single one of them owns is the cluster as a whole: consistent naming, one refusal list per verb drawn from the chapter's seven codes, schema names, and the milestone at which each row first appears. This bead is that integration. Tier: Solid.

## Scope
In: the eight registry entries of the `sense` cluster and the Sensorium side of the two telemetry verbs; per-verb kind, capability scope, input and output schema names, refusal lists, idempotency, cost model, wait defaults for `run` verbs, examples; the milestone rows; the mapping to MCP tool names; a cluster-level conformance test.
Out: each verb's behaviour (its own bead); the generator and the parity gate (the surface beads); the stills renderer (the stills bead).

## Technical approach
**Entries.** One `[[verb]]` table each, in the registry's format (`name`, `cluster`, `kind`, `tier`, `capabilities`, `input_schema`, `output_schema`, `refusals`, `idempotent`, `cost_model`, `first_milestone`, `task_clusters`, `examples`).

| Verb | Kind | Capability | Schemas (`.in/1`, `.out/1`) | Refusals | Implemented by | Earliest delivery |
|---|---|---|---|---|---|---|
| `sense.profile` | read | `design:read` | `frob.sense.profile` | surfaces 440, 441, 126 | BD-099 (v0), N20b-16 | M1 (referee, proprioception); M2 complete |
| `sense.schedule` | read | `design:read` | `frob.sense.schedule` | 440 | BD-078 | M1 (CPU); M2 every tier |
| `sense.causal-test` | run | `sim:run` | `frob.sense.causal-test` | 442 | BD-119, N20b-12 | M1 (referee); M2 every tier |
| `sense.observability` | run | `sim:run` | `frob.sense.observability` | 440, 441 | BD-120, BD-239 | M1 (linearized, CPU); M3 empirical |
| `sense.alias` | run | `sim:run` | `frob.sense.alias` | 445 (raised by training and optimization verbs that find a standing witness) | BD-134, BD-240 | M1 (enumerated docking worlds); M3 search |
| `sense.symmetry` | read | `design:read` | `frob.sense.symmetry` | 443 (raised by consumers), 214 | BD-241 | M3 |
| `sense.calibrate` | run | `sim:run` | `frob.sense.calibrate` | 446, 447 | BD-242, N20b-08 | M3 simulation; M5 logs |
| `sense.visibility` | run | `sim:run` | `frob.sense.visibility` | 441, the stage-7 lead refusal | N20b-33 | M3 |
| `telemetry.stills`, `telemetry.inspect-pixel` | read | `run:read` | telemetry cluster's | 442 never (a still is not an observation) | BD-191 | M2 |

**Rules applied to every entry (DESIGN, from the registry's conventions).**
1. `read` verbs return stored or cheaply computed facts and change nothing; `run` verbs spend compute, take an idempotency key and a budget, accept the bounded synchronous wait (wait to completion on the CLI; 5,000 ms by default on MCP, at most 30,000) and otherwise return a job handle with exit code 8.
2. The MCP tool name is the verb name with `.` and `-` replaced by `_` (`sense.causal-test` → `sense_causal_test`); no registry name contains an underscore; the map must be one-to-one.
3. Every refusal in a verb's list is one of the registry's codes; a verb that raises an unlisted code fails the conformance test. All `4xx` codes exit 3.
4. Every output is one envelope with the evidence block (claim product: class, tier, determinism, identities, seed, Reality `no-claim` by default).
5. `first_milestone` records the earliest milestone at which the verb is reachable at all, with a `coverage` note for what that milestone covers. The chapter's table gives M2 or M3 for verbs that the bead plan delivers on the CPU at M1 because the first mission slice needs them; the registry rows therefore carry M1 with `coverage = "referee"` for `sense.profile`, `sense.schedule`, `sense.causal-test`, `sense.observability` and `sense.alias`, and the chapter's milestone as the one at which coverage is complete. This difference between the chapter's table and the delivery plan is reported to the lead in the unit's coverage file.
6. Task clusters for MCP: the eight verbs do not fit one cluster of seven. DESIGN proposal, to be confirmed by the surface owner: `sense.profile`, `sense.schedule`, `sense.causal-test`, `sense.observability`, `sense.alias`, `sense.symmetry`, `sense.visibility` in a cluster `perceive`; `sense.calibrate` with the Ground verbs in `calibrate`; the telemetry verbs stay in the clusters that already list them.

**Conformance test.** `crates/frob-verbs/tests/sense_cluster.rs`: loads the registry and asserts, for the eight names, the fields above; that each schema file exists and validates its examples; that each verb's refusal list is a subset of the registered codes and contains the codes the table lists; that the MCP name map is one-to-one; that `sense.visibility` (added by a late subsection and absent from the chapter's original verb table) is present.

## Acceptance criteria
- [ ] `registries/verbs.toml` contains the eight entries with the fields above; `frob schema sense.<verb>` prints each schema; `frob robot-docs` lists the cluster.
- [ ] The served MCP tool list contains `sense_profile`, `sense_schedule`, `sense_causal_test`, `sense_observability`, `sense_alias`, `sense_symmetry`, `sense_calibrate`, `sense_visibility` once their milestones are reached, and the registry diff gate shows no drift for them.
- [ ] Each `run` verb returns exit 8 with a job handle when its wait elapses, and the same envelope on completion; each verb's listed refusals exit 3.
- [ ] The cluster conformance test passes; removing a refusal from a list, or adding an underscore to a name, fails it (negative controls).
- [ ] Milestone rows carry the earliest delivery and the coverage note; the difference from the chapter's table is recorded.
- [ ] No verb of the cluster has a second spelling.

## Test plan
### Unit tests
(`cargo test -p frob-verbs sense_cluster`)
- `eight_entries_present_with_kinds`.
- `schemas_exist_and_examples_validate`.
- `refusal_lists_subset_of_registry_and_complete`: expected sets per the table.
- `mcp_names_one_to_one`.
- `run_verbs_have_wait_defaults`.
- `control_unlisted_refusal_fails`, `control_underscore_name_fails`.
### End-to-end script and logging
`scripts/e2e/sense_cluster_surface.sh` (sources the STD-E2E helper): for each verb available at the current milestone, calls it once on the CLI with `--json` and once through the MCP server with a minimal valid request and once with an invalid one; asserts one envelope per call, the documented exit codes (0 or 2, 3 on refusal, 8 on a `run` verb with a zero wait), and equal structured content on both surfaces. Logs to `target/e2e-logs/sense_cluster_surface/<utc>.ndjson` with a transcript: each `cmd` with exit code and wall time, the evidence block, an `assert` per surface-parity check, `refusal` lines, and a summary naming GATE-TETHER-02 (the cluster's rows).
### Known answers and negative controls
The exit-code table on malformed, unknown, over-budget and refused inputs (the surface chapter's known answer) applied to this cluster. Controls: an entry with a missing refusal; a renamed tool. Determinism: the registry and schemas are data; identical generated surfaces on every platform.

## Considerations
- The registry-wide beads depend on the verbs existing; this bead must not depend on them (they depend on implementations), so it carries only the cluster's rows and its own test.
- `sense.alias` raises no refusal of its own for "no witness": it returns "none found", never "none exists" unless a structural or enumerated argument supports it. FROB-REF-445 is raised by training and optimization verbs.
- The two refusals the late subsections state without a code (a peak-load claim without a resolved or modeled force history; a stage-7 target whose lead is shorter than the latency chain) need codes from the registry owner before their verbs can list them; N20-REF records them as pending.
