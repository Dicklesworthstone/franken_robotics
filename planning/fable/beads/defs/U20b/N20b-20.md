## Background
The chapter closes with a table of known answers: 27 cases, each a truth that a correct Sensorium must reproduce and, for most, a negative control (a specific wrong build that must fail). The known-answer suite is tier G1 of the verification program; its registry (`crates/frob-conformance/registry/known_answers.toml`, one derivation file per row) is the source of the numbered rows KA-465 to KA-524 for this chapter. Three late subsections add further answers (the force chain's rectangular and half-sine pulses; the box-and-mast visibility case; the rebound window, the two-speed encoder and the load-cell cut) that the plan states with their gates and without numbers; the decision N20b-45, a dependency, assigns them.

Individual mechanism beads test their own rows. This bead is the chapter-level run: one script that executes every row through the real `frob` binary or the Gauntlet target that wraps it, checks the truth and the control, and writes one log from which an exit review can read the whole chapter's state. It exists for two reasons (DESIGN). The rows are owned by two drafting units and many beads; without one battery nobody can see whether a row fell between them. And a row and its control must be run together: a row reported as passing while its control also passes is a defective test, which only a run that executes both can show.

## Scope
In: the battery manifest, the script, its log and summary; the mapping from the chapter's 27 rows to numbered rows, gates and owning beads; slots for the late answers. Out: the tests themselves (owned by the beads named in the manifest) and the registry bead for the numbered rows.

**Script.** `scripts/e2e/sensorium_known_answers.sh [--milestone M1|M2|M3] [--tier …] [--seed 2000]`. For each manifest entry whose milestone is at or before the requested one, the script runs the entry's `runner`. That is either a `frob` command sequence or `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test <target> -- <row>`, the Gauntlet target that N20-KA's tier column gives for the row, filtered by its KA identifier. The targets are `g0_laws` for KA-472 and KA-490; `g3_metamorphic` for KA-478, KA-497 and KA-505 to KA-507 and KA-509; `g4_chaos` for KA-522; `g5_determinism` for KA-477, KA-508 and KA-524; and `g1_known_answers` for every other row (N38a-02; the Gauntlet has no `frob` verb, ADR-GAUNT-01). It asserts the truth at its tolerance. It then runs the same entry in its control build, `--features gauntlet-mutations` with the control runner adding the control's own `<crate>/<feature>`, one control per build (KNOWN_DRIFTS 1, BD-025), and asserts that it fails. Whether a row has a control is read from the registry at run time (the row's `control.nc`, N38a-12), not from the table above: the chapter leaves six cases blank, and N38b-32 (M2) registers controls for their rows, so a row that has gained one is run with it. Entries whose registry row still says "none stated" are run without a control and are counted separately; the summary reports how many rows have no control so the number is visible. Exit non-zero on any truth failure, any control that passes, or any entry with no runner.

**Logging (STD-E2E).** `target/e2e-logs/sensorium_known_answers/<utc>.ndjson` and a transcript. Per entry: a `cmd` line (exact command, exit code, wall time, the envelope's evidence block); a `metric` line with the measured value, unit, truth and tolerance; an `assert` line for the truth and one for the control ("failed as required"); on failure the first differing value and the artifact path. The final `summary`: rows run, rows passed, controls caught, rows without a stated control, rows pending for a later milestone, the gates touched (GATE-SENS-01 to -18 as applicable), and the counterexample coverage: of the twenty control entries N20-CX registers for this chapter (CX-200 to CX-215 and the four late slots), how many were run as the control of some manifest row and failed as required, with every entry run by no row listed by name (those are caught by their owners' unit tests, which N20-CX's registry check reads).

## Acceptance criteria
- [ ] The manifest contains the 27 chapter cases, the additional numbered rows and the three late slots, each with a runner and an owner; an entry without a runner fails the script.
- [ ] At M3 every row at or before M3 passes at its tolerance and every stated control fails as required.
- [ ] The summary reports the count of rows with no stated control, so that the gap is visible and not silently treated as covered. With N20-KA as it stands, 6 of the 27 chapter cases have none: the turntable, the lidar pattern, lidar motion distortion, the corridor Gramian, the gauge, and sequential reads under a deadline. The mirror's control is set by N20a-21, the spinning lidar's by N20b-01, and the mutations for the T-junction and the bumped sensor are N38b-28's. The reported count is the registry's at run time, so it falls as N38b-32 registers controls for those six.
- [ ] Running with `--milestone M1` runs only M1 rows (the clock rows on the CPU, the docking rows, the causal rows on the referee, the IMU rows on the referee) and reports the rest as pending.
- [ ] The script's own control: with one truth value in the manifest changed (a self-test copy with 19.2 pixels replaced by 19.9), the script exits non-zero.
- [ ] The summary's counterexample coverage lists each of N20-CX's twenty entries for this chapter as run by a manifest row (with the row) or as covered only by its owner's unit test (by name); the late slots carry the numbers N20b-45 assigned, with the slot names as aliases.
- [ ] The log validates against the STD-E2E schema.

### End-to-end script and logging
This bead is the script `scripts/e2e/sensorium_known_answers.sh`, as above.
### Known answers and negative controls
All of them: the table is the content. Determinism lanes: rows of class D0 (clock, docking, symmetry groups, pose-graph patterns) are compared exactly and across platforms; float rows at their tolerances per tier.

## Considerations
- The battery duplicates no test logic; it calls runners owned by mechanism beads. If a mechanism bead renames a test, the manifest's runner breaks loudly.
- Rows owned by the other Sensorium unit carry the keys N20-KA lists for them; if a mechanism bead is split or renamed, N20-KA's owner column is updated first and this manifest follows.
- The late slots carry the numbered rows N20b-45 assigns, so that the registry and the printed appendix agree; the manifest keeps the slot names as aliases and reports each row under its gate.
