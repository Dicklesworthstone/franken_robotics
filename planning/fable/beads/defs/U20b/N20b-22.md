## Background
Two gates accept the M2 sensor suite. GATE-SENS-01 (Known answer, TARGET): depth against analytic scenes within 1 mm plus the brick bound; the three IMU cases (at rest the reading is (0, 0, +g) with zero rate; in free fall without rotation it is zero; in free fall spinning at 5 rad/s with a 0.10 m perpendicular offset it is 2.5 m/s² toward the axis) and the turntable case; lidar beam geometry and instants match the pattern definition. GATE-SENS-02 (Fidelity, TARGET): sensor outputs, masks and delivered-observation digests agree across backends inside their determinism class.

Both are measured on a running system through the real `frob` binary on every tier, so they have one end-to-end bead. The script also exercises `sense.profile`, the read verb through which an agent sees the suite it is testing. One script for known answers and cross-backend agreement is a DESIGN choice: the cross-backend comparison is only meaningful on fixtures whose answers are known to be right on at least one tier, and running them together guarantees the same fixtures and seeds.

"Inside their determinism class" needs care. If a device family attains bit equality with the CPU reference (class D1, a hypothesis until the backends' gate passes), digests are compared for equality. If it holds only class D2 for itself and D3 against others, the script compares masks and integer channels for equality, float payloads inside the recorded envelope, and labels the row a tolerance comparison. A class is never raised by relabelling.

## Scope
In: the script, fixtures list, assertions, structured log, gate receipts. Out: the sensors and kernels.

## Technical approach
**Script.** `scripts/e2e/sense_suite.sh [--tiers referee,batch-cpu,gpu-cuda,gpu-metal] [--seed 2500]` (the tier names of `sim.run`'s `--tier` grammar, passed unchanged to every verb; `cuda` alone is FROB-REF-802). Plain shell, real binary, idempotent (scratch namespace for designs and scenes), seed-explicit, non-zero exit on failure. Tiers that are not available are logged `not run` with the reason and do not fail the script unless `--require-tier` names them.

**Fixtures** (`crates/frob-conformance/fixtures/sensorium/suite/`): analytic scenes `plane`, `sphere-r1`, `box` compiled with `frob scene compile <src> --name ss-<scene> --key ss-sc-<scene> --json` (each records its brick bound); designs `imu-rest`, `imu-freefall`, `imu-spin` (IMU at 0.10 m perpendicular offset, initial spin 5 rad/s), `imu-turntable`, `enc-rotation`, `depth-cam` (640 × 480, f = 600 px), `lidar-16` (16 channels, 1,800 azimuth steps, 10 Hz), `hscan-187`. Each known-answer design carries noise-free cards (noise fields zero, provenance `assumed`, labelled as fixtures), so "noise off" is a property of the fixture and not a run flag; the cross-backend step uses the same designs with their noisy cards (`*-noisy` variants).

**Steps.**
1. `frob sense profile <design> --json` for each design: assert the suite, clocks as exact rationals, queue capacities and per-field provenance are present; log Q and the repeat length.
2. Depth: `frob sim run depth-cam --scene <scene> --tier <tier> --seconds 0.05 --seed <seed> --key ss-depth-<scene>-<tier> --json` (one exposure); read the depth packet with `frob telemetry query <run> --stream sensing --channels depth --json`; compare every valid pixel with the analytic distance for that scene and pose; assert max error ≤ 1 mm + the scene's recorded brick bound. Control build `range-for-depth`: assert the comparison fails.
3. IMU: run the four designs for 1 s (`frob sim run imu-<case> --tier <tier> --seconds 1 --seed <seed> --key ss-imu-<case>-<tier> --json`, noise-free cards) and read `--stream sensing --channels imu`; assert the readings at their truths at the tier's tolerance (10⁻⁹ relative on the referee, 10⁻⁵ relative on `f32` tiers; TARGET values recorded in the receipt). Control build `gravity-twice`: assert failure.
4. Lidar: run `lidar-16` for one scan (`frob sim run lidar-16 --scene <scene> --tier <tier> --seconds 0.1 --telemetry T2 --seed <seed> --key ss-lidar-<tier> --json`; level T2 so that per-ray fields are not downsampled); read ray directions and per-ray instants from the lidar packets' per-ray fields (`frob telemetry query <run> --stream sensing --channels lidar --json`); assert equality with the pattern definition file (instants as integers in quanta; directions within 4 ulp). Control build `lidar-axes-swapped`: assert failure.
5. Height scan and encoder: `hscan-187` over a staircase fixture (step heights within the depth tolerance; key `ss-hscan-<tier>`); `enc-rotation` (tick count exact; key `ss-enc-<tier>`).
6. Cross-backend (GATE-SENS-02): for the same world addresses and seeds with noise on (the `*-noisy` cards), run a 2 s episode of a reference quadruped with the full suite on each available backend (key `ss-xb-<backend>`, one per backend, so the compared runs are distinct jobs); fetch per-sensor output digests, mask digests and delivered-observation digests with `frob telemetry summary <run> --digests --json` (the digest table of BD-187); compare each device with `batch-cpu` under the full step's attained class from `frob spark check --step --backend <backend> --key ss-ck-<backend> --json` (BD-176). Under D1: assert equal digests. Under D3: assert equal mask digests and integer channels, float payload differences inside the envelope, and log the first divergence (`frob telemetry divergence <cpu-run> <device-run> --mode tolerance --json`: tick, stage, channel; then the sensor, ray or axis and both values from `telemetry.query`). Control build `drop-mask-reason` on one backend: assert the mask digests differ.
7. Batch independence spot check: world address A alone and in a batch of 1,024 on one backend (`--worlds 1 --key ss-bi-1` and `--worlds 1024 --key ss-bi-1024`): equal delivered-observation digests (the full property is the noninterference script's).

**Gate records.** Two receipts: GATE-SENS-01 with the measured maxima per scene and tier (depth error in mm against 1 mm plus the bound; IMU errors; pattern equality) and controls caught; GATE-SENS-02 with, per backend pair, the class, the digests compared, and for D3 the envelope and the largest observed difference. The gate rows wrap the script as `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g1_known_answers -- gate_sens_01` and `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g5_determinism -- gate_sens_02` (the Gauntlet has no `frob` command); each value is entered in `registries/gates.toml` with `cargo run -p frob-conformance --example record_gate -- --gate GATE-SENS-01 --receipt <hash>` (and likewise GATE-SENS-02) by a session that did not implement the sensors.

**Logging (STD-E2E).** `target/e2e-logs/sense_suite/<utc>.ndjson` and a transcript. Every line: `ts`, `script`, `bead` (`N20b-22`), `step`, `event`. `cmd`: exact command line, exit code, wall time, the envelope's evidence block (claim, class, tier, determinism, identities, seed). `metric`: value, unit, truth, threshold (for example `depth_err_max_mm`, `imu_spin_accel_mps2`, `lidar_instant_mismatches`). `assert`: expected and observed. Digests wherever state is compared; on failure the first differing value (pixel or ray index, both values) and the run paths. `summary`: assertions passed and failed, tiers run and not run, `gates: ["GATE-SENS-01", "GATE-SENS-02"]`. Analytic fixtures only; nothing private is logged.

## Acceptance criteria
- [ ] The script runs to exit 0 on a correct build for every available tier.
- [ ] Depth error within 1 mm plus the brick bound on the three scenes on every tier; the IMU and turntable rows at their tolerances; lidar geometry and instants equal to the pattern.
- [ ] Each of the four control builds makes its step fail.
- [ ] Cross-backend rows recorded with their class; under D3 the first divergence is logged, not hidden.
- [ ] `sense.profile` output asserted for each design.
- [ ] GATE-SENS-01 and GATE-SENS-02 recorded with measured values; unavailable tiers recorded `not run` with the reason.
- [ ] Same seed, same log metrics on a second run on the same machine.

## Test plan
### Unit tests
`scripts/e2e/tests/sense_suite_selftest.sh`: `fixtures_compile_and_record_bounds`; `analytic_distance_helper_matches_closed_forms` (the script's reference computation for plane, sphere and box against hand values: a ray from (0, 0, 2) straight down to the plane z = 0 has range 2; a ray from (3, 0, 0) toward the origin hits the unit sphere at range 2); `control_builds_fail_steps`; `log_lines_validate`.
### End-to-end script and logging
This bead is the script `scripts/e2e/sense_suite.sh`, as above.
### Known answers and negative controls
KA-465 (depth; control: ray distance swapped for optical depth), KA-466 to KA-469 (IMU; control: gravity applied twice), KA-470 (lidar pattern), KA-510 (encoder ticks), KA-524 (across backends). Planted failures: the four control builds. Determinism lanes: twice on one machine; across worker counts; debug and release; across platforms and backends, each against its class.

## Considerations
- The analytic reference in the script is independent of the kernels (closed forms in a small helper), so the script does not compare the product with itself.
- On the no-device variant of the milestone the script records GATE-SENS-01 on the referee and `batch-cpu` and GATE-SENS-02 as `not run` for devices; any device result that exists is labelled exploratory.
- Runtime (TARGET): under five minutes per tier.
