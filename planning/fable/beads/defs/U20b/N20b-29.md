## Background
An ordered sensor chain (N20b-28) acts on force as a function of time. Whether such a function exists depends on how the tier resolves contact. On the compliant contact laws, force is computed as a function of state at every physics step, and a force history exists. On an impulse-level step (the referee's event step, where an impact is resolved as an instantaneous change of momentum, and the hard-contact batch law) a contact delivers an **impulse**, which has no duration: there is no peak force to clip, and a reading that pretends otherwise is a guess presented as a measurement.

The chapter's rule (DESIGN) is that a contact force history is available in three grades, and that the grade is visible and has consequences:
- **`resolved`**: the compliant laws compute force as a function of state at every physics step, and the chain is applied to that history.
- **`modeled`**: on an impulse-level step the interface card supplies a pulse model with provenance, a duration τ_c and a shape, for example a half-sine with τ_c = π·√(m_eff/k) and peak (π/2)·J/τ_c for an impulse J.
- **`none`**: there is no pulse model; the linear reading is still produced, its `overload` field is `unknown`, and any requirement atom on peak load or on sensor overload evaluates to `undetermined`.
`sense.profile` lists, per sensor, the chain, the grade available on each tier, and the atoms that the grade cannot decide; a peak-load claim without a resolved or modeled force history is refused.

Why three grades and not a default pulse (DESIGN): a default pulse shape nobody chose would turn every impulse into a confident peak force. With `none`, the simulator says what it knows (the momentum transferred) and declines to say what it does not (how hard the knock was). Tier: Solid. Owner: `frob-sense`; pulse models live on interface cards, owned by the contact chapter.

## Scope
In: the grade type and how it is determined per sensor, tier and contact; the pulse-model field and the half-sine shape; applying the chain to a modeled pulse; the `none` path (`overload: unknown`, undetermined atoms, the refusal); the profile entries; the half-sine known answers.
Out: the chain stages (N20b-28); the device kernel and the compliant-tier accuracy row (N20b-30); the contact laws and the card schema's home (contact chapter); the requirement monitors (the requirement-language bead); the gate script (N20b-31).

## Technical approach
**Grade determination (per sensor, per tier, per contact event).**
```rust
// DESIGN. Fixes intent, not signatures.
pub enum ForceGrade { Resolved, Modeled { pulse: PulseModel, provenance: Provenance }, None }
pub struct PulseModel { shape: PulseShape /* HalfSine | Rect */, duration: PulseDuration /* Fixed(seconds) | FromStiffness */ }
```
1. If the tier's contact law for the interface is compliant (force a function of state each step): `Resolved`.
2. Else (an impulse-level step: the referee's event step; the hard-contact batch law): if the interface card of the contacting material pair and condition has a pulse model: `Modeled`, carrying the card field's provenance. Else `None`.
A sensor's grade on a tier is the weakest grade over the contacts that load it during the window (`None` < `Modeled` < `Resolved`); the profile reports it per tier from the cards and the tier's law table, before any run.

**Pulse models.** Half-sine: F(t) = F_peak·sin(π·t/τ_c) for 0 ≤ t ≤ τ_c, with F_peak = (π/2)·J/τ_c so that the integral is J. `FromStiffness`: τ_c = π·√(m_eff/k), half the period of a mass m_eff on a spring k, where m_eff is the effective mass at the contact along its normal (the reciprocal of the normal-normal entry of the contact-space inverse inertia, which the impact solve already has) and k is the interface card's contact stiffness. `Fixed`: τ_c given on the card (a measured or datasheet value). Rectangular: F = J/τ_c over τ_c (used by the rectangular known answers). The pulse starts at the impact instant; where it extends past the close of an exposure window, the part after the close belongs to the next window (a pulse with duration is a force history and is split like any other; only a true impulse belongs to exactly one window).

**Applying the chain to a modeled pulse.** The sensor layer expands the pulse analytically, not by changing the physics step:
1. For a chain whose stages before `integrate` are only `overload: clip` (the common case), use the closed form. With L the clip level and F_peak > L: θ₀ = asin(L/F_peak); ∫ min(F, L) dt = (τ_c/π)·[2·F_peak·(1 − cos θ₀) + L·(π − 2·θ₀)]. With F_peak ≤ L the integral is J. The reading is the integral (plus the continuous part of the history) divided by the exposure length.
2. For a chain with a transfer stage or a recovery law, sub-sample the pulse at a fixed count (64 samples per pulse, DESIGN) and run the stage library on the samples. The sub-sampling happens inside the sensor computation and is a constant of the shape class.
The functions asin and cos here are evaluated on the host or with the dialect's deterministic functions; the closed form is the oracle for the sub-sampled path.

**The `none` path.** The linear reading is produced (impulse added once to the window's integral, divided by the exposure length). The packet's `overload` field is `unknown` (a three-valued field: `no`, `yes`, `unknown`). A requirement atom whose signal is a peak load, or a sensor-overload flag, over a window containing a `None`-grade contact evaluates to `undetermined` with reason `force-history-grade: none`; it is never `satisfied`. A verb asked to assert or certify such a claim refuses (the code that the registry decision N20b-45 applies, with the slot name `sens-peak-load-ungraded` as its alias, or the slot itself while the number is pending; repairs: add a pulse model to the interface card with its provenance; evaluate on a tier with a compliant law; drop the claim). Exit code 3.

**Profile.** For each force-type sensor, `sense.profile` lists the chain, the grade on each tier with the pulse model's provenance when `Modeled`, and `undecidable_atoms`: the atoms of the bound task whose signals are peak load or overload and whose grade on that tier is `None`.

**Known answers (half-sine, J = 1 N·s, clip 200 N, exposure 20 ms).** τ_c = 10 ms: peak (π/2)·1/0.010 = 157 N, no clipping, reading 1/0.020 = 50 N. τ_c = 1 ms: peak 1,571 N; θ₀ = asin(200/1,570.8) = 0.1277 rad; clipped integral = (0.001/π)·[2·1,570.8·(1 − cos 0.1277) + 200·(π − 0.2553)] = 0.1919 N·s; reading 0.1919/0.020 = 9.59 N.

## Acceptance criteria
- [ ] `ForceGrade` is determined per sensor and tier from the tier's law table and the interface cards, before any run, and exposed with its provenance and the undecidable atoms through a function that `sense.profile` reads (N20b-16, which depends on this bead, prints it; the gate script N20b-31 asserts it from the user's side).
- [ ] Half-sine rows: τ_c = 10 ms gives peak 157 N (157.08), no clipping, reading 50 N; τ_c = 1 ms gives peak 1,571 N (1,570.8) and a clipped reading of 9.59 N (9.594); the sub-sampled path agrees with the closed form within 0.5%.
- [ ] `FromStiffness`: m_eff = 2 kg and k = 2·10⁵ N/m give τ_c = π·√(10⁻⁵) = 9.93 ms.
- [ ] On the referee an impulse with grade `none` yields `overload: unknown` and an `undetermined` peak-load atom in 100 of 100 cases (the gate's row), and the linear reading equals J divided by the exposure length.
- [ ] A peak-load claim on a `none`-grade window is refused with the reserved code and the three repairs; exit 3.
- [ ] A pulse that straddles a window close is split between the two windows and the two readings sum to the unsplit integral.
- [ ] A `Modeled` grade carries the pulse model's provenance into the reading's evidence; an `assumed` pulse model keeps Reality at `no-claim`.
- [ ] Negative controls caught: a build that substitutes a default half-sine when the card has no pulse model reports a determined atom and fails the 100-of-100 row; a build that reports `overload: no` for `none` fails likewise.

## Considerations
- The hard-contact batch law arrives later than M2; its grade rule is implemented here against the law table and exercised when that law exists.
- A pulse model is a claim about the contact, not about the sensor: it lives on the interface card so that every sensor loaded by the same contact sees the same pulse.
- τ_c from stiffness can be much shorter than a sensor's bandwidth; the transfer stage then dominates and the sub-sampled path is used.
- The refusal has no code in the chapter; its number comes from the allocation ledger through N20b-45 (not 448, which is another chapter's printed code).
- Requirement authors can see undecidable atoms in the profile before running anything, which is the cheap place to learn that a peak-load requirement needs a compliant tier.
