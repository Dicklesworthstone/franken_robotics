## Background

Spark (the subsystem between a derived kernel and a device result) writes each kernel in two layers. The
**skeleton** of a kernel (its loops, gathers, scans, sorts and barriers inside a thread group) is written by hand,
twice: once in Rust for `batch-cpu`, the permanent CPU reference, and once in the **shared dialect**. The dialect
is the common subset of CUDA C++ and Metal Shading Language, made portable by a per-backend **prelude**: a header
of macros for address-space qualifiers, kernel signatures and thread-group barriers. The arithmetic body of a
kernel is generated (bead BD-018) and pasted into the skeleton as dialect text.

FACT: this pattern already works in the suite. `frankensim/apps/instrument-lab/render-gpu-piano` has one
`kernel.h`, a prelude in `cuda.rs`, a prelude in `metal.rs`, and a CPU emulation that is the oracle. No dependency
on that code is added; it is a pattern only (admission test INT-FSIM-11).

ADR-SPARK-02 (DESIGN). One shared C-dialect source for skeletons plus derived arithmetic stays the route. Reason:
the pattern already works in the suite, and a second source language would double the surface that must stay
inside a determinism class. Rejected alternatives: `wgpu` as the only layer (hides launch graphs, allocators and
barriers; no doubles on Metal); Slang (its Metal target is experimental); a Rust-to-PTX compiler (early alpha,
Linux and NVIDIA only); `rust-gpu`, CubeCL and Burn (alpha or a large dependency tree, in conflict with the
Franken-only core); a kernel language with built-in sine and cosine, fused multiply-adds and an approximate mode
(convenient, but incompatible with a three-way bit-parity gate).

Why a lint. The project wants the same bits run to run on each device family (class D2) and, as a HYPOTHESIS to be
measured, the same bits on CPU, CUDA and Metal (class D1). Five habits destroy that silently: platform
transcendental functions (they differ across libraries and GPUs), floating-point atomics (the main source of GPU
nondeterminism, FACT), multiply-add fusion (compilers contract a·b + c by default on some backends), fast-math
relaxations, and backend intrinsics scattered through sources. A rule that is only written down decays, so the
rules are enforced by a tool that rejects the source with refusal `FROB-REF-251` before any compiler sees it.

FACT: two habits of the suite's piano renderer are deliberately not inherited. It compiles its CUDA source with
multiply-add fusion on and builds its double-float product on `fmaf` and `fma` (`cuda.rs`, `metal.rs`); and it
steps a whole stretch in one persistent launch whose thread groups meet at an atomic grid barrier, which on Metal
"very rarely" leaves one group unscheduled, "about once per few hundred launches", so the host reruns the stretch
(`metal.rs`). Rules 4 and 6 below remove both (ADR-SPARK-09: kernels never use a grid-wide barrier; ADR-SPARK-10:
no fused multiply-add). Tier: Solid.

## Scope

In: the two preludes (version 0), the dialect file layout, the compile-option sets, the lint engine, and lint
rules 1, 2, 3, 4 and 6 of the nine dialect rules, with their planted negative controls.
Out: rules 5, 7, 8 and 9, the lint of Rust kernel sources, and the wiring of the lint into every compile path
(N21a-10); the `det_*` elementary functions (N21a-11); the IR and its emitters (BD-018); driver loading and
compilation (BD-015 for CUDA, BD-016 for Metal); the three-backend run of `K-cay-step` (BD-020).

## Technical approach

**The nine dialect rules (all nine stated here; this bead enforces 1, 2, 3, 4, 6).**

1. No backend intrinsic outside the prelude.
2. No floating-point atomics. Integer atomics are allowed only for operations whose result does not depend on
   arrival order: maximum, minimum, bitwise or, and wrapping addition.
3. No built-in transcendental functions and no reciprocal-square-root built-in. Elementary functions are `det_*`
   functions written in the dialect itself, ported from the deterministic set of FrankenSim's `fs-math`.
4. Floating-point contraction off; no fast-math relaxations; no explicit fused multiply-add.
5. Explicit loop bounds that are literals or capacity constants of the shape class, unsigned 32-bit indices, no
   recursion, no pointer arithmetic beyond buffer plus index.
6. No grid-wide barrier. A stage that needs every world to finish before the next begins is two launches.
7. Integer arithmetic in exact kernels is unsigned and 32 bits wide; shift counts are masked. Signed overflow is
   undefined in both source languages and is therefore unreachable by construction. Sixty-four-bit integers and
   atomics are used only where the hardware fingerprint records them for every device family in use.
8. A mask is a select, never an arithmetic blend: m·a + (1 − m)·b turns an infinity in the unselected arm into NaN.
9. Padding trails the active lanes and holds the neutral element of the operation that will consume it.

**File layout (DESIGN).** Dialect text is plain data and may live in the core workspace, which never depends on a
GPU crate: `crates/frob-kernels/dialect/prelude_cuda.h`, `prelude_metal.h`, `skeletons/<kernel>.h`,
`generated/<kernel>_body.h`. A compiled unit is the concatenation: shape-class `#define` lines, one prelude, the
bodies, the skeletons. `FROB_PRELUDE_VERSION` (an integer, 0 here) is part of every kernel-cache key.

**Prelude macros (DESIGN; names are this bead's to fix, the two expansions are the contract).**

| Macro | CUDA expansion | Metal expansion |
|---|---|---|
| `FROB_KERNEL(name)` … `FROB_KERNEL_END` | `extern "C" __global__ void name(` … `)`, then a local `const u32 frob_gid = blockIdx.x * blockDim.x + threadIdx.x; const u32 frob_lid = threadIdx.x;` | `kernel void name(` … `, uint frob_gid [[thread_position_in_grid]], uint frob_lid [[thread_index_in_threadgroup]])` |
| `FROB_BUF(T, name, i)` / `FROB_BUF_RO(T, name, i)` | `T* name` / `const T* name` | `device T* name [[buffer(i)]]` / `device const T* name [[buffer(i)]]` |
| `FROB_FN` | `__device__ static inline` | `static inline` |
| `FROB_PTR(T)` | `T*` | `device T*` |
| `FROB_GROUP_SHARED(T, name, n)` | `__shared__ T name[n];` | `threadgroup T name[n];` |
| `FROB_GROUP_BARRIER()` | `__syncthreads()` | `threadgroup_barrier(mem_flags::mem_threadgroup)` |
| `FROB_ATOMIC_ADDW_U32`, `_MAX_U32`, `_MIN_U32`, `_OR_U32` `(ptr, v)` | `atomicAdd`, `atomicMax`, `atomicMin`, `atomicOr` on `unsigned int*` | `atomic_fetch_add_explicit` and its max, min, or forms on `device atomic_uint*`, relaxed order |
| `FROB_SQRT(x)` | `sqrtf(x)` | `sqrt(x)` |
| `FROB_SELECT(p, a, b)` | `((p) ? (a) : (b))` | `((p) ? (a) : (b))` |
| Types `f32`, `u32` | `float`, `unsigned int` | `float`, `uint` |

Square root is the one floating-point library call admitted, because IEEE 754 requires it to be correctly rounded;
that is verified per device by the IEEE probe (BD-017), not assumed. There is no macro for a grid-wide barrier, a
floating-point atomic, a fused multiply-add or any transcendental, so a dialect source cannot name one without
breaking rule 1. Metal buffer indices must stay below 31, the gateway's argument limit (FACT:
`ft-kernel-metal` `MAX_ARGUMENTS`).

**Compile-option sets (part of the lint's input).** CUDA: NVRTC with the device architecture (`-arch=sm_89` for an
RTX 4090), `--fmad=false`, and never `--use_fast_math`. Metal: the gateway's `library` call, which compiles under
`MathMode::Safe` (FACT: `frankentorch/crates/ft-kernel-metal/src/compute.rs`; `library_with` selects other modes
and is not used). HYPOTHESIS to settle here: whether the Metal compiler also accepts a source-level
contraction-off pragma inside the prelude; if not, safe mode is the only control. Either way the control is tested
by the contraction detector, not trusted.

**The lint (DESIGN).** A library module `frob_kir::dialect_lint` with
`lint(unit: &DialectUnit, options: &CompileOptions) -> Result<LintReport, Refusal>`. `DialectUnit` marks which
text is prelude (exempt from rule 1) and which is kernel source. It is a library function, not a seventh `xtask`
subcommand: `xtask` is capped at exactly six checks by workspace rule (INV-WS-05), so the lint is called by the
tests of `frob-kernels`, by `xtask check-generated` on generated bodies, and by each backend immediately before
compilation (wired in N21a-10; at M0 the v0 backends call it directly).

Algorithm:
1. Strip comments; tokenize as C (identifiers, numbers, punctuation, preprocessor lines); keep line and column.
2. Rule 1: reject any token from the backend-intrinsic deny list outside prelude text: `__global__`, `__device__`,
   `__shared__`, `__syncthreads`, `blockIdx`, `threadIdx`, `blockDim`, `gridDim`, `atomicAdd` and kin, `kernel`,
   `device`, `threadgroup`, `threadgroup_barrier`, any `[[…]]` attribute, `metal::`, `atomic_*`, `__builtin_*`,
   and any `#pragma` or `#include` other than the prelude include.
3. Rule 2: reject any atomic that is not one of the four `FROB_ATOMIC_*_U32` macros.
4. Rule 3: reject the identifiers `sin cos tan asin acos atan atan2 sinh cosh tanh exp exp2 exp10 expm1 log log2
   log10 log1p pow powr cbrt hypot rsqrt inversesqrt erf tgamma`, each also with an `f` suffix and with `fast::` or
   `precise::` prefixes. Identifiers beginning `det_` are allowed.
5. Rule 4: reject `fma`, `fmaf`, `mad`, `__fmaf_rn` and kin; reject a contraction-on or fast-math pragma; reject a
   CUDA option set that contains `--use_fast_math` or `--fmad=true` or lacks `--fmad=false`; reject a Metal option
   set whose math mode is not safe.
6. Rule 6: reject any `while` or `do` loop (a spin wait is the only way to build a grid barrier from the four
   integer atomics), and any barrier other than `FROB_GROUP_BARRIER`.
7. Report every finding as `{rule, file, line, column, token, message}`; any finding makes the result
   `FROB-REF-251` "a banned operation appears in kernel source (build time)".

**Refusal.** `FROB-REF-251`: exit code 3 at the command line (the numerics family); first repair: use the named
replacement (a `det_*` function, a select, count-scan-write instead of a floating-point atomic, two launches
instead of a grid barrier); retry class `after-change`.

**Determinism and evidence.** The lint is a pure function of its input (class D0). Its report is evidence class
`Tested`. The preludes carry no arithmetic.

## Acceptance criteria

- [ ] `prelude_cuda.h` and `prelude_metal.h` exist; one skeleton source (`K-selftest` or `K-cay-step`) expands through both and compiles on `trj` (NVRTC) and on this Mac (the Metal gateway).
- [ ] The lint rejects, each with `FROB-REF-251` and the right rule number: a built-in transcendental (`sinf(x)`), a floating-point atomic, and a construct that permits fusing a multiply with an add (three forms: explicit `fma`, the option `--fmad=true`, a CUDA option set that omits `--fmad=false`). This is the seed done-condition.
- [ ] The lint rejects a raw `__syncthreads()` outside the prelude (rule 1) and a `while` loop spinning on an atomic (rule 6).
- [ ] The lint accepts `FROB_SQRT`, the four integer atomic macros and every `det_*` identifier.
- [ ] Contraction control is proved on each device: the detector (1 + 2⁻¹²)·(1 + 2⁻¹²) − (1 + 2⁻¹¹) returns exactly 0 through each prelude, and 2⁻²⁴ when a fused operation is planted (run by BD-017's probe; this bead supplies the kernel text and the planted variant).
- [ ] The Metal expansion uses no construct newer than Metal Shading Language 3.1.
- [ ] `CONTRACT.md` of `frob-kernels` documents the nine rules; the lint module has a `tests/conformance.rs`; lint findings are reachable as a structured report from `frob --json` wherever a compile is refused.

## Test plan

### Unit tests (`cargo test -p frob-kir dialect_lint`, `cargo test -p frob-kernels prelude`)
- `lint_rejects_transcendental`: source `f32 y = sinf(x);` → one finding, rule 3, token `sinf`.
- `lint_rejects_rsqrt`: `rsqrt(x)` and `inversesqrt(x)` → rule 3.
- `lint_rejects_float_atomic`: `atomicAdd(&acc_f32, v)` in kernel text → rules 1 and 2.
- `lint_rejects_fma_explicit`: `fmaf(a, b, c)` → rule 4.
- `lint_rejects_contraction_option`: clean source with options `["-arch=sm_89", "--fmad=true"]` → rule 4; with `["-arch=sm_89"]` (flag absent) → rule 4; with `["-arch=sm_89", "--fmad=false"]` → accepted.
- `lint_rejects_fast_math_option`: `--use_fast_math` → rule 4; Metal math mode `fast` → rule 4.
- `lint_rejects_intrinsic_outside_prelude`: `__syncthreads();` in a skeleton → rule 1; the same token inside prelude text → accepted.
- `lint_rejects_spin_loop`: `while (FROB_ATOMIC_MAX_U32(p, 0u) < n) {}` → rule 6.
- `lint_accepts_reference_skeleton`: the checked-in `K-selftest` skeleton has zero findings.
- `lint_reports_positions`: a two-defect source yields two findings with exact line and column.
- `prelude_expansions_differ_only_in_prelude`: the kernel text bytes fed to both backends are identical after the prelude; asserted by digest.

### End-to-end script and logging
Exercised by `scripts/e2e/kernel_toolchain.sh` (bead N21a-25), step `dialect_lint`: it runs the lint over every
checked-in dialect file through `cargo test -p frob-kernels dialect_sources_are_clean`, then over a directory of
planted bad sources, asserting one `FROB-REF-251` per plant with the expected rule. Logged per the shared helper:
`ts`, `script`, `bead`, `step`, `event`, the command line, exit code, wall time, the rule number and token of each
finding, counts of files linted, and a final `summary`. The device half (both preludes compile and run) is logged
by BD-020's script for GATE-SPARK-00.

### Known answers and negative controls
- KA-526 (contraction detector): 0 without contraction, 2⁻²⁴ with; negative control: the fused form itself.
- KA-525 negative control: a prelude with contraction switched on must be reported by the three-backend comparison (BD-020 plants a one-ulp change in one prelude).
- Counterexamples behind the rules: a grid-wide barrier that leaves one thread group unscheduled about once per few hundred launches (CX-221); an arithmetic blend that turns an infinity into NaN (CX-219, enforced in N21a-10); 0.999¹⁰⁰⁰ = 0.37 for "mostly bitwise" unordered scatter (CX-230).
- Planted failures the lint must catch: each of the eleven negative tests above.
- Determinism lanes: the lint report is byte-identical on Linux and macOS and in debug and release.

## Considerations

- A token-level lint can be evaded through macros defined in kernel text; `#define` is therefore rejected outside the prelude and the shape-class constant block.
- The lint proves the absence of banned spellings, not the absence of contraction: a compiler may still fuse. The detector kernel and the IEEE probe are the dynamic half of the control.
- Rule 6 by "no `while` loop" is stricter than the rule needs; N21a-10 replaces it with the full loop-form rule (rule 5).
- OPEN-NUM-1: whether an explicit fused multiply-add is ever admitted in batched kernels. Default: no. Owner: Spark lead. The probe records how each device rounds a fused operation as evidence; the ban does not wait on it.
- RISK-48 (a driver, system or binding update changes kernel results) is why the prelude version and the compile options enter the cache key and the fingerprint.
- Dialect sources have a line cap of 20 thousand lines for the whole library.
