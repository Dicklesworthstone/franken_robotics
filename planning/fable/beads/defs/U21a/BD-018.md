## Background

`frob-kir` is the kernel intermediate representation (IR) of Spark, a layer-1 crate of the core workspace (line cap
14 thousand). It sits between the symbolic derivation engine and the three places a kernel runs. The mathematical
body of a kernel (a Cayley step, an adjoint transport, a cone projection, a Jacobian row) is derived once at build
time by the annex `derive/frob-derive` using FrankenSymPy, lowered to a program in `frob-kir`, and emitted twice:
as Rust for `batch-cpu` (the permanent CPU reference) and as text in the shared dialect (the common subset of CUDA
C++ and Metal Shading Language) for the two device backends. Control structure is not derived; it lives in
hand-written skeletons around the body.

This is construction C-14, "kernels are derived, typed by dimension, and carry certificates": a kernel's arithmetic
is a straight-line program (SLP) over +, −, ×, ÷, √ and selects, generated with common-subexpression elimination;
every value carries its physical dimension as an exponent vector over the base dimensions of FrankenSim's `fs-qty`,
and a program type-checks only if every sum is homogeneous. What it replaces: hand-written kernels with
hand-written derivatives in three languages. What it pays: the same arithmetic on three backends, no dimension
errors, certificates that travel with the code. It is not claimed as a throughput lever.

FACT: FrankenSymPy has expressions, differentiation, Jacobians, simplification and a proof kernel, but no
multi-output code generation with common-subexpression elimination and no GPU emitters, and its bytecode
interpreter caps an expression at 8,192 operations. FrankenRobotics therefore owns the SLP representation and its
emitters; lifting that upstream is work item FD-FSYM-01 (priority P2), and the interim posture is exactly this crate.

ADR-SPARK-02 (DESIGN): the IR has no sine, cosine, exponential, logarithm, power, reciprocal square root or fused
multiply-add, and no approximate mode, because each of those breaks bit parity between backends. Rejected: an IR
with those built in (convenient; incompatible with a three-way parity gate).

Tier: Frontier (derived arithmetic through the IR is under kill gate KILL-KIR: if at M2 the toolchain cannot express
or emit more than 20% of the kernel arithmetic, or emitted kernels miss the speed bound of bet BET-01, arithmetic is
hand-written and bound by differential tests). Version 0 is the M0 spike that makes the pilot (N21a-13) possible.

In (version 0): the program data structure, a canonical serialization with a content hash, the dimension checker
(theorem card T-09, proof obligation PO-SPARK-01), bounded common-subexpression elimination, the Rust emitter, the
dialect emitter, and the `K-cay-step` body as the first emitted kernel.
Out: bounded loops, composite types, loads and stores (N21a-16); unsigned-integer operators and the exact-integer

(N21a-20); double-float pairs (N21a-21); predicate classes and the select lint (BD-053); the derivation itself
(BD-019); the three-backend run (BD-020); certificates (BD-021).

## Technical approach

**Data model (DESIGN sketch).**

```rust
pub enum Ty { F32, F64 /* CPU targets only */, Bool }           // v0; later beads add u32, f32dd, composites
pub struct Dim(/* one i8 exponent per fs-qty base dimension */);
pub enum Op {
    Input { port: PortId },                 // a named scalar input
    Const { bits: u64, ty: Ty, dim: Dim },  // exact bit pattern; +0 and −0 are different constants
    Add(V, V), Sub(V, V), Mul(V, V), Div(V, V), Sqrt(V), Neg(V), Abs(V), Min(V, V), Max(V, V),
    Cmp(CmpOp, V, V),                       // lt, le, eq, ne, ge, gt → Bool
    Select(V, V, V),                        // select(pred, a, b): branchless
}
pub struct Program { name: KernelName, inputs: Vec<Port>, outputs: Vec<(PortId, V)>, nodes: Vec<Node>, meta: Meta }
```

Single assignment: `nodes[i]` may only name operands with index below i. `Min` and `Max` are defined on NaN and on
±0 (a NaN operand yields NaN; min(−0, +0) = −0; max(−0, +0) = +0) and are emitted as explicit selects, never as a
backend built-in, because built-ins differ on NaN and signed zero between languages.

**Canonical form and identity.** `frob.kir/1` is a canonical byte encoding: schema tag, name, ports in declared
order with type and dimension, nodes in index order, outputs, metadata fields in fixed order. The content hash is
BLAKE3 over those bytes. Version 0 metadata: content hash; `math_mode = Ieee754Safe`; operation counts by type;
the CPU reference symbol; the determinism class claimed. Two programs with equal hashes are the same program; the
hash is the basis of the `KernelId` in the kernel manifest.

**Dimension checker (T-09, PO-SPARK-01).** Decided exactly, by integer arithmetic on exponent vectors:
1. `Input`, `Const`: the declared dimension (a constant is dimensionless unless declared otherwise).
2. `Add`, `Sub`, `Min`, `Max`, `Cmp`, and the two value arms of `Select`: operand dimensions must be equal; the
   result has that dimension (`Cmp` yields `Bool`, which has none).
3. `Mul`: exponents add. `Div`: exponents subtract. `Neg`, `Abs`: unchanged.
4. `Sqrt`: every exponent must be even; the result has each exponent halved.
5. Each output's dimension must equal its port's declared dimension.
A violation is `FROB-REF-250` "a kernel is not dimensionally homogeneous (build time)" (N35-REF's row, a
dependency, so the code loads), carrying the kernel, the node index, the two exponent vectors and the source
expression name. Exit code 3; repairs in the row's order: fix the derivation (the diagnostic names the sum);
declare the missing conversion constant with its dimension; the check is never suppressed. Retry class
`after-change`. The vector length is taken from `frob_core::qty` (the only sanctioned path to `fs-qty`), never
hard-coded.

**Common-subexpression elimination (the only rewrite in v0).** Hash-consing while building: a node is keyed by
(operator, operand ids, type); for the commutative operators `Add`, `Mul`, `Min`, `Max` the operand ids are sorted
first, which is exact in IEEE arithmetic. It is *bounded*: the table holds at most a configured number of entries
(default 65,536) and derivation is refused beyond a node budget, so build time and memory are capped. No
reassociation, no distribution, no folding of inexact constant operations.

**Rust emitter.** One function per program: `#[inline] pub fn <name>_body(<inputs>) -> <outputs>` with one
`let vN: f32 = …;` per node in index order, each a single operation. It never emits `mul_add`, never a platform
transcendental, and uses `f32::sqrt` (correctly rounded). The emitted file carries a header with the program hash.

**Dialect emitter.** One `FROB_FN void <name>_body(…)` with one `const f32 vN = …;` per node in the same order,
using only the prelude's macros (`FROB_SQRT`, `FROB_SELECT`, `FROB_F32_BITS`). A `Const` node is written as its
exact bit pattern, `FROB_F32_BITS(0x3e800000u)` for 0.25 and `FROB_F32_BITS(0x80000000u)` for −0.0, never as a
decimal literal (DESIGN: no compiler parses a constant differently, signed zeros survive, and the prelude is the one
place that defines a constant, which BD-020's one-ulp prelude control relies on); the Rust emitter writes the same
constant as `f32::from_bits(0x3e80_0000)`. One operation per statement keeps the evaluation order
identical to the Rust and leaves no compound expression for a compiler to contract. `F64` programs are refused by
this emitter (Metal has no double type): build-time error, not a silent narrowing. The emitted text must pass the
dialect lint of BD-013 with zero findings.

**First kernel: `K-cay-step` body (DESIGN; the derivation in BD-019 must reproduce this program's hash).** State:
a unit quaternion q = (q_w, q_x, q_y, q_z) (dimensionless) and position p in metres. Inputs: body angular velocity
ω in s⁻¹, body linear velocity v in m·s⁻¹, step h in s. With a = h·ω (dimensionless):

- rotation increment as an unnormalized quaternion c = (1, a_x/2, a_y/2, a_z/2); q′ = q ⊗ c (Hamilton product);
- denominator d = 1 + (a·a)/4; the Cayley map cay(â) = (I − â/2)⁻¹(I + â/2) is the rotation of q′/√d;
- translation increment u = (I − â/2)⁻¹(h·v) = (h·v + ½·a × (h·v) + ¼·a·(a·(h·v)))/d;
- p′ = p + R(q)·u, with R(q) the rotation matrix of q written out in products of its components.

Outputs: q′ (unnormalized; the square-root normalization is the separate kernel `K-normalize`), d, and p′. The body
uses only +, −, ×, ÷, so it is a candidate for bit-identical execution on CPU, CUDA and Metal (HYPOTHESIS, measured
by the IEEE probe).

## Acceptance criteria

- [ ] `frob-kir` builds in the core workspace with `unsafe_code = "deny"`, no runtime dependency outside `std` and Franken foundations, and a `CONTRACT.md` with the ten sections.
- [ ] Emits `K-cay-step` as Rust and as dialect text (seed done-condition); the Rust output compiles and the dialect output passes the lint.
- [ ] A seeded dimension violation is rejected with `FROB-REF-250` (seed done-condition): the program `p + a` (metres plus a dimensionless value) and `sqrt(p)` (odd exponent) both fail, each naming the node.
- [ ] The emitted Rust body evaluated on the fixtures below matches the exact values bit for bit in `f32`.
- [ ] CSE: building `(x·y) + (y·x)` yields one multiply node; building `(a + b) + c` and `a + (b + c)` yields two different programs (different hashes).
- [ ] Canonical bytes round-trip (parse(serialize(P)) = P) and the BLAKE3 hash is identical on Linux and macOS.
- [ ] The dialect emitter refuses an `F64` program.
- [ ] The v0 layout of `frob.kir/1` is stated field by field in the crate's `CONTRACT.md` and exported by the crate under that identifier. Printing it with `frob schema frob.kir/1 --json` is N21a-16's criterion, whose dependencies include the schema verb (BD-022); this M0 spike does not wait on the verb layer.

## Test plan

### Unit tests (`cargo test -p frob-kir`)
- `dim_add_requires_equal`: inputs p [L], a [1]; `Add(p, a)` → `FROB-REF-250`, node index reported.
- `dim_mul_div_exponents`: (m·s⁻¹)·s = m; m/s = m·s⁻¹; checked on exponent vectors exactly.
- `dim_sqrt_even_only`: `Sqrt(m²)` = m; `Sqrt(m)` → `FROB-REF-250`.
- `dim_select_arms_equal`: `Select(pred, metres, seconds)` → `FROB-REF-250`.
- `cse_commutative`: `Mul(x, y)` and `Mul(y, x)` are one node; `Sub(x, y)` and `Sub(y, x)` are two.
- `cse_does_not_reassociate`: with `f32` a = 10⁸, b = −10⁸, c = 1: the program (a + b) + c evaluates to 1 and a + (b + c) to 0; the two programs have different hashes and neither is rewritten into the other.
- `const_signed_zero_distinct`: `Const(+0.0)` and `Const(−0.0)` are different nodes.
- `min_max_nan_and_zero`: min(−0, +0) = −0; max(−0, +0) = +0; min(NaN, 1) is NaN; identical in emitted Rust and in the reference interpreter.
- `select_keeps_infinity_out`: `Select(true, 1, +∞)` = 1 exactly (KA-533).
- `cay_step_exact_fixture` (synthetic arithmetic fixture, outside the step's admission bound on purpose): q = (1, 0, 0, 0), a = (0, 0, 1.5), v = 0 → q′ = (1, 0, 0, 0.75), d = 1.5625; after normalization by √d = 1.25: (0.8, 0, 0, 0.6) as the correctly rounded `f32` values.
- `cay_step_small_angle_fixture`: q = (1, 0, 0, 0), ω = (0, 0, 0.2) s⁻¹, h = 1 s → q′/√d = (0.9950372, 0, 0, 0.0995037) to `f32` rounding; rotation angle 2·atan(0.1) = 0.19934 rad, not 0.2 (the Cayley map is second-order).
- `cay_step_translation_fixture`: q = identity, a = 0, v = (1, 2, 3) m·s⁻¹, h = 0.002 s → p′ − p = (0.002, 0.004, 0.006) m as correctly rounded `f32`.
- `emit_rust_matches_interpreter`: 10⁵ seeded random inputs; emitted Rust equals the node-by-node reference interpreter bit for bit.
- `emit_dialect_is_lint_clean`: zero findings from the dialect lint.
- `emit_dialect_refuses_f64`.
- `emit_constants_by_bits`: a program with constants 0.25, −0.0 and 1 emits `FROB_F32_BITS(0x3e800000u)`,
  `FROB_F32_BITS(0x80000000u)` and `FROB_F32_BITS(0x3f800000u)` in the dialect text and the matching
  `f32::from_bits` calls in Rust; no decimal floating literal appears in either emitted file.
- `canonical_roundtrip_and_hash_stable`: golden hash for the `K-cay-step` program checked in.
- `kir::typecheck_homogeneous_sums` (the property test for PO-SPARK-01, under the name the Spark register N21c-27 binds): 10⁴ random well-typed programs type-check; each of 10⁴ single-edit mutants that changes one input's dimension either still type-checks with all sums homogeneous or is rejected, and no accepted program contains an inhomogeneous sum (checked by an independent exponent recomputation). Its registered negative control: a program adding a length [m] to a velocity [m·s⁻¹] must be refused with `FROB-REF-250`.

### End-to-end script and logging
`scripts/e2e/kernel_toolchain.sh` (bead N21a-25), steps `kir_emit` and `kir_dimension_refusal`: regenerates the
`K-cay-step` body, compares digests with the checked-in files, compiles the Rust, runs the fixtures through
`frob spark check --kernel K-cay-step --backend batch-cpu --key <k> --json` (keyed, as every `run` call is; from
M1 a keyless call is refused with `FROB-REF-805` by N32a-09, and the M0 handler accepts it), and feeds a seeded dimension-violating program to
the build, asserting `FROB-REF-250`. Logged: command lines, exit codes, wall time, program hash, digests of emitted
files, the envelope's evidence block (claim, class `Tested`, tier, determinism, identities, seed), measured values
against expected bit patterns, and on failure the first differing node.

### Known answers and negative controls
- KA-525 (one source, three backends) is completed by BD-020; this bead supplies the CPU half and the fixtures.
- KA-533 (select with an infinity in the unselected arm).
- Negative controls: the seeded dimension violations; the reassociation pair (a = 10⁸, b = −10⁸, c = 1); an emitter mutant that writes two operations in one statement must be caught by the one-operation-per-statement test.
- Metamorphic: renaming inputs changes no arithmetic and only the name fields of the hash input; scaling every length input by 4 and every time by 2 (powers of two) reproduces every significand bit of the outputs.
- Determinism lanes: twice on one machine; debug and release; Linux and macOS (class D2 for the emitted Rust; D1 is claimed nowhere in this bead).

## Considerations

- The quaternion form of `K-cay-step` is DESIGN; if BD-019's derivation chooses another algebraic form, the fixture values stand and the golden hash is regenerated once, by BD-019, with the reason recorded.
- KILL-KIR (decided at M2 by BD-221): fallback is hand-written arithmetic in Rust and the dialect bound by differential tests; the skeleton pattern is unaffected and this crate keeps the dimension checker for hand-written bodies.
- RISK-06 (derived kernels slower than hand-written ones) and RISK-07 (expression swell blocks derivations) are watched from the first kernel: operation counts are in the metadata from v0.
- Derivation is per kernel body, never per whole robot, which keeps programs small.
- Generated files are never edited by hand (INV-SPARK-08); the check is `xtask check-generated`.
