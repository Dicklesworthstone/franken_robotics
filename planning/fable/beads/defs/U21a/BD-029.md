## Background

Every figure in Spark that depends on a machine (launch cost, memory limits, whether 64-bit atomics exist, how a
device rounds) is measured once per machine state and bound to a digest, instead of being assumed. The record is the
**hardware fingerprint**, schema `frob.fingerprint/1`; the verb `spark.fingerprint` measures and writes it. Spark is
the subsystem between a derived kernel and a device result (kernel library, kernel IR, CUDA and Metal backends,
arena, placement planner, kernel cache, fingerprint, CPU-versus-device check).

Why it exists (DESIGN). Four consumers key on it: the binary kernel cache (a compiled binary must never be loaded
after a driver or compiler change), the currency of the CPU-versus-device check (`spark check` must be re-run when
driver, compiler or device family changes), the calibration of the cost and memory estimator `sim.estimate`, and
the disclosure block that every Performance claim must carry. A receipt without a fingerprint digest, or with one
that no longer matches the machine, is refused as evidence (`FROB-REF-606`). Risk RISK-48 (a driver, system or
binding update changes kernel results) is mitigated by exactly this gate. Rejected alternative: hard-coding machine
facts from data sheets; the plan's own facts about these machines are marked as starting values that the
fingerprint must reproduce, and everything else about them (bandwidth, launch costs, peer access) is unmeasured and
is not assumed anywhere.

The two machines: this Mac (an M5 Ultra, Metal device, reached through FrankenTorch's `ft-kernel-metal` gateway)
and `trj` (Linux, two RTX 4090, reached through the pinned `cudarc`). Tier: Solid.

## Technical approach

**Record (DESIGN).** `frob.fingerprint/1`:

```text
machine   host, operating-system build, CPU model, performance and efficiency core counts, memory
device[]  family (cuda | metal), name, stable identifier, architecture, driver, runtime, compiler
          memory: total, free at probe, working-set limit, largest single buffer
          execution width; multiprocessor or GPU-core count
          arithmetic: IEEE probe digest and attainable class; subnormals (ieee | flush | mixed);
                      64-bit integers (yes | no); 64-bit atomics (yes | no); canaries (pass | fail)
          bandwidth: measured GB/s of a stream copy at three sizes around the cache boundary
          launch: empty-kernel launch, graph replay against node count, command-buffer commit and wait,
                  per-dispatch encode cost; each as median and 99th percentile
          compile: cold seconds for K-cay-step; cache-hit milliseconds
          peer: device-to-device access (yes | no | untested); measured rate through the host
          thermal: state at probe and after a 20-minute soak
digest    BLAKE3 over the canonical record
```

Every leaf is a typed value `Measured { value, unit, method }` or `Unavailable { reason }`; there is no third state
and no default. A probe that cannot run on a family (graph replay on Metal, command-buffer commit on CUDA) writes
`Unavailable` with the reason "not applicable to this family", which is a complete field.

**Where the discrete fields come from.**
- Machine: host name, operating-system build string, CPU brand string, core counts by performance class, physical
  memory, from the operating system's own queries (no shelling out to tools whose output format drifts).
- CUDA device (annex `spark/frob-spark-cuda`, through the driver loaded at run time by `cudarc`): device name,
  UUID as the stable identifier, compute capability mapped to the architecture string (`sm_89` for an RTX 4090),
  driver version, NVRTC version as the compiler, total and free memory, multiprocessor count; execution width 32
  (a warp; FACT for CUDA).
- Metal device (annex `spark/frob-spark-metal`, through the gateway): device name and registry identifier,
  `recommended_working_set_bytes` (the working-set limit), `max_buffer_length` (the largest single buffer),
  `allocated_bytes`, `max_threadgroup_memory`, and `thread_execution_width` read from a compiled pipeline (never
  assumed; rule R6 of the Metal readback rules). FACT: the gateway exposes all of these (`ft-kernel-metal` 0.1.3,
  `src/compute.rs`). The compiler field records the Metal language version the gateway compiles under.

**Canonical encoding and digest.** Canonical JSON: sorted keys, integers as integers, rates as decimal strings with
a fixed number of significant digits (4), no timestamps inside the hashed bytes (the measurement time is stored
beside the record). `digest` = BLAKE3 over those bytes; it identifies one measurement, and receipts and disclosure
blocks cite it. Because rates differ by a few percent between runs, the full digest changes on every
re-measurement; the value that says "the same machine state" is the separate `identity` over the discrete subset,
defined by the currency bead N21c-05. This bead stores both fields and computes `digest`.

**The verb.** `frob spark fingerprint [--device <id> | --device all] [--soak 20m | --no-soak] --json`.
1. Enumerate devices of each family present (zero devices of a family is valid and recorded).
2. For each device: read discrete fields; run the arithmetic-feature probes; fetch the IEEE probe digest and class
   if a current probe record exists, otherwise write `Unavailable { reason: "spark probe not yet run" }`.
3. Run the rate probes (each returns median and 99th percentile over a stated repetition count).
4. Unless `--no-soak`: hold the sustained load for 20 minutes and record the thermal state before and after. With
   `--no-soak` the thermal-after field is `Unavailable { reason: "soak skipped by request" }` and the record is
   marked `partial: true`; a partial record cannot be cited by a Performance claim.
5. Canonicalize, hash, write the record to the ledger and to `fingerprints/<digest>.json`; return it in the
   envelope with evidence class `Tested`, determinism `exact` for discrete fields and `measured` for rates.
The verb is cancellable between probes (request, drain, finalize) and holds no device memory afterwards. On a host
with no device it still returns the machine block. Under the default compute envelope (16 GiB, 8 cores, one hour,
one device) the full run fits: the soak is 20 minutes on one device.

**Starting values the fingerprint must reproduce (FACT, from the plan's own record; to be re-measured).** This Mac:
36 CPU cores, an 80-core GPU, 256 GB of unified memory; Metal working-set limit about 222.7 GiB; largest single
buffer about 167.0 GiB; 64-bit atomics reported absent. `trj`: two RTX 4090 of 24 GB (the driver reports 24,564 MiB
each), a PCI host bridge between them and no NVLink. Execution width 32 on both families. A mismatch is not hidden:
the record stores what was measured, and the gate reports the difference.

**Refusals.** `FROB-REF-601` (device unavailable or lost) when a named device cannot be opened: exit code 6,
first repair "rerun on another device". `FROB-REF-606` (fingerprint missing, or changed since admission; exit 6;
first repair `frob spark fingerprint`) is raised by consumers, per the currency bead.

## Acceptance criteria

- [ ] GATE-SPARK-07 (TARGET, M0; the seed done-condition): fingerprints of both machines are **complete** (every field `Measured`, or `Unavailable` with a reason), **repeatable** (two runs agree on every discrete field and within 5% on every rate), and **reproduce the starting values** above; the gate record holds the measured values, the commit and both digests.
- [ ] Negative control for completeness: a record with one leaf removed fails schema validation; a record with a leaf set to a bare zero where the probe did not run fails (the only admissible form is `Unavailable`).
- [ ] Negative control for repeatability: a second record whose driver string differs by one character is reported as a discrete mismatch; a rate perturbed by 6% is reported as outside tolerance.
- [ ] `frob spark fingerprint --json` returns exactly one envelope with the record, exit code 0, on this Mac and on `trj`; `frob schema frob.fingerprint/1` prints the schema.
- [ ] The digest of a stored record recomputes bit for bit on the other machine.
- [ ] A `--no-soak` record is `partial` and is refused by the disclosure-block builder.
- [ ] Cancelling during the soak returns a drained state: no device allocation remains (allocated bytes equal the pre-run figure) and no partial record is written.
- [ ] The record type has a row in the format registry with a round-trip test and a refusal test; `CONTRACT.md` lists the verb.

## Test plan

### Unit tests (`cargo test -p frob-kernels fingerprint`)
- `fingerprint_canonical_bytes_stable`: a fixed synthetic record (label `synthetic`) hashes to a checked-in digest; reordering map keys in the input does not change it.
- `fingerprint_leaf_states`: `Measured` and `Unavailable{reason}` round-trip; an empty reason is rejected.
- `fingerprint_completeness_rejects_missing_leaf` (negative control).
- `fingerprint_compare_discrete_and_rates`: two synthetic records differing by 4.9% on one rate compare `repeatable`; by 5.1%, `not repeatable` naming the field; any discrete difference is reported by field path.
- `fingerprint_starting_values_check`: a record with 36 cores, 80 GPU cores, 256 GB, 222.7 GiB (±1%), 167.0 GiB (±1%) passes; one with 32 execution width replaced by 16 fails naming the field.
- `fingerprint_timestamps_outside_hash`: changing the stored measurement time leaves `digest` unchanged.
- On hardware (run by the gate script): `cuda_discrete_fields_present`, `metal_discrete_fields_present`.

### End-to-end script and logging
`scripts/e2e/spark_fingerprint.sh` (the lifecycle script is carried by the end-to-end bead of the fingerprint
subsection; this bead's steps are `measure_a`, `measure_b`, `compare`, `starting_values`). It runs
`frob spark fingerprint --device all --json` twice on each machine, compares the two records field by field, and
checks the starting values. Every NDJSON line has `ts`, `script`, `bead`, `step`, `event`, the exact command line,
exit code, wall time, the envelope's `evidence` block, each rate with its unit and the 5% threshold, both digests,
and on failure the first differing field path with both values. A final `summary` line gives assertion counts and
`gates: ["GATE-SPARK-07"]`. Logs contain machine facts only, no scene data.

### Known answers and negative controls
- KA-546: the starting values; tolerance: discrete fields equal, rates within 5% between runs.
- Negative controls: the missing-leaf record, the one-character driver change, the 6% rate change.
- Determinism lanes: discrete fields identical twice on one machine and in debug and release builds; rates within 5%.

## Considerations

- OPEN-SPARK-6 (whether the two RTX 4090 of `trj` allow device-to-device access): decided by the `peer` field. Default until measured: host-staged transfers of small statistics only. Owner: Spark lead.
- OPEN-SPARK-2 (the compute envelope): default class E0 (16 GiB, 8 cores, one hour, one device); the fingerprint fits inside it.
- `trj` is often heavily loaded (FACT); its rate probes record host load, and a run under heavy load may fail the 5% repeatability clause. The gate then records the load and is re-run; it is not waived.
- The Mac's working-set limit feeds the device memory budget (85% of it by default, about 189 GiB); a changed limit changes admission decisions, which is why it is a discrete field.
- Privacy: host name and device UUID are machine identifiers; they stay in the local ledger and are replaced by a salted hash in any exported disclosure block.
- 64-bit atomics on Metal are reported absent by a recorded compile probe; the fingerprint re-runs that probe, and kernels of a mixed run use no 64-bit atomic unless every device family in use records them.
