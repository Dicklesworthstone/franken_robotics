## Background

A **predicate** is the sign of an expression where the sign selects between outcomes that differ at the boundary:
is this contact active, did the joint reach its limit, does the requirement hold, which key sorts first. Decided in
bare floating point, such a predicate is wrong exactly where it matters. The smallest case: is 16,777,216 less than
16,777,217? In integers, yes. In `f32` the second number (2²⁴ + 1) is not representable and rounds to the first, so
the strict comparison is false.

ADR-SPARK-03 (DESIGN): there are three kernel classes, floating, exact-integer and guarded; a strict predicate or a
digest is never computed in bare floating point; representation is chosen before placement. Reason, FACT as
recorded by a plan-time pilot (to be reproduced at GATE-SPARK-08 before any gate cites it): a one-inequality
boundary classifier with inputs on a grid of 2⁻²⁸ ran as a real Metal command buffer on the M5 Ultra and as a CUDA
kernel on each RTX 4090. On a 65,536-row grid dense near the boundary, the bare `f32` sign of the residual gave 452
false inclusions and 23,438 false exclusions (23,890 of 65,536, 36%), identically on every device. An exact
unsigned-integer kernel returned every label correctly on all three GPUs with identical bytes. A guarded `f32`
kernel that deferred to exact arithmetic whenever the absolute residual was at most 2⁻²¹ (its conversion and
addition sequence bounds the error by 5·2⁻²⁵) decided none of the dense grid on the device and 58,254 of 65,536 rows
of a more widely spaced grid, with no error after fallback. Rejected alternative: a tuned epsilon ("treat anything
within 10⁻⁶ as equal"), which moves the wrong answers instead of removing them and cannot be certified.

Why a class and not a habit: a habit decays under refactoring; a class is a field of the kernel manifest and a
build error when violated (`FROB-REF-252`). This bead puts the class into the kernel IR `frob-kir` (the typed
single-assignment representation from which kernel arithmetic is emitted as Rust and as GPU dialect text). The
probe kernels `K-x-pred` and `K-g-pred` themselves, hand-built at M0, are bead BD-030; here they become products of
the toolchain. Tier: Solid. Determinism: a predicate's decision is class D0 (exact) on every backend.

## Scope

In: the predicate class on `Cmp` and `Select` nodes; the select lint; derivation of the certified error bound for
guarded predicates (PO-SPARK-02, PO-MARROW-06); generation of the exact integer fallback program and its bit
budget (`FROB-REF-215`); the fallback-fraction counter; the 0.3, 0.4, 0.5 fixture.
Out: the unsigned-integer operators the fallback is written in (N21a-17, a dependency); the M0 hand-built probe
kernels and the boundary corpus (BD-030); the device battery over the contact predicates and KILL-MARROW-GUARD
(BD-182); the planner rule that keeps small host-resident predicates on the host (BD-178); the four-class manifest
rules and the `stat` class (N21a-22).

## Technical approach

**Predicate classes (DESIGN).** Every `Cmp` node whose result reaches a `Select` or an output carries one of:

| Class | Arithmetic | Admitted when |
|---|---|---|
| `Exact` | Unsigned 32-bit integer limbs under math mode `ExactInteger` | Always |
| `Guarded` | An `f32` residual r̂ with a certified bound, plus an `Exact` fallback on the same stored inputs | The residual is a polynomial of low degree in `f32` inputs with declared ranges |
| `Plain` | `f32` | Only where the two arms of the select agree at the boundary (clamp, max, a Huber kink), so a wrong sign moves the result continuously and changes no discrete outcome |

**The select lint.** A `Select(pred, a, b)` whose predicate is `Plain` is admitted only if one of these holds:
(1) it is one of the IR's own continuous operators (`Min`, `Max`, `Abs`, `Clip`), which lower to selects whose arms
are equal on the boundary by construction; or (2) it carries a *continuity witness*: a polynomial identity
a − b = r·k for the predicate residual r and some polynomial k, checked at build time by the derivation tool, which
shows the arms coincide on r = 0. Anything else is build error `FROB-REF-252` "a strict predicate in floating point
without an exact form or a certified guard" (exit code 3; first repair: declare the predicate `Guarded` with input
ranges; second: move it to an `Exact` kernel; retry `after-change`). A `Cmp` that feeds an output directly (a
verdict, a flag) is never `Plain`.

**The guarded evaluation.** For a residual polynomial p in stored `f32` inputs:
1. Evaluate p̂ in `f32`, and in the same pass a bound E.
2. If |p̂| > E the sign of p̂ is the sign of p, and the kernel decides.
3. Otherwise the case is emitted to the exact program, which evaluates p exactly on the same stored inputs.
4. The fallback count and the evaluation count are written to the receipt; their ratio is the **fallback fraction**.

**Deriving the bound (PO-SPARK-02: a guard is proved, not tuned).** Forward error analysis over the actual
straight-line program, with unit round-off u = 2⁻²⁴. Each node carries a range (from the declared input ranges)
and an absolute error bound e. The rounding of one operation whose exact result lies in a range whose magnitude
bound falls in the binade [2^k, 2^(k+1)] is at most ρ = 2^(k−24) (half the spacing 2^(k−23) of that binade; an
exact power of two at the top of the range is representable), which is never larger than the relative form
u·|result| and is tighter by up to a factor of two:
- each input carries error 0 and its declared range; a conversion from an integer grid carries ρ of its range;
- `Add`, `Sub`: e = e_x + e_y + ρ(range of x ± y), and ρ = 0 when the operation is exact: a subtraction whose
  operands are within a factor of two of each other (Sterbenz) on the part of the range where the guard decides
  (|p̂| small); on the rest of the range the derivation proves the sign separately (the computed magnitude exceeds
  the accumulated error there, as in BD-030's analysis, where r̂ ≥ ½ outside the Sterbenz domain);
- `Mul`: e = |x|·e_y + |y|·e_x + e_x·e_y + ρ(range of x·y); a multiplication by a power of two adds no rounding of
  its own (exact unless it overflows or underflows, both excluded by the declared ranges), so it only scales e;
- to stay valid on a device that flushes subnormals (FACT: the Metal language specification permits it), an
  operation whose result range meets (0, 2⁻¹²⁶) adds an absolute slack of 2⁻¹²⁶ (the smallest normal `f32`); an
  operation whose results are all zero or normal adds none.
For the boundary classifier's residual r̂ = (Û + ½) − 4ε̂ these rules give 2⁻²⁵ (Û in [½, 1]) + 4·2⁻²⁶ (ε̂ in
[0, ½], scaled exactly by 4) + 2⁻²⁴ (Û + ½ in [1, 1.5]) + 0 (Sterbenz on the guard band) = 5·2⁻²⁵, with no slack
(no node's range meets the subnormals). DESIGN, the reason for the binade form: the plain relative model (u·|result|
on every operation, the power-of-two multiplication rounded too, slack everywhere) gives 2⁻²¹ + 5·2⁻¹²⁶ for the
same program, above the threshold 2⁻²¹, so the pilot's guard would be refused.
Two emitted forms: a **static** ε computed from the declared ranges (a constant in the manifest; the pilot's
5·2⁻²⁵ is of this form, used with threshold 2⁻²¹), and a **running** E = c·u·S, where S is the sum of the absolute
values of the terms evaluated in the same pass and c is a constant derived from the program and stored in the
manifest. The derivation emits the analysis as a certificate input (classed `Certified` once the certificate
checker replays it) and PO-MARROW-06 requires that E is valid for all inputs in the declared ranges. Registration
compares the threshold with the derived bound: a guarded predicate whose threshold τ is below its derived static ε
(or whose running form is compared against less than E) is refused, the IR-side form of BD-030's manifest rule
τ ≥ ε_g.

**The exact fallback.** Every finite `f32` is an integer of at most 24 bits times a power of two, so a polynomial in
such numbers is an integer computation after aligning exponents. It is carried out in 32-bit limbs with widening
multiplies (`mulhi`), which exist identically on CPU, CUDA and Metal. The bit budget is computed at derivation
time from the declared ranges; a predicate whose budget exceeds 256 bits is refused at build time with
`FROB-REF-215` (exit code 3; repair: rescale the predicate), which keeps the fallback a fixed, small integer
program on every backend. "Exact" means exact with respect to the stored single-precision inputs: two backends
with bit-equal inputs take the same branch. It says nothing about how well the inputs approximate real quantities.

**Worked fixture (FACT, recomputed for this bead in exact rational arithmetic).** Take the `f32` numbers nearest
0.3, 0.4 and 0.5 as x, y, z and test x² + y² ≤ z². Their significands are x = 10,066,330·2⁻²⁵,
y = 13,421,773·2⁻²⁵, z = 16,777,216·2⁻²⁵. In `f32`, fl(x²) + fl(y²) rounds to 0.25 and z² = 0.25, so the plain test
reports the point inside the cone. Exactly, 10,066,330² + 13,421,773² − 16,777,216² = +13,421,773, so
x² + y² − z² = 13,421,773·2⁻⁵⁰ ≈ +1.19·10⁻⁸: the point is outside. The guarded kernel has |p̂| = 0 ≤ E, falls back,
and returns "outside". The fallback needs 50 bits: two limbs.

**Manifest fields added.** Per predicate: class, residual program hash, bound form (`static ε` or `running c`),
declared input ranges, fallback program hash, bit budget. Per run (receipt): evaluations, fallbacks.

## Acceptance criteria

- [ ] Single-precision 0.3, 0.4, 0.5 in x² + y² ≤ z² returns the exact sign (outside; residual +13,421,773·2⁻⁵⁰) from the generated guarded kernel on `batch-cpu`; the plain `f32` evaluation returns the wrong sign and is used as the negative control (seed done-condition).
- [ ] PO-MARROW-06 holds for each guarded predicate in the registry: the emitted bound is re-derived by the derivation tool and is never smaller than the true error on the adversarial corpus (seed done-condition).
- [ ] An unguarded strict predicate fails the lint with `FROB-REF-252` naming the node (seed done-condition); a clamp and a `Max` pass; a select with a valid continuity witness passes and one with a forged witness fails.
- [ ] PO-SPARK-02: for the boundary-classifier residual, the derived static bound is 5·2⁻²⁵ (at most that) and the exhaustive check over the 2 × 65,536-row boundary corpus finds no input with |r̂| > ε and the wrong sign (the register's test `guard::sign_agrees_above_epsilon_boundary_corpus`, N21c-27, run on the generated kernel).
- [ ] A guarded predicate registered with a threshold below its derived bound (the pilot residual with τ = 2⁻²⁶ against ε = 5·2⁻²⁵) is refused at registration; τ = 2⁻²¹ is accepted (PO-SPARK-02's negative control in N21c-27).
- [ ] Negative control for the bound: the same bound scaled by ½ is rejected by the exhaustive check.
- [ ] A predicate whose fallback needs more than 256 bits is refused with `FROB-REF-215` at build time.
- [ ] The generated exact fallback returns identical bytes on `batch-cpu` and (through BD-030's harness) on both RTX 4090 and Metal; the fallback fraction is reported in the receipt (contributes to GATE-SPARK-08).
- [ ] Manifest fields are present and schema-valid; `CONTRACT.md` of `frob-kir` documents the three classes.

## Test plan

### Unit tests (`cargo test -p frob-kir predicate`)
- `strict_predicate_2p24`: exact and guarded forms of 16,777,216 < 16,777,217 return true; the plain `f32` form returns false (KA-529).
- `cone_fixture_03_04_05`: as above; asserts the integer residual 13,421,773 and the decision "outside".
- `lint_plain_strict_select_fails`: `Select(Cmp(lt, r, 0), label_a, label_b)` with unequal constant arms → `FROB-REF-252`.
- `lint_plain_clamp_passes`, `lint_plain_max_passes`.
- `lint_continuity_witness`: arms a = r·k + b pass; arms a = r·k + b + 1 with the same witness fail.
- `lint_cmp_to_output_is_never_plain`.
- `bound_static_pilot_sequence`: the conversion-and-addition residual of the boundary classifier yields ε = 5·2⁻²⁵ (the multiplication by 4 and the guard-band subtraction add no rounding; no slack term).
- `bound_relative_model_too_loose` (DESIGN check of the rule choice): the same program under the plain relative model gives 2⁻²¹ + 5·2⁻¹²⁶, above τ.
- `bound_pow2_mul_adds_nothing`: x·4 and x·2⁻³ add no rounding term; x·3 does.
- `bound_slack_only_near_subnormals`: a node with range [2⁻¹⁰, 1] adds no 2⁻¹²⁶ slack; a node with range [0, 2⁻¹²⁰] does.
- `threshold_below_derived_bound_refused`: τ = 2⁻²⁶ refused, τ = 2⁻²¹ accepted for the pilot residual.
- `bound_running_is_sound` (property test for PO-SPARK-02 and PO-MARROW-06): for 10⁶ random inputs in range and 10⁶ adversarial inputs placed within 4 ulp of the zero set, |p̂ − p| ≤ E with p computed in exact rationals.
- `bound_half_is_unsound` (negative control): with E/2 the property test finds a counterexample.
- `bound_includes_underflow_slack`: a residual whose terms underflow still satisfies the bound when subnormal results are replaced by zero.
- `fallback_bit_budget`: degree-2 polynomial in three inputs with exponent spread 0 → 50 bits, 2 limbs; a degree-12 polynomial → over 256 bits → `FROB-REF-215`.
- `fallback_matches_rational`: 10⁶ inputs; the limb program's sign equals the sign from exact rational arithmetic.
- `fallback_fraction_counted`: on the wide grid fixture the counter equals the number of rows with |p̂| ≤ ε.

### End-to-end script and logging
`scripts/e2e/spark_probe.sh` (bead N21b-40, which lists this bead's kernels among its extension steps) runs
`frob spark probe --suite boundary --device <b> --key <k> --json` (a run verb: a distinct key per device and run,
in the script's key scheme) on `batch-cpu`, each RTX 4090 and Metal. For this bead it asserts: zero sign errors for the exact and guarded
kernels, identical output digests across backends, the bare `f32` kernel mislabels at least one row, and the
fallback fraction is present. Logged per line: command, exit code, wall time, evidence block, counts (rows, errors,
fallbacks), digests, thresholds; on failure the first mislabeled row with its three inputs.

### Known answers and negative controls
- KA-529 (2²⁴ < 2²⁴ + 1), KA-530 (boundary corpus; exact: zero errors; guarded: zero errors after fallback; bare `f32` must mislabel at least one row), KA-531 (the guard: sign of r̂ equals sign of r when |r̂| > ε; pilot bound 5·2⁻²⁵ against threshold 2⁻²¹).
- CX-216 (bare `f32` comparison), CX-123 (the 0.3, 0.4, 0.5 cone point).
- Law (Marrow): a `Guarded` predicate returns the sign of its exact evaluation on the stored inputs, for every input.
- Metamorphic: scaling all inputs of a homogeneous predicate by a power of two changes no decision.
- Determinism lanes: decisions byte-identical twice on one machine, across worker counts, debug and release, and across backends (class D0).

## Considerations

- Under class D3 (inputs that differ within a tolerance between tiers) two tiers may legitimately take different branches near a boundary; the decision-level equivalence test counts those. Exactness here is about stored inputs.
- KILL-MARROW-GUARD (decided at M2 by BD-182): fallback rate above 10⁻² on the contact battery on either GPU backend, or an exact path that cannot be made bit-identical across backends. Fallback: strict predicates evaluated exactly only on the strict `batch-cpu` profile and the referee; GPU tiers mark worlds that came within E of a boundary and the sampled referee re-runs them. Target fallback rate: below 10⁻³ of evaluations.
- OPEN-MARROW-3: whether the fallback may use 64-bit integers where a backend offers them. Default: 32-bit limbs everywhere, so the three backends run the same integer program. Owner: Marrow lead.
- OPEN-ARENA-5: the guard band for requirement atoms on each backend. Default 2⁻²¹ with CPU re-evaluation of every flagged atom.
- Placement lesson from the same pilot (CX-217): end to end, the host integer loop was faster than any device (about 34 µs against about 290 µs on Metal, of which under 13 µs was device time, and over 1.2 ms on one RTX 4090). Representation is chosen first; placement follows where the data already lives.
- A fused multiply-add would evaluate a third rounding sequence for the cone fixture, one more reason contraction is off everywhere.
