## Background

Three device services sit under every Spark run and are easy to get subtly wrong: where device memory comes from,
when the host may look at it, and which compiled binary is loaded. ADR-SPARK-06 (DESIGN) fixes all three: **one
arena per bucket, allocated once, read by the host only under a lease; compiled binaries live in a
content-addressed cache keyed by the hardware fingerprint.** Reasons: no allocation in the hot path; no stale
binary after a driver change. (A bucket is one shape class on one device: one arena, one compiled kernel set, one
step plan, one launch graph.)

What each rule prevents. *Allocation in the hot path* causes latency spikes, fragmentation and leaks under
cancellation; the invariant is that after environment creation there is no device allocation at all
(INV-SPARK-03). *Unfenced host reads* see half-written state: on unified memory the temptation is a live zero-copy
read of GPU state, but shared storage must be quiescent before the other processor reads it (FACT: Apple's
documentation), and the data are tiny anyway (a humanoid's integration state is about 540 bytes, so shadowing 256
worlds at 50 Hz moves 6.9 MB/s); the invariant is that the host reads only committed epochs (INV-SPARK-06).
*A stale binary* silently computes with an old compiler's code. FACT: the suite's renderer caches CUDA binaries
under a key built from Rust's default hasher over source and options plus the architecture name, written aside
and renamed; a compile takes about 5 s on an idle host and can take 15 minutes on a heavily loaded one. The
default hasher is not stable across toolchains, so it is not used here.

Rejected alternatives: copy-on-write forks of device world state (state is write-dense: every step rewrites every
world's configuration, velocity, contacts and warm starts, so a fork has copied everything after one step and
paid for indirection in every read; the whole copy is small: 8,192 worlds at 30 kB are 0.25 GB, about half a
millisecond of traffic at an RTX 4090's memory bandwidth); live zero-copy host reads; a cache keyed by an unstable
hash. Tier: Solid.

This is the seed bead for the three services together and the place GATE-SPARK-11 closes. The mechanisms are also
drafted as sub-beads by the unit that owns the arena subsection (named in `needs`); this bead states each
mechanism in full so that it stands alone, and integrates them on both backends.

## Technical approach

**1. The arena.** Every per-world quantity lives in preallocated structure-of-arrays slabs aligned to 256 bytes:
state (configuration, velocity, anchors, warm starts, actuator and battery state), kinematic and dynamic cache,
rows, contacts, variant and scene tables, rollout storage, policy weights and optimizer state, the statistics
ring, the two committed slabs, the snapshot slab and the control block. Slabs are packed into few device buffers
so that every kernel stays under the argument limit (31 buffer arguments on a Metal compute function), and no slab
exceeds the device's largest buffer (about 167.0 GiB on this Mac; the device budget there is the working-set limit
less a host reserve, by default 85% of about 222.7 GiB). Sizes come from the byte model (per world, `f32`: about
35 kB for the reference quadruped and about 97 kB for the reference humanoid) and are refused before allocation if
they exceed the device budget (`FROB-REF-602`, exit code 6; first repair: fewer worlds, a smaller capacity, or the
Mac). After environment creation there is no device allocation (INV-SPARK-03); the backend exposes an
allocated-bytes counter, and transient needs (snapshot staging, readback) are met from the stream-ordered pool on
CUDA or from slabs reserved in the arena.

**2. Leases.**

```rust
// DESIGN: intent, not signatures.
enum Access { Device, HostRead, HostWrite }
struct SlabLease { slab: SlabId, epoch: u64, access: Access }   // valid only while `epoch` is the committed epoch
```

A host-read lease exists only on the current committed slab, the snapshot slab and the previous slot of the
double-buffered ring, so diagnostics read epoch e − 1 while the device writes epoch e. A host-write lease (resets
by the host, admission of a model variant into a free slot) exists only between chunks. On Metal the lease is the
borrow the gateway already enforces (a batch holds each output by exclusive borrow until it returns; compile-fail
tests exist upstream); on CUDA it is a run-time epoch check around stream-ordered copies. A violation is
`FROB-REF-614` "host access to a slab outside its lease" (exit code 6; first repair: read the committed or
snapshot slab). The **residency map** (printed by `spark.place`) lists where each slab lives, its size, its last
committed epoch and who may read it.

**3. The binary kernel cache.**
- *Key*: BLAKE3 over the expanded dialect text, compile options, prelude version, compiler identity, device
  architecture and driver version.
- *Value*: on CUDA a compiled binary (CUBIN). On Metal the expanded source and its digest, because the gateway
  compiles from source only; a precompiled archive is part of upstream work item FD-FT-01 (in FrankenTorch's
  repository), and a warm start there recompiles from cached source.
- *Verification*: a hit is checked against its digest before use; a corrupt entry is a miss. An offline host that
  cannot recompile refuses with `FROB-REF-612` "kernel cache entry corrupt and recompilation unavailable" (exit
  code 6; first repair: `spark precompile` on a build host).
- *Store*: content-addressed directory, entries written aside and renamed, safe to copy between hosts; size capped
  (4 GiB by default); eviction prefers entries that are cheap to recompile (recorded compile seconds per entry).
- *Invalidation*: a change of compiler or driver changes the key, so the old binary is never loaded; it also
  marks the CPU-versus-device check stale for the affected kernels.
- *Admission*: an entry is stored only for a unit that passed the dialect lint.

**4. Verbs.**
- `frob spark precompile <shape-class | arch> [--backend B] --json` (kind `run`): compile or load the kernel set
  of a shape class. `frob spark precompile sm_89` fills the cache on a host without a GPU (NVRTC needs no device).
  Result: per kernel `hit | compiled | failed`, compile seconds, key, entry size. Refusals: `FROB-REF-603` (compile
  failure, diagnostics verbatim), `FROB-REF-612`.
- `frob spark cache [list | verify | evict <key|--to-size N>] --json` (kind `read`; `evict` and `verify --repair`
  are `admin`): contents (key, kernel, backend, architecture, compiler, driver, bytes, compile seconds, last use),
  hit and miss counts, eviction history. Long listings are paginated and say so.

**5. Warm start.** With a populated cache, environment creation performs zero compiler invocations: the backend
counts NVRTC calls (and, on Metal, records source-cache hits; the Metal compiler still runs from cached source
until upstream work lands, which is reported separately and is not counted as a cache miss of ours).

## Acceptance criteria

- [ ] GATE-SPARK-11 (TARGET, M2; the seed done-condition), recorded with measured values on CUDA and on Metal: allocated device bytes are flat over 10⁶ steps; a warm start loads every kernel with zero compiler invocations; each cache control is caught.
- [ ] Cache controls (KA-536): a one-byte change of source, of options, of compiler identity or of driver identity is each a miss; negative control: a corrupted entry is rejected by digest (and is a miss, or `FROB-REF-612` when offline).
- [ ] Negative control for the allocation invariant: one planted device allocation in a hot-path launch moves the allocated-bytes counter and fails the flat-allocation test.
- [ ] Leases: a host read of the slab being written is refused with `FROB-REF-614` on CUDA (run-time epoch check) and does not compile on Metal (compile-fail test); a host write inside a chunk is refused; reads of epoch e − 1 succeed while epoch e is written.
- [ ] Memory admission: a job whose estimate exceeds the device budget is refused with `FROB-REF-602` before any allocation (allocated bytes unchanged).
- [ ] No slab exceeds the device's largest buffer; every kernel's buffer-argument count on Metal is at most 31 after packing.
- [ ] `spark.cache` and `spark.precompile` return one envelope each with documented schemas and exit codes, through `frob --json` and as generated agent tools; `frob spark precompile sm_89` succeeds on a host with no GPU.
- [ ] The cache directory copied from `trj` to another Linux host of the same driver and architecture gives hits there; eviction keeps total size under the cap and removes cheap-to-recompile entries first.
- [ ] `CONTRACT.md` sections for the arena, leases and cache; cancellation tested (a cancelled precompile leaves no partial entry).

## Test plan

### Unit tests
- `arena_alignment_256`: every slab offset is a multiple of 256.
- `arena_packing_respects_limits`: with a 31-argument limit and a largest-buffer limit from a fixture fingerprint, the planner's packing satisfies both; a catalogue that cannot fit is refused with the limiting slab named.
- `arena_bytes_match_byte_model`: for the quadruped workload the per-world total is within 5% of 35 kB; for the humanoid, of 97 kB.
- `lease_valid_only_for_committed_epoch`; `lease_host_read_set` (committed slab, snapshot slab, previous ring slot only); `lease_host_write_only_between_chunks`; `lease_violation_is_614`.
- `cache_key_changes_with_each_input`: six one-byte perturbations (text, options, prelude version, compiler, architecture, driver), six different keys.
- `cache_hit_verifies_digest`; `cache_corrupt_entry_is_miss`; `cache_corrupt_offline_is_612`; `cache_write_is_atomic` (a crash between write and rename leaves no visible entry); `cache_refuses_unlinted_unit`.
- `cache_eviction_prefers_cheap`: entries with compile seconds (1, 5, 300) under a cap that forces one eviction: the 1 s entry goes.
- `precompile_reports_per_kernel`; `precompile_cancel_leaves_no_partial`.
- On hardware: `allocated_bytes_flat_1e6_steps` (gate lane), `warm_start_zero_compiler_invocations`, `planted_allocation_is_caught` (negative control).
- Property test (INV-SPARK-06): for random interleavings of chunk commits and host lease requests, every granted read lease names an epoch that was committed at grant time.

### End-to-end script and logging
`scripts/e2e/spark_gate11_arena_cache.sh` (carried by the end-to-end bead named in `needs`; this bead's steps):
`precompile_cold`, `precompile_warm` (expects zero compiler invocations), `cache_controls` (the four one-byte
changes and the corruption), `run_1e6_steps` (`frob sim run --tier gpu-cuda|gpu-metal --workload Q --steps 1000000
--json`, reading the allocated-bytes series from the receipt), `lease_violation` (a debug hook requests an illegal
read and expects `FROB-REF-614`), `oversize_job` (expects `FROB-REF-602`). Logged per line: `ts`, `script`, `bead`,
`step`, `event`, the exact command line, exit code, wall time, the envelope's `evidence` block, measured values
with thresholds (allocated-bytes minimum and maximum; compiler invocations 0; cache hits and misses), refusal
codes with repairs, and on failure the first step at which the counter moved. Final `summary` with
`gates: ["GATE-SPARK-11"]`.

### Known answers and negative controls
- KA-536 (cache: one-byte change is a miss; warm start with zero compiler invocations; negative control: a corrupted entry rejected by digest).
- KA-543 (allocated device bytes flat over 10⁶ steps); negative control: the planted allocation.
- CX-226 (copy-on-write forks of device state) and CX-229 (live zero-copy reads on unified memory) are the rejected shortcuts; a lease test reproduces the second as a refused read.
- Determinism lanes: cache keys identical on Linux and macOS for identical inputs; a run from a cold cache and a run from a warm cache produce identical per-world digests.

## Considerations

- The cache is part of the supply chain: an entry is trusted only by digest, and kernel-cache integrity is also covered by the supply-chain bead. A cache copied from an untrusted host is safe to load only because every entry is verified against the key recomputed locally.
- On Metal the "warm start" clause cannot mean zero Metal compilations until upstream work adds binary archives; the gate records our cache's hits and the gateway's compile time separately, and the gap is named in the disclosure block.
- Edit-to-first-step latency (warm, cool and cold paths) reads this cache's behaviour; its targets are measured by its own bead.
- OPEN-SPARK-2: 10⁶ steps at 8,192 worlds at the interim floor of 2.0 M world-steps/s takes about an hour on one device, at the edge of the default envelope; the gate run uses fewer worlds (the invariant is per allocation, not per world) or an approved gate-measurement envelope, and says which.
- RISK-48 (a driver, system or binding update changes kernel results): the key includes the driver and compiler, and the fingerprint identity change also stales the device check.
