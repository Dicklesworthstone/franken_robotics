## Background

A reduction (a sum, product, minimum or maximum over many values) is where most batch simulators lose bit
reproducibility: the order of floating-point additions changes the result, and the usual GPU idiom, an atomic add,
makes the order depend on thread arrival. Spark bans floating-point atomics outright and replaces unordered scatter
with **stable-key sort followed by segmented reduction**. The arithmetic of that choice: accepting an unordered
scatter that replays bitwise in "99.9% of windows" means a campaign of a thousand windows replays exactly about one
time in three (0.999¹⁰⁰⁰ = 0.37).

Two utility kernels of the library carry every reduction in the system; no stage carries its own:
- `K-reduce`: reduces a fixed-length lane array (per world: over contacts, rows, links; or, for statistics kernels
  only, over worlds).
- `K-seg-reduce`: reduces each segment of a key-sorted array (for example contributions grouped by body).

They must satisfy the system invariant that a world's result does not depend on the batch it ran in: the same bits
alone, at any slot, beside any co-tenants, at any bucket capacity it fits, on any worker count. Two rules deliver
that. **Tree shape is a function of logical index only**: a pairwise tree anchored at index 0 over power-of-two
blocks, so which two active elements are added first depends neither on capacity nor on how a CPU tiles the work.
**Padding neutrality** (INV-NUM-02): padding trails the active lanes and holds the neutral element of the operation
that consumes it. The counterexample that fixes the neutral for sums: the sum of the single active element −0.0 is
−0.0 alone and +0.0 when one +0.0 lane is appended, because (−0.0) + (+0.0) = +0.0; the values compare equal, the
bits differ, and a digest over bits changes with capacity. So the neutral for a sum is −0.0, not +0.0.

Each kernel exists twice, by the project's rule for skeletons: a Rust function for `batch-cpu` (the permanent CPU
reference) and a text skeleton in the shared dialect (the common subset of CUDA C++ and Metal Shading Language).
Tier: Solid. Rejected alternatives: floating-point atomics (order by arrival); a linear left-to-right sum (correct
but its result at capacity N differs in rounding pattern from a tree and cannot be parallelized without changing
bits); trees shaped by tile boundaries (change with the worker count).

## Technical approach

**Conventions (DESIGN; shared by N21a-08, N21a-09 and BD-152).**
- A *lane* is one element slot of a per-world array of capacity N; active lanes are the first n ≤ N; lanes n … N−1
  are padding and hold the neutral element. Capacities are constants of the shape class.
- Masks are selects, never arithmetic blends.
- Neutral table: sum of `f32` → −0.0; product → 1.0; minimum → +∞; maximum → −∞; wrapping `u32` add → 0; `u32`
  maximum → 0; `u32` minimum → 0xFFFFFFFF; bitwise or → 0; two-limb add → (0, 0).
- Tree-shape function: for capacity N let P be the least power of two ≥ N (lanes N … P−1 are treated as neutral
  without being stored). Level 1 combines (2i, 2i+1); level k combines the results of blocks
  [i·2ᵏ, i·2ᵏ + 2ᵏ⁻¹) and [i·2ᵏ + 2ᵏ⁻¹, (i+1)·2ᵏ), left operand first. The result is the root.

**Why the tree is capacity-independent.** For every operator in the table, x ∘ neutral = x bit for bit, for every
x including −0.0, ±∞ and NaN (a + (−0.0) = a; a·1.0 = a; min(a, +∞) = a with the NaN rule below). A block made only
of padding reduces to the neutral. Doubling the capacity therefore wraps the old root as root ∘ neutral = root.

**`K-reduce`.** Inputs: value slab `v[world][0..N)`; operator; output slab `out[world]`. On `batch-cpu`: a loop per
world over the tree levels, with a scratch of P/2 values on the stack. In the dialect: one thread group per world
(or one thread per world with a serial tree when N ≤ 64), levels separated by `FROB_GROUP_BARRIER()`; loop bounds
are literals or capacity constants; no atomics. Minimum and maximum use `det_min` and `det_max` semantics: any NaN
operand gives NaN (which marks the world `Faulted` downstream), min(−0, +0) = −0, max(−0, +0) = +0.

**`K-seg-reduce`.** Inputs: values `v[0..n)` in key-sorted order, segment keys `k[0..n)` non-decreasing (produced
by `K-sort`), an operator, and outputs `out[0..S)` for S segment slots. For each segment with first index s and
length m: the reduction of v[s … s+m) by the same tree-shape function anchored at the segment's own first element
(index within the segment, not within the array), so a segment's result is independent of where it sits and of
what precedes it. Segment boundaries come from the keys by an exact integer comparison k[i] ≠ k[i−1]. Empty
segment slots receive the neutral.

**Two-limb integer sums.** A sum that can exceed 32 bits (integer sums of quantized values, counts beyond 2³²) is
never accumulated by atomics. Each world writes its own `u32` partial, and `K-seg-reduce` or `K-reduce` adds
two-limb values in the fixed tree: (lo, hi) + (lo′, hi′) = ((lo + lo′) mod 2³², hi + hi′ + carry), with
carry = 1 if (lo + lo′) mod 2³² < lo, else 0 (an unsigned comparison). This exists because exact kernels are 32
bits wide and 64-bit atomics cannot be assumed on every device (FACT to recheck: a compile probe reports no 64-bit
atomic add on Metal).

**Compensated variant.** For long accumulations a second operator `sum_dd` carries a double-float pair through the
same tree using the error-free sum; it depends on N21a-21 and is selected by the manifest, never by a flag at run
time.

**Manifests.** Class `float` for `f32` operators (determinism D2 by design, D1 where the device's IEEE probe
allows), class `exact` for integer operators (D0). Numerical contract: the operator and its neutral. Read footprint
`v[world][0..N)`, write footprint `out[world]`; no kernel reads another world's rows, except that a `stat`
instantiation over worlds is declared as such and its output may never feed state.

## Acceptance criteria

- [ ] Rust and dialect implementations exist for both kernels and every operator in the neutral table; the dialect text passes the dialect lint with zero findings.
- [ ] Capacity invariance: for 10⁴ seeded arrays of active length n ∈ {0, 1, 2, 3, 5, 17, 100}, the result at capacities N ∈ {n, n+1, 2n, 64, 256} is bit-identical for every operator.
- [ ] The −0.0 case: one active element −0.0 with trailing padding returns −0.0 (bit pattern 0x80000000) at every capacity.
- [ ] Negative control: a build that pads sums with +0.0 is caught by the capacity-invariance test on the −0.0 case.
- [ ] Segment invariance: a segment's result is unchanged when other segments are added before or after it and when the array capacity changes.
- [ ] Two-limb add: (0xFFFFFFFF, 0) + (1, 0) = (0, 1); the two-limb reduce matches `u64` addition on 10⁶ random pairs and on 10³ arrays of 1,024 values.
- [ ] `batch-cpu` results are bit-identical across worker counts {1, 2, 3, 5, 8}.
- [ ] Integer operators return identical bytes on `batch-cpu`, CUDA and Metal; `f32` operators agree inside the class each device claims.
- [ ] Each kernel has a manifest with class, footprints and neutral; a CPU reference symbol; a retained CPU-versus-device differential check.

## Test plan

### Unit tests (`cargo test -p frob-kernels reduce`)
- `tree_shape_is_index_only`: the multiset of (left block, right block) pairs for N = 5 equals the hand-written list ((0,1),(2,3),(4,pad),(pad,pad)), ((0..2),(2..4)), ((4..6),(6..8)), ((0..4),(4..8)).
- `sum_neutral_is_negative_zero`: `[-0.0]` at N = 1, 2, 8 → 0x80000000 each time.
- `sum_positive_zero_padding_is_caught` (negative control, runs the mutant operator table).
- `sum_matches_reference_tree`: [1, 2⁻²⁴, 2⁻²⁴, 1] in `f32`: tree gives (1 + 2⁻²⁴) + (2⁻²⁴ + 1) = 1 + 1 = 2 exactly; a left-to-right sum gives the same here, and the second fixture [2²⁴, 1, 1, 1] distinguishes them: tree (2²⁴ + 1) + (1 + 1) = 2²⁴ + 2 = 16,777,218; left-to-right gives 16,777,216.
- `min_max_nan_and_signed_zero`: min(−0, +0) = −0; max(−0, +0) = +0; any NaN → NaN.
- `product_neutral_one`, `min_neutral_pos_inf`, `max_neutral_neg_inf`: an all-padding array returns the neutral.
- `seg_reduce_anchor_is_segment_local`: segments of lengths (3, 1, 5); moving the 5-segment from offset 4 to offset 0 leaves its result bit-identical.
- `seg_reduce_empty_segment_is_neutral`.
- `two_limb_add_carry`: (0xFFFFFFFF, 0) + (1, 0) = (0, 1); (0xFFFFFFFF, 0xFFFFFFFF) + (1, 0) = (0, 0) (wraps at 2⁶⁴ by definition).
- `two_limb_matches_u64`: 10⁶ random pairs.
- `worker_count_invariance`: 4,096 worlds, workers 1, 2, 3, 5, 8, output digest equal.
- Property test (INV-NUM-02): for random arrays and every operator, appending k neutral lanes changes no bit.

### End-to-end script and logging
`scripts/e2e/spark_utility_kernels.sh` (owned by BD-152), steps `reduce_capacity`, `reduce_workers`, `seg_reduce`,
`two_limb`: each runs `frob spark check --kernel K-reduce|K-seg-reduce --backend batch-cpu|gpu-cuda|gpu-metal
--vary capacity,workers --json` and asserts digest equality across the varied axis. Logged per line: command, exit
code, wall time, evidence block, the axis value, the output digest, and on failure the first differing world and
lane with both bit patterns.

### Known answers and negative controls
- The padding counterexample (−0.0) + (+0.0) = +0.0; the scatter arithmetic 0.999¹⁰⁰⁰ = 0.37 (CX-230).
- Two-limb known answer (0xFFFFFFFF, 0) + (1, 0) = (0, 1).
- Negative controls: +0.0 padding; a tree shaped by tile boundaries (a mutant whose pairing depends on the worker count) must fail `worker_count_invariance`.
- Metamorphic: multiplying every value by a power of two multiplies the sum by it exactly (absent overflow); permuting the segments' order permutes the outputs and changes none.
- Determinism lanes: twice on one machine; across worker counts; debug and release; `batch-cpu` against each device inside its class; byte equality for integer operators everywhere.

## Considerations

- A pairwise tree has a different rounding pattern from a left-to-right sum; kernels whose derivation assumed an order must name `K-reduce` so the order is the tree's everywhere, CPU included.
- Stack scratch of P/2 values per world is a resource bound that the manifest must state; for capacities above 256 the dialect version uses thread-group shared memory.
- Performance envelope: a per-world reduce over 64 lanes is 63 operations; it is never the bottleneck, and no variant with relaxed order is offered. Learner reductions that want speed over order exist only inside the labelled non-deterministic training profile, outside this kernel.
- A statistics reduction across worlds is legitimate only for outputs that never feed state; the class check is N21a-22's.
