## Background

Many stages of the batched simulation step produce a sparse set from a dense one: contact candidates that turned
out to touch, pairs that passed the broad-phase filter, rows that are active. The usual GPU idiom appends each
survivor with an atomic counter, so the output order depends on thread arrival and the run is not reproducible.
Spark's rule is **count, exclusive scan, write**: every candidate writes a 0 or 1 flag, an exclusive prefix sum of
the flags gives each survivor its output position, and each survivor writes itself there. The output order is the
input index order, on every backend and every run. One compaction kernel, `K-compact`, serves every stage; no stage
carries its own. It is stage 5 of the ten-stage batched step (contact compaction), and it also serves the broad
phase and row assembly.

`K-scan` is the exclusive prefix sum itself, on unsigned 32-bit integers with wrapping addition, so it is exact
(determinism class D0) on every backend. It also supplies segment starts to the segmented reduction and digit
offsets to the radix sort.

Capacities are fixed at environment creation (static shapes keep GPU launch graphs static). A world can therefore
produce more survivors than its capacity. The rule: an overflow is flagged and never silently clamped; the world is
marked `Degraded` with the reason, it is never undefined behaviour, and the caller's policy chooses refuse, reset
or continue-flagged. Tier: Solid. Both kernels exist twice: a Rust function for `batch-cpu` (the permanent CPU
reference) and a skeleton in the shared dialect (the common subset of CUDA C++ and Metal Shading Language).

Rejected alternatives: atomic-append compaction (order by arrival); a floating-point prefix sum (order-dependent
and unnecessary: positions are integers); dropping overflow silently (changes physics without a trace).

## Technical approach

Conventions (lanes, trailing padding, masks as selects) are those fixed in N21a-07.

**`K-scan` (exclusive scan).** Input: counts `c[world][0..N)` as `u32`. Output: `o[world][0..N]` with
o[0] = 0 and o[i+1] = (o[i] + c[i]) mod 2³²; o[N] is the total. Counts are bounded by capacities, so no wrap occurs
in practice; wrapping is still the defined semantics (dialect rule: integer arithmetic in exact kernels is
unsigned, 32 bits wide, and wraps). Reference implementation: a serial loop per world with a literal bound N. A
parallel up-sweep and down-sweep inside one thread group is admitted for large N only with byte equality against
the serial form (integer addition is associative, so equality is expected and tested, not assumed).

**`K-compact` (count, scan, write).** Inputs: a candidate slab `in[world][0..N)` of fixed-size records, a flag
slab `f[world][0..N)` of 0 or 1 (`u32`), a destination slab `out[world][0..C)` with capacity C, and the world's
status word. Steps per world:
1. o = exclusive scan of f; total = o[N].
2. For each i with f[i] = 1 and o[i] < C: out[o[i]] = in[i]. Positions are unique, so writes never collide and
   need no atomic.
3. For j in [min(total, C), C): out[j] = the padding record (every field its consumer's neutral element; the
   `valid` field 0). Padding trails the active lanes.
4. Write `count[world] = min(total, C)` and `requested[world] = total`.
5. If total > C: set the `Degraded` bit of the status word with reason `capacity:<slab name>` using an integer
   atomic bitwise-or (an order-independent atomic, allowed) or a plain per-world write, and leave the first C
   survivors in index order. Nothing beyond C is written anywhere.
The kernel is **stable**: survivors keep their relative input order. Which survivors are kept on overflow is
therefore deterministic (the first C by index), and the stage that sorted the candidates beforehand decides what
"first" means (the broad phase sorts by a total-order key first).

**Records.** `K-compact` is generic over a record of w 32-bit words (w a literal of the instantiation), copied as
raw words, so floats are moved without arithmetic and their bits are preserved.

**Manifests.** Class `exact`; determinism D0; math mode `ExactInteger`. Read footprint `in[world][0..N)`,
`f[world][0..N)`; write footprint `out[world][0..C)`, `count[world]`, `requested[world]`, the status word of the
same world. No kernel reads or writes another world's rows. Resource bounds: loop bound N, stack words N + 1 for
the serial scan (or thread-group memory for the parallel form). Neutral used for padding: the padding record.

**Refusal surface.** The kernels raise nothing themselves. `Degraded` with `capacity:<slab>` is the typed signal;
under the caller's `refuse` policy the step returns `FROB-REF-610` "capacity overflow under the `refuse` policy"
(exit code 6; first repair: a larger capacity; second: `continue-flagged`).

## Acceptance criteria

- [ ] Rust and dialect implementations exist; dialect text passes the dialect lint (no atomics other than the allowed integer or, literal loop bounds, unsigned indices).
- [ ] `K-scan` of [1, 0, 2, 0, 1] is [0, 1, 1, 3, 3] with total 4; of an all-zero array is all zeros with total 0.
- [ ] `K-compact` output order equals input index order on 10⁴ seeded cases; byte-identical on `batch-cpu`, CUDA and Metal.
- [ ] Overflow: with 5 survivors and C = 3 the first three by index are written, `count` = 3, `requested` = 5, and the world is `Degraded` with reason `capacity:<slab>`; no write lands outside `out[world][0..C)`.
- [ ] Negative control: a mutant that clamps silently (no `Degraded`, `requested` = 3) is caught; a mutant that appends by atomic counter is caught by the order test under a randomized thread schedule on `batch-cpu`.
- [ ] Trailing slots hold the padding record at every capacity; a world's compacted digest is identical at capacities C and 2C when total ≤ C.
- [ ] Bit-identical across worker counts {1, 2, 3, 5, 8}.
- [ ] Manifests with class `exact`, footprints and resource bounds; CPU reference symbols; a retained CPU-versus-device check.

## Test plan

### Unit tests (`cargo test -p frob-kernels scan compact`)
- `scan_known_answer`: as in the acceptance list.
- `scan_wraps_mod_2_32`: counts [0xFFFFFFFF, 2] → offsets [0, 0xFFFFFFFF, 1].
- `scan_parallel_equals_serial`: N ∈ {1, 2, 31, 32, 33, 257}; byte equality.
- `compact_stable_order`: flags [1, 0, 1, 1, 0], records r0 … r4 → out = [r0, r2, r3], count 3.
- `compact_preserves_float_bits`: records containing −0.0, a NaN payload and a subnormal are copied bit for bit.
- `compact_overflow_flags_degraded`: 5 survivors, C = 3.
- `compact_overflow_no_out_of_bounds`: a guard region after `out[world][C)` is unchanged (also checks no write into the next world's rows).
- `compact_silent_clamp_is_caught` (negative control mutant).
- `compact_atomic_append_is_caught` (negative control mutant under a shuffled schedule).
- `compact_padding_trails`: slots [count, C) equal the padding record.
- `compact_capacity_invariance`: digest of the active prefix equal at C and 2C.
- Property test (INV-SPARK-04, write footprint): for random flags, the set of written addresses is a subset of the declared footprint.

### End-to-end script and logging
`scripts/e2e/spark_utility_kernels.sh` (owned by BD-152), steps `scan` and `compact`: `frob spark check --kernel
K-scan|K-compact --backend <b> --vary capacity,workers --json`; asserts byte equality between `batch-cpu` and each
device and across the varied axes, and runs the overflow fixture through `frob sim run` on a synthetic scene that
forces contact overflow, asserting the `Degraded` count in the envelope. Logged per line: command, exit code, wall
time, evidence block, `count`, `requested`, digests, and on failure the first differing record index.

### Known answers and negative controls
- Scan [1, 0, 2, 0, 1] → [0, 1, 1, 3, 3 | 4]; compaction of five candidates with flags [1, 0, 1, 1, 0].
- Negative controls: silent clamp; atomic append; a padding record with a non-neutral field (caught by `compact_capacity_invariance`).
- Metamorphic: inserting a rejected candidate (flag 0) anywhere changes no output; permuting input records permutes survivors consistently.
- Determinism lanes: byte equality twice on one machine, across worker counts, debug and release, and across the three backends (class D0).

## Considerations

- On overflow the retained set depends on input order; stages must sort by a total-order key before compacting, or the result is deterministic but arbitrary. The contact audit labels a verdict shaped by capacity as `capacity-biased`.
- TARGET elsewhere in the plan: fewer than one world-step in 10⁴ marked `Degraded` for capacity on the standard battery; otherwise capacities are raised. This kernel only reports; it does not tune.
- The serial scan is O(N) per world in one thread; at N in the low hundreds this is cheaper than launching a parallel scan. The M2 profile decides whether the parallel form is ever needed.
- A padded contact left marked valid would change the physics; the `valid` field of the padding record is part of the neutrality test.
