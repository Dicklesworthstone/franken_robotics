## Background

Sorting is the second place (after reductions) where a batch simulator silently loses reproducibility: ties and
unstable sorts reorder contacts, and a different contact order gives a different solve. Spark's rule is one sort
primitive for the whole system, **stable**, on **integer keys that form a total order within a world** (value,
then index). One stable integer-key radix sort, `K-sort`, serves every stage; no stage carries its own sort. It
orders broad-phase pairs, groups contributions for segmented reductions (the replacement for unordered
floating-point scatter), and orders anything else that must be visited in a defined order.

A radix sort is chosen because it compares nothing: it is counting, an exclusive scan and a stable scatter, all
unsigned-integer operations, so the result is exact (determinism class D0) and byte-identical on CPU, CUDA and
Metal. Rejected alternatives: comparison sorts on floats (ties and NaN make the order implementation-defined);
bitonic networks on float keys (deterministic but tie order depends on the network and the capacity); per-stage
bespoke sorts (each would need its own cross-backend proof).

The kernel exists twice: a Rust function for `batch-cpu` (the permanent CPU reference) and a skeleton in the shared
dialect (the common subset of CUDA C++ and Metal Shading Language). Tier: Solid.

## Scope

In: `K-sort` in Rust and the dialect; the key-construction helpers (float to order-preserving integer; value then
index); manifests; tests.
Out: `K-scan` (N21a-08, used here); segmented reduction (N21a-07); the broad phase's use of the sort (BD-158);
registration and the cross-kernel battery (BD-152).

## Technical approach

Conventions (lanes, capacities, trailing padding) are those of N21a-07.

**Interface.** Per world: keys `k[world][0..N)` as `u32`, payload `p[world][0..N)` as `u32` (normally the element's
original index), the active count n ≤ N, and a declared `key_bits` ∈ {8, 16, 24, 32} (a literal of the
instantiation). Output: keys and payloads sorted by key ascending, ties in input order. Padding lanes n … N−1 are
not moved and keep the padding key 0xFFFFFFFF, so they trail.

**Algorithm (least-significant-digit radix sort, 8-bit digits, key_bits/8 passes).** For each pass d:
1. Histogram: h[b] = number of active elements whose digit d equals b, for b in 0 … 255 (a serial count per world,
   or integer atomic wrapping adds, which are order-independent).
2. Offsets: exclusive scan of h (`K-scan`).
3. Stable scatter: visit elements in index order i = 0 … n−1; write (k[i], p[i]) to position off[digit(k[i])]++.
   Index-order visiting is what makes the pass stable.
4. Swap source and destination buffers (two slabs of the arena; no allocation).
Loop bounds are the literals 256 and N. Shift counts are masked. No floating-point value is touched.

**Total order.** A stage that needs "value, then index" passes the index as the initial payload; equal keys then
keep index order because the sort is stable, which is a total order within the world. A stage that needs a
secondary key packs both into the 32 bits, or sorts twice (secondary key first), which stability makes correct.

**Float keys.** A float is never compared. The helper `key_from_f32(x)` maps the bit pattern b of x to an
order-preserving `u32`: if the sign bit is set, key = ~b; otherwise key = b | 0x80000000. This is monotone on all
finite values and infinities, places −0.0 immediately before +0.0, and puts NaNs at the two ends (a NaN marks its
world `Faulted` elsewhere; the sort still terminates and stays in bounds). The helper is exact-integer arithmetic.

**Parallel form.** The reference is serial per world (n is at most a few hundred). A thread-group parallel form
(per-thread histograms combined in thread order, then a scatter by precomputed positions) is admitted only with
byte equality against the reference on the test corpus.

**Manifests.** Class `exact`; determinism D0; math mode `ExactInteger`. Read and write footprints: the two key
slabs and two payload slabs of the same world, rows 0 … N−1; scratch: 256 histogram words per world on the stack or
in thread-group memory, stated as a resource bound. Aliasing: source and destination slabs must be distinct.

## Acceptance criteria

- [ ] Rust and dialect implementations exist; the dialect text passes the dialect lint.
- [ ] Sorting keys [3, 1, 3, 0, 1] with payload [0, 1, 2, 3, 4] yields keys [0, 1, 1, 3, 3] and payload [3, 1, 4, 0, 2].
- [ ] Stability: on 10⁴ seeded arrays with heavy ties (keys in 0 … 3), every pair of equal keys keeps input order.
- [ ] Byte-identical output on `batch-cpu`, CUDA and Metal, and across worker counts {1, 2, 3, 5, 8}.
- [ ] `key_from_f32` is monotone: for 10⁶ random pairs of non-NaN floats, x < y implies key(x) < key(y); key(−0.0) + 1 = key(+0.0).
- [ ] Capacity invariance: the sorted active prefix is identical at capacities N and 2N; padding lanes are untouched.
- [ ] Negative control: an unstable variant (scatter visiting in reverse index order on one pass) is caught by the stability test; a variant that orders by a raw `f32` comparison instead of `key_from_f32` leaves −0.0 and +0.0 in input order where the key rule puts −0.0 first, and is caught by the signed-zero fixture [+0.0, −0.0].
- [ ] Manifest with class `exact`, footprints, aliasing rule and resource bounds; CPU reference symbol; retained CPU-versus-device check.

## Test plan

### Unit tests (`cargo test -p frob-kernels sort`)
- `sort_known_answer`: the five-element case above.
- `sort_is_stable_on_ties`.
- `sort_key_bits_8_16_24_32`: each instantiation sorts correctly keys confined to its width; a key outside the declared width is reported by a debug assertion in the CPU reference and is a manifest violation.
- `sort_empty_and_single`: n = 0 and n = 1 are no-ops.
- `sort_padding_trails`: lanes n … N−1 keep 0xFFFFFFFF and their payloads.
- `key_from_f32_monotone`; `key_from_f32_signed_zero_adjacent`; `key_from_f32_infinities`: key(−∞) < key(any finite) < key(+∞).
- `sort_parallel_equals_serial`: byte equality at N ∈ {2, 33, 256, 1,024}.
- `sort_unstable_mutant_is_caught` (negative control).
- `sort_worker_count_invariance`: 4,096 worlds, workers 1, 2, 3, 5, 8.
- Property test: the output is a permutation of the input (multiset equality of (key, payload) pairs) and is non-decreasing in key.

### End-to-end script and logging
`scripts/e2e/spark_utility_kernels.sh` (owned by BD-152), step `sort`: `frob spark check --kernel K-sort --backend
<b> --workers <w> --seed <s> --key sort-<b>-w<w>-<run-id> --json` for w ∈ {1, 2, 3, 5, 8} on the seeded tie-heavy corpus
(one key per compared run, or the second call returns the first one's stored receipt); asserts byte
equality across backends and worker counts (the capacity axis through the family battery the script invokes, until
N21b-33's `--sweeps` enables `sweeps_capacity`). Logged per line: command, exit code, wall time, evidence block, key width, output digest, and on failure the
first position where two backends differ with both (key, payload) pairs.

### Known answers and negative controls
- [3, 1, 3, 0, 1] → [0, 1, 1, 3, 3] with payload [3, 1, 4, 0, 2].
- The reason for the rule: 0.999¹⁰⁰⁰ = 0.37 (CX-230); unstable sorts reorder contacts.
- Negative controls: the unstable mutant; the raw float comparison on the fixture [+0.0, −0.0].
- Metamorphic: adding a constant to every key (without overflow) changes no payload order; sorting an already sorted array is the identity.
- Determinism lanes: byte equality twice on one machine, across worker counts, debug and release, across the three backends (class D0).

## Considerations

- Four passes of 256-bin counting per world cost about 4·(256 + 2n) integer operations; for the broad phase at n ≈ 100 the histogram dominates. `key_bits` lets a stage with small keys run one or two passes. The M2 profile decides whether a 4-bit digit variant is worth having; it would be a second instantiation of the same kernel, not a second sort.
- Histogram scratch (1 kB per world) fits in thread-group memory on both devices; the fused per-world kernel studied elsewhere has a 48 KiB ceiling for such memory, which this respects.
- Sort keys must be total orders within a world; a stage that passes non-unique keys without an index payload still gets a deterministic order (stability), but a different one if its input order changes.
