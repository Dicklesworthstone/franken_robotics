## Background

Kernel skeletons in Spark are written in a shared dialect: the common subset of CUDA C++ and Metal Shading
Language, made portable by a per-backend prelude. Nine rules keep dialect sources inside a determinism class. The
M0 bead BD-013 built the lint engine and rules 1 to 4 and 6 (no backend intrinsic outside the prelude; no
floating-point atomics; no transcendental or reciprocal-square-root built-ins; contraction off, no fast math, no
explicit fused multiply-add; no grid-wide barrier). This bead completes the rule set for the M2 kernel library,
extends the same bans to the Rust sources of `frob-kernels` (the CPU reference must obey them too), and wires the
lint into every path by which source reaches a compiler, so that an unlinted kernel cannot run.

The four remaining rules, with the hazard each removes:

- **Rule 5.** Explicit loop bounds that are literals or capacity constants of the shape class, unsigned 32-bit
  indices, no recursion, no pointer arithmetic beyond buffer plus index. Hazard: data-dependent trip counts make
  launch shapes dynamic and resource bounds unknowable; recursion is unavailable on devices.
- **Rule 7.** Integer arithmetic in exact kernels is unsigned and 32 bits wide; shift counts are masked. Signed
  overflow and oversized shifts are undefined in both source languages, so they are made unreachable by
  construction. Sixty-four-bit integers and atomics are used only where the fingerprint records them for every
  device family in use; a count that can pass 2³² uses two 32-bit limbs.
- **Rule 8.** A mask is a select, never an arithmetic blend: m·a + (1 − m)·b turns an infinity in the unselected
  arm into a NaN, because 0·∞ is NaN.
- **Rule 9.** Padding trails the active lanes and holds the neutral element of the operation that will consume it
  (−0.0 for sums, 1.0 for products, +∞ and −∞ for minimum and maximum).

The bans that apply to every batched kernel on every backend (and are repeated in the Rust lint): no fast-math
relaxation of any kind; no fused multiply-add, contracted or explicit; no built-in transcendental function and no
reciprocal-square-root built-in; no floating-point atomic; no strict predicate in bare floating point. Tier: Solid.

## Scope

In: lint rules 5, 7, 8 and 9 for dialect sources; the lint for Rust kernel sources; the loading of banned
tokens from the registry file `registries/kernel_bans.toml` by both lints, with the file's schema, its reader
and its first content; the compile-path wiring (backends, cache, generated-code check); the full
planted-defect corpus for all nine rules. Rule 7 is the one source-level rule on 64-bit integers and atomics:
the rule, its feature-set parameter, its diagnostics and its planted defects are here.

Out: the engine and rules 1 to 4 and 6 (BD-013); the strict-predicate ban, which is an IR-level check (BD-053);
footprint containment (N21a-06); the `det_*` functions the lint allows (N21a-11); the arithmetic-feature
vocabulary of manifests and its derivation, the rule that a kernel family using 64-bit integers registers a 32-bit
variant, the plan-time intersection over device families, variant selection and `FROB-REF-616` (N21c-42, which
depends on this bead and calls rule 7 with the feature set of the device families in use; for the kernel library
that set admits no 64-bit atomic, which is the clause GATE-SPARK-23 reads); the evidence that the five bans
hold in what is compiled and run (N35-18, which depends on this bead): the ban table completed as the
normative six rows with admitted forms and compiler-confirmed spellings, the conformance corpus with one file
per banned token per language (`frob-conformance/corpus/bans/`, exhaustive over the table; the corpus of this
bead tests each rule's shape with at least two sources per rule and is not exhaustive over tokens), the test
that a token added to the table is rejected without a code change, the audit of recorded compile options, and
the seven ban canaries.

## Technical approach

The lint stays a library module, `frob_kir::dialect_lint`, plus `frob_kir::rust_kernel_lint`. It is not a new
`xtask` subcommand (the workspace fixes `xtask` at six checks); it is invoked by tests, by `check-generated`, and
by the compile paths below. Every finding is `{rule, file, line, column, token, message}`; any finding refuses the
unit with `FROB-REF-251` "a banned operation appears in kernel source (build time)" (exit code 3; repair: the
named replacement; retry `after-change`).

**Rule 5 (replaces M0's blanket ban on `while`).**
1. The only loop form is `for (u32 i = <literal or 0>; i < BOUND; ++i)` (and the stepped form `i += <literal>`),
   where BOUND is an integer literal or an identifier from the shape-class constant block (`NV_CAP`, `LINK_CAP`,
   `CONTACT_CAP`, `ROW_CAP`, …) or a literal multiple of one. `while`, `do`, `goto`, and a `for` whose bound is
   read from a buffer are rejected. Early `break` and `continue` are rejected (masks express early exit).
2. Index variables are `u32`. A signed loop variable is rejected.
3. Recursion: build the call graph of `FROB_FN` functions in the unit; a cycle is rejected.
4. Pointer arithmetic: reject `p + n`, `p++`, `p - q`, `*(…)` on a `FROB_PTR` or buffer parameter; only `buf[index]`
   is accepted.

**Rule 7.**
1. In a unit declared `ExactInteger` (a header comment directive `// frob: math_mode = ExactInteger`, also in the
   manifest): reject the types `int`, `short`, `long`, `char`, signed literals in arithmetic, and any `f32`.
2. Raw `<<` and `>>` are rejected everywhere outside the prelude; the prelude's `FROB_SHL(x, n)` and
   `FROB_SHR(x, n)` expand to `((x) << ((n) & 31u))` and `((x) >> ((n) & 31u))`.
3. 64-bit types (`ulong`, `uint64_t`, `unsigned long long`) and any 64-bit atomic are rejected unless the unit
   carries `// frob: requires = u64` or `u64-atomics` **and** the lint is given a feature set in which every
   device family in use records the feature. With no feature set (the default) they are rejected. FACT to recheck
   (re-run by the fingerprint): a compile probe on the M5 Ultra reports no 64-bit integer atomic add and no 64-bit
   compare-and-swap in Metal Shading Language 3.2 and 4.0, so no kernel of a mixed run uses them.

**Rule 8.**
1. Mask buffers have the element type `frob_mask` (a `u32` typedef in the prelude). Converting a `frob_mask` or a
   comparison result to a floating type (a cast, a constructor call, an implicit conversion in a float
   expression) is rejected: an arithmetic blend cannot be written without it.
2. Multiplying a float by `(1.0f - m)` or `(1 - m)` where `m` is a float is flagged as a blend pattern even when
   `m` came from elsewhere; the accepted form is `FROB_SELECT(pred, a, b)`.

**Rule 9.**
1. Reductions are written only through the utility kernels' operator table; a literal `0.0f` used as the initial
   value of an accumulation, or as the value written to padding lanes of a slab whose manifest declares a `sum`
   consumer, is rejected; the accepted spelling is the prelude constant `FROB_NEG_ZERO` (bit pattern 0x80000000),
   `FROB_ONE`, `FROB_POS_INF`, `FROB_NEG_INF`.
2. The static rule cannot prove neutrality of data; the dynamic proof is capacity invariance (bead BD-152 and the
   batch-composition gate). The lint's job is to remove the common misspelling.

**Token lists as data (DESIGN, agreed with N35-18).** The banned tokens of dialect rules 2, 3 and 4 and of the
Rust kernel lint are not constants of the lint. Both lints load them from `registries/kernel_bans.toml`: one
table per ban (fast math, fused multiply-add, transcendental built-ins, reciprocal square root, floating-point
atomics), each with the arrays `rust`, `cuda` and `metal` and the field `admitted`. This bead defines that
schema and the reader, and creates the file with the tokens its rules reject (the Rust method list below; the
dialect tokens BD-013 compiled in at M0, which move into the file). N35-18 then completes and owns the table.
The lints fail closed: a missing or unparsable file, or a ban with an empty array for a toolchain in use,
refuses every unit with `FROB-REF-251` and the file's path. Rules 5, 7, 8 and 9 are shape rules and carry no
token list.

**The Rust kernel lint.** Over `crates/frob-kernels/src/**` kernel modules (marked by the header comment
`//! frob: kernel` on the module's first line; a comment and not an inner attribute such as `#![frob_kernel]`, which
the compiler would reject as unknown): reject the method names `mul_add`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2`,
`sinh`, `cosh`, `tanh`, `exp`, `exp2`, `exp_m1`, `ln`, `ln_1p`, `log`, `log2`, `log10`, `powf`, `powi`, `cbrt`,
`hypot`, `recip` followed by `sqrt` composition helpers, and any `std::intrinsics` float intrinsic; `sqrt` is
correctly rounded and allowed. Reject `as f32` on a `bool` or comparison (rule 8), `f32::min`/`f32::max` (their
NaN and signed-zero behaviour differs from the dialect; `det_min`/`det_max` are required), atomics of float bits,
and iterator adaptors that reorder (`par_iter` sums, `sum()` on floats: reductions go through `K-reduce`).

**Wiring.**
1. `KernelBackend::compile` in each annex calls the lint on the fully expanded unit and its compile options first;
   a finding refuses compilation. There is no bypass flag in release builds; test builds have
   `--features neg-control-lint-bypass` used only by negative controls.
2. The binary kernel cache stores an entry only for a unit whose lint report is clean, and stores the lint
   version in the entry's metadata; a lint-version change invalidates nothing but is recorded.
3. `xtask check-generated` runs the lint over generated bodies after regenerating them.
4. `cargo test -p frob-kernels dialect_sources_are_clean` and `rust_kernels_are_clean` run it over the library.
5. `spark.precompile` (N21b-13) gains the option `--unit <path>`: compile one dialect unit file for the target
   through the same path (lint first, then compiler, then cache), so that a refusal of a single unit is reachable
   from the command line; this bead adds the option, its schema field and its registry example
   (`frob spark precompile sm_89 --unit <path> --key pc-unit-1 --json`; the verb is run-kind, so the call carries
   an idempotency key). A lint finding on that path is `FROB-REF-251`, exit 3. The `spark.precompile` row of
   VERBS-spark lists the option (`--unit <path>`, extended by this bead) and the code; the unit file is a path
   argument, read under the session's roots through the path jail (`FROB-REF-734`) and the format sniff
   (`FROB-REF-828`), as that row states.

## Acceptance criteria

- [ ] Each of the nine rules has at least two planted-defect sources in `crates/frob-kir/tests/lint_corpus/` that are rejected with the right rule number, and the whole kernel library passes with zero findings.
- [ ] Rule 5: `while`, a buffer-read bound, a signed index, direct recursion, mutual recursion and `p + n` are each rejected.
- [ ] Rule 7: `int` in an exact unit, a raw `<<`, a 64-bit atomic with no feature set, and a 64-bit atomic with a feature set in which Metal lacks it are each rejected; the same atomic is accepted with a feature set in which every family in use has it.
- [ ] Rule 8: `(f32)(a < b)`, `float(m)` on a mask and `m * a + (1.0f - m) * b` are rejected; the infinity case evaluates correctly through `FROB_SELECT` on `batch-cpu`, CUDA and Metal.
- [ ] Rule 9: an accumulation initialized with `0.0f` is rejected; `FROB_NEG_ZERO` is accepted.
- [ ] The Rust lint rejects `mul_add`, `sin`, `powf`, `f32::max` and a float `sum()` in a kernel module, and accepts `sqrt`.
- [ ] Both lints take their banned tokens from `registries/kernel_bans.toml`: with the file removed every unit is refused; the file created here holds every token named in this bead and in BD-013's rules 2 to 4.
- [ ] A backend refuses to compile a unit with a finding (`FROB-REF-251`), and the cache refuses to store it.
- [ ] No 64-bit atomic appears in any kernel source of the library (the clause GATE-SPARK-23 reads).

- Corpus test: every file under `lint_corpus/bad/` produces exactly the rule named in its first line; every file under `lint_corpus/good/` produces none.

### End-to-end script and logging
`scripts/e2e/kernel_toolchain.sh` (bead N21a-25), step `dialect_lint_full`: runs the corpus and the library lint,
then asks each present device backend to compile one bad unit through
`frob spark precompile <target> --unit <path> --key lint-bad-<target> --json` and asserts exit code 3 with
`FROB-REF-251` (an absent device is logged `not-run`). Logged per line: command, exit code, wall time, rule, token, file and
position of each finding, counts of files and findings, and the refusal envelope.

### Known answers and negative controls
- KA-533: select with an infinity in the unselected arm returns the selected arm; negative control: the arithmetic blend returns NaN.
- CX-219 (arithmetic blend; bound by N21-CX to `rule8_select_keeps_infinity` and `rule8_rejects_blend_pattern`, with the plant `N21a-10:blend-mutant`), CX-221 (grid-wide barrier), CX-230 (unordered scatter), and the padding counterexample (−0.0) + (+0.0) = +0.0.
- Negative controls: the whole `bad/` corpus; the lint-bypass feature, under which the cache-refusal test must fail (showing the wiring is what protects).
- Determinism: lint reports are byte-identical on Linux and macOS, debug and release.

## Considerations

- A token-and-shape lint has false negatives; it is one of three layers (lint, IR-level typing, dynamic invariance tests). A defect that passes all three would have to be order-independent and capacity-independent, which is the property wanted.
- Banning `break` costs a few masked iterations in short loops; the M2 profile decides whether any loop needs a different treatment, which would be a rule change by ADR, not a waiver.
- OPEN-NUM-1 (whether an explicit fused multiply-add is ever admitted): default no. If it changes, rule 4 gains a declared-and-probed exception; the lint is where that exception would be encoded.
- Metal dialect sources use no construct newer than Metal Shading Language 3.1 (the binding under the gateway enumerates language versions up to 3.1); the lint carries a deny list of newer constructs as part of rule 1.
