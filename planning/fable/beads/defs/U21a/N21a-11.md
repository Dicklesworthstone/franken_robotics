## Background

Platform elementary functions (sine, exponential, logarithm, power, even minimum and maximum on NaN and signed
zero) differ across math libraries and GPUs. A kernel that calls one cannot be bit-reproducible across backends,
and often not across driver versions. Spark therefore bans every built-in transcendental and the
reciprocal-square-root built-in from kernel sources (a lint enforces it), and the kernel intermediate
representation (IR) has no such operators at all. Where a kernel needs an elementary function it uses a **`det_*`
function**: a subprogram written from +, −, ×, ÷, √ and selects, the operations IEEE 754 requires to be correctly
rounded. Such a subprogram inlines as ordinary arithmetic and inherits the determinism class of those operators:
the same bits run to run on a device (class D2) and, where the device's IEEE probe passes, the same bits as the
CPU (class D1).

The design needs few of them (DESIGN): a revolute joint coordinate is a unit complex number updated rationally, and
group updates are Cayley maps, so the hot path has no trigonometric call. What remains: selection functions whose
NaN and signed-zero behaviour must be pinned (`det_min`, `det_max`, `det_clip`, `det_abs`), and the small set of
functions needed outside the rigid-body core: the normal variate for addressed random draws, and whatever sensing
or reward terms declare. Each is ported from the deterministic set of FrankenSim's `fs-math` (FACT: `fs-math`
provides deterministic elementary functions with error budgets in units in the last place), not reinvented.

Rejected alternatives: calling the platform function and tolerating differences (breaks replay, pairing and
attribution); adding sine and cosine as IR operators with per-backend implementations (the rejected IR of
ADR-SPARK-02); a lookup table with hardware texture filtering (fixed-point filter weights differ by vendor).
Tier: Solid.

## Scope

In: the `det_*` mechanism (a subprogram registry in `frob-kir`, inlining, emission to Rust and dialect); the
initial function set below; error budgets against a reference; cross-backend bit tests; the inventory of which
kernels use which function.
Out: the random streams themselves (BD-180); the IEEE probe (BD-017); the referee tier's use of `fs-math` in `f64`
(the referee is not a batched kernel).

## Technical approach

**Mechanism.** A `det_*` function is an IR program marked `subprogram` with scalar inputs and outputs, written by
hand in the IR builder or derived, checked like any program (dimension typing: arguments of transcendental-like
functions are dimensionless), given a content hash, and inlined at each call site before common-subexpression
elimination. Emitters also write it once as a named function (`det_min_f32` in Rust; `FROB_FN f32 det_min(f32,
f32)` in the dialect) for use by hand-written skeletons. One source, two emitted forms, identical operation order.

**Initial set (DESIGN; the inventory step may add functions, each by the same recipe).**

| Function | Definition | Notes |
|---|---|---|
| `det_min(a, b)` | `select(is_nan(a) or is_nan(b), NAN_Q, select(a < b, a, select(b < a, b, select(is_neg(a), a, b))))` | min(−0, +0) = −0; NaN propagates as the one canonical quiet NaN `NAN_Q` (bits 0x7FC00000) whichever operand carried it (a world with a NaN is marked `Faulted`) |
| `det_max(a, b)` | `select(is_nan(a) or is_nan(b), NAN_Q, select(b < a, a, select(a < b, b, select(is_neg(a), b, a))))` | max(−0, +0) = +0; NaN as for `det_min` |
| `det_abs(a)` | `select(a < 0, neg(a), select(is_neg(a), neg(a), a))` | abs(−0) = +0 |
| `det_clip(x, lo, hi)` | `det_min(det_max(x, lo), hi)` | the two arms agree at the boundary, so its predicate is class `Plain` |
| `det_sign(a)` | −1, 0 (signed as the input) or +1 by selects | no branch |
| `det_recip_sqrt(a)` | `1 / sqrt(a)` (two correctly rounded operations) | replaces the banned `rsqrt` built-in; error at most 1.5 ulp by composition, identical everywhere |
| `det_ln(a)`, `det_cos_2pi(u)` | ported from `fs-math`: argument reduction by exact operations, then a fixed-degree polynomial in Horner form chosen at derivation time | needed only for the normal variate; error budget stated in ulp and tested |
| `det_normal(u1, u2)` | the `fs-rand` construction, ported operation for operation | determinism D2 per backend; D1 across backends only where the IEEE probe passes |

The two tests the selects need are exact-integer tests on the bit view of N21a-17 (a dependency), never float
comparisons: `is_neg(x)` = `(bits(x) >> 31) == 1` and `is_nan(x)` = `(bits(x) & 0x7FFFFFFF) > 0x7F800000`
(unsigned). The explicit NaN arm is required: without it the nested selects return the *second* operand when the
first is NaN and the second is not (all comparisons with NaN are false, so the innermost select decides on the NaN's
sign bit), and min(NaN, 1) would be 1. A canonical NaN rather than the operand's own makes the result commutative
bit for bit and independent of how a device propagates NaN payloads.

What the set deliberately lacks: `det_sin`, `det_cos` and `det_atan2`. No batched kernel takes an angle as input (a revolute coordinate is stored as a unit complex number), and the one mechanism whose mathematics is written with an arctangent and an arccosine, the four-bar closed form (N16c-31), is evaluated algebraically on unit-complex components. A bead that names one of these three in a kernel or in a test (the hazard register's table test names `det_sin` and `det_cos`) either adds the function by this recipe, with its own error budget and tests, or uses a function that is registered (`det_cos_2pi`, `det_ln`); until then the call fails the build as unregistered.

HYPOTHESIS to confirm in the inventory step by reading `fs-rand`: that its normal construction needs a logarithm
and a cosine (a Box–Muller form). If it uses another construction (a ratio method, a table), the two transcendental
rows are replaced by what that construction needs, under the same recipe and tests.

`is_neg(a)` is the sign bit, read through the exact-integer view of the bits (N21a-17). Polynomial coefficients
are IR constants given as exact bit patterns; the Horner order is fixed in the program, never re-associated.

**Inventory.** A build-time report lists, per kernel, the `det_*` functions it inlines and their operation
counts; a kernel that needs a function outside the registry is a build error naming the function, so growth of the
set is deliberate.

**Error budgets.** Each function records `max_ulp_error` against a high-precision reference (exact rational or
`f64` computed with FrankenSim's deterministic functions) over a stated domain; selection functions are exact.
The budget is a claim about accuracy; bit-equality across backends is a separate claim tested separately.

**Determinism and evidence.** Functions built only from +, −, ×, ÷, √ and selects are class D2 on every device by
construction and candidates for D1; results are evidence class `Tested`.

## Acceptance criteria

- [ ] The nine functions of the table above (its eight rows; one row holds two) exist as IR subprograms, as emitted Rust functions and as dialect functions; the dialect text passes the lint (it contains no built-in transcendental).
- [ ] `det_min`, `det_max`, `det_abs`, `det_clip`, `det_sign` are exact on the full edge set {−0, +0, ±∞, NaN, smallest subnormal, largest finite} and on 10⁶ random pairs, against a hand-written truth table.
- [ ] `det_recip_sqrt` equals `1.0f / sqrt(a)` computed as two operations, bit for bit, for all 2³² inputs on `batch-cpu` (exhaustive).
- [ ] `det_ln` and `det_cos_2pi` meet their recorded ulp budgets on 10⁷ sampled inputs and at all domain edges; the budgets are in the function manifests.
- [ ] Emitted Rust and emitted dialect produce identical bits on `batch-cpu` and on each device family for 10⁶ inputs per function wherever that family's IEEE probe attained class D1; where it did not, the measured disagreement is recorded in the divergence ledger and the function is class D2 on that family.
- [ ] A kernel that calls `sin` fails the lint; a kernel that calls an unregistered `det_tan` fails the build with the function named.
- [ ] The inventory report lists every kernel's `det_*` use.

## Test plan

### Unit tests (`cargo test -p frob-kir det`, `cargo test -p frob-kernels det`)
- `det_min_truth_table`: (−0, +0) → −0; (+0, −0) → −0; (1, NaN) → 0x7FC00000; (NaN, 1) → 0x7FC00000 (the case a select chain without the NaN arm gets wrong); (−NaN with payload, +NaN with another payload) → 0x7FC00000; (−∞, 5) → −∞.
- `det_max_truth_table`: (−0, +0) → +0; (+0, −0) → +0; (NaN, 1) and (1, NaN) → 0x7FC00000; (+∞, 5) → +∞.
- `det_min_without_nan_arm_mutant` (negative control): the chain without the NaN arm returns 1 for (NaN, 1) and the truth-table test catches it.
- `det_abs_negative_zero`: abs(−0) has bit pattern 0x00000000.
- `det_clip_boundaries`: clip(lo) = lo, clip(hi) = hi, clip(NaN) = NaN.
- `det_recip_sqrt_exhaustive`: all 2³² `f32` bit patterns (a long test, run in the gate lane, sharded by exponent).
- `det_ln_ulp_budget`, `det_cos_2pi_ulp_budget`: sampled inputs against the reference; edges u = 0, the smallest positive `f32`, 1 − 2⁻²⁴.
- `det_normal_matches_fs_rand`: 10⁶ addressed draws equal the `fs-rand` reference values bit for bit on `batch-cpu`.
- `det_inline_equals_call`: a kernel using the inlined subprogram and one calling the emitted function give identical bits.
- `det_unregistered_is_build_error` (negative control).
- `det_platform_min_differs` (negative control documenting the hazard): the platform `f32::min(−0.0, +0.0)` or a NaN case differs from `det_min` on at least one listed input (the Rust kernel lint's rejection of the platform call is N21a-10's test).

### End-to-end script and logging
`scripts/e2e/kernel_toolchain.sh` (bead N21a-25), step `det_functions`: `frob spark check --kernel K-det-suite
--backend batch-cpu|gpu-cuda|gpu-metal --key det-suite-<backend>-<run-id> --json` (one key per compared run) runs a test-only probe kernel that applies every `det_*` function to a seeded
input slab and digests the output. Asserts digest equality with `batch-cpu` on families at class D1, and a
recorded disagreement histogram otherwise. Logged per line: command, exit code, wall time, evidence block,
function name, input count, digests, the attained class, and on failure the first input where two backends differ
with both bit patterns.

### Known answers and negative controls
- Signed-zero and NaN truth tables; 1/√4 = 0.5 exactly; the normal variate of fixed (u1, u2) pairs from the `fs-rand` vectors.
- Negative controls: the platform `min`/`max`; a Horner form re-associated by one term (changes bits on at least one input in the sample, caught by the golden digest).
- Metamorphic: `det_min(a, b) = det_min(b, a)` bit for bit; `det_abs(det_abs(a)) = det_abs(a)`; `det_clip` is idempotent.
- Determinism lanes: twice on one machine; debug and release; across platforms; across backends against each one's class.

## Considerations

- A normal variate built from `det_*` floating-point functions is class D2 per backend and D1 across backends only where the probe passes; integer and uniform draws stay class D0 everywhere. Results that pair across device families must respect that.
- Subnormal handling on Metal may differ (the specification permits flushing); polynomial evaluation near underflow is in the tested edge set, and a difference there lowers the function's class on that family instead of being hidden.
- Operation counts matter: `det_ln` and `det_cos_2pi` cost tens of operations each; they are used per random draw, not per world-step of rigid-body dynamics.
- If `fs-math`'s functions cannot be ported inside their licence or error budgets, the fallback is to draw normals on the host for the affected streams and upload them, with the transfer charged.
