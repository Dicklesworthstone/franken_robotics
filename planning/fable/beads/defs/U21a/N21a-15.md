## Background

The kernel IR of Spark (`frob-kir`) shrinks derived arithmetic by bounded common-subexpression elimination and a
small closed table of rewrites that are exact in IEEE arithmetic. A stronger technique exists: put the program in
an **e-graph** (a structure that holds many equivalent forms at once), saturate it with rewrite rules, and extract
the cheapest equivalent program. The suite has such a crate. FACT: `frankenjax/crates/fj-egraph` exists (9,408
lines in `src/lib.rs`), built on the third-party `egg` crate over frankenjax's own intermediate representation;
frankenjax pins asupersync 0.5.0.

Posture: **Pattern**. It is never a dependency, because it would add `egg` and a second asupersync version to the
build graph (the workspace allows exactly one). Use at run time: none. The only question is whether extraction,
re-implemented or run offline in the build-time annex `derive/frob-derive`, would shrink kernel arithmetic enough
to matter.

**Ceiling, stated before any test.** The gain is at most the arithmetic share of step time multiplied by the
reduction in operations. If the M2 profile puts arithmetic below 20% of step time, a 10% reduction in operations
is worth at most 2% and the item is dropped without a run. (An earlier observation points the same way: at these
state sizes the step is expected to be bound by memory traffic, not by arithmetic.)

The admission gate and pilot is **INT-FJAX-01** [F], M2 at the earliest and only if the profile asks: in the
`derive/` annex only, with rewrite rules restricted to identities that are exact over the reals **and** preserve
floating-point results under the kernel's determinism class, the extracted kernel matches the baseline bit for bit
on the conformance vectors, and the operation count falls by at least 10% on at least three kernels. Kill: either
condition fails. Fallback: common-subexpression elimination only (FrankenSymPy's `fsym-simplify`, 3,105 lines,
already in the annex). Tier: Frontier.

## Scope

In: the go or no-go from the profile; if go, a bounded extractor in the annex over the IR's exact rule table, the
three-kernel measurement, and the admission record.
Out: any run-time use; any dependency on `fj-egraph` or `egg`; rules that reassociate, distribute or fuse (they
make a different kernel with a new identity, an error bound and a fidelity run, and are not rewrites).

## Technical approach

**Step 0: the screen (no code).** Read the arithmetic share a of step time from the M2 profile (N21a-27): the
fraction of world-step wall time spent in arithmetic of derived bodies, as opposed to memory traffic, launches
and skeleton overhead. Compute the ceiling 1/(1 − a·r) for an operation reduction r = 0.10. If a < 0.20 the
ceiling is below 1.02: record `INT-FJAX-01: not run, ceiling below goal` in the admission file with the measured
a, and close this bead. A speed experiment whose ceiling is below its goal is refused by rule (`FROB-REF-866`).

**Step 1: the extractor (only if the screen passes).** In `derive/frob-derive`, behind the off-by-default feature
`frontier-egraph`:
1. Represent a straight-line program as an e-graph whose e-nodes are IR operators over e-class ids.
2. Rewrite rules: exactly the class-E table of the IR (N21a-19): commutation of + and ×; x·1 → x; x + (−0) → x;
   double negation; select simplification (select(p, a, a) → a; select(true, a, b) → a); folding of exact constant
   operations (an operation on constants whose result is exactly representable); sharing of common subexpressions.
   No reassociation, no distribution, no x·0 → 0 (wrong for NaN and infinities), no x − x → 0 (wrong for NaN and
   infinities), no fused multiply-add.
3. Saturate under a **node budget** (default 10⁵ e-nodes per program) and an iteration limit; stop at either.
4. Extract by a cost function: operation count weighted by type (division and square root heavier than add and
   multiply; weights from the profile), ties broken by lower live-value pressure.
5. Emit a **rule trace**: the sequence of rule applications that maps the source program to the extracted one.
   The trace is replayed by the independent class-E trace checker (theorem card T-27: a class-E rewrite trace maps
   the source program to the target program using only rules of the closed table). A program without a replayable
   trace is not admitted.

**Step 2: the measurement.** On at least three kernels chosen from the profile's top arithmetic consumers:
(a) bit equality of extracted against baseline on the kernel's conformance vectors (at least 10⁶ seeded inputs
plus the edge set) on `batch-cpu`, and on each device through the CPU-versus-device check; (b) operation counts
before and after; (c) the paired lower bound of the whole-step speed ratio with the extracted kernels in place
(an optimization lands only with a bound of at least 1.03 on the row it claims to improve, identical digests, and
its ceiling computed beforehand).

**Decision.** Pass: bit-equal on all vectors and at least 10% fewer operations on at least three kernels; the
extractor is admitted as a build-time step, recorded in `DEPENDENCY_ADMISSION.md`. Fail (either condition): the
feature is removed and the record says so; CSE only.

## Acceptance criteria

- [ ] The screen is recorded with the measured arithmetic share a and the computed ceiling; if a < 0.20 the bead closes `not run` and no extractor code is merged.
- [ ] If run: no dependency on `egg`, `fj-egraph` or a second asupersync appears in any lockfile (`check-deps` passes).
- [ ] If run: extracted kernels are bit-identical to their baselines on the conformance vectors on every backend they claim; every admitted extraction has a rule trace accepted by the independent checker.
- [ ] If run: operation counts fall by at least 10% on at least three kernels, or the gate is recorded as failed and the feature removed.
- [ ] Negative controls: a rule set with one reassociation rule added produces an extraction that differs in bits on the case a = 10⁸, b = −10⁸, c = 1 and is rejected both by the bit comparison and by the trace checker; a trace with one step deleted is rejected.
- [ ] The node budget is enforced: a program that would exceed it stops with a partial result that is still equivalent (checked by trace), never an unbounded run.
- [ ] The admission record for INT-FJAX-01 states pass, fail or not run, with values.

## Test plan

### Unit tests (in `derive/frob-derive`, feature `frontier-egraph`)
- `screen_ceiling_arithmetic`: a = 0.15, r = 0.10 → ceiling 1/(1 − 0.015) = 1.015 → not run; a = 0.50 → 1.053 → run.
- `egraph_cse_only_equals_baseline`: with only the sharing rule, extraction equals the CSE result node for node.
- `egraph_commutation_shares`: `x·y + y·x` extracts to one multiply and one add.
- `egraph_no_x_times_zero`: `x·0` is not rewritten to 0; with x = ∞ the program still returns NaN.
- `egraph_no_x_minus_x`: `x − x` is not rewritten; with x = ∞ it returns NaN.
- `egraph_exact_constant_folding_only`: `0.5·4` folds to 2; `0.1·3` does not fold (the product is inexact).
- `egraph_reassociation_rule_is_rejected` (negative control): the planted rule changes (a + b) + c from 1 to 0.
- `egraph_trace_replays`; `egraph_truncated_trace_rejected` (negative control).
- `egraph_node_budget_stops`.
- `egraph_extraction_is_deterministic`: two runs give the same program hash.

### End-to-end script and logging
`scripts/e2e/kernel_toolchain.sh` (bead N21a-25), step `egraph_pilot`, present only when the feature is built: it
regenerates the three chosen kernels with and without extraction, runs `frob spark check --kernel <name>
--backend <b> --json` for bit equality, and the paired speed comparison. Logged per line: command, exit code, wall
time, evidence block, operation counts before and after with the 10% threshold, the paired lower bound against
1.03, digests of both programs, the trace-checker verdict; on a `not run` screen the step logs the measured share
and the ceiling and ends.

### Known answers and negative controls
- The reassociation case: in `f32`, (10⁸ + (−10⁸)) + 1 = 1 and 10⁸ + ((−10⁸) + 1) = 0.
- Negative controls: the reassociation rule; the truncated trace; the non-finite cases for x·0 and x − x.
- Determinism lanes: extracted kernels are bit-identical to baseline in every lane the baseline holds.

## Considerations

- The expected outcome is `not run`: the plan's own estimate is that the step is bound by memory traffic and that arithmetic is a minority of step time. The bead exists so that the question is settled by the profile and recorded, not reopened later by enthusiasm.
- A rule that is exact over the reals but changes floating-point results (reassociation, distribution, fusion) belongs to class R: it makes a different kernel with a new identity, an error bound and a fidelity run. Nothing in this pilot admits class R.
- Extraction can reduce operation count while raising live-value pressure (more registers); the cost function's tie-break and the resource metadata check (N21a-18) guard against trading arithmetic for spills.
- If the derivation route is killed (KILL-KIR), this pilot is moot and is closed with that reason.
