## Background

`frob-kir` is the kernel intermediate representation of Spark: typed static single assignment, in which every
value carries a physical dimension and every program carries the resource facts a backend needs before it
compiles anything. Kernel arithmetic is derived symbolically at build time, lowered to this IR, and emitted as
Rust (the permanent CPU reference) and as text in the shared GPU dialect (the common subset of CUDA C++ and Metal
Shading Language). Version 0 (bead BD-018) is strict straight-line code over scalars, enough for one Cayley
update. The M2 kernel library needs more: bodies that repeat over the links at one depth of a tree, over rows of
a constraint block, over lanes; vector and matrix values; direct reads and writes of slab memory.

ADR-SPARK-02 (DESIGN): the IR gains **bounded loops and resource metadata and keeps dimension typing**; it still
has no sine, cosine, exponential, logarithm, power, reciprocal square root or fused multiply-add, and no
approximate mode. Why bounded loops instead of unrolling everything: a loop bound is a literal or a capacity of
the shape class, so every program still has a finite, known operation count and a derivative program by the same
transformation, while the emitted text stays small and one kernel serves every design in a bucket (designs are
data, not code). Why loops in the IR instead of only in hand-written skeletons: the body of a per-link recursion
carries values across iterations, and that carried arithmetic must be typed, hashed and differentiated with the
rest. Rejected alternatives: full unrolling per design (per-design kernels are a rejected default; their ceiling is
1.19 to 1.25 and cold compilation of an incumbent's kernels takes about 96 s); general `while` loops (unknown
resource bounds; data-dependent launch shapes); a second IR for integer or embedded targets (the same IR carries
reserved fixed-point words instead).

Tier: Frontier, under kill gate KILL-KIR (decided at M2 by BD-221). This bead starts only after the paper-scale
pilot N21a-13 says `proceed`.

## Scope

In: the full type system; bounded loops with carried values; `select`; `load` and `store`; the complete
floating-point operator list with defined NaN and signed-zero semantics; the canonical encoding and content hash of
`frob.kir/1`; parsing of the reserved fixed-point words; the reference interpreter; extension of both emitters and
of the dimension checker to all of it.
Out: unsigned-integer operators and the exact-integer math mode (N21a-17); resource metadata values and backend
limits (N21a-18); the rewrite table (N21a-19); derivative programs (N21a-20); double-float pairs (N21a-21);
fixed-point semantics and lowering (N21a-26); predicate classes (BD-053).

## Technical approach

**The language (DESIGN: intent, not syntax).**

```text
types      f32 | f64 (CPU targets only) | f32dd (double-float pair) | u32 | bool
           vec3<T> | mat3<T> | se3<T> | sym6<T> | array<T, N>          N is a literal
           q16_16 | q32_32                                              reserved: parsed, never lowered to a GPU
dimension  every floating value has an exponent vector over the fs-qty base dimensions; sums must be homogeneous
statements single assignment
           for i in 0..N carry (a = a₀, …) { …; yield (a′, …) }       N a literal or a shape-class capacity; a value
                                                                       that crosses iterations is a loop argument,
                                                                       so every name is still assigned once
           select(pred, a, b)                                          branchless
operators  add sub mul div sqrt neg abs min max clip compare           min and max are defined on NaN and on ±0
           load(slot, lane, offset) store(slot, lane, offset, v)       offset a literal
excluded   sin cos exp log pow rsqrt fma, any approximate mode
metadata   content hash (BLAKE3); math_mode in {Ieee754Safe, ExactInteger, FixedPoint (reserved)};
           max_regs; max_stack_bytes; operation counts by type; loop bounds; buffer argument count;
           class claimed; CPU reference symbol; derivative program; proof_digest (optional)
```

**Composite types.** `vec3<T>`, `mat3<T>` (nine components, row-major), `se3<T>` (a rotation and a translation),
`sym6<T>` (a symmetric 6 × 6 matrix stored as 21 components), `array<T, N>` with literal N. Composites are
*lowered to scalars before emission*: each component is an ordinary single-assignment value, so composites add no
arithmetic semantics of their own; a composite operator (`mat3·vec3`, `se3∘se3`) is a library of scalar expansions
in a fixed, documented operation order (row by row, left to right, no reassociation). Each component has its own
dimension, so an `se3` can hold a dimensionless rotation and a translation in metres.

**Bounded loops.** `for i in 0..N carry (a = a₀, …) { body; yield (a′, …) }`:
- N is a literal or a named capacity; the loop index `i` is `u32` and may appear in `load`/`store` lane
  expressions affinely with literal coefficients.
- Values defined before the loop are visible inside (loop-invariant). A value that changes across iterations is a
  loop argument: it is bound to a₀ on entry, to the previous `yield` afterwards, and the loop's result is the
  final `yield`. Inside one iteration every name is assigned once.
- Types and dimensions of a₀, the argument and the yield must agree (checked).
- Loops nest; total operation count is the product of bounds times the body count, computed exactly.
- A masked lane inside a loop is a `select` on the carried value; there is no early exit.

**Loads and stores.** `load(slot, lane, offset)` reads component `offset` (a literal) of lane `lane` of buffer
slot `slot`; `store` writes it. Slots are declared in the program header with element type, dimension per
component and access (read, write). The set of loads and stores is the program's footprint (derived by N21a-06).
A program with no loads or stores is a pure body called by a skeleton that does the memory traffic.

**Floating operators.** `add sub mul div sqrt neg abs min max clip compare`, each one IEEE 754 operation or a
fixed select pattern. `min`, `max`, `clip`, `abs` follow the `det_*` definitions (N21a-11): NaN propagates;
min(−0, +0) = −0; max(−0, +0) = +0; abs(−0) = +0.

**Dimension checker extensions (theorem T-09, proof obligation PO-SPARK-01).** Loop arguments: the dimension is
part of the loop signature and must be a fixed point (the yield's dimension equals the argument's). Loads: the
slot's declared component dimension. Composites: per component. Square roots still require even exponents. A
violation is `FROB-REF-250` (build time; exit code 3; repair: fix the derivation).

**Canonical encoding and hash.** `frob.kir/1` bytes: header (schema tag, name, math mode), slot table, input and
output ports, nodes in index order with loops as nested blocks, metadata in fixed field order; integers
little-endian fixed width; constants as bit patterns. The content hash is BLAKE3 over the bytes with the
metadata's own `content hash` and `proof_digest` fields zeroed. Golden hashes are checked in for the library.

**Reserved words.** `q16_16`, `q32_32` and the math mode `FixedPoint` parse and type-check syntactically; any
attempt to lower a program that uses them to a GPU dialect or to the `batch-cpu` emitter through M5 is a
build-time refusal naming the reserved type. They exist so that a later embedded target lowers the same programs
without a second IR.

**Reference interpreter.** A small evaluator of the IR (scalars, loops, loads and stores against in-memory
slabs) in `f32` and `f64`; it is the oracle for both emitters and for footprint derivation.

**Emitters.** Rust: loops become `for i in 0..N` with `let mut` only for carried values (shadowed per iteration in
the emitted form: one assignment per name per iteration); dialect: `for (u32 i = 0u; i < N; ++i)` with the bound
spelled as the capacity constant, one operation per statement, `FROB_SELECT`, `FROB_SQRT`. `f64` programs are
refused by the dialect emitter. Emitted dialect text passes the full dialect lint.

## Acceptance criteria

- [ ] Every construct in the language block parses, type-checks, serializes canonically and round-trips; golden hashes are stable across Linux and macOS.
- [ ] Emitted Rust and the reference interpreter agree bit for bit on 10⁵ seeded inputs for each of: a three-level nested loop, a loop with two carried values, a program with loads and stores, each composite operator.
- [ ] A loop whose bound is not a literal or a declared capacity is rejected at build time; a loop whose yield changes the dimension or type of its argument is rejected (`FROB-REF-250` for dimension).
- [ ] The operation count of a looped program equals bound × body count exactly and is in the metadata.
- [ ] `q16_16` and `q32_32` parse; lowering a program that uses them is refused with the reserved type named.
- [ ] A program using `f64` is emitted to Rust and refused by the dialect emitter.
- [ ] The first M2 kernel that needs a loop (the per-level kinematics body, carried by BD-149) is expressible: a synthetic per-level recursion over `links` with a carried transform is emitted and matches a hand-written reference bit for bit.
- [ ] `CONTRACT.md` documents the language; `frob schema frob.kir/1` prints the schema.

## Test plan

### Unit tests (`cargo test -p frob-kir v1`)
- `loop_sum_fixed_order`: `for i in 0..4 carry (s = −0.0) { yield s + x[i] }` on x = [2²⁴, 1, 1, 1] gives 16,777,216 (left-to-right order, the order the program states), distinct from the pairwise-tree value 16,777,218: the IR keeps exactly the order written.
- `loop_two_carried_values`: a Fibonacci-like recurrence in `u32`-free floats: (a, b) → (b, a + b), 10 iterations from (1, 1) → (89, 144).
- `loop_bound_must_be_literal_or_capacity` (negative control): a bound read from an input is rejected.
- `loop_yield_dimension_fixed_point`: argument in metres, yield in m² → `FROB-REF-250`.
- `nested_loop_operation_count`: 3 × 4 × 5 iterations of a 7-operation body → 420.
- `composite_mat3_vec3_order`: the expansion is row by row, left to right; a golden node list is checked in.
- `composite_se3_compose_matches_scalar`: `se3∘se3` against a hand-expanded scalar program, bit for bit.
- `sym6_storage_is_21_components`.
- `load_store_roundtrip`: store then load the same lane and offset returns the value; a store to a read-only slot is rejected.
- `canonical_roundtrip_all_constructs`; `golden_hashes`.
- `reserved_words_parse_not_lower`; `f64_refused_by_dialect_emitter`.
- `interpreter_equals_emitted_rust`: property test over 10⁴ random well-typed programs with loops (bounds ≤ 8) and selects.
- Property test for PO-SPARK-01: no accepted program contains an inhomogeneous sum, checked by an independent exponent recomputation over the scalar-lowered form.

### End-to-end script and logging
`scripts/e2e/kernel_toolchain.sh` (bead N21a-25), step `kir_v1`: regenerates a looped fixture kernel, compares
digests, runs it through `frob spark check --kernel kir-loop-fixture --backend <backend> --key kir-loop-<backend> --json` on `batch-cpu`,
`gpu-cuda` and `gpu-metal` (an absent device is logged `not-run`), and submits a program with a data-dependent bound, asserting the build-time refusal. Logged per line:
command, exit code, wall time, evidence block, program hash, operation counts, digests of emitted files, and on
failure the first differing node or output.

### Known answers and negative controls
- Known answers: the loop-order case (16,777,216 against 16,777,218), the recurrence (89, 144), the operation count 420.
- Negative controls: data-dependent bound; dimension-changing yield; store to a read-only slot; lowering a reserved type.
- Metamorphic: unrolling a loop by hand into straight-line code gives a program with identical outputs bit for bit (the IR loop adds no arithmetic).
- Determinism lanes: emitted Rust bit-identical twice, in debug and release, across platforms; devices against their class through the CPU-versus-device check.

## Considerations

- Every loop added to the IR is something the differentiation and footprint passes must handle; the bound on features (no `while`, no early exit, affine lane expressions only) is what keeps those passes exact.
- Composite expansions fix an operation order that derivations may not have intended (for example Horner forms are chosen at derivation time, before the program is fixed); a derivation that needs a different order writes scalars.
- The per-kernel-body rule still applies: a loop over links is a body applied per level, not a whole-robot expression.
- If KILL-KIR fires, this IR remains in use for dimension typing of hand-written bodies and for the exact-integer class.
