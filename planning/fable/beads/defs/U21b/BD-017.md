## Background

FrankenRobotics wants a property no incumbent simulator documents: the same bits from a floating-point kernel on
the CPU reference (`batch-cpu`, `f32`), on CUDA and on Metal (determinism class D1). Whether that is attainable is
a HYPOTHESIS. IEEE 754 requires correct rounding of +, −, ×, ÷ and √, and CUDA documents compliance; but Apple
confirmed in September 2026 that Metal offers no control over rounding mode or subnormal handling, and the Metal
Shading Language specification permits flushing subnormals (FACT, source register of the plan, to be re-read before
a gate cites it). A compiler may also contract a·b + c into a fused multiply-add, which changes the rounding of
every such expression. The plan's rule is to measure and not to assume: GATE-SPARK-01 runs an arithmetic probe on
each device family, and its outcome **sets that family's best attainable determinism class**. Everything that later
pairs, replays or teleports results across backends reads this outcome; if a family cannot hold bit equality,
KILL-D1 fires for it (decision bead N21b-34) and it is class D2 for itself and D3 against others.

Determinism classes, for a reader who has not seen them: D0 exact (integers, rationals); D1 bitwise across
backends; D2 bitwise per backend (run to run, across worker counts, and independent of batch composition); D3
agreement inside a recorded tolerance plus agreement of task decisions; D4 unspecified.

This bead builds the probe kernels, the verb `spark.probe` with its `ieee` suite, and the stored report. The
boundary-corpus suite of the same verb is BD-030 and the double-float canary suite is N21b-36. Tier: Solid.
Subsystem: Spark; crates `frob-kernels` (probe library, comparison, report) with the two annexes for execution.

## Scope

In: probe kernels in the shared dialect and their Rust twins; operand generation; the exhaustive and sampled
comparisons; the contraction detector; the record of subnormal, NaN and explicit-fused behaviour; the
attainable-class rule; the report record and its storage as device evidence; the verb surface.

Out: the hardware fingerprint record that embeds the probe digest (BD-029); the exact and guarded predicate probe
(BD-030); canaries (N21b-36); the per-kernel CPU-versus-device check (N21b-32, BD-176); the end-to-end script
(N21b-40); the kill decision (N21b-34).

## Technical approach

**Probe library (DESIGN).** Four kernels, class `float`, each one line of arithmetic per lane, compiled through
the same prelude and flags as production kernels (contraction off, no fast math):

| Kernel | Per lane | Inputs |
|---|---|---|
| `K-probe-unary` | `s = sqrt(x)`, `r = 1.0f / x`, stored as bit patterns | x = the `f32` whose bit pattern is the lane's 32-bit index |
| `K-probe-binary` | `a + b`, `a − b`, `a · b`, `a ÷ b`, stored as bit patterns | operand pairs uploaded by the host |
| `K-probe-contract` | `d = a·a − c`, written as two statements in ordinary dialect code | a = 1 + 2⁻¹², c = 1 + 2⁻¹¹, and 4,096 random triples |
| `K-probe-fma` | `f = FMA(a, a, −c)` through an explicit prelude macro | the same operands |

`K-probe-fma` is the only kernel in the repository allowed to name a fused operation. It lives in the probe library
under a lint exemption recorded in the dialect lint's allow-list with this bead's key, and exists to record how each
family rounds an explicit fused operation (data for OPEN-NUM-1, "is an explicit fused multiply-add ever admitted in
batched kernels"; default no; the ban does not wait on the data).

**Exhaustive unary probe.** All 2³² bit patterns, in 256 chunks of 2²⁴ lanes. For each chunk the device result
slabs (64 MiB each) are read back after completion and compared byte for byte with the reference computed on the
host by Rust `f32::sqrt` and `1.0f32 / x`. The host reference is itself cross-checked: (1) its digest over all 2³²
inputs must be equal on this Mac (AArch64) and on `trj` (x86-64); (2) on a seeded sample of 2²⁴ inputs an exact
integer test confirms correct rounding of √ (for the candidate s and the two neighbouring floats, compare squares
with the input in 128-bit integer arithmetic).

**Sampled binary probe.** 10⁹ operand pairs per device family, generated on the host from FrankenSim's Philox
stream keyed by (seed, stratum, index), uploaded in chunks of 2²⁴ pairs. Eight strata of 1.25·10⁸ pairs each
(DESIGN): (1) uniform random bit patterns; (2) pairs with equal or adjacent exponents (cancellation); (3) one
subnormal operand; (4) results near underflow (exponent sums near −126 to −149); (5) results near overflow
(exponent sums near +127); (6) constructed ties, where the exact result lies halfway between two floats;
(7) special values (±0, ±∞, NaN) against a random partner; (8) powers of two and small integers, including the
signed-zero cases x − x and (−0) + (−0). The seed is explicit and recorded.

**Comparison rule.** Results are compared as bit patterns. A lane whose reference and device results are both NaN
counts as agreeing in value; whether the payload bits also agree is recorded as `nan_payload: same | differs`
(any NaN marks a world `Faulted`, so a payload never enters state). Every other difference is a mismatch and is
counted by class: `normal`, `subnormal-operand`, `subnormal-result`, `signed-zero`, `overflow-edge`. The first
mismatch of each class is kept with input bits, device bits and reference bits.

**Contraction detector (KA-526).** In `f32`, (1 + 2⁻¹²)·(1 + 2⁻¹²) = 1 + 2⁻¹¹ + 2⁻²⁴ exactly; 2⁻²⁴ is half a unit
in the last place at 1 and the tie rounds to even, so the rounded product is 1 + 2⁻¹¹ and d = 0. A fused evaluation
keeps the exact product and returns d = 2⁻²⁴. Expected: `K-probe-contract` returns 0 on every backend;
`K-probe-fma` returns 2⁻²⁴ on a correctly rounding fused unit (its actual value is recorded per family).

**Subnormal behaviour.** Classified from strata 3 and 4 and from the unary probe on subnormal inputs:
`ieee` (all agree), `flush` (results or operands treated as zero), `mixed` (depends on the operation).

**Attainable class (DESIGN).** A device family's best attainable class for `float` kernels is D1 if and only if
the unary probe and all four binary operations show zero mismatches of every class and the contraction detector
returns 0. Otherwise it is D2 for itself and D3 against other placements. The plan defines no intermediate class
(such as "D1 away from subnormals"); the mismatch classes are stored so that the KILL-D1 decision is made on the
detail.

**Report (DESIGN; record `frob.probe/1`, stored in the ledger as device evidence, evidence class `Tested`).**
Fields: device identity and family; driver, runtime and compiler identities; prelude and probe-library hashes; seed;
per operation and stratum: lanes tested, mismatches by class, first mismatch; contraction detector value; explicit
fused value; `subnormals`; `nan_payload`; `attainable_class`; `probe_digest` (BLAKE3 of the canonical record).
The fingerprint (BD-029) copies `probe_digest`, `attainable_class` and `subnormals` into its `arithmetic` block;
if the probe has not run the fingerprint field is `unavailable: probe not run`.

**Verb (registry entry in `registries/verbs.toml`; kind `run`; first milestone M0; cluster `devices`).**
`frob spark probe --device <id|family> [--suite ieee|boundary|canary|all] [--seed N] [--quick] --json`.
As a `run` verb it takes an idempotency key and a budget, honours the bounded synchronous wait and otherwise
returns a job handle with exit code 8. `--quick` runs 2²⁴ unary inputs and 10⁶ pairs per stratum and marks the
report `partial: true`; a partial report never sets `attainable_class`. Schemas `frob.spark.probe.in/1` and
`frob.spark.probe.out/1` (DESIGN names, generated from the registry). Exit 0 when the suite completes with class D1
attainable; exit 2 when it completes with findings (any mismatch, a non-zero detector); exit 6 with
`FROB-REF-601` (device unavailable or lost; repair: another device), `FROB-REF-603` (kernel compile failure,
diagnostics verbatim), or `FROB-REF-606` once fingerprints exist and the stored one no longer matches the machine.

**Cost.** 2³² lanes of two operations and 4·10⁹ binary operations are seconds of device time; the dominant cost is
reading back 2 × 16 GiB of unary results and uploading 8 GB of operands per run, a few minutes. The probe is run on
a fingerprint change, not per job.

## Acceptance criteria

- [ ] On this Mac's Metal device and on each RTX 4090 of `trj`, the full `ieee` suite completes and its report is stored as device evidence keyed by device and driver (seed done-condition: GATE-SPARK-01 results stored for both families).
- [ ] GATE-SPARK-01 is recorded per family with measured values: mismatches of `f32` √ and reciprocal over all 2³² inputs; mismatches of +, −, ×, ÷ over 10⁹ pairs including the subnormal and overflow strata; the contraction detector value; `subnormals`; `nan_payload`; the attainable class.
- [ ] The contraction detector fires on a planted fused multiply-add: a build of `K-probe-contract` through a prelude with contraction switched on returns 2⁻²⁴ and the report says `contraction: detected` (seed done-condition); the explicit fused kernel returns 2⁻²⁴ (KA-526's negative control).
- [ ] A planted one-bit corruption of the device result of one lane is reported with its input bits (comparison negative control).
- [ ] The host reference digest is identical on this Mac and on `trj`.
- [ ] `--quick` reports are marked partial and do not set the class.
- [ ] `frob spark probe --json` returns one envelope with the evidence block; the verb appears in `registries/verbs.toml` with its refusals; the probe kernels have manifests and CPU reference symbols.
- [ ] Cancellation during the suite drains at a chunk boundary and stores nothing as a result.

## Test plan

### Unit tests
- `contraction_detector_reference`: in Rust `f32`, `(1 + 2⁻¹²)·(1 + 2⁻¹²) − (1 + 2⁻¹¹)` is 0, and `mul_add` of the same operands is 2⁻²⁴ (5.9604645e−8).
- `unary_reference_correctly_rounded`: 2²⁴ seeded inputs; the exact 128-bit test accepts the host's √ for every input.
- `strata_generator_is_addressed`: the pair at (seed 7, stratum 6, index 123) is the same regardless of chunk size or generation order; stratum 6 pairs are exact ties in at least one of the four operations.
- `compare_counts_classes`: a synthetic result slab (labelled `synthetic`) with one planted difference per class is counted in the right class and the first mismatch is retained.
- `nan_payload_not_a_mismatch`: NaN against NaN with a different payload yields zero mismatches and `nan_payload: differs`.
- `class_rule`: zero mismatches and detector 0 give D1; one `subnormal-result` mismatch gives D2/D3; detector 2⁻²⁴ gives D2/D3.
- `probe_runs_on_batch_cpu`: the whole `--quick` suite through the harness on `batch-cpu` yields zero mismatches (the backend compared with itself through two code paths: kernel symbol against scalar loop).
- `report_roundtrip_digest`: canonical serialization is stable; `probe_digest` changes when one count changes.

### End-to-end script and logging
`scripts/e2e/spark_probe.sh` (bead N21b-40) drives `frob spark probe --suite all` on the devices of the host it
runs on and logs, per the STD-E2E helper, the command, exit code, wall time, the evidence block, per-operation
mismatch counts against the threshold 0, the detector value, the attainable class and the probe digest.

### Known answers and negative controls
- KA-540 (IEEE probe per device family: exhaustive √ and reciprocal over 2³² inputs; 10⁹ pairs; behaviour
  recorded; outcome sets the class; exact). KA-526 (contraction detector: 0 without contraction, 2⁻²⁴ with).
- Negative controls: the contraction-on prelude; the explicit fused form; a corrupted lane; a reference with a
  planted wrong rounding for one input (the exact integer test must reject it).
- Determinism lanes: the report's counts and digest are identical when the probe runs twice on one device; the host
  reference digest across the two hosts; debug and release builds of the host side.

## Considerations

- KILL-D1 (trigger: GATE-SPARK-01 or GATE-SPARK-02 shows a family cannot hold bit equality with `batch-cpu` for the
  floating kernels of the step; fallback: that family is D2 for itself and D3 against others, with the
  decision-level test; a teleported world is a tolerance replay; a comparison whose arms ran on different families
  is unpaired). This bead supplies the first half of its evidence. M0's stop rule also reads it: a device family
  that can hold no controlled class is dropped from M2.
- RISK-04 (bit equality across backends unattainable on a family; medium): the early signal is exactly this
  report.
- A probe proves agreement on the operations it ran. It does not prove a compiler will never reorder or contract a
  larger expression; that is what the per-kernel check (BD-176) and the canaries (N21b-36) are for.
- A driver, operating-system or compiler update changes the fingerprint and makes the stored report stale; the
  probe is re-run before the family's class is cited again (RISK-48).
- Privacy and safety: the probe reads no scene or design data. Memory: the largest transient is one 2²⁴-lane chunk
  (64 MiB per result slab).
