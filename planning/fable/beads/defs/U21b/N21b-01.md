## Background

A kernel in FrankenRobotics is three things: a manifest, its arithmetic and its sources. The manifest is what the
host believes about the kernel. A device kernel is only as safe as that belief: the Metal gateway, for example,
checks the read and write declarations of a batch against each other but not against the shader source (FACT:
`frankentorch/crates/ft-kernel-metal/src/compute.rs`), so if a declaration is wrong nothing downstream notices.
The manifest therefore carries a **stage signature** (DESIGN): a machine-checked statement of which buffer ranges
the kernel reads and writes, what layout it expects, which ownership epoch it reads and writes, what resources it
needs and what numerical contract it keeps. This bead defines the manifest record, its schema `frob.kernel/1`, its
content hash `KernelId`, and the validation that refuses a manifest or a binding that violates its signature.

It serves three invariants and two proof obligations of Spark: INV-SPARK-04 (no kernel reads or writes another
world's rows, except `stat` kernels, whose outputs never feed state), PO-SPARK-03 (resource bounds in the manifest
hold and fit each backend's limits), PO-SPARK-04 (declared read and write footprints contain the IR's load and
store sets), and, through the layout fields, the stride rule that protects the interchange boundary.

Why layout carries a stride unit and signedness. FACT to recheck at admission (INT-FNP-01, INT-FT-01): the pinned
FrankenNumPy uses signed byte strides and the pinned FrankenTorch unsigned element strides. The smallest case that
breaks a naive hand-off: a 2 × 2 contiguous `f32` view has strides (8, 4) under the first convention and (2, 1)
under the second. Copying (8, 4) verbatim as element strides onto a 16-element buffer reads element 8 + 4 = 12 at
index [1, 1], where element 3 belongs; both reads are in bounds, so nothing faults (KA-532, CX-218). A layout that
does not say what its strides mean cannot be checked.

Tier: Solid. Crate: `frob-kernels` (layer 3).

## Scope

In: the `KernelManifest` and `StageSignature` types; canonical serialization and `KernelId`; the registry file
`registries/kernels.toml` loader for manifests; the fields the doctrine lints D-1, D-3 and D-7 read (each
argument's element kind, component names and state flag; each row's arithmetic origin and the lowering of each
state argument); static validation of a manifest; binding validation (arguments
bound to slabs) used by `KernelBackend::plan`; the per-world footprint rule; the checks of PO-SPARK-03 and
PO-SPARK-04 on the manifest side; the `kernels` section of `frob doctor` that reports manifest validation.

Out: computing load and store sets and resource counts from a program (the IR, BD-018); the skeleton lint (BD-013);
the typed stride converter between array libraries (BD-036: this bead only records the convention a layout uses and
refuses a mismatch); what the binding path does with a mismatch a copy could repair, materialization charged to
the receipt or `FROB-REF-617` under a zero-copy contract (N21a-05, M2, which builds on this check); kernel classes' arithmetic rules and the guard derivation (BD-030, BD-053); certificates
attached to a manifest (frob-lemma beads).

## Technical approach

**Record (DESIGN; schema `frob.kernel/1`).**

```rust
pub struct KernelManifest {
    pub id: KernelId,                       // BLAKE3 over the canonical record without `id`
    pub name: KernelName,                   // e.g. "K-cay-step"
    pub class: KernelClass,                 // Float | Exact | Guarded | Stat
    pub role: KernelRole,                   // Ordinary | StrictPredicate | Digest | NegativeControl (BD-030 adds its tests)
    pub args: Vec<ArgDecl>,                 // inputs and outputs: element type, shape in capacities, physical dimension,
                                            // element kind, component names, state flag (below)
    pub determinism: DeterminismClass,      // class claimed: D0 for Exact and for the decisions of Guarded; D2 for Float
    pub identities: Vec<IdentityDecl>,      // algebraic identities the kernel declares; certificates attach here
    pub derivative: Option<KernelId>,       // the derivative program, if one exists
    pub cpu_reference: SymbolName,          // the Rust symbol that is its permanent CPU reference
    pub signature: StageSignature,
}

pub struct StageSignature {
    pub reads: Vec<Footprint>,              // per buffer argument: index range in terms of capacities
    pub writes: Vec<Footprint>,
    pub may_alias: Vec<(ArgId, ArgId)>,     // pairs that may be the same slab; empty by default
    pub layout: Vec<ArgLayout>,             // element type, extents, stride unit, stride signedness, origin, allocation extent
    pub epoch_read: EpochRef,               // ownership epoch the kernel reads (e.g. committed epoch e − 1)
    pub epoch_write: EpochRef,              // ownership epoch it writes (e.g. e)
    pub resources: ResourceBounds,          // live values, stack bytes, loop bounds, buffer argument count
    pub numerics: NumericalContract,        // precision profile, certified error bound if any, neutral padding elements
}
pub struct Footprint { arg: ArgId, lanes: LaneScope, lo: CapExpr, hi: CapExpr }   // half-open [lo, hi) per lane
pub enum LaneScope { OwnWorld, AllWorlds }                                        // AllWorlds only for class Stat
pub struct ArgLayout { elem: ElemType, extents: Vec<CapExpr>, stride_unit: StrideUnit /* Bytes | Elements */,
                       stride_signed: bool, origin: CapExpr, alloc_extent: CapExpr }
```

`CapExpr` is an affine expression with non-negative integer coefficients over the capacities of a shape class
(`nv_cap`, `link_cap`, `contact_cap`, `row_cap`, `sample_cap`, `actuator_cap`, world count), so a footprint can be
evaluated exactly for any class. Physical dimensions are exponent vectors over the `fs-qty` base dimensions
(re-exported by `frob_core::qty`).

**What an argument holds (DESIGN; read by the doctrine lints of N10a-03).** Each `ArgDecl` also carries
`kind: ElemKind`, `components: Vec<ComponentName>` and `state: bool`. `ElemKind` is the closed set `quaternion`,
`unit-complex`, `turn-count`, `vector`, `twist`, `wrench`, `scalar` (its dimension is the argument's physical
dimension), `integer` (indices, counts, flags, digest words), and the coordinate kinds `angle`, `euler-triple`,
`roll-pitch-yaw`, `axis-angle`, which exist in the set only so that a manifest declaring one can be written and
then refused for state by N10a-03's D-3 lint; this bead's validation does not judge kinds. `components` names
the components in storage order (`["w", "x", "y", "z"]` for a quaternion, `["c", "s"]` for a unit complex number).
`state` is true for a slab of the world's persistent state (read at epoch e − 1, published at e by the commit
fence). The schema requires all three fields, so a manifest without them does not parse. They are part of the
canonical record and so of `KernelId`: an argument whose declared meaning changes is a new kernel interface.

**Canonical form and identity.** Fields in a fixed order, lists sorted by `ArgId`, integers in decimal, serialized
as canonical JSON; `KernelId` = BLAKE3 of those bytes. Two manifests that differ in any signature field have
different identities, so a changed footprint is a new kernel.

**Static validation (run when `registries/kernels.toml` is loaded and again in `KernelBackend::compile`).**

1. Every buffer argument appears in `reads`, `writes` or both; no footprint names an undeclared argument.
2. For every footprint and every admitted shape class, 0 ≤ lo ≤ hi ≤ `alloc_extent` of that argument.
3. `LaneScope::AllWorlds` appears only when `class` is `Stat`; a `Stat` kernel's outputs carry `feeds_state: false`
   and no `Float`, `Exact` or `Guarded` kernel may read a slab that only `Stat` kernels write (INV-SPARK-04).
4. `class = Exact` implies `determinism = D0` and every argument is `u32`, `bool`, or a floating slab declared with
   the view `Bits` (its raw IEEE bit patterns read as `u32` words, with no floating operation applied); `class =
   Guarded` implies a certified error bound ε and a deferral threshold τ ≥ ε are present in `numerics` and an
   `Exact` fallback kernel is named; `role = StrictPredicate` or `role = Digest` with `class = Float` is refused (the
   M0 form of the build-time refusal `FROB-REF-252`; BD-030 carries its tests), and a `NegativeControl` manifest
   loads only into the conformance registry. The `Bits` view exists because exact kernels must read float state: `K-x-digest` folds the raw bit patterns of the
   canonical state slabs, and `K-x-hist` takes its bin from the sign, exponent and top mantissa bits of an `f32`
   pattern (DESIGN). Binding rule 1 treats an `f32` slab bound to an `f32`-`Bits` argument as the same bytes: no
   copy, no conversion.
5. `resources.buffer_args` equals the number of buffer arguments; all bounds are finite.
6. `numerics.neutral` gives, for every padded output consumed by a reduction, the neutral element of that consumer:
   −0.0 for sums, 1.0 for products, +∞ for minimum, −∞ for maximum, identity rows with zero right-hand side for a
   factorization.
7. For a generated body (the manifest names a `frob.kir/1` program), the IR's load set ⊆ `reads` and its store set
   ⊆ `writes`, and the IR's computed `max_regs`, `max_stack_bytes`, loop bounds and argument count equal
   `resources` (PO-SPARK-04, PO-SPARK-03). For a hand-written skeleton the same containment is asserted by the
   dialect lint and recorded as `footprint_evidence: lint`.

**Binding validation (run by `plan` when arguments are bound to slabs).**

1. Element type and layout of the slab equal the argument's `ArgLayout`, including stride unit and signedness. A
   mismatch is the typed error `LayoutMismatch`, naming both layouts (unit, signedness, strides, origin, extent);
   this check never copies. Materializing a view a copy could repair (at environment creation, the copy charged to
   the receipt) or refusing it under a zero-copy contract with `FROB-REF-617` is N21a-05's binding path, built on
   this check and on the typed converter of BD-036.
2. For every pair of arguments bound to overlapping ranges of the same slab where at least one is written: the pair
   must be in `may_alias`, otherwise the binding is refused as an **undeclared alias**, naming the kernel, both
   arguments and the slab.
3. The write footprint, mapped through the binding, must lie inside the slab range the plan declared as this
   kernel's output; writing a slab the stage did not declare is the same error.
4. `epoch_read` and `epoch_write` are consistent with the plan: a kernel that reads epoch e − 1 is never bound to
   the slab another kernel of the same launch writes at epoch e unless that order is declared.
5. Resource bounds are compared with the target backend's limits by the emitter and the backend; a kernel whose
   argument count exceeds a backend limit (31 buffer arguments for a Metal compute function, FACT) is refused for
   that backend before anything is compiled.

**Errors.** Static and binding failures are typed registration errors (`ManifestError::{UndeclaredAlias,
FootprintOutOfRange, CrossWorldFootprint, ClassMismatch, ResourceMismatch, NeutralMissing, LoadStoreNotContained,
LayoutMismatch}`)
that stop the library from compiling; they are build-and-load-time failures, not agent-facing refusals. The plan
assigns no `FROB-REF` code to them (see Considerations).

**Registry.** `registries/kernels.toml` lists every kernel by name with its manifest path and `KernelId`;
`xtask check-generated` compares regenerated manifests with the checked-in ones. Each row also records two
provenance fields that stay outside `KernelId` (DESIGN: re-running a derivation or a lowering under a new hash
leaves the kernel's interface unchanged and must neither make a new kernel nor make its CPU-versus-device check
stale):
- `origin`, the provenance of the kernel's arithmetic core: `derived { derivation_hash, source_hash }` (the hash
  of the symbolic derivation and of the checked-in generated file; BD-019 records the digests of the emitted files
  in the same row), `skeleton` (loops, gathers, sorts, reductions and scans: no floating-point arithmetic beyond
  index arithmetic and copies) or `handwritten { reason, adr }` (the decision record that admits it). Required: a
  row without `origin` does not load, and the error names the kernel.
- `lowers`, one entry per argument whose `state` is true: `{ arg, model, field_path, lowering_hash }`, the
  algebraic description the buffer lowers (the identity of the model schema the field belongs to, the field's
  path such as `links[].joint.rotation`, and the derivation hash of the lowering that packs it into the slab).
  The loader accepts a row with an entry missing, so that N10a-03's D-1 lint can report it as its finding.
Whether an origin is admissible for a kernel's arithmetic, whether a state kind is a coordinate, and the replay of
each registered lowering are N10a-03's lints D-7, D-3 and D-1, which read these fields and the `ArgDecl` fields
above.

**Where a user sees it (DESIGN).** `frob-kernels` provides a `kernels` section to `frob doctor` (BD-022's section
interface): the registry path and digest, the number of manifests, and one finding per manifest that fails static
validation, naming the kernel, the rule and the error (`ManifestError` variant). `frob doctor --section kernels
--json` exits 0 when every manifest validates and 2 with one finding per failure; it compiles nothing and launches
nothing.

## Acceptance criteria

- [ ] `frob.kernel/1` has a schema under `schemas/`, a canonical serializer, and a round-trip test; `KernelId` is stable across macOS and Linux.
- [ ] Each of the seven static rules and five binding rules has a positive test and a planted violation that is refused with its named error.
- [ ] The undeclared-alias case of BD-014's done-condition is refused: two arguments bound to one slab, one written, pair not in `may_alias`.
- [ ] A `Float` kernel with a footprint of scope `AllWorlds` is refused (INV-SPARK-04); the same footprint on a `Stat` kernel is accepted and its outputs cannot be bound as an input of a non-`Stat` kernel.
- [ ] The 2 × 2 stride case: a slab described in bytes, strides (8, 4), bound to an argument declared in elements, strides (2, 1), is refused with `LayoutMismatch` naming both layouts, and the same view described in elements binds. (Materialization with its receipt charge, and `FROB-REF-617` under a zero-copy contract, are N21a-05's criteria: the receipt is BD-014's, which depends on this bead.)
- [ ] A manifest with 32 buffer arguments is refused for the Metal backend and accepted for `batch-cpu`.
- [ ] Containment (PO-SPARK-04) is enforced through an interface that takes a program's load and store sets and resource counts: a manifest with one footprint narrowed by one element is refused. The kernel IR (BD-018) fills that interface for generated bodies and the dialect lint (BD-013) for skeletons; the wiring for the M0 kernels `K-cay-step` and `K-normalize` is asserted in BD-020.
- [ ] Every `ArgDecl` carries `kind`, `components` and `state`, and every registry row `origin` and a `lowers` entry per state argument, in the forms above; a manifest without `kind` does not parse, a row without `origin` does not load (the error names the kernel), and `KernelId` changes with an argument's `kind` but not with a row's `origin` or `lowering_hash`.
- [ ] `CONTRACT.md` of `frob-kernels` documents the manifest fields, the registry row's provenance fields and the validation rules.
- [ ] `frob doctor --section kernels --json` exits 0 on the real registry and 2 with one finding (kernel, rule, error) for each planted bad manifest; an `Exact` kernel reading an `f32` slab through the `Bits` view validates.

## Test plan

### Unit tests
- `manifest_roundtrip_and_id`: serialize, parse, re-serialize; equal bytes; `KernelId` unchanged; changing one footprint bound changes the id.
- `arg_meaning_and_provenance_fields`: a `synthetic` manifest with a `quaternion` state argument (`components = ["w", "x", "y", "z"]`) and its registry row with `origin = derived { … }` and one `lowers` entry round-trip; the manifest without `kind` fails to parse; the row without `origin` fails to load naming the kernel; changing `kind` to `vector` changes `KernelId`, while changing `origin`'s `derivation_hash` or the entry's `lowering_hash` leaves it unchanged; a row whose state argument has no `lowers` entry loads.
- `footprint_eval_all_classes`: evaluates `[0, 4·row_cap)` and similar for the default capacities (degrees of freedom 12, 18, 24, 36, 48, 64) and asserts hi ≤ allocation extent.
- `undeclared_alias_refused`, `declared_alias_accepted`: same binding with and without the pair in `may_alias`.
- `cross_world_footprint_refused`: `AllWorlds` on a `Float` kernel.
- `stat_output_cannot_feed_state`: binding a `Stat` output as a `Float` input is refused.
- `exact_class_requires_u32`: an `Exact` manifest with a plain `f32` argument is refused.
- `exact_reads_float_bits`: a digest-shaped `Exact` manifest (synthetic) reading an `f32` state slab through the `Bits` view is accepted and binds to that slab without a copy; the same manifest with the view removed is refused with `ClassMismatch`.
- `guarded_requires_bound_and_fallback`: missing either is refused.
- `neutral_elements_checked`: a sum-consumed padded output declaring +0.0 is refused; −0.0 is accepted.
- `stride_convention_2x2`: byte strides (8, 4) against element strides (2, 1): `LayoutMismatch` naming both layouts; element strides (2, 1) bind and index [1, 1] addresses element 3. The planted mutant that compares strides without their unit accepts the byte-strided binding, and indexing the 16-element buffer through the copied strides reads element 12 at [1, 1]; the test asserts that value from the mutant and that the real check refuses the same binding.
- `metal_argument_limit`: 31 accepted, 32 refused for the backend whose limit is 31.
- `load_store_containment`: a synthetic IR program (labelled `synthetic`) with a store at offset k outside the declared write range is refused.
- Property test (PO-SPARK-04): for random affine footprints and random load and store sets, validation accepts exactly when containment holds.

### End-to-end script and logging
`scripts/e2e/spark_manifest_registry.sh`: runs `cargo run -p xtask -- check-generated` and
`frob doctor --section kernels --json` on the real registry (exit 0, zero findings, the registry digest logged),
then repeats with each file of `tests/fixtures/bad-manifests/` (one per static rule) copied into a scratch registry
(`FROB_REGISTRY_DIR` pointing at the scratch copy) and asserts exit 2 with exactly one finding naming the planted
kernel and the expected `ManifestError` variant. Logged through the STD-E2E helper: one `cmd` line per run with
exit code and wall time, one `assert` line per fixture with the expected and observed error name, the registry
digest, and on failure the first differing field and the path of the scratch registry. Final `summary` line.

### Known answers and negative controls
- KA-532 (stride conventions on a 2 × 2 view: element 3 at [1, 1]); CX-218 (the verbatim stride copy reads element
  12, in bounds): the mutant must be shown to read 12 and must be refused by the layout check.
- Negative controls registered with the conformance registry: undeclared alias; cross-world footprint; narrowed
  footprint; +0.0 as the neutral element of a sum; a `Stat` output wired into state.
- Metamorphic: permuting the declaration order of arguments leaves `KernelId` unchanged (lists are sorted in the
  canonical form); adding an unused capacity to the shape class leaves validation results unchanged.

## Considerations

- No refusal code is assigned by the plan to a manifest that fails validation. This bead treats it as a build or
  load failure, which never reaches an agent as a result. If the registry of refusal codes later wants an
  agent-visible code (for a user-supplied kernel, which is not planned), it belongs in the build-time `25x` family
  beside `FROB-REF-250` (not dimensionally homogeneous) and `FROB-REF-251` (banned operation).
- The footprint language is deliberately affine in capacities. A kernel whose access pattern cannot be bounded this
  way (data-dependent offsets beyond a gather inside its own world's rows) declares the whole per-world range.
- INV-SPARK-04 is enforced here statically and by GATE-SPARK-15 dynamically (per-world digests identical under
  co-tenancy); the static rule is cheap and catches the defect before a device run.
- FD-FNP-01 (upstream, franken_numpy and frankentorch, P2) adds a named conversion between the two stride
  conventions; until it lands the typed converter of BD-036 stands at the boundary and this bead refuses unlabeled
  strides.
- The epoch fields are inert at M0 (one epoch) and become binding with the commit fence and leases at M2 (N21b-07,
  N21b-11).
