## Background

Two of Spark's seven verbs are the user-visible surface of the binary kernel cache (N21b-12). `spark.cache` lets an
agent or an engineer see what is cached, whether it is intact, how often it hit, and evict entries.
`spark.precompile` compiles or loads the kernel set of a shape class ahead of time, including on a build host that
has no GPU: `frob spark precompile sm_89` fills the cache for an RTX 4090's architecture from a machine without
one, the same recipe FrankenSim's `render-gpu --precompile` uses (FACT). Both matter for the path from an edit to
the first GPU step: a cool start (a new shape class with cached kernels) is targeted at 1 s, 5 s and 10 s at the
50th, 95th and 99th percentiles, while a cold start (empty cache) is reported separately and never averaged with
it; `trj`'s CPU is often heavily loaded and a compile there can take minutes.

The verb registry (`registries/verbs.toml`, owned by `frob-verbs`) is the single source from which the command
line, the daemon protocol, the tool definitions for agents, the schemas and the refusal table are generated. Verb
kinds: `read` returns stored or cheaply computed facts and changes nothing; `run` spends compute, takes an
idempotency key and a budget, accepts the bounded synchronous wait and otherwise returns a job handle with exit
code 8; `admin` cancels, stops, evicts or deletes and needs a capability scope. The registry lists `spark.cache` as
`read, admin` and `spark.precompile` as `run`, both first available at M2, in the cluster `spark` (rows of
VERBS-spark, a dependency; their task clusters are `devices` and `housekeeping` for `spark.cache` and `devices`
for `spark.precompile`). Tier: Solid.

## Scope

In: registry entries, input and output schemas, the verb bodies in `frob-kernels` over the cache API, examples,
refusal lists, exit codes, and unit tests of the surface.

Out: the cache mechanism (N21b-12); specialization builds for survivors as a `spark.precompile` option (BD-371,
M4); the end-to-end script (N21b-14).

## Technical approach

**`spark.cache` (kinds `read` and `admin`).**

```text
frob spark cache --json                      # read: summary
frob spark cache --list [--backend cuda|metal] [--class <ShapeClassId>] --json
frob spark cache --verify --json             # read: recompute every entry's digest; report corrupt entries
frob spark cache --evict <key>|--evict-to <bytes>|--evict-all --json     # admin: needs the cache-admin scope
```

Output (schema `frob.spark.cache.out/1`, DESIGN name): cache directory; size in bytes against the cap (4 GiB by
default); entry count per backend; for the current process and cumulatively since the directory was created: hits,
misses, corrupt entries found, evictions, compiler invocations and compile seconds; with `--list`, per entry: key,
kernel name, backend, device architecture, compiler identity, driver version, value bytes, compile seconds,
created, last used, pinned or not; with `--verify`, per entry `ok | corrupt`. Eviction reports the keys removed and
the bytes freed and refuses to remove a pinned entry (it is listed as `skipped: in use`).

**Paging (the row's `paginated = true`; BD-173 pages long listings, this bead defines how).** The generator gives
the `read` forms the common inputs `cursor`, `limit` and `follow` and appends `FROB-REF-806` and `FROB-REF-807`
(N32a-02); the rules are N32a-10's keyset paging with the cache standing in for the store (DESIGN):
- *Order key*: (backend, key), unique because a key is a content hash; entries are listed in that order.
- *Frontier*: the cache keeps a write sequence `seq`, incremented by every entry written, and each entry's
  metadata records its `created_seq`. The first page pins F = the current `seq`; every page of that sequence
  lists only entries with `created_seq ≤ F` and an order key strictly greater than the cursor's, so entries
  written during the listing never appear in it. The cursor (`frob.cursor/1`) carries the query digest (action,
  `--backend` and `--class` filters, order), F, the last order key, the cache's `cache_epoch` and the schema
  version.
- *Evictions between pages*: an entry evicted after the first page is absent from later pages; each page states
  `evicted_since_first_page` (the cache's eviction counter since F), because a listing pins no cache content
  (DESIGN: a pin per listing reader would block eviction under the cap).
- *Last page*: no cursor, and `complete_at_frontier: F`. With `follow`, the next call opens a segment of the
  entries with F < `created_seq` ≤ F′ and states the new frontier F′.
- *Refusals*: a cursor presented with other filters, another action or another schema version is `FROB-REF-806`
  (exit 3); a cursor whose `cache_epoch` no longer matches (the directory was emptied by `--evict-all`, or replaced
  by a copied directory) is `FROB-REF-807` (exit 3; repair: start a new listing, which states the new frontier).
- *Limit*: DESIGN default 100 entries, range 1 to 1,000; a value outside it is `FROB-REF-808`.
- The summary form returns one page with no cursor. `--verify` alone checks every entry and returns the totals and
  every corrupt entry in full (they are moved aside and are few); `--verify --list` pages the per-entry
  `ok | corrupt` report under the same rules.

`read` forms never modify the directory except that `--verify` moves a corrupt entry aside, which is reported.
`admin` forms (the action `evict`) require the capability scope `spark:admin`; without it the verb returns
`FROB-REF-720` (the session token lacks a required scope; exit code 5, checked before the handler runs, so nothing
is evicted). Exit 0 on success; exit 2 when `--verify` finds corrupt entries
(completed with findings).

**`spark.precompile` (kind `run`).**

```text
frob spark precompile <target> [--class <ShapeClassId> | --workload Q|H | --all-registered] [--offline]
    [--target-fingerprint <file>] [--budget <b>] --key <k> --json
    <target>: a device id of this host (cuda:0, metal:0), a backend family, or a device architecture name such as sm_89
```

`--key` is required: from M2 a job-submitting `run` verb without one is refused with `FROB-REF-805` (exit 3); a
repeated key returns the stored envelope with `idempotent_replay: true` and compiles nothing.

It expands every kernel of the selected shape classes for the target, and for each either finds a valid cache
entry or compiles one and stores it. With an architecture name and no local device of that architecture it compiles
with the run-time-loaded compiler and never touches a device. In that case the driver version and the compiler
identity that enter the cache key cannot be read from a device, so they are read from `--target-fingerprint
<file>`: a `frob.fingerprint/1` record of the host that will load the cache, exported from that host (DESIGN,
N21b-12's `TargetIdentity`: without it the keys would never match on the target and the copied entries would
never hit). The option is required exactly when no device of the named architecture is visible, and is refused
as contradictory (`FROB-REF-802`) beside a device id. A missing record, a record whose architecture is not the
target, or one whose compiler identity differs from the compiler library loaded here is `FROB-REF-606`
(fingerprint missing or changed; exit 6; first repair: `frob spark fingerprint` on the target host and pass its
record). The path is read under the session's roots like any file parameter.

Options that other beads add to this verb, listed here so that the surface has one owner: `--unit <path>`
(N21a-10: compile one dialect unit file for the target through the lint, the compiler and the cache, reporting
`FROB-REF-251` or `FROB-REF-603` for a bad unit), and, at M4 and only while KILL-SPECIALIZE has not fired,
`--specialize <ModelId>` (BD-371: build the specialized kernel set of one survivor design; N21c-18's fallback
removes the option again if the gate fires, and until BD-371 lands it answers `FROB-REF-724`). Output (schema `frob.spark.precompile.out/1`): per
kernel: key, `hit | compiled | failed`, compile seconds; totals; the compiler identity and options used; the cache
size after. As a `run` verb it takes an idempotency key and a budget, honours `sync_wait_ms`, and otherwise returns
a job handle with exit code 8; progress has a denominator (kernels done of kernels total).

Refusals and exits: `FROB-REF-603` kernel compile failure, with the compiler's diagnostics verbatim (exit 6; first
repair: report; the generic kernel if a specialized one failed); `FROB-REF-612` cache entry corrupt and
recompilation unavailable, raised under `--offline` (exit 6; first repair: `spark precompile` on a build host);
`FROB-REF-601` when a named device is unavailable (exit 6); `FROB-REF-616` when the target lacks an arithmetic
feature a kernel declares, for example 64-bit integers (exit 6; first repair: the 32-bit variant, or another
backend); `FROB-REF-606` for the target-fingerprint cases above; `FROB-REF-251` for a lint finding in a `--unit`
file (exit 3, N21a-10). A misspelt target or class is a refusal, never a default. The registry row of
VERBS-spark now lists all six chapter codes, `--target-fingerprint` (a `params` entry of kind
`artifact-input<frob.fingerprint/1>`, so the generator appends 891 to 893, 734 and 828 for it), `--unit`,
`--specialize`, and the conformance-build-only `--kernel-set <name>` (N21c-17: a kernel set registered in the
pilot registry, recorded in the receipt and the disclosure block; absent from a release build's input schema,
802 there), which this bead's parser accepts and lists so that the surface has one owner. One more
conformance-build-only input is defined here for both verbs, with the semantics of `sim.run`'s `--cache-dir`
(N21b-39): `--cache-dir <path>` points the verb at another cache directory for this call (created empty if
absent), so that an end-to-end script can work in a scratch directory and never read or damage the user's cache
(N21b-14); a path outside the session's roots is `FROB-REF-734`; a release build's schema has no such field (802
there). It is requested of both VERBS-spark rows. The appended codes
follow the kind: 720, 723, 724, 802 and 808 on both verbs; 701 to 704, 761, 803 and 805 on `spark.precompile`;
806 and 807 on the paginated `read` of `spark.cache`.

**Evidence.** Both envelopes carry the fingerprint digest of the host (and of the target device when there is one),
evidence class `Tested`, and no physics identity; `spark.precompile` records the commit and the kernel library
hash so that a cache can be traced to the source that filled it.

## Acceptance criteria

- [ ] Both verbs are in `registries/verbs.toml` with kind, cluster `spark`, task clusters, capabilities, schemas, refusals and an example, as VERBS-spark's rows state them; the generated command line and agent tool definitions match the registry.
- [ ] `frob spark cache --json` on an empty directory reports zero entries and the cap; after a cold `frob spark precompile <device> --workload Q --key pc-cold` it reports one entry per kernel and the compile seconds; after a second precompile under a new key, hits equal to the kernel count. (The same after environment creation is N21b-14's `warm` step.)
- [ ] `--verify` detects a planted one-byte corruption, reports the entry `corrupt`, exits 2, and the entry is no longer served.
- [ ] `--evict-to` frees space in the cheapest-to-recompile-first order and skips pinned entries; without the admin scope it returns `FROB-REF-720` with exit 5 and changes nothing.
- [ ] `--list` pages: over a directory of 250 entries with `--limit 100`, three pages in (backend, key) order, the last with no cursor and `complete_at_frontier`; an entry written between pages two and three is absent from page three and present in the `follow` segment; an entry evicted between pages is absent and counted in `evicted_since_first_page`; a cursor with a changed `--backend` filter is `FROB-REF-806`; a cursor presented after `--evict-all` is `FROB-REF-807`; `--limit 0` and `--limit 1001` are `FROB-REF-808`.
- [ ] `frob spark precompile sm_89 --workload Q --target-fingerprint <record of trj> --key pc-sm89 --json` in a process that sees no CUDA device (on `trj` with its devices hidden, or on a Linux build host with NVRTC) exits 0, compiles every kernel of Q's shape class, and a subsequent run under a new key reports every kernel as `hit`; the same call without `--key` is `FROB-REF-805` (exit 3) and compiles nothing; without `--target-fingerprint`, or with a record whose compiler identity differs from the loaded compiler's, it is `FROB-REF-606` (exit 6) and compiles nothing; on `trj` with its devices visible the registry example `frob spark precompile sm_89 --workload Q --key pc-1 --json` needs no record.
- [ ] `--unit <path>` (N21a-10's option) and `--specialize <ModelId>` (BD-371's, `FROB-REF-724` until it lands) are accepted by the parser and listed in the generated help; an unknown option is still refused.
- [ ] A kernel with a planted syntax error makes `spark.precompile` return `FROB-REF-603` with the compiler's message verbatim; `--offline` on an empty cache returns `FROB-REF-612`.
- [ ] Each invocation with `--json` emits exactly one envelope; a long run returns exit 8 with a job handle and a progress denominator.
- [ ] Unknown flags and misspelt targets are refused.

## Test plan

### Unit tests
- `cache_summary_empty_and_filled`.
- `cache_list_fields`: every listed field present and typed; keys are 64 hex digits.
- `cache_list_paging`: the paging clause of the acceptance criteria on a `synthetic` cache directory (250 entries, three backends' worth of keys): order, frontier pin by `created_seq`, the `follow` segment, `evicted_since_first_page`, 806, 807 and 808; the concatenated pages equal one unpaged listing of the same frontier.
- `kernel_set_conformance_only`: `--kernel-set <name>` parses in a conformance build and is 802 in a release build's schema.
- `cache_dir_conformance_only`: in a conformance build `spark precompile --cache-dir <scratch>` fills only `<scratch>` (the default directory's listing is unchanged) and `spark cache --cache-dir <scratch> --json` reports it; a path outside the session's roots is `FROB-REF-734`; a release build's schema has no `cache_dir` field.
- `cache_verify_finds_corruption`.
- `cache_evict_requires_scope`: `FROB-REF-720` and exit 5 without the scope; with it, eviction order follows compile seconds.
- `precompile_requires_key`: no `--key` gives `FROB-REF-805`, exit 3, and the compiler-invocation counter is unchanged.
- `precompile_arch_without_device`: target `sm_89` with a `synthetic` target fingerprint record in a process with no CUDA device visible (the test runs wherever NVRTC can be loaded, on `trj` with the devices hidden; otherwise it is skipped with a logged reason): every kernel `compiled`, keys equal to those a device with the record's driver computes.
- `precompile_target_fingerprint_rules`: no record and no local device of the architecture → `FROB-REF-606`; a record for another architecture → 606 naming `architecture`; a record whose compiler identity differs → 606 naming `compiler`; a record given beside a device id → `FROB-REF-802`.
- `precompile_added_options_parse`: `--unit <path>` and `--specialize <ModelId>` parse; the latter answers `FROB-REF-724` in a build without BD-371.
- `precompile_idempotent`: the same idempotency key returns the stored envelope (`idempotent_replay: true`).
- `precompile_refusals`: 603 with verbatim diagnostics; 612 under `--offline`; 601 for an absent device; 616 for a kernel declaring 64-bit integers on a device that lacks them.
- `misspelt_target_refused`.
- Schema tests: outputs validate against the generated schemas.

### End-to-end script and logging
`scripts/e2e/spark_gate11_arena_cache.sh` (bead N21b-14) drives both verbs from the user's side, every
`spark precompile` under its own idempotency key, plus a `replay` step that repeats one key and asserts
`idempotent_replay: true` with zero compiler invocations, and a `no_key` step that asserts `FROB-REF-805`. Logged
per the STD-E2E helper: command, exit code, wall time, the evidence block, hits, misses, compiler invocations,
bytes against the cap, the keys evicted, and refusal envelopes.

### Known answers and negative controls
- KA-536 through the verb surface: perturbing source, options, compiler or driver identity shows a miss in
  `spark.precompile`'s per-kernel report; a corrupted entry is rejected.
- Negative controls: eviction without scope; an in-use entry targeted for eviction; a `--verify` that only checked
  file sizes (a test-only variant) must miss the one-byte corruption and fail the test.
- Determinism: `spark.precompile` twice with the same inputs produces identical keys and, on CUDA, byte-identical
  CUBINs where the compiler is deterministic; where it is not, the difference is recorded and the key (which hashes
  inputs, not outputs) is unaffected.

## Considerations

- Compile time on a loaded host can reach many minutes; the verb reports progress and never blocks an agent beyond
  the bounded wait.
- Precompiling for an architecture on a host without that GPU produces entries that cannot be run-tested there;
  their CPU-versus-device check is still required on the target before any result is citable.
- Survivor specialization (M4) adds an option to build specialized kernels for a cohort; it stays off until its
  funding gate passes and is out of scope here.
- The cache directory may be shared by several processes; verbs take the directory lock only for eviction.
- Privacy: kernel text contains no scene or design data at M2 (model variants are table data, not code); when
  specialization folds design constants into source, cache listings must not print the source.
