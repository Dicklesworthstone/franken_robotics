## Background

A batch of thousands of worlds cannot stop because one of them misbehaves, and it must never hide that one did.
The plan's rules for faults on the batched tiers:

- Device loss, out-of-memory, compile failure and a per-world non-finite sentinel are **typed refusals** in the
  backend-and-device family of refusal codes (`FROB-REF-6xx`); each carries the fingerprint digest and ranked
  repairs.
- A world that produces a non-finite value is **frozen and marked `Faulted`** for teleport (replay of that world on
  the CPU tier from its nearest snapshot, with step and stage localization).
- A world that overflows a capacity is **marked `Degraded` with the reason**, and the caller's policy chooses
  refuse, reset or continue-flagged. An overflow is never undefined behaviour and never a silent truncation.

The standing rules behind them: refuse, never truncate; a number never claims more than its certificate (every
result records how many worlds were `Degraded` or `Faulted`, and a summary statistic states what it excludes and
why); any NaN marks the world `Faulted`. On `batch-cpu` the capacity flags exist from the batched step's own bead
(BD-159: a forced contact overflow is flagged `Degraded`, never dropped silently). This bead is the device side
and the refusal surface: the per-world status word, the sentinel kernel, the freeze, the policies, and the typed
refusals for device-level faults. The seed bead BD-175 integrates faults and cancellation and records
GATE-SPARK-06. Tier: Solid.

## Scope

In: the per-world status word and reason codes; the non-finite sentinel and the freeze; `Degraded` reasons and the
three caller policies; thresholds and the refusals `FROB-REF-608` and `FROB-REF-610`; the device-level refusals
`FROB-REF-601`, `FROB-REF-602`, `FROB-REF-603`; counts in receipts and disclosure; fault-injection hooks for
tests.

Out: the launch-failure retry ladder and `FROB-REF-607` (N21b-07); the stall watchdog and `FROB-REF-615`
(N21b-24); cancellation (N21b-22); teleport itself (BD-204); the ill-conditioning figure that sets one `Degraded`
reason (N21b-38); capacity audits over the contact battery (BD-168).

## Technical approach

**Status word (DESIGN).** One `u32` per world in the `state` group, part of checkpointable state:

| Bits | Meaning |
|---|---|
| 0 | `Faulted`: a non-finite value was produced; the world is frozen |
| 1 | `Degraded: contact-capacity`: active contacts exceeded the contact capacity |
| 2 | `Degraded: row-capacity`: constraint rows exceeded the row capacity |
| 3 | `Degraded: ill-conditioned`: the conditioning lower bound times unit round-off exceeded 0.1 |
| 4 | `Degraded: sample-capacity` (collision candidates exceeded their capacity) |
| 5 to 7 | reserved for later reasons |
| 8 to 15 | stage index at which the first fault or degradation was detected (1 to 10) |
| 16 to 31 | low 16 bits of the step counter at first detection (the full step is in the telemetry row) |

Flags are sticky within an episode and cleared at a masked reset. Setting a flag is a per-world select; no atomics
are involved, since each world writes only its own word.

**Non-finite sentinel (`K-sentinel`, class `exact`).** At the end of each world-step, before the new state is
accepted, the kernel scans the world's new configuration, velocity and solver outputs as raw bit patterns and
tests the exponent field (all ones means infinity or NaN). The test is integer arithmetic, so it is identical on
every backend and cannot be optimized away by a compiler that assumes no NaNs. If any word is non-finite:
1. the world's new state is discarded by select and its previous state is kept (the world is **frozen** at its
   last finite state);
2. bit 0 is set with the stage and step;
3. from then on the world's `done` mask is forced, so every later step copies it forward unchanged.
The frozen state, the world's address and the step are exactly what teleport needs to replay it on `batch-cpu`.

**`Degraded` (capacity overflow).** Compaction kernels (count, exclusive scan, write) know the true count before
they write; when it exceeds the capacity they write the first `capacity` entries in the deterministic order,
set the reason bit, and record the true count in a per-world overflow counter. The world keeps stepping with the
flagged result unless policy says otherwise. This is the only place a result is computed on less than the full
contact set, and it is always flagged.

**Caller policies (per run; DESIGN surface `--on-overflow refuse|reset|continue-flagged`).**
- `refuse`: the first `Degraded` world ends the run at the next chunk boundary with `FROB-REF-610` (capacity
  overflow under the `refuse` policy; exit code 6; first repair: a larger capacity; then `continue-flagged`). The
  refusal names the world address, the stage, the capacity (`pointer`) and the count that was needed.
  Which code on which tier (decided here, following the two registry rows as integrated): the plan names this
  condition twice, `FROB-REF-610` in the Spark chapter (§21.21) and `FROB-REF-722` in the batched-step chapter
  (§16.14, KA-349). The refusal registries split them by tier: on the device tiers (`gpu-cuda`, `gpu-metal`) this
  bead raises `FROB-REF-610` (N21-REF); on `batch-cpu` and the other lockstep tiers BD-159 raises `FROB-REF-722`
  (N16-REF). Both come from one function that takes the tier, so the trigger, `pointer` and repairs are the same,
  and KA-349's device rows are met by `FROB-REF-610`. A test asserts that a forced overflow gives 610 on each device
  and 722 on `batch-cpu`, with the same pointer and needed count.
- `reset`: the world is reset at the next masked reset and the episode is recorded as invalid (a study error, not
  a transition), counted in the scorecard's exclusions.
- `continue-flagged`: the world continues; every result derived from it carries the flag.
The default is `continue-flagged` for training and `refuse` for evidence-bearing evaluation (DESIGN default; the
verb that starts the run states the policy in its envelope).

**`Faulted` threshold.** A run declares the largest number or fraction of `Faulted` worlds it tolerates
(`--max-faulted <count | fraction>`, an option this bead and BD-175 add to `sim.run` beside `--on-overflow`;
default 0 for evaluation; VERBS-sim lists the option and the code 608). Exceeding it ends the run at the next
chunk boundary with `FROB-REF-608` (worlds marked `Faulted` exceed the caller's threshold; exit code 6; first
repair: teleport a faulted world to `batch-cpu`), listing the faulted world addresses with their stage and step.

**Raising paths of 608 and 610 (one function, two verbs).** The threshold test and the overflow refusal are one
function of the run, called by every verb that steps worlds on a device tier: `sim.run`, and `eval.run` on
`gpu-cuda` or `gpu-metal` (its row lists 601, 602, 608, 610 and 722). Under `eval.run` the threshold is the
evaluation threshold 0 (an evidence-bearing evaluation tolerates no `Faulted` world; `--max-faulted` stays a
`sim.run` option and is not an input of `eval.run`), so one `Faulted` world in a battery run on a GPU tier ends
it with `FROB-REF-608`; its overflow policy is `eval.run`'s `--on-overflow` (default `refuse`), so an overflow
under it is `FROB-REF-610` on a GPU tier and `FROB-REF-722` on `batch-cpu`, from the same function as for
`sim.run`, with the same fields and repairs.

**Device-level typed refusals.**
- `FROB-REF-601` Device unavailable or lost: raised when a device cannot be opened, disappears, or reports a
  context loss. First repair: rerun on another device, or on `batch-cpu` under `mixed-allowed`. After a loss the
  run can resume from the last committed epoch on a device of the same family (a continuation) or be teleported.
- `FROB-REF-602` The memory estimate exceeds the device budget at admission: raised before anything is allocated
  (the arena planner's total against the device budget), with the slab-class `pointer`, observed and required bytes
  and the repairs of that class as N21b-10 computes them (for `worlds`: fewer worlds with the largest count that
  fits named, a smaller capacity, or this Mac).
- `FROB-REF-603` Kernel compile failure, with the compiler diagnostics verbatim. First repair: report; the generic
  kernel if a specialized one failed.
All three are exit code 6, carry the fingerprint digest, and leave no partial result published.

**Counts and wording.** Every receipt, envelope and disclosure block carries the counts of `Degraded` worlds by
reason and of `Faulted` worlds, capacity headroom (the largest active contact and row counts against their
capacities), and for any summary statistic the number of worlds excluded and why. TARGET: under the default
capacities `Degraded` world-steps are at most 10⁻⁴ of all world-steps per robot class on the standard battery, and
every one is flagged.

**Fault-injection hooks (conformance builds only).** Per-world: overwrite one state word of a chosen world with a
NaN bit pattern at a chosen step; force a contact count above capacity. Per-device: fail the next device open
(601); lower the device budget (602); plant a syntax error in one kernel (603).

Their command-line spellings (DESIGN; each absent from a release build's schema, where it is 802; in a
conformance build each enters the run's `StepPlanId`, the precedent of N21b-07's `--inject-faults`), so that the
gate's script drives every fault through a registered input:
- The two per-world hooks are plant kinds of N29a-25's plant file, registered by this bead in
  `registries/plant-kinds.toml` without changing N29a-25, and reached through `sim.run`'s existing
  `--conformance-plant <file>`: kind `nan` (the fields of N29a-25's `Plant`, naming world address, tick, substep,
  stage, output and element, with the action `Nan { bits }`, default `0x7FC00000`, and `0x7F800000` and
  `0xFF800000` admitted for the infinities; the element must be one the sentinel scans) and kind `overflow`
  (`{ world, tick, capacity: contacts | rows | samples, count }`, `count` above the capacity: the compaction of that
  world at that tick sees `count` candidates and takes the overflow path). Admission is this bead's; the receipt
  lists each plant `applied` or `skipped` as for every kind.
- Device loss is a `sim.run` input this bead owns, `--inject-device-loss open | chunk=<k>` (the device open fails;
  or the device reports a context loss at chunk k), listed in VERBS-sim's conformance-only inputs.
- An over-budget request needs no hook from the command line: a world count whose estimate exceeds the real
  device budget is refused at admission (the budget-lowering hook stays a library seam of the unit tests).
- A compile failure from the command line is `frob spark precompile <device> --unit <file>` (N21a-10's input,
  603 in that row) with a dialect unit that passes the lint and fails the device compiler (a call to an
  undeclared function); the planted-kernel hook stays a library seam of the unit tests.

## Acceptance criteria

- [ ] A NaN planted in one world's state at step s freezes that world at its state before s, sets `Faulted` with the stage and step, and changes no other world's digest; the frozen world's state equals its last committed finite state bit for bit.
- [ ] The sentinel detects NaN and both infinities in every checked slab on `batch-cpu`, CUDA and Metal, including under a compiler mode that assumes no NaNs (the test is on bit patterns).
- [ ] A forced contact overflow marks the world `Degraded: contact-capacity` with the needed count; under `refuse` the run ends with `FROB-REF-610` (exit 6) on CUDA and Metal and with `FROB-REF-722` (exit 5) on `batch-cpu`, with identical pointer and needed count; under `reset` the episode is recorded invalid; under `continue-flagged` the run completes and every result of that world is flagged.
- [ ] Exceeding `--max-faulted` yields `FROB-REF-608` listing the faulted worlds with address, stage and step, and with first repair "teleport a faulted world to `batch-cpu`"; for each listed world the last committed snapshot holds its frozen state, so the three things a teleport needs (address, step, frozen state) are on record. The teleport itself (`sim.replay --tier batch-cpu` reproducing the fault or localizing the first diverging stage) is asserted by BD-204, which is built on this bead; it is not a criterion here.
- [ ] Injected device loss, an over-budget request and a planted compile error yield `FROB-REF-601`, `FROB-REF-602` and `FROB-REF-603` respectively, each with exit code 6, the fingerprint digest and its first repair; 603 carries the compiler's text verbatim; 602 allocates nothing.
- [ ] Receipts and the disclosure block report `Degraded` counts by reason, `Faulted` counts and capacity headroom; a summary statistic over a run with excluded worlds states the exclusions (otherwise it is refused by the evidence rule on summaries).
- [ ] A planted silent truncation (a compaction that drops entries without setting the flag) is caught by the capacity audit test (negative control).

## Test plan

### Unit tests
- `status_word_layout`: bit positions; sticky within an episode; cleared at reset.
- `sentinel_bit_patterns`: 0x7FC00000 (quiet NaN), 0x7F800001 (signalling NaN), 0x7F800000 and 0xFF800000 (infinities) detected; 0x7F7FFFFF (largest finite) and subnormals not flagged.
- `faulted_world_frozen`: digests of the faulted world before the fault step and 100 steps later are equal; all other worlds match a run without the injection.
- `overflow_flags_and_counts`: capacity 32, forced count 40: 32 entries written in deterministic order, flag set, counter 40.
- `policy_refuse_reset_continue`: the three behaviours on the same forced overflow.
- `overflow_code_by_tier`: the forced overflow under `refuse` gives `FROB-REF-610` on each device and `FROB-REF-722` on `batch-cpu`, from the same function, with equal `pointer`, capacity and needed count.
- `max_faulted_threshold_608`.
- `device_refusals_601_602_603`: fields, exit code, repairs, no partial publication.
- `fault_hook_spellings`: a plant file with one `nan` plant at world 17, tick 100 and one `overflow` plant (contacts, count 40 against capacity 32) is admitted and both are `applied`; a `nan` plant on padding, or an `overflow` count at or below capacity, is a typed admission error; `--inject-device-loss open` yields `FROB-REF-601` before any world is stepped and `chunk=3` after chunk 2's commit; none of the three exists in a release build's schema.
- `evaluation_policy_raises_608_610`: the shared function called with the evaluation's settings (threshold 0, policy `refuse`) on a run with one planted `Faulted` world gives `FROB-REF-608`, and on a forced overflow gives `FROB-REF-610` on a device tier and `FROB-REF-722` on `batch-cpu`, with the fields `sim.run` gets. The same through `eval.run` is asserted by N24cp3-01 (the M2 form of `eval.run`, which depends on this bead and calls this function); N24c-04 is the M1 form and does not reach the device tiers.
- `counts_in_receipt_and_disclosure`.
- `silent_truncation_detected` (negative control).
- Property test: for random injections into random worlds, exactly the injected worlds change status and no other world's digest changes.

### End-to-end script and logging
`scripts/e2e/spark_gate06_faults_cancel.sh` (bead N21b-25), steps `nan_world`, `overflow_policies`,
`faulted_threshold`, `device_lost`, `over_budget`, `compile_error`: the first four drive `frob sim run` with the
spellings above (`--conformance-plant` with a `nan` or `overflow` plant, `--on-overflow`, `--max-faulted`,
`--inject-device-loss`), `over_budget` drives `frob sim run` with a world count whose estimate exceeds the device
budget (no hook), and `compile_error` drives `frob spark precompile <device> --unit <file>`; each runs under its
own idempotency key (so that no step replays another's stored refusal) and asserts the exit code and refusal code. Logged per the STD-E2E helper: command, exit code, wall
time, the refusal envelope (code, message, pointer, observed, required, repairs), the evidence block, counts of
`Degraded` and `Faulted`, world addresses involved, and on failure the expected against observed code.

### Known answers and negative controls
- KA-542 (every injected fault yields its typed refusal).
- Known answers: the bit-pattern table of the sentinel; an overflow of 40 against capacity 32 reports 40.
- Negative controls: silent truncation; a sentinel written as `x != x` compiled under a no-NaN assumption (a
  conformance variant) must be shown to miss the NaN on at least one compiler mode, which is why the bit test is
  used; a frozen world that keeps integrating (the freeze removed) must change its digest and be caught.
- Determinism lanes: the injected run twice; devices against `batch-cpu` (the same worlds fault at the same step
  when the family holds class D1; otherwise the comparison is by decision: the same worlds are flagged).

## Considerations

- A `Faulted` world is evidence about the simulator or the design, not noise: the count is a first-class output,
  and a scorecard that drops faulted worlds without saying so is refused by the summary rule.
- `Degraded: ill-conditioned` is set by the solve stage when κ̂·u exceeds 0.1 (N21b-38); under `refuse` its code
  is `FROB-REF-248`, a numerics refusal with exit code 3, not a device refusal.
- Freezing costs nothing in shape: the launch graph is unchanged, the frozen world's lanes are masked.
- After device loss the committed slabs are gone with the device; resumption uses the last published snapshot in
  the record, which is why chunks publish at the fence.
- Fault hooks exist only in conformance builds; a release binary has no way to inject a fault (a test asserts the
  symbols are absent).
