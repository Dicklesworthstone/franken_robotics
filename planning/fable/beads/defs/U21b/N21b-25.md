## Background

GATE-SPARK-06 (Known answer, M2, TARGET): cancellation and fault injection: every injected fault yields its typed
refusal, no leaked device memory after 10³ cancel cycles, and the drain report is executor-minted. It is the gate
of the device tier's failure behaviour: an agent driving the studio must be able to tell, from a stable code with
ranked repairs, what went wrong on a device and what to do next, and must be able to cancel work without leaving
device memory behind. "Refuse, never truncate" and "a budget stop publishes nothing partial as a result" are the
standing rules; cancellation tested with request, drain and finalize and no leaked device resources is one of the
eight conditions for calling any capability implemented.

This bead is the end-to-end script that injects each fault from the user's side and checks the envelope, and that
runs the cancel cycles. The mechanisms: chunks and cancellation (N21b-22), world fault states and typed device
refusals (N21b-23), the stall watchdog (N21b-24), the commit fence's bounded retries (N21b-07), leases (N21b-11),
integrated by the seed bead BD-175. Tier: Solid.

## Scope

In: the script, the fault table it drives, its assertions and structured log, and the gate receipt.

Out: mechanisms; the chaos schedules of the conformance battery on devices (BD-223), which reuse these seams at
random; the launch-graph, snapshot and commit-fence clauses of GATE-SPARK-12 (N21b-26).

## Technical approach

**Invocation.** `scripts/e2e/spark_gate06_faults_cancel.sh [--tier gpu-cuda|gpu-metal|batch-cpu] [--cycles N]
[--seed N]`. It uses a conformance build of `frob` (fault seams exist only there). Defaults: every device tier on
the host, 10³ cancel cycles, seed 1. Each command carries an idempotency key from seed and step, so a rerun
returns stored envelopes for completed steps.

**Fault table (each row is one step: inject, run, assert the refusal).**

| Step | Injection | Expected code | Exit | First repair the envelope must offer |
|---|---|---|---|---|
| `device_lost` | The device open fails, and separately the device disappears mid-run | `FROB-REF-601` | 6 | Rerun on another device, or on `batch-cpu` under `mixed-allowed` |
| `over_budget` | A world count whose memory estimate exceeds the device budget | `FROB-REF-602` | 6 | Fewer worlds, a smaller capacity, or this Mac |
| `compile_error` | One kernel source with a planted syntax error | `FROB-REF-603` | 6 | Report; the generic kernel if a specialized one failed. Diagnostics verbatim |
| `launch_fail` | Four consecutive command-buffer or launch failures on one chunk | `FROB-REF-607` | 6 | Resume from the last committed epoch |
| `faulted_threshold` | NaN planted in more worlds than `--max-faulted` allows | `FROB-REF-608` | 6 | Teleport a faulted world to `batch-cpu` |
| `canary` | The folded double-float mutant library with a double-float kernel in the plan | `FROB-REF-609` | 6 | Run without double-float kernels, labelled; file the compiler evidence |
| `overflow_refuse` | Forced contact overflow under `--on-overflow refuse` | `FROB-REF-610` | 6 | A larger capacity; `continue-flagged` |
| `shape_change` | A request to admit a design that does not fit the running bucket | `FROB-REF-611` | 6 | A new bucket |
| `cache_offline` | A corrupted cache entry with `--offline` | `FROB-REF-612` | 6 | `spark precompile` on a build host |
| `lease` | A host read of a slab outside its lease | `FROB-REF-614` | 6 | Read the committed or snapshot slab |
| `stall` | The submit of one chunk sleeps past the watchdog threshold | `FROB-REF-615` | 6 | Restart the device worker |
| `feature` | A kernel declaring 64-bit integers on a device whose fingerprint lacks them | `FROB-REF-616` | 6 | The 32-bit variant, or another backend |

For every row the script asserts: the exit code; `ok: false`; the code; that `refusal.repairs[0]` matches the
table; that the refusal carries the fingerprint digest; that no partial result was published (the job's record
shows no chunk beyond the last committed epoch, and `frob run show` reports the run as refused, not completed);
and that allocated device bytes after the refusal equal the pre-run figure. Codes whose mechanisms belong to other
beads (strict-backend, stale-check, fingerprint and transfer-class refusals: 604, 605, 606, 613, 617, 618) are
exercised by those beads' scripts and listed in this script's summary as `covered elsewhere`, so the gate record
shows where each of the eighteen device codes is tested.

**Positive paths around the faults.** `overflow_policies` runs the same forced overflow under `reset` and
`continue-flagged` and asserts completion with flags; `nan_world` plants one NaN under a tolerant threshold and
asserts the run completes with one `Faulted` world and unchanged digests for every other world; `launch_retry`
injects three consecutive failures and asserts completion with three retries counted.

**Cancel cycles.** `cancel_cycles` repeats 10³ times: start `frob sim run --tier <t> --workload Q --worlds 1024
--json` (exit 8, job handle); after a seeded delay `frob job cancel <id>`; poll `frob job status <id>` until the
drain report is present. Assertions per cycle: the report exists and was minted by the device worker's identity;
outcome `cancelled-drained`; allocated device bytes equal the baseline; stream-ordered pool outstanding bytes are
0. Over all cycles: no leaked device memory (the final free-memory figure of the device equals the initial one),
and the 99th percentile of request-to-drain latency is reported against the 250 ms target. `dropped_handle` kills
the client instead of cancelling and asserts the job is `abandoned` until the supervisor drains it.

**Gate assembly.** `cargo test -p frob-conformance --test g4 -- GATE-SPARK-06` consumes the script's result file
and writes the hash-named receipt; the registry row is entered by a recording session that did not implement the
work. Pass: every row of the fault table yields its code on every device family present; zero leaked bytes after
10³ cycles on each; every drain report executor-minted.

**Logging.** The script sources the STD-E2E helper and writes
`target/e2e-logs/spark_gate06_faults_cancel/<utc-timestamp>.ndjson` with a transcript beside it. Every line: `ts`,
`script`, `bead`, `step`, `event`. `cmd` lines: exact command line, exit code, wall time. `refusal` lines: code,
message, pointer, observed, required, unit, retry class, repairs, fingerprint digest. Result lines copy the
`evidence` block (claim, class, tier, determinism, identities, seed). `metric` lines: allocated bytes before and
after each step (threshold: equal); pool outstanding bytes (threshold 0); request-to-drain milliseconds per cycle
and the 99th percentile (threshold 250 ms, reported); retries; `Faulted` and `Degraded` counts. On failure: the
expected and observed code or the first cycle at which bytes differed, with the job identifier and the paths of
the envelope and the drain report. The final `summary` gives assertions passed and failed, the code coverage map
(tested here, covered elsewhere) and the gate touched. No scene or design contents are logged.

## Acceptance criteria

- [ ] On each device family present and on `batch-cpu` (where the seam applies), every row of the fault table returns its code with exit 6, its first repair, the fingerprint digest, no partial result and no change in allocated device bytes.
- [ ] 10³ cancel cycles on each device family end with zero leaked device bytes and zero outstanding pool bytes, with an executor-minted drain report for every cycle.
- [ ] The dropped-handle case reports `abandoned`, not `cancelled`, until a drain report exists.
- [ ] The summary's coverage map accounts for all eighteen device refusal codes (601 to 618), each either tested here or attributed to the script that tests it.
- [ ] Negative controls demonstrate the script can fail: with a planted leak of 4 KiB per cycle the `cancel_cycles` step fails at the first cycle; with a refusal code swapped in the conformance build the corresponding row fails.
- [ ] The log validates against the STD-E2E schema; the gate receipt names commit, fingerprint digest and seed.

## Test plan

### Unit tests
- `fault_table_matches_registry`: every code in the table exists in `registries/refusals.toml` with the stated first repair; an unknown code is a load-time error.
- `e2e_log_schema_gate06`.
- `conformance_seams_absent_in_release`: the injection flags are rejected by a release build.
- `coverage_map_complete`: the map lists 601 through 618 exactly once each.

### End-to-end script and logging
This bead is the script. A reduced mode (`--cycles 20`, `batch-cpu` only) runs in continuous integration and
records no gate.

### Known answers and negative controls
- KA-542 (cancellation and fault injection on a device: every injected fault yields its typed refusal; no leaked
  device memory after 10³ cancel cycles; the drain report is executor-minted; exact).
- Negative controls: the planted leak; the swapped code; a client-minted drain report (rejected by the schema).
- Determinism lanes: the fault steps twice with the same seed give identical envelopes apart from timing fields;
  runs that complete around a fault (retry, tolerated NaN) give digests equal to the corresponding unfaulted runs.

## Considerations

- A real device loss or hang cannot be produced on demand; the seams simulate the driver's reports. The gate's
  claim is therefore "the software's response to each reported fault is the typed refusal", and the record says
  so. Real incidents, when they occur, are added to the chaos regression set with their logs.
- 10³ cancel cycles at about one second each fit the default compute envelope (one device, one hour).
- Metal's fault seam exists only in builds with debug assertions (FACT), so the Metal rows run a debug-assertions
  build of the annex.
- If a device family is absent, its rows are recorded `not run` with the reason; the gate is then recorded for the
  families present and stays open for the other.
