## Background

The hardware fingerprint record `frob.fingerprint/1` ends in a digest, BLAKE3 over the canonical record. The plan
gives that digest four jobs and one refusal:

> The digest keys the kernel cache, the currency of `spark check`, the calibration of `sim.estimate` and the
> disclosure block of performance claims. A receipt without a fingerprint digest, or with one that no longer
> matches the machine, is refused as evidence (`FROB-REF-606`: "fingerprint missing, or changed since admission";
> first repair: `spark fingerprint`).

The risk it answers is RISK-48: a driver, system or binding update changes kernel results. Leading indicator: a
fingerprint change, or a failed `spark.check`. Mitigation: the fingerprint gate, `--require-current-check`, the
kernel cache keyed by fingerprint, pinned bindings. Invariant INV-SPARK-02 adds that every device result carries a
fingerprint digest (with the twelve accelerator evidence fields and a placement receipt).

**A point the record definition leaves open, and its resolution (DESIGN).** The record holds both discrete facts
(driver, compiler, arithmetic features) and measured rates (bandwidth, launch cost) that agree only within 5%
between runs. A digest over the whole record therefore changes every time the fingerprint is re-measured, although
nothing about the machine changed. If caches and check currency were keyed on it, every re-measurement would
discard them. This bead therefore defines two values:

- `digest`: BLAKE3 over the whole canonical record. It identifies one measurement. Receipts and disclosure blocks
  cite it.
- `identity`: BLAKE3 over the canonical encoding of the **identity subset**: machine (host, operating-system
  build, CPU model, core counts, memory); per device: family, name, stable identifier, architecture, driver,
  runtime, compiler and language version, total memory, working-set limit, largest single buffer, execution width,
  GPU-core or multiprocessor count, and the whole `arithmetic` block. Rates, free memory, thermal state and
  timestamps are excluded.

"Matches the machine" means: the identity recomputed from the live machine equals the identity of the stored
record. Rejected alternatives: keying consumers on the full digest (loses every cache on a re-measure); ignoring
rates entirely in the digest (a receipt could then not say which measured calibration it used).

## Scope

In: the identity subset and its digest; the cheap live re-probe; the status function (`current`, `stale`,
`missing`); the change event and what it invalidates; admission-time and emission-time checks; `FROB-REF-606` with
its fields and repairs; the rule for citing an older receipt. Out: measuring the record (BD-029, N21c-01,
N21c-02); each consumer's own storage (cache, check ledger, estimator), which call the functions defined here;
the full device-result schema check (N21c-28).

## Technical approach

Module `frob-kernels::fingerprint::currency` (core; no GPU crate). The identity subset is the list above; its
encoding is one function, `identity_of(record)`, written by BD-029 (on which this bead builds), which computes and
stores `identity` at write time beside `digest` and recomputes both when it merges a one-device run into the host
record under E0. `live_identity` below calls the same function, so the stored and the live identity are computed by
one piece of code.

1. **Types (DESIGN).** `FingerprintRef { digest: Hash, identity: Hash, device: DeviceId, measured_at }`.
   `Status = Current | Stale { field, stored, live } | Missing`.
2. **Live identity.** `live_identity(device)` reads only what is cheap and launches no kernel: operating-system
   build, driver, runtime and compiler versions, device stable identifier and architecture, memory limits,
   execution width. The `arithmetic` block is taken from the stored record when all of those match, because it is
   a function of them; the start-up canaries still run at every device start (a failed canary is `FROB-REF-609`).
3. **Status.** `status(device)`: `Missing` if no stored record for this host and device; otherwise compare field
   by field in a fixed order and return `Stale` with the first differing field, or `Current`.
4. **Admission.** Every verb that will produce a device result resolves `FingerprintRef` at admission. `Missing`
   or `Stale` refuses with `FROB-REF-606` before any kernel is launched. **Bootstrap exemption (DESIGN):** the two
   measuring verbs, `spark.fingerprint` and `spark.probe`, cannot require what they produce (the record's
   `arithmetic` block cites the probe report). Their reports cite the live `identity` instead of a fingerprint
   digest and are admitted without a stored fingerprint; nothing else is exempt, and a probe report is device
   evidence only once a fingerprint with the same identity cites its digest.
5. **Emission.** Before a device receipt is returned, and at every chunk commit of a long job, `status` is read
   again. If the identity changed since admission (a driver was reloaded, an external GPU reset changed the
   runtime) the job stops at the last committed chunk and the verb refuses with `FROB-REF-606`: results after the
   change are not evidence. Committed chunks before the change keep the admitted digest.
6. **Change event.** On the first observation of a new identity for a device, write `fingerprint.changed
   { device, field, stored, live, old_identity }` to the ledger and call the consumers:
   - kernel cache: nothing to delete; its key (BLAKE3 over expanded dialect text, compile options, prelude
     version, compiler identity, device architecture, driver version) already differs, so an old binary is never
     loaded;
   - `spark check`: every currency row for that device family, driver and compiler is marked stale, so a device
     result is not citable until the check is re-run (`FROB-REF-605` under `--require-current-check`);
   - `sim.estimate`: a new calibration stratum starts; intervals are `uncalibrated` until it has 19 finished jobs;
   - disclosure blocks: new ones cite the new digest once a new fingerprint is measured.
7. **Citing an older receipt.** A stored receipt remains a true record of what ran. It is `historic` when its
   `identity` differs from the device's current identity. A `historic` receipt may be shown and exported with its
   label; it may not be reused as a memoized episode (reuse needs the same backend and fingerprint), may not be an
   arm of a new paired ratio with an arm measured now, and may not record a gate PASS for the present machine
   state. Each of those uses refuses with `FROB-REF-606` and `pointer: fingerprint`.
8. **The refusal.** Envelope `refusal = { code: "FROB-REF-606", message, pointer: "device/<id>/<field>", observed:
   live value, required: stored value, unit: "", affected_claims: ["Performance", "Parity", "Fidelity"], retry:
   "after-change", repairs: [1. `frob spark fingerprint --device <id> --key <k>`, 2. `frob spark check --backend
   <b> --key <k>` with `<b>` the device's backend (`gpu-cuda:<n>` or `gpu-metal`), 3. rerun on `batch-cpu`] }`;
   exit code 6 (backend or device). Like every `6xx` refusal it carries the last
   known fingerprint digest.
9. **Negative-control seam.** In builds with debug assertions only, `FROB_INJECT_IDENTITY=<field>=<value>` overlays
   one live identity field, so that a change can be planted without touching a driver.

Determinism: exact. Ledger: the change event; no private data.

## Acceptance criteria

- [ ] Re-measuring a fingerprint on an unchanged machine yields a new `digest` and the same `identity`; cache entries and check currency stay valid.
- [ ] Changing the driver, compiler, operating-system build or any `arithmetic` field yields a different `identity`, a `Stale` status naming the field, and one `fingerprint.changed` event.
- [ ] A device verb with no stored fingerprint refuses with `FROB-REF-606`, exit 6, before any kernel launches; the first repair is `frob spark fingerprint`.
- [ ] An identity change planted between admission and emission stops the job at the last committed chunk and refuses with `FROB-REF-606`; no receipt with the old digest is emitted for later chunks.
- [ ] After a change, `spark check` currency for that device is stale and the estimator starts a new stratum.
- [ ] A `historic` receipt is refused as a memo, as an arm of a new paired ratio and as a gate record, and is still readable with its label.
- [ ] The identity subset and the two-digest rule are written in the `CONTRACT.md` of `frob-kernels` (invariants and refusals sections).

## Test plan

### Unit tests

`cargo test -p frob-kernels fingerprint::currency`:
- `identity_excludes_rates`: two `synthetic` records differing only in a bandwidth figure have different `digest` and equal `identity`.
- `identity_includes_driver_compiler_os_arith`: four records, each differing in one of those fields, give four distinct identities.
- `status_orders_fields`: a record differing in both driver and compiler reports the earlier field of the fixed order.
- `missing_refuses_606_before_launch`: the launch counter is zero.
- `change_between_admission_and_emission` (with the debug seam): the job stops; the refusal's `pointer` is `device/cuda:0/driver`; `observed` and `required` are the two versions.
- `historic_receipt_uses`: memo reuse, pairing and gate recording each refuse; `artifact.read` succeeds with `label: historic`.
- `change_event_written_once`: two status reads after one change write one event.
- Property test (INV-SPARK-02, fingerprint part): for random device receipts, serialization fails unless a `FingerprintRef` is present.

### End-to-end script and logging

Steps of `scripts/e2e/spark_fingerprint.sh` (N21c-06): run a small device kernel job with a current fingerprint
(expect a receipt citing the digest); delete the stored record and rerun (expect exit 6, `FROB-REF-606`); restore
it, plant a driver-version change with the debug seam and rerun (expect exit 6, pointer naming `driver`); log each
refusal as a `refusal` event with code, pointer, observed, required and the repairs offered.

### Known answers and negative controls

Negative controls: a receipt writer with the admission check removed (the missing-fingerprint step must fail the
script); a status function that compares full digests (the re-measure test must then report a false `Stale`, which
the unit test catches); a consumer that ignores the change event (the stale-check assertion must fail). Lanes:
twice on one machine; debug and release (the seam exists only in debug).

## Considerations

- The identity subset is a contract: adding a field later changes every identity once and stales every check; it
  is a versioned list in the record schema.
- A machine state that flaps (a driver reloaded to the same version) produces no change event, by design.
- The two-digest resolution is this bead's reading of a record definition that names one digest; if the record's
  owner keeps a single digest, the identity subset must then be the whole digested content and rates must move to a
  side record.
