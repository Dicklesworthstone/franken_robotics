## Background

The two machines exchange very little, by rule (ADR-SPARK-07). **What crosses:** seeds and scene recipes (bytes to
kilobytes), design and module differences (kilobytes), model-variant tables (kilobytes to megabytes), policy
weights (megabytes), receipts, digests and telemetry summaries. **What never crosses:** compiled scene fields,
world state, rollout buffers. A scene is regenerated on the receiving machine from its seed with the pinned
generator and must arrive at the same `SceneId`; a failed world is replayed from its address, design, weights and
scene recipe.

Reason: regeneration from a seed is exact and cheaper than moving fields. The numbers: a 2 cm home scene is 40 to
75 MB and a 2 cm warehouse 1.4 to 3.5 GB as narrow bands; 8,192 quadruped worlds are about 0.28 GB of state; one
warehouse field alone exceeds the whole hourly allowance below, while its recipe is kilobytes. A variant table is
about 192 bytes per link, so a 64-link variant is about 12 kB and 256 variants about 3 MB.

Three statements bind this bead:

- TARGET: at most **1 GB crosses per campaign-hour**, metered per transfer class. It is one clause of GATE-SPARK-13
  and one falsifier of BET-35 ("more than 1 GB per campaign-hour crosses between the machines").
- An attempt to ship a field or a state slab is **`FROB-REF-618`** ("a transfer class that may not cross
  machines"; first repair: send the seed or recipe).
- **INV-SPARK-10:** only seeds, recipes, differences, variant tables, weights, receipts and summaries cross
  machines; verified by the transfer-class meter.

The rule is Solid and survives the fleet scheduler's kill gate ("the seeds-only rule stays"), so it cannot live
inside the scheduler.

## Scope

In: the transfer-class enumeration and its mapping from artifact kinds; the one egress and ingress path (a
cross-machine bundle); the meter and its ledger rows; the refusal; the property test of INV-SPARK-10. Out:
regeneration and replay on the receiving side (N21c-09); the peer link transport and the scheduler; the gate
measurement (BD-370).

## Technical approach

**Classes (DESIGN, `frob-kernels::fleet::transfer`).**

```rust
// DESIGN: intent, not signatures.
enum TransferClass {
    Seed, SceneRecipe, DesignDiff, ModuleDiff, VariantTable, PolicyWeights, Receipt, Digest, TelemetrySummary, // may cross
    SceneField, WorldState, RolloutBuffer,                                                                     // never cross
}
fn class_of(kind: ArtifactKind) -> Option<TransferClass>;   // None for a kind not in the registry
```

The class is **derived from the artifact kind recorded in the ledger**, never declared by the caller, so an item
cannot be relabelled into an allowed class. The mapping is a table `registries/transfer_classes.toml` (kind →
class). Fail closed: a kind with no row is treated as forbidden. A whole design or module is sent as its
content-addressed term (kilobytes) under `DesignDiff` or `ModuleDiff`; a job specification and a result summary are
`Receipt`, and so is a certificate bundle (kind `certificate`; DESIGN: a certificate is a checkable record of a
result, as a receipt is, and the Mac's derivation and proof work must be able to send one back; VERBS-artifact's
import example exports one). A `TelemetrySummary` item above 16 MiB (16,777,216 bytes, DESIGN default) is not a
summary but a mislabelled trace and is treated as an unregistered kind: `FROB-REF-618` with `observed` its bytes.

**The bundle (DESIGN, `frob-chronicle`).** Everything that leaves a machine through the product is a
`frob.xfer/1` bundle: a manifest `{ campaign, from_host, to_host, items: [{ id, kind, class, bytes, blake3 }],
total_bytes }` followed by the items. `XferWriter::add(artifact)` computes `class_of`; a forbidden or unknown class
returns the refusal below and the bundle is not written (refuse, never truncate). `XferReader` on the other side
verifies every digest, re-derives every class from the kind and refuses a bundle containing a forbidden class even
if the sender did not. The peer link and `artifact.export --to-host` both use this writer; there is no second
path.

**The two commands (DESIGN; the plan gives the rule and no command, and a rule that must also hold when the
machines run standalone, which is the default, needs a way for a person or an agent to move the allowed things by
hand).**
- *Egress.* This bead adds the option `--to-host <mac|trj>` (with an optional `--campaign <id>`) to
  `artifact.export` (the M1 verb of BD-097, kind `run`): `frob artifact export <digest> [<digest> …] --to-host
  <host> --out <path> --key <k> --json` writes one `frob.xfer/1` bundle under the session's export root in place
  of single files, through `XferWriter`, and its envelope carries the `transfer` block. An `--out` ending in `/`
  names a directory, and the bundle is written there as `<hex>.frobxfer`, `<hex>` being the bundle's digest (the
  row's `<hex>.<kind extension>` rule, with `frobxfer` the extension of `frob.xfer/1`; DESIGN). `--to-host` names the
  destination recorded in the manifest and metered against; it opens no connection (at M2 the file is carried by
  whatever means the operator has; from M4 the peer link carries the same bundle). A forbidden or unknown class
  refuses the whole call with `FROB-REF-618` and writes no file.
- *Ingress.* A bundle is admitted to the local store only through `XferReader`. The peer link calls it in
  process (from M4); for a person or an agent this bead implements the verb `artifact.import`, registered by
  VERBS-artifact (kind `run`, owner `frob-chronicle`, first milestone M2, capability `artifact:run`, `bundle` a
  file parameter, output `frob.artifact.import.out/1`): `frob artifact import <bundle path> --key <k> --json`
  verifies every digest, re-derives every class, admits the items and returns the identities admitted with the
  `transfer` block; `FROB-REF-618` for a bundle holding a forbidden class or an unregistered kind (nothing
  admitted, exit 6); the path refusals every file parameter carries (734, 828). An item whose bytes do not hash
  to its manifest digest is an integrity fault: the `9xx` refusal with the slug `xfer-item-digest-mismatch`
  (DESIGN; exit 9, `retry: never`, `pointer` the item id, `observed` and `required` the two digests, nothing
  admitted), filed as a ledger row through N21-REF and numbered by the ledger (N35-33's allocation), never a
  `6xx` code. The ingress steps of this bead's script run through the verb from M2. The integration entry `cargo
  test -p frob-chronicle --test xfer_ingress -- --nocapture --result <file>`, which opens a second state root and
  calls the same reader in process, stays as the reader's own test entry and is not the user's path.

**The meter.** On every successful send and receive, one ledger row `xfer { ts, campaign, direction, class, items,
bytes }`. Derived figures: bytes per class; total per campaign; **bytes per campaign-hour** = total bytes crossed
in both directions ÷ campaign wall-clock hours, charged at the actual duration with a floor of 0.1 h (DESIGN:
the floor keeps a campaign of a few seconds from turning kilobytes into a large rate; a floor of one hour would
let a 15-minute campaign send four times the target and pass, and the fleet gate's runs are about 13 to 16
minutes, above the floor, so the gate reads their true rate). The
meter never blocks: exceeding 1 GB per campaign-hour sets `over_target: true` on the campaign's transfer summary
and fails the gate clause; it is not a refusal, because the allowance is a measured target and not a quota.

**The refusal.** `FROB-REF-618`, exit code 6, `retry: after-change`, `pointer`: the item id; `observed`: its kind
and class; `required`: the allowed classes; ranked repairs:
1. send the seed or recipe: for a scene, its recipe (generator identifier, pinned generator version, seed and
   parameters) so that the receiver regenerates the same `SceneId`;
2. for world state or a rollout: send the world address, the design, the policy weights and the scene recipe, and
   replay there (`sim.replay`);
3. keep the work on the machine that holds the data (the role table).
Like every `6xx` refusal it carries the fingerprint digest of the sending host.

**Surface.** Every export and import envelope carries a `transfer` block (class, items, bytes, the campaign's
running total, bytes per campaign-hour, `over_target`), which is how the meter is read at M2. From M4 the per-class
totals and the over-target flag are also read by `fleet.status` and printed in the campaign report. Evidence class
of the meter: `Tested`, exact integers.

## Acceptance criteria

- [ ] Each of the nine allowed classes round-trips through a bundle between two state roots with digests verified; each of the three forbidden classes, and an unregistered kind, is refused with `FROB-REF-618`, exit 6, and no bundle file is left behind.
- [ ] `frob artifact export <digests> --to-host <host> --out <path> --key <k> --json` writes one bundle and reports the `transfer` block; without `--key` it is `FROB-REF-805`; the same key repeated returns the stored receipt and writes nothing; an `--out` ending in `/` writes `<hex>.frobxfer` there. `frob artifact import <bundle> --key <k> --json` admits a bundle through `XferReader` and reports the same block; an item corrupted by one byte is refused as `xfer-item-digest-mismatch`, exit 9, nothing admitted.
- [ ] A certificate bundle round-trips as class `Receipt`; a `TelemetrySummary` item of 16,777,217 bytes is refused with `FROB-REF-618` and one of 16,777,216 bytes is sent.
- [ ] A scene-field artifact requested under the class name `scene-recipe` is still refused: the class comes from the kind.
- [ ] The reader refuses a hand-built bundle that contains a state slab.
- [ ] The meter's per-class byte totals equal the sum of item sizes exactly; bytes per campaign-hour is computed as specified.
- [ ] A campaign that sends 1.2 GB in one hour is marked `over_target` and is not refused.
- [ ] INV-SPARK-10 has a property test; the classes, the bundle and the refusal are in the `CONTRACT.md` files of `frob-kernels` and `frob-chronicle`.

## Test plan

### Unit tests

`cargo test -p frob-kernels fleet::transfer` and `-p frob-chronicle xfer`:
- `class_of_every_registered_kind`: every artifact kind in the format registry has a row; a planted kind without a row is `None`.
- `writer_refuses_forbidden`: `SceneField`, `WorldState`, `RolloutBuffer` → `FROB-REF-618`; the refusal lists repair 1 first.
- `writer_cannot_be_relabelled`.
- `reader_reverifies_classes_and_digests`: a one-byte corruption of an item is rejected with `xfer-item-digest-mismatch` (exit 9) and nothing is admitted; a forbidden class is rejected with `FROB-REF-618`.
- `summary_size_bound`: a `TelemetrySummary` of 16,777,216 bytes is admitted; 16,777,217 bytes → `FROB-REF-618`, `observed` the bytes; a `certificate` kind maps to `Receipt`.
- `meter_totals_exact`: items of 12,288 bytes (a 64-link variant table), 3,145,728 bytes and 1,048,576 bytes give 4,206,592 bytes in three classes.
- `campaign_hour_rate`: 1,200,000,000 bytes over 3,600 s → 1.2 GB per campaign-hour, `over_target`; 900,000,000 bytes over 1,800 s → 1.8, `over_target`; 250,000,000 bytes over 900 s → 1.0, not over (the threshold is inclusive); 50,000,000 bytes over 60 s is charged as 0.1 h → 0.5, not over.
- Property test `bundle_classes_subset_of_allowed` (INV-SPARK-10; the test name the invariant register N21c-27 binds): for random sets of artifacts, the set of classes in any written bundle is a subset of the nine allowed classes.

### End-to-end script and logging

`scripts/e2e/fleet_transfer.sh`: with two state roots on one host standing for the two machines (the run's own
`FROB_STATE` for the sender and `work/peer/state/`, passed as `FROB_STATE` to the receiver's commands; and, where
both machines are reachable, the real pair): export a seed, a recipe, a design difference, a variant table,
weights, a receipt and a certificate bundle with `frob artifact export <digest> --to-host <host> --out <scratch>/
--key xfer-<class>-<run-id> --json` (a `run` verb: one key per call, `FROB-REF-805` without one, every envelope
showing `idempotent_replay: false`; each bundle lands as `<scratch>/<hex>.frobxfer`), admit each bundle on the other
state root with `frob artifact import <bundle> --key xfer-in-<class>-<run-id> --json`, and read the `transfer` block
of each envelope for the meter; then attempt to export a compiled scene field, a snapshot slab, a rollout buffer and
a 17 MiB "summary" (each must exit 6 with `FROB-REF-618`), offer the receiver a hand-built bundle holding a state
slab (refused by the reader with the same code, nothing admitted), and offer it a bundle with one item corrupted by
one byte (exit 9, `xfer-item-digest-mismatch`, nothing admitted). Logs per the end-to-end standard: command lines, exit codes, per-class bytes with unit, the
target of 1 GB per campaign-hour, refusal events with code, pointer and repairs, digests of every item compared on
both sides, and a `summary` line.

### Known answers and negative controls

Known sizes: 192 bytes per link; 64 links ≈ 12 kB; 256 variants ≈ 3 MB. Negative controls: a writer with the class
check removed (the forbidden-export step must then succeed and the script must fail); a meter that counts only one
direction (the totals test must fail); a mapping that marks `scene.field` as `SceneRecipe` (the registry lint must
fail: a forbidden kind family may not map to an allowed class). Lanes: twice on one machine with identical meter
rows.

## Considerations

- The product cannot stop a person copying files outside it; ingress therefore accepts only bundles and re-derives
  classes, and scenes are admitted only by regeneration.
- Private places: a recipe carries its private mark and licence joins; purge on one machine must be mirrored on the
  other (the safety chapter's rule), and logs never contain private-scene data.
- Telemetry summaries must stay summaries: a "summary" above a size bound (DESIGN default 16 MiB per item) is
  rejected as a mislabelled trace (`FROB-REF-618`, the trigger requested of N21-REF for the code's row).
