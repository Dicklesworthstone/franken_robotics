## Background

Because compiled scene fields, world state and rollout buffers never cross between the two machines, everything a
machine needs from the other must be reconstructible from small records. Two reconstructions are named by the plan:

1. **A scene is regenerated** on the receiving machine from its seed with the pinned generator, and must arrive at
   the same `SceneId` (the content identity of a compiled scene). The Habitat gate already requires that one seed
   gives one `SceneId` on Linux and macOS.
2. **A world that failed on `trj` is replayed on the Mac** from its address, its design, its policy weights and its
   scene recipe; nothing else is needed. The replay is *exact* or a *tolerance replay* according to the determinism
   class attained between the two device families: class D1 (the same bits on `batch-cpu` in `f32`, CUDA and Metal)
   licenses a claim of bit equality; without D1 the replay is labelled a tolerance replay and compared by the
   decision-level equivalence test. Bit equality across families is a HYPOTHESIS measured by the IEEE probe and
   the CPU-versus-device check, with kill gate KILL-D1; nothing here assumes it.

A third rule rides along: a comparison whose arms ran on different device families is **unpaired** unless class D1
holds; asking for it as paired is refused (`FROB-REF-561`).

This is what makes the division of labour workable: the cards train and fail fast; the Mac, with 36 cores and the
referee, explains. The known answer is "scene regenerated on the other machine from its seed: same `SceneId`", and
its negative control is "a generator with one changed constant".

## Scope

In: the recipe record and the regenerate-and-compare step; the replay closure (the minimal set of artifacts that
makes a world replayable elsewhere) and its export through the cross-machine bundle; the labelling of the replay;
the end-to-end script across the two machines. Out: the generators, the scene compiler, replay and teleport
themselves (their own beads); transfer classes and the meter (N21c-08).

## Technical approach

**Scene recipe (DESIGN; transfer class `SceneRecipe`).** `{ generator: GeneratorId, generator_pin: digest of the
generator's code and tables, seed, parameters (canonical), expected: SceneId }`. Bytes to kilobytes.

**Regenerate.** `frob scene gen --recipe <file> --json` on the receiver:
1. Refuse if the local generator's pin differs from `generator_pin` (the generator is "pinned"; a different
   generator cannot be expected to reproduce an identity).
2. Run the generator and the scene compiler; compute the `SceneId`.
3. Compare with `expected`. Equal: admit the scene under that identity. Different: refuse, admit nothing, and
   report both identities and the first brick whose digest differs. The plan names no refusal code for this
   condition; this bead raises `FROB-REF-303` ("a reference does not resolve") with `pointer: scene_id` and files
   the gap for the refusal registry.

**Replay closure (DESIGN, `frob-chronicle`).** `replay_closure(run, world_address) -> [ArtifactId]` returns exactly:
the episode header (world address, stream keys, task and randomization record, profile, step-plan identity,
decimation), the design term (or its difference from a design the receiver already holds), the policy weights
(digest and bytes), the scene recipe, and the source run's receipts and per-step digest chain for that world
(class `Digest`) to compare against. It contains no state: the committed initial state of a world is a function of
its address and the records above. `frob artifact export --replay-closure <run>:<address> --to-host <h>` writes the
bundle; forbidden classes cannot enter it.

**Replay on the receiver.** `frob sim replay --run <id> --world <address> --tier <t> --json` resolves every input
from the imported closure. It then labels the result:
- same device family, class D2 with a current batch-invariance record: exact; the digest chain must match;
- different family (or `batch-cpu` against a device) with D1 recorded for both: exact, claimed as bit equality;
- otherwise: `tolerance replay`, profile `cross-backend`; the comparison is the decision-level test and the first
  divergence (step, stage, quantity) is recorded, not hidden.
The label is part of the envelope's evidence block; a tolerance replay never carries a bit-equality claim.

**Closure test.** The receiver is run with an empty state root plus the bundle and with the network to the sender
cut: replay must succeed or name the missing artifact. This is what "nothing else is needed" means as a test.

## Acceptance criteria

- [ ] For each M2 terrain generator and 100 seeds, a recipe exported on one machine regenerates on the other to the same `SceneId` (TARGET: 100 of 100); interior archetypes join when their generators land.
- [ ] A generator build with one changed constant yields a different `SceneId` and the scene is refused, with both identities reported.
- [ ] A recipe whose `generator_pin` differs from the local generator is refused before generation.
- [ ] A world exported from `trj` with its replay closure replays on the Mac from an empty state root; the label is `exact` only where the recorded class licenses it, otherwise `tolerance replay` with a recorded first divergence or a passed decision-level test.
- [ ] Removing the weights (or any one item) from the closure makes replay refuse and name that item.
- [ ] The closure bundle contains no forbidden transfer class and its size is logged per class.
- [ ] A paired comparison requested across the two families without class D1 is refused with `FROB-REF-561`.

## Test plan

### Unit tests

`cargo test -p frob-chronicle replay_closure` and `-p frob-scene recipe`:
- `recipe_roundtrip_canonical`: a recipe serializes to the same bytes on both platforms.
- `regenerate_same_id` (`synthetic` small terrain): the identity equals the expected one.
- `regenerate_pin_mismatch_refused`, `regenerate_id_mismatch_refused_with_first_brick`.
- `closure_is_minimal_and_sufficient`: removing any item breaks replay; adding none is needed.
- `closure_contains_no_state`: every item's transfer class is one of the nine allowed.
- `replay_label_table`: (same family, D2) → exact; (cross family, D1) → exact; (cross family, D3) → tolerance; (any, D4) → refused.

### End-to-end script and logging

`scripts/e2e/fleet_regen_replay.sh --from trj --to mac`: (1) `frob scene gen --seed S --json` on the source and
export of the recipe; (2) import and `frob scene gen --recipe … --json` on the receiver; assert identity equality;
(3) the same with the mutant generator build (`--features mutant-generator-constant`), assert refusal; (4) on the
source run a short device batch with a planted failing world (a `synthetic` task that makes one address fall), export
its replay closure; (5) on the receiver `frob sim replay … --tier batch-cpu --json` and `--tier gpu-metal`; assert
the label rule and, where exact, digest-chain equality. Logged per the end-to-end standard: command lines, exit
codes, both hosts' fingerprint digests, `SceneId`s, per-class bundle bytes, the attained class, the first
differing step and quantity if any, and a `summary` line. Where only one machine is available the script runs
between two state roots and marks the run `single-host` (it then proves closure, not cross-platform identity).

### Known answers and negative controls

KA-539 (same `SceneId`; control: a generator with one changed constant). Negative controls: the mutant generator;
a closure with the weights withheld; a replay labelled `exact` across families with no D1 record (the label check
must refuse it). Metamorphic: regenerating twice gives the same identity; replaying the same closure twice gives
the same digest chain on one tier. Lanes: both platforms; debug and release.

## Considerations

- If KILL-D1 fires for a family, every cross-family replay is a tolerance replay and the wording of replay claims
  changes with it; this bead's label rule already covers that branch.
- A generator that uses platform elementary functions or hash-map iteration order will fail the identity test; the
  fix is in the generator, never a tolerance on `SceneId`.
- Private places: a recipe may itself be private; it carries its mark and is purged with the scene.
