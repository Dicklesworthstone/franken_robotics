## Background

Because compiled scene fields, world state and rollout buffers never cross between the two machines, everything a
machine needs from the other must be reconstructible from small records. Two reconstructions are named by the plan:

1. **A scene is regenerated** on the receiving machine from its seed with the pinned generator, and must arrive at
   the same `SceneId` (the content identity of a compiled scene). The Habitat gate already requires that one seed
   gives one `SceneId` on Linux and macOS.
2. **A world that failed on `trj` is replayed on the Mac** from its address, its design, its policy weights and its
   scene recipe; nothing else is needed. The replay is *exact* or a *tolerance replay* according to the determinism
   class attained between the two device families: class D1 (the same bits on `batch-cpu` in `f32`, CUDA and Metal)
   licenses a claim of bit equality; without D1 the replay is labelled a tolerance replay and compared by the
   decision-level equivalence test. Bit equality across families is a HYPOTHESIS measured by the IEEE probe and
   the CPU-versus-device check, with kill gate KILL-D1; nothing here assumes it.

A third rule rides along: a comparison whose arms ran on different device families is **unpaired** unless class D1
holds; asking for it as paired is refused (`FROB-REF-561`).

This is what makes the division of labour workable: the cards train and fail fast; the Mac, with 36 cores and the
referee, explains. The known answer is "scene regenerated on the other machine from its seed: same `SceneId`", and
its negative control is "a generator with one changed constant".

## Scope

In: the recipe record and the regenerate-and-compare step; the replay closure (the minimal set of artifacts that
makes a world replayable elsewhere) and its export through the cross-machine bundle; the labelling of the replay;
the end-to-end script across the two machines. Out: the generators, the scene compiler, replay and teleport
themselves (their own beads); transfer classes and the meter (N21c-08).

## Technical approach

**Scene recipe (DESIGN; record `frob.scene.recipe/1`, transfer class `SceneRecipe`).** One record for every path
that carries a scene between machines, the same that the world bank's cross-machine rule reads (N19c-23, M3, which
adds the bank's admission path to this M2 definition): `{ family: GeneratorId, archetype_variant, parameters
(canonical), seed, generator_pin: digest of the generator's code and tables, compiler_version,
compile_settings_digest, expected: SceneId }`, canonical JSON, bytes to kilobytes. For a derived variant: the
base's recipe plus the ordered typed edits. The sender attaches its compiler stage receipts as digests only.

**Regenerate.** This bead adds the option `--recipe <file>` to `scene.gen` (BD-165's verb, kind `run`; with it
the family, parameters and seed are read from the recipe and may not also be given, `FROB-REF-802`; the option is
registered on the verb's row in VERBS-scene). `frob scene gen --recipe <file> --key <k> --json` on the receiver:
1. Refuse before generation if the local generator's pin differs from `generator_pin`, or the local compiler
   version differs from `compiler_version` (the generator is "pinned"; a different generator cannot be expected
   to reproduce an identity): `FROB-REF-303` ("a reference does not resolve", DESIGN reading: the pinned generator
   the recipe names does not resolve on this machine), exit 3, `pointer: generator_pin` (or `compiler_version`),
   both values in `observed` and `required`, repair 1: install the pinned generator build; repair 2: run the job
   on the machine that holds the pin.
2. Run the generator and the scene compiler; compute the `SceneId`.
3. Compare with `expected`. Equal: admit the scene under that identity. Different: refuse and admit nothing, with
   the integrity refusal `scene-pack-identity-mismatch` (constant `IDENTITY_MISMATCH`; N19c-42's row, a `9xx` row
   numbered by the ledger N35x-02; exit 9, `retry: never`; the earlier `FROB-REF-323` is withdrawn, since a `3xx`
   code cannot exit 9): the record names the recipe, both identities, both
   machines' compiler versions and fingerprint digests, the first compiler stage whose receipt digest differs
   (from the sender's stage digests) and the first brick whose digest differs. An identity mismatch is a
   determinism defect to fix, not to work around; meanwhile the job runs on the machine that compiled the scene.

**The mutant generator (DESIGN; the plant of KA-539's control).** This bead defines the test feature
`mutant-generator-constant` in `frob-scene`: under `cfg(feature = "mutant-generator-constant")` one numeric
constant of the `terrain/stairs` generator is changed in its last digit. It is a per-control mutation feature,
never a member of the umbrella `gauntlet-mutations` and never enabled in a shipped profile (the no-ship lint of
N21c-30). `generator_pin` is the digest of the generator's source files and tables, which a `cfg` branch does not
change, so the mutant build carries the clean build's pin, passes step 1 and is caught by the identity comparison
of step 3 (exit 9), never by `FROB-REF-303`. N21c-31 registers the control `spark.generator-constant` on this
feature; this bead's script runs it first, so the feature cannot wait for the control's bead.

**Replay closure (DESIGN, `frob-chronicle`).** `replay_closure(run, world_address) -> [ArtifactId]` returns exactly:
the episode header (world address, stream keys, task and randomization record, profile, step-plan identity,
decimation), the design term (or its difference from a design the receiver already holds), the policy weights
(digest and bytes), the scene recipe, and the source run's receipts and per-step digest chain for that world
(class `Digest`) to compare against. It contains no state: the committed initial state of a world is a function of
its address and the records above. `frob artifact export --replay-closure <run>:<address> --to-host <h> --out
<path> --key <k> --json` writes the bundle (`--replay-closure` is the option this bead adds to `artifact.export`:
it names the closure's items in place of a list of digests, and is valid only with N21c-08's `--to-host`; given
without `--to-host`, or together with digests, it is a schema failure, `FROB-REF-802`, exit 3; both options are
registered on the verb's row in VERBS-artifact from M2); forbidden classes cannot enter it. The receiver admits the
bundle through N21c-08's ingress, `frob artifact import <bundle> --key <k> --json`.

**Replay on the receiver.** `frob sim replay --run <id> --world <address> --tier <t> --key <k> --json` (a `run`
verb: the key is required, `FROB-REF-805` without it) resolves every input from the imported closure. It then labels the result:
- same device family, class D2 with a current batch-invariance record: exact; the digest chain must match;
- different family (or `batch-cpu` against a device) with D1 recorded for both: exact, claimed as bit equality;
- otherwise: `tolerance-replay` (the label VERBS-sim's `sim.replay` row and N35-07 print), profile `cross-backend`; the comparison is the decision-level test and the first
  divergence (step, stage, quantity) is recorded, not hidden.
The label is part of the envelope's evidence block; a tolerance replay never carries a bit-equality claim.

**Closure test.** The receiver is run with an empty state root plus the bundle and with the network to the sender
cut: replay must succeed or name the missing artifact. This is what "nothing else is needed" means as a test.

## Acceptance criteria

- [ ] For each M2 terrain generator and 100 seeds, a recipe exported on one machine regenerates on the other to the same `SceneId` (TARGET: 100 of 100); interior archetypes join when their generators land.
- [ ] A generator build with one changed constant yields a different `SceneId` and the scene is refused with `scene-pack-identity-mismatch` (exit 9), reporting both identities, the first differing compiler stage and the first differing brick.
- [ ] `--replay-closure` without `--to-host`, or together with a digest list, is refused with `FROB-REF-802`, exit 3, and writes no file.
- [ ] A recipe whose `generator_pin` or `compiler_version` differs from the local one is refused before generation with `FROB-REF-303` (exit 3) naming the field.
- [ ] The recipe record carries every field the world bank's rule reads (N19c-23): family, archetype variant, parameters, seed, compiler version, compile settings digest and expected identity, besides the generator pin.
- [ ] A world exported from `trj` with its replay closure replays on the Mac from an empty state root; the label is `exact` only where the recorded class licenses it, otherwise `tolerance-replay` with a recorded first divergence or a passed decision-level test.
- [ ] Removing the weights (or any one item) from the closure makes replay refuse and name that item.
- [ ] The closure bundle contains no forbidden transfer class and its size is logged per class.
- [ ] A paired comparison requested across the two families without class D1 is refused with `FROB-REF-561`.

## Test plan

### Unit tests

`cargo test -p frob-chronicle replay_closure` and `-p frob-scene recipe`:
- `recipe_roundtrip_canonical`: a recipe serializes to the same bytes on both platforms.
- `regenerate_same_id` (`synthetic` small terrain): the identity equals the expected one.
- `regenerate_pin_mismatch_refused` (`FROB-REF-303`, exit 3, `pointer: generator_pin`; no generator run), `regenerate_compiler_version_mismatch_refused` (`FROB-REF-303`, `pointer: compiler_version`).
- `regenerate_id_mismatch_refused_with_first_brick` (`scene-pack-identity-mismatch`, exit 9, `retry: never`; a planted difference in stage 5's output names stage 5 and its first brick; nothing admitted).
- `recipe_schema_fields`: a recipe without `compile_settings_digest` or `archetype_variant` fails the schema; a derived recipe applies its edits in order.
- `closure_is_minimal_and_sufficient`: removing any item breaks replay; adding none is needed.
- `closure_contains_no_state`: every item's transfer class is one of the nine allowed.
- `replay_label_table`: (same family, D2) → exact; (cross family, D1) → exact; (cross family, D3) → `tolerance-replay`; (any, D4) → refused.
- `cross_family_pair_refused_561` (through N35-07's `licence::check`, reached by BD-204): a paired comparison of a `trj` arm on `gpu-cuda` and a Mac arm on `gpu-metal`, both D2 with no D1 record, demanded `exact` or left at the default → `FROB-REF-561` ("paired across device families without class D1", N35-07's rule 4); the same pair asked `unpaired` → admitted and labelled unpaired; with D1 recorded for the pair → `PairedExact`.

### End-to-end script and logging

`scripts/e2e/fleet_regen_replay.sh --from trj --to mac` (every `scene gen`, `artifact export`, `artifact import`,
`sim run` and `sim replay` is a `run` verb and carries its own key `frr-<step>-<n>-<run-id>`; every envelope must
show `idempotent_replay: false`): (1) `frob scene gen --family terrain/stairs --difficulty 0.4 --seed S --key …
--json` on the source and export of the recipe (`frob artifact export <recipe digest> --to-host mac --out
<scratch>/ --key … --json`); (2) admit the bundle and `frob scene gen --recipe <file> --key … --json` on the
receiver; assert identity equality;
(3) the same with the receiver's `frob` rebuilt with this bead's mutant generator
(`--features frob-scene/mutant-generator-constant`), assert exit 9 with
`scene-pack-identity-mismatch` and the first differing stage and brick, then a recipe with a planted wrong
`generator_pin`, assert exit 3 with `FROB-REF-303` and no generator run; (4) on the
source run a short device batch with a planted failing world (a `synthetic` task that makes one address fall), export
its replay closure (`frob artifact export --replay-closure <run>:<address> --to-host mac --out <scratch>/ --key …
--json`), and assert that the same option without `--to-host`, and with a digest beside it, each answer
`FROB-REF-802`, exit 3; (5) on the receiver, after admitting the bundle, `frob sim replay --run <id> --world <address> --tier
batch-cpu --key … --json` and the same with `--tier gpu-metal` under another key; assert
the label rule and, where exact, digest-chain equality. Logged per the end-to-end standard: command lines, exit
codes, both hosts' fingerprint digests, `SceneId`s, per-class bundle bytes, the attained class, the first
differing step and quantity if any, and a `summary` line. Where only one machine is available the script runs
between two state roots and marks the run `single-host` (it then proves closure, not cross-platform identity).

### Known answers and negative controls

KA-539 (same `SceneId`; control: a generator with one changed constant). Negative controls: the mutant generator;
a closure with the weights withheld; a replay labelled `exact` across families with no D1 record (the label check
must refuse it). Metamorphic: regenerating twice gives the same identity; replaying the same closure twice gives
the same digest chain on one tier. Lanes: both platforms; debug and release.

## Considerations

- If KILL-D1 fires for a family, every cross-family replay is a tolerance replay and the wording of replay claims
  changes with it; this bead's label rule already covers that branch.
- A generator that uses platform elementary functions or hash-map iteration order will fail the identity test; the
  fix is in the generator, never a tolerance on `SceneId`.
- Private places: a recipe may itself be private; it carries its mark and is purged with the scene.
