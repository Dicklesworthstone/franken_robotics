## Background

Spark's verb list ends with two fleet verbs, both of kind `read`, first milestone M4: "`fleet.status`, `fleet.plan`:
roles and queues of the two machines; the assignment by role affinity and estimated work". The chapter's mechanism
register ties `fleet.status` to the **Solid** half of the two-machine design: "roles and seeds-only transfer; owner:
the daemon; verb: `fleet.status`; test: scene identity across machines; gate: GATE-SPARK-13". `fleet.plan` belongs
to the Frontier scheduler.

The distinction matters because the scheduler has a kill gate whose fallback is "the machines run standalone; jobs
are assigned by the role table through ordinary `job.*` verbs; the seeds-only rule stays". Under that fallback an
agent still needs one place to read which machine does what, what is queued where, how many bytes have crossed
between the machines in each transfer class against the allowance of 1 GB per campaign-hour, and whether scenes
regenerated on the other machine arrived at the same `SceneId`. That place is this verb. It must work with the
scheduler funded, not funded, or not yet decided, and with one machine unreachable.

## Scope

In: the registry entry, schemas, handler, rendering, redaction, exit codes, tests and the end-to-end script. Out:
the assignment itself (`fleet.plan`, BD-370; N21c-13); device details (`spark.devices`); job details (`job.list`).

## Technical approach

**Registry entry** (`registries/verbs.toml`). The row is VERBS-fleet's, a dependency, and the fields below repeat
it: owner `frob-cli`, MCP tool `fleet_status`, task clusters `fleet`; if the two ever differ, the registry row
governs. Tier `S` (DESIGN, now in VERBS-fleet's row as well): the chapter's mechanism register lists "roles and
seeds-only transfer" (`fleet.status`) as Solid with no kill gate, and this verb must keep working when KILL-FLEET
fires; a tier `F` would tie it to the scheduler's fate.

```toml
[[verb]]
name = "fleet.status"
cluster = "fleet"
kind = "read"
tier = "S"
capabilities = ["fleet:read"]
input_schema = "frob.fleet.status.in/1"
output_schema = "frob.fleet.status.out/1"
refusals = []
idempotent = true
cost_model = "static: under 1 s; one round trip on the peer link if configured"
first_milestone = "M4"
task_clusters = ["fleet"]
owner = "frob-cli"
purpose = "Roles and queues of the two machines"
examples = ["frob fleet status --json"]
```

The second form, `frob fleet status --campaign <campaign> --json`, is exercised by the end-to-end script; it is not
a registry example, because the registry row lists one.

**Input.** Optional `machine` (`mac`, `trj`), optional `campaign` (restricts the transfer block).

**Output (`result`).**

| Block | Content |
|---|---|
| `machines[]` | name, host, `link`: `up`, `down` (with seconds since the last heartbeat) or `standalone`; fingerprint digest and status per device; the daemon's configuration digest |
| `roles` | the seven role rows with the affinity of each machine (`yes`, `limited` with its condition, `no`), the registry digest and the by-hand rule |
| `scheduler` | `funded`, `by-hand` (KILL-FLEET fired, or the link is not built) or `undecided`; the kill gate's recorded state |
| `queues[]` | per device lane (`trj/cuda:0`, `trj/cuda:1`, `trj/cpu`, `mac/metal:0`, `mac/cpu`): queue length, backlog as an interval in seconds, the running job's role and estimated remaining time, estimate bias, the share of the last 50 jobs over twice their estimate, `estimates: reliable` or `unreliable`, utilization |
| `waiting[]` | jobs that are not placed, each with `why`: `machine-down`, `role`, `class`, `indeterminate`, `pair-group`; filled from the latest fleet plan record in the job ledger when the scheduler is funded (N21c-13, N21c-14 write it), empty with `scheduler: by-hand` |
| `transfer` | per campaign: bytes and items per transfer class in each direction, the total, bytes per campaign-hour against the target of 1 GB, `over_target`, and the count of refused attempts by class (`FROB-REF-618`) |
| `scene_identity` | regenerations checked across machines: count equal, count mismatched, the last mismatch's recipe and both identities |

**Lane statistics** (`frob-cli::fleet::lane_stats`, defined here because this verb is Solid and must print them
whether or not the scheduler exists; the scheduler's balance rule in N21c-14 reads the same function). Over the
lane's last 50 finished jobs from the job ledger (fewer: all of them, with the count printed): **estimate bias**
b = median of ln(actual ÷ point estimate), printed with the count; **over-twice share** = the fraction with
actual > 2 × point estimate; `estimates: unreliable` when that share is at least 20% (10 of 50), `reliable`
otherwise. Backlog = the remaining point estimate of the running job plus the point estimates of the queued jobs,
printed as the interval of their cost intervals. Arithmetic (DESIGN): the median of logs in `f64` from integer
milliseconds, the share as an exact count over 50.

**Behaviour.**
1. Read the local daemon's fleet state. With no peer link in the build or `fleet.peer_link = false` (the default,
   OPEN-TETHER-5), the other machine's entry reads `link: standalone` and its blocks are absent with that reason.
   If a peer link is configured (N32a-35, which carries the status request as one of its `frob.peer/1` frames) and
   up, ask the peer for its half; if it is configured and down, mark the peer's blocks `unavailable` with the
   reason and the seconds since the last heartbeat. The verb never refuses because a machine is unreachable.
2. Redaction: jobs of other principals appear with role, size class and estimate only; identifiers and names are
   shown only inside the caller's namespace.
3. Exit 0 when both machines are up (or one is `standalone` by configuration), no job waits on `machine-down`,
   nothing is over target and no identity mismatch is on record; exit 2 with one `warnings[]` entry per flag
   otherwise. `next_actions[]` suggests `frob spark fingerprint` for a stale device and the by-hand machine for a
   waiting job.
4. Evidence block: class `Tested`, tier `static`, determinism `exact` for the role table and the integer meter;
   `claims` empty (VERBS-fleet's *operational* label); queue estimates are intervals with their calibration flag.
   `reality: no-claim`.
5. Nothing is written. Without a daemon the verb reports roles and the stored transfer rows only and says so.

Human rendering: a two-column role table, one line per device lane, the transfer total against the target.

## Acceptance criteria

- [ ] `frob fleet status --json` returns the seven roles with the 14 affinity cells of the policy table and the registry digest.
- [ ] Standalone (the default): each daemon lists its own device lanes with queue lengths that equal `job.list` counts per device, reports the other machine as `link: standalone` and exits 0 when nothing else is flagged.
- [ ] The lane statistics reproduce `status_lane_stats_hand_case`, and a lane with 10 of its last 50 jobs over twice their estimate reads `estimates: unreliable`.
- [ ] The linked stage of the script (`--stage linked`: five lanes across two linked daemons; the peer killed → that machine `down`, exit 2, the local half still reported) is a hook that runs only when a peer link is configured; it is run and asserted by the peer link's bead (N32a-35), which this bead cannot depend on.
- [ ] The `transfer` block's per-class bytes equal the ledger's meter rows exactly; a campaign at 1.2 GB per campaign-hour shows `over_target: true`.
- [ ] After a planted scene-identity mismatch the `scene_identity` block reports it with both identities.
- [ ] With KILL-FLEET recorded as fired, `scheduler` is `by-hand` and the verb's other blocks are unchanged.
- [ ] Another principal's job identifiers never appear in the output of a caller without that namespace.
- [ ] The MCP tool `fleet_status` returns the same envelope; the output validates against `frob.fleet.status.out/1`; the verb allocates no device memory.

## Test plan

### Unit tests

`cargo test -p frob-verbs fleet_status` and `-p frob-cli fleet::status`:
- `status_roles_block_matches_registry`.
- `status_peer_down_is_flag_not_refusal`: with a peer configured and its heartbeat absent for 40 s (`synthetic` link state), exit 2, `link: down` with 40 s, local queues present.
- `status_standalone_is_not_a_fault`: `fleet.peer_link = false` → the other machine reads `standalone`, exit 0, no warning.
- `status_lane_stats_hand_case`: ratios actual ÷ estimate of 1.0 (20 jobs), 1.5 (20 jobs), 2.5 (10 jobs) → the 25th and 26th of the 50 sorted logs are both ln 1.5, so b = 0.4055; over-twice share 10/50 = 0.20 → `unreliable`; the same with one 2.5 replaced by 1.9 → b unchanged, 9/50, `reliable`. (The median of an even count is the mean of the two middle values.)
- `status_transfer_block_exact`: `synthetic` meter rows of 12,288, 3,145,728 and 1,048,576 bytes total 4,206,592.
- `status_redacts_other_principals`.
- `status_scheduler_states`: `funded`, `by-hand`, `undecided` from three gate-registry fixtures.
- `status_schema_roundtrip`, `status_waiting_reasons_exhaustive` (an unknown reason fails to serialize).

### End-to-end script and logging

`scripts/e2e/fleet_status.sh [--stage standalone|linked]` (default `standalone`). Stage `standalone`, on one
`frobd` with the default configuration (and on each real machine where reachable): `frob fleet status --json`
(assert the seven roles, the 14 cells, the local lanes, the other machine `standalone`, exit 0); submit three
`synthetic` CPU-tier jobs of roles `train`, `derive-prove` and `eval-large` through their own `run` verbs (the
`job.*` verbs of VERBS-job list, find, wait on and cancel jobs and submit none: a `frob sim run` on a 2 cm home
scene, a `frob prove bundle a:…` of a fixture mission answer, a `frob sim run` bound to a 1 cm warehouse scene,
each with `--tier batch-cpu` where the verb takes one and its own `--key fs-<role>-<run-id>`) and assert the lanes'
queue lengths against `frob job list --json`; export a recipe and a
weights file through the cross-machine bundle (N21c-08) and assert the meter with `frob fleet status --campaign
<campaign> --json`; attempt a forbidden export (assert the refused count rises by one); plant a scene-identity
mismatch through the regeneration check (N21c-09: a recipe whose `expected` `SceneId` is planted wrong, `frob scene
gen --recipe <planted recipe> --key fs-regen-<run-id> --json`, expected exit 9 with `scene-pack-identity-mismatch`;
a differing generator pin would be refused with `FROB-REF-303` before generation and record no mismatch) and
assert the `scene_identity` block and exit 2; point the daemon at a scratch gate register recording KILL-FLEET
`fired` (written after `e2e_registries_scratch`, so the run is marked `gates_claimable: false`) and assert
`scheduler: by-hand` with the other blocks unchanged. Stage `linked` (the hook N32a-35 runs once the link
exists): two linked daemons; assert five lanes and `link: up`; kill the peer (assert exit 2, `down`, the local half
present); restart it (assert exit 0). Logs through the STD-E2E helper to `target/e2e-logs/fleet_status/<utc>.ndjson`
with a transcript: `ts`, `script`, `bead`, `step`, `event`, command lines, exit codes, wall times, the evidence
block, queue lengths and byte totals with units and expectations, the lane statistics, registry and configuration
digests, and on failure the first differing field with both values. Final `summary` with assertion counts and the
stage run.

### Known answers and negative controls

Known answers: the 14 cells; the meter arithmetic; KA-539 through the `scene_identity` block. Negative controls: a
handler that refuses when the peer is down (the down step must fail); a handler that reads queue lengths from its
own cache instead of the job ledger (the equality with `job.list` must fail after a submit); a meter block that
omits the incoming direction (the total must fail). Lanes: twice on one machine; Linux and macOS.

## Considerations

- The verb is Solid although its registered milestone is M4; the role table and the meter it prints exist from M2
  and are readable until then through their own records and the export envelope.
- "Standalone" is a configuration, not a fault: OPEN-TETHER-5's default is standalone machines.
- Queue contents reveal load; redaction keeps identities private while keeping the counts honest.
