## Background

Per-design kernel specialization has four standing rules (ADR-SPARK-08): it is never the default and never part of
the edit loop; it is built only for the survivors of a tournament that go on to finalist training, and only if the
profile shows a specializable share of at least one third; a specialized kernel is bit-identical to its generic
kernel; and "survivor cohorts move to specialized kernels only at an acknowledged chunk boundary, with a versioned
state map, and the specialized kernel is another cache entry". The population chapter adds the promotion rule: a
survivor is promoted when T_remaining·(1 − 1/g) exceeds the compile cost, g being the measured gain; compile time
is capped at 60 s per design on CPU workers; the swap happens at a boundary with a versioned state map; a
specialized kernel is a new `KernelId`.

Terms. A *bucket* is one shape class on one device: one arena, one compiled kernel set, one step plan, one launch
graph. A *chunk* is the unit of commit: the host synchronizes once per chunk of control intervals; a chunk ends
with a commit that writes the new state to the other of two committed slabs, and only a completed receipt makes it
current. Between chunks the host may hold a write lease (resets, admission of a variant). No shape change enters a
running environment (INV-SPARK-05; `FROB-REF-611`: a new bucket).

The consequence that shapes this bead: a specialized kernel set is a different kernel set, hence a different step
plan and launch graph. A cohort therefore does not change kernels in place; it **moves** to a bucket built for the
specialized set, by copying its worlds' committed rows. The move must change no digest.

## Scope

In: eligibility and the promotion rule; the off-path compile with its cap; the two-phase switch at a chunk
boundary; the versioned state map; verification after the move; abort paths; the receipt. Out: the specializer
(BD-371); the bit-identity fence (N21c-19); the kill decision (N21c-18).

## Technical approach

1. **Eligibility.** The design carries the survivor flag for finalist training; the kill gate has not fired; the
   job is not an edit-loop job. An edit to the design changes its variant digest, which orphans its specialized
   kernel; the edited design starts again on the generic kernel.
2. **Promotion rule.** Promote when T_remaining·(1 − 1/g) > C, with T_remaining the estimated remaining device
   seconds of the cohort's job on the generic kernel (the estimator's point value), g the measured whole-step gain
   (the paired lower bound on record for this shape class; never an assumed value) and C the compile cost in
   seconds. With g = 1.2 and C = 60 s the job must have more than 360 s left; with g = 1.25 and C = 20 s, more
   than 100 s.
3. **Compile off the hot path.** The specialized set is generated and compiled on CPU workers while the cohort
   keeps running on the generic kernel. Wall-time cap 60 s per design; over the cap the attempt is abandoned and
   recorded, and the cohort stays generic.
4. **Fence.** The specialized set must hold a current bit-identity row for the target device. No row, no switch.
5. **Prepare.** Create the target bucket (arena, kernel set, step plan, one graph capture) for the specialized set.
   Its memory must pass the estimator (`FROB-REF-602` otherwise). Build the **state map**: `StateMap { from:
   (ShapeClassId, layout version), to: (ShapeClassId, layout version), entries: [{ slab, from_offset, from_stride,
   to_offset, to_stride, elements_per_world }], digest }`. It is a pure index mapping from the padded generic
   layout to the specialized layout; trailing padding (which holds neutral elements) is dropped. The map is
   versioned and content-addressed so that a snapshot taken before the switch can be restored after it.
6. **Commit, at an acknowledged chunk boundary.** The owner of the job (the learner or evaluator loop) requests the
   switch; the source environment finishes and commits its current chunk; the owner acknowledges the boundary; in
   the between-chunk window the cohort's committed rows are copied by indexed copy through the state map into the
   target bucket; the source slots are released by a masked reset. A request that arrives mid-chunk waits for the
   boundary; nothing is switched inside a chunk.
7. **Verify.** The in-kernel digest of every moved world, computed in the target bucket, must equal its digest at
   the committed epoch in the source. A mismatch aborts the switch: the target bucket is torn down, the cohort
   continues in the source from the same committed epoch, and the specialized entry is quarantined.
8. **Record.** The placement receipt and the episode records carry: generic and specialized `KernelId`s, the switch
   epoch, the state-map digest, compile seconds, the fence row, and the promotion-rule inputs. Replay and teleport
   of a world across the switch use the map digest to restore either layout.

World addresses, random streams and results are unchanged by the move: results are keyed by address, a world's
result does not depend on the capacity of the bucket it ran in, and the kernels are bit-identical. Determinism
class: unchanged (D2 on the device family).

## Acceptance criteria

- [ ] On a 1,000-episode corpus, a cohort switched at a chunk boundary produces per-world digest chains identical to the same cohort run entirely on the generic kernel, on `batch-cpu` and on each available device.
- [ ] A switch requested mid-chunk takes effect only at the next acknowledged boundary; without the acknowledgement nothing moves.
- [ ] The promotion rule returns the hand cases; a job with too little time left is not promoted.
- [ ] A compile over 60 s, a missing fence row, a failed memory estimate and a post-move digest mismatch each abort cleanly: the cohort continues on the generic kernel from the committed epoch, device memory of the target bucket is released, and the reason is in the receipt.
- [ ] A snapshot taken before the switch restores after it through the state map, and the reverse.
- [ ] An edit to the design returns it to the generic kernel.
- [ ] The source environment performs no graph capture and no shape change during the switch (capture counter unchanged).

## Test plan

### Unit tests

- `promotion_rule_hand_cases`: (T = 400 s, g = 1.2, C = 60 s) → promote (66.7 > 60); (T = 300, 1.2, 60) → no (50 < 60); (T = 120, 1.25, 20) → promote (24 > 20).
- `state_map_roundtrip` (`synthetic` layouts): generic → specialized → generic restores every non-padding element bit for bit.
- `state_map_drops_only_padding`: every dropped element equals its slab's neutral element; a non-neutral dropped element is an error.
- `switch_deferred_to_boundary`, `switch_requires_acknowledgement`.
- `abort_paths`: each of the four abort causes leaves the source epoch and digests unchanged.
- `edit_invalidates_specialization`.

### End-to-end script and logging

`scripts/e2e/specialize_switch.sh`: runs a finalist-training fixture for the reference quadruped twice, once with
`--specialize-survivors` and once without, through `frob train start … --json`; compares per-world digest chains
with `frob telemetry divergence --exact`; then injects each abort cause in turn. Logs per the end-to-end standard:
command lines, exit codes, the switch epoch, state-map digest, compile seconds against 60, kernel identifiers
before and after, digests compared with the first differing world and step on failure, allocated device bytes
before and after an abort, and a `summary` line.

### Known answers and negative controls

Known answer: digests across the switch equal the unswitched run (bit identity, KA-538, carried through the move).
Negative controls: a switch forced inside a chunk (uncommitted state copied; the digest verification must catch
it); a state map with two swapped slab entries (verification must abort the switch); a specialized set with a
reassociated sum (blocked by the fence; if the fence is bypassed in a test build, verification passes at the move
and the corpus comparison must fail later, which shows why the fence is required). Lanes: twice on one machine;
slot permutation of the cohort; two bucket capacities.

## Considerations

- A second environment for one design costs arena memory and one more step plan per step; for a single survivor
  cohort of thousands of worlds this is acceptable, for dozens of small cohorts it is not, which is one more reason
  specialization is for survivors only.
- The acknowledgement exists because learners hold views into rollout storage; they must drop or remap them at the
  boundary.
- Not built if KILL-SPECIALIZE fires.
