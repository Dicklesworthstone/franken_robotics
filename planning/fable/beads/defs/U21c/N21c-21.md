## Background

The fused per-world step kernel is a Moonshot: one persistent kernel per world group would hold a world's working
set in thread-group memory for a whole control interval and touch device memory only at its ends. Its lever is
memory traffic; its ceiling is occupancy: a block limited to 48 KiB of shared memory (the limit the suite's piano
renderer enforces on itself; FACT) holds one quadruped world of about 35 kB, so the device runs few worlds at once
and occupancy is expected to fall to a few percent of its lanes (HYPOTHESIS). The sign of the benefit is unproven.

The kill gate names the pilot exactly: "within one week, fuse kinematics, dynamics terms and one Newton iteration
for the reference quadruped and compare with the staged kernels at 8,192 worlds, digests unchanged. Trigger:
paired lower bound below 2.0 on the whole step. Fallback: the staged step plan, which is the design of record."
This bead is that pilot. Nothing else in the program waits on it.

## Scope

In: the ceiling computed first; one hand-written fused kernel on CUDA for the three named stages of workload Q; the
digest comparison; the paired timing; occupancy and traffic measurements; the pilot record. Out: a general fused
step, a Metal port, the flag on `sim.run` (all in the conditional mechanism bead); the decision (N21c-22).

## Technical approach

**Fixture.** Workload Q: the reference quadruped (12 actuated joints, 18 degrees of freedom, 13 bodies, contact
capacity 32, row capacity 160), step 2 ms, 4 warm-started Newton iterations, decimation 10; 8,192 worlds; one RTX
4090; physics only; launch graphs captured for the staged arm.

**Step 0, the ceiling (before any code).** From the M2 profile: f = the share of the whole step spent in
kinematics, dynamics terms and one Newton iteration; B_staged = bytes of device memory those stages touch per
world-step; B_fused = bytes the fused kernel would touch (one load and one store of the working set per fused
span). With r = B_staged ÷ B_fused and h = an allowance for occupancy loss, the bound is 1/(1 − f + f/r + h). The
pilot is registered with f, r, h and the bound. If the bound is under 2.0 with h = 0, the comparison is refused
(`FROB-REF-866`), the record says "ceiling below goal", and the decision bead reads that as the trigger.

**Step 1, the fused kernel (hand-written, shared dialect, CUDA prelude).**
1. One thread group per world. At entry the group gathers the world's working set for the three stages (state,
   kinematic and dynamic cache, mass matrix and factor, Jacobian, row and contact records: about 35 kB) from the
   device slabs into block-shared memory; the gather is the only device read.
2. Threads of the group run the three stages in the staged kernels' operation order: links of one depth level in
   parallel, rows in parallel, reductions in the same fixed tree shape, with barriers *inside the thread group*
   between phases. No grid-wide barrier; no fused multiply-add; masks are selects.
3. At exit the group scatters the outputs back to the slabs; the remaining stages of the step run as staged
   kernels.
4. The kernel refuses, at compile time, a shape class whose working set exceeds the block's shared-memory limit
   read from the device (the fingerprint), with the bytes needed and the limit.

**Step 2, digests.** On the pinned corpus (1,000 episodes), per-world digest chains of the fused arm must equal the
staged arm's, bit for bit (`frob telemetry divergence --exact`). No timing is taken until they do.

**Step 3, timing.** At least ten pairs (staged, fused), back to back in randomized order, same addresses, warm.
Ratio r_i = t_staged ÷ t_fused on the **whole step**; paired lower bound exp(ℓ̄ − t·s/√n), t = 1.833 for n = 10.
Also recorded per arm: bytes touched per world-step, worlds in flight at once, lane occupancy (active threads ÷
device lanes), shared memory per block, median and 99th-percentile step time, the disclosure block.

**Step 4, record.** `frob.pilot.fused/1` in the review log: the ceiling inputs, the digest comparison, the bound
with n, ℓ̄ and s, occupancy, traffic, fingerprint digest, and the verdict against 2.0. One week of effort; if the
week ends without digest equality the record says so and the kill gate reads it as its trigger.

## Acceptance criteria

- [ ] The registration with f, r, h and the computed ceiling predates any pilot code or timing.
- [ ] Per-world digests of the fused and staged arms are identical on the 1,000-episode corpus, or the record states that identity was not reached within the week.
- [ ] The paired lower bound on the whole step is recorded with at least ten pairs and the full disclosure block.
- [ ] Occupancy, worlds in flight and bytes touched per world-step are recorded for both arms.
- [ ] The fused kernel passes the dialect lint (no grid-wide barrier, no fused multiply-add, no fast math) and makes no device allocation after environment creation.
- [ ] The verdict is recorded whichever way it falls.

## Test plan

### Unit tests

- `fusion_ceiling`: f = 0.5, r = 4, h = 0.1 → 1.379 (refused); f = 0.8, r = 8, h = 0.05 → 2.857 (admitted).
- `working_set_bytes_q`: 4·(61·13 + 17·18) + 12·18² + 4·160·18 + 48·160 + 96·32 = 4,396 + 3,888 + 11,520 + 7,680 + 3,072 = 30,556 bytes, plus about 4,000 of state, under 48 KiB (49,152).
- `working_set_bytes_h_refused`: the humanoid's 9,700 + 14,700 + 44,800 + 15,360 + 6,144 = 90,704 bytes exceeds 49,152 and the kernel refuses the shape class.
- `fused_matches_staged_cpu`: the fused kernel's CPU emulation (the oracle, written in Rust beside it) equals the staged `batch-cpu` kernels on 10⁴ random states, bit for bit.

### End-to-end script and logging

`scripts/e2e/fused_step_pilot.sh --pairs 10 --seed S`: `frob sim run --workload Q --worlds 8192 --tier gpu-cuda
--step-plan staged|fused-pilot --json` in randomized paired order, the digest comparison, and the record. Logs per
the end-to-end standard: command lines, exit codes, wall times, evidence and disclosure blocks, each pair's times
and ratio, the bound against 2.0, bytes touched, occupancy, shared memory per block against the device limit,
digests compared with the first differing world, step and stage on failure, and a `summary` line with the verdict.

### Known answers and negative controls

Known answer: digest equality between arms. Negative controls: an A/A pair (staged against staged) must give a
bound within a few percent of 1; a fused variant that sums a reduction in thread-arrival order must fail the digest
comparison; a fused variant with a grid-wide barrier must be rejected by the dialect lint. Lanes: digests twice on
one machine and under slot permutation.

## Considerations

- If fusion wins only by lowering occupancy-insensitive traffic at small world counts, the result does not
  transfer to 8,192 worlds; the pilot is run at 8,192 as the gate states.
- The pilot fits the default compute envelope (one device, under one hour).
- A positive result is a licence to build one more step plan, not to remove the staged one.
