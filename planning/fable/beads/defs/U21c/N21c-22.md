## Background

KILL-MEGA is the kill gate of the fused per-world step kernel, a Moonshot that would keep a world's working set in
thread-group memory for a whole control interval. Register row: **trigger**: in the one-week fusion pilot (8,192
worlds, digests unchanged) the paired lower bound on the whole step is below 2.0. **Fallback**: the staged step
plan, which is the design of record. **Milestone**: M8, before the work package. The register adds that the gate
has no decision point of its own: its trigger reads a pilot that may run any time after the M2 profile, and it is
decided when the work package would be funded.

The threshold is high on purpose. The benefit is unproven in sign (one quadruped world fills a 48 KiB block, so
lane occupancy is expected to fall to a few percent), the mechanism adds a second step plan that every determinism
and fault test must then cover, and published incumbents already reach parity-level throughput with staged
kernels, so "no order of magnitude is available per step". Only a factor of two on the whole step would pay for a
second execution path.

## Scope

In: the decision rule, the reading of the pilot record, the ADR, downstream effects. Out: the pilot (N21c-21); the
mechanism (N21c-23).

## Technical approach

**Input.** The `[[pilot.result]]` that N21c-21 appends to PILOT-MEGA-01 in
`crates/frob-conformance/registry/pilots.toml` and the payload `frob.pilot.fused/1` it names by its `receipt`
hash, read by that hash: the ceiling inputs (f, r, h and the bound), the digest comparison, the paired lower bound
with n, ℓ̄ and s, occupancy and traffic figures, fingerprint digest.

**Rule.**
1. The ceiling computed before the pilot was below 2.0 and the comparison was refused: **fired** (on paper).
2. Digest identity between the fused and staged arms was not reached within the pilot's week: **fired**.
3. Digests identical and the paired lower bound on the whole step is below 2.0: **fired**.
4. Digests identical and the bound is at least 2.0 (exactly 2.0 passes): **not fired**; the mechanism bead is
   released, behind a flag and off every critical path.
5. The record is missing a required field (fewer than ten pairs, no disclosure block, a mean in place of a bound):
   no decision; the pilot is completed first. A ratio stated without its paired lower bound is refused as a
   performance ratio (`FROB-REF-863`).

There is no repair cycle in this gate's trigger: the pilot is one week and its result stands.

**Fallback when fired.** The staged step plan remains the only step plan. The value `fused` of `sim.run
--step-plan` (registered in VERBS-sim with N21c-23 as owner) is never built and answers the capability refusal
`FROB-REF-724`, exit 5, before any world is stepped, as every option of a bead not in the build does; the
pilot's development hook (`--step-plan fused-pilot` under the feature `pilot-fused-step`, N21c-21) and its kernel
are removed, so no build accepts a fused plan; by N41-17's typed close rules (rule 5) the mechanism bead N21c-23
closes `superseded` with this ADR's identifier and the epic BD-441 closes `fallback` with the fallback's name ("the
staged step plan"); the idea returns to the register of deferred
ideas with the measured bound, occupancy and traffic, so that a later hardware change (a larger block-shared
memory limit, a different bandwidth-to-arithmetic ratio) can reopen it with a new pilot.

**Not fired.** The mechanism bead proceeds with these conditions carried from the pilot: digest identity with the
staged path on every reference workload it claims; the CPU-versus-device check for its kernels; the
batch-composition invariance test; a Metal port only where the device's thread-group memory limit holds the
working set; the staged plan stays the default and the design of record.

**Record.** The ADR `docs/adr/ADR-KILL-MEGA-M8.md` with the fields the kill-gate record bead N40-03 requires
(the kill gate, the milestone, the trigger as registered and any amendments, each measured value with its
receipt hash beside 2.0, the outcome, the fallback in force and the capability's name from now on, the beads
re-read, the downstream changes, the recording session), and also the measured bound and its inputs, occupancy,
bytes touched per world-step for both arms, commit, fingerprint digest, seeds and the rule number. The KILL-MEGA
record of `registries/gates.toml` (entered by the fallback ledger N40-24) gets its one decision entry, `decision =
{ outcome = "not-fired" | "fired", adr, date, session, receipts }` in N40-03's vocabulary, `receipts` the pilot
result's receipt.

## Acceptance criteria

- [ ] The ADR exists, cites the pilot record by identity and states which rule number applied, with measured values.
- [ ] If fired: N21c-23 is closed `superseded` and BD-441 `fallback`, each citing this ADR (N41-17's lifecycle check passes); `--step-plan fused` answers `FROB-REF-724`, exit 5, on a release build and the pilot's `fused-pilot` hook is removed; the deferred-ideas register carries the measurements.
- [ ] If not fired: the release of the mechanism bead cites the ADR and lists the carried conditions.
- [ ] The decision is taken by a session that did not write the pilot kernel, and is listed for the M8 exit review.
- [ ] The decision function reproduces the rule table in its unit tests.

## Test plan

### Unit tests

- `kill_mega_rule_table`: (ceiling 1.38, refused) → fired by rule 1; (no digest identity) → fired by rule 2; (identical, bound 1.6) → fired by rule 3; (identical, bound 2.0) → not fired; (identical, bound 2.4) → not fired; (nine pairs) → no decision.
- `kill_mega_requires_bound_not_mean`: a record with a mean of 2.3 and no bound returns `no decision`.
- `kill_mega_registry_row_matches_decision`.

### End-to-end script and logging

`scripts/e2e/kill_mega_record.sh`: reads the pilot result's payload by its receipt hash through `frob artifact read
<hash> --json`, recomputes the decision and compares it with the KILL-MEGA decision entry of the gate registry;
when the outcome is `fired`, it runs `frob sim run --workload Q --worlds 8 --tier gpu-cuda --step-plan fused --key
km-fb-1 --json` on a release build and asserts `FROB-REF-724`, exit 5, zero worlds stepped. It sources the STD-E2E
helper and writes `target/e2e-logs/kill_mega_record/<utc>.ndjson` with a transcript: `ts`, `script`, `bead`,
`step`, `event`, command lines, exit codes, wall times, the evidence block of the record, `metric` lines for the
bound against 2.0 with n, ℓ̄ and s, the digest verdict, the rule number, the ADR path and digest, on failure the
first differing field between the recomputed decision and the register, and a `summary` line; it fails if the
registry and the recomputed decision differ.

### Known answers and negative controls

Negative controls: a record whose bound was computed on the fused stages only and not on the whole step (rejected:
the record's `scope` field must read `whole-step`); a decision recorded with the threshold in place of the
measurement (rejected by the registry check). The boundary case (exactly 2.0) is in the rule table.

## Considerations

- Priority is one step above the Moonshot default only because the epic cannot close without it.
- A fired gate costs nothing on any critical path; no North-Star scenario depends on the fused kernel.
- The decision records occupancy and traffic so that the bandwidth-bound hypothesis gains one more data point
  whichever way the gate falls.
