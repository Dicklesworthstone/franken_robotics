## Background

If, and only if, the one-week pilot shows a paired lower bound of at least 2.0 on the whole step with digests
unchanged, the fused per-world step kernel is built as a second step plan. The chapter's mechanism register gives
its shape: owner `spark/frob-spark-cuda`; surface: a flag on `sim.run`; test: digests unchanged; gate: the pilot;
kill gate KILL-MEGA. It is "behind a flag, piloted on CUDA first (on Metal the thread-group memory limit is read
from the device), and off every critical path". The staged step plan stays the default and the design of record.

A *step plan* is the static, ordered list of launches with fixed grid sizes built at environment creation; a
rollout repeats it for the control decimation. The staged plan has one launch per kernel stage. The fused plan has
one launch per control interval per bucket, in which each thread group owns one world, holds its working set in
thread-group memory, runs every stage of every step of the interval there, and writes back once.

Why it may be built at all after a pilot of only three stages: the pilot shows whether memory traffic is the lever
at 8,192 worlds. This bead must then show the same on the whole step with every stage fused, or switch itself off.

## Scope

In: the fused step plan for shape classes whose working set fits thread-group memory on CUDA; the flag; refusal
when a shape class does not fit; digest identity; the checks every device kernel owes; the re-measured bound. Out:
the staged plan (unchanged); a Metal port beyond a feasibility check; persistent launches across more than one
control interval (excluded: they need a grid-wide barrier).

## Technical approach

1. **Kernel.** `K-fused-step` in the shared dialect: at entry each thread group gathers its world's rows from the
   committed slab into thread-group memory; for each of the d steps of the control interval it runs the stages in
   the staged kernels' operation order (same depth-level order, same row order, same fixed reduction trees, same
   sort keys), with barriers inside the group only; at exit it scatters state, flags, statistics increments and,
   when telemetry asks for them, per-stage digests computed in the group. No grid-wide barrier, no fused
   multiply-add, no fast math, masks as selects, `u32` exact arithmetic.
2. **Plan.** A `fused` variant of `frob.stepplan/1`: policy forward, then one `K-fused-step` launch per control
   interval, then observation; the control block (step counter, epoch, cancel word, decimation phase) is read by
   the launch as in the staged plan; chunks, the commit fence and the two committed slabs are unchanged. One graph
   capture per bucket; no device allocation after environment creation.
3. **Admission.** Working-set bytes of the shape class (from the byte model) must not exceed the device's
   thread-group memory limit read from the fingerprint (49,152 bytes is the limit the suite's renderer enforces on
   CUDA; the reference quadruped needs about 35 kB, the humanoid about 97 kB). A shape class that does not fit has
   no fused kernel: under an explicit `--step-plan fused` the planner refuses before any world is stepped, as for a
   strict backend request with a missing kernel (`FROB-REF-604`; first repair: the staged plan). There is no
   silent fallback.
4. **Flag.** `frob sim run … --step-plan staged|fused` (default `staged`). The placement receipt and the disclosure
   block name the plan. The fused plan has its own step-plan identity; results are interchangeable with the staged
   plan's because digests are identical.
5. **Checks owed.** (a) Per-world digest chains equal the staged plan's on the standard battery; (b) a current
   CPU-versus-device check for `K-fused-step` (its CPU reference is the staged `batch-cpu` step); (c) the
   batch-composition invariance test (alone, in random co-tenancies, under slot permutation, at two bucket
   capacities, on one and two shards); (d) faults and flags identical: the same worlds are marked `Faulted` or
   `Degraded` at the same steps; (e) cancellation at the launch boundary within the latency target (250 ms at the
   99th percentile), with no leaked device memory after 10³ cancel cycles.
6. **Re-measured bound.** The pilot's criterion is applied again to the whole fused step: at least ten pairs
   against the staged plan at 8,192 worlds, paired lower bound at least 2.0. Below that, the flag is withdrawn and
   the bead closes with the measurement; an optimization lands only with identical digests.
7. **Stage localization.** A first divergence inside a fused interval is localized by replaying the world on the
   staged plan (legitimate because the two are digest-identical) or from the in-group per-stage digests.

Determinism class D2 on CUDA, unchanged; evidence class of outputs as for the staged plan.

## Acceptance criteria

- [ ] `frob sim run --workload Q --worlds 8192 --tier gpu-cuda --step-plan fused --json` completes and its per-world digest chains equal the staged plan's on 1,000 episodes.
- [ ] The humanoid shape class is refused under `--step-plan fused` with `FROB-REF-604` and zero worlds stepped; the default plan is unaffected.
- [ ] The CPU-versus-device check, the batch-composition invariance test and the fault-and-cancellation battery pass for the fused plan; allocated device bytes stay flat; graph captures after warm-up are zero.
- [ ] The paired lower bound against the staged plan on the whole step is recorded (TARGET ≥ 2.0) with the disclosure block; below 2.0 the flag is withdrawn.
- [ ] The dialect lint passes on `K-fused-step`; its manifest declares footprints, resource bounds and the thread-group memory it needs.
- [ ] The staged plan remains the default and the design of record; `CONTRACT.md` of the annex records the fused plan's validity domain and known gaps.

## Test plan

### Unit tests

- `fused_cpu_emulation_matches_staged`: the Rust emulation of `K-fused-step` equals the staged `batch-cpu` step on 10⁴ random states for workload Q, bit for bit, for d = 1, 4 and 10.
- `fused_admission_by_working_set`: 34,556 bytes fits 49,152; 96,704 does not.
- `fused_flags_match`: a planted non-finite state marks the same world `Faulted` at the same step in both plans.
- `fused_plan_identity_differs_results_equal`.
- `fused_no_alloc_after_create`.

### End-to-end script and logging

`scripts/e2e/fused_step.sh`: runs the standard battery under both plans, compares digests
(`frob telemetry divergence --exact`), runs the refusal case, the cancel cycles and the paired timing. Logs per the
end-to-end standard: command lines, exit codes, wall times, evidence and disclosure blocks, digests compared with
the first differing world, step and stage on failure, the bound against 2.0 with n, ℓ̄ and s, allocated bytes,
capture counts, the refusal with its repairs, and a `summary` line.

### Known answers and negative controls

Known answer: digests unchanged against the staged plan. Negative controls: a fused variant with one reduction in
arrival order (digest comparison must fail); a fused variant that keeps a padded contact active (the invariance
test at two bucket capacities must fail); an A/A timing pair (must not clear 2.0). Lanes: twice on one machine;
slot permutation; two capacities; one and two shards.

## Considerations

- Two step plans double the surface every determinism, fault and fidelity test must cover; that cost is why the
  threshold is 2.0 and why the flag is withdrawn below it.
- Occupancy falls when one world fills a block; throughput per device may improve while worlds in flight drop, so
  latency-sensitive uses (many small jobs under slot dispatch) may prefer the staged plan even if this one wins on
  throughput.
- A Metal port needs the device's thread-group memory limit to hold the working set and stays out of scope until
  the CUDA result stands.
