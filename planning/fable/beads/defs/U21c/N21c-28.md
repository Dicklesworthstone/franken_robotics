## Background

FACT: FrankenSim's accelerator doctrine states that FrankenSim ships no accelerator backend, requires a permanent
CPU reference, and defines **twelve evidence fields (AE-01 to AE-12)** for any device run: device identity; driver
and runtime; compiler and backend; kernel source hash; kernel and workload identity; CPU axes; reduction and
determinism policy; CPU-versus-device comparison; the retained CPU reference; cancellation outcome; phase
attribution; and a go or no-go decision. FrankenRobotics has an owner mandate for CUDA and Metal and meets it
without weakening that doctrine (ADR-SPARK-01): every device run emits a receipt with the twelve fields
**unchanged**; FrankenRobotics adds fields beside them (placement per stage, fingerprint digest, determinism class,
capacities) and never renames or drops one of the twelve.

**INV-SPARK-02:** every device result carries AE-01 to AE-12, a placement receipt and a fingerprint digest.
Verification: a schema check at the agent boundary. The agent boundary is the envelope (`frob.envelope/1`) that
every verb writes: no naked number reaches an agent, and a device number without its receipt is exactly a naked
number.

Upstream posture (work item FD-FSIM-09, priority P3): FrankenSim has no home for device receipts in its evidence
types today. Interim posture: local types that use the doctrine's field names. Switch-over rule: when FrankenSim
provides the types, replace the local ones; the field names do not change.

## Scope

In: the local `DeviceReceipt` type with the twelve fields and the FrankenRobotics additions; the boundary check in
the envelope builder; the test that our field names equal the doctrine's; the refusals. Out: producing each field
(backends, planner, check ledger, cancellation machinery); the generic claim product; the disclosure block of
performance claims.

## Technical approach

**Type (DESIGN; `frob-kernels::receipt`).**

```rust
// DESIGN: intent, not signatures. Field identifiers follow the doctrine verbatim.
struct DeviceReceipt {
    ae01_device_identity, ae02_driver_runtime, ae03_compiler_backend, ae04_kernel_source_hash,
    ae05_kernel_workload_identity, ae06_cpu_axes, ae07_reduction_determinism_policy,
    ae08_cpu_device_comparison,      // the check row: class attained, currency, worst disagreement
    ae09_retained_cpu_reference,     // symbol and identity of the CPU reference kernel(s)
    ae10_cancellation_outcome,       // executor-minted: none | requested, drained, finalized
    ae11_phase_attribution,          // compile, transfer, synchronization, device, retries
    ae12_go_no_go,
    // added beside the twelve, never in place of one:
    placement: PlacementReceipt,     // frob.placement/1: per stage requested and actual backend, fallbacks, bytes, syncs
    fingerprint: FingerprintRef,     // digest and identity
    determinism_class: Class, capacities: Capacities, retries: u32, guarded_fallback_fraction: Option<Ratio>,
}
```

**Where it is checked.** The envelope builder in `frob-verbs` classifies a result as a *device result* when its
tier is a device tier or any stage of its placement receipt ran on a device. For a device result it requires a
`DeviceReceipt` and validates:
1. all twelve AE fields present and non-empty (a field that does not apply carries an explicit `not-applicable`
   with a reason, never an omission);
2. the placement receipt present, with one row per stage and header fields (request mode, fingerprint digest,
   shape class, bucket, capacities, class attained, check currency per kernel);
3. the fingerprint reference present and equal to the placement header's digest;
4. AE-08 consistent with the check ledger: under `--require-current-check`, a kernel without a current check is
   `FROB-REF-605`; a device result *cited* as evidence without a current check is `FROB-REF-864`;
5. AE-10 minted by the executor (a dropped handle is not a cancellation receipt);
6. the class in the envelope's evidence block is no stronger than `determinism_class` (the weakest input wins).

**Failure.** A device result that fails 1, 2, 3, 5 or 6 is a defect in the producing verb, not a user error: no
envelope with `ok: true` is written; the verb returns an internal-family refusal (`9xx`, exit 9) naming the missing
field. The plan names no specific code for this condition; the code is assigned in the refusal registry when this
bead lands. A missing or stale fingerprint is `FROB-REF-606` (exit 6).

**Doctrine parity test.** A test reads the twelve field names from the doctrine file at the pinned FrankenSim
revision and compares them with the identifiers of `DeviceReceipt`; a rename or a dropped field on either side
fails. This is the mechanical form of "unchanged".

**Stored results.** The same validation runs when a device result is read back from the ledger for a report or a
comparison, so an older result that predates a field is shown as `incomplete evidence` and cannot be cited.

Determinism: the check is exact. Evidence: the receipt is what gives a device result its class; without it the
result has none.

## Acceptance criteria

- [ ] Every verb that can return a device result (`sim.run`, `spark.check`, `spark.probe`, `train.*`, `eval.*` on device tiers) emits a `DeviceReceipt` that passes the six validations; a schema-valid example of each is in the verb's examples.
- [ ] Removing any one AE field, the placement receipt or the fingerprint reference from a device result makes the envelope builder refuse it; twelve plus two planted omissions are each caught.
- [ ] The doctrine parity test passes at the pinned revision and fails on a planted rename.
- [ ] A CPU-only result is not asked for a device receipt; a mixed placement is.
- [ ] A stored device result without a receipt cannot be cited in a report as evidence.
- [ ] The invariants section of the `frob-kernels` contract lists INV-SPARK-02 with this check; the upstream work item FD-FSIM-09 is referenced with its interim posture and switch-over rule.

## Test plan

### Unit tests

`cargo test -p frob-verbs device_result_schema`, `-p frob-kernels receipt`:
- `requires_ae_placement_fingerprint`: fourteen fixtures, each missing one required part, all refused; the complete fixture accepted.
- `not_applicable_needs_reason`.
- `fingerprint_matches_placement_header`.
- `class_not_stronger_than_receipt`: an envelope claiming D1 over a receipt of D3 is refused.
- `cancellation_must_be_executor_minted`.
- `cpu_result_needs_no_device_receipt`; `mixed_placement_needs_device_receipt`.
- `doctrine_field_names_match`.
- Property test (INV-SPARK-02): for random device results built by the real backends on `batch-cpu` posing as a device tier in a test profile, serialization succeeds only with a complete receipt.

### End-to-end script and logging

`scripts/e2e/device_receipt.sh`: runs one small job per device-capable verb on each available backend with
`--json`, validates each envelope against the published schema with an independent validator, and prints the
twelve AE fields; then runs the fourteen planted-omission builds through the conformance harness. Logs per the
end-to-end standard: command lines, exit codes, wall times, the evidence block and the receipt's digest, one
`assert` per AE field and per addition, and a `summary` line with counts.

### Known answers and negative controls

Negative controls: the fourteen omissions; a receipt whose AE-08 claims a current check that the check ledger does
not hold (must be refused); a renamed AE field. Lanes: both backends; Linux and macOS; twice on one machine with
identical receipts apart from timings.

## Considerations

- The twelve names are FrankenSim's; this bead must not paraphrase them in code. The comments above describe each
  field's content, and the parity test is the authority.
- If OPEN-SPARK-1 (owner ratification of the annex design) stays open, device results also carry the label
  `exploratory`; that label is a field beside the receipt, not a replacement for it.
- When FrankenSim gains evidence types for device receipts, the local type is replaced and the parity test becomes
  a type identity.
