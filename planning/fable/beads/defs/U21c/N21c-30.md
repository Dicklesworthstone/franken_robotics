## Background

The plan's rule for every gate is that it must have at least one negative control: a planted defect the test must
catch, because "a gate that nothing can fail validates nothing". Spark's chapter lists twelve known answers, each
with the negative control that must be caught, and one more in its section on wide counts. The known answers are
measured by the mechanism beads; what tends to be lost is the *control*: someone writes the passing test and never
builds the failing variant. This bead makes the first six controls (those due at M0, behind GATE-SPARK-00, -01 and
-08 and the stride admission test) concrete, registered and re-runnable; the companion bead covers the later ones.

| # | Known answer | Expected | Negative control that must be caught |
|---|---|---|---|
| 1 | One dialect source for `K-cay-step` on three backends | Matches the Rust reference inside its determinism class | A prelude with contraction switched on |
| 2 | Contraction detector in `f32`: (1 + 2⁻¹²)·(1 + 2⁻¹²) − (1 + 2⁻¹¹) | 0 without contraction; 2⁻²⁴ with | The fused form itself |
| 3 | Double-float canaries | (1, 2⁻³⁰) for the error-free sum of 1 and 2⁻³⁰; (1 + 2⁻¹¹, 2⁻²⁴) for the error-free product of 1 + 2⁻¹² with itself | A build with fast math on |
| 4 | Strict predicate 2²⁴ < 2²⁴ + 1 | True in the exact and guarded kernels | The bare `f32` kernel answers false |
| 5 | Boundary corpus of 2 × 65,536 rows with exact ties | Exact kernel: zero errors, identical bytes on every backend. Guarded: zero errors after fallback | The bare `f32` kernel must mislabel at least one row |
| 6 | Stride conventions on a 2 × 2 view | Element 3 at [1, 1] | A verbatim stride copy reads element 12 |

Why each control is the right one. (2): the exact product 1 + 2⁻¹¹ + 2⁻²⁴ is a tie in `f32` and rounds to even,
1 + 2⁻¹¹, so the unfused expression is exactly 0, while a fused multiply-add keeps the 2⁻²⁴. (3): a compiler that
simplifies an error term algebraically returns (1, 0) and the accumulator silently loses its low word. (4), (5):
16,777,217 is not representable in `f32` and rounds to 16,777,216; in a recorded pilot the bare `f32` sign gave 452
false inclusions and 23,438 false exclusions on a 65,536-row grid dense near the boundary, identically on every
device. (6): a 2 × 2 contiguous `f32` view has strides (8, 4) in signed bytes and (2, 1) in unsigned elements;
copying (8, 4) as element strides onto a 16-element buffer reads element 8 + 4 = 12, in bounds, so nothing faults.

## Scope

In: one registry row and one reproducible mutant per control; the harness that activates a mutant and asserts that
the guarded test fails; the rule that mutants never ship; the end-to-end run. Out: the known-answer tests
themselves (probe, exact-kernel, dialect and stride beads); controls 7 to 12 and the wide-count control (N21c-31).

## Technical approach

**Registry rows** in `registries/negative_controls.toml` (the negative-control registry of `frob-conformance`):
`id`, `guards` (known answer, gate), `kind`, `plant`, `expected_detection`, `tier`, `backends`, `owner_test`.

| id | Plant (DESIGN) | Expected detection |
|---|---|---|
| `spark.contraction-prelude` | Annex test feature `mutant-contraction`: the per-backend prelude and compile options permit multiply-add fusion (on CUDA the option the production build switches off; on Metal a library compiled through the gateway's `library_with` in a non-safe math mode instead of `library`, which compiles under the safe mode; FACT about the gateway) | The three-backend comparison of `K-cay-step` over 10⁶ states reports a disagreement outside the class in the divergence ledger; GATE-SPARK-00's test fails |
| `spark.fused-form` | A test-only detector kernel that computes the expression with an explicit fused multiply-add through a mutant-only prelude macro | The probe returns 2⁻²⁴ (bit pattern 0x33800000), not 0; the device's attainable class is recorded as not D1 for that build; the dialect lint rejects the same source if placed in the kernel library (`FROB-REF-251`) |
| `spark.fast-math` | Annex test feature `mutant-fast-math`: the canary kernels compiled with fast-math relaxations | At least one canary fails; the device is refused for double-float kernels with `FROB-REF-609` |
| `spark.bare-f32-strict` | A test-only kernel `K-bare-pred` deciding the strict inequality by the sign of an `f32` residual | It answers false for 16,777,216 < 16,777,217; the build lint rejects a strict predicate in bare floating point in library sources (`FROB-REF-252`) |
| `spark.bare-f32-corpus` | `K-bare-pred` on the boundary corpus (two grids of 65,536 rows on a lattice of 2⁻²⁸ with exact ties) | At least one mislabelled row against the integer oracle (the recorded pilot: 23,890 on the dense grid); the corpus is thereby shown to discriminate |
| `spark.verbatim-strides` | A test-only converter that copies signed byte strides (8, 4) as unsigned element strides | Index [1, 1] reads element 12 where 3 belongs; the typed converter's test fails for the mutant |

**Harness.** `frob-conformance::negctl::run(id)` builds or selects the mutant, runs the `owner_test`, and passes
only if that test **fails in the expected way** (the expected refusal code, or the expected first differing value).
A mutant that survives is a failure of the control and blocks the gate it guards. Results are written to the
registry's run log with commit, fingerprint digest and backend.

**Mutants never ship.** Mutants are `mutant-*` cargo features of the annexes and of test-only crates. A workspace
lint fails if any `mutant-*` feature is enabled in an `apps/` release profile or is a default feature; mutant
kernels are not entries of the kernel library's registry and cannot be placed in a step plan.

**Per-backend applicability.** Controls 1 to 3 run on CUDA and on Metal; 4 and 5 on `batch-cpu`, both RTX 4090 and
Metal; 6 on the host. Where a mutant cannot be built on a backend (the gateway offers no non-safe mode in a given
release), the row records `not plantable` with the reason and the control is satisfied on the other backend only if
the gate's wording allows it; otherwise the gate stays open.

## Acceptance criteria

- [ ] Six rows exist in the negative-control registry with plant, expected detection, tier, backends and owner test.
- [ ] `negctl::run` reports each of the six as caught on every applicable backend, with the recorded first differing value: 2⁻²⁴ for the fused form; a canary pair other than (1, 2⁻³⁰) or (1 + 2⁻¹¹, 2⁻²⁴); `false` for the strict predicate; at least one mislabelled row; element 12.
- [ ] GATE-SPARK-00, GATE-SPARK-01 and GATE-SPARK-08 cannot be recorded as passed unless their controls' last runs were caught (the registry check enforces it).
- [ ] The no-ship lint fails on a planted `apps/` profile that enables a mutant feature.
- [ ] The mutants' sources live outside the kernel library and are rejected by the dialect lint if moved into it (controls 2 and 4).

## Test plan

### Unit tests

`cargo test -p frob-conformance negctl_spark_m0`:
- `detector_arithmetic_host`: in `f32` on the host, (1 + 2⁻¹²)·(1 + 2⁻¹²) rounds to 1 + 2⁻¹¹ and the difference is 0; `f32::mul_add` of the same operands gives 2⁻²⁴.
- `canary_expected_pairs_host`: two-sum(1, 2⁻³⁰) = (1, 2⁻³⁰); split product with splitter 4097 of (1 + 2⁻¹²)² = (1 + 2⁻¹¹, 2⁻²⁴).
- `bare_f32_predicate_wrong_host`: (16,777,216 as f32) < (16,777,217 as f32) is false.
- `verbatim_stride_reads_12`: on a 16-element buffer holding 0..15, strides (8, 4) as elements at [1, 1] give 12; converted strides (2, 1) give 3.
- `negctl_passes_only_on_expected_failure`: a `synthetic` control whose owner test passes is reported as *not caught*.
- `no_ship_lint`.

### End-to-end script and logging

`scripts/e2e/spark_negative_controls.sh --milestone m0 --backend all`: for each row, `cargo test -p
frob-conformance --test negctl -- <id>` on the host and, through the annex test binaries, on each device. Logs per
the end-to-end standard: the control id, the build features, the exact command line, exit code, the expected and
observed detection (refusal code or first differing value with bit patterns), backend and fingerprint digest, and a
`summary` line with caught and not-caught counts and the gates they guard.

### Known answers and negative controls

KA-525 to KA-530 and KA-532 with the values above; CX-216 (bare comparison), CX-218 (strides), CX-220 (canaries).
The bead is itself the registry of controls; its own control is `negctl_passes_only_on_expected_failure`. Lanes:
each device family; debug and release; twice on one machine.

## Considerations

- A device family that contracts multiply-adds even in its safe mode would make control 1 undetectable as a
  *difference between builds*; the detector (control 2) then reports contraction in the production build itself,
  which is a gate failure, not a control failure.
- The recorded pilot numbers (452 and 23,438) are context; the control requires only "at least one row".
- Mutant features widen the build matrix; they are built only by the conformance job.
