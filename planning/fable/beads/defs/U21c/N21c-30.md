## Background

The plan's rule for every gate is that it must have at least one negative control: a planted defect the test must
catch, because "a gate that nothing can fail validates nothing". Spark's chapter lists twelve known answers, each
with the negative control that must be caught, and one more in its section on wide counts. The known answers are
measured by the mechanism beads; what tends to be lost is the *control*: someone writes the passing test and never
builds the failing variant. This bead makes the first six controls (those due at M0, behind GATE-SPARK-00, -01 and
-08 and the stride admission test) concrete, registered and re-runnable; the companion bead covers the later ones.

| # | Known answer | Expected | Negative control that must be caught |
|---|---|---|---|
| 1 | One dialect source for `K-cay-step` on three backends | Matches the Rust reference inside its determinism class | A prelude with contraction switched on |
| 2 | Contraction detector in `f32`: (1 + 2⁻¹²)·(1 + 2⁻¹²) − (1 + 2⁻¹¹) | 0 without contraction; 2⁻²⁴ with | The fused form itself |
| 3 | Double-float canaries | (1, 2⁻³⁰) for the error-free sum of 1 and 2⁻³⁰; (1 + 2⁻¹¹, 2⁻²⁴) for the error-free product of 1 + 2⁻¹² with itself | The folded mutants (error term replaced by 0), which must be caught; also a build with fast math on, whose outcome is recorded per compiler (HYPOTHESIS that it breaks a canary; N21b-36) |
| 4 | Strict predicate 2²⁴ < 2²⁴ + 1 | True in the exact and guarded kernels | The bare `f32` kernel answers false |
| 5 | Boundary corpus of 2 × 65,536 rows with exact ties | Exact kernel: zero errors, identical bytes on every backend. Guarded: zero errors after fallback | The bare `f32` kernel must mislabel at least one row |
| 6 | Stride conventions on a 2 × 2 view | Element 3 at [1, 1] | A verbatim stride copy reads element 12 |

Why each control is the right one. (2): the exact product 1 + 2⁻¹¹ + 2⁻²⁴ is a tie in `f32` and rounds to even,
1 + 2⁻¹¹, so the unfused expression is exactly 0, while a fused multiply-add keeps the 2⁻²⁴. (3): a compiler that
simplifies an error term algebraically returns (1, 0) and the accumulator silently loses its low word. (4), (5):
16,777,217 is not representable in `f32` and rounds to 16,777,216; in a recorded pilot the bare `f32` sign gave 452
false inclusions and 23,438 false exclusions on a 65,536-row grid dense near the boundary, identically on every
device. (6): a 2 × 2 contiguous `f32` view has strides (8, 4) in signed bytes and (2, 1) in unsigned elements;
copying (8, 4) as element strides onto a 16-element buffer reads element 8 + 4 = 12, in bounds, so nothing faults.

## Scope

In: one reproducible plant per control, with the owner test and observable its seeded `Control` record names (the
record itself is written by N38b-05's seeding); the fast-math experiment; the driver that activates a plant and
asserts that the guarded test fails; the rule that mutants never ship; the end-to-end run. Out: the known-answer tests
themselves (probe, exact-kernel, dialect and stride beads); controls 7 to 12 and the wide-count control (N21c-31).

## Technical approach

**Controls as registry records.** Each control is a `Control` record of the program's one negative-control
registry, `crates/frob-conformance/registry/controls.toml` (BD-025's record, read by STD-TEST's loader; the alias
`registries/negative_controls.toml` names the same file, and a second physical copy or a private row format is a
lint failure): `id` (the `NC-` number), `seed`, `gate`, `kind`, `target`, `defect`, `expect`, and `feature` for a
`mutation` or `fixture` for a planted input. This bead writes no record: every control below is stated by a
known-answer row of N21-KA or a catalogue entry of N21-CX, so N38b-05's seeding tool, the only writer of the file,
writes its record (`seed = "KA-nnn"` or `"CX-nnn"`). What this bead supplies is what each record names: the plant,
cited by the KA cells and N21-CX's entries as `N21c-30:<label>` with the labels below; the owner test (`target`);
and the observable (`expect`, with the backends of its lane). The mapping from the field list earlier drafts used:
`guards` → `seed` and `gate`; `plant` → `defect` with `feature` (the `mutant-*` feature named below) or `fixture`;
`expected_detection` → `expect`; `tier` and `backends` → the lane stated in `expect`; `owner_test` → `target`.
N38b-05 seeds the CX entries first, and a KA row whose plant and target match an existing control reuses it
(the row gains that control's `NC-` number in `control.nc`), so a plant that a CX entry and a KA row both name
has one record, seeded by the CX entry (N21-CX states this for CX-216); whether the two bare-`f32` controls are
one record or two follows the same rule, since they share the plant `K-bare-pred` and differ in target.

| Plant label | Stated by → gate (`kind`) | Plant (DESIGN) | Expected detection (`expect`) |
|---|---|---|---|
| `spark.contraction-prelude` | KA-525 → GATE-SPARK-00, GATE-SPARK-02 (`mutation`) | Annex test feature `mutant-contraction`: the per-backend prelude and compile options permit multiply-add fusion (on CUDA the option the production build switches off; on Metal a library compiled through the gateway's `library_with` in a non-safe math mode instead of `library`, which compiles under the safe mode; FACT about the gateway) | The three-backend comparison of `K-cay-step` over 10⁶ states reports a disagreement outside the class in the divergence ledger; GATE-SPARK-00's test fails |
| `spark.fused-form` | KA-526 → GATE-SPARK-01 (`mutation`) | A test-only detector kernel that computes the expression with an explicit fused multiply-add through a mutant-only prelude macro | The probe returns 2⁻²⁴ (bit pattern 0x33800000), not 0; the device's attainable class is recorded as not D1 for that build; the dialect lint rejects the same source if placed in the kernel library (`FROB-REF-251`) |
| `spark.folded-eft` | CX-220 → GATE-SPARK-01 (`mutation`) | The mutant sources of N21b-36, `two_sum_folded` and `two_prod_folded` (the error term replaced by 0), selected through `--library conformance:folded-sum` and `:folded-prod` | Each fails the canary on every backend: the sum returns (1, 0), the product (1 + 2⁻¹¹, 0); the device is refused for double-float kernels with `FROB-REF-609`. | `spark.bare-f32-corpus` | CX-216, KA-530 → GATE-SPARK-08 (`mutation`) | `K-bare-pred` on the boundary corpus (two grids of 65,536 rows on a lattice of 2⁻²⁸ with exact ties) | At least one mislabelled row against the integer oracle (the recorded pilot: 23,890 on the dense grid); the corpus is thereby shown to discriminate |
| `spark.verbatim-strides` | CX-218, KA-532 → the gates N38b-05 resolves from CX-218's rule identifiers (KA-532 names none) (`mutation`) | A test-only converter that copies signed byte strides (8, 4) as unsigned element strides | Index [1, 1] reads element 12 where 3 belongs; the typed converter's test fails for the mutant |

**Harness.** `frob-conformance::negctl::run(id)` builds or selects the plant, runs the record's `target` test, and
reports `caught` only if that test **fails in the expected way** (the record's `expect`: the expected refusal
code, or the expected first differing value), by N38b-04's outcome rules: a surviving plant is `missed` and
blocks the gates the record names, a failure for another reason is `missed` (caught-unexpected), an unbuildable
plant is `stale`. It is the driver N38b-04's control runner uses for the Spark plants that live in annex
workspaces (DESIGN, requested of N38b-04, whose runner otherwise builds a plant only as a feature of the
conformance tier target): the core conformance crate cannot depend on an annex (INV-SPARK-01), so those plants
are built and run through the annex test binaries; the outcome lines enter the gate's receipt like any other control's, and `last_seen`
and the control history are written by the recording session (N38b-19), never here. The fast-math build is not a
control: its outcome is a HYPOTHESIS that may survive, and a control must be caught. It is a recorded experiment,
applied by the same driver, whose outcome per compiler identity (`caught` or `survived`) is logged with the
compiler identity and never blocks a gate; control 3 is carried by `spark.folded-eft` (N21-CX's CX-220 reads it
so; KA-527 and KA-528, whose cells state fast math, are asked to cite the folded mutants as their must-catch
control). Runs are logged with commit, fingerprint digest and backend.

**Mutants never ship.** Mutants are `mutant-*` cargo features of the annexes and of test-only crates. A workspace
lint fails if any `mutant-*` feature is enabled in an `apps/` release profile or is a default feature; mutant
kernels are not entries of the kernel library's registry and cannot be placed in a step plan.

**Per-backend applicability.** Controls 1 to 3 run on CUDA and on Metal (the folded mutants of control 3 also on
`batch-cpu`); 4 and 5 on `batch-cpu`, both RTX 4090 and
Metal; 6 on the host. Where a mutant cannot be built on a backend (the gateway offers no non-safe mode in a given
release), the run reports the control `stale` on that backend with the reason (N38b-04) and the control is
satisfied on the other backend only if the gate's wording allows it; otherwise the gate stays open.

## Acceptance criteria

- [ ] After N38b-05's seeding, each of the six plants is the plant of a `Control` record of `controls.toml` (BD-025's form) seeded from the CX entry or KA row that states it (KA-525, KA-526, CX-220, CX-216 with KA-529 and KA-530, CX-218 with KA-532), with this bead's owner test and observable; this bead writes no record, and the fast-math experiment has its plant and per-compiler log.
- [ ] `negctl::run` reports each of the six must-catch controls as caught on every applicable backend, with the recorded first differing value: a cross-backend disagreement for the contraction prelude; 2⁻²⁴ for the fused form; (1, 0) and (1 + 2⁻¹¹, 0) for the folded mutants; `false` for the strict predicate; at least one mislabelled row; element 12. The `spark.fast-math` experiment records `caught` or `survived` per compiler identity, and a survival does not block GATE-SPARK-01.
- [ ] GATE-SPARK-00, GATE-SPARK-01 and GATE-SPARK-08 cannot be recorded as passed unless their controls' last runs were caught (the registry check enforces it).
- [ ] The no-ship lint fails on a planted `apps/` profile that enables a mutant feature.
- [ ] The mutants' sources live outside the kernel library and are rejected by the dialect lint if moved into it (controls 2 and 4).

## Test plan

### Unit tests

`cargo test -p frob-conformance negctl_spark_m0`:
- `detector_arithmetic_host`: in `f32` on the host, (1 + 2⁻¹²)·(1 + 2⁻¹²) rounds to 1 + 2⁻¹¹ and the difference is 0; `f32::mul_add` of the same operands gives 2⁻²⁴.
- `canary_expected_pairs_host`: two-sum(1, 2⁻³⁰) = (1, 2⁻³⁰); split product with splitter 4097 of (1 + 2⁻¹²)² = (1 + 2⁻¹¹, 2⁻²⁴).
- `folded_eft_pairs_host`: the folded sum gives (1, 0) and the folded product (1 + 2⁻¹¹, 0), each different from the expected pair.
- `hypothesis_row_survival_does_not_block`: a `synthetic` fast-math experiment whose canaries survive is logged `survived` and leaves GATE-SPARK-01 recordable; the same survival of a must-catch control (a `synthetic` `Control` record) is `missed` and blocks it.
- `bare_f32_predicate_wrong_host`: (16,777,216 as f32) < (16,777,217 as f32) is false.
- `verbatim_stride_reads_12`: on a 16-element buffer holding 0..15, strides (8, 4) as elements at [1, 1] give 12; converted strides (2, 1) give 3.
- `negctl_passes_only_on_expected_failure`: a `synthetic` control whose owner test passes is reported `missed`, and one whose owner test fails with an observable other than `expect` is reported caught-unexpected, counted `missed`.
- `no_ship_lint`.

### End-to-end script and logging

`scripts/e2e/spark_negative_controls.sh --milestone m0 --backend all --seed <s>`: for each control,
`FROB_TEST_SEED=<s> cargo test -p frob-conformance --test negctl -- <label>` (the test target `tests/negctl.rs`
this bead adds) on the host and, through the annex test binaries, on each device; then the fast-math experiment
per compiler identity. Logs through the STD-E2E helper to `target/e2e-logs/spark_negative_controls/<utc>.ndjson`:
`ts`, `script`, `bead`, `step`, `event`, the seed as a decimal string; per control one `assert` of kind
`negative-control` with `nc` (the record's identifier), `ka` or `cx` (its seed), `gate`, `caught`, the build
features, the exact command line and exit code, the expected and observed detection (refusal code or first
differing value with bit patterns), backend and fingerprint digest; the fast-math outcome as an `assert` of
kind `check` whose `observed` is `caught` or `survived` with the compiler identity (`status: pass` for either, since
it blocks nothing); and a `summary` line with
`controls_caught`, `controls_missed` and `gates[{id, measured_ok, controls_caught}]` for GATE-SPARK-00, -01 and
-08, whose `measured_ok` stays false because the script runs no gate's passing entries and records nothing.

### Known answers and negative controls

KA-525 to KA-530 and KA-532 with the values above; CX-216 (bare comparison), CX-218 (strides), CX-220 (canaries).
The bead supplies these controls' plants; the harness's own control is `negctl_passes_only_on_expected_failure`. Lanes:
each device family; debug and release; twice on one machine.

## Considerations

- A device family that contracts multiply-adds even in its safe mode would make control 1 undetectable as a
  *difference between builds*; the detector (control 2) then reports contraction in the production build itself,
  which is a gate failure, not a control failure.
- The recorded pilot numbers (452 and 23,438) are context; the control requires only "at least one row".
- Mutant features widen the build matrix; they are built only by the conformance job.
