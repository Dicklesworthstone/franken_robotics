## Background

Exact kernels on devices use unsigned 32-bit integers (dialect rule 7), and 64-bit atomics cannot be assumed on
every backend. Counts are handled by 32-bit bins drained by the host. **Sums** wider than 32 bits, such as integer
sums of quantized values, need a different rule: they "are never accumulated by atomics. Each world writes its own
`u32` partial sum, and `K-seg-reduce` adds two-limb values in its fixed tree:
(lo, hi) + (lo′, hi′) = (lo + lo′ mod 2³², hi + hi′ + carry), with the carry computed by an unsigned comparison."
Digests are wrapping sums by definition and need neither rule.

`K-seg-reduce` is the library's one segmented-reduction primitive: a fixed-shape pairwise tree anchored at index 0
whose shape is a function of logical index only, so that a reduction gives the same result for every worker count,
batch size and backend; padding leaves hold the neutral element of the operation. One such primitive serves every
stage; no stage carries its own reduction.

Why not atomics: an atomic add on a 64-bit cell does not exist on one backend, and an atomic add of a wide value
split over two 32-bit cells is not atomic at all (a carry can be lost between the two updates). Why not floating
point: the sums are evidence (counts, exact totals, integer statistics) and must be class D0.

Known answer: (0xFFFFFFFF, 0) + (1, 0) = (0, 1). Gate clause: the two-limb reduce matches `u64` addition on 10⁶
random pairs.

## Scope

In: the two-limb operator completed on top of the operator slot that N21a-07 puts in the reduce tree: the addition
as the IR subprogram `det_add2` (which replaces the hand-written add of N21a-07 with identical bytes) and its
dialect emission; leaves from `u32` partials and two-limb per-world partials; signed quantities; the declared leaf
bound and leaf count in the manifest; the host-side reading; byte identity on `batch-cpu`, each RTX 4090 and

the first two-limb tests on `batch-cpu` (N21a-07, a dependency, registered by BD-152); histogram bins, the no-wrap
bound and the drain (N21c-39, N21c-40); the 64-bit feature gating (N21c-42).

## Technical approach

1. **Representation (DESIGN).** A two-limb value is a pair of `u32` words (lo, hi) in adjacent slots, denoting
   hi·2³² + lo. The kernel IR gets no new scalar type: the pair is `array<u32, 2>` and the operation below is a
   subprogram `det_add2` built from the existing exact operators of the IR's exact-integer math mode (N21a-17, a
   dependency: `addw`: wrapping add; `compare`: unsigned less-than; `select`).
2. **Addition.**
   - s_lo = addw(lo, lo′)
   - carry = select(s_lo < lo, 1, 0), an **unsigned** comparison: the low sum wrapped exactly when it is smaller
     than an operand
   - s_hi = addw(addw(hi, hi′), carry)
   The result is exact modulo 2⁶⁴. The dialect text uses unsigned types only; no signed arithmetic appears, so no
   undefined overflow is reachable.
3. **Leaves.** Each world writes its own partial sum into its own row, with ordinary (non-atomic) world-local
   arithmetic: a `u32` partial is the leaf (lo, 0). Where the plan-time bound shows that one world's partial
   could itself exceed 2³² − 1 within a chunk (chunk intervals × samples × largest quantized magnitude), the
   world keeps a two-limb partial updated with `det_add2`; no atomic is involved because only that world writes
   it.
4. **Signed quantities.** A signed quantized value is carried in two's complement: the leaf of a signed `u32`
   pattern x is (x, 0xFFFFFFFF) if its top bit is set, else (x, 0). Addition is unchanged; the host reads the pair
   as a signed 64-bit value.
5. **Reduce.** `K-seg-reduce` with operator `add2`: the same fixed tree, the same segment keys; the neutral
   element for padding is (0, 0). Because integer addition is associative, the tree shape cannot change the
   result; the fixed shape is kept so that the primitive stays single.
6. **Range.** A reduction over N leaves of at most 2³² − 1 each is below N·2³², which fits two limbs for every
   N ≤ 2³²; chained reductions across chunks are added on the host into `u64` (or wider) totals at the drain, as
   for histograms. The manifest of a kernel using `add2` declares the leaf bound and the leaf count so that the
   planner can check the range.
7. **Host and CPU reference.** `batch-cpu` runs the same two-limb Rust skeleton; the oracle in tests is native
   `u64` wrapping addition. The host reads (lo, hi) from the committed slab and forms hi·2³² + lo.

Class `exact`; determinism D0 on every backend; byte-identical outputs required, never a tolerance.

## Acceptance criteria

- [ ] `det_add2` returns (0, 1) for (0xFFFFFFFF, 0) + (1, 0) and matches native `u64` wrapping addition on 10⁶ random pairs, on `batch-cpu`, each RTX 4090 and Metal, with identical bytes.
- [ ] A segmented reduction of 8,192 leaves each equal to 0xFFFFFFFF returns (0xFFFFE000, 8,191), that is 35,184,372,080,640.
- [ ] Signed sums are correct across zero: the leaves −1 and +1 (patterns 0xFFFFFFFF and 0x00000001) reduce to (0, 0).
- [ ] Results are identical for 1 and 24 workers on `batch-cpu`, for every batch size and under slot permutation within a segment.
- [ ] The dialect source of the operator contains no 64-bit type, no atomic and no signed arithmetic; the dialect lint's rule 7 (N21a-10, a dependency) confirms it with zero findings, and a copy of the source with `uint64_t` planted is rejected with `FROB-REF-251`.
- [ ] The three negative controls below (signed-comparison carry, dropped carry, atomic two-cell add) are caught.

## Test plan

### Unit tests

`cargo test -p frob-kernels add2`:
- `add2_known_answer`: (0xFFFFFFFF, 0) + (1, 0) = (0, 1).
- `add2_carry_from_two_high_bits`: (0x80000000, 0) + (0x80000000, 0) = (0, 1).
- `add2_no_carry`: (1, 2) + (3, 4) = (4, 6).
- `add2_wraps_mod_2_64`: (0xFFFFFFFF, 0xFFFFFFFF) + (1, 0) = (0, 0).
- `add2_matches_u64_random`: 10⁶ pairs from an address-keyed stream against `u64::wrapping_add`.
- `reduce_all_ones_8192`: (0xFFFFE000, 8,191).
- `reduce_signed_pairs`: {−1, +1} → (0, 0); {−2³¹, −2³¹} → (0, 0xFFFFFFFF), that is −2³².
- `reduce_padding_neutral`: padding with (0, 0) leaves the result unchanged at capacities 8,192 and 16,384.
- Property test: associativity and commutativity of `add2` on random triples; a reduction equals the `u64` sum of its leaves for random segment layouts.

### Known answers and negative controls

Known answer of the wide-count section: (0xFFFFFFFF, 0) + (1, 0) = (0, 1). Negative controls: a carry computed by
a *signed* comparison (the case (0x80000000, 0) + (0x80000000, 0) then gives (0, 0) and must fail); the carry
dropped (the known answer then gives (0, 0)); an atomic two-cell add under contention (lost carries; must differ
from the oracle in the random-pair test). Lanes: three backends; worker counts; debug and release.

## Considerations

- Two limbs suffice for per-chunk reductions; totals across a long run are kept on the host, which is why the
  operator does not need a third limb.
- The operator costs three integer operations and a select per addition; reductions are a small share of the step.
- A backend that records 64-bit integers for every device family in a run could use them for this operator as an
  optimization; it would have to be bit-identical to the two-limb form and is not planned.
