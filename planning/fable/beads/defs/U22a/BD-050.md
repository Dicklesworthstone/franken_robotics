## Background
Contact, joint limits, the control programs of the reflex layer and the certificates of the proof layer all need the same four operations on a convex cone: a product that makes the cone "the set of squares", a spectral decomposition, the Euclidean projection, and a barrier. This bead gives `frob-algebra` (layer 1, tier Solid) one `Cone` abstraction with those operations and the three symmetric cones that occur in the project:

- the nonnegative orthant: joint limits, actuator boxes, multipliers of linear inequalities;
- the second-order cone {(x₀, x̄) : ‖x̄‖ ≤ x₀}: Coulomb friction. At a contact frame the impulse γ = (γₙ, γₜ) lies in 𝒦_μ = {‖γₜ‖ ≤ μ·γₙ}, which is a linear image of the second-order cone; the second-order cone is the cone of squares of the spin-factor Jordan algebra;
- the positive-semidefinite cone: the pseudo-inertia of a rigid body, sum-of-squares certificates, common Lyapunov matrices in gait analysis.

Reason for one abstraction (DESIGN): one kernel family then serves physics and control, and one dual-certificate format serves every infeasibility report. With three hand-written projections in three crates, the contact solve, the baseline controller and the certificate checker could disagree about whether a force is admissible. Alternatives rejected: (a) a friction pyramid (the box |γₜ₁| ≤ μ·γₙ, |γₜ₂| ≤ μ·γₙ): it admits (μ·γₙ, μ·γₙ), of norm √2·μ·γₙ, which is 41% of traction that does not exist along the diagonals; (b) an external conic library: none is admitted, and the determinism rules (no fused multiply-add, no trigonometric calls, identical arithmetic on CPU and devices) require the arithmetic to be ours; (c) per-consumer closed forms without the Jordan structure: the interior-point solver (BD-115) needs the product, the spectrum and the barrier, not only the projection.

The four-dimensional contact cone (normal, two tangential, spin) is one more linear image of the second-order cone and is added at M2 by the contact work (BD-154) on the wrapper this bead provides. The device kernels for cone setup and evaluation are BD-153; this bead is their host reference.

## Scope
In: the trait; the three instances; the generic linear-image wrapper and the three-dimensional friction cone 𝒦_μ with its dual 𝒦_{1/μ} and closed-form projection; exact membership tests; the law tests of the cone row of the Marrow law table; the planted mutants.

## Technical approach
**The trait (DESIGN sketch; fixes intent, not signatures).**
```rust
/// A symmetric cone, by its Jordan algebra.
pub trait Cone {
    type Point;
    fn jordan(a: &Self::Point, b: &Self::Point) -> Self::Point;   // a ∘ b
    fn identity(&self) -> Self::Point;                            // e, with x ∘ e = x
    fn spectral(a: &Self::Point) -> Spectrum;                     // eigenvalues λᵢ and idempotents cᵢ
    fn project(a: &Self::Point) -> Self::Point;                   // Euclidean projection onto the cone
    fn barrier(a: &Self::Point) -> f64;                           // −ln det(a), +∞ outside the interior
    fn rank(&self) -> usize;                                      // number of eigenvalues
    fn contains(a: &Self::Point) -> Membership;                   // Inside | Boundary | Outside, exact where inputs are exact
}
```
Scalars are generic over `f64`, `f32` and the crate's exact rational type. Only +, −, ×, ÷ and √ are used; no trigonometric call and no fused multiply-add, so the same expressions can be emitted as kernels. File layout: `crates/frob-algebra/src/cone/{mod.rs, orthant.rs, soc.rs, psd.rs, image.rs, friction.rs}`.

**Nonnegative orthant ℝⁿ₊.** a ∘ b = (aᵢ·bᵢ); e = (1, …, 1); eigenvalues are the entries, idempotents the coordinate vectors; P(x) = (max(xᵢ, 0)); barrier −Σ ln xᵢ; rank n; self-dual.

**Second-order cone 𝓛ⁿ = {(x₀, x̄) ∈ ℝ × ℝⁿ⁻¹ : ‖x̄‖ ≤ x₀}.** Product (x₀, x̄) ∘ (y₀, ȳ) = (x₀·y₀ + x̄·ȳ, x₀·ȳ + y₀·x̄); e = (1, 0). Eigenvalues λ± = x₀ ± ‖x̄‖; idempotents c± = ½·(1, ±x̄/‖x̄‖), with the fixed convention x̄/‖x̄‖ := first coordinate axis when x̄ = 0 (any unit vector is correct; a fixed one keeps results reproducible). det(x) = λ₊·λ₋ = x₀² − ‖x̄‖²; barrier −ln(x₀² − ‖x̄‖²); rank 2; self-dual. Projection P(x) = max(λ₊, 0)·c₊ + max(λ₋, 0)·c₋, that is: x itself if ‖x̄‖ ≤ x₀; 0 if ‖x̄‖ ≤ −x₀ (x lies in the polar cone); otherwise ½·(x₀ + ‖x̄‖)·(1, x̄/‖x̄‖). Exact membership needs no square root: x₀ ≥ 0 and x₀² ≥ x̄·x̄.

**Positive-semidefinite cone 𝕊ⁿ₊.** X ∘ Y = ½·(X·Y + Y·X); e = I; spectrum from a symmetric eigendecomposition by cyclic Jacobi rotations in a fixed sweep order (deterministic; DESIGN cap n ≤ 32 on the host, since the uses are 4×4 pseudo-inertias and small Lyapunov and sum-of-squares blocks); P(X) = Σ max(λᵢ, 0)·vᵢ·vᵢᵀ; barrier −ln det X; rank n; self-dual under ⟨X, Y⟩ = tr(X·Y). Exact membership for rational matrices is an LDLᵀ factorization with nonnegative pivots (strictly positive for the interior), with no eigenvalues computed.

**Linear images and the friction cone.** `LinearImage<C, T>` represents {x : T·x ∈ C} for an invertible linear map T, with dual cone {y : T⁻ᵀ·y ∈ C*}. The friction cone is 𝒦_μ = {(γₙ, γₜ) : ‖γₜ‖ ≤ μ·γₙ}, the image under (γₙ, γₜ) ↦ (μ·γₙ, γₜ) of membership in 𝓛³; its dual is 𝒦_{1/μ} = {(a, c) : ‖c‖ ≤ a/μ}, equivalently a ≥ μ·‖c‖. The Euclidean projection onto 𝒦_μ is not the conjugate of the second-order projection by T (T is not orthogonal), so it has its own closed form, for x = (n, t): (i) if ‖t‖ ≤ μ·n, P(x) = x; (ii) if μ·‖t‖ ≤ −n, P(x) = 0; (iii) otherwise P(x) = s·(1, μ·t/‖t‖) with s = (n + μ·‖t‖)/(1 + μ²). The wrapper is what the four-dimensional contact cone {‖(λ_t1, λ_t2, λ_s/r)‖ ≤ μ·λ_n} (r the effective patch radius) reuses at M2.

**Polar and dual.** For a closed convex cone 𝒦 the dual is 𝒦* = {y : ⟨y, x⟩ ≥ 0 for all x ∈ 𝒦} and the polar is 𝒦° = −𝒦*. Each instance exposes `dual()` and `project_polar(x) = x − P(x)`.

**Laws tested (tier G0).**
1. Projection: P(P(x)) = P(x).
2. Moreau decomposition: x = P_𝒦(x) + P_𝒦°(x) with the two parts orthogonal.
3. The three projection conditions (theorem card T-07): P(x) ∈ 𝒦; P(x) − x ∈ 𝒦*; ⟨P(x), P(x) − x⟩ = 0.
4. Jordan algebra: a ∘ b = b ∘ a; (a ∘ b) ∘ a² = a ∘ (b ∘ a²); x ∘ e = x; x = Σ λᵢ·cᵢ; cᵢ ∘ cⱼ = δᵢⱼ·cᵢ; Σ cᵢ = e; x ∈ 𝒦 exactly when every λᵢ ≥ 0; every square x ∘ x is in 𝒦.
5. Barrier: +∞ outside the interior; barrier(t·x) = barrier(x) − rank·ln t for t > 0; its gradient equals −x⁻¹ (checked by central differences).
6. Linear image: the four-dimensional contact cone is the image of the second-order cone under its stated linear map (asserted on the wrapper with the three-dimensional cone here; the four-dimensional row is completed by BD-154).
Tolerances are those of the Marrow law gate: on 10⁶ cases per law plus the boundary set (apex, points on the boundary, points in the polar cone, magnitudes from 10⁻³⁰ to 10³⁰, x̄ = 0), at most 64 ulp in `f64` and at most 16 ulp in `f32` for single operations. The reference is exact: rational inputs, with ‖x̄‖ replaced by a rational witness r satisfying r² = x̄·x̄ (inputs drawn from Pythagorean tuples), and LDLᵀ for semidefinite membership.

**Evidence.** Determinism: D0 on the exact path; D2 for the floating paths (bit-identical run to run and across worker counts). Results of the law run are `Tested`.

### End-to-end script and logging
No verb is defined on cones. `scripts/e2e/marrow_cones.sh` runs `cargo test -p frob-algebra --test cones` in debug and release, twice each, and converts the results to the shared newline-delimited JSON format under `target/e2e-logs/marrow_cones/<utc>.ndjson` with a transcript: one `assert` line per law and cone (cases run, worst ulp error against its bound, the input that produced it), one per mutant (which law caught it and at which input), `metric` lines for wall time, the commit and toolchain; on failure the first violating input in exact form and the law's residual; a `summary` line with assertions passed and failed and GATE-MARROW-01 as the gate touched. The gate row itself is written by the full-table run of the Marrow law bead.

## Considerations
- The friction cone's dual is 𝒦_{1/μ}, not 𝒦_μ; the two coincide only at μ = 1. Every certificate downstream (an infeasible force demand is proved by a vector in the dual cone) depends on this, which is why a dedicated mutant guards it.
- The semidefinite instance is a host reference of small size. Larger semidefinite blocks, if a later gate needs them, are a scope conversation, not a silent extension.
- At the apex and on the boundary the idempotents are not unique; tests compare projections and reconstructed points, never the idempotents themselves.
- The kernels of BD-153 must reproduce `project` bit for bit in `f32` on `batch-cpu`; any change to the order of operations here changes kernel digests and is a breaking change of the contract.
- The projection identities become a certified theorem card later (per-case polynomial identities with a witness for the norm); until then they are `Tested`.
