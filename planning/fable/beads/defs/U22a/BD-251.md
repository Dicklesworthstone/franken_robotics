## Background
By M3 every archetype has a baseline controller, and each of them solves cone programs every tick. This bead makes three promises of the reflex layer hold across all of them and records the gate that says so.

- **Infeasibility is an answer.** An infeasible program returns its active inequalities, its residuals, a dual certificate and the prescribed fallback; the task records every fallback. The certificate is a vector y with Aᵀy in the dual cone and bᵀy < 0; it proves that no solution exists because 0 ≤ ⟨Aᵀy, x⟩ = yᵀb < 0 would follow. Proof obligation PO-REFLEX-03: every infeasibility certificate checks in exact rational arithmetic, and the offline auditor re-checks each emitted certificate.
- **Every command has a layer.** Invariant INV-REFLEX-01: every command that reaches a driver records the layer that produced it, and every fallback is a telemetry event with its reason.
- **The wrapper adds nothing.** Proof obligation PO-REFLEX-02: a zero residual reproduces the baseline's digests bit for bit in class D2.

Gate GATE-REFLEX-05 (Known answer, M3; the seed's done-condition): PO-REFLEX-02; every command has a layer record; a planted infeasible program yields a certificate that checks exactly and a fallback event; a run that needs commands beyond the envelope is marked `actuator-infeasible`.

What is new here beyond the parts: the certificates leave the process. At M1 a certificate is checked exactly inside `frob`; from this bead on, each emitted certificate travels in a certificate bundle and is accepted by the independent auditor binary on a machine with neither the agent nor a GPU, and the registered mutations of it are rejected. That is what turns "our solver says infeasible" into a statement a third party can check without trusting the solver. Decision that governs it (ADR-REFLEX-02): one symmetric-cone solver with a fixed iteration count and a mandatory optimality check, so one dual-certificate format serves every infeasibility report.

Tier: Solid. Crate: `frob-control`, with the bundle path through the proof crates.

## Scope
In: adoption of the program layer, layer records and fallback events by every class controller of the archetype set; the certificate record's export as bundle entries and their audit; the program-instance record that makes a certificate checkable offline; the conformance audit across controllers; the gate script and the gate row.
Out: the program layer, whole-body program, records and wrapper themselves (N22a-08, N22a-14, N22a-15, N22a-16); the solver (BD-115); the checker kinds in the auditor (BD-132 and the conic kind named in `needs`); the class controllers (BD-116, BD-117 and the archetype unit's beads); skill and shield uses of the same certificates (BD-336, BD-338).

## Technical approach
**Adoption audit.** A registry `registries/control_programs.toml` lists, per controller class, every program it solves: name, form (feasibility or program), cones used, iteration count, fallback. A test enumerates the controllers of all eighteen archetypes and asserts: each program is declared; each solve site consumes the must-inspect outcome; each has a fallback or the controller is refused at synthesis (FROB-REF-424); each emits layer tags and fallback events through the common path. A controller that solves an undeclared program fails the audit.

**Program-instance record.** For every `infeasible` outcome that is reported outside the process (a `not-synthesizable` witness; a fallback event that a report cites), the instance is stored: the program's structure hash, and the exact rational values of its data (A, G, b, h) as they were at that solve, with the row and cone names. Programs here have tens to a few hundred rows, so an instance is a few kilobytes; identical instances are deduplicated by hash. The record is what lets the auditor check the certificate with no simulator.

**Certificate bundle entries.** Each certificate becomes one entry of a `.frobcert` bundle:
- claim: "the program instance with hash H has no feasible point" (class of claim: Known answer about a stated program; no quantifier over designs or worlds);
- proof kind: `lp-farkas` when every cone block is an orthant (boxes, planar friction), `conic-farkas` when a second-order block is present;
- witness: the rational vector (y, z);
- checking rule, executed by the auditor in exact arithmetic: z in the dual cone block by block (for a second-order block: first component nonnegative and its square at least the scaled sum of squares of the rest); Aᵀ·y + Gᵀ·z = 0 exactly; bᵀ·y + hᵀ·z < 0 strictly; all hashes consistent; the proof kind known and enabled.
- evidence class: `Certified` for the instance. A report that draws a conclusion about a design from it inherits the weakest class among the instance's inputs (the model, the cards, the friction bound).
The auditor is the independent binary of the proof chapter (standard library only); `frob-control` never links it. `frob prove verify <bundle>` runs it; a run's certificates are collected by `frob prove bundle --run <id> --kind control-program`.

**Mutation corpus (the registered mutations the auditor must reject).** For each proof kind in use here, at least three: the dual vector nudged outside its cone by one unit in the last retained digit; the separation value made zero by scaling one row; a certificate attached to a different program instance (hash mismatch); an unknown proof kind with consistent hashes. One specimen per kind must be accepted.

**The gate's four clauses on running systems.**
1. *Zero residual.* The smoke battery under the baseline and under the wrapper with a zero residual: state digests equal at every checkpoint, per archetype and tier.
2. *Layer records.* For every episode of the smoke battery: layer counters sum to control ticks; the conservation laws of fallback events hold.
3. *Planted infeasible program.* A scripted event makes a program infeasible in mid-run (a payload added to the quadruped that the knee torque boxes cannot carry; an arm asked for a tool force beyond its torque limits): the outcome is `infeasible`, the fallback event references a certificate, the certificate is bundled and the auditor accepts it, the mutated bundles are rejected, and the controller's command during the event is the declared fallback.
4. *Beyond the envelope.* A task that can be completed only by requesting more than the continuous envelope for longer than the card's duty rating (a loaded climb held for 12 s at 1.3 times continuous torque against a 5 s rating): the run is marked `actuator-infeasible` and fails the engineering-constraint class of its verdict.

**Gate record.** Row GATE-REFLEX-05 with measured values: digest comparisons run and equal; episodes and ticks audited; certificates emitted, accepted and mutations rejected; marked runs; commit, fingerprint, seeds.

**Determinism and evidence.** Clause 1 is a G5 determinism test in class D2; clauses 2 to 4 are known-answer tests. Certificates are `Certified`; everything else `Tested`.

## Acceptance criteria
- [ ] GATE-REFLEX-05 passes and is recorded with measured values (the seed's done-condition): all four clauses, on the referee and on `batch-cpu`, for every archetype whose baseline exists at M3.
- [ ] The adoption audit passes for all controller classes: every program declared, every outcome inspected, every program with a fallback; a planted undeclared solve site fails the audit.
- [ ] PO-REFLEX-03: 100% of certificates emitted during the gate runs are accepted by the offline auditor on a second machine with no GPU and no `frob` daemon; every registered mutation is rejected (zero false accepts); at least one specimen per proof kind is accepted.
- [ ] No `infeasible` outcome is reported outside the process without a stored instance record and a bundle entry; an `unconverged` outcome never produces a bundle entry.
- [ ] The planted infeasible program's fallback event carries the certificate reference and the binding set, and the command at that tick is the declared fallback (verified from the control-record chain).
- [ ] The overload run is marked `actuator-infeasible`; the same task with a stronger actuator card is not.
- [ ] The gate script is idempotent, exits non-zero on any failed clause, and writes the structured log and the gate row.

## Test plan
### Unit tests
- `control_program_registry_matches_controllers` (the adoption audit, over all archetypes).
- `instance_record_round_trip_exact` (rationals reproduce the stored floats exactly).
- `bundle_entry_accepted_by_auditor` and `mutations_rejected_{nudged_cone, zero_separation, wrong_instance, unknown_kind}` per proof kind.
- `unconverged_never_bundled`.
- `infeasible_report_requires_instance_and_bundle` (constructing an external report from an `infeasible` outcome without them does not compile or is refused at the boundary).
- `fallback_command_is_declared_fallback` (control-record chain inspection on the planted run).
### End-to-end script and logging
`scripts/e2e/reflex_control_programs.sh` (plain shell; seeds explicit; idempotent):
1. `frob sim run --tier batch-cpu --battery smoke --controller baseline --seed 1 --json`, then the same with `--controller baseline+residual:zero`; compare the per-world digest lists.
2. `frob telemetry summary <run> --json` for each run: assert counters and conservation.
3. `frob sim run --tier referee --design e2e-quad --task stand-10s --event add-payload:fixtures/reflex/payload_heavy.json@2s --seed 3 --json`; `frob telemetry failures <run> --json` to read the fallback events; `frob prove bundle --run <run> --kind control-program --out <b>`; `frob prove verify <b>` (expect accept); `frob prove verify` on each mutated bundle (expect reject).
4. The arm variant of step 3 on the arm-on-base archetype.
5. `frob eval run --task loaded-climb-12s --design e2e-quad --seed 3 --json`: assert the flag `actuator-infeasible`, the joint and durations, and the failed engineering class; repeat with the stronger card and assert no mark.
6. Write the gate row.
Logging through the shared helper to `target/e2e-logs/reflex_control_programs/<utc>.ndjson` with a transcript: `ts`, `script`, `bead`, `step`, `event`, exact command line, exit code, wall time, the envelope's evidence block (claim, class, tier, determinism, identities, seed), digests with the first differing world and checkpoint, counters, each certificate's hash, kind and auditor verdict, the overload durations against the ratings with units, and on failure the artifact paths (run, bundle, mutated bundle, envelope). Final `summary`: assertions passed and failed, `gates: ["GATE-REFLEX-05"]`.
### Known answers and negative controls
- KA-556 (the friction certificate y = (0.5, −1), yᵀb = −5 N: used as the accepted specimen of the linear kind, since a planar cone is polyhedral), KA-557 (zero residual: digests equal the baseline's).
- Counterexample carried: CX-235 (an unconverged run proves nothing).
- Negative controls: the four certificate mutations; the nonzero-bias residual (digests must differ); a controller with events suppressed (clause 2 fails); a task that needs overload evaluated with the tracker on delivered torque (clause 4 would pass wrongly; the fixture catches it).
- Determinism lanes: clause 1 twice on one machine, across worker counts, across batch compositions; the auditor's verdicts identical on two machines.

## Considerations
- Until the conic proof kind is admitted, only linear certificates can be audited offline; the gate's planted cases are chosen so that at least one is linear (a torque-box certificate), and conic ones are checked in process and reported as `Certified (in-process)` with the gap named. This is a stated partial state, not a pass of the full obligation.
- Certificates are about program instances. The step from "this instance is infeasible" to "this design cannot do the task" is made by the report that cites it and carries the report's class, not the certificate's.
- The gate is blocked by the open question on the residual's authority only in that ρ must be fixed before the zero-residual runs are recorded; clause 1 itself does not depend on ρ.
- Audit cost: a few hundred certificates per gate run, each checked in microseconds; the instance records dominate storage and are deduplicated.
