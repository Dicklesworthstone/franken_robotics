## Background
A controller that only works on privileged simulator state is not a result. The plan's rule is that every evaluation can run with `--state estimated` or `--state privileged`, and the difference is reported. This bead makes that switch real: two implementations of the `StateSource` trait, a wall between what an estimator may read and what the simulator knows, a rule for packets that arrive late, and the report that puts the two runs side by side.

Three statements of the plan are implemented here.
- **Namespaces.** Truth, measurements, belief and policy observations are separate namespaces with declared access (a decision of the sensing chapter: the commonest silent defect in learned control is a leak of simulator truth). The filter reads measurements and writes belief; a baseline controller reads belief, or truth when the run says `privileged`; a learned policy reads policy observations.
- **Out-of-sequence measurements.** An out-of-sequence measurement may update the filter's future outputs; decisions already taken and the observation actually delivered at each decision instant are preserved in the record.
- **A missing sensor is a refusal.** An estimated-state run that lacks a sensor the filter needs is refused (FROB-REF-464), with the repairs "add the sensor, or run privileged and say so".

Why it matters to the program: baseline controllers can mask design flaws or create false ones (risk RISK-17, medium); the earliest signal is disagreement between estimated-state and privileged-state runs. Alternatives rejected: a single code path with a flag that swaps arrays (nothing then prevents a controller from reading truth in estimated mode); rewriting history when a late packet arrives (a replay would then show decisions the controller never made); silently running privileged when a sensor is missing (the result would be labelled as something it is not).

Tier: Solid. Crate: `frob-control`, against the traits of `frob-dyn` and the observation service of `frob-sense`.

## Scope
In: `PrivilegedState` and `EstimatedState`; namespace types and the access rule; the sensor-requirement check and its refusal; the history buffer and the out-of-sequence rule; the decision record; filter state inside checkpoints and the restore set; the paired difference computation and its flags.
Out: the filter (BD-114); scoring against truth (N22a-02); the verb flags on `eval.run` and `sim.run` and the report rendering (other units; this bead supplies the library and the data); lockstep execution on batched tiers (N22a-13); the causal-policy and noninterference tests of the sensing chapter, which test learned policies (BD-119, BD-215).

## Technical approach
**Namespaces as types (DESIGN).** Four zero-cost wrappers in `frob-dyn`: `Truth<T>`, `Measured<T>`, `Belief<T>`, `PolicyObs<T>`. A function that takes `Measured` cannot be handed `Truth`. `EstimatedState` is constructed from the observation service's delivered-packet handle only; its type holds no reference from which truth can be reached. `PrivilegedState` is constructed from the truth handle and stamps every state view with `kind = Privileged`. The scorer of N22a-02 is the only Reflex code that takes both.

**`EstimatedState`.** Wraps one `Estimator` (the invariant filter, or the comparator) and implements `StateSource`:
1. `required_sensors()` returns the filter's needs: one IMU on the base; an encoder on every joint between the base and each foot; a contact switch (or a declared contact-detection source) per foot; for a wheeled base, wheel encoders. The list comes from the filter manifest and the model, not from a table per robot.
2. Admission: before a run, the list is compared with the design's sensor suite. A missing role is refusal FROB-REF-464 ("an estimated-state run lacks a sensor the filter needs"), exit code 3, with `pointer` at the missing role, and repairs in order: add the sensor to the design (as a typed edit naming the body and the sensor card); run with `--state privileged` and accept the label.
3. `update(delivered, at)` feeds every packet delivered up to the control instant `at`, in timestamp order, into the estimator; `state()` returns the belief with its covariance and error convention.

**Out-of-sequence packets.**
1. The source keeps a ring of snapshots (filter state, covariance and the inputs applied since) covering the largest declared sensor latency plus one control period. If the declared latencies cannot be covered by the configured ring, the run is refused at admission by the sensing chapter's refusal for history buffers that cannot cover the declared window.
2. A packet whose timestamp t_m is earlier than the newest processed timestamp is applied by rolling back to the last snapshot at or before t_m, inserting the packet, and re-applying the later packets in timestamp order. The result from t_m onward is bit-identical to a filter that had received the packets in timestamp order.
3. A packet older than the ring is not applied; an event `oosm-out-of-window` records its sensor, timestamp and age. It is never dropped silently.
4. **The decision record.** At every control instant the source appends an immutable row: the instant, the digest of the belief handed to the controller, the digest of the delivered observation, and (from the controller) the digest of the command. Re-processing after a late packet changes the filter's present and future outputs and never touches earlier rows. Replay reproduces the rows, so "what the controller knew when it decided" is always recoverable.

**Checkpoints.** The estimator state, covariance, snapshot ring and the pending-packet cursor are part of the stage's `save` blob, hence of the restore set of the transactional step and of every checkpoint. A restore followed by the same packets gives byte-equal beliefs.

**The estimated-versus-privileged report.** For an evaluation run in both modes on the same world addresses, design, scene, task and controller:
1. Each metric of the scorecard (success, task score, distance traversed, energy, peak tracking error) is reported as value under estimated state, value under privileged state, and their paired difference with its interval (the pairing is by world address).
2. Flags: `privileged-only` when the requirement verdict passes under privileged state and fails under estimated state on the paired lower bound; `estimator-limited` when the difference in the primary metric exceeds the declared tolerance while both pass; `overconfident` and `drifting` carried from the scorer.
3. A report from a single mode states the mode in its header and prints the other column as `not run`. A privileged-only result may not be cited as a controller result without that header.
The library returns this as a typed record; rendering belongs to the report verbs.

**Determinism and evidence.** Class D2 with the run. All outputs are `Tested`; the state-source kind and the filter manifest hash are fields of the result's identity block.

## Acceptance criteria
- [ ] Type-level wall: a compile-fail test shows that `EstimatedState` cannot be constructed from, or handed, a `Truth` value.
- [ ] Runtime wall: changing a truth-only quantity that alters no delivered packet (a world-frame offset of the whole scene) leaves every belief byte-identical.
- [ ] A quadruped design with its IMU removed is refused for `--state estimated` with FROB-REF-464 naming the missing role and listing both repairs; the same design runs with `--state privileged` and its result header says so.
- [ ] A packet delivered three control periods late changes beliefs from its timestamp onward exactly as in-order delivery would (byte-equal), and the decision-record rows of the earlier instants are unchanged.
- [ ] A packet older than the ring raises `oosm-out-of-window`; none is dropped without an event (the count of packets in equals applied plus evented).
- [ ] Checkpoint at an arbitrary tick, restore, continue: beliefs and decision records are byte-equal to the uninterrupted run, including with a late packet pending at the checkpoint.
- [ ] On a planted controller that feeds back absolute world position (unobservable to the filter), the paired report sets `privileged-only`; on the `hold` controller it sets no flag and the differences are zero within their intervals.

## Test plan
### Unit tests
`crates/frob-control/tests/state_source.rs` and `crates/frob-dyn/tests/ui/` for compile-fail cases; real filter and real packet queues; fixtures labelled `synthetic` where they are.
- `estimated_cannot_take_truth` (compile-fail); `belief_independent_of_truth_only_change`.
- `missing_imu_refused_464`; `missing_foot_switch_refused_464`; `privileged_runs_and_is_labelled`.
- `oosm_equals_in_order_from_timestamp`; `oosm_preserves_past_decisions`; `oosm_out_of_window_event`; `packet_conservation`.
- `checkpoint_restore_belief_bytes`; `checkpoint_with_pending_late_packet`.
- `paired_report_flags_privileged_only`; `single_mode_report_marks_other_not_run`.
### End-to-end script and logging
`scripts/e2e/reflex_state_source.sh`: on the referee smoke world under the built-in `hold` controller, runs `frob sim run --tier referee --state estimated --seed 7 --json` and the same with `--state privileged`, then a run with a scripted late IMU packet, then the design with its IMU removed (expecting exit 3 and FROB-REF-464). It asserts the header's state-source field, the equality or inequality of digests as stated above, and the refusal payload. Logging through the shared helper to `target/e2e-logs/reflex_state_source/<utc>.ndjson` with a transcript: `ts`, `script`, `bead`, `step`, `event`, exact command line, exit code, wall time, the envelope's evidence block (class `Tested`, tier `referee`, determinism, identities including the filter manifest hash and state-source kind, seed), belief and decision-record digests with the first differing row on mismatch, the refusal's code, pointer and repairs, and a `summary` line. Logs carry digests and counts, never scene contents.
### Known answers and negative controls
- No numbered known answer is owned here; the bead supplies the second trigger of FROB-REF-464 and the mechanism behind the plan's sentence on preserved decisions.
- Negative controls: an estimator handed truth through a back door (the runtime wall test must change); a late packet applied by overwriting past rows (the decision-record assertion fails); a late packet applied at arrival time instead of at its timestamp (beliefs differ from the in-order run); a silent fallback to privileged state when a sensor is missing (the header assertion fails).
- Metamorphic: permuting the arrival order of packets with distinct timestamps inside the ring leaves beliefs after the last packet byte-identical.
- Determinism: twice on one machine; debug and release; restore at three adversarial instants (just after a packet is queued, just before a control instant, with a late packet pending).

## Considerations
- The ring's depth is a memory cost per world: 15 + 3·k_max states squared per snapshot. On batched tiers it is a capacity of the shape class (N22a-13).
- Rolling back re-linearizes; the invariant filter's constant error dynamics make the re-propagated covariance equal to the in-order one, and the test holds it to bytes. The comparator is held to the same test.
- The paired report needs both runs to be class D2 on one device family, or it is labelled `paired-by-address` under the determinism rules.
- Policies trained by the learning chapter have their own observation-access tests; this bead covers hand-specified controllers and the estimator.
