## Background
The estimator of the reflex layer is only trustworthy if an agent can look at what it did on a particular run: how far it drifted, whether its uncertainty was honest, which contacts it distrusted, and how a conventional filter would have done on the same data. The plan gives that a verb: `control.estimate` replays a run's packets through the filter and its comparator. It is a `read` verb: it changes nothing, spends a negligible amount of compute, and answers from what the ledger already holds. It is also the surface through which the estimator's gate is measured on a running system (GATE-REFLEX-03), so that the gate is not only a library test.

Why a replay verb and not only an online estimate: an online estimate shows one filter configuration at the moment of the run. A replay lets the same packets be scored under another manifest, with the comparator, or over a window around a failure, with no re-simulation; and because packets are recorded with their delivery times, the replay sees exactly what the online filter saw, late packets included.

Tier: Solid. Surfaces: `frob control estimate` on the command line, the same verb through the daemon, and the generated MCP tool `control_estimate`.

## Scope
In: the registry entry, the input and output schemas, the implementation that reads a run's packet stream and truth from the ledger and runs the two filters and the scorer, the envelope with evidence, the refusals, an example, unit tests of the verb layer, and this bead's own end-to-end script `scripts/e2e/control_estimate_verb.sh` on its own dependencies (KNOWN_DRIFTS 11).
Out: the filter, the scorer and the state sources (BD-114, N22a-02, N22a-03); the gate's script `scripts/e2e/control_estimate.sh` on the trot and the gate record (N22a-05, which may run this bead's script as a stage); the observability analysis verb of the sensing chapter (`sense.observability`, BD-120); report rendering beyond the envelope.

## Technical approach
**Registry entry (`registries/verbs.toml`).**
```toml
[[verb]]
name = "control.estimate"
cluster = "control"
kind = "read"
tier = "S"
capabilities = ["control:read"]
input_schema = "frob.control.estimate.in/1"
output_schema = "frob.control.estimate.out/1"
refusals = ["FROB-REF-464", "FROB-REF-888"]
idempotent = true
paginated = true
cost_model = "static: linear in packets; under 1 s for a 20 s run of a 12-joint robot"
first_milestone = "M1"
task_clusters = ["control"]
examples = ["frob control estimate r:19e2 --json"]
owner = "frob-control"
purpose = "Replay a run's packets through the invariant filter and its comparator"
```
The machine fields (capability, task cluster, example, owner, purpose) are those of the row in the control cluster's registry bead VERBS-control, a dependency; the generator appends the surface-wide refusals (720, 723, 724, 802) and, because the event lists are paginated, 806 and 807 (§32.4 conventions as VERBS-control states them). FROB-REF-888 is the trace chapter's refusal for a metric over missing samples (BD-090, a dependency, owns the gap record and the check); this verb raises it, and the chapter list of VERBS-control carries it (464 and 888).
**Input (`frob.control.estimate.in/1`).** `run` (a run or episode identifier, resolved to an immutable identity that the envelope echoes); optional `world` (an address inside a batched run; default the first traced world); optional `window` as two instants of the run's clock; `comparator` (default true); optional `filter_manifest` (a manifest to replay under instead of the one the run recorded); `align` (only `initial` is accepted; anything else is the scale-fit refusal).

**Algorithm.**
1. Resolve the run; read its recorded packet stream (IMU, encoders, contact switches, wheel encoders) with delivery instants, and the design and sensor cards bound to the run. If the run holds no packet stream for the requested world, or the window contains a recorded gap in a channel the filter needs (dropped telemetry, a collected trace, an untraced world), return FROB-REF-888 ("a metric computed over missing samples"), exit 3, with `pointer` at the world and channel and the repairs, ranked: re-run with the channel retained (a telemetry level that records packets for that world); accept `unavailable` (then only a window that lies wholly outside the gap is scored, and the request must name it).
2. Check the sensors the filter needs against the packets present; a missing role is FROB-REF-464 with the role in `pointer`.
3. Build the filter from the recorded manifest (or the supplied one) and, unless disabled, the quaternion comparator with the same noise parameters. Feed both the packets in delivery order through `EstimatedState`, so late packets follow the out-of-sequence rule.
4. If the run recorded truth, score both filters with the gauge rule (one translation and one yaw fixed at the first sample of the window, never a scale) and compute the consistency statistics. If no truth was recorded (a run imported from a real robot), report innovation statistics only and mark the truth-based columns `not available`.
5. Evaluate the observability rank at up to 64 estimates sampled along the run and report the dimension of the unobservable subspace for each filter.
6. Return the envelope.

**Output (`frob.control.estimate.out/1`).** For each of `invariant` and `comparator`: `aligned_drift_m`, `drift_fraction`, `max_aligned_error_m`, `tilt_error_rad`, mean normalized innovation with its χ² bounds and dimension, normalized estimation error with bounds, covariance coverage, flags `overconfident` and `drifting`, `unobservable_dim` (minimum and maximum over the sampled estimates), the log-linearity departure, bias estimates. Common fields: counts of packets by sensor, touchdown and liftoff counts, `contact-downweighted` events with foot and instant, out-of-sequence events, the filter manifest hash, the scoring manifest hash, the window. Long event lists are paginated with a cursor and never cut silently.

**Envelope and evidence.** One envelope per invocation under `--json`. The evidence block is a claim product: claim kind Known answer when the gate fixture is the input and empty otherwise; class `Tested`; tier of the run that produced the packets; determinism class of that run; identities (run, design, model, filter manifest, scoring manifest); seed; `reality: no-claim`. Exit code 0 when no flag is raised, 2 when `overconfident` or `drifting` is set for the invariant filter (completed with findings), 3 on a refusal.

**Refusals.** FROB-REF-464: an estimator was scored with a fitted scale, or an estimated-state run lacks a sensor the filter needs. Repairs, ranked: score with translation and yaw alignment only; add the sensor, or run privileged and say so. `retry: after-change`. FROB-REF-888: no packet stream, or a recorded gap inside the window, as in step 1; `retry: after-change`.

**Idempotence.** The answer is a pure function of the resolved identities and the two manifests; a repeated call returns the stored envelope with `idempotent_replay: true`.

## Acceptance criteria
- [ ] `frob control estimate <run> --json` returns exactly one envelope that validates against `frob.control.estimate.out/1`, with both filters' columns and the evidence block filled; the same answer is served through the daemon and the MCP tool `control_estimate`.
- [ ] On a run recorded with truth, the scores equal those the library computes on the same packets (byte-equal numbers in canonical JSON).
- [ ] `--align similarity` (or any alignment other than `initial`) exits 3 with FROB-REF-464 and both ranked repairs; a run whose packets lack the IMU exits 3 with the same code and the role in `pointer`.
- [ ] A run without a recorded packet stream, and a window that spans a recorded telemetry gap, are each refused with FROB-REF-888 (exit 3, pointer at world and channel, both repairs); no partial answer is printed.
- [ ] The registry row's machine fields equal VERBS-control's row for `control.estimate` (capability `control:read`, task cluster `control`, example `frob control estimate r:19e2 --json`), and the served refusal list is 464 and 888 plus the generator's appended codes for a paginated read.
- [ ] A truthless run returns innovation statistics and marks truth-based columns `not available`; it does not invent them.
- [ ] Repeating the call returns `idempotent_replay: true` and identical bytes; the verb is listed by `frob capabilities` and documented by `frob schema control.estimate` with its example.
- [ ] Exit codes: 0 clean, 2 when the invariant filter raises a flag, 3 on refusal; exit 1 never.
- [ ] `scripts/e2e/control_estimate_verb.sh` exits 0 on a correct build and non-zero when any assertion fails, on this bead's dependencies alone, and its log carries every field listed below with a closing `summary` line.

- `envelope_validates_against_schema`; `evidence_block_complete` (claim, class, tier, determinism, identities, seed, reality).

- `idempotent_replay_bytes_equal`; `exit_codes_by_outcome`.
- `pagination_of_contact_events` (a run with 10⁴ events returns a cursor and the pages concatenate to the full list).
### End-to-end script and logging
`scripts/e2e/control_estimate_verb.sh` (this bead's; plain shell, idempotent, sources the shared helper of the end-to-end standard, every seed explicit, a distinct `--key` on every run, session namespace `cev-<utc>`). It runs on N22a-03's referee smoke world under the `hold` controller (`<smoke>`, positional):
1. `frob sim run <smoke> --tier referee --telemetry T2 --seed 7 --key cev-run-t2 --json` (packets are recorded at T2) and `frob sim run <smoke> --tier referee --seed 7 --key cev-run-t1 --json` (default `T1`: no packet stream).
2. `frob control estimate <run-t2> --json`: the envelope validates against `frob.control.estimate.out/1`; both columns are present with equal packet counts by sensor; the evidence block has class `Tested`, tier `referee`, the determinism class, the run, design, model, filter-manifest and scoring-manifest identities and the seed; exit 0 or 2 consistent with the invariant filter's flags.
3. `frob control estimate <run-t2> --align similarity --json`: exit 3, FROB-REF-464, both ranked repairs.
4. `frob control estimate <run-t1> --json`: exit 3, FROB-REF-888 with `pointer` at the world and channel; no partial answer on stdout.
5. `frob control estimate <run-t2> --comparator false --window <t0>,<t1> --json`: only the `invariant` column, scored over the window (the window is echoed).
6. The call of step 2 repeated: `idempotent_replay: true` and identical bytes; the same request through the daemon and through the MCP tool `control_estimate`: identical envelopes.
7. Pagination: on the run of step 1, the contact-event list fetched page by page with the cursor concatenates to the unpaged count.
8. `frob capabilities --json` lists `control.estimate`; `frob schema control.estimate` prints its example.
Logging to `target/e2e-logs/control_estimate_verb/<utc>.ndjson` with a transcript beside it: `ts`, `script`, `bead` = `N22a-04`, `step`, `event` (`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact command line, exit code, wall time, the envelope's evidence block, each score as a `metric` with unit and threshold, refusals with code, pointer and repairs, digests of the envelopes compared in step 6, on failure the first differing value with the run identifier; a closing `summary` line with assertions passed and failed. The gate's script `scripts/e2e/control_estimate.sh` (N22a-05) drives the same verb on the referee trot with the same fields.
### Known answers and negative controls
- The verb reports KA-553 (unobservable dimension four; the comparator shows three), KA-554 through its refusal of scale alignment, and KA-555 (consistency and drift on a flat trot; the planted bias raises `overconfident`).
- Negative controls: a verb build that truncates the event list without a cursor (the pagination test fails); one that computes scores on arrival order instead of delivery timestamps (scores differ from the library on a run with a late packet); one that returns exit 0 with `overconfident` set.
- Determinism: the envelope is byte-identical across repeated calls, across debug and release builds, and when the daemon and the command line answer the same request.

## Considerations
- The verb needs runs recorded with a packet stream; the default telemetry level for evaluation runs must therefore include packets for at least the traced worlds, which is a storage cost decided by the telemetry chapter. For untraced worlds the verb says so.
- Replaying under a different manifest is diagnostic only: the result's identity block names the replay manifest, and it never replaces the run's own record.
- A real-robot log imported later through the calibration lane has no truth; the verb then supports the innovation-based half of the consistency check only.
- Capability `control:read` (the registry row's) is enough; the verb exports no artifact and needs no authorization flags beyond the envelope's defaults.
