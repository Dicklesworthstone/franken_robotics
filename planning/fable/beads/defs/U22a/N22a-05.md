## Background
GATE-REFLEX-03 is the estimator's gate (Known answer, milestone M1): filter consistency inside χ² bounds on the simulated IMU; position drift under 2% of distance on a flat trot, scored by the gauge rule; the proof obligation that the filter's linearization has the four-dimensional null space of position and yaw at every estimate (PO-REFLEX-01); and the `overconfident` flag firing on a planted bias. The library measures these on a `synthetic` packet fixture (BD-114). A gate, though, is recorded from a running system: a real `frob` binary, a real referee run of a quadruped trotting under its baseline controller, the real sensor pipeline and the real ledger. This bead is that script and that record.

A gate that nothing can fail validates nothing, so the script also runs the planted failures and requires each to be caught: the unmodelled bias, the scale-fitted score, the missing sensor, and the conventional filter's spurious yaw direction.

## Scope
In: `scripts/e2e/control_estimate.sh`; its fixtures (seeds, the biased sensor card and the design file that carries it, the IMU-free design file, the filter manifest with bias states frozen); the assertions; the structured log; the case `gate_reflex_03_referee` under the GATE-REFLEX-03 entry of `g1_known_answers`, whose tier run writes the receipt; the record of GATE-REFLEX-03 from that receipt (the gate register names this bead as the referee record's measurer).
Out: the filter, scorer, state sources and verb (BD-114, N22a-02, N22a-03, N22a-04; the verb's own script is N22a-04's `control_estimate_verb.sh`); the legged baseline that produces the trot (BD-116); the M1 exit review, which re-runs this script in a fresh-context session.

## Technical approach
**What the script runs, from the user's side** (plain shell, idempotent, every seed explicit; it sources the shared end-to-end helper; every run or mutate call carries its own `--key`, distinct per step and seed, so that no call returns an earlier call's stored receipt).
1. `frob design new e2e-quad --template quad-mammal --key ce-1-design --json` (the name is positional; a second run of the script returns the stored receipt by key).
2. `frob control synth e2e-quad --gait trot --key ce-2-synth --json` (the verb of BD-118) and expect outcome `ok`, capturing the `ControllerId` (the trot is named explicitly: at 0.5 m/s the automatic choice by Froude number would be a walk, and the gate is stated on a trot).
3. For each seed in {11, 12, 13, 14, 15}: `frob sim run e2e-quad --tier referee --task flat-trot-10m --controller <ControllerId> --state privileged --telemetry T2 --seed <s> --key ce-3-s<s> --json`, capturing the run identifier and asserting that the run header's `ControllerId` equals the one of step 2. The design is positional; the gait is the synthesized controller's (step 2) and the commanded speed is the task's: `flat-trot-10m` commands 0.5 m/s forward for 20 s on flat ground. `T2` is the level at which packets are recorded. Privileged state drives the controller so that the estimator under test is not in the loop that generates its own data.
4. For each run: `frob control estimate <run> --json`. Assertions on the envelope:
   - `invariant.nis_mean` inside its reported two-sided 95% χ² bounds in at least 4 of the 5 seeds (DESIGN reading of "inside χ² bounds" over independent seeds, the same reading as BD-114's 43 of 50: a consistent filter lands inside each seed's 95% interval with probability 0.95, so requiring all five would fail a correct filter with probability 1 − 0.95⁵ = 0.226, while 4 of 5 fails it with probability 0.0226, binomial; every seed's value and bound are logged, and the gate row records the count);
   - `invariant.drift_fraction` < 0.02, with `aligned_drift_m` and the true path length logged;
   - `invariant.unobservable_dim` minimum = maximum = 4;
   - `comparator.unobservable_dim` minimum < 4 (the spurious yaw direction);
   - `invariant.overconfident` = false and `invariant.drifting` = false;
   - the evidence block has class `Tested`, tier `referee`, a determinism class, the run, design, model, filter-manifest and scoring-manifest identities, and the seed.
5. Planted bias: `frob design new e2e-quad-bias --file fixtures/reflex/e2e-quad-imu-bias.fbot --key ce-5-design --json` (the quad-mammal design whose IMU card carries a constant accelerometer bias of 0.2 m/s² along the body x axis), `frob control synth e2e-quad-bias --gait trot --key ce-5-synth --json`, one episode `frob sim run e2e-quad-bias --tier referee --task flat-trot-10m --controller <its ControllerId> --state privileged --telemetry T2 --seed 11 --key ce-5-run --json`, then `frob control estimate <run> --filter-manifest fixtures/reflex/filter_bias_frozen.json --json`. Assert `invariant.overconfident` = true, exit code 2, and that `drifting` is reported as its own field.
6. Scale fit: `frob control estimate <run> --align similarity --json` must exit 3 with refusal FROB-REF-464 and the repair "score with translation and yaw alignment only".
7. Missing sensor: `frob design new e2e-quad-noimu --file fixtures/reflex/e2e-quad-no-imu.fbot --key ce-7-design --json`; `frob sim run e2e-quad-noimu --tier referee --task flat-trot-10m --state estimated --seed 11 --key ce-7-est --json` must exit 3 with FROB-REF-464 (refused at admission, before any world is built) and the repairs "add the sensor" and "run privileged and say so"; the same with `--state privileged --key ce-7-priv` runs and its header says `privileged`.
8. Estimated-state loop: `frob sim run e2e-quad --tier referee --task flat-trot-10m --controller <ControllerId> --state estimated --telemetry T2 --seed 11 --key ce-8-est --json` completes the 10 m; the report prints the estimated-versus-privileged difference for distance and success against the seed-11 run of step 3.
9. Idempotence: step 4 for seed 11 is repeated; the envelope is byte-identical and marked `idempotent_replay`.
10. Tier run (step `receipt`): `FROB_TEST_SEED=11 cargo test -p frob-conformance --test g1_known_answers --features gauntlet-mutations -- GATE-REFLEX-03`. The entry holds this bead's case `gate_reflex_03_referee` (the referee trot of seeds 11 to 15 through the real state source, filter and scorer; the clauses of step 4: the 4-of-5 NIS count, drift under 2%, null-space dimension four, the comparator's dimension below four, no flag) and the gate's registered negative controls under `gauntlet-mutations` (the planted bias that must raise `overconfident`, the similarity alignment that must be refused, and the two mutant builds of the last acceptance criterion), and BD-114's library-level case on the synthetic fixture. It writes one hash-named receipt under `target/gauntlet/receipts/`. The script asserts on the receipt's `gates` line and on its `controls` (each `caught`), and asserts that its own measured values of step 4 agree with the receipt's for each seed. A failing run still produces its receipt, with the first differing value; the script writes no gate row.

**Recording (not part of the script).** A session that did not implement BD-114, N22a-02, N22a-03 or N22a-04 enters the row from that receipt: `cargo run -p frob-conformance --example record_gate -- --gate GATE-REFLEX-03 --receipt <hash>` (the gate recorder, N38b-19). The row's `measured` field holds the worst drift fraction over seeds, the NIS count and each seed's ratio to its bound, the null-space dimensions and the flag outcomes; a FAIL is recorded the same way, so the row is never omitted.

**Fixtures.** `fixtures/reflex/` holds the task file for the flat trot, the biased IMU card and the design file `e2e-quad-imu-bias.fbot` that carries it, the frozen-bias filter manifest and the IMU-free design file `e2e-quad-no-imu.fbot`, each content-hashed; the hashes are logged.

**Thresholds (TARGET, from the gate).** Drift under 2% of distance; χ² level 95% two-sided on the mean innovation (with the 4-of-5 seed rule above, DESIGN); null-space dimension exactly four.

## Acceptance criteria
- [ ] `scripts/e2e/control_estimate.sh` exits 0 on a correct build and non-zero if any assertion fails; it is idempotent (a second run reuses designs and runs by key and produces the same measurements).
- [ ] On the referee, all five seeds pass the drift, null-space and flag assertions of step 4, and at least 4 of the 5 have mean NIS inside the 95% bounds (the count and each seed's ratio to its bound are in the gate row).
- [ ] Each planted failure is caught: the biased card sets `overconfident` (exit 2); the similarity alignment is refused (exit 3, FROB-REF-464); the missing IMU is refused (exit 3, FROB-REF-464); the comparator's null space is smaller than four.
- [ ] The log exists at `target/e2e-logs/control_estimate/<utc>.ndjson` with a transcript beside it, every line carries the required fields, and the final `summary` line lists assertions passed and failed and the gate touched.
- [ ] The tier run of step 10 writes a receipt whose GATE-REFLEX-03 line agrees with the script's measurements and whose registered controls are each `caught`; the script writes no gate row. `registries/gates.toml` has the GATE-REFLEX-03 row with measured values, commit, fingerprint and seeds, entered from that receipt through the gate recorder by a session that did not implement the estimator; the row cites the receipt and this bead's log file.
- [ ] A build with the gauge alignment replaced by a similarity alignment, and a build with the g^ block of the filter's error dynamics negated, each make the script fail (mutation check, run once and recorded).

## Test plan
### Unit tests
The script's helpers are tested by `scripts/e2e/tests/control_estimate_helpers.sh`: the JSON extraction of each asserted field on a stored envelope; the comparison of a value with a threshold in exact decimal arithmetic (no floating comparison in shell); the comparison of the script's measurements with a receipt's line. The case `gate_reflex_03_referee` is tested in `crates/frob-conformance/tests/` on a stored receipt: its clause evaluation (4 of 5 seeds; drift below 0.02; dimension four) on values just inside and just outside each threshold. These run on stored envelopes produced by the real binary, not on hand-written ones.
### End-to-end script and logging
Script: `scripts/e2e/control_estimate.sh`. Log: newline-delimited JSON, one line per step, with `ts`, `script` = `control_estimate`, `bead` = `N22a-05`, `step`, `event` (`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact command line, exit code, wall time, the envelope's `evidence` block (claim, class, tier, determinism, identities, seed), measured values with units and thresholds (for example `{"metric":"drift_fraction","value":0.0073,"threshold":0.02,"unit":"1","seed":12}`), digests where envelopes are compared, and on failure the first differing value, the run identifier and the artifact paths (the run's `.frun`, the envelope, the fixture hashes) needed to reproduce. The last line is `summary` with counts and `gates: ["GATE-REFLEX-03"]`. Logs hold identifiers, digests and scalar measurements only; no scene or trajectory data.
### Known answers and negative controls
- KA-553 (unobservable dimension four; the conventional filter gains a spurious yaw direction), KA-554 (scale-fitted scoring is refused), KA-555 (consistency; drift under 2%; the planted bias raises `overconfident`).
- Counterexample exercised: CX-234 (scoring after fitting a scale).
- Planted failures: the four of steps 5 to 7 and step 4's comparator assertion; and the two mutant builds of the last acceptance criterion.
- Determinism lanes: the whole script twice on one machine (identical measurements and digests); the referee runs in debug and release builds of the binary (identical digests, class D2 on the referee); the idempotent replay of step 9.

## Considerations
- The script depends on the legged baseline for a trot on the referee. If the referee's contact capacity or contact law is not yet available for the quadruped at M1, the gate is recorded `not run` with the reason, and the library-level measurement of BD-114 on the synthetic fixture stands as the M1 evidence; it is not relabelled as the gate.
- Run time (TARGET): under five minutes on the development machine, so that it can run on every change to the filter.
- The exit review re-runs this script in a session that did not implement the work and compares its row with the recorded one.
