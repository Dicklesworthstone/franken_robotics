## Background
"It worked" is not a result if the backup controller did the work. The plan's decision (ADR-REFLEX-08): every command that reaches a driver records which layer produced it, and every fallback is an event in the telemetry. The invariant (INV-REFLEX-01): every command that reaches a driver records the layer that produced it, and every fallback is a telemetry event with its reason. Each tick records its layer: `baseline`, `baseline+residual`, `shield-filtered`, `fallback:<reason>` or `backup`.

A second rule guards a different way of fooling oneself. **Actuator bounds are not negotiable.** The driver model enforces the torque-speed envelope in the plant, so a simulated actuator never delivers more than it can. But a run may have succeeded only while the controller requested more than the continuous envelope for longer than the card's duty rating: the motor would have overheated or tripped. Such a run is marked `actuator-infeasible` and counts as a failure of the engineering constraint.

Both are clauses of the gate GATE-REFLEX-05 (Known answer, M3): every command has a layer record; a planted infeasible program yields a certificate that checks exactly and a fallback event; a run that needs commands beyond the envelope is marked `actuator-infeasible`.

Why the layer is a field of the command and not a log line: a log can be dropped, sampled or filtered; a field of the command is in the state the digest chain covers, so a replay reproduces it and a result cannot be separated from it. Alternatives rejected: logging only fallbacks (then "no fallback logged" and "logging off" look the same); deriving the layer afterwards from heuristics on the command (it cannot tell a residual at zero from a baseline); letting the plant's clipping stand as the only actuator check (the run then looks feasible because the simulator silently did less than was asked).

Tier: Solid. Crates: `frob-control`, with channels in `frob-chronicle`.

## Scope
In: the layer code on every command and in the digest; exact per-episode layer counters; the per-tick layer stream for traced worlds; the fallback event schema and its conservation law; the overload tracker and the `actuator-infeasible` mark; their appearance in reports; tests on the referee and on batched tiers; the planted-fallback task file `fixtures/reflex/tasks/stand-10s-payload-at-2s` with its payload `fixtures/reflex/payload_heavy.json`, which this bead's script runs and BD-251's gate script reuses.
Out: the tag type and stage order (N22a-01); the outcomes that cause fallbacks (N22a-08, N22a-09, N22a-14); the residual wrapper's own layer and saturation flag (N22a-16); shields and backup controllers (the shield unit); the gate script (BD-251); the driver model's enforcement of the envelope in the plant (the actuator chapter).

## Technical approach
**Layer code.** `Layer` is an enumeration with a compact integer code and, for `fallback`, a reason code from a closed list: `infeasible:<program>`, `unconverged:<program>`, `invalid-state`, `alarm:<monitor>`, `deadline-missed`. It is a field of `Checked<Command>`; a command cannot be constructed without it. Each world keeps a control-record digest chain over (tick, command values, layer) beside its physics state digest. Two runs that differ only in which layer produced a tick's command have different control-record chains and equal state digests; this separation is what lets a residual wrapper with a zero residual be compared bit for bit with its baseline on state while still being recorded as a different layer.

**What is recorded, at which telemetry level.**
- Always (the lowest level, every world): per episode, one exact integer counter per layer code, incremented once per control tick. The counters sum to the number of control ticks of the episode; `layer_fractions` in every report is their ratio. Counters are integers in the exact kernel class, so they are identical on every backend.
- Always: fallback events (sparse). One event at each transition into a fallback or backup layer and one at each return: world address, tick, layer, reason, program name, the solver end state, a reference to the certificate when the end state is `infeasible`, and on return the number of ticks spent.
- Traced worlds (the reservoir chosen by address): the per-tick layer code as a telemetry channel of kind `enum`.
- On demand: because a world is replayable, the per-tick layer of any world is recovered by replay; the report says whether a per-tick sequence was recorded or reconstructed.

**Conservation laws (tested).** (i) Sum of layer counters equals control ticks. (ii) The number of `enter` fallback events equals the number of maximal runs of consecutive non-nominal ticks. (iii) For every tick with a fallback or backup layer there is an enclosing pair of events. (iv) A certificate reference in an event resolves to a certificate whose exact check passed.

**The overload tracker and `actuator-infeasible`.**
1. Per actuated joint and per control tick, compare the *requested* torque (the controller's proposed command before the limiter and the plant clip it) with the card's continuous envelope at the present joint speed, τ_cont(q̇).
2. Maintain, per joint, the length of the current continuous overload (ticks with |τ_req| > τ_cont) and the overload fraction over the card's duty window.
3. The card's duty rating gives the longest admissible continuous overload t_ov and the admissible overload fraction f_ov over a window t_w. When either is exceeded the episode is marked `actuator-infeasible`, with the joint, the instant, the overload ratio and both measured durations.
4. Consequences: the mark is in the result's flags; the engineering-constraint class of the task verdict fails, whatever the task's goal predicate says; the synthesis report's saturation section lists it; the first-cause list includes it with its timestamp. A marked run is never counted as a success in a corpus tally.
5. The tracker uses integer tick counts (exact) and a single guarded comparison per joint per tick; it is evaluated on every tier.
6. Requests above the *peak* envelope are also counted (the limiter clips them); the report gives the clipped fraction separately, since clipping changes the behaviour immediately while overload changes whether the behaviour is admissible.

**Reports.** Every run result and every synthesis report prints: layer fractions; fallback count with reasons; the longest fallback; `actuator-infeasible` with its joint and durations, or the worst overload margin when not marked.

**Determinism and evidence.** Counters and marks are D0 given the commands; the commands are D2 with the run. A statement "no fallback occurred" is a `Tested` statement about a recorded run with its counters as evidence.

## Acceptance criteria
- [ ] INV-REFLEX-01: on the smoke battery, on the referee and on `batch-cpu`, the layer counters of every episode sum to its control ticks; replaying any world reproduces a per-tick layer sequence whose counts equal the counters.
- [ ] A command without a layer does not compile; changing only the layer of one tick changes the world's control-record digest and leaves its state digest unchanged.
- [ ] Every fallback has its events: on a run with a planted infeasible program and a planted starved solver, the conservation laws (ii) to (iv) hold, each event names the program and end state, and the infeasible one references a certificate whose exact check passed.
- [ ] A run in which fallbacks are suppressed from the log by a test hook is detected: the counters show non-nominal ticks without enclosing events and the invariant check fails.
- [ ] Overload fixture: a joint whose requested torque is 1.3 times the continuous envelope for 12 s against a duty rating of 5 s is marked `actuator-infeasible` at 5 s plus one tick, with the joint named; the same request for 3 s is not marked and reports its margin; a request above peak is counted as clipped and, if it also exceeds the duty rating, marked.
- [ ] A marked run fails the engineering-constraint class of its task verdict even when the goal predicate passes, and is tallied as not successful.
- [ ] On a batch of 4,096 worlds the layer counters and marks cost less than 1% of step time (TARGET; measured value recorded).

### End-to-end script and logging
The gate script is BD-251's (`scripts/e2e/reflex_control_programs.sh`), which asserts the three gate clauses on running systems through `frob sim run`, `frob telemetry summary` and `frob telemetry failures`. This bead's runner `scripts/e2e/reflex_layer_records.sh` executes the test binaries and one referee run with a planted fallback: `frob design new e2e-quad --template quad-mammal --key rlr-design --json`, `frob control synth e2e-quad --key rlr-synth --json`, `frob sim run e2e-quad --tier referee --task fixtures/reflex/tasks/stand-10s-payload-at-2s --seed 3 --key rlr-fallback --json` (this bead's task file, passed by path, since a bare name is looked up as a registered task and refused with 802; whose event schedule adds a payload the knee torque boxes cannot carry at t = 2 s; BD-251's clause 3 reuses it), then `frob telemetry failures <run> --json` to read the two events, and writes the shared newline-delimited JSON log to `target/e2e-logs/reflex_layer_records/<utc>.ndjson` with a transcript: per run the counters, the events with tick and reason, the overload durations with units against the card's ratings, digests, and a `summary` line naming GATE-REFLEX-05.
### Known answers and negative controls
- The invariant INV-REFLEX-01 and the gate clauses of GATE-REFLEX-05 are the subject; there is no numbered known answer.
- Negative controls: the suppressed-event hook; a build that tags fallback ticks as `baseline` (the planted-fault run then shows zero fallback and the test comparing against the solver's end-state counts fails); a tracker that compares the delivered torque instead of the requested one (never exceeds the envelope in the plant, never marks, and fails the overload fixture); a tracker that uses the stall torque instead of the envelope at speed.
- Metamorphic: permuting worlds in a batch permutes counters; concatenating two episodes adds their counters; time-shifting an overload inside the window leaves the fraction unchanged.
- Determinism: counters and marks twice on one machine, across worker counts, debug and release, and across backends: identical.

## Considerations
- Risk: baseline controllers mask design flaws or create false ones; the mitigation named by the plan includes "controller-sensitive" flags. Layer fractions are the cheapest such flag: a design that passes only with 30% of ticks in fallback is a different finding from one that passes cleanly.
- The duty rating is card data with provenance; an `assumed` rating makes the mark `Estimated`, and the report says so. A card without a duty rating is treated as continuous-only: any overload beyond one control period marks the run (fail-closed).
- The thermal model of the actuator chapter gives a second, physical check (winding temperature); the mark here is the rating-based one and the two can disagree, which is reported, not reconciled.
- Storage: counters are a few integers per world per episode; events are sparse; per-tick streams exist only for traced worlds.
