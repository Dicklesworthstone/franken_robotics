## Background
The plan's decision for learned control inside Reflex (ADR-REFLEX-01): every design gets an inspectable, hand-specified baseline before any learned component; a learned residual may be added on top; it never replaces the baseline silently. The mechanism is a wrapper. The command is u = limit(u_base(x̂, t) + Δ(o)), where u_base is the synthesized controller, Δ is a small learned network trained by the learning subsystem, and `limit` is the actuator limiter. The residual has bounded authority: |Δⱼ| ≤ ρⱼ, a declared fraction of each channel's range (DESIGN default ρ = 0.3; the value is an open question with that default). Its output layer starts at zero, so training starts from the baseline's behaviour.

What it must satisfy:
- With Δ ≡ 0 the wrapped controller reproduces the baseline's digests bit for bit in determinism class D2 (proof obligation PO-REFLEX-02; verification: bit comparison on the smoke battery).
- Each tick records its layer: `baseline`, `baseline+residual`, `shield-filtered`, `fallback:<reason>` or `backup`. A residual channel pinned at its bound for more than a declared fraction of ticks sets the flag `residual-saturated`: the baseline is then not the controller, and the result says so.
- Two comparisons are kept apart when bodies are compared. A shared controller isolates the change in the body. Controllers retuned with equal resources compare the best systems. A report states which one it is.

Why bounded and additive: a failure can then be assigned to the body, the baseline or the residual. With unbounded authority the residual can simply replace the baseline, and the inspectable part of the controller becomes decoration. Why the zero-residual bit test: it is the only cheap proof that the wrapper adds nothing of its own; without it, a difference between "baseline" and "baseline plus untrained residual" would be noise injected by plumbing. Tier: Frontier (the rung it serves has a pilot and a kill gate); the wrapper and its obligation are built at M3 because GATE-REFLEX-05 needs them.

## Scope
In: the wrapper type implementing `Controller`; the authority bound; the exact pass-through for a zero residual; the zero-initialization contract for the residual's output layer; the layer tag and the `residual-saturated` flag; the extension of the controller-arm check of study admission (N24b-14) to wrapped controllers; the controller selector `baseline+residual:<policy>`; the controller record fields; PO-REFLEX-02 tests.
Out: training the residual (the learning subsystem; rung R2 measurements in BD-330); the residual's network architecture (a policy with its own identity); layer and fallback telemetry (N22a-15); shields (the shield unit); the ladder verb (N22a-18); the pilot that must precede funding of the rung (N22a-27, a dependency).

## Technical approach
**Type.** `ResidualWrapper<B: Controller>` holds a baseline B, a residual policy handle (anything that maps a policy observation to a raw vector a with one entry per command channel), the authority vector ρ and the channel ranges. It implements `Controller`; its record has kind `baseline+residual`, the baseline's full record, the residual policy's identity, ρ per channel and the limiter's identity.

**Channels and authority.** A command channel j has an admissible interval [loⱼ, hiⱼ] from the actuator card (a torque channel: ± the peak torque; a position-target channel: the joint limits). Its half-range is Rⱼ = (hiⱼ − loⱼ)/2. The residual on channel j is Δⱼ = ρⱼ·Rⱼ·clip(aⱼ, −1, 1). Hence |Δⱼ| ≤ ρⱼ·Rⱼ by construction, for any network output including non-finite ones (a non-finite aⱼ is mapped to zero and counted as a `residual-invalid` event). ρ is declared per channel in the controller record; the default is 0.3 for every channel.

**The sum with exact pass-through.** uⱼ = select(Δⱼ == 0, u_base,ⱼ, u_base,ⱼ + Δⱼ), then `limit`. The select matters: in floating point (−0.0) + (+0.0) = +0.0, so a plain sum with a zero residual can change the bits of a baseline command that happens to be −0.0, and a digest over bits would differ. The select is a mask, as every branch in a kernel must be. The limiter is the same limiter the baseline alone passes through, applied once.

**Zero start.** The residual policy's final linear layer is created with zero weights and zero bias; the wrapper checks at construction that the policy evaluates to exactly zero on a probe batch of observations when it is declared `untrained`, and refuses the declaration otherwise. Training therefore starts from the baseline's behaviour, command for command.

**Layer and saturation.**
- A tick's layer is `baseline+residual` whenever the wrapper is active and no later stage changed the command; later stages re-tag it (`shield-filtered`, `fallback:<reason>`, `backup`).
- Per channel, an exact integer counter counts ticks with |aⱼ| ≥ 1 (the residual pinned at its bound). When, over an episode, any channel's pinned fraction exceeds φ_sat (declared; DESIGN default 0.10, the value the decision on the residual's authority fixes together with ρ, N22c-52, which owns the number), the episode carries `residual-saturated` with the channel and the fraction. The report then states that the baseline is not the controller for this result, and the control ladder treats it as a reason to escalate.
- The mean absolute residual per channel as a fraction of ρⱼ·Rⱼ is reported as `residual_use`.

**PO-REFLEX-02.** For every scenario of the smoke battery and every baseline class available: run the baseline; run the wrapper with a residual that outputs exactly zero (both an untrained policy and a constant-zero stub compiled from the same interface); compare the state digest at every checkpoint and the command values of every tick, bit for bit, in class D2 (same device family, any batch composition). The layer stream differs by design (`baseline` against `baseline+residual`); the state digests and command values must not.

**Comparison kinds.** Any comparison of bodies carries `controller_arm`: `shared` (one controller record applied to every body: isolates the change in the body), `retuned-equal-resources` (each body's controller retuned with the same resources: compares the best systems) or `inherits-weights`. The field and its check already exist: study admission (`study::admit`, N24b-14, M1, a dependency) refuses a design comparison with no declared arm or with arms that contradict it (FROB-REF-802, exit 3, pointer `/controller_arm`, `observed` the identities or resources). This bead adds no second check. It extends that one to wrapped controllers, in two ways. (1) Identity: the wrapped controller's record contains the residual policy's identity and ρ, so under `shared` "one `ControllerId`" already means one baseline, one residual policy and one ρ; two bodies sharing a baseline but carrying different residual policies have two `ControllerId`s and are refused as `shared`. (2) Resources: for `retuned-equal-resources` the wrapper exposes `resources()` for a wrapped controller: the residual policy's recorded training steps, seeds policy and wall-clock cap from its manifest, plus ρ per channel and the baseline's rung (R0 or R1 with its search budget). `study::admit` compares these per arm; arms with equal training steps and different ρ, or with one arm's baseline tuned at R1 and the other's not, are unequal resources and are refused with the differing field named.

**Determinism and evidence.** Class D2. A wrapped controller's results are `Tested`; the residual's training provenance (steps, seeds, the determinism class it was trained under) is carried from the policy's manifest.

## Acceptance criteria
- [ ] PO-REFLEX-02: on the smoke battery, the wrapper with a zero residual reproduces the baseline's state digests at every checkpoint and its command values at every tick, bit for bit, on the referee, on `batch-cpu` in `f32` and `f64`, and on each device backend present, alone and inside a mixed batch.
- [ ] A residual with a nonzero output bias of 10⁻⁶ of range on one channel changes the state digest within the episode (the negative control of the known answer).
- [ ] A baseline command of −0.0 on some channel is preserved as −0.0 by the wrapper with a zero residual; a build that uses a plain sum fails this test.
- [ ] |Δⱼ| ≤ ρⱼ·Rⱼ holds for 10⁶ random raw outputs including infinities and NaN; non-finite outputs raise `residual-invalid` and contribute zero.
- [ ] A policy declared `untrained` whose probe output is not exactly zero is refused at construction.
- [ ] `residual-saturated` is set when a channel is pinned for more than φ_sat of ticks (a planted residual that outputs +2 on one channel sets it with pinned fraction 1.0) and not set for a residual using 10% of its authority; the report's wording for a saturated result says the baseline is not the controller.
- [ ] The controller record contains ρ per channel, the residual policy identity and the limiter; changing ρ from 0.3 to 0.31 changes the `ControllerId`.
- [ ] Through `study::admit` (N24b-14's check, extended here, not duplicated): a comparison declared `shared` whose arms carry one baseline and two residual policies is refused with FROB-REF-802 and pointer `/controller_arm`; a comparison declared `retuned-equal-resources` whose arms have equal training steps and ρ = 0.3 against ρ = 0.5 is refused naming `rho`; with equal steps, seeds policy, cap, ρ and rung it is admitted.
- [ ] The selector `baseline+residual:<policy id>` (and `baseline+residual:zero`, the constant-zero stub, a conformance selector that is never a product controller) is accepted wherever a run names its controller (the `controller` input of `sim.run` and `eval.run`, beside `baseline`, a `ControllerId` and `fixture:<name>`), and the run header carries the wrapped `ControllerId`.

### End-to-end script and logging
The gate script of BD-251 runs the zero-residual comparison through the `frob` binary (`frob eval run … --controller baseline --key <k1>` against `--controller baseline+residual:zero --key <k2>`, two keys because the runs are compared) and compares the reported digests. This bead's runner `scripts/e2e/reflex_residual_wrapper.sh` executes the test binary on each tier present, then drives the selector through the binary on its own dependencies: `frob design new e2e-quad --template quad-mammal --key rrw-design --json`; `frob control synth e2e-quad --key rrw-synth --json`; `frob sim run e2e-quad --tier referee --task stand-10s --controller baseline --seed 1 --key rrw-base --json` and the same with `--controller baseline+residual:zero --key rrw-zero` (state digests equal at every checkpoint; the second header carries the wrapped `ControllerId`; layer fractions `baseline` = 1 against `baseline+residual` = 1); `frob eval run e2e-quad --task stand-10s --worlds 1 --run-seed 1 --controller baseline+residual:zero --key rrw-eval --json` (the run header carries the wrapped `ControllerId`); `--controller residual:zero` and `--controller baseline+residual:` each exit 3 with FROB-REF-802. It writes the shared newline-delimited JSON log to `target/e2e-logs/reflex_residual_wrapper/<utc>.ndjson` with a transcript: per scenario and tier the two digest chains with the first differing checkpoint on mismatch, the pinned fractions, the refusal of the non-zero `untrained` policy, each `frob` command line with exit code, wall time and evidence block, the refusals with code and pointer, and a `summary` line naming GATE-REFLEX-05.
### Known answers and negative controls
- KA-557 (baseline plus residual with a zero residual: digests equal the baseline's; exact by digest; tier G5 on the referee and the strict profile; negative control: a residual with a nonzero bias changes the digest).
- Negative controls: the nonzero bias; the plain-sum mutant on a −0.0 command; a wrapper that applies the limiter twice; a wrapper that tags zero-residual ticks as `baseline` (the layer stream then hides that a residual was present; the layer test of N22a-15 on a wrapped run fails).
- Metamorphic: scaling ρ to zero makes any residual equivalent to the baseline (digests equal); permuting worlds permutes results.
- Determinism lanes: twice on one machine; across worker counts; debug and release; across batch compositions; across backends each against its class.

## Considerations
- "Range" is read here as the half-width of the channel's admissible interval, so that ρ = 1 would let the residual alone reach either limit from the middle. The plan says "a declared fraction of each channel's range" and does not say width or half-width; the choice is recorded in the controller record and is part of the open question on ρ.
- The kill gate of this rung (the residual needs more than 50% of a specialist's training steps for the same return) removes the residual rung, not the wrapper's obligation: the baseline then remains a behaviour-cloning warm start, and this code is retired with a record.
- An allowance on the work the residual may do per tick is a possible later safety device; the rule for debiting the work of a held command (it exceeds power at the tick times the period by F²·h²/(2m)) is stated by the sampled-damping subsection of the chapter and would apply to it.
- During training under a shield, the learner's sampled action is the command before the shield and each intervention is an event; the wrapper sits before the shield and is unaffected.
