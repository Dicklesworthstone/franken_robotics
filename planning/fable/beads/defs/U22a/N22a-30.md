## Background
Shooting for a periodic orbit, its stability and its design gradients all need the derivative of the stride map: the map P̄ that advances the reduced closed-loop state x̄ by one stride of N control periods on a batched tier (N22a-29). On the compliant tiers the control-period map is a composition of kernels, each piecewise smooth, because contact force is a continuous function of state. The plan's route (DESIGN): the Jacobian is built column by column, and each column is a tangent world rolled for one stride beside the nominal one: n tangent worlds for a reduced state of dimension n (estimate: n is 40 to about 130 for the robots in scope). The first implementation uses central differences in `f64` on `batch-cpu` at two step sizes with a Richardson check. The second uses the derivative programs of the kernel dialect and is differentially tested against the first.

Why finite differences first: they need nothing but the step that already exists, they differentiate exactly the map that is being strobed (controller, limiter, actuators, contact, integrator), and a batch makes them cheap: for n = 57 and a trot stride of 250 physics steps, a Jacobian at two step sizes is 4·57 = 228 worlds and 57,000 world-steps. Why not finite differences alone: they cannot tell a derivative from an average across a kink. That is what the labels are for.

The rule the labels implement (decision D-15): every derivative that leaves a kernel or an analysis carries its validity label, and a query near grazing or an ambiguous event order is refused by name. The set is the nine labels of the hybrid-orbit construction:

| Label | Meaning | Carries |
|---|---|---|
| `smooth` | No event in the interval; chart regular | Chart identity |
| `saltation` | Isolated transverse events composed by saltation matrices | Event identities, guard margins, transversality numbers |
| `discrete-step` | Derivative of the time-stepping map with the active set unchanged in each step | Count of active-set changes |
| `fixed-mode` | Mode sequence held fixed by fiat; a conditional derivative | The frozen sequence |
| `one-sided` | Directional derivative on one side of a guard | Side and direction |
| `generalized` | One selection of a piecewise-smooth map | Number of selections and which one |
| `smoothed` | Derivative of a declared smoothed surrogate | Smoothing parameter |
| `finite-difference` | Central difference with events re-located on both sides | Step size, events matched |
| `refused` | No derivative is returned | Offending state and perturbation directions |

The gait section defines no label of its own. Its four cases map onto that set: a derivative with no event in the stride is `smooth`; an estimate on one side of a guard is `one-sided`; a set-valued result, which carries several selection Jacobians, is `generalized`; the derivative of a declared smoothed surrogate is `smoothed`. Compliant-tier Jacobians with an unchanged active set are `discrete-step`, event-located ones are `saltation`, and central differences are `finite-difference`. Near grazing, where the transversality number abs(D g·f⁻) (the rate at which the guard function g is crossed along the incoming flow f⁻) falls below its threshold, an ordinary derivative is `refused` (refusal FROB-REF-431) and the offending state, the perturbation directions and the one-sided estimates are returned.

## Scope
In: state and parameter Jacobians of F̄ᵏ for any number k of control periods; the two-step central difference with Richardson extrapolation and check; per-column event matching, one-sided estimates and selections; grazing detection on a compliant tier and the refusal; the label of each column and of the matrix; the second implementation through derivative programs and the differential test; cost accounting in worlds and world-steps.
Out: the label type itself, its nine labels and the kernel-level refusal FROB-REF-263 (N10b-01, the C-16 specification part in `frob-dyn`, a dependency); the per-step active-set signature (N16ax-01); the derivative programs of the kernel dialect used by the second implementation (N21a-20); saltation matrices on event-located flows (N22a-33); the split check for simultaneous touchdowns (N22a-34); what consumes the Jacobian (N22a-31, N22a-32, N22a-37, BD-334); paired finite-difference design gradients of rollouts, which are a different verb in the design-population chapter (BD-353).

## Technical approach
**Inputs and outputs (DESIGN).**
```rust
pub struct JacobianOpts { pub eps: f64, pub tau_richardson: f64, pub tau_side: f64, pub tau_graze: f64, pub max_selection_cols: u32, pub method: Method /* CentralDiff | TangentProgram */ }
pub struct ColumnLabel { pub label: DerivLabel, pub events_matched: bool, pub richardson_err: f64, pub side: Option<Side> }
pub struct LabeledJacobian {
    pub d: Matrix,                    // n_out × n_in, in the dimensionless chart
    pub cols: Vec<ColumnLabel>, pub label: DerivLabel,       // matrix label = weakest column label
    pub selections: Vec<(usize, Vec<f64>, Vec<f64>)>,        // column index, minus-side column, plus-side column
    pub active_set_changes: u32, pub worlds: u32, pub world_steps: u64,
}
```

**First implementation: central differences.**
1. Step sizes ε and ε/2 in the dimensionless chart (DESIGN default ε = 2 × 10⁻⁵; the round-off-optimal order for a central difference in `f64` is the cube root of machine epsilon, about 6 × 10⁻⁶). Both are recorded.
2. For each input coordinate j, four worlds x̄ ± ε·eⱼ and x̄ ± (ε/2)·eⱼ, plus one nominal world, all in one batch: 4n + 1 worlds. For a parameter θᵢ the same with parameter variants.
3. D_ε[:, j] = (P̄(x̄ + ε·eⱼ) − P̄(x̄ − ε·eⱼ))/(2ε), and likewise D_{ε/2}.
4. Richardson: the reported column is (4·D_{ε/2} − D_ε)/3; its error estimate is ‖D_{ε/2} − D_ε‖/max(‖D_{ε/2}‖, 10⁻¹²). On a smooth map the two agree to about 10⁻⁹. The check passes when the estimate is at most τ_R (DESIGN default 10⁻⁶).
5. *Event matching.* A column's events are matched when the per-step active-set signatures (the hash of the active contact set with a stick or slip state per contact) of its four worlds equal the nominal world's at every step.
6. *Classification of a column.*
   a. Matched and Richardson passes: `finite-difference` with step sizes and `events_matched: true`.
   b. Not matched, or Richardson fails: one-sided estimates D⁺ and D⁻ are formed on each side from the same worlds (forward and backward differences at ε and ε/2, extrapolated as 2·D_{ε/2} − D_ε). If they agree within τ_side (DESIGN default 10⁻³ relative), the kink is below tolerance and the column is `finite-difference` with `events_matched: false`. If they differ, the column is set-valued: both are kept as selections and the column is `generalized` with two selections. If one side leaves the map's domain (the perturbed stride ends in a fall or outside the chart), the column is `one-sided` with the admissible side and direction.
   c. Grazing (below): `refused`.
7. *Label of the matrix.* The weakest statement that applies to any column, in the order `refused`, `generalized`, `one-sided`, `smoothed`, `finite-difference`, `discrete-step`, `smooth`. A step plan that declares a smoothed contact surrogate makes every derivative at best `smoothed`, with the smoothing parameter. The method used and the per-column labels are recorded beside the single label.
8. *Selections.* With k generalized columns there are 2ᵏ selection Jacobians. Consumers enumerate them up to `max_selection_cols` (DESIGN default 4, so at most 16 matrices); beyond that the matrix is `refused` with reason `too-many-selections`, and the caller is routed to finite-perturbation tests.

**Grazing on a compliant tier.** For every touchdown and liftoff in the nominal stride, the transversality number is the normal approach or separation speed at the step where the contact's state changes, normalized by the guard's declared scale g_s (the contact's compliance length) and the model's time scale t_s = √(ℓ₀/g): τ = abs(ġ)·t_s/g_s. A swing foot whose least clearance over the stride is below g_s without touching is treated the same way, since an arbitrarily small perturbation adds an event. If any τ is below τ_graze (DESIGN default 10⁻²; fixed before the gradient gate from that gate's twenty control cases, and recorded), every column whose perturbed worlds change that event's presence or order is `refused`, and the call returns FROB-REF-431 with: the offending state (tick, contact identity, x̄ at the event), the transversality number and threshold, the perturbation directions, and the one-sided estimates D⁺ and D⁻. Ranked repairs: use the one-sided estimates returned; move the parameter; derivative-free search. A kernel-level refusal FROB-REF-263 raised underneath (grazing, ambiguous event order, a change of active set under the requested perturbation, frictional degeneracy) is re-raised as FROB-REF-431 with its payload attached. Touchdowns that are simultaneous by symmetry are not a reason to refuse; they are handled by the split check of N22a-34.

**Second implementation: tangent programs.** Each step kernel has a derived forward-tangent program. A tangent world carries (x, δx) and is rolled beside the nominal one; n tangent worlds give the Jacobian in one pass with the active set of each step taken from the nominal world. The result is `smooth` when no active-set change occurs anywhere in the stride and `discrete-step` otherwise, with the count of active-set changes. It is differentially tested against the first implementation: on every column the first implementation labels matched, the two must agree within 10⁻⁶ relative. A disagreement sets `derivative-disagreement`, the central-difference value is reported, and the case is logged with both columns.

**Cost accounting.** Every result reports worlds and world-steps used. TARGET: a state Jacobian of the reference quadruped's trot stride on `batch-cpu` in under 2 s of CPU on the development machine.

**Determinism and evidence.** Class D2: the Jacobian's bits do not depend on batch composition or worker count. A derivative is class `Estimated` (the class of every orbit-analysis output, N22a-36), and its validity label, which says how far it can be trusted, is part of its identity.

## Acceptance criteria
- [ ] On an analytic smooth map the extrapolated Jacobian agrees with the closed form within 10⁻⁹ and every column is `finite-difference` with `events_matched: true`.
- [ ] On the absolute-value map at the origin the column is `generalized` with selections −1 and +1; at 0.5 it is `finite-difference` with value 1.
- [ ] A kink planted between ε/2 and ε from the nominal point is caught by the Richardson check, not averaged silently.
- [ ] A map defined only on one side at the nominal point yields `one-sided` with the side named.
- [ ] On the reference quadruped's trot stride: a 57-column state Jacobian is produced with labels; worlds = 4n + 1; the same call twice, in different batch compositions and worker counts, gives identical bits.
- [ ] With the swing clearance of one foot reduced until it scuffs, the call returns FROB-REF-431 with the tick, the foot, the transversality number, the affected directions and both one-sided estimates; exit 3 at the surface with the three ranked repairs.
- [ ] A trot with simultaneous diagonal touchdowns and regular clearance is not refused.
- [ ] The parameter Jacobian with respect to one link length is produced with the same labels, and agrees with a re-run at half the step within the Richardson tolerance.
- [ ] When tangent programs exist: agreement with central differences within 10⁻⁶ on matched columns of the standing and trot fixtures; a planted error in one tangent kernel (a dropped term) is caught by the differential test.
- [ ] The grazing threshold, both step sizes and both tolerances are in every result.

## Test plan
### Unit tests
`crates/frob-gait/tests/jacobian.rs`; fixtures that are not robots are labelled `synthetic` and implement the same `StrideMap` trait. A piecewise synthetic fixture reports the branch it evaluates as its `active_set_sig` (for abs(x) the sign of x; for max(0, x − c) the sign of x − c), as a contact model reports its active set: at the origin the central differences of abs(x) at ε and ε/2 are both exactly 0 and pass the Richardson check, so only the unmatched signature sends that column to the one-sided estimates (+1 and −1) that make it `generalized`.
- `smooth_map_matches_closed_form`: P(x) = (x₁² + x₂, sin x₁) at (1, 2) has Jacobian [[2, 1], [cos 1, 0]] = [[2, 1], [0.540302, 0]]; error below 10⁻⁹.
- `abs_at_origin_is_generalized`; `abs_away_is_finite_difference`.
- `kink_inside_step_is_flagged`: P(x) = max(0, x − c) with the nominal point 0.75·ε below c.
- `one_sided_at_domain_edge`.
- `matrix_label_is_weakest_column`.
- `selection_cap_refuses`: five generalized columns with a cap of four give `refused` with reason `too-many-selections`.
- `affine_fixture_exact`: x ↦ A·x + d returns A to 10⁻¹¹.
- `trot_jacobian_world_count_and_bits`.
- `scuff_is_refused_431`; `symmetric_touchdown_not_refused`.
- `parameter_jacobian_link_length`.
- `tangent_program_matches_central_difference`; `planted_tangent_error_caught` (run when tangent programs exist; otherwise reported `not run`).
- `smoothed_surrogate_caps_label`.

User-visible through `frob gait orbit` and `frob gait gradient` (`scripts/e2e/gait_orbit.sh`, `scripts/e2e/gait_gradient.sh`). This bead's runner `scripts/e2e/gait_jacobian.sh` executes the test binary on `batch-cpu` and writes the shared newline-delimited JSON log to `target/e2e-logs/gait_jacobian/<utc>.ndjson` with a transcript: per test the matrix label, per-column labels and Richardson estimates against τ_R, worlds and world-steps, CPU seconds against the 2 s TARGET, the refusal payload for the scuff case (code, state, transversality number, directions, one-sided estimates, repairs), digests for the determinism comparisons, and a `summary` line.
### Known answers and negative controls
- Closed forms above; KA-095 (a ball whose apex touches a ceiling returns `refused`, not a matrix) as the smallest grazing case, run through the gait-level refusal; KA-097 (every derivative is validated against a perturbation of the initial state with events re-located on both sides).
- Counterexample CX-043 (returning a derivative at a grazing event).
- Negative controls: a build that reports the central value for the absolute-value map at the origin (the test expects `generalized`); a build that skips event matching (the kink test fails); a build with τ_graze = 0 (the scuff case returns a matrix and the test fails); a tangent kernel with a dropped term.
- Metamorphic: halving ε changes no label on regular fixtures and changes values by less than τ_R; permuting columns permutes the result; mirroring the state mirrors the Jacobian by the representation matrices.
- Determinism lanes: twice on one machine; across worker counts; across batch compositions; debug and release.

## Considerations
- The grazing threshold and the selection tolerances are recorded parameters with defaults; the gradient suite freezes their values with its control cases (BD-334), and this bead does not wait for that. The thresholds here are defaults to be fixed by data that includes planted grazing cases, before the gate that uses them is recorded; a threshold tuned after seeing the gate's regular cases would be a quiet re-scope.
- A central difference is not a certificate of smoothness. The matched-events test and the Richardson check are necessary conditions; the label says `finite-difference`, never `smooth`, for this method.
- Risk (RISK-47): search or gradients exploit a contact-order or model-form artifact. Earliest signal: a derivative used outside its validity label. The label travels with the number so that a consumer can refuse.
- Memory: 4n + 1 worlds of one robot; for n = 130 that is 521 worlds, well inside `batch-cpu` capacity.
- Device tiers in `f32` are not used for Jacobians: a central difference at 10⁻⁵ is below single-precision resolution of the state.
