## Background
An orbit result is easy to over-read. A table of Floquet multipliers looks like a statement about a robot; it is a statement about one feedback law, on one tier, near one periodic motion on flat ground. The plan therefore fixes what every orbit result contains and what it is called.

- **The record.** A `GaitOrbit` record holds the `ControllerId`, the tier, the gait's symmetry data (H, K, σ), the stride length N, the fixed point x̄*, the residual, the removed coordinates, the multipliers with their block labels, transient growth, order sensitivity, the derivative labels, the metrics, and the standing `screening`.
- **The invariant (INV-GAIT-01).** Every orbit result carries its `ControllerId`, tier, residual, full-space spectrum, derivative labels and the standing `screening`.
- **The label.** Every result of the gait analysis is labelled `screening: gait-orbit`. FACT (the plan's source register): published full-order orbit solves take about 4 to 260 s of CPU at 20 to 68 states with initial guesses supplied, about 1% to 63% of a 410 s quadruped training run; continuation is not guaranteed to arrive, because turning points and bifurcations stop it; an orbit is not an accepted controller, and published hardware gaits needed added heuristics to stabilize. Floquet multipliers describe the chosen feedback law on the chosen tier, and local stability only. A locally stable orbit on flat ground supplies no estimate of recovery on a staircase.

Why each mandatory field is mandatory. The `ControllerId`: an orbit belongs to a closed loop, not to a body, and a change of gain, iteration count or latency model is a different orbit. The tier: a compliant-tier orbit and an event-located one are different maps. The residual: without it "orbit" may mean "the last Newton iterate". The full-space spectrum: a spectrum restricted to the symmetric subspace can call a gait stable that falls over sideways. The derivative labels: a multiplier computed through a kink is not the same kind of number as one computed on a smooth piece. The standing: a screening signal may discard under stated rules and may not establish a comparison.

This bead makes the invariant structural. The record cannot be built without the fields, the standing cannot be set to anything stronger, and the limits travel with the result as data.

## Technical approach
**Record (DESIGN sketch; values illustrative).**
```json
{
  "schema": "frob.gait.orbit/1",
  "orbit_id": "orb:…",
  "design": "dsn:…", "model": "mdl:…", "controller": "ctl:…",
  "tier": { "name": "batch-cpu", "profile": "lockstep", "precision": "f64", "step_plan": "plan:…", "warm_start": "cold-start" },
  "world": { "ground": "flat", "mu": "0.8", "command_twist": ["0.6", "0", "0"], "state_mode": "privileged" },
  "gait": { "name": "trot", "H": "C2", "K": "1", "sigma": "mirror·half-stride", "m": 2 },
  "stride": { "periods": 25, "control_period_s": "1/50", "stride_period_s": "1/2", "phase0": 0 },
  "chart": { "id": "chart:…", "dim": 57, "removed": ["base.x", "base.y", "base.yaw"] },
  "fixed_point": { "xbar": "blob:…", "residual": 3.1e-10, "tolerance": 1e-9, "drift": { "dx_m": 0.300, "dy_m": 0.0, "dyaw_rad": 0.0 } },
  "spectrum": {
    "scope": "full",
    "multipliers": [ { "re": 0.61, "im": 0.12, "modulus": 0.622, "block": "trivial", "temporal_index": 0 } ],
    "spectral_radius": 0.622, "guard": 1e-3, "classification": "Stable",
    "po_gait_01_rel_diff": 2.0e-10, "commutation_residual": 4.0e-9
  },
  "transient_growth": [ { "strides": 1, "gain": 1.9 }, { "strides": 5, "gain": 0.4 } ],
  "simultaneous_groups": [ { "contacts": ["foot_fl", "foot_hr"], "coupling_sign": "negative", "order_sensitivity_norm": 0.002, "agree": true } ],
  "verdict": { "value": "stable", "basis": "agreement" },
  "derivatives": { "label": "finite-difference", "method": "central-difference", "eps": [2e-5, 1e-5], "events_matched": true, "selections": 1, "grazing_threshold": 1e-2 },
  "metrics": { "cost_of_transport": 0.48, "peak_torque_margin": 0.22, "friction_utilization": 0.61, "mean_speed_mps": 0.60 },
  "contact_sequence": "seq:…",
  "standing": "screening: gait-orbit",
  "limits": ["local-stability-only", "this-controller-this-tier", "flat-ground-no-recovery-estimate", "not-an-accepted-controller"],
  "provenance": { "outcome": "converged", "parent_orbit": null, "iterations": 6, "worlds": 229, "world_steps": 57250, "cpu_s": 4.2 }
}
```
Numbers that enter identities or comparisons (periods, rationals of a second) are exact; measured values are `f64`.

**Builder with type-state (DESIGN).** `GaitOrbitBuilder` moves through states that each add a mandatory group: `WithLoop` (design, model, `ControllerId`, tier, world), `WithFixedPoint` (gait, stride, chart, x̄*, residual, drift), `WithSpectrum` (a spectrum whose scope is `full`, or an explicit `Incomplete` marker with the reason), `WithLabels` (derivative labels). Only the last state has `finish()`. There is no public constructor and no `Default`. A spectrum of scope `restricted` can only produce a record whose verdict is `incomplete`. An outcome that is not an orbit (`diverged`, `budget`, `no-seed`, `singular`) has its own small result type and never a `GaitOrbit`: nothing partial is published as an orbit.

**Standing.** `Standing` is an enum owned by this crate with the values `Screening` and `Diagnostic` and no other; it has no conversion to the evidence classes that acceptance reads. Which value new records get is read from `registries/gait.toml` (`orbit_use = "screening" | "diagnostic-only"`). The second value is what the gait kill gate's fallback sets: orbits then serve stability diagnostics and warm starts only, and no design is ranked by an orbit.

**Limits as data.** The four limit codes above are constants of the schema; a renderer prints their sentences: "Local stability only." "Multipliers describe this feedback law on this tier." "A stable orbit on flat ground gives no estimate of recovery on other terrain." "An orbit is not an accepted controller." A record without the list fails validation.

**Identity and memo.** `orbit_id` is the content hash of the canonical record without its provenance block. The memo key of an orbit solve is (model identity, `ControllerId`, tier and step plan, world, gait, stride, tolerances). An edit that changes none of these recomputes nothing. A change of controller, of tier or of a parameter the model depends on voids the stored orbit under the revalidation rules, and the parent's orbit becomes a warm start, not a result.

**Lineage.** `parent_orbit` names the orbit a solve was warm-started from. The provenance block's cost fields let the studio account "reacquisition avoided": solver steps not spent because a child started from a parent's orbit, against a from-scratch control stopped at the same residual.

**Evidence block of an orbit result.** Claim: none (a screening signal makes no claim of the seven kinds). Class `Tested`. Tier and determinism class D2. Identities: design, model, controller, orbit. `reality: no-claim`. The no-authorization flags of the claim product are set.

**What consumers may do (enforced by the consumers, stated here so the label has a meaning).** Discard, under the studio's rules, only where a rank-agreement record for the rung pair (orbit, specialist) meets its threshold for the morphology class and task family; never establish a comparison; never serve as acceptance, promotion or qualification evidence; seed a child's solve; supply a reward reference or a clock.

## Acceptance criteria
- [ ] A `GaitOrbit` cannot be constructed without `ControllerId`, tier, residual, a full-space spectrum or an explicit incomplete marker, derivative labels and standing: a compile-fail test covers each omission.
- [ ] Schema validation rejects a document missing any INV-GAIT-01 field, one whose `standing` is not one of the two values, one without `limits`, and one whose spectrum scope is `restricted` with a verdict other than `incomplete`.
- [ ] INV-GAIT-01 property test: over 10³ generated orbit results (converged, at grazing, order-sensitive, restricted) every emitted record validates and every non-orbit outcome emits no record.
- [ ] The record round-trips through the ledger and the artifact graph: store, load, re-hash to the same `orbit_id`; the provenance block does not affect the identity.
- [ ] Changing a controller gain changes the `ControllerId` and misses the memo; changing an unrelated design annotation hits it.
- [ ] With `orbit_use = "diagnostic-only"` new records carry `standing: "diagnostic"`, and a screening consumer's fixture call that asks to rank by them is refused by that consumer.
- [ ] The text renderer prints the four limit sentences with every orbit; a planted renderer that omits them fails a golden-output test.
- [ ] The evidence block has class `Tested`, `reality: no-claim`, and no claim kind.

- `renderer_prints_limits` (golden output).
### End-to-end script and logging
User-visible through `frob gait orbit --json`, whose envelope carries this record (`scripts/e2e/gait_orbit.sh`, N22a-38, validates every returned record against the schema and asserts the standing and the limits). This bead's runner `scripts/e2e/gait_record.sh` executes the test binaries and writes the shared newline-delimited JSON log to `target/e2e-logs/gait_record/<utc>.ndjson` with a transcript: counts of generated results by kind, validation failures with the first offending field, identities for the round-trip, and a `summary` line.
### Known answers and negative controls
- The invariant is the known content. Negative controls: a record built by a test-only back door without its spectrum (validation must reject it); a restricted spectrum presented as full (the builder cannot express it; the schema check on scope and verdict catches a hand-edited document); a standing of `established` in a hand-edited document; a `diverged` solve that leaks its last iterate as x̄*.
- Metamorphic: reordering the multipliers list does not change the identity (the canonical form sorts them); adding provenance does not change the identity.
- Determinism: canonical serialization is byte-stable across platforms (class D0 for the record given its inputs).

## Considerations
- The schema will grow: autonomous loops add the phase to the removed coordinates and a trivial multiplier that is listed and excluded; multi-mode gaits add a switching verdict. Fields are added by schema version, never by reinterpretation; an old record keeps its identity.
- The kill gate for gaits (decided at M4 on the continuation and rank-agreement gate): if it fires, the registry switch above is the whole downstream change in this crate. The record, the solver and the diagnostics stay.
- Private-scene data: an orbit on flat ground contains none, but x̄* is design-derived; logs carry identities and scalar summaries, never the state blob.
- A lifecycle consumer returns a reduced model to full resolution when a multiplier of the gait orbit approaches the unit circle; that consumer reads `spectral_radius` and `guard` from this record, which is one more reason they are mandatory.
