## Background

Safety here is three separate mechanisms with separate claims (ADR-REFLEX-06): an energy budget that needs
no contact model, runtime filters classed `Tested`, and reduced-order barriers with a measured margin. This
bead is the second and third as one user-visible capability: the **runtime shield**.

**What a shield is.** An `ActionFilter`: a stage between the policy or the baseline controller and the
actuator limiter, which replaces the proposed command u_π by the nearest command that keeps a set of barrier
rows satisfied. It solves: minimize ‖u − u_π‖² in a metric R, subject to A(x̂)·u ≥ b(x̂) + δ and
lo ≤ u ≤ hi, with rows written on a reduced-order template and tightened by a measured tracking margin. When
a row cannot be met, when a solve fails its optimality check, or when an assumption monitor alarms, a backup
controller with a declared domain takes over. It is a runtime filter. Its results are class `Tested`, typed
as a claim product, and nothing converts them into a proof (invariant INV-SHIELD-02).

**Why it is built this way.** Three defects were found in the obvious versions and are designed out: a "for
every disturbance there is a control" condition admits a clairvoyant controller; an infimum over the smaller
friction cone is optimistic for forces the environment chooses; a closed-form projection that ignores the
actuator box returns (1.25, 0.25) where the optimum is (1, 0.5). The surviving form: one control for all
disturbances and estimation errors; separate cones for commanded and environment forces; an exact
sort-and-clip solve for one row, a fixed-iteration solve with a checked optimality certificate and a
verified backup otherwise.

**What it serves.** The bet BET-25 (an energy-budget safety tier with reduced-order shields that add a
statistically measured margin; classed `Tested`, never `Proved`) and the North-Star scenario in which a
runtime shield enforces a budget as a filter on commands, at a measured cost and with a statistically
measured margin. Ceiling: evidence quality only; no speed claim. TARGETs: at most 5% added step cost; at
least 85% of unshielded return kept (measured in BD-339).

Tier Frontier [F]. Crate `frob-shield` (layer 5), with backups in `frob-control`.

## Scope

In: the `Shield` record and its identity; `shield.fit`; the shield half of `shield.check`; the `ActionFilter`
stage wiring with layer records and events; GATE-SHIELD-02. Out: the campaign on in-envelope and shifted

during training (N22b-31); reachable-set tables (BD-440); the two rules of the chapter's later subsections
that extend `shield.fit` and depend on this bead: the timeliness rule for monitored assumptions with its

passivity bound 2·M̄ − h·K_d ⪰ 0 with its gain refusal (N22c-44, GATE-SHIELD-07). Steps 7 and 8 below call
those checks through hooks this bead defines; until they land, `shield.fit` fits the backup gain inside the
no-reversal bound M̄ − h·K_d ⪰ 0 computed by the backup bead (N22b-24) and lists every monitored assumption
with the finding `timeliness: unchecked`, never silently as timely.

## Technical approach

**The record (DESIGN, from the plan's type sketch).**

```rust
/// A runtime shield: a stage of the environment after the policy and before the actuators.
pub struct Shield {
    rows: Vec<BarrierRow>,             // written on a template of 2 to 12 states
    margin: MeasuredMargin,            // ε̂, keyed by design class, policy identity, task family and tier
    backup: BackupController,          // damping injection, posture hold, or widen-lower-freeze
    monitors: Vec<AssumptionMonitor>,  // an alarm also triggers the backup
    budget: Option<EnergyBudget>,
}
pub enum ShieldEvent { Projected { rows: u8 }, Alarm(MonitorId), Backup(BackupKind), Uncovered, MarginRefused }
```

`ShieldId` is the content hash of rows, template, metric R, tolerances, iteration count, margin identity,
backup with its gain, monitors with thresholds and latencies, and the optional budget identity. The shield
has no file format of its own; it is a record in the artifact store.

**`shield.fit`** (kind `run`, first milestone M4). Purpose: rows, measured margins, backup and monitors for a
design, a controller and a task family. Input `frob.shield.fit.in/1`: design, controller or policy identity,
task family, tier, the hard limits to enforce (keep-out regions, speed limits, door-pinch zones, balance
region), α and metric choices, optional energy budget. α is not a command-line input: it is read only from the
OPEN-SHIELD-2 registry entry (step 9), so a second definition cannot arise. Command-line spellings (DESIGN,
fixed here for the VERBS-shield row, whose example is `frob shield fit quad-tray --controller c:2be8 --tasks
kitchen --key sf-1 --json`): the design is positional; `--controller <id>` (a controller or policy identity);
`--tasks <family>`; `--tier <tier>`; `--energy-budget <EnergyBudgetId>` (optional; MCP property
`energy_budget`; renamed from `--budget`, which is the generated compute budget every run verb takes, as the
VERBS-shield row records); `--calibration <N>` (the
calibration count, N22b-29); `--reuse-margin <MarginId>` (a stored calibration offered for reuse, step 4);
`--listing <file|id>` (the monitored-assumption listing, read by N22c-28); `--backup <kind>` with repeated
`--param <name>=<value>` (for example `--backup damping --param kd=300 --param h=0.010`, checked by N22c-44);
`--key <k>`. The hard limits come from the task family's declaration. Steps:

1. Resolve identities; echo them in `bound`. Determine the morphology class and select the template.
2. Build one barrier row per hard limit; tag each force as commanded or environment.
3. Compute coupling components; refuse a component with more than four rows (FROB-REF-454).
4. Obtain the measured margin ε̂ for the scope key (design class, controller or policy identity, task
   family, tier): reuse a stored calibration with that exact key, or run calibration. A margin under any
   other key is refused (FROB-REF-457); the shield never runs on a borrowed margin.
5. Tighten the rows by ε̂ and compute each row's three-part margin δ (inter-sample, estimation error,
   template-to-full).
6. On the calibration set, check that the robust rows have a common admissible command in the box at every
   state; otherwise refuse (FROB-REF-454).
7. Select and fit the backup for the class, with its declared domain and, for damping injection, a gain
   inside the sampled bound checked in exact rationals.
8. Configure the monitors with thresholds, persistence and latency; apply the timeliness rule to every
   assumption listed as monitored.
9. Write the `Shield` record; output `frob.shield.fit.out/1`: `ShieldId`, rows with margins and sources, the
   margin with n and α, the backup with its domain and bound, monitors, findings, the levels in force (α,
   the violation budget, the confidence level and their source, decision identity or `default`, read from
   the OPEN-SHIELD-2 registry entry `registries/shield_levels.toml` of N22b-27 and never from a literal),
   and the claim product (class `Tested`).

**Attaching a shield to a run** (DESIGN). The `ActionFilter` stage enters an environment when the run names
the shield: `--shield <ShieldId>` on `sim.run`, `eval.run` and `train.start` (it enters the run's identity; the
scope check of step 4 runs at start, and a key mismatch emits `MarginRefused` and refuses with FROB-REF-457).
This option is defined here and requested of the VERBS-sim, VERBS-eval and VERBS-train rows; the scripts of
BD-339, BD-340, N22b-31, N22b-32 and NEG-29's S covers use it.

**`shield.check`, shield half** (kind `run`). Input: a run and a shield
(`frob shield check <run> --shield <ShieldId> --key <k> --json`). It replays the run's delivered
transcript: re-evaluates every row at every tick; recomputes each projection independently (single rows by
the rational breakpoint reference; multi-row by a reference solve) and compares with the applied command;
verifies invariant INV-SHIELD-01 at every tick (the box exactly and the active rows within tolerance, or the
backup running); verifies that every applied command has a source (`PassThrough`, `Projected`, `Backup`) and
passed the optimality check where projected (PO-SHIELD-03); recomputes monitor alarms; checks event
consistency. Output `frob.shield.check.out/1`: `holds`, or the first offending tick with recomputed and
recorded values.

**Stage wiring.** The shield implements the `ActionFilter` trait declared in `frob-dyn`. Per tick: the
proposed command arrives; rows are evaluated at the delivered estimate; the projection runs; monitors step;
the applied command and its layer record (`shield-filtered` when projected, `backup` when the backup runs)
and any `ShieldEvent` are written. Every command that reaches a driver records which layer produced it, and
every fallback is a telemetry event with its reason (INV-REFLEX-01).

**Refusals.**

| Code | Meaning | Trigger | Ranked repairs |
|---|---|---|---|
| FROB-REF-454 | A shield's rows have no common admissible command on the calibration set, or more than four are coupled | Step 3 or step 6 | Reduce the row set; widen the actuator box; lower the speed limit |
| FROB-REF-457 | A shield margin is used outside its scope key | Step 4, or running a shield with a policy, class, task family or tier other than its key | Recalibrate for the new policy, class, task family or tier |

Both exit with code 3. `shield.fit` also raises three refusals that have no number yet; each exits with code
3 under its slug and is on no row's list until the allocation ledger (N35-33, N35x-02) numbers it:
`monitored-assumption-not-timely` (N22c-28, through the step-8 hook), `sampled-damping-above-passivity-bound`
(N22c-44, through the step-7 hook) and `insufficient-calibration` (the calibration count below (1 − α)/α,
with the needed count; N22b-29).

## Test plan

### Unit tests

`crates/frob-shield/tests/shield_fit.rs`; the four `gate_*` cases below are the GATE-SHIELD-02 entry of the
`g1_known_answers` tier target of `frob-conformance` (no private gate test file).

- `gate_po_shield_02`: 10⁶ single-row instances; float against rational minimizer; box violations = 0.
- `gate_worked_example`: R = I, u_π = (1, 0), box [0, 1]², row u₁ + u₂ ≥ 1.5 → λ = 0.5, u = (1, 0.5).
- `gate_planted_nonconvergent`: three coupled rows, iteration budget 1 → backup invoked, event recorded.
- `gate_po_shield_03_typestate`: the compile-fail suite.
- `fit_wheeled_keepout`: a differential-drive design, one keep-out disc and a speed limit: unicycle
  template, one row, damping-injection backup, five monitors, margin with its key.
- `fit_five_coupled_refused` (FROB-REF-454), `fit_no_common_command_refused` (the u = d fixture).
- `borrowed_margin_refused`: fitting with a margin calibrated for another policy identity → FROB-REF-457.
- `shield_id_covers_everything`: changing a tolerance, the iteration count, a monitor latency or the backup
  gain changes `ShieldId`.
- `check_first_offender`: a recorded run with one applied command altered after the fact.
- `levels_echoed`: with no decision record the output's levels read α = 10⁻³, budget 10⁻³, confidence 0.95,
  source `default`; after the registry entry is changed to α = 10⁻² the next fit echoes 10⁻² and refits the
  margin instead of reusing the stored one.
- `class_is_tested` and `compile_fail_no_upcast`.
- `laws_c31_on_production_filter`: N10c-02's generic law suite `laws_c31_filter` instantiated on this bead's
  production filter passes, and each of its mutants fails its named law.
- `pending_slugs_uncoded`: the three pending refusals exit 3 under their slugs and appear on no row's refusal
  list; `insufficient-calibration` at 500 episodes and α = 10⁻³ names the needed count 999.
- `attach_shield_to_run`: `--shield <id>` enters the run identity; a run whose policy identity differs from
  the shield's margin key emits `MarginRefused` and is refused with FROB-REF-457; an unknown `ShieldId` is
  refused with FROB-REF-802.
- `energy_budget_spelling`: `shield.fit --energy-budget <id>` enters the shield record and changes its
  `ShieldId`; an unknown `EnergyBudgetId` is refused with FROB-REF-802; `--budget` is parsed as the compute
  budget and never reaches the shield record.
- `matches_compendium_d7`: the single-row shield of the fitted filter returns the D.7 oracle's answer (1, 0.5)
  on its fixture and disagrees with both of the oracle's wrong answers ((1.25, 0.25) unboxed; (1, 0.25)
  clipped); the violation-bound arithmetic of the monitors (N22b-26's estimator fed the oracle's finite
  episode model with planted breach, alarm and violation probabilities) never falls below the oracle's true
  violation probability, and the self-labelled δ₁ = 0 of the oracle's negative control gives a bound the
  oracle marks invalid. The oracle values are read from the compendium's D.7 library (N12-47), never
  regenerated here.

### End-to-end script and logging

`scripts/e2e/shield_runtime.sh` (bead N22b-32) drives `frob shield fit`, a shielded `frob sim run`, and
`frob shield check`, and writes the NDJSON log; its `summary` names GATE-SHIELD-02. The gate's own run logs
one NDJSON line per case (instances, box violations, largest residual, the planted failure caught or not) and
the receipt hash that `record_gate` receives. This bead also turns on the S legs of NEG-29's
`scripts/e2e/hazard_covers.sh` (acceptance above), which log per (hazard, code) the run, the shield identity,
the intervention count on trigger and control, and the exit code.

## Considerations

- KILL-SHIELD (decided after BD-339): if it fires, the energy tier stays, barrier rows become reward
  penalties and alarms, and nothing is called a shield. The row, template and monitor code stays in use; the
  filter stage is not shipped under the name shield.
- OPEN-SHIELD-2 (calibration level α and the per-episode violation budget; default α = 10⁻³ and 10⁻³ per
  episode) is decided in N22b-27 and feeds step 4.
- The reduction of a robot to a template is an assumption that the monitors watch. It is not proved, and
  passivity of the backup establishes neither collision avoidance nor fall avoidance.
- Every export carries the three no-authorization flags; the word "deployable" is not used.
- The bound on violations is per policy and is not claimed under a shift of the world distribution.
