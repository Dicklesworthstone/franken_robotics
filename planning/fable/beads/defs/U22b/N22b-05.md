## Background

The exact layer of skill artifacts answers, before any training, whether a body can realize a skill's
task-space command: per body and contact mode an allocation cone program returns a feasible actuation or a
checked infeasibility witness. The unit tests of the mechanism beads prove the parts. This bead proves the
capability from the user's side: a shell script that drives the real `frob` binary on real fixture files and
asserts what an agent would see, with structured logs detailed enough to diagnose a failure without rerunning.

It also guards against the failure mode the project's testing rules name: a closed bead that proved plumbing.
The script must fail when a planted defect is present, so each assertion group has a negative control run in
the same script.

## Scope

In: one script, its fixtures directory, its log schema use, its negative controls. Out: the mechanisms
themselves; the learned-residual layer.

## Technical approach

**Location and conventions.** `scripts/e2e/skill_exact_layer.sh`, plain POSIX shell, sourcing the shared
helper of the end-to-end harness. Idempotent; every seed explicit; exits non-zero on the first failed
assertion group after writing the summary. Fixtures live in `fixtures/skills/` (synthetic, labelled
`synthetic` in their headers): four `.fbot` designs (`arm-2r-weak`, `pusher-50N`, `cart-tip`, `wheel-speed`)
with a strong variant of each, four `.fskill` files, and the refinement fixture pair.

**Steps.**

1. `frob doctor --json`: record the build, the toolchain and the fingerprint.
2. `frob skill show fixtures/skills/push-cart-level.fskill --json`: assert the five limit texts, the three
   flags all `false`, `evidence.class = "Tested"`, and a stable `SkillId` across two invocations.
3. Round trip: `frob artifact export` then `frob skill show` on the exported file: canonical byte digests
   equal.
4. For each of the four weak bodies: `frob skill compile <skill> --design <body> --key sel-4-<body>-compile
   --json`, then `frob skill check <compiled> --key sel-4-<body>-check --json` (both are run verbs: every call
   of either in this script carries its own `--key`, derived from the step and the body, and no two calls
   whose results are compared share one). Once, on `arm-2r-weak`, also the registry's form `frob skill check
   <skill> --design <body> --key sel-4-arm-direct --json`, asserting the same outcome table. Assert exit code
   3, refusal code FROB-REF-448, and the numbers:
   - `arm-2r-weak`: direction (1, 0), support 8.3333… N (25/3), required 10 N, gap 1.6666… N, binding joint 2;
   - `pusher-50N`: certificate y = (0.5, −1), yᵀb = −5 N, binding contact;
   - `cart-tip`: support 49.05 N, binding front support;
   - `wheel-speed`: support 40 N, binding actuator.
5. For each emitted certificate bundle: `frob-verify <bundle>` on the same machine with no GPU: assert
   `accept`. Then corrupt one coefficient of the bundle (y nudged outside the dual cone) and assert `reject`
   with the first failing rule named.
6. For each strong variant: `frob skill check --replay --json`: assert exit code 0, outcome `feasible` at
   every sampled state, replay error below the recorded tolerance, `sufficiency = "necessary-only"`.
7. Refinement: `frob skill check --refinement` on the {stable, fall} pair: assert exit code 3, FROB-REF-444,
   uncovered successor `fall`; on the all-stable pair: exit code 0.
8. Negative controls for the map: run the gate's tier target with its controls, `FROB_TEST_SEED=1 cargo test
   -p frob-conformance --test g1_known_answers --features gauntlet-mutations -- GATE-REFLEX-08`, and assert from
   its receipt that the space-frame mutant (the space-frame rows used as the tool Jacobian) is `caught` with a
   bound on the arm that differs from 25/3 N, so the arm fixture is shown to discriminate, and that the
   fixed-base-pullback mutant (τ = JᵀF on the floating-base `cart-tip`) is `caught` calling the 60 N push
   feasible (6 N·m of wheel torque inside the 10 N·m limit) where the production path refuses it at 49.05 N, so
   the cart fixture discriminates CX-243.
9. Determinism: repeat step 4 with `FROB_WORKERS=1` and `FROB_WORKERS=8` in the environment (the worker count
   is a property of the pool, not an input of `skill.check`, whose row has no such option) and with keys
   suffixed `-w1` and `-w8`, so that each repeat computes again; assert identical outcome tables and
   certificate digests.
10. Cancellation: start `frob skill check <skill> --design <body> --grid 100000 --key sel-10 --json` (a
    10⁵-state grid), cancel through `frob job cancel`, assert the
    final state is `cancelled` with no verdict published.

**Logging.** Newline-delimited JSON to `target/e2e-logs/skill_exact_layer/<utc-timestamp>.ndjson` and a
human-readable transcript beside it. Every line has `ts`, `script`, `bead` (`N22b-05`), `step`, `event`
(`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact command line, exit code, wall time, and the
envelope's `evidence` block (claim, class, tier, determinism, identities, seed). `metric` lines carry measured
values with units and thresholds (support, required, gap, replay error). `refusal` lines carry code, pointer,
observed, required, repairs. On a failed assertion the line carries the first differing value and the paths
of the artifacts needed to reproduce (the fixture, the compiled skill, the bundle). The final `summary` line
gives assertions passed and failed and `gates: ["GATE-REFLEX-08"]`. No private-scene data is logged; the
fixtures are synthetic.

## Acceptance criteria

- [ ] The script exists, passes on a clean checkout, and fails (non-zero) when any of these planted defects is
      enabled by its environment switch: the space-frame Jacobian mutant in the production path; the
      fixed-base pullback used for a floating-base body; the exists-quantifier refinement mutant; a
      certificate checker that skips cone membership.
- [ ] Every assertion in steps 2 to 10 is logged with measured value and threshold.
- [ ] The log validates against the harness's log schema and contains the `summary` line with the gate.
- [ ] Two consecutive runs produce identical assertion outcomes and identical certificate digests.

## Test plan

### Unit tests

The script's helper functions (number comparison with tolerance, envelope field extraction) are those of the
shared harness and are tested there. This bead adds `scripts/e2e/tests/skill_exact_layer_selftest.sh`, which
runs the script against a recorded envelope set with one value altered (support 8.4 in place of 25/3) and
asserts a non-zero exit and a log line naming the first differing value.

### End-to-end script and logging

As described under Technical approach. Commands used: `frob doctor`, `frob skill show`, `frob skill compile`,
`frob skill check` (with `--replay`, `--refinement`, each call with its `--key`), `frob artifact export` (a
run verb, with `--key` and `--out` under the session's export root), `frob job cancel`,
and the offline auditor `frob-verify`.

### Known answers and negative controls

KA-565 (25/3 N, joint 2), KA-556 (y = (0.5, −1), −5 N), KA-566 (refinement refused), KA-567 (4 of 4 refused,
witnesses replay). Negative controls: CX-236 (space-frame rows), CX-243 (fixed-base pullback on a floating
base), CX-242 (select the stable branch), the nudged certificate. Determinism lanes: twice on one machine; across worker counts; debug and release builds (the
script accepts `FROB_BIN` to point at either build).

## Considerations

- The script asserts numbers to stated tolerances: exact for rational outputs (25/3 printed as a rational
  pair), 10⁻⁹ relative for floating-point supports.
- If the verb registry changes a flag name, the script changes with it; the fixtures and numbers do not.
- Runtime target: under two minutes on a laptop CPU; the 10⁵-state cancellation step uses a budget cap so a
  failed cancel cannot run away.
