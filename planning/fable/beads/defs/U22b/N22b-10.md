## Background

The energy-budget safety tier states a safety claim that needs no contact model: for a declared boundary (a
stop, a bumper, a door at the end of its travel, a lift platform, a compliant cover that may touch a person),
everything that could deliver energy to the boundary is bounded, and the absorber there can take that much:

    E_deliv = T_ub + E_drive + E_ext + E_stored + E_reserve  ≤  W_abs.

The claim is only as good as the arithmetic that decides the inequality. A floating-point comparison near the
boundary can differ between a CPU and a GPU, or between two compilers. The budget is therefore a document
whose quantities are **decimal strings**, converted to **integers at declared unit scales**, so that the
admission predicate is evaluated exactly, with the same value on every backend, and can be recomputed by an
offline auditor that has neither the simulator nor a GPU (proof obligation PO-SHIELD-01).

This bead defines that document: format FMT-FENERGY, extension `.fenergy`, schema `frob.energy/1`. FACT (the
plan's format registry): owner and producer `frob-shield`; consumers `frob-shield`, `frob-mission` and
`frob-lemma`; canonical.

Rejected alternatives. Binary floating-point fields (rounding enters the predicate and differs across
backends). Rational fields without a scale (the runtime monitor needs fixed-width integers). One global unit
scale for the workspace (budgets for a 2 J bumper and a 2 kJ lift platform need different resolutions).

Terms. *Load path*: the components whose motion or stored energy can reach the boundary. *Absorber*: the
element at the boundary that takes work before a limit (bottoming, or a stated force limit). *Provenance*:
where a number came from; a value marked `assumed` makes every claim built on it `Estimated`.
*No-authorization flags*: `execution_authorized`, `hardware_safety_signoff`, `sim_to_real_certified`, all
`false`.

## Scope

In: schema, types, parsing of decimal strings to exact rationals, scale conversion with directed rounding,
the two methods `admits` and `longest_cutoff_delay`, canonical bytes and identity, validation, registry row
content. Out: computing the term values from a design (N22b-11); the premise checks (N22b-12); the runtime
kernel (N22b-13); the certificate kind (N22b-14); the verbs (BD-337).

## Technical approach

**Document (DESIGN sketch; the drop-stop card with no reserve).**

```json
{ "schema": "frob.energy/1",
  "boundary": "dock_stop_A",
  "load_path": ["chassis", "payload", "drive_left", "drive_right"],
  "unit_scale": { "energy": "1e-6 J", "time": "1e-6 s" },
  "terms": {
    "kinetic_ub": { "mass_cap_kg": "8", "speed_error_mps": "0.01", "includes_reflected_inertia": true },
    "drive": { "p_max_w": "20", "cutoff_delay_s": "0.025" },
    "external": [{ "source": "gravity", "bound_j": "0.25", "basis": "slope <= 0.08 over 0.040 m" }],
    "stored": [{ "source": "series_spring", "bound_j": "0.10" }],
    "reserve_j": "0.00" },
  "absorber": { "card": "bumper-50N-40mm", "w_abs_j": "2.00", "provenance": "assumed" },
  "premises": { "sources_complete": "port-graph-digest", "absorber_on_path": "declared-guide" },
  "claim": { "class": "Estimated", "reality": "no-claim" },
  "authorization": { "execution_authorized": false, "hardware_safety_signoff": false,
                     "sim_to_real_certified": false } }
```

**Types (DESIGN, `crates/frob-shield/src/energy/budget.rs`).**

```rust
pub struct EnergyBudget {
    boundary: BoundaryId,
    load_path: Vec<ComponentId>,   // every port that can inject power is listed or cut (FROB-REF-451)
    unit_scale: UnitScale,         // energy and time, each an exact rational number of SI units per integer step
    terms: Terms,                  // kinetic_ub, drive, external[], stored[], reserve
    absorber: Absorber,            // card, w_abs, provenance
    premises: Premises,            // sources_complete, absorber_on_path
    claim: ClaimProduct,
}
impl EnergyBudget {
    /// Admit iff T_ub + E_drive + E_ext + E_stored + E_reserve ≤ W_abs, as integers at the declared scale.
    pub fn admits(&self, speed_reading: Qty) -> bool;
    /// (W_abs − T_ub − E_ext − E_stored − E_reserve) / P_max, rounded down to the time scale.
    pub fn longest_cutoff_delay(&self, speed_reading: Qty) -> Qty;
}
```

**Exact arithmetic rules.**

1. Every quantity string is parsed to an exact rational (decimal digits and an optional power-of-ten
   exponent; no binary float is ever constructed).
2. Conversion to integers at the declared scale uses **directed rounding**: every term on the left of the
   inequality rounds up to the next integer step; W_abs rounds down. A quantity that is already a multiple of
   the step converts exactly.
3. Kinetic term for a reading r: v̂ = |r| + speed_error; T_ub = ⌈½·mass_cap·v̂²⌉ in energy steps. With several
   measured speeds the term is the quadratic form ½·v̂ᵀ·M̄·v̂ with M̄ an entrywise cap (see N22b-11); the
   document then carries `kinetic_ub.channels` and `kinetic_ub.mass_cap_matrix` (upper triangle, decimal
   strings) in place of the scalar pair. The scalar form is the registered sketch; the matrix form is its
   generalization within schema version 1.
4. Drive term: E_drive = ⌈p_max·cutoff_delay⌉. With equal energy and time exponents (10⁻⁶ J and 10⁻⁶ s) one
   watt is one energy step per time step, so 20 W × 25,000 steps = 500,000 steps.
5. `admits` compares the integer sum with the integer W_abs using ≤. The runtime monitor (N22b-13) is
   stricter at the boundary: it cuts when the margin W_abs − E_deliv is not positive. DESIGN: static admission
   accepts equality because the terms are already upper bounds; the runtime cut treats zero margin as
   exhausted, as the plan states ("at zero margin it cuts drive power").
6. `longest_cutoff_delay` = ⌊(W_abs − T_ub − E_ext − E_stored − E_reserve)/p_max⌋ in time steps; if the
   numerator is not positive the result is zero and the budget does not admit at that reading.
7. Bit budget: all intermediates are computed in fixed-width integers whose width is derived from the declared
   ranges at build time; a budget whose products would exceed 256 bits is refused with the workspace's
   bit-budget refusal (FROB-REF-215), which is the signal to choose a coarser scale.

**Canonical form and identity.** Canonical JSON (sorted keys, no insignificant whitespace, decimal strings
kept as written after normalization: no leading plus, no trailing zeros beyond the declared scale's digits).
`EnergyBudgetId` is the BLAKE3 of the canonical bytes. The `premises.sources_complete` value is the digest of
the port graph that was walked, so a design edit that touches the graph changes the identity of any budget
built on it.

**Validation order.** Schema and unknown fields; decimal syntax; positive scales; non-negative terms; every
`external` and `stored` entry names a source; `includes_reflected_inertia` present; `absorber.provenance`
one of the provenance vocabulary; `claim.class` not above the weakest input (an `assumed` absorber with a
class above `Estimated` is refused with FROB-REF-451, second clause); flags present and false. Every refusal
carries the JSON pointer of the failing field, exit 3, under the code the registries assign: an unknown field
or a `schema` major version this build does not read, FROB-REF-891 (the version gate of N34-19's owner trait;
the shield chapter has no code of its own for it); a missing or non-false flag, FROB-REF-816 (the shared reader
check, N37-23); the class rule, FROB-REF-451; the bit budget, FROB-REF-215; every other step (decimal syntax,
a binary-float literal, a non-positive scale, a negative term, an unnamed source, a missing
`includes_reflected_inertia`, a provenance outside the vocabulary), the surface's schema refusal FROB-REF-802.

**Determinism and class.** Parsing, conversion and both methods are class D0. The document's `claim` is a
claim product; this bead stores it and checks its internal consistency, and N22b-11 computes it.

## Acceptance criteria

- [ ] `crates/frob-shield/src/energy/budget.rs` holds the types, reader, writer, the two methods and
      `EnergyBudgetId`; `frob-shield` ships `CONTRACT.md` with its ten sections.
- [ ] The sketch parses, re-serializes to identical canonical bytes, and at a reading of 0.39 m/s gives
      T_ub = 640,000, E_drive = 500,000, E_ext = 250,000, E_stored = 100,000, sum 1,490,000 ≤ 2,000,000.
- [ ] `longest_cutoff_delay` at that reading is 50,500 µs; with `reserve_j` "0.10" it is 45,500 µs and the sum
      is 1,590,000.
- [ ] The pass-counter artifact gives 3,993,600 ≤ 4,500,000 at a reading of 0.50 m/s, margin 506,400,
      cutoff 42,660 µs.
- [ ] Directed rounding is shown by a case that is admitted under rounding to nearest and refused under
      directed rounding.
- [ ] A document with a missing or `true` flag, a binary-float literal in a quantity field, a negative term,
      or class `Tested` on an `assumed` absorber is refused with a pointer.
- [ ] The registry row content is supplied and the round-trip check passes for `.fenergy`.

## Test plan

### Unit tests

`crates/frob-shield/tests/energy_format.rs`.

- `sketch_roundtrip_and_id`: bytes equal after a round trip; identity pinned in a golden file.
- `card_integers_at_039`: reading 0.39 m/s, error 0.01: v̂ = 0.40; ½·8·0.16 = 0.64 J → 640,000; total
  1,490,000.
- `card_integers_at_040`: reading 0.40 m/s: v̂ = 0.41; ½·8·0.1681 = 0.6724 J → 672,400; total 1,522,400;
  still admitted; cutoff ⌊(2,000,000 − 672,400 − 250,000 − 100,000)/20⌋ = 48,880 µs.
- `reserve_shortens_cutoff`: 50,500 → 45,500 µs.
- `pass_counter_card`: the numbers in the acceptance list.
- `directed_rounding`: mass cap "3", speed "0.3331", error "0", every other term zero:
  ½·3·0.11095561 = 0.166433415 J, which is 166,433.415 steps; directed rounding gives 166,434, rounding to
  nearest gives 166,433. With W_abs = "0.166433" J (166,433 steps) the budget is refused; a mutant that rounds
  to nearest admits it and must be caught.
- `equality_admits_statically`: a sum equal to W_abs returns `admits = true`.
- `bit_budget`: energy scale "1e-80 J" with a mass cap of 10⁶ kg and a declared speed range up to 10 m/s:
  the kinetic term alone is ½·10⁶·10² J = 5 × 10⁷ J = 5 × 10⁸⁷ energy steps, about 2²⁹², so the budget is
  refused at build with FROB-REF-215 (the cap is on the derived bit budget from the declared ranges, not on
  the scale itself); the same budget at "1e-18 J" (5 × 10²⁵ steps, about 2⁸⁶) is accepted.
- Property test: for random decimal budgets, `admits` equals the comparison of exact rationals after directed
  rounding, and `longest_cutoff_delay·p_max ≤ numerator < (longest_cutoff_delay + 1)·p_max`.

## Considerations

- The plan's sketch shows the flags as a placeholder string under `claim`, and the worked artifact uses the
  key `flags`; this bead uses a top-level `authorization` object as the output envelope and the certificate
  bundle do. Recorded in the unit's coverage notes.
- The card's "0.4 m/s" is read as the inflated speed v̂ (reading 0.39 m/s plus the 0.01 m/s error); at a
  reading of 0.40 m/s the kinetic term is 0.6724 J. Both are tested.
- `basis` is provenance text in version 1 and is not parsed. Where the builder derives a bound itself it
  rounds outward; the printed 0.25 J for gravity is a declared bound (the raw product is 0.251136 J).
- Schema migration: a version 2 that parses `basis` would be a new schema identifier with a migration; version
  1 documents stay readable.
