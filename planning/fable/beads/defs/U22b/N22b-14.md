## Background

An energy budget is a claim that a stop absorbs everything that can reach it:
T_ub + E_drive + E_ext + E_stored + E_reserve ≤ W_abs, with a term for every source on the load path. The
system's rule for any claim of class `Certified` is that an independent checker, sharing a file format and
nothing else with the producer, must be able to recompute it. That checker is the offline auditor
`frob-verify`: a single binary built from the Rust standard library only, with no simulator, no GPU and no
network, containing its own canonical-JSON reader, BLAKE3, big-integer and rational arithmetic and one small
checker per proof kind. It returns `accept`, `reject` or `unsupported`, with the first failing rule named.

The registry of proof kinds is closed. One of its rows is `energy-budget`: "the inequality of C-31 with its
error bounds and its list of sources". Theorem card T-28 states what is to be checked: *an energy budget
satisfies its inequality with outward-rounded error bounds, and it has a term for every source on the
declared load path*; route: exact rational or interval arithmetic plus a structural check against the port
graph; tier Solid. This bead implements the kind on both sides: the writer (in `frob-lemma`, called by
`frob-shield`) and the checker (in `frob-cert`).

It also implements proof obligation PO-SHIELD-01 (the energy inequality is an exact-integer predicate with
the same value on every backend; verified by recomputing offline from the `.fenergy` file and the run's
integer telemetry) and the mutation corpus that the bet behind this tier is judged on: BET-25 is falsified by
**any false admission on the `.fenergy` mutation corpus**.

Why the checker repeats the structural check. Arithmetic alone cannot see an omitted source: a budget without
its gravity term still adds up. The bundle therefore carries the port-graph source list, and the auditor
verifies that every listed source has a term.

## Scope

In: the writer of `energy-budget` bundles in `frob-lemma`; the run-replay step of the kind's checker in
`frob-cert` (the recomputation of T, E and margin per tick and of the cut latch from a run's integer telemetry,
PO-SHIELD-01), with the `run` member of the payload; the absorber step of the same checker (W_abs recomputed
from the absorber card's bytes carried in the bundle, member `absorber_card`, rule `energy.absorber-mismatch`;
both listed in N12-17, whose copy of the payload and of the rule vocabulary governs, in the same way the
run-replay step is listed there as implemented by this bead); the mutation corpus with its expected verdicts,
on which BET-25 is judged; registration of the kind's fixtures; the mission-scope proof object of the kind in
`frob-core` (the `ProofKind::EnergyBudget` variant and its payload type, which N25b-01 leaves to this bead).
Out: the bundle payload, the checker's static rules (parse and flags, sources, terms and basis, the inequality
in its two readings, class, statement domain), their rule identifiers and the accepted and rejected specimens
of the static checker: these are N12-17, the Lemma chapter's checker bead, on which this bead depends (directly
and through CARD-T-28). This bead writes no second payload, no second checker and no second rule vocabulary; it
adds two steps to that checker (run replay and the absorber recomputation). Also out: producing the budget
(N22b-10 to N22b-12); the absorber card and its integral (N22bx-01, which this step re-implements on the
auditor's own arithmetic and never links); the kernel (N22b-13); the generic bundle format and the other kinds
(Lemma beads).

## Technical approach

**Bundle payload (inside a `.frobcert` bundle; DESIGN; defined by N12-17 and reproduced here so that the
writer can be built from this text; N12-17's copy governs, and it adds the members `reading`, `level` and the
optional `basis` of a source to the sketch below).**

```json
{ "kind": "energy-budget",
  "statement": "E_deliv <= W_abs at boundary dock_stop_A for readings in [0, r_max]",
  "primitive_equations": ["E_deliv = T_ub + E_drive + E_ext + E_stored + E_reserve",
                          "T_ub = ceil(1/2 * v_hat^T * M_cap * v_hat)", "v_hat = |r| + err"],
  "payload": { "budget": { "...": "the full .fenergy document" },
               "sources": [ { "component": "drive_left", "port": "shaft", "class": "drive",
                              "covered_by": "terms.drive" }, "..." ],
               "port_graph_digest": "b3:…",
               "reading_domain": { "r_max": "0.39" },
               "absorber_card": { "hash": "b3:…", "bytes": "<canonical .fcard bytes of kind absorber>" },
               "run": null },
  "assumptions": [ { "input": "absorber.w_abs_j", "provenance": "assumed", "class": "Estimated" }, "..." ] }
```

For a run replay the `run` member holds the run identity and the digest of the integer telemetry stream
(readings, T, E, margin, cut bit per tick).

**Writer (`frob-lemma`, called from `frob-shield`).** Assembles the payload from the budget, the premise
report and (optionally) a run; never calls the auditor's decision code to construct it; writes the three
no-authorization flags as `false`; lists every assumption as an input with its own claim product (a bundle
whose assumptions are missing is refused by the auditor).

**Verb input (`prove.bundle`, the budget form, M4; this bead is in the VERBS-prove row's "Extended by").** In
the same `frob-lemma` change this bead wires the row's budget form and its fields in
`frob.prove.bundle.in/1` and `frob.prove.bundle.out/1`: a positional `EnergyBudgetId` (the identifier
`shield.budget` prints, told from an answer address by its identifier type) writes one `energy-budget` entry
with `run` null; `--run <id>` beside it names a run made under that budget (`sim.run --shield-budget`) and the
entry then carries the `run` member; a run not made under that budget is FROB-REF-802 with `pointer: /run`;
`--run` with neither `--kind control-program` nor a budget stays FROB-REF-802; `--out <path>` names the
`.frobcert` file or directory; `--key` as for every run verb.

**Checker (`frob-cert`, kind `energy-budget`).** The checker and its seven steps are N12-17's: (1) parse and
flags; (2) sources against terms, the digest and the `level` declaration; (3) terms recomputed with directed
rounding at the largest reading, and a term checked against its `basis` where one is given; (4) the inequality
on the integers; (5) the class against the weakest input; (6) run replay; (7) the statement's quantifier and
domain. Its fourteen rule identifiers, as N12-17 defines them, are the eleven of the static steps,
`energy.parse`, `energy.flags`, `energy.source-missing`, `energy.term-without-source`, `energy.digest-mismatch`,
`energy.gravity-undeclared`, `energy.term-mismatch`, `energy.term-below-basis`, `energy.inequality`,
`energy.class-above-inputs` and `energy.domain`, and the three of the steps this bead implements,
`energy.tick-mismatch`, `energy.cut-latch` (run replay) and `energy.absorber-mismatch` (the absorber step,
N12-17's step 3a).

This bead implements step 6, in `crates/frob-cert/src/kinds/` beside the static steps: for a bundle whose `run`
is not null, read the integer telemetry, recompute T, E and margin for every tick from the raw readings,
compare with the recorded values (`energy.tick-mismatch`, with the tick), and check that the cut bit is set at
the first tick with margin ≤ 0 and stays set (`energy.cut-latch`). Before this step exists a bundle with a run
is `unsupported`. The checker claims nothing about whether a run happened: it recomputes arithmetic and
structure, and its report states its trusted base.

This bead also implements the absorber step, run after N12-17's step 3 (terms) and before step 4
(inequality): the auditor parses `absorber_card` with its own canonical reader, checks that its BLAKE3 equals
both `absorber_card.hash` and the hash in the embedded budget's `absorber.card`, recomputes W_abs from the
card's lower envelope exactly as N22bx-01 defines it (trapezoids over the decimal knots up to x_lim, the
stroke or the first crossing of the force limit; each knot's force and the stroke reduced by their stated
uncertainties; exact rationals; rounded down to the energy step), and rejects with
`energy.absorber-mismatch` a budget whose W_abs integer exceeds the recomputed one or whose card hash
differs. Without this step the only defence against an inflated W_abs is the bundle hash, which a writer that
re-hashes consistently defeats (mutant 16). A bundle with no `absorber_card` member is accepted by the other
steps with W_abs as written, and the report states "absorber not recomputed" and caps the claim at
`Estimated`.

**Proof object in `frob-core` (mission scope, exclusion by energy, T-28).** The closed registry
`frob.cert.kinds/1` already lists `energy-budget` with the `mission` scope at version 1, and N25b-01 keeps it on
the pending list of its name test until this bead adds it. This bead adds the variant `ProofKind::EnergyBudget`
and its payload `crates/frob-core/src/proof/payload/energy_budget.rs`, following N25b-01's module layout and
rules: exact numbers only (integers at the declared unit scales and decimal rationals, no floating-point
field), ordered collections, a non-empty `Support.implicit` (the absorber card, the gravity frame, the model
version), and `expects` = `Excluded` for the exclusion reading (a crossing that needs more potential rise than
all admitted energy has no controller) or `Inner` for the holds reading. The payload type mirrors the members
of the bundle payload below (budget digest, sources, port-graph digest, reading domain, absorber card hash, run
digest) and is mapped to and from the bundle by `frob-lemma`, which owns that mapping. In the same change the
kind is removed from the pending list of N25b-01's name test, which then lists `monomial-product` only.

**Mutation corpus (`frob-conformance`, registered against BET-25).** Each mutant is a bundle derived from
the drop-stop card or the pass-counter artifact, except mutant 5, which is derived from N22b-10's
directed-rounding fixture (on the drop-stop card T_ub is exactly 640,000 steps, so rounding to nearest
changes nothing there); each must be rejected. A single accepted mutant is a false
admission.

**Three readings of the drop-stop card's gravity term (DESIGN; the same statement is in the pilot N22b-09, the
card GB-26 and the checker bead N12-17, so that no two beads give "the card" different totals).** The plan prints
8 × 9.81 × 0.040 × 0.08 = 0.25 J and derives 1.49 J, 50.5 ms and 45.5 ms from it; the product is 0.251136 J.
(1) *Printed*: the term entered as the declared 0.25 J with no structured basis (250,000 in units of 10⁻⁶ J):
total 1,490,000, margin 510,000, longest cutoff delay 50,500 µs, or 45,500 µs with the reserve; KA-153 and
KA-568 are asserted on it to the printed digits. (2) *Product*: the term as the product its basis gives,
251,136: total 1,491,136, margin 508,864, delay 50,443.2 µs, or 45,443.2 µs with the reserve; this is the
governing reading, because a bound may not be rounded down. (3) *Outward*: written with fewer digits than its
basis the term is rounded up: 0.26 J at two decimals (total 1.50 J, delay 50.0 ms). The checker accepts all
three and rejects a fourth specimen in which 0.25 J is offered together with the basis (8 kg, 9.81 m/s²,
0.0032 m of rise) that it falls short of.
The corpus derives its mutants from the printed reading (the bundle of 1,490,000), from the pass-counter
artifact and, for mutant 5, from N22b-10's directed-rounding fixture; the specimen `energy.term-below-basis` belongs to N12-17's own tests and is not a mutant of this
corpus.

## Acceptance criteria

- [ ] The writer's bundles of the drop-stop card in its printed reading (1,490,000 ≤ 2,000,000) and its product
      reading (1,491,136 ≤ 2,000,000) and of the pass-counter artifact (3,993,600 ≤ 4,500,000) are accepted by
      `frob-verify` (the checker of N12-17), with class `Estimated` and the absorber named as weakest input.
- [ ] All 16 mutants are rejected, each with the expected first failing rule; zero false admissions.
- [ ] The absorber step recomputes 2,000,000 from `bumper-50N-40mm` and 4,500,000 from `bumper-150N-30mm`
      (the cards of N22bx-01) on the auditor's own arithmetic, and the writer embeds the card bytes in every
      bundle it writes.
- [ ] A run of the monitor on `batch-cpu` and on each available device produces integer telemetry from which
      the auditor recomputes identical margins at every tick (PO-SHIELD-01).
- [ ] The run-replay step builds with an empty dependency table inside `frob-cert`, and the kind's line count
      (the static checker of N12-17 plus this step) is reported against the auditor's size cap.
- [ ] The writer and the checker share no code; a test asserts that `frob-shield` does not link the checker's
      decision functions.
- [ ] The kind's fixtures and mutants are registered in the negative-control registry
      (`crates/frob-conformance/registry/controls.toml`, one row per mutant with its expected first failing
      rule), and the corpus runs as `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test
      g1_known_answers --features gauntlet-mutations -- energy_mutation_corpus`.
- [ ] `ProofKind::EnergyBudget` and its payload exist in `frob-core` with no floating-point field; N25b-01's
      name test passes with `energy-budget` an enum variant and no longer on its pending list.

## Test plan

### Unit tests

`crates/frob-lemma/tests/energy_bundle.rs` (writer), `crates/frob-cert/tests/kind_energy_run_replay.rs` (step
6), `crates/frob-core/tests/proof_energy_budget.rs` (the proof object), and the corpus as the
`energy_mutation_corpus` entry of the `g1_known_answers` tier target of `frob-conformance`, run against the real
checker (no private corpus test file). The static checker's own tests are in N12-17's `kinds_energy_product.rs`.

- `proof_object_energy_budget`: the variant's name equals the registry row; the payload has no float field
  (the compile-time assertion of N25b-01); an exclusion object constructed with `expects = Inner` is refused;
  the writer's bundle maps to the object and back with an identical digest; N25b-01's name test passes with
  the pending list reduced to `monomial-product`.

- `accept_drop_stop`, `accept_pass_counter`: the writer's bundles, as in the acceptance list.
- `mutant_01` … `mutant_16`: one test per row of the corpus, asserting `reject` and the rule identifier.
- `absorber_step` (`crates/frob-cert/tests/kind_energy_absorber.rs`): the two catalog cards give 2,000,000
  and 4,500,000; the ramp card with a 40 N limit gives 640,000 (x_lim = 32 mm); a card whose knot force
  carries an uncertainty of 1 N gives 1,960,000 for the 50 N bumper; a bundle without `absorber_card` is
  accepted with "absorber not recomputed" and class at most `Estimated`.
- `omitted_gravity_control`: the known answer's control ("a budget without the gravity term over the stroke
  is rejected by the checker"), on a bundle produced by the writer and then mutated (the checker-side test of
  the same control is N12-17's `energy_missing_gravity_rejects`).
- `exclusion_reading` (the same inequality read as an exclusion), on bundles produced by the writer: lifting
  8 kg over a 12 mm sill needs 8·9.81·0.012 = 0.94176 J; against a 0.90 J budget the crossing is excluded;
  adding 0.05 J of approach kinetic energy (0.95 J) removes the exclusion; an exclusion bundle with the
  approach-energy term omitted is rejected.
- `independent_parser_agreement`: for 10⁴ random decimal budgets the auditor's integers equal those of
  `frob-shield`.
- `run_recompute`: a 2,000-tick synthetic telemetry stream (`synthetic`) with the cut at tick 1,217.
- `bundle_verb_budget_form`: `prove.bundle` with a positional `EnergyBudgetId` writes one `energy-budget`
  entry with `run` null; with `--run` naming a stored run record made under that budget (a fixture record; the
  run made through `sim.run --shield-budget` is N22b-18's step) the entry carries the `run` member; a run made
  under another budget is FROB-REF-802 with `pointer` `/run`; `--run` alone is FROB-REF-802.

### End-to-end script and logging

`scripts/e2e/shield_energy_budget.sh` (N22b-18) runs `frob prove bundle <budget> --out <path> --key <k> --json`
for a budget and `frob prove bundle <budget> --run <run> --out <path> --key <k> --json` for a run (distinct
keys), then `frob-verify` on each written file in a directory with no GPU and no network access, then the
mutant set. NDJSON lines carry the
bundle hash, the verdict, the first failing rule and, for run replays, the first differing tick.

### Known answers and negative controls

KA-153 (the card; the omitted-term control), KA-154 (the exclusion: 0.94176 J against 0.90 J; 0.05 J removes
it), KA-568, the pass-counter artifact. CX-076 (leaving out small sources) and CX-109 (an exact argument over
`Estimated` inputs is `Estimated`) are mutants 1 and 9. Determinism: the checker is class D0 and gives the
same verdict on every host.

## Considerations

- The auditor cannot attest that the port graph in the bundle is the design's. That link is the digest in the
  budget plus the artifact graph; the report says so.
- Size: one more checker counts against the auditor's cap (TARGET at most 12,000 lines in total); this kind
  needs only the rational and integer arithmetic already present.
- If KILL-ENERGY fires the kind stays in the registry (the exclusion reading used by mission queries still
  needs it), and budgets are emitted as alarms without a `Certified` arithmetic claim.
