## Background

The energy-budget safety tier compares everything that can deliver energy to a boundary with W_abs, the lower
envelope of the work the absorber at that boundary takes before its limit (bottoming, or a stated force
limit). W_abs is a property of a physical part: a bumper, a bump stop, a damper, a compliant cover. A
simulator cannot measure it. The same is true of the drive's peak power and cutoff delay.

The evidence class of a budget is set by its weakest input. If the absorber's envelope is a guess, the whole
claim is a guess, however exact the arithmetic. The plan records this as an open question:

**OPEN-SHIELD-1.** Where absorber envelopes come from before any bench data exist. Owner: the Sinew lead (the
subsystem that owns cards for actuators, transmissions and interfaces) with Ground (the subsystem that
imports physical measurements). It blocks any energy claim above `Estimated`. Fail-closed default, in force
until decided: `assumed` cards and `Estimated` claims.

This is a decision bead: it does not build a mechanism. It records the options, the default that holds
meanwhile, what the decision must contain, and what changes when it is made.

## Scope

In: the options, the criteria, the default, the decision record, and the changes to cards and to the budget
builder's class rule that follow. Out: the bench measurement itself and its import (Ground); the card schema
(Sinew); the builder (N22b-11).

## Technical approach

**What an absorber envelope is, as data.** A lower envelope F_lo(x) of force against displacement up to a
limit x_lim (bottoming or a stated force limit), with W_abs = ∫₀^x_lim F_lo dx; the conditions it holds under
(temperature range, strain-rate range, number of prior cycles); and provenance per field.

**Options to decide between (each with what it would license).**

| Option | Source | Provenance label | Highest class of a budget built on it |
|---|---|---|---|
| A (default) | A generic card written by hand from the part's nominal rating (for example "50 N over 40 mm") | `assumed` | `Estimated` |
| B | A manufacturer datasheet envelope, transcribed with the document on file and a derating factor for temperature and ageing | `datasheet` | `Estimated` for statements about a physical robot; the arithmetic claim about the model may cite the datasheet as its input |
| C | A bench measurement imported through Ground: force–displacement traces at stated rates, with a sealed holdout and a frozen prediction | `measured` | Up to the class the Ground lane grants for the calibrated cell; reality may leave `no-claim` for that cell only |
| D | A structural calculation of the absorber from material cards (a compliant cover as a beam or pad model) | `derived`, inheriting the material card's provenance | No better than the material card |

**What the decision must state.**

1. Which options are admitted at M4 and which wait for the Ground lane at M5.
2. For option B: the derating rule and who transcribes and checks the datasheet.
3. For option C: the minimum bench protocol (displacement rates, number of specimens, temperature points)
   and how a lower envelope is formed from traces (DESIGN proposal: the pointwise minimum over specimens
   minus the instrument bound, never a mean).
4. Whether a budget may mix sources (for example a measured absorber with an assumed drive), which the
   claim-product rule already answers: the weakest input wins.
5. The first two absorbers to obtain, if any (the plan's worked cards use a 50 N over 40 mm bumper and a
   150 N over 30 mm bumper as illustrations).

**Default in force until decided (fail-closed).** Every absorber card is `assumed`; every budget is
`Estimated`; a request for a higher class is refused with FROB-REF-451 (second clause: a class above
`Estimated` is requested on an `assumed` absorber envelope), with the repair "import the absorber
measurement"; reality is `no-claim`.

**Effect of the decision on code.** None on the builder's arithmetic. The provenance vocabulary of interface
cards gains or confirms the labels above; the builder's leaf claim products map each label to a class; the
budget report's first suggested action remains "the measurement that would raise the weakest input".

## Acceptance criteria

- [ ] A decision record exists naming the admitted options, the derating rule (if B), the bench protocol (if
      C), the envelope-forming rule and the owner who signs it.
- [ ] Until the record exists, a test shows the default holds: an `assumed` absorber yields `Estimated`, and
      a request for more is refused with FROB-REF-451.
- [ ] After the record: the provenance labels it admits are in the card schema, and the builder maps each to
      the class the record states; a card with an unknown label is refused.
- [ ] The record is cited by the budget report's "weakest input" line and by the M4 exit review's list of
      open questions.

## Test plan

### Unit tests

`crates/frob-shield/tests/open_shield_1_default.rs`.

- `assumed_is_estimated`: the worked card with provenance `assumed` → class `Estimated`, weakest input
  `absorber.w_abs_j`.
- `refuse_higher_class`: request `Tested` → FROB-REF-451, repair text present, exit code 3.
- `label_to_class_table`: for each admitted label the mapping equals the decision record's table (the test
  reads the table from `registries/` so that the record and the code cannot drift).
- `lower_envelope_rule` (applies when option C is admitted): three synthetic traces (`synthetic`) of a
  nominal 50 N constant-force absorber reading 49, 51 and 50.5 N over 40 mm with an instrument bound of 0.5 N
  give F_lo = 48.5 N and W_abs = 1.94 J, not the mean's 2.007 J.

### End-to-end script and logging

Part of `scripts/e2e/shield_energy_budget.sh` (N22b-18): `frob shield budget … --class Tested --json` on the
`assumed` card must exit with code 3 and FROB-REF-451; the script logs the refusal envelope and the
`weakest` field of the default output.

### Known answers and negative controls

The worked pass-counter artifact states the rule this decision governs: "the claim is `Estimated`, not
`Certified`, because the absorber envelope is `assumed`: the arithmetic is exact and the weakest input sets
the class". CX-109 (an exact argument over `Estimated` inputs is `Estimated`) is the shortcut the default
blocks. Negative control: a card whose provenance was edited from `assumed` to `measured` without a Ground
import record must be refused by the provenance check.

## Considerations

- Nothing in M4 waits on this decision: the default is sufficient for GATE-SHIELD-01, which is about the
  model.
- One absorber measurement and one drive measurement would serve every later policy for that hardware, since
  no term of the budget depends on the policy. That is the argument for spending bench effort here first.
- Risk of option B: datasheets state typical, not minimum, curves. The derating rule must say so, and the
  label must not be confused with `measured`.
- No physical hardware is in scope of the program; option C is an import lane with a recorded `no-claim`
  until data exist.
