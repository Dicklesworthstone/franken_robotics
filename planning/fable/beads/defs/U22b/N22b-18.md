## Background

The energy-budget safety tier bounds everything that can deliver energy to a boundary and compares the total
with what the absorber there can take: T_ub + E_drive + E_ext + E_stored + E_reserve ≤ W_abs, evaluated as an
exact-integer predicate from a `.fenergy` document. Its parts are tested where they live. This bead proves
the capability from the user's side: a shell script that drives the real `frob` binary and the offline
auditor on fixture files, asserts the numbers an agent would see, and logs enough to diagnose any failure
without rerunning. Each assertion group has a planted defect that must make the script fail, because a test
that nothing can fail validates nothing.

## Scope

In: one script, its fixtures, its negative controls, its logs. Out: the 10⁴-sequence campaign, which has its
own script (N22b-15); runtime barrier shields (N22b-32).

## Technical approach

**Location and conventions.** `scripts/e2e/shield_energy_budget.sh`, POSIX shell, sourcing the shared helper
of the end-to-end harness; idempotent; seeds explicit; non-zero exit on failure after the summary is written.
Fixtures in `fixtures/shield/energy/` (all `synthetic`): the design `drop-stop-cart.fbot` with its absorber
card `bumper-50N-40mm` (provenance `assumed`), the design `pass-counter-quad.fbot` with `bumper-150N-30mm`,
the variant `drop-stop-cart-spring-b.fbot` with a planted unlisted spring, the variant with a geared
rotor of 5 × 10⁻⁵ kg·m² behind 50:1 on a 0.05 m wheel, and the variant `drop-stop-cart-slope.fbot` whose scene
carries the 8% slope (the product reading). `drop-stop-cart.fbot` has no slope in its scene and declares the
gravity bound 0.25 J (the printed reading).

Every call of a `run` verb carries `--key` (`seb-<step>-<n>`), distinct wherever a step compares two runs or
two budgets; spellings are the ones BD-337 fixes (positional design, `--boundary`, `--reading-max`,
`--reserve`, `--class`; `--shield-budget` on `sim.run`; `--energy-budget` on `shield.check`, whose `--budget`
is the generated compute budget).

**Steps.**

1. `frob doctor --json`: record build and fingerprint.
2. `frob shield budget drop-stop-cart --boundary dock_stop_A --reading-max 0.39 --key seb-2 --json` (printed
   reading). Assert exit code 0 or 2 (the gravity bound enters as `declared`, BD-337 decides whether an
   unverified declared input is a finding); integer terms 640,000, 500,000, 250,000, 100,000; sum 1,490,000; W_abs 2,000,000;
   margin 510,000; longest cutoff delay 50,500 µs; class `Estimated`; `weakest` = `absorber.w_abs_j`;
   `reality` = `no-claim`; three flags `false`; the "does not support" list present.
   Product reading: `frob shield budget drop-stop-cart-slope --boundary dock_stop_A --reading-max 0.39 --key
   seb-2-slope --json`: gravity 251,136 with the finding `declared-below-derived`; sum 1,491,136; margin
   508,864; cutoff 50,443 µs; exit code 2.
3. The same with `--reserve 0.10 --key seb-3`: sum 1,590,000; cutoff 45,500 µs (product reading with reserve,
   key `seb-3-slope`: 45,443 µs).
4. Pass-counter card at `--reading-max 0.50` (key `seb-4`): 2,433,600 + 1,200,000 + 110,000 + 150,000 +
   100,000 = 3,993,600 ≤ 4,500,000; margin 506,400; cutoff 42,660 µs (the declared gravity 110,000 is above the
   derived 105,948, so no finding).
5. Round trip: `frob artifact export <budget> --out <tmp> --key seb-5 --json`, re-read the `.fenergy`, compare
   canonical byte digests and identities.
6. Refusals: the planted-spring design → exit code 3, FROB-REF-451, `pointer` at the spring's port, two
   repairs in order ("bound the source", "cut it"). `--class Tested` on the `assumed` absorber → exit code 3,
   FROB-REF-451, repair "import the absorber measurement".
7. Rotor variant (key `seb-7`): the budget is not admitted at 0.39 m/s (kinetic term 4.64 J at 0.4 m/s
   inflated speed); exit code 2, a result and not a refusal; the output names the kinetic term and states the
   largest admissible speed bound v̂ = 0.1991 m/s and reading 0.1891 m/s (v̂ less the 0.01 m/s error); assert
   both, and that the gravity term is still 250,000 (reflected inertia carries no weight).
8. Certificate: `frob prove bundle <budget of step 2> --out <tmp>/seb-8.frobcert --key seb-8 --json` (the
   VERBS-prove row's budget form, M4); run `frob-verify <tmp>/seb-8.frobcert` from a directory with no network
   access and no GPU; assert `accept`. Then for each mutant in `fixtures/shield/energy/mutants/` (omitted
   gravity term, rounded-to-nearest kinetic term, class above weakest input, flag set to `true`, altered
   margin in a run replay, `w_abs_j` raised to 2.10 with the bundle re-hashed consistently) assert `reject`
   and the expected first failing rule (the last one `energy.absorber-mismatch`).
9. Run with the monitor: `frob sim run drop-stop-cart --tier referee --shield-budget <id> --seed 7 --key
   seb-9-referee --json` with the adversarial approach command (`--seed` as BD-024 defines it for `sim.run`;
   `--shield-budget` as BD-337 defines it); then `frob shield check <run> --energy-budget <id> --key seb-9-check
   --json`. Assert verdict `holds`; the cut tick is present; the layer record after the cut is `backup`;
   absorbed work from `frob telemetry energy <run> --json` is at most 2.00 J.
10. Backends: repeat step 9 on `batch-cpu` and on each device `frob spark probe --key seb-10-probe --json`
    reports, each run with its own key (`seb-10-<tier>`); assert the margin series digests are identical
    across backends (class D0) and that `frob-verify` recomputes each, on the run-replay bundle written by
    `frob prove bundle <id> --run <run> --out <tmp>/seb-10-<tier>.frobcert --key seb-10-<tier>-bundle --json`.
11. Policy independence (MR-22): rebuild the budget after swapping the command policy and after changing the
    friction coefficient and the contact law in the task; assert the budget identity is unchanged.
12. Absorber card (steps `absorber_*`, specified with the card in N22bx-01): `frob actuator list --kind
    absorber --json` lists the four catalog cards, and `frob actuator show bumper-50N-40mm --json` shows kind
    `absorber`, stroke, provenance `assumed`; `frob actuator check bumper-50N-40mm --json` exits 0 with the
    kind's field rules and no electromechanical check, and with `--strict-data` exits 3 with FROB-REF-113; the
    document of step 2 with `w_abs_j` edited to "2.50", read through `frob shield check <run of step 9>
    --energy-budget <edited .fenergy> --key seb-12-copy --json` (exit code 3, FROB-REF-451, pointer
    `absorber.w_abs_j`); the budget with the temperature condition outside
    the card's range (exit code 3, FROB-REF-451, pointer at the condition); `frob-verify` on the bundle of
    step 8 (the budget of step 2) recomputes W_abs = 2,000,000 from the embedded card.
13. Provenance and class (specified with the decision OPEN-SHIELD-1 in N22b-17): the worked card with the
    absorber card at each provenance label available, requesting each claim class; log provenance,
    requested and granted class, refusals with their code, and the decision record's status (`open` or its
    path); under the default every request above `Estimated` is refused with FROB-REF-451.

**Logging.** NDJSON to `target/e2e-logs/shield_energy_budget/<utc-timestamp>.ndjson` with a transcript
beside it. Every line: `ts`, `script`, `bead` (`N22b-18`), `step`, `event` (`start`, `cmd`, `assert`,
`metric`, `refusal`, `end`), the exact command line, exit code, wall time, the envelope's `evidence` block
(claim, class, tier, determinism, identities, seed). `metric` lines carry each integer term with its
expected value, the margin, the cutoff, the absorbed work against W_abs, and digests where state is compared.
`refusal` lines carry code, pointer, observed, required and repairs. On failure: the first differing value
and the paths of the budget, the bundle and the run needed to reproduce. The final `summary` gives assertions
passed and failed and `gates: ["GATE-SHIELD-01"]`. Fixtures are synthetic, so no private-scene data can
appear.

## Acceptance criteria

- [ ] The script exists and passes on a clean checkout on the CPU-only path; device steps are skipped with a
      logged reason when no device is present.
- [ ] It fails (non-zero) under each of its declared plants (STD-E2E: header `plants`, switched by
      `E2E_PLANT_FAILURE` and injected by the script, checked by `run-all.sh --verify-plants`), each feeding a
      step the output of one defect: a budget built without the reflected rotor inertia (step 7); a budget
      whose source list lacks the planted spring, as a premise walk that follows mechanical edges only writes
      it (step 6); a margin series with the kinetic term rounded to nearest (step 10); the omitted-gravity
      bundle in place of step 8's accepted one; the bundle with `w_abs_j` raised and re-hashed in place of
      step 12's. The code mutants themselves are caught where they live (N22b-11 to N22b-14); product
      binaries never carry `gauntlet-mutations` (STD-TEST).
- [ ] Every assertion in steps 2 to 13 is logged with measured value and expected value.
- [ ] Two consecutive runs give identical assertion outcomes, budget identities and margin digests.

## Test plan

### Unit tests

`scripts/e2e/tests/shield_energy_budget_selftest.sh`: runs the script against a recorded envelope set in
which the sum is 1,490,001; asserts a non-zero exit and a log line naming the first differing value. The
helper functions are tested by the harness bead.

### End-to-end script and logging

As above. Commands: `frob doctor`, `frob shield budget`, `frob shield check --energy-budget`, `frob artifact
export`, `frob prove bundle`, `frob sim run --shield-budget`, `frob telemetry energy`, `frob spark probe`,
`frob actuator list --kind absorber`, `frob actuator show`, `frob actuator check`, and the offline auditor
`frob-verify`. Every
`run` call carries its own `--key`, logged on its `cmd` line; the product-reading and rotor assertions log
the finding or the largest admissible reading beside the expected value.

### Known answers and negative controls

KA-568 (1.49 J ≤ 2.00 J; 50.5 ms; 45.5 ms), KA-569 (50 kg of reflected mass), the worked pass-counter
artifact (3,993,600; 506,400; 42.7 ms), KA-153 (omitted-gravity control). CX-239 (payload-only budget),
CX-076 (omitted small source). Metamorphic relation MR-22 (step 11). Determinism lanes: twice on one machine;
across worker counts; debug and release (via `FROB_BIN`); across backends at class D0 for the predicate.

## Considerations

- Numbers are asserted exactly (integers at 10⁻⁶ J and 10⁻⁶ s); the absorbed-work assertion uses the ledger's
  residual bound as its tolerance.
- The script does not run the 10⁴-world campaign; it runs one adversarial world as a smoke check and leaves
  the gate count to the campaign script.
- If KILL-ENERGY fired, steps 2 to 4 assert the alarm wording and class `Estimated` instead of the claim
  sentence; the integers do not change.
