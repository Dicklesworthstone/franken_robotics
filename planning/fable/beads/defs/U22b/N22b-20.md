## Background

A shield is an `ActionFilter`: a stage between the policy or the baseline controller and the actuator
limiter, which replaces the proposed command u_π by the nearest command that keeps a set of barrier rows
satisfied. It is a runtime filter. Its results are class `Tested`, typed as a claim product, and nothing
converts them into a proof (invariant INV-SHIELD-02).

The filter solves: minimize ‖u − u_π‖² in a metric R, subject to A(x̂)·u ≥ b(x̂) + δ and lo ≤ u ≤ hi. This
bead defines the constraint side: what a row is, where its coefficients come from, what the margin δ contains,
and two rules of formulation that the obvious versions violate. The projection
itself is in N22b-22 and N22b-23; the templates the barriers are written on are in N22b-21.

**The two rules, and the mistakes they prevent.**

- *Quantifier order.* There must exist one command, chosen from delivered information, that satisfies the
  rows for every admitted disturbance and estimation error. The reverse order ("for every disturbance there
  is a command") lets the command depend on the disturbance, which no controller can do. Smallest case: if
  safety needs u = d with the disturbance d ∈ {−1, +1}, each pointwise problem is feasible and no single
  input serves both.
- *Split cones.* Contact forces the robot commands are limited to the inner friction cone K(μ_min). Forces
  the environment may apply range over the outer cone K(μ_max). Taking the infimum over the inner cone for
  forces the environment chooses is optimistic: an infimum over a smaller set is larger.

Tier Frontier. Crate `frob-shield` (layer 5); the trait lives in `frob-dyn` so that layer-4 and layer-5
crates need no edges among themselves.

## Technical approach

**A row.** For a barrier function hᵢ(x) ≥ 0 on a template with control-affine dynamics ẋ = f(x) + G(x)·u,
the condition ḣᵢ + α(hᵢ) ≥ 0 is linear in u:

    aᵢ(x̂)ᵀ·u ≥ bᵢ(x̂),   aᵢ = G(x̂)ᵀ·∇hᵢ(x̂),   bᵢ = −∇hᵢ(x̂)ᵀ·f(x̂) − α(hᵢ(x̂)),

where x̂ is the delivered estimate of the template state and α is a class-K function declared with the row
(DESIGN default: linear, α(h) = κ·h, with κ recorded). A row whose aᵢ is zero at a state has no authority
there and is reported, not silently dropped.

**The margin δᵢ = δ_is + δ_est + δ_trk** (each part declared and recorded per row):

1. *Inter-sample term* δ_is = Lᵢ·Δt, where Lᵢ bounds the time derivative of the row's left side
   aᵢᵀ·u − bᵢ over one control period Δt along admitted trajectories with the command held. It covers what
   happens between ticks.
2. *Estimation-error term* δ_est = sup over the estimation-error set ℰ of the change of aᵢ(x̂ + e)ᵀ·u − bᵢ(x̂ + e)
   for commands in the actuator box, computed from Lipschitz bounds of aᵢ and bᵢ and the radius of ℰ.
3. *Template-to-full term* δ_trk: the barrier is tightened by the measured tracking margin ε̂ between the
   template and the full robot. hᵢ is replaced by hᵢ − ‖∇hᵢ‖·ε̂ (the realized state may be ε̂ closer to the
   boundary than the template state), so the row gains δ_trk = α(hᵢ) − α(hᵢ − ‖∇hᵢ‖·ε̂), which is
   κ·‖∇hᵢ‖·ε̂ for the linear α. ε̂ comes from calibration, keyed by design class, controller or policy
   identity, task family and tier. Every margin part has the dimension of the row (the rate of hᵢ); the
   kernel dimension checker enforces it.

**Quantifier order, as an operation.** Disturbances w and estimation errors e enter a row through f and
through x̂. The row used by the filter is the robust row

    aᵢ(x̂)ᵀ·u ≥ bᵢ(x̂) + δᵢ + sup over admitted (w, e) of [the disturbance's contribution to −ḣᵢ],

so the same u satisfies it for every admitted (w, e). The fitting step refuses any row whose robust form
needs the disturbance as an argument of the command. A certificate or test that establishes rows in the
order "for every (w, e) there is a u" is rejected by the checker (the mismatch of quantifier prefix is the
condition of the certificate refusal FROB-REF-826).

**Assumption ranges.** A monitored assumption (for example μ ∈ [μ_min, μ_max]) may be left outside the
supremum only if its monitor and backup are timely (the rule of the pre-slip aliasing subsection); otherwise
its whole range goes inside the supremum.

**Split cones, as an operation.** Each force appearing in a row is tagged `commanded` or `environment`.
Commanded forces are constrained to K(μ_min) (a force the robot plans to rely on must be available at the
lowest admitted friction). Environment forces are maximized over K(μ_max) in the supremum (a force that can
hurt must be assumed as large as the highest admitted friction allows). The tag is part of the row's type;
an untagged force does not compile.

**Common admissible command.** At fit time, on every state of the calibration set, the row set must have at
least one u in the box satisfying all robust rows: checked by the same cone solver with its optimality check.
A row set with no common admissible command on the calibration set is refused with FROB-REF-454 (repairs:
reduce the row set; widen the actuator box; lower the speed limit).

**Data and lowering (DESIGN).**

```rust
pub struct BarrierRow { id: RowId, template: TemplateId, h: KirProgram, grad_h: KirProgram,
    alpha: ClassK, forces: Vec<ForceTag>, lipschitz: Qty /* L_i */, est_radius: Qty,
    margin: RowMargin /* δ_is, δ_est, δ_trk with their sources */ }
pub enum ForceTag { Commanded { cone: InnerCone }, Environment { cone: OuterCone } }
```

Row evaluation (aᵢ, bᵢ, δᵢ at x̂) is a straight-line kernel program so that the filter runs batched on every
tier; the first implementation is the CPU reference.

## Test plan

### Unit tests

`crates/frob-shield/tests/filter_rows.rs`.

- `row_from_barrier_1d`: single integrator ṗ = u with a wall at p_max = 1.0: h = 1 − p, ∇h = −1, G = 1,
  f = 0, α(h) = 2·h. At p = 0.5: a = −1, b = −1.0, so the row is −u ≥ −1.0, that is u ≤ 1.0 m/s. With
  ε̂ = 0.05 m: δ_trk = κ·ε̂ = 2·0.05 = 0.10 m/s, and the row becomes u ≤ 0.90 m/s.
- `inter_sample_term_braking` (the sampled braking barrier): a cart at range s and speed v with braking
  deceleration μ_min·g = 2.943 m/s² and Δt = 0.02 s. Continuous-time barrier h = s − v²/(2·2.943). At
  s = 0.70 m, v = 2.0 m/s: h = 0.70 − 0.6796 = 0.0204 > 0, so a filter without δ_is permits coasting; one
  tick later s = 0.66 m and braking stops the cart 0.6796 − 0.66 = 0.0196 m beyond the line. With the
  inter-sample term v·Δt = 0.04 m the row is s ≥ v²/(2·2.943) + v·Δt = 0.7196 m and coasting at 0.70 m is
  refused. The overshoot of the mutant is at most v·Δt = 0.04 m. The fixture is the chapter's sampled-data
  case: its filter tests the sampled state's membership of the backup's domain, so the barrier and the term
  are written at the level of h, in metres, the term being the inter-sample bound sup|ḣ|·Δt of a held coasting
  tick (|ḣ| = v); a row's δ_is, which has the dimension of the rate of h, is the specification's
  `inter_sample_margin` case of the acceptance list.
- `quantifier_fixture`: scalar u ∈ [−1, 1], rows u ≥ d and −u ≥ −d for d ∈ {−1, +1}. Per-d feasible
  (u = d); jointly infeasible. Expect FROB-REF-454.
- `split_cone_fixture` (DESIGN numbers): a body of weight 100 N; an environment friction force bounded by
  μ·N opposes the commanded motion; μ_min = 0.3, μ_max = 0.8. The robust row needs commanded authority of at
  least 80 N; the mutant using μ_min concludes 30 N suffices. A command of 50 N passes the mutant row and
  fails the correct one.
- `estimation_term`: with a(x) = x and ℰ = [−0.1, 0.1], box |u| ≤ 2: δ_est ≥ 0.1·2 = 0.2.
- `zero_authority_reported`: a row with a = 0 at a state is flagged `no-authority`.
- `untagged_force_compile_fail` (trybuild).

## Considerations

- L, the estimation radius and κ are declared numbers with sources; an undeclared one is an error at fit,
  never a default of zero.
- Conservative margins cost return; the gate on shielded return (at least 85% of unshielded) is where that
  cost is measured, and δ's three parts are reported separately so the dominant one is visible.
- The bound on violations is not claimed under a shift of the world distribution; rows are fitted for a task
  family and say so.
- If KILL-SHIELD fires, rows remain as definitions of reward penalties and alarms; the row type is unchanged
  and nothing is called a shield.
