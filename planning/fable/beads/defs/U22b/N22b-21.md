## Background

A runtime shield filters commands so that barrier functions stay non-negative. A barrier function with a
usable guarantee cannot be written on a full robot: sum-of-squares methods reach about five to ten states; a
diagonally dominant relaxation reached 30 states only for balancing with pinned feet and no input limits;
and FrankenSim's `certify_roa` uses a fixed quadratic Lyapunov function with a largest example of two states
(FACT: `frankensim/crates/fs-sos/src/roa.rs`). So no full-order certificate is attempted (ADR-REFLEX-06), and
barriers are written on a **template of 2 to 12 states**: a single integrator or a unicycle for a base
(keep-out zones, speed limits, door-pinch zones), a linear inverted pendulum or a capture point for a legged
body. A tracking controller realizes the template's filtered command on the full robot.

The template's guarantee reaches the robot only through the tracking error ε between commanded and realized
template state, and ε depends on inputs, disturbances and the full state, so it cannot be computed in advance
(FACT, source register). It is measured and labelled as measured (the calibration bead). FACT: reduced-order
barrier filters run on real legged and aerial hardware under a tracking assumption, and their published
hardware results say constraints are "rarely violated". They are strongest for wheeled and tracked bases and
for slow legged motion.

This bead supplies the templates: their states, inputs, dynamics, the barrier functions offered on each, the
map from robot state to template state, and the interface to the tracking controller.

## Scope

In: four templates with their barrier constructors; the robot-to-template state map; the template-to-robot
command interface; the definition of the tracking error signal; template selection by morphology class. Out:
the row algebra and margins (N22b-20); projection (N22b-22, N22b-23); measuring ε̂ (N22b-29); reachable-set
tables on templates of at most four states (BD-440).

## Technical approach

**Common interface (DESIGN, `crates/frob-shield/src/filter/templates.rs`).**

```rust
pub trait Template {
    fn id(&self) -> TemplateId;                 // content hash of kind and parameters
    fn dim(&self) -> usize;                     // 2 to 12
    fn drift(&self, x: &[Qty]) -> Vec<Qty>;     // f(x)
    fn input_matrix(&self, x: &[Qty]) -> Mat;   // G(x)
    fn from_robot(&self, est: &StateEstimate) -> Vec<Qty>;   // x̂ from delivered estimates only
    fn command_kind(&self) -> CommandKind;      // what the tracking controller receives
}
```

**The four templates.**

| Template | State | Input | Dynamics | Barriers offered | Realized by |
|---|---|---|---|---|---|
| Single integrator | p ∈ ℝ² (base position), 2 states | u = velocity command | ṗ = u | Keep-out disc h = ‖p − c‖ − r; half-space h = nᵀp − d; time-varying door swept region as a moving half-space; speed limit as the input box | The base's velocity-tracking controller or policy |
| Unicycle with look-ahead | (x, y, θ), 3 states | (v, ω) | ẋ = v·cos θ, ẏ = v·sin θ, θ̇ = ω | The same position barriers evaluated at the look-ahead point p_ℓ = p + ℓ·(cos θ, sin θ), whose velocity is [[cos θ, −ℓ·sin θ], [sin θ, ℓ·cos θ]]·(v, ω), so every row has relative degree one in (v, ω); curvature and speed boxes | Wheeled and tracked baseline controllers (twist command) |
| Linear inverted pendulum | (x, ẋ) per horizontal axis, 2 or 4 states | Zero-moment-point position p_z | ẍ = ω₀²·(x − p_z), ω₀ = √(g/z₀) for centre-of-mass height z₀ | Centre-of-mass position inside a region; velocity bounds | The legged baseline's stance-force program |
| Capture point | ξ = x + ẋ/ω₀ per axis, 1 or 2 states | p_z | ξ̇ = ω₀·(ξ − p_z) | ξ inside the support polygon shrunk by the margin: for each edge with inward unit normal n and offset d, h = nᵀξ − d | Footstep placement and stance forces of the legged baseline |

DESIGN: the unicycle's look-ahead length ℓ is a declared parameter (default 0.1 m); the barrier then guards
the look-ahead point and the keep-out radius is enlarged by ℓ so that the body point is also covered.

**Selection.** By morphology class of the design: wheeled, steered, omnidirectional and tracked bases use the
single integrator (omnidirectional) or the unicycle; legged bodies use the capture point for balance barriers
and the single integrator on the base for keep-out barriers; an arm on a base uses the base's template for
base barriers (arm-space barriers such as joint limits and capsule distances are written directly on joint
coordinates and need no template). A class with no template is refused at fit with the reason.

**Robot-to-template map.** `from_robot` uses delivered estimates only (the invariant filter's base pose and
velocity; never privileged state), so the filter has the same information a deployed controller would.

**Tracking error signal.** For calibration and monitoring, the template is integrated from the delivered
estimate under the filtered command; the error at a tick is ε(t) = ‖x_template(t) − from_robot(estimate(t))‖
in the template's position coordinates, with re-anchoring of the integrated template to the estimate at a
declared interval (DESIGN default: the barrier's look-ahead time 1/κ). The per-episode score is the largest
ε(t). The signal is exported as a telemetry channel.

**Worked rows (hand-checkable).**

- *Keep-out disc, single integrator.* c = (0, 0), r = 0.5 m, κ = 2 s⁻¹. At p = (0.9, 0) with margin
  0.3 m folded into r: h = 0.9 − 0.8 = 0.1, ∇h = (1, 0); row u₁ ≥ −0.2 m/s. A proposed (−1, 0) is filtered
  to (−0.2, 0).
- *Capture point, one axis.* z₀ = 0.5 m gives ω₀ = √(9.81/0.5) = 4.429 rad/s. Support interval
  p_z ∈ [−0.10, 0.10] m. Barrier h = 0.10 − ξ (keep ξ below the front edge), ḣ = −ω₀·(ξ − p_z). With
  α(h) = ω₀·h the row is −ω₀·(ξ − p_z) + ω₀·(0.10 − ξ) ≥ 0, that is p_z ≥ 2ξ − 0.10. At ξ = 0.06 m:
  p_z ≥ 0.02 m, feasible inside the support. At ξ = 0.11 m the state is outside the safe set (h < 0) and the
  row p_z ≥ 0.12 m cannot be met within [−0.10, 0.10]: the backup (widen the stance, lower the body, freeze)
  runs.
- *Unicycle look-ahead.* θ = 0, ℓ = 0.1 m, wall at x_ℓ ≤ 1.0, x_ℓ = 0.9, κ = 2: row −v ≥ −0.2, v ≤ 0.2 m/s;
  ω does not appear at θ = 0 for a wall normal to x, and appears with coefficient −ℓ·cos θ for a wall
  normal to y.

## Acceptance criteria

- [ ] The four templates implement the common interface; each has `dim` between 1 and 12 and a stable
      `TemplateId`.
- [ ] Every barrier constructor returns rows of relative degree one in the template's input, verified by a
      test that the input coefficient is non-zero away from documented singular sets.
- [ ] The three worked rows reproduce to round-off.
- [ ] `from_robot` reads only delivered estimates (a test with privileged state withheld still runs; a test
      double that reads truth fails the access-class check).
- [ ] Template selection returns the documented template per morphology class and a typed reason for an
      unsupported class.
- [ ] The tracking-error channel is produced with its re-anchoring interval recorded.

## Test plan

### Unit tests

`crates/frob-shield/tests/filter_templates.rs`.

- `disc_row`: the keep-out numbers above; also p = (0.8, 0): h = 0, row u₁ ≥ 0 (no motion toward the disc).
- `capture_point_row`: ω₀ = 4.4294 rad/s; ξ = 0.06 → p_z ≥ 0.02; ξ = 0.10 → p_z ≥ 0.10 (only the edge);
  ξ = 0.11 → infeasible in the support box.
- `unicycle_lookahead_velocity`: at θ = π/2, ℓ = 0.1, (v, ω) = (1, 2): ṗ_ℓ = (−0.2, 1.0).
- `lip_consistency`: integrating ẍ = ω₀²·(x − p_z) from (x, ẋ) = (0.02, 0.1) with p_z = 0 gives
  ξ(t) = ξ(0)·e^(ω₀·t) with ξ(0) = 0.02 + 0.1/4.4294 = 0.04258 m; at t = 0.1 s ξ = 0.0663 m (to 10⁻⁴).
- `door_swept_region`: a door edge sweeping at 0.5 rad/s defines a moving half-space; the row's b includes
  the boundary's normal speed, and a base standing still inside the future swept region is commanded away.
- `relative_degree_one`: property test over random states for each constructor.
- `selection_by_class`: the mapping table.

### Known answers and negative controls

The worked rows above are this bead's known answers (hand-derived here; the plan fixes the template list and
not the numbers). Negative controls: a unicycle barrier written at the body point without look-ahead (the
input coefficient of ω is zero and the constructor must refuse it); a capture-point row with the sign of the
normal reversed (must command the zero-moment point the wrong way and fail the test). Metamorphic relation:
translating and rotating the world and the regions together leaves every row's scalar values unchanged.
Determinism: row values are class D2.

## Considerations

- The reduction of a robot to a template is an assumption that the monitors watch (tracking error above the
  calibrated margin is an alarm). It is not proved.
- Legged balance barriers are the weakest case: the legged backup is `Tested` only, with no passivity claim
  once contacts switch.
- A template of more than 12 states is refused; the cap is the plan's.
- Performance: evaluating a template row is a few dozen arithmetic operations; the 5% step-cost target is
  dominated by the projection, not by the templates.
