## Background

A runtime shield replaces a proposed command u_π by the nearest command, in a metric R, that satisfies its
barrier rows and stays inside the actuator box lo ≤ u ≤ hi. Most ticks of most shields have **one** active
row. For one row and a diagonal metric the problem has an exact solution that needs no iterative solver, and
this bead implements it.

The tempting shortcut is the textbook closed form for projecting onto a half-space, followed by clipping to
the box. It is wrong. Counterexample (CX-240, hand-checkable): R = I, u_π = (1, 0), box [0, 1]², row
u₁ + u₂ ≥ 1.5. The unboxed projection is (1.25, 0.25), which leaves the box. Clipping it gives (1, 0.25),
which violates the row (1.25 < 1.5). The true minimizer is (1, 0.5). A filter that returns (1, 0.25) has
silently let an unsafe command through while reporting success.

The exact method: with multiplier λ ≥ 0 on the row a·u ≥ c (c = b + δ), stationarity and the box give
u(λ) = clip(u_π + λ·R⁻¹·a, lo, hi). The scalar aᵀu(λ) is nondecreasing and piecewise linear in λ with at most
2n breakpoints for n actuator channels. Sort them and take the smallest λ ≥ 0 with aᵀu(λ) ≥ c. If the maximum
of aᵀu over the box is below c, the row cannot be met within the actuators and the backup controller runs.

Proof obligation PO-SHIELD-02: the single-row projection equals the exact minimizer and never leaves the box;
verified against a rational reference on 10⁶ instances.

## Scope

In: the algorithm in exact rationals (the reference), in `f64` and `f32` (the product), the infeasibility
branch, the result type handed to the checked-command machinery, the batched kernel form. Out: two to four
rows (N22b-23); the backup itself (N22b-24); row construction (N22b-20).

## Technical approach

**Problem.** minimize ½·(u − u_π)ᵀ·R·(u − u_π) subject to aᵀu ≥ c and lo ≤ u ≤ hi, with R = diag(R₁, …, Rₙ),
Rᵢ > 0.

**Algorithm.**

1. u⁰ = clip(u_π, lo, hi). If aᵀu⁰ ≥ c, return u⁰ with λ = 0 (the row is inactive; note that a proposed
   command outside the box is already clipped here).
2. Feasibility: s_max = Σᵢ max(aᵢ·loᵢ, aᵢ·hiᵢ). If s_max < c, return `RowInfeasible` (the caller invokes the
   backup).
3. For each channel with aᵢ ≠ 0 let gᵢ = aᵢ/Rᵢ. The unclipped coordinate is u_π,ᵢ + λ·gᵢ. It enters the box
   at λ_in,ᵢ and leaves it at λ_out,ᵢ, the two values of λ at which it meets loᵢ and hiᵢ in the direction of
   travel (for gᵢ > 0: (loᵢ − u_π,ᵢ)/gᵢ and (hiᵢ − u_π,ᵢ)/gᵢ; for gᵢ < 0 the roles of lo and hi swap).
   Negative values are replaced by 0. These are the at most 2n breakpoints.
4. Sort the breakpoints ascending (ties in a fixed order by channel index).
5. Walk the segments. Maintain the value S = aᵀu(λ) and the slope σ = Σ over channels currently strictly
   inside the box of aᵢ·gᵢ = Σ aᵢ²/Rᵢ ≥ 0. On each segment [λₖ, λₖ₊₁], if S + σ·(λₖ₊₁ − λₖ) ≥ c then
   λ* = λₖ + (c − S)/σ and stop; otherwise advance S, update σ at the breakpoint (a channel entering the box
   adds its term, a channel leaving removes it) and continue.
6. Return u* = clip(u_π + λ*·R⁻¹·a, lo, hi) and λ*.

Step 2 guarantees the walk terminates with a solution. The result satisfies the box exactly (the clip is the
last operation) and the row with equality in exact arithmetic.

**Floating point.** In `f32` or `f64` the computed aᵀu* may fall short of c by rounding. The product version
therefore (a) evaluates the row residual after step 6 and, if it is negative, moves λ* up by one unit in the
last place repeatedly, re-clipping, until the residual is non-negative or the row tolerance is met (a bounded
loop of at most a declared number of nudges, DESIGN default 4); (b) reports the residual; (c) never returns a
point outside the box. The row tolerance is declared in the shield's identity. Invariant INV-SHIELD-01: a
filtered command satisfies the actuator box exactly and the active rows within tolerance, or the backup
controller is running.

**Output.** `Projection1 { u: Command, lambda: Qty, row_residual: Qty, breakpoints_used: u8 }` or
`RowInfeasible { s_max, c }`. Only the optimality checker of N22b-23 can turn a `Projection1` into a
`Checked<Command>`; for one row the check is the KKT conditions evaluated directly (primal residual, λ ≥ 0,
complementarity, stationarity per coordinate).

**Batched kernel.** One instance per world; n is the template's input dimension (small). On devices the sort
of at most 2n keys uses the deterministic sort utility with index tie-breaks, so the result is class D2 and
identical across worker counts. The CPU reference is the same algorithm in Rust.

**Complexity.** O(n log n) per world; for n ≤ 12 this is a few hundred operations, well inside the target of
at most 5% added step cost.

## Acceptance criteria

- [ ] `crates/frob-shield/src/filter/project1.rs` implements the algorithm for rationals, `f64` and `f32`.
- [ ] The worked example returns λ = 0.5 and u = (1, 0.5) exactly in rationals and to round-off in floats.
- [ ] PO-SHIELD-02: on 10⁶ random instances (n from 1 to 12, mixed signs of a, proposed commands inside and
      outside the box, active and inactive rows, feasible and infeasible) the float result matches the
      rational minimizer within the declared tolerance, with **zero** box violations.
- [ ] The project-then-clip mutant fails the suite on the worked example and on a measurable fraction of the
      random instances; it is registered as a negative control.
- [ ] `RowInfeasible` is returned exactly when s_max < c in the rational reference.
- [ ] The kernel form gives identical bytes twice on one machine and across worker counts.
- [ ] The tier-3 specification's single-row law tests (N10c-02, `laws_c31_filter`: `ka_155_one_row_worked`,
      `project_then_clip_is_wrong`, `breakpoint_equals_active_set_oracle`, `po_shield_02_million`,
      `infeasible_row_invokes_backup`) pass against this production projection, not only against the
      specification's reference model.

## Test plan

### Unit tests

`crates/frob-shield/tests/project1.rs`.

- `worked_example`: R = I, u_π = (1, 0), box [0, 1]², a = (1, 1), c = 3/2. u⁰ = (1, 0), aᵀu⁰ = 1 < 3/2;
  s_max = 2 ≥ 3/2. Channel 1 is at its upper bound for every λ ≥ 0 (breakpoint 0); channel 2 enters at 0 and
  leaves at 1. On [0, 1]: S = 1, σ = 1, so λ* = 1/2 and u* = (1, 1/2).
- `shortcut_values`: unboxed projection λ = (3/2 − 1)/2 = 1/4 gives (5/4, 1/4); clipped (1, 1/4);
  aᵀu = 5/4 < 3/2.
- `inactive_row`: u_π = (1, 1) → returned unchanged, λ = 0.
- `clip_only`: u_π = (2, 0.9), row satisfied after clipping to (1, 0.9): λ = 0, u = (1, 0.9).
- `infeasible_row`: c = 5/2 with box [0, 1]²: s_max = 2 < 5/2 → `RowInfeasible`.
- `weighted_metric`: R = diag(1, 4), u_π = (0, 0), box [0, 1]², a = (1, 1), c = 1: g = (1, 1/4);
  S(λ) = λ + λ/4 until channel 1 saturates at λ = 1; λ* = 4/5, u* = (4/5, 1/5) (cost ½·(0.64 + 4·0.04) =
  0.4, lower than the unweighted answer (1/2, 1/2) with cost ½·(0.25 + 1) = 0.625).
- `negative_coefficient`: R = I, a = (1, −1), u_π = (0, 1), box [0, 1]², c = 1/2: u(λ) = (λ, 1 − λ),
  aᵀu(λ) = 2λ − 1, so λ* = 3/4 and u* = (3/4, 1/4).
- `float_never_leaves_box` (property): 10⁶ instances, both precisions.
- `float_matches_rational` (property): the PO-SHIELD-02 comparison.
- `tie_break_determinism`: instances with equal breakpoints give identical results under channel
  permutation after mapping back.

## Considerations

- A non-diagonal metric has no breakpoint form; such a shield uses the multi-row path even for one row.
- The nudge loop is bounded; if the residual is still negative after it, the tick goes to the backup. That
  path must be exercised by a planted instance.
- This kernel is one of the two shield pieces named for a later firmware export (a shield projection with a
  few rows); keeping it branch-light and integer-indexed helps that.
