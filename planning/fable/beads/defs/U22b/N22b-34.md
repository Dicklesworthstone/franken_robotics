## Background

For a small subsystem whose danger lies in a guard that sensing cannot resolve (a wheel at a threshold, a
tray about to tip, braking across two floor materials), a reachable-set table precomputes, per mode and per
cell of a grid over at most four reduced states, one command that is safe whatever the unresolved facts
turn out to be. This bead builds the table. It is a Moonshot [M], funded only if its pilot (N22b-33) is
positive, and it is off the critical path.

**The rule a table must satisfy.** Cells hold measured states; the true state is the measured state plus an
error in a bounded set E. A cell K_m of mode m keeps a common safe action only if

    R_mn((K_m ⊕ E) ∩ G_mn, D) ⊆ K_n ⊖ (−E)    for every guard G_mn that may be enabled,

where R_mn is the reset map from mode m to mode n, D the disturbance set, ⊕ the Minkowski sum and
A ⊖ B = {x : x + B ⊆ A}. The erosion is by −E, which equals E only for a centrally symmetric error set.
(Reason: the true successor x′ will be read as x′ − e′ for some e′ ∈ E; all of those readings must lie in
kept cells, that is x′ + (−E) ⊆ K_n.) Where cells hold true states and the whole belief set must stay in one
cell, the condition is R_mn(K_m ∩ G_mn, D) ⊆ K_n ⊖ (E ⊕ (−E)). Inter-sample sweep, latency and chatter are
accounted for.

The method is backward viability pruning: start from every cell that is not itself unsafe, repeatedly remove
cells for which no single action satisfies the rule against the cells still present, and stop at the
greatest fixed point. It is abstraction-based reachability; what it proves, it proves about the reduced
model. The reduction of a robot to at most four states is an assumption the shield's monitors watch.

Rejected alternatives. An online reachable-set computation per tick (the table exists to replace it by a
lookup). A barrier function for the same subsystem (it must assume the worst mode everywhere, which the
pilot's hand point shows to be more conservative: 0.6796 m against 0.6057 m of braking range at 2.0 m/s). A
finer or adaptive grid beyond the cap (the cap of 8 modes × 16,384 cells is what keeps the table a small
payload and its certificate checkable).

## Scope

In: the subsystem description; gridding; outward-rounded image enclosures with sensing error, disturbance,
inter-sample sweep, latency and chatter; the pruning iteration; the table payload. Out: the run-time lookup,
the certificate and the gate (N22b-35); choosing which subsystems of a robot get a table (a fit-time
declaration by the task); subsystems of more than four states (refused).

## Technical approach

**Subsystem description (DESIGN, `crates/frob-shield/src/table/spec.rs`).**

```rust
pub struct ReducedSubsystem {
    states: Vec<StateAxis>,          // at most 4; each with range and cell count
    modes: Vec<ModeSpec>,            // at most 8; each with flow x' = F_m(x, a, d) over one tick, as a KIR program
    guards: Vec<Guard>,              // G_mn as a box-decidable predicate, with reset R_mn
    actions: Vec<Action>,            // a finite set (at most 16)
    sensing_error: ErrorSet,         // a box E, possibly asymmetric
    disturbance: Box,                // D
    tick: Ratio, latency_ticks: u8,
    unsafe_set: Predicate,           // states and sweeps that are violations
    cells_hold: CellSemantics,       // Measured | True
}
```

Limits checked at construction: at most 4 states, at most 8 modes, at most 16,384 cells per mode; a
description beyond them is refused with a typed error naming the limit.

**Image enclosure for one (mode m, cell c, action a).**

1. True-state box: X = c ⊕ E (for `Measured` semantics; X = c for `True`).
2. Latency: for `latency_ticks` ticks the previous action is still in force; the builder treats the previous
   action as unknown within the action set (a union over all actions) unless the table is indexed by the
   previous action (DESIGN: an optional extra axis within the same cell budget).
3. Sweep: compute an outward-rounded enclosure of the whole tube {x(τ) : τ ∈ [0, tick]} under F_m with a
   held, for all x ∈ X and d ∈ D, by interval evaluation of the flow (outward-rounded intervals; the
   interval library is admitted through the airlock for analysis use). If the tube meets the unsafe set, the
   action fails.
4. Guards: for every guard G_mn whose predicate the tube can satisfy (it "may be enabled"), compute the
   reset image R_mn(tube ∩ G_mn, D) and continue the flow in mode n for the remainder of the tick, again
   with its sweep. Chatter: if the continued tube can re-enter G_nm within the tick, iterate up to a declared
   switch count (default 2) and, if switching can still continue, treat both modes' flows as possible for
   the whole tick (the conservative union).
5. End sets: for each mode n reachable at the end of the tick, the end box Y_n.
6. Inclusion: for `Measured` semantics inflate Y_n by −E and require every cell of mode n that it touches
   to be currently kept; a part of Y_n ⊕ (−E) outside the gridded range fails. For `True` semantics inflate
   by E ⊕ (−E) and require the result to lie within one kept cell.

**Pruning iteration.**

1. K⁰: all cells of all modes whose true-state box avoids the unsafe set.
2. For each cell in Kⁱ, the surviving actions are those passing steps 1 to 6 against Kⁱ. A cell with none is
   removed.
3. Repeat until no cell is removed. The map is monotone on a finite set, so the iteration reaches the
   greatest fixed point in at most (number of cells) rounds.
4. For each kept cell store the set of surviving actions as a bit mask and one designated common safe
   action (DESIGN: the surviving action closest to "no intervention" in the declared action order).

**Payload.** `SafeTable { subsystem: SubsystemId, modes, grid, kept: BitSet, actions: Vec<u16 mask>,
designated: Vec<u8>, iterations, builder: BuildId }`, at most 8 × 16,384 entries (about 0.4 MB). It is a
payload of the shield record, content-addressed; it has no file format of its own.

**Determinism and class.** The builder is a host computation in outward-rounded arithmetic with a fixed
iteration order: class D0 for a given description (identical tables on every host). Its output is a claim
about the reduced model; with the certificate of N22b-35 the inclusion is `Certified` for that model, and
anything said about the robot is `Tested` at best.

## Acceptance criteria

- [ ] The pilot record (N22b-33) is positive; otherwise this bead closes as not funded with the fallback
      "no tables are built; reduced-order barriers cover those subsystems".
- [ ] The builder accepts descriptions of up to 4 states, 8 modes and 16,384 cells per mode and refuses
      larger ones with the limit named.
- [ ] On the braking fixture (two states, modes A and B, 128 × 128 cells) the kept set lies inside the
      closed-form viable set, covers at least 90% of the sampled, error-inflated reference, and is identical
      on two hosts.
- [ ] With an asymmetric error set, eroding by E instead of −E yields a different table that admits an
      unsafe state; the correct erosion does not (registered negative control).
- [ ] Omitting the inter-sample sweep or the latency union yields a table that admits a state from which the
      line is crossed (registered negative controls).
- [ ] The fixed point is verified: re-running one more round removes nothing, and every kept cell's
      designated action passes the rule against the final table.

## Test plan

### Unit tests

`crates/frob-shield/tests/table_build.rs`.

- `one_dimensional_hand` (hand-checkable): one state x ∈ [0, 1) in 10 cells of width 0.1 (cell k is
  [0.1·k, 0.1·(k + 1))), one mode, no sensing error, no latency. Unsafe: x < 0.2 (cells 0 and 1). Flow per
  tick x′ = x + 0.1·a + d with actions a ∈ {−1, 0, +1} and disturbance |d| ≤ 0.02. The image of cell k
  touches cells k − 2, k − 1, k under a = −1; k − 1, k, k + 1 under a = 0; k, k + 1, k + 2 under a = +1.
  Expected fixed point: cells 2 to 9 are kept, with surviving actions {+1} for cell 2, {0, +1} for cell 3,
  {−1, 0, +1} for cells 4 to 7, {−1, 0} for cell 8 and {−1} for cell 9 (images that leave the range fail).
- `one_dimensional_empty` (hand-checkable): the same system with actions {−1, 0} only. Cell 2 has no
  surviving action in the first round (both images touch cell 1), then cell 3 loses its last action, and so
  on: rounds one to six remove cells 2, 3, 4, 5, 6 and 7 in turn, round seven removes cells 8 and 9
  together, and the fixed point is empty. A pruning that stops after one round keeps cells 3 to 9 and is
  caught.
- `fixed_point_reached`: brute-force reference pruning on a 16 × 16 two-mode toy agrees with the builder
  cell for cell.
- `erosion_sign`: E = [−0.03, +0.01] on one axis (true = measured + e); a true successor box [0.50, 0.52]
  near a removed cell [0.54, 0.57). Readings are x′ − e, so they range over [0.49, 0.55]: the correct
  erosion by −E finds 0.55 in the removed cell and fails the action. Eroding by E checks [0.47, 0.53],
  which misses the removed cell, and wrongly passes.
- `sweep_matters`: a flow that dips below the unsafe bound mid-tick and returns by the end of the tick is
  rejected by the sweep and accepted by an end-point-only mutant.
- `guard_may_be_enabled`: a cell straddling the tile boundary must satisfy the rule under both modes'
  flows.
- `limits_refused`: 5 states; 9 modes; 129 × 128 cells.
- `braking_table_soundness`: the acceptance row against the closed form (every kept cell's worst corner
  satisfies v² ≤ 5.886·s on B and v² ≤ 10·(s − 0.5) + 2.943 on A).
- `host_determinism`: identical table digests in debug and release.

### End-to-end script and logging

Exercised by `scripts/e2e/shield_table_braking.sh` (N22b-35): `frob shield fit … --table braking.json --json`
builds the table as part of fitting; the script logs the kept-cell count per mode, coverage against 0.90,
rounds to the fixed point, build time and the table's digest.

### Known answers and negative controls

The braking fixture's closed-form boundary (hand points: 1.7155 m/s at 0.5 m; 2.8183 m/s at 1.0 m; 0.6057 m
needed at 2.0 m/s) bounds the table from outside. Negative controls: the wrong erosion sign on an asymmetric
error set; the end-point-only image; the latency-free image; a pruning that stops after one round. The
brute-force reference on toy systems is the differential oracle. Determinism: class D0.

## Considerations

- Wrapping: box images over-approximate, and the loss compounds through the pruning. The coverage figure is
  the measure of that loss, and it is reported for every table.
- Build cost: cells × actions × guards × rounds; for the braking fixture about 3 × 10⁴ cells × 5 actions per
  round. A four-state table at the cap is still small in memory and may be slow to build; build time is
  recorded and a budget stop publishes no partial table.
- A table is only as good as the reduced model. The shield's tracking-error monitor and margin apply to the
  subsystem's template exactly as they do to barrier rows.
- If KILL-TUBE fires nothing here ships; the toy and fixture tests stay as documentation of why.
