## Background

A reachable-set table (built by bead N22b-34) stores, per mode and per cell of a grid over at most four
reduced states, one command that is safe whatever the facts sensing cannot resolve turn out to be. This bead
makes the table usable and checkable: the run-time **lookup**, the **certificate** that an independent
auditor can recompute, and the **gate measurement**. It is a Moonshot [M] under the reachable-set epic,
funded only on a positive pilot.

The run-time rule: *the whole belief set is looked up; outside the table the answer is `uncovered` and the
backup domain applies.* The belief set is everything consistent with what was delivered: the measured state
(whose error the table already accounts for when cells hold measured states) and every mode that the
history has not excluded. Looking up only the measured state in the most likely mode is the shortcut this
rule forbids: near a tile boundary the wheel may be on either material.

The certificate: proof kind `tube-inclusion`, one row of the closed registry of proof kinds, defined as
"the inclusion of the reachable-set table condition for every cell and enabled guard of a table". The
offline auditor (a single binary built from the standard library only, with its own interval arithmetic on
integers) recomputes the inclusion; it shares a format and nothing else with the builder.

GATE-SHIELD-05 (known-answer claim, TARGET, M8): *zero false admissions in 5,000 in-envelope episodes on
the braking fixture; `uncovered` outside the table.*

## Scope

In: the lookup stage inside the shield; the `Uncovered` event and hand-over; the table as a payload of the
shield record in `shield.fit` and `shield.report`; the `tube-inclusion` bundle writer; the braking table's
bundle and its mutants as specimens of the kind; the gate campaign on the braking fixture; the end-to-end
script. Out: building tables (N22b-34); the kill decision (N22b-36); the `tube-inclusion` checker in the
auditor (N12-19, a dependency, in `frob-cert`: the payload format the auditor reads, every check it makes,
the caps, the `unsupported` outcome, the statement a bundle certifies, and the registry row's change from
`not-implemented` to `enabled`). This bead first carried a second specification of that checker; it was merged
into N12-19, which now holds everything both texts said, and this bead writes bundles in that format and has
them checked.

## Technical approach

**Lookup (per tick, per world; `crates/frob-shield/src/table/lookup.rs`).**

1. Form the belief: the measured reduced state x̂ (from delivered estimates only) and the mode set
   𝓜 = modes not excluded by the delivered history. A mode is excluded only by a delivered observation that
   is inconsistent with it for every true state within the sensing error; otherwise it stays in 𝓜.
2. `Measured` cell semantics: locate the cell c containing x̂ in each mode of 𝓜. `True` cell semantics:
   locate the cell that contains the whole belief box x̂ ⊕ E in each mode (the true state is the measured
   state plus an error in E, so the true states consistent with x̂ are x̂ + E; the builder's condition
   R(K_m ∩ G_mn, D) ⊆ K_n ⊖ (E ⊕ (−E)) is what guarantees that this box lies in one cell, since a true
   successor y is read as y − e′ and its belief is y − e′ + E); if the box straddles cells the answer is
   `uncovered`.
3. If x̂ is outside the gridded range, or any located cell is not kept: `uncovered`.
4. Otherwise intersect the surviving-action masks of the located cells over 𝓜. Empty intersection:
   `uncovered`. Non-empty: the common safe action set; the applied command is the proposed command if it
   maps to an action in the set, else the set's designated action nearest the proposed command.
5. `uncovered` emits `ShieldEvent::Uncovered`, sets the layer record to `backup`, and hands over to the
   backup controller, whose declared domain applies. Covered ticks emit `Projected` when the command was
   changed.

The lookup is two or three array reads and a mask intersection per world; it runs batched on every tier
and is class D2 (its decisions are integer and identical across worker counts).

**Table in the shield record.** `shield.fit --table <subsystem description>` builds the table and attaches
it as a payload; `ShieldId` covers its digest. The VERBS-shield `shield.fit` row carries `--table` (M8) with
this bead in its `Extended by`. The file's format (DESIGN) is `frob.shield.subsystem/1`, a
canonical-JSON document whose members are the description members of N12-19's `tube-inclusion` payload: the
reduced state axes with ranges and cell counts, the modes with their flows as polynomial or rational one-tick
maps and their primitive equations, the guards and resets, the action set, E, D, the tick, the latency and the
switch-count rule, the unsafe set and the cell semantics; it has none of the members the builder computes (the
kept set, the masks, the designated actions, the target cells). It loads into N22b-34's `ReducedSubsystem`, and
the writer copies its members into the bundle unchanged, so the auditor reads the description the builder was
given. The row declares the input as the `params` entry `table = "artifact-input<subsystem>"`; a file that
fails the schema is refused with the codes the row gives artifact inputs. `shield.report` gains a block: kept-cell count per mode,
coverage, the fraction of ticks answered `uncovered`, and the certificate reference.

**Certificate `tube-inclusion`: the writer.** `frob-lemma`'s bundle writer is given the table and its
subsystem description and emits the payload N12-19 defines; the verb that calls it is `prove.bundle` in its
table form (M8, this bead: a positional `ShieldId` whose record carries a table writes one `tube-inclusion`
entry; a `ShieldId` whose record carries no table is FROB-REF-802; `--out`, `--key` as in every form).
The payload: the grid, the modes, the flows as polynomial or
rational one-tick maps with their primitive equations, the guards, the resets, the action set, E, D, the tick,
the latency and the switch-count rule, the unsafe set, the cell semantics, the kept set, and per kept cell its
action mask, its designated action and its target cells per enabled guard. The writer adds nothing the
builder did not compute and omits nothing the checker reads; a bundle is bound to the shield record by
identity (a bundle whose latency or error set differs from the record's is rejected by the bundle-to-record
identity check before the auditor is asked).

The checker is N12-19's and is not specified here. In one sentence: for every kept cell, every action in its
mask and every guard that may be enabled, it recomputes the swept tube and the end set with outward-rounded
intervals, requires the tube to avoid the unsafe set and the end set, inflated by −E (`Measured`) or by
E ⊕ (−E) and contained in one cell (`True`), to lie in kept cells, and returns `accept`, `reject` with the
first failing cell, action and guard, or `unsupported` for a flow it cannot enclose. The statement certified
is invariance of the kept set for the reduced model under every action in a mask (N12-19 gives its wording;
this bead's first draft named only the designated action, which is narrower than what the lookup relies on,
since the lookup may apply any action of the common set). It is a Proof claim of class `Certified` about that
model and says nothing about the robot beyond what the tracking margin and monitors support.

**Gate campaign.** The braking fixture (two states: range to a stop line and speed; modes: tile A with
μ_A = 0.8 for range above 0.5 m, tile B with μ_B = 0.3 at or below it; brake requests up to 5.0 m/s²
delivering min(request, μ·g); Δt = 0.02 s; one tick of latency; sensing error |e_s| ≤ 0.01 m,
|e_v| ≤ 0.02 m/s; operating set range [0, 2] m and speed [0, 3] m/s; 128 × 128 cells per mode) is run on the
referee and on the `strict` profile:

- *In-envelope set*: 5,000 episodes with initial states drawn inside the table's kept set, friction pairs
  drawn in the declared ranges (μ_A in [0.6, 0.9], μ_B in [0.3, 0.4]) and sensing errors inside E. A *false
  admission* is an episode in which every tick was answered covered and the cart crossed the line with
  positive speed. Required count: 0.
- *Outside set*: 1,000 episodes started outside the kept set or with friction below the declared range.
  Required: every tick whose belief is outside the table is answered `uncovered`, with the hand-over to the
  backup recorded. (What then happens physically is the backup's business and is reported, not gated.)

Decision rule, enumerated: pass iff false admissions = 0 and no outside-table tick is answered covered;
any false admission fails; a covered answer outside the table fails.

## Acceptance criteria

- [ ] The builder bead is funded and closed (positive pilot); otherwise this bead closes as not funded and
      GATE-SHIELD-05 stays `not-run` (no part is recorded; the closing note says "pilot negative").
- [ ] The lookup implements the belief-set rule; near the tile boundary it requires the action to be safe
      in both modes.
- [ ] GATE-SHIELD-05 is recorded with measured values: 0 false admissions in 5,000 in-envelope episodes on
      the braking fixture; `uncovered` on every outside-table tick.
- [ ] The `tube-inclusion` bundle of the braking table is accepted by the offline auditor on a machine with
      no GPU and no network; each registered mutation is rejected with the failing cell named.
- [ ] Negative controls caught: a lookup that uses the measured state in the nearer mode only produces a
      false admission on the campaign; a table built without the sweep term is rejected by the auditor.
- [ ] `shield.fit` and `shield.report` show the table block; every output is class `Tested` for the robot
      and carries the flags; the certificate's class is `Certified` for the reduced model only.

## Test plan

### Unit tests

`crates/frob-shield/tests/table_lookup.rs`, `crates/frob-cert/tests/kind_tube_inclusion.rs`; the gate campaign
is the GATE-SHIELD-05 entry of the `g1_known_answers` tier target of `frob-conformance` (no private gate test
file), run as `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g1_known_answers -- GATE-SHIELD-05`
(with `--features gauntlet-mutations` for the negative controls) and recorded by this bead with `cargo run -p
frob-conformance --example record_gate -- --gate GATE-SHIELD-05 --receipt <hash>`.

- `belief_both_modes`: measured range 0.505 m (within 0.01 m of the boundary at 0.5 m): 𝓜 = {A, B}; the
  action set is the intersection of the two cells' masks.
- `belief_single_mode`: measured range 0.80 m: 𝓜 = {A}.
- `uncovered_outside_range`: speed 3.2 m/s → `uncovered`, event emitted, layer `backup`.
- `uncovered_empty_intersection`: masks {coast} in A and {full brake} in B → `uncovered`.
- `proposed_kept_when_safe`: a proposed command inside the common set passes unchanged.
- `true_semantics_belief_sign`: one axis, cells of width 0.1, E = [−0.03, +0.01] (true = measured + e),
  measured 0.525: the belief box is [0.495, 0.535], which straddles the cells [0.4, 0.5) and [0.5, 0.6) →
  `uncovered`; a mutant that looks up x̂ ⊕ (−E) = [0.515, 0.555] finds one cell and wrongly answers covered.
- `subsystem_file_schema`: `braking.json` loads as `frob.shield.subsystem/1` into the `ReducedSubsystem` the
  builder uses, and its members reappear byte for byte in the bundle; a file carrying a `kept` member, or one
  with five state axes, is refused at load.
- `writer_emits_checker_payload`: the bundle written from the braking table parses under N12-19's payload
  schema with every field present, and from the one-dimensional hand table (cells 2 to 9 kept with the stated
  masks) likewise; both are accepted by the checker.
- `checker_mutants` on the braking bundle (the checker is N12-19's; these are this bead's registered
  mutations of its own specimen): one kept cell added just outside the closed-form boundary; E's sign flipped
  on an asymmetric error set; latency set to zero in the bundle while the table was built for one tick
  (accepted only if the stated rule still holds, and the mismatch with the shield record's latency is
  rejected by the bundle-to-record identity check); a flag set to `true`.
- The checker's own cases this bead first listed (the hand table with action −1 added to cell 3's mask; a
  transcendental flow returning `unsupported`) are tests of N12-19.
- `gate_smoke`: 200 in-envelope and 100 outside episodes on `batch-cpu`.
- `bundle_verb_table_form`: `prove.bundle <ShieldId>` on the braking shield writes one `tube-inclusion` entry
  equal to the writer's bundle; on a shield record without a table it is refused with FROB-REF-802.

### End-to-end script and logging

`scripts/e2e/shield_table_braking.sh` (shared helper; run verbs carry one distinct key each): `frob shield fit
brake-cart --controller <braking controller> --tasks two-tiles --tier referee --table
fixtures/shield/table/braking.json --key stb-1 --json` (the table is built here, so this step is also N22b-34's
end-to-end evidence); `frob prove bundle <ShieldId> --out <scratch>/tube.frobcert --key stb-2 --json` and
`frob-verify <scratch>/tube.frobcert` on the table's certificate, then `frob-verify` on each registered mutant
bundle (each rejected with its first failing cell); the two episode sets through `frob eval run brake-cart
--battery two-tiles-in-envelope --controller <braking controller> --shield <ShieldId> --tier referee --key stb-3
--json` and the same with `--battery two-tiles-outside --key stb-4` (the controller and tier of the shield's
scope key, without which the run would be refused with FROB-REF-457; a battery's items carry their own world
addresses, so no seed is passed; the shield of step 1 in the loop, so that its lookup answers every tick), then
the same two with `--profile strict` (`stb-5`, `stb-6`); `frob shield report <ShieldId> --json`. NDJSON lines carry the exact command, exit code, wall time, the
`evidence` block, kept cells per mode, coverage, false admissions against 0, covered answers outside the
table against 0, the uncovered fraction, the auditor's verdicts with first failing cell; on a false
admission the world address, the initial state, the tick of crossing and the cells visited. `summary`
lists `gates: ["GATE-SHIELD-05"]`.

### Known answers and negative controls

The closed-form viability boundary of the braking fixture (on B: v² ≤ 5.886·s; on A:
v² ≤ 10·(s − 0.5) + 2.943; hand points 1.7155 m/s at 0.5 m and 0.6057 m of range needed at 2.0 m/s) bounds
every kept cell. Negative controls: the single-mode lookup; the sweep-free table; the wrong erosion sign; a
checker that verifies end sets only. Determinism: lookups are integer decisions (identical across worker
counts and batch positions); the campaign's worlds are class D2 on the referee and the `strict` profile.

## Considerations

- Zero false admissions in 5,000 episodes is a test of the implementation against the reduced model and the
  simulator; the certificate is the argument, the campaign is its negative control.
- `uncovered` is an honest answer and may be frequent near the edges of the operating set; its fraction is
  reported so that a table too small to be useful is visible.
- The mode-exclusion rule in the belief is where a subtle unsoundness could hide (excluding a mode on weak
  evidence). The default excludes a mode only on an observation inconsistent with it under every admitted
  error, and the single-mode lookup control exists to keep it that way.
- Auditor size: the `tube-inclusion` checker reuses the interval arithmetic already in the auditor; its
  line count is reported against the auditor's cap.
