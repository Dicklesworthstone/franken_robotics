## Background

A symmetric controller is correct only under the group its closed loop has in the present situation: the
observation-preserving group intersected with the stabilizers of gravity in the body frame, boundary
conditions, the current contact mode and the commanded twist. The verb `control.symmetry` reports the two
stored groups, the stabilizers in force, the usable group and which elements each stabilizer removed. This
bead proves the capability from the user's side with a shell script that drives the real `frob` binary on
fixtures, asserts the exact group elements an agent would see, and logs enough to diagnose a failure
without rerunning. Each assertion group has a planted defect that must make the script fail.

## Scope

In: one script, its fixtures, its planted defects, its logs. Out: the mechanisms (N22b-37 to N22b-40);
learned equivariant policies.

## Technical approach

**Location and conventions.** `scripts/e2e/control_symmetry.sh`, POSIX shell, sourcing the shared helper of
the end-to-end harness; idempotent; seeds explicit; non-zero exit after the summary on any failed group.
Fixtures in `fixtures/symmetry/` (`synthetic`): `quad-sym.fbot` (symmetric fore-aft and left-right, body
frame x forward, y left, z up), `quad-front-lidar.fbot`, `quad-payload-left.fbot` (payload offset to +y on
the transverse mid-plane), a level scene, a scene tilted 10° about the forward axis, a scene with a
slippery strip over y > 0, the `stand` task and `stand-tilt-10deg` (the same task on the tilted scene, the
context `control.synth` reads through `--task`, since it has no `--scene`), the `stand-to-trot` task, the
`two-latch` task, a
`drop-landing` task (flat four-foot landing from 5 cm) and a `graze-landing` task, and `quad-odd-soles.fbot`
(left and right soles of different restitution). Designs are positional, as in the rows' examples; every run
verb (`control synth`, `sim run`, `eval run`, `eval compare`) carries its own `--key sym-<step>-<i>`, distinct
across the calls a step compares.

Element names in outputs: `e`, `m_lr` (P = diag(1, −1, 1)), `m_fa` (P = diag(−1, 1, 1)), `r`
(P = diag(−1, −1, 1)).

**Steps.**

1. `frob doctor --json`: record build and fingerprint.
2. Baseline: `frob control symmetry quad-sym --task stand --json`. Assert `mech` = {e, m_lr, m_fa,
   r}, `obs` equal to `mech`, every stabilizer equal to the whole group, `use` = all four.
3. Planted asymmetries, each asserting set equality of the removed elements:
   - `--scene tilt-10deg`: `stabilizers.gravity.removed` = {m_lr, r}; `use` = {e, m_fa};
   - design `quad-payload-left`: `obs` = {e, m_fa}; breaker = the payload; a typed edit is offered;
   - design `quad-front-lidar`: `obs` = {e, m_lr}; breaker = the lidar mount;
   - `--scene strip-left`: `stabilizers.boundary.removed` = {m_lr, r}; `use` = {e, m_fa}.
4. Other contexts (linear and angular parts of the commanded twist are passed by name, so that no ordering
   convention is assumed): `--twist-linear "0.5 0 0"`: `stabilizers.twist.removed` = {m_fa, r};
   `--twist-angular "0 0 0.3"` (yaw rate): removed = {m_lr, m_fa}; `--mode "FL RR"` (trot stance): removed =
   {m_lr, m_fa}; trot stance with the forward command: `use` = {e}.
5. Refusals: `frob control synth quad-sym --task stand-tilt-10deg --symmetry mech --key sym-5-1 --json` → exit
   code 3, FROB-REF-461, `pointer` naming `m_lr` and the stabilizer `gravity`, repairs "use Γ_use" then the
   typed edit. `frob control synth quad-front-lidar --task stand-tilt-10deg --symmetry mech --key sym-5-2
   --json` → exit code 3, FROB-REF-443 (not 461: an element outside Γ_obs is named first), `pointer` naming `m_fa` with the lidar
   mount as breaker, repairs "use Γ_obs", "change the sensor suite", "restrict to open-loop use".
6. Untying: `frob control synth quad-sym --task stand --symmetry use --verify-reduction --key sym-6-1 --json`
   and the same with `--task stand-tilt-10deg --key sym-6-2` (the synthesis-time comparison of the reduced
   controller with its full twin, N22b-38: both pass, the largest difference logged against its threshold);
   `frob control show <ControllerId> --json` on each: left and right
   stance gains equal on level ground, different on the slope; the two `ControllerId`s differ and the group
   field differs. The controller check of the read verb: `frob control symmetry quad-sym --task stand --scene
   tilt-10deg --controller <the level-ground controller> --json` → exit code 3, FROB-REF-461 naming `m_lr` and `gravity`; the same on the level scene
   → exit 0 with the controller's group per mode and its equivariance mode.
7. Reduced against full, through a stand-to-trot switch on level ground (the fixture task `stand-to-trot`,
   whose gait schedule switches from four-foot stance to the FL+RR trot stance): `frob control synth quad-sym
   --task stand-to-trot --symmetry use --key sym-7-1 --json`, then `frob sim run quad-sym --task stand-to-trot
   --controller <that ControllerId> --tier referee --seconds 2 --seed 1 --verify-reduction --key sym-7-2
   --json`: the largest reduced-against-full command difference is within the class threshold on both sides
   of the switch; the group in force changes at the switch.
8. Two latches: run the task with the tied deterministic controller (256 worlds): 0 successes; the report
   text contains "tied deterministic controller class is excluded" and does not contain "infeasible". Run
   with the in-law controller: 256 of 256 successes; `frob control show <ControllerId> --json` reports mode `in-law`, the
   draw's stream address and the channels sharing it.
9. One-sided patch: the terrain-conditioned controller against the control tied under Γ_mech, on common
   world addresses (`frob eval compare`): the tied control's return is lower; the difference and its
   interval are logged.
10. Landing identity: `frob control symmetry quad-odd-soles --task drop-landing --events landing
    --json`: for `m_lr` with sole laws exchanged, every touchdown class passes within tolerance. With
    `--task graze-landing`: the event is `flagged: grazing` and no pass is reported.
11. Determinism: repeat steps 2 to 4 twice and with the debug and the release binary (via `FROB_BIN`);
    identical outputs byte for byte (group computations are exact; `control.symmetry` has no worker option,
    the computation being single-threaded on the CPU).

**Logging.** NDJSON to `target/e2e-logs/control_symmetry/<utc-timestamp>.ndjson` with a transcript beside
it. Every line: `ts`, `script`, `bead` (`N22b-41`), `step`, `event` (`start`, `cmd`, `assert`, `metric`,
`refusal`, `end`), the exact command line, exit code, wall time, the envelope's `evidence` block (claim,
class, tier, determinism, identities, seed). `assert` lines for group rows carry the expected and observed
element sets; `metric` lines carry gain pairs, the reduced-against-full difference with its threshold,
success counts, the patch return difference with its interval, and identity residuals with tolerance or
the transversality value of a flag. `refusal` lines carry code, pointer and repairs. On failure: the first
differing element or value and the fixture paths. Final `summary`: assertions passed and failed and
`gates: ["GATE-REFLEX-07"]`.

## Acceptance criteria

- [ ] The script exists and passes on a clean checkout (CPU only).
- [ ] It fails (non-zero) under each of its declared plants (STD-E2E: header `plants`, switched by
      `E2E_PLANT_FAILURE` and injected by the script, checked by `run-all.sh --verify-plants`), each replacing
      one step's output by what one defect prints: angular velocity treated as a polar vector in the twist
      stabilizer (step 4's yaw row removes nothing); Γ_use cached across the mode switch (step 7's group does
      not change); a sign table that flips no axis for a mirrored leg (step 7's command difference above its
      threshold); the image event taken without exchanging sole laws (step 10 fails); a report that calls the
      two-latch task infeasible (step 8); a guard order that checks Γ_use before Γ_obs (the front-lidar
      refusal of step 5 reports 461 instead of 443). The code defects themselves are registered controls
      caught by the tests of N22b-37 to N22b-40 and the GATE-REFLEX-07 entry of BD-327; product binaries never
      carry `gauntlet-mutations` (STD-TEST).
- [ ] Every assertion of steps 2 to 11 is logged with expected and observed values.
- [ ] Two consecutive runs give identical outputs for the group steps and identical assertion outcomes
      elsewhere.

## Test plan

### Unit tests

`scripts/e2e/tests/control_symmetry_selftest.sh`: runs the script against a recorded envelope set in which
the tilted scene's removed set is {m_lr} only; asserts a non-zero exit and a log line naming the missing
element `r`.

### End-to-end script and logging

As above. Commands: `frob doctor`, `frob control symmetry` (with `--task`, `--scene`, `--twist-linear`,
`--twist-angular`, `--mode`, `--events`, `--controller`, the spellings BD-327 fixes), `frob control synth --task
--symmetry --verify-reduction --key`, `frob control show`, `frob sim run --verify-reduction --key`, `frob eval run --key`, `frob eval
compare --key`.

### Known answers and negative controls

KA-575 (planted asymmetries remove exactly the expected generators; a side slope removes the left-right
mirror; a front lidar leaves C₂), KA-574 (two latches), KA-070, KA-071. CX-244 (tie under the mechanical
group), CX-032 (axial vectors treated as polar), CX-033 (infeasibility concluded from a failed tied
search). Determinism lanes: twice on one machine; debug and release (via `FROB_BIN`);
group outputs are class D0 and must be byte-identical everywhere.

## Considerations

- The group assertions are exact set comparisons; no tolerance is involved except in the tilted scene's
  gravity test, whose tolerance is far below 10°.
- Step 9 is a small design comparison on 256 worlds; the script asserts only the sign of the difference with
  its interval excluding zero, which is the known-answer control ("the tied control loses return").
- Runtime target: under three minutes on a laptop CPU; the landing steps dominate.
