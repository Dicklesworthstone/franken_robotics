## Background

Reflex states seven invariants and nine proof obligations. Part I of the conformance battery (N22c-02) covers the
four whose mechanisms exist at M1. This bead covers the other twelve, whose mechanisms land at M3 and M4: the
sampling controller, symmetric controllers, gait orbits, the residual wrapper, the energy budget and the runtime
shields. Each property gets one registered conformance case, run against the assembled system, and one planted
violation the case must catch. It also carries the telemetry-level form of INV-REFLEX-01 from part I: at M1 that
invariant is checked in process and against the synthesis report's fallback log, and its statement about
telemetry (a layer record per command, a fallback event with its reason) becomes checkable once the layer-record
telemetry of N22a-15 lands at M3. The mechanism beads test their own code; this battery makes sure that a property
is not lost when a mechanism is split, replaced by its kill-gate fallback, or refactored.

Terms used below. A **shield** is a runtime filter that replaces a proposed command by the nearest one that
keeps a set of barrier rows satisfied inside the actuator box. A **gait orbit** is a fixed point of the map that
advances the closed loop by one stride; its **monodromy** is that map's Jacobian and its eigenvalues are the
Floquet multipliers. The **claim product** is the typed record every result carries: kind of claim, evidence
class (`Proved`, `Certified`, `Tested`, `Estimated`), tier, determinism class, identities and seed. Determinism
class D2 means the same bits run to run and across worker counts on one device family.

## Scope

In: the statements in the owning crates' `CONTRACT.md`; twelve cases with their planted violations; the
telemetry case of INV-REFLEX-01 with its planted violation. Out: the
mechanisms; the gate measurements themselves, which belong to the mechanism beads (this battery reuses their
fixtures and feeds their rows).

**INV-REFLEX-01, telemetry form (carried from part I).** Case: run each baseline of the smoke battery (the M1
archetypes and the classes added at M3) for 20 s on the referee and on `batch-cpu` with traced worlds; read the
layer records and the fallback events back through `frob telemetry query`; assert the conservation laws of
N22a-15: the per-episode layer counters sum to the control ticks; the number of `enter` fallback events equals the
number of maximal runs of consecutive non-nominal ticks; every tick with a fallback or backup layer lies inside an
event pair whose `enter` carries a non-empty reason; and the layer stream of a traced world agrees tick for tick
with the in-process tags of part I. Planted violation: the silent-fallback build of part I (the last feasible
command swapped in without an event): the event count falls short by one and the case names the tick.

**Kill-gate interaction.** Four M4 kill decisions settle which branch each property is tested on: KILL-MPC
(N22c-16), KILL-SHIELD (N22b-28), KILL-GAIT (N22c-17) and KILL-RESIDUAL (N22c-15). They are dependencies of this
bead because part of its content exists on one branch only; none of them reads this battery (their triggers are
GATE-REFLEX-06, GATE-SHIELD-03, GATE-GAIT-03 and the residual pilot), so the order is safe. The battery reads
each decision's ADR at run time and logs the branch. If a mechanism fell back at its kill gate, its properties are
tested on the fallback or retired with a note: after KILL-MPC the sampling controller is a single-world CPU debugging aid and
INV-REFLEX-03 still holds; after KILL-SHIELD nothing is called a shield, INV-SHIELD-01 and PO-SHIELD-02, -03 are
retired, and PO-SHIELD-01, -04 remain (the energy tier and the backups stay); after KILL-GAIT orbits remain as
diagnostics and INV-GAIT-01 and PO-GAIT-01 still hold; after KILL-RESIDUAL (the residual rung is removed and the
baseline remains a behaviour-cloning warm start) PO-REFLEX-02 is retired with the kill decision cited, and the
layer value `baseline+residual` must then never appear in INV-REFLEX-01's case.

## Acceptance criteria

- [ ] `CONTRACT.md` of `frob-control`, `frob-gait` and `frob-shield` list their invariants with these statements.
- [ ] The telemetry case of INV-REFLEX-01 passes on the smoke battery and its planted silent fallback fails it with the tick named.
- [ ] All twelve cases pass, with the counts above (10⁶ projections with zero box violations; a relative difference below 10⁻⁸ on the monodromy; 72 of 80 and 20 of 20 on the gradient suite; 10⁴ episodes of integer-exact agreement).
- [ ] Each planted violation fails its case; the recorded failing run is kept as the control's evidence.
- [ ] Compile-fail tests exist for INV-SHIELD-02 and PO-SHIELD-03.
- [ ] A property whose mechanism fell back at a kill gate is recorded as retired with the kill decision cited, never silently skipped.

## Test plan

### Unit tests
`cargo test -p frob-conformance reflex::invariants` with one test per row, named after the identifier in lower
case (`inv_reflex_03_…` through `po_shield_04_…`), and `inv_reflex_01_telemetry_conservation` for the carried case
(counters sum to ticks; `enter` events equal non-nominal runs; reasons non-empty; traced stream equals in-process
tags). Hand values asserted: the projection example u = (1, 1/2) at
λ = 1/2; the slider (−2 m/s, +1.5 J); the trivial case of the twisted monodromy with m = 1 (twisted equals
direct exactly). Compile-fail cases under `tests/compile_fail/`.

### End-to-end script and logging
`scripts/e2e/reflex_invariants_m4.sh` drives `frob sim run` with traced worlds and `frob telemetry query`, `frob
eval qualify`, `frob eval promote`, `frob control symmetry`, `frob gait orbit`, `frob gait gradient`, `frob shield
check` and `frob-verify` on the registered fixtures, then runs the cases in the Gauntlet form (`e2e_tier g0_laws
reflex::invariants --mutations` and `e2e_tier g1_known_answers reflex::invariants --mutations`), so that each
planted violation is caught in the same run as its case and the receipt hashes are logged. Every call of a
run-kind verb (`sim.run`, `eval.qualify`, `eval.promote`, `gait.orbit`, `gait.gradient`, `shield.check`) carries
`--key`, and the runs a case compares carry distinct keys (`--key inv01-<baseline>-referee` and `…-batch-cpu`; for
PO-REFLEX-02 `--key po02-<baseline>-<wrapped|plain>-w<workers>`), so that a comparison never reads one run's
stored receipt twice. The script records no gate value: the gates it touches are recorded by their measuring beads
(BD-251, BD-333, BD-334, BD-338), whose tier runs include these cases. The script sources the STD-E2E helper and
writes `target/e2e-logs/reflex_invariants_m4/<utc>.ndjson` with a
transcript beside it. Every line has `ts`, `script`, `bead` (`N22c-03`), `step` (the property identifier),
`event`, the exact command line, exit code, wall time and the envelope's `evidence` block (claim, class, tier,
determinism, identities, seed); per property the measured count or difference with its unit against its threshold
(`layer_counter_sum_minus_ticks` = 0, `enter_events_minus_runs` = 0, `fallback_events_without_reason` = 0,
`box_violations` = 0, `monodromy_rel_diff` < 10⁻⁸, `gradient_cos_ok` ≥ 72, `controls_refused` = 20,
`admit_bit_mismatches` = 0, `ledger_increases` = 0); the episode digests compared for PO-REFLEX-02 and PO-SHIELD-01;
the kill-gate branch read for each property and, for a retired one, the ADR identifier; for each planted
violation an `assert` of kind `negative-control` with `caught` and the first differing value; on failure the
fixture path and seed that reproduce it; and a final `summary` line with assertions passed and failed and the
gates touched.

### Known answers and negative controls
KA-557 (zero residual), KA-562 (transverse instability, for INV-GAIT-01's full spectrum), KA-564 (gradient
suite), KA-568 and KA-570 (energy card and randomized sequences), KA-571 (projection), KA-572 (damping backup).
Counterexamples CX-237, CX-239, CX-240, CX-245. Determinism lanes: PO-REFLEX-02 and PO-SHIELD-01 are themselves
determinism tests (across worker counts; across backends for the integer predicate); the rest run twice on one
machine with equal results.

## Considerations

- PO-SHIELD-04's continuous-time part is a theorem card: T-39 (N12x-04, a dependency of this bead; the registry's
  number governs if the numbering decision closes differently). Part (a) checks the card's polynomial identity
  over the entries of M̄, K_d and p as a host test in exact rationals, cites the card, and records the class the
  card's verdict supports; until the card's verdict is recorded, part (a) is recorded as `Tested`.
- The 10⁶-instance and 10⁴-episode counts are the obligation's own numbers; a smaller smoke subset (10⁴ and 10²)
  runs on every commit, the full counts before the gate is recorded.
- INV-REFLEX-03 was written before the delivered-controller lane existed; the case encodes the amended rule so
  that the lane cannot be used as a general exemption.
