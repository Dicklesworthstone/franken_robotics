## Background

Every mechanism of Reflex (estimation, baseline control, sampling control, gait orbits, skills, the energy budget,
runtime shields, symmetric controllers) is tied to a fixture small enough to check by hand, with an expected
answer and a negative control: a planted wrong implementation that the test must catch. The chapter lists fifteen
such fixtures. They are the seeds of the known-answer suite (tier G1 of the test tiers: analytic and synthetic
truths) and of the counterexample catalogue.

A known answer is only useful if it is stated once, as data, by someone who did not write the code under test,
and if the oracle was never regenerated from the candidate. This bead therefore lands the fixtures as **data
files with their expected values**, before the mechanisms exist, so that each mechanism bead tests against a
pinned definition instead of writing its own expectation. The mechanisms arrive between M1 and M4; each fixture
names the milestone and gate at which it is activated.

## Scope

In: fifteen fixture definition files with inputs, expected values, tolerances, tier and execution site, and the
name of each registered mutant; a loader; a self-test that reproduces every hand value by independent host
arithmetic; the eight hand cases that the later subsections add, as appended known-answer rows numbered from a
block of the allocation ledger, with their fixture files. Out: the
registry rows of KA-553 to KA-575 themselves (truth, tolerance, tier and control per row), which are N22-KA:
this pack cites them by number and repeats the values it needs; the
mechanisms under test and the gate measurements (the beads named per row); the mutants' code (N22-CX registers
them; mechanism beads implement them).

## Technical approach

**Files.** `assets/fixtures/reflex/<name>.toml`, schema `frob.reflex.handfixture/1` (DESIGN; not N24b-03's
`frob.fixture/1`, which is the run manifest `assets/fixtures/<name>/fixture.toml` of the fixture registry that
`sim.run --fixture` reads: one schema name for two layouts would let either loader accept the other's file; a hand
fixture that is also run through `sim.run --fixture`, such as the pre-slip cart, is registered there separately by
its mechanism bead, N22c-27): `id`, `ka` (known-answer
numbers), `inputs` (decimal strings with units, so that no binary rounding enters the definition), `expected`
(value, unit, tolerance, exactness: `exact-rational`, `exact-digest`, `exact-verdict` or a numeric tolerance),
`tier` (G1 unless stated), `site` (`host`, `auditor`, `referee`, `strict`, `lockstep`), `negative_control`
(mutant name and what it returns), `activates` (milestone and gate), `owner` (the bead that runs it).

**Self-test.** `crates/frob-conformance/tests/reflex_fixture_pack.rs` recomputes every value above from the inputs

## Acceptance criteria

- [ ] Sixteen fixture files and eight appended rows exist, load, and validate against `frob.reflex.handfixture/1` and the row schema; a fixture-registry manifest offered to the hand-fixture loader (and a hand fixture offered to N24b-03's loader) is refused for its schema name.
- [ ] The eight appended rows carry numbers from a block issued to N22c-04 in `allocations.toml`, in table order, with their tags in `slug`; `registry::alloc::validate` passes and no tag remains outside `slug` at the M1 exit.
- [ ] The self-test reproduces every expected value: exact rationals where marked exact, printed digits otherwise.
- [ ] Each fixture names a registered mutant (N22-CX or the mechanism bead) and its activation gate; the registry check fails if either is missing.
- [ ] No fixture's expected value is generated by running the mechanism it tests (review check; the files carry a `derived_by = "hand"` field and the derivation in a comment).
- [ ] The fixture files are listed in the conformance registry under tier G1 (fixture 5 under G5), with their execution sites.

## Test plan

### Unit tests
- `pack_loads_and_validates`: 16 + 8 entries; unknown fields refused.
- `pack_late_rows_allocated`: the eight appended rows lie in the block issued to N22c-04, contiguous and in table order; a planted row numbered outside the block is refused (`unallocated-number`).
- `pack_speed_limit_rounding`: v²/5.886 + 0.02·v ≤ 0.45 holds at 1.5696 and fails at 1.5697; the printed trigger 0.7196 m is at least 4/5.886 + 0.04.
- `pack_hand_values`: one assertion per value in the two tables, for example 25/3 N; 65,536, 204,800, 40,500 and 299; e^(±1); v/4 and 1/16; 0.64 + 0.50 + 0.25 + 0.10 = 1.49 J and 50.5 ms, 45.5 ms; 50 kg; (1, 0.5); 39.24 N; 1.457107 and 1.207107; −2 m/s and +1.5 J.
- `pack_bar_beta_sweep`: for β ∈ {1/3, 1/2, 1, 2} the first-end speed is 2β·(1 − β)·v/(1 + β)², positive exactly for β < 1.
- `pack_rimless_no_fixed_point_uphill`: b < 0 yields no positive ω*².
- `pack_rimless_two_instances`: instance (a) gives 2.094996 and 1.447410 to 10⁻⁶ relative, equal to N22-KA's
  derived values; instance (b) gives 1.20004; both through one formula function.
- `pack_every_fixture_has_mutant`: the registry check.

### End-to-end script and logging
`scripts/e2e/reflex_fixture_pack.sh` (sources the STD-E2E helper; NDJSON at
`target/e2e-logs/reflex_fixture_pack/<utc>.ndjson` with a transcript). There is no `frob conformance` command
(ADR-GAUNT-01; BD-025's lint `no_conformance_command` fails a script that contains it). The script runs the
self-test `cargo test -p frob-conformance --test reflex_fixture_pack`; then, for each fixture whose `activates`
milestone has been reached, the gate's target in the cargo form `FROB_TEST_SEED=<seed> cargo test -p
frob-conformance --test <tier from the gate's tier field> -- <gate>` (for example `--test g1_known_answers --
GATE-REFLEX-03` at M1), once as is and once with `--features gauntlet-mutations` and the fixture's mutant
feature (a gate whose case has not landed yet is logged `not yet active`, never passed). The membership of the
Reflex fixtures in the `fixtures` battery, with their sites, is checked by the battery's own beads (N24b-01 and
N24c-10, whose scripts run `frob eval run --battery fixtures --key <k> --json`), not here: `eval.run` and that
battery come after this bead, which only lists the fixtures in the conformance registry. Logged per the shared standard
(command line, exit code, wall time, receipt hash): the fixture id, the known-answer number (and slug for an
appended row), the expected and measured values with units and tolerance, the mutant's result (must differ), and
a summary with counts `reproduced`, `control caught`, `not yet active`.

### Known answers and negative controls
All of KA-553, -554, -556 to -560, -562, -563, -565, -566, -568, -569, -571, -572, -574, -575 by value as tabled.
The pack's own negative control: a fixture file whose expected value is altered by one unit in the last printed
digit must fail the self-test. Determinism: the self-test is host arithmetic and identical on every platform.
