## Background

The sampling-based predictive controller (kind `mpc-sample`) works as follows. The decision variable is a set
of spline knots of command targets over a horizon T_h (0.4 to 0.9 s, control at 50 Hz). At each control tick,
for each of N_it annealing iterations, it draws N_s perturbations of the knots from counter-based random
streams keyed by (world address, tick, iteration, sample), forks the world's full state into N_s planning
worlds, rolls each over the horizon on a planning configuration of the **compiled model**, scores each rollout
with morphology-independent cost terms, forms softmax weights, updates the knots and shrinks the noise; it then
applies the first command. One tick costs N_s·H·N_it compiled-model steps.

For one soft-soil regime of a tracked or wheeled base, the lifted model of N22c-23 can replace those rollouts:
its planning step is three 36 × 36 matrix–vector products. This bead puts the lifted model behind the
controller's planning-model interface, selected by `control.mpc --planner lifted:<id>`, with the rule that keeps
it honest: a planner tick whose measured state leaves the calibrated regime is refused and **that tick is
served by `mpc-sample` on the compiled model**. Moonshot; off the critical path.

## Scope

In: the planning-model interface with two implementations; the lifted rollout and its cost evaluation; the
per-tick regime check, refusal event and fallback; identity and labels; cost accounting per tick; the task
fixture `soil-velocity-tracking` (commanded forward speed and yaw rate on `sand-dry`, inside the regime box,
20 s per episode) and its variant `soil-velocity-tracking-overspeed` (the same task whose episode starts at a
forward speed of 1.05 m/s, 5% above the regime's speed box, with the commanded speed inside it). Out: fitting
and admission (N22c-23); the gate measurement (N22c-25); the sampling controller itself (seed beads BD-252 and
BD-331).

## Technical approach

**Interface (DESIGN).** In `frob-control::mpc`:

```rust
pub trait PlanningModel {
    /// Roll N_s candidate input sequences over H steps from the measured state; return per-sample cost inputs.
    fn rollout(&self, x0: &MeasuredState, knots: &KnotBatch, horizon: Horizon) -> RolloutBatch;
    fn id(&self) -> PlanningModelId;          // enters the ControllerId
    fn cost_steps_per_tick(&self, n_s: u32, h: u32, n_it: u32) -> CostAccount;
}
pub struct CompiledModelPlanner { /* forks + compiled-model steps: K-fork, K-cost, K-weight */ }
pub struct LiftedPlanner { model: LiftedModel, fallback: CompiledModelPlanner }
```

**The lifted tick.**
1. Read the measured reduced state x (forward speed, yaw rate, slip and sinkage of each track, pitch) from the
   controller's state source.
2. **Regime check.** If x lies outside the model's regime (soil-card ranges of pressure, slip and sinkage; the
   speed and yaw-rate box; the slope range; every track sample in contact), emit the per-tick refusal event
   `lifted-planner-out-of-regime` with the violated field and value, and serve this tick with
   `CompiledModelPlanner` (the layer record of the tick is `fallback:lifted-out-of-regime`). No lifted rollout is
   used for that tick.
3. Otherwise, for each iteration and each sample: decode the knots to an input sequence, **clamped to the
   calibrated input range**; iterate z⁺ = A·z + u_L·B_L·z + u_R·B_R·z with re-lifting each step for H steps;
   accumulate the cost from the predicted reduced state: body-twist tracking (speed and yaw-rate error), a
   power proxy u·ω, slip above a threshold as the friction-utilization term, sinkage and pitch barriers at the
   regime's edges. A predicted state that leaves the regime inside the horizon receives a barrier cost and is
   never extrapolated: its remaining steps are frozen at the boundary value and the sample is flagged.
4. Softmax weights, knot update and noise shrink as for the compiled planner; the random streams and their keys
   are the same, so a run replays exactly.
5. Apply the first command. Record for the tick: planner used, samples flagged at the regime edge, cost in
   multiply–adds (lifted) or compiled-model steps (fallback).

**Identity and labels.** The `ControllerId` covers the planning configuration; with a lifted planner it also
covers the `LiftId`. Results carry `screening: sampling-control` and `surrogate`, are class `Estimated`, and
inherit every rule of the sampling controller: at most three episodes per design by default; never the scoring
source of acceptance, promotion or qualification (FROB-REF-817); `model-privileged` unless the planning model's
parameters were drawn independently of the plant's randomization and the planner ran on estimated state. A
lifted planner is **not** admitted under the delivered-controller lane: a frozen planner record names a
compiled `ModelId`, and a surrogate planning model is refused there (DESIGN, fail-closed).

**Cost accounting.** Per tick the controller reports `planner_cost` in a common unit, compiled-model-step
equivalents: one compiled planning step counts 1; one lifted step counts its measured time divided by the
measured time of one compiled planning step on the same tier and device. The gate's "at least ten times lower"
is read on this figure at equal tracking accuracy.

**Verb surface.** `frob control mpc <design> --task <task> --planner lifted:<id> [--state privileged|estimated]
[--episodes n] [--seed <s>] --key <idempotency key> --json` (`control.mpc` is a job-submitting `run` verb: without
a key it is refused with FROB-REF-805); with an unknown or unadmitted `LiftId` the verb refuses before running; the
result adds `lifted_ticks`, `fallback_ticks`, `edge_flagged_samples` and `planner_cost_per_tick`. `--state` is the
row's state-source input (`privileged`, the default, or `estimated`; BD-252), never an initial state: a file
there is `FROB-REF-802`. A single out-of-regime query is posed from the command line by a task whose episode
starts outside the regime, the fixture variant `soil-velocity-tracking-overspeed` above.

## Acceptance criteria

- [ ] With `--planner lifted:<id>` and a state inside the regime, no compiled-model rollout is launched for the tick (checked by the launch counter).
- [ ] A tick whose measured state leaves the regime is served by the compiled planner, records `fallback:lifted-out-of-regime`, and emits the refusal event; every such query is refused (a clause of GATE-REFLEX-10).
- [ ] The controlled world's digest does not depend on the number of planning samples run beside it, with either planner.
- [ ] A lifted-planner run replays bit for bit from its seed and world address on `batch-cpu`.
- [ ] Results carry `surrogate`, `screening: sampling-control`, class `Estimated`; an acceptance request over them is refused with FROB-REF-817; a `--freeze` request with a lifted planner is refused.
- [ ] `planner_cost_per_tick` is reported for both planners in the common unit.

## Test plan

### Unit tests
`crates/frob-control/tests/mpc_lifted.rs`:
- `lifted_tick_launches_no_forks`: launch counter of compiled planning steps is zero inside the regime.
- `out_of_regime_tick_falls_back`: speed 5% above the box gives one fallback tick, one event, and the next in-regime tick returns to the lifted planner.
- `inputs_clamped_to_calibrated_range`: a knot decoding to 120% of the calibrated torque is clamped; the clamp count is reported.
- `no_extrapolation_past_edge`: a predicted state leaving the regime at step 7 of 16 is frozen and flagged; its cost includes the barrier.
- `same_streams_same_plan`: with a lifted model that reproduces a linear `synthetic` plant exactly, the lifted and compiled planners return the same first command to 10⁻¹² on that plant.
- `controller_id_includes_lift_id`: changing one coefficient of the model changes the `ControllerId`.
- `freeze_refuses_lifted`: `control.mpc --freeze --planner lifted:<id>` is refused.

### End-to-end script and logging
The gate measurement (paired episodes, the full out-of-regime sweep, the cost ratio) is N22c-25's
`scripts/e2e/gate_reflex_10.sh`. This bead's own script, `scripts/e2e/reflex_mpc_lifted.sh` (sources the
STD-E2E helper; NDJSON to `target/e2e-logs/reflex_mpc_lifted/<utc>.ndjson` with a transcript), checks the verb
surface on an admitted model that it first builds in its own state root from N22c-23's fixtures (`frob design new
tracked-a --template tracked-flipper --key mpl-design --json`; the data run of N22c-23's script with key
`mpl-data`; `frob control lift tracked-a --soil sand-dry --regime regime.toml --fit --key mpl-fit --json` and
`--calibrate --runs <that run id> --key mpl-cal`, asserting `admitted`; its `LiftId` is `<id>` below):
`frob control mpc tracked-a --task soil-velocity-tracking
--planner lifted:<id> --episodes 1 --seed 3 --key mpl-in-1 --json`, whose episode starts inside the regime
(asserting `lifted_ticks` > 0, `fallback_ticks` = 0); the same with `--task soil-velocity-tracking-overspeed --key
mpl-out-1` (asserting the first tick is `fallback:lifted-out-of-regime` with the event naming `speed_box` and the
measured value 1.05 m/s); the in-regime call repeated with key `mpl-in-2`, asserting an equal episode digest (replay);
`--freeze --key mpl-frz-1` (`e2e_expect_refusal FROB-REF-817 3`); and `--planner lifted:l:0000 --key

`edge_flagged_samples` and `planner_cost_per_tick` with its unit, the episode digests, and on failure the first
differing value with the run identifier. `summary`: assertions passed and failed, `gates: ["GATE-REFLEX-10"]`
(touched, not decided here).

### Known answers and negative controls
On the `synthetic` linear plant x⁺ = 0.9·x + 0.5·u the lifted model with dictionary {1, x} is exact, so both
planners agree; this is the integration's known answer. Negative controls: a build that skips the regime check
must be caught by the out-of-regime sweep (a tick outside the box served by the lifted planner fails the test);
a build that lets predicted states extrapolate must fail `no_extrapolation_past_edge`. Determinism lanes: twice
on one machine; across worker counts; debug and release, on `batch-cpu` under the replay profile.

## Considerations

- Ceiling, stated first: inside the controller the benefit is at most the ratio of rollout cost to lifted cost;
  on a design cycle it is the share of wall time the screening rung spends on soft-soil tasks, which is
  unmeasured and expected to be small.
- The fallback planner must stay compiled and warm for every run, so the lifted path never removes the compiled
  planning kernels' memory footprint.
- If the sampling controller was reduced to a single-world CPU debugging aid at its kill gate, this bead is not
  funded.
