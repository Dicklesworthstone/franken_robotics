## Background

The sampling-based predictive controller (kind `mpc-sample`) is refused as the scoring source of acceptance,
promotion or qualification (refusal FROB-REF-817). That rule guards one substitution: scoring a design under a
sampling controller and reporting the score as if a trained policy had earned it. It does not fit the case where
the sampling controller is itself what the mission delivers: an accepted answer is a design, a controller and an
evidence package, and when the controller in that package is of kind `mpc-sample`, episodes run under it are the
only evidence about it. A refusal keyed on the controller kind alone would leave the package with no evidence at
all. The **delivered-controller lane** (Frontier) therefore admits such episodes, for one frozen planner
configuration only and under four conditions.

This bead is the controller-side half: the planner record that freezes the configuration, the flag that writes
it, and the latency model that makes the planner's compute time part of the simulated loop. The episode
admission half is N22c-32. Rejected alternative: relaxing FROB-REF-817 by a task-level flag with no record; it
would let any screening result be relabelled as acceptance evidence.

## Scope

In: the record type, its digest and its place in the `ControllerId`; `control.mpc --freeze`; measurement of
planning time on a named computer; the delay and deadline-miss model in the simulated loop; the
`model-privileged` flag's exact definition; refusal to freeze an inadmissible configuration. Out: admission of
episodes and the verdict string (N22c-32); the sampling controller's kernels (seed bead BD-252).

## Technical approach

**The record (DESIGN, fixes intent).**

```
planner_record  (frob.control.planner/1)
  kind            mpc-sample
  budget          samples N_s · horizon steps H · iterations N_it      model steps per tick = N_s·H·N_it
  planning_step   h_p · control rate
  cost_terms      content hash of the class-default or task-declared cost
  planning_model  ModelId rolled out by the planner · source of its parameters (nominal | estimated | plant)
  state_source    estimated (the invariant filter) | privileged
  compute_target  named computer · measured planning time per tick: median, 99th percentile · deadline
```

```rust
pub struct PlannerRecord {
    kind: ControllerKind,                 // MpcSample
    budget: PlannerBudget,                // n_s, h, n_it; steps_per_tick() = n_s·h·n_it
    planning_step: Rational, control_rate: Rational,
    cost_terms: Digest,
    planning_model: ModelId, parameter_source: ParamSource,   // Nominal | Estimated | Plant
    state_source: StateSourceKind,        // Estimated | Privileged
    compute_target: ComputeTarget,        // machine fingerprint, plan_ms_median, plan_ms_p99, deadline_ms,
                                          // miss_fraction, n_ticks_measured, measured: bool
    spline_family: SplineId,
}
impl PlannerRecord { pub fn digest(&self) -> Digest; pub fn delay_periods(&self) -> u32; }
```

The record's digest is part of the `ControllerId`; any change to a field gives a new controller.

**Definition of `model-privileged`.** An episode is flagged `model-privileged` unless both hold: the planning
model's parameters were drawn independently of the plant's randomization (`parameter_source` is `nominal` or
`estimated`, never `plant`), and the planner ran on estimated state. The flag is computed from the record and
the run, never set by hand.

**Latency model.** The planner's compute time is a modelled delay of one control period unless a measured figure
for a named computer is supplied; a zero-delay planner is labelled as such. With a measurement:
1. delay d = ⌈plan_ms_p99 / control period⌉ whole control periods (`delay_periods`);
2. the plan computed from the observation delivered at tick k is applied from tick k + d; until then the
   previous plan's later knots are executed;
3. a tick that misses its deadline holds the previous plan: in simulation a miss is drawn from a counter-based
   stream keyed by (world address, tick) with probability `miss_fraction` (the measured share of ticks whose
   planning time exceeded the deadline), so that replays are exact;
4. the delay is expressed in the clock contract's rational periods, so it composes with sensor and actuation
   delays.

**Measuring.** `frob control mpc <design> --task <task> --measure-latency --computer <name>` runs the planner at
the record's budget on the named machine for at least 10⁴ ticks, records median, 99th percentile and the share
of ticks above the deadline, with the machine fingerprint (device, driver, thermal state, co-tenancy). The
measurement is a Performance observation with its disclosure block and is not itself evidence about the robot.

**`control.mpc --freeze`.** Writes the record for a design and task and prints its digest. It refuses to freeze
(FROB-REF-817 payload names the missing condition; exit 3) when the configuration could never be admitted:
`parameter_source = plant`; `state_source = privileged`; `compute_target.measured = false` or a zero delay. A
frozen record is immutable; changing the budget or the cost means a new freeze and a new digest. `--freeze` also
lifts the episode cap of `control.mpc` (three episodes unless `--demonstrations` names a distillation job,
`--compare` names a paired screening comparison, or `--freeze` writes a planner record).

**`control.show`** prints the record for a controller of kind `mpc-sample`.

## Acceptance criteria

- [ ] `frob control mpc … --freeze --json` writes a record that validates against `frob.control.planner/1` and returns its digest; the same inputs give the same digest.
- [ ] Any single-field change to the record changes the `ControllerId`.
- [ ] Freezing is refused, with the missing condition named, for `parameter_source = plant`, for `state_source = privileged`, and for an unmeasured or zero delay.
- [ ] With a measured p99 of 23 ms and a 20 ms period the applied delay is 2 periods; a missed tick holds the previous plan; the run replays bit for bit.
- [ ] `model-privileged` is set exactly when the definition says, on a table of the six combinations of parameter source and state source.
- [ ] Steps per tick are reported as N_s·H·N_it (3,072 for 64, 16, 3).
- [ ] `frob-control`'s `CONTRACT.md` documents the record and the latency model; cancellation of a latency measurement is tested.

## Test plan

### Unit tests
`crates/frob-control/tests/planner_record.rs`:
- `record_digest_stable_and_sensitive`: equal inputs, equal digest; one test per field for sensitivity.
- `delay_periods_rounding`: 19 ms → 1; 20 ms → 1; 20.1 ms → 2; 23 ms → 2; 41 ms → 3 (20 ms period).
- `plan_applied_after_delay`: with d = 2 the command at tick k + 2 is the first knot of the plan computed from tick k's observation.
- `missed_tick_holds_previous_plan`: with `miss_fraction` = 1 on one planted tick the previous plan's next knot is applied.
- `miss_draws_replay`: the miss pattern is identical across two runs and across worker counts.
- `model_privileged_truth_table`: (nominal, estimated) → not privileged; every other combination → privileged.
- `freeze_refusals`: three inadmissible configurations, three named conditions.
- `zero_delay_is_labelled`: a planner with no latency model carries the label `zero-delay`.

### End-to-end script and logging
Through `scripts/e2e/gate_reflex_11.sh` (N22c-33): freeze, measure, and run under the record; the log carries
the record's digest in every evidence block.

### Known answers and negative controls
Steps per tick: 2,048·16·2 = 65,536; 2,048·25·4 = 204,800; 30·450·3 = 40,500; 64·16·3 = 3,072. Negative controls:
a record with the delay silently set to zero must be refused at freeze; an identity that omits the record's
digest must be caught by the sensitivity test. Determinism lanes: twice on one machine; across worker counts;
debug and release, on `batch-cpu`.

## Considerations

- A verdict under the lane is tied to the named computer's measurement. A faster or slower computer is a new
  record.
- The 99th percentile sets the delay and the measured miss fraction sets the misses; if the kill gate's deadline
  clause fails (no named computer meets the deadline in 99% of ticks for any class) the lane is withdrawn.
- A lifted (surrogate) planning model is not admitted in a frozen record: `planning_model` must be a compiled
  `ModelId` (DESIGN, fail-closed).
