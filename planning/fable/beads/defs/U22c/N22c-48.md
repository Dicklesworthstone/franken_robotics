## Background

GATE-REFLEX-01 (claim: Known answer): each archetype stands for 10 s and traverses 5 m of flat ground under its
baseline controller. Its parts: the first archetypes on the referee at M1; the same on `batch-cpu` at M2; all
eighteen on `batch-cpu` at M3 **except tracked and hybrid archetypes, which follow at M4 with their contact
laws**. The gate closes at M4 with those archetypes. No seed bead carries the M4 rows, so this bead does.

The archetypes concerned (from the eighteen): `tracked-flipper` (two tracks with front and rear flippers, 6
actuated coordinates; the belt law; skid steering, where turning in place must cost scrub work), `wheel-leg` (a
quadruped with driven wheels as feet, 16 coordinates; two contact laws on one end-effector class; switching
between rolling and stepping) and `tri-wheel-stair` (two tri-wheel clusters on a chassis). Their baseline
classes: **Tracked** (Solid: skid-steer with a slip estimate) and **Hybrid** (Frontier: roll where the route
graph allows, step where it does not; an explicit drive, stand and step mode graph with readiness guards). The
hybrid route is funded only if its pilot (N22c-06) was not falsified; otherwise hybrid archetypes report
`not-synthesizable` and their rows are recorded as `killed: fallback adopted`.

## Scope

In: one script; stand and traverse rows for the tracked and hybrid archetypes on `batch-cpu`, with the `strict`
profile as adjudicator; class-specific checks that the contact laws are really exercised; the gate rows and the
statement that the gate is closed. Out: the controllers (seed bead BD-247); the contact laws (BD-245); the
pilot (N22c-06).

## Technical approach

Script `scripts/e2e/gate_reflex_01_tracked_hybrid.sh`; seed from `FROB_E2E_SEED` (default 1); idempotent;
non-zero exit on any failed assertion.

Tiers. A tracked robot with patch samples along two belts exceeds the referee's limit of 21 contacts in normal
driving, so the referee cannot run it; the rows are measured on `batch-cpu`, and the `strict` profile of
`batch-cpu` (the transactional, event-located step in `f64`) adjudicates. The wheel-leg robot fits the referee
when rolling and is marginal in transitions; its row is measured on `batch-cpu` with a referee run where it fits.

Per archetype A in {`tracked-flipper`, `wheel-leg`, `tri-wheel-stair`}:

1. `frob control synth A --tier batch-cpu --state estimated --seed $SEED --json`: assert the detected class
   (Tracked for the first, Hybrid for the others), the outcome, `stand_s ≥ 10`, `traverse_m ≥ 5`.
2. The same on `--profile strict`: assert the same verdicts; log differences.
3. **Class-specific evidence** (the "evidence required first" of the class table, checked so that a pass is not
   an accident of a simplified contact law):
   - Tracked: a pivot turn of 90° in place: assert the ledger shows positive scrub work (dissipated at the
     belts) and that the heading change matches the slip-aware estimate within 10%; assert that a no-slip model
     of the same base is refused or flagged (it would turn at no cost).
   - Hybrid: on flat ground the traverse uses the `drive` mode (assert the mode record); a 20 mm sill forces one
     `drive → stand → step → stand → drive` cycle per axle (assert the mode sequence and that every guard event
     is recorded).
4. **Layer records.** Every tick has a layer record; the fractions of `fallback:*` and `backup` are reported.
5. **Batch independence.** World 0 alone and in a batch of 64: equal digests.
6. **Record.** One gate row per archetype; then, if every archetype of the eighteen has a recorded row that is a
   pass or a kill decision with its fallback adopted, mark GATE-REFLEX-01 closed in the gate register and list
   the rows it rests on.

**Logging.** Newline-delimited JSON to `target/e2e-logs/gate_reflex_01_tracked_hybrid/<utc>.ndjson` and a
transcript. Every line: `ts`, `script`, `bead` (`N22c-48`), `step`, `event`, the exact command, exit code, wall
time, the envelope's `evidence` block. Metrics with thresholds: `stand_s` (≥ 10), `traverse_m` (≥ 5),
`scrub_work_j` (> 0), `heading_err_frac` (≤ 0.10), `mode_sequence` (as stated), `guard_events_recorded` (all),
`contacts_max` (reported against the tier's capacity), `world0_distinct_digests` (1), `strict_agrees` (true).
On failure: the first differing value and the episode file paths. A `summary` line: assertions passed and
failed; gate GATE-REFLEX-01 with per-archetype status and the closure statement.

## Acceptance criteria

- [ ] The script exits 0 only when each tracked and hybrid archetype has a pass, or a recorded kill decision with its fallback (`not-synthesizable`) adopted.
- [ ] The gate register holds the M4 rows of GATE-REFLEX-01 with measured values, commit and receipt, and the closure entry naming all eighteen archetypes' rows.
- [ ] The tracked pivot shows positive scrub work; the no-slip variant is caught.
- [ ] The hybrid mode sequence across the sill is recorded with its guard events.
- [ ] A capacity overflow is flagged `Degraded` or refused by name, never truncated.

## Test plan

### Unit tests
Helpers in `scripts/e2e/tests/`: `closure_requires_all_eighteen` (a missing row blocks closure);
`killed_row_counts_as_decided` (a row `killed: fallback adopted` satisfies closure; a `fail` or `not run` does
not); `mode_sequence_match`.

### End-to-end script and logging
As specified above; this bead is the script.

### Known answers and negative controls
Gate thresholds 10 s and 5 m (TARGET). Negative controls: a no-slip skid model (turning in place at zero scrub
work) must be caught; a hybrid controller with its support-margin guard removed must fail on the sill; a row
for an archetype whose class was withdrawn by the baseline kill gate must read `killed: fallback adopted`, not
`pass`. Determinism lanes: twice on one machine; across worker counts and batch sizes; `strict` against the
default `batch-cpu` profile with decision-level agreement.

## Considerations

- The list of archetypes that the class detector labels Tracked or Hybrid is determined by the detector; if
  `tri-wheel-stair` is classed otherwise, its row belongs to the M3 part and this script records only the
  archetypes so classed.
- Rank agreement for tracked and hybrid classes (GATE-REFLEX-04) is also due at M4 and is a separate gate.
- If the baseline kill gate limited synthesis to the classes that pass, closure is reached with kill rows.
