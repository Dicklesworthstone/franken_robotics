## Background

A kill gate is a decision named in advance with its trigger, measurement and fallback; a kill gate that fires is
not a failure, because the fallback is the plan. Its decision is recorded as an ADR.

KILL-TUBE governs a Moonshot item of the runtime shields: for a subsystem of at most four reduced states with a
bounded sensing error (a wheel at a threshold, a tray about to tip, braking across two floor materials), a table
over at most 8 modes × 16,384 cells is built by backward viability pruning; at run time the whole belief set is
looked up, and outside the table the answer is `uncovered` and the backup controller's domain applies. The
table is a payload of the shield record, with no file format of its own. The benefit is small by the plan's own
statement: a lookup replaces an online reachable-set computation, and no design decision is known to depend on
it.

## Scope

In: applying the trigger, recording the ADR, stating the downstream changes. Out: the pilot (N22c-13); the
table mechanism, the gate measurement and the epic's plan (seed bead BD-440).

## Technical approach

**Trigger.** GATE-SHIELD-05 fails, or the pilot's falsifier holds. The gate (claim: Known answer; TARGET;
Moonshot): zero false admissions in 5,000 in-envelope episodes on the braking fixture, and `uncovered` outside
the table. The pilot's falsifier: coverage under 90% of the operating set at 16,384 cells per mode, or one false
admission in 5,000 in-envelope episodes.

**Milestone.** M8, or earlier if the pilot is falsified.

**Measurement that decides it.** From N22c-13: coverage of the operating set and the count of false admissions.
From the epic's gate run, if funded: false admissions on the braking fixture and the behaviour of lookups
outside the table. A false admission is counted from the simulator's true state: the table admitted every
belief set along the episode and the true state entered the unsafe set.

**Decision rule.**
1. Pilot falsified (coverage below 0.90, or any false admission) → **fires**; the epic is not funded.
2. Pilot passed and the gate shows zero false admissions with `uncovered` outside the table → `not fired`.
3. Pilot passed and the gate shows a false admission, or an out-of-table lookup that is not `uncovered` →
   **fires**. No repair cycle is named for this gate.
4. If KILL-SHIELD has fired, the tables have no host: this gate is recorded as fired by consequence, with that
   reason.

**Fallback, named in advance.** No tables are built; reduced-order barriers cover those subsystems.

**What changes downstream when it fires.**
- The shield record has no table payload; the `Uncovered` shield event is never emitted by a table.
- Threshold crossings, trays and braking on mixed floors are handled by barrier rows on a reduced-order template
  with the measured margin, or by the closed-form sampled-data backup domain where one exists (for braking:
  s ≥ v²/(2·μ_min·g) + v·Δt).
- The erosion rule for one-sided sensing errors (erosion by −E, not by E) stays as a known answer of the test
  suite, since the same sign error can occur in any margin computation.
- The epic records "not built"; nothing in M0 to M7 changes.

**Record.** ADR with measured values, commit, hardware fingerprint, seeds, decision, fallback and affected
beads; rows of KILL-TUBE and GATE-SHIELD-05 in `registries/gates.toml` updated with the same receipt.

## Acceptance criteria

- [ ] The ADR cites the pilot's coverage and false-admission count and, if run, the gate's.
- [ ] `registries/gates.toml` carries the decision and the gate status with measured values.
- [ ] If fired: a test shows a shield fitted for the braking subsystem using barrier rows or the closed-form backup domain, with no table payload.
- [ ] If not fired: the table's size, coverage and build time are in the record.
- [ ] The decision is made by a session that did not run the measurement.

## Test plan

### Unit tests
- `kill_tube_rule_table`: (coverage 0.86) → fired; (coverage 0.94, 1 false admission) → fired; (coverage 0.94, 0 false admissions, gate clean) → not fired; (KILL-SHIELD fired) → fired by consequence.
- `no_table_payload_after_kill`: a fitted shield record has no table.

### End-to-end script and logging
`scripts/e2e/kill_tube_record.sh`: reads the pilot's and the gate's logs and the registry, asserts agreement,
applies the rule, exercises the fallback when fired. Logged per the shared standard: `coverage` (threshold
0.90), `false_admissions` (threshold 0 of 5,000), `uncovered_outside_table` (true), the decision, the ADR path.

### Known answers and negative controls
The erosion known answer: a cell [0, 1] of measured states with error in [0, 0.1] has admissible true
successors [0.1, 1.0]; erosion by E gives [0, 0.9], which is unsound. Negative control: a record with targets in
place of measured values is rejected by the registry check.

## Considerations

- Moonshot: priority 4; nothing in M0 to M7 depends on the outcome.
- The reduction of a robot to four states is an assumption that the shield's monitors watch; it is not proved,
  whatever this decision.
