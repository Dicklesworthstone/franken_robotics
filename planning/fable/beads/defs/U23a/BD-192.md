## Background
`VecEnv` is the vectorized environment: the one interface through which training, evaluation and `sim.run` step batches of simulated worlds. It exposes `reset(mask)`, `step(actions)`, `snapshot(worlds)` and `restore(snapshot)` over device-resident buffers; host code receives views and nothing is copied unless asked. It is Solid tier, crate `frob-learn::env`, and serves the goal of training on device under correct gym semantics.

The semantics here replace the common convention of *masked automatic reset with post-reset observations*. Under that convention, when a world ends, the step silently resets it and returns the first observation of the next episode. The observation the world actually ended in is lost, and with it the value needed to bootstrap a truncated episode; a single `done` flag then makes a time limit indistinguishable from a real terminal state. The result is a biased value target that no plumbing test notices. Known answer: a true 8 s mission deadline with terminal reward 0 needs bootstrap target 0; an external collection cut at the same instant on a continuing task with V = 10 and γ = 0.99 needs 9.9. One flag cannot produce both (counterexample CX-246).

Decisions restated. **ADR-CORTEX-01**: explicit reset is the default, and the final observation of every ended world is preserved in every mode; reason: a masked automatic reset that returns post-reset observations loses the observation a truncation bootstrap needs. **ADR-CORTEX-02**: the Rust `VecEnv` is the stepping authority and an optional Gymnasium-compatible adapter lives in an annex; reason: rival learning stacks must be able to drive this environment in the head-to-head comparison without Python entering the core. Rejected: adopting the host library's autoreset convention as native (would import its ambiguity into every result); exposing the environment as a verb of its own (the environment has no verb; `train.*`, `eval.*` and `sim.run` reach it).

## Scope

## Technical approach
**Trait and views (DESIGN sketch).**
```rust
pub trait VecEnv {
    fn spec(&self) -> &TaskProgram;
    fn reset(&mut self, mask: &WorldMask, seeds: &SeedPlan, cx: &Cx<'_>) -> Result<ResetView<'_>, Refusal>;
    fn step(&mut self, actions: ActionView<'_>, cx: &Cx<'_>) -> Result<StepView<'_>, Refusal>;
    fn snapshot(&self, worlds: &[WorldId]) -> Result<Snapshot, Refusal>;
    fn restore(&mut self, snapshot: &Snapshot) -> Result<(), Refusal>;
}
pub struct StepView<'a> {
    pub obs: TensorView<'a>,             // after the transition; for an ended world, its final observation
    pub reward: TensorView<'a>,          // integrated over the control interval
    pub dt_sim: TensorView<'a>,          // simulated duration of the interval, per world
    pub terminated: MaskView<'a>,        // success, failure, or an intrinsic mission deadline
    pub truncated: MaskView<'a>,         // an external collection limit on a continuing task
    pub invalid: MaskView<'a>,           // numerical failure: a study error, not a transition
    pub needs_reset: MaskView<'a>,       // terminated | truncated | invalid
    pub applied_action: TensorView<'a>,  // after the limiter and any shield
    pub final_obs: Option<TensorView<'a>>, // masked-autoreset mode only; `obs` then holds post-reset values
    pub info: InfoView<'a>,              // sample ages, validity masks, control layer, shield events
}
pub enum ResetMode { Explicit, AutoresetMasked }
```
`Cx` is the cancellation and budget context of the runtime; `step` checks it at the commit boundary and never mid-step. One `step` is one control interval: the action is held while the physics advances d substeps (the decimation of the task), sensors and packet queues advance by the clock contract, and the task program's observation, reward, termination and monitor stages run in the last stage of the batched step.

**Rules, each with a fixture in GATE-CORTEX-06.**
- **E-1 Explicit reset.** A world with `needs_reset` set stays ended until the caller resets it. Stepping it is refused with FROB-REF-521 before any world in the batch is mutated; the payload names the world ids. Repairs: reset the world; or run in the labeled `autoreset: masked` mode. In a batch, the caller may pass a step mask that excludes ended worlds; excluded worlds are untouched and their views repeat their final values.
- **E-2 The final observation is preserved.** In `Explicit` mode the `obs` of an ended world is its final observation. In `AutoresetMasked` the world is reset inside the step, `final_obs` carries the final observation and `obs` the post-reset one. The mode is in the run manifest and in every result's evidence block. Invariant INV-CORTEX-01: the final observation of every ended world is retrievable in every reset mode.
- **E-3 Termination and truncation are different facts.** `terminated`: success, failure or an intrinsic mission deadline (a deadline that is part of the task). `truncated`: an external collection limit on a task that would have continued. If both are set, termination controls the bootstrap. The task program declares which conditions are which; a condition with no declared kind is refused at task admission.
- **E-4 Invalid physics is a study error.** A world whose step outcome is `Faulted`, or `Degraded` beyond the task's declared policy, sets `invalid`. It has weight zero in policy updates and is kept, with its trace, in benchmark and failure counts. A fall is a valid transition and sets `terminated`, not `invalid`.
- **E-5 Actions are checked before state changes.** A non-finite action (NaN or ±∞ in any component of any live world) is refused with FROB-REF-522 before any state is mutated; the payload names the world and channel. Repair: fix the policy output. For bounded actions the declared out-of-range rule applies, and proposed and applied values are both logged.
- **E-6, E-7, E-8, E-9** are provided by N23a-02, N23a-04 and N23a-03 and are wired here: the views carry typed spaces, masks and ages; views are in caller order by logical id; the actor view is the schema projection; the causality harness runs against this implementation.

**Interval integration.** `reward` is the task program's reward integrated over the interval: a *rate* term (per second) is accumulated as Σ over physics substeps of rate × substep duration; an *event* term is counted once per event identity; a *terminal* term is counted once at the ending step. `dt_sim` is the simulated duration actually advanced for each world in the interval (it may differ between worlds when designs, tasks or rungs have different control periods), and it is what the learner's physical discount consumes. Counterexample the fixture reproduces (CX-247): a penalty of 1 per control step over a 10 s episode totals 500 at 50 Hz and 1,000 at 100 Hz for the same motion; the same penalty declared as a rate of 50 per second totals 500 at both.

**Throughput units.** Receipts report `env_steps` (control intervals) and `world_steps` (physics steps) separately; at ten physics steps per interval, 400 k environment steps per second is 4.0 M world-steps per second. No figure is printed without its unit.

**Masked autoreset, as a labeled mode.** Sequence inside one step for a world that ends: commit the transition; copy the final observation and flags into the `final_obs` slab; reset the world (episode counter, addressed seeds, settled pose, hidden rows, monitors); compute the post-reset observation into `obs`. `terminated`, `truncated` and `reward` refer to the transition that ended. The run manifest records `reset_mode: autoreset-masked`; checkpoints trained under it record the mode in `trained_on.reset_mode`.

**Determinism and evidence.** Class D2 per backend. Every view carries the run's evidence block (tier, determinism class, model, scene and task identities, seed). The ledger records the reset mode, the slot table and per-interval receipts.

## Acceptance criteria
- [ ] GATE-CORTEX-06 (Known answer, M2, TARGET) is measured and recorded with measured values: rules E-1 to E-9 each pass their fixture; the final observation is retrievable in both reset modes; the bootstrap fixture yields 0 and 9.9; the 500 against 1,000 reward fixture is invariant under rate terms (the seed bead's done-condition).
- [ ] E-1: stepping a batch that contains an ended world returns FROB-REF-521 with the world ids and mutates nothing (state digest unchanged).
- [ ] E-2: for a world truncated at step k, `obs` in explicit mode equals `final_obs` in masked-autoreset mode bit for bit, and differs from the post-reset `obs`.
- [ ] E-3: a fixture with a mission deadline and a collection limit at the same step sets both flags, and the bootstrap target computed from the flags is 0.
- [ ] E-4: a planted `Faulted` world sets `invalid`, has weight zero, and appears in the failure count; a fall sets `terminated` only.
- [ ] E-5: a NaN in one action component returns FROB-REF-522 naming world and channel; the state digest is unchanged.
- [ ] Rate term: totals equal at 50 Hz and 100 Hz within 10⁻⁶ relative; per-step penalty totals 500 and 1,000.
- [ ] `env_steps` and `world_steps` in the receipt differ by exactly the decimation.
- [ ] Cancellation at a commit boundary leaves the environment restorable; no partial step is visible.
- [ ] Negative controls caught: a single-`done` implementation gives 0 for both bootstrap cases; a mode that returns only post-reset observations fails the truncation fixture; an action check performed after integration changes the digest before refusing.

### End-to-end script and logging
This bead registers its fixtures as the conformance battery `cortex-env` and records the gate through it (`frob eval run --battery cortex-env --json`, one row per fixture with expected, measured, tolerance and pass; the gate row is written only when every fixture passes and every registered control is caught). `scripts/e2e/cortex_env.sh` (bead N23a-34) then re-measures the same contract end to end from the user's side through `frob sim run`, `frob eval run` and `frob sense causal-test` on `batch-cpu`, in both reset modes, and appends its confirming receipt to the gate row. Each fixture logs `cmd`, `assert` and `metric` lines with expected and measured values, the envelope's evidence block and, on failure, the first differing value and the snapshot path.
### Known answers and negative controls
KA-576, KA-577, KA-578; CX-246, CX-247; the three planted defects above are registered in the negative-control registry against GATE-CORTEX-06. Metamorphic relations: splitting each control interval's physics into twice as many substeps leaves rate-term totals unchanged within tolerance; permuting worlds permutes views and nothing else. ## Considerations
- A fully observed finite-horizon task must give the actor the time remaining, or declare the clock hidden; the environment exposes time remaining as a channel when the task declares it (the learner-side rule is P-8 of the PPO battery).
- Rule E-10 (rewards, flags and `info` fields as access-classed, delivered values) extends this contract and is built by N23b-31; `InfoView` fields are therefore typed, not a free-form map.
- Performance: the full environment step without policy is a parity row (at least 0.75 of the physics-only rate as measured); views must not force host copies; the observation and reward stages are the last stage of the batched step.
- Risk: a learner written against another library's autoreset convention silently misreads `obs`; the mode label in every result and the adapter's explicit mapping are the mitigation.
