## Background
The main source of GPU-simulator training throughput is that observations never leave the device during a rollout: the simulator writes them into device buffers, the policy kernels read them there, and rollout storage (observations, sampled and applied actions, log-probabilities, values, rewards, flags, final observations) stays resident for the whole collection. A `TensorView` is the typed, strided view into a device buffer that rollout and learning kernels share. It carries the device, the allocation id, the dtype, the extents, a logical origin and signed strides in elements, an ownership epoch and the intended access.

Two hazards make this more than a struct.

*Strides.* FACT (read in the pinned sibling sources and re-run at admission by bead BD-036): the suite's NumPy-like library uses **signed byte strides** and its Torch-like library uses **unsigned element strides**. A contiguous 2 × 2 `f32` view has strides (8, 4) in the first and (2, 1) in the second. Copying the numbers verbatim into a view on a 16-element buffer reads element 8 + 4 = 12 at index [1, 1] where element 3 belongs, and both reads are in bounds, so nothing faults (counterexample CX-255). A view with byte origin 4 and strides (8, −4) indexes elements (1, 0, 3, 2) and has no unsigned form at all. The rule is therefore *one stride convention inside, converted at one boundary*: no bare stride tuple crosses between libraries.

*Stale reads.* A host read of a device buffer is valid only after the command buffer that wrote it has completed. Reading early returns the previous step's bytes with no error.

Tier Solid; crate `frob-learn::view`. The typed converter between the two sibling conventions was admitted at M0 (BD-036, interchange boundary tests INT-FNP-01 and INT-FNP-02); this bead builds the view type on top of it, on real devices, with epochs. Rejected alternatives: adopting either sibling's convention internally (each cannot express something the other can, and the failure is silent); always materializing at the boundary (a copy per step defeats device residency; copies are allowed but charged and visible).

## Scope
In: `TensorView`, `MaskView`; the internal convention; the learner's adapter to BD-036's converter for the signed-byte and unsigned-element conventions (the conversion arithmetic itself is BD-036's); the unrepresentable-view policy and FROB-REF-547; ownership epochs and host-read leases on CUDA, Metal and `batch-cpu`; proof obligation PO-CORTEX-05; the measurement of GATE-CORTEX-09. ## Technical approach
**Type (DESIGN).**
```rust
pub struct TensorView<'a> {
    device: DeviceId, alloc: AllocId,           // which device buffer
    dtype: Dtype, extents: SmallVec<[u32; 4]>,
    origin: i64,                                // logical origin, in elements from the allocation start
    strides: SmallVec<[i64; 4]>,                // signed, in elements
    epoch: u64, access: Access,                 // Device | HostRead | HostWrite
    _borrow: PhantomData<&'a ()>,
}
```
Element address of index i: `origin + Σ_k i_k·strides_k`. Constructors check that every reachable address lies inside the allocation (min and max over the index box, using the sign of each stride).

**Conversion at the boundary (one module, `view::convert`).** The arithmetic of conversion is BD-036's typed converter in `frob-core` (`convert(src, target: Convention, contract) -> Result<Converted, Refusal>`, admitted at M0 under INT-FNP-02), reused unchanged; the kernel-boundary binding of N21a-05 calls the same function. DESIGN: one converter in the workspace, because a second implementation of the same rule would be the same artifact specified twice and could drift. `view::convert` is the learner's adapter around it: it maps a `TensorView` to and from the `frob-core` layout descriptor, calls the converter, and at the learner boundary turns its "unrepresentable under a zero-copy contract" outcome into FROB-REF-547 (below). The rules the converter implements, restated so this bead stands alone:
1. *To signed bytes* (the NumPy-like side): `byte_origin = origin·size_of(dtype)`, `byte_strides_k = strides_k·size_of(dtype)`. Always representable.
2. *From signed bytes*: each byte stride and the byte origin must be divisible by the element size, else refuse (a view that straddles elements).
3. *To unsigned elements* (the Torch-like side): representable only if every stride is ≥ 0; then `offset = origin`, `strides_k = strides_k as usize`.
4. *From unsigned elements*: always representable.
5. The adapter's type signatures take and return the typed descriptors `ByteStrided` and `ElemStridedUnsigned` (thin wrappers over `frob-core`'s layout type, which carries the stride unit and signedness); there is no function from a bare tuple (a compile-fail test holds this).
Proof obligation **PO-CORTEX-05**: conversion between stride conventions round-trips or refuses. Verification: exhaustive over two- and three-dimensional views with element strides in −2 to 2 (per axis), extents 1 to 3 and all origins that keep the view in bounds of a 32-element buffer; for each, either the round trip returns the same index-to-element map, or the conversion refuses.

**Unrepresentable views.** When the receiver cannot represent a view (negative stride into the unsigned convention; a non-element-aligned byte view): under the default contract the view is *materialized* into a contiguous buffer on the same device and the copy is charged to the step receipt (`copies: [{reason, bytes}]`); under a declared zero-copy contract (the field `zero_copy` of the environment's construction request, default `false`; `train.start` passes it through as the input `zero_copy`, `--zero-copy`, which the `train.start` row of VERBS-train lists with this code; N23a-14 wires it) it is refused with FROB-REF-547 (meaning: a tensor view the receiver cannot represent, under a zero-copy contract; envelope `pointer` = the view's extents, origin and strides, and the receiver's convention; ranked repairs: 1. allow one charged copy, 2. change the layout; exit code 3; retry `after-change`; the row is N23-REF's). The device layer and the M0 converter raise FROB-REF-617 (exit 6) for the same rule at the kernel boundary (N21a-05, BD-036); one event has one code, divided by raising site: `frob-learn` and the adapter raise 547, the device layer 617.

**Epochs and leases.** Every device buffer has a committed epoch that advances when the command buffer writing it completes (a completion receipt from the device, not an enqueue). A view records the epoch it was created for. A host read requires a `HostRead` lease, which exists only on the current committed slab, the snapshot slab and the previous slot of a double-buffered ring. `read_host(view)` compares the view's epoch with the buffer's committed epoch; a mismatch (the write for that epoch has not completed, or the buffer has moved on) is refused as a stale-epoch read (the device layer's lease-violation refusal, FROB-REF-614, surfaced unchanged). On Metal the lease is the borrow that the gateway already enforces; on CUDA it is a runtime epoch check around stream-ordered copies; on `batch-cpu` it is the same check against the tile program's commit counter, so the CPU path tests the same logic.

**Masks.** `MaskView` is a `TensorView` of `u32` with one bit or one word per world (layout declared); kernels use select-only masking so that control flow does not depend on data.

**Determinism and evidence.** Conversion is exact (class D0). Views do not change values. The receipt records every charged copy and every lease.

## Acceptance criteria
- [ ] GATE-CORTEX-09 (Known answer, M2, TARGET) is measured and recorded: the stride fixture reads element 3; the negative-stride view is materialized or refused; a stale-epoch read is refused (the seed bead's done-condition).
- [ ] The 2 × 2 `f32` fixture: byte strides (8, 4) convert to element strides (2, 1); index [1, 1] reads element 3 on `batch-cpu`, CUDA and Metal.
- [ ] The view with byte origin 4 and byte strides (8, −4) enumerates elements (1, 0, 3, 2); converting it to the unsigned-element convention materializes a 4-element contiguous copy with a charged-copy entry in the receipt under the default contract, and returns FROB-REF-547 under `zero_copy: true`.
- [ ] PO-CORTEX-05 holds exhaustively over the stated space (counts of round-trips and refusals are recorded; zero wrong maps).
- [ ] A host read of a view whose epoch is ahead of the committed epoch is refused; the same read after the completion receipt succeeds and returns the new bytes; a read through a view of an older epoch after the buffer advanced is refused.
- [ ] No public function accepts a bare stride tuple (compile-fail test).
- [ ] Negative controls caught: the verbatim copy (reads element 12; the fixture fails); a converter that drops the sign (maps (1, 0, 3, 2) to another order); an epoch check that compares against the enqueued rather than the completed epoch (the stale-read fixture passes a read of old bytes).

## Considerations
- The two sibling conventions are FACTs about pinned revisions; an upstream work item (FD-FNP-01) proposes a named conversion in the siblings. Interim posture: the typed converter here; switch-over rule: replace the local converter with the upstream one and re-run the interchange test that reads element 3.
- Diagnostics must never wait on the step: they read double-buffered ring slots at epoch e − 1 while the device writes e (built in N23a-06).
- A charged copy is allowed but is a performance signal; `train.status` reports copies per collection so that a silent regression to per-step copies is visible.
- Memory safety: views borrow from the environment (`'a`), so a view cannot outlive the buffer set; device handles are not exposed.
