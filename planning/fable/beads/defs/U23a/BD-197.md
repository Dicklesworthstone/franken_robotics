## Background
Decision **ADR-CORTEX-03**: PPO is specified by rules with tests, and no PPO implementation, ours or a sibling's, is admitted without passing them. Reason: the suite's only existing PPO (the sibling simulator's humanoid training crate) has three errors in its update and a wrong joint law in its action sampler, none of which plumbing tests found. That crate hand-rolls PPO with manual backpropagation; its exported checkpoint has an all-zero policy head, and its own tracker entry says it proves model, training and export plumbing, not learned locomotion (FACT, read in the sibling source at commit `483d09c682f2`). It is not linked here, is not an oracle and is not a baseline; an upstream work item (FD-FSIM-10) asks for its correction, after which it may serve as a comparison baseline only once it passes this same battery.

The eleven rules, each with its test. Together they are the admission battery of gate GATE-CORTEX-07 for any PPO implementation.

| Rule | Statement | Test |
|---|---|---|
| P-1 Two masks | The value bootstrap is cut by termination only; the advantage trace is cut at every reset. | The 0 and 9.9 fixture; both flags set gives 0 |
| P-2 Frozen behaviour | Policy weights and the observation normalizer do not change during collection. | An update attempted mid-collection is refused; two collections from one snapshot are identical |
| P-3 Same random variable | The likelihood ratio is computed for the random variable that was sampled: either the sampled latent command is stored with its density and a deterministic limiter follows (`latent-then-limit`), or the policy is defined on the applied clipped action and has point masses at the bounds (`clipped-with-endpoint-mass`). | Unit-variance Gaussians clipped at +1 with means 0 and 1: the endpoint ratio is 0.5/0.158655 = 3.15149; ordinary densities at +1 give e^0.5 = 1.64872. Each law returns its own number; a mixture is refused (FROB-REF-527) |
| P-4 Clipped surrogate, both signs | With L = min(ρ·A, clip(ρ, 1 − ε, 1 + ε)·A), the unclipped branch is active for A ≥ 0 when ρ ≤ 1 + ε, and for A < 0 when ρ ≥ 1 − ε. | Finite differences of the loss at ρ = 0.5, 1 and 2 with ε = 0.2, for both signs of A and at both clip boundaries |
| P-5 Critic gradient from the current output | The value loss differentiates the current forward value, not the value stored at collection. | Critic output 2 with stored value and return 0: the gradient of c_V·(V − R)² into the value head is 4·c_V, not 0 |
| P-6 Episode boundaries in sequences | A sequence model evaluates each transition under its own episode history. Packed episodes do not see across a reset, and a minibatch that starts mid-episode carries the right position and prior history. | Two independently reset one-step episodes packed together: a frozen policy's ratio is 1 on both |
| P-7 Physical discount | γ and λ come from β, κ and the interval's simulated duration. | The 2.000 and 1.995 fixture across control rates |
| P-8 Time in the input | A finite-horizon task gives the actor the time remaining or declares the clock hidden. | With the clock, the value at the deadline equals the terminal reward; without it the result is labeled |
| P-9 Valid samples only | Invalid worlds and padded elements have weight zero in every loss and statistic, and the advantage trace of the valid samples before an invalid one ends there, bootstrapping from the last valid value as at a truncation. | A planted `Faulted` world changes no gradient and appears in the failure count |
| P-10 Global, versioned, invertible normalization | Advantage and value normalization use statistics over all valid samples of the update; the normalizer is stored with the checkpoint. | The normalizer round-trips; the shard fixtures (gradient 0.25; mean 4/3 and variance 32/9) |
| P-11 Entropy follows the action law | Entropy and multi-dimensional saturation use the registered law of P-3. | The entropy of the clipped law at a bound matches a quadrature reference and differs from the Gaussian's |

The sibling's PPO violates P-4, P-5 and P-6 (the three planted defects below reproduce them), drives its advantage recursion with a single `done` flag, which P-1 forbids, and its action sampler has correct marginals and a wrong joint law, which a twelfth rule (P-12: the sampler N23b-29 and its battery N23b-30) forbids.

Tier Solid. The mechanisms are built in subtask beads (bootstrap and discount N23a-07; action laws N23a-08; the update N23a-10; sequences N23a-11; storage and masks N23a-06). This bead assembles them into the trainer and builds the battery as a reusable admission harness.

## Scope
In: the assembled PPO trainer (`Ppo` in `frob-learn::ppo`) behind one interface; the battery as an implementation-agnostic harness in `frob-conformance` (it tests any implementation of a small `PpoUnderTest` trait); the three planted-defect variants and the single-`done` variant; registration of controls; the measurement and record of GATE-CORTEX-07. Out: the training verbs (N23a-14); the reference training run and its behavioural gate (BD-198); the multi-device reducer itself (N23a-19, a dependency; its P-10 shard fixtures are run here on shards simulated on `batch-cpu`, and the two-card measurement belongs to the sharding bead BD-199); the decision on the default action law (N23b-25, a dependency); rule P-12: the action sampler and its manifest, which this trainer's likelihood reads, are N23b-29 (a dependency), and the joint-law battery that adds P-12 to this battery and measures GATE-CORTEX-18 is N23b-30.

## Technical approach
**The trait the battery drives (DESIGN).**
```rust
pub trait PpoUnderTest {
    fn advantages(&self, traj: &FixtureTrajectory, cfg: &DiscountCfg) -> Advantages;          // P-1, P-7, P-9
    fn log_prob(&self, law: ActionLawKind, params: &GaussParams, stored: &Stored) -> Result<f64, Refusal>;  // P-3
    fn entropy(&self, law: ActionLawKind, params: &GaussParams, bounds: &Bounds) -> f64;      // P-11
    fn loss_and_grads(&self, batch: &FixtureBatch, cfg: &PpoCfg) -> LossGrads;                // P-4, P-5
    fn sequence_log_probs(&self, policy: &FrozenSeqPolicy, pack: &PackedEpisodes) -> Vec<f64>; // P-6
    fn collect_twice(&mut self, snap: &Snapshot) -> (Digest, Digest);                          // P-2
    fn try_update_mid_collection(&mut self) -> Result<(), Refusal>;                            // P-2
    fn normalizer_roundtrip(&self, x: &[f32]) -> Vec<f32>;                                     // P-10
    fn reduce_shards(&self, shards: &[ShardSums]) -> Reduced;                                  // P-10
    fn value_at_deadline(&mut self, task: &ClockFixture) -> ClockReport;                       // P-8
}
```
`frob-learn`'s trainer implements it; a thin adapter could implement it for a sibling's code to run the same battery against it (that adapter belongs to the M0 admission probes; the battery itself is shared).

**Battery layout.** `crates/frob-conformance/src/batteries/cortex_ppo/`: one module per rule, each exporting `run(&mut dyn PpoUnderTest) -> RuleReport { rule, fixtures: Vec<FixtureResult { name, expected, measured, tolerance, pass }> }`. Fixture values (all stated here so the battery needs no other source):
- P-1: an 8 s mission deadline with terminal reward 0 → bootstrap target 0; an external cut at the same instant on a continuing task with V = 10, γ = 0.99 → 9.9; both flags → 0; plus the eight-combination three-step hand table of the bootstrap bead.
- P-2: two digests equal; update mid-collection refused.
- P-3: 3.15149 and 1.64872 to the printed digits; mixture → FROB-REF-527.
- P-4: for ε = 0.2 and a sample with squared standardized residual 3/2, derivative of the surrogate in log σ at ρ = 0.5, 1, 2: for A = −1: 0, −0.5, −1; for A = +1: +0.25, +0.5, 0 (unclipped at ρ = 0.5 and 1; clipped at ρ = 2); at ρ = 0.8 and 1.2 by one-sided differences; tolerance 10⁻³ relative against finite differences of the scalar loss in single precision.
- P-5: 4·c_V exactly (2 at c_V = ½).
- P-6: ratios 1 and 1, to 10⁻⁶ (exactly 1 in class D2 for our implementation).
- P-7: γ = 0.99000 at 20 ms and 0.99499 at 10 ms with β = 0.5025 /s; constant-rate value 2.000·r and 1.995·r.
- P-8: value at the deadline equals the terminal reward within 2%; hidden clock → label present.
- P-9: gradient digest unchanged by a planted `Faulted` world; failure count 1.
- P-10: normalizer round trip within 2 ulp; one sample with gradient 1 and three with 0 → 0.25 on one shard and on shards of sizes 1 and 3; shards {0, 0} and {4} → mean 4/3, variance 32/9.
- P-11: clipped-law entropy at a bound equals the quadrature reference within 10⁻⁶ and differs from ½·log(2π·e).

**Planted defects (negative controls; test-only variants selected by a cargo feature of `frob-conformance`, never present in a release build).**
1. `defect-reversed-branch`: for A < 0, follow the ratio below 1 − ε and clip above 1 + ε. Expected battery outcome: P-4 fails with measured −0.25, −0.5, 0.
2. `defect-stored-value-critic`: form the value gradient from the stored value. Expected: P-5 fails with measured 0.
3. `defect-packed-sequence`: evaluate concatenated episodes as one sequence. Expected: P-6 fails with a second ratio different from 1 (1.582459 on the admission probe's weights).
4. (Additional, for P-1) `defect-single-done`: one flag for both cuts. Expected: the 0-and-9.9 fixture returns 0 for both and fails.
Each is registered in `frob-conformance/registry/controls.toml` with `kind = "mutation"`, the gate, the target function, the defect text and the expected failure, seeded from counterexamples CX-250, CX-251, CX-252 and CX-246. A gate run in which a control is not caught is a failure of the gate.

**Running it.** `cargo test -p frob-conformance --test cortex_ppo` (unit level) and, from the user's side, the battery registered under the name `cortex-ppo` and run with `frob eval run --battery cortex-ppo [--rules P-1,…] --json`, which returns one result row per fixture and the list of controls with `caught: true|false`.

**The gate record.** GATE-CORTEX-07 (Known answer; first milestone M2; TARGET): the PPO battery P-1 to P-11 passes for our implementation, and three planted defects that reproduce the sibling's errors each fail it. The record carries measured values for every fixture, the default action law in force (decision bead N23b-25), the control results, commit, hardware fingerprint and seed, and is written by a session that did not implement the trainer.

**Determinism and evidence.** The fixtures are deterministic; exact ones are compared exactly, the others to the stated tolerance. Evidence class `Tested`; tier host for the arithmetic fixtures and lockstep (`batch-cpu` batched tier) for P-2, P-8, P-9.

## Acceptance criteria
- [ ] GATE-CORTEX-07 is recorded as passed with measured values: all eleven rules pass for the `frob-learn` trainer on `batch-cpu`, and the arithmetic rules (P-1, P-3, P-4, P-5, P-7, P-10, P-11) also pass with the device kernels on CUDA and Metal (the seed bead's done-condition, first half).
- [ ] Each of the three planted defects fails the battery at its rule with the stated measured values, and the single-`done` variant fails P-1 (the seed bead's done-condition, second half).
- [ ] The battery runs against any `PpoUnderTest`; a second, deliberately minimal reference implementation in the test tree (double precision, scalar loops) also passes, showing that the fixtures are not tailored to one code path.
- [ ] All four controls are in the negative-control registry with `caught = true` from this run; a gate run with a control missing or uncaught cannot record a pass.
- [ ] `frob eval run --battery cortex-ppo --json` returns one row per fixture with expected, measured, tolerance and pass, and exits 0 only if all pass.
- [ ] The three sibling probes of the M0 admission bead and this battery's P-4, P-5 and P-6 fixtures use the same fixture data (one source file), so the two cannot drift.

## Test plan
### Unit tests
One test per rule against the real trainer: `battery_p1_two_masks`, `battery_p2_frozen_behaviour`, `battery_p3_same_random_variable`, `battery_p4_clipped_surrogate_both_signs`, `battery_p5_critic_gradient_current_output`, `battery_p6_episode_boundaries`, `battery_p7_physical_discount`, `battery_p8_time_in_input`, `battery_p9_valid_samples_only`, `battery_p10_global_normalization`, `battery_p11_entropy_follows_law`; one per control: `control_reversed_branch_fails_p4` (asserts measured −0.25, −0.5, 0), `control_stored_value_fails_p5` (asserts 0), `control_packed_sequence_fails_p6`, `control_single_done_fails_p1`; `battery_passes_minimal_reference`; `fixtures_shared_with_admission_probes` (file digest equality).
### End-to-end script and logging
`scripts/e2e/cortex_train.sh` (bead N23a-35), step `ppo-battery`: runs `frob eval run --battery cortex-ppo --json` on each available backend, then the four control builds (`--features defect-…` through the conformance runner), and appends a confirming receipt to the GATE-CORTEX-07 row that this bead first records through the same battery. NDJSON: one `assert` per fixture (rule, expected, measured, tolerance), one `assert` per control (`caught`), the envelope's evidence block, the default action law, seed, commit, fingerprint; on failure the rule, the fixture inputs and the first differing value; the `summary` names the gate and counts.
### Known answers and negative controls
KA-576 (bootstrap 0 and 9.9), KA-579 (2.000·r and 1.995·r), KA-582 (3.15149 and 1.64872), KA-583 (0, −0.5, −1 against −0.25, −0.5, 0), KA-584 (4·c_V against 0), KA-585 (1 and 1 against 1.582459), KA-586 (P-2, P-8, P-9, P-10, P-11), KA-587 and KA-588 (0.25; 4/3 and 32/9); counterexamples CX-246, CX-248 to CX-252, CX-357 (a sibling's training code can serve as an oracle or a baseline). Determinism lanes: the battery twice on one machine; across worker counts; debug and release; each backend against its class.

## Considerations
- Risk: a fixture transcribed with the same misunderstanding as the code. Mitigations: finite differences of the scalar loss as an independent check for P-4; the minimal reference implementation; hand tables for P-1; the quadrature reference for P-11.
- The battery is an *admission* battery: any future PPO variant (a clipped value loss option, a different advantage estimator) is admitted only by passing it, with a new fixture where it changes a rule.
- The risk register carries this as a high risk (a reported foundation defect relied on before it is rechecked); the mitigation is exactly that our own PPO passes the same three probes first.
- Performance is not measured here; the battery is small and runs in seconds on the host.
