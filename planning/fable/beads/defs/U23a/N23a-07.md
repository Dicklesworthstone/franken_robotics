## Background
On-policy actor-critic training estimates, for each stored transition, an advantage: how much better the action was than the critic expected. The estimate bootstraps from the critic's value of the next observation, and it accumulates along the episode. Two things routinely go wrong, and both are invisible to a test that only checks that training runs.

**One `done` flag.** If an episode ends because the task is really over (success, failure, an intrinsic mission deadline), the value after the end is zero and must not be bootstrapped. If it ends because the collector stopped it (an external time limit on a task that would have continued), the value after the end is whatever the critic says about the final observation, and it must be bootstrapped. A single flag forces one treatment on both. Known answer: a true 8 s deadline with terminal reward 0 gives a bootstrap target of 0; an external cut at the same instant on a continuing task with V = 10 and γ = 0.99 gives 9.9. The suite's only existing PPO drives its advantage recursion with a single `done` flag (FACT, read in the sibling source), which is why this is a rule with a test and not a convention.

**A per-step discount.** A discount factor per step means something different at every control rate. With γ = 0.99 per step, a constant reward rate r is worth 2.0·r at a 20 ms interval and 1.0·r at 10 ms: the same behaviour, valued at half, because the controller ran faster (counterexample CX-248). Designs, tasks and evaluation rungs in this system differ in control interval, so a per-step discount would make returns incomparable across them.

The rules: **P-1 Two masks**: the value bootstrap is cut by termination only; the advantage trace is cut at every reset. **P-7 Physical discount**: γ and λ come from rates β and κ in 1/s declared by the task and from the interval's simulated duration. Proof obligation **PO-CORTEX-01**: the value bootstrap is cut by termination only and the trace by any reset; verified on all eight flag combinations on a three-step fixture against a hand table.

Tier Solid; crate `frob-learn::rollout::gae`. Rejected alternatives: time-limit handling by adding V to the reward at truncation (equivalent when done correctly, but hides the distinction and breaks with value normalization); a per-task tuned per-step γ (does not survive a change of control rate between rungs).

## Scope
In: the advantage and return kernels over rollout storage, on `batch-cpu` and as device kernels; the two masks; γ(Δt) and λ(Δt); treatment of invalid samples in the trace; the hand-table fixture; defaults for β and κ. Out: normalization of advantages and returns (N23a-10; multi-device merge N23a-19); the reward integration that produces rate-term totals (BD-192, BD-194); time remaining in the observation (N23a-11).

## Technical approach
**Formulas.** For a transition at step t of a world, with reward rₜ (already integrated over the interval), next observation o′ₜ (the *final observation* if the world ended at t, taken from the `final_obs` row of rollout storage), value function V, simulated interval duration Δtₜ, and flags from the environment:

    γₜ = exp(−β·Δtₜ)          λₜ = exp(−κ·Δtₜ)
    δₜ = rₜ + γₜ·(1 − terminatedₜ)·V(o′ₜ) − V(oₜ)
    Aₜ = δₜ + γₜ·λₜ·(1 − needs_resetₜ)·Aₜ₊₁
    Rₜ = Aₜ + V(oₜ)            (the value target)

where `needs_reset = terminated ∨ truncated ∨ invalid`. If both `terminated` and `truncated` are set, termination controls the bootstrap. At the last stored step T − 1 of a collection whose world did not end, the trace stops (A_T = 0) and the bootstrap uses V(o_T), the value of the observation after the last step.

**Invalid samples (rule P-9, trace part).** An invalid transition has weight zero and takes no part. The advantage trace of the valid samples before it ends there: for the last valid transition before an invalid one the recursion uses A = 0 beyond it and bootstraps from the last valid value, exactly as at a truncation.

**Physical discount, numbers.** With β = 0.5025 /s: γ = exp(−0.01005) = 0.99000 at Δt = 20 ms and exp(−0.005025) = 0.99499 at 10 ms. A constant reward rate r (so each interval's reward is r·Δt) is worth r·Δt/(1 − e^(−β·Δt)): 2.000·r at 20 ms and 1.995·r at 10 ms, both near the continuous-time value r/β = 1.990·r. With one per-step γ = 0.99 at both rates the same behaviour is worth 2.0·r and 1.0·r. With κ = 2.565 /s, λ = exp(−0.0513) = 0.95 at 20 ms. Defaults per task family are an open question (OPEN-CORTEX-5; owner: the lead of the task-and-evaluation subsystem; blocks nothing); the fail-closed default is β = 0.5025 /s and κ = 2.565 /s, and a result produced with defaults says so.

**Algorithm (one backward sweep per world, vectorized over worlds).**
1. Evaluate V on `obs_critic[0..=T]` and on `final_obs_critic[t]` for ended worlds (one batched critic forward; no gradient).
2. For t = T − 1 down to 0: compute γₜ, λₜ from `dt_sim[t]`; select `v_next = value_final[t]` if `needs_reset[t]` else `value[t+1]`; compute δₜ with the termination mask; compute Aₜ with the reset mask; carry `A_next = 0` across any step whose weight is zero and across the step before it.
3. Write `adv[T]`, `ret[T]`.
The kernel is select-only (no data-dependent branching), so it obeys the lockstep rule of the batched tiers. `exp` is the backend's deterministic elementary function; γ and λ per sample are stored so that the update never recomputes them differently.

**Hand table for PO-CORTEX-01 (DESIGN; derived from the formulas above and re-derived by the implementer before use).** Three steps, r = (1, 1, 1), V(o₀) = V(o₁) = V(o₂) = 10, V of every next or final observation = 10, constant Δt with γ = 0.99, λ = 0.95 (γ·λ = 0.9405), no flags at steps 0 and 2, and the eight combinations of (terminated, truncated, invalid) at step 1. Unflagged δ = 1 + 9.9 − 10 = 0.9.

| Flags at step 1 (term, trunc, invalid) | A₀ | A₁ | A₂ | weight₁ |
|---|---|---|---|---|
| 0, 0, 0 | 0.9 + 0.9405·1.74645 = 2.542536225 | 0.9 + 0.9405·0.9 = 1.74645 | 0.9 | 1 |
| 1, 0, 0 | 0.9 + 0.9405·(−9) = −7.5645 | 1 + 0 − 10 = −9 | 0.9 | 1 |
| 0, 1, 0 | 1.74645 | 0.9 (bootstrapped from the final observation, trace cut) | 0.9 | 1 |
| 1, 1, 0 | −7.5645 (termination controls) | −9 | 0.9 | 1 |
| 0, 0, 1 and the three other rows with invalid = 1 | 0.9 (trace ends at step 0, bootstrapped from the last valid value) | excluded | 0.9 | 0 |

**Determinism and evidence.** Class D2 per backend; D1 across backends where the deterministic `exp` is bit-equal. Receipts record β, κ, whether they were defaults, and the count of bootstraps from final observations.

## Acceptance criteria
- [ ] The bootstrap fixture returns target 0 for the true deadline and 9.9 for the external cut (V = 10, γ = 0.99), and 0 when both flags are set.
- [ ] PO-CORTEX-01: all eight flag combinations of the three-step fixture match the hand table to 10⁻¹² in double precision on `batch-cpu` and to 10⁻⁵ relative in single precision on each device backend.
- [ ] The discount fixture: with β = 0.5025 /s a constant-rate reward over a long horizon is worth 2.000·r at 20 ms and 1.995·r at 10 ms (to the printed digits); γ is 0.99000 and 0.99499.
- [ ] A world whose control interval differs from its neighbours' in the same batch (20 ms and 10 ms mixed) gets its own γ and λ from `dt_sim`.
- [ ] The value of an ended world's next observation is read from the final-observation row in both reset modes; using the post-reset observation instead changes the truncation fixture (negative control).
- [ ] Negative controls caught: a single `done` flag (gives 0 for both bootstrap cases); a per-step γ = 0.99 (gives 2.0·r and 1.0·r); a trace that continues across an invalid sample.

## Considerations
- `exp` must be the deterministic elementary function of the backend, or D2 fails across driver versions; γ and λ are computed once and stored.
- Value normalization (N23a-10) operates on Rₜ; the bootstrap uses de-normalized values, and the fixture with value normalization on must give the same targets.
- If a task hides the clock on a finite-horizon mission, the value near the deadline is ambiguous; the result is labeled (rule P-8, N23a-11).
