## Background
Proximal policy optimization (PPO) with generalized advantage estimation, value normalization and an adaptive step size is the Solid-tier trainer of the program; every other algorithm is Frontier and must beat it in a pilot before it is built. Decision **ADR-CORTEX-03**: PPO is specified by rules with tests, and no PPO implementation, ours or a sibling's, is admitted without passing them. Reason: the suite's only existing PPO has three errors in its update and a wrong joint law in its action sampler, none of which plumbing tests found.

FACT (read in the sibling simulator's training crate at commit `483d09c682f2`, file `crates/fs-g1-train/src/ppo.rs`, update routine at lines 253–345; the numbers come from executable fixtures and are re-run at admission by bead BD-034). That update (1) reverses the clip-branch test for a negative advantage: it follows the ratio below 0.8 and clips it above 1.2; at ratios 0.5, 1 and 2, finite differences of the fixture loss in log σ give 0, −0.5 and −1, and the code gives −0.25, −0.5 and 0. (2) It forms the value gradient from the value stored at collection: for a critic output of 2 with stored value and return 0, the gradient into the shared critic bias is 0 where the squared-error objective gives 2 (4·c_V with c_V = ½). (3) It evaluates a concatenated trajectory as one sequence (handled in bead N23a-11). That code is not linked, is not an oracle and is not a baseline; an upstream work item (FD-FSIM-10) asks for its correction. A defect this easy to write is easy to write twice, so the same probes are the first tests of this update.

This bead builds the update itself. Rules it must satisfy:
- **P-2 Frozen behaviour.** Policy weights and the observation normalizer do not change during collection (invariant INV-CORTEX-02). Test: an update attempted mid-collection is refused; two collections from one snapshot are identical.
- **P-4 Clipped surrogate, both signs.** With L = min(ρ·A, clip(ρ, 1 − ε, 1 + ε)·A), the unclipped branch is active for A ≥ 0 when ρ ≤ 1 + ε, and for A < 0 when ρ ≥ 1 − ε.
- **P-5 Critic gradient from the current output.** The value loss differentiates the current forward value, not the value stored at collection.
- **P-9 Valid samples only.** Invalid worlds and padded elements have weight zero in every loss and statistic.
- **P-10 Global, versioned, invertible normalization.** Advantage and value normalization use statistics over all valid samples of the update; the normalizer is stored with the checkpoint.

Rejected alternatives: linking or adapting the sibling's PPO (three confirmed defects; it depends only on a math library and hand-rolls backpropagation, and its own tracker entry says it proves plumbing, not learned locomotion); the "clipped value loss" variant that mixes the stored value into the value objective as the default (it is exactly where defect 2 hides; it may be added later as an option only with its own finite-difference fixture).

## Scope
In: the loss, its analytic gradients, minibatch construction, epochs, the optimizer step, the adaptive step size, value normalization, advantage normalization on one device, the collection/update state machine that enforces frozen behaviour, weights of invalid and padded samples, and the unit fixtures for P-2, P-4, P-5, P-9, P-10; the same loss written on FrankenTorch's tape as the pluggable loss of N23a-15's `CpuLearner` (from the same formulas: the surrogate selected by the comparison of its two terms, the value loss on the current output, masked sums divided by the valid count), which is the CPU reference of the acceptance criteria and the loss of the CPU trainer that N23a-14 exposes as `--trainer frankentorch`. Out: bootstrap targets (N23a-07); action laws (N23a-08); sequence policies (N23a-11); the shard reduction across devices (N23a-19); the kernels for matrix products, activations and Adam (BD-196); the battery as an admission harness with planted defects (BD-197).

## Technical approach
**Objective.** For valid samples i with weight wᵢ ∈ {0, 1}, ratio ρᵢ = exp(log π_θ(storedᵢ) − logp_oldᵢ) under the registered action law, normalized advantage Âᵢ, value output V_θ(oᵢ) from the *current* forward pass and target Rᵢ:

    L_π = −(1/n)·Σ wᵢ·min(ρᵢ·Âᵢ, clip(ρᵢ, 1 − ε, 1 + ε)·Âᵢ)
    L_V = c_V·(1/n)·Σ wᵢ·(V_θ(oᵢ) − Rᵢ)²
    L_H = −c_H·(1/n)·Σ wᵢ·H_θ(oᵢ)                     (entropy under the registered law)
    L = L_π + L_V + L_H,      n = Σ wᵢ      (if n = 0 the minibatch is skipped)

**Branch rule for the surrogate gradient (P-4).** ∂/∂ρ of min(ρ·A, clip(ρ)·A) is A when the unclipped term is the minimum, that is when ρ·A ≤ clip(ρ)·A, and 0 otherwise. Written out: for A ≥ 0 the unclipped branch is active when ρ ≤ 1 + ε; for A < 0 it is active when ρ ≥ 1 − ε. The implementation computes both terms and selects by the comparison `ρ·A ≤ clip(ρ)·A` itself, never by a hand-written case on the sign of A, so the rule cannot be reversed for one sign. Hand case: A = −1, ε = 0.2. At ρ = 0.5 the terms are −0.5 and −0.8: the clipped term is the minimum and the gradient is zero. At ρ = 2 they are −2 and −1.2: the unclipped term is the minimum and the gradient flows. At the boundaries ρ = 0.8 and ρ = 1.2 the two terms are equal and the subgradient convention is "unclipped" (≤), fixed and tested.

**The fixture in log σ (DESIGN reconstruction; the admission probe of BD-034 is authoritative).** One sample, one action component, standardized residual z = (stored − μ)/σ with z² = 3/2, A = −1, ε = 0.2. Since ∂ρ/∂ log σ = ρ·(z² − 1) = ρ/2, the derivative of the surrogate min(·) with respect to log σ is A·ρ/2 where the unclipped branch is active and 0 otherwise: 0 at ρ = 0.5, −0.5 at ρ = 1, −1 at ρ = 2. The reversed branch gives −0.25, −0.5, 0.

**Critic gradient (P-5).** ∂L_V/∂V_θ(oᵢ) = 2·c_V·wᵢ·(V_θ(oᵢ) − Rᵢ)/n, with V_θ(oᵢ) the value just computed by the training forward pass. Fixture: output 2, stored value 0, return 0, one sample: gradient 4·c_V. The stored value appears nowhere in the gradient.

**Value normalization.** Returns are normalized by a running (μ_R, σ_R) kept as the triple (n, μ, S) and updated between collections only; the critic predicts normalized values; bootstrap targets are computed with de-normalized values. When the statistics change, the critic's last layer is rescaled so that its de-normalized outputs are unchanged (the standard invertible correction), which is a checked identity. The normalizer is versioned and stored with the checkpoint (P-10).

**Advantage normalization.** Â = (A − μ_A)/(σ_A + 10⁻⁸) with (μ_A, σ_A) over *all valid samples of the update*, computed once per update from the masked statistics triple, not per minibatch and never per shard (the multi-device merge is in N23a-19).

**Minibatches and epochs.** K epochs (default 5) over M minibatches (default 4) of the collection; indices are a permutation drawn by address from the run seed and the update index, so the order is reproducible and can be frozen for equivalence checks. Only valid samples are drawn; padding and invalid samples are never in a minibatch, and the per-minibatch n is the count of valid samples.

**Optimizer and adaptive step size.** Adam through the device kernel, gradient clipping by global norm (default 1.0). Adaptive step size (DESIGN, the common KL-targeted schedule): after each update, with the mean KL divergence between old and new policies over valid samples, multiply the learning rate by 1/1.5 if KL > 2·KL_target and by 1.5 if KL < KL_target/2, clamped to [10⁻⁵, 10⁻²]; KL_target default 0.01. The schedule's state is in the checkpoint.

**Frozen behaviour (P-2).** A state machine `Collecting → Updating → Publishing → Collecting`. During `Collecting` the behaviour weights and the observation normalizer are read-only device buffers under the current epoch; `update()` in that state is refused. Weights are published (swapped into the behaviour slot) only after a complete update. Two collections started from one environment snapshot with the same weights and seeds are bit-identical.

**Defaults (DESIGN).** ε = 0.2, c_V = 0.5 (so the P-5 fixture gradient is 2, the figure quoted for the sibling), c_H task-declared, K = 5, M = 4; every value is in the training receipt.

**Determinism and evidence.** With a fixed minibatch order and reduction order the update is class D2 per backend. Receipts: losses, KL, clip fraction, valid/invalid/padded counts, learning rate, normalizer versions.

## Acceptance criteria
- [ ] P-4: analytic gradients of the surrogate equal central finite differences (relative 10⁻³ in single precision, 10⁻⁸ in double) at ρ = 0.5, 1 and 2 with ε = 0.2 for both signs of A and at both clip boundaries (ρ = 0.8, 1.2, one-sided differences); for the negative-advantage fixture the values are 0, −0.5, −1.
- [ ] P-5: the gradient into the value head for output 2, stored value 0, return 0 is 4·c_V; replacing the forward value by the stored value in a test-only build gives 0 and fails the fixture.
- [ ] P-2: `update()` during collection is refused; two collections from one snapshot have identical storage digests; the normalizer version is unchanged across a collection.
- [ ] P-9: a planted `Faulted` world changes no gradient (bitwise) and appears in the failure count of the receipt.
- [ ] P-10: the value normalizer and observation normalizer round-trip (inverse∘forward = identity within 2 ulp); de-normalized critic outputs are unchanged by a statistics update within 10⁻⁵ relative; advantage statistics equal the masked statistics over all valid samples of the update.
- [ ] A minibatch with zero valid samples is skipped without a division by zero and is counted.
- [ ] The update on `batch-cpu` and on each device backend agrees with the FrankenTorch CPU reference implementation of the same loss within 10⁻⁵ relative on 100 random batches.
- [ ] Negative controls caught: the reversed branch for negative advantage; the stored-value critic gradient; per-minibatch advantage normalization (differs from the global statistics fixture).

## Considerations
- The comparison-based branch selection has a tie at the boundaries; the convention (unclipped on equality) is arbitrary but fixed, and the finite-difference test at a boundary uses one-sided differences.
- The KL-adaptive step can interact with the labeled nondeterministic profile (reduction order changes KL in the last bits); the schedule thresholds are compared with a relative guard so that D2 runs take identical branches.
- Performance: the learner is a parity item (about 13% of training wall-clock on one incumbent stack, FACT from the source register); the update's share on this system is reported per run.
- The first network trained against every baseline is a small observation MLP with explicit normalization; larger networks do not change this bead.
