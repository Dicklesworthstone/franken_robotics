## Background
A policy in this system is a small neural network evaluated on the device beside the simulator. The catalogue of network kinds is fixed by the specification, each with a tier:

- **MLP and GRU [Solid].** A small observation MLP with explicit normalization is the first network trained against every baseline.
- **Asymmetric actor-critic [Solid]**: the critic may read `critic-only` channels and the actor may not (rule E-8 of the environment contract).
- A residual head over a baseline controller [Frontier], with a zero-initialized output layer (bead N23a-20).
- An equivariant MLP under the observation-preserving symmetry group [Frontier], with augmentation and a symmetry loss as the Solid alternative (beads N23a-31, N23a-32).
- A morphology transformer with one token per link [Frontier] (the family policy: BD-320, with the network in N23b-41).
- A geometric-algebra tree policy [Moonshot] (the epic BD-439, after its pilot N23b-01).

This bead builds the two Solid kinds and the specification type that all kinds share. There is no dynamic autograd graph on the device: a network is a declarative `NetworkSpec`, and `frob-learn` compiles it into an ordered list of kernel stages (matrix products, activations) for the forward pass and the mirrored list for the backward pass. The same spec builds a FrankenTorch module on the CPU, which is the CPU trainer and the gradient oracle, so one description has two executions that are tested against each other.

Why small and explicit: policies of a few hundred units in single precision are enough for the reference tasks; the learner is a parity item, not the differentiator; and the security posture of the program allows only an allowlisted weight layout and family of architectures to be loaded (an open safety question, OPEN-SAFE-1, whose default is "the single layout and family of the reference policy"). Rejected alternatives: a general tensor-graph runtime on the device (a large surface with its own determinism questions, for networks that are three dense layers); sharing one trunk between actor and critic by default (couples the two losses and complicates the access-class separation; available as an option, off by default).

## Scope
In: `NetworkSpec` and its canonical encoding; MLP actor and critic; GRU actor (and optionally critic); the asymmetric composition; parameter initialization; the log-standard-deviation parameters of the Gaussian head; compilation to kernel stage lists and to a FrankenTorch module; parameter layout and its digest; the two cases `mlp-twin` and `gru-twin` of the battery `cortex-grad`. Out: the kernels (BD-196); the PPO losses (N23a-10) and sequence handling (N23a-11); the observation normalizer (N23a-02, applied before the first layer); checkpoints and manifests (N23a-13); Frontier and Moonshot network kinds.

## Technical approach
**Specification (DESIGN).**
```rust
pub struct NetworkSpec {
    pub kind: NetKind,                       // Mlp | Gru | (frontier kinds behind features)
    pub actor: TowerSpec, pub critic: TowerSpec,
    pub shared_trunk: bool,                  // default false
    pub action_head: HeadSpec,               // Gaussian: mean layer + state-independent log_std per channel
    pub recurrent: bool,
}
pub struct TowerSpec { pub input: SchemaDigest, pub widths: Vec<u32>, pub activation: Act, pub gru_hidden: Option<u32> }
pub struct HeadSpec { pub out_channels: Vec<ChannelId>, pub init_log_std: f32, pub min_log_std: f32, pub max_log_std: f32 }
```
The manifest form is `{"kind": "mlp", "widths": [256, 256, 128], "recurrent": false}`; the reference policy uses those widths with ELU activations (DESIGN default).

**MLP.** `obs → normalize → [dense → activation]×k → dense(mean)`; critic likewise ending in one scalar. Stage list: one `K-gemm` and one `K-act-fn` per hidden layer.

**GRU.** One GRU layer of width H between an input dense layer and the output head, composed from the same kernels: with input x and previous hidden h, r = σ(W_r·x + U_r·h + b_r); z = σ(W_z·x + U_z·h + b_z); n = tanh(W_n·x + r ⊙ (U_n·h + b_n)); h′ = (1 − z) ⊙ n + z ⊙ h. The gate layout and bias placement must follow FrankenTorch's GRU module exactly so that weights are interchangeable; the equations above show the form with a separate bias inside the candidate's recurrent term as the DESIGN default, and the module's actual form is read from the pinned source before coding (HYPOTHESIS until then, settled by the conformance test that loads the same weights into both and compares outputs). Before each step the reset mask selects the initial hidden state for worlds that ended (the select is inside the recurrent stage). The backward pass through time is the mirrored stage list unrolled over a chunk of at most L steps.

**Asymmetric actor-critic.** The actor tower's input is the frozen actor schema's tensor; the critic tower's input is the critic schema's tensor (actor channels plus `critic-only` channels). The two towers are bound to different device buffers; the build fails with FROB-REF-524 if the actor tower names a non-actor channel. With `shared_trunk = true` the trunk may read only actor channels and the critic adds a side input for its privileged channels.

**Initialization (DESIGN).** Orthogonal initialization with gain √2 for hidden layers, 0.01 for the action-mean layer and 1 for the value layer; biases zero; `log_std` initialized to `init_log_std` (default 0, clamped to [min, max] = [−5, 2] by a select). Orthogonal matrices are produced on the host in double precision from the addressed generator (QR of a Gaussian matrix with sign fix) so that initialization is identical on every backend; the seed address is (run seed, "init", layer index).

**Compilation.** `compile(&NetworkSpec, &ActorSchema, &CriticSchema, backend) -> CompiledNet { forward: Vec<Stage>, backward: Vec<Stage>, params: ParamLayout }`. `ParamLayout` assigns every tensor (weights, biases, log_std, optimizer moments) an offset in the arena's policy slab, in a canonical order (tower, layer, tensor name), and has a digest; that order is also the order of tensors in the safetensors file. `to_torch(&NetworkSpec, &params) -> ft_nn::Module` builds the CPU twin by lowering the spec to N23a-15's ordered layer list (`LayerDesc` entries in `ParamLayout` order) and calling the bridge's `module_from_layers`; the bridge knows no `NetworkSpec`.

**Inference modes.** Stochastic (sample through the registered action law) and deterministic (mean action), chosen per call; evaluation reports which was used.

**Determinism and evidence.** Forward and backward are class D2 per backend. The spec's digest and the parameter-layout digest are recorded in every checkpoint and run.

## Acceptance criteria
- [ ] For the MLP and the GRU, device forward outputs equal the FrankenTorch twin's within 10⁻⁵ relative on 10³ random inputs, and device gradients of a random scalar loss equal the twin's autograd within 10⁻⁵ relative (the same metric as the gradient-parity gate).
- [ ] The GRU fixture: weights exported from the device network and loaded into FrankenTorch's GRU reproduce a 20-step sequence within 10⁻⁵; a deliberately swapped gate order fails.
- [ ] The asymmetric composition binds different buffers to actor and critic, and an actor tower naming a `critic-only` channel is refused with FROB-REF-524.
- [ ] Initialization is bit-identical on `batch-cpu`, CUDA and Metal for a given seed; hidden layers are orthogonal within 10⁻⁵ (‖WᵀW − g²·I‖_max); the freshly initialized action-mean layer is not all zeros (‖W‖ > 0), and a zero-weight policy can be requested explicitly for the negative controls of the training gate.
- [ ] `log_std` stays inside its clamp under optimization steps that push beyond it.
- [ ] The parameter layout's digest changes with any change of widths, activation or channel list, and is stable across builds.
- [ ] Negative controls caught: a backward stage list out of order (fails parity); a shared trunk that reads a privileged channel (refused); a hidden state not reset for an ended world (fails the sequence fixture of N23a-11).

## Test plan
### Unit tests
`mlp_forward_matches_torch_twin`; `mlp_backward_matches_torch_autograd`; `gru_forward_matches_torch_twin_20_steps`; `gru_weight_interchange_roundtrip`; `gru_swapped_gates_detected`; `asymmetric_towers_bind_distinct_buffers`; `actor_tower_privileged_channel_refused_524`; `shared_trunk_privileged_read_refused_524` (with `shared_trunk = true`, a trunk input list naming a `critic-only` channel); `orthogonal_init_identical_across_backends`; `init_orthogonality_and_gains`; `log_std_clamp`; `param_layout_digest_sensitivity`; `deterministic_vs_stochastic_inference_labeled`; property test `compile_is_pure` (compiling the same spec twice gives identical stage lists and layouts).
### End-to-end script and logging
`scripts/e2e/cortex_train.sh` (bead N23a-35), step `networks`: `frob train start quad-ref --task quad-flat-velocity --network mlp:256,256,128 --dry-run --key nw-dry-mlp --json` (a dry run starts no job and takes no budget) and the same for `gru:128` (key `nw-dry-gru`), asserting the reported parameter counts (computed by hand in the script from the widths and the reference task's schema sizes) and the layout digests; then the parity entries with their controls, `FROB_TEST_SEED=$E2E_SEED cargo test -p frob-conformance --features gauntlet-mutations --test g2_parity -- GATE-CORTEX-02` (the Gauntlet has no `frob` command, and `eval.run` has no design-less battery form; the entries are BD-196's, in `crates/frob-conformance/src/batteries/cortex_grad.rs`, one per site `host`, `cuda` and `metal`, and a site whose backend is absent is `Skipped` in the receipt with the reason, never a pass), from whose hash-named receipt the script reads the two cases below. BD-196's battery compares dense layers and the optimizer and cannot know these networks (it lands first), so this bead registers two further cases in that module, `mlp-twin` and `gru-twin`, each an entry naming GATE-CORTEX-02 at every site: the device forward pass and the gradient of a random scalar loss for the reference MLP and the GRU over 20 steps, against the FrankenTorch twin built by `to_torch`, on 10³ random inputs; the gate filter runs every registered case, so no further filter is needed. NDJSON: `metric` lines with parameter counts (expected and measured), digests, worst forward and gradient error against 10⁻⁵, backend fingerprint and seed.
### Known answers and negative controls
Parameter counts are exact known answers (for an MLP with input n₀ and widths n₁…n_k and output m: Σ (n_{i−1} + 1)·n_i + (n_k + 1)·m + m for the log-std vector). Of the three negative controls, the backward stage list out of order is a parity control: it is registered against GATE-CORTEX-02 in `crates/frob-conformance/registry/controls.toml` beside BD-196's four, as a planted mutation behind the `gauntlet-mutations` umbrella, and the receipt must report it `caught`. The other two are not parity checks and are not registered there: a shared trunk that reads a privileged channel is a refusal (FROB-REF-524), asserted by the unit test `shared_trunk_privileged_read_refused_524`; a hidden state not reset for an ended world is the cross-reset defect that N23a-11's fixture catches and registers under GATE-CORTEX-07. Metamorphic relation: permuting hidden units of one layer together with the matching rows and columns of adjacent layers leaves outputs unchanged within round-off. Determinism lanes: twice; worker counts; per backend.

## Considerations
- The allowlist of loadable architectures at M2 is decided by OPEN-SAFE-1 (N37-08, which depends on this bead), whose fail-closed default admits from outside only the single layout and family of the reference policy: the non-recurrent MLP (`kind = "mlp"`, `recurrent = false`, at most 8 layers, width at most 4,096, `F32`, `admit = "external"`). The asymmetric pair is two MLP towers and fits that row. The default also has a `gru` row with `admit = "trained-here"`: checkpoints this system's trainer wrote (their digest matches a store record) reload through the admission door (N37-07), so a GRU run can resume and its policy can be exported and re-read; a GRU file from outside is refused on read (FROB-REF-828) until OPEN-SAFE-1 raises the row to `external`. (An earlier note that GRU policies at M2 live in memory only is withdrawn.) The row's layout function and bounds are this bead's `ParamLayout` and the trainer's bounds.
- The Frontier kinds reuse `NetworkSpec`, `ParamLayout` and the compile step; they add stage kinds (block-parameterized linear maps, attention) behind their features.
- A zero-initialized output layer is used only by the residual head; the ordinary policy's mean layer uses a small non-zero gain so that an exported freshly initialized policy does not look like the all-zero head that a plumbing-only training run would export.
