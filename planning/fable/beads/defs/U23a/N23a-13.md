## Background
A file of network weights is meaningless without knowing what each input and output is: which joint a given output drives, in which unit and with which sign, at what rate, under which action law, with which observation normalizer, trained on which task. Policies that are matched to robots by array position work until a design is edited, a joint order changes or a mirrored leg needs a sign flip, and then they fail silently: the robot moves, wrongly.

The rule of this system (invariant **INV-CORTEX-04**): a checkpoint is inseparable from its manifest and mapping table, and a policy reaches a design only through that table. Channel roles, dimensions, signs, units and rates are matched **by role, never by position or by name order**, and a mismatch is refused (FROB-REF-531). The manifest has schema `frob.policy/1`; it is stored in the safetensors metadata and in the content store. It is not a new file format: weights stay in safetensors, the interchange format shared with the suite's Torch-like library.

The mapping table is also what later mechanisms stand on: applying a family policy to a new design, inheriting a child's policy from its parent through a typed design edit, tying weights under a symmetry group, and distillation (a distilled policy's manifest lists its teachers). Getting it right once at M2 is cheaper than retrofitting it into each of those.

Tier Solid; crate `frob-learn::ckpt`; verb `train.export` (kind: read; first milestone M2; "export a policy with its manifest and mapping table"). Rejected alternatives: a bespoke policy file format (one more format to version and audit; safetensors with typed metadata suffices); matching by channel name (names are authoring conveniences and no mechanical product reads them; two designs can name the same role differently); storing the manifest beside the weights as a separate file (separable, hence losable).

## Scope
In: the manifest type and schema; building it at training time; writing and reading checkpoints (weights + manifest + digests) through the bridge's safetensors functions and the content store; the role matcher that binds a checkpoint to a design and task; FROB-REF-531; the verb `train.export`; mid-run checkpoints (with optimizer and normalizer state and recurrent hidden state) against exported policies (inference state only). Out: `train.start`, `train.status`, `train.stop` (N23a-14); the inheritance map between two designs (N23a-27); the family policy's extra fields (generator, split, support envelope, rank record: BD-320 and N23a-25); the sampler manifest whose digest joins the checkpoint's provenance (N23b-29); the no-authorization flags on exporting verbs in general (the safety chapter's bead; this verb must carry them).

## Technical approach
**Manifest (DESIGN sketch; schema `frob.policy/1`).**
```json
{
  "schema": "frob.policy/1",
  "network": { "kind": "mlp", "widths": [256, 256, 128], "recurrent": false },
  "action_law": "latent-then-limit",
  "discount": { "beta_per_s": "0.5025", "kappa_per_s": "2.565" },
  "channels": [
    { "id": "fl_hip_target", "role": "leg[0].hip", "unit": "rad", "sign": 1,
      "bounds": ["-0.8", "0.8"], "rate_hz": "50/1" }
  ],
  "observation_schema": { "actor": "digest", "critic_only": "digest", "normalizer": "digest" },
  "trained_on": { "task": "TaskId", "scenes": "split-digest", "randomization": "card-digests",
                  "tier": "gpu-cuda", "determinism": "D2", "reset_mode": "explicit", "donor": null },
  "group": { "mech": "C2xC2", "obs": "C2", "tying": "augmentation" }
}
```
```rust
pub struct PolicyManifest {
    network: NetworkSpec,              // kind, widths, recurrent
    action_law: ActionLaw,             // e.g. latent-then-limit
    discount: PhysicalDiscount,        // per second, not per step
    channels: Vec<ChannelMap>,         // matched by role, never by position or name order (INV-CORTEX-04)
    observation_schema: ObsSchema,     // actor, critic-only and normalizer digests
    trained_on: TrainedOn,             // task, scenes, randomization, tier, determinism, reset mode, donor
    group: GroupTying,                 // mechanical group, observation-preserving group, how tying was imposed
}
pub struct ChannelMap { id: Ident, role: Role, unit: Unit, sign: i8, bounds: (Qty, Qty), rate: Ratio }
```
Quantities are decimal or rational strings so that no binary rounding enters the manifest. A `Role` is a design-relative path such as `leg[0].hip`, assigned by the design compiler from the typed design term (limb index in canonical order, joint within the limb), not from an author's name. Observation channels are listed with the same fields under the schema digests' preimages, which are stored in the content store and referenced by digest.

**Writing.** At `train.export`, and at every periodic checkpoint: (1) read the behaviour weights and normalizers under a host-read lease at a commit boundary; (2) build the manifest from the admitted task, the network spec, the registered action law, the run's evidence block and the symmetry record; (3) compute `manifest_digest = BLAKE3(canonical JSON)` and `weights_digest` over the tensors in layout order; (4) write safetensors with metadata keys `frob.policy` (the manifest JSON), `frob.policy.digest`, `frob.weights.digest`; (5) store the file in the content store, whose address is the policy's identity `PolicyId = BLAKE3(manifest_digest ‖ weights_digest)`. A mid-run checkpoint additionally stores optimizer moments, the step count, the learning-rate schedule state, the value normalizer, the recurrent hidden store, the update index and the random-stream indices, so that a resumed run continues bit for bit in class D2.

**Reading and binding.** `load_policy(id) -> LoadedPolicy` verifies both digests; a file with no manifest, or with a digest mismatch, is not a policy and is refused. `bind(policy, design, task) -> BoundPolicy` runs the matcher:
1. For every action channel in the manifest find the design channel with the same `role`; fail if absent or duplicated.
2. Check unit (convert exactly if the units differ by a known factor; refuse otherwise), `sign` (apply the stored sign; if the design's actuator direction differs from the recorded one the bind is refused unless an inheritance map supplies the correspondence), bounds (the design's bounds must contain the manifest's, or the mismatch is refused with both shown), and rate (rational equality).
3. The same for observation channels against the actor schema; compare the normalizer digest.
4. Check the action law against the task's registered law and the reset mode against the evaluation's.
5. Produce a gather/scatter table (permutation and signs) that the device applies between the policy's tensors and the design's channels.
Any failure is **FROB-REF-531** (meaning: a policy's mapping table does not match the design, or cannot be built for an edit; repairs, ranked: supply the correspondence in the typed edit; train fresh; exit code 3). The payload lists every mismatching role with the observed and required values. There is no positional fallback and no "closest name" guess.

**Verb `train.export`.** Inputs: a run identifier or policy identifier; `--at <checkpoint|latest|best-on-dev>`; an output path inside the caller's path jail or `--to store`. Output envelope: `policy_id`, `manifest` (inline), digests, byte size, the `trained_on` block, the evidence block (class `Tested`, tier, determinism class of the training profile, model/task identities, seed), and the three no-authorization flags, all false (`execution_authorized`, `hardware_safety_signoff`, `sim_to_real_certified`). A policy trained under the labeled nondeterministic profile exports with `trained_under: D4` and a note that its results must be re-evaluated on a stricter profile before they are cited. Refusals: unknown run; a run with no completed update; a path outside the jail.

**Determinism and evidence.** The manifest and digests are exact. The export records its identities in the artifact graph (the policy is a node whose parents are the run, the task and the design).

## Acceptance criteria
- [ ] A checkpoint written and re-read reproduces the weights bit for bit and the manifest byte for byte; editing one byte of the manifest or of the weights makes the load fail.
- [ ] A safetensors file without the manifest metadata is refused as a policy.
- [ ] Binding a policy to its own design succeeds; binding after the design's joints are re-ordered in the file (same roles) succeeds with a non-identity permutation and reproduces the same actions; binding to a design that lacks one role, or has a different unit, sign convention, bounds or rate for a role, is refused with FROB-REF-531 naming the role and the two values.
- [ ] A mirrored-limb fixture in which an encoder sign differs is handled by the stored `sign`, and a deliberately wrong sign in the manifest is caught by the bind check against the design's recorded actuator direction.
- [ ] A mid-run checkpoint resumes to identical digests of the next three updates (class D2).
- [ ] `frob train export --json` returns the envelope described, with the manifest inline, the no-authorization flags false and the evidence block; the exported checkpoint, reloaded on `batch-cpu`, has a policy head that is not all zeros (a field `policy_head_norm` is reported and asserted > 0).
- [ ] Invariant INV-CORTEX-04 is covered by a property test (below) and recorded.
- [ ] Negative controls caught: a loader that matches by position (passes on the original design and fails the re-ordered-joints fixture); a loader that ignores the normalizer digest; an export of an all-zero policy head presented as trained.

## Test plan
### Unit tests
`manifest_roundtrip_bytes`; `tamper_manifest_or_weights_refused`; `missing_manifest_refused`; `bind_same_design_identity_permutation`; `bind_reordered_joints_same_actions`; `bind_missing_role_refused_531`; `bind_unit_mismatch_refused_531`; `bind_sign_mismatch_refused_531`; `bind_bounds_outside_design_refused_531`; `bind_rate_mismatch_refused_531`; `bind_normalizer_digest_mismatch_refused`; `midrun_checkpoint_resume_bitwise`; `export_reports_policy_head_norm`; property test `inv_cortex_04_role_matching` (random permutations and renamings of a design's channels with roles preserved: the bound policy's actions on the design are unchanged; any change of a role's unit, sign, bounds or rate is refused).
### End-to-end script and logging
`scripts/e2e/cortex_train.sh` (bead N23a-35), step `export-and-bind`: `frob train export <run> --to store --json`; `frob artifact read <policy_id> --json`; `frob eval run --policy <policy_id> --design <same design, joints re-ordered> --json` (expects equal return); `frob eval run --policy <policy_id> --design <design with regeared knee direction> --json` (expects exit code 3 and FROB-REF-531). NDJSON: `cmd` lines, the envelope's evidence block and flags, `metric` lines (digests, `policy_head_norm` with threshold > 0, byte size), `refusal` lines with the mismatching role, observed and required values.
### Known answers and negative controls
The all-zero-head case is the documented failure of the suite's existing training crate (its exported checkpoint has an all-zero policy head and its own tracker entry says it proves plumbing); the export's `policy_head_norm` and the training gate's replay make that visible (KA-590, CX-257). The three negative controls are registered against GATE-CORTEX-01 (the exported-checkpoint clause). Metamorphic relation: renaming every channel identifier in design and manifest consistently changes no behaviour and no bind result. Determinism lanes: digests identical across machines; resume twice gives identical digests.

## Considerations
- Privacy and licences: weights trained in a private or research-only scene inherit its mark and licence set by default (an open safety question whose default is "they inherit both"); the manifest's `trained_on.scenes` digest is what the inheritance joins on, and export refuses to write outside the jail.
- Security: loading weights is an input path; only the allowlisted layout and architecture family are accepted, tensor shapes are checked against the spec before any allocation, and metadata is treated as untrusted text.
- The symmetry block (`group`) records how tying was imposed (`none`, `augmentation`, `equivariant`) so that a tied policy is never applied to a robot-task pair with a smaller observation-preserving group.
- A distilled policy's manifest lists its teachers and takes the weakest standing among them; the field is reserved here (`trained_on.teachers`) and filled by the distillation bead.
