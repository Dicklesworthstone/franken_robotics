## Background
Training is reached through four verbs of the command surface: `train.start` (algorithm, network, devices, tying and profile are arguments), `train.status`, `train.stop` and `train.export`. The environment has no verb of its own; `train.*`, `eval.*` and `sim.run` reach it. Every verb is callable as `frob <verb> --json`, returns exactly one envelope, and is generated into the agent-facing tool surface from the same registry. This bead builds the first three (the fourth, `train.export`, is bead N23a-13) and the training job that ties collection, update, checkpoints and reporting together.

Registry rows (the verb registry of the specification; the rows of record are in the registry bead VERBS-train, which this bead implements and does not restate differently): `train.start`: kind run, first milestone M2, capability `train:run`, "start training; algorithm, network, devices, tying and profile are arguments", example `frob train start quad-a --task flat-velocity --algo ppo --devices cuda:0 --key tr-1 --json`. `train.status`: kind read, M2, capability `train:read`, "return, steps, learner share and flags of a training run". `train.stop`: kind admin, M2, capability `train:admin`, "stop a training run at a commit boundary". Schemas follow the registry's rule: `frob.train.start.in/1` and `frob.train.start.out/1`, and likewise for the other two. A `run` verb waits synchronously for a bounded time and otherwise returns a job handle with process exit code 8 (accepted and still running).

**Algorithms.** PPO with generalized advantage estimation, value normalization and an adaptive step size is Solid and is the only algorithm admitted at M2. The others named by the specification are Frontier: SAC; TD3; evolution strategies (which would use the sibling simulator's derivative-free optimizers through the single consumption boundary, for small policies and for tuning a handful of baseline-controller gains); teacher-student distillation from privileged to proprioceptive observations; behaviour cloning from the baseline controller as a warm start (the baseline supplies demonstrations for free). Each has a pilot against PPO on the reference task at equal wall-clock and a kill gate (KILL-ALTALGO: if the arm beats PPO neither in time to the threshold nor in final requirement pass rate, that algorithm is not built and PPO remains the trainer). The registry built here is how that rule is enforced in code: an algorithm without a recorded passed pilot cannot be started.

Tier Solid. Rejected alternatives: a long-lived interactive trainer process driven by ad hoc commands (not recoverable after a crash, not idempotent); exposing hyperparameters as free-form key-value text (unvalidated, undocumented).

## Scope
In: the three verbs with their input and output schemas; the training job on the crash-consistent job protocol (chunks, leases, cancel, restart); the algorithm registry and its admission rule; device and backend selection through the placement planner; checkpoint cadence; progress events; refusals; idempotency. Out: the PPO implementation (BD-197 and its subtasks); `train.export` and the manifest (N23a-13); placement policy, precision and the labeled profile's citation rule (N23a-18); the statistical attainment rule with the `crossing` and `attained` fields and the look table of `train.status` (N23b-33, which extends this verb's output and depends on this bead); the action sampler, its manifest and the qualification-receipt check that `train.start` calls at admission (N23b-29, a dependency); the receipts themselves, written by the joint-law battery N23b-30 (also a dependency: this bead's tests that start `ppo`, and its `ppo starts` criterion, need the real receipt for the pinned kernel, which no fixture stands in for); the build of any algorithm other than PPO (SAC N23a-37, TD3 N23a-38, evolution strategies N23a-39, asynchronous sharding N36-12, adaptive randomization N23b-04, each behind its row of KILL-ALTALGO, decided by N23b-23); the reference training gate (BD-198); `train.family`, `train.inherit`, `train.distill` (their own beads).

## Technical approach
**`train.start` inputs (schema `frob.train.start.in/1`, DESIGN).**
| Argument | Meaning | Default |
|---|---|---|
| `task`, `design` (or `model`), `scenes` | Identities; mutable names are resolved to immutable identifiers and echoed in `bound` | required |
| `algo` | Algorithm name from the registry | `ppo` |
| `network` | `mlp:<widths>`, `gru:<hidden>`, or `morph-transformer:<d>,<layers>,<heads>` (for example `morph-transformer:192,4,4`; the kind N23b-41 adds to the `NetworkSpec` catalogue, Frontier, behind its feature: parsed here, and refused as a capability not in the build, `FROB-REF-724`, exit 5, until N23b-41, which depends on this bead, builds it); a malformed string of any kind is `FROB-REF-802`; actor/critic split from the task's access classes | `mlp:256,256,128` |
| `devices`, `backend` | `batch-cpu`, `gpu-cuda[:0,1]`, `gpu-metal`; strict or planner-chosen | planner |
| `shards` | `--shards <n>`, passed through to the trainer configuration's `shards` field of N23a-19's multi-shard update (a dependency through BD-197); on `batch-cpu` a value above 1 splits the batch on the one host; 0 is `FROB-REF-802` | one per device of the placement |
| `trainer` | `device` (kernels) or `frankentorch` (CPU learner); `cpu-readback` is added by N23a-17 on KILL-LEARNKERN's fired branch and `frankentorch-device` by FD-FT-02 on adoption (each refused with `FROB-REF-724`, exit 5, before its bead lands) | `registries/defaults.toml` `train.trainer` (`device` until N23a-16's decision sets it) |
| `tying` | `none`, `augmentation`, `equivariant` (the last two arrive with the symmetry beads) | `none` |
| `determinism` | The row's "profile": the determinism profile, spelled `--determinism` (`--profile` names a step profile, never a determinism profile): `device-replay` (class D2); the labeled `fast-training` (class D4) is added with its knobs and admission by N35-06 at M3 and is refused with `FROB-REF-724` before then (the trainer's half is N23a-18's) | `device-replay` |
| `action_law` | `latent-then-limit` or `clipped-with-endpoint-mass`; passed to admission as `AdmitMode::Train { action_law }` (N23a-05): `Some(argument)` when given; when absent, `None` if the task declares a law (a task-declared law wins over the default) and `Some(registry default)` if it declares none, so `action-law-missing` is never reached through the verb; an explicit argument that differs from the task's law is the finding `action-law-conflict` | the task's declared law, else the registry default (N23b-25), labelled as a default in the envelope |
| `reset_mode` | `--reset-mode explicit\|autoreset-masked` (BD-192), passed to the environment constructor | `explicit`, recorded in the manifest and in `trained_on.reset_mode` |
| `zero_copy` | `--zero-copy` (BD-193), passed to the view contract of the run: a tensor view the receiver cannot represent is refused with `FROB-REF-547` instead of being materialized with a charged copy | off |
| `actor_channels` | `--actor-channels <list \| +id \| -id>` (N23a-03), passed to the network specification's `actor_channels` field: the actor's inputs as a list of channel ids or as edits of the default; a channel of another class is `FROB-REF-524` | every `actor` channel of the task |
| `dry_run` | `--dry-run`: admission and the parameter count only; no job is created and no device memory is allocated; exit 0 with the admission report, the resolved arguments (with defaults labelled) and the parameter count; a failing admission returns the same refusal as a real start. The row names N23b-41, which adds the `morph-transformer` count; the M2 steps of N23a-34 and N23a-35 already use it for `mlp` and `gru`, so this bead serves it from M2 | off |
| `worlds`, `steps_per_collection`, `budget` (environment steps and/or wall seconds and/or GPU seconds; the row's `--steps <n>` is the shorthand for `--budget env_steps=<n>`, and both together are `FROB-REF-802`) | Sizes and stop conditions | task-family defaults |
| `seed`, `key` | Run seed; the idempotency key (`--key`, as for every `run` verb); a repeated key with the same content returns the same job | required key |
| `eval_cadence`, `target` | The registered development-stream cadence and the target return or success rate | task-family defaults |
| `resume` | A mid-run checkpoint to continue from; a continuation whose `eval_cadence` or `target` differs from the values recorded with the checkpoint is `FROB-REF-802` with `pointer` naming the field and the repair "omit it: the registration travels with the checkpoint; or start a new run, whose looks begin at 1" (N23b-33's rule; N23b-33, which depends on this bead, hashes that registration into the run record, and the comparison reads it) | none |

**Admission (before any device work), each failure a refusal with repairs.** The task passes the term contract: `frob_learn::env::admit(program, AdmitMode::Train { action_law })` with the law resolved as in the table, and the pass's findings come back unchanged as one refusal, the Cortex registry's request `term-contract-unmet` (N23-REF, raised behind `frob_learn::refusal::TERM_CONTRACT_UNMET` until the allocation ledger numbers it; exit 3), except the three findings that keep their own code (554, the settled-pose cache's 529, and the spec crate's refusal for a missing scale); the actor schema is frozen from `actor_channels` (524 from the learner's class check, 442 from the freeze of `frob-sense`, surfaced unchanged); the algorithm is in the registry with status `admitted`; the action sampler has a qualification receipt for the pinned kernel (the joint-law rule, `sampler-unqualified`, 558, through N23b-29's `check_qualified`, called before any world is created); the placement fits the device budget (the cost model's estimate is printed; over the per-card budget is 602); `resume` storage was collected under the same action law (else FROB-REF-527) and under the same registration (else 802, above); the determinism profile and knobs pass the licence check (else 247); the profile is permitted for the caller's scopes; the budget does not exceed the session's (exit 4).

**Refusals of `train.start`, as the row lists them (VERBS-train).** Raised at this bead's admission: `term-contract-unmet` and 554 (N23a-05's pass), 529 (the cache's, surfaced), 442 (the freeze's, surfaced), 524, 527, 547 (under `--zero-copy`, the view rule of BD-193), 558, 247 (N35-04's licence check, N35-06's knobs) and 602 (N36-08's per-card estimate). Raised during the job: 522 (a non-finite action from the learned policy, BD-192's check) and 601 (a device lost, N36-08). Raised through the hooks this bead leaves, by the beads that bring the condition: 103, 572 and `randomize-no-interval` (BD-200 at environment admission), 445 (N20a-41: a mission with a standing alias witness, looked up by `alias::standing_witness` at admission) and 457 (BD-338, under `--shield`). The surface's own codes are not repeated in the row: 802 for a malformed or inadmissible argument, 803 for a key reused with different content (exit 7), 724 for a capability not in the build or an algorithm not admitted (below).

**Algorithm registry (`registries/algorithms.toml`).** Rows: `name`, `tier`, `status` (`admitted` | `pilot-pending` | `killed`), `pilot` (record identifier), `kill_gate`. At M2: `ppo` admitted; `sac`, `td3`, `es`, `teacher-student`, `bc-warmstart`, `adaptive-randomization`, `async-sharding` are `pilot-pending`. Starting a `pilot-pending` or `killed` algorithm is refused with `FROB-REF-724` (exit 5, the answer of a capability that is not admitted, as for `short-horizon-ac`'s `not-linked`), with `reason: pilot-pending` or `reason: killed` and the pilot's identifier, its falsifier and the kill gate in the envelope. A row moves to `admitted` only by a recorded passed pilot.

**The job.** A training run is a job whose unit of work is one *iteration* (a collection plus a complete update plus publication of weights). The state machine `Collecting → Updating → Publishing` commits at iteration boundaries: each commit publishes a chunk record (iteration index, weights digest, statistics, digests of the environment state) under the writer's lease. A crash or a cancellation resumes from the last committed iteration and reproduces the same digests (class D2 under `device-replay`). Checkpoints (mid-run form) are written every `checkpoint_every` iterations and at stop.

**`train.status` output (schema `frob.train.status.out/1`).** `state`; `progress {done, total, unit}` in environment steps (always with a denominator); `eta_s` with its interval; throughput in **both units**, `env_steps_per_s` and `world_steps_per_s`; `learner_share` (fraction of wall-clock in the update, for the phase ledger); mean return and episode length on the training stream (labelled descriptive; never evidence under the D4 profile); per-look development-stream scores with the fields `crossing` and `attained` (computed by the attainment rule); counts of valid, invalid and padded samples and per-cause failures; clip fraction, KL, learning rate; charged copies per collection; flags (`trained_under: D4`, `clock-hidden`, `defaults-used`, saturation share); last committed iteration and latest checkpoint identifier; the evidence block.

**`train.stop`.** Kind admin. Requests a stop; the run finishes its current iteration (collection and update complete, weights published), writes a checkpoint and ends in state `stopped`. `--now` cancels at the next commit boundary inside the iteration and discards the partial iteration; nothing partial is ever published as a result. Idempotent.

**Envelope and exit codes.** 0 completed; 2 completed with flags; 3 refused input (the refusals of the learning registry N23-REF, and those of the layers below surfaced unchanged, such as the settled-pose cache's 529 and the actor-schema freeze's 442); 4 budget; 5 not admitted or out of scope; 6 backend unavailable; 7 idempotency conflict; 8 accepted and still running.

**Determinism and evidence.** Under `device-replay` the run is class D2 per backend; the envelope's evidence block names class, tier, determinism, identities and seed. Under `fast-training` every output is tagged D4 and the citation rule applies.

## Acceptance criteria
- [ ] The three verbs are in the verb registry with request and response schemas, examples and refusal lists, reachable through `frob --json` and generated into the agent tool surface.
- [ ] `train.start` returns exit code 8 with a job handle within the synchronous wait bound; a repeated call with the same idempotency key and content returns the same job; the same key with different content is refused (exit code 7).
- [ ] Each admission failure listed above returns its refusal with at least one repair, before any device allocation (verified by the device allocation counter).
- [ ] Starting `algo = sac` at M2 is refused with FROB-REF-724, exit code 5, `reason: pilot-pending`, and names its pilot and kill gate; `ppo` starts.
- [ ] `reset_mode`, `zero_copy` and `actor_channels` reach the environment, the view contract and the network specification: the manifest records the reset mode; a view that would need a copy under `--zero-copy` is FROB-REF-547; `--actor-channels +<critic-only channel>` is FROB-REF-524; the action law resolves as the table states, and an explicit law that differs from the task's is `term-contract-unmet` with the finding `action-law-conflict`.
- [ ] A continuation with a changed `eval_cadence` or `target` is FROB-REF-802 naming the field; `--dry-run` creates no job and allocates no device memory.
- [ ] Every code the row of `train.start` lists is either raised by a test of this bead or named above with the bead that raises it, and the handler raises no chapter code that the row does not list.
- [ ] `train.status` reports both throughput units, the learner share, the failure counts and progress with a denominator; `world_steps_per_s` = d · `env_steps_per_s` exactly, d being the task's decimation.
- [ ] `train.stop` ends the run at an iteration boundary with a loadable checkpoint; `--now` leaves no partial iteration published.
- [ ] Kill the worker process mid-iteration 100 times: the job resumes from the last committed iteration every time and the final weights digest equals the uninterrupted run's (class D2).
- [ ] Cancellation is tested: request, drain, finalize, with no leaked device resources.
- [ ] Negative controls caught: a status that reports a single unlabeled "steps per second"; a stop that publishes a half-updated weight set; an algorithm row marked admitted without a pilot record (the registry loader refuses the registry).

### End-to-end script and logging
`scripts/e2e/cortex_train.sh` (bead N23a-35), steps `verbs-lifecycle` and `verbs-refusals`: `frob train start <reference quadruped> --task <reference> --backend batch-cpu --worlds 256 --budget env_steps=200000 --seed 7 --key e2e-1 --json` (expects exit 8; the same call again returns the same job; the same key with another seed exits 7); `frob train status <job> --json` polled with `frob job wait`; `frob train stop <job> --json`; a kill-and-resume cycle; then the refusal cases (`--algo sac`, exit 5 and FROB-REF-724; a non-finite budget; a missing settled-pose cache; a resume under a different action law; each under its own `--key`). NDJSON per call: exact command line, exit code, wall time, the envelope's evidence block, `metric` lines (both throughput units, learner share, failure counts), `refusal` lines (code, pointer, repairs), digests compared after resume with the first differing iteration on failure; `summary` with assertion counts.
### Known answers and negative controls
The decimation identity between the two throughput units is exact. Negative controls as listed, registered against GATE-CORTEX-01 (the gate's record is produced through these verbs). Determinism lanes: the same start twice gives the same final digest; across worker counts; kill-and-resume against uninterrupted.

## Considerations
- A training curve is a descriptive event stream; acceptance of a policy is the requirement verdict in the blinded qualification lane, never a return printed by `train.status`.
- Budgets: the default compute envelope is one device for one hour; a run that would exceed the session's envelope is refused at admission with the estimate, not stopped half-way.
- The `devices` argument with two cards uses the global normalization rule of the multi-device update; an asynchronous variant is Frontier and is refused until its pilot passes.
- Security: `train.start` accepts no code; custom reward terms are not admitted (an open safety question's default), so the task file is the only source of terms.
