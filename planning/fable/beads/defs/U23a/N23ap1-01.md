## Background
A *requirement* is the acceptance metric of a mission: a temporal-logic formula over an episode whose *margin* ρ is a dimensionless number (each atom ψ(x) ≥ 0 or ψ(x) > 0 is divided by its declared scale s before any minimum or maximum combines atoms) whose sign agrees with the formula's truth away from zero. *Past-time* operators (historically H, once O, since S, over a bounded past window) depend only on what has already happened, so they can be computed inside the simulation step while an episode runs; *future-time* operators (always G, eventually F, until U) give a verdict only on a completed trace and are never evaluated online. An online past-time margin has three consumers: an input to early termination, a score for splitting in the rare-failure search, and an optional added reward term (a Frontier option behind KILL-SPEC-REWARD).

At M1 the monitors exist in lockstep form on the CPU: N24a-07 compiles a past-time formula into a DAG of monitor nodes and runs the block-decomposition kernels through the `batch-cpu` kernel harness; the referee's monotonic-deque formulation is N24a-08; the definitional evaluator (N24a-04) and the two-pass offline evaluator (N24a-09) are the oracles; the guard band and exact re-evaluation of boundary atoms are defined on the host by N24a-10. What is missing, and what this bead builds, is the **device emission**: the same kernels in the shared GPU dialect, running in the last stage of the batched step on CUDA and on Metal, bitwise equal to the offline evaluator on every backend, with the guarded atom kernel that flags near-zero atoms for exact re-evaluation. This is the measurable core of GATE-CORTEX-10's first clause ("streaming past-time robustness equals offline evaluation on 10⁴ random traces").

Why bitwise equality is achievable: minimum, maximum and negation are exact in floating point (the result is always one of the inputs), so a monitor built only of comparisons and selects returns the same bits on every backend for identical atom values, once negative zero is canonicalized and a NaN is turned into a world fault. Why a guard is needed: FACT (boundary-classifier runs on the M5 Ultra's Metal GPU and on both RTX 4090 cards, planning reproduction archive, Appendix H.5): on a dense 65,536-case boundary screen, unguarded single-precision strict comparison gave 452 false admissions and 23,438 false exclusions; with a guard band of 2⁻²¹ and an exact fallback there were no final errors; an exact 32-bit integer kernel classified all 65,536 cases correctly with identical bytes on every device.

This bead was split from BD-255 so that the consumers that need only the online margin on devices (the reward-term option, the splitting score, early termination) do not wait for the M3 task families that BD-255's end-to-end verdict path runs on. Tier Solid. Crates: `frob-spec` (the monitor compiler, unchanged) and the kernel library (the emitted stages).

Rejected alternatives: a monotonic deque on the device (it pops a data-dependent number of elements per sample, which breaks the lockstep rule; the deque stays on the referee); a ring-of-candidates kernel for since with O(W) comparisons per sample (correct but W times more work than N24a-07's lattice decomposition, which is an exact identity already tested against the definition; two kernels for one operator would be the same artifact specified twice); evaluating atoms near zero in single precision without a guard (the 452 and 23,438 errors above).

## Scope

Out: the monitor compiler, the CPU lockstep kernels and their capacity rule (N24a-07); the referee deque (N24a-08); the offline evaluator and the decided-early ticks (N24a-09); the guard band's host definition and the exact re-evaluation (N24a-10); the guard value per backend (N24c-15); writing `frob.verdict/1` per episode from batched runs, `task.verdict` and `task.settle` on batched tiers, early termination in `VecEnv`, the mixed-unit and future-time clauses and the gate record of GATE-CORTEX-10 (BD-255, which depends on this bead); the learner's refusal of a future-time term as an online reward (N23a-05, FROB-REF-554); the optional reward term (N24a-14) and the splitting score (N26a-29).

## Technical approach
**Margin semantics (time is the tick index of the requirement's clock).** Atom e ≥ 0 or e > 0 with scale s: ρ = e(t)/s. Negation −ρ; conjunction min; disjunction max. H_[a,b] φ and O_[a,b] φ at tick t: min and max of ρ(φ, t′) over t′ ∈ [t − b, t − a]. φ S_[a,b] ψ: max over t′ ∈ [t − b, t − a] of min(ρ(ψ, t′), min of ρ(φ, t″) over t″ ∈ (t′, t]). Laws: ρ > 0 implies the formula holds, ρ < 0 implies it fails; at ρ = 0 the margin decides nothing.

**Kernels emitted (the algorithms are N24a-07's; restated so this bead stands alone).**
1. *Sliding extremum for a tick window [a, b]* (H is the minimum; O the maximum, by exchanging min and max): W = b − a + 1; state per (node, world): `raw[W]`, `suf[W]`, a running prefix `pre`, an output delay ring `ring[a]` (absent when a = 0), a coverage counter `cov` and the block position p = k mod W, k counting the world's requirement ticks. Per tick with input x: (i) `pre ← (p = 0) ? x : min(pre, x)`; (ii) `raw[p] ← x`; (iii) `m ← (p = W − 1) ? pre : min(suf[p + 1], pre)`, the minimum over the last W ticks; (iv) if p = W − 1, one backward pass `suf[W − 1] ← raw[W − 1]`, then `suf[j] ← min(raw[j], suf[j + 1])` for j = W − 2 down to 0 (a loop of fixed trip count executed by the worlds at a block boundary); (v) delay by a ticks: `out ← ring[k mod a]`, `ring[k mod a] ← m` (when a = 0, `out ← m`), so `out` is the minimum over ticks [k − b, k − a]; (vi) `cov ← min(cov + 1, b + 1)`, `covered ← (cov = b + 1)` (ticks since creation or reset: the pre-origin clock); beside it the validity counter over the node's input, `vcov ← in_valid ? min(vcov + 1, b + 1) : 0`, and `valid ← (vcov = b + 1)`: the output is valid only when every input value inside the window was valid, so for a nested node its input node must itself have been valid for b + 1 ticks, and for a node over atoms (`in_valid` is the atom slab's per-tick validity, false on a missing sample) a dropped sample invalidates every window that contains it (INV-ARENA-02; N24a-07's counter, emitted unchanged); (vii) the language's pre-origin rule: for H, while not covered, `out ← −∞` through a select with the flag `pre-origin`; for O, the output while not covered is the maximum over the existing ticks (its buffers hold −∞ from the reset). `valid` of step (vi) is exported beside the value: margin consumers read `valid`; Boolean consumers read the value, which is false while H is not covered. Cost: fewer than three comparisons per sample on average; memory 2·W + a values per node and world; every branch condition is on the integer tick counter, never on a signal value, so on a device it is a select mask.
2. *Since*: φ S_[a,b] ψ = min(O_[a,b] ψ, Z), with Z(t) = min(min of ρ(φ, t″) over t″ ∈ (t − a, t], Q(t − a)) and the unbounded since Q(s) = max(ρ(ψ, s), min(ρ(φ, s), Q(s − 1))), Q = −∞ before the episode's first tick (a lattice identity, exact for minima and maxima). The node is one sliding maximum of ψ over [a, b], one sliding minimum of φ over the a most recent ticks (absent when a = 0), the scalar Q with a delay ring of a values, and a final minimum; memory 2·W + 4·a + 1 values; coverage `cov = b + 1`.
3. *Coverage*: every node output carries a validity bit per world, computed by the counter `vcov` of step 1 (vi) (for since, over both inputs: `in_valid` is the conjunction of φ's and ψ's validity); an output is valid only if every input value inside its window was valid.
4. *Reset*: `cov ← 0` and `vcov ← 0`; an H node's buffers are not cleared (its output is forced to −∞ until b + 1 post-reset ticks have been seen, after which it reads only post-reset ticks); an O node's `raw`, `suf`, `pre` and `ring` and a since node's Q, Q-ring and ψ-maximum buffers are filled with −∞; all through selects inside the reset path, never by branching on data.
5. *Floating point*: −0 becomes +0 at the atom; a NaN atom sets the world's fault bit through a select, the monitor's outputs for that world are invalid from then on, and the episode's verdict is `invalid` (a study error, never a margin); no fused operations, no reassociation.
6. *Placement*: the monitor nodes run in the last stage of the batched step, after the atom slab is written and beside the observation and reward stages; their manifests declare buffers, extents, the epoch read and written, resource bounds (2·W + a values per H or O node and world, 2·W + 4·a + 1 per since node, reported by the cost model) and determinism class D1 across backends for identical atom values.
7. *Capacity*: an online window is admitted when its far bound b is at most 4,096 requirement ticks (TARGET); a longer window is offline only and its online use is refused by the language's FROB-REF-528 at compilation, which this bead surfaces unchanged.

**Guarded atom kernel.** An atom is decided on the device only when its normalized margin lies outside the guard band g around zero (g from OPEN-ARENA-5 per backend: one constant, or a per-atom derived bound with 2⁻²¹ as a floor). A world whose verdict atom lies inside the band gets the `boundary` flag with the atom id and tick, and the atom is re-evaluated on the CPU by N24a-10 with its declared comparator: exact rational or integer arithmetic where the inputs belong to the exact-integer kernel class (BD-053), double precision otherwise. Strict and non-strict comparators are distinct atom kinds and are never merged on the device.

**Equality test (the battery `cortex-verdict`, DESIGN name).** 10⁴ random traces per backend from a seeded generator: random formulas over H, O, S, ∧, ∨, ¬ of depth up to 4 with windows from 1 to 4,096 ticks (stratified so that 10% of formulas sit at the 4,096 capacity), random atom values including exact zeros, negative zeros, values within 2⁻²⁴ of zero, ±∞ and planted NaNs, random reset instants. For each, the streamed margin at every tick is compared bitwise with the offline evaluator's value on the same prefix and with the referee deque's value; validity bits are compared exactly. The battery is the fixture set of the known-answer row KA-593 and runs through the Gauntlet, not through a verb (`eval.run` runs task batteries for a design and has no backend option): `FROB_TEST_SEED=11 cargo test -p frob-conformance --test g1_known_answers --features <cuda|metal> -- KA-593`, which runs `batch-cpu` always and each device whose annex feature is built (a device absent on the host is reported `skipped: capability absent`, never passed), with `--features gauntlet-mutations` added for the planted controls; and as `cargo test -p frob-spec --test device_monitors`.

**Boundary screen.** The 65,536-row docking-boundary screen of the archive, run through the guarded atom kernel on each device: zero final errors after exact fallback; the unguarded single-precision strict comparison is the negative control and must reproduce false admissions and false exclusions (452 and 23,438 on the archive's grid; a differing count is written into the record with both values).

**Determinism and evidence.** Monitors: class D1 across backends for identical atom values; atoms inherit the class of their inputs; boundary decisions are D0 after the exact fallback. Evidence class `Tested`; the battery receipt names commit, hardware fingerprint, backend and seed.

## Acceptance criteria
- [ ] On `batch-cpu`, CUDA (`gpu-cuda`) and Metal (`gpu-metal`), the streamed margin equals the offline evaluator bit for bit on 10⁴ random traces each, and equals the referee deque on the same traces: zero mismatches (GATE-CORTEX-10, first clause, first measurement; KA-593).
- [ ] Validity: no streamed value is marked valid before its window is covered; a reset mid-window restarts coverage; checked on every trace.
- [ ] A NaN atom marks the world `Faulted` and invalidates its monitor outputs; it never appears as a margin.
- [ ] A window of 4,096 ticks compiles for online use and one of 4,097 is refused with FROB-REF-528 at compilation.
- [ ] The guarded path on each device makes zero final errors on the 65,536-case screen; the unguarded strict comparison makes false admissions and false exclusions and is caught.
- [ ] The kernel manifests declare the memory per node (2·W + a for H and O, 2·W + 4·a + 1 for S) and the cost model's figure for W = 4,096 and 8,192 worlds matches the allocation within one page.
- [ ] `FROB_TEST_SEED=11 cargo test -p frob-conformance --test g1_known_answers --features <cuda|metal> -- KA-593` exits 0 only when every fixture of `cortex-verdict` passes on every built backend, and the same run with `--features gauntlet-mutations` reports every registered control caught; its receipt (commit, hardware fingerprint, backend, seed) is the one BD-255's gate record cites.
- [ ] Negative controls registered against GATE-CORTEX-10 and caught: a streaming kernel with an off-by-one window; a NaN atom treated as a margin; a kernel that skips the −0 canonicalization (caught on traces with planted negative zeros); an unguarded single-precision strict comparison.

## Considerations
- Memory: 2·W + a values per H or O node and world (2·W + 4·a + 1 for since); at W = 4,096, a = 0, 8,192 worlds and four nodes in `f32` this is 2 · 4,096 · 8,192 · 4 · 4 bytes = 1 GiB; the cost model reports it and admission refuses what does not fit rather than shrinking the window.
- The Metal gateway's 31-argument limit: monitor buffers are packed into one slab per formula.
- Failure mode: a backend whose comparison of ±0 or of NaN differs from IEEE 754 would break the bitwise claim; the canonicalization at the atom and the fault-on-NaN select make the monitors independent of that, and the planted controls test it.
- The guard value is OPEN-ARENA-5's decision (fail-closed default: 2⁻²¹ on every backend); a guard that is too narrow is caught by the boundary screen, one that is too wide only sends more atoms to the CPU and is visible in the flag rate.
- If KILL-SPEC-REWARD removes the requirement-derived reward term, the online margins remain for early termination and splitting; nothing here changes.
