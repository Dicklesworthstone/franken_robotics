## Background

GOAL-16 of FrankenRobotics is that no learned result rests on a simulator artifact. Before a policy result is
reported it is re-evaluated under perturbations that should not matter to a physically meaningful behaviour; a
collapse outside the recorded envelope sets a flag on the result. The ten detectors and their flags:

| Perturbation | Flag |
|---|---|
| Half the time step | `dt-sensitive` |
| The next tier up | `tier-sensitive` |
| Friction and stiffness moved within their card uncertainty | `parameter-sensitive` |
| The alternative contact law, including the hard-contact batch law where it is built | `law-sensitive` |
| Solver tolerance divided by 10, and Newton iterations doubled | `tolerance-sensitive` |
| Contact stiffness halved and doubled | `stiffness-sensitive` |
| Controller rate changed; rotor inertia restored to its card value where a model omitted it | `rate-sensitive` |
| The mirrored policy on a symmetric robot, which must score the same within noise | `mirror-asymmetric` |
| The causal test (identical delivered observations give identical commands) | `leak-sensitive` |
| A per-step work-energy audit from the energy ledger: ΔE_mech − W_act ≤ ε | `energy-created` |

This bead is the user-visible capability: the `run` verb `eval.detect` ("the exploitation detectors, on one
result", first milestone M3), the way flags attach to results and travel with them, and the gate. The detectors
themselves are N23b-05 (harness and five numerical-model detectors) and N23b-06 (five physical and structural
detectors); the planted exploits are N23b-07. Rank robustness of a set of finalists is a different question (does
the ranking survive?) and is N23b-08 with the verb `fidelity.modelform`.

Design reason for a verb of its own: detection costs re-evaluation, so it is a job with a budget and an
idempotency key, not a side effect of every evaluation; and an agent must be able to ask "is this result an
artifact?" about one result and get a typed answer.

Tier: Solid. Owner crate: `frob-learn`, registered through `frob-verbs`.

## Scope

In: the verb (schemas, pipeline, envelope, refusals); the flag record on results and its propagation; the gate
measurement GATE-CORTEX-04; the capability's end-to-end script.
Out: detector internals (N23b-05, N23b-06); the corpus (N23b-07); rankings (N23b-08, BD-266); the promotion rule
(BD-263), which this verb calls for the tier detector.

## Technical approach

**Input (`frob.eval.detect.in/1`, DESIGN).** `result` (the identity of an evaluation result: design, policy,
task, split, tier, step plan, seeds); `detectors` (default: all ten; a subset by flag name); `pairs_budget` per
arm (default 32); `tiers` for the tier detector (default: the next tier up); the `run` verb's idempotency key,
budget and bounded wait (`sync_wait_ms`); `--state estimated|privileged` inherited from the result.

**Pipeline (numbered).**

1. Resolve the result and bind immutable identities; echo them in `bound`.
2. Admission: the result must exist and be replayable (class D2 on its backend); an arm of class D4 or of
   unrecorded class is refused by the determinism licence for paired statistics; a result of a D4-trained policy
   that has no stricter re-evaluation is refused (FROB-REF-867).
3. For each requested detector build its arms (one change each) and estimate cost; refuse at admission if the
   budget cannot cover the minimum of 16 pairs per arm (budget refusal, exit 4).
4. Run arms as paired jobs at the result's world addresses; `energy-created` and `leak-sensitive` read ledger
   rows and causal-test digests and need no paired statistics.
5. Judge each detector: `clean`, `flagged`, `undetermined` or `not-evaluated` with a reason.
6. Write the flag record to the result in the ledger and return the envelope.

**Output (`frob.eval.detect.out/1`, DESIGN).**

```json
{ "result": "r:6f1a…",
  "detectors": [
    { "flag": "law-sensitive", "state": "flagged", "arm": "cone:pyramid", "pairs": 3, "exceedances": 2,
      "envelope": "b3:91c0…", "step_plan": "sp:44d2…", "metric": {"name": "distance", "unit": "m",
      "base": 5.0, "arm": 1.2} },
    { "flag": "mirror-asymmetric", "state": "not-evaluated", "reason": "trivial-group" },
    { "flag": "energy-created", "state": "clean", "created_J_max_window": 0.0 } ],
  "labels": ["law-sensitive"], "standing": "provisional",
  "cost": {"paired_episodes": 118, "gpu_s": 41.0} }
```

`evidence = { class: "Tested", tier, determinism, seed, identities }`. Exit 0 when every requested detector is
`clean`; exit 2 (completed with flags) when any is `flagged`, `undetermined` or `not-evaluated`; exit 8 when
accepted and still running; exit 3 or 4 on refusal. `next_actions` names, for a flag, the cheapest settling step
(for `tier-sensitive`: more referee pairs; for `rate-sensitive` with an unpinned model: pin controller rate and
rotor inertia).

**Flags on results.** A flag is a label of the result. Rules: labels propagate to every result computed from
the flagged one by the weakest-input rule (a ranking that contains a flagged result carries the flag; one that
contains an `energy-created` result is `model-conditional`); a result with any standing flag, or with a detector
`undetermined`, stays `provisional` and cannot be promoted to `established`; citing it as established is refused
by the label-misuse refusal of the fidelity chapter. A result on which `eval.detect` has not run carries
`detectors: not-run`, which is visible on every report and is not a clean bill.

**The gate.** GATE-CORTEX-04 (known answer, M3, TARGET): each detector flags its planted exploit and passes an
honest policy. Measured by running the verb on the ten exploits of N23b-07 and on the honest policies, on
`batch-cpu` and on each device tier that exists; recorded with the per-detector pairs, exceedances and states.

**Layout.** `crates/frob-learn/src/detect/verb.rs`; schemas under the verb registry; examples in the schema.

## Acceptance criteria

- [ ] `frob eval detect --result <id> --json` writes exactly one envelope with the schema above; the same call through MCP returns the same envelope.
- [ ] Seed done-condition: GATE-CORTEX-04 is recorded with measured values: for each of the ten detectors, its planted exploit is `flagged` and the honest policy is `clean` (or `not-evaluated` with a listed reason that the gate record names).
- [ ] The flag record persists on the result; a later `frob run show` and every report that cites the result print the labels; a ranking built from a flagged result carries the flag.
- [ ] A flagged or undetermined result cannot be promoted to `established`; the attempt is refused.
- [ ] Budget below 16 pairs per arm is refused at admission with nothing run; a D4 arm is refused.
- [ ] Cancellation is tested (request, drain at the kernel-batch boundary, finalize): no partial flag is written and no device resource leaks; idempotent replay returns the stored envelope.
- [ ] `CONTRACT.md` of `frob-learn` lists the verb, its evidence class and its limits; the verb is reachable through `frob --json` with a documented schema and exit codes.
- [ ] The gate record contains its negative controls: the ten exploits as registered controls, each caught in the same run.

## Test plan

### Unit tests

`cargo test -p frob-learn detect::verb`:
- `envelope_fields`: every detector entry has a state; `flagged` entries carry arm, pairs, exceedances and envelope hash; `not-evaluated` carries a reason.
- `exit_codes`: all clean → 0; one flagged → 2; one undetermined → 2; admission refusal → 3 or 4.
- `label_propagation`: a comparison result built from a flagged result lists the flag; a ranking containing an `energy-created` result is `model-conditional`.
- `not_run_is_visible`: a result never passed to the verb prints `detectors: not-run`.
- `promotion_blocked`: `eval.promote` on a flagged result is refused.
- `budget_admission`: a budget of 10 pairs per arm is refused before any episode runs (the job ledger shows zero world-steps).
- `subset_selection`: `--detectors dt-sensitive,energy-created` runs exactly those two.

### End-to-end script and logging

`scripts/e2e/eval_detect.sh` sources the helper of `STD-E2E` and writes newline-delimited JSON to
`target/e2e-logs/eval_detect/<utc>.ndjson` with a human-readable transcript beside it. Steps:
(1) the corpus self-check of N23b-07 (`cargo test -p frob-conformance cortex_exploits`);
(2) for each of the ten exploits: `frob eval run --task @fixture:<exploit> --policy @fixture:<exploit>-policy
--tier batch-cpu --seed 11 --json`, then `frob eval detect --result <id> --json`, asserting the expected flag;
(3) the same two commands for each honest policy, asserting no flag;
(4) `frob eval promote --result <flagged id> --json`, asserting the refusal;
(5) `frob eval detect` with `--sync-wait-ms 0` and a `frob job cancel`, asserting a clean cancellation;
(6) where devices exist, steps 2 and 3 on each device tier.
Every `cmd` event carries the exact command line, exit code, wall time and the envelope's evidence block (claim,
class, tier, determinism, identities, seed); `metric` events carry pairs, exceedances and the metric values with
units; `assert` events carry expected and observed flags; on failure the log gives the first detector that
disagreed with the fixture and the artifact paths to replay it. The final `summary` gives assertions passed and
failed and `gates: ["GATE-CORTEX-04"]`. A `--smoke` mode runs three exploits (`law`, `energy`, `leak`) and one
honest policy.

### Known answers and negative controls

- KA-592 (each detector flags its planted exploit and passes an honest policy; the honest policy is the control), KA-591 (the box-cone exploit is flagged `law-sensitive`; an honest policy on the circular cone is not), CX-258.
- Negative controls the gate must catch: the ten exploits; a planted verb build that reports `clean` for a detector it did not run must fail `not_run_is_visible`; a planted build that drops labels at the envelope must fail `label_propagation`.
- Metamorphic relations: permuting the order of `--detectors` leaves every state unchanged; running the verb twice with the same key returns the stored envelope; running it with a different seed set of the same size gives the same states on the corpus.
- Determinism lanes: the envelope is identical twice on one machine and across worker counts under a D2 profile; debug and release agree; across backends the states agree and any difference is reported with its first differing pair.

## Considerations

- RISK: policies exploit contact compliance and promotions keep failing. Early warnings are the promotion failure rate, the count of `energy-created` flags and the share of finalists typed `model-conditional`; this verb is where the first two are counted.
- Cost: a full pass is at most 32 pairs for each of about a dozen arms; typical clean passes use 16 per arm. The verb reports its cost so that a campaign can budget it.
- A detector that cannot run is not a pass; `not-evaluated` reasons are enumerated and reviewed at the milestone exit so that they do not become a way around the gate.
- The list of ten is closed for the gate; adding a detector adds a planted exploit and a control, and changes the gate row.
