## Background

FrankenRobotics keeps Python out of its core: the Rust `VecEnv` (the vectorized environment of crate
`frob-learn`) is the stepping authority (ADR-CORTEX-02). The program's central measurement, the ten-fold test,
compares the product with the strongest composed rival, and one confound in it is the learner: if only our
learner can drive our environment, an engine difference and a learner difference cannot be told apart. The
adapter removes that confound. `bindings/frob-gymnasium` is an optional annex outside the core workspace that
presents the widely used five-result step contract (`obs, reward, terminated, truncated, info`) and a vector
interface to Python learning stacks, so that rival stacks can drive this environment and the "learner-swap"
diagnostic (our engine with their learner) can be run. It contains no physics. The native worker steps; the core
never links an interpreter.

Decisions that bind it: explicit reset is the default and the final observation of every ended world is
preserved in every mode (ADR-CORTEX-01), because a masked automatic reset that returns post-reset observations
loses the observation a truncation bootstrap needs; termination (success, failure or an intrinsic mission
deadline) and truncation (an external collection limit) are different facts.

Tier: Frontier. It has a pre-funding pilot (N23b-11) and a kill gate: ✖ KILL-GYMADAPT fires if GATE-CORTEX-16
fails; fallback, rival stacks drive the environment through the job interface in whole rollouts and the ten-fold
test records the added latency in its phase ledger (N23b-14).

## Scope

In: the annex (a Rust shim and a Python package of at most about a thousand lines); the step contract; the
declared autoreset mapping with the final observation always in `info`; typed spaces; the default transport (one
charged copy per step across a process boundary); digest parity with native stepping; provenance and
admissibility labels; the reward-consumption record; clauses 1 and 2 of GATE-CORTEX-16.
Out: the zero-copy shared-device transport (N23b-12); an external PPO reaching the training threshold through
the adapter, which is clause 3 of the gate (N23b-13); the kill decision and the fallback path (N23b-14, N23b-13);
`VecEnv` itself (BD-192).

## Technical approach

**Layout (DESIGN).** `bindings/frob-gymnasium/shim/` is a Rust crate building the binary `frob-gym-worker`: it
hosts one `VecEnv`, owns every buffer and steps. `bindings/frob-gymnasium/python/frob_gymnasium/` is the Python
half: a class implementing the host library's vector-environment interface, a launcher for the worker, and
nothing else. Default binding (the fail-closed default of the open question on binding): across a process
boundary, with a local socket for control messages (length-prefixed canonical JSON: `spec`, `reset`, `step`,
`snapshot`, `close`) and shared array files for tensors, so that no interpreter is ever in a `frob` binary.

**Step protocol.** (1) The learner writes the action batch into the shared action array. (2) It sends `step
{seq}`. (3) The worker validates actions before any state changes (a non-finite action is FROB-REF-522 and the
batch is unchanged), steps `VecEnv`, copies `obs`, `reward`, `terminated`, `truncated` and the `info` arrays for
`seq` from device to the shared arrays (one copy per step, charged to the receipt: bytes and count), and replies
`done {seq, step_digest}`. (4) The Python half returns views of the shared arrays. A refusal travels as the full
refusal envelope and is raised as one exception type carrying it.

**`info` keys.** `final_obs` and `final_info` (for every world that ended at this step, in every mode);
`invalid` (numerical failure: a study error, not a transition); `needs_reset`; `applied_action` (after the
limiter and any shield); `dt_sim` (simulated duration of the interval, for physical discounting
γ(Δt) = exp(−β·Δt)); `sample_age` and `validity` per channel; `world_id`; `shield_events`.

**Autoreset is declared.** The constructor takes the host library's vector autoreset convention and the adapter
states the mapping in the run manifest. FACT about the host library, to be re-read at the pinned version in the
pilot: its vector API names three conventions, next-step, same-step and disabled.

| Host convention | Maps onto | `obs` of an ended world | `info["final_obs"]` |
|---|---|---|---|
| disabled | `explicit` | The final observation; the world stays ended until `reset` with a mask; stepping it is FROB-REF-521 | The final observation |
| same-step | `autoreset: masked` | The post-reset observation | The final observation |
| next-step | `explicit`, with the adapter resetting ended worlds at the start of the next `step` call and ignoring their submitted action, as that convention prescribes | The final observation at the ending step; the reset observation one call later | The final observation |

A mismatch that cannot be expressed as one of these modes is the pilot's falsifier.

**Spaces.** Observation and action spaces are box spaces built from the task's typed channels: shape, dtype and
bounds; per-channel metadata (channel id, unit, frame, representation, rate as a rational, access class) in the
environment's metadata; sample ages per step in `info`. Normalization is the versioned, invertible normalizer of
the checkpoint: the adapter exposes it and does not apply a second one; clipping is disclosed. Only channels of
access class `actor` appear in `obs`; `critic-only` channels are a separate, explicitly requested output.

**Parity.** The worker computes the same per-step state digests whoever drives it. An episode driven through
the adapter and the same episode driven natively (same seeds, same action sequence) have equal digest chains in
class D2 (bitwise per backend).

**Provenance and admissibility.** The driver reports `learner: {name, version, runtime, packages}`; it is stored
as untrusted provenance (marked as externally supplied text, never interpreted). Every result obtained through
the adapter is labelled `adapter-driven`: admissible to the rival arm of the ten-fold test and to the
learner-swap diagnostic, and refused as evidence for our method gates.

**Reward consumption (rule E-10).** The interface must return rewards to the learner. The adapter records
whether the *driven policy* consumed them: the driver declares its policy inputs, and a probe run perturbs the
delivered reward stream with training frozen and compares command digests. A run whose policy read a field that
the task does not declare as an `actor` channel is labelled `actor-read-undeclared` and cannot be cited for a
mission answer (the refusal "actor read a field outside its information contract").

**Gate clauses measured here.** GATE-CORTEX-16 (parity, M3, TARGET): (1) 10³ episodes driven through the adapter
and natively have equal digests in class D2; (2) the final observation is in `info` in every autoreset mode;
(3) an external PPO reaches the return threshold of the reference training gate through it (N23b-13).

## Acceptance criteria

- [ ] The annex builds in its own workspace; `xtask check-deps` shows no interpreter in any core binary, and the Python half is at most about 1,000 lines.
- [ ] The host library's environment checker passes against the adapter in each of the three autoreset conventions.
- [ ] Clause 1: 10³ episodes on the reference quadruped task driven through the adapter and natively have equal digest chains (D2), recorded with the count of mismatches (required: zero).
- [ ] Clause 2: in each convention the final observation of every ended world is in `info["final_obs"]` and equals the natively retrieved final observation bit for bit.
- [ ] A non-finite action raises the refusal exception with FROB-REF-522 and the state digest is unchanged; stepping an ended world in the disabled convention raises FROB-REF-521.
- [ ] Every result through the adapter carries `adapter-driven` and the untrusted learner provenance; the gate recorder refuses it for a Cortex method gate.
- [ ] The receipt of a run charges exactly one copy per step with its bytes.
- [ ] Seed done-condition: this bead supplies clauses 1 and 2 of GATE-CORTEX-16 with measured values; the gate row is completed by N23b-13 (clause 3) and KILL-GYMADAPT is decided on that record (first reading N23b-14, final reading N23b-13).
- [ ] `CONTRACT.md` of the annex states the mapping table, the labels, the transport and that the adapter contains no physics.

## Test plan

### Unit tests

Rust (`cargo test` in the annex): `step_protocol_roundtrip` (a `step` message with 64 worlds returns arrays of
the declared shapes and a digest); `action_checked_before_state` (a NaN in world 3, channel 2: FROB-REF-522,
equal digests before and after); `final_obs_all_modes` (a two-world fixture where world 0 truncates at step 5:
`info["final_obs"][0]` equals the native final observation in the three conventions; in same-step mode `obs[0]`
is the post-reset observation); `next_step_ignores_action` (the action submitted for a world being reset has no
effect on its digest); `one_copy_per_step` (100 steps charge 100 copies); `provenance_untrusted` (learner text
with markup is stored verbatim and marked). Python (`python -m pytest` in the annex): `checker_passes_<mode>`
(the host library's environment checker in each convention); `spaces_metadata` (units, bounds and channel ids
present); `refusal_exception_carries_envelope`.

### End-to-end script and logging

`scripts/e2e/gym_adapter_parity.sh` sources the helper of `STD-E2E` and writes newline-delimited JSON to
`target/e2e-logs/gym_adapter_parity/<utc>.ndjson` with a transcript. Steps: (1) `frob train export` of the
reference policy; (2) native runs: `frob sim run --task quad-flat-velocity --policy <p> --episodes 1000 --seed
5 --tier <tier> --json`, recording digest chains; (3) the same 1,000 episodes driven by a minimal Python driver
through the adapter, replaying the same policy; (4) digest comparison episode by episode; (5) for each autoreset
convention, a truncation fixture comparing `info["final_obs"]` with `frob run show`; (6) the two refusal cases.
`cmd` events carry the exact command, exit code, wall time and evidence block (claim, class, tier, determinism,
identities, seed); `metric` events carry mismatching episodes (threshold 0), copies per step (threshold 1) and
adapter overhead per step in microseconds; `assert` events carry digests, and on a mismatch the first differing
episode, step and digest with the artifact paths. The `summary` gives assertions passed and failed and `gates:
["GATE-CORTEX-16"]`. A `--smoke` mode uses 64 episodes.

### Known answers and negative controls

- KA-577 (the final observation has the same values in explicit mode and in `final_obs` under masked automatic reset; negative control: a mode that returns only post-reset observations fails the truncation fixture); KA-576 (bootstrap target 0 at a true deadline, 9.9 at an external cut with V = 10, γ = 0.99; a learner that sees one `done` flag gets 0 for both, so the adapter must deliver both flags).
- Negative controls: a planted adapter that drops `final_obs` in same-step mode; a planted adapter that merges `terminated` and `truncated`; a planted adapter that sanitizes NaN actions to zero; a planted adapter that steps physics in Python-side glue (digests diverge). Each must fail its assertion.
- Metamorphic relation: permuting worlds in the batch through the adapter permutes outputs and leaves each world's digest chain unchanged.
- Determinism lanes: parity holds twice on one machine and across worker counts on each backend (D2); across backends the comparison is native against adapter on the same backend only.

## Considerations

- OPEN (owner of the program): whether the adapter ships as a supported, published binding or exists only as the rival's access path. Default: built and gated for the ten-fold test and for conformance only; not a supported public surface.
- OPEN (Cortex lead): binding in process or across a process boundary. Default as built here: across a process boundary with shared array files. The transport question (shared device views or one copy per step) is decided in N23b-27.
- The adapter is the one place where the plan's non-goal "no general Python API" is narrowed; it must not grow verbs, design authoring or physics.
- Security: the worker treats every message from the Python side as untrusted input (length limits, schema check); the learner's self-reported identity is data.
- If the kill gate fires, this annex is not shipped; the rival drives whole rollouts through the job interface.
