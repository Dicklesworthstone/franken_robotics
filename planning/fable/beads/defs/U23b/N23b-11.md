## Background

Every Frontier mechanism of FrankenRobotics has a paper-scale pilot with a falsifier that runs with existing
tools, outside the workspace, before its work package is funded. This is the pilot for the Gymnasium-compatible
adapter (BD-301): an optional annex that lets Python learning stacks drive the Rust vectorized environment
through the five-result step contract, so that rival stacks can train in this environment in the ten-fold test.

The risk the pilot tests is semantic, not speed. This project's environment rules differ on purpose from common
practice: explicit reset is the default; the final observation of every ended world is preserved in every mode;
termination and truncation are different facts; invalid physics is a study error and not a transition; actions
are checked before state changes. The host library has its own conventions for vector environments, including
several automatic-reset conventions. If our rules cannot be presented through the host interface as declared
modes, the adapter would have to lie in one direction or the other, and it must not be built.

Pilot row, as planned: the host library's environment checker against a stub that implements rules E-1 to E-5.
Falsifier: any semantic mismatch that cannot be declared as a mode. Ceiling: none on speed; it removes one
confound from the ten-fold test. Cost: about two engineer-days.

## Scope

In: a stub environment in Python implementing E-1 to E-5 on a trivial dynamics (no physics from this project);
the host library's checker and a hand-written mismatch probe; the record.
Out: the adapter (BD-301); transport and performance (N23b-12, N23b-27); any code in the workspace.

## Technical approach

**The rules the stub implements.**

- E-1 Explicit reset: a world with `needs_reset` stays ended until the caller resets it; stepping it is refused.
- E-2 The final observation is preserved: in explicit mode `obs` of an ended world is its final observation; in
  the labelled masked-autoreset mode the world is reset inside the step, `final_obs` carries the final
  observation and `obs` the post-reset one.
- E-3 Termination and truncation are different facts; if both are set, termination controls the bootstrap.
- E-4 Invalid physics is a study error: an `invalid` mask, weight zero in updates, kept in failure counts.
- E-5 Actions are checked before state changes: a non-finite action is refused before any state mutates.

**Stub.** A vector of N = 8 independent scalar integrators with a step counter: x ← x + a, terminated when
abs(x) > 3, truncated at 20 steps, one world made `invalid` on request. About 150 lines of Python, written for
the pilot and discarded afterwards.

**Protocol (frozen in the record before execution).**

1. Pin the host library at the revision the rival arms will use.
2. For each of the host's vector automatic-reset conventions (FACT to confirm at the pin: three are documented,
   next-step, same-step and disabled), wrap the stub so that it presents that convention, mapping onto `explicit`
   or `autoreset: masked`, and always placing the final observation in `info`.
3. Run the host library's environment checker on each wrapped stub.
4. Run the mismatch probe: a scripted action sequence that drives world 0 to termination at step 4, world 1 to
   truncation at step 20, both flags at once in world 2, a NaN action in world 3 and an invalid state in world
   4, and compares what a host-side learner would compute with what the rules require:
   - bootstrap target at world 1's truncation uses the final observation (with V = 10, γ = 0.99 the target is
     9.9) and at world 0's termination is 0;
   - world 2 bootstraps as terminated;
   - world 3's step raises before any world changed;
   - world 4 has weight zero and is counted.
5. List every place where the host interface cannot carry a rule (for example: no standard key for `invalid`;
   a checker assumption that an ended world may be stepped), and for each decide: expressible as a declared mode
   or an `info` key (not a mismatch), or not expressible (a mismatch).

**Falsifier.** Any semantic mismatch that cannot be declared as a mode. One is enough.

**Record.** Mechanism and tier; the protocol; the host pin; the checker's output per convention; the probe
table; the list of non-standard keys the adapter will need (`final_obs`, `invalid`, `needs_reset`,
`applied_action`, `dt_sim`, `sample_age`); the result `falsified` or `not-falsified`; fallback: whole rollouts
through the job interface (KILL-GYMADAPT).

## Acceptance criteria

- [ ] The record is in the pilot register with the protocol hashed before execution and the host pin named.
- [ ] The checker's result is recorded for every host convention at the pin, with the full output attached.
- [ ] The probe table shows the required values (0, 9.9, termination wins, refusal before mutation, weight zero) for each convention, or names the convention in which a value cannot be delivered.
- [ ] Every divergence between the host's assumptions and rules E-1 to E-5 is listed with its classification and the reason.
- [ ] The falsifier outcome is on file; if it held, the fallback is named and N23b-14 is notified through the record.
- [ ] Nothing in the workspace other than the register entry changed.

## Test plan

### Unit tests

`cargo test -p frob-conformance pilots_registry`: `pilot_gym_adapter_schema` (required fields present);
`pilot_protocol_hash_frozen`; `falsifier_reading` (a synthetic probe table with one unclassifiable divergence →
`falsified`; with all divergences classified as modes → `not-falsified`).

### End-to-end script and logging

`tools/pilots/cortex_gym_adapter/run.sh` (development-time, outside the product; it sources the logging helper of
`STD-E2E` for the standard log form). It creates an isolated environment with the pinned host library, runs the
checker per convention and the probe, and writes newline-delimited JSON to
`target/e2e-logs/pilot_cortex_gym_adapter/<utc>.ndjson` with a transcript: `cmd` events with exact commands, exit
codes and wall times; `assert` events for each probe value (expected 0, 9.9, and so on, observed value); a
`summary` with assertions passed and failed and `gates: []`. It ends by validating the register entry.

### Known answers and negative controls

- Known answers: the bootstrap pair 0 and 9.9 (V = 10, γ = 0.99); termination wins when both flags are set.
- Negative control: a second stub that returns only post-reset observations and no `final_obs` must fail the truncation row (the probe is able to see the defect it exists to find).
- Negative control: a stub that merges both flags into one `done` must give 0 at the truncation row.
- The pilot is deterministic: a second run reproduces the probe table exactly.

## Considerations

- The host library's conventions have changed between its releases; the pilot's result is valid for the pin only, and a pin move repeats the pilot (two engineer-days).
- A checker failure is not automatically a mismatch: a checker may assume behaviour our rules deliberately refuse. The classification step is the substance of the pilot.
- The pilot uses no simulator, so it says nothing about performance or transport; those questions are separate (N23b-27).
