## Background

The Gymnasium-compatible adapter (BD-301) lets Python learning stacks drive the Rust vectorized environment.
Its default transport makes one copy per step from device to shared host arrays, charged to the run's receipt.
Where the host stack runs on the same device, tensors can instead cross as *device-resident views*: the learner
reads observations where the simulator wrote them and no copy is made. The plan allows this under two
conditions: the stride conversion applies, and otherwise one copy per step is made and charged.

The stride conversion is the trap. FACT (to be re-run at admission): the pinned FrankenNumPy uses signed byte
strides and the pinned FrankenTorch uses unsigned element strides. A contiguous 2 × 2 `f32` view has strides
(8, 4) in the first convention and (2, 1) in the second. Copying the numbers verbatim into a view on a 16-element
buffer reads element 12 at index [1, 1] where element 3 belongs, and both reads are in bounds, so nothing faults.
A view with byte origin 4 and strides (8, −4) indexes elements (1, 0, 3, 2) and has no unsigned form. A device
array interface consumed by a Python stack has its own convention again. One typed converter at one boundary is
the rule; a view the receiver cannot represent is materialized with a charged copy, or refused under a zero-copy
contract (FROB-REF-547).

Tier: Frontier, optional. Whether it is built at all is the open question on the adapter's transport (N23b-27):
the fail-closed default is one charged copy per step.

## Scope

In: export of `obs`, `reward`, flag and `info` tensors as device views to a host stack on the same device;
import of the action tensor from a device view; the conversion to the host stack's array-interface convention;
leases and epochs across the boundary; the fallback to a charged copy; the zero-copy refusal.
Out: the default copying transport (BD-301); `TensorView` and the converter between the two sibling conventions
(BD-193, BD-036); cross-device or cross-machine transport (not offered).

## Technical approach

**View descriptor across the boundary (DESIGN).** For each exported tensor the worker sends: device identity,
allocation handle, dtype, extents, logical origin in elements, signed strides in elements, ownership epoch and
intended access (`read` for outputs, `write` for actions). The Python half builds the host stack's device array
object from it through the stack's documented zero-copy import protocol. Strides are converted by the typed
converter: elements → bytes by multiplying by the dtype size with sign kept; a negative stride or a non-zero
origin that the receiving protocol cannot express is *unrepresentable*.

**Rules.**

1. *One conversion boundary.* No bare stride tuple crosses; the descriptor type carries its convention.
2. *Unrepresentable views.* Under the default contract the worker materializes a contiguous copy on the device
   and exports that; the copy is charged to the receipt (bytes, count). Under `--zero-copy` the step is refused
   with FROB-REF-547 (repairs: allow one charged copy; change the layout).
3. *Leases.* A host read of a device buffer is valid only after the command buffer of its epoch has completed.
   The descriptor carries the epoch; the Python half must present the epoch when it signals `step`, and a read
   or a `step` with a stale epoch is refused. Outputs are double-buffered (two ring slots) so that the learner
   may hold step t's observations while step t + 1 is computed; holding older views is a stale-epoch error.
4. *Actions.* The learner writes actions into a device buffer the worker owns; the worker reads it only after
   the learner's `step` message, validates finiteness on the device before any state changes (FROB-REF-522), and
   never reads a buffer whose epoch the learner still holds for writing.
5. *Masks.* Padding worlds and padded degrees of freedom are masked in the exported views as they are in
   kernels: the exported shapes are the logical shapes, never the padded capacities.
6. *Parity.* Digest parity with native stepping holds unchanged (class D2): the transport moves no physics.

**Fallback and receipts.** Any failure to establish a shared view (different device, unsupported protocol
version, export refused by the backend) falls back to the default transport of BD-301 and records
`transport: copy` with the reason; it is never silent. The receipt of every run states `transport`,
`copies_charged` and bytes.

**Layout.** `bindings/frob-gymnasium/shim/src/device_view.rs` and one Python module.

## Acceptance criteria

- [ ] Built only if N23b-27 decided for shared device views; otherwise closed with "default transport in force".
- [ ] With a host stack on the same device, a run reports `transport: device-view` and `copies_charged: 0` for representable views.
- [ ] The stride known answers hold through the boundary: the contiguous 2 × 2 `f32` case reads element 3 at [1, 1]; the negative-stride view is materialized (charged) by default and refused with FROB-REF-547 under `--zero-copy`.
- [ ] A stale-epoch read or step is refused; the double-buffered slots allow holding exactly one previous step.
- [ ] Digest parity with native stepping holds over 10³ episodes with the device-view transport (D2).
- [ ] A non-finite action written to the device buffer is refused before any state changes.
- [ ] Fallback to copying is logged with its reason on the receipt.

## Test plan

### Unit tests

Rust (annex): `descriptor_conversion_contiguous` (element strides (2, 1) → byte strides (8, 4) for `f32`);
`descriptor_unrepresentable_negative` (origin 1 element, strides (2, −1): unrepresentable → materialize or 547);
`verbatim_copy_is_wrong` (the planted converter that copies numbers reads element 12, and the test detects it);
`epoch_stale_refused`; `two_slot_ring` (views of steps t and t − 1 valid, t − 2 refused); `masks_logical_shape`
(exported extents equal logical extents with padding excluded). Python (annex): `device_view_roundtrip` (the
imported array aliases the worker's buffer: a worker-side write is visible without a copy);
`fallback_recorded`.

### End-to-end script and logging

`scripts/e2e/gym_adapter_device_view.sh` (helper of `STD-E2E`; newline-delimited JSON at
`target/e2e-logs/gym_adapter_device_view/<utc>.ndjson` and a transcript). It runs the parity procedure of BD-301
with `--transport device-view` on a CUDA device, then with a planted layout that yields a negative-stride view
under both contracts, then with the learner on another device to force the fallback. `cmd` events carry the
exact command, exit code, wall time and evidence block; `metric` events carry `copies_charged` (threshold 0 for
the first run), bytes and adapter overhead per step; `assert` events carry digests and refusal codes with the
first differing value on failure. `summary`: assertions passed and failed, `gates: []`. On a machine without the
device the script logs `skipped: capability absent` and exits zero with that reason in the summary.

### Known answers and negative controls

- KA-580 (stride conversion: [1, 1] reads element 3; the negative-stride view indexes (1, 0, 3, 2) and is materialized or refused; negative control: a verbatim copy of the stride numbers onto a 16-element buffer reads element 12, in bounds); CX-255.
- Negative controls: the verbatim-copy converter; a planted adapter that reads the action buffer before the learner's `step` message (a torn action batch must be detected by the epoch check); a planted fallback that copies without charging.
- Property (PO-CORTEX-05 at this boundary): conversion round-trips or refuses, exhaustively over two- and three-dimensional views with element strides in −2 … 2.
- Determinism lanes: parity twice on one machine and across worker counts on the device (D2).

## Considerations

- The gain is throughput for the rival's learner, which helps the rival arm of the ten-fold test; that is the purpose, and it is why the default (a charged copy) is acceptable if this is never built.
- Sharing device memory across processes couples the two processes' lifetimes: a crashed learner must not leave the worker's buffers leased. The worker reclaims leases on disconnect.
- Security: the worker never maps memory the learner allocated; the learner only receives handles to worker-owned buffers.
