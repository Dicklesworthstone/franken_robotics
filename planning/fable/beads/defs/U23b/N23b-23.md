## Background

✖ KILL-ALTALGO: for any one of the other learning algorithms (SAC, TD3, evolution strategies, privileged
teacher and student, adaptive randomization, asynchronous sharding), its pilot's falsifier holds. Fallback,
named in advance: that algorithm is not built; PPO under its rule battery remains the trainer. Decided at M4 at
the earliest, per algorithm, before funding.

The pilots (BD-324) run each algorithm against PPO on the reference quadruped task at equal wall-clock on an
incumbent stack with three seeds; the falsifier is that the arm beats PPO neither in time to the threshold nor
in final requirement pass rate. This bead reads the six pilot records and records six decisions. A kill gate is
written before the data exists so that an algorithm which does not pay is removed by rule; "no algorithm is
built without a passed pilot" is part of the seed condition this decision enforces.

## Scope

In: six readings, six decision records, the funding consequences, and the dependency rule for build beads.
Out: running pilots (BD-324); building anything.

## Technical approach

1. **Inputs.** For each algorithm, its pilot record: per-seed looks, time to threshold (attained or censored),
   final requirement pass rate, the ceiling from training's share of the design loop, the A/A and potency
   control outcomes, and the outcome `falsified`, `not-falsified` or `undetermined`.
2. **Rule, per algorithm.**
   - `falsified` → the kill gate fires for this algorithm. Its build bead is closed with the reason; the
     registry's capability list never shows it; PPO remains the trainer.
   - `not-falsified` → the algorithm may be funded. Funding is still subject to its ceiling: where the recorded
     ceiling is below 1.1 (training is a small share of the loop), the decision records "passed pilot, not
     funded: ceiling" and the algorithm is deferred, not killed.
   - `undetermined` → not funded. A repeat needs a new frozen protocol and more seeds.
3. **Record.** One architecture decision record with a row per algorithm: trigger; pilot record hash; the two
   measured comparisons (time to threshold, final pass rate) against the control arm; the ceiling; the branch;
   the session, which differs from the session that ran the pilots. The gate row in `registries/gates.toml`
   holds the per-algorithm status in its `measured` field (`killed: SAC, TD3; open: adaptive randomization; …`).
4. **Dependency rule.** Every build bead of one of the six algorithms depends on this bead and checks its row
   at start: a bead whose row is not "funded" does not start. For adaptive randomization that bead is N23b-04.
5. **What changes downstream when an algorithm is killed.** `train.start --algo <name>` answers the capability
   refusal for that name; documentation and the capability list omit it; for asynchronous sharding, the
   labelled nondeterministic training profile loses its main use and remains only for the learner's relaxed
   reductions; for evolution strategies, controller gains of the baseline rung are tuned by the optimizers of
   the optimization chapter directly, outside Cortex.

## Acceptance criteria

- [ ] Six decisions are recorded, each citing its pilot record by hash and stating both comparisons and the ceiling.
- [ ] For each killed algorithm, `registries/gates.toml` records it under KILL-ALTALGO and its build bead is closed with the kill reason.
- [ ] No build bead of an algorithm whose row is not "funded" can start (checked by the dependency rule and by a test on the capability registry).
- [ ] An `undetermined` pilot never leads to funding.
- [ ] The recording session differs from the pilots' session.

## Test plan

### Unit tests

`cargo test -p frob-conformance kill_gates`: `altalgo_six_rows` (the record has one row per algorithm);
`altalgo_branches` (synthetic pilot outcomes map to `killed`, `funded`, `passed pilot, not funded: ceiling`,
`not funded: undetermined`); `altalgo_capability_refusal` (with SAC killed, the verb registry's `train.start`
schema rejects `--algo sac` with the capability refusal, exit 5); `altalgo_self_recording_refused`.

### End-to-end script and logging

Checked by `scripts/e2e/kill_gate_records.sh` (the shared check of the Cortex kill-gate decisions; helper of
`STD-E2E`; log under `target/e2e-logs/kill_gate_records/`): for KILL-ALTALGO it asserts that each algorithm's
status in the gate row agrees with the decision record, that the six pilot hashes resolve, and that `frob train
start --algo <killed> --json` returns exit 5 with the capability refusal. Each assertion is one `assert` event
with expected and observed values; the `summary` names KILL-ALTALGO.

### Known answers and negative controls

- Negative control: a planted pilot record in which the arm is slower and has a lower pass rate must yield `killed`; a decision of `funded` on it fails the test.
- Negative control: a planted record whose A/A control "beat" PPO must yield `undetermined`.
- Ceiling arithmetic: a training share of 0.2 and a two-times faster trainer give at most 1/(1 − 0.1) = 1.11; at share 0.1, 1.05, which is below 1.1 and gives "not funded: ceiling".

## Considerations

- The "ceiling below 1.1" deferral is this bead's reading of the rule that a test whose ceiling is below its goal confirms nothing; it prevents funding an algorithm that passed its pilot but cannot move the loop.
- The decisions are independent: killing SAC says nothing about TD3.
- If the incumbent phase ledger is revised, ceilings are recomputed and deferred algorithms may be reconsidered without a new pilot; killed ones may not.
