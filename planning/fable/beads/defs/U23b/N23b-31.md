## Background

The vectorized environment of FrankenRobotics already types observation channels by access class (rule E-8:
`actor`, `critic-only` or `evaluation-only`; the actor schema is frozen and run with the other channels absent)
and tests causality (rule E-9: histories with identical delivered observations, past actions and policy random
draws up to a decision instant yield the same command). Both rules speak about observation channels. An online
actor can read more than observations: a step also returns a reward, termination and truncation flags, action
masks and an `info` structure.

A reward is a function of state, and delivered to the actor it is a sensor. Smallest case, on the docking model
(three one-second ticks, hidden gain g ∈ {1, 2}, acceleration g·u): with first command u₀ = ¼ the position
after one tick is x₁ = g/8, so a shaped reward −abs(1 − x₁) is −7/8 under g = 1 and −3/4 under g = 2. When the
velocity packet arrives late, no causal policy docks in both worlds. If the wrapper hands that reward to the
actor before the second command, the two worlds are distinguished and the commands (¼, ½, −¾) and (¼, 0, −¼)
dock both. An exclusion computed without reward visibility in its contract is then false for the environment
that was run.

Rule E-10: the actor's information contract lists every value an online actor can read at a decision instant,
with its delivery instant under the clock contract: observation channels, earlier rewards, termination and
truncation flags, action masks, and each field of `info`. Outputs of the trainer and of the scorer are outside
the actor's view unless the mission declares them delivered.

Tier: Solid. Owners: `frob-learn` (types), `frob-sense` (the test, N23b-32), `frob-spec` (the declaration).

## Scope

In: the contract type; access classes and delivery instants on every step output; the typed projection
`ActorView`; defaults; the contract digest and where it enters; enforcement at policy inference; the label and
refusal for an undeclared read.
Out: the planted leaks, the docking known answer and the gate (N23b-32); observation-channel access classes
themselves (BD-192); the adapter's reward-consumption record (BD-301 uses this type).

## Technical approach

**Types (DESIGN sketch).**

```rust
pub enum AccessClass { Actor, CriticOnly, EvaluationOnly, TrainerOnly }
pub struct FieldContract { field: FieldId, class: AccessClass, delivery: DeliveryRule }
/// When a value produced by control interval t becomes readable: an instant of the clock contract plus a lag.
pub struct DeliveryRule { instant: ClockInstant, lag: RationalDuration }
pub struct InfoContract { fields: Vec<FieldContract> }           // every observation channel and every other
                                                                // step output: reward, terminated, truncated,
                                                                // each action mask, each `info` field
impl InfoContract { pub fn digest(&self) -> ContractDigest }     // canonical bytes: field ids, classes, rules
pub struct ActorView<'a> { /* only fields with class Actor whose delivery instant is at or before the
                              decision instant; constructed by projection, no public constructor */ }
impl<'a> StepView<'a> { pub fn actor_view(&self, c: &InfoContract, at: DecisionInstant) -> ActorView<'a> }
```

**Defaults (fail closed).** Observation channels keep their declared class. The default class of `reward` and
of every `info` field is `TrainerOnly`. `terminated` and `truncated` default to `TrainerOnly` (the runtime
resets recurrent state for ended worlds; the policy does not need the flag). An action mask must be declared;
when declared `Actor` it names the delivered channels it is computed from. A recurrent policy that takes the
previous reward as an input requires the task to declare reward as an `Actor` channel with its delivery rule.
An undeclared field is not readable by anyone but the trainer.

**The projection is the only path to the actor.** Policy inference (the on-device forward kernel's input
gather and the CPU path) is given an `ActorView`, never a `StepView`. Fields of other classes are physically
absent from the actor's input buffers, not zeroed. A field whose delivery instant is after the decision instant
is absent from the view built for that decision, whatever its class. The critic's view adds `CriticOnly`
fields; the evaluator's adds `EvaluationOnly`.

**The digest.** `ContractDigest` is BLAKE3 over the canonical serialization of the sorted field list with
classes and delivery rules. It is part of the `TaskId` (so two tasks that differ only in whether the reward is
delivered to the actor are different tasks), of every memo key that keys an answer about what policies can do,
and of every certificate's assumption set (assumptions form a lattice; a verdict proved under one information
contract is not reused under a larger one without a recorded implication). A cached answer is therefore not
reused under a different contract.

**Undeclared reads.** For native policies an undeclared read is impossible by construction (the projection).
For externally driven policies (the adapter, where the interface must hand rewards to the learner) the run
records whether the driven policy consumed any field outside the contract; such a run is labelled
`actor-read-undeclared` and cannot be cited for a mission answer: the attempt is refused ("actor read a field
outside its information contract"; repairs: declare the field as an `actor` channel with its delivery instant,
which changes the task identity; or remove the read).

**Manifest.** The policy manifest's `observation_schema` gains the contract digest; loading a policy into a
task whose contract digest differs is refused as a schema mismatch.

**Layout.** `crates/frob-learn/src/env/actor_view.rs`; declaration schema in `frob-spec`'s task file; the
digest in `frob-core` identities.

## Acceptance criteria

- [ ] `ActorView` has no public constructor other than the projection; policy inference on CPU and devices accepts only `ActorView`.
- [ ] With defaults, the actor's input buffers contain no reward, flag, mask or `info` field; a test inspects the gathered buffer layout.
- [ ] Declaring reward as an `Actor` channel changes the contract digest and the `TaskId`; a memo entry or certificate produced under the old contract is not served under the new one.
- [ ] A field whose delivery instant is after the decision instant is absent from that decision's view.
- [ ] A recurrent policy configured to read the previous reward fails task admission unless the task declares reward as an `Actor` channel.
- [ ] A run labelled `actor-read-undeclared` is refused as a mission answer with the stated repairs.
- [ ] The causal test and the planted leaks of N23b-32 run against this type (its part of GATE-CORTEX-19).
- [ ] `CONTRACT.md` of `frob-learn` states rule E-10, the four classes, the defaults and the digest's three uses.

## Test plan

### Unit tests

`cargo test -p frob-learn env::actor_view`:
- `defaults_trainer_only`: a task with no declarations: reward, both flags and every `info` field are `TrainerOnly`.
- `projection_excludes_classes`: a `StepView` with fields of all four classes projects to exactly the `Actor` ones.
- `projection_respects_delivery`: reward of interval t with a delivery lag of one control interval is absent at decision t + 1's start if the lag has not elapsed, present afterwards.
- `digest_changes_with_class`: the same task with reward `TrainerOnly` and `Actor` has different contract digests and different `TaskId`s.
- `digest_order_independent`: permuting the declaration order leaves the digest unchanged.
- `memo_not_reused_across_contracts`: a cached answer keyed under digest A is a miss under digest B.
- `recurrent_prev_reward_requires_declaration`.
- `absent_not_zeroed`: the actor input buffer's length excludes non-actor fields (a zeroed field would keep the length).
- `mask_needs_sources`: an `Actor` action mask without declared source channels fails task admission.
- Property (PO-CORTEX-04): for random tasks and random values of non-actor fields, the actor's output is bit-identical.

### End-to-end script and logging

Covered by `scripts/e2e/actor_contract.sh` of N23b-32, which drives `frob sense causal-test`, `frob task show`
(to print the contract and its digest) and the docking known answer, with the standard structured log. This
bead adds no script of its own.

### Known answers and negative controls

- The docking arithmetic: u₀ = ¼, x₁ = g/8; reward −7/8 for g = 1 and −3/4 for g = 2; witness commands (¼, ½, −¾) and (¼, 0, −¼), both reaching (x₃, v₃) = (1, 0) by x₃ = g·(5u₀/2 + 3u₁/2 + u₂/2) and v₃ = g·(u₀ + u₁ + u₂).
- Negative controls: a planted inference path that takes `StepView` (must fail to compile, checked by a compile-fail test); a planted projection that zeroes instead of removing; a planted `TaskId` that omits the contract digest (must fail `digest_changes_with_class` and `memo_not_reused_across_contracts`).
- Determinism: the digest is exact (class D0) and identical on every platform; the projection moves no arithmetic.

## Considerations

- The contract makes "what could the policy know?" a typed, hashed object; every exclusion, alias witness and certificate about policies is bound to it, which is the general rule that a verdict is bound to its declared information.
- Making reward an actor channel is legitimate (some recurrent methods use it); the rule is that the task says so and the identity changes.
- Flags defaulting to `TrainerOnly` is this bead's fail-closed reading; the plan states the default only for reward and `info` fields.
- External learners see everything the interface returns; only the probe of N23b-32 and the declaration can tell what their policy consumed, and the label is conservative.
