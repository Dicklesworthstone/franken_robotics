## Background

A **family policy** is one set of weights that acts on one token per link of any design in a morphology
class; its network is the plain morphology transformer (link and contact tokens from the typed design term,
attention with a tree-distance bias). Construction C-24 is a Moonshot variant: each link token carries
**multivector features** in projective geometric algebra (the algebra in which points, lines, planes and
rigid motions are multivectors, provided by the sibling library `fs-ga`; a *motor* is the multivector of a
rigid motion, a *bivector* represents a line such as a joint axis with its position), and the layers are
equivariant by construction under relabelling and under the rigid motions that preserve gravity (rotations
about the vertical, translations, reflections through vertical planes). If it worked, invariance to
heading and to description conventions would come from the architecture instead of from augmentation.

The honest prior is that it does not pay. FACT (source register; to be re-read before a gate cites it): no
published policy of this kind exists for multi-embodiment locomotion; a pure geometric-algebra network
inside a control loop converged very slowly; such layers ran 1.4 to 7.5 times slower per epoch; fixed tree
message passing has lost to plain transformers; heading normalization with augmentation recovers most of
the benefit. The ceiling stated in advance is 0 to 1.3 times on an amortized pretraining run. The
experiment that decides it has three arms: A, the plain transformer with heading normalization and
convention augmentation (the control and the fallback); B, A with a geometric-algebra encoder and decoder
only; C, full geometric-algebra message passing on the tree.

The epic for the work at scale (BD-439) is a container; the specification bead states the mathematics and
its law suite; the pilot and the first reading of the kill gate decide funding. No task bead builds arms B
and C in the workspace, so the comparison that measures the gate has nothing to compare. This bead builds
them, in the smallest form the comparison needs. It exists only on the funded branch.

## Technical approach

**1. Group and actions.** G = { x ↦ A·x + t : A orthogonal, A·e_z = e_z }, e_z the vertical. Positions map
by A·x + t; polar vectors (linear velocity, force, linear momentum) by A; axial vectors (angular velocity,
torque, angular momentum) by det(A)·A; a twist or wrench at the origin by diag(det(A)·A, A) on (angular,
linear) followed by the shift of origin; a motor and a joint line by conjugation with the motor or
reflection versor of (A, t). Gravity g·(−e_z) is fixed by G and is supplied as a constant feature, so a
rotation about a horizontal axis is **not** a symmetry and the network can tell up from sideways.

**2. Token (DESIGN; `crates/frob-learn/src/ga/token.rs`, feature `moonshot-ga-policy`, off by default).**

```rust
pub struct MvToken { pub motor: Motor,            // link frame relative to the base frame
                     pub joint_line: Bivector,    // joint axis with its position; zero for the base
                     pub momentum: Wrench6,       // (angular, linear) of the link
                     pub wrench: Wrench6,         // net joint wrench estimate from proprioception
                     pub scalars: [f32; K_S],     // G-invariant scalars: mass ratio, length ratios, limits, phase
                     pub parent: u16 }
```

Built from the same typed design term and state the plain tokens use, so that the three arms see the same
information. Quantities are made dimensionless by the class's reference length, mass and time before they
enter a multivector, as for the plain tokens.

**3. Allowed operations (the only ones a layer may use).** (1) Linear maps that commute with the action of
G on multivector grades: geometric products with G-invariant multivectors, grade projections, the join with
the vertical; (2) nonlinearities applied to G-invariant scalars only (norms, inner products, vertical
components), whose result scales the equivariant features; (3) aggregation over children by a
permutation-invariant sum in a canonical order; (4) no positional encoding by token index: tree structure
enters only through parent and child relations.

**4. Arm B.** Encoder: `MvToken` → invariant and equivariant channels by two layers of the allowed
operations; the invariant channels (and the equivariant ones expressed in the heading-normalized base
frame) feed the **unmodified** plain transformer of arm A; decoder: the transformer's per-link outputs
scale equivariant features to give joint-space actions. Arm A's parameter digest must be unchanged for the
shared trunk configuration.

**5. Arm C.** Message passing in the order of the tree recursions of the dynamics: an outward pass from
base to leaves, then an inward pass from leaves to base, each a layer of the allowed operations, repeated
L times (DESIGN default L = 4); a per-link decoder as in arm B. No attention across non-adjacent links.

**6. Surface.** `frob train family --arch plain | ga-encoder | ga-tree …` (the architecture option of
`train.family`; `plain` is arm A and the default). The `train.family` row lists `--arch` and the smoke run's
`--worlds`, `--backend`, `--steps` and `--seed` (spelled as on `train.start`) from M8 under "Extended by:
N23bx-01"; this bead builds them. A policy from arm B or C carries `group.tying` in its
`frob.policy/1` manifest naming the continuous group G, the label Moonshot, and is evaluated like any
policy under a class D2 profile. Without the feature the two options are refused with the capability
refusal FROB-REF-724 (the verb option is not implemented in this build; exit 5), and after KILL-GATREE fires
the same refusal names the kill record and the fallback "the plain morphology transformer".

**7. Reference path and cost.** Host and `batch-cpu` implementation in `f32` with an `f64` reference for
the law tests. Per-step time and parameter count of each arm are recorded in the disclosure block; the
comparison is at equal wall-clock precisely because these layers are slower per step.

## Acceptance criteria

- [ ] The production types bind to the subject trait of the law suite and `cargo test -p frob-learn --features moonshot-ga-policy --test laws_c24` passes unchanged: every layer of arms B and C is equivariant under yaw, translation, vertical-plane reflection and relabelling, exactly in ℚ for rational elements on the reference weights and within 64 units in the last place in `f64`, and within 10⁻⁵ relative in `f32`.
- [ ] Gravity control: a rotation by 90 degrees about a horizontal axis changes the output with an equivariance residual of order one (at least 10⁶ times the round-off bound).
- [ ] With the `controls` feature every mutant of the suite fails on the production layers too: the all-rotations layer fails the gravity control; the polar-parity layer fails under a vertical-plane reflection.
- [ ] `arm_a_is_plain`: with `--arch plain` the parameter digest equals the plain transformer's for the same configuration; the trunk of arm B is that network.
- [ ] Re-description: relabelling links, changing the frame and axis-sign convention, and scaling by a power of two leave the actions of arms B and C unchanged to round-off on 1,000 random states of 20 designs.
- [ ] A default build compiles none of this; `--arch ga-tree` without the feature is refused.
- [ ] A smoke training of each arm (64 worlds, `batch-cpu`, fixed updates) runs, beats the zero-weight control by a margin declared in advance, and is repeatable with identical weight digests.
- [ ] `CONTRACT.md` of `frob-learn` records the group, the allowed operations and the Moonshot label.

## Test plan

### Unit tests
`crates/frob-learn/tests/laws_c24.rs` (the specification's suite, unchanged) and `crates/frob-learn/tests/ga_arms.rs`.
- `layer_equivariance_yaw`, `layer_equivariance_translation`, `layer_equivariance_vertical_reflection`, `layer_equivariance_relabel`: a random token set; the transformed input mapped through the layer equals the transformed output; yaw elements with rational sine and cosine such as (3/5, 4/5).
- `gravity_not_a_symmetry`: a rotation by 30 degrees about a horizontal axis changes the output by more than the round-off bound.
- `parity_of_axial_features`: under the mirror diag(1, −1, 1) the yaw-rate feature changes sign; a mirrored robot turning left is a robot turning right.
- `message_order_outward_then_inward`: a planted token at a leaf reaches the base only after the inward pass.
- `no_index_positional_encoding`: permuting token order with the tree relabelled leaves outputs permuted accordingly.
- `arm_a_is_plain`, `arm_b_trunk_digest_unchanged`.
- `tokens_carry_same_information`: every field of a plain token is recoverable from the multivector token and its scalars.

### End-to-end script and logging
`scripts/e2e/ga_arms_smoke.sh` (sources the STD-E2E helper; seed-explicit; idempotent; feature build):
1. `frob train family --class <reference class> --generator <reference generator> --split dev --task-family
   <reference family task> --arch ga-encoder --worlds 64 --backend batch-cpu --steps <n> --seed 2416 --approval
   <smoke envelope token> --key ga-tf-b-1 --json`, and the same for `ga-tree` (`ga-tf-c-1`) and `plain`
   (`ga-tf-a-1`); then each again with a second key (`ga-tf-<arm>-2`): assert identical weight digests per arm
   (two keys, so the second is a new run and not a stored receipt).
2. For each arm's policy and each of 20 designs and their re-descriptions (links relabelled, frame and
   axis-sign convention changed, scaled by a power of two): `frob policy apply <arm policy> --design <d>
   --task <reference family task> --seed 2416 --key ga-pa-<arm>-<i> --json`; assert the returns of B and C on
   a re-description equal those on the original within round-off.
3. A default build: `frob train family … --arch ga-tree --key ga-tf-off --json` exits 5 with FROB-REF-724.
Logged per STD-E2E: the exact command, exit code, wall time, evidence block with the Moonshot label and
`group.tying`, steps per second and parameter count per arm, weight digests of both runs, returns per design
pair with their difference against the round-off bound, the equivariance residuals, and on failure the first
layer and element that violate a law or the first design pair whose returns differ.

### Known answers and negative controls
- KA-131: for every layer and 100 seeded group elements of each kind (yaw, translation, vertical-plane reflection, relabelling), applying the element before the layer equals applying it after.
- CX-061 controls of the specification: a layer equivariant under all rotations; angular velocity treated as a polar vector.
- Re-description known answer: a policy that reads tokens in file order fails at the first exchange of two legs.
- Determinism: smoke runs twice with identical digests; debug and release; worker counts on `batch-cpu`.
