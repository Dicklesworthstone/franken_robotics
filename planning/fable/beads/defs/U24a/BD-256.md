## Background

The requirement language is only useful if the agents that drive the system can write correct requirements in it,
and can tell when they have not. FACT (source register): a 2023 language model translated natural-language
statements into temporal-logic formulas with 77.7% accuracy over 300 samples. That is the prior for a first draft:
about one in four wrong. The language's defence is admission by labelled examples and a mutation check (`task.check`
refuses a requirement whose labels disagree with its examples, FROB-REF-539, and reports atoms that no example can
distinguish).

GATE-ARENA-09 (claim: Design comparison; M3) measures both halves on an agent that has never seen the system:
on 50 scripted mission statements, each with a reference formula and 20 labelled trajectories the agent does not
see, at most 20% of first-draft requirements mislabel a trajectory, and `task.check` rejects every draft that does.

The second clause is the stronger one. A first-draft error rate is a property of the agent and the documentation;
it can be 15% or 30% depending on the model of the day. "Every wrong draft is rejected by the check" is a property
of this system: it says that an agent cannot end up scoring designs against a requirement that means something
else, because the admission step catches it. The gate is run by a fresh-context session, because a session that
implemented the language knows its idioms and would measure nothing.

## Scope

In: the test protocol; the harness that hands statements to the agent and collects first drafts; scoring against the
hidden trajectories; the comparison with `task.check`'s admission result; controls; the gate record.

Out: the corpus (N24a-32); the paper pilot that precedes funding (N24a-33); the language and its check (N24a-12 and
its dependencies); the MCP surface (BD-138) and the agent documentation.

## Technical approach

**1. Materials (frozen and hashed before the test).** From the corpus bead: 50 mission statements in plain language
with numbers and units; for each, a signal list (names, units, kinds, clocks) and a horizon; a *visible* admission
set of labelled example traces (at least two satisfying and two violating, with near-boundary cases, as the
admission rule requires); a *hidden* set of 20 labelled trajectories; and the reference formula that produced every
label. The agent sees the statement, the signal list and the visible examples. It never sees the reference formula
or the hidden trajectories, which live outside its namespace.

**2. The agent.** A fresh-context session with no access to this repository's source or planning documents, given
only the agent-facing documentation generated from the verb registry and the MCP tools of the task cluster. It works
through the released surface: `task.new`, `task.check`, `task.show`, `task.verdict`.

**3. Procedure, per statement.**

1. The harness opens a session, presents statement k with its signal list and visible examples, and asks for a
   requirement.
2. The agent's **first draft** is the first requirement it submits with `task.new`. The harness records it before
   any feedback (the draft's bytes and `TaskId`).
3. The harness evaluates the first draft on the 20 hidden trajectories with the offline evaluator (`task.verdict`
   with `--re-evaluate`, since the trajectories were recorded under the reference task). The draft
   **mislabels** if its verdict differs from the hidden label on at least one trajectory (an `undetermined` verdict
   on a hidden trajectory counts as a mislabel).
4. Independently, the harness runs `task.check` on the first draft with the visible examples and records whether
   it was admitted or refused, with the refusal code and report.
5. The agent may then iterate using `task.check`'s feedback until admitted or until a budget of 5 further attempts
   is spent; the final admitted requirement, if any, is scored on the hidden set too (reported, not gated).

**4. The two gate quantities.**

    m = number of statements whose first draft mislabels at least one hidden trajectory      (threshold: m ≤ 10 of 50)
    e = number of statements whose first draft mislabels and was nevertheless admitted by task.check   (threshold: e = 0)

Also reported: the number of correct drafts that `task.check` refused (false alarms, with their refusal reasons);
the mislabel rate of final admitted requirements; mislabels by operator class (always, eventually, until, dwell,
multi-stage, exact atoms, strict comparators); attempts per statement; and the tool-call transcript.

**5. Controls.**

- *Potency of the hidden sets.* For every statement, each of its planted wrong formulas (reversed comparator,
  missing dwell, eventually for always, window off by a factor, strict for non-strict) mislabels at least one hidden
  trajectory. Checked by the corpus bead and re-checked here before the agent runs.
- *Potency of the check.* The same planted wrong formulas, submitted through `task.check` with the visible
  examples, are refused. A planted wrong formula that is admitted is a failure of the gate regardless of what the
  agent does.
- *Negative control of the scorer.* The reference formula scores 20 of 20 on every statement.
- *Leak control.* The session's namespace contains no file whose digest matches a hidden trajectory or a reference
  formula; a planted attempt to read one is refused.

**6. Record.** The gate receipt carries m, e, the false-alarm count, the corpus hash, the agent identity (model and
build), the documentation build, the commit and the seeds. It is entered by a session that implemented neither the
language nor the corpus, with `cargo run -p frob-conformance --example record_gate -- --gate GATE-ARENA-09
--receipt <hash>`. Claim: Design comparison, class Tested, on a finite scripted suite: the result is a count
on these 50 statements and is not a population claim.

## Acceptance criteria

- [ ] GATE-ARENA-09 (the seed done-condition): m ≤ 10 of 50 first drafts mislabel a hidden trajectory, and e = 0:
      `task.check` rejects every draft that does (TARGET).
- [ ] The corpus hash predates the agent session in ledger order.
- [ ] All controls pass: every planted wrong formula mislabels a hidden trajectory and is refused by `task.check`;
      the reference formulas score 20 of 20; the leak control holds.
- [ ] First drafts are recorded before any feedback; the harness cannot be given a revised draft as a first draft.
- [ ] The receipt reports measured m, e and false alarms, by operator class.
- [ ] The test is run by a fresh-context session through the MCP surface, and its transcript is retained.

## Test plan

### Unit tests

- `mislabel_definition`: a draft that disagrees on 1 of 20 hidden trajectories counts once; `undetermined` on a
  hidden trajectory counts as a mislabel.
- `first_draft_is_first_submission`: the harness ignores later `task.new` calls for the first-draft record.
- `gate_arithmetic`: (m, e) = (10, 0) passes; (11, 0) fails; (3, 1) fails.
- `planted_wrong_formulas_caught`: for a three-statement fixture corpus, each planted mutant mislabels and is
  refused.
- `reference_scores_full`.
- `hidden_set_unreadable`: an attempt by the agent session to read a hidden trajectory's path is refused.

### End-to-end script and logging

`scripts/e2e/gate_arena_09_requirement_writing.sh`: starts `frob-mcp`, opens a session (`session.open`) in a jailed
namespace, iterates the 50 statements through the agent driver (the agent's own `task_new` and `task_check` tool
calls carry their idempotency keys through MCP), and for each first draft the harness calls `frob task check
<TaskId> --json` and (out of the agent's sight, under the harness scope) `frob task verdict <hidden trace> --task
<TaskId> --re-evaluate --json` on the 20 hidden trajectories (`--re-evaluate` because each hidden trajectory was
recorded under the reference task, so without it the call is refused `verdict-task-mismatch`; exit 0 or 2, both
expected, the verdict read from the envelope); then runs the control passes, submitting each planted wrong formula
with `frob task new <file> --key rw-<statement>-<mutant> --json` and `frob task check <TaskId> --json`. Idempotent per statement (resumable by statement index). NDJSON under
`target/e2e-logs/gate_arena_09_requirement_writing/` with, per statement: the command lines, exit codes, wall time,
the first draft's `TaskId`, hidden mislabel count (0 to 20), `task.check` result with refusal code, attempts used,
and the evidence block; a final `summary` with m against 10, e against 0, false alarms, and the gate name. Hidden
trajectories' contents are never logged, only their digests.

### Known answers and negative controls

- Hand case of the corpus (also a statement in it): "be inside the goal region x ∈ [4.9, 5.1] m and stopped, within
  10 s": the tempting draft `(F (0 s 10 s) in_goal)` is satisfied by a sled passing through at 1 m/s (inside for
  0.2 s); the reference requires a dwell, `(F (0 s 10 s) (H (0 s 2 s) in_goal))`, which the sled violates and a body
  at rest at x = 5 m from t = 6 s satisfies from t = 8 s.
- Negative control: a `task.check` build with the comparison of verdicts against the visible labels disabled (a
  planted defect behind a test-only feature) admits planted wrong formulas, so the potency-of-check control fails on
  it and the gate run refuses to record with that build. A build with the mutation check disabled is run as well;
  it fires only for a planted formula that agrees with every visible label and is refused for vacuity alone, so the
  receipt reports how many planted formulas each stage alone refused rather than requiring this second build to
  fail.
- Negative control: an agent session given the hidden trajectories must be detected by the leak control.
- Determinism: scoring is exact given the drafts; the agent's drafts are not deterministic, and the receipt records
  the agent build and the transcript.

## Considerations

- The 20% figure depends on the agent; if m exceeds 10 while e = 0, the system is still safe (wrong drafts are
  caught) and the repair is documentation and examples in the agent-facing docs, followed by a new registered run on
  a fresh corpus (the used corpus is retired into examples).
- If e > 0 the repair is in the admission rules (stronger near-boundary and mutation requirements), not in the
  agent.
- A single run on 50 statements is a count, not a rate estimate with an interval; the receipt says so.
- The hidden sets are the only confidential material; after the gate is recorded they are released as regression
  fixtures.
