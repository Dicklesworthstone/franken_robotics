## Background

Past-time formulas (historically H, once O, since S, and Boolean combinations of atoms) depend only on what has
already happened, so they can be computed inside the simulation step and used as signals while an episode is still
running. An online signal has three uses: an input to early termination; a score for splitting in the rare-failure
search; and an optional added reward term (a Frontier option behind KILL-SPEC-REWARD). Future-time operators are
never evaluated online (ADR-ARENA-04).

On the batched tiers thousands of worlds advance in lockstep and a kernel may not branch on a world's data. The
textbook streaming algorithm for a sliding minimum, a monotonic deque, pops a data-dependent number of elements per
sample, which is exactly what the lockstep rule forbids. DESIGN: the kernel for a sliding minimum or maximum over a
window of W ticks uses the block decomposition that keeps a prefix and a suffix extremum per block of W samples:
fixed memory of 2·W values per operator node and world, at most three comparisons per sample, and no data-dependent
control flow. The referee uses the monotonic-deque formulation of the same function (N24a-08), and the definitional
evaluator (N24a-04) is the oracle; the three must agree bit for bit (PO-ARENA-01). That agreement is possible because
minimum, maximum and negation are exact in floating point: there is no rounding to differ on, once negative zero is
canonicalized and NaN is turned into a fault.

At M1 there is no batched physics step yet. This bead delivers the kernels as CPU reference code in the lockstep
form, run through the `batch-cpu` kernel harness with a kernel manifest, so that the device emission at M3 (the bead
that puts requirement verdicts on batched tiers) changes the backend and nothing else.

## Scope

In: compilation of a `Past` formula into a DAG of monitor nodes; the block-decomposition kernel for H and O with a
delayed window; the kernel for S; per-world validity (coverage) so that no value is ever produced from an incomplete
window; reset handling; the capacity check (FROB-REF-528); the kernel manifest and its registration in the last
stage of the step beside observations and rewards; memory accounting.

Out: emission in the shared GPU dialect and device runs (N23ap1-01, split from BD-255); the deque monitor (N24a-08); the differential
harness over 10⁶ traces (BD-121); the consumers of online signals (N24a-13).

## Technical approach

**Compilation.** Each `Past` tree becomes a DAG evaluated once per requirement tick, leaves first: `Atom` (reads the
normalized atom slab), `And`/`Or` (elementwise minimum/maximum), `Not` (negation), `H`/`O` (sliding extremum), `S`.
Every node output carries a validity bit per world: an output is valid only if every input it read was valid and its
own window was fully covered.

**Sliding extremum for a tick window [a, b]** (H is the minimum; O the maximum, obtained by exchanging min and max).
Let W = b − a + 1 be the number of ticks in the window. State per (node, world): `raw[W]`, `suf[W]`, a running
prefix `pre`, an output delay ring `ring[a]` (absent when a = 0), a coverage counter `cov`, and the block position
p = k mod W, where k counts the world's requirement ticks since the monitor was created. Per tick, with input x:

1. `pre ← (p = 0) ? x : min(pre, x)`.
2. `raw[p] ← x`.
3. `m ← (p = W − 1) ? pre : min(suf[p + 1], pre)`. This is the minimum over the last W ticks: the current block's
   positions 0…p are in `pre`, and the previous block's positions p + 1…W − 1 are in `suf[p + 1]`.
4. If p = W − 1, finish the block with one backward pass: `suf[W − 1] ← raw[W − 1]`, then for j = W − 2 down to 0,
   `suf[j] ← min(raw[j], suf[j + 1])`.
5. Delay by a ticks: `out ← ring[k mod a]`, then `ring[k mod a] ← m` (when a = 0, `out ← m`). `out` is then the
   minimum over ticks [k − b, k − a].
6. `cov ← min(cov + 1, b + 1)`; `covered ← (cov = b + 1)` (ticks since creation or reset: the pre-origin
   clock). Beside it a validity counter over the node's input, `vcov ← in_valid ? min(vcov + 1, b + 1) : 0`, and
   `valid ← (vcov = b + 1)`: the output is valid only when every input value inside the window was valid, which
   for a nested node means its input node has itself been valid for b + 1 ticks (an input's validity, once set
   after a reset, stays set until the next reset, fault or missing sample, so a run of b + 1 valid ticks is the
   whole window). For a node over atoms, `in_valid` is the atom slab's per-tick validity (false on a missing
   sample), so a dropped sample invalidates every window that contains it (INV-ARENA-02).
7. The pre-origin rule of the language (N24a-04: a tick before the episode origin satisfies nothing). For H, while
   not covered, `out ← −∞` through a select, with the flag `pre-origin`. For O, the output while not covered is the
   maximum over the existing ticks of the window; this is obtained by filling the node's buffers and ring with −∞
   (the identity of the maximum) at reset, so no select is needed. In both cases `valid` of step 6 is exported
   beside the value: margin consumers (a reward term, a splitting score) must read `valid`; Boolean consumers
   (early termination) read the value, which is false while H is not covered.

Cost: two comparisons per sample plus W − 1 comparisons once per W samples, so fewer than three per sample on
average. Memory: 2·W + a values (2·W when a = 0), at most 2·(b + 1). Every branch condition is on the integer tick
counter, never on a signal value; on a device the conditions become select masks and the backward pass a loop of
fixed trip count executed by the worlds at a block boundary.

**Reset.** On a world's reset `cov ← 0` and `vcov ← 0`. An H node's buffers are not cleared: its output is forced to −∞ until
b + 1 post-reset ticks have been seen, and after that it reads only the most recent b + 1 ticks, all post-reset, so
stale pre-reset contents can never reach an output. (Proof sketch for the contract: `out` at tick k reads ticks
[k − b, k − a]; `cov = b + 1` means the reset was at or before tick k − b.) An O node's `raw`, `suf`, `pre` and
`ring` are filled with −∞ at reset (2·W + a writes, done once, inside the reset path, which already restores a
whole world state).

**Since, φ S_[a,b] ψ.** DESIGN (this bead's elaboration; the identity below is a lattice identity, valid for minima
and maxima because every identity between meet-and-join terms that holds in the two-element lattice holds in every
distributive lattice, and the reals under min and max are one):

    φ S_[a,b] ψ  =  min( O_[a,b] ψ ,  Z ),      Z(t) = min( min of ρ(φ, t″) over t″ ∈ (t − a, t] ,  Q(t − a) ),
    Q(s) = max( ρ(ψ, s), min( ρ(φ, s), Q(s − 1) ) ),      Q = −∞ before the episode's first tick.

Q is the unbounded since, a one-value recursion. The node therefore consists of: one sliding maximum of ψ over
[a, b]; one sliding minimum of φ over the a most recent ticks (absent when a = 0); the scalar Q with a delay ring of
a values; and one final minimum. Memory 2·W + 4·a + 1 values. Coverage as above: `cov = b + 1`. On reset Q ← −∞
through a select, and Q's delay ring and the ψ-maximum's buffers are filled with −∞, so that while the window is
not yet covered the node ranges over existing candidate ticks only, as the pre-origin rule requires. Hand check (a = 0, b = 1): the definition gives max( ρ(ψ, t), min( ρ(ψ, t − 1), ρ(φ, t) ) ); the
decomposition gives min( max(A, B), max(A, min(C, max(B, D))) ) with A = ρ(ψ, t), B = ρ(ψ, t − 1), C = ρ(φ, t),
D = min(ρ(φ, t − 1), Q(t − 2)), which reduces to max(A, min(B, C)) by absorption. Because only minima and maxima are
taken, the result is one of the input values and is bit-identical to the definitional value.

**Floating-point rules.** Inputs are canonicalized at the atom: −0 becomes +0. A NaN in an atom marks the world
`Faulted` (a select sets the fault bit; the monitor's outputs for that world are invalid from then on and the
episode's verdict is `invalid`). No fused operations, no reassociation: the kernel contains comparisons and selects
only.

**Capacity.** The capacity of an online window is 4,096 requirement ticks (TARGET), counted on the far bound: a
window `(a b)` is admitted online when b/T ≤ 4,096, the same tick count N24a-06 reports for a window (a 1 s window
on a 1/50 s clock is "50 ticks"; it stores 51 samples). A node whose far bound exceeds 4,096 ticks is refused at task
admission with FROB-REF-528; such a window is offline only. For an `S` node the bound applies to its own b; for a
nested past formula it applies to each node, not to the sum (DESIGN: the bound exists to fix each node's memory,
and each node keeps its own history). Repairs, ranked: (1) move
the formula into the verdict, where the offline evaluator has no such limit; (2) evaluate the online signal on a
slower declared clock (a 1/10 s clock turns 600 s into 6,000 ticks, still refused; 1/5 s into 3,000, admitted),
with the reductions that then apply; (3) shorten the window.

**Manifest and placement.** The kernel is registered with a manifest (inputs: the atom slab and its validity; state:
the buffers above; outputs: one margin and one validity bit per online signal and world) and a stage signature that
places it in the last stage of the step, beside observations and rewards, after the physical state of the tick is
committed. It fires on the requirement clock's ticks under the clock mask. Determinism class D2 by design (D1 where
the device family attains it); outputs carry evidence class Tested.

**Memory accounting** is reported to the cost model: bytes per world = 4 · Σ over nodes of the node's value count
(single precision on fast tiers, 8 on `f64` tiers). Example: fixture 1's `dwell` window (b = 50 ticks, 51 samples)
is 2·51·4 = 408 bytes per world and node; a node at capacity (a = 0, b = 4,096) is 2·4,097·4 = 32,776 bytes, about
32 KiB per world and 128 MiB for 4,096 worlds.

## Acceptance criteria

- [ ] For H, O and S with windows [a, b] over 0 ≤ a ≤ b ≤ 64 ticks, the kernel equals the definitional evaluator
      bit for bit at every valid tick on 10⁴ random traces per operator (the full 10⁶ run is BD-121).
- [ ] No output is flagged valid before b + 1 ticks after creation or reset; after that every output is valid if
      inputs are. While not covered, H outputs −∞ and O outputs the maximum over existing ticks, bit for bit as the
      definitional evaluator does under the pre-origin rule.
- [ ] Fixture 1's online signals compile and run: `dwell` = `(H (0 s 0.5 s) (and cleared upright))` on a 1/100 s
      clock is a 51-tick window using 102 values per world; `stalled` = `(and (H (0 s 0.5 s) saturated) (not
      advancing))`.
- [ ] A planted task with an online window whose far bound is 4,097 ticks is refused with FROB-REF-528; a far bound
      of 4,096 ticks is admitted.
- [ ] The comparison count per sample, instrumented in a test build, is at most 3 on average over any 2·W samples.
- [ ] The kernel source contains no branch on a floating-point value (lint over the kernel's intermediate form).
- [ ] The kernel runs through the `batch-cpu` harness with a receipt; a manifest whose write footprint aliases an
      undeclared buffer is rejected by the harness.

## Test plan

### Unit tests

- `sliding_min_small`: x = [3, 1, 2, −1, 4, 0], H over ticks [0, 2]: outputs −∞, −∞ (both flagged `pre-origin`,
  not valid), then 1, −1, −1, −1.
- `once_partial_window`: same x, O over [0, 2]: outputs 3, 3 (existing ticks only, not valid as margins), then 3,
  2, 4, 4.
- `delayed_window`: same x, H over [1, 2]: at tick 2 → min(x₀, x₁) = 1; tick 3 → min(1, 2) = 1; tick 4 → −1.
- `once_is_max`: O over [0, 2] on the same x: tick 2 → 3; tick 3 → 2; tick 4 → 4.
- `since_matches_definition_small`: all 3⁴ assignments of {−1, 0, 1} to (A, B, C, D) in the hand check.
- `block_boundaries`: W = 4 over 13 samples; compare with brute force at every tick (covers p = 0 and p = W − 1).
- `reset_does_not_leak`: fill with large negative values, reset at tick 10, feed positives; first valid output at
  tick 10 + b is positive.
- `nan_marks_faulted`, `negative_zero_canonical`: a −0 input and a +0 input give identical output bits.
- `capacity_4096_ok_4097_refused`.
- `comparison_budget`: instrumented counter ≤ 3·n over n = 10⁵ samples for W ∈ {1, 2, 3, 50, 4096}.
- `nested_validity`: `(H (0 s 1 s) (O (0 s 1 s) a))` at 1 tick per second is first valid at tick 2 (the inner O
  is valid from tick 1, the outer H needs two valid inputs); a planted kernel that tests only the current input's
  validity reports tick 1 and must fail.
- `missing_sample_invalidates_window`: H over [0, 2] with the atom missing at tick 5: outputs at ticks 5, 6 and 7
  are not valid, tick 8 is valid again.

### End-to-end script and logging

`scripts/e2e/spec_online_kernels.sh [--seed S]` (owned by this bead; default seed 2407; idempotent; sources the
STD-E2E helper). Fixture 1, its recorded runs and the verdict verbs come after this bead, so the script drives the
kernels through their tests, the Gauntlet row and one example program on this bead's own dependencies (the
`batch-cpu` harness of BD-014). Steps:

1. `unit`: `FROB_TEST_SEED=$SEED cargo test -p frob-spec online::` (the unit tests above, the 10⁴-trace comparison
   per operator with the definitional evaluator, the capacity refusal FROB-REF-528 at 4,097 ticks, the comparison
   budget and the no-data-dependent-branch lint).
2. `harness`: `cargo run -p frob-spec --example online_harness -- --worlds 4096 --seed $SEED --json` compiles
   fixture 1's two online signals (built in code on a 1/100 s clock: `dwell` and `stalled`) and runs them through
   the `batch-cpu` harness over seeded atom streams with resets; it prints the window (51 ticks), the values per
   world (102), the receipt, and the count of (world, tick) outputs that differ from the definitional evaluator
   (must be 0). The same example with `--alias-footprint` plants a manifest whose write footprint aliases an
   undeclared buffer and must be rejected by the harness (non-zero exit, the buffer named).
3. `known-answer`: `e2e_tier g1_known_answers KA-596`, then with `--mutations` (the padding monitor, which must be
   caught); the receipt hash is logged.

NDJSON under `target/e2e-logs/spec_online_kernels/<utc>.ndjson` with a transcript beside it; every line carries
`ts`, `script`, `bead` (`N24a-07`), `step`, `event`, the command, exit code, wall time, the evidence block (tier
`batch-cpu`, determinism class), the count of ticks compared and of mismatches against 0, comparisons per sample
against 3, and on mismatch the first differing world and tick with both bit patterns in hexadecimal; a final
`summary` line. Recorded online values of fixture 1 on the referee, read with `frob telemetry query` and checked
against recomputation from the atom channels, are N24a-42's step `online-kernels`, which runs this script as a
stage.

### Known answers and negative controls

- KA-596 (online and offline agreement): a past-time signal sampled at the end of the trace equals the offline
  evaluation of the same formula; exact. Its negative control, a monitor that pads a short window, is planted as a
  build in which step 7's select is removed: `sliding_min_small` then reports 3 and 1 (the minimum over the part of
  the window that exists) at ticks 0 and 1 and the test must fail.
- Construction C-30 streaming test: the streaming result equals the brute-force window minimum on random signals.
- KA-593 (streaming past-time robustness against offline evaluation on 10⁴ random traces: equal) is the same property
  measured at the gate of the batched tiers; this bead provides the CPU reference it compares with.
- Metamorphic relation MR-20: streaming past-time robustness equals offline evaluation; G over [0, T] at 0 equals H
  over [0, T] at T.
- Negative control for the lockstep form: a variant that uses a monotonic deque inside the kernel is rejected by the
  no-data-dependent-branch lint.
- Determinism lanes: twice on one machine; across worker counts of the harness (1, 8, 36); debug and release.

## Considerations

- The backward pass is a burst of W − 1 comparisons at each block boundary. If the burst shows in the step-time
  profile, block phases may be staggered per node (the phase is a function of the node identifier, never of data).
- Whether a device profile accepts a trip executed only by worlds at a block boundary is settled when the kernel is
  emitted for devices; the fallback is to align blocks to the batch's shared requirement-tick counter.
- The since decomposition uses more than 2·W values when a > 0; the contract states the per-node formula instead of
  the headline figure.
- OPEN-NEMESIS-2: when a requirement margin is flat until shortly before failure, an online margin is a poor
  splitting score; the default there is no splitting for that requirement. That is a property of the formula, not
  of this kernel.
- A window of 600 s at 50 Hz (30,000 samples) is deliberately not available online.
