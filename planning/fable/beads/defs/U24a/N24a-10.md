## Background

A strict and a non-strict inequality differ exactly at the boundary, and the boundary is where requirement verdicts
are most often wrong. Decision ADR-ARENA-05: the declared comparator decides at the boundary, in exact arithmetic;
the sign of a floating-point margin does not decide a case that sits on the boundary.

Two facts motivate the mechanism.

- FACT (a recorded boundary-classifier pilot on this project's Metal GPU and on both RTX 4090 cards; listed in the
  source register and reproduced by the exact-kernel probe bead before any gate cites it): on a dense 65,536-case
  boundary screen, unguarded single-precision strict comparison gave 452 false admissions and 23,438 false
  exclusions, identically on every device; with a 2⁻²¹ guard and an exact fallback there were no final errors; an
  exact 32-bit integer kernel classified all 65,536 cases correctly with identical bytes on every device. The
  smallest case that shows why a bare comparison fails: 16,777,216 < 16,777,217 is true in integers, and in single
  precision the second number rounds to the first, so the strict comparison is false.
- The exact scalar docking mission supplies the smallest case in which the *comparator* matters. Three one-second
  ticks; hidden plant gain g ∈ {1, 2}; first command p; one velocity reading with error in [−ε, +ε]. The reading
  lies in [p − ε, p + ε] if g = 1 and in [2p − ε, 2p + ε] if g = 2, and the mission needs the two sets disjoint:
  separation p − 2ε > 0. With command limit U the largest admissible probe is p = (U + ½)/2, which gives the
  boundary ε < (U + ½)/4, equality excluded. At U = 3/4 and ε = 5/16 the separation is exactly zero: p = 5/8, and
  both worlds can report 15/16 while requiring different second commands (−1/4 for g = 1 and −3/4 for g = 2). The
  strict requirement correctly fails. A non-strict comparator would admit a mission that cannot be completed.

The determinism rules of the project put "requirement verdicts at a boundary" in class D0 (exact): a boundary
decision made in bare floating point is refused at build time. This bead is how the requirement language meets that.

## Scope

In: the per-atom guard band; the `boundary` flag; CPU re-evaluation of flagged atoms with the declared comparator,
in exact rational or integer arithmetic where the inputs allow and in double precision otherwise; recording of the
guard and the arithmetic used; the docking boundary case and the 65,536-row screen as tests on the host, including
the single-precision negative control.

Out: evaluation on devices (N23ap1-01, split from BD-255, emits the guarded atom kernel; this bead defines what it must flag); the choice of
guard per backend (OPEN-ARENA-5); the exact-integer and guarded kernel classes themselves (BD-030, BD-053).

## Technical approach

1. **Where a decision is made.** An atom's Boolean value is decided by the fast evaluator only when its normalized
   margin ρ lies outside a guard band around zero: |ρ| > γ. The default is γ = 2⁻²¹ (TARGET). A guard is proved, not
   tuned: the derivation tooling bounds the rounding error of the atom's difference expression from its actual
   operation sequence in the tier's arithmetic (for the pilot's conversion-and-addition sequence the bound is
   5·2⁻²⁵, well inside 2⁻²¹). DESIGN: the effective guard of an atom is the larger of the configured γ and the
   derived bound divided by the scale; if no bound can be derived for an atom's expression, every evaluation of that
   atom is treated as inside the band.
2. **Flagging.** A world with a verdict atom inside the band at a tick the verdict reads is flagged `boundary`. The
   flag names the atoms and ticks.
3. **Re-evaluation.** Each flagged (atom, tick) is recomputed on the CPU from the recorded atom inputs:
   - if the atom's inputs belong to the exact-integer kernel class (integers, fixed-point lattice values, rational
     clock quantities), in exact integer or rational arithmetic; the result is the exact sign of the difference;
   - otherwise in double precision from the recorded samples.
   The declared comparator is then applied: `>` and `<` are false at zero, `>=`, `<=` and `=` are true at zero. The
   re-evaluated Boolean replaces the fast one, and the margin is replaced by the re-evaluated value (exactly zero
   where the exact difference is zero).
4. **Composition.** The verdict's Boolean value is recomputed through the formula's Boolean recursion with the
   re-evaluated atoms. A verdict whose margin is exactly zero is decided by that recursion and never by a sign.
5. **Record.** The verdict record carries `boundary: { flagged, guard, atoms: [{id, tick, arithmetic: "integer" |
   "rational" | "f64", holds}] }`; when nothing is flagged it is `{ "flagged": false, "guard": "2^-21" }`. The
   fraction of worlds flagged is reported in the run receipt (a high fraction is a design smell: a requirement whose
   atoms sit on their boundary by construction).
6. **On the CPU tiers.** On the referee and on `batch-cpu` in double precision the fast evaluation is already
   double; the guard still applies (γ is small against double rounding, so flags are rare) and the exact path is used
   whenever inputs are exact-class. This is what makes the M1 half of the mechanism testable before any device
   exists: the single-precision behaviour is reproduced on the host by evaluating the same atoms in `f32`.
7. **Determinism.** Decisions made on the exact path are class D0 on every machine. Decisions outside the band are
   D0 by the guard's proof. A decision re-evaluated in double precision is a deterministic function of the recorded
   inputs.

## Acceptance criteria

- [ ] Docking boundary: with U = 3/4 and ε = 5/16 entered as exact rationals, the atom `(> separation 0)` is flagged,
      re-evaluated in rational arithmetic, found to have separation exactly 0, and does not hold; the mission
      requirement is `violated`. The same case with `>=` holds (recorded as the negative control).
- [ ] The 65,536-row boundary screen, evaluated as requirement atoms through the guarded path, has zero final
      errors against the exact integer labels; the count of rows flagged and the arithmetic used are recorded.
- [ ] Unguarded single-precision evaluation of the same screen misclassifies at least one row (TARGET: reproduces the
      recorded 452 false admissions and 23,438 false exclusions when run on the recorded grid).
- [ ] An atom with |ρ| = 2⁻²² is flagged; one with |ρ| = 2⁻²⁰ is not.
- [ ] A verdict with margin exactly zero is decided by the comparators: `(>= x 0)` satisfied, `(> x 0)` violated.
- [ ] A synthetic trace constructed exactly at an analytic threshold (recorded atom inputs whose exact difference is
      zero) carries the `boundary` flag naming that atom and tick. The same flag on fixture 1's runs at its six creep
      thresholds is KA-606's control, checked by the creep-rig bead BD-123 (on the referee) and by N24b-09 (on the
      batched tiers), which come after this bead.
- [ ] No code path in `frob-spec` takes the sign of a margin to produce a Boolean (lint: the only conversion from
      margin to Boolean is inside the guarded decision function).

## Test plan

### Unit tests

- `docking_strict_fails_at_equality`: p = 5/8, ε = 5/16 → separation p − 2ε = 0; both worlds can read 15/16
  (p + ε = 2p − ε = 15/16); `>` false, `>=` true.
- `docking_just_inside`: ε = 5/16 − 2⁻²⁸ → separation 2⁻²⁷ > 0: flagged, re-evaluated exactly, holds.
- `f32_integer_neighbours`: 16,777,216 < 16,777,217: true on the integer path, false in `f32`.
- `guard_threshold`: flagged at 2⁻²², not at 2⁻²⁰, flagged at exactly 2⁻²¹ (the band is closed).
- `derived_bound_widens_guard`: an atom whose derived error bound over scale is 2⁻¹⁸ is flagged at 2⁻¹⁹.
- `no_bound_means_always_flagged`.
- `zero_margin_uses_comparator`: all five comparators at exact equality.
- `compound_formula_at_boundary`: `(and a b)` with ρ(a) = 0 under `>` and ρ(b) = 5 → margin 0, Boolean false;
  `(or a b)` → margin 5, true.
- `screen_guarded_zero_errors`, `screen_unguarded_f32_has_errors`: the 65,536-row corpus.
- `flag_fraction_reported`.

### End-to-end script and logging

`scripts/e2e/spec_boundary_guard.sh [--seed S]` (owned by this bead; default seed 2410; idempotent; sources the
STD-E2E helper). The verdict verbs and the recorded docking-fixture runs come after this bead, so the script drives
the guarded decision through its tests and one example program on this bead's own dependencies (the corpus of
BD-030, the error-bound derivation of BD-053, the offline evaluator N24a-09). Steps:

1. `unit`: `FROB_TEST_SEED=$SEED cargo test -p frob-spec boundary::` (the unit tests above, including the two
   screen tests and the margin-to-Boolean lint).
2. `docking`: `cargo run -p frob-spec --example boundary_cases -- --json` evaluates the docking requirement atom
   `(> separation 0)` (built in code, inputs entered as exact rationals) at (U, ε) = (3/4, 5/16), (3/4, 1/4) and
   (3/4, 5/16 − 2⁻²⁸), and the equality case again under `>=`; the script asserts `violated` with
   `boundary.flagged = true`, the atom and tick named and `arithmetic = "rational"` for the first, `satisfied` for
   the second (separation 1/8), flagged and holding for the third, and holding under `>=` (the negative control's
   reference).
3. `screen`: the same example with `--screen` runs BD-030's 65,536-row corpus as requirement atoms through the
   guarded path and asserts zero final errors against the exact labels, logging the rows flagged and the arithmetic
   used; then with `--screen --precision f32 --no-guard` (the example's own flags, the negative control) it must
   report a non-zero error count, and both error counts are logged (452 false admissions and 23,438 false
   exclusions on the recorded grid, TARGET).

NDJSON under `target/e2e-logs/spec_boundary_guard/<utc>.ndjson` with a transcript beside it; every line carries
`ts`, `script`, `bead` (`N24a-10`), `step`, `event`, the command, exit code, wall time, the evidence block
(determinism class D0 for the decisions), the boundary record per case, the counts of rows flagged, final errors
against the threshold 0 and, for the control, the two error counts; on failure the first misclassified row with its
exact label; a final `summary` line naming GATE-ARENA-03 (host half; exercised here, never recorded here). The
same cases through `frob task verdict` on the recorded docking-fixture runs are the `boundary-*` steps of
`scripts/e2e/arena_requirement_pipeline.sh` (N24a-42), a later script with steps of its own that does not run this
one.

### Known answers and negative controls

- KA-615 (boundary comparator): at U = 3/4 and ε = 5/16 the strict docking requirement fails; the 65,536-case screen
  has no final error with the guard; tolerance exact; sites host, then CUDA and Metal when N23ap1-01 lands. Negative
  controls: a non-strict comparator admits the equality case; unguarded single-precision comparison misclassifies the
  screen.
- Docking grid known answer (context for the fixture owner): on U = ½ + i/32 for i = 0…16 and ε = j/64 for
  j = 0…32 a cell is admitted exactly when 2j < 32 + i: 344 of 561 admitted, 217 excluded, nine exactly on the
  boundary. The nine boundary cells are the ones this mechanism must get right.
- KA-606's control (fixture 1): a run exactly at a creep-rig threshold must carry the `boundary` flag.
- Negative control registry seeds: "sign of margin decides" (fails `zero_margin_uses_comparator`); "guard removed"
  (fails `screen_guarded_zero_errors`).
- Determinism lanes: the screen's labels are compared as bytes across debug, release, Linux and macOS.

## Considerations

- OPEN-ARENA-5 is open: the guard per backend. Fail-closed default until decided: 2⁻²¹ with CPU re-evaluation of
  every flagged atom. The device half of GATE-ARENA-03 waits on it; the host half does not.
- Placement lesson from the pilot (FACT): for this small predicate the host integer loop was faster end to end than
  any device (about 34 µs against about 290 µs on Metal and over 1.2 ms on one RTX 4090). Re-evaluation therefore
  stays on the host; only flagged atoms are read back.
- If a task's atoms are inside the band in a large fraction of worlds, re-evaluation cost grows; the receipt's flag
  fraction is the early signal, and the repair is a better-conditioned atom, not a narrower guard.
- A verdict re-evaluated in double precision from single-precision recordings is exact about the *recorded* values;
  it says nothing about what double-precision physics would have produced. The `coverage` and `evidence.tier` fields
  already say which tier the trace came from.
