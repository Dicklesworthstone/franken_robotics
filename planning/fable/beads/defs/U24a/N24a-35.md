## Background

An agent's context is its scarcest resource, and a simulator can fill it in one call: a single episode at control
rate is tens of thousands of samples. The record subsystem's rule is that raw traces are never the default answer.
`frob telemetry summary --budget 800` returns a hierarchical summary sized to a token budget, with handles for
drill-down. Numbers carry units and evidence classes. A compact encoding is available (the suite's MCP tools already
use a compact tabular encoding, FACT).

Brevity is where summaries usually become dishonest: "92% success" with no denominator, a percentage of episodes
that have finished presented as a result, a count that silently omits refused runs. So every summary states its
denominator and the frontier it was computed at. Counts sum to what was planned: completed, failed, refused,
unstarted, and for a paired study the five cells of its accounting identity. Progress is reported with its
denominator ("1,312 of 2,048 episodes committed"), never as a bare percentage. Each number that supports a claim
carries the `claim_id`, so a drill-down handle and an evidence trace are the same thing. This is invariant
INV-CHRON-11: every summary states its denominator, and its counts sum to the planned total.

## Scope

In: the summary builder; the budget rule; the hierarchy and its handles; the counts identity; the frontier pin; the
compact encoding; the verb.

Out: failures by class (BD-094), column queries (N24a-36), the energy view (N24a-37); the artifact graph that
resolves `claim_id`s (its own bead); the dashboard that also reads summaries.

## Technical approach

**1. Input and output.** `telemetry.summary` (read; M1). Input: a run or job, an optional world filter, `--budget
<tokens>` (default 800), `--encoding json|compact`. Output (schema `frob.telemetry.summary/1`): a tree whose root
fits the budget and whose every node has a handle that returns its children.

**2. The budget rule (DESIGN).** The size of an answer is measured by a declared, deterministic estimate: one token
per four bytes of the UTF-8 encoded result, rounded up. The builder fills the tree breadth-first in a fixed priority
order and stops adding nodes before the estimate would exceed the budget. It never truncates a node in the middle,
and it says what it left out: every omitted branch appears as one line "n more under <handle>". A budget too small
for the root (below about 120 tokens) is refused with the smallest admissible budget, not answered with a broken
tree.

**3. The hierarchy, in priority order.**

1. *Identity and standing*: run, task, model, scene and controller identities; tier, determinism class, effort
   profile; state (running, complete, budget-stop, cancelled); the committed frontier (`commit_seq`) the summary was
   computed at.
2. *The counts identity*: planned = completed + failed + refused + unstarted, each count printed, with failed split
   by outcome kind (physical, numerical, budget, protocol). For a paired study: the five cells a-only, b-only, both,
   neither and unscored, which sum to planned pairs.
3. *Verdicts*: counts of `satisfied`, `violated`, `undetermined`, `invalid`; the requirement margin's minimum and
   the atom that bound most often.
4. *Failures*: the top failure classes with counts and one handle each (to `telemetry.failures`).
5. *Energy*: the ledger totals and the residual line, one handle (to `telemetry.energy`).
6. *Notable worlds*: the worst margin, the first fault, the first flagged episode, each as a world address with a
   handle (to `telemetry.query` on that world, and from M2 to stills).
7. *Gaps*: dropped telemetry intervals with their reasons, if any.

**4. Rules for every number.** A number has a unit, the count it was computed from, and the evidence class of its
inputs; a number that supports a claim carries its `claim_id`. A rate is always printed as "k of n" beside any
percentage. A statistic names the frontier it was computed at; two summaries of a running job at different frontiers
are different answers and say so. Integers that can exceed 2⁵³ (ticks, sequence numbers, digests) are strings.

**5. Handles.** A handle is a verb name plus arguments (and, over MCP, a resource address) that returns the next
level: for example `{ "verb": "telemetry.failures", "args": { "run": "r:19e2…", "class": "slip" } }`. A handle is
valid as long as the run is stored; a handle whose target was collected by retention resolves to a refusal that
names the tombstone, never to an empty answer.

**6. Compact encoding.** With `--encoding compact` tables are emitted in the suite's compact tabular form (header
once, rows as delimited values); the JSON form is canonical and the compact form is a view with identical content.
The budget estimate applies to whichever encoding was requested.

**7. Determinism.** The summary is a pure function of the run's committed records at the pinned frontier and of the
budget: the same inputs give the same bytes. Aggregates are integer counts, integer sums, minima and maxima, so they
are identical under any ordering of worlds.

## Acceptance criteria

- [ ] `frob telemetry summary <run> --budget 800 --json` returns a tree whose estimated size is at most 800 tokens
      and whose omitted branches are each named with a handle.
- [ ] The counts identity holds on every summary: completed + failed + refused + unstarted = planned; a planted run
      with refused and unstarted episodes shows all four counts (INV-CHRON-11).
- [ ] No percentage appears without its "k of n"; progress of a running job is printed with its denominator.
- [ ] Every handle in the summary resolves; following handles from the root reaches every recorded episode.
- [ ] Two calls at the same frontier and budget return identical bytes; a call at a later frontier states the new
      frontier.
- [ ] Budgets of 200, 800 and 3,200 give nested trees: everything in the smaller is in the larger.
- [ ] The compact encoding decodes to exactly the JSON content.
- [ ] Reachable through `frob --json` and MCP with the envelope's evidence block.

## Test plan

### Unit tests

- `budget_never_exceeded`: 10³ random runs × budgets {200, 400, 800, 1600, 3200}; estimate ≤ budget.
- `omissions_are_named`: every branch not expanded appears as "n more under <handle>".
- `counts_identity`: planned 2,048 with 1,312 completed, 40 failed, 6 refused, 690 unstarted → the four counts
  printed and summing to 2,048; progress string "1,312 of 2,048 episodes committed".
- `paired_five_cells`: a-only 9, b-only 15, both 30, neither 8, unscored 2 → 64 planned pairs.
- `no_bare_percentage`: a lint over the output schema and a property test over outputs.
- `budget_monotone_nesting`.
- `handle_resolution`: each handle type resolves; a collected target returns the tombstone refusal.
- `frontier_pinned`: appends between two calls do not change a summary pinned to the earlier frontier.
- `compact_equals_json`.
- `too_small_budget_refused`: `--budget 50` → refusal naming the minimum.

### End-to-end script and logging

Steps `summary-*` of `scripts/e2e/telemetry_verbs.sh` (N24a-39): on a recorded referee run with planted refused and
unstarted episodes, `frob telemetry summary --budget 800 --json`, then follow three handles (`telemetry.failures`,
`telemetry.energy`, `telemetry.query`) taken from the result; a second call while a job is still running. Asserts
the size bound, the counts identity, handle resolution and the frontier statement. NDJSON lines carry the command,
exit code, wall time, evidence block, estimated tokens against the budget, the four counts against planned, and the
frontier.

### Known answers and negative controls

- Known answer of the wording rule: "1,312 of 2,048 episodes committed".
- Negative control: a summary builder that reports success over completed episodes only (1,272 of 1,312) with no
  mention of unstarted or refused ones must fail `counts_identity`.
- Negative control: a builder that truncates the JSON at the budget (cutting a node mid-way) must fail
  `omissions_are_named` and schema validation.
- Negative control: a summary computed while reading past its pinned frontier differs between two calls and must
  fail `frontier_pinned`.
- Determinism: bytes compared across debug, release and platforms.

## Considerations

- The token estimate is deliberately crude and declared; what matters is that it is deterministic and conservative
  enough for an agent to budget with. If a tokenizer-specific estimate is ever wanted it is an option, never the
  default, because an answer must not depend on which model is asking.
- A summary is a view, not evidence; claims are cited through their `claim_id`s.
- Private runs: a summary inherits the private mark; handles into private scenes need the caller's scope.
- The dashboard's evidence pane shows numbers reproduced by this verb; a displayed number that this verb cannot
  reproduce is a defect of the dashboard.
