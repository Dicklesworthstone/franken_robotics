## Background

A picture answers "where"; it does not answer "what is that" or "how much". `telemetry.inspect-pixel` closes that
gap for stills drawn by `telemetry.stills`. Given a pixel, it returns what the simulator has there: a link of the
robot, a fixture of the scene, a region of the floor or a contact, and, when an overlay is drawn, the quantity
under the pixel with its unit, channel and world address. The specification states the purpose in one sentence:
the verb returns the quantity under a pixel with its unit, channel and world address, so an agent that cannot see
still reads every overlay.

Two properties make the answer trustworthy. First, the identifier comes from an identifier buffer rendered with
the still by the same rays, from the collision field, so the answer is about the geometry physics used. Second, a
quantity is a stored telemetry value in the channel's own quantization, never a number recovered from a colour.
The equivalent statement for the interactive viewer is a gate of the surface chapter (GATE-TETHER-14, third
milestone: on analytic scenes the overlay value under a probe pixel equals the telemetry channel within its
quantization); this verb is the non-interactive form of the same probe and is tested against the same known
answer one milestone earlier.

Rejected alternative: segmenting the colour image after the fact. It is approximate at silhouettes, cannot
separate two links of one colour, and cannot return a contact at all.

This verb is one of the three of seed BD-191; the seed's done-condition, "a pixel maps to the right link in
fixtures", is this verb's first acceptance criterion. It reads what `telemetry.stills` stores (the still, its tile
table, its identifier, range and overlay value buffers), so it depends on BD-191; the replay writer (N24a-41)
comes after it and carries the seed's joint check.

## Scope

In: the verb (read; second milestone) and its output schema `frob.telemetry.inspect-pixel.out/1` (the name its
registry row gives it); addressing a pixel in a
single still or in a contact sheet; the identifier answer; range and world point; contact addresses; overlay
values; batches and a coarse grid mode; refusals; privacy.

Out: rendering the buffers (the sensing crate's bead); drawing stills and choosing frames (BD-191); the in-page
probe of the HTML replay (N24a-41), which must return the same fields; the viewer's interactive probe (seed BD-300).

## Technical approach

**1. Input.** `frob telemetry inspect-pixel <still_id> --pixel <x>,<y> [--pixel …] [--overlay <name>] [--grid <n>]
--json`. Alternatively `<run> --world <address> [--episode <n>] [--at <selector>] [--views <list>] [--overlay
<list>] [--size <W>x<H>] --pixel …`: the frame, view, overlay and size options are those of `telemetry.stills`
(BD-191) with the same defaults, so the still addressed is exactly the one that verb returns for them (found by
its `still_id`, or drawn first), and the pixel is in that image's coordinates: sheet coordinates when the
selection is a contact sheet. One tick and one view are written `--at tick=<n> --views <name>`. The registry's
example, `frob telemetry inspect-pixel r:19e2 --world 311 --at failure --pixel 412,230 --json`, is this form:
pixel (412, 230) of the default failure sheet, which lies in the tile of row 0, column 1 at local (90, 230).
Pixel coordinates are integers in image space, origin at the top-left corner, x to the right, y down.
At most 64 pixels per call.

**2. Resolving a pixel on a contact sheet.** The sheet's tile table gives each tile's rectangle, view and frame.
A pixel inside a tile maps to tile-local coordinates; a pixel on a gutter or a caption strip returns kind `none`
with reason `gutter` or `caption`. A pixel outside the image is a protocol refusal with the image size.

**3. The identifier answer.** From the identifier buffer at the tile-local pixel:

| Kind | Fields returned |
|---|---|
| `link` | Link name and index; the body it belongs to; the design's identity |
| `fixture` | Fixture name and identifier in the scene pack; its joint state at that tick if it is articulated |
| `region` | Region name (a floor surface, a task region, a film tile, an unknown region); its material and friction where it has them |
| `contact` | The contact's telemetry address: stream `Contact`, site identifier, the two parties, tick; contacts are drawn as small discs at contact points so that they are pickable |
| `none` | Reason: `background`, `gutter`, `caption` |

With it: `range_m` along the pixel's ray, the hit point in the world frame (anchored coordinates) with the frame
named, the surface normal, the tick and simulated time (a rational), the view's camera pose, and the world address
(run seed, world, episode).

**4. The overlay answer.** For each overlay drawn on the still (or the one named by `--overlay`), if the pixel
shows an overlay element, the verb returns the stored value from the overlay value buffer: `value` (the stored
integer and its scale, and the decoded number), `unit`, `channel` (stream and channel name), `quantization`,
`world`, `tick`, the element's telemetry address, and the evidence class of the run. Example for `contact-cones`:
friction utilization 0.83 (dimensionless) on channel `Contact/friction_utilization`, site `front_left_foot`, world
311, tick 1,204. Where a pixel shows no element of that overlay, the answer is `null` with reason `no-element`,
not zero.

**5. Grid mode.** `--grid n` (n ≤ 16) returns the identifier kind and name at the centres of an n × n grid over
each tile, and a histogram of names by pixel count for the tile: a coarse "what is in this picture" for an agent
that cannot see, sized to the caller's token budget.

**6. Consistency with `telemetry.query`.** Every overlay value returned must be reproducible: the answer includes a
drill-down handle (verb `telemetry.query` with the stream, channel, world and tick) that returns the same stored
integer. A value this verb returns and the query cannot reproduce is a defect.

**7. Refusals and absences.** A `still_id` whose buffers were collected by retention and cannot be redrawn (the
trace they would be redrawn from is collected too) is refused with `FROB-REF-888` (a value requested over missing
samples; its trigger list names a collected trace), exit 3, `detail: still-collected`, naming the tombstone: the
`still_id`, the collection's ledger sequence and the chunk keys that would have redrawn it (repairs: 1. re-run the
episode with the channels retained and draw the still again; 2. accept `unavailable`). DESIGN: the plan names the
case and no code; 888 is the record subsystem's code for exactly this absence, so no new code is needed. A still
whose buffers were collected while its trace is retained is redrawn transparently (same `still_id`, same bytes). A
still of a private scene requires the caller's private read scope (`FROB-REF-731` without it, exit 5: a capability
refusal). A still of a run in the blinded confirmation lane is sealed until the campaign closes (`FROB-REF-840` for
a session without the administrative capability, exit 5, N24-REF's row; the attempt is logged). A pixel outside
the image and a malformed argument are `FROB-REF-802`, exit 3. The verb's registry row lists 731, 840 and 888
(`detail: still-collected`).

**8. Determinism and evidence.** The answer is a pure function of the stored buffers: identical bytes on repeat
and across backends, because identifier buffers are exact. Evidence class `Tested`; tier and determinism class of
the run; the envelope carries the run's identities.

## Acceptance criteria

- [ ] Seed done-condition: on the reference quadruped fixture, a pixel aimed at the centroid of each of its 13
      bodies maps to that link; on the cart fixture, the chassis, the payload and each wheel; the sill maps to its
      fixture; the floor to its region; a contact disc to its contact address.
- [ ] On an analytic scene (a sphere of radius 0.10 m centred 1.00 m in front of the camera on its axis) the centre
      pixel returns range 0.90 m and the hit point (0, 0, 0.90) m in the camera frame mapped to world coordinates,
      within the range buffer's quantization.
- [ ] An overlay value under a probe pixel equals the telemetry channel within its quantization, on 100 probe
      points; the drill-down handle returns the same stored integer.
- [ ] A pixel on a gutter or caption returns `none` with its reason; a pixel outside the image is refused.
- [ ] Grid mode returns n² identifiers per tile and a histogram whose counts sum to the tile's pixel count.
- [ ] Sealed and private stills are refused without the scope.
- [ ] Reachable through `frob telemetry inspect-pixel --json` and MCP as `telemetry_inspect_pixel` (the tool name
      is the verb name with `.` and `-` replaced by `_`).

## Test plan

### Unit tests

`crates/frob-chronicle/tests/inspect_pixel.rs`.

- `sheet_pixel_to_tile`: in a 3 × 4 sheet of 320 × 240 tiles with 2-pixel gutters and 16-pixel captions, pixel
  (322, 0) is tile (row 0, column 1), local (0, 0); pixel (320, 0) is a gutter.
- `identifier_decode_kinds`: packed values for each of the five kinds decode to kind and index.
- `link_names_on_quadruped`: 13 pixels → 13 names.
- `contact_disc_returns_address`.
- `sphere_range_known_answer`: range 0.90 m at the centre; at the silhouette's inside edge the range tends to
  √(1.00² − 0.10²) = 0.99499 m.
- `overlay_value_is_stored_integer`: a contact with stored utilization integer 3,400 at scale 1/4,096 → value
  0.830078125, unit dimensionless, with the channel name.
- `no_element_is_null_not_zero`.
- `grid_histogram_sums`: 320 × 240 tile → counts sum to 76,800.
- `out_of_bounds_refused` (`FROB-REF-802`); `collected_still_tombstone` (buffers and trace collected in a scratch
  store: `FROB-REF-888`, exit 3, `detail: still-collected`, the tombstone's `still_id` and chunk keys);
  `collected_buffers_redrawn` (buffers collected, trace retained: the same bytes as before collection);
  `sealed_refused_840` (exit 5); `private_still_without_scope_731` (exit 5).
- `run_form_addresses_the_stills_default`: `<run> --world <w> --at failure --pixel 412,230` returns the same
  answer, byte for byte, as `inspect-pixel <still_id> --pixel 412,230` on the `still_id` that `telemetry.stills
  <run> --world <w> --at failure` returned; the pixel resolves to tile (row 0, column 1), local (90, 230).
- `query_handle_reproduces_value`.
- `mcp_name_mapping`: `telemetry.inspect-pixel` ↔ `telemetry_inspect_pixel`, one-to-one.

### End-to-end script and logging

Steps `pixel-*` of `scripts/e2e/telemetry_stills.sh` (owned by BD-191; this bead adds the group): after
`stills-failure`, the script reads
the expected pixel list for each fixture from `fixtures/e2e/stills/expected_pixels.json` (pixel, expected kind and
name, computed once from the fixture's camera presets and committed), calls `frob telemetry inspect-pixel
<still_id> --pixel … --json` and compares; then 100 probe points on the `contact-cones` overlay are compared with
`frob telemetry query <run> --world <w> --stream contact --channels friction_utilization --from <t> --to <t>
--json` (N24a-36's spellings; the same call as the returned drill-down handle); then a gutter pixel, an out-of-bounds pixel (exit 3) and grid
mode. NDJSON lines carry the command, exit code, wall time, the evidence block, per pixel the expected and returned
kind and name, for probes the stored integer from both verbs (mismatches against threshold 0), and on failure the
first differing pixel with the `still_id` and the identifier-buffer handle.

### Known answers and negative controls

- Sphere: range 0.90 m at the centre pixel (camera distance minus radius).
- Probe: the overlay value under a probe pixel equals the telemetry channel within its quantization (the known
  answer shared with the viewer's gate).
- Negative control 1: a lookup that ignores the tile offset on a contact sheet returns the first tile's link for
  every tile; `sheet_pixel_to_tile` and the fixture comparison must fail.
- Negative control 2: an overlay value decoded from the pixel's colour differs from the stored integer in the last
  bits; `overlay_value_is_stored_integer` must fail.
- Negative control 3: an identifier buffer from the visual mesh maps a pixel on a decorative cover to a link that
  has no collision geometry there; the fixture comparison must fail.
- Determinism: bytes compared twice on one machine, debug and release, and across backends (identifier buffers are
  exact).

## Considerations

- Pixel answers at silhouettes are sensitive to one-pixel shifts; expected-pixel fixtures aim at centroids, and the
  test never asserts on edge pixels.
- The world point is returned in anchored coordinates so that it stays meaningful in large scenes; the frame is
  named in the answer.
- A region answer may reveal scene layout; private scenes are protected by the caller's scope, and logs carry
  names and digests only.
- If the identifier format changes (more kinds, wider indices), the buffer's version is part of `still_id`, so an
  old still is never decoded with a new table.
