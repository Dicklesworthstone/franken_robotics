## Background

People and agents who were not at the terminal need to see what a robot did: a reviewer, a collaborator, a later
session. A live viewer needs a running daemon and the stored run. The self-contained replay removes both needs:
`frob telemetry export-html <run> --world <address>` produces one offline HTML file that replays an episode from
stored telemetry and computes nothing new. The verb belongs to the telemetry cluster and the record crate
(`frob-chronicle`) writes its packet; the page inside it is the viewer's.

The decisive design choice is the order of construction (DESIGN): the packet is an adapter over records that
already exist. It draws a parent world and its forks from the record subsystem and the contrast table from the
counterfactual-debugging subsystem. It computes no fork, no attribution and no verdict, and it contains no stepping
code. Reason: a browser bundle built first becomes a second, unreviewed implementation of replay. A page that only
draws recorded rows cannot disagree with the native harness. For the same reason the fork overlay is enabled only
after the native harness has passed its null-fork and fork-classification gates for the build.

The second choice is honesty about size. The file is capped, the cap is checked against the *encoded* size before a
byte is written, and a request over the cap is refused with a size table and the reductions that would admit it.
Nothing is truncated silently.

This verb is one of the three of seed BD-191 (with `telemetry.stills` and `telemetry.inspect-pixel`, N24a-40). It
embeds the viewer's page bundle (N32b-13), whose probe mirrors pixel inspection, so it is the last of the three to
land and carries the seed's joint check: the three verbs answer on the same runs and `telemetry_stills.sh` passes
with all its groups.

Delivery: the verb's first milestone is the second (a parent world with its overlays), and that is this bead.
Fork timelines and the tables that describe them are part of the same format and are added to the same writer at
the third milestone by N32b-41, which depends on this bead; they are switched on per build when the harness gates
are recorded, and the gate that measures complete packets with 16 forks is a third-milestone gate of the surface
chapter (see `needs`).

## Scope

In: the verb (read; M2); the packet format `frob.replay-packet/1` as bytes in an HTML file, of which this bead is
the only definition for everything a parent-only packet contains: the header, the parent timeline, the overlay
channel columns, how blocks and the page are embedded in the HTML, the `shapes` entry, the anchor cell, the list
of named ticks; the parent-only writer; the size rule and its calculator for any number of timelines, the cap and
the over-cap refusal with reductions; the refusal for frames that are not stored; time decimation that keeps named
ticks; byte determinism; `--check` for the header, the parent timeline and the overlay columns; what a packet may
claim; privacy and sealing; the answer to `--forks` in a build without the fork writer.

Out, with the bead that has it:
- Fork content in a packet (N32b-41, M3): the per-fork header fields, fork timeline blocks with their parent
  prefix, per-fork overlay columns, the tables block, the licence switch with its two refusals, the choice of
  which forks to keep in the "fewer forks" reduction, and `--check` for fork blocks and the tables block. Those
  parts were drafted here too; one definition remains, there. This bead's schema reserves the fields
  (`forks: []`, no tables block at M2) and its size calculator already counts timelines.
- The page that reads these bytes: `PacketSource`, in-page verification, the banner, playback, the rendering
  policy and the in-page probe (N32b-40, which depends on this bead and restates none of the layout); packaging
  the page bundle that this writer embeds (N32b-13).
- Forks, their classification and the contrast table (the fork-harness and attribution beads); the measurement of
  the third-milestone gate (N32b-43) and the kill-gate decision (N32b-32); `run.export` to the episode file
  format.

## Technical approach

**1. Input.** `frob telemetry export-html <run> --world <address> [--episode <n>] [--window <t0>:<t1>] [--fps <n>]
[--overlay <list>] [--forks <list>] [--bodies <subtree>] [--cap <bytes>] [--out <file>] --json`, and
`frob telemetry export-html --check <file> --json`.

**2. Contents, in file order (schema `frob.replay-packet/1`).** One `.html` file that makes no network request.

1. *Header*, canonical JSON: the run, the parent world address and the fork paths (an empty list in a parent-only
   packet); the model, scene, task and policy identities; tier, determinism class and claim class of the source
   run; the tick range and the frame period as a rational; the channel table (name, kind, unit, frame,
   quantization); a BLAKE3 digest per embedded block; the chain digests of the source episode chunks; the
   exporter version; the no-authorization flags (`execution_authorized`, `hardware_safety_signoff`,
   `sim_to_real_certified`, each the constant `false`). Three entries the specification's list does not name and
   a page cannot do without (DESIGN; the first was asked for by the page's bead):
   - `shapes`: the collision primitives of each body and of the scene's analytic elements (boxes, spheres,
     capsules, cylinders, planes, with dimensions in metres; a few hundred bytes per body). Without it a page
     knows where bodies are and not what to draw. Visual meshes are never embedded.
   - `named_ticks`: the ticks that decimation kept out of stride (section 4), each with its name and the index of
     its frame, so that a reader finds them by lookup and not by arithmetic.
   - `anchor_cell`: per timeline, three signed 32-bit integers (see item 2).
   The per-fork header fields are defined by N32b-41.
2. *Timelines*: the parent's, and at the third milestone at most 16 forks' (N32b-41). A frame holds one affine row
   per body: a 3 × 4 matrix in `f32`, 48 bytes, little-endian, row-major, in the anchored convention. A world
   position is an integer cell index plus an `f32` offset from the centre of a cell of side 8 m; 48 bytes hold no
   integers, so (DESIGN) each timeline has one `anchor_cell` in the header, the cell of the world's root body at
   the first tick of the window, and the translation column of every row is the body's offset from the centre of
   that cell, formed as the float offset plus 8 times the integer cell difference. Inside the anchor cell the
   offset lies in [−4, 4) m; a body that leaves the cell has a larger offset, with a resolution of about 2 µm at
   16 m, which is ample for drawing. Rows are for drawing only: every number a reader can probe comes from the
   quantized columns of item 3.
3. *Overlay channels* as quantized columns in the layout of the episode file: contact cones, energy flow, actuator
   state, the seven instants of a sensor sample, as selected.
4. *Tables* (third milestone, N32b-41): the fork classification of each fork, the contrast table with flip rates
   and the placebo flip rate, and the labels of the attribution subsystem. Text is the text the verbs returned,
   copied, not recomputed. A parent-only packet has no tables block.
5. *The page*: script and styles inline.

**How the parts sit in the HTML (DESIGN; this is the interface the page's `PacketSource` reads).** The header is
the text of `<script type="application/json" id="frob-header">`. Each binary block is Base64-encoded as the text
of `<script type="application/octet-stream;base64" id="frob-block-<n>">`, with n the block's index in the
header's digest list. The BLAKE3 digest of the header's bytes is written by the exporter in a trailing HTML
comment `<!-- frob-header-digest: <hex> -->`, the last bytes of the file. The page bundle (N32b-13) contains
exactly one placeholder comment, `<!--FROB-PACKET-BLOCKS-->`: the writer replaces it by the header element
followed by the block elements in index order, appends the trailing comment after the bundle's last byte, and
changes no other byte of the page, so that a reader can undo the insertion and compare what remains with the
committed bundle (N32b-40 does). The header's `/authorization` object holds the three flags; a string member
`banner` beside them is reserved for the generated no-authorization sentence, which the M2 flag-carrier bead
N37p1-01 writes there from `frob_core::auth::banner` (that bead depends on this one; the writer of this bead
does not emit the member, and the page shows it as the first line of its banner when it is present). The
file's content security policy has an empty `connect-src`, so the page can issue no request. Text in the header that originated in an import (a
design name) is data and is never markup.

**3. The size rule.** Timeline bytes = 48 · bodies · frames · timelines. Base64 multiplies by 4/3. DESIGN: the whole
file is capped at 8 MiB = 8,388,608 bytes by default (TARGET), with 600,000 bytes budgeted for the page, so the
binary payload may not exceed (8,388,608 − 600,000) · 3/4 = 5,841,456 bytes.

| Case | Binary bytes | Encoded bytes |
|---|---|---|
| Quadruped, 13 bodies, 3 s at 50 frames per second (150 frames), parent and 16 forks (17 timelines) | 48 · 13 · 150 · 17 = 1,591,200 | 2,121,600 |
| Humanoid, 30 bodies, same window and timelines | 3,672,000 | 4,896,000 |
| Quadruped, parent only (the second-milestone case) | 48 · 13 · 150 = 93,600 | 124,800 |
| Counterexample to budgeting by payload size: 6,200,000 bytes of rows | under the cap as binary | 8,266,667 encoded; 8,866,667 with the page: over |

The writer therefore computes the encoded size before it writes anything: the sum over blocks of the Base64 length,
plus header, tables and the page's actual byte count. The size table printed to the user states ⌈4·n/3⌉ per block
as above; the decision uses the exact encoded length including padding (at most 2 bytes more per block). The
header's `shapes`, `named_ticks` and `anchor_cell` entries are part of the header and so of the sum. A request
over the cap is refused with the size table and the three reductions that would admit it: half the frame rate;
fewer forks; bodies restricted to a named subtree. `--cap` may lower the cap, or raise it to at most 15,000,000
bytes, the ceiling stated for an exported replay.

**4. Decimation.** When `--fps` is below the stored rate, frames are taken at the requested period; decimation in
time always keeps the fork tick, the first-divergence tick and the failure tick (and, DESIGN, the tick at which the
verdict was decided), inserting them as extra frames with their exact times and listing them in the header's
`named_ticks`. A parent-only packet has the failure tick and the decision tick; the other two exist only with
forks.

**5. Refusals.** Four of the packet itself, with the codes and exits the surface chapter's refusal registry
(N32-REF) assigns, and four of the export path (5b); none produces a partial file, and each carries a reason
and repairs.
(a) A packet over the cap: `FROB-REF-836` (provisional number), exit 3, with the size table and the reductions.
(b) Frames requested from a chunk that is neither stored nor pinned: `FROB-REF-837` (provisional number), exit 3,
naming the chunk keys and their retention state.
(c) A fork overlay requested for a run whose determinism class does not license replay (a tolerance-class or
unspecified-class run cannot support a bit-level ghost): `FROB-REF-562`, exit 3.
(d) A fork overlay requested before the harness gates have passed for the build: `FROB-REF-724`, exit 5 (fork
content is then a capability this build does not have; an earlier draft of this bead gave every packet refusal
exit 3).
This bead implements (a) and (b). Of the fork refusals it implements only the M2 form of (d): until the fork
writer of N32b-41 is in the build, any request with `--forks` is answered with `FROB-REF-724`, and a parent-only
export still works. The licence switch itself (the gate-register read for (d), the class test for (c)) is
N32b-41.

**5b. The export path: four more codes.** `--out` writes a file outside the store, so this verb is an exporter:
its registry row has `exports = true`, the capability `export:report` beside `telemetry:read`, and the chapter
codes 731, 733, 734 and 816 beside the four above. Before any byte is written the handler makes, in this order,
the checks every exporter of the record crate makes (the same four as `run.export`, N29a-02):
1. *Privacy.* The packet's privacy mark is the join over the run's inputs (scene, design, policy). A private
   run without the `private:export` scope and the per-call private-export flag is `FROB-REF-731`, exit 5, with
   the private input as `pointer` and the reason (`missing-scope` or `missing-flag`).
2. *Licence.* A licence set of an input that forbids exporting a replay is `FROB-REF-733`, exit 5.
3. *Flags.* An input artifact whose three no-authorization flags are missing or not the literal `false` is
   `FROB-REF-816`, exit 3 (the check `frob_core::auth::check_carried` of N37-23; the packet's own carrier is
   the header's `/authorization` object, item 1 of section 2).
4. *Destination.* `--out` is opened through the retained directory handle of the session's export root (the
   path jail, N37-11): `..`, an absolute path or a link that leaves the root is `FROB-REF-734`, exit 5. The
   file is written under a temporary name in the same directory and renamed, so a refused or interrupted
   export leaves nothing at `--out`.
From the third milestone the export door of the safety chapter (`frob_verbs::export::admit`, N37-18) makes
these four checks for every exporting verb in one place; that bead replaces the handler's own calls by the
door, and the codes, exits and order do not change. Without `--out` the packet is stored as an artifact and
returned as a handle; reading that artifact back is subject to the same privacy mark.

**6. Determinism and read-back.** The same run, options and exporter version produce the same bytes: canonical
JSON, fixed block order, no timestamps, no host names. `--check <file>` recomputes every block digest and compares
it with the source chunks; when the source has been evicted it reports `source: evicted` and checks internal
digests only. Its answer lists per block `match` or `mismatch` (with the block index and the first differing byte
offset) and `source: present | evicted`; it exits 0 when every block matches and 2 when any does not (DESIGN: a
corrupted packet is a finding of the read, not a refusal of the request, so the surface's exit 2 "done with
findings" applies; a file that is not a packet at all is `FROB-REF-802`, exit 3). The in-page probe is the equivalent of `telemetry.inspect-pixel`: it returns the channel, unit, world
address and tick of the quantity under the pointer, so every number a viewer reads is a stored value.

**7. Rendering constraints the writer must respect.** The page draws with WebGL 2; WebGPU is used only when the
page reports a secure context and an adapter (FACT, to be re-read from the primary source before a gate cites it:
WebGPU is exposed only in secure contexts, and whether a file opened from disk is one is left to the browser, so a
packet that required WebGPU would not open everywhere). No frame-rate figure is claimed. The writer embeds only
what the WebGL 2 path needs.

**8. What a packet may say.** The claim class of its source and nothing higher. Fork overlays carry the fork's
label, attributions are `Estimated`, and the header repeats the no-authorization flags. A packet is a view:
importing one creates no evidence, and no verb accepts a packet as input other than `--check`.

**9. Privacy and sealing.** A packet of a private scene is a private artifact and the export requires the caller's
scope and flag (`FROB-REF-731`, check 1 of 5b; the header and the artifact record carry the private mark when
the export is admitted); a run in the blinded confirmation lane cannot be exported before its campaign closes
(FROB-REF-840).

**10. Output of the verb.** The file's path or artifact handle, its byte size against the cap, the size table, the
digest of the file, the list of blocks with digests, the options used, the embedded page as `page: { "bytes",
"manifest_digest" }`, and the envelope's evidence block. The two `page` values are the constants
`frob_chronicle::viewer_page::LEN` and `viewer_page::MANIFEST_DIGEST` of the committed page bundle (N32b-13),
the same `LEN` the size computation of section 3 uses: an export therefore names exactly which page it
embedded, and the page bead's end-to-end script (N32b-40) compares the pair with the committed
`page.manifest.json`.

## Acceptance criteria

- [ ] `frob telemetry export-html <run> --world <w> --json` writes one HTML file for the docking-cart fixture and
      for the split-grip quadruped fixture (parent only at this milestone), each at most 8,388,608 bytes, containing
      no URL that the page fetches.
- [ ] Two exports with the same options are byte-identical.
- [ ] `--check` reports every block digest equal to the source's; after eviction of the source it reports
      `source: evicted` and verifies internal digests; a flipped byte in any block is detected.
- [ ] The four sizes of the table are reproduced by the size calculator; the 6,200,000-byte request is refused with
      8,866,667 printed and the three reductions listed.
- [ ] Decimation to half rate keeps the failure tick and the decision tick as frames.
- [ ] At this milestone a request with `--forks` is refused with `FROB-REF-724` (exit 5) and writes no file. (The
      refusal under a determinism class that does not license replay, and the bit-equality of a null fork's rows
      with its parent's once the gates are recorded, are acceptance of the fork writer N32b-41.)
- [ ] The header carries `shapes` for every body of the timeline, `named_ticks` and `anchor_cell`; the header and
      each block are found under the element identifiers stated above; the trailing comment carries the header's
      digest; the file's content security policy has an empty `connect-src`.
- [ ] 100 probe points read from the packet's columns equal `telemetry.query` within channel quantization.
- [ ] The header carries the source's claim class and the three flags, all false.
- [ ] The export path refuses before writing: a private run without the scope and flag is `FROB-REF-731` (exit
      5); a licence that forbids export is `FROB-REF-733` (exit 5); an input whose flags are missing or not
      `false` is `FROB-REF-816` (exit 3); an `--out` that leaves the export root by `..`, an absolute path or a
      link is `FROB-REF-734` (exit 5); in each case no file exists at the destination afterwards.
- [ ] Every export envelope reports `page.bytes` and `page.manifest_digest`, equal to `viewer_page::LEN` and
      `viewer_page::MANIFEST_DIGEST` and to the committed page manifest.
- [ ] Reachable over MCP as `telemetry_export_html`.
- [ ] Joint check of seed BD-191: `scripts/e2e/telemetry_stills.sh` passes with its `stills-*`, `pixel-*` and
      `replay-*` groups on the same runs, and `telemetry.stills`, `telemetry.inspect-pixel` and
      `telemetry.export-html` answer through the command line and MCP.

## Test plan

### Unit tests

`crates/frob-chronicle/tests/replay_packet.rs`.

- `size_table_known_answers`: 1,591,200 → 2,121,600; 3,672,000 → 4,896,000; 93,600 → 124,800; payload cap
  5,841,456.
- `over_cap_refused_before_write`: 6,200,000 bytes → refusal printing 8,866,667; the output path does not exist
  afterwards.
- `exact_base64_length_used_for_decision`: a payload whose ⌈4n/3⌉ estimate is at the cap and whose padded length
  exceeds it is refused.
- `reductions_listed_and_sufficient`: each listed reduction, applied, yields a size under the cap or is omitted.
- `frame_row_layout`: one body's 3 × 4 `f32` row is 48 bytes, little-endian, row-major; decodes to the stored pose.
- `decimation_keeps_named_ticks`: the failure tick and the decision tick are frames and are listed in
  `named_ticks` with their frame indices.
- `byte_determinism`: two writes, equal digests; a build with a timestamp planted differs.
- `check_detects_flip`; `check_source_evicted`.
- `refusal_chunk_not_stored` (`FROB-REF-837`, exit 3); `over_cap_is_836_exit_3`; `forks_option_is_724_at_m2`
  (exit 5, no file). The fork tests drafted here have one copy each, in N32b-41: `fork_block_starts_at_fork_tick`
  (a fork at tick 90 stores frames from 90 on and a reference to the parent block), `null_fork_bit_equal`,
  `licence_class_is_562`, `licence_missing_gates_is_724`.
- `embedding_elements`: the header parses from `#frob-header`; block n decodes from `#frob-block-<n>` and hashes to
  the header's digest n; the trailing comment's digest equals the header's.
- `page_bytes_unchanged_around_blocks`: in a written packet, replacing the inserted header and block elements
  by `<!--FROB-PACKET-BLOCKS-->` and removing the trailing comment gives back `viewer_page::BYTES` exactly; a
  bundle with no placeholder, or with two, is refused at build time.
- `shapes_cover_every_body`; `anchor_cell_roundtrip` (a body 20 m from the world origin: the row's translation plus
  8 times the anchor cell reproduces its stored position to within single-precision spacing at that offset).
- `header_flags_false_and_claim_not_raised`: a source of class `Tested` cannot yield a header that says more.
- `private_scene_export_refused_731`: a run on a scene pack marked private, exported with `--out` by a session
  without `private:export` → `FROB-REF-731`, exit 5, `pointer` the scene, no file; with the scope and without
  the per-call flag → 731 with reason `missing-flag`; with both → the file is written, its header carries the
  private mark and the artifact record is private.
- `licence_forbids_export_733` (exit 5); `input_flags_816` (a run whose scene artifact lacks
  `execution_authorized` → exit 3); `out_path_jail_734` (`..`, an absolute path, a link swapped to point
  outside the root: each exit 5, nothing written outside the export root, no temporary file left).
- `export_checks_precede_writing`: with a destination that is both outside the root and for a private run, the
  answer is 731 (the first check), and the directory listing of the export root is unchanged.
- `envelope_reports_page`: `page.bytes == viewer_page::LEN`, `page.manifest_digest ==
  viewer_page::MANIFEST_DIGEST`, and the size table's page line equals `page.bytes`.
- `no_network_reference`: the produced file contains no `http:`, `https:` or protocol-relative URL outside the
  embedded licence text allow-list.

### End-to-end script and logging

Steps `replay-*` of `scripts/e2e/telemetry_stills.sh` (owned by BD-191; this bead adds the group): `frob telemetry
export-html` on the two
fixtures; a second export and a byte comparison; `--check` on each file (exit 0, every block `match`); `--check` on
a copy with one byte flipped (expects exit 2 and that block named `mismatch` with its byte offset); the over-cap request (expects exit 3 and the printed size); 100
probe values extracted from the file by the conformance helper and compared with `frob telemetry query`. Opening
the file in pinned browsers under a headless driver with the network disabled belongs to the third-milestone gate
script of the surface chapter; this script asserts only what the writer controls. NDJSON lines carry the command,
exit code, wall time, the evidence block, file bytes against the cap, the size table, digests compared, probe
mismatches against threshold 0, and on failure the first differing block or probe with the file path.

### Known answers and negative controls

- The four sizes above; the payload cap 5,841,456 bytes; the refused request printing 8,866,667.
- A null fork drawn as a ghost coincides with its parent: the rows are bit-equal, so the deviation is exactly zero
  in every frame (a known answer of the format; tested by N32b-41, where fork rows are written).
- A probe value equals the telemetry channel within its quantization.
- Negative control 1: a writer that checks the binary payload against the cap admits the 6,200,000-byte request;
  `over_cap_refused_before_write` must fail it.
- Negative control 2: a writer that truncates the timeline to fit; the frame count in the header no longer matches
  the request and the test must fail.
- Negative control 3: a packet that recomputes a pose by interpolation in the exporter; `--check` against source
  chunks must fail.
- Negative control 4: a header that upgrades the claim class.
- Determinism lanes: byte equality twice on one machine, debug and release, Linux and macOS.

## Considerations

- Kill gate named in advance (decided by the surface chapter's bead): KILL-REPLAYPACK. Trigger: the
  third-milestone packet gate fails after one repair cycle, or the page cannot be held to its byte budget.
  Fallback: `run.export` to the episode file, stills with overlays and the live viewer; no single-file packet. A
  build packet of the manufacturing chapter may include a replay packet as an optional file and never depends on
  one.
- The 600,000-byte page budget is tight for a vendored 3D library; a reduced build of the library is the viewer
  owner's problem, and this writer measures the page's real size instead of assuming the budget.
- Two size figures exist in the specification: a 15 MB ceiling stated with the overlay table and the 8 MiB default
  cap stated with the packet. This bead treats 8 MiB as the default and 15,000,000 bytes as the highest value
  `--cap` accepts.
- A packet contains scene geometry only as body poses and overlay values, but that is still scene data: private
  scenes need the scope, and the end-to-end log never embeds packet bytes.
- What would make us revisit: a need for interaction beyond replay (stepping, editing). That would require stepping
  code in the page and is exactly what the order of construction forbids.
