## Background

The requirement language decides whether a mission was accomplished. Its pieces are built and unit-tested by a
dozen beads of the crate `frob-spec` (schema and identity of the task file, the S-expression view, the syntax tree
and margins, the unit checker, clocks and windows, the online kernels, the referee's deque monitor, the offline
evaluator, the boundary guard, the verdict record, labelled examples, the consumer rules). A user never meets those
pieces. A user writes a task file, asks whether it is well formed, runs a robot, and asks for the verdict. This
bead is the end-to-end test of that capability from the user's side: one shell script that drives the real `frob`
binary through the whole path on real recorded runs, with the planted failures that each piece must catch.

The script is also where gate GATE-ARENA-03 (claim: Known answer; first milestone) is measured and recorded:

> Monitors: the three evaluators agree bit for bit on 10⁶ random traces per operator, including multi-rate signals
> and windows with rounding; every requirement-language refusal (FROB-REF-520, -535, -536, -523, -538, -525, -526,
> -539 and -528) is triggered by its planted task file.

The first half is the differential campaign assembled by the language-core bead (BD-121); the second half needs the
task-file verbs (BD-122) and nine planted files. Neither half alone is the gate, so this bead measures the whole
gate: its script runs the campaign's script as a stage, reads the refusal rows' receipt of N24c-06, and writes one
joined receipt, from which the gate is recorded once (convention 9).

The reference task throughout is the threshold-delivery fixture: a loaded cart crosses a 12 mm door sill and docks
on the run-out. Its requirement, in the S-expression view, is the file the steps below author, check and evaluate:

```lisp
(requirements
  (atom cleared    (>  (- env_min_x 0.10 m) 0 m)                    :scale 0.10 m)
  (atom upright    (>= (- 5 deg tilt) 0 deg)                        :scale 5 deg)
  (atom tilt-ok    (>= (- 35 deg tilt) 0 deg)                       :scale 35 deg)
  (atom current-ok (>= (- 6.01 A i_max) 0 A)                        :scale 6 A)
  (atom no-strike  (=  strikes 0)                                   :exact)
  (atom saturated  (=  drive_saturated 1)                           :exact)
  (atom advancing  (>= (- x_front (delay 0.5 s x_front)) 0.002 m)   :scale 0.002 m)
  (online dwell    (H (0 s 0.5 s) (and cleared upright)))
  (online stalled  (and (H (0 s 0.5 s) saturated) (not advancing)))
  (verdict docked  (U (0 s 8 s) (and tilt-ok current-ok no-strike) dwell)))
```

Clocks: physics 1/2000 s; requirement clock 1/100 s; atoms are interval extrema over the 20 physics ticks of each
requirement tick. The horizon is 8 simulated seconds.

## Scope

In: `scripts/e2e/arena_requirement_pipeline.sh`; the fixture directory `fixtures/e2e/requirements/` (the golden
task, its key-shuffled twin, further planted files of the mechanism beads, three golden recorded runs and one
truncated export with their golden values, the docking-boundary task, the sled task and its amendment); the step
groups named by the mechanism beads; the campaign stage (BD-121's script, the three evaluators on 10⁶ traces per
operator, run here and its receipt read); the helpers of `frob-conformance` that compare recorded values with
N24a-04's definitional evaluator; negative-control builds; the structured log; the receipt of GATE-ARENA-03 (host
half), which joins the campaign's monitor-row receipt with the refusal-row receipt written by
`scripts/e2e/arena_task_file.sh`.

Out: the nine planted refusal files driven through the task-file verbs, and the receipt of the refusal rows
(N24c-06; this script reads that receipt and repeats one planted file per code only as a smoke step); the campaign
and its registered controls (BD-121's `spec_differential_campaign.sh`); the two recorded docking runs (N20b-13,
read in place); the mechanisms themselves; the device half of the gate (batched monitors, and the guard-band decision that blocks
it); the settled-pose cache script (N24a-16); scorecards and reproducibility (N24a-24); the requirement-writing
gate with a fresh agent (BD-256).

## Technical approach

**1. Fixtures.** The planted files of record for the nine refusal codes are the task-file bead's
(`crates/frob-arena/tests/fixtures/tasks/refusals/ref-<code>.ftask`, BD-122), which `scripts/e2e/arena_task_file.sh`
(N24c-06) drives and records for the gate. The `planted/` files below are this script's own second mutations of
the same reference task, one per code (two for 525 and for 539), chosen to differ from the files of record where a
code has more than one trigger (a missing window as well as an unbounded one for 536; two signals of different
dimension as well as a literal for 535; the capacity edge for 528), so that the smoke step adds coverage instead of
repeating it.

**2. Step groups, in order.** Each step is a `frob … --json` command and assertions on its envelope.

1. `ftask-*` (N24a-02): `frob task new fixture1.ftask.json --key arp-ftask-json --json`; `frob task show <id>
   --json`; `frob task new fixture1.shuffled.ftask.json --key arp-ftask-shuffled --json` (a key of its own: under
   the first call's key the second call would return the first one's stored receipt and the identity check would
   pass vacuously); assert both envelopes carry the same task identity; `frob task list --json` shows one task.
2. `sexpr-view` (N24a-03): `frob task new fixture1.ftask.sexp --key arp-ftask-sexp --json` returns the same
   identity; `frob task show <id> --as sexpr` (the view flag of BD-122) equals the input up to whitespace, comments
   and the one number rule of the canonical form (the authored `0.10 m` is printed `0.1 m`; each rewritten literal
   is logged).
3. `units-*` (N24a-05), `clocks-*` (N24a-06): `frob task check <id> --json` on the golden task (exit 0), whose
   report gives the resolved tick windows (the dwell window is ticks 0 to 50, the until window 0 to 800) and the
   reduction table (each atom reduced by its matching extremum over 20 physics ticks).
4. `refusals-*` (the gate's second half, repeated here as a smoke step on this script's second mutations; the
   rows of record are N24c-06's): `frob task check` (or `task new`, whichever admits) on each planted file of the
   nine codes; each must exit 3 with exactly its code, a pointer to the offending node, and ranked repairs. A
   table-driven loop; the log records one line per code.
   `task.verdict` has no evaluator selector and no recomputation option: it answers with the offline evaluator
   (N24c-02). Steps 5 and 6 therefore compare the verb's answers and the recorded online values with N24a-04's
   definitional evaluator through this bead's helpers in `frob-conformance` (unit tests below), which link the
   evaluator as a library and are run by the script on the files the steps produce.
5. `definitional-eval` (N24a-04): `frob task verdict runs/docks.frun --task <id> --json` and the same on `strike`;
   then `FROB_E2E_ARTIFACTS=<this step's artifact directory> cargo test -p frob-conformance
   e2e_requirements::definitional_matches_golden`, which evaluates both runs with the definitional evaluator and
   asserts that verdict, margin, binding atom and binding time equal the golden values on file and the saved
   envelopes of the verb.
6. `online-kernels` (N24a-07) and `deque-monitor` (N24a-08): `frob sim run <cart design> --task <id> --tier
   referee --key arp-online-nominal --json` on the fixture's nominal case with online signals recorded; `frob
   telemetry query <run> --channels dwell,stalled --json` and `frob telemetry query <run> --channels <the seven
   atom channels> --json` (N24a-36's spelling; each paged with `--cursor` to its end and saved to the artifact
   directory); `FROB_E2E_ARTIFACTS=<dir> cargo test -p frob-conformance e2e_requirements::online_matches_definitional`:
   the recorded online values equal the definitional evaluator's recomputation from the atom columns at every tick,
   bit for bit, for each formulation the run recorded (the block kernel, N24a-07; the deque, N24a-08); and `frob
   task verdict <run> --task <id> --requirement dwell --json`: the recorded `dwell` at the last tick equals the
   offline evaluation of the same formula (KA-596 from the user's side).
7. `offline-*` (N24a-09): `frob task verdict <run> --json` on the three runs and the truncated export: `verdict`,
   `decided_at_s`, `binding_atom`, `coverage`; the truncated one is `undetermined` with its reason and no value
   from the part that exists.
8. `boundary-*` (N24a-10): `frob task new docking-boundary.ftask.sexp --key arp-docking-task --json`; `frob task
   verdict crates/frob-conformance/fixtures/docking/runs/docking-u34-e516.frun --task <docking TaskId> --json`
   (expects `violated`, `boundary.flagged = true`, exact rational arithmetic) and the same on
   `docking-u34-e14.frun` (expects `satisfied`); the runs record no task, so `--re-evaluate` is not needed
   (N24c-02's rule for synthetic traces) and the records are labelled `synthetic`; then the 65,536-case boundary
   screen as the Gauntlet row, `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g1_known_answers --
   KA-615`, with zero final errors under the guard and the receipt hash logged.
9. `verdict-record-*` (N24a-11): `frob task verdict` twice on one run (equal `trace_digest`, byte-identical
   result); `frob run show` confirms the ledger row; a scratch copy of the run with its reward channel rewritten
   yields identical verdict bytes (a verdict never depends on a reward term).
10. `examples-*` (N24a-12): `frob task check` on the golden task (no vacuous atom), on `sled` (exit 3,
    FROB-REF-539 with a pointer to the example), on `sled.amended` (exit 0), on the vacuous hard-limit file (exit
    3, FROB-REF-539 with a pointer to the atom).
11. `consumers-*` (N24a-13): three referee runs with termination on the decision signal: episode length equals the
    decision tick, and `frob task verdict` on each returns the same verdict with equal `decided_at_s`; then `frob
    task check <task> --overlay planted/overlay-edits-scale.json` exits 3 with FROB-REF-103 and the same call with
    `overlay-reward-weight.json` exits 0 with the `TaskId` unchanged.
12. `gate-arena-03-monitors` (BD-121): BD-121's `scripts/e2e/spec_differential_campaign.sh --seed <campaign
    seed>` run as a stage (its `campaign` step is the Gauntlet row KA-597 in tier `g5_determinism`, its `controls`
    step the registered negative controls with `--features gauntlet-mutations`); this step asserts zero mismatches
    for each of H, O, S, G, F, U and for the nested campaign, every control `caught`, and reads back the stage's
    receipt hash.
13. `gate-receipt`: joins the stage's campaign receipt with N24c-06's refusal-row receipt (read from
    `target/e2e-logs/arena_task_file/receipts/`; a missing or failed one fails the step) into the hash-named
    receipt of GATE-ARENA-03 (host half): traces per operator, mismatches, the controls caught, the nine refusal
    rows with the code observed, the commit, seeds and hardware fingerprint, and the device half as `not run`. The
    script writes no gate row (one recorder per gate): the gate's value is recorded from that receipt with
    `cargo run -p frob-conformance --example record_gate -- --gate GATE-ARENA-03 --receipt <hash>` by a session
    that did not implement the evaluators.

**3. Negative-control builds.** `--control <name>` runs the relevant group against a build with one planted defect
behind a test-only feature and asserts that the named step fails:

| Control | Planted defect | Step that must fail |
|---|---|---|
| `pad-short-window` | A monitor that pads a window the trace does not cover | `gate-arena-03-monitors`, `offline-truncated` |
| `deque-expiry-off-by-one` | The deque drops a sample one tick late | `gate-arena-03-monitors`, `deque-monitor` |
| `block-suffix-off-by-one` | The block kernel's suffix index is shifted | `gate-arena-03-monitors`, `online-kernels` |
| `raw-margins` | Composition of raw margins with no scales | `units-binding` (the binding atom changes between metres and millimetres) |
| `sign-as-boolean` | The sign of the margin used as the Boolean value at zero | `boundary-docking` |
| `float-window` | A window bound converted through floating point | `clocks-windows` |
| `latched-dwell` | The dwell computed by a latched timer | `offline-never` (a run that lapses after 0.4 s is wrongly `satisfied`) |
| `reward-in-verdict` | The verdict reads a reward channel | `verdict-record-purity` |
| `refusal-swallowed-<code>` | The check for one code disabled (nine variants) | `refusals-<code>` |

**4. Idempotence, seeds, cost.** All commands carry explicit seeds and idempotency keys. The campaign step is the
expensive one (minutes on a many-core host); `--quick` runs the stage with `E2E_SMALL=1` (10⁴ traces per
operator) for per-change use, and the joined receipt then carries the stage's `gates_claimable: false`, so it
cannot be entered as the gate.

## Acceptance criteria

- [ ] The script exits 0 on a correct build and non-zero on any failed assertion; a second run is idempotent.
- [ ] GATE-ARENA-03, host half: 10⁶ traces per operator with zero mismatches among the three evaluators (TARGET),
      including multi-rate signals and windows with rounding; each of the nine refusal codes is triggered by its
      planted file. The joined receipt holds measured values; the script writes no gate row, and the gate is
      recorded from the receipt with `record_gate`.
- [ ] The two docking runs are read from N20b-13's committed files (no copy under `fixtures/e2e/`), and their
      verdicts are `violated` with the boundary flagged in rational arithmetic and `satisfied`.
- [ ] Both views of the golden task and its shuffled twin yield one task identity.
- [ ] The three golden runs and the truncated export return the stated verdicts; the truncated one is
      `undetermined`.
- [ ] Every negative-control build fails its named step.
- [ ] The log is written as specified below; the summary line names GATE-ARENA-03.
- [ ] The device half is reported as `not run: waits for batched monitors and the guard-band decision`, never as
      passed.

## Test plan

### Unit tests

Helpers in `frob-conformance` (`cargo test -p frob-conformance e2e_requirements`):

- `planted_table_complete`: the table of planted files covers exactly the nine codes 520, 535, 536, 523, 538, 525,
  526, 539, 528; removing a row fails.
- `refusal_matcher`: an envelope with the right code and a missing pointer is rejected.
- `sexpr_whitespace_normalizer`: two texts differing only in whitespace, comments and the printing of one
  magnitude (`0.10 m` against `0.1 m`) compare equal; a changed number (`0.10 m` against `0.11 m`) does not.
- `golden_verdict_loader`: golden values load with exact rationals for times (`"8"`, `"1/2"`).
- `quick_receipt_not_claimable`: joining a campaign receipt with `gates_claimable: false` yields a joined receipt
  with `gates_claimable: false`; a joiner that drops the mark fails the test; a missing refusal-row receipt is an
  error, never an empty row set.
- `definitional_matches_golden`: with `FROB_E2E_ARTIFACTS` unset it runs on the committed `runs/docks.frun` and
  `runs/strike.frun` and their golden values; the definitional evaluator's verdict, margin, binding atom and
  binding time equal the golden values and, when saved envelopes are present, the verb's; a golden margin changed
  in its last bit fails it.
- `online_matches_definitional`: with `FROB_E2E_ARTIFACTS` unset it runs on the online and atom columns of the
  committed `runs/docks.frun`; every recorded online value equals the definitional recomputation bit for bit; a
  copy with one value moved by one ulp is reported at that tick with both bit patterns in hexadecimal.

### End-to-end script and logging

`scripts/e2e/arena_requirement_pipeline.sh [--quick] [--control <name>] [--group <prefix>]`, as above. It sources
the shared helper of the end-to-end standard and writes newline-delimited JSON to
`target/e2e-logs/arena_requirement_pipeline/<utc-timestamp>.ndjson` and a transcript beside it. Every line has
`ts`, `script`, `bead` (the owner of the step group), `step`, `event` (`start`, `cmd`, `assert`, `metric`,
`refusal`, `end`), the exact command line, exit code, wall time, the envelope's `evidence` block (claim, class,
tier, determinism, identities, seed), measured values with units and thresholds (traces run; mismatches against 0;
ticks compared; margins against golden values; resolved tick windows against expected counts; mutants formed and
killed), the refusal block (`code`, `pointer`, `observed`, `required`, `unit`, repairs) for refusal steps, the
digests compared (`TaskId`, `trace_digest`, receipt digest), and on failure the first differing tick with both bit
patterns in hexadecimal and the paths of the run and of the regression file. The final `summary` line gives
assertions passed and failed and the gate touched.

### Known answers and negative controls

- KA-597: three evaluators, 10⁶ random traces per operator, agreement bit for bit; the planted task files trigger
  every listed refusal.
- KA-596: a past-time signal sampled at the end of the trace equals the offline evaluation of the same formula.
  Control: `pad-short-window`.
- KA-594: clearance margin 0.02 m and thermal margin 3 K with scales 0.10 m and 10 K give margins 0.2 and 0.3 in
  either unit system; the clearance binds in metres and in millimetres. Control: `raw-margins` (raw minimum 0.02 in
  metres, 3 with the clearance in millimetres).
- KA-615: at U = 3/4 and ε = 5/16 the strict docking requirement fails; the 65,536-case screen has no final error
  with the guard. Control: a non-strict comparator admits the equality case; unguarded single-precision comparison
  misclassifies the screen (452 false admissions and 23,438 false exclusions in the recorded planning run).
- Hand case of the sled: constant 1 m/s through x ∈ [4.9, 5.1] m gives a dwell of 0.2 s; the amended requirement
  with a 2 s dwell is violated by the sled and satisfied from t = 8 s by a body at rest at x = 5 m from t = 6 s.
- Metamorphic relations: MR-19 (unit scaling leaves normalized margins and the binding atom unchanged), MR-20
  (streaming equals offline), MR-35 (canonical form: reordering keys leaves the identity unchanged).
- Determinism lanes: twice on one machine; worker counts 1, 8 and 36 for the campaign (same receipt digest); debug
  and release; Linux and macOS.

## Considerations

- The companion script for the task-file verbs alone is `scripts/e2e/arena_task_file.sh` (N24c-06), on BD-122's
  files of record. The list of the nine codes is one constant in `frob-conformance`: `planted_table_complete`
  checks this script's table against it, and the companion script's bead is asked to check the files of record
  against the same constant, so that a code added to the gate must gain a file of record and a second mutation.
- The guard-band open question (default 2⁻²¹ with CPU re-evaluation of every flagged atom; owner: the GPU backend
  lead) blocks only the device half; this script never reports that half.
- The golden runs are recorded once by the fixture bead and stored by digest; if the fixture's constants change,
  its identity changes and the golden values must be re-derived, never edited in place.
- Logs carry identifiers and digests of runs, never traces of private scenes.
