## Background

`telemetry.stills` draws a picture of a recorded instant for an agent that can see, and `telemetry.inspect-pixel`
returns what is under a pixel for an agent that cannot. The rule that ties stills to the browser viewer is one
sentence of the surface chapter: *stills carry the same overlays* as the viewer, "so an agent that cannot see
still reads every overlay". The viewer's table has ten overlays. The stills verb (BD-191, second milestone)
draws the five whose channels exist at that milestone: `contact-cones`, `energy`, `actuator`, `balance` and
`sensing`. It lists `film` and `clearance` as "third milestone" without building them, and it has no row for
the other three. The page's side of all five later overlays is N32b-12; nothing carried the stills side, while
the viewer conformance gate (N32b-14, GATE-TETHER-14) probes a film patch, a doorway and a null-fork ghost
through `telemetry.stills` and `telemetry.inspect-pixel` and requires the still to agree with the page.

This bead is that stills side: the five later overlays in the stills renderer (Rust, in the record crate
`frob-chronicle`, beside BD-191's five), with their per-pixel value buffers so that pixel inspection answers
for them. It matters more than symmetry. If the kill gate of the offline replay packet fires and live mode is
not shipped, no page draws a recorded episode at all, and stills with overlays are then the only picture of a
counterfactual fork an agent or a person can get (the fallback named in N32b-32).

The rule for every overlay is unchanged: it draws a stored quantity from a named channel or record, with its
unit, a numeric legend and the evidence class of the run; it is a pure function of stored data; it never
estimates, and when its data are absent it is refused with the list of overlays that are available. Stills and
the page share overlay identifiers, channels, units and legend ranges, not code (the lint of N32b-11 compares
the two tables). Tier: Solid. Rejected: rendering the page headlessly to make stills (a still would then need a
browser, and the page draws the visual mesh where stills must show the collision field).

## Scope

In: the overlay identifiers `film`, `clearance`, `ghost`, `world-diff` and `reality-band` on `telemetry.stills`;
their elements, legends and overlay value buffers; the options `--fork` and `--band`; their refusals; the
answers `telemetry.inspect-pixel` gives for them; their rows in the stills overlay table that the lint of
N32b-11 reads; the step group `late-overlays-*` of `scripts/e2e/telemetry_stills.sh`.
Out: the stills verb, frame selection, sheet layout, storage and the five second-milestone overlays (BD-191);
pixel addressing and the answer format (N24a-40); the page's drawing of the same overlays (N32b-12); computing
film state (BD-230), clearance complexes (BD-233), forks and first divergences (BD-205, BD-206), the pairing of
a fork with its parent (N27b-17), counterexample worlds (BD-274) or bands (BD-393, fifth milestone); the first
run of `reality-band` on a band the real verb issued (a step of N32bp2-44's script at the fifth milestone).

## Technical approach

**1. Input.** `--overlay` of `telemetry.stills` accepts five more identifiers, the same spellings as the page's
(N32b-12). Two options are added (DESIGN; requested of the verb's registry row):
- `--fork <fork path>` (repeatable, at most four): the forks whose ghosts are drawn by `ghost`. The null fork
  of the world's fork point may be named like any other. A path that is not a fork of the still's world, or a
  fifth path, is `FROB-REF-802`.
- `--band <result handle>`: the stored result of a `ground.band` call for this run (an envelope of output
  schema `frob.ground.band.out/1`), which `reality-band` draws. Without it the overlay shows the run's own
  `reality:` line, which is `no-claim` for every run before imported measurements exist.

**2. The overlays.** Each element writes, for every pixel it covers, an entry of the overlay value buffer: the
stored value in its own quantization and the element's address (N24a-40 returns it; nothing is decoded from a
colour).

| Overlay id | Drawn on the still | Value under a pixel | Data |
|---|---|---|---|
| `film` | Floor pixels inside a film patch coloured by thickness on a fixed sequential scale; patch outlines; the film state of the drawn tick where the film is per-world and time-varying | `film.thickness` (m) and `film.mu_eff` (dimensionless) of the stored field cell under the pixel; outside every patch: no element | Floor fields of the film law (BD-230) |
| `clearance` | Each doorway or passage cell outlined in the passable style, the impassable style or, where the verdict is unresolved, a hatched third style; the bottleneck of the binding cut highlighted and captioned with its name and margin; the route witness as a polyline when one exists | The cell's identifier and flag; on the bottleneck, `clearance.margin` (m), negative when impassable | The clearance complex of (scene, robot envelope) (BD-233) |
| `ghost` | For each fork given by `--fork`: the fork's bodies at the drawn tick, rendered from the fork's stored rows by the same ray kernels and composed over the parent with a fixed checkerboard stipple (no blending, so bytes stay deterministic); a caption with the fork's class and label, its fork tick and the first-divergence tick and stage | A second identifier buffer for the ghost layer (fork path, body); per ghost body the two stored rows (parent and fork) and their distance in metres, computed in double precision from the anchored values (8 m × cell difference + offset difference) | Fork and parent frames paired on ticks (N27b-17); fork class and label (BD-205); the first-divergence record (BD-206) |
| `world-diff` | One numbered marker per edit at its location in the scene, and a caption list in edit order: property, nominal value → edited value with unit (for example "counter lip 18 → 22 mm") | The edit's index and its row: property, nominal, edited, unit, mechanism | The edit list of the world's `.fmcw` (BD-274) |
| `reality-band` | One extra strip tile at the bottom of the sheet: the metric's axis with the run's value as a marker and the stored interval as a bar from `lower` to `upper` (no upper end for a one-sided band); or, with no band, the words "no claim" and the refusal's code where one was returned | On the bar: `value`, `lower`, `upper`, the unit, n, the level and the status (`calibrated` or `synthetic`); with no band: `null` with reason `no-claim` | The envelope named by `--band`; otherwise the run header's reality field |

**3. Rules specific to the ghost.** (a) A still at a tick before the fork tick has no ghost element and its
caption says "before the fork tick (t_f = …)": the prefix is the parent's. (b) A null fork's ghost coincides
with its parent: the rows are bit-equal, so every distance is exactly 0; a non-zero value is a defect upstream
and is shown, not suppressed. (c) A structural or design-parameter fork has no shared prefix and is drawn as a
second run from tick zero, captioned "re-run from the episode start". (d) The overlay is offered only for runs
whose determinism class licenses counterfactual forks (class D2 with the batch-composition invariance gate
current); otherwise `FROB-REF-562`, exit 3. (e) A fork whose null replay is a mismatch is drawn with the
caption "null fork differs at tick <t>: this record is unsound" and is never hidden.

**4. Rules specific to the band.** The verb does no arithmetic on a band: the bar's ends are the stored
`lower` and `upper`. A band of status `synthetic` is captioned "synthetic rehearsal, not a measurement", and the
word `calibrated` is printed only when the envelope says it. An envelope that is a refusal draws no bar and
prints "no claim" with its code and its observed and required counts. A default-width band is never drawn.

**5. Absent data and refusals.** An overlay whose data were not recorded for the world (no film field, no
clearance complex for this envelope, no fork, a world that is not a counterexample world) is refused with the
list of overlays that are available, as for every stills overlay; the verb never returns a blank overlay.
Privacy and sealing are BD-191's and apply unchanged.

**6. The shared table and layout.** The five rows are added to the stills overlay table
(`crates/frob-chronicle/src/stills/overlays.rs`, with `overlay_film.rs`, `overlay_clearance.rs`,
`overlay_ghost.rs`, `overlay_world_diff.rs`, `overlay_band.rs`); the lint of N32b-11 then requires each id's
channels, units and legend range to equal the page's. `still_id` already hashes the overlay list and options,
so `--fork` and `--band` enter it. Determinism: identical bytes for identical options; the value buffers are
exact on every backend.

## Acceptance criteria

- [ ] `frob telemetry stills <run> --world <w> --at tick=<t> --overlay film --json` on the film fixture returns
      a still whose pixels inside the patch probe (through `telemetry.inspect-pixel`) to thickness 0.0002 m and
      effective friction 0.25, and outside the patch to no film element; the stored integers equal
      `telemetry.query`'s.
- [ ] `clearance` on the door fixture (doorway 0.76 m, envelope 0.774 m) captions the bottleneck "door" with
      margin −0.014 m in the impassable style; with the envelope at 0.746 m the margin is +0.014 m in the
      passable style; an unresolved passage is hatched, never drawn impassable.
- [ ] `ghost` with the null fork: the distance is exactly 0 for all 13 bodies at every drawn tick; with an
      exogenous fork: no ghost element at a tick before the fork tick, and the caption's first-divergence tick
      equals the one `telemetry.divergence` reports.
- [ ] `world-diff` on the two-edit counterexample fixture lists exactly the two edits with nominal and edited
      values and units, and a marker pixel probes to its edit row.
- [ ] `reality-band` without `--band` prints "no claim" and draws no bar; with a band envelope it draws one
      marker and one bar at the stored bounds, and a `synthetic` band never prints `calibrated`.
- [ ] `ghost` on a tolerance-class run is `FROB-REF-562`; a fifth `--fork` is `FROB-REF-802`; an overlay without
      its data is refused with the available list.
- [ ] The lint of N32b-11 passes with the five new rows: ids, channels, units and legend ranges equal the page's.
- [ ] Two calls with the same options return identical bytes and the same `still_id`; adding the overlays
      changes no physics digest.

## Test plan

### Unit tests
`crates/frob-chronicle/tests/stills_late_overlays.rs` (real stored runs of the fixtures; a hand-built band
envelope is labelled `synthetic` and validates against the registry's `ground.band` output schema):
- `film_patch_values`: stored thickness 0.2 mm and effective friction 0.25 beside dry floor at 0.8: a pixel
  inside reads both stored integers; a pixel outside has no film element.
- `clearance_door_margins`: −0.014 m and +0.014 m as above; `clearance_unresolved_is_hatched`.
- `ghost_null_fork_zero`: 13 bodies, 5 ticks: every distance is exactly 0 and the two stored rows are bit-equal.
- `ghost_absent_before_fork_tick`: fork at tick 90, still at tick 60: no ghost element, the caption says so.
- `ghost_distance_anchored`: parent at cell 3 offset 3.9, fork at cell 4 offset −3.9: 8·(4 − 3) + (−3.9 − 3.9)
  = 0.2 m.
- `ghost_layer_has_its_own_identifiers`: a pixel where a ghost body covers a parent body returns both, the
  parent from the identifier buffer and the fork body from the ghost layer.
- `ghost_unlicensed_562`; `fork_not_of_world_802`; `five_forks_802`; `structural_fork_drawn_from_zero`;
  `mismatched_null_fork_captioned`.
- `world_diff_two_edits`: "counter lip 18 → 22 mm" and "wet strip 40 mm before the lip", in edit order.
- `band_no_claim_draws_nothing`; `band_scalar_marker_and_bar` (value 4.20 s, lower 4.01 s, upper 4.39 s:
  the bar's ends are the stored bounds; changing the half-width field alone changes nothing);
  `band_synthetic_never_calibrated`.
- `overlay_without_data_refused_with_list` (five cases); `late_overlays_bytes_deterministic`.

### End-to-end script and logging
Step group `late-overlays-*` added to `scripts/e2e/telemetry_stills.sh` (owned by BD-191, whose step table
admits further groups). Setup, each run verb with its own key: `frob sim run` of the film fixture (`--key
lo-film`), of the door fixture (`--key lo-door`) and of a failing quadruped run under a class-D2 profile
(`--key lo-quad`); `frob run fork <quad> --world <w> --before failure --dt 1.0s --change '<setpoint change>'
--key lo-fork` (which also runs the null fork); `frob nemesis shrink` on a promoted failure (`--key lo-mcw`).
Then, per overlay: `frob telemetry stills <run> --world <w> --at tick=<t> --overlay <id> [--fork <path>]
--single --json`; `frob telemetry inspect-pixel <still_id> --pixel <x>,<y> --overlay <id> --json` at the
planned pixels; and the comparison values from `frob telemetry query <run> --world <w> --channels <the
overlay's channel> --from <t> --to <t> --json` (N24a-36's one spelling: one channel, so its stream is implied;
one tick is `--from t --to t`), from the drill-down handle the probe returns, which must give the same stored
integer, from `frob telemetry divergence <parent> <fork> --json` and from the `.fmcw` listing. Then the refusals (a tolerance-class run; a scene with no film) and a repeat
for byte equality. The script sources the shared helper and logs to
`target/e2e-logs/telemetry_stills/<utc>.ndjson` with a transcript: per line `ts`, `script`, `bead`
(`N24ap2-60`), `step`, `event`, the exact command line, exit code, wall time and the envelope's `evidence`
block; `metric` lines per probe with the overlay, pixel, channel, unit, the stored integer from the still and
from the query (mismatches against 0), the null-fork distance against 0 and the door margins against ∓0.014 m;
`refusal` lines with code, observed, required and first repair; digests of the stills compared; on failure the
first differing probe with the `still_id` and the buffer handles. Image bytes and scene geometry are never
logged. A `summary` line under this bead's key ends the group.

### Known answers and negative controls
- Known answers: the null-fork ghost deviates by exactly zero; the anchored distance 0.2 m; the door margins
  ±0.014 m; the film values 0.0002 m and 0.25; "no claim" with no band.
- Negative control: a ghost drawn from poses interpolated to the parent's frame times (the null-fork distance
  becomes non-zero): `ghost_null_fork_zero` must fail.
- Negative control: a distance computed from offsets alone (it reports 7.8 m): `ghost_distance_anchored` must
  fail.
- Negative control: a `clearance` that draws unresolved passages as impassable: the hatch test must fail.
- Negative control: a `reality-band` that draws a ±10% bar when no band exists: the no-claim test must fail.
- Negative control: a film value decoded from the pixel's colour: it differs from the stored integer in the
  last bits and the probe comparison must fail.
- Determinism lanes: bytes twice on one machine, debug and release, and across backends for the value buffers.

## Considerations

- If a third-milestone mechanism is late (the film law, clearance complexes, counterexample worlds), its
  overlay's tests and script steps are reported `not run` with the reason, never passed; the others ship.
- Kill gates that touch this bead: KILL-REPLAYPACK (N32b-32) makes these stills the fallback picture of a fork,
  so they must not depend on the packet or the page; if the kill gate on bands fires, `reality-band` shows "no
  claim" for every run and nothing here changes.
- A ghost is persuasive. The caption repeats the fork's class and label, and any attribution text beside it is
  the attribution verbs' own, marked `Estimated`; a still never says a fork "fixed" anything.
- Cost: a ghost renders each named fork once more (the same ray count as the parent's tile); the limit of four
  forks bounds it. Film and clearance are floor-aligned lookups of stored fields.
- Privacy: an edit list and a clearance complex describe a scene; stills of a private scene are private
  artifacts under BD-191's rule, and logs carry identifiers and digests only.
