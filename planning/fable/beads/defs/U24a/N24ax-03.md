## Background

A task (file `.ftask`, identity `TaskId`) is written without naming a design: its `interface` section lists
the ports it requires, its terms and signals name channels, and its draws name card fields. When a task is
run on a design, those names are resolved against the design; this is the **binding**. Through the binding
a task reads specific design fields: the pose and card of each sensor an observation term uses, the frame
of the payload port a requirement watches, a design constant in a metric or a normalization (leg length in
a Froude number, total mass in a cost of transport), the card field a randomization range comes from, the
collision envelope behind an envelope signal.

The mission-observable digest of the Phylum subsystem (bead N17a-26) needs exactly that list. The digest is
"the hash of exactly what the step plan and the task read: the lowered tables in canonical link order, the
sensor poses and the task-visible fields"; two designs with equal digests are one experiment and are
evaluated once. The invalidation contract needs the same list to decide which results survive an edit: a
result is reused exactly when the digest of the fields it read is unchanged. If the list omits a field the
task reads, two different experiments share a result. That has happened in an executed test: "a dependency
omitted from a key returned a stale promotion", and the rule drawn from it is that **keys are derived from
declared inputs, never written by hand**.

The gap is reported as "the task file has no declared read set". DESIGN decision: it gets none. A list of
design fields typed into a task would be the hand-written key the rule forbids, and it could not be
correct anyway, because a task does not know the field paths of the designs it will meet. Instead the read
set is **recorded** when the task is bound, by the same mechanism the design compiler uses for its own
products (ADR-SKEL-09: each product stores the set of source paths it read, at field granularity). Rejected
alternatives: a `reads` section in `.ftask` (above); deriving the set inside the digest code from the term
list (a second, unchecked copy of the binding logic, which is what the digest bead would otherwise do);
treating the whole design as read (sound, and it removes every digest class: the measured factor of 30.0
on the ballast fixture would become 1). Tier Solid; crate `frob-spec`, with the tracked view of `frob-model`.

## Scope

In: the binding product `TaskBinding` for a (`TaskId`, `DesignId`) pair and the rule that it is built only
through tracked accessors; its `ReadSet`; the canonical export `task_fields`; the declared source sets of
signals and design constants; the `reads` block of `task.show`; the mutation test that proves the record is
a superset of the reads.

Out: the digest, its classes and its memoization (N17a-26, BD-285); the invalidation contract (BD-286); the
tracked view and the design compiler's influence records (N14a-07, BD-063); the step plan's read set from
kernel stage signatures (N17a-26); the meaning of terms (BD-194) and of requirements (BD-122). The fixtures the
tests bind are their owners': the docking-cart task `cart-sill-dock` with designs A and B (`cart-a`, `cart-b`;
BD-123) and the ballast design family `fixture:ballast-24-8` (the digest pilot N17a-25).

## Technical approach

**1. The binding product (DESIGN; `crates/frob-spec/src/bind.rs`).**

```rust
pub struct TaskBinding { pub task: TaskId, pub design: DesignId, pub bound: BoundNames, pub reads: ReadSet }
pub struct BoundNames { ports: BTreeMap<PortName, InstanceId>, sensors: BTreeMap<TermName, SensorSlot>,
                        constants: BTreeMap<ConstName, Quantity>, draws: BTreeMap<DrawName, CardField>,
                        signal_sources: BTreeMap<SignalName, Vec<FieldPath>> }
pub fn bind(task: &Task, design: Tracked<'_, Term>) -> Result<TaskBinding, BindError>;
pub fn task_fields(b: &TaskBinding, design: &ElaboratedDesign) -> Vec<(FieldPath, Vec<u8>)>;   // sorted by path
```

`bind` receives the design only as the tracked view of the elaborated term, whose accessors append each
accessed path to the stage's `ReadSet`; module privacy makes an untracked read a compile error. `reads` is
therefore a superset of what the binding read, by construction. `TaskBinding` is a product in the memo
graph, keyed by (`TaskId`, the digest of the fields in `reads`), so an edit to a field outside `reads`
reuses the binding.

**2. What binding reads, by section (the complete list; anything else is a defect).**

| Section | Resolved against the design | Paths recorded |
|---|---|---|
| `interface` | Each required port to an instance with that port type | The port's type, frame and declared attributes |
| `terms`, observation | Each term to a sensor slot or a proprioceptive channel | The sensor's mount transform, card reference, pattern, clock and link; for a proprioceptive channel, the joint or actuator slot |
| `terms`, action | Each action channel to an actuator slot | The slot, its command clock and its bounds |
| `terms`, reward and termination | Design constants named in expressions | One leaf per constant |
| `signals` | Each channel to its source | The channel's declared source set (below) |
| `requirements` | Nothing directly (atoms read signals) | — |
| `randomization` | Each draw to a card field or a hazard-registry entry | The card reference and the field with its uncertainty interval |
| `reset` | The settled-pose specification | Nothing here: the cache is keyed by `ModelId`, which already covers the model |
| `world`, `study`, `clocks` | Nothing in the design | — |

**3. Declared source sets.** A telemetry channel or a design constant that depends on design fields
declares which, once, in the registry that defines it (`registries/channels.toml`, `registries/metrics.toml`):
`envelope.min_x` reads the collision geometry of every link; `payload.accel` reads the frame of the payload
port; the constant `leg_length` reads the lengths of the links of the canonical leg chain; `total_mass`
reads every fill and mass. A channel that depends only on state (a joint angle, a base velocity) declares
an empty set: the model tables are already in the digest through the step plan. A channel or constant with
no declaration cannot be named by a task: binding refuses it as an unknown field of the task (the
task-file reader's unknown-field refusal FROB-REF-103, N24a-02, with `detail: no-declared-source-set` and the
pointer at the term; exit code 3), so an undeclared dependency cannot enter silently.

**4. Canonical export.** `task_fields` returns, for every path in `reads` in sorted order, the path and the
canonical bytes of the value at that path (exact rationals as written, quantities with their unit token).
This is the `task_fields` component of the mission view. Names, labels, comments, visual meshes and
provenance are never read by `bind`, so they never appear.

**5. Surface.** `frob task show <task> --design <design> --section reads --json` returns `bound` and
`reads` (paths only; values are in the design). Schema `frob.task.reads/1`. Class `Tested`, tier `static`,
determinism exact (D0).

**6. Ledger.** Each binding writes a record `frob.task.bind/1` with `TaskId`, `DesignId`, the digest of
`reads` and of the read values. The digest bead cites this record; it does not recompute the set.

## Acceptance criteria

- [ ] `bind` compiles only against the tracked view: a test crate that reads the raw term inside the binding module fails to compile (compile-fail test).
- [ ] For the worked task of the cart fixture bound to design A, `reads` equals the hand-listed set in the test (ports, the two drive actuator slots, the card field behind each randomization draw, the collision geometry behind `env_min_x`), and nothing else.
- [ ] Mutation test: for every leaf of the design, change it and re-bind; whenever the bound names or any exported value change, the leaf is in `reads`. Zero violations over every (design, task) pair that binds, among the archetypes on file (the four of BD-109 at this milestone), the two cart designs and a sample of 100 ballast placements, and three tasks (`cart-sill-dock`, a flat-ground locomotion task, and a planted task whose term reads a slug's position). The test iterates over the archetype catalog, so the fourteen archetypes of BD-246 (M3) enter it when they land.
- [ ] An edit to a label, a comment or a visual mesh leaves the binding's memo key unchanged and the binding is reused; an edit to a sensor mount changes it.
- [ ] A task naming a channel with no declared source set is refused at binding with FROB-REF-103 and `detail:
      no-declared-source-set`, exit code 3.
- [ ] `task_fields` is byte-identical across platforms, worker counts, debug and release.
- [ ] `frob task show --section reads` is reachable through `frob --json`; `CONTRACT.md` of `frob-spec` states that `.ftask` has no hand-written read set and why.

## Test plan

### Unit tests
`crates/frob-spec/tests/bind_reads.rs`; real elaborated designs; planted cases labelled `synthetic`.
- `reads_cart_fixture_exact`: the set of the criterion above, compared path by path.
- `reads_superset_mutation`: the mutation test, with the first violating leaf printed on failure.
- `label_edit_reuses_binding`, `sensor_move_invalidates_binding`.
- `constant_declares_sources`: `leg_length` on the reference quadruped reads the two link lengths of the canonical leg (0.20 m and 0.20 m in the fixture) and reports 0.40 m; changing a foot's sole material does not touch it.
- `state_only_channel_reads_nothing`: a task observing joint angles only has no sensor paths in `reads`.
- `undeclared_channel_refused`.
- `task_fields_sorted_and_canonical`: order is by path; a quantity written `0.10 m` exports the same bytes as `0.1 m` after canonicalization.
- `ballast_fixture_reads`: on the eight-slug, 24-slot ballast design under a flat-ground locomotion task, no slug position is in `reads` (the task does not read placements), which is the precondition of the 24,546 classes.

### End-to-end script and logging
`scripts/e2e/task_reads.sh` (sources the STD-E2E helper; idempotent):
1. `frob task show cart-sill-dock --design cart-a --section reads --json`: assert the path list; record the
   `DesignId` of `cart-a` echoed in `bound` as A0.
2. `frob design edit A0 set-param <a quantity of design A that is not in step 1's path list, for example the
   chassis mass> <new value> --expected-parent A0 --key tr-outside --json` (one typed edit in the registry's form of `design.edit`; a
   label or comment has no edit kind, so the label case is the unit test `label_edit_reuses_binding`), then step 1
   with `--design` the new `DesignId`: assert the same `reads` digest and `reused: true`.
3. `frob design edit A0 set-param /payload/mount/x "0.02 m" --expected-parent A0 --key tr-mount --json`, then
   step 1 on that design: assert a different digest.
4. `frob task new fixtures/tasks/undeclared_channel.ftask --key tr-undeclared --json` (admitted: no design is bound
   yet), then `frob task show <its TaskId> --design cart-a --section reads --json`: exit code 3, FROB-REF-103 with
   `detail: no-declared-source-set` and the pointer at the term (`task.show` takes a `TaskId` or name, not a file).
Logged per STD-E2E: command, exit code, wall time, evidence block, `TaskId`, `DesignId`, the `reads`
digest, the count of paths, one `assert` event per expected path, a `refusal` event with the code, detail and
pointer, and on failure the first missing or extra path.

### Known answers and negative controls
- Ballast fixture: C(24, 8) = 735,471 placements; rigid-body dynamics reads count, Σx and Σx² only; 24,546 distinct (Σx, Σx²) pairs. The read set must leave placements out for a task that does not read them, and must include them when a term reads a slug's position (then classes split, down to singletons).
- Negative control `omitted-dependency`: a binding that resolves a design constant through an untracked side table. The mutation test must fail, naming the constant.
- Negative control `whole-design-read`: a binding that records every path. Sound, and caught by `label_edit_reuses_binding`.
- Metamorphic: reordering limbs in the design source leaves `task_fields` unchanged after canonical ordering; renaming a body changes no value in it.
- Determinism: D0 lanes as in the criteria.

## Considerations

- The record is a superset by construction, not an exact set: a binding that looks at a field and discards it still records it. That costs reuse, never soundness; the cart-fixture test bounds the over-approximation on one case.
- Source sets of channels are declarations and can be wrong. The digest's replay check (sampled pairs inside a class must produce identical traces) is what would expose an under-declared channel; a failure there withdraws the channel until its row is corrected.
- If a later task language lets terms compute over arbitrary design fields, those accesses go through the same tracked view and need no change here.
- Privacy: `reads` holds paths, not values; values of a private design are exported only inside the digest computation.
