## Background

A capability counts as implemented only if its known-answer tests pass against a pinned oracle that was never
regenerated from the candidate. The Parity claim (the implementation reproduces a reference tool or a published
number) rests on fixtures captured from a pinned oracle. If a fixture can be rewritten by running our own
code, a test against it tests nothing: the candidate agrees with itself. This bead builds the capture scripts
and the first fixtures, and makes the regeneration path structurally absent.

The subjects are the **reference robots**: imported public models used as parity fixtures and benchmark
baselines. They are never the source of a Reality claim. The oracle for them is MuJoCo C in double precision at
an exact release, run out of process as a development-time comparison instrument. Two gates consume the
fixtures at M1: import parity (each reference robot imports with forward-kinematics parity against the oracle
within 10⁻⁹ m and 10⁻⁹ rad over 10⁴ configurations, with a loss report listing every dropped field) and
contact-free dynamics parity (joint accelerations of each reference robot against the pinned oracle within 10⁻⁹
relative in `f64`).

Decisions that bind this bead. ADR-GAUNT-04: foreign tools are comparison instruments, never dependencies and
never baselines of record; they run out of process, under a pin, on fixtures captured by script. INV-GAUNT-01:
no fixture is regenerated from the candidate; fixtures are written only by `tools/oracle/` scripts whose inputs
exclude the workspace's build products, and CI fails on a fixture changed without a pin record. INV-GAUNT-03:
agreement with an oracle is recorded with claim kind `parity`; it is never reported as Reality, including for
an incumbent that has itself been compared with hardware.

## Scope

In: the layout of `tools/oracle/mujoco-c-f64/` and `tests/fixtures/oracle/`; the pin and admission of the
MuJoCo oracle row (`mujoco-c-f64`) in the oracle register; the reference-robot extension of the fixture header;
capture scripts for forward kinematics and contact-free forward dynamics of the reference
robots; the model manifest with licences; the CI checks that make regeneration from the candidate impossible
to do quietly; the first fixtures on disk. Out, and owned by N38a-04 (M0), which this bead depends on: the
oracle register `crates/frob-conformance/registry/oracles.toml` itself, its `[[oracle]]` row schema, the one
`[[pin_move]]` record format of the program, the generic fixture header and the capture-script convention; this
bead fills the MuJoCo row and follows those formats, it does not define a second pin file. The typed G2 result
and the refusal of a Parity result offered as Reality are N38a-05's. The model record `tools/oracle/models.toml` of this bead is the one
place where a reference robot's source repository, commit, file path and licence identity are entered by hand.
Out: the asset tree `assets/robots/<name>/` with its manifest `frob.robot.asset/1`, the licence check
`robot_licence_check`, the validation of the imported design, the mass-on-file record and the catalogue index
(NEG-15, which depends on this bead: its manifest's `source` and `licence` tables are written from this bead's
model record and checked against it, and add what the record does not hold); the incumbent harness and its recorded environment (BD-039,
reused here to run the oracle); the importers (BD-065, BD-066); the parity tests that read the fixtures
(BD-089 and the import gate); the Gauntlet's wiring of oracles at M1 (BD-146).

## Technical approach

**Layout.**

```
tools/oracle/                       # capture scripts for development-time oracles (standalone; no frob crate)
  README.md                         # N38a-04's list: each script, its oracle, the reproduce-from-empty command
  mujoco-c-f64/                     # one directory per oracle row id, N38a-04's convention
    capture_fk.py  capture_fd.py  sample_configs.py  common.py
  models.toml                       # reference-robot sources, commits, licences
crates/frob-conformance/registry/oracles.toml   # N38a-04's register; this bead fills row `mujoco-c-f64`
tests/fixtures/oracle/              # pinned oracle captures, never regenerated from the candidate
  <robot>/<fixture_kind>.<pin-value>.<model-commit-12>.fixture  # canonical binary with a JSON header
  <robot>/configs.<seed>.bin        # the sampled configurations themselves
  CAPTURES.log                      # one appended line per capture
```

Every capture script follows N38a-04's convention: it takes `--pin` and `--out`, prints the oracle's version
string first, refuses to run (exit 2, message naming both versions) when the installed release or its binary
hash differs from the pin, and writes the fixture with its header.

At M1 the fixtures cover the robots of the four first archetypes (`quad-mammal`, `humanoid`, `diff-drive`,
`mecanum`) and the two URDF sources; the rest are captured when their archetypes land. Twelve of the eighteen
archetypes have no permissively licensed reference model on file; nothing is captured for them.

**The URDF sources.** No model of the Menagerie is published as URDF, so without these two rows the URDF
importer has no oracle and the URDF rows of GATE-SKEL-01 are not run. Their `[[model]]` rows (`g1-urdf`,
`iiwa7-urdf`) have no asset directory of NEG-15 (they are importer fixtures, not catalogue robots); their
`repository`, `commit`, `path`, `entry`, `spdx`, `text_sha256` and `read_on` are those of BD-065's
`PROVENANCE.toml` for the same file, and the check `oracle_urdf_rows_match_provenance` fails on any difference, so
the facts BD-065 read stay entered once. A source BD-065 could not vendor (a licence outside the three) gets no
row and no committed capture, and N14b-24 logs its rows `not run`. Capture (FACT to recheck at the pin: the
MuJoCo URDF compiler fuses bodies joined by fixed joints into their parent unless static-body fusion is off,
option `fusestatic`): `capture_fk.py` loads the unmodified vendored URDF, with its meshes, through the pinned
compiler with static-body fusion off, either through the oracle's model-specification interface or through a
generated wrapper copy that adds `<mujoco><compiler fusestatic="false"/></mujoco>` and whose path and hash are
recorded in the header's `inputs` beside the original's; it then asserts that the compiled body count, the world
body excluded, equals the URDF's link count (38 for `g1-urdf`), so every link keeps its frame and a fused capture
cannot be written. Only forward kinematics is captured for these rows (contact-free dynamics parity is served by
the MJCF models). A source that declares `mimic` joints is sampled with each dependent joint set from its leader
by the URDF's multiplier and offset, so the capture does not depend on whether the pinned compiler honours
`mimic` (FACT to recheck at the pin). The header's `conventions` block states for these rows: joint order as in
the URDF file, link-origin frames (the URDF link frame, not the centre of mass), quaternions as (w, x, y, z), poses
in the root link's frame with the root fixed at identity, and `compiler: {fusestatic: false}`.

**Pin record (row `mujoco-c-f64` of `oracles.toml`, N38a-04's schema).** `id = "mujoco-c-f64"`, `posture =
"out-of-process"`, `pin = { kind = "release", value = "<exact MuJoCo release>", sha256 = "<binary or container
digest>" }`, `roles = ["parity:contact-free-dynamics", "import-fixtures"]`, `admission = { test, control,
status, date }`. This bead sets the pin and admits the row. DESIGN (the register names the test, the plan
gives no numbers): the admission test is `g2:mujoco-pendulum-period`, a single hinge pendulum of point mass on a
massless 1 m link, g = 9.81 m/s², released at 0.01 rad; the oracle's mean period over ten swings must equal
2π·√(1/9.81)·(1 + θ₀²/16) = 2.00608 s within 10⁻⁴ s; its negative control is the same capture run with gravity
silently set to 9.80 m/s² (period 2.00710 s), which the test must reject. The precision (`f64`) is part of the
oracle id; the recorded environment of the incumbent harness (BD-039) is copied into every fixture header's
`environment` field (the register row carries no free-text fields; N38a-04 allows extra fields only on the
development-oracle row). Moving the pin is a deliberate event: an appended `[[pin_move]]` record (N38a-04's single
format: `oracle`, `from`, `to`, `date`, `reason`, `by`, `fixtures_recaptured`); old fixtures stay on disk under
their old pin value. An oracle is admitted like a dependency: a pin, an admission test, a negative control.

**Model record (`models.toml`).** Per robot, one `[[model]]` row: `name` (the robot's key everywhere, for
example `go2`; the same key as the asset directory of NEG-15), `repository`, `commit` (40 hex), `path` (the
directory at that commit), `entry` (the model file), `spdx` (the licence class), `text_sha256` (the hash of the
licence text at that commit), `redistribution` (the rule: `allowed-with-notice`, `allowed`, `not-allowed`,
`not-read`), `read_on` (UTC date). The licence entry travels with every pack or report that contains the model.

DESIGN (one record, not two): the same facts were also specified as hand-entered fields of the asset manifest
`assets/robots/<name>/manifest.toml`. They are entered once, here, because capture needs them first and the
fixture header's `model_commit` must be the commit the capture read. The asset manifest (NEG-15) gets its
`source.repository`, `source.commit`, `source.path`, `source.entry`, `licence.spdx`, `licence.text_sha256` and
`licence.redistribution` by generation from this row, and its licence check fails when they differ. Whether a
licence is admitted, whether the text matches its identifier, the notice files and the export into the licence
join are NEG-15's check; this bead's own rule is only that the capture scripts refuse a robot whose row has
`redistribution = "not-read"` or lacks `text_sha256`.

**Fixture file.** A canonical little-endian binary of IEEE-754 doubles preceded by a JSON header. The header
carries N38a-04's generic fields under their names, `kind: "oracle"`, `oracle: "mujoco-c-f64"`, `pin` (the pin
value at capture), `captured` (UTC date), `script: {path, sha256}` (the capture script under
`tools/oracle/mujoco-c-f64/` and its hash at that commit), `inputs: [{path, sha256}]` (the model file at
`model_commit` and the configuration file), `units`, `tolerance_note`; and this bead's reference-robot
extension: `schema: "frob.oracle.fixture/1"`, `robot` (the `models.toml` key), `fixture_kind: "fk" | "fd"`,
`model_commit`, `environment`, `count`, `layout` (the named columns with units and frames), `conventions`
(joint order, quaternion order, frame definitions, gravity vector), `data_sha256`, `claim: "parity"`. DESIGN:
the reference-robot field is `fixture_kind`, not `kind`, because N38a-04's header already uses `kind` for the
fixture class. The header makes each fixture self-describing: pin, date and script, as oracle hygiene requires.

**Capture, as numbered steps.**

1. `sample_configs.py --robot R --seed S --count 10000` draws joint positions uniformly inside each joint's
   range (and joint velocities and torques for dynamics, inside declared bounds) from a pinned generator, and
   writes them to `configs.S.bin`. The configurations are data on disk; no later step re-derives them.
2. `capture_fk.py` loads the model in the pinned oracle, sets each configuration, and records the world pose of
   every body (position in metres, orientation as a unit quaternion).
3. `capture_fd.py` disables contact and constraints that the parity test excludes, sets configuration,
   velocity and applied torques, and records joint accelerations from the oracle's forward dynamics.
4. Each script writes the fixture with its header and appends a line to `tests/fixtures/oracle/CAPTURES.log`
   (fixture path, data hash, pin id, date).

The scripts depend only on the foreign tool and a standard interpreter. They take the model file and the
configuration file as inputs. They do not import, link, execute or read any artifact of this workspace: no
`frob` binary, no file under `target/`, no generated kernel.

**Making the regeneration path not exist (the seed done-condition).**

1. *No writer in the workspace.* No crate, test or build script of the workspace can write under
   `tests/fixtures/oracle/`: tests open fixtures read-only through one loader in `frob-conformance`; a lint
   fails on any other path literal into that directory or any file-creation call beneath it. There is no
   "update fixtures" flag, environment variable or test mode.
2. *Script inputs exclude build products.* A check parses the capture scripts' imports and subprocess calls
   and fails on any reference to the workspace's crates, binaries or `target/`. The scripts run in an
   environment in which the workspace's build directory is absent.
3. *A fixture changed without a pin record fails CI.* This is N38a-04's rule 1 applied to these fixtures, with
   two reference-robot checks added. For every fixture file added or changed in a commit, CI requires: its
   `data_sha256` matches its bytes; its `oracle` is an admitted row of `oracles.toml` and its `pin` is that
   row's current pin or a `from` value of one of its `[[pin_move]]` records; a matching new line exists in
   `CAPTURES.log`; the header's `script.sha256` matches the script at that commit. A committed fixture file is
   never rewritten: CI fails on any modification of its bytes. A recapture under a new pin is a new file (the
   name carries the pin value) listed in that `[[pin_move]]` record's `fixtures_recaptured`; a recapture for a
   new model commit is a new file too (the name also carries the first 12 hex digits of `model_commit`).
4. *Planted regeneration.* The hygiene gate's control: a fixture whose data were produced by the candidate
   (our own forward kinematics written into the fixture layout) with a copied header. It fails check 3 (the
   capture log and hashes do not line up) and, independently, a provenance check: the header's `script.path`
   must be a script under `tools/oracle/` and the commit must touch no workspace build product in the same
   change.

**Other oracle rules carried here.** Two oracles that disagree are a finding, filed with both pins; the
candidate is not tuned toward either until the disagreement has an explanation in a derivation file. A result
obtained on a development oracle funds or kills a work package and supports no gate; it is labelled
`development-oracle`. A sibling routine is not an oracle because it exists: it needs its own admission.

Evidence produced by tests that read these fixtures: claim Parity; class `Tested`; never Reality.

## Acceptance criteria

- [ ] Fixtures for forward kinematics (10⁴ configurations) and contact-free forward dynamics exist on disk for each reference robot of the four first archetypes, each with pin, date and capture script in its header (the seed condition: fixtures are on disk with their pins).
- [ ] For each URDF source BD-065 vendors, a forward-kinematics fixture of 10⁴ configurations exists under `g1-urdf` or `iiwa7-urdf`, captured with static-body fusion off: its compiled body count equals the URDF's link count (38 for `g1-urdf`), its `[[model]]` row equals the source's `PROVENANCE.toml`, and its header states the conventions above.
- [ ] The regeneration-from-candidate path does not exist: no workspace code can write the fixture directory (lint), no capture script references a workspace build product (check), and there is no update mode (the seed condition).
- [ ] A fixture edited by one byte, a fixture with an unknown pin, a committed fixture rewritten in place, and the planted candidate-generated fixture each fail CI.
- [ ] The row `mujoco-c-f64` of `crates/frob-conformance/registry/oracles.toml` (N38a-04's register; no second pin file exists) holds the exact release and binary digest with `admission.status = "admitted"`, its admission test `g2:mujoco-pendulum-period` passing and its 9.80 m/s² control caught; `models.toml` holds source, commit and licence for every captured robot; the capture scripts refuse to run against any other installed release.
- [ ] Re-running a capture script on the pinned oracle reproduces the fixture's `data_sha256` (the oracle is deterministic at the pin); the re-run is logged, not committed.
- [ ] No foreign tool appears in any production dependency graph (dependency check).
- [ ] Every test that reads a fixture records its result with claim kind `parity`.
- [ ] The oracle-hygiene gate (GATE-GAUNT-05: every fixture has a pin, a date and a capture script; a planted fixture regenerated from the candidate fails CI; no foreign tool appears in any production dependency graph; a planted Parity result offered as Reality is refused) passes for these fixtures.

## Test plan

### Unit tests
- `oracle_fixture_header_complete`: every fixture under `tests/fixtures/oracle/` parses; all header fields present; `claim == "parity"`.
- `oracle_fixture_hash_matches`: `data_sha256` equals the hash of the data block.
- `oracle_fixture_pin_exists`: every header's `oracle` is an admitted row of `oracles.toml` and its `pin` is the row's current pin or the `from` of one of its `[[pin_move]]` records; a header naming an unknown pin is rejected.
- `oracle_fixture_config_hash`: the configuration file's entry in `inputs` equals the hash of that file; count is 10,000 for forward kinematics.
- `oracle_fixture_rewrite_refused`: a committed fixture whose bytes change under the same file name fails the CI check function even when its header hash is updated to match.
- `oracle_admission_pendulum`: the admission record's measured period lies in 2.00608 ± 10⁻⁴ s; the stored control run (g = 9.80 m/s², 2.00710 s) is outside the band.
- `oracle_capture_refuses_wrong_release`: the capture script, given `--pin` with a release different from the installed one, exits 2 and writes nothing.
- `oracle_fixture_quaternions_unit`: every recorded orientation has norm 1 within 10⁻¹².
- `oracle_loader_is_read_only`: the loader opens files read-only; a compile-time lint test finds no other use of the fixture path.
- `oracle_scripts_have_no_workspace_inputs`: static scan of `tools/oracle/**/*.py`.
- `oracle_planted_regeneration_fails`: a synthetic fixture (labelled `synthetic`) built by the test from candidate-style data with a copied header is rejected by the CI check function.
- `oracle_pin_move_keeps_old_fixtures`: appending a `[[pin_move]]` record leaves fixtures of the old pin loadable under their pin value.
- `oracle_urdf_rows_match_provenance`: the rows `g1-urdf` and `iiwa7-urdf` equal BD-065's `PROVENANCE.toml` field by field; a copy with a changed commit fails naming the field; a row without a vendored source is rejected.
- `oracle_urdf_every_link_kept`: the header of each URDF fixture records a body count equal to the source's link count and `fusestatic: false`; a synthetic header recording a fused capture (fewer bodies) is rejected by the CI check function.
- `oracle_urdf_mimic_sampling`: on a synthetic URDF with one `mimic` joint (multiplier 2, offset 0.1 rad), every sampled configuration has the dependent joint at 2·q + 0.1 exactly.

### End-to-end script and logging
`scripts/e2e/oracle_fixture_hygiene.sh`: runs the CI check function over the committed fixtures (expect pass),
then over four scratch copies: one byte flipped, pin removed from the register, a committed fixture rewritten in
place with a matching header hash, and the planted candidate-generated fixture (expect fail for each); runs the
dependency check for foreign tools; checks the URDF rows against BD-065's `PROVENANCE.toml` and logs, per URDF
fixture, a `metric` line with the link count against the recorded body count; where the pinned oracle is installed
(`--with-oracle`), re-captures one robot and `g1-urdf` and compares `data_sha256`, captures `g1-urdf` once more with
static-body fusion on into scratch (expect the body-count check to fail, logged as a caught control), and runs the
capture script once with a wrong `--pin` (expect exit 2). Sources the
shared helper of STD-E2E and writes `target/e2e-logs/oracle_fixture_hygiene/<utc>.ndjson` with a transcript
beside it; every line has `ts`, `script`, `bead: "BD-067"`, `step`, `event`, the exact command line, exit code
and wall time; per fixture a `metric` line with its oracle, pin, model commit, date, script hash and data hash;
the four negative controls as `assert` events with `caught` and, on a miss, the scratch path and the first
differing header field; the dependency-graph scan result; and a final `summary` with passed and failed counts
naming GATE-GAUNT-05. The log holds no model geometry, only identifiers and hashes.

### Known answers and negative controls
The fixtures feed the import-parity row (forward kinematics within 10⁻⁹ m and 10⁻⁹ rad over 10⁴ configurations)
and the contact-free dynamics row (joint accelerations within 10⁻⁹ relative in `f64`). Negative controls: the
planted regenerated fixture; the flipped byte; the in-place rewrite; the admission run under g = 9.80 m/s²; a
capture script edited to read a workspace binary (the static scan must fail); a URDF capture with static-body
fusion on (the body-count check must fail). Metamorphic: re-capturing with the same pin, model commit and configuration file gives
identical bytes. Determinism: fixtures are data; their hashes are the same on every machine.

## Considerations

- OPEN-GAUNT-4 (owner: the rival audit; blocks the hygiene gate and every pilot that needs dynamics before M1): which incumbent release is the development oracle and which releases and container digests form the comparator set. Fail-closed default: no development oracle; those pilots wait for the CPU referee. The MuJoCo C pin for the reference-robot fixtures is recorded with the fixtures in either case.
- RISK-13 (reference-robot imports hide lossy contact mappings; warning sign: fields missing from a loss report). The fixtures here are contact-free on purpose; contact parity with the imported contact model is labelled parity-only by its owner.
- The plan names two homes for fixtures: `frob-conformance/fixtures/` in the Gauntlet's ownership table and `tests/fixtures/oracle/` in the repository layout. This bead puts oracle captures under `tests/fixtures/oracle/` (the path the layout labels "never regenerated from the candidate") and leaves fixtures authored inside the crate under `frob-conformance/fixtures/`; the read-only loader covers both and the no-writer lint applies to the oracle path.
- Licences: only models with a permissive licence on file are captured and committed; a model whose licence was not read stays outside the default pipeline.
- The oracle may use different conventions (joint order, quaternion order, frame at the body or at the centre of mass); the header's `conventions` block is the single place they are stated, and the parity tests convert there.
- If two oracle releases disagree beyond 10⁻⁹ on a robot, both captures are kept under their pins and the disagreement is filed as a finding before any parity gate cites either.
- KILL-DEVORACLE (M1): if two or more of the first five pilots re-run on the CPU referee change verdict relative to their development-oracle run, development-oracle results lose standing as funding evidence. That concerns pilots, not these parity fixtures.
