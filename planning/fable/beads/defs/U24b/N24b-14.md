## Background

A **study** is a registered plan to answer one comparative or absolute question. It declares its type when it
is created and keeps it (INV-ARENA-05: a study has one type for its whole life). There are two types.

| | Anytime-valid study | Fixed-n exact study |
|---|---|---|
| Inference | A betting e-process or a confidence sequence, valid at every stopping time | An exact interval or test at a sample size fixed in advance |
| Stopping | When the evidence crosses its threshold or the budget ends; unfinished episodes are cancelled | At n complete units, never earlier |
| Before the first episode | Null hypothesis, effect margin, bound on outcomes, betting rule, level, budget | n, the rule, the level, and a pre-analysis: which verdicts are reachable at that n, and the power at declared alternatives |
| Reports | The e-value, the confidence sequence, pairs used, the stopping reason | Counts, the interval, the verdict, and the pre-analysis hash |
| Interim information | Any; validity does not depend on it | Progress only. Outcomes may be looked at, and the verdict is computed once, at n |
| Typical use | Screening, racing, promotion between tiers, bisection | Registered A/B questions, equivalence claims, qualification of a finalist |

ADR-ARENA-07 (decision): a study is anytime-valid or fixed-n, never both. Reason: each kind of inference is
valid only under its own stopping rule. A fixed-n interval computed at the moment an anytime-valid study stops
has no coverage guarantee, and a fixed-n study that stops when its running p-value first looks good loses its
level. Counterexample for the second (CX-266): an exact one-sided sign test at nominal level 5% on pairs that
favour either design with probability ½, looked at after every pair: after 8 looks the chance of a false
rejection is 13/256 = 5.08%; after 16 it is 8.76%, after 32, 12.9%, and after 64, 17.4%.

Three other beads already check parts of a study before its first episode, and this bead must not repeat them:

- BD-124 (the seed bead of the two engines) defines the study types (`Study`, `AnytimeStudy`, `FixedNStudy`,
  `PreAnalysis`, `StudyVerdict`, `PairCounts`), records the study, and raises FROB-REF-552, -532 and -533 when
  a study is created. It records three declarations (unit of inference, race level, controller arm) but does
  not validate them.
- N28a-18 (`pairing::admit`) checks the six pairing rules of the comparison chapter and raises the comparison
  codes 553, 555, 542, 543 and 556; its 553, 555 and 542 are the same defects as 552, 532 and 533.
- N33b-19 implements the verbs `study.plan`, `study.submit` and `study.status`.

What no bead does yet is the one Arena entry point that runs these checks in a fixed order, so that an Arena
caller (study planning, a fixture batch, the qualification lane) always gets the Arena code for a defect that
has two codes, plus the validation of three of §24.12's four common rules (the unit of inference when episodes
share a cluster, the level of each pairwise comparison of a race, the controller arm). This bead is that entry
point and those checks. It implements the study half of construction C-15 (evidence is a test martingale;
time-uniform inference and a sealed fixed-n decision are different procedures, and neither substitutes for the
other).

## Technical approach

**Types used (DESIGN sketch; names fix intent).** The study types are BD-124's and are not redefined here. The
plan object is Appendix I.9's:

```rust
pub struct StudyPlan { designs: Vec<DesignId>, scene: SceneRef, task: TaskId, controller_arm: ControllerArm,
    seed_protocol: SeedProtocol, // pairing by (world, replicate); `unit: world | cluster` and the cluster map
    budget: Budget, backend: BackendRequest, study: Study, estimate: CostEstimate }
pub enum ControllerArm { Shared, RetunedEqualResources { resources: Vec<Resources> },
    InheritsWeights { warm_start: WarmStart, transfer_baseline: DesignOrPolicyId } }
pub enum UnitOfInference { World, Cluster { map: ClusterMap } } // ClusterMap: All | Mean { span: LossSpan }
pub struct AdmittedStudy { study: StudyId, pairing: PairingPlan, unit: UnitOfInference, n_units: u32,
    level: Ratio, controller_arm: ControllerArm, interim: InterimRule, ledger_seq: u64 }
```

`StudyPlan` must exist before N28a-18, whose `pairing::admit` takes it, so it belongs with the study types of
BD-124 (requested there); this bead reads it. The `ControllerArm` spellings are those of the `study.plan` input
schema (N33b-19): `shared`, `retuned-equal-resources`, `inherits-weights`.

**`study::admit(plan: &StudyPlan) -> Result<AdmittedStudy, Refusal>`, checks in order, before any episode is
scheduled.** Checks 1 to 3 call BD-124's creation checks first, so that a defect with two codes always gets the
Arena code on an Arena path; check 4 calls N28a-18 for the pairing rules that have no Arena code; checks 5 to
7 are this bead's own.

1. *One type* (BD-124's check, FROB-REF-552). The request carries exactly one of the two declarations. A request
   that carries both, or that asks an anytime-valid study for an exact fixed-n interval at its stopping time,
   or asks a fixed-n study to stop on interim evidence, is refused.
2. *Declarations present.* Anytime-valid: null hypothesis, effect margin, the bound on outcomes (`LossSpan`,
   taken from the task definition and never estimated from the study's own data; a metric without one is
   refused, FROB-REF-543 through N28a-18 in step 4, the only code for it), betting rule, level, budget.
   Fixed-n: n, the rule, the level, and the pre-analysis from `eval.preanalyze` at that n and level. Missing
   pre-analysis, or a declared verdict that the pre-analysis shows unreachable: FROB-REF-532 (BD-124's check)
   with the reachable set and the first reachable n attached; a verdict named in `acknowledge_unreachable` is
   removed from the declared set first (BD-124 step 6). Fixture 1 shows why: at 64 pairs its rule cannot
   return one of its four verdicts.
3. *Determinism class* (BD-124's check, FROB-REF-533), as §35.3 licenses it: both arms D2 or better on one
   device family with GATE-SPARK-15 current, or D1 across families → `paired-exact`; both D3 with a current
   decision-level equivalence record for the task → `paired-by-address`, labelled, with the realized pair
   correlation reported beside the verdict; any arm D4 (the labelled training profile) or of unrecorded class,
   or arms on different device families with neither D1 nor a D3 record → refused (repairs: rerun both arms
   under a replayable profile on one backend; record decision-level equivalence; compare unpaired by
   declaration).
4. *Pairing rules* (`pairing::admit`, N28a-18): pairing by (world, replicate), space- or address-indexed
   exogenous fields, separate settling, no per-design minimum, the planned denominator; returns the
   `PairingPlan` with its label. Its 553, 555 and 542 cannot fire here, because checks 1 to 3 have already
   refused those defects with 552, 532 and 533.
5. *Unit of inference.* Units are paired by world address. When several episodes share a cluster, such as one
   building with its materials, the cluster is the unit of inference: the plan declares `unit: world |
   cluster` and, for clusters, the map from episode outcomes to the unit's outcome, fixed before the first
   episode (DESIGN options: `all`, the unit succeeds when every episode in it is satisfied; `mean`, the mean of
   a bounded outcome, with the span declared). n counts units, not episodes. A plan over worlds that share a
   cluster identifier (from the scene family's records) that declares `unit: world` is refused.
6. *N-way race.* A race of N candidates that eliminates on single pairwise comparisons spends α/(N − 1) per
   comparison, so that a null race keeps its best candidate with probability at least 1 − α. `admit` computes
   the per-comparison level as an exact rational and writes it into each pairwise study; a race plan whose
   pairwise studies carry any other level is refused.
7. *Controller arm.* A comparison of designs declares its controller arm: `shared` (one controller for both,
   which isolates the change of body: both arms carry one `ControllerId`, N22a-07); `retuned-equal-resources`
   (controllers retuned with equal resources, which compares the best systems: the recorded resources, steps,
   seeds and wall-clock cap, are equal per arm); `inherits-weights` (a candidate that inherits weights declares
   its warm start and names a matched transfer baseline that receives the same warm-start budget). A design
   comparison with no declared arm, or whose arms contradict the declared arm (two `ControllerId`s under
   `shared`, unequal resources under `retuned-equal-resources`, no transfer baseline under `inherits-weights`),
   is refused.

**Resources, compared field by field (DESIGN).** BD-124 names `Resources` in `ControllerArm` and leaves its
content to this check; its shape is fixed here (requested of BD-124 to declare it so). A `Resources` is an
ordered list of named fields, each a field name and a canonical value string (integers in decimal, rationals
reduced, durations in integer milliseconds, a per-channel quantity as a list ordered by channel name), so that a
controller crate can produce one without depending on `frob-arena`: an arm's resources come from its controller
through the accessor `resources()` when the controller's record provides one, and otherwise from the plan's
declared `resources` for that arm; a declared value that contradicts the accessor's is refused like an unequal
pair. Check 7 compares the arms' lists over the union of their field names, in name order; a field present in
one arm and absent from another is unequal; the refusal's `observed` names the first differing field with both
values. At M1 the fields are `steps`, `seeds_policy` and `wall_clock_cap`. The comparison is written once, over
any field list, so that a later field enters without a change here: the residual wrapper (N22a-16, M3, which
depends on this bead and adds no arm check of its own) supplies through its `resources()` the residual policy's
training steps, seeds policy and cap, plus `rho` (ρ per command channel) and `baseline_rung` (`R0`, or `R1` with
its search budget), and check 7 then refuses equal steps with ρ 0.3 against 0.5 naming `rho`, and an R0 against
an R1 baseline naming `baseline_rung`.

On success `admit` writes the admitted declarations (study address, type, unit and n in units, per-comparison
level, controller arm with its identities, pairing label, pre-analysis hash) to the ledger before the first
episode, beside BD-124's registry record.

**Interim behaviour.** For a fixed-n study the admitted record carries `interim: progress-only`: `study.status`
returns progress (units done of n) and may return raw outcomes; it returns no interval, test statistic or
verdict before n complete units, and the verdict is computed once. The only early stop is exact curtailment:
every admissible completion of the unresolved units yields the same verdict (function in N24b-06). For an
anytime-valid study any interim information may be shown; when the evidence crosses its threshold or the
budget ends, unfinished episodes are cancelled.

**Refusals.**

| Code | Meaning | Raised by | Ranked repairs | Exit |
|---|---|---|---|---|
| FROB-REF-552 | A request mixes study types | BD-124, called by check 1 | Register two studies, one of each type, on disjoint units; or keep the declared type and drop the foreign statistic | 3 |
| FROB-REF-532 | A fixed-n study has no pre-analysis, or names a verdict it cannot reach | BD-124, called by check 2 | Run `eval.preanalyze`; raise n to the first value at which the verdict is reachable; acknowledge (drop) the verdict; register the equivalence rule | 3 |
| FROB-REF-533 | Paired statistics requested under an uncontrolled determinism class | BD-124, called by check 3 | Re-run both arms under a D2 profile on one backend; or record decision-level equivalence under D3 for the task; or compare unpaired by declaration; never D4 | 3 |
| FROB-REF-543, -556 | An anytime metric without a declared span; a pairing keyed by event order or a training counter | N28a-18, called by check 4 | As in N28a-18 | 3 |
| FROB-REF-802 | Checks 5 to 7: `unit: world` over clustered worlds (pointer `/seed_protocol/unit`); a race level other than α/(N − 1) (pointer to the pairwise study's `level`, with `required` the exact rational); a missing controller arm or arms that contradict it (pointer `/controller_arm`, `observed` the identities or resources) | This bead | Declare `unit: cluster` with a map; let `admit` write the divided level; declare the arm and supply one controller, equal resources or the transfer baseline | 3 |

FROB-REF-802 ("arguments fail the schema") is used for checks 5 to 7 because the plan names no dedicated code;
a missing arm is a missing required field, and the two contradictions are refused with the same code and an
exact pointer (DESIGN; the Arena refusal registry N24-REF is asked whether to assign dedicated codes, in which
case this table and its tests change and nothing else).

Code: `crates/frob-arena/src/study/admit.rs`.

## Acceptance criteria

- [ ] `study::admit` exists and is the Arena path's only admission function: each defect with two codes yields the Arena code (552, 532, 533) through `admit` and the comparison code (553, 555, 542) through `pairing::admit` alone, asserted on one planted plan per defect.
- [ ] A request with both declarations is refused with FROB-REF-552 (BD-124's seed condition, exercised here through `admit`); a request for a fixed-n interval on a stopped anytime-valid study, and a request to stop a fixed-n study on an interim look, are each refused with FROB-REF-552.
- [ ] A fixed-n study without a pre-analysis, and one declaring a practical tie at n = 64 under the fixture-1 rule, are each refused with FROB-REF-532 with n = 86 attached; the same tie named in `acknowledge_unreachable` is admitted without it.
- [ ] A paired study with a D4 arm, or with arms on different device families and neither D1 nor a D3 equivalence record, is refused with FROB-REF-533; two D3 arms with the record are admitted as `paired-by-address`.
- [ ] `study.status` on a fixed-n study before n returns no interval and no verdict (the admitted record carries `interim: progress-only`).
- [ ] A 5-way race at α = 0.05 carries level 0.0125 in each pairwise study; a race plan carrying 0.05 in a pairwise study is refused with FROB-REF-802 and the pointer to that level.
- [ ] A design comparison without a controller arm is refused; each of the three arms is accepted with its required fields; two `ControllerId`s under `shared` are refused.
- [ ] Under `retuned-equal-resources` the arms' `Resources` are compared field by field over the union of their field names: unequal `steps` is refused naming `steps`; a field that only one arm carries is refused naming it; field lists supplied through a `resources()` accessor with the added fields `rho` and `baseline_rung` (planted test controllers standing for N22a-16's wrapper) are compared with no change to the check, ρ 0.3 against 0.5 refused naming `rho` and R0 against R1 naming `baseline_rung`.
- [ ] `scripts/e2e/study_admission.sh` passes on a clean checkout at M1.
- [ ] A study's type cannot be changed after creation (compile-fail and schema tests on BD-124's types, through `admit`); the admitted declarations are in the ledger before the first episode.

## Test plan

### Unit tests
- `study_one_type_for_life`: compile-fail test that no conversion between variants exists; schema test that a JSON study with both `anytime` and `fixed_n` keys is rejected.
- `study_mixture_refused_552`: the three mixture requests above.
- `study_fixed_n_requires_preanalysis_532`; `study_unreachable_verdict_532` (n = 64, tie declared; at n = 86 admitted; at n = 64 with the tie in `acknowledge_unreachable` admitted without it).
- `study_determinism_class_533`: (D2, D2, one family) admitted `paired-exact`; (D2, D4) refused; (D2 on CUDA, D2 on Metal) refused without a D3 equivalence record and admitted `paired-by-address` with one; (D1, D1) across families admitted `paired-exact`.
- `admit_arena_codes_first`: for each of the three two-code defects, `admit` returns the Arena code and `pairing::admit` on the same plan returns the comparison code.
- `study_race_level`: N = 2 → α; N = 5 → α/4; N = 9 → α/8, as exact rationals; a pairwise study carrying α refused with 802.
- `study_cluster_unit`: 12 episodes in 4 clusters with `all` give n = 4 units; one failed episode fails its unit; `mean` with a declared span gives the mean; the same worlds declared `unit: world` refused with 802 and pointer `/seed_protocol/unit`.
- `study_controller_arm_required`: no arm refused; `shared` with one `ControllerId` admitted and with two refused; `retuned-equal-resources` with equal and unequal step budgets; `inherits-weights` with and without a transfer baseline.
- `study_resources_field_by_field`: equal lists admitted; `steps` 10⁶ against 2·10⁶ refused with `observed` naming `steps` and both values; a `wall_clock_cap` carried by one arm only refused naming it; two test controllers whose `resources()` return the M1 fields plus `rho` (per channel, `0.3` against `0.5`) refused naming `rho`, plus `baseline_rung` (`R0` against `R1 budget=64`) refused naming `baseline_rung`, all equal admitted; a declared value contradicting the accessor's refused; the field order of the input does not change the result.
- `peeking_inflates_fixed_n`: exact enumeration of the sign test looked at after every pair gives 13/256 after 8 looks, 2869/32768 (8.76%) after 16, 12.95% after 32 and 17.42% after 64.
- `peeking_safe_under_confidence_sequence`: 10⁴ simulated null sequences of 64 pairs under the e-process of the anytime-valid engine: the fraction ever rejecting is at or below 5% (exact one-sided binomial check at the 1% level).
- `status_hides_interim_inference`: the status object of a fixed-n study at 30 of 64 units has no `interval`, `p_value` or `verdict` field.
- `admit_records_before_first_episode`: the admitted declarations' ledger sequence is smaller than the first episode's.

the STD-E2E helper and uses only this bead's dependencies; `study.plan` routes through `admit` only once N33b-19

1. `admit_fixed_n`: the fixture-1 plan at n = 86: admitted; the admitted declarations and the pre-analysis hash
   (equal to `frob eval preanalyze … --n 86 --json`'s) logged.

   attached), 533, each with `e2e_expect_refusal <code> 3` and the ranked repairs logged.
3. `arena_codes_first`: the same three plans through `pairing::admit` alone (`--pairing-only`): 553, 555, 542.

### Known answers and negative controls
KA-618 (peeking: 13/256 after 8 looks, 8.76%, 12.9%, 17.4%; control: the same data under a confidence sequence
stay below their level). CX-266 (look at a fixed-n test after every pair and stop when it rejects). CX-265.
Negative control for INV-ARENA-05: a build that lets `study.status` return a running p-value for a fixed-n
study; the interim test must fail. Negative control for the code order: a build that calls `pairing::admit`
before BD-124's checks; `admit_arena_codes_first` must fail. Metamorphic: relabelling the two arms mirrors
every admitted study and refusal. Determinism: admission is D0; the same request gives the same study address
twice and across machines.

## Considerations

- The peeking numbers depend on the stopping rule "reject when the exact one-sided p-value is at most 5% at any look"; the test fixes that rule and reproduces the fractions exactly.
- For metrics claimed singly across several metrics, the e-value form of the Benjamini–Hochberg rule applies in the comparison engine; this layer only checks that each metric has its own declared span.
- The qualification lane re-uses `admit` at the level α_i of a request, with clusters as units (bead N24b-16).
- Until `study.plan` routes through `admit` (requested of N33b-19), the verb raises 552, 532 and 533 through BD-124 directly and checks 5 to 7 do not run on that path; N24b-21's step `refuse_admission_declarations` fails until then, which is the intended signal.
- What would make us revisit: an engine that can provide exact fixed-n inference with a valid group-sequential boundary would be a third declared type with its own stopping rule, never a relaxation of these two.
