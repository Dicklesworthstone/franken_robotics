## Background

Unit tests show that pieces work. An end-to-end script shows that a user or an agent driving the real `frob`
binary gets the same answers, with the evidence attached, and that failures are reported in a form someone can
act on. This script covers the user-visible capability "run a registered fixture and see every row against its
known answer" for `fixture:cart-sill-dock`: a loaded cart with 60 mm front wheels (design A) or 75 mm front
wheels (design B) crosses a 12 mm sill and docks. It is the script from which the referee rows of
GATE-ARENA-04 are recorded (fixture 1: every analytic row within tolerance on the referee and inside the
fidelity envelope on the batch tiers; the creep rigs flip at the stated thresholds; both negative controls are
caught), and with one parameter it serves the batch-tier half at M2.

A closed bead is not acceptance: the gate record cites this script's log, which carries measured values, the
commit, the hardware fingerprint and the seed.

## Scope

In: one script, its steps, assertions, negative controls, structured log, idempotence and seed handling. Out:
the fixture and its mechanisms (their beads); the variants' physics (N24b-08) and the batch-tier lowering
(N24b-09), which this script only drives.

## Technical approach

**Path and invocation.** `scripts/e2e/arena_fixture_cart_sill_dock.sh [--tier referee|batch-cpu|cuda|metal]
[--variants] [--mutants] [--long]`. Plain shell; exits non-zero on any failed assertion; idempotent (it writes
only under `target/e2e-logs/arena_fixture_cart_sill_dock/` and a scratch store it creates and removes); every
random input is named by an explicit seed printed in the log (master seed 17 for the batch).

**Steps (each a `step` value in the log).**

1. `register`: `frob task fixture cart-sill-dock --layer analytic --tier host --json` on a fresh store; assert
   `registered_seq` is present and smaller than the sequence of any run record.
2. `refuse_changed_constant`: copy the manifest to scratch, change g from 9.81 to 9.80665, run again; assert
   refusal `FROB-REF-530`, exit code 3, pointer at the constant.
3. `analytic_host`: assert the ten rows: 8.000 and 8.225 kg; 40 N and 32 N; 222.22 and 142.22 N per m/s;
   36.000 and 40.694 mm; friction demands 0.7500, 0.6459, 0.7332, 0.6351 and torque 1.270 N·m; rear demand
   24/23 = 1.043 and 0.887, and 34.2 N against the 32 N cap; 23.0 mm and 1.13%; 0.471 J against 0.360 + 0.018
   J; spectral radii 1.4820, 0.9207, 2.6917, 2.7075; power-ledger figures 9 W, 0.375 A, 8 V, 16 W, 20 W, 4 W.
4. `check_task`: `frob task check <task>`; assert admission, reach 8 s against horizon 8 s, the labelled
   examples agree, the mutation check passes.
5. `settle`: `frob task settle` for designs A and B; assert penetration at most 0.5 mm and first impulse within
   5% of static support.
6. `nominal`: one episode per design at μ = 0.8, δ = 0, heading 0, sharp lip; `frob task verdict`; assert a
   `frob.verdict/1` with coverage kind `interval` and zero missing samples; log both verdicts.
7. `rigs_referee` (or `rigs_batch` with `--tier`): `frob task fixture cart-sill-dock --layer rigs --tier <t>
   --json`; one assertion per rig row with its tolerance.
8. `creep_brackets`: assert "does not climb" and "climbs" at each bracket pair (referee: 0.74/0.76, 0.64/0.66,
   0.72/0.74, 0.63/0.65, 1.03/1.05, 0.88/0.90; fast tiers: 0.74/0.76, 0.63/0.66, 0.72/0.75, 0.62/0.65,
   1.03/1.06, 0.87/0.90).
9. `boundary_flag`: the runs at the thresholds carry `boundary.flagged = true`.
10. `negative_controls` (with `--mutants`, on a build with the `mutants` feature): `--control
    euler-current-then-wheel` and `--control rear-lip-removed`; the named rows must **fail**; the script
    asserts the failure and records each control as caught. If a mutant is silently ineffective the script
    fails.
11. `fixtures_battery`: `frob eval run --battery fixtures --json`; assert the resolved `BatteryId` is echoed.
12. `batch_register`, `batch_run`, `batch_report` (referee; the long step): `frob task fixture cart-sill-dock
    --layer batch --tier referee --json`, waiting on the job handle; assert the input table's registration
    precedes the first episode, 128 verdict objects exist, the accounting identity sums to 64, the reported
    interval and verdict equal a recomputation from the counts with `frob eval preanalyze`'s rule, and both
    energy-per-completion figures are printed.
13. `variants_register`, `variants_run` (with `--variants`): the five registered variants of N24b-08.
14. `determinism`: steps 6 and 7 run twice; assert identical trace digests and row values.

**Logging (the standard of the shared helper from STD-E2E).** The script sources the helper and writes
newline-delimited JSON to `target/e2e-logs/arena_fixture_cart_sill_dock/<utc-timestamp>.ndjson` and a
human-readable transcript beside it. Every line has `ts`, `script`, `bead`, `step`, `event` (`start`, `cmd`,
`assert`, `metric`, `refusal`, `end`), the exact command line, exit code, wall time, the envelope's `evidence`
block (claim, class, tier, determinism, identities, seed), measured values with units and their thresholds,
digests where state is compared, and on failure the first differing value and the artifact paths needed to
reproduce (the `.frun` episode, the rig file, the friction value and world address). Per batch condition a
`metric` line records the address (17, k, 0), the four drawn values, both verdicts, margins and reasons. A
final `summary` line gives counts of assertions passed and failed, controls caught, and the gates touched
(GATE-ARENA-04 referee rows, or batch-tier rows with `--tier`). Logs contain no private-scene data (the
fixture is synthetic).

## Acceptance criteria

- [ ] The script exists, is executable, and passes on a clean checkout at M1 with `--tier referee`; with a batch tier once N24b-09 lands.
- [ ] Every step emits `start`, at least one `cmd`, its `assert` events and `end`; the `summary` counts equal the number of assertions executed.
- [ ] With `--mutants`, each of the two controls makes its row fail and is recorded as caught; with a mutant made ineffective the script fails.
- [ ] Step 2 produces FROB-REF-530 and leaves the registered fixture untouched.
- [ ] Running the script twice gives identical digests for every compared step (determinism lane: twice on one machine).
- [ ] The gate record for GATE-ARENA-04 cites a log file of this script by path and digest.
- [ ] Cancelling the script during `batch_run` leaves no partial store and no orphaned job.

## Test plan

### Unit tests
The script is itself a test; its helper functions are covered by the tests of STD-E2E. A dry mode
(`--list-steps`) prints the step names, and a small test asserts the list above so that a silently dropped
step is caught.

### End-to-end script and logging
This bead is the script. Commands driven from the user's side: `frob task fixture`, `frob task check`, `frob
task settle`, `frob sim run`, `frob task verdict`, `frob eval run`, `frob eval preanalyze`. Assertions and log
content are listed above.

### Known answers and negative controls
KA-602 to KA-611 (the analytic rows), KA-612 (the rule at 64 pairs: 521, 521, 0, 1,103, used to recompute the
batch verdict), KA-598 (energy figures). CX-262, CX-263, CX-265. Negative controls exercised: the changed
constant (FROB-REF-530); the two registered mutants; a third self-check, in which the script is run with an
expected row value deliberately altered in its own table (`--selftest`) and must report a failed assertion,
showing that its assertions can fail. Determinism lanes: twice on one machine; with `--tier`, across backends
against class D3.

## Considerations

- Runtime: the analytic and rig steps take minutes on the referee; the batch (128 episodes of 8 simulated seconds) is the long step and runs behind `--long` in routine CI and always for the gate record.
- If the referee refuses a step at the lip in some rig or trial, the script reports the refusal as a `refusal` event with the world and does not retry with other settings.
- The script never edits the fixture manifest in place; the changed-constant case uses a scratch copy.
