## Background

A mission query is a file, `.fmission`, that states a design family, a world family, an observation channel, a
policy class, a horizon, predicates and, explicitly, the order of the quantifiers that relate them. The same
plant gives opposite answers under "one command per known build" and "one command for the whole family", so
admission echoes the quantifier order exactly as written and refuses an empty or inconsistent domain before
any compute is spent. This script drives admission from the user's side with the real `frob` binary: creating
a query, checking it, each admission refusal by its planted document, and the quantifier-order fixture. It
contributes the admission half of the mutation corpus that GATE-AUGUR-01 counts (admission and checker reject
100% of a mutation corpus of at least 60 mutated queries and certificates with the expected refusal code; zero
false accepts).

## Scope

In: one script, its planted documents, assertions, negative controls and structured log. Out: answering
queries and checking certificates (the mission-core, bundle and checker beads and their own scripts).

## Technical approach

**Path and invocation.** `scripts/e2e/mission_admission.sh [--mutants]`. Plain shell; non-zero exit on a failed
assertion; idempotent (writes only under `target/e2e-logs/mission_admission/` and a scratch store); no
randomness.

**Planted documents** live under `assets/fixtures/mission-admission/`, each a copy of the stance-family query
(four point feet carrying 400 N with 160 N ratings; free parameter v = 1/half-width on [2, 6] per metre) with
one change, and under `assets/fixtures/quantifier-order/` (the pusher y = max(0, g·u − d) on g ∈ [1/2, 2],
u ∈ [0, 2], d ∈ [0, 1/4], required y ∈ [3/4, 5/4]).

**Steps.**

1. `new`: `frob mission new stance.fmission --idempotency-key e2e-1 --json`; assert a `mission_id`; repeat with
   the same key and assert `idempotent_replay: true` and the same id.
2. `check`: `frob mission check <id> --json`; assert `admitted: true`, the echo line
   `∃ policy (per-nominal-design) ∀ world ∀ execution`, `prefix_class: robust`, tier `static`, determinism
   `exact`.
3. `identity`: re-submit the document with keys reordered and whitespace changed (same id expected); with
   `budget.wall_s` changed (same id); with the comparator of `rating` changed from ≤ to < (different id); with
   the horizon changed (different id).
4. `refuse_invalid_868`: four documents: an unknown field; a quantity without a unit; `"box": [2, 6]` as JSON
   numbers; `"value": "6/4"` (a non-reduced rational). Assert `FROB-REF-868`, exit code 3, a pointer to the
   field and the schema diff as first repair. Also the design box `["6", "2"]` (empty design domain).
5. `refuse_empty_world_874`: an empty hull for the first-moment parameter. Assert `FROB-REF-874` and the
   emptying constraint as first repair.
6. `refuse_conflict_877`: ratings of 90 N per foot against a 400 N load. Assert `FROB-REF-877` with the
   conflicting subset {force-balance, rating} and a Farkas certificate.
7. `refuse_prefix_884`: a document with no `quantifiers`; a document with a hidden parameter and no
   persistence. Assert `FROB-REF-884` and, for the second, the two candidate declarations with the out-and-back
   fixture (net displacement 0 if fixed per execution; {−1, 0, 1} if resampled).
8. `refuse_index_887`, `refuse_arrival_847`, `refuse_chance_846`: a policy indexed by a hidden as-built gain;
   an observation field with no arrival instant; a `prob` binder with no population. Assert each code.
9. `clairvoyant`: a document with `policy_class.kind = "clairvoyant"` without the exclusion-only label is
   refused; with the label it is admitted with `prefix_class: clairvoyant` and the warning.
10. `quantifier_order_fixture`: check the three pusher files. Assert: each echo equals the written order; the
    three ids differ; the per-build and shared files match their registered intents; the mis-ordered file
    (written ∀ world ∃ policy where ∃ policy ∀ (world, execution) is meant) is echoed as written and the
    fixture check reports failure for it, printing both prefixes.
11. `mcp_parity` (when the MCP surface exists): the same `mission.check` through the MCP tool returns the same
    envelope.
12. `negative_controls` (with `--mutants`): a build whose echo sorts binders (step 10's verbatim assertion
    must fail); a build that supplies a default prefix (step 7 must fail). Each recorded as caught.
13. `determinism`: steps 1 to 3 twice; assert identical ids and envelopes.

**Logging.** Per the shared helper of STD-E2E: newline-delimited JSON at
`target/e2e-logs/mission_admission/<utc-timestamp>.ndjson` with a transcript; every line has `ts`, `script`,
`bead`, `step`, `event`, the exact command line, exit code, wall time, the envelope's `evidence` block, the
`mission_id`, the echo line and `prefix_class`, and for each planted document a `refusal` event with code,
pointer and first repair. The `summary` line gives assertion counts, the number of admission mutants rejected
(to be added to the corpus count of GATE-AUGUR-01), controls caught and the gate touched.

## Acceptance criteria

- [ ] The script exists, is executable and passes on a clean checkout at M1.
- [ ] Every admission refusal (868, 874, 877, 884, 887, 847, 846) is triggered by its planted document with exit code 3 and its first repair.
- [ ] The quantifier-order fixture behaves as specified: verbatim echoes, distinct ids, and the mis-ordered file failing the fixture check.
- [ ] Identity is stable under formatting and budget changes and changes with a comparator or horizon change.
- [ ] With `--mutants`, both planted defects are caught.
- [ ] The count of admission mutants rejected is reported for the GATE-AUGUR-01 corpus, with zero false accepts.

## Test plan

### Unit tests
`--list-steps` and its asserting test. `--selftest` swaps the expected code of one planted document and must
fail.

### End-to-end script and logging
This bead is the script. Commands from the user's side: `frob mission new`, `frob mission check`, and the MCP
tool of the latter. Assertions and log content as above.

### Known answers and negative controls
The pusher's two prefixes (per-build command set [1/2, 2]; shared command set empty) define the fixture whose
echoes are asserted; KA-032 (the quantifier-order fixture); the persistent-gain known answer (0 against
{−1, 0, 1}). CX-045, CX-075. Negative controls: the mis-ordered file; the two mutant builds; the self-test.
Determinism: class D0, identical twice and on both platforms.

## Considerations

- A fresh agent drives the first mission slice through these verbs in a later bead; this script is the deterministic floor under that test.
- The script does not call `mission.synthesize`; the answers [1/2, 2] and ∅ are asserted by the mission-core script.
