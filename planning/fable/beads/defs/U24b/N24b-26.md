## Background

A mission query is a file, `.fmission`, that states a design family, a world family, an observation channel, a
policy class, a horizon, predicates and, explicitly, the order of the quantifiers that relate them. The same
plant gives opposite answers under "one command per known build" and "one command for the whole family", so
admission echoes the quantifier order exactly as written before any compute is spent. This script drives the
two admission verbs from the user's side with the real `frob` binary: creating a query, reading the
`mission.check` result an agent sees, the echo of every binder kind, what does and does not change a query's
identity, and the quantifier-order fixture with its registered negative control. It contributes admission
mutants to the corpus that GATE-AUGUR-01 counts (admission and checker reject 100% of a mutation corpus of at
least 60 mutated queries and certificates with the expected refusal code; zero false accepts).

DESIGN (one trigger, one script): the single-field refusal triggers of a mission query (868, 874, 877, 884,
887, 847, 846, 855, 856, 724, 881, 853) are asserted by `scripts/e2e/mission_admission.sh` (bead N25a-23), and
the refusal battery of N25d-32 reads that script's log. Both beads had named the same script path; this bead's
script is therefore a second, differently named script that asserts what N25a-23's case table does not: the
creation verb, the result shape, the echo renderings and prefix classes, the non-semantic identity rules and the
quantifier-order fixture, with every M1 admission check present. The two document-level 868 triggers N25a-23
does not hold (an empty design domain, refused by `mission.check` at position 2 after `mission.new` stored the
valid document; a quantity without a unit, refused by `mission.new` at check 1 with nothing stored) are planted
by BD-126's own script, `scripts/e2e/mission_new_check.sh`, which this script runs as a stage and whose
`refusal` lines it re-reads, so each trigger is asserted by one script.

## Scope

In: `scripts/e2e/mission_check_echo.sh`, its planted documents, assertions, negative controls and structured
log. Out, with the bead that has it: every single-field admission refusal of N25a-23's case table, and the
seven semantic identity mutations (N25a-23); the refusal battery of the chapter's twenty codes (N25d-32);
answering queries and checking certificates (the mission-core, bundle and checker beads and their scripts);
the exact golden transcript of the worked agent session (NJL-08).

## Technical approach

**Path and invocation.** `scripts/e2e/mission_check_echo.sh [--mutants] [--selftest] [--list-steps]`. Plain
shell; non-zero exit on a failed assertion; idempotent (writes only under
`target/e2e-logs/mission_check_echo/` and a scratch store created per run); no randomness.

**Documents.** Under `assets/fixtures/mission-admission/`: `stance.fmission` (four point feet carrying 400 N
with 160 N ratings; free parameter v = 1/half-width with chart `inverse-length` on [2, 6] per metre; bound
u = 3 per metre; first-moment hull (±60, ±30) N·m; prefix ∃ policy per nominal design, ∀ world, ∀
execution), and its variants generated by the script. Under `assets/fixtures/quantifier-order/` (BD-126):
`pusher-per-build.fmission`, `pusher-shared.fmission`, `pusher-misordered.fmission` and the manifest with
their registered intents (the pusher y = max(0, g·u − d) on g ∈ [1/2, 2], u ∈ [0, 2], d ∈ [0, 1/4],
required y ∈ [3/4, 5/4]).

**Steps.**

0. `stage_bd126`: BD-126's `scripts/e2e/mission_new_check.sh` runs as a stage; its log path and digest are
   logged.
1. `new`: `frob mission new stance.fmission --key "$(e2e_key new-1)" --json`; assert exit 0, a `mission_id`
   printed `q:…`, and the envelope's `bound.family` equal to `template:four-point-stance@1#b3:` followed by the
   BLAKE3 hash of the family file BD-126 ships (`assets/fixtures/mission/families/four-point-stance@1.toml`);
   repeat with the same key (`e2e_key new-1 --again`) and document and assert `idempotent_replay: true` and the
   same id; repeat with the same key (`--again` once more) and a changed document and assert `FROB-REF-803` with
   exit 7 and both resolutions
   shown (the surface's idempotency binding: a key reused with a different canonical request digest is a
   conflict); and `frob mission new` with no key refused with `FROB-REF-805`, exit 3.
2. `check_shape`: `frob mission check <id> --json`; assert exactly, under the worked session's names:
   `domain: "nonempty"`, `topologies: 1`, `free: ["v"]`, `quantifiers: "∃ policy per nominal design, ∀
   worlds, ∀ executions"`, `fragment: "linear static: exact answer available"`, `horizon: "static"`; and the
   additive fields `admitted: true`, `mission_id` equal to step 1's, `prefix_class: "robust"`,
   `quantifiers_echo` (three binders in the written order), `domain_summary`; evidence tier `static`,
   determinism `exact`; no `admission-incomplete` warning (every position's check exists at M1: positions 2 and
   4 to 13 by N25a-02, 14 by N25a-11, 15 by N25b-07, which is why those three beads are prerequisites).
3. `echo_renderings` (every document of steps 3, 4, 6 and 8 is created with `frob mission new` under a key of
   its own before it is checked): variants of the stance document with the `exists policy` scope set to `cell` and to
   `family` (the policy index changed to match, so the document stays admissible), and the admitted chance
   query of N25a-23's base fixtures (the twenty-world two-stage mission in its `joint` form, N25a-23's case
   a15, which carries a `prob` binder with population, event and confidence). Assert the rendered lines
   "∃ policy per cell, ∀ worlds, ∀ executions", "∃ policy for the family, ∀ worlds, ∀ executions" and, for the
   chance query, a line whose `prob` binder reads "P(worlds) ≥ p at confidence c" with that file's p and c
   as reduced rationals; `prefix_class` `robust`, `robust`, `chance`.
4. `echo_verbatim`: all six orders of the three binders of the stance document, each checked; assert that the
   rendered line and `quantifiers_echo` list the binders in the written order every time; and the classes of
   BD-126's rule: ∃π ∀w ∀τ and ∃π ∀τ ∀w `robust`; ∀w ∃π ∀τ, ∀w ∀τ ∃π and ∀τ ∀w ∃π `clairvoyant`, each with
   the warning that evidence for it cannot establish membership of the robust family; ∀τ ∃π ∀w `other`.
5. `clairvoyant_relaxation`: `policy_class.kind = "clairvoyant"` without the exclusion-only label is refused
   (the code and repair that N25a-02 registers for this rule); with the label it is admitted, echoed with the
   relaxation warning, and its result marks that it can exclude and never include.
6. `identity_nonsemantic`: re-submit the stance document with keys reordered and whitespace changed, with
   `name` changed, with `response` reduced to `["inner"]`, and with `budget.wall_s` changed from 60 to 600;
   assert the same `mission_id` each time. (`mission.check` is a read verb with no budget property, so a budget
   given as a call argument is not exercised here: it belongs to a run verb, `mission.synthesize`, whose bead
   BD-135 is not a dependency of this one.) The seven semantic mutations that must change the id are N25a-23's;
   this step logs its id beside theirs.
7. `refuse_document_868`: the two document-level triggers N25a-23's table does not hold, from the `refusal`
   lines of step 0's stage: the first-moment parameter with its `unit` removed, refused by `mission new` with
   FROB-REF-868, exit 3, pointer `/world/parameters/1/unit`, the schema diff as first repair, `retry:
   "after-change"`, nothing stored; and the free box of `v` written `["6", "2"]`, stored by `mission new` and
   refused by `mission check` with FROB-REF-868 (position 2), pointer `/design_domain/free/0/box`, the empty box
   as first repair, `admitted: false`. This step asserts the lines' fields and re-emits them in N25d-32's form.
8. `quantifier_order_fixture`: check the three pusher files. Assert: each echo equals the written order; the
   three ids differ; the per-build and shared files match their registered intents; the mis-ordered file
   (written ∀ world ∃ policy where ∃ policy ∀ (world, execution) is meant) is echoed as written, carries
   `prefix_class: "clairvoyant"`, and the fixture check reports failure for it, printing both prefixes side by
   side. The answers [1/2, 2] and ∅ are not asserted here (the mission-core script does).
9. `mcp_parity` (when the MCP surface exists): `mission_new` and `mission_check` through the MCP tools return
   the same `result` objects and evidence as steps 1 and 2.
10. `negative_controls` (with `--mutants`): (a) a build whose echo sorts binders: step 4 must fail; (b) a build
    that renders the earlier draft's line `∃ policy (per-nominal-design) ∀ world ∀ execution`: step 2 must
    fail; (c) a build that hashes `budget` into `MissionId`: step 6 must fail. Each is recorded as caught.
11. `determinism`: steps 1, 2 and 6 run twice; assert identical ids and byte-identical `result` objects.

**Logging.** Per the shared helper of STD-E2E: newline-delimited JSON at
`target/e2e-logs/mission_check_echo/<utc-timestamp>.ndjson` with a human-readable transcript beside it; every
line has `ts`, `script`, `bead: "N24b-26"`, `step`, `event` (`start`, `cmd`, `assert`, `refusal`, `metric`,
`end`), the exact command line, exit code, wall time, the envelope's `evidence` block, the `mission_id`, the
echo line and `prefix_class`. Each `assert` line carries expected and observed; on failure the first differing
field (by JSON pointer) and the path of the document and the scratch store needed to reproduce. Each planted
document of step 7 writes a `refusal` line with code, pointer, observed, required and first repair in the form
N25d-32 reads. The final `summary` gives assertion counts, the number of admission mutants rejected (added to
the GATE-AUGUR-01 corpus count with the script name, so N25a-23's count and this one are summed without
overlap), the controls caught and the gate touched.

## Acceptance criteria

- [ ] The script exists, is executable and passes on a clean checkout at M1.
- [ ] Step 2 returns the six worked-session fields with exactly the renderings above, and the additive fields.
- [ ] Every binder kind renders as specified; all six orders of the stance prefix echo verbatim with the stated `prefix_class`.
- [ ] `name`, `response`, `budget` and formatting leave `MissionId` unchanged.
- [ ] The missing unit is refused by `mission new` with FROB-REF-868, exit 3, its pointer and first repair, and stores nothing; the empty design domain is stored by `mission new` and refused by `mission check` with FROB-REF-868, its pointer and first repair (both from the stage of BD-126's script, which passes).
- [ ] No call uses `--idempotency-key` or an option its verb's registry row lacks; every `mission new` carries `--key`.
- [ ] The quantifier-order fixture behaves as specified: verbatim echoes, distinct ids, and the mis-ordered file failing the fixture check.
- [ ] With `--mutants`, the three planted defects are caught; `--selftest` (one expected value swapped) makes the script exit non-zero.
- [ ] No refusal trigger of N25a-23's case table is asserted by this script (checked by `--list-steps` against N25a-23's case list).

## Test plan

### Unit tests
`--list-steps` prints the twelve step names and the trigger list; a shell test asserts the list and that it is
disjoint from N25a-23's case triggers. `--selftest` swaps the expected rendering of one binder and must fail.

### End-to-end script and logging
This bead is the script. Commands from the user's side: `frob mission new`, `frob mission check`, the MCP
tools `mission_new` and `mission_check`, and BD-126's script as a stage. Assertions and log content as above.

### Known answers and negative controls
The pusher's two prefixes (per-build command set [1/2, 2]; shared command set empty) define the fixture whose
echoes are asserted; KA-032 (the quantifier-order fixture: "for every world, some controller works" and "one
controller works for every world" receive different answers). CX-045 (one policy per world accepted as
evidence that one policy works for all worlds), CX-075 (the order is ∃u ∀(w, e) for a safety filter).
Negative controls: the mis-ordered file; the three mutant builds; the self-test. Determinism: class D0,
identical twice, in debug and release, on both platforms.

## Considerations

- A fresh agent drives the first mission slice through these verbs in a later bead, and the golden transcript
  (NJL-08) pins the worked session exactly; this script is the deterministic floor under both.
- The script does not call `mission.synthesize`.
- The two document-level 868 triggers are planted by BD-126's script (the mechanism's own); if N25a-23 later adds them to its table, BD-126's script reads that log instead, and step 7 follows it, so the one-trigger rule holds.
