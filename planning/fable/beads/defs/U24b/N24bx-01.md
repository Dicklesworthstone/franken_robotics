## Background

A **fixture** is a small registered task whose answers are known before any run. The verb `task.fixture`
(kind `run`, first milestone M1) "runs a registered fixture's analytic layer or batch and reports every row
against its known answer". Bead N24b-03 builds the fixture registry and that verb, with the input fields
`fixture`, `layer`, `rows`, `tier`, `designs` and `control`.

The fixtures that other subsystems register need more than those six fields. The Sinew scripts run one
motor fixture at several **actuator levels** (the fidelity ladder of an actuator model: L0 ideal torque
source, L1 torque-speed envelope with reflected inertia and delay, L2 winding current and thermal dynamics,
L3 the rotor as its own coordinate with backlash), ask for **one measured quantity** (`stall-torque`,
`no-load-speed`, `mechanical-time-constant`, `electrical-time-constant`, `thermal-rise`), run batched tiers
at a stated **precision** (`f64` or `f32`), and name the **seed** of a generated case set. Other scripts
select a step-plan **profile** (`lockstep`), a named **variant** of a fixture, or named **report sections**
(`inertia`, `energy`). The Arena's own fixture 2 (`quad-split-grip`, BD-202, N24b-13) runs a named **case
set** (`development` or `holdout`), with or without the **reflected** counterparts of its split-grip cells,
under one of two registered **contact laws** (`rigid`, `compliant`). None of these has a schema field, so
each script would invent its own spelling and the verb registry (which validates every input against its
schema) would reject all of them.

The constraint that shapes the design is ADR-ARENA-10, "a fixture is complete before its first run", and
its invariant INV-ARENA-04: a fixture's constants, seeds, input table and rule are hashed into the ledger
before its first run. A seed or a level typed on the command line and forwarded to the simulator would be a
value nobody registered: the fixture could be re-run with another seed after a failure, which is the tuning
harness the decision exists to prevent. So the caller never *supplies* such a value. The manifest
**declares** each axis with its finite set of admitted values, the declaration is part of the hashed
manifest, and the caller **selects** one declared value. DESIGN, with rejected alternatives:

- *Free pass-through of options to `sim.run`.* Rejected: breaks INV-ARENA-04 as described.
- *One fixture name per combination* (`dc-ref-a-l1-f64-seed7`). Rejected: the same derivation and constants
  would be copied across names, against ADR-GAUNT-06 (one fixture identity per physical case), and a
  correction would have to be made in every copy.
- *Leaving option names to each script.* Rejected: two scripts would spell one axis differently and the
  generated MCP tool `task_fixture` would have no schema for either.

Layer: Arena, crate `frob-arena`, tier Solid. Serves the claim "Known answer" of every fixture row.

## Scope

In: the manifest section `axes` and the row attributes `when`, `measure` and `group`; the added input
fields of `frob.task.fixture.in/1` and their command-line flags; resolution, validation and refusal; the
`selection` block of the output; the per-selection pre-run record; the fixture rows of `task.list`.

Out: the registry, `FixtureId`, the pre-run record of the manifest and the six original input fields
(N24b-03); the `fixtures` battery and `--battery fixtures` (N24c-10, N24b-01); the content of any fixture
(the Sinew fixtures: BD-070 and its neighbours; fixture 1: BD-123; fixture 2: BD-202); the actuator levels
themselves (BD-070 and later Sinew beads); precision profiles of tiers (Spark and Kinesis).

## Technical approach

**Manifest section `axes` (DESIGN; an optional section of `frob.fixture/1`, so it enters the canonical
manifest and therefore `FixtureId`).** Each axis is a named finite set with a default:

| Axis | Manifest key | Admitted values | Flag | Input field |
|---|---|---|---|---|
| Actuator level | `axes.actuator_level` | a subset of `L0`, `L1`, `L2`, `L3` | `--actuator-level` | `actuator_level` |
| Precision | `axes.precision` | a subset of `f64`, `f32` | `--precision` | `precision` |
| Seed | `axes.seed` | a list of unsigned 64-bit integers written as decimal strings | `--seed` | `seed` (a string) |
| Profile | `axes.profile` | a subset of the step-plan profile names the tier registers (for example `lockstep`) | `--profile` | `profile` |
| Variant | `axes.variant` | names, each with a table of constant overrides | `--variant` | `variant` |
| Case set | `axes.set` | names, each with the list of cell ids of the batch it runs (for example `development`, `holdout`) | `--set` | `set` |
| Reflection | `axes.reflect` | a subset of `false`, `true`; `true` admitted only if the manifest names each reflectable cell's mirror (the mirror map of BD-202) | `--reflect` (sets `true`) | `reflect` (boolean) |
| Contact law | `axes.contact_law` | names of contact-law identities the manifest registers (for example `rigid`, `compliant`, each a `ContactLawId` hashed with the manifest) | `--law` | `contact_law` |

Form: `[axes.actuator_level] values = ["L1", "L2"]  default = "L1"`. An absent axis has exactly one value,
its implicit default: the level each actuator card of the fixture's designs declares, `f64`, the fixture's
only seed, the tier's default profile, no variant, the batch's whole cell list as the one set, `false` for
reflection, and the fixture's one contact law. The cell lists of `axes.set` must be disjoint where the
manifest marks a set `held_out = true`: a held-out cell may not appear in any other set, and the fixture's
own rule for a held-out set (N24b-13: its registration precedes its first episode) is applied on top of the
selection record below, not replaced by it. `actuator_level` uses the value domain of `sim.run`'s
`--actuator-level` (L0 and L1 from BD-070, L2 from BD-071; L3 answers 724 there until its pilots land); the fixture verb overrides the card level of every actuator of the rig with the
selected one. For a batch, `axes.seed` must equal the list of `batches[].master_seed`; for a generated case
set (for example 10⁴ random couplings) the manifest also carries the generator pin and the count, and the
hash of the resolved case table for each seed. A `variant` is a constants override declared in the
manifest, so its values are hashed with everything else.

**Row attributes.** A row may carry `when = { actuator_level = ["L2"], precision = ["f64"], tier = [...] }`
(the row exists only for selections that match; absent means always), `measure = "<slug>"` (the measured
quantity the row reports, lower case with hyphens) and `group = "<name>"` (a report section). A row's
`tolerance` may be keyed by precision inside a tier: `tolerance.batch-cpu.f32 = "1e-3"`. Tolerances stay
fixture constants and are hashed.

**Selectors.** `measure` (flag `--measure <slug>`) selects the rows whose `measure` equals the slug.
`report` (flag `--report a,b`) selects the rows whose `group` is listed. `rows` selects by row id, as
before. Given together they intersect. `--analytic` is accepted as a spelling of `--layer analytic`, and
`--key` is the idempotency key N24b-03 already takes.

**Resolution, as numbered steps, inserted after step 1 of N24b-03's invocation algorithm:**

1. For each axis, take the requested value or the default. A value that is not a member of the axis's
   declared set is refused with FROB-REF-530 ("a run offered as a fixture run does not match the fixture's
   recorded hash"), exit code 3, `pointer = axes.<axis>`, with the declared values attached and the ranked
   repairs: (1) select a declared value; (2) register a new fixture version that declares the value.
2. A value that is not in the axis's domain at all (`--actuator-level L7`, `--precision f16`) fails schema
   validation of the input before any fixture is loaded, with the verb registry's invalid-input refusal
   FROB-REF-802 (arguments fail the schema).
3. Check the selection against the tier: an actuator level or a row option the tier does not carry is
   refused with FROB-REF-136 ("a row option the requested tier does not carry"); a profile the tier does not
   register with FROB-REF-222 ("profile not available on tier"); `f32` on a tier that offers only `f64`, or
   the reverse, with FROB-REF-136. Each names the tier and the nearest admitted selection.
4. Compute the set of rows: those whose `when` matches, intersected with the selectors. An empty set is a
   finding of the caller's request, refused as in step 1 with `pointer = rows` and the list of rows that
   exist for the selection. A row that exists but is excluded by a selector is reported under
   `rows_not_selected`, so that a partial run is never read as a full one.
5. Compute `SelectionId` = BLAKE3 of the canonical tuple (`FixtureId`, actuator level, precision, seed,
   profile, variant, set, reflect, contact law). Look up the ledger record `fixture-selection {fixture_id, selection_id, case_table_hash,
   ledger_seq}`; if absent, write it in its own transaction before any rig or episode of this selection is
   scheduled. This extends INV-ARENA-04 to each selection: its record precedes its first run.
6. Run, and evaluate each selected row with the tolerance of the tier and precision.

**Output.** `frob.task.fixture.out/1` gains `selection: {actuator_level, precision, seed, profile, variant,
set, reflect, contact_law, selection_id, selection_seq}` (`seed` and `selection_seq` are strings), `rows_not_selected: [id]`, and per row
`measure` and `group`. Episodes of the run carry `fixture` and `selection` in their run record. Evidence is
unchanged from N24b-03 (claim Known answer, class `Tested`, tier as run); the determinism class is the one
the tier, precision and profile give, and it is printed beside the tier. Exit codes are those of N24b-03:
0 all selected rows pass, 2 at least one out of tolerance, 3 refused, 8 job handle returned.

**Listing.** The registered fixtures are listed by the read verb `task.list` with the optional input field
`kind = "fixture"` (`frob task list --kind fixture --json`; over MCP `task_list` with `kind`), which this bead
adds to `frob.task.list.in/1` (absent, the verb lists tasks as before). `task.fixture` has no listing option:
a command-line spelling that the MCP surface lacks would be the CLI-only alias NJL-04 rejects (`surface-alias`)
and INV-TETHER-01 forbids, so `frob task fixture --list` is an unknown option (FROB-REF-802). The fixture
entries carry: name, version, kind (`synthetic` or `measured`),
`fixture_id`, registered or not, layers, and the declared axes with their values and defaults, so that an
agent discovers the admitted selections without reading a manifest. Pagination is that of `task.list`.

**Registry.** The verb's entry in `registries/verbs.toml` gains the refusals FROB-REF-136 and FROB-REF-222;
the schema file gains the fields above, each optional. Nothing else about the verb changes.

## Acceptance criteria

- [ ] `frob.task.fixture.in/1` validates `actuator_level`, `precision`, `seed`, `profile`, `variant`, `set`, `reflect`, `contact_law`, `measure` and `report`; the generated MCP tool `task_fixture` shows them.
- [ ] `--set`, `--reflect` and `--law` select only declared values; on a fixture that declares none of them, `--set other`, `--reflect` and `--law compliant` are each refused with FROB-REF-530 and the pointer of their axis; a manifest whose held-out set shares a cell with another set is refused at registration.
- [ ] A fixture with `axes.actuator_level = ["L1","L2"]` runs at each level through `--actuator-level`, and the row set differs as its `when` clauses say.
- [ ] `--seed` with a value outside `axes.seed` is refused with FROB-REF-530, exit code 3, `pointer = axes.seed`, listing the declared seeds; no ledger record and no episode is written.
- [ ] Adding a value to an axis changes `FixtureId` and is refused as a changed fixture until a new version is registered.
- [ ] `fixture-selection` is written before the first episode of each selection (ledger order asserted) and is written once per selection.
- [ ] `--measure stall-torque` returns exactly the rows with that measure and lists the others under `rows_not_selected`.
- [ ] `--precision f32` applies the `f32` tolerance of the tier; on a tier without `f32` the call is refused with FROB-REF-136.
- [ ] `frob task list --kind fixture --json` (and `task_list` with `kind = "fixture"` over MCP, byte-identical) lists every registered fixture with its axes; `frob task fixture --list` is refused as an unknown option (FROB-REF-802).
- [ ] Every option spelling used by the scripts that depend on this bead is accepted: `--actuator-level`, `--measure`, `--precision`, `--seed`, `--profile`, `--variant`, `--set`, `--reflect`, `--law`, `--report`, `--analytic`, `--key`.
- [ ] `scripts/e2e/arena_fixture_axes.sh` passes on a clean checkout at M1.
- [ ] `CONTRACT.md` of `frob-arena` records the axes, the selection record and the refusals.

## Test plan

### Unit tests
- `axes_enter_fixture_id`: property test on a `synthetic` manifest; adding, removing or reordering a value of any axis changes `FixtureId` (reordering is canonicalized for sets, so only the default's change counts; asserted both ways).
- `undeclared_seed_refused`: `axes.seed = ["7"]`, request `seed = "8"`; expect FROB-REF-530 with `pointer = axes.seed` and no `fixture-selection` record.
- `default_selection_when_axes_absent`: a manifest without `axes` runs with no selector and reports the implicit defaults in `selection`.
- `when_clause_filters_rows`: rows gated on `L2` are absent at `L1` and are not reported as failed.
- `measure_and_rows_intersect`: `rows = [r1, r2]`, `measure` matching `r2` only; expect one row and `rows_not_selected` holding the rest; a disjoint pair is refused.
- `selection_record_precedes_first_run`: `selection_seq` is smaller than the sequence of the first run record; a second invocation writes no second record.
- `selection_id_is_stable`: the same tuple gives the same `SelectionId` in debug and release.
- `precision_tolerance_lookup`: the `f32` tolerance is used for an `f32` run and the `f64` one otherwise; a row with no `f32` tolerance and an `f32` request is refused, never evaluated with the `f64` tolerance.
- `tier_lacking_level_refused`: `L3` on a tier without rotor rows gives FROB-REF-136 naming the tier.
- `seed_is_a_string_in_json`: a seed above 2⁵³ round-trips exactly.
- `set_reflect_law_axes`: a `synthetic` manifest with sets `development` (cells c1, c2) and `holdout` (c3, `held_out = true`), a mirror map c1↔c1′, and contact laws `rigid` and `compliant`; the eight selections of (set, reflect, law) give eight distinct `SelectionId`s; `--reflect` with set `holdout` and no mirror for c3 is refused with FROB-REF-530 (`pointer = axes.reflect`, the reflectable cells listed); `--set validation` is refused with FROB-REF-530 (`pointer = axes.set`).
- `held_out_set_disjoint`: a manifest putting c3 in both `development` and the held-out set is refused at registration with the registry loader's schema error naming c3.

### End-to-end script and logging
This bead's own script, `scripts/e2e/arena_fixture_axes.sh` (header `bead=N24bx-01 milestone=M1`; sources the
helper of STD-E2E; seed-explicit; idempotent). Every `frob task fixture` call carries `--key "$(e2e_key
<label>)"` with its own label (the verb is `run`; convention 5). On the `synthetic` fixture `axes-demo` (one DC
motor: k_t = k_e = 0.05, R = 0.5 Ω, L = 1 mH, N = 10, η = 0.9, I_max = 40 A, V_lim = 24 V; axes: levels L1 and
L2, precisions `f64` and `f32`, seeds 7 and 9):
1. `frob task list --kind fixture --json`: assert `axes-demo` with its axes and defaults; `frob task fixture
   --list --json` is refused with FROB-REF-802 (no such option).
2. `frob task fixture fixture:axes-demo --tier referee --actuator-level L1 --measure stall-torque --seed 7 --key
   "$(e2e_key stall-l1-7)" --json`: assert one row, 18.0 N·m (η·N·k_t·I_max = 0.9·10·0.05·40), and
   `selection.seed == "7"`.
3. The same with `--measure no-load-speed` under its own key: 48 rad/s (V_lim/(k_e·N)).
4. The same with `--seed 8`: exit code 3, FROB-REF-530, `pointer = axes.seed`.
5. `--actuator-level L2 --measure electrical-time-constant`: 2 ms (L/R).
6. `--tier referee --precision f32` under its own key: exit code 3, FROB-REF-136 naming the tier `referee`
   (its step is double precision only) and the nearest admitted selection (`f64`); no `fixture-selection`
   record. The `f32` tolerance on `batch-cpu`, an M2 tier, is the unit test `precision_tolerance_lookup` here and
   runs end to end in N24b-09's script.
7. `refuse_undeclared_run_axes`: on `axes-demo` (which declares no case set, reflection or contact law),
   `--set holdout`, `--reflect` and `--law compliant` in turn: exit code 3, FROB-REF-530, pointers
   `axes.set`, `axes.reflect` and `axes.contact_law`; assert no `fixture-selection` record was written. The
   selecting path of these three axes is driven on fixture 2 by N24b-22 (`--set development --reflect`,
   `--set holdout --law rigid|compliant`) and N24b-13's script.
8. `selection_record_once`: step 2 again under a new key: the same `selection_id`, and the ledger holds one
   `fixture-selection` record for it, written before the first run record.
Each step logs the command, exit code, wall time, the evidence block, `fixture_id`, `selection_id`, one
`assert` event per row with expected, measured, unit and tolerance, and a `refusal` event with code and
pointer; the final `summary` line gives the counts.

### Known answers and negative controls
- Known answers used by the script: stall 18.0 N·m, no-load 48 rad/s, electrical time constant 2 ms.
- Negative control `free-seed` (a `gauntlet-mutations` build that forwards an undeclared seed to the run): the test `undeclared_seed_refused` must fail.
- Negative control `late-selection-record` (the record written after the first episode): the ordering test must fail.
- Negative control `tolerance-fallback` (an `f32` run judged with the `f64` tolerance): `precision_tolerance_lookup` must fail.
- Determinism: `FixtureId` and `SelectionId` are D0: identical twice, in debug and release, across platforms.

## Considerations

- An axis is not a way to enlarge a fixture after seeing results: every added value is a new `FixtureId`, and earlier results stay attached to the old one.
- The product of the axes can be large; the verb runs one selection per call. A script that wants the whole product loops, and each selection is its own job with its own idempotency key.
- The option names here are the ones the dependent scripts already use; a later rename would be a change to a public schema and needs a schema version.
- `variant` overrides constants only. A variant that changes a design or the task is a different fixture.
- Follow-ups registered after a fixture's first run cannot be values of its axes, since adding a value changes `FixtureId`. The fidelity-dependence follow-ups of fixture 1 (N24b-08) are therefore registered as fixtures of their own, named `cart-sill-dock/<variant>`, each with its own `FixtureId`; the `/` spelling is part of the fixture name, not a selector, and their scripts pass no `--variant`.
- Security: axis values are identifiers checked against closed sets; none is used as a path component.
