## Background

A robot design in this system is a term, stored canonically as JSON (schema `frob.design/1`, extension `.fbot`);
its identity `DesignId` is the BLAKE3 hash of the canonical bytes. The standing rule of the design language is
"refusals instead of repairs in silence": an invalid design is refused with a stable code, a message and **ranked
repairs expressed as typed edits**, and nothing is ever defaulted behind the author's back.

The reason is decision ADR-SKEL-03 (no physics field has a silent default): each plausible default yields a
plausible wrong robot. Worked case: a torso box 0.42 × 0.20 × 0.10 m in aluminium at 2,700 kg/m³ weighs 22.7 kg
read as a solid block and 1.92 kg as a 2.5 mm shell, an error of 11.8 times; through the mass spiral (loop gain
0.59, so each kilogram of structure costs 2.4 kg of robot) a 20.8 kg error in one body becomes about 50 kg of robot
that does not exist, and every actuator is then sized for it. Rejected alternatives: a default fill (the case above);
a warning that lets the compile continue (the wrong robot is simulated under a valid identity); free-text advice
(an agent cannot apply it without another round trip).

A **lint** here is a check that `frob-design` can decide from the design term alone, before the model compiler and
before any analysis of `frob-analyze`. Lints are what stage 1 ("Form") of the eight-stage preflight `design.check`
runs, and what every verb that loads a design runs. A **typed edit** is one of the edit operations of the design
language (`set-param`, `set-fill`, `set-limits`, `set-contact-law`, `swap-module`, `retime`, `rename`, `migrate`,
`declare-lever`, `set-lever`, `lock`, `unlock`, `move-mount`, `replace`, and the others of the edit table), each with
preconditions, an inverse where one exists and a declared symmetry effect; they are implemented by BD-058. A repair
that is a typed edit can be applied by an agent in one call, and the envelope turns the first-ranked repair into
`next_actions`. Tier: Solid. Serves BET-05 (static checks give feedback in seconds) and the archetype catalogue:
BD-109 requires that each archetype "compiles and passes its lints".

## Scope

In: the lint engine in `frob-design`; the lints of the stage-1 refusal set (codes 101, 102, 103, 105, 111, 114, 121,
125, 126) and two advisory lints; the repair generator and its ranking; one triggering and one clean fixture per
lint; the three stage-1 first-rejection fixtures of the negative-control registry; the seeded stage-1 defects that
GATE-SKEL-04 counts.
Out: aggregation of the eight stages, per-stage timing and `design.check` itself (BD-110); refusals owned by later
stages (104 and 106 mass, 107 empty range, 110 closure, 123 self-collision in stages 2 and 3; 118 stage 4; 108 and
109 stage 5; 113, 115, 116, 124, 131 to 133 stage 6; 119 and 120 stages 7 and 8); card self-checks 130 and 134
(the actuator-card bead); the module contract check itself (BD-060; this bead only lints the import site); predicted
mass and margin deltas on repairs, which need the compiled model (BD-062, added by BD-110).

## Technical approach

**Types (DESIGN).** Module `crates/frob-design/src/lint/`.

```rust
pub enum Severity { Refuse, Advisory }
pub struct Finding {
    lint: LintId,                  // stable, e.g. "fill-missing"
    code: Option<RefusalCode>,     // FROB-REF-1xx for Refuse; None for Advisory
    severity: Severity,
    pointer: TermPath,             // JSON pointer into the canonical term, e.g. "/limbs/of/of/chain/1/body"
    message: String,
    observed: Option<Value>, required: Option<Value>, unit: Option<UnitToken>,
    repairs: Vec<Repair>,          // ranked, best first; may be empty only for Advisory
}
pub struct Repair { rank: u8, edit: TypedEdit /* BD-058 */, why: String }
pub trait Lint { fn id(&self) -> LintId; fn check(&self, term: &DesignTerm, cx: &LintCx) -> Vec<Finding>; }
pub fn lint(term: &DesignTerm, cx: &LintCx) -> LintReport;   // every lint, deterministic order
```

Lints run on the parsed term (after the parser of the term model, before admission as a version). The lint table is
a static slice in code; no new registry file is created. `LintReport` sorts findings by (severity, pointer, lint id),
so output bytes are a pure function of the term. Determinism class D0 (exact); evidence class `Tested`, tier
`static`.

**The lints.**

| Lint id | Code | Fires when | Repairs offered, in rank order |
|---|---|---|---|
| `field-unknown` | FROB-REF-103 | A field not in the field reference of its block; a duplicate key | `rename` to the known field at edit distance ≤ 2 (if unique); delete the field |
| `unit-dimension` | FROB-REF-102 | A quantity whose dimension is not the field's (a prismatic travel written in millimetres where the coordinate is read as an angle; a length where a mass is required); an expression adding different dimensions | `set-param` with the same number in the field's coherent unit, offered only when exactly one unit of the required dimension shares the written prefix; otherwise a repair naming the required dimension |
| `port-kind` | FROB-REF-101 | `attach`, `closure` or `use` joins ports of different kinds (mechanical onto electrical, signal onto power) | `move-mount` to the like-kinded port of the same body nearest by name; `replace` the child |
| `fill-missing` | FROB-REF-105 | A body with a Region and no `fill` | `set-fill {shell: t₀}`; `set-fill solid`; `set-fill declared` (needs `mass_properties`) |
| `shell-as-solid` | FROB-REF-105 | `{shell: t}` with t greater than half the Region's smallest dimension | `set-fill solid`; `set-fill {shell: t₀}` |
| `lever-bounds` | FROB-REF-111 | A lever whose current value lies outside its `bounds` or `choices`; a lever path that does not resolve | `set-lever` to the nearest bound; `declare-lever` with bounds widened to contain the value |
| `locked-write` | FROB-REF-111 | A patch or edit writes a path listed in `locks` | `unlock` the path then the edit; the same edit on the nearest unlocked sibling path, if one exists |
| `module-digest` | FROB-REF-114 | A `use` whose content hash does not match the module the name resolves to, or whose bound ports differ from the module's port list | `swap-module` to the resolved hash; correct the `bind` map |
| `contact-law` | FROB-REF-121 | An end effector (`foot`, `wheel`, `track`) with no `contact` block; a law that does not fit the kind (a `wheel` with `foot-patch`); a `foot-patch` torsion radius larger than the foot's own contact radius | `set-contact-law` to the kind's law (`foot-patch` for a foot, `wheel-rolling` for a wheel, `belt` for a track) with the interface card left to supply; torsion radius set to the contact radius |
| `schema-version` | FROB-REF-125 | An unknown major schema version | `migrate` to the current schema, naming the migration |
| `sensor-incomplete` | FROB-REF-126 | A sensor entry without `parent`, `rate` or `clock` | `move-sensor` onto the root body; `retime` to the card's nominal rate; `retime` onto the clock of the first sensor declared |
| `solid-heavy` | advisory | A `solid` body whose mass (density × Region volume, computed here for primitive Regions when the material card resolves) alone exceeds one quarter of `budgets.mass_max` | `set-fill {shell: t₀}`; `set-material` |
| `lattice-isotropy` | advisory | Any `{lattice: φ}` fill: the report prints that the model is an isotropic fraction φ of the solid moments | none |

t₀ is the largest of {1, 1.5, 2, 2.5, 3} mm that does not exceed one quarter of the Region's smallest dimension
(DESIGN of this bead: a deterministic proposal, never applied without the author's edit). `solid-heavy` is advisory
because solid is sometimes what is meant; when the density or volume cannot be computed the lint reports
`not-evaluated` with the reason and never guesses.

**Ranking (DESIGN).** Repairs are ordered by: fewest fields written; then repairs that apply under the enclosing
`mirror` or `radial` constructor (preserving the symmetry groups) before one-sided ones; then by edit name and path
in code-point order. A repair that would write a locked path is never offered. **Repair soundness** is a law:
applying the rank-1 repair of a finding yields a term on which that lint no longer fires at that pointer.

**Envelope.** A refusing finding becomes the envelope's `refusal` (`code`, `message`, `pointer`, `observed`,
`required`, `unit`, `retry: after-change`, `repairs`), exit code 3; advisory findings go to `result.findings` with
exit code 2. `next_actions[0]` carries the command line that applies the rank-1 repair.

**Fixtures.** `crates/frob-design/tests/fixtures/lints/<lint-id>/{trigger,clean}.fbot`, each derived from the small
quadruped example of the format (torso box 0.42 × 0.20 × 0.10 m, four mirrored three-joint legs) with one planted
change, plus a second trigger per refusing code under `seeded/` so that GATE-SKEL-04 has its two defects per code.

**If the static-analysis bet is killed (KILL-STATIC).** Verdicts of the static analyses are downgraded to advisory
lints. The severity field is what carries that downgrade; the form lints of this bead stay refusals, because they
are schema and unit errors and predict nothing.

## Acceptance criteria

- [ ] Each of the thirteen lints has a `trigger` fixture on which it fires with its code and pointer, and a `clean` fixture on which no lint fires (the seed's done-condition).
- [ ] On the `trigger` fixture of every refusing lint, only that lint fires (no collateral finding), and the report bytes are identical on Linux and macOS.
- [ ] Repair soundness holds for every repairing lint on its fixtures and on 10³ random single-defect mutations of valid designs.
- [ ] No lint fires on the first archetypes that exist at M1 or on 10³ random valid designs (the zero-false-refusal clause of GATE-SKEL-04, stage 1 share).
- [ ] The stage-1 seeded defects (at least two per code 101, 102, 103, 105, 111, 114, 121, 125, 126) are all refused by their own code.
- [ ] The three stage-1 first-rejection fixtures are caught: a prismatic travel in millimetres read as radians (102); a point foot with a torsion radius above its contact radius (121); a sensor with no frame, rate or clock (126).
- [ ] The worked torso yields `solid-heavy` when written `solid` against `mass_max: 14 kg` (22.68 kg > 3.5 kg) and no finding as a 2.5 mm shell (1.923 kg).
- [ ] Reachable through `frob --json` with the refusal envelope, exit code 3 for refusals and 2 for advisories; `crates/frob-design/CONTRACT.md` lists every lint under "refusals".

## Test plan

### Unit tests
`cargo test -p frob-design lint`:
- `lint_<id>_trigger` and `lint_<id>_clean` for each of the thirteen ids: asserts code, pointer, severity and the count of findings (exactly one, or zero).
- `fill_missing_ranks_shell_first`: a 0.42 × 0.20 × 0.10 m box with no fill offers `{shell: 3 mm}` first (one quarter of 0.10 m is 25 mm, so the largest listed value is taken), then `solid`, then `declared`.
- `shell_thicker_than_half_refuses`: a 0.10 m smallest dimension with `{shell: 51 mm}` fires 105; 50 mm does not.
- `torsion_radius_above_contact_radius`: sphere foot 0.022 m with `torsion_radius: 30 mm` fires 121; 8 mm does not.
- `solid_heavy_threshold`: masses of 3.49 kg and 3.51 kg against `mass_max: 14 kg` give no finding and a finding.
- `repair_soundness_property`: 10³ random mutations; rank-1 repair removes the finding.
- `repair_never_writes_locked`: every offered repair is checked against `locks`.
- `report_order_is_deterministic`: findings shuffled internally produce identical bytes.
- `no_lint_on_valid_designs`: 10³ generated valid designs, zero findings (PO: lints never refuse a valid design).

### End-to-end script and logging
`scripts/e2e/design_lints.sh`: for each refusing lint, `frob design view <trigger.fbot> --json` must exit 3 with the
expected `refusal.code`; the script then runs the command in `next_actions[0]`, re-runs the view and expects exit 0
or 2. For each `clean.fbot` it expects exit 0. Logged as NDJSON under `target/e2e-logs/design_lints/` with the shared
helper: `ts`, `script`, `bead`, `step`, `event`, the exact command, exit code, wall time, the envelope's `evidence`
block, the refusal code observed against the code expected, the digest of the report, and on failure the first
differing field with the fixture path. A final `summary` line gives assertions passed and failed and names
GATE-SKEL-04 (stage 1 share). When `design.check --stages 1` exists (BD-110) the same script gains that entry point.

### Known answers and negative controls
Known answers: the solid and shell torso masses 22.68 kg and 1.923 kg (and their ratio 11.8). Negative controls
(planted failures the tests must catch): a lint engine built with a default fill passes `fill-missing/trigger` and
must fail the suite; a repair generator that proposes a locked path; a ranking that depends on hash-map iteration
order. Metamorphic: an edit followed by its inverse returns the same `DesignId` and the same lint report; key order
and white space in the input never change a finding. Determinism: twice on one machine, debug and release, Linux
and macOS, all byte-identical (class D0).

## Considerations

- The repair proposals and the ranking rule are DESIGN choices of this bead; the plan fixes only that repairs exist, are ranked and are typed edits. Revisit them if agents in the surface A/B routinely skip the rank-1 repair.
- A lint must never become a silent default: a repair is applied only by an explicit edit, and applying it creates a new design version with its own identity.
- Module lints depend on the module registry; where it is not yet present the `module-digest` lint is compiled out behind the same test names and reported as not built.
- Performance envelope: stage 1 as a whole has a 95th-percentile budget of 100 ms on any archetype (TARGET); linting is linear in term size and allocates no model.
- OPEN-SKEL-4 (whether lattice fills need anisotropy; default isotropic with the assumption printed) is what `lattice-isotropy` implements. OPEN-SKEL-2 (card prices are `assumed`, so the cost budget is advisory) is a stage-6 concern and not a lint here.
