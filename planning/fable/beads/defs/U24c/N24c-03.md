## Background

An episode that starts with a foot 2 mm inside the floor begins with an impulse that no robot would feel, and a
paired comparison in which one design starts settled and the other does not compares spawn artifacts, not designs.
The design decision is therefore that episodes start from **precomputed quasi-static poses**: for each model and
spawn specification a small set of states that have been simulated to rest. `task.settle` is the verb that builds
or refreshes that cache. A task whose cache is missing for the requested model is refused (FROB-REF-529), so no
run can start from an unsettled spawn by accident.

The pairing rules of design comparison depend on this: each design is settled separately, the settled equilibrium
is recomputed per design, and a state is never transported from one design to another; a comparison refuses a
pair whose initial states were settled for only one of the two designs. A design that starts in penetration makes
the pair `unscored`; a buildable design that then stalls is a failed trial, not a missing one.

Crate `frob-arena`; tier Solid. At M1 the only physics tier is the referee (double precision, CPU), which is what
the cart fixture and the first task families need. The same verb drives the batched tiers from M2, where the cache
and its gate are completed by the reset-cache bead.

Alternatives rejected: spawning at a nominal pose and discarding the first steps (the discard length becomes a
tuning constant and differs between designs); settling inside each episode (pays the settle time in every world
and makes the first transitions of training data artifacts).

## Scope

In: the verb `task.settle` (kind `run`, a long tool); the cache key and record; the settle loop and its
criterion on the referee; address-keyed selection of a pose; invalidation; the `Degraded: unsettled` mark;
FROB-REF-529; the hook that `sim.run`, `eval.run` and fixtures call to load a state.
Out: settling on `batch-cpu` and device tiers, the first-impulse check on every tier and GATE-ARENA-08 (BD-195);
registration of the cache as a node of the memo graph with shadow recompute (the memo-graph bead BD-111; this
bead only makes the key a content hash so that registration is possible).

## Technical approach

**Cache key (content hash).** BLAKE3 over: `ModelId`; the task's spawn specification (the `reset` section and the
part of `world` that fixes the ground under the spawn); the contact-law identifiers of the model's end effectors;
the versions of the step kernels or referee build that produced the states. Any design edit that changes mass,
geometry or contact surfaces changes `ModelId` and therefore the key: the old cache is not found, never reused.

**Record.** K = 64 settled states (TARGET), index k = 0 … 63. Each state holds: the configuration (base pose as a
group element, joint coordinates), contact warm starts, actuator states at rest (zero current unless the settle
controller holds posture), and the estimator's initial state. Stored as an artifact referenced from the ledger,
with the claim product (class `Tested`, tier of settling, determinism class of the tier).

**Spawn draws.** State k starts from the spawn specification with its declared variation (base position and yaw
range, joint-angle variation) drawn from the counter-based stream `reset/pose` keyed by (cache key, k). A draw
depends on nothing else, so rebuilding the cache reproduces it bit for bit on the same tier.

**Settle loop (per state).**
1. Place the model at the drawn pose, lifted so that no geometry penetrates the scene.
2. Step the referee under gravity with the settle controller the task names: zero command with brakes as carded
   for wheeled bases; the posture-hold command of the baseline controller for legged bodies.
3. After each step compute the largest base and joint speed in SI units (m/s and rad/s) and the maximum
   penetration over contacts.
4. The state is settled when speeds stay below 10⁻³ for 0.2 s of simulated time with maximum penetration at
   most 0.5 mm (TARGET).
5. Stop with failure after the settle horizon (DESIGN default 5 s simulated; a task may override it). A state
   that fails is stored as `Degraded: unsettled` with its last speeds and penetration; it is counted, never
   dropped, and a world that draws it carries the mark.
6. Record the static support force (the sum of contact normal forces at rest) for the first-impulse check: the
   first contact impulse after loading a cached state on any tier must lie within 5% of the static support force
   times the step (TARGET; measured on every tier by the M2 bead).

**Selection.** A world with address `WorldAddr = (run_seed, world, episode)` takes pose index
k = draw(`reset/select`, address) mod 64 from the counter-based stream. Two designs paired on one address get the
same k, hence the same spawn specification, each in its own settled state. For the cart fixture each design is
settled separately from "stationary, centred and parallel to the lane, front axle at x = −0.50 m".

**Verb.** `task.settle` (kind `run`; first milestone M1): input `task`, `model` (or `design` and `controller`),
`tier` (default `referee`), `--refresh`, idempotency key, budget; accepts the bounded synchronous wait
(`sync_wait_ms`) and otherwise returns a job handle with exit code 8. Output: the cache key, counts of settled and
unsettled states, per-state residual speed and penetration, wall time. Cancellation: request, drain the current
state, finalise; a cancelled build publishes nothing partial.

**Refusal.** FROB-REF-529 "No settled-pose cache for this model and task": raised by any verb that starts
episodes when the key is absent. Exit code 3; `retry: after-change`; ranked repairs: run `task.settle` for this
model and task (the command is given in `next_actions`); if the model changed, settle the new `ModelId`.

## Acceptance criteria

- [ ] `frob task settle --task cart-sill-dock --model <A> --json` builds 64 states on the referee; every state meets speed < 10⁻³ for 0.2 s and penetration ≤ 0.5 mm, or is recorded `Degraded: unsettled` and counted.
- [ ] Starting a run on a model with no cache refuses with FROB-REF-529 and names the settle command.
- [ ] A design edit that changes a wheel radius, a mass or a contact surface gives a new key; the old states are not loaded for the new model.
- [ ] Two designs on one world address receive the same pose index and each loads its own settled state; the selection is independent of batch size and world order.
- [ ] Rebuilding with `--refresh` on the same build reproduces identical state bytes (class D2 on the referee).
- [ ] The verb is a long tool: with a short wait it returns exit code 8 and a job handle; cancellation leaves no partial cache.
- [ ] `CONTRACT.md` of `frob-arena` documents the criterion, the key and the refusal.
- [ ] The referee measurements (residual speed and penetration on all 64 states per reference model) are recorded as the M1 rows toward GATE-ARENA-08; the gate itself is closed on the batched tiers at M2 by the reset-cache bead.

## Test plan

### Unit tests
`cargo test -p frob-arena settle`:
- `settle_box_on_floor`: a 1 kg box dropped 1 mm settles; penetration and speed below thresholds; static support force equals m·g = 9.81 N within 1%.
- `settle_criterion_window`: a body whose speed dips below 10⁻³ for 0.1 s and rises again is not accepted at 0.1 s.
- `unsettled_is_marked_and_counted`: a body on a 30° frictionless slope never settles; the state is `Degraded: unsettled`, count 1 of 64.
- `key_changes_with_mass_geometry_contact`: three single edits, three new keys; a rename leaves the key unchanged.
- `selection_same_index_for_pair`: designs A and B on address (17, 41, 0) both take the index the stream gives; 10³ addresses spread over all 64 indices.
- `selection_batch_invariant`: index for an address computed alone and among 8,192 addresses is equal.
- `missing_cache_refuses_529`.
- `state_never_transported`: loading design A's state into design B is a type error at the API (the state carries its `ModelId`), asserted by a compile-fail test.

### End-to-end script and logging
Step `settle` of `scripts/e2e/arena_m1_families.sh` (bead N24c-07): `frob task settle` for each M1 family and
reference model, then a run that loads the cache; and a negative step that runs a freshly edited design without
settling and expects FROB-REF-529. Logged: commands, exit codes (0, 8 then 0 after `job.wait`, 3), wall time, the
`evidence` block, counts of settled and unsettled states, the largest residual speed and penetration against
their thresholds with units, the cache key, and on failure the first state that missed the criterion.

### Known answers and negative controls
Known answer KA-601 fixes the targets this bead builds toward: penetration at most 0.5 mm and first impulse
within 5% of static support on all 64 states for each reference robot (measured as a gate at M2); its negative
control is that a design edit must invalidate the cache, which the key test above enforces at M1. Further
negative controls: a selector that uses a sequential generator gives the two paired designs different indices
when one has an extra limb; a cache keyed by design name survives a mass edit. Metamorphic: permuting world
indices permutes the selected poses and changes nothing else. Determinism: twice on one machine identical bytes;
debug and release agree on the settled/unsettled classification.

## Considerations

- The thresholds (10⁻³ SI, 0.2 s, 0.5 mm, 5%) and K = 64 are TARGETs; they are part of the task's `reset` section and therefore of the `TaskId`, so changing them makes a new task.
- Legged bodies settled under a posture-hold command have a controller in the loop; the settle controller's identity is part of the key through the spawn specification.
- Settle cost on the referee is 64 short simulations per model; for design campaigns at M2 and later the cache is built on `batch-cpu` in one batch.
- An unsettled state is evidence about the design (it cannot rest on this ground), not a nuisance to filter: unsettled counts appear in scorecards.
