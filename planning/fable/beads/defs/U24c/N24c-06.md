## Background

The task file and its verbs are the first thing an agent touches when it wants to state what a robot must do.
Unit tests inside `frob-spec` and `frob-arena` prove the parser and checker; they do not prove that the capability
is reachable from the user's side, with the documented exit codes, refusal envelopes and evidence blocks. This bead
is the end-to-end script for that capability: plain shell driving the real `frob` binary on real task files.

It is also the user-side measurement of the refusal half of GATE-ARENA-03: "every requirement-language refusal
(FROB-REF-520, -535, -536, -523, -538, -525, -526, -539 and -528) is triggered by its planted task file". The
monitor half of that gate (the three evaluators agree bit for bit on 10⁶ random traces per operator, including
multi-rate signals and windows with rounding) is measured by the requirement-language core bead; this script
records the refusal rows and cites the monitor rows' test.

A gate that nothing can fail validates nothing, so the script carries its own negative controls: files that
must be accepted, and a deliberately wrong expectation that must make the script fail when enabled.

## Scope

In: `scripts/e2e/arena_task_file.sh`, its fixtures under `scripts/e2e/fixtures/arena_task_file/`, its log schema
and assertions: `task.new`, `task.show`, `task.list`, `task.check` and `task.verdict` from the user's side, the
nine planted refusal files of record (BD-122's) each firing its code, the four example-stage steps, the receipt it
writes for the refusal rows of GATE-ARENA-03, and the nine-code constant `GATE_ARENA_03_REFUSALS` of
`frob-conformance` with its completeness test.

Out: the pipeline from authoring to verdict on golden runs, the 10⁶-trace monitor campaign and the assembled
receipt of GATE-ARENA-03, host half (N24a-42, which reads this script's refusal-row record); unit tests of the
mechanisms (their own beads); the M1 task families run (N24c-07); MCP parity of the same verbs (the M1 MCP tools
bead).

## Technical approach

**Script.** `scripts/e2e/arena_task_file.sh`, sourcing the shared helper from the end-to-end harness; idempotent
(it works in a fresh namespace named from the script and a fixed tag, removing it first); seed-explicit (run
seed 17 wherever a run is recorded); exits non-zero on the first failed assertion after writing the summary.

**Fixtures.** `clean/cart-sill-dock.ftask` (JSON) and `clean/cart-sill-dock.sexpr` (the same task in the
S-expression view); `clean/kitchen-tray.sexpr`; `clean/cart-upright4.ftask` (the cart task with the `upright`
bound at 4°, for the re-evaluation steps). The planted refusal files are not copied here: the `ref_<code>` steps
drive BD-122's files of record, `crates/frob-arena/tests/fixtures/tasks/refusals/ref-<code>.ftask` (nine codes,
ten files: two for 525), so that one set of files is the gate's. The nine codes are one constant of
`frob-conformance`, `gates::arena::GATE_ARENA_03_REFUSALS` (520, 535, 536, 523, 538, 525, 526, 539, 528), delivered
by this bead with the helper test `files_of_record_complete`, which lists the directory of record and requires
every code of the constant to have at least one file and every file to name a code of the constant; N24a-42's
`planted_table_complete` reads the same constant for its second mutations, so a code added to GATE-ARENA-03 must
gain both a file of record and a second mutation. Further fixtures: `examples/` with the cart task's ten labelled traces as N24b-05 ships them (five satisfied, five
violated, including `rollover` and `tilt-exactly-35`, so that every comparator has its near-boundary example and
no hard-limit atom is vacuous; fewer, for example two of each kind, are refused by N24a-12's check) and the
prepared variants `flipped-label`, `reversed-comparator`, `vacuous-hard-limit` (the ten without `rollover` and
`tilt-exactly-35`), `short-trace`, `boundary`. `clean/cart-sill-dock.ftask` is byte-identical to the task file
N24b-05 ships (digest asserted in `new_json`), and the referee runs of the verdict steps use N24b-05's designs and
sill scene.

**Logging.** NDJSON to `target/e2e-logs/arena_task_file/<utc-timestamp>.ndjson` and a human-readable transcript
beside it. Every line: `ts`, `script`, `bead` (`N24c-06`), `step`, `event` (`start`, `cmd`, `assert`, `metric`,
`refusal`, `end`), the exact command line, exit code, wall time in milliseconds, the envelope's `evidence` block
(claim, class, tier, determinism, identities, seed). Assertions log the value observed, the value expected and
the comparison. Refusal events log `code_expected`, `code_observed`, `pointer` and the first repair. Digest
comparisons log both digests. On failure: the first differing value and the paths of the fixture and of the
saved envelope under `target/e2e-logs/arena_task_file/artifacts/`. The final `summary` line gives counts of
assertions passed and failed and the gates touched (`GATE-ARENA-03: refusal rows`). No trace samples are logged.

**Receipt.** On a full pass the script writes a hash-named receipt of the refusal rows (ten of ten files of
record refused by their code; zero refusals on the two clean files; the commit and the files' digests) under
`target/e2e-logs/arena_task_file/receipts/`. It writes no gate row: N24a-42 joins this receipt with its monitor
rows into the GATE-ARENA-03 receipt, and the gate's value is recorded from that receipt with the `record_gate`
example by the bead that measures the gate (convention 9).

## Acceptance criteria

- [ ] The script exits 0 on a correct build and writes the NDJSON log, the transcript and the summary line.
- [ ] Every row of the step table is asserted; the ten planted files are refused by exactly their codes.
- [ ] With the environment variable `E2E_PLANT_FAILURE=1` the script expects code 520 from the 535 file and exits non-zero with the first differing value logged (the script's own negative control).
- [ ] Running the script twice in succession passes both times (idempotent) and yields the same `TaskId` and digests.
- [ ] The log contains no private-scene data and no raw trace samples.
- [ ] The refusal-rows receipt is written with measured counts, and the script writes no gate row.
- [ ] `files_of_record_complete` passes on the directory of record, and fails on a scratch copy with `ref-538.ftask` removed (naming 538) and on one with an extra `ref-541.ftask` (a code outside the constant).

## Test plan

### Unit tests
`cargo test -p frob-conformance e2e_requirements`: `files_of_record_complete` (the acceptance criterion above,
with its two scratch copies). A shell self-test `scripts/e2e/tests/arena_task_file_selftest.sh` runs the script
against a stub directory with one missing fixture and asserts a non-zero exit with a readable message; the
mechanisms are tested in BD-122, N24a-12 and N24c-02.

### End-to-end script and logging
This bead is the script; its commands, assertions and log fields are the tables above.

### Known answers and negative controls
KA-597 (the planted task files trigger their refusals; exact). KA-596 through the `verdict_short_trace` step (a
window the trace does not cover is `undetermined`; the padded-window monitor is the control). KA-615 through
`verdict_boundary`. Negative controls: `E2E_PLANT_FAILURE=1`; the two clean files must not refuse; the
`ref_538_rounded` step proves the 538 refusal is about the missing rounding and not the file. Determinism lanes:
the script is run twice on one machine, in debug and release builds, and on Linux and macOS; `TaskId`, canonical
digests and verdict records must be byte-identical in all lanes (class D0 for the checks, the referee's class for
the recorded run).

## Considerations

- The script needs a recorded referee run for the verdict steps; it records its own with a fixed seed so that it does not depend on artifacts from another script.
- If the kitchen-tray example's section keywords change (they are proposals outside the requirement grammar), only the fixture changes; the assertions on reach and horizon stand.
- Wall time target: under one minute on the reference host, so that it can run on every change that touches `frob-spec`.
- The MCP surface of the same verbs is checked by the surface-parity tests, which reuse these fixtures.
