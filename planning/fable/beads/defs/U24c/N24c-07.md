## Background

The M1 exit asks that a fresh agent can take a task, run a robot on it on the referee tier, and get a verdict and
a scorecard with evidence attached. Three task families exist at M1: stand and recover (tasks `stand-10s`,
`recover-push` and `traverse-5m-flat`), threshold delivery (`cart-sill-dock`) and timed docking (`timed-docking`,
with its variants `timed-docking-e5-16` and `timed-docking-late`), all registered by BD-125. This bead is the
end-to-end script for that pipeline: settle, run, verdict, scorecard, from the user's side, with the real `frob`
binary and the task files and reference robots shipped in `assets/tasks/`.

The property the script measures is the one the task-reproducibility gate names: every task is reproducible
inside its determinism class from its `TaskId`, `SceneId`, `ModelId` and seed, and reference-robot baseline
scorecards are recorded. The gate itself (GATE-ARENA-01) is an M2 gate closed by the M2 task families on the
batched tiers; this script records its referee rows at M1 and is extended, not replaced, when the M2 families
arrive. The seed bead's condition is checked literally: a changed seed changes the episode digest.

## Scope

In: `scripts/e2e/arena_m1_families.sh`, its assertions and log: the three M1 families through `task.settle`,
`eval.run` and `eval.scorecard` on the referee, with reproducibility checks, and the receipt of the referee rows of
GATE-ARENA-01 (the script writes no gate record, convention 9).

Out: the gate harness for every family on the batched tiers and the gate record that these rows enter (N24a-24);
the task files and reference scorecards (BD-125); the verbs (N24a-16, N24c-04); the cart's analytic layer and
creep rigs, which have their own script with the fixture; batched tiers.

## Technical approach

**Script.** `scripts/e2e/arena_m1_families.sh`; sources the shared helper; idempotent (fresh namespace, removed
first); seed-explicit (run seeds 17 and 18); non-zero exit on failure. Every call of a run verb carries `--key`,
with a key derived by `e2e_key` from (step, task, model), so no two compared runs share a key (a reused key would
return the first run's stored receipt and compare a run with itself).

**Loop.** For each (task, reference model, controller) in the table:

| Task | Reference model | Controller | Site |
|---|---|---|---|
| `stand-10s` | each M1 archetype that the baseline-controller standing gate covers | baseline from `frob control synth` | `referee` |
| `recover-push` | the same | the same | `referee` |
| `traverse-5m-flat` | the same | the same (`cmd_speed` echoed in the run header) | `referee` |
| `cart-sill-dock` | cart design A (60 mm front wheels, 8.000 kg) and design B (75 mm, 8.225 kg) | the fixture's wheel-rate loop | `referee` |
| `timed-docking` | the plant's model record `timed-docking-plant` | `fixture:docking-witness-p1-4` (probe 1/4; U = 3/4, ε = 1/16) | `referee`, stepped on the host in integer arithmetic (`site: host`, N24c-04) |

the script runs these steps.

| Step | Command | Asserts |
|---|---|---|
| `check` | `frob task check <task> --json` | exit 0 |
| `unsettled_refused` | `frob eval run --task <task> --model <model> --worlds 2 --run-seed 17 --tier referee --key <k> --json` before settling | exit 3, `FROB-REF-529`, `next_actions[0]` is a `task settle` command (skipped for the exact plant, which has no contact) |
| `settle` | `frob task settle <task> --model <model> --key <k> --json` (skipped for the exact plant) | exit 0; 64 accepted states and 0 failed (a complete cache); largest residual speed < 10⁻³ SI and penetration ≤ 0.5 mm on every state |
| `run_a` | `frob eval run --task <task> --model <model> --controller <c> --worlds 16 --run-seed 17 --tier referee --key <k-a> --json` | exit 0 or 2; 16 scenarios; evidence tier `referee` (for docking also `site: host` and class D0), a determinism class, `TaskId`, `ModelId`, `ControllerId` and seed present |
| `run_b_same_seed` | the same command under `--key <k-b>` | every episode digest equals `run_a`'s; verdict records byte-identical |
| `run_c_new_seed` | `--run-seed 18 --key <k-c>` | every episode digest differs from `run_a`'s at the same world index, except a world whose drawn values coincide by chance with `run_a`'s (possible where a draw is discrete: docking selects one of six world types, the standing and traverse tasks one of 64 settled poses); such a world is logged with its drawn values and must keep an equal trace digest; at least one world per task differs (a runner that ignores the seed reproduces every digest and is caught) |
| `scorecard` | `frob eval scorecard <run_a> --json` | the seven outcome columns sum to 16; both denominators printed; each metric has a unit; no naked number (every figure sits inside an envelope with a claim product) |
| `reference_match` | compare with `assets/tasks/<task>/reference/scorecard.json` | column counts and episode digests equal the reference on file |
| `docking_boundary` (docking only) | `frob eval run --task timed-docking-e5-16 --model timed-docking-plant --controller fixture:docking-witness-p5-8 --worlds 16 --run-seed 17 --tier referee --key <k> --json` | at least one world `violated`; a world with reading 15/16 exists for both gains |
| `docking_late` (docking only) | the same with `--task timed-docking-late --controller fixture:docking-witness-p1-4` under its own key | every g = 2 world is `violated` with reason `reading_late` and (x₃, v₃) = (2 m, 0) under the witness policy's no-reading branch, which commands as for g = 1 (BD-125); the g = 1 worlds are logged with their verdicts (a common command vector gives x₃ proportional to g, so no controller docks in both gains) |
| `cancel` (cart only) | `run_a`'s command under a new key, started in the background and sent SIGINT after its first committed episode (M1 has no daemon: the interrupt is the in-process job's cancel request, N32a-08) | one envelope, `job.state: cancelled`, exit 2; no run record or scorecard published; `run_a`'s command under yet another key then reproduces the original digests |

**Logging.** NDJSON to `target/e2e-logs/arena_m1_families/<utc-timestamp>.ndjson` plus a transcript. Every line
has `ts`, `script`, `bead` (`N24c-07`), `step`, `event`, the exact command line, exit code, wall time, and the
envelope's `evidence` block (claim, class, tier, determinism, identities, seed). `metric` events carry the measured
value with its unit and threshold: residual speed (m/s or rad/s, threshold 10⁻³), penetration (m, threshold
5 × 10⁻⁴), column counts against the battery size, restricted-mean time to verdict (s). Digest comparisons log
both digests and the world address. On failure the log gives the first differing episode (its address, the two
digests), and the paths of both `.frun` files and envelopes kept under `artifacts/`. The `summary` line gives
assertions passed and failed and `gates: ["GATE-ARENA-01 (referee rows)"]`.

**Receipt, not a gate record.** On a full pass the script writes a receipt with the measured referee rows of
GATE-ARENA-01: the number of (task, model) pairs reproduced, the digests, and the caught negative control (the
changed seed); its hash is in the `summary` line's `receipts`. The script writes no gate record (convention 9): the
gate is an M2 gate, recorded in parts from the receipt of N24a-24's harness by its recording beads.

## Acceptance criteria

- [ ] The script exits 0 on a correct build and produces the log, transcript and summary.
- [ ] For every (task, model) pair: same seed, same digests; changed seed, changed digests (worlds whose discrete draws coincide by chance are logged and keep equal digests; at least one world per task differs).
- [ ] The unsettled run is refused with FROB-REF-529 and the settle command is offered.
- [ ] Scorecards match the references on file, and their columns sum to the battery size.
- [ ] The docking boundary and late-packet steps give the stated verdicts.
- [ ] Cancellation by interrupt publishes nothing partial (exit 2, `job.state: cancelled`), and a re-run under a new key reproduces the digests.
- [ ] With `E2E_PLANT_FAILURE=1` the script compares `run_c_new_seed` for equality and fails with the first differing digest logged.
- [ ] The receipt of the referee rows of GATE-ARENA-01 is written with measured values, not targets, and no gate record is written by the script.
- [ ] `traverse-5m-flat` is run for every archetype of the table, with `cmd_speed` echoed in each run header.

## Test plan

### Unit tests
None of its own; a shell self-test asserts that the script fails cleanly when a reference scorecard file is
missing. Mechanism tests are in BD-125, N24a-16 and N24c-04.

### End-to-end script and logging
This bead is the script; the commands, assertions and log fields are given above.

### Known answers and negative controls
KA-615 through `docking_boundary` (at U = 3/4 and ε = 5/16 the strict requirement fails; a non-strict comparator
would admit it). KA-601's targets through `settle` (penetration at most 0.5 mm on all 64 states). Negative
controls: the changed seed must change digests (a runner that ignores the seed is caught); the unsettled run must
refuse; `E2E_PLANT_FAILURE=1`. Metamorphic: running the 16 worlds as two batches of 8 gives the same digests per
world address. Determinism lanes: twice on one machine; one worker and all workers; debug and release; Linux and
macOS, each compared inside the referee's class (D2 on one build, tolerance comparison across platforms where
bit equality is not attained, recorded as such).

## Considerations

- Wall time: the cart at a 1/2000 s physics step for 8 s over 16 worlds and two designs is the dominant cost; the script may run the cart with 4 worlds under `E2E_QUICK=1` and records which mode ran.
- Archetypes whose contact count exceeds the referee's cap are skipped with a logged reason, not silently.
- The script is the smoke test the M1 exit review reads; a failure here blocks the review.
- When batched tiers exist the same script gains a `--tier` loop and the comparison becomes "inside the tier's determinism class".
