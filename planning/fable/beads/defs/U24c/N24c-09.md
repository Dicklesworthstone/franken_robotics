## Background

One comparison can be made valid under optional stopping. Nothing in that protects against an agent that submits
fifty candidates to the same held-out scenes until one passes: with independent attempts at level 5% each,
fourteen null submissions give a 51% chance of at least one false promotion (1 − 0.95¹⁴ = 0.512). The **blinded
qualification lane** closes that hole. A **campaign** is a set of confirmation requests that share a claim
family (a task, a baseline class and a held-out world family) and a total error budget α. Request i of a campaign:

1. **Commit.** The request (candidate, baseline, task, claim, study type and rule, tier plan, number of clusters,
   budget) is hashed into the ledger with an idempotency key before any confirmation world exists.
2. **Spend.** It receives the level α_i = α/[i·(i + 1)]; the index advances for every committed request,
   including ones that end inconclusive or are refused after commitment.
3. **Draw.** Fresh world clusters are derived from a sealed key, the campaign identifier, the index i and a
   cluster counter. A cluster is the unit that shares a generator draw (one building with its materials).
4. **Run.** Candidate and baseline run paired on the clusters; the study runs at level α_i with clusters as units.
5. **Answer.** The agent receives a receipt and nothing else: decision, index, level spent, units used, a hash.
6. **Close.** The key is revealed, clusters and episodes become readable, and the family is retired into
   discovery; it never serves as a confirmation family again.

The error-rate argument needs exactly three things, and the four invariants are those three plus the blinding
that protects the claim's population: the request is fixed before the draw; the clusters are fresh; the level is
spent whether or not the agent likes the answer. Conditional on the past the chance of a false promotion at
request i is at most α_i, and a union bound gives at most α·m/(m + 1) < α over m requests, for any number of
retries and any adaptive strategy.

The lane and its firewall are built by other beads. This bead carries the four invariants as executable
property tests over the ledger, each with a planted violation it must catch. It builds no mechanism. Tier Solid;
the tests live in `crates/frob-conformance/tests/qual_invariants.rs` and run against a real `frobd` with a
synthetic sealed family (labelled `synthetic`). (They cannot live under `frob-arena`: a test there that starts
the daemon would be an upward dev-dependency of the arena crate, which the layer lint refuses; the conformance
crate is where daemon-driving tests live.)

## Scope

In: one property test per invariant, the planted violations, registration of the controls, and the retry-cost
known answers that follow from the level series.
Out: the lane (the qualification-lane bead), the firewall and its fuzzed read audit (the firewall bead), the
2,000-campaign gate run (the 500-retry gate bead), replay by the offline auditor (the M5 replay bead), the
decision on family size and on who holds `qual:admin` (N24c-13).

## Technical approach

| Id | Statement | Property test | Planted violation that must be caught |
|---|---|---|---|
| INV-QUAL-01 | Discovery cannot read confirmation worlds | For a running campaign, a session holding every discovery scope and not `qual:admin` calls each read verb in the registry with every identifier it can construct from receipts and from `eval.ledger`; no response contains a sealed field (world address, per-unit outcome, trace, still); each attempt is refused with FROB-REF-840 and written to the audit log | A test build in which `run.show` resolves a sealed episode identifier |
| INV-QUAL-02 | Confirmation clusters are fresh: no cluster serves two requests, and none is in any discovery dataset before the campaign closes | Over 200 random request sequences across three campaigns: the multiset of derived cluster identifiers has no repeat within or across requests; the intersection with every discovery manifest is empty until close; a forced repeat is refused with FROB-REF-844 | A derivation that omits the request index from its key, so request i + 1 redraws request i's clusters |
| INV-QUAL-03 | The ledger of levels is append-only, the index advances by one for every committed request, and the total spent never exceeds α | Random interleavings of commits by several sessions, including requests that end `promoted`, `not-promoted`, `inconclusive`, refused after commitment, cancelled and crashed: indices are 1, 2, 3, … with no gap or repeat; α_i = α/[i·(i + 1)] exactly (rationals); the running sum equals α·m/(m + 1); no ledger row is rewritten (hash chain check) | A lane that does not advance the index for an inconclusive request; a lane that lets a second campaign with the same claim family restart at index 1 without `qual:admin` |
| INV-QUAL-04 | A request's commitment precedes the derivation of its clusters in ledger order | For every request the ledger sequence number of the commitment record is lower than that of its first cluster-derivation record; a request that was not committed first, or that differs from its commitment, is refused with FROB-REF-841 | A lane that derives clusters and then writes the commitment in the same transaction in the reverse order; a request edited after commitment (a changed candidate hash) |

**Planted violations.** Each is a `cfg(feature = "nc-<nnnn>")` branch at its site in the owning crate
(`frob-arena` for the ledger, derivation and commit order; `frob-verbs` for the `run.show` resolution), built
only with `--features gauntlet-mutations,<crate>/nc-<nnnn>` (the suite's one mutation mechanism, N38a-14; never
in a product build), and a control record of `controls.toml` registered by this bead with gates GATE-QUAL-01 and
GATE-QUAL-02, so that the control runner runs it whenever those gates run.

**CX-267 and its plant** (N24-CX names this bead as the planting bead; kind `a-a`). The counterexample:
resubmitting null candidates to the same held-out scenes at a constant 5% gives, after fourteen independent
attempts, a 51% chance of at least one false promotion (1 − 0.95¹⁴ = 0.512), and against reused clusters at a
constant level a scripted adversary obtains a false promotion in more than 99% of campaigns under 500 retries.
Plant `N24c-09:cx-267`: the `synthetic` fixture `crates/frob-conformance/tests/fixtures/cx267/`, a scripted
resubmitting adversary on a no-signal synthetic family (both arms the same design, so every promotion is false;
it sees every receipt and resubmits after each non-promotion), run against the lane built with the two violations
of INV-QUAL-02 and INV-QUAL-03 above enabled together (clusters redrawn without the request index; a constant
level). Caught by `inv_qual_02_clusters_fresh` (a repeated cluster) and `inv_qual_03_level_ledger_append_only`
(a level other than α/[i·(i + 1)]); the run also logs its realised false-promotion count over the fixture's
campaigns beside 0.512, as the case's number, without a statistical assertion (the rate is GATE-QUAL-01's
2,000-campaign measurement, not this bead's). Gate GATE-QUAL-01; KA-620, KA-622.

**Request and receipt shapes the tests read.** A request (`frob.qualify.request/1`) holds `campaign`, `index`,
`alpha_total`, `alpha_i` (for example `"0.05/56"` at index 7), `candidate` and `baseline` (each a design and a
controller), `task`, `claim`, `study` (type, n, rule, pre-analysis hash), `tier_plan`, `clusters`, `budget`, and
`commit` (ledger sequence as a string, hash, idempotency key). A receipt (`frob.qualify.receipt/1`) holds only
`campaign`, `index`, `alpha_i`, `alpha_spent` (for example `"0.05*7/8"`), `decision`, `units_used`,
`sealed_until_close` (the list of what stays sealed), `receipt_hash` and the three authorization flags, all false.
A receipt with any other field fails INV-QUAL-01's test.

**Ledger checks.** The tests read the ledger through the same read verbs an auditor uses (`eval.ledger` returns the
campaign's index, levels spent and receipts, nothing sealed) and, with `qual:admin` in the test harness only,
through the raw sequence of records to check ordering and the hash chain.

**Retry-cost known answers (derived from the series).** Sample size grows with ln(1/α_i). Relative to one test at
α = 0.05: request 1 needs ln 40 / ln 20 = 1.23 times the units, request 10 needs 2.57, request 100 needs 4.08,
request 500 needs 5.15. For the fixed-n paired rule with a five-point margin a practical tie first becomes
reachable at n = 99 for request 1, n = 178 for request 10 and n = 328 for request 500; at 64 pairs request 1 has
478 preferring outcomes of 2,145, where the development level had 521.

## Acceptance criteria

- [ ] Four property tests named after the invariants pass against a running daemon with a synthetic sealed family.
- [ ] Each planted violation, enabled one at a time, makes its test fail, and each is an entry of the negative-control registry.
- [ ] The CX-267 plant (`N24c-09:cx-267`, the adversary against the two violations together) is caught by `inv_qual_02_clusters_fresh` and `inv_qual_03_level_ledger_append_only` under `gauntlet-mutations`, and the control seeded from CX-267's entry is reported caught.
- [ ] The level ledger matches α·m/(m + 1) in exact rationals for every prefix of every random sequence, up to m = 500.
- [ ] The retry-cost figures 1.23, 2.57, 4.08, 5.15 and the counts 99, 178, 328 and 478 of 2,145 are reproduced by the pre-analysis at the requests' levels.
- [ ] A request refused after commitment still consumes its index (asserted explicitly).
- [ ] The tests leave no sealed data in their logs.

## Test plan

### Unit tests
`inv_qual_01_discovery_cannot_read`, `inv_qual_02_clusters_fresh`, `inv_qual_03_level_ledger_append_only`,
`inv_qual_04_commit_precedes_draw`, and the `control_*` tests with their planted violations (one per row of
the table, each run with its own `nc-<nnnn>` feature; `FROB_TEST_SEED=<seed> cargo test -p frob-conformance
--test qual_invariants --features gauntlet-mutations,<crate>/nc-<nnnn> -- control_`). Fixed cases:
`index_7_level_is_0_05_over_56`; `spent_after_7_is_0_05_times_7_over_8`; `fourteen_null_at_5pct_is_51pct`
(1 − 0.95¹⁴); `retry_cost_ratios`; `tie_reachability_at_request_levels`; `receipt_has_only_listed_fields`;
`crash_between_commit_and_draw_keeps_index` (the daemon is killed after the commitment; on restart the index is
consumed and the request can be recovered by its idempotency key).

### End-to-end script and logging
The user-side script of the qualification capability is `scripts/e2e/arena_qualification_lane.sh` (bead
N24b-24). These tests contribute its step 5a, `ledger_invariants`: after a scripted campaign of ten requests the
script calls `frob eval ledger q:e2e-coin/1 --json` and asserts index sequence 1 … 10, levels α/[i·(i + 1)] and
running sum `0.05*10/11`; it logs the command, exit code, the `evidence` block, each level as a rational string
against its expected value, and on failure the first index whose level differs. Nothing sealed is logged.

### Known answers and negative controls
KA-619 (level series, exact rational partial sums for m up to 500; control: a constant level per request),
KA-620 (fourteen null submissions at a constant 5% give 51%; control: the same adversary against reused clusters
at a constant level obtains a false promotion in more than 99% of campaigns), KA-621 (cost of a retry), KA-623
(firewall and replay: no sealed field in 10⁴ fuzzed reads; a reordered index, a changed request and a reused
cluster are each rejected). Counterexamples CX-267 (resubmitting to the same held-out scenes) and CX-384 (letting
the receipt say which worlds failed would let an agent patch for them, so the level schedule would bound an error
rate for a procedure no longer being run). Metamorphic relation MR-13: on no-signal worlds the decision of
request i is unchanged by later requests. Determinism: cluster derivation is exact (class D0) and identical on
every platform for a given sealed key.

## Considerations

- OPEN-ARENA-3 (who holds `qual:admin`; the size and composition of sealed families) blocks the gate, not these tests, which use a synthetic family. Fail-closed default: no result is called qualified until a family exists.
- If a reversal on a sealed family is ever used to inform training or selection, the family is retired at once; a test asserts that retirement is recorded and that the family cannot be reopened.
- Freshness alone controls the error rate; blinding protects the population the claim is about. The tests keep the two apart so that a failure names which property broke.
- RISK-22 and RISK-34 (qualification gamed by adaptive retries or by a leak) are what these tests guard at the level of single properties; the 2,000-campaign gate guards them in aggregate.
