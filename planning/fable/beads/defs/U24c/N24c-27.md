## Background

The foil bodies of the task audit probe ways of satisfying a task without the intended mechanism. The cheapest
such way is **doing nothing**. A requirement or a reward built from safety atoms alone is satisfied in full by a
robot that never leaves its start, and a search over designs or policies will find that robot.

Hand case. A delivery task uses the past-time requirement `(H (0 s 2 s) (and clear-margin thermal-ok spill-ok))`
as its online reward over 60 s. A parked robot keeps all three margins positive for the whole episode and
collects the full reward. A robot that carries the tray through the pass and loses part of its spill margin for
one second collects less. Search prefers the parked robot.

Fixture definition of the hand case (DESIGN, so that "full reward" is a number): the task's only reward term is an
ordinary rate term (BD-194) equal to the smallest of the three safety margins, each normalised by its atom's
scale and saturated at 1, with scales chosen so that a parked robot's three margins exceed 1; the full return is
therefore 60 (1 per second over [0 s, 60 s]). This is the plan's "past-time requirement as its online reward"
written with an ordinary term, because the requirement-derived reward term (N24a-14) is off by default and exists
only on the branch where KILL-SPEC-REWARD does not fire (N24a-15): a fixture built on it would not exist on the
other branch, and the idle arm and its gate are Solid on both. (Written with that term, the ticks before 2 s would
carry the window's pre-origin flag, N24a-04, and the full return would be 58; the flag rule is the same.) Its
verdict is `(G (0 s 60 s) (and clear-margin thermal-ok spill-ok))`, satisfied by the parked robot.

The **idle arm** is one more arm of `task.audit`: it runs the candidate design, and each foil, under three idle
laws and flags a task that rewards idleness. It is Solid (no search, three short runs per body), owned by
`frob-arena`, and it does not depend on the foil arm surviving its kill gate: with no foils it runs on the
candidate design alone. Its findings use the common machinery: a proposed clause, acceptance by the author
(which yields a new `TaskId`) or a marking that idleness is intended (as a station-keeping task would), and the
existing rule that the qualification lane refuses a task with an unresolved finding.

Alternative rejected: a static check that the requirement contains a "progress" atom. Whether an atom forces
progress depends on the scene and the start state; running the idle body decides it.

## Scope

In: the three idle laws; the run and return computation; the flag rule; the proposed clause; resolution through
the common machinery; the gate fixture of ten planted and ten clean tasks; the gate record.
Out: findings storage and the verb (N24c-22); foils (N24c-23); the backup controllers themselves (N22bx-02, a
dependency); the reward-term semantics (BD-194).

## Technical approach

**Idle laws.** For each body under audit (the candidate design; each foil when the foil arm exists):

| Law | Command | Source |
|---|---|---|
| `zero` | Zero command, with the brakes as carded (engaged if the actuator card has a holding brake, otherwise free) | The actuator cards |
| `hold` | The hold-posture command of the baseline controller for the body's morphology class (stance held at the settled pose; wheel rates commanded to zero) | Baseline controller synthesis |
| `backup` | The backup controller of the class: damping injection on the drive outputs then brakes for wheeled and tracked bases; posture hold by energy shaping for an arm; widen the stance, lower the body and freeze for a legged body | The runtime-shield backups |

**Run.** Each (body, law) is run from the settled start for the task's full horizon on the audit's worlds (the
task's nominal world and, by default, 8 worlds drawn by address from the task's discovery randomisation;
DESIGN), on the cheapest tier that supports the task. For each episode compute (a) the requirement verdict and
(b) the **return**: the task's reward terms integrated over simulated time, including any requirement-derived
online reward term.

**Best audited return.** The largest return among the audit's **non-idle** runs for this task on the same worlds:
the foil archive's episodes, the actual-design arm's episodes, and, when available, the reference robot's
baseline run. Idle runs are excluded: if they counted, the best idle run would always have a ratio of 1 to itself
and every task with a positive idle return would be flagged. When no non-idle run exists (for example under the
pilot's falsifier, where only the idle arm and the in-campaign check run, and no baseline run is on file), the
return clause is reported `not evaluated` and only the verdict clause applies.

**Flag rule.** The task is flagged `rewards-idleness` when, for any body and law, an idle run's requirement
verdict is `satisfied`, **or** its return is at least a declared fraction of the best audited return (DESIGN
default 0.5; the fraction is an input recorded in the audit). Returns are compared on the same worlds; when the
best audited return is not positive the return clause is skipped and reported as not evaluated, and only the
verdict clause applies.

**Finding and proposed clause.** A finding with `arm: idle`, `violated_invariant: rewards-idleness`, the body,
the law, the verdict, the return and its ratio to the best audited return, and a replay. The proposed clause is
one of:
- a **progress atom** with its scale, conjoined with the verdict as `(F (0 s T) progressing)` with T the horizon
  (DESIGN: a safety-only verdict has no success operand, and inside the success operand of an until the atom would
  contradict completion, since a placed tray is not approaching): for the hand case, approach speed above
  0.15 m/s on a scale of 0.50 m/s, `(atom progressing (> (- approach_speed 0.15 m/s) 0 m/s) :scale 0.50 m/s)`,
  which gives the parked robot a margin of (0 − 0.15)/0.50 = −0.3, and so the amended verdict a margin of
  min(ρ_safe, −0.3) = −0.3; or
- a **completion requirement with a deadline**: `(F (0 s T) completed)` conjoined with the safety clause, where
  `completed` is the task's own completion signal.
The proposal picks the completion form when the task has a completion signal and the progress form otherwise
(DESIGN). The author accepts it (a new `TaskId`, with the idle trace added as `(example … violated)`), or marks
idleness intended (the idle trace added as `(example … satisfied)`, and the declaration `idle: intended` added to
the task's `study` section, part of the canonical bytes). On a task carrying that declaration the idle arm still
runs and reports every (body, law) result, but raises no `rewards-idleness` finding (DESIGN: one marking covers
all three laws and all worlds, which a single example trace could not).

**Qualification.** `eval.qualify` on a task with an unresolved idleness finding is refused under the existing
rule for unresolved findings; no separate rule is added.

**Gate fixture `assets/tasks/idle-gate/`.** Ten authored tasks with a planted safety-only reward or requirement
(delivery, docking, traversal and transport tasks whose reward or verdict is built only from clearance, thermal,
tilt, spill and current margins) and ten clean tasks (the twins with a progress atom or a completion deadline,
plus two station-keeping tasks in which idleness is intended and already marked so). Labels are hashed before the
arm's parameters are frozen.

**GATE-ARENA-15** (claim kind Known answer, M3): on the ten planted tasks and the ten clean tasks, the idle arm
flags ten of ten and none of ten (TARGET: at least nine, at most one). The hand case is flagged, and after the
progress clause is accepted the parked robot's verdict is `violated`.

## Acceptance criteria

- [ ] The hand case: the parked robot's requirement holds for the whole 60 s and its return is the full reward (60); the task is flagged `rewards-idleness`; the proposed progress atom gives the parked robot a margin of −0.3; after acceptance the parked robot's verdict under the new `TaskId` is `violated` with margin −0.3.
- [ ] The best audited return excludes idle runs; with no non-idle run the return clause is reported `not evaluated`.
- [ ] GATE-ARENA-15: at least nine of the ten planted tasks flagged and at most one of the ten clean tasks flagged; the measured counts are recorded.
- [ ] A station-keeping task marked "idleness intended" is not flagged again on re-audit, and its idle trace is a `satisfied` example.
- [ ] The three laws run for the candidate design; with the foil arm present they also run for each foil; with it absent the arm still runs and passes its gate.
- [ ] The return clause is skipped and reported when the best audited return is not positive.
- [ ] `eval.qualify` refuses a task with an open idleness finding and admits it after resolution.
- [ ] Idle runs are recorded with the controller layer `backup`, `baseline` or none, so a reader can see which law produced each.
- [ ] Under `gauntlet-mutations` the plant `N24c-27:arena-a2` (no idle law run) is caught by `hand_case_parked_collects_full_reward` and by the gate count, and the control seeded from ARENA-A2's entry is reported caught.

### Unit tests
`cargo test -p frob-arena idle_arm`:
- `hand_case_parked_collects_full_reward`: three safety margins positive for 60 s; return 60, the maximum; a carrying trace that loses its spill margin for 1 s returns less (at most 59); the idle arm on the hand-case task raises one `rewards-idleness` finding (the ARENA-A2 plant's catching test).
- `flag_on_satisfied_verdict`; `flag_on_return_fraction`: idle return 0.5 of best flags, 0.49 does not.
- `return_clause_skipped_when_best_nonpositive`; `best_return_excludes_idle_runs` (only idle runs on file → `not evaluated`, not a ratio of 1).
- `intended_declaration_suppresses_flag`: a station-keeping task with `idle: intended` reports its idle runs and raises no finding under any of the three laws.
- `progress_atom_margin`: approach speed 0 gives (0 − 0.15)/0.50 = −0.3.
- `completion_form_chosen_when_signal_exists`.
- `accept_yields_new_task_and_violated_example`; `intended_yields_satisfied_example`.
- `three_laws_three_controllers`: the recorded control layer differs per law.
- `no_foils_still_runs`.
- `clean_twin_not_flagged`: with the completion deadline the idle verdict is `violated` and the return is below half of the reference run.

### End-to-end script and logging
This bead's own script, `scripts/e2e/task_audit_idle.sh`, measures GATE-ARENA-15 with what this bead and its
dependencies deliver: `frob task audit <hand-case TaskId> --arms idle --design <d> --key tai-hand --json` (exit
2, finding `rewards-idleness`); `frob task audit <hand-case TaskId> --resolve <finding> --accept --key
tai-resolve --json` (the progress clause; a new `TaskId`); `frob task verdict <parked run> --task <new TaskId>
--re-evaluate --json` (the parked run was recorded under the original `TaskId`, so without `--re-evaluate` it is
`verdict-task-mismatch`; with it, margin −0.3, `violated`); then `frob task audit <TaskId> --arms idle --design
<class reference design> --key tai-gate-<task> --json` over the 20 gate tasks (each call waits to completion, the
CLI default of NJL-01's `wait.cli`). The script writes the counts into a hash-named receipt and no gate record; this bead, the one that
measures GATE-ARENA-15, records the value from that receipt in a session that did not implement the arm with
`cargo run -p frob-conformance --example record_gate -- --gate GATE-ARENA-15 --receipt <hash>`. The same hand case from the user's side, beside the other arms, is steps
`idle_hand_case`, `idle_resolve` and `idle_gate` of `scripts/e2e/arena_task_audit.sh` (N24c-28). Logged per
STD-E2E: commands, exit codes, wall time, the `evidence` block, per (body, law) the verdict and the return with
its ratio to the best audited return against the 0.5 threshold, the flag, the old and new `TaskId`, the parked
robot's margin (−0.3 expected), the gate counts (planted flagged of 10, clean flagged of 10) against their
thresholds, and on failure the first task whose flag differs from its label. The summary names GATE-ARENA-15.

### Known answers and negative controls
Known answers: the hand case (full reward for the parked robot; margin −0.3 after the clause), N24-KA's late
record KA-ARENA-A2; this bead replaces its `pending: N24c-27` line in the derivation file's front matter with the
crate and the tests `hand_case_parked_collects_full_reward` and `progress_atom_margin`. Counterexample ARENA-A2 (a
requirement built from safety atoms is taken for a mission: the parked robot collects the full reward of
`(H (0 s 2 s) (and clear-margin thermal-ok spill-ok))` over 60 s, the carrying robot less) is planted by this bead,
kind mutation, gate GATE-ARENA-15: plant `N24c-27:arena-a2`, Cargo feature `arena-a2` of `frob-arena`, built only
with `--features gauntlet-mutations`, under which the idle arm returns its record without running any idle law (an
audit that runs no idle law). Caught by `hand_case_parked_collects_full_reward`, which runs the hand-case task
through `task.audit --arms idle` and asserts the `rewards-idleness` finding (none is raised under the plant), and by
the gate count (zero of ten planted tasks flagged). Negative controls: an idle arm that runs only the `zero` law misses a task that is satisfied only under `hold` (a slope
on which the free-wheeling robot rolls out of the safe region; one planted task is of this kind); an arm that
compares returns across different worlds; an arm that flags the station-keeping tasks (the clean set contains
two, so more than one false flag fails the gate). Metamorphic: scaling every reward term by a positive constant
changes no flag. Determinism: idle runs are deterministic and reproduce bit for bit inside the tier's class.

## Considerations

- A progress atom required once is weak (one forward twitch above 0.15 m/s satisfies it); that is why the completion form is proposed whenever the task has a completion signal, and the author may strengthen the progress form (for example a dwell on progress) before accepting.
- The 0.5 return fraction is a DESIGN default; a task family whose honest returns are low relative to an idle robot's (heavy safety shaping) may need another value, declared in the task.
- A task flagged for idleness has usually wasted nothing yet; the cost of the arm is three episodes per body, far below the audit's 5% budget.
- If the requirement-derived reward term is removed by its kill gate, the return is computed from the remaining reward terms; the verdict clause of the flag rule is unaffected.
- The backup controllers are specified with the runtime shields at M4; this arm needs only their commands as a plain controller at M3, which is the stated prerequisite.
