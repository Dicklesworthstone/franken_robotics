## Background

`task.audit` is a user-visible capability: an agent that has written a task calls it before spending a campaign
on that task, reads the findings, resolves them, and only then may ask the qualification lane to confirm a
result under that task. The mechanism beads test the parts. This bead is the end-to-end script that drives the
whole path with the real `frob` binary and daemon, on small fixtures, and asserts what a user would see: exit
codes, envelopes, refusal codes, new task identities, and that the qualification lane really refuses an
unaudited or unresolved task.

The script exercises the two hand cases of the audit exactly. Foil hand case: goal region x ∈ [4.9, 5.1] m and
requirement `(F (0 s 10 s) in_goal)`; a sled at a constant 1 m/s is inside for t ∈ [4.9, 5.1] s, so the verdict
is satisfied with a dwell of 0.2 s; the proposed clause is `(F (0 s 10 s) (H (0 s 2 s) in_goal))`; the sled then
violates it and a body at rest at x = 5 m from t = 6 s satisfies it from t = 8 s. Idle hand case: a delivery
task whose online reward over 60 s is `(H (0 s 2 s) (and clear-margin thermal-ok spill-ok))`; a parked robot
collects the full reward; after the progress clause (approach speed above 0.15 m/s on a scale of 0.50 m/s) is
accepted the parked robot's margin is −0.3 and its verdict is `violated`.

The two gates' full measurements (30 + 30 tasks for the foil arm; 10 + 10 for the idle arm) have their own
scripts with their fixtures; this script contributes the hand-case clauses of both gates and is the smoke test
that runs on every change to the audit.

## Scope

In: `scripts/e2e/arena_task_audit.sh`, its fixtures, assertions and log.
Out: the 60-task gate run (`scripts/e2e/arena_gate_audit.sh`, N24c-25); the mechanisms.

## Technical approach

**Script.** `scripts/e2e/arena_task_audit.sh`; sources the shared helper; starts a private `frobd` with a
synthetic sealed family for the qualification steps (labelled `synthetic`); idempotent (fresh namespace);
seed-explicit (run seed 5); non-zero exit on failure. Environment switch `AUDIT_FOILS=0` runs the fallback
profile (no foil steps), so the same script is valid on both branches of the foil kill gate.

**Fixtures** under `scripts/e2e/fixtures/arena_task_audit/`: `reach-goal.ftask` (the foil hand case, adopting the
`dwell` invariant), `reach-goal-dwell.ftask` (the same task with the 2 s dwell already written into its verdict,
for the fallback profile), `delivery-safety-only.ftask` (the idle hand case, with the fixture reward of N24c-27, an
ordinary rate term: full return 60), a flat scene, a small wheeled design and its baseline controller, a recorded
baseline run of that design carrying the tray through the pass (the non-idle run against which the parked return
is compared; its return is below 60 because its spill margin dips for 1 s), a `synthetic` recorded trace of a body moving at a
constant 1 m/s through the goal region and one of a body at rest at x = 5 m from t = 6 s (both record no
`TaskId`, so `task.verdict` takes `--task` on them and never `--re-evaluate`, N24c-02), a recorded
three-design campaign result with a planted belly-sliding winner, and `reach-goal-sealed.ftask` (the foil hand-case
task whose world family is the synthetic sealed family, for `sealed_refused`).

**Profiles.** `foils` runs every step. `fallback` (`AUDIT_FOILS=0`, or the build's capabilities after N24cp1-01)
skips `foil_instantiate`, `foil_candidate_refused`, `audit_hand_case` and `resolve_accept`, and logs each as
`skipped` with the reason; it still checks the foil hand case's numbers, because a verdict is a pure function of
the trace and the `TaskId`: `amended_verdicts` runs `frob task verdict` on the synthetic 1 m/s trace against
`reach-goal` (satisfied, dwell 0.2 s) and against `reach-goal-dwell` (violated), and on the resting-body trace
against `reach-goal-dwell` (satisfied, decided at 8 s); `audit_fallback_arms` audits `reach-goal-dwell` with the
remaining arms (exit 0, no finding), and `qualify_admitted` runs on that task. `audit_comparator` runs in
`fallback` only where the actual-design arm is built (gate-fired fallback) and is `skipped` otherwise.

**Steps and assertions.**

| Step | Command | Asserts |
|---|---|---|
| `qualify_refused_unaudited` | `frob eval qualify <d> --task <reach-goal TaskId> --claim '<claim>' --key ata-q-1 --json` | exit 3, symbolic refusal `task-audit-missing`; the campaign index reported by `frob eval ledger <campaign> --json` is unchanged |
| `foil_instantiate` | `frob task audit <reach-goal TaskId> --arms foil --list-bodies --key ata-list --json` (the listing option of N24c-23) | the sled, ball, tumbling box, hopper and free centroidal body are listed, each with a `DesignId` and `foil: true` |
| `foil_candidate_refused` | `frob eval compare <sled> <d> --task <reach-goal TaskId> --key ata-cmp --json` | exit 3, `foil-as-candidate` |
| `audit_hand_case` | `frob task audit <reach-goal TaskId> --arms foil --key ata-foil --json` with the default budget (5% of the reference campaign declared in the fixture's `study` section); the CLI waits to completion (NJL-01's `wait.cli`) | exit 2; a finding with body `foil:sled`, verdict `satisfied`, `violated_invariant: dwell`, measured time inside the region 0.2 s; proposed clause `req.wrap-dwell` with window (0 s, 2 s); steps used ≤ 5% of the reference campaign |
| `audit_comparator` | the same with `--arms actual --design <d> --key ata-actual` | the record contains the same-or-adjacent-cell table |
| `resolve_accept` | `frob task audit <reach-goal TaskId> --resolve <finding> --accept --key ata-resolve --json` | exit 0; a new `TaskId` different from the old; the new task's examples include the sled trace labelled `violated`; `frob task check <new> --json` exit 0 |
| `amended_verdicts` | `frob task verdict <sled run of audit_hand_case> --task <new TaskId> --re-evaluate --json` (the run was recorded under the old `TaskId`; without `--re-evaluate` it is `verdict-task-mismatch`) and `frob task verdict <synthetic resting-body trace> --task <new TaskId> --json` | sled `violated`; resting body `satisfied` with `decided_at_s` = 8 |
| `idle_hand_case` | `frob task audit <delivery-safety-only TaskId> --arms idle --design <d> --key ata-idle --json` | exit 2; finding `rewards-idleness`; the parked run's verdict `satisfied`, its return 60, and its ratio to the best audited return (the recorded carrying run; idle runs excluded) above 1 and so ≥ 0.5; three laws listed (`zero`, `hold`, `backup`) |
| `idle_resolve` | `frob task audit <delivery-safety-only TaskId> --resolve <finding> --accept --key ata-idle-resolve --json`; `frob task verdict <parked run of idle_hand_case> --task <new TaskId> --re-evaluate --json` | margin −0.3 (to 10⁻⁹), verdict `violated` |
| `adopt_invariants` | `frob task show <campaign TaskId> --json` | the `requirements` section lists the adopted invariants as online signals tagged `:intent` |
| `in_campaign_check` | `frob task audit <campaign TaskId> --in-campaign <result> --key ata-inc --json` | the planted belly-sliding design is flagged `wins-outside-intent` on `site-only`; the walking design is not |
| `promotion_refused` | `frob eval promote <flagged design result> --tier referee --key ata-pro --json` | exit 3, `wins-outside-intent-unresolved` |
| `qualify_refused_open` | `frob eval qualify <d> --task <TaskId with an open finding> --claim '<claim>' --key ata-q-2 --json` | exit 3, `task-audit-unresolved`; index unchanged |
| `qualify_admitted` | `frob eval qualify <d> --task <amended TaskId> --claim '<claim>' --key ata-q-3 --json` | not a refusal (the CLI waits to completion, so no job handle); a receipt whose only fields are the listed ones; the index advanced by one |
| `cancel_audit` | `frob task audit <TaskId> --arms idle --design <d> --sync-wait-ms 0 --key ata-cancel --json`, then `frob job cancel <job> --json` | exit 8 then cancelled; no audit record; `eval.qualify` (key `ata-q-4`) still refuses with `task-audit-missing` |
| `sealed_refused` | `frob task new reach-goal-sealed.ftask --key ata-new-sealed --json`, then `frob task audit <that TaskId> --arms idle --design <d> --key ata-sealed --json` (its worlds resolve to the sealed family) | exit 3 with the sealed-data refusal (FROB-REF-840) |

**Logging.** NDJSON to `target/e2e-logs/arena_task_audit/<utc-timestamp>.ndjson` and a transcript. Each line:
`ts`, `script`, `bead` (`N24c-28`), `step`, `event`, the exact command, exit code, wall time, the envelope's
`evidence` block (claim, class, tier, determinism, identities, seed, and the `foil` flag where set). `metric`
events: time inside the goal region (s, expected 0.2), budget share (threshold 0.05), return ratio (threshold
0.5), parked margin (expected −0.3). `refusal` events: symbolic or numeric code expected and observed. Identity
changes: old and new `TaskId`. Ledger checks: index before and after. On failure: the first differing value and
the paths of the saved envelopes and replays. The `summary` line gives assertions passed and failed, the profile
(`foils` or `fallback`) and `gates: ["GATE-ARENA-11 (hand case)", "GATE-ARENA-15 (hand case)"]`. No sealed data
and no private-scene data are logged.

## Acceptance criteria

- [ ] The script exits 0 with all steps asserted in the `foils` profile, and with the foil steps skipped and logged as skipped in the `fallback` profile, where the qualification path runs on `reach-goal-dwell`.
- [ ] Both hand cases reproduce their numbers exactly (0.2 s; decided at 8 s; return 60; margin −0.3), in both profiles for the verdict numbers.
- [ ] Every run and mutate call carries its own idempotency key, so the two consecutive runs of the next criterion use a fresh namespace or fresh keys and never return a stored receipt in place of a new run.
- [ ] Every refusal step observes its expected code, and the two qualification refusals leave the campaign index unchanged.
- [ ] `E2E_PLANT_FAILURE=1` (the script then expects the sled to violate the original requirement) makes the script fail with the first differing value logged.
- [ ] Two consecutive runs pass and produce identical finding ids and `TaskId`s.
- [ ] The log carries no sealed or private data.

## Test plan

### Unit tests
A shell self-test asserts the script fails cleanly when a fixture is missing, that `AUDIT_FOILS=0` skips
exactly the four foil steps listed under Profiles and runs `audit_fallback_arms` in their place, and that the
`synthetic` traces' digests match the fixture manifest. Mechanism tests are in the mechanism beads.

### End-to-end script and logging
This bead is the script; steps, assertions and log fields are given above.

### Known answers and negative controls
Known answers: the two hand cases. Negative controls: `E2E_PLANT_FAILURE=1`; the qualification steps (a lane
that checks the audit record after commitment would advance the index and fail the `index unchanged`
assertions); `cancel_audit` (a cancelled audit must not count as audited). Determinism lanes: twice on one
machine; debug and release; Linux and macOS; finding ids, `TaskId`s and verdicts identical inside the tier's
class.

## Considerations

- The qualification steps need the blinded lane and a synthetic sealed family; if the lane is not yet built the script runs them as `not run` with the reason and cannot be used to close this bead.
- Wall time target: a few minutes; the audit budget is small because the hand-case task's reference campaign is declared small in the fixture.
- The MCP surface for `task_audit` in the `audit` task cluster is checked by the surface-parity tests using the same fixtures.
