## Background

A task's `randomization` section draws world parameters, and the plan's rule is that every draw traces to a stated
uncertainty: a field of a card (BD-200: `actuator:knee#torque_constant`, `interface:rubber-60a/tile#mu`) or a row
of a hazard registry (BD-227: `registry:hazards/commercial-kitchen:wet-floor`). There are no free-floating ranges
in a task file. The exposure domains of §24.22 (N24c-36) need two further kinds of draw that neither source
holds: the magnitude and direction of a push applied at a physical time or at a mission event, and the intensity
of a gust driven by a Brownian law. A push is not a property of a card (cards describe hardware, with datasheet
provenance), and it is not a hazard (a hazard is a feature of a place, addressed by interior archetype, and the
hazard registries land at M3, after the exposure domains of M2 need pushes). The exposure-domain bead's example
named `registry:hazards/push#impulse` and `registry:hazards/gust#force_psd`, which address no registry.

This bead supplies the missing source: one registry file of disturbance laws, with the hazard registry's
discipline (exact quantities with units, a distribution per drawn entry, one provenance per row, `assumed` until a
source is recorded), addressed from a task file as `registry:disturbances/<slug>#<dimension id>`. Crate
`frob-arena` (the loader, the resolver the task compiler calls for this source kind through BD-200's `:from`
resolution, and the application function per kind). Tier Solid.

DESIGN choices and the alternatives rejected: (1) an eighth hazard file for disturbances: rejected, because the
hazard address is scoped by archetype, a push belongs to no place, and BD-227 is M3; (2) a card kind
`disturbance`: rejected, because a card's provenance is a datasheet or a measurement of a part and a disturbance
law is a test condition; (3) ranges written in the task file: forbidden by the section's rule. The row schema
follows BD-227's so that one reader of either file sees the same shape.

## Scope

In: the file `registries/disturbances.toml` and its schema `frob.disturbance/1`; the plan-time rows `push` and
`gust` (DESIGN values, every row `assumed`); the loader (load errors, no partial registry); the address and the
resolver for the source kind `registry:disturbances` (a dimension's law, unit and row identifier, recorded with
every draw); how each row's kind is applied (an impulse at an instant; a force from a `BrownianDyadic` driver);
the worded load refusal; the unit tests and this bead's script.
Out: the exposure domains, keys and the exposure table that decide when and by which stream a draw is taken
(N24c-36); the dyadic law and the driver registry (N16c-01); the stream registry rows (N35-23); the hazard
registries of places (BD-227); the push and gust values of the exposure-coupling fixture (N24c-38, which draws
from these rows).

## Technical approach

**Row schema** (`frob.disturbance/1`; the field names of BD-227's hazard row where they mean the same):

```toml
[[disturbance]]
slug = "push"                     # address: registry:disturbances/push ; row identifier: disturbances.push
name = "Push on the base"
kind = "impulse"                  # impulse | force-brownian
applies_to = "base"               # base | port:<typed port> ; resolved against the design's interface
provenance = "assumed"            # assumed | norm: <citation> | measured: <dataset> (one per row)
dimensions = [
  { id = "impulse_per_mass", range = ["0.1 m/s", "0.5 m/s"], distribution = "uniform" },
  { id = "heading",          range = ["0 deg", "360 deg"],   distribution = "uniform" },
  { id = "duration",         value = "0.05 s" },
]

[[disturbance]]
slug = "gust"
name = "Horizontal gust force on the base"
kind = "force-brownian"
applies_to = "base"
provenance = "assumed"
dimensions = [
  { id = "intensity_per_mass", range = ["0.1 m·s^-3/2", "1.0 m·s^-3/2"], distribution = "uniform" },
  { id = "heading",            range = ["0 deg", "360 deg"],              distribution = "uniform" },
]
```

The values are DESIGN, chosen to perturb without toppling a settled class reference design, and every row is
`assumed` (the hazard registry's provenance rule, ADR-HAB-11: no source has been read for them; a row is promoted
only when a citation or dataset is an entry of the source register). `impulse_per_mass` is multiplied by the
design's total mass at resolution (the impulse in N·s); `intensity_per_mass` is the per-kilogram intensity σ of a
`BrownianDyadic` driver (N16c-01: the driver is the gust's impulse, in N·s; its increment over an interval is σ·m
times the tree's increment S, whose variance is the interval's length in seconds, so σ·m is in N·s per √s, that
is N·√s, and σ in m·s^-3/2). `heading` is measured in the horizontal plane from the base's forward
axis at the instant of application.

**Loader.** `disturbances::load(root) -> Result<Registry, LoadError>`: an entry with both `range` and `value`, with
neither, with a `range` and no `distribution`, or with a lower bound above its upper bound; a quantity whose unit
does not parse or does not fit the entry; an unknown field; a duplicate slug; an unknown `kind` or `applies_to`
form: each stops the loader with the file, the slug and the field, and no partial registry is served. A verb that
needs the registry (`task.new` and `task.check` on a task drawing from it; `sim.run --task` at environment
admission) answers one refusal envelope, exit 3, the worded refusal `disturbance-registry-invalid` (an N24-REF
row, raised by slug until N35-33's allocation ledger numbers it), pointer the file, slug and field, repairs
"1. correct the row; 2. restore the registry from the repository".

**Address and resolution.** A task writes `:from registry:disturbances/<slug>#<dimension id>`; the id may be left
out only for a row with exactly one drawn entry. An unknown slug, an unknown id, a missing id on a row with several
drawn entries, or an id naming a fixed entry is refused as an unknown field at `:from` (FROB-REF-103, as BD-200
refuses an unknown card field). `resolve(address) -> DrawSource { law, unit, row_id, provenance, kind,
applies_to, fixed }` is the resolver the task compiler calls for this source kind beside BD-200's card resolver;
the value itself is drawn by the stream and key the draw declares (N24c-36), never by call order, and the drawn
value, its unit, the row identifier and the row's provenance are written with the episode's resolved values. The
dimensions of one row drawn by one draw (the push's magnitude and heading) are drawn under one key with
consecutive components, so a push is one exposure.

**Application by kind.** `impulse`: an impulse of magnitude `impulse_per_mass`·m along `heading`, spread uniformly
over `duration` (a constant force of impulse/duration), applied to the body named by `applies_to` at its centre of
mass; the instant comes from the draw's domain (a time for `process`, an event for `event`). `force-brownian`: a
horizontal force whose increments over any interval are those of a `BrownianDyadic { intensity = σ·m }` driver of
the driver registry (N16c-01), so a run under `strict` or `referee` admits it and FROB-REF-223 never fires for it.

## Acceptance criteria

- [ ] `registries/disturbances.toml` holds the rows `push` and `gust` with the dimensions above, every row `assumed`, and loads; each malformed form listed under Loader is refused with the file, slug and field, and no partial registry is served.
- [ ] A task drawing `registry:disturbances/push#impulse_per_mass` and `registry:disturbances/gust#intensity_per_mass` is admitted by `task.check`; the check report lists for each draw its row identifier, law, unit and provenance.
- [ ] An unknown slug, an unknown dimension id and an id naming the fixed entry `duration` are each FROB-REF-103 pointing at `:from`.
- [ ] In a recorded run the `randomization` block carries each resolved draw with the row identifier (`disturbances.push`, `disturbances.gust`), its drawn value with unit and provenance `assumed`; the application function turns a drawn `impulse_per_mass` into an impulse equal to it times the design's mass to 10⁻¹² relative, spread over 0.05 s. (Applying it at a physical time or at a mission event is the exposure domain's, N24c-36, whose script checks the applied push in a run.)
- [ ] A gust drawn from `gust` is registered as a `BrownianDyadic` driver with intensity σ·m, and a `strict` run admits it.

## Test plan

### Unit tests

`cargo test -p frob-arena disturbances`:
- `rows_load`: two rows; `push` has three entries, two drawn; `gust` has two drawn.
- `load_errors_refused`: one `synthetic` file per malformed form (range and value; neither; range without
  distribution; a range [0.5 m/s, 0.1 m/s] whose lower bound is above its upper; unit `kg` on `impulse_per_mass`; an unknown field; a duplicate slug), each
  refused with its file, slug and field, and no registry returned.
- `address_resolution`: `registry:disturbances/push#heading` resolves to uniform [0, 360) deg; `#duration` is
  refused (fixed entry); `registry:disturbances/push` with no id is refused (two drawn entries);
  `registry:disturbances/kick#impulse_per_mass` is refused with FROB-REF-103.
- `impulse_scaled_by_mass`: a 12.5 kg design and a drawn 0.3 m/s give 3.75 N·s, a constant 75 N for 0.05 s.
- `gust_is_brownian_dyadic`: the resolved driver is `BrownianDyadic` with intensity σ·m; its increment over 1 s has
  variance (σ·m)² over 10⁵ draws within three standard errors.
- `provenance_recorded`: every resolved draw carries `disturbances.<slug>` and `assumed`.
- `draw_is_keyed_not_ordered`: the push's two drawn components are identical whether or not ten unrelated draws
  precede them in the section.

### End-to-end script and logging

`scripts/e2e/disturbance_registry.sh` (sources the STD-E2E helper; seed 17; idempotent): `frob task new
fixtures/disturbance_registry/push-gust.ftask --name dr-push --key dr-new --json` (a flat-ground task for the class
reference quadruped drawing `push#impulse_per_mass`, `push#heading` and `gust#intensity_per_mass` in BD-200's draw
form) and `frob task check dr-push --json` (exit 0; each draw listed with row identifier, law, unit and `assumed`);
`frob task check` on three planted copies (`push#kick`, `push#duration`, and `push` without an id): exit 3,
FROB-REF-103 at `:from`; the same task against a scratch project root whose `registries/disturbances.toml` has a
range without a distribution: exit 3, `disturbance-registry-invalid` naming the file, slug and field; `frob sim run
<reference quadruped> --task dr-push --tier referee --seconds 4 --seed 17 --key dr-run --json`: the run's
`randomization` block (BD-200) lists `disturbances.push` and `disturbances.gust` with their drawn values, units and
`assumed`, and a second run under key `dr-run-2` lists the same values (the draws are keyed, not ordered). Logged per STD-E2E to
`target/e2e-logs/disturbance_registry/<utc>.ndjson` with a transcript: per line `ts`, `script`, `bead`, `step`,
`event`, the command, exit code, wall time, the `evidence` block; the resolved row identifiers, laws and units; the
drawn values with units in both runs and their digest; refusal codes expected and observed with
their pointers; on failure the first differing value and the task and run paths; a final `summary`.

### Known answers and negative controls

Known answers: 0.3 m/s on 12.5 kg is 3.75 N·s, 75 N over 0.05 s; the Brownian increment variance (σ·m)²·Δt.
Negative controls: a loader that serves the rows it could parse and skips the broken one (caught by
`load_errors_refused`, which requires no registry); a resolver that draws by call order (caught by
`draw_is_keyed_not_ordered`); a push applied as one tick's force regardless of `duration` (caught by
`impulse_scaled_by_mass`, which checks the force and its duration). Determinism: the registry and its resolution
are exact (class D0); drawn values follow their stream's class.

## Considerations

- The values are placeholders with honest labels: `assumed` rows count against any realism claim exactly as the hazard rows do; a campaign that wants pushes of a published standard records the source and promotes the row.
- New disturbance kinds (a torque impulse, a payload drop) are new rows and, where the application differs, a new `kind` with its own test; a task never writes a law inline.
- When BD-227's hazard loader lands (M3), the two loaders keep separate files and addresses; sharing the row parser is a refactor that changes no file and no address.
- The direction convention (heading from the base's forward axis at application) makes a push mirror with the robot, which the metamorphic mirroring relation of the exposure fixture uses.
