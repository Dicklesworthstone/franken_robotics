## Background

The quantifier prefix of a mission query is written by the caller and is part of the mission's identity,
because one plant gives opposite answers under two orders of the same binders. The pusher is the standing
regression that proves the public interface keeps them apart. A one-axis, quasi-static pusher moves a package
into a displacement window in a single stroke. A design has a positive stroke gain g in a closed interval G. It
issues a command u in a nonnegative closed stroke interval U. A reset leaves an unknown nonnegative free gap d
in a closed interval D. The pusher first takes up the gap, then pushes by the remaining extension:

  y = max(0, g·u − d),   accepted when y lies in the closed window Y = [L, H], 0 ≤ L ≤ H.

Equality at contact onset yields zero. There is no later feedback. The catalogue gain is known at build time;
the gap is hidden from every controller. Two queries are asked of the same plant:

- **per-build** (a command chosen per known design): { g ∈ G : ∃ u ∈ U ∀ d ∈ D, y ∈ Y };
- **shared** (one command for the family): { u ∈ U : ∀ g ∈ G ∀ d ∈ D, y ∈ Y }.

On G = [1/2, 2], U = [0, 2], D = [0, 1/4], Y = [3/4, 5/4]: for every known gain the command u = 1/g works for
every gap (g·u = 1, so y ∈ [3/4, 1]); no single command works for the whole gain family, because
g·u ∈ [1, 5/4] for both g = 1/2 and g = 2 would need u ≥ 2 and u ≤ 5/8. The first query returns the whole
interval, the second the empty set, and the two differ by one binder.

What the plan-time pilot showed (FACT): a specialized solver and a composed conventional one each returned 20
of 20 intervals; six of six corrupted certificates were rejected; the composed arm took 1.345 times the
specialized arm's time warm and 1.088 cold, on a test whose ceiling was about 1.46; and an off-the-shelf
quantifier-elimination engine produced the family answer from the raw plant for 8 of 12 queries. So there is
no new kind of answer on this plant and no speed to claim. Both solvers ship, as the template's two lowerings
(proof obligation PO-AUGUR-01: a second, independently written lowering, compared exactly), with the roles the
register of lowering pairs gives them (N25d-34, `crates/frob-conformance/registry/lowerings.toml`): the
specialized interval solver is `primary`, the one `mission.synthesize` runs by default, and the composed solver
on the general elimination route is `second`, selected with `--lowering second`. ADR-AUGUR-03 (conventional
formulations first) holds in this form: the conventional route answers every case of the battery behind the
same verb, no timing is claimed for either, and which of the two is the default where they tie is the M3
decision KILL-AUGUR-TIE (N25a-18). The value of the battery is the interface: closed ends, singletons, the
saturation branch, and the two prefixes.

## Technical approach

1. **Preconditions** (refused with the schema refusal otherwise, each named): g_min > 0; u_min ≥ 0; d_min ≥ 0;
   0 ≤ L ≤ H; every interval nonempty.
2. **Guard collapse.** For H ≥ 0, max(0, x) ∈ [L, H] is equivalent to x ≤ H ∧ (L = 0 ∨ x ≥ L). With extension
   t = g·u, the condition "for every d ∈ D" becomes t ∈ [A, B] with

     A = L + d_max if L > 0, and A = 0 if L = 0;     B = H + d_min.

3. **Composed lowering** (role `second`; `crates/frob-mission/src/lower/pusher/composed.rs`; chart r = 1/g, in
   which the constraints are linear in (r, u)):
   rows at the disturbance vertices, (d_max + L)·r − u ≤ 0 when L > 0 and u − (d_min + H)·r ≤ 0, with
   u_min ≤ u ≤ u_max; for the per-build query eliminate u by Fourier–Motzkin projection and intersect the
   scalar half-lines exactly; for the shared query substitute the gain vertices g_min and g_max.
4. **Answers in closed form** (the specialized interval solver, role `primary`;
   `crates/frob-mission/src/lower/pusher/interval.rs`; written independently of step 3, proof obligation
   PO-AUGUR-01):
   - per-build design set: empty if A > B; otherwise g ∈ [max(g_min, A/u_max), min(g_max, B/u_min)], with
     B/u_min read as +∞ when u_min = 0 and A/u_max read as +∞ when u_max = 0 and A > 0; empty if the lower end
     exceeds the upper;
   - witness schedule: u(g) = max(u_min, A/g), for which the extension max(g·u_min, A) lies in [A, B];
   - shared command set: u ∈ [max(u_min, A/g_min), min(u_max, B/g_max)], empty if inverted or if A > B.
5. **Certificates.**
   - Per-build inclusion: the schedule, checked at the corners (g_lo, d_max) and (g_hi, d_min), with the
     monotonicity argument recorded (the scheduled extension is nondecreasing in g; y is nonincreasing in d).
   - Per-build exclusions: for g below the lower end, g·u_max − d_max < L (the window cannot be reached at full
     stroke with the largest gap); for g above the upper end, g·u_min − d_min > H (the smallest stroke already
     overshoots with the smallest gap). Each is a dual over the cell in the chart r.
   - Shared: a nonempty set carries its two corner checks, (g_min, d_max) at the lower command and
     (g_max, d_min) at the upper; an empty set carries the conflicting pair of design and gap corners whose
     command requirements are disjoint (u ≥ A/g_min against u ≤ B/g_max).
   - Empty per-build answers carry one of the exhaustive reasons: A > B; A/u_max > g_max; B/u_min < g_min.
   Kinds: `lp-primal`, `lp-farkas`, `partition`. Closed ends and zero-width intervals are data: a singleton is
   a cell closed at both ends with equal bounds.
6. **Mission encoding.** Design domain: free `g` with chart `inverse-gain` and box G. World: hidden `d` in D,
   `fixed-per-execution`. Observation: none. Per-build query: `policy_class.indexed_by = "nominal-design"`,
   prefix ∃ policy per nominal design, ∀ world. Shared query: `indexed_by = "family"`, prefix ∃ policy for the
   family, ∀ world; its inner set is G when the shared command set is nonempty and empty otherwise, and the
   witness carries the exact command set (`command_set` with `box` and `closed`).
7. **The ten frozen cases** (exact; each row hand-checked from the formulas of step 2 and step 4):

| Case | G | U | D | Y | Per-build design set | Shared command set |
|---|---|---|---|---|---|---|
| `wide` | [1/2, 2] | [0, 2] | [0, 1/4] | [3/4, 5/4] | [1/2, 2] | ∅ |
| `shared-tight` | [1, 5/4] | [0, 2] | [0, 1/4] | [3/4, 5/4] | [1, 5/4] | [1, 1] |
| `weak-design` | [1/4, 2] | [0, 2] | [0, 1/4] | [3/4, 5/4] | [1/2, 2] | ∅ |
| `hidden-gap` | [1, 2] | [0, 2] | [0, 3/4] | [3/4, 5/4] | ∅ | ∅ |
| `zero-allowed` | [1/4, 1] | [1/2, 2] | [1/4, 1/2] | [0, 1/8] | [1/4, 3/4] | ∅ |
| `both-ends` | [1/2, 2] | [1, 3/2] | [0, 1/4] | [3/4, 5/4] | [2/3, 5/4] | ∅ |
| `singleton` | [1/2, 2] | [1, 1] | [0, 0] | [3/4, 3/4] | [3/4, 3/4] | ∅ |
| `branch-crossing` | [1/2, 1] | [0, 1] | [1/4, 1/2] | [0, 1/8] | [1/2, 1] | [0, 3/8] |

8. **Six corrupted certificates** (each must be rejected): a widened design interval; a truncated design
   interval; an overstated shared interval; a schedule that violates the hidden gap; a spurious empty answer
   to the per-build query; a spurious empty answer to the shared query. They are applied to the certificates
   of both lowerings.

9. **Registration and independence.** The module `frob_mission::lower::pusher` exports `entries()` with two
   `LoweringEntry` records for the template `pusher` (N25ap4-01): `pusher-interval` with `Role::Primary` and
   `pusher-composed` with `Role::Second`, added as one line to `frob_mission::lowering::builtin()`. Both
   implement the `Lowering` trait: `fragment` is `linear-static` (DESIGN: after the guard collapse of step 2
   the constraints are affine in the chart r and the command); `applies` is true exactly for a mission whose
   design family is the pusher's and whose prefix is one of the two of step 6; `exact_boundary` returns the
   per-build cells split at the two interval ends (checked with `check_partition`); `propose` returns the
   certificates of step 5, charges the call's measured time to the meter's lines `wall_s` and `cpu_core_s`
   (whole milliseconds), and returns `Undecided(vec![BudgetExhausted])` when the meter refuses the charge. The
   two files share no source beyond
   the query types and the exact rational type, and neither calls the other: `interval.rs` evaluates the
   formulas of step 4, `composed.rs` builds the rows of step 3 and calls the in-tree elimination of BD-128.
   Both live in `frob-mission` because the registry can only construct what that crate holds (`frob-mission`
   may not depend on `frob-conformance`, N25a-01); independence is by file set, which N25d-34's build-time
   check lists.

Determinism D0. Evidence `Certified` after the bundle check, which BD-133 runs before an answer returns; in this
bead's own tests the certificates are proposals, re-evaluated exactly by the test oracle of the Test plan.
Claim kind Known answer for the battery.

## Test plan

### Unit tests

`crates/frob-mission/tests/pusher.rs`: one test per case, named after it, asserting both intervals and their
closed ends; `wide_schedule_is_one_over_g`; `shared_tight_is_the_singleton_one` (A/g_min = 1, B/g_max = 1);
`zero_allowed_has_no_lower_extension_bound` (A = 0, B = 3/8, so g ≤ 3/4 from u_min = 1/2);
`both_ends_cuts_two_sides` (g ≥ A/u_max = 2/3 and g ≤ B/u_min = 5/4); `singleton_design` (A = B = 3/4,
u = 1); `branch_crossing_shared_set` (u ≤ B/g_max = 3/8); `no_stroke_empty`; `forced_overshoot_empty`
(g ≤ 1/2 against G = [1, 2]); `preconditions_refused`; `prefix_mismatch_refused_881`.
`pusher_entries_register_primary_and_second` (the two names and roles; `select(Primary)` and `select(Second)`
on the per-build and shared missions of `wide`; a stance mission selects neither);
`exact_boundary_is_a_partition` (`both-ends`: [1/2, 2/3), [2/3, 5/4], (5/4, 2] passes `check_partition`).
`crates/frob-conformance/tests/pusher_two_lowerings.rs`: `ten_cases_agree`; `random_instances_agree` (10⁴
instances from `FROB_TEST_SEED`: rational ends with denominators up to 16 that meet the preconditions);
`six_corrupted_certificates_rejected`. The test oracle (DESIGN; in the test file, sharing no code with either
lowering) evaluates y = max(0, g·u − d) in exact rationals: an inclusion certificate is accepted when its
schedule gives y ∈ Y at the two recorded corners and at 64 further rational points of the cell and gap box; an
exclusion when its stated inequality holds exactly at the cell's end; a shared set when both corner checks
hold; an empty answer when its stated reason holds. Each corruption fails by the check named: the widened
design interval at its new lower corner (`both-ends` widened to [1/2, 5/4]: at g = 1/2 the full stroke gives
g·u = 3/4 and y = 1/2 < 3/4 at d = 1/4); the truncated one because the exclusion claimed for the cut-off part
is false at its end (`both-ends` cut to [3/4, 5/4]: at g = 2/3, g·u_max − d_max = 3/4, not below L); the
overstated shared interval at its upper command against (g_max, d_min) (`shared-tight` with [1, 9/8]:
y = 45/32 > 5/4); the bad schedule at (g_lo, d_max) (`wide` with g·u = 7/8: y = 5/8 < 3/4); the two spurious
empty answers because the stated reason is false (A = 1 ≤ B = 5/4 on `wide`; A/g_min = 1 ≤ B/g_max = 1 on
`shared-tight`).

## Considerations

- CX-285 and the ceiling rule: the pilot's speed test could not have shown more than about 1.46 (a residual of
  575.7 µs that no solver touches against a batch of 842.8 µs); no speed figure is quoted from this battery.
- The guard here is decided by a fixture constant, so every query is a two-variable linear projection. The
  result says nothing about plants with state-dependent event order; that scope limit is printed with the
  battery.
- KILL-AUGUR-TIE: a conventional program answers this plant. It ships as the `second` lowering behind the same
  verb from M1; whether it becomes the default on this stratum is N25a-18's decision at M3, and a change of
  roles is one edit of `entries()` and of the register's record, with the comparison of N25d-34 re-run.
