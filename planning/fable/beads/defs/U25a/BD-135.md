## Background

The mission subsystem answers questions about a set of robot designs: which members of a family can do a
mission (an inner set with witnesses), which cannot (exclusions with impossibility witnesses), and which are
still unknown. This bead is its public surface at the first milestone: four verbs, generated from the verb
registry like every other verb, on the command line and over MCP.

| Verb | Kind | Mathematical output | What a design agent does with it |
|---|---|---|---|
| `mission.synthesize` | run | Inner and outer feasible sets over named parameters and topologies; witness controllers; unresolved cells; cost bounds when an objective is given | Chooses from a whole family of wheels, legs, transmissions and sensors under constraints |
| `mission.refute` | run | A scoped impossibility bound, or a witness that defeats one proposed design and controller; the binding constraint and the smallest admitted change that relaxes it | Stops an unproductive policy search; asks for the smallest physical change that would help |
| `mission.distinguish` | run | The smallest admissible intervention or instrument whose readings separate alternatives that imply different mission decisions; otherwise two witness mechanisms with opposing margins | Decides whether to collect a measurement, move a mount or fund more simulation |
| `mission.show` | read | A stored answer by set (`inner`, `outer`, `excluded`, `unresolved`), ordered and paged | Reads a large answer without re-running it |

The other verbs of the cluster are separate beads: `mission.new` and `mission.check` (admission),
`mission.separate`, `mission.transport`, `mission.revalidate`, and `experiment.suggest` in its own cluster.

The design decision that needs a reason is the budget stop. The standing rule of the tool surface is that a
budget stop publishes nothing partial as a result (exit 4). A mission answer is different in kind: each decided
cell is certified on its own, so the answer at any moment is a valid answer to "what is known under this
budget" (answers are anytime). DESIGN: a mission query that stops on budget returns its certified cells and
the unresolved remainder. This is the standing rule applied to a result whose parts are separately complete,
not an exception to it. Rejected: discarding certified cells at a budget stop (wastes checked work and forces
agents to over-budget); returning unresolved cells as tentative verdicts (unsound).

## Scope

In: registry entries, input and output schemas, command-line forms, the envelope, `--estimate`, session-budget
admission, the bounded synchronous wait and job handle, progress events, cancellation, the budget-stop rule,
running the checker before an answer is returned, paging of `mission.show`, and the M1 form of
`mission.distinguish`. Out: the mechanisms behind the verbs (N25a-05, N25a-09, N25a-10, N25a-12 and the family
beads); the bundle writer and `prove.*` (BD-133); MCP generation (BD-138); the full distinguish.

## Technical approach

1. **Registry entries** (`registries/verbs.toml`), one per verb, for example:
   ```toml
   [[verb]]
   name = "mission.synthesize"; cluster = "mission"; kind = "run"; tier = "F"
   capabilities = ["mission:run"]
   input_schema = "frob.mission.synthesize.in/1"; output_schema = "frob.mission.synthesize.out/1"
   refusals = ["FROB-REF-868", "FROB-REF-874", "FROB-REF-877", "FROB-REF-881", "FROB-REF-884", "FROB-REF-887",
               "FROB-REF-846", "FROB-REF-847", "FROB-REF-853", "FROB-REF-855", "FROB-REF-856",
               "FROB-REF-701", "FROB-REF-724"]
   idempotent = true; first_milestone = "M1"; task_clusters = ["mission"]
   cost_model = "per fragment: admission + lowering + proposing + checking"
   examples = ["frob mission synthesize carrier.fmission --json"]
   ```
   `mission.refute` (run; example `frob mission refute carrier.fmission --design d:41aa… --policy p:07c2…`),
   `mission.distinguish` (run; first milestone M1 in reduced form, full at M4), `mission.show` (read;
   capability `mission:read`; example `frob mission show q:3c9d… --answer a:0e51… --set outer`). MCP tool
   names replace the dot by an underscore.
2. **Inputs.** A mission by file or by `q:…`; optional `--design`, `--policy`, `--cell`, `--exists`,
   `--paving`, `--from a:…`, `--strategy`, `--set key=value` (a one-field amendment that produces a new
   `MissionId`), `--budget`, `--sync-wait-ms`, `--estimate`, and an idempotency key on run verbs.
3. **Envelope.** `frob.envelope/1` with `result` (the answer rendering), `evidence` (claim product: class,
   tier, determinism, claims, reality), `bound` (the immutable identifiers every name resolved to), `cost`,
   `budget`, `warnings`, `next_actions` and `authorization` (three flags, all `false`).
4. **`--estimate`** returns the cost of admission, lowering, proposing and checking separately, with
   intervals, and runs nothing. Checker time is a budget line of its own because it is part of decision time.
5. **Session budgets.** A query whose estimate (upper end) exceeds a session budget is refused with the
   estimate attached (`FROB-REF-701`, exit 4).
6. **The run.** Admit; choose lowerings; run the driver; for every decided cell obtain proof objects; have the
   bundle written and **checked by the independent auditor before the answer is returned**. A proof the
   auditor rejects is never published: its cell is returned unresolved with explanation `SolverFailure` and a
   warning naming the rejected rule. The answer is stored under its address `a:…` and is immutable.
7. **Budget stop.** When any budget line is exhausted the driver stops at a cell boundary, finishes checking
   what it has proposed if checker budget remains, and returns:
   - exit 0 when the unresolved set satisfies the query's `resolution`;
   - exit 2 with the flag `resolution-unmet` when it does not;
   - exit 4 (`FROB-REF-702`) only when the budget ended before admission and the first checked cell, in which
     case nothing is published.
   This is the fail-closed default of OPEN-AUGUR-7 (owner: the Tether lead). Each returned cell is complete in
   itself: it has its proofs or its explanations. No unresolved cell is printed as a verdict in any output
   path (JSON, text rendering, `mission.show`, `next_actions`).
8. **Jobs.** After `sync_wait_ms` (default: wait to completion on the command line; 5,000 ms on MCP, at most
   30,000) the verb returns exit 8 with a job handle. Progress events report decided measure, unresolved
   measure, certificates checked, and the current next test, always with a denominator. Cancellation drains:
   proposals in flight are discarded, checked cells are kept and returned under the budget-stop rule.
9. **`mission.show`.** Reads a stored answer; `--set` selects the list; rows are ordered canonically and
   paged with a cursor pinned to the committed frontier. For `outer` it returns the definition ("domain minus
   excluded cells"), the cells, `inner_within`, `unresolved_within`, and a measure only when the query's
   `resolution` names one.
10. **`mission.distinguish` at this milestone** works on enumerated worlds and the alias witness of BD-134:
    1. Keep the admitted worlds compatible with the declared observations.
    2. Partition them by the mission decision each implies (the remaining commands it requires).
    3. If every world implies the same decision, stop: identification is not needed.
    4. Otherwise choose the least costly realizable intervention, among the observation and authority fields
       the query marks adjustable (a packet's arrival instant, a read-error bound, a probe command within the
       actuator bound), whose possible readings over the admitted error form disjoint closed sets for every
       pair of worlds with opposite decisions.
    5. Where the reading sets still overlap, return the two witness worlds, their opposing requirements, and
       the reading they share.
    6. Always include direct observation of the hidden quantity as a candidate.
    7. If the declared observations fit no admitted world, report a discrepancy; do not pick the nearest.
11. **Refusals.** Mission refusals are in the `8xx` family and exit 3; each carries `code`, `message`,
    `pointer`, `observed`, `required` and ranked `repairs`. Budget refusals exit 4; an unimplemented strategy
    exits 5 (`FROB-REF-724`); a malformed call exits 3 (`FROB-REF-802`).

Determinism: exact fragments D0; the job path must return the same answer bytes as the synchronous path.

## Acceptance criteria

- [ ] A budget stop returns the certified cells and the unresolved remainder, each cell complete in itself; no
      unresolved cell is printed as a verdict (seed done-condition), checked on the tray query stopped after
      its first pass: one inner cell, eight excluded, three unresolved, exit 0 under resolution 1/4 and exit 2
      with `resolution-unmet` under resolution 1/8.
- [ ] A budget that ends before the first checked cell returns exit 4 and publishes no answer address.
- [ ] `--estimate` prints four cost lines with intervals and performs no work (no ledger write, no job).
- [ ] Synchronous and job paths return byte-identical `result` blocks; exit 8 carries a job handle with a
      progress denominator.
- [ ] Cancellation mid-run returns the cells checked so far and leaks no job, lease or temporary file.
- [ ] `mission.show --set outer` on the tray answer lists c:02, c:03, c:05, c:06; a paged read returns each
      cell once.
- [ ] `mission.distinguish` on the late-packet docking mission returns the timing intervention; at U = 3/4,
      ε = 5/16 it returns the two witness worlds and the shared reading 15/16.
- [ ] Each verb is reachable through `frob --json` with its documented schema and exit codes, and its registry
      entry lists every refusal it can raise (a lint compares raised codes with the list).

## Test plan

### Unit tests

`crates/frob-verbs/tests/mission_verbs.rs` (real kernel, real ledger in a temporary root, no mocks):
`budget_stop_exit0_when_resolution_met`; `budget_stop_exit2_resolution_unmet`;
`budget_before_first_cell_exit4_publishes_nothing`; `estimate_runs_nothing`;
`rejected_proof_is_never_published` (a planted proposer defect whose proof the auditor rejects yields an
unresolved cell and a warning); `job_and_sync_results_identical`; `cancel_keeps_checked_cells`;
`show_outer_is_domain_minus_excluded`; `show_pages_each_cell_once`; `text_rendering_never_calls_unresolved_a_verdict`
(a scan of every output template); `registry_refusal_list_is_complete`;
`distinguish_docking_late_packet`: readings centred at p and 2p with radius ε are disjoint exactly when
p > 2ε; with U = 3/4 and ε = 1/8 the admissible probes are p ∈ (1/4, 5/8], and the widest gap, 3/8, is at
p = 5/8; `distinguish_docking_equality_returns_witness_pair`: at ε = 5/16 and p = 5/8 both worlds can read
15/16 and require second commands −1/4 (gain 1) and −3/4 (gain 2).

### End-to-end script and logging

`scripts/e2e/mission_budget_stops.sh` (bead N25a-24) drives the tray query under three budgets, the estimate,
the job path, cancellation and paging from the shell. It logs every command line, exit code, wall time, the
evidence block, per-list cell counts, the flag `resolution-unmet` when present, and the answer and bundle
digests.

### Known answers and negative controls

The tray cell table (worked artifact of the plan: one inner, three unresolved, eight excluded on a 4 × 3
paving); KA-636 and KA-637 for the docking calls. Negative controls registered: a mutant that returns exit 0
when resolution is unmet; a mutant text renderer that prints an unresolved cell under "excluded"; a mutant
that publishes an answer whose bundle the auditor rejected; a mutant cancel that drops checked cells. Chaos
(tier G4): cancellation at every await point of the submit path; a kill of the daemon mid-run followed by
recovery by idempotency key. Determinism lanes: twice on one machine; worker counts 1 and 8; debug and release.

## Considerations

- OPEN-AUGUR-7 is a question about one exit code; whichever way it is decided, the published content (certified
  cells plus the unresolved remainder) does not change.
- The worked session of the plan shows exit 0 for a first pass with a warning and exit 2 for its refinement;
  the rule above (exit 2 only for `resolution-unmet` or other flags) is the normative one, and the session
  transcript is illustrative.
- GATE-AUGUR-07 measures whether a fresh agent can use these verbs from generated documentation alone; the
  wording of `binding`, `explanation`, `next_test` and `next_actions` is part of what is tested.
- The MCP task cluster for missions holds seven tools, the limit; adding a verb to the cluster means moving
  another out.
