## Background

The mission subsystem's claim is not speed. Its plan-time pilots all ended in ties with conventional programs.
What survives them is an interface: one typed question, a checked answer in a common form, and the discipline
of counterexamples. Whether that interface is usable by a design agent that has never seen the project is an
open question until it is measured, and the first milestone measures it on the smallest slice an implementer
can finish: two hidden gains, two packet timings, one actuator bound, one observation-noise family (the
docking mission), plus the stance family. The compulsory interfaces of the slice are a causal history, a
feasible controller, two indistinguishable worlds, an exact physical parameter chart and an independent
checker. It ships as a CPU worked example before the first complex GPU kernel exists, and it is the M1 exit
demonstration for the subsystem.

GATE-AUGUR-07 (TARGET): a fresh agent given only the generated documentation completes 10 scripted docking and
stance amendments, names the binding hardware restriction in at least 9, and never reports an unresolved cell
as a verdict; the serial turn count is recorded against a second arm restricted to the lower verbs.

Three further things are decided on the same record.
- **The evidence that buys the next investment**: the offline auditor `frob-verify` reproduces the boundary
  ε < (U + 1/2)/4, finds the exact shared reading at equality, and accepts an ordinary scenario-tree program
  as a competing answer. That last clause is ADR-AUGUR-09: a rival's answer goes through the same checker;
  `frob-verify` accepts a bundle from any producer.
- **The one-verb hypothesis**: `mission.synthesize` is the one-verb route from a brief to a set of survivors.
  That it saves serial agent turns is a HYPOTHESIS, tested by the lower-verbs arm. If it does not, the verb
  remains a convenience.
- **The first reading of KILL-AUGUR-TIE**: if a conventional scenario-tree program gives the better answer per
  engineering hour on the docking slice, that program ships behind the same verbs.

Stop decision (written in advance): if a fresh agent cannot complete the amendments after one repair cycle,
the mission chapter is re-planned before physics is added, because the mapping from sensors and actuators to
the query is then the defect. Decision if the slice's evidence fails: repair that mapping before adding
physics, and ship the reference algorithm if it gives the better answer per engineering hour.

## Scope

In: the experiment protocol, the two arms on two surfaces, the run harness, scoring, the record for the gate,
and the two side readings. Out: the amendment fixture and rubric (N25a-14); the verbs (BD-135, BD-129,
BD-130); MCP generation (BD-138); the kill-gate decision itself (N25a-18, decided at M3).

## Technical approach

1. **Sessions.** Every agent session is fresh-context: it has contributed nothing to the project and is given
   only (a) the output of `frob robot-docs` (documentation generated from the verb registry), (b) the base
   mission files `docking.fmission` and `stance.fmission`, and (c) the ten cards, one at a time. One pinned
   agent model at one revision for the whole gate, the same token and tool-call caps per session, no human in
   the loop. The model, revision and caps are printed in the record's disclosure block.
2. **Arms and surfaces.**
   - Arm A, full M1 surface, run twice: once through the `frob` command line, once through `frob-mcp` (the
     `mission` task cluster after `session_focus`).
   - Arm B, lower verbs only, run once through the command line: the registry is served with
     `mission.synthesize` and `mission.distinguish` withheld; the agent keeps `mission.new`, `mission.check`,
     `mission.refute` restricted to one bound design, the `design`, `analyze`, `sim`, `prove` and `artifact`
     verbs. (DESIGN: the plan says "restricted to the lower verbs" and does not list them; this is the list.)
3. **Per card.** The harness shows the card, lets the agent work until it emits a final statement or reaches a
   cap, and records the transcript, every tool call with its envelope, the serial turn count, wall time and
   tokens. A cap reached without a final statement is an incomplete amendment.
4. **Scoring.** An evaluator session that did not implement any bead of the slice scores each final statement
   against the sealed truth record with the rubric of N25a-14: completed (correct verdict category); binding
   restriction named (an accepted name appears); false verdicts (sentences that present an unresolved cell as
   attainable or unattainable). The evaluator sees statements without the arm label where the format allows.
5. **Pass rule.** Arm A passes on a surface when 10 of 10 amendments are completed, the binding restriction is
   named in at least 9, and the false-verdict count is 0. GATE-AUGUR-07 passes when arm A passes on both
   surfaces and the turn counts of both arms are recorded. Arm B's success is not required; its turn count is.
6. **One repair cycle.** If arm A fails, one cycle of repair is allowed: changes to documentation text,
   refusal messages, `next_actions` and field wording, recorded as a diff; then fresh sessions rerun all ten
   cards. A second failure triggers the stop decision.
7. **Checker evidence.** Independently of the agents the script verifies with `frob-verify`, built from an
   empty environment: the docking boundary cells; the equality bundle at U = 3/4, ε = 5/16 with the shared
   reading 15/16; and a bundle produced by the conventional scenario-tree comparator (not by the product's
   writer), which must be accepted. It then mutates the packet's arrival instant and reruns: the answer must
   change from admitted to excluded and the old bundle must be rejected for the new query.
8. **Tie reading.** For the docking slice the record states, for the product path and for the conventional
   scenario-tree program: whether they return the same checked scope, their turnaround, and the engineering
   hours each took to author (from the beads' own logs). The reading is an input to the kill-gate decision; it
   decides nothing by itself at M1 except the wording "the reference algorithm ships behind the same verbs"
   when it gives the better answer per engineering hour.
9. **Record.** One gate record with measured values (not targets): per arm and surface the three counts, turn
   counts per card, totals, the disclosure block, the repair diff if any, and the commit, hardware fingerprint
   and seeds. The recording session is not a session that implemented the slice.

## Acceptance criteria

- [ ] GATE-AUGUR-07 (seed done-condition) is recorded with measured values: completed count, named count,
      false-verdict count and serial turns, for arm A on the command line, arm A on MCP, and arm B.
- [ ] The pass rule of step 5 is evaluated and the outcome (pass, or fail with the stop decision invoked) is
      written as it fell.
- [ ] `frob-verify` accepts the product's docking and stance bundles and the bundle written by the
      conventional comparator; it rejects the pre-mutation bundle offered for the timestamp-mutated query.
- [ ] The one-verb hypothesis is reported as supported or not supported, by the paired difference in serial
      turns over the ten cards, with no claim beyond those ten.
- [ ] The tie reading is recorded with both authoring times.
- [ ] Negative controls of the scorer (three canned transcripts) are classified correctly in the same run.

## Test plan

### Unit tests

`crates/frob-conformance/tests/first_slice_harness.rs`: `scorer_flags_unresolved_reported_as_infeasible`;
`scorer_rejects_wrong_restriction`; `scorer_rejects_attainable_claim_for_third_gain`;
`lower_verbs_registry_withholds_synthesize_and_distinguish`; `turn_counter_counts_serial_tool_calls`;
`incomplete_when_cap_reached`. These run the real scorer and the real registry filter on recorded
transcripts labelled `synthetic`.

### End-to-end script and logging

`scripts/e2e/mission_first_slice.sh`: builds `frob`, `frob-mcp` and `frob-verify`; verifies the fixture
freeze; runs step 7; launches the three agent sessions through the pinned agent runner with the card
sequence; invokes the evaluator session; writes the gate record. Logging through the helper of STD-E2E to
`target/e2e-logs/mission_first_slice/<utc>.ndjson`: for every tool call the exact command or MCP request,
exit code, wall time and the envelope's evidence block; per card a `metric` line (completed, named,
false_verdicts, turns); per arm a totals line; the checker assertions with bundle digests; a `summary` line
with the gates touched (GATE-AUGUR-07, first reading of KILL-AUGUR-TIE). Transcripts are stored beside the
log; nothing from a private scene is involved.

### Known answers and negative controls

The ten truths of N25a-14 (values from KA-624, KA-626, KA-635 to KA-638). Negative controls: the three canned
transcripts for the scorer; an agent run in which `robot-docs` is replaced by an empty document must fail the
gate (it shows the gate is sensitive to documentation); the timestamp mutation. Determinism: agent sessions
are not deterministic and are not claimed to be; everything else in the script is class D0 and is run twice.

## Considerations

- The result is conditional on one agent model, stated as such. A different model is a new run, not a
  correction.
- A fresh agent "naming the binding restriction" depends on the wording of `binding`, `relaxations` and
  `next_actions`; the repair cycle is expected to be spent there.
- RISK-26 (a short robust program over an incumbent engine reaches the same accepted answers in comparable
  time): a tie on this slice is the expected outcome and is acceptable; it ships the conventional program
  behind the same verbs.
- The agent must not be able to read the truth records, the beads or the tests; the harness's working
  directory contains only what step 1 lists.
