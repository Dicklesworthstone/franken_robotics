## Background

A mission answer is only as good as the question it answers. The same robot and the same physics give opposite
answers under "one command per known build" and "one command for the whole family", and the two questions
differ by one binder. Admission is the step that fixes the question before any solver sees it, so that an
optimizer, a learned policy, a cache or a GPU kernel cannot change the question while answering it.

The file format `.fmission` (identifier `FMT-FMISSION`, schema `frob.mission/1`) is owned by `frob-spec`: its
parser and canonical form come from BD-126. `frob-mission` owns *semantic* admission: the rules that make a
well-formed document a well-posed query. This bead implements those rules and their refusals.

Decisions carried here.
- **ADR-AUGUR-11: `.fmission` is canonical JSON with exact numbers as strings.** `MissionId` is the BLAKE3 hash
  of the canonical bytes (domain string `frob.mission/1`), printed `q:…`; which bytes are hashed is fixed by
  BD-126 (the semantic fields; see Identity below). Rationals are reduced integer pairs
  "p/q" with a positive denominator; integers above 2⁵³ never travel as JSON numbers. Reason: a float in a
  query makes the identity depend on a printer. Rejected: decimal floats with a tolerance.
- **ADR-AUGUR-12: hidden as-built parameters live in the world, not in the design index.** A policy may be
  indexed by the known nominal build. It may not be indexed by a tolerance the controller cannot observe.
  Reason: two indistinguishable builds that need different commands cannot each get their own controller.
- **ADR-AUGUR-06 (admission side): region evidence is per constraint, with a bounded split set.** A request for
  a joint paving of the design box, or for a region certificate over more parameters than the admitted limit, is
  refused at admission with the per-constraint decomposition offered. Reason: 10⁴ boxes are 13 bisections, less
  than one cut per axis in 20 dimensions. The certificates themselves belong to the region-evidence beads.
- No default quantifier prefix and no default persistence (ADR-AUGUR-02): evidence for the easier reading looks
  identical in a table of results.

## Scope

In: the semantic checks of admission, added to the entry point `frob_mission::admit` at the positions its order
table gives: the per-field rules for `design_domain`, `world.persistence`, `observation`, `policy_class`,
`horizon`, `predicates`, `quantifiers`, `objective`, `evidence`, `resolution`, `response` and `budget`, with the
refusals 884, 887, 847, 855, 856, 724 and the semantic uses of 868 and 874; the `AdmittedMission` value; the
fragment classification, which fills the `fragment` field of the `mission.check` result.

Out, with the bead that has it:

- The file and everything that is a property of the document alone (BD-126, the seed bead and a dependency of
  this one): the schema, the types, JSON parsing, canonical bytes and `MissionId`; the entry point `admit`, its
  signature and the one order of checks; the checks at positions 1 to 3 of that order (a valid file, 868; a
  non-empty design domain, 868; a non-empty world family, 874); the echo of the prefix with its rendering and
  `prefix_class`; the result object of `mission.check` (schema `frob.mission.check.out/1`); the verbs
  `mission.new` and `mission.check`; the quantifier-order fixture. This bead writes no second `admit`, no
  second report type and no second rendering of the echo.
- Chance-constraint completeness (N25a-11, refusal 846, position 14); the inconsistent-mission test (refusal
  877: N25b-07, position 15, which depends on this bead and runs on the `AdmittedMission` it produces, after
  the other checks and before any search); the `law` field (N25e-28); the remaining verbs (BD-135).

## Technical approach

`pub fn admit(doc: &MissionDocument) -> Result<AdmittedMission, Refusal>` in `frob_mission::admit` is created by
BD-126 with the checks of positions 1 to 3; this bead adds the rest of the table. Checks run in the order below,
which is the order BD-126 fixes (DESIGN, the same table in both beads: the order of the document's fields); the
first failure refuses (exit 3) with `code`, `message`, `pointer` (the JSON path), `observed`, `required` and
ranked `repairs`. Rows 1 and 3, and the non-emptiness half of row 2, are BD-126's checks and are printed here
so that the order can be read in one place.

| # | Field | Rule | Refusal and first repair |
|---|---|---|---|
| 1 | whole document (BD-126) | Known fields only; every required field present; every quantity has a unit; every number is an exact string; rationals reduced with positive denominator | 868; the schema diff |
| 2 | `design_domain` (non-emptiness of boxes and topologies: BD-126) | A family from the design language: template or grammar, admitted topologies, ordered ports, admitted interface-preserving isomorphisms, free parameters each with `unit`, `chart` and `box`, bound parameters, part and fabrication `tolerances`. A free parameter names its chart (for example `inverse-length`) because convexity and monotonicity are properties of a chart | 868 with the missing key |
| 3 | `world` (emptiness: BD-126) | A nonempty declared family: geometry, physics, hidden parameters, initial-state uncertainty; `kind` is `bounded-set` (worst case) or `population` (a named law). Emptiness is tested on the declared hulls and boxes in exact arithmetic | 874; the emptying constraint |
| 4 | `world.persistence` | Every hidden parameter is `fixed-per-execution` or `resampled` at a named instant. No default: treating a fixed parameter as a per-step disturbance is conservative for inclusion and unsound for exclusion | 884; the two candidate declarations and the fixture that separates them (a prescribed out-and-back motion of one second each way with a hidden positive gain g ∈ {1, 2}: net displacement g − g = 0 in both worlds if fixed per execution, reachable net displacements {−1, 0, 1} if resampled per move) |
| 5 | `observation` | Channel, fields, noise bounds, and timing in the seven instants of the clock contract: sample, exposure, timestamp, arrival, decision, command, actuation. Every field has an arrival instant | 847; the instant at which the field becomes usable |
| 6 | `policy_class` | `kind` is `causal` on the history of the channel; `indexed_by` is `nominal-design`, `cell` or `family`; `authority`; `randomization`; `decision_makers`. `clairvoyant` is accepted only as a labelled relaxation (the label is `relaxation: exclusion-only`), usable for exclusion and never for inclusion: a clairvoyant query can never produce an inner cell. Every quantity the policy is indexed by is a known nominal design parameter or an observation field whose arrival is not later than the decision instant; a hidden parameter or a tolerance is neither | 887; move the parameter into the world, or add the calibration observation. A `clairvoyant` kind without the relaxation label is also 887 (the policy would use the world before it is observed); first repair: add `relaxation: exclusion-only`, or declare the policy `causal` |
| 7 | `horizon` | `static`, a finite time, a tick count, or a declared terminal mode set. An unbounded horizon needs a declared completion | 868 |
| 8 | `predicates` | `accept` (the Boolean acceptance predicate), `hard_loss`, optional `margins`. Each atom carries its comparator (`<`, `≤`, `=`) and units; atoms may reference requirement terms of a `.ftask` by identifier. A shaping reward is not a predicate | 868 |
| 9 | `quantifiers` | An ordered, nonempty prefix of binders: `exists policy` with its scope, `forall world`, `forall execution`, or `prob world ≥ p` with population and confidence. The scope of `exists policy` agrees with `policy_class.indexed_by` | 884 when absent; 868 on disagreement |
| 10 | `objective` | Optional: a declared cost and the claim wanted: `feasible-candidate`, `minimum-with-matching-lower-bound` or `pareto`. Several objectives are not combined; a scalarization is the caller's and is recorded | 868 |
| 11 | `evidence` | Profile `exact` (rational certificates), `enclosed` (outward-rounded intervals) or `empirical` (sample coverage under a named population), with accepted classes. One cell never mixes profiles. An `enclosed` request that names a joint paving, or more split parameters than the limit (six), is refused | 855 (split the cell; supply the weighting); 856 (the per-constraint decomposition) |
| 12 | `resolution` | The largest unresolved set the caller accepts, in a stated measure, and mandatory `interior`, `exterior`, `boundary` obligations. No measure is built in; a probability mass needs a caller-supplied weighting | 855 when a mass is asked for without a weighting |
| 13 | `response`, `budget` | Which parts to return; wall, CPU core, GPU, referee and checker seconds, `sync_wait_ms` | 868 on unknown parts |

Further rules.
- **Decision makers.** The field is present and accepts exactly one decision maker in schema version 1; more
  than one is refused with FROB-REF-724 (capability not implemented in this build, exit 5) until the multi-robot
  slice. This is the fail-closed default of OPEN-AUGUR-9; the code choice is a DESIGN of this bead.
- **Fragment classification.** The admitted query is classified, without solving it, as `linear-static`
  (affine constraints in the declared chart with design-independent mission vertices: an exact answer is
  available), `finite-game` (finite hidden set and finite packet schedule), `interval` (enclosures), `campaign`
  (simulation only: `Tested` at best) or `none-at-this-build`. A query with no lowering is admitted; its cells
  come back unresolved with that reason.
- **The report.** The result of `mission.check` is BD-126's object (schema `frob.mission.check.out/1`): `domain`
  (`"nonempty"`), `topologies`, `free`, `quantifiers` (the prefix rendered in the order written, for example
  "∃ policy per nominal design, ∀ worlds, ∀ executions"), `fragment`, `horizon`, with the additive fields
  `mission_id`, `quantifiers_echo` and `prefix_class`. This bead supplies two of its values from the
  `AdmittedMission`: `fragment`, rendered as the worked session has it ("linear static: exact answer
  available" for `linear-static`), and `horizon`. The echo, never normalized or reordered, is rendered by
  BD-126.
- **Identity.** `MissionId` is computed by `frob-spec` (BD-126). DESIGN, stated the same way in BD-126: the hash
  covers the canonical bytes of the semantic fields, that is the document with `name`, `response` and `budget`
  removed. An earlier draft of this bead hashed the whole document; the plan says "the canonical bytes" without
  saying which fields count, and the exclusion is chosen because those three fields change what is returned and
  how long it may take, not what is true, and answers must accumulate under one identity when only the budget
  grows. Invariant INV-AUGUR-03: the identity changes whenever a quantifier, comparator, world support,
  persistence declaration, observation timing, policy class or horizon changes. A per-call budget or response
  selection is an argument of the verb and does not change it. The sensitivity test is BD-126's
  (`fmission_id_sensitivity`); this bead relies on it and does not repeat it.
- **World scope is fixed before candidates are tested.** Evidence recorded under one `MissionId` is never
  attached to another; an attempt (a stored answer offered for an amended world) is refused with 874 and routed
  to revalidation. The check is `admit::same_world(query: &AdmittedMission, stored: &AdmittedMission) ->
  Result<(), Refusal>` (DESIGN): it compares the canonical bytes of the two `world` fields and, when they
  differ, returns 874 with the pointer at the first differing field of `world` and the first repair of the
  registry's row for a changed scope (open a new query, or revalidate the stored answer). The callers are the
  places where stored evidence is offered: the driver's `--from` (N25a-12 step 7) calls it after the prefix
  check and before anything is loaded.

Determinism: admission is a pure function of the canonical bytes (class D0). Evidence: admission produces no
claim; a refusal is a result.

## Acceptance criteria

- [ ] The complete stance query (below) is admitted, classified `linear-static`, and echoed as
      "∃ policy per nominal design, ∀ worlds, ∀ executions".
- [ ] Each of the mutations in the test plan is refused with the stated code, pointer and first repair.
- [ ] Admission is a function of the semantic fields: two documents that differ only in `name`, `response` or
      `budget` yield equal `AdmittedMission` values (their `MissionId` is equal by BD-126's rule).
- [ ] A policy indexed by a hidden tolerance is refused (INV-AUGUR-07); `clairvoyant` is admitted only with the
      relaxation label, and the `AdmittedMission` of such a query is marked exclusion-only (property test over
      1,000 generated queries: the mark is set exactly when the kind is `clairvoyant`). That no inner cell can
      be built from a query so marked is tested on the kernel by N25a-03
      (`clairvoyant_relaxation_can_only_exclude`), which depends on this bead.
- [ ] Reachable through `frob mission check <file> --json` with exit 0 on admission and exit 3 on refusal;
      `scripts/e2e/mission_admit_semantic.sh` passes, with the log described below.

## Considerations

- OPEN-AUGUR-1 (whether predicates are written in the requirement language or reference its terms; owner the
  Arena lead; default: reference by identifier, one grammar). A predicate that embeds requirement syntax is
  refused until the question is decided.
- OPEN-AUGUR-11 (a standard measure on unresolved sets): default none; the caller supplies one.
- The plan does not say whether `name`, `response` and `budget` are excluded from the hashed bytes. The choice is
  BD-126's and is stated under Identity above: they are excluded, and per-call overrides also keep refinement
  under one id.
- A refusal here is cheap; an admitted ambiguous query is expensive. When a rule is uncertain, refuse.
- Refusal 856 has two raising sites: this bead's admission trigger (a document whose `evidence` asks for a
  joint paving or more than six split parameters), asserted from M1; and the region-certificate request at M4
  (the region-evidence beads). The registry row of 856 names both.
