## Background

**ADR-AUGUR-01: the answer to a design question is a pair of sets with proofs, never a score.** Reason: a score
cannot distinguish "this design fails" from "this search failed", and it cannot be reused after an edit without
re-running. Sets with per-cell proofs can. The public answer therefore carries I ⊆ F ⊆ O as a list of cells,
where F is the family of designs that satisfy the mission, I the inner set (each cell with a checked reason why
it works), and O the outer set (everything not excluded by a checked reason).

**ADR-AUGUR-08: answers are anytime.** Each decided cell is individually certified, so the answer at any moment
is a valid answer to "what is known under this budget". More work can only move cells out of the unresolved
set. **ADR-AUGUR-10: the weakest input sets the class.** An answer's class is the claim product of its cells'
classes: a cell proved by a certificate is `Certified`; a cell supported by replayed trajectories is `Tested`;
an empirical coverage statement is `Estimated`. No operation in `frob-mission` raises a class. Rejected
alternatives: one aggregate confidence for the answer (hides the weakest cell); mutable answers updated in
place (a citation could then change meaning under the reader).

The core types (`Cell`, `Verdict`, proof objects) come from BD-128. This bead makes them a public, addressable,
immutable artifact: what an agent reads, cites, pages through and refines.

## Scope

In: the `Answer` value and its JSON rendering inside the envelope's `result`; the construction-time invariants;
the address; refinement and withdrawal; the derived `outer` view; what empty lists mean.
Out: computing verdicts (BD-128 and the family beads); cost bounds (N25a-10); writing and checking the bundle
(BD-133, BD-132); the verbs that return or page the answer (BD-135).

## Technical approach

1. **Types** (DESIGN; fixes intent, not signatures):
   ```rust
   pub struct Cell { topology: TopologyId, chart: ChartId, bounds: Vec<Bound>,   // each end closed or open
                     units: Vec<Unit>, assumptions: AssumptionSet, policy_scope: PolicyScope }
   pub enum Verdict { Inner(Vec<ProofRef>), Excluded(Vec<ProofRef>), Unresolved(Vec<Explanation>) }
   pub struct Answer { mission: MissionId, cells: Vec<(Cell, Verdict)>, witnesses: Vec<Witness>,
                       cost: Option<CostBounds>, next_test: Option<NextTest>, claim: ClaimProduct,
                       bundle: BundleHash, refines: Option<AnswerId>, withdrawals: Vec<Withdrawal> }
   ```
2. **Rendering** (`result` of `frob.envelope/1`; every number an exact string): `mission_id`, `answer`,
   `inner`, `excluded`, `unresolved`, `witnesses`, `cost_bounds`, `next_test`, `certificate { bundle, kinds,
   checker }`, `assumptions`, `authorization`. A cell prints `cell`, `topology`, `chart`, `box`, `closed` (one
   Boolean per end), `policy` (`selectable-per-nominal-design` or `shared`) and `proofs`; an excluded cell adds
   `binding` (the binding constraint in words, with port and load vertex); an unresolved cell adds
   `explanation` and, where known, the competing explanations and its cheapest next test. `outer` is never
   listed: it is the domain minus the excluded cells, that is inner ∪ unresolved, and `Answer::outer()` derives
   it. Cells are serialized in a canonical order (topology, chart, then bounds lexicographically) so that the
   bytes are a deterministic function of the answer.
3. **What empty lists mean** (printed in `robot-docs` and enforced in report text): an empty `inner` means no
   certified witness so far; an empty outer set (the whole domain excluded) means the requested family is
   excluded under the declared model; a nonempty `unresolved` is work still to do. Probability mass of the
   unresolved set is reported only under a weighting of topology classes and continuous parameters that the
   caller supplied. In an empirical profile, sample coverage and confidence under a named population are
   separate fields and are never folded into cell geometry.
4. **Construction-time invariants** (`Answer::new` returns a `Refusal` on violation):
   - INV-AUGUR-02: the inner, excluded and unresolved cells partition the declared domain, with disjoint
     interiors and stated boundary ownership. Checked in exact box arithmetic per topology and chart: the union
     of the cells equals the domain box; two cells that share a face have complementary open and closed ends
     on it.
   - INV-AUGUR-05: `claim.class` equals the minimum class over cells; there is no setter.
   - INV-AUGUR-09: the `authorization` object is present with `execution_authorized`,
     `hardware_safety_signoff` and `sim_to_real_certified`, all `false`. The type has no value `true`.
   - Every inner or excluded cell has at least one `ProofRef`; every unresolved cell has an explanation.
5. **Address and immutability.** `AnswerId` is the BLAKE3 hash of the canonical answer bytes under the domain
   string `frob.mission.answer/1` (DESIGN name), printed `a:…`. An answer is written once to the Chronicle
   ledger and never changed.
6. **Refinement.** A later query with more budget produces a new answer whose `refines` names the old one.
   `fn check_refinement(old: &Answer, new: &Answer) -> Result<(), Refusal>` enforces INV-AUGUR-04 (answers are
   monotone in work): every inner cell of `old` is covered by inner cells of `new`; every excluded cell by
   excluded cells; cells may be split; an unresolved cell may become any mixture. The only exception is a
   **withdrawal**: `Withdrawal { cell, was: Inner | Excluded, counterexample, ledger_seq, cause }`, where
   `counterexample` is a checked proof or a replay address. A cell leaves I or re-enters O only through a
   logged withdrawal that names its counterexample; a new answer that silently changes a decided cell is
   refused.
7. **Evidence block of the envelope**: `class` (as above), `tier` (`static` for static exact answers; the
   lowest physics tier among inputs otherwise), `determinism` (`exact` for rational answers), `claims` (for a
   certified family answer: `["Proof"]`), `reality: "no-claim"`.

## Acceptance criteria

- [ ] The stance answer renders as: inner `c0` v ∈ [2, 14/3] closed at both ends; excluded `c1` v ∈ (14/3, 6]
      with `closed: [false, true]` and binding "rating at foot.pp under P = (60, 30) N*m"; no unresolved cell;
      class `Certified`, tier `static`, determinism `exact`; all three authorization flags `false`.
- [ ] A cell list with a gap, an overlap, or a shared face closed on both sides is refused at construction.
- [ ] An answer with one `Tested` cell among `Certified` cells has class `Tested`.
- [ ] The refinement of the tray answer (below) is accepted; a new answer that flips an inner cell without a
      withdrawal is refused; with a withdrawal naming a counterexample it is accepted and the log is printed.
- [ ] Two encodings of one answer on two hosts have identical bytes and the same `a:` address.
- [ ] `outer()` of the tray answer is {c:02, c:03, c:05, c:06}.

## Considerations

- OPEN-AUGUR-11: no measure on unresolved sets is standardized; `measure` in a `show` result appears only when
  the query's `resolution` names one.
- OPEN-AUGUR-8: whether the primitive equations of a bundle were reviewed is a flag of the bundle; the answer
  repeats it in `assumptions` when the bundle is unreviewed.
- A long answer is paginated and says so; it is never cut silently (the verb bead owns paging).
- A cell is described no more broadly than the fixture that qualified its lowering: the `assumptions` list
  names the authority model, what is observed before the decision, and the physical idealizations.
