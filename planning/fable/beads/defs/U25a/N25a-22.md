## Background

One plant gives opposite answers under two orders of the same quantifiers, and the public interface must keep
them apart. The plant is a one-axis pusher: y = max(0, g·u − d), with known build gain g ∈ G, command u ∈ U,
hidden gap d ∈ D, accepted when y ∈ Y. The per-build query asks for the designs for which some command works
for every gap; the shared query asks for the commands that work for every design and every gap. On
G = [1/2, 2], U = [0, 2], D = [0, 1/4], Y = [3/4, 5/4] the first returns the whole interval [1/2, 2] and the
second the empty set. This pair is a permanent regression test of the public interface, and it sits
permanently in the sealed suite of the ten-fold test as the quantifier-order fixture.

GATE-AUGUR-04 (claim type Known answer, M1, TARGET): the pusher battery returns 20 of 20 intervals with exact
ends, and the per-build and shared queries return [1/2, 2] and ∅ for the same plant. This script measures it
on the real binaries from the user's side.

## Scope

In: the script, the twenty generated queries, the six corrupted certificates, and the gate record. Out: the
lowering (BD-131); the prefix semantics (N25a-03); any timing claim.

## Technical approach

Script `scripts/e2e/mission_pusher.sh`. For each case it writes two `.fmission` files from one template (free
`g` with chart `inverse-gain` and box G; hidden `d` in D, `fixed-per-execution`; no observation; command
bounds U; accept atom "y in Y"): the per-build file has `indexed_by = "nominal-design"` and the prefix
∃ policy per nominal design, ∀ world; the shared file has `indexed_by = "family"` and the prefix ∃ policy for
the family, ∀ world.

Expected intervals (exact, closed ends):

| Case | G | U | D | Y | Per-build design set | Shared command set |
|---|---|---|---|---|---|---|
| `wide` | [1/2, 2] | [0, 2] | [0, 1/4] | [3/4, 5/4] | [1/2, 2] | ∅ |
| `shared-tight` | [1, 5/4] | [0, 2] | [0, 1/4] | [3/4, 5/4] | [1, 5/4] | [1, 1] |
| `weak-design` | [1/4, 2] | [0, 2] | [0, 1/4] | [3/4, 5/4] | [1/2, 2] | ∅ |
| `hidden-gap` | [1, 2] | [0, 2] | [0, 3/4] | [3/4, 5/4] | ∅ | ∅ |
| `zero-allowed` | [1/4, 1] | [1/2, 2] | [1/4, 1/2] | [0, 1/8] | [1/4, 3/4] | ∅ |
| `both-ends` | [1/2, 2] | [1, 3/2] | [0, 1/4] | [3/4, 5/4] | [2/3, 5/4] | ∅ |
| `singleton` | [1/2, 2] | [1, 1] | [0, 0] | [3/4, 3/4] | [3/4, 3/4] | ∅ |
| `branch-crossing` | [1/2, 1] | [0, 1] | [1/4, 1/2] | [0, 1/8] | [1/2, 1] | [0, 3/8] |
| `no-stroke` | [1/2, 2] | [0, 0] | [0, 0] | [1/2, 1] | ∅ | ∅ |
| `forced-overshoot` | [1, 2] | [1, 1] | [0, 0] | [0, 1/2] | ∅ | ∅ |

Steps.
1. Build `frob` and the standalone `frob-verify`.
2. For each of the 20 queries: `frob mission new`, `frob mission check` (assert the echoed prefix),
   `frob mission synthesize --json`. Assert the returned set: for the per-build query the inner cells' union
   with its `closed` flags; for the shared query the inner set (all of G or empty) and the witness's
   `command_set`. Assert that the excluded parts carry proofs and, for an empty answer, the stated reason.
3. Verify every bundle with `frob-verify`: accepted.
4. Corrupt the certificates of `wide`, `both-ends` and `shared-tight` in six ways (widened design interval;
   truncated design interval; overstated shared interval; a schedule that violates the hidden gap; a spurious
   empty per-build answer; a spurious empty shared answer) and submit each to `frob-verify`: all six
   rejected.
5. Prefix mismatch: submit the per-build bundle of `wide` as evidence for the shared mission of `wide`
   (`frob prove verify <bundle> --query q:shared`): rejected (the auditor's prefix rule), and the same offer
   through `frob mission synthesize --evidence` is refused with FROB-REF-881.
6. Controller mode: `frob mission refute wide.shared.fmission --policy u=1 --json` returns
   `refuted: "controller"` with the counterexample world g = 1/2, d = 1/4 (y = 1/4).
7. Run step 2 twice; compare result bytes.
8. Write the gate record: 20 of 20 intervals, the `wide` pair, and the controls caught.

## Acceptance criteria

- [ ] 20 of 20 intervals equal the table with exact ends and closedness; singletons print as closed cells
      with equal bounds.
- [ ] `wide` returns [1/2, 2] for the per-build prefix and the empty set for the shared prefix.
- [ ] Six of six corrupted certificates are rejected; the prefix mismatch is rejected by the auditor and
      refused by the verb.
- [ ] Every non-empty answer's bundle is accepted by the standalone auditor.
- [ ] A planted defect fails the script: a build whose admission normalizes the prefix (treating the shared
      query as per-build) returns [1/2, 2] for `wide` shared and the script exits non-zero.
- [ ] Two runs are byte-identical.

## Test plan

### Unit tests

None of its own; see BD-131 and N25a-03.

### End-to-end script and logging

This bead is the script. Log `target/e2e-logs/mission_pusher/<utc>.ndjson` through the helper of STD-E2E: per
query a `cmd` line (command, exit code, wall time, evidence block with class `Certified`, tier `static`,
determinism `exact`, mission and answer identities) and an `assert` line with expected and observed interval
ends; per corrupted certificate the auditor's rule; the refusal envelope of step 5 with code, pointer and
first repair; digests; a `summary` naming GATE-AUGUR-04.

### Known answers and negative controls

KA-628 (per-build [1/2, 2]; shared empty; the prefix ∀g ∃u offered for ∃u ∀g is rejected), KA-629 (ten frozen
cases, twenty intervals; six corrupted certificates, six of six rejected), CX-272. Each row is hand-checkable:
with A = L + d_max when L > 0 (else 0) and B = H + d_min, the per-build set is
[max(g_min, A/u_max), min(g_max, B/u_min)] and the shared set [max(u_min, A/g_min), min(u_max, B/g_max)].
Negative controls: the six corruptions; the prefix-normalizing build; the per-build bundle offered for the
shared query.

## Considerations

- No time is reported as a claim. The plan-time speed test on this battery had a ceiling of about 1.46 and
  measured 1.345; the ceiling rule forbids quoting a ratio from it.
- The battery's guard is decided by a fixture constant; passing it says nothing about plants with
  state-dependent event order.
