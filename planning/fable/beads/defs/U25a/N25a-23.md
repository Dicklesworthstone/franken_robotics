## Background

A mission query fixes a question about a family of robot designs: the design domain, the world family, what
the controller observes and when, the policy class, the horizon, the predicates, and the order of the
quantifiers. A wrongly posed query is the cheapest place to stop a wrong answer, so admission refuses rather
than guesses: no default quantifier prefix, no default persistence for hidden parameters, no observation
without an arrival instant, no policy indexed by something the controller cannot observe. Each refusal carries
a stable code, the offending field and ranked repairs, and an agent is expected to act on the first repair
without reading source code.

The crate-level tests show that the admission function refuses. This script shows that a user sees the
refusal correctly: the right exit code, one envelope on standard output, the code, the JSON pointer, the first
repair, and nothing published. It also runs, from the user's side, the catalogue of plausible shortcuts that
can be expressed as queries at the first milestone.

## Scope

In: one script, its mutated query fixtures, its log. Out: the admission rules themselves (N25a-02); the
certificate mutation corpus through the auditor (BD-136), which shares this script's log format.

## Technical approach

Script `scripts/e2e/mission_admission.sh`. Base fixtures: the stance query (free `v` = 1/half_width in
[2, 6]; 400 N; first-moment hull (±60, ±30) N·m; ratings 160 N; authority `independent-normal-force`; prefix
∃ policy per nominal design, ∀ world, ∀ execution); the pusher query (`wide`); a twenty-world two-stage
mission. Each case below is a single-field mutation of a base fixture, generated by the script.

| Case | Mutation | Expected |
|---|---|---|
| a1 | Stance, unchanged | `mission.check` exit 0; fragment `linear-static`; echo "∃ policy per nominal design, ∀ worlds, ∀ executions" |
| a2 | A number written as a JSON float (`"value": 3.0`) | exit 3, `FROB-REF-868`, pointer to the field, repair: the schema diff |
| a3 | Rational "6/4" | exit 3, 868, repair "3/2" |
| a4 | Free parameter without `chart` | exit 3, 868 |

| a7 | `quantifiers` removed | exit 3, 884 |
| a8 | An observation field with no arrival instant | exit 3, `FROB-REF-847`, repair: the instant at which it becomes usable |
| a9 | `policy_class.indexed_by` set to a fabrication tolerance | exit 3, `FROB-REF-887`, repair: move the parameter into the world, or add the calibration observation |
| a10 | Two decision makers | exit 5, `FROB-REF-724` |
| a11 | A cell asked with exact and empirical profiles together | exit 3, `FROB-REF-855`, repair: split the cell |

| a16 | Pusher `wide`: the per-build proof offered as evidence for the shared query | exit 3, `FROB-REF-881`, repair: the prefix it does establish |
| a17 | A minimum claimed with a positive gap (an imported cost claim) | exit 3, `FROB-REF-853`, repair: `feasible-candidate` with its gap |
| a18 | Midpoint shortcut: feet at (±1 − e, ±1) m capped at 1/2 N, loads (e, W) = (0, 19/10) and (9/10, 1) admitted; the midpoint (9/20, 29/20) queried | excluded (841/800 N needed from a pair capped at 1 N); no convexity-based inner cell |
| a19 | Sample-point exclusion: stance cell v ∈ [4, 6] with a paving of one cell | the cell is unresolved (`straddles-threshold`), never excluded |
| a20 | Slot for refusal 877 (predicates conflict with the world family for every design) | recorded `due` until its mechanism lands |

For every refused case the script asserts: exactly one envelope on standard output with `ok: false`; the exit
code; `refusal.code`; `refusal.pointer` equal to the mutated field's JSON pointer; a non-empty ranked
`repairs` list whose first entry matches; `retry` is `after-change`; no `mission_id` is stored for malformed
documents and no answer address is created for any refused run (checked with `frob mission show`); the ledger
gains no answer record. For every case the registry entry of the verb lists the code raised.

Identity checks, in the same script: the stance `MissionId` changes under each of seven mutations (a
quantifier, a comparator, the world hull, a persistence declaration, an observation arrival, the policy class,
the horizon) and is unchanged when keys are reordered and whitespace is altered.

## Acceptance criteria

- [ ] All cases a1 to a19 produce the expected exit code, refusal code, pointer and first repair.
- [ ] No refused run leaves a stored answer; malformed documents leave no stored mission.
- [ ] Seven identity mutations change `MissionId`; two canonical-form variations do not.
- [ ] A planted defect fails the script: a build whose admission defaults a missing persistence to `resampled`
      passes a6 silently and the script exits non-zero.
- [ ] The same cases run over MCP (`mission_new`, `mission_check`, `mission_synthesize`) return the same
      envelopes with `isError: true` for refusals (the parity half, run when the MCP tools exist).

## Test plan

### Unit tests

None of its own; see N25a-02, N25a-03, N25a-08, N25a-11.

### End-to-end script and logging

This bead is the script. Log `target/e2e-logs/mission_admission/<utc>.ndjson` through the helper of STD-E2E:
per case a `cmd` line with the exact command, exit code and wall time; a `refusal` line with code, pointer,
observed and required values and the first repair; an `assert` line with expected and observed; for a15 a
`metric` line with the exact fraction; a final `summary` with counts and the gate GATE-AUGUR-01 (admission
half).

### Known answers and negative controls

KA-627 (midpoint: 841/800 N), KA-628 (pusher prefixes), KA-630 (persistent gain), KA-631 (twenty worlds:
18/20, 19/20, 0.9025 under independence). CX-270, CX-272, CX-275, CX-276. Negative controls: the
persistence-defaulting build; a build that reorders the echoed prefix; a build that accepts a float. Each must
make at least one case fail.

## Considerations

- GATE-AUGUR-01 asks for a mutation corpus of at least 60 mutated queries and certificates with zero false
  accepts; this script contributes the query half (19 cases plus 7 identity mutations) and the corpus bead
  the certificate half.
- Refusal text is part of the agent contract; changing a message is allowed, changing a code or a pointer is a
  registry change.
- Two numbering layers exist for some defects (the mission family's 881 and the auditor's 826): the verb
  reports the mission code and names the auditor's rule in `observed`.
