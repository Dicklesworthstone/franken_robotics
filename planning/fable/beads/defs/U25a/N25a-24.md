## Background

A mission answer is anytime: each decided cell of the design domain is certified on its own, so what is known
when a budget runs out is still a valid answer. The verbs therefore return the certified cells and the
unresolved remainder at a budget stop, where every other verb of the tool publishes nothing partial. That
exception is safe only if three things hold from the user's side: no unresolved cell is ever printed as a
verdict; a stop before the first checked cell publishes nothing; and a later run with more budget refines the
earlier answer without changing any decided cell. This script measures those properties on the real binaries,
together with the cost estimate, the job path and cancellation.

The fixture is a two-parameter stance query small enough to check by hand. A quadruped holds a 160 N loaded
tray on four feet at (±1/5, ±1/v) m; the first moment of the load ranges over (±16, ±12) N·m; each foot is
rated at 88 N; each knee holds (1/10 m)·f ≤ r·4 N·m, with belt ratio r. Free parameters: v ∈ [4, 12] per
metre and r ∈ [1, 5/2]. Every balanced allocation has f₊₊ − f₋₋ = 40 + 6·v at the vertex (16, 12), so a
design is feasible exactly when 40 + 6·v ≤ min(88, 40·r), that is v ≤ 8 and r ≥ 1 + 3·v/20. The objective is
the narrowest body (minimize 1/v) and the declared resolution is an unresolved area fraction of at most 1/4.

## Scope

In: the script, the fixture `tray-stance-and-knee.fmission`, the log. Out: the mechanisms (BD-135, N25a-05,
N25a-10, N25a-12); MCP parity of the same flows (the MCP generation bead's script).

## Technical approach

Script `scripts/e2e/mission_budget_stops.sh`, run against a daemon started in a temporary state root.

1. `frob mission new tray-stance-and-knee.fmission`; `frob mission check`: fragment `linear-static`.
2. **Estimate.** `frob mission synthesize q:… --estimate --json`: assert four cost lines (admission,
   lowering, proposing, checking) with intervals; assert no job, no answer and no ledger write were made.
3. **First pass.** `frob mission synthesize q:… --paving v:4,r:3 --json`. Assert the twelve cells:

   | Cells | v | r | Verdict |
   |---|---|---|---|
   | c:01 | [4, 6] | [1, 3/2] | excluded (knee: 64 > 60 at (4, 3/2)) |
   | c:02 | [4, 6] | (3/2, 2) | unresolved, `straddles-threshold` |
   | c:03 | [4, 6] | [2, 5/2] | inner (76 ≤ 80 at (6, 2)); witness (76, 44, 40, 0) N at v = 6, r = 2 |
   | c:04 | (6, 8] | [1, 3/2] | excluded |
   | c:05, c:06 | (6, 8] | (3/2, 2) and [2, 5/2] | unresolved |
   | c:07 to c:12 | (8, 12] | all | excluded (rating) |

   Assert: exit 0 (unresolved area 3/12 meets the resolution 1/4); `cost_bounds` incumbent "1/6", lower
   bound "1/8", `attained: false`, gap "1/24"; the warning that the claimed minimum is not established;
   `next_test` "split cell c:06 at r = 11/5"; class `Certified`.
4. **Resolution unmet.** The same call with `--set resolution.max_unresolved.value=1/8`: exit 2 and the flag
   `resolution-unmet`; the cells are the same.
5. **Budget before the first cell.** `--budget checker_s=0`: exit 4, `FROB-REF-702`, no answer address.
6. **Budget mid-run.** A budget that allows the excluded cells and not the inclusion (set through the
   test-only cost scale of the daemon so that it is deterministic): the answer lists the excluded cells with
   their proofs and c:03 as unresolved with `BudgetExhausted`; no cell appears in two lists; exit 2.
7. **No unresolved cell as a verdict.** For the outputs of steps 3, 4 and 6, in JSON and in the text
   rendering: no unresolved cell identifier appears under `inner` or `excluded`, in `binding`, or in a
   sentence of `next_actions` that asserts feasibility or infeasibility.
8. **Refinement.** `frob mission synthesize q:… --from a:<first> --json`: c:06 is split at r = 11/5 into
   c:06a = (6, 8] × [11/5, 5/2], inner with witness (88, 32, 40, 0) N at v = 8, and c:06b = (6, 8] ×
   [2, 11/5), unresolved; `refines` names the first answer; `cost_bounds` becomes "1/8", "1/8",
   `attained: true`, gap "0"; every cell decided in the first answer has the same verdict.
9. **Job path.** `--sync-wait-ms 0`: exit 8 with a job handle whose progress has a denominator; then
   `frob job wait`; the final `result` bytes equal those of step 3.
10. **Cancellation.** Start the run with a slowed proposer (test-only), cancel after the first progress
    event: the returned answer contains the cells checked so far; no job, lease or temporary file remains.
11. **Paging.** `frob mission show q:… --answer a:… --set outer` returns c:02, c:03, c:05, c:06 with the
    definition "domain minus excluded cells" and area fraction 1/3; `--set excluded --page-size 3` returns
    each of the eight excluded cells exactly once across pages.
12. **Repeat** steps 3 and 8 and compare bytes.

## Acceptance criteria

- [ ] Steps 2 to 12 pass on a clean checkout; exit codes are 0, 2, 4, 2, 8 where stated.
- [ ] A budget stop returns certified cells and the unresolved remainder, each cell complete in itself, and no
      unresolved cell is printed as a verdict in any output form.
- [ ] The refinement changes no decided cell and closes the gap from 1/24 to 0.
- [ ] Job and synchronous paths return identical bytes; cancellation leaks nothing.
- [ ] Planted defects fail the script: a build that returns exit 0 when the resolution is unmet; a text
      renderer that lists an unresolved cell under "excluded"; a refinement that flips c:03.

## Test plan

### Unit tests

None of its own; see BD-135 and N25a-12.

### End-to-end script and logging

This bead is the script. Log `target/e2e-logs/mission_budget_stops/<utc>.ndjson` through the helper of
STD-E2E: per command the exact line, exit code, wall time and evidence block; per answer the per-list cell
counts, the flag set, `cost_bounds` as `metric` lines with units, the answer and bundle digests; for the
verdict scan the offending text on failure; for cancellation the outstanding work at the request and the
observed latency; a final `summary`.

### Known answers and negative controls

The cell table is the plan's worked artifact for this query and is exact: one inner, three unresolved, eight
excluded on the first pass; after the split, incumbent and lower bound meet at 1/8 m. Negative controls: the
three planted defects above. Chaos (tier G4): kill the daemon between the bundle check and the answer write,
restart, and recover by idempotency key: one answer or none exists. Determinism lanes: twice on one machine;
worker counts 1 and 8.

## Considerations

- The mid-run budget case needs a deterministic cost model; the test-only cost scale is a daemon option that
  exists only in test builds and is named in the log.
- The plan's worked session shows exit codes for these two calls that differ from the stated rule; the rule
  (exit 2 only with a flag such as `resolution-unmet`) is what this script asserts.
