## Background

Ground is the subsystem that compares simulation with reality (crate `frob-ground`). Nothing in the project
has been compared with a physical robot, so every report prints `reality: no-claim` until measured data
supports something else. The admission lane (BD-387) is where the first real dataset would land: a real
dataset is a `.frun` episode bundle whose manifest (`frob.ground.dataset/1`) declares `origin = "real"`, its
licence, provenance and rights, every instrument's uncertainty, its clocks, the **cell** it belongs to
(design, hardware units, controller, firmware, surface, task family, envelope of recorded conditions), and a
split into calibration, validation and holdout parts by hardware, condition or day. Validation and holdout
parts are **sealed** at admission: their chunk hashes are committed in the ledger and the chunks move to a
store area whose only read path takes a score token, minted for one prediction that was frozen before the
read. Three decisions make this necessary: Ground is file-in, file-out and never touches a device; a
calibration band belongs to exactly one cell; and a prediction is frozen before its trial data is readable,
because otherwise a comparison is a fit with an unknown error rate.

The verb is `ground.ingest` (kind mutate; capability `ground:write`; idempotency key):
`frob ground ingest <bundle> --design d:… --task-family tf:… --json`. This script is its end-to-end test from
the user's side, on data labelled `synthetic` throughout: it shows that a complete dataset is admitted with
the right identities and commitments, that each incomplete or malformed one is refused with its code and the
missing fields, and that a sealed part cannot be read by any route before a prediction is frozen. No gate is
attached to the admission bead; the script supplies the first of the three protocol mutations that the later
gate on frozen predictions requires (read before freeze).

## Scope

In: the script; a minimal generator of synthetic bundles and their mutations; every refusal of admission;
every read path against a sealed part; idempotency; the kill-and-recover case. Out: admission itself and its
unit tests (BD-387); clock fitting; the planted-parameter rehearsal (BD-388); freezing predictions, scoring
and holdout retirement (BD-392); scans and as-built data.

## Technical approach

Script `scripts/e2e/ground_ingest.sh [--seed S] [--controls]`. It starts `frobd` on an empty store, uses only
the `frob` binary, and writes its bundles under `target/e2e-work/ground_ingest/`.

**The base bundle** (written by `cargo run -p frob-conformance --bin ground-synth -- emit --seed S`): origin
`synthetic`; kind `robot-log`; licence `CC-BY-4.0`; `acquired = { by, on, rights }`; one unit `unit-07`; a
controller identity, firmware `2.4.1`, surface `sealed-concrete/dry`, envelope (temperature 18 to 24 °C,
payload 0 to 2 kg, speed 0 to 1.2 m/s); three instruments, each with `sigma`, `bias_bound`, an instant and a
clock; two clocks with marks; `split.by = "day"` with two calibration days, one validation day and one
holdout day; `sealed = ["validation", "holdout"]`; `attempts = "all"` with a trial counter of 20 and 20 rows,
three of them aborted trials.

Steps.
1. **Admission.** `frob ground ingest base.frun --design d:… --task-family tf:… --json`. Assert: exit 0; the
   result's `dataset` equals the BLAKE3 identity recomputed by the script over the canonical manifest and the
   ordered chunk hashes; `cell` has all seven components; `origin = "synthetic"`; `split` counts per part and
   the two sealed parts; `sealed_commitment` is a ledger sequence; `reality` is unchanged (`no-claim`).
   The dataset's evidence closure (`frob evidence trace <dataset>`) contains one `ground.sealed` ledger event
   per sealed part, with the chunk hashes.
2. **Idempotency.** Repeat with the same idempotency key: the original receipt is returned, no new ledger event
   is written. Repeat with a new key and the same bundle: the same dataset identity, refused or returned as
   already admitted, and the sealed parts are not re-opened.
3. **Refusals of admission.** For each mutation of the base bundle, assert the exit code of the refusal class,
   the code, the offending or missing fields and the first repair in the envelope:

   | Mutation | Expected |
   |---|---|
   | `license` removed | `FROB-REF-873`, missing `dataset.license` |
   | `acquired.rights` removed | 873, missing field named |
   | one instrument without `sigma`; one without `bias_bound` | 873 each |
   | `rig.units` removed; controller removed; firmware removed; surface removed; envelope removed | 873 each, "no declared cell", the missing component named |
   | `--design` omitted; `--task-family` omitted | 873 each, the missing cell component named |
   | `split.by = "rows"` | refused: splits follow hardware, condition or day |
   | validation and holdout sharing one day | refused: overlapping split |
   | an episode whose day is in no part | refused: unassigned episode |
   | trial counter 20 with 17 rows | refused: the denominator is incomplete (a band on survivors) |
   | one byte of one chunk changed | refused: chunk digest mismatch |
   | `origin` edited to `"real"` in the manifest without re-hashing | refused: the dataset fails its hash |
   | a second dataset with firmware `2.4.2` pooled with the first for one band | `FROB-REF-814`; repair "separate the pools" |
   | the bundle carrying the private mark, ingested into a non-private scope | the private-scope refusal; in a private scope it is admitted and `private: true` is inherited |

4. **Sealed reads without a frozen prediction.** Attempt to read a validation chunk and a holdout chunk by
   every route: `frob artifact read`, `frob run export`, a telemetry query over the dataset, the viewer's
   chunk endpoint through the daemon, and the store's direct read call (through the conformance binary).
   Assert for each: `FROB-REF-883`, exit 3, a first repair that names "register a new prediction version", no
   bytes of the chunk in the response, and one logged refusal event in the ledger per attempt.
5. **Freeze before read.** With a prediction record frozen at ledger sequence s₁ (from `frob ground predict`
   when BD-392 has landed; otherwise this step is recorded `not run`), `frob ground score` reads the sealed
   chunk at sequence s₂; assert s₁ < s₂ and that the sealed commitment's sequence precedes both. Then freeze a
   prediction after a refused read attempt of step 4 and assert that it does not retroactively license that
   attempt (the refusal event stays in the ledger).
6. **No device input or output.** `cargo tree -p frob-ground` lists no network, serial or bus crate, and an
   ingest run under a sandbox that denies sockets succeeds.
7. **Cancellation and crash.** Cancel an ingest mid-sealing: no partially sealed part remains. Kill the daemon
   during sealing and restart: either no commitment exists or a complete one does (tier G4, chaos).
8. **Controls (`--controls`).** Conformance-only builds on which the script must exit non-zero: a store with
   the sealed-area guard disabled (step 4 returns bytes); a manifest validator that accepts `by = "rows"`
   (step 3); an ingest that does not check the trial counter.
9. **Determinism.** Run steps 1 and 3 twice on fresh stores: identical dataset identity, cell key, refusal
   payloads and result bytes (admission is a pure function of the bundle and the call, class D0).

## Acceptance criteria

- [ ] The base bundle is admitted with the recomputed identity, a complete cell key, two sealed parts and a
      ledger commitment; `reality` stays `no-claim` and `origin` stays `synthetic`.
- [ ] A dataset with no declared cell is refused, each missing component named (the seed bead's first
      condition), for all seven ways of leaving a component out.
- [ ] A read of a sealed part before a prediction is frozen is refused with 883 on all five read routes, and
      each attempt is in the ledger (the seed bead's second condition).
- [ ] Each mutation in the table of step 3 is refused with the stated code and fields.
- [ ] Ingesting twice with one idempotency key changes nothing.
- [ ] Each of the three control builds makes the script exit non-zero.
- [ ] The log contains identities, counts, codes and ledger sequences, and no dataset content.

## Test plan

### Unit tests

None of its own; admission's tests are in BD-387 (`crates/frob-ground/tests/admission.rs`). The synthetic
bundle generator has two tests in `frob-conformance`: `ground_synth_bundle_is_schema_valid` and
`ground_synth_mutations_change_exactly_one_field`.

### End-to-end script and logging

This bead is the script. Log `target/e2e-logs/ground_ingest/<utc>.ndjson` through the helper of STD-E2E, with
a transcript beside it. Per command a `cmd` line (exact command, exit code, wall time, the envelope's evidence
block: class, tier, determinism, the dataset and cell identities, seed; the `reality` line). Per refusal a
`refusal` line with the code, the missing or offending fields and the first repair. Per sealed-read attempt:
the route, the code, and the ledger sequence of the logged refusal. For step 5 `metric` lines with the three
ledger sequences and the assertion commitment < freeze < read. On failure: the first mutation whose outcome
differs and the path of its bundle. Final `summary`: assertions passed and failed, steps recorded `not run`,
and no gate. Chunk contents, instrument samples and operator identifiers never enter the log; a bundle with
the private mark is logged by digest only.

### Known answers and negative controls

The protocol row of the synthetic rehearsal: a read before freeze, a refit without a new version, and a reuse
of a scored holdout are each refused; the first is asserted here and the other two belong to the scoring
bead. Identity known answer: changing one byte of one chunk changes the dataset identity. Negative controls:
the three control builds of step 8; the relabelled-origin bundle; the 17-of-20 bundle. Determinism lanes:
twice on one machine; debug and release. Chaos lane (G4): the kill during sealing.

## Considerations

- The lane may never see real data before release (no public paired dataset with enough robots per class was
  identified, and the default is that no bench hardware is acquired). That is a legitimate state: the script
  then remains the lane's only exercise, and every artifact it produces says `synthetic`.
- The plan's verb table gives `ground.ingest` a first milestone of M1 "for admission and the `reality:` line"
  while the admission bead is at M5; at M1 only the report line exists and this script has nothing to admit.
- The registry has no code narrower than 873 for "no declared cell", and none for the split and denominator
  refusals; the script asserts the code where one exists and the refusal's field list otherwise, and will
  tighten when codes are assigned.
- The five read routes are the ones that exist at M5. A read route added later must be added to step 4; a
  route missing from the list is how a sealed-data leak would go unseen.
- Licence joins and the private mark decide what may later enter a replication kit; there is no override, and
  the script never copies a private bundle outside its scope.
