## Background

A mission query asks which designs of a family satisfy a mission, and the answer is a list of cells of the
design domain D, each inner (proved to work), excluded (proved unable to work) or unresolved. The inner set I
and the outer set O (the domain minus the excluded cells) enclose the true feasible family F: I ⊆ F ⊆ O.
Answers are anytime (decision ADR-AUGUR-08): each decided cell is certified on its own, so the answer at any
moment is a valid answer to "what is known under this budget", and unknown is a verdict of its own
(ADR-AUGUR-07).

That makes one answer always available and always worthless: every cell unresolved, I empty and O the whole
domain. It is the **vacuous enclosure**, and it is true of every mission. A caller therefore states in the
query how much must be decided before the answer is good enough for the decision at hand. The `.fmission`
field `resolution` holds two things: `max_unresolved`, the largest unresolved set the caller will accept in a
stated measure, and `mandatory`, a subset of the obligations `interior`, `exterior` and `boundary`. The rule
attached to the field is: **a vacuous enclosure cannot satisfy a mandatory obligation.**

The field has consumers that need one precise definition: a budget stop returns exit 0 when the unresolved set
satisfies `resolution` and exit 2 with the flag `resolution-unmet` when it does not; progress events report
decided and unresolved measure; `mission.show` prints a measure only when the query names one. Two queries of
the plan fix the examples. The stance query asks for
`{ "max_unresolved": { "measure": "interval-length", "chart": "v", "value": "0" }, "mandatory": ["interior",
"exterior", "boundary"] }` and is met by one closed inner cell and one half-open excluded cell with nothing
unresolved. The tray query asks for `{ "measure": "area-fraction", "chart": "v, r", "value": "1/4" }` with
`["interior", "exterior"]` and is met by a first pass with one inner cell, eight excluded and three unresolved
of twelve equal cells.

DESIGN and its reason: the plan names the field, the two measures and the rule, and leaves the meaning of the
three obligations to be fixed. This bead fixes them in the weakest form that makes the rule true, so that an
answer cannot be reported as sufficient while saying nothing about the question the caller marked as required.
Rejected: a built-in default measure (there is no canonical measure on a design domain: volume depends on the
chart, and a probability mass on a prior the caller has not given; this is the fail-closed default of
OPEN-AUGUR-11); treating `mandatory` as advisory (then "sufficient" would depend on the reader).

## Scope

In: the `Resolution` type's semantics; the measures; the three obligations; the report attached to an answer;
the function the budget-stop rule calls; the admission checks on the field. Out: the exit codes themselves and
the envelope (BD-135); the driver that decides cells (N25a-12); cost claims and their gap (N25a-10), which are
a separate obligation.

## Technical approach

1. **Types** (DESIGN; in `frob_mission::answer`):
   ```rust
   pub struct Resolution { max_unresolved: Option<MeasureBound>, mandatory: BTreeSet<Obligation> }
   pub struct MeasureBound { measure: Measure, value: Ratio }          // value ≥ 0, exact
   pub enum Measure { IntervalLength { chart: ChartId },              // absolute, in the chart's unit
                      AreaFraction { charts: [ChartId; 2] },          // share of the domain box in two charts
                      VolumeFraction { charts: Vec<ChartId> },        // the same for three or more (DESIGN)
                      Mass { weighting: WeightingId } }               // only under a caller-supplied weighting
   pub enum Obligation { Interior, Exterior, Boundary }
   pub struct ResolutionReport { met: bool, unresolved: Option<Ratio>, bound: Option<Ratio>,
                                 obligations: Vec<(Obligation, Discharge)> }
   pub enum Discharge { ByCells(Vec<CellId>), ByWholeDomain, NotDischarged(&'static str) }
   ```
2. **Measuring the unresolved set.** Cells have disjoint interiors (invariant INV-AUGUR-02), so the measure of
   the unresolved set is the sum over unresolved cells, in exact rationals:
   - `interval-length`: the length of the cell's interval in the named chart; a singleton has length 0. The
     query must have exactly one free parameter in that chart.
   - `area-fraction` and `volume-fraction`: the product of the cell's side lengths in the named charts divided
     by that of the domain box; the named charts must be exactly the free parameters. Open and closed ends do
     not change the value.
   - `mass`: the caller's weighting over topology classes and continuous parameters, integrated over the cell
     by the weighting's own exact rule; without a weighting the request is refused at admission with
     `FROB-REF-855` (first repair: supply the weighting).
   - Several topologies: a length, area or volume bound applies to each topology's sub-domain separately (the
     worst topology decides); only a mass may add across topologies.
   - A cell whose lowering does not exist at this build is unresolved and counts in full.
3. **The measure bound** is met when no `max_unresolved` is given, or when the unresolved measure is at most
   `value`.
4. **The three obligations** (each either discharged with the cells that discharge it, or not):
   - `interior` (what works is exhibited): discharged by at least one inner cell, or by the whole domain being
     excluded (the answer to "which designs work" is then "none", proved). Not discharged while `inner` is
     empty and any cell is unresolved: an empty inner list is the vacuous inner enclosure.
   - `exterior` (what cannot work is exhibited): discharged by at least one excluded cell, or by the whole
     domain being inner. Not discharged while `excluded` is empty and any cell is unresolved: O = D is the
     vacuous outer enclosure.
   - `boundary` (the frontier between the two is located): discharged when `interior` and `exterior` are both
     discharged and the unresolved set meets the measure bound, with one tightening: when the bound is 0, or
     no bound is given, there must be no unresolved cell at all, so that every frontier point is owned by a
     decided cell through its `closed` flags. A singleton left unresolved has length 0 and still fails this
     obligation. A domain that is wholly inner or wholly excluded discharges it (no frontier lies inside).
   Consequence, which is the rule of the field: an answer with no decided cell discharges none of the three,
   whatever `max_unresolved` says. A bound generous enough to accept the entire domain as unresolved waives
   nothing that `mandatory` lists.
5. **The report.** `met` is true exactly when the measure bound is met and every obligation in `mandatory` is
   discharged. The report is a pure function of an answer's cells and the query's `resolution`,
   `ResolutionReport::of(answer: &Answer, r: &Resolution) -> ResolutionReport` (DESIGN): it adds no field to
   the stored answer, whose bytes and address (N25a-05) this bead leaves unchanged, and it needs neither the
   driver nor a lowering. The verb calls it whenever it returns an answer (worklist empty, budget stop or
   cancellation) and renders it in `result.resolution`; when `met` is false the envelope carries the flag
   `resolution-unmet` (BD-135, which depends on this bead). Each undischarged obligation names what would
   discharge it, and the report names the unresolved cell whose decision would change it soonest: the largest
   unresolved cell under the query's measure, ties in canonical order (DESIGN: the same cell stands at the head
   of the driver's worklist, N25a-12, whose default order is larger measure first, so the report and the
   answer's `next_test` agree when no cost gap is open; a choice by static margin would need a lowering, which
   this function does not have).
6. **What it does not do.** It never changes a verdict, never converts unresolved into either verdict, and never
   stops work on its own: a caller (the verb's loop, BD-135) may stop early when the report is met and no cost
   gap is open, because the caller of the query declared that sufficient, and the cells still unresolved keep
   their explanations and next tests.
   Meeting `resolution` says nothing about a claimed minimum: `minimum-with-matching-lower-bound` is closed by
   the cost bounds, and an answer can meet its resolution while its cost claim is still `feasible-candidate`.
7. **Admission checks on the field** (called from semantic admission): a measure whose charts do not match the
   free parameters, a negative bound, or an unknown obligation name is refused with `FROB-REF-868` and a schema
   diff; a `mass` without a weighting with 855. `resolution` is part of the mission document and so of
   `MissionId`; overriding it for one call with `--set resolution…` creates a different mission identity and is
   echoed as such.
8. **Refinement.** By the invariant that answers are monotone in work (INV-AUGUR-04), the unresolved measure of
   a later answer to the same mission never exceeds that of an earlier one, and a discharged obligation stays
   discharged unless a logged withdrawal removes the cell that discharged it; the report of a refining answer
   is checked against its parent's on both counts.

Determinism: exact rational arithmetic on the answer's cells (class D0). Evidence: the report is a statement
about the answer, not a claim about the robot; it has no class of its own.

## Acceptance criteria

- [ ] Stance query (one free chart v ∈ [2, 6], bound 0 by `interval-length`, all three obligations): the exact
      answer [2, 14/3] inner and (14/3, 6] excluded is met; the same answer with (14/3, 5] left unresolved is
      unmet on the bound and on `boundary`; with only the point v = 14/3 unresolved it meets the bound (length
      0) and is still unmet on `boundary`.
- [ ] Tray query (charts v, r; twelve equal cells; `area-fraction` 1/4; `interior` and `exterior`): one inner,
      eight excluded, three unresolved is met with unresolved measure 3/12; with the bound 1/8 it is unmet.
- [ ] An answer with every cell unresolved is unmet for each of the three obligations taken alone, for any
      bound including 1 (the whole domain).
- [ ] A wholly excluded domain discharges all three obligations with `ByWholeDomain`; so does a wholly inner one.
- [ ] `mass` without a weighting is refused with 855; mismatched charts, a negative bound and an unknown
      obligation with 868.
- [ ] A refining answer never has a larger unresolved measure than its parent, and loses a discharged
      obligation only through a logged withdrawal.
- [ ] `ResolutionReport::of` is the one predicate: `met` decides between exit 0 and the flag
      `resolution-unmet`, and nothing else in the crate computes sufficiency. (That the budget-stop rule of the
      mission verbs reads it is BD-135's acceptance and N25a-24's script, both built on this bead.)
- [ ] `scripts/e2e/mission_resolution.sh` passes, with the log described below.

## Considerations

- OPEN-AUGUR-11 (owner: the Augur lead; blocks nothing): whether a measure on unresolved sets should be
  standardized as a volume in a named chart. Default, implemented here: no built-in measure; the caller
  supplies one, and probability mass is reported only under a supplied weighting. If a standard measure is
  later chosen it becomes one more `Measure` variant and no existing query changes meaning.
- OPEN-AUGUR-7 (owner: the Tether lead): the exit code of a budget stop with certified cells. Default: exit 2
  with `resolution-unmet`. This bead supplies the predicate; the code is one table entry elsewhere.
- The meanings of `interior`, `exterior` and `boundary` are this bead's reading of a one-line rule. They are
  written in the crate's contract so that a caller can see what "sufficient" will mean before spending a
  budget; a different reading is a schema-visible change (a new obligation name), not a silent one.
- `volume-fraction` is added for domains of three or more free charts; the plan's two examples use
  `interval-length` and `area-fraction` only. A fraction of volume in a chart is not a probability and is never
  printed as one.
- Meeting a resolution is not a statement of quality: a query that asks for little is satisfied by little, and
  the report says exactly what was asked.
