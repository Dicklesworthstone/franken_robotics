## Background

A certificate that only its producer can read is not evidence. The `.frobcert` bundle (schema `frob.cert/1`,
canonical JSON, format identifier FMT-FROBCERT, one self-contained file) is everything needed to re-check one
claim on a machine that has neither the agent, a GPU nor the simulator. The offline auditor `frob-verify`, built
from the crate `frob-cert` with the standard library alone, reads the bundle and recomputes the argument from the
primitive equations inside it. This bead closes the first complete loop at M0: the three kernel certificates
produced with FrankenSymPy (card T-01: the Cayley map of a skew-symmetric matrix is a rotation; T-03: the
quaternion update preserves the norm; T-04: the adjoint composes) are written as bundles, replayed by the auditor,
and exposed through three verbs. Tier: Solid. Subsystem: Lemma. It serves BET-11 (proof-carrying kernels) and
delivers the offline half of GATE-LEMMA-00, which also closes the admission gate INT-FSYM-01 (the derivation annex
builds against the FrankenSymPy crates by path, derives the Cayley step kernel, and its certificate replays in the
offline auditor).

The division of labour is fixed (ADR-WS-02, and the settled open question OPEN-AUGUR-6): `frob-cert` defines and
reads the format and holds one checker per proof kind; `frob-lemma` writes bundles against the schema and shares
no code with the reader; `frob-verbs` exposes the check. A producer never calls the auditor's decision code to
construct a witness, so the two share a format and nothing else (INV-LEMMA-05). The registry of proof kinds
`frob.cert.kinds/1` is closed and versioned, and an unknown kind is rejected even when every hash is consistent
(ADR-LEMMA-04; doctrine D-11: a hash identifies bytes and never validates an argument).

Rejected alternatives. (1) Ship FrankenSymPy's own capsule as the portable artifact: the auditor would then need
FrankenSymPy, and the dependency count must stay zero; the capsule consumer is kept as a second opinion inside the
conformance crate only. (2) Let the auditor call the producer's normal-form code: one defect would make both
agree. (3) A binary format: a reviewer must be able to read the equations that were proved.

## Technical approach

1. Writer (`crates/frob-lemma/src/bundle/kernel.rs`, DESIGN). Input: an `InstanceCertificate` (the claim, the
   FrankenSymPy checker reference and the witness). Output: one `.frobcert` file with these fields:
   `schema` = `frob.cert/1`; `claim` = `{kind: "kernel-identity", class: "Certified", quantifiers: [], horizon:
   "none"}`; `query` = the BLAKE3 digest and canonical bytes of the statement (the kernel content hash and the
   identity text); `definitions` = units and symbol table of the kernel's program; `assumptions` = the side
   conditions (for T-01, "4 + ω₁² + ω₂² + ω₃² ≠ 0", with its justification); `plant` = the kernel identifier and
   the program digest; `domain` = "all values of the program's inputs over ℚ"; `proof` = `{kind, version,
   primitive_equations, payload}`; `checker` = the auditor name and the protocol version targeted;
   `expected_verdict` = `accept`; `lineage` = a Merkle root equal to the bundle's own leaf for a single claim;
   `authorization` = the three no-authorization flags, all `false`. The writer serializes with the producers'
   canonical writer (keys sorted by code point, exact numbers as strings) and never imports `frob-cert`.
2. `poly-identity` (checker in `crates/frob-cert/src/kinds/poly_identity.rs`). Payload: a variable list; `lhs`
   and `rhs` as expression DAGs with nodes constant (exact rational), variable, sum, product, negation and
   nonnegative integer power; optional `relations` (polynomials that are zero by hypothesis, for example
   t² − radicand, or the entries of RᵀR − I) with `cofactors`, one polynomial per relation.
   Checking rule: (a) expand `lhs`, `rhs`, every relation and every cofactor to sparse normal form (a map from
   exponent vectors to nonzero rational coefficients); (b) compute lhs − rhs − Σᵢ cofactorᵢ·relationᵢ; (c) accept
   only if the result is the zero polynomial; (d) every relation must be listed among the bundle's assumptions
   with its text, otherwise reject with a missing-side-condition rule; (e) terms above the declared limits
   (DESIGN: 10⁶ terms, total degree 256, 16,384-bit coefficients) give `limits.exceeded`. With no relations the
   rule is plain normal-form equality over ℚ. The checker never trusts the producer's normal forms; they travel
   only as a debugging aid.
3. `rational-ldlt` (checker in `kinds/rational_ldlt.rs`). Payload: a square matrix of exact rationals and the
   claim "symmetric with positive pivots". Checking rule: reject unless A = Aᵀ entrywise; then for k = 1 … n
   compute d_k = a_kk − Σ_{j<k} l_kj²·d_j and require d_k > 0 strictly, and l_ik = (a_ik − Σ_{j<k} l_ij·l_kj·d_j)
   / d_k for i > k, with no pivoting; accept only if every pivot is positive. This is positive definiteness by
   exact LDLᵀ over ℚ; it is the kind used later for pseudo-inertia (card T-19) and for Gram matrices.
4. Verbs (generated from `registries/verbs.toml`; kind `read`; first milestone M0; cluster `prove`):
   - `prove.kernel <kernel>`: the instance certificate of a kernel and what it states. Output schema
     `frob.prove.kernel.out/1`: card, identity text, side conditions, kernel content hash, certificate hash,
     checker identity, class, and the fixed sentence that the certificate is about the program over ℚ with square
     roots and says nothing about floating-point results. A kernel with no certificate returns class absent and
     exit 2 with the finding `no-certificate`, never a default class.
   - `prove.verify [<bundle>… | --all]`: re-checks certificates in tree by calling the checkers of `frob-cert`
     in process; output schema `frob.prove.verify.out/1` with one row per bundle: digest, kind, verdict, first
     failing rule, refusal code where one applies. `frob-verify` repeats the same check offline; the two must
     return identical verdicts.
   - `prove.list`: certificates and theorem cards with their classes and checkers (schema
     `frob.prove.list.out/1`).
   All three return the standard envelope with the evidence block (claim Proof, class of the weakest row) and the
   three flags. Exit codes follow the envelope table: 0 completed; 2 completed with findings; 3 refused.
   Examples: `frob prove kernel K-cay-step --json`, `frob prove verify --all --json`, `frob prove list --json`.
5. Refusals surfaced by these verbs: FROB-REF-823 (unknown proof kind; repairs: re-emit with a registered kind;
   upgrade the auditor if the bundle names a newer registry); FROB-REF-833 (a no-authorization flag is missing or
   true; no repair exists, because no code path sets a flag: the artifact is foreign or corrupt and is
   regenerated); FROB-REF-834 (a result presented above the class of its weakest input, or as `Proved` or
   `Certified` without a certificate hash and a checker identity; repair: restate at the weakest class);
   FROB-REF-829 (a side condition of a proof rule is missing; repair: re-emit with the missing relation or
   sub-certificate). Each maps to exit code 3.
6. Specimens and mutants, checked in under `crates/frob-cert/tests/specimens/`: `poly-identity/accept-T-01`,
   `accept-T-03`, `accept-T-04`, each with three mutants (one changed coefficient with hashes recomputed; a
   missing relation; a cofactor changed); `rational-ldlt/accept-pd4` and mutants (a non-positive pivot; an
   asymmetric entry; a non-reduced rational); `generic/flag-true` (a valid T-01 bundle with
   `execution_authorized: true` and consistent hashes).

Determinism class D0. Evidence class of an accepted kernel bundle: `Certified`, bound to one kernel content hash.

## Acceptance criteria

- [ ] GATE-LEMMA-00, offline half (TARGET, M0, claim Proof): the three M0 certificates are written as bundles and
      each replays to `accept` in `frob-verify` built from the copied crate; this closes INT-FSYM-01's last clause.
- [ ] GATE-LEMMA-06, bundle clause: a bundle with a flag set to `true` is rejected with FROB-REF-833 by the
      in-tree verb and by the standalone auditor (KA-214); so is one with a flag missing (KA-216).
- [ ] One changed coefficient in each of the three kernel bundles gives `reject` with the rule named, although
      every hash is consistent (KA-211).
- [ ] `rational-ldlt` accepts the positive-definite specimen and rejects the three mutants.
- [ ] `frob prove kernel`, `frob prove verify` and `frob prove list` are reachable through `frob --json` with the
      schemas above, appear in the generated documentation, and carry the three flags; the in-tree verb and the
      standalone binary agree on every specimen and mutant.
- [ ] The writer's output re-serializes to identical bytes in the auditor (PO-LEMMA-01).
- [ ] `frob-lemma` has no dependency edge to `frob-cert`; `cargo tree -p frob-cert` still prints one line.
- [ ] The two kinds are registered with one accepted specimen and at least three rejected mutations each, and the
      mutants are entered in the negative-control registry.
- [ ] Closing rule: the bead closes on its own tests; the gate rows are written by N12-33 (GATE-LEMMA-00) and
      N12-11 (GATE-LEMMA-06), which depend on it.

## Test plan

### Unit tests

`crates/frob-cert/tests/kinds_m0.rs`, `crates/frob-lemma/tests/bundle_kernel.rs`, `crates/frob-verbs/tests/`.
- `poly_identity_plain`: (x + y)² against x² + 2·x·y + y² accepts; against x² + x·y + y² rejects with the
  residual's leading term x·y reported.
- `poly_identity_modulo_relation`: lhs = t²·s, rhs = r·s with the relation t² − r and cofactor s accepts; the
  same payload without the relation rejects; with the relation present in the payload and absent from the
  assumptions it rejects for a missing side condition.
- `poly_identity_t01_spot`: the nine entries of NᵀN − D²·I for N = D·I + 4·ω̂ + 2·ω̂², D = 4 + |ω|² are zero.
- `ldlt_two_by_two`: [[2, 1], [1, 2]] has pivots (2, 3/2) and accepts; [[1, 2], [2, 1]] has second pivot −3 and
  rejects.
- `ldlt_pd4` (synthetic pseudo-inertia): rows (1, 0, 0, 1), (0, 1/3, 0, 0), (0, 0, 1/3, 0), (1, 0, 0, 2) have
  pivots (1, 1/3, 1/3, 1) and accept; with the last entry 1 the fourth pivot is 0 and the bundle rejects.
- `writer_fields_complete`: every required field of the schema is present; flags are the literal `false`.
- `verb_kernel_without_certificate`: exit 2 with finding `no-certificate`.
- `verbs_agree_with_standalone`: verdict and rule equal on all specimens and mutants.
- Property test: for random polynomials p and q, the bundle "p·q = expand(p·q)" accepts and any single
  coefficient perturbation rejects.

### End-to-end script and logging

`scripts/e2e/lemma_kernel_cert.sh` (bead N12-33) is the user-side script for this capability: it runs the three
verbs through the real `frob` binary, builds `frob-verify` from a copy of the crate with no network, replays the
bundles with a cleared environment and logs, per bundle, the command line, exit code, wall time, the evidence
block, the bundle digest, the verdict and the first failing rule of each mutant.

### Known answers and negative controls

KA-211, KA-214, KA-215 (a bundle with an unknown proof kind and consistent hashes: reject, FROB-REF-823), KA-216,
KA-220, KA-222. CX-106 (a bundle whose hashes are all consistent is a valid certificate: broken by the unknown
kind), CX-115 (an artifact with no authorization fields is neutral: it is rejected exactly like one with a true
flag). Negative controls: the mutants listed above. Metamorphic relations: renaming variables consistently in a
`poly-identity` payload keeps the verdict; permuting rows and columns of a matrix by one permutation keeps the
`rational-ldlt` verdict. Determinism lanes: twice on one machine, debug and release, two hosts: identical bytes
and verdicts.

## Considerations

- The auditor's total size is capped at 12,000 lines (TARGET); the two checkers here should stay under 600.
- Normal-form expansion can swell; the limits make that a refusal, and a refused certificate is reported, never
  counted as accepted.
- A certificate says nothing about floating-point output (CX-112); the verbs print that sentence.
- If KILL-LEMMA later fires, kernel "certificates" become randomized identity tests recorded as `Tested` and the
  word "certificate" leaves kernel manifests; the bundle format and the verbs remain.
- OPEN-LEMMA-4 (is one auditor enough): default one auditor with the per-kind mutation suite; a FrankenSymPy
  re-check of the same bundles runs in the conformance crate as an oracle for the auditor, never as a part of it.
