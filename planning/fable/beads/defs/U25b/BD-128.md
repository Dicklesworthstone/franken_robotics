## Background

Every other subsystem answers a question about one design. Augur answers a question about a set of designs. The
unit of work is a mission query: the caller supplies a design domain D (parameter spaces of typed assembly graphs),
a nonempty world family W fixed before any candidate is tested, an observation channel Y, a class Π_Y of causal
policies on the history of Y, a horizon, a Boolean acceptance predicate A on executions, and the ordered
quantifiers that relate them. With T(d, π, w) the set of maximal admitted executions of design d under policy π in
world w, the robust design family is

  F = { d ∈ D : ∃π ∈ Π_Y  ∀w ∈ W,  T(d, π, w) ≠ ∅  ∧  ∀τ ∈ T(d, π, w), A(τ) }.

The clause T ≠ ∅ matters: a design whose dynamics are undefined in some admitted world does not satisfy the
universal quantifier vacuously. The answer is a pair of sets I ⊆ F ⊆ O given as cells: every inner cell carries a
checked reason why it works, every cell outside O a checked reason why it cannot, and O ∖ I is returned as
unresolved cells with the explanations that keep them open.

This bead is the semantic kernel of the crate `frob-mission` (layer 5): the types, the rules that keep an
optimizer, a cache or a GPU kernel from changing the question while answering it, and the four proof rules as
proposers on the fragments that are exactly solvable (finite games and polyhedral systems). The subsystem as a
whole is Frontier; these fragments are Solid. It serves BET-19 (a query over a design family, answered with inner
and outer sets and witnesses, reaches an accepted answer sooner than point-by-point evaluation; its control is the
quantifier-order fixture of this bead).

Decisions that govern the core, with reasons:

- ADR-AUGUR-01: the answer is a pair of sets with proofs, never a score. A score cannot distinguish "this design
  fails" from "this search failed" and cannot be reused after an edit.
- ADR-AUGUR-02: the quantifier prefix is written by the caller and is part of the mission identity; there is no
  default. The same plant gives opposite answers under "one command per known build" and "one command for the
  whole family", and evidence for the easier order looks identical in a table of results.
- ADR-AUGUR-03: conventional formulations first (a lifted robust linear program, a scenario-tree program, an
  enumeration). In every planning pilot the conventional formulation tied the specialized one.
- ADR-AUGUR-04: propose anywhere, check on the CPU in exact or outward-rounded arithmetic.
- ADR-AUGUR-07: unknown is a verdict. Solver failure, timeout, an enclosure that straddles a threshold and a mode
  sequence that cannot be enclosed all yield unresolved; nothing converts unresolved into another verdict.
- ADR-AUGUR-08: answers are anytime, because each decided cell is individually certified.
- ADR-AUGUR-10: the weakest input sets the class; no operation in `frob-mission` raises a class.
- ADR-AUGUR-12: hidden as-built parameters live in the world, not in the design index.

Rejected: scoring and thresholding (ADR-AUGUR-01); a default prefix; treating a failed training run as an
exclusion; forming the answer by intersecting per-world answers, which proves the clairvoyant statement ∀w ∃π.

## Technical approach

Types (DESIGN; `crates/frob-mission/src/{prefix,cell,verdict,answer,assumptions}.rs`):

```rust
pub enum Binder { Exists { var: Var, scope: PolicyScope }, ForAll { var: Var },
                  Prob { var: Var, population: PopulationId, at_least: Ratio, confidence: Ratio } }
pub enum PolicyScope { PerNominalDesign, PerCell, Family }
pub struct Cell { topology: TopologyId, chart: ChartId, bounds: Vec<Bound>,   // each end open or closed
                  units: Vec<Unit>, assumptions: AssumptionSet, policy_scope: PolicyScope }
pub enum Verdict { Inner(Vec<ProofRef>), Excluded(Vec<ProofRef>), Unresolved(Vec<Explanation>) }
pub enum Explanation { StraddlesThreshold, ModeSequenceUnenclosed, SolverFailure, BudgetExhausted,
                       CompetingMechanisms(Vec<MechanismRef>), NeedsMeasurement(MeasurementRef) }
pub struct Answer { mission: MissionId, cells: Vec<(Cell, Verdict)>, witnesses: Vec<Witness>,
                    cost: Option<CostBounds>, next_test: Option<NextTest>, claim: ClaimProduct, bundle: BundleHash }
```

`Answer::outer()` is inner ∪ unresolved. An answer is immutable and addressed `a:…`; more budget produces a new
answer that refines the old one.

Rules that follow from the quantifier order, each enforced in code:
1. A design-dependent policy is indexed by the known nominal build. A policy indexed by a quantity absent from
   the observation contract at the decision instant cannot be constructed (INV-AUGUR-07).
2. A rollout refutes a particular controller, not a design. No function converts a failed search, a failed
   training run, a timeout or a solver error into `Excluded` (INV-AUGUR-06).
3. A refuter must match the claim it refutes: against "every controller has some failing disturbance", a
   counterexample is one body and one causal controller that meet the mission for every admitted disturbance.
4. Hidden parameters follow their declared persistence. A `fixed-per-execution` parameter is one variable across
   the horizon; a `resampled` one is a fresh variable at each named instant. Treating a fixed parameter as a
   per-step disturbance enlarges W: conservative for inclusion, unsound for exclusion.
5. Private randomization does not rescue a guaranteed mission: under ∀w a randomized policy must succeed with
   probability one in every world.
6. Evidence for an easier order is rejected. Per-world answers bound F from outside only:
   F(V) ⊆ ⋂_{w ∈ V} F({w}). The core offers `outer_from_per_world`, which can exclude a design that fails in
   some world alone, and has no function that turns per-world successes into an inner cell. A proof object
   records the prefix it proves, and one offered for a different prefix is refused (FROB-REF-881: evidence
   establishes a different quantifier prefix than the query's, including clairvoyant evidence offered for a
   robust claim; first repair: the prefix it does establish; exit code 3).

Progress and unknown: (1) deadlock, undefined dynamics and Zeno behaviour without an admitted completion cannot
earn success; (2) a model-level failure of progress shown by an exact argument blocks inclusion, and shown for
every admitted policy supports exclusion; (3) an admitted completion restores evaluation; (4) a numerical failure
(non-convergence, step collapse, an exhausted retry budget, a NaN) leaves the verdict unresolved; (5) comparators
are evaluated as declared: strict, non-strict and equality atoms are distinct, and a uniform positive margin is a
separate request in `predicates.margins`; (6) several objectives are never scalarized by Augur.

The four proof rules as proposers:

- Rule 1, necessary-condition exclusion (polyhedral). Relax controller and dynamics to a system A·x = w(θ),
  0 ≤ x ≤ c over cell parameters θ. A dual vector y excludes a point when yᵀw > Σᵢ max(0, (Aᵀy)ᵢ)·cᵢ, strictly.
  It excludes a cell when yᵀw(θ) − Σᵢ max(0, (Aᵀy)ᵢ)·cᵢ is affine in each cell parameter and positive at every
  vertex of the cell, with strictness handled at open ends. The object records the set inclusions that make the
  system a relaxation. Two limits are enforced: infeasible sample points never exclude a cell; and the relaxation
  must list every admissible state and energy source it encloses (a quasi-static work cut for a passive sill
  crossing of an 8 kg body over a 12 mm rise needs 8 × 9.81 × 0.012 = 0.94176 J against a 0.90 J budget and
  excludes the crossing, and 0.05 J of approach kinetic energy, absent from the budget, removes the exclusion).
- Rule 2, constructive inclusion. Polyhedral: a witness affine in the chart variable, with every constraint
  affine in (chart variable, witness), is checked at the vertices of the cell. Finite: a scenario tree whose
  nodes are decision instants and whose branches are worlds and reading-error vertices; (world, error) pairs
  with equal arrived-packet histories form one information set; a causal policy assigns one command per
  information set; with terminal conditions linear in the commands the whole game is one linear program with a
  constraint block per (world, error vertex). Scope: exact witnesses exist for static, quasi-static and
  finite-game cells; contact-rich full-order cells stay unresolved with `Tested` trajectories attached.
- Rule 3, monotone inheritance or symmetry. The core defines the obligations and refuses a transport that lacks
  one (FROB-REF-852: a monotone or symmetry transport lacks a side condition; repair: the missing
  sub-certificate). Exclusion transports downward under a set inclusion between relaxations; inclusion
  transports upward only under four conditions (admitted disturbances, realizable witness with the same or finer
  observations, mission outputs, simulation of every admitted branch). A symmetry must fix the mission and map W
  and Π_Y onto themselves; restricting to equivariant deterministic policies is a change of Π_Y (two symmetric
  actuators where success needs exactly one to act: the winning actions (0, 1) and (1, 0) are exchanged, and
  the invariant actions (0, 0) and (1, 1) both fail).
- Rule 4, exact partitions and composition. The union of proved inner cells is inner. A cell E leaves the outer
  set only by a proof that E ∩ F = ∅; disjointness from known inner cells leaves E open. The core emits one
  `partition` object per answer. Stage composition is typed here and built later.

Exact path. A floating-point solve (the small dense cone solver, cross-checked by the second linear-program
solver) names an active set; the basis system is solved exactly over ℚ with the proposer's own rational type;
exact primal feasibility is tested, and for an optimum exact dual feasibility. If reconstruction fails the cell
is unresolved with `SolverFailure`. Small linear systems are also eliminated in tree by Fourier–Motzkin
elimination, which serves as the second, independently written route on the fixtures.

Polarity (construction C-18). F is antitone in W and monotone in Π and in A ordered by implication. Each proof
object records its assumptions with an axis and a polarity, and its dependency support:

| Amendment | Inner certificate | Exclusion |
|---|---|---|
| W shrinks | survives | recheck |
| W grows | recheck | survives |
| Π grows (more information, earlier packets, more authority) | survives | recheck |
| Π shrinks | recheck | survives |
| A weakens | survives | recheck |
| A strengthens | recheck | survives |

Invariants enforced by the answer constructor and by `Answer::refine(old, new)`: INV-AUGUR-01 (I ⊆ F ⊆ O: every
inner cell has an inclusion proof for the query's exact prefix, every cell outside O an exclusion proof);
INV-AUGUR-02 (inner, excluded and unresolved cells partition the domain with disjoint interiors and stated
boundary ownership); INV-AUGUR-04 (a later answer to the same `MissionId` moves cells only out of the unresolved
set; a cell leaves I or re-enters O only through a logged withdrawal naming its counterexample); INV-AUGUR-05 (the
class of an answer is the weakest class among its cells); INV-AUGUR-10 (scheduling changes order and cost, never a
verdict); INV-AUGUR-11 (a synthesized candidate has no verdict until a proof rule assigns one).

Outputs are plain proof objects in the neutral vocabulary of `frob-core`; `frob-mission` never links the auditor.
Determinism class D0 for exact fragments. Evidence class: `Certified` for a cell only after the bundle check that
a later step runs; until then the cell's proofs are proposals.

## Acceptance criteria

- [ ] The seed condition: on the quantifier-order fixture the inner set lies inside the exact set and the outer
      set contains it, for both prefixes; and an answer formed by intersecting per-world answers is rejected.
- [ ] Per-build query on the pusher (y = max(0, g·u − d), g ∈ [1/2, 2], u ∈ [0, 2], d ∈ [0, 1/4], required
      y ∈ [3/4, 5/4], chart w = 1/g): inner = [1/2, 2] with the witness u = w; family-scope query: the whole
      domain excluded with a dual witness (u ≥ 2 and u ≤ 5/8 cannot both hold).
- [ ] Every invariant above has a property test; INV-AUGUR-04 is exercised by a refinement that tries to move an
      inner cell back to unresolved and is refused without a withdrawal record.
- [ ] No public function maps a solver failure, timeout or failed search to `Excluded` (a test enumerates the
      public constructors of `Verdict::Excluded` and their required proof arguments).
- [ ] PO-AUGUR-06 (each proof rule is sound on its finite and polyhedral fragments): stated as candidate theorem
      cards (Farkas soundness, the stance specimen, the docking family, the indistinguishability witness) and,
      until proved, tested against the mutation corpus and classed by the weakest step.
- [ ] PO-AUGUR-01 on this bead's lowering: the linear-program route and the in-tree elimination route agree
      exactly on the fixture, and a deliberately invalid lowering (the sign of d flipped) is caught.
- [ ] `frob-mission` has no dependency edge to `frob-cert` and `CONTRACT.md` with ten sections exists (both
      delivered by the crate skeleton N25a-01; this bead adds its modules and its rows to the contract).
- [ ] Cancellation is tested: a cancelled solve leaves no partial cell in the answer.

## Test plan

### Unit tests

`crates/frob-mission/tests/core.rs`; real solvers, no mocks.
- `pusher_per_build_inner_whole_interval`, `pusher_family_scope_excluded` (exact ends compared as rationals).
- `per_world_intersection_is_outer_only`: two worlds g ∈ {1, 2}, plant x = g·u, target x = 1: each world alone
  is solvable (u = 1, u = 1/2), no single u solves both; the helper returns an outer bound and no inner cell;
  offering the per-world successes as an inclusion is refused with FROB-REF-881.
- `persistent_gain_out_and_back`: prescribed out-and-back with a fixed gain g ∈ {1, 2} has net displacement 0;
  with the gain resampled per move the reachable set is {−1, 0, 1}; a return-to-start mission is inner under
  `fixed-per-execution` and not under `resampled`.
- `strict_comparator_boundary`: an atom x < 5/16 is false at x = 5/16; on 0 < w ≤ 1 every realization passes
  w > 0 although the infimum is 0.
- `sample_points_do_not_exclude`: a cell with infeasible sample points and no cell-wide dual stays unresolved.
- `sill_work_cut_needs_energy_sources`: the 0.94176 J against 0.90 J exclusion is refused as a cell exclusion
  when the relaxation's source list omits approach kinetic energy that the mission declares.
- `symmetric_actuators_no_equivariant_winner`.
- `reconstruction_failure_is_unresolved`: a deliberately ill-conditioned program yields `SolverFailure`.
- `class_is_weakest_cell`: an answer with one `Tested` cell has class `Tested`.
- Property tests for INV-AUGUR-02 (random splits keep a partition) and INV-AUGUR-10 (random worklist orders
  give identical verdict sets).

### End-to-end script and logging

`scripts/e2e/mission_quantifier_order.sh` (written with this bead). It runs the two pusher queries, first through
the example binary of the crate and, once the verb exists, through `frob mission synthesize pusher-per-build.fmission
--json` and `frob mission synthesize pusher-family.fmission --json`. It asserts the two exact answers, that the
two `MissionId`s differ, and that a per-world witness offered to the family query is refused. It sources the
shared helper and writes newline-delimited JSON to `target/e2e-logs/mission_quantifier_order/<utc>.ndjson` with a
transcript beside it: `ts`, `script`, `bead`, `step`, `event`, the command line, exit code, wall time, the
envelope's evidence block, each cell's bounds and verdict against the expected value, the two `MissionId`s,
digests of the two answers, the refusal code and first repair of the per-world witness step, and on failure the
first differing bound (expected and actual rationals, the cell and the end) with the paths of the two `.fmission`
fixtures, the answer files and the seed needed to reproduce. Steps are named `per-build`, `family`,
`per-world-refused` and `mission-ids-differ`. A final `summary` line gives assertion counts.

### Known answers and negative controls

KA-628 (pusher: per-build command set all of [1/2, 2]; shared set empty; the prefix ∀g ∃u offered for ∃u ∀g is
rejected), KA-630 (persistent gain), KA-631 (twenty worlds, two stages at 19/20: 18/20 or 19/20, 0.9025 only
under independence), KA-632 (mandatory work 0.94176 J). CX-272 (a command exists for each design, so one exists
for the family), CX-275 (sample points fail, so the cell is excluded), CX-270 (the midpoint of two feasible
designs is feasible: feet at (±1 − e, ±1) m capped at 0.5 N; (e, W) = (0, 1.9) and (0.9, 1) pass and the midpoint
needs 841/800 N from a pair capped at 1 N). Planted failures: a build that maps `SolverFailure` to `Excluded`; a
build that accepts per-world evidence; a build that closes an open end. Metamorphic relations: re-labelling the
chart by an affine change of variable maps cells exactly; shrinking W never removes an inner cell. Determinism
lanes: twice on one machine, across worker counts, debug and release, two hosts: identical answers (class D0).

## Considerations

- OPEN-AUGUR-2 (exact linear programs or floating point with rational reconstruction; owner: Augur lead):
  default floating point, basis reconstruction over ℚ, exact check; decided from the reconstruction failure rate
  on the stance family.
- OPEN-AUGUR-4 (a quantifier-elimination or SMT engine as a production dependency): default comparator only;
  the product uses the in-tree elimination above, so some cells stay unresolved that a general solver would
  close.
- OPEN-AUGUR-5 (sound reachable tubes for contact-rich cells): none exists in the suite; default as stated in
  rule 2; revisited at M4.
- OPEN-AUGUR-11 (a standard measure on unresolved sets): default none; the caller supplies one.
- Kill gates named in advance: KILL-AUGUR-TIE (a short robust program over a conventional solver reaches the
  same checked scope: ship that program behind the same verbs) and KILL-AUGUR-FALSECERT (one accepted false
  certificate disables its proof kind). RISK-35: a certificate issued for a statement other than the one asked.
- Performance: the fragments are tiny; the measured planning result is that the conventional formulation ties,
  so no speed is claimed.
