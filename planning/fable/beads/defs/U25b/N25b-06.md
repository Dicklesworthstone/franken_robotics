## Background

A mission answer is a list of cells of a design family with verdicts. The rule for calling such a capability
implemented is strict: the certificate must travel in a `.frobcert` bundle, and the independent offline auditor
`frob-verify` must accept it on a machine with neither the agent nor a GPU. GATE-AUGUR-05 (M1, claim Proof)
turns that rule into a measurement: every `Certified` cell of the three first-slice known answers (the stance
family, the docking family and the pusher battery) is accepted by `frob-verify` built from an empty environment
on a host with no GPU, in under 10 s in total, and bundle digests are identical across two hosts.

This bead is the end-to-end script that performs the measurement from the user's side and records the gate. It
is the M1 demonstration that an answer survives being carried away from the machine and the agent that produced
it. Tier: test of a Frontier subsystem. It serves BET-19 (mission queries).

What the three answers contain (each exact under its stated model):

- Stance family: a 400 N load on four point feet at (±1/3, ±b) m with 160 N ratings and a centre-of-mass
  rectangle of half-sizes 150 mm and 75 mm. In the chart v = 1/b: inner cell v ∈ [2, 14/3] (half-width at least
  3/14 m), excluded cell v ∈ (14/3, 6], and a partition of [2, 6].
- Docking family: three one-second ticks, hidden gain 1 or 2, one velocity packet with error radius ε, command
  bound U. A grid of 17 bounds by 33 error levels gives 561 cells: 344 admitted (ε < (U + 1/2)/4), 217 excluded,
  nine of them exact boundary cases; with a late packet all 561 are excluded.
- Pusher battery: ten frozen cases and twenty intervals with exact ends, plus the per-build and shared queries on
  one plant ([1/2, 2] and the empty set).

## Scope

In: `scripts/e2e/mission_bundle_audit.sh`; the transfer of bundle sets to the second host; the timing
measurement; the digest comparison; the review-marker assertions; the self-test; the gate record.
Out: producing the answers (the family beads and the mission verbs); the writer and the in-tree check (BD-133);
the seeded-defect half of the second-machine gate (N12-35); the mutation campaign (BD-136).

## Technical approach

Hosts. Host A is the machine that produces the answers. Host B is the audit host: a machine or a container with
no GPU device visible (no `/dev/nvidia*`, no `/dev/dri` render node, no Metal device), no `frob` installation, no
workspace checkout and no network during the audit. The script takes host B as an argument (an SSH target or a
local container image name) and refuses to run the audit step on a host where a GPU device is visible.

Steps (plain shell, `set -euo pipefail`, shared helper sourced, seed-explicit, idempotent):

1. `start`: commit, toolchain, both host fingerprints, seeds.
2. On host A, produce the three answers through the public verbs:
   `frob mission synthesize stance-family-400N.fmission --json`, the docking grid query and its late-packet
   variant, and the pusher battery queries. Assert each envelope has `ok: true`, the evidence class `Certified`
   for the certified cells, the three authorization flags false, and a `certificate.bundle` root.
3. `frob prove bundle <answer> --out <dir> --json` for each answer; record every entry's digest, claim kind,
   class, proof kind and the Merkle root; assert the root equals the answer's `certificate.bundle`.
4. Repeat steps 2 and 3 on a second producing host (the other development machine) with the same seeds; assert
   that every entry digest and every root is identical (PO-AUGUR-05: bundle bytes are a deterministic function of
   the answer; class D0). Also repeat on host A with a different worker count and assert the same.
5. Build the auditor for host B from a copy of `crates/frob-cert` alone, offline, on its stable toolchain (the
   procedure of the independence script), and copy only the binary and the bundle directories to host B.
6. On host B, with `env -i` and the network unreachable, run `frob-verify --json` over all bundle sets. Measure
   wall time for the whole audit with a monotonic clock, three repetitions, and take the maximum.
7. Assert: every entry `accept`; every root recomputed and equal; the class printed for each set equals the
   weakest entry; the report lists what was checked and what was not; the three flags false in every bundle;
   total audit time under 10 s.
8. Counts. Assert the certified-cell counts match the known answers: stance, one inner cell, one excluded cell
   and one partition; docking, 344 admitted cells and 217 excluded cells on the on-time grid (nine of the
   excluded cells being exact boundary cases) and 561 excluded cells on the late-packet grid; pusher, twenty
   intervals with exact ends.
9. Review marker. Assert the auditor's "equations reviewed" line for each set, and that the envelope's claim
   list includes `Proof` for these registered fixtures. Then run two copies of the stance mission: one that
   differs only in `name`, which keeps the `MissionId` (the name is not part of it, INV-AUGUR-03) and must still
   list `Proof`; and one with one load-hull bound changed, which has a new `MissionId`, is not on the fixture
   allowlist and must list no `Proof`, with the warning line of N25b-02 and FROB-REF-819 on an attempted Proof
   citation. Log the three `MissionId`s.
10. Verdict parity. Run `frob prove verify --json` on host A over the same sets and assert verdicts and first
    failing rules (none) equal those of host B.
11. `summary` and gate record: number of bundles audited, accepted, total audit time against 10 s, digest
    equality across hosts and worker counts, and the receipt hash.

Logging: newline-delimited JSON at `target/e2e-logs/mission_bundle_audit/<utc-timestamp>.ndjson` and a
transcript. Every line has `ts`, `script`, `bead` (`N25b-06`), `step`, `event`, the exact command line, exit
code, wall time, and for verb calls the envelope's evidence block (claim, class, tier, determinism, identities,
seed). Per bundle: digest, kind, class, verdict. `metric` lines: `audit_total_s` with threshold 10, and
`digest_mismatches` with threshold 0. On failure: the first differing digest with both values and the paths of
the two bundle files, or the first rejected entry with its rule. The log holds identifiers and digests only, no
scene data.

## Acceptance criteria

- [ ] GATE-AUGUR-05 (TARGET): every `Certified` cell of the three answers is accepted by `frob-verify` built from
      an empty environment on a host with no GPU; total audit time under 10 s (measured value recorded); bundle
      digests identical across two producing hosts.
- [ ] The cell counts of step 8 match exactly.
- [ ] The audit host had no GPU device, no `frob` installation and no network during the audit (asserted and
      logged).
- [ ] In-tree and standalone verdicts are identical on every entry.
- [ ] The script exits non-zero on any failed assertion and the log ends with a `summary` line naming the gate.
- [ ] Negative controls (self-test): (a) one bundle with a force changed by 1 N and hashes recomputed makes
      step 7 fail with the entry named; (b) a writer build that embeds a timestamp makes step 4 fail with the
      first differing digest; (c) an artificial sleep in the audit loop makes the timing assertion fail.

## Test plan

### Unit tests

`scripts/e2e/tests/mission_bundle_audit_selftest.sh` runs the script against the three planted defects above and
asserts the failing step and the logged first difference for each. The count parser is tested on a recorded
`prove.bundle` listing of the stance answer (three entries).

### End-to-end script and logging

This bead is the script. It is run at M1 for the gate, and again at M4 by the bead that extends bundles to family
answers at scale, with that bead's fixtures.

### Known answers and negative controls

KA-624 (stance: admitted iff b ≥ 3/14 m; 165 N needed at b = 1/5 m), KA-637 (docking: 344 admitted, 217
excluded, 9 on the boundary; at U = 3/4 and ε = 5/16 both worlds can read 15/16), KA-636 (late packet: all 561
excluded), KA-629 (pusher battery: twenty intervals, including a singleton shared set {1}, [2/3, 5/4] and
[0, 3/8]), KA-628. Negative controls: the three planted defects. Metamorphic relation: auditing a set in any
file order gives the same verdicts and root. Determinism lanes: two producing hosts, two worker counts, debug and
release builds of the auditor, all with identical digests and verdicts (class D0).

## Considerations

- The 10 s budget is for more than eleven hundred small bundles (561 docking cells on each of the two grids, plus
  the stance and pusher entries); it holds only if the auditor's arithmetic is not
  quadratic in bundle count and process start-up is paid once (the binary takes many files per invocation).
- "No GPU" is a property of the audit host, checked by the script; the producing hosts may have GPUs, since the
  first slice is CPU only.
- If the second development machine is unavailable, digest equality across hosts is recorded `not run` and the
  gate cannot pass.
- KILL-AUGUR-FALSECERT applies to every bundle this script accepts; a later contradiction of one of them starts
  the false-certificate procedure.
- OPEN-AUGUR-7 (the exit code of a mission query that stops on budget with certified cells; default exit 2 with
  `resolution-unmet`) affects step 2 only if a budget is hit; the fixtures fit their budgets, and the script
  treats exit 2 as a failed precondition.
