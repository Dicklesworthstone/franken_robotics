## Background

A mission query asks which designs of a family satisfy a requirement in every world of a declared family. Some
queries cannot be satisfied by any design at all, because the requirement contradicts the world family or the
actuation limits before any body is chosen: a docking target that no admitted command can reach, a load that
exceeds the sum of every admissible rating. Spending a search on such a query and returning "the whole domain is
excluded" is a correct answer and a wasteful one, and it hides the reason. The plan therefore tests consistency at
admission: the predicates are tested against the world family with every design constraint relaxed. If they
conflict, the query is refused with a minimal conflicting subset, found by deletion filtering over the linear and
interval relaxation, with a Farkas certificate where the conflict is linear (refusal FROB-REF-877: the predicates
conflict with the world family for every design; first repair offered: a minimal conflicting subset, with its
Farkas certificate where linear).

Tier: Solid for linear conflicts, Frontier beyond them (interval relaxations of nonlinear atoms). Crate:
`frob-mission`, which owns admission of `.fmission` queries. The refusal is distinct from its neighbour
FROB-REF-874 (the world family is empty, or its scope changed after candidates were tested): here the world
family is nonempty and the requirement is what cannot be met.

Why a minimal subset and not just "infeasible": a refusal must name what to change. An agent that reads
"conflict among {reach the target, command bound, horizon}" knows which three knobs exist; one that reads
"infeasible" does not. Rejected alternatives: returning the full infeasible system (dozens of atoms, most
irrelevant); a minimum-cardinality subset (an NP-hard search for no practical gain; deletion filtering gives an
irreducible subset with a linear number of feasibility tests); skipping the test and letting the search find it
(the search would report cell-by-cell exclusions with no common cause).

## Scope

In: the design-relaxed consistency system; the feasibility test (linear exactly, nonlinear by interval
relaxation); deletion filtering; the certificate; the refusal payload with ranked repairs; the hook in
`mission.check` and at the start of every mission run verb.
Out: schema validity (BD-126) and the other admission refusals (N25a-02, whose `AdmittedMission` value is this
bead's input; this bead depends on it); world-family emptiness, refusal 874 (N25a-02); the command-line script
that fires refusal 877 with the other admission refusals (N25a-23);
the search over cells once the query is admitted (BD-128 and the worklist); the checkers.

## Technical approach

1. The relaxed system. From the admitted query collect: every atom of `predicates.accept` and `hard_loss`
   (each with its comparator and units); the world family's constraints on its parameters; the observation and
   actuation constraints of the policy class (command bounds, the horizon's dynamics where they are part of the
   lowered model). Design constraints are relaxed: every free design parameter ranges over its whole declared
   box, and every design-specific limit (a rating, a stroke, a link length) is replaced by the loosest value the
   design domain admits. The policy is relaxed to clairvoyant: the command may depend on the hidden world. Both
   relaxations enlarge the set of solutions, so infeasibility of the relaxed system implies that no design and
   no admitted policy satisfies the mission in the chosen world. The test is run at one world when the family is
   a singleton and otherwise per vertex of a polyhedral world family; a conflict at any single admitted world
   suffices, because the mission quantifies over all worlds.
2. Feasibility test.
   - Linear part: constraints affine in the unknowns (commands, forces, relaxed design parameters) form
     M·x = r, x within bounds. Solve with the small dense cone solver and cross-check with the second
     linear-program solver; reconstruct the answer exactly over ℚ. Infeasibility is accepted only with an exact
     dual: y with yᵀr > Σᵢ max(0, (Mᵀy)ᵢ)·cᵢ in the box form.
   - Nonlinear part: each remaining atom is enclosed over the box of all unknowns with outward-rounded intervals
     through the airlock; an atom whose enclosure excludes its admissible range is individually contradictory.
     Combined nonlinear conflicts are sought by bisecting the box up to a small budget (DESIGN: 2,048 boxes);
     if every box is excluded by some atom the system is infeasible; if the budget ends first the query is
     admitted (a failed consistency search never refuses a query).
3. Deletion filtering. Given an infeasible system with constraints c₁ … c_n in the order they appear in the
   query: for i = 1 … n, remove cᵢ and test the rest; if still infeasible, leave it removed; otherwise restore
   it. The survivors form an irreducible infeasible subset: removing any one member makes the rest feasible.
   Cost: at most n + 1 feasibility tests. For a purely linear conflict the filter can start from the support of
   the dual vector (the constraints with nonzero multiplier), which is already infeasible.
4. Certificate. Linear: an `lp-farkas` proof object over the subset, with the dual restricted to it. Nonlinear:
   one `interval-box` object per box with the excluding atom named. The certificate is written and checked like
   any exclusion, so the refusal itself can be audited.
5. Refusal payload (envelope, `ok: false`, exit code 3, code FROB-REF-877): `pointer` to the predicate block;
   `observed`: the subset as a list of atom and constraint identifiers with their text; the certificate's bundle
   root; `retry: after-change`; ranked `repairs`, one per member of the subset, each a typed edit to the mission
   with the smallest change that removes the conflict when it can be computed (for a linear conflict the
   required slack on that member is the dual gap divided by the member's multiplier), ordered by the size of
   the change in the member's own units. Members that are world-family constraints are listed last and marked
   "narrows the declared world", since the world family is fixed before candidates are tested.
6. Where it runs. `mission.check` (admission) runs the test and reports the refusal without spending a run
   budget; every run verb re-checks the stored admission result by `MissionId` and never re-solves.
7. Evidence and determinism: the linear path is exact (class D0); the refusal's certificate is `Certified`.

## Acceptance criteria

- [ ] Docking conflict: three one-second ticks from rest, acceleration g·u_k with g ∈ {1, 2}, target
      (x₃, v₃) = (1, 0), and a design domain whose command bound U ranges over [1/16, 1/8]. Rest at the end
      forces u₂ = −u₀ − u₁, so x₃ = g·(2·u₀ + u₁) ≤ 2·3·U ≤ 3/4 < 1. The query is refused with FROB-REF-877; the
      subset is {the position target, the command bound on u₀, the command bound on u₁, the rest condition}
      for the world g = 2, and the Farkas certificate is accepted by the auditor.
- [ ] Static conflict: 400 N on four feet whose ratings range over [0, 80] N each: 400 = Σ fᵢ ≤ Σ capᵢ ≤ 320. The
      subset is the force balance and the four rating bounds; removing any one makes the rest feasible.
- [ ] Nonlinear conflict: the pusher y = max(0, g·u − d) with u ∈ [0, 2], g ∈ [1/2, 2], d ∈ [0, 1/4] and a
      requirement y ≥ 5 is refused with an interval certificate (the enclosure of g·u − d has upper end 4).
- [ ] A hard but consistent mission is admitted: the stance family, whose answer excludes part of the domain,
      passes the test, because some design satisfies it.
- [ ] A consistency search that exhausts its budget admits the query and logs "consistency undecided".
- [ ] Each returned subset is irreducible: a test removes each member in turn and finds the rest feasible.
- [ ] `frob mission check <file> --json` reports the refusal with ranked repairs; the same refusal is produced
      over the tool surface.
- [ ] Negative controls: a filter that stops after the first removal returns a reducible subset and fails the
      irreducibility test; a build that refuses on an exhausted budget is caught by the undecided case.

## Test plan

### Unit tests

`crates/frob-mission/tests/inconsistent.rs`; real solvers.
- `docking_unreachable_target`, `static_capacity_shortfall`, `pusher_interval_conflict` (the three cases above,
  with exact subsets compared as sets of identifiers).
- `dual_support_starts_filter`: for the static case the dual has multiplier 1 on the balance row and on each
  rating row; the filter begins from those five constraints.
- `irreducible_property`: on random infeasible linear systems (up to 12 constraints), every returned subset is
  infeasible and each of its proper subsets obtained by one removal is feasible.
- `repair_slack_value`: in the static case the smallest change on the load is to lower W from 400 N to 320 N
  (gap 80 N with multiplier 1), and on one rating to raise its bound from 80 N to 160 N.
- `consistent_mission_admitted`, `budget_exhaustion_admits`.
- `world_members_listed_last`.

### End-to-end script and logging

`scripts/e2e/mission_inconsistent.sh`: runs `frob mission check` on the three conflict fixtures and on the
stance fixture; asserts exit 3 and FROB-REF-877 for the first three and exit 0 for the fourth; runs
`frob prove bundle` on the refusal's certificate and audits it with the standalone auditor; applies the first
ranked repair with `frob mission new` from the edited document and asserts that the repaired query is admitted.
Log through the shared helper to `target/e2e-logs/mission_inconsistent/<utc>.ndjson` with a transcript: the
command line, exit code, wall time, the refusal's `code`, `pointer`, subset and repairs, the certificate digest
and the auditor's verdict; a `summary` line with assertion counts.

### Known answers and negative controls

Exact values: docking bound x₃ ≤ 6·U (3/4 at U = 1/8); static bound Σ cap ≤ 320 N against 400 N; pusher upper
end 2 × 2 − 0 = 4. These are consequences of the fixtures' stated models and are hand-checkable. The docking
model is that of the first mission slice (v₃ = g·(u₀ + u₁ + u₂), x₃ = g·(5·u₀/2 + 3·u₁/2 + u₂/2)). Negative
controls: the two listed. Metamorphic relations: reordering the query's atoms may change which irreducible
subset is returned and never whether the query is refused; tightening a member of a conflict keeps the refusal.
Determinism lanes: the subset and the certificate are identical across worker counts and hosts for a fixed atom
order.

## Considerations

- An irreducible subset is not unique and not minimum; the payload says "a minimal conflicting subset" and the
  order of the query's atoms decides which one is found.
- The clairvoyant relaxation makes the test sound and incomplete: a mission that is infeasible only because of
  what the policy cannot observe passes admission and is excluded later by an indistinguishability witness.
- The nonlinear budget is small on purpose; this is an admission check, not a solver.
- OPEN-AUGUR-4 (a quantifier-elimination or SMT engine as a production dependency): default comparator only, so
  conflicts that need such an engine are found later, cell by cell.
