## Background

A region certificate says that one constraint holds, or fails, over a whole box of design parameters. For a
lowered constraint g_k(θ) ≤ 0 that reads the parameters S_k, the driver of this bead builds two sets in the
coordinates S_k: an inner set I_k of boxes on which g_k ≤ 0 everywhere and an excluded set of boxes on which
g_k > 0 everywhere. Each box carries a certificate of kind `interval-box` or `taylor-box` that the independent
auditor re-computes with its own arithmetic. Boxes that neither test decides are bisected until a budget ends;
what remains is unresolved.

The decision behind the design is ADR-AUGUR-06: region evidence is per constraint, with a bounded split set;
interval and Taylor-model certificates are issued for one constraint, bisection is confined to about six
parameters, and isotropic paving of a design box of ten to twenty dimensions is not attempted. Reason: bisection
arithmetic (10⁴ boxes are 13 bisections, less than one cut per axis in 20 dimensions) and the published record.
ADR-AUGUR-04 fixes the trust boundary: the driver is a proposer and may use floating point; nothing it says is
believed until the auditor accepts the box's certificate.

FACT (paths under `frankensim/crates/`, read 2026-11-21, to be re-read at the pinned commit): `fs-ivl` provides
outward-rounded intervals, affine forms and multivariate Taylor models (`multi_taylor.rs`: `range_subdomain`,
`recenter`) and interval Newton with `DEFAULT_MAX_ROOT_BOXES = 65_536` (`newton.rs`). It has no paving driver and
no contractors; both are new work here, reached through the airlock. Tier: Frontier. This mechanism exists only
if its pilot did not meet its falsifier (the kill gate KILL-AUGUR-REGION); the bead depends on that decision.

## Technical approach

Interface (DESIGN):

```rust
pub struct PaveRequest { constraint: ExprDag, support: Vec<ParamId>, domain: BoxQ,      // exact rational ends
                         split_set: Vec<ParamId>,   // at most `split_cap` (default 6) members of `support`
                         method: Enclosure,          // Auto | Interval | Affine | Taylor { order }
                         contract: bool, box_budget: u32 /* default 10_000 */, min_width: Ratio }
pub struct Paving { inner: Vec<CertifiedBox>, excluded: Vec<CertifiedBox>, unresolved: Vec<OpenBox>,
                    boxes_used: u32, decided_share: Ratio /* of the sub-box volume */ }
```

Algorithm:
1. Start with the queue holding the domain box. Parameters of the support that are not in the split set stay at
   full range in every box.
2. Pop the next box (order: depth first by smallest depth, then lexicographic index; the order is fixed so runs
   are reproducible). If `contract` is set, run the contractor (step 6) and continue with the contracted box;
   any slab the contractor removed is queued as a candidate excluded box and must pass step 3 on its own.
3. Enclose g over the box with the requested method through the airlock. Upper end at most 0: candidate inner.
   Lower end above 0: candidate excluded. Otherwise undecided. With `Auto`, the default the verb uses, the
   methods are tried in order of cost (plain interval, then affine form, then Taylor model) and the first that
   decides the box is taken; the report names the arithmetic that decided each box.
4. Reproducibility rule. A candidate becomes a certified box only in a form the auditor can re-compute:
   - if the plain interval evaluation of the expression DAG over the box, at the auditor's declared dyadic
     precision, already decides it, emit an `interval-box` object (DAG digest, box, split set, claimed
     enclosure, `holds` or `fails`);
   - if only the affine form or the Taylor model decides it, emit a `taylor-box` object (the model's
     coefficients about the box centre and its remainder bound; an affine form is the order-one case), whose
     checker recomputes the remainder bound and the range;
   - if neither form can be emitted (the plain replay straddles and the model's remainder cannot be bounded by
     the checker's rule), the box is treated as undecided. A box is never certified on the proposer's word.
   Box ends are exact rationals; floating-point ends are widened outward to dyadic rationals before emission.
5. An undecided box is bisected along the split-set parameter with the largest current contribution to the
   enclosure's width (from the affine coefficients; ties by parameter order), unless its width in every
   split-set parameter is below `min_width` or the budget is spent; then it is stored as unresolved with the
   explanation `StraddlesThreshold` (no width left to cut) or `BudgetExhausted` (the box budget ended first).
6. Contractor (forward–backward propagation on the expression DAG). Forward: evaluate every node's interval from
   the leaves. Backward for the test "can g ≤ 0 hold here": intersect the root with (−∞, 0] and push the
   narrowed interval down through each node's inverse operations (sum, product, quotient, power, square root),
   narrowing the leaves; the part of the box cut away cannot satisfy g ≤ 0 and is a candidate excluded slab.
   The dual run with the root intersected with (0, ∞) cuts away parts that cannot violate, giving candidate
   inner slabs. The contractor is a heuristic: every slab is certified only by step 4.
7. Merging. Adjacent certified boxes with the same verdict are merged when the merged box passes step 4 again;
   otherwise they stay separate. Merging reduces bundle count and never changes a verdict.
8. Output per constraint: the paving, with `boxes_used`, the decided share of the sub-box volume (exact, from
   box volumes in the split-set coordinates), and the list of unresolved boxes with their widths.

Budgets and jobs: the driver is cancellable between boxes; a cancelled run returns the boxes certified so far,
each complete in itself. Checker time for the emitted boxes is charged to the query's checker budget. Proof
objects carry the dependency support S_k, so revalidation can tell which boxes an edit touches.

Determinism: box selection is deterministic; enclosures come from IEEE arithmetic with directed rounding, so the
set of decided boxes is reproducible on one platform and may differ in its last boxes across platforms. Every
emitted box is audited exactly, so a platform difference can change which boxes are decided and never the
validity of a decided box. Evidence class of an accepted box: `Certified`, for the static rigid model named in
the bundle.

## Acceptance criteria

- [ ] On g = x² + y² − 1 over [−2, 2]² with 10⁴ boxes, every inner box lies inside the unit disc and every
      excluded box outside it; the decided share exceeds 0.95; the auditor accepts every emitted certificate.
- [ ] On the knee-torque constraint of the three-joint leg over its declared box, the per-constraint decided
      share is reported and every certificate is accepted; the share is compared with the pilot's figure for the
      same constraint form.
- [ ] Zero certified boxes are contradicted by 10⁶ exact point evaluations on each test constraint.
- [ ] A box decided only by an affine form is emitted as a `taylor-box` of order one, or left undecided; it is
      never emitted as an `interval-box` that the auditor's replay would straddle (the auditor's rejection count
      over the emitted set is zero).
- [ ] The contractor never removes a point that satisfies the constraint (property test), and a slab it removed
      that step 4 cannot certify stays in the queue.
- [ ] With the split set capped at six and a constraint that reads eight parameters, the two remaining
      parameters are held at full range in every certified box.
- [ ] The box budget is respected exactly; cancellation returns only complete certified boxes.
- [ ] Negative controls: an enclosure with outward rounding disabled yields a certified box that the point
      evaluations contradict and the auditor rejects; a contractor with a wrong inverse for division loses a
      feasible point and fails the property test; a driver that marks a straddling box inner is contradicted by
      the point evaluations.

## Test plan

### Unit tests

`crates/frob-mission/tests/region_paving.rs`; real airlock arithmetic, real auditor in the loop.
- `disc_paving_sound_and_mostly_decided`.
- `linear_constraint_boundary`: g = x − 1/2 on [0, 1] with `min_width` 2⁻¹⁰: [0, 1/2] is inner after one cut (the
  enclosure's upper end is exactly 0); [3/4, 1], [5/8, 3/4] and so on are excluded; the closed box
  [1/2, 1/2 + 2⁻¹⁰] stays unresolved because its lower end is 0, not above 0. The decided share is 1 − 2⁻¹⁰.
  The exact boundary belongs to the monotone rule, not to bisection.
- `straddle_stays_unresolved`: g = (x − 1/2)² on [0, 1] with comparator ≤ 0 has no inner box of positive width.
- `affine_only_box_becomes_taylor_order_one`: g = x·(1 − x) − y on a box where plain intervals straddle and the
  affine form decides.
- `contractor_soundness` (property over random expression DAGs and boxes).
- `split_cap_respected`, `budget_exact`, `merge_recertifies`.
- `dependent_occurrences`: g = x − x on [0, 1] (the same variable twice) is decided by the affine form and not
  by plain intervals, exercising the reproducibility rule.
- `taylor_beats_interval_on_dependency`: g = x·(1 − x) − 3/10 ≤ 0 on [0, 1]: the plain interval enclosure
  [−0.3, 0.7] decides nothing at the root box; the affine form does not either (x = 1/2 + ε/2 gives
  x·(1 − x) = 1/4 − ε²/4, enclosed as [0, 1/2], so g ∈ [−0.3, 0.2]); the Taylor model of order 2 reaches the
  true range [−0.3, −0.05] and decides it in one box. With `Auto` the report names the Taylor model, and the
  box is emitted as a `taylor-box` of order 2.
- `contractor_peels_slab`: g = x − 0.3 ≤ 0 on [0, 1] with `contract` set: the contractor splits the box in two
  at 0.3 (the end widened to a dyadic rational) with no bisection spent; the slab below the cut is certified
  inner by step 4, and the slab above it is a candidate that step 4 must pass on its own, treated at its closed
  lower end exactly as `linear_constraint_boundary` describes.
- `unresolved_reasons`: a box at `min_width` is `StraddlesThreshold`; a box left when the budget ends is
  `BudgetExhausted`.
- Property test `no_certified_box_contradicted`: random polynomial constraints of degree at most 4 in at most
  6 variables; 10⁴ sampled points per decided box; no inner box contains a violating point and no excluded box
  a satisfying one.

### End-to-end script and logging

The driver is reached from `frob` only through the region mode that BD-358 (which depends on this bead) adds to
`mission.synthesize`; this bead's acceptance rests on the unit tests above, with the real auditor in the loop,
and does not wait on a later script. It exposes the per-constraint paving report (boxes used, decided share,
the arithmetic that decided each box, certificate kinds, unresolved boxes with their reasons) as JSON, which
`scripts/e2e/mission_region_certificates.sh` (bead N25b-11) logs when it drives the 12-parameter static
quadruped family from the user's side: per constraint, boxes used, the decided share against 0.50, the
certificate kinds emitted, the auditor's verdict counts and the number of point contradictions against 0.

### Known answers and negative controls

The arithmetic known answer (10⁴ boxes are 13 bisections; a uniform box keeps 0.64 of each side in 20 dimensions
and 0.41 in 10) is the reason the driver never paves the joint box. The pilot's recorded shares are the baseline.
CX-275 (sample points in a cell fail, so the cell is excluded) is the shortcut a certified box replaces.
Negative controls as listed. Metamorphic relations: an affine change of chart on one parameter maps boxes to
boxes and preserves verdicts; adding a parameter the constraint does not read changes nothing. Determinism
lanes: twice on one machine (identical box lists); two platforms (every emitted box accepted on both).

## Considerations

- The dependency problem (a variable occurring several times widens a plain interval evaluation) is the main
  reason boxes go undecided; affine forms and Taylor models help only with cancellation structure, and the
  published record says the help with dimension is small.
- A certificate bundle per box makes up to 10⁴ bundles per constraint; merging and the auditor's linear cost
  per box keep the audit affordable, and the measured audit time is reported with every region answer.
- OPEN-AUGUR-3 governs which constraints may be paved at all; above six read parameters the request is refused
  until the bounded-split-set rule passes its own gate.
- Kill gate named in advance: KILL-AUGUR-REGION (the pilot's falsifier, or the region gate failing after one
  repair cycle). Fallback: region certificates are removed; family answers use dual witnesses, monotone bounds
  and pointwise static analyses at proposed designs; untested regions are reported as sample coverage,
  `Estimated`.
- No speed is claimed; pointwise static checks prune equally for proposed designs.
