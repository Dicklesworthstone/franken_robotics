## Background

GATE-WS-03 (claim Known answer; its one part is due at M1 in the gate register) states the independence of the
offline auditor `frob-verify` in four clauses: (a) the dependency count of `frob-cert` is zero; (b) the copied
crate directory builds on its stable compiler with no network access; (c) the standalone binary and the
in-daemon verb return identical verdicts on the whole conformance corpus; (d) a system-call trace of an audit
shows no network and no process creation.

The script that measures the gate, `scripts/e2e/auditor_independence.sh`, and the assembler of its receipt are
N25b-05's (M0). Three clauses are measured there at M0. Clause (c) is the recorded result of N12-34's corpus-wide
comparison, an M1 bead, which an M0 bead cannot wait on (a bead's acceptance uses only what it and its
dependencies deliver). This bead is the M1 half: it runs the same script once N12-34's result exists, so that
all four clauses come from one resolution receipt, and it is where the gate's part is recorded. Without it the
M1 part would stay `not-run` and the M1 exit, which reads GATE-WS-03, would be blocked. Tier: Solid.

## Scope

In: the M1 run of `scripts/e2e/auditor_independence.sh` with all four clauses on the Linux host and on the Mac;
the check that clause (c) is read from N12-34's recorded result and from the same commit as the other three; the
receipt; the recording of GATE-WS-03's M1 part by a session that implemented none of the four clauses; the
planted refusals that show the recording cannot pass on mixed or dirty evidence.
Out: the script, its self-test and the assembler (N25b-05); the every-commit guard and clause (a) as a fact of
`cargo xtask check-deps` (N34-25); the corpus-wide comparison itself (N12-34); the recorder (N38b-19).

## Technical approach

1. Preconditions. N12-34's corpus-wide comparison has a recorded result on the current commit (its log and the
   verdict table, identical verdicts from the standalone binary and the in-tree verb on every specimen and
   mutant); the stable release named in `crates/frob-cert/rust-toolchain.toml` is installed on both hosts. A
   missing precondition is reported before any step runs and is not a pass.
2. Run. `scripts/e2e/auditor_independence.sh` (N25b-05) on a clean checkout of one commit, first on the Linux
   host (the record of the gate: the `strace` and network-namespace steps) and then on the Mac (supporting
   evidence: the deny-profile run). Its step 9 now finds N12-34's result and includes it as clause (c).
3. Receipt. The script's assembler writes one hash-named receipt with the four measured values against their
   thresholds (dependencies 0 against 0; offline build success; verdict disagreements 0 against 0 over the
   corpus, with the corpus size; sockets 0 against 0 and child processes 0 against 0), the binary digest per
   host, the commit and the resolution receipt of each clause. The assembler refuses clauses of different
   resolution receipts or from a dirty tree (N25b-05, step 10), so the gate line is `pass` only when all four
   hold on one commit, `fail` with the failing clause otherwise.
4. Record. `cargo run -p frob-conformance --example record_gate -- --gate GATE-WS-03 --receipt <hash> --part M1`
   (N38b-19), in a session that implemented none of the four clauses (the recorder refuses `self-certified`).
   The part names the four measured values, the receipt, the commit, the command, the host fingerprint and the
   recording session; the recorder commits the receipt at `receipts/gates/<hash>.json` and the same-run rule
   requires every control registered for the gate (among them CX-362's third plant,
   `shared-canonicalizer-drops-field`, registered with GATE-WS-03 and GATE-AUGUR-06) to appear in the receipt
   as `caught`, which the self-test run of step 2 supplies.

## Acceptance criteria

- [ ] On one clean commit the script exits 0 on the Linux host and on the Mac with all four clauses measured;
      clause (c) is read from N12-34's recorded result, and its corpus size and disagreement count (0) are in the
      receipt.
- [ ] GATE-WS-03's M1 part is recorded from that receipt with `--part M1`: `pass` only if all four clauses hold
      under one resolution receipt on a clean tree, recorded by a session that implemented none of them;
      otherwise `fail` with the failing clause named.
- [ ] Every control registered for GATE-WS-03 (among them CX-362's third plant) is listed `caught` in the
      receipt, so the recorder's same-run rule is met.
- [ ] Two planted inputs are refused before any record: a receipt assembled with clause (c) from another commit's
      comparison, and one with a clause measured on a dirty tree.
- [ ] The register's status view shows GATE-WS-03 as `pass` (or `fail`) at M1, never as passed from the M0
      receipt alone.

## Test plan

### Unit tests

This bead adds no library code. Its checks are the assertions of the script it runs and of the recorder.
`scripts/e2e/tests/auditor_independence_selftest.sh` (N25b-05) is run first, with its five scratch variants and
its two planted assemblies, now with clause (c) present: `mixed_resolution_refused` (clause (c) taken from a
comparison log of another commit: the assembler refuses and names the clause) and `dirty_tree_refused` (an
untracked change in `crates/frob-cert/` before the run: the assembler refuses). This bead adds one case,
`m0_receipt_not_recordable`: the M0 receipt (clause (c) `not run`) offered to the recorder in a scratch register
is refused with `gate-line-not-eligible` and nothing is written.

### End-to-end script and logging

`scripts/e2e/auditor_independence.sh` (N25b-05) is the script, run here at M1. It sources the STD-E2E helper and
writes `target/e2e-logs/auditor_independence/<utc-timestamp>.ndjson` and a transcript: every line has `ts`,
`script`, `bead` (`N25bp4-01` for this run), `step`, `event`, the exact command line, exit code and wall time;
`metric` lines for the four clauses against their thresholds; for clause (c) the path and digest of N12-34's
result, the corpus size and the disagreement count; per host the binary digest; on failure the first offending
value (the first disagreeing specimen with both verdicts, or the first offending system call with its arguments
and the saved trace path). A final `summary` names GATE-WS-03 and the receipt hash. The script never runs
`record_gate`: STD-E2E's linter fails a log that holds such a `cmd` line as `self-recording`, and a script
produces a receipt, never a record. Step 4 is run by the recording session after the script has passed and
linted, outside its log; that session keeps its command line and output with the record, and the recorded
status is read back from the register's status view.

### Known answers and negative controls

Known answers: `cargo tree -p frob-cert` prints one line; KA-211, KA-214, KA-215 and KA-223 through the audits of
N25b-05's step 5; on the corpus every specimen's standalone verdict equals the in-tree verdict (N12-34). Negative
controls: the five scratch variants of N25b-05 ((a) an added dependency, (b) a host-name lookup, (c) a child
process, (d) a read of `HOME`, (e) CX-362's `shared-canonicalizer-drops-field`), each of which makes the script
fail at its stated step; the two planted assemblies above; the M0 receipt offered to the recorder. Determinism:
verdicts are identical on both hosts and in debug and release builds (class D0); the binary digest is recorded per
host.

## Considerations

- The Linux trace is the gate's record; the Mac's deny profile shows the audit does not need the network or a
  child, not that it never tried, and is logged as supporting evidence.
- If N12-34's comparison finds a disagreement, clause (c) fails and the part is recorded `fail`; the repair is
  N12-34's or the auditor's, and this bead runs again on the repaired commit.
- The M1 exit review (BD-147) reads the part this bead records.
