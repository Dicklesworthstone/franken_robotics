## Background

A product engineer can pay to measure, store and transmit a calibration label for each manufactured variant. The
query asks for the minimum number of distinct labels that lets one controller serve all admitted variants and
payloads by a common commitment deadline. The information passed from manufacturing becomes a design variable
beside the mechanism and the sensor. A label that arrives after a decision is committed has zero value for it.

This is the label count of the information construction of the mathematical spine: with K_s the commands that
work for variant s, variants can share a label exactly when their sets have a common point, and the count is the
least number of colours of the hypergraph whose edges are the inclusion-minimal collections with empty
intersection. The shortcut it replaces is "variants that are pairwise compatible can share a controller"; the
replacement is minimal conflict sets, not pairs.

Honest scope (FACT, plan-time pilots re-run by BD-043): an independent SMT encoding returned unsatisfiable for
one shared label and satisfiable for two, with its own two-label witness; on the deadline fixture, belief-window
intersection and symbolic elimination agreed on all five cases. So ordinary elimination already answers the query
on supplied sets, and no advantage over an SMT or mixed-integer baseline is claimed. The open problem is
extraction of the sets from contact, which is Moonshot and has its own pilot and beads (N25c-39 to N25c-41).

Tier: Frontier on supplied sets. The seed's done-condition is GATE-AUGUR-19 and the decision of
KILL-AUGUR-LABELS; the gate is measured by N25c-38 and the decision recorded by N25c-40.

## Technical approach

**Definitions.** For a fixed observation-identical prefix let K_s be the set of commands that work for every
admitted payload and tolerance of variant s. A set of variants can share a label exactly when their command sets
have a common point. Build a hypergraph on variants with an edge for each inclusion-minimal collection whose
intersection is empty. The least number of labels is the least number of colours with no monochromatic edge.

**Bounds.** A colouring with one feasible command per colour certifies an upper bound; a checked impossibility
of colouring with one fewer proves minimality. For finitely many convex command sets in dimension m, Helly's
theorem bounds a minimal obstruction by m + 1 sets. Hidden contact modes can make the sets nonconvex and remove
that shortcut. If one variant has an empty command set on its own, no label makes the fixed-prefix mission
feasible.

**Query (DESIGN).** A `.fmission` whose design domain is the label map: variants, each with its command set as a
polytope (or a finite union of polytopes) in exact rationals, optionally an inner set and an outer set; the
objective `minimize: label_count` with claim `minimum-with-matching-lower-bound`. Surface:
`frob mission synthesize labels.fmission --json`.

**Algorithm.**

1. Admit: every K_s is nonempty (else return "infeasible for variant s on its own" with its emptiness
   certificate).
2. Minimal conflict sets. Enumerate subsets of variants by increasing size; test emptiness of the intersection
   by linear feasibility (per piece for unions); keep the inclusion-minimal empty ones. For convex sets stop at
   size m + 1; for nonconvex sets continue to the declared cap (DESIGN: 16 variants) and say so.
3. Colouring. Search exactly for the least k such that the variants can be partitioned into k classes with no
   class containing a conflict set (exhaustive up to the cap; branch and bound beyond small sizes).
4. Witness. For each class compute a common command (a point of the intersection, reconstructed over ℚ). Emit
   one `lp-primal` proof object per class.
5. Minimality. For k − 1: every partition into k − 1 classes has a class containing a conflict set. Emit the
   conflict sets, each with an `lp-farkas` proof of emptiness, and the statement that the hypergraph is not
   (k − 1)-colourable; the checker re-derives that statement by its own enumeration.
6. Output: the label map (variant → label), one command per label, the count with `attained: true`, and the
   conflict hypergraph.

**Inner and outer sets.** For a real commissioning question only inner and outer command sets may be known: a
constructive common action needs inner sets, an impossibility needs inconsistent outer sets. Run the algorithm
on the inner sets to get an upper count U (with witnesses) and on the outer sets to get a lower count L (with
conflicts). Return the interval [L, U]. When L < U, name the one measurement that would narrow the gap: the
variant and constraint whose inner-to-outer difference decides a conflict set that is empty for inner sets and
nonempty for outer sets.

```rust
pub struct LabelAnswer { lower: u32, upper: u32, map: Vec<(VariantId, LabelId)>, commands: Vec<(LabelId, Command)>,
                         conflicts: Vec<Vec<VariantId>>, narrowing: Option<MeasurementRef>, proofs: Vec<ProofRef> }
```

**Evidence.** `Certified` (exact rationals, class D0) for polyhedral sets; the answer carries its assumptions:
fixed prefix, supplied sets, labels delivered before commitment on a clean channel unless a channel is declared.

## Test plan

### Unit tests

- `three_variants_two_labels` (KA-644): commands (x, y) ∈ [0, 1]²; variants require x ≥ 2/3, y ≥ 2/3 and
  x + y ≤ 1. Every pair intersects; the triple does not (x + y ≥ 4/3 against x + y ≤ 1). Two labels suffice:
  (2/3, 2/3) for the first two and (0, 0) for the third. One label is impossible. Exactly three two-label
  partitions are valid.
- `helly_bound`: in dimension 2 no minimal conflict set has more than 3 convex sets (property test on 500
  random polytope families).
- `nonconvex_exceeds_helly` (synthetic): four variants on a one-dimensional command, each K_s the union
  {1, 2, 3, 4} minus {s} (as small intervals): every three share a point, all four share none; the minimal
  conflict has 4 sets although m + 1 = 2.
- `empty_single_set`: one variant with K = ∅.
- `label_interval` (synthetic): outer sets are the three-variant fixture (L = 2); inner sets are shrunk so that
  no pair meets (x ≥ 5/6 and y ≤ 1/12; y ≥ 5/6 and x ≤ 1/12; x + y ≤ 1/2 with x, y ≥ 1/4), giving U = 3. The
  answer is [2, 3] and the narrowing measurement names a pair whose inner sets miss and whose outer sets meet.
- `colouring_matches_bruteforce`: 200 random families of at most 8 variants.

### End-to-end script and logging

`scripts/e2e/mission_labels.sh` (bead N25c-38) runs `frob mission synthesize` on the label fixtures and verifies
the bundles. Logged: commands, exit codes, wall time, evidence block, label counts against expected values, the
conflict sets, commands per label as exact rationals, bundle digests.

### Known answers and negative controls

- KA-644 as above. CX-271: variants that are pairwise compatible can share a controller: false (the triple
  needs x + y ≥ 4/3 and x + y ≤ 1).
- Negative control: a pairwise-graph colouring (edges only for pairs) returns one label on the three-variant
  fixture and must be caught.
- Negative control: a lower bound computed from inner sets, or an upper bound from outer sets (polarity
  exchanged), yields an interval that excludes the exact count on a constructed instance.
- Metamorphic: permuting variants or applying one affine map to all command sets leaves the count unchanged.
- Determinism: exact arithmetic; identical answer bytes across hosts and worker counts.

## Considerations

- Kill gate KILL-AUGUR-LABELS (M4). Trigger: deriving command sets costs more than labelling every part, or an
  inner set contains a failing command. Fallback: the query is kept for supplied sets through a conventional
  solver; extraction from contact is parked. The fallback leaves this bead's surface intact.
- The first purchase decision for a real line is whether deriving command sets from a qualified gripper is
  cheaper than testing or labelling every part directly; this bead cannot answer it.
- Exact colouring is exponential in the number of variants; the cap is declared and enforced at admission.
