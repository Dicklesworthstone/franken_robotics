## Background

`mission.transport` is one of the nine verbs of the `mission` cluster (VERBS-mission), owned by `frob-mission`
(layer 5). Its
contract: return a map between task interfaces and a local policy with a bounded error, or a counterexample
naming the contact mode where authority is lost. A design agent uses it to reuse a carry or step skill on another
morphology and retrain only the named modes.

Two registered verbs transport, and their scopes differ. `mission.transport` moves a certified claim through an
interface map: its output is a proof object or a counterexample and nothing in it is learned. `skill.transport`
moves a skill artifact (`.fskill`) to another body with a learned residual and is Moonshot. A skill moved by
`skill.transport` carries no certified claim across unless `mission.transport` has issued the interface
certificate for the same pair of bodies. Neither verb stands in for the other.

This bead builds the Frontier part, called the static core, which the verb registry schedules at M4 (the full
verb is M8). The static core answers one question per contact mode: does the target's reachable wrench set at the
task interface cover the wrench set the skill requests? That is a polytope or cone containment, so it is certified
with the existing proof kinds `lp-primal` (a feasible point per vertex) and `lp-farkas` (a dual vector showing a
vertex is unreachable). Reason for the design (DESIGN): a quadruped and a wheeled carrier have fundamentally
different support transitions, so nothing about the support pattern is ported; only the task-level objective
(tray stabilization) and its feedback state are, and only where coverage is proved.

Rejected alternative: certify the transfer by comparing closed-loop rollouts of the two robots. A rollout refutes
one controller on one world; it proves nothing about the set of wrenches a mode can deliver.

## Scope

In: the `TaskInterface` and `TransportQuery` types; the per-mode coverage test with its two proof objects; the
counterexample output; the ported-objective record; the verb's static path, envelope and refusals; one
independent second lowering of the coverage problem (proof obligation PO-AUGUR-01).

Out: the alternating-simulation relation over dynamics (N25c-03); chance and expected-value claims (the coupling
budget and claim kinds of N25e-02, which extends this bead); the learned residual (`skill.transport`); the experiment and gate (N25c-04).

## Technical approach

**Types (DESIGN sketch; intent, not signatures).**

```rust
pub struct TaskInterface {
    frame: FrameId,                    // task frame, with origin, axes, handedness and sign conventions
    observables: Vec<ObservableId>,    // each with its arrival instant in the clock contract
    command: CommandKind,              // Wrench | Twist | Effort
    predecessor: SetRef,               // states from which the skill may start
    terminal: SetRef,                  // states in which it may end
    clock: ClockAssumption,            // rate and latency the skill was qualified under
    environment: AssumptionSet,        // friction floor, payload range, slope range
    requested: WrenchPolytope,         // vertices r_1..r_k from allowable contact wrench and acceleration limits
}
pub struct TransportQuery { skill: SkillId, source: DesignId, target: DesignId, interface: TaskInterface,
                            states: StateSet, modes: Vec<ContactModeId> }
pub enum TransportAnswer {
    Covered { per_mode: Vec<(ContactModeId, Vec<ProofRef>)>, ported: PortedObjective },
    LostAuthority { mode: ContactModeId, requested: Wrench, direction: Vec<Ratio>, support: Ratio,
                    gap: Ratio, binding: BindingRef, counterexample: ReplayAddress, proof: ProofRef },
    Unresolved { mode: ContactModeId, why: Explanation },
}
```

**Algorithm.**

1. Admit. Both designs must expose the interface: every observable exists on the target with an arrival instant
   not later than the decision (else `FROB-REF-847`); frames, units and port order match the interface
   definitions (else `FROB-REF-850`); the target declares the authority the skill assumes (else `FROB-REF-851`).
2. For each admitted contact mode m of the target and each state (or state cell) in `states`, obtain the affine
   map w = w₀(q, v) + B_m(q)·u from actuator effort u to the task-space wrench, from the constrained mass solve
   of the skill layer (the per-mode maps of `skill.compile`).
3. Coverage. For each vertex r_j of the requested polytope solve: find u in the actuator boxes and contact forces
   f_c in their cones with w₀ + B_m·u = r_j. The proposer may use floating point; the active set is then solved
   exactly over ℚ and the result is an `lp-primal` proof object (the rational u and f_c per vertex).
4. Non-coverage. If a vertex is infeasible, emit an `lp-farkas` proof object: a rational dual vector y such that
   yᵀr_j exceeds the support value of 𝒜_m in direction y. Report the direction, the support value, the gap and
   the binding actuator or contact. The relaxation is written in the box form the `lp-farkas` checker reads
   (A·f = w with 0 ≤ f ≤ c, every cᵢ finite): each actuator effort is shifted to u − u_lo ∈ [0, u_hi − u_lo]
   (the constant moves into w), and each contact force is a nonnegative combination of its polyhedral cone's
   generators whose coefficients are capped by the declared normal-force limit of that contact (DESIGN: the
   contact card's limit, or the target's weight times the declared load factor when the card gives none). The cap
   is an assumption of the proof and is listed in the bundle; an uncapped cone is not lowered.
5. Approximation polarity (DESIGN). Friction cones are second-order. A coverage claim uses an inscribed
   polyhedral cone (an inner set of attainable wrenches), so a pass is sound. A non-coverage claim uses a
   circumscribed polyhedral cone (an outer set), so a failure is sound. A vertex that passes outside and fails
   inside is `Unresolved` with the reason `StraddlesThreshold`.
6. On coverage of every mode: return the ported objective (the tray stabilization cost and its feedback state)
   and state that residual motions are resolved by whole-body inverse dynamics on the target.
7. On lost authority: return the contact mode, the requested wrench, the attainable set (its support function in
   the failing direction) and a counterexample that re-runs on the referee (a replay address at which the target
   in mode m fails to deliver the wrench).

**Scope of the claim.** Coverage is instantaneous: a feasible witness at each listed state is necessary and not
sufficient for dynamic transfer. Over a state cell the map (w₀, B_m) is enclosed with outward-rounded intervals
and the cell is covered only if every vertex is feasible for the whole enclosure; otherwise the answer lists
states, not a cell. The answer's assumptions say: static coverage at the listed states or cells; a successful
transfer of a skill segment does not certify the remainder of the mission.

**Surface.** `frob mission transport <skill> --from d:… --to d:… --interface tray.json --key tr-1 --json`
(`--lowering <vertex|facets>` selects the second lowering of PO-AUGUR-01; vertex by default; registered for this
bead in the verb's row of VERBS-mission from M4). Kind `run`, so every call carries an idempotency key;
accepts `--estimate` and a budget; returns the standard envelope. Evidence: covered and lost-authority cells are
`Certified`, tier `static`, determinism `exact`; the replayed counterexample is a `trace-witness`, class
`Tested`. The claim class of the answer is the weakest among its cells. The `authorization` object carries the
three no-authorization flags, all `false`. The ledger records the query digest, the per-mode maps' digests, the
proof objects and the bundle hash.

**Refusals.** `FROB-REF-847` (an observable without an arrival instant, or used before it arrives);
`FROB-REF-850` (frame, unit, sign or port-order mismatch, for example a first moment passed as a torque);
`FROB-REF-851` (an authority the design does not declare); a transported chance claim without a coupling budget
is refused under the coupling rule (N25e-02's; raised meanwhile as 852 with `detail: coupling-budget-missing`);
a request for the dynamic relation, `--relation compute`, is accepted by name and refused with `FROB-REF-724`
(exit 5, capability not implemented) with the static core named as the available scope, until N25c-03 enables
it at M8. A refinement that selects only the stable branch of a set-valued successor is rejected
(`FROB-REF-444`). These are the verb's codes; a bundle re-checked by `prove.verify` or `frob-verify` reports the
Lemma column of BD-133's mapping instead (a frame, unit, sign or port-order mismatch and an undeclared authority
or omitted active bound are both `FROB-REF-829` there).

## Test plan

### Unit tests

`crates/frob-mission/tests/transport_static.rs` (exact rationals, the real `lp-primal` and `lp-farkas` checkers
in process, no mocks):

- `coverage_two_link_exact`: the arm of the pilot bead; expected values above, in exact rationals.
- `coverage_polarity`: a wrench that is inside the circular cone and outside the inscribed pyramid is
  `Unresolved`, never `Covered`.
- `coverage_cell_enclosure`: over a joint-angle cell that contains a singular posture the answer is `Unresolved`.
- `lost_authority_reports_mode`: on a synthetic two-mode target (mode 1 limits 2.5 N·m, mode 2 limits 4 N·m)
  with a 10 N request, only mode 1 is reported lost.
- `second_lowering_agrees` (PO-AUGUR-01): both lowerings give identical verdicts on 1,000 generated polytopes.
- `refusals_847_850_851`: an observable that arrives after the decision, a swapped port order, and an authority
  the target does not declare are refused with their codes before any solve.
- `branch_selection_refused_444`: a refinement that keeps only the stable successor of {stable, fall} is refused.
- `dynamic_relation_exit_5`: `--relation compute` is refused with `FROB-REF-724`, exit 5, naming the static core.
- `cancel_drains`: a run cancelled between modes returns the modes already decided with their proofs and the rest
  `Unresolved`.

### End-to-end script and logging

`scripts/e2e/mission_transport_static.sh`, written by this bead so that the M4 surface has its own script (the
M8 experiment script `scripts/e2e/mission_transport_tray.sh` of N25c-04 calls this one first as its
self-check). Steps, each through the real `frob` binary with explicit seeds:

1. `frob mission transport <two-link skill> --from d:… --to d:… --interface two-link-8N.json --key ts-8n-<seed>
   --json`: assert `Covered`, exit 0, and the witness torques (∓12/5, ∓12/5) N·m at the vertices (±8, 0) N.
2. The same at the 10 N request (`--key ts-10n-<seed>`): assert `LostAuthority`, direction (1, 0), support
   25/3 N, gap 5/3 N, joint 2 binding.
3. `frob prove bundle a:… --out <dir> --key ts-bundle-<n> --json` for both answers, then `frob prove verify
   <dir>/<bundle>.frobcert --json` on both bundles on the CPU-only host: assert accepted.
4. The tray fixture of the pilot (carrier to quadruped, `--key ts-tray-<seed>`): assert `LostAuthority` only in
   the crest mode, then replay the counterexample with `frob sim replay --run <r> --world <w> --episode <e>
   --from <tick> --key ts-replay-<seed> --json` (the fields of the answer's replay address, as the row of
   `sim.replay` takes them) and assert the referee shows the loss at the logged instant.
5. The four mutations below, each as a bundle edit followed by `frob prove verify` (a read verb, the Lemma
   column of BD-133's mapping): assert each is rejected, the port-order swap and the omitted cone rows with
   `FROB-REF-829` and the rule named, the flipped dual and the screw-Jacobian rows by the `lp-farkas` or
   `lp-primal` rule named in the rejection; then the admission refusals on the verb itself through
   `e2e_expect_refusal` (847, 850, 851, exit 3, each with its own key), and `e2e_expect_refusal FROB-REF-724 5 --
   frob mission transport … --relation compute --key ts-relation-<seed> --json`: the static core named.
6. The second lowering (`--lowering facets`, with keys `ts-facets-<fixture>-<seed>` distinct from steps 1, 2 and
   4) on both fixtures: assert verdicts identical to the vertex program.

It sources the shared helper of STD-E2E and writes NDJSON to
`target/e2e-logs/mission_transport_static/<utc>.ndjson` with a transcript beside it: per step `ts`, `script`,
`bead`, `step`, `event`, the exact command, exit code, wall time, the envelope's evidence block, the per-mode
support values against the requested values with units, the bundle digest, refusal codes with their first
repair, and on failure the first differing value and the bundle and replay paths. The summary line names
KILL-AUGUR-TRANSPORT as the decision this static core informs.

### Known answers and negative controls

- Known answer: 25/3 N against 10 N; τ = JᵀF = (−0.3·F_x + 0.4·F_y, −0.3·F_x).
- Mutations of a written bundle that `prove.verify` and `frob-verify` must reject: a swapped port order with
  unchanged forces (`FROB-REF-829`, the frame/port-order rule; the verb itself reports 850 for the same mismatch
  in a query); the dual vector with one sign flipped (rejected by exact recomputation under the `lp-farkas`
  rule); a `Covered` certificate that omits the contact-cone rows (`FROB-REF-829`, the omitted-bound rule; 851 on
  the verb); the lower rows of a space-frame screw Jacobian used in place of the point Jacobian (the per-vertex
  equality fails under the `lp-primal` rule).
- Metamorphic: scaling all wrenches and limits by a positive rational leaves verdicts unchanged; a change of task
  frame with wrenches transformed by the same isometry leaves verdicts unchanged.
- Determinism: bundle digests identical twice on one machine, across worker counts and across two hosts (D0).

## Considerations

- Floating base: a fixed-base pullback τ = JᵀF is wrong for a floating-base robot; the map must come from the
  contact-consistent constrained solve. The checker cannot detect a wrong map: the primitive equations travel in
  the bundle for review.
- If KILL-AUGUR-TRANSPORT fires at M8 the static core survives as a static analysis; nothing else is kept.
- No speed claim. The value is the named mode.
