## Background

The static core of `mission.transport` (N25c-02) proves that a target robot can deliver, mode by mode, the
wrenches a skill asks for at its task interface. That is a statement about one instant. The stronger goal is to
tell an agent which part of a closed-loop skill carries over to a new embodiment as a whole: a relation between
the two closed loops under which every guarantee proved for the source at its task interface also holds for the
target. This is the Moonshot part of the verb. It is behind a feature flag, off the critical path, and exists
only if KILL-AUGUR-TRANSPORT does not fire (N25c-05).

The object is a relation R(x_A, x_B) between source states and target states, and a causal refinement map from
abstract commands (those of the source skill at the task interface) to target efforts. The relation is an
alternating simulation: the controller chooses, then the environment chooses. That order is the whole point. A
target whose successors are {stable, fall} cannot refine an abstract transition whose only successor is stable by
selecting just its stable branch, because the environment picks the branch, not the controller.

Rejected alternatives. An ordinary (non-alternating) simulation, which lets the proof pick favourable target
branches and so certifies falls as successes. A learned similarity score between embodiments, which is not a
proof object and cannot name the mode that breaks.

## Scope

In: the relation and refinement-map types; the four refinement conditions as checkable obligations; approximate
relations with error and timing budgets; a fixed-point checker on finite abstractions; the counterexample output;
classing of what cannot be enclosed.

Out: the static wrench-coverage test (N25c-02); chance and expectation claims (the coupling rule of another
unit); the learned residual of `skill.transport`; the three-treatment experiment (N25c-04).

## Technical approach

**Conditions.** Seek R and a refinement map κ such that:

1. every admitted initial target state is related to an abstract state compatible with its observable history;
2. for each permitted abstract command, the implementable interface selects one target command using only
   information available before disturbances act;
3. for every admitted target disturbance and every resulting target successor, there is an allowed abstract
   successor related to it, respecting any shared disturbance law;
4. observations, task outputs, timing and target progress are preserved.

**Approximate relations.** A relation may hold up to an error budget ε_y on task outputs and a timing budget δ_t
on event and deadline instants. It is admitted only when both budgets are small enough to preserve the mission's
acceptance predicates: each predicate atom with margin m must still hold when its argument moves by ε_y and its
instant by δ_t. The budgets are part of the certificate, and an atom with no declared margin admits only an exact
relation.

**Checker on a finite abstraction (DESIGN).**

1. Abstract the source skill at its task interface into a finite transition system: cells of the interface state,
   the permitted abstract commands, and for each (cell, command) the set of allowed successors, taken from the
   source's own certificate.
2. For the target, per contact mode, compute for each (cell, target command) an outer enclosure of the successor
   set over all admitted disturbances. Where no sound enclosure exists the pair is marked unenclosed.
3. Compute the greatest relation by fixed-point iteration: start from all pairs with equal observations and task
   outputs (within ε_y); remove a pair (x_A, x_B) if for some permitted abstract command a no target command
   u = κ(a, information available before the disturbance) makes every enclosed target successor related to some
   allowed abstract successor of (x_A, a); repeat until nothing is removed.
4. The relation is accepted if every admitted initial target state remains related. The strategy κ is then a
   table keyed by observation history.
5. If an initial state is removed, walk the removal reasons back to the first (cell, command, mode) that had an
   unmatched target successor: that is the counterexample, returned with its contact mode and a replay address.

**Certificates (DESIGN, fail-closed).** On a finite abstraction the refinement check is a finite two-player
safety game, so the winning table is emitted as a `finite-game` proof object (the checker re-plays every
environment choice and checks that equal histories receive equal commands), with `interval-box` sub-certificates
for each successor enclosure and `composition` sub-certificates where stages chain. The closed registry has no
kind named for refinement. Until the Lemma lead decides whether one is needed, nothing beyond the static core is
issued as `Certified` unless it fits these existing kinds exactly; an unenclosed pair makes its cell
`Unresolved` with `Tested` trajectories attached, and the answer's class is then at most `Tested`.

**Monotone use.** The same four conditions are the side conditions for moving an inclusion upward along a design
order (a wider sole, a longer stroke): disturbances admitted at the new design are admitted at the old, the
witness controller is realizable with the same or a finer observation history, outputs still satisfy the
predicate, and every new branch is simulated by an old one. A transport with a missing condition is rejected
(`FROB-REF-852`), never weakened.

**Surface.** `frob mission transport <claim> --from d:… --to d:… --interface <map> --relation compute --key <k>
--json` (feature flag `transport-relation`; `mission.transport` is a run verb, so every call carries an
idempotency key). `--relation compute` asks the checker to compute the greatest relation on the finite
abstraction; `--relation <relation.json>` (N25e-02's spelling for finite models) supplies a relation that is
checked, never trusted; both answer through the same fixed-point checker. Output: the map, the local policy
table with its error budget, or `LostAuthority` naming the mode. The `mission.transport` row of VERBS-mission
registers both values: `--relation compute` is accepted by name from M4 and refused with `FROB-REF-724` (exit 5)
and the static core named until this bead enables it at M8 behind the flag, and again after
KILL-AUGUR-TRANSPORT fires, so that the static core's script (N25c-02) and the decision script (N25c-05) make
the request by name. Without the flag the request keeps the 724 refusal. Determinism: exact on the finite
abstraction (D0 for the table bytes).

## Acceptance criteria

- [ ] The branch-selection fixture (below) is refused: the relation is empty and the counterexample names the falling successor.
- [ ] On the exact finite fixtures the relation, the table and the counterexamples equal a brute-force enumeration.
- [ ] An approximate relation whose budget exceeds a predicate's margin is refused with the atom named.
- [ ] Every accepted table is checked by `frob-verify` as a `finite-game`; a table that gives different commands to equal histories is rejected.
- [ ] Cells with an unenclosed successor are `Unresolved`; no such cell is reported `Certified`.
- [ ] The feature is off by default and the answer names its scope; KILL-AUGUR-TRANSPORT is recorded as not fired before work starts.
- [ ] `scripts/e2e/mission_transport_relation.sh` passes with the logging listed below.

## Test plan

### Unit tests

- `branch_selection_refused` (synthetic): abstract system with one state s, one command a, successor {stable}.
  Target with one command and successors {stable, fall}. Expected: no relation; counterexample = (s, a, fall).
- `exact_relation_two_gain` (synthetic): source successor on command a is {x + 1}; target with hidden gain
  g ∈ {1, 2} and an on-time reading admits κ(a) = 1/g; with the reading late no κ exists. Expected: related
  with the reading on time, empty when late.
- `budget_respects_margin`: predicate y ≤ 1 with margin 1/10; ε_y = 1/20 accepted, ε_y = 1/5 refused.
- `fixed_point_matches_bruteforce`: 200 random finite systems with at most 6 states, 3 commands, 3 disturbances.
- `shared_disturbance_law`: when source and target share a disturbance, a match that uses different disturbance
  values on the two sides is not a match.

### End-to-end script and logging

`scripts/e2e/mission_transport_relation.sh`, written by this bead (the experiment script of N25c-04 runs before
the kill decision this bead waits on, so it cannot exercise the relation path). Steps through the real `frob`
binary under the feature flag `transport-relation`:

1. `frob mission transport branch-select.fskill --from d:src --to d:tgt --interface branch.json --relation compute
   --key mtr-branch-<seed> --json` on the branch-selection fixture: assert the relation is empty, exit 2 with findings,
   and the counterexample (s, a, fall) with its replay address. Every later call carries its own key
   (`mtr-<fixture>-<seed>`), so that no two compared calls return each other's stored receipt.
2. On the two-gain fixture with the reading on time: assert a related answer and a `finite-game` table with
   κ(a) = 1/g; then with the reading late: assert empty, naming the late reading.
3. The approximate fixture: ε_y = 1/20 accepted and ε_y = 1/5 refused with the atom `y ≤ 1` named.
4. The tray fixture (carrier to quadruped): assert `LostAuthority` at the crest mode, then `frob sim replay --run
   <run> --world <w> --key mtr-replay-<seed> --json` of the counterexample shows the loss; every cell with an unenclosed successor is `Unresolved`, none `Certified`.
5. `frob prove verify` on every bundle; the mutated table that gives different commands to equal histories is
   rejected.
6. With the flag off: assert the verb answers with the static core and names its scope, and that `--relation
   compute` is refused with `FROB-REF-724`, exit 5.

It sources the shared helper of STD-E2E and writes NDJSON to
`target/e2e-logs/mission_transport_relation/<utc>.ndjson` with a transcript beside it: per step the exact
command, exit code, wall time and evidence block, with `ts`, `script`, `bead` (`N25c-03`), `step` and `event` on
every line; the relation size per iteration, the removed pairs with their
reasons, the counterexample's mode and replay address, refusal codes, the bundle digest; on failure the first
differing value and the bundle and replay paths; a summary line with counts and KILL-AUGUR-TRANSPORT named.

### Known answers and negative controls

- Known answer: the branch-selection case; the two-gain case (related on time, empty late).
- Negative controls: an ordinary simulation checker substituted for the alternating one accepts the
  branch-selection fixture and must be caught; a refinement map that reads the disturbance before choosing the
  command is rejected as non-causal; a relation proved for fixed-shape gain changes is not applied across the
  replacement of a wheel or a limb.
- Determinism: the table bytes are identical twice on one machine and across worker counts.

## Considerations

- Ceiling: possibly nil on changed-support transfers; the claim is localization of what must be retrained.
- The enclosure of target successors through contact is the hard part and has no owner in the suite. The
  mechanism may therefore certify only quasi-static and finite cells for a long time, and says so.
- Kill gate: KILL-AUGUR-TRANSPORT. Trigger: the interface arm needs as many target trials as the conditioned
  policy, or reports coverage where the referee shows a fall. Fallback: family policies and inheritance; the
  wrench-coverage test is kept as a static analysis. If it fires, this bead closes as superseded.
- Counts toward the cap of four active Moonshot items.
