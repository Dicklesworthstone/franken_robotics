## Background

A certificate proves a statement about a declared set of worlds. Widen that set by a hair and the statement may
be false everywhere. The docking family shows it in the smallest possible case: keep the packet, the deadline
and the exact target, and admit one more hidden gain, 33/32. Exact docking becomes impossible, and every label
that was feasible under the two-gain mission is wrong under the three-gain mission. On the plan-time native grid
all 34,590 nominally feasible labels of each 65,536-row screen reverse (FACT, re-run by the pilot bead).

The rule this fixture enforces everywhere in the mission chapter: **gain support, delivery deadline, error units
and target tolerance are bound to a classifier's eligibility.** A screen compiled for the gain set {1, 2} is not
reused on {1, 33/32, 2}. The tempting shortcut it kills: "a certificate that held for the declared worlds holds
when a world is added".

This matters for speed work as much as for correctness: a compiled screen, a cached classifier or a GPU kernel
is exactly the kind of object that gets reused across "almost the same" missions. The eligibility record is what
stops that reuse.

## Scope

In: the eligibility record attached to every classifier, screen and certificate of the docking family; the
reuse refusal; the amended three-gain game and its exact answer; the withdrawal of previously positive cells; the
report of the least worst-case error. Out: the two-gain game (BD-129); the full revalidation engine and its
polarity table (BD-292); the device screen (BD-190, BD-355); the finite-tolerance game on a gain interval
(N25e-31 and N25e-32).

## Technical approach

**Eligibility record (DESIGN).** Every reusable object derived from a mission (a compiled screen, a policy
table, a certificate) stores

```rust
pub struct Eligibility { mission: MissionId, hidden_support: Vec<HiddenSupport>,   // e.g. g ∈ {1, 2}
                         deadlines: Vec<(PacketRef, Instant)>,                     // arrival before decision k
                         error_units: Vec<(ChannelRef, Unit, Ratio)>,              // ε and its unit
                         tolerances: Vec<(AtomRef, Comparator, Ratio)> }           // exact target: x₃ = 1
```

`HiddenSupport` (DESIGN) names a hidden parameter and its declared support: a finite set of exact rationals (the
docking gains {1, 2}) or a closed interval with rational ends (the gain interval [1, 2] of N25e-31 and N25e-32,
which use this record). Two supports are equal only when they are the same set: {1, 2} and [1, 2] differ.

**Reuse surface (DESIGN; this bead owns it, N25e-32 applies it to the gain interval).** `mission.synthesize`
and `mission.refute` take `--reuse <stored screen, classifier or bundle>`, which offers the artifact as
caller-supplied evidence under BD-133's rule for caller evidence (step 7: a failing caller artifact is refused
with exit 3). Before any use, the artifact's record is compared field by field with the query. Any difference in
hidden support, delivery deadline, error units or target tolerance refuses the reuse with `FROB-REF-854` (a
classifier, screen or certificate is reused outside its eligibility): exit 3, `retry: after-change`, `pointer`
at the first differing field of the query (for the amendment below `/world/hidden/g`), `observed` the
artifact's value, `required` the query's, nothing published. A matching record passes on to the ordinary check
of caller evidence, so the check is not a blanket refusal of `--reuse`. The first repair is revalidation
(`mission.revalidate` in the registry row). That verb answers from M3 (N25a-16); until then the repair carries
the ready command of the same engine's M1 surface, `frob result revalidate a:<answer the artifact came from>
--against q:<this query>` (N25a-13; two verbs over one engine), so the first repair an M1 caller is handed
runs. Further repairs, in rank order: recompile for the new support (the same query without `--reuse`);
restore the original eligibility. Because each of those fields is part of the mission identity, the two
missions also have different `MissionId` values (INV-AUGUR-03); the eligibility record makes the reason
readable.

**The amended game.** Hidden gain g ∈ {1, 33/32, 2}; U = 3/4; ε = 1/64; packet on time; exact target. For every
first command p with abs(p) ≤ 1 the reading (65/64)·p is possible for both g = 1 (error +p/64) and g = 33/32
(error −p/64), since abs(p)/64 ≤ ε. So for every admissible first command those two worlds can deliver the same
packet history, and a causal controller gives them the same remaining commands. With final velocity zero the
final positions are c and 33·c/32, where c = 2·p + u₁. They cannot both equal 1.

**Answer.**

- Exact docking: excluded, by an `alias-pair` proof with scope "all admitted probes" (the pair of worlds
  g = 1 and g = 33/32, the common reading (65/64)·p for each p, and the disjoint success sets c = 1 and
  c = 32/33).
- Least worst-case error: minimize over c the larger of abs(c − 1) and abs(33·c/32 − 1). The two are equal at
  c = 64/65, where both are 1/65 m. That value is attainable with zero final velocity inside the command bound.
  The answer reports "no exact docking; best worst-case error 1/65 m" as a `feasible-candidate` bound for the
  amended requirement, with the witness command and the alias pair that makes it a lower bound.
- General statement recorded in the answer's assumptions: with bounded probes and ε > 0, a nondegenerate
  interval of hidden positive gains contains an indistinguishable pair that requires different second commands,
  so an exact docking guarantee fails; a finite position tolerance must be declared.

**Withdrawal.** Applying the amendment to a stored two-gain answer:

1. Enlarging the world family is the polarity "inclusion must be rechecked; exclusion is preserved when its
   witness lies in the old set and the policy class and information contract are unchanged". At M1 that
   polarity is the expected outcome, not a licence to skip work: the M1 revalidation engine (N25a-13) has
   grades 1 and 2 only, and every proof of the docking answer reads `world.hidden.g`, so
   `frob result revalidate a:<two-gain answer> --against q:<three-gain query>` invalidates every cell (exit 2,
   each with the reason "reads world.hidden.g", grade 4 in the mask) and inherits none. The polarity rule that
   lets the engine skip the recheck of the exclusions arrives with BD-292 at M3.
2. Re-solving the invalidated cells (`frob mission synthesize --from <revalidated answer>`, N25a-13 step 6)
   rechecks every inner cell of the two-gain grid (344 of 561 at the fixture's grid) under the three-gain
   support; every one with ε ≥ 1/64 is withdrawn, each withdrawal naming its counterexample: the two worlds
   g = 1 and g = 33/32 and their common reading (65/64)·p.
3. Every excluded cell stays excluded: the re-solve emits its `alias-pair` proof for the pair g = 1, g = 2
   again, both worlds still lie in the amended support, and the checker accepts it for the new `MissionId`.
4. The withdrawals are logged; an inner cell leaves the inner set only through a logged withdrawal that names
   its counterexample (INV-AUGUR-04).

Which cells reverse: for a cell (U, ε) with ε > 0, the worlds g = 1 and g = 33/32 alias for every probe with
abs(p) ≤ 64·ε; since probes satisfy abs(p) ≤ U ≤ 1, every cell with ε ≥ 1/64 loses exact docking. At ε = 0 the
reading identifies the gain and exact docking survives (the 17 cells of the row j = 0). The gate's phrase "the
three-gain amendment withdraws every positive cell" refers to the amendment's stated error ε = 1/64 and above;
the implementation reports per cell.

**Surface.** `frob mission synthesize docking.fmission --set world.hidden.g='{1, 33/32, 2}' --key <key> --json`
(a run verb: every call carries its own key) returns the amended answer (exact docking excluded, 1/65 m); `frob result revalidate` and the re-solve of steps 1 and 2
above return the withdrawals of the stored two-gain answer; the same query with `--reuse <two-gain bundle>` is
refused with `FROB-REF-854`; `frob mission show` on the old answer still works (answers are immutable) and marks
it as answered for another `MissionId`.

## Acceptance criteria

- [ ] The eligibility record is stored with every docking screen, table and certificate; code in `crates/frob-mission` (`eligibility.rs`).
- [ ] A screen compiled for {1, 2}, passed with `--reuse` to the {1, 33/32, 2} query, is refused with `FROB-REF-854`, exit 3, pointer `/world/hidden/g`, first repair revalidation whose ready command in an M1 build is `frob result revalidate a:… --against q:…` and answers (exit 2); the same artifact passed with `--reuse` to the two-gain query is accepted.
- [ ] The amended answer excludes exact docking with an `alias-pair` proof accepted by `frob-verify`, and reports 1/65 m at c = 64/65.
- [ ] `frob result revalidate` of the two-gain answer against the three-gain query invalidates every cell and inherits none (M1 grades); after the re-solve every previously inner cell with ε ≥ 1/64 is withdrawn with a named counterexample; every previously excluded cell stays excluded with its re-emitted `alias-pair` proof accepted; the ε = 0 row is reported separately and survives.
- [ ] Changing only the delivery deadline, only the error unit, or only the target tolerance also refuses reuse.
- [ ] The withdrawal log exists and each entry resolves to its counterexample.
- [ ] `scripts/e2e/mission_docking_amendment.sh` passes with the logging below.

## Test plan

### Unit tests

- `alias_reading_three_gain`: for p ∈ {−3/4, 1/4, 5/8, 3/4} the reading (65/64)·p lies in both
  [p − 1/64, p + 1/64] and [(33/32)·p − 1/64, (33/32)·p + 1/64].
- `least_worst_error`: min over c of max(abs(c − 1), abs(33·c/32 − 1)) = 1/65 at c = 64/65.
- `witness_within_bounds`: p = 1/4, u₁ = 64/65 − 1/2 = 63/130, u₂ = −p − u₁ = −191/260 are within 3/4 and give
  v₃ = 0 with x₃ = 64/65 for g = 1 and 66/65 for g = 33/32 (error 1/65 m each). For g = 2 the reading set
  [2·p − ε, 2·p + ε] is disjoint from the other two (p > (64/31)·ε), and the commands (0, −1/4) dock exactly.
- `withdrawal_counts`: the M1 revalidation mask of the two-gain answer against the three-gain query has grade 4
  for every proof (each reads `world.hidden.g`) and no inherited cell; after the re-solve, of the 344 admitted
  two-gain cells the 17 with ε = 0 survive and the other 327 are withdrawn, each naming g = 1, g = 33/32 and the
  reading (65/64)·p; all 217 excluded cells stay excluded with an accepted `alias-pair` proof for g = 1, g = 2.
- `eligibility_four_fields`: four mutated queries (support, deadline, error unit, tolerance) each refused with
  `FROB-REF-854` and a pointer at the mutated field; an identical query is accepted.
- `set_and_interval_supports_differ`: a record with support {1, 2} offered to a query with g ∈ [1, 2] is refused
  with `FROB-REF-854` (pointer `/world/hidden/g`, observed `{1, 2}`, required `[1, 2]`).
- `first_repair_runs_at_m1`: built against a capability set without a `mission.revalidate` handler (an M1
  build), the 854 refusal's first repair carries the command
  `frob result revalidate a:<two-gain answer> --against q:<three-gain query>`; against a set that has the
  handler (M3 on) it carries `frob mission revalidate a:… --after-edit e:…`; the second repair is the query
  without `--reuse`. The end-to-end script runs the M1 command and asserts that it answers.
- `mission_id_changes`: the amended mission has a different `MissionId`.

`scripts/e2e/mission_docking_amendment.sh`, this bead's own, on BD-129's mission files (every run-verb call

… --json` (the two-gain answer) and `frob prove bundle a:<it> --out two-gain/ --key … --json`; (2) `frob mission
synthesize docking.fmission --set world.hidden.g='{1, 33/32, 2}' --key … --json`: exact docking excluded by an
`alias-pair` proof for g = 1 and g = 33/32, best worst-case error 1/65 m at c = 64/65, and a `MissionId`
different from step 1's; (3) `frob result revalidate a:<step 1> --against q:<step 2's query> --key … --json`:
exit 2, every cell invalidated with the reason "reads world.hidden.g", none inherited; `frob mission synthesize
--from <revalidated answer> --key … --json`: 327 withdrawn, each naming g = 1, g = 33/32 and the reading
(65/64)·p, the 17 cells at ε = 0 inner, the 217 excluded cells excluded; (4) `e2e_expect_refusal FROB-REF-854
3 -- frob mission synthesize docking.fmission --set world.hidden.g='{1, 33/32, 2}' --reuse two-gain/ --key …
--json`: pointer `/world/hidden/g`, the repairs in order (revalidation, recompile, restore) with
`e2e_assert_repairs_order`; run the first repair's ready command with a key appended by the script and assert

each bundle: accepted. NDJSON through the STD-E2E helper to `target/e2e-logs/mission_docking_amendment/<utc>.ndjson`
with a transcript: `ts`, `script`, `bead` (`N25c-21`), `step`, `event`, commands, exit codes, wall time,
evidence block, the value 1/65 m as an exact rational, the withdrawal count and the first withdrawn cell with
its counterexample, the refusal events with code, pointer and repairs, answer and bundle digests, and a
`summary` naming GATE-AUGUR-03, KA-638 and CX-282. The gate script of N25c-22 runs this script as a stage.

### Known answers and negative controls

- KA-638: docking with a third gain 33/32 at ε = 1/64: no exact docking; best worst-case error 1/65 m. Control
  named by the register: a certificate reused outside its declared hypothesis support.
- CX-282: a certificate that held for the declared worlds holds when a world is added: false; on the grid every
  positive label reverses.
- Negative control: a revalidation mutant that inherits inner cells across the amendment (treating the edit as
  "narrow the disturbance set") must be caught; one inherited cell is a false accept.
- Negative control: a screen cache keyed without the hidden support returns stale labels and is caught by the
  eligibility check.
- Determinism: exact rationals, D0.

## Considerations

- The count "327 withdrawn, 17 survive" is derived here from the alias condition abs(p) ≤ 64·ε; the plan's gate
  text says "every positive cell" and its native grid has no ε = 0 row. The per-cell report makes both readings
  checkable.
- The device screens (65,536 rows) reverse all 34,590 positive labels under the amendment; that run belongs to
  the device beads and uses this bead's eligibility record.
- The finite-tolerance game that replaces exact docking on a gain interval is solved in closed form by another
  bead; this bead only establishes that the exact requirement fails and by how much on the three-gain set.
- This bead's `--reuse` check is the first emitter of `FROB-REF-854`; the verb-wide form of the rule (raised by
  any verb handed a stale verdict) arrives with `mission.revalidate` at M3 (N25a-16). A repair command is
  rendered for the verb that answers in the build, so no M1 caller is pointed at a verb that refuses with 724.
