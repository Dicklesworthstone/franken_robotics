## Background

An engineer asks: can replacing this sole cause a formerly successful delivery to fail? The usual answer
computes two success sets and compares them, which is expensive and mostly unknown territory. Product-system
dominance asks directly for the relation: run both closed loops on the same exogenous world and ask whether the
outcome pair (A succeeds, B fails) is reachable. If it is unreachable over an enclosure of every admitted joint
execution, the replacement loses nothing on that cell, without either design having a guarantee.

The mechanism is Frontier. Its honest limits are stated before any work: one mislabelled branch invalidates the
certificate, and a conventional hybrid reachability tool applied to exactly the same coupled product with common
inputs and the same terminal monitor is the comparator (FACT from the literature register: the Flow*
reachability tool; to be re-read). The only advantage proposed is selective closure of decision cells, reuse
across amendments, and a robot-specific lowering that preserves spatially coupled disturbances.

This bead is the paper-scale pilot that must run before the mechanism (BD-359) is funded.

- **Pilot.** One contact transition (a sole replacement on a single step edge) with a shared space-indexed
  friction field: close parameter boxes where every compatible branch pair has identical joint labels, split or
  replay the rest, and feed the labels to the frozen paired rule of the comparison studies.
- **Falsifier.** One mislabelled draw against per-case referee replay, or the conventional tool closing the same
  cells at similar cost.
- **Ceiling.** Bounded by the fraction of paired draws whose joint label can be closed without replay, measured
  on the pilot before any claim.

## Scope

In: the frozen fixture; a prototype of box closure on that fixture; per-case replay of every draw; the
conventional tool's run on the same product model; the cost ledger charged to both arms; the falsifier verdict.
Out: the product implementation (BD-359, N25c-25); the gate measurement through the product (N25c-26); the kill
decision (N25c-27).

## Technical approach

**Fixture (frozen before execution; values recorded in the protocol).** One robot body with two soles: design A
(the incumbent sole) and design B (the replacement). Both use the same fixed causal controller for a single step
onto and over one step edge. Shared exogenous inputs: one space-indexed friction field on the floor and the
tread (a low-friction strip whose position and coefficient are parameters), the payload mass, and the clock law.
The two soles place their contact points at different positions, so the two robots read the shared field at
different points. Parameter box: strip edge position, strip friction, payload mass. Outcome per robot: the step
completes without slip beyond the monitor's bound and without a fall.

**Calibration stratum (synthetic, hand-checkable).** A reduced model of the same situation with exact answers,
used to check the prototype before the contact fixture: floor friction μ₁ = 0.5 for x < x_e and μ₂ for x ≥ x_e;
A's contact point at 0.30 m with grip factor 1; B's at 0.34 m with grip factor 1.25; success when
(friction at the contact point) × (grip factor) ≥ 0.4. On the box x_e ∈ [0.25, 0.40] m, μ₂ ∈ [0.2, 0.6] the
joint labels are:

| | μ₂ < 0.32 | 0.32 ≤ μ₂ < 0.4 | μ₂ ≥ 0.4 |
|---|---|---|---|
| x_e ≤ 0.30 (both on μ₂) | (0, 0) | (0, 1) | (1, 1) |
| 0.30 < x_e ≤ 0.34 (A on μ₁, B on μ₂) | (1, 0) | (1, 1) | (1, 1) |
| x_e > 0.34 (both on μ₁) | (1, 1) | (1, 1) | (1, 1) |

Under a uniform law on the box the label shares are (0, 0): 0.100, (0, 1): 0.0667, (1, 0): 0.080, (1, 1):
0.7533. The better-gripping sole regresses in 8% of worlds, because its contact point is elsewhere.

**Arms.**

1. *Box closure (prototype).* Partition the parameter box. For each box enumerate the branch pairs (contact-mode
   sequence of A, contact-mode sequence of B) compatible with the shared inputs in the box; enclose each robot's
   monitor outcome on each branch; if every compatible pair has the same joint label, close the box with that
   label; otherwise split at the mode boundary, and below a size floor hand the draws in the box to replay.
2. *Per-case replay (the truth).* 10⁴ draws from the box under the registered law; each draw is run for both
   robots on the event-located CPU tier and labelled.
3. *Conventional tool.* The same coupled product (two plants, common inputs, the same terminal monitor) given to
   a hybrid reachability tool, with the same box partition budget.

**Charged to both arms.** Every assumption translation, uncertainty split and checker call.

**Measurements.** Mislabelled draws (closed-box label against the replayed label); the fraction of draws closed
without replay; cost per closed draw for arms 1 and 3; the paired-rule verdict fed with closed labels against
the verdict fed with replayed labels.

## Acceptance criteria

- [ ] The protocol (fixture identity, parameter box, sampling law and seed, partition budget, cost definitions, falsifier) is hashed before execution.
- [ ] On the calibration stratum the prototype reproduces the label table and the four shares exactly.
- [ ] On the contact fixture: the count of mislabelled draws over 10⁴ draws is reported (the pilot passes only at zero), with the closed fraction.
- [ ] The conventional tool ran on the same product model; cells closed and cost are reported for both arms.
- [ ] The paired rule's verdict is identical with closed labels and with replayed labels.
- [ ] The falsifier verdict and the measured ceiling are written to the review log and handed to N25c-27.

## Test plan

### Unit tests

- `calibration_labels`: the nine cells of the table; shares 0.100, 0.0667, 0.080, 0.7533.
- `tick_pairing_hides_regression`: pairing the two robots by tick (both receive one friction sample z; A
  succeeds when z ≥ 0.4, B when 1.25·z ≥ 0.4) makes (1, 0) unreachable and would certify dominance; the
  position-indexed product must report the regression cell 0.30 < x_e ≤ 0.34, μ₂ < 0.32.
- `box_straddling_boundary_not_closed`: a box that contains x_e = 0.30 is split or replayed, never closed.
- `independent_branches_retained`: when the two robots' internal branch choices are not tied by a shared input,
  all four combinations are kept in the enclosure.

### End-to-end script and logging

`scripts/e2e/pilot_dominance_contact_transition.sh`: runs the prototype closure, then `frob sim run` for both
designs on each draw's world address (shared scene, payload and clock law), then the comparison. It logs through
the shared end-to-end helper: commands, exit codes, wall time, evidence block, per-box labels, the mislabel
count against the threshold 0, the closed fraction, cost per closed draw for both arms, and replay addresses of
any mislabelled draw. Summary: falsifier verdict; gate informed (KILL-AUGUR-DOMINANCE).

### Known answers and negative controls

- Known answer: the calibration table and shares; the scalar fixture (A succeeds iff z ≥ 3/5, B iff z ≥ 2/5 on
  z ∈ [0, 1]: (1, 0) unreachable, gain [2/5, 3/5)).
- Negative control: separate enclosure of each robot's outcomes admits all four pairs on the scalar fixture and
  must be flagged as not a dominance proof.
- Negative control: a product whose internal branches are wrongly tied reaches only (0, 0) and (1, 1) and hides
  a reachable (1, 0); the joint-coverage check must fail it.
- Determinism: replayed labels identical twice on one machine with the same world addresses.

## Considerations

- The split-grip fixture of the task chapter supplies the low-friction strip; the step edge and the two soles
  are additions frozen in the protocol.
- Compute: 2 × 10⁴ short event-located runs; within the default envelope on the CPU.
- If the conventional tool closes the same cells at similar cost the pilot is falsified even with zero
  mislabels: the lowering is then kept only as the rule for space-indexed shared inputs.
