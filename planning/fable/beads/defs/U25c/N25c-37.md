## Background

The basic label query (BD-363) fixes one observation-identical prefix and asks how many labels one controller
needs. Two things make a real line harder, and each has a small exact fixture.

First, the factory commits to one label map before the later history is known. What the controller will observe
in the field (a public reading, a part class) is not known when the label is attached, and the same label must
work whatever that history turns out to be. Colouring each history separately undercounts.

Second, a label has a delivery time. A label that arrives after a decision is committed has zero value for it.
The number of labels that count is the number delivered before the commitment, and feasibility changes with it.

Tier: Frontier, exact on finite histories and on the one-axis placement fixture.

## Scope

In: the union colouring over finitely many exogenous public histories with one action per reachable (label,
history) pair; the causal policy tree for action-dependent histories; delivery deadlines; the largest tolerable
payload width as a function of labels delivered on time. Out: the single-prefix colouring (BD-363); the encoder
premise (N25c-36); the channel code and its bit times (N25e-35, which checks its message length against these deadlines); the gate script (N25c-38).

## Technical approach

**One label map across histories.** For finitely many exogenous public histories h ∈ H:

1. For each h let V_h be the variants that admit h, and K_s(h) the commands that work for variant s after h.
2. Collect the minimal conflict sets at each history among the variants of V_h (inclusion-minimal subsets with
   empty common command set).
3. Colour the union of all those conflict sets once: a label map is valid when no label class contains a
   conflict set of any history.
4. Return an action for every reachable (label, history) pair: a common command of the label's variants that
   admit that history.
5. Report both counts: the per-history maximum (what a history-specific map would need) and the fixed-map count.

Known answer. Variants A, B, C and three public readings that require opposite command bits for A and B at the
first, B and C at the second, C and A at the third. Two labels suffice at each reading separately and a fixed
map needs three (the union of conflicts is a triangle). Both counts are tested.

**Action-dependent histories.** When the history depends on the controller's own earlier actions, the query is
a causal policy tree with a common factory map and shared-prefix decisions: the label map is chosen at the root;
at each node the action may depend on the label and on the observations so far; two variants with the same label
and the same observations so far receive the same action. This is lowered to the finite observation game of the
docking slice with one extra root decision (the label map), and answered by enumeration within the declared size
caps.

**Deadlines.** Each label carries a delivery instant. Labels delivered at or before the commitment instant of a
decision may inform it; later ones may not (a packet arriving exactly at the decision instant is delivered
before the controller is evaluated). With j labels on time the controller's information is the on-time label
only, and the colouring is run with at most j classes.

Known answer (one-axis placement). The placement error is e = u − bᵢ − q − δ, where the fixture offset
bᵢ ∈ {−1/4, 0, 1/4} mm identifies the variant, the manufacturing offset q ∈ [−1/32, 1/32] mm is hidden, the
payload term δ ∈ [−w, w] mm is hidden, and success is abs(e) ≤ 3/8 mm. For variant i the command set is the
interval K_i(w) = [bᵢ − (11/32 − w), bᵢ + (11/32 − w)], nonempty for w ≤ 11/32. A class of variants shares a
label when the spread of its offsets is at most 2·(11/32 − w). Hence the largest tolerable payload half-width w
is 3/32, 7/32 and 11/32 mm with one, two and three labels delivered before commitment (spreads 1/2, 1/4 and 0),
and 3/32 mm for any number of labels delivered late or for one common action.

**Parametric answer (DESIGN).** The query may leave a parameter of the command sets free (here w) and ask for
its largest value per label budget: the answer is a table (labels on time → threshold, attained, witness map,
binding conflict).

```rust
pub struct HistoryLabelAnswer { per_history: Vec<(HistoryId, u32)>, fixed_map: u32,
                                map: Vec<(VariantId, LabelId)>, actions: Vec<((LabelId, HistoryId), Command)>,
                                proofs: Vec<ProofRef> }
pub struct DeadlineTable { rows: Vec<(u32 /* labels on time */, Ratio /* threshold */, bool /* attained */)> }
```

**Evidence.** `Certified`, exact rationals, D0. The answer's assumptions list the admitted histories, the
commitment instant and each label's delivery instant; changing any of them is a different mission identity.

## Acceptance criteria

- [ ] Code in `crates/frob-mission` (`labels/histories.rs`, `labels/deadlines.rs`).
- [ ] The three-reading fixture returns per-history counts (2, 2, 2) and a fixed-map count of 3, with an action for each of the reachable (label, reading) pairs.
- [ ] The deadline fixture returns 3/32, 7/32, 11/32 mm for one, two and three labels on time, and 3/32 mm for labels delivered late, each `attained: true` with its binding conflict.
- [ ] A label delivered exactly at the commitment instant counts; one delivered after does not.
- [ ] An action-dependent fixture is answered by the policy tree and equals brute-force enumeration.
- [ ] Every answer's proof objects (witness maps, binding conflicts, and the `colouring-bound` object where a count or threshold rests on non-colourability, checked by N12p2-01) pass the check run before the answer returns; a per-history colouring offered as a fixed map is rejected by that check. Bundles of these answers are written by BD-364 and verified by `frob-verify` in N25c-38, which depends on both.
- [ ] `scripts/e2e/mission_label_histories.sh` passes with the logging below.

## Test plan

### Unit tests

`crates/frob-mission/tests/label_histories.rs` (exact rationals, the real colouring and policy tree, no mocks):

- `triangle_of_conflicts` (KA-645): conflicts {A, B} at reading 1, {B, C} at reading 2, {C, A} at reading 3:
  two labels per reading; three for a fixed map.
- `deadline_thresholds` (KA-647): 3/32, 7/32, 11/32 mm; late: 3/32 mm; one common action: 3/32 mm. The
  two-label optimum groups {−1/4, 0} with command −1/8 and {1/4} with command 1/4 (or the mirror image).
- `command_interval`: K_i(w) = bᵢ ± (11/32 − w); at w = 7/32 the classes {−1/4, 0} and {1/4} have commands
  −1/8 ± 0 and 1/4 ± 1/8.
- `arrival_at_commitment_counts`: boundary ordering.
- `five_cases_agree`: the five cases of the deadline fixture (one, two, three early labels; late labels; one
  common action) computed by interval intersection and by symbolic elimination of q and δ agree.
- `action_dependent_tree` (synthetic): the docking plant with gains 1 and 2 as the two variants, U = 3/4 and
  the velocity packet late. With zero labels no policy docks both; with one two-valued label delivered before
  the first command the commands (1/4, 1/2, −3/4) and (1/4, 0, −1/4) dock both; with the label delivered after
  the third command, none again. Enumeration over label maps and policies equals the lowering.

### End-to-end script and logging

`scripts/e2e/mission_label_histories.sh`, owned by this bead and built only on its dependencies (the gate script
`scripts/e2e/mission_labels.sh` of N25c-38 reuses its fixtures in steps 2 and 4 and may run this script as a
stage). This bead writes, under `fixtures/missions/labels/` (the directory N25c-38 reads), the fixtures
`labels-three-readings.fmission`, `labels-deadline.fmission` (w left free,
labels delivered before commitment) and `labels-deadline-late.fmission` (the same mission with every label's
delivery instant after commitment). Steps:
(1) `FROB_TEST_SEED=<seed> cargo test -p frob-mission --test label_histories` (the unit tests above);
(2) `frob mission synthesize labels-three-readings.fmission --key hist-three-<run> --json`: assert per-history
counts (2, 2, 2), fixed-map count 3 with `attained: true` (the `colouring-bound` object over the triangle, whose
checker N12p2-01 BD-363 depends on), and an action for every reachable (label, reading) pair;
(3) `frob mission synthesize labels-deadline.fmission --key hist-deadline-<run> --json` (the parametric answer):
assert the deadline table's rows 3/32, 7/32 and 11/32 mm for one, two and three labels on time, as exact
rationals, each `attained: true` with its binding conflict; then `frob mission synthesize
labels-deadline-late.fmission --key hist-deadline-late-<run> --json`: assert 3/32 mm for every label count;
each answer's `certificate` block shows its proof objects accepted by the check run before the answer returns.
It sources the STD-E2E helper and writes `target/e2e-logs/mission_label_histories/<utc>.ndjson` with a
transcript: per line `ts`, `script`, `bead`, `step`, `event`, the exact command, exit code, wall time and the
envelope's evidence block; both counts, the thresholds as exact rationals against their expected values, the
label map and actions, answer digests, the first differing value on failure, and a summary line naming
GATE-AUGUR-19. Bundles of these answers rest on `colouring-bound` objects (the triangle of the fixed map, and the
triangle of conflicts just above 7/32 mm that bounds two labels), whose writer is BD-364: they are written and
verified by `frob prove bundle` and `frob prove verify` in N25c-38's steps 2 and 7, not here.

### Known answers and negative controls

- KA-645: three variants, three readings: two labels per reading; three for a fixed label map across histories.
- KA-647: the label deadline fixture; control named by the register: labels counted without their delivery
  instants.
- Negative control: a solver that takes the maximum of per-history counts returns 2 on the triangle and must be
  caught.
- Negative control: a solver that counts late labels returns 11/32 mm for three late labels and must be caught.
- Metamorphic: translating all offsets bᵢ by a constant leaves thresholds unchanged; permuting histories leaves
  the fixed-map count unchanged.

## Considerations

- The number of public histories and the size of the policy tree are capped at admission; beyond the caps the
  query is refused with the per-history bound offered as a labelled lower bound.
- A label is a message over a real channel with a length and bit times; that part belongs to the channel
  declaration and can turn an on-time label into a late one.
- Governed by KILL-AUGUR-LABELS only through its fallback, which keeps the supplied-set query.
