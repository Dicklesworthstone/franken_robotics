## Background

GATE-AUGUR-19 (claim: Known answer; milestone M4; threshold TARGET): labels: the three-variant, three-reading and
station-record fixtures exact; with inner and outer sets the returned label interval contains the exact count on
20 generated instances.

The gate checks the label query end to end through the public verb, on the three hand-checkable fixtures and on
generated instances whose exact answer is known by brute force. It also runs the comparator the plan names. The
plan-time pilots found that ordinary tools already answer this query on supplied sets: an independent SMT
encoding returned unsatisfiable for one shared label and satisfiable for two, with its own two-label witness,
and belief-window intersection agreed with symbolic elimination on all five deadline cases. No advantage over an
SMT or mixed-integer baseline is claimed, so the comparator is here to keep the product honest, and a rival's
answer goes through the same checker.

## Scope

In: the fixture mission files; the instance generator with its brute-force oracle; the comparator encodings; the
script, assertions and logging; the gate row. Out: the mechanisms (BD-363, N25c-36, N25c-37); the kill decision
(N25c-40); extraction from contact.

## Technical approach

**Fixture files (under `fixtures/missions/labels/`).**

- `labels-three-variants.fmission`: commands (x, y) ∈ [0, 1]²; variants x ≥ 2/3, y ≥ 2/3, x + y ≤ 1.
- `labels-three-readings.fmission`: variants A, B, C; three public readings with conflicts {A, B}, {B, C},
  {C, A}.
- `labels-station-records.fmission`: builds A and B with opposite commands; records {left, shared} and
  {shared, right}; equal field history.
- `labels-deadline.fmission`: the one-axis placement with offsets −1/4, 0, 1/4 mm, hidden offset in
  [−1/32, 1/32] mm, payload half-width w, tolerance 3/8 mm; variants with zero to three labels on time.

**Generated instances.** A seeded generator produces 20 instances: 4 to 8 variants; command dimension 2 or 3;
each command set a random rational polytope (intersection of 3 to 6 half-spaces within the unit box), with an
inner set (shrunk by a random margin) and an outer set (grown by a random margin). A brute-force oracle
enumerates all partitions of the variants and tests each class's intersection exactly, for the true sets, giving
the exact count; and separately for inner and outer sets.

**Comparator.** Two independent encodings, outside the product crates (`tools/oracle/labels/`):

- SMT: Boolean variables "variant s has label j", real variables for one command per label, constraints
  "label j assigned to s implies command j ∈ K_s"; satisfiability for k = 1, 2, ….
- Mixed-integer: the same with binary assignment variables and big-M constraints.

Their witnesses are converted to proof objects and bundles and checked by `frob-verify` like the product's. Both
engines run out of process at exact releases pinned as `[[oracle]]` rows of
`crates/frob-conformance/registry/oracles.toml` (N38a-04's register, family "conventional solvers": posture
`out-of-process`, pin kind `release`, role `comparator:label-query`, with an admission test on the three-variant
fixture and a negative control), and the encodings are capture scripts under `tools/oracle/labels/` that read no
build product of this workspace.

**Idempotency keys.** Every `frob mission synthesize` call carries its own key (`--key labels-<fixture>-<run>`;
for the deadline fixture `labels-deadline-<n>-<run>` per label count; for generated instance i
`labels-gen-<i>-<inner|outer|true>-<run>`), so that the inner, outer and true-set runs of one instance never return
one another's receipts; `frob prove bundle` carries `--key labels-bundle-<answer>-<run>`; `frob prove verify` is a
read verb.

**Steps.**

0. Stage: run BD-363's `scripts/e2e/mission_labels_core.sh` (the mechanism's own script: its cargo tests, the
   three-variant, triangle, empty-variant and inner/outer fixtures through `frob mission synthesize`, the two
   work-limit instances, and the `lp-primal`/`lp-farkas` bundles). Its exit code, log path and summary are logged
   as one stage event, and a non-zero exit fails this script.
1. `frob mission synthesize labels-three-variants.fmission --key labels-three-variants-<run> --json`: assert
   count 2, `attained: true`, commands (2/3, 2/3) and (0, 0) (or another valid pair), conflict set {1, 2, 3},
   and a proof that one label is impossible.
2. `…labels-three-readings.fmission`: assert per-reading counts (2, 2, 2) and fixed-map count 3, `attained:
   true`, with the no-two-colouring proof of BD-363, a `colouring-bound` object over three `lp-farkas` edges,
   written into the bundle by BD-364 (the M4 writer of that kind, a dependency) and accepted by `frob prove
   verify` through the checker of N12p2-01 (a dependency). A build whose registry lacks
   that kind answers the fail-closed interval [2, 3] with `attained: false`; the assertion then fails with that
   answer logged, so the step tells a missing checker apart from a wrong count.
3. `…labels-station-records.fmission`: assert "no tag count suffices" with an `alias-pair` proof naming the
   record `shared`.
4. `…labels-deadline.fmission` four times: assert thresholds 3/32, 7/32, 11/32 mm (one, two, three labels on
   time) and 3/32 mm (labels late).
5. For each of the 20 generated instances: run the query with inner and outer sets; assert L ≤ exact ≤ U; when
   L < U assert a narrowing measurement is named; run the query on the true sets and assert equality with the
   oracle.
6. Run both comparator encodings on the fixtures of steps 1 to 4 and on the 20 instances; assert agreement with
   the product on every count; verify the comparator's bundles.
7. `frob prove bundle` and `frob prove verify` on every product answer.
8. Record wall time per query for the product and for each comparator, with the phase ledger, as input to the
   kill decision.
9. The script writes its receipt (the four fixture results, the count of generated instances whose interval
   contains the exact count (20 of 20 required), the comparator agreement, the negative controls caught, the
   seed, commit and hardware fingerprint) and prints its hash; it never writes the gate record. The recording
   session, which did not implement the mechanisms, enters the row with `cargo run -p frob-conformance --example
   record_gate -- --gate GATE-AUGUR-19 --receipt <hash>` (N38b-19), the one recorder of the gate.

**Logging.** The script sources the shared end-to-end helper and writes NDJSON to
`target/e2e-logs/mission_labels/<utc>.ndjson` with a transcript. Every line: `ts`, `script`, `bead`, `step`,
`event`, the exact command, exit code, wall time, the envelope's evidence block (claim, class, tier,
determinism, identities, seed), measured values with thresholds (counts; thresholds as exact rationals; for
each generated instance L, exact, U), digests (answer and bundle; comparator bundle), and on failure the first
differing instance with its seed and the artifact paths. Summary: assertions passed and failed; gate
GATE-AUGUR-19.

## Acceptance criteria

- [ ] `scripts/e2e/mission_labels.sh` exists, is idempotent and seed-explicit, and exits non-zero on any failed assertion.
- [ ] The three fixtures named by the gate are exact; the deadline fixture's four thresholds are exact.
- [ ] On 20 of 20 generated instances the returned interval contains the exact count.
- [ ] Both comparator encodings agree with the product on every fixture and instance, and their bundles pass the same checker.
- [ ] Step 0 (BD-363's `scripts/e2e/mission_labels_core.sh`) passes inside this script.
- [ ] Three negative controls are caught (below).
- [ ] GATE-AUGUR-19 has a recorded row with measured values, entered by `record_gate` from the script's receipt (the script writes no gate record); the recording session did not implement the mechanism.

## Test plan

### Unit tests

- `oracle_bruteforce_small`: on the three-variant fixture the oracle returns 2 and lists exactly three valid
  two-class partitions.
- `generator_seeded`: the same seed yields the same 20 instances; every inner set is inside its true set and
  every true set inside its outer set (checked exactly).
- `smt_encoding_matches_oracle`: on 50 small random instances the SMT encoding's least satisfiable k equals the
  oracle's count.
- `log_schema`: a dry run validates against the harness's schema.

This bead is the script; path, commands, assertions and log fields are above.

### Known answers and negative controls

- KA-644 (three variants: two labels suffice, one is impossible); KA-645 (three readings: two per reading,
  three for a fixed map); KA-646 (station records: no tag count suffices); KA-647 (deadlines: 3/32, 7/32, 11/32
  mm; 3/32 mm late).
- Negative control 1 (CX-271): a pairwise-compatibility build returns one label on the three-variant fixture;
  step 1 must fail.
- Negative control 2: inner and outer sets exchanged in the interval computation; step 5 must find an instance
  whose interval excludes the exact count.
- Negative control 3: late labels counted as on time; step 4 must fail on the late variant.
- Determinism lanes: every answer twice on one machine and across worker counts with identical bytes; two hosts.

## Considerations

- A tie with the comparators is the expected result and is recorded as a tie; the query then ships over the
  conventional solver behind the same verb if that is the better route per engineering hour.
- The comparator engines are tools outside the product; their versions are pinned as `[[oracle]]` rows of
  `crates/frob-conformance/registry/oracles.toml`, and a pin moves only with a `[[pin_move]]` record (N38a-04).
- The generated instances are small by design (brute force must finish); they say nothing about scaling.
