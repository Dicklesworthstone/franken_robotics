## Background

Augur is the subsystem that answers questions about a set of designs. Its mission queries decide: the answer to
`mission.synthesize` is an inner set I of designs with a checked reason why each works, an outer set O outside
which each design has a checked reason why it cannot work, and unresolved cells between. The constructive lanes do
something different: they propose. Given a query they build candidate designs (a sized component set, a refined
set of link lengths, a linkage). A design that comes out of a lane is a candidate with a label. It enters I only
through one of the four proof rules of the mission semantics (necessary-condition exclusion, constructive
inclusion, monotone or symmetry inheritance, exact partition and composition), applied by `frob-mission` and
accepted by the independent checker.

The lanes live in the crate `frob-synth` (layer 5; tiers Frontier and Moonshot; scope cap 10 thousand lines).
There are four, each exposed as a strategy of the one verb: monotone co-design (`codesign`), trajectory
optimization with design variables (`refine`), bounded exact linkage synthesis (`linkage`), and numerical
continuation (`continuation`, Moonshot, behind a feature flag). Each reports its candidates into the same answer.

This bead builds what the lanes share. Reason for one shared record: an agent reads one answer shape whichever
lane produced a proposal, and the rule "a candidate has no verdict" is enforced once, by types, instead of four
times by convention. Rejected alternatives: a separate verb per lane (the body of a design is a free output of one
set comprehension; separate verbs would let a lane's output be read as an answer); letting a lane mark its own
output `inner` (a lane's solver is a proposer and nothing a proposer says is believed).

INV-AUGUR-11 (the invariant this bead carries): a candidate from `frob-synth` has no verdict until `frob-mission`
assigns one through a proof rule.

## Scope

In: the crate skeleton and its `CONTRACT.md`; the `Candidate` record and labels; the `Strategy` value set; the
dispatch in `frob-verbs`; the `candidates` block of the answer; budgets and `--estimate` lines for proposing;
refusal behaviour for unknown and disabled strategies; the tests of INV-AUGUR-11.
Out: the lanes themselves (BD-360, BD-362, BD-361, BD-437 and their children); the two small exact constructions
(N25d-08); the strategy `placement` for a prescribed motion (defined by the unit that owns placement and sizing
along a motion; the value is reserved here so the set stays closed).

## Technical approach

**Crate.** `crates/frob-synth/` with `src/lib.rs`, `candidate.rs`, `strategy.rs`, and one module per lane
(`codesign/`, `refine/`, `linkage/`, `continuation/` behind the Cargo feature `continuation`, off by default),
plus `exact/` for the small constructions. Dependencies point downward only: `frob-core`, `frob-algebra`,
`frob-design`, `frob-model`, `frob-actuate`, `frob-analyze`, `frob-spec`, the airlock `frob-fsim` for optimizers.
`frob-synth` does not depend on `frob-mission`, and `frob-mission` does not depend on `frob-synth`; `frob-verbs`
(layer 6) calls both. `unsafe` is denied.

**Types (DESIGN; intent, not signatures).**

```rust
pub enum Strategy { Codesign, Refine, Linkage, Continuation, Placement /* reserved */ }
pub enum CandidateLabel { Candidate,                       // the only label of codesign, refine and linkage output
                          Complete,                        // continuation only: certified count equals the trace-test count
                          Partial { certified_n: u32, lost_n: u32 } }
pub struct Candidate {
    pub id: CandidateId,                // BLAKE3 of the canonical bytes below
    pub strategy: Strategy,
    pub design: DesignRef,              // a DesignId, a typed patch against a parent design, or a module (.fmodule)
    pub label: CandidateLabel,
    pub artifacts: Vec<ArtifactRef>,    // antichain, nominal trajectory, sensitivities, circuit data
    pub proofs: Vec<ProofObject>,       // proof objects about the construction itself, in frob-core types
    pub assumptions: AssumptionSet,     // relations, orders, schedules, surrogates the construction relied on
    pub class: EvidenceClass,           // class of the construction claim: the weakest input
    pub next: NextStep,                 // the query or evaluation rung that would decide it
}
```

There is deliberately no verdict field. `Verdict` and its constructors live in `frob-mission`.

**Dispatch (numbered).**
1. `frob mission synthesize q.fmission --strategy <s> [--budget …] --json`. Without `--strategy` the verb behaves
   as before (it decides and proposes nothing).
2. `frob-verbs` admits the query as usual, then calls `frob_synth::propose(&query, s, &budget, cx)`, which returns
   candidates or a refusal.
3. Each candidate is offered to `frob-mission` as a point query (every design parameter bound) under the query's
   own quantifier prefix. If a proof rule decides it within budget, its cell appears in `inner` or `excluded` with
   its proofs and the candidate carries `decided_by: <cell id>`. Otherwise the candidate stays undecided.
4. The answer gains `result.candidates[]`: `id`, `strategy`, `label`, `design`, `class`, `assumptions`,
   `artifacts`, `next`, and `verdict`, which is `null` unless step 3 decided it. A candidate never appears in
   `inner` on the lane's word.
5. The envelope's evidence is the claim product of everything in the answer; a candidate that rests on a
   simulation surrogate makes its own block `Estimated` and cannot raise anything.

**Refusals and exits.** An unknown strategy fails the schema (`FROB-REF-802`, exit 3). A strategy whose feature
is not compiled or not admitted returns exit 5 (capability not implemented) and names the feature. A lane whose
estimate exceeds the budget is refused under the budget family (`FROB-REF-701`, exit 4) with the estimate
attached. A lane-specific refusal (for example `FROB-REF-857`, a synthesis system outside the symbolic caps)
passes through with its repairs. A failed lane (solver non-convergence, timeout) yields no candidate and is never
an exclusion: the cell stays unresolved with explanation `SolverFailure` or `BudgetExhausted`.

**Estimate and budget.** `--estimate` reports the cost of proposing per lane separately from admission,
lowering, deciding and checking, each with an interval, and runs nothing. Cancellation drains: candidates
completed so far are kept, work in flight is discarded.

**Ledger.** Every candidate is recorded with its strategy, the digests of its inputs (query, catalog, cards,
templates), its assumptions and its label. Determinism: candidate bytes are a deterministic function of inputs
and seed for the exact lanes (class D0); the numerical lanes declare their class.

## Acceptance criteria

- [ ] `crates/frob-synth` exists with `CONTRACT.md` (ten sections); `xtask check-layers` passes; neither of
      `frob-synth` and `frob-mission` depends on the other.
- [ ] INV-AUGUR-11: constructing a verdict from inside `frob-synth` does not compile; through the public verb no
      candidate has a non-null verdict unless a cell with a checked proof names it.
- [ ] `--strategy` accepts exactly `codesign`, `refine`, `linkage`, `continuation` (and the reserved `placement`);
      anything else is a schema refusal; `continuation` without its feature exits 5.
- [ ] The `candidates` block validates against the generated schema; candidate identities are stable across runs.
- [ ] `--estimate` shows a proposing line per lane; an over-budget lane is refused with the estimate attached.
- [ ] A lane failure produces no exclusion (checked on a planted non-converging lane input).
- [ ] Reachable through `frob --json` and `frob-mcp`; cancellation tested (request, drain, finalize).

## Test plan

### Unit tests
`crates/frob-synth/tests/candidate.rs` and a compile-fail test:
- `no_verdict_constructor` (compile-fail): `frob_mission::Verdict::Inner(..)` is not nameable from `frob-synth`.
- `candidate_id_is_content_hash`: two candidates with equal canonical bytes have equal ids; one changed
  assumption changes the id.
- `label_set_per_strategy`: `Complete` and `Partial` are rejected on a non-continuation candidate.
- `class_is_weakest_input`: a candidate with one `Estimated` input is `Estimated`.
- `strategy_value_set_closed`: parsing `"anneal"` fails.

### End-to-end script and logging
The dispatch has no lane of its own, so it is exercised by the first lane's script
(`scripts/e2e/augur_synth_codesign.sh`, bead N25d-10), which asserts for every returned candidate: `verdict` is
`null` or names a checked cell; `label` is `candidate`; the evidence block is present; exit codes for the unknown
and disabled strategies. Those assertions are logged with this bead's key in the `bead` field.

### Known answers and negative controls
Negative controls registered for INV-AUGUR-11: a mutant dispatch that copies a lane's candidate into `inner`
must be caught by the answer validator (an inner cell without a proof is rejected before the answer returns);
a mutant lane that returns an exclusion on solver failure must be caught by the standing-rule test.
Determinism: candidate bytes twice on one machine; debug and release.

## Considerations

- The crate's cap is 10 thousand lines for four lanes; the continuation lane is the first to be cut.
- A candidate's `proofs` are about its construction (a circuit certificate, a placement witness). They do not by
  themselves say the candidate satisfies the mission; that is what step 3 is for.
- The pass rate of synthesized designs under independent closed-loop evaluation is unknown; every candidate goes
  through the ordinary evaluation ladder.
