## Background

GATE-AUGUR-17 (claim: Known answer; milestone M4; TARGET) covers the constructive lanes of Augur, the lanes that
propose candidate designs for a mission query: "the co-design fixed point equals the GB-03 closed form and
rejects the additive-peak rule on the bus fixture; the three-pose dyad and both circuit fixtures exact; zero
certified linkages change circuit on the referee across 240 instances." This bead measures the first clause, the
co-design rows, through the public verb, and at the same time exercises the contract every lane shares: a
candidate has a label and no verdict. The linkage rows are measured by a sibling script (N25d-19); the gate's
PASS is recorded when both have run.

The two fixtures. (1) The mass spiral (worked card GB-03): actuator mass m_a = τ_req/ρ_τ, required torque
τ_req = c·m·g·L, total mass m = m_f + n·m_a, so m = m_f/(1 − κ) with loop gain κ = n·c·g·L/ρ_τ, closing only if
κ < 1. (2) The two-finger bus: two fingers each need one powered tick and the bus powers one finger per tick; a
deadline of one tick has zero schedules, two ticks have two schedules, local motor limits are identical in both
cases, and a rule that adds peak demands prunes the feasible case.

## Scope

In: the measurement of the co-design rows on the lane's fixtures; the four mutants as the rows' registered
controls; the determinism lanes and the metamorphic relation; the co-design part of the gate's tier entry and
its receipt; the gate report row. Out: the lane, its fixtures and its own script (BD-360; this bead runs that
script as a stage); the dispatch and its script (N25d-06); the linkage rows and the one record of the gate
(N25d-19); the continuous-resource and Pareto-coverage acceptance tests that belong to GATE-AUGUR-35 (N25e-44).

## Technical approach

**Fixtures.** BD-360's, under `crates/frob-conformance/fixtures/augur/codesign/`, with their derivation notes:
`mass-spiral` (expected fixed point 30000/2057 kg, κ = 2943/5000), `mass-spiral-long-leg` (κ = 38259/37500,
`LeavesBound`), `mass-spiral-catalogue` (sizes 1, 2, 3 and `LeavesBound`; totals 13.2, 20.9 and 44.2 kg),
`two-finger-bus` (0 and 2 schedules; kept at two ticks), `pareto-antichain` ({(2, 300), (3, 200)}). This bead
adds one: `mass-spiral-catalogue-permuted.fmission`, the catalogue fixture with its rows in reversed order, for
the metamorphic relation.

**Script steps.**
1. Stage: `scripts/e2e/synth_codesign_lane.sh` (BD-360; it runs N25d-06's `synth_dispatch.sh` first), whose
   asserts on every fixture are the measured values of the co-design rows: the fixed point as an exact string,
   the `LeavesBound` outcome, the catalogue sizes, the bus counts with no exclusion citing a peak sum, the
   antichain, null verdicts and `label == "candidate"`, the `authorization` flags all false. A failed stage stops
   the script.
2. Metamorphic: `mass-spiral-catalogue-permuted.fmission` with key `cd-perm-<run>`; the answer bytes equal those
   of the unpermuted fixture.
3. Determinism lanes: the mass-spiral, catalogue and bus fixtures again with their own `<run>` suffixes (second
   run; debug and release builds); identical answer digests (exact class). The `workers` lane (1, 2 and 8
   workers) runs in process inside step 4's tier entry through STD-TEST's `testkit::det::lane` on
   `frob_synth::codesign`, because `mission.synthesize` has no worker option (its row carries none, and no
   script may call one it does not carry).
4. The gate's tier entry for the co-design rows (DESIGN: written by this bead in `g1_known_answers`, tagged
   GATE-AUGUR-17, calling `frob_synth::codesign` on the fixtures above; N25d-19 adds the linkage rows to the same
   entry): `e2e_tier g1_known_answers GATE-AUGUR-17 --mutations` (the STD-E2E helper for
   `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g1_known_answers --features gauntlet-mutations
   -- GATE-AUGUR-17`). The control runner (N38b-04) builds each mutant as its own per-control feature and requires
   it caught in the same run: `increment-stop` (stops when the increment is below 10 g; returns less than the
   fixed point), `additive-peak` (prunes the two-tick bus case), `declared-monotone-prune` (prunes with an
   unchecked relation), `candidate-into-inner` (copies a candidate into `inner`; the answer validator must reject
   it). The script asserts that the receipt's measured values equal step 1's and that its `controls` list all
   four as `caught`.

**Idempotency keys.** Every run-verb call carries `--key` and no two calls the script compares share one (a
shared key returns the first call's stored receipt): the stage's keys are BD-360's (`cl-<fixture>-<run>`); this
script's own are `cd-perm-<run>` and, per determinism lane, `cd-<fixture>-<lane>-<run>`, so that each lane
recomputes instead of returning the first answer. `frob mission check` and `--estimate` run nothing and take none.

**What is recorded.** This script measures the co-design clause of GATE-AUGUR-17: measured fixed point (exact
string and its difference from the closed form, required to be 0), the bus counts, the antichain, the list of
controls caught, commit, hardware fingerprint, seed, and the hash of step 4's receipt. It never runs
`record_gate` (a script produces a receipt and never records a value): the gate has one row and two scripts, and
N25d-19 records it once, from the receipt of the tier entry run over both halves, by a session that did not
implement BD-360 or BD-361.

## Acceptance criteria

- [ ] BD-360's stage passes: all fixtures return their expected values exactly; rationals are compared as strings
      of reduced pairs.
- [ ] Every one of the four mutants is caught in the same tier run, and the receipt lists them.
- [ ] The permuted catalogue gives identical answer bytes; the determinism lanes give identical digests.
- [ ] The script is idempotent, seed-explicit, exits non-zero on any failed assertion, and writes its log and a
      transcript.
- [ ] The co-design clause's measured values (not targets) are in the script's log, in the receipt and in the gate
      report row of GATE-AUGUR-17, from which N25d-19 records the gate.

## Test plan

### Unit tests
`crates/frob-conformance/tests/augur_codesign_fixtures.rs`: each fixture parses and admits; expected values in
the fixture manifest equal the derivation notes (30000/2057; sizes 1, 2, 3; schedule counts 0 and 2; the antichain {(2, 300), (3, 200)});
the permuted fixture holds the same rows as the catalogue fixture in reverse order; the mutant list is non-empty,
every mutant is registered in `controls.toml` against GATE-AUGUR-17 and names the assertion it must break, and
its number is in the gate's `controls` (appended by this bead when it registers it, as N25d-41 states); the
script's key generator gives distinct keys to every compared call and to each determinism lane.

### End-to-end script and logging
`scripts/e2e/augur_synth_codesign.sh` (header `# e2e: bead=N25d-10 milestone=M4 labels=augur,frontier,gate
gates=GATE-AUGUR-17`). Through the STD-E2E helper, log at `target/e2e-logs/augur_synth_codesign/<utc>.ndjson`
with a transcript beside it; every line carries `ts`, `script`, `bead`, `step`, `event`; every command line with
its key, exit code and wall time; the envelope's evidence block (claim, class, tier, determinism, identities,
seed); a `stage` line naming BD-360's script, its log path and its summary; `assert` lines with expected and
observed values; `metric` lines for the measured fixed point (tagged GATE-AUGUR-17, threshold: difference 0) and
the bus counts; the `cmd` line of `e2e_tier` with its `receipt` hash; per mutant the control id and `caught`; on
failure the first differing value and the answer address; a `summary` with assertions passed and failed, the gate
touched, controls caught and the receipt hashes. Lines of the stages carry the stage's bead (BD-360, N25d-06) in
the `bead` field.
