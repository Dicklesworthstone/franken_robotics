## Background

Numerical continuation is the Moonshot lane of Augur's constructive crate `frob-synth` (epic BD-437): for a
mechanism family whose equations exceed the caps of the exact symbolic solver, solve one generic complex
instance once, then follow its solutions to each new specification along the parameter homotopy
H(z, t) = F(z; (1 − t)·p₀ + t·p₁). A Moonshot item is not funded before a paper-scale pilot with a falsifier has
run and its ceiling has been stated.

The pilot family is the forward kinematics of a Stewart–Gough platform: six legs of given lengths join six
anchor points on a base to six on a platform; find every pose of the platform. With base anchors bᵢ, platform
anchors aᵢ, rotation R, translation t and leg lengths Lᵢ the equations are ‖R·aᵢ + t − bᵢ‖² = Lᵢ², i = 1 … 6.
The general problem has 40 solutions over the complex numbers (FACT, literature; to be re-read from the primary
source before any gate cites it). It is a good pilot because the count is known, it is far beyond dyads, and it
is still small: 40 paths per specification.

The pilot must show three things at once: the generic solve finds all 40 without a start system computed by
other means; a parameter homotopy carries all 40 to new parameters without losing a path silently; and each
endpoint can be certified as a true root by an exact test.

Ceiling, stated first: the lane answers "all isolated solutions" for one family at a time; nothing on the
critical path needs it.

## Scope

In: the formulation; the generic solve by monodromy with a trace test; ten target parameter sets; certification
of every endpoint; the falsifier; the record. Out: product code (N25d-22, N25d-23); the gate (N25d-24); the
kill decision (N25d-25).

## Technical approach

**Tools.** Existing continuation software and an existing exact α-certification program, outside the
workspace, at pinned versions recorded in the pilot register; exact rational arithmetic by script for the
checks. No `frob-synth` code.

**Formulation (frozen in the protocol).** The pose in Study (dual-quaternion) coordinates or as a rotation
matrix with its orthogonality equations; whichever is chosen, the protocol states the variables, the equations,
the treatment of solutions at infinity or on the exceptional set, and the expected count of 40. Parameters p:
the 36 anchor coordinates and 6 squared leg lengths.

**Procedure.**
1. Seed. Pick a random complex pose z₀ and random complex anchors; solve the six leg equations for the squared
   lengths (they are linear in them). The pair (z₀, p₀) is a solution by construction.
2. Monodromy. Track z₀ around random closed loops in parameter space that start and end at p₀. Each loop
   permutes the solutions at p₀ and reveals new ones. Stop when the count has not grown for a declared number
   of loops and the trace test passes.
3. Trace test. On a line of parameters through p₀, the sum over all found solutions of a fixed generic linear
   form of z, evaluated at three collinear parameter points, must be affine in the line coordinate (the middle
   value equals the mean of the outer two within tolerance). A missing solution breaks it. (The exact form of
   the test for this parametrization is taken from the primary source and written into the protocol.)
4. Targets. Ten generic real parameter sets (random rational anchors and positive squared lengths, seeded).
   Track the 40 solutions from p₀ to each target with an adaptive predictor–corrector and an endgame; record
   failed and crossed paths; re-run suspicious paths in extended precision.
5. Certify every endpoint: rationalize it; compute a bound on α(f, z) in exact rationals; accept when
   α < (13 − 3√17)/4 ≈ 0.157671; check pairwise distinctness by disjoint balls of radius twice the Newton step;
   classify real against non-real with the robust tests.
6. Label each target run `Complete` (40 certified distinct roots, no lost path, trace test passed) or
   `Partial(certified_n, lost_n)`.
7. Planted loss: repeat one target with one start solution deliberately removed.

**Falsifier (fixed before the run).** Any lost path that the trace test does not flag, or a `Complete` label
on a run that missed a root, or lost paths above 0.1% of the paths tracked to the ten targets (the record's
falsifier is KILL-SYNTH-CONT's trigger, which carries this clause; of 400 paths one lost path is 0.25%, so any
lost path outside the planted run holds the falsifier). The planted loss of step 7 must come out `Partial(39, 1)` with the trace test
failing; if it comes out `Complete`, the falsifier holds.

**Record (pilot register, N38a-09).** The record is `PILOT-C-34-cont` in
`crates/frob-conformance/registry/pilots.toml` (schema `frob.gauntlet.pilot/1`), entered at M0 by N25d-40 as its
row 21 (numerical continuation, lane 2 of construction C-34, which N10c-10 finds by its `bead` field): `tier =
"M"`, `bead = "N25d-21"`, `work_package = "BD-437"`, the falsifier of KILL-SYNTH-CONT's trigger, the ceiling "One
family at a time", `fallback = { ships = "The exact lane plus multi-start CPU recovery; every result labelled
`Partial`", kill_gate = "KILL-SYNTH-CONT" }`, `integrated_gate = "GATE-AUGUR-22"`. This bead registers that record
and writes no second one (a second record for the mechanism fails N25d-40's linkage test and would leave row 21
unregistered, blocking funding): before the generic solve it writes the protocol (formulation, seeds,

## Test plan

### Unit tests
The pilot's check scripts: `alpha_sqrt2` (f = z² − 2 at 3/2: β = 1/12, γ = 1/3, α = 1/36; certified, real);
`alpha_reject` (z = 3: α = 7/36, not certified); `alpha_nonreal` (f = z² + 1 at z = 11i/10: β = 21/220,
γ = 5/11, α = 21/484; the distance to the real axis 11/10 exceeds 2β = 21/110, so the root is certified
non-real); `monodromy_square_root` (z² − p: one loop of p around 0 turns z = 1 into z = −1; the trace z₁ + z₂
is 0 for every p).

### End-to-end script and logging
`scripts/e2e/pilot_continuation_sg.sh` first asserts that `PILOT-C-34-cont` is registered and that the protocol
file hashes to its registered digest, then wraps the external tools and appends the `[[pilot.result]]`. Through
the STD-E2E helper it writes `target/e2e-logs/pilot_continuation_sg/<utc>.ndjson` with a transcript; every line
carries `ts`, `script`, `bead` (`N25d-21`), `step`, `event`, the exact command, exit code and wall time. It logs:
tool versions; the generic solve's loops, paths, time and trace residual; per target the path statistics, the
smallest and largest α bound, the certified and real counts and the label; the planted-loss outcome; `metric`
lines for lost-path share (threshold 0.001) and unflagged losses (threshold 0); the protocol hash; a `summary`
with the verdict and the kill gate touched.

### Known answers and negative controls
KA-655 (40 and 16; to be re-read). Controls: the planted loss; a root perturbed by 10⁻³ in one coordinate must
fail certification; a duplicated endpoint must be caught by the distinctness test.

## Considerations

- A real target need not have 40 distinct finite roots; a target that loses roots to infinity or to a
  multiple root is recorded as `Partial` with the reason, and the pilot's ten targets are checked for
  genericity first.
- The one-time generic solve is cheap here (tens of paths per loop); for the nine-point path problem it is a
  very large computation, which is why the generic solve has its own budget line in the product.
- The α-test proves a nearby nonsingular root and nothing about roots that were not found; completeness rests
  on the count and the trace test, and is a numerical statement.
