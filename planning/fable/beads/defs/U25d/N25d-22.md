## Background

The continuation lane of Augur's constructive crate `frob-synth` (epic BD-437, Moonshot, feature `continuation`)
finds all isolated solutions of a mechanism family's polynomial system F(z; p) = 0, with unknowns z ∈ ℂⁿ and
parameters p, in two phases. Once per family: a generic solve at a random complex parameter point p₀ that
finds every solution there. Per query: a parameter homotopy H(z, t) = F(z; (1 − t)·p₀ + t·p₁) that carries
those solutions to the wanted parameters p₁, tracking only as many paths as the family has solutions (40 for
Stewart–Gough forward kinematics, 16 for 6R inverse kinematics, 4,326 for nine-point four-bar path synthesis).

This bead is the numerical engine. It is a proposer: nothing it returns is believed until the certification
step (N25d-23) has an exact α-test for each root and a completeness label for the set.

Decisions, with reasons. CPU and `f64`: path tracking needs double precision, Metal has none, and the paths of
one query are few. Start systems by monodromy with a trace test, not by a polyhedral start system, whose
one-time cost for large families is unpriced. The generic solve is a ledgered, cached artifact with its own
budget, because for large families it is the dominant cost and must be visible. Recovery of ill-conditioned
paths in extended precision, because a path that jumps to a neighbour silently produces a wrong count.

## Scope

In: the family definition; the tracker (predictor, corrector, step control, endgame, crossing detection,
extended-precision retry); monodromy with seeds and loops; the trace test; the generic-solve artifact and its
cache; path statistics; the example program `continuation_track` and its own end-to-end script. Out: exact
certification, labels, candidates and the verb surface (N25d-23).

## Technical approach

Module `crates/frob-synth/src/continuation/{family,track,monodromy,generic}.rs` (feature `continuation`).

**Family.** `Family { id, variables, parameters, equations }`: polynomials with rational coefficients in z and
p, with a canonical byte form whose hash is the family identity; a routine that, given a point z, returns
parameters p making it a solution when the equations are linear in some parameters (the seed rule), and a
generic real-target predicate.

**Tracker (per path).**
1. State (z, t) with H(z, t) = 0 at t = 0. The segment from p₀ to p₁ is straight in complex parameter space;
   since p₀ is generic complex, the segment misses the discriminant with probability one.
2. Predictor: fourth-order Runge–Kutta on dz/dt = −H_z⁻¹·H_t. Corrector: Newton on H(·, t) = 0, at most three
   iterations, accepted when the step norm falls below the tracking tolerance.
3. Step control: halve on corrector failure; grow after a declared number of successes; a step below the
   minimum marks the path `failed`.
4. Endgame near t = 1: a power-series or Cauchy endgame estimates the endpoint and its winding number, so
   singular endpoints and paths going to infinity are classified (`regular`, `singular`, `at-infinity`) instead
   of being returned as inaccurate regular roots.
5. Crossing detection: after each batch of steps, endpoints of distinct paths that coincide within tolerance at
   an intermediate t are both re-tracked with a tighter tolerance; a second coincidence triggers a retry in
   extended precision (double-double arithmetic); a third marks both `failed`.
6. Every path ends in exactly one of `regular`, `singular`, `at-infinity`, `failed`. `failed` paths are the
   lost paths; each is flagged with its start solution and the t at which it failed. Nothing is dropped.

**Monodromy (the generic solve).**
1. Seed: a random complex z₀ and parameters p₀ from the seed rule.
2. Loop: choose random complex points p′, p″; track every known solution along p₀ → p′ → p″ → p₀; add any
   endpoint at p₀ not already known (compared with a distinctness tolerance, refined by Newton).
3. Stop when the count has not grown for L consecutive loops (DESIGN default L = 5) and the trace test passes,
   or when the budget of the generic solve ends (then the artifact is `incomplete` and the lane can only label
   results `Partial`).
4. Trace test: along a line p(s) = p₀ + s·v with generic v, track all known solutions to s = −1 and s = +1; for
   a fixed generic linear form λ, the residual |Σλ(z(−1)) + Σλ(z(+1)) − 2·Σλ(z(0))| must be below tolerance
   relative to the sums. The precise statement used for each parametrization is recorded in the family's
   derivation file from the primary source. The count that passes it is the family's generic count.

**The generic-solve artifact** (DESIGN, schema `frob.synth.generic/1`): family identity, p₀, the solutions in
`f64` pairs with a refined residual each, the generic count, the trace residual, loops and paths used, wall
time, engine version and seed. It is content-addressed, stored through the ledger, and reused by any query on
the same family and engine version. Its own budget line appears in `--estimate` as "generic solve (one time)".

**Per query.** Load or build the artifact; track all solutions to p₁; return endpoints with their classes and
the path statistics (tracked, regular, singular, at infinity, failed, retried in extended precision).

**Determinism.** Tracking is deterministic given the seed, the thread count and the engine version; paths are
independent and reduced in fixed order. Class D1 on one machine; across machines the decisions (counts and
classes) are compared, not bits. Cancellation is checked between steps; a cancelled generic solve leaves no
artifact.

## Acceptance criteria

- [ ] On the family z² − p: the generic solve finds 2 solutions from one seed after one loop that encircles 0;
      the trace residual is zero; tracking to p₁ = 4 returns ±2.
- [ ] On the two-conic family z₁² + z₂² − p₁ = 0, z₁·z₂ − p₂ = 0: generic count 4; at p₁ = (5, 2) the endpoints
      are (1, 2), (2, 1), (−1, −2), (−2, −1) within tracking tolerance.
- [ ] A target on the discriminant (p₁ = 0 for z² − p) classifies both paths `singular`, not `regular`.
- [ ] Removing one stored solution makes the trace test fail.
- [ ] Every path has exactly one class; the sum of class counts equals the paths tracked.
- [ ] The artifact round-trips, is reused on a second query, and its one-time cost is reported.
- [ ] The Stewart–Gough family reaches generic count 40 with a passing trace test (the pilot's result
      reproduced in product code).

## Test plan

### Unit tests
`crates/frob-synth/tests/continuation_engine.rs` (feature `continuation`; real arithmetic, no mocks):
- `sqrt_family_monodromy`; `two_conics_four_solutions`; `discriminant_endpoint_singular`.
- `trace_test_detects_missing`: 3 of 4 solutions of the two-conic family fail the test.
- `path_at_infinity`: the family p·z − 1 = 0 tracked to p₁ = 0 classifies its path `at-infinity`.
- `crossing_retry_extended`: two paths engineered to pass within 10⁻⁹ of each other (z² − (t − 1/2)² − ε) are
  separated by the extended-precision retry and end at distinct endpoints.
- `step_control_fails_cleanly`: a path through a planted near-singularity is marked `failed`, with its t.
- `artifact_reuse`: the second query performs zero monodromy loops.
- Property test: for random univariate polynomials of degree at most 8 with rational coefficients, tracking
  from a generic member of the family of all monic polynomials of that degree returns endpoints whose
  residuals are below tolerance and whose count equals the degree (multiplicities counted through `singular`).

### End-to-end script and logging
`scripts/e2e/synth_continuation_engine.sh` (owned here, built on this bead's dependencies: the engine has no verb
of its own, the strategy surface being N25d-23's, so the script drives the example program
`crates/frob-synth/examples/continuation_track.rs`, feature `continuation`, which reads one family fixture and a
target parameter point, every number an exact string, and prints the generic-solve artifact's identity, loops,
paths, trace residual and one-time cost, and per query the endpoints with their classes and the path statistics,
as JSON). Fixtures: the hand families of the tests above, checked in as
`crates/frob-synth/fixtures/continuation/{sqrt,two-conics,inverse,crossing}.family` (ids `sqrt`, `two-conics`,
`inverse`, `crossing`), which N25d-23's and N25d-24's scripts also use. Steps: `cargo run -p frob-synth --features
continuation --example continuation_track -- --family <f> --target <p₁> --seed 1 --json` per fixture; assert the
two solutions of `sqrt` after one loop with trace residual 0 and ±2 at p₁ = 4; the four endpoints of `two-conics`
at (5, 2) within tracking tolerance; `singular` on both paths at p₁ = 0 of `sqrt`; `at-infinity` for `inverse`
at p₁ = 0; distinct endpoints after the extended-precision retry on `crossing`; the sum of class counts equal to
the paths tracked; a second query on `two-conics` reusing the artifact with zero loops; and, with
`--drop-solution 1` (the example's planted removal of one stored solution), a failing trace test. Through the
STD-E2E helper it writes `target/e2e-logs/synth_continuation_engine/<utc>.ndjson` and a transcript: every line
`ts`, `script`, `bead` (`N25d-22`), `step`, `event`, the exact command, exit code and wall time; `assert` lines
with expected and observed values; `metric` lines for loops, paths, trace residual and one-time cost; per query
the path statistics; on failure the first differing value and the fixture; a `summary`.

### Known answers and negative controls
The hand families above; KA-655 for the Stewart–Gough count. Planted defects: a tracker without crossing
detection returns a duplicated endpoint on the engineered crossing and is caught by the certification bead's
distinctness test; a monodromy stop rule with L = 0 returns too few solutions and is caught by the trace test.

## Considerations

- Extended precision is double-double arithmetic implemented in the crate; no arbitrary-precision dependency is
  added to the workspace.
- For large families the generic solve may take CPU-days; it is run as a job with its own budget and never
  inside a query's synchronous wait.
- This engine makes no claim; its outputs are inputs to certification.
