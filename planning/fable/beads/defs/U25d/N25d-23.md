## Background

The continuation engine (N25d-22) returns numerical endpoints of solution paths. An endpoint in double
precision is a proposal. This bead turns proposals into checked statements, attaches an honest completeness
label, and exposes the lane as the strategy `continuation` of `mission.synthesize`.

Certification is by Smale's α-theory, outside the proof kernel, in exact rational or interval arithmetic. For
a square polynomial system f and a point z with Df(z) invertible:
- β(f, z) = ‖Df(z)⁻¹·f(z)‖, the length of the Newton step;
- γ(f, z) = sup over k ≥ 2 of ‖Df(z)⁻¹·Dᵏf(z)/k!‖^(1/(k−1));
- α(f, z) = β(f, z)·γ(f, z).
If α(f, z) < (13 − 3√17)/4 ≈ 0.157671, Newton's iteration from z converges quadratically to a root ζ with
‖z − ζ‖ ≤ 2·β(f, z). Two certified points with disjoint balls of radius 2β have distinct roots. For a real
system, a point whose ball is disjoint from its complex conjugate's (‖z − Re z‖ > 2·β) has a non-real root;
reality needs the robust test α(f, z) < 0.03 with ‖z − Re z‖ < 1/(20·γ(f, z)), which shows z and its conjugate
converge to one root. Smale's theorem is a named assumption of the bundle, not a re-proved result (theorem
card T-34).

What a certificate does not say is as binding as what it says: an α-test proves a nearby nonsingular root and
nothing about roots that were not found. Completeness is a separate, numerical statement that rests on a count.

Labels. `Complete` only when the certified count equals an independent generic count from a trace test, with no
lost paths and no positive-dimensional components. Otherwise `Partial(certified_n, lost_n)`. A `Partial` result
can support inclusion of the designs it found and can never support an exclusion.

## Scope

In: rationalization of endpoints; the proposer-side α bound; proof objects of kind `alpha-root`; distinctness
and reality classification; the label rule; mapping roots to candidate designs; the strategy surface; refusals.
Out: the checker (the Moonshot-tier `alpha-root` rule of N12p1-01); the engine (N25d-22); circuit certificates of the resulting mechanisms
(N25d-18, reused unchanged).

## Technical approach

Module `crates/frob-synth/src/continuation/{certify,label,strategy}.rs` (feature `continuation`).

**Certify (per regular endpoint).**
1. Refine by a few Newton steps in extended precision; rationalize each coordinate (real and imaginary parts as
   exact dyadic rationals).
2. Compute rational upper bounds β̄ and γ̄ by the rules the checker applies (N12p1-01), implemented here
   independently from the shared written definition and sharing no code with the checker. With exact
   arithmetic over ℚ(i): evaluate f(z) and Df(z); form a rational complex matrix B approximating Df(z)⁻¹ (a
   rounded floating-point inverse, rationalized); R = I − B·Df(z) must have ‖R‖_F² < 1, and ρ̄ is a verified
   rational upper bound of ‖R‖_F; then ‖Df(z)⁻¹·v‖ ≤ ‖B·v‖/(1 − ρ̄). β̄ bounds ‖Df(z)⁻¹·f(z)‖ that way. For each k
   from 2 to the largest degree d, bound ‖Df(z)⁻¹·Dᵏf(z)/k!‖ by the Frobenius-type norm of the tensor (square
   root of the sum of squared moduli of its entries) combined with the same inverse bound, and take γ̄ as a
   rational with γ̄^(k−1) ≥ that bound for every k (the (k−1)-th root rounded upward as a rational). Square
   roots are replaced by verified rational upper bounds s̄ with s̄² ≥ s. DESIGN reason: a γ̄ computed by any
   other valid bound (for example the condition-number bound of the literature) can be a true upper bound and
   still lie below the checker's own looser per-k bound, and the checker would then reject a true root; the
   proposer therefore computes the quantity the checker verifies. For a univariate quadratic this gives
   γ = |f″(z)/(2·f′(z))| exactly, which is the hand case.
3. If ᾱ = β̄·γ̄ is below (13 − 3√17)/4 (compared exactly: 13 − 4ᾱ > 0 and (13 − 4ᾱ)² > 153), emit an
   `alpha-root` proof object in the checker's payload: the system's digest and sparse monomial lists, the degree
   bound d, z with real and imaginary parts as reduced rationals, the matrix B, β̄, γ̄, and the claimed label
   (`real`, `non-real` or `unlabelled`, the checker's vocabulary); the bundle lists the assumption
   `smale-alpha-theorem`. Otherwise refine once more; if it still fails, the endpoint is uncertified and counts
   as lost for labelling.
4. Distinctness over the certified set: every pair must have ‖z₁ − z₂‖ > 2·(β₁ + β₂). A pair that fails is
   resolved by refining both; a pair that still fails is one root reported once and the event is recorded.
5. Reality: `real` if ᾱ < 3/100 and ‖z − Re z‖²·400·γ̄² < 1; `non-real` if ‖Im z‖² > 4·β̄²; otherwise
   `unlabelled`. Only `real` roots become physical candidates.

**Label (per query).** With G the generic count stored in the generic-solve artifact, m = G − (start
solutions the artifact holds) the starts that are missing, c the number of certified distinct finite roots, s
the number of endpoints classed `singular` or `at-infinity`, and ℓ the number of failed paths, uncertified
regular endpoints and missing starts (each missing start is a root whose path was never tracked, so it counts as
lost: one start removed from a 40-root artifact gives `Partial(39, 1)`, as the pilot froze). The trace test's
result is bound to the artifact's content hash: an artifact whose bytes changed after its trace receipt (a
removed or duplicated solution) has no receipt and is re-tested on load before any label is issued.
- `Complete` iff the artifact's trace test passed, ℓ = 0, no endpoint signals a positive-dimensional component
  (no singular endpoint with a rank-deficient Jacobian that persists under refinement), and c = G: the
  certified count equals the generic count.
- otherwise `Partial(c, ℓ)`. A target whose roots partly went to infinity or merged (s > 0) is therefore
  `Partial`, with s and the endgame's classification stated as the reason; the answer always states c, s, ℓ
  and G.
A `Partial` label is carried by every candidate of the query and by the answer; `frob-mission` refuses to use a
`Partial` result as an exclusion (it is a search that may have missed roots, and a failed search is never an
exclusion).

**Strategy surface.** `frob mission synthesize q.fmission --strategy continuation --family <id> --key <k>
--json` (a run verb: the idempotency key is required; `--family` names the family whose generic-solve artifact
is used and is added to the verb's inputs by this bead; feature-gated; without the feature, exit 5 with
`FROB-REF-724` naming the feature). Flow: build p₁ from the query; run the engine; certify; label;
map each `real` certified root to mechanism dimensions; run the circuit, branch and clearance certificate of the
exact lane on each mechanism; emit candidates (label `Complete` or `Partial(c, ℓ)` plus the per-mechanism
certificate verdict) as modules. `--estimate` shows the one-time generic solve separately. A family with no
stored generic solve and no budget for one is refused under the budget family with the estimate attached
(`FROB-REF-701`). The lane is the second repair named by `FROB-REF-857`.

**Class.** Each root: `Certified` once the auditor accepts its `alpha-root` object. The completeness statement:
`Tested` (a numerical count check), never `Certified`. The answer's class is the weakest among what it relies
on; an inclusion that relies only on one certified root and its mechanism certificate does not rely on
completeness.

## Acceptance criteria

- [ ] f = z² − 2 at z = 3/2: β = 1/12, γ = 1/3, α = 1/36; certified, `real`, root within 1/6. At z = 3:
      α = 7/36; no certificate. f = z² + 1 at z = 11i/10: α = 21/484; certified, `non-real`.
- [ ] The comparison with (13 − 3√17)/4 is exact (no floating-point threshold).
- [ ] With one start solution removed the label is `Partial(39, 1)` on the Stewart–Gough family, never `Complete`.
- [ ] A `Partial` result offered to `frob-mission` as an exclusion is refused; offered as an inclusion of a
      found design it is accepted with its own certificates.
- [ ] Duplicated endpoints are reported once; a perturbed root fails certification and counts as lost.
- [ ] Every candidate carries its label and has no verdict (INV-AUGUR-11); the completeness statement prints
      `Tested`.
- [ ] Reachable through `frob --json` and `frob-mcp` behind the feature; cancellation tested; `CONTRACT.md`
      states what an α-test does not prove.

## Test plan

### Unit tests
`crates/frob-synth/tests/continuation_certify.rs`:
- `alpha_hand_cases` (the three above); `threshold_exact`: α = 157/1000 passes, 158/1000 fails.
- `distinct_balls`: z = 3/2 and z = −3/2 for z² − 2 are distinct (distance 3 > 2·(1/12 + 1/12)).
- `reality_classes`: 3/2 `real`; 11i/10 for z² + 1 `non-real`; a point with α = 1/10 `unlabelled` for reality.
- `gamma_bar_meets_checker_rule`: on the hand cases and on the 40 roots of one Stewart–Gough target, every
  emitted γ̄ satisfies the checker's per-k inequality and every object is accepted by the real auditor
  (N12p1-01); on the two-conic system, where the Frobenius-type tensor bound is strictly looser than the true
  operator norm, a γ̄ set to the true γ (a valid bound on γ, but below the checker's per-k bound) is rejected at
  `alpha.gamma`, which is the reason for step 2's rule.
- `payload_matches_checker`: B, β̄, γ̄ and the label are present and reduced; `smale-alpha-theorem` is listed.
- `label_complete`: G = 4, c = 4, ℓ = 0, trace passed → `Complete`; `label_partial_lost` (ℓ = 1);
  `label_partial_trace_failed` (trace failed with c = G still gives `Partial`); `label_infinity_is_partial`
  (c = 3, s = 1 classified at infinity, G = 4 → `Partial(3, 0)` with the reason stated);
  `label_missing_start_is_lost` (two-conic artifact with G = 4 holding 3 starts, all 3 certified → m = 1,
  `Partial(3, 1)`, and the re-run trace test fails because the artifact's hash no longer matches its receipt).
- `partial_never_excludes`: the mission core refuses a proposed exclusion backed by a `Partial` label.
- Property test: for random rational quadratics with distinct roots, points within 1/10 of the gap from a root
  are certified and their balls contain the root.

### End-to-end script and logging
`scripts/e2e/synth_continuation_strategy.sh` (sources the STD-E2E helper; idempotent; seed explicit). It uses
only this bead and its dependencies, on the hand-family fixtures of N25d-22 (z² − p; the two conics at
p = (5, 2)); the gate script `scripts/e2e/augur_synth_continuation.sh` (N25d-24, which depends on this bead)
calls it as its `strategy-smoke` stage before the Stewart–Gough sets.

1. `frob mission synthesize sqrt2.fmission --strategy continuation --family sqrt --key cs-1 --json`: assert two
   certified roots ±√2 with their `alpha-root` objects, both `real`, label `Complete`, G = c = 2.
2. The two-conic query (`--family two-conics --key cs-2`): assert four certified roots (1, 2), (2, 1), (−1, −2),
   (−2, −1), label `Complete`, and `frob-verify` accepting every object.
3. The same call through `frob-mcp` (tool `mission_synthesize`, key `cs-3`): assert the envelope digest equals
   the CLI's apart from the key and timing fields.
4. The two-conic query against a scratch ledger holding a planted copy of its artifact with one solution removed
   (`--key cs-4`): assert `Partial(3, 1)` on the answer and on every candidate, the trace test re-run and failed,
   the three found designs included with their own certificates, and no cell excluded on the strength of the
   continuation result (the standing rule of N25-REF: a search that may have missed roots is never an
   exclusion).
5. `frob mission synthesize … --family two-conics --sync-wait-ms 0 --key cs-6 --json` against an empty scratch
   ledger, so the generic solve runs as a job; then `frob job cancel <job> --json` and `frob job status <job>
   --json`: assert the job ends cancelled and no generic-solve artifact was stored.
6. A build without the `continuation` feature (`--key cs-7`): `FROB-REF-724`, exit 5; a family with no stored
   generic solve under a zero budget (`--key cs-8`): `FROB-REF-701` with the estimate attached.

Logged per STD-E2E: the exact command, exit code, wall time, the envelope's evidence block, per root β̄, γ̄ and
ᾱ against 0.157671 and its reality class, c, s, ℓ and G with the label, envelope digests of the CLI and MCP
calls, the job states, refusal codes, and on failure the first differing root with the data to reproduce.

### Known answers and negative controls
KA-655; the hand cases. Mutations the auditor must reject: a changed coefficient of f; z moved off the
certified point; a claimed `real` class on a point with ‖z − Re z‖·γ ≥ 1/20. Proposer controls: a build that
labels by count without the trace test issues `Complete` on the removed-solution case and is caught; a build
that skips distinctness double-counts a root and reaches a false count.

## Considerations

- The γ bound is conservative; a true root may need several refinements before its bound drops below the
  threshold. Refinement is cheap; a root that never certifies is reported, not hidden.
- If KILL-SYNTH-CONT fires, the label machinery stays and every result is `Partial`.
- The bound's exact form is fixed by the checker's rule (N12p1-01, `alpha.gamma` with the Frobenius-type
  tensor norm); proposer and checker must not share code, only that written definition. If the checker's owner
  changes the norm, step 2 changes with it, and the test `gamma_bar_meets_checker_rule` catches a drift.
