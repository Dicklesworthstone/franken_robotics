## Background

GATE-AUGUR-22 (claim: Known answer; milestone M8; TARGET): "Continuation: 40 certified Stewart–Gough roots on
10 generic parameter sets; `Complete` issued only when the trace test agrees; lost paths at most 0.1% and
every one flagged." It measures the Moonshot lane `--strategy continuation` of `mission.synthesize`
(epic BD-437): one generic complex instance of a mechanism family is solved once by monodromy, each new
specification is reached by a parameter homotopy H(z, t) = F(z; (1 − t)·p₀ + t·p₁), every endpoint is certified
by Smale's α-test (α(f, z) < (13 − 3√17)/4 ≈ 0.157671) in exact arithmetic, and the set is labelled `Complete`
or `Partial(certified_n, lost_n)`.

The family is the forward kinematics of a Stewart–Gough platform (six leg-length equations in the pose of the
platform), whose general solution count is 40 (FACT, literature, to be re-read before this gate cites it).

## Scope

In: the family fixture and ten frozen parameter sets; the script; the controls; the gate record. Out: the
engine and certification (N25d-22, N25d-23); the pilot (N25d-21); the kill decision (N25d-25).

## Technical approach

**Fixtures (`crates/frob-conformance/fixtures/augur/continuation/`).** The family definition in the
formulation the pilot froze; ten generic real parameter sets (rational anchor coordinates and positive squared
leg lengths, address-seeded, checked for genericity: 40 finite distinct complex roots each, as the pilot
recorded); a derivation note with the re-read source of the count 40. The two hand families for smoke tests
(z² − p; the two conics with p = (5, 2) and roots (1, 2), (2, 1), (−1, −2), (−2, −1)) are N25d-22's family
fixtures, not copies.

**Script steps.** Stage `strategy-smoke` first: `scripts/e2e/synth_continuation_strategy.sh` (N25d-23) runs on
the hand families, its log is kept, and the gate run continues only on its zero-failure summary.
1. `frob mission synthesize sg-<k>.fmission --strategy continuation --family stewart-gough-fk --estimate
   --json`: the one-time generic solve appears as its own line (an estimate is read-only and takes no key).
2. The same without `--estimate`, for k = 1 … 10, with `--key ag22-<k>` (one distinct key per set; the first
   call builds the generic-solve artifact as a job; later calls reuse it).
3. Assert per set: paths tracked 40; lost 0; certified distinct roots 40; the trace residual below tolerance;
   label `Complete`; counts of `real` and `non-real` roots sum to 40 with none `unlabelled` (the checker's
   label vocabulary); every candidate
   built from a real root carries the label and a null verdict.
4. Per set, `frob prove bundle a:<answer> --out <scratch>/sg-<k> --key ag22-b<k> --json`, then `frob prove
   verify <scratch>/sg-<k> --json` and the standalone `frob-verify <scratch>/sg-<k>` on a host with no GPU: every
   `alpha-root` object accepted; total checker time recorded.
5. Lost-path accounting over everything tracked in the run, including the monodromy loops of the generic
   solve: lost share at most 0.1%, and every lost path present in the answer's flagged list with its start
   solution and failure point. (For the 400 target paths alone, 0.1% allows none.)
6. Controls, each required to produce the stated outcome:
   - `drop-start`: one stored solution removed from the artifact → the trace test fails and the label is
     `Partial(39, 1)`; a `Complete` here fails the gate.
   - `count-only-label`: a build that labels by count without the trace test → issues `Complete` on a
     doctored artifact with a duplicated solution in place of the removed one; caught by the distinctness check
     and by the trace residual.
   - `perturbed-root`: one endpoint moved by 10⁻³ → its α bound exceeds the threshold; the auditor rejects the
     object; the label becomes `Partial`.
   - `silent-loss`: a tracker build that drops failed paths without flagging → the path accounting (tracked
     ≠ sum of classes) fails.
7. Refusal row: `--strategy continuation` in a build without the feature (`--key ag22-r1`) exits 5 with
   `FROB-REF-724`; a family with no stored generic solve under a zero generic-solve budget (`--key ag22-r2`) is
   refused with `FROB-REF-701` and the estimate attached.

**Gate decision.** All ten sets `Complete` with 40 certified roots; lost-path share within 0.1% and all
flagged; `Complete` never issued with a failing trace test; all four controls behave as stated.

**Recording the gate.** The script writes receipts and never writes `registries/gates.toml`. GATE-AUGUR-22 is
recorded once, after `scripts/e2e/run-all.sh --gate GATE-AUGUR-22` has run this script, by a session that did
not implement the lane (N25d-22, N25d-23), with `cargo run -p frob-conformance --example record_gate -- --gate
GATE-AUGUR-22 --receipt <hash>`.

## Acceptance criteria

- [ ] The ten sets, the family definition and the count's source are committed before the run.
- [ ] GATE-AUGUR-22 is recorded in `registries/gates.toml` with: certified roots per set, lost and flagged
      counts, the lost share, trace residuals, labels, the one-time generic-solve cost, the commit, the
      hardware fingerprint and the seeds, by a session that did not implement the lane, through
      `cargo run -p frob-conformance --example record_gate -- --gate GATE-AUGUR-22 --receipt <hash>`.
- [ ] All four controls are caught in the same run.
- [ ] Every `alpha-root` object is accepted by `frob-verify` on a host with no GPU.
- [ ] The script is idempotent and resumable (the artifact is reused by content address).

## Test plan

### Unit tests
`crates/frob-conformance/tests/augur_continuation_fixtures.rs`: the ten sets parse and are distinct; the
smoke families return their hand answers; the accounting identity (tracked = regular + singular + at-infinity
+ failed) is asserted on a recorded run; the control list names the assertion each control must break.

### End-to-end script and logging
`scripts/e2e/augur_synth_continuation.sh`. Log at `target/e2e-logs/augur_synth_continuation/<utc>.ndjson`:
every command with exit code and wall time; the evidence block; the artifact's identity, loops, paths, trace
residual and wall time; per set the path statistics, the smallest and largest α bound against 0.157671, the
certified, real and non-real counts and the label; per control its outcome; `metric` lines for the lost share
(threshold 0.001), unflagged losses (threshold 0) and checker seconds; on failure the first failing path or
root with the data to reproduce; a `summary` naming the gate.

### Known answers and negative controls
KA-655 (40; and 16 for 6R, not exercised here). The four controls. Metamorphic relation: permuting the six
legs of a parameter set permutes nothing in the root set (the same 40 poses). Determinism lanes: twice on one
machine with a fixed thread count gives identical labels, counts and certificate bytes; across machines the
counts, labels and certified boxes' contents are compared.

## Considerations

- If the count 40 is not confirmed by the re-read source, the gate is blocked until the family's count is
  established some other way; the trace test alone is not an independent source for the gate's truth.
- A parameter set that turns out non-generic is replaced before the run, never after.
- Compute: 400 target paths are seconds; the generic solve is minutes; exact certification of 400 roots is the
  larger cost and is reported.
