## Background

The first slice of Augur that an implementer can finish is small on purpose: two gains, two packet timings, one
actuator bound, one observation-noise family. It ships as a CPU worked example before the first complex GPU
kernel exists, and it is the M1 exit demonstration for the mission-query chapter. It exercises the five
interfaces every later mission needs: a causal history, a feasible controller, two indistinguishable worlds, an
exact physical parameter chart, and an independent checker.

The mission (the docking family). Position in metres, time in seconds. A robot docks in three one-second ticks
from x₀ = v₀ = 0 with acceleration g·u_k held constant over tick k, a hidden gain g ∈ {1, 2} fixed for the
execution, commands bounded by |u_k| ≤ U, and target (x₃, v₃) = (1, 0). Exact integration gives
v₃ = g·(u₀ + u₁ + u₂) and x₃ = g·(5u₀/2 + 3u₁/2 + u₂/2). The only informative packet is the first velocity
reading v₁ = g·u₀, with additive error in [−ε, +ε]; it arrives either before the second command is decided or
after the third command is committed.

The exact answer. With the packet on time a robust causal policy exists exactly when ε < (U + 1/2)/4 on
U ∈ [1/2, 1], equality excluded. With p = u₀, the terminal equations force u₁ = 1/g − 2p and u₂ = p − 1/g; the
bounds give 1 − U ≤ p ≤ (U + 1/2)/2; the reading sets centred at p and 2p must be disjoint, p > 2ε. At U = 3/4
and ε = 5/16 with p = 5/8 both worlds can report 15/16 while needing second commands −1/4 and −3/4: the strict
predicate fails and the infimum is not attained. With the packet late no causal policy works for both gains
(the terminal position of a common command vector scales with g).

The slice's evidence (what buys the next investment): the offline checker reproduces the boundary, finds the
exact shared reading at equality, and accepts an ordinary scenario-tree program as a competing answer; the
agent can say which hardware restriction to relax. Decision if it fails: repair the mapping from sensors and
actuators to the game before adding physics, and ship the reference algorithm if it gives the better answer
per engineering hour.

## Technical approach

**No demo directory of its own (DESIGN).** The plan calls this slice the M1 exit demonstration of the mission
chapter, and the milestone's exit line names the docking scenario, NS-22: they are one demonstration, so there
is one demo file, `demos/ns-22/demo.yaml` (NS-22), and `demos/` holds no second directory for docking. This
bead is the script that gathers the chapter's evidence for the slice; its record is what NS-22 and BD-140 cite.
The script's commands run in under 60 s in total on the CPU tier (TARGET); its claims are those of
GATE-AUGUR-03 (cited from N25c-22's record) and GATE-AUGUR-05.

**Script steps** (every command with `--json`; every run or mutate verb with its own `--key`, so that no step
returns another step's stored receipt).
1. `frob mission new docking --template docking@1 --key s1-mis-1` (a template with the new query's name, as
   VERBS-mission's `mission.new` row reads): it returns `q:<MissionId>` and `bound.family` naming the template
   with its content hash. Assert that this `MissionId` equals the one `frob mission check
   fixtures/missions/docking/docking.fmission` records (N25c-22's fixture, written by BD-129; NS-22 relies on the
   same identity, so that the two scripts ask one query). Then `frob mission check q:<MissionId>`: the
   quantifier prefix is echoed (exists policy per nominal design; for all worlds; for all executions) and the
   observation's arrival instant is stated. Later steps name the query `q:<MissionId>`.
2. `frob mission synthesize q:<MissionId> --key s1-syn-1` over the chart (U, ε) with U ∈ [1/2, 1]: assert the
   inner region is ε < (U + 1/2)/4 with its end open; the witness policy at (U, ε) = (3/4, 1/4) uses probe
   p = 5/8; the two exact sequences for ε = 0 and p = 1/4 are (1/4, 1/2, −3/4) for g = 1 and (1/4, 0, −1/4) for
   g = 2.
3. Grid check on step 2's answer (the mission carries the grid, so nothing is solved again): `frob mission show
   q:<MissionId> --answer a:<step 2> --set inner --json` and the same with `--set excluded`, following the
   returned `cursor` until each set is exhausted: 17 actuator bounds at spacing 1/32 and 33 error levels at
   spacing 1/64 give 561 cells: 344 admitted, 217 excluded, nine of them exact boundary cases.
4. `frob prove bundle a:<step 2> --out <scratch>/s1-ours --key s1-cb-1` then the standalone `frob-verify
   <scratch>/s1-ours` in an empty environment (no GPU, no network): accepted; the proof kinds are `finite-game`
   (inner cells), `lp-farkas` and `alias-pair` (the pieces of each excluded cell's probe axis) and `partition`.
5. `frob mission refute fixtures/missions/docking/docking-point.fmission --key s1-ref-1` (N25c-22's single-cell
   fixture U = 3/4, ε = 5/16; `mission.refute` takes a cell, a design or, only from M3, the whole family, so the
   point is given as its own query, as N25c-22's step 5 gives it): returns `mode = scope`, the alias pair (both
   worlds read 15/16; required second commands −1/4 and −3/4), the binding constraint, and the repair as an
   open threshold: U > 3/4, `attained: false`, with a feasible priced candidate and its gap; or a smaller read
   error below 5/16. This is the "which hardware restriction to relax" read-out.
6. The rival's answer through the same checker: the independently written scenario-tree linear program for the
   same mission (`frob mission synthesize q:<MissionId> --lowering scenario-tree --key s1-syn-rival`, N25c-20)
   and its bundle (`frob prove bundle a:<rival> --out <scratch>/s1-rival --key s1-cb-2`); `frob-verify` accepts
   it; its cells equal step 2's on all 561 grid cells.
   The script records which producer wrote each bundle. (A rival's answer goes through the same checker; if the
   conventional program gives the same checked scope at similar turnaround, it ships behind the same verbs.)
7. Mutate the packet timestamp: the arrival instant after the third command's commitment, through N25c-22's late
   fixture (`frob mission new fixtures/missions/docking/docking-late.fmission --key s1-mis-2` → `q:<late
   MissionId>`, then `frob mission check` and `frob mission synthesize q:<late MissionId> --key s1-syn-late`):
   `MissionId` changes; every one of the 561 cells is excluded by an `alias-pair` certificate whose
   scope is all admitted policies. The on-time bundle offered for the late query
   (`frob prove verify <on-time bundle> --query q:<late MissionId>`, and the standalone `frob-verify` with the
   same query file) is rejected with `FROB-REF-826` by the auditor's query-match rule: the bundle's policy class
   (`plant.policy_class`) records the packet before the second command, the query's after the third; the first
   failing rule is logged. Without `--query` the same bundle is still accepted: it is a valid certificate of its own claim.
8. Write the slice record: the commit, evidence identifiers, the bundle digests and checker verdicts of steps
   4, 6 and 7, timings of steps 2, 4 and 6 for both producers (the measured half of the first reading of the
   tie rule), and the proposed status `evidence-met` or `stopped`. The script proposes; the status is set by the
   M1 exit review's ADR (N25d-26's rule: the reviewer reads the record and the carriers' gate rows and writes the
   ADR), so a script run never stops or advances the slice by itself.

**Tie fields.** One reading, one field list (DESIGN, the same list in BD-140). The record states, without
interpretation, for each producer the four fields a script can measure: `same_checked_scope` (both bundles
accepted and the cells equal on all 561 grid cells), `wall_time_to_checked_answer_s`, `checker_time_s` and
`mission_specific_lines` (lines of mission-specific code). BD-140 copies them into the record of
GATE-AUGUR-07, adds `authoring_hours` for each producer from the beads' own logs, and states the first reading
of KILL-AUGUR-TIE; this bead states no reading. The decision "ship the reference algorithm if it gives the
better answer per engineering hour" is made by the M1 exit review from those records.

## Acceptance criteria

- [ ] The script's commands finish in under 60 s in total on the CPU tier (TARGET), and the claims it cites exist
      in `registries/gates.toml`. No directory `demos/augur-docking/` exists: the demo of the slice is
      `demos/ns-22/` (NS-22).
- [ ] Steps 2, 3, 5 and 7 return the exact values above (rationals compared as strings).
- [ ] The standalone checker accepts both producers' bundles and rejects the on-time bundle offered with `--query` for the late query (`FROB-REF-826`), while accepting it without `--query`.
- [ ] The repair is reported as an open threshold with `attained: false`, not as a minimum.
- [ ] No unresolved cell is printed as a verdict anywhere in the transcript.
- [ ] Negative controls: a non-strict comparator build admits the equality cells and fails step 3 (it reports
      353 admitted: the nine boundary cells inner); a build that ignores the arrival instant passes the late-packet
      mission and fails step 7.
- [ ] The slice record is written with the commit, the bundle digests, the checker verdicts and the four tie
      fields per producer; the M1 exit review, BD-140 and NS-22 can read it.

## Test plan

### Unit tests
`crates/frob-conformance/tests/augur_docking_demo.rs`: `sequences_reach_target` (both sequences give
(x₃, v₃) = (1, 0) exactly); `equality_reading` (5/8 + 5/16 = 15/16 = 5/4 − 5/16); `grid_counts` (561 = 17 × 33;
344 + 217); `late_packet_no_common_vector` (x₃ scales with g); `mission_id_changes_with_arrival`.

### End-to-end script and logging
`scripts/e2e/augur_slice1_docking.sh`. It sources the STD-E2E helper and logs to
`target/e2e-logs/augur_slice1_docking/<utc>.ndjson` with a transcript beside it; every line carries `ts`,
`script`, `bead`, `step`, `event`; every command with its exact line (key included), exit code and wall time; the envelope's evidence block (class `Certified`, tier `static`, determinism
`exact`, mission and bundle identities); `assert` lines for each exact value; the producer of each bundle and
the checker's verdict and time; `refusal` lines where a bundle is rejected, with the first failing rule; the
561-cell tallies; `metric` lines for both producers' times; on failure the first differing cell; a `summary`
naming GATE-AUGUR-03 and GATE-AUGUR-05.

### Known answers and negative controls
KA-635 (on-time sequences), KA-636 (late packet: no common command vector; all 561 excluded), KA-637 (the
family; 344, 217, 9; the reading 15/16); CX-275 (sample points do not exclude a straddling cell: the nine
boundary cells). Controls: the two builds above. Determinism lanes: twice on one machine (the second run with
its own keys, `s1-<step>-<n>-d2`, so that it recomputes); debug and release; bundle digests identical (exact
class); a second host for the bundle digest. The worker-count lane is the docking lowering's own (BD-129):
`mission.synthesize` carries no worker option, so this script cannot vary it.

## Considerations

- Everything here is a scalar model: no device timing and no physical claim follow from it.
- A third gain (33/32) reverses every positive cell; that amendment belongs to the docking bead's own tests and
  to slice 2's theme (certificates are bound to their declared support).
- The script is the demonstration; it does not replace the gate's own measurement, which the docking bead
  records.
