## Background

Augur's answers are believed only because an independent checker accepts their certificates. The checker lives
in the crate `frob-cert` (binary `frob-verify`), depends on the Rust standard library and nothing else, and
carries its own big-integer, rational and interval arithmetic. That makes five properties of the checker and
of the bundle format load-bearing for every mission claim. They are proof obligations of the chapter:

| ID | Obligation | Verification named by the chapter |
|---|---|---|
| PO-AUGUR-02 | The checker's big-integer and rational arithmetic is exact | Differential test against an independent implementation on 10⁶ random operations and all fixture certificates |
| PO-AUGUR-03 | The checker's interval arithmetic is outward-rounded using `std` only | Every operation widened by one unit in the last place in each direction; property test that the enclosure contains the exact rational result |
| PO-AUGUR-04 | `partition` checking is exact, including open and closed ends | Exhaustive test on boxes with shared faces, edges and corners in up to six dimensions |
| PO-AUGUR-05 | Bundle bytes are a deterministic function of the answer (class D0) | Encode on two hosts and two worker counts; compare digests |
| PO-AUGUR-07 | The checker's dependency closure is `std` and shares no source file with any proposer | A closure check in the build, and a file-set comparison |

Why they are grouped: each is a test battery around code that other beads write, each has an exact pass
condition, and together they are what "checked" means. Reason for the independence rule behind PO-AUGUR-07: a
Monte Carlo run and a solver that share one mistranslated model agree on the wrong answer, and a checker that
shares arithmetic with the proposer can share its defect.

## Scope

In: the five batteries, their oracles, their mutants and their script. Out: implementing the arithmetic, the
partition rule, the bundle writer or the build checks (their own beads); PO-AUGUR-01 (N25d-34) and
PO-AUGUR-06 (N25d-36).

## Technical approach

Batteries live in `crates/frob-conformance/tests/augur_po_*.rs`. `frob-conformance` may link an independent
exact-arithmetic oracle; `frob-cert` may not.

**PO-AUGUR-02 (exact arithmetic).**
1. Oracle: an independent big-rational implementation that shares no code with `frob-cert` (the exact type the
   proposers use, or the symbolic sibling's, reached from the test crate only).
2. Generate 10⁶ random operations, seeded: add, subtract, multiply, divide, negate, compare, reduce, parse and
   print, on operands from 1 to 4,096 bits, with adversarial cases mixed in (zero, ±1, powers of two, operands
   differing in the last bit, numerators and denominators with a large common factor).
3. Compare results as canonical strings (reduced pair, positive denominator). Any difference fails.
4. Replay every arithmetic step of every fixture certificate (stance, docking, pusher bundles) through both.
5. Size limits: an operand beyond the declared limit is refused by the checker, never approximated; the test
   crosses the limit by one bit.

**PO-AUGUR-03 (outward rounding).**
1. For every interval operation (add, subtract, multiply, divide by an interval excluding zero, square, square
   root, the elementary functions the checker supports), on 10⁶ seeded random rational inputs: compute the
   exact rational result (or a rational enclosure of it for the non-rational functions) with the oracle; assert
   it lies inside the checker's interval.
2. Structural check: the checker's endpoints are produced by rounding to nearest and then stepping one unit in
   the last place outward in each direction (down for lower ends, up for upper ends), using `std` only; the
   test asserts that each endpoint differs from the round-to-nearest value by at least one unit in the last
   place in the outward direction.
3. Edge cases: results that are exactly representable (still widened), subnormals, signed zeros, overflow to
   infinity (the interval becomes unbounded, never a NaN).

**PO-AUGUR-04 (exact partitions).**
1. Family A, exhaustive: in dimension d = 1 … 6, split the unit cube at 1/2 along every axis into 2ᵈ cells.
   Per axis the split point's ownership is one of four cases: owned by the lower cell only, by the upper cell
   only (both valid), by both (an overlap), by neither (a gap). All 4ᵈ assignments (at most 4,096) are checked:
   the checker accepts exactly the 2ᵈ assignments in which every axis is valid.
2. Family B, exhaustive in low dimension: in d ≤ 3, every way of removing one cell, duplicating one cell, or
   shifting one cell's end by 1/1000: all rejected.
3. Family C: shared corners and edges: in d = 2 … 6, a cross-shaped partition where 2ᵈ cells meet at one point;
   exactly one cell owns the point in an accepted partition, and the test flips ownership to zero and to two
   owners.
4. The known answer: a box [4, 12] × [1, 5/2] in thirteen cells accepts; removing a cell, overlapping two, or
   closing an open end rejects.

**PO-AUGUR-05 (deterministic bundle bytes).**
1. Encode the bundles of the stance, docking and pusher answers on two hosts (the Mac and the Linux machine)
   and with 1 and 8 workers on each: four encodings per answer; all digests equal. The hosts vary through the
   public verbs; the worker count varies in process (`po_augur_05_worker_counts`, STD-TEST's
   `testkit::det::lane` over the solve and the bundle writer), because neither `mission.synthesize` nor
   `prove.bundle` carries a worker option and no program-wide one exists.
2. Re-serialize each accepted bundle through reader and writer: identical bytes.
3. Reorder the proposer's internal work (cell order, proof order by schedule) with 20 seeds: identical bytes.

**PO-AUGUR-07 (closure and file sets).**
1. `cargo tree -p frob-cert` prints one line; the copied crate directory builds with no network.
2. The set of source files compiled into `frob-verify` and the set compiled into each proposer
   (`frob-mission`, `frob-lemma`, `frob-synth`, the solvers behind the airlock) are computed from build
   metadata; their intersection is empty.
3. A system-call trace of an audit run shows no socket and no child process.

## Acceptance criteria

- [ ] PO-AUGUR-02: 10⁶ of 10⁶ operations agree; every fixture certificate's arithmetic agrees; over-limit
      operands are refused.
- [ ] PO-AUGUR-03: 10⁶ of 10⁶ enclosures contain the exact result; the one-unit outward step is present on
      every endpoint.
- [ ] PO-AUGUR-04: families A, B and C behave exactly as stated in every dimension up to six.
- [ ] PO-AUGUR-05: all digests equal across two hosts and two worker counts; byte-identical re-serialization.
- [ ] PO-AUGUR-07: the closure is `std`; file-set intersections are empty; no socket or child process.
- [ ] Each obligation's mutant is caught: a rational `reduce` that skips the sign normalization; an interval
      add that rounds to nearest; a partition check that treats all ends as closed; a writer that iterates a
      hash map in insertion order; a helper file shared between `frob-cert` and `frob-lemma`.
- [ ] The five identifiers appear in the test names and in `CONTRACT.md` of `frob-cert`.

## Test plan

### Unit tests
`po_augur_02_differential`, `po_augur_02_fixture_replay`, `po_augur_02_size_limit`;
`po_augur_03_enclosure_contains_exact`, `po_augur_03_one_ulp_outward`, `po_augur_03_edges`;
`po_augur_04_axis_ownership_exhaustive` (for d = 6: 4,096 assignments, 64 accepted),
`po_augur_04_single_defects`, `po_augur_04_corner_ownership`, `po_augur_04_thirteen_cells`;
`po_augur_05_worker_counts`, `po_augur_05_reserialize`, `po_augur_05_schedule_independent`;
`po_augur_07_file_sets`.
Hand values used: 2/4 is refused as non-reduced; 1/3 + 1/6 = 1/2; the interval [1/3] as a pair of doubles
strictly contains 1/3; the stance boundary cell ends at 14/3, closed on the inner cell and open on the
excluded one.

### End-to-end script and logging
`scripts/e2e/augur_checker_obligations.sh`: builds `frob-verify` from a copy of the crate directory in an
empty environment, runs the batteries (whose `po_augur_05_worker_counts` covers 1 and 8 workers on each host),
and performs the two-host encoding through the public verbs: on each host (the second over the fleet's remote
build path), `frob mission synthesize` on the stance, docking and pusher missions and `frob prove bundle` on
each answer, each call with its own key (`--key po05-<mission>-<host>` and `--key po05-b-<mission>-<host>`), so
that every host computes and encodes its own answer instead of being served the stored receipt of an earlier
call (a shared key would make the digest comparison vacuous), then compares the Merkle roots and per-entry
digests across hosts and with the in-process worker-count digests. It sources the STD-E2E helper and logs to
`target/e2e-logs/augur_checker_obligations/<utc>.ndjson` with a transcript beside it; every line carries `ts`,
`script`, `bead`, `step`, `event`, the exact command line, exit code and wall time. Per obligation: the counts
run and agreed against the required ones (10⁶; 4,096 and 64 at d = 6), seeds, the first failing operation
with its operands if any, digests per host and worker count with the first differing entry, the dependency
tree and the file-set intersection, the trace summary; a `summary` with five rows (passed, failed or
`not run`).

### Known answers and negative controls
The five mutants above. Metamorphic relations: a + b = b + a and (a·b)/b = a for b ≠ 0 in exact arithmetic;
splitting a cell in two keeps a partition valid. Determinism lanes: the whole of PO-AUGUR-05.

## Considerations

- The differential oracle is test-only; it must never become a dependency of the checker.
- "Exhaustive" for partitions is exhaustive over a structured family; a fully general enumeration of box
  partitions in six dimensions is infeasible, and the family was chosen to cover faces, edges and corners.
- The second-host step needs both machines; if one is unavailable the row is `not run`, never passed.
