## Background

The Solid fragment of mission queries is made of small linear programs: is there a set of foot forces that
balances a load inside every foot's rating (the stance family), is there one command vector that works in both
worlds of a scenario tree (the docking family). A cell of the answer becomes inner or excluded only when an
independent checker, written against the standard library alone with its own exact rational arithmetic,
accepts a certificate: a rational feasible point (`lp-primal`) or a rational dual vector y with
yᵀw > Σᵢ max(0, (Aᵀy)ᵢ)·cᵢ (`lp-farkas`). The rule is "propose anywhere, check on the CPU in exact or
outward-rounded arithmetic" (ADR-AUGUR-04): nothing a proposer says is believed.

That leaves the proposer free, and OPEN-AUGUR-2 asks how it should work. **Default (in force until decided):**
solve in floating point in the cone solver of `frob-algebra`; the floating-point solution names an active set;
the basis system is solved exactly over ℚ; the checker tests exact primal feasibility and, for an optimum,
exact dual feasibility; **a failed reconstruction leaves the cell unresolved.** **Alternative:** solve the
program exactly over ℚ in the proposer (an exact rational simplex), which never fails to reconstruct and costs
big-rational pivoting. Owner: the Augur lead. Decided at GATE-AUGUR-02, from the measured reconstruction
failure rate; this is a question that evidence decides, not preference.

The default is fail-closed because a failure removes a verdict (the cell is unresolved) and can never add one:
"no numerical failure, timeout or failed search is recorded as an exclusion" (INV-AUGUR-06). What it can cost
is coverage exactly where it matters. At the boundary of the stance family (half-width b = 3/14 m, load
vertex P = (60, 30) N·m) the witness (160, 130, 110, 0) N has two bounds active at once (the 160 N rating of
one foot and the zero floor of the opposite one) on a feasible set that has shrunk to one point: a degenerate
vertex, where a floating-point solver returns values like 159.99999999 and 10⁻⁹ and the active set must be
guessed. The certificate format and the checker are identical under either option; only the proposer changes.

## Scope

In: the registered workload on which the rate is measured; the decision rule; the comparison timing of an
exact solve on the same workload; the ADR and register row. Out: the reconstruction mechanism and its counters
(see `needs`); the stance and docking families (BD-130, BD-129); the checker (BD-132).

## Technical approach

**1. Workload W₂ (frozen before the gate run, identified by hash).**

| Part | Programs | What is reconstructed |
|---|---|---|
| Stance grid: u, v ∈ {2, 3, 4}, ratings ∈ {0, 80, 160, 240}⁴, four load vertices and the centroid | 11,520 | A rational allocation for each of the 2,254 feasible states; a rational dual for each of the 9,266 infeasible ones |
| Stance family, lifted robust program and projected (wrench-zonotope) form | the four vertex programs and the excluding dual of each form | Witnesses at v = 14/3 (b = 3/14 m), where two bounds are active; the dual (0, 1/2, 1/2) for v ∈ (14/3, 6] |
| Docking comparator (scenario-tree program) | 51 + 3 | Two extrema for the first command and one common-command feasibility program per actuator bound; three fixed-probe controls |

So N ≥ 11,574 attempts plus the family-level programs. Each attempt records: path taken, success or the stage
that failed, wall time of the floating-point solve and of the exact basis solve, bit length of the largest
numerator and denominator.

**2. Measured quantities.** F = attempts whose cell was left unresolved because reconstruction failed;
F_b = those among cells whose exact answer the fixture fixes at a boundary (the four boundary vertex
programs; the nine boundary cells of the docking grid); R = failures recovered by one exact retry of that
program; t_float, t_exact = median and 95th-percentile time per program for the default route and for an exact
rational solve of the same program (the exact arm exists for this measurement even if it is not adopted).

**3. Decision rule (DESIGN proposal; thresholds may be amended by the Augur lead before the gate run only).**

| Condition on the record | Outcome | What ships |
|---|---|---|
| The record covers fewer attempts than W₂ | `insufficient` | No decision; the default stays in force |
| F = 0 | `keep-default` | Floating point, reconstruction, exact check |
| F > 0, every failure recovered by an exact retry, and F/N < 1% | `hybrid` | The default route with an exact rational solve as the fallback path before a cell is declared unresolved |
| F/N ≥ 1%, or F_b − (recovered boundary failures) > 0 | `exact` | The Solid fragment's programs are solved exactly over ℚ in the proposer; floating point is kept only as a warm start |

The gate itself forces the question: GATE-AUGUR-02 needs the boundary exactly at 3/14 m, four vertex witnesses
and 11,520 of 11,520 grid states agreeing with an independent test, so an unrecovered failure on W₂ fails the
gate as well as triggering `exact`.

**4. Constraints on any outcome.** The proposer's exact arithmetic is never the checker's: the checker's
dependency closure is the standard library and it shares no source file with any proposer (PO-AUGUR-07). A
failed reconstruction never weakens a comparator or widens a tolerance. The answer's class is unaffected: a
cell is `Certified` only by an accepted certificate.

**5. Records.** `docs/adr/ADR-OPEN-AUGUR-2.md` with N, F, F_b, R, the path histogram, both timing pairs, the
largest coefficient size, the rule's outcome and the owner's signature; the register row moves to `decided`.
The decision is re-read when the first program with friction-cone rows or more than about 50 variables is
lowered (HYPOTHESIS: reconstruction degrades with size and conditioning; the M1 programs have 4 variables).

## Acceptance criteria

- [ ] W₂ is frozen with a hash before the gate run; the record covers every program in it.
- [ ] The record states N, F, F_b, R, the path histogram, t_float and t_exact (median and 95th percentile, in
      microseconds) and the largest coefficient bit length.
- [ ] The rule's outcome is reproduced from the record by the script; the ADR cites the record's ledger
      identifier and is signed by the Augur lead or recorded as "default at deadline".
- [ ] Zero cells in the record are excluded without an `lp-farkas` certificate (a failed solve counted as an
      exclusion is an INV-AUGUR-06 violation and fails this bead).
- [ ] Under `hybrid` or `exact`, a file-set comparison shows the proposer's exact code shares no source file
      with the checker.
- [ ] Negative controls: the three synthetic records below give the stated outcomes; a record with 11,000
      attempts gives `insufficient`.

## Test plan

### Unit tests
`crates/frob-conformance/tests/open_questions.rs`:
- `oa2_keep_default`: (N, F, F_b, R) = (11,587, 0, 0, 0) → `keep-default`.
- `oa2_hybrid`: (11,587, 3, 0, 3) → `hybrid` (rate 0.026%).
- `oa2_exact_by_rate`: (11,587, 200, 0, 200) → `exact` (rate 1.73%).
- `oa2_exact_by_boundary`: (11,587, 1, 1, 0) → `exact`.
- `oa2_insufficient`: (11,000, 0, 0, 0) → `insufficient`.
- `oa2_no_failure_is_exclusion`: a record with 9,267 excluded states and 9,266 Farkas certificates is rejected.
- `oa2_degenerate_vertex` (runs the real proposer): the stance program at v = 14/3, P = (60, 30) N·m returns
  exactly (160, 130, 110, 0) N by whichever path, or `Failed`; never a rounded neighbour.

### End-to-end script and logging
`scripts/e2e/open_augur_2.sh`: runs `frob mission synthesize` on the stance grid and family and on the docking
comparator with reconstruction counters enabled, then the exact arm on the same programs, applies the rule and
logs per part of W₂: attempts, failures by stage, recovered, both timings with units, coefficient size; then the
rule's inputs and outcome, and a `summary`. Each line carries the envelope's evidence block and the seed
(none: the workload is deterministic). Exit non-zero on `insufficient` or on any failure counted as an exclusion.

### Known answers and negative controls
KA-624 (boundary b = 3/14 m; forces (160, 130, 110, 0) N; 165 N needed at b = 1/5 m), KA-625 (2,254 of 11,520
feasible), KA-657 (51 programs agree), KA-658 (11,520 of 11,520). Planted failure: a proposer build whose
active-set tolerance is set to 10⁻² so that reconstruction fails on boundary vertices; the record must show
F_b > 0 and the rule must return `exact` or `hybrid`, never `keep-default`. Determinism: the record's counts
are identical twice on one machine and across worker counts; timings are not compared.

## Considerations

- The M1 programs are tiny, so t_exact may be smaller than t_float plus reconstruction. If so, `exact` is the
  simpler system and the rule should not be read as preferring floating point; the ADR may choose `exact` on
  simplicity with the timings as its reason.
- Proposals made on a device in single precision go through the same reconstruction; their failure rate is
  measured separately when family screens exist (M4) and may reopen this decision for that route only.
- A failure rate measured on fixtures says little about conditioning on real robots; the re-read trigger above
  exists for that reason.
