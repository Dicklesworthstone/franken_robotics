## Background

An open question is a decision the plan has not taken, written so that not taking it is safe. Every open
question has an owner, a deadline expressed as the gate or milestone it blocks, a fail-closed default, and the
evidence that would decide it. Five clauses make that operational: (1) a default removes a claim or a
capability and never adds one; (2) a question is asked one milestone before the gate it blocks, and one that
reaches its deadline at its default is reported in the exit review with the capability it removed; (3)
evidence decides where evidence exists, and only the owner's questions are decided by judgement; (4) a closed
question is tombstoned, not reused; (5) the register adopts the identifiers the chapters defined, and where a
chapter named no owner the lead of its subsystem owns the question. Nothing is decided by silence: at its
deadline an undecided question takes its default, and the default is recorded as an ADR.

Augur (mission queries over families of designs) has eleven. A default that nobody tests is a default that
drifts: an admission path quietly accepts two decision makers, a report quietly prints a volume. This bead
writes the eleven rows and builds one battery that proves, through the public verbs, that each default is in
force until an ADR says otherwise, and that the battery follows the ADR afterwards.

## Scope

In: the eleven register rows with carriers; the row linkage test; the battery, one probe group per question;
the decision of OPEN-AUGUR-11, which blocks nothing and has no other home; the tombstone of OPEN-AUGUR-6. Out:
taking the other decisions (their beads are named in the table); the register's schema (N41-03).

Where the chapter and the program register differ, the register governs: the chapter names no owner for
questions 2, 5, 8, 9 and 11; the register names the Augur lead, and the Lemma lead for 8.

**2. Linkage test** (`cargo test -p frob-conformance --test g0 -- registry::augur_open_questions`): eleven
identifiers present once; every `open` row has a non-empty `default`, `default_removes`, `owner` and
`deadline`; `decided` requires an ADR file that exists; OPEN-AUGUR-6 is `tombstoned` with ADR-WS-02 and its
identifier is not reused; a row whose deadline gate has a recorded measurement, or whose milestone's exit
review has started, may not be `open` (it must be `decided` or `default-at-deadline`); each carrier exists in
the bead graph.

**3. OPEN-AUGUR-11, decided here unless the Augur lead objects (DESIGN).** No standard measure. Reason: a
volume depends on the chart, and the chart is the caller's modelling choice. In the stance family the free
parameter is v = 1/b on [2, 6] (b the half-width in metres, so b ∈ [1/6, 1/2]). If the excluded part
(14/3, 6] were instead unresolved, it would be 1/3 of the domain by length in v ((4/3)/4) and 1/7 by length in
b ((3/14 − 1/6)/(1/2 − 1/6) = (1/21)/(1/3)). Neither is "the" unresolved fraction. So `resolution` names a
measure and a chart, the answer reports unresolved measure only in that measure, and a probability mass is
reported only under a weighting of topology classes and continuous parameters that the caller supplied.

register row and its ADR, so a decision changes one expectation table and no code).

## Acceptance criteria

- [ ] Eleven rows are in the register with the texts above; the linkage test passes.
- [ ] The battery runs all eleven groups at M1 and each expectation is met; it is re-run at every milestone
      exit that has an Augur question due (M1, M3, M4, M6, M8), where an `open` row past its deadline fails it.
- [ ] After any decision, the affected group follows the ADR with no change to the script (shown by a test
      copy of the register in which question 7 is switched to its option B: the expectations become 4, 4, 4).
- [ ] Each group has a negative control: a synthetic envelope that violates the default is flagged (below).
- [ ] The status table generated for the README lists the eleven questions with owner, default and status.

## Test plan

### Unit tests
`crates/frob-conformance/tests/open_questions.rs`, on envelopes labelled `synthetic`:
- `row_linkage` (as specified); `tombstone_not_reusable` (a second row named OPEN-AUGUR-6 fails the load).
- `open_past_deadline_fails`: GATE-AUGUR-01 recorded while row 1 is `open` → failure naming the row.
- `default_removes_never_adds`: a row whose `default_removes` is empty, or whose default text grants a
  capability ("assume reviewed"), fails.
- `violation_detected_k` for k = 1…11: a two-maker query answered with an inner cell (9); exit 0 with
  `resolution` unmet (7); a bundle without the unreviewed statement citing Proof (8); an inner `Certified`
  cell resting on a `trace-witness` (5); an excluded cell with no proof (2); a seven-parameter region request
  admitted (3); an inline `(G …)` formula admitted (1); an SMT crate in the closure (4); the mission crate
  linking the auditor (6); a slice enabled with its pilot `not-run` (10); a `measure` printed that the query
  did not name (11). Each must be flagged by the group's assertion.
- `measure_depends_on_chart`: the interval (14/3, 6] of v is 1/3 of [2, 6]; its image [1/6, 3/14) of b is 1/7
  of [1/6, 1/2].

### End-to-end script and logging
`scripts/e2e/augur_open_defaults.sh` sources the helper of `STD-E2E` and writes newline-delimited JSON under
`target/e2e-logs/augur_open_defaults/`: per probe a `cmd` line (exact command, exit code, wall time, the
envelope's evidence block), an `assert` line (question, option in force, expected, observed, first differing
value on failure), `refusal` lines with code, pointer and first repair; a final `summary` with assertions
passed and failed per question and the register's status counts. Idempotent; no seeds (all probes are exact).

### Known answers and negative controls
KA-624 (the stance family: b ≥ 3/14 m; witness (160, 130, 110, 0) N) underlies groups 2, 7 and 8; KA-642
(handoff bit) underlies group 9's reason. The eleven synthetic violations are the negative controls and are
registered in the negative-control registry. Metamorphic relation: switching a row's option in a test copy
of the register changes exactly that group's expectations and no other.

## Considerations

- If every Augur question stayed at its default the chapter would still exit M1: answers exact on the linear
  and finite-game fragments, single decision maker, no engine, unreviewed bundles outside the fixtures, no
  Moonshot. That is the test a default must pass before it is written.
- The battery proves the default is enforced at the surface; it cannot prove that nothing bypasses the
  surface. The invariant and proof-obligation suites cover the inside.
- Group 10 needs only the registry and the capability listing at M1; the Moonshot beads re-run it before
  spending compute.
- The plan says unreviewed bundles say so "in their flags", while the authorization object must hold exactly
  three flags; the marker therefore lives beside it, not inside it, and group 8 checks both facts.
