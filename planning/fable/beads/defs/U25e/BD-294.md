## Background

Every definitive cell of a mission answer rests on a certificate that the offline auditor `frob-verify` (crate
`frob-cert`) accepts. The auditor is the only defence the format offers against a proposer that is wrong, and it is
worth nothing if it shares the proposer's mistakes. ADR-AUGUR-05: the checker shares no code with the proposer; the
checking rules depend on the standard library only and carry their own rational and interval arithmetic. Reason: a
Monte Carlo run and a solver that share one mistranslated model agree on the wrong answer. RISK-36 names the
failure (the proposer and the checker share a defect; early warning: a source file shared between `frob-cert` and a
proposer, or a checker dependency beyond the standard library).

GATE-AUGUR-06 (claim: Proof; due at M1 and repeated at M3; thresholds TARGET): checker independence: the dependency
closure is `std`; zero shared source files with proposers; a seeded-fault campaign of at least 200 mutated
witnesses per proof kind yields zero false accepts. The M1 run (the mission mutation corpus and campaign of the
first slice) covers the kinds of the first slice. By M3 more kinds are in use: monotone transports with their
falsification harness, clearance complexes, control programs with infeasibility certificates, alias and jaw
fixtures, the monomial screen, empirical coverage statements. This bead repeats the gate over every proof kind
enabled at M3. Tier Solid [S]. Rejected alternative: trusting the M1 result for the new kinds (independence is a
property of each checking rule, and each new rule is new code).

## Scope

In: the M3 run of the three independence checks; mutation operators and at least 200 seeded mutants for every
kind enabled at M3; the equivalent-mutant filter; the gate record. Out: the M1 campaign and corpus (BD-136); the
checkers; the per-kind specimens (owned by the checker and producer beads); the M5 corpora (the conformance bead
for M5).

## Technical approach

Kinds in scope at M3 (read from the registry at run time: every kind whose status is `enabled`; the expected
list): `poly-identity`, `rational-ldlt` (M0); `lp-primal` with its law objects, `lp-farkas`, `finite-game`,
`alias-pair`, `partition`, `interval-box`, `trace-witness` (M1); `monotone-transport`, `symmetry-transport`,
`composition`, `monomial-product`, `complex-connectivity`, `conic-farkas`, `sample-coverage` (enabled by M3).
A kind listed and not enabled is skipped with a logged reason; an enabled kind with fewer than 200 mutants fails
the gate.

1. Dependency closure. `cargo tree -p frob-cert --edges normal,build` must list only `frob-cert`; the crate's
   manifest has an empty dependency table; the binary is built alone from a copy of the crate with its own
   toolchain file. PO-AUGUR-07: the checker's dependency closure is `std` and shares no source file with any
   proposer (a closure check in the build, and a file-set comparison).
2. Shared source files. Compute the set of source paths compiled into `frob-cert` and into each proposer or
   writer crate (`frob-mission`, `frob-synth`, `frob-lemma`, `frob-analyze`, `frob-control`, `frob-scene`); the
   intersection must be empty. Also compare content digests, so that a copied file is found: any file of
   `frob-cert` whose normalized content (comments and whitespace stripped) matches a file of a proposer above a
   similarity threshold of 90% of lines is reported and fails the check unless listed in an allowlist with a
   written reason (the allowlist starts empty).
3. Arithmetic. PO-AUGUR-02: the checker's big-integer and rational arithmetic is exact, verified by a
   differential test against an independent implementation on 10⁶ random operations and on all fixture
   certificates. PO-AUGUR-03: its interval arithmetic is outward-rounded using `std` only (every operation
   widened by one unit in the last place in each direction; property test that the enclosure contains the
   exact rational result). Both are re-run at M3 because new kinds use more of the arithmetic.
4. Seeded-fault campaign. For each kind, at least 200 mutated witnesses generated by seeded operators from the
   kind's accepted specimens (seed list pinned; operators per kind below). Every mutant is run through
   `frob-verify` in an empty environment. A false accept is an accepted mutant that is invalid.
5. Equivalent mutants. A mutation can leave a certificate valid (another feasible point, a different valid
   multiplier). Each mutant is therefore classified by an independent reference in `frob-conformance` (a second
   implementation of each checking rule, sharing no file with `frob-cert` or with the proposers). Mutants the
   reference finds still valid are logged as equivalent, excluded from the count and replaced until 200
   invalid mutants per kind exist. A disagreement between the reference and the auditor on an accepted
   specimen is itself a failure.
6. Operators (each kind uses those that apply): a coefficient or witness entry changed by one unit in the last
   digit; a sign flipped; two ordered entries swapped (port order, foot order); a side condition removed; a
   boundary opened or closed; the quantifier prefix, horizon, policy class or cell changed with hashes
   recomputed to stay consistent; a rational made non-reduced or given a negative denominator; a multiplier
   changed by ±1 (`monomial-product`, `lp-farkas`, `conic-farkas`); a law relabelled (`lp-primal`); a path edge
   removed or a component label merged (`complex-connectivity`); a count changed (`sample-coverage`); a
   monotone direction reversed or a stratum boundary crossed (`monotone-transport`); a permutation that moves
   a sensor (`symmetry-transport`); a resource spent twice (`composition`).
7. Record. Per kind: specimens accepted, mutants run, equivalent mutants set aside, false accepts (threshold 0).
   The gate row for GATE-AUGUR-06 gets its M3 record beside the M1 record.

One false certificate found here has the standing consequences, none discretionary: the proof kind and checker
version involved are disabled in the registry until the cause is found; every stored bundle that used them is
marked withdrawn and dependent answers are re-derived or downgraded to `Tested`; the counterexample becomes a
permanent fixture of the mutation corpus (KILL-AUGUR-FALSECERT, standing from M1).

## Acceptance criteria

- [ ] GATE-AUGUR-06 at M3 (TARGET) recorded: dependency closure of `frob-cert` is `std`; zero shared source files with proposers; at least 200 mutated witnesses per proof kind in use at M3, zero false accepts.
- [ ] Every kind enabled in the registry at the M3 exit appears in the record with its counts; none is skipped silently.
- [ ] The differential arithmetic test passes on 10⁶ random operations and all fixture certificates; the outward-rounding property test passes.
- [ ] Equivalent mutants are identified by the independent reference, logged and excluded; the reference and the auditor agree on every accepted specimen.
- [ ] Negative controls are caught: an auditor build with one rule disabled yields false accepts and fails the campaign; a planted shared source file fails the file-set comparison; a planted dependency fails the closure check.
- [ ] The campaign runs in an empty environment on a host with no GPU; verdicts are identical on both hosts.

## Test plan

### Unit tests

`crates/frob-conformance/tests/independence.rs`: `closure_is_std` (parses `cargo tree` output; one line);
`file_sets_disjoint`; `copied_file_detected` (a fixture file copied into a scratch proposer crate is found by the
digest comparison); `mutant_generator_is_seeded` (two runs give identical mutant bytes);
`equivalent_mutant_filtered` (for `lp-primal` at the stance vertex (60, 30) with half-width 1/4 m, where the ++
force may be anything in [150, 160] N, replacing the witness (160, 130, 100, 10) N by (155, 135, 105, 5) N is still
valid and is set aside, not counted); `operators_cover_every_kind` (each enabled kind has at least three applicable operators);
`reference_agrees_on_specimens`.

### End-to-end script and logging

`scripts/e2e/augur_checker_independence_m3.sh`: steps 1 to 7 above, plain shell over `cargo`, the standalone
`frob-verify` under `env -i`, and the in-tree `frob prove verify --json` for agreement. Logs through the STD-E2E
helper to `target/e2e-logs/augur_checker_independence_m3/<utc-timestamp>.ndjson` with a transcript: `ts`, `script`,
`bead` (`BD-294`), `step`, `event`, exact command, exit code, wall time; `metric` lines for the closure line count
(threshold 1), shared files (0), arithmetic mismatches (0), and per kind the mutants run (threshold at least 200)
and false accepts (0); `assert` lines for every false accept with the bundle digest, kind, operator, seed and the
path of the mutant. The `summary` lists the kinds and names GATE-AUGUR-06 (M3).

### Known answers and negative controls

Registry rows exercised: the mutations of the stance specimen (a swapped foot ordering with unchanged forces; a
packet that passes (60, 30) directly as the torque; an unreported positive force floor; a `passive` authority tag
on a certificate that assumes independent forces; a changed quantifier with consistent hashes; a missing side
condition; an unknown proof kind; a non-reduced or negative-denominator rational; a cell whose closed end was
certified only as open), the monomial leg certificate (λ = (1, 1), product 8829/8000; λ = (1, 2) rejected), the
law-object mutations (four vertex commands labelled `affine`; no law object). Negative controls: the three listed
in the acceptance criteria. Determinism lanes: twice on one machine; debug and release; the Mac and the Linux
host; identical verdicts and first failing rules (class D0).

## Considerations

- Independence of code is not independence of thought: one author can make the same mistake twice. The plan's
  mitigations beyond this gate are the primitive equations travelling in every bundle for review, an invalid
  fixture per lowering, and a second checker if one is not enough (an open question of the proof chapter).
- The campaign's run time grows with kinds (about 3,200 mutants at M3); each check is milliseconds, and the
  builds dominate.
- The gate is repeated, not replaced: the M1 record stays, and later milestones re-run the script for kinds
  enabled later.
- RISK-35 (a certificate issued for a statement other than the one asked) is addressed by the prefix and cell
  mutation operators; RISK-36 by checks 1 and 2.
