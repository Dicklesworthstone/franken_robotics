## Background

The equations of motion of a rigid-body tree, M(q)·v̇ + h(q, v) = B(q)·u + J(q)ᵀ·f, are linear in the inertial
parameters of the bodies once the kinematics (joint axes, link lengths) and the motion (q, q̇, q̈) are fixed. Each
rigid body has ten inertial parameters: mass m, first moments h = m·c (three), and the six independent entries of
the second moment about the body frame's origin. They are equivalent to the 4×4 pseudo-inertia matrix
P = [[Σ, h], [hᵀ, m]], and they are physically consistent exactly when P is positive definite. Stacking all bodies'
parameters into π, inverse dynamics can be written

  ID(q, q̇, q̈; π) = Y(q, q̇, q̈)·π,

where the regressor Y has one row per generalized coordinate (the six floating-base rows included) and ten columns
per body. The placement-and-sizing lane (N25e-20) needs Y at every knot of a prescribed motion, because with Y in
hand the unknown masses enter its cone program linearly. The calibration lane of the reality chapter needs the same
object for identification. DESIGN: Y is emitted by the kernel intermediate representation `frob-kir` from the
derived inverse-dynamics kernel, not written by hand, so that the regressor and the dynamics cannot drift apart.
Tier: the emission is Solid mathematics; it is filed under the Frontier lane it serves.

Rejected alternatives: a hand-written regressor recursion (a second implementation of the dynamics that can
disagree with the first); finite differences in π (exact here in principle, because the map is linear, but 10·n_b
kernel evaluations per knot and no symbolic sharing; kept as the test oracle).

## Scope

In: the `frob-kir` pass that extracts Y from the derived inverse-dynamics program; the CPU evaluation path used by
`frob-synth`; the parameter ordering and frames; the identity test on every reference robot; the verb
`analyze.regressor-identity` that exposes that test (its registry row is NJLx-51's, which names this bead as the
implementer). Out: the cone program
(N25e-20); identification and excitation design (the Ground beads); device kernels for Y (not needed: the lane runs
on the CPU).

## Technical approach

1. Parameter convention (DESIGN, fixed in `CONTRACT.md` of `frob-kir`): per body b, in its body frame,
   π_b = (m, h_x, h_y, h_z, Σ_xx, Σ_xy, Σ_xz, Σ_yy, Σ_yz, Σ_zz) with h = m·c the first moment and Σ the second
   moment of mass about the frame origin (the entries of the pseudo-inertia P). The rotational inertia about
   the origin is I = tr(Σ)·1 − Σ. Bodies are ordered as in the model's packed lowering. A converter to and from
   (m, c, I_C) is provided and round-trips exactly in rationals.
2. Extraction pass. The derived inverse-dynamics kernel is a straight-line program whose inputs include the
   spatial inertias. The pass: (a) rewrites each spatial inertia as its linear expression in π_b; (b) propagates
   linear forms in π through the program (every operation of the recursion is linear in the inertia inputs:
   sums, products with kinematic quantities that do not depend on π); (c) rejects, at compile time, any
   operation that would multiply two π-dependent values (that would mean the program is not linear in π, a
   derivation defect); (d) emits the coefficient program for Y with common-subexpression elimination shared
   with the kinematics.
3. Output: a program `K-id-regressor` on the CPU reference path returning Y as a dense (n_v) × (10·n_b) matrix,
   plus the selection matrix S of actuated coordinates and, for a given contact set, the Jacobians J_c from the
   existing kernels. Dimension-checked by the kernel IR's unit checker (rows are generalized forces; columns
   carry the unit of their parameter).
4. Identity test: for random states (q, q̇, q̈) inside joint limits and the model's own π, Y·π equals the derived
   inverse dynamics. Threshold (TARGET): within 10⁻¹² relative on 10⁴ random states per reference robot, in
   double precision on the CPU.
5. Site vectors. For a unit point mass at a site s with position x_s in body b's frame, the parameter vector is
   φ_s = (1, x_s, x_s·x_sᵀ entries): φ_s = (1, x, y, z, x², x·y, x·z, y², y·z, z²). `frob-synth` builds
   π = π_fixed + Σ_s m_s·φ_s from these.
6. Evidence: Y is a derived kernel output; its certificate is the polynomial identity "Y·π − ID ≡ 0" in the
   symbolic variables, issued by the certificate producer for the instance where budgets allow, and the
   numerical identity test otherwise (class `Tested`).

7. Verb (owner `frob-synth`; MCP tool `analyze_regressor_identity`; capability `analyze:read`; output schema
   `frob.analyze.regressor-identity.out/1`): `frob analyze regressor-identity --robot <reference robot>
   [--states <n>] [--seed <u64>] --json`, `--states` an `int53` count with default 10,000. It samples states as in
   step 4 from the seed and returns, per robot, the largest relative error of Y·π against inverse dynamics, the
   state that attains it, the threshold 10⁻¹² (TARGET), evidence `Known answer`, class `Tested`. Exit 0 when the
   error is within the threshold, 2 otherwise. It has no refusal of its own; an unknown robot is the generic
   argument refusal of the verb layer.

Cost: one coefficient program per shape class, derived once and cached with the kernel cache; evaluation per knot
is comparable to ten inverse-dynamics evaluations per body column block before sharing.

## Acceptance criteria

- [ ] `K-id-regressor` exists for every reference robot's shape class, derived by the pass from the same source as the inverse-dynamics kernel.
- [ ] Regressor identity (clause of GATE-AUGUR-29, TARGET): Y·π equals the derived inverse dynamics within 10⁻¹² relative on 10⁴ random states per reference robot; the measured maximum is recorded.
- [ ] The pass refuses a program that is not linear in the inertia inputs, naming the offending operation.
- [ ] The parameter converter round-trips (m, c, I_C) ↔ π exactly in rationals, and rejects parameters whose pseudo-inertia is not positive definite when asked to validate.
- [ ] Site vectors reproduce a point mass: Y·φ_s·m equals the inverse dynamics of the model with a point mass m added at x_s.
- [ ] `CONTRACT.md` documents ordering, frames, units and the first-moment convention.
- [ ] `frob analyze regressor-identity` matches its registry row (NJLx-51): inputs, output schema, exit 0 within the threshold and 2 above it, identical output for one seed twice.

## Test plan

### Unit tests

`crates/frob-kir/tests/regressor.rs`: `pendulum_closed_form` (a single revolute link about z with gravity along −y,
angle θ measured from the x axis: τ = Σ_about-axis·θ̈ + g·(h_x·cos θ − h_y·sin θ), so the row of Y has entries θ̈ on the
planar second-moment columns Σ_xx + Σ_yy and g·cos θ, −g·sin θ on h_x, h_y); `two_link_matches_id` (the planar 2R
chain with link lengths 0.4 m and 0.3 m: Y·π against inverse dynamics at 1,000 random states);
`nonlinear_in_pi_rejected` (a planted program that squares the mass); `site_vector_point_mass`;
`floating_base_rows_present` (the six base rows of Y·π equal the base wrench from inverse dynamics);
`converter_roundtrip_rational`; `units_checked` (a column given the wrong unit fails the dimension check).
`crates/frob-synth/tests/regressor_identity.rs`: the 10⁴-state identity per reference robot, with the comparison
against the numeric regressor of the pilot (unit-vector evaluation) as a second oracle; `verb_exit_codes` (the
verb on a reference robot exits 0; with the planted sign-flipped column it exits 2 and reports the attaining
state); `verb_seed_reproducible`.

### End-to-end script and logging

Covered by `scripts/e2e/augur_placement_lane.sh` (N25e-21), whose first stage runs
`frob analyze regressor-identity --robot <id> --states 10000 --seed 7 --json` per reference robot and logs the
maximum relative error against the 10⁻¹² threshold with the STD-E2E fields.

### Known answers and negative controls

The pendulum row above; the 2R chain. Negative controls: a regressor with one first-moment column sign-flipped
(the identity test must fail by orders of magnitude); a regressor built for the wrong link length (must fail: Y
depends on link lengths nonlinearly, which is why they are not variables of the lane). Metamorphic relations:
scaling π by a constant scales Y·π by the same constant; the sum of two parameter sets gives the sum of the
torques. Determinism lanes: twice on one machine; debug and release; the Mac and the Linux host within the
floating-point class of the CPU reference path.

## Considerations

- The 10⁻¹² threshold is a double-precision statement; no device path is offered because the lane is on the CPU.
- Expression swell on large robots is a known risk of derivation; the pass works per kernel body and per limb.
- Closed kinematic loops need constraint forces in the knot equation; version 1 covers trees with contacts.
- The same Y serves identification; sharing it means a defect would be shared too, so the identity test and the
  numeric oracle stay as independent checks.
