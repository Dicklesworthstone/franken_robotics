## Background

A sensor budget must state the joint law of its read errors, not their pairwise tables. Seven reads of a hidden
binary class, each right with probability 3/4, give a best success of 3807/4096 when the errors are jointly
independent, 3/4 when one fault bit is shared by all reads, and 55/64 under a constructed law that is pairwise
independent and not jointly independent (the number K of wrong reads is 1, 2, 3 or 4 with probabilities
(43, 3, 9, 9)/64, placed uniformly among the seven slots: each read is wrong with probability 1/4 and each pair is
wrong together with probability 1/16, exactly as for independent reads). A requirement of 0.9 is met by the first
law and missed by the third, with the same accuracy and the same pair tables.

GATE-AUGUR-33 (claim: Known answer; thresholds TARGET) has two parts with two milestones. The error-law rows, due
at M3: enumeration of the 128 histories returns 55/64 for the pairwise law, 3807/4096 for the independent law and
3/4 for the shared fault, exactly; a redundancy claim on a card marked `pairwise` is refused. The label rows, due at
M4, are measured by N25e-37. This bead is the script for the first part. Rejected alternative: one script for both
parts at M4 (the M3 exit needs its part recorded at M3).

## Scope

In: `scripts/e2e/augur_error_law.sh`; the mission that asks for 0.9; `truth.json`; the registered control; the
gate record for the error-law rows. Out: the mechanism, the four sensor cards and the design (N25e-34); the label
rows (N25e-37).

## Technical approach

Fixtures: N25e-34's cards and design in `fixtures/augur/error-dependence/` (`E` below), four cards for one binary
probe with single-read accuracy 3/4: `independent.fcard` (`error_dependence: joint-independent`), `shared.fcard`
(`shared-fault`), `pairwise-law.fcard` (`declared-law` referencing `pairwise.errorlaw.json`, the K-law above),
`pairwise-only.fcard` (`pairwise`, no joint law), and the design `probe-bot.fbot` carrying the one binary probe,
named `probe`, whose card `--card` binds (both verbs take a design as well as the mission). This bead's
(`fixtures/augur/error-law/`, `L` below): a mission `payload-class.fmission` (two sealed payload classes requiring
disjoint final forces, seven reads before commitment, required success 9/10) and `truth.json` with the three exact
values.

Steps (plain shell, idempotent; every run-verb call carries its own key with the run's identifier, so no step and
no rerun is answered from a stored receipt):
1. `start`: commit, host.
2. For each of the first three cards: `frob sense alias $E/probe-bot.fbot --mission $L/payload-class.fmission
   --card probe=$E/<card> --reads 7 --key el-<run>-<card> --json` (the `<sensor>=<card>` form VERBS-sense
   registers; `sense.alias` is a `run` verb: without `--key` it is `FROB-REF-805`). Assert `redundancy.guaranteed` equals "3807/4096", "3/4" and "55/64" respectively;
   `redundancy.decoder` is `enumeration` with `histories: 128` for the independent and declared laws;
   `evidence.class` `Certified`, determinism `exact`.
3. The script's own exact helper recomputes the three values from first principles (the product law; the shared
   fault; the K-law with uniform placement: Σ over histories of the larger of the two class likelihoods, halved)
   and compares with the verb's output and with `truth.json`.
4. Marginal check of the declared law: from the result of step 2 for `pairwise-law.fcard`, read
   `redundancy.law_marginals`; assert the per-read error probability is "1/4" for each of the seven reads and
   the joint error probability is "1/16" for each of the 21 pairs.
5. Decision: `frob mission refute $L/payload-class.fmission --design $E/probe-bot.fbot --card
   probe=$E/<card> --key el-<run>-ref-<card> --json` for the three cards (VERBS-mission's one card grammar on
   `mission.refute`; the bare `--card <card>` is `FROB-REF-802`, pointer `/card`). Assert the
   requirement 9/10 is met under `independent` (3807/4096 ≥ 9/10) and missed under `shared` and under the
   pairwise law (55/64 < 9/10), each with the binding assumption named (the error law).
6. Refusal: `frob sense alias $E/probe-bot.fbot --mission $L/payload-class.fmission --card
   probe=$E/pairwise-only.fcard --reads 7 --claim-redundancy --key el-<run>-claim --json` through
   `e2e_expect_refusal` with the code, `detail: joint-error-law-missing`, pointer and the three ranked repairs read
   from row 3 of N25e-45's `fixtures/augur/late-refusals/expected.toml` (the interim `FROB-REF-846` while the
   ledger holds the row, exit 3), never typed into the script; not merely exit 3 (a missing key would also exit
   3, with 805). Assert the refusal "redundancy credited without a joint error law" and that the guaranteed value
   in the refusal's `observed` field is "3/4".
7. Negative control of the gate: A-17's redundancy computed from per-read accuracy and pair tables instead of the
   joint law, a registered mutation control in `crates/frob-conformance/registry/controls.toml` (a
   `cfg(feature = "nc-<nnnn>")` branch of `frob-analyze`, built with `--features
   gauntlet-mutations,frob-analyze/nc-<nnnn>`, numbered at registration by N38b-04), rerun on step 2 for
   `pairwise-law.fcard` with the key `el-<run>-mut-pairwise`; the step must fail (it returns 3807/4096, not 55/64).
8. `summary` with the receipt hash. The script never records a value (STD-E2E's `self-recording` lint): the
   error-law rows of GATE-AUGUR-33 (M3) are recorded from that receipt by a session that did not implement
   N25e-34, with `cargo run -p frob-conformance --example record_gate -- --gate GATE-AUGUR-33 --receipt <hash>
   --part M3` (N38b-19), which refuses the record unless the control of step 7 is listed as caught in the same
   run.

Logging (STD-E2E): `target/e2e-logs/augur_error_law/<utc-timestamp>.ndjson` and a transcript. Every line: `ts`,
`script`, `bead` (`N25e-36`), `step`, `event`, exact command, exit code, wall time, the envelope's `evidence`
block. `metric` lines: card, law, guaranteed success as an exact string against its expected value, histories
enumerated; the `refusal` line with code, detail, pointer and repairs. On failure: the first card whose value
differs, with both values.

55/64) is N25-KA's late row `augur-late-13`, cited by the KA number N38a-40 issues to that slug (a tag in a test
name or derivation file fails `provisional-tag-past-due`). Determinism lanes: twice on one machine; debug and release; both hosts; class D0.
