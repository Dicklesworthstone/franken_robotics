## Background

An adversary with no constraint wins by building worlds no robot is meant to face: a doorway of zero width, a
floor of ice, a push of a thousand newton-seconds. Such a world says nothing about the design. ADR-NEMESIS-01
therefore fixes two things. First, the search runs inside a **legality set**: the worlds a robot of this kind is
meant to face. Second, legality is kept apart from probability: legality is a set, the task's nominal
randomization is a distribution on part of it. A rare but admissible world can be a useful counterexample with
negligible operational probability, so the search does not discard it, and every report states both facts
(the verdict here; the density in N26a-03). Rejected alternatives: an unconstrained adversary; using the nominal
prior as the admissibility filter (it would discard exactly the rare admissible worlds worth finding).

A world is a base scene, an edit list, a disturbance schedule and a parameter vector (N26a-02). This bead owns
the object that says which worlds are admissible, the check, and its refusals. It is Solid: a schema, a checker
and a registry. It serves North-Star use "find failures instead of waiting for them" and bet BET-22 (minimal
counterexample worlds), whose control is an inadmissible or unsolvable world that must be rejected.

## Scope

In: schema `frob.legality/1`; default profiles per archetype generated from the hazard registries and the cards;
the check on the final world (INV-NEMESIS-02); the legality verdict carried by every world; refusals
FROB-REF-360 and FROB-REF-361; the legality row of GATE-NEMESIS-01.
Out: the edit types and FROB-REF-362 (N26a-02); the density under the nominal randomization and the size order
(N26a-03); the oracle rows of GATE-NEMESIS-01 (BD-271); the planted fixtures (N26a-04); the end-to-end script
(N26a-05).

## Technical approach

1. **The profile (DESIGN).** A legality profile lists a bound for every editable quantity, each with a provenance
   class: `cited` with its source, `card` when it is the uncertainty of a card, or `assumed`.
   ```json
   { "schema": "frob.legality/1", "id": "kitchen-commercial/default", "archetype": "commercial-kitchen",
     "sources": { "hazards": "registries/hazards/commercial-kitchen.toml@b3:…", "cards": ["if:tile-wet@…"] },
     "bounds": [
       { "name": "closer_torque", "path": "/fixtures/door[*]/closer_torque", "min": "5 N·m", "max": "20 N·m",
         "provenance": { "class": "assumed" } },
       { "name": "film", "path": "/floor/patch[*]/film", "allowed": ["dry", "water", "grease"],
         "provenance": { "class": "assumed" } },
       { "name": "patch_mu", "path": "/floor/patch[*]/mu", "min": "0.08", "max": "0.9",
         "provenance": { "class": "card", "card": "if:tile-wet@…" } },
       { "name": "push_impulse", "path": "/disturbances/push[*]/impulse", "min": "0 N·s", "max": "15 N·s",
         "provenance": { "class": "assumed" } } ],
     "composite": [
       { "name": "galley_aisle_width", "expr": "min_passage_width(route[galley])", "min": "0.9 m",
         "provenance": { "class": "assumed" } },
       { "name": "scene_acceptance", "expr": "scene_accept()", "provenance": { "class": "assumed" } } ],
     "authorization": { "execution_authorized": false, "hardware_safety_signoff": false,
                        "sim_to_real_certified": false } }
   ```
   A bound is an interval in authored units, an allowed set, or a composite expression over the realized world.
   Profiles are canonical, content-addressed and named `<archetype>/<name>`; a search names one.
2. **Default profiles.** `legality::default_profile(archetype, candidate)` builds the profile from (a) each
   hazard-registry row's dimension range (a threshold 5 to 25 mm; an interior door 0.70 to 0.90 m clear; a
   hallway 0.85 to 1.20 m; a door-closer torque 10 to 40 N·m in an office, 5 to 20 N·m for a kitchen swing door;
   a water film 0.1 to 2 mm; and so on for all seven archetypes), with the row's provenance mapped
   `assumed` → `assumed`, `norm: <citation>` or `measured: <dataset>` → `cited`; (b) each randomized card
   parameter's uncertainty support, class `card`; (c) the task's link and clock models for latency, dropout and
   jitter bounds; (d) composite bounds for every route width the archetype's registry names. Dimensional norms
   for buildings are to come from cited sources; until a source is recorded every such bound is `assumed`.
3. **The check, on the final world (INV-NEMESIS-02).** `check_world(profile, world) -> LegalityVerdict`:
   1. Structural: every edit targets a path matched by some bound. A quantity with no bound is not editable
      (fail closed): FROB-REF-360 with `required: "a bound for this path"`.
   2. Realize the world (apply all edits to the base scene, merge disturbances, override parameters).
   3. Evaluate every per-quantity bound on the final value of each touched path (not on the edit's delta, and
      not edit by edit).
   4. Evaluate every composite bound on the realized world. This is what "checked on the final world" buys: two
      individually legal obstacles can narrow a passage below its minimum width.
   5. Return `{ inside: bool, touched: [{bound, provenance}], violations: [{bound, observed, required, unit}] }`.
   Every world Nemesis evaluates carries this verdict; a world with `inside: false` is never simulated.
4. **Refusals.**
   | Code | Meaning | Trigger | Ranked repairs | Exit |
   |---|---|---|---|---|
   | FROB-REF-360 | A world or edit lies outside the legality profile; the violated bound is named | Any violation in step 1, 3 or 4 | (1) move the value inside the named bound (the nearest legal value is attached); (2) drop the named edit; (3) use a profile that declares the wider bound, with its provenance | 3 |
   | FROB-REF-361 | The request demands `cited` bounds and the profile has an `assumed` bound on a touched quantity | `--require-cited` (or a report that claims realism) and any touched bound of class `assumed` | (1) rerun without the demand and accept the label; (2) record a source for the bound in the source register; (3) restrict the search to quantities with `cited` or `card` bounds | 3 |
   The refusal envelope carries `pointer` (edit index and path, or the composite's name), `observed`, `required`,
   `unit`, `retry: after-change`.
5. **What a counterexample says about its bounds.** Every counterexample lists the bounds it touches with their
   provenance (`"legality": {"inside": true, "touched": [{"bound": "closer_torque", "provenance":
   "assumed"}]}`), so a reader sees at once whether its realism rests on an assumed number.
6. **Surface.** No verb of its own. Every Nemesis verb that takes or produces a world (`nemesis.search`,
   `nemesis.oracle`, `nemesis.shrink`, `nemesis.hardset add`) calls `check_world` first; `nemesis.search` and
   `nemesis.oracle` take `--legality <profile>` and `--require-cited`. Determinism: exact (class D0); bound
   comparisons are done in exact rational arithmetic on authored values where both sides are rational.

## Acceptance criteria

- [ ] Seed done-condition, the legality row of GATE-NEMESIS-01 (TARGET): 100 of 100 planted illegal edits are
      refused with FROB-REF-360 and the violated bound named. The planted registry (N26a-04) is built on top of
      this checker, so the count is measured by the registry's test `illegal_refused` at the library level and
      by the script of N26a-05 from the user's side, which records the measured count in the gate register.
- [ ] The negative control is caught: with the planted bound widened to the whole physical domain, the same
      edit is admitted (so the refusal came from the bound).
- [ ] Two obstacles, each legal alone, that together narrow a 1.00 m hallway to 0.80 m against a 0.85 m minimum
      are refused with the composite bound named; either alone is admitted.
- [ ] An edit to a path the profile does not list is refused with FROB-REF-360 (not silently admitted).
- [ ] `--require-cited` with a touched `assumed` bound gives FROB-REF-361; with only `card` or `cited` bounds
      touched it passes.
- [ ] Default profiles exist for all seven interior archetypes and validate against the schema; every bound has
      a provenance class.
- [ ] Every world record and every counterexample carries `inside` and `touched` with provenance.
- [ ] The check is reachable through `frob --json` on `nemesis.oracle` and `nemesis.search`; schema
      `frob.legality/1` is registered in the format registry; `CONTRACT.md` lists INV-NEMESIS-02.

## Test plan

### Unit tests
`crates/frob-nemesis/tests/legality.rs`:
- `interval_bound`: closer torque 21 N·m against [5, 20] N·m: violation, `observed: 21`, `required: "≤ 20"`,
  unit N·m, nearest legal value 20.
- `allowed_set`: film `ice` against {dry, water, grease}: violation.
- `composite_on_final_world`: the two-obstacle hallway above (widths 1.00 m; obstacles of 0.10 m at one station
  on opposite walls; minimum 0.85 m): `inside: false`, bound `hallway_width`, observed 0.80 m.
- `per_edit_check_would_pass` (negative control as a test): a checker restricted to steps 1 to 3 admits the
  two-obstacle world; the test asserts the full checker does not.
- `unlisted_path_fail_closed`; `require_cited_assumed` (361); `require_cited_card_ok`.
- `touched_lists_provenance`: the two-edit kitchen world (grease film; closer torque 14 → 19 N·m) reports
  `closer_torque: assumed` and `film: assumed`.
- `default_profile_from_registry` (per archetype): the home threshold bound is [5, 25] mm, `assumed`.
- `inv_nemesis_02` (property, 10,000 random worlds from the vocabulary): `inside` holds exactly when no
  per-quantity or composite bound is violated on the realized world; the evaluator of a search never receives a
  world with `inside: false`.
- `exact_boundary`: a value equal to the bound is inside; one authored unit beyond is outside.

### End-to-end script and logging
`scripts/e2e/nemesis_legality.sh` (N26a-05): offers the 100 planted illegal worlds and their legal twins through
`frob nemesis oracle … --legality …`; logs per world the code, pointer, bound, observed, required, unit and
provenance, and the count against the threshold 100 of 100.

### Known answers and negative controls
KA-659: a planted illegal edit is refused with FROB-REF-360 and the bound named; 100 of 100 (GATE-NEMESIS-01);
tier G1 on the host; control: a profile with the bound removed admits it. INV-NEMESIS-02 as the property test
above. Metamorphic: widening any bound never turns an admitted world into a refused one. Determinism: verdicts
identical twice on one machine, in debug and release, and across platforms (exact).

## Considerations

- OPEN-NEMESIS-1 (sources for the legality bounds of interiors; owner: project lead, together with the question
  of which published building norms supply the scene dimensions). It blocks claims that a counterexample is
  realistic, not its validity. Fail-closed default: bounds are `assumed` and every counterexample says so;
  FROB-REF-361 refuses a demand for cited bounds.
- Reading of the plan's negative control: "a profile with the bound removed admits it" is implemented as the
  bound widened to the physical domain, because a quantity with no bound at all is not editable here.
- A profile that is too tight hides real failures; one that is too loose yields unrealistic ones. Both are
  visible: the profile identity is in every result, and touched bounds are listed with provenance.
- KILL-NEMESIS and KILL-MCW leave this bead untouched: the legality profile survives every fallback.
- Scene edits on a private scene: bound names are logged, authored values of private paths are not.
