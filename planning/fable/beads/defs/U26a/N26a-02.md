## Background

The adversarial search needs a space to search and a vocabulary to describe what it found. DESIGN: a **world** is
four things: a base scene, an edit list, a disturbance schedule and a parameter vector. The base scene is a seeded
derivation in a scene grammar (Habitat's interior and terrain generators), so it has a content identity
(`SceneId`). An **edit** is one atomic, typed change in authored units. Every edit declares which causal paths it
changes.

The declaration is not decoration. Moving a light can change the depth-dropout distribution of a camera without
changing friction; wetness may change both contact and optics. A later subsystem (the counterfactual debugger)
treats each edit of a counterexample as an intervention on one mechanism, and a failing world with its
one-edit-removed neighbours as an interventional contrast. An edit that cannot say which path it changes would
make that reading wrong, so it is not admitted (refusal FROB-REF-362).

The vocabulary of scene edits is not invented here. The hazard registries (`registries/hazards/<archetype>.toml`,
one per interior archetype: each row a hazard with a dimension range, the mechanism that represents it and the
failure it provokes) name the quantities of a place that matter to robots, and Habitat's typed scene edits are the
operations. Nemesis mutates scenes only through those. This is Solid work: bookkeeping over mechanisms that exist
elsewhere.

## Scope

In: the `World` type and its identity; the seven edit classes and the causal-path tags; the declaration check;
applying a world to obtain what the simulator runs; canonical ordering and serialization of edits; the mapping
from hazard-registry rows to editable quantities.
Out: bounds on those quantities and the legality verdict (BD-270); the nominal density and the size order
(N26a-03); the counterexample file (N26a-19); normal germs for card parameters (N26a-24).

## Technical approach

1. **Types (DESIGN sketch).**
   ```rust
   pub struct World { base: BaseWorld, edits: Vec<WorldEdit>, disturbances: Vec<Disturbance>, params: ParamVector }
   pub struct BaseWorld { scene: SceneId, addr: WorldAddr }        // WorldAddr = (run_seed, world, episode)
   pub struct WorldEdit { op: EditOp, path: FieldPath, from: Value, to: Value,   // values in authored units
                          class: EditClass, changes: BTreeSet<CausalPath> }
   pub enum EditOp { Set, Add, Remove }
   pub enum EditClass { Geometry, Material, Optics, Fixture, ClockLink, Disturbance, Parameter }
   pub enum CausalPath { Geometry, Material, Optics, Fixture, Timing, Disturbance, Parameter, Payload }
   pub struct Disturbance { tick: Tick, kind: DisturbanceKind /* Push { impulse, direction, body } | PayloadShift {..} */ }
   pub struct ParamVector { entries: BTreeMap<ParamPath, Value> }  // each inside a card's uncertainty
   ```
2. **The seven edit classes.**

   | Edit class | Examples | Declares that it changes | Tag |
   |---|---|---|---|
   | Geometry | A sill height, an edge radius, a door width, the place of an obstacle, a stair riser | Collision geometry and clearance | `geometry` |
   | Material | Friction of a floor patch, a compliant mat, the presence of a film | Contact; optics as well if the material is wet or glossy | `material` (+ `optics`) |
   | Optics | The position of a light, a glass panel, a reflectance | Sensing only | `optics` |
   | Fixture | A door-closer torque, a conveyor speed, a cart left in an aisle | Dynamics of fixtures | `fixture` |
   | Clock and link | A sensor latency, a dropout burst, packet jitter | Timing only | `timing` |
   | Disturbance | A push of stated impulse at a stated time and direction, a payload shift | Exogenous forces | `disturbance` (a payload property: `payload`) |
   | Parameter | A value inside a card's uncertainty: actuator gain, friction coefficient, mass, sensor bias | Model parameters | `parameter` |

   On the wire an edit is `{"op": "set", "path": "/floor/patch[galley-2]/film", "from": "dry", "to": "grease",
   "changes": ["material"]}`; `{"op": "set", "path": "/fixtures/door[pass]/closer_torque", "from": "14 N·m",
   "to": "19 N·m", "changes": ["fixture"]}`; `{"op": "set", "path": "/payloads/tray/fill", "from": "0.50",
   "to": "0.80", "changes": ["payload"]}`. The retrofit catalog's tags `clocks` and `actors` map to `timing` and
   `fixture`.
3. **The declaration check (FROB-REF-362).** For each edit, in order:
   a. `changes` is non-empty and every tag is known; otherwise refuse.
   b. The declared set contains the class's default tag.
   c. Completeness, checked by computation: compile the scene with and without the edit and compare the per-aspect
      digests. Any aspect whose digest changed and whose tag is not declared is an undeclared path: refuse, naming
      the aspect. (A film declared `material` only whose optical class changes the specular return is caught
      here; it must declare `["material", "optics"]`.)
   d. Atomicity: one edit names one path and one value. A request that bundles several is split by the caller.
   Refusal FROB-REF-362: "an edit does not declare the causal paths it changes". Envelope: `pointer` = the edit's
   index and path, `observed` = declared tags, `required` = tags found by the digests, `retry` = `after-change`.
   Ranked repairs: (1) add the listed tags; (2) split the edit into one edit per mechanism; (3) choose a different
   quantity. Exit code 3.
4. **Applying a world.** `World::realize(&self) -> Realized { scene: SceneId, schedule, params }`: scene edits are
   applied through Habitat's typed scene edits, which never mutate a pack and return a new `SceneId`; disturbance
   edits are merged into the declared disturbance schedule (a declared future disturbance, distinct from the
   per-step random disturbance streams, which stay keyed by address); parameter edits override the card draw for
   that address. Realization is a pure function of the world.
5. **Identity and canonical form.** Edits are a set relative to the base: canonical order is by `path` then
   `op`; two edits on one path are merged or refused as a conflict. `WorldId` (`w:…`) is the hash of the
   canonical bytes of (base, edits, disturbances, params). The same world reached by two edit orders has one
   identity.
6. **Dependencies between edits.** An edit whose path lies inside an object that another edit added depends on
   that edit. `World::is_ideal(subset)` says whether a subset of the edit list is closed under dependencies; the
   shrinker tests only such subsets.
7. **The edit vocabulary from the hazard registries.** `vocabulary(archetype) -> Vec<EditableQuantity>` reads the
   archetype's hazard registry and yields, per row, the paths that the row's mechanism exposes (a threshold's
   height, a door's clear width and closer torque, a film's presence and thickness, a rug's thickness and edge
   curl, a cord's diameter, a stair riser and tread, an aisle width, a conveyor speed, a light level, an optical
   class) with the row's dimension range, units and provenance. Card parameters and clock and link quantities come
   from the candidate's cards and the task's link models. Nothing outside this vocabulary is proposed by a search.

## Acceptance criteria

- [ ] Each of the seven edit classes has a fixture edit that applies to a generated kitchen scene and yields a new
      `SceneId` (scene classes) or a changed schedule or parameter row (the other classes).
- [ ] An edit with empty `changes` and an edit whose computed aspect change exceeds its declaration are each
      refused with FROB-REF-362, exit 3, the pointer naming the edit and the missing tag.
- [ ] A wet-film edit declared `["material", "optics"]` is admitted; the same edit declared `["material"]` is
      refused when the film's optical class differs from the dry patch.
- [ ] `WorldId` is invariant under permutation of the edit list (property test, 1,000 permutations).
- [ ] `realize` twice gives identical `SceneId`, schedule and parameter bytes.
- [ ] `vocabulary` for each of the seven archetypes lists at least one quantity per hazard row that carries a
      dimension, and every quantity carries the row's provenance.

## Test plan

### Unit tests
`crates/frob-nemesis/tests/world.rs`:
- `edit_classes_apply`: seven edits, one per class; assert the changed aspect digests are exactly the declared
  ones (light moved: only the optical digest changes; closer torque 14 → 19 N·m: only the fixture digest).
- `undeclared_path_refused`: grease film declared `material`, optical class `specular-floor` on: 362 with
  `required = ["material", "optics"]`.
- `empty_declaration_refused`; `unknown_tag_refused`.
- `canonical_identity`: the two-edit world of the counterexample-file example in both orders has one `WorldId`.
- `conflicting_edits_refused`: two `set` edits on one path with different values.
- `dependency_ideal`: an added cart and an edit of the cart's mass; the subset containing only the mass edit is
  not an ideal.
- `disturbance_merge`: a push of 12 N·s at tick 4,000 appears in the realized schedule and nowhere in the
  per-step streams.
- `vocabulary_home`: the home registry's threshold row yields a height quantity with range 5 to 25 mm, provenance
  `assumed`.

### End-to-end script and logging
Exercised by `scripts/e2e/nemesis_legality.sh` (N26a-05), which offers worlds with undeclared paths and logs the
refusal code, pointer, declared and required tags.

### Known answers and negative controls
Negative control: a declaration check that only tests non-emptiness (the film edit then passes; the test must
catch it). Metamorphic relation: adding an edit and its exact inverse returns the base world's `SceneId`.
Determinism: identities are exact (class D0) and equal across platforms.

## Considerations

- The tags are a small closed set on purpose: the counterfactual debugger refuses an intervention that changes
  two mechanisms unless it is split, so an edit with two tags is admitted here and split there.
- OPEN: the plan's own examples use slightly different tag words in three places (the class table, the retrofit
  catalog, the counterexample file). The closed set above is the reconciliation; if the owner of the scene crate
  fixes a different spelling, only the mapping table changes.
- Performance: the completeness check compiles a scene variant per edit; variants share all untouched bricks, and
  the result is memoized by (base `SceneId`, edit).
- Private scenes: a world derived from a private scene inherits the private mark; paths are never logged for
  such worlds.
