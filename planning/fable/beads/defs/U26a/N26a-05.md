## Background

The legality profile has no verb of its own: it is the first thing every Nemesis verb checks. What a user or an
agent sees is a refusal, with a code, the bound that was violated, the value observed and what to change. This
script proves from the user's side, on the real binary, that an inadmissible world never reaches the simulator
and that the refusal is specific enough to act on. It measures the first row of GATE-NEMESIS-01 (known-answer
claim, earliest milestone M3; TARGET): 100 of 100 planted illegal edits refused. The other two rows of that gate
(0 of 100 impossible traps counted; at least 95 of 100 solvable traps given a witness) are measured by the
oracle's bead (BD-271) and its script (N26a-33), which writes the combined record; the gate is recorded as
passed only when all three rows are.

Refusals exercised, with meaning, repairs and exit code:

| Code | Meaning | Ranked repairs | Exit |
|---|---|---|---|
| FROB-REF-360 | A world or edit lies outside the legality profile; the violated bound is named | Move the value inside the bound (nearest legal value attached); drop the edit; use a profile that declares the wider bound | 3 |
| FROB-REF-361 | The request demands `cited` bounds and the profile has an `assumed` bound on a touched quantity | Rerun without the demand; record a source for the bound; restrict to cited or card bounds | 3 |
| FROB-REF-362 | An edit does not declare the causal paths it changes | Add the listed tags; split the edit; choose another quantity | 3 |

## Scope

In: one script, its fixtures (the planted illegal-edit registry and legal twins of N26a-04), its assertions and
logs, the recorded measurement of the gate's legality row.
Out: the oracle rows of the gate; unit tests of the checker (BD-270, N26a-02).

## Technical approach

1. **Surface used.** `frob nemesis oracle <candidate> --task <task> --world <world.json> --legality <profile>
   --json` (the verb classifies one world for one candidate; legality is checked before anything runs, so an
   illegal world returns in milliseconds with `ok: false`, exit 3, and no job). A second pass offers a sample of
   the same worlds to `frob nemesis search … --worlds <ndjson> --method given` to show the search path refuses
   identically.
2. **Steps.**
   1. `start`: record binary build, registry digest, profile identities, seed.
   2. For each of the 100 illegal records: run the oracle command; assert exit 3, `refusal.code` =
      `FROB-REF-360`, `refusal.pointer` names the planted edit or composite, `refusal.observed` and
      `refusal.required` are present with a unit, the bound name equals the record's `truth.bound`, and
      `cost.gpu_s` = 0 and no episode was created (ledger count unchanged).
   3. For each legal twin: assert the verb is admitted (exit 0, 2 or 8; never 3 with code 360).
   4. Ten worlds with an undeclared causal path: assert `FROB-REF-362`, with `required` listing the missing tag.
   5. Ten legal worlds touching an `assumed` bound with `--require-cited`: assert `FROB-REF-361`; the same
      without the flag: admitted, and the result's `legality.touched` lists the bound with provenance `assumed`.
   6. Negative control: rerun five illegal records against the mutated profile (the planted bound widened to the
      physical domain): assert admitted. If any is still refused, the script fails: the refusal did not come
      from the bound.
   7. Search path: 20 illegal worlds as `--worlds`: assert each appears in the result's `refused` list with code
      360 and `worlds_searched` excludes them.
   8. `metric`: `illegal_refused = k of 100` against threshold `100 of 100`; write the gate record.
   9. `summary`.
3. **Logging.** Sources the shared helper of the end-to-end harness and writes
   `target/e2e-logs/nemesis_legality/<utc>.ndjson` plus a transcript. Every line: `ts`, `script`, `bead`
   (`N26a-05`), `step`, `event`, the exact command line, exit code, wall time, the envelope's `evidence` block,
   and for `refusal` events the code, pointer, bound, observed, required, unit, provenance. On failure: the first
   record whose refusal differs from its truth, with the world file path and the profile path. The final
   `summary` gives assertions passed and failed and `gates: ["GATE-NEMESIS-01 (legality row)"]`. Worlds from
   private scenes do not occur in this corpus; no private-scene data is logged.
4. **Gate record.** The measured count, the registry digest, commit, hardware fingerprint and seed go to the gate
   register as the legality row of GATE-NEMESIS-01; the gate's overall status is computed from all three rows.
5. **Idempotent and seed-explicit.** The script creates nothing persistent except its log and the gate record;
   rerunning it yields the same refusals (exact arithmetic).

## Acceptance criteria

- [ ] `scripts/e2e/nemesis_legality.sh` exits 0 on a correct build and non-zero if any assertion fails.
- [ ] 100 of 100 planted illegal edits are refused with FROB-REF-360 and the right bound (TARGET of the gate
      row), and the measured count is in the gate register with commit, fingerprint and seed.
- [ ] All 100 legal twins are admitted.
- [ ] The widened-bound control admits the planted edits; a deliberately broken checker (per-edit only, built
      behind a test feature) makes the script fail on the composite records.
- [ ] No refused world produced an episode or a charge.
- [ ] The log has one line per command with the fields above and a final summary line.

## Test plan

### Unit tests
None beyond the script's self-test: `scripts/e2e/tests/nemesis_legality_selftest.sh` runs the script against a
build with the test feature `nemesis-broken-legality` (the per-edit-only checker) and asserts a non-zero exit and
a log line naming the first composite record that was wrongly admitted.

### End-to-end script and logging
This bead is the script; see the steps and logging above.

### Known answers and negative controls
KA-659: planted illegal edit refused with FROB-REF-360 and the bound named, 100 of 100; control: a profile with
the bound removed admits it (step 6). Counter-control: legal twins admitted (a checker that refuses everything
fails step 3). Determinism lanes: run twice on one machine and once on the second platform; refusal envelopes are
byte-identical apart from `ts` and `cost.wall_ms`.

## Considerations

- The script depends on the oracle verb only as the thinnest surface that takes one world; if the oracle is not
  yet built when the legality checker is, the same steps run through `nemesis.search --method given` alone.
- A refusal message that names the bound but not the nearest legal value still passes the gate row; the repair
  payload is asserted separately so a regression in it is visible.
