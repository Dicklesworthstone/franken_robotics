## Background

A search method is only as good as what it is compared with. Every adversarial campaign therefore runs
**card-uniform randomization at equal budget as its baseline arm**: worlds drawn from the task's own
randomization (every randomized parameter traces to an uncertainty on a card; scenes come from the generator),
evaluated by the same monitors, and reported beside the search's count. The same arm is also the fallback: if the
search does not beat it (kill gate KILL-NEMESIS: GATE-NEMESIS-02 fails after one repair cycle), the search
methods are removed and Nemesis keeps the legality profile, the solvability oracle, the artifact guard and
shrinking, applied to failures that card randomization finds. So this arm must be a complete pipeline in its own
right, and it must be built first.

A second baseline is admissible: a **scenario-language sampler** (a program in a scenario description language
that generates worlds) given the same generator and the same monitors. It is the strongest conventional
alternative an outside expert would reach for, and the bet behind the search names it as an arm.

This bead is Solid: sampling by address and bookkeeping. It defines the interface every search method implements,
so that methods are interchangeable and every evaluated world is recorded with the law that proposed it.

## Scope

In: trait `SearchMethod`; the `Proposal` record; the card-uniform arm; the `given` arm for externally proposed
worlds (which carries the scenario-language arm); equal-budget accounting; the fallback pipeline.
Out: the campaign driver, the score and the verb (BD-273); the other methods (N26a-08, N26a-09, BD-277); the
oracle, the guard and the shrinker (BD-271, BD-272, BD-274).

## Technical approach

1. **Interface (DESIGN sketch).**
   ```rust
   pub trait SearchMethod {
       fn id(&self) -> SearchMethodId;
       /// Propose up to `n` worlds. Deterministic in (campaign seed, round, history digest).
       fn propose(&mut self, round: u32, n: usize, history: &History) -> Vec<Proposal>;
       /// Receive the scored outcomes of the last proposals (margin, verdict, failure class, binding atom).
       fn observe(&mut self, outcomes: &[Outcome]);
   }
   pub struct Proposal { world: World, law: ProposalLaw, log_q: Option<f64> }   // log proposal density, when known
   ```
   Every proposal is legality-checked by the driver before evaluation; an illegal proposal is counted against the
   method and not simulated. Every evaluated world is recorded with its address and its proposing law, so a later
   importance-weighted estimate remains possible.
2. **Card-uniform arm.** `search::baseline::CardUniform`: world k of the arm is the nominal draw at address
   `(run_seed, k, 0)` on the registered stream of the task's randomization: scene from the generator family,
   parameters from the cards, declared disturbances from the task's law. `law = Nominal`, `log_q` = the nominal
   log density. It never looks at outcomes (`observe` is a no-op). Draws are exact functions of the address, so
   the arm is reproducible and independent of batch size.
3. **The `given` arm.** `search::baseline::Given` reads worlds from a newline-delimited file of world documents
   (edit lists against named base scenes; on the command line the file is the verb's `--worlds <file>`, which
   BD-273 requires with `--method given`) and proposes them in file order: `law = Given { source }`. It is how a
   scenario-language program's output enters: the program runs outside the workspace against an export of the
   same base-scene family and the same legality profile, writes its worlds, and they are legality-checked and
   evaluated here by the same monitors at the same budget. No scenario-language tool is linked or added to the
   dependency graph. The arm is also the way to evaluate hand-written or planted worlds.
4. **Equal budget.** The unit is simulated steps, summed over every episode an arm causes, including the oracle's
   witness runs, the guard's replays and, where the comparison says so, shrinking. `BudgetLedger { arm, phase,
   steps, episodes, gpu_s, cpu_core_s }` is charged per phase (propose, evaluate, oracle, guard, shrink). A
   campaign's budget is split equally between the search arm and the baseline arm; neither may borrow from the
   other, and an arm that stops early returns its remainder unused. The result prints both arms' charged steps.
5. **Fallback pipeline (the KILL-NEMESIS branch).** The fallback is card-uniform proposals → legality →
   evaluate on the fast tier → for each world with negative margin after the boundary check: oracle → guard;
   then shrinking (`nemesis.shrink`) and the hard-world set (`nemesis.hardset add`) on the promoted failures. It
   is the same downstream as the search's, with one proposer. This bead owns the proposer side: the portfolio
   `baseline-only` (card-uniform and `given`, nothing else constructed) and the configuration switch
   `nemesis.search.methods = all | baseline-only` that selects it; the kill decision (N26a-12) sets the switch.
   The downstream is the campaign driver's (BD-273, which depends on this bead and on the oracle and the guard),
   so this bead does not wait for the oracle and the guard and the method beads can proceed beside them. Under
   the switch, `nemesis.search` still exists and reports `method: "card-uniform"`.
6. **Evidence.** Failures found by this arm are discovery data like any other (they were selected by their
   outcome). The arm's draws are nominal, but a count of failures among them is not a bound unless the episodes
   were requested through the certification lane with a frozen predicate; the arm's `law` is `Nominal` and its
   campaign record marks them `selected-by-outcome` when any is forwarded to shrinking.

## Acceptance criteria

- [ ] `CardUniform` proposes the same worlds for the same campaign seed in batches of 1, 64 and 4,096, and in any
      order of rounds (digest of the proposal list equal).
- [ ] The empirical distribution of 10⁵ proposals of a normal card parameter passes a goodness-of-fit test
      against the card's law at level 0.001; a discrete generator feature of probability 1/100 appears in
      between 900 and 1,100 of 10⁵ scenes.
- [ ] `Given` proposes file worlds in order, refuses malformed documents with the line number, and records
      `law = Given` with the file's content hash.
- [ ] The budget ledger of a two-arm campaign shows the two arms within one batch of each other in steps, and
      the oracle and guard steps on the arm that caused them.
- [ ] With `methods = baseline-only`, the portfolio constructs only the card-uniform and `given` arms (no search
      method is linked into the run) and finds a planted trap of probability 10⁻² on a `synthetic` margin within
      2,000 draws in at least 99 of 100 seeded runs (the expected number is 100; the chance of a miss in 2,000
      draws is 0.99²⁰⁰⁰ ≈ 1.9 × 10⁻⁹). The classified, guarded failure through the oracle and the guard is asserted
      by the driver's test `fallback_pipeline_complete` (BD-273) and by N26a-12.
- [ ] Every evaluated world of both arms has a ledger record with address and proposing law.

## Test plan

### Unit tests
`crates/frob-nemesis/tests/baseline.rs`:
- `card_uniform_is_address_function`: three batch sizes, one digest.
- `card_uniform_matches_card_law` (`synthetic` card: normal mean 0.6, standard deviation 0.05; uniform [5, 20]).
- `given_order_and_hash`; `given_malformed_line_refused`.
- `budget_equal_split`: a campaign of 2 × 10⁶ steps: each arm charged at most 10⁶; early stop returns the rest.
- `budget_charges_downstream`: a failure found by the search arm charges its witness and replay steps to that
  arm, not to the baseline.
- `fallback_pipeline_planted_trap`: a planted trap box z₁ > 2.3263 (probability 0.01) on a `synthetic` margin
  function: found within 2,000 draws in at least 99 of 100 seeded runs (the chance of missing in 2,000 draws is
  0.99²⁰⁰⁰ ≈ 1.9 × 10⁻⁹).
- `baseline_only_portfolio`: with the switch at `baseline-only` the portfolio holds exactly `card-uniform` and
  `given`; constructing any other method returns FROB-REF-724 (not implemented in this build; exit 5) with
  pointer `method`, the kill gate KILL-NEMESIS and its decision record named in the message.
- `illegal_proposal_counted_not_run`: a method that proposes an illegal world sees it in its `refused` count and
  no episode exists for it.

### End-to-end script and logging
Driven by `scripts/e2e/nemesis_search.sh` (N26a-11), which runs the baseline arm beside the search and logs per
arm the method, worlds evaluated, steps charged per phase, failures at equal budget; and by a step that runs the
whole script with `methods = baseline-only` to show the fallback branch works.

### Known answers and negative controls
KA-661's control is this arm: card-uniform randomization at the same budget, as the baseline. Negative controls:
a baseline arm given a tenth of the budget (the equal-split test must fail it); a baseline whose draws depend on
batch size. Metamorphic: permuting world indices permutes outcomes and changes no count. Determinism lanes:
twice on one machine; across worker counts; debug and release: identical proposal digests.

## Considerations

- An arm against a weak baseline measures the baseline. The card-uniform arm uses the same monitors, the same
  tier, the same legality profile and the same downstream as the search, so the only difference is the proposer.
- The scenario-language arm depends on a tool outside the workspace; when none is installed the arm is recorded
  `not run` with the reason, never silently skipped.
- Expected cost of the baseline at a probability of 3 × 10⁻⁵ is about 33,333 draws to the first failure; gates
  cap and censor it, which is conservative for the search's measured gain.
