## Background

Given a failing world w = base ⊕ {e₁ … e_n} whose base passes, and a test relation that says whether a subset of
the edits still fails by the same mechanism on paired seeds (N26a-17), this bead finds a small subset that still
fails and says exactly what "small" it has earned. The algorithm is delta debugging. Its guarantee is
**1-minimality**: removing any single remaining edit makes the failure disappear (or makes the world
inadmissible). It is not the minimum, and no stronger claim is made, because failure sets are not monotone: an
edit can mask another, and two disjoint causes can coexist.

The counterexample that fixes the wording (CX-288): let the world fail when edits a and b are both present or
when c, d and e are all present. With the edits listed as (a, c, d, e, b), delta debugging tests the halves
{a, c} and {d, e, b}, which pass, then the singletons and {e, b}, which pass, then finds that the complement
{c, d, e, b} fails, and ends at {c, d, e}: three edits, 1-minimal, while the two-edit counterexample {a, b}
exists. DESIGN: when the original list has at most 12 edits, every subset of one or two edits is also tested, 78
tests at most, and the smaller counterexample replaces the result. A world that passes this check is labelled
minimum among pairs; no world is called the closest failure.

The admissible sub-worlds are the subsets closed under edit dependencies (the order ideals of the edit set); the
search returns a failing ideal from which no single edit can be removed. FACT: the sibling library's `fs-bisect`
bisects a linear history under a monotonicity check and does not search a subset lattice, so this is ours.

Frontier (pilot N26a-06, gate GATE-NEMESIS-03, kill gate KILL-MCW). The algorithm is pure: it sees only the
relation, so all of its properties are tested on synthetic predicates without a simulator.

## Technical approach

1. **Delta debugging (numbered; `test(S)` is true exactly when the relation returns `Fails`).**
   1. Current list C = the edits in their canonical order; k = 2.
   2. While |C| ≥ 2: split C into k contiguous parts, part i covering indices [⌊i·|C|/k⌋, ⌊(i+1)·|C|/k⌋).
   3. Test each part in order. If some part fails: C = that part, k = 2, go to 2.
   4. Otherwise test each complement (C minus one part) in order, skipping complements equal to an already
      tested set. If some complement fails: C = that complement, k = max(k − 1, 2), go to 2.
   5. Otherwise, if k ≥ |C|, stop; else k = min(2k, |C|), go to 2.
   The result is 1-minimal: at the last round every part was a singleton, so every single-removal complement was
   tested and did not fail. Worst-case tests are quadratic in n.
2. **Bisection of continuous edits.** For each remaining edit with a continuous value, in descending order of
   normalized magnitude: let t ∈ [0, 1] interpolate from the nominal value (t = 0, the edit removed, which by
   1-minimality does not fail) to the found value (t = 1, which fails). Bisect: lo = 0, hi = 1; test the world
   with the edit at t = (lo + hi)/2; if it fails hi = t, else lo = t; 6 steps (TARGET; resolution 1/64 of the
   edit's magnitude) or until the step is below the authored resolution of the quantity. Keep hi, the last
   failing value. The edit moved toward its nominal value until the failure was lost; the value kept is a
   failing value found by bisection, not a threshold (the failure need not be monotone in t).
3. **The pair check.** If the original list has n ≤ 12 edits: test every subset of one edit and every subset of
   two edits (n + n·(n − 1)/2 ≤ 78; cached outcomes are reused). If any fails and is smaller in the size order
   (fewer edits, then smaller normalized distance) than the current result, the smallest such replaces it, and
   bisection is rerun on it. The result is then `pairs_exhausted: true`.
4. **Labels (DESIGN reading of the plan's two statements).**
   ```rust
   pub enum Minimality { OneMinimal { pairs_exhausted: bool }, NonMinimal(u32) }
   ```
   - `OneMinimal { pairs_exhausted }`: 1-minimality was verified and the world has at most three atomic edits
     (the TARGET size). Printed as "1-minimal" or "1-minimal; minimum among pairs".
   - `NonMinimal(k)`: the shrunk world has k > 3 edits, or the shrink stopped before 1-minimality was verified
     (budget, seed-fragile input). The world is kept and labelled. A companion field
     `one_minimal_verified: bool` says which case it is, so a 1-minimal five-edit world is not mistaken for an
     unfinished shrink.
5. **Passing neighbours.** After the final world is fixed, each single-removal neighbour (the world with one
   edit removed) is recorded with its world identity; by 1-minimality each exists and does not fail. They are the
   interventional contrasts carried forward with the failing world.
6. **Trace.** `ShrinkTrace { order: [(subset, outcome)], tests, rounds }`: every distinct subset tested, in
   order, so a shrink can be audited and replayed.
7. **Budget.** A test budget (default 400 tests, TARGET) and the verb's compute budget. On exhaustion the current
   list is returned as `NonMinimal(|C|)` with `one_minimal_verified: false`.

## Acceptance criteria

- [ ] PO-NEMESIS-01: on random predicates over up to 16 edits, monotone and non-monotone, the output always
      satisfies the predicate and no single-edit removal does (property test, 10,000 predicates).
- [ ] Planted causes of size 1, 2 and 3 among 8, 16 and 32 edits (failure exactly when the planted set is
      present) return the planted set exactly, with these distinct-test counts for the reference placements:
      n = 8: 4, 16, 26; n = 16: 5, 23, 41; n = 32: 6, 30, 56 (planted {2}; {2, n − 1}; {1, n/2, n}).
- [ ] The order-dependence example reproduces: before the pair check {c, d, e} after 15 distinct tests in the
      order ac, deb, a, c, d, eb, cdeb, ceb, cd, e, b, cdb, cde, de, ce; after the pair check {a, b}, with 5
      further distinct tests (ad, ae, ab, cb, db), 20 in all.
- [ ] Eight edits with failure exactly when edits 3 and 6 are present return {3, 6} (16 distinct tests).
- [ ] With a masking edit (edit 1 fails; edit 2 masks it), an input {1, 3, 4, 5, 6} returns {1} and the result
      carries no distance-to-boundary claim.
- [ ] Bisection of a continuous edit with a planted threshold at 37/64 of its magnitude returns a failing value
      within 1/64 of the threshold after 6 steps.
- [ ] Labels: a 2-edit verified result is `OneMinimal`; a verified 5-edit result is `NonMinimal(5)` with
      `one_minimal_verified: true`; a budget stop is `NonMinimal(k)` with `false`.
- [ ] For 12 edits the pair check runs at most 78 tests; for 13 it does not run and `pairs_exhausted` is false.

- `po_nemesis_01_property` (monotone: failure iff a random planted set is contained; non-monotone: unions of two

- `chunking_rule`: 5 elements into 4 parts gives sizes 1, 1, 1, 2; into 2 parts gives 2, 3.
- `inadmissible_subsets_do_not_fail`: with a dependency (edit 5 needs edit 4), a planted cause {5} returns
  {4, 5}, which is 1-minimal in the sense that removing 4 leaves an inadmissible world.
- `bisection_threshold`, `bisection_non_monotone`: a failure band [0.3, 0.5] ∪ [0.8, 1] returns a failing value
  and labels it "last failing value", not "threshold".
- `pair_check_bounds`: 12 edits → at most 78; 13 → skipped.
- `labels_all_cases`; `budget_stop_returns_current`.
- `neighbours_listed`: a 3-edit result lists 3 neighbours, each not failing.

## Considerations

- The result depends on the order of the edit list. The canonical order (by path) makes it reproducible, not
  canonical in any deeper sense; the pair check removes the order dependence only for causes of size one or two.
- KILL-MCW. Trigger: on unplanted failures fewer than half of shrunk worlds have at most three edits, or fewer
  than 90% replay. Fallback: full failing worlds with replay and the single-edit contrasts ranked by margin; the
  format stays. Under it this module is reduced to the single-removal queries.
- The size TARGET of three edits is an aspiration about worlds, not something the algorithm can force; the share
  of unplanted failures that reach it is recorded by the gate, not asserted.
