## Background

GATE-NEMESIS-01 (known-answer claim; earliest milestone M3; TARGET) has three rows: 100 of 100 planted illegal
edits refused; 0 of 100 planted impossible traps counted; at least 95 of 100 planted solvable traps receive a
witness. The first row is measured by the legality script (N26a-05). This script measures the other two, on the
verb a user or agent calls: `nemesis.oracle` classifies one world for one candidate and returns the witness or
the failed necessary condition.

What is being protected: only solvable worlds count. A world is a counterexample to a design only with a witness
that the candidate's own body, actuators and mission constraints could have satisfied the requirement in it. The
four classes are `solvable-causal` (a controller using only the candidate's observation interface satisfies the
requirement within every actuator and mission limit), `plant-feasible` (a trajectory found with privileged state
satisfies it within the body's limits), `not-excluded` (necessary conditions pass and no trajectory was found:
unresolved, reported, not counted either way) and `infeasible-for-candidate` (a checked necessary condition
fails, with its dual vector or its bottleneck named: not a counterexample, counted in the scorecard's infeasible
column and offered to the retrofit query). The verification program lists this very check among the certifiers
it certifies: planted illegal edits, impossible traps and solvable traps, with "a point-robot oracle is caught on
the narrow doorway" as the control.

## Scope

In: the script, assertions, logs, the two gate rows' record, the combined gate status.
Out: the oracle and its components (BD-271, N26a-13, N26a-14); the plants (N26a-04); the legality row (N26a-05).

## Technical approach

1. **Surface.** `frob nemesis oracle <candidate> --task <task> --world <world.json> --legality <profile> --key
   <k> --json`; long worlds return a job handle (exit 8) and the script waits on it. Result fields asserted:
   `class`; for the solvable classes `witness { controller, source, margin, trace, channels_read, guard }`; for
   `infeasible-for-candidate` `condition { id, kind, certificate (bottleneck or dual-vector hash), check:
   accepted }`; for `not-excluded` `tried: [sources]`. Every run-verb call of the script (`nemesis oracle`,
   `nemesis search`, `sim run`) carries its own `--key no-<step>-<plant>`, so a rerun returns stored receipts and
   no two compared runs share one.
2. **Steps.**
   1. `start`: build, registry digest, seeds, tier, hardware fingerprint.
   2. Impossible traps (100): run the oracle on each. Assert `class` is `infeasible-for-candidate`, the named
      bottleneck or failed condition equals the plant's truth, and the certificate check is `accepted`. Then
      submit all 100 to `frob nemesis search … --method given`: assert none appears in `failures` and all are
      under `not_counted.infeasible_for_candidate`. Metric `impossible_counted = k of 100` against `0`.
   3. Solvable traps (100): for each, take a world inside its trigger box, confirm the candidate fails there
      (`frob sim run`), run the oracle. Assert `class` is `solvable-causal` or `plant-feasible`; the witness's
      guard block is `passed`; for `solvable-causal`, `channels_read` contains only candidate channels. Metric
      `solvable_with_witness = k of 100` against `≥ 95`. Worlds left `not-excluded` are listed with the sources
      tried.
   4. Point-robot control: rerun 10 clearance traps against a build with the test feature
      `nemesis-oracle-point-robot` (footprint replaced by a point); assert the mutated oracle calls them
      solvable or route-feasible, and that the script's own assertion of step 2 fails on that build (inner run
      in a subshell; the outer script requires the inner failure).
   5. Search-failure control: on 5 impossible traps, against a build with N26a-13's test feature
      `nemesis-oracle-no-necessary` (every necessary condition returns `Unresolved`), so the witness search runs
      to its budget and fails: assert the class is `not-excluded`, never `infeasible-for-candidate` (a failed
      search for a witness proves nothing).
   6. Witness-through-artifact control: the 20 planted false witnesses of the guard's registry (N26a-15): assert
      none yields a solvable class on the strength of the planted run.
   7. Scorecard: `frob eval scorecard` over a small battery containing three impossible traps: assert they land
      in the `infeasible-for-candidate` column with the witness attached, and success rates are printed with two
      denominators (all scenarios; scenarios not shown infeasible).
   8. Combine: read the legality receipt of N26a-05; write this script's receipt with all three rows of
      GATE-NEMESIS-01 (the gate passes only if all three do), from which the gate's record is entered (item 4).
      `summary`.
3. **Logging.** `target/e2e-logs/nemesis_oracle/<utc>.ndjson` and a transcript through the shared helper. Every
   line: `ts`, `script`, `bead` (`N26a-33`), `step`, `event`, exact command, exit code, wall time, the evidence
   block. Per world: plant id and kind; the mandatory-events record the conditions were posed from (N26a-36:
   `events_id`, the event kinds, `kinematic_state_fixed` per event, the count of unmapped obligations); each
   necessary condition with its kind (`necessary` or `screen`), result, certificate hash and, for a failed
   condition, the source atoms of the event it was posed for (on the doorway trap a `ReachRegion` beyond the
   door; on the slope trap a `HoldPayload` with `kinematic_state_fixed: true`); each witness source tried with
   steps spent and outcome; the final class; witness
   controller, margin, trace digest, channels read, guard verdict per variant. On failure: the first plant whose
   class differs from its truth, with the world file and the job identity. Metric `not_excluded_with_unmapped`:
   the share of `not-excluded` worlds whose requirement has unmapped obligations (N26a-36's visible cost of its
   under-approximation; recorded, no threshold). Summary: assertions passed and failed;
   `gates: ["GATE-NEMESIS-01"]`.
4. **Gate record.** The three measured counts (100 of 100 illegal refused, from N26a-05; impossible counted;
   solvable with witness), registry digest, commit, fingerprint, seeds, in the script's receipt, which names
   N26a-05's legality receipt beside its own; the gate's record is entered from it by a session that did not
   implement the capability, with `cargo run -p frob-conformance --example record_gate -- --gate
   GATE-NEMESIS-01 --receipt <hash>` (N38b-19; no script writes a gate record).

## Acceptance criteria

- [ ] `scripts/e2e/nemesis_oracle.sh` exits 0 on a correct build and non-zero on any failed assertion.
- [ ] 0 of 100 planted impossible traps are counted as counterexamples, each classified
      `infeasible-for-candidate` with its bottleneck or dual vector (TARGET of the row).
- [ ] At least 95 of 100 planted solvable traps receive a witness that passed the artifact guard (TARGET of the
      row); the measured count is recorded.
- [ ] The point-robot build is caught: on it the script's impossible-trap assertion fails.
- [ ] Budget exhaustion yields `not-excluded` and never infeasibility.
- [ ] GATE-NEMESIS-01 is recorded complete, with all three rows, commit, fingerprint and seeds.
- [ ] The log has the per-world fields above and a final summary line.

### Known answers and negative controls
KA-660 (a doorway narrower than the body is `infeasible-for-candidate` with the bottleneck, never a
counterexample; 0 of 100 counted; control: an oracle that checks a point robot calls it solvable). KA-661 (a
planted solvable trap of known nominal probability is found with a causal witness; at least 95 of 100 receive
one). KA-143 (the impossible-world control of the construction). CX-289. INV-NEMESIS-01 (no world without a
`solvable-causal` or `plant-feasible` witness enters a counterexample count) asserted through the search path in
step 2. Determinism lanes: the oracle's class and witness controller are identical twice on one machine and
across worker counts.

## Considerations

- A solvable trap left `not-excluded` costs yield, not correctness; the 95-of-100 threshold measures the witness
  search's power, and the list of sources tried per miss is the diagnostic.
- The script uses small scenes and one robot class per archetype family so that 200 oracle calls with guarded
  witnesses finish in tens of minutes on CPU cores.
- The hand-off of an infeasible world's bottleneck to the retrofit query (`scene.retrofit`, N19b-40, M4) is
  checked by that later bead, not here (a script calls only what its bead depends on); this script logs each
  bottleneck in the form the oracle returns it, which is that verb's input.
