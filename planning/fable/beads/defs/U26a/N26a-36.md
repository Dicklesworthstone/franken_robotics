## Background

The solvability oracle of Nemesis classifies a failing world before it counts as a counterexample. One of its
four classes, `infeasible-for-candidate`, needs a *checked necessary condition*: a route exists for the
candidate's body, the wrench and torque envelopes suffice, the energy budget closes. All three are statements
about what the task forces the robot to do in that world: where it must arrive, what it must hold still, how far
it must lift. A task file (`.ftask`, schema `frob.task/1`) says this only implicitly, in its requirement: named
**atoms** (a comparison of two expressions over telemetry signals, with a scale), and a **verdict formula** over
the atoms built with `and`, `or`, `not` and the future-time operators `G` (always), `F` (eventually) and `U`
(until), each with a closed window of simulated time. No bead exported the task's obligations to the oracle; the
conditions bead (N26a-13) assumed a set of "mandatory task events" and this bead supplies it.

A **mandatory task event** is a physical fact that every trace satisfying the requirement must exhibit: the body
reaches a named region; a payload stays attached over a window; a body gains a stated height; the body is at
rest in a place for a stated time. Tier Solid: it is bookkeeping over the requirement language, and it lives in
`frob-nemesis` (layer 5) because the oracle is its only consumer.

The design constraint is one-sided soundness. The extraction may miss an event; the oracle then cannot exclude
the world and answers `not-excluded`, which is reported and counted neither way. It must never report an event
the requirement does not force: an invented event can make a solvable world `infeasible-for-candidate`, and a real
counterexample would leave the counts unnoticed (the decision that only solvable worlds count, read from its
other side). Rejected alternatives: (a) a hand-written event list per task family, which drifts from the
requirement and cannot be checked against it; (b) reading events off a successful witness trace, which shows one
way to satisfy the requirement and not what every way must do; (c) a new section of the task file in which the
author declares events, which changes a shared format for one consumer and still needs this check to catch a
declaration the formula does not imply.

## Scope

In: `oracle::events`: the obligation analysis of a verdict formula; the role table that maps a signal to a
physical meaning; the event record with its identity; the soundness property test; three synthetic fixture tasks.
Out: the necessary conditions that consume the events and their certificates (N26a-13); witness search
(N26a-14); the requirement language, its parser and evaluators (BD-121, N24a-04); the task file and its admission
(BD-122); the task families whose signals get roles (BD-253); the oracle's pipeline and verb (BD-271).

## Technical approach

1. **Types (DESIGN).**
   ```rust
   pub struct Literal { atom: Ident, positive: bool }
   pub enum Part { Now(Literal), For { lit: Literal, offset: Window } }   // at tick t; throughout t + offset
   pub enum Obligation {
       Throughout { lit: Literal, window: Window },      // holds at every tick of the window
       Sometime { all_of: Vec<Part>, within: Window },   // one tick t in `within` at which every part holds
   }
   pub enum EventKind {
       ReachRegion { region: RegionRef, by: Time, rest: Option<Duration> },
       StayInRegion { region: RegionRef, over: Window },
       GainHeight { body: BodyRef, dz: Length },
       HoldPayload { payload: PayloadRef, over: Window },
       AtRest { over: Window },
   }
   pub struct MandatoryEvent { kind: EventKind, from: Vec<Obligation>, kinematic_state_fixed: bool }
   pub struct MandatoryEvents { task: TaskId, requirement: Ident, events: Vec<MandatoryEvent>,
                                unmapped: Vec<Obligation>, table_version: u32, id: Blake3 }
   ```
   Windows are closed intervals of simulated time held as exact rationals, measured from the episode start.
2. **Negation normal form.** Push `not` inward to the atoms: ¬G_w φ = F_w ¬φ, ¬F_w φ = G_w ¬φ, De Morgan for
   `and` and `or`. A negated `U` and every past-time subformula (`H`, `O`, `S`) are kept as opaque leaves that
   yield no obligation.
3. **Obligations, by recursion on the formula.** `all(φ, J)` returns obligations that hold when φ is true at
   every tick of the interval J; `some(φ)` returns the parts that hold together at one tick where φ is true.
   The verdict is evaluated at the episode start, so the result is `all(verdict, [0, 0])`. With J ⊕ [a, b] the
   interval [J.lo + a, J.hi + b]:
   - `all(lit, J)` = {Throughout(lit, J)}; `all(φ ∧ ψ, J)` = `all(φ, J)` ∪ `all(ψ, J)`;
     `all(G_[a,b] φ, J)` = `all(φ, J ⊕ [a, b])`.
   - `all(F_[a,b] φ, J)` = {Sometime(`some(φ)`, J ⊕ [a, b])}: for any one tick of J there is a tick in the
     window at which φ is true, and all parts of `some(φ)` hold together there. `all(φ U_[a,b] ψ, J)` is the
     same with ψ in place of φ; the left operand yields nothing, because the until-clause may be met at once.
   - `some(lit)` = [Now(lit)]; `some(φ ∧ ψ)` = `some(φ)` ++ `some(ψ)`; `some(G_[a,b] φ)`, when φ is a
     conjunction of literals, = [For { lit, offset: [a, b] }] for each literal, and otherwise nothing.
   - `some(F_[a,b] φ)` and `some(φ U ψ)` inside another `some` yield nothing (their witness tick is unknown
     relative to the outer one). A `Sometime` with no parts is dropped.
   - **Disjunction keeps only what both sides force, at one tick.** Along an interval the true side of a
     disjunction may alternate, so `all(φ ∨ ψ, J)` is computed at the first tick of J alone: the meet of
     `all(φ, [J.lo, J.lo])` and `all(ψ, [J.lo, J.lo])`. In the meet, two `Throughout` obligations on the same
     literal give `Throughout` over the intersection of their windows, dropped if empty; any other pair on
     the same literal gives a `Sometime` with the single part `Now(lit)` within the hull of the two time spans
     (a `For` part extends its span by its offset); a literal on one side only is dropped. `some(φ ∨ ψ)` keeps
     the parts present on both sides.
   Windows are first normalized to ticks of the requirement's clock by their declared rounding. Soundness is by
   induction on the formula: every trace that satisfies φ satisfies each returned obligation. The argument is
   written in the module's documentation and tested by the property test below.
4. **Roles: from a literal to a physical fact (DESIGN).** FACT: a task's `signals` section lists each telemetry
   channel a requirement reads, with name, unit, channel kind and clock. A literal is mapped only if its atom
   has the shape "one signal compared with a constant", and that signal's channel has a row in
   `registries/nemesis/event_semantics.toml`. The table is closed and versioned; its first rows cover the
   signals of the M3 task families (interior navigation, payload transport, low-friction crossing, tight-space
   maneuvering).

   | Role of the channel | Literal | Obligation | Event |
   |---|---|---|---|
   | Distance from the body's reference point to a named scene region | d ≤ r | `Sometime` | `ReachRegion`, the region grown by r, `by` the end of the window |
   | The same | d ≤ r | `Throughout` | `StayInRegion` |
   | Height of a named body or payload | z ≥ h | either | `GainHeight` with dz = h − (the largest start height the reset specification admits); no event if dz ≤ 0 |
   | Payload attached (an exact atom) | = 1 | `Throughout` | `HoldPayload` |
   | Speed of the base | v ≤ c with c ≤ 0.05 m/s (TARGET rest threshold) | `Throughout`, or a `For` part of positive length | `AtRest`; as a `For` part beside a region part it sets `rest` on that `ReachRegion` |

   An obligation with no row, an atom over two signals, and an atom wrapped in `min`, `max` or `delay` go to
   `unmapped`. Using the largest admitted start height makes the rise a lower bound, which is the direction a
   necessary condition needs.
5. **Fixed kinematic state.** `kinematic_state_fixed` is true for an event that the requirement forces to be met
   at rest: a `ReachRegion` with `rest` set, or a `HoldPayload` or `StayInRegion` whose window overlaps an
   `AtRest` window. Only such events may be posed to the wrench-and-torque condition as `necessary`; the others
   are posed as a screen, since dynamics may carry the body through them.
6. **Record and identity.** `mandatory(task, requirement) -> MandatoryEvents` is pure, runs on the host in exact
   arithmetic and is bit-identical everywhere (determinism class D0). Obligations and events are sorted
   canonically, and `id` is the BLAKE3 hash of the canonical record, so reordering conjuncts does not change it
   and a new table version does. The result is memoized by (TaskId, requirement, table version). Each
   certificate of the conditions bead embeds `id` and the index of the event it was posed for, so an
   infeasibility verdict names the requirement clauses it rests on. Evidence class `Tested`.
7. **Layout.** `crates/frob-nemesis/src/oracle/events.rs`; `registries/nemesis/event_semantics.toml`;
   `crates/frob-nemesis/tests/oracle_events.rs`; fixtures under `crates/frob-nemesis/tests/fixtures/events/`
   (three task files labelled `synthetic`: tray delivery, payload on a slope, lift to a shelf).

Worked case (the tray fixture). Atoms: `upright` (tilt ≤ 0.35 rad), `held` (tray attached = 1, exact),
`delivered` (distance to region `counter` ≤ 0.10 m), `slow` (base speed ≤ 0.05 m/s). Verdict:
`(and (G (0 60) upright) (G (0 60) held) (F (0 60) (and delivered (G (0 2) slow))))`. Obligations:
Throughout(upright, [0, 60]); Throughout(held, [0, 60]); Sometime([Now(delivered), For(slow, [0, 2])], [0, 60]).
Events: `HoldPayload(tray, [0, 60 s])`; `ReachRegion(counter grown by 0.10 m, by 60 s, rest 2 s)` with
`kinematic_state_fixed`; `upright` has no role and is listed as unmapped. The oracle therefore asks for a route
to the counter for the body with the tray, and for a static hold of the tray at the counter.

## Acceptance criteria

- [ ] `mandatory` on the tray fixture returns exactly the two events and the one unmapped obligation above.
- [ ] `(F (0 30) (or at_dock_a at_dock_b))` yields no `ReachRegion`; `(or (F (0 30) at_dock_a) (and (F (0 30)
      at_dock_a) (G (0 30) slow)))` yields `ReachRegion(dock_a)` and no `AtRest`.
- [ ] `(U (0 20) moving docked)` yields `ReachRegion(dock, by 20 s)` and nothing from `moving`.
- [ ] `(not (F (0 10) (not held)))` yields `HoldPayload` over [0, 10 s].
- [ ] `(G (5 10) (F (0 3) delivered))` yields a `Sometime` within [5, 13] s, computed in rationals.
- [ ] A payload-height atom z ≥ 0.90 m with start heights admitted in [0.10, 0.25] m yields `GainHeight` with
      dz = 0.65 m; with start heights up to 0.95 m it yields no event.
- [ ] A signal with no row, and an atom over two signals, appear in `unmapped` and produce no event.
- [ ] Soundness: over 10⁴ random formulas (depth at most 5, six atoms) and 20 random traces of 64 ticks each,
      every trace the definitional evaluator calls satisfied meets every extracted obligation: 0 violations.
- [ ] Each of the three mutants below is caught by a named test.
- [ ] `id` is unchanged under reordering of conjuncts and changes with the table version.
- [ ] The signals of the M3 task families that carry a region distance, a payload attachment, a height or a base
      speed have rows; the registry test lists the families' requirement signals that have none.
- [ ] `CONTRACT.md` of `frob-nemesis` states the one-sided soundness rule and the role table's path.

## Test plan

### Unit tests
`crates/frob-nemesis/tests/oracle_events.rs` (pure; real parser and evaluator of the requirement language; no
mocks): `tray_delivery_events`; `disjunction_intersects`; `until_keeps_target_only`; `negation_pushed`;
`window_arithmetic_exact`; `interval_disjunction_first_tick_only` (`(G (0 20) (or (G (0 5) slow) (G (10 15)
slow)))` yields no `Throughout` on `slow`: a trace that alternates the two sides satisfies the formula with
`slow` false at 12 s); `height_gain_lower_bound` (0.90 − 0.25 = 0.65 m); `unknown_channel_unmapped`;
`two_signal_atom_unmapped`; `rest_sets_kinematic_state` (the slope fixture: `HoldPayload` overlapping `AtRest`
is fixed; without the speed clause it is not); `identity_stable`; property `soundness_on_random_formulas` (as in
the acceptance list, with an independent ten-line checker of obligations on a trace); property
`strengthening_is_monotone` (conjoining a clause never removes an obligation).

### End-to-end script and logging
No script of its own. `scripts/e2e/nemesis_oracle.sh` (N26a-33) runs `frob nemesis oracle … --json` on the planted
traps; for each world its log line for the necessary conditions carries `events_id`, the event kinds, and for
a failed condition the source atoms of the event it was posed for, beside the fields that script already
logs. On the doorway trap the line shows `ReachRegion` beyond the door; on the slope trap `HoldPayload` with
`kinematic_state_fixed: true`.

### Known answers and negative controls
Known answers are the derived values above: the three obligations of the tray verdict; the window [5, 13] s; the
rise 0.65 m. Negative controls, each a feature-gated mutant build that a named test must fail:
`events-mut-or-as-and` (a disjunction treated as a conjunction: over-reports; caught by
`disjunction_intersects` and by the soundness property); `events-mut-until-left` (the left operand of `U`
reported as `Throughout`; caught by the soundness property on traces whose until-clause is met at the first
tick); `events-mut-start-min` (the smallest start height used: 0.80 m in place of 0.65 m; caught by
`height_gain_lower_bound`). Metamorphic: expressing an atom in millimetres with its scale converted leaves the
record's `id` unchanged. Determinism: same bytes twice on one machine, in debug and release, and across
platforms.

## Considerations

- The extraction under-approximates by design. Its cost is visible, not silent: a world the oracle could have
  excluded stays `not-excluded`. The share of `not-excluded` worlds whose requirement has unmapped obligations
  is printed by the oracle script, so a role worth adding shows up as a number.
- A wrong row in the role table is the one way to over-report. Rows are few, reviewed like code and versioned;
  each row names the channel's unit and the fixture trace on which its event was checked by hand, and the
  registry test replays those traces (a role given to a channel of another unit is a load error; one given to
  a channel of the same unit and another meaning fails its trace).
- OPEN (owner: Nemesis lead with the Arena lead): whether roles should be declared beside each signal in the
  task file instead of in a Nemesis registry. Fail-closed default: the registry here; a channel with no role
  yields no event.
- Multi-stage missions chain stages with until-clauses; only the target of each `U` is forced, so intermediate
  stages yield `ReachRegion` events and stage invariants yield none. This is correct and conservative.
- Cost is negligible: a formula has at most a few hundred nodes; the result is memoized per task.
