## Background

A failing seed and a video are what an engineer usually gets when a simulated robot fails. ADR-NEMESIS-04 rules
otherwise: **smallest, not worst.** The smallest change that flips a verdict is more informative than the world
with the lowest score, so every failure is shrunk before it is reported. Rejected alternative: reporting the
minimum-margin world. The object produced is a *minimal counterexample world*: a passing base world plus a short
list of typed, atomic edits in authored units (a film on one floor patch, a door-closer torque, a packet delay)
such that the candidate fails by one named mechanism, with everything needed to replay it bit for bit, the
evidence that the candidate's own body could have coped (the solvability witness), and the neighbouring worlds,
one edit removed, in which the failure disappears. It is stored as a file, format FMT-FMCW, extension `.fmcw`,
schema `frob.mcw/1`, and becomes a regression world, the input of the counterfactual debugger (the failing world
and each passing neighbour are an interventional contrast) and the input of the retrofit question (does a cheap
amendment to the place fix the failure with the policy frozen?).

North-Star scenario NS-15 is this verb's demonstration: a failing world inside the legality bounds, confirmed by
a witness, shrunk to a `.fmcw` of three edits against the nominal scene (a door sill raised by 9 mm, a friction
coefficient of 0.31 on one floor tile, a depth packet delayed by 40 ms); removing any one edit removes the
failure; the world reproduces bit for bit and joins the regression battery.

Tier Frontier: delta debugging is established for programs; its yield on physical worlds is unmeasured. The
shrinking half of bet BET-22 rides on it ("each failure shrinks to a world of at most three edits that reproduces
bit for bit and that the design's own body could have coped with"), with gate GATE-NEMESIS-03 and kill gate
KILL-MCW named in advance. Ceiling, stated before any measurement: a better artifact per failure, measured in
agent repair iterations and not in steps. What "minimal" means is fixed and narrow: **1-minimal under removal of
atomic edits, and nothing stronger** (removing any single edit makes the failure disappear); no world is called
the closest failure, because failure sets are not monotone (CX-288, CX-067).

## Scope

This seed bead is the capstone of shrinking. Its parts are separate beads that it depends on and composes: the
test relation (N26a-17), delta debugging with bisection, the pair check and the labels (N26a-18), and the
counterexample-world file (N26a-19), with the size order of worlds (N26a-03); it is funded after the pilot
(N26a-06). The gate GATE-NEMESIS-03 is measured by the end-to-end script (N26a-34), from whose receipt it is
recorded, and KILL-MCW is decided by its decision bead (N26a-35); both depend on this bead, and this bead
depends on neither.

In: the shrink pipeline that composes the test relation, the search and the file writer; re-promotion and
re-witnessing of the shrunk world; the result schema; the verb on CLI and MCP with its estimate, budget stop,
cancellation and resume; refusal FROB-REF-564 at the verb boundary; the routing of `--out` through the export
door; the mode switch that KILL-MCW sets; the measurements GATE-NEMESIS-03 and KILL-MCW read.
Out: the relation `fails(S)` (N26a-17); delta debugging, bisection, the pair check and the labels (N26a-18); the
file type, reader and replay check (N26a-19); the export door `frob_verbs::export::admit`, its checks and codes
(N37-18); the planted-cause registry and the gate script (N26a-34); the kill decision and the specification of
its fallback mode (N26a-35); the hard-world set (BD-275).

## Technical approach

1. **Request.** A failure: a run identity or a failing world from a search campaign, with its candidate, task and
   legality profile. Options: seeds (64), threshold (48), test budget (400 tests, TARGET), `--no-pair-check`
   (for the order-dependence demonstration only), tier, output directory, idempotency key, compute budget.
2. **Pipeline `shrink::run` (numbered).**
   1. *Promotion first.* The verb does not trust the caller's word that a failure is promoted. It looks up or
      runs the artifact guard and the solvability oracle for the failing world. Guard label `artifact-candidate`
      → refuse with FROB-REF-564. Oracle class `infeasible-for-candidate` or `not-excluded` → no refusal code
      applies; the verb completes with `status: "not-shrunk"`, reason `no-witness`, and writes no file (a
      counterexample is kept only with a witness, INV-NEMESIS-01).
   2. *Replay.* Seed 0 of the full edit set must reproduce the recorded state digests on the originating
      backend and numerical profile; a mismatch → FROB-REF-564.
   3. *Edit list.* The world is written as base ⊕ {e₁ … e_n} with the edits in canonical order (by path) and
      their dependency relation (an edit inside an object another edit added needs that edit).
   4. *Base and full-set checks.* If the candidate fails in the base world there is nothing to shrink and the
      base is the counterexample (a zero-edit result). If the full set fails on fewer than 48 of 64 paired
      seeds the failure is seed-fragile: returned unshrunk, labelled `non-minimal(n)` with the reason.
   5. *Search.* Delta debugging over the edit list under the relation "the sub-world is legal, replays
      deterministically, violates the same requirement atom with the same failure class, on at least 48 of 64
      paired seeds" (TARGET); then bisection of each remaining continuous edit toward its nominal value, keeping
      the last failing value; then, when the original list has at most 12 edits, every subset of one or two
      edits (78 tests at most), the smaller counterexample replacing the result. A subset that fails by a
      different mechanism is not a pass and not the same failure: it is recorded as a separate finding and the
      shrink continues on the original mechanism.
   6. *The shrunk world is a new world: promote and witness it again.* The guard is run on it with the
      hard-world target (one tier up, the four numerical variants, the energy audit, and the referee), and the
      oracle is run on it. A witness of the full world need not be a witness of the smaller one (removing an
      edit can remove what made the world solvable), and a failure that survived the guard in the full world can
      be an artifact in the smaller one. If either check fails, the subset is marked `Inadmissible` in the
      relation's cache with the reason (`witness-lost` or `artifact`), the search resumes from its cached trace
      (the subset now counts as "does not fail"), at most three times (DESIGN); after that the smallest
      witnessed, promoted failing world found so far is returned as `non-minimal(k)` with
      `one_minimal_verified: false` and the reason. Artifact cases are written to the fidelity ledger.
   7. *Assemble.* Legality verdict with the bounds touched and their provenance; the prior
      (`log10_density_ratio` against the nominal world law); the passing neighbours (one identity per edit, each
      the world with that edit removed); the minimality record (`kind`, `pairs_exhausted`, `tests`,
      `seeds_failing`); failure (class, binding atom, margin, time); replay (backend, determinism class, digest
      chain); promotion; oracle; evidence (`Tested`, tier `referee`, standing `established`); the three
      no-authorization flags, all false.
   8. *Write only what replays.* The file is written through the canonical writer and then verified by the
      replay check on the originating backend; a file that does not replay with identical digests is invalid and
      is not published (INV-NEMESIS-04).
   9. *Record.* The world enters the discovery record (origin `nemesis`: it can never be a confirmation sample
      or a nominal draw for a bound). Artifact-graph edges: failing run → shrink trace → `.fmcw`. Separate
      findings enter the campaign as new candidate failures marked `found-while-shrinking`.
3. **Result, output schema `frob.nemesis.shrink.out/1` (input `frob.nemesis.shrink.in/1`; the names the verb
   registry VERBS-nemesis gives by rule).**
   ```json
   { "status": "shrunk", "mode": "minimal", "mcw": {"world": "w:3fa9…", "artifact": "b3:71d0…", "path": "out/w-3fa9.fmcw"},
     "edits_before": 7, "edits_after": 2,
     "minimality": {"kind": "1-minimal", "pairs_exhausted": true, "one_minimal_verified": true,
                    "tests": 37, "seeds_failing": "61/64"},
     "episodes": 2368, "bisection": [{"path": "/fixtures/door[pass]/closer_torque", "steps": 6, "kept": "19 N·m"}],
     "pair_check": {"ran": true, "tests": 12, "replaced": false},
     "neighbours_passing": ["w:51b0…", "w:e7c4…"], "separate_findings": [],
     "promotion": {"tier": "referee", "reproduced": true}, "oracle": {"class": "solvable-causal"},
     "trace": "b3:5c11…" }
   ```
   `tests` counts distinct subsets evaluated; each costs 64 episodes (37 tests are 2,368 episodes). `status` is
   one of `shrunk`, `base-fails` (zero edits), `seed-fragile`, `budget-stop`, `not-shrunk`. `mcw.path` is
   present only when `--out` was given and the export was admitted (item 4); without it the file is the stored
   artifact `mcw.artifact` alone.
4. **Verb.** `nemesis.shrink`, kind run, first milestone M3: shrinks a promoted failure and writes a `.fmcw`.
   CLI `frob nemesis shrink <failure> [--out DIR] [--max-tests 400] [--no-pair-check] [--tier T] --budget … --key
   <k> --json`; MCP tool `nemesis_shrink` in the task cluster `attack`; scope `nemesis:run`. A long verb: bounded
   wait, then a job handle with progress in tests (denominator: the test budget). Exit 2 when a file is written
   or a finding is reported, 3 on FROB-REF-564 or a legality refusal (FROB-REF-360 on the final world), 5 on the
   sealed-read refusal FROB-REF-840 (a failure whose world address is in the confirmation namespace, asked for
   without the qualification administration scope), 4 on a budget refusal at admission, 8 while running; for
   `--out`, the export door's exits below. The verb's refusal list is the registry's: 360, 564, 840, and for
   `--out` the door's 816, 731, 733 and 734 (the missing publish scope is the surface-wide FROB-REF-720).
   `--estimate` prints the cost before anything runs: at most `max-tests × 64` episodes on the fast tier
   (25,600 at the defaults), six guard episodes and up to 16 failing-episode equivalents of witness search per
   final candidate.

   **Where the file goes (DESIGN, the registry row's export treatment).** Without `--out` the `.fmcw` is stored
   as an artifact of the caller's namespace and nothing leaves the store; such a call needs no publish scope.
   With `--out <dir>` the file is also written outside the store, which is an export (N37-18 admits no
   exception for a writer outside the store). After step 2.8 has stored the replay-verified file, the handler
   calls `frob_verbs::export::admit(mcw, ExportKind::Run, session)` (export kind `run`: a derived view of a
   run's failing world) and writes through the jailed export writer only with the returned `ExportGrant`; the
   registry row carries `exports = true` and `option_capabilities = { out = ["export:report"] }`. The door's
   checks, in its order, each refusing before a byte is written: the three no-authorization flags present in
   the `.fmcw`'s manifest (FROB-REF-816, exit 3); the privacy mark of a scene the world derives from against
   the session's scope and flag (FROB-REF-731, exit 5); the licence set of the world's lineage against the
   export kind (FROB-REF-733, exit 5, with the `via` path to the offending asset); the publish scope
   `export:report` on the option (FROB-REF-720, exit 5); the path through the session's export jail
   (FROB-REF-734, exit 5). An `attribution` licence set adds a `NOTICES` file beside the `.fmcw`, listed in its
   manifest with its hash. A refused export leaves the stored artifact in the caller's namespace, readable
   through verbs, so no shrinking work is lost. Reason: a minimal counterexample world is derived from its
   scene, and written outside the store without the door it would leave the machine without the scene's
   privacy mark or licence.
5. **Refusal at this boundary.** FROB-REF-564: "shrinking requested for a failure that does not replay, or that
   the guard labelled an artifact candidate". `pointer`: the run; `observed`: the first differing step or the
   variant that removed the failure; `retry: after-change`. Ranked repairs: (1) rerun the guard after the
   simulator defect is fixed; (2) replay on the originating backend and numerical profile; (3) shrink a different
   failure. Exit 3.
6. **Budget stop, cancellation, resume.** Outcomes are memoized by subset bitmask in the job's chunk store. On a
   test-budget or compute-budget stop the current list is returned as `non-minimal(|C|)` with
   `one_minimal_verified: false` (and still promoted, witnessed and replay-verified before a file is written).
   Cancellation drains the running batch and finalizes the trace; a repeat with the same idempotency key resumes
   from the memo and re-runs no finished test.
7. **Mode.** Configuration `nemesis.shrink.mode = minimal | contrasts`, default `minimal`. The kill decision
   KILL-MCW (N26a-35) only sets the switch; both branches exist in this bead before the decision, so that the
   fallback can be forced and tested whatever the outcome. This bead implements `minimal` and the dispatch.
   Under `contrasts`, pipeline steps 2.1 to 2.4 (promotion, replay, edit list, base and full-set checks) run
   unchanged; steps 2.5 and 2.6 (search, re-promotion of a smaller world) are replaced by N26a-18's
   `shrink::contrasts(E, relation)`, which reads N26a-17's per-subset margin record (one query `fails(E ∖ {e})`
   per edit, on the same 64 paired seeds) and returns the ranked `Contrast { edit, seeds_failing_without,
   margin_gain }` list; steps 2.7 to 2.9 then assemble and write the full failing world (already promoted and
   witnessed) through N26a-19's writer with `minimality = non-minimal(n)`, `one_minimal_verified: false` and the
   ranked `contrasts`, the single removals that pass as `neighbours_passing`, and the replay check before the
   file is written, as in `minimal`. The result carries `"mode": "contrasts"` and `tests` = n distinct subsets
   beyond the cached full set.
8. **What the gate and the kill gate read.** For every shrink the verb records: edits before and after, tests,
   seeds failing, label, whether the written file replays, and the reason for any stop. GATE-NEMESIS-03 (Known
   answer; M3; TARGET): planted causes recovered exactly in at least 95 of 100 trials; every `.fmcw` replays with
   identical digests in 100 of 100; on unplanted failures the share of worlds with at most three edits is
   recorded. KILL-MCW (decided at M3): trigger, on unplanted failures fewer than half of shrunk worlds have at
   most three edits, or fewer than 90% replay; fallback, full failing worlds with replay and single-edit
   contrasts ranked by margin; the format stays.
9. **Determinism and evidence.** The trace is a pure function of the edit order and the relation; file bytes and
   identities are exact. A written file is `Tested` at tier `referee`; it authorizes nothing.

## Acceptance criteria

- [ ] Seed done-condition, in the part this bead delivers (convention 7): every quantity GATE-NEMESIS-03 and
      KILL-MCW read (item 8) is recorded per shrink and checked by `gate_measurements_recorded`. The gate itself
      is measured by N26a-34, which depends on this bead, on 100 planted-cause trials (planted causes recovered
      exactly, TARGET at least 95 of 100; `.fmcw` replay, TARGET 100 of 100; the share of unplanted shrunk
      worlds with at most three edits, recorded with its sample size), and recorded from that script's receipt
      with `record_gate` by a session that did not implement the shrinker (no script writes a gate record);
      KILL-MCW is decided from the same shares by N26a-35. This bead waits on neither.
- [ ] An `artifact-candidate` and a failure whose recorded digest differs are refused with FROB-REF-564, exit 3,
      with the three ranked repairs.
- [ ] A failure whose world has no witness completes as `not-shrunk` and writes no file.
- [ ] The shrunk world is promoted on the referee and witnessed again before the file is written; a planted case
      in which the witness is lost on the smaller world ends `non-minimal(k)` with reason `witness-lost` and the
      written world still has a witness.
- [ ] No file is published that fails the replay check on its originating backend.
- [ ] `tests × 64 = episodes` in every result; a resumed job re-runs no finished test.
- [ ] A shrink runs end to end on the CPU tiers (`batch-cpu` and the referee) with no device; on a device tier
      the originating backend's digests are the ones the file records and the replay check compares.
- [ ] Under `nemesis.shrink.mode = contrasts` the verb writes the full failing world with the ranked contrasts,
      `non-minimal(n)` and `one_minimal_verified: false`, and the file validates and replays.
- [ ] Without `--out` the `.fmcw` is a stored artifact only and the call needs no publish scope; with `--out`
      the handler writes outside the store only with an `ExportGrant` from `export::admit` (export kind `run`),
      and the door's refusals arrive in its order: 816 (exit 3), 731, 733 (with `via`), 720 for a session
      without `export:report`, 734 (each exit 5), with no byte written outside the store and the stored artifact
      kept; N37-18's `exports = true` lint passes for the row.
- [ ] The verb is reachable through `frob --json` and MCP with schema `frob.nemesis.shrink.out/1`, example and
      the refusal list 360, 564, 840, 816, 731, 733, 734; cancellation is
      tested; outputs carry the claim product and the no-authorization flags; `CONTRACT.md` names the verb,
      INV-NEMESIS-04 and PO-NEMESIS-01.

## Test plan

### Unit tests
`crates/frob-nemesis/tests/shrink_pipeline.rs` (real pipeline on the CPU reference tier; small fixtures):
- `unpromoted_failure_is_guarded_and_classified_first`; `artifact_candidate_refused_564`;
  `replay_mismatch_refused_564` (one bit of a recorded digest altered).
- `no_witness_is_not_shrunk`: a doorway trap (body 0.75 m, door 0.70 m) → `not-shrunk`, no file.
- `two_edit_fixture_end_to_end`: seven edits of which the grease film and the closer torque (14 → 19 N·m) are
  the cause → the file lists exactly those two, two passing neighbours, `1-minimal`, `pairs_exhausted: true`.
- `shrunk_world_repromoted_and_rewitnessed`: the result's promotion and oracle blocks refer to the shrunk
  world's identity, not the original's.
- `witness_lost_resumes_and_labels`: a fixture in which edit 4 widens a door that the witness needs; the subset
  without edit 4 is marked `Inadmissible(witness-lost)` and the final world contains edit 4.
- `file_written_only_if_replays` (replay check forced to fail by a planted digest fault).
- `episode_accounting`: 37 tests → 2,368 episodes; cache hits cost none.
- `budget_stop_returns_non_minimal`; `resume_by_key_reruns_nothing`; `cancel_drains_and_finalizes`.
- `separate_finding_enters_campaign`; `base_fails_zero_edit_result`; `exit_codes` (2, 3 for 564 and 360, 5 for
  840, 4, 8).
- `gate_measurements_recorded`: on the two-edit fixture and on a seed-fragile fixture, the per-shrink record
  holds edits before and after, tests, seeds failing, label, whether the written file replays and the stop
  reason (item 8), with the values of the result.
- `out_through_export_door` (scenes and assets labelled `synthetic`): the two-edit fixture without `--out` is a
  stored artifact with no `path`, from a session without `export:report`; with `--out <export root>/m` and the
  scope, the file and its manifest are written and `mcw.path` names them; on a world derived from a private
  scene, without `private:export` → 731; on a world whose scene holds a `research-only` asset → 733 with a
  `via` path ending at that asset; from a session without `export:report` → 720; `--out /etc` → 734; a planted
  writer fault that drops the authorization block from the manifest before `admit` → 816. In every refused
  case nothing is written outside the store, the exit is the door's (3 for 816, 5 for the others), and the
  stored artifact is still readable through `artifact.read`; a private-and-research-only world without scopes
  is refused with 731, the door's first applicable check.
- `mode_dispatch`: the same 7-edit fixture under `nemesis.shrink.mode = minimal` gives the 2-edit `1-minimal`
  file; under `contrasts` it gives the 7-edit file labelled `non-minimal(7)` with `one_minimal_verified: false`,
  the ranked contrasts (the two cause edits first) and exactly 7 tests beyond the cached full set, and the file
  passes N26a-19's reader; switching the mode changes no other field of the result's promotion or oracle blocks.

### End-to-end script and logging
`scripts/e2e/nemesis_shrink.sh` (bead N26a-34) drives `frob nemesis shrink` on 100 planted-cause trials and on
unplanted failures, replays every file with `frob sim replay`, and writes the receipt from which the gate is
recorded; `scripts/e2e/nemesis_loop.sh` (bead N26a-20) runs search, oracle, guard, shrink and the hard-world set
in sequence. Logged per
shrink, in the structured log of the shared helper: edits before and after, each test in order (subset, k of 64,
cache hit), bisection steps, pair-check count, the re-promotion and re-witness outcomes, the label, the file's
world identity and content hash, and the digest comparison.

### Known answers and negative controls
KA-663 (planted causes of size 1, 2 and 3 among 8 to 32 edits: the planted set exactly; control: with edits
listed (a, c, d, e, b) and failure when {a, b} or {c, d, e} is present, the result is {c, d, e} before the pair
check and {a, b} after it). KA-142 (eight edits, failure exactly when 3 and 6 are present: {3, 6}; non-monotone
control: a grease patch fails the design and a rug over it masks it, so {1} fails and {1, 2} passes, and the
result {1} is not described as a distance). KA-144 (a stored `.fmcw` reproduces its state hash). CX-288, CX-067.
INV-NEMESIS-04 and PO-NEMESIS-01 are asserted on every written file (replay; every single removal passes).
Metamorphic relation: removing any edit of a 1-minimal world removes the failure. Planted defects: a pipeline
that copies the original world's witness onto the shrunk world (`witness_lost…` must fail); a writer that skips
the replay check. Determinism lanes: a shrink run twice on one machine, and across worker counts, gives the same
trace, result and file bytes.

## Considerations

- The size TARGET (at most three atomic edits) is an aspiration about worlds; the algorithm cannot force it. A
  shrunk world with more is kept and labelled `non-minimal(k)`.
- Cost: a few hundred tests of 64 episodes; of the order of 10⁴ episodes per shrink on the fast tier.
- The result depends on the order of the edit list; the canonical order makes it reproducible, and the pair
  check removes the dependence only for causes of size one or two.
- A failure without a witness has no refusal code of its own in the plan; `not-shrunk` is a completed result,
  flagged for the owner of the refusal registry (see the registry bead N26-REF).
- If KILL-NEMESIS fires, shrinking is kept and applied to failures that card randomization finds.
