## Background

After a failure, the question an agent needs answered is: which repair edit should I try first? The system
answers it with a small decision procedure, registered as decision core **DC-06** (decision: which cause, and
which repair edit, ranks first after a failure; family: counterfactual forks with a placebo; owner: the Autopsy
crate; timescale: per failure cluster; tier: Solid). Its full statement:

```text
Decision:          Which repair edit should the agent try first for this failure?
States:            The failure has a single removable cause, a joint cause, or none that can be attributed.
Actions:           Buy a fork, name a factor or a set, or decline.
Loss:              Naming a wrong cause sends an agent to edit the wrong thing, which costs a design iteration
                   and its compute; declining costs one fallback to the heuristic ordering.
Artifacts:         Typed interventions; a fork ledger; the placebo flip rate; a rescue rate per factor and
                   per pair; minimal repair sets; one label per factor and per failure.
Obligations:       The empty intervention replays the failure bit for bit, so the starting point is exact.
                   Each intervention changes one declared mechanism (model difference on file).
                   A cause is named only when its contrast beats the placebo under a test at a stated level.
Failure modes:     Chaos makes every nudge look like a cause. The cause precedes the snapshot.
                   The failure does not survive double precision.
Fallback:          The first-anomaly ordering of the telemetry subsystem, labelled Estimated.
Fallback trigger:  Null-replay mismatch; placebo flip rate above 0.2; failed equivalence in double precision.
Budgeted mode:     12 factors, singles and pairs, 8 replicates, 64 placebo forks: 689 forks. A Shapley
                   summary only if no single and no pair changes the outcome.
Baseline:          The heuristic ordering; and one-at-a-time contrasts without coalitions, to measure
                   whether ten forks answer as well as seven hundred.
Rollback:          A configuration flag to the heuristic; recorded forks remain valid experiments.
Verification:      Planted single and joint causes; a planted chaotic failure; the thermal counterexample.
```

The loss model is asymmetric on purpose: naming a cause in a chaotic regime sends the agent after noise, which
costs more than saying nothing. So the decision model's most important property is the one this bead holds it
to: **when nothing can be attributed, it names nothing.** That is invariant INV-AUTOPSY-05 (a factor is named
only when its contrast is tested above the placebo at a stated level and the placebo flip rate is at most 0.2)
and the chapter's stated limits: not an answer in chaotic regimes (above the placebo threshold nothing is
attributed), and not beyond the factor list (a failure whose cause is not among the declared factors yields no
named factor).

The governing decision is **ADR-AUTOPSY-01: a cause is what an intervention removes, net of a placebo.** A factor
is named only when removing it prevents the failure more often than an irrelevant perturbation does.

The rejected alternatives, on record: an attribution that always returns its best guess (it converts every
chaotic failure into a wrong repair); a score without a placebo (in a chaotic system any touch changes some
outcomes, and the placebo measures that floor); observational causal adjustment (exact intervention is
available, so it is not needed).

The decision procedure itself (its stage machine, constants, compiled table, rollback flag, baselines and
evidence records) is the policy bead N27b-12. This bead is the decision model's **abstention contract and its
gate**: the precise statement of when the model must decline or fall back, the verification that it does so on
planted failures in 100 of 100, and the verification that it does not buy that record by declining everything.

## Scope

In: the abstention contract (the three fallback triggers and the two decline outcomes, as observable behaviour
of the policy); the measurement of GATE-AUTOPSY-05 on the planted sets, with its gate record; the non-abstention
controls; the three fallback triggers forced on real forks; the property test of INV-AUTOPSY-05 over the whole
pipeline, from the fork point to the decision; the abstention entries of DC-06's registry record (the replay
cases and the demonstration commands of step 6), added to the record that N27b-12 writes.
Out: the policy itself, which is N27b-12: the stage machine and its constants, the compiled guard table, the
rollback flag, the two baseline arms and shadow mode, the evidence record per decision, the file
`registries/cores/dc-06.toml`, and the unit tests of each stage transition and each trigger on scripted counts;
statistics and labels (N27b-05, N27b-06); the precision routing and FROB-REF-584 (N27b-07); coalitions and the
summary (BD-281); the planted cases (N27a-14); the end-to-end script (N27a-18); registry-wide checks of all
decision cores (BD-349, BD-350).

This seed bead is the capstone of the decision model. It depends on the policy N27b-12 and on the planted
abstention cases N27a-14, and it closes when the policy's `Decline` and `Fallback` paths pass GATE-AUTOPSY-05 on
those cases and answer the 30 controls. Neither component depends on this bead.

## Technical approach

1. **The abstention contract.** For one failing world and a declared factor list, the model's terminal outcome
   is one of: a factor named; a set named; declined; fell back. The following must hold.

   | Situation | Required behaviour | How it is delivered |
   |---|---|---|
   | The null fork does not reproduce its parent | Nothing is attributed. Fallback | Refusal FROB-REF-583 (the record is unsound), exit 3, with the heuristic ordering offered as the first repair |
   | The failure is not reproduced in double precision and is not admitted to the single-precision lane | Nothing is attributed. Fallback | Label `precision-sensitive`; refusal FROB-REF-584; the world is passed to the artifact guard |
   | The placebo flip rate ρ₀ is above 0.2 (in integers: 5 × flips > placebo forks; 13 of 64 is above, 12 of 64 is not) | No factor is named, whatever the contrasts show. Decline | A completed result (exit 2) with outcome `chaotic: unattributable`, every factor `none`, the measured contrasts still printed, and the heuristic ordering attached, labelled `Estimated` |
   | No declared factor and no declared pair rescues | No factor is named. Decline | A completed result with outcome `none`; a Shapley summary may be attached as a description and names nothing |
   | A factor's contrast is positive but not tested above the placebo at its level | That factor is not named | Its label is `none` |

   "Named" means: appears with a label other than `none`, or as `top_factor`, or in `named_set`, or as the first
   `next_action`'s repair edit. The gate reads all four places.
2. **What the fallback is.** The first-anomaly ordering: monitors timestamp their first anomaly, and the earliest
   anomaly before the terminal event is listed first. It is a description, labelled `Estimated`, and it is what
   `frob explain run` already prints. A fallback never borrows the vocabulary of a cause: its text says "first
   anomaly", not "cause".
3. **Gate measurement (GATE-AUTOPSY-05).** On the registry of planted abstention cases:
   - 100 chaotic cases (50 on the host doubling map with failure on the fortieth iterate, 50 simulated with the
     amplifier probe) plus the referee knife-edge fixture: required outcome `chaotic: unattributable` and nothing
     named, in 100 of 100;
   - 100 no-cause cases (a failure planted through a factor outside the ten declared): required outcome `none`
     and nothing named, in 100 of 100;
   - 30 controls whose right answer is a named factor (the five-iterate map with a real factor; no-cause cases
     with the planted factor added to the list; a standing robot that fails a stance-height requirement through
     a declared knee torque cap): required: the factor is named `but-for` in all three kinds, with ρ₀ = 0 on the
     five-iterate map and the standing robot. A model that abstains on a control fails the bead.
   Each case runs the full path from the user's side of the library: fork point, null fork, 64 placebo forks,
   singles and pairs with 8 replicates, the labels, the decision. Tier: the CPU tier in double precision for
   simulated cases; host for the map.
4. **Forced triggers.** The policy bead N27b-12 tests each trigger on scripted counts; here three further tests
   force each fallback trigger on real forks and check its delivery from the user's side of the library: a checkpoint
   with one flipped bit (null-replay mismatch); a planted marginal failure that falls in single precision and not
   in double precision, with the lane disabled (precision); a chaotic case (placebo). After each, the stored
   evidence record of the decision names the trigger.
5. **INV-AUTOPSY-05 over the pipeline.** A property test generates count tables (placebo flips f of 64; per
   factor rescued k of 8 and flips) across the whole range, runs labels and decision, and asserts: named ⇒
   (tested above the placebo at the stated level) ∧ (5·f ≤ 64). It also asserts the converse failure cases:
   with f = 13 nothing is named even when one factor has 8 of 8.
6. **DC-06's registry record, the parts this bead adds.** The file `registries/cores/dc-06.toml` is written by
   N27b-12 (decision, table with version and hash, loss ordering, obligations INV-AUTOPSY-01, -02, -05 and
   PO-AUTOPSY-01, the fallback with its three triggers as above, the budgeted mode, the adoption status). This
   bead adds to that record: the decline outcomes as replay cases (one chaotic host case, one no-cause case, one
   bit-flipped checkpoint, each with its expected terminal outcome), which complete N27b-12's replay scenario of
   one planted failure per terminal action; and the demonstration commands for abstention, which run in under
   60 s on the host cases.
7. **Record.** Gate row with: chaotic cases correct of 100 with the distribution of measured ρ₀; no-cause cases
   correct of 100 with the largest single and pair contrast seen; controls correct of 30; the three forced
   triggers; commit, fingerprint, seeds. The crate test measures and writes no gate status; the row is entered
   by N27a-18, the gate's one recorder, from the receipt of the gate's tier run, by a session that did not
   implement the decision model. The three attributors of "Known answers and negative controls" below (largest
   contrast regardless of ρ₀; nearest declared factor; always decline) are the gate's registered controls,
   records of kind `mutation` in `crates/frob-conformance/registry/controls.toml` naming GATE-AUTOPSY-05, each a
   `cfg(feature = …)` branch in `frob-autopsy`'s decision code: the first under the feature
   `autopsy-no-placebo` (it subtracts no placebo; the same feature is the plant `BD-282:autopsy-no-placebo` of
   CX-300, N27-CX), the other two under `nc-<nnnn>`. This bead registers them, and the tier run plants them.

## Acceptance criteria

- [ ] Seed done-condition, GATE-AUTOPSY-05 (TARGET), met in this bead's measurement: `gate_autopsy_05` prints
      measured counts in which a planted chaotic failure and a planted no-cause failure name no factor in 100 of
      100 (100 of 100 for each kind), with the three registered controls of step 7 failing it. The gate row is
      recorded after this bead closes by its one recorder, N27a-18 (which depends on this bead), from the
      receipt of the tier entry `GATE-AUTOPSY-05` of `g1_known_answers`.
- [ ] The knife-edge fixture on the referee reports `chaotic: unattributable`.
- [ ] All 30 controls are answered without abstention: the real factor is `but-for` on the 20 in-list and
      five-iterate controls, and the torque cap is `but-for` with ρ₀ = 0 on the 10 standing-robot controls.
- [ ] Each forced trigger delivers its fallback in the stated form (FROB-REF-583; FROB-REF-584 with the label
      `precision-sensitive`; a `chaotic: unattributable` result with the ordering attached) and the decision's
      evidence record names the trigger.
- [ ] Boundary: 12 placebo flips of 64 does not trigger abstention and 13 does.
- [ ] On a chaotic case in which a declared factor shows 8 of 8 rescued, that factor is still not named in any
      of the four places a name can appear.
- [ ] The fallback text contains no cause vocabulary and carries the label `Estimated`.
- [ ] DC-06's registry record validates under the decision-core contract check, and its abstention
      demonstration runs in under 60 s.

## Test plan

### Unit tests
`crates/frob-autopsy/tests/abstention.rs` (the real statistics, labels and decision code; counts from recorded
or `synthetic` ledgers):
- `chaos_boundary_12_13`: f = 12 of 64 proceeds to the singles; f = 13 declines.
- `chaotic_with_perfect_rescue_names_nothing`: f = 30 of 64; one factor 8 of 8; outcome `chaotic:
  unattributable`; `top_factor` absent; `named_set` empty; the first next action is not a repair edit.
- `no_cause_names_nothing`: f = 0; ten factors each 0 of 8; 45 pairs each 0 of 8; outcome `none`.
- `untested_contrast_not_named`: f = 12 of 64 (ρ₀ = 0.1875), one factor 5 of 8 among 12 factors: contrast
  0.4375, exact one-sided p = 0.0152, above the level 1/240 = 0.00417: label `none`. With 6 of 8 the same table
  gives p = 0.00237, which is tested, and the factor is named: the two cases bracket the rule.
- `inv_autopsy_05_property` (10⁴ generated tables).
- `forced_null_mismatch`, `forced_precision`, `forced_placebo`: delivery and evidence record.
- `fallback_text_has_no_cause_words`.
- `gate_autopsy_05` (the planted registry, real forks): the three counts printed against 100, 100 and 30.

### End-to-end script and logging
`scripts/e2e/autopsy_coalitions_abstention.sh` (N27a-18) runs `frob run fork`, `frob autopsy intervene` and
`frob autopsy attribute` on the abstention registry and logs per case: kind, ρ₀ with its counts, the outcome
label against the expected one, every place a name could appear, the refusal block where one is expected, and
the fallback block.

### Known answers and negative controls
KA-672 (doubling map with failure on the fortieth iterate: a 10⁻¹² placebo amplified by 2⁴⁰ ≈ 1.1 × 10¹², about
half of placebo forks flip, label `chaotic: unattributable`; control: the same map over five iterates attributes
normally). KA-147 (a fixture where every nudge flips the outcome). KA-670's control (a failure planted through a
factor outside the list names no factor). The flip threshold arithmetic: of 200 failing worlds with a placebo in
30 and nominal friction in 38, the exact one-sided test gives p = 0.176 and nothing is attributed. CX-300,
CX-070. Negative controls registered for the gate, each of which must make it fail: an attributor that names
the largest contrast regardless of ρ₀ (fails the chaotic set); one that names the nearest declared factor when
none rescues (fails the no-cause set); one that always declines (fails the controls). Determinism lanes: the
gate test twice on one machine with identical outcomes and counts; across worker counts; each case alone and
batched with others.

## Considerations

- RISK-50: attribution names a cause where none is stable (likelihood medium; indicator: the placebo flip rate
  on reference failures; controls: this gate, double precision, the kill gate; owner: Autopsy lead). The falsifier
  of the bet behind the subsystem includes "the placebo flip rate exceeds 0.2 on more than half of the reference
  failures, so that most are unattributable". That share is not measured on the planted sets of this gate (their
  chaotic cases are chaotic by construction): it is measured on the 1,000 recorded failing worlds of the
  null-fork population by the script of N27b-04 (`share_rho0_above_0.2`, from the null and placebo forks
  alone), and the kill decision (N27b-11) and the bet's decision (BET-23) read it there. This bead's record
  reports beside its gate figures the share of the 30 controls that were answered, which is the other side of
  the same risk.
- The 0.2 threshold is a TARGET, and the level is a stated default; both are constants of the decision policy,
  and changing either is a new version of the policy with the gate re-run.
- Abstention has a cost the gate does not measure: an attributor that abstains on real, attributable failures
  is useless. The planted single-cause gate measures that side (the planted factor first in at least 90%).
- If the subsystem's kill gate fires, the fallback of the whole subsystem is single-factor paired re-runs from
  the episode start with the first-anomaly ordering; abstention then applies to those re-runs unchanged.
