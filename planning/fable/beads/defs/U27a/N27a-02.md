## Background

Restoring a mid-episode state and then changing the robot can produce a trajectory of no design. A snapshot of a
quadruped one second before a thermal trip holds winding temperatures, contact warm starts, filter states and a
policy's hidden state that were all produced by the old design. Apply a new gear ratio to that state and the run
that follows answers a question nobody asked. The system therefore decides whether a change may be applied at a
mid-episode state from the model difference the change makes, before any state is touched.

Two decisions say the same thing from two chapters and both bind this bead. **ADR-AUTOPSY-02: classify a fork
before restoring state.** **ADR-CHRON-06: a fork is classified before any state is restored**, with the reason
that restoring first and discovering later that the change invalidated the restored state produces a trajectory
of no design. The rejected alternative is the obvious one: restore, apply, run, and warn afterwards.

The classification is the **intervention semantics** and the Autopsy chapter owns it; the fork mechanism in
`frob-chronicle` implements exactly these five classes and adds none. This bead is that implementation's
decision procedure: a pure function from a request and manifests to a class, an earliest valid fork tick and the
list of checkpoint fields that forced that tick. Tier: Solid.

Terms. A **checkpoint** is a complete stored state of one world at a committed tick: physical state; contact
feature memory and impulses and solver warm starts; clock phases and packet queues with their packets;
controller, filter and policy hidden states; actuator electrical and thermal states; scene state the robot can
change; the command cursor. Random streams are counter-based and keyed by address, so they have no state.
**Contact memory** is the per-contact data carried from one step to the next. A **contract** is the identity a
checkpoint was produced under: physical (model and step plan), clock, sensor and policy.

## Scope

In: the rule table, the dependency sets, the algorithm, the refusals FROB-REF-580, -581 and -582 as the

## Technical approach

**The five classes (the specification).**

| Class | What changes | Where it may start | State handling |
|---|---|---|---|
| Continuation | Nothing (the null fork), or a placebo | Any checkpoint whose physical, clock, sensor and policy contracts match the run | Restored bit for bit |
| Exogenous intervention | A future disturbance, a setpoint, a scene property the robot has not yet touched or sensed | The fork tick, which is no later than the first tick at which recorded state depends on a changed field | Restored; nothing regenerated; exogenous draws by address |
| Contact-affecting intervention | Friction or compliance of a surface in contact at the fork tick; the contact law | The fork tick | Positions and velocities restored; contact memory discarded and the first solve run cold with a raised iteration cap; the fork is labelled |
| Information intervention | Sensor noise or latency; an estimator replaced by privileged state | The fork tick | Packet queues and filter state re-initialized as the intervention states; labelled diagnostic where no hardware could realize it |
| Structural or design-parameter intervention | Mass, inertia, geometry, a gear ratio, an actuator card, a sensor mount, controller gains or memory, policy weights | The authored initial condition only | The edited design is settled from its own reset cache; paired exogenous draws are reused; contact memory, proprioception, sensor histories and policy actions are regenerated |

**The principle behind the table (DESIGN).** Every changeable field has a *dependency set*: the checkpoint
fields whose content was produced from it. A dependency is *live* at tick t if that checkpoint field is non-empty
and was written under the old value. The class is decided by what is live:

| Live dependent checkpoint fields | Class |
|---|---|
| None, and no recorded state depends on the changed field at any tick ≤ t | Exogenous |
| Only contact feature memory, contact impulses, solver warm starts (state a cold solve regenerates) | Contact-affecting |
| Only packet queues, filter and estimator state (state the intervention itself re-states) | Information |
| Anything that carries history with no canonical image under the change: actuator thermal or electrical state, battery state of charge, wear, estimator bias learned on the old body, a policy's hidden state and action history, proprioception histories, the settled pose | Structural |

The field registry `registries/fork-fields.toml` (DESIGN) holds, for each changeable field pattern, its mechanism
kind and its dependency set. It is data, validated by the contract check, and the rule table above is its
schema. Mechanism kinds and their rows:

| Mechanism kind | Examples | Dependency set |
|---|---|---|
| `none` | empty change set; a placebo perturbation | — |
| `command` | a setpoint, a future waypoint, the command cursor's future entries | — |
| `disturbance` | a push scheduled at a time ≥ t; removal of one | — (a disturbance already applied is not changeable at t) |
| `scene-surface` | friction, compliance, film, restitution of a surface or patch | contact memory, impulses and warm starts of contacts on that surface; film or wear state on it |
| `contact-law` | the world's contact law (the default convex compliant law against the alternative) | all contact memory, impulses and warm starts |
| `scene-fixture` | a door-closer torque, a conveyor speed | the fixture's own state once the robot has touched it |
| `scene-optics` | a light, a glass panel, a reflectance | packet queues and filter state once a sensor has sampled the region |
| `sensor-link` | noise scale, latency, jitter, dropout, quantization | packet queues, filter state |
| `estimator` | the estimator replaced by privileged state | filter state |
| `actuator-limit` | a joint's torque limit switched off or given a value at the fork tick: `model.joint[<sel>].torque_limit := off`, `:= <torque>`, `:= nominal` (the diagnostic factors `torque-limit-off` and `torque-limit-set` of the intervention vocabulary, N27b-01) | — (the winding temperature, the currents and the trajectory are those of the same motor and transmission; nothing in the checkpoint has to be regenerated) |
| `design` | any typed design edit: mass, inertia, geometry, gear ratio, actuator card (including the card's own limit fields, reached by `set-param` on the card or `swap-actuator`), sensor mount, a payload's mass or fill | everything except exogenous draws |
| `controller` | controller gains or memory, policy weights | controller, filter and policy state, action history, and through them everything else |

**Algorithm `classify(request) → Vec<Classified>`.**

1. *Licence.* Read the parent's determinism class from its record. Below class D2 (bitwise per backend, with the
   batch-independence gate current) the request is refused by the numerics licence with FROB-REF-562; this bead
   calls that check and adds nothing to it.
2. *Resolve the tick.* `at` is a tick, or "before failure by lead Δ": the failure tick minus Δ, snapped to the
   committed tick at or before it (N27a-03).
3. *Resolve each change* against the field registry to a mechanism kind. Compute its model difference by a
   scratch compile through the memoized pipeline (design edits return their invalidation set; scene, task and
   sensor fields return the changed compiled products). `model_diff` is the hash of that difference record. No
   world state is read.
4. *Continuation.* For the empty set or a perturbation-only request, compare the four contracts of the
   checkpoint with the run: physical (`ModelId`, step-plan identity), clock (clock plan and the presence of
   every phase accumulator), sensor (sensor binding and the presence of every packet queue with its packets),
   policy (controller or policy identity and the presence of its hidden state). A missing field or an unequal
   identity is refused with FROB-REF-580: `pointer` is the checkpoint and `observed` names the contract at
   fault with its two identities, or the missing field (the shapes of the registry row, N27-REF; for 581 the
   pointer is the `do` string, for 582 the change set). A request to restore under another
   numerical profile and call it a continuation is Chronicle's FROB-REF-894 (repair: ask for a comparison replay).
5. *First dependence.* For `scene-*` and `actuator-limit` kinds, read from the recorded T1 events the first tick
   t_d at which recorded state depends on the changed field: the first contact event on the surface or fixture,
   the first sensor sample whose frustum or ray set reached the optical region, the first saturation event of the
   limit on a selected joint. If the channel needed is not retained, t_d is taken as 0 (fail closed) and
   `forced_by` says `undecidable: channel not retained`.
6. *Assign the class* by the liveness table. Details:
   - `command` → Exogenous. `disturbance` scheduled at a time ≥ t (added, changed or removed) → Exogenous. A
     disturbance that was already applied before t is part of the recorded prefix: the request is FROB-REF-582
     with the earliest valid tick set to the last committed tick before the disturbance.
   - `scene-fixture`, not yet touched → Exogenous. Touched at some t_d ≤ t → ContactAffecting with the label
     `InterventionFromTick` and `exogenous_until = t_d`; the fixture's own position and velocity are physical
     state and are restored, and contact memory with the fixture is discarded if the robot touches it at t.
   - `scene-surface`, no t_d or t_d > t → Exogenous.
   - `scene-surface`, the surface in contact at t → ContactAffecting, `forced_by` = the live contact fields,
     labels `ContactMemoryDiscarded`, `ColdFirstSolve`.
   - `scene-surface`, t_d ≤ t and not in contact at t → ContactAffecting with the label `InterventionFromTick`
     and `exogenous_until = t_d`: the child is the parent's world changed from tick t on, not a world in which
     the surface was always different; a caller who wants the second forks at or before t_d.
   - `contact-law` → as a change to every surface at once: with any contact active at t, ContactAffecting with
     `forced_by` = all contact memory, impulses and warm starts and the labels `ContactMemoryDiscarded`,
     `ColdFirstSolve`; with no contact at t and none before, Exogenous; with no contact at t but contacts
     earlier, ContactAffecting with `InterventionFromTick` and `exogenous_until` = the first contact tick.
   - `scene-optics`, no t_d or t_d > t → Exogenous.
   - `scene-optics` with t_d ≤ t → Information, labelled, with `exogenous_until = t_d`.
   - `sensor-link` → Information with `forced_by` = the link's packet queues and the filter state fed by it;
     `estimator` → Information with `forced_by` = the filter state. Both carry the `Diagnostic` label where no
     hardware could realize the change (privileged state, zero latency, zero noise).
   - `actuator-limit` → Exogenous at the requested tick with `forced_by` empty and, always, the labels
     `InterventionFromTick` and `Diagnostic`: the whole checkpoint is restored and the limit row takes its new
     value from the fork tick on. `exogenous_until` = t_d when the limit saturated at some t_d ≤ t, absent
     otherwise. DESIGN, with its reason: the plan runs `torque_limit := off` from a mid-episode fork as a
     diagnostic (ADR-AUTOPSY-06; the time-travel session attributes it at the fork tick), and the torque-cap
     class of the planted-cause known answer is rescued by `torque_limit := nominal` from a fork; under `design`
     either would be structural and refused (FROB-REF-581) at every mid-episode tick. The label `Diagnostic` is
     unconditional because no hardware changes its limit at tick t of an episode already lived; the buildable
     form of the change is the typed design edit on the actuator card, which stays `design` (structural) and is
     tested from the episode start (BD-283).
   - `design`, `controller` → Structural with `earliest_valid_tick = 0` and `forced_by` = the live members of the
     dependency set, in one fixed order that covers every history-carrying checkpoint field: payload state (mass
     and slosh), actuator thermal
     state, actuator electrical state, battery state, wear state, controller state, policy history (hidden state
     and action history), filter state (with any estimator bias), packet queues, contact memory (feature memory,
     impulses, warm starts), proprioception history, sensor histories, settled pose. Only fields the checkpoint
     holds are listed (a design with no battery model lists no battery state), so the list is a pure function of
     the change and the checkpoint manifest.
7. *Refusals raised here.*

   | Code | Trigger in the classifier | Returned with it | Ranked repairs | Exit |
   |---|---|---|---|---|
   | FROB-REF-580 | A continuation whose physical, clock, sensor or policy contract does not match the checkpoint, or a checkpoint missing a contract field (a stripped packet queue) | The contract and field at fault | Fork from the nearest snapshot whose four contracts match (the refusal names it); reconstruct the fork point by replay from the world address to the tick; if the contract was changed on purpose, declare the change as an intervention in the change set, which is then classified, or ask for a comparison replay (the order of the registry row, N27-REF) | 3 |
   | FROB-REF-581 | A structural or design-parameter change requested at a tick > 0 without the diagnostic mode | `earliest_valid_fork_tick: 0` and the forcing fields | `autopsy.rerun` with the edit from the episode start; fork at the earliest valid tick returned; the labelled diagnostic forced fork where admitted (the order of the registry row, N27-REF) | 3 |
   | FROB-REF-582 | State from one model grafted onto another: the request asks to reuse a checkpoint field its change set invalidates (a field named in the request's `reuse` list, `--reuse <field>` on the verb, that the change set invalidates; or a checkpoint taken from a run whose `ModelId` differs from the child's) | The earliest valid tick and the field that forces the restart (for the wheel graft: the contact memory) | Fork at the earliest valid tick returned; or restart and settle | 3 |

   With `classify_only` a structural change at a mid-episode tick is not an error: it is returned as
   `structural` with `earliest_valid_tick: 0` and its `forced_by`, and the verb exits 0. Without it the same
   request is FROB-REF-581.
8. *Result.* One `Classified` per change, plus the class of the set (the maximum) and the union of the forcing
   fields. The function is pure and of determinism class D0: it reads manifests, identities, digests and event
   indices, never state values, and returns the same bytes for the same inputs on every platform.

Module: `crates/frob-chronicle/src/fork/classify.rs`; registry loader in `fork/fields.rs`.

## Acceptance criteria

- [ ] `classify` restores nothing: a test instruments the snapshot store and asserts zero state reads during
      classification of every catalogue case.
- [ ] The rule table: each mechanism kind maps to the class stated; the liveness rows hold on constructed
      checkpoints (surface untouched, in contact, touched earlier).
- [ ] The mid-episode gear change returns `structural`, `earliest_valid_tick` 0 and `forced_by` containing the
      actuator thermal state, the policy history and the contact memory; without `classify_only` it is
      FROB-REF-581 carrying the same fields.
- [ ] The warm-start graft (the contact warm start of the 60 mm wheel offered to the 75 mm design at the lip) is
      FROB-REF-582 naming the contact memory.
- [ ] A checkpoint with its packet queue stripped is FROB-REF-580 with `pointer` the checkpoint and `observed`
      naming the sensor contract and the missing queue.
- [ ] A request whose first-dependence channel is not retained classifies fail-closed (tick 0 for the exogenous
      reading) and says so.
- [ ] `model.joint[*.knee].torque_limit := off` and `:= nominal` at a mid-episode tick are `exogenous` with the
      labels `intervention-from-tick` and `diagnostic` and an empty `forced_by` (never FROB-REF-581); the same
      limit changed by a typed design edit on the actuator card is `structural`.
- [ ] Every refusal carries `code`, `pointer`, `observed`, `required`, `retry: after-change` and ranked repairs.
- [ ] GATE-AUTOPSY-02 and GATE-CHRON-05 are measured against this function by N27a-07.

### Known answers and negative controls
KA-676 (warm-start graft across a design edit: refused with FROB-REF-582, exact verdict, host tier) and KA-716
(fork: the 60 mm warm start grafted onto the 75 mm wheel must fail). CX-321: "graft a warm start across a design

debug and release, and on both operating systems.

## Considerations

- The plan describes the exogenous class by "not yet touched" and the contact-affecting class by "in contact at
  the fork tick" and does not say what a surface touched earlier and not in contact now is. This bead classifies
  it as contact-affecting with the `InterventionFromTick` label and reports `exogenous_until`, because recorded
  state already depends on the field, so the unlabelled exogenous reading would be false.
- FROB-REF-581 and FROB-REF-582 can both describe a wheel-radius change at a lip. The split used here: 581 is the
  plain request to apply a design change mid-episode; 582 is a request that carries or names state across models.
- A registry row with too small a dependency set would let an invalid fork run. The catalogue (N27a-07) pins 41
  cases (the gate's 40 and the `actuator-limit` row E9), and any new changeable field must add a row and a
  catalogue case in the same change.
- Classification cost is a scratch compile per distinct change; the memoized compile makes repeats free.
