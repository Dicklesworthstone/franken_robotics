## Background

For a fork to mean anything, three things about the child must be exact.

**It has its own identity.** DESIGN: a child world has the address of its parent extended by a fork path. Every
artifact the system keeps (telemetry chunks, digests, verdicts) is keyed by address, so a child needs one that is
not its parent's.

**It does not disturb its parent.** A child shares its prefix with the parent by reference, and a fork never
mutates its parent (**INV-AUTOPSY-04: a fork never mutates its parent; a child has its own address and shares the
prefix by reference**). An attribution is a set of experiments on a recorded failure; if making the experiments
could change the record, nothing downstream would be evidence.

**The intervention is the only difference.** Random draws in this system are counter-based and keyed by logical
identity, `(WorldAddr, step, stream_id)`, built on Philox streams; there is no generator state. DESIGN: by default
a child reads the same streams as its parent, so that the intervention is the only difference between them. A
*replicate* changes one declared thing more: a state perturbation of stated size, or the key of one named stream.

The two uses of forks want opposite defaults, which is why the mode is explicit. Counterfactual debugging wants
identical streams, so a rescue cannot be an accident of different noise. Rare-event splitting wants fresh noise
after the fork, because a child that shares every stream replays its parent bit for bit and adds nothing; there
the per-step disturbance streams after the fork tick are re-keyed by the child address, which is the replicate
mode of this bead. Tier: Solid.

## Scope

In: derivation of child addresses and fork identities; how a child's artifacts are stored against the parent's
prefix; the write barrier that enforces INV-AUTOPSY-04; the three stream modes and the key derivation; duplicate-
child detection.
Out: the types themselves (N27a-01); perturbation sizes and the placebo's meaning (BD-279 and the perturbation
library in `frob-autopsy`); the copy of state into child slots (BD-205); batch independence as a measured gate
(N27a-06).

## Technical approach

1. **Fork identity.** `ForkId = BLAKE3("frob.fork/1" ‖ parent EpisodeId ‖ canonical WorldAddr ‖ fork tick ‖
   contract identities of the checkpoint)`. Two requests for the same world and tick of the same run give the
   same `ForkId`; the fork point is created once and found again (idempotent).
2. **Child address.** `ChildAddr = (parent WorldAddr, parent path ⧺ [(ForkId, ChildKey)])`. The child key is
   the hash of the child's own specification: the hash of its change set, its series tag (`null`, `placebo` or
   `replicate`, with the perturbation size), its perturbation record itself (coordinate, relative size and
   sign, or the re-keyed stream), its replicate index and its stream mode. Two specifications that differ in
   any of these, the perturbation included, get different keys. It depends on nothing
   else: not on arrival, slot or which siblings were requested with it. The same child requested alone and
   among 511 others therefore has the same address, the same stream keys and (by batch independence) the same
   digests. Callers above this layer choose the series tags and indices; this layer only hashes them.
3. **Prefix by reference.** A child's episode record holds no copy of ticks before the fork tick. Its manifest
   carries `prefix: { parent, through_tick, chain_digest }`, and readers resolve ticks before the fork tick to
   the parent's committed chunks. The child's own chunks start at the fork tick, and its digest chain is seeded
   with the parent's chain value at the fork tick: c_t(child) = H(c_{t−1}, d_t) with c_{fork−1}(child) =
   c_{fork−1}(parent). A child whose change set is empty therefore reproduces the parent's chain values exactly,
   which is how the null fork is compared.
4. **Write barrier.** The child writes only under keys that contain its `ChildAddr`. The chunk store refuses a
   write under a parent key from a fork job (the parent's keys already map to content hashes; a different byte
   string for a committed chunk key is a determinism violation and stops the run). The device path copies state
   out of the snapshot or ring into free slots and never steps the parent's slot.
5. **Stream modes** (per child, recorded in its manifest):

   | Mode | Stream keys of the child | Use |
   |---|---|---|
   | `shared` (default) | Every stream is keyed by the *parent's* `WorldAddr`: the fork path is not mixed in | The null fork, placebo forks, interventions and their replicates: the intervention and the stated perturbation are the only differences |
   | `rekey(stream_id)` | The named stream is keyed by the child's full `ChildAddr` from the fork tick on; all others stay shared | A replicate that changes the key of one named stream |
   | `rekey-disturbances` | All per-step disturbance streams are keyed by `ChildAddr` from the fork tick on | Splitting, which needs fresh per-step noise in every child |

   Key derivation for a re-keyed stream: `Philox(key = H(run_seed, ChildAddr bytes), counter = (step,
   stream_id))`. Draws before the fork tick are never re-keyed, since the prefix is the parent's.
6. **State perturbation** is the other declared difference a replicate may carry: one state coordinate moved by a
   stated relative size (the vocabulary's `Perturbation::State`). It is applied to the restored state before the
   first step of the child and recorded with the coordinate, the size and the sign. It is not randomness of the
   world: it is part of the child's specification, drawn by the caller from a stream of its own.
7. **Duplicate children.** The same specification submitted twice (equal in every field of the key) receives
   the same child key, hence the same address, and is run once. Separately, two children with equal change set,
   equal perturbation and `shared` streams are the same experiment even when their series tags or replicate
   indices differ: their keys differ, but nothing that enters the trajectory does, so their outcomes are equal.
   `children_identical(point, specs)` compares that experiment content (change set, perturbation record,
   stream mode, and under a re-keying mode the re-keyed streams) and ignores series tag and index. A splitting
   request whose children would all be identical (no noise enters after the fork) is refused by the caller's
   rule; this bead supplies the detection.
8. **Nesting.** A child may be forked again; the path grows by one step. The prefix reference chain is followed
   through at most the path's depth.
9. **Batch independence.** A child's trajectory must not depend on the batch it runs in: the same child run
   alone and among 511 siblings gives the same digests. This rests on the rule that a world's trajectory is a
   function of its address, design, scene and task alone, the same bits alone, in any batch, at any slot. This
   bead's contribution is that nothing about a child is keyed by slot or arrival.

Modules: `crates/frob-chronicle/src/fork/identity.rs`, `fork/prefix.rs`, `fork/streams.rs`.

## Acceptance criteria

- [ ] INV-AUTOPSY-04 as a test: after forking a world into 512 children under random change sets and running
      them, every chunk hash, digest and verdict of the parent equals its value before the fork, and the store
      holds no new object under a parent key.
- [ ] A child with the empty change set, no perturbation and `shared` streams has chain digests equal to the
      parent's at every tick after the fork.
- [ ] Child addresses are a function of the plan alone: the same specifications submitted in 100 random orders
      give the same address for each specification.
- [ ] `rekey(s)` changes draws of stream s from the fork tick on and no draw of any other stream; no draw before
      the fork tick changes.
- [ ] A fork job that attempts a write under a parent key is stopped by the store and the attempt is recorded.
- [ ] Reading a child's telemetry at a tick before the fork returns the parent's rows, and the artifact graph
      shows the prefix reference.
- [ ] `children_identical` returns true exactly when no declared difference that enters the trajectory exists
      between children (equal change set, perturbation and streams), whatever their series tags and indices; the
      same specification submitted twice is run once.
- [ ] Two placebo children with the same series tag and index but different perturbation coordinates or signs
      get different keys.

## Test plan

### Unit tests
`crates/frob-chronicle/tests/fork_identity.rs`:
- `fork_id_is_idempotent`; `fork_id_changes_with_tick_and_contract`.
- `child_key_is_order_free`: 8 specifications, 100 permutations, identical addresses; each specification alone
  and among the other 7 has the same key.
- `parent_unchanged_after_512_children` (INV-AUTOPSY-04): hashes of every parent object before and after.
- `write_under_parent_key_refused`: a planted fork job that publishes a chunk under the parent's address.
- `null_child_chain_equals_parent`: 200 ticks after the fork, chain values equal.
- `shared_streams_equal_parent_draws`: 10⁴ draws across all registered streams.
- `rekey_one_stream`: with `rekey("disturbance.push")`, the push draws differ from tick f on; the friction-tile
  and sensor-noise draws are bit-equal to the parent's.
- `rekey_disturbances_children_differ`: 16 children, pairwise different disturbance draws.
- `identical_children_detected`: 16 `shared` children with the empty change set and no perturbation, indices
  0 to 15 → identical; the same 16 under `rekey-disturbances` → not identical; one spec submitted twice → one
  key, one run. `nested_fork_prefix_resolves` (depth 3).
- `child_key_includes_perturbation`: two placebo specs with equal tag, size and index and opposite signs (or
  different coordinates) get different keys and different addresses.
- `prefix_read_through`: a query for ticks f − 10 to f + 10 of a child returns 10 parent rows then 11 child rows.

### Known answers and negative controls
The metamorphic relation "fork and replay" (MR-08): the empty intervention replays bit for bit; a setpoint change
at tick t reuses the prefix to the snapshot before t; a child whose streams are re-keyed has fresh streams. Its
negative controls: a checkpoint with its packet queue stripped; a fork that shares streams where fresh ones were
asked for. KA-716 (the empty intervention replays bit for bit; a setpoint change reuses the prefix). CX-292 and
CX-066: forks of a deterministic simulator do not give independent children; a walk with no noise after the fork
returns identical children. Planted defects: child keys assigned by arrival or by position in the request (the order-free test fails); a
child stream key that mixes in the slot index (digests then change with the batch: caught here and by N27a-06);
a device path that steps the parent's slot (INV-AUTOPSY-04 fails). Determinism lanes: twice on one machine;
across worker counts; debug and release.

## Considerations

- The glossary of the plan says a fork has "fresh keyed streams" while the fork section says a child reads the
  parent's streams by default. Both are kept by making the mode explicit: `shared` for counterfactual forks and
  re-keying for splitting. A caller that forgets the mode gets `shared`, which is the safe default for
  attribution and is detected as identical children by splitting.
- A prefix reference keeps the parent's chunks alive: the retention rule pins a parent's prefix while any child
  cited by an open attribution refers to it.
- Sharing by reference is a storage rule, not copy-on-write of device state; device state is copied in full.
