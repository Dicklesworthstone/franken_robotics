## Background

The fork classifier (N27a-02) says which of five classes a change set belongs to. This bead is what the fork
mechanism does to the checkpoint for each class once the classifier has spoken. The rule is that a part of the
restored state is reused only when it is identical by construction, never because it is "close". State that the
change has invalidated is either regenerated by the simulator itself (contact memory, by a cold solve), re-stated
by the intervention (packet queues and filter state), or the fork does not start at that tick at all (structural
changes).

The table that this bead implements:

| Class | State handling |
|---|---|
| Continuation | Restored bit for bit |
| Exogenous intervention | Restored; nothing regenerated |
| Contact-affecting intervention | Positions and velocities restored; contact memory discarded and the first solve run cold with a raised iteration cap; the fork is labelled |
| Information intervention | Packet queues and filter state re-initialized as the intervention states; labelled diagnostic where no hardware could realize it |
| Structural or design-parameter intervention | Not started from a mid-episode state. The edited design is settled from its own reset cache; paired exogenous draws are reused; contact memory, proprioception, sensor histories and policy actions are regenerated |

Why the middle two classes exist rather than refusing everything that is not exogenous: the most useful
diagnostic interventions are exactly these (a dry floor under the slipping foot, zero sensor latency), and their
invalidated state has a principled replacement. Why the label: the child is then not a state the changed world
would itself have reached, and a reader of the result must be able to see that. Crate `frob-chronicle`. Tier:
Solid.

## Scope

In: the restore procedure for the four classes that may start at the fork tick, the labels each writes, the
record of what was discarded or rebuilt, and the hand-off of the fifth class.
Out: classification (N27a-02); resolving the state (N27a-03); addresses and streams (N27a-04); the copy into
child slots and the verb (BD-205); the paired re-run from the episode start for structural changes (BD-283); the
list of diagnostic factors and their meanings (BD-279).

## Technical approach

Let S be the checkpoint at the fork tick f, and let the child's change set have class k (the maximum over its
changes) with handling equal to the union of its members' handlings.

1. **Continuation.** Copy every field of S into the child's slot unchanged. If the child carries a state
   perturbation (a placebo or a replicate), apply it to the one named coordinate after the copy and before the
   first step. Nothing else differs. The first step of the child must produce the parent's digest at f + 1 when
   there is no perturbation.
2. **Exogenous.** Copy every field of S unchanged. Install the changed exogenous inputs (the new setpoint in the
   command cursor's future entries, the added or removed future disturbance, the changed property of the
   untouched scene part) in the child's task, scene or parameter slot. No field of S is regenerated, and draws
   are read by address from the shared streams.
3. **Contact-affecting.**
   1. Copy positions (group elements and anchored cell indices) and velocities, and every non-contact field:
      clocks and packet queues, controller, filter and policy states, actuator states, scene state, the command
      cursor.
   2. Discard the contact memory: contact feature memory, stored contact impulses and every solver warm start
      for the contacts in the dependency set (all contacts when the contact law itself changes). The discarded
      entries are set to the empty state the solver uses on first contact.
   3. Install the changed surface property or contact law (a per-world parameter variant, so siblings with other
      values share the batch).
   4. Run the first solve cold with a raised iteration cap. DESIGN default: twice the step plan's Newton
      iteration count for the first tick only, as a distinct step-plan identity recorded on the child; on the
      transactional profiles, the retry rule that already exists for a cleared warm start (tolerance divided by
      ten, iteration cap doubled) is used for that tick. From the second tick the ordinary plan resumes.
   5. Label the fork `ContactMemoryDiscarded` and `ColdFirstSolve { iteration_cap }`, and
      `InterventionFromTick` when the classifier set it.
   6. Record the solve residual of the cold first tick; if it exceeds the plan's tolerance the child is marked
      `Degraded: cold-solve-unconverged` and counted, never dropped.
4. **Information.**
   1. Copy the physical state, contact memory, actuator states, controller and policy states, scene state.
   2. Re-initialize the packet queues and the filter state *as the intervention states*. DESIGN defaults per
      kind of change, each overridable by the intervention's own statement:

      | Change | Packet queues | Filter and estimator state |
      |---|---|---|
      | Noise scale changed | Kept: packets already sampled keep their recorded values; samples taken from tick f on use the new law | Kept |
      | Latency or jitter changed | Rebuilt: every in-flight packet keeps its sampling instant and value and receives a delivery instant under the new law; packets whose new delivery instant is at or before f are delivered at f in sampling order | Kept |
      | Dropout law changed | Kept for packets in flight; new law from tick f | Kept |
      | Estimator replaced by privileged state | Kept | Discarded; the estimate is the simulator's true state from tick f on |
   3. Label the fork `Diagnostic` where no hardware could realize the change (privileged state, zero latency,
      zero noise); the label travels to every result that cites the fork.
5. **Structural.** No restore. The mechanism returns the classifier's result (earliest valid tick 0 and the
   forcing fields); the caller either receives FROB-REF-581 or, at M3, routes the edit to the paired re-run from
   the episode start. The one exception is the labelled diagnostic forced fork, which is admitted and specified
   with the re-run verb, not here; this bead exposes the hook `restore_forced(S, edit)` that copies S under the
   edited model, discards the contact memory, runs the first solve cold and labels the child `ForcedFork`, and it
   refuses (FROB-REF-582) any edit that changes the kinematic structure or the collision geometry, because then
   the copied configuration is not a configuration of the edited model.
6. **Record.** Every child manifest carries `restore: { class, discarded: [FieldPath], rebuilt: [FieldPath],
   labels, first_tick_plan, first_tick_residual }`.
7. **Determinism.** Each handling is a deterministic function of S, the change set and the plan. Continuation and
   exogenous restores are bitwise; the other two are bitwise repeatable (class D2) and are not claimed equal to
   any parent tick.

Module: `crates/frob-chronicle/src/fork/restore.rs`.

## Acceptance criteria

- [ ] Continuation: the child's digest at every tick after f equals the parent's (1,000 worlds, by N27a-06).
- [ ] Exogenous: with a setpoint change at tick f, the child's state at f equals the parent's bit for bit, and
      the first differing tick is the first tick at which the new setpoint is read.
- [ ] Contact-affecting: the child's contact memory is empty at f for the affected contacts; positions and
      velocities equal the parent's at f; the first tick's plan identity differs from the run's and carries the
      doubled count; both labels are present.
- [ ] Information: with `latency := 0`, every in-flight packet is delivered at f in sampling order and no packet
      is lost or duplicated (count before equals count after plus deliveries); with the privileged estimator the
      filter state is discarded and the `Diagnostic` label is set.
- [ ] Structural: no state is restored (store read counter zero) and the classifier's fields are returned.
- [ ] `restore_forced` refuses a wheel-radius edit with FROB-REF-582 and admits a gear-ratio edit with the
      `ForcedFork` label.
- [ ] An unconverged cold solve is reported as `Degraded: cold-solve-unconverged` and appears in the count.
- [ ] Each handling repeated twice gives identical child digests; across worker counts likewise.

sill fixture and of a standing quadruped):

- `exogenous_setpoint_reuses_everything`: setpoint 0.30 → 0.20 m/s at f; state at f equal; first difference at
  the next controller tick.
- `contact_memory_discarded`: friction of the stance patch 0.8 → 0.3; warm starts of the four foot contacts are
  empty at f; other fields equal.
- `cold_first_solve_plan`: iteration count on tick f is twice the plan's; on tick f + 1 it is the plan's.
- `cold_solve_converges_on_standing_quadruped`: residual at f within the plan tolerance; support forces within
  5% of the static support force at f.
- `law_change_discards_all_contacts`.
- `latency_zero_flushes_in_order`: three in-flight IMU packets sampled at ticks f − 6, f − 4, f − 2 are delivered
  at f in that order.
- `latency_increase_restamps`: delivery instants move later by exactly the added latency.
- `privileged_estimator_discards_filter`.
- `structural_restores_nothing`.
- `forced_fork_geometry_refused_582`; `forced_fork_gear_ratio_labelled`.
- `handling_of_a_mixed_set`: {latency := 0, friction := 0.3 on the stance patch} flushes the queue and discards
  contact memory; labels are the union.

Covered by `scripts/e2e/run_fork.sh` (N27a-08): one fork per class through `frob run fork`, logging the restore
record (class, discarded and rebuilt fields, labels, first-tick plan and residual).

### Known answers and negative controls
KA-716: the empty intervention replays bit for bit; a setpoint change at tick t reuses the prefix to the snapshot
before t. Negative controls that must be caught: a contact-affecting restore that keeps the old warm starts
(`contact_memory_discarded` fails; this is the graft that the wheel control refuses); an information restore that
drops in-flight packets (the packet count assertion fails); a forced fork that carries configuration across a
geometry change. Metamorphic relation: an exogenous fork whose change is then set back to the recorded value is
a continuation and must equal the parent bit for bit. Determinism lanes: twice on one machine, across worker
counts, debug and release, each backend against itself.

## Considerations

- The raised iteration cap is a DESIGN default (twice); the plan fixes that the cap is raised and that the fork
  is labelled, not the factor. If cold solves on the lockstep tiers do not converge at twice the count in the
  contact battery, the factor is raised and recorded as a new step-plan identity; it is never left silent.
- On the lockstep tiers the number of solver iterations is a constant of the shape class, which is what makes a
  world independent of its batch. A first-tick plan with a different count is therefore a different plan
  identity, and children with and without it are different variants in one mixed batch.
- The information defaults are this bead's reading of "re-initialized as the intervention states"; an
  intervention may state another rule, which is then stored with the fork.
