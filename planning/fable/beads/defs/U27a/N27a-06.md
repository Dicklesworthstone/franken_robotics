## Background

Every attribution the system will ever make starts from one fact: the fork point is the recorded failure, exactly.
The **null fork** applies the empty intervention. It must reproduce the parent bit for bit on the originating
profile (**INV-AUTOPSY-01: the empty intervention replays its parent bit for bit on the originating profile;
otherwise nothing is attributed**; Chronicle states the same as INV-CHRON-07: a fork with the empty change set
equals the replay, bit for bit on the same backend). If it does not, the record is unsound and nothing may be
attributed from it.

The second fact is that a child does not depend on its siblings. Counterfactual debugging forks one failing world
into a batch of hundreds of children, and a rescue must be the intervention's doing and not an effect of sharing
a batch. FACT (source register): one incumbent that documents bitwise replay of a batch holds a world equal to
its isolated run only to 10⁻⁵ to 10⁻⁴ in its own tests; the property is worth having only if it is exact.

GATE-AUTOPSY-01 measures both. Its row in the gate register (claim: Known answer; milestone M2; TARGET):

> Null forks of 1,000 failing worlds replay with identical digests on the originating backend; a world forked
> alone and in a batch of 512 children gives identical digests.

The batch-independence half is one of several gates that record a single shared experiment from the side of the
chapter that consumes it; the fixture is run once per milestone and each gate is compared with the threshold in
its own row. This bead is a measurement and adds no mechanism. Tier: Solid.

## Scope

In: the population of failing worlds; the null-fork measurement on every backend that recorded them; the
alone-versus-512 measurement; the negative controls; the gate record.
Out: the fork mechanism (BD-205 and its parts); the general batch-independence test of the numerics chapter
(BD-181), which this bead reuses for its fixture; placebo forks (BD-279).

## Technical approach

1. **The population.** 1,000 failing worlds per originating backend, taken from recorded evaluation runs of the
   reference quadruped on the M2 task families (velocity tracking and terrain traversal) under the tasks' full
   randomization, with the baseline controller and with the trained flat-velocity policy, so that both
   controller kinds and both hidden-state kinds appear. Failures are whatever terminal physical failures occur
   (falls, slips, torque saturation, timeouts); numerical outcomes are excluded from the population and counted
   in the record. The world addresses are fixed in a manifest committed before the measurement, with the
   failure class of each, so the population cannot be chosen after the fact. Backends: the CPU tier in single
   and in double precision, the CUDA backend and the Metal backend, each against its own record.
2. **Null forks.** For each world: open a fork point one second before the failure (the default lead), from
   whichever source the resolver picks; the population is arranged so that at least 100 worlds each come from a
   stored snapshot, from the ring and from replay-to-tick. Run the null fork to the end of the parent's record.
   Compare the chained state digest at every committed tick with the recorded one. Pass criterion for a world:
   equality at every tick. Gate criterion: 1,000 of 1,000 on each backend.
3. **Alone and among 512.** For 16 worlds of the population: build 512 child specifications (the empty change
   set, 64 placebo perturbations at relative 10⁻¹², and 447 children under change sets drawn from the
   classification catalogue's exogenous, contact-affecting and information rows with three parameter values
   each). Run (a) each of 32 chosen children alone in a batch of one; (b) all 512 in one batch; (c) the 512 in a
   different slot order with 512 unrelated co-tenant worlds. Pass criterion: for each chosen child, the chained
   digest at every tick is equal in (a), (b) and (c).
4. **Negative controls**, each of which must be caught and is recorded as caught:
   - a checkpoint with its packet queue stripped does not replay and is refused (FROB-REF-580) or, if the
     stripped queue is disguised, the null fork reports `mismatch`;
   - a planted padding defect (padding lanes holding +0.0 where the sum's neutral element −0.0 is required)
     changes a digest between the alone and the 512 runs;
   - a planted batch statistic (an observation normalizer computed over the batch) changes a child's trajectory
     when its siblings change;
   - a planted fork that steps one tick past the checkpoint before copying reports `mismatch` at the first tick.
5. **Record.** One gate row per backend with: worlds attempted, worlds bitwise, first mismatch if any (world,
   tick, stage), source mix, the alone-versus-512 count, the controls caught, commit, hardware fingerprint,
   seeds. The measured counts are written, not the targets.

## Acceptance criteria

- [ ] GATE-AUTOPSY-01 recorded PASS on each backend with measured values: null forks bitwise on 1,000 of 1,000
      failing worlds; 32 of 32 chosen children identical alone, in the batch of 512 and under slot permutation

- [ ] The population manifest's hash is committed before the first measurement and cited in the record.
- [ ] Each of the four negative controls is caught; a control that passes fails the bead.
- [ ] A numerical outcome in the population is counted as excluded with its reason and is not silently replaced.
- [ ] The property test for INV-AUTOPSY-01 runs in `cargo test -p frob-chronicle`.
- [ ] The script exits non-zero if any world mismatches and prints the first differing tick and stage with the
      artifact paths needed to reproduce.

## Test plan

### Unit tests
`crates/frob-chronicle/tests/null_fork_invariant.rs`:
- `inv_autopsy_01_property`: for 200 random (world, tick) pairs of a recorded CPU-tier run, the null fork's
  chain digests equal the record at every tick to the end of the record.
- `null_fork_from_each_source`: snapshot, ring, replay-to-tick.
- `alone_equals_batch_small`: one child alone and among 15 siblings (the fast lane of the gate fixture).
- `stripped_queue_caught`, `positive_zero_padding_caught`, `batch_normalizer_caught`, `late_copy_caught`: each
  plants the defect behind a test-only switch and asserts that the comparison reports a difference.
- `numerical_outcome_excluded_and_counted`.

### End-to-end script and logging
`scripts/e2e/gate_autopsy_01.sh`. It sources the shared helper, reads the population manifest, and for each
backend present on the machine runs `frob run fork <run> --world <w> --before failure --dt 1.0s --json` over the
1,000 worlds (in batches), then the alone-versus-512 runs through `frob run fork … --children 512`. Assertions:
`null_replay == "bitwise"` for every world; digest equality across the three arrangements. Log lines (newline-
delimited JSON under `target/e2e-logs/gate_autopsy_01/<utc-timestamp>.ndjson`, with a transcript beside it):
`ts`, `script`, `bead` (`N27a-06`), `step`, `event` (`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the
exact command line, exit code, wall time, the envelope's evidence block (class, tier, determinism, identities,
seed), per world the fork tick, the source, the chain digest of the record and of the null fork at the last tick,
and on failure the first differing tick, stage and digests with the paths of the two episode files. Metrics:
`null_forks_bitwise` against threshold 1000, `children_identical` against 32. A final `summary` line gives the
assertion counts and `gates: ["GATE-AUTOPSY-01"]`. No scene geometry or private-scene data is logged, only
identities and digests. The script is idempotent (fork points are found again by identity) and seed-explicit.

### Known answers and negative controls
KA-671: null fork, identical digests, exact, verification tier G5 on all tiers; negative control: a checkpoint
with its packet queue stripped does not replay and is refused. KA-145: the empty intervention replays the
recorded failure bit for bit. The two smallest cases behind the batch controls: the sum of the single active
element −0.0 is −0.0 alone and +0.0 when one +0.0 lane is appended, because (−0.0) + (+0.0) = +0.0, so the values
compare equal while the bits and the digest differ; and two worlds observing 1 and 3, normalized by their batch
mean, see −1 and +1, while the first world alone sees 0. Determinism lanes: the whole measurement twice on one
machine; with 1, 4 and all workers on the CPU tier; debug and release on the CPU tier; each device against its
own record. Cross-backend equality is not asserted by this gate.

## Considerations

- If a backend fails this gate, attribution is not available on that backend's records; forks remain usable for
  replay with a tolerance label, and the failure is filed as a determinism violation with both digests.
- 1,000 failing worlds require evaluation runs harsh enough to produce them; the manifest may draw from several
  runs. The count per failure class is recorded so that a population of one class is visible.
- Cost: 1,000 null forks of about 2 s each are 2,000 world-seconds per backend, seconds on a device and minutes
  on the CPU tier; the 512-child batches are smaller still.
- The gate is re-run whenever a kernel version, the snapshot column list or the step plan changes; its record
  names the kernel versions.
