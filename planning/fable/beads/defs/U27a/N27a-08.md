## Background

`run.fork` is the user-visible entry to every counterfactual experiment: it makes a fork point from a recorded
run, classifies a proposed change set into one of five classes (continuation, exogenous, contact-affecting,
information, structural) before restoring anything, reports the earliest valid fork tick and the checkpoint
fields that forced it, runs the null fork, and can launch children. The unit tests of its parts run inside the
crates. This bead is the script that drives the real `frob` binary the way an agent does, on real recorded runs,
and checks what an agent would read: envelopes, exit codes, refusal blocks, digests.

The project's testing standard requires one end-to-end script per user-visible capability, in plain shell, with
structured logs detailed enough to reproduce a failure from the log alone. Tier: Solid.

## Scope

In: `scripts/e2e/run_fork.sh`, its fixtures, its assertions and its log.
Out: the 1,000-world null-fork gate (N27a-06, its own script); the first-divergence script (N27a-09); attribution
verbs (later milestone).

## Technical approach

The script sources the shared end-to-end helper (logging, envelope parsing, assertion functions), takes `--seed`
(default 1) and `--tier` (default the CPU tier in single precision; `gpu-cuda` and `gpu-metal` where present),
and is idempotent: every run-producing command carries an idempotency key derived from the seed and the step
name, so a second invocation finds the same runs and fork points.

Steps.

1. **Record the parents.** `frob sim run` the quadruped episode Q and the cart episode C of the classification
   catalogue at the given seed and tier, under the `device-replay` or `reference-replay` profile, with T2
   telemetry on the failing world. Assert exit 0 or 2 and that Q's world of interest ends in a physical failure.
   Save run identities and the chain digest at the last tick.
2. **Fork point.** `frob run fork <Q> --world <w> --before failure --dt 1.0s --json`. Assert: exit 0; `fork`
   starts with `f:`; `tick` equals failure time minus 1.0 s snapped down to a committed tick; `class` is
   `continuation`; `null_replay` is `bitwise`; on a single-precision tier `double_precision` is present and is
   one of `decision-equivalent`, `not-equivalent`.
3. **Idempotence.** Repeat step 2 with the same key: the same `fork`, `idempotent_replay: true`, no new charge.
4. **Classify-only over the catalogue.** For each of the 40 rows: `frob run fork … --at <f> --change '<do>'
   --classify-only --json`. Assert class, earliest valid tick, forcing fields and labels against the row. For
   the refused continuation rows assert exit 3 and the code.
5. **One child per startable class.** Without classify-only: an exogenous child (setpoint change), a contact-
   affecting child (stance-patch friction), an information child (IMU latency 0 s). Assert exit 0, 2 or 8 followed
   by `frob job wait`; assert each child's address extends the parent's by a fork path; assert the restore
   record (discarded and rebuilt fields, labels) for each class; assert each child's state digest at the fork
   tick equals the parent's for the fields its class preserves.
6. **Refusals.** The mid-episode gear change without classify-only: exit 3, `refusal.code` FROB-REF-581,
   `earliest_valid_fork_tick` 0, forcing fields containing the actuator thermal state, the policy history and
   the contact memory, ranked repairs present. The warm-start graft on C: exit 3, FROB-REF-582, the contact
   memory named. A fork of a run recorded under the unspecified-determinism training profile: exit 3,
   FROB-REF-562.
7. **Parent untouched.** `frob run show <Q>` and a digest query: the parent's chain digest at its last tick and
   its manifest hash equal the values saved in step 1.
8. **Reconstruction by replay.** Fork a failing world that is outside the snapshot reservoir: assert `source` is
   `replay-from-start` or `replay-from-snapshot` and `null_replay` is `bitwise`.
9. **Cancellation.** Start a 512-child fork, cancel the job, wait for `cancelled`, and assert through
   `frob doctor` or the environment status that the free-slot count returned to its starting value.
10. **Summary.** Write the gate metrics and the summary line.

Structured log. Newline-delimited JSON at `target/e2e-logs/run_fork/<utc-timestamp>.ndjson`, with a human-
readable transcript beside it. Every line has `ts`, `script` (`run_fork`), `bead` (`N27a-08`), `step`, `event`
(`start`, `cmd`, `assert`, `metric`, `refusal`, `end`). `cmd` lines carry the exact command line, exit code and
wall time, and the envelope's `evidence` block (claim, class, tier, determinism, identities, seed). `assert`
lines carry the name, expected and observed values and pass or fail. `metric` lines carry measured values with
units and thresholds: `pairs_correct` (count, threshold 40), `planted_sets_correct` (count, threshold 100),
`graft_refused` (count, threshold 100), `null_replay_bitwise` (boolean), `reconstruct_ticks`, `reconstruct_wall_ms`.
`refusal` lines carry the code, pointer, observed, required and the first repair. Digests are logged wherever
state is compared (parent before and after; child against parent at the fork tick). On failure the line names
the first differing value and the artifact paths needed to reproduce (run identities, episode file paths, the
fork identity). The final `summary` line gives assertions passed and failed and `gates` touched. The log never
contains scene geometry, stills or private-scene data: identities, digests and scalars only.

## Acceptance criteria

- [ ] `scripts/e2e/run_fork.sh --seed 1` exits 0 on the CPU tier in both precisions, and on each device backend
      present, and exits non-zero when any assertion fails.
- [ ] The log file exists with the fields above on every line and ends in one `summary` line naming
      GATE-AUTOPSY-02 and GATE-CHRON-05 with their measured counts.
- [ ] Running the script twice produces no new runs or fork points the second time and identical digests.
- [ ] The three refusals of step 6 are observed with their codes, exit code 3 and repair lists.
- [ ] Step 7 shows the parent unchanged.
- [ ] With a planted classifier defect (design changes treated as exogenous) the script fails at step 4 or 6 and
      the log's failing line names the row.

## Test plan

### Unit tests
The helper functions the script adds are tested by the harness's own shell tests: `snap_down_time` (11.30 s − 1.0
s at a 0.01 s commit period gives 10.30 s); `class_row_matches` (ordered comparison of forcing fields);
`digest_equal` (reports the first differing hex digit position).

### End-to-end script and logging
This bead is the script; see the technical approach for commands, assertions and log fields.

### Known answers and negative controls
KA-671 (null fork: identical digests), KA-676 (warm-start graft refused with FROB-REF-582), KA-716 (a setpoint
change at tick t reuses the prefix to the snapshot before t). Negative controls run by the script itself in a
`--self-test` mode: it corrupts one byte of a copied episode file and expects `null_replay: mismatch` with exit
2; it strips a packet queue from a copied checkpoint and expects FROB-REF-580. Determinism lanes: the script is
run twice on one machine and the two logs' digest fields are compared; on the CPU tier it is run with 1 and with
all workers; debug and release binaries; each backend against its own record.

## Considerations

- The script does not assert cross-backend equality; a fork on a device is compared with that device's record.
- Wall time on the CPU tier is dominated by recording the two parents (seconds); the catalogue loop is 42
  classify-only calls that restore nothing.
- If the daemon is not running the script starts one for its duration and stops it in a trap handler.
