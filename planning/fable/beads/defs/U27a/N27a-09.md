## Background

Comparing two runs (a fork with its parent, one tier with another, one backend with another) starts with the
first place they differ. Every attribution reads that answer, so the Autopsy chapter restates the algorithm that
the Chronicle subsystem owns and the verb `telemetry.divergence` runs, and gives it a gate of its own. This bead
is that gate: a battery that plants divergences and checks the algorithm finds them, including the one mistake
that is easy to make.

**The algorithm under test** (the contract; the implementation is the first-divergence search bead, BD-206).

```text
first_divergence(A, B, mode):
  align the committed ticks and events of A and B by stable identifiers; a variable with no counterpart
    is listed as unpaired and is never matched by position
  if mode is exact:
      c_t = H(c_{t-1}, d_t) is the chained digest of the per-tick state digests d_t, stored at checkpoints
      bisect over checkpoints for the least k with c_k(A) ≠ c_k(B)
      replay both runs from checkpoint k − 1 and compare d_t tick by tick: the first unequal tick is t1
  if mode is tolerance, with a scale per class of variable:
      for each block of ticks, in chronological order:
          [lo, hi] = bounds on the block maximum of the scaled error
          hi ≤ 1 : the block agrees; go on
          lo > 1 : a mismatch lies inside; descend into the block
          otherwise : unresolved; refine this block before looking at any later block
      where samples are missing, report the earliest possible interval and the coverage gap
  at t1, re-run the tick with per-stage digests or residuals: the first stage over tolerance is s1
  report t1, s1, the variables that differ under their physical names and units, and the first tick at
    which a requirement atom or a task decision differs
```

**The trap.** Bisection is valid only on a predicate that is monotone and decided. "Some tick up to t differs"
is monotone. "The states differ at tick t" is not, because an error can vanish and return. Counterexample: two
traces of eight ticks that differ at ticks 1 and 5 and agree elsewhere. A midpoint search on the pointwise
predicate probes tick 3 or 4, sees agreement, moves right and reports tick 5. The chained digest reports tick 1,
because each chain value covers the whole prefix. The same trap applies to bisecting a design lineage, where the
predicate must be "the outcome has changed by this edit" and each step must be decided by a study.

**Rules for reading the result**, which the battery also checks in the report: the first recorded discrepancy is
labelled with its temporal resolution; the order in which solver stages report residuals inside a tick is not
evidence of a physical cause; for a fork against its parent the first divergent tick is the intervention tick or
later; when topology differs between the runs, only shared interfaces and task observables are compared (a leg
that exists in one run has no counterpart in the other).

Gate row (claim: Known answer; milestone M2; TARGET): **GATE-AUTOPSY-07. First divergence: planted divergences
found at the right tick and stage in 100 of 100 in exact mode; the pointwise mutant is caught; tolerance mode
reports gaps.** Tier: Solid.

## Technical approach

1. **Fault injection for planting.** A test-only hook of the step, compiled only under the conformance feature,
   adds one unit in the last place to one named output of one named stage (kernel) at one named tick of one
   world. Run A is the unmodified run; run B is the same address with the hook armed.
2. **Exact-mode battery.** 100 trials on the CPU tier (50 in each precision), each with a tick t drawn uniformly
   from the episode and a stage s drawn uniformly from the ten stages of the batched step, both by seed.
   `first_divergence(A, B, exact)` must return t1 = t and s1 = s. Ten of the trials place t on a checkpoint
   boundary and ten on the tick after one, the two off-by-one positions of the bisection.
3. **Two-tick case.** Eight-tick traces that differ at ticks 1 and 5 and agree elsewhere (the hook is armed at
   tick 1, disarmed, and armed again at tick 5 with a fault that cancels the first: the state digests at ticks 2
   to 4 are equal). Expected: tick 1.
4. **The pointwise mutant.** A second implementation, kept in the test tree, bisects on "the state digests differ
   at tick t". On the two-tick case it must report tick 5. The battery asserts that the mutant is wrong there,
   so the case stays a live negative control, and asserts that the production function is not the mutant by
   running both on 100 two-tick cases with random first ticks.
5. **Fork against parent.** Fork a world at tick f with a setpoint change that takes effect at f + 3; expected
   t1 = the first tick the changed setpoint is read, never earlier than f; the report includes the order in which
   classes of variable leave tolerance and the first tick at which a requirement atom or task decision differs.
6. **Tolerance mode.**
   - *Loose bound.* A block whose stored envelope gives hi = 1.4 and whose stored samples give lo = 0.6: the
     function must return `unresolved` for the block, refine it before any later block, and then return the right
     interval. A later block with lo > 1 must not be reported first.
   - *Missing samples.* A trace with samples absent for ticks 40 to 59 and a true first mismatch at tick 47
     that persists to the end of the trace:
     expected output is the earliest possible interval [40, 59] and the coverage gap, not a tick. The negative
     control is a tool that skips the gap and reports the first mismatch among retained samples, a later tick.
   - *Agreement soundness.* Whenever a block is reported as agreeing, the true maximum scaled error over the
     block, computed from the full state of both runs, is at most 1.
7. **Unpaired variables and topology.** Run A is a quadruped; run B the same body with a tail added. Expected:
   comparison on shared interfaces and task observables only; the tail's variables listed as unpaired; no match
   by position.
8. **Proof obligations as tests.**
   - **PO-AUTOPSY-02.** `first_divergence` in exact mode returns the least tick at which the prefixes differ.
     Class sought: Tested, with planted divergences; the monotonicity argument is on file in
     `docs/derivations/first-divergence-monotonicity.md`. The derivation: c_k covers ticks 0 to k; if the
     prefixes agree through k then c_j(A) = c_j(B) for all j ≤ k; if they differ at some tick t ≤ k then
     c_j(A) ≠ c_j(B) for all j ≥ t except with the collision probability of the 128-bit mix; hence the predicate
     P(k) = [c_k(A) ≠ c_k(B)] is monotone in k and its least true index brackets t1 between two checkpoints.
   - **PO-AUTOPSY-03.** In tolerance mode, an interval reported as agreeing has a true maximum scaled error of
     at most 1. Class sought: Tested with outward-rounded block bounds: the envelope's upper bound is rounded up
     and the sample-based lower bound rounded down when they are computed in floating point.
9. **Record.** GATE-AUTOPSY-07 with: exact trials passed of 100 (tick and stage separately), mutant caught
   (count of two-tick cases on which it is wrong), tolerance cases passed, commit, fingerprint, seeds.

## Test plan

### Unit tests
`crates/frob-chronicle/tests/first_divergence_gate.rs`:
- `planted_tick_and_stage_100` (seeded): equality of (t1, s1) with the planted pair in every trial.
- `checkpoint_boundary_cases`: t on a checkpoint, t one after.
- `two_ticks_reports_first`: differ at 1 and 5 of 8; expected 1.
- `pointwise_mutant_reports_5`: the mutant's answer on the same traces is 5.
- `po_autopsy_02_least_tick` (property, 1,000 random pairs of traces with one to three planted differences):
  the result equals the minimum planted tick.
- `fork_divergence_not_before_fork_tick`.
- `tolerance_unresolved_then_refined`; `tolerance_refines_chronologically`: with an unresolved block at ticks 20
  to 39 and a proven mismatch at ticks 60 to 79, the reported interval lies in 20 to 39 when the truth does.
- `tolerance_gap_interval`: expected [40, 59] with `coverage_gap: [40, 59]`.
- `gap_skipping_tool_reports_later`: the control implementation returns tick 60.
- `po_autopsy_03_agreeing_blocks_sound` (property, 1,000 random blocks): reported agreement implies a true
  maximum scaled error ≤ 1; with inward rounding planted, the property fails.
- `unpaired_variables_listed`.

### End-to-end script and logging
`scripts/e2e/gate_autopsy_07.sh`. From the user's side: record run A with `frob sim run`; record run B with the
conformance build's fault flag; `frob telemetry divergence <A> <B> --mode exact --json`; then a fork and its
parent; then the tolerance cases with `--mode tolerance` on runs whose telemetry level leaves a gap. Asserts as
in the acceptance list. Log (newline-delimited JSON at `target/e2e-logs/gate_autopsy_07/<utc-timestamp>.ndjson`
plus a transcript): `ts`, `script`, `bead` (`N27a-09`), `step`, `event`, the exact command, exit code, wall time,
the envelope's evidence block, and per trial `planted_tick`, `planted_stage`, `reported_tick`, `reported_stage`,
`checkpoints_probed`, `ticks_replayed`, chain digests of both runs at the bracketing checkpoints; for tolerance
trials the block bounds `[lo, hi]`, the interval and the gap. Metrics: `exact_hits` (threshold 100),
`mutant_caught` (threshold 1), `tolerance_cases_passed`. A final `summary` line with `gates:
["GATE-AUTOPSY-07"]`. On failure: the first differing value and the two run identities and episode paths.

## Considerations

- The same mechanism has two gates (this one and Chronicle's GATE-CHRON-06: the two-tick case 100 of 100, a loose
  bound returning `unresolved` then the right interval, a gap returning an interval). The fixtures are shared and
  each gate is compared with its own row.
- Lineage bisection has the same trap with a different predicate. Its counterexample: outcomes along six
  versions are pass, fail, pass, pass, pass, fail; the midpoint passes, the search goes right and reports the
  last edit while the first edit also changed the outcome. That mechanism returns a pair of adjacent versions
  labelled `a-change` unless the prefix has been scanned; nothing here implements it.
- Stage order inside a tick is an order of computation. The battery's report text must say "first stage over
  tolerance", never "cause".
