## Background

**Autopsy** is the subsystem for counterfactual debugging. After a failed simulated episode, `frob explain`
assembles what happened: the failure class, the energy ledger, saturation, slip, and the earliest anomaly before
the terminal event, which it labels `Estimated` because ordering anomalies in time is a heuristic. Autopsy turns
that heuristic into a measurement: it restores the world to a moment before the failure, changes one thing, runs
forward, and records whether the failure still happens. A proposed cause is tested by intervention; it is never
inferred from the order in which monitors or solver stages reported.

What Autopsy owns: the semantics of forks (their classification and the earliest tick at which a given change
may be applied); the intervention vocabulary `do(factor := value)`; placebo forks; interventional contrasts with
their flip rates; coalition experiments and budgeted Shapley summaries; minimal repair sets; paired re-runs from
the episode start for design parameters; the reading of first divergences on forks; and the transcript of a
debugging session. What it consumes: snapshots, ring buffers, replay and the fork mechanism from the Chronicle
subsystem; verdicts from the task-and-evaluation subsystem (Arena); the typed world edits and the shrinker of
the adversarial-world subsystem (Nemesis); the typed design edits of the design language; and the simulation
tiers.

Everything in the subsystem is tier Solid except one claim. Forks, classification, contrasts with a stability
report, coalition tables and the divergence algorithm are established technique applied carefully. The claim that
an agent repairs designs in fewer turns with these tools than with logs is a HYPOTHESIS with its own gate
(GATE-AUTOPSY-08). Counterfactual replay from restorable simulator state is established practice, and incumbent
simulators expose restorable state and opt-in run-to-run determinism on one GPU (FACT, source register). Nothing
here is claimed as new.

This bead creates the crate that the other Autopsy beads fill: its place in the layering, its shared result
types, the scope every result carries, its contract document, and a check of the four things the engine must
supply for the method to work at all.

**ADR-AUTOPSY-07. The cause is a cause in the model.** Every attribution is scoped to the model, the tier and the
declared factor list. Reason: a causal statement about a simulated failure says nothing about the physical robot
(FACT, source register: causal models of robot failures learned from simulation reached a sim-to-real accuracy of
70% and 72% in one study, with variables chosen by the experimenter), and nothing about factors nobody declared.
The rejected alternative is an unscoped "cause" field, which a reader would take for a cause in the world.

## Scope

the permitted wording and the citation guard FROB-REF-880 (N27b-15).

## Technical approach

1. **Layering.** `[package.metadata.frob] layer = 5`. The crate names `frob_core::fork` (the fork vocabulary and
   the `ForkService` trait) and receives an implementation through the job context; it never depends on
   `frob-chronicle` (layer 6). It depends on `frob-design` (typed edits), `frob-spec` and `frob-arena` (verdicts),
   and on `frob-nemesis` for world-edit types and the shrinker. The last needs an ADR: the crate map lists
   `frob-autopsy` before `frob-nemesis` in layer 5, and rule L-1 allows a same-layer dependency only on an
   earlier row; the rule provides that a chapter that needs a different order changes the rank by ADR. This
   bead writes that ADR (`docs/adr/ADR-AUTOPSY-RANK.md`, DESIGN name): `frob-nemesis` takes rank 2 and
   `frob-autopsy` rank 3 of layer 5, changed in the crate map (`crates/xtask/src/crate_map.rs`) and in the two
   manifests by the commit that records the ADR. Reason: Autopsy consumes Nemesis's typed world edits and its
   shrinking routine, and no Nemesis crate code calls Autopsy (the attack-loop script calls the verb, which is
   not a crate dependency). Fail-closed default until the ADR is recorded: the crate builds without the
   `nemesis` feature, world factors are limited to the field paths the fork mechanism already accepts, and
   repair-set search is unavailable.
2. **Result types** (the plan's sketch; DESIGN, fixes intent). Module `types`.

   ```rust
   pub struct Contrast { intervention: Intervention, rescued: (u32, u32), contrast: f64,
                         flip_rate: FlipRates /* at 10⁻¹² and at 10⁻⁷ */, label: CauseLabel }
   pub enum CauseLabel { ButFor, Contributing, Joint, Alternative, PrecedesSnapshot, PrecisionSensitive,
                         ChaoticUnattributable, None }
   /// Schema frob.autopsy.attribution/1. Class Estimated: a cause in the model at this tier, among the
   /// listed factors.
   pub struct Attribution { fork: ForkId, tier: Tier, precision: Precision, horizon: Qty, forks_run: u32,
                            null_replay: NullReplay, placebo: Placebo, contrasts: Vec<Contrast>,
                            pairs: Vec<PairContrast>, refused: Vec<RefusedIntervention>,
                            scope: Scope, evidence: ClaimProduct }
   pub struct Placebo { n: u32, flips: u32, rate: Ratio, separation_growth: f64 }
   pub struct PairContrast { interventions: [Intervention; 2], rescued: (u32, u32), interaction: Ratio }
   pub struct RefusedIntervention { intervention_text: String, code: RefusalCode, earliest_valid_fork_tick: Tick }
   ```
   Counts are integers and rates are exact rationals internally; decimals appear only on the wire. The label
   enum is extended by the labelling work with the spellings the single-precision lane adds.
3. **Scope** (INV-AUTOPSY-06: every attribution carries its scope: the model, the tier, the precision and the
   factor list).

   ```rust
   pub struct Scope { model: ModelId, design: DesignId, scene: SceneId, task: TaskId,
                      controller: ControllerRef /* a ControllerId, a PolicyId or a sampling-controller record */,
                      tier: Tier, profile: StepProfile, precision: Precision, determinism: DetClass,
                      fork_tick: Tick, horizon: Qty,
                      factors: Vec<FactorPath> /* every factor requested, the refused ones included */ }
   ```
   `Attribution` has no constructor that omits `scope`; the wire form prints `"scope": "cause in the model at
   this tier, among the listed factors"` beside the structured scope. A result type of this crate that names a
   factor without a scope does not compile (the label-bearing types hold a `&Scope` or own one).
   This is the one scope type of the crate, in `scope.rs`. N27b-15 builds on it and does not define a second:
   it adds the constructors of repair results and transcripts that cannot omit a scope, the fixed text form in
   the evidence block, the `non_claims` list, the permitted wording and the citation guard.
4. **Evidence.** A contrast is a replayable experiment and has class `Tested` on its tier; an attribution drawn
   from contrasts has class `Estimated`. The claim product is built by combining the products of the forks
   read; the reality scope is always `no-claim`; the three no-authorization constants are false.
5. **Defaults table.** `defaults.rs` holds every number the subsystem uses, each with its label and meaning, and
   nothing else in the crate contains a literal threshold:

   | Constant | Value | Label |
   |---|---|---|
   | Lead ladder | 0.25, 0.5, 1, 2 s | TARGET |
   | Horizon past the parent's failure | 1 s | TARGET |
   | Placebo forks | 64 | DESIGN |
   | Replicates per intervention | 8 at 10⁻¹², and 8 at 10⁻⁷ for interventions that change the outcome | DESIGN default; OPEN-AUTOPSY-1 |
   | Perturbation sizes | relative 10⁻¹² and 10⁻⁷ | DESIGN |
   | Factor budget | at most 12, singles and pairs | DESIGN |
   | `but-for` | contrast ≥ 0.5 and flip rate ≤ 0.1 at 10⁻¹² | TARGET |
   | Abstention | placebo flip rate above 0.2 | TARGET |
   | Exact Shapley | m ≤ 5 | DESIGN |
   | Level of the exact one-sided test | α = 1/20, divided by the number of factors tested | DESIGN default (N27b-05) |

   The table is open to the beads that come after this one: a bead that introduces a further runtime constant
   of the subsystem adds its row here in the same change, with its label, and the no-literal test covers it (for
   example the single-precision lane's R₀ = 32 replicates, its admission rule ρ₀ ≤ 0.1 and growth bound
   G(W)·u ≤ 10⁻⁴, its 16 replicates; the cross-check's top k = 8). A constant used in the crate and absent from
   the table fails that test.

   A rule of the chapter applies: a value that follows from a stated formula is a derived value and a known
   answer; every other number carries its label. The derived values (689 forks, 78 coalitions, 32 and 1,024
   coalitions) are computed from the table by functions with known-answer tests, never stored.
6. **Precondition check** `preconditions(backend, model) → Result<(), Refusal>`. The engine must supply four
   things, and the check reads the gate records for the backend and kernel versions in use:

   | Need | Evidence read | If absent |
   |---|---|---|
   | An exact null replay | The null-fork gate (GATE-AUTOPSY-01) current for the backend | Attribution refused on that backend's records (the determinism licence, FROB-REF-562) |
   | Replay of one world outside the batch it ran in | The batch-independence gate of the numerics chapter current | The same refusal |
   | Forks that mix interventions on different model variants in one batch | The mixed-variant gate current | Not a refusal: children are grouped into one batch per variant, and the cost estimate says so |
   | A double-precision tier that runs the same model | The CPU tier in double precision admits the `ModelId` | Double-precision attribution is unavailable; the precision routing decides between the single-precision lane and FROB-REF-584 |
7. **Module layout.** `lib.rs`, `types.rs`, `scope.rs`, `defaults.rs`, `preconditions.rs`, and empty modules
   with their owners named in the module documentation, under the file names the owning beads use: `vocab`,
   `mechanism`, `diagnostic` (N27b-01); `modeldiff` (N27b-02); `perturb`, `flip`, `nullfork`, `separation`,
   `fixtures/` (N27b-03); `plan`, `intervene`, `ledger` (BD-279); `sequential` (N27bp2-01); `stats`,
   `preanalysis` (N27b-05); `label`
   (N27b-06); `precision` (N27b-07); `attribute`, `record` (BD-280); `policy`, `policy_table` (N27b-12, whose
   abstention contract BD-282 holds to its gate); `coalition`, `shapley` (BD-281, N27a-11); `rerun`,
   `eligibility` (BD-283, N27a-15); `divergence` (N27a-13); `repair` (N27b-14); `cite` (N27b-15, which also
   extends `scope`); `transcript`, `show` (BD-284); `ghost` (N27b-17); `audit` (N27b-20); `planted/` (N27b-08);
   `lane/` (N27b-23 to N27b-27). Library crates do not print; the crate has no `println!`.
8. **`CONTRACT.md`**, ten sections: purpose (the first two paragraphs above); inputs (a fork handle, typed
   interventions, a factor list, verdicts); outputs (the attribution schema, the re-run report, repair sets, the
   transcript); invariants (INV-AUTOPSY-01 to -06, stated in full); refusals (FROB-REF-580 to -584, -586, -587,
   -880 with triggers and repairs); determinism class (D0 for statistics and labels; children inherit D2 of
   their tier); evidence class of outputs (contrast `Tested`, attribution `Estimated`); validity domain (the
   model, the tier, the declared factors, the fork horizon); oracles (the hand-checkable known answers); known
   gaps (what the subsystem does not claim: not a cause in the world, not beyond the factor list, not a minimal
   repair, not necessity from a Shapley value, not a passing design, not an answer in chaotic regimes, not a
   proof, not a differentiator of the engine).

## Acceptance criteria

- [ ] `cargo build -p frob-autopsy` succeeds; `xtask check-layers` passes with the declared layer and rank;
      a planted dependency on `frob-chronicle` fails the check.
- [ ] `xtask check-contracts` accepts `CONTRACT.md` with its ten sections.
- [ ] INV-AUTOPSY-06: a compile-fail test shows that an `Attribution` cannot be built without a `Scope`, and a
      serialization test shows that `scope` lists the model, the tier, the precision and every requested factor.
- [ ] The attribution type round-trips through canonical JSON and validates against `frob.autopsy.attribution/1`.
- [ ] Every default in the table is defined once, in `defaults.rs`, with its label; a grep-style test finds no
      other literal 0.2, 0.5, 64 or 8 used as a threshold in the crate.
- [ ] `preconditions` returns the stated outcome for each of the four needs when its gate record is absent
      (tested with a registry fixture in which one record at a time is removed).
- [ ] The rank ADR is on file and the crate map lists `frob-nemesis` before `frob-autopsy` in layer 5; with it
      `xtask check-layers` accepts the `nemesis` feature. On a checkout without the ADR the crate builds with
      the `nemesis` feature off and reports the missing capability.

## Test plan

### Unit tests
`crates/frob-autopsy/tests/skeleton.rs`:
- `attribution_requires_scope` (compile-fail, by the workspace's compile-test harness).
- `scope_lists_refused_factors`: four requested factors, one refused: `scope.factors` has four entries.
- `attribution_json_round_trip`: the worked attribution (fork `f:a41c…`, tier `batch-cpu`, precision `f64`,
  horizon 2 s, 137 forks, placebo 2 of 64, three contrasts, one pair with interaction −11/32, one refused
  intervention with FROB-REF-581 and earliest valid fork tick 0) round-trips and validates.
- `evidence_is_estimated`: the claim product of an attribution has class `Estimated`, reality `no-claim`, and
  the three authorization constants false; a contrast alone has class `Tested`.
- `derived_values`: singles and pairs of 12 factors = 78; 78 × 8 + 64 + 1 = 689; 2⁵ = 32; 2¹⁰ = 1,024.
- `defaults_are_labelled`: every entry of the defaults table has a non-empty label.
- `preconditions_*`: four tests, one per need.
- `no_literal_thresholds`.

### End-to-end script and logging
None of its own. The crate's types reach the user through the attribution verbs, whose scripts log the scope
block and the evidence block of every envelope; the scripts of this unit that read them are
`scripts/e2e/autopsy_rerun.sh` (N27a-17) and `scripts/e2e/autopsy_coalitions_abstention.sh` (N27a-18).

### Known answers and negative controls
The derived values above. The interaction in the round-trip fixture is exact: with rescue rates 8/8 and 3/8 for
the singles, 8/8 for the pair and a placebo rate of 2/64, v(pair) − v(first) − v(second) + v(∅) = 1 − 1 − 3/8 +
1/32 = −11/32 = −0.34375, printed −0.34. Negative controls: an attribution serialized without its scope (schema
validation must fail); a claim product built with class `Tested` for an attribution (the constructor must not
exist). Determinism lanes: serialization bytes identical in debug and release and across platforms.

## Considerations

- The crate map gives `frob-autopsy` a size cap of 8 (thousand lines). The method is a few hundred lines per
  mechanism; a crate that reaches the cap stops taking mechanisms until an ADR moves one out.
- If the kill gate of the subsystem fires (planted-cause accuracy below 90%, or the top factor changing in more
  than 30% of cases at 10⁻⁷), coalitions and Shapley summaries are removed and the crate keeps forks,
  single-factor paired re-runs from the episode start and the heuristic ordering labelled `Estimated`. The
  module layout keeps `coalition` and `shapley` behind one feature so that removal is one switch.
- Risk RISK-50 (attribution names a cause where none is stable; likelihood medium; indicator: the placebo flip
  rate on reference failures; controls: abstention, double precision, the kill gate; owner: Autopsy lead).
- The viewer overlay of a fork on its parent and the session transcript are other beads' surfaces.
