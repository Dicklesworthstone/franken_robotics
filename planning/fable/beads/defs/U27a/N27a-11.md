## Background

Causes of a failure interact, so counterfactual debugging runs coalitions of interventions, not only single
ones. For a list N of m candidate factors, the **value of a coalition** S ⊆ N is v(S), the rescue rate when all
interventions of S are applied together: the fraction of replicate forks in which the requirement is no longer
violated. The value of the empty coalition is the placebo flip rate, v(∅) = ρ₀: the fraction of forks with no
intervention, only a round-off-scale perturbation, in which the failure disappears.

A **Shapley summary** compresses the table v into one number per factor. This bead computes it. The summary is
deliberately a second-class output:

- **ADR-AUTOPSY-05. Contrasts first; Shapley values are a summary on a budget.** The table of what each
  intervention and each pair did is the result. A Shapley summary is computed only when that table does not
  already answer the question.
- The method register of the decision cores records "coalition-value attribution as the primary output" as
  rejected: values can be negative and cannot establish necessity; it is kept as a budgeted description.

Two hand-checkable cases show what the summary cannot say, and they are this bead's known answers.

- Two factors that rescue only together (v of the pair is 1, of each single 0) and two factors that each rescue
  alone (v is 1 for either single and for the pair) both have Shapley values (½, ½). The repair sets differ: both
  factors in the first case, either one in the second. The coalition table distinguishes them; the summary does not.
- With v(∅) = 0, v({1}) = 1, v({2}) = 0 and v({1, 2}) = 0 the values are (½, −½). They sum to v(N) − v(∅) = 0 as
  they must, a single-factor repair exists, and factor 2 has a negative value because applying it cancels the
  rescue. A Shapley value can be negative and never establishes that a factor is necessary.

FACT: the sibling library's Shapley estimator is variance-based and says of itself that its effects "are not
causal effects" (`frankensim/crates/fs-uq/src/product_shapley.rs`). It is not used here. The interventional
estimator is a few hundred lines of this crate's own. Tier: Solid.

## Scope

## Technical approach

1. **Definition.** For factor i,
   φᵢ = Σ over S ⊆ N∖{i} of |S|!·(m − |S| − 1)!/m! · [v(S ∪ {i}) − v(S)],
   where m = |N|, the sum runs over the 2^(m−1) coalitions that do not contain i, and the weight is the fraction
   of orderings of N in which exactly the members of S come before i.
2. **Input.** A coalition value table `CoalitionTable { factors: Vec<FactorPath>, values: Map<Bitset, Count> }`
   with `Count { rescued: u32, of: u32 }`, so v(S) = rescued/of is an exact rational; the entry for the empty set
   is the placebo count (flips, placebo forks). Denominators may differ between entries (8 for replicates, 64 for
   the placebo); rational arithmetic makes that harmless.
3. **Exact mode (m ≤ 5).** Requires all 2^m entries: 32 coalitions at m = 5. Arithmetic is on `frob_core`
   rationals with 128-bit integer parts and overflow checks; the common denominator is at most lcm(8, 64)·5! =
   7,680, so nothing can overflow. Output values are exact rationals printed as fractions and as decimals.
4. **Why not exact beyond five.** Exact values over ten factors would take 2¹⁰ = 1,024 coalitions and leave no
   budget for a single replicate, so the stability the whole method depends on could not be measured. For m > 5
   the summary is sampled.
5. **Sampled mode (m > 5).** Draw T permutations π₁ … π_T of N from the keyed stream `autopsy.shapley` (key: the
   fork identity and the factor-list hash; counter: the permutation index), by exact integer Fisher–Yates. For
   each permutation walk its prefixes ∅ = S₀ ⊂ S₁ ⊂ … ⊂ S_m = N and credit the factor added at step j with
   v(S_j) − v(S_{j−1}). φ̂ᵢ is the mean credit of i over the T permutations.
   - The coalitions a permutation visits that are not yet in the table must be run (the caller schedules them);
     T is set by the caller's fork budget: with a budget of B forks at R replicates, at most ⌊B/R⌋ new
     coalitions, hence T = ⌊(B/R)/(m − 2)⌋ when singles and pairs are already in the table.
   - Interval: each credit lies in [−1, 1], so for every factor |φ̂ᵢ − φᵢ| ≤ √(2·ln(2m/δ)/T) with probability at
     least 1 − δ jointly over the m factors (Hoeffding's inequality with the level divided by m). DESIGN default
     δ = 0.05. The interval is reported beside every value; with small T it is wide and the summary says so.
   - Along one permutation the credits telescope to v(N) − v(∅), so the sampled values also sum to v(N) − v(∅)
     exactly. The estimator is unbiased for φ because a uniformly random ordering weights each S exactly as the
     definition does.
6. **Identities** (proof obligation **PO-AUTOPSY-01: the Shapley summary satisfies efficiency, the dummy
   property and symmetry on the computed coalition table; class sought: Tested in exact rational arithmetic on
   integer counts**).
   - Efficiency: Σᵢ φᵢ = v(N) − v(∅), with exact equality (also for the sampled estimator).
   - Dummy: if v(S ∪ {i}) = v(S) for every S not containing i, then φᵢ = 0 exactly.
   - Symmetry: if v(S ∪ {i}) = v(S ∪ {j}) for every S containing neither, then φᵢ = φⱼ exactly (exact mode).
   The function checks efficiency on every table it is given and returns an internal error, never a rounded
   value, if the residual is not exactly zero.
7. **Output.**

   ```rust
   pub struct ShapleySummary { method: ShapleyMethod, values: Vec<ShapleyValue>,
                               sum: Ratio, expected_sum: Ratio /* v(N) − v(∅) */, coalitions_used: u32,
                               note: &'static str /* fixed wording below */ }
   pub enum ShapleyMethod { Exact, Sampled { permutations: u32, delta: Ratio, half_width: f64 } }
   pub struct ShapleyValue { factor: FactorPath, value: Ratio, interval: Option<(f64, f64)> }
   ```
   Fixed note on every summary: "A description of the coalition table. Values can be negative. A value never
   establishes that a factor is necessary; read the contrasts and pairs." The summary has evidence class
   `Estimated` and inherits the scope of its attribution.
8. **Determinism.** Exact mode is class D0. Sampled mode is D0 given the table: the permutations are exact
   integer draws by address, so the same request yields the same permutations on every backend.

Module: `crates/frob-autopsy/src/shapley.rs`.

## Acceptance criteria

- [ ] The three hand cases give (½, ½), (½, ½) and (½, −½) as exact rationals; the third sums to exactly 0.
- [ ] PO-AUTOPSY-01: efficiency, dummy and symmetry hold exactly on 1,000 random integer-count tables for each
      m from 2 to 5, and efficiency holds exactly for the sampled estimator on 1,000 random tables with m from 6
      to 12.
- [ ] Exact mode refuses a table with a missing coalition (naming it) instead of imputing a value.
- [ ] The sampled estimator's interval covers the exact value (computed by brute force for m = 8) in at least
      95% of 1,000 seeded trials at δ = 0.05.
- [ ] The sampled permutations are a function of the fork identity and the factor list: identical across runs
      and platforms.
- [ ] No function of this module returns or accepts a `CauseLabel`: a compile-time check that the module does
      not import the label type.
- [ ] Every summary carries the fixed note and class `Estimated`.

## Test plan

### Unit tests
`crates/frob-autopsy/tests/shapley.rs` (all `synthetic` tables, exact arithmetic):
- `joint_pair`: v(∅) = 0, v({1}) = 0, v({2}) = 0, v({1, 2}) = 1 → (1/2, 1/2).
- `alternative_pair`: v(∅) = 0, v({1}) = v({2}) = v({1, 2}) = 1 → (1/2, 1/2).
- `negative_value`: v(∅) = 0, v({1}) = 1, v({2}) = 0, v({1, 2}) = 0 → (1/2, −1/2); sum 0.
- `counts_with_placebo`: v(∅) = 2/64, v({film}) = 8/8, v({torque}) = 3/8, v(pair) = 8/8 → φ_film = 51/64,
  φ_torque = 11/64; sum 31/32 = v(N) − v(∅).
- `dummy_third_factor`: the joint pair plus a factor that changes nothing → (1/2, 1/2, 0).
- `majority_of_three`: v(S) = 1 iff |S| ≥ 2 → (1/3, 1/3, 1/3).
- `unanimity_of_five`: v(N) = 1 and 0 elsewhere → 1/5 each; 32 table entries read.
- `po_autopsy_01_efficiency`, `_dummy`, `_symmetry` (property tests as in the acceptance list).
- `missing_coalition_refused`.
- `sampled_efficiency_exact`; `sampled_unbiased` (mean of φ̂ over 10⁴ seeds within 0.01 of the exact value for a
  fixed m = 8 table); `sampled_interval_coverage`.
- `half_width_formula`: m = 12, δ = 0.05, T = 6 → √(2·ln(480)/6) = 1.43, wider than the range of a value, and
  the summary's text says the interval is uninformative; T = 400 → 0.176.
- `permutations_are_keyed`.
- `coalition_counts`: 2⁵ = 32; 2¹⁰ = 1,024.

### Known answers and negative controls
KA-673: joint and alternative pairs have Shapley values (½, ½) in both; repair sets {1, 2}, and {1} or {2}
(exact rational; host tier); negative control: a summary that reports only Shapley values cannot tell them
apart. KA-674: negative Shapley value (½, −½) for v(∅) = 0, v({1}) = 1, v({2}) = 0, v({1, 2}) = 0; the values sum
to v(N) − v(∅) = 0 exactly; a single-factor repair exists. KA-146: the same two-case comparison stated with the
construction. CX-296: "a Shapley summary tells joint causes from alternative causes". CX-297: "a positive
Shapley value shows a factor is necessary, and values are nonnegative". CX-069: "a large Shapley value
identifies a necessary cause". Planted defects the tests must catch: weights |S|!·(m − |S|)!/m! (efficiency
fails); floating-point accumulation (the exact-zero residual check fails on the counts table); clipping negative
values to zero (the negative case fails). Determinism lanes: identical bytes in debug and release and across
platforms.

## Considerations

- Open question OPEN-AUTOPSY-2 asks whether one-at-a-time contrasts suffice, which would make pairs optional
  (owner: Autopsy lead; decided by the planted-cause gate; default: singles and pairs). If singles suffice the
  summary is needed even more rarely; nothing here changes.
- If the subsystem's kill gate fires, coalitions and Shapley summaries are removed; this module sits behind the
  feature that removal switches off.
- The interval in sampled mode covers sampling of permutations only. The uncertainty of each v(S) from its 8
  replicates is separate and is reported in the coalition table, not folded into the summary.
- A summary is never an input to a decision: the first repair to try is chosen from contrasts and pairs.
