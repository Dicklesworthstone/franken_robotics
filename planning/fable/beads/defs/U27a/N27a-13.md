## Background

Comparing two runs starts with the first place they differ. The telemetry subsystem owns the algorithm that
finds it (`first_divergence`, run by the verb `telemetry.divergence`): in exact mode it bisects over checkpoints
on the chained digest c_t = H(c_{t−1}, d_t) and then compares per-tick digests; in tolerance mode it walks blocks
of ticks chronologically with bounds [lo, hi] on the block maximum of a scaled error, descending where lo > 1,
passing where hi ≤ 1 and refining unresolved blocks before any later one; at the first divergent tick it re-runs
the tick with per-stage digests or residuals to name the first stage over tolerance; and it reports the tick,
the stage, the variables that differ under their physical names and units, and the first tick at which a
requirement atom or a task decision differs.

Autopsy owns something narrower: **the reading of first divergences on forks.** A fork differs from its parent by
construction from the intervention tick on, so "where do they differ" has a trivial answer. What an attribution
needs is the shape of the separation: which kinds of variable left the parent's trajectory first, when the
difference first reached a decision, and by when the intervention had to be in place. This bead computes that
reading and attaches it to every contrast.

It also enforces four rules for reading the result, because a divergence report is easy to over-read:

1. The first recorded discrepancy is labelled with its temporal resolution.
2. The order in which solver stages report residuals inside a tick is not evidence of a physical cause.
3. For a fork against its parent the first divergent tick is the intervention tick or later, and the useful
   output is the order in which classes of variable leave tolerance and the first decision-level divergence.
4. When topology differs between the runs, only shared interfaces and task observables are compared: a leg that
   exists in one run has no counterpart in the other.

Tier: Solid. Crate `frob-autopsy`. The report is a statement about where two computations part; it is not a
statement about cause.

## Scope

In: the fork-against-parent reader; the class-order table; the first decision-level divergence; the `acts_by`
tick of a rescuing intervention; the wording rules; the block attached to contrasts and to the re-run report.
Out: the divergence algorithm and its verb (BD-206); its gate battery (N27a-09); the growth of placebo
separation over the horizon (measured with the placebo forks, N27b-03); the ghost feed for the viewer, which
takes its first-divergence annotation per fork from this reader (N27b-17); the drawing of a fork over its
parent (the viewer's beads).

## Technical approach

1. **Inputs.** A parent episode, a child of one of its forks (by default replicate 0, the unperturbed fork of
   the intervention), the fork tick f and the intervention's first effective tick t_i ≥ f (for a scheduled change
   such as a future disturbance, t_i is the tick the change is first read).
2. **Variable classes** (DESIGN; the same classes and scales the tolerance comparison uses): base position; base
   orientation; joint positions; base linear velocity; base angular velocity; joint velocities; contact impulses
   and contact-mode set; actuator torques and currents; actuator temperatures; delivered observations;
   controller or policy actions; requirement-atom margins. For class c with scale s_c the scaled error at tick t
   is e_c(t) = max over the class's paired variables of |x_child − x_parent| / s_c.
3. **Class order.** For each class, t_c is the least tick with e_c(t) > 1, found by the tolerance-mode search
   restricted to that class (chronological refinement; an unresolved block is refined before any later block;
   missing samples give the earliest possible interval and a coverage gap, never a tick). The order is the
   classes sorted by t_c, ties in the fixed class order above. A class that stays within tolerance to the
   horizon is listed last as `within tolerance`. Each entry carries its temporal resolution (the sample period
   of the channel it was read from) and, where it came from an interval, the interval.
4. **First decision-level divergence.** The least tick at which any of these differs between child and parent:
   a requirement atom's truth value; a termination and its cause; a success predicate; the contact-mode sequence.
   Reported with its kind and name. This is the quantity the decision-level comparison of two computations reads.
5. **Stage.** At the first divergent tick the divergence service's per-stage answer is passed through under the
   field name `first_stage_over_tolerance`, with the fixed sentence "order of computation inside a tick; not
   evidence of a physical cause". The reader never ranks interventions by stage.
6. **`acts_by`** (DESIGN). For an intervention whose unperturbed fork is rescued, `acts_by` is the first tick at
   which any state class of the rescued child leaves the parent's tolerance: before it the two trajectories are
   the same to tolerance, so the same intervention applied at any tick up to `acts_by` (and no earlier than its
   own validity allows) would act on the same state. Uses: it bounds how late a fork for this factor may start,
   which is what a shortened fork window needs; and it tells the agent when the factor mattered ("the film had
   to be dry by 11.02 s"). It is `None` when the child is not rescued.
7. **Changed topology.** If the child's model differs in structure from the parent's (a structural change in a
   diagnostic forced fork, or a re-run of an edited design), variables are paired by stable identifier only;
   variables with no counterpart are listed under `unpaired` and never matched by position; the class order is
   computed on shared interfaces and task observables (base pose and twist, payload pose, requirement atoms).
8. **Sanity rule.** The first divergent tick of a fork against its parent must be at or after the fork tick. A
   divergence before the fork tick means the shared prefix is not shared: the reader returns an internal
   inconsistency and the attribution is refused as an unsound record (the null-fork refusal), never reported.
9. **Output.**

   ```rust
   pub struct ForkDivergence { child: ChildAddr, fork_tick: Tick, first_tick: TickOrInterval,
                               resolution: Qty, class_order: Vec<ClassExit>,
                               first_decision: Option<DecisionDivergence>,
                               first_stage_over_tolerance: Option<StageId>, unpaired: Vec<VarId>,
                               acts_by: Option<Tick>, coverage_gaps: Vec<TickInterval> }
   pub struct ClassExit { class: VariableClass, at: Option<TickOrInterval>, resolution: Qty, peak: f64 }
   ```
   Wire form inside a contrast: `"divergence": {"first": "10.32 s", "resolution": "0.01 s", "order":
   ["contact impulses @ 10.32 s", "joint velocities @ 10.36 s", "base orientation @ 10.58 s"],
   "first_decision": {"tick": "11.30 s", "kind": "termination", "name": "fall"}, "acts_by": "10.32 s"}`.
   The block is token-bounded: at most the first eight classes and one decision; the rest behind a handle.
10. **Where it is used.** In every contrast of an attribution (for replicate 0); in the re-run report (edited
    arm against original arm, shared interfaces only); by `explain`'s "first physical consequence of an edit"
    line, which leads with the first event at which two lineages' traces part.

Module `crates/frob-autopsy/src/divergence.rs`. Determinism: a pure function of two recorded runs; class D0 over
exact channels and the class of the comparison (tolerance) otherwise. Evidence class of the block: `Tested`
(a replayable comparison), inside an attribution that is `Estimated`.

## Acceptance criteria

- [ ] For a fork with a setpoint change first read at f + 3 ticks, `first_tick` = f + 3 and no class exits
      earlier; for a contact-affecting fork at f the first class to exit is the contact impulses at f.
- [ ] The class order on a constructed pair of runs with exits planted at known ticks equals the planted order,
      and every entry carries its resolution.
- [ ] A divergence that vanishes and returns (exits at ticks 1 and 5 of 8, agreement between) is reported at
      tick 1.
- [ ] Missing samples yield an interval and a coverage gap for the affected class, and later classes are not
      promoted ahead of it.
- [ ] The first decision-level divergence is reported with kind and name; a decision that differs while every
      state class is still within tolerance is reported as such and is flagged `boundary-sensitive`.
- [ ] `acts_by` is present exactly for rescued children; forking the same intervention at `acts_by` reproduces
      the rescue on the fixture, and the rule is reported as a measurement, not a guarantee.
- [ ] With a changed topology, unpaired variables are listed and nothing is matched by position.
- [ ] No output string of the module contains the word "cause" except in the fixed disclaimer; a test greps the
      rendered blocks.
- [ ] A divergence before the fork tick is refused as an unsound record.

### End-to-end script and logging
The block is read from the user's side by `scripts/e2e/autopsy_coalitions_abstention.sh` (N27a-18, an M3
script; the M2 divergence script `gate_autopsy_07.sh` of N27a-09 cannot call `autopsy.attribute`, which lands at
M3). For planted cases it runs `frob telemetry divergence <child> <parent>` and compares its tick with the
`divergence.first` field of the same child's contrast in `frob autopsy attribute`, asserting equality and that
the tick is at or after the fork tick, and logs both ticks, the class order and the first decision tick.

### Known answers and negative controls
KA-677 (two traces of eight ticks that differ at ticks 1 and 5: tick 1; control: the pointwise midpoint search
probes tick 3 or 4, sees agreement and reports tick 5). KA-678 (tolerance mode with a coverage gap: the earliest
possible interval and the coverage gap; control: a tool that skips the gap reports a later tick). CX-299. The
smallest case separating a state tolerance from a decision: a success predicate x ≥ 1 m with one run ending at
1.0000001 m and the other at 0.9999999 m has a state error of 2 × 10⁻⁷ m, inside any envelope, and different
verdicts; the reader must report a decision divergence with no state class having left tolerance. Planted
defects the tests must catch: class order sorted by peak error instead of exit tick; a reader that takes the
first retained sample after a gap; a reader that pairs joints by index across a topology change. Determinism
lanes: identical blocks twice, across worker counts, in debug and release.

## Considerations

- `acts_by` assumes that a state within tolerance of the parent's is the same state for the intervention's
  purposes. Near a contact transition that can be false. The field is advisory, and a shortened fork window is
  always re-verified by running the fork.
- The class list and scales are shared with the tolerance comparison; adding a class changes this block's
  schema version.
- Lineage bisection reads divergences between designs with the same trap as tick bisection: its predicate must
  be "the outcome has changed by this edit", decided by a study at each step. This reader makes no lineage
  claim.
