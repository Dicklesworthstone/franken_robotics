## Background

`autopsy.rerun` answers the question "would this design edit have avoided the failure" by the only experiment
that answers it: apply the typed edit, give the edited design its own settled start, and re-run the failing
worlds from the episode start on the same world addresses, with a sample of worlds that passed and a placebo
arm. A fork from a mid-episode snapshot answers a different question, and the hand-checkable thermal
counterexample shows by how much: a gear ratio of 16 applied at 36.95 s trips at 42.4 s, while the same ratio
from the start peaks at 82.0 °C and passes.

This bead is the script that runs that capability from the user's side through the real `frob` binary, and
the recording of GATE-AUTOPSY-06 from the receipt of its tier run (claim: Known answer; milestone M3; TARGET: the thermal counterexample's four numbers
within 0.1 s and 0.1 K; the mid-episode request is refused and the re-run passes). Tier: Solid.

## Scope

In: `scripts/e2e/autopsy_rerun.sh`, its assertions, its log, the plants of the gate's two registered controls,
and the recording of the gate's row from the receipt of its tier run.
Out: the verb (BD-283), the fixture (N27a-16), eligibility (N27a-15), the fork verb's own script (N27a-08).

## Technical approach

The script sources the shared end-to-end helper, takes `--seed` (default 1) and `--tier` (default the CPU tier
in double precision; the referee with `--tier referee`), opens a session with scopes `sim:run`, `autopsy:run` and
`design:write`, and derives every idempotency key from the seed and the step name; every call of a `run` verb
below carries it as `--key <derived key>`, and two calls whose results are compared carry different keys.

Part A, the thermal counterexample (`fixture:thermal-regear`).

1. `frob sim run` design A (gear ratio 12) on the fixture's task. Assert: exit 2 (completed with findings);
   verdict violated; failure class `thermal-limit`; failure time within 0.1 s of 37.95 s. Metric
   `trip_time_s` against 37.951 ± 0.1.
2. `frob run fork <run> --world 0 --before failure --dt 1.0s --json`. Assert: `null_replay` is `bitwise`; the
   fork tick is 36.95 s. Read the winding temperature at the fork tick with `frob telemetry query`. Metric
   `fork_temperature_c` against 113.283 ± 0.1.
3. `frob autopsy intervene <fork> --do 'model.joint[0].gear_ratio := 16' --json`. The gear change is the only
   intervention, so nothing can run: assert exit 3 with `refusal.code` FROB-REF-581, `earliest_valid_fork_tick`
   0 and forcing fields that include the actuator thermal state (the partial-refusal convention of N27-REF:
   exit 3 with `refusal` when nothing can run; BD-279's `all_refused_exit_3`). Then the same gear change beside
   an intervention that can run, a command change that is exogenous at the fork tick (the held angle's setpoint
   moved by 1°, inside the 2° band): the request completes, so assert exit 2 with the gear change as
   `refused[0]` carrying the same code, tick and fields, and the setpoint's children present.
4. The same with the forced-fork flag (`--diagnostic-force`). Assert: the child carries the class
   `diagnostic-forced`; it fails
   with class `thermal-limit` within 0.1 s of 42.4 s; its outcome appears only in the `diagnostic_forced` block.
   Metric `forced_trip_time_s` against 42.415 ± 0.1.
5. `frob autopsy rerun <run> --edit 'regear joint[0] 16' --worlds failing --json`. Assert: exit 0 or 2; a new
   `DesignId`; `reset_cache.settled` positive; `paired.fail_to_pass` is 1 of 1; evidence class `Estimated`; the
   first next action is an `eval compare` command; no task verdict field. Read the edited arm's peak winding
   temperature. Metric `rerun_peak_c` against 81.984 ± 0.1.
6. Negative control inside the script: assert that the forced fork's verdict (violated) differs from the
   re-run's (satisfied), and that the report of step 5 does not contain the forced fork's trip time. A tool that
   reported the forced fork as the answer would fail here.

Part B, a paired re-run on a walking robot.

7. Record an evaluation of the reference quadruped under its baseline controller on a task of the M3 families
   with at least 20 failing worlds and at least 64 passing worlds (the script raises the randomization and the
   world count until it has both, logging the level).
8. `frob autopsy rerun <run> --edit 'regear *.knee 16' --worlds failing,sample:64 --json`. Assert: the
   controller arm is `resynthesized-per-design`; `worlds.failing` equals the recorded count and
   `worlds.sampled_passing` is 64; the four paired counts sum to those totals; the placebo block is present; a
   label from the allowed set is present; the envelope's evidence block has class `Estimated` and reality
   `no-claim`. Then the short sample, under its own key: the same command with `sample:<p + 10>`, where p is
   the run's count of passing worlds read from the first report's `worlds.passing_available`. Assert:
   `sampled_passing` = `passing_available` = p, the flag `sample-short` is present, and the two pass counts
   sum to p (the verb takes every passing world and refuses nothing, BD-283).
9. Pairing check: for three failing worlds, query the disturbance and friction draws of both arms through the
   telemetry verb and assert digest equality.
10. Repeat step 8 with the same key: `idempotent_replay: true`, no new charge.
11. Refusal: the same edit on a run driven by the specialist flat-terrain policy. Assert exit 3, code
    FROB-REF-587, ranked repairs beginning with `--controller resynth`. Then apply the first repair and assert
    that the original design was re-run under the new controller (`not-reproduced-under-controller` present).
12. Cancellation: start a re-run over 512 worlds, cancel, and assert the job ends `cancelled` with no slot held.

Summary and gate record. The script's `summary` line carries the four measured numbers, the refusal observed
and the re-run's verdict, the commit, the hardware fingerprint and the seed. The script writes no gate status
(a test never does). The row of GATE-AUTOPSY-06 is entered from the receipt of the gate's tier run,
`FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g1_known_answers --features gauntlet-mutations --
GATE-AUTOPSY-06` (an entry that drives part A on the same fixture through the same verbs and plants the gate's
registered controls in the same run), with `cargo run -p frob-conformance --example
record_gate -- --gate GATE-AUTOPSY-06 --receipt <hash>`, by a session that did not implement the re-run
(N38b-19; the recorder refuses a self-certified pass and a pass with no control caught in the same run). The
script runs the tier entry as its last step and logs the receipt hash.

The gate's registered controls are records of `crates/frob-conformance/registry/controls.toml` of kind
`mutation` naming GATE-AUTOPSY-06, each built in its own build by the control runner (`--features
gauntlet-mutations,frob-autopsy/<feature>`, N38b-04), and this bead builds both plants in `frob-autopsy`:
KA-675's control, seeded from N27-KA's control cell, whose plant is the feature `autopsy-forced-fork-answers`
(the re-run report answers the design question with the forced fork's result, a trip at 42.4 s; the same feature
is the plant `N27a-17:autopsy-forced-fork-answers` of CX-298, N27-CX); and a control this bead registers, a
`cfg(feature = "nc-<nnnn>")` branch at BD-283's re-run start that restores the 36.95 s checkpoint under the
edited model and continues (`rerun_peak_c` leaves its tolerance).

Structured log: newline-delimited JSON at `target/e2e-logs/autopsy_rerun/<utc-timestamp>.ndjson` with a human-
readable transcript beside it. Every line: `ts`, `script` (`autopsy_rerun`), `bead` (`N27a-17`), `step`, `event`
(`start`, `cmd`, `assert`, `metric`, `refusal`, `end`). `cmd` lines: the exact command line, exit code, wall
time, and the envelope's `evidence` block (claim, class, tier, determinism, identities, seed). `metric` lines:
name, measured value, unit, reference value, tolerance, pass or fail (`trip_time_s`, `fork_temperature_c`,
`forced_trip_time_s`, `rerun_peak_c`, `fail_to_pass`, `pass_to_fail`, `placebo_rate`). `refusal` lines: code,
pointer, observed, required, first repair. Digests wherever state is compared (the paired draws). On failure:
the first differing value and the run, fork and design identities with the episode file paths. A final `summary`
line: assertions passed and failed, `gates: ["GATE-AUTOPSY-06"]`. No scene geometry or private-scene data.

## Acceptance criteria

- [ ] `scripts/e2e/autopsy_rerun.sh --seed 1` exits 0 on the CPU tier in double precision and on the referee,
      and non-zero on any failed assertion.
- [ ] The four metrics of part A are inside their tolerances; the tier entry's receipt holds the same measured
      values with the two controls caught, and the row recorded from it holds measured values, not targets.
- [ ] The short-sample call returns every passing world with the flag `sample-short`.
- [ ] The mid-episode gear change is observed as FROB-REF-581 with tick 0.
- [ ] The forced fork's outcome is confined to its diagnostic block.
- [ ] Part B's paired counts are consistent and the pairing digests are equal.
- [ ] FROB-REF-587 and its first repair are exercised.
- [ ] A second run of the script creates no new jobs and logs identical digests and metrics.
- [ ] With a planted defect (the re-run restoring the 36.95 s checkpoint under the edited model) the script fails
      at step 5 with `rerun_peak_c` out of tolerance and at step 6.

## Test plan

### Unit tests
Shell-level tests of the helpers this script adds: `within_tolerance 37.94 37.951 0.1` passes and
`within_tolerance 38.06 37.951 0.1` fails; `paired_counts_consistent` rejects counts that do not sum to the
world totals.

### End-to-end script and logging
This bead is the script; commands, assertions and log fields are in the technical approach.

### Known answers and negative controls
KA-675: trip at 60·ln(192/102) = 37.95 s; ratio 16 from the start peaks at 25 + 108·(1 − e^(−0.75)) = 82.0 °C;
ratio 16 applied at 36.95 s finds the winding at 113.3 °C and trips at 42.4 s; tolerance 0.1 s and 0.1 K;
negative control: a tool that reports the forced fork's result as the answer to the design question (step 6).
CX-298: "apply a design edit at a mid-episode fork to see whether it prevents the failure". Determinism lanes:
the script twice on one machine with identical metrics; with 1 and with all workers; debug and release
binaries; the referee and the CPU tier each against its own record, and against each other only within the
gate's tolerances.

## Considerations

- Step 3 asserts both forms of the same refusal: exit 3 with a `refusal` block when the refused intervention is
  the whole request, and exit 2 with a `refused` entry when other children run (N27-REF's partial-refusal
  convention). The refusal content (code, tick, fields, ranked repairs) must be identical in the two.
- Part B depends on real failures of a walking robot and is slower (full episodes); `--part A` runs the gate
  alone in seconds.
- The script does not call `eval compare`; it asserts that the command is offered. The study has its own script.
