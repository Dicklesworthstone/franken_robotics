## Background

Autopsy tests a proposed cause of a simulated failure by intervention: restore the world to a moment before the
failure, change one declared thing, run forward, and see whether the failure still happens. `autopsy.intervene`
is the verb that runs those experiments. It takes a **fork handle** made by `run.fork` (a parent run, one failing
world, a fork tick, and the result of the null replay) and a list of interventions `do(factor := value)`, and it
runs, in one batch of children of that world: the null fork, the placebo forks, R replicates of every intervention
and of every requested coalition, and a second replicate series at single-precision scale for whatever changed
the outcome. It writes a fork ledger from which every child can be replayed by address. It computes no
attribution; `autopsy.attribute` reads what this verb ran.

It is the third of the five moves of a debugging session (read the heuristic, fork, intervene, attribute,
re-run). Tier Solid: counterfactual replay from restorable simulator state is established practice and nothing
here is claimed as new. What the engine must supply is: an exact null replay, replay of one world outside the
batch it ran in, forks that mix interventions on different model variants in one batch, and a double-precision
tier that runs the same model. Crate `frob-autopsy`, layer 5. Serves construction C-29, decision core DC-06 and
bet BET-23 (interventional autopsy is stable enough to act on).

Decisions that bind this verb:

- **ADR-AUTOPSY-02. Classify a fork before restoring state.** Whether a change may be applied at a mid-episode
  state is decided from the model difference it makes, before any state is touched. Rejected: restore first and
  detect incompatibility while stepping, which produces a run that looks valid and is not.
- **ADR-AUTOPSY-03. Design-parameter interventions re-run from the episode start.** History-dependent state
  (winding temperature, state of charge, estimator bias, a policy's hidden state, contact memory) carries the old
  design and has no canonical image under the edit. This verb therefore refuses them mid-episode.
- Autopsy registers no fork verb. A fork point is made with `run.fork`, which classifies a change set into the
  five fork classes (continuation; exogenous; contact-affecting; information; structural or design-parameter),
  returns the earliest valid tick and the null-replay result, and with `--classify-only` restores no child that
  carries a change (the fork point is still opened and its null fork run, BD-205).

## Technical approach

1. **Surface.**
   `frob autopsy intervene <fork> [--do '<assign>' …] [--placebo 64] [--replicates 8] [--coalitions pairs|none]
   [--horizon <duration>|episode] [--series-1e-7 auto|always|never] [--replicate-by perturb|rekey:<stream>]
   [--test fixed|sequential] [--max-pairs 64] [--allow-unreachable] [--lane auto|f64|tier-f32]
   [--reuse <checkpoint field>]… [--diagnostic-force] [--plan-only] --key <k> --json`.
   MCP tool `autopsy_intervene` with the same fields (`fork`, `do[]`, `placebo`, `replicates`, `coalitions`,
   `test`, `max_pairs`, `allow_unreachable`, `lane`, `reuse[]`, `idempotency_key`, `sync_wait_ms`). The CLI
   spells the idempotency key `--key`, the generated common flag of every `run` verb; `idempotency_key` is the
   MCP property. Kind `run`: it spends compute,
   takes an idempotency key and a budget, accepts the bounded synchronous wait and otherwise returns a job handle
   with exit 8. Schemas (DESIGN names): `frob.autopsy.intervene.in/1`, `frob.autopsy.intervene.out/1`. Defaults:
   64 placebo forks, 8 replicates, `--test fixed`, horizon one second past the parent's
   failure time (TARGET), lane `auto`. `--coalitions` defaults to `pairs` under `--test fixed`: the default of
   the open question on pairs is singles and pairs until it is decided (OPEN-AUTOPSY-2, N27b-13, whose decision
   may make `none` the default), and a default request must be able to find a joint cause in one call. Under
   `--test sequential` it defaults to `none`, the only value that mode admits (`--test sequential` and
   `--max-pairs` are the sequential mode's, N27bp2-01; this bead builds `--test fixed`). `--do` is optional:
   with none,
   the verb runs the null fork and the placebo
   forks only (1 + P forks), which is how an agent measures a failure's placebo flip rate before choosing
   factors; `autopsy.attribute` then reports the flag `no-interventions-run`.
   `--lane` (DESIGN: the default follows the precision procedure, so that a failure which double precision does
   not reproduce is not refused outright while a lane could attribute it): `auto` lets the precision route
   decide (step 2c); `f64` asks for double precision only; `tier-f32` forces the single-precision lane and is
   refused with FROB-REF-724 (not implemented in this build) until N27b-24 lands. In a build without the lane,
   `auto` is the double-precision procedure.
   In a build with this crate's `conformance` feature (never a release build) `<fork>` may also be a host
   fixture handle `fixture:host/<name>[:<case>]` (N27b-03), which is how the end-to-end scripts reach the
   doubling map, the host tables, the pendulum and the threshold block through this verb.
2. **Admission, in this order; nothing is restored before step (i) has passed.**
   a. *Licence.* The parent run's determinism class must be D2 or better with a current batch-independence
      record; otherwise FROB-REF-562 (attribution or a counterfactual fork requested below class D2), exit 3.
   b. *Fork handle.* `null_replay` must be `bitwise`: a handle whose null replay is `mismatch` is refused with
      FROB-REF-583 (the null fork does not reproduce its parent; `observed` is the first divergent tick and
      stage stored with the handle), exit 3. A handle whose checkpoint contracts (physical, clock, sensor,
      policy) do not match the run is refused with FROB-REF-580, exit 3.
   c. *Precision route* (N27b-07; read from the record stored with the fork handle). `Native` (the failure was
      recorded in double precision): the children run on the recording profile. `F64` (recorded in single
      precision and decision-equivalent in double precision): the children run in double precision on
      `batch-cpu` from the widened checkpoint, with the double-precision replay as their parent. Not equivalent:
      under `--lane auto` in a build with the single-precision lane, the lane's admission decides (N27b-24);
      under `--lane auto` without the lane, and under `--lane f64`, the request is refused with FROB-REF-584,
      exit 3, with the fields and repairs of N27b-07 and `observed.lane` = `"not-built"` or `"not-requested"`.
      The route, the tier and the precision that result are written to the ledger header.
   d. *Parse and resolve* every `--do` (FROB-REF-802 on a bad string: the whole request is refused, nothing was
      charged). More than 12 factors is refused with FROB-REF-802 pointing at `do`: the budgeted mode is at most
      12 factors, singles and pairs, and no list is trimmed silently. Ranked repairs of that refusal, so that a
      longer list still has a route: (1) run the singles in groups of at most 12 with `--coalitions none`, each
      group a request of its own on the same fork handle (the null and placebo forks are read by address after
      the first group, so a later group costs only its replicates; the level of each group's tests is divided
      by the fork's whole factor family so far, step 7, so splitting a list buys no easier test); (2) then one request with `--coalitions
      pairs` for the 12 factors with the largest single contrasts, read from `autopsy.attribute`; (3) shorten
      the list by hand.
   e. *Model difference* per intervention and per coalition; FROB-REF-586 for one that changes more than one
      declared mechanism (that intervention only).
   f. *Classify* each intervention and coalition through the fork service in classify-only mode. Outcomes per
      intervention: admitted with its class and state handling; **FROB-REF-581** for a structural or
      design-parameter change at a mid-episode tick, with `earliest_valid_fork_tick` (0) and `forced_by` (the
      checkpoint fields that force the restart, for example actuator thermal state, policy history, contact
      memory); **FROB-REF-582** where the change set would reuse state it invalidates. "Reuse" is the `reuse`
      list of the `ForkRequest` this verb sends to the fork service (`frob_core::fork`, N27a-01): the checkpoint
      fields given with `--reuse`, spelled as on `run.fork` (BD-205) and empty by default. A field the change
      set invalidates (`--reuse checkpoint.contact.memory` with a wheel-radius change or a film change) is
      refused for the interventions that invalidate it, with the field as `pointer`; a field the change leaves
      valid is accepted and changes nothing, since it is restored anyway. Under `--diagnostic-force` the same
      code is returned for an edit that changes the kinematic structure or the collision geometry (step 6).
   g. *Test type.* The ledger header of every intervention set declares its test type before a fork runs. This
      bead builds the type `fixed` (a fixed replicate count and the exact test). The type `sequential` (forks
      bought in rounds of pairs, with an e-process and a stopping rule), the options `--test sequential` and
      `--max-pairs`, and the refusal FROB-REF-553 for a factor requested under one type when it was already
      run under the other are the sequential mode's (N27bp2-01, split from this bead; it depends on this bead
      and adds its step at this place of the admission order). Until it lands, `--test` accepts `fixed` only
      and `sequential` is refused with FROB-REF-724 (not implemented in this build).
   h. *Reachability* (N27b-05's pre-analysis, before any fork): for the request's R, P, m (the fork's
      `family_size` with this request counted, step 7: for a first request, the number of its admitted single
      factors) and α, the least rescue count that can be tested above the placebo is enumerated
      for every possible placebo count; if none exists (for example R = 1 against P = 64 at m = 12: the best
      case, 1 of 1 against 0 of 64, has p = 1/65 > 1/240) the request is reported `unreachable` and is not
      admitted without `--allow-unreachable` (FROB-REF-802 pointing at `replicates`, with the least R that makes
      the rule reachable as the first repair). The table's hash is written to the ledger header.
   i. *Budget.* The plan's cost estimate against the remaining budget (FROB-REF-701, exit 4, estimate attached).
3. **The fork plan.** With n admitted interventions: coalitions C = the n singles, plus all n·(n − 1)/2 pairs
   under `--coalitions pairs`. Phase A: 1 null fork + P placebo forks + R per coalition. Phase B: R forks at
   10⁻⁷ for every coalition that *changed the outcome* in phase A (at least one of its R children has a verdict
   different from the parent's). Worked counts: 12 factors with pairs = 78 coalitions; 78 × 8 + 64 + 1 = 689
   forks before phase B. Three interventions with pairs = 6 coalitions: 1 + 64 + 48 = 113, and 137 when three
   coalitions earn a second series. Two interventions with pairs: 1 + 64 + 24 = 89, and 113 with three second
   series. `--plan-only` returns the plan, the counts and the cost estimate and runs nothing.
   The plan above is the fixed test's. The sequential mode plans rounds of pairs in its place and uses this
   bead's admission, batch execution, ledger and result unchanged (N27bp2-01).
4. **Execution.** One failing world is forked K times into a batch of K children. This relies on the rule that a
   world's trajectory does not depend on the batch it ran in. Children that carry different model variants (a
   friction value, a disabled limit row, a re-initialized filter) run as per-world variants in one mixed batch.
   Each child: the fork service restores the checkpoint with the state handling of its class (continuation and
   exogenous: restored bit for bit; contact-affecting: positions and velocities restored, contact memory
   discarded, first solve cold with a raised iteration cap, labelled; information: packet queues and filter state
   re-initialized as the intervention states), the perturbation of its series is applied, and it runs to the
   horizon. A fork never mutates its parent; a child has its own address and shares the prefix by reference
   (INV-AUTOPSY-04). By default forks run in double precision on `batch-cpu`, or on the referee.
5. **Partial refusals and exit codes.** A request in which some interventions are refused under (e) or (f) and
   others run
   completes with exit 2: the refused ones are listed under `refused` with code and fields, and are excluded from
   coalitions. A request in which nothing can run is refused with exit 3 and the first refusal as `refusal`.
   Exit 0 when every requested intervention ran (and for a request with no `--do`); 2 as above, and when the
   request ran under `--allow-unreachable`; 3 on a refusal of the whole request; 4 on a budget refusal; 7 on a
   key conflict; 8 with a job handle when forks are still running at the end of the bounded wait.
6. **`--diagnostic-force`.** A structural or design-parameter factor is applied to the mid-episode state anyway,
   in a labelled diagnostic mode, because it is occasionally the question someone means to ask. Admission is
   the rule of N27a-15, enforced by the restore hook of the fork service (N27a-05): admitted when the edit
   leaves the kinematic structure and the collision geometry digests unchanged (a gear ratio, an actuator card
   parameter, a gain, a mass); refused with FROB-REF-582 when either changes (a wheel radius, an added limb).
   Every such child carries the class `diagnostic-forced`; its outcome is printed in a block of its own,
   `diagnostic_forced`; it can never be labelled a cause and never enters a repair set.
7. **The fork ledger** (schema `frob.autopsy.forkledger/1`, DESIGN). Header: parent run, world address, fork
   tick, identities, tier, profile, precision, determinism class, horizon, the plan. One row per child: child
   address, series and index, canonical interventions and change-set hash, model-difference hash, fork class and
   state handling, perturbation (coordinate class, sign, applied relative size; never raw private state), verdict
   (class, binding atom, time), final chain digest, `unknown` reason if any, cost. The ledger is an artifact in
   the store with its evidence identifier; it is what lets a transcript replay every fork from its address.
   **One ledger per intervention set; children shared by address (DESIGN).** Each request writes the ledger of
   its own intervention set: the header with its plan, counts and test type, and the rows of that plan's
   children. The ledger's identifier (`ledger` in the result) is the BLAKE3 hash of its canonical header and
   rows, so two requests with the same resolved content on one fork denote the same set whatever their keys
   (as long as the fork's factor family, below, has not grown between them). A
   child is the same experiment wherever it is asked for (its address is a function of its own specification,
   N27a-04), so a child that an earlier request on this fork already ran is read by address and not run again:
   its row is listed with the others, `forks_run` counts the plan's children as before, and the envelope's cost
   block says how many were bought and how many read (`forks_bought`, `forks_read`). The fork point keeps the
   list of its intervention sets in the order they completed; `autopsy.attribute` and `autopsy.repair` read the
   latest by default and any other with `--ledger <id>`.
   **The factor family of a fork (DESIGN).** The level of every test is divided by the number of factors
   (INV-AUTOPSY-05). If that number were counted per request, an agent could run twelve factors as twelve
   requests and have each tested at the undivided level. The divisor is therefore the fork's, not the
   request's: the header records `family_size`, the number of distinct single factors (by canonical string)
   run from this fork up to and including this request, under either test type, and that number is the m of
   the reachability enumeration, of the exact test's level α/m and of the sequential threshold m/α for this
   set. It is fixed when the set is planned and never changes afterwards, so a read of the set stays a pure
   function of its ledger. A first request has `family_size` equal to its own count of single factors; a
   second request with the same factors has the same size; a request repeated under a new key after other
   factors were run is a new set at the larger size (under its old key it returns the stored answer, as any
   idempotent replay does); each group of the grouped-singles route of step
   2d is tested at the size reached so far, and the request that follows them at the full size.
   Reason for sets and a stated rule at all: an agent runs more than one set from one fork
   (a placebo-only probe and then its factors; grouped singles and then pairs; the one-at-a-time arm of the
   planted-cause gate), and without a stated rule "the fork's ledger" has no meaning. A test that compares the
   same child in two arrangements (alone and in a batch) therefore uses two state roots, as the null-fork gate
   does (N27a-06).
8. **Result.** `{ "fork", "forks_run", "series": {…counts…}, "placebo": {"n", "flips", "rate"}, "refused": [{do,
   code, earliest_valid_fork_tick, forced_by}], "ledger", "tier", "precision", "lane" }`, with the envelope's
   evidence block (a contrast is a replayable experiment, class Tested on its tier), cost and budget, and
   `next_actions`: `frob autopsy attribute <fork>`; for each FROB-REF-581, the `frob autopsy rerun` command that
   tests the edit from the episode start.
9. **Idempotency, cancellation.** Same key and same resolved content returns the stored answer
   (`idempotent_replay: true`); a different content under the key is a conflict (FROB-REF-803, exit 7).
   Cancellation drains at a tick boundary and finalizes; a cancelled or budget-stopped job publishes no partial
   result (FROB-REF-702) and leaks no device resource.
10. **Layout.** `crates/frob-autopsy/src/plan.rs`, `intervene.rs`, `ledger.rs`. The verb's registry row is
    VERBS-autopsy's (checked against this handler by N27b-16). What this bead defines beyond the row as first
    entered, for the row to carry: `--reuse`; the default `pairs` of `--coalitions`; the default `auto` of
    `--lane`; FROB-REF-584 among the row's refusals.

## Acceptance criteria

- [ ] Seed done-condition, first part: the null fork run by this verb has digests identical to replay of the
      parent, and every placebo child is bit-identical to the replayed state at the fork tick before its
      perturbation and differs after it in exactly one coordinate by a relative size in
      [10⁻¹², 2 × 10⁻¹²). A world forked alone and in a batch of 512 children gives identical digests. The
      reading on 1,000 failing worlds is made by the script of N27b-04, which depends on this bead.
- [ ] Seed done-condition, second part: `--do 'model.joint[*.knee].gear_ratio := 16'` at a mid-episode fork is
      refused with FROB-REF-581, `earliest_valid_fork_tick: 0` and a `forced_by` list that contains the actuator
      thermal state, the policy history and the contact memory; the other interventions of the request run and
      the exit code is 2.
- [ ] Fork counts equal the plan: 689 for 12 factors with pairs before the second series; 113 and 89 for three
      and two interventions with pairs.
- [ ] The second series runs for exactly the coalitions that changed the outcome.
- [ ] The parent's stored chunks hash identically before and after the verb (INV-AUTOPSY-04).
- [ ] Every child in the ledger replays by address to its recorded final digest.
- [ ] FROB-REF-562, -580, -582, -583, -584, -586, -701 and -802 are each raised by a planted case with the
      fields above; `--test sequential` is refused with FROB-REF-724 in a build without the sequential mode.
- [ ] Thirteen factors are refused with FROB-REF-802 whose first repair is the grouped-singles request; the
      repair, executed as two groups of 7 and 6 with `--coalitions none`, is admitted, and the second group
      buys no null or placebo fork.
- [ ] The same request content under a second key buys no fork and returns the same `ledger` identifier and
      the same `result`; a second, different intervention set on the same fork leaves the first readable with
      `--ledger`.
- [ ] A single-precision failure that is decision-equivalent in double precision runs its children in double
      precision from the widened checkpoint; one that is not equivalent is refused with FROB-REF-584 under
      `--lane f64` (`observed.lane = "not-requested"`) and, in a build without the lane, under `auto`
      (`"not-built"`).
- [ ] With no `--coalitions`, a request plans singles and pairs.
- [ ] `family_size` in the header counts the distinct single factors run from the fork so far: three requests
      of one factor each record 1, 2 and 3, and the third is tested at α/3; the first request repeated under
      its own key returns the stored set with size 1, and repeated under a new key it is a new set of size 3.
- [ ] With no `--do`, the verb runs exactly 1 + P forks and records the placebo flip rate.
- [ ] An unreachable rule (R = 1, P = 64, 12 factors) is refused before any fork runs, and admitted with
      `--allow-unreachable`, which records `unreachable: true` in the ledger header.
- [ ] `frob autopsy intervene --json` and the MCP tool return the same envelope; cancellation is tested (request,
      drain, finalize); a CPU reference path exists (the default tier); `CONTRACT.md` documents the verb.

### End-to-end script and logging
`scripts/e2e/autopsy_intervene.sh` (N27b-04): `frob run fork`, then `frob autopsy intervene`, on 1,000 failing
worlds of a recorded evaluation; asserts the two seed conditions, the fork counts and the no-`--do` request,
and logs (NDJSON lines of the shared helper, with the envelope's evidence block) per world
the null digests, placebo counts, refusal fields and fork counts. (The same script's sequential step belongs to
N27bp2-01.)

### Known answers and negative controls
KA-671 (null fork identical; stripped packet queue refused), KA-676 and CX-321 (warm-start graft refused with
FROB-REF-582), KA-145. Metamorphic relation MR-08: the empty intervention replays bit for bit; a setpoint change
at tick t reuses the prefix to the snapshot before t; a child has its own address and reads its parent's
streams unless a stream is re-keyed (stream modes `shared` and `rekey`, N27a-04), so "fresh streams" holds only
for a re-keyed replicate. Negative
controls: a batch whose children share a reduction (alone-versus-batch digests differ); a verb that applies a
gear change mid-episode without the flag (the 581 test fails); a ledger that omits perturbation draws (replay of
a perturbed child misses its digest). Determinism lanes: twice on one machine; across worker counts; debug and
release on `batch-cpu`; on each device family against class D2.

## Considerations

- OPEN-AUTOPSY-4 (owner: Chronicle lead; blocks nothing): the size of the snapshot reservoir on each device.
  Default: sized by the budget estimator; every other fork point is reconstructed by replay from the world
  address, at the cost of one episode prefix on the CPU. At tens of kilobytes per world, twenty snapshots over
  two seconds for 8,192 worlds would take about 4.9 GB, which is why full-state rings are kept for a reservoir.
- Rejected: copy-on-write device state for forks. Copying 8,192 worlds at 30 kB is 0.25 GB; copying is not the
  bottleneck.
- A request with 12 factors and pairs is a small batch on any tier (forks of two or three seconds).
- OPEN-AUTOPSY-1 sets the defaults of `--placebo` and `--replicates`; OPEN-AUTOPSY-2 sets the default of
  `--coalitions` (both decided in N27b-13).
- If KILL-AUTOPSY fires (decision N27b-11), `--coalitions pairs` is removed from the verb and its registry row;
  forks from snapshots remain as described experiments (counts, flip rates, `Estimated`, no labels of cause),
  and the primary answer to "which repair first" becomes single-factor paired re-runs from the episode start
  (`autopsy.rerun`), ordered by the first-anomaly heuristic.
