## Background

Debugging by intervention is useful to an agent only if it is a short, regular sequence of calls with bounded
outputs, and only if the whole sequence can be replayed by someone else. The workflow is **five moves: read the
heuristic, fork, intervene, attribute, re-run.** Each move is one verb with a bounded output, and the session is
recorded as a transcript, schema `frob.autopsy.transcript/1`, that replays every fork from its address.

A session on a quadruped in the wet-floor kitchen scenario (a generated commercial kitchen whose floor has a wet
patch governed by the film-friction law) fixes the shape; its numbers are illustrative:

```text
frob explain run r:19e2 --budget 600
    # first anomaly (Estimated): slip at the left front foot at 11.1 s, 0.2 s before the fall
frob run fork r:19e2 --world 311 --before failure --dt 1.0s --key fk-1 --json
    # fork f:a41c at 10.30 s; class continuation; null replay bitwise on gpu-cuda;
    # double precision on batch-cpu is decision-equivalent (fall at 11.31 s against 11.30 s)
frob autopsy intervene f:a41c --placebo 64 --replicates 8 --coalitions pairs --key aut-1 --json
        --do 'scene./floor/patch[galley-2]/film := dry'
        --do 'model.joint[*.knee].torque_limit := off'
        --do 'sense.imu.latency := 0 s'
        --do 'model.joint[*.knee].gear_ratio := 16'
    # exit 2: three interventions ran from the fork; gear_ratio is a design parameter and was
    # refused with FROB-REF-581 (earliest valid fork tick 0; forced by actuator thermal state,
    # policy history and contact memory)
frob autopsy attribute f:a41c --json
    # film := dry is but-for; torque_limit := off contributes; latency names nothing
frob autopsy rerun r:19e2 --edit 'regear *.knee 16' --worlds failing,sample:64 --key rr-1 --json
    # new design d:8e77 with its own reset cache; baseline controller re-synthesized;
    # 23 failing worlds and 64 sampled passing worlds on the same addresses:
    # 17 of 23 now pass; 63 of 64 still pass, 1 new timeout; label contributing, Estimated
frob eval compare quad-a quad-a@regear --task kitchen-tray --key cmp-1 --json
    # the verdict comes from a study, not from the autopsy
```

What the transcript fixes is the shape: **the heuristic proposes, forks test, design parameters go back to the
start, and a study decides.** `autopsy.show` is the read verb that returns the transcript of a session,
token-budgeted. The viewer can overlay a fork on its parent as a ghost, synchronized on the fork tick (the feed
for that overlay is a separate bead).

Tier Solid for the tools. The claim that an agent repairs designs in fewer turns with these tools than with logs
is a HYPOTHESIS with its own gate at M4 (GATE-AUTOPSY-08: on the planted-defect designs of the corpus, agents
given Autopsy reach an accepted repair in at most one third of the serial turns of agents given logs and
`explain` alone, pre-registered, with an anytime-valid verdict). This bead builds what that comparison will use
and claims nothing about turns. Crate `frob-autopsy`, layer 5; lever "explain by intervention" of the ten-fold
thesis; bet BET-23.

## Technical approach

1. **What a transcript is.** A typed, append-only view of one debugging session: all calls of `explain.run`,
   `run.fork`, `telemetry.divergence`, `autopsy.intervene`, `autopsy.attribute`, `autopsy.repair`,
   `autopsy.rerun` and `eval.compare` that concern one failing run within one caller session. Its identifier is
   `a:<BLAKE3(session ‖ run ‖ first fork)>`. It is built from the session's captured verb calls; the Autopsy
   verbs add their typed summaries.
2. **Schema `frob.autopsy.transcript/1`.**
   ```json
   { "schema": "frob.autopsy.transcript/1", "session": "a:5c1e…", "run": "r:19e2…",
     "identities": {"model": "m:…", "scene": "s:…", "task": "t:…", "policy": "p:…", "tier": "gpu-cuda"},
     "entries": [
       {"seq": 1, "move": "heuristic", "verb": "explain.run", "request": "<canonical command>",
        "result_digest": "b3:…", "summary": {"first_anomaly": "slip, left front foot, 11.1 s", "class": "Estimated"}},
       {"seq": 2, "move": "fork", "verb": "run.fork", "request": "…", "result_digest": "b3:…",
        "summary": {"fork": "f:a41c…", "world": 311, "tick": "10.30 s", "class": "continuation",
                    "null_replay": "bitwise", "double_precision": "decision-equivalent"}},
       {"seq": 3, "move": "intervene", "verb": "autopsy.intervene", "request": "…", "idempotency_key": "…",
        "result_digest": "b3:…", "summary": {"ledger": "b3:…", "forks_run": 137, "refused": ["FROB-REF-581"]}},
       {"seq": 4, "move": "attribute", "verb": "autopsy.attribute", "request": "…", "result_digest": "b3:…",
        "summary": {"outcome": "but-for", "named_set": ["…film := dry", "…torque_limit := off"], "placebo_rate": "2/64"}},
       {"seq": 5, "move": "repair", "verb": "autopsy.repair", "request": "…", "result_digest": "b3:…",
        "summary": {"repair_sets": [["…film := dry"]]}},
       {"seq": 6, "move": "rerun", "verb": "autopsy.rerun", "request": "…", "result_digest": "b3:…",
        "summary": {"design": "d:8e77…", "failing_now_pass": "17/23", "passing_still_pass": "63/64",
                    "label": "contributing", "class": "Estimated"}},
       {"seq": 7, "move": "study", "verb": "eval.compare", "request": "…", "result_digest": "b3:…",
        "summary": {"study": "…", "verdict": "…"}} ],
     "evidence": {"class": "Estimated", "scope": "cause in the model at this tier, among the listed factors"},
     "authorization": {"execution_authorized": false, "hardware_safety_signoff": false,
                       "sim_to_real_certified": false} }
   ```
   `move` takes one of eight values, one per captured verb: `heuristic` (`explain.run`), `fork` (`run.fork`),
   `divergence` (`telemetry.divergence`), `intervene`, `attribute`, `repair`, `rerun` (the Autopsy verbs) and
   `study` (`eval.compare`); an unknown value is a schema error.
   `request` is the canonical command with every mutable name resolved to its immutable identifier, so it can be
   executed again. `result_digest` is the BLAKE3 of the canonical result (the envelope's `result`, without cost,
   timing and trace identifiers). Fork ledgers are referenced by hash; every fork in them is replayable from its
   address.
3. **Bounded moves.** Each move's envelope is bounded: `explain.run` and `autopsy.show` by a token budget;
   `run.fork` returns one handle and one classification row per proposed change; `autopsy.intervene` returns
   counts, never per-fork rows; `autopsy.attribute` returns one row per factor and pair (at most 12 + 66) and
   paginates beyond; `autopsy.repair` returns sets; `autopsy.rerun` returns paired counts. Every result ends with
   `next_actions` naming the next move, so an agent can follow the chain without documentation.
4. **`autopsy.show`.** `frob autopsy show <session|fork|run> [--budget <tokens>] [--format summary|full|script]
   [--compare <session2>] [--cursor <c>] --json`; MCP tool `autopsy_show`. Kind `read`.
   - `summary` (default, budget 600 tokens): one line per move with its key outcome and a handle for drill-down;
     a larger budget adds the contrast table, then the refused interventions, then the repair sets. The answer
     states what it left out and the handle that returns it; nothing is cut silently.
   - `full`: the transcript object, paginated by entries.
   - `script`: the entries' canonical commands as a shell script that re-executes the session in a namespace
     given by the caller (each `run` verb with its recorded idempotency key suffixed by the namespace).
   - `--compare`: entry-by-entry comparison of two transcripts: equal verbs, equal canonical requests modulo
     namespace, equal `result_digest`. It returns `identical: true`, or the first differing entry with the first
     differing field of the two results; exit 0 when identical and 2 when not.
   Two further formats are added to this verb by the beads that build what they show, each a read of stored
   objects: `ghost` (the counterfactual-ghost manifest, with `--max-forks` and `--include-forced`, N27b-17) and
   `crosscheck` (the agreement ledger of the single-precision lane, N27b-26).
5. **Replay to the same repair.** Executing the script of a recorded session in a fresh namespace recomputes
   every fork from its address (nothing is copied from the original store), and `--compare` of the original and
   the replayed transcript must report identical digests for the fork, intervene, attribute and repair entries;
   in particular the repair sets are equal. This holds across machines of one device family under class D2, and
   on `batch-cpu` everywhere.
6. **Writer rules.** Entries are appended in call order with a sequence number; a refused call is an entry with
   its refusal code; a retried idempotent call does not add an entry (`idempotent_replay` answers are
   de-duplicated by key). A transcript carries the evidence block of its weakest entry, which is `Estimated` as
   soon as it contains an attribution, through the class rule of N27b-15 (no path to a stronger class). A
   transcript is a view: importing one creates no evidence.
   `Transcript` has no constructor that omits its `Scope` (the type of N27a-10, taken from the session's fork and
   attribution: model, tier, precision, factor list); its text form is the fixed scope text of N27b-15, and
   every `autopsy.show` envelope carries N27b-15's `non_claims` constant (INV-AUTOPSY-06 for this bead's
   outputs).
7. **Layout.** `crates/frob-autopsy/src/transcript.rs`, `show.rs`; the verb's registry row is VERBS-autopsy's
   (checked against this handler by N27b-16); schema file
   `schemas/frob.autopsy.transcript.1.json`.

## Acceptance criteria

- [ ] Seed done-condition, first part: a recorded transcript of the kitchen session, replayed from its script in
      a fresh namespace, yields a transcript that `--compare` reports identical, with the same repair set.
- [ ] Seed done-condition, second part: citing an attribution of the session as an established cause is refused
      with FROB-REF-880 (the guard is N27b-15; the refusal is asserted here from the session's own attribution).
- [ ] A transcript validates against its schema; every `request` re-executes; every fork in every referenced
      ledger replays from its address to its recorded digest.
- [ ] `autopsy.show --budget 600` returns at most the budget (measured with the project's token counter), states
      what it omitted and gives handles; `--budget 200` still returns one line per move.
- [ ] A planted divergence is caught: with one fork's verdict altered in the replay store, `--compare` returns
      the entry and the field that differ, exit 2.
- [ ] A refused move and an idempotent retry appear as one entry each and zero entries, respectively.
- [ ] `autopsy.show` is a `read` verb (the store digest is unchanged by it), reachable through `frob --json` and
      `frob-mcp`.
- [ ] `crates/frob-autopsy/CONTRACT.md` documents the transcript schema, what enters a transcript, the replay
      procedure and its determinism class; outputs carry the claim product and the no-authorization flags.
- [ ] Every transcript carries a scope (a build with the scope made optional fails `transcript_scope_required`),
      and every `autopsy.show` envelope carries the `non_claims` list of N27b-15.

## Test plan

### Unit tests
`crates/frob-autopsy/tests/transcript.rs`, `show.rs`:
- `schema_golden`: the seven-entry transcript above validates and round-trips.
- `request_is_canonical`: mutable names are resolved; two spellings of one request give one string.
- `result_digest_excludes_cost_and_trace`: two executions with different wall time have equal digests.
- `retry_adds_no_entry`; `refusal_is_an_entry`.
- `show_budget_levels`: 200, 600 and 2,000 tokens → one line per move; plus contrasts; plus refused and repairs;
  each within budget, each with `omitted` handles.
- `show_script_reexecutes` (real forks on fixture 2): the script runs in a fresh namespace and `--compare` is
  identical.
- `compare_reports_first_difference` (a replay store with one altered verdict).
- `evidence_is_weakest_entry`.
- `transcript_scope_required` (compile-fail: no constructor without a `Scope`; property: every generated
  transcript has model, tier, precision and factor list); `show_envelope_non_claims`.
- `show_is_pure`.

### End-to-end script and logging
`scripts/e2e/autopsy_session.sh` (N27b-18) runs the five moves and the repair on a planted kitchen failure,
records the transcript, replays it and compares. Logged per entry: `seq`, move, verb, exit code, `result_digest`;
for the comparison: `identical`, or the first differing entry and field.

### Known answers and negative controls
The shape of the worked session: the gear-ratio intervention is refused at the fork with FROB-REF-581 and
earliest valid tick 0, and reappears as an `autopsy.rerun`; the verdict comes from `eval.compare`. Negative
controls: a transcript writer that stores mutable names (the replay resolves to a newer design and digests
differ); a `show` that truncates without saying so (the budget test checks `omitted`); a replay that copies
ledgers instead of recomputing forks (caught by running it against an empty store). Determinism lanes: record
and replay on one machine; with 1 and 16 workers; on `batch-cpu` across the two platforms; on a device family
against class D2.

## Considerations

- A transcript of a private scene contains scene path names inside intervention strings. It inherits the
  privacy class of its scene: it stays in the owner's namespace, and exporting it follows the scene's export
  rule.
- The seven moves in the example are not a required order. The writer records what was called; the
  documentation for agents presents the five-move order as the default path.
- If GATE-AUTOPSY-08 fails at M4, the tools stay, because they are cheap and exact, and the claim about turns is
  withdrawn. If KILL-AUTOPSY fires, the transcript keeps its schema and loses the coalition entries.
- Transcript size: entries hold digests and short summaries; a session of ten moves is a few kilobytes. Ledgers
  are stored once and referenced.
