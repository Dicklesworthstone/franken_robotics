## Background

An interventional contrast means something only if the intervention changed one thing. If "make the floor dry"
silently also restores depth-camera returns that the wet film had removed, a rescue cannot be attributed to
friction: two mechanisms moved together. The program's rule is invariant **INV-AUTOPSY-02: every intervention
changes one declared mechanism, and its model difference is stored with the fork.** The declared mechanism is a
claim made by the factor (N27b-01); the model difference is the check that the claim is true. A change that
would alter two mechanisms is **split into two interventions or refused (FROB-REF-586)**.

The model difference is also the record that makes a fork auditable later: anyone holding the parent's
identities and the stored difference can rebuild the child's model and scene without trusting the text of the
`do(…)` string.

Design decision and rejected alternative. The difference is computed on the compiled artifacts (the compiled
model and the compiled scene), not on the source text of the edit. Rejected: trusting the edit's own declaration
of what it changes. A declaration is an intention; the compile pipeline is where an innocent-looking edit turns
out to move a second mechanism (a material with a film changes the contact row and the optical return model).
Tier Solid; crate `frob-autopsy`, layer 5. Serves construction C-29, whose *action* step is "a typed intervention
do(X := x) that changes one declared mechanism and is recorded as a model diff".

## Scope

In: computing the model difference of one resolved intervention against the fork's identities; mapping changed
fields to mechanisms; the one-mechanism check; automatic splitting where the factor declares a split; the refusal
FROB-REF-586 with its fields; storing the difference with the fork; the difference of a coalition (several
interventions applied together).
Out: parsing and resolving factors (N27b-01); classifying the change set into a fork class (the fork service,
BD-205, which reads the difference this bead produces); applying the difference to state (BD-205, BD-279).

## Technical approach

1. **Inputs.** A `ResolvedFactor` with its value; the identities of the fork (model, scene, task, policy,
   controller); read access to the compiled model and compiled scene by content hash.
2. **Compute.** Apply the factor to a copy of the *source* (the world edit to the scene description, the typed
   design edit to the design term, the diagnostic factor to the run configuration), compile the affected products
   through the memoized pipeline, and compare old and new products field by field. The result:
   ```rust
   pub struct ModelDiff {
       before: Identities, after: Identities,          // model, scene, controller, policy, step plan
       changed: Vec<ChangedField>,                     // path, owning mechanism, before hash, after hash
       mechanisms: BTreeSet<MechanismId>,              // the set of mechanisms that own a changed field
       state_layout_changed: bool,                     // any change of state dimension or meaning
   }
   // model_diff: Blake3 = hash of the canonical serialization of ModelDiff
   ```
   Every compiled field is owned by exactly one mechanism in `registries/autopsy/mechanisms.toml`; a changed field
   with no owner is a registry defect and is refused as an internal fault (never silently ignored).
3. **The one-mechanism check.** `mechanisms` must equal `{declared mechanism}`.
   - Equal: accept; `Intervention.model_diff` is set.
   - A strict superset, and the factor's registry row declares a split (for example the material edit
     `film := dry` declares the parts `contact.friction` and `sensing.optics`): the intervention is **split** into
     one intervention per mechanism, each with its own difference, named `<factor>#<mechanism>`; both are returned
     to the caller, which runs them as separate interventions and, if coalitions are on, as a pair. A split part
     is realized by applying only the fields of that mechanism (dry friction with wet optics, and the reverse);
     such a part is labelled `diagnostic` when no physical object could have that combination.
   - A strict superset with no declared split: refuse with **FROB-REF-586** (an intervention changes more than
     one declared mechanism). Envelope `refusal`: `pointer` = the `do` string; `observed` = the list of mechanisms
     with the changed fields of each; `required` = "exactly one mechanism"; `retry: after-change`; ranked repairs:
     (1) the split interventions that would be admitted, written out as `--do` strings; (2) a narrower factor path
     that touches one mechanism; (3) declare the split in the mechanism registry if the two parts are separately
     meaningful. Exit 3 when it is the only intervention; when other interventions of the same request ran, the
     verb completes with exit 2 and lists this one under `refused`.
   - Empty (the value equals the current value): the intervention is the empty intervention; it is reported as
     `no-op` and not run, since the null fork already covers it.
4. **Coalitions.** The difference of a coalition S is the difference of applying all of S together, computed the
   same way; its mechanism set must equal the union of its members' mechanisms. A coalition whose joint
   difference touches a mechanism none of its members declares (an interaction inside the compile pipeline) is
   refused with FROB-REF-586 naming the extra mechanism.
5. **What the fork service reads.** `state_layout_changed` and the owning mechanisms are the inputs from which
   the fork service decides the class, the earliest valid tick and the fields that force a restart. This bead
   computes facts; it does not classify.
6. **Storage.** The serialized `ModelDiff` is stored in the fork ledger entry of every child that carries the
   intervention (BD-279) and is addressable by its hash; it carries no scene geometry beyond the changed fields,
   so a private scene's content is not copied into ledgers (hashes and field paths only).
7. **Module layout.** `crates/frob-autopsy/src/modeldiff.rs`; determinism class D0 (hash comparison of compiled
   products); evidence: the difference is a fact about two compiled artifacts, class Tested by its unit tests.

## Acceptance criteria

- [ ] INV-AUTOPSY-02 holds as a property: for every accepted intervention the stored difference touches exactly
      the declared mechanism (property test over generated factors on two robots and three scenes).
- [ ] The wet-floor case: `film := dry` on a patch with a film touches `contact.friction` and `sensing.optics`;
      with the declared split it returns two interventions; with the split removed from the registry it is
      refused with FROB-REF-586 listing both mechanisms and offering the two split strings as the first repair.
- [ ] A coalition with a hidden interaction mechanism is refused; a coalition without one is accepted with the
      union of its members' mechanisms.
- [ ] Rebuilding the child's identities from the parent's identities and the stored difference reproduces
      `after` exactly.
- [ ] A changed field with no owning mechanism is refused as a registry defect, with the field path.
- [ ] The refusal is reachable through `frob autopsy intervene --json` with the fields of step 3.

## Test plan

### Unit tests
`crates/frob-autopsy/tests/modeldiff.rs` (real compile pipeline on small fixtures):
- `single_mechanism_friction`: `scene./floor/patch[strip]/friction := 0.8` on the split-grip landing (strip
  friction 0.25) → one changed field, mechanism `contact.friction`, `state_layout_changed = false`.
- `wet_floor_splits`: film patch with an optical effect → two interventions `…#contact.friction` and
  `…#sensing.optics`, each with a one-mechanism difference.
- `wet_floor_refused_without_split`: same input, split undeclared → FROB-REF-586, `observed` lists both
  mechanisms, repairs[0] contains two `--do` strings.
- `noop_value`: assigning the current value → `no-op`, no difference stored.
- `design_factor_changes_layout`: `model.joint[*.knee].gear_ratio := 16` → new `DesignId` and `ModelId`,
  mechanism `actuator.transmission`, facts consistent with a structural change (`before.model ≠ after.model`).
- `coalition_union`: {friction, door closer torque} → mechanisms {`contact.friction`, `fixture.dynamics`}.
- `coalition_hidden_interaction` (`synthetic` registry row that makes two edits jointly change a third field) →
  FROB-REF-586 naming the third mechanism.
- `inv_autopsy_02` (property, 500 generated interventions): accepted ⇒ `mechanisms = {declared}`.
- `diff_rebuilds_child`: apply(before, diff) = after (hash equality).
- `orphan_field_refused`.

### End-to-end script and logging
`scripts/e2e/autopsy_refusals.sh` (N27b-19) triggers FROB-REF-586 from the CLI on the wet-floor patch and asserts
the envelope fields; `scripts/e2e/autopsy_intervene.sh` (N27b-04) logs, for every intervention it runs, the
difference hash, the mechanism and the count of changed fields.

### Known answers and negative controls
The wet-floor split is the Autopsy specification's own case (a wet floor changes both friction and depth returns). Negative
controls: a difference that compares source text instead of compiled products (misses the optical change: the
split test fails); a check that accepts a superset (the property test fails); a difference that omits the
after-identities (the rebuild test fails). Determinism: the difference hash is identical twice on one machine,
across worker counts and across platforms.

## Considerations

- Cost: one memoized recompile per intervention, shared across all replicates of that intervention. For twelve
  factors with pairs this is 78 compiles of small deltas; the compile cache makes repeats free.
- A split part that no physical object could realize (dry friction under wet optics) is a legitimate diagnostic
  and is labelled so; it never enters a repair set.
- Granularity of mechanisms is a judgement recorded in the registry. Too coarse hides confounds; too fine makes
  every edit a coalition. The registry is reviewed when FROB-REF-586 fires on an edit a user considers atomic.
