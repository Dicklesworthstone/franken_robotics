## Background

Once interventions have been run from a fork, an agent wants the smallest change that makes the failure go
away. `autopsy.repair` answers with **repair sets**: sets of interventions under which the failure no longer
occurs, each 1-minimal, meaning that removing any single intervention from the set brings the failure back. The
mechanism is the shrinker used for adversarial worlds (delta debugging over a list of atomic edits), run here
over the intervention set with the test "the failure no longer occurs".

Three limits are part of the definition and are printed with every result:

- **Not a minimal repair in any stronger sense.** Repair sets are 1-minimal under the tested interventions.
  Rescue sets are not monotone: with v(∅) = 0, v({1}) = 1, v({2}) = 0 and v({1, 2}) = 0, intervention 1 alone
  repairs and adding intervention 2 cancels the rescue. A search that assumes "more interventions rescue more"
  misses {1}.
- **Not a passing design.** A rescue at a fork is not evidence that an edited design passes the task; that takes
  a paired re-run from the episode start and then a study.
- **Diagnostic interventions are not repairs (ADR-AUTOPSY-06).** Switching a torque limit off locates a cause;
  it is not an edit anyone can build. The two kinds are typed apart.

The two hand-checkable cases that fix what the verb must return: two factors that rescue only together give the
repair set {1, 2}; two factors that each rescue alone give the repair sets {1} and {2}. Their Shapley values are
identical, (½, ½); the repair sets differ. Tier Solid (the delta-debugging algorithm is standard; its use over
interventions is a re-application). Crate `frob-autopsy`, layer 5. Constructions C-28 (minimal counterexample by
delta debugging) and C-29. It is the verb behind the transcript's claim "a recorded transcript replays to the
same repair".

## Technical approach

1. **Surface.** `frob autopsy repair <fork> [--ledger <id>] [--max-tests <n>] [--include-diagnostic] --key <k>
   --json`; MCP tool `autopsy_repair` (the MCP property of the key is `idempotency_key`; `--key` is the
   generated common flag of every `run` verb). Kind `run` (it may buy forks): idempotency key, budget, bounded
   wait, job handle with exit 8. Schemas `frob.autopsy.repair.in/1` and `frob.autopsy.repair/1` (DESIGN names).
   The candidate set is the admitted interventions of one intervention set of the fork: the latest by default,
   or the one named with `--ledger <id>`, the same rule as `autopsy.attribute` (BD-279, BD-280); the result
   prints the `ledger` it read. Forks this verb buys are written as an intervention set of their own under the
   same fixed test type, and children already run from this fork are read by address.
2. **Test relation.** A set S of admitted interventions *repairs* when the coalition do(S) meets the rescue
   criterion on its R replicates: contrast v(S) − ρ₀ at least 1/2, tested above the placebo at the attribution's
   level, flip rate at 10⁻¹² at most 1/10. A set whose replicates fail by a *different* atom or class does not
   repair, and is recorded as a separate finding (`other_failure`), as the shrinker does for worlds. The test of
   a set is memoized by its change-set hash: a coalition already run from this fork costs nothing. A set that
   cannot be formed as a coalition does not repair either, and the search goes on: one with a member that was
   refused, one whose members set the same factor to different values, or one whose joint model difference
   changes a mechanism none of its members declares (FROB-REF-586 for that coalition, N27b-02). Such sets are
   listed under `inadmissible` with the reason; none of them makes the verb fail. A candidate set recorded
   under the sequential test has no coalitions to shrink over (that mode runs singles only): the verb then
   returns its tested singles as the repair sets and offers the fixed request as the next action.
3. **Starting sets, in order.** (a) Every rescuing single from the table: each is a repair set, 1-minimal by
   definition. (b) Every rescuing pair neither of whose members rescues alone: 1-minimal. (c) If (a) and (b) are
   empty and the full admitted set N repairs (tested now if absent): delta debugging over N. (d) If nothing in
   (a) to (c): `no-repair-found among the tested interventions`, with the largest partial rescue observed.
4. **Delta debugging over N** (when reached), with the shrinker's own conventions (N26a-18), which decide where
   an order-dependent search ends. Order the interventions by canonical string. Partition the current set C
   into k contiguous parts, part i covering indices [⌊i·|C|/k⌋, ⌊(i+1)·|C|/k⌋) (five items into two parts:
   sizes 2 and 3; into four: 1, 1, 1, 2), starting at k = 2. If some part repairs, recurse on it with k = 2.
   Otherwise if some complement repairs, recurse on it with k = max(k − 1, 2). Otherwise, if k ≥ |C|, stop;
   else set k = min(2k, |C|) and repeat (the shrinker's rule: the granularity is capped at |C| and the search
   stops only after the pass at k = |C|; "double and stop when k exceeds |C|" would stop the example below at
   {c, d, e, b} after k = 3, one pass short). The result
   is 1-minimal: removing any single intervention loses the rescue (checked explicitly at the end by testing
   each set with one intervention removed). Each test buys R forks through the intervene machinery in one batch
   per round.
5. **The pair check.** With at most 12 interventions, every subset of size one and two is tested (78 tests at
   most; all of them are already in the table when `--coalitions pairs` was run). If a smaller repair set exists
   among them it replaces the result, and every set that survives the check is labelled `minimum among pairs`.
   No set is called the smallest repair: rescue sets are not monotone. Counterexample kept as a test: with
   interventions listed (a, c, d, e, b) and repair when {a, b} or {c, d, e} is applied, delta debugging ends at
   {c, d, e}; the pair check then finds {a, b}.
6. **Buildable and diagnostic.** A repair set all of whose members are buildable (world edits, and
   controller-level changes a design edit could make) is reported under `repair_sets`. A set that contains a
   diagnostic factor is reported under `locating_sets`, never as a repair, with the typed design edits its
   diagnostic rows suggest (DESIGN, from the diagnostic registry: `torque-limit-off` suggests `swap-actuator`
   and `regear`; `torque-limit-set` suggests `set-param` on the joint's torque limit with the value that
   rescued, and `swap-actuator`; `estimator-privileged` suggests `add-sensor`, `move-sensor` and `retime`;
   `latency-zero` suggests `retime`). `diagnostic-forced` children never enter either list. The constructor of `RepairSet`
   takes `Buildable` factors only, so the separation is by type.
7. **Result.**
   ```json
   { "schema": "frob.autopsy.repair/1", "fork": "f:a41c…", "ledger": "b3:…", "inadmissible": [],
     "repair_sets": [ {"set": ["scene./floor/patch[galley-2]/film := dry"], "minimality": "1-minimal; minimum among pairs",
                       "rescued": "8/8", "contrast": 0.97} ],
     "locating_sets": [ {"set": ["model.joint[*.knee].torque_limit := off"], "rescued": "3/8",
                         "note": "partial; diagnostic", "suggests": ["swap-actuator", "regear"]} ],
     "tests": 6, "forks_bought": 0, "other_failures": [],
     "not_claimed": ["a minimum repair", "a passing design", "a cause in the physical robot"],
     "evidence": {"class": "Estimated", "scope": "cause in the model at this tier, among the listed factors"},
     "next_actions": [ {"command": "frob autopsy rerun <run> --edit '<typed edit>' --worlds failing,sample:64 --key <k>",
                        "why": "A repair at a fork is tested from the episode start, on failing worlds and on a sample that passed."},
                       {"command": "frob eval compare <design> <design>@<edit> --task <task> --key <k>",
                        "why": "The verdict comes from a study, not from the autopsy."} ] }
   ```
8. **Determinism.** The order of partitions is fixed by canonical strings and the tests are memoized by hash, so
   the same ledger and the same request produce the same repair sets on any machine: this is what lets a
   recorded transcript replay to the same repair.
9. **Refusals.** The fork's attribution must exist and be sound: FROB-REF-583 (null fork), FROB-REF-584
   (precision), FROB-REF-562 (class) propagate. An outcome of `chaotic: unattributable` returns no repair sets
   and exit 2 with that flag: above the placebo threshold nothing is attributed, repairs included. Budget
   refusals as for any `run` verb (FROB-REF-701, -702).
10. **Layout.** `crates/frob-autopsy/src/repair.rs`. The verb's registry row is VERBS-autopsy's (checked
    against this handler by N27b-16); what this bead defines beyond the row as first entered, for the row to
    carry: `--ledger`.

## Acceptance criteria

- [ ] KA-673: on the planted joint pair the verb returns the single repair set {1, 2}; on the planted
      alternative pair it returns {1} and {2}; a summary of Shapley values alone could not have distinguished
      them.
- [ ] The cancelling table (v({1}) = 1, v({1, 2}) = 0) returns {1} and does not return {1, 2}.
- [ ] The order-dependence case ends at {a, b} with the label `minimum among pairs`, after first reaching
      {c, d, e}.
- [ ] Every returned set is 1-minimal: the verb's own final check tested each set with one member removed, and
      the test counts are in the result.
- [ ] No diagnostic factor appears in `repair_sets` (type-level, plus a property test over generated tables).
- [ ] A chaotic fork returns no repair set; an unsound fork is refused with the propagated code.
- [ ] Two runs of the verb on one ledger return byte-identical results; the second buys no fork.
- [ ] Reachable through `frob --json` and `frob-mcp`; cancellation tested; `CONTRACT.md` documents the limits.

## Test plan

### Unit tests
`crates/frob-autopsy/tests/repair.rs` (the search real; rescue outcomes from `synthetic` coalition tables through
the `ForkTarget` fixtures, and from real forks on fixture 2 where stated):
- `joint_pair_repair_set`, `alternative_pair_repair_sets` (KA-673).
- `cancelling_factor` (CX-297 table).
- `order_dependence_then_pair_check` (the (a, c, d, e, b) case, with factor strings chosen so that their
  canonical order is a, c, d, e, b, run from a set with no pairs in the table: delta debugging tests, in
  order and without repeating a memoized set, ac, deb, a, c, d, eb, cdeb (repairs; k becomes 3), ceb, cd, then
  at k = min(6, 4) = 4: e, b, cdb, cde (repairs; k becomes 3), de, ce, and stops at k = |C| = 3 with
  {c, d, e} after 15 tests; the pair check then returns {a, b}).
- `ddmin_does_not_stop_one_pass_short`: the same case under the rule "double k and stop when k exceeds |C|"
  ends at {c, d, e, b}, which the final 1-minimality check rejects (removing b still repairs); the test pins
  the stated rule against that variant.
- `inadmissible_set_is_skipped`: a candidate set in which two interventions set one factor to different
  values: no set containing both is tested, each is listed under `inadmissible`, and the repair set of the
  remaining factors is returned.
- `reads_latest_set_and_named_set`: with two intervention sets on the fork the plain call shrinks over the
  later one and `--ledger` over the earlier; the result prints the ledger read.
- `one_minimal_final_check`: a planted three-factor conjunction among eight interventions returns exactly it.
- `memoized_tests_buy_nothing`: with a full pairs table in the ledger, `forks_bought = 0`.
- `diagnostic_goes_to_locating_sets`; `repair_set_requires_buildable` (compile-fail).
- `different_failure_is_separate_finding`.
- `chaotic_returns_nothing`; `propagates_583`, `propagates_584`.
- `deterministic_across_request_order`: two intervention sets on one fork, built by `autopsy.intervene` from the
  same `--do` flags given in two orders (this verb takes no `--do`), each shrunk with `--ledger` → the same
  result bytes apart from the `ledger` field read.
- `real_fork_film_repair` (fixture 2 with a low-grip strip planted as the cause): the strip's friction set to
  nominal is the single repair set.

### End-to-end script and logging
`scripts/e2e/autopsy_session.sh` (N27b-18) calls `frob autopsy repair` after `frob autopsy attribute`, asserts the
repair set on the planted kitchen failure, replays the transcript and asserts the same repair. Logged: tests run,
forks bought, each tested set with its rescued count, the final 1-minimality checks, the returned sets and their
labels.

### Known answers and negative controls
KA-673 (repair sets {1, 2}, and {1} or {2}); CX-296; CX-297; CX-288 (delta debugging is 1-minimal only; the pair
check; 78 tests at most for 12 edits). Negative controls: a search that assumes monotone rescue and tests only
the full set and its shrinkings (misses {1} on the cancelling table); a search without the pair check (returns
{c, d, e}); a verb that lists the torque-limit switch as a repair. Metamorphic: adding an intervention that
never rescues to the request changes no repair set. Determinism lanes: identical results twice on one machine,
across worker counts, and in debug and release.

## Considerations

- Cost: with pairs already run, a repair query is free. Delta debugging over 12 interventions without a table
  costs at most a few dozen tests of 8 forks each.
- A repair set of world edits is a statement about the place (a retrofit); a repair by design edit always goes
  through the re-run from the start. The result says which is which.
- If KILL-AUTOPSY fires, this verb returns single-factor repairs confirmed by re-run only, and the shrinking
  over coalitions is removed.
- A repair set that leaves the legality profile of the scene (an edit no building could have) is flagged
  `outside_legality` and listed last.
