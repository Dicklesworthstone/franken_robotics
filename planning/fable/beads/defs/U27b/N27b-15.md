## Background

An attribution is persuasive: it names a factor, shows a table and gives a label. The program narrows
what such a result may claim (carrying state across a geometry, inertia or gearing edit is invalid; a mid-run
rescue is conditional on a state the edited robot might never reach; coalition values can be negative and cannot
establish necessity), and the Autopsy specification lists eight things Autopsy does **not** claim. An optimizing agent will
find any path by which a statistical result can be reported as more than it is, so each non-claim is enforced by
a type, a field or a refusal, not by a style guide.

The eight non-claims:

1. **Not a cause in the world.** The result is a cause in the model at a tier. FACT (source register; to be
   re-read before a gate cites it): causal models of robot failures learned from simulation reached a
   sim-to-real accuracy of 70% and 72% in one study, with variables chosen by the experimenter.
2. **Not beyond the factor list.** A failure whose cause is not among the declared factors yields no named
   factor. A planted no-cause control tests this.
3. **Not a minimal repair.** Repair sets are 1-minimal under the tested interventions.
4. **Not necessity from a Shapley value.** A Shapley value can be negative and never establishes that a factor is
   necessary.
5. **Not a passing design.** A rescue at a fork, or a re-run on the failing worlds, is not a verdict on the
   task. A study is.
6. **Not an answer in chaotic regimes.** Above the placebo threshold nothing is attributed.
7. **Not a proof.** A contrast is a replayable experiment and has class `Tested` on its tier; an attribution
   drawn from contrasts has class `Estimated`.
8. **Not a differentiator of the engine.** An incumbent with restorable state and a thin layer can host the same
   method, and the program's comparison against a composed incumbent includes that arm.

**ADR-AUTOPSY-07. The cause is a cause in the model.** Every attribution is scoped to the model, the tier and
the declared factor list (invariant INV-AUTOPSY-06 adds the precision). Rejected alternative: unscoped causal
statements ("the wet floor caused the fall"), which read as statements about a robot that was never built.

The refusal that closes the loop is **FROB-REF-880: an attribution cited as an established cause, or as a cause
in the physical robot.** Tier Solid; crate `frob-autopsy` with hooks in the claim boundary.

## Scope

In: the scope block and its constructor; the evidence classes of contrasts, attributions, repair sets and
transcripts; the `non_claims` list on Autopsy envelopes; permitted wording for reports; the citation rule and
its call sites; FROB-REF-880 with fields and repairs; one enforcement per non-claim; documentation of the
non-claims in the contract and in the agent documentation.
Out: computing the attribution (BD-280); the planted no-cause control and the abstention gate (seed bead
BD-282); Shapley arithmetic (BD-281); the general rule against citing a result above its claim product
(FROB-REF-819, -820; the boundary bead BD-308, whose mechanism this bead registers into).

## Technical approach

1. **Scope block (INV-AUTOPSY-06).**
   ```rust
   pub struct AttributionScope { model: ModelId, scene: SceneId, policy: PolicyId, tier: Tier,
                                 precision: Precision, profile: ProfileId, factors: Vec<FactorPath>,
                                 fork_tick: Tick, horizon: Qty }
   ```
   `Attribution`, `RepairResult` and `Transcript` have no constructor that omits it. Its text form in the
   envelope's evidence block is fixed: `"cause in the model at this tier, among the listed factors"`.
2. **Classes.** A fork's verdict and a contrast: `Tested` on their tier (weakened to `Estimated` by the claim
   product if any input is, for example an `assumed` card field). An attribution, a repair set, a Shapley summary
   and a transcript that contains any of them: `Estimated`, by a leaf product created in `frob-autopsy`; there is
   no path that returns a stronger class (compile-fail tests: no setter, no conversion). `claims: []` (the result
   may be cited for none of the seven claim kinds as a finding in its own right); `reality: "no-claim"`; the
   three no-authorization flags false.
3. **`non_claims` on every Autopsy envelope** (attribute, repair, rerun, show): the list
   `["cause in the physical robot", "cause outside the listed factors", "minimal repair", "necessity from a
   Shapley value", "passing design", "attribution in a chaotic regime", "proof"]`.
4. **Permitted wording** (the only forms a report may print; DESIGN, following the rule that each claim has a
   permitted wording and reports use no other):
   - contrast: "tested: do(⟨factor⟩) rescued ⟨k⟩ of ⟨R⟩ against placebo ⟨f⟩ of ⟨P⟩ on ⟨tier, precision⟩; ledger
     ⟨hash⟩";
   - attribution: "attributed (estimated): ⟨factor⟩ is ⟨label⟩ for ⟨failure class⟩ in model ⟨identity⟩ at
     ⟨tier, precision⟩ among ⟨n⟩ listed factors; attribution ⟨claim identifier⟩";
   - repair: "repair set (1-minimal among tested interventions): ⟨set⟩; not a verdict on the task".
5. **The citation rule.** One function, registered with the artifact graph for every claim whose producer is an
   Autopsy verb:
   ```rust
   pub enum CiteRole { Described, Established, Reality, InputRequiring(EvidenceClass) }
   pub fn offer(claim: &AutopsyClaim, role: CiteRole) -> Result<Wording, Refusal>
   ```
   `Described` returns the permitted wording. `Established`, `Reality`, and `InputRequiring(c)` for any class c
   above `Estimated` return **FROB-REF-880**. Call sites: (a) report generation, when a statement is placed
   under a heading or claim kind that requires `established` standing or the Reality claim; (b) validation of
   any verb input that carries a claim identifier as supporting evidence in a stated role; (c) the check of gate
   rows and demonstration manifests, which list the claim identifiers a recorded pass rests on.
6. **FROB-REF-880 envelope.** `pointer`: the citing statement or input field; `observed`: the claim's class
   (`Estimated`), its scope text and its producer; `required`: the role asked for; `affected_claims`: the citing
   claim; `retry: after-change`; exit 3. Ranked repairs: (1) cite it in the role `Described`, with the permitted
   wording and its scope; (2) to establish something about the *design*: re-run the edit from the episode start
   (`frob autopsy rerun …`) and run a declared study (`frob eval compare …`), then cite the study's verdict,
   which is a Design comparison; (3) for a statement about the *physical robot*: there is none without imported
   measurements and a calibrated band; the result stays `reality: no-claim`.
7. **One enforcement per non-claim.**
   | Non-claim | Enforced by |
   |---|---|
   | 1 Not a cause in the world | Scope block; `reality: no-claim`; FROB-REF-880 for the role `Reality` |
   | 2 Not beyond the factor list | `scope.factors` on every result; the out-of-list planted control must name nothing |
   | 3 Not a minimal repair | The minimality field takes only `1-minimal` and `1-minimal; minimum among pairs`; `not_claimed` on repair results |
   | 4 Not necessity from a Shapley value | Labels come from the table only; the summary object has no label field and is marked `description` |
   | 5 Not a passing design | Repair and re-run results carry class `Estimated` and a next action to a study; FROB-REF-880 for `Established` |
   | 6 Not an answer in chaotic regimes | The chaos clause precedes every label; a chaotic attribution names no factor and returns no repair set |
   | 7 Not a proof | Class fixed at `Estimated`; no conversion upward |
   | 8 Not a differentiator of the engine | Stated in the contract's validity section and in the agent documentation; the composed-incumbent arm of the program comparison lists forks with a placebo among its portable methods |
8. **Documentation.** `crates/frob-autopsy/CONTRACT.md`, sections "evidence class of outputs", "validity domain"
   and "known gaps", carry the eight non-claims verbatim; the generated agent documentation for the `autopsy`
   cluster prints them with the refusal code.
9. **Layout.** `crates/frob-autopsy/src/scope.rs`, `cite.rs`; wording templates in `registries/autopsy/wording.toml`.

## Acceptance criteria

- [ ] INV-AUTOPSY-06 as a property: every attribution, repair result and transcript carries a scope with model,
      tier, precision and factor list; a build with the scope made optional fails the test.
- [ ] `offer(…, Established)` and `offer(…, Reality)` return FROB-REF-880 with the fields of step 6;
      `offer(…, Described)` returns the permitted wording.
- [ ] A report that includes a session prints the attribution in the permitted wording under its class; a
      request to place it under an established-findings or Reality statement is refused with FROB-REF-880.
- [ ] A gate row or demonstration manifest that lists an attribution's claim identifier for a Reality gate fails
      the generated-artifact check with FROB-REF-880.
- [ ] No Autopsy output can be constructed with a class above `Estimated` for an attribution (compile-fail), and
      `claims` is empty and `reality` is `no-claim` on every Autopsy envelope.
- [ ] Each row of the enforcement table has a named test that fails when the enforcement is removed.
- [ ] The contract and the agent documentation list the eight non-claims.

### End-to-end script and logging
`scripts/e2e/autopsy_session.sh` (N27b-18) cites the session's attribution as established through the report
path and asserts FROB-REF-880 (the second half of the workflow's seed condition);
`scripts/e2e/autopsy_refusals.sh` (N27b-19) asserts the envelope fields for both roles. Logged: the claim
identifier, its class and scope, the role offered, the code, the pointer and the repairs.

### Known answers and negative controls
CX-301 ("a contrast between forks is a proof of cause": a contrast is a replayable experiment of class `Tested`
on its tier; the catalogue gives no numeric case). CX-296 and CX-297 for non-claim 4. Negative controls
(mutants the tests must kill): a citation rule that allows `Established` when the contrast is 1.0 with zero
flips; an envelope serializer that prints `reality: "model"`; a report template that drops the scope. Determinism:
exact; wording and refusals are byte-identical across platforms.

## Considerations

- The guard polices structured citations (reports, evidence inputs, gate rows). It cannot police free text an
  agent writes outside the system; the permitted wording and the scope text exist so that the easy thing to
  paste is the honest thing.
- FROB-REF-880 is the Autopsy-specific form of the general refusals against citing above a claim product. Where
  both could fire, this code is returned because its repairs are the useful ones (re-run, then a study).
- The spelling of the citation call on the command line belongs to the artifact-graph and report owners; this
  bead supplies the rule, the refusal and the tests at the function level and through the report path.
- What would make us revisit: a calibrated family with a reality band for failure outcomes, which could one day
  license a scoped statement about a built robot. Until then the role `Reality` is refused without exception.
