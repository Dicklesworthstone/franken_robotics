## Background

Every surface of the system (the CLI, the daemon protocol, the MCP tool definitions, the schemas, the refusal
table and the generated documentation for agents) is derived from one registry, `registries/verbs.toml`, so the
surfaces cannot drift. Autopsy owns one cluster of that registry with exactly five verbs:

| Verb | Kind | First milestone | Notes |
|---|---|---|---|
| `autopsy.intervene` | run | M3 | Runs interventions, placebo forks, replicates and coalitions from a fork handle made by `run.fork` |
| `autopsy.attribute` | read | M3 | Contrasts, flip rates, pairs, labels, an optional Shapley summary |
| `autopsy.repair` | run | M3 | Minimal repair sets by shrinking the intervention set |
| `autopsy.rerun` | run | M3 | Paired re-run from the episode start for design-parameter and structural edits |
| `autopsy.show` | read | M3 | The transcript of a session, token-budgeted |

**Autopsy registers no fork verb and no divergence verb.** A fork point is made with `run.fork` (the replay and
fork service, M2), which returns the class of a proposed change set (one of the five fork classes), the earliest
valid tick and the null-replay result; `--classify-only` restores no child that carries a change. The first
divergence between two runs, in exact or tolerance mode, is read with `telemetry.divergence` (M2). The reason is
the registry's rule
that no verb has a second spelling: one mechanism, one name, owned by the subsystem that owns the mechanism. (The
milestone text for M3 lists a command `frob autopsy fork`; the registry and the Autopsy specification govern, and that command
does not exist. An agent that tries it gets the unknown-verb refusal with `run.fork` as its repair.)

Kinds: `read` returns stored or cheaply computed facts and changes nothing; `run` spends compute, takes an
idempotency key and a budget, accepts the bounded synchronous wait (`sync_wait_ms`) and otherwise returns a job
handle with exit code 8. Tier Solid.

The five rows are entered as data, early, by the cluster registry bead VERBS-autopsy, before any handler
exists. A row written before its handler can be wrong in ways only the handler shows: an example that does not
run, a refusal the handler raises that the row does not list, an output schema the produced object does not
validate against. This bead is the check from the handlers' side, done by the unit that builds them, and it is
where the cluster's one peculiarity (the verbs it deliberately does not have) is pinned.

## Scope

In: the checks of the five rows that need the handlers: every registry example executes against the fixtures;
every row's refusal list covers what the verb's tests raise, and every listed code maps to one exit code; the
output schemas validate the worked artifacts; the cluster's membership and the absence of the four forbidden
names; the alias-free repair for `autopsy fork` and `autopsy divergence`; the content of the generated
`robot-docs` page of the cluster.

Out, with the bead that has it:

- The five rows themselves, every field of each (names, kinds, tiers, capabilities, input and output schema
  names, refusal lists, idempotency, cost models, wait defaults, examples, task-cluster lists): VERBS-autopsy, a
  dependency of this bead. This bead enters no row and holds no second table of their fields; where a check
  here shows a row to be wrong, the correction is made to the row in `registries/verbs.toml` as VERBS-autopsy
  specifies it, and that bead's snapshot is refreshed.
- Parity of CLI and MCP for the five verbs, the MCP name map, the help-schema snapshots, the cluster's
  conformance script `scripts/e2e/verbs_autopsy.sh`, the missing-key refusal and the answer of a verb before
  its milestone (VERBS-autopsy).
- The task-cluster assignment and its lint (NJL-05, which declares the cluster `repair`); the scope registry
  (BD-258).
- The verbs' behaviour (BD-279, BD-280, N27b-14, BD-283, BD-284); the citation guard and `FROB-REF-880`
  (N27b-15); the generator (N32a-02, NJL-01); the M3 verb sweep with the registry freeze and the M3 parity
  record (BD-312, which depends on this bead); the refusal rows themselves (N27-REF).

## Technical approach

1. **What is read.** The compiled registry table of `frob-verbs`, restricted to `cluster = "autopsy"`: for each
   of the five rows its `examples`, its `refusals` (the chapter codes of the row, to which the generator
   appends the surface-wide codes of the row's kind), its `input_schema` and `output_schema`. The values are
   VERBS-autopsy's. Four points of that bead matter to the checks here and are stated the same way in both
   (DESIGN): a row lists the codes its own handler can return, so `FROB-REF-880` is in no row of the cluster (it
   is raised where an Autopsy claim is cited, and is listed under the report and evidence verbs that cite),
   `FROB-REF-581` is not in the row of `autopsy.rerun` (it is returned by `run.fork` and `autopsy.intervene`,
   with `autopsy.rerun` as its repair), and `FROB-REF-866` is not in the row of `autopsy.intervene` (it concerns
   the bulk form, but is raised by the admission check of the method-experiment register, N38a-07, when
   N27b-27's speed experiment is registered, never by a call of the verb); the one listed exception is
   `FROB-REF-840`, the sealed-read refusal that the dispatcher's confirmation firewall raises before any handler
   (BD-261) and that the M3 verb sweep requires in the row of every verb that can expose a world (BD-312), so
   every row lists it and the coverage check of step 3 does not report it as `listed-not-raised`; `FROB-REF-553` is in the row of `autopsy.intervene` as well as that of
   `autopsy.attribute`, because the intervene handler's sequential mode (N27bp2-01, split from BD-279) refuses a
   sequential request for a factor already run as a fixed table on the fork, and the reverse, and the attribute
   handler refuses a pooled read over sets of both types (BD-280); the output schemas are `frob.autopsy.intervene.out/1`,
   `frob.autopsy.attribution/1`, `frob.autopsy.repair/1`, `frob.autopsy.rerun/1` and
   `frob.autopsy.transcript/1`; and every `run` example carries `--key`, because a `run` call without an
   idempotency key is refused (`FROB-REF-805`).
2. **Examples are tests.** Each registry example is executed verbatim against the fixtures of the worked
   session (run `r:19e2`, fork `f:a41c`): `autopsy.intervene` returns a result with exit 0 (the example's one
   intervention is admitted and nothing is refused; exit 2 is the answer of a request with a refused
   intervention, BD-279) or a job handle with
   exit 8; `autopsy.attribute` a `frob.autopsy.attribution/1` object; `autopsy.repair` a repair result;
   `autopsy.rerun` a paired outcome; `autopsy.show` a transcript inside its token budget.
   **What the mechanism beads need of the rows beyond their first entry.** The surfaces are generated from
   the rows, so an input a mechanism bead defines exists only when its row carries it. This bead keeps the
   list of such inputs as test data and checks the rows against it. Known at the time of writing, each
   defined in the bead named and owed by the row: on
   `autopsy.intervene`, the input `reuse`, the default `pairs` of `coalitions` and its values `all` and
   `sampled`, the inputs `shapley` and `shapley_budget`, the default `auto` of `lane`, the inputs `forks` and
   `cluster` and `continue_after_variant`, and FROB-REF-584 among the refusals (BD-279, BD-281, N27b-24,
   N27b-25, N27b-27); on `autopsy.attribute`, the input `ledger`, the default `auto` of `lane` and the value
   `force` of `shapley` (BD-280, BD-281); on `autopsy.repair`, the input `ledger` (N27b-14); on
   `autopsy.show`, the formats `ghost` (with `max_forks` and `include_forced`) and `crosscheck` (N27b-17,
   N27b-26). The test `rows_carry_mechanism_inputs` checks the entries whose defining bead is closed and
   lists the others as `owed: <bead>`; an entry of a closed bead that the row lacks fails the test and names
   the row and the property.
3. **Refusal coverage.** The test runs of the five verb beads log every refusal code a handler returns. The
   coverage check collects those codes per verb and asserts that each is in the verb's generated refusal list
   (the row's codes plus the appended ones). A code raised and not listed fails the check and names the row to
   correct. The reverse direction is also reported: a chapter code listed in a row that no test raises is
   printed as `listed-not-raised`, for review, and does not fail.
4. **Exit codes.** 0 completed; 2 completed with findings or flags (a named factor, a partial refusal, a flag
   such as `chaotic: unattributable`); 3 refused (all eight Autopsy codes are in the families that map to exit
   3); 4 budget; 5 capability (a session token without the scope is refused with FROB-REF-720); 7 conflict
   (idempotency key reuse with different content); 8 accepted and still running. The test asserts that every
   listed refusal maps to exactly one exit code.
5. **No second spelling.** Conformance tests: the `autopsy` cluster has exactly the five names above; the
   registry holds no `autopsy.fork`, `autopsy.divergence`, `autopsy.explain` or `autopsy.replay`. On the CLI,
   `frob autopsy fork …` returns FROB-REF-801 (unknown verb) whose first repair is the equivalent
   `frob run fork …` command, and `frob autopsy divergence …` returns FROB-REF-801 with
   `frob telemetry divergence …`. These are repairs in a refusal, not aliases: nothing executes.
6. **Schemas.** One JSON Schema file per name under `schemas/`, generated from the Rust types with the envelope
   wrapper; `additionalProperties: false`; numbers that must be exact (rates as count pairs, levels) are strings
   or integer pairs; durations carry units. `frob schema autopsy.attribute` prints the output schema. Each
   output schema is validated against the corresponding worked artifact.
7. **Documentation.** The generated `robot-docs` page for the cluster shows the five-move order (read the
   heuristic, fork, intervene, attribute, re-run), one example per verb from the worked session, the refusal
   table with repairs, and the non-claims.

## Acceptance criteria

- [ ] The compiled registry holds the five rows of VERBS-autopsy and nothing else under `autopsy`; the four
      forbidden names are absent.
- [ ] `frob autopsy fork` and `frob autopsy divergence` return FROB-REF-801 with the repair naming `run.fork`
      and `telemetry.divergence`; no handler runs.
- [ ] Each example in the registry executes against the fixtures (the examples are tests).
- [ ] Each verb's listed refusals are a superset of what its tests can raise (a test collects raised codes and
      compares), and each maps to one exit code; no row lists FROB-REF-880.
- [ ] Each of the five output schemas validates its worked artifact.
- [ ] Every input, value, default and refusal that a closed mechanism bead of the cluster defines is carried
      by its row; a missing one is corrected in the row (VERBS-autopsy), never by a second spelling in a
      handler.
- [ ] The `robot-docs` page of the cluster shows the five moves in order, one example per verb, the refusal
      table and the non-claims.
- [ ] Any row corrected as a result of these checks is corrected in the registry and VERBS-autopsy's snapshot
      and tests pass afterwards; this bead leaves no row of its own.

## Test plan

### Unit tests
`crates/frob-verbs/tests/registry_autopsy.rs` (beside VERBS-autopsy's `cluster_autopsy` test, which pins the
field values; the tests here need the handlers):
- `cluster_has_exactly_five`; `no_second_spelling` (the four forbidden names absent).
- `examples_execute_on_fixtures`: each row's example, verbatim, returns the exit code and schema of step 2.
- `schemas_exist_and_validate_examples`: each output schema validates the corresponding worked artifact (the
  attribution object of the worked session; a transcript; a repair result; a re-run result).
- `refusal_lists_cover_raised` (collected from the verb beads' test runs); `listed_not_raised_is_reported`.
- `rows_carry_mechanism_inputs`: for each entry of the list of step 2 whose defining bead is closed, the row's
  generated input schema has the property with the stated value set and default (and the refusal list has
  the code); a `synthetic` row lacking `reuse` on `autopsy.intervene` fails and names the property; an entry
  of an open bead is reported `owed` and does not fail.
- `every_refusal_one_exit_code`.
- `no_row_lists_880`.
- `unknown_autopsy_fork_repair`: the refusal's first repair is a `frob run fork` command with the same arguments;
  `unknown_autopsy_divergence_repair` likewise with `frob telemetry divergence`.

Held by VERBS-autopsy and not repeated here: `kinds_milestones_tiers`, `mcp_names_one_to_one`,
`task_clusters_and_examples` (at most seven per task cluster; every verb placed; `diagnose` exactly its seven),
and the missing-key refusal 805 of its conformance script.

### End-to-end script and logging
`scripts/e2e/autopsy_refusals.sh` (N27b-19) calls `frob autopsy fork` and asserts the unknown-verb refusal and
its repair; `scripts/e2e/autopsy_session.sh` (N27b-18) runs the same session through the CLI and through
`frob-mcp` and asserts envelope equality per move. Logged: verb, surface, exit code, schema name, envelope
digest per surface. The cluster's own conformance script, `scripts/e2e/verbs_autopsy.sh`, is VERBS-autopsy's;
its step that runs each registry example verbatim through the real binary is the end-to-end form of
`examples_execute_on_fixtures`, and this bead adds no script of its own.

### Known answers and negative controls
The worked session and the worked MCP exchange of the program's artifacts are the golden inputs for the schemas
(`autopsy_intervene {fork, placebo: 64, replicates: 8, coalitions: "pairs", do: […], idempotency_key,
sync_wait_ms: 30000}` returning `{fork, forks_run: 113}` with exit 2). Negative controls: a registry with a
sixth verb `autopsy.fork` (the membership test fails); an entry whose refusal list omits FROB-REF-581 for
`autopsy.intervene` (the coverage test fails); an example with its `--key` removed (it is refused with 805 and
the example test fails); an `autopsy.intervene` row without FROB-REF-553 while N27bp2-01's test
`fixed_reread_as_sequential_553` raises it (the coverage test fails and names the row). The control "a task
cluster of eight" belongs to the task-cluster lint (NJL-05).
Determinism: generated artifacts are byte-identical on regeneration.

## Considerations

- The task cluster `repair` ("turn a diagnosis into a tested edit") was first proposed here with `eval_compare`
  as its seventh tool. The assignment belongs to NJL-05, which declares it as `autopsy_repair`, `autopsy_rerun`,
  `autopsy_show`, `run_fork`, `telemetry_divergence`, `design_edit`, `result_revalidate`; that is the list the
  rows use. The constraint that does not move: at most seven tools, every verb placed.
- The capability scopes are `autopsy:run` and `autopsy:read` in the rows. An earlier proposal here added
  `run:read` on the `run` verbs; VERBS-autopsy records why it is not listed and what would change that
  (a ruling of the scope registry, BD-258).
- If KILL-AUTOPSY fires, `--coalitions` disappears from the input schema of `autopsy.intervene`, which is a new
  schema version (`/2`), not a silent change; the example test then runs the example without the flag.
- `--lane` on `autopsy.intervene` and `autopsy.attribute` takes `auto` (the default), `f64` and `tier-f32`.
  Until the single-precision lane lands (N27b-24), `auto` is the double-precision procedure and `tier-f32` is
  refused with FROB-REF-724 (not implemented in this build), which is in every row's generated list; after
  KILL-ENSEMBLE, `tier-f32` leaves the schema and `auto` is the double-precision procedure again (N27b-29).
