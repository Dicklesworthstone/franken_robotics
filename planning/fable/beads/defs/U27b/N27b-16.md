## Background

Every surface of the system (the CLI, the daemon protocol, the MCP tool definitions, the schemas, the refusal
table and the generated documentation for agents) is derived from one registry, `registries/verbs.toml`, so the
surfaces cannot drift. Autopsy owns one cluster of that registry with exactly five verbs:

| Verb | Kind | First milestone | Notes |
|---|---|---|---|
| `autopsy.intervene` | run | M3 | Runs interventions, placebo forks, replicates and coalitions from a fork handle made by `run.fork` |
| `autopsy.attribute` | read | M3 | Contrasts, flip rates, pairs, labels, an optional Shapley summary |
| `autopsy.repair` | run | M3 | Minimal repair sets by shrinking the intervention set |
| `autopsy.rerun` | run | M3 | Paired re-run from the episode start for design-parameter and structural edits |
| `autopsy.show` | read | M3 | The transcript of a session, token-budgeted |

**Autopsy registers no fork verb and no divergence verb.** A fork point is made with `run.fork` (the replay and
fork service, M2), which returns the class of a proposed change set (one of the five fork classes), the earliest
valid tick and the null-replay result; `--classify-only` restores nothing. The first divergence between two
runs, in exact or tolerance mode, is read with `telemetry.divergence` (M2). The reason is the registry's rule
that no verb has a second spelling: one mechanism, one name, owned by the subsystem that owns the mechanism. (The
milestone text for M3 lists a command `frob autopsy fork`; the registry and the Autopsy specification govern, and that command
does not exist. An agent that tries it gets the unknown-verb refusal with `run.fork` as its repair.)

Kinds: `read` returns stored or cheaply computed facts and changes nothing; `run` spends compute, takes an
idempotency key and a budget, accepts the bounded synchronous wait (`sync_wait_ms`) and otherwise returns a job
handle with exit code 8. Tier Solid. Owner of the registry: `frob-verbs`; owner of the entries: this bead.

## Scope

In: the five registry entries with input and output schema names, capabilities, refusal lists, idempotency,
cost models, examples and task-cluster assignments; the conformance tests that pin the cluster's membership and
the absence of second spellings; the alias-free repair for `autopsy fork` and `autopsy divergence`; parity of
CLI and MCP for the five verbs.
Out: the verbs' behaviour (BD-279, BD-280, N27b-14, BD-283, BD-284); the generator and the general M3 verb
sweep (the Tether beads); the refusal rows themselves (N27-REF).

## Technical approach

1. **Entries** (format of the registry; schema names other than the two the Autopsy specification fixes are DESIGN).
   ```toml
   [[verb]]
   name = "autopsy.intervene"
   cluster = "autopsy"
   kind = "run"
   tier = "S"
   capabilities = ["run:read", "autopsy:run"]
   input_schema = "frob.autopsy.intervene.in/1"
   output_schema = "frob.autopsy.intervene.out/1"
   refusals = ["FROB-REF-562", "FROB-REF-580", "FROB-REF-581", "FROB-REF-582", "FROB-REF-583", "FROB-REF-586",
               "FROB-REF-701", "FROB-REF-702", "FROB-REF-802", "FROB-REF-803", "FROB-REF-805"]
   idempotent = true
   cost_model = "forks × horizon in world-seconds; 689 forks for 12 factors with pairs, before the second series"
   first_milestone = "M3"
   task_clusters = ["diagnose"]
   wait_default_ms = { cli = "completion", mcp = 5000 }
   examples = ["frob autopsy intervene f:a41c --placebo 64 --replicates 8 --coalitions pairs --do 'scene./floor/patch[galley-2]/film := dry' --json"]
   ```
   | Verb | Kind | Input / output schema | Refusals listed | Task clusters |
   |---|---|---|---|---|
   | `autopsy.intervene` | run | `frob.autopsy.intervene.in/1` / `.out/1` | 562, 580, 581, 582, 583, 586, 701, 702, 802, 803, 805 | `diagnose` |
   | `autopsy.attribute` | read | `frob.autopsy.attribute.in/1` / `frob.autopsy.attribution/1` | 553, 562, 583, 584, 802, 806, 807 | `diagnose` |
   | `autopsy.repair` | run | `frob.autopsy.repair.in/1` / `frob.autopsy.repair/1` | 562, 583, 584, 701, 702, 802, 803, 805 | `repair` |
   | `autopsy.rerun` | run | `frob.autopsy.rerun.in/1` / `frob.autopsy.rerun/1` | 587, 701, 702, 802, 803, 805, and the design-edit refusals of the edit it applies | `repair` |
   | `autopsy.show` | read | `frob.autopsy.show.in/1` / `frob.autopsy.transcript/1` | 802, 806, 807 | `diagnose` |
   FROB-REF-880 is not in any verb's list: it is raised where an Autopsy claim is cited, and is listed under the
   report and evidence verbs that cite.
2. **Task clusters.** The principal cluster `diagnose` ("find why a run failed") lists seven tools:
   `explain_run`, `autopsy_intervene`, `autopsy_attribute`, `autopsy_show`, `telemetry_query`,
   `telemetry_inspect_pixel`, `telemetry_energy`. `autopsy.repair` and `autopsy.rerun` are not in it, and the
   lint requires every verb to sit in at least one cluster of at most seven. DESIGN (a starting assignment the
   registry lint checks): a further cluster `repair` ("turn a diagnosis into a tested edit"): `autopsy_repair`,
   `autopsy_rerun`, `autopsy_show`, `run_fork`, `telemetry_divergence`, `design_edit`, `eval_compare`. The MCP
   tool name is the verb name with `.` and `-` replaced by `_`.
3. **Capabilities.** `run` verbs need a scope that permits spending compute on the run's namespace
   (`autopsy:run`); `read` verbs need read access to the run. A session token without the scope is refused with
   FROB-REF-720 (exit 5). Scope names follow the capability registry; the two here are proposals to its owner.
4. **Exit codes.** 0 completed; 2 completed with findings or flags (a named factor, a partial refusal, a flag
   such as `chaotic: unattributable`); 3 refused (all eight Autopsy codes are in the families that map to exit
   3); 4 budget; 5 capability; 7 conflict (idempotency key reuse with different content); 8 accepted and still
   running. The registry test asserts that every listed refusal maps to exactly one exit code.
5. **No second spelling.** Conformance tests: the `autopsy` cluster has exactly the five names above; the
   registry holds no `autopsy.fork`, `autopsy.divergence`, `autopsy.explain` or `autopsy.replay`. On the CLI,
   `frob autopsy fork …` returns FROB-REF-801 (unknown verb) whose first repair is the equivalent
   `frob run fork …` command, and `frob autopsy divergence …` returns FROB-REF-801 with
   `frob telemetry divergence …`. These are repairs in a refusal, not aliases: nothing executes.
6. **Schemas.** One JSON Schema file per name under `schemas/`, generated from the Rust types with the envelope
   wrapper; `additionalProperties: false`; numbers that must be exact (rates as count pairs, levels) are strings
   or integer pairs; durations carry units. `frob schema autopsy.attribute` prints the output schema.
7. **Documentation.** The generated `robot-docs` page for the cluster shows the five-move order (read the
   heuristic, fork, intervene, attribute, re-run), one example per verb from the worked session, the refusal
   table with repairs, and the non-claims.

## Acceptance criteria

- [ ] `registries/verbs.toml` holds the five entries; the generated CLI, MCP tool list and schemas contain them
      and nothing else under `autopsy`; the diff of the served `tools/list` against the registry is empty.
- [ ] Every verb sits in a task cluster of at most seven tools; `diagnose` is exactly the seven listed.
- [ ] `frob autopsy fork` and `frob autopsy divergence` return FROB-REF-801 with the repair naming `run.fork`
      and `telemetry.divergence`; no handler runs.
- [ ] Each example in the registry executes against the fixtures (the examples are tests).
- [ ] Each verb's listed refusals are a superset of what its tests can raise (a test collects raised codes and
      compares), and each maps to one exit code.
- [ ] CLI and MCP return the same envelope for each of the five verbs on the same request (the parity test of
      the surface, restricted to this cluster).
- [ ] `run` verbs without an idempotency key are refused with FROB-REF-805; `read` verbs accept none.

## Test plan

### Unit tests
`crates/frob-verbs/tests/registry_autopsy.rs`:
- `cluster_has_exactly_five`; `no_second_spelling` (the four forbidden names absent).
- `kinds_and_milestones`: intervene/repair/rerun `run`, attribute/show `read`, all M3.
- `schemas_exist_and_validate_examples`: each output schema validates the corresponding worked artifact (the
  attribution object of the worked session; a transcript; a repair result).
- `refusal_lists_cover_raised` (collected from the verb beads' test runs).
- `every_refusal_one_exit_code`.
- `task_cluster_lint`: at most seven; every verb placed.
- `mcp_names_one_to_one`: `autopsy.intervene` ↔ `autopsy_intervene`, and so on.
- `unknown_autopsy_fork_repair`: the refusal's first repair is a `frob run fork` command with the same arguments.
- `run_without_key_805`.

### End-to-end script and logging
`scripts/e2e/autopsy_refusals.sh` (N27b-19) calls `frob autopsy fork` and asserts the unknown-verb refusal and
its repair; `scripts/e2e/autopsy_session.sh` (N27b-18) runs the same session through the CLI and through
`frob-mcp` and asserts envelope equality per move. Logged: verb, surface, exit code, schema name, envelope
digest per surface.

### Known answers and negative controls
The worked session and the worked MCP exchange of the program's artifacts are the golden inputs for the schemas
(`autopsy_intervene {fork, placebo: 64, replicates: 8, coalitions: "pairs", do: […], idempotency_key,
sync_wait_ms: 30000}` returning `{fork, forks_run: 113}` with exit 2). Negative controls: a registry with a
sixth verb `autopsy.fork` (the membership test fails); an entry whose refusal list omits FROB-REF-581 (the
coverage test fails); a task cluster of eight (the lint fails). Determinism: generated artifacts are
byte-identical on regeneration.

## Considerations

- The `repair` task cluster and the two capability scope names are proposals; the registry's lint and its owner
  decide the final assignment. The constraint that does not move: at most seven tools, every verb placed.
- If KILL-AUTOPSY fires, `--coalitions` disappears from the input schema of `autopsy.intervene`, which is a new
  schema version (`/2`), not a silent change.
- The single-precision lane adds the value set `f64 | tier-f32 | auto` for `--lane` on `autopsy.intervene` and
  `autopsy.attribute`; until that work lands, the two non-default values are refused with FROB-REF-724 (not
  implemented in this build), which is then listed for both verbs.
