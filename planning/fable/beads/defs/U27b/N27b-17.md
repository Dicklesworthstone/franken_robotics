## Background

The debugging workflow ends with a picture: the viewer can overlay a fork on its parent as a ghost, synchronized
on the fork tick. The viewer's overlay table lists it as **Counterfactual ghost: a fork drawn over its parent,
diverging from the first different event; source: Autopsy.** The self-contained HTML replay packet draws a
parent world and its forks from the telemetry store and the contrast table from Autopsy; it computes no fork, no
attribution and no verdict, and contains no stepping code. Its fork overlay is enabled only after the native
harness has passed its null-fork and fork-classification gates. The reason for that order: a browser bundle
built first becomes a second, unreviewed implementation of replay, while a page that only draws recorded rows
cannot disagree with the harness.

The viewer and the packet writer belong to other beads. What they need from Autopsy is a small, exact feed: for
a session, which forks exist, how each pairs with the parent in time, where each first departs from the parent,
and the text of the tables the verbs returned. This bead is that feed. The viewer never feeds anything back to
physics: the simulator owns state and the viewer reads immutable snapshots.

Tier Solid. Crate `frob-autopsy` (the feed); consumers `viewer/` and `frob-chronicle`.

## Scope

In: the ghost manifest for a session or fork; selection of which forks to show (at most 16); the
synchronization anchor; first-divergence annotations per fork; the tables as returned text; the label and class
each ghost must display; the read path (`autopsy.show --format ghost`); the gating flag.
Out: drawing (the viewer overlay), the HTML packet and its size rules, pose telemetry and frame decimation
(their own beads); computing divergences (`telemetry.divergence`); computing forks or attributions.

## Technical approach

1. **Manifest** (schema `frob.autopsy.ghost/1`, DESIGN), returned by
   `frob autopsy show <session|fork> --format ghost [--max-forks 16] --json`:
   ```json
   { "schema": "frob.autopsy.ghost/1", "session": "a:5c1e…", "parent": {"run": "r:19e2…", "world": 311,
       "address": "w:…", "failure": {"class": "fall", "atom": "upright", "tick": 5650, "time_s": "11.30"}},
     "sync": {"fork_tick": 5150, "time_s": "10.30", "frame_period": "1/50 s"},
     "ghosts": [
       {"fork_path": "…/rep@1e-12/0", "address": "w:…", "do": ["scene./floor/patch[galley-2]/film := dry"],
        "class": "contact-affecting", "label": "but-for", "verdict": "satisfied",
        "first_divergence": {"tick": 5150, "stage": "contact", "variables": ["foot.lf slip speed [m/s]"],
                             "decision_tick": 5650, "mode": "tolerance", "resolution_ticks": 1},
        "evidence": {"class": "Estimated", "tier": "batch-cpu", "precision": "f64"}} ],
     "tables": {"classification": "<text as returned by run.fork>", "contrasts": "<text as returned by autopsy.attribute>",
                "placebo": {"n": 64, "flips": 2}},
     "gated": {"null_fork_gate": "pass", "classification_gate": "pass"},
     "authorization": {"execution_authorized": false, "hardware_safety_signoff": false, "sim_to_real_certified": false} }
   ```
2. **Which forks.** At most 16, chosen deterministically: the null fork first (it must coincide with the
   parent); then, per named factor in ranking order, its unperturbed fork; then one placebo fork that flipped
   and one that did not (if they exist); then unperturbed forks of unnamed factors in ranking order. The rule and
   the count are in the manifest so two exports of one session pick the same forks.
3. **Synchronization.** The anchor is the fork tick of the session's fork handle. A ghost has no frames before
   it and refers to the parent for the prefix (the child shares its prefix with the parent by reference). The
   frame period is a rational; frames of parent and ghost are paired by tick, never by position in a list.
   Decimation by a consumer must keep three ticks: the fork tick, the first-divergence tick and the failure
   tick; the manifest lists them as `keep_ticks`.
4. **First divergence per ghost.** From `telemetry.divergence <parent> <child>`: the first divergent tick
   (which for a fork against its parent is the intervention tick or later), the first stage over tolerance, the
   variables that differ under their physical names and units, and the first tick at which a requirement atom or
   a task decision differs. Two reading rules travel with the numbers as fixed text: the first recorded
   discrepancy is labelled with its temporal resolution; and the order in which solver stages report residuals
   inside a tick is not evidence of a physical cause. Where the fork changed topology-independent quantities
   only, all variables pair by stable identifier; a variable with no counterpart is listed as unpaired.
5. **What a ghost may say.** Its fork class (one of continuation, exogenous, contact-affecting, information, or
   `diagnostic`), its label from the attribution, and class `Estimated`; never more than the claim class of its
   source run. A `diagnostic-forced` child is shown only if asked for (`--include-forced`) and carries that
   label in its row.
6. **Gating.** `gated` reports the status of the null-fork gate and the fork-classification gate for the build.
   If either is not `pass`, the manifest is returned with `ghosts: []` and the reason; consumers must not draw
   forks. A run whose determinism class does not license replay yields the same empty result with that reason.
7. **Pose telemetry.** The feed names, per ghost, the telemetry handle of its body-pose channel if retained, or
   the child address from which a consumer's writer may have it reproduced by replay; the feed itself stores no
   poses.
8. **Layout.** `crates/frob-autopsy/src/ghost.rs`. Determinism: the manifest is a pure function of the
   transcript, the fork ledger and stored divergence results; identical bytes on repeat.

## Acceptance criteria

- [ ] For the null fork the manifest's first-divergence entry is `none`, and a consumer drawing it finds the
      ghost's rows bit-equal to the parent's in every frame (deviation exactly zero).
- [ ] For an intervention fork the first divergent tick is the fork tick or later and the decision tick is
      reported.
- [ ] `keep_ticks` contains the fork tick, the first-divergence tick and the failure tick for every ghost.
- [ ] Selection is deterministic and capped at 16; two calls return identical bytes.
- [ ] With a null-fork or classification gate not passed for the build, `ghosts` is empty and the reason is
      stated.
- [ ] Every ghost row carries class, label and `Estimated`; the tables are byte-equal to the text the verbs
      returned.
- [ ] The viewer overlay and the replay packet consume the manifest without recomputing anything (asserted by
      their own tests; here by a consumer stub in the conformance crate that reads only the manifest and stored
      telemetry).

## Test plan

### Unit tests
`crates/frob-autopsy/tests/ghost.rs` (real forks on fixture 2):
- `null_ghost_coincides`: poses of the null fork equal the parent's bit for bit over the horizon.
- `fork_tick_is_anchor`: frames pair by tick; a ghost has no frame before the anchor.
- `first_divergence_at_or_after_fork_tick` (property over 50 forks).
- `selection_rule_and_cap`: 40 forks in the ledger → 16 chosen in the stated order.
- `keep_ticks_complete`.
- `gated_off_returns_empty` (gate status forced to `not run`).
- `tables_are_verbatim`.
- `forced_children_hidden_by_default`.
- `manifest_is_deterministic`.

### End-to-end script and logging
`scripts/e2e/autopsy_session.sh` (N27b-18) ends with `frob autopsy show <session> --format ghost` and, once the
replay packet exists, an export of the run with the session's forks through `frob telemetry export-html` (the
option that names the forks is the export verb's own); it asserts the manifest's schema, the null
ghost's zero deviation through `frob telemetry query`, and that the exported file's fork table equals the
manifest's. Logged: forks selected, anchors, first-divergence ticks, `keep_ticks`, gate status.

### Known answers and negative controls
The packet's known answer: a null fork drawn as a ghost coincides with its parent; the rows are bit-equal, so
the deviation is exactly zero in every frame. Negative controls: a feed that pairs frames by list position
(a ghost that starts at the fork tick is drawn against the parent's first frame: the anchor test fails); a feed
that reports stage order as cause (the fixed reading-rule text is asserted present); a feed that draws forks
while the gates are not passed. Determinism: byte-identical manifests twice on one machine and across
platforms.

## Considerations

- The 16-fork cap and the size rules are the packet's; a session with more forks is not truncated silently: the
  manifest lists how many were not selected and the rule that excluded them.
- Pose telemetry for children is not retained by default (forks are cheap to replay); a consumer that needs
  frames asks the store to reproduce them from the child address, which costs one fork.
- A ghost is a picture of one fork of one world. It is persuasive and proves nothing; the label and class on
  every row are there for that reason.
