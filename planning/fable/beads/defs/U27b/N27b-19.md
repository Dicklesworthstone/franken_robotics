## Background

A refusal in this system is a typed answer: a stable code, a message, a pointer to what is at fault, what was
observed against what was required, whether a retry can help, and ranked repairs. For an agent debugging a
failure, Autopsy's refusals are as useful as its results: they are how it learns that a gear ratio cannot be
tested one second before a thermal trip, or that a failure does not survive double precision. Autopsy defines
eight codes:

| Code | Refusal |
|---|---|
| FROB-REF-580 | A continuation whose physical, clock, sensor or policy contract does not match the checkpoint |
| FROB-REF-581 | A structural or design-parameter intervention requested at a mid-episode tick; the earliest valid tick and the forcing fields are returned |
| FROB-REF-582 | State from one model grafted onto another |
| FROB-REF-583 | The null fork does not reproduce its parent |
| FROB-REF-584 | Attribution requested for a failure that neither lane admits, or under an uncontrolled determinism class |
| FROB-REF-586 | An intervention changes more than one declared mechanism |
| FROB-REF-587 | A design-parameter re-run with a policy that cannot act on the edited body without retraining |
| FROB-REF-880 | An attribution cited as an established cause, or as a cause in the physical robot |

The registry bead holds each row with its trigger and repairs; the mechanism beads raise them in unit tests.
This bead is the script that raises every one from the user's side, on the real binary and on real fixtures,
and checks the envelope an agent would actually receive, on both surfaces. One script per capability: the
capability is "Autopsy refuses correctly". Tier Solid.

## Scope

In: `scripts/e2e/autopsy_refusals.sh`: one planted trigger per code, the envelope assertions, exit codes, the
CLI and MCP forms, the neighbouring refusals an Autopsy user meets (FROB-REF-562 below class D2; the unknown
verb `autopsy fork`), and the logs.
Out: the registry rows (N27-REF); the mechanisms; the gate-scale refusal checks inside other scripts (the
gear-change and graft clauses of the fork gate in N27b-04).

## Technical approach

1. **Fixtures.** Fixture 1 (the cart at its sill; 60 mm and 75 mm wheel designs); fixture 2 (the quadruped on
   the split-grip landing); a film patch with an optical effect on a generated floor; the marginal-failure
   fixture of the precision known answer (the host threshold block of N27b-07, reached through the Autopsy
   verbs by its handle `fixture:host/threshold-block` in the conformance build of `frob`, N27b-03; the script
   runs on that build and says so in its log header); a body-specific policy. All generated; seeds explicit.
   Every call of a `run` verb carries `--key` with a key derived from the script, the code and the surface.
2. **One trigger per code** (each a `frob … --json` call; the script asserts `ok: false` or the `refused` entry,
   the code, exit code, `pointer`, `observed`, `required`, `retry` and the first repair):
   | Code | Trigger from the CLI | Key fields asserted | Exit |
   |---|---|---|---|
   | 580 | `frob run fork <run> --world <w> --at <tick>` (no `--change`: the null continuation) on a run whose checkpoint was recorded under a different clock contract (a sensor rate changed in the task between record and fork) | `pointer`: the checkpoint; `observed`: the mismatching contract (`clock`); repair 1: fork from the nearest snapshot whose contracts match, or replay from the address | 3 |
   | 581 | `frob autopsy intervene <fork> --do 'model.joint[*.knee].gear_ratio := 16'` at a mid-episode fork | `earliest_valid_fork_tick: 0`; `forced_by` ⊇ {actuator thermal state, policy history, contact memory}; repair 1: the `frob autopsy rerun … --edit 'regear *.knee 16'` command | 3 alone; 2 beside an admitted intervention |
   | 582 | On fixture 1, with C the 60 mm run: `frob run fork <C> --world <w> --at <lip tick> --change 'model.wheel[front].radius := 75 mm' --reuse checkpoint.contact.memory` (the graft as BD-205 defines its request), and the same through `frob autopsy intervene <fork at the lip> --do 'model.wheel[front].radius := 75 mm' --reuse checkpoint.contact.memory` | `pointer`: the contact memory; `observed`: the contact memory as the field that forces a restart; repair 1: fork at the earliest valid tick returned; repair 2: restart and settle | 3 |
   | 583 | `frob autopsy intervene` on a fork whose checkpoint has its packet queue stripped in disguise (entries removed, contract fields intact; a conformance fixture) | `observed`: first divergent tick and stage; repair 1: the `frob telemetry divergence` command; nothing attributed | 3 |
   | 584 | `frob autopsy intervene` with one admissible `--do`, and then `frob autopsy attribute`, on the marginal single-precision failure that double precision does not reproduce and the lane does not admit (the threshold block, reached as `fixture:host/threshold-block` on the conformance build; default `--lane auto` on both) | `observed`: the equivalence table and, in a build with the lane (N27b-23, N27b-24), the lane's ρ₀ and growth figures; in a build without it `observed.lane = "not-built"` (N27b-07), and after KILL-ENSEMBLE the precision route of the decision as first written; repair 1: fork closer to the failure; the world has an artifact-guard record | 3 |
   | 584 (class) | `frob autopsy attribute` on a fork set recorded with a child under an unrecorded determinism class | `observed`: the class; `required`: D2 | 3 |
   | 586 | `frob autopsy intervene <fork> --do 'scene./floor/patch[wet-1]/film := dry'` with the mechanism split undeclared | `observed`: both mechanisms (`contact.friction`, `sensing.optics`) with their changed fields; repair 1: the two split `--do` strings | 3 alone |
   | 587 | `frob autopsy rerun <run> --edit 'regear *.knee 16' --worlds failing` where the run's controller is a policy trained for the original body alone | `pointer`: the policy; repair 1: re-run under the baseline controller re-synthesized from the edited model (`--controller resynth`); repair 2: a family policy (`--controller family:<policy>`); repair 3: a sampling controller (`--controller mpc`) | 3 |
   | 880 | The session's attribution cited through the report path as established, then as a cause in the physical robot | `observed`: class `Estimated` and the scope text; repair 1: cite as described; repair 2: re-run and study | 3 |
3. **Neighbours.** (a) `frob autopsy intervene` on a run of class D3: FROB-REF-562 (attribution or a
   counterfactual fork requested below class D2), exit 3. (b) `frob autopsy fork …`: FROB-REF-801 (unknown
   verb) with `frob run fork …` as the repair. (c) `frob autopsy intervene` with no idempotency key:
   FROB-REF-805. (d) A structural intervention at tick 0 is *admitted* (the positive control of 581). (e) The
   same film intervention with the split declared is *admitted* as two interventions (the positive control of
   586). (f) The body-specific policy case with `--controller resynth` (the spelling of `autopsy.rerun`, BD-283)
   is *admitted* (the positive control of 587). (g) The marginal fixture again with `--lane f64`: FROB-REF-584
   with `observed.lane = "not-requested"` and no lane figures (double precision was forced, so the lane was
   not tried); the same fixture with its wide margin is *admitted* under `--lane f64` (the positive control of
   584). (h) A second request for a factor already run as a fixed table, with `--test sequential`:
   FROB-REF-553 before any fork runs.
4. **Both surfaces.** Each trigger is issued through the CLI and through `frob-mcp`; on MCP the tool result has
   `isError: true` and its structured content is the same envelope; the script compares the two envelopes field
   by field (cost and trace identifiers excluded).
5. **Nothing leaks.** After each refusal the script checks that no fork was run and nothing was charged where
   the refusal precedes admission (`cost` zero; the run's store digest unchanged), and for the partial case of
   581 that exactly the admitted interventions ran.
6. **Registry agreement.** For every code raised, the envelope's message and repairs equal the registry row
   (`registries/refusals.toml`) after template substitution; an envelope with a repair the registry does not
   list fails the script.

## Acceptance criteria

- [ ] Each of the eight codes is raised by its trigger with the fields of the table and exit 3 (2 for the
      partial 581 case), on CLI and on MCP with equal envelopes.
- [ ] Each positive control is admitted.
- [ ] FROB-REF-562, -801, -805 and -553 are raised by the neighbour cases, and the forced-`f64` form of 584
      carries `observed.lane = "not-requested"`.
- [ ] No refusal that precedes admission runs a fork or charges budget.
- [ ] Envelope text and repairs equal the registry rows.
- [ ] The script is idempotent, exits non-zero on any failed assertion, and writes its log and transcript.

## Test plan

### Unit tests
None of its own. `--self-test` runs the 581, 586 and 880 cases, which need no special fixture, on every change.

### End-to-end script and logging
`scripts/e2e/autopsy_refusals.sh`. Log `target/e2e-logs/autopsy_refusals/<utc>.ndjson` and a transcript beside
it. Every line: `ts`, `script`, `bead` (`N27b-19`), `step`, `event`, the exact command, exit code, wall time,
surface (`cli` or `mcp`), and the envelope's evidence block where one exists. One `refusal` line per trigger:
`code`, `pointer`, `observed`, `required`, `retry`, the ranked repairs, `exit`; one `assert` line per field
checked and per registry comparison; `metric` lines `forks_run_after_refusal` (threshold 0) and
`cost_after_refusal` (threshold 0). On failure: the expected and received field, and the fixture and fork
identifiers needed to reproduce. Final `summary`: assertions passed and failed; codes raised (eight of eight);
gates touched: none. No private-scene data is logged.

### Known answers and negative controls
KA-671's control (a stripped packet queue is refused, not replayed: FROB-REF-583 when the strip is disguised,
FROB-REF-580 from classification when it leaves a contract field missing), KA-676 (the warm-start graft is refused
with FROB-REF-582), KA-679 (the marginal failure), the mid-episode request of the thermal counterexample (refused
with FROB-REF-581). The positive controls (d) to (f) are the negative controls of the script itself: a build
that refuses everything fails them. The script's own plants are declared in its header
(`plants=exit-2-for-lone-581,reordered-repairs`) and injected under `E2E_PLANT_FAILURE` (STD-E2E): the observed
exit code of the lone 581 case read as 2, and the script's copy of the 586 registry row with its repairs
reordered; each must fail its assertion, which names the plant (`run-all.sh --verify-plants`). A build-level
defect (an implementation that maps a lone FROB-REF-581 to exit 2) cannot be planted in a product binary
(N38b-04), and this script touches no gate whose receipt could carry a mutation control: it is caught in
BD-279's crate tests (`all_refused_exit_3` on a lone 581 request).
Determinism: refusals are deterministic; the script's envelopes are byte-identical twice on one machine and
across surfaces.

## Considerations

- FROB-REF-584 has two triggers (neither lane admits; an uncontrolled determinism class) and FROB-REF-562 guards
  the door before either. The script exercises all three so that their order of precedence is pinned: the
  licence check on the source run's class fires first.
- The 584 row's `observed` block depends on what the build holds (the lane, no lane, or the lane withdrawn by
  KILL-ENSEMBLE); the script reads the build's capability list and asserts the matching form, and logs which
  form it asserted, so that a lane that silently disappears is visible in the log.
- The 587 trigger needs a policy artifact that declares it was trained for one body. Until policy files carry
  that declaration, the case is run with a `synthetic` policy manifest and labelled so in the log.
- A refusal's repairs are commands. The script executes repair 1 of 581, 586 and 587 and asserts that it is
  admitted, so a repair that does not work is a failing test.
