## Background

After thirty edits a design that used to climb stairs no longer does. Which edit broke it? The lineage (the
content-addressed graph of design versions whose edges are typed edits; bead BD-113) makes the question
answerable by search: `frob design bisect --predicate succeeds --task <task>` walks a lineage path by binary search,
decides each step with the anytime-valid paired comparison, and returns the edit that changed the outcome. It
is part of the scenario the fourth milestone must demonstrate: thirty design-check-simulate-explain-edit cycles
in an hour, every comparison a declared study, and bisect finding the edit that broke stair climbing.

Three properties make the answer trustworthy, and each is a rule here.

- **Bisect is honest about non-monotone lineages.** Binary search is correct only for a predicate that is
  monotone along the path. Counterexample: outcomes along six versions are pass, fail, pass, pass, pass, fail.
  The midpoint passes, the search goes right and reports the last edit, while the first edit also changed the
  outcome and the second changed it back. `design bisect` therefore returns a pair of adjacent versions with
  different decided outcomes, which is always a true statement, labelled `a-change`. It labels the result
  `first-change` only after the prefix has been scanned (every earlier version decided) or when the caller
  declares the predicate monotone, which is recorded as an assumption on the result.
- **Bisect controls its own error.** Each probe is an e-process at level α/⌈log₂ L⌉ for a path of L edits, so
  the whole search errs with probability at most α by the union bound. An inconclusive probe ends the search
  with the bracket reached and the evidence so far. (N28b-02 makes the count exact: α is divided by the number
  P of probes the plan can make, which is ⌈log₂ L⌉ when the bad endpoint already has a stored decided outcome,
  one more when it must be probed, and L − 1 + that one with a prefix scan.)
- **Merge is order-independent.** Lineages and archives from several agents merge as grow-only sets of versions
  and per-cell maxima under a total order (fitness, then `DesignId`). The merge is commutative, associative and
  idempotent, so the result does not depend on who synchronized first. (FACT: the sibling archive routine
  replaces an elite only on strict improvement, so equal fitness keeps the first arrival; the total order
  removes that dependence on arrival.)

Seed done-condition: bisect row of GATE-ATEL-04: the planted edit is found in at least 95 of 100 trials; bisect
on a non-monotone predicate is refused (that is: a `first-change` answer is refused without a scan or a
declared monotone predicate).

## Technical approach

1. **Verb.** `frob design bisect --good <version> --bad <version> --predicate <expr> --task T [--margin δ]
   [--level α] [--via <version>] [--scan-prefix] [--assume-monotone] [--require first-change] [--budget …]
   --key K --json`. Kind `run`; idempotency key (`FROB-REF-805` without one; two searches a test compares carry
   distinct keys) and budget; exit 8 with a job while running; phase `review`. `--level` is the total level α
   (default 0.05), the same spelling as `eval.compare`; `--margin` is the predicate's margin δ, with the same
   meaning and default as `eval.compare`'s `--margin`. The path is the lineage path from `--good` to `--bad`
   (the bad version must be a descendant, else the call is refused with `FROB-REF-802`, exit 3, pointer
   `/bad`, naming both versions and the relation found, `not-descendant`, before any probe; 802 is the
   surface's invalid-request code, appended to every row by the generator, so no chapter code is added; with
   several paths the caller names one with `--via`, else the path with the fewest edits,
   ties by canonical bytes; the rule used is reported as `path_rule`). Migration edges whose record says
   `semantic: Identical` are contracted first by N28b-05's `lineage::contract_identical_migrations` (they
   change no model); L = the number of remaining edits on the path.
2. **Predicate.** One of: `succeeds` (the task's requirement verdict, a success indicator with span [−1, 1]);
   or `metric M worse-by m` in the same form. The good endpoint v₀ is the reference and is never probed. Any
   other version v is decided against v₀ by one paired `anytime` comparison on common world addresses, and the
   comparison's verdict maps to a probe outcome (N28b-02's table): `changed` when it is settled with v worse
   than v₀ by more than δ; `unchanged` when it is tied within ±δ or settled with v not worse than v₀ (a version
   better than v₀ by more than δ is `unchanged`, not undecided); `inconclusive` when the comparison ends
   `inconclusive` at budget, `incomparable` or `infeasible`. The bad endpoint is decided first unless a stored
   comparison against v₀ already decides it: decided `unchanged`, the result is labelled `no-change` (exit 2)
   with its probe record; `inconclusive`, the result is labelled `bracket` with (lo, hi) = (0, L) (exit 2). No
   interior version is probed in either case.
   **Admission of the probes.** Every probe is a paired comparison of BD-262's machinery, so every probe's
   study plan passes N28a-18's `pairing::admit` (and, after it, N35-07's determinism licence, as on
   `eval.compare`) before the error budget is fixed and before the first probe. The probes share the task,
   tier, profile, controller arm and address list, so one failing admission refuses the whole search, zero
   probes, with the admission's code: `FROB-REF-542` (a D4 arm, arms of different classes, or D3 without
   decision-level equivalence recorded for the task); `FROB-REF-543` (the predicate `metric M worse-by m` on a
   metric with no declared span: the e-process needs one; `succeeds` has the span [−1, 1]); `FROB-REF-561` for
   the licence-only cases. A memoized episode reused by a probe carries its recorded class, and one recorded
   under another class is refused the same way rather than mixed in.
3. **Search.** Maintain a bracket (lo, hi) with lo decided `unchanged` (like the good end) and hi decided
   `changed`. Probe the midpoint version ⌊(lo + hi)/2⌋; `unchanged` moves lo, `changed` moves hi; stop when
   hi = lo + 1. At most ⌈log₂ L⌉ interior probes. The error budget is fixed before the first probe: P =
   ⌈log₂ L⌉ + e, where e = 1 when the bad endpoint has no stored decided outcome against v₀ and 0 otherwise,
   and each probe (the endpoint probe included) is a study at level α/P, so the search errs with probability
   at most α. With the bad endpoint stored this is the plan's α/⌈log₂ L⌉. Early termination does not change
   the level. Probes consume episodes in address order and reuse memoized episodes.
4. **Result of the search.** The adjacent pair (v_i, v_{i+1}), the edge between them (patch id, typed edits,
   agent, session), the label `a-change`, the per-probe evidence (e-value, pairs used, tier), total episodes,
   and the error statement "with probability at least 1 − α, v_i is unchanged and v_{i+1} is changed". Exit
   codes (DESIGN): a found change, labelled `a-change` or `first-change` (with or without the recorded
   monotone assumption), exits 0, because the verb answered its question with a true statement; `bracket` and
   `no-change` exit 2 (an honest ending without the pair); a refusal exits 3.
5. **`first-change`.** Granted only if (a) `--scan-prefix`: every version before v_{i+1} on the path is probed
   and decided `unchanged`, skipping versions the search already decided; the plan then counts P = L − 1 + e
   probes (the L − 1 interior versions plus the endpoint probe if needed), each at α/P, fixed before the first
   probe, and the result carries `prefix: scanned` and `scanned_through`; or (b) `--assume-monotone`: the
   result carries `assumption: monotone (declared)`, visible in every report that cites it. `--require
   first-change` (the caller says an `a-change` is not an acceptable answer) with neither flag is refused before
   any probe with **FROB-REF-550**, exit 3 (repairs: scan, or declare and record the assumption). If the scan
   finds an earlier change, the result reports that earlier pair as `first-change` and lists the later ones as
   further changes; an inconclusive scan probe leaves the label `a-change` and reports how far the scan got.
6. **Inconclusive probe.** A probe that ends `inconclusive` ends the search: the result is labelled `bracket`
   (exit 2) with the bracket (lo, hi) reached, every probe's record, the e-values so far and the pairs each
   would still need (from the e-process's rate). The result record is N28b-02's `frob.bisect/1`, with label
   one of `a-change`, `first-change`, `bracket`, `no-change`.
7. **Confirmation.** The found edit's two versions carry `provisional` comparisons when probed on a fast tier;
   `next_actions` offer promotion of that one comparison on the referee and `explain.compare` on it.
8. **Lineage merge.** `lineage::merge(a, b)`: the union of the node sets and of the edge sets (both keyed by
   content; edges by (parent, child, canonical ops)), with per-edge provenance sets united. Properties
   (INV-ATEL-09): merge(a, b) = merge(b, a); merge(a, merge(b, c)) = merge(merge(a, b), c); merge(a, a) = a.
   A merge creates no new design version; a `merge` edge is used only when an agent combines two designs into
   a new term. Archive merge, built by the archive bead on N28b-04's `Join`: per cell keep the entry that is
   greatest under the total order (fitness, then `DesignId`, then `EvidenceId` when one design carries two
   fitness records), which is likewise commutative, associative and idempotent; the serialized form is
   canonical, so two merge orders give identical bytes.
9. **Class.** The search is a pure function of the per-address outcomes of its probes and the path; D0 given
   outcomes. Evidence `Tested`; a development result unless the found comparison is qualified.

## Acceptance criteria

- [ ] GATE-ATEL-04, bisect row (the seed's done-condition; measured and recorded by the battery N28b-03 on
      this bead's verb): over 100 planted lineages (lengths 8 to 32 edits, one planted outcome-changing
      edit in the 80 monotone ones, effect sizes drawn from the registered range), `design bisect` returns the
      planted edit in at least 95 trials at α = 0.05.
- [ ] PO-ATEL-08: on the same set with 20 non-monotone lineages (two or three outcome flips), no result
      labelled `first-change` is wrong; every `a-change` pair returned is a true change; the observed error
      rate of the bracket statement is within the exact binomial bound for α.
- [ ] The six-version fixture (pass, fail, pass, pass, pass, fail): without flags the answer is an `a-change`
      at the last edit; requiring `first-change` is refused (550); with `--scan-prefix` the answer is
      `first-change` at the first edit, with the second and the last listed as further changes.
- [ ] Each probe runs at α/P, recorded in its study plan and fixed before the first probe: with the bad
      endpoint stored and no scan, α/⌈log₂ L⌉ (for L = 32, five probes at α/5); with the bad endpoint not
      stored, P = ⌈log₂ L⌉ + 1 (for L = 32, α/6); with `--scan-prefix`, P = L − 1 + e.
- [ ] An inconclusive probe returns label `bracket` with the bracket and evidence, exit 2; endpoints not decided
      different return `no-change` (bad endpoint `unchanged`) or `bracket` (0, L) (bad endpoint inconclusive),
      exit 2, with no interior probe.
- [ ] `--require first-change` without `--scan-prefix` or `--assume-monotone` returns `FROB-REF-550`, exit 3,
      and runs no probe; an `Identical` migration on the path is contracted before planning.
- [ ] A found change exits 0 (`a-change`, `first-change`); a `--bad` that is not a descendant of `--good` is
      `FROB-REF-802`, exit 3, pointer `/bad`, with no probe; a D4 arm is 542 and `metric M worse-by m` on a
      metric with no declared span is 543, each before any probe.
- [ ] Lineage merge is commutative, associative and idempotent on 10³ random triples of lineages, and merging
      two agents' lineages in both orders gives identical serialized bytes.
- [ ] The verb is reachable through `frob --json` and MCP; cancelling the job publishes no partial result; a
      repeated call with the same key returns the stored answer.

### Known answers and negative controls

KA-702: outcomes pass, fail, pass, pass, pass, fail: an `a-change` at the last edit; no `first-change` without
a scan. Negative controls: CX-313, the plain binary search that reports the last edit as the first change (a
registered mutant, which must be shown wrong on the fixture); a mutant that runs each probe at α instead of
α/⌈log₂ L⌉ (its error rate exceeds α on long paths; caught by `error_rate_within_alpha` at L = 32); a merge
that prefers the first arrival on ties (order-dependent bytes). Determinism: identical results under random
completion order and worker counts.

## Considerations

- Cost: a search over 30 edits is five probes; each probe is a paired comparison that stops early when the
  change is large. Small changes make probes inconclusive, which is reported, not hidden.
- A predicate can change for reasons other than the design (a controller re-synthesized per version); the
  controller arm is part of each probe's plan, and a shared-controller arm isolates the body's change.
- The union bound is conservative; it is kept because it needs no assumption about dependence between probes
  that share addresses.
- Merge never resolves a conflict by time. Two agents that made the same edit meet at the same node; two that
  made different edits produce two branches, which is the correct result.
