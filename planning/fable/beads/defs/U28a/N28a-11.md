## Background

For each static analysis there is a plausible cheaper analysis that gives the wrong answer on a small,
hand-checkable case. The studio keeps those cases on purpose. They are the first seeds of the project's
negative-control registry: a gate that nothing can fail validates nothing, so each gate on an analysis must show
a planted wrong method being contradicted. This bead registers the nine shortcut cases as executable mutants
with their smallest breaking case, so that (a) the real analysis is tested against the case, and (b) the mutant
is run on the same case and observed to give the wrong answer. Both halves are needed: if the mutant gives the
right answer, the case no longer discriminates and the control is void.

Two of the nine concern analyses that other subsystems implement (symmetry, observability). They are registered
here as well, from the studio's side, because `design.check` is where an agent would be misled by them.

## Scope

In: nine registry entries with fixtures, mutants and expected outcomes; the runner glue; the binding to the
gates' rows. Out: the analyses; the full counterexample catalogue of the chapter (key `N28-CX`, another unit),
which lists these and nine more with their rules.

## Technical approach

Each entry: `{id, analysis, shortcut (mutant id), case (fixture), truth, mutant_answer, rule_protected,
first_milestone}`. A mutant is a small alternative implementation in `frob-conformance` (never in the product
crates), callable through the same analysis trait.

**Arithmetic kept in the registry for rows without a mechanism at M1.** Row 6: P(majority of 7 correct at
q = 3/4) = Σ_{k=4..7} C(7, k)·(3/4)ᵏ·(1/4)^{7−k} = (2,835 + 5,103 + 5,103 + 2,187)/16,384 = 3807/4096; the
test computes the sum in rationals and compares, and computes 27/32 for three reads and 459/512 for five. With a
shared fault bit all reads fail together and the success stays 3/4. Row 8: F at the four operating points, for
both μ.

**Runner.** `frob conformance run --registry negative-controls --chapter 28` executes, per entry bound at this
build: the real analysis on the case (must equal `truth`), the mutant on the case (must equal `mutant_answer`,
which differs from `truth`). An entry whose mutant agrees with the truth is reported `control-void` and fails
the run. Entries not yet bound print `not-yet-due (M3)` or `(M4)`.

## Acceptance criteria

- [ ] Nine entries load; seven are bound at M1 (rows 1, 2, 3 growth-vector half, 4, 5, 7, 9) plus the
      arithmetic of row 6; rows 3 (curvature mutant), 6 (alias search) and 8 are listed with their milestones.
- [ ] For every bound row the real analysis returns the truth and the mutant returns the stated wrong answer:
      1,596 wrongly accepted bodies; the two-tick design rejected; (2, 3) reported while the task needs (3);
      the mechanical group of order 4 offered for tying where the usable group has order 2; an exclusion issued
      without approach energy; 2.6917 for both feedforward laws; all three packet variants reported served.
- [ ] A registered mutant that happens to agree with the truth fails the run as `control-void`.
- [ ] Each row is cited by the gate row it protects (GATE-ATEL-02 for rows 1, 3, 4; GATE-ATEL-05 for rows 2, 5,
      6, 7, 8, 9), and the M1 exit review can list every M1 gate of the studio with a caught control.

## Test plan

### Unit tests

`crates/frob-conformance/tests/atelier_shortcuts.rs`: one test per row named `shortcut_<n>_caught`, each
asserting both halves; `majority_3807_4096`, `majority_27_32`, `majority_459_512`, `shared_fault_three_quarters`;
`drawbar_forces`: 3.33, 6.67, 3.33, 6.67 N in the torque-limited runs and 4 N against 8 N in the
traction-limited one; `control_void_detected` with a deliberately correct "mutant".

### End-to-end script and logging

`scripts/e2e/atelier_check.sh` (bead N28a-29) ends with the conformance run above. Logged per row: the case,
the truth, the analysis's answer, the mutant's answer, `caught`, and the gate row it protects; the summary line
lists the gates touched.

### Known answers and negative controls

The truths are KA-680 to KA-688 of the registry (bead N28-KA); the shortcuts are, by row: CX-302 (row 1),
CX-303 (row 2), CX-304 (row 3), CX-305 (row 4), CX-306 (row 5), CX-307 (row 6), CX-308 (row 7), CX-309 (row 8)
and CX-310 (row 9). This bead is
itself the negative-control set; its own control is `control_void_detected`. Determinism: exact arithmetic
except row 7 (double precision, compared to the printed digits).

## Considerations

- Mutants live outside the product crates so that no build can ship one; the conformance crate is layer 7.
- Row 4's refusal (a policy tied under the mechanical group) is implemented by the learning subsystem at M4;
  at M1 the check is that `analyze.symmetry` reports both groups and names the lidar mount as the breaker.
- If a later change makes a case non-discriminating (for example a better screen), the entry is replaced by a
  smaller breaking case, never deleted.
