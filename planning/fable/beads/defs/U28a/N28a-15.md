## Background

A kill gate is a decision named in advance with its trigger, measurement and fallback; one that fires is not a
failure, because the fallback is the plan. KILL-ATLAS governs the one Frontier claim of analysis A-26, the
regime atlas: that the regions it draws on a design's recorded operation (by contact mode, slip state,
saturation state and derivative validity) tell an agent where a gradient is trustworthy. The atlas computes
nothing new about the robot; its whole value is fewer wrong gradient steps and fewer misread rankings, so if
the label does not predict anything, the label goes and the description stays.

## Scope

In: applying the trigger to the pilot's record, the ADR, the feature's fate, the downstream statement. Out: the
pilot (N28a-14); the analysis (N28a-16), which is built in the form this decision selects.

## Technical approach

**Trigger.** The A-26 pilot fails: on recorded runs of the reference quadruped, a region's validity label
predicts the sign agreement between a smoothed gradient estimate and a specialist-checked finite difference no
better than "trust nowhere" at a 95% lower bound.

**Milestone.** M4, before the analysis is built.

**Measurement that decides it.** From the pilot record: skill s = acc_label − acc_never with its one-sided 95%
lower bound (bootstrap clustered by world address); the share of units excluded as inside noise; the
`underpowered` flag.

**Decision rule.**
1. The lower bound of s is above 0 and the pilot is not `underpowered` → `not fired`: A-26 is built with the
   validity label, as a screening signal.
2. The lower bound of s is at or below 0 → **fires**.
3. `underpowered` (more than half the units inside the noise band) → one re-registration with larger
   perturbations is allowed; a second underpowered or failing pilot **fires**.

**Fallback, named in advance.** A-26 is a descriptive report with no validity label.

**What changes downstream when it fires.**
- `analyze.regimes` returns the partition, occupancies, the shortest replayable failure per region and the
  ranking-change regions; the fields `validity` and `local_model` are absent, and the schema version without
  them is the registered one.
- No consumer may gate a gradient step or a discard on an A-26 region: the ladder's screening use of A-26 is
  removed from the stage table of the cascade, and the sensitivity analysis keeps its own labels.
- `explain.compare`'s regime report is unaffected (it never depended on the label).
- The feature `frontier-regime-validity` is deleted, not left dormant; the pilot record and this ADR are what
  a future proposal must answer.

**Record.** `docs/adr/KILL-ATLAS.md` with s, its bound, the unit counts, the pilot's identity, commit and
seeds; the kill row in the gate register; decided by a session that did not run the pilot.

## Acceptance criteria

- [ ] The ADR cites s, its lower bound, the excluded share and the pilot identity.
- [ ] The gate register carries the decision with measured values.
- [ ] If fired: `frob analyze regimes <run> --json` validates against the descriptive schema and contains no
      validity field (test); the cascade's stage table lists no A-26 screening use.
- [ ] If not fired: the analysis bead is released with the label and the screening mark.
- [ ] A decision recorded before the pilot record's ledger sequence is rejected.

## Test plan

### Unit tests

- `kill_atlas_rule_table`: (s = 0.31, bound 0.12) → not fired; (s = 0.05, bound −0.03) → fired;
  (underpowered, then bound 0.08) → not fired; (underpowered twice) → fired.
- `descriptive_schema_has_no_validity`.

### End-to-end script and logging

`scripts/e2e/kill_atlas_record.sh`: reads the pilot record, applies the rule, compares with the ADR and the
register, and when the analysis exists runs `frob analyze regimes` on the one-switch fixture to check the
schema in force. Logged: s and its bound against 0, the excluded share against 1/2, the decision, the ADR path.

### Known answers and negative controls

The rule fixtures. Negative control: a register row with the target in place of the measured bound is rejected.

## Considerations

- The gate is decided on a pilot, not on the finished analysis, because the question is whether to build the
  label at all. If the label is built and later shown to mislead on other robots, the same fallback applies by
  a new decision.
- The decision does not touch the family-batch gradient mechanism, which has its own kill gate.
