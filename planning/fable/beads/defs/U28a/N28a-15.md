## Background

A kill gate is a decision named in advance with its trigger, measurement and fallback; one that fires is not a
failure, because the fallback is the plan. KILL-ATLAS governs the one Frontier claim of analysis A-26, the
regime atlas: that the regions it draws on a design's recorded operation (by contact mode, slip state,
saturation state and derivative validity) tell an agent where a gradient is trustworthy. The atlas computes
nothing new about the robot; its whole value is fewer wrong gradient steps and fewer misread rankings, so if
the label does not predict anything, the label goes and the description stays.

## Scope

In: applying the trigger to the pilot's record, the ADR, the feature's fate, the downstream statement. Out: the
pilot (N28a-14); the analysis (N28a-16), which is built in the form this decision selects.

## Technical approach

**Trigger.** The A-26 pilot fails: on recorded runs of the reference quadruped, a region's validity label
predicts the sign agreement between a smoothed gradient estimate and a specialist-checked finite difference no
better than "trust nowhere" at a 95% lower bound.

**Milestone.** M4, before the analysis is built.

**Measurement that decides it.** From the pilot record: skill s = acc_label − acc_never with its one-sided 95%
lower bound (bootstrap clustered by world address); the share of units excluded as inside noise; the
`underpowered` flag.

**Decision rule** (outcomes in N40-03's closed set).
1. The lower bound of s is above 0 and the pilot is not `underpowered` → `not-fired`: A-26 is built with the
   validity label, as a screening signal.
2. The lower bound of s is at or below 0 → **`fired`**.
3. `underpowered` (more than half the units inside the noise band) → one re-registration with larger
   perturbations is allowed; a second underpowered or failing pilot is **`fired`**.
4. The pilot was not run: its envelope row R19 (N44-01's reservation, filed by N28a-14) was declined or left
   unanswered, N28a-14 closed `withdrawn` citing R19, and no perturbed run exists → **`not-reached`** (N40-03:
   the mechanism was not funded; the capability does not exist and is not described). This is the fail-closed
   branch: the label is not built and A-26 ships in the fallback form, with the same downstream changes as
   `fired`. The entry cites R19's decision record in place of a measured receipt; it is never recorded as a
   pass.

**Fallback, named in advance.** A-26 is a descriptive report with no validity label.

**What changes downstream when it fires** (and on the fail-closed branch, rule 4).
- `analyze.regimes` returns the partition, occupancies, the shortest replayable failure per region and the
  ranking-change regions; the fields `validity` and `local_model` are absent, and the schema version without
  them is the registered one.
- No consumer may gate a gradient step or a discard on an A-26 region: the ladder's screening use of A-26 is
  removed from the stage table of the cascade, and the sensitivity analysis keeps its own labels.
- `explain.compare`'s regime report is unaffected (it never depended on the label).
- The feature `frontier-regime-validity` is deleted, not left dormant; the pilot record and this ADR are what
  a future proposal must answer.

**Record.** The decision record `docs/adr/ADR-KILL-ATLAS-M4.md` (every decision record lives in `docs/adr/`;
`docs/delivery/adr/` is retired) with the fields N40-03 requires: the kill gate; the milestone; the trigger as
registered and the amendments applied (rule 3's re-registration, if used); each measured value with its receipt
hash beside the trigger's number (s, its lower bound against 0, the excluded share against 1/2); the outcome;
the fallback now in force and the name the capability carries from now on (`analyze.regimes`, descriptive
report, if fired or not reached); the beads re-read (N28a-16 "stands on the fallback" in either branch, built to
the schema selected; BD-348's A-26 row; on rule 4, N28a-14 "withdrawn before this decision", citing R19, N41-17
rule 5); what changes downstream (the list above); the recording session. It also carries the pilot's identity
(PILOT-ATLAS-01), commit and seeds (or, on rule 4, R19 and its decision record). The row of KILL-ATLAS in the
gate register gets N40-03's one decision form, `decision = { outcome, adr, date, session, receipts }`, with the
pilot result's receipt (none on rule 4, whose ADR cites R19's ruling). Decided by a session that did not run the
pilot.

## Acceptance criteria

- [ ] `docs/adr/ADR-KILL-ATLAS-M4.md` exists with every field N40-03 requires and cites s, its lower bound, the
      excluded share and the pilot identity PILOT-ATLAS-01.
- [ ] The gate register carries the decision in N40-03's form with measured values and their receipts (on rule
      4, outcome `not-reached` citing R19's decision record, never a pass).
- [ ] If N28a-14 closed `withdrawn` because R19 was not approved: outcome `not-reached`, the ADR lists N28a-14
      as "withdrawn before this decision", and the fired branch's downstream changes below apply.
- [ ] If fired (or not reached): the registered output schema of `analyze.regimes` is the descriptive one (no `validity`, no
      `local_model`; checked on the schema file) and the cascade's stage table lists no A-26 screening use; the
      analysis bead N28a-16, which depends on this decision, builds to that schema and its tests check the verb
      output.
- [ ] If not fired: the analysis bead is released with the label and the screening mark.
- [ ] A decision recorded before the pilot record's ledger sequence is rejected.

## Test plan

### Unit tests

`crates/frob-conformance/tests/kill_atlas.rs` (the convention of the studio's other kill decisions):
- `kill_atlas_rule_table`: (s = 0.31, bound 0.12) → `not-fired`; (s = 0.05, bound −0.03) → `fired`;
  (underpowered, then bound 0.08) → `not-fired`; (underpowered twice) → `fired`; (no pilot result, N28a-14
  `withdrawn` citing a declined R19) → `not-reached`, with the descriptive schema selected.
- `not_reached_is_not_a_pass`: a `not-reached` entry that carries a measured-value receipt, or a register row
  that prints it as passed, is refused.
- `descriptive_schema_has_no_validity` (on the schema file).
- `decision_before_pilot_rejected`: a decision whose ledger sequence precedes the pilot record's is refused.
- `adr_has_required_fields`: an ADR missing the beads re-read, or recorded by the session that ran the pilot,
  is refused.

### End-to-end script and logging

`scripts/e2e/kill_atlas_record.sh`: reads the pilot record PILOT-ATLAS-01 from
`crates/frob-conformance/registry/pilots.toml` (and, when it has no result, R19's row and ruling in
`registries/compute_envelope.toml`), applies the rule, compares with the ADR and the register, and
checks the registered output schema `frob.analyze.regimes.out/1` (the schema file of the VERBS-analyze row)
against the branch: no `validity` and no `local_model` if fired or not reached. It does not run `analyze.regimes`: the
analysis (N28a-16) depends on this decision, and its own script asserts the verb's output against the schema
selected here. It sources the STD-E2E helper and writes NDJSON to
`target/e2e-logs/kill_atlas_record/<utc>.ndjson`; every line carries `ts`, `script`, `bead`, `step` (`read`,
`rule`, `compare`, `schema`), `event`, the exact command line, exit code, wall time; measured values: s and its
bound against 0, the excluded share against 1/2, the decision, the ADR path and the register row; on failure the
first disagreement between rule, ADR and register; a final `summary` line naming KILL-ATLAS.

### Known answers and negative controls

The rule fixtures. Negative controls: a register row with the target in place of the measured bound is
rejected; an ADR recorded by the session that ran the pilot is rejected; on the fired branch, a schema file that
still carries `validity` fails the schema step.

## Considerations

- The gate is decided on a pilot, not on the finished analysis, because the question is whether to build the
  label at all. If the label is built and later shown to mislead on other robots, the same fallback applies by
  a new decision.
- The decision does not touch the family-batch gradient mechanism, which has its own kill gate.
