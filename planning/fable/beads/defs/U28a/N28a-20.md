## Background

A design comparison rarely has one metric and one rival. A candidate is better on energy, worse on speed and
equal on success; a generation of an optimizer has eighty candidates. Each extension is a place where a valid
test becomes an invalid one by a plausible step: multiplying evidence across metrics that are measured on the
same episodes, or eliminating a candidate the first time any single opponent beats it. This bead fixes the
admissible combinations and tests them.

**Several metrics.** The average of the per-metric e-values is an e-value under arbitrary dependence, and it
tests the global null that the candidate is no better on any listed metric. The product of e-values is valid
only for independent comparisons, which metrics computed from the same episodes are not. A claim about one
named metric uses that metric's own e-process; when several metrics are each claimed, the e-value form of the
Benjamini–Hochberg rule is applied across them, which controls the false discovery rate at α under arbitrary
dependence.

**Several designs.** A race over N candidates uses the mixture construction: rounds are the only clock, every
survivor consumes one observation per round in index order, a candidate's elimination evidence is the average
of the pairwise e-processes against all original opponents, and an elimination needs that mixture to reach at
least 1/α, so the true best is eliminated with probability at most α. An implementation that eliminates on any
single pairwise crossing must instead run each comparison at α/(N − 1) (a union bound), so that a null race
keeps its best candidate with probability at least 1 − α.

The sibling simulation suite has these as library routines (FACT: `fs-eproc::combine_average`,
`combine_product`, `e_benjamini_hochberg`; `fs-race::race_field` with its contract). They are used through the
airlock if admission passes; otherwise the same arithmetic is implemented locally against the known answers
below.

## Scope

In: the combination rules as functions with typed inputs that make the invalid combination unrepresentable, the
N-way elimination rule in both admissible forms, the null-race test, the `eval.compare` behaviour with several
`--metric` flags. Out: the single-metric e-process (BD-262); racing as part of optimization, with mid-evaluation
cancellation and the race ledger (BD-341); the nine interference tests on a replayed campaign (BD-350).

## Technical approach

1. **Types.** `EProcess<M>` is tagged with the metric and the set of addresses it consumed.
   `combine_average(&[EProcess]) -> GlobalEValue` accepts any set. `combine_product` accepts only processes
   whose address sets are disjoint (checked at run time; an overlapping set is a programming error surfaced as
   a refusal to combine). There is no other combinator.
2. **Global verdict.** With K metrics, Ē = K⁻¹·Σ_k E_k. The global null "no better on any listed metric" is
   rejected when Ē ≥ 1/α. Since each E_k is an e-process, so is Ē, and the rejection is valid at any stopping
   time.
3. **Named-metric claims (e-BH).** Sort the e-values in descending order e_(1) ≥ … ≥ e_(K). Let
   k* = max{k : k·e_(k)/K ≥ 1/α} (0 if none). The metrics with the k* largest e-values are claimed. With one
   claimed metric named in advance (K = 1) this is the plain threshold 1/α.
4. **`eval.compare` with several metrics.** The request declares, before the first episode, one of
   `claim: global` (step 2), `claim: named [M…]` (step 3) or `claim: all` (the candidate is better on every
   listed metric simultaneously: min_k E_k ≥ 1/α, an intersection-union rule, valid because rejecting all nulls
   needs each one rejected at level α). On the command line: `--metric M` repeated and `--claim
   global|named|all`; the claim is part of the plan hash. The result carries per-metric e-values and confidence
   sequences, Ē, the e-BH set (or the minimum for `all`), and stops when the declared claim is decided or the
   budget ends. A metric without a span is refused for the study type (543) and is not silently dropped. The
   input `claim` is this bead's: `eval.compare`'s row in VERBS-eval lists it (`global`, `named` or `all`) with
   this bead as its extender, beside the repeatable `metric`, and BD-262 passes it through on devices.
5. **N-way elimination, form A (mixture).** For candidates 1…N and round t, every survivor has consumed
   observations 1…t in index order. For candidate c the elimination evidence is
   M_c(t) = (N − 1)⁻¹·Σ_{o ≠ c} E_{o beats c}(t) over all original opponents o (eliminated ones keep the value
   they had when they stopped). c is eliminated when M_c(t) ≥ 1/α.
6. **Form B (pairwise union bound).** c is eliminated when any single E_{o beats c}(t) ≥ (N − 1)/α.
7. **Which form.** Form A is the default (it is the sibling's construction); form B is the documented fallback
   for a local implementation. The form is recorded in the study plan; mixing forms inside one race is
   refused.
8. **Class.** D0 given outcomes; evidence `Tested`.

## Acceptance criteria

- [ ] Worked values: K = 4, α = 0.05, e-values (100, 30, 12, 2): Ē = 36 rejects the global null; e-BH gives
      k* = 1. E-values (100, 50, 30, 2): k* = 3.
- [ ] Dependence counterexample: for two identical metrics whose e-value under the null is 0 or 2 with
      probability ½ each, the product has expectation 2 and the average has expectation 1; over 10⁴ null runs
      with optional stopping the product rule's rejection rate exceeds α and the average rule's does not.
- [ ] `combine_product` refuses two processes that share an address.
- [ ] PO-ATEL-04: in a null race of 81 identical candidates over 512 replays, the designated best candidate is
      eliminated in at most 38 replays (the 0.99 quantile of Binomial(512, 0.05)) under form A and under form
      B; with a planted winner (effect 0.3 standard deviations) both forms return it in at least 95% of 100
      races.
- [ ] A mutant that eliminates on any single pairwise crossing at 1/α loses the null best far more often than α
      (expected rate reported) and is caught.
- [ ] `frob eval compare … --metric success --metric cot --claim named --key …` returns the e-BH set and
      per-metric sequences; declaring the claim after seeing data is impossible (the claim is in the plan hash).
- [ ] `claim: all` on e-values (100, 30, 12, 2) at α = 0.05 is not decided (minimum 2 < 20), and on (40, 30, 25,
      21) it is (minimum 21 ≥ 20).
- [ ] `scripts/e2e/compare_multi.sh` passes on `batch-cpu`.

### Known answers and negative controls

Known answers: the e-BH arithmetic above; the null race bound of 81 candidates (the interference-table row
"DC-01 inside an N-way race: a null race of 81 keeps the best with probability at least 1 − α"). Negative
controls: the product on dependent metrics; the single-crossing mutant; a claim switched from `global` to
`named` after data (plan-hash mismatch). Determinism: seeded replays give identical elimination traces across
worker counts.

## Considerations

- The mixture construction is conservative when many opponents are clearly worse; the benefit of racing depends
  on separation: the sibling's own battery asserts a saving of at least 2 on a separated field and below 1.5 on
  an inseparable one, with 11.7 and 1.03 measured on its fixtures (FACT). Two to five times fewer evaluations
  when candidates are separated, and nothing otherwise, is a HYPOTHESIS for robot design populations.
- e-BH controls a false discovery rate, not a family-wise error; a claim that must hold for every named metric
  simultaneously is the declared `claim: all` of step 4 (the minimum e-value against 1/α).
- A race decides which candidates stop consuming compute; it does not by itself establish a ranking of the
  survivors.
