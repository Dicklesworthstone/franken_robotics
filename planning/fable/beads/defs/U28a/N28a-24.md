## Background

A kill gate is a decision named in advance with its trigger, measurement and fallback; one that fires is not a
failure, because the fallback is the plan. KILL-REUSE governs grade 3 of verdict revalidation: skipping the
recheck of a stored verdict after an edit because a polarity rule of the assumption lattice implies the verdict
still holds (bead BD-347). Grades 1 (identity) and 2 (dependency) are Solid and stay whatever this gate
decides. Grade 3 is Frontier and carries the worst failure the studio can commit, a false accept, for a benefit
that the plan-time evidence could not show: on the four-state camera fixture a correctly keyed dependency graph
did exactly the same work as a semantic receipt.

## Scope

In: applying the trigger to the recorded measurement, the ADR, the flag's default, the downstream statement.
Out: the pilot (N28a-23) and the gate measurement (BD-347).

## Technical approach

**Trigger.** Any unsafe reuse in GATE-ATEL-11, or grade 3 saves less than a fifth of the recheck cost that
grade 2 leaves (TARGET).

**Milestone.** M4. The pilot (N28a-23) can end the question earlier: if either of its falsifiers held, the
production path was not funded and this decision records "fired on the pilot".

**Measurement that decides it.** From BD-347's three-arm run on the frozen campaign of 30 amendments: U = the
number of incorrectly inherited verdicts in the grade-1-to-3 arm (each counted even if a later change restores
feasibility); C₂ = the recheck cost left by grades 1 and 2; C₃ = the recheck cost left by grades 1 to 3;
the saving s = (C₂ − C₃)/C₂.

**Decision rule.**
1. Pilot falsified → **fires** (no measurement).
2. U ≥ 1 → **fires**, and the rule that licensed each unsafe reuse is listed.
3. U = 0 and s < 1/5 → **fires** (the grade is safe on this campaign and not worth its risk).
4. U = 0 and s ≥ 1/5 → `not fired`: grade 3 may be enabled per campaign by flag; it does not become the
   default before a second campaign of amendments, frozen separately, repeats the result.

**Fallback, named in advance.** Grades 1 and 2 only.

**What changes downstream when it fires.**
- `result.revalidate --grades 1,2,3` is refused with the fallback named; the rule registry's rules are set
  `disabled (KILL-REUSE)`; licence records of grade 3 already issued are revoked and their verdicts scheduled
  for recheck (a list the decision produces and the ADR carries).
- The cascade's reuse stage uses grades 1 and 2; its control (a mirror swap must reuse; a shared-bus edit must
  invalidate) is unchanged, because both are dependency-grade facts.
- The mission subsystem's implication rules fall under the same decision for `result.revalidate`; its own
  standing gate continues to remove single rules.
- Reports print `reuse: dependency-keyed only (KILL-REUSE)`; no ten-fold arithmetic changes, since revalidation
  was never counted as a source of the ten-fold.

**Record.** `docs/adr/KILL-REUSE.md` with U, C₂, C₃, s, the campaign identity, commit, hardware fingerprint,
seeds, the list of revoked licences; the kill row in the gate register; decided by a session that did not run
the measurement.

## Acceptance criteria

- [ ] The ADR cites U, C₂, C₃ and s (or the pilot's falsifier) with the campaign identity.
- [ ] The gate register carries the decision with measured values.
- [ ] If fired: a request for grade 3 is refused; no stored verdict retains a grade-3 licence (query on the
      ledger returns none); the revoked list has a recheck job or a `not-rechecked` mark per verdict.
- [ ] If not fired: grade 3 is off by default and on by flag; the second-campaign condition is recorded as an
      open item with an owner.
- [ ] A decision recorded before the measurement's ledger sequence is rejected.

## Test plan

### Unit tests

- `kill_reuse_rule_table`: (pilot falsified) → fired; (U = 1, s = 0.6) → fired; (U = 0, s = 0.12) → fired;
  (U = 0, s = 0.31) → not fired.
- `fired_revokes_grade3_licences`; `fired_refuses_grade3_request`.
- `saving_formula`: C₂ = 400 core-s, C₃ = 300 core-s ⇒ s = 0.25.

### End-to-end script and logging

`scripts/e2e/kill_reuse_record.sh`: reads the gate row and the three-arm table, recomputes U and s, applies the
rule, compares with the ADR and the register, and when fired calls `frob result revalidate … --grades 1,2,3`
to observe the refusal. Logged: U against 0, s against 1/5, the decision, revoked licence count, the ADR path.

### Known answers and negative controls

The rule fixtures. Negative controls: an unsafe reuse that a later amendment "repairs" must still count in U;
a register row holding the target 1/5 in place of the measured s is rejected.

## Considerations

- The asymmetry is deliberate: one unsafe reuse outweighs any saving. The saving threshold exists so that a
  safe but pointless mechanism does not stay in the product as a liability.
- The ceiling was stated first: reuse after a dynamics-affecting edit is at most about a tenth of compute, so
  even a kept grade 3 is an evidence-hygiene feature.
