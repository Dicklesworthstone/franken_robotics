## Background

Lineage queries are how an agent keeps its bearings across dozens of edits: what changed, which edit introduced
a value, which edit broke a task, and how to combine work with another agent. The queries are user-visible
verbs, so they get one end-to-end script that drives the real binary: `design.diff` and `design.blame` (first
studio milestone) and `design.bisect` with lineage merge (fourth). The script has an M1 section that runs alone
at the first milestone and an M4 section added when bisect lands; this bead is recorded at the milestone that
completes it.

## Scope

In: the script, fixtures, assertions, log, self-test. Out: the mechanisms (BD-113, BD-343); the archive's own
merge test (the archive bead).

## Technical approach

**Path.** `scripts/e2e/atelier_lineage.sh [--section m1|m4|all]`; plain shell over `frob`; sources the shared
helper of STD-E2E; idempotent in a scratch namespace; seed from `FROB_E2E_SEED` (default 17).

**M1 section.**
1. `frob design new` from the `quad-mammal` template; three `frob design edit` calls: thigh length 0.21 → 0.24
   m (`set-param`), knee ratio 1.55 → 1.8 (`regear`), shank material aluminium → carbon laminate
   (`set-material`). Record the four `DesignId`s and assert each edit's envelope carries a diff, a symmetry
   effect and an invalidation set.
2. Stale parent: repeat the second edit against the root as expected parent; assert exit 7 and code 112 with
   the current head returned.
3. `frob design diff <root> <head> --json`: assert three edits; apply them to a fresh copy of the root with
   `frob design patch`; assert the resulting `DesignId` equals the head's.
4. `frob design blame <head> <path-of-knee-ratio> --json`: assert the second edit, values 1.55 and 1.8.
   `blame` on the thigh length: the first edit. On a field never edited: `since-root`. On `mass.total`: the
   third edit.
5. A rename edit, then `blame mass.total` again: still the third edit.
6. Branch: from the second version apply a different third edit; `frob design diff <branch-a> <branch-b>`:
   assert the emitted edits reproduce branch b.

**M4 section.**
7. Build a 12-edit lineage with one planted breaking edit (a regear that takes the knee below the step-up
   torque at edit 7) and eleven neutral edits; run `frob design bisect --good v0 --bad v12 --predicate succeeds
   --task <step-up> --level 0.05 --json` on `batch-cpu`. Assert: the returned pair is (v6, v7); label
   `a-change`; four probes, each at level 0.05/4; the error statement; `provisional` on the probes.
8. Require `first-change` without scan or declaration: assert exit 3, code 550. With `--scan-prefix`: assert
   `first-change` at edit 7 and `prefix: scanned`. With `--assume-monotone`: assert the recorded assumption.
9. Non-monotone lineage built from scripted outcomes (pass, fail, pass, pass, pass, fail) through the
   conformance harness: assert `a-change` at the last edit; with the scan, `first-change` at the first edit.
10. Schedule fuzz on step 7 (`FROB_SCHEDULE_FUZZ=1`): assert the identical bracket and probe e-values.
11. Merge: two agents' lineages (two scratch namespaces with overlapping and distinct edits) merged in both
    orders through the conformance harness (`frob conformance run --check lineage-merge --json`; the merge is
    a library operation and the plan registers no verb for it): assert identical bytes and digests, and that
    merging a lineage with itself changes nothing.
12. Gate: `frob conformance run --gate GATE-ATEL-04 --row bisect --json` (100 planted lineages, 20
    non-monotone): assert at least 95 found and no wrong `first-change`.

**Log.** NDJSON at `target/e2e-logs/atelier_lineage/<utc-timestamp>.ndjson` with a transcript. Every line has
`ts`, `script`, `bead`, `step`, `event`, the exact command line, exit code, wall time, the envelope's
`evidence` block (claim, class, tier, determinism, identities, seed), measured values with thresholds (found of
100 against 95; probe levels; pairs per probe; episodes total), digests where state is compared (the patched
`DesignId` against the head; both merge orders), and on failure the first differing value and the artifact
paths to reproduce. A `summary` line gives assertions passed and failed and the gates touched.

## Acceptance criteria

- [ ] The M1 section passes at the first studio milestone and the whole script at the fourth; it exits
      non-zero under each planted regression of its self-test.
- [ ] Step 3 proves the diff round trip on the real binary; step 4 is the seed condition of the lineage bead.
- [ ] Step 12's measured counts equal the bisect row written to the gate register.
- [ ] Logs of two runs with one seed differ only in timestamps, wall times and costs.

## Test plan

### Unit tests

`scripts/e2e/tests/atelier_lineage_selftest.sh`, one planted regression each: (a) blame returns the most recent
edit regardless of field (step 4); (b) diff emits unverified edits (step 3 or 6); (c) bisect labels its result
`first-change` by default (step 8 or 9); (d) probes at level α instead of α/⌈log₂ L⌉ (step 7's level
assertion); (e) merge keeps the first arrival on equal fitness (step 11).

### End-to-end script and logging

This bead is the script. Runtime target: M1 section under 30 s; M4 section under 15 minutes on `batch-cpu`
(TARGET), dominated by the bisect probes of step 7.

### Known answers and negative controls

The three-edit lineage (hand-specified), KA-702 (the six-version fixture), the planted edit at position 7.
Negative controls: the stale parent, the unqualified `first-change` request, CX-313 through step 9, and the
self-test regressions. Determinism lanes: twice on one machine; across worker counts; under schedule fuzz.

## Considerations

- The bisect scenario of the fourth milestone's demonstration uses a wheel-leg hybrid on stairs; the script's
  quadruped step-up stand-in is replaced when that archetype and task exist, and the log says which ran.
- Step 7 needs a real change large enough to decide within budget; the planted regear is sized so that the
  success rate falls from above 0.9 to below 0.2 (checked by the script before it bisects, so an inconclusive
  search is reported as a fixture problem, not a pass).
