## Background

How hard the contact and constraint solver works in each step (how many iterations, to what tolerance, with how
many substeps) is a trade between two losses: an under-converged result that passes as evidence, and iterations
wasted on worlds that had already converged. The studio treats that trade as one of its eleven decision cores,
DC-08, "which solver effort profile a run uses": a recurring decision compiled ahead of time into a small
versioned table with a loss model, obligations, a deterministic fallback and a budgeted mode. Its owner is the
dynamics crate `frob-dyn`, its timescale is the ledger refresh, and its tier is Frontier.

The decision core is specified in three places, and until this bead nothing carried the third. The record and
the compiled guard table of DC-08 are a registry bead (N28a-28). The conformance tests of its gate row are a
test bead (N28c-11). This bead is the mechanism in `frob-dyn` that both of them assume: the declared effort
profiles themselves, each with its own identity; the place where a run asks the table which profile to use; the
rule that re-runs an unconverged world one profile up; and the rule for a profile that does not fit the
throughput budget.

Design reasons, with the rejected alternatives (kept so the question is not reopened without new evidence):
- *A profile is an identity, not a tuning knob.* Evidence and calibration are never pooled across model
  identities: a change of model, kernel version, effort profile or battery version resets the affected ledger
  rows (INV-ATEL-05). A result therefore names the profile it ran under, and two profiles never share a ledger
  row, a memo key or a paired statistic.
- *The table decides, and it reads no clock.* Every decision is a pure function of its table version, the
  ledger state at a pinned frontier, and addresses (INV-ATEL-06). Rejected: feedback control of solver effort
  by a PID or model-predictive loop, because wall-clock feedback into iteration counts makes results depend on
  load and breaks replay; a guard table with hysteresis passes where a feedback loop does not. Rejected:
  Lyapunov and bifurcation analysis of solver effort, because the residual monitor already covers it.
- *The profile does not move to save time.* If the chosen profile misses the throughput budget, the run
  shrinks its world count or is refused; it never drops to a cheaper profile, because that would trade
  evidence quality for speed silently.

## Scope

In: the effort-profile record, its identity and its registry in `frob-dyn`; the default profile; the selector a
run calls at admission, with its fallback triggers and its behaviour in each adoption state; the per-world
convergence flag; the one-step-up re-run; the shrink-or-refuse rule; what a result and the telemetry record
about effort; the option on `sim.run` that pins a profile.

Out: the DC-08 record, its guard table generated from battery results, its calibration and its demonstration
manifest (N28a-28, which depends on this bead for the profiles it tabulates); the conformance tests of the gate
row, including the risk-control simulation that discharges PO-ATEL-10 (N28c-11, which depends on this bead);
the core contract, the table compiler and the decision evidence records with staged adoption (N28c-01,
N28c-02, N28c-03); the numerical parameter set and its digest (N16a-04); the solver and the batched step
(BD-159); the standard battery and its frozen envelopes (BD-212); the retry ladder of the referee step, which
changes numerical parameters inside one transactional step and is a different mechanism (BD-083).

## Technical approach

1. **The profile record (DESIGN).** In `crates/frob-dyn/src/effort.rs`:

   ```rust
   // DESIGN. An effort profile is a named override of the numerical plan's effort fields.
   pub struct EffortProfile {
       pub name: ProfileName,           // registered, lower case
       pub rank: u8,                    // 0 = cheapest; strictly increasing cost
       pub iteration_cap: u16,          // island-solver passes per step
       pub newton_iterations: u8,       // fixed count on lockstep tiers
       pub solver_tolerance: TypedTol,
       pub substeps: u8,                // solver substeps per physics step
   }
   impl EffortProfile { pub fn id(&self) -> EffortProfileId; } // BLAKE3 of the canonical record
   ```

   A profile changes only effort fields; it never changes the physics step h, a contact law or any physical
   parameter (the classification of physical against numerical parameters stays that of the numerical plan).
   The `EffortProfileId` is folded into the step-plan identity, so it is part of every episode identity, memo
   key and ledger row key that already carries the step plan.
2. **The registry.** `registries/effort_profiles.toml`, one table per tier class (referee, batched): an
   ordered list of profiles from cheapest to dearest and exactly one marked `default`. The default profile is
   the numerical plan the dynamics subsystem ships with (its default step and iteration budget); it is the
   fallback of DC-08. The intended set is three profiles per batched tier (DESIGN: one cheaper than the
   default, the default, one dearer); the count is data, and until the others are registered the registry
   holds the default alone. The registry digest is recorded on every DC-08 table as the identity the table
   was built for.
3. **The selector.** `effort::select(stratum, table, registry) -> Selection { profile, rule, trigger }`, called
   once at run admission with the table version pinned at the run's ledger frontier. It returns the cheapest
   profile the guard table holds for the stratum (the table's rule: the cheapest profile j with
   (n·R̂ⱼ + 1)/(n + 1) ≤ τ on the fidelity battery, n battery points, R̂ⱼ the mean monotonized loss), or the
   default profile with a named trigger:
   - `under-19-battery-points`: the stratum's row says the calibration floor is not met (at τ = 0.05 a profile
     with zero losses needs n ≥ 19, since (0 + 1)/(19 + 1) = 0.05);
   - `identity-change`: the registry digest, kernel versions or battery version differ from those the table
     was built for;
   - `no-row`: the stratum has no row;
   - a table that is missing, stale against its contract or not the registry version: the fallback acts and
     the run carries `FROB-REF-871` in `warnings` (repair: regenerate); a request that pins the table rule is
     refused with it.
   The selector's context type exposes no clock, no queue length and no device load. The profile is fixed for
   the whole run: no code path changes it after admission.
4. **Adoption states.** `shadow`: the default profile acts and the decision evidence record holds the profile
   the table would have chosen. `canary`: the table's profile acts for the canary share of runs by address
   hash. `default`: the table's profile acts and a standing sample still records the baseline. `fallback-only`:
   the default profile acts and nothing else is computed. Every admission writes one decision evidence record
   (table version, frontier, stratum, both profiles where applicable, trigger).
5. **Unconverged worlds.** A world is `unconverged` for a run when, at any step, its island solve ended at
   the profile's iteration cap with a residual above the profile's tolerance. The flag is a per-world status
   bit written by the step's residual check and carried to the result; it is distinct from the capacity
   reasons of a degraded world.
6. **One step up (the budgeted mode).** After the run's batch completes, every `unconverged` world is re-run
   once, from the same world address and seed, under the next dearer registered profile. The re-run is a new
   episode with its own identity (the profile differs); the result marks the world `stepped-up` and names
   both profiles. A world that is `unconverged` again is reported `unconverged`, excluded from summary
   statistics with the count and the reason stated, and not stepped up a second time: at most one step up per
   world per run. A run already at the dearest profile reports its unconverged worlds without re-running.
   DESIGN, for paired studies: a pair whose two arms would end under different profiles is not a pair; the
   address is re-run under the dearer profile in both arms, or the pair is dropped and counted in the
   comparison's accounting of dropped pairs.
7. **A profile that does not fit.** Before allocation the run's cost under the selected profile is estimated
   with the cost model of `sim.estimate`. If it exceeds the throughput budget, the run shrinks its world count
   to the largest count that fits and records `worlds_requested` and `worlds_run`, or, when the caller
   forbids shrinking, is refused before allocation by the estimate's budget refusal. The profile identity is
   unchanged in both cases.
8. **What is recorded.** On the result: `effort { profile, profile_id, rule: table | default | pinned,
   trigger, stepped_up: n, unconverged: n }`. In telemetry, the solver channel carries the effort profile
   beside iterations and residuals. In the ledger: the decision evidence record of step 4; the re-run episodes
   with their own identities.
9. **Surface.** `frob sim run … --effort <name> --key <k>` pins a registered profile (rule `pinned`; an
   unregistered name is the schema refusal FROB-REF-802); without the option the run uses the selection of
   step 3 under the adoption state of step 4. The option is `sim.run`'s registered `--effort` (VERBS-sim).
10. **Class.** The selection is D0 data. Episode results under a profile have the determinism class of their
    tier and backend; the profile never lowers it.

## Acceptance criteria

- [ ] `EffortProfileId` changes when any effort field changes and is part of the step-plan identity: two runs
      that differ only in profile have different episode identities and never share a memo hit or a ledger row.
- [ ] The registry loads with exactly one default per tier class and strictly increasing rank; a registry
      with two defaults or a duplicate rank fails to load.
- [ ] Selection floor: a stratum with n = 19 battery points and zero losses selects that profile at τ = 0.05;
      with n = 18 the default profile is selected with trigger `under-19-battery-points`.
- [ ] Each trigger (`under-19-battery-points`, `identity-change`, `no-row`, stale table) yields the default
      profile and an evidence record naming the trigger.
- [ ] In `shadow` the applied profile is the default in 100% of admissions while the table's choice is
      recorded; in `fallback-only` the default acts and no table lookup is made.
- [ ] The profile never changes inside a run and the selector reads no clock: the same run under an idle and
      under a saturated queue has the identical profile identity and identical per-world digests.
- [ ] One step up: a planted world that cannot converge under the cheapest profile and converges under the
      next is re-run once and marked `stepped-up`; a planted world that never converges is re-run once and
      reported `unconverged`, not stepped up twice; both counts appear on the result.
- [ ] A run whose selected profile exceeds the throughput budget shrinks its world count (both counts
      recorded) or is refused before allocation; in neither case does the profile identity change.
- [ ] The crate's `CONTRACT.md` states the profile record, the selector's purity, the step-up rule and the
      refusals; the mechanism is reachable through `frob sim run --json`; cancelling a run during the step-up
      pass publishes no partial result.
- [ ] What the DC-08 row of GATE-ATEL-13 is measured with is reachable from the CLI: each fallback trigger can
      be forced through a scratch registry or a scratch table and writes its evidence record with the trigger;
      every admission in `shadow` writes both profiles. The row itself is measured and recorded by N28c-11,
      which depends on this bead.

## Test plan

### Unit tests

`cargo test -p frob-dyn --test effort` (the real solver on small fixtures; fixtures labelled `synthetic`):
- `profile_id_covers_every_field`: changing each field in turn changes the identifier.
- `profile_in_step_plan_identity`: two profiles give two step-plan identities and two memo keys.
- `registry_one_default_strict_ranks`; `registry_rejects_two_defaults`.
- `select_cheapest_passing`: a table fixture with risk bounds (0.21, 0.05, 0.01) at τ = 0.05 selects the
  second profile.
- `select_floor_19`: n = 19, zero losses → admitted; n = 18 → default with its trigger.
- `select_identity_change_falls_back`; `select_no_row_falls_back`; `stale_table_warns_871`.
- `selector_context_has_no_clock` (compile-time: the context type has no time or load accessor).
- `shadow_applies_default_records_table`; `fallback_only_skips_lookup`.
- `unconverged_flag_from_residual`: a stiff two-body contact fixture with the iteration cap set to 1.
- `one_step_up_then_stop`: the never-converging fixture is re-run exactly once.
- `dearest_profile_reports_without_rerun`.
- `budget_shrinks_world_count`; `budget_refuses_when_shrink_forbidden`; `profile_unchanged_after_shrink`.
- Property: for random tables and strata the selection is the same under permuted admission order.

### End-to-end script and logging

`scripts/e2e/effort_profiles.sh` sources the shared helper of STD-E2E and drives the real binary on
`batch-cpu`; every `frob sim run` carries `--key`, a distinct key for each run that is compared with another
(the idle and saturated runs in particular, or the second would return the first one's stored receipt):
`frob sim run` on the reference quadruped with `--effort` set to each profile of a scratch
registry holding three (cheaper, default, dearer; three episode identities asserted, since the shipped registry
may hold the default alone, see OPEN below), and with an unregistered name (schema refusal, exit 3); the same run without the option under a scratch registry in each adoption state
(`shadow`, `canary`, `default`, `fallback-only`), with the applied profile and the evidence record read back
through `frob evidence trace`; the run repeated while a second job saturates the queue (profile identity and
digests compared); the planted non-converging worlds (step-up counts asserted); a run with a throughput budget
below the selected profile's estimate (shrunk world count, then the refusal with shrinking forbidden). Log
`target/e2e-logs/effort_profiles/<utc-timestamp>.ndjson` and a transcript: `ts`, `script`, `bead`, `step`,
`event`, the exact command line, exit code, wall time, the envelope's `evidence` block, the applied profile
and its identifier, the rule and trigger, worlds requested and run, stepped-up and unconverged counts against
their expected values, digests of the idle and saturated runs, and on failure the first differing value with
the artifact paths. A final `summary` line gives assertions passed and failed and the gate touched. The gate
row itself is measured by phase `dc-08` of `scripts/e2e/decision_cores_m4.sh` (N28c-11).

### Known answers and negative controls

- Known answers: the floor (0 + 1)/(19 + 1) = 0.05 and its failure at n = 18; the selection on the three-bound
  fixture; step-up counts of the two planted worlds (1 and 1, the second still unconverged).
- Negative controls, each a planted defect the tests must catch: a selector that reads queue length (the idle
  and saturated runs then differ in profile); a world stepped up twice; a profile switched after admission; two
  profiles written to one ledger row (the pooling check of INV-ATEL-05 fails it); a run that drops to a cheaper
  profile when over budget.
- Metamorphic: permuting worlds in the batch changes no world's profile, flag or digest.
- Determinism lanes: twice on one machine; worker counts 1 and 8; debug and release; `batch-cpu` and a device
  backend, each inside its class.

## Considerations

- DC-08 is Frontier. Its pilot is its shadow run: until the gate row of DC-08 has passed and its adoption has
  advanced, the default profile acts everywhere and this bead only records what the table would have chosen.
  For a Frontier core the fallback is also its kill fallback: if the core's calibration fails its gate after
  one repair cycle its status becomes `fallback-only` and the default profile acts for good; the profiles
  remain available by pinning.
- The risk bound holds for worlds exchangeable with the battery. A campaign that drifts to designs the battery
  does not resemble is outside the obligation; the identity-change trigger covers a changed battery, not a
  changed population, and the result says which battery version the selection rested on.
- Re-running stepped-up worlds costs at most one extra batch of the unconverged share; a stratum in which that
  share is large is evidence that its table row is wrong and is reported with the count.
- Interaction with other cores: the table changes only at a ledger refresh and never inside a run, and every
  faster decision (which design advances, which experiment is bought, which job runs) treats the profile as a
  constant; the composition tests of the decision cores check that no faster loop writes what this one reads.
- The loss constants and τ are recorded in the DC-08 record; changing either is a new decision-policy version
  and resets nothing in this bead.
- OPEN: the names and the number of registered profiles beyond the default (owner: the dynamics lead).
  Fail-closed default: only the default profile is registered, in which case every selection is the default
  and the core has nothing to decide.
