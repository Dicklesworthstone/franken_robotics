## Background

The studio's static analyses (crate `frob-analyze`) answer questions about a design without simulating it:
mass roll-up (A-02), workspace and reach (A-05), static stability (A-08), co-design closure (A-10), actuator
envelope (A-11), self-collision and clearance (A-13), and the four bound analyses: energy-budget feasibility
(A-20), deadline and latency closure (A-21), sampled-loop stability (A-22) and the shared-bus schedule
(A-23). As drafted, each takes one design and returns numbers in `f64`.

The mission subsystem (Augur) needs the same analyses to answer questions about *sets* of designs:

- **Region certificates** decide one constraint over a box of the parameters it reads, by enclosing the
  constraint with outward-rounded interval, affine or Taylor arithmetic and bisecting. The foundation
  library provides the arithmetic (`fs-ivl`: intervals, affine forms, Taylor models; FACT, to be re-read at
  the pinned commit). The plan lists what the suite lacks: a paving driver, contractors, **and interval
  forms of the robot static analyses**.
- **The constraint-to-parameter graph** is obtained by running an analysis with every free parameter
  replaced by a value that records the expression it takes part in.
- **Discrete families with typed holes** need, for a *partial* design, an optimistic capability and a
  conservative resource figure over every completion: an analysis evaluated over the range of each hole.
- Obligation **PO-AUGUR-01**: each lowering from a design family and a mission to primitive equations is
  correct, discharged by a second, independently written lowering for every supported template, compared
  exactly, and one deliberately invalid fixture per lowering that the checker must reject.

All four assume that an analysis can run on something other than a number. No analysis bead says so, and an
analysis written against `f64` with ordinary `if` statements cannot. Hand-writing an interval copy of each
analysis is the rejected alternative: two implementations drift, and the copy is not the independent second
lowering PO-AUGUR-01 asks for. This bead states the rule and makes the ten analyses obey it.

Terms. A *margin* is a scalar g written so that g ≤ 0 means the requirement holds. An *enclosure* of g over
a box B is an interval that contains g(x) for every x in B. An *affine form* is x₀ + Σ xᵢ·εᵢ + r·[−1, 1] with
noise symbols εᵢ ∈ [−1, 1]; it keeps linear dependencies that plain intervals lose. A *proposer* is
untrusted numerical code whose output is checked; a *checker* evaluates only straight-line arithmetic.
Tier: Frontier, because every consumer is (region evidence, checked cuts); the property delivered is exact.

DESIGN decisions.
1. **Margin kernels.** Each analysis exposes its margins as straight-line functions, generic over a scalar
   trait. Solvers and iterations stay outside the kernel as proposers, and the kernel verifies what they
   return. Reason: a linear program or a fixed-point loop has no interval form worth trusting, while the
   check of its certificate is a handful of sums and products.
2. **Three-valued sign.** A kernel never branches on a comparison of scalars. It uses `min`, `max`, `abs`
   and a sign test that may answer `unknown`. Reason: on an interval that straddles zero both branches are
   live; a recording value has no sign at all.
3. **`frob-analyze` links no interval library.** The trait lives beside the analyses; the interval and
   affine instances are supplied by the calling crate over the airlock types. Reason: the layering rule
   that only admitted groups of the foundation are reached, and only through the airlock.

## Scope

In: the scalar trait and its laws; the `f64` and exact-rational instances; margin kernels for A-02, A-05,
A-08, A-10, A-11, A-13 and A-20 to A-23; the bound-side reading of an enclosure; the lowering registry with a
second route and an invalid fixture per kernel not already compared elsewhere; the enclosure battery.

Out: the recording value, the constraint graph and the second-route comparison for mass, reach, joint torque
and self-clearance on template legs (N25b-08); the paving driver and contractors (N25b-09); typed holes and
checked cuts (N25b-13); the certificates and their checkers (`frob-cert` beads); admission of `fs-ivl`
(BD-127); the analyses' numerical content, which this bead does not change.

## Technical approach

Layout (DESIGN): `crates/frob-analyze/src/scalar.rs`, `crates/frob-analyze/src/kernels/{mass.rs, reach.rs,
stance.rs, closure.rs, envelope.rs, clearance.rs, energy.rs, deadline.rs, loop_stability.rs, bus.rs}`;
`registries/lowerings.toml`; tests in `crates/frob-conformance/tests/analysis_scalar/`.

```rust
// DESIGN sketch: intent, not signatures.
pub enum Tri { Neg, Zero, Pos, Unknown }
pub trait AScalar: Clone + Add<Output = Self> + Sub<Output = Self> + Mul<Output = Self> + Neg<Output = Self> {
    fn from_ratio(r: &Ratio) -> Self;          // every constant and unit factor enters as an exact rational
    fn div(self, d: Self) -> Result<Self, Undecided>;   // refuses when the divisor's sign is Unknown or Zero
    fn sqrt(self) -> Result<Self, Undecided>;           // refuses when the argument may be negative
    fn powi(self, n: u32) -> Self;  fn abs(self) -> Self;
    fn min(self, o: Self) -> Self;  fn max(self, o: Self) -> Self;
    fn sign(&self) -> Tri;
}
pub enum MarginKind { Requirement, Witness, Dual }                      // which verdicts a margin may give
pub struct Margin<S> { g: S, kind: MarginKind, requirement: ReqRef, reads: FieldSet }  // feasible ⇔ g ≤ 0
pub enum BoxVerdict { HoldsOnBox, FailsOnBox, Undecided }               // from an enclosure [lo, hi] of g
```

1. **Laws of the trait** (property-tested per instance): ring identities where the instance is exact;
   *inclusion isotonicity* for set-valued instances (if x ⊆ X then f(x) ⊆ f(X) for every operation); `sign`
   is `Unknown` whenever the set contains values of both signs; `from_ratio` is exact or outward-rounded.
2. **Instances.** `f64`: the production path; a kernel instantiated at `f64` must return the bits the
   analysis returned before this bead (golden values of the analysis known answers). `Ratio`: exact, used by
   known answers and by second-route comparison. Interval and affine: thin wrappers over the airlock types,
   written in the mission crate; this bead supplies the wrapper's conformance test, not the wrapper.
3. **Kernels** (each returns `Vec<Margin<S>>`; angles at declared postures are data, so no trigonometric
   function of a parameter occurs; a margin that would need one is declared `not-lowerable` with its reason):
   - *mass*: Σ mᵢ − budget; centre-of-mass coordinates as quotients; subtree inertia by parallel-axis sums.
   - *reach*: required distance minus the sum of link lengths, and the inner-radius form |l₁ − l₂| − d.
   - *stance* (A-08): the **check** of a dual vector y for the static equilibrium system A·f = w, 0 ≤ f ≤ c:
     the dual margin yᵀw − Σᵢ max(0, (Aᵀy)ᵢ)·cᵢ (positive means no f in [0, c] can give yᵀA·f = yᵀw, so every
     design in the box is excluded; Farkas), and the witness margin maxᵢ max(fᵢ − cᵢ, −fᵢ) for a proposed f
     whose equality A·f = w is checked exactly; under a load-sharing model that fixes the forces (equal
     passive springs) the same expression is a requirement margin; tip-over as d − h·tan θ with tan θ
     supplied as data. The solve
     that proposes y or f stays in `f64`. The margin names the load-sharing model it assumed.
   - *closure* (A-10): κ − 1 for the loop gain κ = n·c·g·L/ρ_τ, and m·(1 − κ) − m_f.
   - *envelope* (A-11): torque and speed against the card's envelope at each declared operating point, and
     the thermal steady state as a verified fixed point: given a proposed temperature T, the margin
     |T − F(T)| − tol together with the contraction bound of F on an interval around T.
   - *clearance* (A-13): the squared-distance margin of each allowed body pair at each declared posture
     (squares avoid the square root; capsule radii enter as (r₁ + r₂)²).
   - *energy* (A-20): mandatory work (potential rise plus unavoidable dissipation) minus stored, injected
     and approach kinetic energy. Approach kinetic energy is always a term.
   - *deadline* (A-21): arrival instant minus decision instant, per decision, in exact rational time.
   - *loop stability* (A-22): the Schur–Cohn (Jury) inequalities of the one-tick map's characteristic
     polynomial, with the hold modelled exactly; no eigenvalue is computed inside the kernel.
   - *bus* (A-23): the check of a proposed joint time-indexed schedule (every demand met by its deadline,
     bus capacity respected per tick) and of an infeasibility dual. Never a sum of peaks.
4. **Bound side.** For an enclosure [lo, hi] of g over a box: hi ≤ 0 gives `HoldsOnBox` (an *inner*
   statement: every design in the box is feasible for this margin); lo > 0 gives `FailsOnBox` (*outer*:
   every design is infeasible); otherwise `Undecided`. The margin's kind restricts this (DESIGN, because a
   checked proposal proves only one side): a `Requirement` margin may give either verdict; a `Witness`
   margin (a proposed solution checked: the stance allocation under independent forces, the thermal fixed
   point, a bus schedule) gives `HoldsOnBox` or `Undecided`, never `FailsOnBox`, since a poor proposal proves
   nothing about the box; a `Dual` margin (a proposed infeasibility certificate checked: the stance dual, the
   bus Farkas vector) gives `FailsOnBox` or `Undecided`, never `HoldsOnBox`. For a partial design the same evaluation over the
   ranges of its holes gives the optimistic capability (the favourable end) and the conservative resource
   figure (the unfavourable end). An `Undecided` from `div` or `sqrt` propagates; it is never replaced by a
   default.
5. **Lowering registry** (`registries/lowerings.toml`): one row per kernel: analysis, kernel, the templates
   it supports, the second route (the closed form produced by the symbolic derivation path, or a hand
   derivation on file), and the invalid fixture. The conformance test fails if a kernel has no second route
   or no fixture. Rows for mass, reach, joint torque (the torque margins of the envelope kernel) and
   clearance point at the comparison N25b-08 runs; this bead writes the second routes and fixtures of the
   other six, and of the envelope kernel's thermal fixed-point margin, which N25b-08 does not compare.
6. **Evidence and determinism.** A kernel at `f64` or `Ratio` is D0. An enclosure's class is that of the
   certificate that carries it; this bead issues no certificate.

## Acceptance criteria

- [ ] Each of the ten analyses calls its kernel at `f64`, and every known answer of those analyses is
      unchanged bit for bit (the golden table recorded before the change).
- [ ] Enclosure battery: for each kernel, 10⁴ seeded boxes and 100 rational points per box, the exact value
      lies in the interval enclosure and in the affine enclosure, with zero violations.
- [ ] No kernel contains a comparison of scalars outside `min`, `max`, `abs` and `sign` (a lint over the
      kernel modules).
- [ ] The affine instance returns a zero-width result for x − x and for (a + b) − a − b; the interval
      instance does not, and the test records both widths.
- [ ] `registries/lowerings.toml` has ten rows; each second route agrees with its kernel exactly at 10³
      seeded rational points per supported template; each invalid fixture is rejected.
- [ ] The stance kernel reproduces the typed result of A-08 on the executed stance cases at b = 1/4 m: under
      independent foot forces the dual check certifies that the least worst-foot load is 150 N (the ++ force
      ranges over [150, 160] N) and the witness margin accepts BD-100's midpoint witness (155, 135, 105, 5) N
      against the 160 N cap; under equal passive springs the forces are (175, 115, 85, 25) N, which exceed
      the cap.
- [ ] A kernel whose divisor's enclosure contains zero returns `Undecided`, and the box is left undecided.
- [ ] `CONTRACT.md` of `frob-analyze` states the kernel rule, the supported templates per kernel, and the
      `not-lowerable` margins with their reasons.

## Test plan

### Unit tests

`cargo test -p frob-analyze --test kernels` and `cargo test -p frob-conformance --test analysis_scalar`:

- `f64_path_bitwise_unchanged`: per analysis, the kernel's result equals the stored golden bits.
- `mass_box_inner`: m₁ ∈ [1.0, 1.2] kg, m₂ ∈ [0.5, 0.6] kg, budget 1.9 kg → g ∈ [−0.4, −0.1], `HoldsOnBox`.
- `reach_box_outer`: l₁, l₂ ∈ [0.20, 0.22] m, target 0.45 m → g ∈ [0.01, 0.05], `FailsOnBox`.
- `energy_three_values`: rise 12 mm, g = 9.81 m/s², budget 0.90 J plus 0.05 J approach kinetic energy: mass
  8 kg exactly → work 0.94176 J, margin −0.00824 J (holds); mass ∈ [7.5, 8.5] kg → work ∈ [0.8829,
  1.00062] J, `Undecided`; mass ∈ [8.1, 8.5] kg → `FailsOnBox`; with the kinetic term removed the 8 kg case
  flips to fail (the planted defect).
- `closure_gain`: κ at the card values of the mass-spiral card equals the closed form; κ ∈ box containing 1
  → `Undecided` from the division.
- `stance_dual_and_witness`: at b = 1/4 m and a 160 N cap, the witness margin of (155, 135, 105, 5) N is ≤ 0;
  with the cap lowered to 149 N the dual check returns `FailsOnBox` (no allocation keeps every foot under
  150 N); the passive-spring forces (175, 115, 85, 25) N give a positive requirement margin of 15 N
  (`FailsOnBox`); at the 160 N cap the dual margin of any y is ≤ 0 and gives `Undecided`, never `HoldsOnBox`,
  and the witness margin of the infeasible proposal (165, 125, 95, 15) N, 5 N over the cap, gives `Undecided`,
  never `FailsOnBox` (`margin_kind_restricts_verdict`).
- `thermal_fixed_point_verified`: a proposed temperature T within tol of F(T) and a contraction bound below 1
  on the interval around T give `HoldsOnBox`; a bound of 1 or more leaves the box `Undecided`.
- `jury_matches_spectral_radius`: on the drive-loop fixture the kernel calls the target-current feedforward
  loop unstable (spectral radius 1.4820) and the measured-current loop stable (0.9207), in `Ratio`.
- `bus_two_fingers`: one powered tick each, one finger per tick: no schedule with a one-tick deadline,
  exactly two with two ticks; the additive-peak rule rejects the two-tick design and is caught.
- `deadline_per_decision`: a packet arriving at tick 1 serves decisions at ticks 2 and 4; at tick 3 it
  serves only the second.
- `inclusion_isotonic` (property test per operation and instance); `sign_unknown_when_straddling`.
- `affine_cancels_dependency`; `sqrt_of_possibly_negative_is_undecided`.
- `lowering_registry`: `registries/lowerings.toml` loads with ten rows, none without a second route or an
  invalid fixture, and a second route whose source path is the kernel's own is rejected.
- `second_route_equal_at_1000_points` (one per registry row); `invalid_fixture_rejected` (one per row: for
  example the closure kernel with the gear ratio bound to its nominal before lowering; the energy kernel
  without approach energy; the bus kernel replaced by a sum of peaks).

### End-to-end script and logging

`scripts/e2e/analysis_scalar.sh --seed <s>`: (1) for each of the four first archetypes (BD-109), `frob
design new as-<archetype> --template <archetype> --key "$(e2e_key new-<archetype>)" --json` (N14a-21; a
template is instantiated, `design.check` takes a design), then `frob design check as-<archetype> --json`, and
compare every analysis value with the golden table (the `f64` path is untouched from the user's side); (2) the enclosure battery and the three box cases (mass, reach, energy) through cargo, since
`frob-conformance` has no binary (ADR-GAUNT-01, BD-025): `FROB_TEST_SEED=<s> cargo test -p frob-conformance
--test analysis_scalar` and `cargo test -p frob-analyze --test kernels`, asserting the enclosure counts (zero
violations) and the three verdicts from the tests' structured output; (3) the registry check, `cargo test -p
frob-conformance --test analysis_scalar -- lowering_registry` (it loads `registries/lowerings.toml` with the
harness's registry loader): ten rows, each with a second route and an invalid fixture; (4) `cargo test -p
frob-conformance --test analysis_scalar -- second_route_equal_at_1000_points invalid_fixture_rejected`,
asserting every second route equal and every invalid fixture rejected. NDJSON per STD-E2E to `target/e2e-logs/analysis_scalar/<utc-timestamp>.ndjson`
with a transcript: `ts`, `script`, `bead`, `step`, `event`, the exact command, exit code, wall time, the
evidence block, per kernel the boxes tried, points tested and violations (threshold 0), enclosure widths for
the two dependency cases, digests of the golden comparison, and on failure the first box and point that
escape with the kernel name and seed. The `summary` line gives assertions passed and failed; no gate is
recorded by this script.

### Known answers and negative controls

- Values used above come from the analyses' own shortcut table: 8 kg × 9.81 m/s² × 0.012 m = 0.94176 J
  against 0.90 J, removed by 0.05 J of approach kinetic energy; the stance forces; the two-finger bus; the
  spectral radii 1.4820 and 0.9207 (the instantaneous model gives 2.6917 for both and misses the stable
  case); the packet deadline case.
- Negative controls: an interval instance with round-to-nearest (the enclosure battery must report escapes);
  a kernel that branches on `g < 0` at `f64` and is then instantiated at intervals (caught by the lint and
  by the straddling test); the three invalid fixtures; a "second route" that calls the kernel itself (caught
  because the registry requires a different source path and the invalid fixture then passes both).
- Metamorphic relations: splitting a box and joining the two enclosures gives an enclosure contained in the
  unsplit one; scaling all lengths by a rational factor scales the reach margin by the same factor exactly.
- Determinism lanes: `f64` and `Ratio` results twice on one machine, debug and release, Linux and macOS.

## Considerations

- Cost to the analysis crate: every analysis is split into proposer and kernel. The split is also what the
  certificate checker needs, so the work is not duplicated later.
- If KILL-AUGUR-REGION fires, region certificates fall back to dual witnesses, monotone bounds and pointwise
  analyses; the stance, energy, deadline and bus kernels are still used by those fallbacks, and the interval
  instances go unused.
- Interval enclosures of long expressions widen (the dependency problem); the remedy is the affine instance
  and the split set of the paving driver, not a tolerance.
- A kernel for a template with a closed kinematic loop reads the closure equations; where the closure needs
  a root, the root is proposed in `f64` and verified by a kernel, and the coupled dimension grows.
- OPEN-AUGUR-3 (measured sparsity; default: region certificates refused above six parameters) is settled by
  the experiment that consumes this bead.
