## Background

Chronicle is the record of the studio: every run, episode, event, verdict and receipt, and the trace data behind
them. It is one crate, `frob-chronicle` (tier Solid). Every other subsystem writes through it and nothing is
reported to an agent that it cannot trace. This bead builds the ground everything else in Chronicle stands on:
the ledger's tables, the on-disk `.frun` format, the three telemetry levels that exist on the referee at the
first studio milestone, the nine streams, and the rules that say what kind of quantity a channel holds. The
seed done-condition is: round-trip tests pass, and a chunk with one changed byte fails its digest.

Decisions that govern this bead, with their reasons and the alternatives rejected:

- **ADR-CHRON-01: metadata in a ledger on FrankenSQLite, bulk data in content-addressed column files.** The
  ledger needs transactions and queries; traces need sequential writes and deduplication. FACT: this is the
  pattern of FrankenSim's `fs-ledger` (`frankensim/crates/fs-ledger`). Rejected: everything in the database
  (traces are too large and are written sequentially); everything in files (no transactions, so a crash can
  leave a run half-recorded).
- **ADR-CHRON-02: the logical chunk partition is fixed per run and independent of device sharding.** After a
  retry splits a shard, two different range keys could cover the same transition. With a fixed partition,
  identical work always has an identical key, so a duplicate is detectable and a conflict is provable.
- **ADR-CHRON-03: evidence aggregates are integers** (count, integer sum, minimum, maximum, bitwise or,
  histogram of integer counts). Integer operations are commutative and associative, so the result has the same
  bits under any scheduling. This bead therefore stores quantized integer columns wherever a channel feeds an
  evidence aggregate.
- **ADR-CHRON-05: BLAKE3 on the host, integer mixes in-kernel.** Host hashes here are BLAKE3 (`fs-blake3`).
- **ADR-CHRON-09: retention never removes evidence silently.** Dropped telemetry is marked with its interval
  and reason; a metric over missing samples is refused, not interpolated.

Terms. A *run* is one admitted job with a manifest. A *world address* is `(run_seed, world, episode)`. An
*episode* is one world's trajectory from reset to its terminal tick. A *control tick* is one period of the
controller. A *stream* groups related channels; a *chunk* is the fixed-length piece of one stream of one
episode of one world. A *channel* is one recorded quantity with a declared kind, unit and frame.

## Technical approach

**1. Storage layout (DESIGN).** One store directory per namespace: `ledger.db` (FrankenSQLite, opened through
the path admitted by BD-009) and `columns/<first two hex digits>/<blake3>.fcol` (content-addressed column
files, written once, never modified). FACT: the suite's foundation ledger names the fallback if the sibling
cannot be consumed: an append-only JSON-lines ledger with the same schema; the table definitions below are
therefore written as plain records with a primary key so both stores can hold them.

**2. Ledger tables (schema version 1).** One row is:

| Table | One row is | Key | Filled by |
|---|---|---|---|
| `run`, `job` | A run or job: manifest hash, identities, state, budgets, terminal receipt with counts | `run_id`; `job_id` | Tether |
| `episode` | (run, world, episode): outcome, T0 metrics, digests, failure class | `(run_id, world, episode)` | this crate |
| `chunk`, `frontier` | A published chunk; the contiguous committed frontier | `ChunkKey`; `(run, world, episode, stream)` | BD-091 |
| `event`, `snapshot` | A T1 event; a T3 snapshot with its content hash | `(run, world, episode, tick, seq)`; content hash | this crate; BD-203 |
| `fidelity`, `rank_agreement`, `tier_correction` | A stratum of one of the three ledgers of disagreement | stratum key | Kinesis, Atelier, Chronicle |
| `verdict`, `prediction`, `core_decision` | A verdict record (`frob.verdict/1`); a registered prediction; one decision of a decision core | content hash; id; `(policy, frontier, seq)` | Atelier |
| `memo_node` | A node of the memo graph with key, determinism class and recompute cost | memo key | memo beads |
| `claim`, `evidence`, `edge` | The artifact graph | `ClaimId`; `EvidenceId`; `(from, kind, to)` | BD-095 |
| `alpha_spend` | A pre-committed confirmation request and its error budget | `(campaign, index)` | Arena |
| `pin`, `tombstone` | A retention pin with its reason; a record of something deleted | object hash | BD-209 |

Every row carries the identities it concerns. Identities are content hashes (BLAKE3): `DesignId`, `ModelId`,
`SceneId`, `KernelId`, `PolicyId`, `EpisodeId`; an identity names bytes and carries no verdict. `RunId` is the
BLAKE3 of the canonical manifest core (identities, seed, tier, kernel versions, effort profile, chunk length,
channel schemas). A `schema_version` row and a migration table exist from the first commit; a reader refuses a
ledger whose version it does not know. Trace identifiers and wall-clock times are stored but never enter a
content hash.

**3. The chunk key, record and chain** (FACT from the plan's type sketch; fields are normative):

```rust
// DESIGN: intent, not signatures.
struct ChunkKey { run: RunId, world: u32, episode: u32, stream: StreamId, index: u32 }
struct ChunkRecord {
    key: ChunkKey,
    content: Blake3,     // hash of the column file bytes
    prev: Blake3,        // chain digest of chunk index − 1; all zero for index 0
    chain: Blake3,       // BLAKE3(prev ‖ content ‖ canonical bytes of key)
    state_digest: u128,  // digest of the world's state at the chunk's last tick
    lease_gen: u64,      // fencing token of the writer (used by BD-091)
    commit_seq: u64,     // assigned in the publishing transaction; a string on the wire
    gaps: Vec<Gap>,      // dropped intervals, each with a reason
}
```

Chunk `i` of episode `e` of world `w` on stream `s` covers control ticks `[i·L, (i+1)·L)`, cut short only by
the episode's terminal tick. `L` is fixed for the run at admission; OPEN-CHRON-2 default: 256 control ticks.
The key names no device, shard, batch slot or retry. Canonical bytes of the key: `run` (32 bytes), then
`world`, `episode`, `stream`, `index` as little-endian `u32`.

**4. The `.frun` format (`FMT-FRUN`, schema `frob.run/1`).** A run exports as a manifest in canonical JSON plus
column files. The manifest holds: the run identity; model, scene, task and policy identities; kernel versions,
tier, determinism class and effort profile; the chunk length; the channel schemas; the chunk index (key,
content hash, chain digest, tick range, gaps); the frontier per (world, episode, stream); every gap with its
reason; `origin` (`sim` by default); and the three no-authorization flags, each the literal `false`. Canonical
JSON: UTF-8, object keys sorted, no insignificant whitespace, no floating-point literals (rationals are reduced
integer pairs with a positive denominator); integers that can exceed 2⁵³ (ticks, sequence numbers, digests) are
strings. A column file (`.fcol`) has a header and a body:

- header: magic `FCOL`, format version `u16`, schema identifier, tick range `[t0, t1)`, row count, and per
  channel: name, kind, unit, frame, quantization (dtype, scale as a rational, offset) and byte offset;
- body: fixed-width little-endian columns, either quantized integers (`i16`, `i32`, `i64`, `u64`) or `f32`.

Column bytes are a pure function of the channel schema and the samples, so the same episode produces the same
`content` hash on every machine (determinism class D0 for the encoding). OPEN-CHRON-1 default: uncompressed
quantized columns, no third-party codec. A `.frun` is readable with no device and no daemon.

**5. Verification.** `frun::verify(path)` recomputes each column file's BLAKE3 and each chain digest from index
0 and returns the first failure as `{key, expected, observed, which: content | chain | manifest}`. The offline
auditor repeats the same check with the standard library only; the byte layout above is the contract between
the two and is written out in `CONTRACT.md` so that neither reads the other's code.

**6. Telemetry levels.**

| Level | Contents | Default scope |
|---|---|---|
| T0 | Per-episode metrics, energy-ledger totals, integer histograms and per-chunk minimum–maximum envelopes of declared channels, state digests at intervals | Every world, always |
| T1 | Events: contacts made and broken, limit and saturation episodes, faults, refusals | Every world |
| T2 | Traces at control rate: joint states, torques, contact wrenches, estimator state | A sample of worlds, and every failing world |

T3 (full-state snapshots) is named in the schema and implemented by BD-203. On the referee at this milestone
every world may be traced; the address-keyed sample is BD-207.

**7. Streams.** Nine `StreamId` values; a chunk belongs to exactly one: `kinematics` (base and joint state as
group elements and velocities), `contact` (feature pair, normal, gap, impulse, patch, stick or slip, solver
residual of the owning island), `energetics` (every energy-ledger term per port), `control` (controller
identity, provenance of each input sample, requested and applied action, saturation, fallback taken),
`sensing` (capture and delivery instants, validity mask, bias state, calibration identity), `solver` (mode,
iterations, residuals, step reductions, precision, contact capacity used, effort profile), `runtime`
(placement per stage, resident bytes, transfers, queue delay, shape bucket), `task` (goal events, termination
against truncation, hard violations, reward and requirement components), `provenance` (identities, versions,
lease generation, frontier).

**8. Channel declarations and kinds.** Every channel declares kind, unit (an `fs-qty` dimension), frame,
sampling (a rational period and phase, or `event`), quantization, permitted consumers, and a label `visible`
(the acting policy may read it) or `privileged`. Chronicle only records the label; isolation is enforced by
the sensing and learning crates and an audit reads the label. The kind fixes how a channel may be downsampled:

| Kind | Example | Correct downsampling | Wrong, and why |
|---|---|---|---|
| `state` | Joint angle, base pose | A sample, or a minimum–maximum envelope; orientation by a group-aware mean or a sample | A componentwise mean of quaternions leaves the group |
| `interval-mean` | Mean power over a tick | Duration-weighted mean | A sample drops energy |
| `impulse` | Contact impulse | Sum over the window | A mean or a sample changes momentum transfer |
| `event` | Contact made, limit hit | All events, or a count | Decimation deletes the event that explains the failure |
| `cumulative-counter` | Energy drawn, distance | Last value | A sum counts everything twice |

`downsample(channel, window)` dispatches on the declared kind and has no override; a caller that asks for a
reduction the kind does not permit gets a typed error at compile time where the kind is static and at run time
otherwise. At a jump (impact, reset map, mode switch) both the state before and the state after are recorded,
as two rows with the same tick and a `phase` of `pre` and `post`.

**9. Gaps and the missing-sample refusal.** Dropped telemetry is a `Gap { from_tick, to_tick, reason }` with
reason one of `level-not-enabled`, `ring-overflow`, `budget-stop`, `cancelled`, `device-lost`. Any metric
computed through this crate checks coverage first; if a required sample lies in a gap it refuses with
`FROB-REF-888` (a metric computed over missing samples; repairs, in order: re-run with the channel retained;
accept `unavailable`; exit code 3). It never estimates from neighbours.

**10. Layout.** `crates/frob-chronicle/src/{ledger/, frun/, column.rs, chunk.rs, stream.rs, channel.rs,
downsample.rs, gap.rs}`; `crates/frob-chronicle/CONTRACT.md` with the ten sections (purpose, inputs, outputs,
invariants, refusals, determinism class, evidence class of outputs, validity domain, oracles, known gaps).

## Acceptance criteria

- [ ] Seed done-condition: a run written to the ledger and exported as `.frun` reads back equal, field for
      field and byte for byte on re-export; a chunk file with one changed byte fails `verify` with its key and
      both hashes.
- [ ] A changed `prev` or a swapped pair of chunks fails the chain check at the first affected index.
- [ ] All tables of section 2 exist at schema version 1; an unknown version is refused on open.
- [ ] The same referee episode exported on two machines gives identical `content` hashes for every chunk.
- [ ] Every integer that can exceed 2⁵³ is a JSON string; the manifest carries the three no-authorization
      flags, all `false`, and a manifest with one missing or `true` is rejected by the reader.
- [ ] The five kinds downsample as the table says; the three wrong reductions (mean of impulses, sample of an
      interval mean, componentwise quaternion mean) are unrepresentable or refused.
- [ ] A metric over a gap returns `FROB-REF-888`; the same metric with full coverage returns a value.
- [ ] Jumps are stored as `pre` and `post` rows; a reader that drops one is caught by the row-count check.
- [ ] The `.frun` reader runs in a process with no device and no daemon.
- [ ] `CONTRACT.md` exists with ten sections and the byte layout; outputs carry identities, tier, determinism
      class and seed so that the envelope's evidence block can be filled by the verbs of BD-097.

## Test plan

### Unit tests

`cargo test -p frob-chronicle`:

- `frun_roundtrip_bytes`: a `synthetic` 3-world, 2-episode, 700-tick run (L = 256, so chunks of 256, 256, 188
  ticks) on four streams; export, import, re-export; manifests and all column files byte-equal.
- `chunk_one_byte_fails`: flip one bit at a random body offset of a random chunk (100 seeds); `verify` fails
  naming that chunk, `which = content`.
- `chain_detects_reorder`: swap chunks 1 and 2 of one stream; failure at index 1, `which = chain`.
- `chain_index0_prev_zero`: `prev` of index 0 is 32 zero bytes; any other value fails.
- `terminal_chunk_short`: an episode ending at tick 700 has a last chunk covering `[512, 700)`.
- `manifest_big_integers_are_strings`: tick 2⁵³ + 1 and a `u128` digest round-trip exactly.
- `manifest_flags_must_be_false`: a manifest with `execution_authorized: true`, and one with the flag absent,
  are both rejected.
- `kind_impulse_sum`: impulses (0.2, 0, 0.3, 0.1) N·s over a 4-tick window downsample to 0.6 N·s.
- `kind_interval_mean_weighted`: powers 10 W for 2 ms and 40 W for 1 ms give 20 W.
- `kind_counter_last`: (1, 3, 6) J gives 6 J; a sum (10 J) is not offered by the API.
- `kind_state_envelope`: (0.1, −0.4, 0.3) rad gives the envelope [−0.4, 0.3].
- `orientation_group_mean_stays_on_group`: the group-aware mean of two unit quaternions has unit norm; the
  componentwise mean of q and −q (the same rotation) is zero and is never produced.
- `jump_pre_post_rows`: an impact at tick 37 yields two rows at tick 37.
- `metric_over_gap_refused_888`; `ledger_unknown_schema_version_refused`; `encoding_deterministic` (property:
  permuting the order in which channels are appended to the writer does not change the bytes).

### End-to-end script and logging

`scripts/e2e/chronicle_frun_roundtrip.sh` sources the shared helper of STD-E2E and drives the real binary:
`frob sim run --tier referee --fixture g1 --telemetry T2 --seed 7 --json`; `frob run export <run> --out
$TMP/a.frun --json`; a second export to `b.frun` and a byte comparison; `frob-verify $TMP/a.frun`; then a copy
with one flipped byte and a second `frob-verify` that must exit non-zero; then a `telemetry.query` of a metric
on a channel that was not retained, expecting `FROB-REF-888` and exit 3. It writes
`target/e2e-logs/chronicle_frun_roundtrip/<utc>.ndjson` and a transcript: per line `ts`, `script`, `bead`,
`step`, `event`, the command, exit code, wall time, the envelope's evidence block, the chunk count, each
compared digest, and on failure the first differing chunk key with both hashes and the artifact paths. A final
`summary` line counts assertions. Logs contain no scene data.

### Known answers and negative controls

- KA-715: an impulse train summed over a window conserves momentum transfer (tolerance: exact in the quantized
  integers). Negative control (CX-322): the same train averaged loses it; the test asserts that the averaged
  value differs and that the API cannot be made to return it for an `impulse` channel.
- Negative controls for the done-condition: the one-byte tamper; the reordered chain; the flag set to true.
- Metamorphic: export → import → export is the identity on bytes; splitting a run's export across two writer
  processes gives the same files.
- Determinism lanes: twice on one machine; debug and release; macOS and Linux hosts. Class D0 for bytes.
- Invariants touched here and tested by BD-091: INV-CHRON-01 (a committed chunk key maps to one content hash)
  and INV-CHRON-02 (committed chunks are exactly indices 0 to the frontier).

## Considerations

- OPEN-CHRON-1 (owner: Chronicle lead; blocks nothing before M2): column compression. Default: none.
- OPEN-CHRON-2 (owner: Chronicle lead; blocks GATE-CHRON-04): chunk length and ring depth. Default: 256 ticks
  and 2 s; `L` is a manifest field so a later choice needs no format change.
- OPEN-CHRON-3 (owner: suite lead): identifier types imported from the suite kernel or defined locally.
  Default: defined locally in `frob-core`, same layout.
- If FrankenSQLite cannot be consumed, the JSON-lines fallback keeps the same records; queries become scans.
- Performance target read later by GATE-CHRON-13: T0 and T1 on every world at most 3% of step time, T2 on a 1%
  sample at most 2% more. Quantization choices here set that cost; they are recorded per channel.
- Privacy: telemetry derived from a private scene inherits the scene's privacy class through export.
- A second parser for `.frun` anywhere in the workspace is a contract violation the registry lint catches.
