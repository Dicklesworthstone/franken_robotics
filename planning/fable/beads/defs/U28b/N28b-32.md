## Background

An edit is an event that puts evidence in question. The studio does not ask "is the cache still warm"; it
asks which verdicts survive, which are revoked, and what the cheapest set of reruns is. `frob result
revalidate <verdict or claim> --after-edit <edit>` answers with the surviving obligations and the licence for
each, the invalidated regions, and the required reruns with their cost. The mission cluster's revalidation
verb is the same engine applied to a mission answer. Decision ADR-ATEL-05 states the principle: a hash
identifies; only an implication licenses skipping a recheck. A content hash says that an input or a result is
the same object and says nothing about whether a verdict survives a different input; reuse of a verdict needs
a dependency argument or an implication argument, recorded and independently checkable.

This bead is the verb's surface: its registry entry, schemas, envelope and refusals, and the rules of what an
answer must contain so that a reused verdict can never look like a recomputed one. The engines behind it
arrive in steps (mission cells at the first milestone; every verdict kind with the rule registry at the
third; implication rules for non-mission verdicts at the fourth), and the surface is fixed first so that
none of those steps changes what an agent sees. Tier: Solid for the surface and for grades 1 and 2; grade 3
is Frontier and sits behind a flag.

Every stored verdict has this shape (`frob.verdict/1`):

```
verdict record
  claim        claim_id · claim type · statement · quantifier prefix
  kind         inclusion (a witness exists) | exclusion (no witness can exist) | comparison | optimum | estimate
  assumptions  disturbance set · world set · hypothesis support · actuator limits · requirement ·
               policy class · information contract (channels and their instants) · catalog and prices ·
               model identity · tier · kernel versions · effort profile
  obligations  feasibility obligations   (the witness is valid)
               optimality obligations    (every cheaper rival is excluded; the cost bound; catalog membership)
               each with: evidence_id · dependency support (the exact fields it read) · checker
  provenance   evidence closure · decision-policy id · trace ids
```

and reuse comes in four grades:

| Grade | Licence to skip the recheck | What is recorded | Tier |
|---|---|---|---|
| 1 Identity | The obligation's full key is unchanged | The memo hit | Solid |
| 2 Dependency | Every changed field lies outside the obligation's recorded dependency support | A mask over the obligations, checkable against the supports without rerunning anything | Solid |
| 3 Implication | A changed field lies inside the support, and a polarity rule of the assumption lattice preserves the obligation | The rule's name, the old and new assumption sets, the order relation between them and its check | Frontier |
| 4 None | — | The rerun and its cost estimate | — |

## Technical approach

**1. Registry entry (DESIGN, in the registry's own format).**

```toml
[[verb]]
name = "result.revalidate"
cluster = "result"
kind = "run"
tier = "S"
capabilities = ["result:read", "result:revalidate"]
input_schema = "frob.result.revalidate.in/1"
output_schema = "frob.revalidate.out/1"
refusals = ["FROB-REF-870", "FROB-REF-854", "FROB-REF-869"]
idempotent = true
cost_model = "ledger reads only for grades 1 and 2; a rule check per touched obligation for grade 3; reruns are separate jobs"
first_milestone = "M1"
task_clusters = ["revalidate", "missions"]
examples = ["frob result revalidate v:7d21 --after-edit e:03aa --json"]
```

The verb table of the plan lists the verb at the fourth milestone, while the gate register gives
GATE-ATEL-11 a first row at the first milestone ("dependency grades on mission cells"). The entry therefore
lands at M1 in reduced form (targets: mission cells; grades 1 and 2) and is extended without a schema change
(OPEN-ATEL-4 default: two verbs, `result.revalidate` and `mission.revalidate`, over one engine).

**2. Input (`frob.result.revalidate.in/1`).** `target`: a `VerdictId`, a `ClaimId`, or a mission answer;
`change`: one of `after_edit` (an edit or patch identifier in a lineage), `between` (two versions of any
identified object: design, card, scene, task, clock, mission), or `amendment` (a set of field changes);
`grades`: the highest grade the caller allows (default 2; 3 only with the flag
`frontier-revalidate-implication` enabled for the session); `estimate_only`; a budget and an idempotency
key.

**3. Output (`frob.revalidate.out/1`).**

```json
{ "target": "v:7d21…", "frontier": "184467",
  "change": [ { "component": "free space of the scene", "direction": "enlarged", "fields": ["scene.doorway_w"] } ],
  "obligations": [
    { "id": 0, "role": "feasibility", "grade": 2, "status": "preserved",
      "licence": { "kind": "dependency", "mask": "ev:19c4…" } },
    { "id": 3, "role": "optimality", "grade": 4, "status": "revoked",
      "licence": { "kind": "none" }, "touched_by": "scene.doorway_w" } ],
  "verdict_after": { "feasible": "preserved", "optimal": "revoked, recheck" },
  "invalidated_regions": [],
  "reruns": [ { "what": "exclude every cheaper rival", "cost": { "cpu_core_s": [2, 9] },
                "command": "frob mission synthesize … --idempotency-key …" } ],
  "counts": { "preserved": 3, "revoked": 1, "by_grade": { "1": 0, "2": 3, "3": 0, "4": 1 } } }
```

Rules on the answer:
- every obligation of the target appears exactly once, with a grade and a licence (INV-ATEL-07: every reused
  verdict carries a grade and a licence; a grade-3 licence names a rule in the registry);
- feasibility and optimality are reported separately, never merged into one word. Standing example: a cost-9
  cart may be the certified minimum while a cost-5 relay is excluded by a doorway; widen the doorway and the
  cart and its trace remain valid, so the verdict splits into `feasible: preserved` and `optimal: revoked,
  recheck`;
- a `preserved` status is never produced by default: with no licence the status is `revoked` (grade 4) and
  the rerun is listed;
- for a mission answer, `invalidated_regions` lists the cells whose verdicts are withdrawn, and for a missed
  dependency found later the withdrawal names the two worlds or the new mode that invalidates the verdict.

**4. The mask.** A grade-2 answer stores a mask as an evidence item: per obligation, the changed fields, the
recorded support and the statement "disjoint". It is checkable against the supports without running any
solver or simulation, by the offline auditor as well as by the engine. A grade-3 licence stores the rule's
name, the old and new assumption sets, the order relation and its check.

**5. Refusals at the surface.**
- `FROB-REF-870`: reuse of a verdict with no licence, or under a rule the registry does not know; repair:
  recheck; exit 3. Raised when a caller (or an importing tool) presents a verdict as still valid after a
  change with no accompanying licence, and when a licence names an unknown rule. The checker rejects an
  unknown rule name or a changed quantifier prefix even when every hash is consistent.
- `FROB-REF-854` (owner: the mission chapter): reuse outside a screen's or classifier's eligibility; repair:
  revalidate.
- `FROB-REF-869`: the target's evidence closure is dangling or tombstoned; repair: re-run the evidence.

**6. Exit codes and evidence.** 0: every obligation preserved. 2: at least one revoked or to be rechecked
(a completed answer with findings). 3: refusal. 8: accepted and still running (a grade-3 check or an
`estimate` that needs the cost model may take longer than the wait). The envelope's evidence block for a
revalidated verdict keeps the original claim's class only for preserved obligations and adds
`revalidated: { grade_max, licence_ids }`; a consumer can therefore always tell a carried-forward verdict from
a fresh one. Determinism: D0 (a pure function of the two states and the stored records at a pinned
frontier). Unsafe reuse is a false accept, even if a later change restores feasibility; the surface never
"heals" a past unsafe reuse by silence.

**7. Layout.** Verb executor in `crates/frob-verbs/src/verbs/result_revalidate.rs`, calling the engine trait
`Revalidate` (implemented first for mission cells); schemas under `registries/schemas/`.

## Acceptance criteria

- [ ] The registry entry exists; `frob result revalidate --help` and the MCP tool `result_revalidate` are
      generated from it; schemas validate the examples.
- [ ] At M1, on a mission cell: an edit outside every support returns all obligations `preserved` at grade 2
      with a checkable mask; an edit inside a support returns grade 4 with the rerun listed (the M1 row of
      GATE-ATEL-11, measured with the mission slice's fixtures).
- [ ] Every obligation appears once with grade and licence; an answer missing either is rejected by the
      output schema.
- [ ] The doorway fixture returns `feasible: preserved` and `optimal: revoked, recheck`.
- [ ] A verdict presented as valid after a change with no licence, and a licence naming an unknown rule, both
      return `FROB-REF-870`; a changed quantifier prefix is rejected even with consistent hashes.
- [ ] Grade 3 is unavailable without the flag; with the flag off, an obligation that only a rule could
      preserve is grade 4.
- [ ] The mask re-checks offline (auditor) with no solver or simulator present.
- [ ] Exit codes 0, 2, 3 and 8 are produced on their fixtures; replay with the same idempotency key returns
      the stored answer.

## Test plan

### Unit tests

`cargo test -p frob-verbs --test result_revalidate_surface`:

- `registry_entry_roundtrip`; `schema_rejects_missing_licence`; `schema_rejects_missing_grade`.
- `every_obligation_listed_once` (property over random verdict records).
- `default_is_revoked`: an engine that returns no licence for an obligation yields `revoked`, grade 4.
- `split_verdict_doorway`: cost-9 cart, cost-5 relay, doorway widened.
- `no_licence_refused_870`; `unknown_rule_refused_870`; `changed_prefix_rejected`.
- `grade3_needs_flag`.
- `mask_checkable_without_solver`: the mask verifier links no solver crate (dependency lint) and accepts the
  fixture's mask; a mask whose support omits a changed field is rejected.
- `evidence_block_marks_revalidated`.
- `exit_codes`: (all preserved, 0), (one revoked, 2), (refusal, 3), (long check, 8).
- `tombstoned_target_869`.

### End-to-end script and logging

`scripts/e2e/result_revalidate.sh` sources the shared helper of STD-E2E. On the mission slice's stance
fixture (the passive-spring amendment) and on the four-state camera fixture: `frob mission synthesize …`,
then `frob result revalidate <answer> --between <mission v1> <mission v2> --json` for each amendment; asserts
grades, licences, the mask's offline check with `frob-verify`, exit codes, and refusal 870 on a hand-edited
answer that claims survival without a licence. From the third milestone the script adds the doorway fixture
and a design edit (`--after-edit`). Log `target/e2e-logs/result_revalidate/<utc>.ndjson` with transcript:
commands, exit codes, wall time, evidence blocks, per obligation the grade, licence kind and status, counts
by grade, solver calls (expected zero for grades 1 and 2), and on failure the first obligation whose status
differs from a fresh recomputation. Final `summary` line naming GATE-ATEL-11.

### Known answers and negative controls

- KA-699: the four-state camera fixture (decisions commit at ticks 2 and 4, a packet at tick 1; states:
  initial, a display label renamed, delivery delayed to tick 2, delivery delayed to tick 3): 2, 0, 0, 1
  scene-pair evaluations and 1, 0, 0, 1 verdict recomputations, each verdict equal to a fresh replay.
  Negative control (CX-315): the key without delivery time keeps a stale promotion.
- KA-700 / CX-316: widening the doorway: the cost-9 cart stays feasible; its optimality is revoked. Negative
  control: an optimum kept after a cheaper rival became feasible.
- Negative control for the surface: an executor that fills `preserved` when the engine is silent (the
  default-is-revoked test fails).
- Determinism: identical answers twice and across worker counts at the same frontier.

## Considerations

- OPEN-ATEL-4 (owner: Tether lead; blocks the verb registry freeze at M3): whether `result.revalidate` and
  the mission cluster's verb stay two verbs over one engine or become one. Default: two verbs, one engine;
  this surface is written so that merging them is a registry change only.
- The ceiling, stated before any speed test: rollouts and training are at least nine tenths of per-design
  compute and depend on every mass and geometry parameter, so exact reuse after a dynamics-affecting edit is
  at most about a tenth of compute. Revalidation is an evidence rule and a hygiene measure. It is not a
  source of the ten-fold, and the verb's output never presents carried-forward evidence as time saved without
  the column name.
- Training avoided by a warm start is not reuse in this sense; it is reported in its own column of the reuse
  ledger and credited to inheritance once.
- RISK-38 (an incomplete key or support serves a stale verdict; high): the surface's contribution is that
  nothing is preserved without a recorded, checkable licence.
