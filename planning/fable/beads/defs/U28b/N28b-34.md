## Background

Grade 3 of verdict reuse is the only grade that keeps a verdict although a field inside its dependency
support changed. Its licence is an *implication*: the assumptions form a lattice, each component of the
assumption set carries a partial order (inclusion for sets, pointwise order for limits, refinement for
information), and a verdict has a polarity: a result that says "a witness exists" (inclusion) survives
changes that make the problem easier, and a result that says "no witness can exist" (exclusion) survives
changes that make it harder (construction C-18). This is Frontier, behind a flag, and the plan keeps a
negative result on purpose to stop anyone from over-valuing it: on the four-state camera fixture a semantic
receipt and a conventional dependency graph given the same eligibility condition did identical work, so on
small cases a correctly keyed dependency graph ties a semantic receipt, and grade 3 has no demonstrated
advantage. What decides safety is the completeness of the key. Grade 2 is the default; grade 3's open value
is whether a useful non-dependence certificate can be obtained cheaply for a rich plant. (A related idea,
reuse of a verdict by sensitivity margin, was withdrawn for want of a certificate; a matched dependency graph
duplicated every saving.)

Because a wrong rule here is a false accept (unsafe reuse is a false accept even if a later change restores
feasibility; one false reused verdict disables the rule that licensed it until it is repaired), every rule
must be proved, tested both ways, and removable. Proof obligation PO-ATEL-06: each polarity rule preserves
what it claims to preserve; discharged by a written derivation per rule, a positive and a negative fixture
per rule, and an exhaustive check on the finite-game fragment of the mission chapter. This bead writes the
table as registry rows and discharges the obligation.

## Scope

In: the sixteen rules with names, side conditions and derivations; the five governing rules as executable
checks; the fixture families and their numbers; the exhaustive finite-game check; the registry rows.

Out: the engine's rule-evaluation path and registry mechanics (BD-292); grade 3 for non-mission verdict
kinds in production and grade 4 (BD-347); the frozen campaign and the gate (N28b-35); the kill decision
(N28b-36).

## Technical approach

**1. The table (the plan's; "Preserved" cells become rules, every other cell is "recheck").**

| Component | Change | Inclusion (a witness exists) | Exclusion (no witness can exist) |
|---|---|---|---|
| Disturbance or world set | Narrowed | Preserved, with the same witness | Recheck |
| | Enlarged | Recheck | Preserved, if the policy class and the information contract are unchanged |
| Hypothesis support (admitted hidden parameters) | Enlarged | Recheck | Preserved |
| Actuator limits | Relaxed | Preserved, if the old command stays realizable and the plant still realizes the old dynamics | Recheck |
| | Tightened | Recheck | Preserved |
| Requirement | Relaxed | Preserved | Recheck |
| | Tightened | Recheck | Preserved |
| Policy class | Enlarged | Preserved | Recheck |
| | Shrunk | Preserved only if the witness policy is still in the class | Preserved |
| Information contract | Refined: more, earlier or better observations, the old ones still recoverable | Preserved | Recheck |
| | Coarsened or delayed | Recheck | Preserved |
| Catalog and prices | Part added or price lowered | Preserved | Recheck. This is where an optimum is lost: every cheaper rival must be excluded again |
| | Part removed | Preserved unless the witness uses the part | Preserved; an optimum that used the part is void |
| Free space of the scene | Enlarged | Preserved, if the witness trace does not touch the changed region | Recheck every exclusion that used the removed obstacle |

A direction the table does not list (a narrowed hypothesis support, a reduced free space) has no rule and is
a recheck: the registry fails closed.

**2. The sixteen rules (registry rows `name`, `component`, `direction`, `verdict_kind`, `side_conditions`).**
`world-narrowed/inclusion` (same witness); `world-enlarged/exclusion` (policy class and information contract
unchanged); `hypothesis-enlarged/exclusion`; `actuator-relaxed/inclusion` (old command realizable; plant
realizes the old dynamics); `actuator-tightened/exclusion`; `requirement-relaxed/inclusion`;
`requirement-tightened/exclusion`; `policy-enlarged/inclusion`; `policy-shrunk/inclusion` (witness policy
still in the class); `policy-shrunk/exclusion`; `information-refined/inclusion` (old observations
recoverable); `information-coarsened/exclusion`; `catalog-added/inclusion`; `catalog-removed/inclusion`
(witness does not use the part); `catalog-removed/exclusion`; `freespace-enlarged/inclusion` (witness trace
does not touch the changed region). Every rule ships `status = disabled` and is enabled only by the
KILL-REUSE ruling's "adopt" branch, one at a time.

**3. The five governing rules, as checks the engine runs before any rule is consulted.**
1. *A rule applies only to a pure change in its direction.* A larger motor relaxes a torque limit and also
   changes mass and rotor inertia. It is not a relaxation; the model diff sends it to grade 4. (A room
   segment may guarantee a wheel-traction margin under a normal-load interval, and a changed motor can leave
   that interval through acceleration.)
2. *Feasibility and optimality are separate obligations.* A cheaper, newly feasible rival always revokes an
   incumbent's optimality claim, including when an amendment adds a catalog part.
3. *Joint edits need a joint check.* Polarity rules compose only when the edited components have disjoint
   dependency supports for the obligation. A simultaneous edit to observation timing and to the floor law is
   checked jointly.
4. *Improving something can destroy a result.* A better sensor preserves witnesses and can void an
   impossibility that rested on two worlds being indistinguishable (hence "information refined: recheck
   exclusions").
5. *Unsafe reuse is a false accept.* One false reused verdict disables the rule that licensed it until it is
   repaired, and a checker rejects an unknown rule name or a changed quantifier prefix even when every hash
   is consistent.

**4. Derivations.** One file per rule under `docs/derivations/polarity/<rule>.md`, each stating the verdict
as a quantified formula over the assumption sets, the order relation, the one-step argument (for an
inclusion ∃π ∀w ∈ W: φ, narrowing W to W′ ⊆ W keeps the same π; for an exclusion ¬∃π ∈ Π ∀w ∈ W: φ, enlarging
W keeps it because any π that worked on the larger set would work on the smaller), every side condition and
the smallest case in which dropping it fails.

**5. Fixture families (exact arithmetic; each rule gets one positive and one negative case).**
- *Interval reach* (hand-checkable): choose a command u with |u| ≤ U so that u − d ≥ R for every disturbance
  |d| ≤ D. A witness exists exactly when U − D ≥ R. Inclusion at (U, D, R) = (3, 1, 2): narrowing D to 1/2
  preserves it (positive); enlarging D to 2 gives 3 − 2 < 2, so the inclusion must be rechecked and is in
  fact lost (negative). Exclusion at (2, 1, 2): enlarging D, tightening U or tightening R preserves it;
  relaxing U to 3 does not. The same family covers the actuator and requirement rows.
- *Mixed change* for governing rule 1: U raised from 2 to 3 by a larger motor whose mass also lowers the
  achievable acceleration so that the old command is no longer realized: the classifier must return `Mixed`
  and grade 4.
- *Docking with a hidden gain* (hypothesis support; the plan's counterexample): the gain is 1 or 2 and one
  velocity reading decides the action. Add the gain 33/32 to the support: it is indistinguishable from gain
  1 at an error radius of 1/64, and every one of the 34,590 positive decisions on each test grid is wrong
  for the amended mission. "Hypothesis support enlarged: recheck inclusions" is not a formality; exclusions
  survive.
- *Policy class*: the stance family under independent foot forces against equal passive springs (shrinking
  the class from independent forces to passive springs keeps exclusions; an inclusion survives only if its
  witness is a passive-spring distribution: under independent forces a stance needs 155 N at the worst foot,
  under equal passive springs the forces are (175, 115, 85, 25) N against a 160 N cap).
- *Information contract*: the camera-delivery fixture (decisions commit at ticks 2 and 4, a packet at tick
  1): an earlier or additional packet preserves inclusions; a delay to tick 3 preserves exclusions and forces
  a recheck of the first decision's inclusion.
- *Catalog and free space*: the cost-9 cart and cost-5 relay with a doorway. Widening the doorway preserves
  the cart's feasibility (its trace does not touch the changed region) and revokes its optimality; adding a
  catalog part does the same; removing a part the witness does not use preserves both kinds.

**6. Exhaustive finite-game check.** On the finite docking game over causal histories with one velocity
packet (the exact fragment of the mission chapter), enumerate every pure change of each kind over a bounded
grid of parameters (gain sets drawn from {1, 33/32, 2}, error radii in sixty-fourths, torque bounds and
tolerances on the grids of the base fixture). For every (verdict, change, rule) triple in which a rule says
"preserved", recompute the verdict from scratch; every one must agree. The count of triples and the count
of agreements are recorded; a single disagreement fails the obligation and names the rule.

**7. Layout.** Registry rows in `registries/revalidation-rules.toml`; fixtures in
`crates/frob-conformance/src/fixtures/polarity/`; derivations under `docs/derivations/polarity/`.

## Acceptance criteria

- [ ] Sixteen rules are registered with names, side conditions and `status = disabled`; unlisted directions
      have no rule.
- [ ] Each rule has a derivation file, a positive fixture (preserved, equal to full recomputation) and a
      negative fixture (the opposite direction or a violated side condition is a recheck, and naive reuse
      there is wrong).
- [ ] PO-ATEL-06: the exhaustive finite-game check passes with zero disagreements; the triple count is
      recorded.
- [ ] The five governing rules are enforced before any rule is consulted: a `Mixed` change, a joint edit on
      shared support, an unknown rule name and a changed quantifier prefix are each rejected on their fixture.
- [ ] The hair-widening case withdraws all 34,590 positive decisions on each test grid and keeps exclusions.
- [ ] Mutants are caught: each rule with its polarity flipped fails its negative fixture; each side condition
      removed fails its smallest case.
- [ ] The rows agree with the mission chapter's registered rules where they overlap (a differential test
      over the docking family).

## Test plan

### Unit tests

`cargo test -p frob-conformance --test polarity_rules`:

- `table_has_sixteen_rules`; `unlisted_direction_has_no_rule` (hypothesis support narrowed; free space
  reduced).
- One pair per rule, for example `world_narrowed_inclusion_positive` ((3, 1, 2) → D = 1/2: preserved, same
  witness u = 3) and `world_enlarged_inclusion_negative` (D = 2: 3 − 2 = 1 < 2, recheck required and the
  verdict flips); `actuator_tightened_exclusion_positive` ((2, 1, 2) → U = 3/2: still excluded);
  `actuator_relaxed_exclusion_negative` (U = 3: now feasible).
- `mixed_change_is_grade_4`; `joint_edit_shared_support_is_grade_4`.
- `hypothesis_hair_widening`: support {1, 2} → {1, 33/32, 2} at error radius 1/64: 34,590 of 34,590
  inclusions withdrawn per grid; exclusions kept.
- `better_sensor_voids_impossibility`: an exclusion resting on two indistinguishable worlds is rechecked
  after refinement and is found false.
- `cheaper_rival_revokes_optimum`: catalog part added at cost 5 → `optimal: revoked`.
- `removed_unused_part_preserves`; `removed_used_part_voids_optimum`.
- `freespace_witness_untouched` against `freespace_witness_touches_region`.
- `polarity_flip_mutants_caught` (sixteen mutants); `side_condition_mutants_caught`.
- `finite_game_exhaustive`: all triples agree with recomputation.

### End-to-end script and logging

Step `polarity` of `scripts/e2e/result_revalidate.sh` (bead N28b-32), enabled with the session flag
`frontier-revalidate-implication` and a scratch registry in which the rules are enabled: for the interval
reach, doorway and docking fixtures, `frob result revalidate … --grades 3 --json` in the preserving and the
non-preserving direction; asserts grade 3 with the rule's name, the old and new assumption sets and the
order relation in the licence for the first, and grade 4 for the second; then disables one rule in the
registry and asserts that its grade-3 survivals become grade-4 reruns on the next call. Logged per STD-E2E:
commands, exit codes, wall time, evidence blocks, per obligation the rule consulted and its check, the
finite-game triple counts, and on failure the first triple whose recomputation disagrees.

### Known answers and negative controls

- KA-701 / CX-314: widening the hypothesis support of the docking fixture by gain 33/32, indistinguishable
  from gain 1 at error radius 1/64, withdraws every one of the 34,590 positive decisions on each test grid.
  Negative control: a hash match taken as verdict transfer.
- KA-700 / CX-316: widening the doorway: the cost-9 cart stays feasible, its optimality is revoked. Negative
  control: an optimum kept after a cheaper rival became feasible.
- The stance figures: 155 N at the worst foot under independent forces; (175, 115, 85, 25) N against a 160 N
  cap under equal passive springs.
- Metamorphic relations of the verification chapter: an edit and its inverse lead to zero evaluations;
  polarity directions (mutation: a hash match taken as verdict transfer); incremental equals full.
- Determinism: the fixtures are exact rational arithmetic; identical everywhere.

## Considerations

- KILL-REUSE (decided at M4): any unsafe reuse on the frozen amendment campaign, or grade 3 saving less than
  a fifth of the recheck cost that grade 2 leaves, keeps every rule disabled. The table and its tests remain,
  because the same rules are what an auditor uses to reject an unlicensed claim of survival.
- The table is about pure changes of one component; most real edits are mixed (governing rule 1), which is
  why the expected benefit of grade 3 is small and why the pilot has a hard stop.
- A rule's side conditions must themselves be checkable from recorded data (is the witness policy in the
  shrunk class; does the witness trace touch the changed region). A side condition that cannot be checked
  makes the rule a recheck.
- New components of the assumption set (a new card field class, a new clock) get no rule until one is
  derived and tested; absence of a rule is always safe.
