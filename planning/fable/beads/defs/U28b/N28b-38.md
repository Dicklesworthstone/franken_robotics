## Background

A memo graph that serves a wrong answer is worse than no memo graph, because it serves it instantly, with
consistent hashes, to every later verb. The studio's memo store therefore follows a written policy with a
loss model, a tripwire, a budget, and a rollback that is a flag. The plan fixes the policy's clauses; this
bead implements them as one module that every node kind goes through, so that no verb has its own idea of
when a cached result may be served. Tier: Solid.

The clauses, as the plan states them:

- *Hits are bit-identical or not served.* Results are placed by index and random streams are keyed by
  address, so a hit equals a recomputation bit for bit inside D0 and same-backend D2. Tolerance-level reuse
  is allowed only for analyses that record an achieved error, never for episodes.
- *Shadow recomputation.* One hit in 64 (DESIGN), chosen by key hash, is recomputed and compared. One digest
  mismatch stops serving that node kind and files a determinism violation.
- *Loss model.* States: valid hit, stale hit, miss. Actions: serve, recompute, shadow. A stale result served
  costs 100 units against the GPU-seconds of a needless recomputation (DESIGN ratio, recorded in the memo
  policy's contract).
- *Budget.* 64 GB by default (DESIGN). On exhaustion the store evicts and never blocks. Nodes in the
  evidence closure of a live claim are pinned.
- *Rollout and rollback.* Shadow, then D0 analyses, then D2 episodes. `--no-memo` disables serving; the
  store can be deleted at any time without losing a result that a claim cites, because cited evidence is
  pinned in Chronicle, not in the cache.
- *Baseline.* Full recomputation per verb with compile-only memoization.

FACTS about siblings the policy leans on: `fs-recompute::Store::can_skip` serves a node cached under a
looser requirement if it achieved enough (the tolerance-reuse pattern); its `StoreError::DeterminismViolation`
is the tripwire pattern; `frankensqlite/crates/fsqlite-pager/src/s3_fifo.rs` implements the three-queue
S3-FIFO eviction policy (a small admission queue, a main queue with bounded reinsertion, a ghost queue of
metadata, an adaptive small share between 5% and 30%), keyed on page numbers, so it is a pattern to follow
and an oracle to compare with, not code to instantiate over content hashes.

Rejected alternatives: serving within a tolerance for episodes (a comparison built on "nearly the same"
episodes is not the comparison that was planned, and its e-value would differ from a recomputation's);
recency-only eviction (a scan over many designs touches each key once and would flush the store); a blocking
store (a full cache must never stall a campaign).

## Scope

In: the serve decision per node kind and determinism class; tolerance reuse for analyses; shadow sampling,
comparison and the per-kind stop latch; the loss model as recorded constants; byte accounting, admission and
eviction rules, pins; rollout modes and `--no-memo`; deletion safety; what is logged per serve decision.

Out: keys and node records (N28b-37); the analyses' and episodes' own wiring and gates (BD-111, BD-220);
retention verbs and collection (BD-209); the equivalence battery (N28b-40).

## Technical approach

**1. The serve decision (numbered; evaluated on every candidate hit).**
1. Mode gate: the store's rollout mode must allow serving this kind (step 6).
2. Latch: the kind's stop latch must be clear.
3. Class gate: the node's determinism class and provenance must allow serving in the caller's context:

| Node's class | Served when |
|---|---|
| D0 (exact) | Always |
| D2 | Same backend and same device fingerprint as the caller's run profile |
| D1 | Same device family, where that family holds D1 for the kernels involved |
| D3 or D4 | Never (a result is never served across a D3 boundary; a D4 result is not memoized) |

4. Tolerance reuse (analyses only): a node that recorded an `achieved_error` may be served for a request
   whose required error is at least that achieved error (a node cached under a looser requirement is served
   if it achieved enough). Episodes, comparisons and controllers have no tolerance reuse.
5. Shadow selection: if the low six bits of BLAKE3(key ‖ kind ‖ "shadow") are zero (one hit in 64), the node
   is recomputed, the digests are compared, and the *recomputed* result is returned; otherwise the stored
   output is served.

**2. The stop latch.** On a shadow mismatch, in one ledger transaction: the kind's latch is set (no further
hit of that kind is served by any session from that commit on: "stops serving within one hit"); a
determinism-violation record is filed with the key, both digests, the two executions' trace identifiers and
device fingerprints; nodes of that kind written since the last clean shadow are marked suspect. Clearing a
latch is an administrative action that cites the repair and re-runs the kind's key tests. The same latch is
set for the node kinds involved when the chunk publisher finds different bytes for a committed chunk key
(`FROB-REF-878`).

**3. The loss model (recorded in `frob-chronicle/CONTRACT.md` and in the policy record).** States: valid hit,
stale hit, miss. Actions: serve, recompute, shadow. Costs: a served stale result costs 100 units; a needless
recomputation costs its GPU-seconds (normalized so that one typical recomputation is 1 unit). Consequences
derived from it and stated in the contract: serving is rational only while the probability of staleness per
hit is below 1/100; the shadow rate of 1/64 detects a systematic defect in a kind within 300 hits with
probability about 0.99 ((63/64)³⁰⁰ ≈ 0.009); shadow costs about 1/64 of the recomputation the store saves.
The ratio and the rate are DESIGN constants; changing either is a new policy version.

**4. Budget, admission, eviction, pins.** The store has a byte budget (default 64 GB; OPEN on the retention
windows and budgets per machine has the same default). Accounting is in bytes of stored outputs plus node
records. On exhaustion the store evicts and never blocks: a write that cannot be admitted is simply not
cached, and the verb returns its computed result. Eviction follows the S3-FIFO pattern; admission is
weighted by recompute cost, because misses are not equally expensive (a cheap entry may be refused admission
in favour of keeping a costly one; that departure from the sibling's policy is tested separately from the
differential test against it). Fallback if the differential oracle fails: least-recently-used with the same
cost-weighted admission; never an unbounded store. Nodes in the evidence closure of a live claim are pinned
and are not eviction candidates; pinned bytes count against the budget and are reported by `store.status`.

**5. Deletion safety.** The cache directory can be deleted at any time. A result that a claim cites is not
lost, because evidence is pinned in Chronicle's content store (chunks, certificates, ledger rows), not in the
cache: after deletion, verbs recompute, and `evidence.trace` on every live claim still resolves.

**6. Rollout and rollback.** A store-wide mode in the configuration registry:

| Mode | Behaviour |
|---|---|
| `off` (the baseline) | Compile-only memoization; every verb recomputes |
| `shadow` | Every candidate hit is recomputed and compared; nothing is served; mismatch counts per kind are recorded |
| `analyses` | D0 analysis, compile and scene nodes are served; episodes are shadowed |
| `episodes` | D2 episodes are also served on the same backend and fingerprint |

Advancing a mode requires the previous mode's record: zero mismatches over at least 10⁴ shadowed hits per
kind being promoted (DESIGN threshold). `--no-memo` on any verb disables serving for that call in any mode;
setting the mode back is a configuration change, not a code change.

**7. What is recorded.** Per call the envelope's cost block carries `memo: { hit, served, shadowed, key }`.
Per kind the ledger keeps counters (hits, served, shadowed, mismatches, admitted, refused admission,
evicted, pinned bytes). The reuse ledger's "exact reuse" column is computed from these counters and the
nodes' recorded costs.

**8. Layout and determinism.** `crates/frob-chronicle/src/memo/{policy.rs, shadow.rs, budget.rs, mode.rs}`.
Serve decisions are pure functions of the node record, the caller's profile, the mode and the latch state at
a ledger frontier; shadow selection is a function of the key, so the same hits are shadowed on every
machine.

## Acceptance criteria

- [ ] The class gate matches the table on every combination of node class and caller profile; no D3 or D4
      node is ever served.
- [ ] Tolerance reuse is available for analyses with a recorded achieved error and refused for every other
      kind.
- [ ] Shadow selection picks 1 key in 64 by the stated hash and is identical across machines; a planted
      mismatch sets the latch, and no further hit of that kind is served afterwards (the next hit recomputes).
- [ ] A determinism-violation record with both digests is filed; clearing the latch requires the cited
      repair and passing key tests.
- [ ] At the byte budget the store evicts and never blocks; a pinned node is never evicted; a refused
      admission returns the computed result uncached.
- [ ] Deleting the cache directory loses no cited evidence: every live claim still resolves, and verbs
      recompute.
- [ ] Modes behave as tabled; advancing without the previous mode's shadow record is refused; `--no-memo`
      computes in every mode.
- [ ] The loss constants, shadow rate, budget and thresholds are in the contract; changing one bumps the
      policy version recorded on serve decisions.

## Test plan

### Unit tests

`cargo test -p frob-chronicle --test memo_policy`:

- `class_gate_matrix`: 5 node classes × 4 caller profiles.
- `tolerance_reuse_analysis_only`: an analysis cached at achieved error 10⁻⁶ serves a request for 10⁻⁴ and
  not one for 10⁻⁸; an episode with any tolerance request is a miss.
- `shadow_rate`: over 2²⁰ generated keys, between 1/64 − 0.001 and 1/64 + 0.001 are selected.
- `shadow_mismatch_latches_kind`: after the planted mismatch the very next candidate hit of that kind is
  recomputed; another kind is still served.
- `latch_set_by_chunk_conflict`.
- `detection_probability`: (63/64)³⁰⁰ < 0.01.
- `budget_never_blocks`: writes at 100% of budget return immediately; byte accounting never exceeds budget
  plus one admission.
- `pinned_never_evicted`: 10⁴ random eviction cycles with pins.
- `cost_weighted_admission`: a 2 MB node of cost 0.01 s is refused while a 2 MB node of cost 300 s is kept.
- `delete_cache_keeps_evidence`.
- `mode_table`; `advance_requires_shadow_record`; `no_memo_flag`.
- `policy_version_on_decisions`.

### End-to-end script and logging

Steps `policy` and `shadow` of `scripts/e2e/memo_graph.sh` (bead N28b-40): with the mode set to `shadow`,
run `frob design check` on the templates and read the per-kind counters with `frob store status --json`
(served = 0, shadowed = hits, mismatches = 0); switch to `analyses` and repeat (served > 0); enable the
conformance fixture's planted nondeterministic analysis and repeat until a shadow fires, then assert the
latch (the next call recomputes, `memo.served` is false, the violation record exists); delete the cache
directory and assert that `frob evidence trace` still resolves a stored claim and that the next check
recomputes. Logged per STD-E2E: commands, exit codes, wall time, evidence blocks, counters per kind, latch
state, both digests of the mismatch, bytes used against the budget, and on failure the first hit served
after a latch.

### Known answers and negative controls

- INV-ATEL-08 (a memo hit is bit-identical to a recomputation inside its determinism class): shadow
  recomputation is its production test; the planted nondeterministic analysis is the negative control it
  must catch.
- Interference rule with the decision cores (a hit is bit-identical to a recomputation, so no core can
  tell): a partly memoized comparison reaches the identical e-value; asserted in N28b-40 and by the
  composition bead.
- Negative controls: a store that serves a D2 episode on another fingerprint (the class gate test fails; the
  seed bead for episodes requires "an episode recorded on another fingerprint is not served"); a store that
  blocks at budget; a latch that only logs.
- Differential oracle (owned with the eviction gate): under a bijection from keys to page numbers the
  eviction sequence equals the sibling's on 10 recorded traces of at least 10⁵ accesses, and on the
  edit-loop trace the hit ratio is not below least-recently-used.
- Determinism: serve decisions identical twice and across platforms for the same ledger state.

## Considerations

- RISK-38 (an incomplete memo key serves a stale verdict; high; owner Atelier lead): keys are the first
  defence, this policy's shadow recomputation and latch the second, the revalidation gate the third.
- Where the reuse is, and is not: the comparison that follows a 2,048-world run of the previous version on
  the same scene reuses that version's episodes at the comparison's addresses; a controller-only edit reuses
  every model analysis; a mass or geometry edit reuses no rollout. The policy cannot change that; it only
  makes what reuse exists safe.
- Targets, unmeasured: `design check` after a one-parameter edit in 0.2 / 0.5 / 1.0 s at the 50th / 95th /
  99th percentile (TARGET). The policy's overhead (lookup, shadow) is part of that budget.
- Private-scene results inherit the scene's privacy class in the cache as in the evidence store; deleting a
  private scene purges its nodes.
