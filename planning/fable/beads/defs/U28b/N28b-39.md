## Background

Two node kinds of the memo graph sit between the model-side nodes (compile, analysis, scene) and the raw
episodes, and they are where most of the reuse an agent actually feels comes from. *Controller synthesis*
(key: model identity, task interface, synthesis version; served within D0 or same-backend D2) means that an
edit which leaves the model untouched (a reward change, a scene change, a rename) does not resynthesize the
baseline controller, and that asking twice costs once. *Comparison and summary* nodes (key: the identities of
their inputs and the rule version; class: derived) mean that a comparison is never an opaque cached verdict:
it is recomputed from memoized episodes and reaches the identical e-value. The plan's example of where reuse
is: the comparison that follows a 2,048-world run of the previous version on the same scene reuses that
version's episodes at the comparison's addresses. Tier: Solid.

The second kind carries a subtle requirement. A study's statistic must be a pure function of the per-address
outcomes taken in address order; it must not depend on completion order, preemption, co-tenancy, shard count
or memo hits (INV-ATEL-02). So reuse of episodes inside a comparison has to be invisible to the statistics,
and the set of addresses a comparison uses must never be chosen by looking at outcomes that already exist.

Rejected alternatives: caching the comparison's verdict under the pair of design identities (a verdict
depends on the task, the addresses, the study type, the margin and the rule version; a coarse key would
serve the wrong verdict, and a fine one adds nothing over recomputing from episodes, which is cheap);
reusing whichever stored episodes happen to exist for an arm (that selects addresses by availability, and
availability can correlate with outcomes, for example when failing worlds were retained and others evicted).

## Scope

In: the controller-synthesis node (inputs, outputs including typed non-success outcomes, serve class); the
derived-node rule for comparisons, scorecards and summaries; how a comparison's address schedule is chosen so
that reuse is possible and unbiased; the prefix rule; what the envelope reports about reuse inside a
comparison.

Out: keys in general and the store policy (N28b-37, N28b-38); episode nodes (BD-220); synthesis itself
(BD-118, BD-247); the comparison engine (BD-262); the equivalence battery (N28b-40).

## Technical approach

**1. Controller synthesis node.** Declared inputs: `ModelId` (the whole model identity: synthesis reads mass
properties, kinematics, actuator cards and contact geometry, so no restriction is attempted), the task
interface (observation and action spaces, the control period and clocks, the commanded quantities; not the
reward and not the scene), and the synthesis version. Output: the three-outcome result as a canonical
record: `synthesized` with the `ControllerId` and its artifact; `synthesized-failed` with the diagnostic;
`not-synthesizable` with the named reason. All three are memoized: a failure is an answer, and re-asking
must not spend the seconds again or return a different failure. Serve class: D0 where the synthesis path is
exact (rational gains, table lookups, the atlas's phase lags); same-backend D2 where it runs a floating-point
program on a backend (the stance force-distribution set-up, any numerical tuning), in which case a hit is
served only on the same backend and fingerprint. The node's `deps` name the analyses it consumed (symmetry,
mass roll-up), so an edit that changes one of those invalidates the controller through the graph.

Consequences that the tests pin: a reward-only or scene-only edit is a hit; a mass or geometry edit is a miss
(seconds to resynthesize); a control-period change is a miss; a rename is a hit.

**2. Derived nodes.** A comparison, a scorecard and a summary are *derived*: their value is a deterministic
fold over the outputs of other nodes (episodes, in address order) under a versioned rule. The rule:

- a derived node is never served as stored bytes on its own authority; it is recomputed from its inputs'
  outputs each time it is requested, and the stored copy (kept so that `result.show` and reports are fast)
  is compared with the recomputation; a difference is a determinism violation of the *rule* and sets that
  kind's latch;
- its key is the hash of its inputs' identities (the ordered list of episode identities per arm, the study
  plan's identity, the frontier where it reads a ledger) and the rule version;
- because inputs are consumed in address order, the fold's result is the same whether an episode was just
  simulated or served from the store. A partly memoized comparison reaches the identical e-value, confidence
  sequence, pair counts and verdict.

**3. The address schedule of a comparison (what makes reuse possible without bias).** A study plan fixes its
world addresses before any episode of the study is drawn, and the caller never chooses them: `eval.compare` has
no seed input (`--run-seed` is `FROB-REF-802` there), because a caller who could name the worlds of a
comparison could choose them after seeing outcomes. By default the comparison engine draws the address list
from the plan key (BD-262, `seed_protocol.addresses = "philox:plan-key"`). A list drawn from the plan key alone
never coincides with the addresses of an earlier run, so no stored episode would ever be reused and the plan's
stated reuse (the comparison that follows a run of the previous version) would be lost. This bead therefore
adds one case to the planner (DESIGN): when a stored run of either arm exists with the same scene, task,
controller or policy, tier, kernel versions and effort profile, the planner takes the seed and world range of
the most recent such run, so that one arm's episodes at those addresses are memo hits; with no such run the
plan-key draw stands. The choice is the planner's, a pure function of the request and the ledger at the plan's
pinned frontier; no input of the verb selects a run, a seed or a range. Two rules keep this honest:
- *the prefix rule:* the study uses a prefix, in address order, of that run's schedule (worlds 0 to n − 1),
  never a subset chosen by which episodes are still stored or by any property of their outcomes. If an
  episode inside the prefix has been evicted it is recomputed; the prefix is not shortened to avoid it;
- *the plan records the choice:* `seed_protocol: { reused_schedule_of: RunId, prefix: n }`, hashed into the
  plan before submission, so the choice is auditable and cannot be changed after outcomes are seen.
The other arm runs fresh episodes at the same addresses, which is what pairing means.

**4. Reporting.** A comparison's envelope carries, beside its statistic, `reuse: { arm_a: { served, computed
}, arm_b: { served, computed } }` in episodes and in recorded GPU-seconds, and the accounting identity
a_only + b_only + both + neither + unscored = planned is checked on the folded result exactly as on a fully
fresh one. The race ledger and the reuse ledger read these counts.

**5. Summaries.** A token-budgeted run summary and a scorecard are derived nodes over a run's committed
chunks at a pinned frontier: key = (run identity, frontier, rule version, budget parameters). A summary names
the frontier it was computed at; a later frontier is a different key.

**6. Layout and determinism.** `crates/frob-verbs/src/memo/{synth_node.rs, derived.rs}`; the planner's
schedule proposal in `crates/frob-opt/src/compare/schedule.rs`. Derived folds are D0 given their inputs'
outputs.

## Acceptance criteria

- [ ] `control.synth` twice on one model and task interface computes once; a reward-only, scene-only or
      rename edit is a hit; a mass, geometry or control-period edit is a miss.
- [ ] `synthesized-failed` and `not-synthesizable` outcomes are memoized and returned identically.
- [ ] A D2 synthesis node is not served on another backend or fingerprint.
- [ ] A comparison computed (a) with all episodes fresh, (b) with one arm fully served, (c) with a random
      half of both arms served, returns byte-identical statistics, pair counts and verdict.
- [ ] The stored copy of a derived node is compared with its recomputation on every request; a planted
      rule-version skew is caught and latches the kind.
- [ ] After a 2,048-world run of version A, `eval.compare A B` reuses A's episodes on a prefix of that run's
      schedule and computes only B's; the plan records the reused schedule; with no qualifying stored run the
      plan says `addresses: "philox:plan-key"`; and `eval.compare … --run-seed <s>` is still 802 (this bead adds
      no seed input).
- [ ] With some of A's episodes inside the prefix evicted, those are recomputed and the prefix is unchanged.
- [ ] A schedule built from "whichever episodes are stored" is rejected by the plan validator.
- [ ] The envelope reports served and computed episodes per arm.

## Test plan

### Unit tests

`cargo test -p frob-verbs --test memo_synth_derived`:

- `synth_hit_on_reward_edit`; `synth_miss_on_mass_edit`; `synth_miss_on_control_period`;
  `synth_hit_on_rename`.
- `synth_failure_memoized`: a design the baseline cannot synthesize returns the same `not-synthesizable`
  record twice with one computation.
- `synth_d2_not_served_cross_backend`.
- `comparison_fresh_equals_memoized`: 256 paired addresses; fresh, one arm served, half served: identical
  e-value, confidence sequence and counts (byte comparison of the canonical result).
- `derived_recompute_checks_stored_copy`; `rule_version_skew_latches`.
- `prefix_rule`: stored run of 2,048 worlds; a comparison of n = 512 uses worlds 0 to 511.
- `evicted_inside_prefix_recomputed`: worlds 100 to 119 evicted → 20 recomputed, prefix still 0 to 511.
- `availability_selected_schedule_rejected`: a plan whose addresses are {stored worlds only, non-contiguous}
  fails validation.
- `summary_key_includes_frontier`: the same run at two frontiers gives two keys.
- `accounting_identity_holds_on_fold`.

### End-to-end script and logging

Step `derived` of `scripts/e2e/memo_graph.sh` (the script's owner is N28b-40, a dependency, which keeps the
step as a hook that fails closed until this bead lands; this bead writes the step): `frob sim run` of design
A for 256 worlds;
`frob design edit` to make B; `frob eval compare A B --task … --json` (expect arm A served: 256, computed: 0
and arm B the reverse); the same comparison with `--no-memo`; a byte comparison of the two results;
`frob control synth` before and after a reward-only edit (hit) and after a mass edit (miss). Every call of a
run or mutate verb in the step carries its own `--key` (`dv-run-a`, `dv-edit-b`, `dv-cmp`, `dv-cmp-nomemo`,
`dv-synth-1` to `dv-synth-3`, `dv-edit-mass`; `design.edit` also its `--expected-parent`): a repeated key
returns the stored receipt of the first call, which would make the second synthesis look like a memo hit
whatever the memo graph did. Logged per
STD-E2E: commands, exit codes, wall time, evidence blocks, served and computed counts per arm with
GPU-seconds, the e-value and pair counts of both forms, result digests, and on failure the first address at
which the two forms' outcomes differ.

### Known answers and negative controls

- The plan's reuse statements as known answers: the comparison after a 2,048-world run reuses that version's
  episodes at the comparison's addresses; a controller-only edit reuses every model analysis; a mass or
  geometry edit reuses no rollout.
- INV-ATEL-02 and INV-ATEL-08: the three-way equality test is their test for comparisons.
- Negative controls: a comparison cached under (A, B) alone (changing the margin then returns the old
  verdict; the test changes the margin and requires a different key); a fold that consumes episodes in
  completion order (differs between the fresh and memoized forms under shuffled completion).
- Metamorphic: requesting the comparison with n = 256 and then n = 512 reuses the first 256 pairs and the
  e-value after 256 pairs in the second equals the first's final value.
- Determinism lanes: twice on one machine; across worker counts; `batch-cpu` and a GPU backend, each against
  its class.

## Considerations

- Reusing the previous run's schedule ties a sequence of comparisons to one set of worlds. That is efficient
  and it is also how an agent overfits to those worlds; comparisons on discovery worlds are development
  results, and a result reported as a claim goes through the blinded qualification lane with fresh sealed
  clusters, where no reuse applies.
- Failing worlds are retained longer than passing ones by the retention policy; the prefix rule exists
  precisely so that this asymmetry can never shape a comparison's sample.
- Synthesis keyed on the whole model identity is deliberately conservative; restricting it to the fields
  synthesis reads is possible later through the tracked-read mechanism if the profile shows resynthesis
  matters.
