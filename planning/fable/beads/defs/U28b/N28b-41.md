## Background

Two designs that the mission cannot tell apart are evaluated once. The mechanism belongs to the population
subsystem: one canonical representative per orbit under the observation-preserving subgroup, and a
*mission-observable digest*, which is the compiled model restricted to the quantities that enter the
mission's equations (total inertia, collision hull, joint and actuator parameters, port coordinates, sensor
visibility, thermal and electrical bus, task objective), with results memoized on it. This is campaign-level
deduplication: algebra spent at campaign time, where it deletes simulations, and not in the per-step loop.
Tier: Frontier for the digest quotient (Solid for orbit counting).

Atelier's part is three rules, and this bead implements them:

1. The digest is a memo key like any other and obeys the store policy: derived from declared inputs,
   shadow-recomputed, stopped on one mismatch.
2. "Equal digests imply identical trajectories" is a structural rule with a bit-identical replay test. It is
   a statement about the simulator and is not offered as a proof obligation to any proof checker.
3. The factor is reported, not promised. A fixture built to have a large factor (ballast slugs that enter
   the dynamics only through count and first and second moments reduce 735,471 placements to 24,546 classes)
   shows the mechanism is exact; it says nothing about the factor on a real brief. Placements with equal
   first moment and different second moment must split, and adding a placement-dependent quantity to the
   mission enlarges the digest and splits classes.

Why Atelier owns these rules: the digest decides that a result computed for one design *is* the result for
another, which is verdict reuse across designs. The studio's rule for all reuse applies (a hash identifies;
only an implication licenses skipping a recheck), and the digest's implication is a claim about what the
simulator reads, which can be tested and cannot be proved by the project's proof tools. BET-31 (campaign
quotienting removes a measurable share of campaign work without removing a winner) is falsified by a single
false equivalence, so the rules are written to find one.

Rejected alternatives: treating equal digests as a certificate (no proof checker decides it; calling it
proved would raise the evidence class of everything built on it); quoting the ballast factor as an
expectation (independent material or compliance changes make every class a singleton on a real brief).

## Technical approach

**1. The digest as a node kind.** Kind `MissionDigestResult`: declared inputs are (a) the mission or task
identity, including its list of observables (the quantities its equations read), (b) the digest itself: the
BLAKE3 of the compiled model's projection onto those observables, in canonical form, (c) scene, controller
or policy, world address, tier, kernel versions, effort profile, device family: everything an episode's key
has except the full model identity, which the digest replaces. In the types of the digest's owner (N17a-26)
that is `ExperimentKey { digest, task, scenes, policy, kernels, tier, profile }` plus the world address and
the device family. The device family is in the memo key and not in `ExperimentKey` (DESIGN): the plan's
sentence "the same task, scenes, policy, kernels, tier and profile are the same experiment" defines the
experiment, and the memo graph's rule that an episode hit is served only on the same backend, class D2, adds
the device family to the key under which a result is stored. The key is derived by the same machinery as
every other kind; no code writes a digest key by hand. The projection's field list is data (declared by the
mission compiler from the mission's equations), so a mission that adds a placement-dependent quantity (a
clearance at one slot, a sensor's view of one module) enlarges the projection, changes digests and splits
classes without any change to this bead.

**2. The two key tests.** These are the two tests every memo node kind has (N28b-37), run on this kind.
*Declared-input perturbation:* changing any declared input of the kind (the digest, and with it any
observable; the task; the scene; the policy; the world address; the tier; the kernel versions; the effort
profile; the device family) changes the key.
*Live dependency:* for every field of the full compiled model, changing it either changes the digest or
leaves the mission's evaluated trajectories bit-identical on a sample of world addresses. The digest's owner
runs the complementary test one level down (N17a-26: every table entry the `batch-cpu` step is recorded as
reading either changes the digest or leaves every output bit unchanged, which catches a kernel that reads an
undeclared column); the test here works from design fields and trajectories and needs no access recording. This is the test
that would catch an observable the mission reads but the projection forgot (for the ballast fixture: a
projection with count and first moment only fails here, because changing the second moment changes the
trajectory and not the digest).

**3. Shadow recomputation for digest classes.** For a class with more than one member, the representative's
episodes are computed and the other members are served from them. The shadow rule is the store policy's,
unchanged, through the memo graph's one selector (N28b-38): each node has a durable hit ordinal n, incremented
in the serve transaction (it survives restarts, and concurrent sessions never draw the same one); its phase is
p = the low six bits of BLAKE3(kind ‖ kind version ‖ key); a hit is shadowed when (n + p) mod 64 = 0. The key
fixes only the phase, and the rate comes from the per-node ordinal. That matters here more than anywhere: every
member of a class shares one memo key, hence one node, per address, so a selector on the key alone would shadow
all members' hits at an address or none of them, while this one shadows each class's shared node exactly once in
every 64 of its member hits; among nodes hit once each, one in 64 is chosen by key hash, as the plan says.
For this kind a hit is an episode of a member other than the representative, served from the stored episode
under the same memo key, and recomputing it means simulating the requesting member's own design at that
address and comparing its per-episode state digest with the stored one, bit for bit, inside the determinism
class (same backend, D2). Recomputing the representative again would test determinism and not the structural
rule. (An earlier draft of this bead shadowed one class in 64 by simulating one second member on all the
class's addresses; the plan's rule for the digest is the store policy's "one hit in 64, chosen by key hash",
which the digest's owner also states, and it samples every member of every class instead of one member of
one class in 64.) What it costs is stated with the factor in section 6. One mismatch:
- sets the latch of this node kind: no further result is served across designs by digest equality, in any
  campaign, until the latch is cleared with a cited repair; a request that would have been served by digest
  while the latch is set is recomputed, and an attempt to serve it anyway is the refusal `FROB-REF-162`
  (reuse without a dependency digest, or a shadow recompute that disagreed; repairs: recompute; quarantine the
  node kind);
- files the pair as a false equivalence (design identities, the mission, the first differing episode and
  tick), which is the falsifier of the quotienting bet and a negative-control seed;
- in the running campaign, every class the digest formed is split and its members are re-admitted, and
  deduplication continues by orbit representatives and content hash only.

**4. The replay test (the structural rule's standing test).** A conformance test, run on every change to the
simulator's kernels, the mission compiler or the projection: for each fixture family (the ballast family and
at least one family per archetype built from module swaps that preserve the observables), draw pairs of
designs with equal digests with the sampler of the digest's owner (`sample_pairs(classes, n, seed)`, N17a-26:
by keyed hash, weighted toward large classes) and replay both on the same world addresses on every backend; the chained state
digests must be identical bit for bit on the same backend. The pilot's falsifier is the same statement: one
merged pair whose replays differ in any bit.

**5. How a result served through the digest is labelled.** Its evidence block carries
`structural_rules: ["equal-digest"]`, the class id (the digest) and the representative's identity; its
evidence class is at most
`Tested` on that account, whatever the class of the representative's own result, and the certificate
checker's closed list of proof kinds contains nothing that would accept "equal digest" as a proof. A report
that prints such a result names the representative.

**6. The factor, reported.** Per campaign and stratum: designs admitted, orbit representatives, digest
classes, designs evaluated, and the factor as an exact ratio with its numerator and denominator, split into
the orbit part and the digest part. No estimate of the digest factor is printed before the stage has run. In
the cost estimate the digest factor is taken as 1 (no saving assumed) and the orbit factor as the counting
formula's value for enumerated families. Episodes simulated in shadow are reported as their own count beside
the factor and are never left out of the work reported: with one hit in 64 shadowed, a class of m members
costs about 1 + (m − 1)/64 design evaluations and not 1, so on the ballast fixture the reduction in designs
dispatched is 30.0 (735,471 over 24,546) and the reduction in work with shadowing on is about
735,471/(24,546 + 710,925/64) = 20.6 (DESIGN arithmetic, not a measurement).

**7. The ballast fixture (the plan's known answer).** Eight equal ballast slugs in 24 collinear slots enter
rigid-body dynamics only through their count, Σx and Σx²; the C(24, 8) = 735,471 placements fall into 24,546
classes. Split controls: slots {1, 4} and {2, 3} have equal Σx = 5 and different Σx², 17 and 13, and must not
merge; adding to the mission a requirement that reads the occupancy of slot 1 must split classes that differ
there.

**8. Layout and determinism.** `crates/frob-opt/src/dedup/digest_policy.rs`; fixtures in
`crates/frob-conformance/src/fixtures/ballast/`. Class formation and the shadow selection are D0; the replay
comparison is in the episodes' determinism class.

## Acceptance criteria

- [ ] The digest is a registered node kind with derived keys and passes both key tests; a projection without
      second moments fails the live-dependency test on the ballast family.
- [ ] 735,471 placements give 24,546 classes (exact count); {1, 4} and {2, 3} are in different classes.
- [ ] Adding a placement-dependent observable to the mission changes digests and increases the class count on
      the fixture.
- [ ] Hits are shadowed exactly when N28b-38's selector fires, by simulating the requesting member's own design
      at that address; a planted false equivalence (a projection that ignores one observable) is detected for
      certain within 64 member hits of one affected node, and within 640 hits spread over an affected class's
      addresses with miss probability at most (63/64)⁶⁴⁰ ≈ 4·10⁻⁵ for a defect that changes every affected hit
      (against 0.36 for 64 such hits on distinct nodes; the number of hits until detection is logged), the latch
      is set, a later attempt to serve
      by digest is `FROB-REF-162`, the campaign's digest classes are split, and the pair is filed.
- [ ] The memo key of the kind is `ExperimentKey` (N17a-26) with the world address and the device family; a
      result stored on one device family is not served on another.
- [ ] The replay test passes on every backend for every fixture family: equal digests give bit-identical
      state digests on the same backend.
- [ ] A result served through the digest is labelled with the structural rule, names its representative, and
      has evidence class at most `Tested`.
- [ ] The campaign report prints designs, representatives, classes and the factor with numerator and
      denominator; the estimate assumes no digest saving.

## Test plan

### Unit tests

`cargo test -p frob-opt --test digest_policy` and `-p frob-conformance --test ballast`:

- `ballast_class_count`: enumerate the 735,471 eight-subsets of 24 slots; distinct (Σx, Σx²) pairs = 24,546.
- `ballast_split_control`: {1, 4} against {2, 3}: Σx 5 and 5, Σx² 17 and 13 → different digests.
- `digest_key_is_derived` (no hand-written key path; compile-fail on constructing the key from bytes).
- `declared_input_perturbation_digest`; `live_dependency_digest_full_model`.
- `projection_without_second_moment_fails_live_dependency`.
- `added_observable_splits_classes`: a mission reading slot 1's occupancy.
- `shadow_selection_one_in_64` (the store's selector on this kind's keys: over 64,000 distinct keys hit once
  each, the selected share is within the exact binomial 99.9% band around 1/64; over 6,400 repeated member hits
  of one class's node at one address, exactly 100 are shadowed, one in every 64 consecutive hits; selection is a
  pure function of the key and the node's durable ordinal);
  `shadow_simulates_requesting_member` (the design simulated is the member that asked, not the representative).
- `key_derivation_property` (every declared input of the kind, the device family among them, perturbs the key);
  `shadow_mismatch_quarantines` (a planted wrong stored result is caught on its sampled shadow recompute, the
  node kind stops serving and the next digest hit answers `FROB-REF-162`).
- `shadow_work_reported`: for the reduced ballast family the shadow episode count is printed beside the
  factor and equals the number of selected hits.
- `false_equivalence_latches_and_splits`.
- `served_result_labelled_and_capped`: class `Certified` on the representative becomes `Tested` on a member
  served by digest.
- `estimate_assumes_factor_one`.

## Considerations

- KILL-QUOTIENT and BET-31's fallback (deduplication by canonical form and content hash only) are decided by
  the quotient's owner; this bead's latch is the same fallback applied automatically when a false
  equivalence is observed.
- Shadowing one hit in 64 costs one sixty-fourth of the episodes of every member served through a class; on a
  real brief where most classes are singletons it costs almost nothing, and where the factor is large it takes
  a visible part of it (30.0 becomes about 20.6 on the ballast fixture) and is reported as such. If that cost
  is judged too high for large classes, the change is a change of the store policy's rate for this node kind,
  recorded in the memo policy's contract, and not a second sampling rule here.
- The coupled-bus control of the quotienting bet (two modules with identical local summaries sharing one
  current-limited bus must not be merged) is a digest question: the bus state is an observable, and the
  live-dependency test over the bus fields is what enforces it.
- A digest saving is "exact reuse" in the reuse ledger's first column, counted once.
