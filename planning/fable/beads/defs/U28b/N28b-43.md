## Background

The program bets that agents design better with structure than with reward alone (BET-10): on the design
benchmark, agents given the full studio surface reach an accepted design in at most half the restricted mean
time of agents given only a simulator and a scalar score, with a one-sided 95% lower bound on the ratio above
1.5. The bet has no kill gate. Its consequence is written in advance instead: the surface is reduced to the
verbs that showed an effect, and the verbs that showed no effect lose their speed claim.

That consequence can only be carried out if something measures which parts of the surface showed an effect.
The surface A/B registers three arms (a minimal arm, the full surface, the full surface plus the one-call
pipeline) and records which verbs the full arm's agents called. Usage is a description; it is not an effect:
a cluster of verbs can be called often and change nothing, or be called once and decide the campaign. Without
a measurement per cluster, a falsified bet would leave the program with a sentence it cannot execute, and a
confirmed bet would leave every verb with a speed claim it did not earn. This bead supplies the measurement:
ablation arms, each the full surface with one task cluster withheld, registered with the main arms before any
data, and a per-cluster table of `effect shown`, `no effect shown` or `not tested`.

Design reasons, with the rejected alternatives:
- *Leave one cluster out, not one verb.* The surface is presented to agents in task clusters of at most seven
  tools; a cluster is the unit an agent sees and the unit a default surface can hide. One arm per verb would
  need an order of magnitude more campaigns than the envelope allows.
- *Ablation from the full arm, not addition to the minimal arm.* Adding one cluster to the minimal arm
  measures the cluster without the verbs it is used with; withholding it from the full arm measures what the
  surface loses without it, which is the question the consequence asks.
- *A registered order instead of all clusters.* Each arm costs as many campaigns as a main arm. The clusters
  are therefore tested in an order fixed before the data, as far as the approved compute reaches, and the rest
  are recorded `not tested`. Rejected: choosing the clusters after seeing which verbs the full arm used in the
  gate run (that is selection on the outcome).
- *"No effect shown" is not "no effect".* The table reports what the experiment could have missed, and makes
  no equivalence claim.

## Scope

In: the definition of an ablation arm as a capability profile; which clusters are eligible; the order in which
they are tested and how it is registered; the pairing and the statistic per cluster; the control of multiple
comparisons; the three labels and the table; the fields this adds to the registration record and to the gate
record; the checks on both.

Out: the registration record, the main arms, equalization, the reachability check and the power statement
(N28b-11, a dependency; this bead adds entries to that record and changes none of its rules); the benchmark,
its briefs, acceptance and clock (N28b-10); running the campaigns and the main verdict of GATE-ATEL-03
(BD-374, which depends on this bead and launches the ablation arms in the same keyed order as the main arms);
the bet's verdict and the reduction of the default surface it implies (the decision bead of BET-10); the
one-call pipeline's own question (BD-372).

## Technical approach

1. **An ablation arm (DESIGN).** Profile `ab-full-minus-<cluster>` in `registries/profiles/`: the profile of
   the full arm with one task cluster's tools withheld, that is, every tool of the cluster except the minimal
   arm's five verbs and the three base tools (step 2), including a tool the cluster shares with another task
   cluster (a verb may sit in several, §32.12.4). Reason for withholding shared tools: an agent that switched
   focus to the other cluster would otherwise still reach them, and the arm would test less than the cluster.
   The withholding is enforced by the agent proxy as N28b-11 configures it for a profile: the tools are not
   listed and a call to one is not forwarded, whatever the agent was told. The token's scopes stay the full
   arm's, because scopes are granted per registry cluster and removing one would also withhold tools of
   other task clusters. The generated agent guide for the arm is built from the registry restricted to the
   remaining tools.
   Everything else is the full arm's: brief card, budgets, deadline, device class, warm state, agent model.
2. **Eligible clusters.** A cluster is eligible when the benchmark's briefs stay solvable without it. The base
   tools of the minimal arm (create, show and edit a design; run a simulation; submit for qualification; the
   job and session tools) are never withheld. For every other cluster the registration-time check runs the
   reference solution path of each development brief with the cluster's tools refused; a cluster on which a
   brief becomes unsolvable is recorded `not-testable` with the brief and the tool that was needed, and is not
   counted as having an effect or as lacking one.
3. **The registered order and the count.** From the dry run of the protocol (all arms on the four development
   briefs), eligible clusters are ordered by the number of calls the full arm made to them, most used first,
   ties by cluster name. The registration states that order, the number K of ablation arms the approved
   compute allows, and that clusters beyond K are `not tested`. K, the order and the profile hashes are part
   of the registration hash; the harness refuses a run whose ablation arms differ from it.
4. **Pairing.** An ablation arm runs on the same sealed briefs, with the same number of campaigns per brief,
   as the full arm. Pair i of cluster g is (full arm, ablated arm) on the same brief and campaign index; the
   campaigns of all arms, main and ablation, are launched in the registration's one keyed and balanced order
   (N28b-11, step 4), so no arm is systematically later. The clock, the acceptance rule and the censoring at the deadline H are the
   benchmark's.
5. **Statistic per cluster.** The quantity is the ratio of restricted mean times to an accepted answer,
   ablated ÷ full, over the paired campaigns, with its one-sided 95% lower confidence bound from the paired
   lower-bound routine (ten pairs of constant ratio ρ must return the bound ρ; ρ, because r is the registration's
count of campaigns per brief, N28b-11). Cluster g's e-process is the
   betting e-process of the main statistic as N28b-11 registers it (BD-124's anytime e-process on a declared
   span; BD-374, which depends on this bead, runs the same rule on the main arms), at c = 1 on pairs
   (ablated, full): with a_j = min(T_ablated,j, H)
   and f_j = min(T_full,j, H), the observation is (a_j − f_j)/(2H) ∈ [−½, ½], its span declared in the
   registration, consumed in registered pair order; the null is "withholding the cluster does not lengthen the
   restricted mean time" (E[a − f] ≤ 0). A second lower bound at the level corrected for the number of clusters
   tested is computed by the e-value form of the Benjamini–Hochberg procedure over the K paired e-processes
   (the rule the studio uses for comparisons of several designs), at α = 0.05: with the e-values sorted in
   decreasing order, the k-th largest is compared with K/(α·k), and the largest k that passes fixes how many
   clusters are rejected (those with the k largest e-values).
6. **Labels.**
   - `effect shown`: the cluster's e-value is rejected by the corrected procedure, that is, withholding the
     cluster makes agents slower with the multiplicity of K clusters accounted for.
   - `no effect shown`: tested and not rejected. The row carries the upper end of the two-sided 90% interval
     of the ratio, so a reader sees how large an effect the experiment could have missed.
   - `not tested`: beyond K, or `not-testable`.
7. **The table (`frob.surface-ablation/1`, in the gate record of GATE-ATEL-03).** Per cluster: the label, the
   ratio with both bounds, the number of pairs, censored shares in each arm, the full arm's call count to the
   cluster (a description), and the profile hash. The table also lists, per verb of the registry, the task
   clusters it sits in (one or more), so that "the verbs that showed an effect" is a query and not a reading:
   a verb showed an effect when at least one cluster it sits in is labelled `effect shown`, because
   withholding that cluster withheld the verb.
8. **What the table licenses.** Nothing by itself. The decision bead of BET-10 reads it: if the bet is
   falsified, the default visible clusters shrink to those labelled `effect shown`; whatever the verdict, a
   verb none of whose clusters is labelled `effect shown` carries no speed claim. No verb is removed
   from the registry by this table; clusters stay callable.
9. **Controls.** Potency: a planted arm that withholds a cluster the reference path of every development
   brief needs after its first step (so the arm must be slower) must be labelled `effect shown` in the dry
   run. A/A: the full arm against itself must not be labelled `effect shown`.
10. **Layout.** Profiles under `registries/profiles/ab-full-minus-*.toml`; analysis in
    `crates/frob-conformance/src/experiments/surface_ablation.rs`; the table beside the gate record.

## Acceptance criteria

- [ ] The registration record lists the eligible clusters, the `not-testable` ones with their reasons, the
      order, K and every ablation profile hash, and its hash precedes the first campaign in the ledger.
- [ ] A session behind the proxy under an ablation profile does not list the withheld tools (shared ones
      included), a call to one is not forwarded (absent from the daemon's transcript), and every other tool of
      the full arm is listed.
- [ ] A run whose ablation arms differ from the registration in order, count or profile is refused, with the
      differing field named.
- [ ] Every cluster of the full arm's surface appears in the table with exactly one of the three labels;
      every verb of the registry maps to the rows of the clusters it sits in.
- [ ] The potency arm is labelled `effect shown` and the A/A arm is not.
- [ ] The corrected procedure is the one registered. With K = 5 and α = 0.05 the k-th largest e-value is
      compared with K/(α·k) = 100, 50, 33.3, 25, 20 and the largest k that passes fixes the number rejected:
      the e-values (40, 25, 3, 1, 0.5) reject none; (120, 60, 3, 1, 0.5) reject exactly two; (60, 55, 40, 1,
      0.5) reject exactly three, although the largest alone is below 100.
- [ ] With no approved compute beyond the default envelope, K = 0 is a valid registration: every cluster is
      `not tested` and the table says so.

## Test plan

### Unit tests

`cargo test -p frob-conformance --test surface_ablation`:
- `profile_removes_only_one_cluster`: the withheld tool set of an ablation profile is the cluster's tools
  minus the minimal arm's five verbs and the three base tools, shared tools included; the scopes and every
  other field equal the full arm's.
- `eligibility_marks_unsolvable_brief`: a `synthetic` brief whose reference path needs a tool of cluster X
  makes X `not-testable` and names the tool.
- `order_is_by_dry_run_calls_then_name`.
- `e_bh_fixtures`: the three fixtures of the acceptance list (none, exactly two, exactly three rejected).
- `labels_are_exhaustive`: every cluster gets exactly one label; a cluster beyond K is `not tested`.
- `no_effect_row_carries_upper_end`.
- `registration_mismatch_refused`: a changed order, a changed K and a changed profile hash are each refused.
- `table_maps_every_verb_to_its_clusters`: a verb in two clusters, one labelled `effect shown`, is listed
  under both and counts as having shown an effect.

### End-to-end script and logging

`scripts/e2e/surface_ablation.sh` sources the shared helper of STD-E2E and runs at dry-run scale on the
development briefs with scripted (`synthetic`) agents whose time to acceptance is a seeded function of the
tools they are allowed, so that the true effect of each cluster is known: for each ablation profile it opens a
session with `frob session open --scopes <the full arm's scopes> --budget … --key abl-<cluster> --json` behind
the agent proxy configured from the profile, checks that the withheld tools are not listed and that a call to
one is not forwarded, registers
the experiment, runs the full arm, K = 3 ablation arms, the potency arm and the A/A arm through the real
harness, computes the table and compares each label with the planted truth. Log
`target/e2e-logs/surface_ablation/<utc-timestamp>.ndjson` and a transcript: `ts`, `script`, `bead`, `step`,
`event`, the exact command line, exit code, wall time, the envelope's `evidence` block, per cluster the ratio
with its bounds, the e-value against its threshold, pairs and censored shares, the label against the planted
truth, the registration hash, and on failure the first cluster whose label differs with the artifact paths.
A final `summary` line gives assertions passed and failed and names GATE-ATEL-03. No private-scene data.

### Known answers and negative controls

- Known answers: the e-value fixtures; ten pairs of constant ratio 1.3 return the lower bound 1.3.
- Negative controls: the A/A arm (must not be `effect shown`); a table built from call counts instead of
  paired times (a planted analysis mutant, caught because a much-called cluster with no planted effect would
  be labelled `effect shown`); an ablation arm launched after all main-arm campaigns (rejected by the
  launch-order check); a cluster chosen for testing after the gate run (rejected by the registration hash).
- Determinism: the analysis is a pure function of the recorded times and the registration; real agents'
  sessions are recorded, not regenerated.

## Considerations

- Compute. Each ablation arm is a set of campaigns of class E2, like a main arm. OPEN (owner): the number of
  ablation arms approved. Fail-closed default: K = 0, every cluster `not tested`; the bet's decision record
  then states that a reduction of the surface is not supported by an effect measurement, and usage is printed
  beside it as a description.
- Power is low for a single cluster by construction: one cluster's effect is a fraction of the whole
  surface's. The upper end printed on a `no effect shown` row is what keeps that label honest.
- Clusters interact: a cluster with no effect alone may matter in combination. The table is about single
  clusters and says so; pairs of clusters are not tested.
- Agents can get lost in a large surface, so withholding a cluster may make an arm faster. A ratio whose
  upper bound is below 1 is reported as such in the row; it is `no effect shown` for the purpose of the speed
  claim and is flagged for the surface owner.
- The agent model is the registered one; a re-run with another model is a new registration.
