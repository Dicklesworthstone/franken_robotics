## Background

Two decision cores of the design studio sit on the platform plane and decide things that change bits. DC-08
decides which solver effort profile a run uses (family: risk-controlled profiles; owner `frob-dyn`; timescale at
ledger refresh; Frontier). DC-11 decides whether a kernel rewrite is accepted (family: certified rewrites; owner
`frob-kir` and `derive/frob-derive`; timescale at build; Solid for the exact class, Frontier for the real class).
A decision core is a compiled decision rule with a table, a loss model, obligations, a deterministic fallback and a
budgeted mode, registered under `registries/cores/`. Gate GATE-ATEL-13 requires that each core's table regenerates
bit-identically, its null calibration holds, its fallback is demonstrated by forcing each trigger, and its shadow
run records both actions. This bead measures the M4 rows for DC-08 and DC-11, and discharges proof obligation
PO-ATEL-10 (the risk bound of DC-08 holds for the monotonized loss) by simulation.

Why these two are dangerous: an effort profile that reacted to load, or a rewrite that silently changed one bit,
would change every digest downstream, and with them replay, both ledgers and every pairing. The loss models say
so: for DC-08, an under-converged result that passes as evidence against wasted iterations; for DC-11, a silent
bit change that invalidates replay and both ledgers against a skipped rewrite that costs a few per cent of speed.

Rejected for these cores: feedback control (PID or model-predictive) on solver effort (wall-clock feedback into
iteration counts makes results depend on load and breaks replay; a guard table with hysteresis passes); Lyapunov
and bifurcation analysis of solver effort (the residual monitor covers it); e-graph saturation with a solver over
real-arithmetic rewrites (every accepted rewrite changes bits, so each needs an error bound, a battery run and a
new kernel identity, while most step time is expected in the solve); stochastic superoptimization and
counterexample-guided synthesis of kernels (no sound equivalence check exists for floating-point code).

## Technical approach

**DC-08 record, as tested.**
- Artifacts: declared effort profiles (iteration counts, tolerances, substeps), each its own model identity,
  ordered from cheapest to dearest; a guard table that holds, per stratum, the cheapest profile whose risk bound
  (n·R̂ + 1)/(n + 1) is at most τ on the fidelity battery, where n is the number of battery points in the stratum
  and R̂ the mean of a loss in [0, 1] (1 when the profile's result at that point falls outside the frozen
  envelope against the reference, else 0; DESIGN for the loss definition); a rule that re-runs unconverged worlds
  one profile up, flagged. If the chosen profile misses the throughput budget, the run shrinks its world count or
  is refused; the profile does not move.
- Obligations: a monotone loss, enforced by taking the running maximum over higher profiles (for each battery
  world w, the monotonized loss at profile j is the maximum of that world's raw losses over profiles j and
  dearer, so that for every world more effort never appears worse than less; R̂ⱼ is the mean of the monotonized
  losses); expected loss at most τ for worlds exchangeable with the battery; the profile never reads the wall
  clock and never changes inside a run; the table changes only at a ledger refresh.
- Fallback: the default profile of the dynamics subsystem. Triggers, with the names the selector of the
  dynamics subsystem (N28a-34) records: `under-19-battery-points` (at τ = 0.05 and R̂ = 0 the bound
  (n·0 + 1)/(n + 1) ≤ 0.05 needs n ≥ 19; the same arithmetic as the conformal floor); `identity-change` (the
  profile registry digest, kernel versions or battery version differ from those the table was built for);
  `no-row` (the stratum has no row: the selector's fail-closed addition, same fallback). A missing, stale or
  non-registry table also puts the default profile in force, with `FROB-REF-871` in the run's `warnings`.
- Budgeted mode: at most one step up per world per run.

**DC-11 record, as tested.**
- Artifacts: a closed rule table. Class E is bit-exact under round-to-nearest with contraction off: commutation,
  common-subexpression elimination, dead-code elimination, scaling by a power of two away from overflow and
  underflow, and scheduling. Class R is equal over the reals only: reassociation, distribution, fused
  multiply-add. A certificate is (source hash, target hash, rule trace), replayed by an independent checker: the
  checker for proof kind `rewrite-trace` of `frob-cert` (N12p2-02, a dependency), which replays each class-E rule
  of the trace on its own and shares no code with the rewriter.
- Obligations: each class-E rule is shown exact once on its domain, and digests match on a pinned corpus on every
  backend; a class-R rewrite needs a polynomial-identity certificate, an error bound, the fidelity battery and a
  new kernel version; a new version is a new identity and resets evidence.
- Fallback: the unrewritten derived kernel. Triggers: `digest-mismatch`; `whole-step-gain-under-3-percent`.
- Budgeted mode: 60 s of search per kernel; one class-R candidate per release.
- Known answer. In `f32` with a = 10⁸, b = −10⁸, c = 1: (a + b) + c = 1 and a + (b + c) = 0, because the spacing of
  `f32` near x is 2^(⌊log₂ x⌋ − 23), which is 8 near 10⁸. Sharing a subexpression used three times saves two
  evaluations and changes no bit. Regrouping makes a different kernel, which must be named as one.
- Ceiling (FACT to re-read before citing): the Lie-algebraic recursions are about 16 to 20% of an incumbent's
  step, so specializing them is worth about 1.2 times at most. Class R and any wider search are worth their
  certificates only if the project's own M2 profile shows more than about a fifth of step time in derived
  arithmetic.

**The four clauses, as tests.**
1. *Regeneration.* DC-08: the guard table from a committed battery-result fixture (per stratum: n, the raw loss
   per profile, the monotonized loss, the chosen profile) with the rule in exact rationals:
   choose the cheapest j with (n·R̂ⱼ + 1) ≤ τ·(n + 1). DC-11: the closed rule table (rule name, class,
   precondition, domain restriction). Both under `xtask check-generated`.
2. *Null calibration.* DC-08 (PO-ATEL-10): simulate 10⁴ battery draws of n = 39 exchangeable worlds from a
   population in which three profiles have true risks (0.20, 0.06, 0.004), with losses monotone per world, and
   τ = 0.05; choose the profile by the table on each draw (the default profile when none qualifies); evaluate on a
   fresh exchangeable world; assert the mean loss of the chosen profile over draws is at most τ = 0.05 (within the
   binomial acceptance bound). Repeat on the planted under-converged ladder: ten profiles with true raw risks
   0.20, then eight profiles at 0.08, then 0.004, with failures independent across profiles for each world, so
   that raw losses are not monotone per world. With monotonization the mean loss of the chosen profile stays at
   most 0.05 (about 0.016 expected: the ninth profile is chosen in about 15% of draws). Without monotonization
   (the planted defect: the cheapest profile whose raw bound passes) a 0.08 profile passes by chance in about 78%
   of draws, the mean loss is about 0.063, and the test must report the bound exceeded.
   DC-11: every class-E rule applied 10⁴ times to random straight-line `f32` and `f64` programs inside its domain
   leaves all outputs bit-identical on `batch-cpu`; each class-R rule produces at least one bit difference on the
   same corpus (so the classification has teeth in both directions).
3. *Forced fallbacks.* DC-08: a stratum with 18 battery points; an effort-profile identity change after the
   table was built; a stratum key with no row. DC-11: a rewrite whose digests differ on one world of the pinned corpus; a certified class-E
   rewrite whose measured whole-step gain is 2%. Each yields the fallback (default profile; unrewritten kernel)
   and a record naming the trigger.
4. *Shadow records.* DC-08 in shadow: runs use the default profile, and each run's record holds the profile the
   table would have chosen. DC-11 in shadow: the build emits the unrewritten kernel and records the rewrite it
   would have accepted with its certificate hash.

**Budgeted-mode and purity checks.** A world that fails to converge is re-run one profile up and flagged; a world
that fails again is reported unconverged, not stepped up twice. A run whose chosen profile misses the throughput
budget shrinks its world count or is refused; its profile identity is unchanged. The profile selector's context
type exposes no clock (the purity guard shared by all cores). A rewrite search stops at 60 s and returns the best
certified class-E result so far; a second class-R candidate in one release is refused.

## Acceptance criteria

- [ ] Artifacts of both cores regenerate bit-identically on both hosts.
- [ ] DC-08 floor: n = 19 with zero losses is admitted at τ = 0.05 ((0 + 1)/20 = 0.05); n = 18 is not and forces
      the default profile.
- [ ] PO-ATEL-10: mean loss of the chosen profile at most 0.05 over 10⁴ draws, measured value recorded; with the
      planted non-monotone profile the monotonized rule still holds the bound, and the un-monotonized planted
      defect is caught (bound exceeded).
- [ ] DC-08 never changes profile inside a run and never reads a clock: identical profile identity and digests for
      a run under an idle and a saturated queue.
- [ ] DC-11 known answer: the `f32` example evaluates to 1 and 0 for the two groupings; common-subexpression
      sharing leaves 1,000 of 1,000 corpus digests unchanged.
- [ ] Every class-E rule is bit-exact on its domain over 10⁴ random programs; the power-of-two scaling rule is
      refused outside its domain (a scale that underflows to a subnormal).
- [ ] A reassociation submitted as class E is rejected by the independent checker replaying the rule trace.
- [ ] A class-R rewrite without all four of: polynomial-identity certificate, error bound, fidelity-battery run,
      new kernel version, is refused; with them it yields a new kernel identity and the affected ledger rows are
      reset.
- [ ] The five forced triggers (three of DC-08, two of DC-11) give the fallback and a record naming the trigger;
      shadow records exist for 100% of decisions.
- [ ] The four clauses for DC-08 and DC-11 are registered as entries under GATE-ATEL-13 in the tier target
      `g1_known_answers` (the gate record's `tier`), with the negative controls below behind
      `gauntlet-mutations`; `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g1_known_answers
      --features gauntlet-mutations -- GATE-ATEL-13` passes with their measured values (PO-ATEL-10's mean loss
      among them) in the receipt and every control `caught`. This bead writes no gate row: the M4 part has one
      recorder, N28cp3-01. On calibration failure after one repair cycle DC-08 is set to `fallback-only`.

run before and after the class-E rewrite; the five forced-trigger runs; shadow builds. Log:
`target/e2e-logs/decision_cores_m4/<utc>.ndjson` with a transcript; every line has `ts`, `script`, `bead`

### Known answers and negative controls

- KA-705: the `f32` regrouping example gives 1 and 0 (exact). The floor n ≥ 19 at τ = 0.05.
- Negative controls that must fail: a reassociation admitted in class E; a profile selector that lowers effort
  when the queue is long; a guard table without monotonization on the non-monotone fixture; a class-R rewrite
  shipped under the old kernel version; a rewrite accepted with fused multiply-add contraction enabled.
- Metamorphic relations: applying a class-E rewrite and then its inverse returns the source hash; permuting
  battery points leaves the chosen profile unchanged.
- Determinism lanes: twice on one machine; debug and release; `batch-cpu`, CUDA and Metal each against its class
  for the pinned corpus digests (class-E rewrites must keep digests on every backend).

## Considerations

- DC-08's risk bound is an average over battery draws for worlds exchangeable with the battery; a campaign whose
  worlds drift from the battery is the dynamics subsystem's alarm to raise, and the fallback is the default
  profile.
- The 3% gain threshold and the 60 s search budget are DESIGN defaults recorded in the record; changing either is
  a new version of the decision policy.
- KILL-KIR (owned by the kernel toolchain) decides whether rewrite rules are consumed at all; if it fires, DC-11's
  record is `fallback-only` and this bead's DC-11 tests reduce to the rule table and the negative controls.
- The profile condition that would reopen wider rewrite search is read from the M2 profile and recorded in the
  rejected-methods register.
