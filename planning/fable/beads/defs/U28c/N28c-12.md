## Background

The design studio computes two kinds of number about a design. A verdict statistic (an e-value, a confidence
sequence, exact discordant-pair counts with their intervals, a failure-rate bound) is produced by a
distribution-free procedure whose error rate is controlled, and may become `established`. An advisory quantity is
produced by a parametric model that only steers effort: the expected value of sample information of an experiment,
an expected opportunity loss, a value-per-cost ratio, a knowledge-gradient score, the extrapolated controller
ceiling J∞ of a design and its saturation index, the predicted outcome interval of a suggested experiment, the
saving a race or a ladder expects. ADR-ATEL-07 draws the line: parametric models rank experiments;
distribution-free tests issue verdicts. The value-of-information model never issues a verdict, so a wrong model
costs efficiency and never validity.

That sentence is only true if an advisory number cannot reach a place where it is read as a verdict. The plan
states it as an invariant and a refusal:

- INV-ATEL-12: a value-of-information quantity never appears in a verdict field.
- `FROB-REF-872`: a value-of-information output cited as a verdict. Ranked repair: run the comparison.

The same invariant binds the controller-budget curve estimate: J∞ is `Estimated`, steers allocation, and never
enters a verdict field; only the measured contrast at the highest budget reached can become `established`.

This bead builds the wall in the type system and at the surface, so that the invariant holds by construction and
not by review. Rejected alternatives: a naming convention (`*_advisory` fields; not enforced); a run-time scan of
verdict records for suspicious numbers (cannot tell a number's origin). Tier: Solid [S]. It is needed at M3 by the
budget-curve estimate and at M4 by experiment suggestion.

## Scope

In: the `Advisory<T>` type and its rules; the envelope placement of advisory values; the result-kind tag on
identifiers; the refusal `FROB-REF-872` at every verb that accepts a verdict or result reference; compile-fail and
schema tests.
Out: computing any advisory quantity (the value-of-information core, the suggestion ranking, the budget-curve
fit); the verdict record itself; the claim-product type (already in `frob-core`).

## Technical approach

1. **Type (DESIGN), in `frob-core::advisory`.**
   ```rust
   /// A number that steers effort and can never be evidence for a verdict.
   pub struct Advisory<T> { value: T, model: AdvisoryModel, interval: Option<(T, T)>, basis: Vec<InputRef> }
   pub enum AdvisoryModel { ValueOfInformation, KnowledgeGradient, OpportunityLoss,
                            BudgetCurveCeiling, SaturationIndex, PredictedOutcome, ExpectedSaving, CostEstimate }
   ```
   Rules, each pinned by a compile-fail test:
   - no `From<Advisory<T>>` or `Into` for any type that appears in `frob.verdict/1`
     (`VerdictStatistic`, `EValue`, `ConfidenceSequence`, `ExactCounts`, `RateBound`, `Evidence<K>`);
   - no public accessor returns the bare `T` outside the crates `frob-opt` (allocation code) and `frob-verbs`
     (serialization); elsewhere the value is readable only through `Advisory::display()` for printing;
   - arithmetic on `Advisory<T>` yields `Advisory<T>` (the taint propagates);
   - `Advisory<T>` does not implement the trait `VerdictInput` that the verdict writer requires of every input.
2. **Evidence class.** An advisory value is always class `Estimated` and carries `claims: []`; a claim product
   built with an advisory input is refused by `ClaimProduct::combine` (the advisory value is not an `InputRef`
   of evidence kind; it has its own `basis` list for traceability).
3. **Envelope placement.** In `frob.envelope/1` results, advisory values are serialized only under a key named
   `advisory` (an object) or inside `next_actions`; the generated output schemas of verbs mark those subtrees with
   `"x-frob-advisory": true`. The schema generator fails if a field of type `Advisory<_>` is placed elsewhere, and
   fails if a field under a verdict subtree (`verdict`, `statistic`, `pairs`, `bound`) has an advisory type.
4. **Result kinds on identifiers.** Stored results carry a kind in their identifier's record: `verdict`,
   `estimate`, `analysis`, `advisory`. A suggestion list, a value-of-information table, a budget-curve fit and a
   registered predicted interval are stored with kind `advisory`.
5. **The refusal.** Every verb parameter declared in the verb registry as accepting a verdict or an establishable
   result (`eval.promote <result>`, `eval.qualify`, `report.design` statements, `result.revalidate <verdict>`,
   `foundry.export` inputs, `evidence.trace` when asked for a claim's deciding statistic, and the `--cite`
   option of report verbs) checks the kind. Given an `advisory` identifier it refuses with `FROB-REF-872`: exit 3;
   `message`: "A value-of-information output was cited as a verdict"; `pointer`: the parameter; `observed`: the
   identifier and its `AdvisoryModel`; `required`: a verdict from a declared study; `retry`: `after-change`;
   `repairs` (ranked): 1. run the comparison (`frob eval compare A B --task T`), with the command pre-filled from
   the advisory value's `basis` when it names two designs and a task; 2. if only a ranking for allocation is
   wanted, read the `advisory` block and do not cite it.
6. **Verdict writer guard.** `VerdictRecord::new` takes only `VerdictInput` values; in addition a debug-and-release
   assertion checks that no evidence identifier in the verdict's provenance closure has kind `advisory` as a
   *supporting* edge (an advisory value may appear on a `decided-by` path only as part of a decision record that
   chose which experiment to run, never as support for the statement).
7. **Reports.** A report prints advisory values in a section titled as advisory, each with its model name, and
   never in a statement that carries a claim type.

Determinism: not applicable (types and checks). The refusal path is class D0.

## Acceptance criteria

- [ ] `Advisory<T>` exists in `frob-core` with the four type rules, each covered by a compile-fail test that
      attempts the forbidden use.
- [ ] `ClaimProduct::combine` refuses an advisory input.
- [ ] The schema generator fails on a planted verb output that places an advisory field under `verdict`, and on a
      planted advisory field outside an `advisory` subtree.
- [ ] `frob eval promote <advisory-id> --json` and each other listed verb form exits 3 with `FROB-REF-872` and the
      ranked repairs; the planted violation fires 100 of 100 times across the listed verbs and identifier forms.
- [ ] A property test over 10⁴ random campaigns (suggestions interleaved with comparisons) finds no advisory value
      in any `frob.verdict/1` record (INV-ATEL-12).
- [ ] Arithmetic taint: `Advisory<f64> + f64`, `min`, `max` and scaling all return `Advisory<f64>`.
- [ ] The `advisory` subtree of every verb that emits one carries the model name and the `basis` identifiers.
- [ ] `CONTRACT.md` of `frob-core` lists the invariant and the refusal.

## Test plan

### Unit tests

`crates/frob-core/tests/advisory.rs` and `crates/frob-core/tests/compile_fail/`:
- `advisory_into_evalue.rs`, `advisory_into_verdict_statistic.rs`, `advisory_as_verdict_input.rs`,
  `advisory_bare_value_outside_opt.rs`: each must fail to compile with the expected error.
- `taint_propagates`: (0.0013 advisory) / (1.0 plain) is advisory.
- `combine_refuses_advisory`.
- `always_estimated_no_claims`.
`crates/frob-verbs/tests/advisory_surface.rs`:
- `schema_generator_rejects_advisory_in_verdict_subtree`;
- `schema_generator_rejects_stray_advisory_field`;
- `citing_advisory_is_872` for each verb parameter in the list (table-driven; expected exit 3, code
  `FROB-REF-872`, first repair "run the comparison");
- `repair_command_prefilled`: an advisory value whose basis names designs `d:a`, `d:b` and task `t:x` yields the
  repair command `frob eval compare d:a d:b --task t:x`.
- `verdict_provenance_has_no_advisory_support`.

### End-to-end script and logging

Exercised by `scripts/e2e/experiment_suggest.sh` and `scripts/e2e/budget_curve.sh`: each obtains an advisory
identifier from the real verb and then attempts to cite it (`frob eval promote <id>`, `frob report design
--cite <id>`); the scripts assert exit 3 and `FROB-REF-872`, and log a `refusal` line with code, pointer, observed
model name and repairs. The refusal battery script repeats the planted violation 100 times.

### Known answers and negative controls

- Negative controls (registered): a build in which `Advisory` implements `VerdictInput` (the property test must
  find an advisory value in a verdict); a verb output schema with an expected-value field inside `statistic`; a
  report template that prints J∞ in a statement with claim type "Design comparison".
- Property test for INV-ATEL-12 as in the acceptance criteria.
- Determinism lanes: the refusal envelope is byte-identical twice on one machine and across hosts.

## Considerations

- The wall must not make advisory values hard to use for their purpose: allocation code in `frob-opt` reads them
  freely; what is blocked is conversion into evidence.
- Cost estimates from `sim.estimate` are advisory in the same sense (they are predictions with intervals) but are
  owned by the performance work; this bead provides the type and leaves adoption there as a follow-up.
- If a future procedure makes a model-based quantity carry a controlled error rate, it gets a new verdict
  statistic type with its own obligation; it does not get an exemption from this wall.
