## Background

`frob experiment suggest <designs or answer> --budget …` returns a ranked list of information-gathering proposals,
each with a testable prediction: more pairs at a rung, a referee batch, a fine-tune, a probe on a bench, a
measurement of a card field, a cell of a mission answer to split. It is advisory. It never decides validity
(ADR-ATEL-07: parametric models rank experiments; distribution-free tests issue verdicts). The verb is registered
once, by the mission-query subsystem, which owns it; the design studio (Atelier) is a consumer and specifies the
ranking by decision value. Two kill gates bear on it and do not overlap: KILL-AUGUR-PROBE governs the probe
generator, and KILL-VOI governs the ranking.

The ranking of simulation proposals by value of information is the seed bead for experiment suggestion (BD-351).
This bead carries what the studio requires of *measurement* proposals, where the danger is different. A
measurement is tempting to choose by what it tells you about a parameter. The plan's rule is to choose it by what
it can change in the design decision:

- **Partition by decision, not by parameter.** For a measurement, the compatible physical mechanisms are
  partitioned by the design decision they imply; the cheapest realizable intervention whose possible readings
  separate incompatible decisions is proposed; where observation sets still overlap, two witness mechanisms with
  opposing design margins are returned; when all mechanisms imply the same choice, identification is skipped. The
  identifiability analysis A-25 checks that the proposed excitation can identify what it claims to.
- **Measuring the target directly is always on the list.** Counterexample (CX-317; FACT from an executed planning
  pilot, re-run in the repository before a gate cites it): a short probe synthesized for three admitted material
  laws chose the right gripper pad in 675 of 675 in-class cases; a fourth, delayed law followed the same early
  trace and reversed all 225 held-out decisions; measuring the candidate pad at mission dwell was right in 900 of
  900. An in-class-perfect probe cannot expose structural error, so every suggestion states its model class and
  lists the direct measurement as a comparator with its cost.

Tier: Frontier [F] for probe proposals (their pilot is the material-probe pilot re-run, and their kill gate is
KILL-AUGUR-PROBE); the comparator rule and the model-class statement are Solid and survive every kill branch.
Rejected alternative: ranking measurements by expected information gain about parameters (it buys knowledge that
cannot change the choice).

## Scope

In: the proposal record `frob.proposal/1`, the one record of `experiment.suggest` in both crates (the simulation
kinds that BD-351 ranks, and the measurement and cell kinds that the Augur side builds); the studio's rules for
measurement proposals, enforced as an admission check on a proposal list before it is ranked: the decision
partition present or the skip note, the model-class statement, the mandatory direct-measurement comparator, the
A-25 gate on each excitation with its replacement, the two-witness payload of a partial proposal, a discrepancy
passed through as a note; how measurement proposals enter the ranked list beside simulation proposals; the
output block.

Out: generating the proposals. Reading the unresolved cells of an answer or a set of competing designs, calling
the partition machinery of `mission.distinguish` (BD-291) for the blocks, the cheapest separating intervention,
the witnesses and the discrepancy, attaching a prediction per mechanism, a cost and the runnable command,
dropping what cannot change the decision and adding the direct measurement are the Augur side of the verb,
N25c-18 in `frob-mission`, which depends on this bead and fills this record. `frob-opt` is a lower layer than
`frob-mission` and cannot call it, so no partition algorithm is implemented in this crate. Also out: the
value-of-information arithmetic and the STOP rule (BD-351; the DC-05 table); the partition algorithm and
experiment grammar themselves (BD-291); A-25, the identifiability analysis and its verb `analyze.identifiability` (N28a-13); registering predictions (N28c-14); the verb's registry
entry and surface (N25c-18).

## Technical approach

Module `crates/frob-opt/src/suggest/measure.rs`, behind the feature `frontier-suggest` (off by default).

1. **Proposal record (DESIGN), schema `frob.proposal/1`.**
   ```rust
   pub struct Proposal {
       id: ProposalId,
       kind: ProposalKind,           // simulation: MorePairs { rung, n } | RefereeBatch { n } | FineTune { fraction }
                                     // measurement: BenchProbe { experiment } | CardField { card, field }
                                     //              | DirectMeasurement { target, conditions }
                                     // cell: SplitCell { answer, cell } | RerunHigherTier { answer, cell, tier }
       target: Option<CellRef>,      // the unresolved cell or the design the proposal is about
       command: String,              // the exact command that would run it
       relevance: Relevance,         // ChangesDecision { between: (DecisionRef, DecisionRef) }; never None in a list
       cost: Cost,                   // GPU-second equivalents at the declared exchange rate, plus declared real cost
       reduces: VarianceComponent,   // Numerical | Statistical | Model
       value: Advisory<f64>,         // reduction in expected opportunity loss of the current choice
       value_per_cost: Advisory<f64>,
       prediction: PredictionRef,    // the registered outcome interval, per mechanism where mechanisms differ
       model_class: ModelClass,      // the set of admitted mechanisms the proposal is conditional on
       comparator: Option<ProposalId>,   // the direct measurement, for every measurement proposal
       identifiability: Option<A25Result>,
       decision_partition: Option<Partition>,   // blocks of mechanisms by implied design decision
       partial: Option<WitnessPair>, // two witness mechanisms with opposing margins, on a proposal that cannot separate
   }
   ```
   `value` and `value_per_cost` are advisory quantities and cannot enter a verdict field. One record (DESIGN, the
   same statement in N25c-18): the Augur side first sketched a record of its own with four kinds (`probe`,
   `measure`, `rerun-higher-tier`, `split-cell`) and the fields `target`, `relevance`, `condition` and `command`.
   The ranking is in this crate, which is a lower layer than `frob-mission`, so the record lives here and that
   bead fills it: `probe` is `BenchProbe`; `measure` is `CardField` for a card field marked `assumed` and
   `DirectMeasurement` for the target at mission conditions; `split-cell` is `SplitCell`; `rerun-higher-tier` is
   `RerunHigherTier`, added to the kinds for it; `condition` is `model_class`; `target`, `relevance` and `command`
   are fields above; its per-mechanism predictions are the content `prediction` refers to.
2. **What a measurement proposal must contain when it arrives.** The proposals are assembled by the Augur side
   (N25c-18) from the partition that `mission.distinguish` computes (BD-291), with these inputs: the pending
   decision (which of the candidate designs or cells is chosen), the set ℳ of mechanisms compatible with archived
   observations and their uncertainty, the realizable interventions with costs (fixture compliance, pad radius,
   sensor position, command waveform, exposure time, preload), the admitted nuisance intervals and the reading
   error bound. This crate holds the contract and checks it on every list before ranking
   (`admit_measurement_proposals`; a violation is a programming error of the producer, tested, never a result):
   1. A measurement proposal carries `decision_partition`: ℳ partitioned by the design decision each mechanism
      implies.
   2. If there is one block, the list holds no identification proposal for it, and the note `skipped: all
      mechanisms imply the same choice` is in the answer's notes. An identification proposal over a one-block
      partition is refused.
   3. Otherwise the proposal is the cheapest intervention whose sets of possible readings, over the nuisance
      intervals and the reading error, are disjoint closed sets for every pair of mechanisms in different blocks.
      It is a `BenchProbe` or a `CardField` and carries, per block, the predicted reading interval and the
      decision that reading implies (the measurement contract). The check recomputes disjointness from the
      intervals in the record.
   4. If no intervention separates all blocks, the proposal is a `BenchProbe` with `partial` set: two witness
      mechanisms from different blocks whose reading sets overlap, with their opposing design margins, so the
      agent sees which two worlds it cannot yet tell apart. A `partial` whose margins have the same sign is
      refused.
   5. If the observations fit no admitted mechanism, a discrepancy note arrives and no proposal is fabricated
      for it; the nearest mechanism is never picked.
3. **The A-25 gate.** Each measurement proposal is passed to the identifiability analysis with its excitation; the
   proposal is kept only if the sensitivity of the predicted readings to the quantity it claims to resolve is
   non-zero over the excitation and every regime of a switching law it relies on is covered. A proposal that
   fails is replaced by A-25's suggested excitation (for example "an excitation in the traction-limited regime")
   or dropped with the reason.
4. **The direct-measurement comparator (mandatory).** For every measurement proposal the list also contains a
   `DirectMeasurement` proposal: measure the target itself at mission conditions (the candidate part at mission
   dwell, speed and load), with its cost. The probe's `comparator` field names it. The list is refused internally
   (a programming error, tested) if a measurement proposal has no comparator. The direct measurement is listed
   even when its cost is higher than every probe and even when its value per cost ranks last.
5. **The model-class statement.** Every proposal's `model_class` lists the mechanisms it is conditional on, and
   the text form says so: "conditional on the admitted laws {…}; a law outside this class can defeat this probe;
   comparator: direct measurement at mission conditions, cost …".
6. **Ranking.** Measurement proposals enter the same ranked list as simulation proposals, by value per cost, with
   value computed as the reduction in expected opportunity loss of the current choice when the mechanism block is
   resolved (the variance component is `Model`). The list ends with STOP when nothing clears the budget price. If
   KILL-VOI has fired, the proposals are listed unranked by value and value is a stop rule only.
7. **Output.** Within the `experiment.suggest` envelope: `proposals[]` (ranked), each with kind, target, command,
   relevance, cost, the `advisory` block (value, value per cost, model), prediction reference, model class,
   comparator, partition summary and A-25 result; `stop: bool`; `notes[]` (skips, discrepancies);
   `dropped_irrelevant` (the count of proposals the Augur side dropped because no outcome could change the
   decision). Evidence class `Estimated`,
   `claims: []`.

## Acceptance criteria

- [ ] Friction-law fixture, on the committed proposal records at this bead's close (the probe is generated by
      N25c-18, which depends on this bead, where the same numbers are unit tests; the same assertions through the
      verb are step 5 of N28c-16, which depends on both): with laws μ₁(v) = 0.5 and μ₂(v) = 0.3 + 0.4·v (v in m/s), which agree
      at 0.5 m/s and imply opposite designs at the mission speed 1.5 m/s (0.5 against 0.9), the proposed probe is
      at 1.0 m/s (readings 0.5 or 0.7) when the reading error bound is below 0.1; with error 0.1 or more no single
      probe at 1.0 m/s is proposed and two witness mechanisms are returned; a probe at 0.5 m/s is never proposed.
- [ ] `frob.proposal/1` is the only proposal record of the verb: `frob-mission` builds values of this type and
      declares none of its own; the admission check refuses a planted list for each broken rule of item 2 (a
      one-block identification proposal, overlapping reading sets without `partial`, same-sign witness margins).
- [ ] Every measurement proposal in every test output has a `DirectMeasurement` comparator with a cost, and a
      non-empty model class.
- [ ] Skip rule: when both laws imply the same pad, no identification proposal is emitted and the note is present.
- [ ] A-25 gate: on the drawbar fixture (F = min(k_t·I/r, μ·N), k_t = 0.2 N·m/A, r = 0.06 m) a proposal to
      identify μ from runs at 1 A and 2 A under 30 N and 40 N is rejected (zero sensitivity: 3.33 N and 6.67 N for
      μ = 0.4 and for μ = 0.8) and replaced by an excitation in the traction-limited regime (3 A under 10 N: 4 N
      against 8 N).
- [ ] Material-pad fixture (the pilot's four laws), on committed records here and through the verb in N28c-16:
      the suggestion output for the three admitted laws lists the synthesized probe with model class {V, P, C} and the direct measurement at mission dwell; a harness that
      follows the probe scores 675 of 675 in class and 0 of 225 on the withheld law D, and one that follows the
      direct measurement scores 900 of 900.
- [ ] A discrepancy (observations fitting no admitted mechanism) is reported and no proposal is fabricated.
- [ ] No proposal value appears in a verdict field; citing a proposal as a verdict is refused (`FROB-REF-872`).
- [ ] With the feature off, or after KILL-AUGUR-PROBE fires, the verb lists the programmed expert grid and the
      direct measurement only, and still states the model class. At this bead's close this is checked on a
      committed `synthetic` list (the expert grid's proposals and the direct measurement): the admission check
      still demands the comparator and a non-empty model class with the feature off, and refuses a generated
      `BenchProbe` in that build. The same through the verb is asserted by N25c-18 and by N28c-16, which depend
      on this bead and build the proposals; this bead does not wait for them.

### End-to-end script and logging

This bead adds the phase `admit` to `scripts/e2e/experiment_suggest.sh` (the script belongs to N28c-16; each
phase runs alone with `--phase <name>`, and the first bead to land creates the script from the STD-E2E template),
so that its own rules are checked from the command line at its close, before the Augur side fills the records:
`cargo run -p frob-conformance --example atelier_harness -- suggest.admit --lists conformance/suggest/admission/
--json` (the example target of N28c-06; `suggest.admit` is this bead's subcommand) feeds the committed `synthetic`
proposal lists (the friction-law records at errors 0.05 and 0.1, the 0.5 m/s record, a one-block identification,
same-sign witnesses, a list without a comparator, a discrepancy) through `admit_measurement_proposals` in the real
binary and asserts admitted or refused per list with the rule named; `frob analyze identifiability` on the drawbar
fixture asserts the motor-limited runs rejected (3.33 N and 6.67 N for both μ) and the traction-limited replacement
(4 N against 8 N); `cargo run -p frob-conformance --example atelier_harness -- suggest.pad-replay --json` (this
bead's second subcommand, which N28c-16 reuses) asserts 675/675, 0/225 and 900/900. Lines go to
`target/e2e-logs/experiment_suggest/<utc-timestamp>.ndjson` with `bead` `N28c-13`, `step` `admit.*`, `event`, the

### Known answers and negative controls

- CX-317 (675 of 675 in class; all 225 held-out decisions reversed by the fourth law; direct measurement 900 of
  900) and CX-309 / KA-688 (the drawbar fixture values) with the numbers stated above. CX-317's control in the
  counterexample registry is the planted input `suggest-without-direct`, and this bead is its planting bead
  (plant `N28c-13:suggest-without-direct`): the committed list without a comparator carries that name
  (`conformance/suggest/admission/suggest-without-direct.json`, with the `synthetic` header), so that the
  seeded control finds its fixture; under another name the control is `stale`.
- Negative controls that must fail: a suggestion list without the direct measurement; a probe proposal that
  omits its model class; a proposal to identify μ from the motor-limited runs that passes A-25; a ranking by
  parameter information gain (on the single-block fixture it proposes an identification the decision cannot use).
- Metamorphic relation: adding a mechanism that implies the same decision as an existing block does not change
  the proposed probe unless its reading set overlaps another block's.
- Determinism lanes: the proposal list is byte-identical twice on one machine and across hosts at a pinned ledger
  frontier (interval arithmetic for reading sets is outward-rounded and deterministic).

## Considerations

- The pilot evidence is unflattering and is kept: the programmed expert tied the generator and direct measurement
  beat both on the withheld law. What this bead ships is therefore a discipline (state the class, always offer
  the direct measurement) more than a generator.
- Real-experiment costs and the exchange rate between GPU-seconds and bench time are OPEN-ATEL-1; until decided,
  measurement proposals carry `cost.real: undeclared` and are listed after simulation proposals of equal value.
- A direct measurement can be impossible before a part exists; the proposal then says `not yet realizable` with
  the earliest stage at which it becomes so, and stays on the list.
- Interaction with calibration against reality: a probe's calibrated result may be reused for a family only
  within the scope the reality subsystem declares.
