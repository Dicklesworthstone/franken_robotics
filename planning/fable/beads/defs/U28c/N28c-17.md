## Background

The design studio has a rule for choosing the next experiment by its value: decision core DC-05 values each
candidate experiment by the expected reduction in opportunity loss of the current choice per unit cost (for two
finalists with posterior difference Δ ~ N(m, s²), an experiment removing variance s̃² is worth
EVSI = s̃·[φ(z) − z·Φ(−z)], z = |m|/s̃), buys in order of value per cost, and stops when nothing clears the budget
price. `experiment.suggest` exposes the ranking, and the finalist stage of the evaluation ladder (layer 3) uses
it. The mechanism is Frontier, and the published record does not support a large benefit against a capable agent:
information-gain selection is plausibly below 1.5 times; a language-model tuner beat random search more often
than Gaussian-process optimization at 10 and at 30 evaluations, and model-based search lost to a genetic algorithm
on a robot co-design benchmark (FACT from the source register, to be re-read before a gate cites it). The plan
therefore treats the rule as a stop rule and a budget allocator, and names a kill gate in advance.

KILL-VOI. Trigger: GATE-ATEL-15 fails. GATE-ATEL-15 (claim kind: Design comparison): in the offline replay, the
knowledge-gradient chooser is at least 1.5 times better than the agent chooser in evaluations to a true top-3; and
the value is exactly zero on a fixture where no outcome can change the choice. Fallback, named in advance: value
of information is a stop rule only; `experiment.suggest` lists proposals unranked by value. Decided at M4 and
recorded as an ADR. A kill gate names its trigger and fallback in advance and is never quietly re-scoped; a
trigger, threshold or fallback changes only by a dated amendment made before the measurement it governs. A kill
gate that fires is not a failure of the program: the fallback is the plan. This bead is that decision. It does not
overlap with KILL-AUGUR-PROBE, which governs the probe generator and is decided by the mission-query work.

## Scope

In: the decision protocol; how the measurement is read; the ADR; the downstream changes on each branch; the
fail-closed posture until the decision.
Out: building the log and running the replay (BD-310, BD-351); the zero-value clause through the verb (N28c-16);
the ladder's own kill gate KILL-LADDER, which is decided on the same log by a different comparison (layer 2
against halving's audited top-k recall at fewer GPU-seconds).

## Technical approach

1. **The experiment being read** (protocol frozen before the log is collected, registered in the pilot register).
   Log once, on an incumbent engine or on `batch-cpu`: 64 designs × 3 rungs × 32 world addresses (about one
   GPU-day, TARGET). Replay four choosers over the log with no further simulation: (a) an agent reading the log so
   far through the studio's read verbs; (b) the knowledge-gradient chooser of DC-05; (c) e-race elimination; (d)
   uniform allocation. Metric: evaluations until a true top-3 design is identified at 95% confidence, over 100
   replays. "True top-3" is defined from the full log at the highest rung, before any replay.
2. **Form of the comparison** (the method-experiment form every such gate has: competing arms, a potency control,
   a paired lower bound, a pre-declared fallback, a ceiling).
   - Pairing: replay i of every chooser uses the same permutation seed of addresses; the quantity is the paired
     ratio rᵢ = evaluations(agent)ᵢ / evaluations(knowledge-gradient)ᵢ.
   - Decision statistic: the one-sided 95% lower confidence bound on the pooled ratio of means over the 100 paired
     replays (computed by the performance harness's paired lower-bound routine; ten pairs of constant ratio r
     must return the bound r). Pass when the bound is at least 1.5. A replay in which a chooser never identifies
     a top-3 design within the log is right-censored at the log size and counted in a restricted mean.
   - Potency control: a planted log in which one rung's noise is 10 times smaller than recorded for half the
     designs; the knowledge-gradient chooser must beat uniform allocation by at least 2 times at the lower bound
     (the harness can see an effect). A/A control: agent arm against itself with different session seeds must not
     clear 1.02.
   - Ceiling, written before the run: the best possible chooser (an oracle that knows the true top-3) needs at
     least 3 × (evaluations needed to confirm one design at 95%); the ratio agent/oracle bounds what any chooser
     can gain. If that ceiling is below 1.5, the gate cannot pass and the fallback is adopted without the run.
   - Agent arm disclosure: model, prompt, tool list, token and turn budget, and the number of sessions that
     failed to complete, all recorded; the agent arm is given the same information the chooser has.
3. **Zero-value clause.** Read from the gate row written by the end-to-end script of `experiment.suggest`: value
   exactly zero on the fixtures where no outcome can change the choice. If this clause fails, the gate fails
   regardless of the ratio (the rule would buy experiments that cannot matter).
4. **Decision.**
   - Both clauses pass → KILL-VOI does not fire; DC-05 may move from `shadow` to `canary` under the adoption
     rules; the gate row records the bound.
   - Either fails → one repair cycle is allowed only for an implementation defect found by the controls (not for
     retuning the value model on the replay log); then, if still failing, KILL-VOI fires: status
     `killed: fallback adopted`.
5. **What changes downstream if it fires.**
   - `registries/cores/dc-05.toml`: `status = "fallback-only"` for ordering; the stop rule (stop when no value
     clears the price) stays in force, because the fallback keeps value of information as a stop rule.
   - `experiment.suggest`: proposals are listed unranked by value (ordered by the fixed order check, simulate,
     train, referee, then by cost); each still carries its cost, prediction, model class and, for measurements,
     the direct-measurement comparator. The envelope says `ranking: "unranked (KILL-VOI)"`.
   - The ladder's layer 3 (finalists, at most 64): allocation follows the fixed order of experiments; every
     verdict still comes from the promotion rule and the comparison rules, as before.
   - The plan's benefit claim for experiment choice is withdrawn from the ten-fold accounting; the phase ledger
     records that the lever was not available.
   - Beads that exist only on the surviving branch (adoption of DC-05 beyond shadow; any later refinement of the
     value model) are closed as not built.
   - Unaffected: registered predictions and their calibration monitor; measurement proposals with comparators;
     the advisory type wall.
6. **Until decided (fail-closed default).** DC-05 is in `shadow`: it records its ranking and the fixed order acts.
   No report states a saving from value-of-information ranking.
7. **Record.** An ADR `docs/adr/KILL-VOI.md` with the protocol hash, the log identity, the bound, both controls,
   the ceiling, the decision and the downstream list; the row of `registries/gates.toml` for KILL-VOI and for
   GATE-ATEL-15 with the claim identifiers; recorded by a session that did not implement DC-05.

## Acceptance criteria

- [ ] The protocol (arms, pairing, statistic, controls, ceiling, censoring rule, agent-arm disclosure) is
      registered with its hash before the replay runs; the registration's ledger sequence number precedes the
      first replay's.
- [ ] The gate row for GATE-ATEL-15 holds the measured lower bound on the ratio, the potency-control result, the
      A/A result and the zero-value result.
- [ ] The ADR exists at M4 with the trigger evaluated against its number (bound below 1.5, or a non-zero value on
      a no-change fixture, fires), and the KILL-VOI row records the decision: not fired (with GATE-ATEL-15 at
      `pass`), or `killed: fallback adopted`.
- [ ] If fired: DC-05's record is `fallback-only`, `frob experiment suggest --json` shows the unranked form, and
      the dependent beads on the losing branch are closed with a typed reason. If not fired: the adoption record
      for DC-05 cites this decision.
- [ ] Measurement sanity: the paired-bound routine returns r on ten pairs of constant ratio r; the potency
      control is detected; the A/A arm stays below 1.02.
- [ ] No amendment to the trigger, threshold or fallback is made after the log exists.

## Test plan

### Unit tests

`crates/frob-conformance/tests/kill_voi.rs`: `paired_bound_constant_ratio` (ten pairs at r = 1.7 → bound 1.7);
`censoring_restricted_mean` (a replay that never identifies is counted at the log size, 6,144 evaluations);
`decision_rule_table` (bound 1.49 fires; 1.50 does not; zero-value failure fires at any bound);
`ceiling_below_threshold_adopts_fallback`; `protocol_hash_precedes_replay` (ordering check on a fixture ledger).

### End-to-end script and logging

`scripts/e2e/kill_voi.sh`: reads the replay records from the ledger, recomputes the paired lower bound and the
controls with `frob-conformance run atelier.voi-replay --json`, checks the zero-value row written by
`experiment_suggest.sh`, and prints the decision. It sources the STD-E2E helper and logs to
`target/e2e-logs/kill_voi/<utc-timestamp>.ndjson`: per chooser the restricted mean evaluations, the paired ratio
and its lower bound against 1.5, the control results, the ceiling, the protocol and log digests, and a `summary`
with the trigger evaluation and `gates: ["KILL-VOI", "GATE-ATEL-15"]`. It exits zero when the measurement is
complete, whatever the decision.

### Known answers and negative controls

- Known answer for the harness: constant-ratio pairs return the ratio; the log size is 64 × 3 × 32 = 6,144
  evaluations.
- Negative controls: the potency log (must be detected); the A/A arm (must not clear 1.02); a replay in which the
  knowledge-gradient chooser is given the true ranking (a leak) must be rejected by the check that the chooser's
  inputs are a prefix of the log.
- Determinism: chooser arms (b) to (d) are pure functions of the log and the permutation seed (identical across
  runs); the agent arm is recorded, not regenerated, when the decision is re-audited.

## Considerations

- The agent arm's strength matters: a weak agent would let the gate pass for the wrong reason. The arm uses the
  same model family and tool surface as the studio's benchmark agents, with the configuration recorded.
- The measurement is on one logged population of 64 designs; the decision is scoped to that evidence, and the ADR
  says so. New evidence reopens the question only through the rejected-methods procedure (a new pilot and an
  ADR).
- Related risk: structure helping agents only slightly (the surface A/B) is a different question with its own
  gate; this decision is about the chooser, not the surface.
- Cost: the replay needs no simulation; the agent arm costs 100 sessions.
