## Background

The design studio defines fifteen refusal codes. A refusal is the system declining to produce a misleading result,
with ranked repairs: a comparison that mixes study types (`FROB-REF-553`), a fixed-n study that declares an
unreachable verdict (`-555`), a paired study under an uncontrolled determinism class (`-542`), an anytime study on
a metric with no declared span (`-543`), a pairing keyed by event order or a training counter (`-556`), a rung
asked to select where its mode is not `selective` (`-545`), calibration from survivors or a cancelled audit
episode (`-546`), a `model-conditional` result offered without its condition (`-557`), pooling across two model
identities (`-548`), a rare-failure bound over selected episodes (`-549`), `first-change` asked of bisect without
a scan (`-550`), an exclusion from an analysis that does not enclose a declared energy source (`-551`), reuse of a
verdict with no licence (`-870`), a missing or stale decision-core table (`-871`), and a value-of-information
output cited as a verdict (`-872`).

Gate GATE-ATEL-06 already requires five of them (`-553`, `-555`, `-542`, `-543`, `-556`) to fire on their planted
violation 100 of 100 at milestone M1, measured with the study planner. No gate names the other ten, and a refusal
that is defined but never fires is the commonest way for a protective rule to rot. This bead is one end-to-end
battery, run at M4 when all fifteen mechanisms exist, that fires every code from the user's side on a planted
violation, checks the envelope against the registry, and checks the clean twin of each request is accepted, so
that a refusal cannot pass the battery by refusing everything. It re-measures the five codes of GATE-ATEL-06
without replacing that gate's M1 record. Tier: Solid [S].

## Scope

In: the script; one planted violation and one clean twin per code (two for codes with two triggers); the 100
seeded variants per case; envelope checks; logging.
Out: the registry rows (N28-REF); raising the codes (the mechanism beads); the M1 gate record of GATE-ATEL-06.

## Technical approach

Phase ownership: the script exists before this bead. N28cx-01 creates it at M1 from the STD-E2E template with
its phase `predict-refusals` (the two refusals of registered predictions, run on fixtures until BD-344 lands);
this bead adds the battery's own steps and owns the whole run; `--phase <name>` runs one phase alone.

`scripts/e2e/atelier_refusals.sh`: plain shell over the real `frob` binary and a private `frobd` on the CPU tier;
sources the STD-E2E helper; idempotent; seed-explicit. For each case the script generates 100 variants from the
seed (different designs from the template set, metrics, sample sizes, strata or identifiers, as applicable), runs
the violating request and its clean twin, and asserts: violating → `ok: false`, exit 3, `refusal.code` equal to
the expected code, `refusal.repairs[0]` equal to the registry's first repair, `pointer`, `observed` and `required`
present; twin → `ok: true` (exit 0, 2 or 8). Each case is the planted violation of the bead that raises the code
(named in the table), so the battery fires the owner's own check and not a second one; parameter spellings are
those of the verb registry at the pinned commit (read with `frob schema <verb> --json` before the run), and a case
whose parameter no longer exists fails with the case named, never silently skipped.

Keys. Every request to a `run` or `mutate` verb whose entry requires a key (read from the same schema: everything
here except `study.plan`, which is `key_optional`, and the `read` and `admin` verbs) carries `--key
ref-<code>-<case>-<i>-$FROB_E2E_SEED` on the violating request and `--key twin-<code>-<case>-<i>-$FROB_E2E_SEED`
on its twin, `<i>` the variant index. Without a key the dispatcher's `FROB-REF-805` fires before any chapter check
and the case would fail for the wrong reason; with one key shared by two different requests 803 would.

Additional checks, once per code: the refusal's exit code is 3 on the command line and the MCP tool result is
`isError: true` with the same envelope (the two surfaces agree); `retry` is `after-change`; `affected_claims` is
populated where a claim would have rested on the result; applying the first repair to the violating request (the
script constructs the repaired command from the refusal payload) yields an accepted request.

**Logging.** `target/e2e-logs/atelier_refusals/<utc-timestamp>.ndjson` and a transcript. Every line: `ts`,
`script`, `bead` (`N28c-21`), `step` (the code and case, for example `555` or `546.b`), `event`, exact command
line, exit code, wall time, the envelope's `evidence` block where present; one `refusal` line per violating
request with code, pointer, observed, required, repairs, retry; `metric` lines per case: `fired` (threshold 100
of 100), `twin_accepted` (threshold 100 of 100), `first_repair_accepted` (threshold 100 of 100),
`surfaces_agree`; on failure the first variant that did not fire or whose twin was refused, with its seed index
and the fixture path. Final `summary` with assertions passed and failed.

## Acceptance criteria

- [ ] Each of the fifteen codes fires on its planted violation in 100 of 100 variants, for every case in the
      table (two cases where two triggers exist).
- [ ] Each clean twin is accepted in 100 of 100 variants.
- [ ] For every case, the envelope's code, exit code, retry class and first repair equal the registry row.
- [ ] `FROB-REF-555` reports the first reachable n (86 at a five-point margin).
- [ ] `FROB-REF-549` fires through the cascade's bound request, and the same episode sets offered to
      `nemesis.bound` directly are refused with `FROB-REF-560`; a nominal draw is accepted on both paths.
- [ ] `FROB-REF-871` without the rule pin completes on the fallback with a warning; with the pin it refuses.
- [ ] The first repair, applied mechanically from the payload, turns each violating request into an accepted one.
- [ ] Command-line and MCP surfaces return the same envelope for every refusal.
- [ ] The script exits non-zero when any one refusal is disabled in a conformance build (run once per code).
- [ ] Log and transcript at the stated path with a `summary` line.

## Test plan

### Unit tests

Helper tests in `cargo test -p frob-conformance --test e2e_scripts`: `variant_generator_is_seeded` (the same seed
yields the same 100 variants); `repair_applier` (builds `--fixed-n 86` from the 555 payload and the manifest
field `seed_protocol.pair_by = ["world", "replicate"]` from the 556 payload); `registry_compare` (flags a
first-repair mismatch); `keys_distinct` (no two requests of one run share a key, and every keyed verb has one).

### End-to-end script and logging

This bead is the script, as specified.

### Known answers and negative controls

- Known answers in payloads: n = 86 for the first reachable practical tie at a five-point margin; at n = 64 the
  rule has 2,145 count pairs (521 promote, 521 inferior, 1,103 inconclusive, 0 ties).
- Negative controls: fifteen conformance builds, each with one refusal check removed; the battery must fail on
  the matching case and only there. One further build refuses every `study plan` request; the clean twins catch
  it.
- Counterexamples behind the cases: CX-311 (epoch-keyed seeds pair only indices equal modulo 64) for 556 (a);
  CX-312 for 556 (b); CX-313 for 550; CX-306 for 551.
- Determinism lanes: twice on one machine with one seed (identical `metric` values); the Mac and the Linux host.

## Considerations

- 100 variants × about 40 requests each is 4,000 invocations, all refused at admission or completed as cheap
  planning calls; budget under 15 minutes on the CPU tier (TARGET). No case needs a GPU.
- Cases that need a running campaign (545, 546 (b)) use the replayed-campaign fixture of N28c-06 (a
  dependency) so that the request arrives at a deterministic point.
- A refusal must be raised before any budget is charged; the script asserts `cost.gpu_s == 0` on every refusal.
- The plan's 557 text also names "input to a build packet". Under the one-code-per-request precedence of
  N28-REF (and N16b-04), a build-packet request with a `model-conditional` input raises `FROB-REF-830`, not 557,
  so this battery has one 557 case. The build-packet case belongs to `foundry.export` (M5), whose own battery
  asserts 830 and that 557 does not fire.
