## Background

The design studio (Atelier) states twelve invariants, INV-ATEL-01 to INV-ATEL-12. An invariant is a property that
must hold in every execution, as opposed to a gate, which is a measurement at a milestone. The testing standard of
the program requires for every invariant a property test, and for every check at least one negative control: a
planted defect the test must catch. Each invariant is enforced where its mechanism lives (the comparison code, the
ladder, the decision cores, revalidation, the memo graph, lineage), and those mechanism beads carry their own
tests. This bead assembles the twelve into one battery in the conformance crate, written against the public
surfaces of the real components, so that the invariants are tested together on one campaign and none is left to
the goodwill of a single owner. It is the bead that carries the invariants table of the chapter.

Why a battery in addition to per-mechanism tests: several invariants are about interaction (a statistic that must
not depend on scheduling; a memo hit that must be invisible; a layer handover that must be one-way), and an
interaction is only tested when the parts run together. Tier: Solid [S].

## Scope

In: one property test and one planted-violation companion per invariant; the shared generators (random campaigns,
schedules, edit sequences, archives); registration of the controls.
Out: enforcing the invariants (the mechanism beads); the nine interference tests as a gate (BD-350), which this
battery reuses for four invariants; the proof obligations (N28c-23).

## Technical approach

`crates/frob-conformance/tests/inv_atel.rs`, using the real components on `batch-cpu` and on the
replayed-campaign fixture (81 designs, three strata, three rungs, 32 addresses; and the real 9-design
mini-campaign). No mocks. Each property runs 10³ random cases by default and 10⁴ in the nightly lane; seeds are
printed on failure with the shrunk case.

| ID | Invariant | Property test (inputs → assertion) | Planted violation that must be caught |
|---|---|---|---|
| INV-ATEL-01 | No stage of the loop runs on a design the previous stage refused, unless the request carries an override that is recorded on every downstream result | Random sequences of loop verbs (check, synthesize, simulate, train, compare) over designs with planted refusals at random stages → every downstream verb on a refused design is itself refused, re-issuing the earliest refusing stage's original code with a pointer to that stage (N28a-02's rule; no new code); with `--override <stage> --override-reason …` it runs, and every result derived from it (run, comparison, report statement) lists the override in its claim-product conditions | A simulate verb that ignores a failed check; an override dropped at the comparison |
| INV-ATEL-02 | A study's statistic is a pure function of the per-address outcomes taken in address order. It does not depend on completion order, preemption, co-tenancy, shard count or memo hits | Random studies (both types) × random schedules, shard counts 1 to 8, memo hit patterns → the statistic (e-value trajectory, or exact counts and intervals), pairs used and verdict are bit-identical | An e-process that consumes in completion order |
| INV-ATEL-03 | No audit-lane episode is cancelled, re-weighted or selected after any score for its design exists | Random campaigns with races and cancellations → for every audit episode: terminal state complete at its fixed n; draw sequence number below the first score's; weight 1 | A race that cancels dominated audit designs; an audit set redrawn after scores |
| INV-ATEL-04 | No design receives allocation requests from both the population layer and the finalist layer | Random campaigns crossing the handover (survivors ≤ 64) → per design, the set of issuing layers after its handover marker has one element | A finalist layer that re-submits to the population rule |
| INV-ATEL-05 | Evidence and calibration are never pooled across model identities. A change of model, kernel version, effort profile or battery version resets the affected ledger rows | Random sequences of identity changes interleaved with ledger writes → no ledger stratum or calibration set holds rows of two identities; after a change the affected rows are restarted; pooling attempts are refused (`FROB-REF-548`) | A ledger keyed without the effort profile |
| INV-ATEL-06 | A decision core's action is a pure function of its table version, the ledger state at a pinned frontier and addresses. It reads no clock | Random decision streams for every registered core × random schedules and injected delays → decision records byte-identical; replay from table and frontier reproduces every action | A core reading the ledger tip; a core branching on elapsed time |
| INV-ATEL-07 | Every reused verdict carries a grade and a licence; a grade-3 licence names a rule in the registry | Random edit sequences on the amendment fixtures → every verdict returned by revalidation as surviving has a grade in {1, 2, 3} and a licence; every grade-3 licence's rule name resolves in the rule registry; an unknown rule or a changed quantifier prefix is refused (`FROB-REF-870`) | A reuse path that returns a verdict with no licence; a licence naming "sensitivity-margin" |
| INV-ATEL-08 | A memo hit is bit-identical to a recomputation inside its determinism class | Random verb calls with memo on, then `--no-memo` → outputs and digests equal inside class D0 and same-backend D2; no hit served across a D3 boundary | A key that omits one declared input (delivery time; effort profile) |
| INV-ATEL-09 | Lineage merge and archive merge are commutative, associative and idempotent | Random triples of lineages and archives (a, b, c) → merge(a, b) = merge(b, a); merge(merge(a, b), c) = merge(a, merge(b, c)); merge(a, a) = a; equality on canonical bytes; ties in fitness resolved by the total order (fitness, then design identifier) | A merge that keeps the first arrival on equal fitness |
| INV-ATEL-10 | Every paired study satisfies the accounting identity and states its denominator | Random paired studies with stalls, penetrating starts and cancellations → a_only + b_only + both + neither + unscored = planned, each a non-negative integer; the verdict text states its denominator; a design that starts in penetration makes the pair `unscored`; a buildable design that stalls is a failed trial, not a missing one | A scorer that drops stalled trials from the denominator |
| INV-ATEL-11 | No verb of this chapter reads a confirmation world of the blinded qualification lane | Every studio verb (analyses, compare, bisect, optimization, cascade, revalidate, suggest, predict, report, cores) run under a session without qualification scopes, with access auditing on the sealed world clusters → zero reads of sealed fields; statically, no studio verb lists a qualification capability | A cascade stage that evaluates finalists on confirmation worlds |
| INV-ATEL-12 | A value-of-information quantity never appears in a verdict field | Random campaigns interleaving suggestions, budget-curve fits and comparisons → no advisory value in any stored verdict record; citing one is refused (`FROB-REF-872`) | An advisory type made acceptable to the verdict writer |

**Shared generators (DESIGN).** `gen::campaign(seed)`: population size 9 to 81, strata 1 to 3, budgets, planted
refusals. `gen::schedule(seed)`: completion permutations, preemption points at snapshot boundaries, co-tenancy,
worker and shard counts. `gen::edit_sequence(seed)`: typed edits of the five classes (mass, mount,
controller-only, mission-only, topology). `gen::archive(seed)`: quality-diversity archives with deliberate fitness
ties. All are seeded and shrinkable.

**Reuse of the interference suite.** INV-ATEL-02, -03, -04, -05 and -08 share fixtures and assertions with
interference tests IT-3, IT-2, IT-1, IT-5 and IT-9; here they run over random campaigns and schedules instead of
the one replayed campaign, which is what makes them property tests.

**Registration.** Each planted violation is a control record in the negative-control registry (kind `mutation`),
attached to this battery and to the gate of its mechanism; the battery fails if a control is not caught.

## Acceptance criteria

- [ ] `cargo test -p frob-conformance --test inv_atel` runs twelve property tests and twelve planted-violation
      companions; all twelve properties hold over 10³ cases each, and each companion fails its property.
- [ ] The nightly lane runs 10⁴ cases per property and records the counts.
- [ ] Every failure prints the seed and a shrunk case (for INV-ATEL-09: the smallest pair of archives whose merge
      order matters).
- [ ] INV-ATEL-11: the sealed-field audit records zero reads across all studio verbs; the planted violation
      produces at least one audited read and fails.
- [ ] INV-ATEL-10: the identity is checked with integers only; a study whose counts are floats is rejected by the
      schema.
- [ ] Each of the twelve invariants is listed in the crate's contract with the name of its property test.
- [ ] The controls are registered and shown `caught` in the registry report for the studio.

## Test plan

### Unit tests

The battery is the set of unit and property tests named `inv_atel_01_stage_order` … `inv_atel_12_no_voi_in_verdict`
with companions `…_planted`. Generator self-tests: `gen_schedule_covers_preemption` (at least one preemption in
95% of generated schedules); `gen_archive_has_ties` (at least one fitness tie in 90% of generated pairs);
`gen_edit_sequence_covers_five_classes`.

Expected values for fixed cases used as smoke tests inside the properties:
- INV-ATEL-09: archives {(cell 3, fitness 0.80, design d:aa)} and {(cell 3, fitness 0.80, design d:ab)} merge to
  d:ab in both orders (the larger design identifier wins a tie under the total order; DESIGN for the direction,
  fixed in the crate contract).
- INV-ATEL-10: planned 64; outcomes a_only 9, b_only 14, both 30, neither 8, unscored 3 → 64.
- INV-ATEL-03: 81 designs, a tenth of spend → the audit draw's sequence number precedes the first score row.

### End-to-end script and logging

`scripts/e2e/atelier_invariants.sh`: runs the battery through `cargo test` with the seed from `FROB_E2E_SEED`,
then demonstrates three invariants from the user's side with real verbs: INV-ATEL-01 (`frob sim run` on a design
whose `design check` was refused → exit 3 with the check's original code; with `--override check
--override-reason …` → runs and the run's envelope lists the override); INV-ATEL-09 (two agents' sessions build
lineages and archives on a shared template; their stores are absorbed in both orders into fresh stores, as the
two-agent merge of BD-342 and N28b-04 does, and `frob opt archive <campaign> --json` and the exported lineages
read from the two stores are byte-identical; there is no merge verb to call); INV-ATEL-10 (`frob eval compare …
--json` → the five counts sum to `planned`). Logged through the STD-E2E helper to
`target/e2e-logs/atelier_invariants/<utc-timestamp>.ndjson`: per invariant a `metric` line with cases run and
failures (threshold 0), `assert` lines for the three demonstrations with digests of the merged archives, the
override identifiers, and on failure the seed and shrunk case path; a final `summary`.

### Known answers and negative controls

- Negative controls: the twelve planted violations above (several are also the controls of interference tests and
  of counterexamples CX-311, CX-313, CX-315).
- Metamorphic relations used inside the properties: permuting design identifiers consistently permutes outcomes;
  doubling worker count changes nothing; adding an unrelated co-tenant job changes nothing.
- Determinism lanes: every property on `batch-cpu` twice, across worker counts, debug and release; INV-ATEL-08
  additionally on one GPU backend at class D2.

## Considerations

- INV-ATEL-01 has no code of its own: N28a-02 settles that a downstream verb re-issues the earliest refusing
  stage's original code with a pointer to that stage. The battery asserts that code and pointer, and the override
  record when the request carries one.
- A property test over the real cascade is slow; the default lane uses the replayed fixture (no simulation) for
  the campaign-level properties and the 9-design real mini-campaign for the digest-level ones.
- INV-ATEL-11 depends on the confirmation firewall's audit hook; without it the property cannot be observed and
  the test must fail closed (report "not observable"), not pass.
