## Background

The design studio's chapter ends its mechanisms with a table of known answers and negative controls: for each
subject (an analysis, the fixed-n rule, a decision core, deduplication, revalidation, bisect) one case whose truth
is known by derivation or exact enumeration, and one negative control that must fail. A known-answer test shows
the implementation recovers an analytic or synthetic truth; the negative control shows the test can fail (a gate
that nothing can fail validates nothing). The mechanism beads each test their own rows. This bead is the battery
that carries the table as a whole: it registers every row as a named known-answer fixture with a pinned expected
value and tolerance, attaches the row's negative control to the negative-control registry, runs all rows in one
suite, and reports, per row, value, tolerance, and whether the control was caught. It is how the milestone exit
reviews see at a glance that no row of the table was dropped.

Rows are due at different milestones (static analyses at M1; decision cores DC-01, DC-09, DC-10 and dependency
revalidation at M3; the rest at M4), so the battery is staged: a row whose mechanism does not exist yet is
reported `not run`, which is not a pass, and the battery's milestone-M4 form requires every row. Tier: Solid [S].

## Scope

In: the battery suite, the fixtures with pinned values, the control attachments, the staged report.
Out: implementing the mechanisms; the registries themselves (the known-answer registry bead of the chapter; the
counterexample registry N28-CX); the per-mechanism test files.

## Technical approach

struct `{ ka, subject, case, expected, tolerance, tier, control, gate, due }`; expected values are stored as exact
rationals or integers where the tolerance is exact. The suite calls the real component through its public surface.

Two registry rows of the chapter that are outside the chapter's own table are carried by the same suite so that
the battery equals the registry: KA-701 (revalidation, widening the hypothesis support of the docking fixture by
gain 33/32: indistinguishable from gain 1 at error radius 1/64; every one of the 34,590 positive decisions on each
test grid is withdrawn; control: a hash match taken as verdict transfer; GATE-ATEL-11) and KA-706 (screening
audit bounds: no top-k design among 30 audited discards bounds the false-discard rate at 9.5% with 95%
confidence; 59 bound it at 5.0%; GATE-ATEL-09).

**Mechanics.**
1. Each row's test function is named `ka_NNN_<subject>` and asserts the expected value with the tolerance; rows
   with "to the printed digits" compare after rounding to the digits shown.
2. Each row with a control has a companion `ka_NNN_control` that builds the planted defect behind the
   `conformance` feature (or supplies the planted input) and asserts the row's test fails; the control is the
   record seeded by the counterexample registry or by the row's `Negative control` cell.
3. Staging: `FROB_MILESTONE` selects which rows are required; a required row that cannot run is a failure; a row
   not yet due prints `not run`.
4. Report: `frob-conformance report ka --chapter 28 --json` lists, per row: measured value, expected, tolerance,
   pass or fail, control caught or not, the gate, the owning bead and the claim identifier of the run.
5. Rows adopted from planning pilots (KA-682, KA-686, KA-698, KA-699, KA-701) carry `to-be-rerun: true` until the
   pilot has been re-executed in this repository and its value re-pinned.

## Acceptance criteria

- [ ] All twenty-five table rows and the two additional registry rows exist as fixtures with pinned expected
      values and tolerances, and agree with the chapter's known-answer registry number for number.
- [ ] At M1 the rows due at M1 pass and their controls are caught; likewise at M3; at M4 every row passes and
      every stated control is caught.
- [ ] Rows with "none stated" controls (KA-694, KA-703) each get a control defined here: for KA-694 a bound
      computed two-sided (1 − 0.025^(1/64) = 0.0560, which the test must reject); for KA-703 a capacity table that
      uses E[S]² in place of E[S²] (first-come wait 220.5 s instead of 2,000.6 s, which the test must reject).
- [ ] The report lists every row with its gate and owner; a missing row fails the generated-artifact check.
- [ ] The arithmetic rows recompute in exact arithmetic inside the suite, independent of the component under
      test: 3807/4096; 0.94176; 86,185 and 500,500; C(66, 2) = 2,145; 0.04573; 86 of 100 and 98.
- [ ] Every control is recorded `caught` in the negative-control registry with session and date.

## Test plan

### Unit tests

The battery is the test suite. Independent arithmetic checks inside it: `burnside_dihedral_six_slots`
((10⁶ + 20 + 200 + 1,000 + 30,000 + 3,000)/12 = 86,185); `mirror_only_count` (500,500); `majority_of_seven`
(3807/4096); `zero_discordance_bound` (0.045730); `two_sided_bound_is_different` (1 − 0.025^(1/64) = 0.0560);
`fcfs_wait_formula` (λ·E[S²]/(2(1 − ρ)) with λ = 1/270, E[S²] = 324,090, ρ = 0.7 → 2,000.6);
`wrong_second_moment_control` (using E[S]² = 35,721 gives 220.5 s; the control's value differs from 2,000.6 by
more than the tolerance).

### End-to-end script and logging

`scripts/e2e/atelier_known_answers.sh`: runs the suite for the current milestone, then
`frob-conformance report ka --chapter 28 --json`, and for six rows calls the real verbs from the user's side
(`frob analyze symmetry` for KA-680; `frob analyze shared-bus` for KA-687; `frob eval preanalyze --n 64 --margin
0.05` for KA-693; `frob cores show dc-01 --rows` for KA-695; `frob design bisect` on the six-version lineage for
KA-702; `frob nemesis cover` for KA-704). Logs through the STD-E2E helper to
`target/e2e-logs/atelier_known_answers/<utc-timestamp>.ndjson`: per row a `metric` line with measured, expected,
tolerance and unit, an `assert` line for the control (`caught: true`), the envelope's `evidence` block for the
verb calls; on failure the row, both values and the fixture path; a `summary` with rows passed, failed and not
run.

### Known answers and negative controls

The table is the content. Determinism lanes: exact rows are identical on both hosts and in debug and release;
KA-686 and KA-703 are compared after rounding to the printed digits; KA-691 and KA-692 run on the referee and
lockstep tiers as their registry rows state.

## Considerations

- A control must be a defect whose value is clearly outside the row's tolerance. That is why the KA-703 control
  is the E[S]² variant: λ·E[S]²/(2(1 − ρ)) = 35,721/(270 × 0.6) = 220.5 s against 2,000.6 s. A control that only
  dropped the short-class load from the preempt-resume denominator would give 0.167 s against 0.172 s, inside
  the printed precision, and would prove nothing.
- The plan prints the 5th-percentile coverage for KA-696's companion statistic as 0.885 in one place and 0.884
  in another; the exact value is 0.8840 and that is what the conformal test uses.
- Several subjects' fixtures are owned by other subsystems (clearance for A-18, wrench attainability for A-24,
  the docking fixture for KA-701); the battery calls their components and does not copy their fixtures.
- A row whose expected value changes is a change to a known answer and needs the derivation on file updated
  first; the suite's fixtures are never regenerated from the implementation.
