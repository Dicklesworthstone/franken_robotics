## Background

Three mechanisms of the design studio are specified against crates of the simulation sibling (FrankenSim), reached
through the airlock (the one crate, `frob-fsim`, that may name the sibling's volatile types):

- the memo graph is modelled on `fs-recompute`, a content-addressed Merkle graph with a skip oracle, pins that
  are never evicted and an independent checker;
- experiment ranking uses `fs-voi`, which provides the value of an action per unit cost, a recommendation with a
  stop threshold, expected opportunity loss and a knowledge-gradient routine over a finite Gaussian menu (its own
  comparison test is a three-design fixture, so no saving is measured);
- racing uses `fs-race`, whose mixture construction keeps the true best with probability at least 1 − α and whose
  battery asserts a saving of at least 2 on a separated field and below 1.5 on an inseparable one.

These are FACTs about sibling code at a pinned commit, to be re-read at admission. Whether each crate can actually
be consumed is an open question, OPEN-ATEL-3: "whether `fs-recompute`, `fs-voi` and `fs-race` pass admission
through the airlock on the toolchain T. Owner: suite lead. Blocks GATE-ATEL-12 and -15. Default: the node record,
the closed-form value and the race are implemented locally against the same known answers." Admission is never
inherited: a foundation first used at a later milestone is admitted then, by its own record, at the pin of that
day. This bead decides, per crate, between consuming and implementing locally, and makes sure the local path is
ready before it is needed.

It is an experiment bead as much as a decision: the answer comes from reading the admission tests. It is due at M1
because the memo graph in front of analyses (the analysis part of GATE-ATEL-12) is an M1 deliverable and the
racing adapter is admitted at M1 (N33a-18, the `fs-race` row of INT-FSIM-14). `fs-voi` is first used at M3 and M4
(experiment suggestion), and admission is never inherited, so its admission is read at its first use: the stats
group's admission (N33b-13, M3) writes that row, and this bead records it as deferred with the local closed form
as the default meanwhile.

## Scope

In: the admission experiments' reading for `fs-recompute` and `fs-race`; the per-crate decision record, with the
`fs-voi` row recorded as deferred to its first-use admission; the interface each studio mechanism codes against
(`Memo`, `Race`, `ValueModel`) so that both branches are interchangeable; the known answers that pin both
branches, run at this bead's close on the branches that exist then.
Out: running the generic admission matrix of the toolchain (its own bead); the `fs-voi` admission and its row
(N33b-13 at M3); implementing the memo graph, the race or the ranking (their beads, which read this decision); the
value known answers on the selected branch (BD-351, which depends on this bead and on N33b-13).

## Technical approach

1. **Per crate, the admission test to read.**
   - `fs-recompute` (admission gate INT-FSIM-16): builds on the toolchain T inside the `ledger` feature group;
     a node cached under a key is skipped only when every declared input is unchanged; a planted digest mismatch
     raises its determinism-violation error and stops serving; a pinned node is never evicted. Extra condition
     for the studio: tolerance-level reuse (serving a node cached under a looser requirement if it achieved
     enough) can be disabled per node kind, because the studio allows it only for analyses that record an
     achieved error and never for episodes.
   - `fs-voi` (INT-FSIM-14, statistics group): builds on T; reproduces the closed form
     EVSI = s̃·[φ(z) − z·Φ(−z)] on the worked menu (0.0013 for 200 fast-tier pairs; 0.0055 for 8 referee pairs);
     returns zero value and a stop when no outcome can change the choice.
   - `fs-race` (INT-FSIM-14): builds on T; in a null race of 81 candidates over 512 replays the designated best
     is eliminated at most 42 times at α = 0.05; on its separated fixture the saving is at least 2; elimination
     order depends on rounds only (index order), never on completion order.
2. **Decision rule per crate.** Consume through the airlock if: it builds on T without a patch to the sibling;
   its admission test passes; its transitive dependency closure adds nothing forbidden to the core (no second
   async runtime version; no forbidden numerical library); and its determinism class meets the studio's use
   (D0 for analyses, same-backend D2 for episodes). Otherwise implement locally: the node record in
   `frob-chronicle` with the same key and pin semantics; the closed-form value and stop rule in `frob-opt`; the
   mixture race in `frob-opt`. A mixed outcome is expected and acceptable (for example consume `fs-race`,
   implement the node record locally).
3. **One interface, two branches.** Each mechanism codes against a trait owned by the studio (`Memo` in
   `frob-core`; `ValueModel` and `Race` in `frob-opt`), with an airlock-backed implementation and a local one
   selected by a build feature recorded in the stack lock. The known answers below are run against whichever is
   selected, and against both wherever both exist, with outputs required to be equal (bit-identical for the
   race's decisions and the memo's skip decisions; within 10⁻¹² relative for the value).
4. **Record.** One admission record per crate in `DEPENDENCY_ADMISSION.md` (command, output, receipt hash, pin),
   and an ADR `docs/adr/OPEN-ATEL-3.md` with the per-crate branch and the reason. The `fs-voi` row reads
   `deferred: admitted at first use (M3)`, with the local closed form as the branch in force, until the stats
   group's admission record exists and the row is completed from it. The siblings are the owner's own projects,
   so a defect or mismatch in one is fixed in its repository: a crate that fails admission for a cause in the
   sibling (it does not build on T, a planted digest mismatch is not caught, its closure pulls a second async
   runtime version) gets an upstream work item, a row of `registries/upstream.toml` mirrored as an `upstream`
   bead in the sibling's tracker, whose interim posture is the local implementation; a defect found in a
   consumed crate is filed the same way. The switch-over rule from local to consumed is "admission test green
   at a new pin, known answers equal on both branches, one milestone of shadow use".
5. **Fail-closed default until decided.** The local implementations are the default. No studio gate may cite a
   sibling crate's behaviour that has no admission record.

## Acceptance criteria

- [ ] Admission records for `fs-recompute` and `fs-race` exist (pass or fail), each with command, output digest,
      receipt hash and pin; the `fs-voi` row is recorded `deferred` with the local default in force.
- [ ] The ADR records the branch per crate with its reason; the open-question row stays open, with the default in
      force for `fs-voi`, until that row is completed at M3.
- [ ] For every branch that exists at this bead's close, the memo and race known answers below pass; where both
      branches exist they agree.
- [ ] The studio's traits compile with either implementation; switching the feature changes no public schema.
- [ ] No studio crate other than `frob-fsim` names a type of the three sibling crates (layer check passes).
- [ ] `atelier_harness` has the subcommand `atelier.race-null` (a thin parser over `frob_opt::race::null_race`),
      and BD-025's lint `no_conformance_command` passes on `open_atel_3.sh`.
- [ ] If `fs-recompute` is consumed, tolerance-level reuse is shown disabled for the episode node kind (a looser
      cached episode is not served).
- [ ] A crate that failed admission for a cause in the sibling has its upstream work item in
      `registries/upstream.toml`, with the local implementation as its interim posture and the switch-over rule
      of step 4.

## Test plan

### Unit tests

`crates/frob-opt/tests/open_atel_3.rs` and `crates/frob-chronicle/tests/memo_branches.rs`, each parameterized over
the available implementations:
- `memo_skip_only_when_inputs_unchanged`; `memo_mismatch_stops_serving`; `memo_pin_never_evicted`;
  `memo_no_tolerance_reuse_for_episodes`;
- `value_trait_contract` (the `ValueModel` trait's signature and its refusal of an unordered menu; the value
  points 0.00131 and 0.00550 within 1% and zero value on the no-change fixture are run by BD-351 against the
  selected branch);
- `race_null_81_512` (at most 42); `race_separated_saving_at_least_2`; `race_round_clock_only` (decisions equal
  under shuffled completion order);
- `branches_agree` (where two implementations exist).

### End-to-end script and logging

`scripts/e2e/open_atel_3.sh`, runnable at this bead's close (M1): runs the `fs-recompute` and `fs-race`
admission tests through the airlock on the toolchain T and prints the decision table (with the `fs-voi` row
`deferred`); runs `frob design check` twice with the memo on and asserts the second call is served from the memo
with identical output digests, then on the four-state camera fixture asserts 2, 0, 0, 1 evaluations and 1, 0, 0,
1 recomputations; runs the null race through the `Race` trait on the selected branch
(`cargo run -p frob-conformance --example atelier_harness -- atelier.race-null --candidates 81 --replays 512
--seed $FROB_E2E_SEED --json`, at most 42 eliminations of the designated best) and the separated fixture (saving
at least 2); and runs the layer check that no studio crate but
`frob-fsim` names a sibling type. The harness: the conformance crate has no binary and no `frob-conformance`
command (BD-025, ADR-GAUNT-01; its lint `no_conformance_command` refuses the old form); the studio's harnesses
are subcommands of the example target `crates/frob-conformance/examples/atelier_harness.rs`, a thin argument
parser over library functions. This bead adds `atelier.race-null`, a parser over `frob_opt::race::null_race(
candidates, replays, alpha, seed)` (the function the unit test `race_null_81_512` calls, run on whichever branch
of `Race` the build selects); at M1 this bead or N28c-27, whichever lands first, creates the file. The script
sources the STD-E2E helper and writes
`target/e2e-logs/open_atel_3/<utc-timestamp>.ndjson` with a transcript; every line has `ts`, `script`, `bead`
(`N28c-28`), `step`, `event`, the exact command line, exit code, wall time and the envelope's `evidence` block
where a verb is called; per crate the admission command, exit code, receipt hash, pin and branch chosen;
`metric` lines for the known answers against their bounds; on failure the crate, the branch and the first
differing value; a `summary` with the decision table.

### Known answers and negative controls

- Known answers shared by both branches: the EVSI values; the null-race bound (42 of 512); the four-state camera
  fixture for the memo (2, 0, 0, 1 evaluations and 1, 0, 0, 1 recomputations).
- Negative controls: a memo implementation whose key omits delivery time keeps a stale promotion at the fourth
  state; a race that eliminates on any single pairwise crossing at level α exceeds the null bound; a value
  routine that returns a positive value on the no-change fixture.
- Determinism lanes: both branches twice on one machine and across worker counts.

## Considerations

- The owner has ruled that the whole build graph uses one toolchain T; admission is therefore a question of
  whether the sibling crates build and behave on T at their pin, not of bridging toolchains.
- Local implementations are small (a node record, a closed form, a mixture of e-processes); the cost of the local
  branch is duplication, and the benefit is independence from a sibling's release rhythm.
- `fs-voi`'s menu is finite and Gaussian; measurement proposals partitioned by decision are outside it in either
  branch.
