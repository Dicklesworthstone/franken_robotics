## Background

The reuse ledger of the design studio keeps three kinds of reuse apart: exact reuse (compute taken unchanged from
the memo graph because no dependency changed), evidence carried forward (verdicts that revalidation keeps without
recomputation, each with the dependency receipt that justifies it), and reacquisition avoided (training or
optimization steps not spent because a child started from a parent's policy, orbit or solution, measured against
a from-scratch control stopped at the same return). Each is a share of total work per accepted child decision, in
GPU-seconds and CPU-seconds, priced cold and warm separately; the three are never summed.

A ledger nobody reads protects nothing. The plan names the surfaces: "`design.diff --reuse` and `report.campaign`
print the three columns per edit class: mass, mount, controller-only, mission-only, topology", and adds a rule
with teeth: "a reuse figure printed without its column name is refused in a report". This bead is those surfaces
and that rule. `design.diff` is the studio's lineage verb (kind `read`, first milestone M1: the structural and
parameter difference of two versions, with the symmetry effect); `report.campaign` is the campaign evidence
package (kind `read`). Tier: Solid [S].

Design reason for refusing an unnamed figure instead of defaulting it to a column: the three columns differ by an
order of magnitude on the same edit (about a tenth for exact reuse after a dynamics-affecting edit; up to 72% in
the third column with a good warm start), and a bare "reuses 70% of prior work" is exactly the sentence the
ledger exists to prevent.

## Scope

In: the `--reuse` option of `design.diff`; the reuse section of `report.campaign`; output schemas; the refusal;
wording rules; token budgets.
Out: the ledger (N28c-42); the controls (N28c-43); the general report machinery (the seed bead for reports) and
the other campaign sections; the gate measurement (N28c-45).

## Technical approach

1. **`frob design diff A B --reuse [--regime cold|warm|both] [--run-control] --json`.** A and B must be a parent
   and child joined by one or more typed edits in one lineage (otherwise a schema refusal: reuse is defined per
   accepted child decision). Without `--reuse` the verb is unchanged. With it, `result` gains:
   ```json
   "reuse": { "estimand": "total work per accepted child decision",
     "edit_class": "controller-only", "mixed": false,
     "records": [ { "regime": "warm", "resource": "gpu_s", "total_s": "240.89", "total_source": "measured",
                    "recomputed_s": "…",
                    "exact_reuse":            { "share": 0.0037, "seconds": "0.89", "by_node_kind": { "kernel-binary": "0.89" } },
                    "evidence_carried_forward": { "share": 0.0, "seconds": "0", "by_grade": {}, "receipts": [] },
                    "reacquisition_avoided":  { "share": null, "status": "not-measured", "why": "no from-scratch control was run" },
                    "identity_residual": 0.004, "status": "closed" } ],
     "controls": { "decision_control": "e:…", "training_control": null },
     "never_summed": true }
   ```
   Every figure appears under its column key; shares are printed with their seconds; the regime and resource are
   always present. `--run-control` submits the from-scratch controls for this edit as a job (exit 8 with a job
   handle unless the bounded wait completes) and the figures marked `not-measured` are filled when it finishes.
   `--estimate` returns the control's cost without running it.
2. **Reuse section of `report.campaign`.** For the campaign's lineage: one table per regime and resource, rows =
   the five edit classes, columns = `exact reuse`, `evidence carried forward`, `reacquisition avoided`, each cell
   a mean share with the number of records and the number of those with a from-scratch control (for example
   "0.08 (n = 6; controls 1)"); a line stating the estimand; a line stating that the columns are not additive.
   Classes with no records print "no edits of this class". Records flagged `ledger-open` are listed separately
   and excluded from the means.
3. **The refusal.** The report generator accepts a reuse number only as a typed value carrying its column and
   regime. Three planted routes are closed: (a) a template placeholder for a bare reuse percentage; (b) a caller
   option asking for a single combined figure (`--reuse-summary total`); (c) a statement in a design report that
   cites a reuse share without its column. Each is refused: the verb returns `ok: false`, exit 3, with a refusal
   whose message is "A reuse figure must name its column (exact reuse, evidence carried forward or reacquisition
   avoided) and its regime (cold or warm)", `pointer` at the offending field, and repairs: 1. print the three
   columns; 2. name the column and regime. The plan assigns no code to this refusal; the implementation uses the
   code the registry owner assigns, and until then a named generation error with the same envelope shape.
4. **Wording rules** (enforced by the report lint together with the other campaign wording rules): the words
   "reuses N% of prior work" may appear only with a column name; the third column is always accompanied by "against
   a from-scratch control stopped at the same return" and by the from-scratch label (`class-prior` or
   `random-init`); a cold figure is never printed without the warm figure beside it.
5. **Envelope and budgets.** `evidence`: claim kind Performance for the timing figures, class `Tested` where a
   control measured the total and `Estimated` where the total is reconstructed; the disclosure block required of
   performance figures (host fingerprint, regime, cache state) is attached. `design.diff --reuse` for one edit is
   under 600 tokens without breakdowns (TARGET); breakdowns by node kind are behind `--detail`.
6. **Arithmetic the surfaces must reproduce** (asserted on fixtures): a controller-only edit shows exact reuse of
   every model analysis; a mass edit shows exact reuse of none of its rollouts; a kernel compile of 95.91 s
   beside 240 s of training prints 28.6% cold and 0.37% warm for the same cache.

Determinism: both outputs are pure functions of ledger rows at a pinned frontier (class D0 given the rows).

## Acceptance criteria

- [ ] `frob design diff A B --reuse --json` on a fixture lineage returns the block above with every figure under
      a column key, with regime, resource, seconds, total source and identity residual.
- [ ] Without a control the third column prints `not-measured` with the reason; after `--run-control` completes
      it prints a measured share with the from-scratch label.
- [ ] `frob report campaign <id> --json` contains the reuse section with five class rows per regime and resource,
      counts and control counts, the estimand line and the non-additivity line.
- [ ] The three planted routes to an unnamed or combined reuse figure are each refused with exit 3 and the stated
      repairs, 100 of 100 over seeded variants.
- [ ] Fixture assertions: controller-only edit → every model-analysis node appears under exact reuse; mass edit →
      zero episode nodes under exact reuse; 28.6% cold and 0.37% warm.
- [ ] No output anywhere contains a sum of the three columns (a scan of the JSON for a key or cell equal to their
      sum on the fixture finds none).
- [ ] Both verbs are reachable through `frob --json` and the MCP surface with updated schemas; `--estimate` works;
      cancelling a `--run-control` job drains cleanly.
- [ ] Performance figures carry the disclosure block; a reuse section without it is refused by the existing
      rule for performance figures.

### Known answers and negative controls

- Known answers: 95.91/(95.91 + 240) = 28.6% cold; 0.89/(0.89 + 240) = 0.37% warm; third column 72% at a = 0.8
  with training at nine tenths of total.
- Negative controls that must fail: a report that prints "reuse: 82%" (the sum of 10% and 72%); a `design.diff`
  that fills the third column from a default fraction; a section that prints the cold figure alone.
- Determinism lanes: outputs byte-identical twice on one machine and across hosts at one ledger frontier.

## Considerations

- The refusal has no code in the registry; this is recorded as a need and in the coverage notes. The behaviour is
  specified completely here so that assigning the code later changes one string.
- Timing figures are performance figures and inherit that discipline: a figure without its disclosure block or
  from an unpinned host is refused by the existing rules, independently of the column rule.
- `design.diff` is a read verb; `--run-control` makes one invocation spend compute. It is therefore routed as a
  job submission inside the read verb's envelope (exit 8), requires an idempotency key, and is listed in the
  registry as a sub-mode with kind `run`, so that budgets and capability scopes apply.
- For lineages without any accepted child decision (pure exploration), the section prints "no accepted child
  decisions" and no figures.
