## Background

The first milestone (M0, "spine and airlock") builds almost nothing and measures the risks that could invalidate
the architecture. One of its artifacts is a single command, `frob sim run g1 --tier referee --seconds 2`, that
steps FrankenSim's built-in 29-joint humanoid (the Unitree G1 model in `fs-mbd::robot_models`) for two seconds on
the referee tier and produces a final state digest equal to the one FrankenSim computes for itself on the same
rollout inside its own tree. It proves four
things at once: the foundation can be consumed from outside its tree through the airlock crate `frob-fsim`; the
verb skeleton writes one well-formed envelope; a result reaches the ledger with its identities; and a second
session can reproduce the artifact from the recorded command alone. The seed done-condition is the last of
these: a fresh session reproduces the M0 artifact from the recorded command.

This bead is the thin slice of the record subsystem (Chronicle) that exists at M0. The full ledger schema, the
`.frun` format and the chunk protocol arrive at M1; here the run writes to the minimal `run` and `episode`
tables of the M0 ledger adapter. The slice still obeys the rules the full system keeps: no naked number reaches
the agent (every output carries its evidence block), two executions of the same work produce the same
identifiers and different execution traces, and a world is determined by its address and identities.

Terms. The *referee* is the double-precision reference tier built on FrankenSim's articulated dynamics. A *state
digest* is the 32-byte BLAKE3 of the canonical referee-state byte string, computed by the one digest source file
`frob_fsim::referee::digest` of BD-007 and never re-implemented here: the ASCII domain tag
`frob.referee-state/1` and one zero byte; `links`, `nq`, `nv` as 32-bit little-endian unsigned integers; every
element of position then velocity as the 8 bytes of its IEEE-754 bit pattern, little-endian; then the tag byte
0x00 (a plain state digest; 0x01 and the accelerations make a forward-dynamics digest). *T0* is the telemetry level that every world always keeps: per-episode metrics and state digests
at intervals. A *world address* is `(run_seed, world, episode)`.

Rejected alternative: a test binary that prints a digest. It would prove consumption but not the verb, the
envelope, the ledger or reproduction by a stranger, which are what later milestones stand on.

## Scope

In: the verb `sim.run` restricted to `--tier referee`, the catalog design `g1`, zero torques and a contact-free step;
its registry entry and schemas; the run manifest and `RunId`; chunked state digests; T0 metrics; the `run` and
`episode` rows; the recorded command; re-execution semantics; cancellation between chunks.
Out: contact, controllers, designs other than the catalog model, other tiers and profiles (later forms of the
verb); the full ledger schema and `.frun` (BD-090); the publishing transaction (BD-091); the worker-process run
(BD-038); replay (BD-203).

## Technical approach

1. **Registry entry.** The row of `sim.run` in `registries/verbs.toml` is entered by the cluster registry bead
   VERBS-sim and is not redefined here: `cluster = "sim"`, `kind = "run"`, `tier = "S"`, `capabilities =
   ["sim:run"]`, `input_schema = "frob.sim.run.in/1"`, `output_schema = "frob.sim.run.out/1"`, `first_milestone
   = "M0"`, `idempotent = false` (the rule for every `run` verb: it takes an idempotency key), the `--estimate`
   cost model, `wait = { cli = "to-completion", mcp_ms = 5000, mcp_max_ms = 30000 }`, owner `frob-dyn`. This bead
   links the M0 handler to that row, whose `examples` already carry the M0 example `frob sim run g1 --tier referee
   --seconds 2 --key run-m0 --json`, and raises only the refusals the M0 handler can actually raise: FROB-REF-802 (schema failure, exit 3),
   FROB-REF-724 (not implemented in this build, exit 5) and FROB-REF-790 (`foundation-group-absent`: the binary
   lacks the `referee` group of `frob-fsim`, exit 5). The chapter refusals of the row (212, 220 to 224, 246, 247,
   601, 602, 610, 721, 722) arrive with the M2 handler (N16b-25) and are not raised at M0.
2. **Input.** `design` (the positional, named as in the row; M0: only `g1`; any other design is FROB-REF-724,
   exit 5, because designs other than the catalog model arrive at M1; `--fixture <name>` is N24b-03's
   registered-fixture input, which enters the schema at M1, so at M0 it is an unknown parameter, FROB-REF-802,
   exit 3), `tier` (an enumeration in `frob.sim.run.in/1`: `referee`,
   `batch-cpu`, `gpu-cuda`, `gpu-metal`; at M0 only `referee` is implemented: a tier of the enumeration other
   than `referee` is FROB-REF-724, "not implemented in this build", exit 5; a value outside the enumeration,
   such as the misspelling `refere`, fails the input schema: FROB-REF-802, exit 3, `pointer` at `/tier`, never
   a silent default), `seconds` (an exact rational > 0 whose product with 480 is a whole number, so that
   N = 480·seconds steps of h = 1/480 s; any other value is FROB-REF-802, exit 3, `pointer` at `/seconds`: the
   step count is never rounded; default 2), `seed` (u64, a string on the wire; default 0), `worlds` (M0: 1; any
   other count is FROB-REF-724), `idempotency_key` (`--key`; optional on the CLI at M0, FROB-REF-805 for a
   missing key from M1; every script and example passes one), `sync_wait_ms`.
3. **Manifest and identity.** The manifest core is canonical JSON: design and model identity (BLAKE3 of the
   catalog model's canonical description as the airlock reports it), tier, step h = 1/480 s as the rational
   `[1, 480]`, step count N = seconds·480 = 960, seed, chunk length L = 256 steps, the kernel and foundation pins
   (the stack receipt hash), and the three no-authorization flags, all `false`. `RunId` = BLAKE3 of those bytes.
   At M0 one control tick is one physics step. The test-only perturbation flag (`--perturb-ulp q0`, compiled
   only in conformance builds) is a manifest field when present, so a perturbed run has its own `RunId` and can
   never be mistaken for a non-reproducing re-execution of the default run.
4. **Execution.** Through `RefereeDynamics` (BD-007): `catalog_model(G1)`, `reference_state`, then N calls of
   `step_free` with zero torques. After steps 256, 512, 768 and 960 (the ends of chunks 0 to 3; the last chunk
   is cut short by the terminal step) the state digest is computed. Cancellation is checked at each chunk end:
   request, stop, finalize; a cancelled run writes no `episode` row and its envelope says `cancelled` with the
   last completed chunk.
5. **T0 record.** Per chunk: `(index, tick_range, state_digest)`. Per episode: steps completed, simulated
   seconds as a rational, the final state digest, the digest of forward dynamics at the reference state (the
   quantity BD-007 gates), the catalog facts (links, nq, nv, total mass in kg), outcome `completed`, and two
   sanity metrics that are recorded and not gated: the drop of the centre of mass and the vertical momentum at
   the end, which for a free body under gravity are near −½·g·t² and −m·g·t (with g and m read from the model).
6. **Ledger.** One transaction through the `Ledger` adapter (BD-009): upsert the `run` row keyed by `RunId`
   (manifest hash, identities, tier, stack receipt hash, state), insert the `episode` row keyed by `(RunId,
   world 0, episode 0)` with the T0 record, and insert an `execution` entry with a fresh 128-bit time-ordered
   trace identifier and the wall-clock start and end. The trace identifier and the times never enter a content
   hash.
7. **Re-execution.** A second invocation with the same manifest, under an idempotency key distinct from the
   first one's, has the same `RunId`. (A call that repeats a stored key with the same request returns the stored
   receipt and runs nothing, by the binding of the common `run` inputs; the same key with a different request is
   FROB-REF-803.) It runs again and compares its chunk digests with the stored ones: equal adds an execution entry and returns the same result with
   `reproduced: true`; unequal returns exit 2 with the finding `digest-mismatch`, the first differing chunk and
   both digests, and marks the run `determinism-violated`. Nothing is overwritten.
8. **Envelope.** `result`: `run`, `final_state_digest`, `chunks`, `steps`, `sim_seconds`, `oracle_match`
   (the forward-dynamics digest compared with the committed oracle fixture
   `tests/fixtures/oracle/fsim/g1_fd_digest.toml` for the same pin: `equal`, `different` or `no-fixture`),
   `rollout_match` (the final state digest after the 960 steps compared with the field `rollout_2s_digest` of
   the same fixture, which BD-007's in-tree probe computes inside FrankenSim's own tree by the same 960 calls of
   the step at h = 1/480 s from the same reference state with zero torques: `equal`, `different` or
   `no-fixture`), `reproduced`, `recorded_command` (the exact argument vector, with every default made explicit
   and without the idempotency key, which belongs to one request and not to the work; DESIGN: a recorded key
   would make a later re-execution return the stored receipt, so whoever re-executes passes a fresh `--key`).
   `evidence`: class `Tested`, tier `referee`, model identity, determinism class `D2` (bitwise on the same
   platform, binary and toolchain; no cross-platform claim until FrankenSim's deterministic elementary functions
   are in use, FD-FSIM-07), seed, `claims: []`, `reality: "no-claim"`. Exit 0; exit 2 on `digest-mismatch`,
   `oracle_match: different` or `rollout_match: different`. `no-fixture` is reported as a finding (exit 2), never
   as a pass: a fixture whose pin differs from the lock's pin counts as missing.
9. **Layout.** `crates/frob-verbs/src/verbs/sim_run.rs` (handler), `crates/frob-chronicle/src/m0.rs` (manifest,
   T0 record, ledger write) which BD-090 later absorbs into the full schema by a migration.

## Acceptance criteria

- [ ] Seed done-condition: a fresh session, given only the `recorded_command` string from a first session's
      envelope, runs it on the same machine under a fresh `--key` and obtains the same `RunId`, the same four
      chunk digests and the same final digest, with `reproduced: true`.
- [ ] `oracle_match` is `equal` against the oracle fixture captured inside FrankenSim at the pinned commit.
- [ ] M0 artifact (§43.3): `rollout_match` is `equal`: the final two-second state digest equals the one
      FrankenSim's own tree computes for the same rollout at the same pin; a missing or stale fixture field is a
      failing finding, not a pass.
- [ ] A perturbed run (seed unchanged, one unit in the last place added to the first joint coordinate through
      the test-only flag) yields a different final digest, `oracle_match: different` and `rollout_match:
      different`, exit 2.
- [ ] The ledger holds one `run` row, one `episode` row and two execution entries after two invocations.
- [ ] With `--json` exactly one envelope is written; integers that can exceed 2⁵³ (seed, digests as hex) are
      strings; the three no-authorization flags are present and `false`.
- [ ] `--tier batch-cpu` is refused with FROB-REF-724 and exit 5; `--tier refere` (outside the enumeration) and an unknown flag are FROB-REF-802, exit 3, the first with `pointer` `/tier`; `--seconds 0.01` (4.8 steps) is FROB-REF-802 with `pointer` `/seconds`; none of them runs or writes a `run` row.
- [ ] A cancel between chunks leaves no `episode` row and reports the last completed chunk.
- [ ] The verb is reachable through `frob --json` and through the MCP tool `sim_run`.

## Test plan

### Unit tests

- `manifest_canonical_and_stable`: the manifest for the default command serializes to the same bytes twice and
  on both operating systems; a changed seed changes `RunId`.
- `chunk_boundaries_m0`: N = 960, L = 256 gives chunks [0, 256), [256, 512), [512, 768), [768, 960).
- `reexecution_same_run_id_new_trace`: two executions under keys `k-a` and `k-b` share `RunId` and differ in
  trace identifier; a third call under `k-a` with the same request returns the stored receipt and adds no
  execution entry; `recorded_command` contains no `--key`.
- `digest_mismatch_is_finding_not_overwrite`: a stored chunk digest altered in a scratch ledger gives exit 2,
  names chunk index and both digests, leaves the stored row unchanged.
- `tier_not_implemented_724` (`batch-cpu`, `gpu-cuda` and `gpu-metal` each give 724, exit 5),
  `tier_misspelt_802` (`refere` gives 802, exit 3, `pointer` `/tier`; no run), `unknown_flag_802`.
- `seconds_whole_steps`: `2` → N = 960; `0.025` → N = 12; `1/48` → N = 10; `0.01` and `0` → 802 with `pointer`
  `/seconds` and no run.
- `rollout_match_fail_closed`: a scratch copy of the fixture with `rollout_2s_digest` removed gives
  `rollout_match: no-fixture` and exit 2; a copy whose recorded pin differs from the lock's pin gives the same;
  neither is ever reported as `equal`.
- `registry_row_from_verbs_sim`: the linked row reads `kind = "run"`, `idempotent = false`, owner `frob-dyn`, its
  positional input is `design`, and its `examples` include `frob sim run g1 --tier referee --seconds 2 --key
  run-m0 --json`; the handler raises no code outside {802, 724, 790} at M0; `--fixture g1` at M0 is 802.
- `cancel_between_chunks`: a cancel raised after chunk 1 stops before chunk 2 completes.
- `sanity_metrics_recorded`: centre-of-mass drop within g·t·h = 0.041 m of ½·g·t² = 19.62 m for g = 9.81 m/s²
  and t = 2 s (the bound of a first-order scheme; recorded, not gated).

### End-to-end script and logging

`scripts/e2e/sim_run_referee_g1.sh` (every call carries its own `--key`, convention 5): (1) `frob sim run g1
--tier referee --seconds 2 --key run-m0 --json`; (2) extract `recorded_command`; (3) run it in a second process
with an empty environment except the store path, adding `--key run-m0-reexec`; (4) assert
equal `RunId`, chunk digests and final digest, `reproduced: true`, `oracle_match: equal` and `rollout_match:
equal`; (5) run the perturbed control (conformance build, `--perturb-ulp q0 --key run-m0-perturb`) and assert
exit 2 with both matches `different`; (6) run `--tier
batch-cpu` and assert exit 5 and code FROB-REF-724, then `--tier refere` and assert exit 3, code FROB-REF-802
and `pointer` `/tier`, neither leaving a `run` row; (7) call the MCP tool `sim_run` over stdio through `frob-mcp`
with the same arguments and the key `run-m0-mcp` and assert one envelope whose `RunId` and final digest equal the CLI's; (8) count the
ledger rows of the default `RunId` (`run` 1, `episode` 1, execution entries 3: steps 1, 3 and 7) and check that
the perturbed run has its own `RunId`. It writes
`target/e2e-logs/sim_run_referee_g1/<utc>.ndjson` with, per line, `ts`, `script`, `bead`, `step`, `event`, the
command, exit code, wall time, the evidence block, each digest compared (candidate and oracle), the sanity
metrics with units (centre-of-mass drop in m, vertical momentum in kg·m/s, wall seconds per simulated second),
and on failure the first differing chunk with both digests, the fixture path and pin, and the store path; a
final `summary` line with assertions passed and failed.

### Known answers and negative controls

- Known answers: the forward-dynamics digest and the two-second rollout digest equal the in-tree oracle's
  (BD-007's fixture, never regenerated from the candidate).
- Negative controls: the last-place perturbation; the altered stored digest; the fixture with the rollout field
  removed (must not pass).
- Determinism lanes: twice on one machine; debug and release; the Mac and the Linux host are compared and the
  result recorded (the referee makes no cross-platform bit claim until FrankenSim's deterministic elementary
  functions are in use, so a difference there is recorded and is not a failure of this bead).

## Considerations

- Clauses of the definition of "implemented" still open after this bead: a `CONTRACT.md` for `frob-chronicle`
  (BD-090), a recorded gate (the M0 exit review reads this bead's log), and the full cancellation test on
  devices. The capability is described as partial until then.
- If the digest differs from FrankenSim's own, that is a finding about consumption (toolchain, feature
  unification or flags) recorded as failing; the run is not repeated until it happens to pass.
- The rollout field of the oracle fixture is written by BD-007's capture script (its in-tree probe already
  steps 960 times; the field records that digest). Until it exists `rollout_match` is `no-fixture` and the M0
  artifact is not met; fail-closed.
- The equal chunk digests through `frob-fsim-worker` (the second half of the M0 artifact) are BD-038's.
- The chunk length of 256 is the fail-closed default of the open question on chunk length; it is a manifest
  field, so a later choice changes `RunId` and nothing else.
