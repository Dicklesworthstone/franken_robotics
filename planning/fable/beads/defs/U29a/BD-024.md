## Background

The first milestone (M0, "spine and airlock") builds almost nothing and measures the risks that could invalidate
the architecture. One of its artifacts is a single command, `frob sim run g1 --tier referee --seconds 2`, that
steps FrankenSim's built-in 29-joint humanoid (the Unitree G1 model in `fs-mbd::robot_models`) for two seconds on
the referee tier and produces a state digest equal to the one FrankenSim computes for itself. It proves four
things at once: the foundation can be consumed from outside its tree through the airlock crate `frob-fsim`; the
verb skeleton writes one well-formed envelope; a result reaches the ledger with its identities; and a second
session can reproduce the artifact from the recorded command alone. The seed done-condition is the last of
these: a fresh session reproduces the M0 artifact from the recorded command.

This bead is the thin slice of the record subsystem (Chronicle) that exists at M0. The full ledger schema, the
`.frun` format and the chunk protocol arrive at M1; here the run writes to the minimal `run` and `episode`
tables of the M0 ledger adapter. The slice still obeys the rules the full system keeps: no naked number reaches
the agent (every output carries its evidence block), two executions of the same work produce the same
identifiers and different execution traces, and a world is determined by its address and identities.

Terms. The *referee* is the double-precision reference tier built on FrankenSim's articulated dynamics. A *state
digest* is the 32-byte BLAKE3 of the canonical referee-state byte string (domain tag `frob.referee-state/1`, the
link and coordinate counts, then every element of position and velocity as its IEEE-754 bit pattern,
little-endian). *T0* is the telemetry level that every world always keeps: per-episode metrics and state digests
at intervals. A *world address* is `(run_seed, world, episode)`.

Rejected alternative: a test binary that prints a digest. It would prove consumption but not the verb, the
envelope, the ledger or reproduction by a stranger, which are what later milestones stand on.

## Scope

In: the verb `sim.run` restricted to `--tier referee`, the fixture `g1`, zero torques and a contact-free step;
its registry entry and schemas; the run manifest and `RunId`; chunked state digests; T0 metrics; the `run` and
`episode` rows; the recorded command; re-execution semantics; cancellation between chunks.
Out: contact, controllers, designs other than the catalog model, other tiers and profiles (later forms of the
verb); the full ledger schema and `.frun` (BD-090); the publishing transaction (BD-091); the worker-process run
(BD-038); replay (BD-203).

## Technical approach

1. **Registry entry** (`registries/verbs.toml`): `name = "sim.run"`, `cluster = "sim"`, `kind = "run"`,
   `tier = "S"`, `capabilities = ["sim:run"]`, `input_schema = "frob.sim.run.in/1"`, `output_schema =
   "frob.sim.run.out/1"`, `first_milestone = "M0"`, `idempotent = true`, `cost_model = "referee: about real time
   per core"`, `examples = ["frob sim run g1 --tier referee --seconds 2 --json"]`,
   `refusals = ["FROB-REF-802", "FROB-REF-724", "FROB-REF-790"]`.
2. **Input.** `fixture` (M0: only `g1`), `tier` (M0: only `referee`; any other value is FROB-REF-724, "not
   implemented in this build", exit 5), `seconds` (an exact rational; default 2), `seed` (u64, a string on the
   wire; default 0), `worlds` (M0: 1), `idempotency_key` (optional on the CLI at M0), `sync_wait_ms`.
3. **Manifest and identity.** The manifest core is canonical JSON: fixture and model identity (BLAKE3 of the
   catalog model's canonical description as the airlock reports it), tier, step h = 1/480 s as the rational
   `[1, 480]`, step count N = seconds·480 = 960, seed, chunk length L = 256 steps, the kernel and foundation pins
   (the stack receipt hash), and the three no-authorization flags, all `false`. `RunId` = BLAKE3 of those bytes.
   At M0 one control tick is one physics step.
4. **Execution.** Through `RefereeDynamics` (BD-007): `catalog_model(G1)`, `reference_state`, then N calls of
   `step_free` with zero torques. After steps 256, 512, 768 and 960 (the ends of chunks 0 to 3; the last chunk
   is cut short by the terminal step) the state digest is computed. Cancellation is checked at each chunk end:
   request, stop, finalize; a cancelled run writes no `episode` row and its envelope says `cancelled` with the
   last completed chunk.
5. **T0 record.** Per chunk: `(index, tick_range, state_digest)`. Per episode: steps completed, simulated
   seconds as a rational, the final state digest, the digest of forward dynamics at the reference state (the
   quantity BD-007 gates), the catalog facts (links, nq, nv, total mass in kg), outcome `completed`, and two
   sanity metrics that are recorded and not gated: the drop of the centre of mass and the vertical momentum at
   the end, which for a free body under gravity are near −½·g·t² and −m·g·t (with g and m read from the model).
6. **Ledger.** One transaction through the `Ledger` adapter (BD-009): upsert the `run` row keyed by `RunId`
   (manifest hash, identities, tier, stack receipt hash, state), insert the `episode` row keyed by `(RunId,
   world 0, episode 0)` with the T0 record, and insert an `execution` entry with a fresh 128-bit time-ordered
   trace identifier and the wall-clock start and end. The trace identifier and the times never enter a content
   hash.
7. **Re-execution.** A second invocation with the same manifest has the same `RunId`. It runs again and compares
   its chunk digests with the stored ones: equal adds an execution entry and returns the same result with
   `reproduced: true`; unequal returns exit 2 with the finding `digest-mismatch`, the first differing chunk and
   both digests, and marks the run `determinism-violated`. Nothing is overwritten.
8. **Envelope.** `result`: `run`, `final_state_digest`, `chunks`, `steps`, `sim_seconds`, `oracle_match`
   (the forward-dynamics digest compared with the committed oracle fixture
   `tests/fixtures/oracle/fsim/g1_fd_digest.toml` for the same pin: `equal`, `different` or `no-fixture`),
   `reproduced`, `recorded_command` (the exact argument vector, with every default made explicit).
   `evidence`: class `Tested`, tier `referee`, model identity, determinism "bitwise on the same platform and
   binary", seed, `claims: []`, `reality: "no-claim"`. Exit 0; exit 2 on `digest-mismatch` or
   `oracle_match: different`.
9. **Layout.** `crates/frob-verbs/src/verbs/sim_run.rs` (handler), `crates/frob-chronicle/src/m0.rs` (manifest,
   T0 record, ledger write) which BD-090 later absorbs into the full schema by a migration.

## Acceptance criteria

- [ ] Seed done-condition: a fresh session, given only the `recorded_command` string from a first session's
      envelope, runs it on the same machine and obtains the same `RunId`, the same four chunk digests and the
      same final digest, with `reproduced: true`.
- [ ] `oracle_match` is `equal` against the oracle fixture captured inside FrankenSim at the pinned commit.
- [ ] A perturbed run (seed unchanged, one unit in the last place added to the first joint coordinate through
      the test-only flag) yields a different final digest and `oracle_match: different`, exit 2.
- [ ] The ledger holds one `run` row, one `episode` row and two execution entries after two invocations.
- [ ] With `--json` exactly one envelope is written; integers that can exceed 2⁵³ (seed, digests as hex) are
      strings; the three no-authorization flags are present and `false`.
- [ ] `--tier batch-cpu` is refused with FROB-REF-724 and exit 5; an unknown flag is FROB-REF-802, exit 3.
- [ ] A cancel between chunks leaves no `episode` row and reports the last completed chunk.
- [ ] The verb is reachable through `frob --json` and through the MCP tool `sim_run`.

## Test plan

### Unit tests

- `manifest_canonical_and_stable`: the manifest for the default command serializes to the same bytes twice and
  on both operating systems; a changed seed changes `RunId`.
- `chunk_boundaries_m0`: N = 960, L = 256 gives chunks [0, 256), [256, 512), [512, 768), [768, 960).
- `reexecution_same_run_id_new_trace`: two executions share `RunId` and differ in trace identifier.
- `digest_mismatch_is_finding_not_overwrite`: a stored chunk digest altered in a scratch ledger gives exit 2,
  names chunk index and both digests, leaves the stored row unchanged.
- `tier_not_implemented_724`, `unknown_flag_802`.
- `cancel_between_chunks`: a cancel raised after chunk 1 stops before chunk 2 completes.
- `sanity_metrics_recorded`: centre-of-mass drop within g·t·h = 0.041 m of ½·g·t² = 19.62 m for g = 9.81 m/s²
  and t = 2 s (the bound of a first-order scheme; recorded, not gated).

### End-to-end script and logging

`scripts/e2e/sim_run_referee_g1.sh`: (1) `frob sim run g1 --tier referee --seconds 2 --json`; (2) extract
`recorded_command`; (3) run it in a second process with an empty environment except the store path; (4) assert
equal `RunId`, chunk digests and final digest, and `reproduced: true`; (5) run the perturbed control and assert
exit 2; (6) run `--tier batch-cpu` and assert exit 5. It writes
`target/e2e-logs/sim_run_referee_g1/<utc>.ndjson` with, per line, `ts`, `script`, `bead`, `step`, `event`, the
command, exit code, wall time, the evidence block, each digest compared, and on failure the first differing
chunk with both digests and the store path; a final `summary` line.

### Known answers and negative controls

- Known answer: the forward-dynamics digest equals the in-tree oracle's (BD-007's fixture, never regenerated
  from the candidate).
- Negative controls: the last-place perturbation; the altered stored digest.
- Determinism lanes: twice on one machine; debug and release; the Mac and the Linux host are compared and the
  result recorded (the referee makes no cross-platform bit claim until FrankenSim's deterministic elementary
  functions are in use, so a difference there is recorded and is not a failure of this bead).

## Considerations

- Clauses of the definition of "implemented" still open after this bead: a `CONTRACT.md` for `frob-chronicle`
  (BD-090), a recorded gate (the M0 exit review reads this bead's log), and the full cancellation test on
  devices. The capability is described as partial until then.
- If the digest differs from FrankenSim's own, that is a finding about consumption (toolchain, feature
  unification or flags) recorded as failing; the run is not repeated until it happens to pass.
- The chunk length of 256 is the fail-closed default of the open question on chunk length; it is a manifest
  field, so a later choice changes `RunId` and nothing else.
