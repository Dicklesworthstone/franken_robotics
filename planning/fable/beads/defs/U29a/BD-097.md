## Background

Everything the record holds is either a ledger row or a content-addressed object: a column file, a snapshot, a
certificate bundle, a report, a still. An agent needs a small, safe way to see what exists and to fetch bytes:
which runs are mine, what is this run, what objects does it have, give me bytes 4,096 to 8,191 of this object,
copy this object to my export directory. These five verbs are that way. They belong to the `artifact` and `run`
clusters, whose owner is the record subsystem (Chronicle); the implementations live with the other verbs in
`frob-verbs` and call `frob-chronicle`. First milestone M1, tier Solid.

Seed done-condition: a byte-range read returns bytes whose digest matches the record; a traversal path is
refused.

Three rules shape them.
- **Objects are named by digest, never by path.** A resource identifier names a registry row or a
  content-addressed object in the store; it is never a filesystem path. The only path an agent supplies is an
  export destination, and that path is confined.
- **The path jail uses a retained directory handle.** Smallest case that breaks a string check: `exports/a` is
  checked as inside the export root, then replaced by a link to another directory before it is opened; the
  string check passes and the write lands outside. Opening relative to a handle of the root that was obtained
  once and kept closes that race.
- **Large objects are read in ranges.** A single answer returns at most 4 MiB (TARGET, the same limit as a
  resource read); a longer object is read by repeated calls.

Rejected alternative: a generic "read file" verb with a path argument filtered by pattern. It makes every
future path bug a data leak.

## Scope

In: the five verbs with registry entries, schemas, refusals and envelopes; integrity checking on read; listing
with pinned pagination; the export root and its jail; privacy, licence and sealed-run refusals as applied here.
Out: `run.export` of a whole `.frun` bundle (N29a-02); `run.fork` (the fork bead of another unit); summaries
(the summary verb); retention and tombstones (BD-209), except that a read of a collected object reports its
tombstone; session tokens and scopes in full (BD-258). The later extensions of these verbs, each through this
bead's handlers and each in its owner bead: on `artifact.export`, the cross-machine form `--to-host <mac|trj>`
with several digests and `--campaign`, the `frob.xfer/1` bundle, its `transfer` block and FROB-REF-618 (a
transfer class that may not cross machines; N21c-08, M2), `--replay-closure <run>:<address>` (N21c-09, M2), and
the scene-pack check that raises FROB-REF-310 through `ScenePack::export_check` (N19b-02, M3, with the export
door of N37-18); the verb `artifact.import` that admits a bundle (N21c-08, M2); on `run.show`, the run summary
sized to `--budget` (N24a-35, M1), `--receipt` (N19c-35) and `--phase-ledger` (N21a-27).

## Technical approach

**Registry entries.** The rows are entered by the cluster registry beads VERBS-artifact and VERBS-run (schemas
`frob.<verb>.in/1` and `frob.<verb>.out/1`, examples, owner `frob-chronicle`, `idempotent = true` for the read
verbs and `false` for `artifact.export`, which takes an idempotency key); this bead implements the handlers and
does not redefine the rows. First milestone M1 for all:

| Verb | Kind | Capability | What it returns |
|---|---|---|---|
| `artifact.read` | read | `artifact:read` | Bytes of one object by digest and byte range |
| `artifact.list` | read | `artifact:read` | Objects of a run or of a kind, paged |
| `artifact.export` | run | `artifact:run`, `export:report` (and `private:export` for a private object) | A copy of one object under the session's export root |
| `run.show` | read | `run:read` | A run's manifest, standing and summary |
| `run.list` | read | `run:read` | Runs in the caller's namespace, paged |

CLI forms (the registry examples run verbatim): `frob artifact read b3:<hex> --range <start>-<end>` (inclusive
byte offsets; `<start>-` reads to the end; the schema fields are `offset` and `length`), `frob artifact list
[--run <run>] [--kind <kind>]`, `frob artifact export b3:<hex> --out <path> --key <key>` (a path ending in `/`
is a directory and the file is named `<hex>.<kind extension>`), `frob run show <run>`, `frob run list`.

**`artifact.read`.** Input: `digest` (`b3:` and 64 hex digits of BLAKE3), `offset` (default 0), `length`
(default: to the end, at most 4 MiB; a larger request is truncated to the limit and says so in `next_offset`).
Algorithm:
1. Look the digest up in the object index; unknown is FROB-REF-802 with the pointer `digest`. If a tombstone
   exists for it, refuse with FROB-REF-869 and the tombstone's class, time and reason.
2. Check the object's privacy mark (FROB-REF-731 without `private:read`) and that its run is not a sealed
   confirmation run (FROB-REF-840).
3. Verify integrity once per process per object: recompute BLAKE3 over the stored bytes and compare with the
   name. A mismatch is an integrity fault: exit 9, the object is quarantined and never served.
4. Return `{digest, kind, total_bytes, offset, length, range_blake3, bytes_b64, next_offset}`. `range_blake3`
   is the hash of the returned bytes, so a client can check each transfer; the concatenation of all ranges
   hashes to `digest`.

**Object kinds (DESIGN).** Every object in the store carries a kind, recorded in the ledger when the object is
written and never declared by a caller. The kinds are the rows of one table, `ObjectKind` in
`crates/frob-chronicle/src/objects.rs`: a name and the file extension an export uses (`<hex>.<extension>`). At
M1 it holds the seven kinds the record writes: `column` (`.fcol`), `snapshot`, `certificate` (`.frobcert`),
`receipt`, `report`, `still` and `bundle` (`.frun`). A bead that stores objects of a new kind adds its row in the
same change: the transfer bundle `frob.xfer/1` (`.frobxfer`) admitted by N21c-08's import, scene packs and kit
or starter packs (N19b-02), policy weights and scene recipes as their owners store them. The same recorded kind
is the one from which N21c-08 derives an item's transfer class, so the filter, the export name and the class
cannot disagree.

**`artifact.list`.** Input: `run` or `kind` (any row of the kind table, the input's enumeration generated from
it, so a kind added by a later bead is listable in the change that adds it, an additive schema change; DESIGN:
the format registry `registries/formats.toml` is not the domain, because it lists file formats, not store
objects: column files, snapshots, receipts and stills are absent from it, and most of its formats never sit in
the store; a kind outside the table is FROB-REF-802 with the pointer `kind` and the table's kinds listed),
`limit`, `cursor`. Output rows: digest, kind, bytes, the ledger row that references it
(for a column file its chunk key), pinned or not. Ordered by (kind, digest); paged against the committed
frontier through the surface cursor `frob.cursor/1` of N32a-10 (its `Paginated` trait over the object index,
with `cursor`, `limit` and `follow`; a cursor with changed filters is FROB-REF-806, an expired pin
FROB-REF-807, both exit 3), so the answer states its `frontier`. Private objects are absent without the scope.

**`artifact.export`.** Input: `digest`, `out` (a path under the export root), `idempotency_key`. Algorithm:
privacy check (FROB-REF-731: a private object, or anything derived from one, needs `private:export` and the
per-call private flag) and licence check (FROB-REF-733: a licence class `research-only`, `proprietary` or
`unknown` forbids export); the export check of the object's kind, if its owner registered one (none at M1; the
hook through which N19b-02's `ScenePack::export_check` raises FROB-REF-310 from M3, its only raiser); for an object of a kind that carries the no-authorization flags, check that the
flags object is present with every field the literal `false` and no extra field (FROB-REF-816 otherwise, naming
`missing:<field>`, `true:<field>`, `not-false:<field>` or `extra:<field>`); open `out` relative to the retained
handle of the export root, refusing `..`, absolute paths and links that leave the root (FROB-REF-734); copy to a
temporary name while hashing; compare the hash with `digest`; rename into place. Output: the relative path,
bytes, the digest, and the `authorization` block with the three no-authorization flags, all `false`. A
repeated key with the same resolved request returns the stored receipt and writes nothing.

**`run.show`.** Input: `run`. Output: the manifest (identities, tier, determinism class, effort profile, chunk
length, channel schemas, seed as a string) and the *standing* (evidence standing `provisional` or
`established`: a fast-tier run is `provisional` until promoted to the referee; state: `admitted`, `running`,
`complete`, `failed`, `cancelled`, or `determinism-violated`; the terminal receipt with its four counts when one
exists; the commit sequence number as `frontier`; the gap count). Progress is always "k of n" with its unit. A
sealed confirmation run is refused with FROB-REF-840. The run summary sized to a token budget, with the input
`budget` (tokens, default 600), is added to this handler by the summary bead N24a-35, which builds the
summary; the input enters the schema in that change (VERBS-run's rule for inputs), so before it `--budget` on
`run.show` is FROB-REF-802.

**`run.list`.** Input: optional filters (`state`, `tier`, `design`, `task`, `since`), `limit`, `cursor`.
Output rows: run identifier, state, tier, world and episode counts, start instant, design and task identities.
Scope: the caller's namespace only. Ordered by (start instant, run identifier), paged with the same cursor
(806, 807, `follow`).

**Envelope.** `evidence` on all five verbs is *pass-through*: it carries the claim product of the stored
objects read (their class, tier and determinism class; for a run, the run's), adds no claim of its own
(`claims: []`), and the read itself is `exact`. Exit codes (from the owning registries): 0; 3 for FROB-REF-802,
-806, -807, -816 and -869; 5 for FROB-REF-731, -733 and -734, for FROB-REF-840 (sealed data is outside the
session's scopes, N24-REF) and for a missing scope (FROB-REF-720); 9 for an integrity fault.

**Layout.** `crates/frob-verbs/src/verbs/{artifact_read.rs, artifact_list.rs, artifact_export.rs, run_show.rs,
run_list.rs}`; `crates/frob-chronicle/src/objects.rs` (object index, integrity cache, quarantine).

## Acceptance criteria

- [ ] Seed done-condition, first half: for an object of 10 MiB read in ranges of 1 MiB, each `range_blake3`
      matches the returned bytes and the concatenation hashes to the object's digest in the record.
- [ ] Seed done-condition, second half: `artifact.export --out ../../x`, `--out /tmp/x` and a destination whose
      parent was swapped for a link after resolution are each refused with FROB-REF-734 (exit 5), and no byte is
      written outside the export root.
- [ ] An export of an object whose authorization flags have one field `true` is refused with FROB-REF-816
      naming the field; an export of a private object without `private:export` is FROB-REF-731; a
      `research-only` object is FROB-REF-733.
- [ ] The registry examples of VERBS-artifact and VERBS-run (`--range`, `--out`) run verbatim.
- [ ] A stored object with one flipped byte is never served: the read exits 9 and the object is quarantined.
- [ ] A read of a collected object is refused with its tombstone's reason; a read of an unknown digest is a
      schema-level refusal, not an empty answer.
- [ ] `run.list` shows only runs of the caller's namespace; a private run's objects are absent from
      `artifact.list` without the scope.
- [ ] `run.show` on a running run reports state, "k of n" progress and the frontier; on a sealed confirmation
      run it is refused with FROB-REF-840.
- [ ] Listing while chunks are being committed returns each object visible at the pin exactly once.
- [ ] `artifact.export` carries the authorization block with three `false` flags; a repeated key writes nothing.
- [ ] All five verbs are reachable through `frob --json` and as MCP tools (`artifact_read`, …, `run_list`),
      with schemas, examples and refusal lists in the registry.
- [ ] The `kind` enumeration of `artifact.list` is generated from the `ObjectKind` table; every stored object's
      recorded kind is a row of it; `scripts/e2e/record_read_verbs.sh` exits 0.

- `length_capped_at_4mib`: a request for 6 MiB returns 4 MiB and `next_offset = 4,194,304`.
- `offset_past_end_refused_802`.
- `flipped_byte_quarantined_exit_9`.
- `tombstoned_object_869`: class, time and reason echoed.
- `export_path_jail`: the three escapes; `export_inside_root_succeeds`; `export_hash_checked`.
- `export_idempotent_replay`.
- `export_flags_816`: objects whose flags object lacks a field, has a field `true`, or has an extra field are
  each refused with 816 and the matching pointer; `export_licence_733`: a `research-only` object is refused;
  `export_private_needs_private_export_731`.
- `range_syntax`: `--range 0-4095` gives offset 0 and length 4,096; `--range 4096-` reads to the end (at most
  4 MiB); `--range 10-5` is FROB-REF-802.
- `evidence_pass_through`: a read of a fast-tier run's column file carries that run's tier and `provisional`
  standing in its evidence block and `claims: []`.
- `private_absent_from_list`; `private_read_needs_scope_731`; `sealed_run_840` for `run.show` and
  `artifact.read`.
- `run_list_namespace_only`; `run_list_pagination_pinned`; `list_cursor_changed_filter_806` (an `artifact.list`

- `unknown_digest_is_refusal`.
- `kind_filter_from_table`: the input schema's `kind` values equal the `ObjectKind` rows (seven at M1); a

### End-to-end script and logging

`scripts/e2e/record_read_verbs.sh`, this bead's own script, built on its dependencies only (N29a-08's
composition script `scripts/e2e/chronicle_record_surface.sh` drives the same verbs together with the `.frun`
export and the offline auditor, and may run this one as a stage). A fresh store under `target/e2e-work/`, seed 7,
every run-kind call with its own key:
1. `frob sim run g1 --tier referee --seconds 2 --telemetry T2 --seed 7 --key rr-run --json` (BD-024 through
   BD-090's ledger).
2. `frob run list --json` holds the run once; `frob run show <run> --json` reports state `complete`, the frontier,
   chunk length 256 and progress "1 of 1".
3. `frob artifact list --run <run> --limit 5 --json`, paged until the cursor ends: no digest repeated; the
   cursor replayed with `--kind snapshot` is FROB-REF-806, exit 3; `--kind weights` (no row at M1) is
   FROB-REF-802, exit 3.
4. `frob artifact read <digest> --range <k·65536>-<k·65536 + 65535> --json` over the first column file until
   `next_offset` is null: each `range_blake3` against a local hash of the decoded bytes, the concatenation
   against the digest.
5. `frob artifact export <digest> --out exports/c0.fcol --key ax-1 --json`, then the same call again (the stored
   receipt, the file's modification time unchanged), then `--out exports/ --key ax-2` (the file `<hex>.fcol`);
   the three escapes (`--out ../escape`, `--out /tmp/escape`, a directory swapped for a link) with keys `ax-3`
   to `ax-5`, each FROB-REF-734, exit 5, nothing written outside the root.
6. One call of each of the five verbs as an MCP tool over stdio: the envelopes agree with the CLI's on `result`,
   `refusal` and `evidence`.
It sources the STD-E2E helper and writes `target/e2e-logs/record_read_verbs/<utc>.ndjson` and a transcript.
Lines carry `ts`, `script`, `bead`, `step`, `event`, the command, exit code, wall time, the evidence block, each
range's digest against the record, the frontier of each listing, the refusal code and exit of each refusal, and
on failure the first mismatching range with both hashes and the store and export paths; a final `summary` line.
No column bytes are logged.

### Known answers and negative controls

- Known answer: the object's digest in the ledger is the truth; the read must reproduce it.
- Negative controls: the flipped byte; the swapped link (a mutant that validates the path as a string must be
  caught by the link case); a mutant `run.list` without the namespace filter.
- The safety gate on the path jail (a corpus of traversal, absolute-path and swapped-link attempts refused on
  every path-taking argument of every verb) runs its corpus against `artifact.export` among the others.
- Determinism: listings and reads are pure functions of (store state at the pin, request); bytes compared on
  repeat.

## Considerations

- RISK-12 (a scan of a private place leaks through a derived artifact): mitigated here by computing the mark
  of an object as the join over its lineage and by keeping private objects out of listings.
- A read never triggers recomputation and never touches a device; these verbs work with no daemon.
- The 4 MiB limit is a TARGET; it bounds the size of one tool result on the MCP surface.
- The integrity check costs one hash of the object on first read; the result is cached by (digest, file
  metadata) and invalidated when the file changes.
