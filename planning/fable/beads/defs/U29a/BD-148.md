## Background

The model compiler turns a design into an immutable `RobotModel` with a content identity, `ModelId`, and then
lowers that model four ways: to the referee's articulated model; to packed structure-of-arrays buffers for the
batched tiers, with depth levels and a path table for sparse Jacobians; to analysis views; and to a variant
record inside a size bucket. This bead is the second lowering. It belongs to the design subsystem (Skeleton,
crate `frob-model`, layer 2) and is the first bead of the batched step at milestone M2: every batched kernel
reads the tables it produces.

Why packed tables. On the batched tiers (`batch-cpu`, CUDA, Metal) the same ten-stage step runs over thousands
of worlds with fixed buffer shapes. Morphology is table data inside padded capacities: no interpreter and no
compile per design. A joint is its screw basis with a column count, so one derived kernel handles every joint
class with no branch on joint kind. The tree is processed level by level, all links of one depth in parallel,
which needs links sorted by depth with the start of each level known.

Decisions that bind the bead:
- **ADR-MARROW-04: packed single-precision layouts are generated, not typed.** There is no hand-written `Se3f32`
  struct. The kernel IR crate emits structure-of-arrays layouts from the same algebraic description as the host
  types, so the host type and the kernel layout cannot disagree.
- **Link numbering is topological:** the parent index λ(i) is less than i, and depth levels are precomputed.
- **Padding is exact:** padding links are identity transforms with zero inertia, appended after the real links
  and masked out of every sum; the real part of every result is bit-identical to the unpadded computation.
- **Capacities are read, not compiled:** kernels read capacities from the step-plan header; a new bucket size
  needs new buffers and no kernel compile.

A *shape class* is the set of capacities one static step plan is built for; its hash, the `ShapeClassId`, is
part of the step plan's identity. Seed done-condition: the layout digest is stable across platforms. Tier Solid.

Rejected alternative: lowering per backend with backend-specific structs. Three layouts would drift, and the
digest of a world's tables could not be compared across tiers.

## Technical approach

**1. Canonical link order.** Input: the kinematic tree of `RobotModel` (after fixed-joint folding). Sort links
by (depth, canonical sibling order from the model), root first; this gives λ(i) < i and depth(i) =
depth(λ(i)) + 1. `level_start[d]` is the index of the first link of depth d, with a final entry equal to the
link count, so level d is the range `level_start[d] .. level_start[d+1]`.

**2. The model table (DESIGN: the type sketch is normative for fields, not for signatures).**

```rust
pub struct ModelTable {           // one per model slot; read-only in a rollout; about 192 bytes per link
    pub model: ModelId,
    pub level_start: Vec<u16>,    // links sorted by depth; ranges per level
    pub parent: Vec<u16>,         // parent index, less than the link's own; padding links are roots of nothing
    pub placement: Vec<Se3Packed>,            // parent_from_joint
    pub screw: Vec<[f32; 18]>,    // screw basis S in ℝ^(6×3), angular rows first
    pub screw_cols: Vec<u8>,      // k = 0 (padding), 1, 2 or 3 active columns: joint classes are data
    pub inertia: Vec<[f32; 10]>,  // mass, first moment (3), second moment (6): pseudo-inertia about the body origin
    pub limits: Vec<JointLimits>,
    pub actuator_slot: Vec<u16>,
    pub sample_range: Vec<(u16, u16)>,
}
```

Additional columns this bead defines: `dof_start: Vec<u16>` (offset of the link's joint coordinates in the
velocity vector; the floating base occupies coordinates 0 to 5), `path_start: Vec<u16>` and `path_dofs:
Vec<u16>` (the path table), and `sample_table` (per collision sample: owning link, primitive kind, local
position and radius). The root's `parent` is the sentinel 0xFFFF.

Column count per joint class: k = 1 for revolute, prismatic and helical joints; 2 for cylindrical and
universal; 3 for spherical and planar. Unused screw columns are zero and masked by `screw_cols`. A revolute
coordinate is stored in state as a unit complex number with an integer turn count; limits are stored for the
half-angle tangent and the turn count, so no raw angle appears in a table.

**3. Layout generation.** The byte layout of each column (field order, element type, stride, alignment 4 bytes
within a column, columns aligned to 256 bytes when packed into a slab) is emitted by the kernel IR's layout
descriptor from the algebraic description of each type; `Se3Packed` is the descriptor's output for a rigid
transform (unit quaternion and translation, seven `f32`), not a struct in this crate. The descriptor's canonical
text is hashed to the **layout digest** (`LayoutId`, BLAKE3).

**4. Conversion to single precision.** Each double-precision model value is converted with round-to-nearest-even
(the language's defined cast), which is the same on every platform. The lowering calls no platform elementary
function: quaternions, screws and inertias arrive from the model compiler as numbers, and only rational scaling
and the cast are applied. A value that overflows `f32` or is not finite is a refusal naming the field.

**5. The path table.** For link i the support path is the list of velocity-coordinate indices of every joint
on the path from the root to i, root first, including the six base coordinates when the base floats. A contact
row on link i touches only those coordinates, so a compact Jacobian needs about R·(6 + depth) entries instead
of R·n_v. `path_dofs[path_start[i] .. path_start[i+1]]` holds link i's list in ascending order. The table's
width cap is `path_cap = 6 + (sum of k along the deepest path)`, recorded with the counts.

**6. Counts.** `PackedCounts { n_v, links, depth, actuators, samples, path_cap, structure: Blake3 }`:
n_v is the number of velocity coordinates with the floating base included; `structure` is the hash of
(parents, `screw_cols`, `level_start`) and is equal for two models that differ only in parameter values.

**7. Padding to a class.** `pad(table, class)` appends padding links up to `class.links`: `parent` = 0xFFFF,
identity placement (quaternion (1, 0, 0, 0), zero translation), `screw_cols` = 0, zero screw and inertia stored
as −0.0 (the neutral element for sums, so that a reduction over the padded axis has the same bits at any
capacity), empty sample range, no actuator. `level_start` gains no level for padding. Padding never changes a
real row, and `pad` then `unpad` is the identity.

**8. `ShapeClass` and `ShapeClassId`.** The plain-data type lives here so that every later crate shares one
definition: `n_v`, `links`, `depth`, `samples`, `contacts` (C, the active-contact capacity), `rows` (R, the
constraint-row capacity), `actuators`, `sensor_layout`, `policy_layout`, `contact_law`, `precision` (`default`
or `stiff`), `iterations` (the lockstep iteration count, a class constant), `single_structure` (one tree,
unmasked path). `ShapeClassId` = BLAKE3 over the domain tag `frob.shape-class/1`, a zero byte, and the fields in
that order as little-endian integers (identifiers as their 32 bytes, booleans and enums as one byte). The
default degree-of-freedom sizes are 12, 18, 24, 36, 48 and 64.

**9. Content digest.** `packed_digest` = BLAKE3 over the layout digest followed by every column's bytes in
layout order, little-endian. It is a pure function of (`ModelId`, compiler version, layout version).

**10. Layout.** `crates/frob-model/src/packed/{order.rs, table.rs, path.rs, pad.rs, shape_class.rs,
digest.rs}`.

## Acceptance criteria

- [ ] Seed done-condition: for the four first archetypes and the built-in humanoid, the layout digest and the
      content digest computed on the Mac (arm64) and on the Linux host (x86-64), in debug and in release, are
      identical.
- [ ] For every compiled archetype: λ(i) < i for all links; depth(i) = depth(λ(i)) + 1; the level ranges
      partition the links.
- [ ] A 12-joint quadruped lowers to n_v = 18, 13 links, depth 3 and `level_start` = [0, 1, 5, 9, 13]; a
      29-joint humanoid to n_v = 35 and 30 links.
- [ ] The path table of a quadruped's shank lists 9 coordinates (6 base, 3 leg); with R = 160 the compact
      Jacobian needs 1,440 entries against 2,880 dense.
- [ ] Padding a 13-link table to 16, 32 and 64 links changes no byte of the first 13 rows; padding entries are
      identity transforms, k = 0 and −0.0.
- [ ] Two models that differ only in a link length have equal `structure` hashes and different content digests.
- [ ] `ShapeClassId` changes when any field changes and is equal across platforms.
- [ ] A non-finite model value is refused with the field named.

## Test plan

### Unit tests

- `topological_order_laws` (property over 1,000 random trees of up to 64 links).
- `quadruped_levels`, `humanoid_counts`, `wheeled_base_counts` (four wheels on a floating base: n_v = 10).
- `joint_classes_as_columns`: a revolute, a universal and a spherical joint give k = 1, 2, 3 with the expected
  screw columns; a prismatic joint has a zero angular part.
- `path_table_quadruped`: lists per link; `path_cap` = 9.
- `path_table_serial_arm`: a fixed-base 7-joint arm: link j lists coordinates 0..j.
- `cast_is_round_to_nearest_even`: 16,777,217.0 becomes 16,777,216.0; 0.1 becomes the nearest `f32`.
- `no_platform_math`: the module's dependency list and a lint show no call to platform elementary functions.
- `padding_is_exact_on_real_rows`; `padding_values`; `pad_unpad_identity`.
- `structure_hash_ignores_parameters`; `content_digest_sees_parameters`.
- `shape_class_id_fields`: flipping each field in turn changes the hash (13 cases).
- `layout_digest_golden`: the digest of the layout descriptor text equals a committed constant; a field
  reorder changes it.
- `nonfinite_refused`.

### End-to-end script and logging

`scripts/e2e/packed_lowering.sh`: `frob design show <archetype> --section packed --json` for `quad-mammal`,
`humanoid`, `diff-drive` and `mecanum` prints counts, `level_start`, the layout digest and the content digest;
the script compares them with the committed golden file `tests/fixtures/packed/digests.toml` and, when run with
`--cross`, with the values recorded by the other host. Log to `target/e2e-logs/packed_lowering/<utc>.ndjson`:
per archetype the command, exit code, wall time, evidence block (class `Tested`, determinism D0), counts and
both digests against their expected values; on failure the first differing column and its byte offset.

### Known answers and negative controls

- Known answers: the counts above (18 and 13 for the quadruped, 35 and 30 for the humanoid, 10 for the wheeled
  base); the arithmetic 160 × 9 = 1,440 against 160 × 18 = 2,880.
- Negative controls: padding with +0.0 instead of −0.0 (a sum of the single active element −0.0 with one
  appended +0.0 lane is +0.0, so a digest over bits changes with capacity; the padding-values test must catch
  it); a link order by insertion instead of by depth (the level test fails); a path table that lists
  descendants instead of ancestors; a cast through a platform `printf` round trip.
- Metamorphic: relabeling links in the design changes no digest after canonical ordering; mirroring a leg
  swaps the corresponding rows and nothing else.
- Determinism lanes: twice on one machine; debug and release; across the two platforms (class D0).

## Considerations

- The seed was filed under the record subsystem by a keyword match; its content is the design subsystem's
  second lowering and the definition of the shape-class type, and it is written here in full on that basis.
  Another unit's fitting bead also prints the shape-class fields; this bead owns the type and its hash, and the
  fitting bead re-exports it (noted in the unit's coverage file).
- The six default sizes disagree in one printed sketch (a `32` where the registered set says `36`); the
  registered default set {12, 18, 24, 36, 48, 64} governs.
- Model tables cost about 192 bytes per link: about 12 kB for a 64-link variant, 3 MB for 256 variants;
  collision sample lists are counted separately.
- The path table becomes the default Jacobian storage only after the batch-independence gate shows identical
  digests with it; until then it is produced and unused by default.
