## Background

One of the project's goals is that any world is reproducible: re-run alone on the CPU from its address, bit for
bit where the device reaches the bitwise class, and independent of the batch it ran in. A world is determined
by its address `(run_seed, world, episode)`, its model, scene, task and policy identities, and its kernel
versions. `frob sim replay <episode>` reproduces it. This is what makes a failure in world 1,337 of 4,096 on a
GPU something an agent can pick up and examine, and it is the base on which teleport, forks, the first-
divergence search, the background referee and memoized episodes all stand.

Reproduction needs three things, and this bead delivers them at milestone M2:
1. a cheap, exact way to say "these two states are the same bits" on every backend: the **state digest**;
2. stored states to start from: **snapshots**, taken at the commit fence where device state is consistent;
3. an engine and a verb that re-run a world and compare: **replay**.

**ADR-CHRON-05: digests are integer mixes computed in-kernel; BLAKE3 is used on the host.** Reason: integer
arithmetic is exact on every backend. The device digest is a 128-bit integer mix of the raw bit patterns of a
world's canonical state slabs. It is a tripwire, not an identity (a 128-bit mix is not a cryptographic hash);
identities in the record are BLAKE3 hashes computed by the host over committed snapshots.

A world's trajectory must not depend on the batch it ran in. Replay of one world alone, in a batch of different
size, and among different co-tenants must give the recorded digests on the same backend. Seed done-condition:
GATE-CHRON-01. Tier Solid.

Rejected alternatives: digests computed on the host from read-back state (a host round trip per tick, and it
would not exist for worlds that are not read back); a floating-point checksum (order-dependent and not exact);
recording all state every tick (cost).

## Technical approach

**1. Per-tick digest and chain.** After stage 10 of every control tick, for every world, the exact-class kernel
computes d_t = `K-x-digest`(address, canonical state slabs) as four `u32` words (a `u128` with the first word
least significant), and updates the world's **digest chain** x_t = D(address, x_{t−1} ‖ d_t), the same mix
applied to the eight words of the previous chain value and the new digest, with x_{−1} = 0. The chain value
covers the whole prefix: x_t(A) = x_t(B) exactly when the digests agree at every tick up to t, up to the
collision budget of a 128-bit mix. The chain value lives in a per-world slab that the commit fence and every
snapshot carry (it travels in the snapshot header), so a continuation resumes it; but the digest does not fold
it, so d_t stays a function of the world's state alone and two runs whose states re-converge show equal d_t
again while their chains stay different. Padding lanes are never folded, so a world's digest is the same at
any bucket capacity.

**2. What is recorded.**
- Every world, every logical chunk (T0): d and x at the chunk's last tick. d is the `state_digest` field of
  the chunk record; x is stored in the T0 row.
- Ring-holding and traced worlds: d_t and x_t for every control tick, in the ring and the T2 stream.
- Per-stage digests are never recorded in a normal run.

**3. Per-stage digests on demand.** A step plan variant `stage-digest` inserts, after each of the ten stages of
each physics substep, the stage-tagged digest over that stage's output slabs for selected worlds. It is used
only when re-running one control tick to localize a difference; its outputs are (substep, stage, kernel name
from the plan's stage-to-kernel map, four words). The variant changes no state bit: the physics digests of a
tick run with and without it are equal (checked).

**4. Digest emission at the fence.** A device chunk ends with `K-commit`, which writes the checkpointable state
to the other committed slab. This bead extends the commit so that each world's d and x at the chunk's last
tick are written into the statistics ring slot of the same epoch. The host reads them only after the
`Completed` receipt. A retried chunk recomputes the same values, because a replay from the committed slab is
bit-identical.

**5. `K-snapshot`.** An index-driven row copy: for an index vector of worlds, every canonical state slab row of
`src[j]` is copied to row j of the snapshot slab, as the last dispatches of the chunk's launch sequence (after
`K-commit`, reading the newly committed slab). The column list is the step plan's canonical slab list, so a
field added to the state is added to the copy by construction. The copy never writes the source. On the CPU it
is a row copy; on CUDA an explicit stream-ordered readback of the snapshot slab; on Metal a host copy of the
shared slab after completion.

**6. Host side of a snapshot.** Under the read lease on the snapshot slab: encode each world's rows into the
container; recompute the state digest from the bytes on the host with the reference implementation and compare
it with the device's d for that tick (a mismatch is recorded in the divergence ledger and the snapshot is
rejected); store the object and its `snapshot` row with the BLAKE3 content hash. `EpisodeId` is the BLAKE3 over
the episode's committed snapshot hashes and chunk chain heads.

**7. T3 schedule (DESIGN defaults).** Traced worlds: one stored full snapshot at every logical chunk boundary
(every 256 control ticks), sparse differences at ring cadence where the ring is flushed. Failing worlds: the
ring's snapshots. Every world: tick zero is reproducible from the address and the reset cache and is not
stored. Any other tick is reached by replay.

**8. The replay engine.** `replay(target, opts)`:
1. Resolve the episode to its run manifest and identities; check that kernels, model, scene, task and policy
   objects with those identities are present (a missing identity is a refusal naming it).
2. Choose the start: the latest stored snapshot at or before `from` whose profile identity equals the
   replay's, else tick zero by address.
3. Build an environment for the world: alone (batch of one), or as `opts` asks (`batch_size`, `co_tenants`
   drawn by seed from other addresses), in the recorded shape class or any class that admits the model.
4. Restore and step to `to` (default: the episode's terminal tick), computing d_t and x_t.
5. Compare at every recorded point: chunk-end d and x for all worlds; per-tick values where recorded. Stop at
   the first mismatch or at the first refusal raised by the step.
6. Return `ReplayReport { class, from, to, compared_points, result: Bitwise | Mismatch { chunk, tick, expected,
   observed } | Refused { code, tick }, captured }`, where `captured` lists what `opts.capture` asked for
   (per-tick digests, a T2 window, snapshots at given ticks, a `reconstruct` marker's range).

**9. The verb `sim.replay`** (kind `run`; M2; capability `sim:run`; schemas `frob.sim.replay.in/1`,
`frob.sim.replay.out/1`). `frob sim replay <episode> | --run <r> --world <w> [--episode <e>] | <file.fmcw>
[--from <tick>|--from-snapshot <hash>] [--to <tick>] [--alone | --batch-size <n> | --co-tenants <seed>]
[--capture digests|t2|snapshots|failure] [--tier <t>] --key <k> --json`. Without `--tier` the replay runs on
the recorded backend and profile. Envelope: `result` is the report; `evidence` has class `Tested`, the tier,
the determinism class that applied (`D2` within a family; with `--tier`, see the teleport bead), identities and
seed. Exit 0 for `Bitwise`; exit 2 for a mismatch (a finding: the first differing chunk and tick with both
digests, and a divergence-ledger row); exit 3 for refusals: FROB-REF-840 (sealed confirmation run),
FROB-REF-894 (a snapshot of another numerical profile offered as a continuation), a missing identity; exit 6
when the recorded backend is unavailable (the repair names `--tier batch-cpu`).

**10. Layout.** `crates/frob-kernels/src/exact/{digest_chain.rs, stage_digest.rs}`,
`crates/frob-kernels/src/util/k_snapshot.rs` with dialect twins; `crates/frob-chronicle/src/{digest.rs,
replay.rs, t3.rs}`; `crates/frob-verbs/src/verbs/sim_replay.rs`.

## Acceptance criteria

- [ ] Seed done-condition, with N29a-19: GATE-CHRON-01 (TARGET): 1,000 random worlds from a GPU run replay with
      identical digests on the same backend, and inside the class on `batch-cpu`; the same worlds replayed
      alone, in a batch of another size and among other co-tenants give the same digests.
- [ ] INV-CHRON-08: a world's digests do not depend on batch size, slot or co-tenants (property test on
      `batch-cpu` in both precisions; the device lanes are the gate's).
- [ ] PO-CHRON-06: the in-kernel digest distinguishes states that differ in any recorded bit, to the collision
      budget of a 128-bit mix: flipping each bit of each canonical slab of a pinned corpus changes d; the
      avalanche statistics are inside their bounds; output is identical on every backend for the corpus.
- [ ] The `stage-digest` plan variant leaves physics digests unchanged.
- [ ] 10⁵ snapshot reads each match the digest emitted for their epoch (shared with the backend unit's fence
      gate; this bead supplies the emission).
- [ ] A replay from a stored snapshot and a replay from tick zero agree with each other and with the record.
- [ ] `frob sim replay` on an unfaulted world returns `Bitwise`, exit 0; with one planted bit flip in a stored
      chunk digest it returns the mismatch with chunk and tick, exit 2.
- [ ] `--capture failure` on a world without a ring produces the same capture bytes as a ring capture.
- [ ] Cancellation of a replay job drains and leaks no device resource; one key yields one job.

## Test plan

### Unit tests

- `chain_covers_prefix`: two 300-tick traces equal except at tick 40: x differs at every tick ≥ 40.
- `chain_resumes_from_snapshot`: x after restore at tick 200 and 100 more ticks equals the uninterrupted x.
- `digest_ignores_padding`: capacities 32, 64, 128 give equal d.
- `digest_bit_sensitivity` (PO-CHRON-06): every single-bit flip over a 4 kB pinned state changes d; over 10⁶
  random flips each output bit changes with frequency in [0.49, 0.51].
- `stage_digest_variant_is_pure`: physics digests equal with and without the variant, 200 ticks.
- `snapshot_gathers_every_canonical_slab`: sentinel per slab; a slab added to the list without a section fails
  (the container's completeness check); `source_rows_untouched`.
- `host_digest_tripwire`: one bit changed in the snapshot slab after the device digest was taken is caught.
- `replay_alone_equals_recorded`, `replay_other_batch_size`, `replay_co_tenants` (`batch-cpu`, single and
  double precision, 200 worlds each).
- `replay_start_selection`: with snapshots at ticks 0, 256, 512 and `--from 600`, the start is 512.
- `replay_mismatch_report_fields`; `replay_stops_at_first_refusal` (a world that faults at tick 77).
- `missing_identity_refused`; `sealed_840`; `profile_mismatch_894`.
- `fmcw_input_resolves_to_address`.

### End-to-end script and logging

`scripts/e2e/sim_replay.sh` (owned by N29a-19): a device run, then `frob sim replay` for sampled worlds in the
three compositions, a planted mismatch, a capture, and the refusals. This bead's step groups are `digest-*`
and `replay-*`; their lines carry the world address, start tick and source, compared points, the determinism
class, the first mismatch with both digests, and the divergence-ledger row identifier.

### Known answers and negative controls

- KA-716, replay half: the empty intervention replays bit for bit (exact; G5 · all tiers).
- Negative controls: a digest that folds padding lanes (changes with capacity); a chain that omits x_{t−1}
  (the prefix test fails); a snapshot copy that omits warm starts or packet queues (continuation differs); a
  replay that compares only the final digest (misses a divergence that heals; the two-tick case of the
  divergence bead); an address that includes the slot.
- Metamorphic: splitting a rollout at a snapshot and resuming equals running it whole; permuting world indices
  permutes results and changes nothing else; adding inactive worlds or unused capacity changes no active
  world's digest (MR-01).
- Determinism lanes: twice on one machine; across worker counts; debug and release on `batch-cpu`; each
  backend against its own record (class D2); across backends only through the teleport bead.

## Considerations

- Cost: one integer pass over a world's state per control tick, about 1% of the memory traffic of the step at
  the reference sizes; measured inside the telemetry cost gate.
- KILL-D1 (decided at M2): if a device family cannot hold bit equality with `batch-cpu`, that family is class
  D2 for itself and D3 against others. Replay on the same family is unaffected.
- The run digest (the wrapping sum of per-world digests keyed by address) is independent of slot order and is
  recorded per chunk for the whole run as a cheap run-level tripwire.
- Memoized episodes, the background referee and the fork service all depend on this bead; each reads snapshots
  through the container and digests through the record, never device slabs directly.
- The collision budget of the mix is about 2⁻¹²⁸ per comparison for independent states; it is stated with every
  `Bitwise` verdict as "digests equal", not as "states proved equal".
