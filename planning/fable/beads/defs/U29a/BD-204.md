## Background

A North-Star scenario of the project: world 1,337 of 4,096 produces NaNs on the GPU. Where an incumbent's
deterministic mode is on, the same batch can be re-run on the same GPU; none documents a bitwise re-run of that
one world on a CPU. Here, `frob sim replay --world 1337 --tier batch-cpu` reproduces that world alone on the
CPU from its address, stops at the first step whose digest differs from the GPU's or at the first refusal, and
reports the contact that started it. Where the device reaches the bitwise class the digests agree to the end,
and the report says which class applied.

This operation is called **teleport**: the run restarts from the nearest snapshot on the CPU, compares digests
step by step with the recorded ones, and at the first difference re-runs that step with per-stage digests to
name the stage and kernel where the tiers part. It is possible because every kernel has one source for all
backends (hand-written skeletons with derived arithmetic), so "stage 6 on CUDA" and "stage 6 on `batch-cpu`"
are the same computation and a difference between them is a finding about a compiler, a driver or a rule
violation, not about two code bases. Emitting one digest per stage and comparing them in order is an
established way to localize a cross-platform difference to a subsystem (FACT: the technique is in use
elsewhere in the suite).

Seed done-condition: GATE-CHRON-02 (teleport localizes a planted single-kernel divergence to the right step and
stage in 100 of 100 trials). Tier Solid.

Rejected alternative: comparing final states and bisecting on "the states differ at tick t". That predicate is
not monotone (an error can vanish and return), so bisection on it can skip the first difference; teleport
steps the digest chain, which is monotone.

## Scope

In: the `--tier` path of `sim.replay`; the start-state rule across backends; step-wise comparison against the
record; obtaining per-tick digests the record lacks; stage localization by per-stage digests; the report; the
class label (exact or tolerance); filing the divergence; the planted-divergence battery and the gate record.
Out: digests, snapshots and same-backend replay (BD-203); the general two-run divergence search and its
tolerance mode (BD-206, N29a-20); the kernel-level CPU-versus-device check (BD-176); the decision-level test
(BD-177).

## Technical approach

**1. Request.** `frob sim replay <episode or address> --tier <target> [--from …] [--to …] [--precision f32|f64]
[--comparison] --key <k> --json`. `target` is usually `batch-cpu`; any tier that has the step plan's profile is
allowed (FROB-REF-222 otherwise).

**2. Class decision, before anything runs.** From the determinism records of the two placements:
- same device family as recorded: an ordinary replay (class D2);
- another family with class D1 attained for every kernel in the plan and a current CPU-versus-device check:
  an **exact teleport**; a continuation in the sense of the fork classes (nothing is regenerated);
- otherwise: a **tolerance teleport** (class D3). It is labelled `tolerance-replay` in the envelope's evidence
  block (the label of VERBS-sim's `sim.replay` row and N35-07; the report's `class` is `tolerance`) and
  compared by envelope and decisions, never reported as bitwise;
- a target with another numerical profile (for example `--precision f64`, or the `strict` profile): a
  comparison replay, which must be requested with `--comparison` (FROB-REF-894 otherwise); the checkpoint is
  widened exactly.

**3. Algorithm, exact teleport.**
1. Start S: the latest stored snapshot of the world at or before the first tick of interest, else tick zero by
   address. Restore S on the target.
2. Step on the target, computing d_t and x_t. Compare with the record at every point it has: chunk ends for
   every world; every tick for traced and ring-holding worlds.
3. If a chunk-end comparison fails and the record has no per-tick digests inside that chunk: re-run the chunk
   for this world on the *source* backend alone from S with per-tick capture (the source's own replay is
   bitwise by its class D2), which supplies the missing d_t.
4. Let t₁ be the first tick with d_t(source) ≠ d_t(target). Both sides agree at t₁ − 1, so both hold the same
   state there.
5. Re-run tick t₁ on both backends from the state at t₁ − 1 under the `stage-digest` plan variant: after each
   of the ten stages of each of the d physics substeps both sides emit the stage-tagged digest of that stage's
   outputs. Let (j₁, s₁) be the first (substep, stage) where they differ. The kernel is the plan's kernel for
   s₁; if a stage is a chain of kernels, the variant emits a digest after each kernel of the chain and the
   first differing kernel is named.
6. Decode the differing output slab on both sides and list the variables that differ under their physical
   names and units (link, joint, contact feature pair), with the largest difference in units in the last
   place.
7. File a divergence-ledger row (run, world address, t₁, j₁, s₁, kernel, quantity, both digests, both
   fingerprints) and return the report.
If the target raises a refusal before any digest differs (a non-finite value, a capacity overflow under the
refuse policy), the report stops there with the refusal's code, tick and stage, and names the contact or row
that triggered it.

**4. Algorithm, tolerance teleport.** Steps 1 and 2 with scaled state error against the recorded envelope
instead of digest equality; t₁ is the first tick outside the envelope; stage localization compares per-stage
outputs by scaled residual and names the first stage over tolerance; the decision-level comparison (verdict,
failure class, binding atom, time of first failure) is attached. The report carries `class: tolerance`.

**5. Report (`frob.sim.replay.out/1`, teleport part).** `{ class: "exact" | "tolerance" | "comparison",
determinism: "D1" | "D3", start: { tick, source }, agreed_through: tick, first_divergence: null | { tick,
substep, stage, kernel, variables: [ { name, unit, source, target, ulps } ] }, first_refusal: null | { code,
tick, stage, subject }, decisions: null | { verdict_equal, failure_class_equal, binding_atom_equal,
first_failure_time: [a, b] }, ledger_row }`. `decisions` is the per-world decision-level comparison of step 4,
present on every `class: tolerance` report (and on `class: comparison`), null on an exact teleport, whose digests
already decide; a consumer that labels a tolerance replay reads it for the one replayed world. Exit 0 when the
tiers agree to the end; exit 2 with a divergence or a refusal on the target (a finding); exit 3 for request
refusals.

**6. The gate battery (GATE-CHRON-02).** 100 trials. Each trial draws by seed: a world of a device run, a tick
t, a substep j, a stage s among the ten, an output variable of that stage, and plants one unit in the last
place on that output on the *device* side through the conformance fault hook (the CPU side is unmodified, so
the tiers part exactly there). Teleport must return t₁ = t, j₁ = j, s₁ = s and the stage's kernel. Ten trials
place t on a chunk boundary and ten on the tick after one. On a family without D1 the battery runs between
`batch-cpu` and `batch-cpu` with the hook armed on one side (the localizer is the same code) and the row says
so. A mutant localizer that always names the last state-writing stage (stage 9) is kept in the test tree and
must be wrong on every trial whose plant is in another stage.

**7. Layout.** `crates/frob-chronicle/src/teleport.rs`; the verb's `--tier` branch in
`crates/frob-verbs/src/verbs/sim_replay.rs`; the battery as entries of the G1 tier
(`crates/frob-conformance/src/teleport_battery.rs`, collected by the test target `g1_known_answers`; it has no
test target of its own).

## Acceptance criteria

- [ ] Seed done-condition, GATE-CHRON-02 (TARGET): a planted single-kernel divergence is localized to the right
      step and stage in 100 of 100 trials; the measured count, the family and the method are recorded.
- [ ] The mutant localizer is caught on every trial with a plant outside stage 9.
- [ ] On an unplanted run of a D1 family, teleport of 100 worlds agrees to the end with `class: exact`; where no
      family holds D1 (KILL-D1 fired, or its gate not current) the row is recorded `not run: no D1 family` and the
      same 100 worlds are teleported between `batch-cpu` and `batch-cpu`.
- [ ] On a family without D1 the envelope says `class: tolerance`, `determinism: D3`, and no field says
      bitwise; the report carries `decisions` (verdict, failure class and binding atom equal or not, and the
      two times of first failure).
- [ ] A world that faults on the device (planted non-finite value) is teleported and the report stops at the
      first differing or refused step, naming stage, kernel and the contact.
- [ ] A chunk-end mismatch with no per-tick digests in the record is resolved by a source-side capture, and the
      reported tick equals the planted tick.
- [ ] `--precision f64` without `--comparison` is refused with FROB-REF-894; with it, the report has
      `class: comparison`.
- [ ] Every divergence is filed in the divergence ledger and the report carries the row identifier.

## Test plan

### Unit tests

- `class_decision_table`: (same family) → replay; (other family, D1 current) → exact; (other family, D1 not
  attained or check stale) → tolerance; (other profile) → needs `--comparison`.
- `first_tick_from_per_tick_record`; `first_tick_needs_source_capture`.
- `stage_localization_each_stage`: a plant in each of the ten stages on `batch-cpu` against `batch-cpu` is
  named correctly; a plant in a chained stage names the kernel within the chain.
- `substep_localization`: a plant at substep 7 of 10 is reported as substep 7.
- `variables_decoded_with_units`: a plant on the z velocity of a named link is listed with unit m/s and 1 ulp.
- `refusal_before_divergence_reported`.
- `tolerance_teleport_uses_envelope`: a 3·10⁻⁷ m difference inside a 10⁻⁵ m envelope is agreement; outside it
  is the first divergence; both reports carry `decisions` with the four fields, and a planted world whose
  failure class differs between the sides gives `failure_class_equal: false`.
- `mutant_last_stage_is_wrong`.
- `comparison_requires_flag_894`.

### Known answers and negative controls

- KA-718: a planted single-kernel divergence is named by step and stage (exact; G1 · all tiers). The suite
  states no negative control; the control added in the known-answer registry is the last-stage mutant.
- Negative controls: the mutant; a localizer that compares stage digests of the *recorded* tick against a
  target state that already differs (it would blame stage 1; prevented by restarting both sides from the
  agreed state at t₁ − 1 and tested by planting two divergences one tick apart).
- Metamorphic: teleporting from an earlier snapshot gives the same first divergence.
- Determinism lanes: the report is identical on repeat; the battery is run in debug and release on the CPU
  side.

## Considerations

- KILL-D1: if a device family cannot hold bit equality with `batch-cpu` for the floating kernels of the step,
  the family is class D2 for itself and D3 against others, and a teleported world is a tolerance replay. The
  verb, the report and this gate remain; only the class label and the comparison rule change.
- The report is a statement about where two computations part. It is not a statement about cause, and the
  order in which solver stages report residuals is not evidence of a first physical cause.
- A teleport needs the source backend only when the record lacks per-tick digests for the chunk in question;
  with a ring capture it runs with no device at all, which is how a failure found on the Linux host is examined
  on the Mac.
- Cost: one world on `batch-cpu` for at most one chunk plus one tick with stage digests; interactive.
