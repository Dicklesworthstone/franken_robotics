## Background

Chronicle is the record of the system. It owns one crate, `frob-chronicle` (layer 6, tier Solid), and through it
seventeen mechanisms: the ledger and column store with the `.frun` format; the chunk protocol and pinned
pagination; telemetry levels, streams and channel kinds; tracing by address; integer histograms; replay and
teleport; fork classification; first divergence; the energy ledger and the created-energy audit; the failure
taxonomy; the tier-correction ledger; the background referee's records; the self-contained replay packet; the
artifact graph; bead logs; simulation testing of the daemon and ledger; and retention. Two sentences fix its
character: Chronicle does not decide anything about a design; and it refuses to let a claim be printed that it
cannot trace, and refuses to compute a metric from samples it does not have.

Many subsystems write into Chronicle's ledger: the surface writes runs and jobs, the comparison subsystem writes
verdicts and predictions, the dynamics subsystem writes fidelity strata, the task subsystem writes the error
budget of confirmation requests. Without a rule, any crate could write any table, and a row's provenance would
be whatever the last writer made it. This bead makes the "written by" column of the storage plan a property of
the types: each table has exactly one writing subsystem, expressed as a capability handle that only that
subsystem can obtain, and Chronicle's own API offers no function that returns a decision about a design.

Rejected alternative: one `Ledger::put(table, row)` open to every caller, with ownership kept by convention. A
convention is a path an optimizing agent finds; a missing constructor is not.

## Scope

In: the ownership map as data; `TableWriter<T>` handles and how they are issued; composition of several writers
in one transaction; the identity stamp and the `writer` stamp on every row; the ledger dump example
`ledger_dump`; the two caller-facing obligations as API (`Traced<T>` and `Covered<T>`); the lint that keeps
design decisions out of the crate; the mechanism inventory check.
Out: table schemas (BD-090); each mechanism's own logic (its bead); the artifact graph behind `Traced` (BD-095);
coverage computation behind `Covered` (BD-090's gap records).

## Technical approach

**1. Ownership map** (`crates/frob-chronicle/src/ownership.rs`, generated into `CONTRACT.md`):

| Table | One row is | The only writer |
|---|---|---|
| `run`, `job` | A run or job: manifest hash, identities, state, budgets, terminal receipt with counts | The surface's job engine (`frob-verbs`) |
| `episode` | (run, world, episode): outcome, T0 metrics, digests, failure class | Chronicle |
| `chunk`, `frontier` | A published chunk; the contiguous committed frontier | Chronicle (the publishing transaction) |
| `event`, `snapshot` | A T1 event; a T3 snapshot with its content hash | Chronicle |
| `fidelity` | A stratum of the fidelity ledger | The dynamics subsystem |
| `rank_agreement` | A stratum of the rank-agreement ledger | The comparison subsystem |
| `tier_correction` | A stratum of the tier-correction ledger | Chronicle |
| `verdict`, `prediction`, `core_decision` | A verdict record; a registered prediction; one decision of a decision core | The comparison subsystem |
| `memo_node` | A node of the memo graph with key, class and cost | The memo policy (comparison subsystem) |
| `claim`, `evidence`, `edge` | The artifact graph | Chronicle |
| `alpha_spend` | A pre-committed confirmation request and its error budget | The task subsystem |
| `pin`, `tombstone` | A retention pin with its reason; a record of something deleted | Chronicle |
| `job_event`, `job_log` | A job's transition with its event payload; a line of its log (the job engine's tables, N32a-08) | The surface's job engine (`frob-verbs`) |
| `run_lease` | A run's lease generation, the fencing token of its writers (BD-091) | Chronicle (`reassign`, which the job engine calls inside the transaction of each assignment change) |

The last two rows are tables that the job engine (N32a-08) and the publishing transaction (BD-091) create in the
same database; whichever of them lands after this bead brings its rows' writer under this map in its own change
(a table with no owner fails `ownership_map_is_total`).

**2. Writer handles (DESIGN).**

```rust
pub struct TableWriter<T: Table> { /* private */ }        // no public constructor, not Clone
pub struct WriterSet { /* one optional handle per table */ }
impl Store { pub fn issue(&self, who: Subsystem, token: &RegistrationToken) -> WriterSet; }
impl<'t> Txn<'t> { pub fn put<T: Table>(&mut self, w: &TableWriter<T>, row: T::Row) -> Result<(), Refusal>; }
```

`Store::issue` returns exactly the handles the map grants to `who`. The registration token is created once per
process by `frob-verbs` at start-up and handed to each subsystem's constructor (dependency inversion: crates
below layer 6 never link `frob-chronicle`; they receive handles and trait objects defined in `frob-core`). A
second `issue` for the same subsystem in one process is refused. Reading is open to every caller through typed
queries.

**3. One transaction, several writers.** `Store::transact(|txn| …)` accepts rows from different handles and
commits them together or not at all. Two compositions the system depends on are provided as named helpers and
tested here as shapes (their content belongs to the beads named): a verdict together with the pins of its
evidence closure; a chunk row together with the advance of its frontier.

**4. The identity stamp.** `Txn::put` refuses a row whose identity fields (design, model, scene, kernel, policy
and episode identities as applicable to the table; run identity; schema version) are absent. It also stamps the
row with `writer`, the subsystem the handle was issued to (DESIGN: the row's provenance stays readable after the
fact, which the end-to-end steps below read). `writer`, wall-clock times and trace identifiers are stored in
separate columns that no hashing function of the crate reads.

**4a. The ledger dump (DESIGN).** An example target of `frob-conformance` that this bead declares, `ledger_dump`
(BD-025's form for a harness reader of another subsystem: it prints one JSON object and exits non-zero when its
own assertion fails): `cargo run -p frob-conformance --example ledger_dump -- --store <dir> --run <run>` prints,
per table, the run's row count and the distinct `writer` values among those rows; `--attempt-write <table> --as
<subsystem>` asks the handle set issued to that subsystem for the table's writer, attempts the write, and
prints `refused` with the table's row count before and after; it exits non-zero if the handle was granted or the
count changed. No verb reports writers: `store.status` of BD-209 reports classes and pins.

**5. The two obligations, as types.**
- `Traced<T>`: a value that crosses the agent boundary as a claim. It can be built only from a `ClaimId` that
  resolves in the artifact graph; the envelope serializer accepts a claim-bearing number only inside `Traced`.
  An unresolved identifier yields `evidence: unavailable` and FROB-REF-869 (citing a claim whose evidence
  closure is dangling or tombstoned; repair: re-run the evidence, the tombstone names what is missing; exit 3).
- `Covered<T>`: a metric value together with the coverage it was computed over. It can be built only by a
  function that checked the gap records first; a required sample inside a gap yields FROB-REF-888 (a metric
  computed over missing samples; repairs: re-run with the channel retained, or accept `unavailable`; exit 3).

**6. No decisions.** A lint in the crate's test suite scans its public API for return types named `Verdict`,
`Ranking`, `Recommendation` or `Decision` and fails if one is constructed inside `frob-chronicle` (the crate
stores such records; it never computes them). The single exception is the tier-correction estimate, which is a
number with an interval and not a label.

**7. Mechanism inventory.** `registries/chronicle-mechanisms.toml`: one row per mechanism with its tier, verb,
gate and module path (ledger and `.frun`: `run.export`, `telemetry.query`, GATE-CHRON-04 and -10; chunk protocol
and pagination: GATE-CHRON-04; levels, streams and kinds: `telemetry.summary`, `telemetry.query`,
GATE-CHRON-13; tracing by address: manifest fields `trace.rate` and `trace.size`, GATE-CHRON-07; integer
histograms: `telemetry.histogram`, GATE-CHRON-07; replay and teleport: `sim.replay`, GATE-CHRON-01 and -02; fork
classification: `run.fork`, GATE-CHRON-05; first divergence: `telemetry.divergence`, GATE-CHRON-06; energy
ledger and audit: `telemetry.energy`, GATE-CHRON-03 and -08; failure taxonomy: `telemetry.failures`,
GATE-CHRON-08; tier-correction ledger: `eval.promote`, GATE-CHRON-09 and the kill gate KILL-DR; background
referee sampler and segment fidelity (Frontier): a daemon setting and `telemetry.query`; self-contained HTML
replay: `telemetry.export-html`, GATE-TETHER-16; artifact graph: `evidence.trace`, GATE-CHRON-10; bead logs: no
verb, GATE-CHRON-10; simulation testing: no verb, GATE-CHRON-11; retention: `store.status`, `store.collect`,
GATE-CHRON-12). A test checks that every verb named exists in the verb registry and every gate in the gate
registry, so the inventory cannot drift from the code.

## Acceptance criteria

- [ ] For every table, a compile-fail test shows that a crate other than its owner cannot obtain or forge a
      `TableWriter` for it.
- [ ] `Store::issue` twice for one subsystem is refused.
- [ ] A transaction with rows from two handles commits both or neither under an injected failure between them.
- [ ] A row without its identity stamp is refused; every committed row carries the `writer` of its handle; no
      hashing function in the crate accepts a trace identifier, a wall-clock time or a `writer` (compile-fail
      test on the hasher's input trait).
- [ ] `ledger_dump` is declared in `frob-conformance`'s `CONTRACT.md` with this bead as its owner, prints the
      per-table writers of a run, and exits 0 on an `--attempt-write` that the map refuses.
- [ ] A number marked as a claim cannot be serialized outside `Traced`; a metric cannot be returned outside
      `Covered` (compile-fail tests); the two refusals carry code, pointer and ranked repairs.
- [ ] The decision lint fails on a planted `fn best_design() -> Ranking` in the crate.
- [ ] The inventory check fails when a verb or gate name is misspelt (planted).
- [ ] `CONTRACT.md` lists the ownership map under "invariants" and both refusals under "refusals".

## Test plan

### Unit tests

- `ownership_map_is_total`: every table of schema version 1 has exactly one owner.
- `writer_handles_compile_fail` (trybuild): five cases, one per foreign-write attempt class.
- `issue_once`; `transact_all_or_nothing` (fault injected after the first `put`, 100 seeds).
- `identity_stamp_required`: a `verdict` row with no `ModelId` is refused.
- `writer_stamped_from_handle`: a `chunk` row put with Chronicle's handle reads back with `writer = chronicle`;
  two rows equal but for their writers have equal content hashes.
- `hasher_rejects_trace_and_time` (trybuild).
- `traced_requires_resolving_claim`: a dangling `ClaimId` gives FROB-REF-869; `covered_requires_coverage`: a
  metric over a gap gives FROB-REF-888.
- `no_decision_types_constructed`; `inventory_matches_registries`.

### End-to-end script and logging

Steps `ownership-*` of `scripts/e2e/chronicle_record_surface.sh` (owned by N29a-08): after a referee run, read
each table's `writer` stamps through this bead's ledger dump (`cargo run -p frob-conformance --example ledger_dump
-- --store "$FROB_STORE" --run <run>`, section 4a) and assert that every table the run wrote has exactly one
`writer`, equal to the map's; then `… --example ledger_dump -- --store "$FROB_STORE" --attempt-write verdict --as
chronicle` and assert it exits 0 with `refused` and equal row counts before and after. NDJSON lines carry the
table, the recorded writer, the expected writer, the refused attempt and the evidence block.

### Known answers and negative controls

Negative controls are the compile-fail cases, the planted decision function and the planted misspelt gate.
Property: for random sequences of writes from random subsystems, the set of committed rows equals the set whose
writer matches the map. Determinism: the generated ownership section of `CONTRACT.md` is byte-stable.

## Considerations

- Handles are a compile-time fence, not a security boundary; authority at the agent boundary is the session
  token of the surface.
- The fallback ledger (append-only JSON lines, used if FrankenSQLite cannot be consumed) keeps the same handles;
  only `transact` changes its implementation.
- Adding a table needs a schema migration, an owner and an inventory row in the same change.
