## Background

A result that is evidence must be the same bits however the work was scheduled: on one shard or four, with
worlds in any order, merged in any grouping. Floating-point sums and approximate quantile sketches do not have
that property, because their result depends on the order of operations. The record subsystem (Chronicle) fixes
this with one decision:

**ADR-CHRON-03: evidence aggregates are integers.** On the evidence path an aggregate is a count, an integer
sum, a minimum, a maximum, a bitwise or, or a histogram of integer counts. Quantiles come from histograms.
Order-dependent sketches are not used. Reason: integer addition, minimum, maximum and or are commutative and
associative, so the result has the same bits under any scheduling, shard split or merge order. The same rule
gives the one positive licence for device-side atomics: integer maximum, minimum, or and add only.

The *evidence path* is everything that can end up in a verdict, a gate record or a number printed to an agent
with a claim attached. Exploratory plots may use anything; they are never evidence.

This bead builds the aggregate types and the first two things computed with them at telemetry level T0: the
per-chunk minimum–maximum envelope of each declared channel, and the state digest kept at intervals. T0 is the
level every world always records. The envelopes are what later lets a comparison of two runs bound the largest
difference over an interval without reading every sample. Histograms are built on these types by their own
bead. Tier Solid.

Rejected alternatives: Kahan-compensated floating sums (smaller error, still order-dependent); sorting before
summing (deterministic, but a sort across shards needs all data in one place); mergeable sketches (see the
histogram bead's counterexample: the same stream in two orders gives two medians).

## Scope

In: the trait and the five scalar aggregates; quantization of a channel value to an integer; saturation and
overflow accounting; the registry of aggregate names; the refusal for an order-dependent aggregate; per-chunk
envelopes; digests at intervals in T0; property tests of the laws.
Out: histograms (N29a-13) and their kernel (N29a-14); device emission of T0 (BD-207); energy-ledger sums (the
energy-ledger beads, which use these types); the difference bounds built from envelopes (N29a-20).

## Technical approach

**1. The trait (DESIGN).**

```rust
pub trait EvidenceAggregate: Sized + Eq {
    const NAME: &'static str;
    fn identity() -> Self;
    fn merge(self, other: Self) -> Self;         // commutative and associative; identity is neutral
    fn to_canonical_bytes(&self) -> Vec<u8>;     // little-endian; equal values have equal bytes
}
pub struct Count(pub u64);                       // merge: checked add
pub struct IntSum(pub i128);                     // merge: checked add; sum of quantized integers
pub struct Min(pub i64);  pub struct Max(pub i64);   // identities i64::MAX and i64::MIN
pub struct BitOr(pub u64);                       // flags; identity 0
```

Overflow of `Count` or `IntSum` is a typed error that names the aggregate and the channel; it is never a wrap.
(At 4 M world-steps/s a 64-bit count lasts about 146,000 years; the check exists for mutants and for misuse.)

**2. Quantization.** A channel declares a quantum u with its unit. A value x becomes the integer
q = round-half-even(x/u), saturated to the channel's declared integer range [−Q, Q]. A saturated value sets the
channel's `saturated_low` or `saturated_high` count (an integer aggregate itself), so saturation is visible.
The result depends only on the bits of x. All scalar aggregates of a floating-point channel are taken over q,
never over x.

**3. Derived quantities.** A mean is the exact rational `IntSum / Count` scaled by u, printed with its count.
A quantile is an interval from a histogram. Nothing else is derived on the evidence path.

**4. The name registry and the refusal.** `registries/aggregates.toml` lists the admitted names: `count`,
`sum`, `min`, `max`, `or`, `histogram`, and the derived `mean` and `quantile`. A request on the evidence path
for any other aggregate (`tdigest`, `kll`, `reservoir-quantile`, `float-sum`, `median-exact`, or any name not in
the registry) is refused with FROB-REF-898 (an order-dependent aggregate requested on the evidence path; repair:
use the integer histogram; exit 3). The refusal names the admitted alternative for the requested name.

**5. Device licence.** The aggregate's merge is the only operation a kernel may apply with an atomic: integer
maximum, minimum, or and add. The types carry an associated constant `ATOMIC_OK` that the kernel manifest
checker reads; no floating aggregate type exists for it to accept.

**6. Per-chunk envelopes (T0).** For each channel that declares `envelope = true`, and for each chunk of each
(world, episode), the worker computes `(Min(q), Max(q), Count)` over the chunk's ticks and writes them as one
row of the T0 `envelope` column set of that chunk: `(channel, min_q: i64, max_q: i64, n: u32)`. For a `state`
channel that holds an orientation, the envelope is taken per component of the rotation vector relative to the
chunk's first sample (a difference, so it is small and meaningful), and the first sample is stored beside it.
For an `impulse` channel the row also carries `IntSum(q)` (the window sum that conserves momentum transfer); for
a `cumulative-counter` channel only the last value. Envelopes merge across chunks by `Min`, `Max` and `Count`.

**7. State digests at intervals (T0).** Each chunk's T0 row stores the world's state digest at the chunk's last
tick (the same 128-bit value the chunk record carries, of the run's `digest_kind` as BD-091 defines it), and,
where the run has one, the running digest-chain value at that tick (the in-kernel chain of N29ap1-01 on the
batched tiers from M2). On the referee at M1 the row also stores the full 32-byte BLAKE3 of the canonical
referee-state byte string, of which the chunk record carries the first 16 bytes. All are integers or byte
strings and are compared for equality only, and only with digests of the same kind.

**8. Layout.** `crates/frob-chronicle/src/{aggregate.rs, quantize.rs, envelope.rs}`; registry file
`registries/aggregates.toml`.

## Acceptance criteria

- [ ] INV-CHRON-06 (every evidence aggregate has the same bits under any permutation of worlds, shard split and
      merge order) holds for the five scalar aggregates and for envelopes over 10⁴ random cases, each with 100
      permutations and 100 random shard splits.
- [ ] `merge` is commutative and associative and `identity` is neutral for each type (law tests).
- [ ] round-half-even quantization: 0.5·u → 0, 1.5·u → 2, 2.5·u → 2, −0.5·u → 0, −1.5·u → −2; saturation sets the
      saturation count and never wraps.
- [ ] A request for `tdigest` or `float-sum` on the evidence path returns FROB-REF-898 naming `histogram` or
      `sum` as the repair; a request for `sum` succeeds.
- [ ] Every chunk of a referee run with envelope-declared channels has an envelope row; merging the envelopes
      of all chunks of an episode equals the envelope computed over the whole episode.
- [ ] The impulse envelope's `IntSum` equals the sum of the chunk's quantized impulses exactly.
- [ ] No type in the module accepts a floating value as an aggregate state (compile-fail test).
- [ ] A planted overflow of `Count` is a typed error, not a wrapped value.

## Test plan

### Unit tests

- `laws_count`, `laws_intsum`, `laws_min`, `laws_max`, `laws_or`: for 10⁴ random triples, (a·b)·c = a·(b·c),
  a·b = b·a, a·e = a.
- `permutation_and_shard_invariance`: 1,000 values of a `synthetic` channel; 100 permutations × 100 splits into
  1 to 16 shards; canonical bytes equal.
- `float_sum_counterexample`: in `f32`, with a = 10⁸, b = −10⁸, c = 1: (a + b) + c = 1 and a + (b + c) = 0; the
  same three values quantized at u = 1 sum to 1 in every order.
- `quantize_half_even_table` (the five values above plus 10⁴ random values against exact rational rounding).
- `saturation_counted`: Q = 2¹⁶ − 1, x/u = 10⁶ → q = 65,535 and `saturated_high = 1`.
- `unknown_aggregate_898`; `registry_names_admitted`.
- `envelope_per_chunk`: values (0.1, −0.4, 0.3) rad at u = 10⁻⁴ rad give min −4,000, max 3,000, n = 3.
- `envelope_merge_equals_whole`: 700 ticks at L = 256.
- `impulse_envelope_sum`: impulses (0.2, 0, 0.3, 0.1) N·s at u = 10⁻⁶ N·s give `IntSum` 600,000.
- `orientation_envelope_is_relative`: a link rotating 0.2 rad about z from an initial yaw of 3.0 rad has an
  envelope of [0, 2,000] at u = 10⁻⁴ rad on the z component, not a wrap near π.
- `overflow_is_error`.

### End-to-end script and logging

Step group `aggregate-*` of `scripts/e2e/chronicle_record_surface.sh` (N29a-08): after a referee run,
`frob telemetry query <run> --stream kinematics --aggregate min,max,count --json` is issued twice with the
world filter given in two different orders, and the two answers must be byte-identical; a third call with
`--aggregate tdigest` must exit 3 with FROB-REF-898. Lines carry the aggregate bytes' digest, the frontier, the
evidence block and, on failure, the first differing aggregate. The `--aggregate` option of `telemetry.query`,
which computes the named aggregates through this bead's registry and types, belongs to the verb's bead
(N24a-36, which depends on this bead); the step group runs in N29a-08's script, which depends on both, so it
always reaches the option. This bead's own closure does not wait for the verb: its unit tests above carry the
same checks at library level.

### Known answers and negative controls

- Counterexample carried as a test: the `f32` regrouping case (1 against 0).
- Negative controls: a mutant `IntSum` that accumulates in `f32`; a mutant envelope that takes the mean of the
  minima when merging; a mutant registry that admits `tdigest`. Each must be caught by the tests above.
- Metamorphic relation MR-32 (integer histograms and address-keyed trace sampling are invariant under
  permutation, shard split and slot assignment) is extended here to the scalar aggregates.
- Determinism lanes: canonical bytes compared twice on one machine, across worker counts, debug and release,
  and across the Mac and the Linux host (class D0).

## Considerations

- The quantum is part of the channel schema and therefore of the run's identity; changing it is a new channel
  version, never an in-place edit.
- A too-coarse quantum hides small differences; the envelope then over-states agreement. The divergence search
  treats an envelope as an upper bound only after adding half a quantum on each side.
- Sums of quantized values lose at most u/2 per sample against the real sum; the bound n·u/2 is reported with
  any derived mean.
- Device-side sums wider than 32 bits never use atomics: per-world partial sums and a fixed tree of two-limb
  additions are used instead.
