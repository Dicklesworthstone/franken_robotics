## Background

At milestone M1 the record subsystem (Chronicle) offers an agent a complete read path over what a simulation
left behind: the run is listed, described, broken into content-addressed objects, read by byte range, exported
as single objects and as a whole `.frun` bundle, and checked offline by the independent auditor. Each of those
steps has its own unit tests in its own bead. None of them shows that the steps compose from the user's side:
that the digest printed by one verb is accepted by the next, that the exported bundle is the one the auditor
accepts, that a refusal arrives with the documented exit code on the real binary.

This bead is the end-to-end script for that pipeline. It drives only the real `frob` binary and the real
`frob-verify` binary on a real referee run; it has no mocks and no fakes. It is also where the "reachable
through `frob --json` with a documented schema and exit code" clause of the project's definition of
"implemented" is exercised for these verbs.

## Scope

In: one shell script with seven step groups; its fixtures; its assertions; its structured log; the transcript.
Out: the mechanisms (their beads); the chunk-protocol battery (N29a-06); device tiers (M2 scripts).

## Technical approach

**Script.** `scripts/e2e/chronicle_record_surface.sh`. Plain POSIX shell. It sources the shared helper of the
end-to-end standard, which provides `step`, `run_cmd` (captures the command line, exit code, wall time and the
envelope), `assert_eq`, `assert_exit`, `metric` and `finish`. It is idempotent (every invocation uses a fresh
store under `target/e2e-work/chronicle_record_surface/<utc>/`) and seed-explicit (`--seed 7` everywhere).

**Environment.** `FROB_STORE` and `FROB_EXPORT_ROOT` point into the work directory; no daemon is started (the
CPU-tier verbs run in process and say so in the envelope).

**Step groups and assertions.**

1. `run-*`: `frob sim run --tier referee --fixture g1 --worlds 3 --seconds 6 --telemetry T2 --seed 7 --key r1
   --json`. Assert exit 0, one envelope on standard output, `evidence.tier = "referee"`, a run identifier, and
   that the three no-authorization flags are absent from this non-exporting verb's envelope.
2. `list-show-*`: `frob run list --json` contains the run exactly once; `frob run show <run> --json` reports
   state `complete`, counts that sum to the planned 3 trials, a frontier, the chunk length 256, and progress as
   "3 of 3".
3. `ownership-*` (from N29a-01): the writer recorded for each table equals the ownership map.
4. `objects-*`: `frob artifact list --run <run> --json` paged with `--limit 5` until the cursor ends; assert
   that the union has no repeated digest and that its count equals the chunk count reported by `run show`
   (6 s at the fixture's control rate and L = 256, times worlds, times streams, as printed by the run).
   For the first column object: read it with `frob artifact read <digest> --offset k·65536 --length 65536
   --json` for k = 0, 1, … until `next_offset` is null; assert each `range_blake3` against a local hash of the
   decoded bytes and the hash of the concatenation against `<digest>`.
5. `export-*` (from N29a-02 and BD-097): `frob artifact export <digest> --to exports/c0.fcol --key x1 --json`;
   `frob run export <run> --out exports/a.frun --key e1 --json`; again to `exports/b.frun --key e2`; assert the
   two bundles are byte-identical, that both envelopes carry `authorization` with three `false` flags, and that
   repeating `--key e1` returns `idempotent_replay: true` and leaves the file's modification time unchanged.
   Then three refusals, each expecting exit 3 and `FROB-REF-734`: `--out ../escape.frun`, `--out
   /tmp/escape.frun`, and an export into a directory that the script replaces with a symbolic link to another
   location (checked by listing that location afterwards: it must be empty).
6. `verify-*` (from N29a-03): `frob-verify exports/a.frun --json` exits 0 and reports the same bundle hash as
   the export envelope. Three mutated copies (one flipped byte in a column file; two chunk files swapped; a
   flag edited to `true`) each exit 2 with `first_failure.check` equal to `content`, `chain` and
   `authorization-flag`.
7. `aggregate-*` (from N29a-07): the two-order aggregate query with byte-equal answers, and `--aggregate
   tdigest` expecting exit 3 with `FROB-REF-898`.

**Logging.** `target/e2e-logs/chronicle_record_surface/<utc>.ndjson` and a human-readable transcript
`<utc>.txt` beside it. Every line has `ts`, `script`, `bead` (the bead whose step group it is), `step`, `event`
(`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact command line, exit code, wall time in
milliseconds, and the envelope's `evidence` block (claim, class, tier, determinism, identities, seed). `metric`
lines carry measured values with units and thresholds (bytes read, chunks listed, bundle bytes). `assert` lines
that compare state carry both digests. On failure the line carries the first differing value and the artifact
paths needed to reproduce (store path, export path, the mutated file). The final `summary` line gives the
counts of assertions passed and failed and lists no gate (this script records none; the M1 gates of the record
are recorded by N29a-06 and N29a-10). Logs contain no column data: only digests, counts and paths.

**Exit status.** Non-zero if any assertion fails or any command exits with an unexpected code; the summary line
is written in both cases.

## Acceptance criteria

- [ ] The script passes on the Mac and on the Linux host from a clean checkout with one command and no manual
      setup, in under five minutes on eight cores (TARGET).
- [ ] Each of the seven groups has at least one assertion that fails when its mechanism is broken: shown by
      running the script against six planted defects (below) and observing a non-zero exit with the right step
      named.
- [ ] The log parses as newline-delimited JSON, every line has the mandatory fields, and the summary counts
      equal the number of `assert` lines.
- [ ] Two consecutive runs produce the same run identifier, the same digests and the same bundle hash (only
      timestamps, wall times and paths differ).
- [ ] No private-scene data and no column bytes appear in the log (a scan for base64 payload fields finds
      none).

## Test plan

### Unit tests

The script's helper functions specific to it are tested by `scripts/e2e/tests/chronicle_record_surface.bats`
(or the shell test runner the end-to-end standard chooses): `concat_ranges_hash` on a fixed three-range
input with a known BLAKE3; `swap_two_chunks` produces a bundle whose manifest is unchanged and whose two files
are exchanged; `flip_byte` changes exactly one byte at the requested offset.

### End-to-end script and logging

This bead is the script. Its own verification is the planted-defect matrix, run by
`scripts/e2e/selftest/chronicle_record_surface_defects.sh` against builds with a conformance-only feature flag
per defect:
1. `artifact.read` returns bytes shifted by one: group 4 fails at the first range.
2. `run.export` omits the frontier pin: group 5's byte comparison fails when a background publish is injected.
3. The path check is a string prefix test: the symbolic-link case of group 5 fails.
4. `frob-verify` skips chains: the swapped-chunk case of group 6 fails.
5. `IntSum` accumulates in `f32`: group 7's byte comparison fails.
6. `run.show` reports "100%" instead of "3 of 3": group 2 fails.

### Known answers and negative controls

- Known answers used: the object digests recorded in the ledger; the bundle hash reported by the exporter; the
  truth that 3 planned trials are 3 completed trials on this fixture.
- Negative controls: the six planted defects; the three mutated bundles; the three path escapes.
- Determinism lanes: the script twice on one machine (digests equal); debug and release builds of `frob`; the
  Mac against the Linux host for bundle bytes (class D0 for the encoding; the referee's state digests are
  compared per platform and a cross-platform difference is recorded, not asserted).

## Considerations

- The script is the M1 demonstration that the record is usable without a device or a daemon; it must stay
  inside the default machine envelope.
- When the M2 verbs arrive (`store.status`, `telemetry.histogram`, `sim.replay`), they get their own scripts;
  this one is not extended, so that an M1 regression stays attributable.
- The symbolic-link case needs a filesystem that supports links; on one that does not, the step is reported
  `not run` with the reason and the summary says so.
