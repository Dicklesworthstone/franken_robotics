## Background

Delivery work in this project is tracked in beads (work items). The project's standing risk is false progress:
a bead closed because its author says it is done. The countermeasure is that a bead closes only on evidence that
a different session recorded, and that the public status table is generated from those records and never
edited. The record subsystem (Chronicle) supplies the record: an append-only structured log per bead.

Every bead has a log, `docs/delivery/logs/<bead>.ndjson`, schema `frob.beadlog/1`, with one line per recorded
event:

```json
{"ts":"2027-02-11T09:14:03Z","bead":"BD-203","commit":"3f9c…","host":"m5u-01:fingerprint:8b1e…",
 "toolchain":"nightly-2026-07-06","determinism":"D2","state_hash":"u128:5a07…","claim_type":"Known answer",
 "claim_ids":["c:7d21…"],"metrics":{"worlds_replayed":{"v":1000,"unit":"1"},"digest_mismatches":{"v":0,"unit":"1"}},
 "refusals":[],"verdict":"pass","recorded_by":"session:fresh-41","gate":"GATE-CHRON-01"}
```

**The closing rule.** A bead closes only with a line whose verdict is `pass`, whose `claim_ids` resolve in the
artifact graph, and whose recording session is not the session that implemented the bead. The honest-status
table is generated from these logs and the gate registry. The check is part of the existing generated-artifact
check; it adds no new tool. The log has no verb: it is written by the gate recorder.

Rejected alternatives: closing on a free-text reason (not checkable); storing the log only in the ledger (the
ledger is machine-local, while the log must travel with the repository so that a fresh clone can regenerate the
status table); allowing an edit of a past line (the log would then record opinions about the past).

## Scope

In: the schema; the append function and its checks; append-only enforcement; the closing-rule evaluator; the
refusal; the generator input for the honest-status table; the event kinds beyond gate records.
Out: the artifact graph that resolves `claim_ids` (BD-095); the gate recorder and gate registry (the
verification-harness beads); the bead tracker itself; exit reviews.

## Technical approach

**1. Schema `frob.beadlog/1`.** One JSON object per line, keys in the order below, UTF-8, no trailing spaces.

| Field | Type | Rule |
|---|---|---|
| `ts` | RFC 3339 instant, UTC | Recorded for humans; never hashed |
| `bead` | string | The bead's key; must equal the file name |
| `event` | `gate-record` (default when absent), `blocked`, `unblocked`, `note` | DESIGN addition, see 5 |
| `commit` | 40-hex commit of this repository | Must exist in the repository at append time |
| `host` | `<name>:fingerprint:<digest>` | The hardware fingerprint current at the run |
| `toolchain` | string | The toolchain the run was built with |
| `determinism` | `D0` … `D4` | The class of the recorded result |
| `state_hash` | `u128:<hex>` or `blake3:<hex>` | The digest the result is bound to (a run digest, a bundle hash) |
| `claim_type` | one of the seven claim kinds | — |
| `claim_ids` | array of `c:<hex>` | At least one for `verdict = pass` |
| `metrics` | object of `{ "v": number or string, "unit": string }` | Measured values, not targets; integers above 2⁵³ as strings |
| `refusals` | array of refusal codes met during the run | — |
| `verdict` | `pass`, `fail`, `not-run`, `fallback`, `superseded` | `fallback` and `superseded` name an ADR in `cause` |
| `recorded_by` | `session:<id>` | The session that ran the recorder |
| `implemented_by` | array of `session:<id>` | The sessions that changed the bead's code, read from commit trailers |
| `gate` | a gate, kill-gate or admission-gate identifier, or null | — |
| `cause` | string, optional | For `blocked`, `unblocked`, `fallback`, `superseded`: a short cause tag or ADR id |

**2. Appending.** `beadlog::append(bead, line)`:
1. Validate against the schema; `bead` equals the file's stem.
2. Check the commit exists and the host fingerprint string is well formed.
3. For `verdict = pass`: `claim_ids` is non-empty and each resolves in the artifact graph now (else the line is
   written with `verdict = fail` and the refusal recorded; a pass that cannot be traced is not a pass).
4. Open the file in append mode, write one line ending in a newline, flush, and record the file's new BLAKE3
   prefix chain value in the ledger (`ledger row` evidence), so that a later rewrite of an earlier line is
   detectable: line n's chain value is BLAKE3(chain of line n − 1 ‖ bytes of line n).
5. The repository check (part of `check-generated`) recomputes the chain from the file and fails on a mismatch
   with the last recorded value, and fails if the history of the file shows a removed or altered line.

**3. The closing-rule evaluator.** `beadlog::may_close(bead)` returns `Ok(line)` for the latest line that has
`verdict = pass`, all `claim_ids` resolving, and `recorded_by ∉ implemented_by`; otherwise it returns
FROB-REF-815 (closing a bead without a resolving log line from another session; repair: record the gate from a
fresh session; exit 3) with the reason: `no-pass-line`, `claims-unresolved` (naming them) or `self-recorded`.
A bead whose kill gate fired closes with a `fallback` line naming the fallback; a dependent that needed the
killed capability closes with `superseded` and the ADR identifier. The tracker's close command calls this
evaluator through the delivery tooling; a close reason shared by several beads is a failure signal that the exit
review rejects.

**4. Feeding the status table.** `beadlog::status_inputs()` yields, per bead, its latest verdict, gate, measured
metrics and claim identifiers. The existing generator of the honest-status table reads these together with
`registries/gates.toml`; the table is regenerated in `check-generated` and a hand edit is a diff that fails the
check. A gate with no record has the status `not run`, which is not a pass.

**5. Other events (DESIGN).** `blocked` and `unblocked` lines carry a `cause` tag (`upstream`, `owner-decision`,
`compute-envelope`, `dependency`, `defect`) so that schedule analyses can attribute waiting time; `note` lines
carry free text in `cause`. These lines have `verdict = not-run` and never satisfy the closing rule.

**6. Layout.** `crates/frob-chronicle/src/beadlog.rs`; `docs/delivery/logs/`; the schema file
`schemas/frob.beadlog.1.json`.

## Acceptance criteria

- [ ] The example line above validates; a line with a missing unit, a `bead` that differs from the file name, a
      non-existent commit, or a pass with an empty `claim_ids` is rejected.
- [ ] `may_close` returns the pass line for a bead recorded by another session, and FROB-REF-815 with the right
      reason in each of the three failing cases.
- [ ] A pass line whose claim is later tombstoned makes `may_close` fail with `claims-unresolved`.
- [ ] Editing or deleting an earlier line makes `check-generated` fail; appending does not.
- [ ] The honest-status table regenerated from the logs equals the committed one; a planted self-certification
      and a planted pass with an unresolved claim are both refused by the generator's input stage.
- [ ] `blocked` and `unblocked` lines round-trip and never count as a pass.
- [ ] Every metric carries a unit and is the value the run measured; a line with a metric object lacking `unit`
      or carrying a threshold in place of a value (a field named `target`) is rejected by the schema.

## Test plan

### Unit tests

- `example_line_validates`; `schema_rejections` (the four cases).
- `pass_requires_resolving_claims`: with a dangling claim the line is stored as `fail` with the refusal.
- `may_close_other_session_ok`; `may_close_self_recorded_815`; `may_close_no_pass_815`;
  `may_close_unresolved_815`.
- `fallback_and_superseded_lines`: accepted only with a `cause` naming an ADR.
- `chain_detects_rewrite`: change one character of line 2 of a five-line log; the recomputed chain differs at
  line 2.
- `append_only_under_concurrent_writers`: two recorders append 100 lines each; 200 well-formed lines result
  (file locking through an exclusive create of a lock file).
- `status_inputs_latest_wins`.
- `blocked_unblocked_never_pass`.

### End-to-end script and logging

Step group `beadlog-*` of `scripts/e2e/evidence_trace.sh` (N29a-10): the recorder is run from a second session
identity for a small known-answer test, the line is appended, `may_close` is queried through the delivery
tooling's dry-run, and then the same is attempted with the implementing session's identity, expecting
FROB-REF-815 and exit 3. Lines of the script's own log carry the bead, the appended line's digest, the chain
value, the resolver's answer per claim and the closing verdict.

### Known answers and negative controls

- Negative controls: self-certification (the same session implements and records); a pass with an unresolved
  claim; a rewritten line; a hand-edited status table. Each must be refused or fail the check.
- The status-accounting gate of the verification program (the README table equals a fresh generation from the
  gate registry; a planted self-certification and a planted PASS with an uncaught control are each refused)
  reads this log.
- Determinism: the generator's output is a pure function of the logs and the registry; bytes compared on repeat
  and across platforms.

## Considerations

- A closed bead is not acceptance; acceptance is the gate's row in the gate registry. The log is evidence for
  both.
- Session identity is whatever the recorder stamps; this bead trusts it as data and makes disagreement visible
  (commit trailers against `recorded_by`). It is a guard against carelessness and reward hacking, not against a
  determined forger.
- Logs live in the repository and must stay small: metrics and identifiers only, no traces and no scene data.
