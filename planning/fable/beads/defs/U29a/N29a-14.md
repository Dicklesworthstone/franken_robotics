## Background

Integer histograms are the project's only distributional summary on the evidence path (decision ADR-CHRON-03:
evidence aggregates are integers). On the throughput tiers they must be filled on the device, every control
tick, for every world, without a host round trip and without breaking determinism. `K-x-hist` is the kernel
that does it. It is a member of the kernel library's *exact* family (with the exact predicates, the digest and
the Philox kernel): kernels whose arithmetic is unsigned 32-bit integers, which is class D0 (exact) on every
backend.

The arithmetic is count-leading-zeros, shifts, masks and integer add: exact on every backend. Merging two
histograms is integer addition of counts. A run-level histogram may be accumulated on the device with integer
atomic add in 32-bit bins, under a width rule: the host drains the bins into 64-bit totals at every chunk
commit, a step plan is admitted only if no bin can receive more than 2³² − 1 increments in one chunk, and no
backend is asked for a 64-bit atomic. FACT to recheck by the hardware fingerprint: the Metal shading language
offers no 64-bit integer atomic add; a 32-bit count wraps after 2³² = 4,294,967,296 increments, which a run at
4 M world-steps/s reaches in 18 minutes if one bin receives every sample.

Integer atomic add is the one place this project uses an atomic in a kernel. It is licensed because integer
addition is order-independent; floating-point atomics, the main source of GPU nondeterminism, stay banned.
Tier Solid.

Rejected alternatives: computing histograms on the host from traces (only sampled worlds have traces);
per-world histograms merged by a reduction tree only (correct, but 640 bins per world per channel is too much
state for a run-level summary; the atomic form keeps one histogram per channel per shard).

## Scope

In: the kernel's manifest, its Rust skeleton for `batch-cpu` and its shared-dialect source for CUDA and Metal;
the quantization step and its admission rule; the two accumulation forms (run-level atomic, per-world row);
masks; zeroing; the per-kernel differential check; tests.
Out: the host-side histogram type and queries (N29a-13); the no-wrap bound and the drain (another unit); which
channels are histogrammed and when the kernel runs in the step plan (BD-207); the verb (N29a-15).

## Technical approach

**1. Manifest (`frob.kernel/1`).** Name `K-x-hist`; class `exact`, math mode `ExactInteger` for the binning and
accumulation; a separate small `float` prelude function for quantization. Reads: one value slab per
histogrammed channel (the world's own rows), the world's active mask, the channel parameter block (quantum
reciprocal, range, m, s). Writes: the run-level bin slab (shared across worlds, atomic add only) or the world's
own per-world histogram row. No other cross-world access. Loop bounds: worlds × samples per world from the
shape class.

**2. Quantization on the device.** q = round-half-even(x/u), saturated to [−(2ᵐ − 1), 2ᵐ − 1] with a side
overflow flag.
- The division is admitted on a device family only if the IEEE probe recorded correctly rounded
  single-precision division for it; otherwise the channel's quantum must be a power of two, so that x·(1/u) is
  an exact scaling, or the channel is histogrammed on the host from T2 traces and the envelope says so.
- Round-half-even without a built-in: for |y| < 2²³, t = (|y| + 2²³) − 2²³ under the default rounding mode,
  with the sign restored by a select; for |y| ≥ 2²³ the value is already an integer. Fast-math and contraction
  are off on every backend, so the two additions are not folded; a start-up canary checks t for the inputs 0.5,
  1.5, 2.5 and 8,388,607.5.
- A NaN marks the world `Faulted` and contributes to no bin.
The result depends only on the bits of x.

**3. Bin index.** With a = |q| as `u32`: if a < 2ˢ, b = a; else e = 31 − clz(a), b = ((e − s + 1) << s) +
((a >> (e − s)) & (2ˢ − 1)); a ≥ 2ᵐ selects the overflow bin. The branch is a select; shifts are by masked
counts. The flat slot is `side·(B + 1) + b` with B = (m − s + 1)·2ˢ and the overflow bin at index B.

**4. Run-level accumulation.** `atomic_add_u32(bins[channel][slot], 1)` under the world's active mask (a masked
world adds 0 through a select of the increment, never by skipping the atomic conditionally in a way that
changes control flow across lanes). Defaults: m = 24, s = 5, 2 × 641 slots per channel.

**5. Per-world accumulation.** The world's own row of 2 × 113 `u16` counts (m = 16, s = 3), packed in `u32`
words on Metal, updated by a saturating increment `min(c + 1, 65,535)`. No atomic is needed: a world writes
only its own row.

**6. Zeroing.** The first kernel of each chunk zeroes the run-level device bins (they are drained at the
previous commit). Per-world rows are zeroed at the world's reset.

**7. Placement in a chunk.** The kernel runs once per control tick after stage 10 for channels sampled at
control rate, or once per physics step for channels declared at step rate; the step plan records, per
histogram, the number of increments one bin can receive in a chunk, which is what the no-wrap bound reads.

**8. CPU reference.** The `batch-cpu` symbol runs the same integer code with a plain add in a fixed loop; it is
the reference of the retained differential check, compared word for word with each device.

**9. Layout.** `crates/frob-kernels/src/exact/hist.rs`, `kernels/dialect/exact/k_x_hist.h` (shared dialect),
tests in `crates/frob-kernels/tests/k_x_hist.rs` and the backend annexes.

## Acceptance criteria

- [ ] On `batch-cpu`, CUDA and Metal the bin slabs after 10⁶ samples of a pinned input corpus are identical
      word for word, and equal to the host histogram type's counts for the same quantized values.
- [ ] Counts are identical when the same samples are processed under 100 permutations of world order and with
      worlds split across one and two devices (sum of the two shards' bins).
- [ ] The quantizer matches exact rational round-half-even on a corpus of 10⁶ values including every half-way
      case in [−1,024.5, 1,024.5], on each backend where division is admitted; on a family where it is not, a
      non-power-of-two quantum is refused for device histograms with the reason recorded.
- [ ] A masked (inactive or padding) world changes no bin.
- [ ] A NaN sample faults its world and changes no bin.
- [ ] The dialect source contains no floating-point atomic and no 64-bit atomic (lint), and no data-dependent
      loop bound.
- [ ] Per-world rows saturate at 65,535 and never wrap.
- [ ] The kernel's manifest footprint equals what the kernel touches (footprint test of the harness).
- [ ] The differential check is recorded per device family and is current before the kernel appears in a
      scored step plan.

## Test plan

### Unit tests

- `bin_index_matches_host`: for all 2¹⁶ magnitudes at (16, 3) and 10⁶ random magnitudes at (24, 5), the kernel's
  slot equals the host function's.
- `quantize_half_even_device`: 0.5 → 0, 1.5 → 2, 2.5 → 2, −0.5 → 0, −2.5 → −2, 8,388,607.5 → 8,388,608.
- `quantize_power_of_two_quantum_exact`: u = 2⁻¹⁰; 10⁶ random inputs equal the exact result.
- `masked_world_adds_nothing`; `nan_faults_world`.
- `atomic_add_order_independent`: the CPU harness applies the increments in 100 random orders; equal slabs.
- `per_world_saturation`: 70,000 samples in one bin read 65,535.
- `overflow_bins`: a value of 2²⁴ quanta lands in the positive overflow slot; −2²⁴ in the negative one.
- `zeroing_first_kernel_of_chunk`: bins written in chunk n are zero at the first sample of chunk n + 1 after
  the drain hook has copied them.
- `footprint_matches_manifest`.
- `lint_no_float_or_wide_atomic`.

### End-to-end script and logging

Step group `kernel-*` of `scripts/e2e/telemetry_sampling_histograms.sh` (N29a-16): `frob spark check --kernel
K-x-hist --json` on each present device family (the CPU-versus-device check of the kernel on a pinned corpus),
then a 4,096-world job run on `batch-cpu` and on each device, with the run-level histograms' canonical digests
compared. Lines carry the device, the fingerprint digest, the placement receipt, the corpus digest, the number
of differing words (threshold 0) and, on failure, the first differing slot with both counts.

### Known answers and negative controls

- KA-714: counts identical under 100 permutations and shard splits, on every backend.
- Boundary of the width rule (owned by the wide-count beads, exercised with this kernel): 65,536 worlds × 4,096
  intervals × 16 samples is exactly 2³² and is refused; one sample fewer per chunk is admitted; a mutant plan
  that lets one bin receive 2³² + 5 increments in a chunk reads 5 on the device.
- Mutants this bead's tests must catch: a floating-point accumulator in place of the integer bins; an increment
  applied before the mask; the sub-bucket taken from the low bits; a quantizer using multiply by a rounded
  reciprocal for a non-power-of-two quantum (differs at half-way cases); a branch on the active mask that skips
  lanes.
- Determinism lanes: twice on one device (class D2 trivially, D0 by construction); across devices (D0); debug
  and release on the CPU.

## Considerations

- The 32-bit bins are safe only together with the plan-time bound and the per-commit drain; this kernel must
  not be admitted into a plan without them, and the plan check refuses otherwise.
- On Metal 16-bit fields are packed into `u32` words because the gateway's typed helpers read `f32`, `u32` and
  bytes; the packing is part of the layout descriptor.
- Cost: one pass over each histogrammed channel per sample instant and one atomic add per sample. Atomics on
  the same bin contend when a distribution is concentrated; the cost is measured by the telemetry cost gate and
  the fallback, if contention is material, is per-world partial counts reduced by the fixed integer tree.
- The kernel bins whatever integer it is handed; the bit-pattern variant described in the numerics chapter
  (sign, exponent and top five mantissa bits of an `f32`) is this kernel with the quantizer replaced by a
  reinterpretation and s = 5 applied to the significand.
