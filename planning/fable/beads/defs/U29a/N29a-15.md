## Background

An agent asks distributional questions about a batch: what is the 95th percentile of knee torque, how is
friction utilization distributed at the front feet, how often does base height drop below a line. The record
subsystem (Chronicle) answers them from integer histograms: a channel's values are quantized to integers,
counted in bins that are exact for small magnitudes and logarithmic above, and merged by integer addition, so
the answer is the same bits under any shard split or world order. This verb is the read surface for them:
`frob telemetry histogram <run> --channel <name> --quantile 0.95` returns the bounds of the bin that contains
the quantile, as an interval, with the count. It never returns a point it did not measure.

Registry name `telemetry.histogram`, cluster `telemetry`, kind `read`, first milestone M2, tier Solid. It
computes nothing on a device and runs with no daemon: it reads stored T0 histograms and ledger totals.

Design points:
- **A quantile is an interval.** The histogram knows which bin holds the requested rank and nothing finer.
  Returning the bin's midpoint would present a number that was not measured; two runs could then "differ" by an
  amount that is an artifact of interpolation.
- **Probabilities are exact.** `0.95` on the command line is parsed as the rational 19/20, so the target rank
  is computed in integers and is the same on every machine.
- **Scope is explicit.** A run-level histogram covers every world; a per-world histogram covers one episode.
  A histogram over traced worlds only (for a channel that exists only at T2) is a sample and is returned with
  its inclusion weights, never presented as the population.

## Scope

In: the registry entry, schemas, argument parsing, the three scopes, the output, weighting for sampled
channels, comparison of two runs' histograms, refusals, pagination of long bin lists.
Out: histogram mathematics (N29a-13); filling histograms on devices (N29a-14, BD-207); the selection rule and
weights (N29a-12); scorecard metrics that consume quantiles (the task subsystem's beads).

## Technical approach

**1. Registry entry.** The row is VERBS-telemetry's and this bead implements it without redefining it: kind
`read`, `idempotent = true`, capability `telemetry:read`, schemas `frob.telemetry.histogram.in/1` and
`frob.telemetry.histogram.out/1`, the static cost model, task cluster `runs`, owner `frob-chronicle`, chapter
refusals FROB-REF-840 (a sealed confirmation run), FROB-REF-888 (gaps in the requested scope) and FROB-REF-898
(any `--method` other than `histogram`), evidence *pass-through*, example `frob telemetry histogram r:19e2
--channel tilt --json` (which must run with the run identifier substituted: the test fixture declares a
run-level histogram on a `tilt` channel, the base tilt angle). The handler also raises the surface's
FROB-REF-802, and, the bin list being paginated (`paginated = true`, which appends 806 and 807), a cursor
mismatch on it surfaces as FROB-REF-806 with the store's FROB-REF-896 as its cause (the division recorded in
N29-REF); all exit 3.

**2. Input.** `run`; `channel` (a declared channel name; an unknown name is FROB-REF-802 with the nearest
declared names in `repairs`); `scope` (`run` by default, `world` with `--world <address>`, `traced`);
`quantile` (zero or more decimal or rational probabilities in (0, 1]); `bins` (include the sparse bin list;
default off for a run-level histogram with more than 64 non-empty bins, where the list is paged); `against`
(a second run for a side-by-side answer); `method` (default `histogram`; any other value is FROB-REF-898);
`at_frontier` (optional pin); `resolution` (optional: a relative width as a rational in (0, 1]; it changes no
number in the answer, and when a returned interval is relatively wider the answer's `next_actions` say to
declare the channel with a larger s in the next run). On the command line these are `--channel`, `--scope`,
`--world`, `--quantile` (repeatable), `--bins`, `--against`, `--method`, `--at-frontier` and `--resolution`,
the spellings and domains of the row.

**3. Algorithm.**
1. Resolve the run and the channel declaration; refuse a sealed confirmation run (FROB-REF-840).
2. Pin the committed frontier (the store's pinned query) so that the answer names the commit sequence number it
   was computed at.
3. Load the histogram: `run` scope from the ledger's 64-bit totals for the channel (merged over devices and
   chunks by integer addition); `world` scope by merging that world's per-world T0 rows over its chunks;
   `traced` scope by binning the T2 samples of traced worlds on the host with the same quantizer.
4. Coverage: if the channel has gaps inside the requested scope, or the channel was not histogrammed at that
   scope in this run, refuse with FROB-REF-888 (a metric computed over missing samples; repairs: re-run with
   the channel retained; accept `unavailable`). Coverage is never repaired by estimation.
5. For each probability c/d: rank r = ⌈c·N/d⌉; find the bin; build the interval.
6. For `traced` scope attach the strata (failing worlds at weight one, sampled worlds at weight 1/p or N/k) and
   compute weighted counts as exact rationals; quantiles are taken over the weighted counts and the answer is
   labelled `sample: true`.
7. With `against`: compute both histograms at their own pins and return them side by side with, per requested
   quantile, whether the two intervals are disjoint, overlapping or identical. No difference of quantiles is
   printed as a number.

**4. Output (the `result` of `frob.telemetry.histogram.out/1`).**

```json
{ "run": "r:19e2…", "channel": "joint_torque.knee_fl", "unit": "N·m", "kind": "state",
  "scope": "run", "quantum": "1/100", "m": 24, "s": 5, "count": "81920000", "frontier": "18233",
  "underflow": "0", "overflow": "0", "saturated": false,
  "quantiles": [ { "p": "19/20", "rank": "77824000", "interval": ["12.155", "12.475"], "bin": ["1216", "1247"],
                   "count_in_bin": "912004", "exact": false, "overflow": "none" } ],
  "bins": null, "sample": false, "strata": null }
```

Counts and ranks are decimal strings (they can exceed 2⁵³). Interval bounds are decimal strings in the
channel's unit, exact images of the integer bounds widened by half a quantum. The envelope's `evidence` block
is *pass-through*: the claim product of the run it reads (its class and tier), determinism `D0` for the
aggregate (the weakest-input rule may lower the envelope's class to the run's), identities and seed, and no
claim of its own (`claims: []`). `cursor` and `frontier` are present when the
bin list is paged. Exit 0; exit 2 when a requested quantile lies in an overflow bin or a count is saturated (a
finding: the declared range or count width was too small).

**5. Layout.** `crates/frob-verbs/src/verbs/telemetry_histogram.rs`; schemas under `schemas/`.

## Acceptance criteria

- [ ] `frob telemetry histogram <run> --channel <c> --quantile 0.95 --json` returns an interval and a count,
      and the interval contains the 95th percentile computed from the full trace of an all-traced reference run.
- [ ] The answer's bytes (apart from cost and timing fields) are identical for the same job run in one shard,
      two shards and co-batched with another job.
- [ ] No output field holds an interpolated point; the schema has no scalar quantile field (schema test).
- [ ] `--method tdigest` is refused with FROB-REF-898 and names `histogram`; a channel with gaps in scope is
      refused with FROB-REF-888; a sealed run with FROB-REF-840; an unknown channel with FROB-REF-802 and
      suggestions.
- [ ] `traced` scope returns `sample: true`, the strata sizes and the weights, and its weighted count equals
      N within the exact interval for the sampling rate.
- [ ] A quantile in the overflow bin is one-sided with exit 2.
- [ ] Probabilities are exact: `--quantile 0.95` and `--quantile 19/20` give byte-identical answers; with N = 3
      and `--quantile 0.5` the rank is 2.
- [ ] The verb is reachable through `frob --json` and MCP (`telemetry_histogram`), and its answer names the
      frontier it was computed at.

## Test plan

### Unit tests

- `parse_probability_exact`: "0.95" → 19/20; "1/3" → 1/3; "0" and "1.2" refused (802).
- `rank_integer`: N = 81,920,000, 19/20 → 77,824,000.
- `interval_strings_exact`: bin [1,216, 1,247] at quantum 1/100 → ["12.155", "12.475"].
- `scope_world_merges_chunks`: three chunks of per-world rows merge to the episode histogram.
- `scope_traced_weights`: p = 1/100 with 3 failing and 79 sampled non-failing worlds: weights 1 and 100.
- `gap_in_scope_888`; `not_histogrammed_888`; `sealed_840`; `unknown_channel_802_with_suggestions`;
  `method_898`.
- `against_reports_relation_not_difference`: two runs whose p95 intervals are [12.155, 12.475] and
  [12.475, 12.795] report `overlapping` (they share an endpoint); no numeric difference field exists.
- `overflow_quantile_exit_2`.
- `paged_bins_pinned`: paging the bin list during a concurrent append returns each bin once at the pin; a cursor
  replayed with another channel is refused with FROB-REF-806 whose cause is FROB-REF-896.
- `registry_example_runs`: the registry example with the fixture run's identifier in place of `r:19e2` exits 0.

### End-to-end script and logging

Step group `verb-*` of `scripts/e2e/telemetry_sampling_histograms.sh` (N29a-16): on the 4,096-world runs of the
`kernel-*` group (`batch-cpu` and each device), `frob telemetry histogram <run> --channel joint_torque.knee_fl
--quantile 0.5 --quantile 0.95 --json`; assert byte-equal answers (apart from cost and timing fields) across the
shard and co-tenancy variations of the gate's tier run (N29a-16 step 2); on an all-traced 64-world run, `frob
sim run <reference quadruped> --scene <rough ground> --tier batch-cpu --worlds 64 --seconds 4 --telemetry T2
--trace-rate 1/1 --seed 20261122 --key hist-ref --json`, assert that each returned interval contains the
percentile the script computes from that run's full trace (read with `frob telemetry query <run> --channels
joint_torque.knee_fl --json`); and the four refusals with their exit codes. Lines carry the command, exit code, wall time, the evidence block, N, the frontier, each interval
with its unit against the reference value, and the answer's digest.

### Known answers and negative controls

- KA-714 (counts identical under permutations and shard splits; the 1, 2, 3 streams): the verb on a three-sample
  `synthetic` channel at quantum 1 returns the median bin [2, 2] with `exact: true` for both orders.
- Negative controls: a build that returns the bin midpoint (the schema test and the "no point" check fail it);
  a build that parses the probability as a binary float (at N = 100 and p = 0.07 the product 0.07·100
  evaluates to 7.000000000000001 in double precision, so ⌈·⌉ gives 8 where the exact rank ⌈7·100/100⌉ is 7;
  the test pins r = 7); a build that silently drops gaps.
- Determinism lanes: answer bytes twice on one machine, across platforms, and across backends for the same
  addresses (the integer aggregate is class D0; the envelope reports the run's class).

## Considerations

- Per-world histograms use 16-bit saturating counts; a saturated count is reported (`saturated: true`) and
  quantiles that depend on it are flagged, not guessed.
- The relative resolution of a quantile is the bin width, 3.1% at the default s = 5; a caller needing finer
  resolution asks for the channel to be declared with a larger s in the next run. The verb says so in
  `next_actions` when an interval is wider than a caller-supplied `--resolution`.
- Histograms of privileged channels carry the privileged label in the output; whether a policy may read them is
  enforced elsewhere.
- Token budget: the default answer (quantiles only) is under 400 tokens; bin lists are paged.
