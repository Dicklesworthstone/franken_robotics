## Background

Replay, teleport, forks, preempt-resume and counterfactual debugging all start from the same object: a stored
state of a world from which the simulation continues exactly as it would have. No foundation library in the
suite has an atomic full-world snapshot, so snapshots covering world, sensor, estimator, policy, solver and
stream state are this project's. The record subsystem (Chronicle) owns the snapshot as a stored object; other
subsystems own the meaning of the bytes in their part of it.

**What a snapshot contains.** Physical state as group elements, velocities and anchored cell indices; contact
feature memory, impulses and every solver warm start; the phase accumulators of every clock and every packet
queue with its packets; controller, estimator and filter state, including a policy's recurrent state; actuator
thermal and electrical state; the step counter that indexes the counter-based random streams (there is no
generator state to save); scene state the robot can change (movable objects, and film or wear fields where
those features are on); learning state when the run is a training run; the command cursor; and the provenance
identities. Full snapshots are relocatable; sparse differences are stored between them. A snapshot is bound to
its numerical profile: restoring it under another profile is a comparison replay, not a continuation.

Why every item is there: a retried or replayed step that keeps part of its state diverges. Warm starts carry
solver state across steps; a checkpoint with its packet queue stripped does not replay; a policy with recurrent
state restarted from zeros takes a different action. Each omission is a registered negative control.

This bead defines the container: the format, the section registry, the completeness check, relocation, sparse
differences, hashing and the profile binding. It writes no physics. Telemetry level T3 is "full state snapshots
at intervals, sufficient for exact restart"; this container is what T3 stores. Tier Solid.

## Scope

In: the format `frob.snapshot/1`; the section registry and the contribution trait; completeness against the

## Technical approach

**1. Format (DESIGN).** A snapshot of one world is a canonical byte string:
- header: magic `FSNP`, format version, `EpisodeId`, world address (run seed, world, episode), control tick and
  substep, the **profile identity** (BLAKE3 of precision profile, contact law, step profile, step size, kernel
  versions and shape-class identity), `ModelId`, `SceneId`, task and policy identities, the step counter of the
  random streams, the command cursor, the state digest and digest-chain value at this tick;
- a section table: for each section its registered identifier, owner, element schema identifier, byte offset
  and length, sorted by identifier;
- section bodies: little-endian arrays in the generated structure-of-arrays layout of the owner's slabs, with
  only the world's **active** elements (padding is never stored).
The content hash is BLAKE3 over the whole string. A snapshot is stored as a content-addressed object and a row
of the `snapshot` table: `(content hash, episode, tick, kind: full | diff, base: content hash or null, bytes,
trigger)`.

**2. Section registry.** `registries/snapshot-sections.toml`, one row per section: identifier, owning subsystem
and crate, the slabs it serializes, whether it is required for a continuation, and the negative control that
proves it is needed. The initial sections:

| Section | Owner | Contents |
|---|---|---|
| `phys.state` | dynamics | Configuration as group elements, velocities, anchored cell indices and offsets, turn counts |
| `contact.memory` | contact | Contact feature memory by feature pair, impulses, every solver warm start, stick or slip state |
| `clock.phase` | sensing | Phase accumulators and next-event times of every clock |
| `sense.queues` | sensing | Packet queues with their packets, open exposures with partial integrals, noise-process states, latent values |
| `control.state` | control | Controller, estimator and filter state and histories; fallback and layer state |
| `policy.state` | learning | Recurrent state; action hold |
| `actuator.state` | actuators | Winding currents, temperatures of thermal nodes, battery state of charge and polarization |
| `scene.mutable` | scene | Poses and velocities of movable objects; film and wear fields where on |
| `learn.state` | learning | Present only for a training run: weights digest reference, optimizer state, normalizers, rollout cursor |
| `task.state` | task | Requirement monitor state, reward accumulators, goal cursor |

Each owner implements `SnapshotSection { id, encode(world, slabs) -> bytes, decode(bytes, slabs, world),
schema() }` (trait in `frob-core`, so that crates below layer 6 do not link `frob-chronicle`).

**3. Completeness.** The step plan lists its *canonical state slabs*, the slabs a continuation must restore
(the same list the state digest folds). At environment creation the container checks that every canonical slab
is covered by exactly one registered section and that no section names a slab outside the list. A slab without
a section is a build-time refusal naming the slab; this is what makes "a field added to the state is added to
the snapshot" true by construction. After `encode`, the container decodes into a scratch world and recomputes
the state digest with the host reference `frob_chronicle::digest::reference` (N29ap1-01); it must equal the
header's.

**4. Relocation.** A full snapshot names no slot, batch, shard or device. `restore(snapshot, env, slot)` writes
the world's active elements into any free slot of any environment whose profile identity equals the snapshot's
and whose shape class admits the model, and fills padding with the neutral elements. Restore is refused if a
required section is absent.

**5. Sparse differences.** Between two full snapshots of one episode a *diff* stores, per section, either the
full section (when more than half its bytes changed) or a list of (offset, length, bytes) runs against its
base. `materialize(diff)` applies the runs to the base and must reproduce the full snapshot's content hash,
which the diff's row records. Chains of diffs are bounded (default: a full snapshot every eighth entry).

**6. Profile binding.** `restore` compares profile identities. Equal: a continuation is permitted. Different:
the caller must ask for a comparison replay; a restore under another profile that is labelled a continuation
is refused with FROB-REF-894 (a snapshot restored under another numerical profile and labelled a continuation;
repair: request a comparison replay; exit 3). A comparison replay converts values exactly where a conversion
exists (single precision widens to double precision exactly; integer state is copied), marks every section it
could not convert exactly, and returns a handle typed `ComparisonStart`, which the replay engine accepts only
for tolerance comparison and never chains into the parent's digest chain.

**7. Layout.** `crates/frob-chronicle/src/snapshot/{format.rs, sections.rs, complete.rs, relocate.rs, diff.rs,
profile.rs}`; the trait in `crates/frob-core/src/snapshot.rs`.

## Acceptance criteria

- [ ] A snapshot taken at any control tick of a `batch-cpu` run and restored into (a) the same slot, (b) another
      slot, (c) a batch of another size, (d) another shape class that admits the model, continues with state
      digests equal to the uninterrupted run for 500 ticks.
- [ ] Removing any one required section in turn makes the continuation's digests differ or the restore refuse,
      and each case is the registered negative control of that section.
- [ ] A canonical slab with no section fails environment creation with the slab named (planted).
- [ ] `materialize(diff)` reproduces the full snapshot's content hash for 10³ random (base, target) pairs.
- [ ] The stored bytes of a world's snapshot are identical whichever slot, capacity or co-tenants the world had.
- [ ] Restoring under another profile as a continuation returns FROB-REF-894; as a comparison replay it returns
      a `ComparisonStart` that the type system does not accept where a continuation is required.
- [ ] Single-precision values widened for a comparison replay equal the originals when narrowed again, for
      every finite value and both signed zeros.
- [ ] One flipped byte in a stored snapshot is detected by the content hash before any state is written.

## Test plan

### Unit tests

- `roundtrip_encode_decode`: a `synthetic` world with a distinct sentinel in every slab; decode(encode) equal.
- `relocate_slot_batch_capacity` (the four cases above, 200 seeds).
- `padding_not_stored`: bytes equal at capacities 32, 64 and 128.
- `section_omission_matrix`: ten sections, ten planted omissions, each caught as stated.
- `packet_queue_stripped_does_not_replay`: a checkpoint taken just after a packet is dropped, restored without
  `sense.queues`, delivers a different observation at the next delivery instant.
- `three_adversarial_instants`: snapshots just after a shutter opens, just after a packet is dropped and just
  before a controller tick each continue bit for bit.
- `completeness_refuses_uncovered_slab`.
- `diff_materializes_to_hash`; `diff_chain_bounded`.
- `profile_mismatch_894`; `comparison_start_not_a_continuation` (compile-fail).
- `widen_narrow_identity` (exhaustive over all 2³² single-precision bit patterns that are finite).
- `flipped_byte_detected`.
- `stream_counter_not_generator_state`: the snapshot holds the step counter only; draws after restore equal the
  parent's.

snapshot is replayed with `--tier batch-cpu --precision f64` (BD-204's options) first without and then with

tick, section list with byte sizes, profile identity, and the digests compared.

### Known answers and negative controls

- Metamorphic: splitting a rollout at a snapshot and resuming equals running it whole; checkpoint and restore
  at any instant, including just after a shutter opens, after a dropped packet and just before a controller
  update, reproduces every later delivered observation byte for byte (MR-16; mutation that must break it:
  packet queues left out of the checkpoint).
- MR-08 (fork and replay; mutation: a checkpoint with its packet queue stripped).
- Negative controls: the ten omissions; a snapshot that stores slot-relative indices (relocation fails); a
  diff applied to the wrong base (hash mismatch); warm starts left out (the first solve after restore differs).
- Determinism lanes: snapshot bytes twice on one machine, across worker counts, across platforms for
  `batch-cpu`; a device snapshot against the `batch-cpu` snapshot of the same world where the bitwise class is
  attained.

## Considerations

- Size: a full snapshot of the reference quadruped is about the per-world state, tens of kilobytes (about
  35 kB with warm starts and solver vectors); the integration state alone is about 135 floats for a 35-degree-
  of-freedom humanoid, so snapshots are dominated by contact rows and warm starts, not by pose.
- A snapshot holds privileged state and inherits the run's privacy class; it is never listed without the scope.
- Adding a section is a format minor version; an old reader refuses a snapshot with an unknown *required*
  section and ignores an unknown optional one.
- Learning state can be large; `learn.state` stores references to content-addressed weight objects rather than
  inlining them.
