## Background

Two runs can be compared bit for bit only when both are in an exact determinism class against each other: the
same backend and profile, or a pair of backends that has been shown to agree bitwise. Many useful comparisons
are not: a device against the CPU where bit equality was not attained, single precision against double
precision, a fast tier against the referee, a fork against its parent after the intervention. For these the
question "where do they part" means "where does their difference first exceed a tolerance", and it has to be
answered from what the record holds: full samples for a few traced worlds, and for every world only the
per-chunk minimum–maximum envelopes of declared channels.

The tolerance class of the first-divergence algorithm: for an interval of ticks, the stored envelopes give an
upper bound on the largest scaled difference and the stored samples give a lower bound. An upper bound at or
below tolerance certifies agreement on the interval; a lower bound above tolerance proves a mismatch inside it;
anything else is unresolved and is refined chronologically, earliest sub-interval first. Where samples are
missing, the answer is the earliest possible interval and a coverage gap, not a tick.

Three properties make this sound rather than merely plausible. *Agreement is certified only by an upper bound*:
an interval reported as agreeing has a true maximum scaled error of at most 1. *A mismatch is claimed only from
a lower bound*: two actual samples that differ by more than the tolerance. *Refinement is chronological*: an
unresolved early block is refined before any later block is examined, so a later proven mismatch can never be
reported while an earlier one might exist. This bead adds the tolerance class to the divergence search. Tier
Solid.

Rejected alternative: sampling a few ticks and reporting the first one over tolerance. Between samples the runs
may have parted and come back; the report would then name a tick later than the first divergence without
saying so.

## Scope

In: the scale table and where scales come from; the scaled difference; block bounds from envelopes and samples

## Technical approach

**1. Scale per class of variable.** `registries/divergence-scales.toml` (DESIGN): one row per variable class
with its unit and default scale, readable by any crate through `frob-core`:

| Class | Unit | Default scale (DESIGN proposal, frozen at M2 with the fidelity ledger) |
|---|---|---|
| position | m | 10⁻³ |
| angle (rotation-vector difference) | rad | 10⁻³ |
| linear velocity | m/s | 10⁻² |
| angular velocity | rad/s | 10⁻² |
| contact impulse | N·s | 10⁻³ |
| joint torque | N·m | 10⁻² × the actuator's rated torque |
| energy | J | 10⁻³ × the absolute work exchanged in the window |
| temperature | K | 0.1 |

A named scale profile replaces the defaults (`--scales <profile>`); when the fidelity ledger holds a frozen
envelope for a quantity in the run's stratum, that envelope is the scale and the report says so. The scaled
difference of a paired variable at a tick is δ = |a − b| / scale(class), with orientation differences taken as
the rotation-vector norm of a⁻¹·b and positions compared as differences of anchored positions (cell difference
times the cell side plus offset difference). The tolerance is δ ≤ 1.

**2. Block bounds.** A block is a range of ticks covered by one stored envelope row per run (at the coarsest
level a logical chunk). For a paired channel with quantum u and envelopes [min_A, max_A], [min_B, max_B] in
real units:
- upper bound: hi = (max(max_A − min_B, max_B − min_A, 0) + u) / scale, rounded up. The added quantum covers
  the half quantum of rounding on each side. For orientation channels the envelope is of the rotation vector
  relative to each run's first sample of the block (stored beside it, N29a-07): with u_t and v_t the two runs'
  relative rotation vectors, the per-component bounds c_i = max(max_A,i − min_B,i, max_B,i − min_A,i, 0) + u
  combine as √(Σ c_i²) ≥ ‖v_t − u_t‖, and the bound adds the distance of the two first samples:
  d(a_t, b_t) ≤ ‖v_t − u_t‖ + d(a₀, b₀). This holds because the rotation distance is bi-invariant (triangle
  inequality through a₀·exp(v_t)) and the exponential map of the rotation group does not increase distances
  (non-negative curvature); a test checks it on random pairs;
- lower bound: lo = max over ticks where both runs have a stored sample of δ, rounded down; 0 when no tick has
  samples in both.
The block's bounds are the maxima of hi and of lo over the paired channels. Floating-point evaluation rounds
outward: hi up, lo down.

**3. Block decision.**
- hi ≤ 1: the block **agrees**; go on to the next block.
- lo > 1: a mismatch lies inside; **descend**.
- otherwise: **unresolved**; refine this block before looking at any later block.

**4. Refinement, in chronological order.**
1. If both runs can be replayed for the block (identities and kernels present): replay both from the snapshot
   or state at the block's start with full per-tick capture for the paired channels, and scan ticks in order;
   the first tick with δ > 1 is t₁. If none, the block agrees after all.
2. If only finer stored envelopes or partial samples exist: split the block at the finer rows and apply the
   decision to the sub-blocks in order, earliest first.
3. If neither is possible, or a refinement budget is exhausted (default: 4 block replays per call; DESIGN):
   stop and return `unresolved` with the block's interval and its bounds. The verb then says what would resolve
   it (a replay with capture) in `next_actions`.

**5. Missing samples.** When a mismatch is proven or possible in a block where one run has a coverage gap, the
answer is the earliest possible interval [first tick of the earliest block not certified as agreeing, last
tick of the block in which a mismatch is first proven] together with the gap records inside it. No tick is
named. Example: samples absent for ticks 40 to 59 (ticks up to 39 certified as agreeing) and a true first
mismatch at tick 47 that persists: the first proven mismatch is at tick 60, so the answer is the interval
[40, 60] with the coverage gap [40, 59], not the first mismatch among retained samples (tick 60). Tick 60 belongs
to the interval because, had every missing tick agreed, it would be the first divergence; the record cannot
exclude that.

**6. Stage.** Once t₁ is known by replay, the tick is re-run on both sides with per-stage outputs and the first
stage whose scaled residual exceeds 1 is s₁. Across backends without bit equality both sides start the tick
from the *source* side's state at t₁ − 1, so that the comparison isolates one tick; when the two sides have
different numerical profiles that state enters the other side as a `ComparisonStart` (N29a-18), never as a
continuation.

**7. Decisions with margins.** The first decision divergence (from the exact bead) is annotated: a decision
whose margin (the distance of its deciding quantity from its boundary) is smaller than the scale of that
quantity is labelled `boundary-sensitive` on both runs.

**8. Result.** The report's `first_state_divergence.resolution` is `tick` (with t₁), `interval` (with [lo, hi]
ticks and `coverage_gaps`), or the report has `unresolved: { interval, bounds: [lo, hi], reason }` and no
divergence claim.

**9. Layout.** `crates/frob-chronicle/src/divergence/{scales.rs, bounds.rs, refine.rs, gaps.rs}`.

## Acceptance criteria

- [ ] PO-AUTOPSY-03 (in tolerance mode, an interval reported as agreeing has a true maximum scaled error of at
      most 1): on 10³ random pairs of traces with full ground truth, no block reported as agreeing has a true
      maximum above 1.
- [ ] A mismatch is reported only when two stored or replayed samples differ by more than the tolerance.
- [ ] Loose bound: a block with hi = 1.4 and lo = 0.6 returns `unresolved` when replay is disabled, and with
      replay enabled is refined before any later block and yields the right tick; a later block with lo > 1 is
      never reported first.
- [ ] Missing samples: the 40-to-59 case returns the interval [40, 60] and the gap [40, 59]; a tool that skips
      the gap and reports the first mismatch among retained samples (tick 60) is caught, and so is one that
      reports [40, 59] (it excludes a possible first divergence).
- [ ] Outward rounding: with bounds computed in single precision in a test build, hi is never below and lo
      never above their exact rational values.
- [ ] The scale table is readable from a crate of a lower layer, and the report names the scale profile and any
      fidelity-ledger envelope used.
- [ ] Orientation differences use the rotation-vector norm; a pair of quaternions q and −q (the same rotation)
      has δ = 0.
- [ ] A decision with a margin below scale is labelled `boundary-sensitive`.

## Test plan

### Unit tests

- `upper_bound_from_envelopes`: A in [0.100, 0.130] m, B in [0.128, 0.131] m, u = 10⁻⁴ m, scale 10⁻³ m:
  hi = (max(0.130 − 0.128, 0.131 − 0.100, 0) + 0.0001)/0.001 = 31.1.
- `certified_agreement`: A in [0.1000, 0.1004], B in [0.1001, 0.1005], same u and scale: hi = (0.0005 +
  0.0001)/0.001 = 0.6 → agrees.
- `lower_bound_from_samples`: one common tick with |a − b| = 0.0018 m → lo = 1.8 → descend.
- `three_way_decision_table`.
- `chronological_refinement_order`: blocks 0 (unresolved), 1 (lo > 1): the function replays block 0 first; with
  a true mismatch at a tick of block 0 it reports that tick, not block 1's.
- `unresolved_without_replay`.
- `missing_samples_interval_and_gap` (the 40-to-59 case: interval [40, 60], gap [40, 59]).
- `orientation_bound_sound`: on 10⁴ random pairs of orientation tracks, the hi computed from relative-rotation
  envelopes and first samples is never below the true maximum rotation distance.
- `outward_rounding_property` (10⁴ random envelopes, exact rationals as the reference).
- `quaternion_double_cover_zero`; `anchored_position_difference`: two positions in adjacent 8 m cells with
  offsets −3.9995 and +3.9995 differ by 0.001 m, not 7.999 m.
- `agreement_soundness_property` (PO-AUTOPSY-03).
- `stage_by_residual`: the first stage with residual above 1 is named; earlier stages with smaller residuals
  are not.
- `boundary_sensitive_label`: a success predicate x ≥ 1 m with endpoints 1.0000001 m and 0.9999999 m.

### Known answers and negative controls

- The gate's two tolerance cases (a loose bound returns `unresolved` and then the right interval after
  refinement; missing samples return an interval and a gap).
- Negative controls: a build that certifies agreement from samples only (a between-sample excursion is
  missed; the soundness property fails); a build that examines the block with the largest lo first (reports a
  later mismatch); a build that skips gaps; a componentwise quaternion difference (q against −q reports a
  mismatch of 2).
- The smallest state-versus-decision case: a state error of 2·10⁻⁷ m inside any envelope with different
  verdicts, and conversely two placements a metre apart that agree that the robot fell.
- Determinism: bounds and decisions are pure functions of the records, the scale table and the options.

## Considerations

- Envelopes are per logical chunk (256 control ticks by default), so the first pass is coarse; the tolerance
  search is cheap exactly when runs agree (every block certified) and pays for replay only where they do not.
- A scale that is too tight makes every block unresolved; a scale that is too loose certifies agreement that
  hides a decision difference, which is why the decision divergence is always reported beside the state result.
- The default scales are proposals of this bead; the numbers that matter in practice are the fidelity ledger's
  frozen envelopes, and the table is replaced by them stratum by stratum as they are frozen.
- For a fork against its parent the useful output is the order in which classes of variable leave tolerance
  and the first decision-level divergence, not the first tick, which is the intervention tick or later.
