## Background

The tier-correction estimator turns N fast-tier episodes and a few referee episodes at the same world addresses
into an estimate of the referee-level value. Each address i gets a prediction mᵢ of its referee outcome, an audit
probability pᵢ and an audit bit Aᵢ; referee episodes run only where Aᵢ = 1; and

```
Zᵢ = mᵢ + Aᵢ · (Y_ref,i − mᵢ) / pᵢ            θ̂ = (1/N) · Σᵢ Zᵢ
```

Its one essential property is that it is unbiased even when the fast tier (and so the prediction) is wrong:
E[Aᵢ/pᵢ] = 1 given everything fixed before the draw, so E[Zᵢ] = E[Y_ref,i]. A bad prediction inflates the variance
and cannot move the mean. That property is a statement about **order of events**: mᵢ and pᵢ must be fixed before
the draw, and the draw must not be a choice. If someone looks at the fast-tier results, decides to audit the
failures, and writes down probabilities afterwards, the same formula is biased (counterexample CX-324; the plan's
negative control "audit bits chosen after seeing fast-tier failures, without recorded probabilities").

The record subsystem (crate `frob-chronicle`) owns the ledger in which rounds are recorded, and therefore owns the
enforcement. Invariant INV-CHRON-13: **the audit set of a tier-correction round is fixed before any referee
outcome of the round exists, and every audit probability is at least the floor.** The floor is p_min = 1/20
(DESIGN), which bounds every weight 1/pᵢ by 20, so nothing is clipped and no clipping bias exists. (Likelihood-ratio
weights for tilted failure proposals are a different object, owned by the adversarial-search subsystem, where
clipped mass is reported.)

Design decision (DESIGN): the store, not the caller, guarantees the order. The audit assignment is an insert-once
record whose bits the store *recomputes* from the addressed random stream, and a referee outcome can be inserted
only under a committed assignment that audits its address. Rejected: trusting the estimator code to write things
in the right order (a later refactor, a retry or a second writer breaks it silently); storing only a hash of the
assignment (then a hand-picked audit set with a matching hash passes).

The same audited pairs feed the promotion label's exceedance bits and this estimator, and the audit draw is frozen
within a round, so the two cannot steer each other.

## Technical approach

**1. Round record (table `tier_round`, schema `frob.tier-round/1`).**

```
round_id   = BLAKE3("tier-round/1" ‖ promotion_id ‖ stratum_id ‖ round_index)
g          = { c, β, estimator_version, row_frontier }, g_hash = BLAKE3(canonical g)     the frozen prediction map
schedule   = the N world addresses in the round's fixed hashed order; schedule_hash
p          = per-address audit probabilities as exact rationals num/den; p_min; p_hash
audit_bits = bitset of N;   n_audited = popcount
state      = open → outcomes → closed;   commit_seq_open
```

**2. The addressed draw.** Aᵢ is not supplied by the caller. The store computes

```
uᵢ = Philox( key = run_seed, counter = (world address i, promotion_id), stream_id = "referee-audit" )  as u64
Aᵢ = 1  iff  uᵢ < ⌊pᵢ · 2⁶⁴⌋           (pᵢ = 1 gives Aᵢ = 1 for every address)
```

The stream identifier is its own, so the draw is independent of every draw the physics makes and of the choice of
traced worlds. Because the bits are a pure function of committed fields, replay needs no record of the choice and
a retry reproduces it.

**3. Opening a round (one ledger transaction).** Preconditions, each a refusal if false: (a) `g.row_frontier` is
not later than the current frontier and the row it names exists (the map comes from earlier rows only; a new
stratum uses c = 0, β = 1); (b) every pᵢ ≥ 1/20; (c) no referee outcome exists for any (stratum, address,
promotion_id) of the schedule; (d) if a round with this `round_id` exists, its g_hash, schedule_hash and p_hash
are identical, in which case the original receipt is returned and nothing is written (idempotent replay);
different content is a conflict (exit 7). The transaction writes the record with the recomputed bits and returns
them. This is the only way audit bits come to exist.

**4. Inserting a referee outcome.** Accepted only if a round in state `open` or `outcomes` exists for it with
Aᵢ = 1 at that address; otherwise refused. The pair row of N29b-07 is written in the same transaction with
`source = promotion` and the round identifier, and the round moves to `outcomes`. An outcome for an unaudited
address, or before the round is open, cannot be stored as part of a round; it can still enter the stratum's
moments as a plain battery pair, where it never carries a weight.

**5. Closing.** `closed` when every audited address has an outcome or a recorded refusal (the referee could not
complete it; counted, never silently dropped). A closed round is immutable.

**6. Read guard, FROB-REF-811** ("a tier-corrected estimate across identities, with no audited address, or below
the effective-sample floor"; ranked repair: referee episodes alone; exit 3, DESIGN from the exit table's rule for
`8xx` codes other than conflicts). `estimate_inputs(round)` returns (mᵢ, pᵢ, Aᵢ, Y_ref,i) only if:
- every pair of the round belongs to the round's stratum (no pooling across model, kernel or battery identities);
- n_audited ≥ 1 (with no audited address the estimate is refused; with every pᵢ = 1 it is the plain referee mean,
  exactly);
- the effective sample size ESS = (Σ wᵢ)² / Σ wᵢ², with wᵢ = 1/pᵢ over audited addresses, is at least 30% of
  n_audited.
The refusal names which trigger fired and its numbers. (The estimator's own switch-off rule also uses ESS and
ρ_ep; the guard is the store-side backstop that holds even if the caller forgets.)

**7. Exactness at full audit.** With every pᵢ = 1, Zᵢ must equal Y_ref,i exactly, and θ̂ the plain mean. In
floating point m + (Y − m) is not always Y (m = 10¹⁶, Y = 1 gives 0), so the store returns for pᵢ = 1 the flag
`exact_full_audit`, and the estimator takes Zᵢ = Y_ref,i on that branch. On quantized integer outcomes the store
can verify the equality itself: Σ y_ref_q / N as an exact rational.

**8. The derivation (filed for PO-CHRON-02).** `docs/proofs/chronicle/po-chron-02.md`: let F be everything fixed
before the draw (addresses, fast outcomes, g, p). Aᵢ ~ Bernoulli(pᵢ) given F, independent of Y_ref,i given F
because the audit stream is addressed and disjoint from the physics streams. Then E[Zᵢ | F] = mᵢ +
E[Aᵢ | F]·(E[Y_ref,i | F] − mᵢ)/pᵢ = E[Y_ref,i | F]. Variance: Var(Zᵢ | F) = Var(Y) + (1 − pᵢ)/pᵢ·E[(Y − mᵢ)²],
which for a constant audit fraction n/N, N ≫ n and the best linear prediction gives (1 − ρ_ep²)·Var(Y_ref)/n.

**9. Layout.** `crates/frob-chronicle/src/ledgers/tier_correction/{round.rs, guard.rs}`. Determinism: exact
(integers, rationals, bitsets). Evidence: a round is evidence of kind `ledger row`, class Tested.

## Acceptance criteria

- [ ] INV-CHRON-13 holds under every operation order tried by a property test: no sequence of store calls leaves a
      referee outcome attached to a round whose assignment was committed after it, and no stored pᵢ is below 1/20.
- [ ] The plant "audit bits chosen after seeing fast-tier failures, without recorded probabilities" cannot be
      written: supplying bits is impossible by the API, and opening a round after outcomes exist is refused.
- [ ] Audit bits recomputed on another machine from the round's committed fields are identical.
- [ ] Replaying `open` with identical content returns the original receipt; with one probability changed it is a
      conflict.
- [ ] FROB-REF-811 fires in its three cases with the numbers in the refusal: mixed identities; zero audited; ESS
      below 30% of the audited count.
- [ ] Store-level rows of GATE-CHRON-09: with every pᵢ = 1 on a stored round of 200 addresses the estimate read
      back equals the plain referee mean exactly; the after-the-fact audit plant is refused 100 of 100.
- [ ] The derivation of PO-CHRON-02 is on file and cited by the proof-obligation record (N29b-16).

## Test plan

### Unit tests (`crates/frob-chronicle/tests/tier_round.rs`)

- `bits_from_addressed_stream`: fixed seed, 1,000 addresses, p = 0.1 → the bitset equals the pinned vector;
  the count lies in [70, 132], the exact central 99.9% range of Binomial(1,000, 0.1).
- `p_one_audits_everything`; `p_below_floor_refused` (p = 0.01 → refused, message names 1/20).
- `open_after_outcome_refused`: insert a referee outcome for address 7, then try to open a round containing 7.
- `outcome_for_unaudited_address_refused`.
- `open_idempotent`; `open_conflict_on_changed_p` (exit 7).
- `enumeration_unbiased`: N = 4, Y_ref = (1, 1, 0, 0), m = 0.5, p = 0.5: over the 16 audit patterns the mean of θ̂
  is exactly 0.5 (rational arithmetic). Example patterns: A = (1, 0, 1, 0) gives Z = (1.5, 0.5, −0.5, 0.5), θ̂ = 0.5; A = (1, 1, 0, 0)
  gives 1.0; A = (0, 0, 1, 1) gives 0.
- `chosen_audit_is_biased` (the counterexample, as arithmetic): auditing exactly the two failures while claiming
  p = 0.5 gives Z = (0.5, 0.5, −0.5, −0.5), θ̂ = 0 against the truth 0.5.
- `prediction_off_by_constant_still_unbiased`: the same enumeration with m = 0.9 gives mean exactly 0.5 (the test
  enumerates in rational arithmetic, so "exactly" is literal).
- `ess_trigger`: weights 20, 20 and thirty of 1.25 → ESS = 7.09 < 0.3 × 32 = 9.6 → FROB-REF-811; thirty-two equal
  weights → ESS = 32, admitted.
- `full_audit_exact`: 200 addresses, p = 1, quantized outcomes → exact rational mean; flag `exact_full_audit`.
- Property `no_order_violates_inv13`: 10⁴ seeded random sequences of open, insert, replay and close calls.

### End-to-end script and logging

Steps `rounds-*` of `scripts/e2e/promotion.sh` (the promotion script of the dynamics unit): `frob eval promote
r:<run> --method dr --json` on a small stratum, then a second process that tries to register an audit set chosen
from the fast-tier failures through the only available path (opening a round after outcomes exist) and must be
refused. Logged per the shared helper: g_hash, p_min, N, n_audited, the round identifier and frontier, ESS against
the 30% threshold, the refusal block with code 811 where expected; on failure the first address whose audit bit
differs from the recomputed bit.

### Known answers and negative controls

- KA-719: with every address audited the estimate equals the plain mean exactly; with a prediction off by a
  constant it is still unbiased (inside the interval). Negative control: audit bits chosen after seeing fast-tier
  failures, without recorded probabilities.
- CX-324, with numbers added here: the four-address enumeration and the chosen-audit bias of −0.5.
- Metamorphic relation MR-33: the tier-corrected estimate has the same mean for every fast-tier prediction; with
  every address audited it is the plain mean. Control: audit bits chosen after the outcomes.
- Determinism lanes: bits identical twice on one machine, across platforms and after restart.

## Considerations

- KILL-DR: if the correction is killed, rounds are no longer opened; this bead's tables remain and the stratum
  moments keep recording (N29b-07).
- The budget rule of the estimator (256 referee episodes per promotion, DESIGN, after which the result stays
  `provisional`) is enforced by the estimator; the store records n_audited so that the budget is auditable.
- Sequential use: Zᵢ is bounded once the metric has a span, so a confidence sequence on θ̂ lets a promotion stop
  early against a declared indifference margin; stopping reads a *prefix* of the schedule in its fixed order, and
  the round record keeps the whole schedule so that the prefix is verifiable. For a design comparison the same
  construction is applied to the paired contrast, and both referee arms run only on audited addresses.
- The loss model of the promotion contract (wrong establishment 100, a referee episode 1, a wrong refusal 10;
  DESIGN constants) lives with the decision core; it does not enter the store.
- Calibration (interval coverage against full-referee values on the standard battery) is the gate's statistical
  row and is measured by the estimator's bead.
