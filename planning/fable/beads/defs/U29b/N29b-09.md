## Background

The record subsystem's artifact graph ties every claim to its evidence with four kinds of identifier:

```
ClaimId            BLAKE3( claim type ‖ subject identities ‖ statement ‖ scope )
EvidenceId         BLAKE3( kind ‖ payload hash )
DecisionPolicyId   ( dotted rule name, version )        e.g. ("atelier.dc01.promote", 3)
TraceId            128-bit, time-ordered identifier of the execution that produced an evidence item
```

Two of the four have a ready-made counterpart in a sibling library. FACT (read at
`/Users/jemanuel/projects/asupersync/franken_kernel/src/lib.rs`): the crate `franken_kernel` defines `TraceId` (a
`u128` serialized as hex, with a UUIDv7-style layout: the high 48 bits are a millisecond Unix timestamp, saturated
to 2⁴⁸ − 1, and the low 80 bits are random), `DecisionId` (a `u128`, hex) and `PolicyId { name, version: u32 }`
serialized by `serde` with the field names `n` and `v` and printed (`Display`) as `name@vN`, a dotted name such
as "scheduler.preempt". It has a text parser for `TraceId` and `DecisionId` and none for `PolicyId`. Its only
dependency is `serde`. It has no claim or evidence identifier. The suite convention this project adopts (DESIGN) is that
`frob-core` mirrors the text form of the identifiers the sibling has, adds `ClaimId` and `EvidenceId` in the same
form, and offers the two new types upstream (upstream work item FD-FKER-01, priority P3; interim posture: local
types with the same text form; switch-over: replace the local types).

A naming trap is already resolved and binds either outcome: the sibling's `PolicyId` names a *decision rule*,
while this project's `PolicyId` (the identity table of the foundations chapter) names a *control policy* by
content hash. The decision-rule identifier is therefore called `DecisionPolicyId` throughout this project,
whichever crate supplies the type.

The open question OPEN-CHRON-3: are the identifier types **imported from `franken_kernel`** under the suite's
single-version rule for asupersync, or **defined locally with the same layout**? Owner: suite lead. It blocks
GATE-CHRON-10 (the artifact graph's gate, first milestone), because `ClaimId`s and trace identifiers are written
into `registries/gates.toml`, bead logs and every envelope from the first recorded gate onward, and changing
their wire form later would orphan recorded evidence.

**Fail-closed default that holds until this bead is closed: defined locally in `frob-core`**, with a wire layout
identical to the sibling's, so that a later switch to the import changes no stored byte and no hash.

## Scope

bead extends and does not duplicate); the admission record of franken-kernel with the sibling's observed forms at

below reads); implementing the artifact graph and
`evidence.trace` (seed BD-095, built on the default and not waiting for this decision); the `ClaimId` and
`EvidenceId` preimages (this project's own in both options; N34-11, used by BD-095 and N29b-10); the gate row
of GATE-CHRON-10 (N29a-10, which waits for this decision).

## Technical approach

**1. Options.**

| | A: import from `franken_kernel` | B: define locally in `frob-core` (default) |
|---|---|---|
| Types affected | `TraceId`, `DecisionId` (mirrored for its text form by N34-11), and `DecisionPolicyId` as a newtype or alias of the sibling's `PolicyId`; `ClaimId` and `EvidenceId` too once FD-FKER-01 has landed upstream | All four local, and the `DecisionId` mirror; `ClaimId` and `EvidenceId` are local in both options until FD-FKER-01 lands |
| Benefit | One definition across the suite; traces from the runtime's own instrumentation and ours are the same type with no conversion | `frob-core` keeps a dependency table it fully controls; no coupling of the identity layer to a sibling's release train |
| Cost | `frob-core` (the bottom layer, on which the standard-library-only auditor and every crate depend) gains a sibling dependency; a sibling version bump can touch the identity layer; the name `PolicyId` must be re-exported under `DecisionPolicyId` and the sibling name hidden | Two definitions that can drift; a conversion at the boundary where the runtime hands us a trace identifier |
| Failure it risks | A second asupersync-family package version in a workspace, which the dependency check forbids (RISK-03: two asupersync versions in one build) | Silent layout drift between the two definitions |

**2. Criteria, fixed before the decision (evidence decides where evidence exists).** Option A is chosen only if
all four hold; otherwise B stands.
1. `franken_kernel` can be depended on from `frob-core` without bringing the asupersync runtime, or any crate
   other than `serde`, into `frob-core`'s dependency closure (`cargo tree -p frob-core` shows exactly one added
   package), and `check-layers` and `check-deps` pass.
2. The single-version rule holds with the import in place: the admission check that every workspace contains
   exactly one asupersync package (seed BD-008) is green, and `franken_kernel` resolves from the same pinned
   source as the rest of the stack lock.
3. The auditor crate (standard library only, its own stable toolchain file) does not need the types: it reads
   identifiers as strings from canonical JSON. If it would need the import, A fails.
4. The sibling's wire forms, as recorded at the pin in the franken-kernel admission record (N33c-27), are exactly
   the ones in item 3 below and are covered by the sibling's own tests, so a sibling release cannot change them
   unnoticed.

**3. The layout both options must satisfy (DESIGN, fixed now).**
- `TraceId`: `u128`; JSON form a 32-digit lowercase hexadecimal string; high 48 bits a millisecond timestamp, low
  80 bits random. It identifies an execution and **never enters a content hash**.
- `DecisionPolicyId`: `{ name: DottedName, version: u32 }`; text form `name@vN`, and the JSON form is that text
  as a string, for example `"atelier.dc01.promote@v3"`; dotted names are lower-case ASCII segments separated by
  `.`, for example `atelier.dc01.promote`. DESIGN, reconciled with N34-11: an earlier draft of this bead fixed
  the JSON form as the sibling's `serde` object `{"n": …, "v": …}`. The plan has `frob-core` mirror the
  sibling's *text* form; N34-11 allows one spelling per identifier; and stored bytes here are written by the
  canonical writer, not by `serde`, so the object form is never stored. Under option A the imported type is
  wrapped so that the canonical writer still prints `name@vN`; the sibling's `serde` derive is not used for any
  stored or hashed byte, which is what keeps a later switch from changing one.
- `ClaimId`, `EvidenceId`: 32-byte BLAKE3 digests; text form `clm:<64 lowercase hex digits>` and
  `ev:<64 lowercase hex digits>`. The plan prints a claim identifier two ways: `clm:…` in the gate registry's
  example row and `c:…` in the bead-log example. `c:` is already the prefix of a controller identity in
  envelopes, so one form holds in every place a claim is printed: `clm:` (DESIGN). These are the forms the
  identifier bead N34-11 implements in `frob_core::graph_id` at the foundation milestone (`clm:`, `ev:`, and
  `name@vN` as the one form of a decision policy, in text and in JSON), and the bead log (N29a-09) prints
  `clm:`. The parser of one kind rejects the text of another.
- Integers that can exceed 2⁵³ are strings in every JSON view (hex here).

**4. The compatibility test (makes the default reversible).** The test `kernel_layout_compat` is added to the
file in the conformance crate that already holds the text-form oracle `franken_kernel_text_forms_agree` which
N34-11 names (`crates/frob-conformance/tests/ids_oracle.rs`, the file of the admission bead N33c-27);
the conformance crate links `franken_kernel` at the stack lock's pin as an oracle. It asserts, for 10³ seeded
values: the JSON string of the local `TraceId` equals the sibling's serialization byte for byte;
`from_parts(ts, random)` agrees, including saturation at 2⁴⁸ − 1; the local `DecisionPolicyId` prints the same
bytes as the sibling's `PolicyId` displays for the same name and version; the JSON string of the local
`DecisionId` mirror equals the sibling's `DecisionId` serialization; ordering agrees for the three types.
DESIGN, reconciled with N34-11: an earlier draft placed this test in `frob-core` behind a feature that added
the sibling as a dev-dependency. Cargo has no optional dev-dependencies, and N34-11 requires that `frob-core`
have no `serde` in its dependency tree; in the conformance crate neither rule is strained, option B ships with
no sibling dependency in `frob-core`, and the test keeps option A open.

**5. Procedure.** (a) Run the four criteria on the pinned stack; record `cargo tree` output, the two checks'
results and the compatibility test's result. (b) The suite lead decides. (c) Write `docs/adr/ADR-CHRON-10.md`
(proposed identifier): the option, the measurements, and what would reopen it (a sibling layout change; the
identity layer needing more of the sibling's vocabulary). (d) Tombstone OPEN-CHRON-3 in the open-question register
with the decision record's identifier; a closed question is tombstoned, not reused. (e) If A: replace the local
definitions by re-exports in one commit, with the compatibility test promoted to a permanent wire-format test.

## Test plan

### Unit tests

The tests of the types themselves are N34-11's and are listed there with their values (`trace_id_layout` with
`from_parts(1_700_000_000_000, 0xABCD_EF01_2345_6789_AB)` and the saturation case 2⁴⁸ + 5 → 2⁴⁸ − 1;
`policy_json_is_text_form`, `("atelier.dc01.promote", 3)` → `"atelier.dc01.promote@v3"`;
`claim_and_evidence_text_forms`; `dotted_name_grammar`; the compile-fail test that a `TraceId` cannot be passed
to the content-hash builder, because the sealed trait for hash pre-images is not implemented for it). This
decision requires them green and adds, in the conformance crate:
- `kernel_layout_compat`: 10³ seeded values agree with the sibling byte for byte (item 4).
- `kernel_layout_compat_catches_swap`: with the timestamp planted in the low bits of the local type, the test
  above fails.
- `policy_id_name_lint`: the generated-artifact check fails on a scratch tree in which `PolicyId` is re-exported
  from the sibling under its own name.

### End-to-end script and logging

`scripts/e2e/chron_id_decision.sh` (owned here and built on this bead's dependencies only; header `bead=N29b-09
milestone=M1 seed=<s>`). It is the decision's measurement, step (a) of the procedure, and its log is what the
decision record attaches:
1. `criterion-1`: `cargo tree -p frob-core` on the workspace as it is (option B: no `serde`, no sibling crate)
   and on a scratch copy of the workspace in which `frob-core` imports `franken_kernel` at the stack lock's pin
   (option A: exactly one added package, no runtime crate); `cargo xtask check-layers` and `cargo xtask
   check-deps` on both.
2. `criterion-2`: `cargo xtask check-stack` on the scratch copy (one asupersync package per workspace, BD-008;
   `franken_kernel` resolved from the pinned source).
3. `criterion-3`: the auditor crate of the scratch copy keeps an empty dependency table and names no identifier
   type of the sibling (the shared-source scan of N34-25).
4. `criterion-4`: `FROB_TEST_SEED=<s> cargo test -p frob-conformance --test ids_oracle --features
   gauntlet-mutations -- franken_kernel_text_forms_agree kernel_layout_compat` (the planted swap of
   `kernel_layout_compat_catches_swap` must be caught), the forms compared with those of N33c-27's admission
   record.
5. `lint`: `policy_id_name_lint` on its scratch tree.

NDJSON lines per the shared logging helper (command, exit code, wall time): per criterion its outcome and the
measured value (packages added against 1; asupersync packages against 1; agreeing values of 10³; the plant
caught), the option the four criteria allow and the layout version; on failure the first differing byte string
of the two serializations, or the package that entered the closure; a final `summary`. The script writes no
decision record: a decision has no runtime behaviour of its own, and the record is the suite lead's.

The check of the four identifier forms on a recorded envelope, a gate row and a bead-log line needs the first
recorded gate, which is N29a-10's (it depends on this bead): it is that bead's step `ids-wire` of
`scripts/e2e/evidence_trace.sh` (regular expressions for the four forms; the identifier class, its form and the
layout version logged), requested there.

### Known answers and negative controls

- The doc-example value of the sibling type (`1_700_000_000_000`, `0xABCD_EF01_2345_6789_AB`) as the pinned known
  answer for the layout.
- Negative controls: the planted layout swap; a build in which `PolicyId` is re-exported under its sibling name
  (the lint must fail); a build in which a trace identifier is mixed into an `EvidenceId` preimage (the
  compile-fail test, and INV-CHRON-10: no trace identifier or wall-clock time enters a content hash).

## Considerations

- Why the default is B: the identity layer is the one place where an unplanned dependency change is most
  expensive, and the benefit of A is convenience at one boundary. The compatibility test costs little and removes
  the main argument against B (drift).
- Interim posture and switch-over rule: local types now; switch only by the procedure above; never both in one
  build.
- This decision blocks the first recorded gate, so it is one step more urgent than its milestone. The artifact
  graph bead proceeds on the default without waiting; what it must not do is record a gate with any other layout.
- `DecisionId` of the sibling (a `u128` per decision instance) is not one of the artifact graph's four
  identifiers, and the four-identifier decision stands: decisions of a decision core are ledger rows keyed by
  content. N34-11 mirrors its text form all the same (32 lower-case hexadecimal digits), because §34.12 says to
  mirror the three identifiers `franken_kernel` has, as an execution identifier like `TraceId`: it never enters a
  content hash and is no graph node, and a decision row may carry it beside its trace. The decision here covers it
  as it covers `TraceId` (option A would re-export it; option B keeps N34-11's local mirror), and the compatibility
  test checks its JSON string against the sibling's as well. A wish for per-decision instance identifiers *as
  graph nodes* reopens this record rather than adding a fifth node type ad hoc.
