## Background

Decision ADR-CHRON-07 of the record subsystem (crate `frob-chronicle`): **no claim without a trace.** Every claim
that crosses the agent boundary has a `claim_id` that resolves to evidence, to the version of the rule that
decided it and to the executions that produced it. A claim that does not resolve is not printed. Reason: an agent
that receives a number will quote it; if the number cannot be traced, nobody can later tell a measured result from
a remembered one, and retention or a lost store turns yesterday's evidence into today's folklore.

The artifact graph that makes this checkable has four identifier kinds and five edge kinds:

```
ClaimId            BLAKE3( claim type ‖ subject identities ‖ statement ‖ scope )
EvidenceId         BLAKE3( kind ‖ payload hash )
                   kinds: episode set · chunk range · snapshot · certificate · receipt · ledger row · analysis result
DecisionPolicyId   ( dotted rule name, version )        e.g. ("atelier.dc01.promote", 3)
TraceId            128-bit, time-ordered identifier of the execution that produced an evidence item

edges   claim ──supported-by──► evidence          claim ──decided-by──► decision policy
        evidence ──produced-by──► trace            evidence ──derived-from──► evidence
        claim ──depends-on──► claim               (the weakest input bounds the claim)
```

Seed bead BD-095 builds the graph: the identifiers, recording, the closure algorithm, the resolution rule (a
claim resolves when its closure has no dangling and no tombstoned node; one that does not prints `evidence:
unavailable` and cannot be cited, FROB-REF-869), the build-time check of the gate registry, and the verb
`evidence.trace`. Its gate is measured by bead N29a-10.

A rule that lives in one crate is only as strong as the number of callers that remember to use it. This bead is
the sub-task that makes the rule hold *everywhere a claim is printed or cited*: one hook that every envelope
passes through, a test that enumerates the verb registry so that a new verb cannot bypass it, a defined
behaviour for each state a claim can be in, a read-time check that a stored claim is no stronger than its
inputs, and a re-affirmation pass that withdraws a recorded PASS when its evidence later becomes unavailable.

Rejected alternatives: checking resolvability only inside `evidence.trace` (the unresolvable claim is printed
and quoted before anyone traces it); printing the claim with a warning (warnings are not read by the next tool);
silently omitting the number (the reader cannot tell missing from zero).

## Scope

In: the envelope hook in the verb layer; the output states; the list of operations that count as citing; the
read-time class check; the unscoped-caller case; memoization; the registry-driven surface test on both surfaces;
the re-affirmation pass for gate rows and bead logs.

Out: the graph, the closure function, the build-time registry check and `evidence.trace` (BD-095); the gate
measurement (bead N29a-10); the bead log and its closing-rule evaluator (bead N29a-09); the gate recorder and
status views (beads N38b-19 and N38b-20 of unit U38b); tombstones and collection (BD-209); report generation
(BD-302), which calls this guard.

## Technical approach

**1. The check (a thin wrapper over BD-095's `closure`).**

```rust
pub enum ClaimState {
    Resolved    { closure_digest: Blake3, product: ClaimProduct, frontier: CommitSeq, epoch: u64 },
    Unavailable { missing: Vec<MissingNode> },      // node id, kind, and why
    Withdrawn   { reason: String },
}
pub enum Why { Dangling, Tombstoned { class, time, reason }, ClassRaised, PrivateNoScope }
pub fn state_of(claim: ClaimId, at: CommitSeq, caller: &Scopes) -> ClaimState;
pub fn cite(claim: ClaimId, caller: &Scopes) -> Result<Citation, Refusal>;   // Ok only on Resolved
```

`closure_digest` is BLAKE3 over the closure's sorted node identifiers and content hashes, never over trace
identifiers or times, so two executions of the same work have the same digest. `epoch` is the store's tombstone
epoch (it increments at every collection cycle and every withdrawal).

**2. The envelope hook.** The verb layer builds every envelope through one function. For each claim the result
may be cited for, the hook calls `state_of` at the frontier the result was computed at and writes one of:

| State | Envelope content | May be cited | Exit |
|---|---|---|---|
| resolved | `claim_id` in `evidence.claims`, `closure_digest`, the claim product, `frontier`, `epoch` | Yes | 0 or 2 as the verb decides |
| unavailable | `claim_id`, `evidence: "unavailable"`, `missing: [{node, kind, why}]`; removed from `evidence.claims` | No | 2 (completed with a finding) |
| withdrawn | `claim_id`, `evidence: "withdrawn"`, the reason | No | 2 |
| not a claim | No `claim_id`: the number is a view (a summary, a progress count) and prints its denominator and frontier | No | as the verb decides |

A number that supports a claim carries the `claim_id` in summaries too, so a drill-down handle and an evidence
trace are the same thing.

**3. What counts as citing.** Each of these calls `cite` and is refused with FROB-REF-869 (exit 3; `retry:
after-change`; repairs: 1. re-run the evidence, with the recorded command of the missing node's producing run;
2. withdraw or restate the claim) unless the state is `Resolved`: writing a gate row with `status = "pass"`;
appending a bead-log line with `verdict = pass`; issuing a verdict or a promotion whose claim depends on it;
building a report statement; composing the inputs of a certificate bundle; listing it in a demonstration file
at release time.

**4. Read-time class check.** BD-095 refuses to *record* a claim whose evidence class exceeds the weakest class in
its support and dependencies. The guard repeats the derivation at *read* time from the closure: class, tier and
determinism are the weakest among the evidence items and the depended-on claims; conditions are the union. A
stored product stronger than the recomputed one (a row altered after recording, an import from another store, a
defect in a writer) makes the claim `Unavailable` with `why: ClassRaised`, and the event is written to the
store's level-T1 log. No public function raises a class.

**5. Callers without scope.** If a closure contains a node the caller may not read (a private scene's chunk), the
caller sees the claim as `Unavailable` with `why: PrivateNoScope` and the node as `{id, kind, private: true}`;
the owning session sees it resolved. Resolution never returns content, only node kinds.

**6. Cost.** `state_of` is memoized by (claim, epoch, scope class); closures of ordinary results are tens of
nodes; a campaign-level claim references an episode-set evidence item with its own digest instead of enumerating
episodes. The guard adds no device work.

**7. Re-affirmation.** A recorded PASS can become untraceable later (a claim withdrawn, evidence purged, a store
lost). `reaffirm(registry, logs)` is a recorder command that, for every gate row with `status = "pass"` and every
closed bead's closing line, calls `state_of` on its claim identifiers against the live store. A row whose claim is
no longer `Resolved` is rewritten to `status = "not-run"` with `cause = "evidence-unavailable"` and the missing
nodes, and a bead-log line of verdict `fail` with the same cause is appended; nothing is deleted. It runs before
every milestone exit review and every release, and its output (rows checked, rows demoted) is part of the exit
record. Because closures of live claims are pinned (N29b-13), a demotion is always the visible consequence of an
explicit withdrawal or purge, never of routine collection.

**8. Layout.** `crates/frob-chronicle/src/graph/{state.rs, cite.rs}`; the hook in
`crates/frob-verbs/src/envelope.rs`; `reaffirm` in `crates/frob-conformance/src/recorder/reaffirm.rs`.
Determinism: exact. Evidence: the guard creates none; it reports on it.

## Acceptance criteria

- [ ] Every verb in the registry whose output schema has a claim field builds its envelope through the hook: a
      registry-driven test enumerates them and fails for a planted verb that serializes a claim directly.
- [ ] A claim whose evidence chunk was tombstoned prints `evidence: unavailable` with the tombstone's reason, is
      absent from `evidence.claims`, and each of the six citing operations refuses it with FROB-REF-869.
- [ ] A dangling evidence identifier behaves the same way with `why: Dangling`; a withdrawn claim prints
      `withdrawn`.
- [ ] A stored claim product stronger than its closure allows is reported `ClassRaised` and the claim is
      unavailable.
- [ ] The CLI and the MCP surface return the same state and the same `closure_digest` for the same claim.
- [ ] `reaffirm` demotes a planted PASS row whose claim was withdrawn, appends the bead-log line, and leaves every
      other row untouched; run on a clean tree it changes nothing.
- [ ] After the evidence is regenerated by the first repair, the claim resolves again with the same
      `closure_digest`.

## Test plan

### Unit tests (`crates/frob-chronicle/tests/citation_guard.rs`)

- `three_states`: resolved, unavailable (dangling; tombstoned with reason "store budget", class "sampled
  traces"), withdrawn.
- `depends_on_propagates`: claim A depends on claim B whose evidence is tombstoned → A unavailable, naming B's
  node.
- `class_raised_detected`: inputs of class Certified and Estimated → product Estimated; a stored Tested is
  `ClassRaised`.
- `conditions_union_along_edges`.
- `cite_refuses_869`: refusal block has the code, the missing nodes, the repairs in order, exit 3.
- `unavailable_exits_2`.
- `private_no_scope_hides_content`.
- `memo_invalidated_by_epoch`: a state cached before a withdrawal is recomputed after it.
- `every_claim_verb_uses_hook` (registry-driven; includes the planted bypass).
- `reaffirm_demotes_only_unavailable`: 5 PASS rows, 1 with a withdrawn claim → 1 demoted, 4 unchanged.
- Property: for random graphs of up to 200 nodes with random tombstones, `state_of` agrees with a brute-force
  reachability oracle.

### End-to-end script and logging

Step groups `surface-*` and `reaffirm-*` added to `scripts/e2e/evidence_trace.sh` (the script of bead N29a-10
for the artifact graph's gate). `surface-*`: for every first-milestone verb with a claim field, run it on its
smallest fixture through `frob --json` and through `frob-mcp`, trace the returned `claim_id`, tombstone one
evidence object in a scratch copy of the store through the conformance helper, and re-read: the verb must print
`unavailable`, and `frob report run … --cite <claim_id>` (or the recorder path where the report verbs do not
exist yet) must refuse with 869. `reaffirm-*`: record a fixture gate, withdraw its claim, run the recorder's
re-affirmation, and check the registry row and the bead log. NDJSON lines per the shared logging helper:
command, exit code, wall time, the envelope's evidence block, `claim_id`, state, `closure_digest` on both
surfaces, the refusal block, rows checked and rows demoted; on failure the first verb or row whose state differs
from expectation.

### Known answers and negative controls

- KA-720: every gate row resolves to evidence and traces. Negative control named by the plan: a claim printed
  after its evidence was collected.
- Negative controls: a verb that bypasses the hook; a class raised by relabelling a stored row; a cached
  `resolved` served after a withdrawal; a re-affirmation that deletes instead of demoting.
- Determinism lanes: closure digests identical twice on one machine, across platforms, and across a store export
  and import.

## Considerations

- This bead overlaps BD-095 by design: that bead owns the rule and the graph; this one owns its enforcement on
  the surfaces and over time. If the two are merged, items 2 to 7 go into BD-095's technical approach.
- RISK-39 (retention deletes the interval that explains a decision): its early warnings are exactly this guard's
  outputs, a refused citation of a collected object and a closure that does not resolve.
- Consumers that cached an envelope keep a stale `resolved`; envelopes therefore carry the frontier and the epoch
  they were resolved at, and a citation always re-checks.
- The identifier text forms are those fixed by the identifier decision (N29b-09).
- Reports and the dashboard print nothing they cannot resolve: they call `cite` for statements and the hook for
  views.
- Premortem story 8 of the risk chapter ("the swarm closed beads that proved plumbing"; earliest signals: shared
  close reasons, a gate without a caught negative control, a PASS recorded by the session that implemented the
  capability) is countered by the verification unit's close audit and recorder; Chronicle's part is that a
  closing line or a PASS row whose claim does not resolve cannot be written, and is demoted if it stops
  resolving.
