## Background

A scene pack built from a scan of a real home or workplace is marked `private`. It is stored under a configured
private root outside the repository; stills, replays, reports and fixtures derived from it inherit the mark and
are not exported without an explicit flag. Inheritance is computed, not declared: the mark of an artifact is the
join of the marks of everything in its lineage (decision ADR-SAFE-03), so a still of a replay of a policy
evaluated in a private scene is private without anyone marking it.

The record subsystem (crate `frob-chronicle`) stores more scene-derived data than any other part of the system:
contact traces carry feature pairs and positions in the scene, snapshots carry the state of movable objects,
kinematic traces draw the robot's path through someone's kitchen. The retention chapter states the rule in one
sentence: **telemetry derived from a private scene inherits the scene's privacy class through retention and
export.** This bead makes that sentence true for every object Chronicle writes and every way such an object
leaves the store, including the ways that are easy to forget: a tombstone, a status listing, a log line, a
summary.

Risk RISK-12 (a scan of a private place leaks through a still, a fixture or policy weights; early warning: a
derived artifact without the private mark; owner: Chronicle lead) is the reason this is a bead and not a
sentence in a contract.

Rejected alternatives: marking runs by hand (the first forgotten flag is a leak); encrypting private chunks in
place (key management for no gain on a single-user machine; the private root and scopes already separate them);
dropping telemetry for private scenes (it would make private places undebuggable, which defeats ingesting them).

## Scope

In: the privacy class on every stored Chronicle object; where private objects are written; the read and export
checks on Chronicle's verbs; what views, summaries, tombstones, status listings and logs may show; purge of a
private scene against pinned evidence; tests with a planted leak path.

Out: the mark's definition, the scopes, the path jail and `scene.purge` itself (BD-305, BD-258); weights trained
in a private scene (the learning subsystem; the open question on whether weights inherit is the safety
chapter's); the replay packet writer (bead N24a-41).

## Technical approach

**1. Class on every object.** Each chunk, snapshot, column file, ledger row that embeds scene-derived content,
evidence node and tombstone carries `privacy: public | private(scene_pack_id…)`. For an object written by a run,
the class is the join over the run's inputs (scene pack, and any private artifact in its lineage). The join is
computed when the run is admitted and stored in the run manifest, so every publisher writes the same value; the
publishing transaction refuses a chunk whose declared class is weaker than its run's.

**2. Placement.** Column files of private class are written under the private root
(`<private root>/chronicle/<namespace>/…`), never under the project store. The ledger row of a private chunk
lives in the same ledger (rows are metadata) but its payload path resolves beneath the private root through the
session's retained directory handle, the path jail of the safety chapter.

**3. Reads.** Verbs that return payloads or scene-derived rows (`telemetry.query`, `telemetry.energy` detail
rows that name contact features, `telemetry.failures` drill-down, `sim.replay`, `artifact.read`,
`evidence.trace` payload fetches) require the scope `private:read` when the object is private. Without it: the
object is *absent* from listings and a direct request is refused (`FROB-REF-720`, the session token lacks a
required scope; exit 5). In `evidence.trace`, a private node appears in the closure as `{ id, kind, private: true
}` with no content; the claim is reported unavailable to that caller with `why: private-no-scope` (N29b-10), so
resolution never leaks content.

**4. Exports.** `run.export` (the `.frun` format), `artifact.export` and `telemetry.export-html` require the scope
`private:export` *and* the explicit export flag when any exported object is private; otherwise they are refused
(`FROB-REF-731`). An admitted private export writes the mark into the artifact (the `.frun` manifest's privacy
field; the replay packet's header) so that the mark survives outside the store. Destination paths resolve under
the export root (`FROB-REF-734` otherwise).

**5. Aggregates and views (DESIGN rule).** A number that is a function of many worlds and reveals no scene
geometry (a success rate, an energy total, a flag count) keeps the class of its inputs for *export*, and may be
shown to the owning session without `private:read`, because the session that ran the job already holds its
results. A view that embeds scene-derived detail (a contact feature pair, a position, a still, a path) needs
`private:read`. Token-budgeted summaries list private drill-down handles only for callers with the scope.

**6. Retention.** Private objects obey the same classes, pins, windows and budgets as public ones, counted
against the same budget but listed in a separate line of `frob store status` that callers without
`private:read` see only as a byte total. A tombstone of a private object keeps: content hash, class, time,
reason, and `privacy: private`; it does not keep the scene pack's name for callers without the scope. Catalogs,
the shared archive, the leaderboard and MCP resource lists omit private objects.

**7. Purge against pins (resolution of two rules that meet).** `scene.purge` removes a private scene pack and the
lineage closure of everything derived from it and writes a receipt listing the removed digests. The pin rule
forbids deleting a pinned object (`FROB-REF-813`; repair: withdraw the claim first). DESIGN, fail closed toward
both: purge first lists the live claims whose closures it would break; with `--withdraw-claims` (and the
`private:export`-independent admin scope) it withdraws them in the same operation, each withdrawal recorded with
reason `purge`, then deletes with tombstones of reason `purge`; without the flag it is refused with 813 and the
list. A purge never leaves a claim that still prints as resolved.

**8. Logs.** End-to-end logs, bead logs and gate rows never contain private-scene data: they carry identifiers,
counts and metrics only. The shared logging helper refuses to write a field whose source object is private; a
script that runs on a private scene logs handles, not values.

**9. Layout.** `crates/frob-chronicle/src/privacy.rs` (class, join, checks) with calls from the publisher, the
readers and the exporters. Determinism: exact. Evidence: none created.

## Acceptance criteria

- [ ] Every object written by a run on a private scene carries `private(scene_pack_id)`, and its payload file is
      under the private root; a publisher that declares a weaker class is refused.
- [ ] Without `private:read`: private chunks, snapshots and detail rows are absent from every listing; direct
      reads are refused with FROB-REF-720; `evidence.trace` shows private nodes without content.
- [ ] `run.export`, `artifact.export` and `telemetry.export-html` on a private run are refused with FROB-REF-731
      without scope and flag, and with them write an artifact that carries the mark.
- [ ] Derived objects inherit: a replay of a private run, a still of that replay, an analysis result over its
      telemetry and a fork of it are all private without any explicit marking (the join test).
- [ ] A tombstone of a private object shown to a caller without the scope reveals no scene name or path.
- [ ] `scene.purge` on a scene with a live claim is refused with 813 listing the claims; with
      `--withdraw-claims` it removes the closure, leaves tombstones of reason `purge`, and the claims print
      `evidence: unavailable`.
- [ ] A planted leak path (a summary that prints a contact position from a private run to an unscoped caller) is
      caught by the audit test.
- [ ] No private value appears in any end-to-end log of the private fixture run (a scan of the log for known
      private strings and coordinates finds none).

## Test plan

### Unit tests

- `class_join`: public ⊔ private(a) = private(a); private(a) ⊔ private(b) = private(a, b); join is commutative,
  associative and idempotent (property test).
- `publisher_refuses_weaker_class`.
- `listing_omits_private_without_scope`; `direct_read_refused_720`.
- `export_refused_731_without_flag`; `export_writes_mark`.
- `trace_closure_hides_private_payloads`.
- `aggregate_visible_detail_hidden`: success rate shown; contact feature rows refused.
- `tombstone_redaction`.
- `purge_refused_on_pinned_813`; `purge_withdraws_and_tombstones`.
- `log_helper_refuses_private_field`.

### End-to-end script and logging

`scripts/e2e/chronicle_privacy.sh`: on a *synthetic* private scene pack (a generated room marked private, labelled
`synthetic`, containing a recognizable marker string and marker coordinates), run a referee job; exercise
listings, reads, exports, trace, status and purge with and without scopes. Asserts the criteria above. NDJSON
lines per the shared helper: command, exit code, wall time, scopes of the session, refusal blocks, counts of
objects by class as seen by each caller; the script ends with a scan of its own log for the marker string and
coordinates and fails if any is found. A `summary` line with assertions passed and failed.

### Known answers and negative controls

- The join laws (exact). The redaction scan (zero hits).
- Negative controls: an export path that forgets the check (planted in the replay-packet path); a listing that
  filters by name instead of by class (a renamed private chunk appears); a purge that deletes pinned evidence
  silently; a log line with a private coordinate.
- Relation to the safety chapter's gate on private places (GATE-SAFE-04): this bead supplies Chronicle's rows of
  that gate; the gate is measured by the safety unit's bead.

## Considerations

- The line between an aggregate and a detail (item 5) is a DESIGN judgement; the fail-closed reading is that
  anything with a position, a feature identifier or a pixel is a detail.
- A caller who holds a private chunk's content hash learns nothing from it; hashes are not secrets, payloads are.
- Seeds, recipes, design and module differences, receipts and policy weights are what crosses between machines;
  a private scan stays on the machine that holds it, and a job that needs it runs there. Chronicle's stores on the
  two machines are therefore never merged across the private boundary.
- Open question of the safety chapter (whether policy weights trained in a private scene inherit the mark;
  default: they inherit) does not change this bead; telemetry always inherits.
- Revisit when real-place ingestion lands (fifth milestone): the synthetic private fixture is then joined by a
  real one that never leaves its machine, and the redaction scan uses that machine's own marker list.
