## Background

Reality ("the simulation agrees with physical measurement") is one of the project's seven claim kinds, and the one
the first release mostly cannot make. Ground (crate `frob-ground`) keeps a lane for it so that the first admitted
dataset has somewhere to land; until then every report prints `reality: no-claim`. Four reasons make `no-claim`
the normal state, stated here so that no later work argues around them:

1. **No data exists.** Nothing in the project has been compared with a physical robot (FACT). A measurement that
   has not been taken cannot be replaced by a larger batch of simulations.
2. **Agreement between tiers cannot reveal a wrong card.** Every simulation tier consumes the same actuator card,
   so tier-agreement (Fidelity) and oracle-agreement (Parity) results say nothing about whether the card
   describes a real motor.
3. **A Reality result has a scope and no meaning outside it.** The scope is a *cell*: which physical units, which
   controller and firmware, which surface, which task family, inside which envelope of conditions.
4. **A design that was never built has no reality band.** Band coverage is a statement about draws exchangeable
   with the calibration draws; an unbuilt design is not such a draw, and the distance between it and the
   calibrated ones cannot be measured.

Rejected alternatives: a boolean "validated" flag (it has no scope and cannot expire); a numeric "sim-to-real
score" (it invites reading a simulated number as measured); leaving the field out when nothing is known (absence
is then indistinguishable from omission, so the default must be printed).

## Scope

In: the status type with its payloads; the transition function and its ledger event; the combination rule for a
statement that rests on several results; the grammar, printer and parser of the line. Out: printing the line on
every report surface and the negative battery of 50 planted misuses (BD-139); the published-anchor comparison
itself (BD-311); the cell key (N30a-07); bands and retirement mechanics (N30a-36 to N30a-43).
The guard that checks a status against the record tables, and the tables themselves, are BD-139's (modules
`reality` and `records`); BD-139 is the capstone and depends on this bead.

## Technical approach

**1. The statuses.**

| Status | Meaning | Rule |
|---|---|---|
| `no-claim` | Nothing measured supports the number. | The default. A legitimate terminal state, not a failure. |
| `synthetic` | The comparison ran against data generated by a simulator standing in for reality. | Never promoted (INV-GROUND-06). |
| `published-anchor` | A simulated quantity was compared with a figure published for the same robot. | A Parity result, never Reality: published test conditions are loose. |
| `candidate(cell)` | A posterior was fitted in this cell and has not been scored on sealed data. | Changes no randomization width. |
| `calibrated(cell, n, level)` | A frozen prediction was scored on sealed data and a band is issued. | Valid only inside the cell. |
| `retired(cell, reason)` | A drift monitor fired, the scope changed, or the calibration expired. | Reverts to `no-claim` with the reason. |

**2. Types** (DESIGN). The data type lives in `frob-core`, so that every envelope and report can carry it without
depending on a layer-5 crate; the transition logic lives in `frob-ground`.

```rust
// frob-core
pub enum RealityStatus {
    NoClaim { reason: Option<NoClaimReason> },                 // reason set after a retirement or a refused band
    Synthetic { dataset: DatasetPrefix },
    PublishedAnchor { source: AnchorKey },
    Candidate { cell: CellId, dataset: DatasetPrefix },          // the dataset the posterior was fitted on
    Calibrated { cell: CellId, n: u32, level: Level, band: QtyWithUnit, dataset: DatasetPrefix },
    Retired { cell: CellId, reason: RetireReason },
}
pub enum RetireReason { ScopeChange(ScopeComponent), RankDrift, MissDrift, Expired, Manual }
```

`Calibrated` and `Candidate` have no public constructor in `frob-core`: they are built by `frob-ground` from a
ledger event, and a reader that deserializes one checks that the event it names exists (BD-139 tests this path).

**3. Transitions** (`frob_ground::status::advance(state, event) -> Result<RealityStatus, Refusal>`), per key
(cell, metric, model lineage). Every accepted transition appends a ledger event `ground.status` with the old
state, the new state, the cause artifact and the ledger sequence.

| From | Event | To |
|---|---|---|
| `no-claim` | A candidate posterior written in the cell by identification on data of origin `real` | `candidate(cell)` |
| `no-claim` | A comparison, posterior, score or band computed on data of origin `synthetic` only (the rehearsal, a stand-in simulator) | `synthetic` (with that dataset) |
| `no-claim` | A Parity comparison with a published figure (BD-311) | unchanged: the citing statement is labelled `published-anchor(source)`; the key's state stays `no-claim` |
| `candidate` | A frozen prediction scored on sealed data covered, and a band was issued | `calibrated(cell, n, level)` |
| `candidate` | The posterior was rejected at validation | `no-claim` (reason: rejected) |
| `calibrated` | Scope change, rank drift, miss drift, expiry, or a capability-guarded manual retirement | `retired(cell, reason)` |
| `retired` | Read by a report | printed as `no-claim` with the retirement reason |
| `retired` | Calibration restarts inside the new regime | `candidate(cell′)` for the new cell or epoch |
| any real-data state | An input of origin `synthetic` enters the comparison | refused (`FROB-REF-814`: pooling of synthetic with real data) |
| `synthetic` | any | `synthetic` (no event leads out of it) |

No transition leads from `no-claim` or `candidate` directly to `calibrated` without a score event, and none
leads from `synthetic` or `published-anchor` to any cell state. `published-anchor` is not a cell state at all: it
labels one Parity comparison.

**4. Combination.** A statement that rests on several results takes `combine` over its parts (DESIGN: the
weakest input wins, as in the claim product; settled with BD-139, whose guard calls this function):
(i) if any part is `synthetic` the result is `synthetic`: the label is sticky and can be neither dropped nor
raised, which is INV-GROUND-06 read literally (data of origin `synthetic` never yields a status other than
`synthetic`); (ii) otherwise, if all parts are equal and, for a cell status, name the same cell, band record
(hence the same n, level and dataset) and model identity, the result is that status; (iii) otherwise
`no-claim`, and a `retired` part adds its retirement reason to the result's `warnings`. No combination of
inputs yields `calibrated` from parts that are not all `calibrated` in one cell. In the order `synthetic`,
then `no-claim`, then every other status, `combine` never returns a status above any of its inputs.

**5. The line.** One line per report statement:
`reality: <status> [cell=<id> n=<n> level=<1−α> band=<q̂ with unit> dataset=<hash prefix>]`. Grammar: the
literal `reality: `, one of the six status words, then an optional bracketed list of space-separated
`key=value` fields in this fixed order: `cell`, `n`, `level`, `band`, `dataset`, `source`, `reason`. Fields per
status: `no-claim` none, or `reason` (and `cell`) after a retirement; `synthetic` `dataset`; `published-anchor`
`source`; `candidate` `cell dataset` (DESIGN: a candidate rests on the dataset it was fitted on, and naming it
lets a reader find the calibration record; BD-139 prints the same pair); `calibrated` all of `cell n level band
dataset`; `retired` `cell reason`. `level`
prints as a decimal (`0.90`); `band` as a number with its unit and no space (`0.12s`); hash prefixes are 12 hex
digits. The printer is the only writer; the parser accepts exactly what the printer emits and rejects a
`calibrated` line with a missing field. The envelope's `evidence.reality` holds the same text after `reality: `.

## Acceptance criteria

- [ ] `RealityStatus::default()` is `NoClaim { reason: None }` and prints `reality: no-claim` (INV-GROUND-01,
      unit level).
- [ ] The transition table is total: every (state, event) pair either yields the listed state or a typed refusal;
      no path reaches `calibrated` without a score event; no path leaves `synthetic` (INV-GROUND-06); work done
      on synthetic data only enters `synthetic`, never `candidate`.
- [ ] Printing then parsing is the identity on 10⁴ generated statuses; the parser rejects each of 12 malformed
      lines (missing `n`, unknown status word, fields out of order, `band` without a unit, and so on).
- [ ] `combine` is commutative, associative and idempotent, and never returns a status stronger than either input.
- [ ] Every accepted transition has exactly one `ground.status` ledger event, and replaying the events from the
      ledger reproduces the current state.
- [ ] `combine` of a `synthetic` and a `calibrated` part is `synthetic`; a `retired` part gives `no-claim` with
      the retirement reason in `warnings`.

### Known answers and negative controls

KA-735: the line is printed on every report and reads `no-claim` with no dataset (the type-level half is here).
The row's one runner entry, `ka:KA-735@host` (every report surface in a fresh store plus the 50-row battery, with
three mutation controls), is BD-139's; this bead adds no second entry. It names its type-level tests
(`default_is_no_claim`, `print_parse_roundtrip`, `calibrated_line_exact`, `malformed_lines_rejected`,
`synthetic_is_absorbing`) in the front matter of KA-735's derivation file, beside BD-139's entry.
Counterexample CX-334: recovering planted parameters from a simulator is not a Reality result; everything the
truth simulator emits is `origin = "synthetic"` and the claim stays `no-claim`. Negative controls: a transition
table mutant with an edge `synthetic → candidate` must fail `synthetic_is_absorbing`; a printer mutant that
omits the line when the status is `no-claim` must fail `default_is_no_claim`. Determinism: class D0.

## Considerations

- The plan's type sketch lists the six variants without payloads; the payloads here are DESIGN and follow the
  line's fields. If the envelope schema is frozen before M5, the M1 schema must already admit all six words.
- Risk register row "sim-to-real was never tested and claims overreached": the mitigation is this line at every
  milestone exit. Kill gate KILL-BAND (decided at M5: if the band-coverage or drift gate fails, bands are
  withdrawn) leaves this type unchanged: reports then print `reality: no-claim` with the raw residual table.
- A status is keyed by model lineage because a new card version is a new model identity, and evidence attached
  to the old identity does not carry over.
