## Background

A Reality result (a comparison of simulation with physical measurement, made by the subsystem Ground, crate
`frob-ground`) has a scope and no meaning outside it. The scope is the **cell**: which physical units, which
controller and firmware, which surface, which task family, inside which envelope of conditions. Decision
ADR-GROUND-02: the unit of calibration is the cell, and a band belongs to exactly one cell, because conformal
coverage holds for exchangeable draws only and pooling hides a failing regime. The demonstration: pooled
calibration at a 90% target covers 20 of 20 episodes in one regime and 16 of 20 in a shifted one; the total,
36 of 40, is nominal overall and 80% where it matters.

The admission bead (BD-387) reads the cell's components from a dataset manifest and refuses a dataset that does
not determine them. This bead makes the cell a first-class value that every later mechanism keys on: frozen
predictions name a cell, a band's bucket is a cell, a drift monitor belongs to a cell, and a change to any
component is a scope change that retires a calibration. Without one canonical identity, two code paths would
disagree about whether two datasets are "the same cell", and pooling would happen by accident.

Rejected alternatives: a free-text cell name chosen by the operator (two names for one cell, or one name for
two); a hierarchy of cells with inherited bands (inheritance is pooling under another name).

## Scope

In: the type, its canonical encoding and identity; envelope containment; the component diff; the pool guard and
refusal 814; narrowing a cell. Out: reading the manifest and refusing an undeclared cell (BD-387); what a scope
change does to a calibration (N30a-40, N30a-43); the exchangeable-unit rule inside a cell (N30a-37).

## Technical approach

1. **The key** (the plan's definition):
   `CellKey = (design: DesignId, units: set of unit ids, controller: ControllerId, firmware: text, surface: class,
   task_family: TaskFamilyId, envelope: box over the recorded conditions)`.
   DESIGN types: `units: BTreeSet<UnitId>` (serial-level identities; one unit is one cluster); `controller` a
   content hash of the controller artifact, or the explicit value `none` for a measurement that has no
   controller (the rule of BD-387 for a scale reading, a pendulum period or a scan; likewise `firmware`,
   `surface` and the task family `tf:none`), encoded under its own tag so that it can never collide with a
   hash or a text; `firmware` the text the device reported, compared byte for byte
   after Unicode normalization and trimming; `surface: SurfaceClass` a normalized `material/condition` pair
   such as `sealed-concrete/dry`; `envelope: BTreeMap<ConditionName, Interval>` with each interval closed,
   lo ≤ hi, carrying a unit (for example `temperature_C = [18, 24]`, `payload_kg = [0, 2]`,
   `speed_m_s = [0, 1.2]`).
2. **Canonical bytes and identity.** Serialize as: the domain tag `frob.ground.cell/1`; then each component in
   the order above, length-prefixed; set and map entries in sorted order; interval bounds as exact decimal
   strings converted to reduced rationals; units of measure as canonical symbols. `CellId = BLAKE3(canonical
   bytes)`, printed as `c:` plus 12 hex digits in report lines and in full in artifacts.
3. **Containment.** `cell.contains(conditions) -> Result<(), OutOfEnvelope { name, value, lo, hi }>`: every
   envelope dimension must be present in the recorded conditions and lie inside its closed interval; a
   recorded condition with no envelope dimension is ignored for containment and listed in a warning; a missing
   one is an error. At admission every episode of a dataset must be contained: this bead adds that call to
   the admission path of BD-387 (which landed first and compares components only), and a bundle with an
   episode outside its own declared envelope is refused with `FROB-REF-873`, pointer `rig.envelope`, naming
   the episode, the condition, its value and the interval (DESIGN: the envelope is by definition the box over
   the recorded conditions, so such a manifest does not determine its cell). Later, a new episode that is not
   contained is the scope-change trigger "a recorded condition leaves the envelope". From this bead on, the
   `cell` field of the admission result carries the `CellId` beside the seven components.
4. **Diff.** `CellKey::diff(a, b) -> Vec<ScopeComponent>` where
   `ScopeComponent = Design | Units { added, removed } | Controller | Firmware { from, to } | Surface | TaskFamily
   | Envelope { name, from, to }`. The empty diff is equality. The scope-change trigger and the pool guard both
   call this one function.
5. **The pool guard (refusal 814).** Calibration residuals, validation scores and holdout scores are collected
   only through `Pool::new(cell: CellId, model: ModelId, origin: Origin)` and `Pool::push(item)`. A push whose
   cell, model identity or origin (`real` or `synthetic`) differs from the pool's is refused with
   `FROB-REF-814` (pooling across cells, across `ModelId`s, or of synthetic with real data; repair: separate
   the pools; exit code 3), and the refusal payload carries the diff from step 4. There is no merge operation
   on pools.
6. **A cell needs built units.** `CellKey::new` refuses an empty `units` set. A request for a band on a design
   with no cell (a design that was never built) is therefore unanswerable by construction; the band verb
   reports it as `FROB-REF-895` (a band for a design that was never built; repair: `reality: no-claim`, with
   the simulation's own interval).
7. **Narrowing.** `cell.narrow(name, sub_interval) -> CellKey` returns a new cell with one envelope dimension
   restricted (used when a reversed ranking narrows the domain to where the ranking held, N30a-32). The result
   is a different `CellId` with a `narrowed_from` link in the ledger; no band or monitor is inherited: a band
   for the narrower cell is re-issued from the calibration points that lie inside it and must meet the minimum
   count on its own.

Determinism: class D0 (exact). No floating-point value enters the identity.

## Acceptance criteria

- [ ] The `CellId` does not depend on the order in which units or envelope dimensions were written, nor on
      `18`, `18.0` or `18.00` spellings of a bound.
- [ ] Changing any one of the seven components changes the `CellId`, and `diff` names exactly that component.
- [ ] Containment is inclusive at both ends; a condition at 24.0 °C is inside [18, 24] and one at 24.1 °C is out.
- [ ] `frob ground ingest` on a synthetic bundle with one episode recorded at 24.1 °C under the envelope
      [18, 24] is refused with 873 naming that episode and condition; the same bundle with the episode at
      24.0 °C is admitted and its result carries the `CellId`.
- [ ] `Pool::push` refuses a different cell, a different `ModelId` and a different origin, each with 814 and the
      diff; the 20-of-20 and 16-of-20 fixture cannot be pooled into 36 of 40 through any public function.
- [ ] `CellKey::new` with no units is refused; a narrowed cell inherits nothing.

`containment_missing_dimension_is_error`; `admission_refuses_episode_outside_envelope_873` (the 24.1 °C
bundle, through the admission function of BD-387); `pool_refuses_other_cell_814`; `pool_refuses_other_model_814`;
`pool_refuses_synthetic_with_real_814`; `no_public_merge_of_pools` (a compile-fail case);
`empty_units_refused`; `none_components_are_values` (a cell with controller `none` has a different `CellId`
from the same unit's driven cell, and `diff` names `Controller`);
`narrowed_cell_is_new_identity_and_inherits_nothing`.

### End-to-end script and logging

`scripts/e2e/ground_band.sh` (N30a-39) carries the pooled-regime case from the user's side: two synthetic
datasets that differ only in surface condition, a pooled band request, the 814 refusal and its diff. The log's
`refusal` line holds the code, both `CellId`s and the differing component.

### Known answers and negative controls

KA-736 and counterexample CX-330 (pool calibration data across regimes to get more points: 20 of 20 and 16 of
20 give 36 of 40, nominal overall and 80% where it matters; the rule protected is that the cell is the bucket).
Negative controls: an identity that omits `firmware` (the firmware case of `each_component_changes_id` fails);
a pool that checks the cell and not the origin. Determinism: D0; twice, debug and release, both machines.

## Considerations

- The plan gives the surface as a "class"; the registry of surface classes belongs to the contact and scene
  subsystems. Until a class registry is fixed, comparison is on the normalized text, which errs toward more
  cells (safe: never fewer).
- Firmware "as reported by the device" may be coarse; two builds that report one version string are one cell
  to this type. The controller content hash is the stronger identity where the controller is ours.
- Operators will want to merge cells to reach the minimum count. There is no override; the decision
  (ADR-GROUND-02) is the reason, and the refusal's repair says "separate the pools".
- Privacy: unit serials can identify an owner. A dataset recorded in a private place carries the private mark,
  and a `CellId` (a hash) is what leaves the scope, never the serials.
