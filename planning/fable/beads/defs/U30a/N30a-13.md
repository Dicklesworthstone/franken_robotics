## Background

Ground (crate `frob-ground`) maps the clocks of a real dataset to one reference clock before any time-based
comparison of simulation with measurement. Two shortcuts are tempting, both give smaller reported errors, and
both are wrong. This bead makes each unrepresentable in the types and detectable in the record.

**Rule 2: the clock is never fitted to the event being scored.** Counterexample: the prediction says the wheel
crosses the sill at 4.212 s and the log shows 4.180 s. Choosing the offset that aligns the two reports a
crossing-time error of zero and an offset of 32 ms. The whole error has been moved into the clock.

**Rule 3: cross-correlating command and response is not a clock fit.** It estimates offset plus actuator delay:
a delay of 8 ms with an offset of −8 ms produces the same logs as no delay and no offset. Without a shared
hardware mark the identified quantity is reported as "delay plus offset" and the actuator card's delay is not
updated. This is structural alias 5 of the identifiability analysis (actuator delay against clock offset; what
separates them: a shared hardware mark).

Why it matters downstream: actuator delay is one of the parameters the sim-to-real literature calls critical;
a card whose delay silently contains a logging offset mispredicts on every other rig.

## Scope

In: the independence check between a clock fit and scored events; the tamper check on a clock artifact; the
clock graph and the `Delay` against `DelayPlusOffset` types; the lag diagnostic; the refusals. Out: the fit
(N30a-11); bracket and interval rules (N30a-12); delay profiling inside identification (N30a-23); the card
writer (N30a-27), which consumes the `Delay` type defined here.

## Technical approach

1. **Marks are committed at admission.** The dataset manifest lists each clock's marks, and each mark has a
   kind: `hardware-pulse`, `sync-edge` or `protocol-sync` (DESIGN). The marks are part of the hashed manifest,
   so the set of marks is fixed before any sealed chunk can be read. A "mark" that is a task event (a contact,
   a threshold crossing, the start of motion) is not a mark kind and cannot be declared.
2. **A fit is a pure function of the marks.** `ClockFit` artifacts record the mark identities used. On every
   use in scoring, `clock::verify(fit, dataset)` recomputes the fit from the committed marks and compares it
   bit for bit with the artifact. A mismatch is refused with `FROB-REF-876` and labelled
   `clock-not-from-marks`; this is how an offset adjusted by hand (the 32 ms of the counterexample) is detected.
3. **Independence from the scored event.** `score` passes the scored metric's channels and window to
   `clock::independent_of(fit, channels, window)`, which checks in the artifact graph that no input of the fit
   is a sample of those channels. Because inputs are marks only (step 1), the check can fail only for a
   tampered or foreign artifact; it is kept as a second lock and logged.
4. **The clock graph.** Nodes are clocks; an edge joins two clocks that share at least the marks the fit model
   needs (two for an affine fit). `clock::linked(a, b)` is true when a path exists; the alignment between a and
   b then has a covariance composed along the path. For the `Delay` type of step 5 only hardware marks count
   toward an edge (kinds `hardware-pulse` and `sync-edge`, the plan's "shared hardware mark"); `protocol-sync`
   marks may align clocks for scoring but never turn a lag into a `Delay` (the manifest field rules are
   N30ax-01's, which states the same requirement).
5. **Typed lags** (DESIGN).
   ```rust
   pub struct Delay { value: Qty, sigma: Qty, evidence: LinkedClocks }          // may update a card
   pub struct DelayPlusOffset { value: Qty, sigma: Qty, missing: MarkNeeded }   // may not
   ```
   Any estimator of a lag between a command channel and a response channel (the cross-correlation diagnostic
   below; the delay profile of identification) returns `Delay` only if both channels are on one clock or their
   clocks are `linked`; otherwise it returns `DelayPlusOffset`. The card writer's delay field accepts `Delay`
   only: there is no conversion from `DelayPlusOffset`.
6. **Reporting.** With no shared mark the identification report prints "delay plus offset = <value> ± <σ>"
   and lists the mark that would separate the two (a pulse visible on both the command logger and the encoder
   clock). The card's delay keeps its prior value and provenance. An explicit request to write the delay is
   refused with `FROB-REF-879` (a fit on a parameter set that fails identifiability; repair offered: the
   aliased combination and the separating experiment; exit code 3).
7. **The lag diagnostic.** `clock::xcorr_lag(command, response, max_lag)`: both signals are resampled on the
   response clock's raw grid, differenced once, normalized, cross-correlated over ±max_lag, and the peak is
   refined by a three-point parabola; σ comes from the curvature at the peak and the residual variance. It is
   a diagnostic and a warm start for delay profiling, and its return type follows step 5.

## Acceptance criteria

- [ ] The crossing counterexample: a clock artifact whose offset was shifted by 32 ms so that a predicted
      crossing at 4.212 s matches a logged 4.180 s is refused at scoring with 876 and the label
      `clock-not-from-marks`; with the honest fit the score reports a crossing-time error of 32 ms (within the
      alignment uncertainty).
- [ ] A manifest that declares a task event as a mark is refused at admission.
- [ ] Planted delay 8 ms with planted offset −8 ms and no shared mark: the report reads "delay plus offset = 0"
      (within its σ), the card's delay field is unchanged, and a forced delay update is refused with 879.
- [ ] The same data with one shared pulse pair added (two marks): the result type is `Delay`, the estimate is
      8 ms within one grid step of the profile, and the offset is −8 ms within 3·σ.
- [ ] `Delay` cannot be constructed from `DelayPlusOffset` anywhere in the workspace (compile-fail test).

## Test plan

### Unit tests

`crates/frob-ground/tests/clock_misuse.rs`: `tampered_offset_detected` (32 ms shift);
`honest_fit_reports_32ms_error`; `task_event_mark_refused`; `fit_inputs_are_marks_only`;
`clock_graph_linked_through_intermediate` (A–B and B–C share marks, A–C do not: linked);
`protocol_sync_marks_never_make_a_delay` (command and encoder clocks share two `protocol-sync` marks only: the
lag is `DelayPlusOffset`);
`unlinked_lag_is_delay_plus_offset`; `delay8_offset_minus8_reports_zero`; `forced_delay_update_refused_879`;
`linked_lag_is_delay`; `xcorr_peak_refinement` (a pure delay of 8.0 ms at 1 kHz on a multisine recovers 8.0 ms
within 0.05 ms); trybuild `no_conversion_delay_plus_offset_to_delay`.

### End-to-end script and logging

Part of `scripts/e2e/ground_clock.sh` (N30a-14): the tampered-artifact control and the delay-against-offset
case run through `frob ground ingest`, `frob ground identify --stage actuators` and `frob ground score`.
Logged: the recomputed and the stored fit parameters with their difference, the label, the report text
"delay plus offset = …", and the card identity before and after (equal).

### Known answers and negative controls

KA-721's second control (an offset fitted to the scored event is detected) and KA-725 (delay 8 ms, offset
−8 ms, no shared hardware mark: reported as "delay plus offset = 0"; control: a card delay update is refused).
Counterexamples CX-326 (fit the clock offset to the event being scored) and CX-327 (cross-correlating command
and response fits the clock). Negative controls registered: a scoring path that skips `clock::verify`; a card
writer mutant that accepts `DelayPlusOffset`. Determinism: verification is a bitwise comparison on one
platform; across platforms it compares inside the fit's recorded tolerance and says which was used.

## Considerations

- Bitwise recomputation assumes the fit runs on the same platform class as the one that wrote the artifact;
  across platforms the tolerance is 10⁻¹² relative on the parameters (DESIGN), far below 32 ms and far above
  rounding.
- Protocol-level synchronisation (for example a network time protocol) can serve as marks only with a stated
  σ_m; its error is usually much larger than a hardware pulse's, and the fit's uncertainty shows it.
- The spatial counterpart of this alias (a sensor's exposure delay against a translation of its mount along
  the direction of travel) is a separate fixture with its own gate, drafted with the chapter's second half.
- If the kill gate KILL-CLOCK fires, no delay is reported at all and both checks remain as guards.
