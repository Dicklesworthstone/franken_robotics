## Background

A Reality result that only its authors can reproduce is an anecdote. A **replication kit** lets a third party
rebuild a result without access to this machine or to anything private: the inputs, the records, the protocol
by which the data was acquired, the expected outputs with their tolerances, and a rehearsal that runs with no
hardware at all. Ground (crate `frob-ground`) is the subsystem that compares simulation with measured reality;
the kit is how its results leave the building.

Four properties define it.

- **Contents.** The design, cards, scene pack, task and prediction records; the dataset if its licence permits,
  otherwise its hash and the acquisition protocol; the bench protocol (rig description, excitation plan as
  data, instrument list); the analysis configuration; expected outputs with tolerances and determinism classes;
  any cited certificate bundle; the no-authorization flags; and the synthetic rehearsal, so the known answers
  run with no hardware.
- **Nothing private.** The builder refuses any input that carries or inherits the private mark, and any asset
  whose licence forbids redistribution. There is no override flag.
- **Self-test.** A kit passes when a clean machine reproduces its numbers: bit for bit on the same backend
  (determinism class D2), inside the recorded envelope otherwise (class D3). The checker is N30b-12.
- **Losing results too.** A kit is built for a falsified prediction as readily as for a confirmed one.

Background on the two rules it leans on. The private mark is computed, not assigned: the mark of an artifact is
the join of the marks of everything in its lineage, so a score computed on a log recorded in a private home is
private without anyone marking it. Licences have five classes (`redistributable`, `attribution`,
`research-only`, `proprietary`, `unknown`, the last treated as the most restrictive) and the licence set of a
derived artifact is the join over its inputs.

Rejected alternatives: an `--allow-private` flag "for internal sharing" (the kit is defined by being safe to
hand to a stranger, and a flag is a path); shipping only winners (a reader then cannot tell a method that works
from one that was tried until it worked).

Tier: Frontier. Kill gate KILL-KIT, named in advance: if GATE-GROUND-09 fails, the kit ships as an archive of
inputs, records and hashes, with no reproduction claim.

## Scope

In: the kit's layout and manifest; selection of contents from a result's lineage; the privacy and licence
screen and its refusal; the dataset-or-protocol substitution; expected outputs; embedding the rehearsal; the
build form of the verb. Out: the check form and the clean-machine self-test (N30b-12); the private mark and
licence join themselves (the safety subsystem); the kill decision (N30b-21).

## Technical approach

1. **Verb.** `frob ground kit build --result <score-or-band-id> --out <dir> --json`; kind `run` (idempotency
   key, budget); capability `ground:read` plus the export scope of the session; schemas
   `frob.ground.kit.in/1`, `.out/1`. Result: kit identifier (hash of the manifest), file list with hashes,
   substitutions made, the classes of the expected outputs. Refusal: FROB-REF-899 (a private or
   non-redistributable input to a kit). The check form is `frob ground kit check <dir>`.
2. **Layout** (a directory, written atomically, addressed by the manifest hash):

   ```
   kit.toml                       # frob.ground.kit/1: result, lineage, files with hashes, flags, classes
   design/  cards/  scene/  task/ # the identities the result was computed on
   predictions/                   # every prediction version, superseded ones included
   records/                       # clock fits, calibration records, score records, band and monitor records
   dataset/                       # the bundle, or dataset.stub.toml with its hash and acquisition protocol
   protocol/                      # rig description, excitation plan as data, instrument list
   analysis/                      # the exact verb calls with arguments, seeds and the stack pin
   expected/                      # outputs with tolerances and determinism classes
   certs/                         # any cited .frobcert
   rehearsal/                     # generator recipe, seed, dataset ids and bundles of the synthetic rehearsal
   NOTICE                         # attribution notices required by the licence join
   ```
3. **Selection.** The contents are the lineage closure of the result in the artifact graph, cut at datasets:
   every design, card version, scene, task, prediction, record and certificate the result resolves to.
4. **Screen** (before any byte is written):
   - any candidate that carries or inherits the private mark → FROB-REF-899, listing each offending input with
     the lineage step that marks it. No substitution is offered for private inputs: a result computed on
     private data cannot be put in a kit.
   - a dataset whose licence class forbids redistribution, and that is not private → replaced by
     `dataset.stub.toml` (dataset id, chunk hashes, licence, the acquisition protocol). Outputs derived from
     that dataset's bytes (scores, bands, monitor records) carry its licence join; where the join forbids
     redistribution they are left out and listed in the manifest as `withheld: licence`, while the prediction
     records, which were frozen before the data was read and do not derive from it, are included.
   - any other asset whose joined licence forbids redistribution → 899.
   - `attribution` class inputs add their notices to `NOTICE`.
5. **Expected outputs.** For each verb call in `analysis/`: the expected envelope's result fields, each with a
   tolerance and the determinism class it was produced under, and the digest for class D2 outputs. On a
   machine of the same backend and fingerprint family the check is bit equality; otherwise it is the recorded
   envelope (class D3).
6. **Flags.** `kit.toml` and every exported document carry `execution_authorized: false`,
   `hardware_safety_signoff: false` and `sim_to_real_certified: false`; no parameter produces another value.
7. **Rehearsal.** The synthetic rehearsal's recipe, seed and bundles are always included, with their own
   expected outputs, so that a recipient can run the subsystem's known answers before trusting anything else.
   Its files are labelled `synthetic` and stay so.
8. **Losing results.** `--result` accepts a rejected candidate, a `ranking-falsified` score or a retired cell;
   the manifest's `outcome` field states it, and nothing in the builder branches on the outcome.

Determinism: the build is a pure function of the lineage and the options; two builds give the same kit
identifier (class D0). Evidence: a kit carries the claim products of its contents unchanged.

## Acceptance criteria

- [ ] GATE-GROUND-09, refusal part (TARGET): a kit request whose lineage contains a private input is refused
      with FROB-REF-899 naming the input and the marking step; no file is written.
- [ ] A kit of the synthetic rehearsal builds, and its check passes on a clean machine (the reproduction part of
      the gate, measured by N30b-12).
- [ ] A `research-only` dataset is replaced by its stub; the predictions are present; derived scores are listed
      as withheld; `NOTICE` holds the attribution texts of `attribution` inputs.
- [ ] The verb's schema has no parameter that overrides the screen (registry test); a planted
      `--allow-private` argument is refused as an unknown parameter.
- [ ] A kit built for a falsified prediction contains the same sections as one for a confirmed prediction, and
      its manifest says `outcome = "falsified"`.
- [ ] Two builds of one result give identical manifest hashes; a changed seed in `analysis/` changes it.
- [ ] The measurement is handed to the KILL-KIT decision (N30b-21).
- [ ] Reachable through `frob ground kit --json` and the path jail: `--out` outside the session's export root is
      refused; cancellation leaves no partial directory.

## Test plan

### Unit tests

`crates/frob-ground/tests/kit_build.rs` (real store, `synthetic` inputs; a private mark is planted on a
`synthetic` dataset through the real marking API): `lineage_closure_is_complete`;
`private_input_refused_899`; `inherited_private_mark_refused_899` (a score derived from a private log);
`refusal_writes_nothing`; `research_only_dataset_becomes_stub`; `withheld_outputs_listed`;
`predictions_survive_substitution`; `unknown_licence_treated_as_most_restrictive`;
`attribution_notice_collected`; `flags_all_false`; `no_override_parameter_in_schema`;
`losing_result_same_sections`; `manifest_hash_stable`; `rehearsal_always_embedded`;
`superseded_predictions_included`.

### End-to-end script and logging

`scripts/e2e/ground_kit.sh` (bead N30b-36) builds a kit from the rehearsal result, then attempts a build from a
result whose lineage has a planted private mark, and logs the manifest hash, the file count, the substitutions,
the refusal with its code and the offending lineage path (identifiers only, never content).

### Known answers and negative controls

The gate's refusal clause (a private input is refused). Planted failures: a builder that checks the mark of the
direct inputs only (the inherited mark passes: caught); a builder that copies a `research-only` dataset; a
builder that omits a superseded, failed prediction (the losing history is lost: caught by
`superseded_predictions_included`). Metamorphic relation: adding an unrelated artifact to the store changes no
kit. Determinism lanes: twice on one machine; debug and release; identical manifest hashes across platforms.

## Considerations

- The screen is conservative by construction: `unknown` licence is the most restrictive class, and the private
  mark has no substitution. A team that needs to share private results internally uses the ordinary export
  path with its own scopes, not a kit.
- A kit of a result on real data whose dataset cannot ship is still useful: it carries the frozen predictions,
  the protocol and the rehearsal, and a recipient with their own rig can acquire data and score against the
  same predictions.
- Size: a rehearsal kit is hundreds of megabytes (TARGET under 1 GB); the population fixtures are regenerated
  from the recipe by the checker and only their ids are stored.
- The kit manifest is a schema of this crate; whether it becomes a registered file format is the format
  registry owner's call.
