## Background

Every capability of the system is reached through verbs declared in one registry, `registries/verbs.toml`,
owned by the crate `frob-verbs`. The command line, the daemon protocol, the MCP tool definitions, the schemas,
the refusal table and the agent documentation are generated from it, so the surfaces cannot drift. A cluster is
a namespace in that registry. Ground, the subsystem that compares simulation with measured reality, has the
cluster `ground` with seven verbs, which is the limit a cluster is allowed for tools shown to an agent at once.

Verb kinds: `read` returns stored or cheaply computed facts and changes nothing; `run` spends compute, takes an
idempotency key and a budget, accepts the bounded synchronous wait (`sync_wait_ms`) and otherwise returns a job
handle with exit code 8; `mutate` creates or changes a named object in the caller's namespace and takes an
idempotency key and an expected parent; `admin` needs a capability scope.

This bead is the surface of the subsystem: the seven registry entries, complete and consistent. The handlers
are built by the mechanism beads. Three things make a separate bead necessary. The chapter's verb table lists
refusal numbers from an earlier numbering (840 to 850, which the registry assigns to other subsystems); the
entries here use the registry's codes. Two of the seven verbs are not in the task cluster the registry shows an
agent for calibration work, and a lint requires every verb to sit in at least one. And one verb is registered
as `read` while one of its forms changes state.

## Scope

In: the seven entries; kinds; first milestones; input and output schema names; capabilities; refusal lists;
cost models; examples; the mapping to MCP tool names; task-cluster placement; long-verb behaviour. Out: the
handlers (BD-387 `ground.ingest`, BD-390 `ground.excite`, BD-391 `ground.identify`, BD-392 `ground.predict`,
N30b-06 `ground.score`, BD-393 `ground.band`, BD-396 and N30b-12 `ground.kit`); the refusal rows themselves
(N30-REF).

## Technical approach

1. **Entries** (one `[[verb]]` table each; `cluster = "ground"`; `tier = "F"` except where noted).

   | Verb | Kind | First milestone | Does | Capabilities | Refusals (registry codes) |
   |---|---|---|---|---|---|
   | `ground.ingest` | mutate | M1 for the reality line it must not disturb; M5 for admission of logs and bench measurements, and for scans | Admits a log, a bench measurement or a scan; fits clocks; seals splits; feeds the monitors of calibrated cells | `ground:write` | FROB-REF-873, -876, -812, -814, -886 |
   | `ground.excite` | read | M5 (may be recorded from M4) | Identifiability report and excitation plan for a design, a card set and a rig description; needs no data and never returns a fit | `ground:read` | FROB-REF-879 |
   | `ground.identify` | run | M5 | Staged identification; writes candidate card versions and the calibration record | `ground:write` | FROB-REF-879, -814 |
   | `ground.predict` | mutate | M5 | Freezes a prediction for a planned trial | `ground:write` | FROB-REF-883; consumed: -532, -552, -102 |
   | `ground.score` | run | M5 | Opens sealed data once, scores, retires the holdout, admits or rejects the posterior | `ground:score` | FROB-REF-883, -886, -876 |
   | `ground.band` | read | M5 | Issues or refuses a band; lists cells, coverage accounting and monitor states; `--retire` needs a capability | `ground:read`; `ground:retire` for `--retire` | FROB-REF-889, -895, -897, -814 |
   | `ground.kit` | run | M5 | Builds or checks a replication kit | `ground:read` and the session's export scope | FROB-REF-899 |

   Every verb also passes through the private-scope refusal (FROB-REF-731), the licence refusal (-733) and the
   schema refusal (-802) unchanged.
2. **Schemas.** `frob.ground.<verb>.in/1` and `frob.ground.<verb>.out/1` for each; the stored record schemas
   they reference: `frob.ground.dataset/1`, `frob.ground.clockfit/1`, `frob.ground.calibration/1`,
   `frob.ground.prediction/1`, `frob.ground.score/1`, `frob.ground.band/1`, `frob.ground.monitor/1`,
   `frob.ground.asbuilt/1`, `frob.ground.kit/1`. Every output schema carries `evidence` with `class` fixed to
   `Estimated` for this cluster, `reality`, and for exporting forms `authorization` with the three flags false.
3. **Long verbs.** `identify`, `score` and `kit` take the bounded synchronous wait and otherwise return a job
   handle with exit code 8; progress always has a denominator (rigs, joints, calls replayed). `ingest` of a
   large bundle is a `mutate` with chunked upload under the job protocol.
4. **`ground.band --retire`.** DESIGN: the entry keeps kind `read`; the registry declares a second parameter
   set `retire` with `requires = ["ground:retire"]`, `idempotent = true` and its own idempotency key, and the
   generated MCP tool exposes it as a separate optional group. The registry lint that forbids state change in
   `read` verbs lists this parameter set as its one exemption for the cluster.
5. **MCP names and task clusters.** Tool names are the verb names with `.` replaced by `_`. The principal task
   cluster for calibration work is `reality`: `ground_ingest`, `ground_identify`, `ground_predict`,
   `ground_score`, `ground_band`, `predict_report`, `report_run`. DESIGN: `ground_excite` and `ground_kit` are
   placed in a further task cluster `reality-plan` with `experiment_suggest`, `predict_register`,
   `actuator_show`, `prove_verify` and `artifact_export` (seven tools), so the lint passes and an agent that is
   planning a bench session or packaging a result sees the tools for that.
6. **Cost models and examples.** Each entry has a `cost_model` line (`ingest`: linear in bundle bytes;
   `excite`: static, seconds; `identify`: minutes per joint; `predict`: one simulated trial per registered
   trial; `score`: seconds per trial; `band`: static; `kit`: minutes to an hour for a check) and at least one
   example that runs on the synthetic rehearsal, for example
   `frob ground band --cell c:9f2c41 --metric crossing_time_s --level 0.90 --json`.

## Acceptance criteria

- [ ] The seven entries load; `frob capabilities --json` lists them with the kinds and milestones above; the
      cluster has exactly seven verbs and a lint fails on an eighth.
- [ ] No entry lists a refusal code in 840 to 850; the lists equal those of the refusal registry in both
      directions (`xtask check-generated`).
- [ ] The MCP surface serves seven tools for the cluster with the mapped names, and both task clusters have at
      most seven tools; every `ground` verb is in at least one.
- [ ] Each example in the registry parses against its input schema now; once its handler has landed it runs on
      the rehearsal and returns an envelope that validates against its output schema with
      `evidence.class = "Estimated"` and `evidence.reality = "synthetic"` (asserted by the end-to-end run N30b-31).
- [ ] `ground.band --retire` without `ground:retire` is refused with the capability refusal; the three read
      forms need only `ground:read`.
- [ ] `identify`, `score` and `kit` return exit code 8 with a job handle when `sync_wait_ms` elapses, and the
      job completes with the same envelope a synchronous call returns.
- [ ] Until a handler lands, its verb answers with the not-implemented refusal (FROB-REF-724), never with a
      silent success.

### End-to-end script and logging

`scripts/e2e/ground_rehearsal.sh` (bead N30b-31) calls all seven verbs in the order of the procedure through
the CLI and, for three of them, through `frob-mcp`, and logs for each the command, kind, exit code, the evidence
block and schema validation of the envelope. `scripts/e2e/ground_refusals.sh` (bead N30b-37) covers the refusal
lists.

### Known answers and negative controls

Negative controls: a registry with `ground.band` listing FROB-REF-846 (the stale-number lint fails); a registry
with an eighth `ground` verb (the cluster-limit lint fails); a task-cluster assignment that omits
`ground_excite` (the membership lint fails); an output schema whose class is free (the fixed-class test fails).

## Considerations

- The chapter gives `ground.excite` a first milestone of M4 and the gate register governs with M5; the entry
  says M5 and notes that the verb may be exercised from M4 if its handler exists.
- The chapter gives `ground.ingest` M1 "for admission and the reality line"; the admission handler is scheduled
  at M5. At M1 the entry exists and answers not-implemented, and the reality line is carried by every other
  verb's envelope.
- Naming: the registry holds no second spelling. `ground.kit` has two forms (`build`, `check`) as a positional
  argument, not two verbs, to stay inside the limit of seven.
- The class of every output of this cluster is fixed in the schema, which is how open question OPEN-GROUND-5
  (who could promote an estimated candidate: nobody, by default) is enforced at the surface.
