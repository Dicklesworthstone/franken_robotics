## Background

A gate passes only with a recorded measurement against its threshold. The record is a row of
`registries/gates.toml` that cites a commit, the command, its output and a receipt hash, and that resolves in
the artifact graph. A gate with no record has the status `not run`, which is not a pass. Statuses are
`not run`, `pass`, `fail`, `killed: fallback adopted` and `blocked: ⟨open question⟩`. Each gate names exactly
one of the seven kinds of claim. Every convergence gate has a registered negative control that it catches, and
a gate whose control has not been shown to fail has not passed. Where a subsystem's own text and the central
register differ on a gate's identity, claim, milestone or numbers, the register governs.

Ground, the subsystem that compares simulation with measured reality, has eleven convergence gates and five
kill gates. Their measurements are spread over many beads; this bead enters the rows themselves once, so that
every measuring bead writes into a row that already states the threshold, the fixture, the controls and the
milestone, and so that the status table can show the subsystem honestly from M1 on (ten rows `not run`, one
measured).

Ceiling, stated with the rows: Ground has no lever on time or compute. It is an honesty mechanism, and its
only possible saving, on real-trial count, is bounded near 1.3. No row below is a Performance claim.

## Scope

In: the sixteen rows with claim, threshold, earliest milestone, fixture, measuring bead, controls and kill
linkage; the recurring rule for the first gate; the unscheduled rule for the tenth; the lint that keeps rows
and measuring scripts in agreement. Out: measuring anything; the control records (N30-CX); the kill decisions
(N30b-17 to N30b-21).

3. **Row content.** Each row: `id`, `claim`, `threshold` (structured, with numbers and units), `earliest`,
   `recurring`, `fixture`, `command` (the end-to-end script), `controls` (identifiers from the control
   registry), `kill`, `owner = "ground"`, and a list of `records`, each with commit, hardware fingerprint,
   seed, measured values, receipt hash, the recording session and status. Records are appended, never
   overwritten.
4. **Rules encoded.**
   - GATE-GROUND-01 is `recurring = true`: every milestone exit after M1 appends a record; an exit with no new
     record for it is incomplete.
   - GATE-GROUND-03 carries `earliest = "M5"` with the note that the subsystem's own text tags it M4 and that it
     may be recorded there.
   - GATE-GROUND-10 carries `earliest = "unscheduled"`; it never blocks an exit; at M5 the exit requires that
     the lane has a record or a recorded no-claim.
   - GATE-GROUND-11 belongs to a subsection added after the main tables were compiled; it is a full row.
   - A gate with a kill gate does not block the exit when it fails: the kill decision with its fallback adopted
     is the record. GATE-GROUND-01, -03 and -11 have no kill gate and block.
5. **Lint.** A test compares each row's `command` with the scripts under `scripts/e2e/`: the script exists, its
   header names a bead listed in the row, and its `summary` line can emit the row's gate identifier. A row
   whose controls are not all present in the control registry cannot take the status `pass`.

## Acceptance criteria

- [ ] Sixteen rows load from `registries/gates.toml`; each convergence row names exactly one claim; ten are
      Known answer and one is Reality.
- [ ] At M1 the status table generated from the registry shows GATE-GROUND-01 with its measured record and the
      other ten as `not run`, and never prints a pass for a row with no record.
- [ ] Every convergence row has at least one control that resolves in the control registry.
- [ ] The lint fails when a script named by a row is missing, and when a script claims a gate no row assigns to
      it.
- [ ] A planted `pass` record written by the same session that implemented the measured bead is refused (no
      self-certification), and a planted `pass` with an uncaught control is refused.
- [ ] Thresholds in rows equal the numbers in this bead; a change to a kill gate's trigger, threshold or
      fallback is accepted only as a dated amendment entry that precedes the measurement it governs.

## Test plan

### Unit tests

`crates/frob-conformance/tests/gates_ground.rs`: `sixteen_rows`; `claims_one_each`; `milestones_per_register`
(03 at M5; 10 unscheduled; 01 recurring); `kill_linkage` (02 and 05 → KILL-CLOCK; 06 and 07 → KILL-BAND; 04 →
KILL-GROUND with `repair_cycles = 1`; 08 → KILL-ASBUILT; 09 → KILL-KIT); `rows_have_controls`;
`scripts_match_rows`; `self_certified_pass_refused`; `pass_with_uncaught_control_refused`;
`late_amendment_refused`.

### End-to-end script and logging

No script of its own. Each row's `command` is the script of its measuring bead; those scripts emit
`e2e_gate <id>` and `e2e_metric … --gate <id>`, and the gate report tool of the shared harness assembles the
records this bead's rows hold.

### Known answers and negative controls

Reference values present in rows: 19/21 = 0.9048; 0.069; 21 ppm; 990 of 1,000; 95, 0.70 and 90; 20 episodes;
10⁴ null runs; 80 mm to 10⁻⁹. Negative controls: a registry in which GATE-GROUND-03 is tagged M4 only (the
milestone lint fails against the register); a row for GATE-GROUND-10 with `earliest = "M5"` (it would block the
exit: refused by the lint).

## Considerations

- The gate for the eight structural aliases is measured by the bead that owns the identifiability analysis.
  This bead registers its row and the end-to-end rehearsal re-asserts it; if that owner bead were to change
  scope, the row would still name a measuring script.
- Four of the eleven thresholds are statistical. Their rows record the seed and the expected value beside the
  measured one, so a reader can tell a near-miss from a defect.
- The pairing of GATE-GROUND-05 with KILL-CLOCK is the register's and is kept; the kill decision adds a
  fail-closed rule for that case.
