## Background

Ground is the subsystem that compares simulation with measured reality. It owns no hardware: it reads files and
writes files. Whether it ever has real data to read depends on a question that engineering cannot answer:
**whether any bench hardware is acquired.** Six optional bench packages are defined (an actuator stand; a ramp
and drag sled for material pairs; the instrumented cart and sill fixture; one built link; a calibrated release
of named robot, surface and task cells; an independent revalidation). Decision **ADR-GROUND-10:** bench work is
optional, is packaged separately and blocks no milestone, because Reality is an import lane. None of the
packages is scheduled against a milestone, none gates a release, and each leaves `reality: no-claim` in place
if it never runs. Sourcing may start at M0, and nothing waits for it.

- **Fail-closed default:** none acquired; Reality stays `no-claim`.
- **Owner:** project lead. **Blocks:** nothing. **Owner input wanted at:** M5.

The decision bead exists, although the question blocks no milestone, because six beads exist only on one branch
of it and because the owner's input is explicitly asked for at the M5 exit.

## Scope

In: the options, what each buys in terms of the subsystem's statements, the decision and its record, what
changes on each outcome. Out: the packages themselves (N30b-38 to N30b-40); the choice of a public dataset
(N30b-25).

## Technical approach

1. **Options, cheapest first, with what each makes sayable.**

   | Option | Rig | What becomes sayable | What stays `no-claim` |
   |---|---|---|---|
   | None | — | Nothing measured; the rehearsal shows the machinery is sound | Everything |
   | A | One actuator of a catalogue class on a stand with a known payload | One card of one unit with `measured` fields, admitted by a sealed prediction of a held-out trajectory | Contact, whole robots, any class statement |
   | A + B | Adds an incline and a drag sled | Friction per material pair with its interval; the friction-against-torque-limit alias shown separated | Whole robots |
   | A + B + C | Adds the cart and sill fixture with 60 mm and 75 mm wheels | A frozen prediction and the A/B ranking scored on a sealed day: the first whole-system cell | Legged robots; any other task |
   | D | One printed or machined link with fiducials, a scanner and a scale | The as-built loop closed on one part, with its tolerance audit | Assemblies |
   | E, F | Named robot, surface and task cells; independently acquired traces | Bands per cell from held-out predictions with limits stated; each ranking reversal and calibration limit reported | Units and cells not measured |
2. **Value statement for the owner** (from the real-episode planner): in an uncalibrated cell the reality gap
   is the largest unknown, and twenty real pairs are worth about three times all remaining simulation for a
   decision between two close finalists (0.0251 against 0.0084 in the worked case); in a calibrated cell the
   order reverses. The first batch of real data is the valuable one.
3. **Cost side.** No rate between operator time and compute is assumed (a separate open question, default: real
   episodes are recommended, never scheduled). The owner sees costs in episodes, parts and days.
4. **Decision.** One of: none (default); a named subset of packages with a budget and an operator; or defer
   with a date. A decision to acquire does not create a milestone dependency: the packages stay imports.
5. **Record.** `docs/adr/OPEN-GROUND-2.md` with the option chosen, the budget if any, the owner's sign-off and
   the date; the open-questions registry row updated. On "none" the three package beads are closed as not
   funded with a typed reason citing this record, and can be reopened by a later decision.

## Acceptance criteria

- [ ] The decision record exists at the M5 exit, signed by the owner named for the question, in one of the three
      forms.
- [ ] Under the default, the package beads are closed as not funded and the Reality lane's record states the
      default of this question.
- [ ] Under any acquisition, no milestone epic gains a dependency on a package bead (a graph lint).
- [ ] The record states, per chosen package, what becomes sayable and what stays `no-claim`.

`crates/frob-conformance/tests/open_ground_2.rs`: `default_is_none`; `packages_never_block_milestones` (the
dependency graph has no path from any milestone exit bead to a package bead);
`not_funded_close_reason_cites_record`.

### End-to-end script and logging

`scripts/e2e/ground_first_record.sh` (bead BD-397) prints the state of this question at the top of its log; with
no decision record it asserts the default and that every report surface prints `reality: no-claim`.

### Known answers and negative controls

Reference values in the value statement: 0.0251, 0.0084 and 0.0035 (real batch uncalibrated; all remaining
simulation; the same real batch calibrated). Negative control: a planted dependency from the M5 exit review to
a package bead must fail the graph lint.

## Considerations

- A bench rig is also a liability: it needs calibration identities for its instruments, an operator who records
  every attempt including aborted ones, and conditions assigned from a registered draw. A package acquired
  without that discipline produces data that admission will refuse.
- Borrowed time on someone else's robot is a form of acquisition and goes through the same record, with the
  data's licence and privacy mark decided first.
- The subsystem's value does not depend on this decision: with no hardware it still prevents a simulated number
  from being read as measured.
