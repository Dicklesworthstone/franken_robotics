## Background

Ground, the subsystem that compares simulation with measured reality, is a procedure of ten steps: admit data
and seal splits; fit clocks; analyse identifiability and design excitation; identify actuators; identify
contact, inertia and sensors; write candidate cards; freeze predictions; score on sealed data, retire the
holdout and admit or reject; issue or refuse a band; monitor drift and retire; feed discrepancy back. Each step
has a verb, an output and a state it fails closed to. With no real data, the only way to know that the steps
work together is to run them, in order, on the synthetic rehearsal: a truth simulator with planted parameters
whose every output is labelled `synthetic`.

The per-gate batteries (clock, identification, protocol, bands and drift, as-built, kit) measure statistical
thresholds one mechanism at a time. This script is different: it is the user's path. One agent-like session
takes one rig from a bundle on disk to a band and a kit, and one assertion per known-answer row checks that
the planted truth came out. It completes, from the user's side and through all seven verbs, what the
rehearsal's seed bead BD-388 can only show for the generator and admission (the known answers reproduce; every
output prints `synthetic`), and it is the demonstration the M5 milestone names: the seven `ground` verbs
exercised first on the synthetic rehearsal. BD-388 closes on its own tests and does not wait for this script.

## Scope

In: the script; its fixtures (generated, not stored); its assertions per row; its log; the run of the
cluster's seven registry examples on the rehearsal, with their rows of the example-identity file. Out: the statistical
batteries (N30a-14, N30a-26, N30a-35, N30a-39, N30a-44, N30a-48 and N30b-36); the refusal battery (N30b-37); the ninth-alias gate (N30b-30).
The order of the ten steps, the refusal of out-of-order calls and the fail-closed outcome of each step are
asserted by `scripts/e2e/ground_procedure.sh` (N30a-10); the per-cell procedure state both scripts walk is
N30a-09 (a dependency). This script asserts the values: one assertion per known-answer row, through all seven
verbs and on both surfaces.

## Technical approach

`scripts/e2e/ground_rehearsal.sh`, header `bead=N30b-31 milestone=M5 labels=ground,e2e gates=GATE-GROUND-03
seed=1 needs=cpu,mcp
plants=truth-in-bundle,score-reads-calibration,band-keyed-by-design,monitor-resets,asbuilt-residual-as-uncertainty`.
It sources `scripts/e2e/lib.sh`, runs in the run's own state root (the fresh `FROB_STATE` that `e2e_init`
exports) and is idempotent. Every call of a `run` or `mutate` verb (`ingest`, `identify`, `predict`, `score`,
`kit`) carries its own idempotency key, written `--key "$(e2e_key <label>)"` and shown below as `--key <k>`;
without it the call would be refused with FROB-REF-805.

**The registry examples** (step `examples`; the registry bead states that each example of the cluster runs on
the rehearsal and names this script as the place where that is asserted). The examples tell one story: the
design `cart-a` with its card set `drive-60` on the stand rig `stand-A` (bundle directory `stand-A-01/`,
dataset `ds:stand-A-01`), and the sill crossing (scene `sill-12mm`, task `sill-crossing`, dataset
`ds:sill-day-3`, cell `c:9f2c41`, prediction `pred:b3:11a0`, score `sc:4e1`, kit directory `kit/`). DESIGN, so
that each example runs: before the step, the script stores the rehearsal's objects under those names in its
own state root and working directory. The nominal rig of R-04 supplies the design, the card set, the rig and
the bundle `stand-A-01/` (a bench bundle, hence the example's `--task-family tf:none`); the dataset, cell,
prediction and score that the `predict`, `score` and `band` steps produced stand for `ds:sill-day-3`,
`c:9f2c41`, `pred:b3:11a0` and `sc:4e1`, and that prediction's scene and task are stored under the names
`sill-12mm` and `sill-crossing`, with `crossing_time_s` among its registered metrics so that the `predict`
and `band` examples name a metric the cell has. The five abbreviated identities are resolved by the harness's rule for example identities: this bead adds their
rows to `fixtures/verbs/identities.toml` (abbreviation, kind, the full identity, `stored_by =
"ground_rehearsal.sh"`, milestone M5), the full identities being the ones the seed-1 rehearsal produces on the
recorded platform; each example is run with the abbreviation replaced by the full identity and nothing else
changed, and both lines are logged (`example`, `resolved`). On a platform where the rehearsal's identities
differ (the generator is class D3 across platforms), or for a name the rehearsal cannot supply, the example is
logged as one `assert` with `status: "skip"` naming the example and the reason, and counted in the summary's
skipped assertions: a skip is never a pass.

Log: `target/e2e-logs/ground_rehearsal/<utc-timestamp>.ndjson` and a transcript beside it. Every line has `ts`,
`script`, `bead`, `step`, `event`, the exact command, exit code, wall time and the envelope's evidence block
(claim, class, tier, determinism, identities, seed); each assertion logs the planted value (read from the truth
file by the harness, never by `frob`), the recovered value, the tolerance and the unit; each refusal logs code,
pointer, observed, required and repairs; digests are logged where state is compared (content addresses of
cards before and after, the randomization block, dataset ids). On failure the line names the first differing
value and the paths of the bundle and truth file needed to reproduce. The final `summary` gives assertions
passed and failed and the gates touched. Every line carries `synthetic: true`.

The script touches the known-answer rows of every Ground gate from the second to the ninth and writes no gate
record (a script never does: each gate has one recorder, and GATE-GROUND-03's is N30a-19, from its tier run's
receipt). It re-asserts the eight-alias row in its `excite` step, tagging those assertions `--gate
GATE-GROUND-03 --ka KA-722`, and leaves the statistical thresholds to the batteries.

## Acceptance criteria

- [ ] The script exits 0 on a correct build: every row of the table asserts, and the sweep finds no envelope
      with a status other than `synthetic` or a class other than Estimated.
- [ ] All seven verbs are called; `ground_predict`, `ground_score` and `ground_band` are also called through
      `frob-mcp` and return envelopes equal to the CLI's apart from transport fields.
- [ ] With `E2E_PLANT_FAILURE` set to each of: `truth-in-bundle`, `score-reads-calibration`,
      `band-keyed-by-design`, `monitor-resets`, `asbuilt-residual-as-uncertainty`, the script exits non-zero and
      names the step.
- [ ] Two runs with one seed produce logs that differ only in timestamps and wall times.
- [ ] Runtime under 30 minutes on the CPU with the single nominal rig (TARGET); the 100-rig population is not
      part of this script.
- [ ] Every `run` and `mutate` call in the log carries `--key`, and no key is issued twice; the log holds no
      `frob-conformance` command and no `record_gate` command (the conformance crate's command-form lint and
      the harness lint `self-recording` pass).
- [ ] The one-pulse ingest is asserted in its exit-2 form (dataset admitted, 876 in `clocks[0].refused`), not
      as a refused call.
- [ ] Step `examples` runs each of the seven registry examples after the identity substitution, with the
      five rows of this cluster present in `fixtures/verbs/identities.toml`; each returned envelope has class
      Estimated and reality `synthetic`; an example that could not run appears as a logged skip with its
      reason and is listed in the summary.

## Test plan

### Unit tests

`crates/frob-conformance/tests/ground_rehearsal_table.rs`: `rows_cover_ka_721_to_734_and_736` (each
known-answer identifier appears in exactly one step); `truth_read_only_by_harness`;
`plants_registered_for_verify_plants`; `ground_example_identities_have_rows` (the five abbreviations of the
cluster's registry examples each have a row of `fixtures/verbs/identities.toml` with a full identity of the
right kind; a planted example naming an abbreviation with no row is reported `example-unresolved`).

### End-to-end script and logging

This bead is the script; see the technical approach. `scripts/e2e/run-all.sh --milestone M5 --label ground`
runs it with the six batteries, and `--verify-plants` checks each plant.

### Known answers and negative controls

KA-721 to KA-734 and KA-736, with the values in the table. CX-326 to CX-334 as the plants and refusals named.
Metamorphic check inside the script: rerunning `identify` on the same record with the experiments listed in
reverse order yields posteriors that agree within their own standard errors. Determinism lanes: twice on one
machine; debug and release; the other platform in class D3 (record, compare inside the envelope).

## Considerations

- The script proves a bounded loop is sound and nothing more; its last log line says so in words, and the
  Reality claim stays `no-claim`.
- Order matters and is part of what is tested: running `band` before `score`, or `identify --stage contact`
  before actuators, must be refused, and the script includes those two out-of-order calls.
- If a kill gate of the subsystem has fired, the corresponding step asserts the fallback's behaviour instead
  (for example time-free metrics only), keyed on the kill gate's row in the registry.
