## Background

GATE-GROUND-05 is the gate of the protocol that makes a comparison with reality mean something. In Ground, the
subsystem that compares simulation with measured reality, the validation and holdout parts of every dataset
are sealed at admission; a prediction is frozen in the ledger before the seal is opened; `ground.score` is the
only reader, once; and a scored holdout is spent. The gate (claim kind: Known answer; TARGET): the
freeze-before-read order holds for every trial; the three protocol mutations are refused. The mutations are:
a read before a prediction is frozen; a refit scored without a new prediction version; reuse of a spent
holdout.

A unit test can show that each guard refuses. Only a run from the outside, trying every read path a script or
an agent could reach, shows that there is no way around them. This script is that attack, on the synthetic
rehearsal. Its record is read by the kill decision KILL-CLOCK, whose trigger includes a failure of this gate.

## Scope

In: the script; the order check over every trial; the three mutations and their variants; the crash lane; the
log and the gate record. Out: the mechanisms (BD-387 for sealing, BD-392 for prediction, N30b-06 for scoring).

## Technical approach

`scripts/e2e/ground_predict_score.sh`, header `bead=N30b-33 milestone=M5 labels=ground,e2e,gate seed=1`. It
sources `scripts/e2e/lib.sh` and works in a fresh store on fixtures R-04 (nominal rig), R-06 (omitted law),
R-12 (reachability) and R-14 (protocol) of the rehearsal.

1. **Step `order`.** For every trial in the sealed validation and holdout parts (all fixtures):
   `frob ground predict … --json`, then `frob ground score <prediction> --json`. From the two envelopes and
   from `frob evidence trace` on the score, read the ledger sequence of `ground.prediction.frozen` and of the
   first `ground.sealed.read` for the same chunk hashes; assert freeze < read. `e2e_metric
   order_violations <count> trials == 0 --gate GATE-GROUND-05`, with the number of trials logged.
2. **Step `mutation-read-before-freeze`.** On an unpredicted sealed part, attempt each read path:
   `frob artifact read <chunk-digest>`, `frob run export <run>`, `frob telemetry query …` over the sealed
   trials, the HTML replay export, and `frob ground score` with a prediction identifier that does not exist.
   Each: `e2e_expect_refusal FROB-REF-883 3 -- …`. Then freeze a prediction and confirm the read event's
   sequence is larger than any of the refused attempts' sequences (the attempts were logged, not served).
3. **Step `mutation-refit-without-version`.** Score a prediction; refit the cards with
   `frob ground identify`; attempt (a) to score the old prediction record again with the refitted cards named,
   (b) to register a "version 1" with changed intervals under the old identifier, (c) to register version 2
   against the already-read chunks. Each refused with FROB-REF-883. Then register version 2 against fresh
   sealed chunks: accepted, with `supersedes` set and the old version still listed as scored.
4. **Step `mutation-holdout-reuse`.** Call `frob ground score` twice on one holdout (second:
   `e2e_expect_refusal FROB-REF-886 3`); once more after a refit, same lineage (886); and ingest a new dataset
   that declares the spent chunk as its holdout (886 at admission).
5. **Step `registration-rules`.** A claim of "failure rate under 5%" at n = 20 is refused at registration with
   the reachability refusal and n = 59 in the payload; a study declaring both types is refused; a tolerance
   with no unit is refused.
6. **Step `sealing-matters`.** On R-06: the omitted-law candidate is rejected by the real scorer;
   `e2e_expect_caught NC-GROUND-0331 -- …` runs the mutant scorer that reads the calibration split and shows the
   same candidate passing.
7. **Step `crash`.** With the fault-injection build: kill the process at each await point between the spend
   event and the score record; after restart, `frob job find` by idempotency key and re-issue the call; assert
   the holdout is spent exactly once, the score equals the uninterrupted score, and no sealed byte was returned
   by any call that has no spend event.
8. **Step `record`.** `e2e_gate GATE-GROUND-05`; `e2e_metric mutations_refused <count> mutations == 3
   --gate GATE-GROUND-05`.

Log: `target/e2e-logs/ground_predict_score/<utc-timestamp>.ndjson` and a transcript. Per trial: prediction
identifier and hash, freeze sequence, read sequence, their difference. Per attack: the command, the read path
attacked, exit code, refusal code, pointer and repairs, and the ledger sequence at which the attempt was
logged. Per crash point: the await point's name, the state found after restart. Evidence blocks on every line
(class Estimated, reality `synthetic`). On failure: the first trial whose order is wrong, or the first attack
that returned data, with the chunk digest and the path used. Summary: assertions passed and failed and
`gates: ["GATE-GROUND-05"]`.

## Acceptance criteria

- [ ] The script exits 0 when the order holds on every trial and every attack is refused; non-zero otherwise.
- [ ] The gate record holds: trials checked, order violations (zero), mutations refused (three of three), read
      paths attacked (count), crash points exercised (count), controls caught.
- [ ] With `E2E_PLANT_FAILURE=sealed-guard-off` the read-before-freeze step fails and names the path;
      with `spent-table-by-version` the reuse-after-refit attack succeeds and the script fails;
      with `record-rewrite-allowed` the refit step fails.
- [ ] No sealed sample value appears anywhere in the log (a lint over the log checks that only identifiers,
      counts and digests are present).
- [ ] The record is written by a session that did not implement the measured beads.

## Considerations

- The list of read paths is generated from the registry so that a read verb added later is attacked without
  anyone remembering to add it.
- The script never needs to open a sealed chunk outside `ground.score`; if a future assertion seems to need
  it, the assertion is wrong.
- A failure of this gate fires KILL-CLOCK as registered, and the kill decision adds a fail-closed suspension of
  admission until the invariant's own test passes again.
