## Background

A refusal is the system declining to produce a result that would mislead, with a stable code, a message and
ranked repairs. Ground, the subsystem that compares simulation with measured reality, defines eleven codes,
all in the evidence-and-protocol family, all with exit code 3 as refused calls (one of them, 876, also
appears inside a completed `ground.ingest` result, below): FROB-REF-873 (a dataset lacking licence,
provenance, rights or measurement uncertainty), -876 (clock alignment under-determined, or a scored instant
outside the bracket), -879 (a fit on a parameter set that fails identifiability), -883 (a read of sealed data
with no frozen prediction, or a prediction changed after freezing), -886 (reuse of a spent holdout), -889 (a
band for an uncalibrated cell, or with too few calibration points), -895 (a band for a design that was never
built), -897 (use of a retired calibration), -899 (a private or non-redistributable input to a kit), -812 (an
as-built registration that is ill-posed or below its noise screen) and -814 (pooling across cells, across
model identities, or of synthetic with real data).

The registry bead enters the rows and the mechanism beads raise the codes. This bead is the battery that shows,
from the user's side, that each code fires on the condition its row states, with the payload and repairs its
row states, on both surfaces, and that it does not fire on the nearest legal input. The second half matters as
much as the first: a guard that refuses everything is easy to write and useless, so every planted violation
has a **clean twin** that differs only in the violated condition and must be accepted.

## Scope

In: the script; at least three planted violations and one clean twin per code; payload and repair-order
checks; both surfaces; the stale-number check; the edited-class attempt. Out: the registry rows (N30-REF); the
fifty misuses of the reality line (N30b-01); the protocol attack on sealed data in depth (N30a-35).

## Technical approach

`scripts/e2e/ground_refusals.sh`, header `bead=N30b-37 milestone=M5 labels=ground,e2e seed=1 needs=cpu,mcp
plants=guard-873-off,guard-876-off,guard-879-off,guard-883-off,guard-886-off,guard-889-off,guard-895-off,guard-897-off,guard-899-off,guard-812-off,guard-814-off,refuse-everything`.
It sources `scripts/e2e/lib.sh` and builds its inputs from the synthetic rehearsal with this bead's example
target, `cargo run -p frob-conformance --example ground_refusal_cases -- plant <case> --out <dir>`
(`examples/ground_refusal_cases.rs`, declared here: a thin argument parser over the library module
`frob_conformance::ground_refusal_cases`, which holds the case table and builds each case as a small mutation
of a legal input; it prints one JSON object with the case, its twin, the paths written and the commands to
run). The conformance crate has no binary named `frob-conformance`, which an earlier text of this bead
called.

For each planted violation: `e2e_expect_refusal <code> 3 -- <command>`, then `e2e_assert_json` on `pointer`,
`observed`, `required` and `retry == "after-change"`, and `e2e_assert_repairs_order` against the registry row.
The three clock cases at `ground.ingest` are not refused calls, so they are asserted in the form the registry
gives them: `e2e_cmd --expect-exit 2 -- <command>`, then `e2e_assert_json` that `ok` is true, that the
dataset identity is present, that `/result/clocks/0/refused/code` is `FROB-REF-876` with its pointer, marks
present, marks needed and repairs, and that the envelope's own `refusal` is empty.
For each clean twin: `e2e_cmd --expect-exit 0,2,8 -- <command>` and an assertion that `ok` is true (or a job
handle is returned). Every call of a `run` or `mutate` verb, refused or not, carries its own key (`--key
"$(e2e_key <case>)"`), so that the refusal observed is the one under test and never FROB-REF-805. One violation per code is repeated through `frob-mcp`: the tool result has `isError: true`
and its structured content equals the CLI envelope apart from transport fields.

Three further steps. **`stale-numbers`:** `frob schema ground.band` and every other `ground` verb list no code
in 840 to 850. **`edited-class`:** a Ground envelope edited to class `Tested` is offered to a consuming verb
and refused with FROB-REF-834 (a result presented above the class of its weakest input), exit 3. **`no-override`:** `frob ground kit build … --allow-private`
and `--force` are refused as unknown parameters (`e2e_expect_refusal FROB-REF-802 3`, the pointer naming the
option), each call with its own key.

Log: `target/e2e-logs/ground_refusals/<utc-timestamp>.ndjson` and a transcript. Per case: the case identifier,
the mutation applied, the command, exit code, the refusal's code, message, pointer, observed, required, retry
and repairs, the expected values from the registry, and the surface. Per clean twin: the command, exit code and
`ok`. Evidence blocks on every line (reality `synthetic`). On failure: the case, the observed against expected
code or payload field, and the path of the planted input. Summary: counts of violations refused, twins
accepted, and codes covered (eleven).

## Acceptance criteria

- [ ] Every planted violation is refused with its code and exit 3, on the CLI, and the repeated ones on MCP,
      except the three clock cases at `ground.ingest`, which complete with exit 2 and carry the 876 object in
      `clocks[i].refused`; at least three violations per code, 46 or more in all.
- [ ] The stage-order case of 879 carries pointer `stage` and its two repairs in order, and both of its twins
      are accepted; the 883 case at `ground.ingest` is refused and its twin admitted.
- [ ] Every clean twin is accepted.
- [ ] Payload fields and repair order equal the registry rows for every code.
- [ ] No `ground` verb's schema lists a code in 840 to 850.
- [ ] With `E2E_PLANT_FAILURE` set to `guard-<code>-off` for any of the eleven codes, the script exits non-zero
      and names the first violation that was accepted; with `refuse-everything` it exits non-zero on the first
      clean twin.
- [ ] Two runs produce logs that differ only in timestamps.

## Test plan

### Unit tests

`crates/frob-conformance/tests/ground_refusal_cases.rs`: `eleven_codes_covered`; `at_least_three_cases_per_code`;
`every_case_has_a_clean_twin`; `twin_differs_only_in_violated_condition` (a structural diff of each pair of
planted inputs has exactly one changed field or record); `cases_are_deterministic`;
`ingest_clock_cases_expect_exit_2` (the three 876 cases at `ground.ingest` are marked as completed calls with
the refusal object in `clocks[i].refused`, and the two at `ground.score` as refused calls);
`stage_order_and_sealed_redeclare_cases_present` (the 879 case with pointer `stage` and its two twins; the
883 case at `ground.ingest`); `example_prints_one_json_object` (the example target on every case).

### End-to-end script and logging

This bead is the script; see the technical approach.

### Known answers and negative controls

Payload values: 0, 8 and 18 present against 19 needed; 3 units against 9; marks 1 against 2; k against k + 1;
for the stage-order case, `observed` "actuators: no record".
Negative controls: the eleven `guard-off` plants and the `refuse-everything` plant. The clean twins are the
controls against over-refusal.

## Considerations

- Some violations can be reached through more than one verb; the table names the verb the registry lists
  first, and the per-verb refusal lists are checked in both directions by the registry bead's unit test.
- Refusals are logged by the system as well as returned; the script also checks that each refused attempt on
  sealed data left a ledger entry.
- Cases needing retired cells or spent holdouts build that state through the real verbs on rehearsal data,
  never by editing the store.
