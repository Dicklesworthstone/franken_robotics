## Background

The structure loop is the path from a qualified design to a link geometry whose mass the robot was simulated
with:

```
 qualified design ─► load campaign (T2 telemetry) ─► load cases and spectra ─► size (beam rung)
        ▲                                                                          │
        │                                                        finalists only    ▼
        │                                                              optimize (topology rung)
        │                                                                          │
        │            independent check: stress, buckling, modes, fatigue  ◄────────┘
        │                         │
        └── typed edit: new mass, centre of mass, inertia          repeat until the convergence test passes
                                  │
                                  ▼
          manufacturability ─► tolerances ─► export ─► .fbuild (flags false) ─► as-built scan
```

It is a loop because the two quantities feed each other: structural mass of a link sized to a stress cap grows
with the loads, and the loads grow with total mass. A link sized for the loads of the old, heavier or lighter
robot is sized for a robot that no longer exists. The loop therefore edits the design with the new mass
properties, re-synthesizes the baseline controller, re-runs the same load campaign on the same worlds, and
repeats until a convergence test passes or refuses.

The mechanisms of each box are separate beads. This bead is the machine that sequences them, keeps the
iterations paired, records what happened, and can be cancelled and resumed. It is the body of the verb
`foundry.optimize` ("topology optimization of link classes with the loads–mass loop").

Two rungs (ADR-FOUNDRY-02): closed-form beam sizing by default and as fallback; three-dimensional topology
optimization for finalists. If the topology rung is killed (KILL-TOPOPT: the stage-2 comparison saves under 7%,
does not converge, or exceeds its budget), beam-rung sizing supplies the mass and inertia feedback and the
machine is unchanged.

## Scope

In: the stage machine, the rung interface, the per-iteration record, pairing of campaigns across iterations,
parallelism across link classes, budgets, cancellation and resume, the loop record written for the packet.
Out: every stage's mathematics (campaign N31a-06; envelope cases N31a-10; beam rung BD-401; topology N31a-15;
independent check N31a-19 to N31a-21; mass properties and typed edit N31a-23; convergence test N31a-24); the
outer actuator re-selection step (N31a-25); the stages after convergence (manufacturability, tolerances,
export), which are separate verbs that read this bead's record.

## Technical approach

1. **Stages** (`structure_loop.rs`, DESIGN). One iteration k on design d_k:
   1. `Admit` (once): qualification verdict or exploratory label (N31a-03).
   2. `Controller`: for k ≥ 1, re-synthesize the baseline controller for d_k. An outcome other than success
      stops the loop with the controller's own refusal attached; a structure result under a controller that
      could not be synthesized is not produced.
   3. `Campaign`: run the load campaign for d_k with the campaign specification fixed at k = 0: same task set,
      same world addresses, same tier and profile, T2 on every world.
   4. `Extract`: free-body check, envelope cases per link class, spectra at gauges.
   5. `Size`: the rung produces a candidate geometry per link class. Rung `beam`: lightest stock section
      passing every envelope case. Rung `topology`: the optimized surface; the beam-rung section is still
      computed, as the engineered baseline every optimized part is judged against.
   6. `Check`: independent stress, buckling, modal and fatigue check of the candidate under this iteration's
      loads. A failed check on an optimized part is refusal FROB-REF-261 for that link class; the machine
      applies the rung's repair once (tighter stress cap or length scale) and otherwise falls back to the beam
      section for that class, recording the fallback.
   7. `Feedback`: mass, centre of mass and inertia of the checked geometry become a typed edit; the result is
      d_{k+1}, a new `DesignId`.
   8. `Test`: the convergence test on the vector x_k of link masses and principal inertias. Outcomes:
      `continue`, `converged`, `diverged` or `cycling` (refusal FROB-REF-260), `budget-exhausted` (FROB-REF-260).
2. **Rung interface.**
   ```rust
   pub trait Rung { fn size(&self, class: &LinkClass, loads: &EnvelopeSet, prev: Option<&Candidate>, cx: &JobCx)
                        -> Result<Candidate, Refusal>; }
   pub struct Candidate { geometry: GeometryRef, baseline: BeamSection, provenance: Provenance /* Beam | Optimized */ }
   ```
3. **Pairing.** The map G from x_k to x_{k+1} is deterministic only because the campaign reuses its world
   addresses: randomness is drawn by address, so two designs given the same addresses see the same worlds. The
   machine refuses to start an iteration whose campaign specification hash differs from iteration 0. With
   fresh random worlds each iteration, sampling noise sets a floor above the 2% tolerance and the convergence
   test cannot pass; that configuration is kept as a registered negative control.
4. **Budgets (TARGET, unmeasured).** At most five iterations. Topology rung: at most 120 s per unique link
   class for the coarse solve and 10 minutes for a finalist solve on the CPU cores of the M5 Ultra. A symmetric
   quadruped has three to five link classes. Classes run in parallel as separate sibling jobs; iterations are
   sequential. Each stage reports wall time and CPU core-seconds; a class over budget is reported, not killed
   silently: the stage ends with `over-budget` and the gate record shows it.
5. **Job record and resume.** State lives in the daemon's job ledger. Each completed stage writes a
   content-addressed stage record (inputs' hashes, outputs' hashes, labels, cost). Resume after a crash or a
   cancellation restarts at the first stage without a record; a stage record whose input hashes do not match is
   discarded. Stage records of iteration k are immutable once iteration k + 1 starts.
6. **Cancellation.** Requested at any time; honoured at stage boundaries and inside a campaign at the
   kernel-batch boundary, and inside a sibling job at that job's boundary (a worker job is abandoned and its
   partial output discarded). The receipt names the last completed stage and iteration. No partial geometry or
   partial edit is published.
7. **The loop record** (`structure/loop.json` in a packet; schema `frob.foundry.loop/1`, DESIGN): campaign
   specification hash; per iteration: design and model identities, controller identity, x_k, Δ_k, λ̂_k, the
   a-posteriori bound, envelope movement, check results, labels, cost; the final outcome and its reason;
   whether Aitken or the under-relaxed step proposed any iterate. Every number carries class Estimated.
8. **Output of the verb.** The final design identity, per link class the candidate with its mass against the
   beam baseline, the loop record, the ceiling line (N31a-02), and next actions (qualify the final design;
   `foundry.check`; `foundry.export`).

## Acceptance criteria

- [ ] On the synthetic planted-gain rung (link mass S = A + λ·(M₀ + S) with A = 0.6 kg, λ = 0.15, M₀ = 12 kg, start 4.0 kg) the machine produces iterates 3.0, 2.85, 2.8275, 2.8241 and stops `converged` within five iterations.
- [ ] With λ = 1.1 the machine stops with FROB-REF-260 `diverged` within three iterations and names the beam rung as the repair.
- [ ] An iteration whose campaign specification differs from iteration 0 is refused before any simulation.
- [ ] Kill the job after each of the eight stages in turn: resume completes with the same final record hash as an uninterrupted run (same machine).
- [ ] Cancellation mid-campaign leaves no stage record for that stage and no new design in the lineage graph.
- [ ] A failed controller re-synthesis stops the loop with that refusal and no structure result.
- [ ] With rung `topology` unavailable (feature off or KILL-TOPOPT in force), `foundry.optimize` runs the beam rung and says so in the result.
- [ ] The stage-2 comparison of GATE-FOUNDRY-05 is runnable through this machine: it records saving against the beam baseline, the convergence outcome and the coarse-solve time per link class.

## Test plan

### Unit tests
`cargo test -p frob-foundry structure_loop` (real machine, `synthetic` rungs and a `synthetic` campaign stage
that maps masses to loads by the linear law):
- `planted_gain_converges_in_budget`; `divergent_gain_refused_260`; `two_size_cycle_detected`.
- `campaign_spec_must_match_iteration_zero`.
- `resume_after_each_stage_is_identical` (eight kill points).
- `cancel_publishes_nothing`.
- `check_failure_applies_repair_once_then_beam_fallback`: a rung that always fails the check ends with every class on the beam section and the fallback recorded.
- `controller_failure_stops_loop`.
- `classes_run_in_parallel_iterations_in_series`: record timestamps show overlap across classes and none across iterations.
- Planted defects, each caught: `fresh-worlds-each-iteration` (the convergence test never passes; the test asserts the floor above 2%), `reuse-stale-stage-record` (resume accepts a record with mismatched input hash).

### End-to-end script and logging
`scripts/e2e/foundry_structure_loop.sh` (bead N31a-54) drives `frob foundry optimize` on the reference
quadruped fixture and on the planted-gain fixture and logs per iteration x_k, Δ_k, λ̂_k and stage timings.

### Known answers and negative controls
Loads–mass loop (KA-743): iterates 3.0, 2.85, 2.8275, 2.8241, 2.8236; fixed point 2.8235 kg; λ̂ = 0.15;
control: λ = 1.1 is refused as divergent within three iterations, and a planted two-size cycle is detected.
Determinism: the loop record is bitwise identical twice on one machine and across worker counts; across
platforms only the D0 parts (the planted-gain fixture in rationals) are compared.

## Considerations

- KILL-TOPOPT (decided at M5): trigger GATE-FOUNDRY-05 fails (saving under 7%, no convergence, or over
  budget); fallback: beam-rung sizing supplies mass and inertia feedback, three-dimensional optimization becomes
  an offline option or is dropped, and analysis A-15 is unaffected. The rung interface is what makes the
  fallback a configuration change.
- Each iteration costs a campaign plus solves. Referee re-extraction of envelope cases (a rule owned by unit
  U31b) adds 108 to 180 referee-seconds of simulated time per iteration on a symmetric quadruped.
- Actuator cards are held fixed inside this loop (ADR-FOUNDRY-07); the machine refuses an edit proposal that
  changes an actuator binding between iterations.
- The loop's result is a new design that has no qualification verdict yet (N31a-03).
