## Background

An optimizer or a sizing routine can afford a handful of load cases per link, not millions of samples. The
question is which handful. The tempting answer is to take the peak of every load channel over the campaign and
assemble the peaks into one case. It is wrong in both directions.

**Counterexample (CX-336, known answer KA-740).** A simply supported beam of span L carries a load P at L/3 at
one instant and P at 2L/3 at another. The mid-span moment is P·L/6 each time. Assembling both peaks into one
case gives P·L/3, a twofold over-design. If the second load has the opposite sign, the assembled case gives
zero while each real case gives ±P·L/6: **the assembled case is unsafe.**

Hence ADR-FOUNDRY-03: **a load case is one instant of one episode. Peaks from different instants are never
assembled.** Invariant INV-FOUNDRY-02 states it for testing: a load case is a single instant of a single
episode at a recorded world address, and each case replays to its sample.

**Envelope cases** drive optimization. For a fixed, deterministic set of directions in scaled load space, the
case is the sample that maximizes the projection; every case is a real instant with all ports and the body
field taken from the same sample. This keeps what the peak-assembly rule was after (the extreme of each load
component is represented) without inventing a load state the robot was never in.

Refusal FROB-REF-167, first half: a load case that is not one instant is refused, and the repair is the list of
offending samples. GATE-FOUNDRY-02 includes "the assembled-peak mutation refused".

## Scope

In: the scale vector; the direction sets; selection by maximum projection with a deterministic tie rule; the
case record; replay verification; the reader that refuses a case not equal to one sample; de-duplication.
Out: union over symmetric limbs (N31a-11); variants and the `model-conditional` label (N31a-12); per-gauge
governing instants (N31a-09); the referee re-extraction rule (unit U31b); hand-declared cases, which are a
different type (N31a-13).

## Technical approach

1. **Scaled load space.** Load coordinates ℓ ∈ ℝⁿ (n = 18 for a two-port link, 24 for three ports) have mixed
   units. The scale s_j is the campaign maximum of |ℓ_j| for the link class at iteration 0 of the structure
   loop, frozen in the campaign record and reused in every later iteration, so the direction set means the
   same thing throughout the loop (DESIGN). A coordinate with s_j = 0 is removed from the direction set and
   listed. Scaled sample: z = ℓ ⊘ s.
2. **Direction sets** (`loads/envelope.rs`, DESIGN):
   - `axes` (default): the 2n signed coordinate directions ±e_j; 36 for a two-port link;
   - `axes+pairs`: adds (±e_i ± e_j)/√2 for i < j; 2n + 2n·(n − 1) = 648 directions for n = 18;
   - `custom`: a file of unit vectors with a content hash.
   The set is identified by name and hash; it is never random.
3. **Selection.** For direction d the case is the sample maximizing d·z over all admitted samples of the class
   (free-body check passed, not off-port). Ties are broken by duty order: the earliest sample wins. One pass
   over the stream keeps the running best per direction; memory is O(directions).
4. **Case record** (schema `frob.foundry.case/1`):
   ```rust
   pub struct EnvelopeCase {
       class: LinkClassId, instance: BodyId,          // which limb the instant came from
       directions: Vec<DirectionId>, projection: Vec<f64>,
       load: LinkLoad,                                 // addr, tick, side, ports, a0, alpha, omega, model
       variant: ContactVariant, labels: Vec<StructLabel>,
       trace_digest: Blake3,                           // digest of the T2 record at (addr, tick)
       scale_hash: Blake3, direction_set: (String, Blake3),
   }
   ```
   A sample that wins several directions is stored once with all of them.
5. **Replay verification (INV-FOUNDRY-02).** `verify_case(case)` replays the world at `load.addr` to
   `load.tick` on the backend that produced it and compares the T2 record digest with `trace_digest`. The
   envelope stage verifies every case before returning; consumers may call it again.
6. **The reader refuses anything that is not one instant.** Load cases enter the optimizer, the sizing routine
   and the check only through `EnvelopeSet::read`, which for every case looks up the trace record at
   (addr, tick) and requires every port wrench and the body field to equal it bit for bit. A case with no
   address, with components matching different ticks, or matching no tick at all → FROB-REF-167 with payload:
   the case, and for each component the nearest tick at which that component alone occurs (which makes an
   assembled case recognizable as such). Exit code 3; `retry: never` for that file.
7. **Output of `foundry.loads`.** Per link class: the scale vector, the direction set, the cases with
   projections, and the count of distinct instants.
8. **Class.** Estimated; tier and determinism from the campaign. Cases from a fast tier are `provisional`
   until re-extracted on the referee; the record carries what that rule needs.

## Acceptance criteria

- [ ] On the simply supported span fixture (P at L/3 at tick 1 and at 2L/3 at tick 2) the envelope holds the two real instants, each with mid-span moment P·L/6, and no case with P·L/3.
- [ ] GATE-FOUNDRY-02: the assembling mutation (per-channel peaks written as one case) is refused by the reader with FROB-REF-167, and the payload shows the two different ticks its components came from.
- [ ] With opposite signs the two real cases are both present (±P·L/6); the assembled case, which sums to zero load at mid-span, is refused.
- [ ] Every envelope case replays to its sample (digest equality), for every case of the reference campaign.
- [ ] The default set gives at most 2n cases per class; the same campaign read twice gives identical case files.
- [ ] A tie between two samples is resolved to the earlier one; changing the chunk size does not change any case.
- [ ] The scale vector of iteration 0 is reused at iteration 1; an attempt to rescale mid-loop is refused.

## Test plan

### Unit tests
`cargo test -p frob-foundry loads::envelope`:
- `span_two_instants`: L = 0.3 m, P = 60 N: each instant gives mid-span moment 60 × 0.3/6 = 3.0 N·m; the assembled case would give 6.0 N·m; with opposite signs it would give 0.
- `argmax_per_direction` on a 1,000-sample seeded stream against a brute-force oracle.
- `tie_goes_to_earliest`.
- `axes_count_is_2n` (36 and 48); `axes_plus_pairs_count` (648 for n = 18).
- `zero_scale_coordinate_removed_and_listed`.
- `reader_refuses_assembled_167`; `reader_refuses_addressless_167`; `reader_refuses_perturbed_wrench_167` (one unit in the last place changed).
- `replay_digest_matches` on a recorded `synthetic` world.
- `dedup_multi_direction_winner`.
- `scale_frozen_across_iterations`.
- Planted defects, each caught: `assemble-peaks` (the registered mutation), `argmax-of-absolute-value` (selects by |d·z| and loses the sign), `rescale-per-iteration`.

### End-to-end script and logging
`scripts/e2e/foundry_loads.sh` (N31a-53): after a campaign, writes a mutated load file with per-channel peaks,
feeds it to `frob foundry size --loads <file>` and asserts exit 3 with `FROB-REF-167`; replays three cases
with `frob sim replay` and asserts the digests; logs per class n, directions, distinct instants and the largest
projection per direction.

### Known answers and negative controls
KA-740 (assembled peaks: P·L/6 per instant; assembled P·L/3 or 0; control: the assembling mutation is
refused). CX-336 is the same case as a counterexample. Negative controls: the three planted defects.
Metamorphic: permuting the order of directions permutes the cases and changes nothing else; adding a sample
with smaller projection in every direction changes no case. Determinism: case files are bitwise identical
twice on one machine, across worker counts and chunk sizes.

## Considerations

- A direction set cannot guarantee that the governing stress state is among the cases. That is why the check
  adds each gauge's governing instants from the influence matrix, and why the check runs on the final geometry
  with all of them.
- Scaling by campaign maxima makes the cases depend on the campaign's extremes; this is intended, and the
  frozen scale keeps the loop's map deterministic.
- 2n referee windows of 1 s per link class is the cost the referee re-extraction rule pays per iteration
  (36 windows for a two-port link).
- KILL-LOADS fallback: with declared cases there is no envelope selection; the declared set is used as given
  and labelled.
