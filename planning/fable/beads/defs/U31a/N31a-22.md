## Background

Every structural number Foundry prints rests on material data: a modulus, a yield strength, a stress-life
curve. In this program a card creates one claim product per field from that field's provenance, so that a
single assumed number is visible as the weakest input of everything built on it. Foundry adds the rule that a
check does not run on data that is missing or does not apply to the part in front of it.

Refusal FROB-REF-163: **a check whose material card lacks the field or provenance it needs.** Repair offered:
the missing field; `fatigue: no-claim`.

The fatigue rule is the sharpest case: **the curve must be valid for the material state, the process and the
surface finish. Otherwise the result is `fatigue: no-claim`.** A stress-life curve measured on polished
wrought bar says little about an as-printed part with a rough surface and a build direction, and the sibling's
fatigue module says of itself that calibration for printed and cast material is whatever a card supplies and
that it is an empirical baseline, "not a validated component-life claim". OPEN-FOUNDRY-4 (stress-life data for
printed material by process and orientation) is undecided; its fail-closed default is `fatigue: no-claim` for
printed parts, and it blocks the fatigue leg of GATE-FOUNDRY-05 for printed fixtures only.

The alternative of applying knock-down factors to a wrought curve when no printed curve exists was rejected:
it produces a number, and the number would be read.

## Scope

In: the `structure` section of the material card; what each check requires; the validity test between a part's
declaration and a curve's stated domain; the two outcomes (refusal, or `no-claim` on fatigue alone); provenance
and strict-data handling; the claim-product leaf per field.
Out: the card format's base and catalogue (BD-069, BD-068); the checks that consume the fields (BD-401,
N31a-19 to N31a-21); process cards (N31a-26); lifecycle law coefficients (N31a-48).

## Technical approach

1. **Fields** (`check/card.rs`; section `structure` of a material card, DESIGN):
   ```toml
   [structure]
   state = "6061-T6 wrought"                 # material state (temper, heat treatment)
   E_Pa = { value = 6.9e10, provenance = "datasheet", source = "…" }
   nu = { value = 0.33, provenance = "datasheet" }
   density_kg_m3 = { value = 2700, rel_uncertainty = 0.01, provenance = "datasheet" }
   yield_Pa = { value = 2.76e8, provenance = "datasheet" }
   criterion = "von-mises"                   # or a named alternative for brittle or anisotropic material
   wall_buckling_knockdown = { value = 0.5, provenance = "generic" }
   anisotropy = "isotropic"                  # or a material frame and its constants
   [[structure.sn_curve]]
   law = "basquin"
   S0_Pa = …                                 # N = (S/S0)^(−m) at the reference stress ratio
   m = …
   reference_R = -1
   cycles_valid = [1e3, 1e8]
   mean_stress = "goodman"                   # named correction, or "none"
   cutoff = "none"                           # or "knee" with a second slope, or "hard"
   scatter_factor = 4
   valid_for = [ { state = "6061-T6 wrought", process = ["cnc-3axis", "cnc-5axis"],
                   finish = ["machined"], orientation = "any" } ]
   provenance = "datasheet"
   source = "…"
   ```
2. **Requirements per check.**

   | Check | Required fields |
   |---|---|
   | Beam rung, stress | E, ν, yield, criterion |
   | Column and wall buckling | E, ν, knock-down (beam rung only) |
   | Modes, mass feedback | E, density |
   | Fatigue | a stress-life curve with reference ratio, mean-stress policy, cut-off, scatter factor and a `valid_for` entry matching the part |
   | Anisotropic material | the material frame per part |
3. **Validity test for fatigue.** A made part declares material state, process (`cnc-3axis`, `cnc-5axis`,
   `sheet`, `fdm`, `sls`, `slm`), surface finish and, for additive processes, build orientation. A curve is
   valid when one of its `valid_for` entries matches all four. No match → `FatigueOutcome::NoClaim { reason }`
   with the first mismatching attribute. Printed processes (`fdm`, `sls`, `slm`) match only curves that name
   that process and an orientation; while OPEN-FOUNDRY-4 is undecided the generic catalogue ships none, so
   printed parts read `fatigue: no-claim`.
4. **Outcomes.**
   - A field required by stress, buckling, modes or mass is absent or has no provenance → FROB-REF-163.
     Payload: card identity and version, the check, the field path, what provenance was found, and repairs:
     (1) add the field with a source; (2) choose a card of the same material that has it (listed by name).
     Exit code 3; `retry: after-change`.
   - Fatigue data absent or invalid → the fatigue criterion alone reads `no-claim`; the other criteria
     answer. If the caller requires fatigue (`--require fatigue`, or a packet that would record a fatigue
     pass) → FROB-REF-163 with the mismatching attribute and the repair "a curve valid for <state, process,
     finish, orientation>".
   - `--strict-data`: any required field of provenance `assumed` → FROB-REF-113, the program's strict-data
     refusal of N15b-06 (a dependency of this bead), naming the card, the field path and the check, with the
     repairs: (1) replace the field by one of provenance `datasheet` or `measured`; (2) run without
     `--strict-data`, in which case the result names the field as its weakest input. DESIGN: one code for
     "an `assumed` card field under `--strict-data`" across the program (actuator cards, lifecycle laws in
     `foundry.lifecycle`, and material cards here), so an agent handles the flag's refusal in one way;
     FROB-REF-163 stays the code for a field that is absent, has no provenance, or does not apply to the part.
     The rows of `foundry.size`, `foundry.check` and `foundry.optimize` carry 113 and the option
     `--strict-data` with this bead (VERBS-foundry; N31-REF Table 2).
5. **Claim product.** Each field read creates a leaf of class Estimated whose input reference is the card
   hash and field path. Results name as `weakest` the field with the lowest provenance among those they used
   (order: assumed < generic < datasheet < measured), and the report's first next action is the measurement
   that would raise it.
6. **Safety factors** are not card fields: SF for yield, the buckling factor of 2 and the service duration H
   are design policy, declared on the design, and recorded beside the card fields in every result.
7. **Units.** All fields are dimension-typed quantities; a yield strength entered in MPa without its unit does
   not parse.

## Acceptance criteria

- [ ] A card without `yield_Pa` gives FROB-REF-163 on the stress check, naming `structure.yield_Pa`, with both repairs.
- [ ] A card with a valid wrought curve and a part declared `slm` gives `fatigue: no-claim` with reason `process`, while stress, buckling and modes answer.
- [ ] The same request with `--require fatigue` gives FROB-REF-163.
- [ ] A part declared `cnc-3axis`, `machined`, state matching, gets a numeric fatigue utilization.
- [ ] A curve whose `valid_for` names finish `polished` does not match a `machined` part.
- [ ] Under `--strict-data` an `assumed` modulus refuses with FROB-REF-113 naming `structure.E_Pa` (exit 3); without it the result is produced and names that field as the weakest input.
- [ ] The generic catalogue contains no stress-life curve for `fdm`, `sls` or `slm` while OPEN-FOUNDRY-4 is open (a test over the catalogue).
- [ ] A yield value without a unit is rejected by the card parser.

## Test plan

### Unit tests
`cargo test -p frob-foundry check::card`:
- `missing_yield_refuses_163`; `missing_provenance_refuses_163`.
- `fatigue_no_claim_on_process_mismatch`; `on_finish_mismatch`; `on_state_mismatch`; `on_missing_orientation_for_additive`.
- `require_fatigue_escalates_to_163`.
- `matching_curve_validates`.
- `strict_data_refuses_assumed`: FROB-REF-113 with the field path, never 163.
- `weakest_field_is_named`: E `datasheet`, yield `assumed` → weakest is yield.
- `printed_processes_have_no_generic_curve`.
- `unitless_yield_rejected`; `mpa_and_pa_agree` (276 MPa equals 2.76 × 10⁸ Pa).
- `anisotropic_card_requires_frame`.
- Planted defects, each caught: `knockdown-wrought-curve-for-printed` (a helper that scales a wrought curve by 0.5 and reports a number), `ignore-finish`, `default-yield-when-missing`.

### End-to-end script and logging
`scripts/e2e/foundry_card_validity.sh` (this bead's own, built only on its dependencies; it sources the
STD-E2E helper library). Steps: (1) `cargo test -p frob-foundry -- check::card` through `e2e_cmd` (including
the three planted defects); (2) `cargo run -p frob-foundry --example card_validity -- --card <file> --part
<declaration> --checks stress,buckling,modes,fatigue --json`, an example program of this bead running the
validity test of a card against a part declaration and printing, per check, the fields read with their
provenance, the outcome and the weakest input: a scratch copy of the cantilever's card without `yield_Pa`
gives exit 3 and FROB-REF-163 with pointer `structure.yield_Pa` and both repairs in the row's order; a wrought
curve against an `slm` part gives `fatigue: no-claim` with reason `process` while the other checks are
admitted; the same with `--require fatigue` gives FROB-REF-163; a `cnc-3axis`, `machined` part with matching
state admits fatigue; (3) a card with an `assumed` modulus under `--strict-data`: exit 3 and FROB-REF-113
naming `structure.E_Pa`, and without the flag the outcome names that field as the weakest input; (4) a yield
value without a unit is rejected by the parser. No `frob` verb is called, so the evidence block is recorded as
absent with reason `no-verb`. Logs to `target/e2e-logs/foundry_card_validity/<utc>.ndjson` with a transcript:
per line `ts`, `script`, `bead` = N31a-22, `step`, `event`, the command, exit code and wall time; the card
hash, the fields read with their provenance, and the weakest input; on failure the first differing outcome; a
final `summary`. The verb-level steps are in `scripts/e2e/foundry_check.sh` (N31a-55), which runs this script
as a stage: the check on the cantilever fixture with a card stripped of its yield field (exit 3, FROB-REF-163,
pointer `structure.yield_Pa`) and a printed-part fixture (`result.fatigue == "no-claim"`, exit 0 or 2 by the
other criteria), each `frob foundry check` call carrying `--key "$(e2e_key <label>)"`.

### Known answers and negative controls
No numeric known answer of its own; the unit-equivalence case 276 MPa = 2.76 × 10⁸ Pa. Negative controls: the
three planted defects. Metamorphic: adding an unrelated field to a card changes its hash and no outcome;
raising a field's provenance never lowers a result's class. Determinism: host logic, identical everywhere.

## Considerations

- Material uncertainty is retained on the density field and passed to mass properties as a relative
  uncertainty; it is not turned into a bound on inertia (the mass-properties sibling retains it the same way).
- A refusal on missing data is annoying at exactly the moment a user wants a number. The repair list names
  cards that have the field, so the fastest path is a card choice, not a guess.
- If OPEN-FOUNDRY-4 is decided with a data source, printed curves enter the catalogue with their process and
  orientation and nothing here changes.
- The same validity pattern (a law with a stated domain that refuses outside it) is used by lifecycle laws
  with their own code, FROB-REF-831.
