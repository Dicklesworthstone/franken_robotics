## Background

Mechanical engineers exchange solids as STEP files. The exchange sibling can parse and write Part-21 syntax
within bounds, strictly decode a triangle-only faceted solid, and re-emit a decoded faceted solid
deterministically with a mandatory self-parse and bit-exact replay. Its faceted exporter accepts only a solid
produced by its own decoder: there is no entry point from a mesh (FACT). A mesh entry point is upstream work
item FD-FSIM-26.

The plan's route needs no upstream change: **Foundry builds a syntax-level `StepDocument` of the
faceted-solid entity chain, writes it with `write_step`, parses and decodes it with
`decode_faceted_brep_with_limits`, and re-emits it with `export_decoded_faceted_brep`, which refuses unless
every coordinate bit and triangle index replays.** The file that enters the packet is the re-emitted one, so
it has passed the sibling's own strict decoder and replay.

**Bound.** The default limit of 10⁶ instances admits about 285,000 triangles for a closed mesh, at three
instances per triangle, about half a point per triangle, and two more (FACT, arithmetic). A larger part is
decimated under a stated Hausdorff tolerance and re-checked, or refused (FROB-REF-824: a STEP export above its
bounds or failing bit-exact replay; repair: decimate under a stated tolerance). The file has no curved
surfaces and no units entity; the manifest states metres.

ADR-FOUNDRY-08: exported STEP is a faceted solid and is described as interchange evidence; no curved-surface
re-fit is attempted, because that is what the sibling exporter emits and checks. A fitted spline model would
be a new geometry that nothing in this system has analysed.

Gate (TARGET): GATE-FOUNDRY-09, Known answer, M5: tetrahedron round trip bit-exact; open shell and over-bound
parts refused; mass properties from exported geometry within 10⁻⁶ of the model. This bead carries the first
two clauses.

## Scope

In: construction of the syntax-level document from the canonical mesh; the write, decode, re-emit and replay
sequence; the instance arithmetic and the triangle bound; decimation as a new geometry that must be
re-checked; the refusal; what the file does and does not claim; the switch-over test for the mesh entry point.
Out: the canonical mesh and the other formats (N31a-34); mass properties recomputed from the exports (N31a-40);
the independent check that a decimated part must pass again (N31a-19) and the mass-property feedback edit it
goes through again (N31a-23): both are called here, so both are dependencies.

## Technical approach

1. **Entity chain** (`export/step.rs`). From the canonical export-exact mesh with V vertices and T triangles
   the document holds: one point instance per vertex; per triangle a loop over its three points, a face bound
   and a face (three instances); one closed shell listing all faces; one faceted solid. Instance count
   N = 3·T + V + 2. (The entity names are those the sibling's strict faceted decoder accepts; the sibling
   fact probe pins them, and this bead restates only the counts the plan gives: three per triangle, one per
   point, two more.) No units entity, no product context, no curved surface, no application-protocol claim.
2. **Bound arithmetic.** For a closed surface of genus g, V = T/2 + 2 − 2·g. With g = 0, N = 3.5·T + 4. The
   default limit N ≤ 10⁶ gives T ≤ 285,713, and T is even, so **T ≤ 285,712**. A tetrahedron (T = 4, V = 4)
   has N = 18.
3. **Sequence.**
   1. Build the document; coordinates are the single-precision-exact values written as shortest round-trip
      decimals.
   2. `write_step` → bytes b₁.
   3. Parse b₁ and `decode_faceted_brep_with_limits` with the default limits → a decoded solid. A refusal
      here (open shell, non-triangle face, over limit) is converted to FROB-REF-824 with the sibling's reason.
   4. `export_decoded_faceted_brep` → bytes b₂. The sibling self-parses b₂ and refuses unless every
      coordinate bit and triangle index replays.
   5. Foundry independently decodes b₂ and compares vertices and triangles with the canonical mesh, bit for
      bit, in canonical order. b₂ and its BLAKE3 enter the packet. b₁ is discarded.
4. **Above the bound.** If T > 285,712 the part cannot be exported as checked. Two outcomes:
   - `--decimate <hausdorff tolerance>` was given: decimate the canonical mesh by edge collapse under the
     stated two-sided Hausdorff tolerance until T ≤ bound; the result is a **new geometry**: it is made
     export-exact, re-validated, re-meshed, sent through the independent check and through mass properties
     and the feedback edit again ("re-checked"). Only then may it be exported, in all four formats. The
     record states the tolerance, the triangle counts before and after, and the measured Hausdorff distance.
   - otherwise: FROB-REF-824. Payload: T, V, N, the limit 10⁶, the bound 285,712, and the repair "decimate
     under a stated tolerance" with the smallest tolerance that reaches the bound, estimated from a trial
     decimation. Exit code 3; `retry: after-change`.
   Extraction keeps optimized parts under the bound, so this path is for hand-built or imported geometry.
5. **Replay failure.** Any mismatch in step 3.4 or 3.5 is FROB-REF-824 with reason `replay`, the first
   differing vertex or triangle and both values. It is never downgraded to a warning.
6. **Statement in the manifest.** For every STEP file: `kind: "faceted solid (triangles)"`, `units: "metre
   (stated here; the file has no units entity)"`, `curved_surfaces: false`, `conformance_claim: "none"`,
   `role: "interchange evidence"`.
7. **Switch-over (FD-FSIM-26).** When the sibling gains a mesh entry point, the route becomes a single call.
   The test `step_mesh_entry_hash_equality` (ignored until then) re-exports the packet fixtures through the
   new entry and requires byte-identical files; then steps 3.1 to 3.3 are deleted.
8. **Determinism.** Class D0 on the file bytes: the same canonical mesh gives the same file on every platform
   (verification tier G5 on the host).

## Acceptance criteria

- [ ] GATE-FOUNDRY-09: a tetrahedron exports with 18 instances and the re-emitted file replays bit for bit; an independent decode equals the canonical mesh.
- [ ] GATE-FOUNDRY-09: an open shell (the tetrahedron with one face removed) is refused with FROB-REF-824 and the sibling's reason.
- [ ] GATE-FOUNDRY-09: a closed mesh of 285,714 triangles is refused with FROB-REF-824, stating N = 1,000,003 against 10⁶ and the bound 285,712; a mesh of 285,712 triangles (N = 999,996) exports.
- [ ] With `--decimate`, the over-bound part is decimated within the stated Hausdorff tolerance, re-checked, and exported in all four formats; without a passing re-check it is not exported.
- [ ] A planted change of one coordinate bit between write and re-emit is detected as a replay failure.
- [ ] The manifest entry for each STEP file carries the five statements of step 6.
- [ ] The file is byte-identical across two runs and across platforms.

## Test plan

### Unit tests
`cargo test -p frob-foundry export::step export::decimate` (feature `structure`):
- `instance_count_formula`: T = 4, V = 4 → 18; cube T = 12, V = 8 → 46; torus with T = 2·V: N = 3.5·T + 2.
- `bound_is_285712`: 3.5 × 285,712 + 4 = 999,996; 3.5 × 285,714 + 4 = 1,000,003.
- `tetrahedron_round_trip_bit_exact`.
- `open_shell_refused_824`; `quad_face_refused_824` (a non-triangle face in a hand-built document).
- `over_bound_refused_with_numbers`.
- `independent_decode_equals_canonical`.
- `planted_bit_flip_is_replay_failure`.
- `decimation_respects_hausdorff_tolerance`: on a sphere of radius 20 mm the measured distance is at most the stated 0.05 mm.
- `decimated_geometry_requires_recheck` (a type-level rule: the decimator returns an unchecked geometry).
- `manifest_statements_present`.
- `file_bytes_identical_twice`.
- Planted defects, each caught: `export-b1-not-b2` (ships the first write, skipping the sibling's replay), `decimate-and-export-without-recheck`, `count-points-per-triangle-corner` (writes three points per triangle, tripling instances; caught by the count test and the bound).

### End-to-end script and logging
`scripts/e2e/foundry_export_packet.sh` (bead N31a-57): `frob foundry export --fixture tetrahedron
--geometry-only --format step --json` asserting 18 instances and `replay: bit-exact`; the open-shell and over-bound
fixtures asserting exit 3 and FROB-REF-824 with the bound in the payload; logs T, V, N against 10⁶, the file
hash, and for decimation the tolerance and measured distance. Every `frob foundry export` call carries `--key "$(foundry_key <step>)"` from the cluster preamble (N31a-51), because the verb is `run`.

### Known answers and negative controls
KA-748 (STEP round trip of a tetrahedron: 18 instances; bit-exact replay; controls: an open shell is refused;
a part above the bound is refused with the bound stated). Arithmetic: 3.5·T + 4 ≤ 10⁶ gives T ≤ 285,712.
Negative controls: the three planted defects. Metamorphic: permuting the input mesh's vertex and triangle
order leaves the file unchanged (canonical order); a rigid motion of the part in the link frame leaves the
part-frame file unchanged. Determinism: byte identity across platforms.

## Considerations

- A faceted solid of a quarter of a million triangles is a poor thing to machine from; it is interchange
  evidence of shape, and a shop will re-model. Saying so in the manifest is part of the design.
- KILL-PACKET (M5): if GATE-FOUNDRY-09 or -10 fails after one repair cycle, the packet is reduced to a parts
  list, mass properties and STL, and STEP is deferred.
- Decimation is where "the object that was checked" and "the object that was exported" could silently part
  ways. Making the decimated mesh a new, unchecked geometry in the type system is the guard.
- The sibling's limits are defaults and could be raised; the plan keeps the default so that a consumer with
  default limits can read every file a packet contains.
