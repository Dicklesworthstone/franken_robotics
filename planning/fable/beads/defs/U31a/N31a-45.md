## Background

Fixed-point arithmetic overflows silently: a sum that leaves its word wraps around and becomes a large number
of the opposite sign, and a motor command changes sign with it. The first three of the exporter's checks exist
to show, for the exported controller and its declared input ranges, that no intermediate value can overflow.

**Checks, in order (the first three).**

1. **Range analysis.** Declared input ranges are propagated through the kernel IR by interval arithmetic,
   fixing a Q format for every intermediate.
2. **Bit-vector queries.** Where intervals are too coarse (correlated terms such as a·x − a·y), the question
   "is there an input in range for which this intermediate overflows?" is bit-blasted and decided by
   `fln-verdict::bv_decide`. An unsatisfiable answer with a replayed proof stream is an instance certificate,
   class Certified. It is not Proved, because the proof-term step is not built upstream. This is theorem card
   T-14.
3. **State.** Integrators and filters need an inductive range invariant: one query for the base case and one
   for the step.

**Counterexamples that seed the registry (CX-342, CX-343).** In Q15, (−1)·(−1) is 0x8000·0x8000 = 0x40000000,
which shifts to 0x8000 and reads as −1; the negation of −32768 overflows; an integrator adding 400 counts per
tick from zero overflows sixteen bits at tick 82, and without a clamp the one-step query returns the state
32,400 at once. The tempting beliefs they break: "Q15 multiplication cannot overflow" and "an integrator
without a clamp is safe if each step is small".

Proof obligation PO-FOUNDRY-04: for each exported controller, no intermediate overflows on the declared input
ranges (T-14); discharged by replayed bit-vector certificates. Refusal FROB-REF-827: a fixed-point obligation
refuted or undecided within budget; repair offered: the counterexample input, or a wider format.
OPEN-FOUNDRY-6: the time budget per obligation; default 2 s (TARGET), with a timeout treated as undecided and
therefore refused.

The sibling's bit-vector tool returns a checked certificate, not a kernel proof (FACT: the step that would
derive the kernel proof term from the replayed certificate "is not built"). That is why the class is
Certified and why this is the one place where a Foundry result exceeds Estimated (INV-FOUNDRY-06's stated
exception).

## Scope

In: declared ranges and relations; interval propagation; Q-format assignment; obligation generation;
when a query is needed; the induction scheme; the budget; counterexample handling; the refusal; the
obligation table handed to emission.
Out: the certificate format, the replay and its trusted base (CARD-T-14); code emission (N31a-44);
quantization error and vectors (N31a-46).

## Technical approach

1. **Declarations** (`firmware/range.rs`). For each input signal: a physical range with unit (position error
   in radians, velocity in rad/s, current in amperes) and a resolution; optionally *relations* between inputs
   (|x − y| ≤ d; x ≥ 0 when a mode bit is set). For each state variable: an initial value and a claimed
   invariant range. For each constant (gains): the exact rational value.
2. **Interval propagation.** Each IR operation maps intervals of real values to an interval: sum and
   difference by endpoint arithmetic, product by the four endpoint products, shift by scaling, clamp by
   intersection, select by union. Outward rounding throughout. Relations are ignored at this stage, which is
   why it can be coarse.
3. **Q-format assignment** (`firmware/qformat.rs`). For an intermediate with range [lo, hi]: integer bits
   m = 1 + ⌈log₂(max(|lo|, |hi|) + ulp)⌉ (the 1 is the sign), fraction bits n = W − m for the chosen word W
   (16, 32 or 64; the smallest that keeps the fraction bits required by the quantization budget of N31a-46).
   Products are computed at double width and shifted back; the format of the double-width intermediate is an
   obligation of its own. The table (signal, W, n, range in counts) is the content of the generated
   `qformat.rs`.
4. **Obligations.** One per intermediate value v of the lowered integer program: "for all inputs within their
   declared ranges and relations, and all states within their invariant, the two's-complement value of v
   computed at extended width equals its W-bit truncation." If interval propagation in integer counts already
   shows the range fits in W bits, the obligation is discharged by an *interval certificate* (the box and the
   operation, checkable by exact integer arithmetic; class Certified). Otherwise, or whenever a relation
   exists that touches v, it becomes a bit-vector query.
5. **Bit-vector query.** Variables: inputs and states as bit-vectors constrained to their ranges and
   relations; formula: extended-width v ≠ sign-extension of its W-bit truncation. Decided by `bv_decide` under
   the time budget (2 s per obligation by default).
   - *Unsatisfiable* with a proof stream that the independent checker replays → an instance certificate bound
     to the kernel-IR hash, the obligation, the ranges and relations (by digest) and the proof-stream digest,
     as the theorem card specifies.
   - *Satisfiable* → the model is re-decoded into input and state values and re-executed by the exporter's
     own integer interpreter to confirm the overflow; it is stored as a test vector; the obligation is
     *refuted*.
   - *Timeout or unknown* → *undecided*.
6. **Induction for state.** For each state variable s with claimed invariant R: the base obligation "the
   initial value is in R" and the step obligation "s ∈ R and inputs in range imply next(s) ∈ R, and no
   intermediate of the step overflows". The step query does not unroll time: it asks about one step from any
   state in R. If R is not inductive the query returns a state in R whose successor leaves R.
7. **Outcome.** All obligations certified → the obligation table and certificates go to emission. Any refuted
   or undecided → FROB-REF-827, exit code 3, and no code is emitted. Payload per failing obligation:
   the intermediate (IR name and source position), its format, `status: refuted | undecided`; for refuted, the
   counterexample inputs and state in counts and in physical units and the offending value; repairs ranked:
   (1) widen the format to the stated W and n that the interval analysis says suffices; (2) add a clamp or
   saturating operation at the named point; (3) narrow the declared input range to the stated bound (the
   largest range for which the obligation holds, found by bisection on the range under the same budget);
   (4) for undecided only, a larger budget.
8. **The seeded cases as obligations.**
   - Q15 product p = (a·b) ≫ 15 with a, b ∈ [−32768, 32767]: refuted by a = b = −32768 (the product
     0x40000000 shifts to 0x8000 = 32768, outside [−32768, 32767]; truncated it reads −32768, that is −1.0).
     With the range [−32767, 32767], or with a saturating product, certified.
   - Negation n = −a with a ∈ [−32768, 32767]: refuted by a = −32768.
   - Integrator s′ = s + 400 in 16 bits with R = [−32768, 32767]: the step obligation is refuted at once by a
     state whose successor overflows; restricted to reachable states s = 400·k from zero, the unique witness
     is s = 32,400 (k = 81; the overflow is at tick 82, since 400 × 82 = 32,800 > 32,767). With
     s′ = clamp(s + u, −32000, 32000), u ∈ [−400, 400] and R = [−32000, 32000], base and step are certified
     (s + u ∈ [−32400, 32400] fits sixteen bits).
9. **Class.** Instance certificates are Certified, per controller, per range. Everything else in the export
   stays Estimated or Tested. No certificate is ever labelled Proved.

## Acceptance criteria

- [ ] GATE-FOUNDRY-11, fixed-point cases: each of the three counterexamples is found (the Q15 product at (−32768, −32768); the negation at −32768; the unclamped integrator's step query with a witness whose successor overflows, equal to 32,400 under the reachability constraint), and the clamped controller is certified.
- [ ] PO-FOUNDRY-04: for the exported PI loop every obligation has an interval certificate or a replayed bit-vector certificate bound to the kernel-IR hash.
- [ ] A widened input range breaks a certificate: re-checking the clamped controller's certificates after widening u to [−800, 800] fails on the digest of the ranges, and re-running the query refutes or re-certifies under the new range as appropriate.
- [ ] A correlated term a·x − a·y with the relation |x − y| ≤ d is certified by a bit-vector query where interval analysis alone demands one more integer bit.
- [ ] An obligation that exceeds the 2 s budget is reported undecided and the export is refused with FROB-REF-827; no source file is written.
- [ ] Every counterexample re-executes to an actual overflow in the exporter's integer interpreter before it is reported.
- [ ] The refusal payload contains the counterexample in counts and physical units and the four ranked repairs.
- [ ] No certificate carries class Proved.

## Test plan

### Unit tests
`cargo test -p frob-foundry --features firmware-export firmware::range firmware::qformat firmware::bv firmware::induct`
(bit-vector tests need the `fln` checker and run in the Linux lane):
- `interval_propagation_basic`: x ∈ [−1, 1], gain 3/4: product in [−0.75, 0.75]; sum of two such in [−1.5, 1.5], needing two integer bits.
- `q_format_from_range`: range ±1.5 in a 16-bit word gives Q2.14.
- `q15_minus_one_squared_refuted`: 0x8000 × 0x8000 = 0x40000000; ≫ 15 = 0x8000.
- `q15_negate_min_refuted`.
- `q15_product_certified_on_symmetric_range`: with [−32767, 32767] the largest product is 32767², which shifted is 32,766.
- `integrator_overflow_tick_82`: 400 × 81 = 32,400 fits; 400 × 82 = 32,800 does not.
- `integrator_step_query_refuted_with_valid_witness`; `integrator_witness_is_32400_under_reachability`.
- `clamped_integrator_base_and_step_certified`.
- `correlated_difference_needs_query`: interval says [−2, 2); with |x − y| ≤ 2⁻⁴ the query certifies Q1.15.
- `timeout_is_undecided_and_refused_827`.
- `counterexample_reexecutes`.
- `widened_range_invalidates_certificate`.
- `repair_bisection_finds_largest_safe_range`.
- `no_certificate_is_proved`.
- Planted defects, each caught: `drop-relation-in-query` (the correlated term is refuted spuriously, or with the relation dropped from the digest a certificate survives a relation change), `skip-step-obligation` (certifies the unclamped integrator from the base case alone), `treat-timeout-as-safe`, `report-unverified-model` (a counterexample that does not overflow when executed).

### End-to-end script and logging
`scripts/e2e/foundry_firmware.sh` (bead N31a-58): exports the PI loop without a clamp (assert exit 3,
FROB-REF-827, a witness in the payload, no `src/` written) and with a clamp (assert certificates present and
replayed); logs per obligation the intermediate, format, method (interval or bit-vector), status, solver time
against 2 s and the certificate hash.

### Known answers and negative controls
KA-749 (fixed point, Q15: (−1)·(−1); negation of −32768; an integrator adding 400 counts per tick from zero:
each counterexample is found and the clamped controller is certified; control: a widened input range breaks a
certificate). CX-342 (Q15 multiplication cannot overflow) and CX-343 (an integrator without a clamp is safe if
each step is small). Negative controls: the four planted defects. Determinism: interval analysis and format
assignment are exact; solver verdicts are deterministic for a fixed build, and a different witness from a
different solver build is accepted when it re-executes to an overflow.

## Considerations

- KILL-FIRMWARE (M8): if GATE-FOUNDRY-11 fails, the export is controller parameters, Q formats and the
  test-vector manifest only; no code. The Q-format table of step 3 survives the kill.
- The certificate says "no overflow on these ranges". It says nothing about whether the ranges hold on a
  robot; an input outside its declared range is the caller's to clamp, and the generated code clamps inputs
  at entry only if the design says so.
- The bit-vector checker lives in another sibling repository and runs as a subprocess on a Linux host; where
  it is unavailable the result is an unavailable-backend refusal, never a silent skip.
- The trusted base of a certificate is the streaming checker, not a proof kernel; the theorem card names it.
