## Background

In this program a refusal is a result with a type: a code, a pointer at the field or part at fault, what was
observed and what was required, a `retry` value and ranked repairs an agent can act on. Foundry defines
fourteen codes (FROB-REF-163, -164, -165, -166, -167, -169, -260, -261, -262, -818, -824, -827, -831, -860).
Their payload types, the renderer and the shared assertion helper are bead N31a-52; the verbs that raise them
are built by the capstone beads BD-400 to BD-408, which consume those types. **A refusal that exists in a
table and that no test can trigger is not a refusal the system has.** This bead is the proof that each code
is reached through the real verbs, carries what its row promises, and that its first repair works.

It was split from N31a-52 in polishing round 1: the battery runs through verbs whose beads depend on the
payload types, so it cannot be part of the bead that defines them.

The refusal registry N31-REF names the binding of each of its rows: a test `ref_<code>_<name>` and a step of
the repair-replay script `scripts/e2e/foundry_refusals.sh`. Both are implemented here. Two codes need a
Moonshot feature compiled in: FROB-REF-827 (fixed-point obligations, feature `moonshot-firmware-export`, M8)
and FROB-REF-831 (lifecycle laws, `moonshot-lifecycle` in the verb layer, M6). This bead is M5 and cannot
depend on later work, so their triggers are written in the feature lanes by the firmware and lifecycle
scripts (N31a-58, N31a-59) with the same helper and fixture layout, and the binding check reports those two
rows as pending on their feature until those lanes run.

## Scope

In: `tests/refusal_battery.rs` with the trigger fixtures of the twelve codes reachable in a default M5 build;
the binding tests `ref_<code>_<name>` of those twelve rows as N31-REF specifies them; the repair-replay
script; the near-miss fixtures that must not refuse; the refusals of other chapters and the chapter's uncoded
refusals as they arrive through `foundry.export` and `foundry.loads`; the scan of real payloads for private
data; MCP parity of one refusal per verb implemented at M5; the run of the coverage checker over the logs.
Out: the payload types, renderer, `assert_refusal` helper and coverage checker (N31a-52); the triggering
logic (the mechanism beads and capstones); the 827 and 831 triggers (N31a-58, N31a-59, in their feature
lanes); the registry rows (N31-REF); codes for the uncoded refusals (N31b-45).

## Technical approach

1. **Fixtures** under `fixtures/foundry/refusals/<code>/<variant>/`, one directory per trigger, each the
   smallest real input that raises it; the cluster scripts (N31a-53 to N31a-57) reuse these directories, so
   each trigger fixture exists once.
2. **The battery** (`tests/refusal_battery.rs`, each case through the `frob` binary with `--json`):

   | Code | Trigger fixtures | Verb (capstone) |
   |---|---|---|
   | 166 | unqualified design to `optimize`; to `export`; an exploratory record offered to a packet | `foundry.optimize` (BD-403), `foundry.export` (BD-408) |
   | 167 | campaign with a sign-flipped joint reaction; a load file of assembled peaks | `foundry.loads` (BD-400), `foundry.size` (BD-401) |
   | 169 | a T2 chunk removed; a class envelope from one limb only | `foundry.loads` (BD-400), `foundry.size` (BD-401) |
   | 163 | card without yield; printed part with `--require fatigue` | `foundry.check` (BD-402, BD-405) |
   | 164 | keep-out slab across the link; empty keep-in | `foundry.optimize` (BD-403) |
   | 165 | q = x² under `--method statistical`; no worst-case box above the process floor; an unknown simulated sensitivity | `foundry.tolerance` (BD-406) |
   | 260 | planted gain 1.1; planted two-size cycle; a gain needing more than five iterations | `foundry.optimize` (BD-404) |
   | 261 | optimized part with a thin neck (stress); with a slender strut (buckling) | `foundry.optimize`, `foundry.check` (BD-402, BD-404) |
   | 262 | soft link without the transient flag | `foundry.loads` (BD-400) |
   | 860 | manifest flag set true; flag removed (both read through `foundry.check <packet>`); a request carrying a flag key (to `foundry.export`, with its own key) | `foundry.export` (BD-408), `foundry.check` in its packet mode (N31b-32) |
   | 818 | `--priced` without a catalogue | `foundry.export` (BD-408) |
   | 824 | open shell; 285,714 triangles; a planted replay mismatch | `foundry.export --geometry-only` (BD-407) |

   Twenty-seven fixtures. For each, `assert_refusal` (N31a-52) checks exit 3, the code, a non-empty
   `pointer` matching the row, `observed` and `required` with `unit` where a quantity, `retry` as specified
   and the first repair (an empty list for 860). Where the first repair is a command, the battery runs it on
   the same fixture and asserts that the outcome changes: a result (exit 0 or 2) or the next expected state
   (for 166, `--exploratory` gives a labelled result that a packet request still refuses).
3. **Binding tests** (`cargo test -p frob-foundry refusals`), named `ref_<code>_<name>` with the registry's
   kebab name in snake case, on the inputs N31-REF states: `ref_163` (card without its yield field,
   `structure.yield_Pa` in N31a-22's card section, as N31-REF names it);
   `ref_164` (keep-out covering the whole envelope); `ref_165` (sensitivity 0); `ref_166` (design without a
   verdict; and `--exploratory` accepted and labelled); `ref_167` (a case built from ticks 10 and 11; and a
   campaign with 0.2% dropped samples); `ref_169` (campaign without control-rate traces); `ref_260` (planted
   gain 1.1); `ref_261` (planted overstress at utilization 1.25); `ref_262` (f₁ = 4 × the loaded frequency);
   `ref_818`; `ref_824` (300,000 triangles; and a replay with one flipped coordinate bit); `ref_860` (a
   manifest with `fabrication_released: true`, and one with the field absent). Each asserts code, exit,
   pointer and repair order. `every_code_has_a_fixture` requires the twelve in a default build and fourteen
   when both Moonshot features are compiled (the two extra are `ref_827` and `ref_831`, written in N31a-58 and
   N31a-59 to the same naming); `exit_code_is_3_for_all`.
4. **Near-miss fixtures** (must not refuse, so that no check refuses too eagerly): a dropped share of exactly
   0.1% (167); a closed mesh of 285,712 triangles, N = 999,996 (824); a frequency ratio of exactly 5 (262);
   λ̂ = 0.99 converging slowly inside the iteration budget (260); a rational quantity whose band-extreme
   discrepancy is exactly 10% of the margin (165, the threshold is "more than 10%").
5. **Refusals of other chapters and uncoded ones, through the real verbs.** On `foundry.export`: a design
   with a `provisional` envelope case (`provisional-load-case-in-packet`, interim FROB-REF-820); a design
   whose ranking is `model-conditional` (FROB-REF-830) and one with a `tier-sensitive` selection record
   (FROB-REF-819); a planted cross-consistency failure (`packet-inconsistent`: row 10 of N31b-45, held with no
   fitting interim, so it is asserted by its `detail` constant with no code until the ledger assigns a number,
   then by code), planted through the assembler's conformance-only hook `FROB_TEST_PACKET_PLANT=<plant>`
   (N31a-43) on a `frob` built with `--features gauntlet-mutations`, since the verb takes a design and has no
   input through which a section could be made inconsistent; a `--packet` directory outside the session's export root (the export door's FROB-REF-734,
   exit 5, nothing written; N37-18 through the writer of N31a-36). On `foundry.loads`: a campaign whose
   Chronicle chunk is missing samples, refused as FROB-REF-169 with the upstream FROB-REF-888 kept in the
   payload.
6. **Private data.** Every payload the battery produces is scanned against the private fields of its
   fixture's scene (coordinates of scene geometry); world addresses and counts may appear, geometry may not.
7. **MCP parity.** For each of the six verbs implemented at M5, as the MCP tool of its row (`foundry_size`,
   `foundry_optimize`, `foundry_check`, `foundry_tolerance` and `foundry_export` of the task cluster `make`,
   and `foundry_loads` of the task cluster `structure`; NJL-05), one battery fixture is sent through the tool
   (a `run` verb's with its own key) and its refusal envelope equals the CLI's, field for field.
8. **Repair-replay script** `scripts/e2e/foundry_refusals.sh` (as N31-REF specifies it): for each code, the
   fixture's `frob foundry …` command with `--json` (a call of a `run` verb, which is every Foundry verb but
   `size` and `tolerance`, carries `--key "$(foundry_key <code>-<variant>)"` from the cluster preamble of
   N31a-51, and the repair replay takes a new key, or it would get the stored refusal back); assert `ok: false`, the code, exit 3 and the first
   repair through `assert_refusal`; then apply the first repair where one exists and assert the command now
   succeeds (163: adding the field; 165: the worst-case-box command, exit 2; 166: `--exploratory` with the
   label present; 262: `--transient impact-windows`; 818: prices omitted; 824: `--decimate` with the stated
   tolerance, re-checked). At the end it runs `scripts/e2e/foundry_refusal_coverage.sh` over its own log and
   the cluster scripts' logs of the same run.

## Acceptance criteria

- [ ] Each of the twelve default-build codes is raised by each of its listed fixtures through the `frob` binary (27 fixtures), with the payload fields of N31a-52's table.
- [ ] For every first repair that is a command, executing it on the fixture changes the outcome to a result or to the next expected state.
- [ ] The five near-miss fixtures complete without a refusal.
- [ ] The binding tests `ref_<code>_<name>` exist for the twelve rows and pass, and N31-REF's binding check reports them `bound`; 827 and 831 are reported pending on their feature lanes, not missing.
- [ ] On `foundry.export`, the provisional case (interim 820), the conditional (830) and tier-sensitive (819) selections and the cross-consistency failure (`packet-inconsistent`, by its `detail` constant) each refuse with exit 3 and no packet directory, and a target outside the export root refuses with 734 and exit 5; on `foundry.loads`, 888 arrives as 169 with 888 kept.
- [ ] No payload contains scene geometry or other private-scene data.
- [ ] Through MCP, one refusal per verb implemented at M5 (six tools) equals the CLI envelope.
- [ ] The coverage checker passes on the run's logs with the required set of a default build (twelve codes).

## Test plan

### Unit tests
`cargo test -p frob-foundry --test refusal_battery` and `cargo test -p frob-foundry refusals`:
- `battery_<code>_<variant>` × 27.
- `ref_<code>_<name>` × 12 (with the second inputs of 166, 167, 824 and 860); `every_code_has_a_fixture`; `exit_code_is_3_for_all`.
- `repair_command_changes_outcome` for every fixture whose first repair is a command.
- `near_miss_167_drop_share`; `near_miss_824_bound`; `near_miss_262_ratio_5`; `near_miss_260_slow_contraction`; `near_miss_165_ten_percent`.
- `export_provisional_case_820_interim`; `export_selection_830`; `export_selection_819`; `export_packet_inconsistent_by_detail`; `export_outside_root_734_exit_5`; `loads_888_becomes_169_upstream_kept`.
- `no_private_data_in_real_payloads`; `mcp_refusal_parity_per_verb` (six tools).
- Planted defects in the harness, each caught: `assert-code-only` (a planted payload with the right code and a wrong first repair must fail the battery); `skip-repair-replay` (the replay count must equal the number of command repairs); `refuse-at-threshold` (a mechanism mutant refusing 285,712 triangles is caught by the near-miss).

### End-to-end script and logging
`scripts/e2e/foundry_refusals.sh` (sources the STD-E2E helper), as specified in step 8. NDJSON to
`target/e2e-logs/foundry_refusals/<utc-timestamp>.ndjson` with a transcript: every line has `ts`, `script`,
`bead` (`N31ap1-51`), `step`, `event`, the exact command line, exit code and wall time; per trigger an
`event: "refusal"` line with code (or uncoded name), pointer, observed, required, unit, retry and the full
ranked repairs; per repair replay an `event: "assert"` line with the repair command, its exit code and the new
outcome; per near-miss the threshold, the fixture value and the outcome. On failure: the first differing
field with expected and observed values and the fixture path. The `summary` counts codes exercised (12 of the
12 required in a default build), fixtures run (27), repairs replayed, near-misses passed (5 of 5), the
other-chapter and uncoded refusals seen, and the coverage checker's result.

### Known answers and negative controls
Each fixture has one expected code and first repair; thresholds: dropped share 0.1%; bound 285,712 triangles
(N = 3.5·T + 4 ≤ 10⁶); frequency ratio 5; contraction within five iterations; 10% of the margin. Negative
controls: the five near-misses and the three planted harness defects. Determinism: every payload is identical
on two runs on one machine.

## Considerations

- The slowest fixtures are the topology-optimization triggers (164, 260, 261); each uses the smallest link
  class and grid that raises its code, and the battery's wall time is logged per fixture so that a slow
  fixture is visible.
- The repair replay is what keeps the first repair honest: a wrong first repair costs an agent a loop
  iteration at best and teaches it to route around the check at worst.
- When the ledger assigns numbers to `packet-inconsistent` and `provisional-load-case-in-packet` (N31b-45),
  the battery asserts the codes and the interim disappears; until then it asserts the interim 820 with its
  `detail` for the provisional case and the `detail` constant alone for `packet-inconsistent`, and a code
  emitted without its registry row fails the battery.
- The options the triggers and repairs use (`--require fatigue` on `foundry.check`, `--transient
  impact-windows` on `foundry.loads`, `--decimate` and `--geometry-only` on `foundry.export`, `--method` on
  `foundry.tolerance`) belong to their mechanism beads and are listed in VERBS-foundry's rows.
- The M5 binding check does not treat 827 and 831 as missing in a build without their features: N31-REF's
  check reports them `pending: N31a-58` and `pending: N31a-59` on their feature lanes.
