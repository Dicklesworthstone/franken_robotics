## Background

A controller that is evaluated in simulation in floating point and then re-implemented by hand in fixed point
for a microcontroller is two controllers. Firmware export closes that gap for the small controllers where it
can be closed: the exporter emits fixed-point source whose arithmetic is, integer for integer, the arithmetic
that the simulator ran, together with certificates that no intermediate value overflows on the declared input
ranges.

Scope is deliberately narrow: joint-level controllers and monitors only (a proportional–derivative or
proportional–integral loop, the energy-budget monitor, a shield projection with a few rows). Whole-body
controllers and state estimators in fixed point are out of scope.

Ceiling, stated first: no speed claim. The benefit is that the controller evaluated in simulation is, integer
for integer, the arithmetic that would be shipped. What cannot be claimed: that a fixed-point lowering is
equivalent to its floating-point kernel (that needs a verified compiler and a model of the target); the
project claims an overflow bound per function (theorem card T-14: an exported fixed-point controller has no
overflow on its stated input range) and otherwise parity tests.

It is a Moonshot [M], behind feature `firmware-export` (ADR-FOUNDRY-12), off the critical path; the build
packet does not depend on it (INV-FOUNDRY-07). The exported artifact carries the no-authorization flags as a
constant in the generated crate and in its manifest; the code compiles only against hardware interfaces the
caller supplies and never addresses a register, a bus socket or an emergency-stop relay.

FACT (`franken_lean/crates/fln-verdict`, commit `4426f8ea7`): a bit-blaster, a CDCL solver, a proof stream
with an independent streaming checker, and `bv_decide`, which returns a re-decoded counterexample or a
replayed unsatisfiability candidate. The step that would derive the kernel proof term from the replayed
certificate "is not built". A result is therefore a checked certificate, not a kernel proof: class Certified,
never Proved. FACT (this plan's kernel IR): the fixed-point types `q16_16` and `q32_32` are reserved words with
defined wrapping and saturation semantics; no kernel uses them through M5; they exist so that an embedded
target lowers the same programs without a second IR.

## Technical approach

**The short plan (the seed's first done-condition).** Order of work: pilot → (if positive, and funded) budget
decision → mechanism → gate → kill decision.

**Output of `foundry.export --with-firmware`** (into `firmware/` of the packet): source for a `no_std`,
heap-free crate that forbids unsafe code and sits behind a caller-owned bus trait; Q-format declarations for
every input, state and intermediate; a test-vector manifest; overflow certificates; quantization error
bounds; the flags. The exporter emits no register access, no bus driver and no stop-circuit code.

**Checks, in order.**
1. *Range analysis.* Declared input ranges are propagated through the kernel IR of the controller by interval
   arithmetic, fixing a Q format for every intermediate (a signed word with a stated number of fractional
   bits; Q15 is a 16-bit word with 15 fractional bits and range [−1, 1 − 2⁻¹⁵]).
2. *Bit-vector queries.* Where intervals are too coarse (correlated terms such as a·x − a·y), the question
   "is there an input in range for which this intermediate overflows?" is bit-blasted and decided by
   `fln-verdict::bv_decide`. An unsatisfiable answer with a replayed proof stream is an instance certificate,
   class Certified. A satisfiable answer returns a counterexample input. A timeout is undecided. Refuted or
   undecided within budget is refused with FROB-REF-827 (repair: the counterexample input, or a wider format).
3. *State.* Integrators and filters need an inductive range invariant: one query for the base case and one
   for the step.
4. *Quantization.* The difference from the real-valued controller is bounded by interval arithmetic, and its
   closed-loop effect is measured by running the fixed-point controller in the loop in the exact-integer
   kernel class, so the simulated controller computes the same integers on every backend. Class Tested.
5. *Vectors.* 10⁶ vectors agree bit for bit between the exported crate built for the host and the integer
   kernel (TARGET). That is a test, and it is not called equivalence.
6. *Not claimed.* Execution time, stack depth and behaviour on a board: `timing: no-claim` until a receipt
   from a linked binary on real hardware is imported.

Proof obligation PO-FOUNDRY-04: for each exported controller, no intermediate overflows on the declared input
ranges; tested by replaying the bit-vector certificates.

**Counterexamples that seed the registry.** In Q15, (−1)·(−1) is 0x8000·0x8000 = 0x40000000, which shifts to
0x8000 and reads as −1. The negation of −32768 overflows. An integrator adding 400 counts per tick from zero
overflows sixteen bits at tick 82, and without a clamp the one-step query returns the state 32,400 at once.

**Pilot before funding** (N31b-10). A Q15 proportional–integral loop with and without a clamp. Falsifier: a
missed overflow, or an obligation undecided inside its budget. If the falsifier holds, nothing else in this
epic is built.

**Gate.** GATE-FOUNDRY-11 (claim Known answer, TARGET, M8): the fixed-point cases above (each counterexample
found; the clamped controller certified; a widened input range breaks a certificate); 10⁶ vectors bit-equal.

**Kill gate.** KILL-FIRMWARE: GATE-FOUNDRY-11 fails. Fallback: controller parameters, Q formats and the
test-vector manifest only; no code.

## Acceptance criteria

- [ ] A short plan (this bead, amended with the pilot's findings) is on file before any product code is written.
- [ ] The pilot has run and its record is in the pilot register (N31b-10).
- [ ] GATE-FOUNDRY-11 is recorded with measured values from N31a-58's receipt; or, on a negative pilot, its row stays `not-run` (the register has no value "not run: pilot negative") and the KILL-FIRMWARE decision records `not-reached`, citing the pilot's result (N31b-21).
- [ ] KILL-FIRMWARE is decided and recorded (N31b-21).
- [ ] If the epic proceeds: every exported controller has a replayed certificate per intermediate or a refusal; certificates are class Certified and never Proved; the generated crate is `no_std`, heap-free, without `unsafe`, without register or bus access, and carries the flags as a constant; `timing` reads `no-claim`; the packet builds and verifies without the feature.
- [ ] If the epic proceeds and KILL-FIRMWARE fires (the gate fails): the fallback (parameters, Q formats and the vector manifest) is what `--with-firmware` writes, under that name. If the pilot is negative or the epic is not funded, nothing else of the epic is built, no fallback output exists and the capability is not described (the outcome `not-reached`).

## Test plan

### Unit tests
Carried by the children; the epic names the ones that must exist: `q15_minus_one_squared` (0x8000 × 0x8000 =
0x40000000; shifted by 15 it is 0x8000, read as −1; the query is satisfiable and returns this input);
`q15_negate_min` (−(−32768) overflows; counterexample returned); `integrator_overflows_at_tick_82` (400 × 81 =
32,400 fits; 400 × 82 = 32,800 does not); `inductive_step_query_without_clamp_returns_32400` (any state of at
least 32,368 refutes the step; the documented witness is 32,400); `clamped_pi_certified` (base and step
queries unsatisfiable; proof streams replay); `widened_range_breaks_certificate`; `correlated_terms_need_bv`
(a·x − a·y with x, y in a common range: intervals say overflow may occur, the bit-vector query proves it
cannot when |x − y| is bounded); `timeout_is_undecided_and_refused_827`; `quantization_bound_contains_measured_error`;
`generated_crate_forbids_unsafe_and_alloc`; `flags_constant_present`.

### End-to-end script and logging
`scripts/e2e/foundry_firmware.sh` (bead N31a-58): `frob foundry export --with-firmware` on the clamped and
unclamped loops; builds the generated crate for the host; runs 10⁶ vectors against the integer kernel; replays
every certificate with the independent checker; logs obligations decided, refuted and undecided, the largest
query time against the budget, vectors compared and mismatches (0), and the evidence block; the summary names
GATE-FOUNDRY-11.

### Known answers and negative controls
KA-749 (the three fixed-point cases; control: a widened input range breaks a certificate). Counterexamples
CX-342 and CX-343. Negative controls: the unclamped loop (must be refused); a certificate with one proof-stream
record altered (the independent checker must reject it); a generated crate with one coefficient changed after
export (the vector comparison must find a mismatch).

## Considerations

- Moonshot priority 4 whatever the milestone; funded only on a positive pilot and the owner's approval; an epic that has not passed its pilot within its planned weeks returns to the register of deferred items.
- OPEN-FOUNDRY-6: the time budget per bit-vector obligation. Default 2 s (TARGET), with a timeout treated as undecided and therefore refused. It blocks GATE-FOUNDRY-11 (N31b-29).
- The certificate is an instance certificate for one controller, one set of ranges and one word length. Changing any of them invalidates it.
- Dependence on shields: the shield projection is one of the three exportable kinds; if runtime shields were withdrawn at their kill gate, that kind is dropped and the other two remain.
- Nothing here authorizes running the code on hardware: the flags say so in the crate itself.
