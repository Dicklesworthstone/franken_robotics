## Background

A known answer is a case whose result is known independently of the code under test. The program's rule for
one: a derivation on file that states the model, the derivation, the numeric value with its digits and the
error budget of the test; a tolerance with a reason; a negative control (a mutation or planted failure that
must make the row fail); and a tier and site. Foundry's known answers are hand calculations; fixture
dimensions and material constants are DESIGN choices. The oracle must never be regenerated from the candidate
code, which is why the derivations are documents and the recomputation test uses only exact arithmetic on the
fixture inputs.

The chapter lists seventeen rows, the registry adds one for the quasi-static limit, and three late
subsections add more. Two registry rows are printed with tolerance `to set` and four with no negative control;
such rows cannot support a gate until both are supplied. This bead writes all the derivation files and
proposes the missing tolerances and controls, each labelled DESIGN, for registration.

## Scope

In: one derivation file per numbered row below under `docs/derivations/foundry/`; the derivation sections of
the six later-subsection answers in `docs/derivations/foundry/derived.md`; proposed tolerances and controls for
the incomplete rows; a recomputation test in exact rational or high-precision arithmetic.
Out: the registry bead (`N31-KA`); the fixtures and gate wiring (N31b-05); proof-obligation derivations
(N31b-02).

## Technical approach

**File form.** `docs/derivations/foundry/<ka>-<slug>.md`: model and assumptions; inputs with units; derivation
in steps; the value to at least six significant digits and the printed value; the error budget of the test
(truncation, round-off, tier envelope); tolerance and its reason; the negative control and the value it
produces.

**Rows.** Printed values are the registry's; extra digits are computed here and never replace the printed
value ("values are not improved in transit").

**Answers of the chapter's later subsections.** These take no KA number: the Foundry registry N31-KA (which
depends on this bead) records them as Part 3, ids `foundry/S-1` to `foundry/S-6`, in their one home
`docs/derivations/foundry/derived.md`, and no number is requested for them (an earlier draft of this bead kept
five local ids `D31-1` to `D31-5` and asked for registry numbers). This bead writes their hand derivations as the
six sections of that file's body under N31-KA's ids and table order; N31-KA writes the file's front-matter
records and registers them.

**Recomputation test.** `crates/frob-conformance/tests/foundry_derivations.rs` recomputes every value above
from the inputs in exact rational arithmetic where the formula is rational, and with outward-rounded
intervals where π, a root or an exponential enters, and asserts that the printed value lies inside the
interval rounded to the printed digits. It links no Foundry code.

## Test plan

### Unit tests
`cargo test -p frob-conformance --test foundry_derivations`: one test per row, named `ka_737_cantilever` …
`ka_754_quasi_static_limit`, `s_1_cross_export_tube` … `s_6_member_sizing` (S-3 has no value and is checked
for its section only), each asserting the digits in the tables (for example `ka_742`: Σ = 1,094 and 977;
`ka_745`: 15.990412 and 6.345799; `ka_744`: 0.095002 kg; `s_6`: 1.8453 mm and 0.14087 kg).

### End-to-end script and logging
`scripts/e2e/foundry_derivations.sh` (sources the STD-E2E helper): runs the test target and a link check that
each of the eighteen KA identifiers has its file and each of the six S identifiers its section (the check from
registry rows to files is N31-KA's completeness check, since the rows are entered there, after this bead);
then the two negative controls on a scratch copy (one digit edited in a derivation file; one derivation file
removed), each of which must fail. Logs to `target/e2e-logs/foundry_derivations/<utc-timestamp>.ndjson` with a transcript: every line
has `ts`, `script`, `bead` (`N31b-04`), `step`, `event`, the exact command line, exit code and wall time; per row
the identifier, the printed value with its unit, the recomputed interval, `inside`, and the file's content
digest; on a failure the row, the printed value, the interval and the path of the file. The `summary` counts
rows recomputed (23: eighteen KA rows and S-1, S-2, S-4, S-5, S-6), files and sections present (18 and 6),
files stating a DESIGN tolerance or control for N31-KA (6) and controls caught (2 of 2).

### Known answers and negative controls
The tables are the known answers. Negative controls for this bead: a derivation file whose value is edited by
one digit (the recomputation must fail); a derivation file removed (the link check must fail). Determinism: exact arithmetic; identical everywhere.

## Considerations

- The window-split result 7.816 × 10⁻⁶ depends on the convention that the fifth point closes the first window and opens the second; the derivation states it, because splitting without the shared point gives a different number.
- The proposed controls and tolerances are DESIGN; N31-KA, which depends on this bead, registers them as these files state them, and a change to one is made in both in the same change.
- Constants such as copper resistivity and the Poisson ratio used for the shear estimate are fixture choices and are written in the files.
