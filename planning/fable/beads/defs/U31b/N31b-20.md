## Background

Firmware export (a Moonshot of Foundry, behind feature `firmware-export`) emits fixed-point source for
joint-level controllers: a `no_std`, heap-free crate that forbids unsafe code and sits behind a caller-owned
bus trait, with Q-format declarations, a test-vector manifest, overflow certificates, quantization error
bounds and the no-authorization flags. Its claim is narrow: no intermediate overflows on the declared input
ranges (an instance certificate per controller, class Certified), and the exported arithmetic equals the
simulated arithmetic integer for integer on tested vectors (class Tested, never called equivalence).

GATE-FOUNDRY-11 (Known answer, Moonshot, TARGET, M8): the fixed-point cases of the chapter's known answers
(each counterexample found; the clamped controller certified; a widened input range breaks a certificate);
10⁶ vectors bit-equal. If it fails, KILL-FIRMWARE fires and the export is reduced to controller parameters,
Q formats and the test-vector manifest, with no code.

This bead is the end-to-end measurement of that gate through the released verb, and the discharge record for
proof obligation PO-FOUNDRY-04 (for each exported controller, no intermediate overflows on the declared input
ranges). It runs only if the pilot was positive and the epic was funded.

## Scope

In: the script; the fixtures; the vector comparison; certificate replay; the gate row; the PO-FOUNDRY-04
ledger row.
Out: the mechanism; the pilot (N31b-10); the kill decision (N31b-21).

## Technical approach

**Fixtures** (under `frob-conformance/fixtures/foundry/firmware/`), all Q15 in 16-bit words:
- `pi-clamped`: a proportional–integral loop whose integrator is clamped to ± 32,000 with increments of at
  most 400 counts; inputs declared in [−0.49, 0.49].
- `pi-unclamped`: the same without the clamp.
- `mul-full-range`: a product whose operands are declared over the full Q15 range.
- `neg-full-range`: a negation whose operand is declared over the full range.
- `pd-loop` and `energy-monitor`: two further exportable kinds (a proportional–derivative loop; the
  energy-budget monitor), expected to certify.

**Clauses measured.**
1. *Counterexamples found.* `mul-full-range` is refused with FROB-REF-827 and the counterexample 0x8000 ×
   0x8000 (0x40000000, shifted to 0x8000, read as −1). `neg-full-range` is refused with the counterexample
   −32768. `pi-unclamped` is refused: the inductive step query returns a state from which one increment
   overflows (the documented witness is 32,400; any state of at least 32,368 is accepted as the same
   finding), and the unrolled trace overflows at tick 82.
2. *Clamped controller certified.* `pi-clamped` exports; every intermediate has an interval range or an
   unsatisfiable bit-vector query whose proof stream the independent checker replays; the integrator has a
   base and a step certificate.
3. *A widened range breaks a certificate.* Re-declaring the inputs of `pi-clamped` as [−1, 1) makes at least
   one obligation satisfiable and the export refuse.
4. *Vectors.* The generated crate is built for the host; 10⁶ input vectors (a registered seed; uniformly
   random within the declared ranges, plus all range corners and the sequences that drive the integrator to
   its clamp) are run through the crate and through the exact-integer kernel in the simulator; every output
   and every state word is equal bit for bit.
5. *Artifact properties.* The crate has `#![no_std]` and `#![forbid(unsafe_code)]`, no allocation, no
   register access, no bus driver and no stop-circuit code (a source scan against a deny list and a build for
   a bare-metal target triple); the flags are a constant in the crate and in its manifest; `timing` reads
   `no-claim`; the quantization bound contains the measured difference from the real-valued controller on
   the vectors.
6. *Budget.* The largest query time against the per-obligation budget fixed by the budget decision (2 s by
   default); an undecided obligation is a refusal and fails clause 2 for that fixture.

**Record.** The gate row for GATE-FOUNDRY-11: per fixture the verdict, counterexamples, certificate digests
and replay results; vectors compared and mismatches (0 required); the artifact scan; query-time distribution;
commit, host fingerprint and seed. The PO-FOUNDRY-04 ledger row is updated with the certificate identities.

## Acceptance criteria

- [ ] Clauses 1 to 3 hold on the fixtures: three refusals with their counterexamples, one certified export with replayed proof streams, and a broken certificate under the widened range.
- [ ] 10⁶ vectors are bit-equal between the host-built crate and the integer kernel, including all state words.
- [ ] The artifact scan passes and the crate builds for a bare-metal target without the standard library.
- [ ] Certificates are recorded as class Certified and vectors as class Tested; nothing is recorded as Proved or as equivalence.
- [ ] The gate row and the PO-FOUNDRY-04 row hold measured values; the script exits zero when the measurement is complete, whatever the outcome.
- [ ] The packet written with `--with-firmware` differs from the one without only in `firmware/` and its manifest entries, and both pass the offline auditor.

## Test plan

### Unit tests
`crates/frob-conformance/tests/gate_foundry_11.rs`: `witness_equivalence_class` (any state from 32,368 to
32,767 counts as the integrator finding); `vector_set_contains_corners_and_clamp_sequences`;
`mismatch_report_names_first_vector`; `deny_list_scan_catches_volatile_write` (a planted `write_volatile`);
`clause_table` (the gate passes only if clauses 1 to 5 pass and no obligation is undecided).

### End-to-end script and logging
`scripts/e2e/foundry_firmware.sh`: for each fixture `frob foundry export <fixture> --with-firmware --json`;
for refusals assert exit 3, FROB-REF-827 and the counterexample; for exports build the crate (`cargo build`
for the host and for a bare-metal triple), run the vector harness, replay every certificate with the
independent checker, run the scan. Logs per STD-E2E to `target/e2e-logs/foundry_firmware/`: per fixture
`obligations_total`, `decided_unsat`, `refuted`, `undecided` (0 required for certified fixtures),
`query_ms_max` against the budget, `certificates_replayed`; `vectors` (1,000,000) and `mismatches` (0);
`scan_findings` (0); the evidence block; the summary names GATE-FOUNDRY-11.

### Known answers and negative controls
The fixed-point known answer (the three cases; control: a widened input range breaks a certificate).
Counterexamples "Q15 multiplication cannot overflow" and "an integrator without a clamp is safe if each step
is small". Negative controls: a generated crate with one coefficient altered after export (the vector
comparison must report a mismatch); a proof stream with one record altered (the checker must reject); a
harness that compares only outputs and not state words, against a controller whose state diverges before its
output does (the full comparison must catch what the weak one misses). Determinism: verdicts, counterexample
classes and vector results are identical across runs and backends; query times are not.

## Considerations

- 10⁶ agreeing vectors are a test. The export's claim about all inputs is the overflow certificate only.
- A certificate covers one controller, one set of ranges and one word length; the row records all three.
- The gate runs on a host where the sibling checker is admitted; no device and no board is involved, and no timing is measured.
- If the pilot was negative this bead is closed as `not run: pilot negative` and the gate row says the same.
