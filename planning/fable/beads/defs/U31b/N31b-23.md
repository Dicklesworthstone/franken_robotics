## Background

Lifecycle compression is a Moonshot of Foundry in its own crate, `frob-lifecycle`: slow wear, fatigue,
insulation and cell states are advanced by averaged macro steps so that months of duty can be estimated from
a few million simulated steps. It is off the critical path, and the build packet does not depend on it. Its
kill gate and fallback were named before any measurement.

KILL-LIFECYCLE. Trigger: GATE-FOUNDRY-12 fails. Fallback: aged model variants at hand-specified wear states,
with no time axis and no compression claim. The chapter printed the decision at M8; lifecycle compression is
an M6 item and the gate register sets M6. Decided by an ADR. The workspace rule for the crate is stricter
than for most: if the pilot fails, the crate's fallback is deletion, not absorption into another crate. This
bead is that decision.

GATE-FOUNDRY-12 (Fidelity, TARGET): a 100-hour reference (1.8 × 10⁸ steps) compressed at least 50-fold in
steps with at most 5% error on every slow state; the planted backlash-induced gait collapse caught.

## Scope

In: reading the gate receipt and the pilot record; the decision; the fallback's exact form; downstream
changes; the ADR; the posture until decided.
Out: the measurement (N31b-22); the pilot (N31b-11); the battery-ageing kill gate, which belongs to the
actuator chapter.

## Technical approach

1. **What is read.** From the pilot record: the error at a compression of 50 in steps against 5%, and whether
   the planted collapse forced full resolution. From the gate row: compression; largest error per slow-state
   family at every hourly mark; the collapse clause; the four known answers; the controls.
2. **Decision.**
   - Pilot negative: the epic was never funded; record `killed: fallback adopted` on the pilot's record, the
     gate as `not run: pilot negative`, and the crate is not created (or is deleted).
   - Gate measured and every clause passes: KILL-LIFECYCLE does not fire.
   - Any clause fails (compression under 50, any slow state over 5% at any mark, the collapse not caught): it
     fires. The gate grants no repair cycle; a run voided by a harness defect is repeated once.
3. **The fallback** (if fired). Aged model variants at hand-specified wear states: a caller names a wear
   state directly, for example backlash per joint, capacity fade and resistance growth, a friction change,
   each with its provenance (`hand-specified`). The variant is a new model identity; aged and new robots run
   as per-world variants in one batch, so "does the worn robot still pass?" is one run. There is no time
   axis: no "after N hours", no time to first threshold, no maintenance interval, no mass against service
   duration front, and no compression figure. The verb `foundry.lifecycle` is not registered; aged variants
   are created through the design and model surface, with the label `aged: hand-specified`.
4. **What else changes downstream if it fires.** `frob-lifecycle` is deleted and its firewall rules go with
   it by ADR; the refusal code for lifecycle laws stays registered and unused; the open question on wear,
   insulation and cell-fade coefficients loses its Foundry consumer (the actuator chapter's ageing question
   remains its own); evaluation and adversarial search can still request aged variants, now by wear state.
   Unaffected: fatigue utilization inside one campaign (the structural check), the build packet.
5. **Until decided (fail-closed default).** No report states a service duration, a time to threshold or a
   maintenance interval; aged variants may be made by hand-specified state.
6. **Record.** `docs/adr/KILL-LIFECYCLE.md` with the pilot's and the gate's values, the decision, the
   fallback's surface and the downstream list; the gate rows for KILL-LIFECYCLE and GATE-FOUNDRY-12; a note
   citing the state of KILL-SINEW-AGE; written by a session that did not implement the mechanism.

## Acceptance criteria

- [ ] The ADR exists at M6 with each clause of the gate, or the pilot's falsifier, evaluated against its number (50; 5%; collapse).
- [ ] The KILL-LIFECYCLE row records `pass` on the gate with the kill not fired, or `killed: fallback adopted`, with milestone M6.
- [ ] If fired: an aged variant can be created at a hand-specified wear state and run beside the new robot in one batch; no output carries a time axis or a compression figure; `frob-lifecycle` is absent from the workspace and the packet path still builds.
- [ ] If not fired: every lifecycle output still prints class Estimated and the step-ratio wording.
- [ ] The ADR cites the recorded state of KILL-SINEW-AGE without deciding it.

## Test plan

### Unit tests
`crates/frob-conformance/tests/kill_lifecycle.rs`: `decision_table` (all clauses pass → not fired;
compression 49 → fired; one slow state at 5.1% at one mark → fired; collapse stepped across → fired; pilot
negative → `not run`, fallback, crate absent); `fallback_variant_has_no_time_axis` (schema check: no hours
field); `aged_variant_is_new_model_identity`.

### End-to-end script and logging
`scripts/e2e/kill_lifecycle.sh`: reads the pilot record and the gate receipt, evaluates the rule, prints the
decision; on a fixture registry with the kill fired creates an aged variant (`frob design edit … --set
backlash …` with provenance `hand-specified`), runs new and aged in one batch, and asserts that
`frob foundry lifecycle` is not a registered verb. Logs per STD-E2E to `target/e2e-logs/kill_lifecycle/`:
the clause values, the decision, both model identities, the batch's per-variant verdicts; `summary` with
`gates: ["KILL-LIFECYCLE", "GATE-FOUNDRY-12"]`.

### Known answers and negative controls
Known answer: the decision table. Negative controls: a fallback report that prints "after 1,000 hours"
(rejected by a wording and schema check); a workspace in which the packet path fails to build once the crate
is removed (the firewall's deletion drill must have prevented this); a receipt whose step count omits
settling steps (rejected: the accounting must include every fast step).

## Considerations

- The fallback answers the most useful of the four questions ("does the worn design still pass?") and gives up the other three, which need a time axis.
- The register's milestone (M6) governs over the chapter's (M8); the verb registry's M8 date for `foundry.lifecycle` is the surface's date, not the decision's.
- Killing a Moonshot frees a slot under the cap on active Moonshots; the decision is therefore one step more urgent than the work.
