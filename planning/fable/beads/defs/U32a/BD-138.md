## Background

The verb registry of FrankenRobotics will hold about 243 verbs. An agent harness pays for every tool definition
in its context window on every turn, and a model choosing among hundreds of tools chooses badly. A registry
cluster is only a namespace and can be large (`design` has ten verbs, `analyze` sixteen or more). What an agent
sees is therefore a **task cluster**: at most seven tools chosen for one activity ("make and change a design",
"find out why it failed"), declared in the registry beside the verbs. A verb may sit in several task clusters, and
a lint requires every verb to sit in at least one. The agent moves between clusters with one tool,
`session_focus`.

This bead delivers that mechanism for the M1 verbs on the MCP server `frob-mcp` (the server built on the sibling
library `fastmcp_rust`, with one generic handler `VerbTool` per registry entry), together with the four `session`
verbs. It serves the program risk "the agent surface was too large and agents got lost", whose mitigations are
exactly: clusters of at most seven tools, `session.focus`, `next_actions` and the generated guide.

**Focus is about context size, not authority.** Authority is the session's capability token. Hiding a tool does
not protect anything, and a direct call to a hidden tool is refused only because the library refuses calls to
disabled tools, not because the caller lacks a right.

Design decision ADR-TETHER-01 allows exactly one piece of per-verb code in `frob-mcp`: the MCP half of
`session.focus`, which edits the visible tool set of the connection. Everything else is generated.

## Scope

In: task-cluster declarations for the M1 verbs; the default cluster; the three base tools; `session_focus` on MCP
(enable and disable per connection, the notification, the listing in the result); the four `session` verbs on
both surfaces in their M1 form; `job_wait` and `job_cancel` in their in-process CPU form; the size target; the
M1 parity record for MCP. Out: the fallbacks for clients without session state or without re-listing, and the
compatibility experiment (N32a-12); tokens, scopes and enforced budgets (BD-258, N32a-15); the bounded wait and
cancellation semantics in full (N32a-16, N32a-17); the complete set of seventeen clusters and later verbs
(BD-298).

## Technical approach

**The principal task clusters** (the registry holds the full assignment; at M1 a cluster lists only the tools
whose verbs are registered).

| Task cluster | Activity | Tools |
|---|---|---|
| `orient` (default) | Find out what exists | `capabilities`, `doctor`, `robot_docs`, `schema`, `design_templates`, `scene_list`, `session_show` |
| `author` | Make and change a design | `design_new`, `design_show`, `design_edit`, `design_diff`, `design_check`, `design_import`, `control_synth` |
| `analyze-body`, `analyze-motion`, `analyze-budget` | Static questions | The static analyses, at most seven per cluster |
| `simulate` | Estimate, run, look | `sim_estimate`, `sim_run`, `sim_replay`, `run_fork`, `telemetry_summary`, `telemetry_failures`, `telemetry_stills` |
| `diagnose` | Why it failed | `explain_run`, `autopsy_intervene`, `autopsy_attribute`, `autopsy_show`, `telemetry_query`, `telemetry_inspect_pixel`, `telemetry_energy` |
| `compare` | Paired studies | `study_plan`, `study_submit`, `study_status`, `study_compare`, `eval_promote`, `experiment_suggest`, `predict_register` |
| `mission` | Inverse design | `mission_new`, `mission_check`, `mission_synthesize`, `mission_refute`, `mission_distinguish`, `mission_show`, `result_revalidate` |
| `qualify` | The blinded lane and certificates | `eval_qualify`, `eval_scorecard`, `eval_ledger`, `prove_bundle`, `prove_verify`, `report_design`, `prove_list` |
| `operate` | Watch jobs, artifacts, devices, the session | The job, artifact, device and session verbs, at most seven per cluster (split as `operate` and `operate-2` if needed, DESIGN) |

The clusters `attack`, `learn`, `places`, `search`, `reality` and `make` are declared now and fill at later
milestones. M1 verbs that no principal row lists (`module.*`, `actuator.*`, `algebra.*`, `task.*`, `sense.*`,
`contact.*`, `evidence.trace`, `design.patch`, `design.blame`, `design.view`, `design.export`) are assigned to
further clusters of at most seven (starting assignment, DESIGN, checked by the registry lint): `tasks` (the seven
`task` verbs), `sensing` (the `sense` verbs), `contact`, `modules` (the four `module` verbs with `design_patch`,
`design_view`, `design_export`), `actuators` (the six `actuator` verbs with `design_blame`), `algebra`
(`algebra_irreps`, `algebra_orbits`, `analyze_symmetry`, `evidence_trace`).

**Base tools.** Three tools are always listed and are not counted: `session_focus`, `job_wait`, `job_cancel`.

**Switching, numbered.** `session_focus {cluster}`:
1. Validate `cluster` against the declared names (an unknown name is `FROB-REF-802` with the list of names as the
   repair).
2. Record the focus in the session (the generic half, in `frob-verbs`; the CLI records it too, where it only
   sets the default of `robot-docs --cluster`).
3. MCP half: for each tool of the previous cluster not in the target and not a base tool, call
   `McpContext::disable_tool`; for each tool of the target, `enable_tool`. FACT: the library then omits disabled
   tools from `tools/list`, refuses a direct call to one, and emits its catalog-changed notification.
4. Return an envelope whose result lists the names and one-line purposes of the now-visible tools, for clients
   that do not act on the notification.

A new connection starts focused on `orient`: at start-up every tool outside `orient` and the base three is
disabled for that connection. TARGET: the definitions of the base tools plus one task cluster occupy at most
12 kB of `tools/list`.

**The `session` verbs (cluster `session`; M1 form).**

| Verb | Kind | Input | Result | Refusals |
|---|---|---|---|---|
| `session.open` | mutate | `scopes` (list), `budget` (map of unit to amount), `namespace` (optional), `idempotency_key` | `session` identifier, `namespace`, the scopes and budgets recorded, the focus (`orient`) | 802, 805, 803 |
| `session.show` | read | none | scopes, budgets left per unit, namespace, focus, visible tools; from M2 also the daemon's overhead line | 802 |
| `session.focus` | mutate | `cluster` | the now-visible tools with one-line purposes | 802 |
| `session.close` | mutate | `idempotency_key` | the reservations released and the final spend | 802, 805 |

At M1 a session is a local record: one principal, a namespace, a focus and declared budgets, of which the
CPU-seconds budget is enforced by the in-process job engine. Authenticated, attenuable tokens and device budgets
replace this record without changing the four schemas. Example (from the worked mission session):
`frob session open --scopes design:write,mission:run,nemesis:run,autopsy:run,sim:run,qual:run --budget
gpu_s=1800,cpu_core_s=7200 --json` returns exit 0 with a session identifier and the namespace `agent-17`.

**`job_wait` and `job_cancel` at M1.** With no daemon, a long CPU `run` tool is executed by the in-process job
engine and its tool call returns a handle when its wait elapses. `job_wait {job, sync_wait_ms}` re-attaches to
the job; `job_cancel {job}` requests cancellation and returns the receipt. The envelope carries the warning
`executor: in-process`. If the server process dies, the job stays in the ledger and is resumed from its last
committed checkpoint by the next process that opens the ledger.

Determinism: `tools/list` for a given focus is a pure function of the registry. Evidence: session verbs return
class `Tested`, tier `static`, `claims: []`.

## Acceptance criteria

- [ ] The parity diff for the M1 verbs is empty and the served `tools/list` (all clusters listed) equals the registry under the name map.
- [ ] After `session_focus` to any declared cluster, `tools/list` holds at most seven tools plus the base three, and exactly the tools the registry assigns to that cluster.
- [ ] A new connection lists `orient` plus the base three and nothing else.
- [ ] A direct call to a tool outside the focus is refused by the library; after focusing on its cluster the same call succeeds.
- [ ] The result of `session_focus` lists every now-visible tool with a purpose line.
- [ ] For every declared cluster, the serialized `tools/list` result of the base tools plus that cluster is at most 12 kB (TARGET; the measured maximum is recorded).
- [ ] The four session verbs have schemas, examples and refusal lists and answer identically on the CLI and over MCP.
- [ ] A `run` tool that outlives its wait returns exit 8 with a job handle, and `job_wait` returns the result.

## Test plan

### Unit tests (`cargo test -p frob-mcp focus`, `cargo test -p frob-verbs session`)
- `default_focus_is_orient`: in-memory transport, fresh connection → 7 + 3 tools, names equal the `orient` row.
- `focus_author_lists_exactly_author`: `design_new`, `design_show`, `design_edit`, `design_diff`, `design_check`, `design_import`, `control_synth` plus the base three.
- `focus_result_lists_tools`: the envelope's result has one entry per visible tool.
- `hidden_tool_call_refused`: `mission_synthesize` while focused on `author` → library refusal; after `session_focus {cluster: "mission"}` → accepted.
- `unknown_cluster_802`: `session_focus {cluster: "authr"}` → 802 with the declared names.
- `cluster_size_at_most_seven`: over all declared clusters.
- `union_of_clusters_is_registry`: every registered verb appears in at least one cluster.
- `list_bytes_at_most_12k`: per cluster, the byte length of the serialized list.
- `focus_is_not_authority`: with a synthetic token lacking `mission:run`, focusing on `mission` shows the tools and a call is refused with `FROB-REF-720`, exit 5.
- `session_open_show_close_roundtrip`: budgets declared are the budgets shown; close releases them.
- `two_connections_independent_focus`.

### End-to-end script and logging
`scripts/e2e/mcp_m1_clusters.sh`: starts the real `frob-mcp` over stdio and over loopback HTTP; lists tools;
focuses on each declared cluster in turn and lists again; runs the M1 studio sequence through tools
(`design_new`, `design_check`, `design_edit`, `design_check`, `control_synth`, `sim_run`, `explain_run`) with
focus changes between `author`, `simulate` and `diagnose`; runs one long `mission_synthesize` with
`sync_wait_ms: 0` and holds it with `job_wait`. It sources the shared helper and writes
`target/e2e-logs/mcp_m1_clusters/<utc>.ndjson` plus a wire transcript: `cmd` lines per tool call with exit code
and wall time, the envelope `evidence` block, `metric` lines for tools listed per focus (threshold 7 + 3), list
bytes per cluster (threshold 12,000), `assert` lines for each list against the registry row; a `summary` naming
GATE-TETHER-02 and the focus clause of GATE-TETHER-12.

### Known answers and negative controls
- Known answers: the `orient` and `author` rows above; the base set of three.
- Negative controls: a registry with eight tools in one cluster (the build must fail); a server build that skips `disable_tool` on focus (the list test must find more than ten tools); a verb in no cluster (the lint must fail).
- Determinism lanes: list bytes per focus identical twice on one machine, on both transports, in debug and release.

## Considerations

- OPEN-TETHER-2 (do the agent harnesses in use speak one of the two protocol eras the library serves, and act on catalog-changed notifications; owner: Tether lead; blocks GATE-TETHER-12) is open. Fail-closed default: static clusters by launch flag plus the generic tool `verb_invoke`. Those fallbacks and the experiment are a separate bead; this bead's `session_focus` result already lists the visible tools for clients that ignore the notification.
- FACT: when a connection has no session state, `disable_tool` reports failure; the handler must surface that as a warning naming the fallback and must not pretend the list changed.
- The plan dates the session verbs at M0 in its verb appendix and builds them here at M1; they were registered as declared at M0.
- The assignment of unlisted verbs to further clusters is a starting assignment; the fresh-agent gates decide whether it helps.
