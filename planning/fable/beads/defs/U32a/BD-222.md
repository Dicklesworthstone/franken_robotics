## Background

Milestone M2 brings the batched tiers, the two GPU backends, model families, sensors on devices, on-device
training and the daemon `frobd`. Each of those arrives with verbs. This bead registers them: every verb whose
first milestone is M2 becomes an entry of `registries/verbs.toml` (compiled into the static table of the crate
`frob-verbs`, from which the CLI, the MCP tools, the schemas and the agent guide are generated) with an input
schema, an output schema, at least one runnable example and a refusal list, and the surface parity gate is
recorded for the M2 set.

As at M1 this is integration work. A verb's computation is built by its subsystem's bead (this bead's
dependencies); here it gets its thin binding in `frob-verbs::handlers`, its registry entry, its schemas, its
golden envelope and its honest status. What is new at M2 is the daemon: `run` verbs now submit jobs to `frobd`,
take budgets with estimates, accept the bounded synchronous wait and can return exit code 8 with a job handle;
`admin` verbs appear (`job.cancel`, `train.stop`, `study.cancel`, `store.collect`, cache eviction); and verbs
that export an artifact carry the three no-authorization flags.

GATE-TETHER-02 (Known answer, TARGET): the CLI and MCP surfaces are generated from the registry and their parity
diff is empty; every verb has a schema, an example and a refusal list; the served `tools/list` equals the
registry under the name map (`.` and `-` replaced by `_`).

## Scope

In: schemas, examples, bindings, golden envelopes and status for the M2 set, and the check that each M2 verb's
registry row (entered once by its cluster's registry bead, VERBS-<cluster>) is complete and seated in the
task-cluster assignment of NJL-05; the daemon-era common properties on every `run` verb; the M2 parity record. Out: each
verb's computation; the parity harness (N32a-11); idempotency, cursors and number types (BD-211 and its
mechanism beads); budgets (N32a-15); the wait (N32a-16); the M3 safety gates on flags and untrusted text.

## Technical approach

**The checklist per verb** (the same seven items as at M1): a complete `[[verb]]` entry; two schemas using only
`int53`, `u64str` and `i64str` for integers, with units on quantities and the untrusted mark on fields that echo
imported text; at least one example that runs on the fixtures; a refusal list made of the handler's own codes
plus the common codes of its kind; a golden envelope; a binding with no computation; a truthful `capabilities`
row.

**Common codes by kind.** One rule for every milestone, the appended sets of the registry's entry schema (NJL-01),
exactly as at M1 (BD-137): `read` 720, 723, 724, 802, and a paginated read also 806, 807; `run` 701, 702,
703, 704, 720, 723, 724, 761, 802, 803, 805, 808 (761: the job exceeds the compute envelope in force, exit 4,
refused by the envelope admission before any queue, so every `run` verb can return it; 808 through
`sync_wait_ms`); `mutate` 720, 723, 724, 725, 802, 803, 804, 805 (805 omitted for a `key_optional` row, N32a-02
RL-21); `admin` 720, 723, 724, 802.
NJL-01 also appends codes from fields: 808 for an entry of any kind with an `int53` input (a code is listed
where it can be raised, so a `read` or `mutate` with string inputs only does not carry it); 790 for a row with
a non-empty `needs_groups` (a required foundation
group absent from the build, exit 5); 891 for a parameter of kind `artifact-input<F>`, `artifact-ref<F>` or
`artifact-identity<F>`, 892 also for an `artifact-identity<F>`, 893 for a `foreign-file`; and 734 (path jail,
exit 5) with 828 (the dispatcher's payload sniff, exit 3) for every parameter that accepts a path to a file
(`artifact-input<F>`, `artifact-identity<F>`, `foreign-file`). The token codes 720 and 723 are in every list
before tokens exist, because a list is what a verb may return over its schema's life. (An earlier draft of this
bead had a shorter daemon-era list, without 704, 723 and 761, and 720 only once tokens exist; a later one put
808 on every `read` and `mutate`.) The
backend-unavailable codes (`6xx`) a device-tier `run` verb can return are chapter codes in its row's own list,
not appended.

**Common properties added by kind** (identical on both surfaces): `run` adds `sync_wait_ms`, `idempotency_key`,
`budget`, `estimate_only`, `on_cancel`, `envelope_scope`; `mutate` adds `idempotency_key` and `expected_parent`. Every `run` verb
whose cost model can exceed one second is `estimable = true` (the lint `estimate-required` of N32a-15).

**Daemon-era conformance per `run` verb** (table-driven): without a key → 805; with `estimate_only` → an estimate
and no job; over budget → 701 with the estimate; with `sync_wait_ms: 0` → exit 8 and a handle whose `job_wait`
returns the result; retried with the same key → `idempotent_replay: true`; without the daemon and needing a
device → `FROB-REF-601` with `pointer: daemon`, exit 6, first repair "start `frobd`" (the dispatch route of
N32a-04).

**Task clusters** (as NJL-05's assignment seats the M2 verbs; that table governs and this bead checks it).
`simulate` completes (`sim_estimate`, `sim_run`, `sim_replay`, `run_fork`,
`telemetry_summary`, `telemetry_failures`, `telemetry_stills`); `learn` fills (`train_start`, `train_status`,
`train_stop`, `train_export`, `eval_run`, `sim_estimate`, `telemetry_summary`); `places` part-fills
(`scene_gen`, `scene_compile`, `scene_list`, `scene_show`, `telemetry_stills`, `design_check`); `operate` gains
`job_list`, `job_status` and `job_find` (`job_wait` and `job_cancel` become base tools, and `store_status` and
`store_collect` sit in `housekeeping`); `devices` holds the seven `spark` verbs; `families` the `phylum` verbs; `fidelity` its
verbs.

**Gate run.** `scripts/e2e/tether_parity.sh --through M2` (N32a-11's script) against `frob` with `frobd` running
and `frob-mcp`. The M2 record of GATE-TETHER-02 is made from that run's receipt with `cargo run -p
frob-conformance --example record_gate -- --gate GATE-TETHER-02 --receipt <hash>`; no script writes a gate row.
Examples are run after the identity substitution of NJL-02, and this bead adds the rows of
`fixtures/verbs/identities.toml` for the examples its handlers make run (as BD-137 does at M1).

## Acceptance criteria

- [ ] GATE-TETHER-02 for the M2 verbs: empty parity diff; a schema, an example and a refusal list for every M2 verb; `tools/list` equals the registry under the name map; measured counts recorded.
- [ ] Every M2 `run` verb passes the daemon-era conformance table above.
- [ ] Every M2 `admin` verb is refused without its scope (tested with a synthetic restricted token until real tokens land) and names the scope in the refusal.
- [ ] `sim.estimate` and `phylum.plan` run no physics: no job row, no device call.
- [ ] Every exporting M2 verb's envelope carries `execution_authorized`, `hardware_safety_signoff` and `sim_to_real_certified`, all `false`.
- [ ] No M2 schema has a bare integer; world addresses, seeds, ticks and instants are `u64str`.
- [ ] `frob capabilities --json` reports each M2 verb's true status per device family (resolved modes and ceilings per device).
- [ ] Golden envelopes for every implemented M2 verb pass the double-decoding client.

## Test plan

### Unit tests (`cargo test -p frob-verbs handlers_m2`, `cargo test -p frob-conformance golden`)
- `every_m2_entry_complete` (table-driven checklist).
- `appended_refusals_one_rule`: the appended list of every M2 verb equals the entry schema's set for its kind and fields (the same assertion as BD-137's `common_refusals_by_kind`); a `run` verb's list contains 704, 723 and 761; every M2 row with a parameter that accepts a path to a file contains 734 and 828, and every M2 row with a non-empty `needs_groups` contains 790 (both enumerated from the registry, not listed by hand).
- `study_cancel_declared_at_m2`: 724, exit 5, `capabilities` shows it not implemented, and `job.cancel` on the study's job cancels it.
- `run_verb_conformance_table`: the six daemon-era rows for each M2 `run` verb.
- `admin_requires_scope`: `job.cancel`, `train.stop`, `study.cancel`, `store.collect`, `spark.cache --action evict`, `fidelity.shadow`.
- `two_kind_verb_actions`: `spark.cache` with no `--action` runs its default action, kind `read`, under `spark:read`; `--action evict` is `admin` under `spark:admin` (refused `FROB-REF-720` without it); `--action show` is `FROB-REF-802` (the default action has no name to pass, NJL-01 action rule 1).
- `estimate_verbs_run_nothing`.
- `export_flags_present`: `train.export`, `telemetry.export-html`.
- `sim_replay_tier_argument`: `--tier` accepted values are the registered tiers; an unknown tier is 802.
- `capabilities_per_device`: a verb implemented on one device family and not the other is reported so.

### End-to-end script and logging
`scripts/e2e/m2_verbs.sh` (seed-explicit; its own state root; `frobd` running): the estimate-run-look loop on a
batched tier: `frob sim estimate quad-a --scene terrain:stairs@0.4 --worlds 2048 --seconds 20 --tier <tier>
--json`; `frob sim run … --key r1 --sync-wait-ms 0 --json` (exit 8); `frob job wait <job> --json`;
`frob telemetry stills <run> --world 311 --at failure --json`; `frob sim replay --run <run> --world 311 --tier referee
--key t1 --json`; `frob run fork <run> --world 311 --before failure --classify-only --key f1 --json` (`run.fork` is a `run` verb, so it
carries a key even when it only classifies); `frob job list --json`; then the parity script. (Keys are shown by
their labels; the script writes each as `--key "$(e2e_key <label>)"`.)
It sources the shared helper and writes `target/e2e-logs/m2_verbs/<utc>.ndjson` plus a transcript: `cmd` lines
with exit code and wall time; the envelope's `evidence` block (class, tier, determinism, identities, seed) per
call; `assert` lines for expected exit codes, job-handle continuity and the flags on exports; `metric` lines for
estimate against actual cost; a `summary` naming GATE-TETHER-02 (M2).

### Known answers and negative controls
- Known answers: empty diff with one exemption; registry, CLI and MCP counts equal for the M2 set.
- Negative controls: an M2 `run` verb registered without `estimable` although its cost model exceeds one second (the lint must fail); an exporting verb without the flags (schema validation must fail); a `run` binding that bypasses the admission guard (the missing-key test must fail).
- Determinism lanes: generated documentation and golden envelopes identical twice on one machine, in debug and release, on both hosts.

## Considerations

- A verb can be implemented on `batch-cpu` and not yet on a device; `capabilities` is per device for that reason, and a call on an unsupported device is the backend-unavailable family (exit 6), not 724.
- Until capability tokens land, admin verbs are protected only by the local user boundary; the scope checks are exercised with synthetic tokens so that the control flow is already the final one.
- The plan dates `fidelity.shadow` at M3 in its verb appendix while its mechanism bead is at M2; it is registered here and reported by status.
- The M2 exit lists GATE-TETHER-04, -05, -06 and -08; this bead contributes the registry side only.
