## Background

Every costly verb of FrankenRobotics can be asked what it will cost before it runs, and a job is admitted only if
the **upper end** of its cost interval fits the remaining budget. An interval that is too narrow admits jobs that
then hit a budget stop, which publishes nothing and wastes the whole spend. An interval that is too wide refuses
questions that would have fitted. So the interval has to mean what it says: a "90% interval" should contain the
actual cost about 90% of the time.

The plan's choice is a **split-conformal interval per stratum** (tier Solid). It needs no distributional
assumption about the cost model's error, only that the errors of recent jobs in the same stratum are
exchangeable with the next one's. Until a stratum has enough history the interval is honestly labelled
`uncalibrated` and admission uses a fixed factor of 2 (DESIGN, conservative). Alternatives implied and excluded:
a Gaussian error bar around the model (cost errors are skewed and heavy-tailed); one global calibration (a new
driver or a different shape class has different errors).

FACT: the suite has a conformal calibrator to follow (`asupersync/src/lab/conformal.rs`, `ConformalCalibrator`,
`CalibrationReport`). It calibrates that library's own test-oracle metrics and is not a general interval
library, so the pattern is followed here and its code is not linked for this purpose.

This is the seed bead for "estimates and budgets: calibrated intervals per stratum"; the budget accounting
itself (reservation, upper-end admission, attributable device time) is an earlier bead and is only consumed here.

## Scope

In: strata and their epochs; the residual windows; the interval and its index in exact integer arithmetic; the
`calibrated` and `uncalibrated` labels; persistence; the prequential coverage record; the calibration monitor

admission (N32a-15); the scheduler's reaction to unreliable estimates (N32a-21, BD-296).

## Technical approach

**Definitions.** The cost model gives a point prediction ŷ > 0 for a quantity (GPU seconds, CPU core-seconds,
memory bytes, disk bytes). A **stratum** is (verb, tier, device family, shape class). For each stratum and
quantity the daemon keeps the last n absolute log residuals of finished jobs,

    r_i = | ln( y_i ÷ ŷ_i ) |

where y_i is the actual cost. At miscoverage α the half-width q is the k-th smallest residual with

    k = ⌈ (n + 1)·(1 − α) ⌉

and the interval is [ ŷ·e^(−q), ŷ·e^(q) ].

**The index in exact arithmetic.** With α = a ÷ b (α = 0.10 is 1 ÷ 10; α = 0.05 is 1 ÷ 20),
k = ((n + 1)·(b − a) + b − 1) div b, computed in integers; floating point is never used for the index. The index
exists only when k ≤ n: that is n ≥ 9 at α = 0.10 and n ≥ 19 at α = 0.05 (DESIGN arithmetic). Examples: n = 9,
α = 0.10 → k = 9 (the largest); n = 19, α = 0.05 → k = 19 (the largest); n = 19, α = 0.10 → k = 18; n = 199,
α = 0.10 → k = 180.

**Labels.** The daemon reports the 90% interval and calls a stratum **calibrated from n = 19**, so one stratum
serves both levels. Below that the envelope marks the interval `uncalibrated` and uses the fixed factor:
[ŷ ÷ 2, ŷ × 2].

**Why it covers (proof obligation PO-TETHER-04; class Tested).** If the residuals r_1, …, r_n of the window and
the next job's residual r_(n+1) are exchangeable, the rank of r_(n+1) among the n + 1 values is uniformly
distributed over {1, …, n + 1} (ties counted against coverage). Hence P(r_(n+1) ≤ k-th smallest of the window) ≥
k ÷ (n + 1) ≥ 1 − α. And r_(n+1) ≤ q is exactly ŷ·e^(−q) ≤ y ≤ ŷ·e^(q). The guarantee is marginal over jobs in
the stratum, not conditional on a particular job. Verification: the rank argument written in `CONTRACT.md`, and
empirical coverage in the gate.

**Epochs.** A driver, compiler or kernel-version change starts a new stratum, since exchangeability across it is
not credible. The stratum key therefore includes an epoch digest taken from the hardware fingerprint's driver
and compiler fields and the kernel library version; on a change the old window is archived, n restarts at 0 and
the stratum reports `uncalibrated` until it has 19 points again.

**Window (DESIGN).** The last 199 residuals per (stratum, quantity): a sliding window, so that slow drift is
followed, sized so that (n + 1)·(1 − α) is an integer at both levels when full. Stored in the ledger
(`estimate_residual(stratum, quantity, seq, residual)`), updated in the same transaction that settles a job's
budget. A job whose actual or predicted cost is below one millisecond or one byte is floored to that unit before
the logarithm; cancelled and budget-stopped jobs contribute no residual (their actual cost is censored) and are
counted separately.

**Prequential coverage record.** When a job is admitted, the interval issued to it is stored with the job. When
it finishes, the stored interval is scored against the actual cost: covered or not. The job's own residual
enters the window only after that. Every scored job is therefore held out from the interval that judged it. The
record per stratum: jobs scored, covered count, coverage, the calibration label at issue time.

**Calibration monitor.** Two figures are exported per stratum for the scheduler's decision model and the
dashboard: of the last 50 finished jobs, how many ran over twice their point estimate (the fallback trigger is
20%), and the rolling coverage of the 90% interval. A stratum whose rolling coverage over the last 50 scored
jobs falls below 80% is relabelled `uncalibrated` and its window is restarted (DESIGN: treated as an undetected
epoch change).

**Surface.** The estimate block of an envelope carries, per quantity, `point`, `lo`, `hi`, `level: 0.90`,
`calibration`, `n`, and the stratum; `session.show` and the dashboard's queue pane show estimate against actual
and the calibration of the interval per stratum.

Determinism: the interval is a pure function of ŷ and the stored window. Evidence class: Tested for coverage;
the estimate itself is `Estimated`.

## Acceptance criteria

- [ ] GATE-TETHER-11 (TARGET): the 90% estimate interval covers the actual cost in 85% to 95% of at least 200 held-out jobs per stratum; a stratum with fewer than 19 points reports `uncalibrated`. The record lists every stratum measured with its count and coverage.
- [ ] The index function returns the documented k for the example pairs and never uses floating point; for n below the threshold it returns "no index".
- [ ] KA-759: at n = 19 and α = 0.05 the half-width is the 19th smallest residual, the largest.
- [ ] An epoch change (a changed driver field in a synthetic fingerprint) restarts the stratum as `uncalibrated`.
- [ ] Coverage is prequential: a test proves that a job's residual is not in the window that produced its own interval.
- [ ] On synthetic exchangeable residuals (log-normal, 10⁵ jobs) the empirical coverage of the 90% interval is at least 90% minus sampling error; on a planted shift without an epoch change the monitor relabels the stratum within 50 jobs.
- [ ] Admission uses `hi`; an `uncalibrated` stratum admits on 2·ŷ.
- [ ] The residual windows survive a daemon restart.

## Test plan

### Unit tests (`cargo test -p frob-verbs conformal`)
- `index_examples`: (n, α) → k: (9, 1/10) → 9; (8, 1/10) → none; (19, 1/20) → 19; (18, 1/20) → none; (19, 1/10) → 18; (199, 1/10) → 180; (199, 1/20) → 190.
- `index_is_integer_arithmetic`: a property test against a big-rational reference for n up to 10⁴.
- `interval_from_window`: residuals {0.05, 0.10, …, 0.95} (n = 19), ŷ = 100 → at α = 0.10, q = 0.90, interval [100·e^(−0.9), 100·e^(0.9)] = [40.66, 245.96]; at α = 0.05, q = 0.95 → [38.67, 258.57].
- `uncalibrated_below_19`: n = 18 → label `uncalibrated`, interval [50, 200] for ŷ = 100.
- `calibrated_at_19_serves_both_levels`.
- `epoch_change_restarts`.
- `prequential_excludes_self`.
- `censored_jobs_add_no_residual`: a budget-stopped job leaves the window unchanged.
- `floor_small_costs`: y = 0 is floored, no infinite residual.
- `coverage_on_exchangeable_synthetic`: 10⁵ jobs, seed 1 → coverage in [0.895, 0.915].
- `monitor_relabels_on_shift`: residual scale tripled at job 1,000 → relabelled by job 1,050.
- `window_slides_at_199`.

### End-to-end script and logging
`scripts/e2e/estimate_coverage.sh --lane batch-cpu|cuda|metal --seed <s>`: with `frobd` running, submits a
seeded workload of at least 220 jobs per stratum for the reference strata (`sim.run` on each available tier
and two shape classes; `study.submit` on one), each preceded by `--estimate`; reads the prequential record;
then moves the synthetic epoch and checks the label. It sources the shared helper and writes
`target/e2e-logs/estimate_coverage/<utc>.ndjson` plus a transcript: `cmd` lines with exit code and wall time;
per job a `metric` line with ŷ, `lo`, `hi`, the actual cost and covered or not; per stratum a `metric` line with
jobs scored (threshold ≥ 200), coverage (thresholds 0.85 and 0.95), n and the label; `assert` lines for the
`uncalibrated` label below 19; the envelope `evidence` block; a `summary` naming GATE-TETHER-11 with the number
of strata passing.

### Known answers and negative controls
- KA-759 (exact index): the conformal index at n = 19, α = 0.05 is the 19th smallest residual, that is, the largest.
- Known arithmetic: the index exists for n ≥ 9 at α = 0.10 and n ≥ 19 at α = 0.05.
- Negative controls (each must be caught): an index computed as ⌈n·(1 − α)⌉ instead of ⌈(n + 1)·(1 − α)⌉ (coverage on the synthetic set falls below 90% for small n, and `index_examples` fails); a window that includes the job's own residual before scoring (the prequential test fails, and coverage is biased upwards); intervals built on raw instead of log residuals for a skewed model (coverage of the lower end fails); a stratum that ignores the epoch (the planted driver change shows under-coverage).
- Metamorphic relation: multiplying every actual and predicted cost in a stratum by a constant leaves every residual, and so every relative interval, unchanged.
- Determinism lanes: unit tests twice, debug and release; the device lanes record measured coverage and are not expected to repeat exactly.

## Considerations

- Sampling noise: with 200 jobs and true coverage 0.90 the standard deviation of the observed coverage is about 0.021, so the 85% to 95% band is about ±2.4 standard deviations; a correct stratum fails by chance roughly once in fifty. A stratum that fails is re-measured once with new seeds before it is recorded as failing, and both results are kept.
- Exchangeability is an assumption. Workloads whose cost depends on something the stratum does not key (scene complexity, contact count) will show under-coverage; the remedy is a finer stratum or a better ŷ, and the monitor is how it is noticed.
- The interval is marginal: it says nothing about one particular job. The generated guide words it so.
- Memory and disk estimates are checked by preflight at admission and have their own windows; their intervals matter for refusal quality, not for budget stops.
- The window length of 199 is DESIGN; the plan says "the last n".
