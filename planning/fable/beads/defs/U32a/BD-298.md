## Background

By milestone M3 FrankenRobotics has its places, tasks, adversaries and qualification lane, and with them about
two hundred verbs. The MCP server `frob-mcp` (built on the sibling library `fastmcp_rust`, a member of the core
build graph, with one generic handler per registry entry) must present all of that to agent harnesses in a form
they can actually use: a few tools at a time, long work that neither blocks nor needs constant polling, progress
with denominators, cancellation that does not destroy paid work, reading material as resources, and standard
workflows as prompts.

Each of those pieces is built by its own bead. This seed bead is the integration: it assembles them into the
full surface on the M3 daemon (shared slot dispatch, capability tokens), checks on the served surface that the
one task-cluster assignment (NJL-05's) seats every verb registered by M3, applies the outcome of the harness compatibility experiment to the default launch
configuration, cites the kill-gate decision on the Tasks extension (N32a-29's record), and measures the surface
gate.

GATE-TETHER-12 (Known answer; M3; TARGET): *every `run` tool returns within its `sync_wait_ms` plus 500 ms with
a result or a handle; a wire-cancelled wait leaves the job running; after `session_focus` the list holds at most
seven tools plus the base three; each resource kind is listed and readable; prompts match `robot-docs`.*

The claim made for this surface is deliberately narrow. MCP access to a simulator is prior art (FACT: one
incumbent ships an MCP server for documentation lookup, and a community server exposes 42 tools that drive that
simulator; neither documents compute budgets, provenance or a typed refusal taxonomy). What is claimed is that
every verb carries a compute budget, provenance and a typed refusal, and that both surfaces are generated from
one registry.

## Scope

In: the served-surface check of the task-cluster assignment for every verb registered by M3; integration of wait, progress, cancellation, resources, prompts and
transports on the M3 daemon; the default launch configuration; the parity harness extended to resources and

Out: each mechanism (its own bead); the assignment of verbs to task clusters, its lints (at most seven tools;
every verb seated; no base tool in a cluster) and the list budget on the generated definitions (NJL-05, a

injection sweep over every echoing verb on the hostile corpus (BD-304, which depends on this bead).

## Technical approach

**The seventeen task clusters** (quoted from the registry; NJL-05's assignment governs if the two ever differ).
Fourteen named clusters, two further analysis clusters and `operate`. Three
base tools are always listed and are not counted: `session_focus`, `job_wait`, `job_cancel`.

Verbs of the subsystem clusters that no principal row lists are seated by NJL-05 in further task clusters of at
most seven (45 clusters in all: the seventeen principal ones, eleven further ones the registry appendix names,
and seventeen NJL-05 adds so that every verb has a seat; among them `families`, `fidelity`, `audit`, `contact`,
`sensing`, `gaits`, `shield`, `tasks`, `devices`, `inherit`, `ladder`). This bead keeps no list of its own: an
earlier draft carried a starting assignment of those clusters, withdrawn in favour of NJL-05's as BD-138's was,
because the lint "every verb sits in at least one task cluster" can only be checked against one table, and its
M-focus measurement reads the rows from the registry. A cluster lists a tool only once its verb is registered; tools of M4 and
M5 verbs appear as declared and answer `FROB-REF-724` until implemented. TARGET: the definitions of the base
tools plus one task cluster occupy at most 12 kB of `tools/list`.

**Integration points, numbered.**
1. *Daemon.* Every `run` tool submits through the in-process dispatch back end to `frobd` (shared slot dispatch)
   under an idempotency key; `frobd --mcp` hosts the same server.
2. *Authority.* Every call carries the session's capability token (from the environment on stdio, from the bearer
   token on HTTP); focus changes context size, never authority.
3. *Wait.* `sync_wait_ms` default 5,000, maximum 30,000, 0 for an immediate handle; exit 8 with a handle when the
   timer wins; the server's request timeout is 40 s.
4. *Progress and cancellation.* Each progress frame has a numerator, a denominator and a unit; a cancelled wait
   leaves the job running unless the call set `on_cancel: "cancel_job"`; `job_cancel` drains in the daemon.
5. *Resources.* The seven groups under `frob://` (documentation; capabilities and registry; schemas; twelve
   catalogs; stills; reports and certificates; jobs and run summaries), thirteen URI forms in all (N32a-25),
   each a view of a verb, at most 4 MiB per read, never a filesystem path.
6. *Prompts.* `studio_loop`, `mission_query`, `diagnose_failure`, `qualify_design`, `compare_designs`,
   `import_robot`, `calibrate_to_reality`, generated from the same worked examples as `robot-docs`; arguments
   are identifiers only.
7. *Launch default.* From the harness compatibility record: dynamic focus if every harness in use re-lists on
   the catalog-changed notification; otherwise static clusters by launch flag plus `verb_invoke` (the
   fail-closed default of OPEN-TETHER-2).
8. *Parity.* The parity harness gains a resource extractor (every resource equals its source verb) and a prompt
   extractor (every prompt's steps equal the guide's).

**The five measurements.**
- *M-wait:* for every `run` tool whose verb is implemented in the build (a declared M4 or M5 tool answers
  `FROB-REF-724` at once and is logged as such), with a job that outlives the wait, time from request to response
  minus `sync_wait_ms`, at waits of 0, 5,000 and 30,000 ms; threshold 500 ms. Each submission computes: a tool
  whose row sets `memo = true` is called with `no_memo: true` (NJL-01 variation 14), since a result served from
  the memo graph returns at once and would measure no wait.
- *M-cancel:* a wire cancellation during the wait, per transport; the job must be `running` afterwards and reach
  `complete` with the digests of an uncancelled run of the same input under its own key (both with
  `no_memo: true` where the row has it).
- *M-focus:* after `session_focus` to each of the declared clusters, `tools/list` holds at most seven tools plus
  the base three, and exactly the registry's assignment.
- *M-resources:* each resource kind listed (or templated) and read.
- *M-prompts:* each prompt's step list equals `robot-docs --workflow`.

Determinism: lists, resources and prompts are pure functions of the registry and the store at a frontier;
timings are measurements. Evidence class of the gate: Tested.

## Acceptance criteria

- [ ] GATE-TETHER-12 (TARGET), all five clauses, on stdio and loopback HTTP, with measured values recorded (`cargo run -p frob-conformance --example record_gate -- --gate GATE-TETHER-12 --receipt <hash>`): every `run` tool returns within its `sync_wait_ms` plus 500 ms with a result or a handle; a wire-cancelled wait leaves the job running; after `session_focus` at most seven tools plus the base three; each resource kind listed and readable; prompts match `robot-docs`.
- [ ] KILL-MCPTASKS is decided (N32a-29) and its ADR is cited by this bead's closing note; the GATE-TETHER-12 record states which branch was in force when the gate was measured.
- [ ] INT-FMCP-01, full-surface form: `frob-mcp` builds in the core graph on T with one asupersync package and lists the tools generated from the whole registry.
- [ ] On the served surface (the registry lints are NJL-05's): every registered verb is listed in at least one focused cluster; no focused list exceeds seven tools plus the base three; the union over clusters equals the registry; the largest served cluster list is at most 12 kB.
- [ ] The parity diff, now including resources and prompts, is empty with exactly one exemption.
- [ ] The default launch configuration matches the recorded decision on OPEN-TETHER-2.
- [ ] Four concurrent sessions with different tokens each see only their own namespace's jobs and budgets through tools and resources.
- [ ] No tool description, prompt, server instruction or `next_actions.command` contains text that originated in an import (INV-TETHER-13), on a store seeded by the script's own imports whose design names, link names and metadata carry planted instruction-like strings.

### End-to-end script and logging
`scripts/e2e/mcp_full_surface.sh --transport stdio|http --seed <s>` (header: `bead=BD-298 milestone=M3
labels=tether,mcp gates=GATE-TETHER-12,INT-FMCP-01 seed=298 timeout_s=3600 needs=cpu,frobd,mcp
plants=ignore-timer,cancel-on-wire,eighth-tool,resource-removed,prompt-edited,name-in-description`, each plant one
negative control below; the timeout covers about fifty implemented `run` tools at waits of 0, 5 and 30 s, some
29 minutes of waiting per transport): grants four principals with `e2e_session grant` before it starts `frobd`
(shared dispatch), then opens one session each with `e2e_session open` (from M2 a call without a token is
`FROB-REF-723`) and starts `frob-mcp` under each session's token (environment on stdio, bearer token on HTTP);
imports the planted-string fixtures (`frob design import <fixture> --key "$(e2e_key imp-<i>)" --json`); for each
`run` tool submits a slow fixture and measures M-wait at three waits, each of the three a separate submission
under its own `idempotency_key` (`"$(e2e_key mw-<verb>-<wait>)"`, the verb name with `.` and `_` written as `-`),
since a repeated key would return the stored receipt at once and measure the replay instead of the wait, and
cancels each measured job with `job_cancel` once its wait is measured;
runs M-cancel; focuses on every cluster and lists; lists and reads every resource kind; renders every prompt
and compares with `frob robot-docs --workflow`; runs the extended parity harness. It sources the shared helper
and writes `target/e2e-logs/mcp_full_surface/<utc>.ndjson` plus wire transcripts. Every line has `ts`, `script`,
`bead` (`BD-298`), `step`, `event`, the exact tool call, exit code, wall time and the envelope's `evidence`
block; `metric` lines: per `run` tool the excess over `sync_wait_ms` (threshold 500 ms) and the maximum over
all tools; jobs still running after wire cancellation (all); tools listed per focus (≤ 7 + 3) and list bytes
(≤ 12,000); resource kinds read (7 groups, 13 URI forms, 12 catalogs); prompt differences (0); parity diff entries (0). On
failure: the tool, the transport, the measured time or the first differing list entry, and the transcript path.
The `summary` names GATE-TETHER-12 and INT-FMCP-01.

### Known answers and negative controls
- Known answers: the named cluster rows; the base set of three; one parity exemption (the unknown-tool case).
- Negative controls (each must be caught): a `run` tool whose handler ignores the timer (M-wait); a handler that cancels the job on wire cancellation (M-cancel); a registry with eight tools in `attack` (the build); a resource kind removed from the server (M-resources); a prompt edited by hand (M-prompts); a description that embeds a stored design name (the INV-TETHER-13 check).
- Determinism lanes: lists, resources and prompts byte-identical twice on one machine and across the two transports; debug and release.

## Considerations

- Program risk: "the agent surface was too large and agents got lost" (earliest signals: failures of the fresh-agent gates; serial turns per accepted answer). This bead delivers the structural mitigations; the fresh-agent gates and the surface A/B measure whether they work.
- OPEN-TETHER-2 (harness protocol eras and re-listing) blocks this gate only through the launch default; the gate's focus clause is measured with the library's client.
- OPEN-TETHER-3 (the wait's default and maximum) stays at 5,000 and 30,000 here and is re-read at M4.
- If the kill gate KILL-MCP fired at M0, this surface runs in the socket-fallback configuration; M-wait then includes the socket hop and its margin is re-measured.
- The cluster count "seventeen" counts principal clusters; the further clusters for subsystem verbs are in addition and are NJL-05's assignment (45 clusters in all), which its registry lints check and this bead's M-focus reads from the registry.
