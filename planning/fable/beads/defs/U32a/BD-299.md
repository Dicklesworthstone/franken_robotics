## Background

A caller of FrankenRobotics meets exactly three kinds of failure, and each is tested on both surfaces, the
command line `frob` and the MCP server `frob-mcp`.

| Class | What happened | CLI | MCP | What the caller does |
|---|---|---|---|---|
| **Domain** | The verb was reached and it refused, stopped on budget, lacked a capability or a device, or met a conflict. A numerical refusal, a budget stop and a physical failure of the robot are three different outcomes: the first two are refusals, the third is a result with findings | Envelope with `ok: false`; exit 3, 4, 5, 6 or 7 | Tool result with `isError: true` whose structured content is the same envelope | Read `refusal.repairs` and `retry` |
| **Protocol** | The request never reached a verb: unknown verb, or arguments that fail the schema | Envelope, exit 3, `FROB-REF-801` or `-802` (the CLI owns its parser) | Unknown tool: a JSON-RPC error from the library before any handler runs (FACT: `InvalidParams`, −32602, "Unknown tool"). Schema failure: the library's input-validation error, mapped to an envelope skeleton with exit 3 by the registration-time error hook | Fix the call; nothing was charged |
| **Transport** | The connection, the client or the daemon died, or a deadline passed before a receipt arrived. The job may be running | Exit 9 if the CLI survives the daemon; otherwise whatever the shell reports | No result. The library may deliver a request-cancelled error (FACT: −32004) or nothing | Never resubmit blindly. Reconnect and call `job.find` with the verb and the idempotency key (`frob job find --verb <verb> --key <key>`; a key is scoped to principal and verb); one job and one charge exist or none do |

The one permitted difference between the surfaces is the unknown-verb case in the Protocol row: on MCP the
library answers before generated code runs, so no envelope exists. The parity gate lists it as the only
exemption.

Why this deserves a gate of its own: an agent's recovery behaviour is learned from these three shapes. If a
refusal sometimes arrives as a successful tool result, or a schema failure sometimes arrives as free text, or a
dropped connection is indistinguishable from a refusal, agents either waste budget (resubmitting running work)
or stall. GATE-TETHER-04 (Known answer; TARGET): each of the three failure classes is exercised on both
surfaces; every refusal code maps to exactly one exit code; a killed connection during a wait leaves the job
recoverable by key in 100 of 100 trials.

The gate was first recorded at M2 on the surface that existed then. This seed bead closes it on the full M3
surface: every registered verb, real capability tokens, shared slot dispatch with preemption, resources and
prompts, and the daemon-hosted server.

## Scope

In: registry-driven failure conformance for every verb on both surfaces; the registration-time error hook on
every tool; failure mapping for resources and prompts; authentication failures on each transport; the
code-to-exit check over the complete registry; the kill campaign under shared dispatch and preemption; the M3
gate record. Out: the fixture, kill harness and recovery procedure built at M2 (N32a-19, reused); the mechanisms
that produce each refusal; the three standing rules of refusal as a registry sweep (N35-26, M1, a dependency):
never truncate, no partial result on a budget stop, and three misspellings of every parameter of every verb and
an unknown field in every authored format. That sweep asks whether each rule holds for each verb; this bead asks
whether each failure arrives in the right class with the right shape on each surface. Where the two meet (a
misspelt parameter; a starved budget; a fall that is a finding and not a refusal) this bead takes one stimulus
per verb from that bead's generator (`frob_conformance::refusal_rules`), checks the class, exit code, `isError`
and the equality of the two surfaces' envelopes, and does not repeat the per-parameter sweep.

## Technical approach

**1. Registry-driven conformance (generated, not hand-listed).** For every entry of the static verb table the
harness derives stimuli:
- *Protocol:* the verb's first example with one parameter misspelt (the first misspelling that the generator of
  N35-26 emits for the verb's first named parameter: one character dropped); with one required parameter removed; and,
  for `run` verbs, with `sync_wait_ms` = 30,001. Expected: CLI envelope with `FROB-REF-802`, exit 3; MCP
  `isError: true` with the envelope skeleton carrying 802 and exit 3. Nothing charged: the session budget and
  the ledger's job count are unchanged.
- *Domain, by kind:* `run` and `mutate` without an idempotency key → `FROB-REF-805`, exit 3 (except the
  `key_optional` rows of N32a-02 RL-21, such as `session.focus`: for them the call without a key must succeed and
  805 must be absent from the row's list); a keyed verb
  replayed with a changed payload → `-803`, exit 7; a `mutate` with a stale parent → `-804`, exit 7; a `run`
  under a zero budget → `-701`, exit 4; any verb under a token without its scope → `-720`, exit 5; an expired
  token → `-723`, exit 5; a `mutate` into another namespace → `-725`, exit 5; a declared verb without a
  handler → `-724`, exit 5; a paginated verb with a foreign cursor → `-806`, exit 3; a device verb with the
  device withdrawn → `FROB-REF-601` (device unavailable or lost; `pointer` the device, or `daemon` when no
  `frobd` answers), exit 6.
- *Domain, verb-specific:* for each code in the entry's refusal list that has a registered trigger fixture, that
  fixture. A code with no trigger fixture is reported as untested by name; the gate record lists the count.
For every Domain stimulus the MCP structured content must equal the CLI envelope after masking `cost.wall_ms`.

**2. The registration-time error hook.** Each tool declares an output schema, so the handler supplies envelope
skeletons for the library's two framework error kinds: input validation (exit 3, `FROB-REF-802`) and handler
fault (exit 9, the internal fault `FROB-REF-990` of N32a-03, `retry: never`, with the repair `frob job find
--verb <verb> --key <key>` on keyed verbs). The library validates the skeletons against the schema at registration. The check here:
start-up fails if any tool lacks either skeleton; a forced handler panic on a sample of tools yields the exit-9
skeleton and never a bare protocol error.

**3. Resources and prompts.** A resource read that its source verb refuses returns the read's error with the
refusal envelope as data (domain). A malformed URI or an unknown resource is the library's not-found error
(protocol). A prompt argument failing the identifier pattern is `FROB-REF-802` (protocol). None of them charges.

**4. Authentication on each transport.** HTTP without a bearer token: the library's unauthorized response
(protocol; no handler ran). A well-formed but expired token on a tool call: `FROB-REF-723` (domain). stdio with
no session once tokens are enabled: `-723` with a repair naming `frob session open`.

**5. The code-to-exit check over the complete registry.** Every refusal code of every chapter has exactly one
exit code, in {3, 4, 5, 6, 7, 9}; family defaults hold where defined (`1xx` to `5xx` → 3; `6xx` → 6; `70x` → 4;
`72x`, `73x` → 5; `8xx` → 3 except conflicts → 7 and the chunk conflict → 9; `9xx` → 9); families without a
default carry an explicit exit. Exit 1 is produced by no code path; exit 8 is not a failure and appears in no
refusal. This is the M3 reading of N32a-19's standing per-commit test: it is the first with the codes of §26 and
§39 (N26-REF, N39-REF) registered, and with the codes that the allocation rounds gave to refusals the chapters
state without a number (N35-33, N35x-02); the record names the chapters present and the one still absent (§31,
N31-REF, M5), whose codes the standing test checks the day they are entered. Why every chapter's refusal bead is
a dependency (the graph tool flagged the count): the check's subject is the complete registry, so each chapter's
rows must exist before it can pass; none is implied by another.

**6. Transport campaign on the M3 daemon.** The M2 kill harness, now with shared slot dispatch and
preempt-resume active and four concurrent sessions: for each of 100 seeded trials per kill kind (close the
connection during a wait; kill the client process; kill and restart the daemon; let a client deadline pass),
the recovery procedure (do not resubmit; reconnect; `job.find` by verb and key; `job.wait`, or resubmit with the same
key if no job exists) must end with exactly one job and one charge and digests equal to an uninterrupted run.
A trial in which the killed job was parked by the scheduler at the moment of the kill is included by seeding.

Determinism: stimuli are generated deterministically from the registry digest and a seed; outcomes are exact.

## Acceptance criteria

- [ ] GATE-TETHER-04 (TARGET) on the full M3 surface: each of the three classes is exercised on the CLI, on MCP over stdio and on MCP over loopback HTTP; every refusal code maps to exactly one exit code; a killed connection during a wait leaves the job recoverable by key in 100 of 100 trials. Measured counts recorded (`cargo run -p frob-conformance --example record_gate -- --gate GATE-TETHER-04 --receipt <hash>`).
- [ ] For every registered verb, the generated Protocol and by-kind Domain stimuli produce the expected code, exit and `isError`, and the two surfaces' envelopes are equal after masking.
- [ ] The record lists how many (verb, refusal code) pairs have a trigger fixture and names those that do not; no pair is recorded as passing without a fixture.
- [ ] Every tool has both framework-error skeletons, validated at registration; a forced panic yields the exit-9 skeleton carrying `FROB-REF-990`.
- [ ] The code-to-exit record lists the chapters whose codes were checked (every chapter's refusal bead through M3, including N26-REF and N39-REF) and names §31 as not yet registered.
- [ ] The sealed-read refusal of the blinded lane carries no world address in `observed` or `pointer` on either surface.
- [ ] Protocol-class stimuli charge nothing across the whole campaign (budget and job count unchanged).
- [ ] A physical failure of the robot is returned as a result with findings (exit 2) on both surfaces, never as a refusal.
- [ ] The exemption list has exactly one entry: the unknown-verb case.
- [ ] The three other kill kinds also recover 100 of 100, including trials in which the job was preempted.

## Test plan

### Unit tests (`cargo test -p frob-conformance failure_m3`, `cargo test -p frob-mcp errors`)
- `stimuli_generated_for_every_verb`: the count of Protocol stimuli is three per `run` verb and two per other verb.
- `by_kind_domain_table`: the ten rows above on one representative verb per kind.
- `mcp_equals_cli_envelope` over the generated set (in-memory transport).
- `skeletons_present_for_all_tools`; `panic_yields_exit_9_skeleton` (code `FROB-REF-990`, `retry: never`).
- `key_optional_rows_skip_805`: `session.focus` without a key succeeds; its list lacks 805; every other `run` and `mutate` row without a key gives 805.
- `sealed_read_refusal_reveals_no_world`: the blinded lane's sealed-read refusal, on both surfaces, has no world address in `observed` or `pointer` and has the same fields as any other domain refusal of its kind.
- `resource_refusal_carries_envelope`; `prompt_bad_argument_802`.
- `http_no_token_unauthorized_no_handler`; `expired_token_723`.
- `code_exit_map_complete_registry` (the chapters present listed, §26 and §39 among them); `no_refusal_has_exit_8_or_1`.
- `physical_failure_is_finding`: an episode in which the robot falls → exit 2 with a finding; `refusal` absent.
- `untested_pairs_listed`: a synthetic code without a fixture appears in the untested list, not in the pass list.

### End-to-end script and logging
`scripts/e2e/failure_classes.sh --surface cli|mcp-stdio|mcp-http --registry-driven --trials 100 --seed <s>` (the
M2 script with the registry-driven mode; header: `bead=BD-299 milestone=M3 labels=tether,failure-classes
gates=GATE-TETHER-04 seed=299 needs=cpu,frobd,mcp
plants=refusal-not-error,wrapped-unknown,new-key-resubmit,two-exit-row,fall-as-refusal`, each plant one negative
control below): starts `frobd` with shared dispatch and four sessions; runs the generated stimuli for every verb
(keyed stimuli carry keys derived from the seed, the verb and the stimulus, so that no two stimuli share a key
and the 803 stimulus reuses exactly one earlier key with a changed payload); runs the resource, prompt and
authentication rows; runs the four kill kinds, recovering each with `frob job find --verb <verb> --key <key>
--json` (or `job_find {verb, idempotency_key}`) and then `frob job wait <job> --json`.
It sources the shared helper and writes `target/e2e-logs/failure_classes/<utc>.ndjson` plus a transcript. Every
line has `ts`, `script`, `bead` (`BD-299`), `step`, `event`, the exact command or tool call, exit code, wall
time and the envelope's `evidence` block where one exists; `refusal` lines carry code, exit, `retry`,
`pointer` and the first repair; `metric` lines: verbs covered (must equal the registry count), stimuli run and
passed, (verb, code) pairs with and without fixtures, codes with exactly one exit (must equal the registry's
code count), budget change across Protocol stimuli (0), recoveries per kill kind (100 of 100), jobs and charges
per key (exactly 1). On failure: the verb, the stimulus, the first differing field and the ledger copy path.
The `summary` names GATE-TETHER-04.

### Known answers and negative controls
- KA-755 (exact): malformed → 802, exit 3; unknown → 801, exit 3; over-budget → 701, exit 4; unscoped → 720, exit 5; conflicting → 803, exit 7. All five rows are now exercised with real tokens and the real binding.
- KA-763 (exact), through the transport campaign: one job and one charge per key; the retry is a replay.
- Negative controls (each must be caught): a tool that returns a refusal with `isError: false`; a server that wraps unknown tools in an envelope (the exemption changes); a client procedure that resubmits with a new key (two jobs); a refusal row with two exits; a handler that turns a robot's fall into a refusal.
- Determinism lanes: the generated stimuli and their outcomes identical twice on one machine; on both hosts.

## Considerations

- The gate register dates this gate at M2 and this seed bead closes it at M3 behind the full MCP surface; both records are kept, and the M3 record supersedes for the exit review.
- Coverage of verb-specific refusals depends on trigger fixtures owned by the subsystems; this bead reports the gap and does not hide it.
- The sealed-read refusal of the blinded qualification lane must look like any other domain refusal: its envelope must not reveal which worlds exist. A row checks that the refusal's `observed` and `pointer` carry no world address.
- If the kill gate KILL-MCP fired, the MCP rows run in the socket-fallback configuration and the transport class gains a case (the adapter loses its socket to the daemon), which must surface to the client as no result or exit 9, never as a partial envelope.
