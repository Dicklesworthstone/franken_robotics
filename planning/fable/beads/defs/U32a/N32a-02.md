## Background

FrankenRobotics exposes every capability as a **verb**: one named operation with a typed input, a typed output and
a list of typed refusals. There will be about 243 of them in 34 clusters (FACT about the plan's inventory: 163
verbs found mechanically, 55 named by chapters, and 25 further `analyze` verbs; a recount of the chapter list
gives 56, so the registry's own count is authoritative and no test hard-codes 243). Two surfaces serve them: the
command line `frob` and the MCP server `frob-mcp`. If each surface described its verbs by hand they would drift:
a flag present on one and missing on the other, a refusal documented and never returned.

The decision (ADR-TETHER-01) is that the file `registries/verbs.toml` defines each verb once, and that a build
script in the crate `frob-verbs` compiles it into a static table. The CLI parser, the MCP tool definitions, the
JSON schemas, the refusal lists and the agent documentation are all read from that table. Neither `frob-cli` nor
`frob-mcp` contains per-verb code, with one exception: the MCP half of `session.focus`, which edits the visible
tool set. Reason: parity by construction, so the parity gate (GATE-TETHER-02) checks the served surfaces and not
the generator's intentions. Alternative excluded: a hand-written command or tool per verb in each adapter (the
usual design, and the source of drift).

A second decision (ADR-TETHER-02): `frob-verbs` has a feature `registry-only` with no dependency on any physics
crate or on the airlock crate `frob-fsim` (the one crate through which FrankenSim, the sibling physics library, is
reached). Reason: it is what the first fallback of the kill gate KILL-MCP links. If the MCP server cannot join the
core build graph it is built as its own workspace, and it must still share the table, the schemas and the envelope
types. In the default build `frob-mcp` links `frob-verbs` whole.

Terms. A **cluster** is a namespace (`design`, `sim`). A **kind** is one of `read` (returns stored or cheaply
computed facts and changes nothing), `run` (spends compute, takes an idempotency key and a budget, accepts the
bounded synchronous wait and otherwise returns a job handle with exit code 8), `mutate` (creates or changes a
named object in the caller's namespace and takes an idempotency key and an expected parent), `admin` (cancels,
stops, evicts or deletes and needs a capability scope). A **task cluster** is a set of at most seven tools chosen
for one activity, which is what an agent sees listed at a time.

## Scope

In: the registry file format and its schema; the build script and the generated table; the name map to MCP tool
names; task-cluster declarations; every registry lint; the `registry-only` feature and its dependency test. Out:
the envelope types (N32a-03); the integer schema types and their lint (N32a-07); the dispatch interface (N32a-04);
the entries of each milestone (BD-022 for M0, BD-137, BD-222, BD-312, BD-376, BD-409); the parity harness that
diffs served surfaces (N32a-11).

## Technical approach

**One entry (schema `frob.verbs/1`; the first block is the plan's example, the rest DESIGN).**

```toml
[[verb]]
name = "design.check"
cluster = "design"
kind = "read"
tier = "S"                                   # S, F or M
capabilities = ["design:read"]
input_schema = "frob.design.check.in/1"
output_schema = "frob.design.check.out/1"
refusals = ["FROB-REF-101", "FROB-REF-104", "FROB-REF-107", "FROB-REF-110"]
idempotent = true
cost_model = "static: under 2 s for template-sized designs"
first_milestone = "M1"
task_clusters = ["author", "places"]
examples = ["frob design check quad-a --json"]
# DESIGN additions
purpose = "Run the preflight stages and the analyses marked for check; return findings with ranked repairs."
when = "After any edit and before any simulation."
schema_version = 1
paginated = false
exports = false          # true: the envelope carries the three no-authorization flags
estimable = false        # true: accepts --estimate / estimate_only
```

A `run` verb adds `wait = { cli = "complete", mcp_default_ms = 5000, max_ms = 30000 }` (the per-surface default is
a registry field so the parity gate knows about it). An `admin` verb adds `destructive = true|false`. A verb with
two kinds (three exist: `nemesis.hardset` read and run, `scene.bank` read and admin, `spark.cache` read and admin)
declares `kind = ["read", "run"]` and an `[verb.actions]` table mapping each value of its `action` argument to
one kind; the common properties and required capabilities are those of the selected action (DESIGN).

**Task clusters** are declared in the same file: `[[task_cluster]] name = "author"`, `activity = "Make and change
a design"`, `default = false`, and are populated from each verb's `task_clusters`. Three **base tools** are always
listed and are not counted: `session_focus`, `job_wait`, `job_cancel`. Exactly one cluster has `default = true`
(`orient`).

**The MCP name map.** Tool name = verb name with `.` and `-` replaced by `_`: `design.check` → `design_check`,
`telemetry.inspect-pixel` → `telemetry_inspect_pixel`, `robot-docs` → `robot_docs`. No registry name contains an
underscore, and a lint checks that the map is one-to-one.

**Build script (`crates/frob-verbs/build.rs`), numbered.**
1. Read `registries/verbs.toml` and every schema file under `registries/schemas/` (`<schema id with / as @>.json`).
2. Parse strictly: an unknown key is an error (a misspelt field must not be ignored).
3. Run every lint below; on the first failure print the entry name, the lint identifier and the offending value,
   and fail the build.
4. Emit `$OUT_DIR/verbs_table.rs`: `pub static VERBS: [VerbEntry; N]`, sorted by name so lookup is a binary search;
   `pub static TASK_CLUSTERS: [TaskCluster; K]`; `pub static SCHEMAS: [(SchemaId, &str); S]` with each schema's
   canonical JSON text embedded; `pub const REGISTRY_DIGEST: [u8; 32]`, the BLAKE3 digest of the canonical
   serialization of all entries, which every envelope's producer can report and which `capabilities` prints.
5. Emit nothing that depends on the build machine: no timestamps, no absolute paths; iteration is over sorted
   keys. `xtask check-generated` re-runs the script and compares bytes.

```rust
// DESIGN: intent, not signatures.
pub struct VerbEntry {
    pub name: &'static str, pub cluster: &'static str, pub kinds: &'static [Kind], pub tier: Tier,
    pub capabilities: &'static [&'static str], pub input_schema: SchemaId, pub output_schema: SchemaId,
    pub refusals: &'static [RefusalCode], pub idempotent: bool, pub cost_model: &'static str,
    pub first_milestone: Milestone, pub task_clusters: &'static [&'static str],
    pub examples: &'static [&'static str], pub purpose: &'static str, pub when: &'static str,
    pub schema_version: u32, pub wait: Option<WaitDefaults>, pub paginated: bool, pub exports: bool,
    pub estimable: bool, pub destructive: bool,
}
impl VerbEntry {
    pub fn tool_name(&self) -> String;            // "." and "-" to "_"
    pub fn cli_words(&self) -> Vec<&str>;         // "design.check" -> ["design", "check"]
    pub fn needs_key(&self) -> bool;              // mutate, and run that submits a job
}
pub fn lookup(name: &str) -> Option<&'static VerbEntry>;
pub fn lookup_tool(tool_name: &str) -> Option<&'static VerbEntry>;
```

**Registry lints (identifier: rule).**
- `RL-01` name grammar: `^[a-z][a-z0-9]*(-[a-z0-9]+)*(\.[a-z][a-z0-9]*(-[a-z0-9]+)*)?$`; no underscore; the part before the dot equals `cluster` (operator verbs have no dot and cluster `operator`).
- `RL-02` the tool-name map is one-to-one over all entries and the three base tools.
- `RL-03` one name per verb: no entry's name appears in the `[[retired_name]]` table (rows `name`, `use`), which holds every second spelling the plan retired (for example the separating-pair search is `mission.separate`, forks are `run.fork`, first divergence is `telemetry.divergence`, the screening audit is `nemesis.audit`, the model-form check is `fidelity.modelform`, the rank-agreement record is `eval.rank-agreement`, the pre-analysis is `eval.preanalyze`, the self-contained replay is `telemetry.export-html`, the cascade is `opt.cascade` with `solve.run` as its agent-facing caller); and no two entries share both schema identifiers.
- `RL-04` every verb sits in at least one task cluster; every task cluster holds at most seven tools; every cluster named by a verb is declared; exactly one cluster is the default.
- `RL-05` every schema identifier resolves to a schema file; identifiers match `^frob(\.[a-z0-9-]+)+/[0-9]+$`.
- `RL-06` every refusal code resolves in the refusal registry of `frob-core` (an unknown code is a load-time error there) and the list is non-empty for every verb that takes input.
- `RL-07` at least one example; each example parses under the CLI grammar generated from the entry and its arguments validate against the input schema.
- `RL-08` kind rules: `mutate` and job-submitting `run` verbs have the common idempotency-key property; `read` verbs have none and are `idempotent = true`; `admin` verbs list at least one capability; `destructive` appears only on `admin`.
- `RL-09` `run` verbs declare `wait` with `0 ≤ mcp_default_ms ≤ max_ms ≤ 30000`.
- `RL-10` `capabilities` is present on every entry (an empty list must be written explicitly together with `public = true`).
- `RL-11` the generated MCP description (purpose, when, cost class, refusal codes, one example) is at most 800 characters (TARGET).
- `RL-12` `first_milestone` is one of M0 … M8, and `tier` is S, F or M.

**The `registry-only` feature.** With `--no-default-features --features registry-only` the crate compiles the
table, the schemas, the name map, the envelope and refusal types and the request canonicalizer, and nothing else:
no handler module, no dependency on `frob-fsim` or any subsystem crate. Default features add `handlers`.

Determinism: the generated table is a pure function of the registry and schema files (class exact). Refusals
this bead introduces: none at run time; every failure here is a build failure.

## Acceptance criteria

- [ ] `registries/verbs.toml` validates under `frob.verbs/1`; the build script emits the table; `xtask check-generated` shows no difference on a second run.
- [ ] Each of `RL-01` to `RL-12` has a test that passes on the committed registry and fails on a planted violation naming the entry and the lint.
- [ ] `lookup("design.check")` and `lookup_tool("design_check")` return the same entry; `lookup_tool("telemetry_inspect_pixel")` returns `telemetry.inspect-pixel`.
- [ ] `cargo tree -p frob-verbs --no-default-features --features registry-only -e normal` contains no `frob-fsim`, no `fs-*` crate and no subsystem crate; `cargo build` with that feature set succeeds.
- [ ] `REGISTRY_DIGEST` is identical in debug and release and on both hosts.
- [ ] The crate ships `CONTRACT.md` with its ten sections, and the registry format is documented in it with one valid example.

## Test plan

### Unit tests (`cargo test -p frob-verbs registry`)
- `table_sorted_and_unique`: `VERBS` is strictly increasing by name.
- `name_map_examples`: `design.check` → `design_check`; `telemetry.inspect-pixel` → `telemetry_inspect_pixel`; `robot-docs` → `robot_docs`.
- `rl02_collision_caught`: adding `robot.docs` beside `robot-docs` fails the build with `RL-02`.
- `rl01_underscore_caught`: `design.check_all` fails with `RL-01`.
- `rl03_retired_name_caught`: with a `synthetic` retired-name row (`name = "mission.adversarial-pair"`, `use = "mission.separate"`), registering that name fails with `RL-03` and prints the `use` value.
- `rl04_eight_tools_caught`: an eighth tool in `author` fails; a verb with `task_clusters = []` fails.
- `rl06_unknown_refusal_caught`: `FROB-REF-999999` fails at load.
- `rl07_example_must_validate`: an example with a misspelt flag fails.
- `rl08_mutate_without_key_caught`; `rl09_wait_out_of_range_caught` (`max_ms = 60000`).
- `rl11_description_801_chars_caught`.
- `unknown_toml_key_is_error`: `refusal = [...]` (singular) fails the strict parse.
- `two_kind_verb_actions`: `spark.cache` with `action = "evict"` resolves to kind `admin` and requires its scope; `action = "show"` resolves to `read`.
- `registry_only_has_no_physics`: parses `cargo tree` output and asserts the forbidden set is absent.

### End-to-end script and logging
`scripts/e2e/tether_registry.sh`: builds `frob-verbs` in both feature sets, runs `xtask check-generated`, runs the
lint suite, then plants each of five violations in a scratch copy of the registry and asserts a non-zero build
with the expected lint identifier. Log lines (NDJSON under `target/e2e-logs/tether_registry/`): `ts`, `script`,
`bead`, `step`, `event`, command, exit code, wall time; `metric` lines for entry count, cluster count, largest
task cluster (threshold 7), longest description (threshold 800), registry digest; on failure the entry and lint.
A final `summary` names GATE-TETHER-02 as touched (generation half).

### Known answers and negative controls
- Known answers: the three name-map examples above; the base-tool set is exactly {`session_focus`, `job_wait`, `job_cancel`}.
- Negative controls registered for GATE-TETHER-02: a tool-name collision; an unknown TOML key; a verb in no task cluster; a cluster of eight; a physics dependency added under `registry-only`.
- Metamorphic relation: permuting the order of entries in the file leaves the generated table and the digest unchanged.
- Determinism lanes: table bytes identical twice on one machine, in debug and release, on the Linux host and on the Mac.

## Considerations

- The registry is large even in clusters (program risk: the agent surface is too large and agents get lost). The lints on cluster size and description length are the structural defence; the fresh-agent gates measure whether it worked.
- Entries may be present before their handler exists; such a verb answers with `FROB-REF-724` (not implemented in this build, exit 5) and `capabilities` lists it as not implemented. The milestone verb-set beads add entries.
- OPEN-ATEL-4 (whether `result.revalidate` and `mission.revalidate` stay two verbs over one engine; default two verbs, one engine; owner: Tether lead; due at the registry freeze of M3) is a registry question; `RL-03` permits the pair because their schemas differ.
- OPEN-AUGUR-7 (exit code of a mission query that stops on budget with certified cells; default exit 2 with `resolution-unmet`) is recorded on the `mission.synthesize` entry by the M1 verb-set bead.
- The treatment of two-kind verbs is DESIGN; the plan lists three and does not say how one entry carries two kinds.
