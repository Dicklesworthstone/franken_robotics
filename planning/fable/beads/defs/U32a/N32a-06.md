## Background

This bead exists on one branch only: it is built if, and only if, the kill gate KILL-MCP fires. That gate fires
when the admission gate INT-FMCP-01 cannot pass within the M0 budget after the two upstream work items
(FD-FMCP-01, which brings the sibling MCP library `fastmcp_rust` onto the project's one toolchain T, and
FD-ASUP-01, which aligns the suite on one asupersync version) have both been attempted. The usual cause would be
that `frob-mcp` cannot share a compiler or an asupersync package with the rest of the core build graph.

Fallback 1 keeps an MCP surface without that sharing: `frob-mcp` becomes its own Cargo workspace. It still links
the crate `frob-verbs`, but only with the feature `registry-only` (ADR-TETHER-02), which contains the static verb
table, the schemas, the name map and the envelope types and has no dependency on any physics crate or on the
airlock crate `frob-fsim`. It runs no verb itself: every call is forwarded to the daemon `frobd` over a local
Unix-domain socket in newline-delimited JSON (`frob.rpc/1`), through the socket back end of the dispatch trait
(ADR-TETHER-03), which has existed and been tested since M0 precisely so that this fallback needs no redesign.

Why this is second best (the reason it is not the default): a protocol hop and a second build on every agent
call; CPU-tier verbs can no longer run inside the MCP process; and `frobd --mcp` (one process serving the job
queue and the MCP transports) is not available. Fallback 2, if this cannot be made to work either, is the CLI
alone, which is complete on its own.

## Scope

In: the separate workspace and lockfile; the socket-only dispatch wiring; the verb-serving loop of the daemon
brought forward to the milestone at which MCP is offered; the tests and gates re-run in this configuration; the
way back. Out: the decision (N32a-05); the dispatch trait and framing (N32a-04); the daemon's job engine, which
arrives on its own schedule (N32a-14).

## Technical approach

1. **Workspace.** Remove `surface/frob-mcp` from the root workspace `members`. Give it its own `Cargo.toml`
   workspace table, its own `Cargo.lock`, and, only on this branch, its own toolchain file if the cause was the
   compiler (recorded as an exception to the one-toolchain rule in the ADR, with the date it is expected to end).
   It depends on `fastmcp_rust` by commit and on `frob-verbs` by path with `default-features = false,
   features = ["registry-only"]`.
2. **Dispatch.** `VerbTool` is constructed with the `Socket` back end only. Schema validation still happens in
   the MCP process (the schemas are in the table), so a protocol failure is answered without a round trip;
   capability checks, name resolution, digesting, idempotency and execution happen in `frobd`.
3. **The daemon side.** `frobd` must serve verbs from the first milestone at which MCP is offered. If the full
   daemon (job ledger, dispatcher) has not landed yet, a reduced `frobd` is shipped that runs the verb-serving
   loop over the in-process handler table and executes every request to completion on the CPU (no job queue); it
   is replaced by the full daemon when that lands, with no change on the wire.
4. **Start-up.** `frob-mcp` connects to the socket under the daemon's state root; if no daemon is listening it
   starts none and every tool call returns the backend-unavailable refusal (exit 6) with a repair naming
   `frobd`; `tools/list`, resources that are static (documentation, schemas, the registry) and prompts still work.
5. **Supply chain.** `check-deps` runs on both workspaces; each has exactly one asupersync package; the registry
   digest compiled into `frob-mcp` must equal the digest `frobd` reports at connection time, otherwise every tool
   call is refused with a version-mismatch finding (the two builds must describe the same verbs).
6. **The way back.** When the upstream items land, INT-FMCP-01 is re-run with `frob-mcp` restored to the root
   workspace; on a pass the separate workspace is deleted in the same change.

Determinism and evidence: unchanged; envelopes are produced by the daemon and passed through byte for byte.

## Acceptance criteria

- [ ] The separate workspace builds with `--locked`; `cargo tree -e normal` shows no physics crate and no `frob-fsim`; each workspace has one asupersync package.
- [ ] The MCP smoke test of INT-FMCP-01 (initialize, `tools/list`, calls of `doctor` and `capabilities`, unknown tool, misspelt parameter, shutdown) passes over stdio and HTTP in this configuration.
- [ ] For every verb available at the milestone, the envelope returned through MCP equals the CLI's after masking `cost.wall_ms`.
- [ ] A registry-digest mismatch between the two builds refuses every call and is reported by `doctor`.
- [ ] Killing `frob-mcp` during a call leaves the daemon serving the CLI and leaves any admitted job recoverable by its key.
- [ ] With no daemon running, `tools/list` still answers and a tool call is refused with exit 6.
- [ ] The parity gate is re-run and its record states that this configuration was measured.

## Test plan

### Unit tests (`cargo test` in the separate workspace)
- `socket_only_backend_selected`: the binary contains no handler table (a link-time symbol check).
- `digest_mismatch_refuses`: a daemon reporting another registry digest → every call refused, one finding.
- `protocol_failure_without_round_trip`: a misspelt parameter is answered with the 802 skeleton and the socket sees no frame.
- `no_daemon_exit_6`: tool call with no listener → refusal with exit 6 and a repair.

### End-to-end script and logging
`scripts/e2e/mcp_fallback_socket.sh`: starts `frobd` (reduced or full), starts `frob-mcp` from the separate
workspace, runs the smoke test on both transports, runs every available verb through both surfaces and diffs the
masked envelopes, kills `frob-mcp` mid-call and checks the daemon. NDJSON under
`target/e2e-logs/mcp_fallback_socket/`: `cmd` lines, `assert` lines per verb with both envelope digests, `metric`
lines for socket round-trip latency at the 50th and 99th percentiles (recorded; no threshold is claimed), and a
`summary` naming KILL-MCP and INT-FMCP-01 (fallback configuration).

### Known answers and negative controls
- Known answer: masked envelopes equal across surfaces for every verb.
- Negative controls: add a default-feature dependency on `frob-verbs` (the dependency check must fail); run the two builds from different registry files (the digest check must refuse).
- Determinism lanes: the diff twice on one machine; on both hosts.

## Considerations

- If this branch is taken, the statement of record everywhere becomes "the MCP server reaches verbs through the daemon"; documentation generated from the registry does not change, since the tool definitions are identical.
- The reduced daemon is a deliberate, temporary second executor; it must share the handler table and envelope code with the CLI so that it cannot become a second implementation of any verb.
- Latency: the socket hop is paid on every call. It is recorded here so that the bounded-wait defaults can be re-read with it.
- This bead is closed as `not needed` with a typed reason if KILL-MCP is recorded `not fired`.
