## Background

The second principle of the FrankenRobotics surface is that agents ask questions and spend budgets; they do not
drive solvers. A budget is only meaningful if three things hold. The agent can learn what a question will cost
before paying (**estimates**). The system refuses work that would not fit, instead of starting it and stopping
half way (**admission**). And what is charged is what the agent's work actually used, even when its episodes
shared a device with other agents' (**attribution**).

The rules, from the plan:
- Every verb that can cost more than a second accepts `--estimate` and returns CPU core-seconds, GPU seconds,
  memory and disk with an interval, without running.
- A session carries budgets; a verb that would exceed one is refused with the estimate attached.
- **Admission uses the upper end.** A job is admitted when the interval's upper end fits the remaining budget
  (`FROB-REF-701` otherwise). DESIGN reason: a budget stop publishes nothing, so an underestimate wastes the
  whole spend while an overestimate costs only a refusal the agent can answer with a smaller question.
  Alternative excluded: admit on the point estimate and stop when the money runs out, which converts estimation
  error into wasted compute.
- A budget stop publishes nothing partial as a result (INV-TETHER-03).

This bead builds the accounting. The statistical calibration of the interval (a conformal interval per stratum)
is a later bead; until a stratum is calibrated the interval is marked `uncalibrated` and admission uses a fixed
factor of 2 on the point estimate (DESIGN, conservative). Tier Solid; crates `frob-verbs` (accounting) and
`frob-cli` (the daemon hosts it).

## Scope

In: the estimate envelope and the `--estimate` / `estimate_only` plumbing for every estimable verb; the session
budget ledger; reservation, settlement and release; upper-end admission and `FROB-REF-701`; the budget stop and
`FROB-REF-702`; the eight capped quantities; attributable device time and the daemon's overhead line; the
`budget` and `cost` blocks of the envelope. Out: the cost model itself (BD-219); conformal calibration and
GATE-TETHER-11 (BD-297); the admission guard and campaign class (`FROB-REF-703`, `-704`; BD-296); token scopes
and attenuation (BD-258).

## Technical approach

**The estimate (`frob.estimate/1`).** Returned by `--estimate` on the CLI and `estimate_only: true` on MCP, and
attached to every `701` refusal. It runs no physics.

```json
{ "gpu_s":        { "point": 38, "lo": 31, "hi": 47, "level": 0.90, "calibration": "calibrated", "n": 212 },
  "cpu_core_s":   { "point": 4.1, "lo": 2.05, "hi": 8.2, "level": 0.90, "calibration": "uncalibrated", "n": 6 },
  "memory_bytes": { "point": 3100000000, "…": "…" }, "disk_bytes": { "…": "…" },
  "stratum": { "verb": "sim.run", "tier": "gpu-cuda", "device_family": "…", "shape_class": "…" } }
```

For an uncalibrated stratum `lo = point ÷ 2` and `hi = point × 2`. A registry lint requires `estimable = true`
on every verb whose cost model can exceed one second. Worked figures from the plan's sessions (illustrative):
a 2,048-world, 20 s run estimates 38 GPU-seconds with a 90% interval of 31 to 47 and 3.1 GB; a mission synthesis
estimates 640 GPU-seconds with a 90% interval of 512 to 800.

**What a budget can cap** (units as they appear in `--budget k=v` and in the envelope):

| Quantity | Unit key | Enforced where |
|---|---|---|
| Wall time | `wall_s` | The job engine, at safe boundaries |
| Simulated time | `sim_s` | The job engine, by tick count |
| GPU seconds | `gpu_s` | Attributable device time (below) |
| CPU core-seconds | `cpu_core_s` | The worker pool's accounting |
| Device memory | `device_mem_bytes` | Preflight at admission; never exceeded at run time |
| Trace bytes | `trace_bytes` | The publisher; telemetry cannot fill a disk |
| Episode count | `episodes` | The job engine |
| Solver iteration caps | `solver_iters` | Passed to the solver as a cap; reaching it is a numerical refusal of that trial, not a budget stop |

**Reservation and settlement, numbered.**
1. *Estimate.* Compute the estimate for the resolved request.
2. *Admit or refuse.* For each capped unit, required = the interval's upper end `hi`. If required exceeds the
   session's remaining budget in that unit, or the call's own `--budget` in that unit, refuse with
   `FROB-REF-701` (exit 4), `observed` = `hi`, `required` = the remaining amount, the estimate attached, and
   ranked repairs (fewer worlds, a shorter horizon, a cheaper tier), each with its own estimate.
3. *Reserve.* Inside the admission transaction (the same one that binds the idempotency key and inserts the job
   row), debit the reservation `hi` from the session's remaining budget.
4. *Meter.* While the job runs, accumulate actual use per unit. If actual use reaches the reservation or the
   call's budget, request a stop at the next safe boundary: drain, discard unpublished state, end the job
   `failed` with `FROB-REF-702` (exit 4). Nothing partial is published as a result; committed telemetry chunks
   remain; the receipt says `budget-stop` and counts the unstarted trials.
5. *Settle.* At any terminal state, charge the actual use and release the rest of the reservation, in one ledger
   transaction. The envelope's `cost` is the actual use; `budget` is what the session has left afterwards.

**Attributable device time.** Under shared batches a job is charged

    charge(job) = Σ over steps of (slots occupied by the job ÷ batch capacity B) × (wall time of the step).

Idle reserve and unfilled slots are charged to the daemon's own overhead line,
`overhead = Σ over steps of (unoccupied slots ÷ B) × (wall time of the step)`, reported by `session.show` and
never charged to an agent. Conservation: Σ over jobs of charge + overhead = Σ over steps of wall time. Worked
value (the plan's arithmetic): a 96-pair comparison occupies 192 of B = 8,192 slots; over a batch-episode of
40.96 s of device time it is charged 192 ÷ 8,192 × 40.96 = 0.96 s. Time spent waiting in a queue or parked by
preemption is not charged. With per-job dispatch (the M2 mode) a job occupies its whole environment and is
charged its environment's device time.

**Budget ledger (DESIGN tables).** `session_budget(session, unit, granted, reserved, spent)` and
`budget_event(session, seq, job, unit, kind, amount)` with kinds `reserve`, `charge`, `release`. Invariant
checked after every transaction: `granted − spent − reserved ≥ 0` and equals the remaining amount shown.

Determinism. Charges are measured wall-clock quantities; they appear only in `cost`, `budget` and receipts, never
in a result or an evidence record (INV-TETHER-09). The one way wall time can affect an outcome is a budget stop,
and a budget stop yields a refusal, not a result. Refusals: `FROB-REF-701` and `-702`, both exit 4.

## Acceptance criteria

- [ ] Every verb marked estimable answers `--estimate` with a schema-valid `frob.estimate/1` and runs no physics (no job row, no device call, no charge); the lint fails for a verb with a cost model above one second that is not estimable.
- [ ] A request whose upper end exceeds the remaining budget is refused with `FROB-REF-701`, exit 4, with the estimate and at least one repair that would be admitted.
- [ ] Reservation, charge and release balance: after 10⁴ seeded jobs with random outcomes, `granted − spent − reserved` equals the remaining budget shown, and `reserved` is zero when no job is live.
- [ ] A budget stop ends the job with `FROB-REF-702`, publishes no result object, leaves committed telemetry readable and reports unstarted trials.
- [ ] Attributable charges and the overhead line sum to total device time within floating-point rounding on a recorded shared-batch trace; the 192-slot example is charged 0.96 s.
- [ ] `session.show` reports granted, reserved, spent and left per unit and the daemon overhead line.
- [ ] An `uncalibrated` stratum yields `lo = point ÷ 2`, `hi = point × 2` and admission on `hi`.
- [ ] A kill between reserve and settle leaves, after recovery, either an admitted job holding its reservation or no reservation (never a reservation without a job).

## Test plan

### Unit tests (`cargo test -p frob-verbs budget estimate`)
- `estimate_runs_nothing`: counters for job rows, device calls and charges are unchanged.
- `admit_on_upper_end`: point 38, interval 31 to 47, remaining 40 → refused 701 (47 > 40); remaining 47 → admitted with 47 reserved.
- `uncalibrated_factor_two`: point 10 → 5 to 20; remaining 15 → refused.
- `refusal_carries_estimate_and_repair`.
- `reserve_charge_release_balance` (property, 10⁴ cases).
- `budget_stop_702_no_result`.
- `attributable_time_example`: 192 slots, B = 8,192, 40.96 s → 0.96 s.
- `conservation_of_device_time`: random occupancy traces; jobs plus overhead equal the total.
- `queue_wait_not_charged`; `parked_time_not_charged`.
- `solver_iteration_cap_is_trial_refusal`: reaching the cap increments the job's `refused` trial count and does not stop the job.
- `call_budget_tighter_than_session`: `--budget gpu_s=30` with 600 left → refused on 47 > 30.
- `no_reservation_without_job` under crash injection at each write point.

### End-to-end script and logging
`scripts/e2e/budgets_admission.sh`: opens a session with `--budget gpu_s=60,cpu_core_s=600`; runs
`frob sim estimate …`; submits a run that fits and one that does not (expect exit 4 with 701 and a repair);
applies the repair and submits again; runs a job against a deliberately low call budget on a slow fixture
(expect 702 and no result object); reads `frob session show --json` after each step. It sources the shared
helper and writes `target/e2e-logs/budgets_admission/<utc>.ndjson` plus a transcript: `cmd` lines with exit code
and wall time; `assert` lines for each refusal code and exit; `metric` lines for estimate against actual per
unit, reserved against charged, the overhead line, the balance invariant (threshold: exact); the envelope
`evidence` block; a `summary` with counts.

### Known answers and negative controls
- Known answers: the slot-share arithmetic (192 ÷ 8,192 of 40.96 s = 0.96 s; KA-761 gives the share as 2.34%); the uncalibrated interval [point ÷ 2, point × 2].
- Negative controls: a build that admits on the point estimate (the 38-against-40 case must be seen to be admitted and the test must fail); a build that publishes the partial result of a budget-stopped job (the no-result assertion must fail); a build that charges idle reserve to the job (conservation must fail).
- Determinism lanes: the accounting tests are exact and repeat identically; charges on real devices are recorded, not asserted for equality.

## Considerations

- OPEN-SPARK-2 (the compute envelope; owner: the project owner; default 16 GiB, 8 cores, one hour, one device) bounds any single job regardless of session budget.
- A `--budget` on the call caps that call; a session budget caps the session; a derived token's budget is debited from its parent. This bead implements the first two and leaves the hook for the third.
- Memory and disk are checked at admission by preflight and are not metered quantities; exceeding them at run time is a device refusal, not a budget stop.
- An agent that always asks the largest question it can afford will see many 701 refusals when estimates are uncalibrated; the repairs in the refusal are what keep that loop short.
- Authorization distinguishes three acts: reading an existing trace, allocating a job, and publishing an export. Budgets govern the second.
