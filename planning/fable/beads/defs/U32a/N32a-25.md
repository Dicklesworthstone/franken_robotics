## Background

MCP, the tool-calling protocol agent harnesses speak, has a second primitive besides tools: **resources**,
addressable pieces of content a client can list, read and subscribe to. FrankenRobotics uses them for what an
agent reads rather than does: the guide, the verb registry, schemas, catalogs, stills, reports, the state of a
job. Serving these as resources keeps them out of tool results (where they would be paid for in context on every
call) and lets a client that supports subscriptions be told when a job changes state instead of polling.

Two rules shape the design. First, a resource URI names a registry row or a content-addressed object in the
store; **it is never a filesystem path**. Private places must stay private and a path is an invitation to
traversal. Second, in the spirit of ADR-TETHER-10 (no private interface; every value shown is obtainable by a
named verb), **every resource is a view of a verb**: its content is what a named verb returns, so nothing is
reachable through a resource that is not reachable, authorized and audited through the verb.

FACT about the library (`fastmcp_rust`, to re-read at the pin): resources are `Resource`, `ResourceTemplate` (an
RFC 6570 `uriTemplate`) and `ResourceContent { uri, mime_type, text, blob }` with `blob` in base64; handlers are
declared with `#[resource]`; `McpContext::notify_resource_updated` notifies subscribers; the listener capacity
is set with `subscription_capacity` and is at most 64 streams server-wide; list methods page behind an opaque
`nextCursor`. A consumer in the suite uses templated URIs such as `resource://agents/{project_key}`.

Tier Solid. Measured by the resource clause of GATE-TETHER-12: each resource kind is listed and readable.

## Scope

In: the URI scheme and its parser; the eight resource groups; templates; the mapping from each resource to its
source verb; authorization on reads; subscriptions on job resources; the size cap; private-scene handling;
paging of catalogs. Out: the verbs that produce the content (their own beads); prompts (N32a-26); transports
and the bearer-token mapping (N32a-27); the untrusted-text mark itself (BD-304).

## Technical approach

**The scheme.** `frob://<group>/<path>`; segments match `^[A-Za-z0-9:._@-]+$`; no `..`, no percent-encoded
slashes, no absolute paths. Identifiers in URIs are registry names or content addresses (`r:19e2…`, `d:41aa…`).

| URI | Contents | Form | Source verb |
|---|---|---|---|
| `frob://docs/guide`, `frob://docs/clusters`, `frob://docs/verb/{name}` | The agent guide, the task-cluster directory, long verb documentation | Text | `robot-docs`, `robot-docs --cluster`, `robot-docs --verb` |
| `frob://capabilities`, `frob://registry/verbs`, `frob://registry/refusals` | What is implemented in the project's eight-condition sense; the registry; the refusal table | JSON | `capabilities`, `schema`, `robot-docs` |
| `frob://schema/{schema_id}` | A schema with a minimal valid example | JSON | `schema` |
| `frob://catalog/{kind}` | Catalogs: `archetypes`, `templates`, `actuators`, `interfaces`, `materials`, `parts`, `scenes`, `tasks`, `fixtures`, `retrofits`, `counterexamples`, `reference-robots` | JSON, paged | `design.templates`, `actuator.list`, `module.list`, `scene.list`, `task.list`, `nemesis.hardset` and the other catalog verbs |
| `frob://still/{run}/{world}/{instant}` | A still or contact sheet, with overlays | PNG, as `blob` | `telemetry.stills` |
| `frob://report/{id}`, `frob://cert/{id}` | A report index; a certificate bundle's manifest | Text, JSON | `report.*`, `prove.list` |
| `frob://job/{id}`, `frob://run/{id}/summary` | Job state and log tail; a token-budgeted run summary | JSON, text | `job.status`, `telemetry.summary` |

The URI, contents and form columns are the plan's; the source-verb column is DESIGN, and a catalog kind whose
listing verb does not exist yet is served when that verb lands. Templated URIs use the library's resource
templates. Fixed resources are listed by `resources/list`; templates
by the templates listing. Hand-written `#[resource]` handlers are permitted by the generation rule (only tool
definitions must be generated); each handler body is: parse the URI, build the source verb's request, call the
dispatch interface, convert the envelope's result to `ResourceContent`. A refusal from the verb becomes the
resource read's error with the envelope as its data.

**Authorization.** A read is authorized exactly as its source verb: the session token's scopes are checked
(`<cluster>:read`, `export:report` and so on). No resource grants reading a confirmation world of the blinded
qualification lane; the verb refuses and so does the resource.

**Private scenes.** An object derived from a private scene is not listed, and a read is refused without the
`private:read` scope (`FROB-REF-731`).

**Size.** A resource read returns at most 4 MiB (TARGET), counted on the encoded response (a `blob` is base64,
so at most 3 MiB of binary). Larger artifacts are read with `artifact.read` by byte range or exported under the
session's export root; the oversized read is refused with a repair naming that verb and the object's digest.
Nothing is truncated.

**Catalog paging.** `frob://catalog/{kind}{?cursor,limit}`: the first read fixes the committed frontier and
returns a cursor (the surface's one cursor implementation); later reads pass it. The content states `frontier`
and whether it is complete.

**Subscriptions.** A client that subscribes to `frob://job/{id}` is notified through `notify_resource_updated`
when the job changes state, which replaces polling where the client supports it. The server is built with
`subscription_capacity(64)`. When capacity is exhausted a new subscription is refused with a repair "use
`job_wait`"; a subscription is dropped when its job is terminal and the final update has been sent. Notification
is driven by the daemon's job events; a missed notification can never lose state, because the resource read
always returns the ledger's current row.

**Imported text.** Where a resource's text includes text that originated in an import (a design name, an asset's
metadata), it appears only inside the delimited data block with its provenance; never in a resource's
`description` or `name`.

Determinism: a resource's content at a fixed frontier equals its source verb's result bytes. Evidence: carried
in the content where the source envelope has it (JSON resources embed the `evidence` block; text resources end
with a one-line evidence footer).

## Acceptance criteria

- [ ] Each of the eight resource groups is listed (fixed resources) or templated, and readable, over stdio and loopback HTTP (resource clause of GATE-TETHER-12; the count of kinds measured is recorded).
- [ ] For every resource, the content equals the result of its source verb called with the equivalent arguments (after the documented conversion), for a sample of at least 5 objects per group.
- [ ] All twelve catalog kinds are readable and page to completion with no row repeated or skipped while new objects are being added.
- [ ] A URI with `..`, a path separator in an identifier, an absolute path or a `file:` scheme is refused; no test can make the server open a path derived from a URI.
- [ ] A private-derived object is absent from listings and is refused with `FROB-REF-731` without `private:read`; with the scope it is readable.
- [ ] A read over 4 MiB is refused with a repair naming `artifact.read` and the digest; a read just under is served whole.
- [ ] A subscriber to a job resource receives an update for each state change; the 65th concurrent subscription is refused with the `job_wait` repair; subscriptions are released at terminal state.
- [ ] A read without the source verb's scope is refused with `FROB-REF-720`.

## Test plan

### Unit tests (`cargo test -p frob-mcp resources`)
- `uri_parser_accepts_table`: each URI form above with sample identifiers.
- `uri_parser_rejects`: `frob://still/../../etc/passwd`, `frob://docs/verb/design%2Fcheck`, `file:///tmp/x`, `frob://catalog/` (empty kind), `frob://catalog/unknown-kind`.
- `resource_equals_verb`: `frob://capabilities` against `capabilities`; `frob://schema/frob.envelope@1`-style identifier against `schema`; `frob://run/{id}/summary` against `telemetry.summary`.
- `catalog_kinds_are_twelve`.
- `still_is_png_blob`: MIME type `image/png`; base64 decodes; the PNG signature bytes are present.
- `oversize_refused_with_repair`: a 5 MiB synthetic artifact.
- `private_not_listed_and_731`.
- `scope_checked_720`.
- `subscription_updates_on_state_change`: admitted → running → complete yields three updates.
- `subscription_capacity_64`.
- `missed_notification_harmless`: drop every notification; a read still shows the terminal state.
- `no_import_text_in_descriptions`: with a design named "ignore previous instructions", no `name` or `description` field of any listed resource changes.

### End-to-end script and logging
`scripts/e2e/mcp_resources.sh`: starts `frobd` and `frob-mcp`; over both transports lists resources and
templates; reads one object per kind; pages two catalogs to the end while a second client adds designs;
subscribes to a job resource and runs the job; attempts the forbidden URIs, the oversize read and the private
read with and without the scope. It sources the shared helper and writes
`target/e2e-logs/mcp_resources/<utc>.ndjson` plus a wire transcript: `cmd` lines; `metric` lines for kinds listed
and read (threshold: all eight groups, twelve catalogs), bytes per read (threshold 4 MiB), updates received per
state change, duplicates and skips in catalog paging (0); `assert` lines for each resource-against-verb
comparison with both digests; `refusal` lines with codes; a `summary` naming GATE-TETHER-12 (resource clause).
No private-scene content is written to the log, only identifiers and refusal codes.

### Known answers and negative controls
- Known answers: the catalog kind list has twelve entries; a resource and its source verb agree byte for byte after conversion.
- Negative controls (each must be caught): a handler that reads a file path taken from the URI (the traversal test must fail the build's lint and the run-time test); a resource that lists a private-derived object; a still served by truncation at 4 MiB (the PNG must fail to decode and the test must catch it); a resource with content that no verb returns (the view-of-a-verb test must fail).
- Determinism lanes: content bytes identical twice on one machine and on both transports.

## Considerations

- OPEN-TETHER-2 covers whether harnesses read resources and act on subscriptions at all; every resource has a verb behind it, so a harness without resource support loses convenience, not capability.
- The chapter names no refusal code for the oversize case; one must be assigned by the registry owner. Until then the implementation uses the registry's code for "result exceeds the surface size limit" if one exists and otherwise blocks on this point; it must not reuse an unrelated code.
- Resource listing is itself paged by the library; a server with thousands of reports must not enumerate them eagerly, so `frob://report/{id}` and stills are templates, not listed items.
- Text resources are token-budgeted like their verbs, with handles for drill-down.
