## Background

The MCP server of FrankenRobotics, `frob-mcp`, is reached in two ways. An agent harness can launch it as a
subprocess and talk over standard input and output. Or a swarm of agents can share one server over HTTP on the
local machine, which the daemon can host itself (`frobd --mcp`), so that one process serves the job queue and
the MCP transports. In both cases the caller's authority must be the same thing: the session's **capability
token**, minted by the daemon when a session is opened, carrying scopes such as `design:write`, `sim:run` and
budgets such as `gpu:seconds=600`. Focus, tool visibility and transport give no authority.

The plan's table of transports:

| Transport | Offered | Use | Notes |
|---|---|---|---|
| stdio | Yes, the default | An agent harness launches `frob-mcp` as a subprocess | On Unix the reactor-driven pairing; elsewhere the blocking pump. The session token comes from the environment |
| Streamable HTTP on loopback | Yes | A swarm shares one server, which `frobd --mcp` can host | Bound to 127.0.0.1 unless configured. A bearer token in `Authorization`, checked by an `AuthProvider`, maps to the session's capability token. The library's OAuth surfaces are not used |
| WebSocket | Behind a flag, unsupported | Experiments only | The library marks it experimental |
| Legacy SSE | No | — | HTTP covers it; the library's SSE path lacks split routing and resumption |
| In-memory | Tests only | Conformance tests without a process | — |

The protocol policy is the library's automatic one, which serves 2026-07-28 clients and the exact 2024-11-05
handshake. Open question OPEN-TETHER-2 records the risk that a client speaks neither.

FACT about the library (`fastmcp_rust`, to re-read at the pin): stdio through `run_stdio_with_cx` (a blocking
pump) or, on Unix, `serve_stdio_io` over `NativePipeReader::from_stdin` and `NativePipeWriter::from_stdout`
(reactor-driven, no blocking pool); HTTP through `run_http_with_cx`, `bind_http`, `serve_http`; WebSocket through
`bind_websocket` and `serve_websocket` behind an experimental feature; legacy SSE through `run_sse_with_cx`; an
in-memory transport for tests. Native HTTP accepts credentials only in `Authorization`. OAuth and OIDC surfaces
are unpromoted. Wire cancellation is routed while a handler runs on Unix stdio and native WebSocket; non-Unix
stdio, SSE and custom transports keep blocking boundaries. The builder offers `.auth_provider`,
`.rate_limiting`, `.subscription_capacity`, `.request_timeout`.

Tier Solid (WebSocket excluded). This completes the M3 form of the admission gate INT-FMCP-01, which is re-run
on the full surface.

## Scope

In: launch modes and flags; stdio session binding from the environment; the HTTP transport, its bind rule and
its `AuthProvider`; mapping of authentication failures to the failure classes; rate limiting and listener
bounds; `frobd --mcp`; the WebSocket flag; the absence of SSE; per-transport conformance. Out: token minting,
scopes and attenuation (BD-258); the tools, resources and prompts served (their beads); the Tasks extension
(N32a-30); the socket-fallback workspace (N32a-06).

## Technical approach

**Launch (DESIGN flags).** `frob-mcp` (stdio, the default); `frob-mcp --http 127.0.0.1:<port>`;
`frobd --mcp [--mcp-http 127.0.0.1:<port>]`; `--clusters <list|all>`; `--compat-verb-invoke`;
`--experimental-websocket <addr>` (compiled only with the feature `experimental-websocket`, prints a warning
that it is unsupported, and is excluded from every gate). No flag enables SSE: the code path is not compiled.

**Server build.** `auto::ServerBuilder::new("frob-mcp", <version>)` with `.request_timeout(40)`,
`.strict_input_validation(true)`, `.mask_error_details(true)`, `.on_duplicate(DuplicateBehavior::Error)`,
`.subscription_capacity(64)`, `.rate_limiting(…)`, `.auth_provider(…)` on HTTP, `.instructions(<constant>)`,
`.try_build()`.

**stdio.** On Unix the reactor-driven pairing (`serve_stdio_io` over the native pipe reader and writer), so that
wire cancellation is routed while a handler runs; elsewhere the blocking pump. The session token is read once
from the environment variable `FROB_SESSION` at start-up. Standard output carries protocol frames only; all
logging goes to standard error or a file (a stray print would corrupt the stream, so a lint forbids `println!`
in the crate).

**HTTP.** Bound to 127.0.0.1 unless configured. A non-loopback bind requires both `--bind <addr>` and
`--allow-remote`, refuses to start without capability tokens enabled, and logs a warning (DESIGN, fail-closed;
the plan says only "unless configured"). The `AuthProvider` reads the bearer token from `Authorization`,
verifies it with the daemon key (signature, expiry), and attaches the resulting capability token to the
connection so that `ctx.auth()` returns it to the request pipeline. The library's OAuth and OIDC surfaces are
not used and not compiled in.

**Authentication and the failure classes.**

| Situation | Answer |
|---|---|
| HTTP request with no `Authorization` header, or a header that is not a bearer token | The library's unauthorized response; no handler runs, nothing is charged (protocol class) |
| A well-formed token that is invalid or expired | `FROB-REF-723` (exit 5) in an envelope for a tool call; the library's unauthorized response for the handshake |
| A valid token lacking the scope a verb requires | `FROB-REF-720` (exit 5), naming the scope |
| stdio with no `FROB_SESSION` | Before tokens exist: the local principal with a warning. Once tokens are enabled: every tool call is refused with `FROB-REF-723` and a repair naming `frob session open`; `tools/list`, static resources and prompts still work |

**One token, both surfaces.** The same token string works as `--session` on the CLI, as `FROB_SESSION` for
stdio and as the HTTP bearer token, and yields the same principal, namespace, scopes and budgets. Two HTTP
connections with different tokens are different principals on one server.

**Governance.** Rate limiting per session through the library's limiter (DESIGN default: 20 calls per second
with a burst of 40; configuration); the listener bound of 64 subscription streams server-wide; the 40 s request
timeout as the wall-clock ceiling of a call (long work is a job, so no call needs longer).

**`frobd --mcp`.** The daemon loads the `frob-mcp` library and serves its HTTP transport in process; the adapter
calls the job engine directly. There is then one process to supervise; killing a client connection affects no
job, and stopping the daemon stops the MCP transport with it.

Determinism: transports carry bytes; for a given call the envelope is identical on every transport after
masking `cost.wall_ms`.

## Acceptance criteria

- [ ] The full conformance suite of the MCP surface passes on stdio (reactor-driven on Unix), on loopback HTTP and on the in-memory transport, with identical masked envelopes for identical calls.
- [ ] INT-FMCP-01, M3 form: `frob-mcp` builds in the core graph on T with exactly one asupersync package, lists the tools generated from the full registry, and passes the protocol smoke test over stdio and HTTP; the record is appended to the admission file.
- [ ] HTTP binds to 127.0.0.1 by default; a non-loopback bind without both flags, or without tokens, refuses to start.
- [ ] The four authentication situations of the table produce the stated answers; nothing is charged in the first.
- [ ] One token gives the same `session.show` on the CLI, over stdio and over HTTP.
- [ ] Exceeding the rate limit yields the library's rate-limit response and no partial work; the 65th subscription is refused.
- [ ] `frobd --mcp` serves the same tools as a separate `frob-mcp`, and killing 100 client connections during waits loses no job.
- [ ] The binary built without the experimental feature has no WebSocket listener, and no build has an SSE endpoint (a symbol and a port-probe check).
- [ ] Nothing but protocol frames is ever written to standard output in stdio mode (10⁴ calls, including refusals and panics).

## Test plan

### Unit tests (`cargo test -p frob-mcp transports auth`)
- `stdio_reactor_on_unix` (compile-time selection test); `stdio_stdout_frames_only`.
- `http_default_bind_loopback`; `http_remote_bind_needs_both_flags`; `http_remote_bind_needs_tokens`.
- `bearer_only_in_authorization`: a token in a query parameter or a cookie is ignored and the request is unauthorized.
- `expired_token_723`; `missing_scope_720`; `stdio_without_session_after_tokens_723`.
- `same_token_same_principal_three_ways`.
- `two_tokens_two_namespaces_one_server`: a write by one is invisible as a writable object to the other (`FROB-REF-725` on cross-namespace write).
- `rate_limit_refuses_cleanly`.
- `request_timeout_is_40s`.
- `no_sse_symbol`, `no_websocket_without_feature`.
- `frobd_mcp_same_tool_list`: equal `tools/list` bytes for the hosted and the standalone server.

### End-to-end script and logging
`scripts/e2e/mcp_transports.sh`: starts `frobd`, opens two sessions with different scopes; runs the conformance
calls over stdio (subprocess with `FROB_SESSION`), over loopback HTTP (bearer tokens), and against
`frobd --mcp`; runs the authentication table; floods one session past the rate limit; probes for SSE and
WebSocket endpoints. It sources the shared helper and writes `target/e2e-logs/mcp_transports/<utc>.ndjson` plus
wire transcripts with tokens redacted: `cmd` lines with exit code and wall time; `metric` lines for the protocol
revision negotiated per transport, calls compared across transports and differing (threshold 0), asupersync
package count (1), rate-limited calls, connections killed and jobs lost (0); `refusal` lines with codes for the
authentication rows; a `summary` naming INT-FMCP-01 (M3). Tokens never appear in logs.

### Known answers and negative controls
- Known answer: identical masked envelopes across the three transports for the same call and token.
- Negative controls (each must be caught): a build that accepts a token from a query string; a build that binds 0.0.0.0 by default (the bind test and a port probe from a second interface); a `println!` in a handler (the stdout-frames test); a server that maps focus to authority (a tool visible but unscoped must still be refused 720).
- Determinism lanes: `tools/list` and the conformance envelopes identical twice on one machine, per transport, in debug and release.

## Considerations

- OPEN-TETHER-2: if a harness speaks neither served protocol revision it cannot use MCP at all and falls back to the CLI; the transport record states which revision each harness negotiated.
- On non-Unix platforms stdio uses the blocking pump and cancellation is only observed at checkpoints; the long-tool handler checkpoints at every frame, so the wait still ends, at the next frame.
- The WebSocket path stays behind a flag until the library promotes it; nothing may depend on it.
- A loopback HTTP server is reachable by every local process of any user; the bearer token is therefore mandatory on HTTP once tokens exist, and before that the HTTP transport is offered only in single-user development mode with a warning (DESIGN).
- If the kill gate KILL-MCP fired, `frobd --mcp` is not offered and the standalone server uses the socket back end; this bead's transports are unchanged.
