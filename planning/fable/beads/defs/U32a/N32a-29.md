## Background

A kill gate in this project is a decision written before the work starts: a trigger with its measurement, a
milestone, and a fallback named in advance. This bead is the decision for **KILL-MCPTASKS**.

The mechanism at stake is an optional adapter in the MCP server `frob-mcp` that surfaces a long-running job as an
MCP Task (an extension of protocol revision 2026-07-28), through an application-owned store backed by the
daemon's job ledger. Its ceiling was stated before any test: no compute is saved; the benefit is client-native
progress display, bounded by the number of long jobs in a session. The decision of record (ADR-TETHER-06) is
that the extension is never the primary contract: every client, on every protocol era, can hold a job with the
handle contract (a call whose bounded wait elapses returns exit code 8 and a job handle; `job_wait` continues
the wait). The upstream library labels its Tasks support experimental and provisional (FACT, to re-read at the
pin).

## Scope

In: reading the pilot, deciding, recording, the standing re-read whenever the library pin moves, and the
consequences on each branch. Out: the pilot (N32a-28); the adapter (N32a-30, which exists only if this gate does
not fire).

## Technical approach

**The gate.**

| Item | Value |
|---|---|
| Trigger | The pilot fails (one disagreement between Task states and ledger states over 20 scripted jobs on the in-memory transport); or the extension changes incompatibly |
| Milestone | M3; and a standing re-read at every move of the `fastmcp_rust` pin thereafter |
| Measurement | The pilot record: comparisons made, disagreements, identifiers resolved after a server restart, the library commit and the Task state names as read |
| Fallback | Job handles only |

**Decision procedure, numbered.**
1. Read the pilot record. Verdict `pass` with zero disagreements and a non-zero comparison count: not fired.
   Verdict `fail`: fired.
2. Classify a failure for the record: (a) a mapping defect in the prototype (repairable here: one repair and one
   re-run are allowed, since the falsifier is about the mechanism, not about a typing error in the prototype;
   DESIGN); (b) the library cannot host an application-owned store, or loses identifiers across a restart
   despite one; (c) the extension's surface differs incompatibly from what the design assumed. For (b) and (c)
   the gate fires without a re-run and an upstream work item is opened in the library's repository if the
   defect is the library's.
3. Write the ADR (`docs/adr/tether/KILL-MCPTASKS.md`) with the record's hash, the classification and the branch.
4. Standing re-read: the compatibility train re-runs the pilot script whenever the library pin moves. A later
   failure fires the gate then (the "extension changes incompatibly" clause), and the adapter's feature is
   turned off in the same change.

**What changes downstream.**

| Branch | Consequence |
|---|---|
| Not fired | The adapter bead is funded. `run` tools may surface their job as a Task for clients that negotiate the extension. The handle contract is unchanged and remains what every gate measures |
| Fired | The adapter is not built, or its cargo feature is disabled if it was. `frob-mcp` does not advertise the Tasks capability and registers no task supervisor. Nothing else changes: the bounded wait, `job_wait`, `job_cancel`, progress and resource subscriptions on `frob://job/{id}` are complete without it. The MCP surface gate has no Tasks clause, so it is unaffected. The generated guide omits any mention of Tasks |

## Acceptance criteria

- [ ] An ADR for KILL-MCPTASKS exists with status `not fired` or `fired` and the classification, citing the pilot record by hash and the library commit.
- [ ] The kill-gate register row carries the decision, date and commit.
- [ ] The compatibility train's gate list includes the pilot script, so that a pin move re-reads the gate.
- [ ] If fired: `frob-mcp` built by default advertises no Tasks capability (checked on the wire), and the handle-contract tests pass unchanged.
- [ ] If not fired: the adapter bead is unblocked and names this ADR.

## Test plan

### Unit tests
- `decision_table`: (verdict, comparisons, classification) → branch: (pass, 240, –) → not fired; (pass, 0, –) → invalid record, no decision; (fail, –, a, repaired and re-run pass) → not fired with the repair recorded; (fail, –, a, re-run fail) → fired; (fail, –, b) → fired; (fail, –, c) → fired.
- `adr_status_consistent_with_record`.
- `capability_not_advertised_when_fired`: the initialize result of a default build contains no Tasks capability.
- `handle_contract_independent_of_tasks`: the bounded-wait and `job_wait` tests pass with the adapter feature off.

### End-to-end script and logging
`scripts/e2e/kill_mcptasks_decision.sh`: reads the pilot record; applies the table; in the fired branch builds
the default server, performs the handshake over stdio and loopback HTTP and asserts the capability is absent,
then runs the handle-contract smoke (a `run` tool with `sync_wait_ms: 0`, then `job_wait`). NDJSON under
`target/e2e-logs/kill_mcptasks_decision/`: `cmd` lines; `metric` lines repeating the pilot's comparisons and
disagreements; `assert` lines for the branch, the capability and the handle contract; a `summary` naming
KILL-MCPTASKS.

### Known answers and negative controls
- Known answer: the six rows of the decision table.
- Negative controls: a record with zero comparisons labelled `pass` (must be rejected as invalid); an ADR `not fired` citing a failing record (the consistency test must fail); a fired branch in which the server still advertises the capability (the wire check must fail).

## Considerations

- The gate is cheap to fire and cheap to reverse: the adapter is behind a cargo feature and the fallback is the system's ordinary behaviour.
- One repair of the prototype before firing is DESIGN; the plan's falsifier ("one disagreement falsifies it") is applied strictly to the repaired prototype.
- Whether any harness in use displays Tasks is a separate observation of the harness compatibility experiment; if none does, the adapter may be left unbuilt even when the gate does not fire, and the ADR says so.
