## Background

FrankenRobotics keeps its enumerable facts in registry files under `registries/` in the repository: the verbs,
the refusal codes, the capability scopes, the formats, the gate status, the compute envelope and others. The
binaries `frob` (command line), `frobd` (daemon) and `frob-mcp` (MCP server) use them in two different ways, and
no rule said which registry is used how, or how a test points a binary at a copy.

- Some registries **define the surface or the meaning of an identifier**. The verb registry is compiled into a
  static table by a build script (ADR-TETHER-01), and the refusal registry is embedded and turned into the code
  type; a deployment can therefore never serve a surface the tests did not see. These cannot be changed without
  a rebuild.
- Some registries **record a decision or a status that changes without a rebuild**. The first is the compute
  envelope (`registries/compute_envelope.toml`): the owner's ruling on how much compute a job may use. The
  fail-closed default is class E0 (16 GiB, 8 cores, 1 hour, one device), inherited from the machine rule of the
  simulation foundation; classes E1 to E3 exist only once the owner approves a request row. `sim.estimate` prints
  the class a job needs, and a job above the class in force is refused before it starts (`FROB-REF-761`). An
  approval is an edit of that file, so the file must be read when the tool runs.

Three beads test the envelope with a **scratch registry**: a copy of `registries/` in which a test marks a row
approved, so that admission under an approval can be exercised without touching the committed file. They need a
named way to make `frob` and `frobd` read `registries/` from another directory. That switch is also a hazard: it
is exactly the lever by which an agent could approve itself a larger envelope. This bead names the switch and
makes its use visible, unusable for evidence, and unable to spend compute beyond what the registry of record
allows.

DESIGN decisions. (1) One process option, `--registries-root`, and one environment variable,
`FROB_REGISTRIES_ROOT`; never a verb parameter, so it cannot be set through an MCP tool call. (2) Only run-time
registries follow the root; embedded ones never reload. (3) A root other than the default is a **scratch** root:
everything produced under it is marked, and jobs it admits beyond the class in force of record are held, not run.
Rejected: a per-verb `registries` parameter (an agent-reachable way to change the rules it is judged by); reading
every registry at run time (the served surface could then differ from the tested one); a test-only build with the
approval compiled in (the tests would no longer drive the binary that ships).

Tier Solid. Crates: `frob-core` (index, resolver, digests), `frob-verbs` (the mark on envelopes and receipts),
`frob-cli` (the option on `frob` and `frobd`), `surface/frob-mcp` (the launch option), `frob-conformance` (the
gate recorder's hook `receipts_of_record`).

## Scope

In: the index that classifies every registry file as embedded or run-time; the resolver and its order; the three
kinds of root; what a scratch root marks and forbids; the execution hold; digests in receipts and in the daemon's
configuration digest; fail-closed behaviour of a missing or malformed run-time registry; the `registries` section of `frob doctor`
(`frob doctor --section registries`, or its shorthand `--registries`); the same option on the repository's own
tools; tests. The consequences of a
hold are asserted by the beads that call `scratch_hold`: N36-20 (the M0 refusal) and N32a-08 with N32a-09 (the held
job from M1), all of which depend on this bead. Out: the content and schema of any registry
(their owning beads: the compute envelope record N21c-35 and its enforcement N36-20; the verb registry N32a-02
and NJL-01; the refusal registry N35-33); the build-time override used to plant a defective verb registry in a
negative-control lane (NJL-01); the daemon's state root (N32a-14); the gate recorder (N38b-19) and its hook
mechanism, to whose step-7 hook list this bead adds one entry.

## Technical approach

**1. The index** (`registries/index.toml`, schema `frob.registries.index/1`; itself embedded).

```toml
[[registry]]
file = "verbs.toml"
class = "embedded"                 # compiled in by the owner's build script
owner = "frob-verbs"
[[registry]]
file = "compute_envelope.toml"
class = "runtime"                  # read from the registries root when the process starts
owner = "frob-core"
fail_closed = "class E0 in force; no request row approved"
```

Initial classification: `verbs.toml`, `refusals.toml`, `scopes.toml` and `formats.toml` are `embedded`;
`compute_envelope.toml` is `runtime`. Every other file under `registries/` gets a row from its owning bead; the
default for a file whose owner states nothing is `embedded`. Checks (in `xtask check-generated`):
`registry-unlisted` (a file under `registries/` with no row); `runtime-without-fail-closed`;
`embedded-without-build-digest` (an embedded registry whose digest is not recorded in the binary). A run-time
registry also ships as an embedded snapshot, used only by rule 3 below.

**2. Resolution** (`frob_core::registries::resolve_root`; first match wins).

| Order | Source | Kind of root |
|---|---|---|
| 1 | The process option `--registries-root <dir>` | `override` |
| 2 | The environment variable `FROB_REGISTRIES_ROOT` | `override` |
| 3 | The workspace's `registries/` directory, whose path is recorded at build time, if it exists | `of-record` |
| 4 | The embedded snapshots, each with its fail-closed reading | `embedded-snapshot` |

The option is a process option like `--json`: `frob --registries-root DIR sim estimate …`, `frobd
--registries-root DIR`, `frob-mcp --registries-root DIR`. It is not in any verb's input schema, so a tool call
that carries a property of that name is `FROB-REF-802`. The directory must exist, be owned by the user and not
be writable by others; symbolic links are resolved first. When a daemon is running its root governs: a `frob`
started with a different root than the daemon's is refused (`FROB-REF-802`, `pointer: /registries_root`,
`observed` and `required` naming the two), because a client must not change the rules of a shared daemon.
`frob` without a daemon reads the run-time registries on every invocation; `frobd` and `frob-mcp` read them at
start, and a changed file takes effect at the next start.

**3. Reading.** Each run-time registry is read, validated against its schema and hashed (BLAKE3 of the file's
bytes). A missing or invalid file does not stop the tool: its `fail_closed` reading is in force, every envelope
carries the warning `registries: fail-closed <file>`, and `doctor` reports a finding. An embedded registry is
never read from the root; if the root holds a copy whose digest differs from the compiled one, `doctor` lists
`embedded-mismatch: <file>` and the compiled registry stays in force.

**4. What a scratch root does.** When the kind is `override`:
1. *Scratch state is required.* The process refuses to start unless its state root (`FROB_STATE`) is not the
   default per-user directory (`FROB-REF-802`, exit 3). Scratch approvals therefore never meet the ledger, the
   budget tables or the device-hour meter of record.
2. *The mark.* Every envelope carries the warning `registries: override`; every job receipt and the daemon's
   configuration digest include `registries: { kind, root_digest, files: { <file>: <digest> } }`.
3. *Not evidence of record.* `frob_core::registries::assert_of_record(receipt)` fails for a receipt whose kind is
   not `of-record`; a run-time registry in its fail-closed reading also fails the check. The recorder cannot call
   this bead (this bead depends on it, through BD-022), so this bead registers the check with it: the hook
   `receipts_of_record` in `register::record::CHECKS` of `frob-conformance` (N38b-19's step 7), a pure function
   of the candidate row and its resolved evidence that returns the harness reason `receipt-not-of-record` when
   `assert_of_record` fails for any evidence receipt, so no gate row can cite a run made under a scratch or
   snapshot root.
4. *Verdicts from the scratch root, execution bounded by the record.* Admission decisions (class in force,
   `FROB-REF-761`, the refusal payloads) are computed from the scratch registries, which is what the tests
   observe. In addition the process loads the registries of record (rule 3 or 4 of the table) and, for each
   admitted job, compares the class it needs with the class in force **of record**. A job that needs more is
   admitted and held: state `admitted`, `hold: scratch-approval`, no device allocation, no world stepped, until it
   is cancelled. A scratch approval can show that a job would be admitted; it cannot run it. This bead provides the
   decision as a pure function, `frob_core::registries::scratch_hold(needed: Class, in_force_of_record: Class,
   root_kind: RootKind) -> Option<Hold>`; the hold is stored where jobs are: the column `hold` of the job row
   (N32a-08, M1), written by the admission transaction (N32a-09, M1), which calls this function. Before the job
   ledger exists (M0) there is no job to hold: a run under a scratch root that this function would hold is not
   started and its envelope is refused with `FROB-REF-761`, whose payload adds `scratch_verdict: "admitted"`, so
   the test still observes what the scratch approval would decide.

**5. The `registries` section of `doctor` (`frob doctor --section registries --json`).** Contributed through
BD-022's section interface, under the selector the operator row of record registers (`--section`, repeatable),
with the shorthand `--registries` that the same row registers for this section (so it is a declared input, not a
parser-only flag). Prints the root, its
kind, and per registry: class, owner, digest (compiled digest for embedded, file digest for run-time), schema
validity, the fail-closed reading if it is in force, and any embedded mismatch. One finding per condition, with
BD-022's severities: `low` for an override or snapshot root and for an embedded mismatch, `high` for a run-time
registry that is missing or invalid (its fail-closed reading in force). Exit 0 when the kind is `of-record` and
every file is valid; exit 2 otherwise (a finding above `info`).

**6. The repository's own tools.** `xtask` checks, the gate recorder and the conformance runners take the same
option and variable through the same resolver, so that a test can run a check against a scratch gate or envelope
registry. Their outputs carry the same `registries` block.

Files: `registries/index.toml`; `crates/frob-core/src/registries/{index,resolve,digest,record}.rs`; the option
in `crates/frob-cli/src/options.rs`; the hook's entry in `frob-conformance`'s `register::record::CHECKS`;
`schemas/frob.registries.index.1.json`. Determinism: resolution and digests
are exact (class D0); no result depends on the root's path, only on the files' contents.

## Acceptance criteria

- [ ] `registries/index.toml` lists every file under `registries/`; the three index checks each fire on a planted defect.
- [ ] Resolution follows the table: with both the option and the variable set the option wins; with neither, the kind is `of-record`; with the workspace directory absent, `embedded-snapshot`.
- [ ] Under an override root every envelope carries `registries: override`, and `frob doctor --section registries --json` reports the kind, the root and one digest per registry with exit 2.
- [ ] An override root with the default state root is refused before any verb runs.
- [ ] No verb input schema and no MCP tool definition has a property that sets the root; a tool call that sends one is `FROB-REF-802`, exit 3.
- [ ] Editing `compute_envelope.toml` under a scratch root changes its digest in the `registries` section and in the next envelope's `registries` block at the next `frob` invocation (and, once N21c-35's `class_in_force` exists, the class in force for the edited row's scope); editing a scratch `verbs.toml` changes nothing and is reported as `embedded-mismatch`.
- [ ] A truncated run-time registry leaves the tool running in the fail-closed reading (class E0 for the envelope), with the warning and a `doctor` finding.
- [ ] `scratch_hold` returns a hold exactly when the root kind is `override` and the class needed exceeds the class in force of record (table-driven over the 4 × 4 classes and the three root kinds).
- [ ] The two consequences are run by this bead's tests and script as soon as their callers exist, and are logged `skipped: capability absent` before, never as passed: once N36-20 lands (M0), with E1 approved only in a scratch registry for a scope `gate:<id>`, a run that needs E1 and cites that scope (`--envelope-scope gate:<id>`) is not started and is refused with `FROB-REF-761` carrying `scratch_verdict: "admitted"`; once N32a-08 and N32a-09 land (M1), the same job is admitted and held: zero worlds stepped and zero device bytes allocated after 5 s; cancelling it yields a cancellation receipt. The same run with no citation is `adhoc`, whose class in force is E0 whatever the registry holds: a plain `FROB-REF-761` without `scratch_verdict` (`FROB-REF-704` from BD-296's size classifier when the job is campaign-class, N36-20), never a hold.
- [ ] `assert_of_record` rejects a receipt of kind `override` or `embedded-snapshot` and a receipt with a fail-closed registry; it accepts an `of-record` receipt. The hook `receipts_of_record` is in `register::record::CHECKS` and returns `receipt-not-of-record` for a candidate row citing any of the three rejected receipts.
- [ ] From M2: `frobd`'s configuration digest changes when a run-time registry's digest changes, and a client whose root differs from the daemon's is refused.
- [ ] The committed `registries/` directory is byte-identical before and after the whole test suite.

## Test plan

### Unit tests

`cargo test -p frob-core registries` and `cargo test -p frob-cli --test registries_root` (real files in temporary
directories; fixture registries are labelled `synthetic`):
- `resolve_order`: option over variable over workspace over snapshot, four cases.
- `kind_of_record_by_default`; `snapshot_when_workspace_absent`.
- `root_must_be_safe_directory`: a file, a missing path, a directory writable by others → refused; a symbolic link is resolved and reported by its target.
- `override_requires_scratch_state`.
- `override_marks_every_envelope`: `doctor`, a `read` verb and a refused call each carry the warning.
- `runtime_reread_each_invocation`; `embedded_never_reloaded` (a scratch `verbs.toml` with an extra verb: the verb is unknown, code 801; `doctor` lists the mismatch).
- `malformed_runtime_fails_closed`: a truncated `compute_envelope.toml` → class in force E0, warning present, `doctor` exit 2.
- `digest_is_of_bytes`: one changed byte changes the digest; the receipt's `registries` block lists it.
- `assert_of_record_cases`: the four receipts of the acceptance criterion.
- `receipts_of_record_hook` (`cargo test -p frob-conformance receipts_of_record`): the hook is listed in `register::record::CHECKS`; on a candidate row whose evidence receipt has kind `override`, `embedded-snapshot` or a fail-closed registry it returns `receipt-not-of-record`, and on an `of-record` receipt `Ok` (the recorder's own `hook_refusal_stops_write` covers what a refusing hook does to the write).
- `scratch_hold_table`: the pure function over every (needed, in force of record, root kind) triple; a hold only for `override` with needed above the record.
- `m0_scratch_verdict_without_ledger` (enabled once N36-20's admission, which calls `scratch_hold`, exists; `skipped: capability absent` before): a `synthetic` two-device run citing `gate:<id>` under a scratch E1 approval for that scope, with no job ledger → not started, `FROB-REF-761` with `scratch_verdict: "admitted"`, worlds-stepped counter 0.
- `uncited_run_is_adhoc`: the same run with no citation → class in force E0, `FROB-REF-761` without `scratch_verdict`, no hold.
- `hold_on_scratch_approval` (enabled once the job ledger exists, M1): the same specification → admitted, `hold: scratch-approval`, device-allocation counter 0, worlds-stepped counter 0; `cancel` → `cancelled`.
- `no_hold_when_record_allows` (enabled with N36-20): a job that needs E0 under a scratch root starts normally.
- `doctor_registries_section`: `frob doctor --section registries --json` under the default root → exit 0; under an override root → one `low` finding, exit 2; with a truncated run-time registry → one `high` finding; the shorthand `frob doctor --registries --json` returns the same section byte for byte.
- `mcp_schema_has_no_root_property`: searched over every generated tool definition.
- `index_checks`: the three planted indexes.
- `client_daemon_root_mismatch` (enabled when the daemon exists).

### End-to-end script and logging

`scripts/e2e/registries_root.sh` (header: `bead=N32ax-03 milestone=M0 labels=tether,registries,envelope seed=1
needs=cpu,mcp plants=per-call-root,no-mark,no-hold`). The script creates a scratch directory and fails at once if it
resolves inside the repository. Steps: (1) record the BLAKE3 of every committed registry file; (2) `frob doctor
--section registries --json` → kind `of-record`, exit 0; (3) copy `registries/` to the scratch directory and set a
scratch `FROB_STATE`; `frob --registries-root <scratch> doctor --section registries --json` → kind `override`, exit 2;
(4) the same through `FROB_REGISTRIES_ROOT` → identical digests; (5) without the scratch state root →
`e2e_expect_refusal FROB-REF-802 3 -- frob --registries-root <scratch> doctor --section registries --json`; (6)
`frob --registries-root <scratch> sim estimate "$(e2e_fixture two-card-train)" --json` (the path from the
helper, since the `@fixture:` resolver, N34p3-01, builds on this bead's build-time record of the workspace) →
class needed E1, class in force E0; approve an E1 request row for a scope `gate:<id>` in the scratch
`compute_envelope.toml`; repeat → the changed envelope digest and the warning `registries: override`, and still
class in force E0, because an estimate is a read and prices the `adhoc` scope (N36-20) (logged `skipped:
capability absent` until the envelope record and its enforcement exist, never as passed); (7) submit the job as
a run citing the approved scope, `--envelope-scope gate:<id>`, with its own idempotency key (`--key
"$(e2e_key rr-hold-s<seed>)"`) →
before the job ledger exists, refused `FROB-REF-761` with `scratch_verdict: "admitted"` and zero worlds
stepped; from M1, admitted with `hold: scratch-approval`; after 5 s assert zero worlds stepped; cancel; then the same run with no citation and its own key (`--key
"$(e2e_key rr-adhoc-s<seed>)"`) → `adhoc`, a plain `FROB-REF-761` without `scratch_verdict` (or
`FROB-REF-704` once BD-296's size classifier exists and the job is campaign-class) (each logged `skipped:
capability absent` until N36-20, respectively N32a-08 and N32a-09, have landed); (8) truncate the scratch
envelope file → class in force E0, warning `registries: fail-closed compute_envelope.toml`; (9) start `frob-mcp
--registries-root <scratch>` over stdio, list the tools, assert no root property, call one tool with a
`registries_root` argument → the library's validation error mapped to `FROB-REF-802`; (10) re-hash the committed
registry files and assert equality with step 1; (11) the three plants must each be caught. Logs through the
shared helper to `target/e2e-logs/registries_root/<utc>.ndjson` with a transcript: each `cmd` with exit code and
wall time, the envelope's `evidence` block and warnings, `assert` lines with observed and expected kind and
digests, `metric` lines `worlds_stepped_while_held` (== 0) and `device_bytes_while_held` (== 0), each refusal
with code and pointer, the scratch paths on failure, and the `summary`.

### Known answers and negative controls

- Known answer (exact): the resolution table; the fail-closed reading of the envelope is E0.
- Negative controls: `per-call-root` (a build that accepts the root as a verb parameter: step 9 must fail);
  `no-mark` (a build that omits the warning under an override: step 3 must fail); `no-hold` (a build that starts
  a job admitted only by a scratch approval: the zero-worlds metric must fail); a gate record made from an
  override receipt (the recorder's hook `receipts_of_record` must refuse it with `receipt-not-of-record`).
- Metamorphic: copying the registries of record to a scratch root unchanged gives the same verdicts for every
  call as the default root, differing only in the warning and the receipt's kind.
- Determinism lanes: twice on one machine, debug and release, Linux and macOS.

## Considerations

- Threat boundary. Every agent on a host runs as the same user and can set an environment variable. The switch
  cannot be made secret; it is made harmless: marked, isolated from the state of record, excluded from gate
  records, and unable to release compute beyond the record. The owner approves an envelope only by changing the
  registry of record.
- The machine rule of 16 GiB, 8 cores and one hour applies to builds and tests too. The hold is what lets an
  envelope test show an approval's effect while executing nothing above class E0.
- A relocated binary with no workspace directory runs on the embedded snapshots, which for the envelope means
  E0. That is fail-closed and is reported, not hidden.
- Which further registries are run-time is their owners' statement in the index. A registry moved from embedded
  to run-time loses the guarantee that the tested surface is the served one; the index check
  `runtime-without-fail-closed` is the minimum such a move must meet.
- Some scripts name a scratch store by another variable; the state root meant here is the daemon's.
- If kill gate KILL-MCP fires and `frob-mcp` reaches verbs only through the daemon's socket, the daemon's root
  governs and the MCP server's launch option only has to agree with it.
