## Background

A session is how an agent enters the system. `session.open` states what the agent may do and spend; `session.show`
answers "what can I do, what have I left, where am I". They are two of the four verbs of the `session` cluster in
the verb registry (`registries/verbs.toml`), from which the command line, the MCP tools, the schemas and the agent
documentation are generated. `session.show` is in the default task cluster `orient`, so it is among the first
tools a fresh agent sees.

Both verbs exist from the first milestone in a minimal form (a session identifier and a namespace, no
enforcement). This bead delivers the form in which tokens and budgets are real (second milestone): `session.open`
mints a capability token (N32b-01) and `session.show` reports live budget accounting. At the third milestone the
same verbs carry derivation (N32b-02) and the namespace rules (N32b-03); their schemas are fixed here so that the
later beads add behaviour, not fields.

Principle served: units, seeds, budgets, versions and capabilities are never implicit. An agent can always ask the
system what its authority and remaining budget are, in typed fields with units, instead of inferring them from
refusals.

## Scope

In: registry entries, input and output schemas, examples and refusal lists for `session.open` and `session.show`;
the CLI flags and the MCP tool forms; idempotency of `session.open`; the budget table; listing of derived
sessions; the daemon's overhead line; the secret-marking of the returned token; paging of long session lists.
Out: token mechanics (N32b-01); derivation checks and debit (N32b-02); namespace rules (N32b-03); `session.focus`
and `session.close` (the other Tether unit); the `transcript` input and the `audit` action of `session.show`
(N32bx-01, M3; they answer `FROB-REF-724` before it lands), which the diagnosis battery reads (N32b-38); the
`safety.toml` file and its `principal.<id>` tables (N37-02).

## Technical approach

**Registry entries (DESIGN).**

```toml
[[verb]]
name = "session.open"
cluster = "session"
kind = "mutate"
tier = "S"
capabilities = []                       # opening a root session needs the local socket, not a prior token
public = true                           # the registry's flag for a row that needs no scope (lint: `[]` without it fails)
option_capabilities = {}                # derive = true is checked by the attenuation order (N32b-02), not a scope
input_schema = "frob.session.open.in/1"
output_schema = "frob.session.open.out/1"
refusals = []                           # chapter codes: none; the generator appends by kind (below)
idempotent = false                      # the registry's rule for `mutate`: replay safety comes from the key
first_milestone = "M0"
task_clusters = ["housekeeping"]        # the task-cluster table (NJL-05): `operate` is full at seven
examples = ["frob session open --scopes design:write,sim:run --budget gpu_s=600,cpu_core_s=7200 --key s-1 --json"]

[[verb]]
name = "session.show"
cluster = "session"
kind = "read"
tier = "S"
capabilities = []                       # a session may always read itself
public = true
option_capabilities = { all = ["session:read"] }   # listing every session's budget table
paginated = true                        # `children` and the `all` listing are paged: adds cursor, limit, follow
input_schema = "frob.session.show.in/1"
output_schema = "frob.session.show.out/1"
refusals = []                           # chapter codes: none; the generator appends by kind (below)
idempotent = true
first_milestone = "M0"
task_clusters = ["orient"]
examples = ["frob session show --json"]
```

The generated refusal lists, by the registry's rule for each kind (NJL-01): `session.open` (mutate) 720, 723,
724, 725, 802, 803, 804, 805, 808 (808: a budget count outside ±(2⁵³ − 1)); `session.show` (read, paginated)
720, 723, 724, 802, 806, 807, 808. DESIGN, `capabilities =
[]` on both: the worked MCP session holds six scopes, none of them `session:*`, and calls `session_show`
successfully, so reading one's own session must need no scope; and a root `session.open` has no prior token to
hold one. `option_capabilities` (DESIGN, a registry field added here) names a scope that one option needs; the token
check of N32b-01 applies it when the option is present, and the scope-catalogue lint counts a scope used by an
option as used, so `session:read` is a live scope. The registry rows bead for the cluster (VERBS-session, a
dependency) carries the same values, `public = true` and `paginated = true` included; the fields not written
above (`cost_model`, `owner`, `purpose`) follow that bead's rule for the cluster.

**`session.open` input.** `scopes` (list of catalogue scopes, non-budget); `budget` (map: `gpu_s`, `cpu_core_s`,
`disk_bytes`, each an `int53` count, and optional caps `wall_s`, `sim_s`, `device_mem_bytes`, `trace_bytes`,
`episodes`); `namespace` (optional; root sessions only); `principal` (optional; root sessions only: the agent
principal whose grant, the table `principal.<id>` of the owner-held `safety.toml` (N37-02), the root token is
minted from, by N32b-01's minting rule); `derive` (boolean: derive from the caller's token, which travels in
`FROB_SESSION_TOKEN` or `--session-token-file` and never as an argument; the
field is in the schema from M2, and until the derivation bead N32b-02 lands at M3 `derive: true` is refused with
`FROB-REF-724`, reason `not-linked`, so an agent learns the option exists and when);
`ttl_s` (optional, at most the daemon's maximum); `idempotency_key` (required; absent gives `FROB-REF-805`). The CLI
spelling is `--scopes a,b,c --budget gpu_s=1800,cpu_core_s=7200 --principal agent-17`; a budget entry `gpu_s=N`
is stored as the scope `gpu:seconds=N`, `cpu_core_s=N` as `cpu:core_seconds=N`, `disk_bytes=N` as `disk:bytes=N`.

Defaults and refusals of a root call (DESIGN; the rule is N32b-01's minting, stated here as the verb's contract).
Without `principal` the session is minted for the one principal of the configuration when it grants exactly one,
which keeps the plan's worked call (`session open --scopes … --budget …`, no principal) valid on a single-agent
host; when it grants several, the call is `FROB-REF-802` with `pointer: /principal` and the granted identifiers in
the repair; an unlisted principal, or any root call when none is granted, is `FROB-REF-723` (nothing to mint
from). Omitted `scopes` does not mean the principal's whole grant: authority is always named, so the session
holds no non-budget scope (it can call `public` verbs and read itself), as the named-scope rule of N32bx-02
requires; an omitted budget unit means the grant's amount of that unit; the output echoes the granted set and
table, so nothing stays implicit. A request beyond the
grant (scope, amount, lifetime above `max_lifetime_s`, namespace other than the grant's) is `FROB-REF-723` naming
the widening element. `principal` given with `derive: true` is `FROB-REF-802`: a derived session inherits its
parent's principal (N32b-02). A root call that presents a valid token is `FROB-REF-723` (N32b-01: a holder
derives), so over MCP, where every call carries a token, `session_open` is derive-only.

**`session.open` output.** `session` (`s:…`), `namespace`, `principal`, `scopes` (sorted; the set the token
holds, which is the requested set closed under the implied-read rule of N32b-01: `<cluster>:run` and
`<cluster>:write` add `<cluster>:read`, so a caller sees at once what it was granted), `budget` (the table
below, with `left = cap`), `expires` (an instant as `u64str` nanoseconds and an RFC 3339 rendering), `parent`
(or null), `focus` (`orient`, the task cluster a new session starts in; a field of the M1 form, BD-138, kept as
the registry row lists it), and `token` (schema-marked `x-frob-secret`: printed once, redacted by every logger). The envelope's
`bound` holds the session identifier; `next_actions` suggests `frob session show` and `frob robot-docs`. A replay
with the same key returns the stored session with `idempotent_replay: true` and does not print the token again
unless the daemon can re-derive it (it can: the token is a function of the session row and the key).

**`session.show` output.**

| Field | Content |
|---|---|
| `session`, `namespace`, `principal`, `parent`, `expires` | Identity of the session |
| `scopes` | The non-budget scopes the token holds, sorted: the requested ones and the `:read` scopes they imply (N32b-01) |
| `focus` | The MCP task cluster in view (`orient` by default); null on the CLI |
| `tools` | The names of the tools listed under that focus (the base tools and the focused cluster's), as `session.focus` returns them; a field of the M1 form (BD-138), kept as the registry row lists it; null where `focus` is null |
| `budget` | Per unit: `cap`, `reserved`, `spent`, `left`, with `unit` (`s`, `core_s`, `bytes`); `cap = reserved + spent + left + delegated`. The numbers are read through the budget ledger's report function `budget::report(session)` (N32a-15); `cap` is that ledger's `granted` column, and `delegated` (the caps of open derived sessions) is 0 before M3 |
| `budget_short` | `gpu_s_left`, `cpu_core_s_left`: the two numbers every envelope's `budget` field also carries |
| `children` | Derived sessions, open and closed: identifier, state, scopes, caps, spent, left, returned (paged with a cursor when long; always empty before M3) |
| `jobs` | Counts of this session's jobs by state |
| `daemon_overhead` | Device time charged to the daemon's own line (idle reserve), by device; reported, never charged to a session |
| `dispatch` | `daemon` or `in-process` (no daemon reachable; CPU-tier verbs only) |

Budget semantics shown (FACT about the design of the budget system): under shared batches a job is charged
attributable device time, the sum over steps of (its occupied slots ÷ batch capacity) × the step's wall time; idle
reserve goes to the daemon's overhead line. With `all: true` and the scope `session:read`, `session.show` lists
every open session's budget table (the dashboard's Budgets pane uses this); without the scope the option is
refused with `FROB-REF-720`.

**Surfaces.** CLI: `frob session open …`, `frob session show [--all] [--json]`. MCP: tools `session_open` and
`session_show`, generated by the generic verb handler from the same entries; annotations `read_only` for
`session_show`, `idempotent` for both. The human-readable CLI form prints the budget table with units.

**Evidence block.** Both envelopes carry class `Tested`, tier `static`, determinism `exact`, no claims, `reality:
no-claim`: they report ledger facts, not physics.

## Acceptance criteria

- [ ] Both verbs appear in the generated CLI and in the served MCP `tools/list` with identical schemas (the parity
      diff of GATE-TETHER-02 is empty for them), each with an example and a refusal list.
- [ ] On a state root whose `safety.toml` grants one principal these scopes and amounts, `frob session open
      --scopes design:write,mission:run,nemesis:run,autopsy:run,sim:run,qual:run --budget
      gpu_s=1800,cpu_core_s=7200 --key k --json` exits 0 with a session identifier, a namespace, the focus
      `orient` and a token.
- [ ] `session.show` then returns those six scopes and the reads they imply, sorted: for each requested
      `<c>:run` or `<c>:write`, the scope `<c>:read` when the catalogue has it (`design:read` and `sim:read`
      among them; the test computes the expected set from `registries/scopes.toml` by N32b-01's rule); and
      `gpu_s_left = 1800`, `cpu_core_s_left = 7200`.
- [ ] After a job is admitted and finishes, `reserved`, `spent` and `left` change so that the identity
      `cap = reserved + spent + left + delegated` holds at every read.
- [ ] `session.open` without a key returns `FROB-REF-805`, exit 3; an unknown scope or a misspelt flag returns
      `FROB-REF-802`, exit 3; the same key with different scopes returns `FROB-REF-803`, exit 7.
- [ ] `principal`: an unlisted principal returns `FROB-REF-723`, exit 5, and writes nothing; with two principals
      granted, a root call without `principal` returns `FROB-REF-802`, pointer `/principal`; with one granted,
      the same call is minted for it and the output's `principal` names it; `principal` with `derive: true`
      returns `FROB-REF-802`; a call without `scopes` holds no non-budget scope and the grant's budget amounts.
- [ ] The token is absent from the transcript, the NDJSON log and the job ledger.
- [ ] `session.show --all` without `session:read` returns `FROB-REF-720`; `session.show` without it, for the
      caller's own session, succeeds.
- [ ] Until M3, `derive: true` returns `FROB-REF-724` and writes nothing.
- [ ] `scripts/e2e/tether_session_verbs.sh` passes at M2 with the logging below.

`cpu:core_seconds=7200`, with namespace `agent-17`, unless a test installs another; root opens are made with no
token in the environment):
- `open_show_roundtrip`: the acceptance example; `scopes` is sorted, contains the six requested scopes,
  `design:read` and `sim:read`, and equals `Scopes::close_implied` of the six computed against the catalogue
  (so `mission:read`, `nemesis:read`, `autopsy:read` and `qual:read` are present exactly when the catalogue has
  them); budget values as above.
- `budget_identity_over_job_lifecycle`: reads at admitted, running, complete; identity holds; `spent` equals the
  job receipt's charge.
- `budget_scope_spelling`: `gpu_s=600` yields scope `gpu:seconds=600`.
- `open_requires_key`, `open_unknown_scope_is_802`, `open_key_reuse_different_content_is_803`.
- `open_principal_rules`: with `principal.agent-17` alone granted, `open` without `principal` returns `principal:
  "agent-17"`; adding `principal.agent-18`, the same call is `-802` with `pointer: /principal` and both
  identifiers in the repair; `--principal agent-99` is `-723` with the ledger digest unchanged; `--principal
  agent-17 --derive` is `-802`; `open --principal agent-17 --key s-9` without `--scopes` or `--budget` holds
  no non-budget scope and the grant's amounts (`gpu_s_left = 1800`, `cpu_core_s_left = 7200`), and its

- `show_needs_no_scope`: a session holding only `sim:run` reads itself; `--all` with that token is `-720`, and with

- `registry_rows_match`: the two entries above equal the rows of the cluster's registry bead field for field,

### Known answers and negative controls
- Known answer (the worked MCP session, with the grant above naming namespace `agent-17`): `session_show {}`
  returns principal and namespace `agent-17`, focus `orient`, the six
  requested scopes with their implied reads added and `{ "gpu_s_left": 1800, "cpu_core_s_left": 7200 }`.
  (The plan's illustrative transcript lists the six as requested; it predates the implied-read rule decided in
  BD-258, under which a stored scope set is always closed, and it is that closed set which every later check
  reads, so it is the set shown.)
- Negative control: a `session.show` that computes `left` locally as cap − spent (ignoring reservations) disagrees
  with the daemon during a running job; `budget_identity_over_job_lifecycle` must catch it.
- Negative control: a logger without redaction; the secrecy test must find the token.
- Parity: the CLI envelope and the MCP structured content for the same call are equal after removing the
  per-surface defaults the registry declares.

## Considerations

- Returning the token on replay is a convenience that depends on the token being a pure function of the session
  row and the key; if token format ever gains a nonce, replay must stop printing it.
- `session.show` is called often by agents; it reads the ledger only and must stay under the bounded synchronous
  wait by a wide margin (TARGET: under 50 ms on the reference host; recorded, not gated).
- The overhead line exists so that fair sharing is auditable: an agent can check that reserve it never used was
  not billed to it.
