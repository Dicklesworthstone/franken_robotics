## Background

FrankenRobotics is meant to be driven by many agents at once. Its surface, Tether, gives each agent a session with
a capability token (scopes for reading, spending and publishing, plus budgets), lets a holder derive narrower
tokens for sub-agents whose budgets are debited from the parent, gives each agent its own design namespace and
lineage, and offers a shared archive and leaderboard as read-only views. Each of those mechanisms has unit tests
in its own bead (N32b-01 to N32b-04). This bead is the end-to-end proof from the user's side: several real `frob`
and `frob-mcp` clients against one real `frobd`, doing what a careless or adversarial swarm would do, with the
ledger inspected after every step.

The property the seed work item for this area states is the heart of it: a session without the scope receives the
refusal and no partial data. "No partial data" is checked three ways here: the standard output holds exactly one
envelope with no `result`; no artifact, job, binding or reservation appears in the ledger; and no file appears
under any session root.

## Scope

In: `scripts/e2e/tether_capabilities.sh` with step groups `token-*`, `session-*`, `derive-*`, `ns-*`, `sealed-*`,
`kill-*` and `views-*`; the fixtures it needs; its log.
Out: the mechanisms (N32b-01 to -04); the path-jail corpus (seed BD-258); the full refusal battery (N32b-21).

## Technical approach

The script is plain shell, idempotent and seed-explicit. It creates a temporary state root, starts `frobd` on it
with the `batch-cpu` backend only, and tears it down at exit. It sources the shared end-to-end helper. Every step
runs through the CLI and, where marked, again through `frob-mcp` over loopback HTTP, comparing the two envelopes.

| Group | Steps (commands abbreviated) | Asserts |
|---|---|---|
| `session-*` | Agents A and B each `frob session open` with `design:read,design:write,sim:run` and `gpu_s=0,cpu_core_s=600`; `frob session show` | Exit 0; distinct namespaces; six budget fields consistent; token redacted in the transcript |
| `token-*` | A calls `design show` (admitted); A calls `train start` (no `train:run`); A repeats `design show` with one character of the token changed; C opens with `ttl_s=1`, waits 2 s, calls `design show` | Exit 0; exit 5 `FROB-REF-720` with `required: train:run`; exit 5 `FROB-REF-723`; exit 5 `FROB-REF-723`. Ledger digest unchanged across the three refusals; one envelope each; no `result` |
| `derive-*` | A derives A1 with `sim:run` and `cpu_core_s=200`; A derives with `scene:import` (not held); A derives with `cpu_core_s=500` (400 left); A1 runs a 64-world, 2 s `sim run --tier batch-cpu --key j1`; A shows; A1 is closed; A shows | Admitted, A left 400; `-723` twice with the widening element named; job completes; A's `children` row shows A1's spend; after close A's left = 600 − (A1's spend) |
| `ns-*` | A and B each `design new quad-a --template quadruped-12dof`; B runs `design edit agent-a/quad-a …`; B runs `design new mine --from <A's address>`; B runs `job list` | Both designs exist; exit 5 `FROB-REF-725`, A's head unchanged; fork succeeds and records provenance; A's job appears to B as a count by class only |
| `sealed-*` | A session with every grantable scope calls `telemetry query`, `run show`, `sim replay`, `artifact read` on a planted confirmation run | Each refused with `FROB-REF-840`; no world address, outcome or trace returned |
| `kill-*` | During A1's job, the `frob` client is killed with signal 9 at a seeded random instant, 20 trials; then `frob job find --key j1` | The job is found in every trial; the ledger passes its consistency check; exactly one job and one charge exist for the key |
| `views-*` | A and B each produce a scored result; `opt archive` and `eval scorecard` shared views are read by both | Identical view digests for A and B; entries from both namespaces present; private fixture entry absent |

Fixtures: the built-in quadruped template; a flat-terrain scene; a planted confirmation run created by a helper
that holds the owner scope (the helper's token never reaches the agent sessions); a private-marked synthetic scene
(labelled `synthetic`).

**Consistency check of the ledger** (used after every refusal and every kill): no job without a binding, no
binding without a reservation, the budget conservation law for every session tree, the commit frontier contiguous
for every (world, episode), and the sum of terminal counts equal to planned trials for finished jobs.

## Acceptance criteria

- [ ] The script exits 0 on a correct build and non-zero on each planted defect listed below.
- [ ] Every refusal step shows exactly one envelope, `ok: false`, no `result`, the expected code and exit, and an
      unchanged ledger digest.
- [ ] The derive group shows the parent's `left` falling at derivation and rising by the unspent remainder at
      close, to the unit.
- [ ] In 20 of 20 kills the job is recoverable by key with one job and one charge.
- [ ] CLI and MCP envelopes agree for every step after removing declared per-surface defaults.
- [ ] The log holds no token and no private-scene data.

## Test plan

### Unit tests
The mechanisms' unit tests are in N32b-01 to N32b-04. This bead adds only helper tests:
`crates/frob-conformance/tests/ledger_consistency.rs`: `consistency_check_detects_orphan_job`,
`consistency_check_detects_double_charge`, `consistency_check_detects_conservation_break` (each on a ledger copy
with one row altered by hand).

### End-to-end script and logging
`scripts/e2e/tether_capabilities.sh`. Log: `target/e2e-logs/tether_capabilities/<utc-timestamp>.ndjson` and a
transcript beside it. Every line has `ts`, `script`, `bead` (`N32b-05`, or the mechanism bead for its group),
`step`, `event` (`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact command line with secrets
redacted, exit code, wall time, the envelope's `evidence` block (claim, class, tier, determinism, identities,
seed), measured values with units and thresholds (budget triples; kill trials recovered against 20; view digests
equal), ledger digests before and after where state is compared, and on failure the first differing value and
the paths of the state root copy and both envelopes. The final `summary` line counts assertions passed and
failed and lists the invariants touched (INV-TETHER-05, INV-TETHER-10).

### Known answers and negative controls
- Known answers: budget arithmetic of the derive group (600 − 200 = 400; refusal at 500 > 400); the unscoped row
  of KA-755 (`FROB-REF-720`, exit 5).
- Planted defects the script must catch (each a test build behind the negative-control feature): (1) scope check
  after the handler: the refused `train start` leaves a job row; (2) derived budget not debited: the 500 request is
  admitted; (3) ownership checked on the unresolved name: B's edit of A's design succeeds; (4) a `job list` that
  returns other principals' job names; (5) a confirmation run readable through `artifact read`.
- Determinism lanes: the script twice on one machine gives equal ledger digests at each step apart from
  wall-clock fields; on both platforms; kill instants come from a logged seed.

## Considerations

- The kill group uses the client, not the daemon; daemon restarts under seeded faults belong to the job-protocol
  gate (GATE-TETHER-08).
- Timing: the `ttl_s=1` step uses a real 2 s sleep; everything else is time-independent, so the script stays under
  about two minutes on the reference host (TARGET).
- If the MCP HTTP transport is not yet available in a build, the MCP half is skipped with a logged `metric` line
  `mcp_half: skipped` and the summary says so; a skipped half never counts as a pass of the parity assertion.
