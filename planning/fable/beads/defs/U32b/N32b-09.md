## Background

GATE-TETHER-14 is the acceptance gate for the two things in FrankenRobotics a person looks at: the terminal
dashboard and the viewer. Its dashboard half reads: *a snapshot test per pane on a recorded daemon trace, and
every displayed number is reproduced by its source verb* (claim kind: Known answer; third milestone; TARGET
threshold). This bead measures that half. The viewer half is N32b-14. The seed work item BD-300 records the gate
together with the admission gate of the terminal library.

Why the gate is shaped this way. The dashboard is an ordinary client with no private interface (decision
ADR-TETHER-10). The risk of any dashboard is that it quietly becomes a second source of truth: a pane sums,
rounds or caches differently from the verb an agent would call, and a person and an agent then argue from
different numbers. "Reproduced by its source verb" removes that risk by test: for each numeric cell the harness
re-issues the verb the pane names and compares the value at the cell's source pointer. The snapshot test pins the
rendering so that a change in what a person sees is a reviewed change.

The same run supplies the two measurements on which the dashboard's kill gate is decided (KILL-TUI: FrankenTUI
cannot be admitted with one asupersync package, or the snapshot tests cannot be made stable), and checks the two
invariants the dashboard must not break: killing it leaves the ledger consistent (INV-TETHER-10), and turning it
on or off changes no physics digest (INV-TETHER-12).

## Scope

In: the recorded daemon trace fixture and how it is produced; seven snapshot tests (six panes and the gate view);
number reproduction; snapshot stability over repeated replays and across platforms; the kill and noninterference
checks for the dashboard; `scripts/e2e/tui_panes.sh`; the measurement record for GATE-TETHER-14 (dashboard half)
and for KILL-TUI.
Out: pane implementations (N32b-06 to -08); the viewer half (N32b-14); recording the gate and the admission gate
in the register (BD-300); the kill decision (N32b-31).

## Technical approach

**1. The scenario (seeded, `batch-cpu` only, so it runs on any host).** A temporary state root; `frobd` started
with an environment of B = 512 slots and a 5% reserve; two agent sessions with budgets; a scripted job set: one
anytime-valid paired study (cap 96 pairs), one fixed-n study of 30 pairs, three interactive `sim run` jobs, one
long batch job that is preempted once, one job cancelled by its owner, one job refused at admission, a planted
qualification campaign with four submissions, one planted autopsy record and one hard-world entry. Seeds and the
job script are files under `fixtures/tether/dashboard/`.

**2. Recording.** `frob-tui --record trace.ndjson` runs against the live daemon until the job set is finished.
The trace (`frob.tui-trace/1`) holds every external message: verb envelopes with their source keys and event
frames, in arrival order with sequence numbers. The daemon is then paused (no new jobs) and its state root copied:
this frozen state is what source verbs are re-issued against. The committed fixture trace
`fixtures/tether/dashboard/daemon_trace_01.ndjson` is one such recording, checked in, with the digest of the state
root it came from; it is regenerated only by this script's `--regenerate` mode, never by hand, and a regenerated
trace is a reviewed change.

**3. Snapshot per pane.** `frob-tui --replay trace --dump out/` renders Races, Budgets, Evidence, Devices, Queue,
Failures and the gate view at a fixed virtual size (160 × 50). Each `<pane>.txt` is compared byte for byte with
`fixtures/tether/dashboard/snapshots/<pane>.txt`.

**4. Number reproduction.** For every cell in `<pane>.cells.json` with a `src`: re-issue `frob <verb> <args>
--json` against the frozen state root (arguments recovered from the trace by `args_digest`), read the value at
`pointer`, and compare with the cell's `value` exactly (numbers as their JSON spelling, strings byte for byte).
For a derived cell, recompute it from its declared inputs. Mismatches allowed: 0.

**5. Stability.** The replay and dump are repeated 20 times on each platform (Linux and macOS); all dumps must
be byte-identical to one another and to the stored snapshots. "The snapshot tests cannot be made stable" (the
kill trigger) is defined here as: any differing frame in these 40 replays after one repair cycle.

**6. Admission measurements.** `cargo tree -d -p frob-tui` parsed for the number of distinct asupersync packages
(threshold: at most 1); processor time of `frob-tui` over a 60 s idle window on the live daemon divided by wall
time (threshold: at most 2% of one core).

**7. Invariants.** (a) INV-TETHER-10: `frob-tui` is killed with signal 9 at 20 seeded instants, including during
a poll and with the cancel confirmation open; after each kill the ledger consistency check passes and every
admitted job is found by `frob job find --key`. (b) INV-TETHER-12: the scripted job set is run twice from the same
seeds, once with the dashboard attached and polling and once without; every run's digest chain is equal
(`frob telemetry divergence` reports none).

## Acceptance criteria

- [ ] GATE-TETHER-14, dashboard half, has a measured record: 7 of 7 snapshots equal; cells compared N (reported),
      mismatched 0.
- [ ] 40 of 40 replays byte-identical across the two platforms; the count is recorded for KILL-TUI.
- [ ] asupersync package count at most 1; idle processor use at most 2% of one core over 60 s; both recorded.
- [ ] 20 of 20 kills leave the ledger consistent with every job recoverable by key.
- [ ] Digest chains with and without the dashboard are identical for every run of the job set.
- [ ] Each negative control below makes the script exit non-zero with the failing cell or frame named.
- [ ] The measurement file `target/gates/GATE-TETHER-14.dashboard.json` exists with values, thresholds, commit,
      host fingerprint and seed, written by the script and not by hand.

## Test plan

### Unit tests
`crates/frob-conformance/tests/tui_reproduction.rs`:
- `pointer_compare_exact`: `1800` and `1800.0` are different spellings and are reported as a mismatch (the pane
  must print the verb's own spelling).
- `derived_cell_recomputed`: the pair-count sum cell is recomputed from its five inputs.
- `args_recovered_from_trace`: every `args_digest` in the fixture resolves to arguments in the trace.
- `trace_fixture_digest_matches_state_root`.

### End-to-end script and logging
`scripts/e2e/tui_panes.sh`, step groups `core-*` (N32b-06), `evidence-*` (N32b-07), `machine-*` (N32b-08),
`repro-*`, `stability-*`, `admission-*`, `kill-*`, `noninterference-*` (this bead). BD-300's script calls it as
its dashboard part. Log: `target/e2e-logs/tui_panes/<utc-timestamp>.ndjson` with a transcript. Every line has
`ts`, `script`, `bead`, `step`, `event`, the exact command line, exit code, wall time, the `evidence` block of
each source envelope, measured values with units and thresholds (snapshots equal of 7; cells compared and
mismatched against 0; replays identical of 40; asupersync packages against 1; idle CPU percent against 2; kills
recovered of 20; digest pairs equal), digests of dumps and of the state root, and on failure the first differing
cell (pane, row, column, shown value, verb value, pointer) or the first differing frame line, with artifact
paths. The `summary` line lists GATE-TETHER-14 (dashboard half), INT-FTUI-01 and KILL-TUI as gates touched.

### Known answers and negative controls
- Known answers shown in the panes and checked by pointer: the α schedule (KA-760), pair accounting (KA-757),
  slot share (KA-761: at B = 512 the 96-pair study's 192 slots are 37.5%; the 8,192 figure is checked on a GPU
  host).
- Negative control 1: a pane that computes a number itself (planted: Budgets sums job charges locally) while the
  frozen daemon state holds a different `spent`: number reproduction must fail on that cell.
- Negative control 2: a stored snapshot with one character changed: the snapshot test must fail and name the line.
- Negative control 3: a build with the forbidden executor feature: the package count must be 2 and fail.
- Negative control 4: a pane that prints the local time in its header: stability must fail between replays.
- Negative control 5: a dashboard build that issues `sim.run` (a non-read verb): the request-log check fails.
- Determinism lanes: twice on one machine; debug and release; Linux and macOS.

## Considerations

- Regenerating the trace changes every snapshot at once; the script therefore prints a per-pane diff and the
  review rule is that a regenerated trace lands in its own change.
- Number reproduction depends on the frozen state root; if a verb's answer legitimately depends on wall-clock
  time (it should not), the comparison would flake. Any such field found here is a defect in the verb.
- This script gives the kill gate its numbers but does not decide it; a failing stability count after one repair
  cycle is reported to N32b-31.
- The viewer's half of the gate and the dashboard's half are recorded separately and the gate passes only with
  both.
