## Background

The viewer is how a person (or an agent that can see) watches a recorded episode: a web page that draws the
robot, the scene and physical overlays from telemetry. It belongs to Tether, the surface subsystem, lives under
`viewer/` and has no binary of its own. It is an ordinary Three.js page at the pinned release r186.

Three rules define it. (1) *The viewer never feeds anything back to physics.* The simulator owns state; the viewer
reads immutable snapshots. Turning it on or off changes no physics digest (invariant INV-TETHER-12). (2) *The
viewer is an ordinary client* (decision ADR-TETHER-10): every value it shows is obtainable by a named verb, so it
is not a private path to state, and an agent without eyes loses nothing because `telemetry.inspect-pixel` returns
the quantity under any pixel. (3) *Nothing is fetched from the network.* Three.js is vendored at a pinned version
with its hash; an exported replay is one self-contained file.

Design decision (DESIGN): the page separates *where snapshots come from* from *how they are drawn*. One interface,
`SnapshotSource`, has two shipped implementations: the embedded blocks of a replay packet (`PacketSource`, N32b-40,
M2) and read verbs called over the daemon's loopback MCP endpoint (`VerbSource`, live mode, N32bp1-01, M3: the
loopback HTTP transport with a bearer token that live mode needs is N32a-27, a third-milestone bead). Both build
the same immutable snapshot through one conversion, `snapshotFromEnvelopes`, defined here. Overlays (N32b-11,
N32b-12) are pure functions of a snapshot and never know which source produced it. Rejected: a viewer that links simulation code compiled to WebAssembly to
re-step or interpolate (it would be a second, unreviewed implementation of replay); a viewer fed by a private
daemon socket (an unaudited interface).

The page arrives at the second milestone with stills; overlays and the dashboard follow at the third.

## Technical approach

**Layout.** `viewer/src/` ES modules: `source.js` (interface and `VerbSource`), `snapshot.js`, `scene.js`,
`timeline.js`, `pick.js`, `legend.js`, `overlays/` (later beads), `test-entry.js`; `viewer/vendor/three-r186/`
with `three.module.min.js` and `vendor.lock` (release tag, byte length, SHA-256 and BLAKE3 of the file);
`viewer/build/` (Node scripts, development-only tooling, never a Cargo dependency); `viewer/tests/`.

**Snapshot model (immutable).**

| Part | Content |
|---|---|
| `header` | Run, world address, episode; model, scene, task and policy identities; tier, determinism class and claim class of the run; tick range; frame period as a rational; the channel table (name, kind, unit, frame, quantization) |
| `shapes` | Per body: collision primitives (box, sphere, capsule, cylinder, with dimensions in metres) and, where the source has it, a handle to the visual mesh; scene shapes likewise |
| `frames` | Per tick stored: one affine row per body, a 3 × 4 matrix in `f32` (48 bytes, little-endian, row-major: rotation and scale in the left 3 × 3, translation in the last column), in the anchored convention; plus the per-body cell index when the scene spans more than one cell |
| `columns` | Overlay channels as quantized integer or `f32` columns in the layout of the run file format |

Objects are frozen after construction (`Object.freeze` on containers, typed arrays never written); no module
holds a reference to a verb of kind other than `read`.

**`SnapshotSource`.** `header()`, `shapes()`, `frame(tick)`, `column(name, tickRange)`, `nearestStoredTick(tick)`.

**`snapshotFromEnvelopes` (in `snapshot.js`).** A pure function from the envelopes of `run.show` (header,
identities, tier, classes, tick range, frame period, channel table, named ticks), `telemetry.query` (pose and
overlay columns, paged against one committed frontier: it follows cursors and never asks beyond the frontier it
was given) and `artifact.read` (shapes and visual-mesh handles, by digest and byte range) to a frozen snapshot.
It refuses, naming the field, an envelope whose schema name or channel table it does not know. Live mode
(N32bp1-01) calls it on envelopes fetched over the loopback endpoint; the fixture tool below calls it on
envelopes fetched through the CLI, so the page's tests exercise the same conversion on real data.

**Recorded fixtures for the page's own tests.** `viewer/build/record-snapshot.mjs <run> --out
viewer/tests/fixtures/<name>/` issues `frob run show`, `frob telemetry query` and `frob artifact read` with
`--json` (read verbs only, under a session holding their clusters' read scopes), stores the raw envelopes with
their digests and a header naming the fixture kind `recorded`, the run identifier and the commit frontier, and
nothing else. A test-only `FixtureSource` (`viewer/tests/fixture-source.js`, never part of the bundle) passes
those envelopes through `snapshotFromEnvelopes`. Hand-built snapshots are labelled `synthetic`. This is how the
page is tested at the second milestone, before `PacketSource` (N32b-40, which depends on this bead) and live mode
(M3) exist.

**Poses.** A recorded position is cell index c (signed 32-bit integers per axis; cells of side 8 m) plus an `f32`
offset o from the cell centre in [−4, 4) m. The page draws relative to the camera's anchored position
(c_cam, o_cam): p_rel = 8·(c − c_cam) + (o − o_cam), with the integer difference formed first (exactly, in integer
arithmetic) and the offset difference second, so single-precision vertex arithmetic on the graphics card never
sees a large absolute coordinate. A source may give one cell for all bodies of a timeline with offsets outside
[−4, 4) (the replay packet's single anchor cell per timeline, N24a-41); the formula is unchanged. The matrix is
used as stored; the page applies no smoothing and no interpolation between ticks: frame(t) is the row of the
nearest stored tick at or before t, and the legend states the drawn tick.

**Timeline.** Playback maps presentation time to ticks with the rational frame period; pause, step by one stored
frame, jump to named ticks (first contact, first anomaly, failure) taken from the header's event list. The
presentation clock only selects which stored frame is shown; it changes no value.

**Picking.** A ray from a pixel through the camera to the first surface, returning `{kind: body | fixture | region
| contact | overlay-element, id, world_address, tick}`. When the ray is taken into an instance's local frame by
A⁻¹ and its direction is renormalized, a local hit parameter s_L is converted to a world distance by
s_W = s_L / ‖A⁻¹·d‖, with d the unit world direction; nearest-hit ordering uses s_W. (Without the conversion, hits
on scaled instances are ordered in local units and a farther object can win.)

**Headless test entry.** `window.__frobViewerTest`: `load(source)` (any `SnapshotSource`; live mode adds
`attach` and `detach` here), `setTick(n)`, `setCamera(pose)`,
`cameraPath(name, i)` (deterministic presets: `orbit-12` gives 12 poses on a circle of fixed radius and
elevation around the scene centre; `top`, `side`), `pick(x, y)`, `renderPixels()` (RGBA of the canvas),
`state()` (the drawn tick, channel list, legend values). Tests drive the page through this object only.

**Security.** A content security policy in the page: `default-src 'none'`; inline script and style allowed (the
bundle is one file); images from `data:` and `blob:`; `connect-src 'none'` in the page this bead ships (live
mode, N32bp1-01, is the only variant that may name one loopback origin). Text that originated in an import (a
link name, an asset's metadata) is inserted as text nodes, never as markup.

## Acceptance criteria

- [ ] `viewer/vendor/vendor.lock` matches the vendored file; a changed byte fails the build.
- [ ] The page loads a snapshot of the reference quadruped on a plane and draws 13 bodies at the stored poses;
      `state().tick` equals the requested stored tick.
- [ ] No mutation of a snapshot is possible from page code (a planted write throws in strict mode).
- [ ] With the network disabled the page loads a recorded fixture through the test entry and plays 100 frames;
      the driver's request log is empty, in both pinned browsers of N32b-44.
- [ ] `pick` at the projected centroid of each body returns that body; on a uniformly scaled instance the nearest
      hit is correct (the conversion test below).
- [ ] `snapshotFromEnvelopes` turns the recorded envelopes of the reference run into a snapshot whose frame rows
      equal the poses `telemetry.query` returns, body for body and tick for tick, after the anchored conversion.
- [ ] `scripts/e2e/viewer_page.sh` passes with the logging below.
- [ ] `viewer/README.md` documents the test entry and states that the viewer computes no physics.

## Test plan

### Unit tests
`viewer/tests/` (run under a pinned headless browser by `viewer/build/test.mjs`; fixtures are real exported
snapshots, labelled `synthetic` where hand-built):
- `vendor_hash_matches_lock`.
- `frame_row_decoding`: a body at translation (1.5, −2.25, 0.75) with a 90° rotation about z decodes from its 48
  bytes to that pose exactly.
- `anchored_relative_pose`: body at cell (125, 0, 0) offset 3.5 and camera at cell (125, 0, 0) offset −3.0 are
  6.5 m apart; with the camera at cell (124, 0, 0) offset 3.0 the distance is 8·1 + 3.5 − 3.0 = 8.5 m, exact.
- `no_interpolation`: at a time between two stored ticks the drawn pose equals the earlier tick's, bit for bit.
- `snapshot_is_frozen`.
- `pick_centroids_quadruped`: 13 of 13.
- `pick_scaled_instance`: two spheres along one ray, the nearer inside an instance scaled by 2 (A = 2·I, so
  ‖A⁻¹·d‖ = 0.5): local hit s_L = 1 is world distance 2; a farther unscaled sphere at s = 2.5 must lose; in the
  reversed arrangement (the scaled hit at s_L = 1.5, world 3.0, behind an unscaled hit at 2.5) the unscaled one
  must win.
- `camera_path_deterministic`: `orbit-12` poses equal the stored table.
- `fixture_recorder_reads_only`: the commands `record-snapshot.mjs` issues are a subset of {`run show`,
  `telemetry query`, `artifact read`}, each `read` in the registry.
- `envelopes_to_snapshot`: on the recorded reference run, every frame row equals the pose from the
  `telemetry.query` envelope; an envelope with an unknown schema name or channel is refused naming the field.
- `frontier_respected`: the conversion follows cursors of one frontier and never mixes rows of a later one.
- `csp_blocks_external`: an injected `fetch` to a public origin is blocked.

### End-to-end script and logging
`scripts/e2e/viewer_page.sh` (header `bead=N32b-10 milestone=M2 labels=tether,chronicle`; owned here, rerun as
steps `page-*` by N32b-14's `viewer_overlays.sh`): on a temporary state root, `frob sim run` of the reference
quadruped on a plane (`--tier batch-cpu --seed 7 --key vp-1 --json`); `node viewer/build/record-snapshot.mjs` on
that run; `node viewer/build/test.mjs` (N32b-44's launcher, networking off, software rasterizer) in both pinned
browsers: load the fixture, play 100 frames, compare each drawn pose with the `telemetry.query` envelope, pick at
the 13 projected centroids and at the two scaled-instance arrangements. It sources the STD-E2E helper and writes
`target/e2e-logs/viewer_page/<utc>.ndjson` and a transcript; each line has `ts`, `script`, `bead`, `step`,
`event`, the exact command line, exit code, wall time, the run envelope's `evidence` block, the browser name,
version and hash, bodies drawn against 13, poses equal against 1,300, picks correct against 13, external requests
against 0, the vendored-file and fixture digests, and on failure the first differing tick, body or pick with the
paths of the fixture and the pixel dump; then a `summary`.

### Known answers and negative controls
- Known value (a unit-test constant, not a registry row): the scaled-instance conversion above (distance 2,
  not 1). Presentation noninterference of a live viewer is asserted by N32bp1-01 and N32b-14; a viewer that only
  reads recorded data after the run cannot perturb it.
- Negative control: a page build that linearly interpolates poses between ticks; `no_interpolation` must fail.
- Negative control: a pick that orders hits by local parameter; `pick_scaled_instance` must fail (it would report
  the nearer hit at 1 correctly here, so the fixture also includes the reversed arrangement in which the scaled
  instance is the farther object and local ordering picks it wrongly).
- Negative control: a vendored file with one changed byte.
- Determinism lanes: page tests twice on one machine and on both platforms with a software rasterizer.

## Considerations

- A native viewport on the Mac is a possible later addition (Frontier); no work is funded for it and nothing here
  assumes it.
- Privacy: a snapshot of a private scene is private; reading it needs the private read scope and a packet needs
  the export scope and flag. The viewer adds no path around those checks because its data come only from verbs.
  A recorded fixture of a private scene is never committed: fixtures are of synthetic scenes.
- Large scenes: geometry of a scan-derived scene can be large; live mode fetches meshes by byte range and shows
  collision primitives until the visual mesh arrives.
- What would make us revisit: a need to scrub at sub-frame resolution. The answer is to record more frames, not
  to interpolate in the page.
