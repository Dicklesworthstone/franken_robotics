## Background

The viewer (page in N32b-10: a Three.js r186 page that draws immutable telemetry snapshots) is useful to an
engineer because of its overlays: drawings of physical quantities on top of the robot and the scene. The rule for
every overlay is strict. It draws a physical quantity from a *named telemetry channel*, with its *unit*, a
*numeric legend* and the *evidence class of the run*; and it is a *pure function of the snapshot*. An overlay
never estimates, smooths or infers. If a quantity was not recorded, the overlay draws nothing and says so.

Reasons. A picture of a robot invites trust that colours do not earn; binding each drawn element to a stored
value with a unit makes the picture checkable, and the acceptance gate checks it: the overlay value under a probe
pixel must equal the telemetry channel within the channel's quantization (GATE-TETHER-14, viewer half, measured
in N32b-14). Purity makes the overlay the same function of the same stored values in the live viewer and in the
self-contained replay (one page, two snapshot sources). Stills (`telemetry.stills --overlay contact-cones,film`,
seed BD-191) draw the same overlays by id with their own renderer in Rust, from the same channels; an agent that
cannot see reads the same quantity through `telemetry.inspect-pixel`, which returns the quantity under a pixel
with its unit, channel and world address. The page and the still share ids, channels, units and legend ranges, not
code, and N32b-14 checks that they agree pixel by pixel.

This bead defines the overlay interface and builds five of the ten overlays: those whose channels exist from the
batched tiers of the second milestone. The other five are N32b-12.

## Scope

In: the `Overlay` interface, the legend, the probe record, the registration table; overlays `contact-cones`,
`energy`, `actuator`, `balance`, `sensing`; behaviour when a channel is absent; the overlay value buffer used by
the probe.
Out: the page (N32b-10); overlays `film`, `clearance`, `ghost`, `world-diff`, `reality-band` and the two map
layers (N32b-12); the stills verb and its own overlay drawing in Rust (seed BD-191), with which this bead shares
ids, channels, units and ranges through the lint below; live mode (N32bp1-01); the gate measurement (N32b-14).

## Technical approach

**Interface (DESIGN; `viewer/src/overlays/overlay.js`).**

```js
// An overlay is a record of pure functions. No function reads a clock, the network or mutable module state.
{ id: "contact-cones",
  requires: [ {channel: "contact.fn", kind: "scalar", unit: "N"}, ... ],
  elements(snapshot, tick)  -> [Element],      // geometry + the stored values each element shows
  legend(snapshot)          -> {channel, unit, min, max, scale, evidence_class, tier, determinism},
  probe(element, hit)       -> {channel, unit, value_q, value, quantization, world_address, tick, element_id} }
```

An `Element` carries: a primitive (arrow, cone, bar, polygon, polyline, point, frustum), its placement in the
body or world frame, a colour index into the legend's scale, and `values`: for each quantity it shows, the stored
quantized integer `value_q` exactly as in the column, the channel name and the telemetry address (world,
episode, tick, element index). `value = value_q × quantization` is computed for display; the probe returns both.
The page renders, beside the colour image, an *overlay value buffer*: per pixel, the identifier of the element
drawn there. `pick` resolves a pixel to an element and `probe` returns its stored values. Same snapshot and tick
give byte-identical element lists.

**Legend.** Always visible when an overlay is on: channel name, unit, the numeric minimum and maximum mapped to
the colour scale, the scale's name (fixed perceptually uniform scales; one diverging scale for signed
quantities), and the run's evidence class, tier and determinism class from the snapshot header. Scale limits are
taken from the channel's declared range in the channel table, or from a fixed physical range (utilization: 0 to
1), never from the visible frame, so colours mean the same thing at every tick.

**Absent channel.** `requires` is checked against the snapshot's channel table. If anything is missing the
overlay's `elements` is the empty list and the legend reads "channel <name> not recorded for this world". No
fallback computation exists.

**The five overlays.**

| Overlay id | Quantity drawn | Elements and encoding | Channels (unit) |
|---|---|---|---|
| `contact-cones` | The four-dimensional cone at each contact (normal, two tangential, spin) with friction utilization as colour; the contact wrench as an arrow | At each contact point: a cone of half-angle atan(μ) about the contact normal, coloured by utilization u = ‖f_t‖ / (μ·f_n) on the scale 0 to 1 (u at 1 is drawn in the saturation colour); a force arrow along the stored force with length proportional to newtons (scale bar in the legend); a twist glyph about the normal for the spin moment, coloured by its own utilization as recorded | `contact.fn` (N), `contact.ft1`, `contact.ft2` (N), `contact.spin` (N·m), `contact.mu`, `contact.util`, `contact.spin_util` (1), `contact.point`, `contact.normal` |
| `energy` | Power per actuator, losses by kind, dissipation at contacts; the numerical residual as its own bar | A bar group anchored at each actuator: mechanical output power, and one segment per loss kind (winding, driver, friction in the transmission); a disc at each contact sized by dissipated power; one screen-fixed bar for the numerical residual of the energy ledger at this tick, drawn even when small, in its own colour | `energy.p_mech`, `energy.loss.<kind>`, `energy.contact_diss`, `energy.residual` (W) |
| `actuator` | Torque and speed utilization against the card; winding temperature | Per joint: two arcs, torque ÷ available torque at the present speed and speed ÷ no-load speed, each 0 to 1; a temperature swatch on the motor body | `act.tau` (N·m), `act.tau_avail` (N·m), `act.omega`, `act.omega_max` (rad/s), `act.temp_winding` (K) |
| `balance` | Centre of mass, support polygon, margin to tipping | A point at the centre of mass and its ground projection; the support polygon as a ground outline; a line from the projection to the nearest polygon edge labelled with the margin (negative outside) | `bal.com` (m), `bal.support` (m, vertex list), `bal.margin` (m) |
| `sensing` | Frusta and rays with occlusion; the seven instants of a sample on a timeline | Each sensor's frustum; individual rays to their hit points, coloured by mask reason (valid, out of range, occluded, glass, mirror, dropout); a timeline strip per selected sample with seven marks: sample, exposure, timestamp, arrival, decision, command, actuation, each at its recorded instant, with the sample's age (decision − sample) written out | `sense.ray.hit`, `sense.ray.mask`, `sense.frustum`, `sense.t_sample`, `t_exposure`, `t_stamp`, `t_arrival`, `cmd.t_decision`, `t_command`, `t_actuation` (quanta, as decimal strings) |

Checks the sensing strip displays, because the recorded contract promises them: sample ≤ exposure ≤ arrival;
decision ≤ command ≤ actuation; a packet shown as used by a decision has arrival ≤ decision. The timestamp mark
is unconstrained (it is what the device believes). A violation is drawn in the alarm colour; the overlay does not
hide or reorder marks.

**Registration.** `viewer/src/overlays/index.js` exports the table of overlays by id. The ids are the ones the
stills verb accepts: `contact-cones`, `energy`, `actuator`, `balance`, `sensing` (and N32b-12's `film`,
`clearance`, `ghost`, `world-diff` and `reality-band`, which the stills verb accepts from M3, N24ap2-60). A lint checks that ids, channel names and units equal the registry of telemetry channels, and that each
id's channels, units and legend range equal those of the same id in the stills verb's overlay table (BD-191), so a
pixel of the page and a pixel of a still mean the same quantity.

## Acceptance criteria

- [ ] Each of the five overlays renders on its fixture, and its legend shows channel, unit, numeric range, scale
      name and the run's evidence class.
- [ ] `elements(snapshot, tick)` called twice returns byte-identical serializations; no overlay module imports a
      clock, random or network API (static check).
- [ ] With a required channel removed from a snapshot, the overlay draws nothing and the legend names the missing
      channel.
- [ ] `probe` on any drawn element returns the stored `value_q`, its quantization, unit, channel, world address
      and tick.
- [ ] Overlay ids, channel names and units match the telemetry channel registry and the stills verb's overlay
      table (lint).
- [ ] The residual bar of `energy` is present whenever the channel is, including at zero.

## Test plan

### Unit tests
`viewer/tests/overlays_a.test.mjs` (pinned headless browser of N32b-44; recorded fixtures of real runs of
analytic scenes made with N32b-10's `record-snapshot.mjs`, labelled `recorded`, plus hand-built ones labelled
`synthetic`):
- `overlay_purity`: for each overlay, two calls, equal bytes; a third after unrelated page activity, equal bytes.
- `overlay_missing_channel_draws_nothing`: five cases.
- `cones_box_at_rest`: a 2 kg box on a plane with μ = 0.8: one cone per contact point with half-angle
  atan(0.8) = 38.66°; the sum of normal-force values over the contact elements is 19.62 N within quantization;
  utilization 0.
- `cones_box_on_incline`: the same box on a 20° incline, at rest: Σ f_n = 19.62·cos 20° = 18.44 N,
  Σ‖f_t‖ = 19.62·sin 20° = 6.71 N, utilization tan 20° / 0.8 = 0.455.
- `energy_blocked_winding`: a blocked winding at 3 A through 1 Ω: the winding-loss segment shows 9 W, mechanical
  power 0 W, residual bar present.
- `actuator_arcs`: τ = 1.2 N·m of 2.4 N·m available shows 0.5; speed 2.5 of 5.0 rad/s shows 0.5.
- `balance_margin_sign`: projection 0.03 m inside the nearest edge shows +0.030 m; 0.01 m outside shows −0.010 m.
- `sensing_seven_marks_ordered`: a packet with instants (in quanta) 100, 104, 103, 130, 140, 141, 150 draws seven
  marks; age reads 40; no alarm. With arrival 145 and decision 140 the "used before arrival" alarm is drawn.
- `legend_scale_fixed_across_ticks`: utilization scale is 0 to 1 at every tick.
- `probe_returns_stored_integer`: a contact with stored utilization integer 3,400 at quantization 1/4,096 probes
  as value_q = 3,400 and value = 0.830078125.

### End-to-end script and logging
Steps `overlay-a-*` of `scripts/e2e/viewer_overlays.sh` (N32b-14): run the box-at-rest and box-on-incline scenes
and a blocked-rotor actuator rig through `frob sim run`, load each run in the headless page through the live
source (N32bp1-01; under its fail-closed default, as a replay packet) with the five overlays, probe fixed pixels, and compare with `frob telemetry query` and `frob telemetry inspect-pixel`.
Lines log the command, exit code, wall time, the run's `evidence` block, per probe the channel, unit, page value,
verb value and quantization (threshold: equal within one quantum), and the first mismatch.

### Known answers and negative controls
- Known answers: 2 × 9.81 = 19.62 N; 18.44 N and 6.71 N on the incline; utilization 0.455; 9 W in a 1 Ω winding
  at 3 A.
- Negative control: an overlay that rescales its colour range to the visible frame; the fixed-scale test fails.
- Negative control: an overlay reading the wrong channel (tangential for normal); the box-at-rest probe fails.
- Negative control: a `contact-cones` that recomputes utilization from the force arrows it drew (rounded
  geometry) instead of the stored channel; the stored-integer probe fails.
- Metamorphic relation: mirroring the scene mirrors element placements and leaves every probed value unchanged.

## Considerations

- Colour is never the measurement. Anything quantitative is read through the probe or the verbs; the legend says
  so.
- Dense contact sets (hundreds of contacts) clutter; the overlay may thin by drawing the k largest normal forces,
  but then states "k of n shown" in the legend, and the probe still reaches every element through the list view.
- The spin utilization definition belongs to the contact law; this overlay displays the recorded channel and
  must not define its own.
- Units: temperatures are stored in kelvin and may be displayed in degrees Celsius only with the unit shown.
