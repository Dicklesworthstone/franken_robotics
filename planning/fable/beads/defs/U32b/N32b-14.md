## Background

GATE-TETHER-14 is the acceptance gate for what a person looks at in FrankenRobotics. Its viewer half reads: *on
analytic scenes the overlay value under a probe pixel equals the telemetry channel within its quantization*
(claim kind: Known answer; third milestone; TARGET). This bead measures that half; the dashboard half is N32b-09;
the seed work item BD-300 records the gate.

The viewer draws overlays of physical quantities (contact cones, film, clearance, energy flow, actuator state,
balance, sensing, counterfactual ghosts, world differences, reality bands) on recorded episodes. Every overlay
is required to be a pure function of the telemetry snapshot, drawing a named channel with its unit. The gate
turns that requirement into a measurement with three independent readings of one quantity:

1. the value the page's probe returns for the overlay element under a pixel;
2. the value `telemetry.inspect-pixel` returns for the same pixel of a still drawn with the same overlay;
3. the value `telemetry.query` returns for that channel, world, tick and element.

On an *analytic scene* there is a fourth reading: the closed-form truth (a box's weight, an incline's friction
demand). The gate's sentence concerns readings 1 and 3; the script checks all four, because a viewer that agrees
with telemetry while telemetry is wrong would otherwise pass unnoticed here, and a still that disagrees with the
page would break the promise that an agent without eyes reads every overlay.

A *quantum* is the channel's quantization step from the channel table (for a channel stored as a 12-bit fraction,
1/4,096). "Within its quantization" means the stored integers are equal; displayed decimals may differ by at
most one quantum only where a unit conversion for display intervenes.

## Scope

In: the analytic scene set; the probe plan (pixels, expected elements); the four-way comparison; the viewer's
noninterference check; `scripts/e2e/viewer_overlays.sh`; the measurement record for the viewer half of
GATE-TETHER-14.
Out: the overlays (N32b-11, N32b-12); the page, packaging and live mode (N32b-10, N32b-13, N32bp1-01), whose own
scripts this script reruns; the stills side of the overlays this script probes: `contact-cones`, `energy`,
`actuator`, `balance` and `sensing` on stills are BD-191's, and `film`, `clearance` and `ghost` on stills (with
the `--fork` option the null-fork row uses) are N24ap2-60's, both dependencies; packets (N32b-40, N32b-43);
recording the gate (BD-300).

## Technical approach

**Analytic scenes** (fixtures under `fixtures/tether/viewer/`; each a small design, a scene and a seed, run with
`frob sim run --tier batch-cpu` and on the referee):

| Scene | Overlay | Probe points | Closed form |
|---|---|---|---|
| A 2 kg box at rest on a level plane, μ = 0.8 | `contact-cones` | Each contact element | Σ f_n = 2 × 9.81 = 19.62 N; utilization 0 |
| The same box on a 20° incline, at rest | `contact-cones` | Each contact element | Σ f_n = 18.44 N; Σ‖f_t‖ = 6.71 N; utilization tan 20° ÷ 0.8 = 0.455 |
| A body resting on a film patch (thickness 0.2 mm, effective friction 0.25) beside dry floor (0.8) | `film` | Three pixels inside the patch, three outside | 0.0002 m and 0.25 inside; no film outside |
| A blocked rotor at 3 A through 1 Ω | `energy`, `actuator` | The winding-loss bar; the torque arc | 9 W; torque 0.2 N·m/A × 3 A = 0.6 N·m against its available value |
| A box whose centre of mass projects 0.030 m inside the nearest support edge | `balance` | The margin label | +0.030 m |
| A depth sensor facing a wall at 2.000 m, one packet with instants 100, 104, 103, 130, 140, 141, 150 quanta | `sensing` | Three rays; the seven timeline marks | Range 2.000 m; age 40 quanta |
| A doorway 0.76 m wide and an envelope 0.774 m wide | `clearance` | The bottleneck label | Margin −0.014 m |
| A run with a null fork | `ghost` | Ten body-frame pairs | Deviation exactly 0 |

At least 100 probe points in total across the scenes (TARGET count; the plan file lists each: scene, tick,
camera preset, pixel, expected element kind).

**Procedure per probe point.**

1. `frob telemetry stills <run> --world <w> --at tick=<t> --views <preset> --overlay <id> --single --json`
   (the frame selector and options of the stills verb, BD-191), then `frob telemetry inspect-pixel <still_id>
   --pixel <x>,<y> --overlay <id> --json` (N24a-40): record channel, unit, `value_q`, quantization, world
   address, tick, and the camera pose and intrinsics the still's tile reports.
2. Load the run in the headless page through the live source (N32bp1-01; under its fail-closed default, a replay
   packet of the run written by `frob telemetry export-html` with the probed overlays' channels and read by
   N32b-40; the log names the source used), set the tick, set the camera with `setCamera` to the pose and
   intrinsics the still reported, enable the overlay, and call the test entry's `pick(x, y)` then `probe`: record
   the same fields.
3. `frob telemetry query <run> --world <w> --stream <s> --channels <c> --from <t> --to <t> --json`: the world,
   the channel's stream, the channel and the one-tick range [t, t], in the spellings the query verb's bead fixes
   (N24a-36: one tick is `--from t --to t`; `--ticks`, `--channel` and `--page-size` are `FROB-REF-802`; a page
   size, where one is needed, is `--limit`). The drill-down handle that `inspect-pixel` returned in step 1 is
   the same query and may be issued verbatim. Record the stored integer.
4. Assert: page `value_q` = query integer; still `value_q` = query integer; channel, unit, world address and tick
   equal in all three; the dequantized value is within the stated tolerance of the closed form (one quantum plus
   the solver's contact tolerance for forces; exact for the null fork and the timeline marks).

The page takes its camera from the still's own report (pose and intrinsics per tile), so a pixel means the same
ray in both by construction, whatever the preset names of the two renderers (`orbit-12`, `top`, `side` in the
page; `orbit`, `top`, `side`, `follow`, `sensor:<name>` in the stills verb); where the two renderers rasterize an element edge differently by a pixel,
probe points are chosen at element interiors (the plan file stores, per point, a 3 × 3 neighbourhood that must
lie inside the element in both).

**Noninterference (INV-TETHER-12).** Each scene is run twice from the same seed: once with nothing attached, once
with the viewer attached in live mode and polling every 100 ms and a still requested every 100 steps (under live
mode's fail-closed default, the test driver issues the same read verbs at the same rate and the log says
`live_mode: not shipped`). The attached viewer and the driver work under one session, opened with the scopes
N32bp1-01's script names after this script has written a `principal.<id>` table granting them to the state
root's `safety.toml` (a root token is minted only from a grant, N32b-01). The digest chains must be equal (`frob telemetry divergence` reports none), on every
tier the scene runs on. The two runs of a pair carry different idempotency keys (`vo-<scene>-<tier>-bare` and
`vo-<scene>-<tier>-viewed`): with one key the second call would return the first run's stored receipt and the
comparison would compare a run with itself. Every other run verb of the script (`sim.run`, `run.fork`,
`nemesis.shrink`) likewise carries its own key.

**Measurement record.** `target/gates/GATE-TETHER-14.viewer.json`: probe points, mismatches (threshold 0),
largest closed-form deviation in quanta, digest pairs compared and equal, commit, host fingerprint, seed.

## Acceptance criteria

- [ ] At least 100 probe points; for every one the page's stored value equals the telemetry channel's (0
      mismatches), with equal channel, unit, world address and tick.
- [ ] For every probe point, `telemetry.inspect-pixel` on the still agrees with the page.
- [ ] Each closed form is met within its stated tolerance; the null-fork deviation is exactly 0.
- [ ] Digest chains with and without the viewer are equal for every scene and tier.
- [ ] Each negative control below makes the script exit non-zero and names the failing probe.
- [ ] The viewer half of GATE-TETHER-14 has a measured record written by the script; together with the dashboard
      half it lets BD-300 record the gate.

## Test plan

### Unit tests
`crates/frob-conformance/tests/viewer_probe_plan.rs`:
- `probe_plan_well_formed`: every point names an existing scene, overlay, preset and tick; at least 100 points;
  every overlay of the table appears.
- `closed_forms_recomputed`: the expected values in the plan file are recomputed from scene parameters
  (19.62, 18.44, 6.71, 0.455, 9, 0.6, 0.030, 40, −0.014, 0), not hand-entered.
- `neighbourhood_inside_element`: the 3 × 3 rule holds for each point in both renderers' identifier buffers.
- `compare_requires_integer_equality`: equal decimals from unequal stored integers are a mismatch.

### End-to-end script and logging
`scripts/e2e/viewer_overlays.sh`, step groups `page-*` (reruns N32b-10's `viewer_page.sh`), `pack-*` (reruns
N32b-13's `viewer_pack.sh`), `live-*` (reruns N32bp1-01's `viewer_live.sh`), `overlay-a-*` (N32b-11),
`overlay-b-*` (N32b-12), `probe-*` and `noninterference-*` (this bead); a rerun script's `summary` line is folded
into this log under its own bead key. BD-300's script calls it as its viewer
part. Log: `target/e2e-logs/viewer_overlays/<utc-timestamp>.ndjson` and a transcript. Every line has `ts`,
`script`, `bead`, `step`, `event`, the exact command line, exit code, wall time, the run's `evidence` block
(claim, class, tier, determinism, identities, seed), and for each probe a `metric` line: scene, overlay, pixel,
channel, unit, quantization, the three stored integers, the closed-form value and the deviation in quanta against
its threshold. Digests are logged where state is compared (the two digest chains; the still's identifier). On
failure: the first differing value and the paths of the exported view, the still and the page's pixel dump. The
`summary` line counts assertions and names GATE-TETHER-14 (viewer half). No private-scene data appears: all
fixtures are synthetic.

### Known answers and negative controls
- Known answers: the closed forms in the scene table; presentation noninterference (turning the viewer, stills or
  the telemetry level on or off leaves every physics digest and delivered observation unchanged).
- Negative control 1: an overlay reading the wrong channel (tangential force drawn as normal): the box-at-rest
  probe must fail.
- Negative control 2: an overlay that displays a recomputed value (utilization from drawn arrow lengths): integer
  equality must fail.
- Negative control 3: a page that ignores the still's reported camera and uses its own preset rotated by 1° of
  yaw: probes land on different elements and the agreement check must fail.
- Negative control 4: a still renderer that advances a keyed noise counter when drawing: noninterference fails.
- Determinism lanes: the script twice on one machine; debug and release; both platforms with the software
  rasterizer; referee and `batch-cpu` tiers, each against its determinism class.

## Considerations

- The gate checks stored-value fidelity, not picture quality. A handsome overlay with a wrong legend fails; an
  ugly one with right values passes. That is the intended priority.
- Rasterization differs across graphics stacks; the test uses a software rasterizer and interior probe points to
  stay machine-independent. The packet gate's two-browser run (N32b-43) uses the same software path through the
  pinned lane of N32b-44; hardware rendering is exercised by no gate.
- The film, clearance and ghost rows need third-milestone mechanisms of other subsystems; if one is late, its
  rows are reported `not run` with the reason and the gate record stays incomplete, never green.
