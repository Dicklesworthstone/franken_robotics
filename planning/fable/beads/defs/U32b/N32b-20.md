## Background

Two of the four operator verbs of FrankenRobotics answer the practical questions "what exactly do I send?" and
"is this installation healthy?".

`frob schema <kind>` returns a schema and a minimal valid example. Every verb's input and output, the envelope,
the refusal block, each file format and each wire record has a schema identifier of the form `frob.<name>/<n>`;
an agent composing a call should never have to guess a field name, because a misspelt parameter is a refusal,
not a default.

`frob doctor` checks toolchains, foundation pins, devices, kernel caches and probe status. FrankenRobotics is
built on about a dozen sibling libraries pinned by commit on one Rust toolchain, drives two kinds of GPU through
kernels it compiles at run time, and trusts a GPU for a given arithmetic only after probing it. Each of those is
a place where an installation can be subtly wrong. `doctor` is the single read-only command that says so, with
repairs, before an agent spends a budget on a broken host.

Both verbs exist in a first form from the first milestone (seed BD-022). This bead is their complete form, due
when devices, kernel caches and the full schema set exist (second milestone). Both are kind `read`, need no
capability scope, sit in the task cluster `orient`, and are generated onto the CLI and the MCP surface from the
verb registry like every other verb.

## Scope

In: `schema`: the schema catalogue, minimal examples and their validation, listing, the resource form; `doctor`:
the check list, findings with severities and repairs, exit codes, the resource-free read-only rule; tests.
Out: the registry build script that generates schemas (N32a-02); `capabilities` (N32b-19); device probing and
cache mechanics themselves (the Spark beads); the path jail and supply-chain gates (the safety unit), whose
results `doctor` reads.

## Technical approach

### `schema`

`frob schema [<schema_id> | --verb <name> | --list] [--json]`.

- `--list`: every schema identifier with kind (`verb-input`, `verb-output`, `envelope`, `refusal`, `format`,
  `wire`, `registry`), owning crate and version; paged.
- `<schema_id>`: `{ schema, example, example_digest, notes }`. `schema` is JSON Schema as generated by the
  registry build script. `example` is the **minimal valid example**: the smallest instance that validates, with
  every required field present and every optional field absent, values taken from the built-in fixtures
  (`quad-a`, the template `quadruped-12dof`, a flat-terrain scene). `notes` lists, per field, its unit and its
  integer type where relevant.
- `--verb <name>`: both schemas of the verb and, for `run` and `mutate` verbs, the common fields added by kind
  (`sync_wait_ms`, `idempotency_key`, `budget`, `estimate_only`, `on_cancel`; `idempotency_key`,
  `expected_parent`).

Rules. (1) Examples are data files beside the schemas (`registries/examples/<schema_id>.json`), not generated
text: each is validated against its schema at build time, and each verb-input example is also executed in a test
(with `--estimate` for `run` verbs) so that "valid" means "accepted by the real parser", not only by the schema.
(2) Integer fields are typed `int53` (a JSON number within ±(2⁵³ − 1)) or `u64str`/`i64str` (a decimal string
matching `^(0|[1-9][0-9]{0,19})$`, with an optional leading minus for the signed type); the lint forbids any
other integer type, and `notes` says which is which. (3) An unknown identifier is refused with `FROB-REF-802` and
the three nearest identifiers. (4) The MCP resource `frob://schema/{schema_id}` returns the same JSON.

### `doctor`

`frob doctor [--check <group>]… [--json]`. It runs checks in groups and returns findings; it changes nothing (no
cache is rebuilt, no pin moved, no probe re-run: it reports and names the command that would).

| Group | Checks | A finding when |
|---|---|---|
| `toolchain` | The compiler that built this binary equals the toolchain T recorded in `franken-stack.lock` and `rust-toolchain.toml`; the lockfile digest in the binary equals the file on disk | They differ |
| `pins` | Each consumed sibling's commit in the build's stack receipt equals `franken-stack.lock`; the build graph holds exactly one asupersync package; no forbidden feature is enabled | A pin differs; a second package; a forbidden feature |
| `daemon` | `frobd` reachable on its socket; socket mode 0600; ledger opens and passes its consistency check; daemon and client were built from the same stack receipt | Unreachable (severity info: CPU-tier verbs still run in process); wrong mode; inconsistent ledger; receipt mismatch |
| `devices` | For each expected device: driver present and loadable; the run-time kernel compiler present (CUDA) or the Metal gateway present (Mac); device memory readable; `spark check` currency (the CPU-versus-device differential check is current for the installed driver) | A device is absent, a driver changed since the last check, or the check is stale |
| `kernel-cache` | Every cache entry's content hash equals its key's recorded hash; entries keyed by a driver or fingerprint that no longer matches are counted as stale; total bytes against the cache budget | A hash mismatch (severity high: the entry will be recompiled and the event logged); stale entries; over budget |
| `probes` | The IEEE probe report exists for each device and matches the current hardware fingerprint and driver; exact-integer and guarded-precision kernel classes have a probe verdict | No report, or a report from another fingerprint or driver |
| `store` | State root and export root exist, are writable, and have free space above the preflight threshold; the private root is outside the repository | Any fails |

Output (`frob.doctor.out/1`): `groups[]` with `status` (`ok`, `findings`, `skipped` with a reason) and
`findings[]`: `code` (a stable slug such as `pins.sibling-mismatch`), `severity` (`info`, `low`, `high`),
`message`, `observed`, `required`, and ranked `repairs` (commands). Exit 0 when no finding is above `info`;
exit 2 otherwise. `doctor` never exits with a refusal for an unhealthy host: an unhealthy host is a result with
findings. Evidence block: class `Tested`, tier `static`, determinism `exact`.

`next_actions` gives the first repair of the highest-severity finding, for example `frob spark check` or `frob
spark precompile`.

## Acceptance criteria

- [ ] `frob schema --list` covers every `input_schema` and `output_schema` named in the verb registry plus the
      envelope and the refusal block; `frob schema <id>` returns a schema and an example for each.
- [ ] Every example validates against its schema; every verb-input example is accepted by its verb's parser.
- [ ] The schema lint finds no bare 64-bit integer; a planted one fails.
- [ ] `frob doctor --json` on a healthy host exits 0 with every group `ok` or `skipped` with a reason; on each
      planted fault below it exits 2 with the expected finding code.
- [ ] `doctor` performs no write: the state root's digest is unchanged by a run.
- [ ] Both verbs are on the CLI and in the served MCP tool list with identical schemas; the resource
      `frob://schema/{schema_id}` equals the CLI answer.

## Test plan

### Unit tests
`crates/frob-verbs/tests/schema_verb.rs`, `crates/frob-cli/tests/doctor.rs` (real registries; a temporary state
root with planted faults):
- `schema_list_covers_registry`.
- `examples_validate` and `verb_input_examples_execute` (every verb; `--estimate` for `run`).
- `example_is_minimal`: removing any field of an example makes it invalid; no optional field is present.
- `integer_types_only`: lint over all schemas; planted `"type": "integer", "format": "int64"` fails.
- `unknown_schema_is_802_with_suggestions`.
- `doctor_healthy_exit_0`.
- `doctor_toolchain_mismatch`: a lockfile naming another nightly gives `toolchain.mismatch`, severity high.
- `doctor_two_asupersync_packages`: a fixture metadata file with two packages gives `pins.duplicate-runtime`.
- `doctor_cache_hash_mismatch`: one flipped byte in a cache entry gives `kernel-cache.hash-mismatch`.
- `doctor_probe_stale_after_driver_change`.
- `doctor_socket_mode`: mode 0644 gives `daemon.socket-mode`.
- `doctor_is_read_only`: state-root digest equal before and after.
- `doctor_daemon_absent_is_info`: exit 0 with an `info` finding and `dispatch: in-process` noted.

### End-to-end script and logging
`scripts/e2e/operator_verbs.sh`, steps `schema-*` and `doctor-*`: list schemas; fetch each; pipe each
verb-input example back into its verb; run `frob doctor --json` on the clean state root, then after each planted
fault (a copied state root with one fault at a time). NDJSON lines: `ts`, `script`, `bead`, `step`, `event`,
command, exit code, wall time, the `evidence` block, schemas listed against the registry count, examples
accepted against the total, the finding code against expected per fault, state-root digests before and after,
and on failure the first schema or check that differs.

### Known answers and negative controls
- KA-756: 2⁵³ + 1 = 9,007,199,254,740,993 is refused in an `int53` field (`FROB-REF-808`) and preserved exactly
  in a `u64str` field; the example for a schema with a tick index uses the string form.
- Negative control: an example with a misspelt field name; `verb_input_examples_execute` fails with
  `FROB-REF-802`.
- Negative control: a `doctor` that rebuilds a stale cache entry while checking; `doctor_is_read_only` fails.
- Negative control: a `doctor` that reports `ok` when the daemon and the client carry different stack receipts.

## Considerations

- `doctor` reads host facts that can be private (paths, device serials inside a fingerprint). It prints digests
  of fingerprints, not their raw fields, and paths only relative to the session roots.
- The device group needs hardware; on a host without GPUs those checks are `skipped` with the reason, never
  `ok`.
- Minimal examples must stay minimal as schemas grow; the minimality test is what prevents examples from
  becoming a second place where defaults are documented.
