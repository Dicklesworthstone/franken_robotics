## Background

A proof obligation, in this project, is a statement that a mechanism's design must be shown to satisfy, together
with the method that shows it. Tether, the surface subsystem (verb registry, daemon `frobd` with its job ledger
and dispatcher, MCP server), has five. Each backs one of the surface's invariants with an argument that can be
read and a check that can fail:

| ID | Obligation | Verification named by the specification |
|---|---|---|
| PO-TETHER-01 | The admission transaction yields "one job and one budget charge per (principal, verb, idempotency key), under any interleaving and any crash point" | Exhaustive interleavings of two submitters and one crash over the four steps on the deterministic runtime; the two-statement variant must fail |
| PO-TETHER-02 | Keyset pagination over a total order restricted to a fixed frontier partitions the snapshot | Induction on pages, written in the crate's `CONTRACT.md`; property test under random appends |
| PO-TETHER-03 | Slot dispatch preserves digests | The purity argument; the golden co-tenancy test of the slot-invariance gate |
| PO-TETHER-04 | The estimate interval covers with probability at least 1 − α under exchangeability | The rank argument; empirical coverage in the estimate gate. Class: Tested |
| PO-TETHER-05 | With linear ageing no admitted job waits forever | After 600 s a job's key is the minimum; ties break by admission order. Model check on the guard table |

The mechanisms are built by other beads (idempotency and pagination, slot dispatch, size classes and
preempt-resume, calibrated estimates). This bead owns the obligations themselves: the written arguments, placed
where the crate contract requires them, and the five checks as named, runnable artifacts with their negative
controls. Without it the arguments would live only in the heads of the implementers.

## Scope

In: for each obligation, the precise statement with symbols defined, the argument text for `CONTRACT.md`, the
check's construction and size, its negative control, and where its record is kept.
Out: building the mechanisms; the thirteen invariants as property tests (N32b-22); the gates' full-scale
measurements (the mechanism beads); the kill decisions (N32b-27, N32b-28).

## Technical approach

**PO-TETHER-01: the admission transaction.** The protocol has four steps. (1) Resolve names to immutable
identifiers, fill defaults, serialize canonically and take the BLAKE3 digest d. (2) Begin an immediate
transaction on the ledger and look up (principal, verb, key). (3) Found with digest d: return the stored receipt
with `idempotent_replay: true`. Found with another digest: refuse (key reuse with different content, exit 7).
Not found: insert the binding, debit the reservation and insert the job row in state `admitted`, all in this
transaction. (4) Commit; only then enqueue the job and return the receipt. On restart the daemon enqueues every
`admitted` job with no start record.

*Argument.* The immediate transaction holds the ledger's write lock from step 2 to step 4, so the lookup and the
insert of one submitter are not interleaved with another's; the unique index on (principal, verb, key) makes a
second insert impossible even if they were. Binding, debit and job row commit atomically or not at all, so no
state has a job without a charge or a charge without a job. A crash before commit leaves nothing; a crash after
commit leaves exactly one admitted job, found by the retry.

*Check.* A model on the deterministic runtime: two submitters A and B, each four steps, with the lock modelled
(step 2 blocks while the other holds it). All interleavings of the two step sequences that respect each
submitter's order are enumerated: C(8, 4) = 70. For each, a crash is injected at each of the 9 positions (before
the first step, between any two, after the last), giving 630 schedules; after a crash the daemon restarts and
both callers retry with the same key. Cases: same key and same payload; same key and different payload.
Assertions on every schedule: jobs per key ∈ {0, 1}; charges = jobs; once any caller holds a receipt, exactly
one job; with different payloads exactly one caller is refused. *Negative control:* the variant with lookup and
insert as two statements and no unique index must fail on the schedule A2, B2, A3, B3 (miss, miss, insert,
insert: two jobs, two charges).

**PO-TETHER-02: pagination.** Let F be the committed frontier pinned by the first page, S the set of rows of the
query committed at or below F, k a total order key on rows (instant, world address, channel, sample index), p
the page size, c₀ = −∞ and cᵢ the key of the last row of page i. Page i + 1 returns the first p rows of
{r ∈ S : k(r) > cᵢ} in order.

*Argument (induction on pages).* Claim: after i pages the concatenation is the first min(i·p, |S|) rows of S in
k-order. Base: zero pages, empty. Step: S is fixed, because rows committed after the first page have commit
above F and are excluded; k is total, so "the rows strictly after cᵢ" is exactly the suffix of S after the i·p-th
row; taking its first p rows extends the prefix by p (or by what remains). Hence none is skipped and none
repeated, and the sequence ends with a page shorter than p. A cursor used with changed filters would change S,
so it is refused; a cursor whose frontier was collected cannot reconstruct S, so it is refused.

*Check.* A property test: random row sets with many equal instants, random page sizes, random appends (some with
keys below cᵢ, as from a slower world) committed between pages: concatenation equals the snapshot at F. *Negative
controls:* offset pagination (repeats a row) and a time-only cursor (skips a row).

**PO-TETHER-03: slot dispatch.** *Argument (purity).* (a) Dispatch is a pure function of queue state: which
episode enters which slot at which reset boundary depends only on ledger integers. (b) No kernel reads another
world's rows: every kernel is elementwise or reduces within a world's segment. (c) Randomness is drawn by
address: counter-based streams keyed by (world address, step, stream), with no device-side generator state. (d)
A reset writes a slot's complete per-world state from the admitted episode's identities. Therefore a world's
trajectory, and so its digest, is a function of its address and identities alone, and is independent of slot,
co-tenants, dispatch order, preemption and resumption. *Check.* The golden co-tenancy test: the same episodes
solo and in random co-tenancies, slot permutations and preempt-resume points give identical per-world digests
(1,000 episodes in 100 random co-tenancies at the gate; a reduced set here on `batch-cpu`). *Negative control:*
a stand-in kernel with a planted read of slot i − 1.

**PO-TETHER-04: the estimate interval.** For a stratum (verb, tier, device family, shape class) the daemon keeps
the last n absolute log residuals rᵢ = |ln(yᵢ / ŷᵢ)| of finished jobs, y the actual cost and ŷ the cost model's
point prediction. At miscoverage α let k = ⌈(n + 1)(1 − α)⌉ and q the k-th smallest residual; the interval is
[ŷ·e^(−q), ŷ·e^(q)].

*Argument (rank).* If r₁, …, rₙ and the new job's residual rₙ₊₁ are exchangeable, the rank of rₙ₊₁ among the n + 1
values is uniform on {1, …, n + 1} (ties resolved against coverage), so P(rₙ₊₁ ≤ q) ≥ k/(n + 1) ≥ 1 − α; and
rₙ₊₁ ≤ q is exactly the event that y lies in the interval. The index exists only when k ≤ n: n ≥ 9 at α = 0.10 and
n ≥ 19 at α = 0.05. The daemon reports the 90% interval and calls a stratum calibrated from n = 19; below that it
marks the interval `uncalibrated` and admission uses a fixed factor of 2. A driver, compiler or kernel-version
change starts a new stratum, since exchangeability across it is not credible.

*Check.* Unit: the index rule on constructed residual lists. Simulation: 10⁴ synthetic strata with exchangeable
residuals: empirical coverage of the 90% interval is at least 0.90 minus sampling error. Gate-scale: coverage in
85% to 95% of at least 200 held-out jobs per stratum. *Negative control:* residuals with a planted drift (a
driver change not starting a new stratum): coverage falls below 85% and the check must fail. Class: Tested.

**PO-TETHER-05: no starvation.** Within a size class the dispatcher orders agents by deficit round-robin
weighted by remaining budget and, within an agent, by shortest estimated remaining work; a waiting job's
effective work decays linearly to zero over 600 s (TARGET): w_eff(a) = w·max(0, 1 − a/600 s) for age a.

*Argument.* After 600 s a job's key is 0, the minimum possible; ties break by admission order, so among aged jobs
of an agent the earliest admitted is first. Shorter jobs arriving later have keys above 0 until they too age,
and then sort behind it. Deficit round-robin gives every agent with positive weight a turn in every round, and
the batch class keeps a floor of device time, so the head job of each agent is served within a bounded number of
rounds. Hence every admitted job starts in bounded time.

*Check.* A finite model of the guard table (states: under-filled, saturated, mixed shapes, one agent dominant,
estimates unreliable; actions as tabulated; hysteresis included) with up to 3 agents, 6 jobs, 2 shape classes
and time in quanta, explored exhaustively: the property "every admitted job starts within T_max" holds, with
T_max computed from the ageing period, the quantum and the class floor. *Negative control:* the model with
ageing removed admits an infinite stream of shorter jobs that starves a long one; the checker must produce that
trace.

**Where the records live.** Arguments: `crates/frob-verbs/CONTRACT.md` (01, 02, 04) and
`crates/frob-cli/CONTRACT.md` for the daemon (03, 05), in the invariants section, each headed by its identifier.
Checks: `crates/frob-conformance/tests/tether_obligations.rs`. Each obligation has a row in the conformance
registry: identifier, statement, argument location, check name, control, evidence class.

### End-to-end script and logging
`scripts/e2e/tether_invariants.sh` (N32b-22) gains a group `obligations-*` that runs the five checks through
`cargo test -p frob-conformance tether_obligations` and, for PO-TETHER-01 and -02, repeats a reduced form
against the real `frobd` (two racing `frob sim run` calls with one key; a paged `frob telemetry query` during
appends). NDJSON lines: `ts`, `script`, `bead`, `step` (the obligation), `event`, command, exit code, wall time,
schedules or cases run and passed, coverage measured against its bounds, the control's expected failure
observed, and on failure the minimal failing schedule or trace.

### Known answers and negative controls
- KA-759: conformal index at n = 19, α = 0.05: the 19th smallest residual, that is, the largest.
- KA-763 (one job, one charge; replay returns the stored receipt), KA-764 (page two is {3, 4}).
- Negative controls: one per obligation, as stated above; all five are registered.
- Determinism: the interleaving and model checks are exhaustive and seed-free; property tests are seeded; all
  identical twice and across platforms.

## Considerations

- PO-TETHER-04 holds only under exchangeability within a stratum. Bursty workloads that change the job mix inside
  a stratum weaken it; the estimate gate's coverage band (85% to 95%) is the monitor, and a stratum that leaves
  the band is reported, not silently widened.
- PO-TETHER-05's bound depends on constants under an open question (reserve, job cap, quantum, ageing period;
  defaults 5%, 64, 5 s, 600 s); the model reads them from the decision-core table, so the check re-runs when they
  change.
- PO-TETHER-03 is an argument about our kernels; it is only as true as the absence of cross-world reads, which
  is why the kernel-level batch-composition test is a precondition of the slot gate.
