## Background

Several acceptance tests of FrankenRobotics judge what an agent *did*, not only what it answered: how many
simulations it ran before naming a cause, how many serial turns it needed per accepted design, whether its
conclusion follows from the results it actually received. Self-reports are useless for that. The surface
therefore records a **session transcript**: for every call in a session, written by the daemon in dispatch, the
sequence number, the surface, the verb, the digest of the resolved request, the digest of the envelope
delivered, the exit code, the cost, the budget after the call, the focus and wall time; `session.show
--transcript` returns it, paged. The record (`frob.session-transcript/1`) and its capture are built with the
agent documentation and the studio agent test (seed BD-313); the specification assigns transcript capture to the
verb crate and says the diagnosis battery "runs through `session.open`, with a namespace per arm".

This bead is what the agent diagnosis battery adds on top of that record. The battery (thirty wrong-setup tasks;
tasks in N32b-37, scoring in N32b-39) scores five figures per agent arm, and three of them are computed from the
transcript: the number of simulations run beyond the minimal evidence, wall time to the answer, and *whether a
clean client reproduces the diagnosis from the receipts alone*. A clean client is a process with no memory of
the agent's session: it is given the transcript, re-obtains the evidence-bearing answers, and must arrive at the
same named cause by a fixed reading rule. If it cannot, the agent's diagnosis rested on something other than
what the system told it.

Design decisions (DESIGN). The transcript stores digests, not bodies; reproduction therefore needs the resolved
request behind each digest to be retrievable from the content-addressed store, which this bead requires and
tests. Counts are pure functions of a transcript, kept in the conformance crate so that every gate that counts
turns or simulations uses one definition. Rejected: client-side logging (the client is the thing under test);
counting simulations from the agent's own report.

## Scope

In: the requirements this bead places on the transcript record and the tests that they hold; the registry field
that marks verbs that spend physics; the derived counts (simulations, causal tests, turns, wall time); the
clean-client replayer and its reading rules per cause class; privacy of what it reads.
Out: capturing the transcript and `session.show --transcript` (seed BD-313); the battery's tasks (N32b-37) and
scoring (N32b-39); the idempotency binding (seed BD-211); the artifact graph (seed BD-095).

## Technical approach

**1. What the battery requires of the transcript** (checked here against the record as built).

| Requirement | Why | Check |
|---|---|---|
| One row per call that reached dispatch, on either surface, in order | Counts must not depend on the client | A scripted session of known length over CLI and MCP |
| The request digest is that of the *resolved* request (names replaced by immutable identifiers, defaults filled); for keyed verbs it equals the idempotency binding's digest | A replay must ask the same question even after a name has moved | Move a mutable name after the call; the digest still resolves to the original identifiers |
| The resolved request is retrievable by its digest from the store for as long as the session's job records are kept, with secrets removed and untrusted text confined to its marked fields | The clean client must be able to re-issue the call | Fetch by digest; search for the token |
| The row carries the exit code, the refusal code if any, the job identifier if one was created or found, and whether the answer was an idempotent replay | A replayed call must not count as a new simulation | Three calls with one key |
| Arrival and delivery instants per row (daemon wall clock; operational data, never part of a result or an evidence record) | Wall time to the answer; turn segmentation | Monotone per session |
| A session reads its own transcript and its derived sessions'; a scorer reads with an owner-held scope; nobody else | The key and other arms must stay hidden | Cross-namespace read refused |

Where the record as built lacks one of these (for example it holds the request digest but the resolved request
is not kept), this bead adds it in `frob-verbs` beside the capture code, as a content-addressed artifact written
in the same ledger transaction that finalizes the call.

**2. A registry field.** Each verb entry gains `spends_physics = true | false` (true for `sim.run`, `eval.run`,
`eval.compare`, `study.submit`, `nemesis.search`, `autopsy.intervene`, `autopsy.rerun`, `train.start`,
`mission.synthesize` and the like; false for static analyses, `scene.accept`, `--estimate` forms and every
`read` verb). A lint requires the field on every `run` verb. `sense.causal-test` is marked false and counted
separately, because the battery treats it as evidence, not as a rollout.

**3. Derived counts** (pure functions of a transcript; `crates/frob-conformance/src/transcript_counts.rs`).

- *Simulations run:* the number of distinct jobs created by calls to verbs with `spends_physics = true`,
  counting an idempotent replay zero times and an `--estimate` call zero times.
- *Causal tests:* calls to `sense.causal-test` that created a job.
- *Turns:* where the harness passes a turn marker as request metadata, the number of distinct markers;
  otherwise a turn is a maximal run of calls with no gap between one call's delivery and the next call's arrival
  above a harness-specific threshold (default 5 s, DESIGN). The method used is recorded with every count.
  *Serial turns per accepted design* divides turns by designs that reached an accepted verdict.
- *Wall time to the answer:* from the first call's arrival to the delivery of the last call before the answer
  was submitted.

**4. The clean client** (binary `frob-replay-diagnosis` in `frob-conformance`). Input: a transcript and a claimed
diagnosis (`{cause: kind, object, field}`, or `no-defect`, or `unknown` with two candidates). Procedure:

1. Open a fresh session in a fresh namespace with read scopes and a small budget; it reaches the agent's objects
   only by immutable identifiers.
2. Select the evidence-bearing calls: every `read` call and every `run` call whose result the agent received
   before answering, in order.
3. Re-obtain each answer. A `read` call is re-issued with its stored resolved request; its envelope digest must
   equal the recorded one. A `run` call is looked up by its recorded idempotency key under the scorer's scope,
   which returns the stored receipt and result with no new spend; its digest must equal the record.
4. Apply the reading rule for the claimed cause's class to the re-obtained envelopes:

   | Class | Verb and field read | Rule |
   |---|---|---|
   | Wrong units | `design.check`: the mass roll-up and the declared budget | The roll-up departs from the budget, and the largest contributor's dimension field is the claimed field |
   | Insufficient friction | The fixture's analytic layer (the friction-demand row) and the scene's friction | Scene friction below the demand |
   | Low current limit | The tread-force cap row; one run's failure reason | Cap below the required traction, and the run's reason is `stall` |
   | Visual and collision mismatch | `scene.accept`: the deviation report | A region above the pack threshold; it is the claimed object |
   | Delayed observations | `sense.causal-test` verdict; the sample-age field | The test fails at a decision instant, or age exceeds the deadline, on the claimed sensor |
   | No defect | A verdict record | The requirement's verdict is pass and no rule above reads a cause |
   | Unknown | All of the above | No rule separates the two named candidates |

5. The diagnosis is *reproduced* when every re-obtained digest matches and the rule's reading equals the claim.

A diagnosis can fail reproduction in three distinguishable ways, each reported: a digest mismatch (the system
did not answer the same way twice), missing evidence (the transcript holds no call showing the cause), or a
reading mismatch (the evidence shows something else).

**5. Privacy.** Resolved requests can hold private names; they inherit the strictest privacy mark of the objects
they name. End-to-end logs carry transcript digests and counts, never request bodies.

## Acceptance criteria

- [ ] Each requirement of the table holds on the transcript record as built, on both surfaces; where one did
      not, the addition is in place with its test.
- [ ] Every `run` verb in the registry carries `spends_physics`; the lint fails on a missing field.
- [ ] Simulation, causal-test and turn counts computed from a scripted session equal the script's known counts.
- [ ] The clean client reproduces a correct scripted diagnosis for each of the seven classes and reports each of
      the three failure kinds on its planted case.
- [ ] A replayed call and an `--estimate` call add nothing to the simulation count.
- [ ] No token and no envelope body is stored in the transcript; resolved requests are free of secrets.

## Test plan

### Unit tests
`crates/frob-conformance/tests/transcript_counts.rs`, `crates/frob-conformance/tests/replay_diagnosis.rs`,
`crates/frob-verbs/tests/transcript_requirements.rs`:
- `one_row_per_dispatched_call`: 12 calls (3 refused) give 12 rows with sequence numbers 1 to 12.
- `request_resolves_after_name_moves`: a call using the name `quad-a`; the name is then moved; the stored
  request still names the original content address.
- `request_retrievable_and_secret_free`.
- `digest_equals_idempotency_binding`.
- `replay_counts_zero`: one `sim.run` key called three times counts one simulation.
- `estimate_counts_zero`; `causal_test_counted_separately`.
- `turn_segmentation`: gaps of 0.2 s, 0.3 s, 45 s, 0.1 s with a 5 s threshold give 2 turns; with turn markers
  present the marker count is used.
- `clean_client_reproduces_each_class` (seven scripted diagnoses).
- `clean_client_missing_evidence`: the "low current limit" claim with the cap-row call removed.
- `clean_client_reading_mismatch`: the claim "insufficient friction" on that transcript.
- `clean_client_digest_mismatch`: a transcript whose recorded digest was altered.
- `foreign_transcript_refused`.

### End-to-end script and logging
`scripts/e2e/diagnosis_battery.sh` (N32b-39), phase `transcript-*`: a scripted client performs a fixed
eleven-call session over the CLI and the same over MCP; the script reads both transcripts with `frob session show
--transcript --json`, checks they are equal apart from surface and instants, computes the counts and runs the
clean client on a scripted diagnosis. NDJSON lines per the shared helper: `ts`, `script`, `bead`, `step`,
`event`, command, exit code, wall time, the envelope's `evidence` block, rows against calls, simulations and
turns against the script's known values, digests compared, the clean client's verdict, and on failure the first
differing row.

### Known answers and negative controls
- Known answer: the scripted session has 11 calls, 2 simulations, 1 causal test and 3 turns.
- Negative control: a transcript whose request digest is of the request as typed (mutable names); the
  resolution test fails after the name is moved.
- Negative control: a counter that reads simulations from the agent's answer; the replay-count test fails it.
- Negative control: a clean client that accepts a diagnosis when digests match but applies no reading rule; the
  reading-mismatch case must fail it.

## Considerations

- The same counts feed the one-call-pipeline decision (plumbing turns) and the surface A/B (turns per accepted
  design); one definition in one crate keeps those gates comparable.
- Turn segmentation by gap is a heuristic; the turn marker is preferred where a harness can pass it.
- A transcript makes agent behaviour auditable to whoever holds the scope. That is intended for gates and for an
  agent reviewing its own session; it is why reading another principal's transcript needs an explicit scope.
- If the reading rules ever need judgment, the class is not identifiable by receipts and belongs among the
  inconclusive tasks.
