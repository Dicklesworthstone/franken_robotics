## Background

The agent diagnosis battery is an acceptance test of the agent surface of FrankenRobotics on setups that are
wrong in the ways an engineer meets. Thirty tasks on two registered fixtures (a cart crossing a door sill; a
quadruped on a split-grip landing) are each handed to a fresh agent with only the generated documentation and a
budget: twenty carry one seeded cause from five classes (wrong units, insufficient friction, low current limit,
hidden visual and collision mismatch, delayed observations; four tasks per class), five carry no defect, and
five are inconclusive by construction. The tasks and their sealed answer key are built by N32b-37; what the
agent did is captured by the session transcript of N32b-38. This bead scores the answers and runs the gate.

The battery complements the two task-completion gates of the surface, which score whether an agent can finish
studio and mission tasks. Here the score is on **diagnosis** (was the first named cause the real one?) and on
**restraint** (did the agent get there without burning simulations, and did it decline to invent a cause when
there was none or when the evidence could not decide?). Restraint is scored because a surface that only rewards
finding causes teaches agents to always find one.

GATE-TETHER-15 (claim kind: Design comparison; third milestone; TARGET thresholds): on the 30 tasks a fresh
agent names the seeded cause first in at least 16 of 20 seeded tasks; converts no inconclusive or no-defect task
into a cause; runs at most twice the minimal number of simulations in the median task; and every diagnosis is
reproduced by a clean client. A second arm with `sim.run` and logs only is run as the comparison, and the
difference is reported with its interval.

## Scope

In: the answer format; the two arms and how each is confined; the five scoring figures; the gate's decision
rule with every term made precise; the paired comparison and its pre-analysis; controls for the scorer;
`scripts/e2e/diagnosis_battery.sh`; the gate record.
Out: the tasks (N32b-37); transcripts and the clean client (N32b-38); the agent harness.

## Technical approach

**Arms.** Each arm runs the same thirty task instances (one instantiation seed, registered before the run) in
its own namespace, each task in a fresh agent context, with task order re-randomized per arm from a logged
seed.

| Arm | Session scopes | What the agent is given |
|---|---|---|
| A: the surface | Read scopes for every cluster the documentation teaches (design, scene, sense, sim, telemetry, explain, run, job, task, experiment), `sim:run`, `sense:run`, `scene:run`; a per-task budget | `robot-docs` output; the task statement |
| B: `sim.run` and logs only | `sim:read`, `sim:run`, `telemetry:read`, `run:read`, `job:read`; the same budget | The task statement, the text of the design, scene and task files as documents, and a one-page note on the verbs its scopes admit |

Arm B's confinement is by capability token, not by hiding tools: a call to `design.check`, `scene.accept`,
`sense.causal-test`, `explain.run` or `experiment.suggest` is refused for lack of scope. The table gives each
arm's widest scopes. Each arm is one root session opened with `session.open` for the arm's own agent principal
(`--principal diag-a`, `--principal diag-b`), in its own namespace (`--namespace diag-a-<serial>`,
`diag-b-<serial>`; the specification's "a namespace per arm"), with `capture: "strict"`. The two principals are
tables of the owner-held `safety.toml` (N37-02), each granting exactly its arm's row above and the battery's
budget and naming no namespace, so that one grant serves every instantiation: a root token is minted only from
a grant (N32b-01), which makes the grant the ceiling of arm B's confinement, whatever a root open asks for.
The arms cannot be derived from one common session, because a derived session keeps its
parent's namespace (N32b-02). Each task's session is derived from its arm's root with the intersection of the
arm's scopes and the scopes in the task's `task.json` (N32b-37), so an inconclusive task's withheld scopes are
withheld in both arms, and its budget is debited from the arm's root; the arm's root reads its tasks'
transcripts as transcripts of derived sessions, and the scorer reads both arms' transcripts with the owner-held
`session:audit` (N32bx-01). No arm session can hold `qual:admin` (N32b-01 refuses to mint it for an agent
principal, and derivation cannot add it), which is what keeps the keys sealed from the arms.

**Harness.** The agent harness is BD-313's fresh-agent runner, reused unchanged: a fresh-context agent of a
pinned harness and model per task, with no access to the repository or the plan; strict-capture sessions; a
turn marker per agent turn (`FROB_TURN` on the CLI, `frob/turn` on MCP); a wall-clock ceiling per task; the
transcript read with `frob session show --transcript --json` and saved with its digest. This bead supplies the
battery's tasks, sessions and answer extraction to it and scores what it returns.

**Answer** (`frob.diagnosis-answer/1`, extracted by the harness from the agent's final message; a malformed
answer counts as wrong and is recorded as such): `task`; `verdict` ∈ {`cause`, `no-defect`, `unknown`};
`causes`: an ordered list, first is the named cause, each `{kind, object, field}` with `kind` from the five
class names; for `unknown`: `candidates` (two) and `experiment` (the proposal that would decide); `evidence`: the
transcript sequence numbers the agent relies on.

**Five figures per arm.**

1. *First-cause accuracy:* the number of seeded tasks whose `causes[0]` equals the key's seeded cause (kind and
   object must match; field must match where the key names one), of 20.
2. *Excess simulations:* per task, sᵢ = simulations counted from the transcript and mᵢ = the task's minimal
   count from the key (0 or 1); reported as Σ max(0, sᵢ − mᵢ) and as the restraint statistic below.
3. *Wall time to the answer:* per task from the transcript; reported as median and 95th percentile.
4. *Reproduction:* per task, whether the clean client reproduces the diagnosis from the receipts alone.
5. *Abstention:* on the ten no-defect and inconclusive tasks, whether the verdict was `no-defect` or `unknown`
   respectively and no cause was named.

**The gate's rule, made precise.** Arm A passes when all four hold:

- (i) figure 1 ≥ 16 of 20;
- (ii) on every no-defect task the verdict is `no-defect`, and on every inconclusive task it is `unknown` with
  an empty `causes` list. One invented cause on an inconclusive task fails the arm outright. An `unknown` on a
  seeded task is a miss under (i), not a violation of (ii);
- (iii) restraint: the median over the 30 tasks of (sᵢ − 2·mᵢ) is at most 0. This is the literal reading of "at
  most twice the minimal number of simulations in the median task"; because mᵢ = 0 for most tasks, it requires
  the agent to settle at least half the battery without any excess simulation;
- (iv) figure 4 holds for all 30 tasks: for cause verdicts the clean client reads the same cause; for
  `no-defect` it finds a passing verdict in the receipts; for `unknown` it confirms that the receipts do not
  separate the two candidates.

**The comparison.** For the 20 seeded tasks, let b be the number where only arm A names the seeded cause first,
a the number where only arm B does. The difference in accuracy is (b − a)/20, reported with the exact paired
interval: two-sided 97.5% Clopper–Pearson intervals [L_b, U_b] and [L_a, U_a] on the two discordance
probabilities, and [L_b − U_a, U_b − L_a], which covers the difference with probability at least 95%. The same
is reported for abstention on the ten unseeded tasks, and the two arms' restraint statistics and wall times are
tabulated side by side. The gate's pass is decided by arm A's four conditions; the comparison is evidence about
how much the surface contributes and is reported whatever its sign.

**Pre-analysis, enumerated before any run.** With n = 20 and a = 0, U_a = 1 − 0.0125^(1/20) = 0.1968, so the
interval's lower end is above zero only when b ≥ 9 (L_b = 0.2069 at b = 9; 0.1696 at b = 8). A difference of
fewer than nine tasks cannot be distinguished from zero at this size, and the report says so in advance.

**Run protocol.** (1) Register the instantiation seed, the model and harness versions, the budgets and this rule
(a ledger entry before the first task). (2) Build the tasks (N32b-37's validation must pass). (3) Run arm A,
then arm B. (4) Score from an owner session holding `session:audit` and `qual:admin` (the owner's session,
opened from the command line as N32b-01's open point on the owner's session provides), after both arms' sessions
are closed: transcripts with `session:audit`; keys from the instantiation's battery campaign (N32b-37's sealing)
with `frob eval ledger q:battery-diag/<serial> --read-sealed <task-id> --json`, each read entered in the ledger.
(5) Run the scorer's controls. (6) Write the gate record from a session that did not build the surface under
test, and record it with `cargo run -p frob-conformance --example record_gate -- --gate GATE-TETHER-15 --receipt
<hash>`. (7) The owner closes the battery campaign with the admin action `close`, which takes no key (`frob
eval ledger q:battery-diag/<serial> --action close --json`; `--key` on `eval.ledger` is `FROB-REF-802`,
VERBS-eval); the instantiation seed may be logged only after that.

## Acceptance criteria

- [ ] GATE-TETHER-15 has a recorded result with the five figures for both arms, the four conditions for arm A,
      and the paired interval, citing transcripts by digest.
- [ ] The rule and seeds were registered before the first task (ledger order).
- [ ] Every arm-B call to an analysis verb was refused for scope (transcript check), and no arm read the key.
- [ ] The three scripted control agents below score as predicted in the same run.
- [ ] The record states the model and harness; a rerun with another model is a new record, not an overwrite.
- [ ] A failed gate is recorded as failed with the same detail; no threshold is edited after the run.

## Test plan

### Unit tests
`crates/frob-conformance/tests/diagnosis_scorer.rs` (stored answers, transcripts and keys; no agent needed):
- `first_cause_only_counts`: a correct cause listed second scores 0 for that task.
- `sixteen_of_twenty_boundary`: 16 passes (i), 15 fails.
- `invented_cause_on_inconclusive_fails_arm`: one such answer fails the arm whatever the other figures.
- `unknown_on_seeded_is_a_miss_not_a_violation`.
- `restraint_statistic`: with the battery's minimal counts (mᵢ = 1 on 9 tasks: four low-current-limit and five
  no-defect; mᵢ = 0 on 21): sᵢ = 2 on the 9 and 0 on the 21 gives median slack 0 (pass); sᵢ = 1 on sixteen of the
  zero-minimum tasks gives median slack 1 (fail).
- `excess_sum`: sᵢ − mᵢ summed over positives.
- `paired_interval_known_values`: b = 9, a = 0, n = 20: L_b = 0.2069, U_a = 0.1968, lower end 0.0102; b = 8:
  lower end −0.0271.
- `malformed_answer_is_wrong`.
- `reproduction_three_failure_kinds_reported`.

### End-to-end script and logging
`scripts/e2e/diagnosis_battery.sh` (header: `bead=N32b-39 milestone=M3 labels=tether,gauntlet,diagnosis
gates=GATE-TETHER-15 seed=39 needs=cpu,frobd,mcp plants=range-refused-units-seed,inconclusive-field-differs,inconclusive-scope-leak,statement-leak,typed-request-digest,self-reported-count,reissuing-clean-client,ruleless-clean-client,any-position-scorer,ignores-inconclusive-scorer,self-report-sim-scorer`,
N32b-37's four controls, N32b-38's four, then this bead's three scorer defects): phases `build-*` (N32b-37),
`transcript-*` (N32b-38), then `control-*`, `arm-a-*`, `arm-b-*`, `score-*`. Before the daemon starts the script
writes the state root's `safety.toml` only through STD-E2E's `e2e_session grant` (item 17): `diag-a` and
`diag-b` with the arms' rows and the battery's budget and no namespace, the scripted clients of the first two
phases (`tr`, with the read scopes and `sim:run` and `sense:run` of N32b-38's session, and `val`, the validation
client of N32b-37), and `owner` with `qual:admin`, `session:audit` and `eval:read`, the owner's table that the
sealing and the scoring sessions are opened from (N32b-01's open point on the owner's session). After `frobd`
starts every root session is opened with `e2e_session open <label> --principal <id> …` (the arm roots with
`--namespace diag-a-<serial>` or `diag-b-<serial>` and `--capture strict`; the owner's as `e2e_session open own
--principal owner`), each task session is derived from its arm's root, `e2e_session use` switches between them,
every key is written with `e2e_key`, and a token never appears in a log. Agent arms need a model and are run in
the gate lane, where the script is invoked with the runner's harness configuration; elsewhere `arm-a-*` and
`arm-b-*` are an `e2e_skip` with the reason (no model), never a pass; the control phase runs in every CI lane with
scripted agents. Log: `target/e2e-logs/diagnosis_battery/<utc-timestamp>.ndjson` and a
transcript. Every line has `ts`, `script`, `bead`, `step` (arm and task), `event`, the exact command line or
harness invocation, exit code, wall time, the `evidence` block of the session's last envelope, and `metric`
lines: per task correct or not, sᵢ and mᵢ, wall time, reproduced or the failure kind; per arm the five figures
against their thresholds (16 of 20; 0 conversions; median slack ≤ 0; 30 of 30 reproduced); the paired counts
and interval. The key is never logged; tasks are named by identifier only. On failure: the first task that
breaks a condition and the transcript digest. The `summary` line names GATE-TETHER-15.

### Known answers and negative controls
- Control agent 1, *minimal-evidence*: a scripted client that performs exactly the key's minimal evidence and
  answers by the reading rules: must score 20 of 20, 10 of 10 abstentions, median slack 0, 30 of 30 reproduced.
- Control agent 2, *always-commonest-class*: with no evidence call, always answers `insufficient-friction` on
  the floor of the task's scene, field `friction` (every class has four tasks, so any single class is a
  commonest one): must score exactly 4 of 20 on (i) (the four friction tasks, whose key names that object and
  field), and fail (ii) (a cause on every unseeded task) and (iv) (missing evidence).
- Control agent 3, *simulate-everything*: correct answers but five simulations on every task: must pass (i) and
  (ii) and fail (iii).
- Planted scorer defects that the controls must expose: a scorer that accepts a correct cause in any list
  position; one that ignores inconclusive tasks; one that reads `sᵢ` from the agent's self-report.
- Determinism: scoring is a pure function of answers, transcripts and keys (twice, both platforms); the control
  agents are deterministic end to end.

## Considerations

- The restraint condition's wording admits other readings (a ratio per task is undefined where the minimal
  count is zero). The reading adopted is stated above and registered with the run; the per-task table is
  published so that another reading can be recomputed.
- One model on one day is one sample of "a fresh agent". The record names the model and harness, and the gate is
  re-run when the documentation or the surface changes materially; trends across reruns are reported, never
  pooled.
- Arm B is given the files' text because without `design:read` it could not see the design at all; that makes
  it a fair "logs and source" baseline and slightly favours it, which is the conservative direction for the
  comparison.
- Cost: thirty tasks per arm with small budgets; the battery is designed to run on `batch-cpu` so that the gate
  does not wait on a GPU.
