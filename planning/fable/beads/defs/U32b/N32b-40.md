## Background

The offline replay packet is how a recorded episode of FrankenRobotics reaches someone with no daemon and no
store: one HTML file, written by the verb `telemetry.export-html`, that replays a world with its overlays and
makes no network request. The packet has two halves with two owners. The *writer* (in the record crate
`frob-chronicle`) lays out the data and enforces the size rule. The *page* (in `viewer/`) is the viewer's
single-file bundle, embedded in the packet, which reads those data and draws them. This bead is the page's
packet side at the second milestone: reading the embedded blocks, verifying them, playing the parent world,
and the in-page probe. Fork timelines and tables arrive at the third milestone (N32b-41 for the writer side,
N32b-42 for the page side).

The governing design decision is the order of construction: the packet is an adapter over records that already
exist. It computes no fork, no attribution and no verdict, and it contains no stepping code. Reason: a browser
bundle built first becomes a second, unreviewed implementation of replay; a page that only draws recorded rows
cannot disagree with the native harness. The page is therefore the ordinary viewer (N32b-10) with a different
`SnapshotSource`, and every number a reader sees in it is a stored value.

## Scope

In: the `PacketSource` implementation of the viewer's snapshot interface; locating and decoding the embedded
blocks; verifying block digests in the page; the header banner (claim class, flags); parent-world playback, with
the exported channels available to the probe and, from the third milestone, to the overlays of N32b-11 and
N32b-12 (which draw from any `SnapshotSource` and so need nothing more from this bead); the rendering policy
(WebGL 2; WebGPU only under two conditions); the in-page probe; behaviour on a damaged or foreign file; the check
that the page a packet embeds is the committed bundle; `scripts/e2e/replay_packet_page.sh`.
Out, with the bead that has it: the packet format itself, that is the header's fields, the frame row and its
anchor cell, the overlay columns, the element identifiers under which the header and the blocks sit in the HTML,
the trailing header digest, the `shapes` entry and the content security policy, together with writing packets
and `--check` (the writer bead N24a-41, a dependency; this bead reads that format and defines none of it); fork
timelines, ghost playback and tables (N32b-41 for the writer, N32b-42 for the page); the gate with two pinned
browsers (N32b-43); packaging the page bundle (N32b-13).

## Technical approach

**1. What the page finds in the file.** The format `frob.replay-packet/1` is defined once, by the writer bead
N24a-41, and the page is tested against files the real writer produces. What this bead relies on, by the names
that bead fixes: the header as canonical JSON in the element `#frob-header` (identities, tier, determinism and
claim class, tick range and frame period, the channel table, one BLAKE3 digest per block, the three
no-authorization flags, `shapes`, `named_ticks`, and one `anchor_cell` per timeline); binary blocks
Base64-encoded in elements `#frob-block-<n>` (the parent timeline as 48-byte little-endian rows of one 3 × 4 `f32`
matrix per body, whose translation column is the offset from the centre of the timeline's anchor cell; the
overlay channels as quantized columns in the run file's column layout); the header's own digest in the trailing
comment; and this page's code inline. Fork timelines and the tables block arrive at the third milestone. A file
that lacks any of these, or whose schema name differs, is foreign and is refused with a message naming what is
missing.

**2. `PacketSource`.** Implements `header()`, `shapes()`, `frame(tick)`, `column(name, range)`,
`nearestStoredTick(tick)` over the embedded blocks. Decoding: Base64 to `ArrayBuffer` with the browser's
built-in decoder, then typed-array views (`Float32Array` for rows; integer views for quantized columns),
little-endian checked once at start (the page refuses to run on a big-endian host with a clear message). Frames
are addressed by index = (tick − first tick) ÷ frame stride; ticks kept by decimation rules (the failure tick
and other named ticks) are listed in the header and found by lookup, not by arithmetic.

**3. Verification in the page.** Before first draw the page recomputes the BLAKE3 digest of each block's decoded
bytes (a small in-page implementation, part of the bundle and its byte budget) and compares with the header. A
mismatch stops playback of that block and shows "block <n> does not match its digest": the page never draws
bytes it cannot vouch for. The header's own digest is checked against a value in a trailing comment written by
the exporter. This is the reader's half of the read-back promise; the full comparison with source chunks is the
verb's `--check`.

**4. Banner.** Always visible: the run identifier, world address, tier, determinism class, the claim class of
the source (and nothing higher), `reality: no-claim` unless the header says otherwise, and the three flags shown
as "authorizes nothing: execution, hardware safety, sim-to-real: all false". If any flag field is missing or not
`false`, the page treats the file as foreign and refuses to play (absence is not read as false).

The banner has a first line above that short summary, reserved for the program's generated no-authorization
sentence ("Simulation results are not a safety case for a physical robot. execution_authorized: false · …"),
which one Rust function, `frob_core::auth::banner`, produces for every exporter so that the wording cannot
drift. A page cannot call that function, and a copy of the sentence in the page's script could drift from it,
so (DESIGN) the sentence travels in the packet: when the header's `/authorization` object has a string member
`banner`, the page shows that string verbatim, as a text node, as line 1 of the banner, and the short summary
stays beside it as line 2; the page never composes, shortens or rewords it. The generator, the exporter's
writing of the member and the golden file that pins the text belong to the M2 flag-carrier bead N37p1-01,
which depends on this bead and on the writer (so neither may depend on it): until it lands, packets carry no
such member, line 1 is absent and the summary alone is shown. A `banner` member that is present but is not a
non-empty string makes the file foreign, like a damaged flag.

**5. Playback.** As the viewer: stored frames only, no interpolation, the legend states the drawn tick; named
ticks on the timeline (first contact, first anomaly, failure; later the fork tick and first divergence).
Overlays are those whose channels are in the channel table; an overlay whose channel was not exported is listed
as "not in this packet".

**6. Rendering policy.** WebGL 2 through the Three.js page. WebGPU is used only when the page reports a secure
context *and* an adapter is obtained. FACT (to be re-read from the primary source before a gate cites it):
WebGPU is exposed only in secure contexts, and whether a file opened from disk is one is left to the browser, so
a packet that required WebGPU would not open everywhere. No frame-rate figure is claimed. If WebGL 2 is
unavailable the page shows the header, the banner and the tables as text and says that drawing is unavailable.

**7. In-page probe.** The equivalent of `telemetry.inspect-pixel`: for the pixel under the pointer it returns
the channel, unit, world address and tick of the quantity there, with the stored quantized integer and its
dequantized value. The overlays are third-milestone work (N32b-11, N32b-12), so at the second milestone the probe
reads the packet's columns directly: the element under the pixel comes from N32b-10's `pick`, and the value is
the stored integer of the named channel for that element at the drawn tick. From the third milestone, with an
overlay enabled, the probe returns that overlay's probe record (N32b-11's `probe(element, hit)`), whose integer is
the same stored value; N32b-14 and N32b-43 check that end to end. The headless test entry exposes it as
`probe(x, y, channel)` (the channel argument optional once an overlay is enabled) so that tests compare it with
`telemetry.query`.

**8. No network.** `connect-src` is empty in the packet's content security policy; the page issues no request.
Text in the header that originated in an import (a design name) is shown as text nodes only.

## Acceptance criteria

- [ ] A packet of the docking fixture (parent only) opens from disk with networking disabled and plays; the
      driver's request log is empty.
- [ ] Every block's digest is recomputed in the page and equals the header's; a packet with one flipped payload
      byte shows the mismatch message and draws nothing from that block.
- [ ] The banner shows the source's claim class and the three flags; a packet whose flag is `true` or missing is
      refused by the page.
- [ ] `probe` at 100 fixed points returns stored integers equal to `telemetry.query` for the same channel,
      world, tick and element.
- [ ] With WebGPU present but the context not secure, the page uses WebGL 2; the choice is shown in a
      diagnostics line.
- [ ] The packet-reading code and the digest implementation fit within the page's 600,000-byte bundle budget
      together with the rest of the viewer (size table recorded).
- [ ] The page embedded in an exported packet is the committed bundle: the export envelope's `page.bytes` and
      `page.manifest_digest` (reported by the writer N24a-41 from `frob_chronicle::viewer_page`) equal the
      committed manifest's length and digest (N32b-13), and the packet's own bytes are that bundle: with the
      inserted header and block elements replaced by the bundle's placeholder comment
      `<!--FROB-PACKET-BLOCKS-->` and the trailing header-digest comment removed, the file equals
      `viewer/dist/page.html` byte for byte (the writer changes no other byte of the page, N24a-41).
- [ ] A packet whose header carries `/authorization/banner` shows that string verbatim as the first line of the
      banner with the short summary beside it; a packet without the member shows the summary alone; the page's
      script contains no copy of the generated sentence.
- [ ] `scripts/e2e/replay_packet_page.sh` passes with the logging below.

## Test plan

### Unit tests
`viewer/tests/packet_source.test.mjs` (pinned headless browser; packets produced by the real writer from
fixture runs, plus hand-built damaged ones labelled `synthetic`):
- `locates_and_decodes_blocks`: header parsed; block count equals the header's digest list.
- `frame_row_from_block`: body 3, tick 75 of a 13-body packet starts at byte (75 × 13 + 3) × 48 = 46,944 of the
  parent block and decodes to the stored pose.
- `blake3_known_vectors`: the in-page digest equals the published test vectors for empty input and for the
  1,024-byte pattern input, and equals the exporter's digest for each fixture block.
- `flipped_byte_detected`; `truncated_block_detected`.
- `flags_missing_or_true_refused`.
- `banner_generated_line_is_header_string`: a packet whose header was given `authorization.banner = "<text
  with an angle bracket and an ampersand>"` (a `synthetic` copy of a real packet, header digest recomputed)
  shows exactly that text as line 1, inserted as a text node (no element is created from it), and the summary
  as line 2; the real writer's packet, which has no such member before N37p1-01, shows the summary alone; a
  member that is an empty string or a number makes the file foreign.
- `embedded_page_is_the_bundle`: the real writer's packet, with its inserted elements replaced by the
  placeholder and the trailing comment removed, equals the committed `page.html` byte for byte.
- `claim_class_not_raised`: a header with class `Tested` renders "Tested" and no stronger word anywhere.
- `named_ticks_found_by_lookup`: a decimated packet at half rate still jumps to the exact failure tick.
- `webgpu_policy`: (secure, adapter) uses WebGPU; (not secure, adapter) and (secure, no adapter) use WebGL 2.
- `no_webgl2_shows_text_fallback`.
- `probe_returns_stored_integer`: a named channel at a picked body equals the column's stored integer.
- `probe_unknown_channel_refused`: a channel absent from the header's table returns "not in this packet".
- `big_endian_refused` (simulated flag).

### End-to-end script and logging
`scripts/e2e/replay_packet_page.sh` (header `bead=N32b-40 milestone=M2 labels=tether,chronicle seed=40 needs=cpu
plants=skip-verification,lenient-flags,unconditional-webgpu`, each plant one negative control below; N32b-43's
third-milestone `replay_packet_gate.sh` reruns it as its step group `page-*`): on a temporary state root, `frob
telemetry export-html` on the docking fixture run (parent only); compare the envelope's `page` fields with the
committed manifest and hash the embedded page; open the file in both pinned browsers through N32b-44's launcher
with networking disabled; play 150 frames; run 100 probes over the exported channels and compare each with `frob
telemetry query`; repeat on a copy with one flipped byte and on a copy with a flag removed (both refused as
specified). It sources the STD-E2E helper and writes `target/e2e-logs/replay_packet_page/<utc>.ndjson` and a
transcript; each line has `ts`, `script`, `bead`, `step`, `event`, the exact command line, exit code, wall time,
the export envelope's `evidence` block, page bytes and manifest digest against the committed ones, blocks
verified against the header's count, external requests against 0, probes equal against 100, the browser name,
version and hash, the renderer chosen, and on failure the first failing block or probe with the file's path; then
a `summary`.

### Known answers and negative controls
- Known answers: timeline bytes are 48 · bodies · frames · timelines; a quadruped with 13 bodies over a 3 s
  window at 50 frames per second, parent only, is 48 · 13 · 150 = 93,600 bytes (124,800 encoded); a probe value
  equals the telemetry channel within its quantization.
- Negative control: a page that skips verification plays the flipped-byte packet; the test must fail it.
- Negative control: a page that reads the flags leniently (missing means false) plays a packet without them.
- Negative control: a page that requests WebGPU unconditionally fails to open under the not-secure case.
- Determinism: the same packet renders the same pixel dump twice with the software rasterizer.

## Considerations

- Gap resolved by design: the specification's list of packet contents has no geometry, yet a page must know
  body shapes to draw them. The writer bead N24a-41 now defines a `shapes` entry in the header (collision
  primitives only: boxes, spheres, capsules, cylinders, planes, with dimensions; a few hundred bytes per body),
  covered by the header's digest and counted in the writer's size computation. Visual meshes are not embedded.
  A packet without the entry is foreign under the rule of section 1.
- The frame rows give positions as single-precision offsets from one anchor cell per timeline (the writer's
  DESIGN for fitting the anchored convention into 48 bytes). The page adds 8 m times the cell difference only
  when it draws two timelines with different anchor cells, which does not happen before forks.
- An in-page BLAKE3 costs bytes and a little start-up time; it is what lets a reader trust a file that travelled
  by e-mail. If the byte budget forces a choice, the digest check stays and an overlay goes.
- A packet is a view: importing one creates no evidence, and nothing in the page offers to "re-run" or "edit".
- Private scenes: a packet of a private scene is a private artifact; the page cannot enforce that once the file
  exists, which is why export needs the scope and the flag.
