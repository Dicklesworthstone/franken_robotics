## Background

The offline replay packet of FrankenRobotics is one HTML file that replays a recorded episode with overlays and
needs no network, daemon or store. At the second milestone it carries one world. Its purpose at the third
milestone is larger: to show a *counterfactual argument*. The debugging subsystem answers "why did it fail?" by
forking the failing run at a snapshot, changing one declared mechanism, and re-running; the difference between
the fork and its parent, measured against a placebo, is the evidence. A reviewer who was not there should be
able to see that argument: the parent, the forks drawn over it from the moment they diverge, and the table of
contrasts, all in one file.

This bead extends the packet writer (in the record crate `frob-chronicle`) with fork timelines, the tables
block, and the switch that decides when a build may put fork content in a packet at all. The base format (the
header, the parent timeline, the overlay columns, the embedding in HTML, the cap and the size calculator) is
defined by the parent-only writer N24a-41 and is not restated here; this bead defines what forks add to it, and
repeats the size arithmetic only for the fork case, which is where the size rule binds.

The decisive rule is the order of construction (DESIGN). The packet is an adapter over records that already
exist: it draws a parent world and its forks from the record store and the contrast table from the debugging
subsystem. It computes no fork, no attribution and no verdict, and it contains no stepping code. The fork
overlay is enabled only after the native fork harness has passed its null-fork and fork-classification gates
for the build. Reason: a browser bundle built first becomes a second, unreviewed implementation of replay; a
page that only draws recorded rows cannot disagree with the harness.

## Scope

In, as the only definition of each: the per-fork fields of the header; fork timeline blocks and the
parent-prefix reference; per-fork overlay columns; the tables block; the licence switch and the two fork
refusals (`FROB-REF-724` per build, `FROB-REF-562` per run); the pre-write size bound with forks; which forks
the "fewer forks" reduction keeps; the fork tick and the first-divergence tick as named ticks under decimation;
what a packet with forks may say; `--check` for fork blocks and the tables block.

Out, with the bead that has it: the base format `frob.replay-packet/1` and the parent-only writer, that is the
header's other fields including `shapes`, `named_ticks` and `anchor_cell`, the 48-byte frame row, the overlay
column layout, the element identifiers and trailing digest in the HTML, the cap of 8,388,608 bytes and the size
calculator, the over-cap and not-stored refusals (`FROB-REF-836`, `FROB-REF-837`), the decimation rule with the
failure tick and the decision tick, byte determinism and the core of `--check` (the writer bead N24a-41, a
dependency, which until this bead lands answers any `--forks` request with `FROB-REF-724`); the page (N32b-40,
N32b-42); computing forks, classifications and contrasts (their subsystems); the gate (N32b-43).

## Technical approach

**1. What forks add to the format** (schema `frob.replay-packet/1`; the parts of the file, in file order, are
the header, the timelines, the overlay channels, the tables and the page; N24a-41 defines the header, the parent
timeline, the overlay column layout, the embedding and the page slot).

1. *Header.* The fork paths (empty in a parent-only packet) are filled, and for each fork the header adds: fork
   path, fork tick, class, label, first-divergence tick and stage, the intervention as `do(factor := value)`
   with its unit, the index of its timeline block, and its `anchor_cell`, which equals the parent's for every
   fork that shares a prefix, so that a ghost is drawn in the parent's coordinates without a cell correction.
2. *Timelines* for at most 16 forks beside the parent's, in the base format's 48-byte rows. A fork is stored
   from its fork tick and refers to the parent block for its prefix (section 2).
3. *Overlay channels* per fork, in the base format's column layout, where the fork's channels were recorded.
4. *Tables*: the fork classification of each fork, the contrast table with flip rates and the placebo flip rate,
   and the attribution labels. Text is the text the verbs returned, copied byte for byte (section 5). The block
   is embedded like any other block, under its index in the header's digest list.
5. *The page* is unchanged by this bead; the page side of forks is N32b-42.

**2. Fork timelines.** For fork f with fork tick t_f in a window [t₀, t₁): frames are stored for ticks t ≥ t_f
only; the block's header gives `prefix: {block: <parent index>, until_tick: t_f}`. A *continuation* fork (the
null fork or a placebo) and an *exogenous*, *contact-affecting* or *information* intervention all share the
parent's prefix by construction. A *structural or design-parameter* intervention starts at the authored initial
condition: it has no shared prefix, its block is stored from t₀ with `prefix: null`, and it counts as a full
timeline in the size table. The null fork is stored like any other fork (its rows are bit-equal to the
parent's); the writer does not deduplicate it, so that a reader can verify the equality.

**3. Size (FACT, arithmetic).** Timeline bytes are 48 · bodies · frames · timelines, with every fork counted as a
full timeline for the pre-write bound. Base64 multiplies by 4/3. The whole file is capped at 8 MiB = 8,388,608
bytes by default (TARGET), with 600,000 bytes budgeted for the page, so the binary payload may not exceed
(8,388,608 − 600,000) · 3/4 = 5,841,456 bytes.

| Case | Binary bytes | Encoded bytes |
|---|---|---|
| Quadruped, 13 bodies, 3 s at 50 frames per second (150 frames), a parent and 16 forks (17 timelines) | 48 · 13 · 150 · 17 = 1,591,200 | 2,121,600 |
| Humanoid, 30 bodies, same window and timelines | 48 · 30 · 150 · 17 = 3,672,000 | 4,896,000 |
| Counterexample to budgeting by payload size: 6,200,000 bytes of rows | Under the cap as binary | 8,266,667 encoded; 8,866,667 with the page: over |

The writer computes the encoded size before it writes anything (the exact Base64 length per block, plus header,
tables and the page's real byte count). A request over the cap is refused with the size table and the three
reductions that would admit it, each with the size it would give: half the frame rate; fewer forks (the largest
number that fits, keeping the null fork, the placebo and the forks with the largest contrasts first); bodies
restricted to a named subtree. Nothing is truncated silently. Decimation in time always keeps the fork tick,
the first-divergence tick and the failure tick, as extra frames at their exact ticks; the base writer's rule
also keeps the tick at which the verdict was decided, and all of them are listed in the header's `named_ticks`.

**4. The licence switch.** Fork content enters a packet only when both hold:

- *Per build:* the gate register shows a recorded pass, for this build's stack receipt, of the two fork harness
  gates (null forks of failing worlds replay with identical digests on the originating backend, alone and in a
  batch of children; catalogued intervention and state pairs are classified correctly, and the two structured
  refusals fire). Otherwise a request with `--forks` is refused as a capability not implemented in this build
  (`FROB-REF-724`, exit 5), naming the missing gates. A parent-only export still works.
- *Per run:* the source run's determinism class licenses counterfactual forks (class D2 with the
  batch-composition invariance gate current). Otherwise refused with `FROB-REF-562` (a counterfactual fork below
  class D2), exit 3.

The other two packet refusals are the base writer's (N24a-41) and apply unchanged to forks: a packet over the
cap (`FROB-REF-836`, provisional number, exit 3) and frames requested from a chunk that is neither stored nor
pinned (`FROB-REF-837`, provisional number, exit 3). No refusal leaves a partial file. All four codes and exits
are those of the refusal registry N32-REF.

**5. Tables block.** Canonical JSON with three arrays: `forks` (path, class, label, fork tick, earliest valid
tick and the checkpoint fields that forced it); `contrasts` (per intervention: replicates, rescue rate, the
placebo flip rate ρ₀, contrast = rescue rate − ρ₀, flip rate under perturbation at relative 10⁻¹² and at 10⁻⁷);
`labels` (the attribution labels, with their standing). Every string is copied from the verbs' stored
envelopes; each row carries the content address of the envelope it came from, so `--check` can compare.

**6. What a packet may say.** The claim class of its source and nothing higher. Fork overlays carry the fork's
label; attributions are `Estimated`; the header repeats the flags. A packet is a view: importing one creates no
evidence.

**7. Read-back.** `frob telemetry export-html --check <file>` recomputes every block digest, including fork
blocks and the tables block, and compares each with the source: fork frames with the fork's stored chunks,
table rows with the stored envelopes. When the source has been evicted it reports `source: evicted` and checks
internal digests only. The same run, options and exporter version produce the same bytes.

## Acceptance criteria

- [ ] For the docking fixture and the split-grip fixture, a packet with a parent and 16 forks is written, is at
      most 8,388,608 bytes, and two exports are byte-identical.
- [ ] Each non-structural fork's block starts at its fork tick and names the parent prefix; a structural fork's
      block starts at the window start with no prefix.
- [ ] The null fork's rows are bit-equal to the parent's over the common ticks (deviation exactly zero).
- [ ] The size calculator reproduces 1,591,200 → 2,121,600 and 3,672,000 → 4,896,000; a 6,200,000-byte request
      is refused with 8,866,667 printed and three reductions, each of which fits when applied.
- [ ] On a build without the recorded harness gates `--forks` returns `FROB-REF-724`; on a run below the
      licensing class it returns `FROB-REF-562`; in both cases no file exists afterwards.
- [ ] Half-rate decimation keeps the fork tick, the first-divergence tick and the failure tick.
- [ ] `--check` passes on a fresh packet and fails, naming the block, when one byte of a fork block or one
      character of the tables block is changed.
- [ ] Table text equals the stored verb envelopes byte for byte.

## Test plan

### Unit tests
`crates/frob-chronicle/tests/replay_packet_forks.rs` (real store; fixture runs with real forks made by the fork
verbs on `batch-cpu`):
- `size_table_with_forks`: the two rows above; payload ceiling 5,841,456.
- `fork_block_starts_at_fork_tick`: fork at tick 90 of [0, 150): 60 frames stored, prefix until 90.
- `structural_fork_has_no_prefix`.
- `null_fork_bit_equal`: byte comparison of fork rows with parent rows for ticks ≥ t_f.
- `seventeen_forks_refused`: `--forks` with 17 paths is refused with the limit 16 (`FROB-REF-802`, exit 3: the
  input schema bounds the list at 16 items, so the request never reaches the size calculator).
- `over_cap_reductions_fit`: for a constructed over-cap request each reduction's stated size is at most the cap
  and equals the size actually produced.
- `fewer_forks_keeps_null_and_placebo_first`.
- `decimation_keeps_three_named_ticks`: fork tick 91, first divergence 97, failure 143 at stride 2: all three
  present.
- `licence_missing_gates_is_724`; `licence_class_is_562`; `no_partial_file_on_refusal`.
- `tables_copied_verbatim`: a contrast row with rescue 60 of 64 and placebo flips 2 of 64 shows rescue rate
  0.9375, ρ₀ = 0.03125, contrast 0.90625 exactly as stored.
- `check_detects_fork_block_flip`; `check_detects_table_edit`; `check_source_evicted`.
- `byte_determinism_with_forks`.

### End-to-end script and logging

bead's key.

### Known answers and negative controls
- Known answers: the four sizes; a null fork drawn as a ghost coincides with its parent, deviation exactly zero
  in every frame; the 6,200,000-byte request is refused with 8,866,667 printed.
- Negative control: a writer that checks the binary payload against the cap admits the over-cap request. This
  is the plant `packet-binary-budget`, which N32b-24 (M2, a dependency) built in this writer's crate for the
  catalogue entry `tether-packet-payload-budget` of N32-CX; the test here runs that plant on a 16-fork request
  and reports to the entry's one seeded control. No second mutant of the writer is built.
- Negative control: a writer that stores a recomputed (re-simulated or interpolated) fork row; `--check` against
  the fork's chunks fails.
- Negative control: a writer that deduplicates the null fork by referencing the parent for all ticks; the
  bit-equality test cannot then detect a broken null fork, and the test that requires stored null-fork rows
  fails.
- Negative control: a tables block that rounds the contrast to two decimals; the verbatim test fails.

## Considerations

- Kill gate named in advance: KILL-REPLAYPACK (decision bead N32b-32). Trigger: the packet gate fails after one
  repair cycle, or the page cannot be held to its byte budget. Fallback: run export, stills with overlays and
  the live viewer. A build packet may include a replay packet as an optional file and never depends on one.
- The pre-write bound counts every fork as a full timeline; real packets are smaller because prefixes are
  shared. The bound is deliberately the simple one, so that a refusal can be reasoned about by hand.
- The licence switch reads the gate register, so a build that has not run its harness gates cannot ship fork
  packets even if the code is present. That is the intended coupling.
- Two code numbers are provisional (allocated by the refusal registry bead); the conditions and exits are fixed.
