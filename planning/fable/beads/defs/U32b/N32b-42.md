## Background

A replay packet of FrankenRobotics is one offline HTML file that shows a recorded episode. From the third
milestone it can carry a parent world and up to 16 counterfactual forks, with the tables that summarize what the
forks showed. The writer side (N32b-41) lays out fork timelines, each stored from its fork tick with a reference
to the parent block for its prefix, and a tables block copied from the verbs. This bead is the page side: it
makes the viewer inside the packet read those blocks and present the counterfactual argument so that a reader
can check it by eye and by probe.

The presentation has to be honest in a specific way. A fork that "fixes" a failure is the most persuasive
picture this system produces, and it is evidence about one intervention in one simulated model, of class
`Estimated`. So the page shows three things together and never one alone: the ghost (the fork drawn over its
parent from the first different event), the fork's label and class, and the contrast against the placebo, which
measures how much of an apparent rescue is mere sensitivity. A null fork must coincide with its parent exactly;
the page displays that as a checked fact, because if it fails nothing else in the packet means anything.

The page still computes nothing about physics. It reads rows; the deviation it prints is a difference of two
stored poses; every text in the tables panel is the text the verbs returned.

## Scope

In: extending the packet source to fork blocks and prefixes; the fork selector; ghost playback in packet mode
(using the ghost overlay of N32b-12); the deviation readout and the null-fork check; the tables panel; labels
and banners for fork content; behaviour when a packet has no forks or a fork block fails verification.
Out: the ghost overlay's drawing function (N32b-12); writing fork blocks and tables (N32b-41); the gate
(N32b-43).

## Technical approach

**1. Reading forks.** The header lists, per fork: path, fork tick t_f, class, label, first-divergence tick and
stage, the intervention as `do(factor := value)` with unit, and its timeline block index. `PacketSource` gains
`forks()` and `forkFrame(fork, tick)`:

- for tick < t_f and a block with a prefix reference: the parent's frame at that tick (the prefix is the
  parent's, by reference; no bytes are copied);
- for tick ≥ t_f: the fork block's frame at index (tick − t_f) ÷ stride, with named ticks found by lookup;
- for a fork without a prefix (a structural or design-parameter intervention, which starts from the authored
  initial condition): the fork block's own frame at every tick.

A fork whose block fails digest verification is listed as unavailable with the reason; other forks still play.

**2. Fork selector.** A list of forks with class, label and intervention text; the null fork and the placebo are
always listed first and marked as controls. Selecting one or more forks (at most four drawn at once, DESIGN, for
legibility; all remain reachable) enables their ghosts.

**3. Ghost playback.** The ghost overlay draws each selected fork's bodies translucent over the parent from the
fork tick, and nothing extra before it. A timeline marker sits at the fork tick and another at the first
different event, labelled with tick and stage. A structural fork is drawn from tick zero as a second run and
labelled "re-run from the episode start (no shared prefix)". Playback uses stored frames only.

**4. Deviation readout and the null-fork check.** For the selected fork and each body, the page shows the
distance between the fork's and the parent's stored translations at the drawn tick, computed in double
precision from the anchored values (8 m × cell difference + offset difference). On load, for every continuation
fork marked as the null fork, the page compares the fork block's bytes with the parent's bytes over the common
ticks and shows one of two lines in the fork list: "null fork: bit-equal to parent over <n> frames" or "null
fork DIFFERS at tick <t>, body <i>: this record is unsound; nothing below should be read as attribution". The
second line is styled as an alarm and disables nothing: the reader sees everything, with the warning.

**5. Tables panel.** Three tables rendered from the tables block, with no computed column:

| Table | Columns, as stored |
|---|---|
| Forks | Path, class (continuation; exogenous intervention; contact-affecting intervention; information intervention; structural or design-parameter intervention), label, fork tick, earliest valid tick, the checkpoint fields that forced it |
| Contrasts | Intervention, replicates, rescue rate, placebo flip rate ρ₀, contrast (rescue rate minus ρ₀), flip rate under perturbation at 10⁻¹² and at 10⁻⁷ |
| Labels | The attribution labels with their standing |

Every cell is a text node holding the stored string. A header line above the contrasts table reads
"Attributions are Estimated. A contrast is a difference of rates between forks of this run under one
intervention; it is not an established cause, and not a statement about the physical robot." Clicking a
contrast row selects the fork it describes.

**6. In-page probe on forks.** The probe on a ghost element returns the fork's channel, unit, world address
(the fork path) and tick with its stored integer, and beside it the parent's value at the same tick and element,
so the two stored numbers can be compared without leaving the page.

**7. Packets without forks.** The selector and the tables panel are hidden; a line states "this packet holds one
world". A parent-only packet from the second milestone plays unchanged.

**8. Byte budget.** Fork reading, the selector and the tables panel are plain DOM and typed-array code; their
size is recorded in the bundle's per-module table and counts against the page's 600,000 bytes.

## Acceptance criteria

- [ ] A packet with a parent and 16 forks opens offline; all 17 timelines are selectable and play.
- [ ] For a non-structural fork the frame before the fork tick is the parent's frame object (by reference); from
      the fork tick on it comes from the fork block.
- [ ] The null fork line reads "bit-equal" on the fixtures; on a packet with one altered null-fork byte it shows
      the alarm with the right tick and body.
- [ ] The deviation readout for the null fork is exactly 0 at every frame; for an intervention fork it is 0
      before the first different event and matches `telemetry.divergence`'s first tick.
- [ ] The tables panel's cells equal the tables block strings byte for byte; no cell is computed in the page.
- [ ] The probe on a ghost returns the fork's stored value and the parent's, each equal to `telemetry.query`.
- [ ] A fork whose block fails verification is shown unavailable while the others play.

## Test plan

### Unit tests
`viewer/tests/packet_forks.test.mjs` (pinned headless browser; packets from the real writer with real forks):
- `prefix_by_reference`: `forkFrame(f, t)` for t below the fork tick is identical (same object) to
  `frame(t)`.
- `fork_frame_index`: fork at tick 90, stride 1: tick 120 is index 30 of the fork block.
- `structural_fork_from_zero`.
- `null_fork_bit_equal_line`; `null_fork_alarm_on_altered_byte` (tick and body reported correctly).
- `deviation_zero_until_first_divergence`: for a fork with first divergence at tick 97, deviations at ticks 90
  to 96 are exactly 0 and at 97 at least one body is non-zero.
- `deviation_anchored`: parent cell 3 offset 3.9 against fork cell 4 offset −3.9 reads 0.2 m.
- `tables_are_verbatim`: every cell's text equals the block's string; a contrast stored as "0.90625" is shown as
  "0.90625".
- `no_computed_cells`: static check that the tables module contains no arithmetic on cell values.
- `selector_lists_controls_first`.
- `unverified_fork_isolated`.
- `parent_only_packet_hides_fork_ui`.

### End-to-end script and logging
`scripts/e2e/replay_packet_gate.sh` (N32b-43), steps `ghost-*`: open each fixture's 16-fork packet headless;
select the null fork and read the equality line; step through an intervention fork and record deviations per
tick; read the tables panel's cells; probe ten ghost elements. NDJSON lines per the shared helper: `ts`,
`script`, `bead`, `step`, `event`, command, exit code, wall time, the export envelope's `evidence` block,
timelines playable against 17, maximum null-fork deviation against 0, first non-zero deviation tick against the
header's first-divergence tick, table cells equal against total, probes equal against 10, and on failure the
first differing cell or frame.

### Known answers and negative controls
- Known answer: a null fork drawn as a ghost coincides with its parent: the rows are bit-equal, so the deviation
  is exactly zero in every frame.
- Known answer: rescue 60 of 64 with placebo flips 2 of 64 is stored and shown as rescue rate 0.9375, ρ₀ =
  0.03125, contrast 0.90625.
- Negative control: a page that draws the fork's rows before the fork tick from the fork block index (reading
  garbage or the wrong ticks) fails `prefix_by_reference`.
- Negative control: a page that recomputes the contrast from the rates and prints its own rounding fails
  `tables_are_verbatim` and `no_computed_cells`.
- Negative control: a page that hides the null-fork alarm when the difference is below a tolerance; the
  altered-byte test fails it (the check is bit equality, not closeness).

## Considerations

- Showing sixteen ghosts at once is unreadable; the limit of four drawn at a time is a display choice and does
  not hide data.
- The alarm for a differing null fork is deliberately loud and deliberately non-blocking: a reviewer must be
  able to inspect a broken record, and must not be able to miss that it is broken.
- If the packet's kill gate fires, this code is removed with the packet; the ghost overlay itself stays, because
  the live viewer uses it.
- Wording beside attributions is fixed text reviewed with the debugging subsystem's refusal that an attribution
  must not be cited as an established cause or as a cause in the physical robot.
