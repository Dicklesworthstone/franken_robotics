## Background

The offline replay packet of FrankenRobotics is a single HTML file, written by `telemetry.export-html`, that
replays a recorded world and up to 16 counterfactual forks with overlays and tables, makes no network request,
and is at most 8 MiB by default. It is a view over existing records: it computes nothing and contains no
stepping code. Its acceptance gate is GATE-TETHER-16 (claim kind: Known answer; third milestone; TARGET):

> For the docking fixture and the split-grip fixture, each with a parent and 16 forks: the file is at most
> 8,388,608 bytes; it opens and plays from a local file with the network disabled in two pinned browsers under a
> headless driver; two exports are byte-identical; every block digest equals the source's; 100 probe points per
> packet equal `telemetry.query` within channel quantization; the null-fork deviation is zero; the over-cap
> request is refused with its size table.

This bead measures the gate. Its seven clauses test seven different promises: honesty about size, real
self-containment, reproducible export, fidelity to the source record, fidelity of what a reader probes, the
soundness check of counterfactuals, and the refusal to truncate. The gate's kill gate (KILL-REPLAYPACK, decided
in N32b-32 from this bead's record) fires if the gate fails after one repair cycle or the page cannot be held
to its byte budget.

The two fixtures are the project's registered small problems: a loaded cart crossing a 12 mm door sill and
docking (six moving bodies: chassis, payload and four wheels; the sill is scene) and the reference quadruped (13
bodies) climbing a ramp onto a landing with a low-grip strip. Both have failing conditions by construction, so
failing runs and their forks are available without search.

## Scope

In: building the two 16-fork packets from real runs; the seven clause measurements; the browser lane; the
over-cap request; `scripts/e2e/replay_packet_gate.sh`; the gate's measurement record.
Out: the writer and the page (N32b-41, N32b-40, N32b-42, N32b-13); the kill decision (N32b-32).

## Technical approach

**Setup per fixture.** (1) `frob sim run` under a profile of determinism class D2 on `batch-cpu` (so that forks
are licensed and the lane needs no GPU), in a condition that fails (fixture 1: design A at friction 0.60, sharp
lip; fixture 2: the narrow sole with the strip offset toward the strip). (2) From the failing world: one null
fork and one placebo fork (`frob run fork`), and fourteen intervention forks by `frob autopsy intervene` (for
fixture 1: lip friction to 0.8; payload offset to +0.04 m; current limit raised; lip filleted; and replicates;
for fixture 2: strip friction to its dry value; payload shift; and replicates), then `frob autopsy attribute`
for the contrast table. (3) Confirm the build's fork harness gates are recorded (otherwise the lane stops with
`not run: fork content not licensed for this build`, which is not a pass).

**Clause measurements.**

| # | Clause | How it is measured | Threshold |
|---|---|---|---|
| 1 | Size | `frob telemetry export-html <run> --world <w> --forks <16 paths> --window 3s --fps 50 --overlay contact-cones,energy,actuator --out p.html --json`; file length from the file system and from the envelope | At most 8,388,608 bytes; the two figures equal |
| 2 | Opens and plays offline in two pinned browsers | Each browser is launched headless by the driver with networking disabled at the browser level and at the host level (no route); the file is opened by `file://` path; the page's test entry reports `ready`; 150 frames are stepped; the driver's network log and console error log are read | Ready in both; 150 frames stepped; 0 network requests; 0 console errors |
| 3 | Byte identity | A second export with the same options into another path; `cmp` | Identical |
| 4 | Block digests equal the source's | `frob telemetry export-html --check p.html --json` | Every block `match`, `source: present` |
| 5 | Probes | 100 probe points per packet (parent and ghost elements across the exported overlays, from a stored plan with pixel, tick and expected element kind); the page's `probe` against `frob telemetry query` for the same channel, world or fork path, tick and element | 100 of 100 stored integers equal |
| 6 | Null-fork deviation | The page's null-fork line and the per-frame deviation readout; independently, a byte comparison of the null fork's block with the parent's rows by the conformance helper | Exactly 0 in every frame; bit-equal |
| 7 | Over-cap refusal | A request constructed to exceed the cap: the window and frame rate raised until the pre-write bound is 6,200,000 bytes of rows or more (for 13 bodies and 17 timelines: 585 frames give 48 · 13 · 585 · 17 = 6,205,680) | Exit 3; the refusal carries the size table with the encoded total and the three reductions; no output file exists |

Expected sizes, used as cross-checks on clause 1: the quadruped packet's timeline bound is 48 · 13 · 150 · 17 =
1,591,200 bytes (2,121,600 encoded); the cart's, with 6 bodies, 48 · 6 · 150 · 17 = 734,400 (979,200 encoded);
the real files are smaller than bound + overlay columns + tables + page because fork prefixes are shared, and
the script reports both the bound and the actual size.

**Browser lane.** DESIGN: two engine families so that an accident of one implementation does not decide the
gate; versions and binary hashes pinned in `tools/browsers.lock`; the driver speaks the browsers' standard
automation protocols and is development-only tooling. Rendering uses each browser's default path for a local
file (WebGL 2; the page must not require WebGPU, which is exposed only in secure contexts, and whether a file
opened from disk is one is left to the browser). A software rasterizer is forced so the lane runs on a host
without a GPU. No frame-rate figure is measured or claimed.

**Measurement record.** `target/gates/GATE-TETHER-16.json`: per fixture and clause the measured value and
threshold; browser names, versions and hashes; the exporter and page bundle digests; commit, host fingerprint,
seeds; the repair-cycle counter (from the history of this record); the negative controls caught.

## Acceptance criteria

- [ ] Both fixtures' packets satisfy all seven clauses; the record holds measured values, not targets.
- [ ] The packets were built from real runs and forks (their chunk chain digests are in the header and
      `--check` matches the store).
- [ ] Networking was disabled at two levels and the request log is empty in both browsers.
- [ ] The over-cap refusal prints the encoded size, and each of its three reductions, when applied, yields a
      file under the cap.
- [ ] The negative controls below each turn the named clause red in the same run.
- [ ] The gate register row is filled by a session that did not build the packet; KILL-REPLAYPACK's decision
      bead can read the record.

## Test plan

### Unit tests
`crates/frob-conformance/tests/replay_gate_plan.rs`:
- `probe_plan_well_formed`: 100 points per fixture, each naming an exported overlay, a tick inside the window,
  and a parent or fork path present in the packet.
- `over_cap_request_arithmetic`: 585 frames × 13 bodies × 17 timelines × 48 = 6,205,680 ≥ 6,200,000; encoded
  ⌈6,205,680 ÷ 3⌉ × 4 = 8,274,240; with a 600,000-byte page 8,874,240 > 8,388,608.
- `expected_bounds`: 1,591,200 and 734,400.
- `browser_lock_complete`: two entries with version and hash.
- `record_schema`: the measurement record validates and its repair counter increments only when the page or
  writer digest changes between failing and passing runs.

### End-to-end script and logging
`scripts/e2e/replay_packet_gate.sh`, step groups `page-*` (N32b-40), `forks-*` (N32b-41), `ghost-*` (N32b-42),
then per fixture `size`, `offline-<browser>`, `identity`, `check`, `probe`, `null-fork`, `over-cap`. Log:
`target/e2e-logs/replay_packet_gate/<utc-timestamp>.ndjson` and a transcript. Every line has `ts`, `script`,
`bead`, `step`, `event` (`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact command line or driver
call, exit code, wall time, the export envelope's `evidence` block (claim, class, tier, determinism,
identities, seed), measured values with units and thresholds (file bytes against 8,388,608; requests against 0;
console errors against 0; frames stepped against 150; blocks matched against the block count; probes equal
against 100; null-fork deviation against 0; the refusal's printed size), digests where state is compared (the
two exports; each block), and on failure the first differing value with the packet's path, the browser's
console log and a pixel dump. The `summary` line counts assertions and names GATE-TETHER-16. Fixtures are
synthetic; no private-scene data can appear.

### Known answers and negative controls
- Known answers: the sizes above; the over-cap arithmetic; a null fork coincides with its parent exactly; a
  probe value equals the telemetry channel within its quantization (stored integers equal).
- Negative control 1 (clause 1 and 7): a writer that budgets by binary payload admits the over-cap request.
- Negative control 2 (clause 2): a page that loads a font from a public address: the request log is non-empty.
- Negative control 3 (clause 3): an exporter that stamps the wall-clock time: exports differ.
- Negative control 4 (clause 4): a packet with one flipped byte in a fork block: `--check` names the block.
- Negative control 5 (clause 5): an overlay that shows a recomputed value: stored integers differ.
- Negative control 6 (clause 6): a null fork made with a perturbation of one unit in the last place: deviation
  is non-zero and the equality line is the alarm.
- Determinism lanes: the whole script twice on one machine gives the same packet digests; Linux and macOS
  produce byte-identical packets from the same store; both browsers on each platform.

## Considerations

- The gate needs the fork harness gates recorded first; it cannot pass on a build that has not earned fork
  content, by design.
- "Opens from a local file" is the hard clause across browsers: local files have restricted origins, and
  features differ. The page therefore uses only inline script, typed arrays, the built-in Base64 decoder and
  WebGL 2, and the lane is the detector for anything else creeping in.
- One repair cycle is allowed before the kill gate fires; the record's history counts cycles, so the allowance
  cannot be spent twice.
- The 15 MB statement made with the viewer's overlay table is the absolute ceiling for any exported replay; the
  gate is measured at the packet format's 8 MiB default.
