## Background

The viewer of FrankenRobotics is a Three.js r186 web page under `viewer/` (N32b-10) that draws a recorded episode
from immutable snapshots. It reads them through one interface, `SnapshotSource`, with two shipped
implementations: the blocks embedded in an offline replay packet (`PacketSource`, N32b-40, second milestone) and
**live mode**, the subject of this bead: a page opened beside a running daemon (`frobd`) that reads the same
snapshot through the read verbs of the record, called over the daemon's loopback MCP endpoint. Live mode is how a
person watches a run while it is still publishing, and it is what the viewer conformance gate (N32b-14) uses to
compare an overlay value under a pixel with the telemetry channel on a live run.

This work was split from N32b-10 because it cannot land at the second milestone: a browser page cannot use the
standard-input transport, and the loopback HTTP transport that carries a session's bearer token is N32a-27, a
third-milestone bead. The page itself, its snapshot model and the conversion `snapshotFromEnvelopes` stay in
N32b-10; this bead adds only the live source and what comes with it.

Two rules of the viewer bind this bead. (1) *The viewer never feeds anything back to physics*: turning a live
viewer on or off changes no physics digest (invariant INV-TETHER-12). (2) *The viewer is an ordinary client*
(decision ADR-TETHER-10): it calls registered `read` verbs under a session token, exactly as an agent would, so it
is no private path to state.

## Scope

In: `VerbSource` (`viewer/src/source.js`); following a run that is still publishing; `attach` and `detach`; how
the endpoint and token reach the page; the live variant of the page bundle and its content security policy; the
page's behaviour on refusals and on a lost daemon; the noninterference check of a live viewer;
`scripts/e2e/viewer_live.sh`.
Out: the page, the snapshot model, `snapshotFromEnvelopes`, picking and the test entry (N32b-10); the packet
source (N32b-40); the plain bundle and its byte budgets (N32b-13, whose `pack.mjs` this bead extends by one
variant flag); the MCP transports and the bearer-token binding (N32a-27); the verbs themselves (`run.show` and
`artifact.read`, BD-097; `telemetry.query`, N24a-36; `telemetry.stills`, BD-191); the overlay conformance gate
(N32b-14).

## Technical approach

**1. `VerbSource`.** Implements `header()`, `shapes()`, `frame(tick)`, `column(name, tickRange)` and
`nearestStoredTick(tick)` by calling the MCP tools `run_show`, `telemetry_query`, `artifact_read` (by digest and
byte range) and `telemetry_stills` (thumbnails only) over streamable HTTP on loopback, and passing the envelopes
to `snapshotFromEnvelopes` (N32b-10). Every tool it may call is `read` in the registry; the list is a constant
of the module and a test compares it with the registry.

**2. Following a publishing run.** `telemetry.query` is paged against the committed frontier the first
`run.show` returned; the source follows cursors and never asks beyond that frontier. To see newer ticks it calls
`run.show` again no sooner than the envelope's `poll_after_ms` (and at least 100 ms apart, DESIGN), takes the new
frontier, and reads only the new chunk range. A snapshot built for one frontier is never mutated: a newer frontier
yields a new frozen snapshot that shares the older one's frames.

**3. Attach and detach.** `attach(run)` starts reading through the source and drawing the newest stored tick;
`detach()` stops all requests and keeps the last snapshot on screen marked with its frontier. Both are read-side
only. The test entry gains `attach` and `detach` so that the noninterference check can toggle the viewer during a
run.

**4. Endpoint and token.** The live page is opened as `viewer/dist/live.html#endpoint=http://127.0.0.1:<port>/mcp&token=<tk>`:
the fragment is never sent to any server. The token goes only into the `Authorization: Bearer` header of each
request (the only place N32a-27's HTTP transport accepts it), never into a URL, a log line, the page's DOM or its
dumps. It carries the read scopes of the record's clusters; a private scene needs the private read scope, exactly
as for any verb.

**5. The live bundle.** `node viewer/build/pack.mjs --variant live` produces `viewer/dist/live.html`: the same
modules as the plain bundle plus `VerbSource`, with one difference in the content security policy,
`connect-src http://127.0.0.1:* http://[::1]:*`. The plain bundle that packets embed keeps `connect-src 'none'`
and contains no `VerbSource`; the variant is recorded in each bundle's manifest, and a check refuses a packet
build that embeds the live variant.

**6. Origin (DESIGN, fail-closed default).** A page opened from disk has the opaque origin `null`. The loopback
HTTP host of N32a-27 must answer such a page's requests without weakening its origin checks (it authenticates by
bearer token, sends no cookies, and must not answer a page that presents no token). If that cannot be done without
weakening those checks, live mode is not shipped, the live bundle is not built, and the viewer opens packets only;
every overlay still works because overlays depend on snapshots, not on the source. In that case N32b-14 reads its
runs through replay packets and its noninterference step polls the same verbs at the same rate from the test
driver; both scripts log `live_mode: not shipped`, never a pass of the live steps.

**7. Refusals and a lost daemon.** A tool answering `FROB-REF-720` shows the code and the missing scope from the
envelope's `required`; `FROB-REF-723` (token invalid or expired) shows the code and the repair `frob session open`;
an HTTP unauthorized response shows "no token accepted"; a lost connection keeps the last snapshot marked stale
with its frontier and retries at most once a second. Nothing is ever drawn from a refused envelope.

## Acceptance criteria

- [ ] On a live `batch-cpu` run of the reference quadruped, the live page draws the newest committed tick, and the
      drawn poses equal `telemetry.query` for that tick, body for body.
- [ ] The tools called by `VerbSource` are a subset of {`run_show`, `telemetry_query`, `artifact_read`,
      `telemetry_stills`} (from the daemon's request log), and none is of a kind other than `read`.
- [ ] No request asks beyond the frontier the last `run.show` returned; no snapshot changes after it is built.
- [ ] A run with the live page attached and polling every 100 ms has the same digest chain as the same run from
      the same seed with nothing attached (`frob telemetry divergence` reports none), on `batch-cpu` and on the
      referee tier.
- [ ] The token appears in no request URL, no log line and no dump; a token without the record's read scope shows
      `FROB-REF-720` with the scope.
- [ ] The live bundle's `connect-src` names only loopback origins; the plain bundle is unchanged, and a packet
      build that embeds the live variant is refused.
- [ ] Under the fail-closed default of section 6, the live steps are reported `not run` with the reason.
- [ ] `scripts/e2e/viewer_live.sh` passes with the logging below.

## Test plan

### Unit tests
`viewer/tests/verb_source.test.mjs` (N32b-44's launcher, networking limited to loopback, against a real `frobd`
on a temporary state root; no mocks):
- `verb_source_reads_only`: the tool list equals the module constant, and each is `read` in the registry.
- `frontier_pinned_paging`: with a chunk committed between page one and page two, page two still reads the old
  frontier and no row repeats or is skipped (the property of KA-764, seen from the page).
- `new_frontier_new_snapshot`: after a second `run.show` with a later frontier, the old snapshot object is
  unchanged and frozen.
- `poll_respects_poll_after_ms`: an envelope saying 2,000 ms gives the next `run.show` at 2,000 ms, not 100.
- `token_only_in_header`: the request log holds the token in no URL; the page's DOM and `state()` dump hold none.
- `refusal_720_shown_with_scope`; `refusal_723_shown_with_repair`; `unauthorized_shown`.
- `detach_stops_requests`: after `detach()`, zero requests over 5 s.
- `lost_daemon_marks_stale`: the daemon is stopped; the last snapshot stays, marked stale with its frontier.
`viewer/tests/pack.test.mjs` (additions): `live_variant_csp_loopback_only`; `plain_variant_has_no_verb_source`;
`packet_refuses_live_variant`.

### End-to-end script and logging
`scripts/e2e/viewer_live.sh` (header `bead=N32bp1-01 milestone=M3 labels=tether,chronicle`; rerun by N32b-14 as
steps `live-*`): on a temporary state root, `frobd --mcp` on loopback; `frob session open --scopes
run:read,telemetry:read,artifact:read --key vl-1 --json`; `node viewer/build/pack.mjs --variant live`; a
`frob sim run` of the reference quadruped on a plane (`--tier batch-cpu --seed 7 --key vl-run-1`) while the live
page is attached in both pinned browsers and polls every 100 ms; detach and re-attach once mid-run; then the same
run from the same seed with nothing attached (`--key vl-run-2`) and `frob telemetry divergence` between the two;
the refusal steps with a token lacking `telemetry:read` and with an expired token. It sources the STD-E2E helper
and writes `target/e2e-logs/viewer_live/<utc>.ndjson` and a transcript; each line has `ts`, `script`, `bead`,
`step`, `event`, the exact command line with the token redacted to its `tk:` identifier, exit code, wall time, the
run envelope's `evidence` block, the browser name, version and hash, frontiers read, requests issued and their
tools, poses equal against bodies × ticks checked, requests beyond the frontier against 0, the two digest chains
and the divergence report, the refusal codes against expected, and on failure the first differing tick or body or
the offending request with the paths of the state-root copy and the page dump; then a `summary` naming
INV-TETHER-12.

### Known answers and negative controls
- Known answer: presentation noninterference: attaching, polling and detaching the live page leaves every physics
  digest unchanged.
- Negative control: a source that asks `telemetry.query` without a cursor at each poll (offset paging) repeats a
  row when a chunk commits between pages; `frontier_pinned_paging` must fail.
- Negative control: a page that puts the token in the query string; `token_only_in_header` must fail.
- Negative control: a source that calls `sim.replay` to fill a gap (a verb that runs physics); the read-only check
  must fail.
- Negative control: a live page whose polling advances a keyed noise counter in the daemon (planted); the digest
  chains differ and the noninterference assertion must fail.
- Determinism lanes: the script twice on one machine; both pinned browsers; Linux and macOS.

## Considerations

- Origin is the open point (owner: Tether lead; fail-closed default in section 6: no live mode). A possible
  alternative is for the loopback host to serve `live.html` itself at a fixed path, which makes the page
  same-origin with the endpoint; that would be a change to N32a-27 and is not assumed here.
- Load on the daemon: one live page polls `run.show` at most every 100 ms and reads only new chunk ranges; the
  dashboard (N32b-06) and a live viewer together must stay inside the read-verb rate limits N32a-27 configures.
- Privacy: the page shows only what the token may read; objects of a private scene are absent without the
  private read scope. Nothing is written to disk by the page.
- Large scenes: meshes are read by byte range; collision primitives are drawn until the visual mesh arrives.
