## Background

FrankenRobotics is reached through verbs served by the command line `frob`, the daemon `frobd` and the MCP server
`frob-mcp`. An agent works inside a **session**: a row in the daemon's ledger with a capability token, budgets and
a namespace. Several acceptance tests judge what an agent did, not what it says it did: how many simulations it
ran before naming a cause (the agent diagnosis battery, GATE-TETHER-15), how many serial turns an accepted design
cost (GATE-TETHER-01, GATE-TETHER-13), whether a clean client reaches the same diagnosis from the receipts alone.
The debugging subsystem builds its replayable transcript of a session (`frob.autopsy.transcript/1`) from the same
source. All of them need one record that the client cannot shape: for every verb call of a session, what was
asked (as resolved), under which idempotency key, and what was answered. The specification assigns that capture
to the verb crate.

This bead is that capture and nothing else. It was first drafted inside the bead that builds the agent guide and
the fresh-agent studio test (BD-313), which waits on the whole M3 surface. The Autopsy transcript (BD-284) and
the transcript counts of the diagnosis battery (N32b-38) need the capture and must not wait for the guide, so it
is its own bead and all three depend on it.

Terms. *Resolved request*: the request after every mutable name has been replaced by an immutable identifier and
defaults have been filled; its canonical JSON has a BLAKE3 digest, which for keyed verbs is the digest the
idempotency binding stores. *Envelope*: the single JSON object `frob.envelope/1` a verb returns. *Surface*: the
adapter that received the call (`cli`, `mcp`, or `rpc` for a direct socket client).

DESIGN decisions. (1) The daemon writes the record, in dispatch; the client never does. Rejected: client-side
logging (the client is the thing under test) and reconstruction from job records (reads and refusals create no
job). (2) Rows hold identifiers and digests, never bodies: a transcript can then be shown to a scorer without
exposing designs or scenes, and stays small. (3) The digest of an answer excludes operational fields, so that the
same question answered twice has the same digest.

## Scope

In: the row and its schema; when a row is opened and closed and by whom; which calls have a row; the stable
envelope digest and the result digest; storage of the resolved request by digest; the read surface `session.show
--transcript` with its access rule and pagination; the named scope `session:audit` and the `audit` action of
`session.show` that it guards; the session option `capture`; retention; tests. Out: the
derived counts (simulations, turns) and the clean-client replayer (N32b-38); the Autopsy transcript built from
these rows (BD-284); the agent guide, the worked sessions, the scripted tasks and their scorer (BD-313, which
consumes this record); the session verbs themselves (N32b-04); the idempotency binding (N32a-09).

## Technical approach

**1. The row** (ledger table `session_call`; one element of a `frob.session-transcript/1` page).

| Field | Type | Content |
|---|---|---|
| `seq` | `int53` | Per session, from 1, strictly increasing, no gaps; allocated by the daemon |
| `surface` | `cli`, `mcp`, `rpc` | The adapter that received the call |
| `verb`, `action`, `kind` | registry names | `action` only for a verb with two kinds |
| `request_digest` | hex | BLAKE3 of the canonical resolved request. For a keyed verb it equals the idempotency binding's digest |
| `resolved` | bool | `false` when the call was refused before resolution (schema failure, missing scope); the digest is then that of the arguments as received |
| `idempotency_key` | string or null | As supplied. A key is not a secret and grants nothing |
| `job` | job identifier or null | The job created or found |
| `idempotent_replay` | bool | The answer was the stored answer to an earlier request with the same key |
| `ok`, `exit`, `refusal_code` | bool, integer, code or null | From the envelope |
| `envelope_digest` | hex | BLAKE3 of the stable envelope (below) |
| `result_digest` | hex or null | BLAKE3 of the canonical `result`; null when the envelope has none |
| `cost`, `budget_after` | objects | The envelope's `cost` and `budget` blocks |
| `focus` | task-cluster name or null | The MCP focus when the call arrived; null on other surfaces |
| `turn` | string or null | A harness-supplied turn marker (`FROB_TURN` in the CLI's environment; the request metadata key `frob/turn` on MCP), accepted only if it matches `[A-Za-z0-9_.-]{1,64}` |
| `arrival_ns`, `delivery_ns` | `u64str` | Daemon wall clock at arrival and at delivery. Operational data: never part of a result or an evidence record |
| `delivery` | `delivered`, `not-recorded` | `not-recorded` when the row was opened and never closed |
| `closed_by` | `daemon`, `adapter` | Who reported the answer (point 3) |

The *stable envelope* is the envelope without `cost`, `budget`, `idempotent_replay`, the `job` block and the
`executor` warning; its digest is over canonical JSON (sorted keys, no insignificant whitespace, NFC strings,
integers above 2⁵³ as strings). Nothing else is removed: a changed `bound`, `evidence`, `result` or `refusal`
changes the digest.

**2. Which calls have a row.** Every call that presents a valid token of an open session and names a registry
verb: results, findings, deferred answers (exit 8) and refusals of every class, including `FROB-REF-802` and
`-720`. No row: an unknown verb (`FROB-REF-801` on the CLI; the library's unknown-tool error on MCP), an invalid
or expired token (`-723`: there is no session to record under), and calls made with no daemon as the built-in
principal `local`. `job.wait` and `job.status` are calls like any other. A verb that submits child jobs records
one row for the call; the children appear through the job's receipt, not as rows.

**3. Opening and closing.** A token can only be verified by the daemon, so every session call reaches the
daemon's pipeline at least up to authorization. There the daemon allocates `seq` and writes the open row
(`surface`, `verb`, the digest of the arguments, `arrival_ns`). What follows depends on where the verb executes:

- *The daemon executes* (a job, the socket back end, `frobd --mcp`): the daemon fills and closes the row in the
  ledger transaction that finalizes the call; for a keyed verb the admission transaction writes `request_digest`,
  `idempotency_key` and `job` into the open row as part of the binding, so that a job admitted for a call whose
  client then died is still attached to its row. `closed_by: daemon`.
- *The adapter executes in process* (a CPU-tier verb): the daemon returns the grant with `seq`; the adapter runs
  the verb and sends a close frame of the daemon protocol `frob.rpc/1` carrying the digests, exit and cost;
  `closed_by: adapter`.

A session opened with `capture: "strict"` (a new optional input of `session.open`, CLI `--capture
strict|adapter`, default `adapter`, which this bead serves in VERBS-session's row of that verb; a derived
session inherits its parent's mode) gets no
in-process grant: the daemon executes every verb of that session, so every row is `closed_by: daemon`. Gate
harnesses open their arms in strict mode. If the open row cannot be written the verb is not executed: no session
call goes unrecorded. If a client dies before the close, the row stays open and reads as `delivery:
not-recorded` (INV-TETHER-10: killing `frob`, `frob-mcp` or `frob-tui` at any instant leaves the ledger
consistent and every admitted job discoverable by its key).

**4. The resolved request by digest.** When a row gains its resolved digest, the canonical resolved request is
stored as a content-addressed artifact `frob.resolved-request/1` whose address is `request_digest`, in the same
transaction. Fields marked `x-frob-secret` in the verb's schema are removed before storage; text of untrusted
origin stays inside the schema fields that carry the untrusted mark. The artifact is pinned by the session row and
kept as long as the session's job records; it inherits the strictest privacy mark of the objects it names, and
reading it (`artifact.read` by digest) needs what reading the transcript needs, plus `private:read` where marked.

**5. Reading.** `session.show --transcript [--of-session <id>] [--limit n] [--cursor c] [--follow]` returns
`frob.session-transcript/1`: `{ session, rows: […], cursor, frontier }`. The foreign session is the input
`of_session` (DESIGN name), not `session`: `--session` is the process option that carries the caller's own session
identifier, which N32b-01 refuses with `FROB-REF-802` when it differs from the token's session, so a verb input of
that name would be refused before the `audit` action is chosen, and NJL-01's lint `common-property-shadowed`
fails the build on it. `limit`, `cursor` and `follow` are not inputs of this bead: the generator adds them to a
`paginated` row, and `session.show` is one (N32b-04); the transcript is a second listing of the same paged
form. Pages are pinned to the session's last
closed `seq` at the first page, ordered by `seq`, with the authenticated cursor `frob.cursor/1`; rows added
later are visible to a new query or under `follow`. Access: a session reads its own transcript and those of
sessions derived from it; any other session's needs the scope `session:audit` (DESIGN name), which is owner-held
and not mintable by an agent through `session.open`; otherwise `FROB-REF-720`, exit 5. The token never appears
in a row, an artifact or a log.

**5a. `session:audit` as a named scope** (under the named-scope rule of N32bx-02, whose six lints it passes).
Catalogue row in `registries/scopes.toml`: `scope = "session:audit"`, `kind = "read"`, `grants =
["session.show#audit"]`, `defined_in = "§32.23"`, `irreversible = false`, `owner_only = true` (N32b-01's flag:
`session.open` refuses to mint it for an agent principal with `FROB-REF-723`, and it cannot be derived), `since =
"M3"`, `purpose = "Read the call transcript of a session that is neither yours nor derived from yours."`.
Registry form: `session.show` gains `actions = [{ name = "audit", kind = "read", capabilities =
["session:audit"] }]`; the dispatcher selects `audit` when `--transcript --of-session <id>` names a session that is
neither the caller's nor one of its descendants (a ledger lookup of the session's ancestry, done in dispatch
before the capability check, so the check still precedes the handler). The default action keeps its own
capabilities (none for one's own session, N32b-04). The row of `session.show` is VERBS-session's (a dependency),
which now carries the `audit` action in exactly this form; this bead serves it and enters no second copy.

**6. Cost and retention.** One ledger write at open and one at close, coalesced into one when the daemon
executes a call that finishes inside its own transaction. TARGET: capture adds at most 1 ms to a call at the
95th percentile. A row is about 400 bytes; rows are kept as long as the session row.

Files: `crates/frob-verbs/src/capture/{row,digest,store}.rs`; the open and close steps in the daemon's dispatch
(`frob-cli`); `schemas/frob.session-transcript.1.json`, `schemas/frob.resolved-request.1.json`. Determinism:
digests are exact (class D0); instants are operational and excluded from every digest.

## Acceptance criteria

- [ ] A scripted session of 12 calls over the CLI and MCP, 3 of them refused, yields rows with `seq` 1 to 12, each call exactly once, in arrival order.
- [ ] Two adapters calling on one session concurrently (1,000 calls) produce `seq` 1 to 1,000 with no gap and no duplicate.
- [ ] For a keyed verb the row's `request_digest` equals the idempotency binding's digest; a second call with the same key has `idempotent_replay: true` and the same `job`.
- [ ] Re-issuing a recorded `read` call from its stored resolved request yields the recorded `envelope_digest`, after the mutable name it used has been moved.
- [ ] A client killed after admission and before delivery leaves a row with `delivery: not-recorded` whose `job` is the admitted job; 100 of 100 kills at random instants leave no row that is neither open nor closed.
- [ ] No token, no envelope body and no request body is stored in `session_call`; the stored resolved request contains no field marked secret.
- [ ] A session cannot read another principal's transcript (`session.show --transcript --of-session <id>`: `FROB-REF-720`, `required: "session:audit"`); a holder of `session:audit` can; a parent can read its derived session's; the input is `of_session`, and NJL-01's lint `common-property-shadowed` passes on the row.
- [ ] `session:audit` is a catalogue row with `owner_only = true` that passes the six named-scope lints; an agent's `session.open` naming it is refused with `FROB-REF-723`.
- [ ] In a `capture: "strict"` session every row is `closed_by: daemon`, including CPU-tier reads.
- [ ] Paging with a limit of 5 returns the rows at the pinned frontier, none skipped and none repeated, while new calls arrive.
- [ ] Measured capture overhead is recorded against the 1 ms target; `crates/frob-verbs/CONTRACT.md` documents the row, the stable envelope and the access rule.

## Test plan

### Unit tests

`cargo test -p frob-verbs capture` and `cargo test -p frob-cli --test session_capture` (the real daemon loop and
ledger in a temporary state root; no mocks):
- `one_row_per_dispatched_call`: 12 calls, 3 refused → 12 rows, sequence 1 to 12.
- `refusals_recorded`: an 802 row has `resolved: false`; a 720 row has `refusal_code` and no `job`; a 701 row has `resolved: true` and no `job`.
- `unknown_verb_has_no_row`; `invalid_token_has_no_row`; `daemonless_local_has_no_row`.
- `seq_gap_free_two_adapters` (property, seeds 0 to 99, on the deterministic runtime).
- `keyed_digest_equals_binding`; `replay_flag_same_job`.
- `stable_digest_ignores_operational_fields`: the same read twice with different wall times and budgets → equal `envelope_digest`; a changed `result` → different.
- `result_digest_null_on_refusal`.
- `resolved_request_survives_name_move`: call with the name `quad-a`, move the name, fetch by digest → the original content address.
- `resolved_request_secret_free`; `token_absent_everywhere` (byte search of the ledger, the store and logs).
- `open_row_after_kill`: kill the adapter at each await point between open and close.
- `strict_mode_all_daemon`; `adapter_mode_marks_adapter`.
- `access_own_child_audit`: own, derived, foreign without and with `session:audit`.
- `audit_scope_row`: kind `read`, grants `session.show#audit`, `owner_only = true`; `audit_not_mintable_by_agent`
  (723); `audit_action_selected_in_dispatch`: the handler entry counter is 0 on the refused foreign read.
- `pagination_pinned`: 12 rows, read with limit 5 from a `session:audit` holder (so the reads add no rows), 3 calls inserted between pages → pages concatenate to rows 1 to 12; a new query returns 15.
- `own_reads_lie_beyond_frontier`: a session paging its own transcript sees rows up to the frontier pinned at the first page; its reading calls are later rows and appear only in a new query.
- `turn_marker_pattern`: a marker with a space is refused with code 802; a valid one is stored.
- `row_schema_has_no_free_text`: every string property of the row schema has a pattern or an enumeration.

### End-to-end script and logging

`scripts/e2e/session_transcript.sh` (header: `bead=N32bx-01 milestone=M3 labels=tether,session seed=1
needs=cpu,frobd,mcp plants=adapter-seq,body-in-row,digest-with-wall`). Before `frobd` starts, STD-E2E's
`e2e_session grant` writes the grants (N32b-01 mints a root token only from a grant): `agent-a` (the scopes and
the 60 GPU-seconds of step 1), `agent-b` (no scope) and `owner` (`session:audit`, the owner's session as N32b-01's
open point on it defines it); root opens go through `e2e_session open` (no token in the call's environment, the
token kept out of every log and exported; `e2e_session use` switches), and every key is written with `e2e_key`:
(1) `e2e_session open st-1 --principal agent-a --scopes
design:read,design:write,sim:read,sim:run,telemetry:read,job:read,artifact:read --budget gpu_s=60` (the read
scopes the registry lists for `sim.estimate`, `telemetry.summary`, `job.find` and `artifact.read`, so that the
only refusals are the three planted ones; `session_show` of one's own session needs no scope, N32b-04); (2) six
CLI calls (`design check`, `sim estimate`, `sim run` with label `k1`, the same again with `k1` issued `--again`,
one with a misspelt parameter, `telemetry summary`) and six MCP calls through a `frob-mcp` started with the
session's token (`design_show`, an over-budget `sim_run` with label `k3`, an unscoped `study_plan`, `sim_run` with
label `k2` whose client is killed during the wait, `job_find` for `k2`, `session_show`); (3) `frob session show --transcript
--limit 5 --json` followed by its cursors, asserting 12 rows in order (the reading calls are rows 13 onward and
lie beyond the pinned frontier), exactly 3 with a `refusal_code` (802, 701, 720), exactly one replay, exactly one
`not-recorded` whose `job` equals the job `job_find` returned; (4) `frob
artifact read <request_digest>` for the `design check` row, re-issue it, compare the stable digest; (5) a second
session (`e2e_session open st-2 --principal agent-b`) tries to read the first one's transcript (`frob session
show --transcript --of-session <first> --json`) → `e2e_expect_refusal FROB-REF-720 5` with `required:
"session:audit"`; (5b) an agent's root open naming the owner-only scope, `e2e_expect_refusal FROB-REF-723 5 --
env -u FROB_SESSION_TOKEN frob --json session open --principal agent-b --scopes session:audit --key "$(e2e_key
st-3)"`, made with no token in its environment so that the 723 can only be the owner-only refusal and not the
refusal of a root open that presents a token; then the owner's session (`e2e_session open own --principal owner
--scopes session:audit`) reads the first session's transcript and gets the same rows; (6) the same script in a
`capture: "strict"` session (`e2e_session open st-4 --principal agent-a … --capture strict`), asserting
`closed_by` is `daemon` on every row. Logs go to
`target/e2e-logs/session_transcript/<utc>.ndjson` through the shared helper, with a transcript beside it: each
`cmd` with the token redacted, exit code and wall time, the envelope's `evidence` block, `assert` lines with
observed and expected row counts and digests, a `metric` line for capture overhead in ms against 1, the first
differing row on failure, and the `summary`. No request or envelope body is logged.

### Known answers and negative controls

- Known answer (exact): the 12-call script yields 12 rows, 3 refusals, 1 replay, 1 undelivered row.
- Negative controls: `adapter-seq` (the adapter assigns `seq`: the two-adapter property must find a duplicate);
  `body-in-row` (the row stores the envelope: the schema and byte-search checks must fail); `digest-with-wall`
  (the digest covers `cost`: the re-issue comparison must fail).
- Metamorphic: the same calls through the CLI and through MCP give equal `request_digest`, `envelope_digest` and
  `result_digest` row for row; only `surface` and `focus` differ.
- Invariant carried: INV-TETHER-10, as `open_row_after_kill` and the kill step of the script.
- Determinism lanes: digests identical twice on one machine, in debug and release, on both hosts.

## Considerations

- In `adapter` mode the answer's digests are reported by the adapter process. That is acceptable for an agent
  reviewing its own session and not for a gate; hence strict mode, which costs a protocol hop on every read.
- A transcript makes behaviour auditable to whoever may read it. `session:audit` is deliberately outside what an
  agent can mint.
- A resolved request can name private objects; it is never copied into a log, and its privacy mark travels with
  it. Idempotency keys are caller-chosen strings and may themselves carry meaning; they are length-capped and
  shown only to readers of the transcript.
- Turn markers are trusted only as a grouping hint; a harness that supplies none gets turns segmented by gaps in
  the instants, by the bead that counts them.
- If kill gate KILL-MCP fires and `frob-mcp` reaches verbs only through the daemon's socket, every MCP row is
  `closed_by: daemon` and nothing else changes.
