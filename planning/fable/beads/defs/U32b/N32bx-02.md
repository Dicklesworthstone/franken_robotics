## Background

Every agent of FrankenRobotics works in a session that holds a **capability token**: a statement, authenticated by
the daemon `frobd`, of what the session may read, spend and publish. Each verb's entry in `registries/verbs.toml`
lists the scopes it needs; the dispatcher compares them with the token before any handler runs and refuses a
missing one with `FROB-REF-720` (exit 5). The scopes that exist are a closed catalogue,
`registries/scopes.toml`: a verb entry that cites a scope outside it fails the build, and so does a catalogue
scope that no verb uses. The surface chapter lists the catalogue's content: `<cluster>:read`, `<cluster>:run`,
named spending scopes, `design:write`, `scene:import`, `ground:import`, `cert:write`, the export and private
scopes, `job:cancel`, and budgets.

One capability that the specification requires is not in that list. The calibration subsystem (Ground) issues
**reality bands**: calibrated intervals around a simulated metric, per calibrated cell. A calibration is retired
when a monitor fires, and can also be retired by hand: the registry row of the verb says `ground.band`: "issue or
refuse a reality band; cells, coverage accounting, monitor states; `--retire` needs a capability". The
specification names no scope for it. The Ground beads call it `ground:retire`: manual retirement produces the
reason `Manual` with the caller's text and session identity, turns the cell's status to `retired`, sends reports
that cited the band back to `reality: no-claim`, marks citing verdicts stale, and makes every later use of the
calibration a refusal (`FROB-REF-897`). There is no un-retire. `ground.band` is otherwise a `read` verb, and the
scope rules say a `read` verb needs only `:read` scopes, so the retire action cannot simply be added to the
entry's scope list.

DESIGN: `ground:retire` enters the catalogue as a **named admin scope**, beside `job:cancel`, and guards the one
action `retire` of `ground.band`. Rejected alternatives: `ground:admin` (a container for whatever admin actions the
cluster gains later; retirement is irreversible and reaches other namespaces' reports, so it gets least
privilege and a name of its own, and two Ground beads already cite the name); `ground:write` or `ground:import`
(write scopes are for creating objects in the caller's namespace; a session that may ingest a bench log should
not thereby be able to withdraw a calibration); a separate verb `ground.retire` (the registry is closed and the
specification registers the action under `ground.band`; one mechanism, one name).

Tier Solid. Crate `frob-verbs` (catalogue row, lints); the check itself is the token check that already exists.

## Technical approach

**1. The catalogue row** (`registries/scopes.toml`; fields beyond `scope`, `kind` and `grants` are DESIGN
additions that apply to every named scope).

```toml
[[scope]]
scope = "ground:retire"
kind = "admin"                         # read | spend | write | publish | private | admin | budget
grants = ["ground.band#retire"]        # <verb>#<action>: the action `retire` of the verb `ground.band`
defined_in = "§30.16"
irreversible = true                    # the guarded action cannot be undone
owner_only = false                     # N32b-01's flag on every catalogue row; true = owner-held, never minted for an agent
since = "M3"
purpose = "Retire a calibration by hand: its band is withdrawn and results that cited it go stale."
```

**2. The registry entry.** `ground.band` keeps `kind = "read"` and `capabilities = ["ground:read"]`. The retire
action is the entry form the registry already has for a verb with a guarded second action:

```toml
actions = [{ name = "retire", kind = "admin", capabilities = ["ground:read", "ground:retire"] }]
```

On the CLI the action is selected only with `--action` (NJL-01's action rule): `frob ground band --action retire
--cell <id> --reason "<text>" --json`. Being of kind `admin` it takes no idempotency key (`--key` on `ground_band`
is `FROB-REF-802`), and it is idempotent by its effect (the row of VERBS-ground): a retire of an already retired
cell returns the stored retirement record with `already: retired` and writes nothing. Over MCP it is the input
property `action: "retire"` of the tool `ground_band`. (The Ground registry bead describes the same thing as
"a second parameter set `retire`"; there is one entry form and this is it.) Because one action is not a read, the
tool's MCP annotation `read_only` is false.

**3. What the scope means, exactly.**
- *Necessary, not sufficient.* It admits the call to the handler. Whatever ownership rule Ground applies to a
  calibration still applies (a write outside the caller's namespace is `FROB-REF-725`).
- *Implies nothing; implied by nothing.* `ground:run`, `ground:import` and any write scope do not carry it, and it
  does not carry `ground:read`: the action lists both.
- *Minting.* `session.open` grants it only when `--scopes` names it; no default or convenience scope set contains
  it (a rule for every named scope, point 5). `owner_only = false` (DESIGN, see Considerations for the
  alternative `true`). The catalogue has one minting field, N32b-01's `owner_only`; this bead adds no second one.
- *Attenuation.* It is an ordinary non-budget scope in the subset rule: a derived session may hold it only if its
  parent does; asking for it from a parent that lacks it is `FROB-REF-723` with `observed: ["ground:retire"]`.
- *Visibility.* `session.show` lists it with the marker `irreversible`; `frob robot-docs` prints it in the Admin
  group with its purpose line; `frob capabilities --json` lists the action with its scopes.
- *Focus is not authority.* Seeing `ground_band` in a focused task cluster (`reality`, `calibrate`) grants nothing.

**4. The refusal.** Calling the action without the scope: one envelope, `ok: false`, `FROB-REF-720`, exit 5,
`pointer: /session/scopes`, `required: "ground:retire"`, repairs (1) open a session that holds the scope, (2)
ask the parent session to derive a token that includes it. The check precedes the handler, so nothing was
retired, no event was written and the ledger is unchanged. The default action of the same verb, with the same
token, still answers. Before the handler exists (the verb first answers at M5) the order of the dispatch
pipeline decides what a caller sees: without the scope `FROB-REF-720`; with it `FROB-REF-724` (not implemented in
this build).

**5. The rule for a named scope** (how any chapter adds one; `ground:retire` is its first use).
1. A named scope is a row of the catalogue with every field of point 1. A scope cited by a verb or an action and
   absent from the catalogue fails the build (`unknown-scope`).
2. `scope-unused`: a catalogue scope that no verb and no action lists fails the build; the lint reads `actions`
   as well as `capabilities`.
3. `scope-kind-act`: the kind of a scope fits the kind of what lists it. An entry's default action of kind `read`
   lists only scopes of kind `read` or `private`; an action or verb of kind `admin` lists at least one scope of
   kind `admin` (`<cluster>:admin`, `job:cancel`, or a named admin scope such as this one). The act lint of the
   capability bead BD-258 takes the kind from the catalogue, not from the scope's suffix.
4. `irreversible-needs-reason`: a verb or action guarded by a scope with `irreversible = true` has a required
   input `reason` (text, stored as data, never interpolated into a message, a prompt or a next action).
5. `owner-only-not-mintable`: `session.open` refuses to mint a scope whose `owner_only` is true (`FROB-REF-723`;
   the check is N32b-01's, and this lint verifies it holds for every named scope row); such a scope cannot stand
   in an agent principal's grant (a start-up error of `frobd`, N37-02), cannot be derived, and is held only by
   the owner's session (N32b-01). A named scope is in no default or convenience scope set: it is granted only
   when `--scopes` names it and the principal's grant holds it.
6. `grants-resolve`: every `grants` target names a registered verb, or a registered action of one.

Files: `registries/scopes.toml`; `crates/frob-verbs/src/scopes/{catalogue,lint}.rs`;
`crates/frob-verbs/tests/scope_named.rs`. Determinism: the catalogue and the lints are build-time data, class D0.

## Acceptance criteria

- [ ] `registries/scopes.toml` holds the row of point 1; the registry entry of `ground.band` carries the action of point 2; the build passes all six lints.
- [ ] A token with `ground:read` and without `ground:retire` gets `FROB-REF-720`, exit 5, `required: "ground:retire"` on the retire action, on the CLI and over MCP, and the ledger digest is unchanged; the default action with the same token is not refused for scope.
- [ ] A token with both scopes reaches the handler (from M5: the retirement record; before: `FROB-REF-724`, exit 5).
- [ ] No token minted without naming the scope holds it; `ground:run`, `ground:import` and every write scope fail the retire action with 720.
- [ ] Deriving `ground:retire` from a parent without it is `FROB-REF-723`; a child of a holder that was derived without it cannot retire.
- [ ] `session.show` marks the scope `irreversible`; `frob robot-docs --json` lists it in the Admin group; `frob capabilities --json` lists `ground.band#retire` with both scopes.
- [ ] Each of the six lints fires on its planted registry or catalogue and names it.
- [ ] The MCP tool `ground_band` has `read_only: false`.
- [ ] `crates/frob-verbs/CONTRACT.md` states the named-scope rule and lists `ground:retire`.

### Known answers and negative controls

- Known answer: the unscoped row of the surface's exit-code fixture (KA-755): a call without a required scope is
  `FROB-REF-720`, exit 5. Here it is asserted for an action-level scope.
- Negative controls: `scope-on-read` (the scope moved to the entry's `capabilities`: every band read by an agent
  without it would be refused; the `scope-kind-act` lint must fail the build); `suffix-lint` (an act lint that
  accepts only scopes ending in `:admin` must reject this catalogue, showing the lint reads the kind); a
  dispatcher that checks only the entry's `capabilities` and ignores the action's (the retire call with
  `ground:read` alone must be seen to reach the handler, and `retire_without_scope_720` must fail).
- Metamorphic: adding or removing `ground:retire` from a token changes the answer of no call other than the
  retire action.
- Determinism lanes: catalogue, lints and refusals identical twice on one machine, debug and release, both hosts.

## Considerations

- `owner_only = false` is a DESIGN default and the fail-open side of a real choice. The argument for it:
  retirement makes the system claim less, never more; it is recorded with the session's identity and reason; and
  an agent running a calibration campaign must be able to withdraw a calibration it knows to be wrong. The
  argument for `owner_only = true`: retirement is irreversible and sends other agents' reports back to `no-claim`.
  If the owner prefers the stricter reading, the change is one field, and lint 5 then keeps agents from minting
  it.
- The scope does not decide whose calibration may be retired; that is Ground's ownership rule plus the namespace
  refusal. A shared calibration retired by a session that did not own the bench data is the case to watch.
- Other clusters' rows cite `<cluster>:admin` for their admin verbs; N32b-01's catalogue generates those forms
  from the second milestone for exactly the clusters whose rows cite them, and BD-258 keeps the act lint over the
  M3 surface. This bead adds one named scope and the rule, not a second vocabulary; the rule's second user is
  `session:audit` (N32bx-01).
- If the Ground cluster is cut back at a kill gate, the row stays (the lint `scope-unused` reads the registered
  action, which answers `FROB-REF-724`), so tokens that name the scope remain valid.
