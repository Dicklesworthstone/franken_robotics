## Background

The **referee** is the most trusted simulation tier of FrankenRobotics: double precision, FrankenSim's own
articulated dynamics and contact solve, one to a few dozen worlds. It adjudicates the fast batched tiers. It
is not called ground truth: its outputs carry the evidence class FrankenSim's contracts give them. The referee
reaches FrankenSim only through the airlock crate `frob-fsim`, the one crate allowed to name FrankenSim's
volatile types, so that a FrankenSim API change costs one crate.

This bead is the first real adapter in the airlock and the second half of the admission gate INT-FSIM-01: from
this repository, the crate that depends by path on FrankenSim must not only type-check (BD-006) but **reproduce
the digest of a G1 forward-dynamics state computed inside FrankenSim at the pinned commit**. G1 is the Unitree
G1 humanoid (29 degrees of freedom), which FrankenSim ships as a catalog model (FACT:
`frankensim/crates/fs-mbd/src/robot_models.rs`; the builder keeps 30 links). Equal digests mean that consuming
FrankenSim from outside its tree, on this project's toolchain, with the repeated patch, profile and
build-identity settings, computes the same bits as FrankenSim computes for itself. That is the measurement bet
BET-04 stands on. A perturbed input must change the digest, or the test proves nothing.

FACT about what is wrapped (read 2026-11-21; re-read at the pin): `fs-mbd` provides tree kinematics, recursive
Newton–Euler, an articulated-body solve and floating-base maps in `articulated.rs` (3,428 lines) and
`articulated/generalized.rs`; its stepping is a second-order Lie midpoint step that its contract calls "neither
an energy-exact nor a variational/symplectic integrator"; it is plain `f64`, not generic over a differentiation
scalar, emits no articulated adjoints, has no batched environments, supports fixed, revolute, prismatic and
helical joints, and uses platform square root, sine and cosine, so the referee claims same-platform
determinism only.

Design decisions (DESIGN): trait names fix intent, not signatures; no FrankenSim type appears in the trait's
public face; the adapter converts and never reinterprets; and the digest is defined by this project, not
borrowed, so that both sides run the identical hashing code over identically ordered bytes.

## Scope

In: the trait `RefereeDynamics` and its in-process adapter over `fs_mbd::articulated`; the built-in G1 model
through the airlock; forward dynamics and a contact-free step; the canonical referee-state digest; the in-tree
probe and the oracle capture, which records both the forward-dynamics digest and the two-second rollout digest
that the M0 artifact compares with (`rollout_2s_digest`); the perturbation control.
Out: contact (`RefereeContact`, bead N33a-14); refusal conversion in full (N33a-13); the verb `sim.run --tier
referee` and telemetry to the ledger (BD-024); the lowering of a compiled design to a referee model (BD-061);
the worker mode (BD-038); deeper admission of the articulated module (BD-032).

## Technical approach

**Trait (DESIGN: intent, not signatures; module `frob_fsim::referee`, feature `referee`).**

```rust
pub trait RefereeDynamics {
    fn catalog_model(&self, which: CatalogRobot) -> Result<RefereeModel, RefereeRefusal>;   // v0: G1
    fn reference_state(&self, m: &RefereeModel) -> RefereeState;                             // catalog default pose
    fn forward_dynamics(&self, m: &RefereeModel, s: &RefereeState, tau: &[f64]) -> Result<Vec<f64>, RefereeRefusal>;
    fn step_free(&self, m: &RefereeModel, s: &RefereeState, tau: &[f64], h: Rational) -> Result<RefereeState, RefereeRefusal>;
    fn describe(&self, m: &RefereeModel) -> ModelFacts;      // link count, coordinate layout, total mass
}
pub struct RefereeState { pub q: Vec<f64>, pub v: Vec<f64> }   // generalized position and velocity
pub struct ModelFacts { pub links: u32, pub nq: u32, pub nv: u32, pub layout: CoordLayout, pub mass_kg: f64 }
```

`RefereeModel` is an opaque handle owned by the airlock. `CoordLayout` states, as data, the order and meaning
of every generalized coordinate (floating-base position in metres, base orientation and its parameterization,
then joints in tree order with their units), read from FrankenSim's public accessors at the pin. `frob-fsim` is
a layer-0 crate, so plain `f64` vectors with documented units are allowed here; typed quantities arrive with
the model compiler above it.

**Adapter rules that bind already in v0.** (1) Every FrankenSim error becomes a `RefereeRefusal` carrying the
upstream reason text; nothing is retried with weakened inputs. (2) A state containing a NaN or an infinity is
refused before FrankenSim is called. (3) Vector lengths are checked against `nq`, `nv` and the actuator count;
a mismatch is a refusal naming both lengths.

**The canonical referee-state digest (DESIGN, `frob_fsim::referee::digest`, one source file with no dependency
except the bedrock hash crate `fs-blake3`).** The byte string hashed is, in order:
1. the ASCII domain tag `frob.referee-state/1` followed by one zero byte;
2. `links`, `nq`, `nv` as 32-bit little-endian unsigned integers;
3. each element of `q`, then each element of `v`, as the 8 bytes of its IEEE-754 bit pattern, little-endian;
4. for a forward-dynamics digest, the tag byte 0x01 and each element of the acceleration vector in the same
   encoding; for a plain state digest, the tag byte 0x00.
The digest is the 32-byte BLAKE3 of that string, printed as 64 hex digits. Negative zero and positive zero
hash differently on purpose: the digest distinguishes states that differ in any bit.

**The G1 digest test (algorithm).**
1. *Candidate side.* In this repository: `catalog_model(G1)`, `reference_state`, zero torques,
   `forward_dynamics`, digest of (q, v, q̈). Also the plain state digest (tag byte 0x00) after 960 calls of
   `step_free` with zero torques and h = 1/480 s (two seconds) from the same reference state: the **rollout
   digest**. Both sides pass h to FrankenSim as the `f64` value `1.0 / 480.0` (the correctly rounded quotient),
   so the two rollouts call the same step with the same bits.
2. *Oracle side: inside FrankenSim at the pinned commit.* A capture script `tools/oracle/fsim_g1_digest.sh`:
   (a) exports the pinned commit with `git archive <rev>` into a scratch directory under
   `${BIG_SCRATCH:-${TMPDIR:-/tmp}}/frob-fsim-intree/<rev>/` (the sibling checkout is neither modified nor
   moved; branches and worktrees are not used); (b) copies the probe crate `crates/frob-fsim/intree-probe/`
   into the export under `apps/frob-digest-probe/`, where, like the five existing out-of-workspace crates of
   FrankenSim, it has its own `[workspace]` table, consumes `fs-mbd` by path and inherits FrankenSim's own
   `.cargo/config.toml` and toolchain file; (c) builds and runs it through the offload shim; the probe prints two
   digests: the forward-dynamics digest of step 1, and the rollout digest, computed by 960 direct calls of the
   same `fs_mbd` contact-free step from the same reference state with zero torques and h = `1.0 / 480.0`;
   (d) writes the printed digests with the pin, the toolchain and the date to
   `tests/fixtures/oracle/fsim/g1_fd_digest.toml`, fields `fd_digest`, `rollout_2s_digest`, `rollout_steps =
   960`, `rollout_h = [1, 480]`, `pin`, `toolchain`, `captured_on`, `capture_log_blake3`. The probe calls `fs_mbd`
   directly (no airlock) and includes the same digest source file byte for byte. (e) Checks in the **capture
   record** beside the fixture: `g1_fd_digest.capture.log`, the probe's build and run output, which contains the
   `rustc -vV` output of the toolchain that built the probe and the two digest lines the probe printed; the
   fixture carries `capture_log_blake3`, the BLAKE3 of that log. The capture record check re-hashes the log and
   compares it with `capture_log_blake3`, and requires the log's two digest lines to equal the fixture's
   `fd_digest` and `rollout_2s_digest` and its toolchain line to equal the fixture's toolchain, so a fixture
   whose digests were written by hand or copied from the candidate has no matching capture record and is
   refused. The fixture is read by BD-024 (`oracle_match`, `rollout_match`) and by N41-19.
3. *Compare.* The candidate forward-dynamics digest must equal the oracle's `fd_digest` for the same pin, on
   the same machine (the gate). The candidate rollout digest is compared with `rollout_2s_digest` the same way:
   this equality is the M0 artifact of §43.3 ("a state digest equal to the one FrankenSim computes for
   itself"), asserted here as a unit test and through the verb by BD-024; it is recorded beside the gate
   digest and is not a clause of INT-FSIM-01's pass criterion.
4. *Perturb.* Add one unit in the last place to the first joint coordinate of the reference state on the
   candidate side; the digest must differ from the oracle's. Then, with the state unchanged, change the first
   torque from 0 to 1 N·m; the forward-dynamics digest must differ. The second control is the one that shows the
   acceleration is in the digest and depends on its input: q and v are hashed themselves, so the first would
   change the digest even if the acceleration were ignored. The torque change is finite because one unit in the
   last place of a zero torque is 4.9·10⁻³²⁴ N·m, which any nonzero bias term absorbs without changing one bit
   of the acceleration, so that perturbation could leave the digest unchanged on a correct adapter.
5. Write the completed INT-FSIM-01 admission record with N33a-07's command (`cargo run -p frob-conformance
   --example admission -- record --gate INT-FSIM-01 --input <file>`). Records are append-only files named by
   their hash, so BD-006's record is not edited: the new input repeats its `covers`, `command`, `measured` and
   `controls` and adds two `measured` entries, `g1_fd_digest` and `g1_rollout_2s_digest` (each with the
   candidate's 64-hex digest as `value`, the oracle's as `threshold`, relation `==`, unit `blake3`), the
   oracle side's toolchain and the fixture's `capture_log_blake3` as `facts_reread` entries, and the two
   perturbation controls and the copied-fixture control in `controls` with `caught`. The pin is the record's
   `sibling_rev` and the candidate's toolchain its `toolchain`. A mismatch is recorded with status `fail`. As
   for BD-006's record, a `pass` is written by a session that did not implement this bead, `harness_receipt` is
   null until the gate's tier run, and the row of `registries/gates.toml` is entered by N33a-28, the gate's one
   recorder. Each session that works on this bead appends its hours to the effort clock BD-006 started
   (`[effort_clock]` of `docs/delivery/kill-fsim/ledger.toml`): the gate has not passed until this half has.

**What a mismatch means.** The two builds differ in toolchain (T against FrankenSim's own nightly while those
differ), in feature unification, in the asupersync package resolved, in profile settings and possibly in
compiler flags that FrankenSim's `.cargo/config.toml` sets and an outside workspace does not inherit. A
mismatch is therefore a finding about consumption, localized by rebuilding the candidate with each difference
removed in turn; it is recorded as a failing value of INT-FSIM-01, not retried until it passes.

Determinism class: same-platform, same-binary bit equality (the referee's class). Evidence class of v0
outputs: `Tested`. The fixture file is an oracle capture and is never regenerated from the candidate.

## Acceptance criteria

- [ ] The candidate digest of the G1 forward-dynamics state equals the digest computed inside FrankenSim at the pinned commit (seed done-condition); both are in the admission record with the pin and the toolchain of each side.
- [ ] A perturbed input changes the digest (seed done-condition): one unit in the last place on one coordinate, and separately the first torque changed from 0 to 1 N·m with the state unchanged.
- [ ] The fixture carries `rollout_2s_digest` captured inside FrankenSim's tree (960 steps of h = 1/480 s, zero torques, from the reference state), and the candidate's rollout digest equals it at the pin; both are in the admission record. A mismatch is recorded as a failing finding of the M0 artifact, never retried until it passes.
- [ ] The public API of the `referee` module names no `fs_mbd` type; the adapter compiles only under the `referee` feature.
- [ ] `describe` reports the link count and coordinate layout read at the pin (30 links on the day of reading), and the layout is stored with the fixture.
- [ ] A state with a NaN, and a torque vector of the wrong length, are each refused with a typed refusal before FrankenSim is called.
- [ ] The capture script leaves the FrankenSim checkout byte-identical and writes only under the scratch directory and the fixture path.
- [ ] `CONTRACT.md` of `frob-fsim` states for `RefereeDynamics`: inputs, outputs, refusals, determinism class (same platform only), evidence class, validity domain (joint classes fixed, revolute, prismatic, helical), oracle (the in-tree probe), known gaps (no contact, no adjoints, `f64` only).

## Test plan

### Unit tests (`cargo test -p frob-fsim referee`)
- `g1_fd_digest_matches_oracle`: equality with `tests/fixtures/oracle/fsim/g1_fd_digest.toml` for the current pin; if the fixture's pin differs from the lock's pin the test fails with "capture missing for pin", never passes vacuously.
- `g1_fd_digest_changes_on_ulp_perturbation`: `f64::from_bits(q[0].to_bits() + 1)` → different digest.
- `g1_fd_digest_changes_on_torque_perturbation`: `tau[0] = 1.0` (N·m) with q and v unchanged → a forward-dynamics digest different from the oracle's; the same call with `tau[0] = 0.0` reproduces it.
- `digest_layout_known_answer` (synthetic): links = 1, nq = 1, nv = 1, q = [1.0], v = [−0.0], no acceleration → the BLAKE3 of the explicit 50-byte string (the 20-character tag and its zero terminator, three 4-byte integers, two 8-byte floats, the tag byte 0x00), whose hex value is computed by an independent script and checked in.
- `digest_distinguishes_signed_zero`: v = [0.0] against v = [−0.0] → different digests.
- `state_with_nan_refused`, `wrong_length_refused`.
- `g1_rollout_2s_digest_matches_oracle`: the candidate's 960-step rollout digest equals the fixture's `rollout_2s_digest` for the current pin; a fixture without the field, or with another pin, fails with "capture missing for pin", never passes vacuously.
- `fixture_capture_record_consistent`: the checked-in fixture's `capture_log_blake3` equals the BLAKE3 of its capture log, and the log's two digest lines and toolchain line equal the fixture's; four planted fixtures (the candidate forward-dynamics digest copied in with the log unchanged; the candidate rollout digest copied in the same way; the log edited by one byte; the toolchain line changed) are each refused.
- `forward_dynamics_is_repeatable`: 100 calls on the same state give bit-identical accelerations.
- `step_free_two_seconds_repeatable`: the 960-step digest is identical twice in one process and across two processes.
- Property test `digest_injective_on_single_bit_flips`: for 10³ random states, flipping any one bit of q or v changes the digest.

### End-to-end script and logging
`scripts/e2e/admission_m0.sh` (bead N33a-28), step `int_fsim_01_digest`: runs the capture script, then the
candidate test, and logs both digests of each side (forward dynamics and rollout), both toolchains, the pin, the
perturbed digests and the comparisons. On
failure the log carries the first differing coordinate of the acceleration vectors (printed by a diagnostic
mode of both programs) and the paths of the two dumps.

### Known answers and negative controls
- Known answer: digest equality at the pin (the gate); the rollout digest equal to FrankenSim's own (the M0 artifact); the synthetic layout digest.
- Negative controls (registered for INT-FSIM-01): each of the two perturbations (one unit in the last place on a coordinate; 1 N·m on the first torque) must change the digest; an oracle fixture regenerated from the candidate (planted by copying the candidate digest into the fixture without running the probe) must be refused by the fixture's capture record check.
- Metamorphic relation: the digest is invariant under rebuilding with a different target directory and under running from a different working directory.
- Determinism lanes: twice on one machine; debug and release are recorded separately (equality between them is observed, not required, because FrankenSim's code is compiled under different optimization); across platforms is not claimed for the referee.

## Considerations

- The G1 catalog model omits four welded links with nonzero mass (reported: 1.377 kg; the 30 kept masses sum to 31.96314202 kg against a 38-link source of 33.34014202 kg). It is used as a reduced profile and never as the import-parity reference. This does not affect the digest test, which compares FrankenSim with itself.
- A pin move invalidates the fixture; the compatibility train reruns the capture and this test. The airlock never caches across pins.
- If FrankenSim does not build on the candidate for T, the oracle side still runs inside an export of FrankenSim's own tree on FrankenSim's pin (it is FrankenSim's build, outside this project's build graph), and the comparison is exactly the measurement wanted; the remedy for this project's side is the upstream change that advances FrankenSim's pin (NF-03), never a second toolchain here.
- If the worker-process fallback is ever active, this trait is served by the worker with the same digest function, and the same test compares in-process and worker digests.
- RISK-01: every change to this adapter at a pin move is counted for the breakage ledger.
