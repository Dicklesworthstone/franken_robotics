## Background

Spark is the subsystem of FrankenRobotics between a derived kernel and a device result. Its Metal backend, for
the project's M5 Ultra Mac, lives in the annex workspace `spark/frob-spark-metal`. It does not bind Metal
itself. It uses **FrankenTorch's `ft_kernel_metal::compute::Gateway`**, a safe gateway to custom Metal Shading
Language kernels, foundation row `FD-FT` (posture Consume; confined to this annex for the gateway; admission
gates INT-FT-01 and INT-FT-02).

FACT, read from `frankentorch/crates/ft-kernel-metal` version 0.1.3 (`src/compute.rs`, `src/lib.rs`) on
2026-11-21, to be re-read at the pin: `Gateway::open` returns the process-wide device and command queue;
`library` compiles Metal Shading Language under `MathMode::Safe`, which disables fast math (`library_with`
selects otherwise); `Library::pipeline` builds a compute pipeline and exposes `max_threads_per_threadgroup` and
`thread_execution_width`; buffers are shared-storage allocations made by `buffer_f32`, `buffer_u32` and
`buffer_zeroed`, read by `read_f32`, `read_u32` and `read_u8`, rewritten in place by `write_f32` and
`write_u32`; `Gateway::batch` encodes several kernels in order into one serial compute encoder of one command
buffer, checks read and write declarations for aliases, borrows every output exclusively until `submit`
returns, and returns a `Receipt` with the kernel count and the device's execution time. State is resident: a
buffer persists across command buffers.

FACT about the build: FrankenTorch's workspace carries a `[patch.crates-io] block` entry for the `metal` 0.33.0
binding, and Cargo does not propagate a patch from a path dependency, so whichever workspace resolves
`ft-kernel-metal` must **repeat the `block` patch at its own root**. That is one of the reasons the annex has
its own lockfile: the patch stays out of the core's resolution. FrankenTorch is at head `8165d6a18028` on
`nightly-2026-08-31` with asupersync `0.6.2`, default features off.

**INT-FT-01**: `ft-kernel-metal`'s gateway builds in the Metal annex, with FrankenTorch's `block` patch
repeated at the annex root, and runs a kernel on this Mac. The seed done-condition is stronger: the kernel
matches a Rust loop bit for bit on 10⁶ quaternions, and an admission record exists. INT-FT-01 also records the
Metal Shading Language version the gateway compiles under, because the `metal` 0.33.0 binding's language
enumeration ends at version 3.1, and dialect sources may use no construct newer than that.

Decision context (DESIGN): until upstream work item FD-FT-01 lands in FrankenTorch's repository, Spark works
inside the gateway's limits. It does not patch the gateway locally and does not bind Metal a second time
beside it; a Metal binding of this project's own needs an owner decision (OPEN-SPARK-5; default: no).

## Scope

In: the annex workspace with the repeated patch; opening the gateway; compiling one dialect unit through the
Metal prelude; buffers, one batch, readback; the bit comparison on 10⁶ quaternions; the receipt; the recorded
gateway facts and language version; typed refusals; the admission record.
Out: resident buffers across command buffers and device completion receipts as a gate (INT-FT-02, BD-028);
the full backend with packed arguments, batch chains and snapshot blits (BD-174); the IEEE probe (BD-017); the
three-backend comparison (BD-020); FrankenTorch's CPU trainer crates (bead N33a-22).

## Technical approach

**Workspace.** `spark/frob-spark-metal/Cargo.toml` with its own `[workspace]` table and lockfile; a path
dependency on `frankentorch/crates/ft-kernel-metal` at the pin of `franken-stack.lock` with default features
off; path dependencies on the core crates `frob-core` and `frob-kernels`; and at the root the repeated entry
`[patch.crates-io] block = …`, copied from FrankenTorch's manifest at the pinned commit by reading it, never
from memory. The annex builds on T and has no toolchain file. The annex contains no unsafe code of its own in
v0: the gateway is the safe boundary.

**Necessity test for the patch (recorded).** In a scratch copy with the `block` entry removed, run `cargo
check`. Record what happens (a resolution or compile failure, or a different `block` version in the lockfile).
This settles, for this patch, the same hypothesis the core settles for the asupersync patch.

**Steps of v0.**
1. `Gateway::open`. A missing device (a non-Apple host, or Metal unavailable) is `FROB-REF-601`, never a panic.
2. Record gateway facts: `max_buffer_length`, `recommended_working_set_bytes`, `max_threadgroup_memory`, and
   from the pipeline `max_threads_per_threadgroup` and `thread_execution_width`.
3. Assemble the compiled unit: shape-class `#define` lines (the gateway has no function constants), the Metal
   prelude, the generated body, the skeleton. Run the dialect lint; compile with `library`, which is the
   safe-math entry point. `library_with` is never called. A compiler failure is `FROB-REF-603` with the
   diagnostics verbatim.
4. Record the Metal Shading Language version in force (as reported by the gateway or the binding at the pin).
5. Allocate shared buffers with `buffer_f32` and `buffer_zeroed`; at most 31 buffer arguments per kernel (the
   gateway's limit); v0 needs far fewer.
6. Encode one `Batch` with the one kernel; thread-group size is a multiple of the pipeline's
   `thread_execution_width`, which is read and never assumed.
7. `submit` blocks until the command buffer completes (completion is synchronous in the gateway today). Only
   then read outputs (readback rule: the host reads a device buffer only after the command buffer that last
   wrote it has completed and returned its receipt; under the gateway that is a compile-time fact, since a
   batch holds each output by exclusive borrow until `submit` returns).
8. Build the backend `Receipt` (the twelve doctrine fields, plus device seconds from the gateway's receipt,
   which spans the device's start and end times). A run is labelled native on the device only if its receipt
   carries a completed command buffer with times from that device. A terminal state other than completed
   invalidates every buffer the batch could write; v0 reports `FROB-REF-607` after bounded retries (at most
   four attempts with growing waits).

**The comparison.** Kernel: the single-body Cayley step (orientation quaternion q, position p, body angular
velocity ω, body linear velocity v, step h; with a = h·ω: q′ = q ⊗ (1, a/2), denominator d = 1 + (a·a)/4,
translation increment u = (h·v + ½·a × (h·v) + ¼·a·(a·(h·v)))/d, p′ = p + R(q)·u; arithmetic uses only +, −,
×, ÷). Inputs: 10⁶ rows generated on the host from a counter-based stream with a recorded seed, with ‖ω‖·h at
most 0.2. Reference: the Rust body generated from the same program, run in a plain loop. Pass: every output
word of every row equal as a 32-bit pattern. The count of differing rows and the first differing row with both
bit patterns are recorded either way.

**Why bit equality is plausible and still measured.** The kernel uses only operations IEEE 754 requires to be
correctly rounded, the gateway compiles in safe math mode, and the dialect bans fused multiply-add. Whether the
Metal compiler honours this is a HYPOTHESIS; the test is the measurement, and the contraction detector of the
probe bead is the cross-check.

Determinism and evidence: evidence class `Tested`; the result is `citable: false` until the hardware
fingerprint exists.

## Acceptance criteria

- [ ] The annex builds on T through the offload shim with the `block` patch repeated at its root; the necessity test's outcome without the patch is recorded.
- [ ] The kernel runs on this Mac through the gateway and matches the Rust loop bit for bit on 10⁶ quaternions (seed done-condition): zero differing rows.
- [ ] An admission record for INT-FT-01 exists (seed done-condition) with the pin, the gateway version, the recorded Metal Shading Language version, the gateway facts of step 2, compile and device seconds, and the comparison counts.
- [ ] `cargo tree -d` in the annex shows one asupersync package or none, and no `block` duplicate.
- [ ] The source lint refuses a unit compiled with a non-safe math mode, and a grep of the annex finds no call to `library_with`.
- [ ] The planted wrong-constant kernel is reported as differing (the negative control).
- [ ] On a host without Metal the backend refuses with `FROB-REF-601`.
- [ ] The receipt validates and carries device start and end times from the device.

## Test plan

### Unit tests (`cargo test` in the annex; device tests are `#[ignore]` and run on the Mac by the gate command)
- `unit_assembly_order`: defines, prelude, body, skeleton, in that order; the kernel text after the prelude is byte-identical to the text the CUDA annex receives (digest equality with the shared file).
- `threadgroup_size_is_multiple_of_execution_width` (device).
- `argument_count_under_31`: the v0 kernel declares fewer than 31 buffers; a synthetic manifest with 32 is refused before compilation.
- `cay_step_bit_equal_1e6` (device): zero differing rows; on failure prints the first differing row, the output index and both 32-bit patterns.
- `cay_step_exact_fixture` (device): q = (1, 0, 0, 0), a = (0, 0, 1.5), v = 0 → q′ = (1, 0, 0, 0.75), d = 1.5625 exactly.
- `planted_constant_detected` (device): the same kernel with ½ replaced by 0.5000001 differs on more than 99% of rows.
- `no_library_with_calls` (source scan).
- `no_metal_refuses_601` (run on Linux).
- `receipt_native_label_requires_device_times`.

### End-to-end script and logging
`scripts/e2e/admission_m0.sh` (bead N33a-28), step `int_ft_01` (run on the Mac): builds the annex, runs the
device tests, the patch necessity test, and writes the admission record. NDJSON lines carry the command, exit
code, wall time, the gateway facts, the language version, compile seconds, device seconds, rows compared, rows
differing, and on a difference the first differing row with both bit patterns and the path of the dumped
inputs.

### Known answers and negative controls
- Known answers: the exact fixture above; bit equality with the Rust loop on the seeded 10⁶ rows.
- Negative controls (registered for INT-FT-01): the planted constant; a prelude variant that permits contraction (supplied by the prelude bead) must change at least one output bit on the detector input (1 + 2⁻¹²)·(1 + 2⁻¹²) − (1 + 2⁻¹¹), which is 0 without contraction and 2⁻²⁴ with.
- Determinism lanes: the device run twice gives identical bytes; debug and release host builds give identical device outputs.

## Considerations

- The gateway's limits that shape later work (FACT): synchronous completion; at most 31 buffer arguments; buffers bind at offset zero; shared storage only; host data copied in and out with typed helpers for `f32`, `u32` and bytes; compilation from source only, no function constants, no binary archive; one device and queue per process with 64 command buffers; an uninterruptible wait; a failed batch's outputs undefined; a receipt with kernel count and device seconds only; the `metal` 0.33 binding deprecated by its maintainers. Each has a consequence in the full backend and most are part of FD-FT-01 (P1; switch-over rule: re-run INT-FT-01, INT-FT-02 and the device parity gates).
- RISK-08 (the gateway's limits throttle the Mac tier) and the kill gate KILL-METAL (decided at M2; fallback: the Mac keeps the world bank, proof, replay and `batch-cpu` roles) read this bead's measurements; neither is decided here.
- A reported fact to recheck through the fingerprint: Metal Shading Language 3.2 and 4.0 provide no 64-bit integer atomic add and no 64-bit compare-and-swap on this machine.
- If INT-FT-01 fails, nothing on the M1 path is affected; the CPU tiers remain.
