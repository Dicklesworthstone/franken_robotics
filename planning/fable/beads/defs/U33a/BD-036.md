## Background

FrankenRobotics exchanges arrays with the outside world at one place, the **interchange boundary**: telemetry
columns and policy tensors leaving as array files, tensors handed to a Gymnasium-compatible learner, and
reference results coming from oracle libraries. Two sibling libraries meet at that boundary. **franken_numpy**
(foundation row `FD-FNP`: consumed narrowly for array files through its crate `fnp-io`, and as an `f64` oracle;
confined to `frob-chronicle`, `frob-conformance` and `bindings/frob-gymnasium`; fallback: plain binary columns
and no oracle) and **FrankenTorch** (host tensors). FACT (read 2026-11-21): franken_numpy is an `f64` array
library on heap vectors with no single-precision storage and no fixed-size matrix types; it is the right tool
at the boundary and is not put in a hot path.

One reported foundation defect lives exactly here, and it is the reason this is an M0 admission bead. It is a
**stride-convention trap**: franken_numpy's array type uses *signed byte strides* and FrankenTorch's tensor
type uses *unsigned element strides* (FACT: both conventions confirmed by reading `fnp-ndarray/src/lib.rs:258,
:390` and `ft-core/src/lib.rs:397, :2460`; the wrong read was not executed). Neither library is wrong by
itself; the trap is at our boundary. A stride tuple copied verbatim from one to the other reads the wrong
element, **in bounds**, so nothing faults.

The hand case. A contiguous 2×2 single-precision view has strides (8, 4) in bytes and (2, 1) in elements.
Copying (8, 4) into an element-stride view over a 16-element buffer addresses element 8 + 4 = 12 at index
[1, 1], where element 3 belongs. A second case: a view with byte origin 4 and byte strides (8, −4) addresses
elements (1, 0, 3, 2), which unsigned strides cannot express at all.

The two gates: **INT-FNP-01**, an array file written through `fnp-io` reads back identically; **INT-FNP-02**,
the stride conversion at the interchange boundary reads element 3, not element 12, on the 2×2 case. Upstream
work item FD-FNP-01 (priority P2) asks both siblings for a named conversion; the interim posture is the typed
converter built here, with the rule that **no bare stride tuple crosses the boundary**; the switch-over rule
is to replace the local converter and re-run INT-FNP-02.

Rejected alternatives: always copy at the boundary (wasteful for large tensors, and it hides the convention
instead of naming it); trust both libraries' "from raw parts" constructors (that is the trap).

## Scope

In: the view-layout type and converter in `frob-core`; the write-independence check; the `fnp-io` round-trip

## Technical approach

**Types (DESIGN, `frob_core::view`; pure integer logic, standard library only).**

```rust
pub enum StrideUnit { Bytes, Elements }
pub enum Signedness { Signed, Unsigned }
pub struct Convention { pub unit: StrideUnit, pub sign: Signedness }   // fnp: (Bytes, Signed); ft: (Elements, Unsigned)
pub struct ViewLayout {
    elem_size: u32,          // bytes per element (4 for f32, 8 for f64)
    shape: Vec<u64>,
    strides: Vec<i64>,       // in `convention.unit`
    origin: i64,             // logical origin: offset of index [0, …, 0] from the allocation start, in the same unit
    extent: u64,             // allocation extent, in the same unit
    convention: Convention,
    writable: bool,
}
pub enum Converted { ZeroCopy(ViewLayout), Materialized { layout: ViewLayout, copied_bytes: u64 } }
pub enum Contract { ZeroCopyRequired, CopyAllowed }
```

Fields are private. The only constructors take every field explicitly, including the unit and the signedness;
there is no constructor from a bare tuple of strides, and no method that relabels the unit without converting
the numbers. A layout arriving from a foreign descriptor without a declared unit is refused.

**`ViewLayout::validate` (run by every constructor).**
1. `shape.len() == strides.len()`; `elem_size > 0`.
2. In unit Bytes: `origin` and every stride are multiples of `elem_size` (otherwise `misaligned`).
3. Bounds: lowest offset = origin + Σ_k min(0, (shape_k − 1)·stride_k) ≥ 0; highest offset + (one element in
   the unit) ≤ extent. All sums in checked 128-bit arithmetic; an overflow is a refusal.
4. Unsigned convention: every stride ≥ 0.

**`convert(src, target: Convention, contract) -> Result<Converted, Refusal>`.**
1. Validate `src`.
2. Bytes → Elements: divide origin, extent and each stride by `elem_size` (exact after step 2 of validation).
   Elements → Bytes: multiply, checked.
3. If the target is unsigned and any converted stride is negative, the target cannot represent the view. Under
   `CopyAllowed`: build a contiguous copy in logical index order and return `Materialized` with
   `copied_bytes = elem_size · Π shape_k`, which is charged to the caller. Under `ZeroCopyRequired`: refuse with
   `FROB-REF-617` (a view cannot cross a stride convention without a copy, under a zero-copy contract; exit
   code 6; repairs: allow the copy; make the source contiguous first).
4. Validate the result under the target convention and return `ZeroCopy`.

**Write independence (separate from bounds).** A writable view needs an injective index map. Check: for views
of at most 2²⁰ elements, enumerate offsets into a bitmap and refuse on the first repeat, naming two indices
that collide; for larger views, with axes of length greater than one sorted by |stride| ascending, require
|stride_k| ≥ 1 + Σ_{j<k} (shape_j − 1)·|stride_j| for every k (a sufficient condition), and refuse with
"independence not proved" otherwise. Shared elements are admitted for reads; a write needs an injective map, a
declared reduction or separate storage, and is refused otherwise. Smallest case: a 2×2 view with element
strides (1, 1) maps index [0, 1] and index [1, 0] to one element, so stores of 7 and 11 leave a result that
depends on their order.

**The `fnp-io` round trip (INT-FNP-01; test crate in `frob-conformance`, which is in the foundation's
confinement).** Write through `fnp-io`, read back, compare: (a) a 3×4 `f64` array whose values include +0, −0,
the largest and smallest normal numbers, a subnormal, +∞ and −∞; (b) a 1,000-element array from a seeded
stream; (c) a single-precision telemetry column widened to `f64` (every `f32` is exactly representable as an
`f64`), read back and narrowed, compared bit for bit with the original column. "Identically" means: shape,
element type and value bit patterns equal, and a second write of the read-back array produces a byte-identical
file.

**Admission records.** One for INT-FNP-01 (`covers.crates` = the franken_numpy packages in the tracked
lockfile) and one for INT-FNP-02, each with the command, output, receipt hash, the measured counts and the
caught controls; INT-FNP-02's record also stores the two stride conventions re-read at the pins (the four
source lines above), since the converter's correctness depends on them.

Determinism class: D0. Evidence class: `Tested`.

## Acceptance criteria

- [ ] An array file written through `fnp-io` reads back identically for the three cases, and rewriting gives byte-identical files (seed done-condition; INT-FNP-01).
- [ ] The 2×2 case reads element 3: converting the byte-stride layout (8, 4), origin 0, extent 16 bytes, element size 4 gives element strides (2, 1), and index [1, 1] addresses element 3 (seed done-condition; INT-FNP-02).
- [ ] The verbatim stride copy that would read element 12 is refused (seed done-condition): no API accepts a bare stride tuple (a compile-fail test), and a foreign descriptor without a declared unit is refused at run time.
- [ ] The negative-stride view (byte origin 4, strides (8, −4)) converts to element origin 1 with strides (2, −1) addressing (1, 0, 3, 2); to the unsigned convention it is `Materialized` with 16 bytes charged under `CopyAllowed`, and refused with `FROB-REF-617` under `ZeroCopyRequired`.
- [ ] A writable 2×2 view with element strides (1, 1) is refused, naming the colliding indices [0, 1] and [1, 0]; the same view read-only is accepted.
- [ ] Both admission records exist and validate; `cargo tree -d` shows one asupersync package with franken_numpy in the graph.
- [ ] The failing fixture (the 2×2 case and the negative-stride case as a standalone test) is attached to the upstream work item FD-FNP-01.

## Test plan

### Unit tests (`cargo test -p frob-core view`, `cargo test -p frob-conformance --test admission_int_fnp`)
- `bytes_to_elements_2x2`: (8, 4)/4 → (2, 1); offsets of indices [0,0], [0,1], [1,0], [1,1] are 0, 1, 2, 3.
- `negative_stride_addresses_1_0_3_2`.
- `unsigned_target_materializes_or_refuses_617`.
- `bare_tuple_does_not_compile` (trybuild): a call passing `(8, 4)` where a `ViewLayout` is required fails to compile.
- `foreign_descriptor_without_unit_refused`.
- `misaligned_byte_stride_refused`: byte strides (6, 4) with element size 4.
- `out_of_bounds_refused`: element strides (2, 1), shape (3, 2), extent 4 → highest offset 5 ≥ 4.
- `overflow_refused`: strides near 2⁶² with shape 4.
- `write_overlap_refused_2x2`, `read_overlap_allowed_2x2`.
- `write_independence_sufficient_condition`: a 1,024 × 2,048 contiguous view passes; the same with the inner stride equal to the outer fails.
- `fnp_roundtrip_special_values`, `fnp_roundtrip_seeded_1000`, `fnp_f32_column_widen_narrow_bit_exact`, `fnp_rewrite_byte_identical`.
- Property test `convert_preserves_addressing`: for 10⁴ random valid layouts, every index addresses the same element (as a byte offset from the allocation start) before and after conversion, and after materialization the copy holds the same values in logical order.
- Property test `roundtrip_convention`: Bytes → Elements → Bytes is the identity on valid aligned layouts.

### End-to-end script and logging
`scripts/e2e/admission_m0.sh` (bead N33a-28), step `int_fnp`: runs both test sets through the offload shim and
writes the two records. NDJSON lines carry the command, exit code, wall time, per case the element index read
(expected 3), the element addressed by the planted verbatim copy (expected 12, and expected to be refused by
the real API), the materialized byte count (16), the refusal object for the zero-copy case, and file digests
for the round trip.

### Known answers and negative controls
- KA-777: index [1, 1] is element 3; the negative-stride view addresses (1, 0, 3, 2).
- Negative control (registered for INT-FNP-02): a planted converter that copies the stride numbers verbatim, run on a 16-element buffer filled with 0 to 15, reads 12 at [1, 1]; the test must fail on it. A control that is not caught fails the gate.
- Negative control for INT-FNP-01: a file with one flipped payload byte must be reported as different on read-back comparison.
- Counterexamples protected: "a stride tuple means the same thing in every array library" (CX-353) and "strides can be copied verbatim between array libraries" (CX-218).
- Metamorphic relation: transposing a view (swapping two axes of shape and strides) commutes with conversion.
- Determinism lanes: all results identical on both platforms; file bytes identical across platforms for the same input.

## Considerations

- Quiet NaN payloads survive widening and narrowing on the project's two platforms, but telemetry columns do not store NaN as data (a masked sample carries a reason elsewhere); the round-trip test excludes signalling NaNs and records what it observes for quiet ones.
- The converter does not inspect element type beyond its size; endianness is fixed little-endian at the boundary and recorded in the file header by `fnp-io`.
- A materialized copy is charged to the caller in bytes so that budgets see it; a silent copy of a multi-gigabyte tensor would otherwise look like a zero-copy hand-off.
- If INT-FNP-01 fails, the fallback is plain binary columns with a small header owned by Chronicle, and the oracle use is dropped; nothing on the M1 path depends on franken_numpy.
- When FD-FNP-01 lands upstream, the local converter is replaced by the sibling's named conversion and INT-FNP-02 is re-run at the new pin.
