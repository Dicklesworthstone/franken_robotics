## Background

The **memo graph** of FrankenRobotics is one content-addressed store in front of every verb's executor: the
`Memo` trait is declared in `frob-core`, wraps executors in `frob-verbs`, and stores in `frob-chronicle`. At M1
it serves analyses (exact results, determinism class D0). This bead extends it to the most expensive node kind:
the **episode**, one rollout of one world.

What makes episode reuse safe is narrow, and the bead is about keeping it narrow. Determinism classes (DESIGN,
from the numerics chapter): **D0** exact (integers, rationals, digests; the same bytes everywhere); **D1** the
same bits on CPU, CUDA and Metal (a hypothesis to be measured per kernel set); **D2** the same bits on repeat
on one device family, under any permutation or regrouping of worlds; **D3** agreement within tolerance with a
decision-level equivalence test; **D4** uncontrolled. An episode memo hit is served within same-backend D2 (or
D1 where the device family holds it) and **never across a D3 boundary**, because "bit-identical or not served"
is the only reuse rule that cannot change a statistic.

"On one fingerprint" sharpens "same backend". The hardware fingerprint (`frob.fingerprint/1`) records a
machine state: device family and identifier, driver, runtime, compiler, the IEEE probe digest and the
attainable class. A driver or compiler update can change kernel bits while every model, scene and kernel
identity stays the same. So an episode's key carries the fingerprint digest, and **an episode recorded on
another fingerprint is not served** (the seed done-condition).

Where the reuse is, and is not: the comparison that follows a 2,048-world run of the previous design version on
the same scene reuses that version's episodes at the comparison's addresses; a controller-only edit reuses
every model analysis; a mass or geometry edit reuses no rollout. The incumbent is this project's own reference
path, full recomputation, and the mechanism is adopted through a shadow run first.

Gates: the episode part of **GATE-ATEL-12** (incremental evaluation with the memo graph equals full
recomputation, obligation PO-ATEL-07; a shadow mismatch stops serving within one hit) and **INT-FSQL-02**
re-run on episode traces (the store's eviction sequence equals FrankenSQLite's three-queue pager policy on
recorded traces; first recorded at M1 on analysis traces by bead N33c-20).

## Scope

In: the episode node kind (key, class rules, serve rule, shadow recomputation); fingerprint scoping; byte
accounting and pins for episode entries; rollout order and the `--no-memo` path; the INT-FSQL-02 re-run with
episode traces; the episode part of GATE-ATEL-12.
Out: the graph and analysis nodes (BD-111); the eviction policy and its oracle harness (N33c-18, N33c-19, N33c-20); comparison and
summary nodes, which are derived and recomputed from memoized episodes (BD-262); revalidation across stacks
(BD-292); the latency percentiles of `design.check` (the analysis part of the gate).

## Technical approach

**Episode key (derived, never written by hand).** A key is generated from the declared inputs of the node
kind: model identity; scene identity; task identity; controller or policy identity; the world address (run
seed lineage, world, replicate, episode); tier and step profile; step-plan identity (shape class, capacities,
contact law, sensor layout); kernel versions; effort profile; device family; **fingerprint digest**;
determinism class attained by the backend for this kernel set; and the stack-lock digest (results computed
through the airlock) with the stack receipt hash recorded beside the entry. The key is the BLAKE3 of the
canonical encoding of that tuple.

Two tests are generated for the node kind from the same declaration, so that a missing input cannot hide: a
*key test* that perturbs every declared input and requires the key to change; and a *live-dependency test*
that perturbs every field the computation reads and requires the key to change or the output to stay the same.

**Value.** Not the trajectory: the episode's ledger rows and chunk references (outcome, T0 metrics, the chain
of state digests, the content hashes of its column files) and a byte size for accounting. Chunks are
content-addressed in Chronicle, so serving a hit republishes nothing.

**Serve rule (in order).**
1. `--no-memo` on the request: do not look up; compute; still store.
2. Class check: the request's required class and the entry's attained class must both be D2 or better on the
   same device family (or D1 where recorded as attained); a request or entry at D3 or D4 is never served and
   never stored as an episode node.
3. Fingerprint check: the current fingerprint digest of the executing device equals the key's. This is implied
   by key equality; it is also checked explicitly at serve time against the live device, so that a store
   copied to another machine or surviving a driver update serves nothing. A missing or stale fingerprint is
   `FROB-REF-606` for the computation and a miss for the memo.
4. Stack check: same stack (the receipt of the entry equals the binary's; bead N33a-06). Otherwise a miss.
5. Lookup by key. A hit returns the stored rows with `memo: {hit: true, key, shadowed: bool}` in the envelope.
6. **Shadow recomputation**: one hit in 64, chosen by the memo graph's one shadow selector (implemented by the
   store policy N28b-38 and wired by BD-111), never by a second rule: each episode node has a durable hit
   ordinal n (incremented in the serve transaction) and a phase p = the low six bits of BLAKE3(kind ‖ kind
   version ‖ key), and a hit is shadowed when (n + p) mod 64 = 0, so every window of 64 consecutive hits of one
   episode node holds exactly one shadowed hit (a stale entry is found within 64 of its own hits however it is
   requested), and among episodes hit once each, one address in 64 is shadowed, chosen by key hash. (A single
   ordinal per kind was rejected: hits that recur with a period sharing a factor with 64, such as two designs
   compared alternately, would leave one of them never shadowed.) For a batch, the hits are known when the
   batch is planned: the planner reserves the ordinals of every node the batch hits in a single store
   transaction and assigns them to the batch's hits in address order, so the shadowed addresses of a batch do
   not depend on the order in which concurrent workers finish, and replaying the batch against the same store
   state shadows the same addresses. The shadowed episode is recomputed and its state-digest chain
   compared with the stored one. A single mismatch stops serving the episode node kind immediately (within one
   hit), marks the run `determinism-violated`, and files the violation with both chains and the first differing
   tick. Serving resumes only by the memo graph's one lift rule (N28b-38, wired by BD-111): `Memo::reenable(kind, explanation)`
   with an explanation record that names the violation, its cause and its fix (for an episode kind, normally a
   kind-version bump or a changed code identity) and carries a re-run of the mismatching episode under the fixed
   code that equals the fresh chain byte for byte twice; a restart, a store deletion or a bare version bump does
   not lift it.

**Why a hit equals a recomputation.** Results are placed by world index and random streams are keyed by
address, and a world's digests do not depend on its batch size, slot or co-tenants (class D2, an invariant of
the dynamics and chronicle subsystems). So recomputing one address alone, or inside any batch, yields the same
bits. Tolerance-level reuse is never allowed for episodes.

**Statistics over memoized episodes.** A study's statistic is a pure function of per-address outcomes taken in
address order; it does not depend on which outcomes were memo hits. A comparison recomputed from memoized
episodes reaches the identical e-value.

**Store.** Byte budget (64 GB by default); eviction by the three-queue policy of beads N33c-18 and N33c-19 with admission
weighted by recompute cost (an episode's cost is its device-seconds); nodes in the evidence closure of a live
claim are pinned. The store can be deleted at any time without losing a result a claim cites, because cited
evidence is pinned in Chronicle and not in the cache.

**Rollout and rollback.** Shadow only (compute everything, compare with what would have been served, serve
nothing), then D0 analyses, then D2 episodes. Demotion is one flag.

**INT-FSQL-02 on episode traces.** Three traces of at least 10⁵ accesses recorded from episode-level use (a
paired comparison after a version bump; a sweep over a design population; a training evaluation loop) are
added to the trace set and compared against the sibling policy in unit mode, as at M1.

Determinism: the memo layer is D0 bookkeeping. Evidence: a served result carries the evidence class of the
original computation and the flag that it was served; it is never upgraded.

## Acceptance criteria

- [ ] Episode part of GATE-ATEL-12, with N28b-42 (the battery, which depends on this bead and records the gate row): over random edit sequences of a design, scene, controller and task, evaluation with the memo graph equals full recomputation (identical ledger rows and digest chains) on the episode lane's seeds (0 to 999 on `batch-cpu` in `f64` and `f32`, 0 to 99 on each GPU backend present: N28b-42's DESIGN split of PO-ATEL-07's 10⁴ sequences, all of which the analysis lane of N28b-40 runs), and a planted shadow mismatch stops serving within one hit. This bead supplies the mechanism and the unit tests below.
- [ ] INT-FSQL-02 holds on the three episode traces (zero differences in eviction sequence under the bijection), recorded at this bead's pin.
- [ ] An episode recorded on another fingerprint is not served (seed done-condition): with the fingerprint digest changed (a synthetic driver-version change), every lookup is a miss and the envelope says why.
- [ ] A D3 or D4 episode is neither stored nor served; a D2 episode from `gpu-cuda` is not served to a `gpu-metal` or `batch-cpu` request unless D1 is recorded as attained for that kernel set.
- [ ] A controller-only edit reuses no rollout of the edited controller and every model analysis; a version bump followed by a comparison at the same addresses reuses the previous version's episodes (hit count equals the number of shared addresses).
- [ ] The comparison's e-value with memo hits is bit-identical to its e-value with `--no-memo`.
- [ ] The key test and the live-dependency test pass for every declared input, and fail on the planted omission of one input.
- [ ] Cancellation is tested: a run cancelled mid-batch stores episode nodes only for episodes whose chunks were committed whole, and a later request recomputes the rest; the memo policy's section of `CONTRACT.md` in `frob-verbs` states the serve rule, the loss ratio, the budget and the safe mode (`--no-memo`, full recomputation).

## Test plan

### Unit tests (`cargo test -p frob-verbs memo::episode`)
- `episode_key_changes_with_each_input`: the thirteen declared inputs of the key tuple, each perturbed in turn.
- `episode_live_dependency`: every field the executor reads is perturbed; the key changes or the output is unchanged.
- `planted_missing_input_caught`: a key derivation that omits the effort profile serves a stale hit, and the live-dependency test fails.
- `other_fingerprint_not_served`, `stale_fingerprint_is_miss_and_606_for_compute`.
- `d3_not_stored_not_served`, `cross_family_requires_d1`.
- `other_stack_not_served`.
- `shadow_selects_exactly_one_per_window_of_64`: one episode key requested 64,000 times is shadowed exactly 1,000 times, once in every window of 64 of its hits; two keys requested alternately 6,400 times each are each shadowed exactly 100 times; over 64,000 distinct keys hit once each, 1,000 ± 100 are shadowed; the selector is N28b-38's (one implementation, called, not copied).
- `shadow_batch_ordinals_in_address_order`: a batch of 300 hits planned once and executed by 8 workers finishing in random orders shadows the same addresses in every run; replaying the batch against a copy of the same store state shadows the same addresses.
- `reenable_requires_explanation_record`: after a planted mismatch, a restart, a store deletion and a bare kind-version bump each leave the kind disabled; `Memo::reenable` with an explanation record lacking the byte-equal re-run is refused; with the complete record the kind serves again.
- `shadow_mismatch_stops_within_one_hit`: after the planted mismatch the next lookup of the node kind is a miss with reason `serving-stopped`.
- `hit_equals_recompute_bitwise` (on `batch-cpu`, synthetic small model): 1,000 addresses computed in one batch, then each recomputed alone; digest chains equal.
- `statistic_independent_of_hits`: an e-process over 512 pairs with a random half served from memo equals the all-computed value bit for bit.
- `pinned_episode_survives_eviction`, `byte_budget_holds`.
- `no_memo_flag_bypasses_lookup_but_stores`.

### End-to-end script and logging
`scripts/e2e/memo_episodes.sh`: on `batch-cpu` and, where a device is present, on one device family. Every
call of a run or mutate verb carries its own `--key`, so that no rerun is answered by the first call's stored
receipt. (1) `frob eval run <design> --task <t> --worlds 2048 --run-seed 17 --tier batch-cpu --key me-run-1
--json`; (2) apply a controller-only edit (`--key me-edit-ctl`) and run again (`--key me-run-2`); (3) bump an
unrelated design field (`frob design edit … --expected-parent <id> --key me-edit-bump --json`), then compare
the two versions at the addresses of step 1 as a paired anytime study: `frob study plan <manifest> --json` and
`frob study submit <plan> --key me-cmp-1 --json`, polled with `frob study status` (N33b-19's verbs; before
M3 `eval.compare` answers only its CPU referee form, N33b-19, and its full row arrives with BD-262); (4) the same submit with `--no-memo --key me-cmp-2`; (5) replace
the fingerprint with a synthetic one and rerun step 1 (`--key me-run-3`); (6) enable the planted shadow
mismatch and rerun (`--key me-run-4`). It asserts hit counts, digest equality between memoized and recomputed runs, bit-identical e-values in
steps 3 and 4, zero hits in step 5 and serving stopped after one hit in step 6. Logging per `STD-E2E`: every
line with `ts`, `script`, `bead`, `step`, `event`, the command, exit code, wall time, the envelope's `evidence`
block (claim, class, tier, determinism, identities, seed) and the `memo` block; `metric` lines for hits,
misses, shadowed hits, device-seconds saved, the e-values; digests with the first differing tick on failure; a
`summary` naming INT-FSQL-02 and GATE-ATEL-12.

### Known answers and negative controls
- Known answers: incremental equals full on 10⁴ edit sequences (PO-ATEL-07); identical e-values with and without memo hits.
- Negative controls (registered for GATE-ATEL-12): an input missing from a key (caught by the shadow recompute within 64 hits and by the live-dependency test); a planted nondeterministic reduction in a kernel (the shadow comparison must fire); an entry copied from another fingerprint (must not be served).
- Counterexample protected: a plan-time pilot showed that a correctly keyed dependency graph and a semantic receipt give the same answers, and that omitting one dependency inherits a stale promotion.
- Metamorphic relations: the set of served keys is invariant under the order in which a batch's worlds complete; hit counts are invariant under shard count.
- Determinism lanes: twice on one machine; across worker counts; debug and release; across platforms each against its class (no cross-family hit unless D1 is recorded).

## Considerations

- A stale result served is costed at 100 units against the device-seconds of a needless recomputation (DESIGN ratio in the memo policy's contract); every rule above errs toward a miss.
- A driver update invalidates every episode entry of that machine at once. That is the correct cost of not knowing whether bits changed; the compatibility of old and new results is a matter for the CPU-versus-device check, not for the cache.
- Privacy: an episode entry inherits the private mark of its scene; a private entry is never served to a session without the scope, and eviction of a purged scene's entries is immediate.
- Memory and disk: values are small rows and references; the column files they point to are governed by Chronicle's retention.
- If the fingerprint cannot be attained on a device (the probe shows no controlled class), episodes on that device are never memoized.
