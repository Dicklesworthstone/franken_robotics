## Background

Tether is the surface subsystem of FrankenRobotics: the command line, the daemon, the MCP server, and two
things for a person watching: a terminal **dashboard** and a browser **viewer**. Both are conveniences. No
claim and no agent workflow depends on either; an agent that cannot see reads every number through verbs.
That ceiling is stated first because it bounds the effort: this bead must never become a private interface or
a second source of truth.

**The dashboard, `frob-tui`**, is built on FrankenTUI, the owner's terminal UI library (foundation row
`FD-FTUI`, Consume, Frontier, confined to `frob-tui`). FACT (read 2026-11-21): workspace version 0.10.0 on
`nightly-2026-08-31`, twenty crates, about 1.15 million lines; an Elm-style runtime (`Model`, `Cmd`) in
`ftui-runtime`; an inline mode that keeps scrollback; a pane workspace (`PaneTree` in `ftui-layout`); widgets
`Table`, `Sparkline`, `ProgressBar`, `Tree`, `Tabs`, `LogViewer`, `JsonView` and `StatusLine`; `BarChart` and
`LineChart` in `ftui-extras`; a test harness with shadow-run comparison and determinism fixtures in
`ftui-harness`. FACT: `ftui-runtime` has an optional `asupersync-executor` feature pinned exactly to asupersync
0.5.0 (`crates/ftui-runtime/Cargo.toml:56, :81`). The whole build graph of this project holds exactly one
asupersync package and 0.5.0 never enters a graph, so that feature is forbidden: FrankenTUI is consumed with
default features off and `runtime` and `native-backend` on.

**The viewer** is an ordinary Three.js r186 page that consumes telemetry snapshots; replays are exported as
one self-contained HTML file. It never feeds anything back to physics: the simulator owns state and the viewer
reads immutable snapshots. FrankenThreeD (foundation row `FD-F3D`, Pattern and Subprocess, Frontier) offers an
optional packaging route for it. FACT: four crates; its status table says Three.js r186 is pinned, an ingest
command routes an ordinary application's WebGPU renderer to a new backend for an admitted feature subset,
pixel parity holds for ten scenes on a software rasterizer, no hardware run and no speedup have been measured,
and single-file packaging is not built; it pins asupersync 0.5.0 and `serde_json = "=1.0.151"`. So it is never
a Cargo dependency: it is a subprocess of the viewer's build scripts, and the self-contained HTML export is
this project's own build step.

Tier and pilots: both items are Frontier, and each gate is also the pilot of its item, run on recorded data
before the crate or route is funded (beads N33c-23 and N33c-24, on which this bead depends). Kill gate
KILL-TUI is decided at M3.

## Scope
After integration this seed is the capstone of the dashboard and of the viewer overlays: its parts are built by
the component beads, which are its dependencies, and it assembles them, records the three gates and reads the
decision. The parts: the dashboard core and its event-stream client (N32b-06); the Races, Budgets and Evidence
panes and the gate view (N32b-07); the Devices, Queue and Failures panes (N32b-08); the dashboard conformance
script (N32b-09); the viewer page and its packaging with the plain bundle and the optional FrankenThreeD route
(N32b-10, N32b-13); the overlay interface and the ten overlays (N32b-11, N32b-12); the viewer conformance script
(N32b-14); the two pilots that precede funding (N33c-23 for frankentui, N33c-24 for the renderer route).

In (specified here and nowhere else): the assembly of those parts into the crate `frob-tui` and the viewer
release; the admission records of INT-FTUI-01 and INT-F3D-01 re-run at the M3 pin in production use (an
admission is never inherited; the pilots N33c-23 and N33c-24 hold the first values and are the recorders of
those two gates' rows, one M3 part each, so this bead enters no row for them); the record of GATE-TETHER-14 from
the two conformance scripts, of which this bead is the recorder, citing the outcome of KILL-TUI, which the

and the two admission checks at one pin and writes the measurement records from which the GATE-TETHER-14 row

see the end-to-end section).

## Technical approach

### Part 1: the dashboard

**Rules (DESIGN).** (1) The dashboard issues only `read` verbs, plus `job.cancel` under a token that holds that
scope and after a confirmation. (2) It has no private interface (decision ADR-TETHER-10): every number it shows
comes from a verb's envelope or from the daemon's public event stream, and the pane definition names that
source. (3) It reads the event stream over the local socket and links no physics crate and no airlock group.
(4) It is optional: nothing depends on it.

**Panes.**

| Pane | Shows | Source verb |
|---|---|---|
| Races | Survival brackets of each race and ladder rung; per pair the e-value, pairs used of the cap, the verdict; cancelled candidates | `opt.status` (from M4; at M3 the pane names it as not built, N32b-07), `study.status` |
| Budgets | Per agent: GPU seconds, CPU core-seconds and disk spent and left; the qualification error budget with each submission's αᵢ = α/[i·(i + 1)] and the sum spent | `session.show`, `eval.scorecard` |
| Devices | Per device: a slot strip coloured by job and agent, the reserve, environments by shape class, arena and kernel-cache use, requested and actual placement of each stage, temperature on the Mac | `spark.devices`, `job.list` |
| Queue | Jobs by size class with wait, estimate against actual, the calibration of the estimate interval, preemptions | `job.list` |
| Failures | Latest autopsies with first cause and stability; new minimal counterexample worlds | `autopsy.show`, `nemesis.hardset` |
| Evidence | Promotions, results still provisional, alarms from the fidelity ledger and the exchangeability monitor | `eval.scorecard`, `telemetry.summary` |

A seventh view, gate status, is generated from `registries/gates.toml` and from nothing else.

**Structure (built by N32b-06; the properties the gates rely on).** `Model` holds the latest envelope of each
source verb and a ring of events; `update` is a pure function of (model, message); `view` renders panes from
the model only and reads no clock. A recorded trace (the sequence of event-stream messages and verb envelopes,
canonical JSON lines, format `frob.tui-trace/1`) therefore determines every frame. Idle behaviour: no redraw
without a message; the next poll of a source is due after the larger of the pane's minimum interval and the
`poll_after_ms` the daemon's last envelope carried.

**Number reproduction (pointers by N32b-06; the comparison by N32b-09).** Each displayed number carries, in the
model, the JSON pointer into its source envelope. The test harness re-issues the source verb against the
recorded daemon state and compares.

### Part 2: the viewer overlays

The page the overlays are drawn in is N32b-10's: it reads immutable snapshots through one interface
(`SnapshotSource`: the embedded blocks of a replay, or read verbs in live mode), draws the nearest stored
frame with no interpolation, and exposes the headless test entry the probe tests drive. The overlays
(N32b-11, N32b-12) are what this part of the capstone is about. Each overlay draws a physical quantity from a named telemetry channel, with its unit, a numeric legend and the
evidence class of the run, and is a pure function of the snapshot.

| Overlay | Quantity |
|---|---|
| Contact cones | The four-dimensional cone at each contact (normal, two tangential, spin) with friction utilization as colour; the contact wrench as an arrow |
| Film and friction map | Film thickness and effective friction on floors, including film the robot has moved |
| Clearance | Doorways and passages of a clearance complex, passable or not, with the bottleneck named |
| Energy flow | Power per actuator, losses by kind, dissipation at contacts; the numerical residual as its own bar |
| Actuator state | Torque and speed utilization against the card; winding temperature |
| Balance | Centre of mass, support polygon, margin to tipping |
| Sensing | Frusta and rays with occlusion; the seven instants of a sample on a timeline |
| Counterfactual ghost | A fork drawn over its parent, diverging from the first different event |
| World difference | The edits that separate a minimal counterexample world from its nominal world |
| Reality band | The calibrated band around a predicted trace, or the words "no claim" |

An overlay whose channel is absent from the snapshot draws nothing and says so in the legend; it never
interpolates a missing channel. Stills carry the same overlays, and `telemetry.inspect-pixel` returns the
quantity under a pixel with its unit, channel and world address.

**Packaging.** Plain route (always available, the fallback): the page, Three.js r186 vendored by hash, the
snapshot data, no network fetch, one HTML file of at most 15 MB (TARGET). FrankenThreeD route (optional, when
the page stays inside its admitted feature subset): `node tools/ingest/cli.mjs app.html --build-app out
--pack-html replay.html`, run as a subprocess from `viewer/` build scripts at a pinned revision; an unadmitted
feature must fail explicitly, and the build then falls back to the plain route with the reason recorded.

### Gates

- **INT-FTUI-01**: one asupersync package or none in `frob-tui`'s graph; the job pane rendered from a recorded
  event stream equals its stored snapshot in the headless harness; idle processor use at most 2% of one core.
- **INT-F3D-01**: ten reference frames of the replay page built through the route match the plain bundle
  within 1/255 per channel on at least 99.9% of pixels, and an unadmitted feature fails explicitly.
- **GATE-TETHER-14**: a snapshot test per pane on a recorded daemon trace, and every displayed number is
  reproduced by its source verb; on analytic scenes the overlay value under a probe pixel equals the telemetry
  channel within its quantization.
- **KILL-TUI** (decided at M3 by the decision bead N32b-31, which writes its decision record and the kill
  record's `decision` entry; the GATE-TETHER-14 record of this bead cites that outcome, and on `fired` its
  dashboard half is recorded `killed` while the viewer half stands on its own): trigger: FrankenTUI cannot be admitted with one asupersync package, or the snapshot tests cannot
  be made stable. Fallback: no dashboard; `job.list` and `session.show` carry the same
  numbers and the same events are available as line-delimited JSON. If FrankenTUI does not build on T, the
  remedy is an upstream change in FrankenTUI or the toolchain train; the crate gets no toolchain of its own.

- [ ] KILL-TUI is decided by N32b-31, and the GATE-TETHER-14 record cites its decision record and measured trigger values; if it fired, the crate is not shipped and the README says "no dashboard" (N32b-31's firing branch).
- [ ] Every component is closed (N32b-06 to N32b-14, N32b-31, and the pilots N33c-23 and N33c-24), each with its own acceptance met, or, for N32b-06 to N32b-09 after a `do not fund` pilot, `withdrawn`; this bead restates none of their tests with other numbers, and the GATE-TETHER-14 record and the two admission records cite the log files of `tui_panes.sh` (when the dashboard was built) and `viewer_overlays.sh` at the M3 pin.

- [ ] The exported replay is one file of at most 15 MB that opens with networking disabled.
- [ ] `job.cancel` from the dashboard without the scope is refused, and with it requires a confirmation.

## Test plan

### Unit tests (`cargo test -p frob-tui`; viewer tests under `viewer/tests/` run with a headless browser)
The tests of the parts are written in the component beads, named in brackets; they are listed here because the
gate records of this bead cite their results, and this bead adds only the two assembly tests at the end.
- `pane_snapshots_seven` [N32b-09]: each pane rendered in the headless harness from `fixtures/daemon_trace_01.ndjson` equals its stored snapshot.
- `update_is_pure` [N32b-06]: replaying the trace twice yields identical models (canonical bytes).
- `numbers_trace_to_envelopes` [N32b-06, as `cells_have_source_pointers`; the comparison with the re-issued verb is N32b-09's]: every numeric cell has a source pointer that resolves.
- `no_redraw_without_message` [N32b-06]: 10⁴ idle ticks produce zero frames.
- `alpha_spend_column` [N32b-07]: with α = 0.05 the displayed αᵢ for submissions 1 to 4 are 0.025, 0.0083333, 0.0041667, 0.0025 and the sum spent is 0.04 = α·n/(n + 1) for n = 4.
- `cancel_requires_scope_and_confirmation` [N32b-06, as `cancel_hidden_without_scope` and `cancel_requires_confirmation`].
- `overlay_is_pure_function_of_snapshot` [N32b-11]: the same snapshot renders the same overlay buffers.
- `overlay_missing_channel_draws_nothing` [N32b-11, N32b-12].
- `overlay_probe_box_at_rest` [N32b-11; measured end to end by N32b-14]: a 2 kg box on a plane: the contact-cone overlay's total normal force under the probe is 19.62 N within the channel's quantization; friction utilization is 0.
- `plain_bundle_has_no_network_fetch` [N32b-13]: the HTML contains no absolute URL outside data URIs.
- Viewer page tests (frame decoding, anchored poses, no interpolation, picking, frozen snapshots, vendored hash) [N32b-10].
- `gate_records_complete` (this bead): the gate register holds GATE-TETHER-14's M3 part with its measured values, thresholds and the log files it was read from, and the admission records of INT-FTUI-01 (on `not-fired`) and INT-F3D-01 at the M3 pin validate, with the sibling commits and this bead's tier receipt; a measurement record with a missing clause is rejected.
- `kill_tui_outcome_matches_decision` (this bead): the outcome GATE-TETHER-14's record cites equals the decision record of N32b-31, the dashboard half is `killed` exactly when that outcome is `fired`, and on `fired` the workspace manifest does not ship `frob-tui`.

### End-to-end script and logging
`scripts/e2e/dashboard_viewer.sh` is the capstone's script. It does not repeat the steps of the conformance
scripts: it runs `scripts/e2e/tui_panes.sh` (N32b-09) and `scripts/e2e/viewer_overlays.sh` (N32b-14) at one
pin, adds the two admission checks, and writes one measurement record per gate from their logs
(`target/gates/<gate>.json`: measured values, thresholds, sibling commits, the log files read). It never writes
a row of the gate register. Each of the three gates is run in its tier, `FROB_TEST_SEED=<seed> cargo test -p
frob-conformance --test <tier> --features gauntlet-mutations -- <gate>` (`<tier>` is the test target named by
the `tier` field of the gate's record; the entry reads the measurement record above and runs the gate's
controls in the same run). GATE-TETHER-14 is entered from that run's receipt with `cargo run -p
frob-conformance --example record_gate -- --gate GATE-TETHER-14 --receipt <hash>`; for INT-FTUI-01 and
INT-F3D-01 the receipt is cited by an admission record written with `cargo run -p frob-conformance --example
admission -- record --gate <gate> --input <file> --harness-receipt <hash>` (N33a-07's command), and no row is
entered. Rows and passing records are written by a session that did not implement the parts. In order: (1) through
`tui_panes.sh`: starts `frobd` against a recorded job set, runs `frob-tui` headless on the live stream for
60 s, captures panes and CPU time; (2) through the same script: re-issues each source verb with `frob --json`
and compares numbers; (3) its own step: writes a replay packet of an analytic scene with `frob telemetry
export-html`, builds the page by both routes (`node viewer/build/pack.mjs` and `node viewer/build/pack.mjs
--route f3d`, N32b-13; the export verb itself always embeds the committed plain bundle), loads the packet's
data in each page headless, renders ten frames of each and compares pixels (the INT-F3D-01 check at the M3
pin, with the harness of the pilot N33c-24), and counts asupersync packages in `frob-tui`'s graph (INT-FTUI-01); (4) through
`viewer_overlays.sh`: runs `frob telemetry inspect-pixel` at the probe pixels. When N32b-31's decision is
`fired`, steps (1) and (2) and the asupersync count are logged `not-run` citing the decision record, and the
dashboard half's measurement record says `killed`.
Logging per `STD-E2E`: every line with `ts`, `script`, `bead`, `step`, `event`, the exact command, exit code,
wall time and the envelope's `evidence` block; `metric` lines for idle CPU percent (threshold 2), asupersync
package count (threshold ≤ 1), numbers compared and mismatched (threshold 0), per frame the share of pixels
within 1/255 (threshold 99.9%), file size (threshold 15 MB); on failure the first differing cell or pixel and
the artifact paths; a `summary` naming GATE-TETHER-14, INT-FTUI-01, INT-F3D-01 and KILL-TUI. Logs contain no
private-scene data (the fixtures are synthetic).

### Known answers and negative controls
- Known answers: αᵢ = α/[i·(i + 1)] and Σ_{i ≤ n} αᵢ = α·n/(n + 1); the box's weight 2 × 9.81 = 19.62 N.
- Negative controls: a pane that computes a number itself instead of reading it (planted: a locally summed budget) must fail number reproduction when the daemon's value differs; a snapshot with one changed character must fail; a build with the executor feature must fail the asupersync count; an overlay reading the wrong channel must fail the probe test; a frame with a one-level colour shift on 0.2% of pixels must fail the 99.9% rule.
- Determinism lanes: snapshots identical twice on one machine and on both platforms (terminal rendering is to a virtual buffer); frame comparison uses a software rasterizer so that it is machine-independent.

## Considerations

- Ceiling, stated before the work: a convenience for a person watching a campaign. If the snapshot tests are flaky after one repair cycle, KILL-TUI fires and nothing else changes.
- FrankenThreeD's route changes rendering cost only, and rendering is outside every claim of the project; if INT-F3D-01 fails the plain bundle ships.
- FD-FTUI-01 (P3) would relax the executor's asupersync pin; nothing here needs the executor.
- Privacy: a dashboard shows job and scene names; a private scene is not listed without the private scope, exactly as in the verbs it reads.
- Accessibility of the same information without sight is a design rule, not an afterthought: `telemetry.inspect-pixel` and the read verbs carry everything the overlays and panes show.
