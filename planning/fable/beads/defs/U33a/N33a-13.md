## Background

The airlock crate `frob-fsim` adapts FrankenRobotics-native traits to FrankenSim, the sibling physics library
that serves as the **referee** (the most trusted simulation tier). Three rules bind every adapter. This bead
implements the first:

> **It converts, and never reinterprets**: a FrankenSim refusal becomes a typed referee refusal carrying the
> upstream reason, and is never retried with weakened inputs.

Why this rule exists. FrankenSim refuses by name where its models do not apply: more than 21 contacts in one
sustained solve, a contact witness that separates tangentially, a material pair with no data, a spectral
problem outside its admission, an import over a size bound. Those refusals are the behaviour this project
wants from a referee, because a referee that answers outside its validity domain adjudicates with a wrong
number. Three tempting shortcuts would each destroy that property:

1. *Retry with weakened inputs*: drop the contacts beyond the capacity, loosen a tolerance, clamp a parameter
   into range. The contact set of a tracked robot overflows where a point-foot robot's does not, so dropping
   contacts biases exactly the comparison the studio exists to make.
2. *Reinterpret*: report an upstream limit as a physical fact. A reported case: a FrankenSim routine for the
   differential of the SE(3) exponential refuses as "ill-conditioned" for a pure translation of 33 m, a pose
   that is regular. A limit of an owner is reported as `unsupported`, never as a singular pose.
3. *Swallow*: map every upstream error to one generic failure, losing the reason an agent needs to choose a
   repair.

The design rule for the dynamics subsystem (its decision ADR-KIN-06) is the consumer of this bead: where
FrankenSim's limits bind, the system refuses by name and routes the adjudication to the `strict` CPU profile,
recording which adjudicator answered. And its decision ADR-KIN-05 says a retry may change numerical parameters
only (step, iteration plan), never physical ones. The airlock therefore has to tell its callers, per refusal,
what kind of retry is legitimate.

## Scope

In: the type `RefereeRefusal`; the closed mapping from FrankenSim error kinds to refusal codes; the upstream
reason record; the retry class; the structural guarantees that no adapter weakens inputs; the conversion to the
workspace refusal type of `frob-core`.
Out: the capacity check itself (N33a-14); the retry ladder (BD-083); the envelope rendering (BD-022); refusals
that originate in this project and not upstream (`FROB-REF-790`: its value in N33a-11, its envelope in N33c-32;
`FROB-REF-791` in N33c-13; the rows of all three in N33-REF).

## Technical approach

**Types (DESIGN, `frob_fsim::refuse`).**

```rust
#[must_use]
pub struct RefereeRefusal {
    pub code: RefusalCode,              // a registered FROB-REF code; never a free string
    pub kind: RefereeRefusalKind,       // closed enum: Capacity, FixedWitness, IndeterminateContact,
                                        // OutsideDomain, OwnerLimit, Other at M0; FormatVersion and
                                        // AuthorizationFlags added at M1 by N33a-17
    pub upstream: UpstreamReason,
    pub retry: RetryClass,
    pub observed: Option<Measured>, pub required: Option<Measured>,   // e.g. 22 contacts against a cap of 21
}
pub struct UpstreamReason {
    pub crate_name: &'static str,       // "fs-contact"
    pub variant: String,                // the upstream error variant's name, verbatim
    pub message: String,                // the upstream Display text, verbatim, bounded to 2 KiB
    pub pin: StackLockDigest,           // which stack said so
}
pub enum RetryClass { Never, AfterChange, NumericalOnly }
```

`RetryClass::NumericalOnly` means the caller's retry ladder may try another numerical plan (a shorter
sub-interval, another iteration plan) with the same physical inputs. `AfterChange` means the request itself
must change (a different design, scene or profile). `Never` is for integrity failures.

**The mapping is closed and exhaustive.** Each adapter matches exhaustively on the FrankenSim error enums it
can receive, with no wildcard arm. A new upstream variant is then a compile error at the next pin move, which
is the wanted signal: someone must read the new refusal and give it a row. The table at M0 (rows are added by
each adapter bead as its group lands):

| Upstream situation (FrankenSim side) | `kind` | Code | Retry | Ranked repairs carried to the caller |
|---|---|---|---|---|
| A contact set above the solver's capacity (21 on the day of reading) | `Capacity` | `FROB-REF-721` | AfterChange | A documented patch reduction with its qualification fixture; the `strict` profile as adjudicator |
| The sustained step's fixed-witness gate refuses (a witness separates tangentially; the contact frame would change) | `FixedWitness` | `FROB-REF-721` | NumericalOnly | A shorter interval so that witnesses are fixed inside it (witness migration between calls); then the `strict` profile |
| The contact solve reports no solution, or several distinct post-event motions | `IndeterminateContact` | `FROB-REF-224` | Never | Report the configuration; do not return a number |
| An input outside the upstream model's stated domain (an unsupported joint class, a non-finite value that passed our own checks, an inconsistent inertia) | `OutsideDomain` | `FROB-REF-792` | AfterChange | Lower the model as the airlock's contract states; fix the input the upstream reason names |
| A numerical limit of an upstream routine that is not a property of the physical input (a series bound, an iteration cap) | `OwnerLimit` | `FROB-REF-792` | NumericalOnly | Use the path this project owns for that quantity; report `unsupported` |
| Any other upstream error | `Other` | `FROB-REF-792` | Never | Read `upstream.message`; record the case as an upstream work item with a reproducing fixture |

The code for the last three rows is `FROB-REF-792` `referee-upstream-refusal`, registered by the chapter's
refusal registry (N33-REF, a dependency of this bead) with the three kinds as its payload field. `FROB-REF-721`
(exit 5) and `FROB-REF-224` (exit 3), with the repairs quoted in the table, are rows of the dynamics chapter's
registry (N16-REF, also a dependency): this bead and the capacity check of N33a-14 raise them at M0, so those
rows must load at M0. The number was
proposed at integration and is read from `registries/refusals.toml`, never written as a literal outside the
registry: the conformance test below fails on any row whose code is not in the registry, because an unknown code
is a load-time error by workspace rule.

**Rows added by adapter beads.** The `Session` adapter (N33a-17, M1) adds five rows, two of them under two new
arms of `RefereeRefusalKind`, `FormatVersion` and `AuthorizationFlags` (the enum then has eight arms):

| Upstream situation (`fs-session`, `fs-package`) | `kind` | Code | Retry |
|---|---|---|---|
| The package's schema names a major version this build does not read, or a required field the reader's schema does not list | `FormatVersion` (new arm) | `FROB-REF-891` (exit 3, N34-REF) | AfterChange |
| The authorization flags object or a flag is absent, a flag is not the literal `false`, or an extra flag is present | `AuthorizationFlags` (new arm) | `FROB-REF-816` (exit 3, N37-REF) | Never |
| The manifest carries no stack receipt | `OutsideDomain` | `FROB-REF-792` | AfterChange |
| At pack, a manifest string is an absolute path or names a home directory of the writing machine | `OutsideDomain` | `FROB-REF-792` | AfterChange |
| A referenced blob is absent or does not hash to its reference | `Other` | `FROB-REF-792` | Never |

Rule for every adapter: where a registry requires a code of every reader of this system's artifacts (`FROB-REF-891`
for the version gate, `FROB-REF-816` for the authorization flags), the adapter raises that workspace code, with
the pointer and payload of its row, and not `FROB-REF-792`; 792 is reserved for upstream conditions that no
registry names. The two new arms enter the enum with N33a-17, at the milestone where N34-REF's row 891 loads,
so that `all_codes_registered` holds at every milestone.

**Conversion function per adapter.** `fn convert(e: fs_x::Error, ctx: &CallCtx) -> RefereeRefusal`, one per
FrankenSim crate, private to the group module. It copies the variant name and the message verbatim, attaches
the lock digest, fills `observed` and `required` where the upstream error carries numbers, and never inspects
the message text to decide behaviour (the variant decides; text is for people).

**No weakening, structurally.**
1. Adapter functions take their inputs by shared reference and have no optional "relaxed" parameters: there is
   no argument named or meaning tolerance scale, contact drop policy, clamp or fallback.
2. No adapter module contains a loop or a second call to FrankenSim on the error path. A source-level test
   scans group modules for a FrankenSim call lexically inside a `match … Err` arm or after an `if let Err`.
3. `RefereeRefusal` is `#[must_use]`, and there is no `From<RefereeRefusal>` into a success type.
4. The capacity path's planted mutant (truncate to the first 21 contacts and retry) and the test that catches
   it (`truncation_mutant_caught`) are N33a-14's, which owns the capacity check and depends on this bead.

**Conversion to the workspace refusal.** `impl From<RefereeRefusal> for frob_core::Refusal` fills `code`,
`message` (this project's text for the code), `pointer`, `observed`, `required`, `unit`, `retry` (`never`,
`after-change`; `NumericalOnly` is presented as `after-change` to an agent, with the repair list saying which
numerical plan or profile to request), ranked `repairs` in the order of the code's registry row for its payload
kind (for 721 `fixed-witness`: the shorter interval, then `--profile strict`), and an `upstream` object with crate, variant, message and pin. For
`FROB-REF-792` the `pointer` is `referee/<crate>/<variant>` (for example `referee/fs-mbd/InconsistentInertia`)
and the payload's `kind` is `outside-domain`, `owner-limit` or `other`, as N33-REF's row states; for 721 and
224 the pointer and payload are those of N16-REF's rows. The upstream message is data, never instructions, and
is marked as sibling-originated text in the envelope.

**Recording.** Every referee refusal that ends an adjudication is written to the run's terminal receipt as a
numerical refusal, kept separate from a budget stop and from a physical failure of the robot (three outcomes
that are never merged).

Determinism: conversion is a pure function. Evidence: a refusal carries no claim.

## Acceptance criteria

- [ ] Every adapter in the `referee` group matches exhaustively on its upstream error type (a test compiles a fixture that adds a variant to a mirrored enum and expects a compile failure; and a grep finds no `_ =>` arm in conversion functions).
- [ ] Each row of the table is produced by a real FrankenSim call at the pin where one can be provoked at M0 (capacity: 22 contacts; fixed witness: the flat-to-edge transition; outside domain: a non-finite input injected below our own check in a test build), with the upstream variant and message preserved verbatim.
- [ ] Every `code` in the table is present in `registries/refusals.toml`; the test fails on a missing or placeholder code.
- [ ] No adapter function has a relaxed-input parameter, and the source scan finds no FrankenSim call on an error path.
- [ ] `frob_core::Refusal::from` a converted capacity refusal carries `code = "FROB-REF-721"`, `observed = 22`, `required = 21`, the two repairs in the registry's order, and an `upstream` object with crate `fs-contact`; the same fields through `frob --json` are asserted at M1 by N33ap1-01's step `capacity_overflows`, once the referee contact step of BD-080 makes a contact set reachable through `frob`.
- [ ] `CONTRACT.md` of `frob-fsim` lists the mapping table in its refusals section.

## Test plan

### Unit tests (`cargo test -p frob-fsim refuse`)
- `convert_capacity`: upstream capacity error with 22 against 21 → kind `Capacity`, code 721, retry `AfterChange`, observed 22, required 21.
- `convert_fixed_witness`: → kind `FixedWitness`, code 721, retry `NumericalOnly`.
- `convert_indeterminate`: → code 224, retry `Never`.
- `convert_preserves_message_verbatim`: a message with unusual characters and length 3 KiB is carried, truncated at 2 KiB with an explicit truncation marker, never reworded.
- `convert_attaches_pin`: `upstream.pin` equals the binary's lock digest.
- `all_codes_registered`: every code of the table loads from the registry.
- `no_wildcard_arm_in_convert` and `no_fsim_call_on_error_path`: the two source scans.
- `no_relaxed_parameters`: the public signatures of the group modules contain none of the words tolerance-scale, clamp, drop, fallback as parameter names (a deny-list test on the API listing).
- `retry_class_presentation`: `NumericalOnly` renders as `after-change`, with the repairs in the order of N16-REF's row for its payload kind: for 721 `fixed-witness` the shorter interval first, then `--profile strict`.
- `into_workspace_refusal_upstream_792`: an `OutsideDomain` refusal from `fs-mbd` converts to code 792 with `pointer` `referee/fs-mbd/<variant>` and payload `kind` `outside-domain`; an `OwnerLimit` and an `Other` give `owner-limit` and `other` with retry `after-change` and `never` respectively, matching N33-REF's row.
- `into_workspace_refusal_capacity`: the converted capacity refusal into `frob_core::Refusal` → code 721, observed 22, required 21, unit `contacts`, retry `after-change`, the registry's two repairs in order, `upstream` with crate, variant, message and pin, and the sibling-originated marker on the message.
- Property test `conversion_is_total_and_pure`: for every constructible upstream error in a generated corpus, conversion returns a refusal with a registered code, and twice gives identical bytes.

### End-to-end script and logging
`scripts/e2e/airlock_refusals.sh`, its M1 steps (bead N33ap1-01; at M0 no `frob` verb reaches a contact set,
so the conversion is proved by the unit tests above until then). Step `capacity_overflows` drives `frob` to a
referee capacity refusal on a fixture with 22 contacts and asserts the envelope fields above and exit code 5 for
the `72x` code; step `upstream_refusal` provokes a refusal raised by FrankenSim itself (the fixed-witness case)
and asserts the upstream variant and message verbatim and exactly one upstream call. Both log the refusal
object, the upstream variant and message, and the lock digest.

### Known answers and negative controls
- KA-778's control: a set of 22 contacts returns the typed capacity refusal.
- Negative controls (planted defects): a conversion that rewrites the message (must fail `convert_preserves_message_verbatim`); a wildcard arm that maps an unknown variant to capacity (must fail `no_wildcard_arm_in_convert` and the exhaustiveness fixture). The truncate-and-retry mutant is N33a-14's.
- Counterexamples protected: "when a world exceeds its contact capacity the extra contacts can be dropped" (a tracked design against a point-foot design under an artificially low cap must not be compared as if both were simulated); "the referee can adjudicate every scenario the fast tiers run" (a sole with eight samples per foot fits when standing, 16 contacts, and overflows in a fall).
- Determinism lanes: refusal bytes identical twice and across debug and release.

## Considerations

- The share of scenarios the referee completes is a reported figure with its own gate in the dynamics subsystem; this bead makes the numerator honest by ensuring a refused scenario is counted as refused.
- Exhaustive matching makes pin moves noisier. That is the price of knowing about every new upstream refusal on the day it arrives; the breakage ledger counts those days.
- An upstream message may contain a file path of the sibling; it is repository-relative in FrankenSim's own errors, and the converter strips any absolute prefix before storing it.
- If the worker-process fallback is active, the worker runs the same conversion and sends `{ job_hash, code, upstream_reason }`; the client does not re-map.
