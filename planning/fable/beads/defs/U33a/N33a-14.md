## Background

The airlock crate `frob-fsim` adapts FrankenRobotics traits to FrankenSim, the referee of the system. The third
of its three binding rules is the subject of this bead:

> **It exposes capacities as data**: the 21-contact limit is a field of `RefereeContact`, checked when a model
> is compiled and again at run time, so that an over-capacity contact set is a refusal by name and is never
> silently truncated.

FACT (read 2026-11-21, re-read at the pin by the fact probes): FrankenSim's sustained contact solver admits at
most 21 contacts (`frankensim/crates/fs-contact/src/sustained/solve.rs:26`, `pub const MAX_CONTACTS: usize =
21`, also the default budget of its frictional multi-contact solve). Its articulated contact step
(`articulated_contacts::step::step_articulated_frictional_contacts`) is first-order kick-contact-drift, takes
the contact set from the caller, and states that independent endpoint gap checks are not continuous collision
detection. Its sustained step keeps fixed material witnesses and a fixed contact frame and refuses when a
witness separates tangentially.

Why the capacity must be data and not an error discovered late. A single robot is one contact island, because
every foot couples through the floating body. A sole with eight samples per foot fits when a biped stands (16
contacts) and overflows in a fall or a crawl. Six feet down with four samples each is 24. A tracked robot with
patch samples along two belts overflows in normal driving. If the limit surfaced only as a mid-run error, a
comparison between a point-foot design and a tracked design would be decided by which one the referee happened
to be able to simulate. Exposed as a number, the limit lets the model compiler say before any run which
stances the referee can adjudicate, lets the fidelity reports state the share of scenarios the referee
completes, and lets the caller choose a documented patch reduction or the `strict` CPU profile instead.

Rejected alternative: truncate to the 21 deepest contacts and continue. Dropping contacts biases exactly the
comparison the studio exists to make, and it would do so silently.

## Scope

In: the trait `RefereeContact` and its capacities record; the static check used at model compile; the run-time
check before every upstream call; the in-process adapter over FrankenSim's articulated contact step for a
caller-supplied contact set; the over-capacity refusal.
Out: generating contact sets (BD-079); the transactional step, witness migration and the energy ledger around
the call (BD-080, BD-081, BD-093); the admission tests INT-FSIM-04 and INT-FSIM-07, which another unit runs
through this trait (BD-035); patch reductions and their qualification fixtures (the contact subsystem).

## Technical approach

**Trait (DESIGN: intent, not signatures; module `frob_fsim::referee::contact`, feature `referee`).**

```rust
pub trait RefereeContact {
    fn capacities(&self) -> ContactCapacities;
    fn check_static(&self, bound: &ContactBound) -> Result<CapacityReport, RefereeRefusal>;
    fn step_frictional(&self, m: &RefereeModel, s: &RefereeState, tau: &[f64],
                       contacts: &ContactSet, h: Rational) -> Result<ContactStep, RefereeRefusal>;
}
pub struct ContactCapacities {
    pub max_contacts_per_solve: u32,     // read from FrankenSim's public constant at build time; 21 at the pin of reading
    pub fixed_witnesses: bool,           // true: witnesses and contact frame are fixed inside one call
    pub contact_set_from_caller: bool,   // true: no contact generation, no continuous collision detection inside
    pub source: SiblingFactRef,          // the fact-registry row this value was read under
}
pub struct ContactBound { pub islands: Vec<IslandBound> }       // from the model compiler
pub struct IslandBound { pub name: String, pub stance_sets: Vec<StanceSet> }
pub struct StanceSet { pub label: String, pub contacts: u32 }   // e.g. "stand: 2 feet × 8 samples" = 16
pub struct CapacityReport { pub capacity: u32, pub fits: Vec<String>, pub overflows: Vec<(String, u32)> }
```

**The capacity is never a literal in this repository.** `max_contacts_per_solve` is initialized from
FrankenSim's own public constant. If that constant is not public at the pin, the adapter obtains the value by
the documented route the pin offers (an accessor, or the default budget of the solve configuration), and the
admission record says which. A unit test compares the value with the fact probe's reading, so a silent upstream
change (for example to 24) is seen as a changed fact and not absorbed.

**Check 1, when a model is compiled.** The model compiler passes the contact bound it derives from the
design: per island, the stance sets the design declares or implies (standing, each gait's support pattern,
crawl, fall on side, track patches in driving) with their contact counts (contacts = contact bodies in the set
× samples per body). `check_static` returns which sets fit and which overflow. Policy on the result (DESIGN):
1. The report is stored on the compiled model as `referee_coverage`.
2. A request to adjudicate on the referee a scenario whose declared nominal stance overflows is refused at
   admission, before any step, with `FROB-REF-721` (referee capacity), `observed` the set's count, `required`
   the capacity, and the repairs "patch reduction with its qualification fixture" then "`--profile strict`".
3. A design whose nominal stance fits and whose exceptional sets (fall, crawl) overflow is admitted, with the
   overflow sets listed, so that a later run-time refusal is expected and counted, not a surprise.

**Check 2, at run time.** Before every upstream call: if `contacts.len() > max_contacts_per_solve`, return
the capacity refusal immediately. The upstream solver would refuse too; checking first guarantees the refusal
is ours by name with `observed` and `required` filled, and that no partial upstream state is touched. The
contact set is passed to FrankenSim whole or not at all: the adapter has no code path that selects a subset.

**Step adapter.** Converts the caller's `ContactSet` (per contact: the two body handles, the witness points in
each body's frame, the contact frame, gap, and the friction-law selection with its parameters, all in
FrankenRobotics vocabulary) into FrankenSim's input, calls the articulated frictional contact step for one
interval `h`, and converts the result (new state, per-contact impulses in the contact frame, the upstream
solver's status) back. Every upstream refusal goes through the conversion of bead N33a-13: over capacity and
the fixed-witness gate map to `FROB-REF-721`; no solution or several solutions map to `FROB-REF-224`.

**What the trait deliberately does not hide.** `fixed_witnesses: true` and `contact_set_from_caller: true` are
data for the same reason as the capacity: the transactional step above the airlock uses them to decide that it
must migrate witnesses between calls and audit the path with certified continuous collision detection.

Determinism class: same platform, same binary (the referee's class). Outputs carry the evidence class
FrankenSim's contracts give them. Nothing is cached here; any memoized result above carries the stack-lock
digest in its key.

## Acceptance criteria

- [ ] `capacities().max_contacts_per_solve` equals the value in FrankenSim's source at the pin (21 on the day of reading) and equals the fact probe's reading; no literal 21 appears in `frob-fsim` outside tests and documentation.
- [ ] `check_static` on a bound with stance sets {stand: 16, crawl: 32} returns `fits = [stand]`, `overflows = [(crawl, 32)]`.
- [ ] A referee adjudication request whose nominal stance has 24 contacts is refused at admission with `FROB-REF-721`, `observed = 24`, `required = 21`, before any step runs.
- [ ] A run-time call with 22 contacts returns the typed capacity refusal and makes no upstream call (verified by a call counter in the test build); a call with 21 contacts reaches FrankenSim.
- [ ] The planted mutant that truncates to 21 contacts and proceeds is caught by a test that compares the returned impulse count with the input contact count.
- [ ] The adapter exposes `fixed_witnesses` and `contact_set_from_caller` as true at the pin, each tied to a fact-registry row.
- [ ] The `referee` section of `CONTRACT.md` states the capacity, the two structural limits, the refusals and the interim posture.

## Test plan

### Unit tests (`cargo test -p frob-fsim referee::contact`)
- `capacity_matches_upstream_constant`: equality with the upstream value and with the registry row.
- `static_check_fit_and_overflow`: inputs {16, 21, 22, 24, 32} → fits {16, 21}, overflows {22, 24, 32}.
- `static_check_empty_bound`: no islands → an empty report, not an error.
- `runtime_refuses_22_without_upstream_call`: call counter stays 0; refusal fields asserted.
- `runtime_accepts_21`: 21 point contacts of a fixture body on a plane (synthetic) step once and return 21 impulses.
- `no_subset_path`: the returned per-contact results have exactly the input length for every admitted size 0 to 21 (property test over random sets).
- `truncation_mutant_caught`: the test build with the mutant enabled fails `no_subset_path`.
- `box_on_plane_static_known_answer` (synthetic, four corner contacts, friction coefficient 0.5, box of mass 2 kg at rest, g = 9.81 m/s², h = 1/480 s): the sum of normal impulses over one step equals m·g·h = 2 × 9.81 / 480 = 0.040875 N·s to 10⁻¹² relative, and the box's velocity stays zero to 10⁻¹².
- `fixed_witness_refusal_is_typed`: a tangentially separating witness fixture returns kind `FixedWitness`.

### End-to-end script and logging
`scripts/e2e/airlock_refusals.sh` (bead N33a-29), step `capacity`: a fixture scene with a body resting on 22
contact samples is submitted to the referee through `frob --json`; the script asserts exit code 5, code
`FROB-REF-721`, `observed = 22`, `required = 21`, and that the same fixture with 21 samples runs. Logged: the
capacity as reported by `frob doctor --json`, both envelopes, the contact counts.

### Known answers and negative controls
- KA-778 (control half): over capacity, 21 contacts, refuses. Box at rest: Σ normal impulse = m·g·h = 0.040875 N·s.
- Negative controls: the truncation mutant; a build with the run-time check removed (the upstream refusal then arrives without `observed`/`required`, and the field assertions fail); a hard-coded capacity that disagrees with a patched upstream constant in a scratch copy.
- Counterexamples protected: extra contacts can be dropped (false); the referee can adjudicate every scenario the fast tiers run (false).
- Determinism lanes: the 21-contact step is bit-identical twice on one machine.

## Considerations

- Upstream work item FD-FSIM-13 (priority P1) asks FrankenSim for a sustained solve above 21 contacts, an island-wise solve, or a documented patch model with a qualification fixture. Interim posture: over-capacity sets refuse by name and patch reductions are declared. Switch-over rule: re-run the capacity fixtures of the contact subsystem; the capacity field then changes by itself because it is read from the sibling.
- FD-FSIM-12 (P1) asks for a moving-surface owner for the sustained step. Interim posture: the referee's transactional step migrates witnesses above the airlock, so each call sees an interval short enough that its witnesses are fixed.
- What M1 can claim follows from these limits: referee rollouts over planes and primitive obstacles are admitted; a wheel climbing a riser is admitted only through the event-located transactional step.
- Performance: the checks are O(1) per call; the conversion of at most 21 contacts is negligible beside the solve.
- If the worker-process fallback is active, `capacities()` is answered by the worker for its own pin, which may differ from the core's.
