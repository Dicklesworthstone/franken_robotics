## Background

The airlock crate `frob-fsim` exposes FrankenSim to FrankenRobotics through traits grouped into Cargo features.
The `ledger` group (on by default) holds `Ledger` (bead BD-009: the transactional metadata store on
FrankenSQLite), and two further traits, `Recompute` (specified and admitted by N33b-15 after integration) and `Session` (this
bead):

- **`Recompute`**, over FrankenSim's `fs-recompute`: a content-addressed Merkle graph of results with slack,
  skip-soundness certificates and invalidation. FACT (read 2026-11-21; re-read at the pin): 3,034 lines of
  library source (5,661 with tests); its closure is 10 other FrankenSim crates plus FrankenSQLite; it needs the
  units crate `fs-qty`; `Store::can_skip` serves a node cached under a looser requirement if it achieved
  enough; it has a determinism trip-wire (`StoreError::DeterminismViolation`), pins that are never evicted and
  an independent checker.
- **`Session`**, over `fs-session` and `fs-package`: packaged sessions and evidence packages. FACT:
  `fs-package` is FrankenSim's evidence-package pattern, with a standalone checker in `fs-checker`.

What they serve. FrankenRobotics memoizes everything downstream of the compiled model in one content-addressed
**memo graph**: the `Memo` trait is declared in `frob-core`, wraps each verb's executor in `frob-verbs`, and
stores in `frob-chronicle`. `fs-recompute` is the candidate store behind it: "it is consumed through the
airlock if admission passes; otherwise the same node record is implemented in `frob-chronicle`". `Session`
serves the export of a run or a report as a self-describing package an outside reader can check.

Why an adapter and not a direct dependency from `frob-chronicle`: `fs-recompute` is a volatile crate coupled to
`fs-qty`, and its tolerance-level reuse rule is wider than this project allows. The adapter is where the
project's stricter rules are applied before anything reaches the store.

Admission is never inherited: `fs-ledger` is admitted with INT-FSQL-01; `fs-recompute` is admitted by its group
gate INT-FSIM-16 at M1 (run by another bead through this trait); `fs-session` and `fs-package` are first used
here and are admitted here by their own record.

## Scope
In: the trait `Session` with its in-process adapter over `fs-session` and `fs-package`; the package rules applied
at the airlock; the admission record for `fs-session` and `fs-package`; adapter-level known answers.
Out: the trait `Recompute`, its node record, the sibling-backed and the local implementation, the reuse rules
and the gate INT-FSIM-16 (N33b-15, which is the single owner of that trait; the reuse rules and tests this draft
had for it are folded there); the memo graph, its key derivation, shadow recomputation and store policy (BD-111,
BD-220); report generation (the Chronicle and Tether units).

## Technical approach

**Traits (DESIGN: intent, not signatures; module `frob_fsim::ledger`).**

```rust
// `Recompute` (over fs-recompute) is specified by N33b-15.
pub trait Session {
    fn pack(&self, manifest: &PackageManifest, blobs: &[BlobRef]) -> Result<PackageId, RefereeRefusal>;
    fn check(&self, package: &Path) -> Result<PackageVerdict, RefereeRefusal>;   // hashes, completeness, schema
}
```

**`Session` rules.** A package manifest never embeds a path on the machine that wrote it; large data are blobs
addressed by hash; a package carries the schema name, the three no-authorization flags (all false) and the
stack receipt of the binary that wrote it; `check` recomputes every hash and refuses a package with a missing
blob, an unknown schema major version or a flag that is missing or true.

**The refusals, as rows of the airlock's closed mapping.** A `RefereeRefusal` carries a registered code and
never a free string, and each adapter bead adds its rows to the mapping table of N33a-13. These are this
adapter's five, checked in this order by `check` (the version gate runs before any field is interpreted, the
flags before any content is read), so that a package with two faults always names the same one:

| Situation | `kind` | Code | Retry | Payload and first repair |
|---|---|---|---|---|
| The package's `schema` names a major version this build does not read, or uses a required field the reader's schema does not list | `FormatVersion` | `FROB-REF-891` (`format-version-unsupported`, exit 3; the workspace registry's code, which every owner's reader raises for this condition) | AfterChange | The `schema` member and both versions; read the package with a build that knows the version, or export it again |
| The flags object is absent, a flag is absent, a flag is `true` or not the literal `false`, or an extra flag field is present | `AuthorizationFlags` | `FROB-REF-816` (`authorization-flags-missing-or-not-false`, exit 3; the safety registry's code for any reader of one of this system's artifacts) | Never | `missing:<field>`, `true:<field>`, `not-false:<field>` or `extra:<field>`; export the package again from its source. No input makes a true flag acceptable |
| The manifest carries no stack receipt | `OutsideDomain` | `FROB-REF-792` (`referee-upstream-refusal`, exit 5) | AfterChange | The missing member; pack again with a build that stamps `BUILT_UNDER` |
| A referenced blob is absent, or a blob's bytes do not hash to its reference | `Other` | `FROB-REF-792` | Never (an integrity failure) | The blob's reference, with the hash expected and the hash found or `absent`; fetch the package again from its source |
| At `pack`: a manifest string that is an absolute path or names a home directory of the writing machine | `OutsideDomain` | `FROB-REF-792` | AfterChange | The JSON pointer of the member; replace the path by a blob reference |

DESIGN, the last three rows: no code of the registries names these conditions, and `FROB-REF-792` is the
chapter's code for an airlock refusal with no dedicated one, with the `kind` as its payload field; a path in a
manifest is not `FROB-REF-734`, which is the refusal of a path *argument* that leaves the session's roots.
`FormatVersion` and `AuthorizationFlags` are not among the six arms `RefereeRefusalKind` has at M0: this bead adds
them to N33a-13's closed enum (which then has eight arms) together with their two rows of N33a-13's mapping
table, at M1, where N34-REF's row 891 loads, and the conversion to the workspace refusal fills their codes from
the registry as for every other arm.

**Admission record.** `covers.crates = ["fs-session", "fs-package"]` with the known answers and controls below;
the `fs-recompute` record is INT-FSIM-16's. This bead fixes the record's content; the record is written under
`--record` by the step `ledger_group_admission` of N33a-34 (which depends on this bead) with N33a-07's writer,
and its existence and validity at the pin are asserted there.

Determinism class: D0 (pure bookkeeping over hashes). Evidence: the store carries digests, never claims.

## Acceptance criteria

- [ ] `Session` compiles under the `ledger` feature with no volatile type in its public face.
- [ ] A package round-trips through `pack` and `check`; a package with one byte of one blob changed, with a missing blob, or with an authorization flag set to true is rejected with the reason named.
- [ ] Each of the five refusal rows is raised with its registered code and retry class (`FROB-REF-891`, `-816`, and `-792` three times), the five rows are in the mapping table of N33a-13, `RefereeRefusalKind` has the two new arms `FormatVersion` and `AuthorizationFlags` (eight in all), and the adapter's match on the upstream error enums of `fs-session` and `fs-package` has no wildcard arm.
- [ ] The tests below provide every known answer and control the admission record cites (`covers.crates = ["fs-session", "fs-package"]`): the round trip, and the tamper, missing-blob, flag and machine-path controls each caught; the record itself is written and validated by N33a-34's step `ledger_group_admission`.

## Test plan

### Unit tests (`cargo test -p frob-fsim ledger::session`)
- `package_roundtrip`, `package_tamper_detected`, `package_missing_blob_detected`, `package_flag_true_rejected`, `package_has_no_machine_path` (a manifest containing `/Users/` or `/home/` is refused at `pack`).
- `package_flag_missing_rejected`: a manifest with one of the three no-authorization flags absent → rejected, the flag named.
- `package_unknown_schema_major_refused`: schema `…/2` against a reader of `…/1` → refused naming both versions; a higher minor version of the same major → accepted.
- `package_carries_stack_receipt`: the packed manifest carries `BUILT_UNDER`'s receipt hash (`sr:` form, N33a-06); `check` reports it in the verdict; a manifest without it is rejected.
- `package_blobs_addressed_by_hash`: every blob reference is its BLAKE3; a blob renamed on disk but unchanged is still found; two equal blobs are stored once.
- `refusal_codes_registered`: the cases above return, in turn, `FROB-REF-792` kind `Other` retry `Never` with both hashes (tamper) and with `absent` (missing blob); `FROB-REF-816` with `true:<field>` and with `missing:<field>`; `FROB-REF-891` with both versions; `FROB-REF-792` kind `OutsideDomain` for the machine path (with the JSON pointer) and for the missing receipt; every code loads from `registries/refusals.toml`.
- `first_fault_is_stable`: a package with an unknown major version, a true flag and a changed blob is refused with `FROB-REF-891`; with the version repaired, `-816`; with the flag repaired, `-792` naming the blob.

### End-to-end script and logging
No script of its own. `Session` is exercised end to end by the report and export scripts of the Chronicle unit. The admission step
`ledger_group_admission` of `scripts/e2e/airlock_groups.sh` (bead N33a-34) runs these tests, writes the
record and logs, per package case, the package identifier, blob count and bytes, the manifest's schema and
stack receipt, the verdict with its named reason, and each control's `caught` flag (the hit, miss and stale
counts of `Recompute` are logged by N33b-15's step, not here).

### Known answers and negative controls
- Known answer: a package round-trips through `pack` and `check`. Negative controls: one byte of one blob changed, a missing blob, an authorization flag set to true, and a machine path in a manifest are each rejected with the reason named.
- Determinism lanes: package bytes and verdicts are identical twice on one machine and across platforms.

## Considerations

- A package may contain private-scene data; the private mark and licence joins are applied by the safety unit's export path, and this adapter refuses nothing on those grounds itself.
- If `fs-session` or `fs-package` cannot be admitted at the pin (the record does not validate, or their closure brings in a crate the dependency firewall forbids), the fail-closed default is that `Session` is not offered: the trait stays declared, its adapter is compiled out, and no admission is inherited from `fs-ledger`. Nothing at this milestone needs it: a run is exported as the project's own `.frun` bundle (N29a-02), checked by `frob-verify` (N29a-03), which links nothing. The failure is recorded as an upstream work item with the reproducing case.
- `check` reads every blob once; its cost is one BLAKE3 pass over the package's bytes, and it holds one blob in memory at a time, never the package.
