## Background

The airlock crate `frob-fsim` exposes FrankenSim to FrankenRobotics through traits grouped into Cargo features.
The `ledger` group (on by default) holds `Ledger` (bead BD-009: the transactional metadata store on
FrankenSQLite), and the two traits of this bead:

- **`Recompute`**, over FrankenSim's `fs-recompute`: a content-addressed Merkle graph of results with slack,
  skip-soundness certificates and invalidation. FACT (read 2026-11-21; re-read at the pin): 3,034 lines of
  library source (5,661 with tests); its closure is 10 other FrankenSim crates plus FrankenSQLite; it needs the
  units crate `fs-qty`; `Store::can_skip` serves a node cached under a looser requirement if it achieved
  enough; it has a determinism trip-wire (`StoreError::DeterminismViolation`), pins that are never evicted and
  an independent checker.
- **`Session`**, over `fs-session` and `fs-package`: packaged sessions and evidence packages. FACT:
  `fs-package` is FrankenSim's evidence-package pattern, with a standalone checker in `fs-checker`.

What they serve. FrankenRobotics memoizes everything downstream of the compiled model in one content-addressed
**memo graph**: the `Memo` trait is declared in `frob-core`, wraps each verb's executor in `frob-verbs`, and
stores in `frob-chronicle`. `fs-recompute` is the candidate store behind it: "it is consumed through the
airlock if admission passes; otherwise the same node record is implemented in `frob-chronicle`". `Session`
serves the export of a run or a report as a self-describing package an outside reader can check.

Why an adapter and not a direct dependency from `frob-chronicle`: `fs-recompute` is a volatile crate coupled to
`fs-qty`, and its tolerance-level reuse rule is wider than this project allows. The adapter is where the
project's stricter rules are applied before anything reaches the store.

Admission is never inherited: `fs-ledger` is admitted with INT-FSQL-01; `fs-recompute` is admitted by its group
gate INT-FSIM-16 at M1 (run by another bead through this trait); `fs-session` and `fs-package` are first used
here and are admitted here by their own record.

## Scope

In: the two traits with in-process adapters; the reuse rules applied at the airlock; the determinism-violation
path; the admission record for `fs-session` and `fs-package`; adapter-level known answers.
Out: the memo graph, its key derivation, shadow recomputation and store policy (BD-111, BD-220); the
INT-FSIM-16 campaign itself (BD-111); report generation (the Chronicle and Tether units); the local fallback
node record in `frob-chronicle` (built only if admission fails, under OPEN-ATEL-3's default).

## Technical approach

**Traits (DESIGN: intent, not signatures; module `frob_fsim::ledger`).**

```rust
pub trait Recompute {
    fn open(ledger: &dyn Ledger, opts: RecomputeOptions) -> Result<Self, RefereeRefusal> where Self: Sized;
    fn node(&mut self, key: NodeKey, inputs: &[NodeKey], class: ReuseClass) -> Result<NodeHandle, RefereeRefusal>;
    fn lookup(&self, key: &NodeKey, need: &Requirement) -> Result<Lookup, RefereeRefusal>;
    fn store(&mut self, node: NodeHandle, digest: Blake3, achieved: Option<AchievedError>) -> Result<(), RefereeRefusal>;
    fn invalidate(&mut self, key: &NodeKey) -> Result<InvalidationSet, RefereeRefusal>;   // downstream closure
    fn pin(&mut self, key: &NodeKey, reason: PinReason) -> Result<(), RefereeRefusal>;
    fn report_mismatch(&mut self, key: &NodeKey, stored: Blake3, recomputed: Blake3) -> RefereeRefusal;
}
pub enum ReuseClass { BitIdentical, ToleranceRecorded }
pub enum Lookup { Hit { digest: Blake3 }, Miss, Stale { why: StaleReason } }

pub trait Session {
    fn pack(&self, manifest: &PackageManifest, blobs: &[BlobRef]) -> Result<PackageId, RefereeRefusal>;
    fn check(&self, package: &Path) -> Result<PackageVerdict, RefereeRefusal>;   // hashes, completeness, schema
}
```

`NodeKey` is a 32-byte content hash derived above the airlock from a node kind's declared inputs. The airlock
appends nothing to it, but it refuses a key whose derivation record does not list the stack-lock digest for a
node kind that names an airlock trait (the no-cache-across-pins rule; bead N33a-06).

**Rules applied at the airlock (DESIGN; each stricter than or equal to the sibling's).**
1. *Hits are bit-identical or not served.* `ReuseClass::BitIdentical` nodes are served only on digest equality
   of all inputs. The sibling's tolerance-level reuse (`can_skip` under a looser requirement) is reachable only
   for `ReuseClass::ToleranceRecorded` nodes, which must have stored an `AchievedError`. Episodes are always
   `BitIdentical`; only analyses that record an achieved error may be `ToleranceRecorded`.
2. *A determinism violation is loud.* `report_mismatch` (called when a shadow recomputation disagrees with a
   stored digest) records the violation through the sibling's trip-wire and returns a refusal; serving that
   node kind stops above the airlock. The adapter never repairs the store by overwriting.
3. *Pins outlive eviction.* A node in the evidence closure of a live claim is pinned; the adapter refuses an
   eviction request for a pinned node by name.
4. *Invalidation returns its set.* `invalidate` returns every downstream key it invalidated, so that the caller
   can report what an edit recomputes.
5. *The stack matters.* A store opened under one stack-lock digest and reopened under another serves nothing
   from before the change (every key differs), and says so in its open report.

**`Session` rules.** A package manifest never embeds a path on the machine that wrote it; large data are blobs
addressed by hash; a package carries the schema name, the three no-authorization flags (all false) and the
stack receipt of the binary that wrote it; `check` recomputes every hash and refuses a package with a missing
blob, an unknown schema major version or a flag that is missing or true.

**Admission record.** `covers.crates = ["fs-session", "fs-package"]` with the known answers below; the
`fs-recompute` record is INT-FSIM-16's.

Determinism class: D0 (pure bookkeeping over hashes). Evidence: the store carries digests, never claims.

## Acceptance criteria

- [ ] Both traits compile under the `ledger` feature with no volatile type in their public face.
- [ ] A `BitIdentical` node is a `Hit` only when every input key is unchanged; changing one input yields `Miss`.
- [ ] A `ToleranceRecorded` node without a stored `AchievedError` is refused at `store`; with one, a looser later requirement is a `Hit` and a tighter one is a `Miss`.
- [ ] An episode-kind node submitted as `ToleranceRecorded` is refused.
- [ ] `invalidate` on the root of a three-level chain returns exactly the two downstream keys.
- [ ] `report_mismatch` returns a refusal and leaves the stored digest unchanged; a subsequent `lookup` of that key is `Stale { determinism-violation }`.
- [ ] A package round-trips through `pack` and `check`; a package with one byte of one blob changed, with a missing blob, or with an authorization flag set to true is rejected with the reason named.
- [ ] The admission record for `fs-session` and `fs-package` exists and validates.

## Test plan

### Unit tests (`cargo test -p frob-fsim ledger::recompute ledger::session`)
- `hit_requires_all_inputs_equal`: graph A → B; store B; lookup B is `Hit`; change A's key; lookup is `Miss`.
- `diamond_invalidation`: A → {B, C} → D; invalidate A returns {B, C, D} exactly once each.
- `tolerance_reuse_only_with_achieved_error`: stored achieved error 10⁻⁸; requirement 10⁻⁶ → `Hit`; requirement 10⁻¹⁰ → `Miss`; no achieved error → refusal at `store`.
- `episode_never_tolerance_reused`.
- `mismatch_trips_wire_and_keeps_store`.
- `pinned_node_not_evictable`.
- `reopen_under_new_lock_digest_serves_nothing`: 100 nodes stored under digest X; under digest Y all 100 lookups are `Miss`.
- `package_roundtrip`, `package_tamper_detected`, `package_missing_blob_detected`, `package_flag_true_rejected`, `package_has_no_machine_path` (a manifest containing `/Users/` or `/home/` is refused at `pack`).
- Property test `incremental_equals_full_small`: on 10³ random edit sequences over a ten-node graph of pure integer functions, values obtained through lookups and recomputation equal a full recomputation (a small-scale version of the INT-FSIM-16 known answer; the 10⁴-sequence campaign is BD-111's).

### End-to-end script and logging
No script of its own. `Recompute` is exercised end to end by the memo-graph script of bead BD-111, and
`Session` by the report and export scripts of the Chronicle unit. The admission step
`ledger_group_admission` of `scripts/e2e/airlock_groups.sh` (bead N33a-34) runs these tests, writes the
record and logs hit, miss and stale counts, the invalidation set sizes and the package verdicts.

### Known answers and negative controls
- KA-771 (small-scale form): incremental recomputation equals full recomputation; control: an input missing from a key (planted in the test graph by deriving a key from two of three inputs) must produce a stale hit that the property test detects.
- Negative controls: a tolerance-reused episode; a store that overwrites on mismatch (planted) must fail `mismatch_trips_wire_and_keeps_store`.
- Counterexample protected: omitting one dependency inherits a stale promotion (a plan-time pilot showed a semantic receipt and a correctly keyed dependency graph give the same answers, and that a missing dependency serves a stale result).
- Determinism lanes: store contents and lookup results are identical twice on one machine and across platforms.

## Considerations

- If `fs-recompute` fails admission (OPEN-ATEL-3; owner: the suite lead; it blocks the memo-graph performance gate), the same trait is implemented by a local node record in `frob-chronicle`, and the airlock adapter is not built. The trait is therefore declared so that a non-FrankenSim implementation can satisfy it.
- `fs-recompute` brings `fs-qty` and FrankenSQLite into the closure of whatever enables it; both are already in the M1 set.
- Store size is governed above the airlock (64 GB by default, eviction by a three-queue policy with admission weighted by recompute cost; bead BD-220); the adapter only refuses to evict pinned nodes.
- A package may contain private-scene data; the private mark and licence joins are applied by the safety unit's export path, and this adapter refuses nothing on those grounds itself.
