## Background

Two foundations of FrankenRobotics have the posture **Oracle**: development and test only, never in a
production dependency graph. An oracle is still a dependency of the test harness, so it is still admitted by
its own record (an admission is never inherited), and it is confined to `frob-conformance`, the Gauntlet's
harness crate. Neither blocks a milestone: the firewall lists both as "used if admitted" at M1, and the
fallback of each is to do without.

**FD-FSCI, frankenscipy** (the owner's Rust SciPy): reference integrators (`solve_ivp`), rotation conversions
(`fsci-spatial`) and cross-check optimizers. Its ledger row says admission is "with INT-FSIM-01", because
FrankenSim already pins it: its packages are in the lockfile as soon as FrankenSim is. That makes it
*present*; it does not make any use of it *admitted*, which is what this bead records. FACT (read 2026-11-21):
head `edb7ae619c2d`, toolchain `nightly-2026-08-31`, asupersync `0.6.2` with default features off, and a
requirement of `serde_json` 1.0.154 or later. Fallback: drop the cross-checks.

**FD-FKER, franken-kernel and franken-evidence** (in the asupersync repository): the wire shape of trace,
decision and policy identifiers. FACT: franken-kernel 0.6.0 (`asupersync/franken_kernel`, 1,801 lines) defines
`TraceId`, `DecisionId`, `PolicyId`, `SchemaVersion`, `Budget` and a capability-typed context; it has no claim
or evidence identifier type; it depends on `serde`. Posture: Pattern for the shape (`frob-core` mirrors the
text form of the three identifiers it has and adds `ClaimId` and `EvidenceId` in the same form; it does not
link the crate, because `frob-core` admits no `serde`) and Oracle for a round trip in `frob-conformance`. Its
ledger row says admission is "with INT-ASUP-01" (same repository, same package set). Fallback: local
identifier types with the same text form, which is already the default.

Why oracles need this care: an oracle that silently disagrees in convention (a quaternion stored scalar-last
where this project is scalar-first; an identifier with a different checksum character) produces a parity
failure that is blamed on the candidate. Each oracle is therefore admitted with a convention record and a
control that exercises the convention.

## Scope
In: the dev-dependency edges on the frankenscipy packages used; convention records for each oracle routine;
known answers and controls; the admission record of FD-FSCI.
Out: franken-kernel as the round-trip oracle of identifier text forms and the admission record of FD-FKER
(N33c-27, the single owner after integration; the round-trip steps this draft had are folded there); the second
linear-program solver from frankenscipy (`fsci-opt` `linprog`, admitted by BD-127 for mission work);
franken_numpy's oracle use (N33a-21); the artifact graph itself.

## Technical approach

**Edges.** `frob-conformance` gains dev-dependencies on the needed frankenscipy crates (the integrator crate
that provides `solve_ivp`, `fsci-spatial`, and the optimizer crate used for cross-checks) at the pins of
`franken-stack.lock`, default features off (the `franken-kernel` dev-dependency is N33c-27's). `check-deps`
enforces that these are dev-dependencies of that one crate (rule 2 of the posture table, N33a-01): a normal
dependency, or an edge from any other crate, fails. One asupersync package and one `serde_json` version per
binary must still hold.

**Frankenscipy: routines, conventions and known answers.**

| Routine | Convention record (read at the pin, stored with the fixture) | Known answer | Control |
|---|---|---|---|
| `solve_ivp` | Method name, relative and absolute tolerance arguments, dense-output semantics, how the right-hand side receives time | ẍ + x = 0 with x(0) = 1, ẋ(0) = 0 integrated over one period 2π returns (1, 0) with error below 10 times the requested relative tolerance at tolerances 10⁻⁶ and 10⁻⁹; the energy ½(x² + ẋ²) stays within the same bound of ½ | A right-hand side with the sign of x flipped (ẍ − x = 0) must fail the comparison: the true value at 2π is cosh 2π ≈ 267.74 |
| `fsci-spatial` rotations | Quaternion component order (scalar-first or scalar-last), active or passive convention, Euler axis sequence and intrinsic or extrinsic meaning | The rotation by 90° about z maps (1, 0, 0) to (0, 1, 0); its unit quaternion has scalar part √½ and vector part (0, 0, √½); composing it twice gives the rotation by 180° about z | The same four numbers read in the other component order describe a rotation by 90° about x, which maps (1, 0, 0) to itself: the test must fail when the order is swapped |
| Cross-check optimizer | Objective signature, bounds convention, termination tolerances | The minimum of f(x) = Σ (xᵢ − i)² over i = 1..4 is at x = (1, 2, 3, 4) with value 0, found to 10⁻⁸ | An objective with one term's sign flipped is unbounded below along that coordinate and must not be reported as converged to (1, 2, 3, 4) |

Each use of an oracle in a parity test cites the convention record, and the adapter that converts between this
project's conventions and the oracle's lives in `frob-conformance` beside the record. Agreement with an oracle
is recorded with the claim kind `parity`, never as a known answer.

**Admission record.** One, for FD-FSCI (`covers.crates` = the frankenscipy packages used; the record of FD-FKER
is written by N33c-27), with the command, output, the stack receipt hash, the convention records' digests, the
measured errors against their thresholds, and the caught controls. Its gate field names the gate the ledger row
ties it to, INT-FSIM-01, with `covers` distinguishing this use.

Determinism class: the rotation and optimizer known answers are D0 at a pin; the integrator comparison is
tolerance-based. Evidence:
`Tested`; results that rest on an oracle are labelled `development-oracle` where they enter a report.

## Acceptance criteria

- [ ] The three frankenscipy known answers pass at the pin, and each control fails as stated.
- [ ] The convention record for `fsci-spatial` states the quaternion component order and the active or passive meaning as read at the pin; the adapter converts to this project's convention and the 90° test passes through it.
- [ ] `check-deps` refuses a planted normal dependency on a frankenscipy crate from `frob-conformance` and any dependency on it from `frob-dyn`.
- [ ] The FD-FSCI admission record exists and validates; with the oracle's feature enabled, `cargo tree -d` shows one asupersync package and one `serde_json` version.
- [ ] With the oracle removed (the fallback), the conformance suite still builds and reports the dependent cross-checks as `not run: oracle absent`, not as passed.

## Test plan

### Unit tests (`cargo test -p frob-conformance oracle::fsci`)
- `ivp_harmonic_oscillator_one_period`: tolerances 10⁻⁶ and 10⁻⁹; errors recorded.
- `ivp_sign_flipped_control_fails`.
- `rotation_z90_maps_x_to_y`, `rotation_z90_twice_is_z180`, `rotation_component_order_control_fails`.
- `optimizer_quadratic_bowl`, `optimizer_unbounded_control_not_converged`.
- `fsci_edges_dev_only`: a planted normal dependency on a frankenscipy crate from `frob-conformance`, and a planted dependency from `frob-dyn`, are each refused by `check-deps`; the shipped dev-dependency is allowed.
- `fsci_one_serde_json`: with the oracle enabled, the resolved graph has one `serde_json` version (at least 1.0.154) and one asupersync package.
- `oracle_absent_reports_not_run`: built without the oracle feature, the dependent tests are skipped with the recorded reason.
- `parity_records_have_kind_parity`: a result compared against an oracle cannot be constructed with another claim kind.

### End-to-end script and logging
No script of its own. The step `oracle_admissions` of `scripts/e2e/airlock_groups.sh` (bead N33a-34) runs
these tests through the offload shim, writes the FD-FSCI record and logs per routine the convention digest,
the measured error with unit and threshold, and each control's `caught` flag (the FD-FKER identifier round
trips are logged by N33c-27's step).

### Known answers and negative controls
- Closed forms: (cos 2π, −sin 2π) = (1, 0); cosh 2π ≈ 267.7468 for the flipped control; the 90° rotation about z; the quadratic bowl.
- Negative controls: the three of the table; a planted regeneration of an oracle fixture from the candidate (must fail the oracle-hygiene check).
- Determinism lanes: the rotation and optimizer results are identical twice on one machine; integrator results are recorded per platform and compared within tolerance.

## Considerations

- franken_threed and franken_textiles pin `serde_json = "=1.0.151"` while frankenscipy requires 1.0.154 or later and fastmcp_rust pins `=1.0.154`; this is why those two siblings are never Cargo dependencies of anything that links FrankenSim's graph. Admitting frankenscipy here fixes the core graph's `serde_json` at the version FrankenSim's graph resolves.
- An oracle is not truth. Where the oracle and the candidate disagree, the first step is to check the convention record; the second is an independent closed form.
- These oracles are never used to regenerate a fixture from the candidate and never appear in a release binary.
