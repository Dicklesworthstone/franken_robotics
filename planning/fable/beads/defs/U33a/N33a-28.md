## Background

A foundation (a sibling project FrankenRobotics builds on) is not used above the airlock until its admission
gate has a record: a file that cites a commit of this repository whose tracked `Cargo.lock` contains the
foundation, with the command, its output and the hash of the stack resolution receipt, the measured values
against their thresholds, the negative controls caught, and the sibling facts re-read at the pin. The M0
milestone ("spine and airlock") is defined by those records: its first artifact is that `frob doctor` lists
the admitted foundations with their records and the stack receipt, and `DEPENDENCY_ADMISSION.md` holds every
record, passing or failing.

The first implementation session of the project is written as a sequence of observations, not scaffolds:
create the workspace and write the first receipt; consume FrankenSim once and compare a digest with
FrankenSim's own; count runtimes and compilers; one kernel on Metal; the same kernel on CUDA; write every
result, passing or failing, into the admission file with commands and outputs. This bead is the script that
performs the admission observations owned by this unit and validates everything that lands in the admission
file, so that an exit reviewer can rerun M0's admissions with one command per machine.

It is one script for one user-visible capability: "the foundations are admitted, and the tool can show it".
Two machines are involved: the M5 Ultra Mac (Metal steps) and `trj`, the Linux host with two RTX 4090 cards
(CUDA steps). The script runs the steps its host supports and marks the others `skipped: other host`, and the
two logs together cover the set.

## Scope

In: the script; the steps for the gates this unit carries at M0 (INT-FSIM-01 with its digest half, INT-FSQL-01,
INT-CUDA-01, INT-FT-01, INT-FSYM-01, INT-FSYM-02, INT-FNP-01, INT-FNP-02); the build-identity, bedrock,
sibling-fact and KILL-FSIM status steps; record validation; the `frob doctor` assertions; a completeness check
over all M0 admission gates.
Out: running the gates owned by other units (the script checks that their records exist and validate, and
calls their steps if their scripts are present); the stack-receipt mechanics (bead N33a-27).

## Technical approach

**Form.** `scripts/e2e/admission_m0.sh`: POSIX shell with `set -eu`, sourcing the shared helper of `STD-E2E`.
Options: `--host mac|trj|auto`, `--only <step>`, `--seed <n>` (default 1; used by the forced-kill and
comparison steps), `--record` (write admission records; without it the script runs the tests and validates
existing records only). Every cargo invocation goes through the build-offload shim; every long step runs under
a timeout inside the machine envelope (16 GiB, 8 cores, one hour, one device). Idempotent: records are
content-addressed, so a rerun on an unchanged tree adds nothing.

**Steps.**
1. `preflight`: disk space; `xtask check-stack --json`; if `may_record_pass` is false (a dirty or off-pin
   sibling), the script continues in observe-only mode and says so: no record with status `pass` can be
   written, by the guard.
2. `build_identity`: build `frob-fsim`; in a scratch copy without the build-identity entry, assert the build
   fails closed with FrankenSim's build-script message; build from `apps/`.
3. `int_fsim_01_cold`, `int_fsim_01_warm`, `int_fsim_01_necessity`: `cargo check --all-targets -p frob-fsim`
   from an empty target directory on candidate (a), and on candidate (b) only if (a) fails; the warm rerun;
   the three necessity tests (patch entry, profile overrides, build identity removed in turn). Measured: wall
   seconds (threshold 3,600), peak resident bytes (threshold 16 GiB), jobs (8), FrankenSim crates compiled,
   package count total and from the registry.
4. `int_fsim_01_digest`: run the oracle capture inside an export of FrankenSim at the pin; run the candidate;
   assert the two G1 forward-dynamics digests are equal; assert the perturbed digests differ.
5. `bedrock_direct`: the ten bedrock known answers and controls; the closure audit (no volatile crate, one
   asupersync package, no FrankenTorch crate).
6. `sibling_facts`: probe every registered sibling fact at the pins; log read and observed values.
7. `int_fsql_01`: the forced-kill harness for seeds 0 to 99; the planted non-transactional writer.
8. `int_fnp`: the array-file round trips; the stride cases (element 3; the verbatim copy that would read 12;
   the negative-stride view; the overlapping write).
9. `int_fsym_01`: build the derivation annex; `xtask check-generated`; the identity and false-twin tests; the
   certificate replay through `frob prove verify` when that verb exists (otherwise the record states the
   replay half as pending).
10. `int_fsym_02`: the planar two-link Jacobian at the regular and the singular configuration.
11. `int_ft_01` (Mac): build the Metal annex with the repeated `block` patch; run the Cayley kernel on 10⁶
    rows; assert zero differing rows against the Rust loop; the planted wrong constant must differ.
12. `int_cuda_01` (`trj`): build the CUDA annex with no toolkit installed; enumerate two devices; run the
    kernel on each; the binding survey; the cache hit and the refusals.
13. `kill_fsim_status`: evaluate the KILL-FSIM trigger ledger; log hours against 80, the cold check against
    the envelope, the largest breakage-day count in a 28-day window against 4.
14. `records_validate`: run the admission-record validator over every record; plant, in a scratch copy, the
    seven invalid records (crate absent from the cited lockfile; missing receipt; missing output; PASS on a
    dirty receipt; PASS without a caught control; self-certified PASS; a threshold with no measurement) and
    assert each is refused.
15. `admission_file`: regenerate `DEPENDENCY_ADMISSION.md`; assert it equals the checked-in file after
    `--record`, and that a gate with no record prints as `not run`.
16. `doctor`: `frob doctor --json`; assert every foundation of the ledger appears with its posture, pin,
    newest record or `not run`, and that the stack receipt hash equals `receipts/HEAD`.
17. `m0_completeness`: for every admission gate the register dates at M0 (INT-TOOLCHAIN-01; INT-FSIM-01 to
    -11 and -18; INT-ASUP-01; INT-FSQL-01; INT-FT-01, -02; INT-CUDA-01; INT-FSYM-01, -02; INT-FMCP-01;
    INT-FNP-01, -02), log its status; the step fails only under `--strict` (the mode the exit review uses) if
    any is `not run`.

**Logging (per the shared standard).** NDJSON to `target/e2e-logs/admission_m0/<utc>.ndjson` with a transcript
beside it. Every line has `ts`, `script`, `bead` (the key of the bead whose gate the step measures), `step`,
`event`, the exact command line, exit code and wall time; the envelope's `evidence` block for `frob` calls;
measured values with units and thresholds (seconds, bytes, counts, rows differing, units in the last place,
passes of 100); digests where state is compared (the two G1 digests, receipt and record hashes, generated-file
digests); for refusals the code and upstream reason; on failure the first differing value (coordinate index
and both bit patterns for a digest mismatch; row and word for a kernel mismatch; the seed, kill point and
recovered prefix for a ledger failure) and the artifact paths needed to reproduce. A final `summary` gives
assertions passed and failed and the gates touched. No private-scene data exists at M0; fixtures are synthetic
or catalog models.

## Acceptance criteria

- [ ] On the Mac the script passes all steps except those marked for `trj`, and on `trj` all except those marked for the Mac; the union covers every step.
- [ ] With `--record` on a clean stack, admission records are written for INT-FSIM-01 (both halves), INT-FSQL-01, INT-CUDA-01, INT-FT-01, INT-FSYM-01, INT-FSYM-02, INT-FNP-01 and INT-FNP-02, each validating, each with at least one caught control.
- [ ] On a dirty stack the script completes in observe-only mode and writes no `pass`.
- [ ] `frob doctor --json` lists all eighteen foundations with their records and the stack receipt.
- [ ] The seven invalid-record plants and each gate's negative control are caught; an uncaught plant fails the script.
- [ ] `--strict` fails when any M0 admission gate is `not run`, naming it.
- [ ] The log validates against the shared schema and ends with a `summary` that lists the gates touched.

## Test plan

### Unit tests
The script is the test. Its helpers have a `--self-test` mode (each assertion helper is run on a passing and a
failing input and must tell them apart), and a shell lint runs in the formatting lane. A dry-run mode
(`--plan`) prints the steps and commands without running them, for review.

### End-to-end script and logging
This bead is the script. It is run by the first implementation session, by the M0 exit review (bead BD-044,
with `--strict`), and by the compatibility train at every pin move (the admission gates are rerun at the new
pin, since an admission is never inherited).

### Known answers and negative controls
- Known answers asserted: the G1 digest equality; KA-777 (element 3; the tuple (1, 0, 3, 2)); the Cayley fixtures ((1, 0, 0, 0.75) with denominator 1.5625; (0.8, 0, 0, 0.6) after normalization); det J = l₁·l₂·sin q₂ with the regular value 0.046999614577649 m² and zero at the singular configuration; 100 of 100 forced-kill recoveries.
- Negative controls exercised: the unset build identity; the perturbed digest inputs; the non-transactional ledger writer; the verbatim stride copy; the false identity twins; the sign-flipped Jacobian entry; the wrong-constant kernel on each backend; the hidden driver; the seven invalid records.
- Mutation check of the script: in self-test, replacing the record validator by a stub that accepts everything must make at least seven assertions fail.
- Determinism lanes: every digest and count is identical on a rerun of the same tree and seed; device steps are compared twice on the same device.

## Considerations

- The cold check of the FrankenSim closure dominates the runtime (TARGET: under one hour); `--only` lets a developer run the cheap steps, and the script reuses a warm target directory unless `--cold` is given.
- A failing admission is a result. The script exits non-zero and still writes the failing record under `--record`, so the admission file shows it; it never retries a gate until it passes.
- The script does not modify siblings; the FrankenSim export for the digest oracle lives in scratch.
- Device steps need the devices idle; they run one device at a time and log host load in the disclosure fields of their receipts.
