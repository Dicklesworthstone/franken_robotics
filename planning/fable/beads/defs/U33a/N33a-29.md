## Background

The airlock crate `frob-fsim` is the only crate of FrankenRobotics that names FrankenSim's volatile types.
Three rules bind it: it converts and never reinterprets (a FrankenSim refusal becomes a typed referee refusal
carrying the upstream reason and is never retried with weakened inputs); it does not cache across pins; and it
exposes capacities as data (the 21-contact limit of FrankenSim's sustained solver is a field, checked at model
compile and at run time, so an over-capacity contact set is a refusal by name and is never silently
truncated). A fourth behaviour follows from building the airlock in feature groups: a verb that needs a group
this binary was not built with is refused with `FROB-REF-790` (`foundation-group-absent`).

A refusal is part of the product's surface. An agent meets it as an envelope with `ok: false`, a stable code,
the field at fault, what was observed and what is required, whether to retry, and ranked repairs. The standing
rules of the numerics chapter are: refuse, never truncate; a budget stop publishes nothing partial; a misspelt
parameter is a refusal, not a default. This script proves, from the user's side with the real binary, that the
airlock's refusals arrive in that form, with the right exit codes, and that the tempting wrong behaviours
(truncate and continue; swallow the reason; crash) do not happen.

It is the end-to-end script of one user-visible capability: "the referee tells you by name why it will not
answer".

## Scope

In: the script, its three refusal scenarios and one positive scenario each, built on the M0 verb `sim.run
--tier referee`.
Out: the mechanisms (beads N33a-11, N33a-13, N33a-14); per-group admission steps at later milestones (bead
N33a-34); the worker-mismatch refusal `FROB-REF-791` (the worker-fallback bead's script); the stack-mismatch
refusal `FROB-REF-890` (exercised in bead N33a-27).

## Technical approach

**Form.** `scripts/e2e/airlock_refusals.sh`: POSIX shell with `set -eu`, sourcing the shared helper of
`STD-E2E`; idempotent; seed-explicit (`--seed`, default 1, used for fixture placement jitter that must not
change any contact count). It builds two binaries through the offload shim: the default `frob`, and
`frob-noreferee`, built with `--no-default-features` and only the `geometry` and `ledger` groups of the airlock,
into a separate target directory.

**Fixtures (synthetic, checked in under `tests/fixtures/airlock/`).** `rest21.fscene-lite`: a rigid slab
resting on a plane through 21 contact samples (a 7 × 3 grid of feet). `rest22.fscene-lite`: the same with one
more sample. Both are tiny referee scenes in the M0 scene vocabulary (boxes and half-spaces with roles).

**Steps.**
1. `group_absent`: `frob-noreferee sim run g1 --tier referee --seconds 0.01 --json`. Assert: exit code 5;
   envelope `ok: false`; `refusal.code = "FROB-REF-790"`; `refusal.pointer = "referee"`; `observed` lists the
   built-with groups (`geometry`, `ledger`); `required` lists `referee`; `retry = "after-change"`; the first
   repair names a binary built with the group; `cost` shows no device time and the budget is unchanged
   (nothing was charged).
2. `group_present`: the same command with the default binary. Assert: exit code 0 or 2, a state digest in the
   result, the evidence block present.
3. `capacity_fits`: `frob sim run --scene rest21 --tier referee --seconds 0.05 --json`. Assert: completes; the
   result reports 21 contacts solved; no refusal.
4. `capacity_overflows`: the same with `rest22`. Assert: exit code 5; `refusal.code = "FROB-REF-721"`;
   `observed = 22`; `required = 21`; repairs in order: a documented patch reduction with its qualification
   fixture, then `--profile strict`; an `upstream` object with the crate name, the upstream variant and
   message verbatim and the stack-lock digest; and the terminal receipt counts one refused trial, zero
   completed, zero failed.
5. `no_truncation`: assert that the refused run of step 4 published no chunk and no partial result: `frob run
   show <run> --json` (or the M0 equivalent ledger read) shows the run with state `refused` and an empty
   frontier.
6. `capacity_is_data`: `frob doctor --json` reports the referee's contact capacity and its source (the
   sibling fact row); assert it equals the `required` value of step 4.
7. `upstream_refusal`: a referee request with an input FrankenSim's own domain check rejects at the pin (the
   case is chosen from the airlock's mapping table and recorded; at M0 the fixed-witness refusal on a
   flat-to-edge transition when its fixture exists, otherwise an unsupported joint class in a hand-written
   referee model). Assert: `ok: false`; a registered code; the upstream variant and message present and
   non-empty; `retry` consistent with the mapping table; no second attempt was made (the daemon or CLI trace
   shows one upstream call).
8. `misspelt_parameter`: `frob sim run g1 --tier refere --json`. Assert: a refusal with the protocol code for
   bad arguments and exit code 3, not a silent default tier.

**Logging (per the shared standard).** NDJSON to `target/e2e-logs/airlock_refusals/<utc>.ndjson` with a
transcript. Every line has `ts`, `script`, `bead`, `step`, `event`, the exact command line, exit code and wall
time, and the envelope's `evidence` block; `refusal` events carry the full refusal object (code, message,
pointer, observed, required, unit, retry, repairs, upstream); `metric` lines carry contact counts with their
capacity threshold; digests of the two completed runs; on failure the first differing field of the expected
and actual refusal. A final `summary` gives assertions passed and failed and the refusal codes seen.

## Acceptance criteria

- [ ] The script passes from a clean checkout; all eight steps assert as stated.
- [ ] `FROB-REF-790` is returned with exit code 5 by the binary lacking the `referee` group, before any work and with no budget charge.
- [ ] `FROB-REF-721` is returned with `observed = 22` and `required = 21`; the 21-contact scene runs.
- [ ] A refused run has no published chunk and no partial result.
- [ ] The upstream reason appears verbatim in the envelope and exactly one upstream call was made.
- [ ] The capacity shown by `frob doctor` equals the refusal's `required` value.
- [ ] The log validates against the shared schema and ends with a `summary`.

## Test plan

### Unit tests
The script is the test; its helpers have a `--self-test` mode in which each refusal matcher is run on a
matching and a non-matching envelope fixture and must tell them apart. A shell lint runs in the formatting
lane.

### End-to-end script and logging
This bead is the script. It is run at the M0 exit review and after every pin move (an upstream change of the
capacity constant or of a refusal variant shows up here first).

### Known answers and negative controls
- Known answers: 21 contacts fit and 22 refuse (the control of KA-778); a slab at rest stays at rest over the 0.05 s run (its velocity digest equals the zero-velocity digest).
- Negative controls, each run against a test build of the airlock with one planted defect, which the script must report as a failure: (1) truncate to 21 and continue (step 4 would wrongly complete); (2) the group check stubbed out (step 1 would fail later with an unhelpful error); (3) the upstream message replaced by a generic string (step 7's verbatim check fails); (4) a retry with a relaxed tolerance on refusal (two upstream calls are seen).
- Counterexamples protected: extra contacts can be dropped when a world exceeds its capacity (false); the referee can adjudicate every scenario the fast tiers run (false).
- Determinism lanes: the refusal envelopes are byte-identical on a rerun except for `ts` and `cost.wall_ms`; the two completed runs give identical digests twice on one machine.

## Considerations

- Building a second binary costs a second link of the M1 closure minus the referee group; the script reuses the warm target directory and runs under a timeout inside the machine envelope.
- When FrankenSim raises its contact capacity upstream, steps 3 and 4 must be regenerated from the capacity read at the pin (the fixtures are parameterized by `capacity` and `capacity + 1`), so the script does not hard-code 21.
- The upstream-refusal step depends on which refusals the pin can be provoked into at M0; the chosen case is recorded in the log so a reviewer can see what was actually exercised.
- No private data: all fixtures are synthetic.
