## Background

The airlock crate `frob-fsim` is the only crate of FrankenRobotics that names FrankenSim's volatile types.
Three rules bind it: it converts and never reinterprets (a FrankenSim refusal becomes a typed referee refusal
carrying the upstream reason and is never retried with weakened inputs); it does not cache across pins; and it
exposes capacities as data (the 21-contact limit of FrankenSim's sustained solver is a field, checked at model
compile and at run time, so an over-capacity contact set is a refusal by name and is never silently
truncated). A fourth behaviour follows from building the airlock in feature groups: a verb that needs a group
this binary was not built with is refused with `FROB-REF-790` (`foundation-group-absent`).

A refusal is part of the product's surface. An agent meets it as an envelope with `ok: false`, a stable code,
the field at fault, what was observed and what is required, whether to retry, and ranked repairs. The standing
rules of the numerics chapter are: refuse, never truncate; a budget stop publishes nothing partial; a misspelt
parameter is a refusal, not a default. This script proves, from the user's side with the real binary, that the
airlock's refusals arrive in that form, with the right exit codes, and that the tempting wrong behaviours
(truncate and continue; swallow the reason; crash) do not happen.

It is the end-to-end script of one user-visible capability: "the referee tells you by name why it will not
answer".

What M0 can show from the user's side is bounded by the M0 verb: `sim.run` at M0 (BD-024) takes only the
catalog fixture `g1`, only `--tier referee`, zero torques and a contact-free step, and raises only 802, 724 and
790. A contact set therefore reaches the referee through `frob` first at M1, when the contact step of BD-080
lands. The script is split along that line: this bead is the M0 part (the absent group, the capacity published
as data, the misspelt parameter); bead N33ap1-01 adds to the same script, at M1, the over-capacity contact set,
the no-truncation check and the upstream refusal carried verbatim. Below M1 the capacity refusal is proved by
the unit tests of N33a-13 and N33a-14.

## Scope

In: the script `airlock_refusals.sh` and its M0 steps: one refusal scenario per M0-reachable refusal of the
airlock (790; the input-schema refusal of a misspelt tier), one positive scenario, and the capacity as reported
by `frob doctor`.
Out: the mechanisms (beads N33a-11, N33a-14 with its `referee` doctor section, N33c-32); the over-capacity,
no-truncation and upstream-refusal steps (bead N33ap1-01, M1, which extends this script); per-group admission
steps at later milestones (bead N33a-34); the worker-mismatch refusal `FROB-REF-791` (the worker-fallback
bead's script); the stack-mismatch refusal `FROB-REF-890` (exercised in bead N33a-27).

## Technical approach

**Form.** `scripts/e2e/airlock_refusals.sh`: POSIX shell with `set -eu`, sourcing the shared helper of
`STD-E2E`; idempotent; seed-explicit (`--seed`, default 1; no M0 step draws from it, and the M1 steps of
N33ap1-01 use it for fixture placement jitter that must not change any contact count). It builds two binaries
through the offload shim: the default `frob`, and `frob-noreferee`, built with `--no-default-features` and only
the `geometry` and `ledger` groups of the airlock, into a separate target directory. Steps are tagged with the
milestone from which they run; `--milestone M0` (the default until M1 is reached) runs the M0 steps only, and a
step whose milestone has not been reached is logged `not-run` with the key of the bead that adds it, never as
passed.

**Steps (M0).**
1. `group_absent`: `frob-noreferee sim run g1 --tier referee --seconds 0.025 --key ar-absent --json` (12 steps
   of 1/480 s; a duration that is not a whole number of steps would be refused by the schema with 802 first,
   BD-024; every `sim run` call of the script carries its own `--key`, as every run-kind call does, so that a
   missing key is never the refusal observed). Assert: exit code 5;
   envelope `ok: false`; `refusal.code = "FROB-REF-790"`; `refusal.pointer = "foundation/referee/compiled"`
   (N33a-11); `observed` lists the built-with groups (`geometry`, `ledger`); `required` lists `referee`;
   `retry = "after-change"`; the repairs equal the registry row's in its order (N33-REF, attached by N33c-32),
   the first naming a build that has the group; `cost` shows no device time and the budget is unchanged
   (nothing was charged); the ledger has no `run` row for the request.
2. `group_present`: the same command with the default binary and `--key ar-present`. Assert: exit code 0 or 2, a state digest in the
   result, the evidence block present.
3. `capacity_is_data`: `frob doctor --json --section referee` (the section of N33a-14). Assert: the referee's
   contact capacity `max_contacts_per_solve` is present with its source (the sibling fact row) and equals the
   reading of the fact probe for that row (N33a-09, `frob-conformance` facts at the pin); `fixed_witnesses` and
   `contact_set_from_caller` are present and `true` at the pin. The same section in `frob-noreferee` reports the
   group as not compiled, with no finding and exit 0.
4. `misspelt_parameter`: `frob sim run g1 --tier refere --key ar-misspelt --json`. Assert: exit code 3 and
   `refusal.code = "FROB-REF-802"` with `pointer` naming the `tier` field (a value outside the tier enumeration
   of `frob.sim.run.in/1` fails the input schema), no run at any tier and no `run` row; then
   `frob sim run g1 --tier batch-cpu --key ar-tier-m2 --json` (a tier of the enumeration not implemented at M0)
   gives exit 5 and
   `FROB-REF-724`. A misspelt parameter is a refusal, never a silent default.

**Logging (per the shared standard).** NDJSON to `target/e2e-logs/airlock_refusals/<utc>.ndjson` with a
transcript. Every line has `ts`, `script`, `bead`, `step`, `event`, the exact command line, exit code and wall
time, and the envelope's `evidence` block; `refusal` events carry the full refusal object (code, message,
pointer, observed, required, unit, retry, repairs, upstream); `metric` lines carry the doctor capacity with its
source row and the fact probe's reading; the digest of the completed run; the built-with set of each binary;
`not-run` lines for steps of a later milestone with the key of the bead that adds them; on failure the first
differing field of the expected and actual refusal. A final `summary` gives assertions passed and failed, the
steps not run and the refusal codes seen.

## Acceptance criteria

- [ ] The script passes from a clean checkout on the Mac and on the Linux host; the four M0 steps assert as stated, and the M1 steps of N33ap1-01 are logged `not-run` until M1.
- [ ] `FROB-REF-790` is returned with exit code 5 and pointer `foundation/referee/compiled` by the binary lacking the `referee` group, before any work, with no budget charge and no `run` row; the default binary runs the same command.
- [ ] `frob doctor --section referee` reports the contact capacity, its source row and the two structural flags, and the capacity equals the fact probe's reading at the pin.
- [ ] `--tier refere` is refused with `FROB-REF-802` and exit code 3, and `--tier batch-cpu` with `FROB-REF-724` and exit code 5; neither runs.
- [ ] The log validates against the shared schema and ends with a `summary`.

## Test plan

### Unit tests
The script is the test; its helpers have a `--self-test` mode in which each refusal matcher is run on a
matching and a non-matching envelope fixture and must tell them apart (a 790 envelope with the right and with a
bare `referee` pointer; an 802 and a 724 envelope; a doctor section with and without the source row). A shell
lint runs in the formatting lane.

### End-to-end script and logging
This bead is the script. It is run at the M0 exit review (BD-044) and after every pin move (an upstream change
of the capacity constant shows up in step 3 first).

### Known answers and negative controls
- Known answers: the capacity read at the pin (21 on the day of reading) equals the fact probe's reading; the default binary's `g1` run completes with its state digest.
- Negative controls, each run against a test build with one planted defect, which the script must report as a failure: (1) the group check stubbed out (step 1 then fails later with an unhelpful error and no 790); (2) a doctor section that prints a literal capacity instead of the value read from the sibling, run on a scratch copy whose upstream constant is patched to 24 (step 3's equality with the fact probe fails); (3) a tier parser that falls back to `referee` on an unknown value (step 4 sees a run instead of 802).
- Counterexample protected: a misspelt parameter can be replaced by its default (false).
- Determinism lanes: the refusal envelopes are byte-identical on a rerun except for `ts` and `cost.wall_ms`; the completed run gives identical digests twice on one machine.

## Considerations

- Building a second binary costs a second link of the M0 closure minus the referee group; the script reuses the warm target directory and runs under a timeout inside the machine envelope.
- The script never hard-codes 21: step 3 compares the doctor value with the fact probe, and the M1 fixtures of N33ap1-01 are parameterized by `capacity` and `capacity + 1`.
- Below M1 the over-capacity refusal and the verbatim upstream reason are proved by unit tests only (N33a-13, N33a-14); the M0 exit review reads that as such, not as an end-to-end result.
- Step 4 follows BD-024's input rule: a tier of the enumeration not implemented at M0 is 724 (exit 5), a value outside the enumeration fails the schema with 802 (exit 3, `pointer` `/tier`), which BD-024's unit test `tier_misspelt_802` also asserts.
- No private data: the only fixture is the catalog model `g1`.
