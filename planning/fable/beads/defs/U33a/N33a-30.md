## Background

The airlock crate `frob-fsim` is the only crate of FrankenRobotics that names FrankenSim's volatile types. Its
`geometry` feature group lists eight FrankenSim crates behind three traits. Bead N33a-16 builds the two traits
the CPU referee needs at M1 over `fs-query`, `fs-geom` and `fs-scene`. This bead builds the rest when the
scene subsystem needs it (first the design language's mesh Regions at M1, then the scene compiler at M2): the trait **`MeshExchange`** and the field and topology queries, over

- `fs-io` (FACT: 22,276 lines of library source, 28,772 with tests; a closure of 13 other FrankenSim crates;
  depends on the units crate): hardened mesh interchange and bounded STEP exchange with quarantine receipts;
- `fs-rep-mesh`, `fs-rep-sdf`, `fs-rep-frep`: mesh, signed-distance-field and implicit (function)
  representations;
- `fs-topo` (FACT: 1,976 lines): manifoldness with defect localization and Betti numbers, used in scene
  acceptance; its cubical module implements zero-dimensional persistence for voxel fields with chart
  voxelization capped at 10⁶ cells and no periodic axis, which is why the scene crate implements its own
  clearance sweep and uses `fs-topo` as a parity oracle on small fixtures.

What they serve: a scene pack is compiled from source geometry through the airlock; an imported mesh must be
watertight and consistently oriented or it is refused, not patched (`FROB-REF-301`); a decode limit exceeded is
a refusal (`FROB-REF-303`); collision fields carry stated interpolation bounds. Imported geometry is hostile
input by default, which is why the sibling's quarantine behaviour (refuse to parse above a bound, and say so
with a receipt) is something this project wants to preserve end to end rather than wrap away.

One inconsistency in the design is resolved here. The group table places `fs-io` in the default-on `geometry`
group, while the known answer that admits it (a mesh written through `fs-io` reads back with the same hash; a
STEP file above the stated bound is quarantined) is listed under the `structure` group gate INT-FSIM-15 at M5.
Since an admission is never inherited and is made at first use, the mesh round-trip half is admitted here, at
M1, by its own record; the STEP half stays with INT-FSIM-15.

## Scope

In: `MeshExchange` and its adapter; field queries added to the geometry module (signed distance field built
from a mesh or an implicit, sampled with a stated bound); the topology report; quarantine and limit handling;
the first-use admission record for the five crates, at M1; known answers and controls.
Out: scene packs, bricks and the brick pool, overlays, the scene compiler and acceptance report (the scene
subsystem); bounded STEP exchange and geometry export (BD-401, BD-407); clearance complexes (the scene
subsystem; `fs-topo` is only a parity oracle there); the fuzz corpus (BD-307); the chart surface
`GeometryKernel::signed_distance_chart`, whose constructive-solid charts give an interval range over a box and
whose mesh charts take their sign from winding numbers (N19ap4-01, which depends on this bead: `FieldQuery` here
returns point samples only).

## Technical approach

**Trait (DESIGN: intent, not signatures; module `frob_fsim::geometry::mesh`, feature `geometry`).**

```rust
pub trait MeshExchange {
    fn limits(&self) -> ExchangeLimits;        // byte, vertex and face bounds read from the sibling at the pin
    fn read(&self, bytes: &[u8], format: MeshFormat, profile: &ImportProfile) -> Result<MeshHandle, RefereeRefusal>;
    fn write(&self, mesh: &MeshHandle, format: MeshFormat) -> Result<Vec<u8>, RefereeRefusal>;
    fn content_hash(&self, mesh: &MeshHandle) -> Blake3;      // of the canonical mesh, not of file bytes
    fn topology(&self, mesh: &MeshHandle) -> Result<TopologyReport, RefereeRefusal>;
    fn facts(&self, mesh: &MeshHandle) -> MeshFacts;          // vertices, faces, volume, area, bounding box
}
pub struct TopologyReport { pub closed: bool, pub oriented: bool, pub manifold: bool,
                            pub betti: [u32; 3], pub euler: i64, pub defects: Vec<Defect> }
pub struct Defect { pub kind: DefectKind, pub edges: Vec<(u32, u32)>, pub near: Point3 }   // localized
pub enum ReadOutcome { /* inside RefereeRefusal on failure: */ Quarantined { receipt: QuarantineReceipt } }

pub trait FieldQuery {          // an extension of the geometry kernel, first used at M1
    fn sdf_from_mesh(&self, mesh: &MeshHandle, spec: &FieldSpec) -> Result<FieldHandle, RefereeRefusal>;
    fn sdf_from_implicit(&self, f: &ImplicitSpec, spec: &FieldSpec) -> Result<FieldHandle, RefereeRefusal>;
    fn sample(&self, field: &FieldHandle, p: Point3) -> Result<Enclosed<f64>, RefereeRefusal>;   // value with its bound
    fn bound(&self, field: &FieldHandle) -> f64;       // the field's stated error bound, metres
}
```

**Rules.**
1. *Limits are data and are enforced before parsing.* `read` checks the input's byte length against the
   profile and the sibling's bound first. Over the bound, nothing is parsed and the refusal carries a
   quarantine receipt (input hash, length, the bound, the reason). The adapter never raises a sibling bound.
2. *No repair in silence.* A mesh that is not closed, not consistently oriented or not manifold is returned
   with its `TopologyReport`; the adapter does not weld, fill or flip. Repair is a separate, explicit request
   of the scene subsystem with receipts.
3. *Hashes are of content.* `content_hash` is computed from the canonical mesh (vertices and faces in the
   sibling's canonical order), so a write followed by a read yields the same hash even if file bytes differ
   between formats.
4. *Fields say how wrong they may be.* `sample` returns an enclosure; a caller that needs a certified gap uses
   the lower end. A truncated field reports its range, and a query outside it is a refusal, not an
   extrapolation.
5. *Voxel caps are data.* A topology or persistence request above the sibling's cell cap (10⁶ on the day of
   reading) is refused by name.
6. Every sibling error passes through the conversion of bead N33a-13; decode-limit and reference errors map
   to the scene refusals for limits and non-watertight geometry when the caller is the scene compiler.

**Admission record (first use, M1).** `covers.crates = ["fs-io", "fs-rep-mesh", "fs-rep-sdf", "fs-rep-frep", "fs-topo"]`,
filed under the gate INT-FSIM-01, in the form of the FrankenSim path gate applied to crates first used: compiled
from this repository behind the `geometry` feature, the known answers below through the traits, one negative
control failing, citing the stack receipt of the day; `harness_receipt` is null and no row of
`registries/gates.toml` is written (KA-770's STEP half and the gate INT-FSIM-15 stay with the `structure` group
at M5). This bead fixes the record's content; the record is written under `--record` by the step
`geometry_mesh_admission` of N33a-34 (which depends on this bead) with N33a-07's command, `cargo run -p
frob-conformance --example admission -- record --gate INT-FSIM-01 --input <step file>`, and its existence and
validity at the pin are asserted there.

Determinism class: same platform, same binary; content hashes are D0. Evidence: as the sibling's contracts
state; field samples are enclosures.

## Acceptance criteria

- [ ] Mesh round trip: a unit cube (8 vertices, 12 triangles) written and read back has the same content hash, in each mesh format the sibling supports at the pin (the mesh half of KA-770).
- [ ] Cube facts: volume 1 m³, area 6 m², Euler characteristic 8 − 18 + 12 = 2, Betti numbers (1, 0, 1), closed, oriented, manifold.
- [ ] Torus (a 16 × 16 quad torus triangulated: 256 vertices, 768 edges, 512 faces): Euler characteristic 0, Betti numbers (1, 2, 1).
- [ ] Open box (the cube with one face's two triangles removed): `closed = false`, one defect of kind boundary loop with exactly 4 edges, located on the missing face.
- [ ] A flipped triangle in the cube gives `oriented = false` with the offending edges named; nothing is repaired.
- [ ] An input one byte over the configured bound is not parsed and yields a quarantine receipt with the input's hash.
- [ ] Sphere field: the signed distance field of a unit sphere built from an implicit, sampled at (2, 0, 0), encloses 1.0 and at the origin encloses −1.0, each within the field's stated bound; a sample outside a truncated range is refused.
- [ ] The tests below provide every known answer and control the first-use admission record of the five crates cites (gate INT-FSIM-01, M1); the record itself is written and validated by N33a-34's step `geometry_mesh_admission`.

## Test plan

### Unit tests (`cargo test -p frob-fsim -- geometry::mesh geometry::field`)
- `cube_roundtrip_same_hash`, `cube_facts`, `cube_topology`.
- `torus_betti_1_2_1`.
- `open_box_boundary_loop_of_four`.
- `flipped_triangle_reports_orientation_defect`.
- `oversize_input_quarantined_not_parsed`: a parser-call counter in the test build stays at zero, and the quarantine receipt carries the input's BLAKE3 hash, its length, the bound applied and the reason.
- `profile_cannot_raise_sibling_bound`: an import profile whose byte bound is twice the sibling's; an input one byte over the sibling's bound is still quarantined, and `limits()` equals the sibling's bounds read at the pin.
- `truncated_field_out_of_range_refused`.
- `sphere_sdf_enclosures`: |sample − (‖p‖ − 1)| ≤ bound at 10³ seeded points with 0.2 ≤ ‖p‖ ≤ 3.
- `mesh_sdf_matches_implicit_sdf_on_cube`: at 10³ points the two enclosures intersect.
- `voxel_cap_refused_by_name`.
- `no_silent_repair`: reading the open box and writing it back yields the same 10 triangles.
- Property test `content_hash_invariant_under_format`: write in format A, read, write in format B, read: equal hashes.

### End-to-end script and logging
No script of its own; observed through `frob scene compile` in the scene unit's script. The admission is the
step `geometry_mesh_admission` of `scripts/e2e/airlock_groups.sh` (bead N33a-34), which logs each fixture's
facts and Betti numbers against the expected values, both content hashes of the round trip, the quarantine
receipt and the control outcomes.

### Known answers and negative controls
- KA-770 (mesh half): a mesh written through `fs-io` reads back with the same hash. Closed forms: cube and torus invariants; the sphere's distance function.
- Negative controls: an adapter that welds the open box closed (planted) must fail `open_box_boundary_loop_of_four`; a hash of file bytes instead of content (planted) must fail the cross-format property; a reader that parses before checking the bound must trip the parser-call counter.
- Counterexample kept in view: "import the mesh and trust it" (an unobserved region is not free space; a hole closed by repair stays unknown).
- Determinism lanes: content hashes identical twice, in debug and release, and on both platforms.

## Considerations
- Mesh files from outside are untrusted. The adapter adds no parsing of its own; all decoding stays in the sibling's hardened reader behind the bound, and the fuzz targets of the safety unit drive this entry point.
- Private scenes: mesh content may be private; hashes may be logged, payloads may not.
- If FrankenSim changes its canonical mesh order at a pin move, content hashes change; the stack-lock digest in every scene-compile memo key makes that a clean miss and not a mismatch.
- The 10⁶-cell cap makes `fs-topo` unsuitable for whole-building persistence; that is a known limit, not something this adapter hides.
- Milestone. This bead was drafted at M2, for the scene compiler. The design language needs the same traits one
  milestone earlier: mesh Regions and mesh shells (closure and orientation checks, signed distance) and mesh
  blobs by content hash are M1 work (N14a-14, N14a-03). An admission is never inherited and never late: a crate
  first used at M1 is admitted at M1, so the bead and its record move to M1. The scene compiler (BD-163) re-runs
  the admission at its own pin at M2; the bounded-STEP half stays with INT-FSIM-15 at M5. With the move, the
  bead sits under WP-39, the M1 package of the airlock's other M1 groups (N33a-15, N33a-16), not under the M2
  scene package WP-17.
