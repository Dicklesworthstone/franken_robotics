## Background

PPO (proximal policy optimization) is the first learning algorithm of the gym subsystem. The suite has exactly one
existing PPO: `fs_g1_train::ppo_update` in FrankenSim (`frankensim/crates/fs-g1-train/src/ppo.rs`, 515 lines,
update at lines 253–345), hand-rolled with manual backpropagation and depending only on `libm`. The plan was
tempted to use it as a comparison baseline, together with the walking objective in
`fs-cmaes-viz-wasm/src/g1_walking.rs` (2,630 lines). Three errors were reported in the update. They are facts to
recheck: the first two are confirmed by reading (lines 322–326 and 340), the third is consistent with line 309
and its number was not re-run.

1. **The clip branch is reversed for negative advantage.** The clipped surrogate is
   L = min(ρ·Â, clip(ρ, 1 − ε, 1 + ε)·Â), with ρ the likelihood ratio of new to old policy and Â the advantage.
   The unclipped branch carries the gradient exactly when ρ·Â ≤ clip(ρ)·Â: for Â ≥ 0 when ρ ≤ 1 + ε, and for
   Â < 0 when ρ ≥ 1 − ε. The source tests the opposite inequality when Â < 0: it follows the ratio below 0.8 and
   clips it above 1.2.
2. **The critic gradient ignores the current output.** It is formed from the value stored during the rollout;
   the value returned by the training forward pass is discarded.
3. **Two reset episodes concatenated are forwarded as one sequence**, so the second episode's first step is
   evaluated with the first episode's history.

Decision (DESIGN): the sibling update is **not linked, not an oracle and not a baseline**; PPO is written in this
project. The admission gate INT-FSIM-06 records what the pinned source does, and upstream work item FD-FSIM-10
(P2) corrects it in FrankenSim's repository. Until INT-FSIM-06 passes upstream, neither `ppo.rs` nor
`g1_walking.rs` may be cited as a baseline. The same three probes are the first tests of this project's own PPO,
because a defect this easy to write is easy to write twice (counterexample CX-357: "a sibling's training code can
serve as an oracle or a baseline").

## Scope

In: a probe library in `frob-conformance` with three probes, their hand cases and tolerances; a correct reference
implementation and three planted-defect implementations; a harness that runs the probes against the sibling
source at the pin without placing it in any FrankenRobotics build graph; the admission record and the baseline
mark.

Out: this project's PPO and the full rule battery P-1 to P-11 (BD-197, gate GATE-CORTEX-07, which reuses these
probes); the joint law of the sibling's action sampler (rule P-12, upstream item FD-FSIM-32, a later
foundation-fact gate); training runs (BD-198); the upstream fix (FD-FSIM-10).

## Technical approach

**Probe interface (DESIGN, `crates/frob-conformance/src/probes/ppo.rs`).** A probe drives an implementation
through a small trait so that the same probe runs against the reference, the planted mutants, the sibling adapter
and later this project's PPO:

```rust
// DESIGN: intent, not signatures. Single precision throughout, as on the device tiers.
pub trait PpoUnderTest {
    fn surrogate(&self, log_sigma: f32, case: &ClipCase) -> f32;            // scalar loss term for one sample
    fn surrogate_grad_log_sigma(&self, log_sigma: f32, case: &ClipCase) -> f32;
    fn critic_bias_grad(&self, current_value: f32, stored_value: f32, ret: f32, c_v: f32) -> f32;
    fn sequence_ratios(&self, episodes: &[Episode], frozen: &PolicyParams) -> Vec<f32>;
}
```

**Probe A, the clip branch (four combinations of advantage sign and clip side).** Fixture: a one-dimensional
Gaussian policy; the sampled action sits at standardized distance z with z² = 3/2, so ∂ log π/∂ log σ = z² − 1 = ½;
the stored old log-probability is chosen so that the ratio at the current parameters is ρ ∈ {0.5, 1, 2}; ε = 0.2;
Â ∈ {+1, −1}. Since ∂ρ/∂ log σ = ρ/2, the correct derivative of L in log σ is Â·ρ/2 where the unclipped term is the
minimum and 0 where the clipped term is:

| Â | ρ | ρ·Â | clip(ρ)·Â | Minimum | Correct ∂L/∂ log σ | Reported code path |
|---|---|---|---|---|---|---|
| −1 | 0.5 | −0.5 | −0.8 | clipped | 0 | −0.25 |
| −1 | 1 | −1 | −1 | unclipped | −0.5 | −0.5 |
| −1 | 2 | −2 | −1.2 | unclipped | −1 | 0 |
| +1 | 0.5 | 0.5 | 0.8 | unclipped | +0.25 | (to record) |
| +1 | 1 | 1 | 1 | unclipped | +0.5 | (to record) |
| +1 | 2 | 2 | 1.2 | clipped | 0 | (to record) |

The probe compares the implementation's analytic gradient with a central finite difference of the scalar loss in
log σ (step 5·10⁻³: truncation of order 10⁻⁵, rounding of order 2·10⁻⁵ in single precision). Pass: relative
difference at most 10⁻³ where the correct value is nonzero and absolute difference at most 10⁻³ where it is zero.
Both clip boundaries (ρ = 0.8 and ρ = 1.2) are probed with one-sided differences for both signs of Â: on the
unclipped side the one-sided slope is Â·ρ/2, on the clipped side it is 0.

**Probe B, the critic gradient.** With value loss c_V·(V − R)² and c_V = ½: current forward output V = 2, stored
rollout value 0, return R = 0. The gradient into the critic bias is 2·c_V·(V − R) = 2. An implementation that
differentiates the stored value returns 0. Pass: equality to 10⁻⁶. The probe also perturbs V to 2 + h and requires
the loss to change by (V − R)·h to first order, which an implementation that never reads V cannot show.

**Probe C, packed sequences across a reset.** Two independently reset one-step episodes are packed into one batch
for a recurrent policy. With frozen parameters the likelihood ratio must be 1 on both, to 10⁻⁶, and must equal the
ratios obtained by replaying each episode alone. The reported code path gives a second ratio of 1.582459. The
probe runs the pack in both orders and with a padding element between the episodes.

**Reference and planted implementations (`frob-conformance`, test-only).** A reference of about one hundred lines:
the Gaussian surrogate above; the squared-error critic; a one-unit recurrent policy h′ = tanh(w·h + u·o), μ = v·h′
with h reset to 0 at each episode start. Three mutants, each registered in the negative-control registry:
- `planted::reversed_negative_clip` tests ρ·Â ≥ clip(ρ)·Â when Â < 0; it returns −0.25, −0.5, 0 at ρ = 0.5, 1, 2.
- `planted::stale_value_gradient` returns 2·c_V·(V_stored − R) = 0.
- `planted::no_reset_in_pack` carries h across the boundary. With w = u = v = 1, both observations 1, unit
  variance and each action at its own episode's mean tanh(1) = 0.761594, the packed second mean is
  tanh(1.761594) = 0.942681 and the second ratio is exp(−(0.181087)²/2) ≈ 0.98374 instead of 1.

**Running the probes against the sibling at the pin, without linking it.** `fs-g1-train` is excluded from
FrankenSim's workspace and is on this project's not-admitted list, so it may appear in no lockfile of this
repository. The harness is a development-time capture tool under `tools/oracle/fs_g1_train_probe/` with its own
`[workspace]` table and lockfile, a path dependency on `fs-g1-train` at the commit named in `franken-stack.lock`,
and a binary that prints one JSON object per probe (inputs, the sibling's outputs, the correct values). It is
never a member of the core, annex, `apps/`, `derive/`, `bindings/` or `worker/` workspaces, and `xtask check-deps`
fails if the package name `fs-g1-train` appears in any of their lockfiles. Its output is stored as a pinned
capture `tests/fixtures/oracle/fs_g1_train_ppo/<sibling-rev>.json` with the revision and date. Where the sibling's
API cannot realize a hand fixture exactly, the harness reproduces the reported fixture instead and the record
says so. The walking objective of `g1_walking.rs` is not executed; its baseline mark follows this gate.

**Record and mark.** `DEPENDENCY_ADMISSION.md` entry: commit, command, output hash, receipt hash, the three probe
results for the sibling (`defect-reproduced` or `defect-absent`, with numbers), and the state of FD-FSIM-10. The
gate's status for the sibling is `pass` only if all three probes pass; otherwise `fail` with the interim posture
adopted, and the conformance baseline registry keeps both files marked `not-a-baseline`. Claim: Known answer;
class `Tested`; tier host; determinism D0 for the reference on fixed inputs.

- `clip_probe_reference_positive_advantage`: expects (+0.25, +0.5, 0).
- `clip_probe_boundaries_one_sided`: at ρ = 0.8 and 1.2, both signs; expects the pair (Â·ρ/2, 0) on the correct sides.
- `clip_probe_fd_matches_analytic`: analytic against central difference within 10⁻³ in `f32`.
- `critic_probe_reference_is_two`; `critic_probe_loss_responds_to_current_value`.
- `pack_probe_reference_ratios_are_one`: both orders, with and without padding; expects abs(ρ − 1) ≤ 10⁻⁶.

## Considerations

- A reported number stays a report until the capture records it. If a defect does not reproduce at the pin, the record says `defect-absent`, and the baseline mark still requires all three probes to pass.
- Switch-over rule of FD-FSIM-10: re-run INT-FSIM-06 by a compatibility train; only then may the sibling serve as a comparison baseline. It is never an oracle for this project's PPO, which is judged by the rule battery.
- The sibling also drives its advantage recursion with a single `done` flag and its sampler has a wrong joint law (adjacent channels agree in sign with probability 0.6655). Both are other rules' tests (P-1, P-12) and are recorded as out of scope here so that a passing INT-FSIM-06 is not read as a clean bill.
- The lesson recorded with the gate: a training gate tests learned behaviour against a negative control, never plumbing; the sibling's exported checkpoint has an all-zero policy head.
- The capture tool builds on the toolchain of the pinned FrankenSim commit if that differs from this repository's; it is outside every `frob` graph, so the one-toolchain rule is not affected.
