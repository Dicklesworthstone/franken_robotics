## Background

Actuators are first-class in this simulator: a motor, its gear, its winding temperature, the battery and the bus
are modelled as **port-Hamiltonian** elements. An element has the form ẋ = (J(x) − R(x))·∇H(x) + G(x)·u with
output y = G(x)ᵀ·∇H(x), where H is stored energy, J is skew-symmetric and R is positive semidefinite. Then
Ḣ = uᵀ·y − ∇Hᵀ·R·∇H: stored energy changes by the power at the ports minus what the element dissipates, and
dissipation is never negative. Elements are joined by **power-conserving junctions**, so the property survives
composition. This is what makes the energy checks of the actuator subsystem statements about structure and not
bookkeeping.

The sibling FrankenSim already implements this form and the data around it (FACT, to be re-checked here):
`fs-phs` (66,221 library lines; port-Hamiltonian composition, an interconnection entry point
`interconnect_mapped`, discrete-gradient stepping that keeps the power identity in the discrete step, a finite
state-of-charge battery); `fs-tribo` (Stribeck, LuGre and rolling-loss laws, a set-valued friction step,
friction-law selection); `fs-matdb` (material data with provenance). On the referee tier the actuator crate
`frob-actuate` reuses these laws through the airlock; for the batched tiers it re-derives the arithmetic as
kernels. `fs-phs` and `fs-matdb` sit behind the airlock's `actuation` feature group, which is off by default and
is first compiled by the milestone that needs it; `fs-tribo` is in the default `referee` group.

The first file-level test of these three crates ran at M0 through test-only adapters (bead N33b-10). An admission
is never inherited: a crate first used in production at M1 is admitted at M1, by its own record, at the pin of
that day. This bead is that admission. It builds the production adapters that `frob-actuate`, the model compiler
and the contact subsystem call, and it re-runs INT-FSIM-09 through them.

Rejected alternatives. Calling the sibling crates directly from `frob-actuate`: the airlock is the only place
volatile sibling types may be named, so an upstream change is admitted by re-running a test and costs one crate.
Re-implementing the port-Hamiltonian composition here: the sibling's is the referee, and a second copy would be a
fork to maintain. Relying on `fs-phs` for closed-loop mechanisms: its constrained interconnections are deferred
upstream, so they are not used.

## Technical approach

Module layout in `crates/frob-fsim/src/`: `actuation/phs.rs`, `actuation/matdb.rs` (feature `actuation`) and
`referee/tribo.rs` (feature `referee`).

```rust
// DESIGN: trait names fix intent, not signatures. Quantities are frob_core::qty types.
pub trait PortHamiltonian {
    type Element; type Junction;
    fn element(&self, spec: &ElementSpec) -> Result<Self::Element, RefereeRefusal>;      // H, J, R, G as data
    fn interconnect(&self, parts: &[Self::Element], map: &PortMap) -> Result<Self::Junction, RefereeRefusal>;
    fn port_power(&self, j: &Self::Junction, state: &PortState) -> Vec<(PortId, Watts)>; // signed, into the junction
    fn step(&self, j: &Self::Junction, x: &State, u: &Inputs, dt: Seconds, cx: &Cx) -> Result<(State, StepAudit), RefereeRefusal>;
}
pub struct StepAudit { pub stored_before: Joules, pub stored_after: Joules, pub port_work: Joules,
                       pub dissipated: Joules, pub residual: Joules }                    // closes to rounding
pub trait FrictionLaws {
    fn select(&self, pair: &MaterialPair, condition: Condition) -> Result<SelectedLaw, RefereeRefusal>;
}
pub struct SelectedLaw { pub law: LawKind /* Coulomb | Stribeck | LuGre | RollingLoss */, pub params: Vec<Param> }
pub struct Param { pub name: &'static str, pub value: Qty, pub provenance: Provenance }   // provenance is not optional
pub trait MaterialData {
    fn material(&self, id: &MaterialId) -> Result<MaterialRecord, RefereeRefusal>;       // density etc., each field with provenance
}
```

Rules the adapters obey:
1. **Convert, never reinterpret.** A sibling refusal becomes a typed `RefereeRefusal` carrying the upstream reason
   verbatim. Nothing is retried with weakened inputs.
2. **No default data.** A missing material or a missing pair is a refusal and never a default coefficient: a
   silent default would make every design look equally plausible on a floor nobody characterized. `Param` has no
   constructor without a `Provenance`.
3. **One interconnection entry point.** Only `interconnect_mapped` is reached, and the authored sign of each
   mapped port is passed explicitly. The sibling's `transformer` helper drives the opposite direction while also
   conserving power, so power conservation alone cannot expose a swapped sign. `PortHamiltonian` builds every
   transformer, gear and coupling junction through the one adapter of the M0 probe N33c-43,
   `frob_fsim::actuation::coupling::transformer(driving, driven, direction: Direction, ratio: PositiveRatio)`
   (`Direction::Same | Direction::Opposite`), and adds no entry of its own that takes a signed coefficient.
4. **Only unconstrained junctions.** A request that would need a constrained interconnection is refused with the
   upstream reason; closed-loop mechanisms are handled by the dynamics subsystem's own rows.
5. **No cache across pins.** Any memoized selection or element carries the stack-lock digest in its key.
6. **Group membership is enforced.** The crates allowed to enable `actuation` are `frob-actuate` and
   `frob-conformance` (allow-list in bead N33b-09, checked by `xtask check-deps`); a verb that needs the group in
   a binary built without it returns `FROB-REF-790` (`foundation-group-absent`).

Sign convention for the gate (PO-SINEW-03 states the same law): at an ideal two-port of ratio r with flows
f₂ = r·f₁ and efforts e₁ = −r·e₂, the port powers satisfy e₁·f₁ + e₂·f₂ = 0.

**INT-FSIM-09 through the production adapters.**
1. *Power across an interconnection.* The brushed-motor composite: winding (state φ = L·i, H = φ²/(2L), R = R_w),
   rotor (state p = J_r·ω, H = p²/(2J_r), viscous b), and a gyrator of modulus k (τ = k·i, e = k·ω), with
   x = (φ, p), J = [[0, −k], [k, 0]], R = diag(R_w, b), u = (v, −τ_load). The two rows read
   L·di/dt = v − R_w·i − k·ω and J_r·dω/dt = k·i − b·ω − τ_load, and Ḣ = v·i − τ_load·ω − R_w·i² − b·ω².
   Over 1,000 seeded states and parameter sets: the signed powers at the gyrator's ports sum to zero within
   10⁻¹²·Σ abs(e_j·f_j); a gear (transformer of modulus N) is tested the same way.
2. *Discrete step audit.* For 10⁴ seeded steps of the motor composite, `StepAudit.residual` =
   stored_after − stored_before − port_work + dissipated is at most 10⁻⁹ relative to the larger of the terms, and
   `dissipated` is nonnegative. (The system-level gate on port energy balance is BD-076; this is the adapter's
   own check that it reports what the sibling computed.)
3. *Provenance.* Every parameter of every pair `fs-matdb` lists at the pin returns with a provenance record.
4. *Missing pair.* (`frob-test:unobtainium`, `frob-test:void`) is refused by type with the upstream reason.

**Record.** A new entry in `DEPENDENCY_ADMISSION.md` for INT-FSIM-09 at the M1 pin: commit, command, output hash,
receipt hash, worst power-sum error, pair and parameter counts, the facts re-read (entry points used; the
constrained-interconnection limit; the laws `fs-tribo` offers), and the compile cost of enabling `actuation`.
Claim: Known answer; class `Tested`; tier `referee`; determinism D2 on one platform.

## Acceptance criteria
- [ ] Power across an interconnection sums to zero to 10⁻¹² relative on 1,000 seeded states, for the gyrator and the gear, through the production `PortHamiltonian` adapter (seed done-condition).
- [ ] A missing material pair is a refusal, typed, carrying the upstream reason; no code path returns a default coefficient (seed done-condition).
- [ ] Every pair parameter returns with its provenance record; `Param` cannot be built without one (compile-fail test).
- [ ] The step audit closes to 10⁻⁹ relative over 10⁴ steps and dissipation is never negative.
- [ ] Only `interconnect_mapped` is called; a constrained interconnection request is refused with the upstream reason.
- [ ] `actuation` is off in every default build; `check-deps` fails a crate outside the allow-list that enables it; in a build without the group, a request to a verb whose registry row names `actuation` in `needs_groups` returns `FROB-REF-790` (exit 5) naming the group before its handler runs (the admission check of N33c-32, tested here on a `synthetic` row: `actuation_group_absent_790`). The real row that names it is `sim.run`'s, under the predicate `design-has-port-actuators`, which N15a-05 (a bead that depends on this one) registers with that member; that case is asserted by N15a-05's test `port_actuators_require_actuation` and by the `actuation` stage of N33b-21.
- [ ] INT-FSIM-09 has an admission record at the M1 pin (the production admission; an admission is per use and per pin, and N40-07's exit check reads it), citing the harness receipt of one run; the M0 record stays as history. The run is in N33a-07's form: the three clauses are bound as entries of `g1_known_answers` that wrap this bead's admission lane (`cargo test -p frob-fsim --features actuation`) and read its measured values, with the three planted adapters as the gate's controls; `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g1_known_answers --features gauntlet-mutations -- INT-FSIM-09` writes the harness receipt; and the admission record, written by a session that did not implement the adapters, cites it as `harness_receipt`. The register's one part of INT-FSIM-09 (M0) is N33b-10's row, recorded at M0 (each part has one recording bead, N38b-19): this bead writes no gate row.
- [ ] `crates/frob-fsim/CONTRACT.md` lists the three traits with their refusals, determinism class and evidence class.
- [ ] Electrical step known answer through `PortHamiltonian::step`: a locked rotor with R_w = 1 Ω, L = 10 mH and V = 12 V has current (V/R_w)·(1 − e^(−t/τ)) with τ = L/R_w = 10 ms; at t = 10 ms the current is 12·(1 − e⁻¹) = 7.5854 A, matched to 10⁻³ relative at h = 1/48,000 s (TARGET) and converging at the scheme's order under step halving.
- [ ] Interconnecting with the authored direction reversed drives the opposite direction and conserves power in both cases; every transformer junction of `PortHamiltonian` is built through N33c-43's adapter, and no public function of the `actuation` group takes a signed coefficient.
- [ ] A build whose airlock reaches the legacy entry point is rejected (the rule fixed at M0 by the probe N33c-43): a source scan finds no path or `use` item naming `fs_phs::interconnection::transformer` (or a re-export of it at the pin) outside the module `frob_fsim::conformance`, and a default-feature release build of `frob-fsim` contains no symbol of that function. The scan matches that path, not the bare word `transformer`, so the adapter `coupling::transformer` is not a hit.

### End-to-end script and logging
`scripts/e2e/suite_airlock_groups.sh` (bead N33b-21, which depends on this bead and owns the script), step
`actuation`: runs this bead's admission lane (`cargo test -p frob-fsim --features actuation`) and reads its
measured values, then builds `frob` with and without the `actuation` group. With it: `frob capabilities --json`
lists the group. Without it: the group is absent from `frob capabilities --json` and from the binary's feature
graph, and every verb whose registry row names `actuation` in `needs_groups` exits 5 with `FROB-REF-790` naming
the group. At M1 that row is `sim.run`'s, whose member `{ groups = ["actuation"], when =
"design-has-port-actuators" }` N15a-05 enters with its predicate: a referee run of a design with port actuators
exits 5 with 790 naming `actuation` in the binary without the group, a design without them runs, and with the
group both run. Logged per STD-E2E: command, exit code, wall time, evidence block, the `refusal` event, metrics
`power_sum_rel_max` (10⁻¹²), `audit_residual_rel_max` (10⁻⁹), `parameters_without_provenance` (0),
`pairs_enumerated`, and on failure the case index and the port powers.

### Known answers and negative controls
The motor's two rate values (5,000 A/s and 990 rad/s²); the power identity Ḣ = v·i − τ_load·ω − R_w·i² − b·ω²,
which at the hand state is 48 − 10 − 8 − 0.1 = 29.9 W; the gyrator hand case of the M0 probe (20 W in, 20 W out).
Negative controls: the three planted adapters. Metamorphic: scaling k by s scales both gyrator port powers by s
and leaves their sum zero; exchanging the two materials of a pair returns the same law and parameters.
Determinism: twice on one machine with one seed gives identical audits; debug and release agree inside D2.

## Considerations
- OPEN-SINEW-4: whether the second polarization pair on the referee is composed from existing sibling circuit elements or needs an upstream change. Default: open the upstream item (FD-FSIM-21) and use an in-house `f64` reference until it lands. It is decided at this admission and recorded here.
- Every tier reads the same card. If a card is wrong, the referee and the fast tiers are wrong together; provenance on every parameter is what lets a verdict that rests on an `assumed` field be refused under `--strict-data`.
- The gate register lists INT-FSIM-09 as first needed at M0 and the seed places this bead at M1. Both hold: the M0 record is the first test (N33b-10) and this is the production admission.
- If the group cannot be admitted at the M1 pin, `frob-actuate` keeps its in-house `f64` reference path for the referee and the actuator gates are run against the closed forms alone; the failure is a recorded result with that fallback.
- Compile cost: `actuation` adds 2 crates and about 151 thousand lines beyond the M1 closure (FACT, computed from the manifests on 2026-11-21); the record carries the measured check time.
- FD-FSIM-21 (P3): the battery element of `fs-phs` lacks a second polarization pair; interim posture: an in-house `f64` reference until it lands; switch-over rule: re-run the battery gate of the actuator subsystem against the sibling element.
- The airlock exposes the stored energy of a junction (joules) beside the step audit, so that a caller can check H(x_next) − H(x) = port work − dissipated from data; the tighter residual of the folded test `phs_energy_balance_closes` (10⁻¹² relative over 10⁴ steps with a time-varying voltage) is recorded beside the 10⁻⁹ bound of the gate and the smaller measured value is what the record reports.
