## Background

Kill gate KILL-FSIM (decision bead N33b-05) has a first fallback, named in advance: **the volatile FrankenSim
crates move behind a process boundary.** One pinned FrankenSim worker process per device exchanges whole jobs
with the core through the same airlock traits. The decision behind it is ADR-SUITE-02: before any FrankenSim
source is lifted, the referee moves behind a process boundary. The airlock `frob-fsim` already has two build
modes behind its traits, the feature pair `mode-inproc` (the default; adapters call FrankenSim through path
dependencies) and `mode-remote` (every volatile `fs-*` dependency compiled out; adapters speak a job protocol
(N33c-10) to the binary `frob-fsim-worker`,
a target of the same crate built in mode `inproc` from the small workspace `worker/` on FrankenSim's toolchain at
the pinned commit). The M0 gate INT-FSIM-18 exercised that path while it was inactive.

**This bead exists only on the branch where the decision is "adopt (a)".** It is not funded otherwise. Its work
is to turn an exercised fallback into the default wiring and to re-admit everything through it.

What the posture preserves: the referee is FrankenSim's own code; teleport from a device tier to the referee (a
job whose initial state is a snapshot); shadow sampling; promotion. What it costs: a fixed overhead per job, so
the referee is called in rollouts and never inside a loop; and a second build to keep, though only at pin moves.
What it does not solve: an API change still costs the adapter, but the worker can stay on an old pin while the
core moves.

## Scope

In: flipping the default mode; which bedrock-direct crates stay path dependencies and which are lifted first;
routing of every airlock trait through the job protocol; worker lifecycle under the daemon; the receipt check;
re-running the admission and group gates through the worker; the treatment of scenes that need witness
migration; overhead measurement; documentation of the posture.

Out: the protocol (N33c-10), the remote mode's client (N33c-11), the worker binary and its workspace
(N33c-12), worker supervision and `FROB-REF-791` (N33c-13), and INT-FSIM-18's exercise of them at M0 (BD-038);
the lift of the referee set (N33b-07, the second fallback); the daemon itself.

## Technical approach

**1. Default mode.** The `frob` binary's default feature set becomes `referee-remote` (which enables
`frob-fsim/mode-remote`, N33c-11) in place of the group features it enables today; since every group feature of
`frob-fsim` implies `mode-inproc`, no core crate enables a group any more, and the groups are compiled into the
worker instead (item 4). The core workspace's lockfile then contains no volatile `fs-*` crate; `xtask check-deps` gains the rule that under this posture only `worker/` may
resolve them. The stack lock's FD-FSIM row changes `posture` to `subprocess-worker`, keeps `git_rev`, and
records the worker's own toolchain channel (the worker builds on the pin's toolchain; this is the one exception
to the one-toolchain rule and it is a fallback by design).

**2. Bedrock.** Each bedrock-direct crate (`fs-ga`, `fs-math`, `fs-qty`, `fs-rand`, `fs-blake3`, `fs-ivl`,
`fs-simd`, `fs-exec`, `fs-evidence`, `fs-ad`) is re-admitted on its own from outside the tree. Those that pass
stay path dependencies. Those that do not are lifted first, since they are small (eight of the ten are under
nine thousand lines), each with a provenance header, a row in `registries/lifts.toml` and a golden test.

**3. The protocol, as wired.** Whole jobs and bounded chunks; never a per-link, per-ray or per-tick call.

```text
job    = { job_hash, stack_receipt, model (compiled referee model, canonical bytes), scene, initial_states,
           control (a schedule, or a controller program the worker evaluates), horizon, cadence, seeds,
           outputs (state columns, events, digests, energy-ledger rows) }
chunk  = { job_hash, index, first_step, last_step, columns, events, digest, final: bool }
refuse = { job_hash, code, upstream_reason }
```

A job is identified by the BLAKE3 hash of its canonical bytes and submission is idempotent on that hash. Chunks
follow a fixed logical partition of the horizon, so a restarted worker regenerates the same boundaries and the
client resumes from the last contiguous chunk whose digest it holds. The worker reports the stack receipt it was
built under; a mismatch with the job's receipt is refusal `FROB-REF-791` (`referee-worker-mismatch`: the worker
is absent, or was built under a different stack receipt than the job names), not a warning. Transport is a local
socket or a pipe, framed by length, with integers above 2⁵³ as strings where JSON is used and binary columns
elsewhere.

**4. Routing of the airlock traits.** `RefereeDynamics` and `RefereeContact` rollouts become jobs. Geometry
queries used at model and scene compile time (`GeometryKernel`, `SceneQuery`, `MeshExchange`) become batch jobs
of many queries. `Ledger`, `Session` and `Recompute` do not need the worker if their crates pass admission as
path dependencies; otherwise the local node record is used. Optional groups (`stats`, `structure`,
`multiphysics`, `actuation`, `spectral`, `optimize`) are compiled into the worker by feature and reached as
jobs; a group not built into the running worker is `FROB-REF-790`.

**5. The transactional step under this posture (the hard part, stated plainly).** The referee's transaction
calls the sibling's sustained step once per sub-interval and migrates witnesses between calls. Those calls
cannot cross the process boundary without breaking the "no per-tick call" rule, and the worker binary, being a
target of the layer-0 airlock crate, cannot link the transaction driver that lives above it. Fail-closed default
(DESIGN): under the worker posture a job carries only what the sibling's own step can complete with fixed
witnesses per segment (rollouts over planes and primitive obstacles), the worker returns the sibling's typed
refusal for the rest, and scenes that need witness migration are adjudicated by the `strict` profile, with the
referee coverage figure reporting the loss per robot class. The alternative, letting the worker host the
transaction driver, changes the layering of the worker target and needs an owner decision recorded as an ADR
before it is built; this bead prepares that decision with measurements (the share of the standard battery that
loses its referee) and does not take it.

**6. Supervision.** The daemon starts one worker per device or process slot, watches liveness, restarts on
exit, and resubmits unfinished jobs by hash. A killed worker loses no committed chunk.

**7. Re-admission and measurement.** Every admission gate and group gate in use is re-run through the worker
and recorded with the worker's receipt. INT-FSIM-18's criteria are re-measured as production numbers: a
2,000-step G1 referee rollout returns chunk digests equal, bit for bit, to the same job run in process (while an
in-process build still exists for comparison); killing the worker mid-job and resubmitting returns the same
digests; fixed overhead at most 50 ms per job and at most 5% of wall time on jobs of one second or more (TARGET).
The shadowing share is recorded against the bottom of the CPU-referee range, 0.1% of device world-seconds at
the M2 batch size; below it the worker cannot do the referee's job and the lift is considered.

## Acceptance criteria

- [ ] The KILL-FSIM decision record says "adopt (a)"; without it this bead does not start.
- [ ] `cargo build -p frob` (default features, now `referee-remote`) builds with no volatile `fs-*` crate in the core lockfile; `check-deps` enforces it.
- [ ] `frob sim run g1 --tier referee --seconds 2 --key wp-g1 --json` (the registry's M0 form; a `run` verb without a key is `FROB-REF-805`) through the worker returns the digest FrankenSim computes for itself, and the 2,000-step rollout's chunk digests equal the in-process ones bit for bit.
- [ ] Killing the worker mid-job and resubmitting returns the same digests; no committed chunk is lost or duplicated.
- [ ] A worker built at a different commit refuses the job with `FROB-REF-791`.
- [ ] Measured fixed overhead is at most 50 ms per job and at most 5% of wall time on jobs of one second or more, or the measured values are recorded with the consequence for how often the referee can be called.
- [ ] Every admission and group gate in use has a record made through the worker; bedrock crates are each recorded as `path` or `lifted`.
- [ ] The witness-migration question is written up with the measured coverage loss and handed to the owner; until decided, such scenes are adjudicated by `strict` and labelled.
- [ ] The README and `frob doctor` state the posture (`referee: worker process at <rev>`).

## Test plan

### Unit tests
- `remote_mode_has_no_volatile_fs_crate` (from `cargo metadata`).
- `job_hash_idempotent`: submitting one job twice yields one execution and the stored chunks.
- `chunk_partition_fixed_across_restart`: a restarted worker produces the same chunk boundaries and digests.
- `receipt_mismatch_refused_791`; `worker_absent_refused_791`.
- `refusal_carries_upstream_reason`: through `refuse`, the lip fixture returns `FROB-REF-721` (kind `FixedWitness`) with the sibling's reason verbatim, and a 22-contact job returns `FROB-REF-721` (kind `Capacity`, `observed` 22, `required` 21) raised by the airlock's capacity check inside the worker before any sibling call (N33a-14), with no upstream reason.
- `ints_above_2_53_travel_as_strings`: 9,007,199,254,740,993 round-trips exactly.
- `group_not_in_worker_refused_790`.
- `fixed_witness_scene_routed_to_strict`: the lip fixture is not attempted as a per-sub-interval exchange; it returns the typed refusal and the routing label.

### End-to-end script and logging
`scripts/e2e/suite_worker_posture.sh`: build `frob` in `remote` mode and the worker from `worker/`; run the G1
rollout; kill the worker with a signal mid-job and resubmit; start a worker from a different commit and submit;
time 100 short jobs and 10 one-second jobs. Logged per STD-E2E: command, exit code, wall time, evidence block
(the worker's receipt among the identities), the `refusal` events, metrics `digest_equal_inproc` (true),
`digest_equal_after_kill` (true), `overhead_ms_p50` and `_p95` (threshold 50), `overhead_fraction_1s_jobs`
(threshold 0.05), `chunks_lost` (0), and on failure the first differing chunk index with both digests. Summary
names INT-FSIM-18.

### Known answers and negative controls
KA-780: a 2,000-step G1 referee rollout through the worker returns chunk digests equal, bit for bit, to the same
job run in process, also after the worker is killed mid-job and the job resubmitted; overhead at most 50 ms per
job and 5% on jobs of one second or more; negative control: a worker built at a different commit refuses the
job. Counterexample CX-356: a fallback that exists only on paper is not a fallback. Metamorphic: splitting a
horizon into two jobs whose second starts from the first's final snapshot gives the same final digest as one
job. Determinism: chunk digests are identical twice on one machine and across worker restarts.

## Considerations

- The posture is priced, not free: the referee leaves every inner loop. Teleport, shadow sampling and promotion are rollout-shaped and survive; anything that wanted the referee per step must use the `strict` profile.
- Results from a worker at a different receipt are never merged into a same-stack claim (invariant INV-SUITE-05; refusal `FROB-REF-890` when offered).
- The worker may stay on an old pin while the core moves. That is the point of the fallback and also a slow fork of behaviour; the compatibility train still re-runs parity between the worker's pin and the newest admitted pin when one exists.
- If this posture also fails (INT-FSIM-18 cannot be met in production, or the pin builds on no toolchain), the second fallback is the lift, and the program's stop decision applies: re-plan before M1.
- Process isolation adds a small attack surface (a local socket); it is local only, framed by length, and the worker holds no credentials.
