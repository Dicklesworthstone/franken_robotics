## Background

Kill gate KILL-FSIM (decision bead N33b-05) has a second fallback, taken **only if** the first (a pinned
FrankenSim worker process) fails its gate INT-FSIM-18 or the pinned commit can no longer be built on any
available toolchain: lift the minimal referee set. "Lift" is one of the five postures of the suite: copied source
with a provenance header, a row in `registries/lifts.toml` and a golden test, re-owned in this repository. The
set, as the plan names it: `fs-ga`, the deterministic functions of `fs-math`, `fs-rand`, the `fs-mbd` articulated
module, and the `fs-contact` multicontact solve. The README then states "lift-only", and the upstream work items
stay open.

This epic exists only on the branch where the decision is "adopt (b)". It is a plan, not funded work, until
then. Its honest size is the reason it is second: the lift set is small only on paper. FACT (computed from the
manifests on 2026-11-21): a path dependency on `fs-mbd` compiles 42 other FrankenSim crates and about 1.57
million lines of library source, because `fs-contact` depends on `fs-material` (633 thousand lines),
`fs-thermal`, `fs-thermochem` and `fs-feec`. The two modules the lift names sit on a closure of about 1.5 million
lines, and cutting them free of the material crate is engineering that the worker fallback avoids entirely. The
program's stop decision says the same: re-plan before M1 if path consumption cannot pass within two weeks and the
worker also fails, because the only route left is this lift.

(the lift copies; improvements go upstream as before).

## Technical approach

1. **Provenance header on every lifted file**: origin repository, path, commit, date of lift, the modifications
   made (ideally none beyond import paths), and the licence statement. A file under a lifted path without the
   header fails the registry test that pairs files with rows.
2. **`registries/lifts.toml` row per file**: `origin_repo`, `origin_path`, `origin_rev`, `local_path`,
   `content_hash_at_lift`, `golden_test`, `modified` (boolean) and `reason`. The registry loader rejects a lifted
   file with no row and a row with no file.
3. **Golden test per lifted unit**: outputs of the lifted code equal pinned captures taken from the original at
   `origin_rev` (stored under `tests/fixtures/oracle/` with the pin and date, never regenerated from the
   candidate). While the worker process still runs FrankenSim's real code at the old pin, it is the live oracle:
   the same job through `remote` and through `lifted` must give equal chunk digests.
4. **Cutting free of the material crate** is done by the census, not by guesswork: stage 1 lists exactly which
   types and functions of `fs-material`, `fs-thermal`, `fs-thermochem` and `fs-feec` the multicontact solve
   touches. Each is either lifted with it, replaced by a trait the lifted code defines and this project
   implements, or shown unused. The census output is the estimate on which the owner decides whether stage 4 is
   affordable or the program re-plans.
5. **Where the lifted code lives.** The lifted referee exceeds the airlock crate's cap of 20 thousand lines; an
   ADR either raises the cap with the reason or creates one new crate for lifted sources under the new-crate
   rule. Either way `frob-fsim` remains the only crate that names the lifted types to the rest of the workspace.
6. **Upstream stays open.** Lifted files are a frozen copy; defects are still reported and fixed upstream first,
   then re-lifted with a new row. The limits recorded by the admission tests (21 contacts, fixed witnesses,
   joint kinds, platform elementary functions) are lifted with the code and keep their postures.

## Acceptance criteria

- [ ] The KILL-FSIM decision record says "adopt (b)", citing the failed worker gate or the unbuildable pin; without it nothing in this epic starts.
- [ ] Stage 1's census exists and gives a line estimate for stage 4 with the symbol list; the owner has accepted the estimate or chosen to re-plan.
- [ ] Every lifted file has a provenance header and a `registries/lifts.toml` row, and every row's golden test passes.
- [ ] In mode `lifted` the admission tests for the Lie façades, the articulated dynamics, the broad phase and capacity pass with the same tolerances as in mode `inproc`, and the G1 digest equals the capture from the original.
- [ ] The README states "lift-only" and `frob doctor` reports `referee: lifted from <rev>`.
- [ ] The fidelity ledger is re-baselined once and the old and new envelopes are recorded.
- [ ] The upstream work items remain open in `registries/upstream.toml`.

## Test plan

### Unit tests
Per stage, the stage's own bead names them. Required of every stage: `lifted_file_has_header`,
`lifts_registry_row_matches_file_hash`, `golden_capture_equal`, and the corresponding admission test run in mode
`lifted`.

### End-to-end script and logging
`scripts/e2e/suite_lift_parity.sh` (written with stage 5): the same referee jobs through `remote` (the worker at
the old pin) and through `lifted`, asserting equal chunk digests; then `frob sim run g1 --tier referee --seconds
2 --key "$(e2e_key lifted-g1)" --json` (`sim.run` is a `run` verb, so the key is required; a keyless call is
`FROB-REF-805`) asserting the captured digest. Logged per STD-E2E with the evidence block, both receipts, the metric
`digest_mismatches` (threshold 0), `lifted_files`, `lifted_lines`, and the first differing chunk on failure.

### Known answers and negative controls
The known answers of the admission tests it re-runs (frame-invariant power to 10⁻¹²; arm accelerations to 10⁻¹⁰;
1,000 of 1,000 thin steps; the 22-contact refusal). Negative control: a lifted file edited after the lift without
a registry update fails the hash check; a golden capture regenerated from the lifted code is rejected by the
fixture's recorded origin.

## Considerations

- This is the most expensive fallback in the suite chapter and the least desirable: it turns a referee maintained upstream into a copy maintained here. It is written down so that the choice, if it comes, is made with the census in hand and not in a hurry.
- A lift forfeits upstream fixes until re-lifted; the worker posture forfeits nothing. That asymmetry is why the order of the fallbacks is fixed.
- Every sibling is the owner's project, so the licence of lifted code is not an obstacle; the header still records it.
- If the census shows the multicontact solve cannot be cut free at acceptable cost, the alternative inside this branch is to adjudicate contact with the `strict` profile on this project's own kernels and lift only the dynamics; that is a re-scoping decision for the owner, recorded by amendment before it is acted on.
