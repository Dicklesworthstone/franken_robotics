## Background

FrankenRobotics consumes FrankenSim by path, and only the airlock crate `frob-fsim` may name types from
FrankenSim's volatile crates (rule L-2, invariant INV-SUITE-01). The airlock groups its adapters into Cargo
features so that a crate above it compiles, and may name, only the closure it uses. The first table of groups
serves the M1 spine. The subsystems added later (gait orbits, rare-failure statistics, structure, the memo graph,
living worlds) need more FrankenSim crates, and the plan lists them one by one: what each provides, how large it
is, which crate above the airlock reaches it, and which group gate admits it. It also lists the crates the design
was tempted to use and decides each: through the airlock, pattern only, oracle only, or not admitted.

A list in prose is not enforced. The check that enforces it already has a home: `xtask check-deps` enforces
"feature groups of `frob-fsim` enabled only by the crates listed for them", rule L-4 (each foundation is confined
to the crates in its ledger row) and rule L-12 (features that select a tier of ambition are off by default). This
bead supplies the data those rules read, for the extended list, and the tests that prove the rules bite.

Design choice (DESIGN): the data lives in the feature records of `crates/frob-fsim/contract.toml`, which already
carries the crate's feature flags with their tiers and is validated against the manifest by `check-contracts`.
Rejected: a new registry file for the airlock (one more file to drift; the feature records exist anyway) and
prose in `CONTRACT.md` alone (nothing could check it).

## Scope

In: the machine-readable form of the extended list (crates per group, consumers per crate, group gate, default,
tier); the decisions on the thirteen other crates as allow, pattern-only, oracle-only and deny rules; the
`check-deps` tests for each rule; the stub path that returns `FROB-REF-790` when a group is absent; a script that
re-reads the size and closure facts at the pin.

Out: the adapters themselves and their group gates (N33b-11 spectral, N33b-12 and N33b-13 statistics, N33b-14
structure, N33b-15 recompute, N33b-16 multiphysics, BD-068 actuation); the first group table and the
bedrock-direct list (the airlock bead of the first part of the chapter); `check-deps` as a tool (BD-003).

**4. What `check-deps` computes from these records.** (a) For every workspace member, the set of `frob-fsim`
features its manifest requests is a subset of the features whose `consumers` or `test_consumers` list names it.
(b) No default feature set of any member enables a group whose `default` is false. (c) No crate other than
`frob-fsim` and the bedrock-direct users has a direct edge to any `fs-*` crate (L-2); the pattern-only crates
have no direct edge at all; `fs-la` appears only under `[dev-dependencies]` of the allowed test crates. (d) The
deny list is absent from `cargo metadata` of every workspace. Each violation prints the rule, the offending
manifest and the dependency path.

**5. The absent-group refusal.** For each non-default group `frob-fsim` compiles a stub module when the feature
is off, whose constructors return `GroupAbsent { group }`. `frob-verbs` maps it to `FROB-REF-790`
(`foundation-group-absent`: a verb needs an airlock feature group that this binary was not built with), exit
code 5, with repairs "use a binary built with group <name>" and, where one exists, the local fallback the verb
offers. A verb never falls back silently.

**6. Facts are re-read, not trusted.** `tools/oracle/airlock_facts.sh` counts lines of Rust under each listed
crate's `src` and under its whole directory at the pinned commit, computes each closure from the manifests, and
writes the table into the admission record of the group's gate. A size or closure that moved by more than 20%
since this list was written is flagged for review of the group's compile-cost decision.

## Acceptance criteria

- [ ] `contract.toml` of `frob-fsim` carries a record for every group with crates, consumers, gate, default and tier, and `check-contracts` validates it against the manifest's `[features]`.
- [ ] `check-deps` fails each planted violation and names the rule: a crate off the allow-list requesting `structure`; a default feature set enabling `multiphysics`; a direct edge from `frob-analyze` to `fs-voi`; a normal (non-dev) edge to `fs-la`; any edge to `fs-checker`; `fs-g1-train`, `fs-truss`, `fs-conform` or an `fnx-*` package in a lockfile.
- [ ] `check-deps` passes on the real tree at M0 with only the default groups requested.
- [ ] A verb reaching an absent group returns `FROB-REF-790` with exit code 5 and names the group; no verb substitutes a fallback without saying so.
- [ ] The facts script reproduces the table at the pin or reports each difference; its output is cited by the first group-gate record that uses it.
- [ ] Both tables are present in `crates/frob-fsim/CONTRACT.md` (generated from the records, not hand-copied).

`cargo metadata`, no mocks):

- `default_enables_gated_group_fails` (rule b).
- `direct_fs_edge_outside_airlock_fails` (rule c, L-2); `bedrock_direct_edge_allowed`.
- `pattern_only_crate_edge_fails`; `fs_la_normal_edge_fails`; `fs_la_dev_edge_allowed_for_conformance`.
- `deny_list_in_lockfile_fails` for each of `fs-g1-train`, `fs-truss`, `fs-conform`, `fnx-classes`.
- `feature_record_matches_manifest`: a record naming a crate that the manifest's feature does not pull in fails `check-contracts`.
`crates/frob-fsim/tests/group_absent.rs`: `every_non_default_group_has_stub`; `stub_returns_group_absent_with_name`.
`crates/frob-verbs/tests/refusal_790.rs`: `group_absent_maps_to_790_exit_5`.

### End-to-end script and logging
`scripts/e2e/suite_airlock_groups.sh` (bead N33b-21), step `rules`: runs `cargo xtask check-deps` and
`check-contracts` on the real tree (expect success), then on four scratch copies each with one planted violation
(expect failure with the rule name). Logged per STD-E2E: command, exit code, wall time, metrics `rules_checked`,
`violations` (0 on the real tree), `planted_caught` (4 of 4), the hash of the feature records, and on failure the
manifest path and dependency chain.

### Known answers and negative controls
Known answer: the real tree passes with the default groups only. Negative controls: the planted violations
above, one per rule. Metamorphic: reordering workspace members or features changes no verdict; adding a consumer
to an allow-list turns exactly that violation into a pass. Determinism: the checks are pure functions of
manifests and lockfiles.

## Considerations

- Cargo unifies features across a build, so once one crate requests a group every crate in that build sees it. The rule therefore constrains who may request, which is what bounds the closure of each binary; `frob-conformance` may request any group for admission lanes and is never a dependency of a production binary.
- The plan's row for `fs-couple` names "coupled islands" as the consumer without naming a crate; the record uses `frob-scene`, which owns living-world state, and the coverage file reports the choice.
- `fs-eproc` and `fs-race` sit in group `optimize` in the first group table while their admission is recorded under the statistics gate; the feature records follow the group table.
- Transitive presence is not a violation: path dependencies on FrankenSim bring its closure, including third-party crates such as `nalgebra` and `rayon` through other siblings. The rules are about direct edges and about the deny list.
- Every size here is a FACT of one day. Sizes drive one decision only, whether a group is worth a feature gate; the facts script exists so that decision is revisited with numbers.
