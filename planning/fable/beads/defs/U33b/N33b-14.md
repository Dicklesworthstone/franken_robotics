## Background

At M5 the structure subsystem ("Foundry", crate `frob-foundry`) sizes links, optimizes their topology, checks
stress and fatigue, allocates tolerances and writes build packets. Its own code is the robotics and the glue:
load extraction, interface tractions, gauge placement, the loads–mass loop, the packet. The solid mechanics, the
optimizers and the exchange formats are FrankenSim's, reached only through the airlock `frob-fsim` behind the
Cargo feature group **`structure`**, off by default and compiled only by the M5 lanes.

of other FrankenSim crates a non-optional path dependency compiles):

Beyond the M1 closure the group adds 13 crates and about 412 thousand lines of library source (FACT, computed
from the manifests on 2026-11-21). It is one of the two groups whose feature gate saves real compile time.

Group gate INT-FSIM-15 (first needed at M5; thresholds are TARGETs). The group compiles from this repository
behind its feature, one known answer passes through the airlock trait, and one negative control fails:

| Known answer through the airlock | Negative control |
|---|---|
| A tolerance allocation on a two-term stack reproduces the hand-computed variance split; a mesh written through `fs-io` reads back with the same hash | A STEP file above the stated bound is quarantined with a receipt, not parsed |

What the siblings do not provide, and the plan says so (it shapes the adapters): no path from telemetry to load
cases; no multibody interface; `fs-topols` is two-dimensional and plane strain; the three-dimensional lane of
`fs-topopt` is feature-gated upstream and its stress aggregate is not a bound on the maximum; `fs-fab` compares
a supplied number with a limit and measures no geometry; the faceted STEP exporter accepts only a solid produced
by its own decoder; `fs-asbuilt` needs supplied correspondences.

## Scope

In: feature `structure` of `frob-fsim` with its four traits and typed refusals; the mesh and STEP surface of
`MeshExchange` that Foundry uses; the consumer allow-list; the INT-FSIM-15 test; recorded limits; the record.

## Technical approach

Modules `crates/frob-fsim/src/structure/{solid,topopt,toleralloc,asbuilt,geocon,fab}.rs` behind feature
`structure`; `geometry/exchange.rs` for `fs-io`.

```rust
// DESIGN: trait names fix intent, not signatures. Quantities are frob_core::qty types.
pub trait ToleranceAllocation {
    fn variance_budget(&self, spec_margin: Qty, target: Ratio) -> Result<Qty, RefereeRefusal>;
    fn allocate(&self, features: &[Feature], budget: Qty, k_sigma: Ratio) -> Result<Vec<Allocated>, RefereeRefusal>;
    fn robustness_check(&self, alloc: &[Allocated], q: &dyn Fn(&[Qty]) -> Qty) -> Result<BandReport, RefereeRefusal>;
}
pub struct Feature { pub sensitivity: Qty, pub cost_coeff: Qty }           // sensitivity must be positive
pub trait StructuralOpt  { /* elastic solve on a tetrahedral mesh; density or level-set optimization; whole jobs */ }
pub trait AsBuilt        { /* rigid registration with supplied correspondences; the fit residual is returned */ }
pub trait FabricationRules { /* scalar limit constraints by process; a repair target per violation */ }
pub trait MeshExchange {
    fn write_mesh(&self, mesh: &TriMesh, fmt: MeshFormat) -> Result<Bytes, RefereeRefusal>;
    fn read_mesh(&self, bytes: &[u8], fmt: MeshFormat, limits: &ImportLimits) -> Result<Imported<TriMesh>, RefereeRefusal>;
    fn read_step(&self, bytes: &[u8], limits: &ImportLimits) -> Result<Imported<FacetedSolid>, RefereeRefusal>;
}
pub enum Imported<T> { Accepted(T, QuarantineReceipt), Quarantined(QuarantineReceipt) }   // every import has a receipt
```

Adapter rules: convert and never reinterpret; never retry with weakened inputs (an over-bound file is not
re-read with a larger bound); no cache across pins; limits are data (`ImportLimits` are read from the sibling's
defaults and can only be tightened by the caller); structural jobs are whole jobs with cancellation checked at
the job's stated safe points. A verb that needs the group in a binary built without it returns `FROB-REF-790`.

**INT-FSIM-15, the test** (`crates/frob-fsim/tests/admission/int_fsim_15.rs`, lane `--features structure`).
1. *The two-term stack, by hand.* Two features with sensitivities s = (1, 4), equal cost coefficients, tolerances
   quoted at k = 3 standard deviations, and a budget √B = 10 µm on the stacked quantity. The cost-optimal
   allocation is t_i ∝ (c_i/s_i²)^(1/3), so t₂/t₁ = (1/16)^(1/3) = 0.39685, and the budget condition
   Σ s_i²·(t_i/k)² = B gives t₁²·(1 + 16 × 0.15749) = 900 µm². Hence t = (15.99, 6.35) µm. The **variance split**
   is s_i²·(t_i/k)²: 28.41 µm² and 71.59 µm², summing to 100 µm². Equal tolerances meeting the same budget are
   7.28 µm each, and under a 1/t cost model the allocation costs 19.9% less. Pass: the adapter returns both
   tolerances to 10⁻⁹ relative, the variance contributions sum to the budget to 10⁻¹², and the split matches.
   *KA-770's printed fixture* (N33-KA): the stack y = a₁·x₁ + a₂·x₂ with a = (1, 2) and σ = (0.03, 0.02) mm
   (that is t = k·σ with k = 3) gives contributions a_i²·σ_i² = 0.0009 and 0.0016 mm², σ_y = 0.05 mm and shares
   36% and 64%; the adapter's split of that allocation (the same s_i²·(t_i/k)² with s = a) matches to 10⁻¹²
   relative.
2. *Mesh round trip.* A tetrahedron and a 1,000-triangle seeded closed mesh are written through `MeshExchange`
   in each supported mesh format and read back; pass when the canonical mesh hash (BLAKE3 over the canonical
   vertex and index bytes) is identical and each import returns `Accepted` with a quarantine receipt.
3. *Negative control from the gate.* A STEP file whose instance count exceeds the stated bound (the sibling's
   default admits 10⁶ instances per file; the test tightens the bound to 100 and supplies 101) must return
   `Quarantined` with a receipt that names the bound and the observed count, and no solid. A second file with an
   open shell is refused.
4. *Planted adapters.* `planted::raise-bound-and-retry` re-reads an over-bound file with a larger bound and
   returns the solid; `planted::equal-tolerances` returns 7.28 µm for both features. Both must be caught.
5. *Zero sensitivity.* A feature with sensitivity 0 is refused by the adapter with the upstream reason (the
   sibling requires positive sensitivities); it is not given an unbounded tolerance.
6. *Recorded limits* (each with file and line at the pin): `fs-topols` is two-dimensional and plane strain; the
   `sdf3` lane of `fs-topopt` is behind an upstream feature; the faceted STEP exporter has no mesh entry point;
   `fs-fab` measures no geometry; `fs-asbuilt` needs correspondences; default import limits.

**Record.** `DEPENDENCY_ADMISSION.md` entry for INT-FSIM-15 at the M5 pin: commit, command, output hash, receipt
hash, the measured tolerances and split, the mesh hashes, the quarantine receipt of the control, the recorded
limits, and the compile cost of the group (cold and warm check time and peak memory against the envelope of one
hour, 16 GiB and 8 cores). Claim: Known answer; class `Tested`; tier host; determinism D0 for the allocation and
the round trip. The gate is recorded in N33a-07's form: KA-770 (N33-KA) is bound as an entry of
`g1_known_answers` naming INT-FSIM-15 that wraps case 1 (KA-770's fixture with the two-term hand case) and case
2 through the airlock traits, with the over-bound STEP file of case 3 and the two planted adapters as its
controls; `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g1_known_answers --features
gauntlet-mutations -- INT-FSIM-15` writes the harness receipt; the admission record cites it as
`harness_receipt`; and the gate value is entered from the same receipt with `cargo run -p frob-conformance
--example record_gate -- --gate INT-FSIM-15 --receipt <hash>` by a session that did not write the adapters.
BD-401 re-runs these entries at its own pin.

### Unit tests
- `toleralloc_two_term_stack_hand_case` ((15.99, 6.35) µm; ratio 0.39685; split 28.41 / 71.59 µm²); `toleralloc_ka770_fixture` (0.0009 and 0.0016 mm²; σ_y = 0.05 mm; 36% and 64%).
- `toleralloc_equal_cost_saving`: cost Σ 1/t is 0.2201 per µm against 0.2749 for equal tolerances, 19.9% lower.
- `toleralloc_zero_sensitivity_refused`; `toleralloc_budget_met_exactly` (property test over seeded stacks of 2 to 16 terms).
- `mesh_round_trip_hash_equal_all_formats`; `import_always_returns_receipt`.
- `step_over_bound_quarantined_not_parsed` (expects `Quarantined`, bound 100, observed 101); `step_open_shell_refused`.
- `step_tetrahedron_round_trip`: 18 instances; bit-exact replay of the re-emitted file.
- `planted_raise_bound_caught`; `planted_equal_tolerances_caught`.
- `limits_only_tighten`: a caller cannot pass limits looser than the sibling's defaults.
- `group_absent_refusal_790`.

### End-to-end script and logging
`scripts/e2e/suite_airlock_groups.sh` (owned by N33b-21, a dependency: an M1 bead whose script holds a stage per
group, skipped until the group's bead lands), step `structure`, which this bead enables: it runs the lane
(`cargo test -p frob-fsim --features structure --test admission -- int_fsim_15`) under a timeout on the
`with-structure` build, and the `group_absent_refusal_790` test on the `without-structure` build, and logs the
hashes of the harness receipt and the admission record; it writes no gate record. That is this bead's evidence. The step's
verb-level rows (with the group, `frob foundry size --fixture cantilever --fe --json` within 2% and 5%;
without it, the same command exiting 5 with `FROB-REF-790` while `frob foundry size --fixture cantilever
--json` without `--fe` answers from the closed-form beam rung, exit 0, 1.159 mm and 30 MPa) need the verb of
BD-401, which depends on this bead: they run once BD-401 lands, BD-401's own script asserts them (its steps 3
and 6), and this bead's closure does not wait on them. Logged per STD-E2E: command, exit code, wall time, evidence block, the `refusal` event, metrics
`tolerance_rel_err_max` (10⁻⁹), `variance_sum_um2` (100), `mesh_hash_equal` (true), `step_quarantined` (true),
`cold_check_s`, `peak_rss_gib`, and on failure the format or feature at fault with both values.

### Known answers and negative controls
KA-770: a two-term tolerance stack reproduces the hand-computed variance split, and a mesh written through
`fs-io` reads back with the same hash; negative control: a STEP file above the stated bound is quarantined with a
receipt, not parsed. Metamorphic: scaling both sensitivities by a factor c scales both tolerances by 1/c;
exchanging the two features exchanges their tolerances; translating a mesh changes its hash and leaves its
topology hash unchanged. Determinism: identical bytes for the written meshes and the re-emitted STEP file twice
on one machine and across platforms.

## Considerations
- Upstream work items in this group (all P3, done in FrankenSim's repository): a correspondence-search lane for `fs-asbuilt` (FD-FSIM-25; interim: datums and fiducials placed at design time); a mesh entry point to the faceted STEP exporter (FD-FSIM-26; interim: faceted export under a stated triangle bound with decimation and re-check or refusal); a plane-stress option in `fs-topols` (FD-FSIM-27; interim: three-dimensional runs only, thin plates checked by the independent solver); a stable surface for `fs-topopt::sdf3` (FD-FSIM-28; interim: reached behind its feature, pinned by commit); geometric evaluators in `fs-fab` (FD-FSIM-29; interim: Foundry owns them and reports `review: no-claim`); a statement of boundary conformity in `fs-mesh` (FD-FSIM-30; interim: conformity measured per mesh).
- If the group fails admission, nothing on a critical path stops: the beam rung is closed-form and needs no sibling; topology optimization falls under its own kill gate; tolerance allocation falls back to worst-case boxes; export falls back to parts list, mass properties and STL.
- A first-order allocator treats a zero sensitivity as freedom to loosen without limit. The refusal in case 5 is the guard; the band-extreme check that handles such features belongs to the Foundry tolerance bead.
- Every imported file is hostile input until its receipt says otherwise; the adapter exposes no entry point that parses before quarantine.
- An admission is never inherited: `fs-io` was admitted for scenes earlier under the `geometry` group; its STEP surface is first used here and is admitted here.
- The `structure` group serves Frontier work. Its adapters are built only after the structure-loop pilot (N31b-06,
  a dependency) has a record that funds the loop; if the pilot's falsifier holds, only the mesh and bounded-STEP
  surface of `MeshExchange` is built here.
