## Background

M0 answers one question by measurement: can the foundations be consumed from outside their trees, and do the
files this project leans on behave as it assumes? The answer is a set of admission records. The user-visible
form of that answer is one command: `frob doctor` lists the admitted foundations with their records and the stack
receipt, and `DEPENDENCY_ADMISSION.md` holds every record, passing or failing.

Each admission test has its own bead with its unit tests. What no single bead shows is the whole battery run
from the user's side in one pass, with one log that an exit reviewer can read: which gates ran, on which
receipt, with which measured values, and which negative controls were caught. That is this bead. It is the
end-to-end script for the capability "foundation admission at M0" of the suite chapter's middle subsections
(the file-by-file tests and the reported foundation defects).

The battery also guards two rules that are easy to break quietly. A record is valid only if it cites a commit
of this repository whose tracked `Cargo.lock` contains the foundation (a sibling product once found admission
records for crates that were not in its build). And no gate records a PASS on a dirty sibling tree.

## Scope

In: the script `scripts/e2e/suite_admission_m0.sh`, its step list, its assertions against `frob doctor` and the
gate status file, its structured log; the cross-checks on records; a self-test of the script with planted
failures.

Out: the admission tests themselves (their beads); the path-consumption gate and the toolchain gate (BD-006,
BD-031); the worker fallback gate (BD-038), whose own script is called as a step if present; the group gates of
later milestones (N33b-21).

## Technical approach

Plain shell, sourcing the shared helper of STD-E2E; it drives the real `frob` binary and the real test targets on
real sibling checkouts, is idempotent (a scratch store and a scratch copy of the gate file per run) and
seed-explicit (`FROB_E2E_SEED`, default fixed). Every long command starts under a timeout and inside the machine
envelope (16 GiB, 8 cores, one hour).

**Steps.**

| Step | Runs | Asserts |
|---|---|---|
| `stack` | `cargo xtask check-stack`; `frob doctor --json` | The receipt hash printed by both is the same; every sibling's drift class is reported; a dirty sibling makes later PASS assertions downgrade to "development only" |
| `asup` | `cargo xtask check-deps`; the asupersync identity checks | One package per workspace, one version (INT-ASUP-01); the planted second version fails on a scratch copy |
| `int_fsim_02`, `int_fsim_03` | The admission lane of `frob-fsim` | Power invariance at most 10⁻¹² relative; Jacobian at most 10⁻⁷; reversed adjoint fails at least three fixtures; arm accelerations at most 10⁻¹⁰ from the energy derivation; the recorded facts present |
| `int_fsim_04`, `int_fsim_07_refusal` | The same lane; `frob sim run --tier referee --fixture wheel-over-lip --no-migration --json` | 1,000 of 1,000 thin steps detected; 22 contacts refused with cap 21; the lip transition exits 5 with `FROB-REF-721` and the upstream reason |
| `int_fsim_05` | The oracle tests of `frob-conformance` and the sibling run | Chord (0, 2/π) m; one metre over 400 steps at heading 32 rad; the record states whether zero translation reproduces; the oracle mark matches the gate status |
| `int_fsim_06` | The capture tool in its own workspace; the probe tests | The three probe results recorded for the sibling; three planted defects caught; `fs-g1-train` in no lockfile |
| `int_fsim_08`, `_09`, `_10` | The lane with `--features actuation,optimize` | Support gaps at most 10⁻¹² m; power sum at most 10⁻¹² relative; every parameter with provenance; missing pair refused; implicit sensitivity (5.785124, 1.652893) |
| `int_ft_02` (Mac only) | The Metal annex test; `frob spark probe --backend gpu-metal --json` | Residency across two command buffers; device receipt; zero coverage from a tag |
| `foreign` | Steps of other units if present: INT-FSIM-11, INT-FSYM-02, INT-FNP-01, INT-FNP-02, INT-FSIM-18 | Each either passes or is logged `skipped: capability absent` |
| `records` | Reads `DEPENDENCY_ADMISSION.md`, `registries/gates.toml`, `frob doctor --json` | Every gate above has exactly one current record; each record cites a commit whose tracked lockfile contains the foundation, a command, an output hash and the receipt hash of step `stack`; no PASS on a dirty tree; `frob doctor` shows the same statuses as the gate file |

**Cross-checks in step `records`.**
1. For each record, check out nothing: read the cited commit's lockfile with `git show <commit>:<lockfile>` and
   assert the foundation's package name is present.
2. Recompute the BLAKE3 of each command's stored output and compare with the record's hash.
3. Assert that a gate whose test detected a real sibling defect is recorded `fail` with the interim posture
   named (the planar drive and the PPO update are expected in this state at the first pin) and that such a
   `fail` is listed under "recorded: fallback adopted", not under "blocking".
4. Assert INT-FSIM-07 is `part 1 of 2` at M0.

**Self-test.** `scripts/e2e/tests/suite_admission_m0_selftest.sh` runs the script against scratch inputs with
three planted failures: a record citing a commit whose lockfile lacks the foundation; a PASS recorded with a
dirty sibling; a tampered output hash. Each must fail step `records`.

**Logging (STD-E2E).** Newline-delimited JSON to `target/e2e-logs/suite_admission_m0/<utc-timestamp>.ndjson` and a
transcript beside it. Every line has `ts`, `script`, `bead`, `step`, `event` (`start`, `cmd`, `assert`, `metric`,
`refusal`, `end`), the exact command line, exit code, wall time, the envelope's `evidence` block where a `frob`
command ran (claim, class, tier, determinism, identities, seed), each measured value with its unit and
threshold, digests where state is compared, and on failure the first differing value and the artifact paths
needed to reproduce. The final `summary` line gives assertions passed and failed, steps skipped with reasons,
and the gates touched. Logs contain no private-scene data (the battery uses built-in fixtures only).

## Acceptance criteria

- [ ] The script exits 0 on a clean stack at the admission pin when every step's assertions hold, and non-zero on the first failed assertion with the failing value in the log.
- [ ] Every gate in this bead's `gates` field appears in the summary line with its status and measured values.
- [ ] `frob doctor --json` and `registries/gates.toml` agree on every status, and both carry the receipt hash of step `stack`.
- [ ] The three planted failures of the self-test are each caught by step `records`.
- [ ] Skipped steps are logged as `skipped` with a reason and are never counted as passed; on a host without Metal the `int_ft_02` step is skipped and INT-FT-02 stays `not run` for that host.
- [ ] Two consecutive runs on an unchanged tree produce logs that are identical except for timestamps and wall times.
- [ ] The summary is attached to the M0 exit review as the admission evidence for the file-by-file and defect gates.

## Test plan

### Unit tests
Shell tests under `scripts/e2e/tests/`:
- `e2e_log_schema_suite_admission_m0`: every log line validates against the STD-E2E schema.
- `e2e_summary_counts_match`: the summary's counts equal the number of `assert` events.
- `e2e_skip_is_not_pass`.
- `e2e_script_idempotent`: a second run in the same scratch directory succeeds and changes no tracked file.
- `records_citing_absent_foundation_fail`, `pass_on_dirty_tree_fails`, `tampered_output_hash_fails` (the self-test).

### End-to-end script and logging
This bead is the script. Commands and assertions as tabulated; logging as specified.

### Known answers and negative controls
The battery re-asserts, from the user's side, the hand values of its member tests: torque (0, −1, 0) N·m for the
pushed wrench; (−9g/7, +12g/7) for the two rods; the chord (0, 2/π) m; finite differences 0, −0.5, −1; critic
gradient 2; ratio 1; gaps 0.01 m and 0.292893 m; (700/121, 200/121); element values 2·(i + 1) on the device.
Negative controls: one planted defect per member test is re-run through the script's `--controls` mode and must
turn its step red (the reversed adjoint, the endpoint-only detector, the truncating adapter, the threshold-branch
integrator, the three PPO mutants, the default-friction adapter, the host round trip). Determinism lanes: twice
on one machine; debug and release for the pure lanes; cross-platform equality is not asserted for results that
depend on the sibling's platform elementary functions.

## Considerations

- A red gate here is information, not a broken build: at the first pin two sibling defects are expected to reproduce. The script distinguishes "assertion of this project failed" (exit non-zero) from "sibling defect recorded with posture adopted" (exit 0, listed in the summary).
- The battery compiles two non-default airlock groups and one out-of-graph capture tool. Its cold run is dominated by the FrankenSim closure (about 65 crates and 2.06 million lines for the M1 set); it runs at admission, at every pin move and at the exit review, not per commit.
- Admission is never inherited: the compatibility train calls this script after each pin move, and the records it checks must carry the new receipt.
- The script never writes to a sibling checkout and never resets one; a drifted sibling is reported with its class and the PASS assertions are downgraded.
