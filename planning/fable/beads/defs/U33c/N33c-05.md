## Background

FrankenRobotics types its physical quantities with FrankenSim's `fs-qty`, reached through the single module
`frob_core::qty`. `fs-qty` depends on `generic_const_exprs`, a nightly compiler feature marked incomplete. Three
events could make that dependency untenable: a toolchain train moves the project's toolchain T to a nightly where
the feature has regressed; a crate in the graph needs a newer compiler than any nightly on which `fs-qty`
compiles; or a stable-only target appears (firmware export would be one).

The preferred remedy is always an upstream change in FrankenSim's own repository: FD-FSIM-15 (the
macro-generated dimension products `fs-qty` documents as its fallback, behind a feature) or FD-FSIM-31 (remove
`fs-qty` from `fs-evidence`). `frob-units` is the fallback for the case that neither can land in time.

**The trigger (DESIGN).** `frob-units` is created if, and only if, `fs-qty` fails on T after a toolchain train
and the upstream change cannot land within that train. The decision is an ADR written at INT-TOOLCHAIN-01
(BD-031) and revisited by every toolchain train (NF-02, step 3: the `fs-qty` decision at a train). Until the
trigger fires this bead is not started; it
exists so that the fallback is specified in advance and not improvised. It is conditional and is not counted in
the crate map: layer 0, cap 3 thousand lines of Rust including tests.

**How it closes either way (DESIGN).** The M0 exit review (BD-044) waits on this bead through N33c-06, so the bead
must be closable on both branches of BD-031's decision. Hatch open: it is built to this text and closes `pass`.
Hatch closed: it closes `withdrawn` citing BD-031's `frob-units` ADR
(`withdrawn: not needed: escape hatch closed, docs/adr/<that ADR>`), the close the lifecycle rules give a bead on
a branch a decision did not take (N41-17, rule 5), and N33c-06 closes the same way. A later toolchain train
whose ADR opens the hatch (NF-02, step 3) reopens this bead and N33c-06, and that train does not proceed until
both close `pass`.

**The cost, stated.** `frob-units` loses `fs-qty`'s open-ended dimension arithmetic. A quantity outside the
alias set must be added to it or carried as a checked runtime value. That is why `frob_core::qty` has exposed
only a closed alias set from the first commit (N33c-03).

Rejected alternatives: a fork of `fs-qty` (it would carry the nightly feature with it); a third-party units crate
(the core's runtime dependencies are the standard library and Franken foundations only); dropping typed
quantities (rule L-6 forbids bare `f64` physical quantities above layer 1).

## Scope

In: the crate `crates/frob-units` with dimension vectors, the alias types, the macro that generates products and
quotients, the runtime-checked quantity, SI unit strings and parsing of the unit strings the design language
uses, its contract and tests. Out: conversions to and from `fs-qty` and the switch of the re-export (N33c-06);
the alias decision (N33c-04).

## Technical approach

1. **Dependencies and compiler.** Standard library only; `#![forbid(unsafe_code)]`; no feature attribute.
   Compiles on T and on the stable release named in `frob-cert`'s toolchain file. Layer 0, rank after
   `frob-core`'s dependencies allow (it has none, so `frob-core` may depend on it).
2. **Dimension (DESIGN).** `pub struct Dim([i8; 6])`: six signed 8-bit exponents in the order metre, kilogram,
   second, kelvin, ampere, mole. This is `fs-qty`'s order (FACT: `fs-qty/src/lib.rs`, `DIMENSION_COUNT = 6`), so
   a dimension vector means the same thing on both sides of a conversion. `Dim::add`, `Dim::sub` are checked:
   an exponent leaving [−128, 127] is a refusal, never a wrap.
3. **Aliases.** One newtype per alias of `registries/qty_aliases.toml`: `#[repr(transparent)] pub struct
   Torque(f64);` with an associated `const DIM: Dim` and `const UNIT: &str`. Same-dimension aliases are distinct
   types by construction (Torque and Energy both have (2, 1, −2, 0, 0, 0) and do not add). Each alias implements
   `Add`, `Sub`, `Neg` with itself, `Mul<f64>` and `Div<f64>`, `PartialOrd`, and `value()` / `new()` in SI base
   units. No `Deref` to `f64`.
4. **Products and quotients.** A declarative macro `qty_products! { Force * Length = Energy; Energy / Time =
   Power; … }` expands each row of `registries/qty_products.toml` into `impl Mul<Rhs> for Lhs { type Output = Out;
   }` (or `Div`). A `const` assertion in each expansion checks `Out::DIM == Lhs::DIM ± Rhs::DIM`, so a wrong row
   fails to compile. Dividing an alias by itself yields `Ratio`. This is the fallback `fs-qty` documents for
   itself.
5. **Runtime-checked quantity.** `pub struct Checked { value: f64, dim: Dim }` for data loaded at run time
   (cards, imported models). `Checked::into::<A>()` returns `A` if `dim == A::DIM` and otherwise an error
   carrying both vectors, which `frob-core` maps to refusal `FROB-REF-102`. Arithmetic on `Checked` adds and
   subtracts exponents and refuses a sum of unequal dimensions.
6. **Unit strings.** `parse_si(&str) -> Result<Checked, ParseError>` for the unit grammar the design language
   uses (a number, an optional SI prefix, base and named derived units, `·`, `/`, integer exponents). Exact
   decimals stay strings until the caller chooses a conversion; the parser returns the scale as a rational pair
   and the dimension, and multiplies last.
7. **Generated code.** The alias and product declarations are generated from the two registry files, the same
   source `frob_core::qty` is generated from, and checked by `xtask check-generated`.
8. **Contract.** `CONTRACT.md` with the ten sections; `contract.toml` with layer 0, determinism class exact (no
   floating-point operation beyond the caller's own arithmetic), no budgets, no features.

## Acceptance criteria

- [ ] `cargo tree -p frob-units` prints one line (no dependency), and the crate builds on T and on the stable compiler with no feature gate.
- [ ] The crate is at most 3,000 lines including tests; the contract check reports the count.
- [ ] Every alias and every product of the registries exists; a product row with a wrong output dimension fails to compile.
- [ ] Compile-fail tests: pressure + time; torque + energy; every other equal-dimension pair of the registry.
- [ ] `Checked` refuses a mismatched conversion and a sum of unequal dimensions, with both dimension vectors in the error.
- [ ] `parse_si` round-trips the unit strings of the fixture list and refuses unknown units and non-integer exponents.
- [ ] The alias count is at most 64 (the same gate as N33c-03).

## Test plan

### Unit tests

`cargo test -p frob-units`:
- `dim_add_sub_checked`: (1, 1, −2, 0, 0, 0) + (1, 0, 0, 0, 0, 0) = (2, 1, −2, 0, 0, 0); an exponent of 127 plus 1 refuses.
- `torque_energy_same_dim_distinct_type`: `Torque::DIM == Energy::DIM`; `compile_fail/torque_plus_energy.rs` fails to compile.
- `compile_fail/pressure_plus_time.rs` fails to compile; `compile_fail/deref_to_f64.rs` fails to compile (no alias dereferences to `f64`); one file per further equal-dimension pair of the registry (the nine pairs of N33c-03 on the starter set), derived from the registry as in N33c-03's `equal_dimension_pairs_covered`.
- `product_table_dimensions`: for every generated impl, the output dimension equals the sum or difference.
- `ratio_from_self_division`: `Length / Length` has type `Ratio`.
- `checked_into_alias`: match returns the same bits; mismatch returns the error with both vectors.
- `parse_si_fixtures`: `"60 mm"` → value 0.06, dim (1, 0, 0, 0, 0, 0); `"0.1 N·m"` → dim (2, 1, −2, 0, 0, 0); `"9.81 m/s^2"`; `"12 V"`; `"3 furlong"` refuses.
- Property test: for seeded random pairs of aliases with a registered product, `(a * b).value() == a.value() * b.value()` bit for bit (the crate adds no arithmetic of its own).

### End-to-end script and logging

`scripts/e2e/suite_units_hatch.sh`, owned by this bead, which writes it with its first stage (N33c-06 adds stages
2 to 4: the differential test, the switch and the planted edge): builds `frob-units` alone on the stable compiler
from a copy of its directory, runs its tests on T and on stable, and logs `cmd` events with both compiler
versions, a `metric` event `frob_units_lines` against the threshold 3,000, and `assert` events for the
compile-fail set (each with the file and whether it failed to compile, as required). It sources the STD-E2E helper,
writes `target/e2e-logs/suite_units_hatch/<utc>.ndjson` and a transcript, and ends with a `summary` line of
assertions passed and failed.

### Known answers and negative controls

KA-779's third clause, on this crate alone (the first two, the differential test against `fs-qty` and the bit
round trip through the airlock, are N33c-06's): a pressure cannot be added to a time (compile-fail); its
negative control, a torque added to an energy, must also fail to compile although both have dimension vector
(kilogram 1, metre 2, second −2) (CX-354). Planted defects: a product row `Force * Length = Power` (must fail to
compile through the dimension assertion); a blanket `impl<A: Alias, B: Alias> Add<B> for A` (or a single `impl
Add<Energy> for Torque`) planted in a scratch copy, under which `torque_plus_energy.rs` compiles and the harness
must report that compile-fail test as failed; a `Deref<Target = f64>` on an alias, caught by the compile-fail test
`deref_to_f64.rs` (`let x: f64 = *Torque::new(1.0);` must not compile). Lanes: T and stable; debug and release.

## Considerations

- Priority is 0, the milestone's default: the M0 exit review (priority 0) waits on this bead's close on either
  branch, and the bead is not ready before BD-031 has decided, so whoever picks it up acts on a recorded decision
  (build it, or close it `withdrawn` citing the ADR). Reopened by a train, it blocks that train.
- The cap is a claim about scope. If the alias set approaches 64 the product table dominates the line count; a
  crate that reaches 115% of its cap stops taking aliases until an ADR raises the cap or moves quantities to
  `Checked`.
- `frob-cert`, the independent auditor, must not depend on this crate either: the auditor depends on nothing.
- If FD-FSIM-15 lands after this crate exists, the switch-over rule is: re-run INT-TOOLCHAIN-01; if `fs-qty`
  compiles on T without the nightly feature, the hatch closes again, `frob_core::qty` re-exports `fs-qty`, and
  `frob-units` is retained only as the differential oracle or removed by ADR.
