## Background

The plan's statements about sibling code were read on 2026-11-21 and are FACTs with paths. A sibling fact goes
stale when the sibling moves, and the rule of the suite chapter is that a fact a gate depends on is re-read by
that gate's admission test and is never copied from the plan into a record. The choice of the one toolchain T
(INT-TOOLCHAIN-01), the one-asupersync rule (INT-ASUP-01) and the dependency deny rules all rest on one table of
facts about fifteen repositories. This bead turns that table into a script that re-reads it and reports what
changed, so that the gates cite a dated survey instead of the plan.

## Scope

In: `scripts/admission/suite_survey.sh`, its record, the diff against the previous survey. Out: any change to a
sibling; the deny rules themselves (N33c-09); the receipt (BD-001, BD-004), which records only consumed
siblings.

## Technical approach

1. **Inputs.** A table `registries/siblings.toml` (DESIGN): one row per sibling with `name`, `path` (relative,
   `../<dir>`), `toolchain_file`, the manifest and key from which the asupersync requirement is read, the manifest
   keys for other watched facts (`rust-version`, workspace version, exact pins of `serde_json`), and
   `posture`.
2. **Reads, all read-only.** For each row: `git -C <path> rev-parse HEAD` (40 hex); `git -C <path> status
   --porcelain | wc -l` (modified paths); the `channel` of its toolchain file; the asupersync requirement string
   exactly as written (`path`, version requirement, `optional`, `default-features`); the watched keys. No
   `cargo` command runs inside a sibling. A missing sibling directory is recorded as `absent`, not an error.
3. **For the two "not read" rows** (franken_textiles, franken_firmware) the script reads the asupersync
   requirement and records it, closing the gap the plan left.
4. **Record.** `receipts/surveys/<utc>.json`, schema `frob.suite-survey/1`, canonical JSON: `date`, `rows[]
   {name, head, modified_paths, channel, asupersync {kind, requirement, optional, default_features}, watched{}}`,
   and derived fields: `channels_in_play` (sorted distinct list), `asupersync_0_5_0_named_by` (list),
   `not_on_candidate_a` (siblings whose channel differs from `nightly-2026-08-31`), `minimum_rust_versions`
   (crate → declared `rust-version`).
5. **Diff.** Against the previous survey (or, for the first, against the table above embedded as
   `tests/admission/survey_2026-11-21.json`): every changed head, channel or requirement is printed as one line,
   and a change in a row with posture `consume` sets exit status 3 so that a gate run notices before it cites
   the old fact.
6. **Use.** INT-TOOLCHAIN-01's ADR for the choice of T lists "the sibling pins a toolchain train must move":
   that list is `not_on_candidate_a` of the survey at the time, not the list printed above.

Determinism: exact for a fixed set of trees. No evidence class; an admission record cites the survey's hash.

## Acceptance criteria

- [ ] The script exits 0 or 3 and writes a record with fifteen rows, each with a 40-hex head or `absent`.
- [ ] The first run's diff against the embedded 2026-11-21 table is printed and attached to the INT-TOOLCHAIN-01 admission record.
- [ ] `channels_in_play` and `asupersync_0_5_0_named_by` are present; on the starting state they are four nightlies plus stable 1.99.0, and {frankentui, franken_threed, frankenjax}.
- [ ] The asupersync requirements of franken_textiles and franken_firmware are recorded (no row says "not read").
- [ ] Every sibling's `git status --porcelain` and head are identical before and after a run.
- [ ] Two runs on unchanged trees write byte-identical `rows`.

## Test plan

### Unit tests

Shell tests under `scripts/admission/tests/` against three `synthetic` sibling fixtures (small git repositories
created in scratch):
- `reads_channel_and_requirement`: a fixture with `channel = "nightly-2026-08-20"` and `asupersync = { version = "=0.5.0", optional = true }` yields those values.
- `path_requirement`: `asupersync = { path = "../asupersync" }` yields kind `path`.
- `counts_modified_paths`: two modified tracked files yield `modified_paths: 2`.
- `absent_sibling`: a missing directory yields `absent` and exit 0.
- `diff_flags_consumed_change`: a changed channel on a `consume` row yields exit 3 and one diff line.

### End-to-end script and logging

A step of `scripts/e2e/suite_toolchain_matrix.sh`: runs the survey on the real siblings, logs a `metric` event
with the count of distinct channels and the count of siblings naming asupersync 0.5.0, an `assert` event that no
sibling was modified, and the record hash.

### Known answers and negative controls

Known answer: on the embedded 2026-11-21 fixture the derived fields are exactly: channels `nightly-2026-07-06`,
`-08-20`, `-08-25`, `-08-31`, stable `1.99.0`; 0.5.0 named by frankentui, franken_threed, frankenjax;
`not_on_candidate_a` = frankensim, frankensympy, fastmcp_rust, franken_firmware. Negative control: a fixture
whose toolchain file is changed between two surveys must produce a diff line; a survey implementation that reads
the channel from the plan's table instead of the file would not, and is caught by this test. Lanes: twice on one
machine; on both machines (the two machines may hold siblings at different heads, which the diff reports).

## Considerations

- The survey is a development aid for gates, not a seventh `xtask` check: it is a script under
  `scripts/admission/`, it records no gate, and `xtask check-stack` remains the enforcer for consumed siblings.
- Sibling heads move daily (409 commits touched FrankenSim's multibody crate in thirty days). A survey is valid
  for the gate run that cites it and no longer.
- RISK-03 (two asupersync versions in one build) and RISK-02 (the toolchain train) read their leading
  indicators from this record and from `cargo tree -d`.
