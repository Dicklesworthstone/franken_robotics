## Background

Under ADR-SUITE-02 the referee can run behind a process boundary: the core, built in mode `remote`, submits whole
jobs to a worker that holds FrankenSim's real code. The worker is the binary target `frob-fsim-worker` of the
crate `frob-fsim`, built in mode `inproc` from the small workspace `worker/` at the pinned FrankenSim commit. No
new crate is created (the crate map lists `frob-fsim-worker` as a target of `frob-fsim`, not as a crate), and
`frob-fsim` remains the only code that names FrankenSim's volatile types. One worker runs per device or per
process slot; the daemon starts, supervises and stops it.

Why a separate workspace: the worker must be buildable with its own lockfile, so that it can stay on an old
FrankenSim pin (and that pin's toolchain) while the core moves. `worker/` is the seventh workspace of the
repository and only re-targets an existing crate. While the pins coincide it builds on the project's toolchain T;
when the first fallback of KILL-FSIM keeps the worker at an older pin, `worker/` builds on that pin's toolchain,
the one designed exception to the one-toolchain rule.

## Scope

In: the `worker/` workspace manifest; the binary target; the serving loop; deterministic chunk production shared
with mode `inproc`; the embedded receipt; behaviour on kill, on cancel and on end of input. Out: the protocol
encoding (N33c-10); the client (N33c-11); the supervisor and the handshake check on the client side (N33c-13);
the gate (BD-038).

## Technical approach

1. **Workspace layout (DESIGN; Cargo behaviour to confirm on T).** A package can belong to one workspace only, and
   `crates/frob-fsim` is a member of the core. `worker/Cargo.toml` is therefore a workspace root with a single
   manifest-only package that contains no source of its own:
   - `[dependencies] frob-fsim = { path = "../crates/frob-fsim", default-features = false, features =
     ["mode-inproc", "referee", "geometry", "ledger"] }` (the mode features are the pair of the airlock skeleton,
     N33a-11);
   - `[[bin]] name = "frob-fsim-worker"`, `path = "../crates/frob-fsim/src/bin/frob-fsim-worker.rs"`;
   - the same three root settings the core repeats, because Cargo does not propagate them from a path
     dependency: FrankenSim's `[patch.crates-io] asupersync` entry, its FrankenSQLite profile overrides, and
     `worker/.cargo/config.toml` with `FRANKENSIM_DEPGRAPH_SALT`;
   - its own `Cargo.lock`, committed.
   The source file `src/bin/frob-fsim-worker.rs` lives in `frob-fsim` and is also declared there as a `[[bin]]`
   with `required-features = ["mode-inproc"]`, so the core workspace can build the same binary at the same pin. If
   Cargo refuses the out-of-directory `path` for a binary, the fallback is a one-line `worker/src/main.rs` that
   calls `frob_fsim::worker::main()`; the admission record states which form was used.
2. **Old-pin operation.** When the worker must stay behind, the `FD-FSIM` row of `franken-stack.lock` gains
   `worker_rev` and `worker_toolchain`; `worker/` is built from a checkout of this repository at the commit that
   last matched that pin, with `worker/rust-toolchain.toml` naming `worker_toolchain`. Nothing in this bead moves
   a sibling checkout: the old FrankenSim source is obtained as a read-only export of `worker_rev`.
3. **Embedded receipt.** The worker binary embeds the hash of the resolution receipt it was built under. The
   build reads `FROB_STACK_RECEIPT` (64 hex) from the environment and fails closed if it is unset or malformed,
   the same discipline as FrankenSim's own build-identity variable. The build recipe
   `scripts/build/worker.sh` obtains the hash from the newest receipt under `receipts/` after `xtask check-stack`
   has verified it, and refuses to build on a dirty sibling tree unless `--development` is given, in which case
   the binary reports `receipt_class: development` in its `hello`.
4. **Serving loop (`frob_fsim::worker::main`).**
   1. Open the transport: stdin and stdout by default, or `--socket <path>` for a local socket.
   2. Send `hello { protocol: "frob.fsim-job/1", stack_receipt, receipt_class (`gate` or `development`),
      features (compiled groups and capacities, for example `sustained_contact_capacity: 21`), pid }`.
   3. Read frames. On `job`: verify `job_hash` against the received bytes; compare `job.stack_receipt` with the
      embedded receipt and answer `refuse { code: FROB-REF-791 }` on a mismatch; otherwise run.
   4. Run: build the referee model from the canonical model bytes, set initial states, and step. After each
      partition extent, emit one `chunk` with its digest. If a `resume { next_index }` accompanied the job, the
      worker still computes from step 0 (state is not persisted across restarts at M0) and suppresses emission of
      chunks below `next_index`. A later optimization may checkpoint at chunk boundaries; it must not change any
      digest.
   5. On a FrankenSim refusal: emit `refuse` with the mapped code and the upstream reason, and stop the job.
   6. On `cancel`: stop at the next step boundary and emit nothing further for that job.
   7. On end of input (the parent closed the pipe or died): exit at once. A worker never outlives its parent,
      which is how "when an agent stops, its jobs stop" is kept.
5. **One chunking code path.** Chunk assembly and digest computation are one function used by mode `inproc` and
   by the worker, so the bit-equality of INT-FSIM-18 tests the process boundary and the transport, not two
   implementations of the same formatting.
6. **Resource rule.** The worker runs one job at a time, single-threaded stepping unless the job asks for a
   worker count, and honours the machine envelope through limits set by its supervisor.

Determinism: the worker's output for a job is a pure function of the job bytes and the pinned code; no wall
clock, no address-dependent order, no thread-count dependence in the stepped state.

## Acceptance criteria

- [ ] `cargo build --release --locked` in `worker/` (through the offload shim) produces `frob-fsim-worker`; `cargo metadata` there shows `frob-fsim` as the only local package besides the manifest-only one, and no source file exists under `worker/` other than manifests and configuration (or the one-line `main.rs` of the stated fallback).
- [ ] The build fails closed with `FROB_STACK_RECEIPT` unset.
- [ ] `worker/.cargo/config.toml` sets `FRANKENSIM_DEPGRAPH_SALT` to the string of the root config and of the `FD-FSIM` row's `build_env` (N33a-08); on a scratch copy with the entry removed and the root config absent, the worker build fails closed with FrankenSim's own message.
- [ ] The first frame from a started worker is `hello` with the protocol string, the embedded receipt and the compiled features.
- [ ] A job whose `stack_receipt` differs from the embedded one is answered with `refuse` carrying `FROB-REF-791`, and no step is executed.
- [ ] Killing the worker with SIGKILL mid-job and starting a new one with the same job yields the same chunk digests.
- [ ] Closing the worker's stdin makes it exit within 1 s (TARGET) with no child left behind.
- [ ] The resolution receipt lists the `worker` workspace lockfile with its hash and package count.

## Test plan

### Unit tests

`cargo test -p frob-fsim worker::` (mode `inproc`) and harness tests that start the real binary and speak to it
with frames from the codec of N33c-10 (the client of N33c-11 and the supervisor of N33c-13 are built after this
bead and on it):
- `hello_first`: the first frame is `hello`; fields as specified.
- `job_hash_mismatch_refused`: a job whose bytes were altered after hashing is refused as a protocol error.
- `receipt_mismatch_refuses_791`: zero steps executed (a step counter in `hello`-level statistics is unchanged).
- `chunks_follow_partition`: a 2,000-step job at C = 250 emits exactly indices 0 to 7 with the expected bounds.
- `resume_suppresses_earlier_chunks`: with `resume { 5 }` only indices 5, 6, 7 arrive, with unchanged digests.
- `cancel_stops_at_step_boundary`.
- `exits_on_stdin_close`.
- `upstream_refusal_mapped`: a 22-contact island yields `refuse` with the capacity code and FrankenSim's text.

### End-to-end script and logging

`scripts/e2e/fsim_worker.sh` (owned by this bead; header `bead=N33c-12 milestone=M0 labels=suite,frob-fsim
plants=ignore-resume,digest-without-events`), on the STD-E2E helper: builds the worker with
`scripts/build/worker.sh` (and once with `FROB_STACK_RECEIPT` unset, expecting the build to fail closed), runs
`cargo metadata --locked --format-version 1` in `worker/`, runs the harness tests above against the real binary,
then builds the second worker under a different receipt and asserts the `FROB-REF-791` refusal with zero steps.
It logs the build commands with exit code and wall time, the `hello` contents (receipt hash, receipt class,
features), one `assert` event per scenario with the worker's exit status, and on a failure the scenario and the
first unexpected frame. Under `E2E_PLANT_FAILURE=<plant>` the named defect below is built and its test must turn
red. The in-process against worker comparison is BD-038's `suite_worker_fallback.sh`, which depends on this bead.

### Known answers and negative controls

KA-780's negative control lives here: a worker built at a different commit refuses the job. It is produced by
building the worker a second time with `FROB_STACK_RECEIPT` set to the receipt of a different tree (a scratch
copy with one sibling commit moved), and the job must be refused with `FROB-REF-791`. Further planted defects: a
worker that ignores `resume` and re-emits chunk 0 (the client's contiguity check and this bead's test must flag
it); a worker whose chunk digest omits the event bytes (the in-process comparison fails on the first job with a
contact event). Lanes: debug and release produce equal digests; two runs on one machine; `trj` and the Mac
compared and recorded (cross-platform equality is recorded, not required, because the referee claims
same-platform determinism only).

## Considerations

- The worker is a second build to keep, though only at pin moves; its lockfile is part of every receipt.
- Recomputing from step 0 on resume doubles the cost of a kill late in a long job. That is acceptable at M0,
  where the goal is that the fallback has run; checkpointing is an optimization that needs its own digest test.
- A worker at an old pin produces results under a different receipt than the core; such results are valid
  referee results and are never merged into a same-stack claim without revalidation (INV-SUITE-05).
- FrankenSim's rules forbid branches and worktrees in its repository; the read-only export for an old pin is made
  outside it.
