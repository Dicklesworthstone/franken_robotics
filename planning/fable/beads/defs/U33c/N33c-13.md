## Background

When the referee runs as a worker process (the first fallback of the kill gate KILL-FSIM, exercised at M0 by the
gate INT-FSIM-18), something must start the process, check that it is the right build, notice when it dies,
restart it, and stop it when the work or the agent ends. The design assigns this to the daemon: one worker runs
per device or per process slot; the daemon starts, supervises and stops it. The daemon arrives at M3, so at M0
the supervisor is a small library inside `frob-fsim` that the `frob` binary uses directly and the daemon adopts
later without change.

The check that it is the right build is the heart of the matter. A pin states intent; what was built is a
different fact. The worker reports the stack receipt it was built under (the BLAKE3 of the resolution receipt:
sibling revisions, toolchain, lockfiles, patches, build environment). A mismatch with the receipt the job names
is a refusal, not a warning:

| Code | Name | When |
|---|---|---|
| `FROB-REF-791` | `referee-worker-mismatch` | The worker is absent, or was built under a different stack receipt than the job names |

A warning would let a referee result computed by different code be compared as if it were the same referee,
which is exactly the comparison the receipt exists to prevent.

## Scope

In: `frob_fsim::remote::Supervisor` (spawn, handshake, liveness, stop, bounded restart); the raising of
`FROB-REF-791` in all its cases; the registry row's payload and repairs. Out: the daemon's slot scheduling
(BD-295); the protocol (N33c-10); the client's job logic (N33c-11, which is built on this supervisor and depends
on it); the worker (N33c-12); the registry bead that lists the code (N33-REF). The supervisor needs no client:
its tests submit jobs and resubmissions to the real worker as raw frames from the codec of N33c-10.

## Technical approach

1. **Configuration (DESIGN).** `SupervisorConfig { worker_path, transport: Pipe | Socket(path), expected_receipt,
   expected_protocol: "frob.fsim-job/1", start_timeout: 10 s, watchdog: 60 s, stop_grace: 2 s, max_restarts: 3
   per job, limits { memory: 16 GiB, cores: 8, wall: 1 h } }`. `worker_path` is resolved in this order:
   `--referee-worker`, the environment variable `FROB_FSIM_WORKER`, then `frob-fsim-worker` beside the running
   binary. `expected_receipt` is the `receipt` of the `FD-FSIM` row of `franken-stack.lock`, compiled into the
   `frob` binary.
2. **Start.** Spawn the worker with the build-identity variable in its environment and with its standard input
   and output as the transport (or connect to the socket). Read the first frame within `start_timeout`. It must
   be `hello`.
3. **Handshake checks, in order; the first failure refuses with `FROB-REF-791` and the worker is stopped.**
   1. No executable at `worker_path`, or spawn fails → `absent`.
   2. No `hello` within the timeout, or a first frame of another kind → `no-handshake`.
   3. `hello.protocol` has another major version → `protocol`.
   4. `hello.stack_receipt` ≠ `expected_receipt` → `receipt`.
   5. `hello.receipt_class` is `development` and the caller requested gate-grade evidence → `development-build`.
4. **The refusal envelope.** `refusal { code: "FROB-REF-791", message: "referee worker absent or built under a
   different stack receipt", pointer: "referee/worker/<case>", observed: the worker's receipt or protocol (or
   `none`), required: the expected value, unit: "", affected_claims: ["Fidelity", "Parity"], retry:
   "after-change", repairs: [ 1. rebuild the worker at the pinned commit: `scripts/build/worker.sh`; 2. run
   `cargo xtask check-stack` and resolve the drift it reports; 3. if the worker is meant to stay on an older
   pin, set `worker_rev` in the stack lock and name that receipt in the job; 4. use mode `inproc` if this binary
   has it ] }`. Exit code 5 (capability not admitted) on the CLI; DESIGN, because the exit table names only the
   `70x`, `72x` and `73x` ranges of the `7xx` family explicitly, and an absent or wrong worker is a missing
   capability of this installation, not a budget stop.
5. **Liveness.** The supervisor considers the worker dead on child exit, on a broken transport, or when no frame
   arrives for the watchdog interval while a job is running (DESIGN: `watchdog` = 60 s at M0, replaced by ten
   times the estimated time per chunk once estimates exist). The protocol has no keep-alive frame; `chunk_steps`
   bounds the silence between chunks.
6. **Restart.** On death during a job the supervisor starts a new worker, repeats the handshake, and hands the
   connection to the client, which resubmits with `resume`. After `max_restarts` deaths on one job the job fails
   with a refusal naming the last committed chunk; the supervisor does not loop.
7. **Stop.** `cancel` for the running job, close the transport (the worker exits on end of input), wait
   `stop_grace`, then terminate, then kill. Dropping the supervisor does the same. No worker survives its parent.
8. **Slots.** `Supervisor` owns exactly one worker. A pool is a map from slot identifier (a device or a process
   slot) to supervisor; the M0 CLI uses one slot.

Events: the supervisor emits typed `WorkerEvent`s (start, handshake result, death, restart, stop, refusal) with
pid, receipt, protocol, exit status and, for a refusal, its `FROB-REF-791` case, to an event sink its owner
supplies (`frob-fsim` sits at layer 0 and cannot write the ledger itself). The `frob` binary built in mode
`remote` records them in the ledger (BD-009) through the sink that N33c-11 wires; BD-038's script checks that
they arrive there. Determinism: supervision affects no result bytes.

## Acceptance criteria

- [ ] Each of the five handshake cases produces `FROB-REF-791` with the stated `pointer`, `observed` and `required`, exit code 5, and leaves no worker process running.
- [ ] A worker built under a different receipt is refused before any job frame is sent (the worker's received-frame count is zero).
- [ ] Killing the worker mid-job leads to a restart and a completed job with unchanged digests; three kills on one job lead to a refusal naming the last committed chunk.
- [ ] Dropping the supervisor, or killing the parent `frob` process, leaves no `frob-fsim-worker` process after 3 s.
- [ ] Start, death, restart, stop and refusal events reach the event sink with pid and receipt, in order, one per occurrence (the ledger record of them is checked by BD-038).
- [ ] The refusal row for `FROB-REF-791` in `registries/refusals.toml` carries the four ranked repairs and the exit code.

## Test plan

### Unit tests

`cargo test -p frob-fsim --no-default-features --features mode-remote remote::supervisor::`, all against real
processes (the jobs, kills and resubmissions are driven by the test with raw frames of N33c-10):
- `absent_worker_refuses_791`: a path that does not exist; pointer `referee/worker/absent`.
- `silent_worker_refuses_791`: the real system `sleep` binary as the worker; pointer `…/no-handshake` after the timeout.
- `receipt_mismatch_refuses_791`: the worker built with another receipt; `observed` and `required` are the two hashes.
- `protocol_mismatch_refuses_791`: a worker built with a test feature that reports `frob.fsim-job/2`.
- `development_build_refused_for_gate_grade`.
- `restart_then_complete`, `gives_up_after_three_deaths`.
- `no_orphan_after_drop`, `no_orphan_after_parent_kill` (the test spawns a parent, kills it, and scans for the worker pid).
- `watchdog_fires_on_stall`: a worker stopped with SIGSTOP is declared dead after the watchdog interval (set to 2 s in the test).
- `events_reach_sink`: one job with one kill yields, in order, start, handshake ok, death, start, handshake ok, stop, each with pid and receipt.

### End-to-end script and logging

`scripts/e2e/suite_worker_fallback.sh` (BD-038) provokes the receipt mismatch through the real `frob` binary and
logs a `refusal` event with code, pointer, observed, required and the repairs offered; `scripts/e2e/
suite_refusals.sh` (N33-REF) provokes the absent-worker case. Both log the process table check for orphans as an
`assert` event.

### Known answers and negative controls

KA-780's control: a worker built at a different commit refuses the job. Planted defects the tests must catch: a
supervisor that downgrades the receipt mismatch to a warning and proceeds (the mismatch test asserts that zero
job frames were sent); a supervisor that does not close the transport on drop (the orphan test fails); a restart
loop without a bound (the three-deaths test would hang; it runs under a timeout). Lanes: debug and release; Linux
(`trj`) and macOS, since process and signal behaviour differ.

## Considerations

- Security: `worker_path` is never taken from a job, a design file or any imported text; only from the command
  line, the environment or the installation directory.
- The exit code for `79x` refusals is a reading of the exit-code table that the refusal registry must confirm;
  the rule that every refusal code maps to exactly one exit code makes an explicit row necessary.
- OPEN-SUITE-3 interacts: a worker built on a dirty sibling tree is a development build and cannot back a gate
  PASS.
- When the daemon arrives it holds supervisors per slot and applies its own preemption; the supervisor's
  contract (one worker, bounded restarts, no orphans) is what it relies on.
