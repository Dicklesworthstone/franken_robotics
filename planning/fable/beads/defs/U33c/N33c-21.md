## Background

Kernel arithmetic in FrankenRobotics is derived, not hand-written: symbolic expressions are lowered to
straight-line programs over +, −, ×, ÷, √ and selects, with common-subexpression elimination, and emitted for the
CPU and both GPU backends from one source. An e-graph (a data structure that represents many equivalent forms of
an expression at once, from which the cheapest form is extracted) could shrink that arithmetic beyond what
common-subexpression elimination finds.

frankenjax, a sibling, has one. FACT (read 2026-11-21 at head `fa93fb775e1c`): `frankenjax/crates/fj-egraph`
exists (9,408 lines in `src/lib.rs`), built on the third-party `egg` crate over frankenjax's own intermediate
representation; frankenjax pins asupersync 0.5.0. Use at run time: none. **Posture: Pattern.** It is never a
dependency, because it would add `egg` and a second asupersync to the graph. Whatever is built here is written
here, in the `derive/` annex only, and takes frankenjax's rule sets as reference reading.

This is a Frontier [F] item, so it has a ceiling stated before any test, a pilot with a falsifier, a kill rule
and a fallback, and it is funded only if the pilot passes.

- **Ceiling.** The gain is at most the arithmetic share of step time multiplied by the reduction in operations.
  If the M2 profile puts arithmetic below 20% of step time, a 10% reduction is worth at most 2% and the item is
  dropped without a run.
- **Pilot and gate INT-FJAX-01** (M2 at the earliest, and only if the profile asks): with rewrite rules
  restricted to identities exact over the reals that also preserve floating-point results under the kernel's
  determinism class, the extracted kernel matches the baseline bit for bit on the conformance vectors, and the
  operation count falls by at least 10% on at least three kernels.
- **Kill.** Either condition fails.
- **Fallback.** Common-subexpression elimination only (`fsym-simplify`, 3,105 lines, already in the annex).

The kernel IR of Spark (`frob-kir`) already shrinks derived arithmetic by bounded common-subexpression
elimination and a small closed table of rewrites that are exact in IEEE arithmetic (the class-E table, N21a-19).
The only question this pilot answers is whether extraction, re-implemented in the build-time annex
`derive/frob-derive`, would shrink kernel arithmetic enough to matter. An earlier observation points to "no": at
these state sizes the step is expected to be bound by memory traffic, not by arithmetic.

This pilot was drafted twice, in the suite unit and in the kernel-toolchain unit (N21a-15, now superseded by
this bead). This is the one kept, because the gate INT-FJAX-01 is an admission gate of the suite chapter, and it
carries the content of both.

## Scope

In: the ceiling decision (go or no-go) from the measured profile; if it passes, a minimal e-graph with the exact
rule set and a bounded extractor in the annex, run on the pilot kernels; the measurement; the gate and admission
record. Out: adoption into the derivation pipeline for all kernels (N33c-22, which depends on this pilot); any
run-time use; any dependency on frankenjax, `fj-egraph` or `egg`; rules that reassociate, distribute or fuse
(they make a different kernel with a new identity, an error bound and a fidelity run, and are not rewrites); the
rule table itself and its trace checker (N21a-19).

## Technical approach

**Step 0: the ceiling check (no code).** The derivation-toolchain bead BD-221, a dependency, reads the same
profile for its own screen of this item and records the go or no-go beside its KILL-KIR decision. This step does
not measure a second time: it reads the profile record, recomputes the ceiling below, and must agree with
BD-221's recorded screen (a disagreement is a finding that keeps both beads open). This bead is the one writer
of the INT-FJAX-01 row in `registries/gates.toml` and of its entry in the admission file; BD-221 writes neither.
From the M2 profile (the phase ledger of the batched step, BD-217, with
the arithmetic share that N21a-27 reports), take a = the share of step wall time spent in the arithmetic of
derived kernel bodies, as opposed to memory traffic, launches and skeleton overhead, on the standard workloads Q
(quadruped) and H (humanoid), per backend. Compute the ceiling c = a × 0.10 (the value of the 10% reduction the
gate asks for; as a speed ratio, 1/(1 − a·r) with r = 0.10) and c_max = a × r for the largest reduction r the
pilot could plausibly find (use r = 0.30 as an optimistic bound, DESIGN). The speed ratios are not computed here:
for each workload and backend this step builds one ceiling record `frob.perf.ceiling/1` of N36-05 (experiment
`INT-FJAX-01/<workload>/<backend>`; baseline: the M2 profile, cache `warm`, this machine's fingerprint; f = a;
r = 10/9, the speed factor of a 10% reduction in operations; h = 0; goal 50/49 = 1/(1 − 0.02) ≈ 1.0204), takes its
ceiling from N36-05's `ceiling(f, r, h)` = 1/(1 − a/10), stores the record in the ledger before any pilot run, and
passes it to N36-05's `admit_experiment(record)`, the one place `FROB-REF-866` is raised; this bead builds no
comparison of ceiling with goal and no list of repairs of its own. Decision: if a < 0.20 on every backend and
workload, every record's ceiling is below its goal, so `admit_experiment` refuses each with `FROB-REF-866`
(exit 3, pointer `goal`, N36-05's four ranked repairs) and the ceiling c is below 2% of step time: the gate
is recorded `not run` with the reason `dropped-by-ceiling`
("dropped without a run: ceiling 2% or less") and the measured a, in the admission file and in
`registries/gates.toml`; no extractor code is merged; this bead closes with reason `pass` on its script's log,
whose outcome reads `dropped-by-ceiling` (the ceiling check is the work, and the gate row stays `not run`, never
passed); and N33c-22 closes with reason `superseded`, naming the ceiling ADR, as not funded. (The two drafts worded this record differently; this is the one wording.) If
`admit_experiment` admits the record of at least one workload and backend, continue. The
decision, its numbers and the filed ceiling records are an ADR either way.

**Step 1: the rule set (closed, exact).** Exactly the class-E table of the kernel representation (N21a-19, which
owns it; listed here so that the pilot can be read alone): only rewrites that change no bit under
round-to-nearest with contraction off:
- commutation of + and ×: a + b ⇄ b + a; a × b ⇄ b × a;
- identities: x × 1 → x; x + (−0) → x; −(−x) → x;
- select simplification: select(c, x, x) → x; select(true, x, y) → x; select(false, x, y) → y;
- folding of exact constant operations (both operands constants and the result exactly representable);
- scaling by a power of two, where no overflow or underflow is possible on the declared ranges;
- sharing of equal subterms (the e-graph's congruence closure does this by construction).
Not rules, ever: reassociation ((a + b) + c ⇄ a + (b + c)), distribution, fused multiply-add, x × 0 → 0 (wrong
for NaN and infinities), x − x → 0 (wrong for NaN and infinities), x + 0 → x (wrong for −0), x / x → 1. The
classic check: in `f32` with a = 10⁸, b = −10⁸, c = 1, (a + b) + c is 1 and a + (b + c) is 0.

**Step 2: a minimal e-graph (DESIGN; in `derive/frob-derive`, behind the feature `frontier-egraph`, off by
default).** E-classes in a union-find; e-nodes hash-consed by (operator, child classes); rebuild to restore
congruence; saturation by repeated rule application under a node budget N_max = 50,000 e-nodes and an iteration
budget of 30 per kernel (both TARGETs), stopping when either is reached or no rule fires. (DESIGN: the other
draft of this pilot set the default node budget at 10⁵ e-nodes per program; the plan asks only for "a node
budget"; 50,000 is kept because the adoption pass N33c-22 is written against it, and the value is recorded with
every result so that it can be raised by a dated change.) A program that would exceed the budget stops with a
partial result that is still equivalent (checked by trace), never an unbounded run. No dependency beyond what
the annex already has. The e-nodes are IR operators over e-class identifiers, for a straight-line program.

**Step 3: extraction.** Cost of an e-node = its operation cost (1 for +, −, ×, select; 4 for ÷; 6 for √; 0 for
a leaf, DESIGN weights recorded in the result, to be replaced by weights measured in the profile where it gives
them) with shared subterms counted once; ties are broken by lower live-value pressure. Greedy bottom-up
extraction followed by a pass that recounts with sharing; the extracted program is re-lowered through the
ordinary emitter.

**Step 4: the rule trace.** Every extracted program ships a trace of the rule applications that connect it to the
baseline program, in N21a-19's format `frob.kir.trace/1`, replayable by the independent trace checker (theorem
card T-27: a class-E rewrite trace maps the source program to the target using only rules of the closed table).
The independent checker is the `rewrite-trace` proof kind of `frob-cert` (N12p2-02, M2); N21a-19's reference
replayer in `frob-kir`'s tests is a second, non-independent replay. If N12p2-02 has not landed when the pilot
runs, the pilot replays with the reference replayer, the record names the replayer used (`replayer: reference`,
else `replayer: frob-cert`), and the independent replay is owed before any extracted kernel enters checked-in
sources (N33c-22, which depends on N12p2-02, does it). A
program without a replayable trace is not a candidate.

**Step 5: the pilot kernels.** At least five derived kernels with the most arithmetic in the profile (expected
candidates: the mass-matrix level kernel, the recursive Newton–Euler level kernel, the Jacobian-rows kernel, the
cone evaluation kernel, the Cayley step). For each: baseline operation count (after common-subexpression
elimination), extracted count, reduction, saturation statistics, and bit comparison on the kernel's conformance
vectors (at least 10⁶ seeded inputs plus the edge set) on `batch-cpu` in `f32` and `f64`, and on each device
through the CPU-versus-device check. Also recorded: the paired lower bound of the whole-step speed ratio with
the extracted kernels in place (an optimization lands only with a bound of at least 1.03 on the row it claims
to improve, identical digests, and its ceiling computed beforehand).

**Step 6: the gate.** PASS if every extracted kernel matches its baseline bit for bit on its conformance vectors
and the operation count falls by at least 10% on at least three kernels: the extractor is then admitted as a
build-time step. FAIL if either condition fails: the feature is removed, the record says so, and
common-subexpression elimination only stays in force. Record in `DEPENDENCY_ADMISSION.md` (the foundation is
the frankenjax pattern; the record states that nothing was linked; it states pass, fail or not run, with
values) and in `registries/gates.toml`. The script never writes the gate register: the INT-FJAX-01 row (pass,
fail, or `not run` with `dropped-by-ceiling`) is entered from the receipt of the pilot's run with `cargo run -p
frob-conformance --example record_gate -- --gate INT-FJAX-01 --receipt <hash>`, by this bead, the one that
measures the gate (one recorder per gate).

## Acceptance criteria

- [ ] The ceiling ADR exists with the measured arithmetic share per workload and backend and the decision; if the share is below 20% everywhere, the gate row reads `not run` with the reason `dropped-by-ceiling`, the bead closes on that record and nothing else is built; the decision agrees with the screen BD-221 recorded.
- [ ] If run: the rule set is the closed list above; a test proves each excluded rewrite is rejected by the trace checker.
- [ ] If run: every extracted kernel is bit-identical to its baseline on its conformance vectors in `f32` and `f64`, on every backend it claims; every admitted extraction has a rule trace accepted by the independent checker of N12p2-02, or, if that checker has not landed, by N21a-19's reference replayer with `replayer: reference` in the record and the independent replay left to N33c-22.
- [ ] The ceiling records are filed in the ledger before the first pilot run, their ceilings come from N36-05's `ceiling`, and every refusal on this path is `FROB-REF-866` raised by `admit_experiment` with N36-05's four repairs in order.
- [ ] If run: the node budget is enforced: a program that would exceed it stops with a partial result that is still equivalent (checked by trace).
- [ ] Negative controls: a rule set with one reassociation rule added produces an extraction that differs in bits on the case a = 10⁸, b = −10⁸, c = 1 and is rejected both by the bit comparison and by the trace checker; a trace with one step deleted is rejected.
- [ ] No second asupersync appears in any lockfile.
- [ ] If run: the operation count falls by at least 10% on at least three kernels, or the gate is recorded as failed and the fallback (common-subexpression elimination only) stays in force.
- [ ] No package from frankenjax and no `egg` crate appears in any graph (`xtask check-deps`).
- [ ] The feature `frontier-egraph` is off in every default build.
- [ ] The pilot record names the falsifier, the computed ceiling, the fallback and the result (the four parts every Frontier pilot record needs).

## Test plan

### Unit tests

`cargo test -p frob-derive --features frontier-egraph egraph::`:
- `screen_ceiling_arithmetic`: a = 0.15, r = 0.10 → ceiling 1/(1 − 0.015) = 1.015 → not run; a = 0.50 → 1.053 → run.
- `ceiling_refusal_through_admit_experiment`: the record with f = 0.15, r = 10/9, h = 0 has ceiling 200/197 ≈ 1.0152 below the goal 50/49 and is refused by `admit_experiment` with `FROB-REF-866`, exit 3, pointer `goal` and N36-05's four repairs in order; f = 0.50 gives 20/19 ≈ 1.0526 and is admitted; f = 0.20 gives exactly 50/49 and is admitted (the boundary is not a refusal). Negative control: a screen that compares ceiling with goal itself and skips `admit_experiment` files no ceiling record, and this test fails.
- `egraph_cse_only_equals_baseline`: with only the sharing rule, extraction equals the common-subexpression result node for node.
- `egraph_commutation_shares`: `x·y + y·x` extracts to one multiply and one add.
- `egraph_exact_constant_folding_only`: `0.5·4` folds to 2; `0.1·3` does not fold (the product is inexact).
- `egraph_no_x_times_zero`, `egraph_no_x_minus_x`: neither is rewritten; with x = ∞ each program still returns NaN.
- `egraph_truncated_trace_rejected` (negative control): a trace with one step deleted is rejected.
- `egraph_extraction_is_deterministic`: two runs give the same program hash.
- `congruence_shares_commuted_sum`: a + b and b + a land in one e-class; a program computing both has one addition after extraction.
- `double_negation_removed`; `select_same_branches_removed`.
- `reassociation_not_derivable`: (a + b) + c and a + (b + c) stay in different e-classes after saturation.
- `x_times_zero_not_rewritten`, `x_minus_x_not_rewritten`, `x_plus_zero_not_rewritten`.
- `node_budget_respected`: a kernel that would exceed 50,000 e-nodes stops at the budget and still extracts a valid program.
- `trace_replays`: the rule trace of an extraction replays in the checker the record names (N12p2-02's `rewrite-trace` checker when it has landed, else N21a-19's reference replayer); a trace with one reassociation inserted is rejected.
- `f32_regrouping_case`: with a = 10⁸, b = −10⁸, c = 1 the extracted program returns 1, as the baseline does.
- Property test: for 10³ random straight-line programs of up to 200 operations, the extracted program equals the baseline bit for bit on 10³ random inputs including NaN, infinities, signed zeros and subnormals.

### End-to-end script and logging

`scripts/e2e/suite_egraph_pilot.sh`: reads the profile record, computes the ceiling and logs it as a `metric`
event (`arithmetic_share`, `ceiling_fraction`, threshold 0.20 on the share) per workload and backend, with the
digest of the filed ceiling record and the answer of `admit_experiment` (a `refusal` event with `FROB-REF-866`,
its pointer and its first repair when refused); if the pilot runs, derives each
pilot kernel with and without the feature through the real derivation tool, runs the conformance vectors, and
logs per kernel `ops_baseline`, `ops_extracted`, `reduction` (threshold 0.10), `bit_identical`, `enodes`,
`iterations`, the paired lower bound against 1.03, digests of both programs, the trace-checker verdict, and on a
bit mismatch the first differing vector index and output element. The `summary` names
`gates: [INT-FJAX-01]` and the outcome (`dropped-by-ceiling`, `pass` or `fail`). There is one script: the kernel
toolchain's script `scripts/e2e/kernel_toolchain.sh` (bead N21a-25) calls it as its step `egraph_pilot` when
the feature is built, and logs nothing of its own for this gate.

### Known answers and negative controls

Known answers: the commuted-sum case (two additions become one); the `f32` regrouping case (1, not 0). Negative
controls: a rule set with reassociation added must produce a kernel that fails bit identity on the regrouping
vector (if it does not, the conformance vectors are too weak and the gate cannot be trusted); a rule x × 0 → 0
must fail the property test on a NaN input. Lanes: debug and release; `batch-cpu` on both machines; the
extraction must be deterministic (two runs give the same program hash).

## Considerations

- The whole item is conditional twice over: on the profile, and on the pilot. The most likely outcome is
  "dropped by ceiling", because the Lie-algebraic recursions are reported at about 16 to 20% of an incumbent's
  step; that outcome is a result, recorded once, and not a failure.
- Exact rules give an e-graph little room (mostly sharing modulo commutativity); the pilot exists to measure
  whether that room is 10%.
- The kill gate of the kernel toolchain (KILL-KIR) is decided separately by the derivation-toolchain bead; if
  it fires, this pilot is moot.
- Reference reading: the rule sets of `fj-egraph`. Reading is the whole of the Pattern posture; no code is
  copied.
- The bead exists so that the question is settled by the profile and recorded, not reopened later by
  enthusiasm.
- A rule that is exact over the reals but changes floating-point results (reassociation, distribution, fusion)
  belongs to class R: it makes a different kernel with a new identity, an error bound and a fidelity run.
  Nothing in this pilot admits class R.
- Extraction can reduce operation count while raising live-value pressure (more registers); the cost function's
  tie-break and the resource metadata check (N21a-18) guard against trading arithmetic for spills.
