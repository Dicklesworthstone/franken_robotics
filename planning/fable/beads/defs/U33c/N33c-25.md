## Background

A place scanned by a drone or a phone should be able to enter Habitat (the scene subsystem) with its coverage and
uncertainty attached, so that a robot design can be evaluated in one particular real place. A sibling project,
franken_drone_geometry_reconstruction, is building the pipeline that produces such scans.

FACT (read 2026-11-21 at head `db45703afc5e`): its status file (`IMPLEMENTATION_STATUS.md`, snapshot 2026-09-04)
describes an evidence path from recorded-media custody to an audited relative bundle problem, and says it does
not yet optimize cameras, emit metres or publish geometry; its crates hold about 27 thousand lines. The schemas
for what it will publish exist: `schemas/geometry_generation.schema.json` requires `coordinate_frame`,
`scale_status`, `representations`, `uncertainty_root`, `coverage_root` and `publication_stage`, and
`schemas/scale_model.schema.json` records a scale authority with residuals in parts per million.

**Posture.** Pattern today, as a schema adapter in `frob-scene` with no crate dependency; Subprocess once its
command-line tool publishes geometry. This is a Frontier [F] item. **Ceiling:** one import lane among several; no
milestone waits for the sibling to publish geometry. **Pilot:** the schema fixtures and the refusal cases, which
need no geometry. **Gate INT-FDGR-01** (TARGET): the schema fixtures validate; a geometry generation whose scale
status is not metric is refused, because a relative scale cannot enter a physics scene; coverage masks become the
scene's unknown-space label, so a clearance certificate treats an unscanned region as unknown and never as free;
and the privacy inheritance of the safety chapter applies to the result. First needed at M3 for the schema
fixtures and at M5 for scan import. **Fallback:** mesh and point-cloud import through `fs-io` with scale declared
by the operator and `reality: no-claim`. **Kill:** no published geometry by the M5 entry review, after which the
lane stays a schema adapter.

Counterexample to the shortcut "import the mesh and trust it" (CX-355): a corridor whose far half was never
observed appears as empty space in a naive import, and a traversal certificate over it would be false; with the
coverage mask the same query returns unknown.

## Technical approach

1. **Vendored schemas.** `crates/frob-scene/tests/fixtures/fdgr/geometry_generation.schema.json` and
   `scale_model.schema.json`, copied with a provenance header (source path, sibling revision, date, BLAKE3) and a
   row in `registries/lifts.toml` (they are lifted test fixtures, not code). A test re-reads the sibling's files
   at the pinned revision when the sibling checkout is present and fails if they differ from the vendored copies,
   so a schema change upstream is noticed.
2. **Adapter types (DESIGN; module `frob_scene::ingest::drone_schema`, file
   `crates/frob-scene/src/ingest/drone_schema.rs`, feature `frontier-scan-import`, off by default; the one
   location of the drone record's types and validation. An earlier draft of this bead named the module
   `frob_scene::import::fdgr` while the ingest bead N19c-04 placed a drone schema adapter at
   `ingest/drone_schema.rs`; the scene crate keeps all ingest code under `ingest/`, so that path is used and
   N19c-04 extends this file at M5).**
   `GeometryGeneration { coordinate_frame, scale_status: ScaleStatus, representations: Vec<Representation>,
   uncertainty_root: Hash, coverage_root: Hash, publication_stage }`, `ScaleStatus = Surveyed | Witnessed
   | Estimated | RelativeOnly` (the sibling's four values, FACT: its `scale_model` schema and `fdgr-scale` crate;
   mapped one to one onto the scene's scale label, whose semantics the scale-label bead N19c-02 owns), `ScaleModel { authority, residual_ppm, … }`. Parsing uses this project's own canonical
   reader (duplicate member names refused; unknown required fields refused); no `serde` type from the sibling.
3. **Validation order (each failure is a typed refusal before anything is built).**
   1. The document validates against the vendored schema: all six required members present.
   2. `scale_status` is metric (`surveyed` or `witnessed`), with a scale model whose authority is named, or
      `estimated` for an exploratory run (labelled so). Otherwise refuse: a relative scale
      cannot enter a physics scene. Payload: the observed status, the required status `metric`, and the repair
      list (1. supply a scale witness to the reconstruction; 2. use the fallback import with an operator-declared
      scale, which labels the scene `reality: no-claim`). The refusal is `FROB-REF-304` (scale authority is below
      what the task requires; a row of the Habitat refusal registry), raised with the pointer
      `scan-scale-not-metric`. `surveyed` and `witnessed` are metric; `estimated` is admitted for exploratory
      runs only and labelled so; `relative_only` is refused for every physics scene.
   3. `coverage_root` and `uncertainty_root` resolve to present artifacts with matching hashes.
   4. `publication_stage` is one the adapter admits (published); a draft stage is refused with the stage named.
4. **Coverage becomes unknown space.** The coverage artifact marks which regions of the bounding volume were
   observed. The adapter writes it into the scene pack's unknown-space label: every voxel (or brick) not covered
   is `unknown`; covered and empty is `free`; covered and occupied is `occupied`. Nothing uncovered is ever
   `free`. Queries on the result: a clearance query through an unknown region returns `unresolved` (and a
   required route through it is refused with `FROB-REF-305`, a required route, spawn or contact lies in an unknown
   region); a clearance certificate may be issued only over `free` cells.
5. **Uncertainty.** The per-region uncertainty is carried into the scene's registration-uncertainty field; where
   a clearance verdict would reverse inside that uncertainty, the verdict is `unresolved` and a probe request
   names the box to rescan.
6. **Privacy.** A scene produced by this lane carries the private mark, is stored outside the repository, and
   everything derived from it (stills, fixtures, policy weights, reports) inherits the mark. The adapter sets the
   mark unconditionally; removing it is not an adapter option.
7. **The pilot fixtures (`synthetic`, no real geometry).** Five generation documents: (a) valid and metric with a
   coverage mask over the near half of a 10 m corridor; (b) relative scale; (c) missing `coverage_root`; (d) a
   duplicated member name; (e) a draft publication stage. Expected: (a) admitted; (b) to (e) refused, each with
   its own reason.
8. **Record.** Admission record for the M3 half (sibling revision, schema hashes, the five outcomes), a gate row
   that states "schema fixtures: recorded; scan import: due at M5", and the funding note for BD-398. The script
   never writes the gate register: the row is entered from the receipt of the M3 run with `cargo run -p
   frob-conformance --example record_gate -- --gate INT-FDGR-01 --receipt <hash>`, by this bead, the one that
   measures the M3 half.

**Pilot record and frozen protocol (DESIGN).** Before the run a `[[pilot]]` record is written to the pilot
register `crates/frob-conformance/registry/pilots.toml` (schema `frob.gauntlet.pilot/1`, N38a-09): mechanism,
real-place ingestion, drone scan lane, `tier = "F"`; `owner = "§33.15"`, `bead = "N33c-25"`, `work_package =
"WP-32"`; `gated_beads = ["NFp2-02"]`, the drone lane's own mechanism work (the switch-over that runs the lane
through `scene.import` at M5). WP-32 holds three upper-tier mechanisms and can be `Partial`, and N38a-09's
`fundable_bead` answers a bead with the mechanism of every record that lists it, so this record lists no bead
shared with the twin lane: N19c-02 to N19c-05, N19c-07 and BD-398 (the `DroneGeometryAdapter` of N19c-04
included) are gated by the twin lane's record of N19c-01 alone, and a drone-lane `falsifier-holds` does not block
them. NFp2-02 reads its readiness with `cargo run -p frob-conformance --example pilots -- fundable --bead NFp2-02
--json`. This bead is the record's `bead`, the one that produces its verdict, and is not listed in its own
`gated_beads`: it would then answer `Blocked{registered}` until its own result is appended and could never start;
tools and pins (the drone project's schemas at its revision of the day); cost at most one agent-day and no device; ceiling (ingestion has no effect on decision time; its
value is that a candidate can be evaluated in one particular place, the precondition of a Reality claim about
that place); kill gate KILL-INGEST, decided at M5 with the importer; fallback, a place authored in the interior
grammar from a tape-measure survey, labelled a proxy, and for the scan lane mesh and point-cloud import with an
operator-declared scale and `reality: no-claim`. The result's verdict is `falsifier-rejected` with the
recommendation `fund the importer on this lane` when Part A holds, and `falsifier-holds` with `upstream first`
(the finding attached to FD-FDGR-01) when it does not.

**Part A, further fixtures.** Besides (a) to (e): (f) valid with `scale_status = witnessed`, admitted as metric;
(g) schema-valid with `estimated`, admitted for exploratory runs only; (h) schema-valid with `surveyed`, coverage
and uncertainty present, admitted as metric. An independent JSON-schema validator is run on every fixture beside
the adapter, so that a validator that ignores `required` is caught by fixture (c).

**Falsifier.** An expected outcome of Part A does not hold with the sibling's schemas as they are (for example
the schema cannot express per-region coverage, or admits a document without a scale status); then the scan lane
is not built as designed and the finding is attached to FD-FDGR-01. The pilot record gets the drone lane's
recommendation: `fund the importer on this lane` or `upstream first`. (The twin lane's falsifier, any of four
landmarks, a scale witness or coverage absent from an inspected twin package, is N19c-01's.)

**Example driver (the M3 entry point).** At M3 the `place` form of `scene.import` answers `FROB-REF-724`, exit 5
(VERBS-scene; it lands with BD-398 at M5), so the adapter is driven by a Cargo example of the scene crate:
`cargo run -p frob-scene --features frontier-scan-import --example scan_schema -- <generation> --json`. It runs
the validation order above and, for an admitted document, writes the `synthetic` private pack of step 4 into the
store beneath the configured private root (`roots.private`, BD-305), printing one envelope with the same
`frob.scene.import.out/1` result and refusal block that the verb returns at M5. An example target is neither a
verb nor a conformance binary (there is no `frob-conformance scan-schema`; an earlier text named one).

- `scale_relative_only_refused_304`, `scale_estimated_exploratory_only`, `scale_witnessed_metric`, `scale_surveyed_metric`; a status outside the four values is refused as schema-invalid.
- `three_valued_query`: over the half-observed corridor the witness search fails and the cut search fails, giving `unresolved`.
- `duplicate_member_refused`: `{"scale_status": "surveyed", "scale_status": "relative_only"}` is refused before either value is used.

### Known answers and negative controls

Known answer: 160 of 320 voxels unknown in the corridor fixture, and the traversal verdict `unresolved`. CX-355: a
naive import of the same fixture's mesh (coverage ignored) labels the far half free and would certify the
traversal; that naive importer is kept as a registered mutant and must fail the corridor test. Further controls:
an adapter that accepts `relative_only` scale by scaling to a default must be caught by `scale_relative_only_refused_304`; an
adapter that drops the private mark must be caught by the still test. Lanes: twice on one machine; both machines.

## Considerations
- The sibling's schemas may change before it publishes geometry; the vendored-copy comparison turns that into a
  visible test failure and a deliberate update.
- OPEN-HAB-5 (which reconstruction package and version is the import contract; N19c-09) defaults to the twin
  package first and the drone route when it publishes geometry; when no witness exists the scale is declared by
  the operator under the fallback import, with `reality: no-claim`.
- RISK-12 (a scan of a private place leaks through a still, a fixture or policy weights): the private mark and
  its inheritance are the mitigation and are part of this gate.
- The scene chapter's own real-place path consumes a different sibling's twin package first; this lane is one
  import lane among several and is on no critical path.
- Schema validity is not truth: a document can validate and still describe a badly scaled place. The scale label
  and its witness are what a task may rely on, and the label's authority is checked again at import.
- A mapping that accepts `relative_only` as metric and a mapping that treats a missing coverage entry as free are
  registered negative controls of INT-FDGR-01 beside the naive importer.
- If the sibling's schema changes between M3 and M5, the M5 half reruns the fixtures at the new pin (an admission
  is never inherited).
