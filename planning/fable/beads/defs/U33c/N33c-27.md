## Background

Every gate claim in FrankenRobotics has a `claim_id` that resolves to the `evidence_id`s of the records
supporting it, the identifier of the decision rule and thresholds in force, and the `trace_id` of the run. The
wider suite already has identifier types for some of these, in franken-kernel, a small crate that lives in the
asupersync repository. FACT (read 2026-11-21): `asupersync/franken_kernel` (1,801 lines, version 0.6.0) defines
`TraceId`, `DecisionId`, `PolicyId`, `SchemaVersion`, `Budget` and a capability-typed `Cx`. It has no claim or
evidence identifier type. It depends on `serde`. It implements a text parser (`FromStr`) for `TraceId`,
`DecisionId` and `SchemaVersion` and none for `PolicyId`, whose own `serde` form is an object with fields `n` and
`v` (FACT as recorded by N34-11, same file and date; re-read by this bead at the pin). Its `PolicyId` is a dotted rule name with a version and names a
decision rule (this project calls the same thing `DecisionPolicyId`, because its own `PolicyId` names a control
policy by content hash). Its `TraceId` is a 128-bit, time-ordered identifier.

**Posture: Pattern; Oracle.** `frob-core` mirrors the text form of the identifiers the sibling has, adds
`ClaimId` and `EvidenceId` in the same form, and proposes them upstream (work item FD-FKER-01, priority P3;
interim posture: local types in `frob-core` with the same text form; switch-over: replace the local types).
franken-kernel is **not linked into `frob-core`**, which admits no `serde`. It is linked only into the
conformance harness, as a round-trip oracle. The foundation's ledger row gives its admission as "with
INT-ASUP-01" (it comes from the same repository and the same pin) and its fallback as local identifier types with
the same text form.

Why bother with an oracle for three string formats: identifiers cross tool boundaries (logs, the ledger, other
suite tools, the MCP surface). If this project's `TraceId` text differs from the suite's by one character class,
no tool reports an error; cross-referencing silently stops working.

## Scope

In: the round-trip tests between `frob-core`'s identifier text forms and franken-kernel's; attaching the text
forms of the two identifiers the sibling lacks to the upstream proposal; the dev-only dependency; the FD-FKER
admission record. Out: the identifier types, their text forms (`clm:<64 hex>`, `ev:<64 hex>`, `name@vN`, 32 hex
digits for a trace) and their local tests (N34-11, a dependency); the artifact graph (BD-095); the upstream change
(FD-FKER-01). The first oracle test, `franken_kernel_text_forms_agree`, is named in N34-11's test plan; it lives
in this bead's test file `crates/frob-conformance/tests/ids_oracle.rs` (one owner of the franken-kernel edge),
and the tests below extend it.

## Technical approach

1. **Dependency.** `franken-kernel` as a dev-dependency of `frob-conformance` only, by path into the asupersync
   checkout at the pinned revision, default features off. The deny rows of `xtask check-deps` allow exactly this
   edge and refuse any normal edge and any edge from `frob-core`.
2. **Read the sibling's forms at the pin (recorded in the test's header, never copied from here).** For each of
   `TraceId`, `DecisionId` and `PolicyId`: the `Display` output, the parse grammar where a parser exists, the
   bit width, the ordering property (time-ordered for `TraceId`), and the `serde` representation (string or
   structured).
3. **Round trips (the oracle), N = 10⁴ seeded values per kind.**
   - `TraceId` (both sides have a parser): ours → text → theirs → text and theirs → text → ours → text are
     byte-identical; the order of our values equals the order of theirs on the same underlying 128-bit values,
     and the lexical order of the text forms agrees with it if the sibling's does; rejection parity: a corpus of
     malformed texts (wrong length, an illegal character, a missing separator, upper case where lower case is
     required) is rejected by both parsers, and any text one accepts and the other rejects is a failure with the
     text printed.
   - `DecisionPolicyId` against the sibling's `PolicyId` (the sibling has no parser): for the same (name,
     version) the two printed forms are byte-identical, and the sibling's print parses with this crate's parser
     back to the same value; the malformed corpus (an empty name segment `a..b`, an upper-case letter, white
     space, a missing `@v`) is rejected by this crate's parser and is checked never to be printed by the
     sibling's `Display` on the seeded values.
   - `DecisionId` (N34-11, item 4b: 128 bits printed as 32 lower-case hex digits, the sibling's text form, with
     the bit layout the sibling has; both sides have a parser): the same two-way byte-identical round trip and
     rejection parity as `TraceId`, and the layout read at the pin (written to the test header) is the one
     N34-11 adopts. Because a `TraceId` and a `DecisionId` share one text form, no test asserts that one
     parser rejects the other's text; they are told apart by the field that holds them (N34-11).
4. **The two identifiers the sibling lacks (the proposal carried upstream by FD-FKER-01).** `ClaimId` =
   BLAKE3(claim type ‖ subject identities ‖ statement ‖ scope) and `EvidenceId` = BLAKE3(kind ‖ payload hash),
   32 bytes each, with N34-11's text forms `clm:<64 hex>` and `ev:<64 hex>` (this bead does not choose them;
   one spelling per identifier). The proposal attached to FD-FKER-01 cites those forms and the sibling's prefix
   style as read at the pin. Tests: every example in the proposal parses with N34-11's parsers and round-trips;
   a text of the right shape with the other kind's prefix is rejected; identifiers of the five local kinds and
   the sibling's three are nonempty strings of printable characters with no code point below 32 and not 127, so
   that each survives a shell variable.
5. **Content hashes never contain trace identifiers.** A test builds two evidence records that differ only in
   `TraceId` and wall-clock time and asserts equal `EvidenceId`s: trace identifiers and times identify executions
   and never enter a content hash.
6. **Record.** The observed forms and the round-trip counts are written into the admission record of the
   foundation row FD-FKER, a record of its own with `covers.crates = ["franken-kernel"]` (an admission is never
   inherited from asupersync's) (franken-kernel: Pattern and Oracle; not linked into any production
   graph).

Determinism: exact.

## Acceptance criteria
- [ ] `cargo tree -e normal -p frob-core` contains neither `franken-kernel` nor `serde`; `franken-kernel` appears only under dev-dependencies of `frob-conformance`.
- [ ] 10⁴ of 10⁴ `TraceId` and 10⁴ of 10⁴ `DecisionId` round trips are byte-identical in both directions; 10⁴ of 10⁴ decision-policy prints are byte-identical and the sibling's print parses with this crate's parser; the sibling's `DecisionId` bit layout is recorded and equals N34-11's.
- [ ] The `TraceId` and `DecisionId` malformed-text corpora are rejected by both parsers with no disagreement; the decision-policy corpus is rejected by this crate's parser.
- [ ] `ClaimId` and `EvidenceId` round-trip, reject each other's prefix, and are printable.
- [ ] Two evidence records differing only in trace and time have equal `EvidenceId`s.
- [ ] The sibling's observed forms are recorded with the asupersync revision; the proposal for the two new identifiers is attached to the upstream bead.
- [ ] Boundary cases round-trip in both directions: the all-zero and all-ones values, and the shortest and longest admitted text of each kind.
- [ ] An identifier form with a changed prefix is rejected by both parsers (a registered negative control), and a regeneration of the oracle fixture from the candidate fails the oracle-hygiene check.

## Test plan

### Unit tests

`cargo test -p frob-conformance ids_oracle`:
- `franken_kernel_text_forms_agree` (named by N34-11): `trace_id_roundtrip_both_ways`, `decision_id_roundtrip_both_ways` and `decision_policy_print_agrees` (10⁴ seeded values each; for the decision policy, names with one to five dotted segments and versions 0 to 2³² − 1).
- `decision_id_layout_recorded`: the sibling's `DecisionId` print, grammar and bit layout are written to the test header and equal N34-11's.
- `trace_id_order_agrees`.
- `malformed_rejected_by_both` (at least 200 `TraceId` and 200 `DecisionId` texts, generated by single-character mutations of valid ones); `decision_policy_malformed_rejected`.
- `ids_boundary_values`: the all-zero and all-ones trace and decision values, a one-segment name at version 0 and a five-segment name at version 2³² − 1, round-trip in each direction that exists.
- `claim_evidence_roundtrip`, `claim_rejects_evidence_prefix`.
- `identifiers_printable`: no code point below 32, none equal to 127, nonempty.
- `evidence_id_ignores_trace_and_time`.

### End-to-end script and logging

A step of `scripts/e2e/suite_deps_rules.sh` (created by N33c-09, a dependency, with its STD-E2E log contract; this
bead adds the step): runs the oracle tests and the dependency check for the dev-only edge, and logs `metric` events `roundtrips_ok` per kind (threshold 10,000 of 10,000) and `parser_disagreements`
(threshold 0), with the first disagreeing text on failure.

### Known answers and negative controls

Known answer: byte-identical texts in both directions. Negative controls: a local `TraceId` formatter that
prints upper-case hex (or drops a separator) must be caught by the round trip; a local `PolicyId` parser that
accepts an empty name segment (`a..b`) must be caught by rejection parity if the sibling rejects it; a planted
normal dependency of `frob-core` on `franken-kernel` must fail `xtask check-deps`; an oracle fixture regenerated
from the candidate (this crate's own output) must fail the oracle-hygiene check of the oracle register (N38a-04).
Lanes: twice on one machine; both machines.

## Considerations
- OPEN-CHRON-3 (which crate supplies the decision-rule identifier type) is why the local name is
  `DecisionPolicyId`; the oracle compares it with the sibling's `PolicyId`.
- If the sibling changes a text form, the round trip fails at the next pin move; the local form follows the
  sibling, and stored identifiers are migrated or accepted in both forms by an explicit, versioned parser.
- If INT-ASUP-01 fails and a fallback splits the graph, this oracle still builds in the conformance harness,
  because it depends only on franken-kernel.
- This bead is the single owner of the FD-FKER admission after integration; the duplicate half of N33a-20, which
  now admits frankenscipy only, is folded here (its tests `ids_roundtrip_local_to_kernel_10k` and
  `ids_roundtrip_kernel_to_local_10k` are the two directions of `trace_id_roundtrip_both_ways`;
  `ids_boundary_values` and `ids_malformed_rejected_by_both` are `ids_boundary_values` and
  `malformed_rejected_by_both` above).
- If franken-kernel gains claim and evidence identifiers (FD-FKER-01, done in the asupersync repository;
  switch-over rule: replace the local types), the round trip extends to them and the local types may be replaced,
  subject to OPEN-CHRON-3 and to `frob-core` staying free of `serde`.
