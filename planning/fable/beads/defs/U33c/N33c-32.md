## Background

The airlock crate `frob-fsim` groups its traits, and each group is a Cargo feature, so that a crate above the
airlock compiles only the FrankenSim closure it uses:

| Feature group | Traits exposed | Default |
|---|---|---|
| `referee` | `RefereeDynamics`, `RefereeContact`, `Integrator`, `PortSystem` | on |
| `geometry` | `GeometryKernel`, `SceneQuery`, `MeshExchange` | on |
| `ledger` | `Ledger`, `Session`, `Recompute` | on |
| `optimize` | `Optimizer`, `Archive`, `Racing` | off |
| `stats` | `Uncertainty`, `ValueOfInformation`, `Surrogate`, `Assimilation` | off |
| `spectral` | `Spectral` | off |
| `actuation` | `Magnetics`, `ThermalNetwork`, `CurrentLoop`, `PortHamiltonian` | off |
| `structure` | `StructuralOpt`, `ToleranceAllocation`, `AsBuilt`, `FabricationRules` | off |
| `multiphysics` | `FluidIsland`, `CoupledIsland` | off; gated bridge |
| `harness` | none (test support) | dev only |

The groups bound what a crate above the airlock may name, always, and they save compile time for the last two
(`structure` adds 13 crates and about 412 thousand lines beyond the M1 set; `multiphysics` adds 19 crates and
about 2.31 million). A consequence: a given `frob` binary may have been built without a group. A milestone-M1
build has `referee`, `geometry` and `ledger`; the multiphysics bridge is compiled only by the M6 lanes; a binary
in mode `remote` has whatever groups its worker was built with.

A verb that needs a missing group must not fail with a link error, a panic, or a silently degraded answer. It
refuses by name:

| Code | Name | When |
|---|---|---|
| `FROB-REF-790` | `foundation-group-absent` | A verb needs an airlock feature group that this binary was not built with |

This is one case of the project's standing rule: a capability that is not present says so, with repairs.

## Scope

In: the group-presence table compiled into the binary; the verb-to-group requirement in the verb registry; the
admission-time check; the refusal with payload and repairs; how `capabilities` and `doctor` show groups; the
multiphysics-bridge refusals that reuse this code; the option `--require-group <group>` (repeatable) of the
operator verb `capabilities` (BD-022's verb, extended here), whose `needs_groups` is that argument: it provokes the
refusal at M0, when no other verb needs an off-by-default group, and lets a script or an agent ask for a group
before it plans work (DESIGN: an earlier draft added a test-support verb `conformance.probe`, but the program has
no `conformance` verb namespace and a verb that exists only to refuse helps no user); the predicate
`scene-has-coupled-island` in `frob_verbs::admission::predicates`; arm 6 of NJL-01's `derive.rs`. Out: the groups themselves and their admission gates (the
airlock beads and the group-gate beads); `FROB-REF-724` (a verb not implemented in this build), which is a
different refusal and is distinguished below.

## Technical approach

1. **Presence table (DESIGN).** `frob_fsim::groups() -> &'static [GroupInfo]`, which extends the compiled-in set
   `BUILT_WITH` of the crate skeleton (N33a-11) by the `admitted` column, generated at build time from the
   crate's enabled features: `GroupInfo { name, compiled: bool, admitted: Option<AdmissionRef> }`. `compiled` is
   `cfg!(feature = "<group>")`. `admitted` is the admission record (gate identifier and receipt hash) embedded
   at build time from `registries/gates.toml` for the group's gate (`referee`/`geometry`/`ledger`: INT-FSIM-01;
   `spectral`: INT-FSIM-13; `stats`: INT-FSIM-14; `structure`: INT-FSIM-15; `ledger`'s recompute part:
   INT-FSIM-16; `multiphysics`: INT-FSIM-17; `optimize` and `actuation`: the admission gate recorded when first
   used). In mode `remote` the table is the intersection of what the client was built to expect and the groups
   in the worker's `hello.features`.
2. **Requirement in the registry.** Each verb row of `registries/verbs.toml` gains `needs_groups = [...]`
   (possibly empty), and where a requirement depends on arguments, a named predicate (for example `sim.run`
   needs `multiphysics` only when the scene contains a coupled island). The entry schema of N32a-02 is closed
   (`unknown-field` fails the build) and names this bead as the one that adds the field, so this bead adds it
   there, with the member on the emitted `VerbEntry` and its lint (DESIGN shape): a list whose items are a group
   name (always required), a table `{ groups = [...], when = "<predicate>" }` (required when the named
   predicate of `frob_verbs::admission::predicates` holds for the resolved request), or, for `capabilities`
   only, `{ from_argument = "require_group" }` (the groups named by that argument). This bead registers the
   first predicate, `scene-has-coupled-island`: true when the resolved request's scene declares at least one
   coupled island (a fluid or coupled island region, the declarations of N19b-21); it is false for every scene
   until island declarations exist, and `sim.run`'s row uses it (`needs_groups = ["referee", { groups =
   ["multiphysics"], when = "scene-has-coupled-island" }]`). Other predicates are registered by the beads that
   name them in a row (`stills-quality-hero`, N20ap2-01). Lint `needs-groups-known`: every name is one of the
   known groups, every predicate is registered, and `from_argument` names an input property of the verb. The
   known groups are the ten of the table above and `tracer`, the eleventh, which ADR-SUITE-03 declares and
   N33bx-02 adds to the airlock at M4 (Frontier, off by default; `telemetry.stills` names it): a known name
   that `frob_fsim::groups()` does not yet carry is reported not compiled, so a verb needing it answers 790,
   fail-closed. The CLI, the daemon protocol and the MCP tool definitions are generated from the registry.
   This bead writes arm 6 of NJL-01's `derive.rs` (row 6 of its variation table) in the change that adds the
   field: the member `needs_groups()` on the emitted `VerbEntry`, and in `all_refusals()` the append of
   `FROB-REF-790` with source `Field("needs_groups")` to every entry whose list is non-empty (an empty list never
   gets it), so the list of verbs that may return 790 is generated too.
3. **Admission check.** Before a job is planned or a budget is charged, `frob-verbs` evaluates the verb's
   requirement against the presence table. For the first missing group: refuse with `FROB-REF-790`.
4. **Distinguishing three situations.**
   - Group not compiled into this binary → `FROB-REF-790`, pointer `foundation/<group>/compiled`.
   - Group compiled but its admission gate has no passing record at this pin (an admission is never inherited:
     a group first used at a milestone is admitted at that milestone, by its own record) → `FROB-REF-790`,
     pointer `foundation/<group>/admitted`, with the gate named. Under `--allow-unadmitted` (development only)
     the verb runs and its evidence is labelled `development`. The flag is a process option of the `frob`
     skeleton (BD-022), in no verb's schema: this bead adds `allow-unadmitted` to
     `PROCESS_OPTIONS` of NJL-01 (the list every invocation accepts, which its lint `common-property-shadowed`
     checks generated flags against), as N33c-11 does for `referee-worker`.
   - The verb itself is not implemented in this build → `FROB-REF-724` (not this bead).
5. **The envelope.** `refusal { code: "FROB-REF-790", message: "this binary was built without the airlock
   feature group the verb needs", pointer, observed: the groups compiled (a list), required: the missing group,
   unit: "", affected_claims: [], retry: "after-change", repairs: [ 1. use a build with the group: `frob
   capabilities --json` lists the groups of this binary, and the release notes list which distributed binaries
   carry which groups; 2. rebuild with `--features frob-fsim/<group>` (cost: the closure the group adds, stated
   in the message for `structure` and `multiphysics`); 3. for an admitted-but-missing record, run the group's
   admission gate; 4. where one exists, use the fallback the verb documents (for a fluid film: the Solid
   film-friction law; for coupled islands: none) ] }`. Exit code 5 (capability not implemented or not
   admitted), the exit the allocation ledger's rule fixes for the `79x` decade (N35-33) and N33-REF's row states.
6. **The gated bridge reuses the code.** A request that needs `multiphysics` in a binary without it is refused
   with `FROB-REF-790`. A request for a throughput-tier result through the bridge is refused whatever the build
   (a result that crossed the bridge is evaluation tier and cannot enter a throughput claim); that second
   refusal is raised by the bridge with its own pointer `foundation/multiphysics/tier` under the same code
   (DESIGN: the suite chapter names no separate code for it, and for a throughput tier the group is absent by
   construction, since no kernel of the batched step calls across the bridge), so that both halves of the
   bridge's negative control are observable through one registered refusal.
7. **Visibility.** `frob capabilities --json` lists every group with `compiled`, `admitted` and the gate;
   `frob doctor` lists the admitted foundations with their records and the stack receipt and flags a group that
   is compiled and unadmitted. `frob capabilities --require-group <group> [--require-group <group> …] --json`
   answers exit 0 with the same listing when every named group is compiled and admitted, and otherwise refuses
   with `FROB-REF-790` for the first missing one (pointer, observed and repairs as in item 5). The option's
   values are the known group names; any other value is refused by schema validation as invalid input
   (`FROB-REF-802`). The `capabilities` row of VERBS-operator carries it: the input `--require-group <group>`
   (repeatable) and `needs_groups = [{ from_argument = "require_group" }]`, so the generator appends 790 with
   source `field:needs_groups`; this bead writes the input and the field into that row in the change that adds
   `needs_groups` to the entry schema, since no row may carry the field before that change.

Determinism: exact. No physics runs before the refusal.

## Acceptance criteria

- [ ] A binary built without `stats` refuses a verb that needs it with `FROB-REF-790`, exit 5, pointer `foundation/stats/compiled`, before any job identifier exists and with nothing charged.
- [ ] A binary with the group compiled and no passing admission record refuses with pointer `foundation/<group>/admitted` and names the gate; `--allow-unadmitted` runs and labels the evidence `development`.
- [ ] `frob capabilities --json` lists all ten groups with their state; the list equals `frob_fsim::groups()` (eleven once N33bx-02 adds `tracer`).
- [ ] `frob capabilities --require-group stats --json` on a default build refuses with `FROB-REF-790`, exit 5, pointer `foundation/stats/compiled`; `--require-group referee` answers exit 0; `--require-group tracer` refuses with 790 until N33bx-02 lands; `--require-group gpu-cuda` is refused as invalid input.
- [ ] Arm 6 of NJL-01's `derive.rs` exists: the generated refusal list of every verb with a non-empty `needs_groups` contains `FROB-REF-790` with source `Field("needs_groups")`; a verb with an empty list never returns it.
- [ ] The predicate `scene-has-coupled-island` is registered, and `sim.run`'s row passes `needs-groups-known`.
- [ ] A multiphysics request in a default build is refused; a throughput-tier request through the bridge is refused in a build that has the feature.
- [ ] In mode `remote`, a group missing from the worker's `hello.features` yields the same refusal with `observed` listing the worker's groups.
- [ ] The row for `FROB-REF-790` in `registries/refusals.toml` has the four ranked repairs and exit code 5.

## Test plan

### Unit tests

`cargo test -p frob-verbs admission::groups` (the crate built twice in the test matrix: default groups, and with
`stats` added):
- `missing_group_refuses_790_before_planning`: the job-planner call counter is zero; the budget ledger is unchanged.
- `unadmitted_group_refuses_with_gate_named`.
- `allow_unadmitted_labels_development`; `allow_unadmitted_is_a_process_option`: `PROCESS_OPTIONS` contains `allow-unadmitted`, `common-property-shadowed` passes on the real registry, and `frob capabilities --allow-unadmitted --json` parses on every build.
- `argument_dependent_requirement`: through the registered predicate `scene-has-coupled-island`, a `synthetic` resolved `sim.run` request whose scene declares no island does not require `multiphysics`; the same request with one coupled-island declaration does, and is refused with 790 in a default build.
- `registry_refusal_lists_generated`: on a scratch registry, a row with `needs_groups = ["stats"]` has 790 in `all_refusals()` with source `Field("needs_groups")` and the same row with `needs_groups = []` has not; on the real registry, every verb with a non-empty list (`sim.run` among them) lists 790.
- `capabilities_matches_groups_table`.
- `remote_mode_uses_worker_features` (with the real worker of N33c-12 built without a group, reached through the client of N33c-11).
- `capabilities_require_group`: the `capabilities` row carries `require_group` and `needs_groups = [{ from_argument = "require_group" }]` and passes the registry lints (NJL-01); `--require-group stats` on the default build is 790 with pointer `foundation/stats/compiled`, `--require-group referee` is exit 0, `--require-group tracer` is 790 naming `tracer`.
- `needs_groups_lint`: a row naming the group `gpu-cuda` (a device backend, not an airlock group), a predicate that is not registered, or a `from_argument` that is not an input property fails `needs-groups-known`; a row naming `tracer` passes; the field on a row before this bead's schema change would fail `unknown-field` (checked on a scratch registry).
- `distinct_from_724`: an unimplemented verb returns 724, not 790.

### End-to-end script and logging

`scripts/e2e/suite_refusals.sh` (N33-REF; its 790 step runs once this bead lands): with the default `frob`
binary, asks for an off-by-default group (at M0 `frob capabilities --require-group stats --json`, the option this
bead adds to the `capabilities` row; like every option it is generated on both surfaces, so the parity of
GATE-TETHER-02 is untouched; from M3 on, a real statistics verb as well) and expects exit 5; logs a `refusal`
event with code, pointer, observed groups, required group and repairs; then runs `frob capabilities --json` and
asserts that the missing group is listed as not compiled, and `frob capabilities --require-group referee --json`
and asserts exit 0.

### Known answers and negative controls

Known answer: the default M1 build reports `referee`, `geometry`, `ledger` compiled and the other seven not.
The negative control of the multiphysics group gate is carried here in part: the bridge refuses when the feature
is off, and refuses a throughput-tier request. Planted defects: an admission check placed after job planning (the
planner counter test fails); a verb that catches the absence and returns an empty result with exit 0 (the
end-to-end script expects exit 5 and fails it); a presence table hard-coded instead of generated (building with
`stats` and observing "not compiled" fails `capabilities_matches_groups_table`). Lanes: default build and
all-groups build; mode `inproc` and mode `remote`.

## Considerations

- The exit code for the `79x` codes is not in the surface's exit table (which names `70x` for exit 4 and `72x`,
  `73x` for exit 5); the allocation ledger's exit rule (N35-33) fixes `79x` at 5, and the refusal registry states
  it explicitly in the row because every refusal code maps to exactly one exit code.
- A distributed binary for a milestone carries that milestone's groups; the README's status table lists them,
  generated from the same table.
- RISK-22 (the FrankenSim closure makes builds slow) is the reason groups exist; this refusal is the user-facing
  half of that trade.
