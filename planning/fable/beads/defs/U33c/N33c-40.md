## Background

The suite chapter records defects, limits and convention hazards found in the sibling components this project
stands on. Each is treated the same way: what was reported, what a reading of the source confirms, the admission
test that settles it at the pinned commit, the upstream work item that would fix it in the sibling, and what this
project does meanwhile. None of the readings was executed when the plan was written; a reported number stays a
report until its admission test records it.

Four such facts were added late, as rows 5 to 8 of that table:

| # | Component | Fact | Admission test | Interim posture |
|---|---|---|---|---|
| 5 | `fs-mbd::Wrench` | The step's external wrench is `force_world` with `torque_body`: two frames in one value | A free body at R = R_z(90°) receives a pure world force and a pure body torque through the airlock; linear and angular momentum changes match to 10⁻¹² | A fourth frame type in `frob-fsim` only, with exactly two constructors |
| 6 | `fs_g1_train::gaussian_action` | Adjacent channels agree in sign with probability 0.6655 where independence gives ½; the marginals are correct | The joint-law battery (rule P-12) | Not linked; a planted copy is the negative control |
| 7 | `serde_json` pins across siblings | franken_textiles and franken_threed pin `=1.0.151`; fastmcp_rust pins `=1.0.154`; frankenscipy requires 1.0.154 or later | `cargo metadata` resolves the graph that the cloth-oracle gate needs, or reports the conflict | `ftx-drape` is reached as a separate process in its own workspace; `f3d-*` crates are used with their `serde` feature off |
| 8 | The `metal` 0.33.0 binding under `ft-kernel-metal` 0.1.3 | Its language-version enumeration ends at Metal Shading Language 3.1; it already exposes indirect thread-group dispatch and thread-group memory length, which the gateway does not wrap | INT-FT-01 records the language version the gateway compiles under | Dialect sources use no construct newer than 3.1; the upstream work item wraps the existing bindings |

**GATE-WS-06** (claim type: known answer). The mixed-wrench probe passes and its unconverted mutant fails; the
planted sampler is rejected by rule P-12; `xtask check-deps` reports exactly one `serde_json` version per binary
and fails a graph that adds `ftx-drape` to the core workspace; the Metal language version and the 64-bit atomic
probe are recorded in the fingerprint. Milestone M0; the sampler row at M2.

This bead is the gate's measurement and record. The mechanisms and probes are separate beads; here they are run
together, at one pin, under one receipt.

## Scope

In: the end-to-end script, the gate record with its four rows, the rule for a row that is found fixed upstream,
and the M0 and M2 closing conditions. Out: the probes themselves (N33c-36 row 5; N33c-37 row 6; N33c-38 row 7;
N33c-39 row 8).

## Technical approach

1. **Preconditions.** `cargo xtask check-stack` passes on clean sibling trees; the resolution receipt is
   written; the FrankenSim, frankentorch, franken_textiles, franken_threed, fastmcp_rust and frankenscipy
   revisions are those of the stack lock (or, for siblings that are not consumed, of the suite survey).
2. **Row 5.** Run the four free-body cases of the mixed-wrench probe through the airlock (mass 2 kg, inertia
   diag(0.02, 0.03, 0.04) kg·m², R = R_z(90°), at rest, Δt = 1/1000 s): world force (1, 0, 0) N → Δp = (0.001,
   0, 0) kg·m/s; body torque (1, 0, 0) N·m → ΔL_world = (0, 0.001, 0) kg·m²/s; body force (1, 0, 0) N → Δp = (0,
   0.001, 0); world torque (1, 0, 0) N·m → ΔL_world = (0.001, 0, 0); each to 10⁻¹² relative. Run the unconverted
   mutant on the last two; both must fail.
3. **Row 6 (M2).** Run the joint-law battery on the planted linear-phase sampler for action dimensions 2, 12 and
   29, N = 10⁵ decisions, 64 worlds: rejected, with adjacent-channel agreement 0.6655 ± 0.005. The plant
   (N33c-37) and the battery (N23b-30) are both M2 beads, so at M0 the row is recorded as `due M2` with nothing
   attached, and the script logs its steps `not-run: N33c-37`. Once the plant has landed, its own unit tests
   (marginal ½, adjacent agreement 0.6655) are attached as preliminary evidence; the row is counted as passed only
   when the battery rejects the plant, which N23b-30 records by running the `--sampler-row` mode.
4. **Row 7.** `cargo xtask check-deps`: exactly one `serde_json` version per binary. The conflict probe:
   `conflict` (with both requirement strings) or `resolves`. The plant: `ftx-drape` added to the core workspace
   behind an off-by-default feature must fail the check.
5. **Row 8 (on the Mac).** `frob spark fingerprint --device metal:0 --key ws06-fp-<run> --json` (a run verb: an
   idempotency key is required, `FROB-REF-805` without it; `--device metal:0` names the device whose entry is
   read; `<run>` is the script's run identifier, so a repeated run measures again instead of returning the
   stored receipt): the Metal device entry
   carries the language version and the 64-bit integer and 64-bit atomic probe results; the INT-FT-01 admission
   record carries `msl_version`.
6. **Fixed upstream.** If a probe shows that the sibling no longer has the fact (the wrench type gained named
   constructors; the sampler was corrected; the pins were relaxed; the gateway wraps the bindings or the binding
   was replaced), the row is recorded as `fixed upstream at <revision>`, the interim posture is reviewed by its
   owner bead and either kept (with the reason) or removed through the switch-over rule of the upstream work
   item (FD-FSIM-33; FD-FSIM-32; FD-FTX-01 and FD-F3D-01; FD-FT-01). A row is never silently dropped.
7. **Record.** A row in `registries/gates.toml` for GATE-WS-06 with four sub-results, each with its measured
   values, its negative control and whether it was caught, the receipt hash and the sibling revisions; an entry
   in `DEPENDENCY_ADMISSION.md`. The script never writes the gate register (one recorder per gate). The gate is
   measured by G1 entries registered under GATE-WS-06 in `crates/frob-conformance/tests/g1_known_answers.rs`
   (N38a-02's `Entry`, whose `gates` and `controls` fields name the gate and each row's `NC-` control): rows 5, 7
   and 8 by this bead (row 5 calls N33c-36's probe and mutants in process under `gauntlet-mutations`; row 7
   reads the guard's per-binary report on the clean tree, the conflict probe's outcome file and the plant's
   failure on a scratch copy; row 8 is an entry at the `metal` site reading the device entry of the fingerprint
   and the INT-FT-01 record, `Skipped` elsewhere, and a skip is never a pass), row 6 by N23b-30 at M2. The
   recording session enters the M0 part from the receipt of `FROB_TEST_SEED=<seed> cargo test -p
   frob-conformance --features gauntlet-mutations --test g1_known_answers -- GATE-WS-06` run on the Mac, with
   `cargo run -p frob-conformance --example record_gate -- --gate GATE-WS-06 --receipt <hash> --part M0`; the
   gate's M0 state is then `pass (rows 5, 7, 8); row 6 due M2`. At M2 the sampler-battery bead N23b-30 enters part
   M2 the same way (`--part M2`) from the receipt of the `--sampler-row` mode, and the gate becomes `pass`. No
   PASS is written on a dirty sibling tree (the receipt's `dirty` flag is refused by the recorder).

## Acceptance criteria

- [ ] Row 5: the four probe cases pass to 10⁻¹² and the unconverted mutant fails both crossing cases.
- [ ] Row 7: one `serde_json` version per binary; the conflict probe's outcome recorded; the `ftx-drape` plant fails `check-deps`.
- [ ] Row 8: the fingerprint of the Mac carries the Metal language version and the 64-bit atomic probe; `msl_version` is in the INT-FT-01 record.
- [ ] Row 6 is recorded `due M2` at M0 (its steps logged `not-run: N33c-37`) and completed at M2 with the battery's rejection of the plant at 0.6655 ± 0.005 (N23b-30).
- [ ] Each row has a negative control registered and caught: the unconverted mutant; the qualified sampler passing where the plant fails; the planted second pin; the post-3.1 dialect plant.
- [ ] The G1 entries of rows 5, 7 and 8 are registered under GATE-WS-06 with their controls; the gate row's M0 part was entered with `record_gate --part M0` from the receipt of the tier run on the Mac, and with the admission entry it cites the receipt and the sibling revisions and distinguishes `pass`, `fixed upstream` and `due`.
- [ ] The M0 exit review finds this gate with a recorded value; the M2 exit review finds it complete.

## Test plan

### Unit tests

The unit tests of the four probe beads are prerequisites and are run by the script. This bead adds
`crates/frob-conformance/tests/gate_ws06.rs`:
- `gate_record_has_four_rows`: the registry row parses and names rows 5 to 8 with a state each.
- `m0_state_requires_rows_5_7_8`: with row 7 missing the state is `incomplete`, never `pass`.
- `row6_cannot_pass_without_battery`: a record that marks row 6 passed with only the plant's unit tests attached is rejected.
- `fixed_upstream_requires_revision_and_review`: a `fixed upstream` state without a sibling revision or without a review note is rejected.

### End-to-end script and logging

`scripts/e2e/suite_ws06.sh` (modes: default for M0; `--sampler-row` for M2):
1. `cargo xtask check-stack`.
2. Row 5 through the conformance driver: `cargo run -p frob-conformance --features gauntlet-mutations --example
   foundation_probe -- mixed-wrench --json` (the example declared by the probe beads, N33c-36 adding this
   subcommand; there is no `frob-conformance` binary, BD-025).
3. Row 7: `cargo xtask check-deps`; `scripts/admission/pin_conflict_probe.sh`; the plant on a scratch copy.
4. Row 8 (Mac): `frob spark fingerprint --device metal:0 --key ws06-fp-<run> --json`; read the INT-FT-01 record.
5. With `--sampler-row`: the battery on the plant and on the qualified sampler, through the gate run of
   GATE-CORTEX-18 (`FROB_TEST_SEED=<seed> cargo test -p frob-conformance --features gauntlet-mutations --test
   g1_known_answers -- GATE-CORTEX-18`); from that run's receipt, the assertion that the plant was refused by
   the admission check that `train.start` calls (N23b-29's function, called in process by an entry of the gate
   run): the Cortex refusal `sampler-unqualified` (`FROB-REF-558`, N23-REF), no world created. `frob train
   start` is not used: the planted sampler is a fixture of `frob-conformance` and cannot be selected from the
   `frob` binary. Then the tier run of GATE-WS-06 at M2 (`... --test g1_known_answers -- GATE-WS-06`), whose
   receipt carries row 6's entry, for N23b-30 to record part M2.
6. The M0 tier run of GATE-WS-06 (item 7); the script logs the receipt hash and stops there: the row is entered
   by the recording session with `record_gate`, never by the script.
The script sources the STD-E2E helper and writes `target/e2e-logs/suite_ws06/<utc>.ndjson` and a transcript.
Each line has `ts`, `script`, `bead: N33c-40`, `step`, `event`; `cmd` lines carry the exact command, exit code
and wall time; `metric` lines carry the momentum components with expected values and the tolerance 10⁻¹², the
`serde_json` version count per binary, the agreement frequencies with ½ ± 0.005 and 0.6655 ± 0.005; `assert`
lines carry each negative control's outcome; envelopes' `evidence` blocks are copied where a `frob` verb answered;
on failure, the first differing component or binary and the artifact paths. The `summary` gives assertions passed
and failed, the state of each row, and `gates: [GATE-WS-06]`.

### Known answers and negative controls

Known answers: the four momentum vectors; adjacent-channel agreement 0.6655 (reported counts 66,552, 66,552 and
66,551 in 100,000); the `serde_json` versions 1.0.151 and 1.0.154 in conflict; the enumeration ending at 3.1.
Negative controls: one per row as listed in the acceptance criteria. A control on the gate itself: a run on a
dirty FrankenSim tree must produce a development record and no PASS. Lanes: `trj` and the Mac (row 8 on the Mac
only); twice on one machine with identical records apart from timestamps.
