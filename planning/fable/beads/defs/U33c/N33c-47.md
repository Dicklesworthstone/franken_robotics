## Background

Every sibling repository FrankenRobotics consumes belongs to the same owner, so a limitation, defect or mismatch
found in a sibling is work this program does, in the sibling's repository, under that repository's own
`AGENTS.md`, gates and conventions. Each such change is an **upstream work item**: a bead in this program's graph
with the label `upstream`, mirrored as a bead in the sibling's tracker, and recorded in `registries/upstream.toml`
with five things: the change, a priority, the interim posture here, the switch-over rule, and one reproducible
failing fixture. No milestone waits on an upstream change landing, and no local patch or fork stands in for one.
A defect found in a sibling becomes an admission test here and an upstream work item there, in that order.
Upstream changes are additive (a new mode, entry point, type or feature, never a change to existing behaviour),
and before an upstream change edits a file it reserves that file through Agent Mail and follows the sibling's
coordination rules.

A seed bead (BD-037) defines the register's format and writes the 53 rows of the plan's main register. Five of
those 53 follow from the coupling note and the further foundation facts, and BD-037 writes them with their full
content (change, priority, interim posture, switch-over rule, fixture, mirrored bead); this bead does not write
them again. It links their admission probes to them:

| Item (row written by BD-037) | Repo | Priority | What it changes, in one line | Admission probe that this bead links to it |
|---|---|---|---|---|
| FD-FSIM-31 | frankensim | P2 | `fs-evidence` without its `fs-qty` dependency | INT-TOOLCHAIN-01 (the coupling note) |
| FD-FSIM-32 | frankensim | P2 | `fs_g1_train::gaussian_action` with independent channels | foundation-fact row 6: the planted sampler (N33c-37) |
| FD-FSIM-33 | frankensim | P2 | `fs-mbd::Wrench` frames documented, or named constructors | foundation-fact row 5: the mixed-wrench probe (N33c-36) |
| FD-FTX-01 | franken_textiles | P3 | the exact pin `serde_json = "=1.0.151"` relaxed | foundation-fact row 7: the exact-pin conflict probe (N33c-38) |
| FD-F3D-01 | franken_threed | P3 | the same relaxation | foundation-fact row 7: the same probe (N33c-38) |

Six more are described by the last subsection of the suite chapter and were added to the register "by
description", without identifiers: fold or declare the omitted masses of the G1 catalog; a closed-form
differential for small rotation and large translation; a documented or removed legacy transformer; an arc-aware
swept bound; an authored-coefficient check and an outward-rounded result in `fs-sos`; a ray transform that
returns the scale of its parameter. Each is done in the sibling's repository under its rules, and the interim
postures hold until it lands. The row about the Metal gateway's unwrapped bindings is already part of FD-FT-01.

Without this bead those eleven items would exist only as sentences; a later reader could not tell whether an
interim posture is still needed.

## Technical approach

1. **Rows for the six unnumbered items (DESIGN: priorities follow the value to this project: P3 unless a gate of

   every one has an interim posture that removes the sibling from the trusted path, so all six are P3. The
   `fs-sos` row is P3 for that reason: no `fs-sos` value enters a certificate, and NF-11 states the same priority.
   Identifiers are the next free numbers of the sibling's series, taken in the order of foundation-fact rows 9
   to 14: `FD-FSIM-34` to `FD-FSIM-38` and `FD-F3D-02`. They are fixed when the row is written and never reused;
   NF-07 to NF-12 name the same numbers. If another row has taken one of these numbers by the time this bead
   runs, the six take the next free run in the same order and the six upstream beads are updated in the same
   change.)**

2. **For each of the six new rows.**
   1. Write the row in `registries/upstream.toml` in the format of BD-037 (schema `frob.upstream/1`): `id` (the
      identifier above), `repo`, `change`, `priority`, `interim_posture`, `switch_over`, `fixture`,
      `admission_test` (`GATE-WS-09 row 9` to `row 14`), `bead` (`NF-07` to `NF-12`), `mirror`, `status = "open"`
      and `observed_at` (the sibling revision at which the fixture was seen to fail).
   2. Open the fixture in the one form BD-037's fixture rule gives every row: the directory
      `tests/upstream/<bead key>/` (`tests/upstream/NF-07/` to `tests/upstream/NF-12/`; DESIGN, as in BD-037: the
      directory is named by the bead key and is not renamed when the `FD-` number is assigned), holding one
      `#[ignore]`d `frob-conformance` integration test (`upstream_nf_07` to `upstream_nf_12`) and `expected.toml`
      with `upstream = "<identifier>"`, `observed_at`, the failing assertion and the observed value. The test is
      the admission probe's case pointed at the sibling's entry point at the pin (the last column of the table);
      it asks for the capability the change adds and fails because the capability is absent. The admission
      probe's own test is not the fixture: the probe passes at the pin (it records what the pin does), the
      fixture fails at the pin (it asks for what the change will provide). For rows 12 and 14, whose probes are
      measured at M2, the fixture is still written here at M0: it needs only the sibling's public entry point.
      `FD-F3D-02` concerns franken_threed, which has no pin at M0 (it is first consumed at M3): its row follows
      BD-037's fixture timing rule, with `pin_state = "unpinned"` and `observed_at` the franken_threed head read
      on the day; NF-12 re-runs the fixture at franken_threed's first admission and clears the field.
   3. The bead here already exists (NF-07 to NF-12, label `upstream`); store its key in `bead` and name the probe
      bead in the row's notes.
   4. Open the mirrored bead in the sibling's own tracker, following that repository's rules, with the row as
      its body; record its identifier in `mirror`. The upstream bead (NF-07 to NF-12) later replaces the body
      with its full report and closes the mirrored bead when the change lands.
3. **For each of the eleven late items (the six above and BD-037's five).** A comment-free machine-readable
   link from the probe to its identifier, in the table-entry form: one file this bead owns,
   `crates/frob-conformance/src/upstream/probe_links.toml`, with one entry per link, `{ row, probe, upstream }`,
   where `row` is the foundation-fact row (or `INT-TOOLCHAIN-01`), `probe` the probe's test path and `upstream`
   the identifier, so that when the probe reports `fixed upstream` the register row can be found and its
   switch-over rule run. The entries: INT-TOOLCHAIN-01 (BD-031's coupling test) → FD-FSIM-31; row 5 (N33c-36)
   → FD-FSIM-33; row 6 (N33c-37) → FD-FSIM-32; row 7 (N33c-38) → FD-FTX-01 and FD-F3D-01; row 8 (N33c-39) →
   FD-FT-01; rows 9 to 14 (N33c-41 to N33c-46) → FD-FSIM-34 to FD-FSIM-38 and FD-F3D-02; rows 1 to 4, the
   reported defects with their own admission gates: row 1 (`ppo_update`, INT-FSIM-06, BD-034) → FD-FSIM-10; row 2
   (`planar_drive`, INT-FSIM-05, BD-033) → FD-FSIM-11; row 3 (strides, INT-FNP-02, BD-036) → FD-FNP-01; row 4
   (sustained contact step, INT-FSIM-04 and -07, BD-035) → FD-FSIM-12 and FD-FSIM-13. No row of the fourteen
   carries the note "no upstream change" today; the note exists for a later row whose fact needs none. The probes' own test code is
   not edited by this bead, so it does not wait on them. A probe whose test does not exist yet is reported
   `probe pending` and does not fail the test; at M0 the probes of rows 6, 12 and 14 (N33c-37, N33c-44, N33c-46,
   written at M2) are pending by design, and any other pending M0 probe is left for the gate that records its
   row (GATE-WS-06, N33c-40; GATE-WS-09, N33c-48) to close.
4. **Consistency check.** A test in `frob-conformance` reads `registries/upstream.toml` and the link table of
   item 3 and asserts: every foundation-fact row 1 to 14 has an upstream identifier or the note "no upstream
   change" (row 7's worker posture and row 8's part of FD-FT-01 are covered by identifiers); every identifier in
   the link table names a row of the register; every upstream row
   has a fixture that exists; no identifier is reused; counts by repository and priority are printed (the main
   register had 53 items before these six: 33 in frankensim, 3 in frankentorch, 5 in frankensympy, 2 in
   franken_lean and one each in ten other repositories or groups; two P0, eight P1, sixteen P2, twenty-seven
   P3. After the six: 59 items, 38 in frankensim, 2 in franken_threed, and two P0, eight P1, sixteen P2,
   thirty-three P3). The count is taken over the 59 identifiers this bead and BD-037 name, held in a constant
   beside the test, so that a well-formed row added later by another bead does not fail it; BD-037's own count
   test counts its 53 in the same way.
5. **What registration does not do.** It moves no pin, edits no sibling file, and blocks no milestone. An item
   that lands is adopted only through its switch-over rule and a compatibility train (move the pin, write a new
   receipt, rerun the admission and parity gates, relock).

## Test plan

### Unit tests

`cargo test -p frob-conformance upstream_register`:
- `rows_have_five_things`: every row has the five required fields non-empty.
- `fixtures_exist`: every fixture path resolves to a test in this repository.
- `identifiers_unique_and_never_reused`: no identifier appears in two rows, and the six new numbers are not below `FD-FSIM-34` or `FD-F3D-02` (no number of BD-037's series is reissued). Withdrawn numbers and reservations are NFx-01's check (its series file of reservations and tombstones), which depends on this bead.
- `foundation_fact_rows_linked`: rows 1 to 14 each map to an identifier or an explicit note.
- `counts_by_repo_and_priority`: after this bead, frankensim 38, franken_threed 2, total 59, and 2/8/16/33 by priority; printed.
- `late_fixtures_in_register_form`: each of the six fixtures is `tests/upstream/NF-07/` … `NF-12/`, holds an `#[ignore]`d test and an `expected.toml` whose `upstream` equals the row's `id`.
- `probe_links_resolve`: every entry of `probe_links.toml` names a row of the register and a probe test that exists or is reported `probe pending`; a planted entry `FD-FSIM-99` must fail.

### End-to-end script and logging

`scripts/e2e/upstream_register_late.sh` (owned by this bead; header `bead=N33c-47 milestone=M0
labels=suite,upstream,registry plants=fixture-passes-at-pin,empty-switch-over,dangling-fixture,reused-id`), on the
STD-E2E helper: runs `cargo test -p frob-conformance upstream_register` and logs one `assert` event per test;
runs each of the six fixtures with `-- --ignored` and asserts that it fails at its recorded commit (an `assert`
event per fixture with the identifier, `observed_at` and the failing assertion, the franken_threed one with
`pin_state = "unpinned"`); logs per link of `probe_links.toml` an `assert` event with its state (`linked` or
`probe pending`); logs the counts by repository and priority as `metric` events against the known answers below.
Under `E2E_PLANT_FAILURE=<plant>` the named negative control below is planted in a scratch copy and must be
caught. Reading the probes' reports and printing `switch_over_due` for a probe that reports `fixed upstream` is
N33c-48's `suite_ws09.sh`, which depends on this bead and runs this consistency test as its step 4.

### Known answers and negative controls

Known answer: 53 items before, 59 after; frankensim 33 + 5 = 38; franken_threed 1 + 1 = 2; P3 27 + 6 = 33.
Negative controls: a fixture edited to pass at the pin must fail the registry check (BD-037's rule); a
row with an empty switch-over rule must fail `rows_have_five_things`; a row whose fixture path points to a
deleted test must fail `fixtures_exist`; an identifier reused for a different change must fail the uniqueness
test. Lanes: not applicable beyond running the test on both machines.

## Considerations
- RISK-55: an upstream change collides with other agents working in the same sibling repository. Registration
  is the cheap part; the changes themselves reserve files first and land small.
- The priority of an upstream work item states its value to this project and orders it in this program's queue.
  No priority makes a milestone wait: the interim posture holds until the switch-over rule has been run.
- An upstream work item is never a mitigation by itself; its interim posture is.
- The six new identifiers are assigned by this bead when it writes the rows, as the next free numbers of each
  sibling's series (`FD-FSIM-34` to `FD-FSIM-38`, `FD-F3D-02`). BD-037's register ends at `FD-FSIM-33` and
  `FD-F3D-01`. Another upstream item raised without a number (an input-affine fit in `fs-surrogate`) is expected
  to take `FD-FSIM-39`, after these.
- A third-party gap is not an upstream work item; none of these eleven is third-party.
- The six items of the later foundation facts map to upstream beads as follows: G1 catalog mass (N33c-41) → NF-07;
  the SE(3) differential limit (N33c-42) → NF-08; the legacy transformer sign (N33c-43) → NF-09; the arc-aware
  swept bound (N33c-44) → NF-10; `fs-sos` bounds (N33c-45) → NF-11; the ray transform (N33c-46) → NF-12. The
  register rows cite those keys in `bead`.
- Division with BD-037 and with NF-07 to NF-12 (DESIGN): a register row is written once, by one bead. BD-037
  writes the 53; this bead writes six; an upstream bead never writes a row, it only updates `status`,
  `observed_at` and the body of its mirrored bead.
