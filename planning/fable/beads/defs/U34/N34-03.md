## Background

`check-deps` is one of the six workspace checks of the `xtask` tool. Its first rules (who may depend on what)
are written in BD-003. This bead adds the rules that come from consuming a suite of sibling repositories whose
pins and features move, and the rule that keeps frontier work out of default builds. All are DESIGN decisions
enforced by tool, because each failure they prevent is silent at build time. Tier: Solid.

- **One async runtime package per binary** (invariant INV-SUITE-02). Every binary links exactly one
  `asupersync` package. FACT (2026-11-21): three siblings still pin 0.5.0 (frankentui's optional executor,
  franken_threed's runtime crate, frankenjax, optional); the MCP library's registry package 0.13.0 carries 0.5.0
  while its source tree pins 0.6.2; FrankenTorch requires 0.6.2; FrankenSim consumes the runtime by path. Two
  runtime packages in one binary mean two schedulers, two cancellation trees and types that do not unify. The
  siblings are aligned upstream (upstream work item FD-ASUP-01), and this rule is what notices a regression.
  Two neighbouring statements of the design are enforced elsewhere and are not rules of this bead: that every
  workspace resolves the same published version, the one in the stack lock (the stack check, wired by BD-008),
  and that version 0.5.0 never enters a graph (a deny row of N33c-09).
- **Forbidden sibling forms** (frankentui's `asupersync-executor` feature; frankenjax and franken_threed never
  Cargo dependencies) are deny rows of the same check. They are written, with the posture register of the
  siblings, in N33c-09, and are named here only because the ownership rule below covers their findings too.
- **Airlock feature groups.** The airlock crate `frob-fsim` exposes its traits in Cargo feature groups so that a
  crate above it compiles only the closure it uses. The groups bound what a crate above the airlock may name,
  always; a group may be enabled only by the crates listed for it.
- **L-12.** Features that select a tier of ambition are named and off by default: `frontier-*` and `moonshot-*`
  features gate every Frontier and Moonshot mechanism in a mixed crate, and no default build enables one
  (invariant INV-WS-04). Reason: a moonshot must never sit on a critical path, and "it was only compiled in"
  is how one gets there.
- **Resolution with everything on.** Counterexample to "a passing build means the pins are compatible": a build
  that never enables an oracle's feature flag resolves, and the conflict appears only when the flag is first
  turned on at the oracle's milestone. The resolution check therefore runs with every optional feature group
  enabled.

  GATE-WS-01);

  `fsim.optional-default-on`), read from the feature records of `crates/frob-fsim/contract.toml`;

  `suite.forbidden-package`; dev-only siblings; `egg`) and the posture register `registries/siblings.toml`:

- The upstream alignment itself (FD-ASUP-01, FD-FMCP-01, done in the sibling repositories); the admission gate

  the planted second pin (the risk-register unit).

## Technical approach

Inputs: for each workspace, `cargo metadata --format-version 1 --locked --offline` **with** the resolve graph,
once with default features (the read BD-003 already makes, shared within the one `check-deps` process) and once
with `--all-features`; the committed lockfiles; `franken-stack.lock`.

Per-binary precision (DESIGN). `cargo metadata` resolves features for the whole workspace at once, which
over-approximates the features a single binary's build enables, so a walk from one binary's package can only
see too much, never too little. Each `asup.duplicate` candidate is therefore confirmed for its binary with
`cargo tree -p <package> --target <triple> -e normal,build -i asupersync --locked --offline`, which resolves
features for that package alone, and only a confirmed duplicate is reported. Fail-closed: if the confirmation
cannot run, the unconfirmed candidate is reported, with `confirmed: false`.

1. **Per-binary closure.** For every binary target in every workspace (`frob`, `frobd`, `frob-mcp`,
   `frob-verify`, `frob-fsim-worker`, `frob-tui`, `xtask`, the device-enabled `frob` and `frobd` of `apps/`),
   walk the resolve graph from its package over normal and build edges, and collect the packages named
   `asupersync`. The walk is made twice, on the default-feature resolution (the features that target enables)
   and on the resolution with every optional feature group enabled, and for each target platform in use, so
   that a duplicate which only one binary's feature set pulls in is seen.
   - `asup.duplicate` (guards INV-SUITE-02): more than one package in one binary's closure. Two versions are
     two packages; so is one version from two sources (the registry and a path).
   - Count required (DESIGN): exactly one for a binary that links the runtime; zero for `frob-verify` and for
     the crate `frob-cert` built alone (the independent auditor depends on nothing); a binary whose closure has
     none (`xtask` may be one) is reported as `none` and is not a finding. Reason: the invariant's hazard is a
     second package, and "exactly one" read literally would contradict the auditor's rule.
   Not findings of this rule: the resolved version differing from the stack lock's asupersync row, or two
   workspaces resolving different versions, is a finding of `check-stack` (BD-008), because comparing the
   stack lock with lockfiles is that check's job; an `asupersync` package of version 0.5.0 anywhere is the
   deny row `asup.v0_5_0` of N33c-09.
2. **Forbidden forms** are not rules of this bead. The findings `asup.v0_5_0`, `ftui.executor-feature` and
   `suite.forbidden-package` belong to the deny rows of N33c-09 (same check, same report format).
3. **Airlock groups** (`fsim.group-not-allowed`, guards INV-SUITE-01). The data is not kept in `xtask`: the
   rule reads the feature records of `crates/frob-fsim/contract.toml` (defined by N33a-11 and extended by
   N33b-09: per group its default, `consumers` and `test_consumers`). A workspace member whose manifest enables
   a feature of `frob-fsim` without being named in that feature's `consumers` or `test_consumers` fails; a
   record changes only with the group's admission record or with an ADR that amends the lists (ADR-SUITE-03 of
   N33bx-02 is the first: five amended lists and an eleventh record, `tracer`, which this rule reads like the
   others). `check-contracts` fails a record that differs from the table generated into
   `crates/frob-fsim/CONTRACT.md` (N33bx-02), so the records and the published table cannot drift; that rule is
   the contract check's, not this one's. The records at the time of writing, before ADR-SUITE-03, restated for
   the reader (the file governs; DESIGN of N33a-11):

   | Group | Default | May be enabled by |
   |---|---|---|
   | `referee` | on | `frob-model`, `frob-dyn`, `frob-contact`, `frob-analyze`, `frob-verbs`, `frob-conformance` |
   | `geometry` | on | `frob-contact`, `frob-scene`, `frob-foundry`, `frob-conformance` |
   | `ledger` | on | `frob-chronicle`, `frob-verbs` |
   | `optimize` | off | `frob-opt`, `frob-arena`, `frob-dyn`, `frob-mission`, `frob-analyze` |
   | `stats` | off | `frob-nemesis`, `frob-arena`, `frob-ground`, `frob-opt`, `frob-mission`, `frob-dyn` |
   | `spectral` | off | `frob-gait`, `frob-lifecycle` |
   | `actuation` | off | `frob-actuate` |
   | `structure` | off | `frob-foundry`, `frob-ground` |
   | `multiphysics` | off, gated bridge | `frob-scene` (evaluation tier only) |
   | `harness` | dev only | `frob-fsim` and `frob-conformance`, as dev-dependencies |

   `fsim.default-set`: the default *group* set of `frob-fsim` is exactly `referee`, `geometry`, `ledger` (the
   build-mode feature `mode-inproc`, also on by default, is not a group and is not counted).
   `fsim.optional-default-on` (DESIGN; the consumer's side of the same rule, which the amending decision
   ADR-SUITE-03 of N33bx-02 states as "a consumer requests an optional group only through a feature of its own
   that is off by default; no default feature set enables an optional group" and which had no finding): in the
   default-feature resolution of a workspace, the resolved feature set of `frob-fsim` contains a group whose
   record says `off`. The finding names each member that causes it and how: a plain dependency declaration on
   `frob-fsim` that lists the group in `features`, or a feature of the member's `default` list that enables
   `frob-fsim/<group>` directly or through the member's other features. The passing form is a feature of the
   consumer that is not in its `default` list (for example `frob-algebra`'s `airlock-tropical` enabling
   `frob-fsim/optimize`). One finding per defect: a member that is not on the group's list is reported as
   `fsim.group-not-allowed` only, and `harness` (dev only) is judged by its list alone. Reason for a finding
   and not only a test: without it the bound "a crate above the airlock compiles only the closure it uses"
   holds for the airlock's own defaults and fails silently at the first consumer that turns a group on for
   every build.
   `fsim.group-absent` is the matching runtime refusal (FROB-REF-790: a verb needs an airlock feature group that
   this binary was not built with) and is not raised by this check.
4. **Tier features (L-12, INV-WS-04).** `tier.default-on`: any feature named `frontier-*` or `moonshot-*` is in
   a `default` feature list, or is enabled by a dependency declaration inside the core workspace without an
   explicit feature of the same tier on the depending crate, or is enabled in the default-feature resolution of
   any binary. `tier.unnamed`: a crate whose crate-map tier includes F or M has a `contract.toml` feature of
   tier F or M whose name lacks the prefix.
5. **All-features resolution** (`resolve.all-features`). The `--all-features` resolution of each workspace must
   succeed; a failure reports the two requirements that conflict. Runs offline against the committed lockfile;
   when the lockfile cannot satisfy all features the finding names the package.
6. **Ownership.** A second asupersync package is a finding of this check only. The stack check records
   duplicates in the resolution receipt as data and does not fail on them, so that a planted second package is
   caught by exactly one check (the workspace gate GATE-WS-01 requires each of its seven plants to be caught by
   the check that owns it and by no other). The converse holds for the version: a single package whose version
   differs from the stack lock's row is a finding of the stack check only, and this check does not report it.
   BD-008, which wires both, states the same split.

Report format: each finding line carries the rule identifier, the invariant it guards where there is one
(`asup.duplicate` → INV-SUITE-02; `fsim.group-not-allowed` → INV-SUITE-01; `tier.default-on` → INV-WS-04), the
binary or crate, the offending package identifiers with their sources, and one dependency path for each, so
that the sibling that brought a second package is named.

Report facts: per binary, the asupersync version linked and its source (or `none`); per workspace, the enabled
airlock groups by crate. BD-008 copies the per-binary facts into the admission record of INT-ASUP-01.

## Acceptance criteria

- [ ] A scratch copy in which `frob-verbs` gains a dummy path dependency that pulls a second `asupersync`
      package fails with `asup.duplicate`, naming both versions and one dependency path each; `check-layers`,
      `check-stack` and the other checks stay clean on the same copy (the third plant of GATE-WS-01).
- [ ] The same version from two sources (registry and path) in one binary's closure fails with
      `asup.duplicate`; a duplicate reachable only from one binary's feature set is caught although the
      workspace-level duplicate listing alone would pass.
- [ ] `frob-gait` enabling `optimize` fails with `fsim.group-not-allowed`; `frob-opt` enabling it passes. The
      allow-lists are read from the feature records of `crates/frob-fsim/contract.toml`, and no copy of them is
      compiled into `xtask`.
- [ ] The planted fixture shipped by N33a-11 under `crates/frob-fsim/tests/fixtures/` (a manifest in which
      `frob-dyn` enables `structure`) fails with `fsim.group-not-allowed`, naming `frob-dyn` and `structure`.
- [ ] A listed consumer that enables its optional group for every build fails with `fsim.optional-default-on`
      and with no other finding: `frob-opt` with `features = ["optimize"]` on its plain `frob-fsim` dependency,
      and `frob-opt` with a feature `airlock-optimize` (enabling `frob-fsim/optimize`) in its `default` list;
      the same feature outside the `default` list passes.
- [ ] A single asupersync package whose version differs from the stack lock's row produces no finding of this
      check (it is a finding of `check-stack`, BD-008).
- [ ] INV-WS-04: a `frontier-gait` feature added to a `default` list fails; the same feature enabled explicitly
      by a binary's non-default feature passes.
- [ ] A planted second exact pin on one package behind an optional feature fails `resolve.all-features` and
      passes the default resolution.
- [ ] Every binary's report line shows exactly one asupersync version, or `none`, and `frob-verify` shows
      `none` (INV-SUITE-02). Equality with the stack lock's version is asserted by `check-stack` (BD-008).
- [ ] The rules of this bead add at most 7 s to `check-deps` on a warm tree, the `--all-features` resolution
      included (TARGET; this bead's line of the GATE-WS-04 share table in BD-004).

## Test plan

### Unit tests

`cargo test -p xtask deps_suite` on `synthetic` scratch workspaces resolved by the real `cargo metadata` (dummy
crates under the fixture directory stand for the siblings; no network):
- `one_asupersync_per_binary`; `second_asupersync_by_path_fails`; `second_asupersync_by_registry_fails`;
  `same_version_two_sources_fails` (registry 0.6.2 and path 0.6.2 without the patch entry: two package
  identities at one version); `binary_scoped_duplicate_caught` (a duplicate reachable only from one binary's
  feature set: the workspace-level listing alone would pass, the per-binary walk fails);
  `frob_verify_links_none`; `binary_without_runtime_reports_none`; `version_mismatch_is_not_reported_here`
  (one package at a version other than the stack lock's: no finding of this check);
  `unification_only_candidate_not_reported` (a second package that appears only because another workspace
  member enables a feature: the workspace walk flags it for binary A, the per-package confirmation clears it,
  and binary B, whose own features pull it in, is reported with `confirmed: true`).
- `group_allow_list` (one passing and one failing crate per off-by-default group, read from the feature
  records); `default_groups_are_three`; `on_by_default_lists_are_explicit` (`frob-spec`, a layer-4 crate
  that is on neither list, enabling `referee` or `geometry` → `fsim.group-not-allowed`; `frob-scene` enabling
  `geometry` passes).
- `optional_group_default_on`: `frob-opt` with `optimize` in the `features` of its plain dependency →
  `fsim.optional-default-on` naming `frob-opt`, `optimize` and "plain declaration"; with `default =
  ["airlock-optimize"]` and `airlock-optimize = ["frob-fsim/optimize"]` → the same finding naming the feature;
  through one more step (`default = ["full"]`, `full = ["airlock-optimize"]`) → the same; with
  `airlock-optimize` outside `default` → no finding; `frob-gait` doing any of these → `fsim.group-not-allowed`
  alone.
- `airlock_fixture_frob_dyn_structure_refused`: N33a-11's planted fixture, run through the rule unchanged (the
  fixture file is read where N33a-11 ships it, not copied) → one `fsim.group-not-allowed` finding with the crate
  and the group; with `frob-dyn` added to a scratch copy of the `structure` record's `consumers` → no finding,
  which shows the rule reads the records.
- `tier_feature_in_default_fails`; `tier_feature_leaks_through_dependency_fails`;
  `tier_feature_behind_explicit_feature_passes`.
- `all_features_conflict_fails` (two dummy dependencies with `=1.0.151` and `=1.0.154` on one package).

## Considerations

- RISK-03 (two asupersync versions in one build; severity High; owner: Build lead). If a surface still brings a
  second package after the upstream alignment, the MCP kill gate's first fallback moves that surface into its
  own workspace; this check then verifies the rule per workspace as before.
- The toolchain-train risk: two asupersync packages in the duplicate listing is its earliest signal besides a
  failing cell of the toolchain matrix.
- The airlock table is an initial reading of the design; the first contract of each consuming crate confirms or
  changes its rows, and each off-by-default group is admitted by its own group gate at the milestone that first
  uses it. Until a row lists a crate the check refuses it. The draft of this bead carried its own table, which
  had drifted from the feature records (`optimize` and `stats` lacked `frob-dyn`, `optimize` lacked
  `frob-analyze`, `harness` lacked `frob-fsim`); reading the records instead of compiling a copy removes that
  failure mode.
- franken_threed and frankenjax are named in two ways by the design (never Cargo dependencies; used behind a
  feature or in the derivation annex if admitted). The fail-closed reading is implemented by the deny row of
  N33c-09: absent from every graph until a stack-lock row with an admission gate lists the workspace.
- Supply chain: committed lockfiles and `--locked` are assumed; a missing lockfile is a finding of the stack check.
