## Background

Twelve layer and dependency rules govern the core workspace. Ten of them are assigned to one of the six checks of
the `xtask` tool. Two are not, and a rule nobody enforces decays:

- **L-6** No bare `f64` physical quantity in a public signature above layer 1. Quantities are `frob_core::qty`
  types or group elements. Reason: the convention of the whole system is SI units with dimension-typed
  quantities at every public API, and tolerances carry dimensions (one unitless epsilon across angles, impulses
  and temperatures is invalid). A public function `fn set_gain(k: f64)` is the place where a newton-metre is
  passed as a newton-metre per radian and nothing faults. Layers 0 and 1 are exempt because they define the
  quantity vocabulary and the Lie-group algebra, whose coordinates are dimensionless or already typed. Device
  buffers are raw `f32` with the dimension recorded in the buffer schema; they are not public signatures.
- **L-7** Library crates do not print. Hot loops emit no per-iteration JSON. Reason: every verb writes exactly
  one envelope to standard output, and an agent parses it; a stray `println!` from a library corrupts the
  envelope, and per-step JSON in a batched step destroys throughput and floods the context of the agent reading
  it. Telemetry leaves a computation through the evidence sink and the chunk store, never through the console.

The design fixes the number of `xtask` checks at six: a seventh needs a named defect class it would have caught
and the owner's approval. DESIGN: both rules are therefore enforced with tools the compiler and the test runner
already provide: the workspace lint table for L-7, and each crate's own conformance test for L-6. No subcommand
is added. Tier: Solid.

Rejected alternatives: (1) a seventh check `check-api` (breaks the six-check guard for something lints can do);
(2) enforce L-6 by review (it is exactly the kind of rule a tired reviewer waives); (3) a blanket ban on `f64`
in public signatures (dimensionless ratios, probabilities and counts-as-reals are legitimate and are written as
the dimensionless aliases of `frob_core::qty`, `Ratio` among them, or as `Checked` (N33c-03; the set is decided by
N33c-04), which keeps the scan simple and the intent explicit).

## Scope

In: the workspace lint entries for L-7; the helper for the L-6 public-signature scan in `frob-core`'s
test-support module and its use from each crate's `tests/conformance.rs`; the allow-list format; tests with
planted violations. Out: the six checks; the units crate and its escape hatch (BD-031); the content of each
crate's conformance test beyond this helper.

## Technical approach

1. **L-7 by lints.** The root `Cargo.toml` `[workspace.lints.clippy]` table denies `print_stdout`,
   `print_stderr` and `dbg_macro`. Every library crate of the core inherits the table (`[lints] workspace =
   true`; the lint-table inheritance itself is checked by the unsafe-and-lints check, N34-07). Binary roots
   that own a console (`frob`, `frobd`, `frob-mcp`, `frob-verify`, `frob-tui`, `xtask`) allow the two print
   lints at the crate root of the binary target only, never in a library target. Tests may print.
2. **L-7, hot loops.** "No per-iteration JSON" is a property of code paths, not of names, so it is tested where
   it matters: each crate that owns a stepping loop asserts in its conformance test that stepping N worlds for K
   steps with telemetry level T0 (the lowest level, which every world always records: per-episode metrics,
   energy-ledger totals, integer histograms and state digests at intervals) performs zero calls on the evidence sink
   per step (the counting sink of
   `frob-core`'s test support records calls and bytes) and that the number of sink calls is independent of K
   between chunk boundaries. A sink call per step is a failure. The counting sink is a real implementation of
   the `EvidenceSink` port trait of `frob_core::ports` (N34-06) that records each call and its byte count and
   returns the content-derived identifier; it is not a mock of the store.
3. **L-6 by a signature scan.** `frob_core::testkit::public_signatures(crate_dir) -> Vec<Sig>` parses the crate's
   source files with a small tokenizer (no macro expansion; items generated by macros are scanned at the macro's
   definition) and returns every `pub fn`, `pub` trait method and `pub` struct field reachable through `pub`
   modules, with its parameter and return types as text. `assert_no_bare_float(sigs, allow)` fails on any type
   that mentions `f64` or `f32` outside these forms: inside a `qty` type's own constructor module; in a type
   alias or newtype the crate declares in its `contract.toml` under `[api.float_ok]` with a one-line reason
   (examples: a raw device buffer view, a learned-policy weight tensor, a probability already wrapped as
   `Ratio`); in a private or `pub(crate)` item. Each crate above layer 1 calls it from `tests/conformance.rs`:
   ```rust
   #[test] fn l6_no_bare_float_in_public_api() {
       let sigs = frob_core::testkit::public_signatures(env!("CARGO_MANIFEST_DIR"));
       frob_core::testkit::assert_no_bare_float(&sigs, include_str!("../contract.toml"));
   }
   ```
   `frob_core::testkit` is the shared test module that STD-TEST creates, behind the feature `test-support`
   (off by default; enabled from dev-dependencies, and as a normal dependency only by `frob-conformance`); this
   bead adds the scan, the assertion and the counting sink to it, so it adds no upward edge (every crate may
   depend on layer 0), no second test feature and no code in production builds.
4. **The allow-list is data in the contract.** `[api.float_ok]` entries are `path = "reason"`. The contract check
   reports their count per crate; an entry whose path no longer exists fails the conformance test, so the list
   cannot rot.
5. **What counts as a quantity.** Anything from `frob_core::qty`, a group element or algebra element of the Lie
   crate, an exact rational, an integer count, or a newtype over one of these.

Determinism class D0; the scan is a pure function of the source text.

## Acceptance criteria

- [ ] A `println!` planted in a library crate of the core fails `cargo clippy` with the deny lint; the same call
      in the `frob` binary root passes.
- [ ] A crate at layer 3 with `pub fn set_gain(k: f64)` fails its conformance test, and the failure names the
      function, the parameter and rule L-6; the same function taking `qty::Stiffness` passes.
- [ ] A crate at layer 1 (`frob-lie`) with `f64` in a public signature is not scanned (the rule starts above
      layer 1); a layer-2 crate is.
- [ ] An `[api.float_ok]` entry with an empty reason, or naming a path that does not exist, fails.
- [ ] The stepping conformance test fails for a planted step that records one evidence item per step and passes
      for one that records per chunk.
- [ ] `xtask` still has exactly six subcommands; `frob-core` built without the `test-support` feature contains none
      of the helper's code (a symbol check in the crate's own test).

## Test plan

### Unit tests

`cargo test -p frob-core --features test-support testkit`:
- `scan_finds_pub_fn_param_and_return`; `scan_ignores_private_and_pub_crate`; `scan_finds_pub_struct_field`;
  `scan_finds_pub_trait_method` (`pub trait Gain { fn k(&self) -> f64; }` is reported); `pub_type_alias_of_f64_is_reported`;
  `scan_follows_pub_modules_only`; `scan_handles_generics_and_references` (`&[f64]`, `Option<f64>`,
  `impl Iterator<Item = f32>` are all reported).
- `allow_list_requires_reason`; `stale_allow_entry_fails`.
- `qty_types_pass`: signatures over `qty::Length`, `Transform<A, B>`, `Ratio` and `u32` produce no finding.
- `counting_sink_counts`: the test sink reports calls and bytes exactly.
- `per_step_sink_call_is_caught` (the planted step of the acceptance): a `synthetic` loop over 4 worlds with
  chunks of 64 steps, run for K = 64 and K = 128 against the counting sink. The variant that records once per
  chunk makes 1 and 2 calls and none between chunk boundaries, and passes the assertion of item 2; the variant
  that records once per step makes 64 and 128 calls and fails it, the failure naming rule L-7.
Fixtures are small `synthetic` source trees on disk; the scanner is the real one.

### End-to-end script and logging

`scripts/e2e/workspace_checks.sh` (bead N34-14) runs `cargo clippy --workspace --locked` and the workspace's
conformance tests once on the clean tree and once on two extra plants (the library `println!`, the bare-float
signature), and logs for each the command, exit code, wall time and the first reported item in the structured
format of STD-E2E. These two plants are outside the seven of GATE-WS-01 and are reported in a separate section
of the summary line.

### Known answers and negative controls

Known answer: zero findings on the clean tree. Negative controls: the planted `println!`; the planted
`pub fn set_gain(k: f64)`; the planted per-step sink call. Live-dependency proof: removing the allow entry for a
legitimately raw signature makes the conformance test fail, so the entry is doing work. Determinism: the scan
output is sorted by path and identical twice on one machine.

## Considerations

- The scan is textual. A public function that takes a private type alias of `f64` defeats it; the alias must be
  `pub` to appear in a public signature, and a `pub type X = f64` is itself reported.
- Macro-generated public items are scanned where the macro is defined; a crate that generates signatures from a
  macro in another crate lists them in its contract.
- The units-crate coupling (the units crate enables an incomplete compiler feature) does not change this rule:
  quantity types reach every crate through `frob_core::qty`, whichever crate backs it.
- Performance: the scan adds well under a second per crate to the test suite.
- If a defect class escapes both mechanisms twice, that is the evidence the design asks for before a seventh
  check is proposed to the owner.
