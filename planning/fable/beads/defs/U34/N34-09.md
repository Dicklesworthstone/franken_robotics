## Background

`check-contracts` is one of the six checks of the workspace's `xtask` tool. Its first half (contract files and
line counts) is written at M0. This bead adds the cross-checks between the registries and the tree that become
meaningful at M1, when the first artifact formats and the first release exist. They are assigned to this check
by design, so that no seventh check is created. Tier: Solid.

Three rules are enforced, each a DESIGN decision:

1. **Every format row has an owner, a round-trip test and a refusal test.** The format registry
   (`registries/formats.toml`, thirteen rows) gives each artifact format one owner crate, which holds the schema,
   the canonicalization rule, the reference reader and the version refusal. A row whose owner cannot show that
   its reader round-trips and refuses is a promise without a test.
2. **Invariant INV-WS-03: every registered extension has exactly one owner crate, and no other crate contains a
   parser for it**, enforced by a search for the schema name outside the owner. Reason: a second parser for a
   design file is a second opinion about which robot the file describes, and the artifact's identity would then
   depend on who read it. The one deliberate exception is the certificate bundle: its schema and reader live in
   `frob-cert`, and its writer lives in `frob-lemma`, written against the schema and sharing no code with the
   reader.
3. **A demo file linked to claims for every release path.** `demos/<demo_id>/demo.yaml` lists the `demo_id`, the
   `claim_id`s it demonstrates, commands that finish in under 60 seconds on the CPU tier (TARGET), and checksums
   of their outputs. A capability with no demo is not released. A demo is evidence that a path runs; it is never
   evidence for the claim's numbers, which come from the gate.

Rejected alternatives: detecting a second parser by behaviour (it would need to run every crate on every
format); listing test names in the registry row (the registry's row shape is fixed by its schema, and a naming
convention needs no new field).

## Scope

In: the three rule groups inside `check-contracts`; the strict readers they need (a YAML-subset reader for
`demo.yaml`). Out: running demos and timing them (N34-12: `xtask` runs no physics); the round-trip harness and
the round trips themselves (N34-22, BD-141, BD-410); the release-manifest cell rules that the delivery chapter
adds to this check under its own gate; the rule `fmt.param-without-row` for schema-named files beyond the
thirteen formats (N34-27).

## Technical approach

**Format rows.** For each row of the registry whose owner crate exists in the tree (a row whose owner has not
landed is listed under `facts.pending`, not reported):

- `fmt.owner-unknown`: the owner is not a row of the crate map.
- `fmt.no-roundtrip-test`: the owner's `tests/conformance.rs` (or a module it declares under `tests/`) has no
  `#[test] fn fmt_<ext>_roundtrip` (the extension without its dot: `fmt_fbot_roundtrip`), or that function does
  not call the shared round-trip harness entry point.
- `fmt.no-refusal-test`: no `#[test] fn fmt_<ext>_refusals`, or it does not mention the registry's version
  refusal (the function must exercise an unknown major version and an unknown field).
- `fmt.no-view-test`: the row declares a view and there is no `#[test] fn fmt_<ext>_view_roundtrip`.
- `fmt.no-fuzz-target`: the owner has no fuzz target named `fmt_<ext>_read`.
- `fmt.schema-missing`: `schemas/` has no generated schema file for the row's schema name (the generated-file
  check owns whether the file is current; this rule owns only its existence for a landed owner).

**The single-parser search (INV-WS-03).** For each row, scan every Rust source file of every crate of the
repository except the owner for the schema name's stem as a string literal (`"frob.design/` followed by a
digit) and for the extension as a string literal (`".fbot"`). A hit is `fmt.second-parser` unless the file is
one of: the declared writer crate of that row (only `frob-lemma` for `frob.cert/1`); a generated table (first
line carries the generated marker); the format registry module of `frob-core` and the routing module of
`frob-verbs`, which read names from the registry and carry the marker `// frob:format-routing`; a file under
`tests/fixtures/`; the offline auditor's standard-library-only reader of the `.frun` manifest and column-file
header under `crates/frob-cert/src/frun/` (bead N29a-03), whose files carry the marker
`// frob:auditor-reader` and are listed in the `FMT-FRUN` row as `auditor_reader`. That reader is the one
sanctioned second implementation of a format: it checks hashes, chains and the frontier and decodes no
column, it is written from the byte-level contract of `frob-chronicle`, and it may share no source file with
it (the shared-source scan of N34-25). Any other literal in `frob-cert` for a format it does not own is a
finding. Consumers below the owner receive typed values and have no reason to name the schema. The
finding lists file, line and the literal.

**Demo files.** With a strict reader for the YAML subset the demo schema uses (block mappings, block sequences,
plain and double-quoted scalars; anything else is an error with line and column):

- `demo.schema`: a `demos/*/demo.yaml` fails its schema (`demo_id`, `claim_ids`, `commands`, `checksums`
  required; unknown key refused). The schema is the one BD-002 ships, extended by N34x-03 with the optional
  keys that the demo runner N34-12 and the first-run demo N00-29 read (`tier`, `expect_exit`,
  `expect_refusal`, `compare`, `expect`, `title`, `milestone`, `actors`, `lane`, `fresh_agent`,
  `not_evidence_for`); this rule reads the schema file and keeps no key list of its own, so a key is admitted
  by adding it to the schema, never to this check.
- `demo.id-mismatch`: `demo_id` differs from its directory name.
- `demo.claim-unknown`: a `claim_id` is not carried by any row of `registries/gates.toml`, or is not in the
  claim identifier's one text form.
- `demo.command-not-frob`: a command's first word is not `frob` (a demo shows the product's path, not a script).
- `demo.missing-for-release-path`: a released capability has no demo whose commands invoke it. The list of
  released capabilities is the release manifest once it exists; until then it is the set of verbs whose registry
  row is marked released.
- `demo.orphan-checksum`: `checksums` names an output that no command produces.
- `demo.expectation-shape`: the cross-member constraints JSON Schema cannot state (N34x-03): a key of
  `expect_exit`, `expect_refusal`, `compare` or `expect` that is not a member of `commands`; a command in
  `expect_refusal` whose `expect_exit` is not 3, or the reverse; a refusal code absent from
  `registries/refusals.toml`; a command other than an exit-3 command without exactly one of a checksum and a
  comparison; an `expect` file that does not exist in the demo directory.

Report facts: per format, owner, tests found, pending status; per demo, the claims it names and the verbs its
commands invoke; the count of released capabilities with and without a demo.

Inputs are files only; nothing is compiled or run. Determinism class D0; findings sorted by (rule, subject).

## Acceptance criteria

- [ ] Seed-level condition used by the M1 format bead: a second parser for a registered extension fails
      `check-contracts`. A scratch copy in which `frob-analyze` contains the literal `"frob.design/1"` and a
      parse function fails with `fmt.second-parser`, naming file and line.
- [ ] The same literal inside `frob-design`, inside a generated table, and inside `frob-lemma` for
      `"frob.cert/1"` does not fail; inside `frob-lemma` for `"frob.design/1"` it does.
- [ ] The literal `"frob.run/1"` in a file of `crates/frob-cert/src/frun/` that carries the marker
      `// frob:auditor-reader` and is listed in the `FMT-FRUN` row does not fail; the same literal in another
      file of `frob-cert`, or under the marker in a file the row does not list, fails with `fmt.second-parser`.
- [ ] Removing `fmt_ftask_roundtrip` from `frob-spec`'s conformance test fails with `fmt.no-roundtrip-test`;
      removing the refusal test fails with `fmt.no-refusal-test`.
- [ ] A `demo.yaml` naming a claim absent from the gate registry fails with `demo.claim-unknown`; a released
      verb with no demo fails with `demo.missing-for-release-path`.
- [ ] A YAML construct outside the subset (an anchor, a flow mapping) is refused with its line and column.
- [ ] On the clean tree at M1 the check reports seven landed format rows with their three tests each and six
      rows pending, and exits 0.
- [ ] The added rules keep `check-contracts` within its 10-second share of the 60-second budget (TARGET).

## Test plan

### Unit tests

`cargo test -p xtask contracts_registry`, on `synthetic` scratch trees with a three-row registry:
- `owner_must_be_in_crate_map`; `pending_owner_is_not_a_finding`.
- `roundtrip_test_required`; `refusal_test_required`; `view_test_required_only_with_view`;
  `fuzz_target_required`.
- `second_parser_literal_schema`; `second_parser_literal_extension`; `owner_is_exempt`;
  `declared_writer_is_exempt_for_its_row_only`; `generated_table_is_exempt`; `routing_marker_is_exempt`;
  `literal_in_comment_is_ignored`.
- `demo_schema_cases`; `demo_optional_keys_admitted` (a demo using every one of the eleven optional keys
  passes; a demo with `expect_exitt` fails `demo.schema` naming the key); `demo_id_must_match_directory`;
  `demo_claim_must_exist`; `demo_command_must_be_frob`; `demo_expectation_shape` (one case per clause of the
  rule);
  `released_verb_needs_demo`; `orphan_checksum`.
- `yaml_subset_accepts_schema_examples`; `yaml_subset_refuses_anchors_and_flow`.

### End-to-end script and logging

`scripts/e2e/format_registry.sh` (bead N34-23) runs `cargo xtask check-contracts --json` on the clean tree and on
a scratch copy with a planted second parser, and logs the command, exit code, wall time, the finding and the
per-format facts in the structured format of STD-E2E. `scripts/e2e/demos.sh` (bead N34-12) runs it before
executing any demo.

### Known answers and negative controls

Known answer: at M1, seven landed rows and six pending. Negative controls: the planted second parser (registered
against GATE-WS-02 in the conformance crate's control registry, because the gate's meaning depends on one reader
per format); the removed round-trip test; the demo with an unknown claim. Live-dependency proof: renaming the
schema in the registry row makes the owner's own literal a finding until the owner is updated, so the search
reads the registry. Determinism: identical reports twice on one machine.

## Considerations

- The search finds parsers that name the schema or the extension. A crate that parses a design without ever
  naming either would escape it; such a crate would also have to receive raw bytes, which the verb layer's
  owner routing prevents (FROB-REF-893, `format-owner-bypass`).
- The naming convention for tests is a contract between this check and every format owner; it is stated in the
  contract template and in each owner's bead.
- The YAML subset keeps `xtask` free of a third-party parser; if demo files need more of YAML, the schema
  changes, not the reader.
- A demo is never a gate. The check refuses a demo whose claim does not exist; it does not look at whether the
  claim's gate has passed, which the status table reports.
