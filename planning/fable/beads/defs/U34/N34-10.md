## Background

Six conventions of the wider suite are adopted by FrankenRobotics. Each replaces an ad hoc habit with something
a tool can check, and each is assigned to one of the six workspace checks so that adopting it adds no seventh:

| Convention | What it says | Where it is carried |
|---|---|---|
| Artifact-graph identifiers | Every gate claim has a `claim_id` that resolves to its evidence, the decision rule in force and the trace of the run | Identifier types in `frob-core` (N34-11); the graph in the telemetry subsystem |
| Contracts as code | Each crate's `contract.toml` states budgets and a safe mode: what the crate does when a budget is exhausted or a calibration check fails, which is always to fall back to its reference path or to refuse by name | `check-contracts` (N34-08) |
| A demo file linked to claims for every release path | No demo, no release; a demo shows a path runs and is never evidence for the claim's numbers | `check-contracts` (N34-09); the demo runner (N34-12) |
| Shadow-run as the adoption wedge | A mechanism that replaces a reference path first runs beside it | **This bead** |
| Two planes | Computation and decision are separate: a kernel can be replayed without the policy that chose to run it, and a policy can be replaced without touching a digest | `check-layers` (rule L-11); the `plane` field of the contract |
| The controller gate | No adaptive controller ships without a replay scenario, evidence records, a calibration report and a demonstrated fallback | **This bead** |

**Shadow-run (DESIGN).** A mechanism that replaces a reference path first runs beside it: both results are
reported and the old one is acted on. It is promoted when its agreement gate passes and demoted by one flag. The
incumbent is always this project's own reference path: full recomputation for the memo graph, one batch per job
for shared batches, the paired e-process for a variance-reduced estimator, the CPU referee for a device tier.
Reason: a faster path that silently replaces a trusted one turns every later disagreement into an argument about
which is right; running both first turns it into a measurement.

**The controller gate (DESIGN).** No adaptive controller ships (a scheduler, an allocator, a racing rule, a
cache policy) without a replay scenario, evidence records, a calibration report and a demonstrated fallback. Two
controllers that read the same telemetry need an interference test before both are enabled. Reason: an adaptive
rule that cannot be replayed cannot be debugged, and two rules tuned alone can oscillate together.

The design does not say which check owns these two conventions. DESIGN of this bead: they are records in each
crate's `contract.toml`, validated by `check-contracts`, plus one small type in `frob-core` so that every shadow
run reports its two results the same way. Tier: Solid.

## Scope

In: the `[[replaces]]` and `[[controller]]` tables of `contract.toml` and their rules in `check-contracts`; the
`Shadowed<T>` type and its envelope rendering in `frob-core`. Out: every mechanism that uses them (the memo
graph, shared batches, variance-reduced estimators, device tiers, the daemon's scheduler, racing, cache
policies), each in its own bead; the agreement gates themselves; the interference tests' content (the
decision-core beads).

## Technical approach

**Contract records** (DESIGN; added to `schemas/contract.schema.json`):

```toml
[[replaces]]
mechanism = "memo-graph"                # a mechanism of this crate
incumbent = "full-recompute"            # one of: full-recompute | one-batch-per-job | paired-e-process | cpu-referee | <named reference path of this crate>
agreement_gate = "GATE-ATEL-11"         # the gate whose pass promotes it
mode = "shadow"                         # off | shadow | promoted
demote_key = "memo.graph"               # the one configuration key that demotes it to the incumbent

[[controller]]
id = "verbs.dispatch.size-classes"
kind = "scheduler"                      # scheduler | allocator | racing-rule | cache-policy | estimator
decision_policy = "tether.dc09.dispatch@v1"       # the versioned rule, in the decision-policy text form
reads = ["queue-depth", "eta-interval"]           # telemetry channels the rule reads
replay = "tests/fixtures/replay/dispatch-01.ndjson"     # a recorded scenario the rule can be re-run on
evidence = "ledger-row"                 # the evidence kind each decision is recorded as
calibration = "<gate identifier>"       # the gate that holds its calibration report
fallback = "fifo"                       # the fixed rule used when calibration fails or the controller is off
interference = [{ with = "opt.race.halving", test = "interference_dispatch_vs_racing" }]
```

**Rules in `check-contracts`:**

1. `conv.replaces-schema`: a `[[replaces]]` row lacks a field or names an unknown mode.
2. `conv.gate-unknown`: `agreement_gate` or `calibration` is not a row of `registries/gates.toml`.
3. `conv.promoted-without-pass`: `mode = "promoted"` while the agreement gate's row is not a recorded pass. The
   row must then be `shadow` (or `off`); promotion is a commit that follows the gate, never precedes it.
4. `conv.demote-key-missing`: the `demote_key` string does not occur in the crate's source as a configuration
   key (a textual scan): a mechanism that cannot be turned off by one key is not demotable.
5. `conv.controller-incomplete`: a `[[controller]]` row lacks `replay`, `evidence`, `calibration` or `fallback`,
   or its `replay` file does not exist, or `decision_policy` is not in the `name@vN` form (checked with the
   parser of `DecisionPolicyId` from N34-11, so the check and the runtime share one grammar).
6. A `[[controller]]` row in a crate of layers 1 to 3 is not reported here: it is rule L-11 (no crate of the
   compute plane holds a scheduler, an allocator, a racing rule, a cache policy or an estimator) and the layer
   check reports it, so that the defect has one owner.
7. `conv.interference-missing`: two controller rows anywhere in the workspace share an entry of `reads`, and
   either lacks an `interference` item naming the other, or the named test function does not exist in the tree.
8. Facts in the report: every mechanism in shadow mode with its gate's status; every controller with its
   fallback; pairs of controllers that share telemetry.

**The runtime shape** (`frob_core::shadow`):

```rust
pub struct Shadowed<T> { pub acted_on: T, pub candidate: Option<T>, pub agreement: Agreement, pub mode: ShadowMode }
pub enum Agreement { NotCompared, Equal, WithinEnvelope { measure: Qty }, Differs { first: DiffRef } }
pub enum ShadowMode { Off, Shadow, Promoted }
```

Rules: in `Shadow` mode `acted_on` is the incumbent's result and `candidate` is the new mechanism's; in
`Promoted` mode `acted_on` is the new mechanism's and the incumbent runs only on the sampled fraction its gate
prescribes; in `Off` mode only the incumbent runs. An envelope that carries a shadowed result prints both values
and the agreement, and its claim product is computed from `acted_on` alone. A `Differs` outcome is written to
the evidence sink with the first differing item; it never changes which result is acted on.

Determinism class D0 for the check; the type adds no behaviour of its own.

## Acceptance criteria

- [ ] A crate whose contract says `mode = "promoted"` for a mechanism whose agreement gate is `not-run` fails
      with `conv.promoted-without-pass`; with the gate recorded as a pass it is accepted.
- [ ] A `[[controller]]` row without a `fallback` fails; one whose `replay` file is missing fails.
- [ ] Two controllers that both read `queue-depth` and do not name each other fail with
      `conv.interference-missing`; after each names the other and the test function exists, the check passes.
- [ ] A `[[controller]]` row in `frob-dyn` (layer 3) fails `check-layers` with the L-11 finding and is not
      reported a second time by `check-contracts`.
- [ ] `Shadowed<T>` in `Shadow` mode acts on the incumbent: a property test over random pairs shows `acted_on`
      equals the incumbent whatever the candidate is.
- [ ] The envelope rendering of a shadowed result contains both values, the agreement and the mode.
- [ ] No seventh check exists; `check-contracts` stays within its time share.

## Test plan

### Unit tests

`cargo test -p xtask contracts_conventions` on `synthetic` contracts and a `synthetic` gate registry:
`replaces_schema_cases`; `promoted_needs_passed_gate`; `demote_key_must_exist_in_source`;
`controller_needs_four_things` (four cases); `decision_policy_grammar` (`tether.dc09.dispatch@v1` passes;
`Tether.dc09@v1`, `a@1` and `a..b@v1` fail with `conv.controller-incomplete`);
`controller_in_compute_plane_is_left_to_the_layer_check`;
`shared_telemetry_needs_interference_test`; `interference_test_function_must_exist`;
`facts_list_shadow_mechanisms`.
`cargo test -p frob-core shadow`: `shadow_acts_on_incumbent` (property); `promoted_acts_on_candidate`;
`off_has_no_candidate`; `differs_does_not_change_action`; `claim_product_uses_acted_on_only`;
`shadow_rendering_has_both_values` (the canonical rendering of a `Shadowed<u32>` in `Shadow` mode with
`acted_on` 3, `candidate` 4 and `Differs` has the four members `acted_on`, `candidate`, `agreement` and `mode`
with those values; in `Off` mode `candidate` is absent).

### End-to-end script and logging

No script of its own: each adopting mechanism's end-to-end script shows the shadow report from the user's side
(for example the memo graph's shadow-recompute script prints both results per query). This bead adds two steps to
`scripts/e2e/workspace_checks.sh` (N34-14, a dependency): a scratch copy with a prematurely promoted mechanism,
and one with two controllers that read `queue-depth` without naming each other, asserting
`conv.promoted-without-pass` and `conv.interference-missing` respectively and that the clean tree has neither.
Each is logged among the extra plants in the structured format of STD-E2E: `ts`, `script`, `bead` (`N34-10`),
`step`, `event`, the command `cargo xtask check-contracts --root <copy> --json`, exit code, wall time, the finding's rule,
crate and file, the digest of the scratch contract, and on failure the expected and returned finding lists and
the scratch path.

### Known answers and negative controls

Known answer: with a gate at `not-run`, the only accepted modes are `off` and `shadow`. Negative controls: the
premature promotion; the controller with no fallback; the unlisted telemetry sharing; a `Shadowed` build that
acts on the candidate in shadow mode, which the property test must catch. Determinism: the check's findings are
identical twice on one machine.

## Considerations

- The assignment of these two conventions to `check-contracts` is this bead's reading; if the owner prefers
  another of the six checks, the records stay and only the reader moves.
- The record cannot prove that a replay scenario is representative or that a fallback was exercised; those are
  claims of the controller's own gate, which the record names. The check guarantees only that the four things
  exist and that promotion follows a recorded pass.
- Telemetry names in `reads` are free strings at this stage; when the telemetry registry lands they are checked
  against it.
- A mechanism with no incumbent (nothing it replaces) has no `[[replaces]]` row; inventing an incumbent to
  satisfy the form would be process for its own sake.
- The decision cores of the studio loop are the largest users of the controller gate; their interference tests
  are theirs, and this check only requires that they exist where telemetry is shared.
