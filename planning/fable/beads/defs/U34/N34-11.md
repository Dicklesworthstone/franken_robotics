## Background

Every claim that crosses the agent boundary must be traceable to what supports it. The convention adopted from
the wider suite is the artifact graph: every gate claim has a `claim_id` that resolves to the `evidence_id`s of
the records supporting it, the `policy_id` of the rule and thresholds in force, and the `trace_id` of the run.
It replaces an ad hoc habit (a sentence in a report that says "passed") with something a tool can check, and it
is assigned to an existing workspace check so that adopting it adds no seventh check.

FACT (read in `asupersync/franken_kernel/src/lib.rs` at the sibling's head on 2026-11-22; to be re-read at the
pin of the asupersync admission gate): `franken-kernel` 0.6.0 defines `TraceId` and `DecisionId` as 128-bit
values printed as 32 lower-case hexadecimal digits; a `TraceId` holds a millisecond Unix timestamp in its high
48 bits and 80 random bits below; `PolicyId` is a dotted name and a version printed `name@vN` (for example
`scheduler.preempt@v3`); `SchemaVersion` prints `major.minor.patch`. It has no claim or evidence identifier
type, and it depends on `serde`.

DESIGN: `frob-core` (layer 0, tier Solid) mirrors the text form of the three identifiers the sibling has
(`TraceId`, `DecisionId`, and `PolicyId` under the name `DecisionPolicyId`), adds `ClaimId` and `EvidenceId` in
the same style, and proposes them upstream. Four of these are the nodes and labels of the artifact graph;
`DecisionId` is mirrored for its text form only and is no graph node (see step 4b). The sibling crate is **not linked**
into `frob-core`, which admits no `serde`; it is a pattern and, in the conformance crate, a round-trip oracle.
Naming: the sibling's `PolicyId` names a decision rule, while this project's `PolicyId` names a control policy by
content hash. The decision-rule identifier is therefore called `DecisionPolicyId` everywhere here.

Rejected alternatives: (1) import the sibling's types (brings `serde` into layer 0 and couples layer 0 to the
async runtime's repository); (2) use ledger sequence numbers as evidence identifiers (they differ between two
executions of the same work, so two runs of one experiment would not agree on what the evidence is).

## Scope

In: the four types, their construction rules, text forms and parsers in `frob_core::graph_id`; the text-form
mirror of the sibling's `DecisionId`; the canonical pre-images that make `ClaimId` and `EvidenceId`
unambiguous; the upstream posture.
Out: the artifact graph itself, its storage, `frob evidence trace` and the closure rule (BD-095, which depends
on this bead, uses these pre-images and text forms unchanged, and adds only what it passes as a payload hash
and how it builds a statement from a structured result); the decision on OPEN-CHRON-3 between these local types
and an import, with its criteria, its byte-level compatibility test and its record (N29b-09, which depends on
this bead; this bead implements the default); the gate registry rows that carry claim identifiers (BD-002); the
check that a demo's claims exist in the gate registry (N34-09); the upstream change in the sibling repository
(the upstream bead for FD-FKER-01). This bead is the one definition of the four types: where BD-095 or N29b-09
restate a form, this bead's text governs.

## Technical approach

```rust
// DESIGN sketch: fixes intent, not signatures.
pub struct ClaimId(Blake3);        // BLAKE3(claim type ‖ subject identities ‖ statement ‖ scope)
pub struct EvidenceId(Blake3);     // BLAKE3(kind ‖ payload hash)
pub struct DecisionPolicyId { name: DottedName, version: u32 }   // a decision rule, not a control policy
pub struct TraceId(u128);          // time-ordered identifier of the execution that produced an item
```

1. **`ClaimId`.** The concatenation in the definition is made unambiguous by hashing a canonical JSON object
   (written by the canonical writer, never a library map) under the schema name `frob.claim/1`:
   `{"scope": <scope>, "statement": "<text>", "subjects": ["<identity>", …], "type": "<one of the seven claims>"}`,
   where `type` is one of the tokens `proof`, `known-answer`, `parity`, `fidelity`, `design-comparison`,
   `reality`, `performance` (DESIGN: the lower-case hyphenated names of the seven claim kinds, the spelling
   BD-095 records), `subjects` is the sorted list of the identities the claim is about (design, model, scene, task, study,
   bundle), `statement` is the claim's sentence in its permitted wording with numbers as exact strings, and
   `scope` carries the design family, world family, quantifier order, horizon and validity region. Two
   executions that establish the same statement about the same subjects in the same scope produce the same
   `ClaimId`.
2. **`EvidenceId`.** The identity of `{"kind": "<kind>", "payload": "<hash>"}` under `frob.evidence/1`. Kinds, a
   closed list: `episode-set`, `chunk-range`, `snapshot`, `certificate`, `receipt`, `ledger-row`,
   `analysis-result`. The payload hash is the identity or blob hash of the item.
3. **`DecisionPolicyId`.** A dotted lower-case name and a version, printed `name@vN`, for example
   `atelier.dc01.promote@v3`. The version is incremented when the rule's logic or thresholds change.
4. **`TraceId`.** 128 bits: the high 48 bits are a millisecond Unix timestamp (saturated at 2⁴⁸ − 1), the low 80
   bits come from the job context. Printed as 32 lower-case hexadecimal digits. A trace identifier and a
   wall-clock time identify an execution; they **never enter a content hash**, so two executions of the same
   work produce the same evidence identifiers and different traces.
4b. **`DecisionId`** (the third identifier of the sibling that §34.12 says to mirror). 128 bits printed as 32
   lower-case hexadecimal digits, the sibling's text form. It names one decision instance (one decision a
   controller or a decision core took). It is an execution identifier like `TraceId`: it never enters a content
   hash, and it is not a node of the artifact graph, whose record of a decision is a ledger row keyed by content
   (N29b-09); such a row may carry the `DecisionId` beside its trace. Its bit layout is the sibling's, read at the
   pin by the oracle test of N33c-27; this bead fixes the text form and the parser, and adds no layout of its own.
5. **Text forms.** `clm:<64 hex>` for a claim, `ev:<64 hex>` for evidence, `name@vN` for a decision policy,
   32 hex digits for a trace and for a decision instance. Parsers accept exactly these forms; upper-case hex, a
   missing prefix or a wrong length is an error, and the parser of one kind rejects the text of another, with
   one stated exception: a `TraceId` and a `DecisionId` share the sibling's text form, so the two are told apart
   by the field that holds them, never by their text. One spelling per identifier: a
   reader that accepted two would give one claim two names. The same holds in JSON: in every JSON view (an
   envelope, a ledger row, a gate row, a bead-log line) each of the four is a string holding its text form. A
   decision policy is the string `"atelier.dc01.promote@v3"`, never an object. DESIGN: the plan has `frob-core`
   mirror the sibling's text form; the sibling's own `serde` form of `PolicyId` is an object with the fields `n`
   and `v` (FACT, same file), and this project does not store it, because the canonical writer, not `serde`,
   writes every stored byte here and a second spelling would break the rule above. N29b-09 records the same
   choice. A dotted name is one or more lower-case ASCII segments separated by `.`; an empty segment, an
   upper-case letter or white space is an error.
6. **Edges the types serve** (the graph is stored elsewhere): claim —supported-by→ evidence; claim —decided-by→
   decision policy; evidence —produced-by→ trace; evidence —derived-from→ evidence; claim —depends-on→ claim
   (the weakest input bounds the claim). Rows of `registries/gates.toml` carry their `claim_id`.
7. **Upstream posture.** FD-FKER-01 (repository: asupersync, crate franken-kernel; priority P3): add claim and
   evidence identifier types beside the existing three. The work is done in the sibling's repository under its
   own rules. Interim posture: these local types. Switch-over rule: replace the local types once the sibling's
   types exist, the admission gate has been re-run, and the oracle test of N33c-27
   (`franken_kernel_text_forms_agree`) shows equal text forms; no milestone waits on it.

Determinism class D0 for claim, evidence and decision-policy identifiers; a trace identifier is not
deterministic by design and is excluded from every digest.

## Acceptance criteria

- [ ] `ClaimId` of two claims that differ only in quantifier order differ; of two claims with the same four
      parts and subjects listed in different orders, they are equal.
- [ ] `EvidenceId` over an unknown kind is a typed error.
- [ ] No function of the crate accepts a `TraceId` or a timestamp as input to `identity` (a `compile_fail`
      doctest attempts it through the canonical-writer trait, which `TraceId` does not implement).
- [ ] Print-then-parse is the identity for all four types and for `DecisionId`; the parser rejects `CLM:…`,
      `c:…`, 63 digits and upper-case hex.
- [ ] `DecisionId` cannot be passed to `identity` (the same `compile_fail` doctest as `TraceId`).
- [ ] `DecisionPolicyId::new("atelier.dc01.promote", 3)` prints `atelier.dc01.promote@v3`.
- [ ] `frob-core` still has no `serde` in `cargo tree`.

## Test plan

### Unit tests

`cargo test -p frob-core graph_id`:
- `claim_id_ignores_subject_order`; `claim_id_changes_with_scope`; `claim_id_changes_with_quantifier_order`;
  `claim_id_changes_with_claim_type` (a Parity claim and a Reality claim about the same sentence differ).
- `evidence_id_kinds_closed`: the seven kinds accepted, `"log"` refused.
- `trace_id_layout`: `from_parts(1_700_000_000_000, 0xABCD_EF01_2345_6789_AB)` has the timestamp in the high 48
  bits and the random value in the low 80; a timestamp of 2⁴⁸ saturates and does not spill into the random bits;
  a timestamp of 2⁴⁸ + 5 stores 2⁴⁸ − 1 and leaves the random field intact.
- `trace_id_text`: 32 lower-case hex digits; round trip.
- `decision_id_text`: 32 lower-case hex digits; round trip; upper case and 31 digits refused; the same text
  parses as a `TraceId` too (asserted, so the stated exception of step 5 is a tested fact, not an accident).
- `policy_text`: `scheduler.preempt@v3` parses to name `scheduler.preempt`, version 3; `a@3`, `a@v`, `@v1` fail.
- `policy_json_is_text_form`: the canonical writer emits `("atelier.dc01.promote", 3)` as the JSON string
  `"atelier.dc01.promote@v3"`.
- `dotted_name_grammar`: `a.b` and `atelier.dc01.promote` accepted; an empty segment, upper case and white
  space refused.
- `claim_and_evidence_text_forms`: `clm:` and `ev:` prefixes with 64 hex digits; a `clm:` text is rejected by the
  `EvidenceId` parser and the reverse; `c:` is rejected as a claim.
- `two_executions_same_evidence_id`: the same payload hash and kind under two different traces give one
  `EvidenceId`.

The oracle against the sibling is not this bead's test, because this bead's crate may not link the sibling and
the edge to `franken-kernel` has one owner: `franken_kernel_text_forms_agree` is N33c-27's test, in
`crates/frob-conformance/tests/ids_oracle.rs` (N33c-27 depends on this bead, and on BD-025 and N33c-09 for the
conformance crate and the dev-only edge). It parses this crate's printed `TraceId`, `DecisionId` and
`DecisionPolicyId` with the sibling's parsers and the reverse, on 10⁴ seeded values. FACT (same file, same
date): the sibling implements a text parser (`FromStr`) for `TraceId`, `DecisionId` and `SchemaVersion` and none
for `PolicyId`; for the decision policy that test therefore compares the two printed forms and parses the
sibling's print with this crate's parser. The decision bead N29b-09 extends that test file with the byte-level
layout assertions it needs (construction from parts, saturation, ordering). This bead's part of the agreement is
that its printers and parsers are the ones the oracle calls; `frob-core`'s dependency tree stays free of
`serde`.

### End-to-end script and logging

No script of its own. The identifiers appear in every structured log line of every end-to-end script (the
`evidence` block and `claim_ids`), and the artifact-graph script of the Chronicle unit resolves them. This bead's
evidence is the unit-test transcript; the oracle's output is N33c-27's.

### Known answers and negative controls

Known answers: the text forms above; the `TraceId` layout from the sibling's own documented example. Negative
controls: a build in which the trace identifier is appended to the evidence pre-image makes
`two_executions_same_evidence_id` fail; a parser that accepts both `c:` and `clm:` fails the single-spelling
test. Determinism lanes: twice on one machine, debug and release, Linux and macOS for the three content-derived
identifiers (D0).

## Considerations

- OPEN-CHRON-3 (whether identifier types are imported from the sibling under the single-version rule or defined
  locally with the same layout): fail-closed default is local definition in `frob-core`. This bead implements
  the default.
- A claim identifier is only as stable as the statement's wording. The permitted wordings per claim kind are
  fixed (for example "recovers ⟨KA identifier⟩ within ⟨tolerance⟩" for a Known answer), and numbers inside a
  statement are exact strings, so that formatting cannot split one claim into two.
- A claim whose closure contains a dangling or tombstoned node cannot be cited (FROB-REF-869); that rule lives
  with the graph, not with these types.
- Privacy: identifiers are hashes; a statement about a private scene is hashed, not stored, by these types.
