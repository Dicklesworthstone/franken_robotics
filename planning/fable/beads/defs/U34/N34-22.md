## Background

FrankenRobotics has thirteen artifact formats, each owned by one crate. An artifact's identity is the hash of
its canonical bytes, so a format is only as trustworthy as three properties of its owner's reader and writer:
reading and writing again changes no byte; a view (such as the S-expression text of a design) converts to the
canonical form and back without loss; and no change to the bytes can leave the identity unchanged while still
being accepted. The gate that states this with numbers is:

**GATE-WS-02** (TARGET; claim Known answer; first due at M1 for the formats that exist, then at each new format;
complete at M5). For each of the thirteen formats: 10,000 seeded round trips canonical → value → canonical with
zero byte differences; where a view exists, 10,000 round trips view → canonical → view with zero differences;
every one of 10,000 single-byte mutations either fails to parse or changes the identity; and each reader
survives 10⁷ fuzz executions with zero panics before the format's first release. Negative control: a reader
built with key-order canonicalization disabled must fail the first clause.

Thirteen owners writing thirteen versions of these tests would test thirteen slightly different properties.
This bead writes the four clauses once, as a generic harness that every owner plugs its format into, and the
battery that runs them for all landed formats and records the gate's rows. Tier: Solid.

A subtlety decides the harness's design. If the first clause only compared the candidate's writer with itself
(`write(read(write(v))) = write(v)`), a writer that never sorted keys would pass, because it is self-consistent.
The stated negative control must fail, so the clause needs a second opinion on what canonical means: a small
**reference canonicalizer**, written independently of the canonical writer, that the candidate's bytes must be a
fixed point of.

## Scope

In: `frob_core::testkit::format` (the generic clause functions, the reference canonicalizer, the respeller, the
mutator, a deterministic mutational fuzzer), behind the dev-only `testkit` feature; the `formats` battery in the
conformance crate; the negative-control build. Out: each owner's value generator and format implementation (the
owners; the rows are assembled by BD-141 and BD-410); the user-side script (N34-23); coverage-guided fuzzing with
an external engine (the importer-fuzzing bead decides whether one is admitted; its targets reuse the names used
here).

## Technical approach

**What an owner supplies** (in its `tests/conformance.rs`):

```rust
impl testkit::format::Subject for DesignFormat {          // DESIGN sketch
    type Fmt = DesignFormat;                              // implements ArtifactFormat
    fn generate(rng: &mut SeededRng, size: u32) -> <Self::Fmt as ArtifactFormat>::Value;   // valid values only
    fn view() -> Option<&'static dyn ViewCodec<Self::Fmt>> { Some(&SEXPR) }                 // None if no view
}
#[test] fn fmt_fbot_roundtrip()      { testkit::format::roundtrip::<DesignFormat>(SEED, 10_000).assert_clean(); }
#[test] fn fmt_fbot_view_roundtrip() { testkit::format::view_roundtrip::<DesignFormat>(SEED, 10_000).assert_clean(); }
#[test] fn fmt_fbot_refusals()       { testkit::format::refusals::<DesignFormat>().assert_clean(); }
```

The generator must reach every field of the schema (the harness counts which schema fields appeared across the
run and fails if a field of the generated schema file never did), and must be a pure function of the seed.

**Clause 1, round trip** (`roundtrip(seed, n)`), for i in 0..n:
1. v = generate(seed, i); b₀ = write(v).
2. Fixed point of the reference canonicalizer: `reference(b₀) == b₀`. The reference canonicalizer parses b₀ into
   a plain tree with its own parser and re-serializes with keys sorted by code point, the minimal escapes
   (`\"`, `\\`, `\u00XX` in lower-case hex below code point 32) and number lexemes unchanged. It shares no code
   with the canonical writer.
3. v₁ = read(b₀); b₁ = write(v₁); assert b₁ == b₀ byte for byte and `id(b₁) == id(b₀)`.
4. Respelling: b′ = respell(b₀, rng) permutes member order, inserts white space and replaces characters by
   equivalent escapes; `write(read_view(b′)) == b₀`.
5. `assert_no_machine_path(b₀)`; for a format with binary64 fields, the owner's stated float rule holds
   (each such lexeme is the shortest round-trip spelling, or the field is an exact string).
The report gives n, byte differences (threshold 0), the first failing index with its seed, and field coverage.

**Clause 2, view round trip** (`view_roundtrip`), for i in 0..n: t₀ = view.print(v); v₁ = view.parse(t₀);
assert `write(v₁) == write(v)` (the view reaches the same canonical bytes) and `view.print(v₁) == t₀` (view →
canonical → view with zero differences).

**Clause 3, mutations** (`mutations(seed, n)`), for i in 0..n: pick a generated artifact b₀ and a position p;
replace the byte at p by a different seeded value to get b′; call the strict identity-bearing read path (the
bytes are claimed canonical, as when an artifact is fetched by its identity). The outcome must be a refusal, or
an accepted value whose identity differs from `id(b₀)`. "Accepted with the same identity" is a failure, reported
with p, both bytes and the artifact. (A respelled-but-equivalent byte string is refused on this path as not
canonical; that is what makes the clause provable.)

**Clause 4, fuzz** (`fuzz(target, corpus, seed, executions)`): a deterministic mutational fuzzer seeded from a
corpus of generated artifacts and the registry's own examples: byte flips, insertions, deletions, splices,
dictionary tokens from the schema's field names, and structure-aware edits on the parsed tree. Each execution
calls the reader inside a panic boundary; a panic, a hang beyond a per-input step budget, or an accepted input
whose re-serialization does not re-read equal is a failure, saved with its seed and index. Being seeded, a count
of 10⁷ is exact and a failure reproduces from two integers. The commit lane runs 10⁵ executions per format; the
gate lane runs 10⁷.

**Refusal cases** (`refusals::<F>()`): an unknown major version; one unknown field at top level and one nested;
a duplicate member; a view offered to the identity-bearing path. Each must refuse with the owner's stated code.

**The battery** (`frob-conformance`): clauses 1 to 3 are rows of the metamorphic tier's test target and clause
4 is a row of the chaos tier's, both selected by the gate's identifier. For each registry row whose owner has
landed, run the four clauses at gate sizes, then rebuild the canonical writer as N34-18's `writer-no-key-sort`
mutant (N34-CX's plant 1 of CX-358, `N34-18:writer-no-key-sort`), by the suite's one mutation mechanism
(`--features gauntlet-mutations,frob-core/writer-no-key-sort`, the feature named by its plant, BD-025, whose
control record the seeding tool of N38b-05 derives from that plant;
DESIGN correction of an earlier `--cfg frob_nc="no-key-sort"` compiler flag, which N34-CX rule 4 replaces), and
assert that clause 1 **fails** for that format (the negative control). It writes one
record per format: counts, differences, fuzz executions, panics, the control's outcome, seed, commit, receipt.
A format's row of the gate is a pass only if all four clauses are clean and the control was caught.

Determinism class D0: every clause is a function of (format, seed, n). Evidence class of the records: Tested.

## Acceptance criteria

- [ ] The toy format of the harness's own tests passes all four clauses at n = 10,000 and 10⁵ fuzz executions.
- [ ] Built with N34-18's `writer-no-key-sort` mutant (`--features gauntlet-mutations,frob-core/writer-no-key-sort`),
      clause 1 fails on the toy format at step 2 (negative control caught); a toy writer that is self-consistent
      but unsorted is thereby rejected. No `--cfg frob_nc` flag exists in the tree.
- [ ] A toy reader that ignores an unknown field (the shape of N34-CX's CX-361 plant `reader-ignores-unknown`,
      whose mutation on a real owner reader BD-141 plants) fails clause 3 (a mutation of that field's name is
      accepted with an unchanged identity) and the refusal cases.
- [ ] A toy reader that tolerates `\u000A` for `\u000a` on the identity-bearing path fails clause 3.
- [ ] A toy view codec that drops a comment-like token fails clause 2 at the second assertion.
- [ ] A generator that never emits one schema field fails the field-coverage check.
- [ ] A planted panic at fuzz execution 54,321 is found, and re-running with the reported seed and index
      reproduces it on the first execution.
- [ ] The battery's record for a format contains every number the gate's row needs, and none of the harness's
      code is present in a build without the `testkit` feature.

## Test plan

### Unit tests

`cargo test -p frob-core --features testkit testkit::format` on a `synthetic` toy format (`frob.toy/1`, with a
nested object, an array, a quantity string, an int53, a `u64str`, a binary64 and a text view):
`reference_canonicalizer_is_independent` (it is tested against hand-written canonical strings, not against the
writer); `roundtrip_clean`; `roundtrip_fails_without_key_sort`; `respell_preserves_identity`;
`view_roundtrip_clean`; `lossy_view_fails`; `mutations_clean`; `ignored_field_fails_mutations`;
`equivalent_escape_fails_mutations`; `fuzz_is_reproducible`; `fuzz_finds_planted_panic`;
`field_coverage_enforced`; `machine_path_detected`.

### End-to-end script and logging

`scripts/e2e/format_registry.sh` (bead N34-23) invokes the battery as the conformance crate's test targets
(`FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g3_metamorphic -- GATE-WS-02` and the same with
`--test g4_chaos`, then the control with `--features gauntlet-mutations`, to which the control runner adds
`frob-core/writer-no-key-sort`; the conformance
harness has no agent verb and no `xtask` subcommand, by design, ADR-GAUNT-01) and logs one `metric` line per format and clause: n,
differences against the threshold 0, fuzz executions against 10⁷, panics against 0, the negative control's
outcome, the seed, and on failure the first failing index and the saved artifact path, in the structured format
of STD-E2E.

### Known answers and negative controls

KA-781 (one identity for `{"b":1,"a":2}` and `{"a":2,"b":1}`: the respelling step). KA-782 (for each of the
thirteen formats: 10,000 seeded round trips canonical → value → canonical; where a view exists, 10,000 round
trips view → canonical → view; 10,000 single-byte mutations; truth: zero byte differences in both directions,
every mutation either fails to parse or changes the identity, each reader survives 10⁷ fuzz executions with zero
panics; tolerance exact; tier G3 on the host; negative control: key-order canonicalization disabled).
Counterexamples protected: CX-358, CX-360, CX-361. Metamorphic relations used: respelling preserves identity;
any accepted single-byte change alters identity; view and canonical commute. Negative controls are builds or
inputs in which the property was removed (no key sort; an ignored field; a tolerant escape), never boundary
cases; by N34-CX's plant identifiers they are `writer-no-key-sort` (CX-358) and the toy form of
`reader-ignores-unknown` (CX-361). Determinism lanes: twice on one machine; debug and release; Linux and macOS;
identical reports.

## Considerations

- The fuzzer is deliberately in-house and seeded: reproducible counts, no third-party engine in the core graph.
  It has no coverage feedback, so it is weaker at finding deep paths; the structure-aware edits and the schema
  dictionary compensate in part. If an external coverage-guided engine is admitted for the importers, the
  format targets run there as well and this harness stays the gate's counted lane.
- 10⁷ executions per format is minutes of CPU per format on small inputs and fits the default machine envelope;
  the battery runs formats in sequence and under the envelope guard.
- A generator that produces only small or shallow values makes the gate easy; field coverage is the minimum
  defence, and each owner's bead states its generator's size distribution.
- The reference canonicalizer is a third implementation of the canonical form (after the writer and the
  auditor's); it must stay small enough to read in one sitting, and a change to the canonical form touches all
  three.
