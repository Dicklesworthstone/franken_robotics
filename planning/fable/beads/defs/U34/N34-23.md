## Background

FrankenRobotics has thirteen artifact formats in one registry. Each has one owner crate and one canonical
encoding; an artifact's identity is the hash of its canonical bytes under its schema name; a view is never an
identity. The in-crate harness proves those properties for each owner's reader and writer with seeded round
trips, mutations and fuzzing. This bead is the other half: the end-to-end script that shows the same properties
from the user's side, through the `frob` binary and the MCP server, for every format that has landed, and that
assembles the gate's record.

**GATE-WS-02** (TARGET; claim Known answer; M1 for the formats that exist, then at each new format; complete at
M5): for each of the thirteen formats, 10,000 seeded round trips canonical → value → canonical with zero byte
differences; where a view exists, 10,000 round trips view → canonical → view with zero differences; every one of
10,000 single-byte mutations either fails to parse or changes the identity; and each reader survives 10⁷ fuzz
executions with zero panics before the format's first release. Negative control: a reader built with key-order
canonicalization disabled must fail the first clause.

Why a user-side script as well as a harness: the harness calls readers directly. An agent never does. Between
the agent and the reader sit raw-byte admission, routing by extension, the envelope and the store, and a format
is only as sound as that whole path. Tier: Solid. This is a test bead and builds no mechanism.

## Scope

In: `scripts/e2e/format_registry.sh`; its per-format table of verbs; the gate record for the landed formats.
Out: the harness and the gate-lane tests it invokes (N34-22, BD-141, BD-410); the mechanisms under test.

## Technical approach

The script is plain shell, sources the shared helper of STD-E2E and the envelope guard, takes `--seed` (default
34), `--formats <list>` (default: every registry row whose owner has landed) and `--lane commit|gate`, works in
an empty scratch store, is idempotent, and exits non-zero on any failed assertion.

Per-format verbs (data in the script; a format is skipped, and logged as pending, until its row's verbs exist):

| Format | Milestone | Read and bind an identity with | Write a fixture with |
|---|---|---|---|
| `.fbot` | M1 | `frob design show`, `frob design check` | `frob design new` from a template |
| `.fmodule` | M1 | `frob module show`, `frob module check` | The built-in module catalog |
| `.fcard` | M1 | `frob actuator show`, `frob actuator check` | The generic card catalog |
| `.ftask` | M1 | `frob task show`, `frob task check` | `frob task new` |
| `.fmission` | M1 | `frob mission check`, `frob mission show` | `frob mission new` |
| `.frun` | M1 | `frob run show` | A two-second referee run of a built-in model |
| `.frobcert` | M1 | `frob prove verify`, and the standalone `frob-verify` | `frob prove bundle` on a fixture claim |
| `.fscene`, `.fclear`, `.fmcw`, `.fskill`, `.fenergy`, `.fbuild` | M2 to M5 | Each owner's show or check verb | Each owner's generating verb |

Steps, for each landed format F:

1. **Schema.** `frob schema <schema name> --json` returns the generated schema; its digest equals the file under
   `schemas/`.
2. **Fixture.** Produce one real artifact with the writing verb; export its canonical bytes with
   `frob artifact export`; record its identity from the envelope's `bound` field.
3. **Identity from canonical bytes.** Read the exported file back with the reading verb: same identity.
4. **Respelling.** Produce three respellings with a small filter (reverse the member order, pretty-print,
   escape one ASCII letter in a member name); each reads back to the same identity (the rule that
   `{"b":1,"a":2}` and `{"a":2,"b":1}` have one identity, on a real artifact).
5. **View** (formats with a lossless view; the design at M1): `frob design view --as sexpr`, then `--as json` on
   the result: the bytes equal the canonical export and the identity is unchanged. For export views (the run's
   array files and summaries): the envelope of the exporting verb carries no identity for the view, and offering
   the view file back to the reading verb is refused.
6. **Mutations.** 200 seeded single-byte replacements of the canonical file; each either refuses (exit 3) or
   binds a different identity. "Accepted with the same identity" fails the script and saves the mutant.
7. **Registry refusals**, on the CLI and repeated through `frob-mcp` over stdio:
   - the `schema` member's major version raised by one → the version refusal (FROB-REF-891, or the owner's own
     version code where its chapter defines one);
   - one unknown member added at top level → refused, with a pointer to the member;
   - a view or a respelled file given to an identity-required parameter (for example the statement of
     `frob prove bundle`) → FROB-REF-892;
   - the file given to a foreign-file parameter (for example `frob design import --format urdf`) → FROB-REF-893.
   Each refusal: exit 3, the expected code, ranked repairs present, no job created, equal fields on both
   surfaces.
8. **Export provenance.** The envelope of `frob artifact export` for F carries the `authorization` object with
   three fields, all `false`, the schema name and the stack receipt of the binary; the exported manifest
   contains no path of the writing machine (a scan for a leading slash, a home directory or a drive letter in
   string values).
9. **Static rule.** `cargo xtask check-contracts --json` is clean; on a scratch copy with a planted second
   parser for F's extension it fails with `fmt.second-parser`. Once per run, not per format (the rule of the
   decision bead N34-27, a dependency): in a scratch copy of `registries/`, a verb row gains a `params` entry
   `artifact-input<frob.example/1>`, a schema no format row has; `cargo xtask check-contracts --root <copy>
   --json` exits 2 with `fmt.param-without-row` naming the verb and the schema; the entry is removed and the
   check exits 0. Both runs are logged as `cmd` and `assert` lines with the finding's file and line.
10. **Gate lane** (`--lane gate`): run the conformance crate's test targets selected by the gate, through the
    harness helper `e2e_tier`, which logs each run's receipt hash
    (`FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g3_metamorphic -- GATE-WS-02` for round trips,
    views and mutations at 10,000 each; `--test g4_chaos -- GATE-WS-02` for 10⁷ fuzz executions per reader;
    ADR-GAUNT-01, no `frob` verb runs the harness), then the controls registered for GATE-WS-02 in the
    control registry, named by N34-CX's plant identifiers, each planted by the suite's mutation mechanism
    (`--features gauntlet-mutations,<crate>/nc-<nnnn>`, N38b-04) or as a fixture, and each required to be
    caught:
    - `writer-no-key-sort` (CX-358; N34-18's mutant of the canonical writer, `frob-core/nc-<nnnn>`): the tier
      target is rerun and the first clause must fail for every format;
    - `reader-ignores-unknown` (CX-361; BD-141's mutant of the `.fbot` reader, `frob-design/nc-<nnnn>`): the
      mutation clause must report an accepted change with an unchanged identity;
    - `view-has-identity` (CX-360; N34-19's plant on the `View` type): its compile-fail test must fail, because
      the code now compiles;
    - `view-converted-silently` (CX-360; N34-24's mutant, `frob-verbs/nc-<nnnn>`): a debug `frob` built with the
      plant is run through the FROB-REF-892 case of step 7, which must fail (the view is accepted);
    - `debug-render-identity` (CX-359; BD-141's planted row of the release identities): the comparison must
      fail on that row.
    For each control the script logs its plant identifier, its `NC-` record, its catalogue seed, whether it
    was caught and the gate. Collect one record per format.
11. **Gate line.** Per format: the four clause results against their thresholds and the controls' outcomes;
    overall: formats passed of formats landed, and of thirteen. The gate is complete only at thirteen of
    thirteen. The line is a log line. The script writes no row of `registries/gates.toml`: the recording
    session enters the gate's part for the milestone from the receipts of the tier runs, with
    `cargo run -p frob-conformance --example record_gate -- --gate GATE-WS-02 --receipt <hash> --part <milestone>`
    (BD-141 at M1, the format beads N34p1-01 to N34p1-03 at M2 to M4, BD-410 at M5).

Logging (STD-E2E format) to `target/e2e-logs/format_registry/<utc>.ndjson` with a transcript: `cmd` lines with
exact command line, exit code and wall time; `assert` lines with format, step, expected and observed identity or
refusal code, and on failure the first differing value and the saved artifact path; `metric` lines for clause
counts with thresholds (differences 0; executions 10⁷; panics 0); the envelope's `evidence` block; digests of
every exported artifact; a `summary` line with assertions passed and failed and the gate touched. Fixtures are
built-in or generated; no private scene is read.

## Acceptance criteria

- [ ] At M1 the script passes steps 1 to 9 for the seven landed formats and logs six formats as pending.
- [ ] `--lane gate` records, for each landed format: 10,000 round trips with 0 byte differences; view round
      trips with 0 differences where a lossless view exists; 10,000 mutations with 0 accepted-unchanged; 10⁷ fuzz
      executions with 0 panics; the negative control caught.
- [ ] For every landed format the three registry refusals and the unknown-member refusal are returned with the
      expected codes on both surfaces, with no job created.
- [ ] Every export carries the three flags, all false, the schema name and a stack receipt hash; no exported
      manifest contains a machine path.
- [ ] The planted second parser is caught by `check-contracts` (`fmt.second-parser`), and the planted verb
      parameter naming an unregistered schema is caught with `fmt.param-without-row` naming the verb and the
      schema; after each plant is removed the check exits 0.
- [ ] The gate line reports "n of 13" truthfully: 7 of 13 at M1; the registry row is a pass only at 13 of 13.
- [ ] A rerun with the same seed gives the same identities, the same mutation outcomes and the same refusals.

## Test plan

### Unit tests

`scripts/e2e/tests/format_registry_selftest.sh`: runs the script's filters and parsers on recorded envelopes
(one accepted, one of each refusal, kept as fixtures): the respelling filter produces three distinct byte
strings that an independent canonicalizer maps to the original; the mutation driver is reproducible from its
seed; the machine-path scan flags `/Users/x/a.bin` and passes a blob reference; the gate-line assembler prints
"7 of 13" for seven clean records and refuses to print a pass for the gate.

### End-to-end script and logging

This bead is the script, as specified. Invocation: `scripts/e2e/format_registry.sh --seed 34` in the commit
lane; `--lane gate` at a milestone exit and before a format's first release.

### Known answers and negative controls

KA-781 (one identity for the two key orders), realized in step 4 on real artifacts. KA-782 (the gate's four
numbers per format; exact; tier G3 on the host; control: key-order canonicalization disabled). Counterexamples
exercised from the user's side: CX-358 (hash the file as written: step 4), CX-360 (the view is lossless, so hash
either form: step 5 and FROB-REF-892), CX-361 (tolerate unknown fields: step 7). Negative controls, by N34-CX's
plant identifiers: the `writer-no-key-sort` build; `reader-ignores-unknown`; `view-has-identity`; the planted
fixture row `debug-render-identity`; the planted second parser; the planted verb parameter without a format
row; a `frob` build whose identity-required path converts views
silently (`view-converted-silently`; must fail step 7); an artifact edited so that one authorization flag is `true` (must be refused on
read; the flags gate of the safety chapter owns that rule and this script only checks exports). Determinism
lanes: the commit lane twice on one machine and on Linux and macOS: identical identities (class D0).

## Considerations

- The gate lane's fuzz clause dominates the cost: about 10⁷ executions per landed format. It stays inside the
  default machine envelope for seven formats; at thirteen it is still minutes per format, run in sequence.
- The script grows a row per format as formats land: `.fscene` at M2 (N34p1-01), `.fclear` and `.fmcw` at M3
  (N34p1-02), `.fskill` and `.fenergy` at M4 (N34p1-03), each adding its row and running `--lane gate` before
  the format's first release; BD-410 adds `.fbuild` and reruns it at thirteen on one commit.
- A format whose owner defines its own version code is checked against that code; the script's table says which
  formats do.
- If the MCP byte-level guard is not available, step 7's MCP half is logged as not run and the gate's surface
  statement is the CLI's; the round-trip clauses are unaffected.
- The script never deletes outside its scratch directory and never reads a sealed or private store.
