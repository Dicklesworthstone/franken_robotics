## Background

An artifact that agents exchange, cite and cache needs an identity that does not depend on who wrote the bytes.
The workspace decision ADR-WS-03 (DESIGN) gives every artifact **format** one identifier, one schema name with
a version, one owner crate and one canonical encoding; everything else is a view, and a view is never hashed,
signed or cited. The format registry (`registries/formats.toml`, types in `frob-core`) holds thirteen rows: a
design (`.fbot`), a module (`.fmodule`), a card (`.fcard`), a scene pack (`.fscene`), a clearance complex
(`.fclear`), a task (`.ftask`), a mission (`.fmission`), an energy budget (`.fenergy`), a skill (`.fskill`), a
minimal counterexample world (`.fmcw`), a run (`.frun`), a build packet (`.fbuild`) and a certificate bundle
(`.frobcert`). The gate GATE-WS-02 (TARGET; Known answer) is stated for the formats that exist at M1, "then at
each new format", and is complete at M5 for all thirteen.

The chapters also define files that carry a schema name and are not among the thirteen. FACT (from the beads
that write them): the replication kit's manifest (the Reality lane; the verb `ground.kit`); the bench protocol
`frob.ground.protocol/1`, a TOML file produced by `frob ground excite` and completed by an operator; the
review record `frob.review/1`, a sidecar addressed by a build packet's manifest digest and imported by
`foundry.check --review-record`; the decision-core table `frob.core-table/1` beside `registries/cores/<id>.toml`;
the study plan `frob.plan/1` and the registration of a method experiment `frob.registration/1`; the resolution
receipt `frob.stack-receipt/1`; the dataset manifest of the Reality lane; the scene edit list
`frob.scene.edit/1`, which `scene.compile` takes by path; the survey document `frob.scene.survey/1`, which
`scene.gen --survey` takes by path; the training overlay `frob.task.overlay/1`, which `task.check --overlay`
takes by path; the group element `frob.group.element/1`, which `task.check --element` takes by path; the study
manifest `frob.study.manifest/1`, which `study.plan` takes by path; the fork-children list
`frob.fork.children/1`, which `run.fork` takes by path; the curriculum grid `frob.scene.grid/1` (`scene.gen
--grid`); the scene recipe `frob.scene.recipe/1` (`scene.gen` and `scene.bank`); the calibration edge record
`frob.sense.calib.edges/1` (`sense.calibrate --edges`); the host fingerprint `frob.fingerprint/1`
(`spark.precompile --target-fingerprint`); the shield's subsystem description `frob.shield.subsystem/1`
(`shield.fit --table`). Some of these are passed to a verb
by path, some are cited by identity from another artifact, and some only ever live inside the store.

OPEN (owner: the project owner, on the proposal of the workspace lead; due at M1, before the first such file
ships; re-read at each milestone exit at which a new schema-named file appears): which of these get a row in
the format registry, with everything a row brings (one owner and one parser, the four clauses of GATE-WS-02,
the version refusal, the owner-routing and view-is-not-identity refusals), and which are **records**: canonical
JSON or TOML with a schema under `schemas/`, written by the canonical writer, but outside the registry. Without
a ruling each unit decides for itself, which is the situation ADR-WS-03 exists to prevent: the Reality and
Foundry beads already state that the registration of their files "is the registry owner's decision".

Rejected alternatives: (1) register every schema-named file (envelopes, receipts and log lines would each need
10,000 round trips, a fuzz target and a single-parser search, and the registry would stop meaning "an artifact
a person hands to another"); (2) freeze the registry at thirteen (a kit manifest or a review record that is
cited by identity and read by two tools would then have no single-parser rule and no version refusal); (3)
leave it to each chapter (two parsers of one file appear exactly where nobody is looking).

Tier: Solid. This bead decides and records; it builds one lint rule.

## Technical approach

**The criterion proposed to the owner (DESIGN).** A schema-named file gets a format row when all three hold:

1. **It crosses the tool boundary as a file**: a user or another tool is expected to hold it, pass it to a
   verb by path, or receive it from an exporting verb.
2. **It bears an identity that something else cites**: an artifact, a claim, a certificate or a ledger row
   refers to the hash of its bytes.
3. **A second reader is plausible**: more than one crate, or a tool outside this repository, has a reason to
   read it.

A file that fails any of the three is a **record**: it is written through the canonical writer of `frob-core`,
its schema is generated into `schemas/`, it obeys the version rule (an unknown major version or an unknown
required field is refused, never parsed on a best-effort basis), and it is exempt from the four clauses of
GATE-WS-02. A record that later comes to satisfy all three becomes a format by a commit that adds its row and
its tests and cites the decision note; nothing is promoted silently.

**Fail-closed default (in force until the ruling, and for any file the ruling does not name).** A schema name
that appears as the format of an artifact parameter of a verb (a `params` entry of kind `artifact-input`,
`artifact-ref` or `artifact-identity` in the verb registry) must have a format row. The contract check gains
one rule in its format group, `fmt.param-without-row`: a verb parameter names a format F that resolves to no
row (F is written and resolved as N34-24 states: a row's identifier, schema name, schema stem or extension). The
owner of such a file therefore enters a row, with its round-trip, refusal and fuzz tests through the shared
harness, before the verb that takes it can be registered. A file that no verb takes by path stays a record
without further ceremony. Reason for this default: it errs toward one parser and tested round trips exactly for
the files that strangers can hand in.

**The record of the ruling.** A decision record, `docs/adr/ADR-WS-06-format-rows.md` (every decision record of
the program lives in `docs/adr/`; DESIGN number: ADR-WS-04 and ADR-WS-05 are the two inversion decisions of
N34x-01 and N16a-01), with the table above as ruled, cited by
`registries/formats.toml` in the field `decision` (the record's path) on every row beyond the thirteenth; a field,
not a comment, because the registry loader discards comments and must be able to refuse a row without the
citation (the field is added to the row schema by N34x-03 and to `FormatRow` by N34-19). The gate record of GATE-WS-02 then
reads "13 of 13 plan formats" and, separately, "k added formats", each with its own measured clauses; the count
of plan formats never changes silently.

**What the ruling changes.** For each file ruled a format: its owner's bead enters the row and wires the
harness; BD-410 lists it in its final run as an added format; the single-parser search covers its schema name
and extension. For each file ruled a record: nothing but the canonical writer, the generated schema and the
version rule apply, and the bead that writes it says so in its Scope.

## Acceptance criteria

- [ ] The decision record `docs/adr/ADR-WS-06-format-rows.md` exists at the M1 exit with the criterion, the
      table and the owner's ruling, or the explicit statement that the fail-closed default stands; it is re-read
      at each later exit.
- [ ] `cargo xtask check-contracts` reports `fmt.param-without-row` on a `synthetic` registry in which a verb
      parameter names `frob.example/1` without a row, and passes when the row and its tests are added.
- [ ] No verb of the committed registry takes by path a schema-named file that has no row.
- [ ] Every row beyond the thirteenth cites the decision note; a row without the citation fails registry load.
- [ ] The decision record names, for each file of the table, the bead that writes it and whether the file is a
      format or a record (printing plan formats and added formats apart in GATE-WS-02's gate line is the
      script's, N34-23, which depends on this bead).

## Test plan

### Unit tests

`cargo test -p xtask contracts_format_params` (the real registry readers; planted registries are TOML strings
labelled `synthetic`): `param_without_row_is_finding`; `param_with_row_passes`; `record_schema_without_param_passes`
(a schema under `schemas/` that no verb takes by path raises nothing); `added_row_needs_decision_citation`
(a fourteenth row without the citation fails to load; with it, it loads). `cargo test -p frob-core format`:
`plan_formats_are_thirteen` (the identifiers of the thirteen are a constant list, and the loader reports added
rows separately).

### End-to-end script and logging

The rule runs inside `scripts/e2e/format_registry.sh` (the user-side script of the format registry, N34-23, which
depends on this bead and carries the step, because a test follows the rule it exercises), which gains one step:
plant a verb parameter that names an unregistered schema in a scratch copy of the registries, run `cargo xtask check-contracts --json`, assert exit 2 with `fmt.param-without-row`, the verb and
the schema name; restore and assert a clean run. Logged in the structured format of STD-E2E to
`target/e2e-logs/format_registry/<utc>.ndjson`: the command line, exit code, wall time, the finding with its
file and line, and a `summary` line counting plan formats and added formats. No private-scene data is read.

### Known answers and negative controls

Known answers: thirteen plan formats; zero verb parameters without a row on the committed tree. Negative
controls: the planted parameter above; a build of the check with the rule disabled, which must let the plant
pass and fail the test; an added row without its decision citation. Determinism: the check is a pure function
of the registries (class D0), equal twice on one machine and across platforms.

## Considerations

- The criterion is a proposal. If the owner rules that every file a stranger can hold is a format regardless
  of citations, the table changes and the default already covers it; if the owner freezes the registry at
  thirteen, the lint rule is withdrawn and each named bead records the risk of a second parser in its own
  Considerations.
- A record is not a lesser artifact: it still has an identity under its schema name and still refuses unknown
  fields. What it lacks is the gate-size round-trip run and the single-parser search.
- TOML as a canonical encoding (the bench protocol) needs a canonical TOML writer, which does not exist; the
  alternative is to keep the operator-facing TOML as a view and make a canonical JSON form the identity. The
  Reality lane's bead decides which when it enters its row.
- Each added format costs its owner the harness wiring and a gate-size run; the decision is taken before M5
  for that reason.
- What would make us revisit: a second reader appearing for a file ruled a record, which the single-parser
  search cannot see because the file has no row; the review at each milestone exit asks for it by name.
