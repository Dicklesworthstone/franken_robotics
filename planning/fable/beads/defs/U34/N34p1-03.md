## Background

FrankenRobotics identifies every artifact by the BLAKE3 hash of its canonical bytes under a domain string equal
to its schema name, and keeps one registry of its thirteen artifact formats (`registries/formats.toml`): one
identifier, one schema name with a major version, one owner crate and one canonical encoding each; everything
else is a view, which is never hashed, signed or cited. Two formats land at M4, both in work package WP-65
(energy budgets and runtime shields, with the skill artifacts of the controller crate):

- The skill artifact `.fskill` (`frob.skill/1`, owner `frob-control`): produced by controller synthesis and by
  `frob-learn`, with network weights held as blobs addressed by hash; consumed by `frob-control`, `frob-learn`,
  `frob-arena` and `frob-shield`. Written and read by `skill.compile`, `skill.check` and `skill.show` (BD-336).
- The energy budget `.fenergy` (`frob.energy/1`, owner `frob-shield`): produced and consumed by `frob-shield`, and
  consumed by `frob-mission` and `frob-lemma`. Written by `shield.budget` (BD-337); the offline auditor recomputes
  it from the file and a run's integer telemetry.

**GATE-WS-02** (TARGET; claim Known answer; M1 for the formats that exist, then at each new format; complete at
M5): for each format, 10,000 seeded round trips canonical → value → canonical with zero byte differences; where a
view exists, 10,000 round trips view → canonical → view with zero differences; every one of 10,000 single-byte
mutations either fails to parse or changes the identity; and each reader survives 10⁷ fuzz executions with zero
panics before the format's first release. Negative control: a reader built with key-order canonicalization
disabled must fail the first clause. Both formats are first released with M4, so their gate lane is due at M4.
Tier: Solid (the subsystems are partly Frontier; the registry rule is not).

## Scope

In: the two rows in final form; each owner's `Subject` and named conformance tests; the weight-blob clause of
`.fskill`; the flags clause of both; the gate-lane run and two records; the two rows of the script's verb table.
Out: the formats themselves (BD-336, BD-337); the harness (N34-22); the script (N34-23); the M2 and M3 formats
(N34p1-01, N34p1-02); the build packet and the thirteen-of-thirteen record (BD-410).

## Technical approach

**Rows and number rules** (registry rule 4; DESIGN defaults proposed here, confirmed or replaced by each owner's
contract; a row without a number rule does not load):

| Format | Number rule | View kind |
|---|---|---|
| `.fskill` | The exact layer's coefficients as reduced rationals `"p/q"` (positive denominator) with a unit token; weights never in the JSON, only as blobs addressed by hash and length | None |
| `.fenergy` | Budgets and bounds as reduced rationals `"p/q"` with units; tick counts and integer telemetry references as decimal strings; no binary64 field bears identity, so the auditor's integer recomputation is exact | None |

**Weight-blob clause** (`.fskill`): the manifest references each weight blob by hash and length; a single-byte
change in a weight blob makes the read refuse with the blob named; a missing blob refuses and is never replaced
by zeros or a default; `assert_no_machine_path` on the manifest (registry rule 5).

**Flags clause** (registry rule 6): a skill carries the three no-authorization fields (`execution_authorized`,
`hardware_safety_signoff`, `sim_to_real_certified`), all `false`, in its file header; an exported `.fenergy`
carries them in the export's `authorization` object; both exports carry the schema name and the writing
binary's stack receipt. A file edited to `true`, or with a field removed, is refused on read (absence is not read
as false).

## Acceptance criteria

- [ ] GATE-WS-02 for `.fskill` and `.fenergy`: 10,000 round trips each with 0 byte differences; 10,000 mutations
      each with 0 accepted-unchanged; 10⁷ fuzz executions each with 0 panics; the key-order control caught;
      recorded before the M4 release.
- [ ] A single-byte change in a weight blob is refused with the blob named; a missing weight blob is refused.
- [ ] Both formats carry their flags, all `false`, with the schema name and a stack receipt hash on export;
      `true` or a removed field is refused.
- [ ] `.fenergy` contains no identity-bearing binary64 value (the schema has no JSON number with a fraction or an
      exponent in an identity-bearing field).
- [ ] Both generators reach every schema field; the script's gate line prints the true count and no pass.
- [ ] `release_identities.toml` holds three rows for each of the two formats with first release `M4`, and
      `fmt_release_identities_hold` passes with them.

## Test plan

### Unit tests

`cargo test -p frob-control --test conformance fmt_fskill`: `fmt_fskill_roundtrip`, `fmt_fskill_refusals`
(unknown major version → FROB-REF-891 or the owner's own code; unknown member at two depths; duplicate member;
a view on the identity path → FROB-REF-892), `fmt_fskill_mutations`, `fmt_fskill_blob_mutation`,
`fmt_fskill_flags`, `fmt_fskill_no_machine_path`. `cargo test -p frob-shield --test conformance fmt_fenergy`:
`fmt_fenergy_roundtrip`, `fmt_fenergy_refusals`, `fmt_fenergy_mutations`, `fmt_fenergy_flags`,
`fmt_fenergy_rationals_reduced` (`"2/4"` is refused as not canonical on the identity path; `"1/2"` is accepted).
Fuzz targets `fmt_fskill_read`, `fmt_fenergy_read` (10⁵ in the commit lane, 10⁷ in the gate lane).

### End-to-end script and logging

`scripts/e2e/format_registry.sh --formats fskill,fenergy` (commit lane) and `--lane gate`, the script's steps 1
to 11 for each format. NDJSON through the STD-E2E helper to `target/e2e-logs/format_registry/<utc>.ndjson`:
`bead: "N34p1-03"`, step, event, exact command line, exit code, wall time, the envelope's `evidence` block, the
artifact identities, `metric` lines per clause with thresholds (differences 0, executions 10⁷, panics 0), the
control's outcome, digests of exported files and blobs, and on failure the first failing index, seed and saved
artifact path; a `summary` line with the count of passed formats of thirteen.

### Known answers and negative controls

KA-781 and KA-782 for both formats (exact; tier G3 on the host). Counterexamples: CX-358, CX-359 (identities
recorded at this first release are compared at M5), CX-360, CX-361. Negative controls: the `writer-no-key-sort`
build (N34-18's mutant, N34-CX's plant 1 of CX-358); a

lane twice on one machine; debug and release; Linux and macOS.

## Considerations

- Weight blobs can be large; the generator uses small seeded weight tensors so that 10⁷ fuzz executions on the
  manifest stay minutes of CPU inside the default machine envelope. Blob mutations are a separate test, not part
  of the fuzz count.
- If the shield subsystem falls back at its kill gate, the `.fenergy` row is recorded under the fallback's name or
  tombstoned by ADR; the count of thirteen changes only by that ADR.
- The auditor's recomputation of a `.fenergy` budget is a check of the shield chapter, not of this gate; this bead
  only guarantees that the bytes it recomputes from are canonical and identity-bearing.
