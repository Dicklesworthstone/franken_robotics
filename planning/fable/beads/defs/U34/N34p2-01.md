## Background

Every file that states a rule of this repository is TOML: the registries under `registries/` (gates, refusals,
verbs, formats, lifts, capsules and the rest), each crate's `contract.toml`, the stack lock `franken-stack.lock`,
`rust-toolchain.toml`, and this repository's own `Cargo.toml` manifests, which the `xtask` checks read for their
`[lints]` table, their `[package.metadata.frob]` table and their dependency tables. Rule L-5 keeps third-party
libraries out of `frob-core` and `xtask` (core runtime dependencies are the standard library and Franken
foundations; `serde` and `serde_json` are admitted at exact pins in six boundary crates only), so the repository
reads all of these with one small reader of its own, in `frob-core`, the lowest layer.

The reader is strict because the failure it prevents is silent: a misspelt key that a lenient reader ignores is a
registry rule that has stopped binding, and a duplicate key is a file with two meanings. Every construct outside
a fixed subset of TOML is therefore an error with a line and a column, and every loader built on the reader
refuses a key it did not consume.

DESIGN (round 2 of the bead polish): the reader was item 5 of the `frob-core` v0 bead (BD-005), and is split out
here because it depends on nothing while BD-005 links two FrankenSim crates (`fs-blake3`, `fs-qty`) by path. The
first-commit generator of the README status table (BD-002), the lift registry (N33a-01), the stack-lock parser
(N33a-03) and BD-005's own refusal-registry loader all need the reader and nothing else of `frob-core`; with the
reader in its own bead they start without waiting on FrankenSim consumption.

Rejected alternatives: (1) the third-party `toml` crate: a dependency in `frob-core` and `xtask` against L-5, and
its `serde` derivation ignores unknown fields unless every type opts out; (2) one reader per consumer: two
readers disagree about a corner of the grammar, and a registry then means one thing to the check and another to
the product.

## Scope

In: the crate `crates/frob-core` as it first exists (manifest with no dependency, `src/lib.rs` declaring only the
`registry` module, no `unsafe`); the module `registry::toml`: the grammar subset, the value tree with source
positions, the error type, the typed-access helpers that make unknown keys an error, the size and depth limits;
its unit, property and corpus tests; `scripts/e2e/toml_reader.sh`.
Out, with the bead that has it: the other modules of `frob-core`, its dependencies on `fs-blake3` and `fs-qty`,
its `CONTRACT.md` and `contract.toml`, and the refusal-registry loader with its exit-family rule (BD-005); the JSON
admission reader (N34-17); the schema and typed model of each file read with this reader (their owner beads: the
registries of the first commit BD-002, the lift registry N33a-01, the stack lock N33a-03, the capsule registry
N34-07, `contract.toml` N34-08, and later registry beads); reading a sibling repository's files, which are not
written inside the subset (the suite survey N33c-07 reads them by its own means and never through this reader).

## Technical approach

**The crate.** `crates/frob-core/Cargo.toml`: `[package] name = "frob-core"`, `publish = false`, the workspace
edition and `[lints] workspace = true`; no `[dependencies]` table. `src/lib.rs` declares `pub mod registry;` and
nothing else. BD-005 adds the remaining modules and dependencies in place. The crate prints nothing (rule L-7)
and contains no `unsafe` code.

**The subset (DESIGN; a strict subset of TOML 1.0, so every file this reader accepts is valid TOML with the same
meaning).**
1. Encoding: UTF-8, no byte-order mark; line ends LF or CRLF (equal results); `#` starts a comment that runs to
   the end of the line, outside strings.
2. Keys: bare keys of `A–Z a–z 0–9 _ -`, and quoted keys written as basic strings. A dotted key on the left of
   `=` (`serde.workspace = true`) is refused; this repository writes `serde = { workspace = true }`.
3. Headers: tables `[a]` and arrays of tables `[[a]]`, each dotted or not (`[package.metadata.frob]`,
   `[json_library.features]`, `[[foundation]]`). Defining a table twice, or a key both as a table and as a
   value, is refused.
4. Values: basic strings `"…"` with the escapes `\" \\ \n \t \r \uXXXX \UXXXXXXXX` (TOML 1.0's other two,
   `\b` and `\f`, are outside the subset; any escape TOML does not have is a syntax error); decimal integers
   with an optional sign, no leading zero, no underscore, in the range of `i64`; `true` and `false`; arrays
   `[…]` (they may span lines, hold comments and end with a comma; all elements of one type, a restriction of
   the subset, since TOML 1.0 allows mixed types); inline tables `{ k = v, … }` on one line, without a trailing
   comma.
5. Refused, each by name: literal strings `'…'`, multi-line strings, floats (including `inf` and `nan`), dates
   and times, hexadecimal, octal and binary integers, underscores in integers, the escapes `\b` and `\f`,
   dotted keys, mixed-type arrays, and anything else outside items 1 to 4.
6. Which error a refusal is (DESIGN; the corpus test below depends on it): a document that TOML 1.0 accepts and
   the subset does not is refused with `OutsideSubset` naming the construct of item 5; a document that TOML 1.0
   itself rejects (a leading zero `007`, an escape such as `\x41`, a trailing comma in an inline table, an
   inline table across lines, a duplicate key, a redefined table) is refused with `Syntax`, `DuplicateKey`,
   `TableRedefined` or another non-subset kind. A valid TOML document is therefore never reported as malformed.

**Value tree.** `enum Value { Str(String), Int(i64), Bool(bool), Array(Vec<Spanned<Value>>), Table(Table) }`;
`Table` maps a key to `Spanned<Value>`, where `Spanned` carries the line and column of the key, so that every
later error, including those raised by a loader, names a position in the file. Arrays of tables keep their
source order; key order inside a table carries no meaning.

**Errors.** `TomlError { line: u32, column: u32, kind: TomlErrorKind }` with the kinds `Syntax(String)`,
`DuplicateKey(String)`, `TableRedefined(String)`, `OutsideSubset(&'static str)` (naming the construct: "dotted
key", "literal string", "multi-line string", "float", "date", "hexadecimal integer", …),
`IntegerOutOfRange`, `InvalidUtf8`, `ByteOrderMark`, `TooLarge`, `TooDeep`, and the loader kinds
`UnknownKey { table, key }`, `MissingKey { table, key }`, `TypeMismatch { key, expected, found }`. Display form:
`<line>:<column>: <message>`; a loader prefixes the file path. Lines and columns count from 1, columns in
Unicode scalar values.

**Typed access, the reason unknown keys are refused.** A loader takes a table into `Fields`, removes each key it
knows with `take`, `require_str`, `require_int`, `require_bool`, `require_array`, `require_table` (each with an
`opt_` form), and ends with `Fields::finish()`, which returns `UnknownKey` for the first key in source order that
was not taken. `Fields` is `#[must_use]`, and dropping it without `finish` in a debug build panics in tests, so a
loader that forgets the call fails its own unit tests.

**Limits (DESIGN).** Input above 16 MiB is refused (`TooLarge`) before parsing; nesting of arrays and inline
tables deeper than 64 is refused (`TooDeep`), so adversarial input cannot exhaust the stack. The reader never
panics: every input returns `Ok` or `Err`.

**API.** `registry::toml::parse(bytes: &[u8]) -> Result<Table, TomlError>`;
`registry::toml::Fields::new(table, table_name)` with the helpers above. A pure function of the bytes
(determinism class D0); it reads no file and no environment variable itself.

**Cost.** The six checks read about fifty manifests and a dozen registries inside their 60-second budget
(GATE-WS-04); the reader parses a 1 MiB file in at most 50 ms in a release build on the development host
(TARGET), measured by the test below.

## Acceptance criteria

- [ ] `cargo test -p frob-core registry::toml` passes, and `cargo tree -p frob-core` at this bead's commit lists
      no dependency.
- [ ] Each construct of the refused list yields its named error at the right line and column (one fixture per
      construct, item 5 above, plus a duplicate key, a redefined table and a mixed-type array).
- [ ] A `synthetic` crate manifest with comments, `[package.metadata.frob]`, `[lints] workspace = true` and
      inline-table dependencies parses to the expected tree; the FD-FSIM and FD-ASUP template rows of
      `franken-stack.lock`, a `[[gate]]` row of `registries/gates.toml` and a `rust-toolchain.toml` parse.
- [ ] A loader built on `Fields` refuses a misspelt key (`psture = "consume"`) with `UnknownKey` naming the key,
      its table and its position.
- [ ] On the vendored `toml-test` corpus, every valid case either parses to the corpus's expected value or is
      refused with `OutsideSubset`, never parsed to a different value, and every invalid case is refused.
- [ ] No input panics: 10⁵ generated and mutated inputs return `Ok` or `Err` within 10 s in total.
- [ ] A 1 MiB `synthetic` registry parses in at most 50 ms in a release build on the development host (TARGET;
      the measured value is printed).

## Test plan

### Unit tests

`cargo test -p frob-core registry::toml` (fixtures are `synthetic` strings in the test module):
- `toml_duplicate_key_is_error`: `a = 1` twice in one table → `DuplicateKey("a")` at line 2, column 1.
- `toml_unknown_key_is_error`: a loader that takes `posture` from `{ psture = "consume" }` → `UnknownKey`
  naming `psture`.
- `toml_outside_subset_is_error_with_position`: `serde.workspace = true` at line 7 → `OutsideSubset("dotted
  key")` at 7:1; `x = 'y'` → "literal string"; `x = 1.5` → "float"; `x = 1979-05-27` → "date"; `x = 0x1F` →
  "hexadecimal integer"; `x = """a"""` → "multi-line string".
- `toml_reads_a_manifest`: the synthetic manifest of the acceptance list → the expected tables, including
  `dependencies.serde = { workspace = true }` as an inline table.
- `toml_reads_stack_lock_template`: the two template rows → two `foundation` entries in source order;
  `build_env.FRANKENSIM_DEPGRAPH_SALT = "franken-robotics-dev-v1"`.
- `toml_reads_a_cargo_lock`: a `synthetic` lockfile with its `@generated` comment, `version = 4` and three
  `[[package]]` tables (one with `dependencies = [...]` over several lines) → three packages with their names.
- `toml_table_redefinition_is_error`: `[a]` twice → `TableRedefined("a")`; `a = 1` then `[a]` → the same.
- `toml_mixed_array_refused`: `x = [1, "a"]` → `OutsideSubset("mixed-type array")` at the second element's
  line and column (valid TOML 1.0, so never `Syntax`).
- `toml_inline_table_rules`: `{ a = 1, }` and an inline table across two lines each refused with `Syntax`
  (both invalid TOML 1.0).
- `toml_escapes`: `"é"` → `é`; `"\b"` → `OutsideSubset("escape \b")`; `"\x41"` → `Syntax`.
- `toml_integer_range`: `9223372036854775807` parses; `9223372036854775808` → `IntegerOutOfRange`; `007` →
  `Syntax`; `1_000` → `OutsideSubset("underscore in integer")`.
- `toml_error_kind_rule`: every refused-list fixture of item 5 yields `OutsideSubset`, and every fixture of
  item 6's TOML-invalid list yields a non-subset kind (the property the corpus test relies on).
- `toml_bom_refused`; `toml_crlf_equals_lf` (the same document with both line ends → equal trees).
- `toml_depth_cap`: 64 nested arrays parse; 65 → `TooDeep`. `toml_size_cap`: 16 MiB + 1 byte → `TooLarge`.
- `fields_finish_required`: a loader that drops `Fields` without `finish` panics in the test build.
- Property `toml_print_parse_roundtrip`: for 10³ generated value trees inside the subset, a printer in the test
  module writes them and `parse` returns the same tree.
- Property `toml_no_panic`: 10⁵ inputs (random bytes, and byte-level mutations of every fixture) each return
  `Ok` or `Err`.
- `toml_parse_speed`: a generated 1 MiB registry (8,192 `[[gate]]` rows) parsed in release mode; the time is
  printed and compared with 50 ms (TARGET; marked `#[ignore]` in debug, run by the script below).

Conformance: `crates/frob-core/tests/toml_corpus.rs` over the `toml-test` corpus (FACT: the public test suite of
the TOML language, `github.com/toml-lang/toml-test`, MIT licence; vendored at a pinned commit under
`crates/frob-core/tests/fixtures/toml-test/` with that commit recorded beside it; to be re-read before the pin is
moved). The run takes the suite's TOML 1.0.0 case list (the suite also carries TOML 1.1 cases, such as inline
tables across lines, that are invalid in 1.0 and refused here as `Syntax`; they are excluded by the suite's own
version selection, and the excluded count is logged). Each valid case: parse and compare with the corpus's
expected JSON, or `OutsideSubset`; each invalid case: an error of any kind.

### End-to-end script and logging

`scripts/e2e/toml_reader.sh` sources the STD-E2E helper and runs, through the build-offload shim, the corpus test
and the speed test in release mode on the real vendored corpus. It calls nothing a later bead delivers: the
reader is first seen from the user's side through `cargo xtask check-stack` on a lock with a misspelt key
(`psture = "consume"`), which is the stack-lock parser's test `lock_rejects_unknown_field` (N33a-03) and the
finding `stack.lock-schema` of N33a-05, both of which depend on this bead and print this reader's line and
column. It writes `target/e2e-logs/toml_reader/<utc>.ndjson` with a transcript
beside it; every line carries `ts`, `script`, `bead`, `step`, `event`. `cmd` lines carry the exact command line,
exit code and wall time; one `assert` line per corpus case (case name, expected accept or refuse, observed, error
kind and position); a `metric` line for the parse time of the 1 MiB file in milliseconds with its threshold 50;
the BLAKE3 of the vendored corpus directory listing; on failure the first case whose result differs and the path
of the fixture. The `summary` line gives cases passed and failed and the count of valid cases refused as outside
the subset.

### Known answers and negative controls

Known answers: the expected trees of the manifest and stack-lock fixtures above; the corpus's expected values.
Negative controls: a mutant whose `finish` accepts leftover keys must fail `toml_unknown_key_is_error`; a mutant
that accepts dotted keys must fail `toml_outside_subset_is_error_with_position`; a mutant that keeps the last of
two duplicate keys must fail `toml_duplicate_key_is_error`; a mutant that reports a mixed-type array as `Syntax`
must fail `toml_mixed_array_refused` and the valid half of the corpus; the invalid half of the corpus. Determinism: equal
trees and equal errors twice on one machine, in debug and release, on Linux and macOS (D0).

## Considerations

- The subset is a constraint on this repository's files: a manifest written outside it (for example with a dotted
  key that Cargo accepts) is reported by whichever check read it, with its line and column, and is rewritten in
  the subset; the reader is never widened silently. Widening it is a change to this bead's grammar with a test per
  new construct.
- A `Cargo.lock` of the working tree is read through `cargo metadata` or hashed as bytes. A lockfile at an older
  commit, which `cargo metadata` cannot read (the admission validator's rule that a record's cited commit
  contains the foundation, N33a-07), is inside the subset and is read with this reader; the test
  `toml_reads_a_cargo_lock` (a `synthetic` lockfile with its `@generated` comment, `version = 4` and three
  `[[package]]` tables) covers it.
- Cap: `frob-core` has 8 thousand lines with tests; the reader and its tests are expected near 900, which leaves
  BD-005 and the later `frob-core` beads their room (RISK-18 watches caps).
- Licence: the vendored corpus is MIT; it is test data and is not linked into any binary.
- Error messages are read by agents: each names the file, the position, the construct and the fix (for a dotted
  key: "write `serde = { workspace = true }`").
