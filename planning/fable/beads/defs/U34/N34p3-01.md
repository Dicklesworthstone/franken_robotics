## Background

End-to-end scripts and worked examples of FrankenRobotics pass test inputs to the `frob` command as fixture
references: `frob sim run @fixture:envelope-two-device --json`. The harness bead STD-E2E defines the form (DESIGN)
and its reason: a script's command is then the command a user copies, with no shell variable holding a path
that the log cannot show. It leaves the resolution inside `frob` to the verb layer. This bead is that resolver.

It is a separate bead at M0 because scripts of M0 beads already pass the form (the compute-envelope refusals of
N36-20 and N21c-35), while the artifact-input stage that routes a file to its format owner (N34-24) lands at M1
with the owners. Split from N34-24 for that reason; N34-24 depends on this bead and adds nothing to the grammar.

Terms. A *fixture* is a file or a directory under the workspace's `fixtures/` directory. The *parameter kind* of
a verb input is declared in the `params` field of its row of `registries/verbs.toml` (N32a-02's entry schema):
`artifact-input<F>`, `artifact-identity<F>` and `foreign-file` can take a path; `artifact-ref<F>` cannot. The
envelope's `bound` field reports what every name in a request was resolved to, once, before the request is
digested (ADR-TETHER-11: otherwise a retry after a name has moved would be a different request under the same
idempotency key). Tier: Solid. Owner: `frob-verbs` (layer 6).

Rejected alternatives: resolving in the shell helper only (the logged command would not be the one a user can
run, and the envelope would not say which bytes were read); a `--fixture-root` verb parameter (an agent-reachable
way to redirect inputs; the root follows the build, as the registries root does); searching several directories
(an ambiguous reference must refuse, never pick).

## Scope

In: the grammar check; resolution of a reference to a file, to the files of a directory, or to a directory; the
`bound.fixtures` echo; the refusal for an unknown, ambiguous or malformed reference and for a missing root; unit
tests and the script. Out: the helper `e2e_fixture` and the script-side rule (STD-E2E); routing a resolved file
to its owner's reader, the format of a `.json` file by its `schema` member, and the other forms of an artifact
argument (N34-24, M1); the fixtures themselves (the beads whose scripts name them); the arena's `fixture:<name>`
names (no `@`, N24b-03) and `@corpus:`, `@archive:`, `@workload:` (their own beads).

## Technical approach

**Grammar.** `@fixture:<name>`, where `<name>` is one or more segments `[a-z0-9][a-z0-9._-]*` joined by `/`,
with an optional trailing `/`; no empty segment, no `.` or `..` segment, at most 255 bytes.

**Root.** `fixtures/` under the workspace directory whose path the build records, the same record by which
`frob` finds the workspace's `registries/` directory (N32ax-03's resolver; this bead adds no second record and
no option or environment variable). The directory is opened read-only and nothing under it is ever written.
A binary run away from its workspace has no root, and every reference is refused.

**Resolution** (`frob_verbs::input::fixture::resolve(root, reference, kind, list_valued) -> Result<Vec<Resolved>,
Refusal>`; it runs in the *Resolve* step of the dispatch pipeline of N32a-04, after raw-byte admission of the
request and before the request digest, so the digest covers each resolved file's digest). It applies to an
argument whose parameter kind is one of the three that can take a path; a `@fixture:` value given to any other
parameter is an ordinary schema fault of that parameter.
1. Check the grammar; resolve symbolic links and require the result to stay under the root.
2. `fixtures/<name>` is a regular file: that file.
3. It is a directory and the parameter takes one file: the one regular file directly inside it that has the
   extension registered for F (the `extension` column of F's row in the embedded `registries/formats.toml`, the
   thirteen rows of the first commit, BD-002, read through `frob_core::registry::toml`; N34-24 replaces this
   lookup by the typed format registry at M1 and adds JSON files whose `schema` member names F). For
   `foreign-file`, which has no registered format: the one regular file in the directory, if there is exactly one.
4. It is a directory and the parameter is list-valued: every such file, sorted by file name in code-point order.
5. The parameter takes a directory (the reference ends in `/`): the directory itself.
6. Each resolved file is then treated exactly as a file named by path: its bytes pass the raw-byte admission of
   N34-20 (stage 1), and the verb's handler receives the path.

**Echo (DESIGN).** The envelope gains `bound.fixtures`: an array, in parameter order then file order, of
`{ "param": "<input name>", "reference": "@fixture:<name>", "path": "fixtures/<…>" (relative to the workspace),
"digest": "<BLAKE3 of the file's bytes, 64 hexadecimal digits>" }` (for a directory argument, the digest of the
sorted lines `<relative path> <digest>`). It is present on every envelope issued after the Resolve step,
including a refusal of a later stage. It is a member of the envelope's `bound` object, whose schema is N32a-03's.

**Refusal.** No code is invented: the fault is the ledger request `fixture-reference-unresolved` (family `8xx`,
second round of the allocation ledger, N35x-02, filed for the chapter's registry bead N34-REF), raised as its
interim code by the rule of interim codes (N35-33 rule 7) and N34-REF's `detail` row: FROB-REF-802 (arguments
fail the schema) with `detail = "fixture-reference-unresolved"`, behind one named constant, exit 3, `retry:
after-change`, `pointer` the parameter, `observed` one of `fixture-name-invalid`, `fixtures-root-absent`, `fixture-unknown:<name>`,
`fixture-outside-root:<name>` (a symbolic link that leaves the root), `fixture-ambiguous:<name>:<count>` (more
than one candidate where one is required) or `fixture-empty:<name>` (a directory with no file of the format). Ranked repairs: 1. pass the reference of the file itself; 2. pass a
path. The refusal is issued before the request digest, so no key is bound, no job exists and nothing is charged.

Determinism class D0: the resolution is a function of the reference, the parameter kind and the directory's
contents. Evidence: a resolved fixture contributes nothing by itself; the artifact read from it does.

## Acceptance criteria

- [ ] A file reference, a directory holding one file of the parameter's format, and a directory given to a
      list-valued parameter resolve as stated, and `bound.fixtures` lists reference, relative path and digest for
      each file; the digest equals an independent BLAKE3 of the file.
- [ ] An unknown name, an ambiguous directory, an empty directory, a name outside the grammar (`@fixture:../x`,
      `@fixture:A/b`, `@fixture:`), a symbolic link that leaves the root, and a build whose recorded workspace
      has no `fixtures/` directory each refuse with FROB-REF-802, `detail = "fixture-reference-unresolved"` and
      the stated `observed` value, exit 3, with no job, no bound key and zero cost; the same request through `frob-mcp` returns the same refusal fields.
- [ ] Two requests that differ only in the bytes of a resolved fixture have different request digests (the
      digest of N32a-04's step 5 covers each resolved file's digest), so that from M1 a replayed key over
      changed bytes is refused by the admission transaction (N32a-09, `FROB-REF-803`), never a silent second
      meaning; that refusal is N32a-09's to test.
- [ ] Nothing under `fixtures/` is created, changed or removed by any call (a recursive hash before and after).
- [ ] A `@fixture:` value given to a parameter of kind `artifact-ref<F>` or to a non-artifact parameter is
      refused as that parameter's schema fault and is not resolved.

## Test plan

### Unit tests

`cargo test -p frob-verbs fixture` (the real resolver on `synthetic` directory trees built in a temporary
directory; no mocks): `grammar_accepts_and_rejects` (`designs/quad.fbot`, `cortex/` accepted; `../x`, `A/b`,
`a//b`, an empty name and a 256-byte name → `fixture-name-invalid`); `file_resolves`;
`directory_single_file_of_format` (`a.fbot` beside `notes.txt` → `a.fbot`); `directory_list_is_sorted`
(`b.fbot`, `a.fbot`, `notes.txt` → `a.fbot`, `b.fbot`); `directory_argument_is_the_directory`;
`foreign_file_needs_exactly_one`; `unknown_is_refused` (FROB-REF-802, `detail: "fixture-reference-unresolved"`,
`observed: "fixture-unknown:designs/nope.fbot"`);
`ambiguous_is_refused` (two `.fbot` files → `fixture-ambiguous:designs/pair:2`); `empty_is_refused`
(`fixture-empty:designs/none`); `symlink_out_of_root_is_refused` (`fixture-outside-root:designs/link`); `root_absent_is_refused`; `bound_lists_reference_path_digest` (digest of a
three-byte file `abc` equals the published BLAKE3 of `abc`,
`6437b3ac38465133ffb63b75273a8db548c558465d79db03fd359c6cd5bd9d85`); `resolution_precedes_digest` (the same
request over a fixture file `abc` and over the same path holding `abd` gives two request digests);
`refusal_writes_nothing` (ledger file hash and job count unchanged);
`other_kinds_do_not_resolve`; `fixtures_directory_is_never_written`.

### End-to-end script and logging

`scripts/e2e/fixture_refs.sh` (this bead; header `bead=N34p3-01 milestone=M0 labels=workspace,tether,verb`). It
drives the real `frob` binary and `frob-mcp` over stdio on the verb `sim.run` (BD-024), whose design input is a
path-taking parameter from M0, with fixtures this bead commits under `fixtures/fixture-refs/` (`one/` with one
`.fbot` file, `pair/` with two, `none/` with a text file only), each `synthetic` and with its BLAKE3 digest
pinned in the script: each call carries its own `--key "$(e2e_key <case>)"`. Cases: the file reference and the
single-file directory (the envelope, which at M0 is the handler's refusal of a design other than the built-in
one, `FROB-REF-724`, carries `bound.fixtures` with the expected relative path and the pinned digest, and its
code is not 802); the unknown, ambiguous, empty and malformed references (exit 3, FROB-REF-802, `detail`
`fixture-reference-unresolved`, the `observed` value, equal fields on both surfaces, the `ledger` block of `frob doctor --section ledger --json` unchanged); a
recursive hash of `fixtures/` before and after the run. It sources the STD-E2E helper and writes
`target/e2e-logs/fixture_refs/<utc>.ndjson` with a transcript: every line has `ts`, `script`, `bead`, `step`
(the case), `event`, the exact command line, exit code, wall time, the envelope's `evidence` block, the
reference, resolved path and digest from `bound.fixtures`, the refusal code, `detail` and `observed`; on failure the first
differing field, both envelopes saved, and the command that reproduces it; then a `summary` with assertions
passed and failed and `gates: []`.

### Known answers and negative controls

Known answers: the BLAKE3 of `abc` above; sorted order `a.fbot`, `b.fbot`. Negative controls: a resolver that
takes the first file of an ambiguous directory must fail `ambiguous_is_refused`; one that follows a symbolic
link out of the root must fail `symlink_out_of_root_is_refused`; one that resolves after the request digest
must fail `resolution_precedes_digest`. Determinism: identical resolutions and refusals twice on one machine and
on Linux and macOS (directory order never leaks: the sort is explicit).

## Considerations

- Security: the reference is untrusted text. The grammar excludes `..`, absolute paths and upper-case or
  non-ASCII names; the symbolic-link check keeps a committed link from leaving the root.
- The path jail (N37-11, M1) confines every path argument to the session's roots (project, private, export), and
  the workspace's `fixtures/` directory is none of them. DESIGN: from M1 a `@fixture:` reference is opened
  beneath a retained, read-only directory handle of the fixtures root, which the jail admits for references
  only; a plain path that points into `fixtures/` gets no exemption and is jailed like any path
  (FROB-REF-734). Requested of N37-11; at M0 no jail exists and the resolver opens the root itself, read-only.
- Privacy: fixtures are committed, synthetic or licensed inputs; a refusal names the reference, never file
  content.
- An installed binary has no workspace and refuses every reference; fixtures are a development and test
  facility, and `robot-docs` says so.
- N32ax-03's own script cannot pass a reference verbatim, because this bead builds on N32ax-03: it obtains the
  path with the STD-E2E helper `e2e_fixture` and passes the path.
- Open (owner: the surface lead; default as written): whether `bound.fixtures` should also be mirrored per
  parameter. Default: one array, so that `bound.<param>` stays the identity string agents already compare.
