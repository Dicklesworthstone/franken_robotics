## Background

A reader should be able to find the crate for any mechanism, and a tool should be able to refuse a dependency the
design forbids. `xtask` is that tool: a small binary crate in the core workspace (layer 7, tier Solid, cap 3
thousand lines with tests) that holds exactly six checks. The first commit (BD-001) leaves it a skeleton: a `main`
that prints usage and exits 3, reached through the `[alias] xtask` of `.cargo/config.toml`. This bead gives it its
command-line surface and report format, and the first check, `check-layers`, which enforces the layer rules. They are DESIGN decisions with
these reasons:

- **L-1** A crate depends only on lower crates. Lower means a lower layer number, or the same layer and an
  earlier row of the crate map (a smaller rank). Each crate declares both in its manifest
  (`[package.metadata.frob] layer = 3`, `rank = 2`). A chapter that needs a different order inside a layer
  changes the rank by ADR; a cycle is never admitted. Counterexample for the intra-layer clause (CX-363): if rows
  inside a layer were unordered, `frob-arena` could depend on `frob-opt` for comparison while `frob-opt` depends
  on `frob-arena` for batteries, and Cargo would reject the cycle only after both were written. The rank makes
  the second edge a failure on the day it is added.
- **L-3** The core never depends on an annex (a separate workspace with its own lockfile for code the core's
  rules exclude: GPU driver bindings, a Python binding, build-time symbolic derivation). Backends implement core
  traits.
- **L-10** A lower crate reaches a service above it only through a trait it defines itself; five standing
  inversions are registered.
- **L-11** Two planes: kernels and the step never depend on a dispatcher, a memo policy, an estimator or a
  scheduler: no crate of layers 1 to 3 holds one. Decisions about what to run live at layer 4 and above and in
  the daemon. Compile memoization in `frob-model` is a pure cache keyed by identity with a fixed bound, not a
  policy; the memo graph for results sits in front of verb executors in `frob-verbs`, with its bytes in
  `frob-chronicle`.

Why this is its own bead: these rules read only the crate map (N34-02) and the manifests. The dependency rules of
`check-deps` (BD-003) read the stack lock and decide through the posture rules of the stack-lock beads; keeping the
layer rules apart lets the surface every later check plugs into, and the check that the crate-map and register
beads exercise, be built before the stack-lock parser exists.

Rejected alternatives: a general-purpose dependency linter configured by file (the rules here are few, fixed and
tied to this project's own tables; a compiled table changes only by a reviewed commit); enforcing layers by
review.

## Technical approach

**Surface.** `cargo xtask <check> [--root <dir>] [--json]`, through an alias in `.cargo/config.toml`. `--root`
points a check at a scratch copy. The subcommands are rows of one static array of `(name, fn)` pairs in
`crates/xtask/src/main.rs`; this bead writes the array with its one row, `check-layers`; BD-003, N34-07, N34-08 and N34p4-03
each add the row of their check, and BD-004 adds the row of `check-stack` over N33a-05's module and the test that
the array holds exactly six. Exit codes: 0 clean; 2 findings; 3 usage error (an
unknown subcommand, a missing `--root` directory, no argument: the subcommand names are printed); anything else is
a fault of the tool. With `--json` the check writes one report, schema `frob.xtask.report/1`:
`{"check", "ok", "root", "findings": [{"rule", "subject", "path", "line", "message", "repair"}], "facts": {…},
"elapsed_ms"}`, written with `frob-core`'s canonical writer (`frob_core::canon`, N34-18). Its JSON Schema is
hand-written source, not an output of `check-generated`, so it is kept at `schemas/xtask.report.schema.json`
(DESIGN: beside the other hand-written schemas `schemas/demo.schema.json` and `schemas/contract.schema.json`), outside
`schemas/frob.*.json`, where a file no generator row produces is `gen.orphan` (N34p4-03). Every finding has a stable rule identifier; ownership
of a defect class is defined on those identifiers, so that one planted defect is reported by one check.

**Inputs.** The workspace roots to read are an argument of every check (`roots: &[WorkspaceRoot]`); the command
fills it from the workspace table (`crates/xtask/src/workspaces.rs`) of N34p4-02, which depends on this bead and
adds its rows; this bead's command passes the root workspace, and its tests pass `synthetic` roots. For each root,
one read of `cargo metadata --format-version 1 --no-deps --locked --offline` through `frob-core`'s JSON admission
reader (N34-17) gives the declared direct edges with their kinds and each package's `[package.metadata.frob]`
table. Manifests and `contract.toml` files are read through `frob-core`'s strict TOML-subset reader
(`frob_core::registry::toml`, N34p2-01). `xtask` depends on `frob-core` and the standard library only (FACT: the
sibling's own `xtask` likewise links no TOML or JSON library). The check compiles nothing and touches no network: a
read that would need the network is a usage error (exit 3) with the repair "run `cargo fetch` once through the
build shim".

**check-layers**, in order:
1. Crate-map validation against N34-02's table: `ADR-WS-01.unlisted-crate` (a package of the core workspace with
   no row and not one of the exempt names the workspace table passes), `map.metadata-mismatch` (a manifest whose
   `layer` or `rank` differs from its row).
2. For every edge A → B between crates of this repository, of any kind (normal, build, dev; DESIGN: a test that
   needs a higher crate belongs in the higher crate, and shared fixtures are files, not crates):
   `L-1.upward` if layer(B) > layer(A); `L-1.rank` if the layers are equal and rank(B) ≥ rank(A).
3. `L-3.core-to-annex` for any edge from a core crate to an annex crate or to a path under `spark/`, `derive/`,
   `bindings/` or `apps/`; `L-3.annex-to-annex` for an edge between two annexes outside `apps/`. The decision is
   by path, so it needs no workspace table.
4. The inversion register `crates/xtask/src/inversions.rs` (rows: identifier, trait path, defining crate,
   allowed implementing crates, authority `standing` or `adr = "<path>"`): `L-10.unregistered-inversion` (a
   marker line `// frob:inversion <id>` with no row), `L-10.unlisted-implementor` (an `impl <Trait> for` in a
   crate that is neither the row's defining crate nor one of its allowed crates; DESIGN: a null or reference
   implementation beside the trait reaches nothing above it, so the null ports of N34-06 in `frob-core` and the
   `batch-cpu` backend beside `KernelBackend` in `frob-kernels` need no entry), `L-10.wrong-home` (the trait is
   defined in a crate other than the row's; a trait that no crate defines yet raises nothing, because a row may
   precede its trait, as the row of the device backend does),
   `L-10.inversion-without-adr` (a row that is not `standing` and names no ADR file that exists). This bead ships
   the register's type and an empty table; that the real register has exactly the five `standing` rows of rule
   L-10 is the register's own test (N34-06).
5. `L-11.controller-in-compute-plane` if a crate of layers 1 to 3 declares `plane = "decision"` or carries a
   `[[controller]]` record in its `contract.toml` (the record every adaptive controller must have).

The proof-boundary table `edge.forbidden` is `check-deps`' (BD-003); while the layers forbid such an edge this check
reports it as `L-1.upward` and `check-deps` stays silent.

Determinism class D0: findings are sorted by (rule, subject, path); the same tree gives the same report bytes.

## Acceptance criteria

- [ ] Seed done-condition (layer half): in scratch copies, a deliberate upward edge (`frob-lie` → `frob-design`)
      and an intra-layer edge against rank (`frob-arena` → `frob-opt`) each fail with `L-1.upward` and `L-1.rank`
      respectively, exit 2.
- [ ] The clean tree passes `check-layers` with exit 0 and zero findings.
- [ ] INV-WS-01 (the dependency graph respects layer and rank): a property test over 10³ seeded random crate
      graphs shows `check-layers` reports a finding exactly when some edge violates the order.
- [ ] A package `frob-extra` not in the crate map fails with `ADR-WS-01.unlisted-crate`; `frob-dyn` declaring
      `layer = 2` against the map's 3 fails with `map.metadata-mismatch`.
- [ ] A path dependency of a core crate into `spark/` fails with `L-3.core-to-annex`; an annex depending on a
      core crate passes.
- [ ] `cargo xtask` with no argument exits 3 and prints the subcommand names; an unknown subcommand and a missing
      `--root` directory exit 3.
- [ ] `xtask`'s only dependency is `frob-core`; `--json` output validates against `frob.xtask.report/1`.

## Test plan

### Unit tests

`cargo test -p xtask` (graph logic on manifests parsed by the real readers; fixtures are `synthetic` scratch
workspaces under `crates/xtask/tests/fixtures/`, run through the real `cargo metadata`):
- `upward_edge_fails`; `rank_edge_fails`; `same_layer_lower_rank_passes`; `dev_dependency_upward_fails`.
- `cx363_arena_opt_cycle`: `frob-opt` → `frob-arena` passes, the reverse edge fails on its own, before any cycle
  exists.
- `core_to_annex_fails`; `annex_to_core_passes`; `annex_to_annex_fails`.
- `unlisted_crate_fails`; `metadata_mismatch_fails` (the two cases of the acceptance).
- `l10_rules` on a `synthetic` register fixture of two rows: a marker `// frob:inversion nope` with no row →
  `L-10.unregistered-inversion`; `impl EvidenceSink for X` in a crate outside the row's allow-list →
  `L-10.unlisted-implementor`; the trait defined in a crate other than the row's → `L-10.wrong-home`; a third
  row with neither `standing` nor an existing `adr` file → `L-10.inversion-without-adr`; the conforming fixture
  → no finding; an `impl EvidenceSink for Null` in the row's defining crate → no finding; a row whose trait no
  crate of the fixture defines → no finding.
- `l11_rules`: `plane = "decision"` in a layer-3 crate's `contract.toml` → `L-11.controller-in-compute-plane`; a
  `[[controller]]` record in a layer-2 crate → the same rule; the same record in a layer-4 crate → no finding.
- `exit_codes`: clean tree 0; a finding 2; no argument, an unknown subcommand or a missing `--root` directory 3.
- `report_is_sorted_and_stable`: two runs give identical bytes; `report_matches_schema`.
- `random_graph_property` (INV-WS-01).

### End-to-end script and logging

`scripts/e2e/workspace_checks.sh` (bead N34-14) copies the tree to a scratch directory, plants each defect, runs
all six checks with `--json`, and logs per cell of the plant-by-check matrix the command, exit code, wall time,
the rule identifiers reported and the expected owner, in the structured format of STD-E2E. The lines this bead
owns are the plants `upward-edge` (`frob-lie` → `frob-design`, plant 1 of GATE-WS-01) and `edge-against-rank`
(`frob-arena` → `frob-opt`, plant 2; the plant identifier of CX-363 in the counterexample registry N34-CX), and
the extra plants `unlisted-crate`, `unregistered-inversion` and `unlisted-implementor`: each NDJSON line carries
`ts`, `script`, `bead: "N34p4-01"`, `step`, `event`, the exact `cargo xtask` command line, exit code,
`elapsed_ms`, the sorted list of rule identifiers, the expected owner, and the BLAKE3 digest of the `--json`
report; on a miss it logs the first unexpected rule and the scratch-copy path.

### Known answers and negative controls

KA-784 (workspace checks: a deliberate upward edge, an intra-layer edge against rank, a second asupersync
package, an unregistered capsule, an edited generated file and a contract missing a section are each caught;

## Considerations

- OPEN-WS-1 (owner: Build lead): the rank order inside layers 4 and 5 may need edges the map did not foresee.
  Default: the map's order; a change is an ADR. The check never admits a cycle.
- The cap of `xtask` is 3 thousand lines with tests; six checks with fixtures will press on it (RISK-18). If it
  reaches 115%, the registry readers move into `frob-core` or an ADR raises the cap; no seventh check appears.
- `xtask` runs no physics, records no gate and holds no policy.
- Budget: `check-layers` shares the 10 s line of GATE-WS-04 with the rules of BD-003 (BD-004's table); the
  declared-edge read is the cheaper of the two `cargo metadata` reads.
