## Background

The repository holds more than one Cargo workspace on purpose. The core is a set of crates in which unsafe code
is denied and every direct runtime dependency is a Franken foundation or the standard library. Some code cannot
live under those rules: a GPU driver binding with registered unsafe capsules, a Python interpreter, a symbolic
algebra system used at build time. Such code lives in an **annex**: a separate workspace with its own lockfile,
which may depend on the core but on which the core never depends (rule L-3: the core never depends on an annex;
backends implement core traits).

DESIGN, with its reason: the reason for an annex boundary is never the compiler. Every Rust workspace of the
repository builds on the one toolchain T recorded in `rust-toolchain.toml` and in the stack lock, and no annex
carries a toolchain file of its own. The boundary is the unsafe and foreign-interface policy: a dependency the
core's lockfile may not contain. A separate lockfile keeps driver bindings, registered capsules and a sibling's
patch entries out of the core's resolution. This rests on FACTs: the suite keeps its working GPU code outside
FrankenSim's workspace; `cudarc` is a third-party driver binding; `ft-kernel-metal` needs FrankenTorch's
`[patch.crates-io] block` entry at the root of whichever workspace resolves it.

`surface/frob-mcp` has no such reason. The MCP library it uses is a Franken foundation that forbids unsafe code
(FACT), so the server is an ordinary member of the core workspace; its directory name says only that it is a
surface. Rejected alternative: one workspace for everything. It would put `cudarc`, the Metal patch and a Python
binding into the lockfile that every core build resolves, and the rule "unsafe denied in the core" would hold
only by review.

This bead fixes the workspace set as data, makes the boundary testable on the core lockfile, and states the layout
and the lockfile and toolchain-file rules once. It needs no backend, receipt or verb type, so it is built right
after the first two checks; the `apps/` workspace that links core and annexes into the device-enabled binaries is
N34-01's. Tier: Solid.

## Scope

In: the workspace table (`crates/xtask/src/workspaces.rs`, data used by three checks) with its forbidden-package
list; the rule of `check-deps` that applies that list to the core's resolved graph (`core.forbidden-package`); the
table's rows as the workspace roots that `check-layers` and `check-deps` read (the argument of
N34p4-01) and as the exempt link-package names that N34-02's `validate` takes; the repository layout; the lockfile,
toolchain-file and directory rules as testable statements; the tests `crates/xtask/tests/workspaces.rs`; the
end-to-end script `scripts/e2e/workspace_layout.sh` with its table, lockfile and core-edge steps. This bead is the
one statement of the repository layout, of the forbidden-package list and of the lockfile and toolchain-file
rules; the Spark annex policy bead N21a-01 restates none of them.
Out: the `apps/` workspace, the backend-registration entry point in `frob-cli`, `FROB-REF-601` at start, the
device-enabled builds and the steps of the same script that build and run them (N34-01); the Spark-specific
policy (N21a-01); the enforcement of the toolchain-file rule (`check-stack`, condition 2 of N33c-08); the capsule
registry and `check-unsafe` (N34-07); the core root manifest, toolchain file and stack lock (BD-001); the annex
crates and their workspace manifests (BD-015 CUDA, BD-016 Metal, BD-019 derivation, BD-301 Gymnasium adapter);
the worker (BD-038); `lean/` and `viewer/` contents.

## Technical approach

Layout (DESIGN; the repository root):

```
Cargo.toml  rust-toolchain.toml  franken-stack.lock      # core workspace; the one toolchain T
.cargo/config.toml                                       # build-identity setting for path consumption; `xtask` alias
AGENTS.md  README.md  DEPENDENCY_ADMISSION.md
crates/frob-*/  crates/xtask/   # the core: 38 crates, unsafe denied, Franken-only direct runtime dependencies
crates/frob-cert/               # also builds alone, on a stable compiler, with no dependency
surface/frob-mcp/               # MCP server; core workspace member
spark/frob-spark-cuda/          # annex workspace: cudarc, registered unsafe capsules
spark/frob-spark-metal/         # annex workspace: the ft-kernel-metal gateway
apps/                           # workspace that links core + annexes into frob, frobd
worker/                         # workspace manifest for the frob-fsim worker binary
derive/frob-derive/             # annex workspace: build-time derivation with FrankenSymPy
bindings/frob-gymnasium/        # annex workspace: a Rust shim and a Python package
lean/                           # Lake project; outputs not committed (not Rust)
viewer/                         # Three.js viewer and HTML export (not Rust)
kernels/                        # shared-dialect sources and generated arithmetic, with digests
registries/                     # verbs, refusals, kernels, gates, formats, upstream, lifts, capsules (.toml); cards/
schemas/                        # generated from formats.toml and verbs.toml; never edited
demos/                          # one demo.yaml per release path
receipts/                       # resolution receipts, named by their hash
assets/                         # templates, generic actuator and interface cards, licence manifests
tests/fixtures/oracle/          # pinned oracle captures, never regenerated from the candidate
fixtures/                       # committed test inputs; `@fixture:<name>` denotes `fixtures/<name>` (STD-E2E; resolved by N34p3-01)
fixtures/golden/                # golden fixtures: worked artifacts and help-schema snapshots (added by NJL-07)
zoo/                            # pinned archetype instances with their expectation files (added by NEG-30)
tools/oracle/                   # capture scripts for development-time oracles
docs/delivery/                  # the delivery log
docs/adr/                       # every decision record: architecture, bet, open-question and kill-gate decisions
```

1. **Workspace table** (`crates/xtask/src/workspaces.rs`, data): seven Rust workspaces. Six link code: `core`
   (root; includes `surface/frob-mcp`), `spark-cuda`, `spark-metal`, `apps`, `derive`, `bindings`. The seventh,
   `worker`, only re-targets an existing crate (the worker binary of `frob-fsim`). Each row: name, root
   directory, lockfile path, kind (`core`, `annex`, `link`, `retarget`), for the `link` row the names of its link
   packages (the two-line binaries under `apps/frob` and `apps/frobd`, which hold no logic and have no crate-map
   row), and the packages the core lockfile must never contain because of it (`cudarc`; `metal`, `objc2-metal`,
   `ft-kernel-metal` and `block`; `wgpu`; `pyo3`-class bindings; every `fsym-*` crate; and every crate whose
   manifest lies under `spark/`, `apps/`, `derive/` or `bindings/`). This is the one copy of the list:
   `check-deps`, the lockfile grep of this bead's script, the INV-SPARK-01 test of N21a-01 and the
   routes-not-taken registry test of N21c-24 all read it. (The Spark bead had listed `objc2-metal`,
   `ft-kernel-metal` and `wgpu`, which this table lacked, and this table `block`, the Python bindings and
   `fsym-*`, which that list lacked; the union is kept.)
   Each entry of the list is `{ package, why }`, where `why` is one of `annex = "<workspace>"` (the annex whose
   lockfile holds it), `route = "<route id>"` (a row of `registries/routes_not_taken.toml`, the decision record
   of routes researched and not taken) or `nongoal = "<NONGOAL-id>"` (a record of `registries/nongoals.toml`;
   the rendering and FrankenSim aerodynamic crates that the non-goal register N00-23 adds to this list). A
   package pattern ending in `*` matches a name prefix. The routes-not-taken names enter this same list from
   N21c-24, each with its route id: `ash`, `vulkano`, `opencl3`, `cubecl`, `burn*`, `spirv-std` (the `rust-gpu`
   runtime) and the Slang bindings; no second deny list exists anywhere. An entry with neither reason is a test
   failure.
   **The rule that reads the list** (DESIGN; a rule this bead adds to `check-deps`, as N34-03 and N34-04 add
   theirs; N00-23, N21a-01 and N21c-24 enter rows and rely on it): for the `core` row, every
   `[[package]]` of the committed `Cargo.lock` (read with the TOML reader of N34p2-01, so that optional
   dependencies count whatever features a build selects) is matched against the list, by name and by name
   prefix for a `*` pattern; the crates under `spark/`, `apps/`, `derive/` and `bindings/` are matched by the
   manifest path that the resolved `cargo metadata` read of BD-003 gives, and that read supplies the path. A match is the finding `core.forbidden-package`: it names the
   package, the entry's reason with its identifier (`annex = "spark-cuda"`, `route = "<route id>"`,
   `nongoal = "NONGOAL-01"`) and one dependency path from a core crate, direct or transitive (`lockfile-only`
   when no edge of the resolved graph reaches the package). Reason: the direct-edge rules of BD-003 (`L-4`, `L-5`) see only a core
   crate's own edges, while the statement to keep is about what the core lockfile contains, and the pre-commit
   recipe runs the checks on every commit where the script's lockfile grep runs only with the script. It adds
   no `cargo` call and stays inside the 10 s line that `check-layers` and BD-003's rules share.
   On the branch where the MCP kill gate fires, N32a-06 enters an eighth row, `mcp` (root `surface/frob-mcp`,
   its own `Cargo.lock`, kind `annex`), and takes `surface/frob-mcp` out of the `core` row, so that both checks
   read that workspace; the two count tests below read their expected counts from constants beside the table,
   which that bead raises in the same commit (eight rows, seven that link code).
2. **Wiring.** `xtask`'s command passes the rows whose root holds a `Cargo.toml` as the workspace roots of
   `check-layers` and `check-deps` (N34p4-01's `roots` argument), and the link-package names of the `link` row to
   N34-02's `validate(workspace_members, link_packages)`; any other package under `apps/` stays
   `ADR-WS-01.unlisted-crate`. A row whose root has no manifest yet is skipped by the checks and reported under
   `facts` as `absent`, never as clean.
3. **Lockfiles.** Every workspace commits its `Cargo.lock` and builds with `--locked` on T. Sibling repositories
   are pinned by commit and registry crates by exact version. The resolution receipt `frob.stack-receipt/1`
   records a hash of each lockfile (N33a-04), and `check-stack` compares them with the newest receipt (N33a-05).
4. **Toolchain files.** Exactly one `rust-toolchain.toml` governs the build graph, at the root. Two exceptions,
   both by design: `crates/frob-cert/rust-toolchain.toml` names a stable release so that a copy of that directory
   builds alone; and `worker/rust-toolchain.toml` may exist only while the FrankenSim kill gate's fallback (a) is
   in force (the volatile crates behind a pinned worker process at an older pin), in which case the stack lock
   records it. Any other toolchain file is a finding of `check-stack`: condition 2 of the one-toolchain rule
   (N33c-08, finding `stack.toolchain-file`), which matches the file names anywhere in the repository and names
   the two exceptions itself; its plants include a toolchain file under `spark/frob-spark-cuda/`.
5. **Directory rules and who enforces each.** `schemas/` and generated kernel arithmetic are regenerated and
   compared by the generated-file check (N34p4-03). `tests/fixtures/oracle/` holds captures from pinned external
   tools; a fixture file is accompanied by a capture record (tool, pin, date, command, hash) and is never written
   by a program built from this repository (the conformance crate refuses a fixture whose record names the
   candidate). `receipts/` files are named by the BLAKE3 hash of their content. `docs/delivery/` holds the
   delivery log and per-bead logs; planning text never records delivery state.
6. **`lean/`** is a Lake project with its own toolchain; its build outputs are not committed.

Determinism: the table is a compiled constant; the forbidden list is sorted by package name and the script's
lockfile digests are BLAKE3 of the committed bytes.

## Acceptance criteria

- [ ] `crates/xtask/src/workspaces.rs` holds the seven rows above, and every forbidden entry carries exactly one
      reason of the three kinds.
- [ ] `cargo metadata --locked` succeeds in the core workspace; the script runs it for every row whose root holds
      a manifest and logs each other row as `absent`.
- [ ] The core `Cargo.lock` contains none of: `cudarc`, `metal`, `objc2-metal`, `ft-kernel-metal`, `block`,
      `wgpu`, any `fsym-*` package, any Python binding crate, any crate from `spark/`, `apps/`, `derive/` or
      `bindings/`, nor any package of a `route` or `nongoal` entry present in the table.
- [ ] A scratch copy in which a core crate gains a `cudarc` dependency fails `check-deps` (exit 2, a finding
      whose subject is that edge; the stack lock's `cudarc` row confines the crate to `spark/frob-spark-cuda`),
      and the same run reports `core.forbidden-package` naming `cudarc` with `annex = "spark-cuda"`.
- [ ] A `synthetic` core workspace in which a core crate depends on a helper crate that depends on a package
      named `cudarc` fails `check-deps` with `core.forbidden-package` and the path core crate → helper →
      `cudarc`; the same package in the `spark-cuda` row's workspace raises nothing; the clean tree has no such
      finding.
- [ ] No file under `crates/` or `surface/` contains a path dependency into `spark/`, `derive/`, `bindings/` or
      `apps/` (`check-layers`, rule L-3, exits 0 on the clean tree).
- [ ] `rust-toolchain.toml` exists at the root and in `crates/frob-cert/` only (and in `worker/` only when the
      stack lock records the worker fallback): a file search of the clean tree, logged by the script.

## Test plan

### Unit tests

- `crates/xtask/tests/workspaces.rs`: `seven_workspaces_listed`; `six_link_code_one_retargets`;
  `forbidden_core_packages_cover_every_annex`; `every_forbidden_entry_has_a_reason` (a planted entry with none of
  `annex`, `route` and `nongoal` fails; a `route` naming a row absent from a `synthetic`
  `routes_not_taken.toml` fails; a `nongoal` naming no record of a `synthetic` `nongoals.toml` fails; the real
  files are read when they exist); `prefix_pattern_matches` (`burn*` matches `burn-core` and not `sunburn`);
  `link_packages_exempt` (the two link packages pass N34-02's validation, a third package under a `synthetic`
  `apps/` is `ADR-WS-01.unlisted-crate`); `absent_root_is_fact_not_clean` (a row whose root has no manifest
  appears under `facts` as `absent`); `forbidden_package_in_core_closure` (the transitive `cudarc` fixture of
  the acceptance → `core.forbidden-package` with the reason and the three-step path; `burn-core` in the core
  closure matches the entry `burn*` and names its route; a package present in the lockfile and reached by no
  edge → the same finding with `lockfile-only`; an annex workspace holding `cudarc` → no finding).

### End-to-end script and logging

`scripts/e2e/workspace_layout.sh` (this bead creates it; N34-01 adds the steps that build and run the `apps/`
binaries): for each row of the table whose root holds a manifest, runs `cargo metadata --locked --format-version
1` through the build-offload shim; greps each lockfile for the forbidden package list; plants the core-to-`cudarc`
edge in a scratch copy and asserts that `cargo xtask check-deps --root <copy> --json` exits 2 with a finding on
that edge; lists the `rust-toolchain.toml` files of the tree. It logs newline-delimited JSON
through the shared helper of STD-E2E to `target/e2e-logs/workspace_layout/<utc>.ndjson`: one `cmd` line per
command with exit code and wall time, one `assert` line per expectation with the first offending package or path
on failure, an `absent` line per row without a manifest, the lockfile digests, and a `summary` line. Idempotent;
uses a scratch directory under `${RCH_TARGET_BASE:-${TMPDIR:-/tmp}}`.

### Known answers and negative controls

Known answer: the core lockfile's forbidden-package count is 0. Negative controls: the planted `cudarc` edge in a
core crate (must fail `check-deps`); a forbidden entry with no reason (must fail
`every_forbidden_entry_has_a_reason`); a build of the rule that matches only direct dependencies must fail
`forbidden_package_in_core_closure` on its transitive case. The stray toolchain file is N33c-08's plant. Determinism: the table and
the grep result are identical twice on one machine and on Linux and macOS.

## Considerations

- The worker exception is a fallback, exercised at M0 although inactive; it adds a second build to keep only at
  pin moves.
- If the MCP kill gate fires (the server cannot join the core graph on T within the M0 budget), its first
  fallback makes `frob-mcp` its own workspace talking to `frobd` over a local socket; the workspace table then
  gains the row `mcp` by ADR, entered by N32a-06 as item 1 states.
- Security: committed lockfiles and `--locked` builds are the supply-chain rule; an annex lockfile is reviewed
  like the core's.
- Honesty about the closure: path dependencies on FrankenSim bring third-party crates transitively (FACT: 262
  registry packages among the 479 in its lockfile, `nalgebra` 0.35.0 and `rayon` 1.12.0 among them).
  "Franken-only" describes direct edges of core crates.
