## Background

Rule L-8 of the workspace chapter: generated files are never edited by hand. Schemas, the refusal-code enum, the
admission document, the honest-status table of the README and the arithmetic of the kernels are all produced from
registry files; a hand edit to one of them makes the committed artifact disagree with its source while every test
that reads the artifact still passes. `check-generated` is the `xtask` check that keeps them honest: it regenerates
each output and compares, or, where regeneration is too expensive, compares digests.

It is one of the six checks of `xtask` (the workspace's policy tool, layer 7, tier Solid). It is its own bead so
that every bead that only adds a generator row or a rule inside this check (the verb-table emitter of N32a-02, the
refusal printout of N35-33, the bead-log chain of N29a-09, the artifact-graph export of BD-095) waits on this check
and not on the assembly of all six (BD-004). Tier: Solid.

Rejected alternative: regenerate in a build script and never commit outputs. Schemas, the README table and the
admission document are read by people and by tools that do not build the workspace; a committed file with a check
is readable everywhere and still cannot drift.

## Scope

In: the `check-generated` subcommand (its row in N34p4-01's command array, its report `frob.xtask.report/1`); the
generator interface in `xtask::generate` (a list of input globs per row, outputs, mode); the six rows of the table
below; the `gen.*` findings; `--write`; the steps of `scripts/e2e/status_table.sh` (created by BD-002) that need
this check.
Out: the six-entry command table test, the ownership rule over finding identifiers across checks, the in-crate
plant matrix and the timing table (BD-004); the status-table generator's rules (BD-002); the admission-document
generator itself (`xtask::generate::admission_doc`, N33a-07; this bead runs it as a row); the stack-lock model
(N33a-03); the rules later beads add inside this check (below); the end-to-end run on the real tree that records
GATE-WS-01 (N34-14).

## Technical approach

**The generator interface.** A generator is a pure function from registry files to output files, written in
`xtask::generate` with `frob-core`'s registry readers and canonical writer, and depending on none of the crates that
consume its output. Each row names a list of input globs (not one file, because later rows read several inputs),
its outputs and its mode. Table (data):

| Generator | Inputs | Outputs | Mode |
|---|---|---|---|
| Format and verb schemas | `registries/formats.toml`, `registries/verbs.toml` | `schemas/frob.*.json`, one file per schema identifier with `/` written as `.` | Regenerate, compare bytes |
| Stack-lock schema | The typed model of the stack lock (`stack::lock`, N33a-03) | `schemas/frob.stack-lock.1.json` | Regenerate, compare bytes |
| Admission document | The record files under `receipts/admissions/` and the first-commit header (`xtask::generate::admission_doc`, N33a-07) | `DEPENDENCY_ADMISSION.md` | Regenerate, compare bytes |
| Refusal codes | `registries/refusals.toml` | The generated `RefusalCode` enum in `frob-core` | Regenerate, compare bytes |
| Honest-status table | `registries/gates.toml` | The block between the status markers of `README.md` | Regenerate, compare bytes |
| Kernel arithmetic | Kernel manifests in `registries/kernels.toml` | Generated arithmetic under `kernels/` | Digest: each file's BLAKE3 must equal the digest its manifest records |

The kernel row uses digests because re-deriving kernel arithmetic needs the symbolic-derivation annex and would
break the 10-second share of this check; the derivation lane regenerates and this check proves nobody edited the
result. DESIGN: the generated paths are exactly the outputs column. The hand-written schemas of the first commit
and their later edits (the registry-file schemas under `schemas/registries/`, `schemas/demo.schema.json` and
`schemas/contract.schema.json`; BD-002, N34x-03, N34-07, N33a-01) are reviewed source, not outputs: they are not
regenerated and never `gen.orphan`, which is reported only for a `schemas/frob.*.json` file that no row produces.
(An earlier wording gave the first row the output `schemas/**`, which made every hand-written schema an orphan on
the clean tree.)

**Findings.** Every generated file carries a marker on its first line naming its generator and inputs.
`gen.differs` (path and first differing line), `gen.missing`, `gen.orphan` (a file under a generated directory
that no generator produces), `gen.digest`, `gen.marker-missing`, `gen.status-invalid` (the status generator
refused a registry row, for example a pass with no measured value). Exit codes are the surface's: 0 clean, 2
findings, 3 usage.

**`--write`.** `cargo xtask check-generated --write` rewrites the regenerable outputs; it never rewrites a digest
and never touches files outside the outputs column. Output bytes are deterministic: sorted rows, fixed widths,
`\n` endings. Determinism class D0.

**Later rules inside this check** (each is a generator row or a rule added by its own bead; none is a new check):
the per-bead logs `docs/delivery/logs/<bead>.ndjson` (schema `frob.beadlog/1`) become a second input of the
honest-status table, and their append-only chain is recomputed so that an edited or deleted earlier line fails
(N29a-09, M1); the committed export of the artifact graph is checked against the registry so that every
`claim_id` of a closing line resolves (BD-095, M1); the command-line and MCP surfaces generated from
`registries/verbs.toml`, which by ADR-TETHER-01 are one static table that `frob-verbs`'s build script emits into
`$OUT_DIR/verbs_table.rs` (neither `frob-cli` nor `surface/frob-mcp` holds a per-verb table, so no committed copy
exists here to compare): N32a-02 (M0) adds the rule that re-runs that emitter and compares bytes, and fails a
build made with its `FROB_VERBS_REGISTRY` override; the generated printout `docs/generated/refusals.md` and the
refusal registry's cross-chapter checks (N35-33, M0). DESIGN: an earlier wording of the table gave the verb tables
as committed Rust files under `frob-cli` and `surface/frob-mcp`, which contradicts ADR-TETHER-01.

## Acceptance criteria

- [ ] Plant 5 of GATE-WS-01, this check's half: changing one byte of a generated schema file

      hand-editing the README status block afterwards fails.
- [ ] A kernel arithmetic file with one changed character fails with `gen.digest`.
- [ ] INV-SPARK-08: one changed byte in each regenerable output of the table fails with `gen.differs`, and one in
      a kernel file with `gen.digest` (the test `check_generated_detects_edit`).
- [ ] `check-generated` finishes within its 10 s share of GATE-WS-04 on a warm tree (BD-004's table; TARGET),
      and its report carries `elapsed_ms`.

## Test plan

### Unit tests

`cargo test -p xtask`:
- `generated_schema_roundtrip`: generate into a temporary tree, compare, expect clean; flip one byte, expect
  `gen.differs` with the right line.
- `orphan_schema_file_is_finding` (a stray `schemas/frob.unknown.1.json` → `gen.orphan`; a hand-written
  `schemas/registries/x.schema.json` → no finding); `missing_generated_file_is_finding`; `marker_required`.
- `stack_lock_schema_regenerates`: the committed `schemas/frob.stack-lock.1.json` equals the output of N33a-03's
  typed model; one changed byte → `gen.differs`.
- `write_mode_touches_only_outputs`: a recursive hash of everything outside the outputs column is unchanged.
- `check_generated_detects_edit` (INV-SPARK-08, the name the invariant register row of the Spark chapter cites:
  generated code is never edited by hand; the check regenerates and compares digests): one byte changed in a
  generated kernel source under `kernels/` fails with `gen.digest` naming the file and the manifest digest; one
  byte changed in each regenerable output of this bead's table (a schema, the stack-lock schema, the admission
  document, the `RefusalCode` enum, the status block) fails with `gen.differs` and the first differing line; the
  unedited tree is clean.
- `write_mode_does_not_rewrite_digests`.
- `status_block_regenerates_byte_identical`; `status_pass_without_measured_is_invalid`.
- `input_globs_per_row`: a `synthetic` row with two input globs regenerates from both, and an edit to the second
  input alone changes the output.

### End-to-end script and logging

This bead adds to `scripts/e2e/status_table.sh` (created by BD-002) the steps that need `check-generated`: on the
five-row fixture, `cargo xtask check-generated --write` then `cargo xtask check-generated` (exit 0 after the
invalid row is removed, exit 2 with `gen.status-invalid` before), and a hand edit of the README block → exit 2 with
`gen.differs` and the first differing line (the first clause of GATE-GAUNT-10); each logged as a `cmd` and an
`assert` line with the report's finding identifiers, in the structured format of STD-E2E. Plant 5 on the real
tree is a line of `scripts/e2e/workspace_checks.sh` (N34-14), logged with `bead: "N34p4-03"`.

### Known answers and negative controls

KA-784 (workspace checks: a deliberate upward edge, an intra-layer edge against rank, a second asupersync
package, an unregistered capsule, an edited generated file and a contract missing a section are each caught;
tolerance exact; tier G0 on the host; the planted violations are the controls); the edited generated file is this
check's. Negative controls: the one-byte edit of each output kind (must fail); a hand-written schema
(must not fail: proves the outputs column is not over-broad); `--write` run on a kernel digest (must leave it
unchanged). Determinism: `--json` reports are byte-identical twice on one machine apart from `elapsed_ms`, which
the comparison excludes.

## Considerations

- If `check-generated` nears its 10-second share, the first lever is to skip regeneration when the input digests
  equal those recorded in the output markers.
- Generators are the largest part of `xtask`, whose cap of 3 thousand lines with tests is the tightest in the
  workspace (RISK-18); they move to the crates that own their registries only by ADR.
- The bead-log check rides inside this check rather than being a seventh check (BD-004's rule on the number six).
