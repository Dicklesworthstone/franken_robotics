## Background

FrankenRobotics is built by many agents working at once on shared machines, beside sibling projects that other
agents are changing at the same time. Twelve working rules are inherited from the machine-level agent instructions
and from the suite's main simulation project (FACT: `frankensim/AGENTS.md`), and adopted here; each was learned
from a failure (a local compile that starved every other agent, a deleted file nobody could restore, a branch that
diverged for a week, a sibling checkout "fixed" by moving it back to a pin while someone was working in it, a week
of tooling that shipped no capability).

Rules stated in a document are followed until the first deadline, so the document must say, for each rule, what
other than goodwill enforces it. N34-15 holds the rule table and builds the mechanical pieces it names (the
machine-envelope guard `scripts/lib/envelope.sh` and the pre-commit recipe `scripts/precommit.sh`). This bead
writes that table into `AGENTS.md`, the file every implementing agent reads first, and has it reviewed. It is its
own bead because `AGENTS.md` is created by the companion-documents bead BD-002, while the guard needs no document
and is wanted by every heavy script lane as early as possible. Tier: Solid.

## Scope

In: the section "Working rules" of `AGENTS.md` with the twelve rules of N34-15's table, each with its reason and its
enforcement point; the build-failure recipe of rule 10 (its first step is `cargo xtask check-stack`); the review by
a session that did not write the section; a text check that keeps the section and the table in step.
Out: `AGENTS.md` as a whole and the other companion documents (BD-002); the rule table itself, the guard and the
pre-commit recipe (N34-15); the compute-envelope record and its approvals (N21c-35, N44-01); the verbs' admission
by compute class (N36-20).

## Technical approach

1. **The section.** A level-two heading `## Working rules` in `AGENTS.md`, placed after BD-002's content rules,
   holding a table with the columns `#`, `Rule`, `Why`, `Enforced by`, one row per rule of N34-15's table in the
   same order and with the same numbers 1 to 12. The `Enforced by` cell names the mechanism by its command or
   function exactly as N34-15 ships it (`frob_envelope_run`, `frob_target_dir`, `frob_scratch_dir`,
   `frob_disk_preflight`, `scripts/precommit.sh`, `cargo xtask check-stack`, the exactly-six rule), or says
   "review" or "nothing to enforce" where N34-15's table does.
2. **Rule 4 in full.** The machine envelope is written with its numbers (16 GiB, 8 cores, one hour, one device;
   approval before the run; a timeout for any run longer than a few minutes; jobs stop when the agent stops) and
   with the sentence that the guard covers runs outside the verbs while the verbs' own admission (N36-20) covers
   runs through `frob` and `frob-launch`, both reading `registries/compute_envelope.toml`.
3. **The build-failure recipe** (rule 10) as a numbered list: run `cargo xtask check-stack`; classify an off-pin
   sibling as fast-forward or divergence (N33a-04's drift classes) before any remedy; never move a sibling checkout
   back to its pin to make a check pass.
4. **The text check** `scripts/lib/tests/agents_rules_test.sh`: extracts the section's table and fails on a
   missing or repeated rule number, on a row without a reason or an enforcement point, on an `Enforced by` cell
   that names a shell function `scripts/lib/envelope.sh` does not define, and on one that names a script path
   that does not exist.

## Acceptance criteria

- [ ] `AGENTS.md` has the section `## Working rules` with twelve rows numbered 1 to 12, each with a reason and an
      enforcement point.
- [ ] A review by a session that did not write the section finds each rule of N34-15's table present and none
      weakened; the review is recorded in the bead's close reason with the reviewer's session.
- [ ] `agents_rules_test.sh` passes on the clean tree and fails on a scratch copy with row 4 removed, and on one
      whose `Enforced by` cell names `frob_envelope_runx`.
- [ ] The build-failure recipe of rule 10 is present and its first step is `cargo xtask check-stack`.

## Test plan

### Unit tests

`scripts/lib/tests/agents_rules_test.sh` (real files, scratch copies, no mocks): `twelve_rows_present`;
`numbers_contiguous`; `enforcement_names_exist` (each function named in the table is defined in
`scripts/lib/envelope.sh`, each script path exists); `missing_row_fails` (`synthetic` copy without row 4);
`misnamed_function_fails`.

### End-to-end script and logging

This bead adds the text check to the test steps of `scripts/precommit.sh` (N34-15), and
`scripts/e2e/first_commit.sh` (N34-16) checks the first commit's inventory, `AGENTS.md` among it. The test logs through the shared helper of STD-E2E: one `assert`
line per row with the rule number and the enforcement name, and a `summary` line.

### Known answers and negative controls

Known answer: twelve rows. Negative controls: the removed row; the misspelled function name. Determinism: the
extraction is a pure function of the two files.

## Considerations

- The section restates N34-15's table; the text check keeps its enforcement names pointing at things that exist,
  and the review keeps its wording from weakening a rule. A change to a rule is made in N34-15's table first.
- Rule 11 (process is never the product) applies to this bead: it addresses the blocker that agents start work
  without the rules in front of them; one section and one text check are the smallest direct action.
