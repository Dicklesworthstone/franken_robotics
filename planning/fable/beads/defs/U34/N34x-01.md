## Background

The crates of the core are stacked in layers 0 to 7, and a crate depends only on lower crates (rule L-1: a lower
layer, or the same layer and an earlier row of the crate map). Rule L-10 is the one way a lower crate reaches a
service that lives above it: through a trait the lower crate defines itself, implemented above it. The plan lists
the standing inversions as five: the device backend (trait `KernelBackend` in `frob-kernels`, implemented by the
two GPU annex crates); the evidence sink and the trace source (defined in `frob-core`, implemented in
`frob-chronicle`); the job context for cancellation and budgets (defined in `frob-core`, supplied by the daemon);
and the certificate sink (defined in `frob-core`, implemented in `frob-lemma`). The layer check
(`xtask check-layers`) reads a register of these, `crates/xtask/src/inversions.rs` (N34-06): one row per
inversion with identifier, trait path, defining crate, allowed implementing crates and its authority, `standing`
for the five the rule names or `adr = "<path>"` for any other. A marker line `// frob:inversion <id>` precedes
each trait; a marker with no row fails as `L-10.unregistered-inversion`, an `impl` of a registered trait outside
its allowed crates fails as `L-10.unlisted-implementor`, and a row that is not `standing` and names no existing
ADR fails as `L-10.inversion-without-adr` (BD-003, from M0). The register's own test asserts exactly five
`standing` rows. At M1 five rows are added under ADR-WS-05 (`restorable` and `energy-sink`, N16a-01;
`controller`, `action-filter` and `state-source`, N22a-01), so the register holds ten rows when this bead starts.

One more inversion is now needed. The design preflight (`frob design check`) gains, at stage 6 (statics and sizing), a
check that every declared link wall can carry the design's own bounded loads, so that screening cannot reward a
limb too thin to build; and the fill `{shell: sized}` is resolved to the thinnest passing stock wall before a
model is compiled. The plan assigns the sizing kernel to `frob-foundry` (layer 5) and says that `frob-analyze`
(layer 4) calls it at stage 6. A direct call is an upward edge, which L-1 forbids. The two beads that build the
check and the fill therefore define a trait `MemberSizer` in `frob-analyze`, implement it in `frob-foundry` and
have `frob-verbs` (layer 6) pass the implementation in. Without a register row their marker fails the layer
check, and no bead records the decision. This bead records it and adds the row. Tier: Solid.

## Scope

In: the ADR with the options weighed; the `member-sizer` register row and its marker; the register's known
answer at M3 (eleven rows); the behaviour with no implementation attached, decided in the ADR; the planted
cases. Out: the trait's request and answer types, the null sizer and the stage-6 check with its no-sizer tests
(N31b-39); the sized fill and its fixed point (N31b-41); the
sizing formulas (N31b-38); the register, its row format with the authority field, the five standing rows and the
standing-count test (N34-06, BD-014); the layer check and its rule `L-10.inversion-without-adr` (BD-003); the
ADR-WS-05 rows (N16a-01, N22a-01). An earlier draft of this bead introduced the `adr` field and the ADR rule
itself and changed the count from five to six; both now exist from M0, and this bead adds a row only.

## Technical approach

**1. The ADR (`docs/adr/ADR-WS-04-member-sizer-inversion.md`; DESIGN number, the next free of the workspace
series at conversion).** It states the need above and weighs five options:

| Option | Verdict | Reason |
|---|---|---|
| Put the sizing kernel in `frob-analyze` | Rejected | The plan assigns sizing to `frob-foundry`; the beam rung of the structural-margin analysis at M5 extends the same code, so a copy in layer 4 would be a second implementation of one formula set |
| Move `frob-foundry` below `frob-analyze` | Rejected | A rank change by ADR is possible only inside a layer; moving a layer-5 crate that holds fatigue, tolerance allocation and build packets under the analyses changes the crate map for one function |
| A new base crate holding the kernel | Rejected | The rule for creating a crate asks for a named defect class or a cap overflow; neither exists here, and the kernel has one owner today |
| Compose at the verb layer: `frob-verbs` calls the stages, then the sizer, and merges findings | Rejected | Stage 6 is one pass with one timing line, one ordering of findings and one typed repair list, all owned by `frob-analyze`; a merge outside it would give stage 6 two owners |
| **A trait defined in `frob-analyze`, implemented in `frob-foundry`, wired by `frob-verbs`** | **Adopted** | It is exactly rule L-10: the lower crate names the service it needs; no upward edge; one kernel |

**2. The register row (DESIGN).**

| Field | Value |
|---|---|
| `id` | `member-sizer` |
| `trait_path` | `frob_analyze::preflight::MemberSizer` |
| `defining_crate` | `frob-analyze` (layer 4) |
| `implementors` | `["frob-foundry"]` (layer 5) |
| authority | `adr = "docs/adr/ADR-WS-04-member-sizer-inversion.md"` |

The row uses the format N34-06 fixed at M0 and adds no field. The crate that constructs the implementation and
passes it down (`frob-verbs`, layer 6) is named in the ADR's text, not in the row, because no rule reads it. The
marker `// frob:inversion member-sizer` precedes the trait in `frob-analyze`. `frob-foundry` gains the
dependency `frob-analyze` (a lower crate, allowed); `frob-analyze` gains none.

**3. The ADR rule is already in force.** The row is admitted by its `adr` authority under BD-003's rule
`L-10.inversion-without-adr`, and N34-06's register test still finds exactly five `standing` rows. What this
bead changes is the register's known answer: from ten rows at M1 (five standing, five under ADR-WS-05) to eleven
at M3. Reason the guard holds: the count of five standing rows guards against quiet growth, and every addition
cites its decision.

**4. No implementation attached (decided here, built and tested by N31b-39 and N31b-41).** `frob-analyze`
ships a null sizer whose answer is `not-checked`, and stage 6
then reports `structure: not checked (no sizer)`, which is never a pass and never a silent skip: a verb that
needs a model of a design with a sized fill refuses when no sizer is wired (FROB-REF-724, not implemented in
this build, exit 5, naming the member sizer; DESIGN: the build lacks a capability, the design is not wrong). This is the defined behaviour of a
build that links `frob-analyze` without `frob-foundry` (a CPU-only analysis tool, a test of a lower crate). If
the kernel sits behind a `frontier-` feature of `frob-foundry` (rule L-12: tier features are off by default),
the default build is such a build; the ADR records which it is, from the kernel bead's own declaration.

**5. Two planes (rule L-11).** The trait has one method, a pure function from a sizing request to an answer. It
chooses nothing: no schedule, no memo policy, no estimator. A later method that returns a policy decision is
refused by review and by the ADR's text.

Determinism class D0 for the register check. Nothing here enters the run ledger; the gate that the check serves
(the workspace checks gate) records the layer check's result as before.

## Acceptance criteria

- [ ] The ADR exists with the five options, the adopted one, the reasons and the wiring crate; the register has
      eleven rows (five `standing`, five under ADR-WS-05, `member-sizer` under ADR-WS-04) and the new row cites
      this ADR.
- [ ] `cargo xtask check-layers` passes on a tree in which `frob-analyze` defines `MemberSizer` under its marker,
      `frob-foundry` implements it and `frob-verbs` wires it; `frob-analyze` has no dependency on `frob-foundry`.
- [ ] An `impl MemberSizer for X` planted in `frob-opt` fails with `L-10.unlisted-implementor`.
- [ ] The `member-sizer` row with its ADR file removed in a scratch copy fails with `L-10.inversion-without-adr`;
      the same row marked `standing` fails N34-06's standing-count test.
- [ ] A direct dependency of `frob-analyze` on `frob-foundry`, planted in a scratch manifest, fails rule L-1.
- [ ] The ADR states the behaviour with no implementation attached (item 4) and names the tests that assert it in
      the beads that build on this row, which depend on it and so cannot be run here: N31b-39's
      `no_sizer_reports_not_checked` and its no-sizer end-to-end step (stage 6 reports `structure: not checked (no
      sizer)`, exit 2, never 0), and N31b-41's `sized_fill_without_sizer_refuses`; and the stage-6 bead's
      `verb_and_stage_paths_agree` (the public sizing verb and the stage-6 path give the same answer, from M5).

## Test plan

### Unit tests
`cargo test -p xtask inversions` (the real register; planted trees are scratch copies labelled `synthetic`):
- `register_has_five_standing_rows` (N34-06's test) still passes with the new row.
- `register_member_sizer_row`: the row's fields above, exactly, with authority `adr`.
- `member_sizer_adr_must_exist` (the scratch copy without the ADR file); `member_sizer_marked_standing_fails`.
- `member_sizer_impl_outside_allow_list_is_finding` (planted in `frob-opt`).
- `member_sizer_defined_in_wrong_crate_is_finding` (the marker and trait planted in `frob-foundry`).
The null sizer and its behaviour are tested where they are built (N31b-39, N31b-41), not here.

### End-to-end script and logging
`scripts/e2e/workspace_checks.sh` (the script of the workspace checks, N34-14) gains two rows of its extra-plant
table from M3: the unlisted implementor of `MemberSizer` and the `member-sizer` row without its ADR file, each
asserted by rule identifier and exit 2, and a third, the upward dependency of `frob-analyze` on `frob-foundry`
in a scratch manifest, asserted as rule L-1. (The no-sizer step of `scripts/e2e/design_check_member_sizing.sh`
is N31b-39's, which depends on this bead.) The rows log through the STD-E2E helper to
`target/e2e-logs/workspace_checks/<utc-timestamp>.ndjson`: `ts`, `script`, `bead`, `step`, `event`; `cmd` lines
with exact command line, exit code and wall time; an `assert` line per plant with the rule identifier found and,
on a miss, the scratch tree's path and the rule expected; a `summary` line. No private-scene data.

### Known answers and negative controls
- Known answer: eleven register rows at M3, five standing, five under ADR-WS-05 and one under ADR-WS-04; for
  this row, layers 4 (defines), 5 (implements), 6 (wires).
- Negative controls (each must be caught): the unlisted implementor; the row without its ADR; the upward
  dependency. (A null sizer whose answer is reported as a pass is planted in N31b-39's stage-6 test.)
- Determinism: the register check is a pure function of the tree, identical twice and across platforms.

## Considerations

- The stage-6 check is Solid and its kernel lives in a crate whose other content is Frontier. If the kernel is
  feature-gated, a default build checks no structure; the stage says so in its report. Whether the default
  release build enables that feature is decided with the kernel bead and written into the ADR, because it
  decides what `design.check` means for most users.
- Every further inversion costs a row and an ADR. Two in one milestone is a signal that a crate sits in the
  wrong layer, and the milestone's exit review asks that question by name.
- What would make us revisit: a second consumer of the sizer below layer 5 (then the trait may belong in a
  lower crate), or a move of the kernel, in which case the row moves in the same commit and the layer check
  fails if row and trait disagree.
