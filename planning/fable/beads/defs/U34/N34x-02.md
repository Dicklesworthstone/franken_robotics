## Background

Every crate ships a prose contract (`CONTRACT.md`, ten sections) and beside it a small machine-readable record,
`crates/<crate>/contract.toml`: layer and rank, plane, determinism class, evidence class of outputs, budgets,
feature flags with their tiers, safe mode, and two lists of identifiers the crate cites, `gates` and `refusals`.
The workspace check `xtask check-contracts` validates the record against `schemas/contract.schema.json`, the
manifest and the registries; an unknown key fails. This is the suite convention "contracts as code".

A gate is stated twice in this project: once in the chapter that owns the mechanism (thresholds, tolerances,
controls) and once in the gate register `registries/gates.toml` (identity, one claim kind, earliest milestone, a
brief; for a kill gate its trigger, its fallback and its decision point, kept in the fallback ledger with dated
amendments). Two statements drift. Two conformance checks exist to catch the drift: a lint that joins what each
crate declares about its gates with the register (every register row has exactly one owner; owner and register
agree on claim, part milestones and every number of the brief; a consumer may restate and never change), and a
cross-check of every kill-gate decision against the fallback ledger (trigger and fallback text, comparison
directions, the decision point, and for a decided gate the ADR, the measured values with receipts and an outcome
consistent with them).

Both checks need a **machine-readable declaration beside the mechanism**. Both chose the same place, a `[[gate]]`
block in the crate's `contract.toml`, and both wrote the same caveat: the contract schema knows only the list
`gates = [...]` of cited identifiers, so until the schema gains the block they read one hand-kept file,
`registries/gate_declarations.toml`. The contract check's own bead says a new key is added "by the bead that
introduces it". Each side therefore waits for the other, and a hand-kept file of every gate's thresholds beside
the register is a third statement of the same facts, which is the drift the checks exist to remove. This bead
adds the block. Tier: Solid.

Rejected: keeping the hand-kept file for good (three statements, one of them far from the code); putting the
declarations in `CONTRACT.md` prose (not machine-readable; the check does not grade prose); a separate file per
crate (a second record beside the contract with its own schema and its own drift).

## Scope

In: the block's schema in `schemas/contract.schema.json`; the typed reader shared by the contract check and the
two conformance checks; the contract check's rules for the block; the migration from
`registries/gate_declarations.toml` and the rule that ends that file's use; tests. Out: the comparison of
declarations with the register and its list of recorded discrepancies (N40-09); the comparison of kill-gate
decisions with the fallback ledger (N40-30); the register and the ledger themselves (N40-01, N40-02, N40-03 and
the ledger registries); the other keys of `contract.toml` (N34-08, N34-10).

## Technical approach

**1. The block (DESIGN; field names are the ones both consuming checks already use).**

```toml
[[gate]]
id = "GATE-TRAC-01"                  # a row of registries/gates.toml, or a KILL- row of the fallback ledger
role = "owner"                       # owner | consumer
claim = "known-answer"               # proof | known-answer | parity | fidelity | design-comparison | reality | performance
milestone_parts = ["M1: CPU rows", "M2: device rows"]   # "<milestone>: <part>"; one entry "M1: whole" if undivided
threshold_numbers = ["0.7", "200"]   # every number of the gate's brief, as exact decimal or rational strings

[[gate]]
id = "KILL-EXAMPLE"                  # a kill gate adds:
role = "owner"
trigger = "…"                        # the text fixed in advance
fallback = "…"
decided = "M2"                       # the decision point
mode = "exit"                        # exit | pilot-before-funding | standing | rolling
reads = ["GATE-TRAC-01"]             # the gates whose records the decision reads
# reread = ["M3"]                    # optional: later exits at which the decision is taken again
decision = { outcome = "not-fired", adr = "docs/adr/…", date = "…", session = "…", receipts = ["…"], measured = [ { name = "…", value = "…", unit = "…", receipt = "…" } ] }   # present once decided
# a deferred entry: { outcome = "deferred", adr = "…", deferred_to = "M3", reason = "…" }
# or, for a gate decided more than once or per scope, an array of the same tables, each with `exit`, with `scope`
# where the ledger row has a scope kind, and with `reading` on a second entry for one scope at one exit:
# decision = [ { exit = "M3", scope = "cell:wheeled", outcome = "fired", adr = "…", measured = [ … ] },
#              { exit = "M3", scope = "cell:tracked", outcome = "not-fired", adr = "…", receipts = ["…"], measured = [ … ] },
#              { exit = "M3", scope = "cell:tracked", reading = "final", outcome = "fired", adr = "…-final.md", measured = [ … ] } ]
```
The enumerations and the shape of `decision` are those of the kill-gate record that owns them (N40-03, a
dependency), so that the block and the fallback ledger can be compared field by field. `mode`: `exit` (decided at
the exit named by `decided`, once, or again at each exit `reread` names), `pilot-before-funding` (decided when the
work package that the pilot gates is funded, at the earliest from `decided`), `standing` (a rule in force from
`decided` onward, evaluated at every exit and whenever its event occurs) and `rolling` (re-read at the exits
`reread` names, or at every later exit when it is omitted). `reread` is optional, a list of milestones each later
than `decided`. `outcome` is one of `fired`, `not-fired`, `not-reached` (the mechanism was not funded, so the
capability does not exist) and `deferred` (an ADR moved the decision to a named later exit). `decision` is a single
table, read as a one-entry array, or an array of tables. A decision table mirrors the ledger's decision entry
field by field (N40-03), so that an entry copied from the ledger validates here and the cross-check compares like
with like:
- `outcome` and `adr`: always required; the ADR path has the one form `docs/adr/ADR-<gate-name>-<milestone>.md`,
  with the suffix `-final` or `-reopened` where `reading` says so.
- `date` (ISO) and `session` (the recording session): admitted, and required by the ledger, not by the block.
- `receipts`: the hashes of the gate receipts the outcome rests on. A `not-fired` entry needs at least one
  receipt, in `receipts` or cited by a `measured` value.
- `measured`: the block's own addition, the measured values beside the trigger's numbers, each with `name`,
  `value`, `unit` and `receipt`.
- `deferred_to` and `reason`: required on a `deferred` entry and refused on any other; `deferred_to` is an exit
  later than the entry's, `reason` is non-empty.
- `exit`: the milestone at which the entry was taken (default `decided`).
- `scope`: `<kind>:<value>` for a gate the ledger decides per scope, with `<kind>` one of the ledger's closed
  table of scope kinds, eight at the time of writing: `cell` (a stratum of the ten-fold test), `algorithm`,
  `half`, `clause`, `backend` (a tier name), `item`, `resolution`, `kind` (an island kind). The table is
  N40-03's; a kind added there is added to this reader in the same change, and that the scope's kind is the
  ledger row's own `scope_kind` is the cross-check's comparison, not this schema's.
- `reading`: `final` or `reopened`, only on a second entry for one scope at one exit (a gate decided in two
  stages, or a decision re-opened by a new ADR).
The latest entry per scope is the one in force. Numbers
are strings so that "0.5" and "1/2" are compared as written and nothing passes through a float.

**1b. Chapter-side fields (optional on any block; the register lint does not compare them).** The chapter
register beads moved their chapter-side data out of invented fields of `registries/gates.toml` into this block
(reconciliation note of N40-02), so the block admits exactly these, with these shapes (DESIGN):

```toml
criterion = "…"                      # the full criterion of the defining subsection; the register's threshold is its brief
criteria = [ { quantity = "…", unit = "…", op = ">=", value = "0.7", site = "…" } ]   # one per clause of the criterion
measured_by = ["N25d-07", "scripts/e2e/…"]   # the bead keys and scripts that measure the gate (the Carrier column)
fixture = "tests/…"                  # the gate's fixture directory
script = "scripts/e2e/…"             # the gate's end-to-end script
kill = "KILL-…"                      # the kill gate this gate's record can trigger
notes = "…"                          # reconciliations and milestone rulings, in prose
form_hash = "b3:…"                   # a design-comparison gate: the hash of its registered pre-analysis form
strata_fixture = "…"                 # the fixture identity the ten-fold protocol draws strata from
bet = "…"                            # the bet tag the gate belongs to
```
`op` is one of `<`, `<=`, `=`, `>=`, `>`; `value` is an exact decimal or rational string. When `criteria` is
present, `threshold_numbers` equals its `value`s in order (the list is generated from it). One name per field:
the Carrier column is `measured_by` everywhere (one chapter bead wrote `carrier_beads`, and is asked to rename).

**2. Schema.** `schemas/contract.schema.json` gains the array `gate` with the two shapes above (selected by the
prefix of `id`), `additionalProperties: false`, and the required fields: `id` and `role` always; `claim`,
`milestone_parts`, `threshold_numbers` for a `GATE-`, `INT-` or program-gate row with role `owner`; `trigger`,
`fallback`, `decided`, `mode` for a `KILL-` row with role `owner`. A consumer needs only `id` and `role` and may
restate any field. The chapter-side fields of 1b are optional on both shapes.

**3. One reader (DESIGN).** `frob_core::contract::GateDecl` and `read_gate_decls(path) -> Vec<GateDecl>` in
`frob-core` (layer 0, so that `xtask` and `frob-conformance` both call it and neither parses the block itself).
It uses the strict TOML-subset reader of `frob-core` (an unknown key or a duplicate key is an error with line
and column).

**4. Rules added to `check-contracts`** (shape and existence only; agreement with the register is the lint's):
1. `contract.gate-decl-schema`: a block fails the schema (unknown key, missing required field, wrong enumeration).
2. `contract.gate-decl-unknown`: `id`, or the `kill` field, names a gate in neither `registries/gates.toml` nor
   the fallback ledger; a `measured_by` entry is neither a bead key of the commit's bead export (when present)
   nor a path that exists.
3. `contract.gate-decl-not-cited`: a block's `id` is absent from the crate's `gates` list, or a cited identifier
   that this crate owns has no block. The list stays the index; the blocks are the content.
4. `contract.gate-decl-duplicate`: two blocks with one `id` in one crate.
5. `contract.gate-decl-number`: an entry of `threshold_numbers`, or a `criteria` value, that is not an exact
   decimal or rational; or `threshold_numbers` that differs from the `criteria` values when both are present.
   The schema rule (1) also refuses a `reread` entry at or before `decided`; a `scope` whose kind is not one of
   the eight above or whose value is empty; a `reading` other than `final` or `reopened`; two `decision`
   entries with the same `exit`, `scope` and `reading` (an absent `reading` counting as one value); a
   `deferred` entry without `deferred_to` and `reason`, or with a `deferred_to` that is not later than its
   exit; `deferred_to` or `reason` on an entry that is not `deferred`; and a `not-fired` entry that cites no
   receipt.
Two owners of one gate in two crates is not this check's finding; it is the register lint's first rule.

**5. Switch-over.** The two conformance checks take their declarations from `read_gate_decls` over every crate's
`contract.toml`. If `registries/gate_declarations.toml` exists because either check started under the interim:
(a) each of its rows is moved into the `contract.toml` of the crate that owns the mechanism (owner rows) or
consumes it (consumer rows); (b) a test asserts that the set of declarations read from the crates equals the
set the file held, field by field; (c) the file is reduced to a header stating that declarations live in
`contract.toml`, and a row added to it afterwards fails `contract.gate-decl-stray-file`. Removing the file
altogether is asked of the owner (no file is deleted without explicit permission). Crates that landed at M0
receive their blocks in this step; a crate that does not exist yet has no declaration, and the register lint
reports its gates as `pending: <crate>` until the crate's milestone.

Determinism class D0. Outputs are findings of a workspace check; nothing enters the run ledger.

## Acceptance criteria

- [ ] `schemas/contract.schema.json` contains the `gate` array with both shapes; a `contract.toml` with a
      well-formed block passes `check-contracts`, and one with an unknown key in the block fails with
      `contract.gate-decl-schema`.
- [ ] Each of rules 2 to 5 has a planted `synthetic` crate that raises it by identifier.
- [ ] A block carrying every chapter-side field of 1b passes the schema; `carrier_beads` or any other unlisted
      key fails `contract.gate-decl-schema`; `criteria` values that disagree with `threshold_numbers` fail
      `contract.gate-decl-number`.
- [ ] `frob-conformance` and `xtask` contain no parser of the block other than the call to
      `frob_core::contract::read_gate_decls`.
- [ ] The register lint and the kill-decision cross-check run from `contract.toml` blocks; with a
      `gate_declarations.toml` present before migration, the equality test passes after it.
- [ ] A row added to `registries/gate_declarations.toml` after the switch fails `contract.gate-decl-stray-file`.
- [ ] Every crate present at the M1 exit declares, as owner, each gate of its defining subsection that is due
      by M1, and the register lint reports zero rows without an owner among crates that exist.
- [ ] The contract check still finishes in under 10 s on a warm tree (TARGET; its share of the 60-second budget
      of the six checks).

- `reads_owner_gate_block`; `reads_kill_block_with_decision`; `consumer_needs_only_id_and_role`.
- `kill_enumerations_match_ledger` (the four modes and four outcomes of N40-03 read back; `at-exit` and an outcome
  `pending` are errors); `single_decision_is_one_entry_array`; `decision_array_with_exit_and_scope` (two entries
  `{exit = "M3", scope = "cell:wheeled", outcome = "fired"}` and `{exit = "M3", scope = "cell:tracked", outcome =
  "not-fired"}` read back in order); `reread_after_decided_only` (`decided = "M1"`, `reread = ["M1"]` is an error;
  `["M2"]` reads); `scope_form_checked` (one value of each of the eight kinds accepted, `backend:gpu-metal` and
  `resolution:2x2` among them; `region:x` and `cell:` with an empty value refused).
- `decision_entry_mirrors_ledger`: an entry with `date`, `session`, `receipts`, `exit`, `scope` and `measured`
  reads back with every field; `deferred_needs_exit_and_reason` (`outcome = "deferred"` alone is an error; with
  `deferred_to = "M3"` on an entry taken at M2 and a non-empty `reason` it reads; `deferred_to = "M2"` on that
  entry is an error; `reason` on a `fired` entry is an error); `not_fired_needs_a_receipt` (no `receipts` and no
  `measured` receipt is an error; either one suffices); `second_reading_at_one_exit` (two entries for
  `cell:tracked` at M3, the second with `reading = "final"`, read back in order; without `reading` on the second
  they are a duplicate and an error; `reading = "second"` is an error).
- `unknown_key_is_error_with_line_and_column`; `duplicate_key_is_error`.
- `numbers_stay_strings`: `"1/2"` and `"0.5"` are distinct values after reading.
- `reads_chapter_side_fields`: all ten fields of 1b read back with their shapes; `criteria` entries keep order.
`cargo test -p xtask contracts_gate_decl` (planted crates are TOML strings labelled `synthetic`):
- `decl_unknown_gate_is_finding`; `decl_not_cited_is_finding`; `cited_owned_gate_without_block_is_finding`;
  `decl_duplicate_is_finding`; `decl_number_not_exact_is_finding`; `stray_file_row_is_finding`;
  `criteria_must_match_threshold_numbers`; `unknown_kill_reference_is_finding`; `carrier_beads_is_unknown_key`.
- `migration_preserves_declarations`: a scratch `gate_declarations.toml` of six rows (three gates, two kill

### End-to-end script and logging
`scripts/e2e/contract_gate_decls.sh`: (1) `cargo xtask check-contracts --json` on the tree, asserting no
`contract.gate-decl-*` finding; (2) five scratch copies, one per rule, each asserted by identifier, file and
line with exit 2; (3) `cargo test -p frob-conformance --test register_agreement` and `--test kill_ledger`,
asserting that both report the number of declarations they read and that the number equals the count of
`[[gate]]` blocks in the tree; (4) the stray-file plant. It logs through the STD-E2E helper to
`target/e2e-logs/contract_gate_decls/<utc-timestamp>.ndjson`: `cmd` lines with exact command line, exit code and
wall time; `metric` lines for blocks read, owners, consumers, kill blocks; one `assert` per plant with the
finding; a `summary` line. This script records no gate: GATE-GAUNT-10 is measured by the register lint and the
kill-decision cross-check (N40-09, N40-30), and its value is entered from their tier run's receipt with the
`record_gate` example. No private-scene data is involved.

### Known answers and negative controls
- Known answers: seven claim kinds; four modes; four outcomes; eight scope kinds; two readings; the migration
  fixture's six declarations.
- Negative controls (each must be caught): the five planted rule violations; a build of the check with rule 3
  disabled, which must let a cited-but-undeclared gate pass and fail the test; a second parser of the block
  planted in `frob-conformance` (caught by a source scan for the block's key names outside `frob-core`).
- Metamorphic: reordering blocks inside a file, or keys inside a block, changes no finding.
- Determinism: pure functions of the tree, equal twice on one machine and across platforms.

## Considerations

- The block restates numbers that the register also holds. That is deliberate: the lint needs two independent
  statements to compare, one beside the code and one in the register. What this bead removes is the third.
- Decision beads for kill gates are work items, not crates; the owner declaration of a kill gate lives in the
  contract of the crate that owns the mechanism the gate can stop.
- A gate owned by a document or a harness with no crate of its own (program gates, exit gates) is declared in
  the contract of `frob-conformance`.
- The shared reader adds about 150 lines with tests to `frob-core`, whose cap of 8 thousand lines is already
  watched; it is placed there because nothing may depend on `frob-conformance` and `xtask` is the last crate of
  the map, so no other crate is below both callers.
- What would make us revisit: a field either consuming check needs that is not listed here. It is added to
  the schema by the bead that needs it, as the contract check's own rule says, and the shared reader follows.
