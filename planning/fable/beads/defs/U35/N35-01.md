## Background

FrankenRobotics simulates robots on four tiers: `referee` (double precision, the trusted reference), `batch-cpu`
(our own batched kernels on the CPU), `gpu-cuda` and `gpu-metal`. A number from any of them is compared,
replayed, paired or cited by other parts of the system, and each of those uses needs a different guarantee. The
numerics chapter fixes five **determinism classes** and requires that every result records its class
(GOAL-20: state determinism as a class on every result, and test it).

| Class | Guarantee | Where it applies | Tested by |
|---|---|---|---|
| **D0 Exact** | Integer, rational or symbolic results | Static analyses over ℚ, group computations, certificates, world addressing; exact-integer kernels and the decisions of guarded kernels on every backend; integer and uniform random draws; rational clocks and phase accumulators | GATE-SPARK-08 |
| **D1 Bitwise across backends** | The same bits on `batch-cpu` (`f32`), CUDA and Metal | Algebraic kernels, if GATE-SPARK-01 passes for the device family. A HYPOTHESIS until then (kill gate KILL-D1) | GATE-SPARK-01, -02 |
| **D2 Bitwise per backend** | The same bits run to run and across worker counts on one device family, driver and compiler; and across batch size, slot, co-tenant worlds, bucket capacity and shard count | The design requirement for every kernel | GATE-SPARK-15 |
| **D3 Tolerance** | Agreement inside a recorded envelope, and agreement of task decisions | Cross-backend comparison when D1 is unavailable; cross-tier fidelity | GATE-SPARK-02, -16 |
| **D4 Unspecified** | None | Never cited as evidence. Its one sanctioned use is the labelled training profile | GATE-SPARK-17 |

A normal random variate built from deterministic floating-point elementary functions is D2 per backend, and D1
across backends only where GATE-SPARK-01 passes; the integer draw under it is D0.

Two rules govern the classes. **The weakest input wins** (INV-NUM-06): the class of a result is the weakest
class among the kernels, placements, profile and inputs that produced it. **A class is never raised by
relabelling**, only by running again under a stricter profile. The reason is that a statistic that pairs,
replays or attributes is only as good as the replay under it; a class that could be edited would make every
licence downstream meaningless.

The seed bead for `frob-core` (BD-005) puts a `determinism` field in the claim product (the typed record of what
a result asserts) and combines it by the weakest rule. This bead is the type itself and its laws: the lattice,
the serialized form, the provenance of a class, the mapping from kernel class to determinism class, and the
compile-time guarantee that no conversion upward exists. Tier: Solid. Decision ADR-NUM-01 (every verb declares
the minimum determinism class of its inputs and refuses below it) rests on this type; the declaration and the
check are N35-07.

Alternative rejected: a free-form string or a boolean `deterministic` flag. A boolean cannot distinguish "the
same batch repeats" (parity with incumbent engines) from "a world is independent of its batch" or from "equal
bits on another backend", and those three license different uses.

## Scope

In: `DetClass` and its order; `meet`; `DetProvenance`; the serialized forms; the kernel-class mapping; the
absence of upward conversions, with compile-fail tests; the contract text for `CONTRACT.md` section
"determinism class". Out: how a class is attained for a kernel set on a device (N35-02); profiles (N35-04);
what a class licenses (N35-07); the claim product's `combine` (BD-005).

## Technical approach

**Type (DESIGN; module `frob_core::det`).**

```rust
/// Ord: weakest first, so `min` is the meet.  D4 < D3 < D2 < D1 < D0.
pub enum DetClass { D4Unspecified, D3Tolerance, D2PerBackend, D1CrossBackend, D0Exact }

pub struct DetProvenance {          // why this class holds; carried beside the class, never used to raise it
    class: DetClass,                // private; no setter
    weakest: InputRef,              // the input that set it: content hash and field path
    profile: Option<ProfileName>,   // the determinism profile the run declared, if a run
    records: Vec<ReceiptId>,        // gate or check receipts that attest the class for the kernels and placement
}
impl DetClass  { pub fn meet(self, other: DetClass) -> DetClass; }           // = min
impl DetProvenance { pub fn combine(parts: &[DetProvenance]) -> Result<DetProvenance, Refusal>; }
```

1. `meet` is `min` in the order above; it is associative, commutative and idempotent, with D0 the identity and
   D4 absorbing.
2. `DetProvenance::combine` returns the part attaining the minimum (ties broken by lowest content hash, then
   field path, so the answer is deterministic) and the union of `records`. An empty slice is a caller error
   returned as a typed refusal.
3. **No way up.** There is no `From`, `TryFrom`, setter or public constructor that produces a class stronger
   than its inputs. The only constructors are: `DetProvenance::exact(input)` for values that are integers,
   rationals or symbolic by type; `DetProvenance::attested(class, records)`, a hidden doorway callable only by
   the determinism classifier (N35-02) and the conformance harness, marked `#[deprecated]` with a note naming
   those call sites (the workspace denies `deprecated`, so any other call fails the lint); and `combine`.
   Because a local `#[allow(deprecated)]` would silence that lint, a source scan of the workspace (a test of
   `frob-core`, `det_doorway_call_sites`) fails on any call of `DetProvenance::attested` outside the
   classifier's module and the conformance harness, whether or not an `allow` covers it, and on any
   `allow(deprecated)` attribute whose scope contains such a call.
   A result whose inputs carry no class is D4: absence is never read as a stronger class.
4. **Serialized form.** In envelopes, receipts and ledgers: the strings `"D0"` … `"D4"`. A reader rejects any
   other string, and rejects a missing field where the schema requires one (it does not default to D2).
5. **Kernel-class mapping** (used by the classifier, stated here because it is a property of the type):

   | Kernel class | Arithmetic | Determinism of outputs |
   |---|---|---|
   | `exact` | Unsigned 32-bit integers | D0 on every backend |
   | `guarded` | An `f32` residual with a certified error bound, plus an exact fallback | D0 in its decisions; the residual itself is as `float` |
   | `float` | `f32` and double-float accumulators, IEEE safe mode | D2 by design; D1 only where attested for the device family |
   | `stat` | Any, across worlds | Never feeds state; its outputs carry the class of their inputs and are never an input to a state kernel |

6. **Contract text.** Every crate's `CONTRACT.md` has a section "determinism class"; this module exports the
   five one-line definitions as constants so that the generated section and the type cannot disagree.

**Parity statement the type must be able to express.** Two incumbent engines document opt-in bitwise run-to-run
determinism for the same batch on the same GPU, and one states that CPU and GPU results usually differ (FACT,
source register). Class D2 read as "the same batch repeated" is therefore parity. The two properties this
program adds, each claimed only after its gate, are the independence of a world from its batch (D2 as defined
above) and bit equality between a device and the CPU reference (D1). `DetProvenance.records` is what
distinguishes a D2 that has its batch-independence record from one that has only been repeated.

## Acceptance criteria

- [ ] `DetClass` has exactly five variants with the order D4 < D3 < D2 < D1 < D0; `meet` equals `min`.
- [ ] Over 10⁴ seeded random multisets of classes, `combine` returns the minimum and names an input that attains it; the result is independent of the order of the parts.
- [ ] Three compile-fail tests pin the absent conversions: no `From<DetClass>` that raises, no setter on `DetProvenance.class`, and no public constructor taking a class as an argument other than the `attested` doorway, whose call outside its two permitted call sites fails the build.
- [ ] The doorway scan fails a planted call of `DetProvenance::attested` in another crate both without and with a local `#[allow(deprecated)]`, and passes the two permitted call sites.
- [ ] A planted `impl From<D3-valued provenance> for D2` in a test crate is rejected by the build check: the developer-level unit test `ka_804_planted_upward_conversion_fails_build` of `frob-core` passes at M0 (the negative control that KA-804's row will name). This bead claims no runner entry: the row KA-804 enters the registry at M1 (N35-KA, which names this test as the owner test), and the runner entry `ka:KA-804@host` of N38a-13 is added at M1 by the M1 conformance battery (BD-146).
- [ ] Serialization round-trips the five strings; `"d2"`, `"D5"`, an empty string and a missing required field are each a parse error.
- [ ] A value with no class recorded reads as D4 in every consumer (a test feeds an envelope without the field to the reader of each schema that carries it).
- [ ] `CONTRACT.md` of `frob-core` lists the type, its laws and the doorway constructor with its permitted call sites.

## Test plan

### Unit tests
- `det_order_is_weakest_first`: D4 < D3 < D2 < D1 < D0.
- `det_meet_laws` (property): associativity, commutativity, idempotence, identity D0, absorbing D4, over all 125 triples exhaustively.
- `det_combine_weakest_wins` (property, 10⁴ cases): class = min; `weakest` attains it; permuting the parts changes nothing.
- `det_combine_tie_break_is_deterministic`: two parts of class D3 with hashes `aa…` and `bb…` return the `aa…` part.
- `det_no_upward_conversion` (compile-fail, three cases as listed).
- `ka_804_planted_upward_conversion_fails_build` (compile-fail): a test crate holding `impl From<D3-valued provenance> for D2` (a conversion that would raise a D3 provenance to D2) does not build; the expected compiler diagnostic names the private field or the missing constructor. A developer-level binding of KA-804 from M0 (N38a-13: a `ka_<nnn>_` test in the owning crate is a second binding beside the runner entry, not a replacement).
- `det_doorway_call_sites`: the workspace scan; planted controls: a call of `attested` in a scratch crate (fails the deny lint), the same call under `#[allow(deprecated)]` (fails the scan), and the classifier's call (passes).
- `det_absent_is_d4`: an input without a class combines to D4.
- `det_serde_strict`: the five strings round-trip; four malformed inputs fail.
- `det_kernel_class_mapping`: `exact` → D0; `guarded` decisions → D0; `float` without attestation → D2; `float` with a D1 attestation for the family → D1; a `stat` output offered as a state input is a type error.

### End-to-end script and logging
`scripts/e2e/num_detclass.sh`: runs `frob --json doctor` and `frob --json capabilities` and asserts that each
envelope's `evidence.determinism` is one of the five strings and equals the weakest class among
`evidence.inputs` (for these two verbs: D0, since they compute nothing in floating point); then runs
`cargo test -p frob-core det_` and `cargo test -p frob-core ka_804_` and asserts every test listed above ran and
passed, including the three compile-fail cases and the KA-804 plant. The run-level form (a simulation's class equals the weakest of its kernels, placement,
profile and inputs) is asserted by `scripts/e2e/num_profiles.sh` (N35-31). Logging through the STD-E2E helper
to `target/e2e-logs/num_detclass/<utc-timestamp>.ndjson`: every `cmd` with exact command line, exit code and
wall time; the envelope's evidence block (claim, class, tier, determinism, identities, seed); an `assert` line
per check with expected and observed class; a `summary` line with counts.

### Known answers and negative controls
- KA-804: the class of a combined result is the weakest class among what produced it; no conversion upward
  compiles. Negative control: the planted upward conversion must fail the build
  (`ka_804_planted_upward_conversion_fails_build`). At M0 this is a developer-level test; the registry row is
  due at M1 (N35-KA), its runner entry `ka:KA-804@host` is BD-146's, and its control record (seed `KA-804`) is
  issued by N38b-05's seeding tool once the row exists. This bead writes neither.
- Metamorphic: permuting or duplicating inputs leaves the class unchanged; adding an input never raises it.
- Determinism lanes: the type is pure data; its tests run twice and across debug and release with identical
  output.

## Considerations

- The doorway constructor is the only place a class above D4 enters for floating results. If a second crate
  needs it, that is a design review, not a new call site.
- KILL-D1 (decided at M2 per device family): if a family cannot hold bit equality with `batch-cpu`, no value
  on that family is ever attested D1; nothing in this type changes.
- The claim product also carries an evidence class (Estimated, Tested, Certified, Proved) and a tier. They are
  three independent orders; a strong evidence class never compensates for a weak determinism class.
- The referee tier aims at cross-platform determinism in double precision; the upstream dynamics crate
  currently calls platform square root, sine and cosine and makes no such claim (FACT), so referee results are
  attested "same platform" until the upstream work item FD-FSIM-07 lands; the lane that measures it is N35-03.
