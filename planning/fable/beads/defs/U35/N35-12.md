## Background

GATE-SPARK-16 (claim: Fidelity; TARGET; earliest M2) says: for every class D3 pair of placements used as
evidence, on a frozen ensemble of at least 4,096 worlds per reference workload, the upper bound on discordant
decisions is at most 1%, the bound on net one-sided discordance is at most 0.5%, continuous outcomes are
equivalent inside ledger margins, first divergences are recorded, and a planted bias of one decision in fifty
must fail. Class D3 is the determinism class of two placements that agree inside a recorded tolerance and on
task decisions without being bit-identical; the test that establishes it is the decision-level equivalence
test, run by `frob spark check --decisions` (BD-177).

A gate is recorded only from a run of the real binaries on the real machines, with measured values and with
its negative control shown to fail. This bead is that run as a script: plain shell, seed-explicit, idempotent,
exiting non-zero on any failed assertion, and writing the structured log a reviewer or a later session needs
to see exactly what was measured. It adds no mechanism. Tier: Solid.

## Scope

In: the script, its steps, assertions and log lines; the gate-recording hand-off. Out: everything the script
calls (BD-177 and the beads under it); the thresholds (N35-11).

## Technical approach

**Invocation.** `scripts/e2e/num_decision_equivalence.sh [--pairs all|<A>:<B>,…] [--workloads Q,H]
[--seed N] [--short]`. Defaults: all registered pairs whose two placements exist on this machine; both
workloads; the ensembles' own frozen run seed (the `--seed` option seeds only the script's choice of sampled
worlds for spot output). `--short` uses 512 worlds and 100 control intervals and must end in
`insufficient-ensemble`; it exists so that the script itself can be tested inside the default compute
envelope and never writes a gate row.

**Steps (each a `step` value in the log).**
1. `preflight`: `frob --json doctor`; `frob --json spark devices`; assert the fingerprint digests are current;
   read the threshold record and assert it is frozen (otherwise log `provisional-thresholds` and continue
   without the `gate` step).
2. `ensembles`: verify the content hashes of the Q and H ensembles against the registry.
3. `aa`: for each placement, `frob --json spark check --decisions --pair <A>:<A>`; assert zero discordant
   worlds and verdict `equivalent`.
4. `pairs`: for each pair and workload, `frob --json spark check --decisions --pair <A>:<B> --workload <w>`;
   assert the envelope carries a verdict, n ≥ 4,096, and a first-divergence record for every discordant
   world; record the measured values.
5. `boundary_fixture`: run the conformance fixture world whose success predicate is x ≥ 1 m and whose two
   placements end 10⁻⁷ m either side; assert it is listed as discordant and `boundary-sensitive` on both
   placements.
6. `planted_bias`: repeat step 4 for one pair per machine with `--mutant decision-bias-1-in-50` on placement
   B; assert verdict `not-equivalent`, U above 2%, and that the envelope carries `conformance_mutant`.
7. `states_only`: `cargo test -p frob-conformance states_only_variant_rejected`.
8. `read_back`: `frob --json artifact read <verdict>` for each verdict; assert the stored record equals the
   envelope and names the threshold record's hash.
9. `gate`: `cargo test -p frob-conformance --test g5 -- GATE-SPARK-16`, which reads the verdict records of
   step 4 and the control results of steps 3, 6 and 7 and prints the gate table.
10. `summary`.

**Assertions tied to numbers.** For every pair and workload: `U ≤ 0.01`; `U_net ≤ 0.005`; for each continuous
outcome both one-sided bounds inside ±Δ (Δ read from the fidelity ledger and logged); `first_divergences ==
k`. For the planted bias: `U > 0.02`. For A/A: `k == 0` and `U == 0.000731` to three significant digits at
n = 4,096.

**Logging.** The script sources the shared helper of STD-E2E and writes newline-delimited JSON to
`target/e2e-logs/num_decision_equivalence/<utc-timestamp>.ndjson` and a human-readable transcript beside it.
Every line has `ts`, `script`, `bead` (`N35-12`), `step`, `event` (`start`, `cmd`, `assert`, `metric`,
`refusal`, `end`), the exact command line, exit code and wall time. `cmd` lines carry the envelope's
`evidence` block (claim fidelity, class, tier pair, determinism D3 or D1, identities including both fingerprint
digests, the ensemble hash and the threshold record hash, seed). `metric` lines carry `n`, `k`, `U`, `b`, `c`,
`mixed`, `U_net`, each outcome's `d_bar`, `s`, lower and upper bounds and `delta` with units, `tau` with its
interval, `boundary_sensitive_count`, each with its threshold. `assert` lines carry expected and observed
values. On failure the log gives the first discordant world address, the decision identifier, both values,
both margins with unit, the envelope, the first-divergence step and kernel, and the paths of both episode
records and of the per-world comparison record. The final `summary` line counts assertions passed and failed
and names GATE-SPARK-16. No scene geometry or other private-scene data is written; worlds are named by
address.

**Hand-off.** The script does not write `registries/gates.toml`. A recording session that did not implement
the work reads the log and the receipts and enters the rows (one per pair and workload).

## Acceptance criteria

- [ ] The script exits 0 only if every assertion passed, and non-zero otherwise; a second run with the same options reproduces the same verdict records (same hashes).
- [ ] On the Mac it covers `batch-cpu` against `gpu-metal` and `batch-cpu` `f32` against `f64`; on host `trj` it covers `batch-cpu` against `gpu-cuda`; the cross-machine pair `gpu-cuda` against `gpu-metal` is assembled from the two machines' stored runs by `--pairs gpu-cuda:gpu-metal` on either machine, or logged `skipped: peer runs absent`.
- [ ] The planted-bias step fails the test as required and the script treats that failure as a passed assertion.
- [ ] `--short` ends with `insufficient-ensemble` everywhere, exit 0, and no `gate` step.
- [ ] The log validates against the STD-E2E line schema; every `cmd` line has an exit code, wall time and evidence block.
- [ ] A pair whose class is D1 is logged as exempt with its bit-equality receipt and is not asserted against the D3 thresholds.

## Test plan

### Unit tests
The script has no unit tests of its own; `scripts/e2e/tests/num_decision_equivalence.bats` (run by the
harness's self-test) checks: option parsing; that `--short` never reaches the `gate` step; that a simulated
non-zero exit of `frob` in step 4 makes the script exit non-zero and emits a `summary` line with the failure
counted; that the log lines validate against the schema.

### End-to-end script and logging
This bead is the script; see the steps and logging above.

### Known answers and negative controls
- KA-788 (step 5), KA-789 (the thresholds and the planted bias, steps 4 and 6).
- CX-364, CX-365 (`--short` shows that a small ensemble proves nothing).
- Negative controls exercised: the planted bias (must fail the test); the states-only comparator (must be
  rejected); a deliberately stale fingerprint in preflight on a conformance run (the script must stop before
  step 3 with the refusal logged).
- Determinism lanes: steps 3 and 4 run each placement of each ensemble once; BD-177's lanes cover running
  twice. The script's own outputs (verdict hashes) are compared between two consecutive invocations.

## Considerations

- Wall time on the Mac for both workloads and both local pairs is a few minutes of device time plus the
  `batch-cpu` runs; all of it fits the default compute envelope except pairs that include the referee, which
  are logged `skipped: envelope` unless the gate-measurement class is approved.
- Under kill gate KILL-D1's fallback more pairs become D3 pairs; the registry of pairs grows and this script
  picks them up without change.
- If thresholds are still provisional the script is useful as a rehearsal but cannot produce a gate row; it
  says so in its summary.
