## Background

Worlds of different sizes run in one batch inside padded buffers: a world with 9 active contacts in a buffer
of capacity 32, a robot with 18 degrees of freedom in a bucket of capacity 24. The program claims that a
world's trajectory does not depend on the batch it ran in, which includes the capacity of the bucket it was
placed in. That claim holds only if padding changes no bit of any active result. **Padding neutrality
(INV-NUM-02): outputs of active lanes are bit-identical at any capacity at or above the active count.**

Two of the eight design conditions of batch independence are about reductions and are specified here:

- A per-world reduction is a pairwise tree anchored at index 0 over power-of-two blocks, so which two active
  elements are added first does not depend on capacity.
- Padding trails the active lanes and holds the neutral element of its consumer: −0.0 for sums, 1.0 for
  products, +∞ and −∞ for minimum and maximum, and identity rows with zero right-hand side in the
  factorization, which follow every active row and so never enter an active entry.

Two small cases show the rules are not pedantry. *Padding with +0.0 is not neutral*: the sum of the single
active element −0.0 is −0.0 alone and +0.0 when one +0.0 lane is appended, because (−0.0) + (+0.0) = +0.0; the
values compare equal, the bits differ (0x80000000 against 0x00000000), and a digest over bits changes with
capacity. *Grouping by capacity changes sums*: in `f32` with a = 10⁸, b = −10⁸, c = 1, (a + b) + c = 1 and
a + (b + c) = 0, because the spacing near 10⁸ is 8.

The hazard table of the numerics chapter adds: reductions use fixed-shape pairwise trees anchored at index 0,
with compensated sums for long accumulations; and on the CPU the tree shape is a function of logical index
only, never of tile boundaries or worker count. This bead is the contract (what every reduction in the kernel
library must compute), a host reference implementation, and the law tests that the reduction kernels
(`K-reduce`, `K-seg-reduce`, and reductions inside other kernels) are checked against. Tier: Solid.

Alternative rejected: masking padded lanes out of every reduction with a branch or an arithmetic blend. A
branch breaks the rule that lanes of one wave share control flow; an arithmetic blend m·a + (1 − m)·b turns an
infinity in the unselected arm into NaN. Neutral padding needs neither.

## Technical approach

**Neutral elements (the consumer decides; a buffer read by two consumers with different neutral elements is
split or re-initialized between them).**

| Consumer | Neutral element | Why it is neutral bit for bit |
|---|---|---|
| Floating sum | −0.0 (pattern 0x80000000) | x + (−0.0) = x for every non-NaN x, including +0.0 and −0.0; (−0.0) + (−0.0) = −0.0 |
| Floating product | 1.0 | x · 1.0 = x for every non-NaN x |
| Minimum | +∞ | `det_min(x, +∞)` = x |
| Maximum | −∞ | `det_max(x, −∞)` = x |
| Integer wrapping sum, count, bitwise or | 0 | exact |
| Unsigned 32-bit maximum | 0 | exact |
| Unsigned 32-bit minimum | 0xFFFFFFFF | exact |
| Two-limb unsigned add (lo, hi) | (0, 0) | exact, with the carry by unsigned comparison (the operator is N21a-07's) |
| Bitwise and | 0xFFFFFFFF | exact |
| Factorization | Identity rows with a zero right-hand side, after every active row | The leading block of a Cholesky factor does not depend on later rows |

`det_min` and `det_max` are the dialect's explicit selects (the built-ins differ between languages on NaN and
on ±0): min(−0, +0) = −0, max(−0, +0) = +0, and any NaN operand gives NaN. Any NaN marks the world `Faulted`, so
neutrality is required for non-NaN inputs only, and no bit pattern is claimed for a NaN result. This table is
the one statement of the neutral elements: the operator table of the utility kernels (N21a-07) carries the same
values for the operators it offers (the four floating operators, the wrapping `u32` add, `u32` maximum and
minimum, bitwise or, the two-limb add), and `neutral_table_agrees` below fails if a kernel manifest declares a
different element for the same operation.

**The anchored pairwise tree.** For a buffer x of capacity P with the n active elements in the prefix x[0..n)
and neutral padding in x[n..P), let P′ be the smallest power of two at or above P (lanes P..P′ are treated as
neutral without being stored). Define for a power-of-two length ℓ:

  T(lo, 1) = x[lo];   T(lo, ℓ) = T(lo, ℓ/2) ⊕ T(lo + ℓ/2, ℓ/2).

The reduction is T(0, P′). The tree is *anchored at index 0*: block boundaries are multiples of powers of two
counted from lane 0, never from the end of the active range, a tile boundary or a thread-group boundary.

**Lemma (capacity independence).** For every P ≥ n, T(0, P′) is bit-identical to T(0, p(n)), where p(n) is
the smallest power of two at or above n. Proof: a subtree that lies wholly in padding returns the neutral
element (by the third column of the table); at the node where an active left subtree meets a padding right
subtree the result is the left value unchanged; so every node above the block [0, p(n)) returns its left
child, and inside that block the tree is the same for every P.

**Compensated variant (for long accumulations inside one kernel invocation, where the manifest asks for it).**
Each node carries a pair (s, e). Combine uses the error-free two-sum written without a fused operation:
s = a + b; t = s − a; r = (a − (s − t)) + (b − t); e = (e_a + e_b) + r. The final value is
`select(e == 0, s, s + e)`. The select matters: two-sum with a −0.0 partner returns an error term of +0.0, and
adding +0.0 to a result of −0.0 would flip its sign bit; the comparison `e == 0` treats both zeros alike, so a
zero error term never touches s. Capacity independence holds for the same reason as above: a neutral partner
contributes an error term of zero. In the kernels this variant is the operator slot `sum_dd` of `K-reduce` and
`K-seg-reduce` (N21a-07), whose two-sum is the error-free sum of the IR's pair type (N21a-21); the node
arithmetic and the final select stated here are its definition, and its result is one `f32`. It is not the
double-float accumulator that carries a pair across steps.

**Host reference (DESIGN; `frob_kernels::reduce`).**
`tree_sum_f32(x: &[f32], n: usize) -> f32`, `tree_prod_f32`, `tree_min_f32`, `tree_max_f32`,
`tree_sum_comp_f32`, the `f64` twins, and `tree_plan(p: usize) -> Vec<(u8 /*level*/, u32, u32)>`, the list of
pairings, which is a function of the capacity's power-of-two ceiling only. The module `frob_kernels::reduce`
already holds the `batch-cpu` functions of `K-reduce` and `K-seg-reduce` (N21a-07, built first); the reference
functions are added beside them, written as the recursion T(lo, ℓ) above. `K-reduce` and `K-seg-reduce`, on
`batch-cpu` and in the dialect, are compared with the reference bit for bit on every backend through the kernel
harness. `batch-cpu` code written after this bead that reduces over a padded axis or over tiles (the tile
program of BD-160; reductions inside other kernels) calls the reference functions and defines no tree of its
own.

**Manifest and audit.** Every kernel manifest lists, per padded-axis reduction, the operation, the neutral
element and whether the compensated form is used. `padding_audit(kernel)`: for each such kernel, generate
active content for n lanes, run at capacities c ≥ n and 2c with the declared neutral padding, and compare
every active output bit for bit. A kernel whose manifest declares no neutral element for a buffer it reduces
fails the manifest check.

## Acceptance criteria

- [ ] `tree_sum_f32` of the single active element −0.0 returns 0x80000000 at capacities 1, 2, 32 and 64.
- [ ] For 10⁵ seeded random cases (n from 1 to 300, capacity from n to 1,024, values spanning 2⁻⁴⁰ to 2⁴⁰ with both signs and both zeros), each of the five reductions returns bits identical to its result at capacity p(n).
- [ ] `tree_plan` for a given capacity is identical whatever the worker count or tile size passed to the CPU harness (the functions take no such argument; a compile-time test pins the signature).
- [ ] The reduction kernels equal the host reference bit for bit on `batch-cpu` for the same 10⁵ cases, through the kernel harness (BD-014). On CUDA and Metal the same comparison is the stage `padding` of N35-17's script, which depends on this bead and reaches the device harnesses this bead does not; it is recorded per backend there.
- [ ] `padding_audit` passes for every kernel in the M2 library that reduces over a padded axis, at two capacities, and its result is stored with the kernel's check row.
- [ ] The compensated variant returns −0.0 for the single active element −0.0, is capacity-independent on the same random cases, and for the sequence (1, 2⁻³⁰ repeated 1,024 times) returns 1 + 2⁻²⁰ where the plain tree returns a value that differs from it.
- [ ] Each negative control below is caught by a named test.
- [ ] A 2 × 2 symmetric positive definite matrix padded to 4 × 4 with identity rows gives a factor whose leading 2 × 2 block is bit-identical to the unpadded factor.

## Test plan

### Unit tests
- `minus_zero_is_neutral_for_sum`: for x in {+0.0, −0.0, 1.0, −1.0, the smallest subnormal, +∞, −∞}: (x + (−0.0)) has the bits of x.
- `plus_zero_padding_changes_bits`: tree sum of [−0.0] padded with one +0.0 is 0x00000000; with −0.0 it is 0x80000000.
- `one_is_neutral_for_product`; `inf_is_neutral_for_min_max` (including `det_min(+0.0, −0.0)` under the dialect's rule, stated in the prelude and asserted here).
- `tree_anchored_at_zero`: for n = 3 at capacities 4, 8 and 64 the pairings among the active elements are (0, 1) then with 2; never (1, 2) first.
- `anchored_grouping_1e8`: a = 10⁸, b = −10⁸, c = 1 in lanes 0 to 2: the anchored tree gives (a + b) + (c + pad) = 1 at capacities 4, 8 and 64.
- `capacity_shaped_grouping_differs`: the seven addends (0, 0, 0, 10⁸, 1, −10⁸, 1): the anchored tree gives 0 at capacities 8, 12, 16, 18, 24, 32 and 64; a conformance tree that splits the buffer at its midpoint (⌈len/2⌉) gives 1 at capacities 12 and 24 and 0 at capacities 8, 16, 18, 32 and 64.
- `capacity_independence_property` (10⁵ cases as above, five reductions).
- `compensated_minus_zero`, `compensated_capacity_independence`, `compensated_long_sum_known_answer`: 1 followed by 1,024 copies of 2⁻³⁰: exact sum 1 + 2⁻²⁰; the plain `f32` pairwise tree over capacity 2,048 returns 0x3F800007 (one unit in the last place short); the compensated tree returns 1 + 2⁻²⁰ = 0x3F800008.
- `cholesky_padding_leading_block`: the 2 × 2 in 4 × 4 case.
- `manifest_requires_neutral_declaration`: a planted manifest without the field fails.
- `neutral_table_agrees`: for every operator slot of `K-reduce` and `K-seg-reduce` the neutral element in the
  kernel manifest equals the row of the table above (nine operators, including (0, 0) for the two-limb add); a
  planted manifest that declares +0.0 for the floating sum fails.
- `k_reduce_matches_reference`: on the 10⁵ random cases the `batch-cpu` `K-reduce` of N21a-07 returns the bits of
  `tree_sum_f32`, `tree_prod_f32`, `tree_min_f32` and `tree_max_f32`, and its `sum_dd` slot the bits of
  `tree_sum_comp_f32`.

### Known answers and negative controls
- KA-786: the sum of the one active element −0.0 at two capacities is −0.0 both times. Negative control:
  padding with +0.0.
- CX-367 (padding with +0.0 is not neutral); the dynamics chapter's grouping counterexample with 10⁸.
- Plants built by this bead (conformance builds only, each a Cargo feature of `frob-kernels`):
  `pad-plus-zero` (sum padding initialized with +0.0); `tree-midpoint-split` (a recursion that splits the
  buffer at its midpoint, so that the grouping depends on a capacity that is not a power of two);
  `min-pad-zero` (minimum padded with 0.0, which wins against positive active values); `comp-no-select` (the
  compensated fold without its final select). `pad-plus-zero` is CX-367's plant: its control row is the one
  N38b-05's seeding tool derives from CX-367 (KA-786's control cell names the same plant), and BD-160 (through
  the tile path) and N35-15 (on the `capacity` axis) fire it by this name, so it is built once. This bead
  writes no row of `controls.toml`; the other three are caught by its own tests.
- Metamorphic: appending neutral lanes changes no active output; permuting *active* elements may change a
  floating sum and is not claimed.
- Determinism lanes: the reference functions twice, across worker counts, debug and release, and across the
  two CPU architectures.

## Considerations

- One entry of the counterexample catalogue prints the canonical zero of a padded sum as +0; the rule here and
  in the dynamics chapter's text is −0.0, and KA-786 fixes it. The discrepancy is listed for the lead.
- A reduction whose active count can exceed its capacity is a capacity overflow, handled by the capacity
  policy (refuse, or continue flagged), never by truncating the tree.
- The compensated form costs about four times the additions of the plain tree; it is declared per reduction
  in the manifest and is not the default. Accumulation across steps (time offsets, odometry, the energy
  ledger) uses double-float accumulators, which are another bead.
- Cross-world reductions are a different thing: statistics across worlds never feed state (N35-14).
