## Background

Random numbers in the simulator are not drawn from generator state. They are counter-based: a draw is a pure
function of a logical identity, `(WorldAddr, step, stream_id)`, computed by the Philox block function, which
is 32-bit integer arithmetic and therefore exact on every backend (determinism class D0). No device-side
generator state exists. Common random numbers for a comparison are then free: two designs given the same
addresses see the same world.

**INV-NUM-04.** A random draw is a function of (address, step, stream) alone: not of slot, bucket, variant
index, shard, device or batch size. Its stated verification is "draw tables compared across slots, buckets,
shards and backends". The batch-independence gate (GATE-SPARK-15) includes the clause "draws depend on address
alone". The metamorphic relation of the program's register says the same thing and names the mutation that
must break it: a draw depends on (address, step, stream) only, and adding a stream changes no other stream;
mutation: sequential draws from one generator.

This bead is the draw-table test. It is separate from the digest sweeps because a digest can hide a draw
defect: if a draw were keyed by slot but the affected quantity happened to be masked in the test worlds, the
digests would agree. A table of raw draws cannot hide it. Tier: Solid.

## Scope

In: the frozen table of 4,096 addresses and its golden file, produced once by the host reference; the
comparisons of every backend against that golden file and across the five arrangements; the uniform conversion
of each backend against the host's bit patterns; the stream-addition test on the frozen table; normal variates
per backend with the cross-backend histogram; the battery's negative controls; the `draws` evidence row for the
gate; the conformance raw-draw tap that the in-situ comparison reads. This bead is the conformance battery for
invariant INV-NUM-04: it writes no generator, no key layout and no kernel. Out, with the bead that has each: the
host stream service, the address type, the key layout and its five pinned vectors (N35-22); the stream registry
and its loader, which refuses the renumbering overlay (N35-23); the device kernel `K-x-philox` and that bead's
own seed condition, which is tables over 10⁴ generated addresses × 100 steps compared across arrangements on its
own kernel, the extra-leg fixture and the kernel's mutant builds (BD-180; this bead depends on it and re-runs
the comparison as a battery against a frozen golden file on every backend); keying by physical entity (N35-24);
the digest sweeps (BD-181); the telemetry tiers and their histograms (BD-207), which carry no raw-draw channel.

## Technical approach

**The frozen address table (content-hashed; `frob-conformance/battery/draws/table.toml`).** 4,096 rows
`(world address, step or tick, stream, entity, component)` chosen to cover: every stream registered at M2;
64 world indices including 0 and 2³² − 1; episodes 0, 1 and 2³² − 1; namespaces 0 and 1; a forked address;
ticks 0, 1, 999 and 2⁶⁴ − 1; entities 0, 1 and 2³² − 1; components 0 to 3. The expected output is the golden
file `table.golden` of 4,096 × 4 `u32` words, produced once by the host reference and committed with its
BLAKE3 hash; it is never regenerated from a device.

**Anchors for the block function (FACT: the sibling library's tests carry these Random123 vectors for
Philox4x32 with ten rounds; `frankensim/crates/fs-rand/src/philox.rs`).**

| Counter | Key | Output |
|---|---|---|
| (0, 0, 0, 0) | (0, 0) | (0x6627e8d5, 0xe169c58d, 0xbc57ac4c, 0x9b00dbd8) |
| (0xffffffff ×4) | (0xffffffff ×2) | (0x408f276d, 0x41c83b0e, 0xa20bc7c6, 0x6d5451fd) |
| (0x243f6a88, 0x85a308d3, 0x13198a2e, 0x03707344) | (0xa4093822, 0x299f31d0) | (0xd16cfe09, 0x94fdcceb, 0x5001e420, 0x24126ea1) |

**Comparisons (every one is byte equality of `u32` words; rows are matched by address, never by position).**
1. *Host against golden.* The host service reproduces `table.golden`.
2. *Each backend against golden.* The addressed-draw kernel on `batch-cpu`, CUDA and Metal, given the table's
   rows as a batch, returns the golden words.
3. *Slots.* The same rows in reversed order and in three seeded permutations.
4. *Batch size.* The rows in batches of 1, 32, 1,024 and 4,096.
5. *Buckets.* The rows attached to worlds placed in two bucket capacities (the world's own and the next
   registered one).
6. *Shards.* One device against two shards (two cards on the Linux host; two environments on one device
   elsewhere).
7. *In situ.* Draws captured from inside a running step (the reset pose stream and one disturbance stream of
   workload Q, read from the telemetry tap that records raw draw words) for 64 world addresses over 100
   control intervals, in the arrangements of 3 to 6: equal per address and step.

**The raw-draw tap (DESIGN; conformance build only; built in this bead).** Comparison 7 needs the words a
running step really drew, and no telemetry bead carries such a channel. In a conformance build, each call
site of the addressed-draw kernel in the step plan also writes its four output words, with the draw address
(world address, tick, stream, entity, component), to a per-world statistics buffer of fixed capacity (64
draws per world per control interval; an overflow sets a flag and fails the comparison, it never drops
silently). The buffer is a statistics output: no kernel reads it, it is drained at the chunk fence with the
other statistics (a section of BD-207's drain handler), and enabling it changes no state digest (asserted on the 64 worlds: digests with and
without the tap are equal). A release build has no tap, and the option that enables it, `--conformance-draw-tap` on `sim.run`
(DESIGN; a conformance-only option of VERBS-sim's `sim.run` row, owned by this bead, like `--conformance-host-read`), is
refused there as an unknown parameter.

**Adding a stream.** Load the stream registry with one extra conformance stream appended (a registry overlay),
regenerate the table for the original rows, and require identical words. Then, as the negative control, load
an overlay that inserts the stream in the middle and renumbers the later identifiers: the words of the
renumbered streams must change, and the registry loader must refuse the overlay in the first place (stream
identifiers are never renumbered or reused).

**Uniform conversion per backend (PO-NUM-03 on devices).** For all 2²⁴ values v of x ≫ 8, the kernel's
`f32` result v·2⁻²⁴ equals the host's bit pattern; the largest is 0x3F7FFFFF (0.99999994) and none equals 1.0.

**Normal variates.** A normal variate is built from two uniform draws with deterministic logarithm, square
root and cosine functions (the sibling library's construction: z = √(−2·ln u)·cos(2π·v), u in (0, 1],
consuming exactly two draws). It is class D2 per backend, and D1 across backends only where the device
family's bit-equality gate passed. The test therefore asserts: per backend, the table of 4,096 normal variates
is identical run to run and across arrangements 3 to 6; across backends, the disagreement is recorded as an
integer histogram of units in the last place and is asserted to be zero only for a family whose D1 status is
`attained`.

**Evidence row.** The result is written as the `draws` field of the batch-independence record for the device
family (rows compared, arrangements, mismatches, fingerprint digest), which BD-181 cites for the gate's clause
"draws depend on address alone".

## Acceptance criteria

- [ ] The three Random123 vectors hold on the host and on every backend.
- [ ] The golden table (4,096 rows) is reproduced by the host and by each backend with zero mismatching words.
- [ ] Zero mismatches under slot permutation, batch sizes 1 to 4,096, two bucket capacities and one against two shards, on `batch-cpu` and each device family; in-situ draws agree per address and step in the same arrangements.
- [ ] Appending a stream changes no word of any existing row; the renumbering overlay is refused by the registry loader, and when forced in a conformance build it changes words and is caught.
- [ ] The uniform conversion is bit-identical to the host for all 2²⁴ inputs on each backend, with maximum 0x3F7FFFFF.
- [ ] Normal variates are identical per backend across runs and arrangements; the cross-backend histogram is stored; equality across backends is asserted only where D1 is attained.
- [ ] The raw-draw tap exists only in a conformance build: with it enabled the state digests of the 64 in-situ worlds equal those without it; a release build refuses the option as an unknown parameter; an overflow of the 64-draw buffer fails the comparison and is never dropped silently.
- [ ] Each negative control below is caught, and the evidence row is written for each device family.

## Test plan

### Unit tests
- `philox_random123_vectors` (host).
- `draw_table_matches_golden_host`; `draw_table_golden_hash_frozen` (the committed BLAKE3 equals the file's hash).
- `draw_table_address_coverage`: the table contains every registered M2 stream and the boundary values listed.
- `draw_rows_matched_by_address`: a comparison of two tables in different row orders reports equality.
- `raw_draw_tap_changes_no_digest`: 64 worlds of workload Q for 100 control intervals on `batch-cpu`, with and without the tap: identical digest chains; `raw_draw_tap_overflow_fails`: a world forced to 65 draws in one control interval sets the flag and the comparison fails.
- `draw_in_situ_arrangements` (comparison 7 on the backend selected by `FROB_TEST_DEVICE`, `batch-cpu` by default): 64 world addresses over 100 control intervals in the arrangements of comparisons 3 to 6, tapped words equal per address and step; `draw_in_situ_controls`: `slot-keyed-draws` fails comparison 3 and `counter-reset` fails comparison 7 at the second chunk.
- `append_stream_changes_nothing`; `renumber_stream_refused`.
- `uniform_exhaustive_host_reference` (delegates to N35-22's exhaustive test and checks the device harness reads the same expected file).
- `normal_table_per_backend_repeatable` (`batch-cpu`).

### End-to-end script and logging
This bead's own lane is `scripts/e2e/draw_tables.sh [--backend batch-cpu|gpu-cuda|gpu-metal] --seed <s>`:
`table` (`FROB_TEST_DEVICE=<id> cargo test -p frob-conformance --features frob-core/conformance draw_table_`
with the backend selected; the table's rows become addresses through `DrawAddr::from_parts`, which exists only
with frob-core's `conformance` feature, and that feature never compiles under `--release` (N38b-04's guard):
the golden table, the Random123 vectors, arrangements 3 to 6, the 2²⁴ uniform conversions, the normal variates);
`in_situ` (conformance build: the four arrangements of 3 to 6 through `FROB_TEST_DEVICE=<id> cargo test -p
frob-conformance --features gauntlet-mutations draw_in_situ_`, never under `--release`, where the umbrella does
not compile (BD-025), which places the 64 world addresses in permuted slots, in batch sizes,
in two bucket capacities and on one and two shards; then through the verb, `frob sim run --tier <t> --workload Q
--worlds 64 --seconds 2 --seed <s> --conformance-draw-tap --key dt-64-<t>-<run-id> --json` and the same with
`--worlds 1024 --key dt-1024-<t>-<run-id>` (the first 64 addresses inside a larger batch), the tapped words read
back and compared per address and step; and once without the tap, `--key dt-notap-<t>-<run-id>`, the digests
with and without the tap compared with `frob telemetry divergence <tap> <no tap> --mode exact --json`; each call
its own key); `streams` (the appended-stream overlay and the refused renumbering overlay);
`controls` (the sequential generator and full-word conversion builds of BD-180; `slot-keyed-draws` from N35-15
and `counter-reset`, each caught in `draw_in_situ_`). A missing device gives a `skip` event, never counted as
passed. The later lane is `scripts/e2e/num_batch_invariance.sh` (bead
N35-17), step `draws`, which adds `frob spark check --kernel K-x-philox --sweeps all` on each backend. The lane
logs through the STD-E2E helper to `target/e2e-logs/draw_tables/<utc>.ndjson`: `cmd` lines with exit code and
wall time, the evidence block, `metric` lines per backend and arrangement
(`rows`, `words_compared`, `mismatches`, threshold 0), the uniform-conversion count (2²⁴, mismatches 0), the
normal-variate histogram across backends, and on failure the first mismatching row (address, step, stream,
entity, component) with both words.

### Known answers and negative controls
- KA-795: a random draw is a function of (address, step, stream) alone; adding a stream changes no draw of any
  other stream. KA-794 on each backend (the uniform conversion).
- Metamorphic relation MR-03, with its mutation (sequential draws from one generator).
- Negative controls: `slot-keyed-draws` (N35-15: fails comparison 3); a sequential generator substituted for
  the addressed kernel (fails comparisons 3 and 4, since the n-th draw depends on how many came before);
  `counter-reset` (N21b-42's mutant, reused by name and not built again: the step counter restarted at each
  chunk, which fails comparison 7 at the second chunk); the
  renumbering overlay; a uniform conversion that scales the full 32-bit word (returns 1.0 for 0xFFFFFFFF and
  fails the range check). The sequential generator and the full-word conversion are the mutant builds BD-180
  keeps for its kernel (`sequential_per_world_counter` and `float_scale_by_division` in
  `crates/frob-kernels/tests/support/philox_mutants.rs`); the battery runs those builds and writes no second
  copy of them.
- Determinism lanes: every comparison twice; `batch-cpu` across worker counts and across the two CPU
  architectures.

## Considerations

- The integer draws are class D0, so there is no tolerance anywhere in this test except the recorded
  cross-backend histogram for normal variates.
- The raw-draw telemetry tap exists for conformance; it is a statistics output and never feeds state.
- If kill gate KILL-D1 fires for a family, normal variates differ across backends by construction and a
  world teleported from that family is a tolerance replay; the integer draws still agree exactly, which keeps
  common random numbers common.
- 64-bit ticks and the three-level key layout of N35-22 (world key, stream key, draw block) must be computed
  in 32-bit limbs on devices that lack 64-bit integers; the boundary rows (2⁶⁴ − 1, 2³² − 1) are in the table for that reason.
