## Background

The program claims that a world's trajectory does not depend on the batch it ran in: the same bits alone, in
any batch, at any slot, beside any co-tenants, in any bucket it fits and on any number of shards of one device
family. Two gates measure it. GATE-SPARK-15 (Known answer; TARGET; earliest M2): for 1,000 episodes of each
reference workload, per-world digests are identical alone, in 100 random co-tenancies, under slot permutation,
at two bucket capacities and on one and two shards, on `batch-cpu` and on each device family; draws depend on
address alone; the negative controls of the chapter's known-answer table are caught. GATE-KIN-05 (Known
answer; earliest M2): 1,000 episodes with identical digests solo and in 100 random co-tenancies, capacities
and slot assignments, per back end; the path-table Jacobian gives the same digests as the dense one.

A gate is recorded only from a run of the real binaries on the real machines, with measured values and with
its negative controls shown to fail. This bead is that run as a script: plain shell, seed-explicit,
idempotent, exiting non-zero on any failed assertion, with a structured log. It adds no mechanism. Tier:
Solid.

## Scope

In: the script, its steps, assertions and log lines; the reduced rehearsal mode; the gate-recording hand-off.
Out: everything the script calls (BD-181, N35-13 to N35-16).

## Technical approach

**Invocation.** `scripts/e2e/num_batch_invariance.sh [--tier batch-cpu|gpu-cuda|gpu-metal|all]
[--workloads Q,H] [--episodes 1000] [--cotenancies 100] [--seed N] [--rehearsal]`. Defaults: every tier
present on this machine, both workloads, gate size, the world set's frozen run seed (`--seed` seeds the
co-tenancy plans, default 1). `--rehearsal` sets 64 episodes and 8 co-tenancies, fits the default compute
envelope, and never reaches the `gate` step.

**Steps (each a `step` value in the log).**
1. `preflight`: `frob --json doctor`; `frob --json spark devices`; where the estimate verb exists (BD-219),
   `frob --json sim estimate` for the matrix, asserting the compute class in force admits it (otherwise the
   script stops with the refusal logged and suggests `--rehearsal`). Where it does not exist yet, the
   sub-step is logged as a `skip` event `capability absent` (never counted as passed), and the compute-envelope admission of the first gate-size
   invocation (`FROB-REF-761`, exit 4, N36-20) is the stop instead: the script treats that refusal as the
   preflight's, logs it, suggests `--rehearsal` and writes no gate evidence.
2. `world_set`: verify the content hashes of the Q and H world sets and of the four fixture worlds.
3. `conditions`: `frob --json spark check --conditions --plan <id> --backend <tier> --key
   nbi-conditions-<w>-<tier>-<run-id>` for each reference step plan and tier; assert eight static passes and
   eight fixture passes.
4. `padding`: `frob --json spark check --kernel K-reduce --backend <tier> --sweeps capacity --key
   nbi-padding-<tier>-<run-id>`, then the per-kernel padding audit over each step plan; assert zero bit
   mismatches.
5. `draws`: `frob --json spark check --kernel K-x-philox --backend <tier> --sweeps all --key
   nbi-draws-<tier>-<run-id>` on each tier, then the stages of N35-16's `scripts/e2e/draw_tables.sh`: the
   draw-table comparisons (golden, slots, batch sizes, buckets, shards, in situ, the appended stream, the
   uniform conversion over 2²⁴ values); assert zero mismatching words.
6. `alone`: `frob --json spark check --invariance --workload <w> --backend <tier> --axes alone --episodes <E>
   --key nbi-alone-<w>-<tier>-<run-id>` (the reference digests).
7. `cotenancy`, `slot`, `capacity`, `shard`, `jacobian`: one invocation per axis and workload, `frob --json
   spark check --invariance --workload <w> --backend <tier> --axes <axis> --episodes <E> --cotenancies <C> --key
   nbi-<axis>-<w>-<tier>-<run-id>`; assert zero digest mismatches against step 6.
8. `repeat`: step 6 again for 64 worlds under key `nbi-repeat-<w>-<tier>-<run-id>`; assert identical digests
   (the run-to-run half of class D2).
9. `controls`: for each mutant of the specificity matrix and each axis it is keyed on, the two arrangements
   with `--mutant <name>` (N21b-42's loader, no key suffix) and keys `nbi-ctl-<name>-<axis>-<w>-<tier>-<arm>-<run-id>`;
   assert the digests differ and that `frob --json telemetry divergence` names the planted kernel; for each
   mutant, one axis it is not keyed on, asserting equality.
10. `record`: `frob --json spark check --invariance --report --workload <w> --key nbi-record-<w>-<run-id>`
    (BD-181's form: no run, every device family's stored record printed, the key still required) to read back
    the composition record of each device family; assert each is current and names the audit and draw-table
    records.
11. `gate`: `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g5_determinism -- GATE-SPARK-15
    GATE-KIN-05`, which writes the hash-named receipts; the recording session enters each with `cargo run -p
    frob-conformance --example record_gate -- --gate <id> --receipt <hash>`.
12. `summary`.

Every `spark check` and `sim run` call carries its own idempotency key (`--key nbi-<step>-<w>-<tier>-<arm>-<run-id>`;
both are `run` verbs): arrangements compared with each other never share a key, and each envelope must show
`idempotent_replay: false`, since a reused key returns the stored receipt and would compare a run with itself.

**Assertions tied to numbers.** `digest_mismatches == 0` for every axis, workload and tier, over
`worlds == 1004` (1,000 tested worlds and four fixture worlds) and the stated arrangement counts
(100 co-tenancies; 5 slot orders; 2 bucket capacities × 3 contact capacities; 2 shard arrangements; 2
Jacobian variants); `draw_word_mismatches == 0`; `uniform_values == 16777216` with maximum pattern
`0x3F7FFFFF`; `controls_caught == controls_run` for the keyed axes.

**Logging.** The script sources the shared helper of STD-E2E and writes newline-delimited JSON to
`target/e2e-logs/num_batch_invariance/<utc-timestamp>.ndjson` and a human-readable transcript beside it. Every
line has `ts`, `script`, `bead` (`N35-17`), `step`, `event` (`start`, `cmd`, `assert`, `metric`, `refusal`,
`end`), the exact command line, exit code and wall time. `cmd` lines carry the envelope's `evidence` block
(claim known-answer, class, tier, determinism D2, identities with the fingerprint digest, the world-set hash
and the step plan identity, seed). `metric` lines carry, per axis: `worlds`, `episodes`, `arrangements`,
`world_steps`, `digest_mismatches` with threshold 0, and the run digest (the wrapping sum of per-world digests
keyed by address) of each arrangement. `assert` lines carry expected and observed values. On failure the log
gives the arrangement, the first differing world address, the chunk, step, stage, kernel and quantity, both
bit patterns, and the paths of both digest chains and of the first-divergence record. The final `summary`
line counts assertions passed and failed and names GATE-SPARK-15 and GATE-KIN-05. Worlds are named by address;
no scene geometry or other private-scene data is written.

**Hand-off.** The script does not write `registries/gates.toml`. A recording session that did not implement
the work reads the log and the receipts and enters one row per gate, backend and workload.

## Acceptance criteria

- [ ] The script exits 0 only if every assertion passed; a second run with the same options reproduces the same run digests for every arrangement.
- [ ] At gate size on `batch-cpu`, on each RTX 4090 pair (two shards) and on Metal, every axis reports zero mismatches for Q and H, and the `gate` step passes.
- [ ] Every keyed control is caught and localized to its planted kernel; every unkeyed check passes; the racy mutant is counted only on families where it was admitted, and is logged `not-discriminating` elsewhere.
- [ ] `--rehearsal` completes inside the default compute envelope, exits 0 on equality, and its summary states that no gate was measured.
- [ ] When the compute class in force does not admit the gate-size matrix, the script stops (in `preflight` through `sim estimate` where that verb exists, otherwise at the first gate-size invocation's `FROB-REF-761`) with the refusal code logged and writes no gate evidence.
- [ ] The log validates against the STD-E2E line schema.

## Test plan

### Unit tests
The script has no unit tests of its own; `scripts/e2e/tests/num_batch_invariance.bats` (run by the harness's
self-test) checks: option parsing; that `--rehearsal` never reaches `gate`; that a simulated mismatch in
step 7 makes the script exit non-zero with the failure counted in `summary`; that a simulated uncaught control
in step 9 does the same; that the log lines validate against the schema.

### End-to-end script and logging
This bead is the script; see the steps and logging above.

### Known answers and negative controls
- KA-785 (steps 6 and 7), KA-786 (step 4 and the fixture world), KA-787 (step 3 and the fixture world), KA-795
  and KA-794 (step 5).
- CX-367, CX-368.
- Negative controls exercised: the ten mutants of the specificity matrix in step 9; a stale fingerprint in
  `preflight` on a conformance run (the script must stop before step 3).
- Determinism lanes: step 8 (twice on one machine); `batch-cpu` is additionally run at two worker counts in
  step 6, once with `--workers 1` and once with `--workers 8` (each with its own key), and must give equal digests.

## Considerations

- At gate size the `alone` axis is the slow one on devices (a thousand batch-of-one runs). The script runs it
  once per workload and tier and reuses its digests for every other axis.
- Two shards need both cards on the Linux host; on the Mac the shard axis uses two environments on one device
  and the log records which form ran.
- If a device family fails an axis, the script still completes the other tiers and exits non-zero; the failed
  family's composition record is written as failed, which removes its class D2 and with it bit-exact pairing,
  forks and attribution on that family.
- The M2 stop decision reads this script's outcome: if no device family passes, M2 exits in its no-GPU
  variant.
