## Background

Distributional summaries (the 95th percentile of knee torque, the distribution of disagreement between two
backends) are needed everywhere, and the usual tools for them are mergeable quantile sketches. Their output
depends on insertion and merge order: the same worlds replayed under a different shard split give different
bits, which breaks determinism class D2 for anything computed from them.

The smallest case: a two-centroid sketch that merges its closest pair, fed {0, 3, 5, 9}. In the order 0, 3, 5,
9 it ends as (8/3 with weight 3; 9 with weight 1); in the order 0, 9, 5, 3 it ends as (1.5 with weight 2; 7
with weight 2). Same data, different sketch, so the statistic depends on shard count and arrival.

The rule of the numerics chapter replaces sketches by integer log-bin histograms: the bin is the sign, the
exponent and the top five mantissa bits of the `f32` pattern, so a bin is at most 3.2% wide; counts are
integers; merging is addition; a quantile is reported as a bin interval. Integer counts added in any order
give the same counts, so the histogram is exact, mergeable across shards and identical on every backend. The
price is resolution, and the rule is honest about it: a quantile read from a histogram is an interval, never a
point that was not measured (one of the three wording rules enforced by schema).

This bead is the law and the host types. The device kernel that fills histograms and the telemetry verb are
the telemetry unit's seed bead; they must reproduce these types' results. Tier: Solid.

## Scope

In: the bin function over `f32` patterns; the integer-magnitude bin function used for counts such as
units in the last place; the histogram type with merge; quantiles as intervals; the serialized form; law
tests; the sketch counterexample as a registered negative control. Out: device accumulation, draining and
width rules (BD-207); the telemetry verb; channel quanta.

## Technical approach

**Bin function for floating values (DESIGN; `frob_core::hist`).**

  `bin14(x) = bits(x) ≫ 18`   (a 14-bit index: 1 sign bit, 8 exponent bits, the top 5 of 23 mantissa bits).

There are 16,384 bins. For a normal positive value in [2^e, 2^(e+1)) the bin has absolute width 2^(e−5), so its
width relative to its lower edge is at most 2⁻⁵ = 3.125% (the "at most 3.2%" of the rule). Properties:

1. The bin depends only on the bits of x; no comparison, logarithm or rounding is evaluated.
2. +0.0 is bin 0 and −0.0 is bin 8,192; they are distinct bins and both are reported.
3. Positive bins increase with value; negative bins (index 8,192 and above) increase with magnitude. The value
   order of bins is: negative bins by descending index, then positive bins by ascending index.
4. Infinities and NaNs fall in the bins with exponent 255 (indices 8,160 to 8,191 and 16,352 to 16,383). They
   are counted and reported as `non_finite`, and are excluded from quantiles with their count stated.
5. Subnormals (exponent 0) share bins of absolute width 2⁻¹³¹; the relative-width bound does not apply below
   the smallest normal number, and the interval returned says so by its bounds.
6. Bin bounds: lower = `from_bits(b ≪ 18)`, upper (exclusive) = `from_bits((b + 1) ≪ 18)` for positive finite
   bins; mirrored for negative ones.

**Bin function for non-negative integers (for distances in units in the last place, counts and other integer
quantities).** With sub-bucket exponent s (default 5): for q < 2ˢ the bin is q itself (exact); otherwise with
e = ⌊log₂ q⌋ the bin is ((e − s + 1) ≪ s) | ((q ≫ (e − s)) & (2ˢ − 1)), computed with count-leading-zeros,
shifts and masks. Every bin's width is at most 2⁻ˢ of its lower edge. This is the same octave-splitting rule
the telemetry chapter applies to channel-quantized values; one implementation serves both.

**Histogram.**

```rust
pub struct Hist14 { counts: BTreeMap<u16, u64> }           // sparse, ordered; integers above 2^53 serialize as strings
impl Hist14 {
    pub fn add(&mut self, x: f32);                          // counts[bin14(x)] += 1
    pub fn merge(&mut self, other: &Hist14);                // integer addition per bin
    pub fn total(&self) -> u64;
    pub fn quantile(&self, q: Rational) -> Result<QuantileInterval, Refusal>;
}
pub struct QuantileInterval { lower: f32, upper: f32, bin: u16, rank: u64, n: u64, excluded_non_finite: u64 }
```

`merge` is commutative and associative because it is integer addition; a histogram built from any partition
of a multiset of values, merged in any order, equals the histogram built from the whole.

**Quantile.** For q in (0, 1], given as an exact rational: n = the count of finite samples; rank r =
max(1, ⌈q·n⌉) computed in integers; walk the bins in value order accumulating counts until the running total
reaches r; return that bin's bounds as the half-open interval [lower, upper), with r and n. With n = 0 the
call refuses (there is no quantile of nothing). `QuantileInterval` has no method that returns a single number:
a consumer that wants a point must choose a bound and say which.

**Serialized form (`frob.hist14/1`).** `{ "bins": [[index, "count"], …] in ascending index, "non_finite":
"count", "n": "count" }`; counts are decimal strings (they may exceed 2⁵³). A quantile is serialized as
`{ "lower": …, "upper": …, "bin": …, "rank": "…", "n": "…" }`. The envelope schema types every histogram
quantile as this object; a scalar in its place fails validation.

**Worked case.** {0, 3, 5, 9}: patterns 0x00000000, 0x40400000, 0x40A00000, 0x41100000; bins 0, 4,112, 4,136,
4,164; one count each, in either insertion order. Bin bounds: [3.0, 3.0625), [5.0, 5.125), [9.0, 9.25). The
median (q = ½, r = 2) is the interval [3.0, 3.0625); the 75th percentile (r = 3) is [5.0, 5.125).

## Acceptance criteria

- [ ] `bin14` equals `bits ≫ 18` for all 2³² patterns (exhaustive test), and bin bounds contain their value for every finite pattern.
- [ ] For every positive normal bin, (upper − lower)/lower ≤ 2⁻⁵ exactly computed (checked for all 8,128 positive normal bins).
- [ ] The histogram of {0, 3, 5, 9} is identical in the orders (0, 3, 5, 9) and (0, 9, 5, 3): bins 0, 4,112, 4,136 and 4,164 with count 1 each.
- [ ] Merge is order-independent: for 10⁴ seeded cases, a multiset of 1,000 values split into 1 to 8 parts and merged in a random order gives the histogram of the whole, bin for bin.
- [ ] `quantile` returns intervals, with the worked values above; it refuses on an empty histogram; non-finite samples are excluded and counted.
- [ ] The type exposes no scalar quantile; the envelope schema rejects a scalar where a histogram quantile is declared.
- [ ] The integer bin function at s = 5 maps 0 to 31 exactly, and its bins above have relative width at most 2⁻⁵ (checked for all q below 2²⁴).
- [ ] The two-centroid sketch control produces two different summaries for the two orders, and the registered negative control records it.

(2) where the telemetry verb exists, `frob --json telemetry histogram <run> --channel <c> --quantile 0.95` on

### Known answers and negative controls
- KA-800: the set {0, 3, 5, 9} histogrammed in two orders gives identical histograms. Negative control: the
  closest-pair two-centroid sketch.
- The telemetry chapter's own smallest case for order dependence: a compactor of capacity two that keeps the
  lower of each sorted pair summarizes 1, 2, 3 as {1 with weight 2, 3} and 3, 2, 1 as {2 with weight 2, 1},
  medians 1 and 2; integer bin counts are 1, 1, 1 in both orders.
- Metamorphic: permuting the samples, or re-partitioning them into shards, leaves the histogram unchanged.
- Determinism lanes: the type is integer arithmetic (class D0): identical twice, across worker counts, build
  profiles and CPU architectures.

## Considerations

- Two parametrizations appear in the program's text: bins taken from the `f32` pattern (this chapter) and
  bins of a channel value quantized by a declared quantum with 2ˢ sub-buckets per octave (the telemetry
  chapter; defaults 24 magnitude bits and s = 5 for run-level histograms, 16 bits and s = 3 for per-world
  ones). Both are integer-count histograms with the same octave-splitting rule; this bead implements the
  pattern form and the integer form and leaves the quantum and the device kernel to the telemetry bead. The
  difference is listed for the lead.
- A 3% bin is coarse for a tail percentile of a narrow distribution. The repair is a channel quantum chosen
  for the channel, not interpolation inside a bin.
- Per-world histograms on devices use narrower counters with saturation; saturation is reported, never
  silent.
