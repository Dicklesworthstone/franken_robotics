## Background

Random numbers in the simulator are counter-based streams keyed by logical identity,
`(WorldAddr, step, stream_id)`, built on the sibling simulation library's Philox streams. No generator state
exists anywhere: a draw is a pure function of its address. Consequences the rest of the program relies on:
common random numbers for a comparison are free (two designs given the same addresses see the same world);
replay needs no saved generator state (a snapshot stores only the step counter); a draw cannot depend on slot,
bucket, variant index, shard, device or batch size.

The numerics chapter adds five properties (DESIGN): draws are exact; a draw depends on nothing else; streams
are registered; streams are keyed by the physical entity they perturb; proposal draws carry exact weights.
This bead delivers the first two on the host: the address, the key layout and the conversions. The registry is
N35-23, entity keying is N35-24 and proposals are N35-25. The device kernel that computes the same function in
the kernel dialect is the seed bead for randomness by address at M2; this host service is needed at M1, when
the referee, the first sensors, the task language and the two study types all draw on the CPU.

FACT (the sibling crate, `frankensim/crates/fs-rand/src/lib.rs` and `philox.rs`, to be re-read at admission):
the block function is Philox4x32 with ten rounds, pure integer arithmetic; a stream is identified by
`StreamKey { seed: u64, kernel: u32, tile: u32 }`; `Stream::at(key, index: u64) -> [u32; 4]` evaluates it at
counter `[index_lo, index_hi, tile, kernel]` under key `[seed_lo, seed_hi]`; a 64-bit draw is
`(word1 ≪ 32) | word0`; a uniform `f64` is `(u64 ≫ 11)·2⁻⁵³`; a standard normal is Box–Muller on the library's
deterministic `sqrt`, `ln` and `cos`, with u = 1 − uniform in (0, 1], consuming exactly two draws; the ziggurat
path is not admitted to strict use.

**Draws are exact.** Philox is 32-bit integer arithmetic, so a draw is determinism class D0 on every backend.
A uniform `f32` in [0, 1) is (x ≫ 8)·2⁻²⁴, which is exact (PO-NUM-03). A normal variate built from
deterministic floating-point functions is class D2 per backend, and D1 across backends only where the device
family's bit-equality gate passes. Tier: Solid.

Alternative rejected: one generator per world advanced in sequence. One extra draw shifts every later draw, so
adding a sensor or a leg changes the disturbances of everything else, and a retry or a fork must save and
restore generator state.

## Technical approach

**Types (DESIGN; `frob_core::addr`).**

```rust
pub struct WorldAddr { pub run_seed: u64, pub namespace: u32, pub world: u32, pub episode: u32, pub fork: u32 }
pub struct StreamId(pub u32);                 // registry-assigned, stable, never reused (N35-23)
pub struct DrawAddr { pub world: WorldAddr, pub stream: StreamId, pub entity: u32, pub tick: u64, pub component: u32 }
```

`fork` is 0 for a recorded world; a fork's child has its own address (a non-zero fork word assigned by the
fork mechanism from the parent's fork word, the fork tick and the child's index). `namespace` separates
address spaces that must be disjoint by construction (discovery and confirmation); it is compared as an
integer. `tick` is the integer time or step counter the stream is indexed by; `entity` and `component` are the
stream's own sub-keys (N35-24).

**Key layout (DESIGN; one layout for host and devices, written with 32-bit operations only so that the device
kernel is a line-by-line port).** With P(counter[4], key[2]) the Philox4x32-10 block function:

1. World key, a function of the address alone:
   k = P([world, episode, namespace, fork], [run_seed_lo, run_seed_hi]).
2. Stream key, a function of the address, the stream and the entity:
   s = P([stream, entity, k₂, k₃], [k₀, k₁]).
3. Draw block, a function of all of the above, the tick and the component:
   b = P([tick_lo, tick_hi, component, 0], [s₀, s₁]).

`block(addr) -> [u32; 4]` returns b. Through the sibling's API,
P(c, key) = `Stream::at(StreamKey { seed: key₀ | key₁ ≪ 32, kernel: c₃, tile: c₂ }, c₀ | c₁ ≪ 32)`, so no
function beyond `Stream::at` is needed from the airlock. Each stream consumes whole blocks: a consumer that
needs more than four words of one (tick, entity) uses successive `component` values.

**Why three levels.** The world key isolates worlds under one run seed; the stream key makes every (stream,
entity) pair an independent stream, so adding a stream or an entity changes no draw of any other; the last
level gives random access in time. Nothing in the layout refers to a slot, a batch or a device.

**Conversions.**
- `uniform_f32(word) = (word ≫ 8) as f32 · 2⁻²⁴`. Exact, in [0, 1 − 2⁻²⁴]: an integer below 2²⁴ is
  representable in `f32` and multiplication by a power of two is exact (PO-NUM-03). The largest value is
  0.99999994 (pattern 0x3F7FFFFF); 1.0 is never returned.
- `uniform_f64(word0, word1) = (((word1 ≪ 32) | word0) ≫ 11) as f64 · 2⁻⁵³`, exact, as the sibling does.
- `normal_f64(addr)`: from one block, u = 1 − uniform_f64(b₀, b₁) in (0, 1], v = uniform_f64(b₂, b₃),
  z = det_sqrt(−2·det_ln(u))·det_cos(2π·v), with the sibling's deterministic functions. One block per normal.
- `normal_f32(addr)` (the `batch-cpu` twin of the device kernel): u = 1 − uniform_f32(b₀) in [2⁻²⁴, 1],
  v = uniform_f32(b₁), the same formula with the dialect's `det_*` functions in `f32`.
- `below(addr, n)`: a uniform integer in [0, n) by the widening-multiply method with deterministic rejection;
  a rejected candidate takes the next `component`, so the number of blocks consumed is a pure function of the
  address.

**Classes.** `block`, both uniforms and `below` are class D0. `normal_f64` is D2 on the host, and identical
across CPU architectures to the extent the sibling's deterministic functions are (the sibling states that
aim); `normal_f32` is D2 per backend. A referee world in `f64` and a device world in `f32` reading "the same"
normal draw therefore read the same integers and values that differ in rounding: the pair is class D3.

## Acceptance criteria

- [ ] The block function reached through the airlock reproduces the three Random123 vectors for Philox4x32 with ten rounds.
- [ ] `block` reproduces the five pinned vectors; changing any one field of the address changes the block.
- [ ] PO-NUM-03 is discharged exhaustively: for all 2²⁴ values v, `uniform_f32(v ≪ 8)` equals v·2⁻²⁴ exactly (the product v·2⁻²⁴ converted back by ·2²⁴ is v), is at least 0 and below 1; the maximum is 0x3F7FFFFF.
- [ ] The eight low bits of the word do not affect `uniform_f32` (the conversion uses the top 24 bits only).
- [ ] `normal_f64` consumes one block and equals the sibling's Box–Muller applied to the same four words; over 10⁶ addressed draws the sample mean is within ±0.004 and the variance within ±0.006 of 0 and 1.
- [ ] `below(addr, n)` is in [0, n) for 10⁶ cases and its rejection path consumes successive components deterministically.
- [ ] No API in the service takes a slot, a batch size, a device or a thread identifier; a compile-time test pins the signatures.
- [ ] `CONTRACT.md` of each crate states the layout, the classes of each function and the pinned vectors.

## Test plan

### Unit tests
- `philox_random123_vectors`: counter 0⁴ and key 0² → (0x6627e8d5, 0xe169c58d, 0xbc57ac4c, 0x9b00dbd8); all-ones → (0x408f276d, 0x41c83b0e, 0xa20bc7c6, 0x6d5451fd); the π-digit case → (0xd16cfe09, 0x94fdcceb, 0x5001e420, 0x24126ea1).
- `block_pinned_vectors` (the five rows).
- `block_field_sensitivity` (property): flipping one bit of any field changes at least one output word, over 10⁴ random addresses.
- `uniform_f32_exhaustive`: all 2²⁴ values.
- `uniform_f32_never_one`: the word 0xFFFFFFFF gives 0x3F7FFFFF; the conformance variant `word as f32 · 2⁻³²` gives 1.0 for the same word and is rejected by the range assertion.
- `uniform_f64_matches_sibling`: equality with the sibling's `next_f64` on the same block words for 10⁴ cases.
- `normal_f64_matches_sibling_box_muller`; `normal_moments` (10⁶ draws).
- `normal_f32_u_range`: u = 1 − uniform_f32 is never 0 (smallest 2⁻²⁴), so the logarithm's argument is positive.
- `below_range_and_rejection`: n = 3, 10, 2³¹ + 1; the number of blocks consumed equals the count predicted from the words.
- `signatures_have_no_slot` (compile-time).
- `stream_independence_smoke`: correlation between the first words of streams 1 and 2 over 10⁵ addresses is within ±0.01.

### End-to-end script and logging
`scripts/e2e/num_host_streams.sh [--seed N]`: (1) `cargo test -p frob-fsim rand_` and
`cargo test -p frob-core addr_`, including the exhaustive uniform test; (2) `frob --json sim run --tier
referee` on a conformance fixture of this bead (the built-in single-robot rollout with its initial base
velocity perturbed by one addressed normal draw), twice, then with a second, unused stream registered through
a conformance overlay: assert identical digests in all three runs (a draw depends on its
address only; adding a stream changes nothing); (3) the same world as world index 5 of two different run
requests of different sizes: identical digests. Logs through the STD-E2E helper to
`target/e2e-logs/num_host_streams/<utc-timestamp>.ndjson`: `cmd` lines with exact command line, exit code and
wall time; the evidence block (class, tier referee, determinism D2, identities, seed); `metric` lines for the
exhaustive count (16,777,216 values, 0 mismatches) and the pinned vectors; digests of the three runs; a
`summary` line.

### Known answers and negative controls
- KA-794: u = (x ≫ 8)·2⁻²⁴ is exact and lies in [0, 1); exhaustive over 2²⁴ values.
- KA-795 on the host: a draw is a function of (address, step, stream) alone.
- Negative controls: the full-word conversion that returns 1.0; a layout variant that omits the stream from
  level 2 (two streams then return the same block; `block_field_sensitivity` fails); a sequential generator
  substituted in the referee fixture (the digests of step 2 change when the unused stream is added).
- Determinism lanes: every test twice, across worker counts, debug and release, and on both CPU
  architectures; the integer functions must agree bit for bit across architectures.

## Considerations

- The layout is a public contract: changing it changes every random draw of every stored run. It carries a
  version (`address scheme version`, part of every run's pins), and a change is a new version, never an edit.
- The seed bead for the device kernel must port this exact layout; the draw-table test (N35-16) compares the
  two. If that bead's owner needs a different layout for a device reason, the layout changes here first and
  the pinned vectors with it.
- Three block evaluations per draw block is about 60 integer multiplications; on the host this is negligible
  beside a physics step, and on devices it is paid once per (world, stream, entity, tick).
- 32-bit `entity` identifiers that come from hashes of names can collide; the registry (N35-23) checks for
  collisions within a design at load time and refuses a design that has one.
- The sibling moves fast; the facts above are re-read at the pinned commit, and the airlock's admission test
  for `fs-rand` runs the Random123 vectors on every pin move.
