## Background

Every random draw in the simulator is a pure function of an address: the world address
`(run_seed, world, episode)`, a tick, and a `stream_id` (with an entity and a component as sub-keys). The
numerics chapter requires that **streams are registered**: `stream_id` names a purpose (disturbance, each
sensor's noise, reset pose, each randomized parameter, action sampling, minibatch permutation) in a registry,
and adding a stream changes no draw of any other stream.

The second half is what makes experiments comparable over the life of the project. If stream identifiers were
positions in a list, inserting a stream would renumber the ones after it and silently change every later
draw: a study re-run after an unrelated feature landed would meet different worlds. With registered, stable
identifiers that enter the key (the stream key is derived from the world key, the stream identifier and the
entity), a new stream is a new function and leaves the old ones untouched.

The task language adds a second role for the registry. Every draw in a task's `randomization` section declares
one of four **exposure domains**, which say what kind of physical thing the draw belongs to and therefore what
it is keyed by, and "the stream registry holds the domains":

| Domain | Key, beside the world address and the stream | Meaning | Example |
|---|---|---|---|
| `field` | An anchored coordinate cell or a fixture identifier | Sampled once per world at stable coordinates; a robot reads it where it is | Friction of a floor tile; the mass of a cart in the scene |
| `process` | A node of the dyadic tree over physical time | An exogenous process in physical time; a change of step or control rate reads the same path | A gust; a push scheduled at 3 s |
| `event` | A mission role and an occurrence index | Exists only where the task defines the exposure by a declared mission event | A push when the base first crosses the docking gate |
| `private` | The hash of a port name | Noise with no counterpart in the other arm | Noise of a sensor that only one design carries |

Several other subsystems need streams of their own that must be disjoint from every physics draw: the
telemetry reservoir chooses which worlds to trace by a hash of the address under its own stream; the sampled
background referee, promotion sampling, bootstrap intervals, adversarial search, audits, certification draws
and counterfactual perturbations all do the same. This bead creates the registry, its rules and its first
rows. Tier: Solid.

## Scope

In: the registry file and schema; identifier rules; the generated constants; the loader and its checks; the
entity-hash function and collision check; the first rows; the registry version as a pin. Out: the draw service
(N35-22); the rule that says which entity a stream is keyed by and its tests (N35-24); the task compiler's
exposure table and the coupling test (the task unit); the device kernel (BD-180).

## Technical approach

**File and row (DESIGN; `registries/streams.toml`, schema `frob.streams/1`).**

```toml
[[stream]]
id        = 6                    # u32; never reused, never renumbered; 0 is reserved
name      = "sensor-noise"       # the purpose; lower-case with hyphens; unique
domain    = "private"            # field | process | event | private | engine
entity    = "port-name-hash"     # what the 32-bit entity sub-key is
tick      = "sample-index"       # what the 64-bit tick is
component = "channel"            # what the component index is
owner     = "frob-sense"         # crate
since     = 1                    # registry version in which the row appeared
status    = "active"             # active | retired
```

**Rules.**
1. Identifiers are assigned once, in increasing order of registration, and never reused or renumbered. A
   retired stream keeps its row with `status = "retired"`; its identifier is a tombstone.
2. Names are unique. A purpose that covers many entities ("each sensor's noise", "each randomized parameter")
   is one row; the entity sub-key distinguishes the members.
3. `domain = "engine"` marks a stream that is not an exposure of the simulated world (sampling for telemetry,
   action sampling, permutations, bootstrap); the four exposure domains are the task language's.
4. The registry has a version (an integer incremented whenever a row is appended or retired). The version is
   part of every run's pins and of memo keys; because appending a row changes no existing draw, a run recorded
   under version v replays under any later version, and the replay check asserts exactly that.
5. A crate obtains identifiers only from the generated constants (`frob_core::streams::SENSOR_NOISE`, …); a
   literal identifier in source is rejected by the generated-file check.

**Entity sub-keys.** `entity_of_name(family, name)` = the low 32 bits of BLAKE3 over the domain-separation
string `"frob.stream.entity/1"`, the family name and the entity's stable name (a port name, a parameter path,
a fixture identifier, a mission role). Integer entities (a tile index, a joint index) are used as they are.
At design and task admission the loader computes the hashes of all names in each family and refuses a design
or task in which two names of one family collide, naming both. With 32-bit hashes and at most a few hundred
names per family the collision probability is of the order of 10⁻⁵ per design; the check makes it a refusal
instead of a silent coupling.

**Loader checks (`frob_core::streams::Registry::load`).** Duplicate identifier; duplicate name; identifier 0
used; an identifier lower than the highest one in the previous committed version that is not present in it
(an insertion or renumbering); a row whose `domain`, `entity`, `tick` or `component` is not in the closed
vocabulary; a `retired` row that was not present before. Each is a load-time error with the row named. The
comparison with the previous version reads the registry's committed history file
`registries/streams.lock` (the list of identifier and name pairs ever assigned), which the generated-file
check keeps append-only.

## Acceptance criteria

- [ ] `registries/streams.toml` and `registries/streams.lock` exist with the 22 rows above; the loader accepts them and the generated constants match the file (the generated-file check passes).
- [ ] Appending a row changes no draw of any existing stream: the block of every pinned vector of N35-22 is unchanged after a 23rd row is appended.
- [ ] The loader refuses: a duplicate identifier; a duplicate name; identifier 0; a row inserted with an identifier below the current maximum that is absent from the lock file; a renumbered row; an unknown domain; removal of a row (as opposed to retiring it).
- [ ] A design or task with two names of one family whose 32-bit entity hashes collide is refused at admission with both names; the test uses a constructed colliding pair found by search.
- [ ] A literal stream identifier in crate source fails the generated-file check; a run recorded under registry version v replays bit for bit under version v + 1.
- [ ] Every stream named by another subsystem's bead as needed (telemetry sampling, sampled referee, promotion, bootstrap, the four adversarial streams, the two attribution streams, the generator, command schedule) has a row.

## Test plan

### Unit tests
- `streams_registry_loads`: 22 rows; identifiers 1 to 22; names unique.
- `streams_lock_is_append_only`: a lock file with a removed line fails the check.
- `append_changes_no_draw`: with a 23rd conformance row, the five pinned blocks of the draw service are unchanged.
- `insertion_refused`, `renumbering_refused`, `duplicate_refused`, `zero_refused`, `unknown_domain_refused`, `removal_refused` (one planted file each).
- `entity_of_name_vectors`: the hash of ("sensor-noise", "imu.gyro") is stable across platforms (the value is pinned when the function is first implemented and committed with the test).
- `entity_collision_refused`: a pair of names with equal low 32 bits (found by a birthday search over about 10⁵ candidates in the test's fixture generator, then pinned) in one family is refused; the same pair in two different families is accepted.
- `constants_generated`: `SENSOR_NOISE == StreamId(6)` and so on for all rows.
- `registry_version_in_pins`: a run's address pins carry the version; a replay under a later version is admitted, under an earlier one refused.

### End-to-end script and logging
The registry is exercised by `scripts/e2e/num_host_streams.sh` (bead N35-22), whose step 2 appends an unused
stream through a conformance overlay and asserts identical digests, and by `scripts/e2e/num_batch_invariance.sh`
(bead N35-17), step `draws`, on devices. Both log, through the STD-E2E helper, the registry version in the
evidence block's identities and a `metric` line `streams_registered`. This bead adds one check to the build's
own script: `cargo xtask check-generated` must fail on a planted literal identifier, logged as an `assert`.

### Known answers and negative controls
- KA-795: adding a stream changes no draw of any other stream.
- Metamorphic relation MR-03 (a draw depends on address, step and stream only), with its mutation.
- Negative controls: the renumbering overlay (a conformance loader that accepts it shows changed draws for
  every stream after the insertion point); a registry in which `sensor-noise` is keyed by sensor *index*
  instead of port-name hash (adding a sensor then shifts the others' noise; caught by N35-24's test).
- Determinism: the loader's output and the entity hashes are identical on every platform.

## Considerations

- The first-row allocation is a DESIGN default. Other units' beads that asked for streams named them; where a
  name here differs from theirs, the name in this registry governs and the difference is listed for the lead.
- The dyadic-tree tick of the `process` domain (so that a change of step or control rate reads the same path,
  and a retried interval refines a path instead of redrawing it) is defined by the transactional step's
  refinement law; this registry only records that a stream uses it.
- A stream for confirmation worlds is not a separate stream: confirmation and discovery are separated by the
  address's namespace field, compared as integers.
- Kill gate KILL-EXPODOMAIN (the task chapter's: under a factor of 2 in contrast variance on its held-out
  battery, or an automatic coupling choice that fails its test) falls back to "the keyed streams as they
  stand, with explicit per-stream adapters"; this registry is that fallback's substrate and is unaffected.
