## Background

Rare failures are estimated by sampling worlds from a *proposal* distribution that visits dangerous conditions
more often than the nominal distribution does, and correcting each sample by its importance weight
w = p(x)/q(x), the ratio of the nominal density to the proposal density at the sampled value. If the weight is
wrong, the estimate is wrong in a way no confidence interval reveals.

In this system every random draw is addressed: it is a pure function of the world address, the stream, the
entity and the tick. The numerics chapter draws the consequence: **proposal draws carry exact weights.**
Because every draw is addressed, a disturbance drawn from a tilted proposal has an importance weight that is
computed, not estimated. The value a world received and the weight that corrects for it are two functions of
the same integer words, so the weight can be recomputed from the address alone at any time, on any machine,
and audited.

The consumer is the certification lane for rare failures: bounded-weight importance sampling with a
*defensive mixture* q = ε·p + (1 − ε)·p_shifted, whose likelihood ratio is at most 1/ε, so that ε·w·1[failure]
is an observation in [0, 1] with mean ε·p and a confidence sequence on that mean bounds p at every stopping
time (construction C-27: rare failures; bounded weights certify, splitting explores). The same mixture is used
for discrete scene edits, where the weight bound holds for the same reason. This bead is the draw-side half:
proposals as addressed transforms with their weights. Tier: Solid.

Alternative rejected: estimating weights from samples (self-normalized importance sampling). It is biased at
finite sample size and has no bound per observation, so it cannot feed a certifying sequence.

## Scope

In: the proposal types; the germ form (normal germs with a mean shift, pushed through declared monotone
transforms); the finite form (rational category probabilities); weight computation and its class; the type
separation between bounded and unbounded weights; the per-draw record; law tests. Out: the estimator, the
confidence sequence, admission of non-nominal episodes and their refusals (the adversarial-search unit);
choosing a proposal (fitted on a separate pilot, never on the data it corrects); splitting, which re-keys
streams by a child address and needs no weight.

## Technical approach

**Principle.** A proposal draw at address a is `(x, w) = sample(a, nominal, proposal)`, where x is a
deterministic function of the block words at a (and of one more block for the mixture branch), and w is the
closed-form density ratio p(x)/q(x) evaluated at that x. Nothing about w depends on other samples.

**Germ form (continuous parameters).** A nominal parameter is a monotone transform θ = T(z) of a standard
normal germ z (T is declared with the card field or scene parameter; the identity for a Gaussian). The
proposal is a defensive mixture in germ space with nominal share ε ∈ (0, 1] and shift μ:

1. Draw the germ z₀ = `normal_f64(a with component c)` and the branch uniform u = `uniform_f64` of the block
   at component c + 1.
2. If u < ε: z = z₀ (the nominal branch); otherwise z = z₀ + μ (the shifted branch).
3. Weight: w(z) = φ(z) / (ε·φ(z) + (1 − ε)·φ(z − μ)) = 1 / (ε + (1 − ε)·exp(μ·z − μ²/2)), with φ the standard
   normal density. It depends on z only, not on which branch produced z, and satisfies w ≤ 1/ε.
4. θ = T(z). Since T is a bijection, the weight in θ-space equals the weight in germ space.

For d independent germs with shift vector μ applied jointly (one branch draw for the vector):
w = 1 / (ε + (1 − ε)·exp(μ·z − ‖μ‖²/2)). The exponential and the normal construction use the deterministic
elementary functions of the sibling library on the host, so w is class D2 and identical across CPU
architectures to the extent those functions are.

**Finite form (discrete scene edits and categories).** Nominal probabilities pᵢ and shifted probabilities rᵢ
are exact rationals; the proposal is qᵢ = ε·pᵢ + (1 − ε)·rᵢ. Sampling: one 64-bit addressed draw U is compared
with integer thresholds Tᵢ = ⌊(q₁ + … + qᵢ)·2⁶⁴⌋; category i is chosen when Tᵢ₋₁ ≤ U < Tᵢ. The probability the
sampler realizes is q̃ᵢ = (Tᵢ − Tᵢ₋₁)/2⁶⁴, and the weight is wᵢ = pᵢ / q̃ᵢ, an exact rational (class D0). Using
the realized q̃ᵢ, not the intended qᵢ, makes the weight exact for the sampler that actually ran; the
difference is below 2⁻⁶⁴ per category and the bound w ≤ 1/ε is checked on q̃ (a proposal whose quantization
would break the bound for some category is refused at construction).

**Types (DESIGN).**

```rust
pub struct Defensive { eps: Rational /* 0 < eps <= 1 */, shift: Shift }      // constructor refuses eps = 0
pub struct BoundedWeight { w: f64 /* or Rational */, bound: Rational }        // w <= 1/eps by construction
pub struct ExplorationWeight(f64);                                            // from a pure tilt; no bound
pub struct ProposalDraw<T, W> { addr: DrawAddr, value: T, weight: W, nominal: LawRef, proposal: ProposalId }
```

A pure tilt (ε = 0) can only produce `ExplorationWeight`; a certifying estimator's interface accepts
`BoundedWeight` only, so offering a tilted episode to a bound is a type error before it is a run-time refusal.

**Recomputation.** `reweigh(addr, nominal, proposal) -> (value, weight)` recomputes both from the address. An
audit calls it for every stored proposal draw and requires bit equality with the stored pair.

**Record.** Each proposal draw stores the address, the nominal law's reference (a card field or scene
parameter with its content hash), the proposal's identity (ε, μ or the rᵢ, and the pilot it was fitted on),
the value and the weight. A summary over draws reports the largest weight, the bound 1/ε and the effective
sample size (Σw)²/Σw².

## Acceptance criteria

- [ ] The weight formula is reproduced at hand values (ε = 0.1, μ = 4): w(0) = 9.9699, w(2) = 1, w(4) = 3.7272·10⁻⁴; every weight over 10⁶ draws is at most 10.
- [ ] Unbiasedness in the germ form: over 10⁶ addressed draws the mean weight is within ±0.013 of 1, and the weighted frequency of z > 4 is within 2% of 3.167·10⁻⁵.
- [ ] Finite form: for nominal (0.95, 0.05), shifted (0, 1) and ε = 0.1 the weights are 10 and 10/181 up to the 2⁻⁶⁴ quantization, exact rationals, and Σ q̃ᵢ·wᵢ = 1 exactly.
- [ ] `reweigh` reproduces every stored (value, weight) pair bit for bit from the address alone, on both CPU architectures.
- [ ] A value and its weight do not change when the world runs in another slot, batch, bucket or shard (the draw-table arrangements applied to proposal draws).
- [ ] `Defensive` cannot be constructed with ε = 0; an `ExplorationWeight` cannot be passed where a `BoundedWeight` is required (compile-fail test).
- [ ] A finite proposal whose quantized q̃ would give a weight above 1/ε for some category is refused at construction, naming the category.

## Test plan

### Unit tests
- `weight_hand_values`: the three values above; and for ε = 1 (no shift mass) w = 1 for every z.
- `weight_bound`: for 10⁶ random z in [−8, 12] and μ in [0, 6], w ≤ 1/ε.
- `weight_independent_of_branch`: the same z reached through the nominal branch and through the shifted branch (constructed by choosing z₀) has the same weight bits.
- `mean_weight_is_one`; `gaussian_tail_recovered` (10⁶ draws each, addresses from one run seed).
- `finite_weights_exact`: the two-category case; a five-category case with rational probabilities whose weights sum check Σ q̃ᵢ·wᵢ = Σ pᵢ = 1 in exact arithmetic.
- `finite_quantization_bound`: a constructed proposal with a category of probability 2⁻⁷⁰ is refused.
- `monotone_transform_preserves_weight`: with T(z) = exp(0.5·z) (a log-normal card field) the weight of θ equals the weight of z.
- `reweigh_roundtrip`; `types_separate_bounded_from_exploration` (compile-fail).
- `vector_shift_weight`: d = 2, μ = (3, 4), z = (3, 4): μ·z − ‖μ‖²/2 = 25 − 12.5 = 12.5, w = 1/(ε + (1 − ε)·e^12.5).

### End-to-end script and logging

and wall time; the evidence block (class, tier, determinism, identities, seed); `metric` lines `max_weight`
against the bound 10, `mean_weight` against 1 ± 0.013, the tail estimate against 3.167·10⁻⁵ ± 2%, the
effective sample size, and `reweigh_mismatches` against 0; a `summary` line.

### Known answers and negative controls
- The adversarial chapter's known answer: the Gaussian tail by defensive mixture with shift 4 and ε = 0.1
  recovers P(z > 4) = 3.167·10⁻⁵ with every weight at most 10; its control is a mixture without its nominal
  share on a mis-centred proposal.
- The bounded-weight identity: n⁻¹·Σ wᵢ·1[fail] with w = dp/dq ≤ w_max is unbiased with terms in [0, w_max];
  with nominal share ε the weights are at most 1/ε, and zero failures certify only p ≤ ln(1/δ)/(ε·n).
- Negative controls: a weight computed with the intended qᵢ where the realized q̃ᵢ differs by a deliberately
  coarse 16-bit quantization (Σ q̃ᵢ·wᵢ ≠ 1; caught by `finite_weights_exact`); a weight estimated by
  self-normalization (not equal to `reweigh`; caught by the audit); a branch-dependent weight
  (`weight_independent_of_branch` fails).
- Determinism lanes: all tests twice, across worker counts, debug and release, and on both CPU architectures.

## Considerations

- On devices the proposal value is computed in single precision by the device kernel, while the certifying
  weight is recomputed on the host in double precision from the same address. The value the world actually
  received and the host's value differ by rounding in the germ; the weight is a smooth function of z, so the
  relative effect is of the order of 10⁻⁷, far below the estimator's interval, and the record stores both the
  device value's bits and the host weight.
- With weights bounded by 1/ε, the upper bound after n runs without a failure cannot fall below about
  ln(1/δ)/(ε·n): importance sampling is never the cheaper way to certify absence. This bead does not change
  that; it makes the weights trustworthy where the method is used.
- A proposal must be chosen before the run or fitted on a separate completed pilot whose data are never
  reused; that discipline is the estimator's, and the proposal's identity recorded here includes the pilot.
