## Background

**A number never claims more than its certificate.** Two parts of that rule concern how results are stated,
not how they are computed.

First: a summary statistic over worlds states how many worlds it excludes and why. A mean return over "the
worlds that finished" silently drops the worlds that blew up, were marked `Degraded` for ill-conditioning or
capacity, or were never scored; an agent optimizing that number learns to push failures out of the
denominator. Invariant INV-NUM-05: a summary statistic states its exclusions; its verification is a schema
check, and the refusal for a summary statistic that omits what it excluded is `FROB-REF-865`.

Second: three rules of wording, enforced by schema.

1. A lower bound is called a lower bound and an estimate an estimate.
2. A quantile read from a histogram is an interval.
3. A device digest is a tripwire classed `Tested`; it is never called an identity, and no result is called
   verified.

The reasons are concrete. The conditioning figure κ̂ reported with every contact solve is a lower bound on the
condition number, and calling it "the condition number" would understate the risk it measures. A percentile
taken from a histogram with 3% bins is known only to within a bin. The in-kernel digest is a 128-bit integer
mix used to notice divergence; identities in the record are BLAKE3 hashes computed by the host over committed
snapshots. And "verified" promises more than any evidence class of the program (Estimated, Tested, Certified,
Proved) delivers. Words in an output are read by agents as facts; a wrong word is a wrong claim. Tier: Solid.

## Scope

In: the summary type with its accounting identity; the reasons vocabulary; where `FROB-REF-865` is raised; the
field-kind annotation; the schema lint for the three wording rules; the vocabulary lint over templates; the
script. Out: the numeric certificate block (N35-27); the histogram and its interval type (N35-21); the claim
product and evidence classes (the core bead); report rendering (the surface unit).

## Technical approach

**Summary type (DESIGN; `frob_core::summary`).**

```rust
pub struct Summary<T> {
    value: T,                         // the statistic, over the worlds actually used
    planned: u64, used: u64,
    excluded: Vec<(ExclusionReason, u64)>,
    denominator: Denominator,         // Planned | Used, stated, never implied
}
pub enum ExclusionReason { Degraded(DegradedReason), Faulted(FaultCause), Unscored, Masked(MaskReason),
                           NotApplicable(&'static str), NonFinite }
```

1. *Accounting identity:* `used + Σ excluded counts = planned`, all integers. The only constructor,
   `Summary::over(records, statistic, policy)`, counts every record into exactly one of `used` or an
   exclusion reason; there is no constructor that takes a bare value.
2. *The denominator is explicit.* A rate (a success rate, a failure rate) says whether it is over planned
   worlds or used worlds; the default for rates that an agent could game (success, promotion) is `Planned`,
   so that an excluded world counts against the rate unless the task defines otherwise.
3. *Nothing is excluded silently by a default.* The exclusion policy is part of the request and of the
   record; `Degraded` worlds are included with their flag unless the policy excludes them, and either way
   they are counted.
4. *Serialization.* `{ "value": …, "planned": "…", "used": "…", "excluded": [{ "reason": …, "count": "…" }],
   "denominator": … }`; a summary field in any output schema is this object (annotation
   `x-frob-summary: true`).

**`FROB-REF-865` is raised when:** an artifact offered as an input or for citation contains a summary
statistic without its exclusion table (an imported or hand-edited result); the accounting identity does not
hold; or a request asks a verb to compute a statistic "over valid worlds only" without accepting the
exclusion table in the output. Exit code 3; repairs: regenerate through `frob telemetry summary`, which states
exclusions; or add the counts by reason and the denominator. The check is one function of this bead,
`frob_core::summary::check_offered(&Value) -> Result<(), Refusal>`, which every verb's input path calls on an
offered artifact, the citation path of the citing verbs included, so that a citing verb raises 865 through this
function and defines no second check.

**Field kinds (DESIGN).** Every floating-point field in an output schema carries
`x-frob-kind: exact | measured | estimate | lower-bound | upper-bound | interval | tripwire`.

**Wording lint (run by the generated-artifact check over all generated schemas, refusal message templates,
report templates and the human-readable strings of the CLI).**

| Rule | Check | Example that fails |
|---|---|---|
| 1a | A field of kind `lower-bound` or `upper-bound` has a name ending in `_lower_bound` or `_upper_bound` (or `_lb`, `_ub` inside an object whose name says so) | `condition_number` for κ̂ |
| 1b | A field whose value has evidence class Estimated, or kind `estimate`, is not named or described with `measured`, `exact`, `true` or `certified` | `true_failure_rate` for a sampled estimate |
| 2 | A field named `median`, `quantile`, `percentile` or `pNN`, whose source is a histogram (`x-frob-source: histogram`), has type `QuantileInterval` | `"p95": 41.7` from a histogram |
| 3a | A field of kind `tripwire` has evidence class `Tested`, and no field whose name or description contains `identity`, `id` or `hash` has kind `tripwire` | `state_identity` filled with the device digest |
| 3b | The word `verified` does not occur as a status value, a field name, an enumeration value or in a result's message template | `"status": "verified"` |

The vocabulary for statuses is closed: evidence classes `Estimated`, `Tested`, `Certified`, `Proved`; gate
statuses as the gate record defines them (N40-01: `not-run`, `pass`, `fail`, `killed`, `blocked`, `no-claim`,
`superseded`) and kill-gate outcomes (N40-03: `not-fired`, `fired`, `not-reached`, `deferred`), read from those
types rather than copied; checker verdicts `accept`, `reject`; currency `current`, `stale`. The checker binary's and the verb's own names (which contain "verify") are actions, not statuses,
and are on the lint's allowlist by exact string.

**Where the rules bite at run time.** The lint is a build-time check. At run time the envelope writer
validates each output against its schema, so a quantile cannot be emitted as a scalar and a summary cannot be
emitted without its table.

## Acceptance criteria

- [ ] `Summary::over` is the only way to build a summary; a compile-fail test pins the absence of a constructor from a bare value; the accounting identity holds for 10⁴ seeded record sets.
- [ ] Every summary-valued output in the generated surface (at M2, `telemetry.summary` and the outputs of N35-27's block) is the summary object with `planned`, `used`, `excluded` and `denominator`; the schema lint fails a planted summary-valued field that is not, so `eval.run`, `eval.scorecard` and the comparison verbs carry it when their beads land.
- [ ] A fixture run with 1,000 planned worlds, of which 7 are `Degraded: ill-conditioned`, 2 `Faulted` and 5 unscored, reports those counts by reason and a success rate whose denominator is stated; the rate over `Planned` and the rate over `Used` differ and both are reproducible from the counts.
- [ ] Offering a result whose summary lacks the exclusion table, or whose counts do not add up, returns `FROB-REF-865` with exit 3 and the stated repairs.
- [ ] Every floating field in every generated output schema has an `x-frob-kind`; the lint fails a planted field without one.
- [ ] Each of the five lint rows fails on its planted example and passes on the real schemas; the word `verified` appears in no output status anywhere in the generated surface.
- [ ] κ̂ appears only as `kappa_lower_bound…`; histogram quantiles appear only as intervals; the device digest appears only as a `tripwire` of class `Tested`.

## Test plan

### Unit tests
- `summary_accounting_identity` (property, 10⁴ cases).
- `summary_no_bare_constructor` (compile-fail).
- `summary_denominator_explicit`: 986 used of 1,000 planned with 900 successes → 0.900 over planned, 0.9128 over used; both printed with their denominators.
- `summary_missing_table_refused_865`; `summary_counts_mismatch_refused_865`.
- `kind_annotation_required`: a schema field without `x-frob-kind` fails the lint.
- `lint_rule_1a_bound_names`, `lint_rule_1b_estimate_words`, `lint_rule_2_quantile_interval`, `lint_rule_3a_tripwire`, `lint_rule_3b_no_verified` (one planted schema each, plus the real schemas passing).
- `status_vocabulary_closed`: every enumeration marked as a status in the schemas is a subset of the closed list.
- `allowlist_is_exact`: the verb and binary names containing "verify" pass; `verified_at` as a field name fails.

### End-to-end script and logging
`scripts/e2e/num_summary_wording.sh --seed <s>`: (1) `lint`: `cargo xtask check-generated` (which runs the
wording lint) and the planted-violation variants through `cargo test -p frob-verbs --release lint_rule_`,
expecting failure for each; (2) `summary`: `frob sim run <fixture> --tier batch-cpu --worlds 1000 --seed <s>
--on-degraded continue-flagged --key nsw-run-<run-id> --json` on the fixture with the planted 7 ill-conditioned,
2 faulted and 5 unscored worlds, then `frob telemetry summary <run> --json`: assert the exclusion table and both
rates with their denominators; (3) `refusal`: `cargo test -p frob-verbs --release --test summary_e2e`, which
offers a hand-edited copy of that result without its exclusion table, and one whose counts do not add up, to
`check_offered` on the input path: assert `FROB-REF-865`, exit 3, and the stated repairs; (4) `wording`: the envelopes of steps 2 and 3 read back with `frob artifact read`, asserting
`kappa_lower_bound…` names, the device digest as a `tripwire` of class `Tested`, and no `verified` anywhere.
Logs through the STD-E2E helper to `target/e2e-logs/num_summary_wording/<utc-timestamp>.ndjson` with a
transcript: `ts`, `script`, `bead`, `step`, `event`; `cmd` lines with exact command line, exit code and wall
time; the evidence block; `metric` lines `planned`, `used`, each exclusion count, both rates with denominators;
a `refusal` event for 865 with `pointer`, `observed`, `required` and first repair; `assert` lines per lint rule;
a `summary` line. The later lanes are the citing verbs that raise 865 on their own inputs (`eval.scorecard`,
BD-254 at M3; `report.campaign`, N39b-46) and the interval-typed quantile of `telemetry.histogram` in step group
`verb-*` of `scripts/e2e/telemetry_sampling_histograms.sh` (N29a-16).

### Known answers and negative controls
- The accounting identity of paired studies as a second instance of the same rule.
- Negative controls: a summary computed over finished worlds only with no table (must be refused when cited);
  the five planted schema violations; a report template that prints "verified by simulation".
- Metamorphic: permuting worlds changes no count; moving a world from `used` to an exclusion reason changes
  exactly two counts and keeps the identity.
- Determinism lanes: counts are integers (class D0); the lint's output is a pure function of the schemas.

## Considerations

- A buildable design that stalls is a failed trial, not a missing one; a failed training run is never an
  exclusion. Those rules belong to the comparison and task chapters and use this type's `used` and `excluded`
  to be visible.
- The lint is conservative on names (`id` matches many fields); rule 3a therefore keys on kind `tripwire`
  first and only then inspects names, and a waiver needs a reason in the schema.
- "Verified" is common in everyday engineering speech. The ban is on outputs, where the word would be read as
  a claim; documentation that explains the checker may use the verb.
- INV-NUM-05's schema check applies from the first summaries at M1; this bead lands the type at M2 with the
  device results, and the M1 telemetry summaries are migrated to it by their owner's bead.
