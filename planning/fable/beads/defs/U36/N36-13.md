## Background

A **Performance** claim is one of the seven kinds of claim a FrankenRobotics result may make: a speed or scale
figure on named hardware. Its only permitted wording is "measured ⟨figure⟩ on ⟨hardware⟩; disclosure block
⟨identifier⟩", and it establishes nothing about another workload, world count or machine. The disclosure block is
therefore not paperwork: it is what turns a number into a claim.

Why it is mandatory. FACT (source register, to be re-read before a gate cites it): a public dispute over one
simulator's headline throughput number ended with the number being re-measured two orders of magnitude lower under
corrected settings. The settings that moved it (what was inside the timed loop, the step, the number of substeps,
the scene, whether anything was colliding) are exactly the fields below. A figure without the complete block is
refused as a Performance claim (`FROB-REF-862`).

The block is needed at M0 because the first performance records of the project are incumbent measurements, and
the milestone's exit requires each of them "under the disclosure block". Tier: Solid. Rejected alternatives: a
free-form "notes" field (cannot be checked for completeness); a short block with optional fields (the dispute above
turned on optional fields); deriving the block after the fact from logs (a block is written by the run that
produced the figure, from its own receipts).

## Scope

In: the schema, its field list, the applicability table, the completeness check, the content identity, the
refusal, and the adapter that fills the block from one of our own run receipts and a fingerprint record. This
bead is the only definition of the block: the field list and the check are stated here and nowhere else, and
the check is the one place `FROB-REF-862` is raised for a block. The code's registry row (meaning, triggers,
pointer shape, ranked repairs, exit code) is N35-REF's, a dependency, and is quoted below, not restated. Out: the rate types (N36-03); the ratio fields' statistics (N36-06); measuring bytes touched
(N36-18); the campaign runner (BD-216); running incumbents and the adapter that fills this block from an
incumbent run record (`subject: "incumbent"`), which are BD-039's and use this bead's schema and check.

## Technical approach

**Fields.** Every Performance figure carries all of the following. Group A is the base list; group B was added
by design to close the remaining ways a figure can mislead.

| # | Field | Content |
|---|---|---|
| A1 | `hardware`, `driver` | Machine, device name and stable identifier, driver and runtime versions |
| A2 | `backend`, `compiler`, `kernels` | Backend (`batch-cpu`, `gpu-cuda`, `gpu-metal`, or the incumbent's), compiler version, kernel-set identity |
| A3 | `worlds` | World count |
| A4 | `h_s`, `substeps`, `decimation` | Time step, substeps, control decimation |
| A5 | `solver` | Iterations and tolerance |
| A6 | `contact_capacity`, `mean_active_contacts` | Capacity C and mean active contacts per world |
| A7 | `sensors` | Sensors enabled |
| A8 | `includes` | Whether the policy and learning are included |
| A9 | `scene` | Scene identity |
| A10 | `determinism` | Determinism class of the run (D0 exact; D1 same bits on CPU and devices; D2 same bits run to run on one device family; D3 inside a recorded tolerance; D4 labelled nondeterministic) |
| A11 | `warmup_s`, `duration_s` | Warm-up and measured duration |
| A12 | `launch_graphs_captured` | Whether launch graphs were captured |
| A13 | `step_time` | Median and 99th-percentile step time |
| A14 | `peak_memory_bytes` | Peak memory |
| B1 | `rates[]` | Every rate with its unit and the decimation beside it (the `Rate` wire form) |
| B2 | `row_capacity`, `degraded_worlds`, `faulted_worlds` | Row capacity R and the counts of worlds marked `Degraded` and `Faulted` |
| B3 | `profile`, `precision_profile`, `fingerprint`, `placement` | Profile and precision profile; the hardware fingerprint digest; the placement receipt: requested and actual backend per stage, fallback count, transfer bytes, synchronization count |
| B4 | `start` | `cold` or `warm`, with compile and admission times and the cache state |
| B5 | `mixed_batch` | For a mixed batch: buckets, variants per bucket and the padding fraction |
| B6 | `thermal`, `soak_s`, `host_load` | Thermal state and soak duration; host load |
| B7 | `ratio` | For a ratio: the number of pairs, the lower bound, and the comparator's revision and configuration |
| B8 | `not_fitting_rows[]` | Rows that did not fit in memory, kept in the table and marked |
| B9 | `energy` | Energy where the platform exposes credible data, and a named gap where it does not; never a zero |
| B10 | `bytes_touched_per_world_step` | Per launch and in total (a first-class figure; filled from M2) |
| B11 | `parity_defect` | Present while a throughput row sits in the recorded-defect band of the parity kill gate: the row, its measured bound and the tolerance |

**Schema (DESIGN name `frob.perf.disclosure/1`; the format registry fixes the final name).**

```json
{ "schema": "frob.perf.disclosure/1", "subject": "ours | incumbent",
  "hardware": {"machine": "trj", "device": "RTX 4090 #0", "id": "…"}, "driver": {"name": "…", "version": "…"},
  "backend": "gpu-cuda", "compiler": "…", "kernels": "k:…", "worlds": 8192,
  "h_s": "1/500", "substeps": 1, "decimation": "10/1", "solver": {"iterations": 4, "tolerance": "…"},
  "contact_capacity": 32, "mean_active_contacts": "…", "row_capacity": 160,
  "degraded_worlds": 0, "faulted_worlds": 0, "sensors": ["proprioception"], "includes": {"policy": false, "learning": false},
  "scene": "s:…", "determinism": "D2", "profile": "device-replay", "precision_profile": "f32",
  "warmup_s": "…", "duration_s": "…", "launch_graphs_captured": true,
  "step_time": {"median_s": "…", "p99_s": "…"}, "peak_memory_bytes": "…",
  "rates": [ { "value": "…", "unit": "world_steps_per_s", "decimation": "10/1", "scope": "physics_only" } ],
  "fingerprint": "b3:…", "placement": "b3:…",
  "start": {"kind": "warm", "compile_s": "…", "admission_s": "…", "cache": "hit"},
  "mixed_batch": {"na": "homogeneous batch"},
  "thermal": {"state": "nominal", "soak_s": 1200}, "host_load": {"load1": "…", "gpu_util_other": "…"},
  "ratio": {"na": "not a ratio"}, "not_fitting_rows": [],
  "energy": {"gap": "no credible energy counter on this device (OPEN-PERF-3)"},
  "bytes_touched_per_world_step": {"na": "measured from M2"}, "parity_defect": null,
  "seed": "…", "commit": "…", "block_id": "b3:…" }
```

**Incumbent figures (DESIGN; the group comes from the incumbent harness's field list, which named "the
comparator's revision and configuration" on every figure it produces).** A block with `subject: "incumbent"`
also carries `comparator = {"name": "…", "revision": "<commit>", "container_digest": "sha256:…",
"configuration": "b3:…"}`, copied from the row of `crates/frob-conformance/registry/comparators.toml` that was
run (`name`, `source_revision`, `container_digest`) and the configuration hash its launcher verified. Reason: a
single incumbent figure is not a ratio, so group B7 does not apply to it, and without this group the block would
not say which incumbent revision was measured. When a ratio is later formed, `ratio.comparator` is copied from
this group. For `subject: "ours"` the group is absent, and its presence is refused.

**Completeness check (`frob_core::perf::disclosure::check`).** Numbered steps:
1. Every field of the table is present. Absent is never the same as not applicable.
2. A field may hold `{"na": "<reason>"}` only where the applicability table allows it for the block's `subject` and
   `backend`: `launch_graphs_captured` on `batch-cpu` and Metal; `placement`, `kernels`, `row_capacity`,
   `contact_capacity` for `subject: incumbent` where the incumbent has no such notion (the reason says so);
   `mixed_batch` for a homogeneous batch; `ratio` for a figure that is not a ratio;
   `bytes_touched_per_world_step` before M2 and for incumbents. Any other `na` is a missing field. For
   `subject: "incumbent"` the `comparator` group is required with all four members and may not be `na`.
3. `energy` is a measured value with its source, or `{"gap": "<named reason>"}`. The number zero is refused.
4. Every entry of `rates` passes the rate schema of N36-03: unit, decimation, scope, counts (a missing decimation
   is 862 with pointer `rates[i].decimation`). The block's step rates pass `check_ordering` (N36-03); an
   `OrderingViolation` is 862 as the interim of the held ledger request `rates-violate-unit-ordering` (N36-REF;
   N35-33 rule 7): `detail = "rates-violate-unit-ordering"`, pointer `rates.ordering` (N36-03's constants
   `ORDERING_DETAIL` and `ORDERING_POINTER`) and a message naming INV-PERF-01.
5. If `ratio` is present as a value it has `pairs ≥ 10`, `lower_bound`, `comparator.revision` and
   `comparator.configuration`. A ratio with no lower bound is the neighbouring refusal `FROB-REF-863`; the other
   missing parts are `FROB-REF-862`.
6. `fingerprint` names a fingerprint record whose digest matches the machine at the time of the run.
7. `block_id` equals BLAKE3 over the canonical JSON of the block without `block_id`. This is the "disclosure block
   ⟨identifier⟩" of the permitted Performance wording.

**Refusal.** `FROB-REF-862`: "a performance figure without a complete disclosure block". Exit code 3. `pointer`
names the first missing or inadmissible field; `retry: after-change`. Ranked repairs, in the order of the
registry row of N35-REF (tests read them from the row): (1) re-run the measurement
under the performance harness, which fills the block from the run's receipts; (2) supply the named field;
(3) cite the figure as context with no claim. The check runs wherever a result sets `claims: ["Performance"]` in
its evidence block and wherever a gate record or a release manifest cites a speed figure.

**Filling the block.** `from_receipt(run_receipt, fingerprint, campaign) -> Disclosure` reads the fields from what
the run itself recorded; a field the receipt cannot supply is left absent, so that the check fails instead of a
default being invented. For incumbents the out-of-process harness supplies the same structure from its own
recorded environment.

**Evidence.** A Performance figure is class `Tested`. The block is stored in the ledger as a content-addressed
record and referenced by `block_id`.

## Acceptance criteria

- [ ] The schema is registered and `check` accepts a complete block for each of: our CUDA run, our Metal run, a `batch-cpu` run, an incumbent run.
- [ ] Removing any one required field makes `check` fail with `FROB-REF-862` and a pointer to that field (exhaustive over the field list).
- [ ] An `energy` of zero is refused; a named gap is accepted.
- [ ] `na` is accepted only where the applicability table allows it.
- [ ] A block with `subject: "incumbent"` and no `comparator` group, or with one of its four members missing, is refused with `FROB-REF-862` and pointer `comparator`; a block with `subject: "ours"` that carries the group is refused.
- [ ] A step rate without a decimation inside the block is refused with pointer `rates[i].decimation`.
- [ ] A block whose rates carry the KA-806 pair (400 k env-steps/s of training beside 2.0 M world-steps/s of physics at d = 10) is refused with `FROB-REF-862`, `detail = "rates-violate-unit-ordering"` and pointer `rates.ordering`.
- [ ] `block_id` is stable under key reordering and whitespace and changes when any field changes.
- [ ] KA-825 (first half): a Performance figure without the complete block is refused, shown at M0 by this bead's own test `each_missing_field_is_862`; from M2 the same check is a clause of GATE-SPARK-19, whose entries call it (BD-216) and whose record is not a condition of this bead.
- [ ] An envelope that sets `claims: ["Performance"]` without a valid `block_id` is rejected at the agent boundary; documented in `CONTRACT.md` under refusals.

## Test plan

### Unit tests

`cargo test -p frob-core perf::disclosure`:
- `complete_blocks_accept` (four fixtures, labelled `synthetic`).
- `each_missing_field_is_862`: for each of the 25 field groups, delete it and expect the refusal with that pointer.
- `energy_zero_refused`, `energy_gap_accepted`, `energy_measured_requires_source`.
- `na_only_where_allowed`: `{"na": …}` on `worlds` is refused; on `launch_graphs_captured` for Metal it is accepted.
- `incumbent_block_requires_comparator`: the incumbent fixture without `comparator`, and with `comparator.revision` removed, are both `FROB-REF-862`; our CUDA fixture with a `comparator` group added is refused.
- `ratio_without_bound_is_863`, `ratio_without_comparator_revision_is_862`, `ratio_with_nine_pairs_is_862`.
- `mixed_batch_requires_buckets_variants_padding`.
- `ordering_violation_is_interim_862`: the KA-806 block → `FROB-REF-862`, `detail = "rates-violate-unit-ordering"`, pointer `rates.ordering`, exit 3; the consistent triple of N36-03 (400 k, 340 k, 280 k env-steps/s) passes.
- `stale_fingerprint_refused`: a block whose fingerprint digest differs from the supplied machine record.
- `block_id_canonical`: two serializations with different key order give the same identifier; one changed digit changes it.
- `from_receipt_leaves_unknown_absent`: a receipt lacking `peak_memory_bytes` yields a block that fails the check, never a zero.
- Property test: any block that passes still passes after a canonical round trip.

### End-to-end script and logging

`scripts/e2e/perf_parity_baseline.sh` (N36-29, M0) and `scripts/e2e/perf_harness_gate19.sh` (N36-30, M2) both
include a step `disclosure`: every recorded figure's block is validated, then one field at a time is removed from
a copy and the refusal is asserted. Logged per line: the figure, `block_id`, the removed field, the refusal code
and pointer, exit code 3. Block contents are logged by identifier only; no scene data beyond the scene identity.

### Known answers and negative controls

- KA-825: a figure without the complete block is refused (`FROB-REF-862`); exact.
- Negative controls registered against GATE-SPARK-19: a checker that treats an absent field as not applicable; a checker that accepts `energy: 0`. Both must be caught by the exhaustive deletion test.
- Metamorphic: adding an unknown extra field is refused (a misspelt field is a refusal, not a default).

## Considerations

- **OPEN-PERF-3** (a credible energy source on each machine; owner: the performance lead; blocks nothing). Fail-closed default: a named gap in every block. Candidates to evaluate when someone needs the figure: the card's own power telemetry on `trj`, the operating system's power counters on the Mac. A source is admitted only with a stated accuracy and sampling interval; until then the field says why it is empty.
- RISK-45 (an optimization changes unrelated semantics): the block is the detector. A throughput figure that rises while `mean_active_contacts`, `sensors` or a `Degraded` count moves is flagged by the harness's block diff (BD-216).
- RISK-09 (`trj` is often heavily loaded): `host_load` is recorded, never corrected for.
- The block grows; it is referenced by identifier everywhere and printed in full only on request.
- Privacy: `scene` is an identity, never scene content; private scenes stay private under the project's export rules.
