## Background

GATE-SPARK-22 (claim: Known answer; earliest milestone M2; TARGET): `sim.estimate` memory is within 5% of measured
high-water marks at 1, 8, 64 and 256 worlds and at capacity for the reference quadruped workload Q and humanoid
workload H on each device; a job that does not fit is refused before allocation; time estimates fall inside their
intervals on at least 90% of held-out runs; bytes touched per world-step are measured per launch.

The gate is what entitles an agent to trust the estimate before spending compute: the memory figure is checked
against what the device actually held, the refusal is shown to happen before anything is allocated, and the time
interval is scored on runs it never saw. This bead is the end-to-end script that demonstrates all four clauses
through the real `frob` binary and writes the structured log and the gate receipt.

## Scope

In: the script, its steps, assertions and logging; the registered negative controls of the gate. Out: the models
(BD-219, N36-16 to N36-19); the dynamics chapter's output groups and their script.

## Technical approach

**Invocation.** `scripts/e2e/sim_estimate_gate22.sh --machine trj|mac --device <id> [--skip-capacity] --seed <s>`.
Plain shell; sources the shared end-to-end helper; seed-explicit; idempotent (measurements are keyed by request
identity, fingerprint digest and seed); exits non-zero on a failed assertion. One device per invocation.

**Steps.**
1. `preflight`: `frob doctor --json`; `frob spark fingerprint --json` (assert current; print memory total, free,
   working-set limit and largest single buffer); the envelope class in force.
2. `memory`: for W in {Q, H} and N in {1, 8, 64, 256}: `frob sim estimate --workload W --tier <t> --worlds N
   --json`, then `frob sim run --workload W --tier <t> --worlds N --seconds 2 --seed <s> --json`; read the run
   receipt's peak device bytes; assert |estimate − measured| ÷ measured ≤ 0.05. Also assert the estimate call
   executed no physics (the engine's step counter is zero) and returned in under 2 s on a warm cache.
3. `capacity`: `frob sim estimate --workload W --tier <t> --worlds max --json` returns the largest world count
   that fits; run at that count for a few steps; assert the 5% agreement. On the Mac this point is far above the
   default machine envelope and runs only under the gate-measurement class; otherwise it is logged `not run` with
   the reason.
4. `refusal`: request a world count above the largest that fits with `frob sim run`; assert exit code 6, refusal
   `FROB-REF-602`, the fingerprint digest in the envelope, the repairs (fewer worlds with the count named, a
   smaller capacity, the Mac), and that the device's allocated-bytes counter before and after the call is
   unchanged.
5. `scenes`: generate and compile one small interior (`frob scene gen`, `frob scene compile`); estimate and run
   with 1, 4 and 16 scene variants; assert `memory.scenes` within 5% of the measured scene slabs; request one
   scene per world on 8,192 worlds and assert the refusal with the shared-variant repair first.
6. `cameras`: a 64 × 64 depth task at 8,192 worlds and a two-camera 640 × 480 task at 256 worlds: estimate, run,
   assert 5%; then the 640 × 480 task at 8,192 worlds on a card: assert the refusal and its repairs.
7. `calibrate` and `heldout`: run the declared calibration job list; then for each job of the declared held-out
   list call `frob sim estimate`, store the interval, run the job, and record inside or outside. Assert coverage
   of the headline interval ≥ 0.90.
8. `bytes_touched`: for Q and H at 8,192 worlds, assert the run receipt has the per-launch table of bytes read
   and written per world-step and that it sums to the total; log the measured efficiency against the
   fingerprint's bandwidth.
9. `envelope_class`: assert the estimate prints the class a two-device job and a 24-thread job need, and that
   submitting either under the default class is refused with `FROB-REF-761` (exit code 4).
10. `gate`: `cargo test -p frob-conformance --test g1 -- GATE-SPARK-22` assembles the record per device from the
    measurements and writes the receipt (commit, command, output, receipt hash, fingerprint digest, seed).

**Logging.** NDJSON to `target/e2e-logs/sim_estimate_gate22/<utc-timestamp>.ndjson` and a transcript. Every line:
`ts`, `script`, `bead`, `step`, `event` (`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact command
line, exit code, wall time, the envelope's evidence block (claim, class, tier, determinism, identities, seed).
`metric` lines: workload, device, world count, the estimate's breakdown by slab class in bytes, the budget, the
measured high-water mark, the relative difference against 0.05; for time, the stratum, both interval ends, the
measured wall time and inside or outside; for bytes touched, the per-launch figures. `refusal` lines: code,
pointer, exit code, repairs, allocated bytes before and after. On failure: the first slab class whose bytes
differ and the paths of both records. Final `summary`: assertions passed and failed, coverage, points `not run`
with reasons, `gates: ["GATE-SPARK-22"]`. Only public reference robots and generated scenes are used; no
private-scene data is logged.

## Acceptance criteria

- [ ] The script exits 0 on a correct build for each device and writes a GATE-SPARK-22 record with measured values per clause.
- [ ] The memory clause is shown at 1, 8, 64 and 256 worlds and at capacity for Q and H; a capacity point that could not run under the envelope in force is recorded `not run` with the reason.
- [ ] The refusal is shown to precede allocation by the unchanged allocated-bytes counter.
- [ ] Held-out coverage is computed on a job list declared and hashed before the calibration runs.
- [ ] The per-launch bytes-touched table is present for both workloads.
- [ ] Each registered negative control makes the script fail when planted.
- [ ] Every NDJSON line has the required fields and the `summary` names the gate.

## Test plan

### Unit tests

None of its own beyond a shell lint and a dry-run mode (`--plan`); the models' unit tests are in their beads.

### End-to-end script and logging

This bead is the script; steps, assertions and log fields are defined above.

### Known answers and negative controls

- KA-826 (the gate's three numeric clauses), KA-814 and KA-816 (the estimate's terms printed and checked for Q and H), KA-817 (camera frame sets), KA-822 (bytes-touched budget printed beside the measurement).
- Registered controls: an estimator that sums all slabs instead of the live-interval peak; an admission path that allocates before checking; an estimator calibrated on the held-out list; a backend that reports bytes touched at capacities instead of active counts; an estimator that charges a scene per world.
- Determinism lanes: steps 2 to 6 give identical estimates on repeat (the estimate is a pure function of request and fingerprint); measured marks are exact allocator counts and are also identical on repeat; step 7 is a measurement.

## Considerations

- The 5% tolerance covers what the model does not see (driver bookkeeping, alignment by the allocator); a difference above 5% at one world usually means the per-fingerprint fixed overhead is stale and must be re-measured.
- OPEN-SPARK-2: capacity runs on the Mac and any two-device point need the gate-measurement class; the script never works around a refusal.
- `trj` under heavy load has less free device memory than the planning figure; the capacity point uses the fingerprint's reading at the time, and the record states it.
- The script is re-run after any change to the arena layout, the slab catalogue, the scene pack format or the fingerprint.
