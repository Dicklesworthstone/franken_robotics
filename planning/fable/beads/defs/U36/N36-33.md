## Background

Every throughput target, every parity ratio and every estimator check of the performance program is stated on one
of two **reference workloads**, records with an identity kept in `registries/workloads.toml` (bead N36-02):

| Workload | Robot | Degrees of freedom | Bodies | Contact capacity C | Row capacity R | Step h | Newton iterations | Decimation d |
|---|---|---|---|---|---|---|---|---|
| Q | Reference quadruped, 12 actuated joints, 16 foot samples | 18 | 13 | 32 | 160 | 2 ms | 4, warm-started | 10 (50 Hz control) |
| H | Reference humanoid, 29 actuated joints | 35 | 30 | 64 | 320 | 2 ms | 4, warm-started | 10 (50 Hz control) |

A measurement is comparable across time, machines and simulators only if the workload behind it is the same bytes
each time. The run verbs, however, take a design, a scene, capacities, a step and an iteration budget as separate
arguments, so two scripts that both say "workload Q" can run different things, and a figure can carry the name Q
while its capacities differ. More than forty beads of the device backends, the numerics and telemetry gates, the
performance harness, the estimator and the scaling gate write their commands as `frob sim run --workload Q …`. This bead is the piece of work that
makes that option exist and makes it mean exactly one thing.

DESIGN (the specification's verb registry lists `sim.run` with a design, a scene, a profile and per-world slots, and
names no workload option; the option is added here because the program's own measurements need one spelling).
`--workload <id>` is not a new way to describe a run. It is a name for a fixed set of request fields, resolved
before admission, so that the run is the same request it would have been with every field typed out. Tier: Solid.

Rejected alternatives. (1) A shell helper that expands the arguments: scripts, the harness, agents on the MCP
surface and the daemon would each need their own copy, and they drift. (2) Letting an explicit argument override a
field of the workload: the figure would be stamped Q while running other capacities, which is the error the
identity exists to prevent. (3) A workload as a kind of task: the reference workloads fix the engine's settings
(capacities, step, iterations), and the same workload is run physics-only, as a full environment step and under
training; the task is a separate argument.

## Scope

In: the resolver from a workload identifier to request fields; the embedded registry and its digest in
`frob-verbs`; the shared argument group; its wiring into `sim.run`; the contradiction and unknown-identifier
refusals; the workload stamp on receipts and results; the schema entry and surface parity; tests and an
end-to-end script. Out: the records and their lint, and the record type `Workload` with its strict parser and
`WorkloadId` in `frob_core::perf::workload` (N36-02, a dependency: they are needed at M0, when the parity
baseline reads the workloads, two milestones before this verb option); the verbs `sim.estimate` (BD-219), `train.start`
(the learning unit's verb bead), `spark.place`, `spark.precompile` and `spark.check` (the device unit's beads),
each of which adds the same argument group by calling this resolver in its own bead; the robot models the
records name (the reference-robot asset beads); freezing capacities (the decision on OPEN-SPARK-3) and restating
rows if the step changes (N36-26).

## Technical approach

**Where the code lives (DESIGN).** Nothing may depend on the conformance crate, so the record type does not live
there: `frob_core::perf::workload` holds `Workload` (the fields of `frob.workload/1`), its strict parser (an
unknown field is an error) and `WorkloadId` = BLAKE3 over the canonical record, all written at M0 by N36-02,
whose loader checks in `frob-conformance` call the same parser. This bead adds no type and no parser: the
resolver (`frob_verbs::workload_arg`) calls that parser. `frob-verbs` embeds `registries/workloads.toml` at build
time and exposes `registry_digest()`; a scratch registry directory can be selected for tests in the same way as
for the other registries.

**The argument.** `--workload <id>[:<ground>]`, for example `Q`, `Q:rough`, `H:heightfield`. `<id>` is a key of
the registry; `<ground>` is one of the record's `grounds` and defaults to the first (`flat`).

**Resolution, numbered (`WorkloadArg::resolve(id, ground) -> ResolvedWorkload`).**
1. Look the identifier up; unknown → refusal (below) with up to three nearest identifiers.
2. Check the ground against the record's list; unknown → refusal naming the admissible grounds.
3. Resolve the record's `robot` to an admitted model identity. A record that names a model which is not admitted
   on this build is refused with the model's name; nothing is substituted. DESIGN reading of the default records, to be
   confirmed by the comparator decision (N36-25): `ref-quadruped-12` is the 12-joint quadruped asset `go1` of
   the permissively licensed public model collection (13 bodies), and `ref-humanoid-29` is the 30-link reduced
   humanoid of the sibling simulation suite's catalogue, asset `fsim-g1` (29 actuated joints). Those two asset
   beads are therefore dependencies; if the decision names other models, the records change and this resolver
   does not.
4. Produce the request fields the workload fixes: design (the model identity), scene (the ground variant),
   contact capacity, row capacity, step h as an exact rational, Newton iteration budget and warm start,
   decimation d. A verb whose schema has no such field (decimation on a physics-only `sim.run`) ignores it for
   execution and still stamps it.
5. Produce the default the workload suggests and does not fix: the world count (8,192), used only when
   `--worlds` is absent.

**Free and fixed arguments.** Free beside `--workload` (they are not part of the workload identity): `--worlds`,
`--seconds`, `--intervals`, `--steps`, `--seed`, `--tier`, the determinism and precision profile options,
telemetry options, the idempotency key and the output options. Fixed by the workload: design, scene, capacities,
step, iteration budget, decimation. Giving `--workload` together with any fixed argument is a refusal, whether
or not the two values agree; one way to say a thing keeps the request digest unique.

**Refusals.** Both use the protocol family's existing code for arguments that fail the schema, `FROB-REF-802`
(exit code 3, `retry: after-change`, nothing charged): an unknown workload or ground (pointer `workload`;
repairs: the nearest valid identifier; `frob schema sim.run`), and a fixed argument given beside `--workload`
(pointer: that argument; `observed`: both values; repairs: drop the argument; or drop `--workload` and type the
full request, which is then not stamped unless it resolves to the same fields). No new code is introduced.

**Equivalence (the property that makes the option safe).** The resolved request is canonicalized exactly as a
fully typed request is. Therefore `--workload Q` and the equivalent explicit arguments give the same request
digest, the same step-plan identity and the same per-world digests, and an idempotency key bound to one is
answered by the other.

**The stamp.** Every receipt and result of a run whose resolved request equals a workload's expansion carries
`workload { id, ground, workload_id, registry_digest, status }` in its identities (`status` is the record's
`default` or `frozen`). The stamp is a function of the resolved request, not of how it was typed: a hand-typed
request that resolves to Q's fields is stamped Q, and a request that differs in one capacity is not stamped at
all. The disclosure block and the target register read the stamp; neither trusts a workload name passed beside a
figure.

**Wiring.** The argument group is registered once in `frob-verbs` and attached to `sim.run` here, on every tier
the verb supports when this bead lands (the referee from the first milestone; the batched tiers as their beads
land). The verb's registry entry, help text and schema gain the parameter, and the surface-parity check covers
it on the command line and on the MCP surface.

**Determinism and evidence.** Resolution is a pure function of the identifier, the ground and the embedded
registry. The stamp is identity data, not a claim.

## Acceptance criteria

- [ ] `frob sim run --workload Q --tier batch-cpu --worlds 64 --seconds 2 --seed 7 --json` and the same request with design, scene, capacities, step and iterations typed out return equal request digests, equal step-plan identities and equal per-world digests.
- [ ] `frob sim run --workload H --tier referee --worlds 1 --seconds 2 --seed 7 --json` runs and its receipt carries `workload.id = "H"` with the `WorkloadId` that N36-02's registry prints.
- [ ] An unknown identifier, an unknown ground and a fixed argument given beside `--workload` (one case per fixed argument) are each refused with `FROB-REF-802`, exit code 3, the stated pointer and repairs, before admission; no device memory is allocated and no budget is charged.
- [ ] `--worlds` absent runs 8,192 worlds on a device tier; `--worlds 256` runs 256; the stamp is the same in both.
- [ ] A hand-typed request equal to Q's expansion is stamped Q; the same request with contact capacity 48 is not stamped.
- [ ] Changing any field of a record in a scratch registry changes the `WorkloadId` on the receipt, and a figure measured under the old identity is not accepted by the target register against a row stated on the new one.
- [ ] `frob schema sim.run` lists the parameter with its admissible values; the verb registry's surface-parity and schema-snapshot checks pass on the command line and on the MCP surface.
- [ ] The resolver calls N36-02's parser in `frob-core` and `frob-verbs` holds no second parser of `frob.workload/1` (a source check); `cargo tree` shows no dependency of `frob-verbs` or `frob-kernels` on the conformance crate.
- [ ] `CONTRACT.md` of `frob-verbs` documents the argument group, the free and fixed lists and the two refusals.

## Test plan

### Unit tests

`cargo test -p frob-verbs workload_arg` (the parser's own tests, an unknown field and the identity property, are
N36-02's in `frob-core` and are not repeated):
- `resolve_q_and_h_fields`: the resolved requests carry degrees of freedom 18 and 35; capacities (32, 160) and (64, 320); h = 1/500 s; d = 10.
- `embedded_registry_digest`: `registry_digest()` equals the digest of the file N36-02's lint accepts; a scratch registry gives its own.
- `resolve_default_ground`: `Q` → flat; `Q:rough` → rough; `H:heightfield` → heightfield; `H:rough` → refused, naming `flat` and `heightfield`.
- `unknown_id_names_nearest`: `q` and `Quad` → refused with `Q` first.
- `fixed_argument_conflicts` (one case each for design, scene, contact capacity, row capacity, step, iterations, decimation), including the case where the explicit value equals the record's.
- `free_arguments_do_not_change_stamp`.
- `explicit_equals_workload_digest`: canonical request bytes are identical for the two spellings.
- `stamp_is_function_of_resolved_request`: equal fields → stamped; capacity 48 → no stamp.
- `unadmitted_model_refused`: a scratch record naming a model that is not admitted.
- `default_worlds_only_when_absent`.

### End-to-end script and logging

`scripts/e2e/perf_workload_selector.sh` (owned by this bead; sources the shared end-to-end helper; seed-explicit,
default seed 7; idempotent; `batch-cpu` and the referee only, so it runs inside the default machine envelope).
Steps: `resolve` (`frob sim run --workload Q --tier batch-cpu --worlds 64 --seconds 2 --seed 7 --json`, then the
explicit form; assert equal digests); `humanoid` (`--workload H --tier referee --worlds 1 --seconds 2`; assert
the stamp); `grounds` (`Q:rough`, `H:heightfield`; assert the scene identity differs from the flat run and the
`WorkloadId` does not); `refusals` (unknown identifier, unknown ground, each fixed argument beside `--workload`;
assert code, exit code 3, pointer, repairs and that the allocated-bytes figure is unchanged); `scratch` (a
scratch registry with one capacity changed; assert a different `WorkloadId` on the receipt); `mcp` (the same
`resolve` request over the MCP surface; assert an identical result apart from timestamps). Each NDJSON line
carries `ts`, `script`, `bead`, `step`, `event`, the exact command line, exit code, wall time, the envelope's
evidence block, the request digest, the step-plan identity, the stamp, and on a refusal the whole refusal object;
on failure the first differing field and both request records. A final `summary` counts assertions.

### Known answers and negative controls

- KA-815 through the verb: the receipt of `--workload Q` shows row capacity 160 and that of `--workload H` shows 320.
- Negative controls (registered; each must make a named test or the script fail): a resolver in which an explicit capacity silently overrides the record; a stamp taken from the typed name instead of the resolved request; a resolver that falls back to the default ground on a misspelt one.
- Metamorphic: the order of options on the command line does not change the request digest; `--workload Q` equals `--workload Q:flat`.
- Determinism lanes: the two spellings twice on one machine and across worker counts on `batch-cpu` give identical digests (class D2 for the run; resolution itself is exact).

## Considerations

- The option is a DESIGN addition to the verb's surface. If the verb registry's owners prefer another spelling, the resolver and the stamp stay and only the parameter name changes; the many beads that write `--workload` follow the registry's retired-name rule.
- OPEN-SPARK-3 (owner: the Spark lead) freezes the capacities of Q and H at M2. A change there changes `WorkloadId`; figures under the old identity stay on record and are not compared with rows stated on the new one. OPEN-PERF-4 does the same for the step and decimation.
- Other verbs that take the option (`sim.estimate`, `train.start`, `spark.place`, `spark.precompile`, `spark.check`) must call this resolver and not parse the registry themselves; a second parser is the failure this bead exists to prevent.
- Workloads other than Q and H (their capacities are a separate open question of the dynamics chapter) are added as registry rows, with no change here.
- The reference robots are parity fixtures; a stamp is never evidence about a physical robot.
