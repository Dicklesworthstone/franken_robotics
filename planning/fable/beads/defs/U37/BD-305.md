## Background

The threat model's third asset is **private places**: a scan of a real home or workplace, or anything derived
from it, leaving the machine or appearing in a shared view. There is no out-of-scope clause for it. The rule:
a scene pack built from a scan of a real home or workplace is marked `private`. It is stored under a
configured private root outside the repository. Stills, replays, reports and fixtures derived from it inherit
the mark and are not exported without an explicit flag. FACT: the owner's own reconstruction skills state the
same rule for walkthrough captures.

Four statements complete it.

- **Inheritance is computed.** The mark of an artifact is the join of the marks of everything in its lineage,
  so a still of a replay of a policy evaluated in a private scene is private without anyone marking it; policy
  weights trained in a private scene inherit by default (the owner's decision on that is N37-20). The lattice
  and the join are N37-17.
- **Seeds, not voxels.** Only seeds, recipes, design and module differences, receipts and policy weights
  cross between machines. A private scan stays on the machine that holds it, and a job that needs it runs
  there.
- **Views.** Private objects are absent from catalogs, the shared archive, the leaderboard and MCP resource
  lists; a direct read needs the scope `private:read`, and an export needs `private:export` and the flag;
  otherwise the refusal is `FROB-REF-731`.
- **Purge.** `scene.purge` removes a private pack and the lineage closure of everything derived from it
  (N37-19).

This seed bead is the enforcement: where private bytes live, what listings show, what reads and exports
require, and the two gate records that the seed names. Gates (TARGET, M3): **GATE-SAFE-04**, privacy: for a
private scene, each derived artifact kind carries the mark; exports without the flag are refused; after
`scene.purge` no digest of the closure remains in the store. **GATE-SAFE-05**, licences: over random
derivation graphs the licence set equals the join of the inputs; a research-only asset cannot be made to
enter an exported report or pack. Risk served: RISK-12 (a private scan leaks through a still, a fixture or
policy weights; high; owner: the evidence-store lead).

Rejected alternatives: a private flag honoured only by the export verb (listings, resource reads and shared
views leak first); encrypting private packs at rest as the main control (it protects a stolen disk, which is
outside this threat model, and does nothing about a still in a shared view).

## Scope

In: routing of private objects to the private root; listing filters on every catalog and shared view; the
read check and the export check with `FROB-REF-731`; the export log; the envelope's mark and log redaction;
the cross-machine rule for private objects; the generated sweep over derived artifact kinds; the records of
GATE-SAFE-04 and GATE-SAFE-05. Out: the lattice and join (N37-17); licence decisions and notices (N37-18);
the purge verb (N37-19); the path jail (N37-11); tokens and scopes (BD-258); real-place ingestion (M5).

## Technical approach

1. **Two store roots.** The content store has a project root and a private root (the owner-held
   configuration key `roots.private`, which must lie outside every version-controlled tree). The store writes
   an object beneath the private root exactly when its computed mark is `Private`. If a late lineage edge
   raises an existing object to `Private`, the same transaction copies its bytes beneath the private root,
   verifies the digest and removes the public copy. With no private root configured, any write whose mark is
   `Private` is refused (`FROB-REF-734`, `observed = root-unset`): private data is never parked in the project
   tree.
2. **Declaring a pack private.** An importer of a real-place capture sets the root mark `Private`. Any
   session may also declare a pack private when it imports it (`scene import --private`; DESIGN: an import
   argument that can only raise the root mark; no verb or argument lowers a mark).
3. **Listings.** Every listing verb and view takes its rows through one filter,
   `visible(session, object)`: an object marked `Private` is omitted from `scene.list`, `artifact.list`,
   `run.list`, `job.list` rows that name private scenes, the catalogs `frob://catalog/{kind}`, MCP
   `resources/list` and resource templates, the shared archive and the leaderboard. A session holding
   `private:read` sees its private objects only through an explicit private listing (`scene list --private`,
   `artifact list --private`; DESIGN), whose envelope is itself marked private. Shared views (archive,
   leaderboard) never contain private rows for anyone and print no count of withheld rows. A registry lint
   asserts that every verb whose output schema is a list of stored objects is declared `listing = true` and
   calls the filter (the list type cannot be constructed without it).
4. **Direct reads.** For any verb argument that resolves to a stored object, the dispatcher reads the
   object's mark before the handler runs; a `Private` object without `private:read` in the token is refused
   with `FROB-REF-731`. This covers `artifact.read`, `run.show`, `scene.show`, the telemetry, explain,
   autopsy, report and study verbs, forks and replays, and MCP resource reads.
5. **Exports.** Through the one export door: a `Private` artifact is exported only if the token holds
   `private:export`, the call passes `--allow-private-export`, and the owner-held key
   `private.export_allowed` is true; otherwise `FROB-REF-731` with `observed` one of `missing-scope`,
   `missing-flag`, `export-disabled-by-owner`. An exported private artifact keeps `privacy: private` in its
   manifest, so a re-import elsewhere is private again. Every private export is a row in the ledger table
   `export` (session, artifact digest, kind, time, path relative to the export root, the flag), which the
   purge receipt later reads.
6. **Between machines.** Sending a private-marked object to the other machine is an export in the sense of
   step 5. Independently, compiled scene fields and world state never cross at all (the device chapter's
   transfer-class refusal). A job whose inputs include a private scan is scheduled on the machine that holds
   it; submitted elsewhere it is refused with `FROB-REF-731` and the repair "run it on the holder".
7. **The refusal.** `FROB-REF-731`, "a private object, or anything derived from one, without the private
   scope and flag". Exit 5; `retry: after-change`. Ranked repairs (DESIGN): (1) keep the result local and read
   it through verbs under `private:read`, running the job on the machine that holds the scan; (2) if the
   result must be shared, re-derive it from a non-private proxy of the place (a scene authored in the interior
   grammar from measured dimensions); (3) ask the owner for `private:export` and pass the flag.
8. **Envelopes and logs.** An envelope whose result was computed from private objects carries
   `"marks": {"privacy": "private"}`. The structured-logging helper of the end-to-end harness, the per-bead
   log and the job log record, for such an envelope, its digest and its refusal or summary counts only, never
   the result body: logs never contain private-scene data.
9. **The sweep over derived artifact kinds (first clause of GATE-SAFE-04).** `registries/artifact-kinds.toml`
   lists every stored and exported kind with `scene_derivable = true | false` and, when true, the fixture
   pipeline that produces one from a scene. The sweep builds a `synthetic` stand-in pack declared private and
   research-only, runs each pipeline, and asserts each product's mark. Kinds at M3: compiled scene; clearance
   complex; run and episode; chunk; snapshot; still and contact sheet; replay packet; telemetry summary and
   histogram; verdict; study and comparison; scorecard row; fixture; memo node; trained weights and
   checkpoint; minimal counterexample world; hard-set entry; fork and intervention result; mission answer and
   its certificate bundle; report (design, run, mission). A kind marked derivable with no pipeline fails the
   sweep, so a new kind cannot be missed; kinds that arrive later (skill artifacts, calibration datasets,
   build packets, kits) add their rows and re-run the gate.
10. **Gate records.** GATE-SAFE-04: kinds swept and marked (n of n); export attempts without scope, without
    flag and with the owner key off, per export kind (all refused); the purge check (`remaining_digests = 0`);
    listings byte-identical before and after for a session without the scope; controls caught.
    GATE-SAFE-05: the random-graph property count and the laundering battery from N37-18. Both recorded by a
    session that did not implement the mechanisms.

## Acceptance criteria

- [ ] GATE-SAFE-04 (TARGET): for a private scene every derived artifact kind of the registry carries the
      mark; exports without the flag are refused; after `scene.purge` no digest of the closure remains.
      Recorded with counts (seed done-condition).
- [ ] GATE-SAFE-05 (TARGET): the licence set equals the join over 10⁴ random derivation graphs; a
      research-only asset cannot be made to enter an exported report or pack. Recorded (seed done-condition).
- [ ] For a session without `private:read`, every listing, catalog and MCP resource list is byte-identical
      before and after the private scene and its derivatives are created; the shared archive and leaderboard
      contain none of them for any session.
- [ ] A direct read of each derived kind without `private:read` is `FROB-REF-731`, exit 5.
- [ ] After the full pipeline, no blob of the private closure exists beneath the project root or the export
      root (a hash scan), and with no private root configured the first private write is refused.
- [ ] A private export with scope, flag and owner key succeeds, is logged in the export table, and its
      manifest says `private`; removing any one of the three gives `FROB-REF-731` with the matching
      `observed`.
- [ ] No log written by the pipeline contains bytes of the scene or its derivatives (a scan with the
      fixture's canary strings).

### Known answers and negative controls
KA-827 (join over a three-step derivation: a private, research-only scene; a replay of it; a still of the
replay: private and research-only at every step; exact; tier G1; control: an export without the flag is
refused, and after `scene.purge` no digest of the closure remains). KA-832 (licence joins). Negative controls
registered against GATE-SAFE-04: a `mutants` build whose still writer drops parents (the sweep finds an
unmarked still); one whose MCP resource list skips the filter; one whose `report` export bypasses the export
door; one whose purge follows one level only. Metamorphic relation: for a session without the private scope,
the whole surface behaves identically whether or not private objects exist, apart from direct reads by
identifier. Determinism lanes: marks, listings and refusals identical on Linux and macOS.

## Considerations

- A direct read by identifier answers `FROB-REF-731`, which tells a caller who already holds the identifier
  that the object exists; listings never reveal it. This is the stated behaviour and is accepted.
- A sealed qualification family built on a private scan needs both isolations; they are independent marks
  with their own refusals.
- Telemetry derived from a private scene keeps its privacy class through retention and collection: the
  collector's tombstones for private objects are themselves private rows.
- Over-marking has a cost (results that cannot be shared); the repair is a non-private proxy scene, which is
  also the fallback of real-place ingestion.
- A local user with root, backups made outside the tool, and bytes a caller has read and saved elsewhere are
  beyond these mechanisms; the documentation says so.
