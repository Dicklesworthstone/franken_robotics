## Background

Imports are hostile input. The URDF, MJCF and mesh importers are safe Rust with limits on size, nesting depth
and polygon count (a violated limit is `FROB-REF-832`), and **each has a fuzz target**. An import always
returns a loss report. Weights are hostile data too: a policy file is read by a bounded reader of the plain
tensor layout. The threat is a hostile imported file reaching the owner's machines through a parser.

Gate **GATE-SAFE-07** (Known answer, TARGET): at least 10⁷ fuzz executions per importer with no panic; each
limit is reached by a crafted file and refused. The gate register dates it to M2, and its first record is
taken then by the importer script on the importers that exist at M2 (the XML reader, the URDF and MJCF
mappers, the STL and OBJ readers, the scene source decoder). The limits, the crafted corpus, the target
functions and the seeded driver were built with the importers (N37-05); the M2 campaign is N37-06.

This seed bead completes the work at M3: every importer is in a registry that the gate reads, so none can be
missed; the importers that arrive by M3 get targets and limit rows; inputs are generated with knowledge of
each format, not only mutated; crashes have a fixed route into the regression corpus and the negative-control
registry; the hostile-input corpora of the safety chapter are packaged for the conformance batteries; and the
gate is re-recorded over the complete surface. Seed done-condition: GATE-SAFE-07.

Why generation beside mutation: a mutational engine on a 64 MiB limit never reaches the parts of a parser
that sit behind a well-formed header; a generator that emits well-formed prefixes with one hostile field
does. Why a registry: "each importer has a fuzz target" is a statement about a list, and a list kept in
prose falls behind the code.

## Scope

In: `registries/importers.toml` and its lint; targets and limit rows for the M3 importers; structure-aware
generators per format; the extended oracle; the recurring campaign with summed, disjoint index ranges; crash
triage; the corpora package; the M3 record of the gate. Out: the limits and targets of the M1 importers
(N37-05); the M2 script and record (N37-06); the weight reader itself (N37-07); the thirteen format readers'
own fuzz gate (the format registry's gate, owned by the workspace chapter); the scene decoders themselves.

## Technical approach

1. **The importer registry (DESIGN).** `registries/importers.toml`, one row per importer:
   ```toml
   [[importer]]
   name = "urdf"
   crate = "frob-io"
   entry = "frob_io::urdf::import"
   verbs = ["design.import"]
   extensions = [".urdf", ".xml"]
   profile_rows = ["xml", "mesh"]
   fuzz_target = "urdf_import"
   generator = "xml-robot"
   corpus = "crates/frob-io/fuzz_corpus/urdf_import"
   threats = ["T1.b"]
   since = "M1"
   ```
   Lint (`crates/frob-conformance/tests/importers_registry.rs`): every verb argument that reads a file in a
   foreign or bulk format maps to exactly one row; every row names an existing target function, at least one
   limit row and a non-empty seed corpus; a row without a generator must state `generator = "mutation-only"`
   with a reason. A new importer without a row fails the build's tests.
2. **Rows at M3.** From M1 and M2: `xml` (the reader alone), `urdf`, `mjcf`, `stl`, `obj`, `scene-decode`,
   `weights` (the plain tensor container; target `weights_reader`, built by N37-07 and fuzzed in the M2
   campaign of N37-06; this bead adds its structure-aware generator). Added by this bead: `scene-assets` (the
   asset path of `scene.import`: container JSON and binary chunks, accessors and buffer views, texture and
   material counts; target `scene_assets_import`; limits of the scene import profile, refusal by the scene
   chapter's decode code); `scan-schema` (the scan-import interface's schema fixtures: manifest, coverage
   masks, scale status; target `scan_schema_read`); `robot-log` (line-oriented logs offered to the data
   admission verb, each line typed as untrusted text; target `robot_log_read`; limits: bytes, lines, line
   length). An importer that arrives after M3 (real-place capture packages, as-built scans, calibration
   datasets) adds its row in its own bead and re-runs the gate.
3. **Generators** (`frob-conformance::fuzz::gen`, seeded, counter-based like the mutator, so execution i of
   seed s is reproducible):
   - `xml-robot`: random element trees over the URDF and MJCF vocabularies with valid nesting most of the
     time and one or two violations; numeric attributes drawn from boundary sets (0, −0.0, 1e308, 1e−320,
     NaN and infinity spellings, 20-digit integers, empty strings); names drawn from the hostile-string
     corpus; includes and mesh references drawn from the path-jail corpus.
   - `mesh`: binary STL headers with consistent and inconsistent triangle counts; ASCII STL and OBJ with long
     lines, huge indices, negative indices, faces referencing missing vertices.
   - `tensor-container`: header lengths around the true length; offsets that overlap, leave gaps or exceed
     the buffer; shapes whose product overflows; non-finite values; metadata with unknown keys.
   - `scene-container`: chunk lengths that disagree with the file; accessor counts beyond buffer views;
     self-referential node trees; instance depth one over the limit.
   Each campaign splits its executions between mutation and generation (DESIGN: half and half) and records
   both counts.
4. **The oracle, extended.** For every execution: (a) the call returns `Ok` with a loss report or `Err` with
   a refusal code that is in the registry; (b) no panic, no abort, no arithmetic overflow (overflow checks
   on); (c) at most 1 s; (d) peak allocation at most 64 times the input length plus 1 MiB; (e) no file-system
   access outside the in-memory import root (the target's jail records every open; any attempt outside is a
   violation); (f) on `Ok`, the product passes the canonical round trip of its format and every string in it
   that came from the input is of the untrusted type; (g) on `Err` nothing was written to the store.
5. **Campaign arithmetic.** At least 10⁷ executions per importer per recorded gate run. With ten importers
   that is 10⁸ executions; the campaign is split into runs that each fit the default compute envelope (8
   cores, under an hour), each with a disjoint index range of the same seed, and the record sums them
   (`executions = Σ ranges`, with the ranges listed). A run is never shortened to fit; a slower importer gets
   more runs.
6. **Crash route.** A violation of the oracle: the driver replays (seed, target, index), minimizes the input
   by delta debugging, stores it under `<corpus>/regressions/<digest>`, and emits a record. The gate is FAIL
   until the defect is fixed. The reproducer is then registered in the negative-control registry as a
   permanent control of GATE-SAFE-07 (kind `planted-input`) with the commit of the fix. If the fault is in a
   sibling library reached through the airlock, it becomes an admission test here and an upstream work item
   in the sibling's repository; no local patch stands in for the fix.
7. **Limits, complete.** The crafted at-limit and over-limit corpus is regenerated for every limit row of
   every importer row (the lint asserts that each limit key appears in the corpus), and each pair is run
   through its verb: `FROB-REF-832` for design and weight importers; the scene chapter's decode refusal for
   scene importers; `observed = limit + 1` in every case.
8. **The corpora package.** `crates/frob-conformance/corpora/` with `corpora.toml` (name, digest of the
   directory listing, count, the gate it serves): `limits` (every pair), `injection` (the hostile strings),
   `path_jail` (traversal, absolute, link recipes), `code_payloads` (the signature table's specimens),
   `weights` (admitted and refused specimens), `regressions` (minimized reproducers). The M3 conformance bead
   wires them into the chaos tier's malformed-input family; this bead guarantees each exists, is counted and
   is hashed.
9. **Record.** Per importer: executions by mutation and by generation, index ranges, panics, timeouts, oracle
   violations (all zero), limit rows reached and refused (n of n), regressions replayed and passing, controls
   caught.

## Acceptance criteria

- [ ] GATE-SAFE-07 on the M3 surface (TARGET): at least 10⁷ fuzz executions for each importer in the registry
      with no panic; each limit reached by a crafted file and refused. The M3 part recorded with counts and
      ranges from the `g4_chaos` receipt of the `--profile m3` run with `record_gate … --part M3` (seed
      done-condition).
- [ ] The registry lint passes; a planted verb argument that reads a new file format with no importer row
      fails; a planted row with no target fails.
- [ ] Every limit key of every row has an at-limit and an over-limit file in the corpus, and each over-limit
      file is refused with `observed = limit + 1`.
- [ ] The extended oracle is enforced in every target; a planted importer that opens `../x` relative to its
      root, one that writes to the store before failing, and one that returns an imported string as a plain
      string are each reported as violations.
- [ ] A planted panic behind a well-formed header (reachable by generation, not by plain mutation of the seed
      corpus within 10⁵ executions) is found by the generator lane.
- [ ] `corpora.toml` lists the six corpora with counts and digests; the injection corpus has at least 200
      strings.
- [ ] Every regression reproducer on file replays as passing in the ordinary test run.

## Test plan

### Unit tests
`cargo test -p frob-conformance --test importers_registry --test fuzz_generators --test fuzz_oracle` and the
smoke lanes of each owning crate:
- `every_file_reading_argument_has_importer_row`; `row_requires_target_limits_and_corpus`.
- `generator_is_counter_based` (execution i of seed s identical across `--jobs`).
- `xml_robot_generator_reaches_deep_paths`: within 10⁴ generated inputs at least one is accepted by the URDF
  mapper and at least one is refused by each of five named refusal codes (a coverage proxy stated in advance).
- `tensor_container_generator_hits_each_check`: each of the seven reader checks refuses at least once in 10⁴
  inputs.
- `oracle_detects_outside_open`, `oracle_detects_store_write_on_error`, `oracle_detects_plain_string`
  (three planted importers, `synthetic`).
- `limit_corpus_covers_every_key`.
- `fuzz_smoke_<target>`: 10⁵ executions per target, half generated.
- `regressions_replay_clean`.
- `corpora_manifest_counts_and_digests`.

### End-to-end script and logging
`scripts/e2e/safe_importers.sh --long --profile m3` (the script of N37-06, extended here with the option
`--profile m3`): reads the importer registry, runs the limit pairs of every row through `frob`, runs the
campaign per target with its index range, replays regressions, runs the planted builds (`--features
gauntlet-mutations`), and ends with its `receipt` step (`e2e_tier g4_chaos GATE-SAFE-07 --mutations`), whose
tier entry now covers every row of the importer registry. The script records nothing (convention 9): this
bead records the M3 part from that receipt, in a session that did not implement the importers, with `cargo
run -p frob-conformance --example record_gate -- --gate GATE-SAFE-07 --receipt <hash> --part M3`; the M2
part is N37-06's and is not rewritten. Logged per STD-E2E:
per importer `metric` lines `executions_mutation`, `executions_generation`, `panics`, `timeouts`,
`oracle_violations`, `max_alloc_ratio`, each against its threshold; per limit pair the refusal fields; the
ranges summed; a `summary` naming GATE-SAFE-07. Inputs are named by digest and never logged.

### Known answers and negative controls
Known answers: `observed = limit + 1` for every limit row; zero violations in at least 10⁷ executions per
importer. (The known-answer appendix has no row for this gate; these are the bead-level answers, listed in the
chapter's registry.) Negative controls registered against GATE-SAFE-07: the planted `unwrap()` and the
removed polygon check of the M2 script; the header-gated panic that only generation reaches; the three planted
importers of the oracle tests; every minimized regression ever found. Metamorphic relation: prepending a
byte-order mark or changing attribute order in a generated XML document changes no verdict of the limit rows.
Determinism lanes: identical campaign summaries for equal (seed, range) across worker counts and machines.

## Considerations

- Ten importers at 10⁷ executions each is the largest routine compute cost of the safety chapter; it stays
  inside the default envelope by splitting, and a recorded gate run lists its ranges so a reviewer can check
  the sum.
- Decoders reached through the airlock may contain unsafe code of the sibling; the fuzz lane runs them with
  overflow checks and debug assertions, and, where the toolchain supports it on the host, an additional lane
  under the address sanitizer is recorded separately (not required for the gate).
- The format readers of the thirteen artifact formats have their own fuzz clause in the format registry's
  gate; an importer row is for foreign or bulk inputs, and the two lists together cover "the thirteen format
  readers, the envelope parser and every importer" of the chaos tier.
- The weight allowlist decision (owner: the learning lead) changes which families the `weights` target's
  generator emits as admissible; the default is the reference policy's single family.
- The seed lists this bead at M3 while the gate's first date is M2; the M2 record is N37-06's.
