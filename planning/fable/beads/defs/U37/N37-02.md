## Background

Every mechanism of the safety chapter (the path jail, the untrusted-text type, the import limits, the private
mark, the licence join, the no-authorization flags, the claim product, the refusal of D4 results as evidence,
confirmation isolation, capability scopes and budgets) is the default behaviour of the system. The standing
rule is: **none is on by request, and none has an off switch below an owner-held configuration.** An agent is
the party these mechanisms constrain; if a verb argument, a command-line flag, an environment variable or a
session scope could disable one, an agent acting on injected text (threat T1 of the threat model: a confused,
wasteful or injected agent) would disable it.

Some values do have to be chosen by a person: where the private root is, which directory exports may land in,
how large an import may be, how long logs are kept. Those live in one file that only the owner edits, outside
any session. This bead defines that file, how it is protected, what its fail-closed defaults are, and the test
sweep that proves no other path changes a safety behaviour.

Design decision and rejected alternatives. (1) Rejected: per-session safety settings carried in the capability
token. A token is something an agent holds and derives; anything in it is agent-reachable. (2) Rejected:
environment variables. They are inherited by sub-agents and set by tools the owner never reads. (3) Rejected: a
`--unsafe` family of flags "for tests". Tests that need a weakened build use a compile-time feature (`mutants`)
that never ships; a runtime switch that exists for tests exists for everyone.

## Scope

In: the file `safety.toml`, its schema, location, ownership and permission checks, defaults, digest and
surfacing through `doctor` and `session.show`; the three static lints and the behavioural sweep that enforce
"no off switch"; the list of keys with their owning mechanisms. Out: the mechanisms that read each key (path
jail N37-11; import limits N37-05; weight allowlist N37-07; private places BD-305; retention N37-30 and the
store's collector; compute envelope, owned by the performance chapter); capability tokens (BD-258).

## Technical approach

1. **Location (DESIGN).** `$FROB_STATE/safety.toml`, where `$FROB_STATE` is the daemon's state root (default
   `~/.local/state/frob` on Linux, `~/Library/Application Support/frob` on macOS). The environment variable
   chooses the state root only at process start of `frobd`, which the owner launches; `frob` and `frob-mcp` ask
   the daemon for the configuration digest and never read a second file. With no daemon (CPU-tier verbs run in
   process and the envelope says so), `frob` reads the same file itself under the same checks.
2. **Protection.** At start the reader opens the file through a directory handle on the state root and checks:
   it is a regular file, not a symbolic link; its owner is the effective user; its mode has no group or other
   write bit (expected 0600); the state root has mode 0700. Any failure is a start-up error of `frobd` (it does
   not start) and a refusal of every verb in the no-daemon path (exit 5, `FROB-REF-734`, pointer
   `safety.toml`, message naming the failed check). The file is read once; a change takes effect at restart.
   Its BLAKE3 digest (plain blob hash) is part of the daemon configuration digest, is printed by `frob doctor`
   and `frob session show`, and is recorded in every job row, so a later reader can tell under which
   configuration a result was produced.
3. **Schema `frob.safety/1` and defaults.** Unknown key, duplicate key or wrong type is a start-up error (the
   strict TOML-subset reader of `frob-core`). A missing file means every default below.
   | Key | Meaning | Default (fail-closed) |
   |---|---|---|
   | `roots.project` | Directory under which project-relative path arguments resolve | The directory `frobd` was started in |
   | `roots.export` | The only directory exports may be written under | `<project>/exports`, created 0700 |
   | `roots.private` | Where private scene packs and everything derived from them are stored; must lie outside every version-controlled tree (the reader walks ancestors and refuses a path with a `.git` ancestor) | Unset: importing or deriving anything private is refused until the owner sets it |
   | `import.profile` | Name of the import profile in force (`default`, `large-building`, …) | `default` |
   | `weights.allowlist` | Path of the weight-layout and architecture allowlist registry row set | The single layout and family of the reference policy |
   | `private.export_allowed` | Whether an export of a private-marked artifact can be admitted at all (the per-call flag and the `private:export` scope are still required) | `false` |
   | `private.weights_inherit`, `licence.weights_inherit` | Whether policy weights trained in a private or research-only scene inherit its privacy mark, and its licence set | `true` and `true` (the fail-closed default of the open question on inheritance: they inherit both) |
   | `retention.job_log_days`, `retention.idempotency_key_days` | Retention of job logs and idempotency keys | 30 and 30 |
   | `retention.retired_clusters` | What happens to retired confirmation clusters | `sealed-indefinitely` |
   | `qualification.admin_principals` | Principals for which the daemon may mint the owner's qualification scope | The owner only |
   | `envelope.class` | Compute envelope class in force (E0: 16 GiB, 8 cores, 1 hour, one device) | `E0` |
   | `mcp.rate_limit_per_min`, `mcp.subscription_listeners` | Server-wide request rate and subscription-listener bound | 600; 64 |
   | `admission.max_utilization` | Device utilization above which new work is refused | 0.8 (TARGET) |
   Each key names its owning mechanism in a comment column of the generated documentation. A key can only make
   a default more permissive in the listed, bounded ways; no key removes a mechanism.
4. **What does not exist (the rule, enforced three ways).**
   - *Schema lint* (`crates/frob-verbs/tests/no_off_switch.rs`): walks every verb input schema in the registry
     and fails on a property whose name matches `^(no|skip|disable|unsafe|trust|force|bypass)[-_]` or
     `allow[-_]`, except entries of a reviewed allow-list file `registries/safety-flags.toml`. The allow-list
     starts with exactly one entry, `allow_private_export`, annotated with the scope it additionally requires
     (`private:export`) and the configuration key that must also be true.
   - *Environment lint*: `std::env::var` and `var_os` may be called only in `frob-cli::env`; that module's list
     of names is a constant array, and a test asserts the array equals the reviewed list (`FROB_STATE`,
     `FROB_TOKEN`, `NO_COLOR`, the build-offload variables). A token from the environment can only narrow
     authority.
   - *Behavioural sweep*: for each mechanism row of a table in the test (mechanism, a request that would be
     refused, the refusal code), the test replays the request with each of a list of plausible disabling
     arguments (`--force`, `--no-jail`, `--trusted`, `--skip-limits`, `--allow-true-flags`, `unsafe: true` in
     JSON, and every allow-listed flag without its scope). Expected: the unknown ones are `FROB-REF-802`
     (arguments fail the schema; a misspelt or unknown parameter is a refusal, never a default), the
     allow-listed one without its scope is `FROB-REF-731`, and the original refusal still stands.
5. **Surfacing.** `frob doctor --json` prints the configuration digest, each key with its value and whether it
   is a default, and a finding of severity high for `roots.private` unset when any private-marked object exists
   in the store. `frob session show` prints the digest. Neither prints the daemon key.
6. **Classes.** D0. Nothing here produces evidence; the digest is an identity recorded beside results.

## Acceptance criteria

- [ ] A `safety.toml` that is a symbolic link, is owned by another user, or is group-writable stops `frobd`
      from starting and makes the no-daemon path refuse with exit 5.
- [ ] With no file, the defaults of the table are in force and `doctor` reports each as `default`.
- [ ] `roots.private` inside a version-controlled tree is a start-up error naming the `.git` ancestor.
- [ ] The schema lint, the environment lint and the behavioural sweep pass; planting a property named
      `skip_limits` on any verb fails the schema lint; planting `std::env::var("FROB_NO_JAIL")` outside the
      allowed module fails the environment lint.
- [ ] The configuration digest appears in `doctor`, `session show` and each job row, and changes when any key
      changes.
- [ ] No verb, flag, scope or environment variable makes any of the sweep's refused requests succeed.

## Test plan

### Unit tests
`cargo test -p frob-verbs --test no_off_switch -p frob-cli --test safety_config` (real files in a temporary
state root; no mocks):
- `missing_file_gives_defaults`: E0, 30, 30, `sealed-indefinitely`, 0.8, `private.export_allowed = false`.
- `symlinked_config_refused`, `wrong_owner_refused` (skipped with a logged reason when not runnable as a
  second user), `group_writable_refused`.
- `private_root_under_git_refused`.
- `unknown_key_is_error` (`roots.privat`): line and column reported.
- `digest_changes_with_any_key` (property over each key).
- `schema_lint_catches_planted_switch`; `env_lint_catches_planted_read`.
- `sweep_table`: one row per mechanism (path jail, import limit, flags reader, private export, licence export,
  D4 evidence, citation above product, code payload); each row's disabling attempts keep the refusal.

### End-to-end script and logging
This bead creates `scripts/e2e/safe_no_off_switch.sh` (plain shell, sourcing the shared helper of STD-E2E).
Against the real `frob` binary it: starts with a missing configuration and asserts the defaults through
`frob doctor --json`; installs a symlinked and then a group-writable `safety.toml` and asserts the refusal;
then replays the refused requests that exist at the build's milestone (at M1: a path outside the roots, an
over-limit import, a code-bearing payload, an export with a flag-producing argument; later milestones add a
private export, a missing scope, a D4 result as evidence) with five disabling arguments each (`--force`,
`--no-jail`, `--trusted`, `--skip-limits`, a JSON member `"unsafe": true`) and asserts the refusal codes.
Logged to `target/e2e-logs/safe_no_off_switch/<utc-timestamp>.ndjson`: the command line, exit code, refusal
code, the configuration digest from the envelope, one `assert` line per attempt, and a `summary` with counts
(no gate). The M3 script `safe_capabilities.sh` (N37-15) calls this script as its `no_off_switch` step.

### Known answers and negative controls
Known answers: the default values above. Negative controls: the two planted lints; a `mutants` build in which
`--trusted` is honoured must fail the sweep. Determinism lanes: the configuration digest is identical on Linux
and macOS for the same bytes; twice on one machine.

## Considerations

- The owner can weaken a default; that is the meaning of owner-held. Every such key is bounded (a larger limit,
  a different root), and `doctor` prints non-default keys so a reviewer sees them.
- A local user with root is outside the threat model: the ownership and mode checks stop accidents and
  same-user agents that try to edit the file through a verb (no verb writes outside the roots), not root.
- Open questions folded in as defaults: retention periods (30 days; retired clusters sealed indefinitely;
  owner: the project owner; N37-30), weights inheriting marks (true; N37-20), the weight allowlist (N37-08),
  the compute envelope (E0 until the owner approves a class).
- If a future mechanism needs a new owner-set value it adds a key here by ADR; it never adds a verb flag.
