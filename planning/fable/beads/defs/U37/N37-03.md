## Background

In the first version of the system an agent submits **designs, task specifications, controller configurations
and policy weights**. It cannot submit kernels or arbitrary programs. This is the first line of the threat
model's defence of the owner's machines against an agent that is confused, wasteful or acting on injected text:
if no verb accepts code, an injected instruction has nothing to run. Invariant **INV-SAFE-01**: no verb accepts
a kernel, a program or an expression outside the closed language.

Three statements make the rule concrete.

- **Expressions are data.** Requirement predicates and reward terms are expressions in the closed, total
  requirement language owned by `frob-spec` (atoms over named signals with units, comparators, Boolean
  connectives, bounded-window temporal operators): every expression has a size bound, and the language has no
  loops and no recursion, so evaluation terminates in time proportional to the expression size times the window.
- **A patch contains typed edits only.** A design patch (`frob.design.patch/1`) is a list of typed edits from a
  closed list, each with typed arguments. It carries no filesystem path and no code.
- **Kernels come from this repository only.** Kernel sources are generated by the repository's own derivation
  and emitters. No verb takes kernel source or a compiled kernel from a caller.

What bounds an MCP client follows from the same rule. The MCP server runs verbs in process, so a client is
bounded by exactly three things: the session's capability scopes; the tool set, which is generated from the
verb registry and holds nothing else; and the rule that text from imports is data. There is no "run this"
tool, and no tool whose argument is interpreted as a program.

Sandboxed custom reward terms (user-supplied code in a sandbox) are tier Frontier and are **not admitted**:
that is an open question for the owner whose fail-closed default is the closed expression language only
(decision bead N37-09). Rejected alternative for this bead: scanning inputs for "dangerous" strings. A deny-list
of strings is never complete; the rule here is positive: an input leaf has one of a closed set of data types,
or the registry does not load.

## Scope

In: the closed list of input leaf types and the registry lint that enforces it; the expression bounds at the
boundary; the patch-shape lint; the blob rule (a blob is a registered format or it is refused) with the
magic-number sniff that names code-bearing payloads; the refusal FROB-REF-828 for a payload that carries code;
the assertion that the MCP tool set equals the registry's. Out: the requirement language itself and its parser
(BD-121); weight-file admission and the weight allowlist (N37-07, N37-08; the second half of FROB-REF-828);
imported text (N37-04, BD-304); importer limits (N37-05); kernel-cache integrity (BD-306, N37-22).

## Technical approach

1. **Closed input leaf types (DESIGN).** Every leaf of every verb input schema in `registries/verbs.toml` must
   be one of: a Boolean; an enumerated string; an identifier (lower-case ASCII pattern, at most 128 bytes); a
   typed identity (`d:`, `m:`, `s:`, …) or digest; `int53`, `u64str`, `i64str`; a quantity with unit; a
   rational; an untrusted-text field (annotation `x-frob-untrusted`, length-capped); an expression
   (`frob.expr/1`); a path argument (`frob.path/1`, resolved by the path jail); an artifact reference; an
   idempotency key; a budget object; a cursor. Arrays and objects are allowed only with closed member lists
   (`additionalProperties: false`). The lint `crates/frob-verbs/tests/input_leaves.rs` walks the registry and
   fails on any other leaf, on a free-form object, and on a property whose name or `format` is one of
   `source`, `script`, `code`, `kernel`, `program`, `wasm`, `plugin`, `command`, `shell`, `exec`, `eval`,
   `callback`, `hook` (the name list is a second net; the type rule is the first).
2. **Expressions.** A `frob.expr/1` leaf is passed, as bytes, to the one parser in `frob-spec` and nowhere
   else. Bounds checked by the dispatcher before parsing and by the parser while parsing (DESIGN defaults,
   recorded in the registry so a refusal can quote them): text at most 65,536 bytes; at most 4,096 nodes;
   nesting depth at most 64; every temporal window finite. The parser is non-recursive (explicit stack), so the
   depth bound, not the call stack, limits nesting. An expression over a bound, or using an operator outside
   the language, is refused by the language's own codes (the requirement chapter's refusals for a missing
   scale, a dimension mismatch, an unbounded window); the dispatcher adds nothing but the size check, which
   reports `FROB-REF-802` with `pointer` at the field, `observed` and `required`.
3. **Patches.** The lint asserts that the schema `frob.design.patch/1` has: an `edits` array whose items are a
   tagged union over the registered edit kinds; no leaf of type `frob.path/1`; no leaf outside the list of
   step 1. A patch that names a file path in a string field cannot validate, because no string field is
   free-form: names are identifiers, and labels are untrusted text that is never a path component.
4. **Blobs.** A verb may take bulk bytes only as (a) a path argument to a file with a registered extension,
   read through the owning crate's reader, or (b) a digest of an object already in the store whose format row
   exists. For each such argument the dispatcher, before calling the reader: checks the declared format is in
   the format or importer registry; reads the first 16 bytes and runs the sniff table below; refuses with
   `FROB-REF-828` on a hit.
   | Signature (hex, at offset 0) | Kind |
   |---|---|
   | `7F 45 4C 46` | ELF executable or shared object |
   | `FE ED FA CE`, `FE ED FA CF`, `CE FA ED FE`, `CF FA ED FE`, `CA FE BA BE` | Mach-O, fat binary (also a class file) |
   | `4D 5A` | Portable executable |
   | `00 61 73 6D` | WebAssembly module |
   | `23 21` | Script with an interpreter line |
   | `80 02` to `80 05` | Pickle stream, protocols 2 to 5 |
   | `50 4B 03 04` | Zip archive (pickled checkpoint archives, wheels, jars) unless the declared format is a registered zip-based format (none at plan time) |
   | `42 43 C0 DE`, `03 02 23 07` | Compiler bitcode; SPIR-V |
   The sniff is the diagnostic layer: it lets the refusal say what the payload is. The enforcing layer is the
   reader: a blob that is not a valid instance of its declared data format is refused by that reader.
5. **Kernels.** `spark.precompile` and every verb that names a kernel take a `KernelId` that must resolve in
   the build's kernel registry. There is no argument for kernel source. A test asserts that no input schema
   mentions a dialect, CUDA or Metal source field.
6. **The MCP tool set.** A test over the in-memory transport lists tools and asserts the set equals the image
   of the registry under the name map (`.` and `-` to `_`) plus the three base tools, and that the
   compatibility tool `verb_invoke {verb, arguments}`, when enabled, validates `arguments` against the named
   verb's schema and reaches no other code path.
7. **The refusal.** `FROB-REF-828`, "a payload that carries code, or a weight format outside the allowlist".
   Exit 3, `retry: never`. Fields: `pointer` (the argument), `observed` (the kind from the sniff table or
   `not-a-<format>`), `required` (the data format). Ranked repairs (DESIGN): (1) submit the data form: an
   expression in the requirement language, a typed edit, weights in the plain tensor layout; (2) for a term the
   language lacks, compose it from the language's operators, or request a new operator as a change to the
   language (custom code terms are not admitted); (3) for a kernel, change the model or the derivation input;
   kernels are generated here. Every refusal of this kind is logged with the session and the argument digest.
8. **Classes.** D0. No evidence is produced.

## Acceptance criteria

- [ ] INV-SAFE-01 as a test: the leaf lint passes on the registry; a planted input property `script: string`,
      a planted free-form object, and a planted leaf of type `string` with no annotation each fail it.
- [ ] An expression of 4,097 nodes, of depth 65, or of 65,537 bytes is refused before evaluation with the bound
      quoted; one at each bound is accepted.
- [ ] A file with a registered extension whose bytes begin with each signature of the table is refused with
      `FROB-REF-828`, exit 3, naming the kind; nothing from the file is read past the first 16 bytes.
- [ ] The patch schema has no path leaf and no free-form string; a patch carrying `"path": "../x"` fails
      validation with `FROB-REF-802`.
- [ ] No input schema carries kernel source; `spark.precompile` with an unknown `KernelId` is refused.
- [ ] The served MCP tool set equals the registry's image plus the base tools.

## Test plan

### Unit tests
`cargo test -p frob-verbs --test input_leaves --test code_payload` (the real registry; planted rows are
`synthetic` copies):
- `registry_leaves_are_closed`; `planted_script_field_fails`; `planted_free_object_fails`;
  `planted_bare_string_fails`.
- `expr_bounds`: table of (nodes, depth, bytes) at and one over each bound.
- `expr_parser_is_iterative`: depth 10⁵ input is refused by the bound with no stack overflow.
- `sniff_table`: one 16-byte fixture per signature row → the named kind; a valid design file → no hit.
- `blob_must_be_registered_format`: an argument declaring format `frob.unknown/1` is refused.
- `patch_schema_has_no_path_leaf`; `patch_with_path_string_fails_schema`.
- `no_kernel_source_inputs`; `precompile_unknown_kernel_refused`.
- `mcp_tools_equal_registry_image` (in-memory transport); `verb_invoke_validates_against_schema`.
- Property test for INV-SAFE-01: for 10⁴ random JSON values offered as arguments to each verb, every accepted
  value validates against the closed leaf types (no accepted value contains a leaf outside them).

### End-to-end script and logging
`scripts/e2e/safe_importers.sh` (created at M1 by the import-limits bead N37-05) has a step `code_payloads`,
whose content this bead supplies: `frob --json design import` on eight crafted files (one per signature row, each with a `.urdf` or `.xml` name) and `frob --json task new` with an
over-bound expression. It asserts exit 3 and the code for each, and logs per STD-E2E the command line, exit
code, refusal code and `observed` kind, with a `summary` of assertions. File contents are synthetic and are
never logged.

### Known answers and negative controls
Known answers: the bounds 65,536 bytes, 4,096 nodes, depth 64; the eight signature rows. Negative controls
(each must be caught): the three planted schema rows; a `mutants` build whose dispatcher skips the sniff must
fail `sniff_table`; a build whose expression parser recurses must fail `expr_parser_is_iterative`. Metamorphic:
renaming a payload's extension does not change the refusal. Determinism lanes: identical results in debug and
release and on Linux and macOS (D0).

## Considerations

- The sniff table cannot be complete and is not relied on; a polyglot file that is a valid design and also a
  valid script is harmless here because nothing executes inputs.
- Controller configurations are data interpreted by fixed code (gain tables, layer records of a control
  program); if a later controller format needs conditionals, they are expressions of the requirement language,
  not a new interpreter.
- The expression bounds are DESIGN defaults; they move by a registry change with a recorded reason, never by a
  verb flag.
- The open question on sandboxed custom reward terms (owner: the project owner; blocks M4) keeps its
  fail-closed default until N37-09 is decided.
- Interaction: a Python interpreter is permitted only in the Gymnasium-compatible adapter annex
  (`bindings/frob-gymnasium`); no verb embeds one, and the leaf lint applies to that annex's verbs like any
  other.
