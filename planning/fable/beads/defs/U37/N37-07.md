## Background

An agent may submit **policy weights**, and weights travel between the two machines. Weights are numbers, but
the files that usually carry them are not: the common checkpoint formats of machine-learning tools are object
serializations or archives that can execute code when loaded. The rule of the safety chapter is: **weights are
hostile data.** A policy file is accepted only in a plain layout (named tensors, shapes, raw values), for an
architecture from an allowlisted family, with every value finite and the size under a cap. Formats that can
carry executable content are refused with `FROB-REF-828` ("a payload that carries code, or a weight format
outside the allowlist").

FACT (the learning chapter's design): every checkpoint this system writes is a safetensors container whose
metadata holds the policy manifest and mapping table, schema `frob.policy/1` (network kind and widths, action
law, discount, channels with roles, units, signs and bounds, observation schema digests, what it was trained
on, symmetry group). A policy reaches a design only through that mapping table. The plain layout of this bead
is that container, read by our own bounded reader.

Why our own reader first: a hostile file must be rejected by code we wrote for hostile input, in safe Rust
with limits, before any general-purpose parser of a sibling library touches it. Rejected alternatives: trusting
the container library's validation (it validates for well-meaning files and is outside our fuzz gate);
accepting the popular archive checkpoints "with unsafe loading off" (the format still carries a program; one
loader option is the only barrier); a custom weight format (one more format to version; the plain container
already is named tensors, shapes and raw values).

Which layouts and families are admitted at M2 is an open question owned by the learning lead (decision bead
N37-08). Its fail-closed default, used here until decided: the single layout and the single family of the
reference policy.

## Scope

In: the bounded container reader `frob_io::weights::read_plain`; the caps; the finiteness scan; the family
check `frob_learn::ckpt::admit` against `registries/policy-families.toml`; the rule that every verb argument
that takes a policy file routes through admission; refusal mapping; the fuzz target function for the reader.
Out: writing checkpoints and the mapping-table matcher (the learning chapter); the campaign that fuzzes the
reader to 10⁷ executions (BD-307); what a D4-trained policy may be cited for (N37-28); marks on weights
trained in private scenes (N37-20, BD-305).

## Technical approach

1. **Container layout (the plain layout).** Bytes 0 to 7: an unsigned 64-bit little-endian header length N.
   Bytes 8 to 8 + N − 1: a JSON object mapping each tensor name to `{ "dtype", "shape", "data_offsets":
   [begin, end] }`, plus an optional `__metadata__` object of string to string. The rest: one raw byte buffer;
   offsets are relative to its start.
2. **`read_plain(bytes, caps) -> Result<PlainTensors, Refusal>`** (in `frob-io`, layer 2, no knowledge of
   networks). Checks, in order, stopping at the first failure:
   1. Sniff the first 16 bytes with the code-payload table (pickle stream `80 02` to `80 05`; zip `50 4B 03
      04`; HDF5 `89 48 44 46 0D 0A 1A 0A`; NumPy array file `93 4E 55 4D 50 59`; executables and bitcode) →
      `FROB-REF-828`, `observed` = the kind.
   2. `len ≤ caps.max_bytes`; `N ≤ caps.max_header_bytes`; `8 + N ≤ len` → otherwise `FROB-REF-832` (an import
      over its size limit) for the two caps and `FROB-REF-828` (`not-plain-layout`) for an inconsistent length.
   3. Parse the header with the bounded JSON admission reader: depth at most 4; duplicate member names are an
      error; at most `caps.max_tensors` tensors.
   4. Per tensor: name matches `^[a-z0-9_.]{1,128}$`; `dtype` is in `caps.dtypes` (DESIGN at M2: `F32` only);
      rank at most 4, every dimension at least 1; `end − begin = (∏ dims) · sizeof(dtype)` in checked
      128-bit arithmetic; `begin ≤ end ≤ buffer length`.
   5. No hidden bytes: sorted by `begin`, the tensors tile the buffer exactly: the first begins at 0, each
      begins where the previous ends, the last ends at the buffer length. A gap, an overlap or trailing bytes
      is `FROB-REF-828` (`observed: unaccounted-bytes`).
   6. Finiteness: every element of every floating tensor is finite. The scan reads the bit patterns (an `F32`
      is non-finite when its exponent field is all ones); the first offender is reported as tensor name and
      flat index, with the count. Non-finite → `FROB-REF-828` (`observed: non-finite-value`).
   7. `__metadata__`: only the registered keys (`frob.policy/1` for the manifest, `frob.digests/1` for tensor
      digests); any other key is `FROB-REF-828` (`observed: unknown-metadata-key`). Metadata strings from an
      outside file are untrusted text until the manifest parser has accepted them as data.
   DESIGN caps, profile `default` in `registries/import-profiles.toml` under importer `weights`:
   `max_bytes` 67,108,864 (64 MiB, about 16.7 million single-precision parameters; the reference policy with
   widths 256, 256, 128 is under 1 MiB); `max_header_bytes` 1,048,576; `max_tensors` 1,024.
3. **`admit(PlainTensors, &FamilyAllowlist) -> Result<AdmittedPolicy, Refusal>`** (in `frob-learn`). Parse
   the manifest against schema `frob.policy/1`; look the pair (`network.kind`, layout version) up in
   `registries/policy-families.toml`; build the network specification the manifest declares and compute the
   parameter layout it expects (names and shapes); require set equality with the file's tensors: no missing
   tensor, no extra tensor, equal shapes. Family rows carry bounds (DESIGN default row: `kind = "mlp"`,
   `recurrent = false`, at most 8 layers, width at most 4,096, `dtype = F32`). A family not listed, a width
   over its bound or a layout mismatch is `FROB-REF-828` (`observed: family-not-allowlisted` or
   `layout-mismatch`, with the first differing tensor).
4. **One door.** `AdmittedPolicy` has no public constructor other than `admit` and the trainer's own
   checkpoint writer. A `PolicyId` for weights that came from a file exists only as a result of `admit`. A
   registry lint asserts that every verb input of schema type `frob.policy.file/1` (the initial weights of
   `train.start`, the policy of `eval.run` and `sim.run`, teachers of distillation, the source of
   `policy.apply` when they arrive) is declared `admission = "weights"`, and the dispatcher calls admission
   before the handler. Checkpoints written by this system are re-admitted on read by the same path (their
   stored digests make that a hash comparison plus the layout check).
5. **What admission does not grant.** Admitted weights are data. The manifest's statements about training
   (task, scenes, tier, determinism class) are recorded as `declared` when the file came from outside and are
   never evidence; every claim about the policy comes from evaluating it. The admission record stores the file
   digest, the caps profile digest, the family row and `origin: external | trained-here`.
6. **Refusal details.** `FROB-REF-828`: exit 3, `retry: never` for code-bearing formats and `after-change`
   otherwise; ranked repairs (DESIGN): (1) export the tensors by name in single precision to the plain
   container with the policy manifest; (2) use an allowlisted family, or ask the learning lead to add the
   family to the registry; (3) for non-finite values, the training run diverged: restart from the last finite
   checkpoint. `FROB-REF-832` for the size caps: repairs as for any import limit (reduce, or the owner selects
   a larger profile).
7. **Fuzz target.** `weights_reader(&[u8])` runs `read_plain` under the `fuzz` profile (`max_bytes` 4,096,
   `max_tensors` 8) with the importer oracle: a refusal or a `PlainTensors` whose tensors tile the buffer; no
   panic; allocation bounded.
8. **Classes.** Admission is D0 (a function of the bytes, the caps and the allowlist).

## Acceptance criteria

- [ ] A checkpoint written by `train.export` is admitted; its tensors equal the trainer's bit for bit.
- [ ] Each of these is refused with `FROB-REF-828` and the stated `observed`: a pickle stream; a zip-based
      checkpoint archive; an HDF5 file; a NumPy array file; a plain container with 16 trailing bytes; with a
      16-byte gap between tensors; with overlapping offsets; with one NaN; with one infinity; with an extra
      tensor `backdoor.weight`; with a missing bias; with `network.kind = "transformer"` (not on the default
      allowlist); with an unknown metadata key.
- [ ] A container of 67,108,865 bytes, a header of 1,048,577 bytes and a header listing 1,025 tensors are each
      refused with `FROB-REF-832` and `observed = limit + 1`.
- [ ] A header declaring shape [4,294,967,296, 4,294,967,296] with 16 bytes of data is refused by the size
      equation with no allocation beyond the header.
- [ ] The registry lint finds every policy-file argument routed through admission; a planted verb argument of
      that type without `admission = "weights"` fails it.
- [ ] `AdmittedPolicy` cannot be constructed outside the two permitted sites (compile-fail test).

## Test plan

### Unit tests
`cargo test -p frob-io --test weights -p frob-learn --test admit_policy` (synthetic files built by a
deterministic generator):
- `roundtrip_reference_policy`: widths 256, 256, 128; admitted; digests equal.
- `sniff_refuses_<kind>` for pickle, zip, HDF5, NumPy.
- `trailing_bytes_refused`, `gap_refused`, `overlap_refused`, `unsorted_offsets_refused`.
- `nan_refused_names_tensor_and_index`: NaN planted at `policy.0.weight[17]` → reported exactly; count 1.
- `infinity_refused`; `negative_zero_and_subnormals_accepted`.
- `shape_overflow_refused_without_alloc` (counting allocator).
- `caps_at_and_over`: the three caps at L and L + 1.
- `duplicate_header_key_refused`; `bad_tensor_name_refused` (`../x`, upper case, 129 bytes).
- `extra_tensor_refused`, `missing_tensor_refused`, `shape_mismatch_refused`, `family_not_listed_refused`.
- `external_manifest_training_fields_are_declared_not_evidence`.
- `fuzz_smoke_weights_reader`: 10⁵ executions, seed 1.

### End-to-end script and logging
This bead adds a step `weights` to `scripts/e2e/safe_importers.sh`: `frob --json eval run --policy <file>`
on an admitted file (reaches estimation) and on each refused specimen (exit 3, the code, `observed`), plus
10⁵ smoke executions of the `weights_reader` target (the 10⁷ campaign for this reader is BD-307's). Logged
per STD-E2E: command line, exit code, refusal code, `observed`, `required`, the caps profile digest and the
family row; a `summary` of assertions. Weight values are never logged; files are named by digest.

### Known answers and negative controls
Known answers: 64 MiB at single precision is 16,777,216 parameters; an `F32` is non-finite exactly when bits
23 to 30 are all ones. Negative controls: a `mutants` build that skips the tiling check must fail
`trailing_bytes_refused`; one that skips the finiteness scan must fail `nan_refused…`; one that matches
tensors as a subset must fail `extra_tensor_refused`. Determinism lanes: identical verdicts and fields on
Linux and macOS, debug and release.

## Considerations

- The allowlist grows with the learning chapter (recurrent networks, family policies with one token per link
  at M4); each addition is a registry row with bounds, decided by the learning lead, and its reader stays the
  same plain container.
- Weights that passed admission can still encode an undesirable policy; admission is about the file being
  data, and behaviour is established only by evaluation under a determinism class that licenses it.
- An outside weight file's licence class is `unknown` unless the submitter declares one, and `unknown` is the
  most restrictive class at export (N37-18).
- The finiteness scan is linear in the file size: 64 MiB scans in well under a second and runs once per
  admission.
- The verb registry has no dedicated verb for importing weights; admission is attached to the
  arguments that take a policy file. If a `policy.import` verb is added later it is one more caller of the
  same door.
