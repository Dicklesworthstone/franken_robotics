## Background

Policy weights are admitted to the system only as hostile data: a plain layout (named tensors, shapes, raw
values), an architecture from an allowlisted family, every value finite, the size under a cap; a format that
can carry executable content is refused (`FROB-REF-828`). The mechanism is N37-07. What it cannot decide for
itself is the content of the allowlist.

**OPEN-SAFE-1** (open question of the safety chapter). *Which weight layout and which policy architectures are
on the allowlist at M2.* Owner: the learning (Cortex) lead. It blocks GATE-SAFE-07 (importer fuzzing and
limits), because the weight-file reader is an importer whose fuzz target and limit rows must exist for the
gate's complete record. **Fail-closed default: the single layout and the single family of the reference
policy.**

Why this is a decision and not an implementation detail: every admitted family is attack surface (a reader
path to fuzz, bounds to choose, a parameter layout to match exactly), and every refused family is a policy an
agent cannot bring from outside. The default is deliberately the narrowest set that lets the M2 training gate
run.

## Scope

In: the decision record; the registry rows it fixes; what each option costs; the default that holds until it
is made; what must be re-run when it changes. Out: the admission mechanism (N37-07); fuzzing (BD-307);
anything about how policies are trained.

## Technical approach

1. **What is being decided.** Three things, each a row set in a registry file.
   - *Layout*: the container and its version. Candidates: (a) the plain container already used for
     checkpoints (an 8-byte length, a JSON header of name, dtype, shape and offsets, a raw buffer), with the
     policy manifest `frob.policy/1` in its metadata; (b) the same plus a second, even simpler layout for
     interchange with tools that cannot write it (a directory of raw little-endian arrays with a JSON index).
   - *Element types*: single precision only, or single and double.
   - *Families*: which `network.kind` values with which bounds. Candidates at M2: the small observation MLP
     with explicit normalization (the reference policy; widths 256, 256, 128); the recurrent variant (a gated
     recurrent unit); the asymmetric actor-critic pair (the critic reads channels the actor may not).
     Frontier families (a residual head over a baseline controller, an equivariant MLP, a morphology
     transformer with one token per link) and the Moonshot tree policy are not candidates at M2.
2. **The default in force** (`registries/policy-families.toml`, written by N37-07):
   ```toml
   [[layout]]
   id = "plain-container/1"
   dtypes = ["F32"]

   [[family]]
   kind = "mlp"
   recurrent = false
   max_layers = 8
   max_width = 4096
   layout = "plain-container/1"
   admit = "external"            # admits a file of either origin (N37-07's `admit` field)
   since = "M2"
   decided_by = "default (OPEN-SAFE-1 undecided)"

   [[family]]
   kind = "gru"
   recurrent = true
   max_layers = 8
   max_width = 4096
   layout = "plain-container/1"
   admit = "trained-here"        # only checkpoints this system's trainer wrote (digest matches a store record)
   since = "M2"
   decided_by = "default (OPEN-SAFE-1 undecided): own checkpoints only"
   ```
   The second row is part of the default and does not widen it (DESIGN, with the reason): the question is
   which layouts and architectures an agent may bring in, and under the default the only family accepted from
   outside is the reference MLP (the asymmetric actor-critic pair is two MLP towers and fits that row). The
   learning chapter trains a Solid gated recurrent policy at M2 (sequence PPO, recurrent hidden state in the
   checkpoint); without the `trained-here` row its own checkpoints would be refused on re-read by N37-07, and
   recurrent policies would be confined to memory, unable to resume a run or be exported. The row's layout
   function is the trainer's `ParamLayout` (N23a-12) and its bounds are the trainer's. What the owner of the
   question decides is whether `gru` (and later families) become `admit = "external"`.
3. **What each addition obliges.** Raising a row from `trained-here` to `external`, or adding a family: its
   parameter-layout function (names and shapes from the manifest), bounds, at least three admitted specimens
   and one refused specimen per bound in the weight test corpus, and a rerun of the weight reader's fuzz
   campaign. For a new layout: a new bounded reader with
   its own limit rows and fuzz target, and a new line in the gate record. For a new element type: the
   finiteness scan for that type and a statement of whether device kernels accept it.
4. **How the decision is recorded.** An ADR in `docs/adr/` named for OPEN-SAFE-1 with: the rows chosen, the
   reason, the rejected candidates, the date and the decider; the registry rows with `decided_by` naming the
   ADR; an entry in the open-question register marking the question closed. The honest-status table prints
   the allowlist, and so does `frob capabilities --json`: this bead adds to `frob.capabilities.out/1` the
   optional member `policy_families`, one entry per row of `registries/policy-families.toml` (`kind`,
   `layout`, `dtypes`, the bounds, `admit`, `since`, `decided_by`), read from the embedded registry, so that
   an agent refused with `family-not-allowlisted` can see what is admitted. A later change (for example adding
   family policies at M4) is a new ADR, never an edit of the old one.
5. **Deadline.** Before the M2 measurement of GATE-SAFE-07 (N37-06, which depends on this bead and fuzzes
   the allowlist in force), and in any case before the M2 exit review. If undecided at that point, this bead
   closes by recording the default as the decision of record for M2 ("default adopted", with the date and the
   open-question register entry), the gate is then measured on the default surface, and the question stays
   open for M4. The mechanism (N37-07) never waits for the decision: it ships the default rows.

## Acceptance criteria

- [ ] An ADR for OPEN-SAFE-1 exists, signed by the learning lead, or, at the deadline of step 5, the
      decision record states "default adopted" with the default rows above (before N37-06 records the gate).
- [ ] `registries/policy-families.toml` contains exactly the rows the ADR lists; each row has bounds and
      `decided_by`.
- [ ] For every row beyond the default, the obligations of step 3 are met before the row is merged (the
      registry test fails on a family row with no specimens or no layout function).
- [ ] `frob capabilities --json` prints the allowlist in force in its member `policy_families`.
- [ ] The open-question register shows OPEN-SAFE-1 with its state and the ADR link.

## Test plan

### Unit tests
`cargo test -p frob-learn --test policy_families`: `default_rows_present` (the two rows above, with their
`admit` values); `row_without_bounds_fails`; `row_without_specimens_fails` (applies to every `external` row
beyond the reference MLP); `row_names_existing_layout`; `trained_here_row_needs_layout_function` (a
`trained-here` row whose kind has no `ParamLayout` in the trainer fails). `cargo test -p frob-verbs --test
capabilities_policy_families`: `capabilities_prints_allowlist` (the member `policy_families` holds both default
rows, with `admit`; a scratch registry with a third row prints three entries).

### End-to-end script and logging
None of its own (a decision). The `weights` step of `scripts/e2e/safe_importers.sh` (N37-06, which depends on
this bead) reads the allowlist from `frob --json capabilities` (`/result/policy_families`), logs it (per
STD-E2E: the `metric` line `allowlisted_families` with the list and the ADR identifier or `default`), and
attempts one specimen per listed family and one unlisted family.

### Known answers and negative controls
Known answers: under the default, a recurrent-network file from outside the system is refused with
`FROB-REF-828` (`family-not-allowlisted`); a recurrent checkpoint written by the trainer here and re-read is
admitted; the reference MLP is admitted from either origin. Negative controls: a registry copy that lists a
family with no bounds must fail the registry test; a registry copy whose `gru` row says `admit = "external"`
without the step-3 specimens must fail `row_without_specimens_fails`.

## Considerations

- Choosing wider now saves agents a conversion step later and costs a larger gate; choosing the default costs
  agents only the ability to bring recurrent weights from outside at M2, because the system's own recurrent
  checkpoints reload under the `trained-here` row.
- The recurrent and asymmetric variants are Solid in the learning chapter and are the likeliest first
  additions; their hidden-state shapes belong in the manifest, not in extra tensors.
- Double precision is rarely needed on devices that run single-precision kernels; admitting it doubles the
  cap's meaning in parameters and is best decided together with the CPU trainer's needs.
- Fail-closed means an agent holding a perfectly good policy in another layout is refused with a repair that
  says how to convert it. That friction is intended.
