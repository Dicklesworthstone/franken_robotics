## Background

Many verbs take a path: a file to import, a place to export to. Each such argument is a way for a confused or
injected agent to read a file it should not, or to write over one. The rule: **every path-taking argument
resolves beneath one of the session's roots (project, private, export) through a retained directory handle**;
a path outside the roots is refused with `FROB-REF-734`.

Decision **ADR-SAFE-04**: paths are resolved beneath retained directory handles, never by checking a string and
reopening. Reason: a check on a string is defeated by a link swapped between the check and the open. The
smallest case: `exports/a` is checked as inside the export root, then replaced by a link to another directory
before it is opened; a string check passes and the write lands outside. Rejected alternatives: canonicalize
then compare a prefix (exactly the race above, and it leaks host paths into error text); a deny-list of `..`
alone (symbolic links need no `..`); running each verb in an operating-system sandbox (heavier, platform
specific, and unnecessary when no code path opens by string).

FACT: the suite's MCP library takes the same approach for its filesystem resources: `fastmcp_rust/Cargo.toml`
pins `cap-std = "=4.0.3"`, a capability-based filesystem library whose directory type opens paths relative to
a held descriptor and refuses escapes.

Gate: **GATE-SAFE-10** (Known answer, TARGET; the gate register dates it to M1): a corpus of traversal,
absolute-path and swapped-link attempts is refused on every path-taking argument of every verb. This bead
builds the mechanism and passes the gate for the verbs that exist at M1; the capability bead BD-258 re-records
it at M3 over the full surface with per-session roots.

## Scope

In: the three roots and their handles; the argument type and the registry lint that forces every path
argument through it; lexical refusals; handle-relative resolution for reads and writes; atomic writes; the
ban on opening by string in verb code; the refusal with its fields and repairs; the attempt corpus and the
generated sweep; the M1 gate record. Out: per-session and per-namespace sub-roots and the scopes that select
a root (BD-258); the private root's contents (BD-305); the end-to-end script (N37-12); the store's own object
files, which live under the store's handles and are addressed by digest, never by a caller's path.

## Technical approach

Module `frob_verbs::jail`.

1. **Roots.** At process start the owner-held safety configuration yields three directories: `project`,
   `export` and (optional) `private`. Each is opened once as a directory handle and retained for the life of
   the process (`Roots { project: Dir, export: Dir, private: Option<Dir> }`). Nothing later reopens a root by
   name. The root directory itself must not be a symbolic link (checked on the opened handle), and the export
   and private roots must have mode 0700.
2. **The argument type.** A path argument's schema is
   `{ "type": "string", "maxLength": 4096, "x-frob-path": { "root": "project" | "export" | "private",
   "access": "read" | "create" | "replace", "kind": "file" | "dir" } }` (schema name `frob.path/1`). The
   dispatcher resolves the argument before the handler runs and passes the handler an open `JailedFile` or
   `JailedDir`, never a string. Registry lint: the closed list of input leaf types (the data-not-code lint)
   leaves `frob.path/1` as the only leaf that can denote a file; in addition, any string leaf named like
   `path`, `file`, `dir`, `out`, `output`, `dest`, `from` or `to` that is not `frob.path/1`, an identifier or
   an identity fails the lint.
3. **Lexical refusals (before any system call).** Refused with `FROB-REF-734` and an `observed` class:
   empty (`empty`); a NUL byte or control character (`control-character`); absolute forms: a leading `/`, a
   leading `~`, a drive letter with colon, a leading double backslash, a URL scheme such as `file:`
   (`absolute`); any component equal to `..` (`parent-component`), wherever it appears and whatever it would
   resolve to; any backslash (`backslash`: it is not a separator here, and refusing it removes
   cross-platform ambiguity); a component over 255 bytes or a path over 4,096 bytes (`too-long`). A `.`
   component is dropped. Nothing is percent-decoded or Unicode-normalized: `%2e%2e` and full-width dots are
   ordinary file names inside the root.
4. **Resolution.** Component by component from the root handle, each step an open relative to the handle of
   the previous step, never following a link out of the root:
   - `read`: symbolic links are followed only while resolution stays beneath the root handle (the library's
     beneath-root resolution); a link whose target leaves the root is refused (`symlink-escape`).
   - `create` and `replace`: no component may be a symbolic link at all (each intermediate directory is
     opened with no-follow and directory flags; `symlink-in-write-path`). Missing intermediate directories
     are created (mode 0700) through the handles.
   - All metadata comes from the opened handle (`fstat`), never from a second lookup by name. The final object
     must be a regular file (or a directory for `kind: dir`); a FIFO, socket or device is refused
     (`not-regular`).
5. **Writes are atomic and exclusive.** A file is written as `.<name>.<12 hex>.tmp` created with exclusive
   create (mode 0600) inside the destination directory handle, flushed, and renamed onto the final name with a
   rename relative to the same handle. `create` refuses an existing name; `replace` renames over an existing
   regular file only if its link count is 1 (so a hard link to an outside file is never written through:
   `hard-linked-target`). A directory export (a build packet, a run bundle) is written into a temporary
   directory beneath the handle and renamed once.
6. **No opening by string anywhere else.** The workspace lint table lists, as disallowed in `frob-verbs`,
   `frob-cli`, `frob-mcp` and every crate a handler calls for file access: `std::fs::File::open`,
   `File::create`, `OpenOptions::open`, `std::fs::read*`, `write`, `rename`, `remove_*`, `create_dir*`,
   `canonicalize`, `metadata`, `symlink_metadata`. The allowed sites are the `jail` module and the store
   module (which works beneath its own retained handles). Readers of formats take a `Read` or a handle.
7. **Import roots.** For an import, the directory of the imported file (already a jailed handle) becomes the
   import root: relative references inside the document (a mesh `filename`, an include) are resolved beneath
   that handle by the same rules, so `filename="../../etc/passwd"` is `parent-component` and reads nothing.
8. **The refusal.** `FROB-REF-734`, "a path outside the session's roots". Exit 5; `retry: never` for a
   lexical refusal and `after-change` otherwise. Fields: `pointer` (the argument), `observed` (the class
   above), `required` (`a relative path beneath the <root> root`). The message never contains a host path:
   roots are named by kind, since machine paths must not enter envelopes or artifacts. Ranked repairs
   (DESIGN): (1) pass a relative path beneath the named root; (2) refer to the object by identifier or digest
   and use `artifact.read` or `artifact.export`; (3) ask the owner to configure the root (when
   `observed = root-unset`, for example the private root).
9. **MCP.** Resource URIs name registry rows or content-addressed objects and are never filesystem paths; the
   tools generated from path-taking verbs carry the same `frob.path/1` schema.
10. **The attempt corpus** (`crates/frob-conformance/corpora/path_jail/`; each entry has an identifier, a
    class and a setup recipe):
    - traversal (40 entries): `../x`, `a/../../x`, `a/b/../../../x`, `./../x`, `..`, `a/..`, trailing `/..`,
      mixed with `.` components, 64 levels of `../`, a NUL after a valid prefix, overlong components;
    - absolute (25): `/etc/passwd`, `//etc/passwd`, `~/x`, `~root/x`, `C:\x`, `C:/x`, `\\host\share\x`,
      `file:///etc/passwd`, an absolute path that points inside the root;
    - literal look-alikes that must **not** be treated as traversal and must stay inside the root (10):
      `%2e%2e/x`, `..%2fx`, full-width dots and solidus, `...`, `.. ` with a trailing space;
    - links present before the call (20): a link to an outside file; to an outside directory; a chain inside
      to inside to outside; a link in an intermediate component of a write path; a link as the final component
      of a write; a relative link `../../outside`;
    - links swapped during the call (5 recipes): a helper process alternates `exports/a` between a real
      directory and a link to a sentinel directory outside the root as fast as it can while the verb writes
      `exports/a/out.json` 1,000 times; the same for an intermediate component two levels down; the same for
      the final component;
    - special targets (10): a FIFO, a socket, a device node where creatable, a directory where a file is
      required, a hard link (link count 2) to an outside file as the target of `replace`.
11. **The generated sweep.** A test harness reads the registry, enumerates every `frob.path/1` argument of
    every verb present, and for each argument runs every corpus entry with otherwise valid arguments.
    Oracle: entries of the refused classes return `FROB-REF-734` with exit 5 and the expected `observed`; the
    look-alike entries succeed and their files are found inside the root; after the whole sweep the sentinel
    directory outside the roots is byte-identical to its initial state (a digest of its tree), and for the
    swap recipes every one of the 1,000 calls either succeeded inside the root or was refused.
12. **Classes.** D0 for lexical refusals; the swap recipes are a concurrency test whose oracle (nothing lands
    outside) holds on every schedule.

## Acceptance criteria

- [ ] GATE-SAFE-10 at M1 (TARGET): every corpus entry of the refused classes is refused on every path-taking
      argument of every M1 verb; the sentinel tree is unchanged. The generated sweep of step 11 is delivered
      here and exercised on a conformance verb with one argument of each access kind; the record over the
      real M1 verbs, with the counts of arguments, entries and refusals, is taken by the script bead N37-12.
- [ ] The smallest case: with `exports/a` swapped for a link to the sentinel directory during 1,000 writes,
      zero files appear in the sentinel directory.
- [ ] A handler cannot obtain a path string: the handler signature takes `JailedFile` or `JailedDir`
      (compile-time), and the disallowed-methods lint fails on a planted `std::fs::File::open` in a handler.
- [ ] `FROB-REF-734` messages contain no host path (a scan of all refusal envelopes of the sweep finds no
      substring of the roots' absolute paths).
- [ ] A registry row with a string argument named `out` that is not `frob.path/1` fails the lint.
- [ ] `replace` over a file with link count 2 is refused; `create` over an existing file is refused; a
      written file appears atomically (no partial file is ever visible under its final name).

## Test plan

### Unit tests
`cargo test -p frob-verbs --test jail` (real temporary directories; no mocks):
- `lexical_table`: one row per lexical class with its `observed` value.
- `lookalikes_are_plain_names`: `%2e%2e/x` creates the directory `%2e%2e` inside the root.
- `read_follows_only_beneath_root`; `read_link_to_outside_refused`.
- `write_refuses_any_symlink_component`; `write_refuses_final_symlink`.
- `swap_race_1000`: the smallest case; sentinel digest unchanged.
- `replace_hard_link_refused`; `create_existing_refused`; `fifo_refused`.
- `atomic_write_never_partial`: a reader polling the final name sees either no file or the complete file.
- `import_root_confines_references`.
- `root_must_not_be_symlink`.
- `refusal_has_no_host_path`.
- `planted_fs_open_fails_lint`; `planted_unjailed_out_argument_fails_lint`.
- Property test: for 10⁴ random relative paths over the alphabet {`a`, `b`, `.`, `..`, `/`}, the jail either
  refuses or opens a file whose handle-derived location is beneath the root handle.

### End-to-end script and logging
`scripts/e2e/safe_path_jail.sh` (N37-12) drives the sweep through the real `frob` binary and logs each attempt.

### Known answers and negative controls
KA-835 (a corpus of traversal, absolute-path and swapped-link attempts is refused on every path-taking
argument of every verb; exact; tier G4). Negative controls, registered against GATE-SAFE-10: a `mutants`
build that checks the canonical string and then opens by name (the swap recipe must put a file in the
sentinel directory and the test must report it); a build that percent-decodes components; a build in which
one verb takes its output path as a plain string. Determinism lanes: lexical verdicts identical on Linux and
macOS; the swap recipes run on both.

## Considerations

- **Dependency rule.** The core's rule allows the standard library and the suite's own foundations as runtime
  dependencies. Handle-relative opening is not expressible with the standard library alone, so this bead needs
  `cap-std` (exact pin equal to the MCP library's, so the lockfile gains no second copy) admitted for
  `frob-verbs` by an ADR and an admission record. Until that is granted the fail-closed posture is: read
  arguments resolve only when no component is a symbolic link (checked on handles opened with no-follow at
  the final component), and write arguments other than a fresh run-private directory created by the process
  are refused with `observed = root-unset`. This is recorded as a finding for the lead.
- Hard links and bind mounts made by the same user are outside the string-versus-handle threat; the
  link-count rule on `replace` closes the one write path they would open.
- Platform differences: beneath-root resolution uses the kernel's own facility where it exists and a manual
  component walk elsewhere; both are exercised by the swap recipes on Linux and macOS.
- A local user with root is outside the threat model.
- Performance: one open per path component; path arguments are rare and never in a hot loop.
