## Background

The capability under test, from the user's side: whatever path an agent types into any verb, the system reads
and writes only beneath its configured roots (project, private, export). Paths are resolved beneath retained
directory handles, never by checking a string and reopening, because a string check is defeated by a link
swapped between the check and the open; an attempt outside the roots is refused with `FROB-REF-734` (exit 5).

GATE-SAFE-10 (Known answer, TARGET; earliest M1 in the gate register): a corpus of traversal, absolute-path
and swapped-link attempts is refused on every path-taking argument of every verb. This script is the
measurement on the running binary. It is generated from the verb registry, so it grows with the surface: at
M1 it covers the M1 verbs and gives the M1 exit its record; at M3 (with BD-258) it covers every verb, per
session root.

## Scope

In: the script; the sentinel tree; the corpus-driven sweep through `frob`; the swap helper; assertions;
logging; the gate record. Out: the mechanism and the corpus definition (N37-11); scopes and per-session roots
(BD-258).

## Technical approach

`scripts/e2e/safe_path_jail.sh [--iterations 1000] [--mcp]` (plain shell; sources the shared helper of
STD-E2E; idempotent; everything lives under `target/e2e/safe_path_jail/<run>/`).

Layout the script creates: `<run>/project/` (project root, with a small valid design and task), `<run>/exports/`
(export root), `<run>/private/` (private root), and `<run>/outside/` (the **sentinel**: a directory outside all
roots holding `secret.txt` with known bytes and a subdirectory `drop/`). A safety configuration in a temporary
state root names the three roots.

Steps:

1. `enumerate`: `frob schema --path-args --json` lists every (verb, argument, root, access, kind). Assert the
   list is non-empty and equals the registry's (`frob-conformance jail list-args`).
2. `sentinel_before`: digest of the sentinel tree (names, sizes, modes, contents) → `S0`.
3. `lexical`: for each path argument and each traversal and absolute corpus entry, run the verb with otherwise
   valid arguments (`frob --json <verb> … <arg>=<entry>` with an idempotency key where required). Assert exit
   5, `refusal.code = FROB-REF-734`, the expected `refusal.observed` class, and that the refusal text contains
   neither the absolute path of any root nor the string `outside`.
4. `lookalikes`: the ten literal look-alike entries must succeed (exit 0 or 2) on a `create` argument and the
   created file must be found beneath the export root under the literal name.
5. `links_static`: for each pre-existing link recipe the helper builds the link inside the root, then runs
   every argument of matching access. Assert `FROB-REF-734` with `symlink-escape`, `symlink-in-write-path` or
   `not-regular` as the recipe states; a `read` through a link that stays inside the root succeeds.
6. `links_swapped`: start `frob-conformance jail swapper --path <run>/exports/a --target <run>/outside/drop`
   (alternates the name between a real directory and a link as fast as it can); run
   `frob --json artifact export <id> --out a/out-<i>.json` for i in 1..iterations; stop the swapper. Assert:
   each call exited 0 or 5 (with `FROB-REF-734`); `<run>/outside/drop/` is empty. Repeat for an intermediate
   component two levels down and for the final component, and for `design import a/in.urdf` as a read (the
   swapper alternates the file with a link to `secret.txt`: no envelope may contain the secret's bytes or its
   digest).
7. `special_targets`: FIFO, directory-for-file, and a hard link (link count 2) to `secret.txt` as a `replace`
   target: `FROB-REF-734`; `secret.txt` unchanged.
8. `sentinel_after`: digest → `S1`; assert `S1 = S0`.
9. `mcp` (with `--mcp`, from M1's generated tools): steps 3 and 5 through the MCP tools over stdio; the tool
   result is an error whose structured content is the same refusal envelope.
10. `planted` (a build with feature `mutants`): the variant that checks a canonical string and then opens by
    name. Run step 6: the step passes only if at least one file lands in `<run>/outside/drop/` and the script's
    oracle reports it (the control is caught). A second variant percent-decodes components: step 4 must fail.
11. `record`: write GATE-SAFE-10's measured values through the conformance harness: verbs, path arguments,
    corpus entries by class, attempts, refusals, successes inside the root, files outside (0), swap iterations,
    controls caught, and the milestone of the surface measured.

**Logging.** `target/e2e-logs/safe_path_jail/<utc-timestamp>.ndjson` and a transcript. Every line: `ts`,
`script`, `bead` (`N37-12`), `step`, `event` (`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact
command line, exit code, wall time, the envelope's `evidence` block, the corpus entry identifier and class,
the refusal code and `observed`; for the swap recipes a `metric` line with `calls`, `succeeded_inside`,
`refused`, `landed_outside` (threshold 0); `S0` and `S1`. On failure: the first differing sentinel entry and
the paths of the saved envelope and the offending file. `summary`: assertions passed and failed and
`gates: ["GATE-SAFE-10"]`. The secret's bytes are never logged.

## Acceptance criteria

- [ ] On a clean build the script exits 0, the sentinel digest is unchanged, `landed_outside = 0` in every
      swap recipe at 1,000 iterations, and GATE-SAFE-10 is recorded for the surface present (M1 verbs at the
      M1 exit; every verb at M3).
- [ ] Every (verb, path argument) pair from the registry was attempted; a pair missing from the sweep fails
      step 1.
- [ ] The ten look-alike names are created inside the root.
- [ ] Both planted variants are caught in step 10.
- [ ] No refusal text contains a host path; the log contains no secret bytes.

## Test plan

### Unit tests
`cargo test -p frob-conformance --test jail_helpers`: `swapper_alternates` (observes both states within 10 ms);
`sentinel_digest_detects_one_byte_change`; `args_list_matches_registry`.

### End-to-end script and logging
This bead is the script. It runs in the ordinary end-to-end suite with `--iterations 100` and for the gate
with the default 1,000.

### Known answers and negative controls
KA-835 (refused on every path-taking argument of every verb; exact; tier G4, host). Negative controls: the
check-then-open variant and the percent-decoding variant. Metamorphic relation: renaming the roots changes no
verdict and no refusal text. Determinism lanes: lexical results identical twice on one machine and on Linux
and macOS; the swap recipes are run on both platforms and their oracle holds on every schedule.

## Considerations

- The swap recipes are probabilistic as attacks and deterministic as oracles: a correct jail passes on every
  schedule, and the planted variant is given 1,000 iterations so that the race is hit with high probability
  (if a platform makes the race too narrow to hit, the control is run with a helper that pauses the mutant
  between check and open through a test-only hook).
- The script needs no elevated rights; device-node recipes are skipped with a logged reason where they cannot
  be created.
- At M3 the same script runs once per session root kind and per namespace, under tokens with and without the
  private scopes.
