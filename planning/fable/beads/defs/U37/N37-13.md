## Background

An authorized agent can still be confused or wasteful: it can ask for 10¹² worlds, trace every channel of
every world, open a thousand subscriptions, or retry one submission in a loop. The threat model protects the
owner's machines and devices from such an agent, and other agents' work from a client that retries blindly.
The protection is **resource governance**: budgets, quotas and draining cancellation; device-memory and disk
preflight; and the compute envelope (the owner-approved class of work a job may be; the fail-closed default
is 16 GiB of memory, 8 cores, one hour and one device).

This bead owns the additions the safety chapter states on top of the job engine:

1. allocation sizes are validated before any device work;
2. each call has a wall-clock ceiling, and each session a budget in every unit a budget can cap;
3. the MCP server applies the library's rate limiting and a bound on subscription listeners;
4. trace bytes are a budgeted quantity, so telemetry cannot fill a disk;
5. the admission guard holds device utilization under 0.8 (TARGET).

(A sixth, the remote worker's manifest, is N37-14.) Much of the machinery is built elsewhere: estimates with
calibrated intervals, admission against the upper end of the interval, size classes and the guard, the
crash-consistent job protocol, one job and one charge per idempotency key. What is missing without this bead
is the guarantee that **no request path reaches a device, a large host allocation or the disk before those
checks**, in every unit, with nothing defaulting to unlimited. Rejected alternative: relying on the operating
system to fail allocations. An out-of-memory kill takes the daemon and every other agent's jobs with it.

## Scope

In: checked size arithmetic from request to bytes; the preflight order; per-verb wall-clock ceilings;
completion of the budget vector and its fail-closed defaults; trace-byte reservation; disk preflight; MCP rate
and listener bounds; a session-count cap; the exhaustion battery. Out: the estimator and its intervals; the
scheduler, the guard's implementation and preempt-resume; the job protocol and cancellation; tokens and
scopes (BD-258); the remote worker (N37-14).

## Technical approach

1. **Sizes before work.** Every quantity a request can scale (worlds, episodes, horizon ticks, bucket
   capacities, contact and row capacities, traced worlds and channels, telemetry level, camera count,
   resolution and cadence, scene variants, population size, pairs, cells) is an `int53` or a typed quantity
   in the input schema, with a schema maximum. The dispatcher computes the request's byte and work figures
   with checked integer arithmetic (an overflow is a refusal `FROB-REF-802` naming the field, never a wrap)
   by calling the same model `sim.estimate` exposes: device bytes (arena slabs, frame buffers, scene fields),
   host bytes, trace bytes, disk bytes, device seconds, CPU core-seconds. Only then may admission proceed.
   No handler allocates a buffer whose size came from a request without that figure having passed preflight
   (a lint forbids `Vec::with_capacity`, `vec![…; n]` and device-buffer creation on a value of the request
   type outside the admission module).
2. **Preflight order** (each failure is a typed refusal and nothing later runs):
   1. schema and range (`FROB-REF-802`, exit 3);
   2. the compute envelope: the job's class against the class in force (`FROB-REF-761`: a job exceeds the
      compute envelope in force; `FROB-REF-704`: a campaign-class job without an approved envelope; exit 4);
   3. session budgets, using the upper end of the estimate interval in each unit (`FROB-REF-701` with the
      estimate attached; exit 4);
   4. device memory against the device budget (`FROB-REF-602`; exit 6);
   5. disk: free space on the store's file system minus a reserve (DESIGN: the larger of 8 GiB and 10% of the
      volume) must exceed the upper end of the disk estimate (`FROB-REF-701` with unit `disk_bytes`);
   6. the admission guard: device utilization at or above 0.8 (TARGET), or the per-environment job cap
      reached (`FROB-REF-703`, `retry: backoff`; exit 4);
   7. the idempotency binding, the budget reservation and the job row in one transaction.
3. **The budget vector, complete and never unlimited.** A budget can cap: wall time, simulated time, GPU
   seconds, CPU core-seconds, device memory, trace bytes, episode count and solver iteration caps; the token
   also carries disk bytes. A unit the token does not name takes the session default from the owner-held
   configuration (DESIGN defaults equal to the envelope class E0 and, for trace and disk bytes, 1 GiB and
   2 GiB); the type has no "unbounded" value. Under shared batches a job is charged attributable device time:
   the sum over steps of (its occupied slots ÷ batch capacity) × the step's wall time.
4. **Wall-clock ceiling per call.** Each verb row has `max_wall_ms` (DESIGN defaults: `read` and `mutate`
   30,000; `run` the smaller of its wall-time budget and the envelope class's limit). In-process handlers
   check the job context's deadline at their cancellation checkpoints; a job that reaches its ceiling stops at
   a safe boundary, publishes nothing partial as a result, and ends with `FROB-REF-702` naming the last
   committed tick. The MCP server's request timeout is 40 s, above the longest bounded wait of 30 s.
5. **Trace bytes.** The chunk publisher reserves a chunk's encoded size from the session's `trace_bytes`
   budget in the publishing transaction. If the reservation fails, the job stops at that chunk boundary with
   `FROB-REF-702` (unit `trace_bytes`): committed chunks stay, nothing partial is published as a result. The
   telemetry level is never silently lowered to fit.
6. **MCP bounds.** The server is built with the library's rate limiter (DESIGN default: 600 requests per
   minute per session with a burst of 60; configurable only in the owner-held file) and with a subscription
   listener capacity of 64 streams server-wide (FACT: the library's stated limit). A subscription beyond
   capacity is refused by the library; the client falls back to polling `job.wait`. Requests over the rate
   receive the library's rate-limit error before any handler runs and are charged nothing.
7. **Session count.** At most 256 open sessions per principal, counting derived ones (DESIGN); the 257th
   `session.open` is `FROB-REF-703` with `observed: sessions`.
8. **Blind retries.** One job and one budget charge per (principal, verb, idempotency key) under any
   interleaving; a mutating or job-submitting call without a key is `FROB-REF-805`. This bead adds the storm
   test below to the idempotency gate's evidence.
9. **Classes and records.** Admission decisions are D0 given the estimate. Each refusal is a ledger row with
   the figures that caused it. No wall-clock quantity enters a result.

## Acceptance criteria

- [ ] The exhaustion battery (below) ends, case by case, in the stated refusal, and for every refused case the
      device allocated-bytes counter, the store's size and the process's peak resident memory are unchanged
      within noise (TARGET: device 0 bytes; store 0 bytes; host under 16 MiB above baseline).
- [ ] A token that names no trace or disk budget is limited by the defaults (1 GiB and 2 GiB), not unlimited.
- [ ] A job whose traces would exceed the trace budget is refused at admission by the estimate, and a job
      whose estimate was too low stops at the chunk boundary with `FROB-REF-702` and a contiguous frontier.
- [ ] With utilization forced to 0.8, a new submission is `FROB-REF-703` with `retry: backoff`.
- [ ] The allocation lint fails on a planted `Vec::with_capacity(request.worlds)` in a handler.
- [ ] 1,000 parallel submissions with one idempotency key leave one job and one charge.

## Test plan

### Unit tests
`cargo test -p frob-verbs --test governance` and `-p frob-cli --test admission_order` (the real ledger; the
device is `batch-cpu`; no mocks):
- `size_arithmetic_checked`: worlds 9,007,199,254,740,991 × horizon 9,007,199,254,740,991 → `FROB-REF-802`
  (overflow), no panic.
- `frame_bytes_known_answer`: a 640 × 480 frame with 4 bytes of colour and 4 of depth is 2,457,600 bytes; two
  cameras on 256 worlds are 1,258,291,200 bytes.
- `preflight_order`: a request failing steps 2, 3 and 4 at once reports the envelope refusal (the first).
- `budget_vector_has_no_unbounded`: compile-time (no such variant) and a default-fill test.
- `wall_ceiling_stops_at_boundary`: a `batch-cpu` run with a 2 s ceiling ends `FROB-REF-702` with a committed
  tick and no result.
- `trace_reservation_stops_at_chunk`.
- `disk_reserve_rule`: free space 9 GiB on a 50 GiB volume (reserve 8 GiB) admits a 0.9 GiB estimate and
  refuses 1.1 GiB.

- `planted_allocation_fails_lint`.

### End-to-end script and logging
`scripts/e2e/safe_capabilities.sh` (N37-15), step `governance`, runs the battery through `frob` and
`frob-mcp` against `frobd` and logs per STD-E2E: each command line, exit code, refusal code with `observed`,
`required` and `unit`, the estimate block, and `metric` lines for device bytes allocated, store bytes and
peak resident memory before and after each case against their thresholds.

### Known answers and negative controls
Known answers: the frame arithmetic above (KA-817); a 96-pair comparison occupies 192 of 8,192 slots (2.34%).
Counterexample protected: "device memory limits the number of worlds" is false for state (a world is about 35
kB for a quadruped and 97 kB for a humanoid, so 8,192 worlds are 0.28 GB and 0.79 GB) and true for camera
frames, which is why frames enter the estimate (CX-381). Negative controls: a `mutants` build that allocates
before preflight (the device-bytes metric must move and the battery must fail); one whose trace budget
defaults to unlimited; the two-statement idempotency variant (two jobs under the storm). Determinism lanes:
admission verdicts identical twice on one machine for the same ledger state.

## Considerations

- The safety chapter defines no gate of its own for resource governance; its evidence is this battery plus the
  surface chapter's gates on estimates, idempotency and scheduling. The battery's controls are registered
  against those gates so that it is run whenever they are.
- The guard's threshold and the per-environment job cap are TARGETs to be refitted from the M2 queue trace.
- A rate limit protects the daemon, not fairness between agents; fairness is the scheduler's deficit
  round-robin.
- The disk reserve is a DESIGN default; on the training machine the store may live on a volume shared with
  other projects, and the owner sets the reserve accordingly.
