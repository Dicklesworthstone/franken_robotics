## Background

Work leaves the process that accepted it in three ways: to a device worker owned by the daemon; to the pinned
referee worker process (the fallback that keeps the trusted reference dynamics behind a process boundary); and,
if the peer link between the two machines is built, to the other machine. Each of these is a place where
"run this job" could quietly become "run this command". The safety chapter's rule: **a remote worker receives
an allowlisted job manifest, hash-checked immutable inputs and an output quota, never a shell.**

Why each part. *Allowlisted manifest*: the worker can do only what its compiled-in handlers do; a job is a
kind from a closed list plus typed parameters, so there is nothing to inject a command into. *Hash-checked
immutable inputs*: what the worker computes on is exactly what the submitter named; a swapped file changes a
digest and the job refuses. *Output quota*: a job cannot fill the receiving disk or the link. *Never a
shell*: no field is a command line, an environment variable, a host path, a URL or a script, and the worker
spawns no process on a job's behalf. Rejected alternative: remote execution by sending command lines over a
login shell. It is the simplest thing that works and it turns every string field of a job into a possible
command.

Related standing rules this bead relies on: only seeds, recipes, design and module differences, model-variant
tables, policy weights, receipts, digests and telemetry summaries cross between machines (compiled scene
fields, world state and rollout buffers never do; an attempt is refused with `FROB-REF-618`); and a private
scan stays on the machine that holds it, so a job that needs it runs there.

## Scope

In: the manifest schema and the job-kind allowlist; input verification; the output quota and its enforcement
on both ends; the static and dynamic checks for "never a shell"; the attenuated token a worker receives; the
contract the peer link must meet. Out: the worker protocol's chunk partition and bit-equality (the worker
fallback bead); the fleet scheduler and the transfer-class meter (device chapter, M4); slot dispatch.

## Technical approach

1. **Manifest (DESIGN; schema `frob.job-manifest/1`, canonical JSON; the job's identity is the BLAKE3 hash of
   these bytes and submission is idempotent on it).**
   ```json
   { "schema": "frob.job-manifest/1", "kind": "referee-rollout", "stack_receipt": "b3:…",
     "inputs": [ { "role": "model", "schema": "frob.model/1", "digest": "b3:…", "bytes": "48211" },
                 { "role": "scene-recipe", "schema": "frob.scene/1", "digest": "b3:…", "bytes": "912" } ],
     "params": { "horizon_ticks": "2000", "cadence": "1/500", "tier": "referee" },
     "seeds": { "world": "u64 as string" }, "profile": "reference-replay",
     "budget": { "cpu_core_s": "120", "wall_s": "300" },
     "output": { "quota_bytes": "268435456", "chunk_ticks": "250", "columns": ["state", "events", "digests"] },
     "token": "<an attenuated capability token valid for this job only>" }
   ```
   The schema is closed (`additionalProperties: false` everywhere). The leaf types are the closed input leaf
   types of the data-not-code rule; in particular there is no string leaf for a command, an environment
   variable, a path or a URL.
2. **Kind allowlist.** `registries/job-kinds.toml` lists each kind with its parameter schema, the input roles
   it requires, the transfer class of each role, and the handler symbol. The worker binary embeds the
   registry; `kind` selects a compiled-in handler through a match on an enum generated from it. An unknown
   kind, a missing or extra role, or a parameter outside its schema is a `refuse` frame carrying
   `FROB-REF-802`. A manifest whose `stack_receipt` differs from the worker's is refused (the worker
   fallback's receipt-mismatch refusal).
3. **Inputs.** Each input is fetched by digest from the sender's store, written to the worker's store under a
   retained handle, and its BLAKE3 is recomputed over the received bytes before any parser sees them; a
   mismatch, a length different from `bytes`, or a digest not named in the manifest is a refusal and the
   bytes are discarded. Inputs are opened read-only and never modified. For the peer link, each role's
   transfer class is checked against the classes that may cross; a compiled field or a state slab is
   `FROB-REF-618` ("a transfer class that may not cross machines"; first repair: send the seed or recipe); an
   input carrying the private mark does not cross unless the submitting session holds the private export
   scope and passed the per-call flag (`FROB-REF-731` otherwise).
4. **Output quota.** The worker counts the encoded bytes of every chunk and result it emits for a job. A
   chunk that would pass `quota_bytes` is not sent; the job stops at that chunk boundary and ends with
   `FROB-REF-702` (unit `output_bytes`), nothing partial published as a result. The receiver enforces the same
   count independently and drops the connection on a frame beyond the quota (a worker that ignores its own
   quota is treated as faulty).
5. **The worker's token.** The daemon derives, for each job, a token whose scopes are exactly the job kind's
   needs, whose budget is the job's reservation and whose expiry is the job's wall limit plus a margin. The
   worker presents it when publishing chunks; it authorizes nothing else.
6. **Never a shell: three checks.**
   - Schema: the manifest lint above, run on the registry.
   - Static: in the worker crate and every crate a job handler calls, `std::process::Command` and the
     functions that spawn or replace a process are disallowed by the workspace lint table, with no exception
     inside handlers. (Kernel compilation happens in process through the device libraries. The derivation
     subprocess of the symbolic toolchain is started by the core at build or design time, never by a job
     handler from job data.)
   - Dynamic: the worker runs a job under a system-call tracer on a host where tracing is available, and the
     trace shows no process creation and no socket other than the one it was given.
7. **The peer link.** If the link between the two machines is built, it forwards a manifest and fetches
   inputs by digest; it offers no other operation. Until it is built (the default is standalone machines),
   work on the other machine is started by running verbs on that machine under its own daemon and tokens;
   no part of this system logs in to another host to run a command string.
8. **Classes.** The manifest identity and input checks are D0. A worker's results carry the stack receipt it
   reported.

## Acceptance criteria

- [ ] A manifest with an unknown `kind`, an extra property, a missing role or a parameter out of range is
      refused before any input is fetched.
- [ ] An input whose bytes differ in one bit from its digest is refused and not stored; the job does not start.
- [ ] A job producing more than its quota stops at a chunk boundary with `FROB-REF-702`; the receiver holds at
      most `quota_bytes` for it.
- [ ] The manifest schema has no leaf that can hold a command, an environment variable, a path or a URL (the
      leaf lint passes; a planted `command` property fails it).
- [ ] The static lint fails on a planted `std::process::Command::new` in a handler; the system-call trace of a
      referee rollout through the worker shows no process creation.
- [ ] A manifest listing a compiled scene field as an input for the peer link is refused with `FROB-REF-618`;
      a private-marked input without the scope and flag is refused with `FROB-REF-731`.
- [ ] The worker's token cannot be used for any verb other than publishing that job's chunks
      (`FROB-REF-720`).

## Test plan

### Unit tests
`cargo test -p frob-fsim --test worker_manifest -p frob-verbs --test job_kinds` (a real worker process on
`batch-cpu` and the referee; no mocks):
- `manifest_identity_is_canonical`: key order and whitespace do not change `job_hash`.
- `unknown_kind_refused`; `extra_property_refused`; `missing_role_refused`.
- `input_one_bit_flip_refused` (for each role).
- `input_length_mismatch_refused`.
- `quota_stops_at_boundary`: quota 1 MiB, chunks of 300 kB → three chunks sent, the fourth withheld, refusal
  with `observed` 1,200,000 and `required` 1,048,576.
- `receiver_enforces_quota_against_faulty_worker` (a `mutants` worker that ignores its quota).
- `worker_token_scoped_to_job`.
- `transfer_class_field_refused_618`; `private_input_refused_731`.
- `planted_command_field_fails_lint`; `planted_process_spawn_fails_lint`.

### End-to-end script and logging
`scripts/e2e/safe_capabilities.sh` (N37-15), step `worker_manifest`: a referee rollout submitted through
`frob --json sim run --tier referee` with the worker mode enabled; then the same with a tampered input in the
sender's store, and with a quota of 1 MiB. Logged per STD-E2E: command lines, exit codes, the manifest's
`job_hash`, each input's digest and verification result, bytes published against the quota, the refusal codes;
on a host with a tracer, a `metric` line `process_creations` with threshold 0.

### Known answers and negative controls
Known answers: the quota arithmetic above (three chunks of 300 kB fit in 1,048,576 bytes; four do not).
Negative controls: the quota-ignoring worker (the receiver must cut it off); a `mutants` worker that skips
input verification (the one-bit-flip test must then fail the bead); a manifest schema with a free-form
`params` object (the leaf lint must fail). Determinism lanes: `job_hash` identical on Linux and macOS; a
killed and resubmitted job returns the same chunk digests.

## Considerations

- A worker on the same host is not a security boundary against a local user; the manifest rule is about what
  an agent can cause through job fields, and about keeping the cross-machine surface to a list.
- The peer link is Frontier and may never be built (its pilot is a week of queue traces; under 10% overlap of
  idle and queued time it is not built). The manifest contract costs nothing to keep and is what the link
  would have to satisfy.
- System-call tracing needs privileges on some hosts; where it cannot run, the dynamic check is recorded
  `not run` with the reason, and the static lint stands alone.
- Output quotas interact with trace budgets: the quota bounds one job's bytes on the wire and at the receiver;
  the session's trace budget bounds what is kept.
