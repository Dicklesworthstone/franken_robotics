## Background

Two properties of an artifact restrict where it may go: whether it is **private** (built from a scan of a real
home or workplace, or from anything derived from one), and what its **licences** allow (an asset may be
redistributable, need attribution, be for research only, be proprietary, or be of unknown terms). Both must
follow an artifact through every derivation: a still of a replay of a policy evaluated in a private scene is
private, and a report that includes a figure computed with a research-only asset is research-only.

Decision **ADR-SAFE-03**: privacy and licence marks propagate through lineage as a join; nothing derived can
be less restricted than an input. Reason: marks attached by hand are forgotten on the second derivation.
Rejected alternatives: a `private` flag that each writer sets (the writer of a contact sheet does not know
where the run's scene came from); marking by storage location alone (a file copied out of the private root
loses its mark); propagating at export time by walking back from the artifact (correct but late: listings and
shared views need the mark at read time).

So **inheritance is computed**. The mark of an artifact is the join of the marks of everything in its
lineage, so that a still of a replay of a policy evaluated in a private scene is private without anyone
marking it. Invariant **INV-SAFE-04**: the privacy mark and licence set of an artifact are the joins of those
of its lineage; neither can decrease along a derivation. Proof obligation **PO-SAFE-01**: the join of marks is
monotone along lineage (verification: the mark lattice is finite; a property test over random derivation
graphs; the argument in the crate's `CONTRACT.md`).

Risks served: RISK-12 (a scan of a private place leaks through a still, a fixture or policy weights; signal:
a derived artifact without the private mark) and RISK-11 (asset licences restrict what can ship).

## Scope

In: the mark types and their order; the join; computing and storing a mark at every store write from the
parents' marks; the store API shape that makes a hand-set mark on a derived object impossible; marks in
manifests and their recomputation on read; the store-wide audit; the argument for PO-SAFE-01. Out: what a mark
forbids (private places and views: BD-305; licence refusals and notices: N37-18; purge: N37-19); the root
marks of scene packs (scene chapter); whether weights inherit (the decision is N37-20; the switch it sets,
one filtered edge role read from the owner-held configuration, is built here, and its default is that they
inherit both).

## Technical approach

Types in `frob_core::mark` (so that every crate can name them); computation and storage in
`frob_chronicle::marks`.

1. **The lattice (DESIGN sketch).**
   ```rust
   pub enum Privacy { Public, Private }                                   // Public < Private
   pub enum LicenceClass { Redistributable, Attribution, ResearchOnly, Proprietary, Unknown }  // weakest first
   pub struct LicenceEntry { source: Ident, licence: Ident, class: LicenceClass, notice: Option<Blake3> }
   pub struct LicenceSet(BTreeSet<LicenceEntry>);                         // join = union
   pub struct Mark { privacy: Privacy, licences: LicenceSet }             // fields private
   impl Mark { pub fn bottom() -> Mark; pub fn join(&self, other: &Mark) -> Mark; pub fn class(&self) -> LicenceClass; }
   ```
   `unknown` is treated as the most restrictive class. `class()` of a set is the maximum class among its
   entries, and `Redistributable` for the empty set. Order: m₁ ≤ m₂ exactly when privacy₁ ≤ privacy₂ and
   licences₁ ⊆ licences₂. The join is componentwise: the larger privacy and the union of the sets. It is
   associative, commutative and idempotent, with `bottom()` = (Public, ∅) as its identity. The class
   projection (privacy, class) has 2 × 5 = 10 values, a finite lattice in which the join is the componentwise
   maximum; the projection of a join is the join of the projections.
2. **Where marks come from.** A *root* object declares its own mark: an imported scan is `Private`; an
   imported asset carries the licence entry of its manifest (class `Unknown` when nothing is declared);
   procedural content carries one entry with source `frob-scene` and class `Redistributable`; an authored
   design or task is `bottom()` unless its author declares more. Every other object is *derived*.
3. **The store API makes the rule structural.** There are two ways to write an object:
   `put_root(kind, bytes, own: Mark)`, callable only from importers and authoring verbs (a hidden doorway
   whose call sites are enumerated by a signature scan and compared with a reviewed list), and
   `put_derived(kind, bytes, parents: &NonEmpty<Parent>, extra: Mark)` with
   `Parent { id: ObjectId, role: ParentRole }` (a closed enum: `Input`, `TrainingRun`, `InitialWeights`,
   `Donor`, `Cited`), which computes
   `mark = extra ⊔ ⨆_{p ∈ parents} carried(p, mark(p))`
   inside the same ledger transaction that writes the object and its `derived-from` edges. `carried` is the
   identity on every edge except the one of step 4a, and is never a caller argument. There is no function
   that writes a derived object with a caller-chosen mark, and `extra` can only raise it. `put_derived` with
   an empty parent list is a compile-time error (a non-empty slice type).
4. **Parents, by artifact kind** (the bead that stores each kind supplies them; this table is the contract):
   | Derived kind | Parents |
   |---|---|
   | Compiled scene, clearance complex | The scene pack and every asset it references |
   | Episode, run | Scene, design, task, policy, cards |
   | Chunk, snapshot, event | Its episode |
   | Still, contact sheet, replay packet, telemetry summary | The chunks or snapshots it draws from |
   | Study, comparison, verdict, scorecard row | Every run it aggregates |
   | Policy weights, checkpoint | The training run (hence its scenes), the initial weights, the donor |
   | Report, certificate bundle, build packet, kit | Every artifact it cites or embeds |
   | Memo node | The inputs of the memoized result |
   | Fixture extracted from a run | The run |

   4a. **The one filtered edge (OPEN-SAFE-2).** Whether weights inherit is an owner decision (N37-20) held in
   two keys of the owner-held safety configuration, `private.weights_inherit` and `licence.weights_inherit`
   (N37-02; both `true` by default, the fail-closed answer). For a policy-weights or checkpoint object, the
   edge to the parent of role `TrainingRun` is written with `carries ∈ {both, privacy, licences, none}`, taken
   from those two keys as they stand at write time; the join takes from that parent only the carried
   components (privacy, the licence set, or both). Every other edge, including those to `InitialWeights` and
   `Donor`, carries both. `put_derived` refuses role `TrainingRun` for any other child kind (an integrity
   fault, not a refusal code). The edge row stores `carries`, so a later change of a key never lowers a mark
   already written (N37-20's rule) and the audit recomputes with the value in force at write time.
5. **Storage.** Ledger tables `mark (object, privacy, licence_set)` and `licence_set (set_digest, entries)`,
   the set content-addressed so equal sets are stored once; the `derived-from` edge row gains `carries`
   (default `both`). The mark of every object is readable in O(1); the lineage closure is never walked at read
   time.
   **Stores from before M3.** Objects written before this bead have no mark row. The ledger migration that
   creates the tables runs the audit's single pass (step 8) to write them: roots from their manifests (an
   imported asset's licence entry, `Unknown` when it declares none; nothing written before M3 is private,
   because private import arrives with BD-305), every other object by the join, every existing edge with
   `carries = both`. The migration is idempotent and logs the number of objects it marked.
6. **Late edges.** If a `derived-from` edge is added after the child exists (a lineage discovered late, a
   memo hit linked afterwards), the transaction recomputes the child's mark and propagates upward-only
   through its descendants in topological order; a mark is never lowered by an update.
7. **Manifests.** An exported artifact's manifest carries `"marks": { "privacy": …, "licence_class": …,
   "licences": [ … ] }`. A reader recomputes the class from the entries; a stored class that differs from the
   recomputation is refused as a corrupt manifest. An imported artifact's manifest mark becomes its root mark
   (never less than what the manifest states).
8. **Audit.** `frob_chronicle::marks::audit` recomputes, for the whole store, each object's mark from the
   root marks and the edges (a single pass in topological order) and compares it with the stored mark; a
   difference is an integrity fault with both values and the object. It uses each edge's stored `carries`. It
   also reports any object of a derived kind with no parent edge, and any edge with `carries ≠ both` that is
   not a weights-or-checkpoint edge of role `TrainingRun`. Command form (declared here; BD-025's rule for a
   driver whose code lives in another crate; there is no `frob-conformance` binary):
   `cargo run -p frob-chronicle --example marks_audit -- --state <state root>`, a thin argument parser over
   that function that opens the ledger read-only, prints one JSON object (objects checked, differences with
   both values, orphans, filtered edges) and exits non-zero on any difference or orphan. The migration of
   step 5 calls the same function.
9. **PO-SAFE-01, the argument (to be written in `CONTRACT.md`).** By construction
   mark(a) = own(a) ⊔ ⨆ mark(p) over parents p. A join is an upper bound of its operands, so mark(a) ≥
   mark(p) for each parent; by induction along a path, mark(a) ≥ mark(b) for every ancestor b. Unfolding the
   recursion over the finite acyclic graph gives the closed form mark(a) = ⨆ own(b) over a and all its
   ancestors. Late edges only add operands to a join, which cannot lower it. Acyclicity holds because a
   parent must already exist when its child is written, and the late-edge transaction of step 6 rejects an
   edge whose parent has the child among its ancestors. With a filtered edge (step 4a) the same argument holds
   for each component separately along the edges that carry it; under the default every edge carries both
   and the statement is the plan's without qualification. A filtered edge is the owner's recorded decision
   (N37-20), the only place a derived artifact can be less restricted than an input in one component, and the
   audit names every such edge.
10. **Classes.** D0: set arithmetic on declared data. A mark is a restriction, not evidence, and does not
    enter the claim product.

## Acceptance criteria

- [ ] KA-827: for a private, research-only scene, a replay of it and a still of the replay, the mark is
      private and research-only at each of the three steps, with no call that sets a mark on the replay or
      the still.
- [ ] PO-SAFE-01 and INV-SAFE-04: over 10⁴ random derivation graphs of up to 200 nodes, every node's stored
      mark equals the join of the own marks of itself and all ancestors, and is at least each parent's mark.
- [ ] `put_derived` cannot be called with an explicit lower mark or with no parents (compile-fail tests); the
      doorway scan lists exactly the reviewed `put_root` call sites.
- [ ] A manifest whose stored licence class is weaker than its entries is refused on read.
- [ ] The audit passes on a store built by the test suite and reports a planted object whose mark row was
      lowered by hand in the ledger.
- [ ] Adding a late edge from a private object raises the marks of all descendants in the same transaction.
- [ ] `CONTRACT.md` of the crate contains the monotonicity argument.

## Test plan

### Unit tests
`cargo test -p frob-core --test mark -p frob-chronicle --test marks`:
- `join_laws` (property): associative, commutative, idempotent; `bottom` is the identity.
- `class_is_max`: {redistributable, attribution} → attribution; adding research-only → research-only; adding
  unknown → unknown; ∅ → redistributable.
- `order_is_componentwise`.
- `three_step_derivation` (KA-827).
- `random_graphs_closed_form` (10⁴ graphs, seed 1): stored mark = join over ancestors' own marks; a second
  run of 10⁴ graphs in which weights nodes carry random `carries` filters checks the componentwise closed
  form (each component the join over the ancestors reachable by edges that carry it).
- `monotone_along_every_edge` (same graphs).
- `late_edge_propagates_upward_only`.
- `policy_weights_inherit_scene_mark`: weights trained on a private scene are private (default).
- `training_run_edge_filtered_by_keys`: with `licence.weights_inherit = false` in a test configuration the
  checkpoint is private and its licence set holds only the initial weights' and donor's entries; with both
  keys `false` its mark is the join of `InitialWeights` and `Donor` only; the edge rows store the `carries`
  used.
- `key_change_lowers_no_written_mark`: a checkpoint written under the default keeps its mark after the keys
  are set to `false`; the audit passes on both.
- `training_run_role_only_for_weights`: role `TrainingRun` on a still is an integrity fault; a planted ledger
  edge with `carries = none` on a still is reported by the audit.
- `migration_backfills_marks`: a store written without marks (the pre-M3 layout) gets a mark row for every
  object, equal to the audit's recomputation; running the migration twice changes nothing.
- `aggregate_inherits_all`: a scorecard over 100 runs of which one is private is private.
- `manifest_class_recomputed`; `manifest_weaker_class_refused`.
- `audit_detects_lowered_mark`; `audit_detects_orphan_derived_object`.
- Compile-fail: `put_derived(kind, bytes, &[], extra)`; a call naming a mark parameter that would replace the
  computed one; a call passing a `carries` value.

### End-to-end script and logging
`scripts/e2e/safe_private_licence.sh` (N37-21) exercises the join through real verbs (import a private,
research-only scene; run; replay; still; report) and prints each artifact's mark with `frob --json artifact
list --private` (a session holding `private:read`; without `--private` a private object is absent from the
listing, BD-305, VERBS-artifact). Logged per STD-E2E: for each derivation step the object digest, kind, parents and mark, and an `assert`
line comparing the mark with the expected join. No private content is logged; objects are named by digest.

### Known answers and negative controls
KA-827 (join over a three-step derivation: private and research-only at every step; exact; tier G1, host) and
KA-832 (over random derivation graphs the licence set equals the join of the inputs; exact). Negative
controls (built with `--features gauntlet-mutations`): a build in which a still takes only its first parent's
mark; one in which the class of a
set is the minimum; one in which a late edge does not propagate. Each must be caught by the random-graph
property. Metamorphic relation: permuting the order of parents changes no mark. Determinism lanes: marks and
set digests identical on Linux and macOS, debug and release.

## Considerations

- Over-marking is the intended failure direction: an artifact that touched a private input is private even if
  no private information survives in it. The owner's remedy is an explicit, logged export with the private
  export scope and flag, never an unmarking.
- The parents table is only as good as the edges other beads write; the audit's orphan check and the
  conformance sweep over artifact kinds (in the private-places bead) are what find a missing edge.
- Whether policy weights should inherit is an open question for the owner (default: they inherit both mark
  and licence set; the decision bead is N37-20); the switch is the `carries` of one edge role (step 4a), set
  from two keys of the owner-held configuration and never from a caller.
- Cost: one join per write, proportional to the parents' set sizes; licence sets are small (tens of entries).
