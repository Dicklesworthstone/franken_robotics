## Background

Licences are enforced at pack time. Each asset has a manifest entry (its source, its licence and any
restriction on redistribution), and the entry travels with every pack that contains the asset. **Research-only
assets cannot enter an exported report or a redistributed pack.**

The classes are `redistributable`, `attribution`, `research-only`, `proprietary` and `unknown`, and `unknown`
is treated as the most restrictive. The licence set of a derived artifact is the join over its inputs and
travels in its manifest (the mark lattice and its join are N37-17); an export whose set forbids it is refused
with `FROB-REF-733`, and an `attribution` class adds the notices to the exported report.

FACT (a research pass on 2026-11-21; licences are re-checked at admission; an asset whose licence was not read
is marked so and stays outside the default pipeline). Reference robots: MuJoCo Menagerie models under BSD-3
(Unitree Go1, Go2, A1, H1, G1; ANYmal B and C; Spot), MIT (Cassie) and Apache-2.0 (Stretch 3, TIAGo, Booster
T1, Apptronik Apollo, Fourier N1, OP3, TALOS, Barkour); the suite's own robot models. Scene assets: this
project's procedural generators; Infinigen Indoors (BSD-3); Google Scanned Objects (CC-BY 4.0); RoboCasa (code
MIT, assets CC BY 4.0); ProcTHOR (code Apache-2.0, dataset licence not verified: generator reference only);
HSSD (CC BY-NC 4.0), HM3D (academic, non-commercial), PartNet-Mobility (non-commercial research terms) and
BEHAVIOR-1K (its own agreement): user-supplied import only, never redistributed; Objaverse-XL (per object, not
used by default). The starter pack ships only synthetic and redistributable fixtures.

**Dependencies are assets too.** FACT: the suite's MCP library and its mail server are under an MIT licence
with a rider (`fastmcp_rust/LICENSE`); that text is carried in the dependency's admission record and in any
redistributed binary's notices.

Risk served: RISK-11 (asset licences restrict what can ship; signal: a pack whose licence join is not
redistributable; mitigation: procedural first, licence manifests enforced at pack time, GATE-SAFE-05).
Rejected alternative: checking licences only when a scene pack is built. A research-only asset reaches a
report through a run, a study and a scorecard without any pack being built on the way.

## Scope

In: the single export admission function every exporting verb calls; the licence decision per export kind;
`FROB-REF-733` with the lineage path to the offending asset; the Notices section and file for `attribution`;
generation of third-party notices for binaries; the laundering battery; the measurement of GATE-SAFE-05. Out:
the lattice and join (N37-17); the scene pack's own pack-time check and its code `FROB-REF-310` (scene
chapter); the private mark's export rule (BD-305); the dependency admission records themselves (BD-306).

## Technical approach

1. **One export door.** `frob_verbs::export::admit(artifact, kind, session) -> Result<ExportGrant, Refusal>`
   is the only producer of an `ExportGrant`, and every writer of bytes outside the store (the jailed export
   writer) requires one. Checks, in this order: the no-authorization flags are present in the artifact's
   manifest (`FROB-REF-816` otherwise); the privacy mark against scope and flag (`FROB-REF-731`); the licence
   set against the export kind (`FROB-REF-733`); the export scope for the kind (`FROB-REF-720`); the output
   path through the path jail (`FROB-REF-734`). A registry lint asserts that every verb with a non-empty
   `exports` field routes through `admit` (handlers cannot reach the export writer without a grant: the
   grant type has no public constructor).
2. **Decision by class (DESIGN).** Export kinds: `report`, `pack` (a scene pack, a kit, a starter pack),
   `run` (a run bundle or a view of it), `replay` (the self-contained page), `policy`, `bundle` (a certificate
   bundle), `packet` (a build packet), `design`.
   | Class of the artifact's licence set | Decision for every export kind |
   |---|---|
   | `redistributable` | Allowed |
   | `attribution` | Allowed; the notices of every attribution entry are added to the export (step 4) |
   | `research-only` | Refused, `FROB-REF-733` |
   | `proprietary` | Refused, `FROB-REF-733` |
   | `unknown` | Refused, `FROB-REF-733` (treated as the most restrictive) |
   Reading an artifact through a verb is not an export and is not affected.
3. **The refusal.** `FROB-REF-733`, "the licence set of the artifact forbids this export". Exit 5;
   `retry: after-change`. Fields: `pointer` (the artifact), `observed` (the class and the offending entries:
   source, licence, class), `required` (`class at most attribution`), and `via`: for each offending entry the
   shortest `derived-from` path from the artifact to the root asset, as a list of (kind, digest), so the
   caller can see which input brought the restriction. Ranked repairs (DESIGN): (1) replace or remove the
   named asset and re-derive the result (the `via` path names what must be recomputed); (2) for `unknown`,
   record the asset's licence and source in its manifest entry so that it is classified; (3) keep the
   artifact local and read it through verbs. Licence strings are imported text: in the envelope they sit in
   fields marked untrusted.
4. **Notices.** For an `attribution` set the exporter assembles, deterministically (entries sorted by source
   then licence), a notices block: one item per entry with the source, the licence identifier and the notice
   text addressed by `notice`. A `report` gains a final section "Notices"; a `pack`, `run`, `packet` or
   `policy` export gains a `NOTICES` file listed in its manifest with its hash; a `replay` embeds the block in
   its header. An attribution entry with no notice text is treated as `unknown` (the notice cannot be
   honoured).
5. **Same bytes, same or higher mark.** Importing bytes whose digest already exists in the store joins the
   declared root mark with the existing object's mark; a re-import can raise a mark and never lower it. So an
   artifact read out through a verb and imported again under a permissive declaration keeps its restriction.
6. **Third-party notices for binaries.** A generator (part of the existing generated-artifact check, so no
   new workspace check is added) reads each workspace's lockfile and `DEPENDENCY_ADMISSION.md` and writes
   `THIRD_PARTY_NOTICES`: for every package in the closure of a shipped binary, its name, exact version or
   commit, licence identifier and, where the admission record carries one, the full licence text (the MIT
   text with its rider for the MCP library and the mail server). A package in a shipped binary's closure with
   no licence in its admission record fails generation. `frob doctor --notices` prints the file embedded in
   the binary.
7. **The laundering battery (the second clause of the gate).** Fixture: a scene containing one stand-in
   asset declared `research-only`. Each row is an attempt to get it, or something computed with it, exported:
   | Attempt | Expected |
   |---|---|
   | Export the compiled pack | Refused at pack time (the scene chapter's `FROB-REF-310`) |
   | Run, then export the run bundle | `FROB-REF-733` |
   | Still of the run, exported | `FROB-REF-733` |
   | Self-contained replay | `FROB-REF-733` |
   | Scorecard over 100 runs, one of which used the scene, as a report | `FROB-REF-733`, `via` naming that run |
   | Train on the scene, export the policy | `FROB-REF-733` (weights inherit by default) |
   | A comparison whose answer was served from the memo store | `FROB-REF-733` (the memo node carries the mark) |
   | A certificate bundle for a mission answer over the scene | `FROB-REF-733` |
   | Read the still's bytes with `artifact.read`, import them as a new asset declared `redistributable`, export | `FROB-REF-733` (step 5) |
   | A report citing a claim whose evidence closure contains the run | `FROB-REF-733` |
   After the asset is replaced by a redistributable one and the chain re-derived, every export succeeds.
8. **Classes.** D0. The licence class is a statement about declared inputs, not a legal judgement.

## Acceptance criteria

- [ ] GATE-SAFE-05 (TARGET): over random derivation graphs the licence set equals the join of the inputs (the
      property of N37-17, 10⁴ graphs), and a research-only asset cannot be made to enter an exported report or
      pack (all ten rows of the battery refused). Recorded with counts.
- [ ] Every exporting verb in the registry routes through `admit`; a planted exporter that writes without a
      grant does not compile; a planted registry row with `exports` set and no route fails the lint.
- [ ] An `attribution` export contains the notices block with one item per attribution entry, byte-identical
      across two exports; an attribution entry without notice text is refused as `unknown`.
- [ ] `FROB-REF-733` names the offending entries and a `via` path that ends at the root asset.
- [ ] `THIRD_PARTY_NOTICES` lists every package of each shipped binary's closure and includes the MIT text
      with its rider; removing a licence from one admission record fails generation.
- [ ] Re-import of existing bytes under a weaker declaration does not lower the mark.

- `laundering_battery`: the ten rows.
- `notices_generator_requires_licence`; `notices_include_mit_rider_text` (by digest of the recorded text).
- `unknown_is_most_restrictive`.

### End-to-end script and logging
`scripts/e2e/safe_private_licence.sh` (N37-21), steps `licence_*`, runs the battery through the real `frob`
binary. Logged per STD-E2E: command line, exit code, refusal code, the artifact's class, the offending source
and licence identifiers, the length of `via`, and for allowed exports the digest of the notices block.

### Known answers and negative controls
KA-832 (licences over random derivation graphs: the licence set equals the join of the inputs; a
research-only asset cannot enter an exported report or pack; exact; tier G1, host). KA-827 (the three-step
derivation is research-only at every step). Negative controls: a `mutants` build whose `report` exporter
bypasses `admit`; one that treats `unknown` as permissive; one whose memo store drops marks. Each must fail
the battery. Metamorphic relation: adding a redistributable asset to any fixture changes no decision.
Determinism lanes: decisions, notices bytes and `via` paths identical on Linux and macOS.

## Considerations

- The appendix on known answers states no negative control for KA-832; the three planted builds above are
  registered as its controls so the gate can record PASS.
- Two codes can refuse a pack: the scene chapter's `FROB-REF-310` at pack time and `FROB-REF-733` at the
  export door. Both are kept; the battery accepts 310 only on the pack row.
- The tool enforces declared classes and refuses on doubt; it gives no legal advice. An owner who is entitled
  to export research-only material for a permitted use does so outside the tool or changes the declared class
  with a recorded source.
- Policy weights inherit the licence set of their training scenes by default (open question for the owner;
  N37-20).
- A model cannot redistribute what it cannot export, but `artifact.read` returns bytes to the caller; what a
  caller does with bytes it has read is outside the tool's reach and is stated as such in the agent guide.
