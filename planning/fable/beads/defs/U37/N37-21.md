## Background

The capability under test, from the user's side: the owner brings in a scene that is private (a scan of a
real place) and that contains a research-only asset; agents work with it; everything they derive from it
carries both restrictions without anyone marking anything; none of it shows up in a shared view or leaves
through an export; and when the owner purges the scene, it and everything derived from it are gone, with a
receipt.

Gates measured (Known answer, TARGET, M3). **GATE-SAFE-04**: for a private scene, each derived artifact kind
carries the mark; exports without the flag are refused; after `scene.purge` no digest of the closure remains
in the store. **GATE-SAFE-05**: over random derivation graphs the licence set equals the join of the inputs;
a research-only asset cannot be made to enter an exported report or pack. The known answer that ties them
together: the join over a three-step derivation (a private, research-only scene; a replay of it; a still of
the replay) is private and research-only at every step.

## Scope

In: the script, its fixture, steps, assertions, logging with redaction, and a re-run of both gates' tier
entries (BD-305, their one recorder, records them from its own tier run, which does not wait on this script);
the helper the script calls for what no mechanism bead provides,
declared here as an example of the conformance crate (BD-025's rule; there is no `frob-conformance`
binary): `crates/frob-conformance/examples/marks.rs`, run as `cargo run -p frob-conformance --example marks
-- <sub> …`, a thin argument parser over the harness library that prints one JSON object on standard output
and exits non-zero on a failed check, with three subcommands: `sweep --scene <id>` (the artifact-kind sweep
of step 4), `random-graphs --count <n> --seed <s>` (drives N37-17's random-graph generator through the real
store API and prints mismatches), and `scan-digests --receipt <digest>` (step 14). The store audit is
N37-17's (`cargo run -p frob-chronicle --example marks_audit -- --state <root>`). Out: the mechanisms
(N37-17, N37-18, N37-19, BD-305), the decision on weights (N37-20), and writing either gate row.

## Technical approach

`scripts/e2e/safe_private_licence.sh [--seed N] [--mcp]` (plain shell; sources the shared helper of STD-E2E;
idempotent; works under `target/e2e/safe_private_licence/<run>/` with its own state root, project root,
export root and a private root outside any version-controlled tree; `frobd` on `batch-cpu`).

Fixture (all `synthetic`): a small room authored in the interior grammar, imported with `--private`,
containing two procedural props and one stand-in asset whose manifest entry declares
`licence = "cc-by-nc-4.0"`, `class = "research-only"`. The room's wall texture and the asset's metadata
contain four **canary strings** (random 32-character tokens generated per run) so that leaks into logs and
listings can be searched for. A second, public scene of the same shape is used for comparisons.

Sessions: `owner` (all scopes including `private:read`, `private:export`, `scene:admin`); `agent` (discovery
scopes and `private:read`); `outsider` (discovery scopes only). Each is a root session of its own principal:
the three grants are written with STD-E2E's `e2e_session grant` before `frobd` starts, and each session is
opened with `e2e_session open` (no token in the environment; a root call presenting one is `FROB-REF-723`)
naming its scopes explicitly, because omitted scopes grant no non-budget scope; the discovery scopes are the
scopes that `frob schema --verbs --json` lists for the verbs of steps 1 to 11.

Steps (every `run` and `mutate` call carries its own `--key`, the CLI spelling of the idempotency key; a
call without one would meet `FROB-REF-805` before the assertion it is there for; `admin` calls take none):

1. `baseline_listings`: as `outsider`, save the output of every listing verb, every catalog resource, MCP
   `resources/list` and the shared archive and leaderboard → set `L0` (digests of each response).
2. `import`: as `owner`, `frob --json scene import <fixture> --private`; `scene compile`. Assert the marks:
   `privacy = private`, `licence_class = research-only`.
3. `derive`: as `agent`: `sim run` on the scene; `sim replay`; `telemetry stills`; `telemetry summary`;
   `eval run` and `eval scorecard`; a paired comparison against the public scene; a short `train start` on the
   scene and `train status` to a checkpoint; `nemesis search` and `nemesis shrink` to a minimal
   counterexample world; `run fork` and one intervention; `mission synthesize` on a one-cell mission over the
   scene and `prove bundle`; `report run` and `report design`.
4. `kinds_sweep`: `cargo run -p frob-conformance --example marks -- sweep --scene <id>` walks `registries/artifact-kinds.toml`, finds
   the object of each scene-derivable kind produced in step 3 (running a kind's own fixture pipeline if step 3
   produced none) and asserts each mark is private and research-only. Assert every derivable kind was found;
   log one line per kind. The "trained weights" row takes its expected value from the two inheritance keys
   printed by `frob doctor --json`.
5. `ka_827`: for the replay and a still of the replay, `frob --json artifact list --private` shows both marks
   at each of the three steps, and `cargo run -p frob-chronicle --example marks_audit -- --state <state root>`
   (N37-17's audit) recomputes the whole store with no difference.
6. `views`: as `outsider`, repeat step 1 → `L1`; assert `L1 = L0` response by response. As `agent`, assert
   the shared archive and leaderboard contain no private row and that the explicit private listing shows the
   objects.
7. `reads`: as `outsider`, a direct read of each derived kind by identifier → exit 5, `FROB-REF-731`.
8. `exports_private`: as `agent` (no `private:export`): each exporting verb on a derived artifact → exit 5,
   `FROB-REF-731`, `observed = missing-scope`. As `owner` without the flag → `missing-flag`. With the owner
   key `private.export_allowed = false` (the default) and scope and flag → `export-disabled-by-owner`.
   (The licence refusal is tested separately on a non-private copy in step 10, because the privacy check
   comes first.)
9. `no_private_bytes_in_project`: hash every file beneath the project root and the export root; assert none
   equals a digest of the private closure; search both trees and every log written so far for the canary
   strings; assert zero hits.
10. `licence_battery`: the same room imported without `--private` (so only the licence restricts it) and the
    ten laundering attempts: pack export (expect the scene chapter's pack-time refusal `FROB-REF-310`); run
    bundle; still; replay page; scorecard report over 100 runs with one in the scene; trained policy export;
    memoized comparison; certificate bundle; read-bytes-and-reimport as `redistributable`; a report citing a
    claim over the run (each expect `FROB-REF-733` with a `via` path ending at the asset; the trained-policy
    row takes its expected value from `licence.weights_inherit` as printed by `frob doctor --json`, as in
    step 4: refused under the default, admitted under a recorded option B or D). Then replace the
    asset by a redistributable one, re-derive, and assert every export succeeds; with an `attribution` asset,
    assert the exported report has a Notices section naming it and that two exports are byte-identical.
11. `licence_random_graphs`: `cargo run -p frob-conformance --example marks -- random-graphs --count 10000
    --seed <seed>`; assert zero mismatches between stored marks and the join over ancestors.
12. `purge_dry_run`: as `owner`, first `frob --json study plan <manifest>` with a manifest bound to the
    private pack (save the plan identifier for step 15); then `frob --json scene purge <id>` (dry run by
    default): save the closure digest and counts; assert the counts cover every object of step 3.
13. `purge`: `frob --json scene purge <id> --dry-run=false --confirm <digest>` (`scene.purge` is an `admin`
    verb and takes no idempotency key; the confirm digest guards the call); wait for the job; save the receipt
    digest. Repeat the same call: assert it removes nothing and returns the same receipt digest.
14. `purge_verify`: `cargo run -p frob-conformance --example marks -- scan-digests --receipt <digest>` hashes
    every file under both store roots and reads every ledger row: assert `remaining_digests = 0` (tombstones
    excepted); each removed digest read with `artifact read` is refused; the public scene and its runs are
    untouched (digests and marks equal to before); a citation of a withdrawn claim is refused.
15. `purge_plan_stale` (N32a-13's removed-scene case of `FROB-REF-809`; N37-19): `frob --json session show`
    (budget before); `frob --json study submit <plan of step 12> --key pst-1` → exit 7, `FROB-REF-809`, naming
    the removed scene identity with current identity none; `frob --json session show` again: the budget is
    unchanged (nothing charged).
16. `planted` (builds with `--features gauntlet-mutations`, convention 1; each must make the named step fail): a still writer that drops
    its parents (step 4); a resource list that skips the filter (step 6); a `report` exporter that bypasses
    the export door (step 8 or 10); a purge that follows one level (step 14); a licence class computed as the
    minimum (step 11); and N37-18's two further controls of GATE-SAFE-05, `unknown` treated as permissive
    (step 10, with the asset's class set to `unknown`) and a memo store that drops marks (step 10, the
    memoized-comparison row). Seven builds; each control's identifier from the registry of N37-CX is logged
    with its outcome.
17. `receipt`: `e2e_tier g1_known_answers GATE-SAFE-04 --mutations` and `e2e_tier g1_known_answers
    GATE-SAFE-05 --mutations` (STD-E2E: the tier entries of the two gates run KA-827 and KA-832 with every
    control registered against each gate in the same run); assert on `$E2E_LAST_RECEIPT` with `e2e_get
    --file` that each gate's value is present and every registered control is `caught`. The script records
    nothing (one recorder per gate): BD-305 records both gates with `cargo run -p frob-conformance --example
    record_gate -- --gate <id> --receipt <hash>` from its own run of these tier entries, which needs nothing
    later than BD-305; this script, which depends on BD-305, re-measures them from the user's side, and a
    later re-record may cite its receipts.

**Logging.** `target/e2e-logs/safe_private_licence/<utc-timestamp>.ndjson` and a transcript. Every line:
`ts`, `script`, `bead` (`N37-21`), `step`, `event`, the exact command line, exit code, wall time, the
envelope's `evidence` block, refusal code with `observed`; `metric` lines: `kinds_marked` of `kinds_derivable`
(threshold: equal), `listing_differences` (0), `canary_hits` (0), `graph_mismatches` (0), `battery_refused`
(10 of 10 under the default; the policy row as the option in force states), `remaining_digests` (0). For envelopes marked private the helper logs only the envelope digest,
the refusal or the counts, never the result body. On failure: the kind or step, the object digest, expected
and observed marks, and the saved envelope path under the private root. `summary`: assertions passed and
failed and `gates: ["GATE-SAFE-04", "GATE-SAFE-05"]`. The log is scanned for the canary strings before the
script exits.

## Acceptance criteria

- [ ] On a clean build the script exits 0 and its `receipt` step yields, on the same tier entries BD-305
      records from, the evidence of GATE-SAFE-04 (every derivable kind marked; every export attempt without scope, flag or owner key
      refused; `remaining_digests = 0`) and GATE-SAFE-05 (zero graph mismatches in 10⁴; 10 of 10 laundering
      attempts refused under the default inheritance keys, the policy row otherwise as the recorded
      OPEN-SAFE-2 option states), each receipt with every registered control `caught`; the script writes no
      gate row.
- [ ] After the purge, submitting a plan bound to the purged pack is `FROB-REF-809`, exit 7, naming the
      removed identity, with nothing charged; a repeated purge returns the same receipt.
- [ ] The script passes the `no_conformance_command` lint (BD-025): every harness call is a `cargo run …
      --example` form.
- [ ] `L1 = L0` for the session without the private scope.
- [ ] Zero canary hits in the project tree, the export tree and all logs.
- [ ] Each of the seven planted builds fails at its named step.
- [ ] The purge receipt lists every digest that step 14 checks, and the public scene is untouched.

## Test plan

### Unit tests
`cargo test -p frob-conformance --test marks_helpers`: `sweep_requires_every_derivable_kind`;
`scan_digests_finds_planted_blob`; `canary_scan_finds_planted_string`; `listing_digest_ignores_nothing` (two
listings that differ by one row have different digests); `random_graphs_reports_planted_mismatch` (with the
planted still writer that drops a parent, built with `--features gauntlet-mutations`, 100 graphs give a mismatch count above 0; the clean build gives 0,
and the same seed gives the same graphs); `sweep_expected_value_follows_weights_keys` (the trained-weights row
expects private and research-only under the default and public under option D in a test configuration).

### End-to-end script and logging
This bead is the script. It runs in the ordinary end-to-end suite from M3 (with a shortened training step)
and, at the M3 exit, to re-measure the two gates from the user's side beside BD-305's record.

### Known answers and negative controls
KA-827 (private and research-only at every step of the three-step derivation; exact; control: an export
without the flag is refused and after `scene.purge` no digest of the closure remains) and KA-832 (licence set
equals the join; a research-only asset cannot enter an exported report or pack; exact). Negative controls:
the seven planted builds. Metamorphic relations: swapping the order of steps 3's derivations changes no mark;
for the outsider session the surface is identical with and without the private scene. Determinism lanes: marks,
refusals and the closure digest identical for the same seed twice on one machine and on Linux and macOS.

## Considerations

- The fixture is a stand-in: real-place ingestion arrives at M5 and re-runs this script on a real twin
  package under the same assertions, with the capture never leaving the private root.
- The training step is the slowest; under the default compute envelope it is a few hundred updates on
  `batch-cpu`, enough to produce a checkpoint whose mark can be tested.
- Canary strings test logs and trees for content leaks; they do not prove absence of every derived bit, which
  is why the hash scan over the closure is also run.
