## Background

The second asset of the threat model is evidence, and one of its threats is a stale or forged artifact. A
result is only as trustworthy as the code that produced it, so the build itself has rules: exact pins;
admission records with real build evidence; kernel caches checked by content hash before load.

GATE-SAFE-06 (Known answer, TARGET; the gate register dates it to M2): **one `asupersync` package per
workspace; all lockfiles committed; a kernel cache entry with one flipped byte is refused; `frob-verify`
builds with no dependency outside the standard library.** Invariant INV-SAFE-08: each workspace resolves
exactly one `asupersync` package, and no kernel loads without a matching content hash.

Why each clause exists.

- *One runtime package.* `asupersync` is the suite's asynchronous runtime; two copies in one program are two
  runtimes with separate cancellation trees and timers, and types from one do not unify with the other. FACT
  (2026-11-21): `fastmcp_rust` (the suite's MCP library) pins 0.6.2 in its source tree while its registry
  package 0.13.0 carries 0.5.0; FrankenTorch requires 0.6.2; FrankenSim consumes it by path; the optional
  executor feature of `ftui-runtime` (FrankenTUI) and FrankenThreeD's `f3d-runtime` pin 0.5.0. The rule
  decides which form of each sibling may be linked (`fastmcp_rust` by commit, never its registry package; the
  executor feature off; `f3d-runtime` never linked in the core).
- *Committed lockfiles.* A build that resolves fresh versions is a different program from the one that was
  tested.
- *Cache integrity.* A binary kernel cache is keyed by source hash, compiler, driver and hardware fingerprint
  and is checked by content hash before load; a mismatch recompiles and is logged. A cache directory may be
  copied between hosts, so its contents are untrusted bytes until hashed.
- *A standard-library-only auditor.* `frob-verify` checks certificate bundles; if it shared a dependency with
  what produced them, one defect could make both agree.

The mechanisms already exist by M2 in other beads (the workspace checks, the asupersync alignment, the
auditor crate, the kernel cache). This bead is the gate's measurement on the running tree at M2, with its
negative controls, so that the M2 exit review has a recorded value. The remaining supply-chain rules
(admission-record completeness, exact pins, viewer vendoring, no local patches) and the M3 re-record are the
seed bead BD-306.

## Scope

In: the script; an independent recomputation of each clause (not merely calling the workspace checks); the
four negative controls; the `cache_check` example of the kernel-cache crate; recording the M2 part of the gate
from the script's tier receipt. Out: implementing the checks (workspace and suite beads); the
cache (device chapter); the auditor (certificate chapter); the M3 rules (BD-306).

## Technical approach

`scripts/e2e/safe_supply_chain.sh [--device cuda|metal|none]` (plain shell; sources the shared helper of
STD-E2E; idempotent; scratch copies live under `target/e2e/safe_supply_chain/<run>/`; it never edits a
tracked file and never touches a sibling checkout).

Steps:

1. `workspaces`: list every tracked `Cargo.toml` that declares `[workspace]` (`git ls-files`), plus the
   auditor crate's standalone manifest; compare the list with the workspace list of `franken-stack.lock`.
   Assert equality (a workspace missing from the lock, or listed and absent, fails).
2. `one_runtime`: for each workspace, `cargo metadata --locked --format-version 1`; from the `resolve` graph
   count packages named `asupersync` and collect their versions. Assert: at most one per workspace; exactly
   one in every workspace the stack lock marks as consuming it; the same version in all of them, equal to the
   lock's `FD-ASUP` version; no package `asupersync` at 0.5.0 anywhere; and, for every binary target,
   `cargo tree -d --locked -p <bin>` prints no duplicate `asupersync`. Then run the workspace check
   (`cargo xtask check-deps`) and assert it agrees.
3. `lockfiles`: for each workspace, `git ls-files --error-unmatch <dir>/Cargo.lock` (tracked, not ignored);
   run `cargo metadata --locked` and `cargo build --locked -p <a small member>`; assert `git status
   --porcelain` shows no change to any lockfile; assert the BLAKE3 of each lockfile equals the newest
   resolution receipt's entry. Then `cargo xtask check-stack` must agree.
4. `auditor_std_only`: `cargo tree --locked --manifest-path crates/frob-cert/Cargo.toml` prints exactly one
   line; `cargo metadata` for it lists one package and no dependency of any kind (normal, build or
   development); copy the directory alone to the scratch area and `cargo build --release --offline` there on
   its own stable toolchain file. Assert success and that the binary `frob-verify` runs `--version`.
5. `cache_flip` (device hosts): `frob --json spark precompile <arch> --key pc-1` for the reference step plan;
   choose one cache entry (the first in key order); record its key, digest and size; copy it aside; flip one
   bit of the byte at offset ⌊size/2⌋ in place; run `frob --json sim run --key cf-1` on the built-in fixture
   that needs that kernel (each `run` call carries its own `--key`; the second run below uses `cf-2`). Assert:
   the envelope is `ok`; `warnings` or the job log holds one event `kernel-cache-mismatch` with the key, the
   expected digest and the observed digest; the entry on disk now has the correct digest again (recompiled);
   the run's state digest equals the digest of the same run before the flip. Then flip again and run with
   recompilation disabled by the offline switch of the cache module's test configuration: assert exit 6 with
   `FROB-REF-612` (kernel cache entry corrupt and recompilation unavailable) and that nothing was launched.
   On a host with `--device none` the same two cases run against the cache module with a `synthetic` entry
   through `cargo run -p frob-kernels --example cache_check -- --dir <scratch cache> [--offline]`, and the
   device rows of the gate's value are `not run` (which is not a pass). The example is declared here (BD-025's
   rule: a driver whose code lives in another crate is an example of that crate; there is no
   `frob-conformance` binary): `crates/frob-kernels/examples/cache_check.rs`, a thin argument parser over
   N21b-12's `KernelCache` lookup that writes one `synthetic` entry into the scratch directory, flips one bit
   of the byte at offset ⌊size/2⌋, performs the checked lookup, and prints one JSON object (key, expected and
   observed digests, `loaded`, `moved_to_corrupt`, `recompiled`, and under `--offline` the refusal code
   `FROB-REF-612` with exit 6); it exits non-zero if the flipped entry was loaded.
6. `controls` (scratch copies only):
   1. Copy the core workspace manifest and lockfile; add a second `asupersync` at another version through a
      renamed dependency; run the step-2 logic on the copy → must report two packages.
   2. Copy an annex workspace without its `Cargo.lock` → step-3 logic must fail on "not tracked".
   3. The flipped byte of step 5 is the third control: a `mutants` build whose loader skips the digest
      comparison must load the flipped entry, and the script must detect that no mismatch event was logged.
   4. Copy `crates/frob-cert`, add one registry dependency to its manifest → step-4 logic must report more
      than one line.
7. `receipt`: `e2e_tier g1_known_answers GATE-SAFE-06 --mutations` (STD-E2E); the tier entry of the gate runs
   KA-833 and the controls registered against the gate in one run and re-checks the measured values this
   script saved by digest: workspaces (count), asupersync packages per workspace (all 1) and the version,
   lockfiles tracked (n of n), auditor dependency count (0), cache flip refused and recompiled (per device
   family, or `not run`), controls caught (4 of 4). Assert on `$E2E_LAST_RECEIPT` with `e2e_get --file` that
   the gate's value is present and each control is `caught`. The script records nothing.

**Recording.** One recorder per gate, by milestone part: this bead records the M2 part of GATE-SAFE-06 from
that receipt with `cargo run -p frob-conformance --example record_gate -- --gate GATE-SAFE-06 --receipt
<hash> --part M2`, in a session that did not implement the checks being measured; BD-306 records the M3
part from the receipt of the M3 re-run.

**Logging.** `target/e2e-logs/safe_supply_chain/<utc-timestamp>.ndjson` and a transcript. Every line: `ts`,
`script`, `bead` (`N37-22`), `step`, `event`, the exact command line, exit code, wall time; `metric` lines per
workspace (`asupersync_packages`, threshold exactly 1 or at most 1; `lockfile_tracked`; `lockfile_hash`),
`auditor_packages` (threshold 1), and for the cache: key, expected and observed digests, `recompiled`,
`state_digest_before`, `state_digest_after`. For verb calls the envelope's `evidence` block is logged. On
failure: the workspace, the two versions or the differing digest, and the saved `cargo metadata` output path.
`summary`: assertions passed and failed and `gates: ["GATE-SAFE-06"]`.

## Acceptance criteria

- [ ] On the M2 tree the script exits 0 and its receipt carries GATE-SAFE-06's value, from which this bead
      records the M2 part: exactly one `asupersync` package in each consuming workspace at one version; every
      lockfile tracked and unchanged by a locked build; the flipped cache entry not loaded, logged and
      recompiled on each device family present; `frob-verify` built from a bare copy with zero dependencies.
- [ ] The script passes the `no_conformance_command` lint (BD-025); the `cache_check` example refuses the
      flipped `synthetic` entry (exit non-zero if it was loaded).
- [ ] Each of the four controls is caught.
- [ ] The script's own counts agree with `xtask check-deps` and `check-stack`; a disagreement fails the
      script (the checks and the independent recomputation guard each other).
- [ ] No tracked file and no sibling checkout is modified (`git status --porcelain` empty at the end, apart
      from files under `target/`).
- [ ] Device rows that could not run are recorded `not run`, never `pass`.

## Test plan

### Unit tests
`cargo test -p frob-conformance --test supply_chain_helpers`: `count_runtime_packages_from_metadata` (a
`synthetic` metadata document with two versions → 2); `lockfile_must_be_tracked`; `flip_one_bit_changes_digest`
(BLAKE3 of the entry before and after differ); `cache_check_refuses_flipped_synthetic_entry`.

### End-to-end script and logging
This bead is the script. It runs in the ordinary end-to-end suite with `--device none` and, for the gate, on
the training machine (`cuda`) and on the Mac (`metal`).

### Known answers and negative controls
KA-833 (supply chain: one `asupersync` package per workspace; all lockfiles committed; `frob-verify` builds
with no dependency outside the standard library; exact; tier G1, host; control: a kernel cache entry with one
flipped byte is refused). Known answer adopted from the workspace chapter: the dependency tree of the auditor
crate prints one line. Negative controls: the four of step 6. Determinism lanes: the script's counts and the
lockfile hashes are identical on Linux and macOS; the cache flip is run per device family.

## Considerations

- "Refused" for a flipped entry means never loaded: with a compiler available the entry is a miss and is
  recompiled; without one the run refuses with the device chapter's code. Both cases are measured.
- The independent recomputation exists because a gate that only calls the check it is gating would pass when
  the check is broken.
- If the MCP library cannot be brought onto one runtime version within its own budget, the fallback puts the
  MCP adapter in its own workspace; the rule "one package per workspace" still holds there and step 1 picks
  the new workspace up from the stack lock.
- The run touches the network only if a locked build needs to download a crate already named in a lockfile;
  on the build-offload shim this is the worker's concern, and `--offline` is used for the auditor copy.
