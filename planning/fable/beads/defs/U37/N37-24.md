## Background

The capability under test, from the user's side: whatever an agent exports from the system (a run bundle, a
certificate bundle, a design view, a controller, a report, a replay, a policy), the file says in
machine-readable form that it authorizes nothing: `execution_authorized`, `hardware_safety_signoff` and
`sim_to_real_certified` are each the constant `false` (a build packet adds `fabrication_released`). If
someone edits a flag to `true` or strips the fields, the system's own readers and the offline auditor refuse
the file; absence is never read as false.

GATE-SAFE-01 (Known answer, TARGET): every artifact produced by every exporting verb carries the three
fields, all `false`; negative control: an artifact edited to `true`, and one with the fields removed, are each
refused by the importer and by `frob-verify`. The gate register dates it to M1 and lists it among the four
gates re-run at every milestone exit. This script is that measurement. It is driven by the export locator
registry, so each milestone's run covers exactly the exporters that exist then.

## Scope

In: the script with its milestone profiles; fixtures; the sweep; the three mutants per kind; the
produce-true attempts; logging; the gate record. Out: the type, schemas, registry and reader check (N37-23);
the M3 rows and banner (BD-303).

## Technical approach

`scripts/e2e/safe_flags.sh [--profile m1|m2|m3|current]` (plain shell; sources the shared helper of STD-E2E;
idempotent; a fresh project, state root and export root under `target/e2e/safe_flags/<run>/`; `current`, the
default, uses every locator row whose `since` is at or before the build's milestone as printed by
`frob capabilities --json`).

Steps:

1. `threat_register`: run the threat-register traceability test; log one line per threat row.
2. `rows`: `frob schema --exports --json` lists (verb, kind, carrier, pointer, spelling, flag count) from the
   locator registry. Assert every verb whose registry entry has `exports` appears, and that the list is
   non-empty.
3. `fixtures`: create what the exporters need from built-in fixtures: a template design, a referee run of the
   built-in mechanism, a synthesized baseline controller, an M0 certificate, and (from the profile `m2`
   onward) a short trained policy, stills and a replay; (from `m3`) a report, a verdict, a qualification
   receipt from a test campaign, a minimal counterexample world.
4. `export_all`: for each row, call the verb so that it writes under the export root (`--out` relative to the
   export root; an idempotency key where required) and save the envelope. Assert exit 0 or 2 and that the
   envelope has `authorization` with exactly three `false` members.
5. `sweep`: `frob-conformance flags sweep --export-root <dir> --envelopes <dir>`: walks every file written,
   classifies it by the registry, reads the carrier (manifest pointer, header, container metadata, sidecar
   and embedded comment or text chunk) and asserts the object is present, has exactly the expected member
   names and each value is the JSON literal `false`. A file that matches no row fails. Output: one line per
   artifact.
6. `banner` (from `m3`): every rendered report form and the replay page contain the banner sentence; the
   human-readable output of each exporting verb begins with it.
7. `mutants`: for each artifact kind, `frob-conformance flags mutate` writes three copies: `true` (one flag
   set to true, chosen in rotation so that all three flags are covered across kinds); `stripped` (the object
   removed; for a sidecar kind, the sidecar deleted); `stringy` (one value replaced by the string `"false"`).
   Each copy is offered to the kind's importing verb (`artifact read` or the kind's own load path, with
   `--json`): assert exit 3 and `refusal.code = FROB-REF-816` with `observed` naming the fault and the field.
   For bundle kinds each copy is also given to the standalone auditor: `frob-verify <file>`: assert a
   non-zero exit and a `reject` verdict whose rule names the flag fault (the auditor's own code). Hashes that
   the mutation invalidates are recomputed by the mutator, so the refusal is for the flags and not for a hash.
8. `produce_true`: for three exporting verbs, attempt `--authorize`, `--execution-authorized=true`, and a JSON
   request member `"execution_authorized": true`; assert `FROB-REF-802` for each, then export normally and
   assert three `false`.
9. `planted` (builds with feature `mutants`; each must fail the named step): an exporter that omits the
   object (step 5); one that writes `true` (step 5); a reader that treats absence as false (step 7: the
   `stripped` copy is accepted and the script reports it); an exporting verb with no locator row (step 2).
10. `record`: write GATE-SAFE-01's measured values for this milestone through the conformance harness:
    verbs swept, artifact kinds, artifacts inspected, violations (0), mutants offered and refused per reader,
    controls caught, the profile.

**Logging.** `target/e2e-logs/safe_flags/<utc-timestamp>.ndjson` and a transcript. Every line: `ts`,
`script`, `bead` (`N37-24`), `step`, `event` (`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact
command line, exit code, wall time, the envelope's `evidence` block (claim, class, tier, determinism,
identities, seed); per artifact a line with `kind`, `digest`, `carrier`, `pointer` and the values found; per
mutant a `refusal` line with the reader, the code and `observed`; `metric` lines `violations` (threshold 0),
`mutants_refused` of `mutants_offered` (threshold: equal). On failure: the first artifact or mutant that
broke the rule, with its path. `summary`: assertions passed and failed and `gates: ["GATE-SAFE-01"]`.

## Acceptance criteria

- [ ] At the M1 exit, `safe_flags.sh --profile m1` exits 0 and records GATE-SAFE-01 for the M1 exporters
      (`artifact.export`, `run.export`, `design.export`, `prove.bundle`, `control.show --export`): zero
      violations; every `true`, `stripped` and `stringy` mutant refused by the importer, and by `frob-verify`
      for bundles.
- [ ] The same script with `--profile current` is run and recorded at every later milestone exit, covering
      that milestone's exporters.
- [ ] All three flags are covered by a `true` mutant in each run (the rotation is logged).
- [ ] Each of the four planted builds is caught at its named step.
- [ ] A stray file under the export root that matches no locator row fails the sweep.

## Test plan

### Unit tests
`cargo test -p frob-conformance --test flags_helpers`: `mutator_recomputes_hashes` (the `true` mutant of a
certificate bundle still has consistent hashes, so the auditor rejects it for the flag rule);
`rotation_covers_three_flags`; `sweep_fails_on_unmatched_file`; `sweep_reads_each_carrier` (manifest, header,
container metadata, sidecar).

### End-to-end script and logging
This bead is the script. It is part of the ordinary end-to-end suite from M1 and is the recurring gate's
measurement at every exit review.

### Known answers and negative controls
KA-828 (an artifact with one no-authorization flag set to `true` is refused by the importer and by
`frob-verify`; exact, verdict; tier G0; control: an artifact with the fields removed is also refused).
Negative controls: the four planted builds, registered against GATE-SAFE-01. Metamorphic relation: exporting
the same object twice gives byte-identical flags objects and identical sweep lines. Determinism lanes: the
sweep's output is identical in debug and release and on Linux and macOS; the auditor's verdicts are identical
for the standalone binary and the in-tree verb.

## Considerations

- The script takes minutes at M1 and grows with the surface; the training fixture of profile `m2` is a few
  hundred updates on the CPU tier, enough to produce a policy file.
- The auditor is run as the standalone binary built from the bare crate directory, so that the refusal does
  not depend on any code that produced the artifact.
- If a kind's importer does not exist yet at a milestone (a kind that can be written but not yet read back),
  its mutants are offered to `artifact read`, which applies the shared reader check by format.
