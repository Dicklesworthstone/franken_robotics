## Background

The capability under test, from the user's side: every answer the system gives says how strong it is, and
that statement is the weakest of everything the answer rests on. An agent cannot get a stronger label by
choosing which input to mention, by going through a cache or an aggregate, or by handing a weak result to a
verb that needs a strong one.

The smallest case is the script's spine: design A was evaluated on the referee and design B on a fast tier,
still provisional. A "majority" or "best input" rule would label their comparison established; the claim
product labels it provisional. Offering that comparison where an established result is required is refused
(`FROB-REF-819`); after B's result is promoted the same call is admitted.

Gate measured: GATE-SAFE-08 (Known answer, TARGET): over random sets of input evidence the envelope's class
equals the meet; no public function returns a stronger class than its inputs. The script and its profile
`m1` (random sets through the conformance verb, the smallest case, the API scan; the M1 record) are created
by the M1 bead N37-25. This bead adds profile `m3`: the same campaign on real results of the full surface,
the citation steps, reports, the memo store, bundles, and the full-surface record.

## Scope

In: the script with two profiles; fixtures; the random-set campaign through `frob`; the smallest case; the
citation and report steps; the bundle recomputation; planted defects; logging; the gate record. Out: the
mechanisms (N37-25, BD-308, N37-26).

## Technical approach

`scripts/e2e/safe_claim_boundary.sh [--profile m1|m3] [--seed N] [--sets 10000]` (plain shell; sources the
shared helper of STD-E2E; idempotent; a fresh project and state root under
`target/e2e/safe_claim_boundary/<run>/`; the daemon on `batch-cpu`, plus a device where one is present).

Steps:

1. `random_sets` (both profiles): `frob-conformance claim-sets generate --seed <seed> --count <sets>` stores
   the leaf results (in profile `m1`, synthetic leaves through the conformance doorways; in `m3`, real
   results of the surface: referee runs, `batch-cpu` runs, device runs, analyses, a certified kernel identity,
   assumed and measured card fields, a study, a promoted result). For each set the helper calls
   `frob --json conformance combine --kind <k> <refs…>` (a conformance build) and, in `m3`, the real
   aggregating verb where the set's shape allows (`eval compare`, `study compare`, `eval scorecard`,
   `explain compare`, `report run`). `frob-conformance claim-sets check` compares every member of each
   envelope's `evidence` block with the independent oracle. Assert zero mismatches.
2. `smallest_case`: create designs A and B from a template with one typed edit between them; `eval run A
   --tier referee`; `eval run B --tier batch-cpu`; `eval compare A B` reading both stored results. Assert the
   comparison's `evidence`: class `Tested`, tier `batch-cpu`, `standing: provisional`, `weakest` pointing at
   B's run, `non_claims` containing `reality: no-claim`; and that `next_actions[0].command` is the promote
   command for B's result.
3. `cite_provisional` (`m3`): offer the comparison to a consumer that requires established evidence (the
   leaderboard submission and, where present, the build-packet evidence argument). Assert exit 3,
   `refusal.code = FROB-REF-819`, `observed: provisional`, `required: established`, the `weakest` reference,
   first repair the promote action; assert the session's budget is unchanged and one refused-citation row
   exists in the ledger.
4. `promote_then_cite` (`m3`): `eval promote` on B's result (a handful of referee episodes); re-run
   `eval compare`; assert `standing: established`, tier now the adjudicator's; repeat step 3's calls; assert
   they are admitted.
5. `worked_case` (`m3`): a comparison that consumes a certified kernel identity, a card whose friction field
   is `assumed`, and a paired study under determinism class D2 on a fast tier. Assert class `Estimated`,
   `weakest` = the card's friction field path, standing provisional, reality `no-claim`, and that the first
   next action is the registered measurement action for that field.
6. `report_wording` (`m3`): `frob report run` on the provisional comparison: assert the rendered sentence
   uses the Design-comparison wording with its evidence and study identifier, prints `provisional`, and
   contains neither "established" nor "verified"; a conformance template that states `established` is
   refused and no report file is written.
7. `memo_and_aggregate` (`m3`): repeat step 2's comparison (served from the memo store): identical
   `evidence`; build a scorecard over 100 runs of which one has an Estimated input: class `Estimated`.
8. `bundle` (`m3`): `frob prove bundle` for a result with a certificate; `frob-verify <bundle>` accepts; two
   mutants (the stored class raised one step; one input removed, with hashes made consistent) are each
   rejected with the auditor's rule for a result presented above its weakest input.
9. `api_scan`: `frob-conformance evidence-functions scan` over the workspace's documentation JSON: assert no
   public function with evidence in and out lacks a passing property, and leaf constructors equal the doorway
   list.
10. `planted` (builds with feature `mutants`; each must fail the named step): `combine` takes the maximum
    class (step 1); standing by majority (step 2); a handler that drops one input (step 1, `m3`); an `admit`
    that compares only the class (step 3); a memo store that returns values without products (step 7).
11. `record`: GATE-SAFE-08's measured values for the profile: sets, mismatches (0), verbs exercised, bundle
    mutants rejected, functions scanned and missing properties (0), controls caught.

**Logging.** `target/e2e-logs/safe_claim_boundary/<utc-timestamp>.ndjson` and a transcript. Every line: `ts`,
`script`, `bead` (`N37-27`), `step`, `event`, the exact command line, exit code, wall time, and the
envelope's full `evidence` block (kind, class, tier, determinism, standing, reality, conditions, claims,
non-claims, weakest, identities, seed). For step 1: `metric` lines `sets` and `mismatches` (threshold 0) and,
on a mismatch, the set's leaves with their blocks, the oracle's block, the observed block and the first
differing member. For steps 3 and 4: the requirement, the failing member, the code and the repairs. For step
8: the auditor's verdict and rule per file. `summary`: assertions passed and failed and
`gates: ["GATE-SAFE-08"]`.

## Test plan

### Unit tests
`cargo test -p frob-conformance --test claim_sets_helpers`: `generator_is_seeded_and_stable`;
`check_reports_first_differing_member`; `real_leaf_catalogue_covers_every_tier_present`.

### End-to-end script and logging
This bead is profile `m3` of the script (profile `m1` exists from M1). Both run in the ordinary suite; the
full-surface gate record is taken at the M3 exit by a session that did not implement the mechanisms.

### Known answers and negative controls
KA-829 (the product of {Tested on the referee, Tested and provisional on a fast tier} is provisional; over
random sets the envelope's class equals the meet; exact; tier G0; control: a public function that returns a
stronger class than its inputs). Negative controls: the five planted builds. Metamorphic relations: swapping
A and B changes the sign of the comparison and nothing in `evidence`; permuting the leaves of a set changes
nothing. Determinism lanes: the campaign is identical for the same seed twice on one machine, across worker
counts, in debug and release; referee and `batch-cpu` leaves are bitwise repeatable in their classes; device
leaves are compared within their class.

## Considerations

- The promotion step needs a few referee episodes and is the slowest part; under the default compute envelope
  the whole script fits in minutes on the built-in fixture.
- On a host with no device the fast tier is `batch-cpu`, which is enough for the smallest case; device leaves
  are added on the machines that have them and recorded per device family.
- Profile `m1` uses the conformance verb for combination because few M1 verbs aggregate stored results; the
  gate's meaning is the same, and the M3 profile replaces the synthetic leaves with real ones.
