## Background

Every artifact this system exports carries three fields, each the constant `false`: `execution_authorized`,
`hardware_safety_signoff`, `sim_to_real_certified` (a build packet adds `fabrication_released`). They say in
machine-readable form that no result of this project is permission to run hardware, a safety sign-off, or a
statement about a physical robot. In code they are one type with a single value (ADR-SAFE-01: a boolean can be
set, a constant cannot). A reader that meets `true`, or an artifact of ours without the fields, refuses it
(`FROB-REF-816`, exit 3); absence is not read as false. Gate GATE-SAFE-01 (Known answer, TARGET): every
artifact produced by every exporting verb carries the three fields, all `false`; an artifact edited to `true`
and one with the fields removed are each refused by the importer and by `frob-verify`. The gate is dated M1
and is one of the four gates re-run at every milestone exit.

The type, the schema fragment, the locator registry `registries/exports.toml`, the shared reader check and
the M1 rows exist from M1 (N37-23). The second milestone adds three exporters whose artifacts are not
canonical-JSON manifests: `train.export` writes a policy checkpoint (a binary tensor container),
`telemetry.stills` writes PNG images, and `telemetry.export-html` writes a self-contained HTML replay page.
Without locator rows for them, N37-23's registry test fails the day they are registered and the M2 exit's
re-run of GATE-SAFE-01 (`safe_flags.sh --profile m2`, N37-24) cannot pass. The same milestone adds one
operator diagnostic file under the export root, the resolved randomization lists that `sim.run --resolved-out`
writes as JSON lines (BD-200); it is an export like any other (N37-18 decides that diagnostic writers have no
exception) and needs a row too. This bead supplies those rows and
carriers at M2, and with them the two pieces that later artifact kinds need and that do not depend on the
third milestone's exporters: the banner text generated from the type, and the locator contract rows for the
kinds of M4, M5 and M8. It was split from the seed BD-303, which keeps the third milestone's exporters, the
report template lint and the M3 record; beads of later kinds (the skill artifact, the energy budget file, the
build packet and its checker, the replication kit) need only this bead's contract, not the M3 sweep.

## Scope

In: locator rows and carriers for `train.export`, `telemetry.stills`, `telemetry.export-html` and the
diagnostic file of `sim.run --resolved-out`; the
container-metadata carrier for binary containers; the image carrier; the banner generator and its use on the
replay page and in the human-readable output of every exporting verb that exists at M2; contract rows for the
later kinds; mutants for the three M2 kinds; GATE-SAFE-01 at the M2 exit. Out: the type, schema fragment,
reader check and M1 rows (N37-23); the M3 rows, the report-template lint and the M3 record (BD-303); the
sweep script and its profiles (N37-24); the writers of the later kinds (N22b-01, N22b-10, BD-408, N31a-37,
BD-396, N39b-18) and the auditor's packet checker (N31b-44), which read this bead's contract rows; the
weight-admission door that re-reads checkpoints (N37-07).

## Technical approach

1. **Rows for the M2 exporters** (`registries/exports.toml`, the row layout of N37-23: verb, kind, format,
   carrier, pointer, name, flags, since):
   | Verb | Kind | Carrier | Pointer and place |
   |---|---|---|---|
   | `train.export` | policy checkpoint | `embedded-metadata` and `manifest` | the container's metadata map key `frob.authorization/1`; `/authorization` in the `frob.policy/1` manifest |
   | `telemetry.stills` (written under the export root) | still or contact sheet (PNG) | `sidecar` | `<name>.frob.json` at `/authorization` |
   | `telemetry.export-html` | replay packet (HTML) | `header` | `/authorization` in the canonical-JSON header block at the top of the file, with the string member `banner` beside the three flags (step 4) |
   | `sim.run` with option `resolved_out` | `diagnostic` (resolved randomization lists, JSON lines) | `header` | `/authorization` in the first line, a canonical-JSON object of schema `frob.diag-header/1` (DESIGN, N37-18); every later line is a data record |
   Each row has `since = "M2"` and `flags = 3`. The diagnostic header at M2 holds `schema`, `kind` and
   `authorization`; the export door of N37-18 adds `privacy`, `licences` and `notices` to it at M3, when marks
   exist, and the row does not change. Each of these verbs also returns `authorization` in its
   envelope (N37-23's schema fragment, already generated for every exporting verb).
2. **Container-metadata carrier.** A binary container with a string-to-string metadata map (the checkpoint
   container of N23a-13) stores the canonical JSON of the flags object, exactly
   `{"execution_authorized":false,"hardware_safety_signoff":false,"sim_to_real_certified":false}`, as the
   value of the one registered key `frob.authorization/1`. The trainer writes the key into every checkpoint
   it writes, mid-run or exported, so that a stored checkpoint and its export are the same bytes (the
   weight-admission door of N37-07 recognizes a checkpoint of this system by that digest and requires the
   key on it). Reading a checkpoint of this system (on load, on
   `artifact.read`, and in the re-admission of N37-07) extracts that value, parses it and calls the shared
   check `frob_core::auth::check_carried`; a missing key, `true`, a string `"false"` or an extra member is
   `FROB-REF-816` before any tensor is read. The key and the manifest must agree; a disagreement is reported
   as `Missing` for the carrier that lacks the object.
3. **Image carrier (DESIGN).** A still carries its flags only in its sidecar `<name>.frob.json` (schema name,
   the PNG's BLAKE3, the stack receipt hash, the flags), written in the same atomic export. The PNG gets no text
   chunk. Reason: the stills verb (BD-191) fixes an in-tree encoder that writes no text chunk so that a still
   is byte-identical across encodes and the exported file equals the stored artifact whose digest the sidecar
   and the lineage name; a chunk added at export would make the exported bytes differ from that digest. A
   PNG offered as ours without its sidecar is `FROB-REF-816` (`Missing`); it can still be imported as foreign
   data. An earlier draft of BD-303 named a text chunk `frob:authorization`; it is withdrawn for this reason.
4. **The banner (DESIGN text, generated from the type so that it cannot drift).**
   `Simulation results are not a safety case for a physical robot. execution_authorized: false ·
   hardware_safety_signoff: false · sim_to_real_certified: false`
   and, for a type with the fourth field, `· fabrication_released: false` appended. The generator is one
   function `frob_core::auth::banner(&NoAuthorization) -> &'static str` (and its packet twin), whose output is
   pinned by a golden file. It is printed as the first line of the human-readable (non-`--json`) output of
   every exporting verb. The replay page cannot call the function, and a copy of the sentence in the page's
   script could drift, so the sentence travels in the packet: the exporter of `telemetry.export-html`
   (N24a-41's writer, which reserves the member and does not emit it) writes the packet header's member
   `/authorization/banner` with the value `frob_core::auth::banner(&NO_AUTHORIZATION)` into every packet,
   and the page (N32b-40, which reserves line 1 of its always-visible banner for it) shows that string
   verbatim as line 1; the viewer's own short summary, "authorizes nothing: execution, hardware safety,
   sim-to-real: all false", stays beside it as line 2. The page and its bundle (N32b-13) hold no copy of the
   sentence. The same golden file pins the member's bytes. The replay header's schema is N37-23's flags
   fragment with this one added property, `"banner": {"const": <the generated sentence>}`, generated from
   the same function; the reader of the replay header takes `banner` out before calling `check_carried` on
   the three flags and admits it only when it is a string equal to the generated sentence; any other value
   (a different string, a non-string, an empty string) is `FROB-REF-816` with the fault `Extra { field:
   "banner" }`. A packet without the member (none is written after this bead lands) passes the flags check
   and shows the short summary alone (N32b-40). The banner cannot be removed by an option. Report forms use
   the same generator from M3 (BD-303).
5. **Contract rows for later kinds** (written now with `since` set to their milestone, so that N37-24's sweep
   expects them the day the verb is registered, and each writer bead implements to a row that already
   exists): the skill artifact `.fskill` (M4; `header`); the energy budget `.fenergy` (M4; `header`); the
   build packet `.fbuild` (M5; `flags = 4`; manifest root and each generated drawing and bill-of-materials
   header; its reader refuses with the manufacturing chapter's code `FROB-REF-860`, and the auditor with its
   own); the replication kit (M5; `manifest`); the firmware export (M8, Moonshot; a constant in the generated
   crate, `pub const AUTHORIZATION: NoAuthorization`, and its manifest). For the firmware export the row also
   records the boundary the safety chapter sets: the generated code compiles only against hardware
   interfaces the caller supplies and never addresses a register, a bus socket or an emergency-stop relay; a
   source scan of the generated crate for register access, bus-driver or stop-circuit code is part of that
   bead's acceptance.
6. **GATE-SAFE-01 at the M2 exit.** `scripts/e2e/safe_flags.sh --profile m2` (N37-24, the script's owner)
   sweeps the M1 and M2 rows, offers the `true`, `stripped` and `stringy` mutants of each M2 kind to its
   reader (checkpoint load, `artifact read` for stills and the replay page, `frob-verify` for the diagnostic
   file) and ends with its receipt step (`e2e_tier g0_laws GATE-SAFE-01 --mutations`), whose value holds:
   exporting verbs swept (n of n), kinds, artifacts inspected, violations (0), mutants refused (3 per kind),
   banner present (n of n human-readable exporter outputs and the replay page's header member), controls
   caught. The script records nothing. This bead is the one recorder of the gate's M2 part: a session that
   did not implement the carriers records it from that receipt with `cargo run -p frob-conformance --example
   record_gate -- --gate GATE-SAFE-01 --receipt <hash> --part M2`; the record cites this bead and N37-24.

Determinism class D0 for every carrier; the flags object's canonical bytes are identical in every kind.

## Acceptance criteria

- [ ] `registries/exports.toml` has rows for `train.export`, `telemetry.stills`, `telemetry.export-html` and
      `sim.run --resolved-out` with `since = "M2"`; N37-23's registry test passes on the M2 registry.
- [ ] The first line of a file written by `sim.run --resolved-out` is the `frob.diag-header/1` object with the
      three fields `false`; with that line removed, or a field set to `true`, `frob-verify` refuses the file
      with `FROB-REF-816`.
- [ ] A checkpoint exported by `train.export` carries the flags under `frob.authorization/1` and in its
      manifest; with the key removed, set to `true`, or set to the string `"false"`, loading it as a
      checkpoint of this system is `FROB-REF-816`, exit 3, and no tensor is read.
- [ ] A still exported under the export root has its sidecar and no PNG text chunk; the PNG's bytes equal the
      stored still's; the PNG without its sidecar, offered as ours, is `FROB-REF-816`.
- [ ] The human-readable output of each M2 exporting verb begins with the generated banner; every replay
      packet's header carries `/authorization/banner` equal to it, which the page shows as line 1; the banner
      equals the golden file; the page bundle holds no copy of the sentence; a header whose `banner` member is
      altered is `FROB-REF-816`.
- [ ] Contract rows exist for `.fskill`, `.fenergy`, `.fbuild` (four flags), the replication kit and the
      firmware export, each with its milestone and carrier.
- [ ] GATE-SAFE-01's M2 part recorded by this bead at the M2 exit, from the receipt of `safe_flags.sh
      --profile m2`, with zero violations and every mutant refused.

## Test plan

### Unit tests
`cargo test -p frob-verbs --test exports_m2 -p frob-core --test auth_banner -p frob-learn --test
checkpoint_flags` (real writers, real files in a temporary export root; no mocks):
- `m2_exporters_have_rows`: generated from the M2 registry; a planted fourth M2 exporter with `exports = true`
  and no row fails naming it.
- `policy_container_metadata_flags`: export a 3-update CPU-trained policy (synthetic task fixture); the
  container's metadata value under `frob.authorization/1` equals the 92-byte canonical string above.
- `policy_container_mutants_refused`: key removed → `Missing`; `true` → `True { field }`; `"false"` →
  `NotFalse`; each `FROB-REF-816` before tensor bytes are touched (the reader's trace shows no tensor read).
- `still_sidecar_only`: the exported PNG has no `tEXt`, `iTXt` or `zTXt` chunk; its BLAKE3 equals the stored
  artifact's and the sidecar's `blake3` field.
- `still_without_sidecar_refused`.
- `replay_header_flags`: the header block's `/authorization` holds the three `false` members; a page with the
  header member set to `true` is `FROB-REF-816` from `artifact read`.
- `banner_is_generated_and_golden`: `banner(&NO_AUTHORIZATION)` equals the golden file; the packet form ends
  with `· fabrication_released: false`.
- `banner_first_line_of_human_output`: for each M2 exporter, line 1 of the non-JSON output is the banner.
- `replay_header_banner_member`: a packet written by `telemetry.export-html` has `/authorization/banner`
  byte-identical to the golden file; a scan of the page bundle (N32b-13) finds no copy of the sentence; the
  header with the member changed by one character, set to a number, or set to `""` is `FROB-REF-816` with
  `Extra { field: "banner" }` from `artifact read`; a header without the member passes the flags check.
- `diagnostic_header_flags`: `sim.run --resolved-out r.jsonl` on a 4-world `batch-cpu` fixture writes a file
  whose line 1 parses as `frob.diag-header/1` with `/authorization` holding the three `false` members and
  whose remaining 4 or more lines are data records; the stripped and `true` mutants are `FROB-REF-816`.
- `contract_rows_present_for_later_kinds`: rows for the five later kinds with the stated `since` and `flags`.

### End-to-end script and logging
`scripts/e2e/safe_flags.sh --profile m2` (N37-24) against the real `frob`, `frobd` and `frob-verify`, with
the structured logging of STD-E2E (`target/e2e-logs/safe_flags/<utc-timestamp>.ndjson` and a transcript): per
verb the exact command line, exit code and wall time; per artifact the kind, digest, carrier, pointer and the
values found; per mutant the reader, exit code, refusal code and `observed`; `metric` lines `violations`
(threshold 0) and `mutants_refused` of `mutants_offered`; on failure the first artifact or mutant that broke
the rule with its path; a final `summary` with `gates: ["GATE-SAFE-01"]` and the profile.

### Known answers and negative controls
KA-828 (an artifact with one flag set to `true` is refused by the importer and by `frob-verify`; exact; an
artifact with the fields removed is also refused), applied to the three M2 kinds. Negative controls
registered against GATE-SAFE-01: a checkpoint writer that omits the metadata key; a stills exporter that
skips the sidecar; a replay writer whose header writes `true`; a `--resolved-out` writer that omits its header
line; a planted M2 exporter with no locator row; an
exporter whose human-readable output omits the banner. Metamorphic relation: the flags object is
byte-identical across the three kinds after canonicalization. Determinism lanes: the exported carrier bytes
identical twice on one machine, in debug and release, on Linux and macOS.

## Considerations

- A checkpoint container's metadata map is untyped text; the value is parsed with the strict canonical-JSON
  reader and checked by the one function, never compared as a string, so that whitespace or member order
  cannot pass a malformed object.
- A sidecar can be separated from its PNG by a person; the image alone is then correctly not an artifact of
  this system and is refused as one.
- The contract rows for later kinds are a promise that the writer beads must keep; if a later kind needs a
  carrier this registry does not have, the row is changed here first (additively) and the sweep follows.
- The flags never depend on configuration; the no-off-switch sweep (N37-02) covers the three M2 verbs.
