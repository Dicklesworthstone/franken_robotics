## Background

Before any FrankenRobotics code existed, small exact pilots were run on the program's ideas. Each is a FACT about a
small program on a small model. The program's rule is that such a number becomes this repository's own only after
it has been re-run here and recorded, and that no gate may cite it before then (GATE-GAUNT-08: the plan-time pilots
re-run at M0 and reproduce every count exactly). This bead re-runs the docking pilot, the first exact known answer
of the program and the fixture of the first mission slice at M1 (the docking family is later served through the
public verbs by BD-129 and on every backend by BD-190).

The docking fixture is a scalar model that puts sensor error, actuator authority and packet timing into one
inequality. It matters for three program-wide rules it demonstrates in the smallest possible case: a strict
predicate must be evaluated exactly (nine grid cells sit exactly on the boundary); the time at which an observation
arrives can decide feasibility with the hardware unchanged (an "alias witness" whose cause is timing); and a
verdict is bound to the declared support of the hidden parameters (adding one nearby gain reverses every positive
label). It makes no statement about any real docking device.

What the pilot did not do is part of the record: it used no FrankenSim dynamics, no contact and no sensor pipeline;
its strong baseline tied (an independently written scenario-tree linear program gives the same answer on all 561
cells), so what survives is an interface and a discipline of counterexamples, not a new algorithm.

Rejected alternative: copying the recorded counts into the registry without execution. The rule asks for
execution, and for a second, independent derivation written in this repository, which becomes the seed of the
certificate checker's exact arithmetic and of the fixture's derivation file.

## Scope

In: re-running the three archived drivers; an independent exact re-derivation in Rust with the standard library
only; the planted negative control; the arithmetic rows of the cart fixture named below; the records in the pilot
register and the admission file. Out: the stance pilot (BD-042); the other Augur pilots (BD-043); the native
65,536-row screens on Metal and CUDA (BD-030); the docking family through `mission.*` verbs (BD-129); the
remaining plan-time pilots (N38a-11).

## Technical approach

**The model.** Position in metres, time in seconds. Three ticks of one second from x₀ = v₀ = 0. During tick k the
acceleration is g·u_k, held constant; g ∈ {1, 2} is hidden and fixed; |u_k| ≤ U with U ∈ [½, 1]. Exact
zero-order-hold integration per tick: x ← x + v + g·u/2, then v ← v + g·u. Hence
v₃ = g·(u₀ + u₁ + u₂) and x₃ = g·(5u₀/2 + 3u₁/2 + u₂/2). The mission is (x₃, v₃) = (1, 0) exactly. The only
informative packet is a reading of v₁ = g·u₀ with additive error in the closed interval [−ε, +ε].

**Derivation (to be written to `docs/derivations/docking.md`).** Write p = u₀. With v₃ = 0, x₃ = g·(2p + u₁), so
the terminal conditions force u₁ = 1/g − 2p and u₂ = p − 1/g. The bounds for both gains hold exactly when
1 − U ≤ p ≤ (U + ½)/2. The readings lie in [p − ε, p + ε] for g = 1 and [2p − ε, 2p + ε] for g = 2; the required
second commands differ by ½, so the intervals must be disjoint: ε < p/2. At the largest admissible p:
**a robust causal policy exists exactly when ε < (U + ½)/4, equality excluded**, if the packet arrives before the
second command. If it arrives after the third command is committed, one command vector serves both worlds, the
final position g·(2p + u₁) cannot equal 1 for both gains, and every case is excluded.

**Procedure.**
1. Locate the reproduction archive: the single `.zip` in `planning/`. Record its size and SHA-256 and compare
   with the recorded 241,568 bytes and `0326e89d…b09a4f`. FACT observed at drafting (to re-observe): the file on
   disk is `astra-10x-reproduction.zip` with SHA-256 `9620da42…cd7980`, a later revision; a difference is written
   into the record with both digests.
2. Extract into a new empty directory `target/pilots/<first 16 hex of the digest>/`; nothing in it is imported by
   workspace code. Record interpreter and library versions (recorded: CPython 3.15.0, SciPy 1.18.1 with HiGHS,
   Z3 4.15.4).
3. Run `mor/repro/P04-docking.py` (standard library). Expected output, exactly:
   `observed gain 1 commands 1/4 1/2 -3/4 final 1 0`; `observed gain 2 commands 1/4 0 -1/4 final 1 0`;
   `late-only observation: incompatible required base positions 1 and 1/2`.
4. Run `mor/repro/P05-docking-family.py` (needs SciPy). Expected: `{'cells': 561, 'admitted': 344, 'excluded': 217,
   'equality': 9, 'late_excluded': 561}`, the line on U = 3/4 (fixed first command 1/4: ε < 1/8; optimized 5/8:
   ε < 5/16), and the line that at ε = 5/16 both gains admit the reading 15/16 while requiring second commands
   −1/4 and −3/4. It solves 51 linear programs (per bound: two extrema of the first-command separation and one
   common-command feasibility program, which must be infeasible) and three more for the fixed-probe control.
5. Run `followups/docking_support.py` (needs `z3`). Expected: four lines (`a first command avoiding this
   midpoint: unsat`; `common exact docking: unsat`; `common position error strictly under 1/65: unsat`; `bound
   attained for close pair at zero final velocity: sat`) and, for scales 1 and 2048, `nominal positives
   34590/65536; rows forcing ambiguous close gains for every first pulse 65536/65536`.
6. Run this repository's own program, `crates/frob-conformance/tests/pilot_docking.rs`, with exact rationals over
   `i128` (numerator and denominator reduced by gcd; no floating point anywhere):
   a. Grid: U = ½ + i/32 for i = 0…16 and ε = j/64 for j = 0…32. A cell is admitted exactly when 2j < 32 + i.
      Count admitted, excluded and boundary (2j = 32 + i) cells.
   b. Witnesses: integrate (¼, ½, −¾) with g = 1 and (¼, 0, −¼) with g = 2; both must end at (1, 0) with every
      |u_k| ≤ ¾.
   c. For every i, take p = (U + ½)/2 and check that u₁ = 1/g − 2p and u₂ = p − 1/g satisfy the bound for both
      gains and reach (1, 0).
   d. Equality: at U = ¾, p = 5/8, ε = 5/16, check p + ε = 2p − ε = 15/16 and required u₁ of −¼ and −¾.
   e. Late packet: for the three unit command vectors, x₃ under g = 2 is twice x₃ under g = 1, so by linearity no
      common vector gives x₃ = 1 in both worlds; all 561 cells are excluded.
   f. Third gain 33/32 at U = ¾, ε = 1/64: for every |p| ≤ ¾ the reading (65/64)·p is within 1/64 of both p and
      33p/32 (distance |p|/64), so both worlds receive the same remaining commands; with c = 2p + u₁ the final
      positions are c and 33c/32; max(|c − 1|, |33c/32 − 1|) is minimized at c = 64/65 with value 1/65; the
      vector (½, −1/65, −63/130) attains it with zero final velocity in both worlds.
   g. Integer corpus (the grid of the native screens): for n = 0…65,535, H = 2²⁷, u = H + (n·65,537) mod (H + 1),
      e = ⌊(u + H)/4⌋ + ((n mod 9) − 4)·s for s = 1 and s = 2,048. Positives are rows with 4e < u + H; rows forcing
      ambiguity are those with u ≤ 64e. Expected (34,590, 65,536) for both s.
7. Negative control: replace `<` by `≤` in step 6a and confirm that exactly nine cells change (344 becomes 353).
8. Arithmetic rows of the cart fixture `fixture:cart-sill-dock` (pure arithmetic on its constants, recomputed in
   the same test file): total mass 5.0 + 2.2 + 4 × 0.2 = 8.000 kg for design A and 8.225 kg for design B (front
   wheels of 0.3125 kg); tread force caps from two driven wheels at 0.2 N·m/A and a 6 A limit, 2.4 N·m ÷ 0.060 m
   = 40 N and 2.4 N·m ÷ 0.075 m = 32 N; lip lever
   a = √(2rh − h²) at h = 12 mm: 36.000 mm for r = 60 mm and 40.694 mm for r = 75 mm; friction demand a/(r − h):
   0.7500 and 0.6459.
9. Write one record per pilot row (two gains; three gains) into the pilot register with date, digests,
   environment, commands, values and status `reproduced` or `differs`; write the counts and the hash of the
   program of step 6 into `DEPENDENCY_ADMISSION.md`.

Determinism: every value is class D0 (exact). Evidence class of the record: `Tested`, labelled `synthetic`
(scalar plant). No product claim follows.

`crates/frob-conformance/tests/pilot_docking.rs` (no mocks, exact arithmetic):
- `grid_counts`: (344, 217, 9) of 561. `late_packet_all_excluded`: 561 of 561.
- `witness_g1`, `witness_g2`: end states equal (1, 0); commands within ¾.
- `probe_tradeoff`: at U = ¾, p = ¼ tolerates ε < 1/8 and p = 5/8 tolerates ε < 5/16.
- `equality_reading`: 15/16 in both worlds; required u₁ equal to −¼ and −¾.
- `third_gain_worst_error`: 1/65 at c = 64/65; a candidate c = 1 gives 1/32 and c = 32/33 gives 1/33, both larger.
- `third_gain_attained`: (½, −1/65, −63/130) gives 64/65 and 66/65 with zero final velocity.
- `corpus_counts`: (34,590, 65,536) for s = 1 and s = 2,048.

- `cart_rows`: 8.000, 8.225, 40, 32, 36.000, 40.694, 0.7500, 0.6459.

### End-to-end script and logging

`scripts/e2e/pilot_docking.sh` (header: `bead=BD-041 milestone=M0 labels=pilot,gauntlet gates=GATE-GAUNT-08
plants=nonstrict`). Steps: digest and extract the archive; run the three drivers (a missing SciPy or `z3` is
logged as a skip of that driver, not a pass); run the Rust test target; compare; write the records. It logs
through the STD-E2E helper to `target/e2e-logs/pilot_docking/<utc>.ndjson`: one `cmd` line per driver with exit
code and wall time, one `assert` per expected value (expected, observed, kind `eq` or `rational`), the archive
digest as a `metric`, one `assert` of kind `negative-control` for the planted comparator, and the `summary` naming
GATE-GAUNT-08.

## Considerations

- The archive on disk is a later revision than the recorded digest; the drivers named here are present in it.
- SciPy and Z3 are tools of the pilot, outside the product, and never dependencies of the workspace.
- With bounded probes and positive read error, any nondegenerate interval of hidden gains contains an
  indistinguishable pair, so exact docking fails and a finite tolerance must be declared; that case (least
  guaranteed tolerance (√1745 − 41)/32 m, about 24.2 mm, at U = ¾ and ε = 1/64) is a later known answer and out of
  scope here.
- If a count fails to reproduce, the known answers above are flagged and the owners of BD-129 and BD-190 are told
  before M1.
