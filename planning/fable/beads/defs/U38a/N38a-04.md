## Background

An oracle is something a candidate implementation is compared with: a sibling library, a foreign simulator, a
symbolic system, an analytic derivation. The Gauntlet (the verification subsystem of FrankenRobotics, crate
`frob-conformance`) owns the list of oracles, their pins and the fixtures captured from them. The rules exist
because parity is easy to fake by accident: a fixture regenerated from the candidate agrees with it by
construction; a pin that moves silently changes what was compared; and a routine in a sibling is not an oracle
merely because it exists. FACT to recheck: the suite's own PPO update fails three rules it would have been an
oracle for, and its `planar_drive` routine returns zero translation on a near-straight case; both are held out of
every oracle role until their admission tests pass.

DESIGN: oracles are admitted like dependencies (a pin, an admission test, a negative control) and recorded in one
register. Rejected: per-test ad hoc reference data (no pin, no capture script, no way to tell stale from wrong).

## Scope

In: `registry/oracles.toml` with its thirteen seed rows, the role grammar and the rule for rows appended later,
the pin-move log format used for every pin, the fixture store and its header, the capture-script convention, and
rules 1, 2, 5 and 6 below as they apply to oracles and their fixtures.

Out, with the bead that has it:
- The comparator registry `crates/frob-conformance/registry/comparators.toml`: its file, its row schema, its
  loader and the check that refuses a comparator pin move while a study that froze the pin is open are the
  incumbent harness bead's (BD-039). This bead's register only points at that file (the row "incumbent batched
  simulators") and defines the `[[pin_move]]` record that BD-039 reuses. Which releases and configurations the
  file freezes is the decision N36-25; which release is the development oracle is the decision N38b-35.
- The typing rule that parity is never reality and the hygiene gate's planted failures (N38a-05); the
  development oracle's lane (N38a-06); the reference-robot fixtures themselves (BD-067).

## Technical approach

**The register (`crates/frob-conformance/registry/oracles.toml`), thirteen rows.**

| FrankenTorch autograd | The pinned commit | Gradient oracle for on-device learning kernels | Oracle |

**Records.**
```toml
[[oracle]]
id = "mujoco-c-f64"; posture = "out-of-process"      # consume | oracle | out-of-process | derivation
pin = { kind = "release", value = "…", sha256 = "…" } # or { kind = "commit", repo = "frankensim", value = "…" }
admission = { test = "g2:mujoco-pendulum-period", control = "NC-…", status = "not-admitted", date = "" }
roles = ["parity:contact-free-dynamics", "import-fixtures"]   # grammar below
family = ""                                            # optional: the id of the seed row this row specializes
held_out = ""                                          # non-empty = reason it may not serve any role yet
[[pin_move]]                                           # appended, never edited
oracle = "…"; from = "…"; to = "…"; date = "…"; reason = "…"; by = "…"; fixtures_recaptured = ["…"]
```
A release pin may also carry `commit = "<sha>"`. The row `development-oracle` is written by the decision bead
N38b-35 in this same shape and carries four more fields, allowed on that row only: `tool`, `label =
"development-oracle"`, `decided`, `decision`.

The `[[pin_move]]` record is the one format for every pin move in the program (DESIGN: the incumbent harness
had drafted a second record with "who"; `by` carries it, so that one format serves both registers). In
`comparators.toml` the same record is appended with the key `comparator` in place of `oracle`.
A fixture file starts with a header: `kind = "oracle"`, `oracle`, `pin`, `captured` (date), `script`
(`tools/oracle/<name>` with its hash), `inputs` (paths and hashes), `units`, `tolerance_note`.

**Roles (DESIGN).** A role is `<kind>` or `<kind>:<subject>`; the subject is lower-case words joined by hyphens
and is named by the bead that uses the oracle. The kinds are a closed list, read off the Use column of the
table: `parity` (agreement of the candidate with the oracle on the subject, tier G2), `reference` (values,
trajectories or gradients that known answers are checked against), `second-checker` (an independent checker of
certificates, never linked into the auditor), `comparator` (a conventional method or an incumbent tool that the
candidate is compared with and must not lose to: a comparison instrument, never a truth), `import-fixtures`,
`referee` (the dynamics source of the referee tier; FrankenSim only) and `pilot` (the development oracle's only
role). A role of another kind, or with an empty or upper-case subject, is a load error naming the row. Role
names that other beads declare and this grammar admits: `comparator:hybrid-reachability` (N25c-24),
`comparator:label-query` (N25c-38), `second-checker:exact-interval` and `second-checker:bounded-linf-residual`
(N33bx-01).

**Rows appended after the seed (DESIGN).** The thirteen rows are the seed, entered here. The register is
append-only: a bead that needs a tool of its own appends an `[[oracle]]` row in this schema, with its own pin,
admission test and control, and may set `family` to the `id` of the seed row it specializes; a `family` naming
no seed row is a load error. The tools of the row "conventional solvers" (seed `id = "conventional-solvers"`)
are pinned this way, one row per tool, because a family has no release to record: the hybrid-reachability tool
of N25c-24 and the two label-query engines of N25c-38 (capture scripts under `tools/oracle/labels/`), each with
posture `out-of-process` and pin kind `release`. `fs-checker` (N33bx-01) is an appended row with no family:
posture `out-of-process`, pin kind `commit`, and `held_out` until its out-of-process entry lands upstream
(FD-FSIM-42). This bead writes none of those rows; its loader and its register check admit them.

**Rules implemented here.**
1. **Capture, never regenerate.** A fixture is written only by a script under `tools/oracle/`, stored with its
   pin and date. A capture script's declared inputs exclude every build product of this workspace (no path under
   `target/`, no `frob` binary, no crate of this repository). INV-GAUNT-01: no fixture is regenerated from the
   candidate. The check compares each fixture's bytes with the hash in its header and with the pin-move log: a
   fixture whose bytes changed without a `pin_move` record, or whose script lists a workspace product, fails.
2. **Moving a pin is a deliberate event with its own record.** Here: an oracle's pin in `oracles.toml` changes
   only together with an appended `[[pin_move]]` record that lists the fixtures recaptured, and the register
   check fails on a pin that differs from the last record. The second sentence of the rule, that a comparator
   pin does not move between the freeze and the end of the study that uses it, is enforced where the comparator
   rows live: `comparators.toml` carries `frozen_for = ["<study id>"]` on each row and BD-039's freeze check
   refuses a `[[pin_move]]` while a listed study is open.
5. **Admission.** An oracle serves a role only when `admission.status = "admitted"` and its control has been
   caught. `held_out` rows (the sibling PPO update; `planar_drive`) are refused in every role. Besides the
   thirteen rows of the table, the register therefore holds two held-out rows, `fs-g1-train-ppo-update` and
   `fs-mbd-planar-drive`, each with `admission.status = "not-admitted"`, no role, and a `held_out` reason citing
   its admission gate (INT-FSIM-06, BD-034; INT-FSIM-05, BD-033); the standing posture checks of N33b-08 read
   them, and only a passing re-run of that gate, recorded with a `[[pin_move]]` or admission edit, clears them.
6. **Disagreement is a finding.** When two admitted oracles disagree on a fixture beyond the tighter of their
   tolerances, the runner writes a finding with both pins to `registry/oracle_findings.toml` and marks the
   fixture `disputed`; a disputed fixture supports no gate, and the candidate is not tuned toward either oracle
   until a derivation file explains the difference.
(Rules 3 and 4 are N38a-05; rule 7 is N38a-06.)

**Capture scripts.** `tools/oracle/<oracle>/<fixture>.sh` (or the oracle's own language, run out of process),
taking `--pin` and `--out`, printing the tool's version string, refusing to run when the installed version
differs from the pin, and writing the fixture with its header. `tools/oracle/README.md` lists each script, its
oracle, and the command that reproduces a fixture from an empty machine.

## Acceptance criteria

- [ ] `oracles.toml` holds the thirteen seed rows with posture, pin kind and roles, and the two held-out rows with
      their reasons; a row appended later in the same schema loads, with its `family` checked against the seed
      ids; every role parses under the role grammar and an unknown kind is refused; the row "incumbent batched
      simulators" names `crates/frob-conformance/registry/comparators.toml` as its pin and this bead creates no
      such file (BD-039 does).
- [ ] Every fixture under `tests/fixtures/oracle/` and `crates/frob-conformance/fixtures/` has a header with pin,
      date and capture script, and its bytes match the recorded hash.
- [ ] A fixture changed without a pin-move record fails the check; a capture script that names a workspace build
      product fails the check.
- [ ] A role requested from a non-admitted or held-out oracle is refused by the runner.
- [ ] An oracle pin changed without a `[[pin_move]]` record fails the register check. (The refusal of a
      comparator pin move while a study that froze it is open is BD-039's acceptance.)
- [ ] Two oracles made to disagree on a planted fixture produce a finding with both pins and a `disputed` mark.

## Test plan

### Unit tests

`crates/frob-conformance/tests/oracle_register.rs`:
- `register_has_thirteen_rows` (the thirteen seed ids and the two held-out rows, `fs-g1-train-ppo-update` and
  `fs-mbd-planar-drive`, are present; rows appended later do not fail it); `posture_values_closed` (an unknown
  posture is a load error).
- `role_grammar`: `parity:contact-free-dynamics`, `import-fixtures`, `pilot`, `comparator:hybrid-reachability`,
  `comparator:label-query` and `second-checker:exact-interval` load; `benchmark:speed` (unknown kind),
  `Parity:x` and `comparator:` are load errors naming the row.
- `appended_row_admitted`: a scratch row with `family = "conventional-solvers"`, posture `out-of-process`, a
  release pin and role `comparator:label-query` loads and is `not-admitted` until its admission test passes;
  `family = "no-such-row"` is a load error.
- `fixture_header_required`: a fixture with no header is rejected by the loader.
- `fixture_bytes_match_hash`: one flipped byte is detected.
- `changed_fixture_needs_pin_move`: fails without a record, passes with one.
- `capture_inputs_exclude_workspace`: a script declaring `target/release/frob` as input is rejected.
- `held_out_refused`: requesting `planar_drive` as a parity oracle returns the held-out reason.
- `oracle_pin_move_needs_record`: an edited `pin.value` with no appended `[[pin_move]]` fails; with the record,
  including `by` and `fixtures_recaptured`, it passes. (`frozen_pin_cannot_move`, on comparator rows, is in
  BD-039's test file.)
- `disagreement_is_finding`: oracle A returns 2.0061 s and oracle B 2.0101 s for a pendulum period with
  tolerances 10⁻⁴ s; a finding is written and the fixture is `disputed`.

### End-to-end script and logging

`scripts/e2e/oracle_register.sh` (header: `bead=N38a-04 milestone=M0 labels=gauntlet,oracle
gates=GATE-GAUNT-05 plants=regen-from-candidate`). It validates the register and every fixture, then plants a
fixture regenerated from the candidate (bytes replaced, no pin move) and requires the failure. Log at
`target/e2e-logs/oracle_register/<utc>.ndjson`: commands, counts of fixtures per oracle and per status as
`metric` lines, fixture hashes as digests, one `assert` per rule, the negative-control assertion, the `summary`.

### Known answers and negative controls

Negative controls: the regenerated fixture; the workspace input; the held-out oracle; an oracle pin moved with
no record (the comparator pin moved during a freeze is BD-039's control). Counterexample carried: the sibling routine that returns zero translation at heading 32 rad is not an
oracle until its admission test passes (the independent chord formula is BD-033's). Determinism lane: the checks
are class D0; identical twice and on both platforms.

## Considerations

- Open: which incumbent release is the development oracle (N38b-35) and which releases form the comparator set
  (N36-25) is decided by the rival audit; until then the rows of `comparators.toml` (BD-039) are unfrozen
  defaults and every comparison that needs a frozen comparator is `not run`.
- Licences of foreign tools are recorded with the pin; a tool whose licence forbids publishing a comparison is
  replaced by the next strongest and the replacement is printed.
- A sibling oracle (FrankenTorch, FrankenSciPy, FrankenSymPy, FrankenNumPy) whose pin conflicts with the core
  graph (toolchain T, the one asupersync package) is the program's own upstream work item in that sibling's
  repository, under its rules: the sibling is brought onto T and the shared versions, since every sibling is the
  owner's. Interim posture until that lands: the oracle runs as a worker process in its own workspace and is
  never a Cargo dependency of a production crate; switch-over rule: when the sibling builds on T with one
  asupersync package, the row's posture is re-admitted by a `[[pin_move]]` record and its admission test re-run.
