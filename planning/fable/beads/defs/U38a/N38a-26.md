## Background

Tier G4 of the Gauntlet (the verification subsystem of FrankenRobotics) injects faults and requires each case to
end in its typed refusal or in an accepted state, with no leaked resource. This bead covers the two families in
which the fault is the input itself.

*Malformed input.* Agents and importers hand the system files: designs, cards, scenes, tasks, missions,
certificates, robot descriptions from other tools. A reader that panics, loops, allocates without bound, follows
a path out of its root, or passes a hostile string onward as if it were trusted text is a defect of safety, not
only of robustness: an agent reads what the system prints. The system has thirteen registered artifact formats,
each with one owner crate and one canonical reader: `.fbot` (design), `.fmodule`, `.fcard`, `.fscene`,
`.fclear`, `.ftask`, `.fmission`, `.fenergy`, `.fskill`, `.fmcw` (minimal counterexample world), `.frun`,
`.fbuild`, `.frobcert` (certificate bundle); plus the parser of the request envelope and the importers (URDF,
MJCF, scans, STEP and mesh files).

*Confirmation firewall.* The blinded qualification lane keeps sealed world clusters and per-world outcomes that
no discovery process may read. If any verb, under any argument, returns a sealed field, the lane's error rate is
void. The firewall is attacked with fuzzed read attempts, and its audit must find a planted leak path.

## Scope

In: schedules, mutators, oracles, corpora and counts for the two families. Out: the framework (N38a-23); the
readers' and importers' own fuzz targets and limits (BD-307 and the format owners), which this tier drives; the
firewall mechanism (BD-261).

## Technical approach

| Family | Injection | Oracle |
|---|---|---|
| Malformed input | Fuzzing of the thirteen format readers, the envelope parser and every importer (10⁷ executions each, TARGET); path traversal; hostile strings in imported text | No panic; each limit reached by a crafted file and refused; no hostile string outside an untrusted-marked field |
| Confirmation firewall | 10⁴ fuzzed read attempts against a sealed campaign; a planted leak path | No sealed field returned; the leak found by the audit |

**Malformed input.**
1. *Target interface.* Each reader and importer exposes one entry `fuzz_one(bytes) -> Result<(), Refusal>` in its
   owner crate; the tier calls it in process. The envelope parser is driven through the real `frob` binary on
   standard input for a sampled subset and in process for the bulk.
2. *Mutator.* Structure-aware and seeded (the test kit's address-keyed generator; no third-party engine in the
   production graph): bit and byte flips; truncation at every offset of small seeds; member duplication
   (including duplicates that differ only by escape sequences, at depths 1 to 8); reordering; nesting to and past
   the depth limit; integers at 2⁵³ − 1, 2⁵³ and 2⁵³ + 1 and decimals whose nearest double differs between
   parsers; non-printable and empty identifiers; invalid UTF-8; strings past the length limit; arrays past the
   element limit; schema version too new and too old; unknown members; a member moved to the wrong object.
3. *Seeds.* `crates/frob-conformance/chaos/corpus/<target>/`: the worked artifacts of the documentation, the
   reference robots, every fixture, and every minimized regression.
4. *Limits.* For each limit an owner declares (file size, depth, element count, string length, polygon count,
   mesh vertices), one crafted file exactly at the limit is accepted and one just past it is refused with the
   owner's code; "the limit exists" is thereby tested in both directions.
5. *Path traversal.* Every path-taking argument and every path inside an artifact is tried with `..` segments,
   absolute paths, a symbolic link swapped in after the check, and a path beneath the private root; each must
   resolve beneath one of the session's roots through a retained directory handle or be refused
   (`FROB-REF-734`). Smallest case: `exports/a` passes a string check and is replaced by a link to another
   directory before it is opened.
6. *Hostile strings.* Imported names, comments and descriptions containing shell metacharacters, terminal
   escape sequences, markup, and sentences that read as instructions to an agent. After import, every envelope,
   report and log line is scanned: the string may appear only inside a field marked untrusted, never in a
   message, a `next_actions` command, a file name or a refusal's repair.
7. *Oracle per execution.* Returns `Ok` or a typed refusal (exit code 3 on the surface) within the execution's
   time and memory cap (1 s, 256 MiB, DESIGN); never a panic, an abort, a hang or an unbounded allocation;
   accepted input round-trips (canonical → value → canonical is exact).
8. *Counts.* 10⁷ executions per target per release (TARGET), 10⁴ per change; the count run is printed.

**Confirmation firewall.**
1. Create a sealed campaign on a scratch ledger with canary values planted in sealed fields (world addresses,
   per-world outcomes, the sealing key's derivatives).
2. Generate 10⁴ read attempts across every verb of the registry: valid and fuzzed arguments, identifiers of
   sealed objects, pagination cursors pointing into sealed ranges, lineage queries from a receipt, artifact-graph
   traversals, log and telemetry queries, both through the command line and the MCP surface, with discovery
   scopes only.
3. Oracle: no response, log line, error message, cursor or timing-independent side channel in the response body
   contains a canary or a sealed field; a receipt contains only the decision, the index, the level spent, the
   units used and a hash.
4. Plant a leak path (a debug field that echoes a sealed address in one verb's refusal message, compiled only
   under a mutation feature) and require the firewall audit to find it and name the verb and field.

## Acceptance criteria

- [ ] Each of the thirteen readers, the envelope parser and each importer has a target, a seed corpus and limit
      files, and survives its executions with zero panics, hangs or unbounded allocations.
- [ ] For every declared limit, the at-limit file is accepted and the past-limit file is refused with its code.
- [ ] Every traversal attempt is refused or resolves inside a session root; the link-swap case is refused.
- [ ] No hostile string appears outside an untrusted-marked field in any output.
- [ ] 10⁴ fuzzed read attempts return no sealed field and no canary; the planted leak is found by the audit.
- [ ] Every crash found is stored as a minimized regression and replayed first thereafter.

## Test plan

### Unit tests

`crates/frob-conformance/tests/chaos_input.rs`:
- `duplicate_member_refused`: `{"wheel_radius_mm": 60, "wheel_radius_mm": 75}` and the same with the second name
  escaped (`"wheel_radius_mm"`) are refused before any identity is computed.
- `integers_above_2_53_are_strings`: 9007199254740993 as a bare number is refused or carried as a string.
- `depth_limit_both_sides`, `string_limit_both_sides`, `element_limit_both_sides`: one target each.
- `truncation_never_panics`: every prefix of the reference quadruped's design file returns a refusal or `Ok`.
- `link_swap_refused`.
- `hostile_name_stays_untrusted`: a link named with an instruction-like sentence and an escape sequence appears
  only in fields marked untrusted in the `design.show` envelope.
- `firewall_no_canary_in_10k`: 10⁴ seeded attempts on a scratch campaign.
- `planted_leak_found`.

### End-to-end script and logging

Measured by `scripts/e2e/chaos_g4.sh` (N38a-27) with the family filter `input`: it pipes sampled mutated files
to `frob design check --json`, `frob design import` and `frob-verify`, expects typed refusals with
`e2e_expect_refusal`, runs the firewall attempts through `frob` and `frob-mcp`, and scans every captured output
and the log itself for canaries and hostile strings. Per target the log has executions, panics and hangs
(thresholds zero), refusal codes met, limits tested, and the two negative controls.

### Known answers and negative controls

Known answers: the duplicate-member case (a reader that keeps the first value simulates a 60 mm wheel, one that
keeps the last simulates 75 mm, and both hash the same bytes); 2⁵³ + 1 is not representable as a double.
Negative controls (each must be caught): a reader that keeps the last duplicate; a string-prefix path check; an
importer that copies a description into a message; the planted leak path; a limit removed from a reader (the
past-limit file is accepted). Determinism lane: the mutator is seeded and class D0; a crash reproduces from its
(seed, index).

## Considerations

- Formats that do not exist yet at M3 (`.fenergy`, `.fbuild`, parts of `.fskill`) are bound when their owners
  land; until then their rows are `not-yet-due`, and the gate prints which were run.
- Each reader must survive 10⁷ executions with zero panics before its format's first release; the importers'
  own gate asks the same of them.
- Fuzzing budgets are large; the release run names its envelope and may be spread over nights, with the
  cumulative count recorded.
- Private scenes: no corpus file is derived from a private scan.
