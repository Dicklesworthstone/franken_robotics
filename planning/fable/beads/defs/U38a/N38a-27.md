## Background

FrankenRobotics injects faults into itself in ten families (cancellation; device faults; transaction faults; job
protocol; chunk protocol; daemon and ledger; capacity; malformed input; confirmation firewall; worker fallback).
The verification subsystem, the Gauntlet (crate `frob-conformance`), owns the schedules and oracles. This bead
is the end-to-end measurement of the gate over them:

GATE-GAUNT-06 (claim kind Known answer; TARGET; M2 for kernels, M3 for the daemon): every row of the fault table
ends in its typed refusal or an accepted state with no leaked resource; 10⁵ seeded schedules per release; every
await point on the publish and submit paths hit.

The measurement is made from the user's side wherever the fault can be reached from there: real `frob`, `frobd`,
`frob-mcp` and worker processes, on a scratch ledger, killed, starved, fed hostile files and asked to cancel. The
in-process and simulated schedules are run through the tier's test target and their receipt is read. The log
must show, family by family, what was injected, how the system answered, and that nothing leaked.

## Scope

In: the script, its family filters and modes, its assertions and log. Out: the framework and the families
(N38a-23 to N38a-26); writing the gate status.

## Technical approach

**Script `scripts/e2e/chaos_g4.sh`.** Header: `bead=N38a-27 milestone=M3 labels=gauntlet,gate,chaos
gates=GATE-GAUNT-06 needs=cpu,frobd plants=swallow-refusal,leak-lease,skip-await-point timeout_s=3600`.

Steps (each family is one step; `--family kernel|protocols|input|<name>` selects). The family filters `kernel`,
`protocols` and `input` call the family beads' own scripts (`chaos_kernel.sh` of N38a-24, `chaos_protocols.sh`
of N38a-25, `chaos_input.sh` of N38a-26) for the steps below that those scripts own, and fold their logs into
this one by digest; this script owns the setup, the baseline and final audit, the plants and the account.
1. `setup`: scratch project root and ledger; start `frobd`; record the resource-audit baseline with
   `frob doctor --json` (device buffers and leases, open jobs, reserved budget, worker processes).
2. `cancellation`: start `frob sim run` (8 worlds, 200 ticks, `batch-cpu`; devices too when present), send
   `frob job cancel` at a seeded tick, wait for the receipt; assert it names the last committed tick per world
   and that `frob sim replay` to that tick reproduces the digest. Then drop a client connection without
   cancelling and assert no cancellation receipt exists.
3. `device-faults` (needs a device; otherwise skipped and named): corrupt one byte of a kernel-cache entry in
   the scratch cache and run a job (the entry is refused and rebuilt); request more worlds than admission
   allows (budget refusal, exit code 4).
4. `transaction-faults`, `capacity`: run the tier target for these families and read its receipt (they are not
   reachable from the surface as single commands); additionally submit one over-capacity scene through
   `frob sim run` and expect the typed refusal or the `capacity-biased` label in the evidence block.
5. `job-protocol`: submit with an idempotency key; kill `frobd` with a signal between acceptance and receipt;
   restart it; `frob job find --verb sim.run --key <k> --json` returns the one job; resubmitting with the same key returns the original
   receipt (`idempotent_replay: true`); the budget shows one charge; a different body under the same key is
   refused as a conflict (exit code 7).
6. `chunk-protocol`: kill the daemon during chunk publication; restart; assert a contiguous frontier per world
   and stream with `frob run show <run> --json` and `frob telemetry query <run> --stream <s> --json` (the verb
   that pages against the committed frontier; `evidence.trace` reads a claim's evidence closure, not chunks);
   offer different bytes for a committed extent through the test hook and
   expect `FROB-REF-810`.
7. `daemon-and-ledger`: run `cargo test -p frob-conformance --test g4_chaos -- daemon --count N` (N = 10⁵ in
   release mode, 10³ in smoke mode); read schedules run, violations, and await points hit of total.
8. `worker-fallback`: run a job in `remote` mode, kill the worker process mid-job, resubmit; compare chunk
   digests with the in-process run.
9. `malformed-input`: pipe 200 sampled mutated files per reader to the matching verb and expect a typed refusal
   or success, never exit code 1; run the limit files in both directions; run the traversal cases.
10. `firewall`: on a sealed scratch campaign, replay 10⁴ read attempts through `frob` and a sample through
    `frob-mcp`; scan all captured output for canaries.
11. `audit`: stop all jobs; compare the resource audit with the baseline; any difference is a failed assertion
    naming the resource.
12. `account`: per family: injections, refusals (by code), accepted states, violations, leaks; coverage of
    await points; the gate line.

**Plants.** `swallow-refusal`: a scratch build in which one refusal is converted to a success envelope with an
empty result (the family must report a violation). `leak-lease`: a lease left held after cancellation (step 11
must fail). `skip-await-point`: one await point removed from the schedule generator (coverage must fail).

## Acceptance criteria

- [ ] The script runs every family available on the host and exits 0 only with zero violations, zero leaks and
      full await-point coverage.
- [ ] The kernel part (steps 2 to 4) is claimable at M2 and the whole at M3; the summary states which part was
      run and on which sites, and smoke mode is never claimable.
- [ ] Every refusal met is logged with code, exit code, message and ranked repairs, and matches the family's
      expected code.
- [ ] No command ends with exit code 1, and no captured output contains a canary, a hostile string outside an
      untrusted field, or private-scene data.
- [ ] The three plants are caught.
- [ ] The audit after the run equals the baseline.

## Test plan

### Unit tests

The accounting used by the script is tested in `crates/frob-conformance/tests/chaos_account.rs` on recorded
receipts of real runs of the framework's example workload: `account_zero_violations_pass`;
`account_one_leak_fails` (a leaked lease counter of 1); `account_coverage_hole_fails` (one await point with zero
hits); `account_reduced_count_printed` (10³ of 10⁵ is not claimable); `account_family_skipped_named`.

### End-to-end script and logging

The script above. Log at `target/e2e-logs/chaos_g4/<utc>.ndjson` through the shared helper: every command with
its exact command line, exit code and wall time (including the signals sent, as commands); the evidence block of
each envelope; one `refusal` line per refusal with `expected: true` or `false`; per family `metric` lines
`violations` (`== 0`), `leaks` (`== 0`), `schedules` (`>= N`), `await_points_hit` (`== await_points_total`);
digests wherever state is compared (replayed ticks, chunk digests, the audit before and after); on a violation
the first differing value, the minimized schedule's path and the artifacts needed to replay it; the three
negative-control assertions; the `summary` with counts and the gate touched.

### Known answers and negative controls

Known answers: one job and one charge per idempotency key; a contiguous frontier; bit-equal digests after a
worker kill; zero uncommitted reads in 10⁵ transaction faults; the baseline audit equals the final audit.
Negative controls: the three plants, and every control listed in GATE-GAUNT-06's `controls` (the gate row of
`registries/gates.toml`), counted from that list and not from the family beads, since most are records other
beads own: sixteen at plan time, kernel six (five registered by N38a-24 with `seed = "GATE-GAUNT-06"`, and
CX-144's redraw on rejection, also MR-09's), protocols five (BD-096's two-statement binding, also MR-36's, its
lost-chunk publisher and its order-dependent fake device; MR-36's offset pagination; MR-37's stale worker) and
input five (N34-17's `dup-last-wins` of CX-361, N37-CX's SAFE-X01 and SAFE-X02 records, the removed-limit control
of GATE-SAFE-07, BD-261's planted leak). The account prints each with its state; a missed control fails the
gate line and a `stale` one makes it `not-eligible`, never a pass. Determinism lanes:
simulated schedules replay to identical ledger bytes; the surface steps are run twice in smoke mode and their
logs agree after removing timestamps, process identifiers, wall times and paths.

## Considerations

- Killing a daemon mid-write is timing-dependent from a shell; the script uses the daemon's fault hook to stop
  at a named await point where exact placement matters, and a plain signal elsewhere; both kinds are counted.
- The release run exceeds the per-change budget and is scheduled per release under a named envelope.
- A family whose mechanism was replaced at a kill gate (for example the process-boundary server instead of the
  in-process one) is run against the fallback and the account says so.
