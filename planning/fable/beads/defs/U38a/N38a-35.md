## Background

Every number FrankenRobotics produces records how repeatable it is, as one of five determinism classes:

| Class | Guarantee |
|---|---|
| D0 Exact | Integer, rational or symbolic results |
| D1 Bitwise across backends | The same bits on the CPU batch tier in `f32`, on CUDA and on Metal (a HYPOTHESIS per device family until its IEEE probe gate passes) |
| D2 Bitwise per backend | The same bits run to run and across worker counts on one device family, driver and compiler; and across batch size, slot, co-tenant worlds, bucket capacity and shard count |
| D3 Tolerance | Agreement inside a recorded envelope, and agreement of task decisions |
| D4 Unspecified | None; never cited as evidence; its one sanctioned use is a labelled fast-training profile |

Much of the system stands on these classes: paired comparisons need both arms replayable; counterfactual forks
need bit-exact replay; a memoized episode may be reused only at class D2 on the same backend. Two rules govern
them: the weakest input wins, and a class is never raised by relabelling, only by running again under a stricter
profile. Tier G5 of the Gauntlet (the verification subsystem, crate `frob-conformance`) is where a declared
class is tested. This bead is that tier's runner and its measurement.

The gate (GATE-GAUNT-07, claim kind Known answer, TARGET, M2): every kernel and every verb meets its declared
class twice on one machine, across worker counts, in debug and release, across platforms and across backends;
and the batch-composition relation MR-01 holds on 10⁴ worlds per device family.

Rejected alternative: testing determinism only by repeating a batch. Incumbent simulators document that (replay
of the same batch on the same GPU); what this design adds, and therefore must test, is independence of a world
from its batch and bit equality between a device and the CPU reference.

## Scope

In: the enumeration of kernels and verbs with their classes; the five lanes applied to each; the added G5
content (batch composition, decision-level equivalence, exact and guarded kernels, the two refusals); the
account and script. Out: the lane helpers themselves (the test kit, STD-TEST); the batch-composition test's
implementation (BD-181); the self-test of the determinism classifier (drafted with the certifier self-tests).

## Technical approach

1. **Subjects.** Every row of the kernel registry (identifier, declared class per backend) and every verb of
   the verb registry (declared class of its output for a declared profile). A subject with no declared class is
   a failure of the tier (`undeclared`), not class D4.
2. **Workloads.** For a kernel: 10⁴ random admissible inputs from the test kit's generator, plus its boundary
   set. For a verb: its registered demo request and three seeded variants, run through `frob --json`.
3. **Lanes** (helpers from the test kit; each returns digests at checkpoints).

| Lane | Varies | Expected for D0, D1, D2 | For D3 | For D4 |
|---|---|---|---|---|
| `twice` | Nothing | Identical bytes | Inside the envelope; decisions agree | Not asserted; the label must be present |
| `workers` | Worker count 1, 2, 8; shard count 1, 2 on devices | Identical bytes | As above | As above |
| `profiles` | Debug and release builds | Identical bytes | As above | As above |
| `platforms` | arm64 macOS and x86-64 Linux | D0 identical; referee `f64` identical only where the upstream cross-ISA work has landed, otherwise judged as D3 | As above | As above |
| `backends` | CPU batch tier in `f32`, CUDA, Metal | D0 identical; D1 identical; D2 makes no cross-backend claim and is judged as D3 here | Envelope and decisions | As above |

4. **Batch composition.** MR-01 on 10⁴ worlds per device family: each world alone, in 100 random co-tenancies,
   under slot permutation, at bucket capacities 32, 64 and 128, and on one and two shards; digests identical.
5. **Decision-level equivalence under D3.** For a pair of placements claimed at D3, on a frozen ensemble of
   world addresses with frozen policies, compare per world: state error in physically scaled units until the
   first divergence beyond the envelope; impulse and work residuals; event times; task decisions (termination
   cause, each success predicate, each requirement verdict, the winner of each comparison, each gate metric);
   and each decision's margin. Equivalent when (TARGETs): the one-sided 95% exact binomial upper bound on the
   rate of discordant decisions is at most 1% (with zero discordant worlds the bound is about 3/n, so at least
   300 worlds are needed; 4,096 worlds admit roughly thirty); the bound on the net one-sided rate is at most
   0.5%; continuous outcomes are equivalent by two one-sided tests inside the fidelity ledger's margins; the top
   of the design ranking agrees. A decision whose margin is smaller than the divergence envelope is reported
   `boundary-sensitive` on both placements.
6. **Exact-integer and guarded kernels.** Every exact-integer kernel and the decisions of every guarded kernel
   are class D0 on every backend: identical bytes across all five lanes, including on the 65,536-row boundary
   corpus (where bare single precision gives 452 false admissions and 23,438 false exclusions and the guarded
   kernel with exact fallback gives zero final errors).
7. **Refusals that are part of the tier.** (a) A paired statistic requested with an arm of class D4 or of
   unrecorded class, or as paired across device families without class D1, is refused with `FROB-REF-561`
   (under D3 it is allowed, labelled `paired-by-address`, with the realized pair correlation reported).
   (b) A number from a run under the fast-training profile cited as evidence, or a policy trained under it
   offered without a stricter re-evaluation, is refused with `FROB-REF-861`. (c) Interventional attribution
   below class D2 is refused with `FROB-REF-562`.
8. **Account.** Per subject and lane: declared class, observed outcome (`identical`, `within-envelope`,
   `decision-equivalent`, `mismatch` with the first differing checkpoint, step and quantity, `skipped`), and
   whether the declared class is met. A subject that meets a weaker class than declared is `overclaimed` and
   fails; one that meets a stronger class is reported and its declaration is not raised by this run.

## Acceptance criteria

- [ ] Every kernel and verb is enumerated with a declared class; an undeclared subject fails the tier.
- [ ] GATE-GAUNT-07 (TARGET): each subject meets its declared class on all five lanes available, and MR-01
      holds on 10⁴ worlds per device family; lanes that need the second host or a device are named when skipped,
      and the gate is claimable only when all were run.
- [ ] The decision-level test reports discordant worlds with margins and labels `boundary-sensitive` decisions.
- [ ] The three refusals are returned with their codes on the surface.
- [ ] Each lane catches its planted defect (below); an overclaimed subject is reported.

## Test plan

### Unit tests

`crates/frob-conformance/tests/g5_determinism.rs` and `tests/g5_account.rs`:
- `undeclared_subject_fails`.
- `twice_catches_uninitialized_padding`: a kernel build that leaves a padding lane unwritten gives two digests.
- `workers_catches_arrival_order_reduction`.
- `profiles_catches_contraction`: a build that permits fused multiply-add differs between debug and release.
- `backends_d1_requires_probe`: with the probe gate not passed for a device family, a D1 claim on it is judged
  `unproven` and blocks.
- `decision_bound_values`: with zero discordant worlds the bound is 1 − 0.05^(1/n): 0.00994 at n = 300,
  0.00997 at n = 299 and 0.010002 at n = 298, so 299 is the smallest n that can show 1% (the design's round
  figure is 300).
- `boundary_sensitive_label`: outcomes 1.0000001 and 0.9999999 around the predicate x ≥ 1 are inside any state
  envelope and are discordant; both are labelled.
- `overclaim_reported`: a subject declared D2 that only meets D3.
- `refusal_561`, `refusal_861`, `refusal_562`.

### End-to-end script and logging

`scripts/e2e/determinism_g5.sh` (header: `bead=N38a-35 milestone=M2 labels=gauntlet,gate,determinism
gates=GATE-GAUNT-07 needs=cpu,second-host plants=capacity-shaped-reduction,unlabelled-d4 timeout_s=3600`).
Steps: enumerate subjects; run `frob sim run` for the reference workload twice, with 1, 2 and 8 workers, from
debug and release binaries, and (when `FROB_E2E_SECOND_HOST` is set) on the other platform, comparing the
digests in the envelopes; run the tier target for kernels and for MR-01; issue the three refused requests with
`e2e_expect_refusal`; plant `capacity-shaped-reduction` (a reduction tree whose shape depends on bucket
capacity: MR-01 must fail between capacities 32 and 64) and `unlabelled-d4` (a fast-training result with its
label stripped: refused). Log at `target/e2e-logs/determinism_g5/<utc>.ndjson`: commands with exit codes and
wall time; each envelope's evidence block with its determinism class and identities; digests per lane; per lane
`metric` lines `subjects`, `mismatches` (`== 0`), `overclaimed` (`== 0`); the decision-level bounds with their
thresholds; the refusals; the negative controls; the `summary`.

### Known answers and negative controls

Known answers: the smallest n with 1 − 0.05^(1/n) ≤ 0.01 is 299; the padding identity (−0.0) + (+0.0) = +0.0;
the boundary-corpus counts 452 and 23,438 for bare single precision and zero for the guarded kernel. Negative
controls: a capacity-shaped reduction tree; a batch-wide normalizer (two worlds observing 1 and 3 see −1 and +1
in a batch and 0 alone); sequential draws from one generator; an unlabelled D4 result; a fused multiply-add.
Determinism lanes: the tier is the lanes.

## Considerations

- Class D1 on devices is a hypothesis with its own kill gate; if it fails for a family, cross-backend claims on
  that family are D3 with the decision-level test, and this tier's `backends` lane says so.
- The platforms lane needs both machines; a release run schedules it explicitly, and a single-host run prints
  `platforms: not run`.
- A difference of one unit in the last place grows like e^(λt) in contact-rich dynamics and reaches order one
  after about 16.6/λ seconds; long-horizon digests are therefore compared at checkpoints, with the first
  divergence kept.
