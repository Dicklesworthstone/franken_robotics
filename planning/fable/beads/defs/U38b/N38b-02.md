## Background

FrankenRobotics prints one line on every report, `reality: <status> […]`, stating whether anything measured on
a physical robot supports the result. With no admitted dataset the line reads `reality: no-claim`. The
verification subsystem (the Gauntlet) has four duties toward the Reality lane: the line is present; a
comparison with a published figure is labelled Parity (`published-anchor`) and a comparison with a stand-in
simulator is labelled `synthetic` and never promoted; the calibration machinery is rehearsed on synthetic data
only; and reports that support a benchmark claim print the share of card fields that were guessed (`generic`
or `assumed` provenance). In addition no exported artifact may carry `sim_to_real_certified = true`.

This bead is the end-to-end script that shows the five behaviours from the user's side, with planted misuses,
at M1 and again at M3 and M5 as the later behaviours become available.

## Scope

In: one script with a milestone argument, its fixtures and log. Out: the checks' unit tests (N38b-01) and the
mechanisms (the calibration subsystem's beads).

## Technical approach

`scripts/e2e/reality_lane.sh <M1|M3|M5>` (header: `bead=N38b-02 milestone=M1 labels=gauntlet,ground
gates=GATE-GROUND-01 plants=strip-line,flag-true,promote-synthetic`), seed 0, scratch store.

Steps.
1. `line` (M1): `frob --json sim run g1 --tier referee --seconds 2` then `frob --json explain run <run>`;
   assert `evidence.reality == "no-claim"` in both envelopes and exactly one line `reality: no-claim` in the
   rendered explanation. Repeat for every verb the registry marks as producing a report.
2. `flag` (M1): `frob --json run export <run>`; assert `authorization` holds the three fields, all `false`.
   Plant: edit the exported bundle's `sim_to_real_certified` to `true` and import it; expect exit 3 and refusal
   FROB-REF-816. Plant: remove the field; expect the same refusal (absence is not read as false).
3. `strip-line` (M1): render a report with a test template that omits the line; expect the report generator's
   guard to fail and the conformance check `line_on_every_report` to exit non-zero.
4. `anchor` (M3): run the published-anchor script; assert the stored result has claim kind `parity`, status
   `published-anchor`, a source and conditions, and that the report prints `reality: published-anchor` beside
   a Parity sentence of the form "matches <source> at <pin> within <tolerance> on <fixture>". Plant: submit a
   hand-written result offering the anchor as Reality; expect refusal by the loader.
5. `share` (M3): `frob --json report design <design>` on a benchmark design; assert the line `card fields
   guessed: k of n (s%)` and recompute k and n from the cards' provenance fields.
6. `synthetic` (M5): `frob ground identify` and `frob ground band` on the rehearsal dataset; assert every
   envelope has `origin: synthetic` in its evidence and the line does not read `calibrated`. Plant: request
   promotion of the synthetic comparison (`promote-synthetic`); expect refusal (pooling or promoting synthetic
   with real data is refused, existing code FROB-REF-814).
7. `end`: summary.

**Logging.** `target/e2e-logs/reality_lane/<utc>.ndjson` and a transcript. `cmd` events: exact command, exit
code, wall time. `assert` events: the reality value of each envelope; the count of reports checked and of lines
found (threshold: equal); the share as printed against the share as recomputed. `refusal` events: code and
message for each plant. The evidence block of each envelope (claim, class, tier, determinism, identities, seed,
reality). `summary`: assertions passed and failed; GATE-GROUND-01. The log never contains scene data from a
private place; the fixtures are public reference robots and generated scenes.

## Acceptance criteria

- [ ] At M1, steps 1 to 3 pass and all three plants are refused or caught.
- [ ] At M3, steps 4 and 5 pass; the hand-written Reality record is refused; the share recomputes.
- [ ] At M5, step 6 passes; the promotion of synthetic data is refused.
- [ ] Steps not yet due are logged `not-due` with the milestone, never as passed.
- [ ] The script is idempotent and leaves the repository unchanged.

## Test plan

### Unit tests

None of its own beyond the harness self-test; the checks are N38b-01's.

### End-to-end script and logging

As above; selected by `scripts/e2e/run-all.sh --label ground --milestone <M>` and at each milestone exit,
because the reality line's gate is re-run at every exit after its first.

### Known answers and negative controls

Known answer: with no dataset, every line reads `reality: no-claim`. Negative controls: the stripped line; the
flag set to true; the flag removed; the anchor offered as Reality; the promoted synthetic comparison.
Determinism: outcomes identical twice on one machine and on both platforms.

## Considerations

- If a real dataset is admitted, step 6 gains a `calibrated` branch for its cell and keeps the `no-claim`
  assertion everywhere else.
- A design that was never built never receives a band; the script asserts the refusal when the band verb exists.
