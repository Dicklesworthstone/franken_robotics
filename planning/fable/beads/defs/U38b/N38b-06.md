## Background

One way a swarm of agents produces the appearance of progress is a result that does not depend on what it
claims to depend on: a figure served from a fixture, a cache or a stand-in. A sibling project recorded exactly
that (FACT): beads closed while "serving figures from a stand-in". The verification subsystem of
FrankenRobotics (the Gauntlet, crate `frob-conformance`) answers with a rule that every bead inherits:

- **Live-dependency proofs.** For a gate that claims a result depends on an input (a scene, a card, a policy),
  the test perturbs the input and requires the output to change.

This bead supplies the mechanism: a helper in the shared test kit, a declaration on gate entries, a catalogue of
perturbations per kind of input, the complementary check that an input the result should *not* read leaves it
unchanged, and the lint that makes a gate with a declared dependency ineligible until its proof exists.
Rejected alternative: inferring dependence from code coverage (a covered line can still feed a constant).

## Scope

In: the declaration, the helper, the perturbation catalogue, the two-sided check, the lint, the planted
stand-in. Out: the `synthetic` label rule (N38b-07); behavioural controls for learning gates (N38b-08);
metamorphic relations about revalidation (N38a-16).

## Technical approach

**Declaration.** A conformance entry may carry `depends = ["scene", "card:<field>", "policy", "design",
"task", "seed", "battery", "state"]`, and a gate row in `registries/gates.toml` whose threshold names an input
gets the same list (`depends`). A gate with a non-empty `depends` and no live-dependency result in its receipt
prints `not-eligible: no live-dependency proof`. Both carriers are closed records, so this bead adds its two
fields to them, additively (a row or a receipt without them loads unchanged): the optional `depends` on `[[gate]]`
in the register's one schema file (`frob.gates/1`, written by N38b-18 and extended by N40-01, where an unknown
field fails the load), and the optional `live` list of the receipt `frob.gauntlet.receipt/1` (N38a-02).

**Helper (`frob_core::testkit::live::prove`, feature `test-support`).**
```rust
// DESIGN sketch
pub struct Proof { pub input: InputKind, pub changed: bool, pub base: Digest, pub perturbed: Digest,
                   pub bound_changed: bool, pub control_unchanged: bool }
pub fn prove(input: InputKind, base: &Request, measured: &[&str], perturb: impl Fn(&mut Request),
             irrelevant: impl Fn(&mut Request), run: impl Fn(&Request) -> Envelope) -> Proof;
```
Algorithm.
1. Run `base`; record the digest of the *measured* part of the result block and the envelope's `bound`
   identities. The measured part is the fields the gate's threshold reads, named by the caller as JSON pointers
   into `result` (`measured`; for `sim.run` the chunk digests and the final state digest). A field that restates
   the request (the run identity, the recorded command) is never one of them: it changes with every input, so a
   digest over the whole block would make every proof hold by echo, also for a stand-in that serves a fixed
   figure. An empty `measured` list is an error of the test.
2. Apply `perturb` to a copy (from the catalogue below); run; record the same.
3. `changed` = the measured digests differ. `bound_changed` = the identity of the perturbed input in `bound`
   (or in the claim product's input list) differs between the two envelopes. An input that is a manifest field
   and no resolved name (the seed, the state perturbation) has the run's manifest identity (`RunId`, the
   `run` field of `sim.run`'s result) as its identity.
4. Apply `irrelevant` (a change to something the result must not read) to another copy; run;
   `control_unchanged` = the measured digest equals the base digest.
5. The proof holds only if `changed`, `bound_changed` and `control_unchanged` are all true. `changed` without
   `bound_changed` is reported as `unbound-dependency` (the output moved but the envelope does not say on
   what); `changed` false is `stand-in-suspected`, whether or not `bound` moved (a stand-in that recomputes
   identities and serves a recorded figure is still a stand-in).

**Perturbation catalogue (each is the smallest change that must alter the result; DESIGN).**

| Input | Perturbation | Irrelevant change used as the control |
|---|---|---|
| Scene | Move one obstacle or the sill by 0.1 m; or select a second scene of the same family | Rename the scene; change an optical property for a task with no camera |
| Card field | Multiply a torque constant, a friction coefficient or a resistance by 2 (a power of two keeps arithmetic exact) | Change the card's free-text note |
| Policy | Replace the weights by zeros, or permute the output units | Re-serialize the same weights |
| Design | Change one link length or one gear ratio by a typed edit | An edit followed by its inverse (same design identity) |
| Task | Tighten one requirement bound across the measured margin | Reorder independent requirement terms |
| Seed | Change the seed | Change the worker count under a class of at least D2 |
| Battery | Remove one scenario (the battery identity must change) | Reorder the manifest |
| State (an initial coordinate, an applied torque) | One unit in the last place, `f64::from_bits(x.to_bits() + 1)`; on `sim.run` the conformance build's `--perturb-ulp q0` (BD-024) | The seed of a run that draws nothing (the M0 free fall); otherwise the worker count |

The seed and design rows need a run that reads them. The M0 run of BD-024 does not: it accepts no design but
`g1` (any other is FROB-REF-724 until stored designs arrive at M1, N29ax-01) and it is a free fall under zero
torques that draws no random number, so its state digests are equal under every seed and only `RunId` moves. At
M0 the proof on the real run is therefore the state row, with the seed as its irrelevant side; a gate that
declared `seed` for that run would rightly read `stand-in-suspected`.

**Lint (`tests/live_dependency_lint.rs`).** Every gate with `depends` has, for each listed input, a `live_`
test bound to it by name (`live_<gate>_<input>`); a missing one fails. The tier runner copies each proof into
the receipt (`live[{input, changed, bound_changed, control_unchanged}]`).

**Planted stand-in (the negative control of the mechanism).** A test-only verb wrapper that returns a recorded
envelope whatever the request; `prove` must report `stand-in-suspected` for every input kind.

## Acceptance criteria

- [ ] `prove` returns a holding proof for the M0 referee run of BD-024 when its initial state is perturbed
      (input `state`, `--perturb-ulp q0`), with a change of seed as the irrelevant side; with the seed offered
      as the perturbed input of that run it returns `stand-in-suspected`; and it returns `stand-in-suspected`
      for the planted wrapper. The seed and design rows hold on the synthetic run of the unit tests.
- [ ] An output that changes while the envelope's bound identities do not is reported `unbound-dependency`.
- [ ] The irrelevant change leaves the result digest unchanged in every catalogue row; a planted reader of an
      irrelevant field is caught by `control_unchanged = false`.
- [ ] A gate row with `depends` and no proof is `not-eligible`; the lint names the missing test.
- [ ] Receipts carry the proofs; the helper builds only under `test-support`.

## Test plan

### Unit tests

`crates/frob-core/tests/testkit_live.rs` (the helper's logic; `frob-core` cannot call the referee, so its run is
a small deterministic computation defined in the test and labelled `synthetic`, which reads each of the eight
inputs, draws one value from the seed and writes each input's digest into `bound`) and
`crates/frob-conformance/tests/live_dependency_lint.rs` (the lint, and the proof on the real M0 run):
- `live_seed_changes_digest`: the synthetic run with seeds 0 and 1 gives different measured digests; worker
  counts 1 and 8 give the same.
- `live_design_changes_digest`: one link length × 2 changes the measured digest and the design identity in
  `bound`.
- `edit_and_inverse_is_irrelevant`: same design identity, same digest.
- `m0_referee_state_proof` (in the conformance crate, on BD-024's run `g1`, referee, 2 s, built with the
  perturbation flag): one unit in the last place on `q0` changes the final state digest and `RunId`, so the
  proof holds; seeds 0 and 1 give equal chunk digests and an equal final digest with different `RunId`
  (`control_unchanged`); the seed offered as the perturbed input gives `stand-in-suspected`.
- `echo_is_not_change`: a wrapper whose result restates the request (a run identity, the recorded command)
  around fixed measured fields is `stand-in-suspected`; with the whole block named as `measured` the same
  wrapper would pass, which is why those fields are excluded.
- `stand_in_suspected`: the recorded-envelope wrapper is caught for all eight input kinds.
- `unbound_dependency`: a wrapper that perturbs the result but copies the base `bound` block.
- `irrelevant_reader_caught`: a verb variant that hashes the scene's name into its result.
- `lint_missing_proof`: a scratch gate with `depends = ["scene"]` and no `live_` test.
- `gate_not_eligible_without_proof`.

### End-to-end script and logging

`scripts/e2e/live_dependency.sh` (header: `bead=N38b-06 milestone=M0 labels=gauntlet gates=GATE-GAUNT-01
plants=stand-in,unbound`). Every call carries its own key from `e2e_key`. It runs `frob sim run g1 --tier
referee --seconds 2 --seed 0 --key <base> --json`; the same with `--seed 1 --key <seed>`; and, with the
conformance build of `frob` that BD-024's script uses for its perturbed control, the first with `--perturb-ulp
q0 --key <state>`. It asserts that the perturbed run's final state digest and `RunId` differ from the base's,
and that the seed run's four chunk digests and final digest equal the base's while its `RunId` differs; then
runs both plants. Log at `target/e2e-logs/live_dependency/<utc>.ndjson`: commands, exit codes, wall time; base and
perturbed digests per input; `bound` identities; one `assert` per proof and per plant with the first differing
field on failure; the evidence blocks; the `summary`.

### Known answers and negative controls

Negative controls: the stand-in wrapper; the unbound wrapper; the irrelevant-field reader; the echo wrapper
(a whole-block digest must not count as a change). Metamorphic
relations used as the irrelevant side: an edit followed by its inverse returns the same design identity;
permuting world indices permutes results and changes nothing else. Determinism: the proof compares digests
under the declared class; under class D3 it compares task decisions and envelope bounds instead of bits.

## Considerations

- A legitimately memoized result still passes: a perturbed input changes the memo key, so the perturbed run is
  computed afresh; a memo key that omits the input is exactly the defect this proof finds.
- For statistical outputs the perturbation must be large enough to move the measured value beyond its
  interval; the catalogue's factors of 2 are chosen for that.
- Cost: three runs per input per gate; proofs run with the gate, not per change.
