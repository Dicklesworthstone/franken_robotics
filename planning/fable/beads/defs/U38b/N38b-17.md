## Background

GATE-GAUNT-04 is the gate of FrankenRobotics' verification subsystem (the Gauntlet) that certifies the
certifiers: the components whose verdicts everything else trusts. Claim kind: known answer. Threshold (TARGET):
every row of the certifier table meets its threshold, and the certificate mutation corpus holds at least 1,000
mutants per proof kind with zero accepted. Earliest milestones: M1 for the certificate checker; M3 for the
lanes (qualification, solvability, rank agreement, screening audits, monitors, pre-analysis, rare-event
bounds, attribution, conformal bands, claim product, determinism classifier, energy audit, the harness). The
reason for the gate is that a false certificate is worse than an ordinary wrong answer, and a broken certifier
is invisible to every test that relies on it.

This bead is the end-to-end script that measures the gate from the user's side: it drives the real `frob`
binary and the standalone auditor `frob-verify`, reads the certifier register, and for every row runs both
halves of the self-test (the certifier on known inputs; the broken certifier, which must fail).

## Scope

In: the script, its row table, its measured values and log. Out: the self-tests themselves (N38b-10 to
N38b-16) and the mechanisms they test.

## Technical approach

`scripts/e2e/certifiers.sh <M1|M3|M5>` (header: `bead=N38b-17 milestone=M3 labels=gauntlet,gate
gates=GATE-GAUNT-04 plants=broken-certifier-per-row`). The milestone argument selects the rows due.

|---|---|---|---|---|

Steps per row: (1) run the command on the row's fixture; (2) compare the measured value with the threshold;
(3) rebuild or re-run with the row's broken certifier and require the self-test to FAIL; (4) emit the row's
`metric` and `assert` events. A row whose broken certifier is not caught fails the gate whatever its first
half says. Rows not yet due are listed as `not-due`, never as passed.

**Measured value of the gate.** (rows meeting threshold, rows due, broken certifiers caught, mutants accepted);
threshold (due, due, due, 0).

**Logging.** `target/e2e-logs/certifiers/<utc>.ndjson` and a transcript. Per row: `cmd` events with the exact
command, exit code and wall time; `metric` events with value, unit and threshold; `refusal` events with the
refusal code where the expected outcome is a refusal; `assert` events for both halves, with on failure the
first differing value (for the corpus: the first accepted mutant's class and hash) and the artifact paths; the
envelope's evidence block (claim, class, tier, determinism, identities, seed). The `summary` gives rows passed
and failed, controls caught, and GATE-GAUNT-04. No sealed campaign field and no private-scene data appear.

## Acceptance criteria

- [ ] The script exits 0 only if every due row meets its threshold and every due broken certifier is caught.
- [ ] Run with `M1` it measures the eight M1 rows; with `M3` all rows except the product binding of CERT-15.
- [ ] A planted regression in any single certifier (the checker skipping quantifiers, reused clusters, a
      point-robot oracle, whole-population τ, a padding monitor, a best-input claim product, the audit switched
      off) makes the script exit non-zero and names the row.
- [ ] The gate is recorded in two parts, each by a session that implemented none of the certifiers.
- [ ] Runs above the default machine envelope print their reduced counts and are not recorded as passes at
      full count.

## Test plan

### Unit tests

The units are those of N38b-10 to N38b-16. One meta-test here, `certifier_rows_match_register`
(`crates/frob-conformance/tests/certifier_register.rs`): the script's row table and the register have the same
nineteen identifiers and due milestones.

### End-to-end script and logging

As above; selected by `scripts/e2e/run-all.sh --label gate --milestone <M>`.

### Known answers and negative controls

Known answers: the thresholds in the table (551 of 10⁴; 123 of 2,000; 19/21; 9.5%; the enumeration counts).
Negative controls: one broken certifier per row; a vacuous variant of the script that skips step 3 is planted
in the harness self-test and must be flagged. Determinism: counts identical twice on one machine for a fixed
seed; device rows are compared at the level of outcomes.

## Considerations

- The gate is known-answer in kind: it shows each certifier behaves on planted inputs, not that it is correct
  everywhere.
- A certifier added later appends a register row and a table row; the meta-test keeps the two together.
- Cost is dominated by CERT-07 through the real verb and by CERT-11 at 10⁶ traces; both run nightly.
