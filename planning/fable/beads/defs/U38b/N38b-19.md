## Background

In FrankenRobotics a gate (a numbered acceptance threshold) is recorded in `registries/gates.toml`. The
verification subsystem (the Gauntlet, crate `frob-conformance`) has no agent verb: a tier of the harness is a
Cargo test target, a run writes a *receipt* (a canonical JSON file named by the BLAKE3 hash of its bytes, with
the commit, toolchain, hardware fingerprint, seed, the measured values, one line per negative control and one
line per gate), and a *recording session* then enters the gate's row, citing the receipt. This bead is that
recording step.

Two rules make the step more than a file edit. First, invariant INV-GAUNT-02: every gate that records a pass
has at least one registered negative control that was caught in the same run. Second, invariant INV-GAUNT-05
("no self-certification"): a pass is recorded by a session that did not implement the capability; the exit
review of a milestone is likewise done by a fresh-context session. The reason is recorded experience from
sibling projects, where the swarm that built a thing also declared it done (risk signal: "a PASS recorded by the
session that implemented the capability").

DESIGN: the recorder is a library function plus a Cargo example target, `cargo run -p frob-conformance --example
record_gate -- --gate <id> --receipt <hash> [--part <milestone>]`. An example target is neither a verb nor an
`xtask` subcommand, so the harness is not reachable through the surface it judges. Rejected: letting the tier
runner write the status itself (the session that ran the test would certify it); a `frob gate record` verb.

## Scope

In: the recording algorithm; how the two session identities are obtained; the same-run rule; the recorder's
refusals; the side effects (control history, bead log line, regenerated views). Out: the record schema
(N38b-18); the register layer's extra validation and kill decisions (`needs`); the views' generators (N38b-20).

## Technical approach

**Session identities (DESIGN).** Every agent session has an identifier (`session:<name>`), exported as
`FROB_SESSION` by the session harness and written as a `Frob-Session:` trailer on each commit it makes.
- `recorded.session` = `FROB_SESSION` of the session running the recorder.
- `recorded.implemented_by` = the set of sessions on commits that changed the capability: the union of
  `Frob-Session` trailers over commits, from the opening of the beads that deliver the gate up to the receipt's
  commit, that touch the crates named by those beads; plus every session on an `implement` line of those beads'
  logs. Stored sorted and comma-joined.
- Refusal `self-certified` when `recorded.session` is a member of `implemented_by`.
This is a discipline check, not authentication: an identity can be falsified by a session that sets another
name. The planted self-certification test and the exit review are the detection; the limit is stated in
`CONTRACT.md`.

**Algorithm (`register::record`).**
1. Load the receipt `target/gauntlet/receipts/<hash>.json`; recompute BLAKE3 of the bytes; mismatch →
   `receipt-hash-mismatch`.
2. The receipt's `commit` must be an ancestor of `HEAD` and its `dirty` flag false → else
   `receipt-commit-unknown`, `receipt-dirty-tree`.
3. Find the gate's line. `pass` in the receipt is required to record `pass`; `fail` records `fail` with the first
   differing value; `not-eligible` records nothing (`gate-line-not-eligible`).
4. Same-run rule: every identifier in the row's `controls` must appear in the receipt's `controls` list for this
   gate with outcome `caught`. Missing → `control-missing-from-receipt`; `missed` or `stale` →
   `control-not-caught`. An empty `controls` list → `pass-without-control`.
5. Compute the session identities; refuse `self-certified`.
6. Resolve every evidence item and the `claim_id` in the artifact graph; a dangling or tombstoned node →
   `evidence-unresolved`.
7. Run the register layer's validator on the candidate row.
8. Write: `status`, `measured` (the receipt's measured values with units and intervals, or the count),
   `evidence`, `recorded = { date, session, implemented_by }`, and the receipt hash, commit and command.
9. Side effects in the same commit: set each control's `last_seen` in `registry/controls.toml`; append one line
   per control to `registry/control_history.ndjson`; append a line to the delivering bead's log
   `docs/delivery/logs/<bead>.ndjson` (verdict, claim identifiers, `recorded_by`, gate); regenerate the status
   views.
10. Print the row and the list of regenerated files. Nothing is written if any step refuses.

**Other statuses.** `killed`: requires the kill gate's identifier, the fallback's name and the decision record;
the row then describes the capability by the fallback's name. `no-claim`: only for a `reality` gate, with the
reason (for example "no dataset admitted"). `fail`: recorded with the measured value; a failing value is a
record and blocks the milestone exit unless a kill gate covers it.

**Refusal reasons (recorder errors, not agent-facing refusal codes; exit status 3).** `receipt-hash-mismatch`,
`receipt-commit-unknown`, `receipt-dirty-tree`, `gate-line-not-eligible`, `pass-without-control`,
`control-missing-from-receipt`, `control-not-caught`, `self-certified`, `evidence-unresolved`, each with the
repair (re-run the tier; register the control first; record from a fresh session; cite a live receipt).

**Evidence and determinism.** A recorded row is evidence of class `Tested` (or the class of the claim it
cites); the recorder is deterministic (D0) apart from `date`.

## Acceptance criteria

- [ ] Recording a passing receipt writes the row, the control history, the bead log line and the views in one
      commit; re-running with the same receipt is a no-op.
- [ ] A planted self-certification is refused (`self-certified`), and the same receipt recorded by another
      session is accepted (GATE-GAUNT-10, clause 2).
- [ ] A planted pass whose receipt shows one control `missed`, or omits a listed control, is refused
      (GATE-GAUNT-10, clause 3; INV-GAUNT-02).
- [ ] A receipt altered by one byte, from a dirty tree, or from an unknown commit is refused.
- [ ] A pass citing a tombstoned evidence item is refused.
- [ ] `measured` in the written row equals the receipt's measured values, never the threshold text.
- [ ] `CONTRACT.md` states the identity mechanism and its limit.

## Test plan

### Unit tests

`crates/frob-conformance/tests/recorder.rs`, on a scratch repository built by the test (real git, real files):
- `record_pass_happy_path`: gate with controls NC-A and NC-B, both `caught` in the receipt, recorder session
  `s2`, implementer `s1` → row `pass`; history has two lines; the log line has `recorded_by: "session:s2"`.
- `record_idempotent`: second call changes no byte.
- `refuse_self_certified`: recorder `s1`, commits by `s1` → refused; a co-implementer set {`s1`, `s3`} refuses
  `s3` as well.
- `refuse_control_missed`, `refuse_control_absent_from_receipt`, `refuse_empty_controls`.
- `refuse_tampered_receipt`, `refuse_dirty_tree`, `refuse_unknown_commit`.
- `refuse_unresolved_evidence`.
- `fail_is_recorded`: a failing receipt writes `fail` with the first differing value.
- `killed_needs_fallback`, `no_claim_only_reality`.
- `measured_copied_from_receipt`: value "0.9207 (1)" with its unit, not the threshold sentence.

### End-to-end script and logging

`scripts/e2e/status_accounting.sh` (bead N38b-21) drives the recorder from the user's side. This bead's script,
`scripts/e2e/record_gate.sh` (header: `bead=N38b-19 milestone=M0 labels=gauntlet,gate gates=GATE-GAUNT-10
plants=self-certify,missed-control,tampered-receipt`), runs a small tier filter, records its gate from a second
session identity, then replays the three plants, each of which must be refused with its reason. Log at
`target/e2e-logs/record_gate/<utc>.ndjson`: commands with exit codes and wall time, the receipt hash and the
digest of `gates.toml` before and after, one `refusal` event per plant with the reason, the evidence block of
the recorded row, and the `summary`.

### Known answers and negative controls

Negative controls: the self-certifying session; the missed control; the omitted control; the tampered receipt;
the tombstoned evidence. Live-dependency proof: changing one measured value in a fresh receipt changes the
written `measured` and the regenerated README cell. Determinism: D0 apart from `date`; two recordings of one
receipt by one session are byte-identical.

## Considerations

- A bead closes only with a log line whose verdict is `pass`, whose claim identifiers resolve and whose
  recording session is not the implementing session (existing refusal FROB-REF-815 for a close without a
  resolving line from another session). A closed bead is not acceptance: acceptance is the gate's row.
- A close reason shared by several beads is a failure signal handled by the close audit (N38b-03).
- If the swarm runs with one session only, nothing can pass: that is the intended fail-closed behaviour.
- Performance: recording is file work; no budget concern.
