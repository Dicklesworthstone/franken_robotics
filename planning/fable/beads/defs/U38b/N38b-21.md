## Background

GATE-GAUNT-10 is the status-accounting gate of FrankenRobotics' verification subsystem (the Gauntlet). Claim
kind: known answer. Threshold (TARGET): the README status table equals a fresh generation from
`registries/gates.toml`; a planted self-certification and a planted PASS with an uncaught control are each
refused. Earliest milestone M0, then every milestone exit. It protects two invariants: a pass is recorded by a
session that did not implement the capability (INV-GAUNT-05), and status tables are generated and never edited
(INV-GAUNT-06); and it depends on a third, that every passing gate has a negative control caught in the same
run (INV-GAUNT-02). This bead is the end-to-end script that measures the gate from the user's side, on a real
harness run, and records it.

## Scope

In: one script, its fixtures, the gate's G0 entry `tests/status_accounting.rs` (step 8) and its log. Out: the
mechanisms it drives (record schema N38b-18, recorder
N38b-19, generators N38b-20, control runner N38b-04).

## Technical approach

`scripts/e2e/status_accounting.sh` (header: `bead=N38b-21 milestone=M0 labels=gauntlet,gate
gates=GATE-GAUNT-10 plants=self-certify,uncaught-control,edit-readme`). It works in a scratch clone of the
repository so that the working tree is never modified, with seed 0 and two session identities
`session:e2e-impl` and `session:e2e-fresh`.

Steps.
1. `start`: log the digest of the checkout's `registries/gates.toml`; clone to the scratch directory; export
   `FROB_SESSION=session:e2e-impl`; write the fixture gate's row and its two control records into the clone's
   registries and commit them with one trivial commit to the fixture gate's capability, so that the implementer
   set is known and the receipt of step 2 comes from a clean tree (the recorder refuses a dirty one,
   `receipt-dirty-tree`, N38b-19 step 2).
2. `run-tier`: `FROB_TEST_SEED=0 cargo test -p frob-conformance --test g0_laws --features gauntlet-mutations --
   GATE-TEST-ACCT` (a fixture gate with two controls registered for this script: a no-claim-raise law and its
   mutation; without the feature the mutation cannot be planted and the control reads `stale`). Assert a
   receipt exists and its file name equals the BLAKE3 of its bytes; assert both controls `caught`.
3. `record-fresh`: with `FROB_SESSION=session:e2e-fresh`, `cargo run -p frob-conformance --example record_gate
   -- --gate GATE-TEST-ACCT --receipt <hash>`. Assert exit 0, status `pass`, `measured` non-empty and unequal
   to the threshold text, `recorded.session = session:e2e-fresh`.
4. `views`: regenerate; assert `README.md` gate block equals a fresh generation (clause 1); `cargo xtask
   check-generated` exits 0.
5. `plant-self-certify`: reset the row; record the same receipt with `FROB_SESSION=session:e2e-impl`. Assert
   non-zero exit and reason `self-certified`; assert `gates.toml` unchanged by digest (clause 2).
6. `plant-uncaught-control`: produce a second receipt with the control's mutation replaced by a no-op (the
   control is `missed`); record it from the fresh session. Assert refusal `control-not-caught` and an unchanged
   file. Then hand-write `status = "pass"` into the row and run the validator: assert it rejects the row
   (clause 3).
7. `plant-edit-readme`: change one "open" cell (the printed form of `not-run`, N38b-20) to "pass" in the README
   block; assert the equality test and
   `check-generated` both fail and name the line.
8. `gate-entry`: in the checkout of record (never committing, never recording), run the gate's own entry,
   `FROB_TEST_SEED=0 FROB_MILESTONE=<milestone> cargo test -p frob-conformance --test g0_laws --features
   gauntlet-mutations -- GATE-GAUNT-10`. The entry (`tests/status_accounting.rs`, registered by this bead in the
   G0 target; DESIGN) checks clause 1 with N38b-20's equality test on the committed views and clauses 2 and 3 by
   calling the recorder in-process on a scratch repository it builds (as N38b-19's `tests/recorder.rs` does),
   and in the same run the control runner plants the gate's three controls (N38b-23: the self-certifying
   session, the pass with an uncaught control, the hand-edited README cell), so the receipt carries
   GATE-GAUNT-10's line and its controls `caught`. This is the receipt the gate is recorded from: a receipt of
   the clone (steps 2 and 6) names a commit that is not an ancestor of the checkout's `HEAD` and is refused
   `receipt-commit-unknown` (N38b-19 step 2).
9. `end`: write the gate's own measured values: clause 1 `equal` (true), clause 2 `refused` (true), clause 3
   `refused` (true), and the hash of the step-8 receipt; assert the checkout's `registries/gates.toml` has the
   digest logged at step 1. Every write of this script goes to the clone's copy of `gates.toml`, never to the
   one of record; the script records nothing in the real file (a fresh session does that from the step-8
   receipt).

**Logging.** Through the shared helper to `target/e2e-logs/status_accounting/<utc>.ndjson` and a transcript
beside it. Every line has `ts`, `script`, `bead`, `step`, `event`. `cmd` events carry the exact command line,
exit code and wall time; `assert` events the compared digests (`gates.toml` before and after, the README block,
the receipt hash) and, on failure, the first differing line and the scratch paths; `refusal` events the reason
string; `metric` events `controls_caught` (2 of 2, threshold all), `views_equal` (1, threshold 1),
`plants_refused` (3, threshold 3). The evidence block is `{claim: known-answer, class: Tested, tier: G0:host,
determinism: D0, seed: 0}`. The final `summary` gives assertions passed and failed and names GATE-GAUNT-10.

## Acceptance criteria

- [ ] The script exits 0 on the clean tree and non-zero if any assertion fails.
- [ ] Each of the three plants is caught, with its reason in the log.
- [ ] The log validates against the end-to-end log schema and contains no private-scene data.
- [ ] The script is idempotent: two runs leave the repository unchanged and produce equal assertion counts.
- [ ] GATE-GAUNT-10 is recorded at M0 from the receipt of step 8 (the checkout's run of the gate's entry, its
      three controls `caught`) by a session other than the implementer, with measured values, and is
      re-measured at every milestone exit.
- [ ] The checkout's `registries/gates.toml` is byte-identical before and after the script; every write goes to
      the scratch clone's copy.

## Test plan

### Unit tests

None of its own: the units are those of the mechanisms. The harness self-test covers the helper functions
(`e2e_expect_caught`, digest comparison).

### End-to-end script and logging

As above; run by `scripts/e2e/run-all.sh --label gauntlet --milestone M0` and at each exit.

### Known answers and negative controls

Negative controls, all required to be caught: the self-certifying session; the pass with an uncaught control
(both through the recorder and through a hand-written row); the hand-edited README cell. A deliberately broken
variant of the script's own assertion (comparing the README with itself) is planted in the harness self-test
and must be flagged as vacuous. Determinism: the assertion outcomes are identical twice on one machine and on
both platforms.

## Considerations

- The fixture gate `GATE-TEST-ACCT` lives only in the scratch clone's registry; the committed `gates.toml`
  never contains test gates.
- At later exits the script is run against real gates of the milestone as well (sampling three passing rows and
  re-verifying their receipts), so that the gate is not measured on a fixture alone.
- If only one session identity is available the gate cannot pass; the exit review must supply a fresh one.
