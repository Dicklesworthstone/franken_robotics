## Background

The known-answer suite of FrankenRobotics has 835 rows at plan time. A row needs a tolerance with a reason:
`exact` for integers, rationals, Booleans, verdicts and digests; for real values the tolerance of the owning
gate, scaled as the numerics rules require. 133 rows are printed with tolerance `to set` because their chapter
states none, or only part of one, for a real-valued truth (FACT, counted from the suite; 70 are `to set`
outright and 63 state a partial tolerance such as "exact for the refusal; to set for the ceiling"). Such a row
is an obligation, not a test: it is not eligible to pass until its derivation file states a tolerance.

This is open question OPEN-GAUNT-2 of the verification subsystem (the Gauntlet): **tolerances for the 133 rows
printed `to set`.** Owner: each owning chapter. Blocks: GATE-GAUNT-02 (every known-answer row due at a
milestone passes inside its tolerance; no row with tolerance `to set` is counted; the count of such rows is
printed and is zero by M3 for rows due by M3). Fail-closed default: the row is not counted as passing.

This bead closes the question as a program: the rules by which a tolerance is set, the complete list of
affected rows by chapter, the registry mechanics, and the burn-down to zero.

## Scope

In: the tolerance rules; the list; the procedure per row; the checks. Out: the rows' content (chapter registry
beads); negative controls for rows that state none (N38b-28 to N38b-34); values that disagree with their own
formulas (N38b-50 to N38b-61).

## Technical approach

**Rules for setting a tolerance (applied in order; the first that fits is used; each result is written into
the row's derivation file with its reason).**
1. *The truth is an integer, a rational, a Boolean, a verdict, a label or a digest*: `exact`. Many rows printed
   `to set` are of this kind once the derivation states the exact rational behind a rounded printed value.
2. *The truth is printed arithmetic of exact inputs* ("about 1.46", "about 7.7"): register the exact rational
   (842.8/575.7; 1/(1 − 0.87)) as the truth and set the tolerance to half a unit in the last printed digit of
   the text, so that the printed value is checked as a rounding of the exact one.
3. *The owning gate states a tolerance for the quantity*: use it (`gate` tolerance), scaled in physically
   scaled units.
4. *A real-valued result of a numerical method on a tier*: tolerance = 2 × (truncation bound + round-off bound
   + tier envelope) from the derivation's error budget, each term stated; on the referee in double precision
   the default is 10⁻⁹ relative for closed forms and the integrator's order for trajectories; on
   single-precision tiers the fidelity envelope of the quantity.
5. *A FACT quoted from a pilot, a sibling's source or a publication*: the tolerance is the source's stated
   precision; the row stays `to set` until the source is re-read or the pilot re-run.
6. *A truth that the chapter names and does not write*: no tolerance can be set before the derivation file
   exists; the row is listed under "derivation owed" (N38b-47) and stays an obligation.

**Procedure per row.**
1. The owning chapter's registry bead applies the rules and proposes `tolerance = { kind, value, unit, reason }`.
2. The derivation file `docs/derivations/<fixture>.md` gains an "error budget" section (truncation order,
   round-off bound, tier envelope) that yields the value.
3. The registry record changes from `to-set` to the kind; the loader then computes the row's eligibility.
4. A meta-test (`tests/tolerance_obligations.rs`) holds the list above as data and reports, per chapter, rows
   still `to-set`; the report is printed in every G1 account. For rows due at or before M3 the count must be
   zero at the M3 exit.

**Fail-closed behaviour until set.** `assert_ka` on such a row runs the comparison and reports `obligation`,
never `pass`; GATE-GAUNT-02's count excludes it and prints it.

## Acceptance criteria

- [ ] The list of 133 is held as data and matches the registry's `to-set` rows at plan time; a mismatch is
      reported with the differing numbers.
- [ ] Every row whose tolerance is set carries a kind, a value with unit and a reason, and its derivation file
      has an error budget that produces the value.
- [ ] No row with tolerance `to-set` is counted as passing by any gate.
- [ ] The count of `to-set` rows due by M3 is zero at the M3 exit; rows of later milestones are zero by their
      milestone.
- [ ] A tolerance wider than the distance between the truth and the row's negative-control value is rejected
      (the control could no longer fail the row).

## Considerations

- A tolerance is part of the claim: loosening one after a failure is a dated amendment with its reason, made
  before the next measurement, never a quiet edit.
- Where a recomputation disagrees with a printed value the row keeps the printed value and is handled by the
  reconciliation beads; this bead does not improve values in transit.
- Twelve of the affected rows are performance arithmetic whose inputs are FACTs to re-read; they fall under
  rule 5 and stay obligations until re-read.
