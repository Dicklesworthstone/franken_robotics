## Background

The known-answer suite of FrankenRobotics has 835 rows at plan time. A row needs a tolerance with a reason:
`exact` for integers, rationals, Booleans, verdicts and digests; for real values the tolerance of the owning
gate, scaled as the numerics rules require. 133 rows are printed with tolerance `to set` because their chapter
states none, or only part of one, for a real-valued truth (FACT, counted from the suite; 70 are printed `to
set` with nothing more, and 63 carry a qualifier: a partial tolerance such as "exact for the refusal; to set for
the ceiling", the precision the text prints, or the gate whose number is still to come). Such a row is an
obligation, not a test: it is not eligible to pass until its derivation file states a tolerance.

This is open question OPEN-GAUNT-2 of the verification subsystem (the Gauntlet): **tolerances for the 133 rows
printed `to set`.** Owner: each owning chapter. Blocks: GATE-GAUNT-02 (every known-answer row due at a
milestone passes inside its tolerance; no row with tolerance `to set` is counted; the count of such rows is
printed and is zero by M3 for rows due by M3). Fail-closed default: the row is not counted as passing.

This bead closes the question as a program: the rules by which a tolerance is set, the complete list of
affected rows by chapter, the registry mechanics, and the burn-down to zero.

## Scope

In: the tolerance rules; the list of the 133 rows as data; the procedure per row; the meta-test and its
burn-down report; the check that a tolerance is narrower than the gap to the row's control. This bead sets no
row's tolerance value itself: it decides how a value is set, by whom, and how the program knows when none is
left.

Out, with the bead that has it: the rows' content and the tolerance values, which each owning chapter's registry
bead and specification beads set and write into the derivation file. In particular, of the 47 rows of the
constructions, the 23 of constructions C-01 to C-15 (KA-040 to KA-043, 046 to 049, 054, 056, 059 to 061, 064 to
066, 074, 076, 077, 081 to 083, 086) already have their values in the registry bead N10-KA1, set in agreement
with `SPEC-C-01` to `SPEC-C-15`; those values stand and are not decided a second time here (N10-KA1 also refines
two rows that were never `to set`, KA-053 and KA-088). The other 24 construction rows (094 to 187) are carried
as printed by N10-KA2 and N10-KA3 and are set by their specification beads under the rules below. Also out:
negative controls for rows that state none (N38b-28 to N38b-34); values that disagree with their own formulas
(N38b-50 to N38b-61).

## Technical approach

**Rules for setting a tolerance (applied in order; the first that fits is used; each result is written into
the row's derivation file with its reason).**
1. *The truth is an integer, a rational, a Boolean, a verdict, a label or a digest*: `exact`. Many rows printed
   `to set` are of this kind once the derivation states the exact rational behind a rounded printed value.
2. *The truth is printed arithmetic of exact inputs* ("about 1.46", "about 7.7"): register the exact rational
   (842.8/575.7; 1/(1 − 0.87)) as the truth and set the tolerance to half a unit in the last printed digit of
   the text, so that the printed value is checked as a rounding of the exact one.
3. *The owning gate states a tolerance for the quantity*: use it (`gate` tolerance), scaled in physically
   scaled units.
4. *A real-valued result of a numerical method on a tier*: tolerance = 2 × (truncation bound + round-off bound
   + tier envelope) from the derivation's error budget, each term stated; on the referee in double precision
   the default is 10⁻⁹ relative for closed forms and the integrator's order for trajectories; on
   single-precision tiers the fidelity envelope of the quantity.
5. *A FACT quoted from a pilot, a sibling's source or a publication* (the truth is the quoted number itself,
   with no arithmetic of this project behind it): the tolerance is the source's stated precision; the row stays
   `to set` until the source is re-read or the pilot re-run. Where the truth is arithmetic on quoted inputs
   (1/(1 − 0.87) with 87% from a recorded pilot), rule 2 sets the tolerance of the arithmetic and the row keeps
   its FACT label: it may pass as arithmetic, and a gate cites it only after the source is re-read or the pilot
   re-run (the registry's FACT rule, N38a-12). The two conditions are separate and both are printed.
6. *A truth that the chapter names and does not write*: no tolerance can be set before the derivation file
   exists; the row is listed under "derivation owed" (N38b-47) and stays an obligation.

**Rules and owners' values (DESIGN).** The rules give the default and the form of the reason; the derivation
file is the authority for a row's value. Where an owner has set a value with its error budget that is tighter
or looser than a rule's default (for example 10⁻¹² relative against the integrator's discrete parabola for the
ballistic-flight row KA-047, where rule 4's referee default is 10⁻⁹), the owner's value stands and its `reason`
names the rule it falls under and why it departs from the default. The meta-test checks that a reason and an
error budget exist, and the control-gap condition; it does not recompute a value from the rules.

**Procedure per row.**
1. The owning chapter's registry bead applies the rules and proposes `tolerance = { kind, value, unit, reason }`
   (for the 23 rows above this has been done in N10-KA1; the record there already carries the value).
2. The derivation file `docs/derivations/<fixture>.md` gains an "error budget" section (truncation order,
   round-off bound, tier envelope) that yields the value.
3. The registry record changes from `to-set` to the kind; the loader then computes the row's eligibility.
4. A meta-test (`tests/tolerance_obligations.rs`) holds the list above as data
   (`registry/tolerance_obligations_plan_time.toml`: one record per KA number with its chapter and printed
   tolerance text) and reports, per chapter and per due milestone, the rows still `to-set`, by KA number. The
   report is the "tolerance" column of the one burn-down report of N38b-49 (`target/gauntlet/obligations.json`),
   not a second report; it is printed in every G1 account. For rows due at or before M3 the count must be zero
   at the M3 exit.
5. The reason check: a tolerance set on a row of the list must name its rule ("rule 1" to "rule 6") in
   `reason` and, for a real value, point at the error-budget section; otherwise the meta-test fails with
   `tolerance-without-rule` and the KA number.
6. The control-gap check: for a row whose control states a value (`expect` of its NC record), the loader
   rejects a tolerance t with t ≥ |truth − control value| (`tolerance-swallows-control`), printing both
   numbers; a row whose control has no numeric value (a refusal, a verdict) is exempt and says so.

**Fail-closed behaviour until set.** `assert_ka` on such a row runs the comparison and reports `obligation`,
never `pass`; GATE-GAUNT-02's count excludes it and prints it.

## Acceptance criteria

- [ ] The list of 133 is held as data and matches the registry's `to-set` rows at plan time; a mismatch is
      reported with the differing numbers.
- [ ] Every row whose tolerance is set carries a kind, a value with unit and a reason, and its derivation file
      has an error budget that produces the value.
- [ ] No row with tolerance `to-set` is counted as passing by any gate.
- [ ] The milestone rule is enforced by the meta-test: a run with the milestone set to M3 and one planted
      `to-set` row due at M2 fails and names the row; the same registry at M1 prints the row and does not fail.
      (The count itself reaching zero is measured at the M3 exit by GATE-GAUNT-02; rows of later milestones
      are zero by their milestone.)
- [ ] A tolerance wider than the distance between the truth and the row's negative-control value is rejected
      (the control could no longer fail the row).
- [ ] A tolerance set on a row of the list whose `reason` names no rule (1 to 6) is rejected by the meta-test
      (rows never printed `to set` are not subject to this check); a row with arithmetic on
      quoted inputs (KA-818) shows both conditions: the arithmetic tolerance of rule 2 and the FACT condition
      that keeps a gate from citing it before the source is re-read.

  18, 3, 2, 4, 1, 2, 2, 1, 12). The comparison is with the suite as printed (the baseline the registry keeps of

- `constructions_part1_already_set`: once N10-KA1's records are loaded, the 23 rows of C-01 to C-15 report
  `set` with a reason, and the constructions' burn-down count is 24.
- `rule_2_printed_rounding`: truth 842.8/575.7 = 1.46396 with printed "1.46" → tolerance 0.005, passes; printed
  "1.47" would fail. Second case: 1/(1 − 0.87) = 100/13 = 7.6923 with printed "7.7" → tolerance 0.05, passes;
  printed "7.8" (|7.8 − 7.6923| = 0.108) fails.
- `rule_1_exact_for_counts`: a row whose truth is the integer 616 (decision instants) set by rule 1 has kind
  `exact`; an observed 615 fails, 616 passes; a rule-1 row given kind `rel` is rejected (`exact-kind-required`).
- `to_set_is_obligation_not_pass`: a scratch row with truth 1.46396, tolerance `to-set` and an observed value
  of exactly 1.46396 reports `obligation: tolerance`, never `pass`, and GATE-GAUNT-02's count excludes it and
  prints it as 1.
- `rule_named_in_reason`: on a row of the list, a tolerance `{ kind = "rel", value = 1e-9, reason = "looks
  right" }` is rejected with `tolerance-without-rule`; the same with `reason = "rule 4: …"` and an error budget
  is accepted; a row never printed `to set` with a bare reason is not checked.
- `fact_arithmetic_two_conditions`: KA-818 set by rule 2 (truth 100/13, tolerance 0.05) passes as arithmetic and
  is reported `fact: re-read owed` until its source record is marked re-read; a gate citing it is refused.
- `tolerance_narrower_than_control_gap`: thermal row with truth 33.49 s and control 34.08 s: tolerance 0.1
  accepted, 1.0 rejected (`tolerance-swallows-control`, printing 1.0 ≥ 0.59).
- `burn_down_report`: on the seeded registry, the "tolerance" column of `obligations.json` lists 133 rows by
  number; after loading N10-KA1 it lists 110, the constructions' count falling from 47 to 24; per due milestone
  the counts sum to the chapter count.
- `m3_rule_enforced`: with the milestone set to M3, a planted `to-set` row due at M2 fails the check and is
  named; with the milestone set to M1 it is printed and the check passes (before M3 the line reads `not-due`).

### End-to-end script and logging

`scripts/e2e/ka_tolerances.sh` (header: `bead=N38b-27 milestone=M1 labels=gauntlet,registry
gates=GATE-GAUNT-02 plants=count-to-set-row,wide-tolerance,reasonless-tolerance`; sources the STD-E2E helper).
The burn-down script `scripts/e2e/ka_obligations.sh` belongs to N38b-49 (M0); this script is the tolerance
program's own, so that this bead closes on its own log. Steps, each in a scratch copy of the registries:
1. `cargo test -p frob-conformance --test tolerance_obligations` and the G1 target with
   `-- due:<milestone>`; the plan-time list (133; per chapter as above) is asserted against the baseline.
2. The "tolerance" column of `target/gauntlet/obligations.json` is read; one `metric` line per chapter
   (`to_set_rows`, unit `rows`, threshold `== 0` for rows due at or before the current milestone from M3 on,
   printed without threshold before M3) and one per due milestone.
3. The rule-2 known answers (1.46396 against "1.46"; 100/13 against "7.7") through the row comparison, each
   an `assert` with observed, expected, tolerance and unit.
4. Plants, each through `e2e_expect_caught`: `count-to-set-row` (a `to-set` row whose observed value equals the
   truth is offered as a pass: the account must report it as an obligation), `wide-tolerance` (the thermal row
   given tolerance 1.0 s against a control 0.59 s away: the loader must reject it), `reasonless-tolerance` (a
   tolerance whose reason names no rule: rejected).
Log at `target/e2e-logs/ka_tolerances/<utc>.ndjson` with the transcript beside it: every line carries `ts`,
`script`, `bead`, `step`, `event`; each `cmd` line the exact command line, exit code, wall time and the
stdout digest; each `assert` the observed and expected values with tolerance and unit, and on failure the first
differing KA number with its printed and registered tolerance and the paths of the scratch registry and the
obligations file; the `summary` gives counts of assertions passed and failed, controls caught, and names
GATE-GAUNT-02.

### Known answers and negative controls

Known answers: the counts 133, 70 and 63 and the per-chapter table; 110 and 24 once N10-KA1 is loaded; the

## Considerations

- A tolerance is part of the claim: loosening one after a failure is a dated amendment with its reason, made
  before the next measurement, never a quiet edit.
- Where a recomputation disagrees with a printed value the row keeps the printed value and is handled by the
  reconciliation beads; this bead does not improve values in transit.
- Twelve of the affected rows are performance arithmetic (KA-808 to KA-824), several on inputs that quote a
  recorded pilot or a published figure. Their arithmetic is set by rule 2 (or rule 4 where a model is run);
  the FACT inputs keep them from supporting a gate until the source is re-read or the pilot re-run (the
  arithmetic-on-quoted-inputs case of rule 5). Treating them as rule-5 rows outright would leave checkable arithmetic unchecked.
