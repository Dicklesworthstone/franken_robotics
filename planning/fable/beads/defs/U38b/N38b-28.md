## Background

Every row of FrankenRobotics' known-answer suite needs a *negative control*: the mutation or planted failure
that must make the row fail. A row printed `none stated` cannot support a gate until a control is registered.
At plan time 325 of the 835 rows state none (FACT, counted), and a further handful state a boundary behaviour
where a mutation is needed. This is open question OPEN-GAUNT-3 of the verification subsystem (the Gauntlet):
**negative controls for the 325 rows printed `none stated`, and mutations for the rows whose stated control is
a boundary behaviour.** Owner: each owning chapter. Blocks: GATE-GAUNT-01 (every passing gate has a caught
control). Fail-closed default: the row supports no gate.

Seven beads close the question. This one fixes the rule every control must satisfy, replaces the boundary
behaviours, and offers alternates for the first 15 rows, whose registered controls are their owners' (N00-33,
N09-KA). The other six carry the remaining 310 rows by chapter group. Every proposal is DESIGN, to be confirmed by the owning chapter; what is binding is the rule.

## Technical approach

**The rule (a control is accepted by the loader only if all hold).**
1. It is a defect, not a boundary: it names the build, input, design, world or procedure in which the rule is
   broken, never the product's own refusal at a limit.
2. It has one of five kinds: `mutation` (a wrong formula or implementation choice), `planted-input` (a request
   for an unsound conclusion), `planted-design` (a design a wrong screen would accept or discard),
   `planted-world` (a world or pair that separates the shortcut from the rule), `a-a` (a wrong experimental
   procedure, or a scripted adversary).
3. It states what the row then reports (`expect`), and that value differs from the truth by more than the
   row's tolerance; a control whose value lies inside the tolerance, or on the safe side of an inequality, is
   rejected (`cannot-fail`, both numbers printed). The side is read from the row's declared safe direction,
   a field of the known-answer record: `safe = "higher"` for an episode count, a margin or a bound on an
   error, `safe = "lower"` for a claimed probability or a tolerance; the planted value must lie strictly on
   the unsafe side. A row without a declared direction is checked by running the control: a control whose
   run leaves the row passing is `missed`. (Declaring `safe` on every counting row of the suite, and the
   replacement controls of the zero-failure row, are N38b-57's.)
4. It is the shortcut somebody would plausibly take for this row, not an arbitrary edit.
5. It names the gate that owns the row, and it is run every time that gate is run.

**Procedure per row.** (1) Read the row's truth and derivation. (2) Write the tempting wrong derivation and
compute its value. (3) Check rule 3 against the tolerance. (4) Register the control (an NC record with `seed =
"KA-nnn"`), and for a `mutation` add the feature branch in the owning crate. (5) Add the wrong value to the
derivation file under "what the control gives". (6) Run the row with the control planted: it must fail.

**Meta-test (`tests/control_obligations.rs`).** Holds the 325 numbers by chapter as data
(`registry/control_obligations_plan_time.toml`); reports rows still without a registered control per chapter
and per due milestone, by KA number. The report is the "control" column of the one burn-down report of N38b-49
(`target/gauntlet/obligations.json`), printed in every G1 account and in the all-controls run, not a second
report. For rows due at or before M3 the count is zero at the M3 exit. A row counts as closed only when an NC
record with `seed = "KA-nnn"` exists, passes the loader's rule, and names the row's gate.

## Acceptance criteria

- [ ] The rule is enforced by the control loader (`boundary-not-control`, `cannot-fail`, kind closed, gate
      named).
- [ ] KA-444, KA-489 and KA-496 carry a registered mutation in place of the boundary behaviour (an NC record
      that passes the loader, with `removed_check` where a limit is removed and `due` at the mechanism's
      milestone); the stated boundary text stays in the row's history, flagged `boundary-only`.
- [ ] For the fifteen rows the registered controls are N00-33's and N09-KA's; this bead's acceptance does not
      wait for them (the meta-test reports a row as open until its owner's record lands), and each of the nine
      differing alternates (the eight thesis and North-Star rows and KA-033) has a recorded disposition:
      registered as a further control, or declined with a dated note.
- [ ] The meta-test's list equals the registry's `none stated` rows at plan time (325; per-chapter counts 7, 7,
      1, 72, 6, 6, 6, 7, 25, 11, 9, 24, 21, 35, 14, 4, 1, 11, 8, 2, 3, 1, 4, 4, 7, 1, 10, 15, 3).
- [ ] No row without a registered control is counted toward any gate.

## Test plan

### Unit tests

`crates/frob-conformance/tests/control_obligations.rs`:
- `plan_time_list_matches_registry`: 325 rows and the 29 per-chapter counts above, compared with the printed
  baseline (a row that has since gained a control leaves the burn-down count and stays in the plan-time list).
- `control_value_outside_tolerance`: KA-010: 1.15 against 7.69; KA-015: 6.25 against 1.19; KA-016: 3.33 against
  1.96; KA-012: 5.0 against 6.0; each accepted, the gap printed.
- `control_inside_tolerance_rejected` (synthetic): a control whose value is 7.70 for a truth 100/13 = 7.6923
  with tolerance 0.05 is rejected `cannot-fail`.
- `boundary_rows_replaced`: the records of KA-444, KA-489 and KA-496 load; each has kind `mutation`; the
  KA-444 record carries `removed_check`; the "factor 3/4 dropped" variant computes 2.73 mm against 2.48 mm.
- `boundary_only_control_rejected`: a record for KA-444 whose `expect` is `FROB-REF-307` and which has no
  `removed_check` is rejected `boundary-not-control`.
- `safe_side_control_rejected`: the zero-failure count rounded down at p⋆ = 10⁻⁴, δ = 0.05 gives 29,957 ≥ the
  exact 29,956, on the safe side of a minimum: rejected `cannot-fail`, both numbers printed.
- `kind_closed_and_gate_named`: a record with kind `other`, and one with an empty gate list, are rejected.
- `row_without_control_supports_no_gate`: a gate whose only row is KA-021 with no registered control reports
  `not-eligible`, never `pass`.
- `burn_down_by_chapter`: the "control" column of `obligations.json` lists 325 rows on the seeded registry; with
  N00-33's fourteen records and N09-KA's KA-033 record loaded it lists 310, and the three chapters of this bead
  show zero.

### End-to-end script and logging

`scripts/e2e/ka_obligations.sh` (owned by N38b-49, header there, milestone M0; this bead adds the steps named
`controls-*`, and its plants `boundary-only-control`, `safe-side-control` and `control-row-counted` to the
header's `plants` list). The steps, in a scratch copy of the registries:
1. `controls-rule`: `cargo test -p frob-conformance --test control_obligations`; then the three planted records
   (a boundary-only record for KA-444, the safe-side 29,957 record, a row without a control counted toward a
   gate), each through `e2e_expect_caught`, must be rejected with `boundary-not-control`, `cannot-fail` and
   `not-eligible`.
2. `controls-boundary`: loads the three replacement records and logs each as an `assert` (kind, `removed_check`,
   `due`); from the record's `due` milestone on, runs the row's gate with the record planted through the control
   runner and requires `caught`; before it, logs `skip` with reason `not-due: <milestone>` (a skip is never a
   pass).
3. `controls-ka033`: runs KA-033 (G2 · host) with its registered control (N09-KA) and, if accepted, the `a-a`
   alternate, through the tier target; logs truth (3/14 m), the control's observation and `caught`.
4. `controls-burn-down`: reads the "control" column of `target/gauntlet/obligations.json` and emits one
   `metric` line per chapter (`rows_without_control`, unit `rows`, threshold `== 0` for rows due at or before
   the current milestone from M3 on; printed without threshold before M3).
Every line carries the STD-E2E fields: `ts`, `script`, `bead`, `step`, `event`, the exact command line, exit
code and wall time on `cmd` lines, observed and expected with unit on `assert` lines, and on failure the first
differing KA or NC identifier with the scratch-registry path; the `summary` gives assertion and control counts
and names GATE-GAUNT-01 and GATE-GAUNT-02. The fourteen thesis and North-Star rows with their registered
controls are run by `scripts/e2e/ka_controls_part0_8.sh` (N00-33).

### Known answers and negative controls

Known answers: the truths in the table, the count 325 and the 29 per-chapter counts, 2.48 mm against 2.73 mm
for the film limit. Negative controls: the fifteen alternates (each must make its row fail when planted); the
three boundary replacements; a boundary-only control (rejected); a safe-side control (rejected); a control
inside the tolerance (rejected); a row without a control counted toward a gate (refused). Determinism: D0 for
the arithmetic rows and for the burn-down file, byte-identical twice.

## Considerations

- Where an owning chapter already registered a control for one of these rows, its control stands and the
  proposal here is dropped; the meta-test only requires that one exists and obeys the rule.
- A control must stay plausible: if a row's mechanism changes so that the shortcut can no longer be planted,
  the control is `stale` and the row returns to obligation.
