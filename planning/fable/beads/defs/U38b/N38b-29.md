## Background

The known-answer suite of FrankenRobotics holds 154 rows stated by its forty mathematical *constructions* (the
contracts behind the subsystems: Lie-group kinematics, cones, symmetry, design functors, statistics, mission
polarity, numerical similarity, quotienting, tier correction, rare events, forks, requirements, certificates,
structure, variational steps, contact cones, actuators, value of information). 72 of those rows state no
negative control (FACT, counted). A row without a control cannot support a gate, because a test that nothing
can fail validates nothing; this is open question OPEN-GAUNT-3 with the fail-closed default "the row supports
no gate".

This bead proposes one control per row. Each is the shortcut somebody would plausibly take, written so that
the row then reports a value outside its tolerance. Every proposal is DESIGN and is confirmed by the owner of
the construction; the binding rule is the one every control must satisfy (stated in full in N38b-28): a defect
and not a boundary; one of five kinds; a stated wrong outcome outside tolerance and on the unsafe side; a named
gate; run whenever that gate runs.

## Scope

In: 72 proposed controls, their registration as NC records with `seed = "KA-nnn"`, the wrong value added to
each derivation file, and the run that shows each row fails with its control planted. Out: the rows themselves;
tolerances still to set for 47 construction rows (N38b-27); truths named and not written (N38b-47).

Kinds: M = `mutation`, I = `planted-input`, D = `planted-design`, W = `planted-world`, A = `a-a` or scripted
adversary. "→" introduces what the row reports with the defect planted.

**Registration.** For each row: an NC record (`seed`, `gate` = the gate that owns the row or, for a pure law
row, the construction's specification gate; `kind`; `target`; `defect`; `expect`), a feature branch for kind M,
a fixture for kinds I, D and W, and a line "what the control gives" in the derivation file.

## Acceptance criteria

- [ ] Each of the 72 rows has a registered control obeying the rule, confirmed or replaced by its owner.
- [ ] With its control planted each row fails for the stated reason; none is `cannot-fail` or
      `boundary-not-control`.
- [ ] The meta-test of obligations reports zero construction rows without a control at the milestone where the
      row is due (and zero for rows due by M3 at the M3 exit).
- [ ] KA-061's control is registered as an obligation until its derivation file states values.

## Test plan

### Unit tests

`crates/frob-conformance/tests/control_obligations.rs`: `constructions_72_listed` (the 72 numbers);
`wrong_values_outside_tolerance` for the rows with closed forms (064: −¼ against −¾; 096: 15 against 27; 125:
130 against 92; 126: 9 against 6; 134: 0.25 against 2.25; 169: 0.5025 against 0.5625; 179: μNR against
(2/3)·μNR); `each_control_names_a_gate`. Per row, a test `nc_<id>_caught` in the owning crate's conformance
target.

### End-to-end script and logging

`scripts/e2e/ka_obligations.sh` (shared; header in N38b-27) runs these rows with controls planted through the
G0 and G1 tier targets and logs per row truth, tolerance, control value and `caught`, then the burn-down count
for the constructions against the threshold of the current milestone.

### Known answers and negative controls

The 72 proposals are the negative controls. Known answers used to check them: the closed-form wrong values
listed above. Determinism: D0 for host rows; referee rows compare under their tolerance.

## Considerations

- Several proposals coincide with mutations registered elsewhere (backlash as a dead zone; the stripped packet
  queue; the point-robot oracle); the registry then links the row to the existing control instead of making a
  second one.
- A law row (tier G0) whose property test already runs against a mutated implementation needs only the
  registration.
- Mutant builds are grouped by crate; 72 controls cost a handful of rebuilds, not 72.
