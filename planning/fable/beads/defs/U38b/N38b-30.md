## Background

In FrankenRobotics a known-answer row cannot support a gate until a *negative control* is registered for it:
the mutation or planted failure that must make the row fail. Of the 835 rows of the suite, 325 state none
(open question OPEN-GAUNT-3; fail-closed default: the row supports no gate). This bead covers 25 of them, from
four chapters: the conventions shared by every subsystem (frames, inertia parameters, clocks, sensing windows;
6 rows), the proof subsystem called Lemma (6), the algebraic core called Marrow (6) and the design language
called Skeleton (7). It also covers one Marrow row whose printed control admits none under the binding rule:
KA-239 (the group axioms), whose cell names "the eight planted mutations" of N13-18, none of which breaks
associativity, identity or inverse, so that N13-KA reports it `obligation: control` until this bead registers
one; 26 rows in all. Most of these rows are *laws* (tier G0) or round trips; their tempting shortcuts are
dropped factors, wrong orders and omitted canonicalization.

Each proposal below is DESIGN, confirmed by the row's owner. The binding rule (stated in full in N38b-28): a
control is a defect and not a boundary; it has one of five kinds; it states a wrong outcome that lies outside
the row's tolerance and on the unsafe side; it names the row's gate and runs whenever that gate runs.

## Scope

In: 26 proposed controls: seven registered as the row's first control, twelve as second records once the owner
confirms, seven linked to the owner's identical record (see the owners' table below); all as NC records with
`seed = "KA-nnn"`; the check of every control of these rows, the owners' included, against the binding rule;
the wrong outcome recorded in each derivation file; the run showing each row fails with its control planted.

Out, with the bead that has it: the rows themselves, which this bead never edits (the registry beads of the
four chapters, N11-KA, N12-KA, N13-KA and N14-KA, on which this bead depends); the controls those owners or
their mechanism beads already name for nineteen of these rows, which stay each row's first control and are
registered by the owners: KA-196 (N13-02), KA-202 to KA-205 (N13-06), KA-210 (N12-KA), KA-240, -241, -246,
-250, -255 and -257 (N13-KA's test beads), KA-262, -263 and -269 (N14-KA), KA-287 (BD-063), KA-288 (BD-057),
KA-290 (BD-066) and KA-292 (BD-059); tolerances to set (N38b-27); the balancer pole's closed form (N38b-47).

**Registration.** For each row: an NC record (`seed`, `gate` = the row's owning gate, `kind`, `target`,
`defect`, `expect`), a feature branch in the owning crate for kind M or a fixture for kind I, and a line "what
the control gives" in the derivation file.

## Acceptance criteria

- [ ] Each of the 26 rows has a registered control obeying the rule: the owner's first control for the
      nineteen in the owners' table, this bead's for the seven others (KA-239 among them, so that N13-KA no
      longer reports it `obligation: control`); each of the twelve differing proposals is
      registered as a second record or declined with a dated note; the seven identical ones are linked, not
      registered twice (a second record with the owner's defect text is rejected as a duplicate).
- [ ] With its control planted each row due by the current milestone fails for the stated reason; rows due
      later (KA-269 with BD-246 at M3) are run by the control runner from their due milestone and logged
      `not-due` before it.
- [ ] The burn-down (N38b-49) reports zero rows of these four chapters without a control at the milestone
      where each row is due; the M3 rule is enforced by a planted open row due at M2 in a run set to M3.
- [ ] KA-269's second control (wheel inertia omitted) stays an obligation until its closed form is on file;
      its first control (gravity reversed) does not wait for it.

## Test plan

### Unit tests

`crates/frob-conformance/tests/control_obligations.rs` (section for these four chapters):
- `conventions_lemma_marrow_skeleton_26_listed`: the 26 numbers (6, 6, 7, 7 by chapter).
- `owners_first_controls_present`: for the nineteen rows of the owners' table the `registered` record carries
  the owner's defect text and names the row's gate; the seven others carry this bead's.
- `identical_proposals_linked`: the seven linked rows have one record each; a planted duplicate with the
  owner's defect text is rejected.
- `wrong_values_outside_tolerance` for the closed-form rows: 202: ⌊(n − φ)/N⌋ against ⌊(n − φ)/N⌋ + 1, one
  short at every n ≥ φ (n = 120, φ = 0, N = 40: 3 against 4); 226: α·π²/6 = 1.645·α against α; 241: x/2 against
  x at x = (0.3, −0.2, 0.1); 262: 1.59 against 2.44 kg per kilogram (1/(1 − 0.59) = 2.439); 204: a 0.2 N·s
  impact on the shared boundary counted in two windows, 20 N in each, against 20 N in one.
  239: the translation of g·g⁻¹ with the unrotated inverse, (1, −1, 0) m against (0, 0, 0) for R = R_z(π/2),
  p = (1, 0, 0) m.
Per row, `nc_<id>_caught` in the owning crate's conformance target.

### End-to-end script and logging

`scripts/e2e/ka_controls_conventions_to_skeleton.sh` (header: `bead=N38b-30 milestone=M1
labels=gauntlet,registry gates=GATE-GAUNT-01,GATE-GAUNT-02 plants=duplicate-linked-record,uncaught-control`;
sources the STD-E2E helper; scratch copy of the registries). Steps: (1) `check`: `cargo test -p
frob-conformance --test control_obligations -- conventions_lemma_marrow_skeleton`, one `assert` per row (first
control present, owner, rule passed); (2) `run`: for each row due by the current milestone, every control
record (first and second) planted through the G0, G1 and G3 tier targets (`--features
gauntlet-mutations,<crate>/<feature>`,
the record's `feature` field as written, for mutations; the planted fixture for KA-210), an `e2e_expect_caught`
line per record with the truth, the control's outcome and `caught`; rows due later logged `skip` with
`not-due: <milestone>`; (3) `burn-down`: one `metric` per chapter (`rows_without_control`, unit `rows`,
threshold `== 0` for rows due by the current milestone from M3 on); (4) plants: `duplicate-linked-record` (a
second record for KA-203 with the owner's text: rejected) and `uncaught-control` (in the scratch copy KA-226's
mutant made a no-op: its feature still declared, its `cfg` branch removed, so the planted build passes; the
control reads `missed` and the gate line `fail`, N38b-04 step 5; removing the feature itself would read `stale`
and `not-eligible`, a different outcome). Log at
`target/e2e-logs/ka_controls_conventions_to_skeleton/<utc>.ndjson` with the transcript; every line has `ts`,
`script`, `bead`, `step`, `event`; `cmd` lines the exact command, exit code and wall time; failed assertions
the first differing KA or NC identifier with observed and expected and the scratch paths; the `summary` the
counts and gates GATE-GAUNT-01 and GATE-GAUNT-02.

### Known answers and negative controls

The owners' nineteen controls and this bead's seven first controls are the rows' negative controls; the twelve
second records add to them. Several coincide with mutations already registered for metamorphic relations
(packet queues left out of a checkpoint; key-order canonicalization disabled; an input missing from a key; a
two-statement idempotency check); the registry links the row to the existing control. Negative controls of this
bead's own check: the duplicate linked record; the uncaught control. Determinism: D0 on the host and the
auditor.

## Considerations

- Law rows whose property tests run 10⁶ to 10⁹ cases need the control to be caught at the per-change count as
  well, so that a regression is seen before the nightly run.
- KA-263 is a refusal row: its control is the build with the check removed, never the refusal itself.
