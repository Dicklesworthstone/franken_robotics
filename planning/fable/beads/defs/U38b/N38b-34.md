## Background

A known-answer row of FrankenRobotics supports a gate only when a *negative control* is registered for it: the
mutation or planted failure that must make the row fail. 325 of the suite's 835 rows state none (open question
OPEN-GAUNT-3; fail-closed default: the row supports no gate). This bead covers the last 45, in eight chapters:
telemetry and replay (Chronicle, 1 row); calibration against reality (Ground, 4); structure and lifecycle
(Foundry, 4); the command-line and agent surface (Tether, 7); suite consumption (1); numerics and determinism
(10); the performance program (15); safety, security and privacy (3). Many are arithmetic on planning figures
or exactness laws; their tempting shortcuts are a dropped factor, an approximation where an exact count is
needed, and a check removed.

Each proposal is DESIGN, confirmed by the row's owner. The binding rule (in full in N38b-28): a control is a
defect, not a boundary; one of five kinds; a stated wrong outcome outside the row's tolerance and on the
unsafe side; the row's gate named; run whenever that gate runs. For a row whose truth is a refusal, the
control is the build with the check removed, never the refusal itself.

## Scope

In: 45 proposed controls registered as NC records with `seed = "KA-nnn"`; each wrong outcome in its derivation
file; the run showing each row fails. Out: the rows; tolerances (twelve of the performance rows also await
one, N38b-27); the unreconciled values among the performance rows (N38b-50, N38b-51, N38b-58).

## Acceptance criteria

- [ ] Each of the 45 rows has a registered control obeying the rule, confirmed or replaced by its owner.
- [ ] With its control planted each row fails for the stated reason.
- [ ] Refusal rows (729, 734, 802, 805, 812, 825, 835) carry a check-removed mutation, not a boundary case.
- [ ] The obligations meta-test reports zero rows of these eight chapters without a control at the milestone
      where each is due, and zero for rows due by M3 at the M3 exit.

## Test plan

### Unit tests

`crates/frob-conformance/tests/control_obligations.rs`: `chronicle_to_safety_45_listed`;
`wrong_values_outside_tolerance` (731: (0.22/0.5)⁴ = 0.037 against (0.5/0.22)⁴ = 26.7; 747: 0.63 against 36
mm; 753: 10.5 against 4.5%; 759: 18 against 19; 761: 1.17 against 2.34%; 803: 7.7 against 10; 808: 1.74
against 1.58; 817: 1,228,800 against 2,457,600; 818: 1.15 against 7.69). Per row, `nc_<id>_caught` in the
owning crate.

### End-to-end script and logging

`scripts/e2e/ka_obligations.sh` (shared; header in N38b-27) runs these rows with controls planted and logs per
row the truth, tolerance, control value and `caught`, then the final burn-down: 325 rows, by chapter, against
zero for those due.

### Known answers and negative controls

The 45 proposals are the negative controls; several link to existing controls (sequential draws; the offset
range [0, 8); the claimed ratio above the ceiling). Determinism: D0 on the host; the device row (826)
compares measured memory, which is a distribution.

## Considerations

- The performance rows are planning arithmetic whose inputs are FACTs to re-read; a control can be registered
  now, and the row counts only once its inputs are re-read and its tolerance set.
- Safety corpora grow; a hostile input found in use is appended and becomes a permanent control.
