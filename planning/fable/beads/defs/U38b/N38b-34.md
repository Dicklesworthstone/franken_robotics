## Background

A known-answer row of FrankenRobotics supports a gate only when a *negative control* is registered for it: the
mutation or planted failure that must make the row fail. 325 of the suite's 835 rows state none (open question
OPEN-GAUNT-3; fail-closed default: the row supports no gate). This bead covers the last 45, in eight chapters:
telemetry and replay (Chronicle, 1 row); calibration against reality (Ground, 4); structure and lifecycle
(Foundry, 4); the command-line and agent surface (Tether, 7); suite consumption (1); numerics and determinism
(10); the performance program (15); safety, security and privacy (3). Many are arithmetic on planning figures
or exactness laws; their tempting shortcuts are a dropped factor, an approximation where an exact count is
needed, and a check removed.

Each proposal is DESIGN, confirmed by the row's owner. The binding rule (in full in N38b-28): a control is a
defect, not a boundary; one of five kinds; a stated wrong outcome outside the row's tolerance and on the
unsafe side; the row's gate named; run whenever that gate runs. For a row whose truth is a refusal, the
control is the build with the check removed, never the refusal itself.

## Scope

In: 45 proposed controls registered as NC records with `seed = "KA-nnn"` (first, second or linked, by the
owners' rule below); the check of every control of these rows, the owners' included, against the binding
rule; each wrong outcome in its derivation file; the run showing each row fails. Out: the rows (N29-KA,
N30-KA, N32-KA, N33-KA, N35-KA, N36-KA and N37-KA, on which this bead depends; N30-KA is an M1 registry, so its
four Ground rows are present from M1, and a row due at M5 is reported `not-due` until then; the Foundry rows in
N31-KA, an M5 registry, are registered when those rows land and are reported `open: row not registered` until
then); the controls owners already register, which stay first; tolerances
(twelve of the performance rows also await one, N38b-27); the unreconciled values among the performance rows
(N38b-50, N38b-51, N38b-58).

## Acceptance criteria

- [ ] Each of the 45 rows has a registered control obeying the rule, confirmed or replaced by its owner; the
      34 rows of the owners' table have the owner's record first (sixteen linked, eighteen with a second record
      from this bead); no row has two records both marked first; the four Ground rows are present from M1
      (N30-KA); the Foundry rows are reported `open: row not registered` until N31-KA lands at M5.
- [ ] With its control planted each row due by the current milestone fails for the stated reason; rows due
      later are run by the control runner from their due milestone and logged `not-due` before it.
- [ ] Refusal rows (729, 734, 802, 805, 812, 825, 835) carry a check-removed mutation (`removed_check`), not a
      boundary case.
- [ ] The burn-down (N38b-49) reports zero rows of these eight chapters without a control at the milestone
      where each is due; the M3 rule is enforced by a planted open row due at M2 in a run set to M3.

### End-to-end script and logging

`scripts/e2e/ka_controls_evidence_to_safety.sh` (header: `bead=N38b-34 milestone=M2 labels=gauntlet,registry
gates=GATE-GAUNT-01,GATE-GAUNT-02 plants=boundary-refusal-control,two-first-records`; sources the STD-E2E
helper; scratch copy of the registries). Steps: (1) `check`: `cargo test -p frob-conformance --test
control_obligations -- chronicle_to_safety`, one `assert` per row naming its first record and its bead, or
`skip` with `open: row not registered`; (2) `run`: for each row due by the current milestone, every record
planted through its tier target (`--features gauntlet-mutations,<crate>/<feature>`,
the record's `feature` field as written, or the planted input); for
the refusal rows the verb is driven through `frob --json` in the mutant build and the envelope must no longer
carry the refusal (`e2e_expect_caught`), while the clean build returns it (`e2e_expect_refusal`); per record
the truth, tolerance, control value and `caught`; rows due later logged `skip` with `not-due: <milestone>`;
(3) `burn-down`: one `metric` per chapter (`rows_without_control`, unit `rows`, threshold `== 0` for rows due by
the current milestone from M3 on), and the suite-wide line for all 325 rows; (4) plants:
`boundary-refusal-control` (KA-812's control written as the refusal itself: rejected) and `two-first-records`
(a second record for KA-761 marked first: rejected). Log at
`target/e2e-logs/ka_controls_evidence_to_safety/<utc>.ndjson` with the transcript; every line has `ts`,
`script`, `bead`, `step`, `event`; `cmd` lines the exact command, exit code, wall time and the envelope's
evidence block for verb calls; failed assertions the first differing KA or NC identifier with observed and
expected values and the scratch paths; the `summary` the counts and gates GATE-GAUNT-01 and GATE-GAUNT-02.
