## Background

Two of the fourteen known answers adopted by FrankenRobotics' verification subsystem (the Gauntlet) concern
single-precision arithmetic and memory views on devices, and land at M2 with the batched engine. Both run
under gate GATE-GAUNT-11, whose threshold for such rows is strict: single-precision rows are bit-exact on every
backend (the CPU batch tier, CUDA and Metal) and every negative control fails.

*Moment merge.* Training on two devices splits samples into shards; observation and advantage statistics must
be the statistics of the union, not per-shard ones. The safe way merges per-shard triples (count n, mean μ, sum
of squared deviations S) by an exact pairwise formula. The tempting way keeps the mean of squares and
subtracts the squared mean, which cancels catastrophically in single precision.

*Writable view.* Array views cross between libraries with different stride conventions. A view can be entirely
in bounds and still map two indices to one element; reading through it is fine, writing through it makes the
result depend on the order of stores.

## Scope

In: the two rows on `strict`, `cuda` and `metal` with bit-exact comparison; two controls. Out: the registry
records (N38-KA); the learning update and the view machinery themselves.

## Technical approach

**Row A, moment merge in single precision (KA-841).** Three cases, each two equal-size shards of constants:
(4,095; 4,097), (−1; +1), (8,191; 8,193). Per-shard triples have S = 0 and means equal to the constants.
Merge: n = n_a + n_b, d = μ_b − μ_a, μ = μ_a + d·n_b/n, S = S_a + S_b + d²·n_a·n_b/n. With n_a = n_b: μ is the
midpoint and S/n = d²/4 = 1. Expected population variance: exactly 1.0 in single precision, in all three
cases, on every backend (bit pattern 0x3F800000). Shard size for the test: 1,024 per shard, and also 1 per
shard.
Control (`mutation` of the statistics kernel): variance = mean of squares − (mean)². In single precision
4,096² + 1 = 16,777,217 is not representable (the spacing above 2²⁴ is 2) and 8,192² + 1 = 67,108,865 is not
(spacing 8 above 2²⁶), so the raw form returns 0 for the first and third cases and 1 for the second. The
control is caught when the row reads 0 where 1 is true.
FACT to re-run before the gate cites it (a recorded planning pilot): a native single-precision kernel on the
Metal device and on each RTX 4090 returned 0 by the raw form and 1 by the centred merge for the pair at 4,095
and 4,097, 1 by both for the pair at ±1, and 0 by the raw form at 8,192. Each device merged locally; nothing
about communication between devices or training throughput follows.

**Row B, independence of a writable view (KA-843).** A 2×2 view with element strides (1, 1) over a buffer of at
least 3 elements: index [i, j] addresses offset i + j, so [0, 1] and [1, 0] both address offset 1. Expected:
(1) the view is admitted for reading; (2) a request to write through it is refused, with the two colliding
indices named; (3) with a declared reduction (for example sum) or with separate storage the write is admitted.
Demonstration of why: storing 7 at [0, 1] and 11 at [1, 0] leaves 7 or 11 at offset 1 depending on order.
Control (`mutation` of the admission check): a check of address bounds alone admits the write; the test then
observes an order-dependent result (two runs with the stores in opposite order differ) and fails.
The check runs on the host at the interchange boundary and on each device backend where a view becomes a
kernel argument.

**Bit-exact comparison.** Each entry returns the raw 32-bit patterns; the comparison is equality of patterns
across `strict`, `cuda` and `metal`, and with the host's exact expectation. A device family that has not passed
its floating-point probe is skipped and named; a skip is never a pass.

## Acceptance criteria

- [ ] Row A returns 1.0 (0x3F800000) in all three cases on every admitted backend, for both shard sizes.
- [ ] The raw-form mutant returns 0, 1, 0 and is caught on every backend.
- [ ] Row B: read admitted, write refused naming [0, 1] and [1, 0]; the bounds-only mutant admits the write and
      is caught by the order-dependence check.
- [ ] The planning pilot's device observations are reproduced and recorded before the gate cites the row.
- [ ] Both rows are recorded as the M2 part of GATE-GAUNT-11 from the receipt of `adopted_known_answers.sh M2`
      (N38b-46, M1, on which this bead depends for that script) by a session that did not implement the kernels.

## Test plan

### Unit tests

Conformance entries `ka:KA-841@strict|cuda|metal`, `ka:KA-843@host|cuda|metal`, and
`crates/frob-conformance/tests/adopted_rows_m2.rs`:
- `ka_841_centred_merge_bits`: three cases × two shard sizes → 0x3F800000.
- `ka_841_raw_form_values_f32`: 0.0, 1.0, 0.0 (host `f32` arithmetic, showing the cancellation).
- `ka_841_unrepresentable_integers`: (16,777,217 as f32) = 16,777,216; (67,108,865 as f32) = 67,108,864.
- `ka_841_merge_is_associative_on_triples`: merging three shards in either grouping gives the same triple for
  these inputs (property test over small integer constants).
- `ka_843_alias_detected`; `ka_843_read_admitted_write_refused`; `ka_843_reduction_admitted`.
- `ka_843_order_dependence`: under the mutant, stores in the two orders leave 7 and 11.
- `nc_raw_second_moment_caught`; `nc_bounds_only_view_caught`.

### End-to-end script and logging

`scripts/e2e/adopted_known_answers.sh M2` (bead N38b-46): `frob --json spark check` on the statistics kernel
for each backend (the kernel's CPU-versus-device check), then the two tier entries and their controls. It logs,
with the fields of STD-E2E (`ts`, `script`, `bead`, `step`, `event`; exact command, exit code, wall time), the
bit patterns per backend as hex, equality across backends as digests, the refusal for the view with the two
colliding indices, each control's outcome with the observed value (0, 1, 0; the two store orders), a `skip`
line naming any device family not admitted, and on failure the first differing bit pattern with its case,
shard size and backend; the evidence block names tier, backend, determinism class and seed.

### Known answers and negative controls

Known answers: variance 1 in three cases (KA-841); one element addressed twice (KA-843). Negative controls:
raw second moment (0, 1, 0); bounds-only view check. Metamorphic relations: adding the same constant to both
shards leaves the variance bits unchanged for the centred merge; permuting shard order changes nothing.
Determinism lanes: `twice`, `workers` and `backends`; these rows are class D1 (bitwise across backends) by
construction, since every intermediate is exactly representable.

## Considerations

- If a device family is not admitted at M2, its site is skipped and the row is recorded for the remaining
  backends, with the skipped family named in the gate's measured value.
- The rows say nothing about training throughput or communication between devices.
- The stride-convention trap between array libraries (byte strides against element strides) is a separate
  known answer of the backend chapter; this row is about write independence only.
