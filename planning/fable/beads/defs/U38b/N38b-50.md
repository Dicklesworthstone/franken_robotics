## Background

While the known-answer suite of FrankenRobotics was compiled, every hand-checkable value was recomputed. Eleven
values did not reconcile with their own formulas at that time. Seven have since been corrected in the design
(the suite carries the corrected values and records what was first printed); four stand as remarks. The rule
of the suite is that values are not improved in transit: a row keeps the printed value, is listed in a
reconciliation table, and its gate cites the derivation file once the reconciliation is closed (open question
OPEN-GAUNT-6; owner: the lead and the owning chapters; blocks any gate that cites one of the values;
fail-closed default: the row keeps the printed value and is flagged).

This bead does three things. It creates the *reconciliation register*, the data file and checks that all eleven
value beads use. It builds the *withdrawn-value scan*, the one engine in `frob-conformance` that searches the
workspace for values that have been withdrawn. And it settles value 1.

**Three lists, one scan.** The design recomputed its figures three times, for three purposes, and each pass
left a list: the eleven values of the known-answer suite (this register, identifiers REC-01 to REC-11), the
twelve items found while the 41 worked cards were recomputed (the discrepancy register
`registries/cards/discrepancies.toml` of NEG-03, identifiers E7-…), and the eight figures found while the
killed-idea register was compiled, with nine more found later (the discrepancy pins
`crates/frob-conformance/registry/discrepancy_pins.toml` of NAB-41, identifiers DX-01 to DX-17). The lists
overlap: REC-01 is E7-3 and DX-03, REC-02 is E7-2 and DX-02, REC-06 is E7-6, REC-07 is E7-1. Each list keeps
its own file, schema and identifiers, because each records where a value was found and what its owner did.
What they share is the search for a withdrawn value in its context. Three searches with three matching rules
and three exemption lists would each flag the other two registers' records, tests and printouts, which quote
the withdrawn values on purpose. So there is one engine, here, in the bead of the chapter that owns the
conformance crate and the rule that values are not improved in transit; the other two registers supply
entries to it (DESIGN).

**Value 1.** A planning pilot compared a specialized solver with a composed one: the composed solver took
1.345 times the specialized time warm (1.088 cold). The design's rule "ceiling first" came from asking how
much any solver could have shown. It was first printed as: a zero-cost solver would reach "about 1.46" warm,
from the ratio 1.345 and a shared share of 94% of the specialized batch. Recomputed, 1.345 ÷ 0.94 = 1.43, not
1.46. Corrected: the share attribution is withdrawn. The specialized batch held a residual of 575.7 µs that
the solver does not touch (parsing, assembly, checking, serialization and harness, not separately timed), and
the ceiling is 842.8 ÷ 575.7 = 1.46. The conclusion is unchanged: the measured 1.345 was tested against a
ceiling of about 1.46, so the test could not have confirmed its claim.

## Technical approach

**Register (`crates/frob-conformance/registry/reconciliations.toml`; one `[[reconciliation]]` each).**
```toml
[[reconciliation]]
id         = "REC-01"                    # append-only
where      = ["hygiene rules", "ten-fold thesis", "mission pilots", "performance program"]
rows       = ["KA-001", "KA-812", "CX-001"]
formula    = "ceiling = composed_time / residual_untouched"
printed    = { text = "about 1.46, from 1.345 and a shared share of 94%", value = "1.46" }
recomputed = { text = "1.345 / 0.94", value = "1.43" }
status     = "corrected"                 # corrected | remark | open
settled    = { value = "8428/5757", prints_as = "1.46", tolerance = "0.005", derivation = "docs/derivations/solver-ceiling.md" }
retired    = [                           # stale entries in the common form of the scan (below)
  { pattern = "1\\.43", scope = "solver|ceiling|zero.cost" },
  { pattern = "94 ?%",  scope = "shared|share of|batch", all_of = ["solver"] },
]
confirmed_by = ""                        # owning chapter's confirming session, never the settlement's author (N38b-61)
decision   = ""                          # identifier of the record that closes it
```
A record of this register carries no pointer to the other two registers: the links run towards this one. An
E7 item or a DX record that records the same correction names the REC identifier in its own `same_as` field
(E7-3 and DX-03 name REC-01; E7-2 and DX-02 name REC-02; E7-6 names REC-06; E7-1 names REC-07), and the scan
resolves the links in both directions when it reports. DESIGN: this register exists first and the known-answer
rows it names hold the settled values, so it is the hub and holds no forward reference.
Rules: a known-answer row named in `rows` carries `printed` in its own record and is `flagged: unreconciled`
until `settled` is filled and its derivation file exists; a row never changes its truth silently; the
printed reconciliation table is generated from this file.

**REC-12, the first record appended under the standing rule (N38b-61; the entry N38-KA names for KA-837).**
`rows = ["KA-837"]`; `where = ["§38.17"]`; `formula = "z = (p/(k_c/b + k_φ))^(1/n), the n = 0.7 control"`;
`printed = { text = "9.17, 19.01 and 11.71 cm (§38.17, the n = 0.7 control)", value = "0.0917, 0.1901, 0.1171" }`;
`recomputed = { text = "from the unrounded p = 5,016.48 Pa; 9.17 follows only from p rounded to 5.017 kPa before
the power 1/n (0.091660 m)", value = "0.091646, 0.190127, 0.117076" }`; `status = "open"`, to be settled as
`corrected` (the recomputed values, a `retired` entry for "9.17" in a sinkage context, the row's derivation
file) by the bead that tests the row at M4, N38b-43, and confirmed by a session of the contact chapter that did
not write the settlement. Until then KA-837 reads `flagged: unreconciled` (N38a-12) and GATE-FID-09 does not
count it; the row is due at M4, so nothing earlier is blocked. The truths (3.52, 9.79 and 4.96 cm) are not
affected.

**Meta-tests (`tests/reconciliations.rs`).** (1) Eleven records at plan time, seven `corrected` (1, 2, 3, 5,
6, 7, 9) and four `remark` (4, 8, 10, 11), and REC-12 appended `open` with rows `["KA-837"]`. (2) For each record, a test function recomputes `recomputed` and
`settled` from the stated inputs. (3) *Retired-value scan* (`retired_value_scan`): the scan engine below is
run over the `retired` entries of every record; a hit fails. (4) A row in `rows` whose registry truth differs
from `settled.value` fails.

**The withdrawn-value scan (`crates/frob-conformance/src/stale_scan.rs`, DESIGN; one engine for the three
registers).**

1. *Entry form.* `{ pattern, scope, all_of }`. `pattern` is a regular expression for the withdrawn value as it
   was printed. `scope` is a regular expression of which at least one match must lie in the window. `all_of`
   is a list of phrases every one of which must occur in the window, compared without regard to case. `scope`
   and `all_of` are each optional and at least one is present: a bare value is never searched for without a
   context, which is what keeps "7.8 mm" in a dimension table, "615" as a part count, and the unrelated cap
   (410 + 60)/60 = 7.83 printed as "7.8" from firing.
2. *Window.* The text is read with every run of white space, line breaks included, collapsed to one space. The
   window of a match is the 200 characters before it and the 200 after it. DESIGN: one of the three drafts
   matched within a sentence and another within 200 characters of a line; a sentence splitter breaks on
   abbreviations and on decimal points ("1.46"), while the window on collapsed text needs no splitter and gives
   the same result when a paragraph is reflowed, so the window governs for all three registers.
3. *Sources.* A source is a register file with a loader that yields, per record, its identifier, its entries,
   its `same_as` list, its settled text, its exempt paths and its finding code. This bead registers
   `reconciliations.toml` (entries: `retired`). NEG-03 registers `registries/cards/discrepancies.toml`
   (entries: `stale`). NAB-41 registers `discrepancy_pins.toml` (each of its `withdrawn_tokens` taken literally
   as a `pattern`, its `context` words as `all_of`; finding code `dx.withdrawn-figure`). A source that is not
   present in the tree is skipped, so each register's test runs as soon as its own file exists.
4. *Walk set.* `README.md`, `registries/`, `schemas/`, `crates/*/CONTRACT.md`, `crates/*/tests/`,
   `crates/*/registry/`, `scripts/e2e/`, `demos/`, `assets/`, `docs/` (generated documents and registry
   printouts included) and report templates. Never `target/`, never the specification document itself. Files
   are visited in sorted order so that the report is byte-identical between runs.
5. *Exemptions (one list for the three registers).* (a) The three register files. (b) The generated printout
   of a register, declared by its source as an exempt path: the reconciliation table here, the report of
   NEG-03, the killed-idea document for NAB-41. (c) The derivation file a record names, for that record's
   entries and those of the records linked to it: a derivation must be able to state the withdrawn computation
   it replaces (step 3 of the derivation below does). (d) A line that carries the marker
   `stale-as-control: <id>`, where `<id>` is the record's identifier or one linked to it by `same_as`: a test
   that uses the withdrawn value as its planted wrong golden, or a fixture that quotes it. The same value on an
   unmarked line fires.
6. *Hit.* `{ file, line, ids, settled, code }`: the line on which the match begins; `ids` holds the record
   whose entry matched and every record linked to it by `same_as` in either direction; `settled` is the settled
   text of the first; `code` is the source's finding code where it declares one. Two entries of linked records
   that match the same text yield one hit, not two.
7. *Links.* `resolve_links(sources)` fails when a `same_as` identifier names no record of a loaded source, and
   when a linked record states a numeric `value` that differs from `settled.value` of the REC record it names
   (or, where that record settles several figures, from every figure in its `settled` block). The registers of
   NEG-03 and NAB-41 call it in their own tests.

**Value 1: derivation (`docs/derivations/solver-ceiling.md`).**
1. Measured (FACT, planning pilot, to be re-run here; the source register records the residual as "the
   610.1 µs full median less the 34.4 µs solve-only median"): composed batch median 842.8 µs warm; specialized
   batch full median 610.1 µs; specialized solve-only median 34.4 µs; residual untouched by any solver
   610.1 − 34.4 = 575.7 µs. The ratio of batch medians is 842.8/610.1 = 1.3814; the reported 1.345 is the
   median of the per-fixture ratios, a different statistic, so the specialized batch time is not 842.8/1.345
   and is never derived that way. The file records both statistics with their definitions, as NEG-06 stores
   them.
2. Ceiling of any solver against the composed arm: 842.8/575.7 = 1.4640 (exact rational 8428/5757).
3. The withdrawn derivation: 1.345/0.94 = 1.4309. The "94%" was an attribution of shared work that the data
   did not support, since the residual was not separately timed. (575.7/610.1 = 94.4% is the untouched share
   of the specialized batch; it is not a share of the composed batch and cannot be divided into 1.345.)
4. Consequence unchanged: claimed ratio 1.345 < ceiling 1.46, and a goal above 1.46 could not be confirmed.
Settlement: truth 8428/5757, printed "about 1.46", tolerance half a unit of the last printed digit (0.005);
1.43 is retired. The pilot's re-run must time parsing, assembly, checking, serialization and harness as
separate phases, replace "not separately timed" by measured phases, and re-derive the ceiling from them; if
the re-run's ceiling differs, the row's truth becomes the re-run's value by a dated record.

      meta-tests; the printed reconciliation table is generated from it; KA-837 reads `flagged: unreconciled`.

- [ ] The retired strings "1.43" and "94%" appear nowhere in generated text about the solver ceiling outside
      the reconciliation table, the derivation file and lines marked `stale-as-control: REC-01`.
- [ ] The scan engine exists once in `frob-conformance`; `reconciliations.toml` is registered as a source; the
      engine's unit tests below pass; a tree without the registers of NEG-03 and NAB-41 scans cleanly.
- [ ] The derivation file states 610.1 µs, 34.4 µs and 575.7 µs and both ratio statistics (1.345, the median
      of per-fixture ratios; 1.3814, the ratio of medians); it does not derive a specialized batch time from
      842.8/1.345.
- [ ] The re-run pilot's phase timings are linked from the derivation file, or the row stays flagged "FACT to
      re-run".
- [ ] A planted edit that changes a row's truth without a register record fails the meta-test.

`crates/frob-conformance/tests/reconciliations.rs`:
- `register_has_eleven`: seven corrected, four remarks, identifiers REC-01 to REC-11 at plan time.
- `rec_12_plate_sinkage`: REC-12 is `open` with rows `["KA-837"]`; from k_c = 0.41, k_φ = 21.6, b = 0.08 m and

  5.017 kPa gives 0.091660 m, the printed 9.17 cm; KA-837 is `flagged: unreconciled`.
- `rec_01_ceiling`: 842.8/575.7 = 1.46396 rounds to 1.46; 1.345/0.94 = 1.43085 rounds to 1.43; the two differ
  by more than the tolerance 0.005.
- `rec_01_residual`: 610.1 − 34.4 = 575.7 µs; 842.8/610.1 = 1.3814, which differs from 1.345 by more than
  0.005 (the two statistics are not interchangeable); 575.7/610.1 = 0.9436.
- `retired_value_scan` (fixture documents with and without the retired strings).

`crates/frob-conformance/tests/stale_scan.rs` (the engine, on `synthetic` scratch trees):
- `scan_needs_a_context`: an entry with neither `scope` nor `all_of` is rejected when the source is loaded.
- `scan_scope_filters`: "7.8 mm" in a dimension table and "(410 + 60)/60 = 7.8" do not fire for an entry
  `{ pattern = "7\\.8", scope = "step share|Amdahl" }`; "a ceiling of about 7.8 at a step share of 87%" does.
- `scan_all_of`: with `all_of = ["step share", "87%", "ceiling"]` the sentence fires only when all three
  phrases are within the window.
- `scan_reflow_invariant` (metamorphic): the hits are unchanged when the fixture's paragraphs are re-wrapped
  at 40, 80 and 120 columns.
- `scan_window_is_200`: a context phrase 199 characters from the match counts and one 201 characters away
  does not.
- `scan_exemptions`: the register file, a declared printout, the record's derivation file and a line marked
  `stale-as-control: REC-01` do not fire; the same text in an unmarked file does; a marker naming an unlinked
  record does not exempt.
- `scan_linked_hit_is_one`: two sources with linked records whose entries match the same text give one hit
  listing both identifiers.
- `scan_missing_source_is_skipped`; `scan_report_is_sorted_and_stable` (two runs, byte-identical reports).
- `resolve_links_catches_dangling_and_disagreeing`: a `same_as` naming REC-99 fails; a linked `value` of
  "1.43" against `settled.value = "8428/5757"` fails.
- `row_truth_matches_settled`; `unsettled_row_is_flagged`.

### End-to-end script and logging

`scripts/e2e/reconciliations.sh` (header: `bead=N38b-50 milestone=M0 labels=gauntlet,registry
gates=GATE-GAUNT-02 plants=silent-truth-edit,retired-string,unmarked-control-quote`; sources the STD-E2E helper;
works on a scratch copy of the tree). Steps: (1) `register`: `cargo test -p frob-conformance --test
reconciliations --test stale_scan`; one `metric` line per record (printed, recomputed, settled, status) and the
counts 7 corrected and 4 remarks; (2) `table`: the reconciliation table regenerated and its digest compared with
the committed printout; (3) `rows`: for every settled record, the known-answer rows it names run through their tier target
(`cargo test -p frob-conformance --test g1_known_answers -- <KA ids>`), one `assert` per row with the settled
truth and tolerance (for REC-01: KA-001 and KA-812, 8428/5757, 0.005), and rows of unsettled records logged
`flagged: unreconciled`; the claimed ratio 1.5 submitted for locking against the ceiling refused (KA-001's
control, `e2e_expect_refusal`); the value beads N38b-51 to N38b-60 add no script and are logged here as their
records are settled; (4) `scan`: the engine over the walk set with every loaded source; one `metric` for
hits (threshold `== 0`), the sources loaded and skipped, and the report's digest (two runs, equal); (5) plants,

written beside "solver ceiling" in a generated page (one hit naming REC-01, its file and line); the same quote

`step`, `event`; `cmd` lines the exact command, exit code and wall time; failed assertions the record or hit
(file, line, ids, settled text) with observed and expected values and the scratch paths; the `summary` with
records by status, hits, plants caught and GATE-GAUNT-02.

### Known answers and negative controls

Known answers: 1.46396 and 1.43085; 575.7 µs from 610.1 − 34.4. Negative controls: the silent edit; the
retired string; a claimed ratio of 1.5 submitted for locking against the ceiling 1.46 (must be refused, the
control of KA-001); for the engine, the unmarked reintroduction, the dangling link and the disagreeing linked
value. Metamorphic relation: reflowing a document leaves the scan's hits unchanged. Determinism: D0; the scan
is a pure function of the tree.

## Considerations

- The ceiling is a FACT about a small pilot on a small model; nothing about product speed follows.
- Other beads' texts carry "about 1.46 (842.8 ÷ 575.7)"; that is the settled form.
- The scan is a guard against regression, not a proof of absence in prose: a paraphrase ("a little over 1.4")
  escapes it, which is why every record also has a test on the computed value.
- The three registers are kept apart on purpose: a single file would lose where each value was found and
  which appendix's owner settled it. Only the search is shared. A fourth list, if one appears, registers as a
  source and adds no second engine.
