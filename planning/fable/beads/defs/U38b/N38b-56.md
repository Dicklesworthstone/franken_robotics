## Background

To certify that a failure probability is at most p⋆ with confidence 1 − δ from nominal episodes with zero
failures, FrankenRobotics needs n episodes with (1 − p⋆)ⁿ ≤ δ, that is n = ⌈ln δ/ln(1 − p⋆)⌉. At δ = 0.05 this
gives 29,956 episodes for p⋆ = 10⁻⁴, 299,572 for 10⁻⁵ and 2,995,731 for 10⁻⁶. Inside the blinded
qualification lane the level of request i is αᵢ = α/[i·(i + 1)], so the tenth request is tested at
α₁₀ = 0.05/110 and needs more episodes.

The design first printed the tenth request's count as 76,963. The exact rule used for the rest of the same
table gives 76,959; 76,963 comes from the approximation ⌈ln(1/α₁₀)/p⋆⌉ (ln(1/α₁₀)/p⋆ = 76,962.1). The text was
corrected to 76,959. This is one of eleven values that did not reconcile with their own formulas when the
known-answer suite was compiled (register record REC-07; status corrected).

## Scope

In: the record; the single counting rule; the row's truth and derivation; a test. Out: the register
(N38b-50); the control of the same row that errs on the safe side (N38b-57).

## Technical approach

**Formula (exact rule, used everywhere).** n(δ, p⋆) = ⌈ln δ/ln(1 − p⋆)⌉, the least n with (1 − p⋆)ⁿ ≤ δ.
Approximation (never used for a count): ln(1/δ)/p⋆, which is larger than the exact real value because
−ln(1 − p) > p.

**Both values at α₁₀ = 0.05/110 = 4.5455 × 10⁻⁴ and p⋆ = 10⁻⁴.** Exact: ln α₁₀/ln(1 − 10⁻⁴) = 76,958.28, so
n = 76,959. Approximate: ln(1/α₁₀)/10⁻⁴ = 76,962.13, so 76,963. The difference is four episodes.

**The rest of the table (exact rule).** δ = 0.05: 29,956 (real value 29,955.82), 299,572 and 2,995,731.

**Settlement.**
1. The row's truth is the exact integers 29,956, 299,572, 2,995,731 and 76,959, tolerance `exact`.
2. One function `zero_failure_episodes(delta, p_star)` computes counts for the certification lane, the
   qualification lane, the documentation generator and the test. It evaluates in exact or interval arithmetic
   near integer boundaries: the count is the least n for which an outward-rounded upper bound of (1 − p⋆)ⁿ is
   at most δ.
3. The derivation file `docs/derivations/zero-failure-count.md` gives the rule, the approximation and why the
   approximation always errs high; 76,963 is retired.

## Test plan

### Unit tests

`crates/frob-conformance/tests/reconciliations.rs`:
- `rec_07_exact_counts`: 29,956; 299,572; 2,995,731; 76,959.
- `rec_07_minimality`: (1 − 10⁻⁴)^29,956 = 0.0499991 ≤ 0.05 < (1 − 10⁻⁴)^29,955 = 0.0500041; the same pair of
  inequalities at 76,959 and 76,958 against α₁₀, in interval arithmetic.
- `rec_07_approximation_is_high`: ⌈ln(1/δ)/p⋆⌉ ≥ exact count for δ in {0.05, 0.05/110} and p⋆ in {10⁻⁴, 10⁻⁵,
  10⁻⁶} (76,963 ≥ 76,959; 29,958 ≥ 29,956).
- `level_of_tenth_request`: 0.05/(10 × 11) = 1/2,200.

Known answers: the four exact counts. Negative control: a count one below the exact value, 29,955 or 76,958,
for which the bound fails (the subject of N38b-57). Determinism: D0.

## Considerations

- Four episodes in 77 thousand are immaterial for compute and material for a registry: an "exact" row with two
  different integers in the documents cannot be tested.
- At 10⁻⁶ the count needs a compute class above the default; the arithmetic is unaffected.
