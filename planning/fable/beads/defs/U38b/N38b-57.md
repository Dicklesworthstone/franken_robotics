## Background

A negative control is a planted defect that must make a known-answer row fail. The known-answer row for the
*zero-failure rule* of FrankenRobotics (to certify a failure probability of at most p⋆ at confidence 1 − δ,
run n = ⌈ln δ/ln(1 − p⋆)⌉ nominal episodes with no failure: 29,956 at δ = 0.05 and p⋆ = 10⁻⁴) states as its
control "an episode count from ln(1/δ)/p⋆ rounded down".

Recomputed: ln(1/0.05)/10⁻⁴ = 29,957.3, so that count is 29,957, which *exceeds* the exact 29,956. The planted
defect errs on the safe side at these values and cannot make the row fail: with 29,957 episodes the bound
holds. A control that undercounts is needed. This is one of eleven values that did not reconcile when the
known-answer suite was compiled (register record REC-08; status remark). It is the cleanest example of a rule
the control registry needs: a control must err in the unsafe direction of the rule it tests.

## Scope

In: the record REC-08; the two replacement controls; the declaration of the safe direction on every counting
row; tests. Out: the register (N38b-50); the exact counts themselves (N38b-56); the loader rule `cannot-fail`
that reads the direction (rule 3 of N38b-28); the control runner that plants the records (N38b-04).

## Technical approach

**Formula.** Exact: n = ⌈ln δ/ln(1 − p⋆)⌉. The stated control: ⌊ln(1/δ)/p⋆⌋.

**Both values at δ = 0.05, p⋆ = 10⁻⁴.** Exact 29,956 (real value 29,955.82). Stated control ⌊29,957.32⌋ =
29,957. Since −ln(1 − p) > p for 0 < p < 1, ln(1/δ)/p⋆ always exceeds ln δ/ln(1 − p⋆); here the gap (1.5) is
larger than one, so even rounded down the approximation stays above the exact count.

**Replacement controls (both registered; kind `mutation`; gates: the row's gate and GATE-GAUNT-01).**
1. *One short*: the exact expression rounded down, ⌊ln δ/ln(1 − p⋆)⌋ = 29,955. Then
   (1 − 10⁻⁴)^29,955 = 0.0500041 > 0.05: the bound is claimed without being established. The row's test must
   reject a certificate issued at 29,955 episodes.
2. *Level not spent*: the tenth qualification request tested with the count for δ = 0.05 (29,956) instead of
   α₁₀ = 0.05/110 (76,959): an undercount of 47,003 episodes. The test must reject a tenth-request promotion
   at 29,956 failure-free episodes.
The stated control is kept in the row's history as `retired: cannot-fail` with this record's identifier.

**Loader rule (`cannot-fail`) and the safe direction.** The rejection is rule 3 of the control loader, which
N38b-28 (M0, on which this bead depends) enforces: for a row whose truth is a threshold with a declared safe
direction (`safe = "higher"` for an episode count, a margin, a bound on an error; `safe = "lower"` for a
claimed probability or a tolerance), the control's planted value must lie strictly on the unsafe side of the
truth, or the loader rejects it with `cannot-fail` and prints both numbers; rows without a declared direction
are checked by running the control, and a control whose run leaves the row passing is `missed`. DESIGN (one
rule, one owner): this bead's first draft defined the rule itself; it now uses N38b-28's, and what it adds is
the declaration of `safe` on KA-664 and on every other counting row of the suite (the rows whose truth is an
episode count, a sample size or a one-sided bound), with REC-08 as the rule's worked case.

## Test plan

### Unit tests

`crates/frob-conformance/tests/reconciliations.rs` and `tests/control_runner.rs`:
- `rec_08_stated_control_is_safe`: ⌊ln 20/10⁻⁴⌋ = 29,957 ≥ 29,956.
- `rec_08_one_short_fails_bound`: (1 − 10⁻⁴)^29,955 > 0.05 ≥ (1 − 10⁻⁴)^29,956, in interval arithmetic.
- `rec_08_level_not_spent`: 76,959 − 29,956 = 47,003; (1 − 10⁻⁴)^29,956 = 0.04999 > α₁₀ = 0.000455.
- `cannot_fail_rejected`: a control with planted value 29,957 on a row with truth 29,956 and `safe = "higher"`.
- `unsafe_side_accepted`: 29,955.
- `approximation_always_high`: property test over δ in (0, ½) and p⋆ in (0, ½): ln(1/δ)/p⋆ > ln δ/ln(1 − p⋆).
- `counting_rows_declare_safe`: every row whose truth is an episode count, a sample size or a one-sided bound
  (among them KA-559, KA-614, KA-664, KA-694, KA-706 and KA-762) declares `safe`, and each of its registered
  controls lies on the unsafe side; a planted counting row without `safe` is listed by number.

### End-to-end script and logging

The two replacement records are planted by the control runner like every registered record, so
`scripts/e2e/control_runner.sh` (N38b-04) runs them whenever KA-664's gate runs and logs `caught` for each.
`scripts/e2e/reconciliations.sh` (N38b-50, on which this bead depends) carries REC-08: the `register` step logs
its `metric` line (stated control 29,957, exact 29,956, replacements 29,955 and 29,956 at α₁₀, status remark);
the `rows` step runs KA-664 with each replacement planted (`e2e_expect_caught`: a certificate at 29,955
rejected with (1 − 10⁻⁴)^29,955 = 0.0500041 logged against δ = 0.05; a tenth-request promotion at 29,956
rejected with 0.0499991 against α₁₀ = 0.000455) and offers the original record to the loader
(`e2e_expect_refusal`, `cannot-fail`, both numbers logged). Each line carries the STD-E2E fields (`ts`,
`script`, `bead`, `step`, `event`; exact command, exit code and wall time on `cmd` lines; observed and expected
values on failure, with the scratch-registry path).

### Known answers and negative controls

Known answers: 29,956; 29,955 fails; 29,957 passes. Negative controls: the two replacements; and, for the
loader rule itself, the original control (must be rejected). Determinism: D0.

## Considerations

- At other values the original control could undercount (when the approximation's excess is below its
  fractional part); a control whose direction depends on the numbers is not a control.
- The same check found nothing wrong with the row's truth; only its control was powerless. Rows like this are
  why a control is run, and its failure observed, every time its gate runs.
