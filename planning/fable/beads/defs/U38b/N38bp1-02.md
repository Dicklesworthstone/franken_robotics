## Background

GATE-GAUNT-04 is the gate of FrankenRobotics' verification subsystem (the Gauntlet, crate `frob-conformance`)
that certifies the certifiers: the components whose verdicts everything else trusts. Claim kind: known answer.
Threshold (TARGET): every row of the certifier table meets its threshold, and the certificate mutation corpus
holds at least 1,000 mutants per proof kind with zero accepted. It is due in two parts: at M1 for the checker,
at M3 for the lanes. Each certifier row has two halves: the certifier gives the right verdict on inputs whose
truth is known, and a planted *broken certifier* (a variant that accepts what it should reject) must fail the
same self-test, because a self-test that a broken certifier passes certifies nothing.

The end-to-end script that measures the gate, `scripts/e2e/certifiers.sh`, was first carried whole by an M3 bead
(N38b-17). That left the gate's M1 part, and the M1 self-tests of N38b-10, N38b-11 and N38b-14, without a script
that drives the real binaries until M3. This bead, split from N38b-17 by milestone, creates the script at M1 with
the eight rows whose certifiers exist at M1, and measures and records the M1 part. N38b-17 extends the same
script with the M3 rows and the M4 and M5 modes; there is one script.

## Scope

In: the script `scripts/e2e/certifiers.sh` with its argument handling, its row table format and its `M1` mode;
the eight M1 rows; the measured value of the gate's M1 part; the log; the planted broken certifier of each row;
the meta-test keeping the script's M1 rows and the register together.

Out, with the bead that has it: the certifier register and the carried self-tests CERT-01 to CERT-04 (N38b-10);
the certificate mutation corpus and the checker-before-an-answer test, rows CERT-05 and CERT-06, with their own
script `cert_corpus.sh` (N38b-11); the monitor and pre-analysis self-tests CERT-11 and CERT-12 (N38b-14); the
M3 rows and the `M3`, `M4` and `M5` modes (N38b-17); the recorder (N38b-19); the certifiers themselves.

## Technical approach

`scripts/e2e/certifiers.sh <M1|M3|M4|M5>` (header: `bead=N38bp1-02 milestone=M1 labels=gauntlet,gate
gates=GATE-GAUNT-04 plants=broken-certifier-per-row`). At M1 only the `M1` mode exists; any later argument
prints `not-built` and exits 2 until N38b-17 lands. The row table is read from the certifier register
(`crates/frob-conformance/registry/certifiers.toml`), not typed into the script: a row is selected when one of
its `due` milestones is at or before the argument.

| Row | Certifier | Command from the user's side | Measured against (TARGET) | Broken certifier that must fail |
|---|---|---|---|---|
| CERT-01, -05 | Certificate checker | `scripts/e2e/cert_corpus.sh` (N38b-11): `frob-verify` over the corpus; `frob prove verify` in the daemon | 0 mutants accepted of ≥ 1,000 per kind, ≥ 50 per applicable class; specimens byte-stable; verdicts identical; 0 dependencies | A checker that skips the quantifier-prefix comparison |
| CERT-06 | Checker before an answer | `frob mission synthesize` on the stance fixture with the planted lowering defect | False cell never `Certified` | A verb layer that returns the producer's bundle unchecked |
| CERT-02 | Dimension checker | `frob spark check` on the four seeded kernels and four clean kernels | 100% of seeded violations rejected; every clean kernel accepted | A checker that treats all quantities as dimensionless when one operand is a literal |
| CERT-03 | e-process under optional stopping | `frob study submit` on 10⁴ null campaigns, seed 0 | ≤ 551 false rejections of 10⁴; the peeking control's rate consistent with 13/256 | A fixed-n test peeked at eight times |
| CERT-04 | Physical consistency | `frob design check` on the three inertia fixtures | λ_min = −10⁻⁹ rejected (FROB-REF-104, eigenvalue reported); +10⁻⁹ accepted; (1, 1, 2.1) rejected | A test that checks only the mass and the diagonal |
| CERT-11 | Requirement monitors | `frob task verdict` on recorded traces through each of the three evaluators | 0 disagreements of 10⁶ traces per operator | A monitor that pads a short window with the neutral element |
| CERT-12 | Fixed-n pre-analysis | `frob eval preanalyze --n 64`, `--n 86`, `--n 128`, `--n 256`; `frob study plan` naming a tie at n = 64 | Tables equal (521/521/0/1,103 at 64; 1,031/1,031/1/1,765 at 86; 2,517/2,517/4/3,347 at 128; 11,384/11,384/39/10,346 at 256); the tie refused (FROB-REF-532) | A pre-analysis by normal approximation |

The CERT-01 and CERT-05 rows run `cert_corpus.sh` once and read its summary; the corpus is not generated a
second time.

**Steps per row.** (1) Run the command on the row's fixture; (2) compare the measured value with the threshold;
(3) run the row's G0 entry with its broken certifier, `cargo test -p frob-conformance --test g0_laws
--features gauntlet-mutations -- <row>`, and require the self-test to FAIL for the stated reason; (4) emit the
row's `metric` and `assert` events. A row whose broken certifier is not caught fails the gate whatever its first
half says. Rows not yet due are listed as `not-due`, never as passed.

**Measured value of the M1 part.** (rows meeting threshold, rows due, broken certifiers caught, mutants accepted);
threshold (8, 8, 8, 0). The tier run of the M1 rows, `cargo test -p frob-conformance --test g0_laws --
GATE-GAUNT-04`, writes the hash-named receipt (ADR-GAUNT-01) that a fresh-context session cites with the recorder
(N38b-19) to record the M1 part; the script records nothing itself.

**Logging.** Through the shared helper (STD-E2E) to `target/e2e-logs/certifiers/<utc>.ndjson` and a transcript
beside it. Every line carries `ts`, `script`, `bead`, `step`, `event`, `row`. `cmd` events: exact command, exit
code, wall time. `metric` events: value, unit and threshold (for CERT-03 the count of false rejections and 551;
for CERT-12 each of the sixteen counts beside its expected value; for CERT-11 disagreements per operator).
`refusal` events: the refusal code where the expected outcome is a refusal (FROB-REF-104, -532, the corpus
codes). `assert` events for both halves, with on failure the first differing value and the artifact paths (for
the corpus: the first accepted mutant's class and hash). The envelope's evidence block (claim, class, tier,
determinism, identities, seed). The `summary` gives rows passed and failed, broken certifiers caught, the receipt
hash and GATE-GAUNT-04 (part M1). No sealed campaign field and no private-scene data appear.

## Acceptance criteria

- [ ] `certifiers.sh M1` exits 0 only if all eight M1 rows meet their thresholds and all eight broken
      certifiers are caught; the measured tuple is (8, 8, 8, 0).
- [ ] A planted regression in any single M1 certifier (the checker skipping quantifiers, the unchecked answer,
      the literal-dimensionless checker, the peeking test, the diagonal-only inertia test, the padding monitor,
      the normal-approximation pre-analysis) makes the script exit non-zero and names the row.
- [ ] Rows of the register due at M3 or later are listed `not-due` and are never counted.
- [ ] The row table is read from the register; a register row added with `due = "M1"` is selected without an
      edit to the script.
- [ ] GATE-GAUNT-04's M1 part is recorded from the receipt of this run by a session that implemented none of the
      certifiers.
- [ ] A run above the default machine envelope (16 GiB, 8 cores, one hour) prints its reduced counts (for
      example `reduced: 2000 of 10000` campaigns) and is not recorded as a pass at the full count.

## Test plan

### Unit tests

`crates/frob-conformance/tests/certifier_register.rs` (shared with N38b-10 and N38b-17):
- `m1_rows_match_register`: the rows the script selects for `M1` are exactly the register's rows with an M1
  `due`: CERT-01, -02, -03, -04, -05, -06, -11, -12.
- `later_rows_not_due`: with a fixture register holding an M3 row, the `M1` selection lists it `not-due`.
- `measured_tuple`: fixture outcomes with all rows met and all controls caught give (8, 8, 8, 0) and `pass`;
  one uncaught broken certifier gives (8, 8, 7, 0) and `fail`; one accepted mutant gives `fail`.
- `vacuous_script_flagged`: a variant of the script that skips step 3 is planted in the harness self-test and is
  flagged as vacuous.
- `later_mode_not_built`: before N38b-17, the `M3` argument exits 2 with `not-built`.

### End-to-end script and logging

As above; selected by `scripts/e2e/run-all.sh --label gate --milestone M1` and re-run at every later exit.

### Known answers and negative controls

Known answers: the thresholds in the table (551 of 10⁴; 13/256; the sixteen enumeration counts; λ_min = −10⁻⁹).
Negative controls: the eight broken certifiers, one per row; the vacuous script variant. Determinism: counts
identical twice on one machine for a fixed seed (D0 for CERT-02, -04, -12; D0 given the seed for CERT-03 and
CERT-11).

## Considerations

- Cost is dominated by CERT-11 at 10⁶ traces per operator and by the corpus at 1,000 mutants per kind; both run
  nightly inside the default envelope when traces are short, and a reduced count is printed.
- The script reads the register so that the later rows (N38b-17) are an extension of data, not a second script.
- Split from N38b-17 in polishing round 1 so that the gate part due at M1 has its measurement at M1.
