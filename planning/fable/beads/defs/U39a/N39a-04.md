## Background

The primary claim of the ten-fold test is wall time: the ratio of restricted mean times to an independently
accepted answer between FrankenRobotics (arm A) and the rival arms (B and C). A wall-time ratio alone can hide a
trade: an arm may be faster because it burned ten times the compute, more agent tokens, or a person's attention.
The protocol therefore fixes identical resource caps for every arm and reports a set of cost columns beside the
clock for every run.

DESIGN: the columns are GPU-hours, CPU-hours, energy where a credible meter exists, agent tokens and tool calls,
human minutes (the default is zero, and any intervention is logged), and money at declared prices. Two derived
units are reported for design strata: designs decided per hour, and compute per accepted decision at a matched
error rate. **No cost claim is made.** A cost claim would need its own prices and its own registered test; the
columns exist so that a reader can see what the time ratio cost, and so that the "designs per hour" statements of
the program cite a defined quantity.

Rejected: folding cost into a single score (correctness and cost would then trade against time inside one number,
which the protocol forbids: correctness is a gate, and the time score is never improved by lowering the bar);
reporting energy as zero where no meter exists (a zero reads as a measurement).

## Scope

In: the cap set and its enforcement points; the cost columns and their sources; the price table; the two derived
units; the intervention log. Out: the clock (N39a-03); the resource table of the phase ledger from which device-
and core-seconds are read (N39a-24); the agent proxy and the rival process wrapper through which token, tool-call
and process caps are observed (N39a-25); the equal-terms rules that choose the caps (N39a-19); the accepted-output
rate ratio, a different estimand that is cited only for statements about decisions per hour (N39b-35).

## Technical approach

**1. Caps (identical for every arm of a pair; values come from the gate's pre-registration).**

| Cap | Unit | Enforced by | On breach |
|---|---|---|---|
| Devices | named GPU indices (primary result: one RTX 4090 of the Linux host) | device visibility set by the harness before launch | `cap_breach(device)` |
| CPU cores | count, pinned set | CPU affinity and a control group | `cap_breach(cpu)` |
| Memory | bytes, host and device | control group limit; device memory watermark sampled every second | `cap_breach(memory)` |
| Agent tokens | input and output tokens per campaign | the harness's agent proxy, which every arm's agent calls go through | `cap_breach(tokens)` |
| Tool calls | count per campaign | the same proxy | `cap_breach(tool_calls)` |
| Wall time | the stratum deadline H | the timekeeper | censoring at H |

A breach is not a disqualification: the run is censored at the instant of the breach and costs H (N39a-03). The
caps are recorded in the campaign record and in each arm's freeze manifest; a pair whose two campaigns ran under
different caps is refused (`caps-differ`, a row of the ten-fold refusal registry N39-REF). This bead supplies
that check as a function over two campaign records (`cost::caps_equal`, naming the cap that differs); the
scorer's pair validation, built later (N39a-27), calls it and raises the same reason.

**2. Columns, per campaign (appended to `campaign.json` under `cost`).**

| Column | Definition | Source |
|---|---|---|
| `gpu_h` | Σ device-seconds over all devices and phases ÷ 3600 | resource table of the phase ledger |
| `cpu_h` | Σ core-seconds ÷ 3600 | resource table |
| `energy_wh` | integrated device and host power over the clock | a named meter, or `{"gap": "<reason>"}`; never `0` for "unknown" |
| `tokens_in`, `tokens_out`, `agent_turns`, `tool_calls` | counts | the agent proxy |
| `human_min` | Σ durations of logged interventions | the intervention log; default `"0"` |
| `money` | Σ column × declared price | the price table |

*Price table* (`prices.json`, committed with the suite hash): `{currency, per_gpu_h, per_cpu_core_h,
per_mtok_in, per_mtok_out, per_kwh, declared_at}`. DESIGN: `gpu_h`, `cpu_h` and `money` are exact reduced
rationals (`"p/q"`) with a six-place decimal rendering beside them (half-to-even, the record rule of N39a-01),
because an hour count such as 160/3600 = 2/45 has no finite decimal. Money is computed from the integer device-
and core-seconds and the price strings in exact rationals, never from a rounded hour figure. Changing a price after
commitment is refused.

*Intervention log.* The equal-terms rule is no human in the loop. If a person nevertheless acts on a running
campaign (restarting a host, answering an agent's question), the action is an entry `{ts, actor, role, reason,
duration_s}` and the campaign is flagged `human-intervened`; the flag is printed in every table that includes the
campaign. An intervention is never silent.

**3. Derived units, for design strata.**
- *Designs decided per hour* = `designs_decided` ÷ (clock_s ÷ 3600). A design is *decided* when the arm has
  recorded a keep-or-discard decision on a distinct design identity together with the evidence it used. For arm A
  the count comes from the campaign report of the product; for arms B and C from the advocate's wrapper, which
  logs each distinct design identity at the moment its decision is written. A design evaluated but never decided
  does not count. The count is audited by sampling: the adjudicator opens five decided designs per campaign and
  checks that a decision record with evidence exists; a missing record voids the column for that campaign.
- *Compute per accepted decision at a matched error rate* = (device-seconds, core-seconds) ÷ number of accepted
  answers, printed as two numbers, and only for pairs in which both arms' answers were accepted under the same
  acceptance rule (same threshold, same level schedule); the matched error rate is the level of that rule.
  Otherwise the cell prints `unmatched`.

**4. Aggregation.** Per cell (a stratum and a regime) each column is reported as a sum and a per-accepted-answer
figure for each arm, beside the time ratio, never combined with it. The report states `cost_claim: none`.

## Acceptance criteria

- [ ] Each cap is enforced: six planted breaches (one per cap) each produce a censored outcome, the five resource
      caps with the matching `cap_breach` event and `censored-cap`, the wall-time cap with the `deadline` event
      and `censored-deadline` (N39a-03's classes); none produces a disqualification.
- [ ] `gpu_h` and `cpu_h` equal the resource table's sums divided by 3600 exactly, as reduced rationals with
      their six-place rendering.
- [ ] A host without a credible meter prints `{"gap": …}` for energy; no code path emits `"0"` for an unmeasured
      quantity.
- [ ] A planted intervention sets `human-intervened` and `human_min`, and the flag appears in the cell table.
- [ ] Money equals the sum of column × price in exact rationals; a changed price table is refused.
- [ ] The pair check refuses two campaign records with differing caps (`caps-differ`, naming the cap); the cell's
      cost block carries `cost_claim: none`. (That the scorer calls the check and that the report prints the
      line are criteria of N39a-27 and of the report writer N39a-36, which come after this bead.)

## Test plan

### Unit tests

`cargo test -p frob-conformance --test tenfold -- cost::`
- `hours_from_resource_table`: device seconds {screen 96, train 150, evaluate 60} → `gpu_h` = `"17/200"`
  (306/3600), rendered `0.085000`; core seconds {check 160} → `cpu_h` = `"2/45"`, rendered `0.044444`.
- `designs_per_hour`: 128 designs decided in a clock of 1,500 s → 128 ÷ (1500/3600) = 307.2 per hour.
- `money_exact`: 306 device-seconds at 1.20 per GPU-hour (51/500), 160 core-seconds at 0.05 per core-hour
  (1/450), 1.2 M tokens in at 3.00 (18/5) and 0.2 M out at 15.00 (3) → money = `"30169/4500"`, rendered
  `6.704222`; a mutant that multiplies the rounded `0.044444` hours gives 6.704222 by luck at six places but a
  different rational, and the test compares rationals; no binary floating point in the path.
- `energy_gap_not_zero`: no meter → `gap`; a serializer mutant that writes `"0"` fails.
- `caps_differ_refused`: a pair with 8 and 16 cores → `caps-differ`.
- `unmatched_error_rate`: arms accepted under different thresholds → `unmatched`.
- `intervention_flag`: one 90 s intervention → `human_min` = 1.5, flag set.

### End-to-end script and logging

`scripts/e2e/tenfold_caps.sh`: runs a synthetic arm six times on a rehearsal mission, each time breaching one cap
(a process that allocates past the memory cap, a proxy client that exceeds the token cap, and so on), then once
within caps with a planted intervention. Asserts the event, the outcome and the cost columns. It sources
`scripts/e2e/lib.sh` (STD-E2E) and writes NDJSON to `target/e2e-logs/tenfold_caps/<utc>.ndjson`. Logs command,
exit code, wall time, the cap and its value, the measured usage at the breach with units, the outcome, each cost
column with its unit, the `human-intervened` flag, on failure the first differing column with the campaign
directory, and a summary. Fixtures are labelled `synthetic`.

### Known answers and negative controls

Known answers: the arithmetic above; the cost of a cell of 24 mission families with three arms at a deadline of
4 h is at most 24 × 3 × 4 = 288 device-hours (every run censored) and about 24 × (1.5 + 1.0 + 0.4) = 69.6
device-hours at the hypothesised restricted mean times of 1.5 h, 1.0 h and 0.4 h (HYPOTHESIS; planning figure).
Negative controls: a wrapper that under-reports designs decided (caught by the sampled audit); an arm that calls
the model provider around the proxy (token count disagrees with the provider's usage record; the campaign is
flagged); energy written as zero.

## Considerations

- Energy: no credible meter is assumed on either machine until one is named; the default is a named gap in every
  record.
- The agent proxy is a trust point for token and tool-call counts; arms B and C must route through it, and the
  freeze manifest records the proxy's configuration hash.
- Runs of this test exceed the default compute envelope (16 GiB, 8 cores, one hour, one device); each gate names
  its budget and waits for the owner's approval of a campaign class before it runs.
- Device-seconds charged to background work during an agent turn are in the resource table and therefore in
  `gpu_h`, even though the exclusive time table does not show them.
