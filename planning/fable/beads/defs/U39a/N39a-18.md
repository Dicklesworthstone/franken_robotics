## Background

A timed comparison between two systems is a comparison between two *configurations*, and a configuration that can
still move is not one thing. If the rival is improved after the missions are seen, it was tuned against them; if
the product is patched mid-gate, the earlier runs measured something else. The ten-fold protocol therefore turns
every arm into a frozen, published object before any timed pair exists.

DESIGN. **Incumbents are frozen first**: no paired run of any kind happens before every arm in it has a published
freeze manifest (**INV-TENFOLD-03**: no paired run exists whose arms were not all frozen and published before it
started; no arm changes after its freeze). A manifest is content-addressed and is published, with the advocate's
signed statement that this is the strongest configuration the budget allowed and a list of what more budget would
have added. After the freeze nothing changes in any arm, arm A included. A defect found in a frozen arm after the
suite opens voids the affected cells, which are re-run at the next gate; it is never patched mid-gate.

The arms: A is FrankenRobotics at the gate's commit, driven by the common agent through its generated
documentation and public verbs, built and tuned by the builders. B is the strongest composed rival (a named
incumbent engine, per-design reinforcement learning, a standard outer-loop optimizer, analytic bounds and a
verifier where the stratum needs them, and the same agent), built and tuned by the rival advocates. C is the
ablation arm, a short robust program over an incumbent engine, also the advocates'.

Rejected: a freeze recorded only as a version tag (a tag does not cover hyperparameters, caches, wrappers or the
agent's guide); freezing the rival and leaving the product free to take fixes (the product would be tuned against
missions it has seen fail).

## Scope

In: the manifest record and what each field covers; content addressing and publication; the advocate's
statement; the three enforcement points of INV-TENFOLD-03; the drift check at every campaign start; voiding
cells. Out: the equal-terms values the manifest must agree with (N39a-19); arm B's composition and tuning
(N39a-20); arm C (N39a-21); the tag map's content (N39a-25); standing-asset arithmetic (N39a-17); the 10%
reproduction check of each frozen configuration on the gate's hardware (the rival audit N39b-37, register row
GATE-TENFOLD-11 N40-20); the disqualification that a `frozen-arm-changed` signal starts (N39b-01); what the agent
is (OPEN-TENFOLD-6, N39b-31); the licence readings and the `cleared` check itself (OPEN-TENFOLD-7, N39b-32),
which the freeze calls; the reason ids (N39-REF).

## Technical approach

**1. The record (one per arm and stratum; DESIGN field meanings, sample from the protocol).**
```json
{ "schema": "frob.tenfold.freeze/1", "gate": "M3-partial", "arm": "B", "stratum": "legged-quad",
  "engine": {"name": "…", "revision": "…", "licence": "…"}, "learner": {"name": "…", "revision": "…"},
  "outer_loop": {"name": "…", "script": "b3:…"}, "tool_layer": "b3:…", "agent_guide": "b3:…",
  "agent": {"model": "…", "revision": "…", "token_cap": "…", "tool_call_cap": "…"},
  "caches": {"compile": "warm", "policies": ["b3:…"]},
  "standing_assets": [{"name": "…", "build_wall_s": "…", "build_device_s": "…", "hash": "b3:…"}],
  "phase_tags": "b3:…", "tuning_log": "b3:…", "development_scores": "b3:…",
  "advocate": {"statement": "b3:…", "would_add_with_more_budget": ["…"]},
  "hardware": {"fingerprint": "b3:…"}, "frozen_at": "…", "manifest_hash": "b3:…" }
```

| Field | Covers |
|---|---|
| `engine`, `learner` | Exact revisions and the container digest of the environment they run in; the licence text's identity. For arm A: the product commit and the stack lock |
| `outer_loop` | The optimizer and its script (search space, budgets, halving schedule) |
| `tool_layer` | Everything the agent can call: wrappers, command-line tools, the MCP server configuration; for arm A the verb registry's hash |
| `agent_guide` | The documentation the agent may read: arm A's generated documentation; for B and C the incumbents' own documentation plus an advocate-written guide no longer than arm A's documentation |
| `agent` | The common agent model at one pinned revision, with the same token and tool-call caps for every arm |
| `caches` | The declared state of compile caches at clock start, and policies available at clock start |
| `standing_assets` | Everything built for the mission class before a clock starts, with its measured build cost |
| `phase_tags` | The tag map by which the wrapper assigns every launched process to a phase of the ledger |
| `tuning_log` | The log of tuning on the development suite: runs, device-hours, changes made |
| `development_scores` | The arm's times and outcomes on the development suite, including the easy-win families |
| `advocate` | The signed statement, and what more budget would have added |
| `hardware.fingerprint` | The hardware fingerprint record of the machine the arm is frozen for |

`manifest_hash` is the content address of the record with that field blanked. Every `b3:` it names must resolve
in the published pack (the arm's files in a content-addressed directory), so the manifest pins bytes.

**2. Publication.** `frob-tenfold freeze publish` copies the manifest and the pack's index to the gate's public
area and appends the step-4 entry to the sealing ledger. "Published" means readable by every party of the gate,
builders and advocates included. Incumbent code itself is not redistributed: the pack pins revisions and gives
fetch instructions; wrappers, scripts, guides and tag maps are in the pack.

**3. The advocate's statement.** A text signed under the advocate's registered identity: "this is the strongest
configuration the budget allowed", the budget spent in device-hours, each documented incumbent capability left
unused with the reason, and the list `would_add_with_more_budget`. For arm A the builders sign the equivalent
statement. A manifest without a verifying statement is not accepted (`freeze-statement-missing`).

**4. Enforcement of INV-TENFOLD-03 (three points).**
1. *At step 4.* `freeze write` refuses a manifest whose `frozen_at` precedes the suite commitment
   (`freeze-before-suite-commit`), and one whose step-4 entry would follow the `open` entry (`freeze-after-open`,
   raised by the sealing ledger's order check, N39a-15, which this bead calls rather than repeats). It also runs
   every check registered for the gate through a freeze-check hook this bead exposes, and refuses with the reason
   the check returns, appending no step-4 entry. The equal-terms
   bead (N39a-19, which depends on this one and owns the terms record committed at step 2) registers the
   agent-block and hardware-fingerprint comparisons there (`freeze-agent-differs`, `freeze-hardware-differs`);
   this bead does not define those values. This bead itself registers, for arms B and C, the wrapper bead's
   tool-layer check and tag-map validator (N39a-25: every tool a shim, every tool covered by a rule, `default`
   null, the reserved phases), so that a pack failing either cannot be frozen. It also registers the licence
   check of the OPEN-TENFOLD-7 decision (N39b-32): for every incumbent the manifest names (the `engine`, the
   `learner` and every pinned incumbent tool of the tool layer, at the revision the manifest pins),
   `licences::cleared(incumbent, revision)` must answer cleared; an incumbent whose licence reading for *run* or
   *publish* is not `yes` (`unclear` counts as `no`), or whose reading is stale because its pin moved, refuses the
   freeze with `tenfold.incumbent-licence-not-cleared` (exit 3; repairs: replace it by the next strongest
   candidate whose licence permits publication and print the replacement; repeat the reading at the new pin; ask
   the owner to rule on an `unclear` reading). Arm A names no incumbent and is not checked.
2. *At every campaign start.* The harness rebuilds the arm's workspace from the pack and recomputes the hash of
   every file and of the engine's container; any difference from the manifest refuses the campaign and raises a
   `frozen-arm-changed` signal (a change to a frozen arm after its freeze is a disqualifying event). A campaign
   for a pair is refused unless *every* arm of that pair has a published manifest whose step-4 entry precedes the
   `open` entry (`pair-arm-not-frozen`).
3. *At scoring.* The scorer checks that each ledger's `freeze` field names the manifest hash published at step 4
   for that arm and stratum; a ledger citing any other hash is excluded as a protocol breach, not as an
   inconvenient run. The scorer's side of this check is its pair rule (N39a-27, check 2, `pair-mismatch`); this bead
   supplies the list of published manifest hashes per arm and stratum that it reads.

**5. A defect found after opening.** The adjudicator appends `void-cells {arm, stratum, reason, evidence}`; the
cells are reported `void: defect in frozen arm` with no ratio and are re-run at the next gate on fresh families.
No repair is applied to a frozen arm while the gate is open, for either side.

**6. One configuration per stratum.** An arm has exactly one manifest per stratum for a gate; a per-mission choice
of configuration is refused (`freeze-duplicate`). The same configuration may serve several strata under separate
manifests.

## Acceptance criteria

- [ ] The sample record parses, and its `manifest_hash` verifies; every `b3:` reference resolves in the pack.
- [ ] A manifest whose freeze time follows the suite opening is refused and no run starts.
- [ ] A campaign start with one byte of the tool layer changed refuses and raises `frozen-arm-changed`.
- [ ] A pair in which arm C has no published manifest cannot start, even if A and B are frozen.
- [ ] A second manifest for the same arm and stratum is refused.
- [ ] A manifest naming an incumbent whose licence is not cleared at its pin (`unclear` included) is refused at
      freeze with `tenfold.incumbent-licence-not-cleared`.
- [ ] INV-TENFOLD-03 holds over the gate's records as a query: for every campaign, each arm's step-4 sequence
      number is lower than the campaign's `card_delivered` sequence number, and the workspace hash at start equals
      the manifest's.
- [ ] A voided cell prints no ratio and names its reason.

## Test plan

### Unit tests

`cargo test -p frob-conformance --test tenfold -- freeze::`
- `sample_parses_and_hashes`: the record above with concrete values.
- `dangling_reference`: `tool_layer` hash absent from the pack → refused.
- `frozen_before_commit`, `frozen_after_open`: both refused with their reasons.
- `freeze_hook_refusal_propagates`: a check registered through the freeze-check hook that returns
  `freeze-agent-differs` → `freeze write` exits 3 with that reason and the sealing ledger gains no step-4 entry; a
  check that passes → the entry is appended.
- `drift_detected`: pack file changed after publication → `frozen-arm-changed` at campaign start.
- `all_arms_of_pair_frozen`: {A, B} frozen, C missing → `pair-arm-not-frozen`.
- `one_manifest_per_stratum`: duplicate → `freeze-duplicate`.
- `wrapper_checks_at_freeze`: an arm B pack whose tool layer holds a non-shim executable, or whose tag map has a
  non-null `default` or an uncovered tool (`tagmap-uncovered-tool`), cannot be frozen; the corrected pack can.
- `licence_unclear_refused_at_freeze`: a manifest naming an engine whose licence reading has `publish = unclear`
  (a `synthetic` reading in `licence_readings.toml`) → `freeze write` exits 3 with
  `tenfold.incumbent-licence-not-cleared` and no step-4 entry; the same engine with `publish = yes` and
  `run = yes` freezes; a reading taken at an earlier pin than the manifest's → refused as stale.
- `inv_tenfold_03_query`: a constructed gate store with one campaign started before its arm's freeze entry → the
  query returns that campaign.
- `statement_signature`: an unsigned or wrongly signed statement → `freeze-statement-missing`.

### End-to-end script and logging

`scripts/e2e/tenfold_freeze.sh`: on a rehearsal gate, builds packs for two synthetic arms, writes and publishes
their manifests after a synthetic suite commitment, starts a paired campaign, then changes one wrapper byte and
starts another. Asserts acceptance of the first and refusal of the second, and the refusal of a pair with an
unfrozen third arm. It also attempts to freeze a third pack whose engine carries a `synthetic` licence reading
with `publish = unclear`, and asserts `tenfold.incumbent-licence-not-cleared` (exit 3) with no step-4 entry. It sources `scripts/e2e/lib.sh` (STD-E2E) and writes NDJSON to
`target/e2e-logs/tenfold_freeze/<utc>.ndjson`. Logs each command, exit code, wall time, each manifest hash, the
workspace hash at start beside the manifest's, on a drift the first differing pack path with both hashes, each
refusal reason (`tenfold.frozen-arm-changed` with exit 9, `tenfold.pair-arm-not-frozen` with exit 3), the
sealing-ledger sequence numbers, and the summary naming GATE-TENFOLD-04.

### Known answers and negative controls

Negative controls (each must be caught): a manifest whose freeze time follows the suite opening (the run is
refused); an arm changed after its freeze; a pair started with one arm unfrozen; a manifest that names a version
tag instead of a revision hash; a ledger citing an unpublished manifest; a manifest naming an incumbent whose
licence reading is `unclear` (refused at freeze). Two of these are entries of the harness's counterexample
registry (N39-CX), and this bead writes their planted inputs under the registry's plant names, as `synthetic`
fixture directories under `crates/frob-conformance/fixtures/tenfold/controls/`: `freeze_after_open/` (TF-CX-14;
gates GATE-TENFOLD-03 and -04), a rehearsal store whose arm B manifest has its step-4 entry after the `open`
entry, caught when `freeze write` refuses it with `freeze-after-open` (exit 3) and no campaign of the pair
starts; and `arm_patched_after_open/` (TF-CX-24; GATE-TENFOLD-03), a store in which one file of arm A's pack was
replaced by a fix after the `open` entry, caught when the next campaign start refuses with `frozen-arm-changed`
(exit 9) and the affected cells can only be recorded `void: defect in frozen arm` (step 5), never scored on the
patched arm. The gate auditor (N39b-23) reads both. Metamorphic: re-serializing a manifest
does not change its hash. Determinism: hashes are D0 on both platforms.

## Considerations

- OPEN-TENFOLD-6 (owner, N39b-31): the agent model, its revision and its caps; it blocks every freeze. Default:
  the agent the project is developed with at the gate's date, pinned; one agent only, with the result stated as
  conditional on it.
- A hosted agent model can change behind a fixed name; the manifest records the provider's revision identifier
  and the dates of the gate, and a provider-side change during the gate is a protocol breach that voids the cells
  it spans.
- At M7 every pin of every arm and of every sibling library is frozen for the length of the tournament; a ratio
  of times measured across a pin move is not one measurement.
- The pack contains advocate-written code that the builders may read after publication and before `open`; that
  is intended (they may object in writing that the rival is under-built) and harmless, because arm A is frozen in
  the same step.
