## Background

The ten-fold test reports a ratio of times. A ratio by itself explains nothing: it does not say whether the
rival's time went into training, into the agent thinking, or into waiting for a compile, and so it cannot say
which mechanism earned the difference or which one could never have. The **phase ledger** is what turns a ratio
into an explanation: every run of every arm records where its clock went. It is also the only input the ceiling
arithmetic of the test accepts, and no end-to-end phase ledger of an agent-driven design loop on the current
incumbent stacks has been published (FACT about the sources read), which is why the program measures the rival's
ledger at its first two milestones before funding any mechanism against it.

The clock T of a run is the wall time from the moment the agent receives the mission card to the moment the
adjudicator accepts the answer (or the stratum's deadline). This bead defines the vocabulary of thirteen phases,
the raw record from which a ledger is built, and the rule that assigns **every instant** of the clock to exactly
one phase.

DESIGN decisions. (1) Attribution is *exclusive* on the critical path: one instant, one phase, so the table sums
to the clock. Rejected: summing all activity per phase (concurrent jobs would make the table exceed the clock and
hide what the agent was actually waiting for). (2) While the agent is blocked on several jobs, the job that
finishes last owns the instants, because it alone determines when the agent can continue. Rejected: splitting
blocked time among concurrent jobs in proportion (rewards padding with parallel work). (3) Work done in the
background of an agent turn is not lost: it goes to a second, *resource* table (N39a-24).

## Scope

In: the phase vocabulary and its mapping from the product's own phase names; the raw interval record; the
attribution algorithm and its tie-breaks; the exclusive table. Out: the resource table, the closure rule and the
ledger record (N39a-24); how intervals are captured from an arm's processes (N39a-25); what reads the table
(N39a-26, N39a-37).

## Technical approach

**1. The phases.**

| Phase | What is charged to it | Product phase names that map here |
|---|---|---|
| `author` | Writing the environment, design domain, reward or requirement, and evaluation set from the mission card | studio loop: authoring |
| `propose` | An agent turn that reads results and emits the next request: model latency and tool-call overhead | studio loop: review |
| `check` | Design realization and static analysis: edit to a valid model, preflight, pre-simulation analyses | studio loop: check |
| `synthesize` | Controller synthesis without training: baseline controllers, gait orbits, trajectory optimization | studio loop: synthesis |
| `compile` | Compilation or cache lookup, model upload, variant admission, graph capture, scene compile, up to the first device step | performance program: compilation, admission |
| `screen` | Rollouts on cheap rungs that train nothing | studio loop: simulation; performance program: screening |
| `train` | Policy training, fine-tuning and distillation, learner time included | studio loop: training; performance program: training |
| `evaluate` | Evaluation batteries, comparisons, promotion to a higher tier | studio loop: promotion; performance program: evaluation, promotion |
| `qualify` | The arm's own blinded confirmation before it submits | performance program: qualification |
| `certify` | Proof search, certificate writing and the arm's own checking | none |
| `diagnose` | Failure analysis: replays, forks, attribution, counterexample search, reading logs | studio loop: review |
| `wait` | Queueing, device transfer, idle time, harness service time | performance program: waiting |
| `adjudicate` | From a committed submission to its receipt | none |

A fourteenth bucket, `unattributed`, holds instants the instrumentation cannot place. It is not a phase.

**2. Raw record (`intervals.ndjson`, one object per line; times are integer milliseconds on the harness clock).**
```
{ "id": 17, "kind": "turn" | "block" | "work" | "harness" | "adjudication",
  "phase": "<one of the 13>" | null, "start_ms": "…", "end_ms": "…",
  "awaits": [ids]            (kind block: the work, harness and adjudication intervals the agent is waiting for)
  "resource": {"devices": [0], "cores": 8, "cpu_ms": "…", "learner_ms": "…"}   (kind work)
  "tokens_in": "…", "tokens_out": "…", "tool_calls": 0                      (kind turn)
  "proc": "<process or job identity>", "tag_rule": "<rule of the tag map that set the phase>" }
```
- `turn`: an agent turn in progress, from the start of a model call to the dispatch of the tool calls it emitted.
- `block`: the agent is waiting on tool results; `awaits` lists what it waits for.
- `work`: a job or process doing something, with its phase. A job that passes through several phases (compile,
  then screen) emits one `work` interval per phase, split at the first device step.
- `harness`: the harness serving a request of the arm. `adjudication`: a committed submission until its receipt.

**3. The phase of a turn.** `author` if every tool call the turn emits carries the tag `author`; `diagnose` if
every one carries `diagnose`; otherwise `propose`. A turn that emits no tool call (a final answer) is `propose`.
Model latency before a tool call therefore goes where the request it produced goes.

**4. Attribution algorithm (`phase/exclusive.rs`).** Input: the intervals of one campaign, t₀ and t_stop.
1. Clip every interval to [t₀, t_stop). Collect all endpoints, sort, and form the elementary segments [u, v).
2. For each segment, the owner is the first rule that applies:
   a. A `turn` covers it → the turn's phase. (Two overlapping turns of parallel agent workers: the one that
      started first owns it; tie → lower `id`.)
   b. A `block` covers it. Among the things it awaits, the *owner* is the one with the latest `end_ms`
      (tie → lower `id`). A multi-phase job is represented by several `work` intervals sharing `proc`; "the
      owner" is then the whole job, and its end is its last interval's end. Where the owner's own interval covers
      this segment, the segment takes that interval's phase: `adjudicate` for an adjudication, `wait` for a
      harness interval, the interval's phase for work. Where the owner does not cover the segment (it has not
      started yet, or it is between two of its sub-phases) the segment is `wait`: the agent is idle on the
      critical path.
   c. No turn and no block, and an `adjudication` covers it → `adjudicate`; else a `harness` covers it → `wait`.
   d. Otherwise → `unattributed`.
3. The exclusive table is the sum of segment lengths per phase. By construction
   Σ_phases + `unattributed` = t_stop − t₀ = T (or H for a censored run), exactly, in milliseconds.
Complexity: O(n log n) in the number of intervals. The function is pure and class D0.

**5. Worked attribution (a unit-test fixture).** t₀ = 0, t_stop = 100 s. Turn 1 [0, 10) `propose`. Block [10, 60)
awaiting job 1 (`compile` [10, 22), `screen` [22, 40)) and job 2 (`train` [12, 60)). Turn 2 [60, 70) `propose`.
Block [70, 90) awaiting an adjudication [70, 90). Nothing in [90, 100). Job 2 finishes last, so it owns the first
block: [10, 12) is `wait` (the owner has not started), [12, 60) is `train`. Result: `propose` 20, `wait` 2,
`train` 48, `adjudicate` 20, `unattributed` 10; sum 100. Job 1's 12 s of compilation and 18 s of screening appear
only in the resource table: they ran in the shadow of the training job and did not delay the agent.

**6. Censored and breached runs.** For a run censored at H, t_stop = t₀ + H and intervals are clipped there. For a
run censored by a cap breach the table covers [t₀, breach) and the remainder H − (breach − t₀) is charged to
`wait` with the flag `censored-remainder` (DESIGN: the restricted time is H, and the remainder is time the arm
did not use; marking it keeps the table equal to the charged time while letting ceiling arithmetic exclude it).

## Acceptance criteria

- [ ] The phase enumeration has exactly the thirteen names plus `unattributed`; an interval with any other phase
      is refused at read time.
- [ ] For every campaign, the exclusive table sums to the charged clock exactly (in milliseconds).
- [ ] The worked fixture yields the five values of step 5.
- [ ] Rule 2b's tie-breaks are deterministic: the same interval set in any input order gives the same table.
- [ ] A multi-phase job charges `compile` up to its first device step and its run phase afterwards.
- [ ] The algorithm handles 10⁵ intervals in under one second on a laptop core (TARGET; it is offline analysis).

## Test plan

### Unit tests

`cargo test -p frob-conformance --test tenfold -- phase::exclusive::`
- `worked_fixture`: step 5, exact.
- `sums_to_clock_property`: 10⁴ random interval sets (random kinds, overlaps, gaps); Σ = T in every case.
- `turn_beats_block`: a turn overlapping a block → the turn's phase owns the overlap.
- `last_finisher_owns`: awaited works ending at 40 and 60 → the second owns [start, 60).
- `tie_break_lower_id`: equal ends → lower id.
- `adjudication_owner`: a block [20, 80) awaiting a training job [20, 50) and an adjudication [30, 80) → the
  adjudication ends last and owns the block: [20, 30) is `wait` (the owner has not started), [30, 80) is
  `adjudicate`, and the training job's 30 s appear only in the resource table.
- `turn_phase_rule`: tool tags {author, author} → `author`; {author, screen} → `propose`; {} → `propose`;
  {diagnose} → `diagnose`.
- `order_invariance`: shuffled input lines → identical table.
- `censored_clip`: intervals past H are clipped; cap-breach remainder goes to `wait` with its flag.
- `unknown_phase_refused`.

### End-to-end script and logging

`scripts/e2e/tenfold_phase_attribution.sh` (`bead=N39a-23 milestone=M0 needs=cpu`): runs
`frob-tenfold phase attribute <intervals.ndjson> --t0 … --stop …` (the subcommand this bead adds to the operator
shell of N39a-01; it prints the exclusive table as canonical JSON) on (1) the worked fixture of step 5 and the
`adjudication_owner` fixture, comparing exactly; (2) interval files built for the two campaigns of the single-pair
card (turns, blocks and awaited work laid out to its phase durations), comparing with the known-answer tables
below; (3) a generated file of 10⁵ intervals, timing the run against
the 1 s TARGET; (4) the same 10⁵ intervals shuffled, comparing the two tables byte for byte; (5) a file with a
fourteenth phase name, expecting the refusal. Capturing intervals from real processes through the wrapper and
building the ledger record are the next two beads' end-to-end scripts (N39a-25 runs the scripted two-turn,
two-job, one-submission scenario against durations within 0.3 s; N39a-24 builds and checks the ledger), because
both depend on this one. It sources `scripts/e2e/lib.sh` (STD-E2E) and writes NDJSON to
`target/e2e-logs/tenfold_phase_attribution/<utc>.ndjson`. Logs each command, exit code, wall time, the table in
seconds beside the expected values, the sum beside the clock, the 10⁵-interval time against 1 s, and on failure
the offending segment with the intervals covering it. The generated files are labelled `synthetic`.

### Known answers and negative controls

Known answers: the worked fixture; the single-pair card of the harness's known-answer set, whose two exclusive
tables are, in seconds, arm B: `author` 900, `propose` 1,080, `check` 240, `compile` 540, `screen` 0, `train`
4,920, `evaluate` 360, `qualify` 0, `diagnose` 600, `wait` 180, `adjudicate` 180 (clock 9,000) and arm A, in the
same order: 600, 360, 20, 12, 96, 150, 60, 40, 30, 42, 90 (clock 1,500); `synthesize` and `certify` are 0 in both
and `unattributed` is 0. Negative controls: an attribution that sums all activity
(the table exceeds the clock; the property test fails it); one that splits blocked time evenly among awaited jobs
(the worked fixture would give `train` 24 and fails); one that drops gaps instead of marking them `unattributed`
(the sum falls short).

## Considerations

- "Agent blocked on jobs" presumes the harness can see what the agent waits for. For arm A that comes from the
  product's verbs and job handles; for rival arms from the wrapper's process tree per tool call (N39a-25). Where
  that link is missing, the block's `awaits` is empty and the block falls to `wait`, which inflates `wait` and
  shows up as an implausible share; the tag map's review exists to catch it.
- Parallel agent workers are allowed under equal caps; the first-started rule is a simplification that keeps
  attribution exclusive. If an arm relies heavily on parallel workers, its `propose` share is a lower bound on
  agent activity and the resource table carries the rest.
- The mapping from the product's two phase vocabularies is many-to-one in places (`review` maps to both `propose`
  and `diagnose`, split by tool tags); the tag map is where that split is made explicit.
