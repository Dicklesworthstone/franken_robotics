## Background

The phase ledger of the ten-fold test assigns every instant of an arm's clock to one of thirteen phases
(`author`, `propose`, `check`, `synthesize`, `compile`, `screen`, `train`, `evaluate`, `qualify`, `certify`,
`diagnose`, `wait`, `adjudicate`). That requires knowing, for each arm, what the agent was doing and what every
process it launched was doing. FrankenRobotics reports this itself through its verbs and job handles. A rival arm
is a composition of foreign tools (an incumbent simulator, a learning stack, an optimizer script, a solver) that
report nothing in common.

DESIGN: for arms B and C **the advocate's wrapper tags every process it launches, and the tag map is part of the
freeze manifest**. The wrapper is the single launch path for everything the rival's agent can run; the tag map is
the published, frozen rule by which a launched command becomes a phase. The harness also places an **agent
proxy** between every arm's agent and its model provider and tools, because the agent's own turns are the one
thing all arms have in common and must be measured identically.

Reasons. A ledger that the rival's advocates cannot audit would let the builders mis-describe where the rival's
time goes; a ledger the advocates tag after the fact would let them do the same. A rule frozen before any sealed
run, applied mechanically, does neither. Rejected: sampling profilers on the rival's processes (no phase
semantics); asking the agent to self-report phases (unverifiable, and it spends tokens).

This bead is needed at M0: the incumbent phases that need no agent (cold start, edit to first step, training to
threshold) are timed through this wrapper on the Linux host, and the M1 agent-driven rival loop adds the proxy.

## Scope

In: the wrapper (launch, process-tree tracking, interval emission, resource sampling); the agent proxy (turn and
tool-call intervals, token and tool-call counts, cap enforcement hooks, block intervals with their awaited set);
the tag map format, its matching rules, its validation and its freezing; the coverage report. Out: the attribution
algorithm (N39a-23); ledger assembly (N39a-24), which the end-to-end script below calls; the incumbent
environments and pins (BD-039); arm A's own tag map and its derivation of intervals from verb envelopes and job
records (the our-arm bead of the partial gate, BD-316, using the format and validator defined here); the freeze
manifest that hashes the tag map and runs this bead's checks at step 4 (N39a-18).

## Technical approach

**1. The wrapper (`frob-tenfold wrap -- <command…>`; library in `phase/tagmap.rs` and `arms/`).**
1. Every tool in a rival arm's tool layer is installed as a shim that calls the wrapper; the tool-layer check
   this bead provides (`frob-tenfold wrap check <tool-layer>`, run again by the freeze manifest's freeze-check
   hook at M3) refuses a tool layer containing an executable that is not a shim or a pinned incumbent binary
   reached only through one.
2. On launch the wrapper: assigns an interval identity; places the command in a fresh process group and control
   group (the same one that enforces the campaign's caps); resolves its phase from the tag map; emits a `work`
   interval start with `proc`, `phase`, `tag_rule`, devices and cores.
3. While it runs: samples device utilization and memory per second for the devices it holds; accumulates CPU time
   of the whole process tree from the control group.
4. Phase changes inside one command: a tool may print marker lines on a dedicated file descriptor
   (`@phase <name>`), and the wrapper closes the current `work` interval and opens the next. The one mandatory
   marker is the **first device step** of a simulation or training command, which ends `compile` (compilation or
   cache lookup, model upload, variant admission, graph capture, scene compile) and begins the command's run
   phase. Incumbent tools are made to emit it by a thin patch in the advocate's wrapper script (for example a
   callback after the first environment step), which is part of the pack.
5. Learner timers: for `train`, the wrapper reads the training loop's own cumulative timers (environment,
   inference, learning) from its log at exit and records `learner_ms`.
6. On exit: emits the interval end with the exit status, CPU time and peak memory. A process that escapes its
   process group is killed with the campaign and reported (`wrapper-escape`).

**2. The agent proxy.** One process per campaign through which the agent's model calls and tool calls pass, for
every arm.
- Model call start → `turn` interval start; completion and dispatch of its tool calls → `turn` end, with
  `tokens_in`, `tokens_out`, `tool_calls`.
- Each dispatched tool call → the proxy records which `work` intervals (processes or jobs) it started and, until
  its result returns to the agent, a `block` interval whose `awaits` lists them. For asynchronous tools (start a
  job, return a handle) the block ends at once and a later explicit wait call opens a new block awaiting the
  handles it names.
- Requests the harness serves (card delivery, artifact hand-off, submission intake) → `harness` intervals.
- The proxy counts tokens and tool calls against the campaign's caps and signals a breach.
- It refuses a session identifier it has seen before (fresh context per campaign).

**3. The tag map (`phase_tags` in the freeze manifest; canonical JSON).**
```
{ "arm": "B", "stratum": "legged-quad",
  "rules": [ { "id": "r1", "match": {"tool": "train_policy", "argv_regex": ".*"}, "phase": "train",
               "first_step_marker": true },
             { "id": "r2", "match": {"tool": "edit_design"}, "phase": "check" }, … ],
  "tool_tags": { "write_env": "author", "read_logs": "diagnose", "replay": "diagnose", … },
  "default": null }
```
- Rules are tried in order; the first match gives the phase. `tool_tags` gives the tag used for the phase of an
  agent *turn* (a turn is `author` if every tool call it emits is tagged `author`, `diagnose` if every one is
  tagged `diagnose`, otherwise `propose`).
- `default` must be `null`: a launched command that matches no rule is recorded with `phase: null` and its time
  becomes `unattributed`. There is no catch-all bucket to hide in.
- Validation at freeze: every tool of the tool layer appears in at least one rule (`tagmap-uncovered-tool`); every
  phase name is one of the thirteen; a rule may not assign `wait` or `adjudicate` (those are the harness's);
  simulation and training rules declare the first-step marker. `tagmap-uncovered-tool` and `wrapper-escape` are
  rows of the ten-fold refusal registry (N39-REF).
- Review before the freeze: the builders may read the rival's tag map and object through the comment channel
  (for example to training being tagged `screen`); the adjudicator rules. The same applies in reverse to arm A's.

**4. Coverage report (`frob-tenfold tagmap report`).** After the development runs: per rule, the number of
launches and total seconds; the list of unmatched launches; the share of the clock that is `unattributed` per
campaign. An arm whose development campaigns are more than 2% unattributed is told before the freeze, because its
sealed runs would be `ledger-open` and useless for ceiling arithmetic.

**5. Arm A.** The product needs no wrapper: each verb call's envelope carries its timing and job handles, and the
daemon's job records carry start, first device step and end. Arm A still runs behind the same agent proxy, and
its tag map has the same format with `match` on verb names (for example `design.check` → `check`,
`train.start` → `train`, `autopsy.attribute` → `diagnose`, `prove.bundle` → `certify`, `eval.qualify` →
`qualify`). Writing arm A's map is part of the our-arm bead of the partial gate (BD-316); the format and validator
are here.

## Acceptance criteria

- [ ] A command launched through the wrapper yields `work` intervals whose total duration equals the measured wall
      time of the command within 50 ms, with CPU time and device assignment recorded.
- [ ] A training command with the first-step marker yields a `compile` interval followed by a `train` interval,
      split at the marker; without the marker the freeze check refuses the rule.
- [ ] An unmatched command becomes `unattributed` time; `default` other than `null` is refused.
- [ ] The proxy's `turn` and `block` intervals reproduce the scripted timeline of the attribution fixture; token
      and tool-call counts equal the provider's own usage figures on a recorded session.
- [ ] A tool layer with a non-shim executable is refused; a process escaping its group is killed and reported.
- [ ] The tag map validator enforces coverage, phase names and the two reserved phases.

## Test plan

### Unit tests

`cargo test -p frob-conformance --test tenfold -- tagmap::`
- `first_match_wins`: two rules matching one command → the first.
- `uncovered_tool`: a tool with no rule → `tagmap-uncovered-tool`.
- `reserved_phases`: a rule assigning `adjudicate` → refused.
- `default_must_be_null`.
- `marker_splits_interval`: start 0, marker at 45 s, end 410 s → `compile` 45, `train` 365.
- `turn_tag_resolution`: tool tags per the three cases.
- `async_tool_blocks`: start-job returns at once (no block), wait-job blocks until the job's end with `awaits`
  naming it.
- `proxy_counts`: a recorded session of 4 turns → `turns: 4` and the recorded token totals.

### End-to-end script and logging

`scripts/e2e/tenfold_wrapper.sh` (`bead=N39a-25 milestone=M0 needs=cpu`): installs a three-tool synthetic tool
layer (an "edit" that sleeps 1 s, a "train" that prints the first-step marker after 2 s and runs 5 s, an
unmatched "mystery" tool), drives it with a scripted agent through the proxy, and builds the ledger. Asserts the
`compile` and `train` split, the `unattributed` time of the unmatched tool, and the coverage report. A second
scenario (moved here from the attribution bead N39a-23, whose script cannot use the wrapper it precedes): the
scripted agent makes two turns, launches two overlapping jobs with known sleep durations through the wrapper and
makes one submission through the proxy's intake (a `harness` interval); the ledger is built with
`frob-tenfold ledger build` and each phase of the exclusive table is compared with the scripted duration within
0.3 s. The `adjudication` interval from a commit to a real receipt is asserted at M3 by the receipt bead's script
(N39a-09). It sources `scripts/e2e/lib.sh` (STD-E2E) and writes NDJSON to
`target/e2e-logs/tenfold_wrapper/<utc>.ndjson`. Logs each command, exit code, wall time, every interval with its
rule, the per-rule totals, CPU seconds, the exclusive table beside the scripted durations, on a failed
comparison the offending segment with the intervals covering it, and the summary. The tool layer and the agent
are labelled `synthetic`. On the Linux host with an incumbent installed, a third step wraps one real incumbent
training launch at reduced size and logs its compile region against the published figure of about 45 s (context,
not an assertion); elsewhere it exits 77 for that step with the reason.

### Known answers and negative controls

Known answers: the marker split 45 + 365 = 410 s (the published one-card training time with its compile region,
used as fixture numbers). Negative controls: a tag map with a catch-all default (refused); a wrapper script that
launches a second process outside the wrapper (caught by the process group and by the pack check); training
tagged as `screen` (not mechanically detectable: caught by the pre-freeze review, and by the resource table,
where a `screen` phase with learner seconds is flagged as inconsistent); a proxy bypass (token counts disagree
with the provider's usage record).

## Considerations

- The first-step marker requires a small patch to incumbent tools; it is the advocates' code, it is in the pack,
  and it must not change the incumbent's behaviour (the rival's home-task time is re-measured with the patch in
  place and must stay within 20% of its published figure).
- Wrapper overhead is charged to the arm like any tool overhead; it is measured on the null command and reported
  (TARGET: under 20 ms per launch).
- The wrapper sees command lines and timing only; it records no simulator state and no private data.
- Where a rival tool cannot be made to emit the marker, the advocates may declare the whole command `train` (or
  its run phase); its compile time then inflates that phase, which the pre-freeze review notes.
