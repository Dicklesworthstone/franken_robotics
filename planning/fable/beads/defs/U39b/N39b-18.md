## Background

A result nobody else can recompute is a claim, not a measurement. Every gate of the ten-fold test is therefore
published with a replication kit: everything needed to recompute the published numbers from the raw records
(level 1) and to run sampled pairs again (level 2). The kit matters most when no external adjudicator was
available: a ratio measured by the project's own adjudicating session is labelled `self-adjudicated`, and the
words "independently accepted" and "ten-fold" wait until an external party has re-run the kit. GATE-TENFOLD-08
(claim kind: Known answer; M7): level 1 reproduces every published number bit for bit on a clean machine; level
2 re-runs one sampled pair per stratum with the same acceptance outcome and a time within a factor of 1.5 in at
least 90% of pairs; a kit with a private input is refused. If the gate is not met the result is labelled
`unreplicated` and the word "ten-fold" is not used. This bead builds the kit; the scorer is N39b-19, the level-2
procedure N39b-20, the gate's script N39b-21.

Terms. *Manifest of hashes*: a list of every file in the kit with its content hash, itself hashed to give the
kit's digest. *Freeze manifest*: an arm's published, content-addressed configuration. *Private*: the mark
carried by anything derived from a scan of a real home or workplace; it is inherited through lineage.
*No-authorization flags*: three fields with the constant value `false` on every exported artifact
(`execution_authorized`, `hardware_safety_signoff`, `sim_to_real_certified`).

## Scope

In: the kit's contents and layout; the builder and the verifier; the manifest; the limits (no incumbent code, no
private input, flags on everything); a secrets check on transcripts. Out: the scorer (N39b-19); the re-run
(N39b-20); publication (BD-433).

## Technical approach

Commands (DESIGN): `frob-tenfold kit build --gate <id> --out <dir>` and `frob-tenfold kit verify <dir>`; module
`crates/frob-conformance/src/tenfold/kit.rs`.

**Contents (all required; a missing class refuses the build with `tenfold.kit-incomplete`).**

| Directory | Contents |
|---|---|
| `registration/` | The pre-registration (parameter block, confirmatory cells, result types, margins) and the recorded pre-analysis, with the event-log entries that date them |
| `suite/` | Every mission card, the world generators, and the revealed keys (sealed key, canary derivation label) |
| `protocol/` | The referee protocol and the adjudicator's acceptance code |
| `arms/<arm>/` | Every freeze manifest with the scripts, wrappers, tag maps and agent guides it names; the advocate's signed statement; for incumbents, pins and fetch instructions only |
| `records/` | Every ledger, every receipt, every agent transcript, the gate's event log |
| `scorer/` | The scorer's source with a build recipe that needs only a Rust compiler and no dependency outside the standard library |
| `hardware/` | Hardware fingerprints and the disclosure block of every run |
| `report/` | The published report (JSON, Markdown, HTML) |
| `MANIFEST.json` | Schema `frob.tenfold.kit/1` (DESIGN: the manifest's own schema name; the chapter names none): for every file its path, size and BLAKE3 hash; the kit digest; the gate; the labels in force; the authorization flags |
| `README.md`, `LICENCE` | How to run level 1 (the scorer's recipe `rustc --edition 2021 -O scorer/main.rs -o tenfold-score`, N39b-19, run on `records/`) and level 2 (`frob-tenfold kit level2 <kit-dir> --party external --out <dir> --json`, N39b-20); the licence of the kit's own content |

**Build algorithm.**
1. Resolve the gate directory; refuse if the gate is not closed and revealed (`tenfold.kit-gate-open`).
2. Lineage check: compute the `private` mark and the licence join of every input. Any private or
   non-redistributable input refuses the build (FROB-REF-899) naming the input; ranked repairs: replace it by
   its generator seed and recipe; pin and give fetch instructions; exclude the stratum and print it
   `not replicable`.
3. Incumbent code: never copied. For each incumbent the kit carries name, release, revision, container digest,
   licence and fetch instructions, and only what the licence decision of OPEN-TENFOLD-7 (N39b-32) allows; a
   file whose hash matches a known incumbent artifact refuses the build (FROB-REF-899, non-redistributable).
4. Secrets check (DESIGN): transcripts and wrappers are scanned for credential patterns (provider keys, tokens,
   private hosts); a hit refuses the build (`tenfold.kit-credential-found`, naming file and offset, never the
   matched text) until the span is replaced by a typed redaction marker that records
   the span's hash, so that level 1 still verifies the transcript's recorded digest through the marker table.
5. Flags: every exported artifact is written through the exporting path that attaches the three flags, all
   false; an artifact without them refuses the build (FROB-REF-860).
6. Completeness: every number in the report must be recomputable from `records/` by the scorer; the builder
   runs level 1 itself and refuses on any difference.
7. Canonical form: files in sorted order, canonical JSON, no timestamps other than those inside records; the
   same gate directory yields the same kit bytes and digest (class D0).

**Verify.** Recomputes every hash and the kit digest; checks the flags; checks that the report's digest equals
the one cited by the gate's row; lists anything extra or missing.

**Limits stated in the README.** Incumbent code is not redistributed. A private scene or dataset cannot enter a
kit. The kit proves recomputation and sampled re-runs, not the truth of the simulators.

## Acceptance criteria

- [ ] `kit build` on the rehearsal gate produces every directory of the table and a manifest whose digest is
      stable across two builds.
- [ ] `kit verify` passes on the built kit and fails when any one byte of any file is changed, naming the file.
- [ ] A kit with a private input is refused (FROB-REF-899); a kit containing an incumbent artifact is refused; an
      artifact without flags is refused (FROB-REF-860); a transcript with a planted credential is refused.
- [ ] The builder's own level-1 run reproduces every published number bit for bit, or the build is refused.
- [ ] The kit unpacks and verifies on a machine with no project checkout.

## Test plan

### Unit tests

`cargo test -p frob-conformance tenfold::kit`: `manifest_covers_every_file`; `digest_is_order_independent_of_
filesystem` (files created in two orders give one digest); `private_lineage_refused` (a still derived from a
replay of a policy evaluated in a private scene); `incumbent_artifact_refused`; `flags_required_and_false`;
`credential_refused_then_redacted_verifies`; `missing_receipts_incomplete`; `verify_detects_one_byte`;
`open_gate_refused` (`tenfold.kit-gate-open`); `licence_decision_limits_contents` (an incumbent whose recorded
licence decision allows pins and fetch instructions only contributes no other file).

### End-to-end script and logging

`scripts/e2e/tenfold_kit_build.sh`, owned by this bead and built only on its dependencies (header `bead=N39b-18
milestone=M7 labels=tenfold,e2e gates=GATE-TENFOLD-08 seed=391801 needs=cpu plants=private-input,incumbent-file,
no-flags,credential,missing-receipt,open-gate,one-byte,stale-report`), on the closed, scored rehearsal gate
directory that `scripts/e2e/tenfold_partial_gate.sh` (N39b-12) keeps when run in replay mode with `--keep-gate
<dir>` (labelled `synthetic`, never claimable): (1) `FROB_TEST_SEED=391801 cargo test -p frob-conformance
tenfold::kit`; (2) `frob-tenfold kit build` twice into two scratch directories: assert every directory of the
contents table, a manifest listing every file, equal bytes and equal digest, and the builder's own level-1 run
with zero differences; (3) `frob-tenfold kit verify` (exit 0); (4) the plants, each on a fresh copy and through
`e2e_expect_refusal` or `e2e_expect_caught`: a lineage including the private fixture (FROB-REF-899, the three
repairs in rank order); an incumbent artifact under `arms/` (FROB-REF-899); an artifact without the flags object
(FROB-REF-860); a planted credential in a transcript (`tenfold.kit-credential-found`, naming file and offset, then
redacted through the marker table and verified); one receipt removed (`tenfold.kit-incomplete`); a copy whose
event log is cut before its close entry, a valid prefix of the chain (`tenfold.kit-gate-open`); one byte of one ledger changed in the built kit (`kit verify` fails naming the file);
the report regenerated after the gate's record cited its digest (`kit verify` fails on the digest). Logged as
NDJSON through the STD-E2E helper (`ts`, `script`, `bead`, `step`, `event`, exact command line, exit code, wall
time, seed): the kit digest, file counts per directory, each refusal with its code and first repair, the level-1
comparison count, each plant as a `negative-control` assertion with `caught`; on failure the first differing
value and the kit's path; a final `summary` with assertion counts. `scripts/e2e/tenfold_kit.sh` (N39b-21, which
depends on this bead) runs this script as a stage before its step `build` and then ships the kit to a second
host.

### Known answers and negative controls

Negative controls: TF-CX-19 (a private input); one changed byte; a kit whose report was regenerated after the
gate row was recorded (digest mismatch). Determinism: two builds, equal bytes; debug and release.

## Considerations

- Repository visibility and the licence file are an owner decision; the default is a private repository, with
  the kit and the offline auditor as the only artifacts prepared for a third party. A private repository cannot
  be independently confirmed; the kit is the countermeasure.
- Agent transcripts are large; the kit stores them compressed with a fixed, recorded codec setting so that
  hashes are stable.
- Incumbent licences decide what the kit may carry; the default is revisions and fetch instructions only.
