## Background

The published numbers of the ten-fold test are computed by one program, the scorer, from ledgers and receipts
alone. The replication kit carries it, and the kit's first level of replication is that the scorer reproduces
every published ratio, interval, count and verdict, bit for bit, on a clean machine. For that the scorer, like
the offline certificate auditor, depends on nothing outside the standard library: a third party must be able to
read it, build it with a bare compiler and trust that no dependency changed its arithmetic. The scorer is also
where two classic mistakes would silently inflate the result (averaging per-family ratios; dropping a run that
never finished), so it is tested against planted wrong scorers.

Symbols. H: the stratum's deadline. T_X,j: the clock of arm X on pair j (A this system, B the rival, C the
ablation arm). A campaign not accepted by H is censored and contributes H. Cell: a stratum and a regime; m
families, c campaigns per family, n = m·c pairs. S_X: build cost of arm X's standing assets. ā, b̄: pooled
restricted mean times per amendment.

Rejected alternatives. Floating-point sums (rejected: order-dependent). The platform's `ln`, `exp` and normal
quantile for the bootstrap (rejected: library results differ across platforms in the last bit, which can move a
selected order statistic). A scorer inside the harness crate's dependency graph only (rejected: a clean machine
would have to build the whole workspace).

## Scope

In: the binary, its input and output schemas, exact arithmetic rules, the deterministic bootstrap, the
standard-library-only constraint and its test, the comparison mode. Out: the statistical design itself (the
statistics beads); the contrast test's definition (N39b-35); three-arm statistics (N39b-43), which call the same
primitives; the report (N39b-14).

## Technical approach

**Layout (DESIGN).** Sources in `crates/frob-conformance/src/tenfold/score/`, in the module layout the harness
skeleton fixed (N39a-01: `ratio`, `bootstrap`, `guard`, `noninferiority`, `verdict`, `warm`, `monitor`,
`ceiling`, `preanalysis`, `normal`, `rng`; later beads add `contrast` (N39b-35) and `threearm` (N39b-43)). This
bead adds `input.rs` (reading the gate directory and checking every digest against the event log), `exact.rs`
(decimal parsing to integer milliseconds and outward/half-even rendering) and the kit entry `kit/scorer/main.rs`,
which declares the same files as `#[path]` modules. Only `std` and the three auditor source files (canonical
JSON, BLAKE3, exact rationals) are used, included by path; the boundary lint of N39a-01 enforces it. The harness
crate compiles the same files as a module, so there is one implementation. Build recipe in the kit:
`rustc --edition 2021 -O scorer/main.rs -o tenfold-score`.

**One program, one design.** Inside the workspace the scorer is the binary `frob-tenfold-score`
(`crates/frob-conformance/src/bin/frob-tenfold-score.rs`, created with the harness skeleton); the kit's recipe
above builds the same sources with `rustc` alone and names the output `tenfold-score`. The statistical design is
that of the statistics beads (the pooled ratio and censoring rule N39a-27, the bootstrap N39a-28, the guard
N39a-29, the non-inferiority and zero-count bounds N39a-30, the verdict rule N39a-32, the warm ratio N39a-17);
this bead packages their modules and restates the formulas so that the binary is self-describing. Where the
restatement below and those beads differ, those beads govern, and four points are fixed here so that the two
texts agree: (i) durations are canonical decimal strings of seconds with at most three fractional digits and are
summed as integer milliseconds, as every harness record writes them; (ii) the bootstrap's generator, its seed
(derived from the suite commitment, the stratum and the regime, not chosen), the definition of p₀ with half
weight on ties and its clamp, the index rule on (B + 1) and the near-integer guard are those of N39a-28, and the
normal functions are the one file `score/normal.rs` specified there (absolute error at most 10⁻¹²); (iii) exit
codes follow the chapter's refusal registry (N39-REF): 3 for a refusal, 9 for an integrity fault, and 1 only for
a `--check` difference; (iv) of the two builds of these sources, the kit's is the bare-compiler build of this
bead, with the auditor's files included by path and no crate dependency, and the workspace's is the package
build set up with the harness skeleton (N39a-01), with one path dependency on the auditor's crate; a test builds
both and requires equal output bytes on the worked cards.

**Command.** `tenfold-score --gate-dir <dir> --out score.json [--check report.json]`. Exit 0 on success; 2 on
success with flags (a `ledger-open` run or an `index_tie` recorded); 3 on a typed refusal (an open campaign, a
monitor output offered, a missing input record); 9 on an integrity fault (a record whose digest does not match
the event log); 1 only when `--check` finds a difference (the first differing field is printed). These are the
codes of the chapter's refusal registry (N39-REF).

**Inputs.** The registration (parameter block; cells with m, c, H, regime, result type; the confirmatory list
and the number of confirmatory cells; the bootstrap seed), every ledger and receipt, the event log, and the
gate records the verdict rule reads through its input views (N39a-32): each cell's pre-analysis record
(`PreanalysisView`), the disqualification records of arms A, B and C, the adjudication label, and the
replication record (`ReplicationView`) where one exists. The tie record (`TieView`) is not an input: the scorer
computes it from arm C's (or W's) ledgers in `threearm` (N39b-43). A cell missing any record the verdict needs
is refused (`verdict-input-missing`, exit 3), never defaulted. Each record's digest is recomputed and compared
with the event log before use. There is no input field for a
monitor's output, and the scorer refuses to run on a cell whose planned campaigns are not all closed or
recorded as excluded (the fixed-n verdict is computed once, at n).

**Exact arithmetic.** Times are parsed from decimal strings into integer milliseconds; sums are integers
(128-bit); ratios are reduced rationals; a decimal is printed from the rational by exact long division. The
rendering rule is the one all harness records use: a point estimate is rounded half to even at the stated number
of digits; a confidence bound is rounded outward (an upper bound up, a lower bound down), so that a printed bound
is never tighter than the computed one (which is why the zero-count bound 0.11734615… prints as 0.1174).
Binomial tails are exact: P(X ≥ x) = Σ_{k≥x} C(m, k) ÷ 2^m.

**Statistics computed (formulas restated so the binary is self-describing).**
1. Pooled ratio, cold: R̂ = Σ_j min(T_B,j, H) ÷ Σ_j min(T_A,j, H). Per family i: ρ_i on that family's pairs; when
   arm B is censored ρ_i is a lower bound, flagged; when arm A is censored ρ_i ≤ 1.
2. Censoring and exclusions: both-censored pairs stay in both sums; a pair excluded for a second harness fault
   is excluded for every arm and counted; over 5% excluded makes the cell `descriptive`. A cap breach censors
   at the instant of the breach and costs H. A mission whose accepted answer was later shown wrong costs H.
3. Warm: R_warm(N) = (S_B + N·b̄) ÷ (S_A + N·ā) at N = 1, 10, 100 and the limit b̄ ÷ ā; N* = the smallest N with
   S_A + N·ā ≤ S_B + N·b̄ (none if ā ≥ b̄ and S_A > S_B); the cell's R̂ is R_warm(10).
4. Bounds L and U (one-sided 95%): bias-corrected bootstrap, B = 10,000 replicates, families resampled with
   replacement and each family's pairs kept together. The generator is SplitMix64 seeded from the first eight
   bytes of BLAKE3(suite commitment ‖ stratum ‖ regime ‖ "bootstrap/1"); replicate r = 1…B draws m family
   indices in order with the unbiased `below(m)` (128-bit multiply with rejection). Each replicate's ratio R*_r
   is an exact rational. p₀ = (#{R*_r < R̂} + ½·#{R*_r = R̂}) ÷ B, clamped to [1/(2B), 1 − 1/(2B)], and
   z₀ = Φ⁻¹(p₀); the lower bound is the order statistic at k_L = max(1, ⌊(B + 1)·Φ(2·z₀ + z_0.05)⌋) and the
   upper at k_U = min(B, ⌈(B + 1)·Φ(2·z₀ + z_0.95)⌉). Because order statistics commute with the logarithm,
   selecting on R* equals selecting on ln R* and no logarithm of data is needed. Φ and Φ⁻¹ are evaluated by
   fixed algorithms written in this crate from additions, multiplications, divisions and square roots only
   (which IEEE arithmetic rounds identically everywhere), with their own `exp` and `ln` by argument reduction
   and fixed polynomials; if (B + 1)·Φ(…) lies within 10⁻⁶ of an integer the more conservative index is taken
   (one lower for L, one higher for U, within [1, B]) and `index_tie: true` is recorded.
5. Guard: X = #{i : ρ_i > 5} (a lower-bound ρ_i counts when the bound itself exceeds 5); critical count from the
   exact tail at the cell's Holm-adjusted level (step-down across the confirmatory cells at family level 0.05).
6. Completion by H per arm, and on family strata the share of mandatory obligations discharged, with the exact
   non-inferiority bound against margin 0.05; a zero-count rate is given the bound 1 − α^(1/n), never a
   bootstrap.
7. Verdict, first row that applies: `disqualified`; `descriptive`; `withdrawn` (R̂ < 3); `ten-fold`; `measured`.
8. The rate ratio R_rate = (accepted_A ÷ makespan_A) ÷ (accepted_B ÷ makespan_B), printed as a different
   estimand; the bounded paired contrast where a population result was declared.
9. Phase tables: pooled exclusive seconds and shares per arm over closed runs; `ledger-open` runs counted and
   excluded from ceilings but kept in ratios.
10. Ceilings: the six ceilings of the cell evaluated on the rival's closed ledgers by `score/ceiling.rs`
    (N39a-37), so that level 1 recomputes the ceilings the report prints (the completion ceiling R ≤ 1/q and,
    on these rival times, Σ min(T_B, H) ÷ (missed × H): 3.75 on the six-family card). `ceiling.rs` evaluates
    its formulas with the thesis calculators (N00-17) and pools shares through the ledger bead's closed-only
    selection (N39a-24); the bare-compiler build therefore includes those source files by path too, and they
    obey the same boundary (std and the auditor's exact rationals only). The boundary lint covers them; a
    calculator that imports any other crate fails `std_only_sources`.

**Output.** `score.json` in canonical JSON with every value as a string (rational and decimal), every input
digest, the seed, the scorer's own source digest and the compiler version. Two runs give equal bytes (class D0)
on any conforming platform.

## Acceptance criteria

- [ ] The scorer builds with a bare compiler and no external crate; a test fails if any `extern crate` or
      non-`std` path appears in its sources.
- [ ] On the six-family card it prints R̂ = 45/17 (2.647), the six per-family ratios, the ceiling 3.75 and "no
      verdict: n below 10"; on the warm card 0.272, 2.120, 6.596, limit 8.617 and N* = 5.
- [ ] The planted wrong scorers (average of ratios: 6.23; dropping the censored family: 7.05) differ from it on
      the card and are caught by `--check`.
- [ ] Output bytes are equal on arm64 macOS and x86-64 Linux, in debug and release, for the rehearsal gate.
- [ ] A cell with an open campaign, and any attempt to pass a monitor output, are refused.
- [ ] `--check` against a published report passes on the unmodified gate directory and fails on any edited
      ledger, naming the first differing field.

### Known answers and negative controls

Known answers: rows TF-01 to TF-19 of the harness registry. Negative controls: TF-CX-01, -02, -04, -05, -06, -08,
-09. Metamorphic relations: permuting families or pairs leaves every output unchanged; multiplying all times
and H by a constant leaves ratios, counts and verdicts unchanged; adding a both-censored pair lowers a ratio
above 1 toward 1. Determinism lanes: twice on one machine; debug and release; two platforms.

## Considerations

- The bootstrap interval is approximate and descriptive and does not decide the word; it is printed with every
  ratio. On a 24-family suite from a population whose true ratio is 1.82, a percentile bootstrap can report 20.
- Integer milliseconds bound a sum of 10⁶ runs of 10⁵ s well inside 128 bits.
- The scorer must stay small enough to read in an afternoon (TARGET: under 2,500 lines with tests).
