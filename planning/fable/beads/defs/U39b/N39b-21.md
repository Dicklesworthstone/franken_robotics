## Background

GATE-TENFOLD-08 is the gate of the replication kit (claim kind: Known answer; M7). Its threshold: level 1
reproduces every published number bit for bit on a clean machine; level 2 re-runs one sampled pair per stratum
with the same acceptance outcome and a time within a factor of 1.5 in at least 90% of pairs; a kit with a
private input is refused. If it is not met the result is labelled `unreplicated` and the word "ten-fold" is not
used. This bead is the end-to-end script that exercises the kit the way a third party would: from an unpacked
directory, with a bare compiler, on a machine that has no checkout of the project. It runs first on the
rehearsal gate (where it proves the machinery and claims nothing) and then on the tournament's kit, where its
log is the evidence the gate's row cites for levels 1 and 2 (the external party's own run is recorded beside it).

## Scope

In: the script that measures GATE-TENFOLD-08, its steps, plants and log: it builds and ships the kit, runs
level 1 and level 2 on the second host, and catches the plants. Its log, with the measured counts and the share,
is the measurement the gate is decided on.

Out, with the bead that has it: the builder, scorer and level-2 procedure (N39b-18, -19, -20); the gate's row
in the gate register, the check `tenfold08` that reads this script's log and the kit and assigns the two
sub-results `level1` and `level2`, applying the comparability function of N39b-20 to the logged fingerprints, and the
consequence while the row is not `pass` (figures stamped `unreplicated`, the word "ten-fold" refused): the
program-gate bead N40-17, which depends on this bead. This script enters no row; N40-17 runs no level.

## Technical approach

`scripts/e2e/tenfold_kit.sh`; header `bead=N39b-21 milestone=M7 labels=tenfold,e2e gates=GATE-TENFOLD-08
seed=390821 needs=cpu,second-host plants=one-byte,private-input,incumbent-file,missing-receipt,stale-report,
slow-arm,outcome-flip,true-flag`. On the rehearsal gate the arms are the synthetic CPU arms of N39b-12, so `cpu`
suffices; on the tournament's kit the `level2` step also needs `cuda` on the second host (one RTX 4090 and the
gate's core count per campaign, the comparability rule of N39b-20). Where the second host has no such device the
step is written with `e2e_skip` naming the missing device: a skip is never a pass, so level 2 is then not
measured and N40-17 cannot record the gate.

Steps:

1. `build`: `frob-tenfold kit build --gate <gate> --out <scratch>/kit`; assert every directory of the contents
   table exists and the manifest lists every file; record the kit digest.
2. `rebuild`: build again into a second directory; assert equal bytes and equal digest.
3. `verify`: `frob-tenfold kit verify`; assert pass.
4. `ship`: copy the kit alone to the second host (no repository, no toolchain cache).
5. `level1`: first run `scripts/e2e/tenfold_scorer.sh` (N39b-19's script) as a stage; then, on the second
   host, build the scorer with a bare compiler from `kit/scorer/`; run it on
   `kit/records/`; assert that its output equals the published report's numbers field by field and that the
   scorer's output digest equals the one recorded in the report; run it twice and compare bytes.
6. `level2`: first run `scripts/e2e/tenfold_level2.sh` (N39b-20's script) as a stage; then, on the second host,
   `frob-tenfold kit level2 kit --party internal --out <scratch> --json` (N39b-20's command) rebuilds each arm
   from its manifest, re-runs the sampled pair of each stratum and adjudicates with the released acceptance
   code; assert the record's sampled pairs equal the public draw and the share of replicating pairs against 0.9.
7. `refusals` (each through `e2e_expect_refusal` or `e2e_expect_caught`):
   - `private-input`: a gate directory whose lineage includes the private fixture: build refused (FROB-REF-899),
     repairs in rank order (seed and recipe; pin and fetch; exclude the stratum).
   - `incumbent-file`: an incumbent artifact placed under `arms/`: build refused (FROB-REF-899,
     non-redistributable).
   - `missing-receipt`: one receipt removed: build refused as incomplete (`tenfold.kit-incomplete`).
   - `true-flag`: an artifact whose `execution_authorized` is true: refused by the reader as foreign
     (FROB-REF-816, flags missing or not `false`); an artifact with no flags object is refused at export
     (FROB-REF-860).
8. `tamper`:
   - `one-byte`: change one byte of one ledger in the shipped kit: `verify` fails naming the file, and level 1
     reports the first differing field.
   - `stale-report`: regenerate the report after the gate row was recorded: digest mismatch caught.
   - `slow-arm`: plant a factor-2 slowdown in one arm's level-2 re-run: the pair does not replicate.
   - `outcome-flip`: in one arm's level-2 re-run of a pair accepted originally, substitute a submission the
     released acceptance code rejects, at the original time: the pair does not replicate although q = 1.0
     (the outcome half of the level-2 rule is tested apart from its time half).
9. `summary`: gate table with measured values: files hashed, numbers recomputed and equal (count), pairs
   sampled, pairs replicated, share.

**Logging.** Through the shared helper, for every step: the exact command, exit code and wall time on each host
(the host is named by its fingerprint digest, never by host name); the kit digest; for level 1 one `assert` per
published number with observed and expected as exact strings; for level 2 one `metric` per campaign (time ratio
against 1.5) and one for the share (against 0.9); every refusal with its code, first repair and `expected:
true`; on failure the first differing value and the paths of the two files. The summary lists
`gates: [{id: "GATE-TENFOLD-08", measured_ok, controls_caught}]`; on the rehearsal gate `gates_claimable: false`.
Transcripts in the kit are referenced by digest in the log and never copied into it.

**Idempotence.** Scratch directories on both hosts are per run; the script removes nothing outside them; the
seed fixes the sampled pairs of the rehearsal and the order of plants.

## Acceptance criteria

- [ ] On the rehearsal gate the script passes with every plant caught, on two consecutive runs with equal kit
      digests.
- [ ] Level 1 on the second host compares every published number (count logged) and finds zero differences.
- [ ] Level 2's share is logged against 0.9 and the step fails below it.
- [ ] The private-input build is refused with FROB-REF-899 and the stated repairs.
- [ ] On the tournament's kit the log is handed to the program-gate bead N40-17, which attaches it to the gate's
      row; without the log the row cannot record a pass.

## Test plan

### Unit tests

None of its own beyond a header check (`frob-e2e list` shows the gate, the eight plants and the second-host
need); the mechanisms' unit tests are in their beads.

### End-to-end script and logging

This bead is the script.

### Known answers and negative controls

Known answers: the published numbers of the rehearsal gate (R̂ = 45/17 and its companions); the level-2 count
rule ⌈0.9·S⌉. Negative controls: the eight plants. Determinism lanes: the kit built twice on one machine; the
scorer on two platforms; debug and release builds of the scorer giving equal output.

## Considerations

- The second host must be genuinely clean: the script checks that no project path exists there before step 4.
- Level 2 on the tournament's kit is expensive (up to one deadline per arm per stratum); the script accepts a
  resumable state file so that an interrupted re-run continues with the same sample.
- An external party may run this script unmodified; their log, with their fingerprint, is the external record.
