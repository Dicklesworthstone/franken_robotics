## Background

Every arm of the ten-fold test is driven by the same AI agent: the same model at one pinned revision for the
whole gate, the same token and tool-call caps per campaign, a fresh context per campaign, and no human in the
loop. The agent's latency per turn is common to both arms and bounds what any system can gain per turn (with
latency t and a rival cost C per decision, deciding one design per turn gives at most (C + t)/t). Which agent,
at which revision and with which caps, is an open question owned by the project owner. It blocks every freeze,
and the first use is at M1: the incumbent design loop is measured "with the common agent" (GATE-TENFOLD-02).

Fail-closed default: the agent the project itself is developed with at the gate's date, pinned; one agent only,
with the result stated as conditional on it.

## Scope

In: the decision record; the pin and caps; the seed policy; the retirement risk; how the choice is stated in
results. Out: the agent documentation of this system and the advocates' guide (their beads).

## Technical approach

1. **What is decided.** (a) The model and its exact revision identifier as the provider publishes it. (b) The
   token cap and the tool-call cap per campaign, the same for every arm. (c) The per-turn output limit and
   context limit, if the provider exposes them. (d) Whether the provider allows a sampling seed; if it does,
   the campaign seed fixes it; if not, the record says so and agent sampling is an unpaired source of variance.
   (e) Parallel workers per campaign (the same cap on model calls and parallel workers for every arm).
2. **How caps are chosen (DESIGN).** From the M1 baseline pilot runs: the caps are set at twice the 90th
   percentile of tokens and of tool calls that the rival's agent used on development missions that reached
   acceptance, so that a cap rarely binds a run that would have finished; a cap breach is not a
   disqualification, the run is censored at the breach and costs H. Caps are revisited before each gate's
   freeze and never during a gate.
3. **One agent only.** The primary result uses one agent. A second agent may be run as a separate, labelled
   result; ratios are never pooled across agents. Every reported ratio is conditional on the pinned agent, and
   the limits block of every report says so.
4. **Equal documentation.** Arm A's agent reads this system's agent documentation; the agents of arms B and C
   read the incumbents' own documentation and an advocate-written guide no longer than that documentation,
   frozen with the arm. The decision records the length reference (in tokens of the pinned model).
5. **Revision drift.** Before every campaign the harness records the revision the provider reports; a campaign
   whose reported revision differs from the pin is refused. If the provider retires the revision during a gate,
   the gate is suspended, not continued on another revision; cells not yet complete are void and re-run at the
   next gate. The kit's README states the known retirement date, since level 2 of replication depends on it.
6. **Record.** `decisions/OPEN-TENFOLD-6.md`: the fields of step 1, the cap derivation with the measured
   percentiles, the length reference, and the date; cited by every freeze manifest's `agent` block.

## Acceptance criteria

- [ ] The decision or the default is recorded before the M1 incumbent loop runs; the baseline's records carry
      the agent pin.
- [ ] Caps are identical across arms in every freeze manifest of a gate; a manifest with different caps is
      refused at publication.
- [ ] A campaign started under a different reported revision is refused.
- [ ] Reports state that ratios are conditional on the pinned agent.

## Test plan

### Unit tests

`cargo test -p frob-conformance tenfold::agentpin`: `caps_equal_across_arms`; `revision_mismatch_refuses_campaign`;
`cap_rule_twice_p90` (p90 of 180,000 tokens gives a cap of 360,000); `cap_breach_censors` (the run contributes
H, flagged `cap_breach: tokens`); `second_agent_not_pooled`.

### End-to-end script and logging

Step `run` of `scripts/e2e/tenfold_partial_gate.sh` (N39b-12) asserts, for the synthetic arms, equal caps and a
refused campaign under a planted revision mismatch; `scripts/e2e/tenfold_incumbent_loop.sh` (BD-143) logs the
agent pin, tokens and tool calls per campaign against the caps.

### Known answers and negative controls

Known answer: the latency ceiling (C + t)/t, for example C = 410 s and t = 90 s gives 5.56. Negative controls: a
manifest with a larger token cap for one arm; a silent revision change.

## Considerations

- A stronger agent may shrink the ratio (it compensates for a weaker tool surface) or grow it; the test makes
  no claim about agents that were not run.
- Provider-side nondeterminism cannot be removed; it is why times replicate only within a factor (1.5 in the
  kit's second level) and why the family, not the campaign, is the unit of inference.
- Token cost is reported in the cost columns at declared prices; no cost claim is made.
