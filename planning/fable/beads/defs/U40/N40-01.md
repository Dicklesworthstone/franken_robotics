## Background

A **gate** in this program is a named, numbered condition with a threshold: a foundation may be used only after its
*admission gate* (`INT-…`) has a record; a capability counts only after its *convergence gate* (`GATE-…`) has one; a
bet is abandoned by a *kill gate* (`KILL-…`, printed with ✖) whose trigger and fallback are written before the
measurement; and a handful of *program gates* decide whether the program continues as planned. The gate register is
the single list of all of them. It is data: `registries/gates.toml`, one record per gate, and every printed table (the
README's honest-status table, the register's own tables, the milestone exit reports, the release rubric, the
dashboard's gate view) is generated from that file and from nothing else.

This bead fixes what a record is and the nine rules every record obeys. It exists because the sibling projects showed
how a program can look finished when it is not: gates that were never run printed as green, a gate was re-scoped
after its measurement came in low, and the session that built a capability also declared it passed. The rules below
make each of those states unrepresentable or refused at write time. DESIGN decisions and the alternatives rejected:

- *One file, generated views* (ADR-GAUNT-02: registries are data and the document is their printout). Rejected: a
  hand-edited status table, because a hand-edited table drifts from the tests that are supposed to back it.
- *No verb and no `xtask` subcommand writes a gate* (ADR-GAUNT-01). A tier of the verification harness is a test
  target of `frob-conformance`, run as `cargo test -p frob-conformance --test <tier> -- <gate or row>`; the run writes
  a hash-named receipt; a recording session then enters the row that cites the receipt. Rejected: a `frob gate pass`
  verb, because a harness driven through the surface it judges is a path to self-certification, and `xtask` holds
  exactly six checks, runs no physics and records no gate.
- *A missing measurement is a status of its own.* Rejected: a boolean `passed`, which cannot tell "not run" from
  "failed" and tempts a default of true.

Terms: a **negative control** is a planted defect that the gate's test must catch (registry
`frob-conformance/registry/controls.toml`, identifiers `NC-nnnn`); a **receipt** is the hash-named output file of a
harness run; the **artifact graph** is the content-addressed graph of claims, evidence and executions behind
`frob evidence trace`; a **fresh-context session** is an agent session that did not implement the capability.

## Scope

In: the record schema `frob.gates/1` (base record plus the fields rule 6 and rule 2 need), the status set and its
printed forms, the nine rules as validation, the write-time refusals, the loader and validator. Out: the rows
themselves (N40-02, N40-10), kill-gate decision records and amendments (N40-03), the exit query (N40-04), the README
table generator (seed BD-002), the negative-control registry (seed BD-025), the artifact graph (seed BD-095).

## Technical approach

**1. The record (DESIGN; the base fields are the Gauntlet chapter's, the fields marked ＋ are added here).**

```toml
[[gate]]
id         = "GATE-KIN-04"
kind       = "convergence"         # ＋ admission | convergence | program | kill
claim      = "known-answer"        # proof | known-answer | parity | fidelity | design-comparison | reality | performance
claim_id   = "clm:…"               # the claim identifier the PASS rests on; resolves in the artifact graph
section    = "16.17"               # the defining subsection: its owner (rule 9)
consumers  = []                    # ＋ other subsections that state the same gate from their side
threshold  = "…"                   # the brief; the full criterion is the defining bead's
milestone  = "M1"                  # the earliest milestone (rule 6)
recurring  = false                 # ＋ true for the gates of rule 8
tier       = ["G1:host"]
controls   = ["NC-0412"]           # registered negative controls; empty forbids pass
[[gate.part]]                      # ＋ one per milestone at which a part is due; a single-part gate has one
milestone  = "M1"
scope      = "referee rows"
status     = "not-run"             # not-run | pass | fail | killed | blocked | no-claim | superseded
measured   = ""                    # the value with unit and interval, or the count; never the target
commit     = ""                    # ＋ commit of this repository
command    = ""                    # ＋ the exact command line
receipt    = ""                    # ＋ BLAKE3 hash of the receipt file; the output it names
fingerprint = ""                   # ＋ hardware fingerprint; with the seed, required by the definition of "implemented"
seed       = ""
evidence   = []                    # ledger sequence numbers and trace identifiers
recorded   = { date = "", session = "", implemented_by = "" }
detail     = ""                    # ＋ for killed: kill gate and fallback; for blocked: the OPEN identifier
```

Admission rows carry `foundation` and `first_needed` and are mirrored in `DEPENDENCY_ADMISSION.md`. Kill rows carry
`trigger`, `fallback`, `decided`, `owner`, `consumers` (N40-03).

**2. Statuses (seven; a reconciliation recorded here).** The register chapter lists `not run`, `pass`, `fail`,
`killed: fallback adopted`, `blocked: ⟨open question⟩`; the Gauntlet chapter's schema lists `not-run`, `pass`, `fail`,
`killed`, `no-claim`, `superseded`. The file uses the union: `not-run` (prints "not run", shown as open, never as
passed); `pass`; `fail`; `killed` (prints "killed: fallback adopted", with the kill gate and the fallback's name);
`blocked` (prints "blocked: OPEN-…"); `no-claim` (terminal, only for gates whose claim is `reality`); `superseded`
(a gate replaced by another, naming it). A row with no part recorded is `not-run`.

**3. The nine rules, as checks of `validate()`.**

1. *A gate passes only with a recorded measurement against its threshold.* `pass` requires `measured`, `commit`,
   `command`, `receipt`, `fingerprint`, `seed` non-empty and every `evidence` entry and `claim_id` resolving.
2. *A kill gate names trigger and fallback in advance and is never quietly re-scoped.* A kill row's `trigger`,
   threshold or `fallback` differs from the last amendment only if a dated amendment precedes the measurement
   (N40-03). A kill gate that fires is not a failure of the program: the fallback is the plan.
3. *Exactly one of the seven claims.* `claim` is one value of the closed set. A chapter row reading "method" or
   "Performance of the method" is `design-comparison`. A row that named two claims takes the claim of its governing
   part (the list is N40-02's).
4. *Where a chapter and the register differ, the register governs*: on a gate's identity, its claim, its earliest
   milestone, a kill gate's trigger, fallback and decision point, and every number the register states. `threshold`
   is a brief: the full criterion with fixtures and controls is the defining subsection's, and a clause the brief
   leaves out is not waived.
5. *Every convergence gate has a registered negative control that it catches.* `pass` is refused when `controls` is
   empty or any control was not caught in the same run (INV-GAUNT-02).
6. *Earliest milestone.* `milestone` is the first exit at which the gate must have a record; a part is due at each
   milestone of `[[gate.part]]`. A milestone exits when every part due there is `pass` or `killed` with its
   fallback adopted. A `fail` on a convergence gate with no kill gate blocks the exit.
7. *Admission is never inherited.* A foundation first used at a later milestone is admitted then, by its own
   record, at the pin of that day (N40-07 checks it).
8. *Recurring gates.* GATE-GROUND-01, GATE-SAFE-01, GATE-GAUNT-01 and GATE-TENFOLD-09 are re-run at every exit
   after their first: `recurring = true` makes the exit query (N40-04) demand a part per later exit.
9. *Owner.* The chapter of the defining subsection owns the gate and its fixtures. Six kill gates are stated in two
   chapters; each is listed once under its owner, with the other chapter in `consumers`.

**4. Write-time refusals (DESIGN reason strings of the validator; not agent-facing refusal codes).**

| Reason | Condition | Repair |
|---|---|---|
| `pass-without-control` | `pass` with `controls` empty | Register the control first (ADR-GAUNT-03) |
| `control-not-caught` | a listed control has `last_seen.caught = false` for this run | Fix the gate's test or the plant |
| `self-certified` | `recorded.session == recorded.implemented_by` (INV-GAUNT-05) | Record from a fresh-context session |
| `evidence-unresolved` | an evidence item or `claim_id` dangles or is tombstoned | Re-run; cite a live receipt |
| `target-as-measurement` | `measured` empty or byte-equal to `threshold` | Record the measured value |
| `claim-not-one-of-seven` | `claim` outside the set, or two values | Apply rule 3 |
| `no-claim-on-non-reality` | `no-claim` on a gate whose claim is not `reality` | Use `not-run` or `fail` |
| `blocked-without-question` | `blocked` with no `OPEN-…` in `detail` | Name the question |
| `killed-without-decision` | `killed` with no kill gate, fallback and ADR in `detail` | Record the decision (N40-03) |
| `duplicate-id` / `reused-id` | an identifier appears twice, or a retired one returns | Identifiers are append-only |

**5. Code (DESIGN).** `crates/frob-conformance/src/register/{mod,row,validate,write}.rs`: `GateRow`, `Part`,
`Status`, `Kind`, `Claim`; `load(path) -> Result<Register, Vec<Violation>>`; `record(part, receipt, session)` which
runs every refusal before writing. Parsing uses the registry loader of `frob-core` (seed BD-005). The row types and
the table printer have no dependency outside `frob-core`, so that `xtask check-generated` can regenerate tables
without depending on `frob-conformance`. Determinism: loading and printing are pure functions of the file bytes;
rows are printed in file order, which is identifier order within kind.

## Acceptance criteria

- [ ] `registries/gates.toml` loads under schema `frob.gates/1`; an unknown field, an unknown status and an unknown
      claim each fail the load with the row identifier.
- [ ] Each of the ten write-time refusals fires on its planted row and names its reason.
- [ ] A row with no recorded part prints "not run" in every generated view, never "pass" (the done-condition of
      seed BD-002 holds through this loader).
- [ ] The four recurring gates are flagged and no other gate is.
- [ ] `pass` cannot be written by a session whose identity equals `implemented_by` (GATE-GAUNT-10's planted
      self-certification is refused).
- [ ] A `pass` whose control was not caught in the same run is refused (GATE-GAUNT-10's second plant; GATE-GAUNT-01).
- [ ] `crates/frob-conformance/CONTRACT.md` lists the register module's inputs, outputs, invariants and refusals.
- [ ] The reconciliation of the two status lists is recorded as an ADR and cited in the schema file.

## Test plan

### Unit tests

`cargo test -p frob-conformance register::` (no mocks; fixtures under `crates/frob-conformance/tests/register/`,
each labelled `synthetic`).

- `status_default_is_not_run`: a row with zero parts recorded → `Status::NotRun`, printed "not run".
- `pass_requires_all_fields`: remove in turn `measured`, `commit`, `command`, `receipt`, `fingerprint`, `seed` from a
  valid pass part → six refusals, each naming the field.
- `pass_refused_without_control`: `controls = []` → `pass-without-control`.
- `pass_refused_when_control_missed`: control `NC-0001` with `caught = false` → `control-not-caught`.
- `pass_refused_self_certified`: `session = "s1"`, `implemented_by = "s1"` → `self-certified`; `"s2"` accepted.
- `claim_closed_set`: each of the seven values loads; `"method"`, `"performance of the method"` and
  `["parity","performance"]` are rejected.
- `no_claim_only_for_reality`: `no-claim` on GATE-GROUND-10 (reality) accepted; on GATE-KIN-01 refused.
- `blocked_needs_open_id`: `detail = "OPEN-SPARK-1"` accepted; empty refused.
- `recurring_set_is_four`: the set of `recurring = true` rows in the seeded file equals {GATE-GROUND-01,
  GATE-SAFE-01, GATE-GAUNT-01, GATE-TENFOLD-09}.
- `ids_append_only` (property test, INV-GAUNT-07 applied to gates): over 10³ random edit scripts, any script that
  renumbers or reuses an identifier is rejected and any pure append is accepted.
- `print_is_pure`: printing the same bytes twice, in debug and release, gives identical output.

### End-to-end script and logging

`scripts/e2e/gate_register_semantics.sh` (sources the shared helper of STD-E2E): copies the tree to a scratch
directory; runs `cargo test -p frob-conformance --test register`; then for each of the ten planted rows applies the
plant, runs the validator through `cargo xtask check-generated`, and asserts a non-zero exit and the reason string;
then asserts on the clean tree that `frob capabilities --json` reports no capability as implemented whose gate is
`not-run`. Each step logs `ts`, `script`, `bead`, `step`, `event`, the command line, exit code, wall time, the reason
string, and on failure the first differing value and the path of the planted file; the final `summary` line counts
assertions and names GATE-GAUNT-10 and GATE-GAUNT-01.

### Known answers and negative controls

Known answers: seven statuses; seven claims; four recurring gates; ten refusals (N40-KA rows R-01 to R-04).
Negative controls (N40-CX rows RC-01 to RC-06): a PASS with no control; a PASS with an uncaught control; a
self-certification; a dangling evidence item; a target copied into `measured`; a status table edited by hand
(caught by `check-generated`). Determinism lanes: twice on one machine and debug against release, bit-equal output.

## Considerations

- The parts model changes the Gauntlet chapter's single-status record; the two beads must agree before either is
  implemented. Fail-closed default until they do: a gate with any part not recorded prints "not run".
- 35 convergence gates and 3 admission gates have parts at more than one exit (FACT, counted from the register);
  a single status per gate would force either a premature pass or a late one.
- The file is read by the README table, the exit query, the release rubric, the dashboard and `check-contracts`
  (every release path has a demo whose claims exist in the file). A registry that nothing reads is deleted: each
  added field above names its reader.
- Risk: a recording session that copies the threshold into `measured`. The `target-as-measurement` refusal catches
  byte equality only; the exit review (N40-05) reads receipts.
- Size: the validator and printer stay under 800 lines; `frob-conformance` has a cap of 24 thousand.
