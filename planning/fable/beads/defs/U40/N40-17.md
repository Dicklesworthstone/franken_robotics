## Background

A published ratio that nobody else can recompute is an assertion. The **replication kit** is everything needed to
recompute the tournament's result and to re-run it: a gate's result is published with its kit. GATE-TENFOLD-08 is
the program gate that tests the kit. If it is not met, **the result is labelled `unreplicated` and the word
"ten-fold" is not used**, whatever the tournament measured. Claim kind: Known answer (the recomputation is exact).

Two levels, for two different doubts. *Level 1, recompute*, answers "is the arithmetic right": from ledgers and
receipts alone, a scorer with no dependency outside the standard library reproduces every published ratio,
interval, count and verdict, bit for bit, on a clean machine. *Level 2, re-run*, answers "does it happen again":
from the frozen manifests, on hardware with a comparable fingerprint, one sampled pair per stratum is run again for
every arm. DESIGN decision: the scorer is dependency-free, like the offline certificate auditor, so that a third
party can audit it by reading it. Rejected: scoring inside the main binary, which would make replication depend on
building the system being judged.

## Scope

In: the two levels as checks; the refusal of a kit with a private input; the labelling consequence; the record.
Out: building the kit and the scorer (the ten-fold chapter's beads, seed BD-433); the tournament itself (N40-16).

## Technical approach

**1. Kit contents (the check verifies presence and hashes).** The pre-registration and the pre-analysis. The
mission cards, the world generators and the revealed keys. The referee protocol and the adjudicator's acceptance
code. Every freeze manifest, with the scripts, wrappers, tag maps and agent guides it names. Every ledger, receipt
and agent transcript. The scorer. Hardware fingerprints and disclosure blocks. A manifest of hashes over all of it.

**2. Limits.** Incumbent code is not redistributed: the kit pins revisions and gives fetch instructions. A private
scene or dataset cannot enter a kit, and a kit built from one is refused. Every exported artifact carries the
no-authorization flags, all false.

**3. Level 1.** On a clean machine (an empty environment with a stock compiler), build the scorer from the kit and
run it over the kit's ledgers and receipts. Every published ratio, interval, count and verdict is reproduced bit
for bit. Any difference fails the level and names the first differing value.

**4. Level 2.** From the frozen manifests, on hardware whose fingerprint is comparable (same device family and
count; discrete fields equal; rates within the fingerprint's own repeatability band), one pair per stratum is
sampled by a seed recorded before the tournament closes, and run again for every arm. TARGET: the acceptance
outcome is the same and the time is within a factor of 1.5 in at least 90% of the sampled pairs.

**5. The check** `tenfold08(kit) -> Verdict` in `crates/frob-conformance/src/tenfold/replicate.rs`: manifest hashes
verify; no file's provenance closure contains a private mark; level 1 exact; level 2 at or above 90%. The register
row has two recorded sub-results (`level1`, `level2`) and passes only with both.

**6. Consequence.** While the row is not `pass`, the report generator stamps `unreplicated` on every figure of the
tournament report and the README, and the lint that guards wording refuses the word "ten-fold". With the default
answer to the adjudication question (self-adjudicated), the word additionally waits for an external party's re-run
of the kit.

## Acceptance criteria

- [ ] The kit's manifest verifies and lists every item of step 1.
- [ ] Level 1 reproduces every published number bit for bit on a clean machine with the dependency-free scorer.
- [ ] Level 2 re-runs one sampled pair per stratum for every arm, with the same acceptance outcome and a time
      within a factor of 1.5 in at least 90% of pairs (TARGET).
- [ ] A kit with a private input is refused; no incumbent code is in the kit.
- [ ] Every artifact in the kit carries the no-authorization flags, all false.
- [ ] While the gate is not passed, every figure is printed `unreplicated` and the word "ten-fold" appears nowhere.

## Test plan

### Unit tests

`cargo test -p frob-conformance tenfold::replicate::`.

- `level1_bit_exact`: a kit whose ledgers reproduce the published table → pass; one receipt with one time changed
  by 1 ms → fail naming the cell.
- `level2_threshold`: 10 sampled pairs, 9 within a factor of 1.5 with equal outcomes → pass (90%); 8 → fail.
- `outcome_must_match`: a pair within the time factor whose acceptance outcome flipped counts as a miss.
- `private_input_refused`: a kit whose closure contains a private scene mark → refused.
- `scorer_has_no_dependencies`: the scorer's manifest has an empty dependency table.
- `sample_seed_precommitted`: a level-2 sample whose seed was recorded after the close → refused.
- `unreplicated_stamp`: with the row `not-run`, the generated report contains `unreplicated` beside every ratio.

### End-to-end script and logging

`scripts/e2e/tenfold_08.sh`: builds a kit from the synthetic tournament of `tenfold_07.sh`; copies it to an empty
directory with an emptied environment; builds the scorer there; runs level 1 and compares bit for bit; runs level
2 on one sampled pair per synthetic stratum; then plants a private mark and asserts the refusal. Logs: command,
exit code, wall time, each recomputed value beside the published one, the level-2 time ratios beside 1.5 and the
share beside 90%, manifest and kit hashes, and on failure the first differing value with paths.

### Known answers and negative controls

Known answers: the published table itself (level 1 is equality). Negative controls: a kit with a private input
(refused); a scorer that links the main crates (refused by the dependency check); a published number edited by
hand after scoring (level 1 fails); a level-2 pair chosen after seeing which pairs replicate (refused by the
precommitted seed).

## Considerations

- "Comparable hardware" is judged by fingerprint, not by model name; a third party without two RTX 4090 cards can
  run level 1 and report level 2 as `unavailable`.
- Level 2's 90% is a TARGET on a small sample; its count is reported, not just pass or fail.
- Repository visibility is an owner question; default private, with the kit and the certificate auditor as the
  artifacts prepared for a third party.
