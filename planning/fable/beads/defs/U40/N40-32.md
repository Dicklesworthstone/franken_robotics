## Background

DESIGN: **for every bet that a milestone tests, the milestone has an exit that does not need the bet to hold.** The
fallback ships under its own name, and the lost capability is recorded. This is the structural property that lets
the program make 37 bets without any one of them being able to stall it: a failed bet costs a capability, never a
milestone.

A property like this is easy to state and easy to lose. A gate added later may quietly require the mechanism of a
bet (a gate that can only pass on a GPU; a demonstration that only a family policy can perform), and from then on
the fallback exit no longer exists, although the table still says it does. This bead therefore does two things: it
records the twenty fallback exits as data, and it **rehearses** each one: on a synthetic register in which that
bet has failed and its kill decision is recorded, the exit query for that milestone must still return
`exit-ready`. If a later change makes a rehearsal fail, the change has made a milestone hostage to a bet, and the
test says which.

A related, weaker guarantee is recorded with it: if every open question stayed at its fail-closed default, the
program would still exit M0 to M5 and M7. The resulting product would be a CPU-first studio with exploratory GPU
results, no family policy, cheap rungs that only discard, generic cards and assumed norms, no Reality claim, a
ten-fold ratio labelled `self-adjudicated`, and a private repository, every one of those limits printed on the
results it touches.

## Scope

In: the twenty rows; the rehearsal of each; the all-defaults rehearsal; the lost-capability record. Out: the kill
ledgers (N40-23 to N40-28); the two variants' definitions (N40-33, N40-34); the bets (their beads).

The first three columns are the design's own table; the last two are added here from the kill ledgers so that each
row names its record and what is lost.

**2. The rehearsal** (`crates/frob-conformance/tests/fallback_exits.rs`). For each row r:

1. Build a synthetic register for milestone r.milestone in which every part due is `pass` with caught controls.
2. Apply the failure of r: set every gate read by r.kill_gates to `fail`; record the kill decisions as `fired` with
   their ADRs; or, for an admission or owner-question row, set the admission to `fail` or the question to its
   default with its ADR and attach the variant record where the row names one.
3. Propagate (N40-03): failed gates read by a fired kill gate become `killed`; variant-listed gates become
   `not run (variant)`.
4. Run the exit query (N40-04). Expected: `exit-ready`, with the fallback's name printed and r.lost listed in the
   exit record's "capabilities removed" section.
5. Control: repeat step 2 *without* recording the decision or the variant. Expected: `not-ready`. (The fallback
   exit exists because the decision is recorded, not because failures are ignored.)

A rehearsal that returns `not-ready` at step 4 names the blocking part: that part depends on the failed bet's
mechanism with no route through the fallback, and is either a defect of the gate's definition or a missing row
here.

**3. The all-defaults rehearsal.** A synthetic register in which every owner question is at its default (GPU
results exploratory; default compute envelope; no rank-agreement experiment above it; no pretraining; pinned
incumbent CPU engine as adjudicator; the adapter for the test only; comparator-only SMT; `reality: no-claim`;
generic cards and assumed norms; private repository) and each gate takes the status its default implies. Expected:
M0 to M5 and M7 are `exit-ready`; each exit record lists the limits printed on results.

**4. Coverage check against the bets.** For every bet whose row in the bets registry (N40-31) names a milestone,
either a fallback-exit row here covers it at that milestone or its kill gate's fallback is in a ledger and the
rehearsal of a synthetic row generated from the ledger passes. Bets with no kill gate (BET-08, BET-10, BET-12,
BET-21) must have their written consequence represented: BET-21 is a row; BET-12's is the re-plan pause, which is
the one case that deliberately stops the program and is excluded from the rehearsal.

## Acceptance criteria

- [ ] Twenty fallback-exit rows load and equal the first three columns of the table.
- [ ] Each of the twenty rehearsals returns `exit-ready` with the decision recorded and `not-ready` without it.
- [ ] The all-defaults rehearsal returns `exit-ready` for M0, M1, M2, M3, M4, M5 and M7.
- [ ] Every exit record produced by a rehearsal names the fallback and lists the lost capability.
- [ ] The coverage check finds no bet tested at a milestone without a route to exit.
- [ ] The rehearsals run in CI on every change to `registries/gates.toml`; a change that breaks one names the
      blocking gate.

## Test plan

### Unit tests

`cargo test -p frob-conformance --test fallback_exits`: one test per row, named `m0_bet04_worker`,
`m0_mcp_socket_then_cli`, `m1_foundation_fails`, `m1_bet19_conventional_program`, `m2_no_gpu`,
`m2_bet18_templates`, `m2_bet09_metal`, `m2_bet34_strict_adjudicator`, `m3_bet06_baselines`, `m3_bet21_fixed_n`,
`m3_bet22_23_search_attribution`, `m3_no_neutral_party`, `m4_no_family_policy`, `m4_bet17_low_rank`,
`m4_bet20_regions`, `m5_bet11_certificates`, `m5_bet28_no_data`, `m5_bet29_structure`, `m7_bet13_under_ten`,
`m7_bet14_tie`, each asserting step 4 and step 5; plus `all_defaults_exit` and `every_bet_has_a_route`.
`m1_schedule_gate_is_the_exception` asserts that a `not met` schedule gate is the one planted failure that makes
M1 `not-ready` by design.

### End-to-end script and logging

`scripts/e2e/fallback_exits.sh`: runs the twenty rehearsals and the all-defaults rehearsal through the conformance
test target, writing each synthetic exit report to a scratch directory; asserts verdicts; then adds a synthetic
gate that can pass only on a device to the M2 due set and asserts that `m2_no_gpu` now fails and names it. Logs
per rehearsal: command, exit code, wall time, the row, the gates set to fail, the decisions recorded, the verdict
with and without the decision, the lost capability printed, and on failure the blocking part with the report path.

### Known answers and negative controls

Known answers: 20 rows; 21 rehearsals; the exits reachable under all defaults are M0 to M5 and M7 (N40-KA R-28).
Negative controls: N40-CX RC-49 (a device-only gate added to M2 with no CPU part and no variant listing), RC-50 (a
fallback exit taken with no kill decision recorded), RC-13 (a decision with no cited receipt).

## Considerations

- The rehearsal tests the *gate graph*, not the engineering: it shows that no recorded gate forbids the fallback
  exit. Whether the fallback itself works is the business of the kill gate's own bead.
- M6 and M8 have no rows: every epic there is optional and exits by its own decision.
- A fallback taken at one milestone changes later rows (after the no-GPU variant, the partial gate at M3 charges
  the CPU engine's measured rate in full and runs first the strata that need no device); the rehearsals are run
  per milestone and also as two chains (all M2 fallbacks then M3; all M4 fallbacks then M7).
