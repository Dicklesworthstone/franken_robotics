## Background

The program promises that a failed bet costs a capability and never a milestone, and that a capability which fell
back is described by the fallback's name from then on. Those promises pass through many small mechanisms: the kill
row with its trigger and fallback fixed in advance, the dated amendment, the measurement, the decision recorded as
an ADR by a session that did not build the mechanism, the propagation to the gate's status, the generated tables,
the capability list, the tracker's close reasons, and the exit query that then lets the milestone exit. Each is
unit-tested in its own bead. This bead is the **end-to-end test of the whole kill-decision path**, driven from the
user's side on a real, cheap kill gate, with every way of softening the decision refused.

It is one end-to-end bead for one user-visible capability: *an honest fallback*. It is placed at M1, where the
first ordinary kill decisions are due (KILL-SKEL-SEXPR and KILL-SKEL-SUBST) and where a real mechanism with a real
fallback exists to exercise.

## Scope

In: the script, its fixture kill gate, its assertions and its logging. Out: the mechanisms under test (N40-03,
N40-04, N40-30, N40-32); the measurement path of an ordinary gate (N40-36).

## Technical approach

**1. The fixture.** KILL-SKEL-SEXPR: trigger, the round-trip invariant of the S-expression view of a design
cannot be held after one repair cycle; fallback, the S-expression view is removed and JSON is the only syntax;
decided at M1. It is chosen because it can be made to fire deliberately and cheaply (a test build with a planted
defect in the S-expression printer, which is the gate's own negative control) and because its fallback is
observable from the command line (the view verb refuses with its typed refusal, and `frob capabilities` no longer
lists the S-expression view). The script takes the kill gate as a parameter; any kill gate whose trigger can be
planted and whose fallback is observable can stand in. All work happens in a scratch copy with a synthetic
tracker export; the real register and tracker are never written. The mechanism the fixture exercises, the
S-expression view with the verb `design.view`, the round-trip property test of GATE-SKEL-05 and its planted printer
defect, is BD-057's (a dependency); the real decision of KILL-SKEL-SEXPR is N14a-20's and is not touched.

**2. The script** `scripts/e2e/kill_decision_path.sh` (plain shell; idempotent; seed-explicit; sources the shared
helper of STD-E2E):

1. `start`: scratch clone at HEAD; record the commit, the register digest and the ledger row's seeded hash for the
   fixture (trigger, fallback, decision point M1).
2. Not fired: run the gate that the trigger reads (the round-trip property test on 10⁴ random designs, through
   `FROB_TEST_SEED=<seed> cargo test -p frob-conformance --test g1_known_answers -- GATE-SKEL-05`, the tier
   target named by the gate record's `tier` field under its long name) on the unmodified build; record the pass and a
   decision `not-fired` with an ADR citing the receipt, as a fresh session. Assert: the M1 exit report lists the
   kill gate as decided; `frob capabilities --json` lists the S-expression view; the cross-check (N40-30) passes.
3. Fire it: rebuild with the planted printer defect (the gate's registered control, built with `--features
   gauntlet-mutations` and that control's own mutation feature); run the gate (it fails); log one repair cycle (open, a
   re-measurement that still fails, close); record the decision `fired` with an ADR that cites both failing
   receipts, names the fallback and the renamed capability, and lists the dependents re-read.
4. Propagation: assert the read gate's part is `killed` with `detail` naming KILL-SKEL-SEXPR and the fallback; the
   README table and the register printout show the row under the fallback's name ("JSON is the only syntax");
   `frob capabilities --json` no longer lists the S-expression view and lists the fallback; the view verb called
   with the S-expression format exits with its typed refusal and a repair that names the JSON view.
5. Tracker: in the synthetic export, the bead that carried the view is closed with reason `fallback` and the
   fallback's name; one dependent is closed `superseded` with the ADR identifier; one dependent stands on the
   fallback and stays open; assert the cross-check accepts this and rejects a third dependent left open on the
   killed capability.
6. Exit: regenerate the M1 exit report on a register where every other part passes; assert `exit-ready`, the
   "capabilities removed" section naming the S-expression view, and the fallback exit of the corresponding kind
   rehearsed by N40-32 still passing.
7. Refusals, each in a fresh scratch copy, each asserting a non-zero exit and the reason:
   (a) lower the trigger after the failing receipt exists → `amended-after-measurement`;
   (b) rewrite the fallback with no amendment → `changed-without-amendment`;
   (c) record `not-fired` while the measured values meet the trigger → `outcome-contradicts-measurement`;
   (d) record the decision as the session that implemented the view → refused as self-certified;
   (e) record `fired` with no receipt cited → refused, no evidence;
   (f) leave `frob capabilities` listing the killed capability (a stale generated file) → `check-generated` fails;
   (g) a second repair cycle with no `deferred` ADR → refused;
   (h) skip the decision altogether and regenerate the exit report → `not-ready`, naming the kill gate.
8. A valid amendment, for contrast: before any measurement, amend the decision point with a reason and a date;
   assert it is accepted and replays to the row's text.
9. `end`: print the summary.

**2a. Where it runs.** This bead attaches the record `kill-decision-path` to `scripts/exit/checks.toml` (N40-05,
reached through N41-16, section 5a): step 6, since M1, `after = "kill-ledger"` (N40-30's check), command
`scripts/exit/kill-decision-path.sh`, which runs this script at the candidate commit and prints the check's JSON
object, a failed assertion being a block naming the step and the first differing value; so every exit review from
M1 runs it.

**3. Logging (structured newline-delimited JSON to `target/e2e-logs/kill_decision_path/<utc>.ndjson`, with a
human-readable transcript beside it).** Every line: `ts`, `script`, `bead` (`N40-37`), `step`, `event` (`start`,
`cmd`, `assert`, `metric`, `refusal`, `end`), the exact command line, exit code, wall time, the envelope's
`evidence` block where a verb returned one (claim, class, tier, determinism, identities, seed), measured values
with units and thresholds (round-trip failures out of 10⁴ against 0), digests where state is compared (the ledger
row before and after, the register, the README table, the capability list), the refusal code and repair where a
verb refused, and on failure the first differing value and the artifact paths needed to reproduce. A final
`summary` line gives assertions passed and failed and the gates touched (GATE-GAUNT-10, the fixture kill gate and
the gate it reads).

## Acceptance criteria

- [ ] The script exits 0 on a clean tree and non-zero if any assertion fails; it is idempotent.
- [ ] After the fired decision the capability is described by the fallback's name in the README table, the
      register printout and `frob capabilities --json`, and by the killed capability's name in none of them.
- [ ] Each of the eight refusals of step 7 fires with its reason; the valid amendment of step 8 is accepted.
- [ ] The M1 exit report is `exit-ready` with the fired decision recorded and `not-ready` without it.
- [ ] A dependent left open on the killed capability is reported.
- [ ] The log has one line per command, assertion and refusal, and a summary; it contains no private-scene data.
- [ ] The script runs in under 5 minutes on the CPU tier (TARGET) and is attached as the record
      `kill-decision-path` of `scripts/exit/checks.toml` from M1 on.

## Test plan

### Unit tests

None of its own: this bead is a test. `scripts/e2e/kill_decision_path.sh --selftest` plants a wrong expected
capability name and asserts that the script fails and logs the first differing value.

### End-to-end script and logging

As specified in the technical approach: `scripts/e2e/kill_decision_path.sh [--kill <identifier>] [--seed N]`.

### Known answers and negative controls

Known answers: the ledger row's seeded text for the fixture (trigger, fallback, M1); zero round-trip failures on
the unmodified build; at least one on the planted build. Negative controls: the eight refusals (N40-CX RC-10 to
RC-13, RC-44, RC-45, RC-50, RC-56: a second repair cycle taken silently). Determinism lanes: twice on one machine,
debug and release, macOS and Linux, comparing the register, report and capability-list digests; equal in each
lane.

## Considerations

- The planted defect is the fixture gate's registered negative control, built only in the test profile and never
  compiled into a release binary.
- If KILL-SKEL-SEXPR really fires at M1, the S-expression view is gone and this script's default fixture with it;
  the script then defaults to the next kill gate whose trigger can be planted (KILL-SKEL-SUBST: a reused product
  differing from its recompiled value), and the bead records the change.
- The script exercises the tracker rules on a synthetic export because test agents do not run the
  tracker; the lead's tooling applies the same check to the real export.
