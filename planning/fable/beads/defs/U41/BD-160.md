## Background

`batch-cpu` is the permanent reference for the batched algorithm: it runs the same derived kernels in the same
stage order as the GPU tiers, in `f64` or `f32`, anywhere, including where there is no GPU; it is the debugging
target for a world teleported from a device and the CPU reference path that every capability must have. The
batched step of the preceding bead runs its ten stages over all worlds on one thread. This bead makes it parallel
on the host without changing one bit of any result: the **tile program**, in which each stage is cut into tiles of
worlds and executed on FrankenSim's executor `fs-exec`.

FACT (`frankensim/crates/fs-exec/src/lib.rs`, read 2026-11-22; to be re-read at the pinned commit): `fs-exec` is a
two-lane executor. Its throughput lane, `TilePool`, is a work-stealing fork-join pool whose units of work are
tiles; per-worker deques are seeded with contiguous tile runs; reductions are **fixed-slot**, folded in tile order,
so results are bit-identical across worker counts and steal schedules by construction. The contract a kernel
programs against is `TileKernel` (`tiles() -> TilePlan`, `run(tile, &Cx) -> ControlFlow<Cancelled, Out>` with
`Out: Reduce`) and `Cx`: the cancellation gate polled at tile boundaries, a tile-scoped arena, a random-stream
identity keyed by (seed, kernel, tile, iteration) and never by worker, a budget slice and an execution mode. A
panicking tile is caught, its siblings drain through the gate, and the run returns a structured error with tile
provenance.

Why this needs its own bead (the hazards, each a rule of the determinism chapter): thread completion order varies,
so results must be placed by index and never by arrival (INV-NUM-01); a reduction tree shaped by tile boundaries
changes with the worker count or the tile size, so tree shape must be a function of logical index only; floating
atomics are the main source of parallel nondeterminism and are banned; and a random stream keyed by tile would make
a world's draws depend on how the batch was cut. Rejected alternatives: a general data-parallel library with
arrival-ordered folds (sums change with scheduling); one OS thread per device-style shard with a mean of shard
means (weights samples by shard size); per-worker accumulators merged at the end (grouping depends on stealing).

## Scope

In: wrapping every stage kernel of the `batch-cpu` step plan as a `TileKernel`; the tile plan; index-placed
outputs; fixed-slot reductions with an index-defined tree; cancellation at tile boundaries with whole-state
restore; scratch from the tile arena; receipts; the worker-count, tile-size and steal-schedule determinism tests.
Out: the stages themselves (BD-159 and the kernel beads); batch-composition invariance across co-tenancy, slots,

## Technical approach

Module (DESIGN): `crates/frob-kernels/src/cpu/{tile_plan.rs, tile_kernel.rs, reduce.rs, commit.rs}`.

**Tile plan.** A tile is a contiguous range of world indices of length T_w, a power of two (default 32, DESIGN;
recorded in the receipt), aligned at multiples of T_w; the last tile may be short. The plan is a function of the
world count and T_w only: not of the worker count, not of load. Worker count comes from the pool configuration and
defaults to the machine envelope (8 cores); neither T_w nor the worker count enters `StepPlanId` or any state
digest.

**Stage kernels as tile kernels.** For each stage, `run(tile, cx)` calls the stage's CPU kernel over the tile's
world range, reading and writing only the lanes of those worlds (the kernel manifest's footprints, checked at plan
build: two tiles of one stage never write the same lane). Stages run in the fixed order of the step; a stage
starts when the previous stage's last tile has returned. The lockstep Newton solve is the same sequence of tile
kernels repeated for the fixed iteration count, under the per-world `done` mask.

**Reductions (fixed slots, index-defined tree).** Any quantity folded over worlds (counts of `Degraded` worlds,
telemetry sums, the fixed-order sums a learner reads) is computed as follows.

1. Each tile computes the pairwise tree over its own worlds, anchored at the tile's first index, and writes the
   partial into `slots[tile_index]`. Integer counts are exact; floating sums use the tree, never an accumulator.
2. After the stage, the slots are folded by the same pairwise tree over tile indices, anchored at index 0.
3. Missing entries (a short last tile, padded worlds) hold the neutral element of the operation, trailing the real
   entries: −0.0 for sums (since (−0.0) + (+0.0) = +0.0 would change the bits of a sum that is −0.0), +∞ for
   minima, −∞ for maxima.
Because T_w is a power of two and tiles are aligned, the composed tree equals the pairwise tree over world indices
aligned to powers of two, whatever T_w is: the result is independent of worker count, steal schedule and tile
size. No reduction over worlds ever feeds a world's state (a batch-wide reduction that feeds state makes a world
depend on its neighbours).

**Randomness.** No stage draws from the executor's tile-keyed stream. Every draw is a function of
(world address, step, stream) alone; a plan-build check rejects a tile kernel that reads `Cx`'s stream.

**Memory.** All state buffers are allocated at environment creation. Scratch comes from the tile-scoped arena and
is released at the tile boundary; allocated bytes are flat over a run.

**Cancellation and faults.** The cancel gate is polled at tile boundaries: request, drain (running tiles finish,
queued tiles are skipped), finalize. A step is committed at the fence only after every tile of every stage has
returned; a cancelled or faulted step restores the whole committed state from the previous fence (a retried step
that keeps part of its state diverges), and the drain report names the tiles that ran. A panicking tile yields a
structured error with its world range; the step is not committed and the job reports the fault with the tile's
provenance, never a partial state.

**Receipt.** The `batch-cpu` receipt records T_w, worker count, tiles per stage, steals observed and the peak arena
bytes as execution facts, outside every identity.

Determinism class: D2 on the host (bit-identical run to run and across worker counts, and, by the tree rule,
across tile sizes). Evidence class is unchanged by parallel execution: results are what the step would produce on
one thread, bit for bit.

## Acceptance criteria

- [ ] Seed condition: for the reference quadruped and humanoid workloads, 4,096 worlds and 10⁴ steps in `f32` and
      10³ steps in `f64`, the per-world state digests and every reduced quantity are bit-identical for worker
      counts 1, 2, 3, 4 and 8.
- [ ] The same holds for tile sizes 16, 32 and 64, and under an adversarial steal schedule (the pool's test hook
      that forces steals at every tile boundary).
- [ ] The digests equal those of the single-threaded step of the preceding bead.
- [ ] KA-786 holds through the tile reduction: the sum of one active element −0.0 is −0.0 at two capacities.
- [ ] The three planted mutants are caught (controls below).
- [ ] Cancellation at a random tile boundary in 10³ trials leaves the committed state equal to the previous fence
      (digest), leaks no arena bytes, and a resumed run reproduces the uncancelled digests.
- [ ] A planted panic in one tile returns a structured error naming the tile's world range; no state is committed.
- [ ] Allocated bytes are flat over 10⁵ steps; a tile kernel that reads the executor's random stream is rejected
      at plan build.
- [ ] The build graph still contains exactly one asupersync package.
- [ ] Open clauses of the definition of implemented: the gate record for determinism across worker counts is
      taken by the determinism tier of the Gauntlet (GATE-GAUNT-07) and by GATE-KIN-05 with the composition test.

## Test plan

### Unit tests
`crates/frob-kernels/tests/tile_program.rs`; the real pool, no mocks.
- `tree_is_index_defined`: the `f32` values a = 10⁸, b = −10⁸, c = 1 at indices 0, 1, 2 sum to 1 (the tree computes
  (a + b) + (c + neutral)) for every tile size and worker count; a sum grouped as a + (b + c) would give 0.
- `tile_sizes_compose_to_one_tree`: 1,000 random `f32` vectors of length 4,096: sums at T_w ∈ {16, 32, 64} are
  bit-equal to the single pairwise tree.
- `negative_zero_neutral` (KA-786); `short_last_tile_padded_with_neutral`.
- `outputs_placed_by_index`: with a pool hook that completes tiles in reverse order, every lane equals the
  single-threaded lane.
- `worker_counts_bitwise_{quadruped, humanoid}_{f32, f64}`; `adversarial_steals_bitwise`.
- `cancel_restores_fence_state`; `panic_in_tile_is_structured_error`; `arena_bytes_flat`.
- `tile_stream_use_rejected_at_plan_build`; `overlapping_write_footprints_rejected`.
- Mutants (`tests/support/tile_mutants.rs`): `fold_by_arrival` (an accumulator updated as tiles complete: differs
  between 1 and 8 workers on the a, b, c fixture); `tree_by_tile_boundary` with T_w = 24 (differs from T_w = 32);
  `positive_zero_padding` (fails KA-786).

### End-to-end script and logging
`scripts/e2e/batch_cpu_tiles.sh`: `frob sim run --tier batch-cpu --profile lockstep --task fixtures/quad-flat.ftask
--worlds 4096 --steps 10000 --seed 11 --json` with `--workers` 1, 2, 3, 4, 8 and `--tile-worlds` 16, 32, 64 (DESIGN
flag spellings, operator-only); asserts equal `state_digest` and equal reduced telemetry across all runs; one run
cancelled by `frob job cancel` mid-step, then resumed, asserting the same final digest. Logs per the standard:
`cmd`, exit code, wall time, evidence block (tier, determinism class D2, identities, seed), digests per run with
the first differing world index on failure, receipts' tile facts as `metric` lines, and a `summary`.

### Known answers and negative controls
- KA-786 (padding with −0.0), the regrouping counterexample in `f32` (1 against 0), INV-NUM-01 (placed by index),
  INV-NUM-02 (padding neutrality).
- Negative controls: the three mutants above; each is registered against the determinism tier.
- Metamorphic: permuting worker identities, pinning or unpinning threads, and changing the pool's seed for steal
  victim selection change no output bit.
- Determinism lanes: twice on one machine; across worker counts; debug and release; Linux and macOS for the same
  precision and compiler (recorded against class D2 per platform, not asserted equal across platforms here).

## Considerations

- Tile size trades scheduling overhead against balance; because results do not depend on it, it may be tuned from
  the profile without touching any identity.
- The machine envelope caps a default run at 8 cores; the all-core rows of the performance gates need the owner's
  approved envelope class and are run by the parity bead.
- `fs-exec` brings asupersync by path; if the single-version admission fails, the fallback is a local fixed-slot
  pool with the same `TileKernel` shape, behind the same tests (the tests are written against behaviour, not
  against the sibling's types).
- What would make us revisit: a stage whose cost per world varies by orders of magnitude (then tiles are weighted,
  still by index and never by measured time).
