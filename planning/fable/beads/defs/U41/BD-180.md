## Background

Every stochastic input of a world (a disturbance push, sensor noise, a reset pose, a randomized friction
coefficient, action sampling, a minibatch permutation) must be reproducible alone: any world must replay from its
address without the batch it ran in, and two designs compared on "the same worlds" must really see the same
disturbances. A generator with state that hands out numbers in call order cannot give either property. The
smallest case: a sequential stream r₀, r₁, r₂. Design A draws a push (r₀) and a friction (r₁). Design B has one
more leg and draws a per-leg value first, so its push is r₁ and its friction r₂. The seeds are equal and the two
designs were pushed differently. One extra element shifts every later draw.

The decision (DESIGN): randomness is **counter-based and keyed by logical identity**. A draw is a pure function of
`(WorldAddr, step, stream_id)` (and, inside a stream, of the physical entity and index it belongs to), where
`WorldAddr = (run_seed, world, episode)` and a fork's child has its own address. The type is
`frob_core::addr::WorldAddr` of N35-22, which carries the three words of that tuple and two more that keep address
spaces disjoint by construction: `namespace` (discovery against confirmation worlds) and `fork` (zero for a recorded
world, non-zero for a fork's child). This bead defines no address type. No device-side generator state
exists. Common random numbers for a comparison are then free. The generator is Philox, because it is 32-bit
integer arithmetic and therefore bit-identical on every backend (determinism class D0), and because the suite
already has it as a tested host implementation.

FACT (`frankensim/crates/fs-rand/src/philox.rs`, read 2026-11-22, to be re-read at the pinned commit): `fs-rand`
implements Philox4x32-10 of the Random123 lineage: a 128-bit counter and a 64-bit key give 128 output bits in ten
rounds; multipliers M0 = 0xD2511F53 and M1 = 0xCD9E8D57; key-schedule increments W0 = 0x9E3779B9 and
W1 = 0xBB67AE85; it carries the three published known-answer vectors of that lineage as tests. FACT (same crate,
`philox_normals.rs`): its normal construction consumes two draws per normal.

This bead puts that generator into the kernel library as `K-x-philox` (the exact family of kernels, crate
`frob-kernels`, tier Solid) and fixes how an address becomes a key and a counter.

## Scope

In: the block function as an exact-integer kernel in the dialect and in Rust; the port of the three-level key

noise addressing (the sensing beads); importance weights of tilted proposals (the adversary work); the
composition-invariance gate itself (BD-181).

This bead is the capstone of randomness by address on the batched tiers. The host parts were written by the
Numerics unit and are dependencies:

- N35-22, addressed random streams on the host: the key layout, the exact uniform conversion and the normal
  construction. They are the CPU reference that the kernels here must equal bit for bit.
- N35-23, `registries/streams.toml`: the one stream registry, with purpose, exposure domain and key schema per

## Technical approach

Module (DESIGN): `crates/frob-kernels/src/exact/philox.rs`, dialect source `kernels/exact/philox.fk`, registry
`registries/streams.toml`.

**Block function** `philox(ctr: [u32; 4], key: [u32; 2]) -> [u32; 4]`, ten rounds; before every round except the
first, key₀ += W0 and key₁ += W1 (wrapping). One round, with mulhilo(a, b) the high and low 32 bits of the 64-bit
product: (hi₀, lo₀) = mulhilo(M0, ctr₀); (hi₁, lo₁) = mulhilo(M1, ctr₂);
ctr ← [hi₁ ⊕ ctr₁ ⊕ key₀, lo₁, hi₀ ⊕ ctr₃ ⊕ key₁, lo₀]. The kernel uses unsigned arithmetic only; the high half
comes from the prelude's exact `mulhi_u32`, with a 16-bit-limb fallback for a backend that lacks it, proved equal
on 10⁹ sampled pairs and on all pairs with one operand in the 2¹⁶ boundary set.

**Key derivation** (three applications of the block function, each keyed by the level above, so that the map from
identity to stream is a tree and levels cannot collide by arithmetic on keys). The layout is the one N35-22
specifies for host and devices and pins with five block vectors; the kernel is a line-by-line port of it, written
with 32-bit operations only. With P(counter[4], key[2]) the block function, the address
`WorldAddr { run_seed: u64, namespace: u32, world: u32, episode: u32, fork: u32 }` and the draw address
`DrawAddr { world, stream: StreamId, entity: u32, tick: u64, component: u32 }`:

1. World key, a function of the address alone: k = P([world, episode, namespace, fork], [run_seed_lo, run_seed_hi]).
   `fork` is zero for a recorded world and the fork mechanism's non-zero word for a fork's child.
2. Stream key, a function of the address, the stream and the entity: s = P([stream, entity, k₂, k₃], [k₀, k₁]).
   `stream` is the registered integer identifier of the stream (the `id` of its row in N35-23's registry); `entity`
   is the 32-bit sub-key of the physical thing perturbed where that thing exists independently of the design (a
   gust by its time index, floor friction by tile index, a sensor's noise by the registry's 32-bit hash of its port
   name), and zero otherwise (which entity keys a stream is N35-24's rule).
3. Draw block: b = P([tick_lo, tick_hi, component, 0], [s₀, s₁]). `tick` is the physics step, the decision index
   or the other counter the stream's row declares; `component` numbers blocks within a tick. The four words of b
   are four draws; a consumer that needs fewer discards the rest.

The world key depends on the address only, so a table of k (four words per live world) may be built at reset as
constant data for the episode, and s may be cached per (world, stream, entity) for the same span; both are pure
functions of the address, nothing derived here is state, and nothing is stored in snapshots.

DESIGN (the conflict settled, stated identically in N35-22). An earlier draft of this bead derived the stream key
first (from the run seed, the stream code, a 64-bit entity and the constant 0x5354524D) and the world key second
(with a 64-bit fork path), and had no namespace word. The plan fixes only that a draw is a function of
`(WorldAddr, step, stream_id)`; it gives no layout. N35-22's layout governs, for three reasons: it lands at M1 and
every host draw of the referee, the sensors, the task language and the studies is made with it before this kernel
exists; its vectors are pinned and enter stored runs through the address scheme version; and this bead's own
contract is bit equality with that host reference. The cost accepted: the precomputable table is per world and
episode instead of per stream and entity for the whole run, and entity and fork identities are 32-bit words (the
registry's collision check at admission covers the entity hash).

**Uniforms.** From a 32-bit draw x: u = (x ≫ 8)·2⁻²⁴, an `f32` in [0, 1), exact because a 24-bit integer and a
power-of-two scale are both exact in `f32` (proof obligation PO-NUM-03, discharged exhaustively over 2²⁴ values).
On the host an `f64` uniform uses 53 bits from two words. An open interval, where a consumer needs one, is
((x ≫ 8) | 1)·2⁻²⁴ and is a different registered conversion, never an ad hoc "+ε"; its host twin is
`uniform_f32_open` in N35-22, and the kernel equals it bit for bit.

**Normals.** The construction is `fs-rand`'s, ported to the dialect with elementary functions from the
deterministic `det_*` set (built-in transcendentals are banned in batched kernels). The integer draws under a
normal are D0; the normal itself is a floating result of class D2 per backend, and D1 only where the probe shows
the `det_*` functions agree. Each normal consumes two draws of one block, as the host twin `normal_f32` of N35-22
does (u = 1 − uniform_f32(b₀) in [2⁻²⁴, 1], v = uniform_f32(b₁), z = det_sqrt(−2·det_ln(u))·det_cos(2π·v); one
block per normal, words b₂ and b₃ discarded); the second output of a pair is never cached across calls (a cached
second output is generator state).

**Stream registry.** There is one registry, `registries/streams.toml` (schema `frob.streams/1`), and it is N35-23's:
its row is `id` (the `u32` identifier that enters the key, never reused or renumbered), `name`, `domain`, `entity`,
`tick`, `component`, `owner`, `since` and `status`, with N35-23's closed vocabularies, loader and lock file. This
bead adds two optional fields to a row and nothing else (an earlier draft of this bead showed a row with a string
`id`, an integer `code` and its own `entity` vocabulary; that form is withdrawn):

```toml
[[stream]]
id        = 4                      # N35-23's row, unchanged
name      = "disturbance-process"
domain    = "process"
# … entity, tick, component, owner, since, status as N35-23 wrote them …
kernel    = "K-x-philox"           # added here: the device kernel that serves the stream
clock     = "physics-step"         # added here: physics-step | decision | reset | minibatch
```

`kernel` is the identity of the device kernel that computes the stream's draw blocks; a row without it is a stream
never drawn on a device. `clock` names the counter of the device control block that supplies the row's `tick` on the
batched tiers (N35-23's `tick` says what the 64-bit tick means; `clock` says which device counter carries it).
Adding the two fields to a row is neither an append nor a retirement: it changes no draw, does not increment the
registry version and does not touch `streams.lock`.

Purposes that must have a device row at M2, by N35-23's names: disturbances (`disturbance-process`,
`disturbance-event`), each sensor's noise (`sensor-noise`), reset pose (`reset-pose`), each randomized parameter
(`task-parameter`, `scene-field`), action sampling (`action-sampling`), minibatch permutation
(`minibatch-permutation`), the telemetry sample (`telemetry-sample`) and the audit assignment
(`promotion-sample`, keyed by the promotion identifier). Adding a stream changes no draw of any other stream, by
construction of step 2 of the layout. A kernel that requests a stream identifier not in the registry is refused at
plan build.

**Kernel manifest.** `K-x-philox`: class exact-integer; determinism D0; inputs: address columns (run seed,
namespace, world, episode, fork), the control block's counters named by `clock`, an optional table of world keys;
outputs: `u32` draws or `f32` uniforms at the caller's lanes; no buffer holds generator state; stage signature with
read-only footprints on every input.

**Rules enforced by tests and by a source lint.** A draw depends on nothing else: not on slot, bucket, variant
index, shard, device, batch size, tile or worker (INV-NUM-04). No kernel or host module in `frob-*` may own a
stateful generator; the lint rejects one (FROB-REF-251 family at build time).

## Acceptance criteria

- [ ] The block function reproduces the three published known-answer vectors on `batch-cpu` (on CUDA and Metal they
      are re-run by the device differential check of the open clause below and by N35-16's battery, both on this
      bead's kernel): counter and key all zero give 6627e8d5 e169c58d bc57ac4c 9b00dbd8; all
      ones give 408f276d 41c83b0e a20bc7c6 6d5451fd; counter 243f6a88 85a308d3 13198a2e 03707344 with key a4093822
      299f31d0 gives d16cfe09 94fdcceb 5001e420 24126ea1 (FACTs from the sibling's test, re-read from the primary
      source before the test cites them); and it equals `fs-rand`'s host function on 10⁷ random inputs.
- [ ] The kernel's draw block equals the host service's `block` (N35-22) for the five pinned vectors of that bead
      (the first: run seed 0, namespace 0, world 0, episode 0, fork 0, stream 1, entity 0, tick 0, component 0 gives
      0x62ee17e7, 0xb09bf32a, 0xe0864da7, 0xe6a584b3) and for 10⁷ random draw addresses: one layout on host and
      device.
- [ ] Seed condition, first half: draw tables for 10⁴ addresses × 100 steps × every registered stream are
      bit-identical across slot permutations, batch sizes 1 to 8,192, two bucket capacities, one and two shards,
      worker counts and tile sizes (KA-795).
- [ ] Seed condition, second half: the sequential-draw mutant is caught by the extra-leg fixture (KA-793): with
      addressed draws designs A and B receive the same push and the same friction; with the mutant they do not.
- [ ] Adding a stream to the registry changes no draw of any existing stream (table comparison before and after).
- [ ] PO-NUM-03: u = (x ≫ 8)·2⁻²⁴ is exact and in [0, 1) for all 2²⁴ values, on each backend (KA-794).
- [ ] A fork's child draws differently from its parent after the fork point and identically before it.
- [ ] A slot-keyed mutant and a tile-keyed mutant are each caught by the table test.
- [ ] The lint rejects a planted stateful generator in a kernel source and in a `frob-*` crate.
- [ ] Manifest validates; the kernel has its CPU reference; the dialect lint passes.
- [ ] Open clauses of the definition of implemented: the device differential check and the gate record
      (GATE-SPARK-15, recorded by the composition-invariance bead).

`crates/frob-kernels/tests/philox.rs`; no mocks.
- `kat_three_vectors`; `equals_fs_rand_host_1e7`; `mulhi_limb_fallback_equal`.
- `key_derivation_levels_are_independent`: changing only `stream`, only `entity`, only `namespace`, only `world`,
  only `episode`, only `fork`, only `tick`, only `component` changes the block; equal identities give equal blocks.
- `block_equals_host_pinned_vectors` (the five rows of N35-22) and `block_equals_host_1e7`.
- `layout_order_mutant` (negative control): a kernel that derives the stream key before the world key (the
  withdrawn order) fails the pinned vectors.
- `uniform_exhaustive_2_24` (KA-794): minimum 0, maximum 1 − 2⁻²⁴, every value exactly representable.
- `extra_leg_fixture` (KA-793, CX-371): push and friction equal for A and B.
- `draw_table_invariance` (KA-795) over slots, batch sizes, capacities, shards, workers, tile sizes.
- `adding_a_stream_changes_nothing_else`; `unregistered_stream_refused_at_plan_build`;
  `device_fields_validate` (a `clock` outside its four values is refused by the loader; a row without `kernel`
  requested by a device plan is refused at plan build). That a retired identifier cannot be reused is a rule of the
  registry and is tested there (N35-23, `retired_identifier_not_reusable`).
- `fork_child_has_fresh_streams`.
- `normal_equals_host_twin`: on `batch-cpu` the kernel's normal equals N35-22's `normal_f32` bit for bit over
  10⁶ draw addresses (the comparison of the host's `f64` normal with `fs-rand`'s Box–Muller is N35-22's test
  `normal_f64_matches_sibling_box_muller` and is not repeated here); `open_uniform_equals_host_twin` (the
  kernel's open conversion against `uniform_f32_open` for all 2²⁴ values); `no_cached_second_output` (two
  interleaved consumers get the values each would get alone).
- Statistical smoke (not a gate): uniform chi-square over 10⁶ draws inside its 99.9% band for three streams.
- Mutants (`tests/support/philox_mutants.rs`): `sequential_per_world_counter`; `keyed_by_slot`; `keyed_by_tile`;
  `nine_rounds` (fails the vectors); `float_scale_by_division` (u = x/2³², not exact, can return 1.0: fails the
  exhaustive test at x = 2³² − 1).

### Known answers and negative controls
- KA-793 (sequential draws with one extra leg; control: the sequential stream), KA-794 (integer-to-uniform
  conversion, exhaustive), KA-795 (draw tables across slots, buckets, shards and backends; adding a stream changes
  no other stream). Counterexamples CX-371 (equal seeds do not give equal disturbances) and CX-215 (a noise
  generator handing out draws in call order).
- Metamorphic: relabelling slots, changing batch size or shard count, and reordering kernel launches within a step
  leave every draw unchanged.
- Determinism lanes: twice on one machine; across worker counts; debug and release; Linux and macOS, all
  bit-identical (class D0 for integer draws and uniforms); CUDA and Metal by N35-16's battery on this kernel.

## Considerations

- A stream's `tick` and `clock` matter: noise keyed by physics step changes meaning if the step size changes;
  streams that must survive a change of h are keyed by decision index or by time index and say so in the registry
  row (N35-23's `tick`, with this bead's `clock` naming the device counter).
- Keying by physical entity is what makes a pairing a pairing by physical field; where no such entity exists the
  key falls back to the design's own index, and the registry row shows it in N35-23's vocabulary (its `domain` and
  `entity` fields), so a reader of a comparison can see which streams are only seed-paired.
- Three block evaluations per draw block cost about 60 integer multiplies; the profile decides whether the world
  key k and the stream key s are cached per episode as constant data (allowed: each is a pure function of the
  address).
- Security and privacy: none specific; seeds are not secrets.
- What would make us revisit: a need for more than 2³² blocks per step and stream, or a backend with no exact
  32-bit multiply-high.
