## Background

The risk register is only useful if somebody reads it at the moments when acting is still cheap, and if a signal
that has fired cannot be passed over in silence. The plan fixes four rules for its use.

- **Review.** The register is read at every milestone exit by the fresh-context session that records the exit (a
  session that did not implement the work). For each row the session records whether the earliest signal has fired.
- **Escalation.** A fired signal ends in one of three recorded outcomes: a kill gate decided, an architecture
  decision record (ADR) that changes a mechanism or a scope, or a written reason why neither applies. A fired signal
  with no record is a defect of the exit review.
- **Growth.** A new risk continues the series. A risk that can no longer occur is tombstoned with the gate that
  retired it and is not renumbered.
- **No risk is mitigated by a hope.** A mitigation names a mechanism with a gate, a fallback named in advance, or an
  owner decision with a fail-closed default. An upstream work item (a change this program makes in a sibling
  repository) is never a mitigation by itself; its interim posture is.

This bead turns the register and those rules into something a program can check: a registry file, a loader that
rejects a row which breaks a rule, and a review step in the exit runner that blocks an exit when a fired signal has
no recorded outcome. It lives in `frob-conformance` and in the exit scripts, not in `xtask`: the workspace check
tool has a hard scope of six checks, and a new check there needs a named defect class it would have caught, so the
register's checks are part of the exit runner, which already exists for the same occasions.

Rejected alternatives: a register kept as a table in a document (nothing fails when a signal fires and nobody
writes anything); a review that asks "any concerns?" without per-row readings (it is answered "no"); mitigations
written as intentions ("we will keep an eye on throughput").

## Scope

In: the schema of `registries/risks.toml`; the loader and its rules; the review step, its record and its blocking
rule; the tombstone and growth rules; the generated printout; the per-exit list of rows that become readable. Out:
the rows themselves (N41-RISK1 to N41-RISK4); the pre-mortem tables (N41-PM); the planted instances of the four
late rows and gate GATE-WS-07's runs (N41-02); the open-question register (N41-03); the exit protocol as a whole
(N40-05).

## Technical approach

Files (DESIGN): `registries/risks.toml` (schema `frob.risk/1`), `crates/frob-conformance/src/exit/risks.rs`,
`scripts/exit/risk-review.sh` (called by the exit runner), output `docs/delivery/exits/M<n>/risk-review.json`
(schema `frob.riskreview/1`) and a generated section of the exit record.

**Record.**

```toml
[[risk]]
id        = "RISK-23"
title     = "Dirty or off-pin sibling trees make a receipt unrepeatable"
severity  = "medium"                  # high | medium | low
owner     = "Build lead"              # a role
signal    = "A drift class other than on-pin in check-stack at a gate run"
detector  = { kind = "check", ref = "xtask check-stack" }   # check | gate | admission | ledger-query | review-listing
mitigation = [ { kind = "mechanism", text = "the resolution receipt hashes bytes", gate = "GATE-WS-01" },
               { kind = "owner-default", open = "OPEN-SUITE-3", text = "no gate records a PASS on a dirty tree" } ]
upstream  = []                        # upstream work items named by the row; each needs `interim_posture`
detects   = ["GATE-WS-01"]
beads     = ["N33a-04", "N33a-05", "N34-13"]
planted   = { control = "ctl:risk-23-dirty-tree", text = "one modified file in a sibling during a gate run" }
first_readable = "M0"
status    = "open"                    # open | retired
retired_by = ""                       # gate or ADR that retired it, when status = retired
```

**Loader rules** (each a typed load error naming the row).

1. Identifiers are `RISK-nn`, unique, and form a series with no gap; a retired row stays in the file.
2. `severity` and `status` are in their closed sets; a retired row names `retired_by`.
3. No hope: `mitigation` is non-empty and every entry has kind `mechanism` with a gate, `fallback` with a kill
   gate, or `owner-default` with an open-question identifier. Every identifier in `upstream` has a non-empty
   `interim_posture`, and a row cannot have `upstream` as its only content.
4. Every `detects` identifier exists in `registries/gates.toml` (or is the literal `review-listing`); every `beads`
   key exists in the tracker export; every `open` identifier exists in the open-question register.
5. Every row has a `planted` control that is registered in the negative-control registry, and a `first_readable`
   milestone. (This is the clause "no row of the register lacks a planted instance" of gate GATE-WS-07, read here
   over the whole register; the four late rows also need 100 of 100 firings, which N41-02 measures.)

**The review step** (run by `scripts/exit/risk-review.sh <Mn>` inside the exit runner; the reviewer completes it).

1. Select the rows with `first_readable` ≤ Mn and `status = open`.
2. For each, evaluate the detector where it is mechanical (a check's exit status, a gate's recorded value against
   the signal's threshold, an admission record, a ledger query) and pre-fill `fired` (`yes`, `no`) with the
   observed value and the artifact that holds it. A detector of kind `review-listing` prints the listing for the
   reviewer, who sets `fired`.
3. Rows with `first_readable` > Mn are recorded as `not-readable`, which is different from `no`.
4. For every `fired = yes` the reviewer records exactly one outcome: `kill-gate-decided` (the kill gate and its
   ADR), `adr` (the ADR that changes a mechanism or scope), or `reason` (a written reason why neither applies, at
   least one sentence naming the evidence). The runner verifies that a named kill gate has a decision record and
   that a named ADR file exists.
5. Block rule: the exit runner fails if any selected row has no reading, or any fired row has no outcome. That
   failure is reported as a defect of the exit review, not of the milestone's work.
6. Write `risk-review.json`: milestone, commit, reviewer session identity (refused if it appears as an implementer
   of the milestone's beads), one entry per row; and render the section of the exit record: fired rows first, each
   with signal, observed value, outcome and link.

**Growth and retirement.** A new risk takes the next free number and is added by a change that also registers its
planted control; the loader refuses a new row that reuses a number. Retirement is an edit of `status` and
`retired_by`, recorded in the exit record of the milestone at which it happened.

**Generated printout.** `docs/delivery/risks.md` is generated from the registry (the workspace's generated-file
check compares it), one table per theme, so that nobody edits a second copy.

## Acceptance criteria

- [ ] The registry with all 59 rows loads; each of the five loader rules has a planted violation that is rejected
      with the row named.
- [ ] A row whose only mitigation is an upstream work item is rejected; the same row with an interim posture and a
      fallback loads.
- [ ] `scripts/exit/risk-review.sh M0` on a scratch repository selects the 21 rows of the table, pre-fills
      mechanical detectors, and writes `risk-review.json`.
- [ ] A fired signal with no outcome blocks the exit; adding a kill-gate decision, an ADR or a written reason
      unblocks it; an outcome that names a missing ADR file still blocks.
- [ ] A reviewer session identity that appears as an implementer is refused.
- [ ] `not-readable` rows are listed separately from rows that did not fire.
- [ ] Adding RISK-60 with a planted control loads; adding it without one, or renumbering an existing row, is
      rejected; retiring a row keeps it in the file and in the printout.
- [ ] `docs/delivery/risks.md` regenerates byte-identically from the registry.

hand in the printout only (caught by the generated-file comparison).

## Considerations

- A detector that cannot be evaluated mechanically is a weakness of the row, not a reason to skip it; the review
  listing forces a written reading, and rows are improved toward mechanical detectors over time.
- The review costs minutes when nothing has fired. Its cost is concentrated where it should be: on fired signals.
- The register must not become a second gate register. A row points at gates; it does not restate their thresholds
  as authority (the unit tests of the four parts compare quoted thresholds with the gate register).
- Privacy: readings quote metric values and artifact identifiers, never private-scene data.
