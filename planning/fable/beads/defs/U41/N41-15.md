## Background

The ten-fold test is designed so that the party proposing a result never checks it, and so that the rival is as
strong as an honest advocate can make it. Before anything can be frozen for the partial gate at M3, four inputs
are needed that the test's own chapter assigns to the project owner. They are adopted into the open-question
register with the defaults that chapter states.

| Question | Fail-closed default | Blocks |
|---|---|---|
| OPEN-TENFOLD-3: who the rival advocates are, and their budget | Agent sessions that have contributed nothing to FrankenRobotics, 40 device-hours per stratum, and the label `rival: internally advocated` on every result | GATE-TENFOLD-04 (freeze and seal) |
| OPEN-TENFOLD-4: the compute envelope for the partial gate and the tournament (a campaign class for each run, and the pretraining class where an arm builds a standing asset) | Nothing above the default class runs, the gate is recorded as `not run`, and M3 does not exit | GATE-TENFOLD-06 and GATE-TENFOLD-07 |
| OPEN-TENFOLD-6: the agent model, its revision and its caps | The agent the project itself is developed with at the gate's date, pinned; one agent only, with the result stated as conditional on it | Every freeze |
| OPEN-TENFOLD-8: ratification of the thresholds 3 and 10, the guard floor 5, the tie factor 1.5, the margin 0.05 and the limit of four confirmatory cells | As written | The first suite hash |

Why these are the owner's. A *rival advocate* is whoever is responsible for making the incumbent arm strong:
choosing its tools, its warm configuration and its tuning within a budget; if the advocate is weak the ratio is
inflated, so who they are and what they may spend is a credibility decision. The *agent model* drives both arms;
the result is conditional on it, and choosing it is choosing what the result is about. The *thresholds* define what
words the report may use. The *compute* is the owner's money.

One of the four defaults is unlike every other default in the register: OPEN-TENFOLD-4 at its default **blocks the
M3 exit**. The partial gate must be recorded with its outcome; "not run" for lack of compute is not an outcome the
milestone can exit on. It is therefore asked two milestones early and repeated.

## Scope

In: the four decision records; the request pages; the configuration record the harness reads; the labels and
refusals under each default; the blocking rule for the envelope. Out: the adjudicator and neutral party (N41-06);
the deadline per stratum, incumbent licences and the fourth arm (the ten-fold unit's questions); the freeze
procedure, the arms and the decision rule themselves.

## Technical approach

**Configuration record** (DESIGN): `registries/tenfold/owner-inputs.toml`, generated from the ADRs and read by the
ten-fold harness at every freeze:

```toml
[advocates]
kind    = "internal-sessions"       # or "external", with names
budget_device_hours_per_stratum = 40
label   = "rival: internally advocated"
[agent]
model    = "<pinned identifier>"    # the agent the project is developed with at the gate's date
revision = "<pinned revision>"
caps     = { turns = "<cap>", tokens = "<cap>", wall_clock = "<cap>" }   # the same for every arm
single_agent = true
[thresholds]                        # ratified or as written
describe_from = 3
confirm_at    = 10
guard_floor   = 5
tie_factor    = 1.5
margin        = 0.05
confirmatory_cells_max = 4
[envelope]
partial_gate = "E0"                 # until approved; a campaign class per run once approved
tournament   = "E0"
pretraining  = "none"
```

**What is put to the owner.** At the M0 exit: the envelope request (so that a refusal is known two milestones
before it would block). At the M1 exit: all four, as one page.

1. *Advocates.* Options: external advocates with named affiliations; or the default internal sessions. For either:
   the budget per stratum; the rule that an advocate has contributed nothing to this product; the advocate
   statement each arm publishes at the freeze. Under the default every result line carries
   `rival: internally advocated`.
2. *Envelope.* The partial gate's campaigns on both arms (a design-campaign class per run; the pretraining class
   only where an arm builds a standing asset such as a family policy), with the arithmetic from the work-package
   table (24 mission families per cell by default at the tournament, at least 32 for a cell that declares a
   population result, on both machines), a ceiling per run and a kill rule written first. If not approved: fewer
   strata at the tournament, each declared `not run` with the reason; at M3, no exit until at least the CPU strata
   of the partial gate have run inside the default envelope and are recorded, with the device strata `not run`.
3. *Agent.* The model and revision to pin, and its caps, identical for all arms. The report states the result as
   conditional on that agent. More than one agent is a larger test; the default is one.
4. *Thresholds.* The six constants above, to ratify or amend **before the first suite hash exists**. After that
   they are part of the sealed protocol and cannot change for that suite.

**Recording.** ADRs `ADR-PROG-15` (advocates), `-16` (envelope), `-17` (agent), `-18` (thresholds); the register
rows move to `decided` or `defaulted`; the configuration record is regenerated and its digest enters the suite
manifest at the freeze.

**Checks in the harness.**

- A freeze refuses to start unless all four rows are `decided` or `defaulted` and the configuration digest
  matches the ADRs.
- A threshold changed after the first suite hash is refused (the suite manifest embeds the digest).
- A campaign of the partial gate above the class in force is refused before it starts (`FROB-REF-761`).
- The M3 exit check reads the partial gate's record: `not run` for every stratum blocks the exit and names
  OPEN-TENFOLD-4; CPU strata recorded with device strata `not run` (with the reason) is a recordable outcome.
- An advocate identity that appears among this product's implementers is rejected; under internal advocacy the
  label is required on every result line.
- The agent pin and caps are equal across arms; a differing cap is refused.

## Acceptance criteria

- [ ] All four register rows are `decided` or `defaulted` with ADRs before the first freeze; the configuration
      record equals its generation from the ADRs.
- [ ] A freeze attempted with any row `open` is refused, naming the row.
- [ ] A threshold edit after the first suite hash is refused.
- [ ] With OPEN-TENFOLD-4 at its default and no stratum recorded, the M3 exit is blocked with the message that
      names it; with the CPU strata recorded it is not.
- [ ] Under internal advocacy every result line of a synthetic report carries the label; an advocate who is an
      implementer is rejected.
- [ ] Arms with unequal agent caps are refused.

## Test plan

### Unit tests
`crates/frob-conformance/tests/tenfold_owner_inputs.rs`: `freeze_refuses_with_open_row`;
`config_digest_matches_adrs`; `threshold_change_after_hash_refused`; `m3_exit_blocked_when_all_not_run`;
`m3_exit_allowed_with_cpu_strata`; `internal_advocacy_label_required`; `advocate_is_implementer_rejected`;
`unequal_caps_refused`; `campaign_above_class_refused_761`; `defaults_are_as_written` (3, 10, 5, 1.5, 0.05, 4;
40 device-hours).

### End-to-end script and logging
`scripts/e2e/owner_tenfold_inputs.sh`: on a scratch tournament directory attempts a freeze with open rows
(refusal), writes the four default ADRs, regenerates the configuration, freezes a synthetic development suite
(labelled `synthetic`), attempts to change `tie_factor` (refusal), and runs the M3 exit check in the two states of
the envelope. Logs: `cmd`, exit codes, the configuration digest, `refusal` lines, the exit check's verdict, a
`summary` naming GATE-TENFOLD-04 and GATE-TENFOLD-06 as read.

### Known answers and negative controls
Known answers: the six constants; 40 device-hours per stratum; 24 and 32 families. Negative controls: a freeze with
an open row; a post-hash threshold change; an M3 exit on an all-`not run` partial gate; unequal caps; an unlabelled
internally advocated result.

## Considerations

- Ratifying thresholds before any data exists is the whole point of asking early; an owner who wants different
  numbers can have them at no cost before the first suite hash and at the cost of a new suite after it.
- The agent pin makes the result conditional on one model at one revision. That is a limit of the claim, printed
  with it, not a defect to hide.
- External advocates need a budget and time to prepare; asking at the M1 exit leaves a milestone to engage them.
