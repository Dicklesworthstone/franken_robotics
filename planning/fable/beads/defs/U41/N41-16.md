## Background

The work of the program lives in a tracker of beads (work items) with blocking dependencies, grouped into
work-package epics under milestone epics, each milestone ending in an exit review. The plan's seed list had 442
beads and a set of mechanically checked graph facts; after conversion the tracker is larger and it changes every
day, so the guarantee against cycles is the tracker's own cycle check and not the original numbering. A tracker
that nobody audits decays in known ways: a bead with no path to any exit review (work nobody will ever ask for), a
gate that no bead measures (a threshold nobody will ever record), a bead with no test plan (work that can be
closed on assertion), a dependency on something that does not exist.

This bead is the audit, run at every milestone exit and on every change to the tracker export. It checks four
structural properties (no cycles; no orphans; every gate carried by a bead; every bead with a test plan) and a
few lesser ones, and it proves itself first on the seed graph, whose facts are recorded below as known answers.

It is a script and a small library, not a seventh `xtask` check: the workspace check tool has a hard scope of six
checks, and tracker structure is not a property of the source tree.

## Scope

In: the script, its library, the checks, their known answers on the seed graph, the table of gates that close in
parts, and the output consumed by the exit runner. Out: creating or editing beads (done only with the tracker's
own tool); work-package table generation and membership rules (N44-03, N44-04); close-reason and lifecycle rules
(N41-17); gate status (the gate register).

## Technical approach

Files (DESIGN): `scripts/tracker-check.sh` (plain shell wrapper), `crates/frob-conformance/src/tracker/{load.rs,
graph.rs, checks.rs}` (reads the tracker's JSONL export; never writes it), fixture `tests/fixtures/tracker/seed.jsonl`
(the 442 seed beads as exported), output `target/tracker-check/report.json` (schema `frob.trackercheck/1`).

**Checks** (each returns a list of offending keys; any non-empty list fails the script unless marked advisory).

1. *No cycles.* Topological sort of blocking dependencies succeeds. (The tracker refuses cycles at entry; this
   re-checks the export.)
2. *Dependencies resolve.* Every key in a dependency list or parent field exists. A bead never depends on its own
   parent epic.
3. *No orphans.* (a) Every bead that is not an epic has a parent that is a work-package epic or a milestone epic;
   exit reviews belong to no work package. (b) Every bead of milestone Mn other than epics is an ancestor of the
   exit review of Mn, directly or through other beads. (c) The exit reviews form a chain, each depending on the
   one before it: BD-044 → BD-147 → BD-224 → BD-319 → BD-378 → BD-412 → BD-427 → BD-434 → BD-442, so the last has
   every other bead as an ancestor.
4. *Every gate carried.* Every identifier in `registries/gates.toml` (convergence gates, kill gates, admission
   gates, and the program gates) is cited in the `gates` field of at least one open or closed bead; a kill gate is
   cited by a bead labelled `kill-gate`. A gate that closes in parts (table below) has a bead for each part.
5. *Every bead has a test plan.* Every bead of type `task` or `feature` has a body with the sections Background,
   Scope, Technical approach, Acceptance criteria, Test plan (with its three parts: unit tests, end-to-end script
   and logging, known answers and negative controls), Considerations and References; an acceptance list with at
   least one checkbox; and in the test plan at least one named negative control. Decision and registry beads are
   held to the same sections. Epics need Background, Scope and Acceptance criteria.
6. *Labels.* Every bead carries its milestone label, a subsystem label and, where it has one, its crate and tier;
   a bead labelled `frontier` or `moonshot` that is not itself a pilot depends on a bead labelled `pilot`; every
   bead whose type is an end-to-end test depends on the end-to-end harness bead.
7. *Milestone order (advisory).* A bead that depends on a bead of a later milestone is listed.
8. *No "see section" bodies (advisory at M0, failing from M1).* A body line that consists only of a pointer to a
   plan section in place of content is listed.

**Use.** `scripts/tracker-check.sh [--export <path>] [--self-test]`. `--self-test` runs every check and every known

## Acceptance criteria

- [ ] `--self-test` reproduces every known answer above on the seed fixture (counts, the root, the 44 beads, both
      longest chains, the widest beads, the exit chain, gate coverage of the seed inventory).
- [ ] Each check catches its planted defect on a mutated copy of the fixture (controls below).
- [ ] On the live export the script reports zero cycles, zero unresolved keys, zero orphans, zero uncarried gates
      and zero beads without a test plan, or lists them; any non-empty failing list makes the exit runner block.
- [ ] Every gate of the parts table has a bead per part in the live export.
- [ ] The report is deterministic (sorted, stable) and the script finishes in under 10 seconds on the live export
      (TARGET).

## Test plan

### Unit tests
`crates/frob-conformance/tests/tracker_checks.rs` on the seed fixture and mutated copies:
`seed_counts`, `seed_edges_1091`, `seed_single_root`, `seed_numbering_is_topological`,
`seed_exit_chain_and_ancestors`, `seed_44_exit_only_consumers`, `seed_longest_chain_37`,
`seed_longest_chain_without_exits_33`, `seed_widest_24`, `seed_gate_coverage`;
`cycle_detected` (an added edge BD-005 → BD-014 closes a cycle); `unresolved_key_detected`;
`orphan_detected` (a bead with no parent; a bead not on any path to its exit review);
`broken_exit_chain_detected`; `uncarried_gate_detected` (a gate added to the register with no bead);
`missing_test_plan_detected` (a body without the three test-plan parts); `no_negative_control_detected`;
`frontier_without_pilot_detected`; `later_milestone_dependency_listed`.

### End-to-end script and logging
`scripts/e2e/tracker_hygiene.sh`: runs `scripts/tracker-check.sh --self-test`, then the live check, then each
planted-defect copy, writing the shared newline-delimited JSON log: one `cmd` line per run with exit code and wall
time; one `metric` line per known answer with expected and observed values; one `assert` line per planted defect
naming the check that caught it and the offending key; on failure the first offending key and the path of the
report. `summary`: assertions passed and failed; gate GATE-GAUNT-01 named as supported (every gate has a bead that
can record it and its control).

### Known answers and negative controls
Known answers: the seed graph facts listed above. Negative controls: the nine planted defects of the unit tests.
Metamorphic: renumbering beads by a random permutation that preserves dependencies changes no check's verdict
(only the "numbering is topological" fact, which is a property of the seed and is not required of the live graph).
Determinism: byte-identical reports on Linux and macOS.

## Considerations

- After conversion a dependency may point to a higher number (a bead discovered during implementation takes the
  next free number); only cycles are forbidden.
- Check 5 reads structure, not quality. A test plan that is present and empty of substance passes it; the exit
  review by a fresh-context session is what judges substance. The script makes sure there is something to judge.
- The seed facts are frozen history; they must never be "updated" to match a changed fixture. If the fixture and
  the facts disagree, the fixture is wrong.
- Process is never the product: if no exit runner or reviewer reads this report, the script is deleted.
