## Background

The whole program consumes FrankenSim, a large and fast-moving sibling library, by path at a pinned commit, through
one airlock crate. The bet that this is affordable (BET-04) stands on a measurement that had not been taken when
the plan was written: does a crate **outside** FrankenSim's tree, depending by path on its geometric-algebra and
multibody crates, build and compute the same numbers as FrankenSim computes for itself? Step 2 of the first
session takes that measurement, with the smallest program that can: build FrankenSim's built-in G1 humanoid model,
run forward dynamics at one state, and compare a digest with the digest a test inside FrankenSim produces at the
same commit.

FACTs that make this non-trivial (each to be re-read at the pinned commit): a path dependency on the multibody
crate compiles 42 other FrankenSim crates and about 1.57 million lines; its linear-algebra crate's build script
fails closed outside the tree without the build-identity setting; 409 commits touched the multibody crate in the
thirty days before planning. If the cold check exceeds the machine envelope, or the effort to get the admission
passing exceeds its budget, kill gate KILL-FSIM names the fallbacks in order: a pinned FrankenSim worker process
first, a lift of a minimal referee set second.

Session rules apply (offload shim; default envelope; no sibling edited; a failing result is recorded as failing and
not retried until it passes). **If this step fails, the session still completes steps 3 to 8, because none of them
depends on it, and the failure is the session's most important result.**

## Scope

In: running the step once, in session order, on the artifacts of the admission bead and the airlock's first
version; the four observations (digest equality, sensitivity, build cost, the two-second rollout); the two that
only this step has (the sensitivity control and the two-second rollout); the session-step record
(`frob.sessionstep/1`), which cites the admission record by hash.

Out, and where it is:
- the consuming crate `frob-fsim`, the three root settings, the definition of the cold and warm checks and of
  each cost measurement (wall time, peak memory, crate, line and package counts), the three necessity tests of
  which the fail-closed control is one, the thresholds, and the admission record `frob.admission/1` of
  INT-FSIM-01: BD-006. This step runs that procedure through its scripted steps and defines none of it again;
  where this bead names a measurement, the definition in BD-006 governs;
- the digest test inside FrankenSim, the digest from this repository and the referee wrapper: BD-007, the other
  seed bead this step depends on, which completes the same admission record with the digest half;
- the worker-process fallback (its own bead); the `sim.run` verb (a later M0 bead; this step calls the crate's
  test binary directly).

## Technical approach

Procedure (artifacts under `docs/delivery/sessions/first/step-2/`):

Steps 1 to 3 are the procedure of BD-006, run with the commands BD-006 defines; they are summarized here so that
the step can be read alone, and they write the admission record. The same commands are later the steps
`int_fsim_01_cold`, `int_fsim_01_warm` and `int_fsim_01_necessity` of `scripts/e2e/admission_m0.sh`, but that
script's bead (N33a-28) comes after this session (through BD-031 and N41-20) and does not exist when it runs.

1. *Cold check.* With an empty, isolated target directory (under the offload shim's target base), run
   `cargo check -p frob-fsim --all-targets` with a 60-minute timeout and at most 8 jobs. Record wall time, peak
   memory and the package count as BD-006 defines them: peak resident memory of the whole cargo process tree,
   which is the figure compared with the 16 GiB limit (DESIGN, the same statement in BD-006: the envelope bounds
   the machine, and eight compiler processes that are each small can together exceed it), with the largest
   single compiler process recorded beside it; and the package count of the tracked `Cargo.lock`, total and from
   the registry.
2. *Warm check.* Run the same command again unchanged, and again after touching one source file of `frob-fsim`;
   record wall time.
3. *Fail-closed control.* In a scratch copy with the build-identity variable removed from `.cargo/config.toml`, run
   the same check; it must fail in the linear-algebra crate's build script. Record the failure line. (This is
   one of BD-006's three necessity tests; the other two, removing the patch entry and removing the profile
   overrides, run in the same scripted step.)
4. *Digest inside FrankenSim.* Run BD-007's capture script `tools/oracle/fsim_g1_digest.sh`, which exports the
   pinned commit with `git archive` into a scratch directory, places the probe crate inside the export so that it
   inherits FrankenSim's own configuration and toolchain file, and builds and runs it through the offload shim;
   nothing is built in, or written to, FrankenSim's checkout. It prints the digest of forward dynamics for the
   built-in G1 model at the fixed state (the state and the digest function are those BD-007 fixed). Record the
   digest and the export's directory.
5. *Digest from here.* Run the consuming crate's test that builds the same model through the airlock, evaluates
   forward dynamics at the same state and prints the digest. Record it and compare byte for byte.
6. *Sensitivity control.* Perturb one input (the first joint position by one unit in the last place) and confirm
   that the digest changes; a digest that does not change is a defect of the digest, recorded as a failure.
7. *Two-second rollout.* Step the model on the referee for two seconds of simulated time at the referee's default
   step h = 1/480 s (960 steps of BD-007's `step_free`, h passed as the `f64` value `1.0 / 480.0`) from the fixed
   initial state with zero actuation, and record the final-state digest, the number of steps, and wall time. Run
   it twice; the two digests must be equal. Compare the digest with `rollout_2s_digest`, which the capture script
   of step 4 wrote into `tests/fixtures/oracle/fsim/g1_fd_digest.toml` from the same rollout run inside
   FrankenSim's tree; record `rollout_matches_frankensim`. That equality is the M0 artifact of §43.3, recorded
   here and not a clause of INT-FSIM-01.

**The record** (`step-2/record.json`, schema `frob.sessionstep/1`): commands with exit codes and output digests;
`observation` = { `digest_frankensim`, `digest_here`, `digests_equal`, `perturbed_digest_differs`,
`cold_check_seconds`, `warm_check_seconds`, `peak_memory_gib`, `packages`, `fail_closed_without_setting`,
`rollout_digest`, `rollout_steps`, `rollout_repeat_equal`, `rollout_digest_frankensim`,
`rollout_matches_frankensim` }; `decides` = ["INT-FSIM-01", "BET-04's measurement",
"whether KILL-FSIM's worker process is needed at once", "the hypothesis of step 1, second half"]; `verdict`.

What the observation decides: the admission INT-FSIM-01; the figures BET-04 stands on; whether the worker-process
fallback is needed at once (if the cold check is over the envelope of one hour, 16 GiB, 8 cores, or the digests
cannot be made equal).

## Acceptance criteria

- [ ] The record states whether the two digests match; if they do, the admission record of INT-FSIM-01
      (`frob.admission/1`, written by BD-006's procedure and completed with the digest by BD-007) is the one this
      run produced, and the step record cites it by hash without copying a value by hand; if they do not, both
      digests and the first differing intermediate (link index and quantity, where the tests print it) are
      recorded and the step's verdict is `fail`.
- [ ] Cold and warm check times, peak memory (the process-tree total, with the largest single process beside it)
      and package count are recorded with units, and equal the values in the admission record of the same run.
- [ ] The build fails closed with the build-identity variable unset.
- [ ] A one-unit-in-the-last-place perturbation changes the digest.
- [ ] The two-second rollout (960 steps of 1/480 s) ran twice with equal final digests, or its failure is recorded; its digest is compared with the fixture's `rollout_2s_digest` and the result recorded either way.
- [ ] FrankenSim's checkout is byte-identical before and after the step (head, tree hash and untracked files).
- [ ] The record validates, and the bead closes on the recorded observation whatever the verdict: a `fail` here
      is the session's result and blocks no later step.

## Test plan

### Unit tests
None new: the step runs tests owned by its dependencies. The record validator's tests (shared with step 1) cover
`digests_equal_requires_both_digests` and `verdict_fail_keeps_all_observations`.

### End-to-end script and logging
`scripts/session/first/step-2.sh`: the procedure above, with the shared logging helper: `cmd` lines for each
command with exit code and wall time; `metric` lines for cold seconds, warm seconds, peak memory and packages
against the envelope thresholds (3,600 s, 16 GiB); `assert` lines for digest equality, sensitivity, fail-closed,
rollout repeatability and the rollout digest against FrankenSim's own, each with both values; on failure the
first differing value and the artifact paths.
`summary` names INT-FSIM-01 as touched.

### Known answers and negative controls
Known answers: the forward-dynamics digest and the two-second rollout digest printed by the probe inside
FrankenSim's tree at the pinned commit (oracles that are never regenerated from this repository). Negative
controls: the perturbed input; the unset build-identity variable.
Determinism: the rollout twice on one machine with equal digests.

## Considerations

- The digest compares numbers produced by the same code compiled in two graphs; a mismatch points at feature
  unification, a patch that did not apply, or a different dependency version, and the saved `cargo tree` output of
  both graphs is the first thing to compare.
- The two-second rollout's known answer is FrankenSim's own rollout at the pin (`rollout_2s_digest`, captured by
  BD-007's script); the run is recorded so that the first referee artifact exists, matches FrankenSim, and can be
  reproduced by a fresh session later. A mismatch is recorded as the session's finding, never retried until it
  passes.
- Peak memory matters as much as time: the envelope caps both.
