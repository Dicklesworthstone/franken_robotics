## Background

The device layer's central promise is that **one kernel source** runs on the CPU, on CUDA and on Metal, and that a
world's results do not depend on where it ran beyond a declared determinism class. Whether single-precision
arithmetic on a given GPU family can be made bit-equal to the CPU at all is an empirical question about that
family: compilers contract a·b + c into a fused multiply-add by default on some backends, shading languages permit
reassociation and flushing of subnormals, and built-in elementary functions differ. The design's answer is a small
dialect with those freedoms switched off, kernels whose arithmetic is rational (the Cayley map needs no
transcendental function), and a probe that records what each device family actually does.

Steps 4 and 5 of the first session take the first measurement of that promise with the smallest kernel that
exercises real arithmetic: a twenty-line Cayley step that advances a unit quaternion by a body angular velocity,
q′ = q ⊗ (1, h·ω/2) followed by normalization with one square root and four divisions. Step 4 is the Metal half, on
the Mac this session runs on, through FrankenTorch's Metal compute gateway (FACT to re-read at admission:
`ft_kernel_metal::compute::Gateway`, with a safe math mode that disables contraction and the no-NaN assumption).
It also runs the first half of the IEEE probe: square root compared with the correctly rounded reference over all
2³² single-precision bit patterns.

Session rules apply (offload shim for builds; default envelope; no sibling edited; failures recorded as failures).

## Scope

## Technical approach

Procedure (artifacts under `docs/delivery/sessions/first/step-4/`):

1. Record the device: model, operating-system and shading-language versions, the gateway crate's version and the
   math mode in force (`MathMode::Safe`).
2. *Kernel text.* The twenty-line Cayley step in Metal Shading Language, generated from (or, at this first
   session, written to match) the shared dialect source; save its text and its BLAKE3 hash. The same text with the
   CUDA prelude is what step 5 compiles.
3. *Inputs.* 10⁶ unit quaternions and 10⁶ angular velocities with ‖ω‖·h ≤ 0.2, generated on the host from a
   recorded seed by a counter-based generator; save the input digest.
4. *Reference.* A Rust loop on the host computing the same expression in `f32` in the same operation order, with no
   fused multiply-add; save the output digest.
5. *Run on Metal.* Open the gateway, compile the kernel from source, bind the buffers at offset zero, run once,
   read back. Compare with the reference **bit for bit**: the count of differing elements and, if any differ, the
   first index with input bits, expected bits and observed bits.
6. *Contraction control.* Compile the same kernel with the safe mode switched off (the fast mode) and run it;
   record whether the output differs from the reference. A difference shows the control is live; no difference is
   recorded as "contraction not observed on this kernel", not as a pass of anything.
7. *Square root, exhaustive.* A second kernel computes `sqrt` over all 2³² bit patterns in batches; the host
   compares each batch with the correctly rounded reference (non-negative finite inputs bit for bit; negative
   inputs and NaNs by class; signed zeros by sign). Record the count of mismatches by class and the wall time; the
   run is chunked so that each launch stays inside the gateway's limits and the whole fits the one-hour envelope.

**The record** (`step-4/record.json`, schema `frob.sessionstep/1`): `observation` = { `device`, `math_mode`,
`kernel_hash`, `input_digest`, `reference_digest`, `metal_digest`, `differing_elements`, `first_difference`,
`fast_mode_differs`, `sqrt_mismatches`: by class, `sqrt_inputs_checked`: 4,294,967,296, `wall_seconds` };
`decides` = ["GATE-SPARK-00 (Metal row)", "the first half of GATE-SPARK-01", "the best attainable determinism
class of the Metal family, input to KILL-D1"]; `verdict`.

What the observation decides (with step 5): bit agreement of one algebraic kernel on three backends
(GATE-SPARK-00); the first half of the IEEE probe (GATE-SPARK-01); each family's best attainable determinism class,
which is what kill gate KILL-D1 is decided on (if bit equality with the CPU is unattainable on a family, that
family claims bit equality only with itself and statistical equivalence against others).

## Test plan

### Unit tests
The host reference has a unit test in the annex crate: `cayley_step_known_values` (q = identity, ω = (0, 0, 2),
h = 1 gives the unnormalized (1, 0, 0, 1) and the normalized quarter turn); `reference_has_no_fma` (the reference
is compiled with contraction off and its digest is stable in debug and release).

### End-to-end script and logging
`scripts/session/first/step-4.sh` with the shared logging helper: `cmd` lines; `metric` lines for differing
elements (threshold 0), square-root mismatches by class (threshold 0 for finite non-negative), inputs checked and
wall time; `assert` lines for the bit comparison and for "fast mode recorded"; digests of inputs and outputs;
`summary` naming INT-FT-01, GATE-SPARK-00 and GATE-SPARK-01 as touched (partial). Evidence fields: tier
`gpu-metal`, determinism class as measured, seed.

### Known answers and negative controls
Known answers: the Rust loop's digest for the recorded seed; the correctly rounded square root. Negative controls:
the fast-mode compile (expected to be able to differ); a kernel variant with one operand order swapped in the
quaternion product, which must differ from the reference on some inputs (a one-ulp change in one prelude is the
control the three-backend gate later uses).

## Considerations

- 2³² square roots at a few nanoseconds each are tens of seconds of device time; the cost is in transfer and
  comparison, which is why the run is chunked and compared on the host by batch digest first, element-wise only
  when a batch differs.
- Subnormal flushing on Metal is permitted by its specification and cannot be controlled; the probe records it,
  and bit equality is claimed only where behaviour matches.
- The gateway's limits (synchronous launches, at most 31 buffers, offset-zero binding) do not bind for this
  kernel; they are recorded here because later kernels meet them.
