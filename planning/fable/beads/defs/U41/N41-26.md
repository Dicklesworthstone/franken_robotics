## Background

"Done" for this program is not a feeling and not a count of closed work items. It is sixteen clauses, each tied to
gates whose thresholds live in the gate register. **The program has delivered when each clause is true and its
gate has a recorded value. A clause whose mechanism fell back at a kill gate is true when the fallback is in
force, recorded as an ADR, and described by its own name.** Every clause is a DESIGN statement of acceptance; no
clause requires a particular measured number except where its gate does.

Three things are deliberately **not** required for done. No Moonshot item is required: the design works without
every one of them. No particular ratio is required: a published ratio of 2 with an honest ledger satisfies the
ten-fold clause, and an unpublished ratio of 12 does not. No calibration against hardware is required: a recorded
`no-claim` satisfies the ground clause.

This bead makes the definition executable: a registry of the clauses and a checker that, at any commit, reports
each clause as true, true by fallback, false or not yet evaluable, from recorded evidence only. It is run at every
milestone exit (to show how far the program is) and decides nothing by itself: acceptance of a gate is the gate's
row in the gate register, and the checker reads those rows.

## Scope

In: the clause registry; the evaluation rules; the fallback rule; the three not-required rules as checks; the
report. Out: the gates and their measurements; the per-capability eight conditions (their registry; used by the
release checker, N41-27); release rules and the rubric (N41-27, N41-28); the exit protocol.

## Technical approach

Files (DESIGN): `registries/done.toml` (schema `frob.done/1`), `crates/frob-conformance/src/done.rs`, command
`frob-conformance done --json` (also `scripts/release/done-check.sh`), report `target/done/report.json`.

**Clause record:** `id`, `name`, `statement`, `gates` (all must have status `pass` with a measured value and a
caught negative control), `alternatives` (a kill gate whose recorded decision "fired", with the fallback name and
ADR, makes the listed gates optional), `extra` (named checks beyond gates), `not_required` notes.

**Evaluation** (pure function of the registries at a commit; class D0).

1. For each listed gate read status, measured value and caught control. `pass` with both present counts. `pass`
   with a target in place of a measured value, or with no caught control, does not.
2. Fallback: if a kill gate named in `alternatives` has a decision record "fired" with an ADR and a fallback name,
   the gates that the fallback replaces are waived for the clause, the clause is `true-by-fallback`, and the
   report prints the fallback's name in place of the mechanism's. A fired kill gate with no ADR waives nothing.
3. Import-lane gates (the first-real-cell gate) count as satisfied by a recorded "import lane, no data admitted"
   state: that is the third not-required rule, implemented as a status and never as a PASS.
4. Extra checks: clause 1 reads the construction register (four obligation fields per construction, or a
   killed-idea entry with reason); clause 14 reads the published report's manifest and runs the wording lint;
   clause 16 reads the upstream registry (every sibling change has a bead here and a mirror), scans the lockfiles
   for patched or forked sibling sources not covered by a kill-decision ADR, compares the toolchain files with T,
   and checks each admission record's commit against the lockfile.
5. Not-required rules as checks: no clause lists a gate whose only bead is labelled `moonshot` (the loader
   refuses such a clause); clause 14 contains no threshold on the ratio (a planted ratio of 2 with a complete
   report passes; a planted ratio of 12 with no published report fails); clause 12 passes on `no-claim`.
6. Result per clause: `true`, `true-by-fallback` (with names), `false` (with the failing gates or checks), or
   `not-yet` (a gate whose earliest milestone is later than the current one). The program is done when all sixteen
   are `true` or `true-by-fallback`.

**Report.** One line per clause with its state, the gates and their recorded values by reference, the fallbacks in
force by name, and the ADRs. The exit runner attaches it to every exit record; the README's status section links
it. Nothing in the report is typed by hand.

## Acceptance criteria

- [ ] `registries/done.toml` holds the sixteen clauses with their gates; a clause naming an unknown gate fails to
      load.
- [ ] On a scratch gate register: all gates passing with values and controls gives sixteen `true`; removing one
      measured value turns its clause `false`; a fired kill gate with ADR turns its clause `true-by-fallback` with
      the fallback's name; the same without an ADR leaves it `false`.
- [ ] Clause 12 is `true` with `no-claim` recorded and no data admitted; clause 14 is `true` for a published ratio
      of 2 and `false` for an unpublished ratio of 12; no clause depends on a Moonshot-only gate.
- [ ] Clause 16 is `false` when a lockfile contains a locally patched sibling source without a kill-decision ADR,
      when a toolchain file differs from T, or when an admission record's commit lacks the foundation in its
      lockfile.
- [ ] `frob-conformance done --json` is deterministic and is attached to each exit record.

## Test plan

### Unit tests
`crates/frob-conformance/tests/done.rs` on scratch registries (labelled `synthetic`): `sixteen_clauses_load`;
`all_pass_is_done`; `target_instead_of_measured_does_not_count`; `pass_without_caught_control_does_not_count`;
`fallback_with_adr_counts_under_its_name` (KILL-FAMILY and KILL-PACKET cases); `fallback_without_adr_waives_nothing`;
`no_claim_satisfies_ground`; `ratio_two_published_satisfies_tenfold`; `ratio_twelve_unpublished_fails`;
`moonshot_gate_in_clause_rejected`; `patched_sibling_fails_foundations`; `second_toolchain_fails_foundations`;
`not_yet_for_later_milestone_gates`; `construction_missing_obligation_fails_spine`;
`construction_in_killed_register_with_reason_passes`.

### End-to-end script and logging
`scripts/e2e/done_check.sh`: runs the checker on the real registries (expecting mostly `not-yet` early in the
program) and on four scratch states (all pass; one missing value; one fallback with ADR; one patched sibling),
asserting the clause states. Logged with the shared helper: `cmd` lines; one `assert` per clause and state with
the gates read; `metric` lines for counts of `true`, `true-by-fallback`, `false`, `not-yet`; a `summary`.

### Known answers and negative controls
Known answers: sixteen clauses; the three not-required rules; the gate lists above. Negative controls: a gate
`pass` with an empty measured field; a fired kill gate without an ADR; an unpublished large ratio; a clause edited
to require a Moonshot gate; a report worded "verified" (clause 15 reads the wording lint's result).

## Considerations

- The checker reads records and cannot be satisfied by closing beads; that is its purpose.
- Clause 1 depends on the construction register being honest about payoffs; a construction whose "measured
  payoff" is a target is caught by the same measured-value rule as a gate.
- `not-yet` is not `false`: at an early exit the report shows the distance to done without calling it failure.
- If a gate is retired or renamed by an ADR, the clause registry changes in the same commit; the loader's
  unknown-gate error forces it.
