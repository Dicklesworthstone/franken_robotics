## Background

"Done" for this program is not a feeling and not a count of closed work items. It is sixteen clauses, each tied to
gates whose thresholds live in the gate register. **The program has delivered when each clause is true and its
gate has a recorded value. A clause whose mechanism fell back at a kill gate is true when the fallback is in
force, recorded as an ADR, and described by its own name.** Every clause is a DESIGN statement of acceptance; no
clause requires a particular measured number except where its gate does.

Three things are deliberately **not** required for done. No Moonshot item is required: the design works without
every one of them. No particular ratio is required: a published ratio of 2 with an honest ledger satisfies the
ten-fold clause, and an unpublished ratio of 12 does not. No calibration against hardware is required: a recorded
`no-claim` satisfies the ground clause.

This bead makes the definition executable: a registry of the clauses and a checker that, at any commit, reports
each clause as true, true by fallback, false or not yet evaluable, from recorded evidence only. It is run at every
milestone exit (to show how far the program is) and decides nothing by itself: acceptance of a gate is the gate's
row in the gate register, and the checker reads those rows.

## Scope

In: the clause registry; the evaluation rules; the fallback rule; the three not-required rules as checks; the
report, the example target that prints it and its record among the exit runner's attached checks. Out: the gates
and their measurements; the per-capability eight conditions (their registry; used by the release checker,
N41-27); release rules and the rubric (N41-27, N41-28); the exit protocol and its runner (N40-05).

## Technical approach

Files (DESIGN): `registries/done.toml` (schema `frob.done/1`), `crates/frob-conformance/src/done.rs`, the example
target `crates/frob-conformance/examples/done_check.rs`, the wrappers `scripts/release/done-check.sh` and
`scripts/exit/done-report.sh`, report `target/done/report.json`.

**Command.** The crate `frob-conformance` has no binary of its own name (BD-025, ADR-GAUNT-01), so the checker is
run through an example target that this bead declares: `cargo run -p frob-conformance --example done_check --
[--milestone <Mn>] [--root <dir>] --json`. It prints the report as one JSON object and writes
`target/done/report.json`. `--milestone` is the milestone under review, against which `not-yet` is decided
(default: the milestone after the last recorded exit); `--root` names a directory whose `registries/`, `docs/adr/`
and lockfiles are read in place of the workspace's (the scratch states of the tests, and the root the exit runner
passes). Exit 0 when the report was produced, whatever the clause states; exit 3 with
`reason=done-clause-invalid` on its first line when the clause registry does not load.

**Clause record:** `id`, `name`, `statement`, `gates` (all must have status `pass` with a measured value and a
caught negative control), `alternatives` (a kill gate whose recorded decision "fired", with the fallback name and
ADR, makes the listed gates optional), `extra` (named checks beyond gates), `not_required` notes.

**Alternatives.** The plan names two fallbacks inside the clauses, and they are entered by hand: clause 4 lists
KILL-FAMILY (specialists with inheritance stand in for the family policy, waiving GATE-CORTEX-11) and clause 13
lists KILL-PACKET (the reduced packet is in force, waiving the full-packet rows of GATE-FOUNDRY-08 to -10). For
every other clause the loader derives `alternatives` from the kill-gate records (N40-03): each kill gate whose
record names a gate of the clause as the mechanism it decides. DESIGN, reason: the definition's rule ("a clause
whose mechanism fell back at a kill gate is true when the fallback is in force") applies to every clause, and a
hand-kept list would drift from the kill-gate register; deriving it makes a new kill gate apply at once.

**Evaluation** (pure function of the registries at a commit; class D0).

1. For each listed gate read status, measured value and caught control. `pass` with both present counts. `pass`
   with a target in place of a measured value, or with no caught control, does not.
2. Fallback: if a kill gate named in `alternatives` has a decision record "fired" with an ADR and a fallback name,
   the gates that the fallback replaces are waived for the clause, the clause is `true-by-fallback`, and the
   report prints the fallback's name in place of the mechanism's. A fired kill gate with no ADR waives nothing.
3. Import-lane gates (the first-real-cell gate) count as satisfied by a recorded "import lane, no data admitted"
   state: that is the third not-required rule, implemented as a status and never as a PASS.
4. Extra checks: clause 1 reads the construction register (four obligation fields per construction, or a
   killed-idea entry with reason); clause 14 reads the published report's manifest and runs the wording lint (the
   gate-conditioned ten-fold rules of the claims-wording registry, N00-15);
   clause 16 reads the upstream registry (every sibling change has a bead here and a mirror), scans the lockfiles
   for patched or forked sibling sources not covered by a kill-decision ADR, compares the toolchain files with T,
   and checks each admission record's commit against the lockfile.
5. Not-required rules as checks: no clause lists a gate whose only bead is labelled `moonshot` (the loader
   refuses such a clause); clause 14 contains no threshold on the ratio (a planted ratio of 2 with a complete
   report passes; a planted ratio of 12 with no published report fails); clause 12 passes on `no-claim`.
6. Result per clause: `true`, `true-by-fallback` (with names), `false` (with the failing gates or checks), or
   `not-yet` (a gate whose earliest milestone is later than the current one). The program is done when all sixteen
   are `true` or `true-by-fallback`.

**Report.** One line per clause with its state, the gates and their recorded values by reference, the fallbacks in
force by name, and the ADRs. The README's status section links it. Nothing in the report is typed by hand.

**Attached to every exit record from M1.** The exit runner of N40-05 names no check in its source; a bead attaches
its exit-time reading through a record of `scripts/exit/checks.toml` (schema `frob.exitchecks/1`). This bead adds
the record `id = "done-report"`, `owner = "N41-26"`, `step = 6` (the step that lists the parts not yet passed),
`since = "M1"`, `command = "scripts/exit/done-report.sh"`. Under the runner's check contract the wrapper is run as
`scripts/exit/done-report.sh <Mn> --root <dir> --json`, calls the example above with `--milestone <Mn> --root
<dir>`, and prints one object `{check, milestone, section, blocks, warnings}`, exiting 0 whenever it ran.
`section` is the report as Markdown, one line per clause. A clause state is never a block: `false` and `not-yet`
are the distance to done, not a failure of an exit. The one block is a clause registry that does not load (`id`
the clause, `reason` `done-clause-invalid`), because the exit record would otherwise carry no report.

## Acceptance criteria

- [ ] `registries/done.toml` holds the sixteen clauses with their gates; a clause naming an unknown gate, or a
      gate whose only bead is labelled `moonshot`, fails to load with `reason=done-clause-invalid` (exit 3).
- [ ] On a scratch gate register: all gates passing with values and controls gives sixteen `true`; removing one
      measured value turns its clause `false`; a fired kill gate with ADR turns its clause `true-by-fallback` with
      the fallback's name; the same without an ADR leaves it `false`.
- [ ] Clause 12 is `true` with `no-claim` recorded and no data admitted; clause 14 is `true` for a published ratio
      of 2 and `false` for an unpublished ratio of 12; no clause depends on a Moonshot-only gate.
- [ ] Clause 16 is `false` when a lockfile contains a locally patched sibling source without a kill-decision ADR,
      when a toolchain file differs from T, or when an admission record's commit lacks the foundation in its
      lockfile.
- [ ] `cargo run -p frob-conformance --example done_check -- --json` is deterministic: two runs at one commit
      print the same bytes.
- [ ] The record `done-report` is in `scripts/exit/checks.toml`; through the runner of N40-05 the check is not
      run at M0, runs from M1, and its section is in the exit record under its identifier; a `false` clause adds
      no block and a clause registry that does not load is a block with `done-clause-invalid`.

## Test plan

### Unit tests
`crates/frob-conformance/tests/done.rs` on scratch registries (labelled `synthetic`): `sixteen_clauses_load`;
`all_pass_is_done`; `target_instead_of_measured_does_not_count`; `pass_without_caught_control_does_not_count`;
`fallback_with_adr_counts_under_its_name` (KILL-FAMILY and KILL-PACKET cases); `fallback_without_adr_waives_nothing`;
`no_claim_satisfies_ground`; `ratio_two_published_satisfies_tenfold`; `ratio_twelve_unpublished_fails`;
`moonshot_gate_in_clause_rejected`; `patched_sibling_fails_foundations`; `second_toolchain_fails_foundations`;
`not_yet_for_later_milestone_gates`; `construction_missing_obligation_fails_spine`;
`construction_in_killed_register_with_reason_passes`; `done_report_as_exit_check` (through the runner of N40-05 on
a scratch repository: at M0 the check is not run; at M1 its section is in the exit record under `done-report`; a
scratch register with one clause `false` gives no block; a clause naming an unknown gate gives one block with
`done-clause-invalid` and the verdict `not exited`).

### End-to-end script and logging
`scripts/e2e/done_check.sh` sources the shared logging helper of STD-E2E and writes
`target/e2e-logs/done_check/<utc-timestamp>.ndjson` and a transcript; every line carries `ts`, `script`, `bead`
(`N41-26`), `step` and `event`. It runs `cargo run -p frob-conformance --example done_check -- --json` on the real
registries (expecting mostly `not-yet` early in the program) and, with `--root <scratch state>`, on eight scratch
states (all pass; one missing value; one fallback with ADR; the same fallback without ADR; one patched sibling; a
published ratio of 2 and an unpublished ratio of 12; a clause edited to require a Moonshot-only gate; a `pass`
carrying a target in place of a measured value), asserting the clause states; then it runs
`scripts/exit/done-report.sh M1 --root <scratch state> --json` on the all-pass state and on the Moonshot-clause
state and asserts the check object (a section of sixteen lines and no block; one block with
`done-clause-invalid`). It logs `start`; `cmd` lines with the exact command line, exit code and wall time; one
`assert` per clause and state with the gates read and their recorded values by reference; `refusal` lines with
the reason for the load failures; `metric` lines for counts of `true`, `true-by-fallback`, `false`, `not-yet`; the
digest of the report, and an `assert` that a second run gives the same bytes; on failure the first clause whose
state differs, expected and observed, and the paths of the scratch registries and the report; `end`; and a
`summary` with assertions passed and failed.

### Known answers and negative controls
Known answers (K41-34, K41-40): sixteen clauses; the three not-required rules; the gate lists above. Negative
controls: X41-47, a gate `pass` with an empty measured field or a target in its place; X41-39, a fired kill gate
without an ADR; X41-38, an unpublished ratio of 12 beside a published ratio of 2; X41-46, a clause edited to require
a Moonshot gate; a report worded "verified" (clause 15 reads the result of the wording lint of N00-01).

## Considerations

- The checker reads records and cannot be satisfied by closing beads; that is its purpose.
- Clause 1 depends on the construction register being honest about payoffs; a construction whose "measured
  payoff" is a target is caught by the same measured-value rule as a gate.
- `not-yet` is not `false`: at an early exit the report shows the distance to done without calling it failure.
- If a gate is retired or renamed by an ADR, the clause registry changes in the same commit; the loader's
  unknown-gate error forces it.
