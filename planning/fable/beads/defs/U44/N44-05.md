## Background

Two scripts keep the map of work packages honest: the regenerator, which recomputes the package table and the order
between packages from the dependencies of the beads (N44-03), and the checker, which tests coverage of crates and
milestones, membership, pilots before upper-tier work, and the placement of upstream work (N44-04). Both are tested
on synthetic fixtures. This bead is their end-to-end run on the real graph: the tracker's export as it stands on the
day, with structured logs that a milestone exit review can cite.

It exists because the user-visible capability is neither script alone but the answer to three questions an exit
review asks of every package: which beads does it hold and how many are open; does the order between packages still
match what the epics say; and may this package be declared complete. A fresh-context reviewer who did not implement
the milestone must be able to get those answers from one command and one log. Subsystem workspace, tier Solid,
milestone M0, re-run at every milestone exit.

Alternative rejected: letting each exit review query the tracker ad hoc. Reviews would then differ in what they count,
and a package could be called complete on a count of closed beads, which the program's rules forbid: a closed bead is
not acceptance, and acceptance is the gate's row in the gate registry.

## Scope

In: `scripts/e2e/wp_table.sh`; its assertions; its log format; the per-package report it prints. Out: the algorithms
(N44-03, N44-04); the gate registry and the artifact graph that a pass resolves in (the Chronicle beads, BD-095); the
exit reviews themselves.

## Technical approach

Plain shell, sourcing the shared helper of STD-E2E; idempotent; no seed is needed because nothing is sampled, and the
log records `seed: none`. It never invokes the tracker binary and never writes outside `docs/delivery/` and
`target/e2e-logs/`.

Steps:

1. `start`: record the commit, the export's line count and its BLAKE3 digest, and the BLAKE3 digests of the inputs
   the checker reads beside it: `registries/gates.toml`, `registries/compute_envelope.toml` (check 11 reads its
   `[[request]]` rows) and the fixtures of N44-04.
2. `cmd`: `scripts/wp-table.sh generate`. Assert exit zero and that both generated files exist.
3. `cmd`: `scripts/wp-table.sh generate` again. Assert the digests of both files are unchanged (determinism lane:
   twice on one machine).
4. `cmd`: `scripts/wp-table.sh check`. Assert exit zero. Log as metrics: packages (threshold: equals 80), parts,
   edges before and after reduction, cycles surviving the split into parts (threshold: equals 0 under
   `--strict-acyclic` when the script is run with `--exit M<n>`), unpackaged beads, differences from the drafted
   column (added, removed), differences from the epics' `related` fields.
5. `cmd`: `scripts/wp-check.sh`. One `assert` event per check with its violation count against the threshold zero;
   exceptions from the committed exceptions file are logged with their reason and counted separately.
6. With `--exit M<n>`: for every package whose last part is at or before `M<n>`, run
   `scripts/wp-check.sh --declare-complete WP-nn` and log the verdict with, per key gate, its status from
   `registries/gates.toml`. A package with an open child or a gate at `not run` is reported `incomplete` with the
   first missing item; that is a finding for the review, and the script exits non-zero only if a package was already
   marked complete in the tracker and fails the test.
7. Print the per-package report: key, title, milestones, children open and closed by kind, key gates with status,
   packages it waits for (regenerated), packages that wait for it.
8. `summary`: counts of assertions passed and failed, and the list of gates touched (none: this script measures no
   gate and says so).

**Log.** Newline-delimited JSON at `target/e2e-logs/wp_table/<utc-timestamp>.ndjson` with a human-readable transcript
beside it. Every line has `ts`, `script`, `bead` (`N44-05`), `step`, `event` (`start`, `cmd`, `assert`, `metric`,
`end`), the exact command line, the exit code and the wall time. Because no `frob` verb runs, the `evidence` block is
logged with `claim: none`, `class: none` and the identities of the inputs (export digest, commit, the digests of the fixtures,
of `registries/gates.toml` and of `registries/compute_envelope.toml`). Metrics carry their value, unit `count` and threshold. On a failed assertion the line holds the first
differing value and the paths of the scratch copy and of the committed file. The log holds keys, labels and counts
only, and no scene or dataset content.

## Acceptance criteria

- [ ] `scripts/e2e/wp_table.sh` exits zero on the loaded graph at M0 and writes the log and the transcript.
- [ ] Running it twice in a row produces generated files with identical digests, and the second log says so.
- [ ] With a stale `docs/delivery/work-packages.md` planted, the script exits non-zero and the failing line names the
      first differing line of the file.
- [ ] With a bead planted under an unknown package, the script exits non-zero, and both the regenerator's failing
      line (steps 2 to 4: the unknown package key or the broken parent chain, N44-03) and the checker's
      `wp_children_have_one_parent` line (step 5) name the bead.
- [ ] With `--exit M0` on a graph where a package of M0 has one open child, that package is reported `incomplete`
      with the child's key, and the script exits zero unless the tracker already marks the package complete.
- [ ] The summary line reports the number of assertions passed and failed and `gates: []`.
- [ ] The run ends its transcript with the path of its log and the BLAKE3 digest of its summary line, which is what a
      milestone exit review cites (the citation is the exit review's own criterion, BD-044 at M0 and each later review;
      this bead does not wait for them).

## Test plan

### Unit tests

The script's own logic is thin; its two helpers are tested in `scripts/lib/tests/wp_e2e_test.sh`:
`report_row_format` (one package with two parts and three children gives the expected report line) and
`complete_requires_gate_record` (a package with all children closed and one key gate at `not run` is `incomplete`).

### End-to-end script and logging

This bead is the script: `scripts/e2e/wp_table.sh`, with the steps and the log format above.

### Known answers and negative controls

Known answers: on the fixture that encodes the drafted table, 80 packages, 139 edges and 125 after reduction, no
cycle; first-milestone counts 10, 15, 18, 14, 8, 5, 4, 2, 3. Negative controls run by the script's self-test mode
(`--self-test`, on scratch copies, never on the real export): the stale generated file; the bead under an unknown
package; a package marked complete with a gate at `not run`; an input shuffled line by line, which must change
nothing. Determinism lanes: twice on one machine (step 3); on the Mac and on the Linux host the digests of the
generated files are equal, which the exit review compares from the two logs.

## Considerations

- The script measures no gate and must not be cited as one; it is cited as the source of a package's completeness.
- It is cheap by construction (a few hundred lines of JSON, no build), so it fits the default machine envelope with a
  wide margin and runs under the shared timeout of the helper.
- If the tracker's export is empty or absent the script fails at step 1 with a clear message, not with zero packages.
- Hygiene: if no exit review cites this log by the M1 exit, the script and both tools behind it are deleted.
