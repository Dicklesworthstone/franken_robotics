## Background

**The row.** WP-02: Airlock and referee smoke; one asupersync version across the consumed siblings (upstream work item
FD-ASUP-01). Crates: `frob-fsim`; upstream in frankensim, frankentorch and fastmcp_rust. Milestone: M0. Key gates:
INT-FSIM-01, INT-ASUP-01, INT-FSQL-01. Waits for: WP-01.

This package answers by measurement the first question the architecture rests on (BET-04): can the foundations be
consumed from outside their trees. It delivers `frob-fsim` v0, the airlock: the only crate allowed to name types from
FrankenSim's volatile crates, here with `RefereeDynamics` over `fs_mbd::articulated`. It reproduces the digest of a G1
forward-dynamics state at the pinned commit, opens the Chronicle ledger on FrankenSQLite and recovers it after a
forced kill mid-write, and runs the first verb end to end: `frob sim run g1 --tier referee --seconds 2` produces a
state digest equal to the one FrankenSim computes for itself, with T0 telemetry in the ledger. It also carries one of
the two P0 upstream work items, FD-ASUP-01, which makes the whole stack resolve to one asupersync package.

It is one unit of work because the airlock, its first use and the alignment of the async runtime are one question:
does the stack resolve to one dependency graph and reproduce a digest. None of the three is evidence without the
others.

**Order.** It waits for WP-01, which provides the workspace, the stack lock and `check-stack`; INT-ASUP-01 is wired
into that check. (The order between packages is recorded in `related`, never in `deps`: a blocked epic would block
every child, so the child beads carry the real dependencies.)

has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **KILL-FSIM** (decided M0, then rolling). Trigger: INT-FSIM-01 cannot pass within two weeks of M0 effort, or its
  cold check exceeds the machine envelope, or upstream breakage exceeds 20% of working days in any four-week window
  (BET-04). Fallback, named in advance: (a) One pinned FrankenSim worker process per device exchanging whole jobs
  through the airlock traits. (b) Only if (a) fails INT-FSIM-18 or the pin can no longer be built: lift the minimal
  referee set with provenance headers and golden tests, and state lift-only.
- **FrankenSim's API still moves daily**, which is why the airlock stays even after admission. Pins advance by a
  compatibility train; a sibling's newer clean head is never rolled back locally; `xtask check-stack` runs before any
  build failure is attributed to this repository.
- **The closure is not Franken-only.** Path consumption brings FrankenSim's transitive closure, third-party crates
  included (FACT: 262 registry packages among the 479 in `frankensim/Cargo.lock`). 'Franken-only' describes direct
  edges.
- **Stop decision of M0.** If INT-FSIM-01 cannot pass within two weeks and the worker process also fails INT-FSIM-18,
  the program re-plans before M1: the only route left is a lift from a closure of about 1.5 million lines (FACT).
- OPEN-SUITE-3 (a dirty asupersync checkout between receipts: allowed for development with the tree hash in the
  receipt, and no gate records a pass) and OPEN-SUITE-5 (the cold-build budget: the machine envelope) take their
  defaults until the owner answers.
