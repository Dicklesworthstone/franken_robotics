## Background

**The row.** WP-06: Verb registry and surfaces; fastmcp_rust brought onto T (upstream work item FD-FMCP-01), with
`frob-mcp` in the core graph running verbs in process. Crates: `frob-verbs`, `frob-cli`, `surface/frob-mcp`; upstream
in fastmcp_rust. Milestone: M0, M1. Key gates: INT-FMCP-01; GATE-TETHER-02, -03, -07. Waits for: WP-01.

Every capability of the system is reached through a verb, and both agent surfaces are generated from one registry,
`registries/verbs.toml`: the command line `frob --json` and the MCP server `frob-mcp`, which is built on fastmcp_rust
as an ordinary member of the core workspace, links `frob-verbs` and runs verbs in process. The package delivers
`frob-verbs` v0 and the `frob` skeleton (the registry loader, the envelope with the claim product and the flags, exit
codes including 8 for 'accepted and still running', `doctor`), the admission of fastmcp_rust with its upstream item,
the M1 verbs with schemas, examples and refusal lists, and the MCP tools generated for them in task clusters of at
most seven with `session.open`, `session.show`, `session.focus` and `session.close`.

It is one unit of work because the two surfaces must have an empty parity diff, and that holds only when one package
generates both from one registry.

**Order.** It waits for WP-01: the workspace, and T, on which fastmcp_rust must build before `frob-mcp` can be a
member of the core graph. (The order between packages is recorded in `related`, never in `deps`: a blocked epic would
block every child, so the child beads carry the real dependencies.)

## Scope

Crates and other units, with layer, tier of contents, scope cap (thousands of lines, DESIGN; 115% opens a scope
review) and role:

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **KILL-MCP** (decided M0; re-read at M1 with the M1 verbs). Trigger: INT-FMCP-01 cannot pass within the M0 budget
  after FD-FMCP-01 and FD-ASUP-01 have been attempted. Fallback, named in advance: Fallback 1: `frob-mcp` as its own
  workspace, talking to `frobd` over a local socket in newline-delimited JSON. Fallback 2: agents use the CLI, which
  is complete on its own (§33.13, §40.7).
- **Integers above 2⁵³** travel as strings; the schema lint finds no bare 64-bit integer, and a double-decoding client
  must not change any value of the golden envelope set.
- **No naked numbers.** Every output that crosses the agent boundary carries the claim product (kind of claim,
  evidence class set by the weakest input, tier, determinism class, model identity, seed) and the no-authorization
  flags.
- KILL-MCP is first read at M0 and re-read at M1 with the M1 verbs. Neither fallback changes a verb, a schema or an
  exit code.
