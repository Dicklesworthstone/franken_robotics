## Background

**The row.** WP-07: Design language and compiler. Crates: `frob-design`, `frob-model`. Milestone: M1. Key gates:
GATE-SKEL-02, -03, -05, -08. Waits for: WP-03.

A design is a content-addressed term, and a model is what a functor makes of it. `frob-design` delivers the term model
with schema `frob.design/1`, the seven canonical-form rules and `DesignId`; the `.fbot` fields (fills with shell
thickness and no default fill, budgets, levers, locks, the power bus, sensors, payloads, symmetry assertions); the
constructors `attach`, `chain`, `serial`, `mirror`, `radial`, `scale`, `replace` and `closure`; the S-expression view;
typed edits with preconditions, inverses and declared symmetry effects; design patches with an expected parent, an
idempotency key and schema migration; the lineage graph over patches with `design.diff` and `design.blame`; and lints
whose ranked repairs are typed edits. `frob-model` delivers the kinematic functor, `RobotModel` and the referee
lowering, the geometry and inertia functor (regions, materials, the fill rule with shell moments as a difference of
solids, primitive fitting with recorded error), and memoized incremental compilation that returns the invalidation set
of an edit.

It is one unit of work because the functor laws can only be tested with both halves present, and because the identity
of a design must be fixed before anything is keyed by it.

**Order.** It waits for WP-03: models are built from Lie-group joint maps and frame-typed quantities. (The order
between packages is recorded in `related`, never in `deps`: a blocked epic would block every child, so the child beads
carry the real dependencies.)

(WP-09); the packed lowering for batched tiers (WP-15); lineage bisect and merge (WP-28).

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **KILL-SKEL-SEXPR** (decided M1). Trigger: INV-SKEL-04 cannot be held after one repair cycle. Fallback, named in
  advance: The S-expression view is removed; JSON is the only syntax.
- **Identity through foreign clients.** A JavaScript client's round trip of every wide integer and hash must match the
  native decoder (GATE-SKEL-05).
- **Schema migration** must leave forward kinematics and mass properties bit-identical and old runs replayable
  (GATE-SKEL-08); a stale parent refuses, and a repeated idempotency key returns the same `DesignId`.
- `serde` and `serde_json` are allowed here only as boundary dependencies at exact pins, never in a hot path.
