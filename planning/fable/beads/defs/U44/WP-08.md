## Background

**The row.** WP-08: Import and export. Crates: `frob-io`. Milestone: M1. Key gates: GATE-SKEL-01. Waits for: WP-07.

Reference robots arrive as URDF and MJCF files, and designs leave the same way. `frob-io` delivers the in-house XML
reader, URDF import and MJCF import each with a loss report, and URDF and MJCF export with the reverse loss report. A
loss report lists every field the conversion dropped, and it is checked by a field-coverage diff, so an importer
cannot be silently lossy.

It is one unit of work because an importer is only honest together with its loss report and its parity test against
the oracle: forward kinematics of each reference robot within 10⁻⁹ m and 10⁻⁹ rad over 10⁴ configurations.

**Order.** It waits for WP-07: an import produces a design term and an export consumes one. (The order between
packages is recorded in `related`, never in `deps`: a blocked epic would block every child, so the child beads carry
the real dependencies.)

## Technical approach

An epic implements nothing: it contains its child beads, which name it in `parent`, and it is where the package's
acceptance is read. Each bead has one package (the owner of its crate at its milestone, or of the crate where its gate
is measured); exit reviews have none.

Seed beads (the table of contents, assigned by crate, title and gate):

**Frontier and Moonshot content, and the pilot that must be on record first.** None. Every mechanism of this package

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **RISK-13**: reference robot imports hide lossy contact mappings. Trigger: fields missing from a loss report in the
  field-coverage diff. Mitigation: the loss reports of GATE-SKEL-01, and the imported contact law labelled
  parity-only.
- Imported files are untrusted input: size and depth limits are enforced before parsing, and the reader is in-house so
  that no third-party XML library enters the core graph.
