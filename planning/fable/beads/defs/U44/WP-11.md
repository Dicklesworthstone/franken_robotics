## Background

**The row.** WP-11: Static analyses I. Crates: `frob-analyze`. Milestone: M1. Key gates: GATE-ATEL-02. Waits for:
WP-07, WP-09.

Static analyses decide things about a design without simulating it, which is the cheapest rung of the whole program
(BET-05). The package delivers A-01 mobility, A-02 mass roll-up, A-03 symmetry (the groups Γ_mech and Γ_obs with their
breakers and near-symmetry repairs), A-05 workspace and A-06 singularities with the derived leg inverse-kinematics
kernel, A-07 growth vector and maneuverability, A-08 static stability, A-10 co-design closure and A-11 actuator
envelope with the temperature-dependent steady state, A-12 modes with symmetry block-diagonalization, A-13
self-collision and clearance, A-17 observability as the linearized Gramian modulo gauge, and A-20 to A-23
(energy-budget feasibility, deadline and latency closure, sampled-loop stability, the shared-bus schedule). Each is a
verb and an input to `design check`.

It is one unit of work because the analyses share one crate, one known-answer gate and one latency budget: `design
check` finishes in under 2 s at the 95th percentile on templates.

**Order.** It waits for WP-07 (the compiled model) and WP-09 (the actuator envelope, the thermal steady state and the
bus). (The order between packages is recorded in `related`, never in `deps`: a blocked epic would block every child,
so the child beads carry the real dependencies.)

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

- **Envelope.** The plan's envelope table registers no request for this package, and its M1 analyses fit the default
  E0 (16 GiB, 8 cores, one hour, one device). One request is reserved: row R19 of the envelope register (N44-01),
  filed by the KILL-ATLAS pilot (N28a-14) before its first run above E0, for its 48 specialist fine-tunings (24

  decision N28a-15 takes its fail-closed branch: A-26 ships as a descriptive report with no validity label. A run
  above the class in force is refused before it starts (`FROB-REF-761`).

  descriptive report with no validity label. The gate is measured by the pilot N28a-14 and decided by N28a-15, which
  sit directly under EPIC-M4 with no package of their own; this package carries A-26 and the gate.
- **BET-05 is not decided here.** Whether static analysis predicts failure well enough to prune is measured on the
  design corpus at M3 (GATE-ATEL-01, KILL-STATIC, in WP-25). If it fails, `design check` verdicts become advisory
  lints; the analyses themselves stay.
- INT-FSIM-10, measured by the bead that carries A-09, A-14 and A-16 wherever it is parented, admits `fs-symmetry` and
  `fs-ad` with a recorded scope: cyclic groups only, and no contact-event derivatives.
