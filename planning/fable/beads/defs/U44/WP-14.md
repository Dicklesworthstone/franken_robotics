## Background

**The row.** WP-14: Gauntlet harness and oracles. Crates: `frob-conformance`, `tools/oracle`. Milestone: M1. Key
gates: GATE-GAUNT-01. Waits for: WP-02.

The Gauntlet is the verification program, and its one rule is that a gate which nothing can fail validates nothing.
The package delivers the harness with its tiers G0 to G5 and the negative-control registry, the oracle capture scripts
and the reference-robot fixtures with pin and date, the known answers of M1 against pinned oracles, the seeds of the
counterexample catalogue, and the `smoke` and `fixtures` batteries. It then carries the conformance content each later
milestone adds: the `standard` battery wiring, the metamorphic relations and the chaos tests on devices (M2); the
`hard` and `covering` batteries, the planted-defect registries of Nemesis and Autopsy and the hostile-input corpora
(M3); the calibration sets, the frozen 30-amendment campaign and the seeded cascade population (M4); the certificate
mutation corpora, the synthetic rehearsal and the structure fixtures (M5).

It is one unit of work because one registry enforces the rule for every gate of every package: a gate registered
without a negative control fails the registry check.

**Order.** It waits for WP-02: the referee reached through the airlock is the first oracle, and the reference
integrators and optimizers used as cross-checks are pinned with FrankenSim. (The order between packages is recorded in
`related`, never in `deps`: a blocked epic would block every child, so the child beads carry the real dependencies.)

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
