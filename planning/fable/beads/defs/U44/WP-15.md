## Background

**The row.** WP-15: Kernel library and batched step. Crates: `frob-kernels`, `frob-dyn`. Milestone: M2. Key gates:
GATE-KIN-03, -05, -07. Waits for: WP-05, WP-07, WP-09.

M2 puts a batch under the studio, and this package is the batch on the CPU. It delivers the packed lowering of
`RobotModel` (depth levels, path tables, capacities, `ShapeClassId`), the derived and emitted kernels `K-fk-level`,
`K-twist-level`, `K-crba-level` and `K-rnea-level`, the utility kernels `K-scan`, `K-sort`, `K-reduce`, `K-seg-reduce`
and `K-compact`, the articulated `K-cay-step`, `K-normalize` and `K-anchor`, the batched step on `batch-cpu` in `f64`
and `f32` with lockstep masks and capacity flags, the tile program on `fs-exec` with fixed-slot reductions, and the
`strict` profile: the transactional, event-located step in `f64` on our own kernels. It also measures the derivation
toolchain against its kill gate.

It is one unit of work because a kernel library exists only to be stepped, and `batch-cpu` is the CPU reference path
that every device claim must be differentially checked against.

**Order.** It waits for WP-05 (the derivation toolchain that emits the arithmetic), WP-07 (the `RobotModel` being
lowered) and WP-09 (the actuator models whose kernels join the step). (The order between packages is recorded in
`related`, never in `deps`: a blocked epic would block every child, so the child beads carry the real dependencies.)

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **KILL-KIR** (decided M2). Trigger: At M2 the derivation toolchain cannot express or emit more than 20% of the
  kernel arithmetic, or emitted kernels miss BET-01's speed bound after one optimization pass. Fallback, named in
  advance: Arithmetic is hand-written in Rust and the dialect and bound by differential tests; certificates fall back
  per KILL-LEMMA.
- **Kill gates from later subsections, decided inside this package.** KILL-ROWQUEUE (row-class solve queues),
  KILL-LOOPELIM (closed-form elimination of planar closures) and KILL-ANCESTOR (the ancestor-sparse solve path for 18
  to 60 coordinates), each decided at M2 from its pilot and each falling back to the dense path of this package.
- **The no-GPU variant of M2.** If no device family is admitted or holds a controlled class, everything of M2 lands on
  `batch-cpu`, on the 36 cores of the M5 Ultra and the CPU of `trj`; this package is then the engine.
- **Two planes.** Kernels and the step never depend on a dispatcher, a memo policy, an estimator or a scheduler; no
  crate of layers 1 to 3 holds one.
- `Degraded` world-steps must stay at or below 10⁻⁴ of world-steps per class on the standard battery, every forced
  overflow is flagged, and capacities are printed in every disclosure block.
