## Background

**The row.** WP-20: Sensors I. Crates: `frob-sense`. Milestone: M2. Key gates: GATE-SENS-01, -02, -03. Waits for:
WP-16.

A policy sees the world only through sensors, so sensors must be as reproducible as the step. The package delivers the
ray kernels, height scan, depth and lidar, proprioception with noise on the batched tiers, the noninterference test,
and the causal-policy test on every tier.

It is one unit of work because the three gates read one property from three sides: outputs are right against analytic
scenes, they agree across back ends inside the determinism class, and adding, removing or reordering sensors does not
change what the others read.

**Order.** It waits for WP-16: sensors read the collision field, the overlays and the optical map, never the visual
mesh, so rays need the batched narrow phase and the scene fields behind it. (The order between packages is recorded in
`related`, never in `deps`: a blocked epic would block every child, so the child beads carry the real dependencies.)

## Technical approach

An epic implements nothing: it contains its child beads, which name it in `parent`, and it is where the package's
acceptance is read. Each bead has one package (the owner of its crate at its milestone, or of the crate where its gate
is measured); exit reviews have none.

Seed beads (the table of contents, assigned by crate, title and gate; a seed's own `parent` governs where it differs,
and N44-03 regenerates this list from the graph):
- M2: BD-187 Ray kernels; height scan, depth, lidar; proprioception with noise on batched tiers; BD-215 The
  noninterference test, and the causal-policy test on every tier
- Beads drafted from the chapters for what no seed covers (`N<chapter>-<nn>`: mechanism parts, registries, end-to-end
  tests, pilots, kill-gate decisions) attach through their own `parent` field.

**Frontier and Moonshot content, and the pilot that must be on record first.** None. Every mechanism of this package
is Solid.

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- The draw-order control must fail: a sensor whose noise depends on the order of draws breaks noninterference, which
  is why noise is drawn by address.
- Depth is accepted within 1 mm plus the brick bound, so the scene's interpolation bound is part of every sensor
  tolerance.
