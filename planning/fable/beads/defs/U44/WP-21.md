## Background

**The row.** WP-21: Cortex I: `VecEnv` and PPO on device. Crates: `frob-learn`. Milestone: M2. Key gates:
GATE-CORTEX-01, -02, -05. Waits for: WP-18, WP-19, WP-20.

Learning is only as fast as the path from a step to a gradient, so the learner sits on the device beside the
environment. The package delivers on-device networks and the optimizer (`K-gemm`, `K-act-fn`, `K-adam`) with backward
kernels in parity with FrankenTorch's autograd, PPO training of the reference quadruped's flat velocity task to a
return threshold on `batch-cpu` and on each GPU backend (`train.start`, `train.status`, `train.stop`, `train.export`),
the settled-pose reset cache, randomization from cards drawn by address, and the measurement of training time on one
RTX 4090 against an incumbent re-measured on the same card.

It is one unit of work because the gate is a trained policy, and nothing short of the whole loop produces one: a
zero-weight policy and a random policy must both fail the threshold, and the exported checkpoint reloaded on
`batch-cpu` must reproduce the return with a non-zero policy head.

**Order.** It waits for WP-18 and WP-19 (the device backends the learner runs on) and WP-20 (the observations a policy
reads). (The order between packages is recorded in `related`, never in `deps`: a blocked epic would block every child,
so the child beads carry the real dependencies.)

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** The package needs more than the default machine envelope E0 (16 GiB, 8 cores, one hour, one device).
  Request R2 of the envelope register (shared with WP-48): Training to threshold on two cards; the scaling rows. Class
  asked: E1. If not approved: One card; GATE-SPARK-20 is recorded `not run`. Nothing above E0 starts before the
  owner's written approval is recorded on row R2 of `registries/compute_envelope.toml` (N44-01); a job above the
  class in force is refused before it starts (`FROB-REF-761`). The one-card form is the not-approved fallback and is
  admitted under E0.
- **KILL-LEARNKERN** (decided M2). Trigger: GATE-CORTEX-02 fails after one repair cycle, or GATE-CORTEX-05 is missed
  by more than two times after one optimization pass. Fallback, named in advance: The forward pass stays on the
  device; rollout storage is read back once per rollout and the learner runs on FrankenTorch on the CPU, with the lost
  throughput disclosed.
- **Training-time parity is parity, not advantage.** The TARGET is at most 1.25 times an incumbent's wall-clock for
  the comparable task (published context: about 410 s), under the disclosure block.
- **FrankenSim's own PPO update is not a baseline.** It fails three probes at the pin (the clip branch for negative
  advantage, the critic gradient from the current output, episode boundaries in packed sequences). PPO is written here
  and passes the same probes first; the sibling's file may serve as a comparison only after the upstream item
  FD-FSIM-10 lands and INT-FSIM-06 passes.
- A result trained under the nondeterministic `fast-training` profile (class D4) may not be cited as evidence; the
  policy must be re-evaluated under class D2 (licences of WP-58).
