## Background

**The row.** WP-22: Trust ladder and replay. Crates: `frob-dyn`, `frob-chronicle`. Milestone: M2. Key gates:
GATE-FID-01; GATE-CHRON-01, -02; GATE-SPARK-05. Waits for: WP-13, WP-16.

A fast tier is trusted only as far as two things allow: its measured disagreement with the referee on a frozen
battery, and the ability to replay any world exactly and to move it to another tier to see where it diverges. The
package delivers the standard battery, frozen, and the fidelity ledger with its frozen envelopes (`fidelity.ledger`);
in-kernel digests (`K-x-digest`), per-stage digests and snapshots at the commit fence (`K-commit`, `K-snapshot`) with
replay (`sim.replay`); teleport with step and stage localization (`sim.replay --tier`); and anchored positions (cell
side 8 m, offset in [−4, 4) m) with the precision battery and the conditioning certificate, which is how single
precision is made safe far from the origin (BET-08).

It is one unit of work because fidelity is a statement about identified worlds: a disagreement means something only if
the world can be replayed with identical digests and teleported to the tier that localizes it.

**Order.** It waits for WP-13 (the ledger and episode files that replay reads) and WP-16 (batched contact, without
which the M2 battery has no fast-tier side). (The order between packages is recorded in `related`, never in `deps`: a
blocked epic would block every child, so the child beads carry the real dependencies.)

## Technical approach

An epic implements nothing: it contains its child beads, which name it in `parent`, and it is where the package's
acceptance is read. Each bead has one package (the owner of its crate at its milestone, or of the crate where its gate
is measured); exit reviews have none.

Seed beads (the table of contents, assigned by crate, title and gate; a seed's own `parent` governs where it differs,
and N44-03 regenerates this list from the graph):

  In-kernel digests (`K-x-digest`), per-stage digests, snapshots at the fence …; BD-204 Teleport with step and stage

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **GATE-FID-01 is re-baselined once** at M2 with a written rationale and then frozen. A later change of the envelopes
  needs an ADR; the upstream items that replace an interim posture in the contact step (FD-FSIM-02, FD-FSIM-12) each
  allow one further re-baseline at switch-over.
- **KILL-CONTACT** (carried by WP-16) is triggered by this package's gate: GATE-FID-01 failing on slip or creep after
  parameter mapping and one repair cycle.
- **KILL-D1** (WP-46) changes what replay means: for a device family that cannot hold bit equality with `batch-cpu`, a
  teleported world is a tolerance replay and cross-family comparisons are unpaired.
- BET-08 (single precision is adequate on the GPU, given anchored coordinates, group-preserving updates, diagonal
  scaling and guarded comparisons with an exact fallback) has no kill gate. It is falsified if the precision battery
  fails at long horizons; its comparison arm is `batch-cpu` in double precision on the same worlds; half precision is
  never used, and a request for it is refused (`FROB-REF-245`).
