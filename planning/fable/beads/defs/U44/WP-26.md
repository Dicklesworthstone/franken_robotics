## Background

**The row.** WP-26: Tether, full: slot dispatch, capabilities, the full MCP surface. Crates: `frob-cli`, `frob-verbs`,
`surface/frob-mcp`. Milestone: M3. Key gates: GATE-TETHER-01, -09 to -12. Waits for: WP-06, WP-25.

Many agents must share one machine without any of them changing another's result. The package delivers the daemon
`frobd` with persistent environments and slot-level episode dispatch; size classes (`interactive`, `batch`,
`campaign`), shortest estimated work and preempt-resume with the DC-09 table; estimates and budgets with calibrated
intervals per stratum; the full MCP surface in seventeen task clusters with the bounded synchronous wait, progress and
cancellation, resources and prompts; the three failure classes exercised on both surfaces; `robot-docs`, the skill
file and two worked sessions with the fresh-agent test; and the verb sets of M3, M4 and M5 with schemas, examples and
refusal lists.

It is one unit of work because its acceptance is an agent, not a function: a fresh agent given only `robot-docs`
completes 20 scripted studio tasks with at least 18 correct and no budget violation, which needs the daemon, the
surface and the documentation at once.

**Order.** It waits for WP-06 (the registry and both surfaces) and WP-25 (the studio verbs a fresh agent is asked to
use: compare, promote, explain, the reports). (The order between packages is recorded in `related`, never in `deps`: a
blocked epic would block every child, so the child beads carry the real dependencies.)

Crates and other units, with layer, tier of contents, scope cap (thousands of lines, DESIGN; 115% opens a scope
review) and role:
- `frob-cli` (layer 7; Solid; cap 8): The `frob` and `frobd` binaries.

- **M3.** The daemon, the scheduler, estimates, the full MCP surface, `robot-docs` and the M3 verbs; GATE-TETHER-01,

Out of scope: capability scopes, session budgets and the path jail, which are carried with the safety package (WP-58);
the job protocol, idempotency and pagination (WP-43); the dashboard and the viewer (WP-52); `solve.run` and the

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **KILL-SLOT** (decided M3). Trigger: Any digest difference under co-tenancy, or GATE-TETHER-09's throughput or
  step-time limits fail after one optimization pass. Fallback, named in advance: `frobd --dispatch=per-job`: one
  environment per job, queued.
- **KILL-PREEMPT** (decided M3). Trigger: A resumed job's digest differs, or measured resume cost exceeds the quantum.
  Fallback, named in advance: Run to completion with the slot reserve only.
- **KILL-MCPTASKS** (decided M3). Trigger: The pilot of §32.12.6 fails, or the protocol extension changes
  incompatibly. Fallback, named in advance: Job handles only.
- **Slot dispatch is rolled out in shadow first**: on `batch-cpu` each job runs both ways and digests are compared;
  the rollback is `frobd --dispatch=per-job`.
- **The `campaign` size class is above the machine envelope.** Size classes come from the system's own estimate,
  never from the agent. A job above the compute envelope in force is refused at estimation and at submission, on
  every surface, with `FROB-REF-761` (N36-20), so it never reaches the queue; the scheduler sizes each queued job
  again at dispatch and refuses with `FROB-REF-704` a `campaign`-class job whose scope has no approved request row at
  that moment (the approval expired or was withdrawn while it waited). Both are exit code 4. The approvals are rows
  of `registries/compute_envelope.toml` (N21c-35, N44-01).
- **The engine back end** (N32ax-02, M4) exists only on the branch where KILL-TENFOLD-TIE fires: an incumbent engine
  behind the same verbs, with no change to a verb, a schema or an exit code.
- A stratum with fewer than 19 points reports `uncalibrated` instead of an interval (GATE-TETHER-11).
