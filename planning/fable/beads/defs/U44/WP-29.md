## Background

**The row.** WP-29: Symmetry: equivariant policies and symmetric controllers [S], [F]. Crates: `frob-algebra`,
`frob-analyze`, `frob-learn`. Milestone: M4. Key gates: GATE-CORTEX-03; GATE-MARROW-04; GATE-REFLEX-07. Waits for:
WP-11, WP-21.

A robot's symmetry is a fact about its body and its sensors, and it can be spent twice: to shrink a policy network and
to constrain a controller. The package delivers equivariant linear maps by irreducible blocks under the
observation-preserving group Γ_obs, the three-arm equivariance experiment (equivariant, augmented, unaugmented), and
symmetric controllers under stabilizer intersection (`control.symmetry`).

It is one unit of work because all three consume one object, the symmetry group computed by analysis A-03, and are
defeated by the same error: treating a mechanical symmetry as usable when a sensor, a payload or the terrain breaks
it. The planted asymmetries (side slope, off-centre payload, front-only sensor, one-sided patch) must remove exactly
the expected generators.

**Order.** It waits for WP-11 (the symmetry analysis that supplies Γ_mech and Γ_obs) and WP-21 (PPO on device, which
the three-arm experiment trains with). (The order between packages is recorded in `related`, never in `deps`: a
blocked epic would block every child, so the child beads carry the real dependencies.)

## Technical approach

An epic implements nothing: it contains its child beads, which name it in `parent`, and it is where the package's
acceptance is read. Each bead has one package (the owner of its crate at its milestone, or of the crate where its gate
is measured); exit reviews have none.

Seed beads (the table of contents, assigned by crate, title and gate; a seed's own `parent` governs where it differs,
and N44-03 regenerates this list from the graph):

  BD-327 Symmetric controllers under stabilizer intersection (`control.symmetry`)
- Beads drafted from the chapters for what no seed covers (`N<chapter>-<nn>`: mechanism parts, registries, end-to-end
  tests, pilots, kill-gate decisions) attach through their own `parent` field.

**Frontier and Moonshot content, and the pilot that must be on record first.** Solid: the block decomposition and its

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **KILL-EQUIV** (decided M4). Trigger: GATE-CORTEX-03 fails (BET-07). Fallback, named in advance: Symmetry is used
  for augmentation and metamorphic testing only.
- **KILL-MARROW-BLOCKS** (decided M4). Trigger: GATE-MARROW-04 fails after one repair cycle, or exact field arithmetic
  for n ≤ 12 exceeds its bit budget. Fallback, named in advance: Equivariant layers by Reynolds projection in `f64`
  with an idempotence test, classed `Tested`; the free-parameter count is read from the projection's rank.
- The comparison with the augmented arm is reported whichever arm wins: the gate asks only that the equivariant arm
  reach the return in at most 0.7 times the steps of the unaugmented arm with no loss of final return.
- If both kill gates fire, symmetry remains in use for augmentation and for metamorphic testing, which the
  verification program needs in any case.
