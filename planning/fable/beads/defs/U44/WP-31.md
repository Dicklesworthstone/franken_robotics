## Background

**The row.** WP-31: Lemma: certificate coverage and Lean capsules [F]. Crates: `frob-lemma`, `lean/`,
`derive/frob-derive`. Milestone: M5. Key gates: INT-FLN-01, -02; GATE-LEMMA-01, -02; GATE-QUAL-03. Waits for: WP-05,
WP-15.

M5 strengthens what can be trusted. The package delivers certificate coverage for derived kernels (a replayable
instance certificate for each identity a kernel's manifest declares), the Lean project and the admission of the
independent checker, Lean theorem cards as sealed capsules (proof kind `lean-capsule`) that verify from an empty
environment, and replay of a qualification campaign by `frob-verify`.

It is one unit of work because coverage is a ratio over the whole kernel library and the capsules are what the ratio's
identities rest on. None of it shortens the time to a decision, so none of it gates the tournament.

**Order.** It waits for WP-05 (the derivation toolchain and `frob-lemma` v0) and WP-15 (the kernel library whose
manifests declare the identities to be covered). (The order between packages is recorded in `related`, never in
`deps`: a blocked epic would block every child, so the child beads carry the real dependencies.)

## Scope

Crates and other units, with layer, tier of contents, scope cap (thousands of lines, DESIGN; 115% opens a scope

  exact-synthesis subprocess.
- `lean/`: the Lake project of the theorem cards. Its outputs are not committed; capsules are sealed and re-checked by

WP-66); the reflection pilot (WP-72).

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **KILL-LEMMA** (decided M5). Trigger: GATE-LEMMA-01 below 50% after one repair cycle. Fallback, named in advance:
  Certificates become exact-rational randomized identity tests recorded as `Tested`; the word certificate leaves
  kernel manifests.
- **OPEN-LEMMA-5**: whether certificates change any design decision. It is counted in the phase ledger of the ten-fold
  test; if the count is zero by this exit, Lemma work beyond the coverage gate is not funded further before M7 and
  stays off the critical path.
- If the independent checker cannot be admitted, the named fallback is stock Lean alone, recorded as a single-kernel
  check.
- A sealed stratum of the tournament that needs a mechanism of M5 which has not landed is declared `not run` with the
  reason; M5 never blocks M7.
