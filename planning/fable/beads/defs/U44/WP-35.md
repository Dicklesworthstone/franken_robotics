## Background

**The row.** WP-35: Hardware fingerprint; exact and guarded kernels. Crates: `frob-kir`, `frob-kernels`, the Spark
annexes. Milestone: M0. Key gates: GATE-SPARK-07, -08. Waits for: WP-04.

Two M0 measurements are read by everything that follows. The first is what the hardware is: `spark.fingerprint`
records both machines in schema `frob.fingerprint/1`, with every field measured or marked `unavailable` with a reason.
The second is whether a decision can be computed exactly on a device: the exact-integer kernel class and guarded
single precision with an exact fallback (`K-x-pred`, `K-g-pred`) are probed on the docking-boundary screen of 65,536
rows, and must give identical bytes on `batch-cpu`, both RTX 4090 and Metal. At M1 the classes become first-class in
`frob-kir`: predicate typing, the select lint and derived error bounds.

It is one unit of work because both are properties of a device family established before any physics runs on it, and
because exact decisions on devices are what later lets mission queries over design families run on GPUs with zero
final errors against exact CPU arithmetic.

**Order.** It waits for WP-04: the annexes at version 0 and the IEEE probe, whose outcome bounds what a guarded kernel
may assume. (The order between packages is recorded in `related`, never in `deps`: a blocked epic would block every
child, so the child beads carry the real dependencies.)

## Scope

Crates and other units, with layer, tier of contents, scope cap (thousands of lines, DESIGN; 115% opens a scope
review) and role:
- `frob-kir` (layer 1; Solid, Frontier; cap 14): Straight-line programs with bounded loops and resource metadata,
  dimension checking, differentiation, emitters; the exact-integer kernel class.
- `frob-kernels` (layer 3; Solid; cap 26): The kernel library: manifests, Rust skeletons, generated arithmetic, exact
  and guarded predicates.
- `spark/frob-spark-cuda` (annex workspace; Solid; cap 8): CUDA backend, arena lease, binary kernel cache.
- `spark/frob-spark-metal` (annex workspace; Solid; cap 7): Metal backend.

What lands at each milestone:
- **M0.** The fingerprint of both machines; the exact and guarded kernel probe; GATE-SPARK-07 (recorded by N21c-06)
  and -08. The cross-host script N21b-40 is the recorder of GATE-SPARK-08 (measured by BD-030) and also of
  GATE-SPARK-01, the IEEE probe that is a key gate of WP-04 and is measured there by BD-017.
- **M1.** Two beads: exact predicates and guarded single precision as kernel classes in `frob-kir` (BD-053), and the
  exact-integer math mode they are written in (N21a-17: wrapping `u32` operators, masked shifts, `mulhi`, bit views
  and their emitters).

Out of scope: guarded predicates over the contact battery on devices and the decision KILL-MARROW-GUARD (WP-46); the
docking fixture in exact arithmetic on every backend (WP-49); family queries on the GPU (WP-66).

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** The plan's envelope table registers no request for this package; one request beyond that table is
  written by N44-01 as row R11 of `registries/compute_envelope.toml`: the two-card fingerprint and the peer experiment
  of GATE-SPARK-07 on `trj` (N21c-03, N21c-06), class E1 for `gate:GATE-SPARK-07`. If not approved: under the default
  E0 (16 GiB, 8 cores, one hour, one device) the fingerprint runs as two one-device jobs (`--device cuda:0`, then
  `--device cuda:1`) merged into one host record, and the `peer` block reads `untested` with the envelope reason,
  which is a complete answer for the gate. On the Mac (one device) E0 suffices. The class in force is written into
  the host receipt. A run above it is refused before it starts (`FROB-REF-761`).
- A fingerprint must be repeatable: two runs agree on every discrete field and within 5% on every rate, and it
  reproduces the starting values the performance arithmetic assumed.
- The guarded kernel's fallback fraction is reported, because a guard that almost always falls back is exact and
  useless; the later threshold is a fallback rate below 10⁻³ of evaluations on the contact battery.
