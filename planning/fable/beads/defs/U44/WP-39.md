## Background

**The row.** WP-39: Transactional referee step. Crates: `frob-dyn`, `frob-contact`, `frob-fsim`. Milestone: M1. Key
gates: GATE-KIN-04; GATE-TRAC-06. Waits for: WP-10.

On the referee a step is a transaction: it commits at a fence or it restores all state, and no reader ever sees an
uncommitted value. The package delivers the restore set and the commit fence with `commit_epoch`, event location on
rational base intervals with coupled impulses per island, the retry ladder that changes numerical parameters only
together with the refinement law for random inputs, witness migration across an edge, and the thin-barrier and sill
fixtures under the transactional step.

It is one unit of work because the four mechanisms defend one property and are tested by the same injected faults: a
retried step must give equal digests, must not redraw its random inputs, and must not miss a thin barrier that lies
between two clear endpoint poses.

**Order.** It waits for WP-10: the transaction wraps the referee step. (The order between packages is recorded in
`related`, never in `deps`: a blocked epic would block every child, so the child beads carry the real dependencies.)

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).

The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **OPEN-KIN-5**: the limits of the transactional step. Defaults (DESIGN): L_max = 16 levels of dyadic subdivision of
  a base interval (at a 2 ms base interval that resolves 31 ns), E_max = 64 events inside one base interval, and a
  retry budget of 3; exceeding a limit refuses with `FROB-REF-220`. They are decided by the refusal rate on the
  standard battery at M1.
- **Stop decision of M1**: the referee is re-planned if its refusal rate on the M1 fixtures leaves the sill fixture
  without a completed run.
- Witness migration is done above the airlock as the interim posture of an upstream item (FD-FSIM-12, a moving-surface
  owner for the sustained step); at switch-over the fidelity ledger is re-baselined once.
- The redraw mutation (a retry that draws new random inputs) and the endpoint-only mutation (collision checked at the
  end poses only) are the registered negative controls and must both be caught.
