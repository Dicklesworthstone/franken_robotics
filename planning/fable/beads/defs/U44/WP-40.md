## Background

**The row.** WP-40: Clock contract. Crates: `frob-sense`. Milestone: M1, M2. Key gates: GATE-SENS-04, -05. Waits for:
WP-10.

When a sensor sample is taken, sent, delayed and delivered decides what a controller can know, and a schedule kept in
floating point drifts. The package delivers the clock contract (rational periods, phase accumulators, the seven
instants and the boundary ordering rule; `sense.schedule`), packet queues and delivered observations with the queues
inside every checkpoint, proprioception on the referee (the IMU with its lever arm, encoders, sensor cards;
`sense.profile`), the causal-policy test (`sense.causal-test`), and the same contract and checkpointed queues on every
tier.

It is one unit of work because the contract is tested as one object at the instants where it is easiest to break: a
restore at three adversarial instants must give byte-equal delivered observations and physics digests over the next
10⁴ ticks.

**Order.** It waits for WP-10: ticks and commit instants are defined by the referee step. (The order between packages
is recorded in `related`, never in `deps`: a blocked epic would block every child, so the child beads carry the real
dependencies.)

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **KILL-SCHED** (decided M2). Trigger: The race check misses a planted race. Fallback, named in advance: The fixed
  total order, with no enumeration.
- The 400/30 schedule must be exact, with zero drift against rational arithmetic over 10⁹ ticks and identical
  schedules on every tier.
- A queue that is not inside the checkpoint makes replay and forks silently wrong: this is why the queues are part of
  every snapshot and why the restore test runs at adversarial instants.
