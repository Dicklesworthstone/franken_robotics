## Background

**The row.** WP-48: Gym semantics, the PPO battery and the two-device update. Crates: `frob-learn`. Milestone: M2. Key
gates: GATE-CORTEX-06, -07, -08, -09. Waits for: WP-21.

A learner can be silently wrong in ways no return curve shows, and each of those ways gets a fixture here. The package
delivers `VecEnv` with the corrected semantics E-1 to E-9 (explicit reset, the preserved final observation,
termination against truncation, typed spaces, access classes, snapshots), device-resident tensor views with the stride
converter and ownership epochs, declarative task specifications with requirement terms, time-aware rewards, physical
discounting and the likelihood of the applied action, PPO under the rules P-1 to P-11, and sharding across both RTX
4090 with multi-device PPO under the global normalization rule.

It is one unit of work because these are the contracts between environment and learner, and they fail together: a lost
final observation, a bootstrap through a true termination, a per-shard normalization or a mis-strided view each
produce a policy that trains and is wrong.

**Order.** It waits for WP-21, the learner on one device. Inside M2 the bead dependencies run both ways (training the
reference task needs the environment semantics), which the regenerated package table shows as parts. (The order
between packages is recorded in `related`, never in `deps`: a blocked epic would block every child, so the child beads
carry the real dependencies.)

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** The package needs more than the default machine envelope E0 (16 GiB, 8 cores, one hour, one device).
  Request (row WP-21, WP-48): Training to threshold on two cards; the scaling rows. Class asked: E1. If not approved:
  One card; GATE-SPARK-20 is recorded `not run`. Nothing above E0 starts before the owner's written approval (N44-01);
  a job above the class in force is refused before it starts (`FROB-REF-761`).
- **KILL-SHARD** (decided M2). Trigger: After one optimization pass the paired lower bound of strong scaling at equal
  task quality is below 1.6. Fallback, named in advance: No further sharding work is funded; the two cards run as
  independent job lanes; the tolerance of 1.25 still applies where synchronous sharding is used.
- Three planted defects that reproduce the sibling's PPO errors must each fail the battery (GATE-CORTEX-07).
- The stride fixture must read element 3, a negative-stride view is materialized or refused, and a stale-epoch read is
  refused (GATE-CORTEX-09).
- Two-shard and one-device updates must agree inside the D3 envelope on 10³ random batches, an empty shard included;
  the scaling figure itself is evaluated by GATE-SPARK-20 (WP-47).
