## Background

**The row.** WP-49: Sensors II and the sensing analyses. Crates: `frob-sense`, `frob-analyze`. Milestone: M2, M3. Key
gates: GATE-SENS-06, -12, -13; GATE-SENS-07 to -11, -14. Waits for: WP-20, WP-40.

Sensors fail in ways that decide missions, and some missions are unsolvable because two worlds look the same. The
package delivers camera timing (exposure integration, rolling shutter, lidar beam instants), the docking fixture in
exact arithmetic on every backend, optical failure modes (mirror, glass, steam, pattern dropout, with a reason on
every masked sample), sensor cards with failure modes and per-field provenance, the empirical observability Gramian on
batched tiers, the alias-witness search over admitted world families (`sense.alias`), Γ_obs per robot and task with
the equivariance test (`sense.symmetry`), and sensor calibration as a least-squares pose graph (`sense.calibrate`).

It is one unit of work because the analyses consume the sensor models directly: an alias witness or an unobservable
direction is only as good as the timing and failure model of the sensor that produced it.

**Order.** It waits for WP-20 (the batched sensor models) and WP-40 (the clock contract that timing is expressed in).
(The order between packages is recorded in `related`, never in `deps`: a blocked epic would block every child, so the
child beads carry the real dependencies.)

(WP-11, WP-42); preflight stage 8, which uses these analyses (WP-38); tactile sensing, event cameras and pixel scenes,
which are M6 items (WP-74).

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **KILL-EXPOSURE** (decided M2). Trigger: Exposure integration costs more than 25% of the ray stage, or changes no
  mask statistic beyond noise. Fallback, named in advance: Midpoint sampling.
- **KILL-ALIAS** (decided M3). Trigger: One false witness from the searched lane. Fallback, named in advance:
  Structural, enumerated and declared witnesses only.
- The docking fixture must give 344, 217 and 9 in exact arithmetic on `batch-cpu`, CUDA and Metal with identical
  bytes; guarded single precision with fallback gives zero final errors; the third-gain amendment reverses every
  admitted cell (GATE-SENS-13).
- Repeated reads through one glass pane must fail together: independent per-sample failure would overstate what
  redundancy buys.
- A calibration is called a least-squares pose graph because that is what it is; no claim from a richer theory is
  attached to it.
