## Background

**The row.** WP-54: Blinded qualification lane. Crates: `frob-arena`, `frob-verbs`. Milestone: M3. Key gates:
GATE-QUAL-01, -02; GATE-SAFE-03; INT-FSIM-14. Waits for: WP-24, WP-26.

An agent that may retry until it passes will pass, so confirmation happens on worlds the agent has never seen, with
requests committed in advance and an error budget that is spent, not reset (BET-21). The package delivers the blinded
lane: sealed world clusters, pre-committed requests, receipts, the error budget α_i = α / [i·(i + 1)] for the i-th
request (`eval.qualify`, `eval.ledger`); the 500-retry gate on no-signal worlds; and the confirmation firewall with
the capability scopes `qual:admin` and `qual:run` and the sealed-field audit.

It is one unit of work because the statistics and the firewall are one guarantee: the error budget holds only if no
verb leaks a sealed field, and the firewall matters only because the budget is finite.

**Order.** It waits for WP-24 (tasks, verdicts and scorecards to qualify against) and WP-26 (the daemon and the
capability machinery of the surface). (The order between packages is recorded in `related`, never in `deps`: a blocked
epic would block every child, so the child beads carry the real dependencies.)

acceptance is read. Each bead has one package (the owner of its crate at its milestone, or of the crate where its gate
is measured); exit reviews have none.

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **BET-21 has no kill gate.** If GATE-QUAL-01 fails, nothing is called qualified and confirmation falls back to
  fixed-n exact studies with a hard cap on submissions before any tournament is scheduled.
- **OPEN-ARENA-3**: who holds `qual:admin`, and the size of the sealed families. Default: the owner alone opens and
  closes campaigns; one sealed family per task family, sized for 20 requests at 256 clusters; nothing is called
  qualified until a family exists.
- The gate's adversary is scripted and sees every receipt and all discovery data: over 2,000 no-signal campaigns at α
  = 0.05 with 500 adaptive retries each, a false promotion may occur in at most 123.
