## Background

**The row.** WP-56: Autopsy. Crates: `frob-autopsy`. Milestone: M3, M4. Key gates: GATE-AUTOPSY-03 to -06, -08. Waits
for: WP-51.

When a design fails, the useful answer is the one factor whose change would have prevented it, and an honest tool says
when there is no such factor (BET-23). The package delivers interventions and the placebo fork (`autopsy.intervene`),
interventional contrasts with flip rates in double precision (`autopsy.attribute`), coalitions and budgeted Shapley
summaries, the decision model for attribution with abstention (decision core DC-06), design parameters re-run from the
episode start (`autopsy.rerun`), time-travel debugging as an agent workflow (`autopsy.repair`, `autopsy.show`), and at
M4 the comparison of agents with Autopsy against agents with logs and `explain` alone.

It is one unit of work because attribution is trusted only with its controls beside it: the placebo fork, the planted
single causes, the chaotic and no-cause failures on which it must name nothing.

**Order.** It waits for WP-51: every intervention is a classified fork from a snapshot. (The order between packages is
recorded in `related`, never in `deps`: a blocked epic would block every child, so the child beads carry the real
dependencies.)

acceptance is read. Each bead has one package (the owner of its crate at its milestone, or of the crate where its gate
is measured); exit reviews have none.

Seed beads (the table of contents, assigned by crate, title and gate; a seed's own `parent` governs where it differs,
and N44-03 regenerates this list from the graph):

None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging

each gate's status, and fails if a gate above has no record when the package is declared complete.

Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **KILL-AUTOPSY** (decided M3). Trigger: GATE-AUTOPSY-03 fails after one repair cycle: planted-cause accuracy below
  90%, or the top factor changes in more than 30% of cases at 10⁻⁷. Fallback, named in advance: Single-factor paired
  re-runs from the episode start, with first-anomaly ordering labelled `Estimated`; coalitions and Shapley summaries
  are removed.
- **Kill gates from later subsections, decided inside this package.** KILL-ENSEMBLE: agreement with double precision
  below 90%, or fewer than half of the reference failures admitted at any window of 0.5 s or more, or a bulk speedup
  below 3. Fallback: attribution in double precision only, and a failure not reproduced there goes to the artifact
  guard unattributed.
- **A design parameter cannot be changed mid-episode.** The thermal counterexample shows why: the mid-episode request
  is refused and the re-run from the episode start passes, with all four numbers within 0.1 s and 0.1 K.
- The top factor may change in at most 30% of cases under a 10⁻⁷ perturbation; otherwise the ranking is noise and the
  kill gate fires.
- Attributions are class `Estimated`, and a report never states them as causes without the flip rate.
