## Background

**The row.** WP-57: Gymnasium-compatible adapter [F]. Crates: `bindings/frob-gymnasium`, `frob-learn`. Milestone: M3.
Key gates: GATE-CORTEX-16. Waits for: WP-48, WP-37.

The ten-fold test gives the rival its own learning stack, and that stack speaks the Gymnasium interface. The package
delivers `bindings/frob-gymnasium`, a thin Rust shim and a Python package (the Python half capped at 1 thousand
lines, the annex as a whole at 3 thousand) through which a Gymnasium-compatible learner drives the Rust `VecEnv`. It is the only place a Python interpreter may appear, and never
in a production graph.

It is one unit of work because the adapter is accepted by one comparison: 10³ episodes driven through it and natively
have equal digests, the final observation is in `info` in every autoreset mode, and an external PPO reaches the
reference return threshold through it.

**Order.** It waits for WP-48 (the environment semantics and tensor views the adapter must preserve) and WP-37 (the
admitted array interchange and its typed stride converter). (The order between packages is recorded in `related`,
never in `deps`: a blocked epic would block every child, so the child beads carry the real dependencies.)

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **KILL-GYMADAPT** (decided M3). Trigger: GATE-CORTEX-16 fails. Fallback, named in advance: Rival stacks drive the
  environment through the job interface of §32 in whole rollouts, and the ten-fold test records the added latency in
  its phase ledger. (The job interface is the daemon's: a rollout is submitted as a job and read back by `job.wait`
  and the artifact verbs, so the rival never holds the environment step by step. The fallback is built by its own
  child bead only if the kill gate fires at either reading.)
- **OPEN-PROG-3**: whether the adapter ships as a supported, published binding. Default: built and gated for the
  ten-fold test and for conformance only; not a supported public surface; no interpreter in any `frob` binary.
- If the adapter fails its gate the rival still has access: whole rollouts through the job interface, with the added
  latency recorded in the rival's phase ledger so that it is not charged silently.
