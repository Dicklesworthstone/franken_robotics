## Background

**The row.** WP-75: Lifecycle compression [M]. Crates: `frob-lifecycle`. Milestone: M6. Key gates: GATE-FOUNDRY-12.
Waits for: WP-70.

A robot changes as it is used: backlash grows, batteries fade, and a gait that worked can collapse. The epic delivers
lifecycle compression (`foundry.lifecycle`): advancing the slow states of wear over long horizons without simulating
every step, so that a design can be judged at its hundredth hour.

It is one unit of work, a single Moonshot epic in a crate of its own, because its claim is one number checked against
one reference: a 100-hour reference run of 1.8 × 10⁸ steps compressed at least 50-fold in steps, with at most 5% error
on every slow state, and with the planted backlash-induced gait collapse still caught.

**Order.** It waits for WP-70: the fatigue and damage laws of the structure loop are among the slow states that are
advanced. (The order between packages is recorded in `related`, never in `deps`: a blocked epic would block every
child, so the child beads carry the real dependencies.)

acceptance is read. Each bead has one package (the owner of its crate at its milestone, or of the crate where its gate
is measured); exit reviews have none.

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

  otherwise the class that covers the estimate. If not approved: GATE-FOUNDRY-12 is `not-run`, never `pass`, no
  compression figure is printed, and KILL-LIFECYCLE (N31b-23) records `deferred` with the reason `no envelope`.
  Nothing above E0 starts before the owner's written approval is recorded on row R24 of
  `registries/compute_envelope.toml`; any other run that needs more is refused (`FROB-REF-761`) until a request
  with its class and its not-approved fallback is registered and approved.
- **KILL-LIFECYCLE** (decided M6). Trigger: GATE-FOUNDRY-12 fails. Fallback, named in advance: Aged model variants at
  hand-specified wear states, with no time axis and no compression claim.
- A Moonshot item is priority 4 whatever its milestone, counts toward the cap of four active Moonshot items, and is
  never on a critical path.
- The register reads this gate as a Fidelity claim: a compressed run agrees with a reference within a stated error; no
  speed figure on named hardware is claimed.
