## Background

**The row.** WP-79: Learned transport and tree policies: skill transport with learned residuals, geometric-algebra
tree policies, reachable-set tables [M]. Crates: `frob-control`, `frob-learn`, `frob-shield`, `frob-mission`.
Milestone: M8. Key gates: GATE-REFLEX-09; GATE-AUGUR-23; GATE-CORTEX-17; GATE-SHIELD-05. Waits for: WP-61, WP-65.

Three Moonshot epics ask whether what was learned or certified on one body can be moved to another. Skill transport:
`skill.transport` moves a skill artifact with a learned residual, and `mission.transport` moves a certified claim
through an interface map. Geometric-algebra tree policies at scale: a policy architecture that reads the kinematic
tree with geometric-algebra features. Reachable-set tables for shields: precomputed tables that admit or refuse a
state for small subsystems.

It is one package because the three share a rule and a risk: each is compared against a baseline that already ships
(family policies and inheritance, the plain morphology transformer, reduced-order barriers), and each needs
pretraining or precomputation above the default envelope.

**Order.** It waits for WP-61 (family policies and inheritance, which are both the baseline and the fallback) and
WP-65 (runtime shields, which the tables extend). (The order between packages is recorded in `related`, never in
`deps`: a blocked epic would block every child, so the child beads carry the real dependencies.)

## Technical approach

An epic implements nothing: it contains its child beads, which name it in `parent`, and it is where the package's
acceptance is read. Each bead has one package (the owner of its crate at its milestone, or of the crate where its gate
is measured); exit reviews have none.

Seed beads (the table of contents, assigned by crate, title and gate; a seed's own `parent` governs where it differs,
and N44-03 regenerates this list from the graph):
- M8: BD-436 Epic: skill transport. `skill.transport` moves a skill artifact with a learned residual [M] …; BD-439
  Epic: geometric-algebra tree policies at scale; BD-440 Epic: reachable-set tables for shields
- Beads drafted from the chapters for what no seed covers (`N<chapter>-<nn>`: mechanism parts, registries, end-to-end
  tests, pilots, kill-gate decisions) attach through their own `parent` field.

**Frontier and Moonshot content, and the pilot that must be on record first.** The package is Moonshot. Pilots on
record first: skill transport by a learned task-space residual on 24 target bodies under three treatments at equal
cost; three policy arms at equal wall-clock, a plain transformer against geometric-algebra variants, on existing tools
(construction C-24); a reachable-set table for braking across two floor materials (two states and a mode), measuring
coverage and false admissions; and coupling budgets from common-noise sealed paired runs on the tray fixture.

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** The package needs more than the default machine envelope E0 (16 GiB, 8 cores, one hour, one device).
  Request (row WP-79): Pretraining for tree policies [M]. Class asked: E3. If not approved: The epic is not funded.
  Nothing above E0 starts before the owner's written approval (N44-01); a job above the class in force is refused
  before it starts (`FROB-REF-761`).
- **KILL-SKILL** (decided M8). Trigger: GATE-REFLEX-09 fails. Fallback, named in advance: Keep the exact layer and its
  witnesses; drop the learned residual.
- **KILL-AUGUR-TRANSPORT** (decided M8). Trigger: The interface arm needs as many target trials as the conditioned
  policy, or reports coverage where the referee shows a fall. Fallback, named in advance: Family policies and
  inheritance of §23; the wrench-coverage test is kept as a static analysis.
- **KILL-GATREE** (decided M8). Trigger: GATE-CORTEX-17 fails. Fallback, named in advance: The plain morphology
  transformer remains; `fs-ga` features are not used in policies.
- **KILL-TUBE** (decided M8). Trigger: GATE-SHIELD-05 fails, or the pilot's falsifier holds. Fallback, named in
  advance: No tables are built; reduced-order barriers cover those subsystems.
- **Kill gates from later subsections, decided inside this package.** KILL-COUPLING (chance and expectation claims
  crossing `mission.transport`): one violated transported bound that survives a repair cycle, or no skill on the tray
  fixture with a budget below its slack. Fallback: `mission.transport` carries universal claims only, and every chance
  or expected-value claim is re-measured on the target in the qualification lane.
- Each kill gate's fallback is something that ships at M4, so a fired gate costs the epic and nothing else.
- A reachable-set table must show zero false admissions in 5,000 in-envelope episodes and answer `uncovered` outside
  the table; it is never extrapolated.
