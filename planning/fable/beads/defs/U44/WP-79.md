## Background

**The row.** WP-79: Learned transport and tree policies: skill transport with learned residuals, geometric-algebra
tree policies, reachable-set tables [M]. Crates: `frob-control`, `frob-learn`, `frob-shield`, `frob-mission`.
Milestone: M8. Key gates: GATE-REFLEX-09; GATE-AUGUR-23; GATE-CORTEX-17; GATE-SHIELD-05. Waits for: WP-61, WP-65.

Three Moonshot epics ask whether what was learned or certified on one body can be moved to another. Skill transport:
`skill.transport` moves a skill artifact with a learned residual, and `mission.transport` moves a certified claim
through an interface map. Geometric-algebra tree policies at scale: a policy architecture that reads the kinematic
tree with geometric-algebra features. Reachable-set tables for shields: precomputed tables that admit or refuse a
state for small subsystems.

It is one package because the three share a rule and a risk: each is compared against a baseline that already ships
(family policies and inheritance, the plain morphology transformer, reduced-order barriers), and each needs
pretraining or precomputation above the default envelope.

**Order.** It waits for WP-61 (family policies and inheritance, which are both the baseline and the fallback) and
WP-65 (runtime shields, which the tables extend). (The order between packages is recorded in `related`, never in
`deps`: a blocked epic would block every child, so the child beads carry the real dependencies.)

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

  Request (row R10 of `registries/compute_envelope.toml`, N44-01): Pretraining for tree policies [M]. Class asked:

    device-hours per gate. If not approved: the pilot is closed `withdrawn` (`not run: no envelope`, citing R21),
    N22b-07 is not funded, and KILL-SKILL records its fallback: the exact layer and its witnesses are kept and the
    learned residual is dropped.
  - R22, the two training arms of GATE-AUGUR-23 in N25c-04 (arms 1 and 2 of the pre-registered three-treatment
    tray transfer; the plan gives no budget): the class that covers the budget its protocol states, for
    `gate:GATE-AUGUR-23`. If not approved: arms 1 and 2 are recorded `not run` with the envelope reason,
    GATE-AUGUR-23 is `not-run`, never `pass`, and the interface map is not claimed on the gate.

  witnesses; drop the learned residual.
- **KILL-AUGUR-TRANSPORT** (decided M8). Trigger: The interface arm needs as many target trials as the conditioned
  policy, or reports coverage where the referee shows a fall. Fallback, named in advance: Family policies and
  inheritance of §23; the wrench-coverage test is kept as a static analysis.
- **KILL-GATREE** (decided M8). Trigger: GATE-CORTEX-17 fails. Fallback, named in advance: The plain morphology
  transformer remains; `fs-ga` features are not used in policies.
- **KILL-TUBE** (decided M8). Trigger: GATE-SHIELD-05 fails, or the pilot's falsifier holds. Fallback, named in
