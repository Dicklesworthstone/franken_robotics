## Background

**The row.** WP-80: Continuation-based synthesis, firmware export and the fused step kernel [M]. Crates: `frob-synth`,
`frob-foundry`, `frob-kernels`. Milestone: M8. Key gates: GATE-AUGUR-22; GATE-FOUNDRY-11. Waits for: WP-67, WP-71,
WP-15.

Three Moonshot epics complete three pipelines. Continuation-based synthesis (strategy `continuation` of
`mission.synthesize`) finds all solutions of a mechanism's polynomial system by following paths from a solved start
system. Firmware export turns a controller into code with fixed-point arithmetic and test vectors. The fused per-world
step kernel replaces the staged step plan by one kernel per world.

It is one package only as a queue: each epic has its own crate, its own pilot and its own kill gate, and each replaces
nothing until its gate passes, because the staged step plan, the exact synthesis lane and the parameter export are the
designs of record.

**Order.** It waits for WP-67 (the exact synthesis lane that continuation extends), WP-71 (the build packet that
firmware export joins) and WP-15 (the staged step that the fused kernel is compared with, digests unchanged). (The
order between packages is recorded in `related`, never in `deps`: a blocked epic would block every child, so the child
beads carry the real dependencies.)

## Scope

Crates and other units, with layer, tier of contents, scope cap (thousands of lines, DESIGN; 115% opens a scope
review) and role:
- `frob-synth` (layer 5; Frontier, Moonshot; cap 10): Bounded exact linkage synthesis; trajectory optimization with
  design variables; continuation lanes.
- `frob-foundry` (layer 5; Frontier; cap 12): Structure, fatigue, tolerance allocation, build packets.
- `frob-kernels` (layer 3; Solid; cap 26): The kernel library: manifests, Rust skeletons, generated arithmetic, exact
  and guarded predicates.

What lands at each milestone:
- **M8.** Per funded epic: plan, pilot, kill decision, mechanism; GATE-AUGUR-22 (continuation) and GATE-FOUNDRY-11
  (firmware: the fixed-point cases, 10⁶ vectors bit-equal).

Out of scope: the staged step plan and survivor specialization (WP-15, WP-46); the exact and numerical synthesis lanes
(WP-67); the build packet (WP-71).

## Technical approach

An epic implements nothing: it contains its child beads, which name it in `parent`, and it is where the package's
acceptance is read. Each bead has one package (the owner of its crate at its milestone, or of the crate where its gate
is measured); exit reviews have none.

Seed beads (the table of contents, assigned by crate, title and gate; a seed's own `parent` governs where it differs,
and N44-03 regenerates this list from the graph):
- M8: BD-437 Epic: continuation-based synthesis (strategy `continuation`); BD-438 Epic: firmware export; BD-441 Epic:
  the fused per-world step kernel
- Beads drafted from the chapters for what no seed covers (`N<chapter>-<nn>`: mechanism parts, registries, end-to-end
  tests, pilots, kill-gate decisions) attach through their own `parent` field.

**Frontier and Moonshot content, and the pilot that must be on record first.** The package is Moonshot. Pilots on
record first: Stewart–Gough forward kinematics by parameter homotopy from one monodromy solve, 40 certified roots on
generic parameter sets; the one-week fusion pilot of kinematics, dynamics terms and one Newton iteration for a
quadruped at 8,192 worlds with digests unchanged; and fixed-point types `q16_16` and `q32_32` for an embedded target
with defined semantics. The firmware boundary follows a sibling project as a pattern only; no dependency is added
until the epic is funded.

## Test plan

### Unit tests
None of its own: the children's tests run beside the code with `cargo test -p <crate>`, without mocks. The package's
structural tests are in N44-04 (`wp_children_have_one_parent`, `wp_gate_ids_exist`, `wp_tier_tag_has_pilot`).
### End-to-end script and logging
The children's scripts under `scripts/e2e/` demonstrate the package through the real `frob` binary, with the
structured logs of STD-E2E. `scripts/e2e/wp_table.sh` (N44-05) prints this row with its children, the open count and
each gate's status, and fails if a gate above has no record when the package is declared complete.
### Known answers and negative controls
Carried by the children and their chapter registries. A gate above counts only when its registered negative control
has been shown to fail (GATE-GAUNT-01).

## Considerations

- **Envelope.** No request above the default E0 (16 GiB, 8 cores, one hour, one device) is registered. A run that
  needs more is refused (`FROB-REF-761`) until a request with its class and its not-approved fallback is registered
  and approved (N44-01).
- **KILL-SYNTH-CONT** (decided M8). Trigger: More than 0.1% lost paths, an unflagged lost path, or a missed known
  count. Fallback, named in advance: The exact lane plus multi-start CPU recovery; every result labelled `Partial`.
- **KILL-FIRMWARE** (decided M8). Trigger: GATE-FOUNDRY-11 fails. Fallback, named in advance: Controller parameters, Q
  formats and the test-vector manifest only; no code.
- **KILL-MEGA** (decided M8, before the work package). Trigger: In the one-week fusion pilot (8,192 worlds, digests
  unchanged) the paired lower bound on the whole step is below 2.0. Fallback, named in advance: The staged step plan,
  which is the design of record.
- `Complete` is issued by the continuation lane only when the trace test agrees; lost paths are at most 0.1% and every
  one is flagged, or the result is labelled `Partial`.
- Exported firmware carries the no-authorization flags; if KILL-FIRMWARE fires, the export is controller parameters, Q
  formats and the test-vector manifest, and no code.
- The fused kernel is funded only if the paired lower bound on the whole step is at least 2.0 with digests unchanged.
