## Background

Kernels are derived as straight-line programs in an intermediate representation (`frob-kir`) and optimized by
rewrites before being emitted for CUDA, Metal and the CPU. The whole evidence system rests on digests of
simulation state: replay, both ledgers and every paired comparison assume that the same kernel on the same
inputs produces the same bits. A rewrite that changes one bit therefore changes every digest downstream.
Construction C-14 splits rewrites into two classes. Class E is bit-exact under round-to-nearest with
contraction off: commutation, sharing a common subexpression, removing dead code, scaling by a power of two
away from overflow and underflow. Class R is equal over the reals only: reassociation, distribution, fused
multiply-add. Class E rewrites are applied freely and recorded as a replayable trace that the offline auditor
can check (theorem card T-27); a class R rewrite is admitted only as a new kernel with a new identity and its
own evidence (decision core DC-11). Proof obligation PO-KIN-03 fixes the summation order of reductions for the
same reason. No fast-math flag is ever set. Tier: Solid. Subsystem: Spark (kernel toolchain).

## Scope

## Technical approach

**Equation.** The spacing of `f32` near x is 2^(⌊log₂ x⌋ − 23). Class E and class R as defined above.

**Substituted (exact arithmetic), with goldens.**

| Output | Inputs | Golden | Tolerance |
|---|---|---|---|
| Spacing of `f32` near 10⁸ | ⌊log₂ 10⁸⌋ = 26 | 2³ = 8 | bits |
| (a + b) + c | a = 10⁸, b = −10⁸, c = 1 in `f32` | 1.0 (bits 0x3F800000) | bits |
| a + (b + c) | same | 0.0 (bits 0x00000000), because b + c rounds to −10⁸ | bits |
| Sharing a subexpression used three times | — | saves two evaluations; changes no bit | bits |
| x·y + z against fma(x, y, z) | x = y = 1 + 2⁻¹², z = −(1 + 2⁻¹¹) in `f32`; the exact product 1 + 2⁻¹¹ + 2⁻²⁴ is a tie and rounds to even, 1 + 2⁻¹¹ | 0.0 unfused; 2⁻²⁴ fused | bits |
| Commutation a + b against b + a | 10⁶ random `f32` pairs | identical bits | bits |
| Scaling by 2ᵏ away from overflow and underflow | (2·x)·y against 2·(x·y) | identical bits | bits |
| FACT: share of an incumbent step in the Lie-algebraic recursions | source register | 16 to 20%, which caps specialization near 1.2 | as recorded |

**Intuition.** A rewrite that changes one bit changes every digest downstream, and replay, both ledgers and
every pairing go with it. Regrouping is admitted only as a new kernel, with a new identity and its own evidence.

**Assumptions.** IEEE 754 single precision; no contraction; no fast-math.

**Flip.** A profile with more than about a fifth of step time in derived arithmetic would make class R worth
its certificates. The FACT above puts that share at 16 to 20% of an incumbent step, which caps specialization
near 1.2 (1/(1 − 0.2·(1 − 1/r)) ≤ 1.25).

**Lane A.** `f32` arithmetic in the test with explicit operation order (each intermediate stored to an `f32`
variable; no expression the compiler could contract), compared by `to_bits`.

**Lane B.** `frob-kir`: (1) the program t = (a + b) + c and its reassociated form have different canonical
hashes, and the rewrite engine refuses to produce one from the other under class E; (2) common-subexpression
elimination on a program that uses a·b three times yields a program with one multiplication whose evaluation
is bit-identical on 10⁶ random inputs; (3) the Rust emitter and the dialect emitter both evaluate the two
groupings to 1.0 and 0.0; (4) a trace that files a reassociation as class E is rejected by the trace checker
with verdict `reject`; (5) the dialect lint fails a kernel source that contains an fma intrinsic or a
contraction pragma. Surface: `frob prove kernel <kernel> --json` lists the rewrite trace with every rule's
class.

**Milestones of the lane B checks (the card is M0; two checks wait for later mechanisms).** Checks (2), (3) and
(5), and the hash half of (1), use `frob-kir` v0 (BD-018) and run from M0. The refusal half of (1) needs the
closed table of exact rewrites (N21a-19, M2) and runs from M2 as `gb_25_mechanism_rewrite_refused`; check (4)
needs the independent `rewrite-trace` checker of `frob-cert` (N12p2-02, M2: it was split out of the M4 bead
N12-18, which keeps the two group-theoretic kinds) and runs from M2 as `gb_25_mechanism_trace_reject`.
Each is declared in the card file as a `[[mechanism]]` entry with its own `first_milestone` (NEG-01) and is
reported `not run` before it, never `pass`. The surface `frob prove kernel` carries `first_milestone = "M2"` and
reports `not run` before it: the verb exists from M0, but a kernel's certificate holds a rewrite trace only
once the M2 kernels ship theirs and the `rewrite-trace` kind is enabled (N12p2-02).

## Acceptance criteria

- [ ] The card file validates with all five fields; goldens are hexadecimal bit patterns.
- [ ] `gb_25` passes both lanes on the CPU and, through the probe kernels, on CUDA and Metal (the two
      groupings give 1 and 0 on each backend).
- [ ] At M0 a class R rewrite produces a kernel with a different canonical hash (identity); from M2 the rewrite
      engine refuses to produce the reassociated form under class E (N21a-19) and a reassociation filed as
      class E in a trace is rejected by the trace checker (N12p2-02); before M2 the two checks are reported
      `not run`.

## Test plan

### Unit tests

- `gb_25_reference_regroup`: 1.0 and 0.0 by bits; spacing 8.
- `gb_25_reference_fma`: 0.0 unfused against 2⁻²⁴ from a software fused multiply-add (exact product in `f64`,
  one rounding).
- `gb_25_reference_class_e_laws`: commutation, power-of-two scaling, subexpression sharing on 10⁶ random
  inputs (seeded), bit-identical; power-of-two scaling is excluded near overflow (2·MAX) and for subnormals,
  where the test shows a difference and the rule's side condition is checked.
- `gb_25_mechanism_hash_differs`, `gb_25_mechanism_cse_bit_identical`, `gb_25_mechanism_lint_fma` (M0);
  `gb_25_mechanism_rewrite_refused` (M2); `gb_25_mechanism_trace_reject` (M2).
- `gb_25_controls`: (a) a build with contraction enabled turns x·y + z into the fused result and is caught by
  the bit comparison; (b) a reassociated reduction (pairwise against sequential over 1,024 values of mixed
  magnitude) differs in at least one bit and must be detected as a new kernel identity; (c) distribution
  a·(b + c) → a·b + a·c filed as class E is rejected.

### End-to-end script and logging

NEG-02 runs `frob spark probe --device <d> --key <k> --json` for each available device (the verb's registry form;
its `K-probe-contract` executes the regrouping pair and the contraction pair on that backend, and `K-probe-fma` the
fused form, BD-017) and compares the four bit patterns with the goldens above; logs backend, device fingerprint
digest and the patterns.

### Known answers and negative controls

KA-087 (rewrite control in `f32` with a = 10⁸, b = −10⁸, c = 1: 1 and 0; a reassociation filed as class E is
rejected by the trace checker); KA-212 (the rejection as a verdict); KA-705 (DC-11: the two groupings give 1
and 0). Determinism: this card is the definition of bit-exactness; identical on every IEEE-754 platform.

## Considerations

- Whether a device's division and square root are correctly rounded is measured by the fingerprint, not assumed
  here; the card uses only addition and multiplication.
- The 16 to 20% share is FACT about an incumbent; the project's own profile at M2 decides whether class R work
  is ever funded.
