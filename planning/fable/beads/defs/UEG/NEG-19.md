## Background

Clutter on a floor (toys, shoes, small household objects of 20 to 150 mm) is a hazard class of the home
archetype: a robot rides up on it, tips, or blocks a castor. The Solid representation is rigid proxy bodies
generated by the project. For populated interiors at M5, real object shapes come from Google Scanned Objects:
a collection of scanned household items, on file under CC-BY 4.0 (FACT from the research pass of 2026-11-21;
re-checked at admission). CC-BY allows redistribution and adaptation provided attribution is given, a link to
the licence, and an indication of changes. That makes it the first source whose obligation is not a notice
file beside the asset but an attribution that must appear wherever the asset is distributed, including
exported packs and reports; the licence manifest's `notice` field exists for this. It is a Frontier source,
funded only after the dressing pilot.

## Scope

In: the register row; the admission reading; the attribution text and its propagation test; the import
profile for small rigid objects; validation; `assets/scenes/google-scanned-objects/` with its manifest and
selection list. Out: the licence manifest and pack-time checks (N19b-02); rigid proxies generated by the
project (BD-231); populated interiors (BD-399).

## Technical approach

**Register row.** `key = "google-scanned-objects"`, `licence = "CC-BY-4.0"`, `class = "attribution"`,
`default_pipeline = true` after the admission reading, `redistribute = "with-attribution"`,
`kind = "object-collection"`, `use = "household clutter"`.

**Admission reading.** Read the collection's licence statement at its primary host and record text hash,
date and the exact attribution the licensor asks for (creator, title, source, licence link). Confirm whether
the licence applies to every object or per object, and whether any object depicts a branded product whose
trade dress raises a separate question; branded items are excluded from the selection list by default.

**Selection list.** `assets/scenes/google-scanned-objects/selection.toml`: the object identifiers used, each
with its hash, the category (toy, shoe, container, tool), the bounding dimensions, and `branded = false`.
Only listed objects are importable in the default pipeline. DESIGN: the list narrows this row's default
pipeline to the objects it names, so an import in default mode (no `--user-supplied`) of an object that is not
listed, or is listed with `branded = true`, is refused before anything is written, with the worded refusal of
the default-pipeline filter, `asset-source-not-default-pipeline` (N19b-02; exit 3; interim code `FROB-REF-802`
behind `ASSET_SOURCE_NOT_DEFAULT` until the ledger assigns a number), `observed` naming the object identifier and
`assets/scenes/google-scanned-objects/selection.toml`, and the same two ranked repairs (re-run with
`--user-supplied`; choose a listed object).

**Import profile.** `frob --json scene import --kind asset <object> --source google-scanned-objects --profile
small-rigid --behaviour free --key <k>` (the verb and its inputs are N19a-46's: `kind` is required, a `run` verb
takes an idempotency key, and a part that can move needs its declared behaviour; this bead adds the import
profile `small-rigid`, recorded in `registries/import-profiles.toml`, with the steps below). The import: decode the mesh; check watertightness; compute volume and assign mass from a declared density per category
(`assumed`); compute inertia from the solid mesh; build a collision shape (convex decomposition with a cap on
hull count and recorded Hausdorff error, or fitted primitives); assign an interface card by category
(`assumed`) and an optical class; mark as a free rigid body; write the licence entry with the attribution
text; record the modification ("collision geometry simplified; visual mesh decimated") since CC-BY requires
changes to be indicated.

**Validation.** Dimensions inside the clutter hazard range 20 to 150 mm or tagged out-of-range; mass
positive, inertia consistent; rest pose stable on a plane (settles within 2 s on the referee); collision error
below 2 mm for objects under 150 mm; an exported pack and an exported report that contain the object embed
the attribution text and the change statement.

## Acceptance criteria

- [ ] The admission record holds the licence text hash, the attribution wording and the per-object question's
      answer.
- [ ] Ten selected objects import, validate and settle; each has a licence entry with attribution and a
      change statement.
- [ ] An export containing any of them embeds the attribution (a pack through the pack export check of
      N19b-02, a report through the export door of N37-18, which adds the notices); removing the `notice` field
      makes the entry count as `unknown` (N19b-02), so the pack check refuses with `FROB-REF-310` (exit 3) and the
      door refuses the report with `FROB-REF-733` (exit 5), each naming the object.
- [ ] A non-selected or branded object is refused in default mode with `asset-source-not-default-pipeline`
      (exit 3, nothing written), `observed` naming the object and the selection list.

## Test plan

### Unit tests

- `asset_source_gso_row_valid`.
- `gso_import_attribution_entry`: licence entry has class `attribution` and a non-empty notice.
- `gso_export_embeds_attribution_and_changes`.
- `gso_import_rejects_non_watertight_or_reports`: a `synthetic` open mesh is repaired only with a recorded
  loss entry, never silently.
- `gso_mass_from_assumed_density_labelled`.
- `gso_selection_enforced`.

### End-to-end script and logging

`scripts/e2e/assets_licences.sh` (the M5 scene-asset loop, owned and run by NEGp1-54, which depends on this
bead; this bead lists the steps of its row), every `run` verb call with its own `--key`: the import of each
selected object as written above (`--key al-gso-<n>`); a non-selected object and a branded one (`--key al-gso-x1`,
`al-gso-x2`; each refused with `asset-source-not-default-pipeline`, exit 3, nothing written); a scene with five objects dropped on a floor (`frob --json scene
compile` of the stand-in floor with the five objects, `--key al-gso-scn`; after `e2e_scene_ready <pack>`, a
referee run `frob --json sim run quad-a --scene <pack> --tier referee --seconds 2 --key al-gso-run`, every object
settled within 2 s); `frob --json artifact export <pack> --out exports/ --key al-gso-exp1` and the export of the
run's report (`--key al-gso-exp2`), each embedding the attribution and the change statement; the same with the
`notice` field removed (the pack check refuses with `FROB-REF-310`, exit 3; the door refuses the report with
`FROB-REF-733`, exit 5). Log lines carry `ts`, `script`,
`bead: "NEG-19"`, `step`, `event`, the exact command, exit code, wall time, the `evidence` block, object
identifiers, hashes, mass, collision error, the attribution text's hash and its presence in both exports, each
refusal code with its exit code, and no geometry.

### Known answers and negative controls

The licence-join rule (an export's licence set is the join of its inputs'). Controls: an export with the
attribution stripped; a branded object in the selection; density reported as measured. Determinism: an
import of the same file yields the same asset identifier and collision decomposition (the decomposition is
seeded and its seed recorded).

## Considerations

- Scans are shapes and textures, not physics: every mass, friction and stiffness value is assigned by the
  project and labelled `assumed`.
- The clutter failure classes (ride-up, tip, blocked castor) are already provoked by rigid proxies; whether
  scanned shapes add any is exactly what the dressing pilot asks.
