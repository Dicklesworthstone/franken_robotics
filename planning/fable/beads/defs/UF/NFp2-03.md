## Background

Upstream work item FD-FSS-01 is conditional. The paper-scale pilot of real-place ingestion (N19c-01) inspects one
twin package of the walkthrough route (video to an agent-built Blender twin, in `franken_surveillance_system`) for
three things a physics scene needs: four non-coplanar landmarks (registration without a mirror ambiguity), a scale
witness (so that the scale label, one of `relative-only`, `estimated`, `witnessed`, `surveyed` in order of
authority, can be `witnessed`), and coverage or confidence per region (so that unobserved space is unknown, never
free). If the pilot finds any missing, FD-FSS-01 adds them to the twin package in that repository. The plan's
switch-over rule for the item: re-run GATE-HAB-03 **with a scale label of `witnessed` or better**, and the twin
package's version becomes part of the import contract (OPEN-HAB-5). This sibling is a pattern, not a build
dependency: its "pin" is the package version named in the import contract.

This bead is that switch-over. It is separate from FD-FSS-01 for the order-of-work reason of NFp2-01: the
upstream change can start as soon as the pilot has recorded what is missing (M3), while the re-run needs the
`place` form of `scene.import` (the M5 capstone BD-398), the gate script (N19c-07) and the contract file (N19c-09).
The step that needs both comes after both.

## Scope

In: the precondition check (including the case in which FD-FSS-01 was closed as not needed); the contract row of
the extended package version; the checks through the importer (registration from the package's landmarks, the
scale label, unobserved regions as unknown space, a probe request); GATE-HAB-03 at `witnessed` or better on one
place, or `no-claim`; the registry row's move to `adopted`; the script.

Out: the pilot (N19c-01); the upstream change, its validator fixture and the version record (FD-FSS-01); the
importer, registration and acceptance (BD-398, BD-228, N19c-04); scale labels and the unknown mask (N19c-02,
N19c-03); the gate script (N19c-07); the contract file and its enforcement (N19c-09); the KILL-INGEST decision
(N19c-08); the drone route's switch-over (NFp2-02).

## Technical approach

1. **Preconditions and the not-needed case.** (a) FD-FSS-01's row in `registries/upstream.toml` reads
   `not-needed` (admitted by BD-037's loader only with the pilot's verdict in `tests/upstream/FD-FSS-01/PILOT.md`):
   the package the pilot inspected already carries the
   three things, there is nothing to switch over, and this bead records exactly that (the package version already
   in the contract, and that GATE-HAB-03's label requirement is met by N19c-07's own run), clears the row's
   `pin_state` (that contract version is the sibling's admission, BD-037's fixture timing rule), then closes.
   (b) The row reads `landed`: the three additions are on the sibling's `main`, FD-FSS-01's validator passes on a
   package exported from the landed commit, and that package's version is recorded in FD-FSS-01's closing note.
   Otherwise the script stops before any write.
2. **Contract row.** The admitted triple (adapter `twin`, the new package version, the package schema's digest) is
   added to `registries/ingest_contract.toml` (N19c-09), and the earlier twin row is kept for packs already
   imported; the stack lock records the package version and the sibling commit that exported it. OPEN-HAB-5 is
   not re-decided here: a version change inside the admitted package is a contract amendment under the ruling in
   `docs/adr/OPEN-HAB-5.md` (or its default), cited by the row. The version entered here is the sibling's first
   admission, so FD-FSS-01's registry row gets `observed_at` equal to the exporting commit and its
   `pin_state = "unpinned"` is cleared (BD-037's fixture timing rule; FD-FSS-01 leaves the field to this bead).
3. **Checks through the importer.** On a `synthetic` package exported in the new format and, where one exists, the
   owner's package from the landed commit: `frob --json scene import --kind place --from twin <package> --key
   fss-imp-<n>` (the twin adapter of BD-398's place form, as the gate script's `--from twin` below);
   four-point registration from the package's own landmarks (the registration receipt in the result, the mirror
   case excluded); the scale label `witnessed` from the package's witness, or `surveyed`; regions the package marks
   unobserved are unknown space (a clearance query across one is `unresolved`); `frob --json scene accept <id> --key
   fss-acc-<n>`; on a door whose clear width is `unresolved` within the scale interval, `frob --json scene
   probe-request <answer>` emits one request naming the box, the quantity and the accuracy that would settle it.
4. **GATE-HAB-03 at `witnessed` or better.** N19c-07's script on one place exported in the new format
   (`scripts/e2e/gate_hab_03_real_place.sh --lane private --from twin --package <package>`, with the owner's
   configured private root); or, with no capture admitted, the rehearsal lane on the synthetic package and the
   row `no-claim` naming the missing capture. The value is recorded with
   `cargo run -p frob-conformance --example record_gate -- --gate GATE-HAB-03 --receipt <hash> --part M5` by a
   session that did not implement the work.
5. **Adoption.** The row's `status` becomes `adopted`, citing the receipts of steps 3 and 4; the interim posture
   (surveyed proxies, N19c-06, or operator-declared scale with `reality: no-claim`) ends for places exported in the
   new format.

## Acceptance criteria

- [ ] With FD-FSS-01's row reading `not-needed`, this bead records the not-needed case, clears the row's `pin_state`, and changes nothing else.
- [ ] With a precondition of step 1(b) missing, the script stops before any write.
- [ ] The contract file holds the new package version's row; a package of the old format still imports under its own row, and a package whose version or schema digest is in no row is refused with `FROB-REF-303`.
- [ ] On a package from the landed commit: registration from its four landmarks succeeds and the mirror is rejected; the scale label is `witnessed` or better; unobserved regions are unknown space; a probe request is emitted for an unresolved door.
- [ ] GATE-HAB-03 is recorded with that label on one place, or `no-claim` naming the missing capture, by a session that did not implement the work; never a pass from the rehearsal lane.
- [ ] The row of FD-FSS-01 reads `adopted` with the receipts, `observed_at` names the exporting commit, and the row carries no `pin_state`.

## Test plan

### Unit tests

`crates/frob-scene/tests/fss_switchover.rs` (real files in a temporary directory; packages labelled `synthetic`):
- `registration_from_four_landmarks`: a twin rotated 30° about z, translated by (2, −1, 0.5) m and scaled by 1.02 relative to the scene; the recovered transform reproduces the four landmarks within 1 mm, and its mirror image is rejected (the determinant of the rotation is +1).
- `scale_without_witness_is_not_witnessed`: a package without a witness yields at best the label `estimated` (clearance verdicts are then `unresolved` within the stated scale interval), and with no scale prior `relative-only`, on which every metric task is refused (`FROB-REF-304`).
- `witness_gives_witnessed`: a measured baseline of 0.800 m ± 0.004 m between two named features → `witnessed`, ε_c = 0.005.
- `unobserved_region_is_unknown`: a region the package marks unobserved is unknown space; a traversal query through it returns `unknown`.
- `contract_rows_coexist`: the old and the new twin rows both admit their own packages; a third version is `FROB-REF-303`.
- `not_needed_case_records_nothing` (the script's helper, in `scripts/e2e/tests/fss_switchover_helpers.sh`, plain bash sourcing the STD-E2E helper): a row reading `not-needed` makes the script write only the not-needed record and the cleared `pin_state`; a row reading `open` (the pilot found something missing and FD-FSS-01 has not landed) stops the script before any write.

### End-to-end script and logging

`scripts/e2e/upstream_fd_fss_01_switchover.sh` (sources the STD-E2E helper; header `bead=NFp2-03 milestone=M5
gates=GATE-HAB-03 plants=three-landmarks,coverage-ignored,witness-removed`; `roots.private` of the scratch state
and `FROB_PRIVATE_ROOT` point at a temporary directory outside the repository; every `run` call carries its own
`--key`): `preconditions` (the row read with `frob --json doctor`; FD-FSS-01's validator on the landed package,
expecting a pass; or the not-needed case); `contract` (the rows read back; a package with an altered schema digest,
expecting `FROB-REF-303`); `import` (step 3, keys `fss-imp-<n>`, `fss-acc-<n>`, `fss-fit-<n>`; the same package with
its witness removed, expecting a label below `witnessed`); `probe` (the request on the unresolved door);
`gate-hab-03` (N19c-07's script as in step 4, its own log linked by path and digest); `adopt` (the row read back:
`adopted`, `observed_at` the exporting commit, no `pin_state`).
Log: `target/e2e-logs/upstream_fd_fss_01_switchover/<utc>.ndjson` with a transcript beside it; every line has `ts`,
`script`, `bead`, `step`, `event` (`start`, `cmd`, `assert`, `metric`, `refusal`, `end`), the exact command line,
exit code, wall time and the envelope's `evidence` block; it also records the package version and its exporting
commit, the contract row matched, the landmark residual, the scale label with ε_c, the unknown fraction, the probe
request's quantity and accuracy, each refusal's code and exit code, and, on failure, the first differing value and
the artifact identifiers needed to reproduce. A final `summary` line gives assertions passed, failed and skipped
and names GATE-HAB-03. No private-scene data is logged: features appear as salted digests.

### Known answers and negative controls

- Known answers: four points are coplanar exactly when the tetrahedron they span has zero volume (1/6 m³ for the
  unit corner, 0 for the square); a similarity transform has seven parameters, and four non-coplanar
  correspondences determine it with redundancy and exclude a reflection; a 0.800 m ± 0.004 m baseline gives
  ε_c = 0.5%.
- Negative controls (each must make the script fail): a registration from three landmarks that does not report the
  mirror ambiguity; an importer that ignores the coverage partition and answers `free` in an unobserved region
  (CX-355); a package whose witness was removed but which still imports as `witnessed`.
- Determinism: registration twice gives identical transforms; the same package imported twice under distinct keys
  gives the same `SceneId`.

## Considerations

- The item may never be needed; then this bead is a one-line record and closes (step 1a), which is the cheapest
  outcome by design.
- If KILL-INGEST fired at M5 before this bead runs, a pass here at `witnessed` is the capture N19c-08 names as the
  condition for re-opening; it goes to a new ADR that supersedes the decision from its date and does not rewrite it.
- Real-place data is private: packages of a real place live beneath the private root, and only digests and labels
  are logged.
- Neither a pin nor the toolchain moves during the ten-fold tournament of M7, so this bead does not run then.
