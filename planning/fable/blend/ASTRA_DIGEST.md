## 1. Thesis, product definition and user workflows

**1.1 Research objective (A preamble).** "Give the studio a mission, a catalog of parts, a controller class and a description of what the robot can observe. Ask it for the *set* of designs that can do the job." The answer has three parts: a body and controller that work over a stated region; a checkable reason some alternatives cannot work; and the cheapest experiment that could settle the remaining region. An engineer amends the mission ("deliver on a dry floor" becomes "also deliver with a wet left wheel and an occluded camera") and sees which conclusions survive. *Why:* the engineering deliverable is a decision over a family, not a score for one robot. *BASE:* LACKS. B§22.1's loop is forward only; B§22.6 optimizes points and B§22.2 A-10 proves closure for one design. *Weakness:* ASTRA itself records the combined interface as a hypothesis (claim C006).

**1.2 The 10× target (A preamble, A§19).** A tenfold reduction in elapsed time to an independently accepted engineering answer at matched accuracy, scope, resources and evidence. The comparator may combine leading simulators, an optimizer, analytic bounds, a verifier and the same AI agent. A second target is "a new query that an independent checker can adjudicate over a continuous family of designs". Both are stated as funding and acceptance criteria. *BASE:* LACKS. BASE targets throughput in world-steps/s (B§28.1) and method bets (BET-05, BET-10); none is defined against a rival's whole workflow. Details in §13 below.

**1.3 First 10× research bet (A preamble).** Derive the physical conditions under which an accepted design decision survives an edit. If a new gearbox changes rear-axle traction or shifts the arrival of a camera packet, identify the exact obligation to re-solve; if the edit stays inside a proved range, return the earlier result with a checkable justification. ASTRA concedes that existing solvers already match several small family queries when given the same conditions, so W32/W40 measure the cost of *deriving* the conditions. *BASE:* LACKS. B§12.3's memoization reuses compile products, never verdicts.

**1.4 "One result the studio should be able to explain" (A preamble, A§18.10).** The three-tick docking robot: at command limit ¾, a fixed probe tolerates sensor error below 1/8; designing probe and feedback together moves the threshold to 5/16; a third plausible gain 33/32 defeats exact docking on every formerly feasible row. Full derivation in §12.10 below. *BASE:* LACKS anything comparable.

**1.5 Flagship commission (A preamble, A§18.9).** Hand the studio an incomplete survey of a working facility, a parts catalog and a delivery brief. It prices a legged or wheeled carrier, a two-robot handoff and a small facility change under the same payload, power and scheduling constraints. The deliverable is a set of feasible repairs with witnesses, exclusions, and the site or material measurement that would decide between survivors. *BASE:* LACKS. B§16 scenes are fixed test environments, and there is no multi-robot or facility-edit concept.

**1.6 Foundation and first decisions (A preamble).** The product is a headless design studio plus a vectorized RL gym. FrankenSim supplies mechanics; "a typed algebra of assemblies, frames, power ports, observations and hybrid state transitions describes each experiment"; a compiler specializes it into a CPU reference and native CUDA or Metal plans; one CLI/MCP service; a person opens the same run as synchronized 3D replay, plots and a design diff.
- *First forward decision:* does a larger drive wheel help a small indoor cart cross a raised threshold with motor, envelope, battery, payload and current limit fixed? A larger wheel improves approach geometry and reduces tangential force per axle torque, so either design can lose.
- *First legged decision:* can a quadruped keep its footing on a landing when the left feet meet a different material from the right feet?
*BASE:* WEAKER. NS-01 to NS-12 (B§5) are acceptance stories with illustrative numbers; none is a registered experiment whose outcome is unknown in advance.

**1.12 Integration order (A§2.2).**
1. Capture source trees, features, compiler channels, lock files and transitive constraints in one *resolution receipt*; hash actual bytes when a tree is dirty.
2. FrankenSim's `constellation.lock` names different Torch and NumPy revisions from local heads, and three nightlies are in play (`2026-07-06` Sim, `2026-08-20` SymPy, `2026-08-31` Lean/NumPy/Torch).
3. Prefer one direct Rust closure for the stepping process; if incompatible, run **one pinned FrankenSim worker per device/process** and exchange whole jobs and bounded chunks, never per-link, per-ray or per-tick RPC.
4. Symbolic and proof work run in separately pinned build jobs, cached by expression, assumptions, checker and compiler profile; an unavailable checker leaves a proof pending.
5. Extend the owner when a missing capability is a physics primitive with other consumers; queue an upstream ask with one reproducible failing fixture.
6. External references generate fixtures at development time only; "a simulator comparison with a shared solver has correlated error".
*BASE:* HAS most of it (B§25). The whole-job worker fallback (3) is new: BASE's only fallback is KILL-FSIM lifting.

**1.13 Architecture and serialization (A§3).** Pipeline: CLI/MCP/gym → validate (dimensions, frame graph, realizability, clocks, capabilities) → compile assembly + task into a typed hybrid system with scheduled kernels and a resource plan → run worlds (sensor buffers → estimator → controller → actuator ports) → trace chunks and checkpoints → comparisons, counterexamples, viewer, next edit. The mission compiler sits *above* this graph.
- A compiled object "records exactly which source fields influenced it" (moving a camera changes extrinsics, imagery, occlusion and fitted cable mass; a display label does not rebuild a BVH).
- Three representations: versioned manifest (authoring), canonical typed bytes (identity), packed arrays (hot state). SI canonical; each authored field is quantity + unit + source; optional measurements carry explicit state ("a zero-valued missing field loses information").
- **Artifact envelope:** schema major/minor, type, canonicalization revision, payload digest, parent digests, generator pin, unit/frame profile, validity region, byte length, source/license.
- **I-JSON rule:** exact 64-bit IDs, absolute nanoseconds and rationals travel as canonical decimal strings, because a binary64 client parses 9007199254740992 and 9007199254740993 as one number; bounded counts stay numeric; test a JS round trip against the native decoder.
- Logical IDs (world, agent, tick, part, sensor sample) are public; dense device indices are private permutations with an emitted map.
*BASE:* WEAKER. BASE has content hashes and canonical JSON (B§12.1, B§9) but no field-level influence record, no validity region in the envelope and no wide-integer wire rule.

## 2. Robot design language ("design calculus"), edits and versioning

**2.1 Assemblies are typed open systems (A§4.1).** A part has an inertial frame, spatial inertia about a stated point, geometry variants and named ports; a port has a frame, admissible connections, state space, conjugate effort/flow variables and units. The assembly description is a **symmetric monoidal category of typed interfaces**: objects are finite ordered interfaces; a morphism relates boundary variables and internal state trajectories under constitutive laws; tensor is side-by-side placement; composition identifies a compatible port pair, applies its junction law and hides the connection. Junction laws: rigid mechanical (identify twists in a common frame, balance signed wrenches); electrical node (identify voltages, balance currents); read-only signal (producer, typed consumers, fan-out rule). The symmetry exchanges factors with an explicit channel permutation. Feedback introduces algebraic constraints, and the compiler resolves causality or returns a singular algebraic-loop diagnostic. Semantics are *relational*: a relation may have several admissible solutions.
- *Tests:* associativity up to renaming is a metamorphic test; copying an encoder signal is legal, while copying a power port doubles energy and fails; exercise all three junctions with a battery, motor, encoder and a reversed gearbox frame.
*BASE:* HAS the same core (C-12 operad with five functors). ASTRA adds the copy/no-copy rule for signal versus power ports, relational semantics and the algebraic-loop diagnostic. BASE's five functors and Kleene closure are richer downstream.

**2.2 From assembly to stochastic control system (A§4.1).** Each compiled assembly gets spaces X, U, Y and a transition kernel K(dx′ ∣ x, u). Where contact admits several continuations, keep a **transition relation or set of kernels** until a declared selector or an empirically justified law resolves them: "a solver's choice of pivot or contact order cannot supply the probability law." X is extended with noise-process memory, clocks and packet queues so the step is Markov; a sensor kernel O(dy ∣ x′) on the extended state implements delayed or partial observation; a policy is a causal kernel on history or belief.
- *Persistent-uncertainty fixture:* a fixed unknown gain of 1 or 2 with commands +1 then −1 gives net displacement 0 in either world; redrawing the gain each stage adds spurious offsets −1 and +1.
- *Symmetry test:* K(· ∣ g_X x, g_U u) = (g_X)_* K(· ∣ x, u), plus the observation analogue; changing a foot material can preserve an encoder permutation while breaking transition symmetry, recorded separately.
- *Lowering semantics:* decode device state and compare stepping before and after lowering under a stated metric, horizon, event tolerance and error estimator. "Equality of program shapes carries no implication about agreement of the physical trajectories."
*BASE:* LACKS. BASE defines the step and randomization (B§14.3, B§19.5, B§27.4) but never the closed-loop system as a kernel or relation, and it redraws by `(WorldAddr, step, stream_id)` with no rule for uncertainty shared across time.

**2.3 Part families with first rejection fixtures (A§4.2).**

| Family | Required fields | First rejection fixture |
|---|---|---|
| Rigid link | Positive mass, COM, inertia about COM, collision/visual frames, geometry source | Principal moments violate the triangle inequalities |
| Joint | Parent/child frames, screw axis and pitch or constraint type, travel, velocity, strength limits | Prismatic millimetres read as radians |
| Transmission | Signed gear ratio, efficiency or loss law, rotor inertia, backlash/deadband | Reverse drive produces free electrical energy |
| Actuator | Command mode, current/torque/speed envelope, lag, saturation, thermal parameters | Stall torque available indefinitely at high speed |
| Drive wheel | Loaded radius, tread material, width, axle, suspension, permissible load | Changed wheel intersects the body at nominal mount pose |
| Track | Sprocket, idler, belt path, tension, patch widths, slip/shear profile, permitted fidelity | Turning in place at zero scrub work on a frictional floor |
| Foot | Sole geometry/material, compliance, joint transform, load and impulse limits | A point foot silently acquires torsional support |
| Sensor | Intrinsics, lever arm, noise family, clock, range/rate, visibility layer | Measurements with no timestamp or an unknown frame |
| Power source | Usable energy, voltage/impedance curve, current limits, thermal/cutoff policy | An empty battery keeps supplying commanded power |
| Passive part | Fastening pose, mass law, exceptions for massless markers | Swapping a payload leaves assembly inertia unchanged |

*BASE:* HAS the components (B§12.1) and refusals (B§12.4); the per-family negative fixture is a direct fit for BASE's negative-control registry (B§30.8). Adopt verbatim.

**2.4 Design variables, locks and witnesses (A§4.2).** A variable declares dimension, bounds, prior, allowed edits and dependent derived values. Mass and lengths are positively parameterized; pseudo-inertia checks accompany searches over moments; a discrete part swap is a topology edit with a separate compile key. An agent can *lock* outer envelope, part availability, sensor budget, mass or electric power. An infeasible candidate gets a witness naming the violated inequality and part. *BASE:* HAS bounds, manifold kind and provenance (B§12.1). LACKS priors, user locks and the witness-naming rule (BASE returns ranked repairs instead, which is better for agents; keep both).

**2.5 Mass-support bound (A§4.2).** A part whose mass lies in a sphere of centre o and radius R must satisfy ‖c − o‖² + tr(I_C)/(2m) ≤ R². The left side is the mass-weighted mean squared distance from o. A centred 1 kg part with three principal moments of 0.008 kg·m² passes the triangle and pseudo-inertia tests yet needs 0.012 m² inside a 0.10 m sphere that allows 0.010 m². An isotropic thin shell (moments 1/150 kg·m²) reaches equality. Apply it to declared mass support, never to an unrelated collision proxy. *Why:* pseudo-inertia positivity admits inertias that no body inside the envelope could have. *BASE:* LACKS (C-03 tests P ≻ 0 only). *Evidence:* arithmetic verified; fixture in `followups/r2_contracts.py`.

**2.6 Geometry and mass provenance (A§4.2).** Parts provide measured geometry, parametric solids or a finite catalog. Derive mass and inertia from density when watertight geometry justifies it; if a catalog gives independent mass properties, keep both and compare; mark designs infeasible *before training* when parameters cross an assembly, interference or material limit. *BASE:* HAS (C-03 default geometry-derived inertia).

**2.7 Import and export (A§4.3).** A documented URDF subset first; echo every unsupported element with file location; expand xacro in a pinned external tool, retain the expanded document, never execute scripts inside the studio; MJCF and SDF later through feature matrices. Each export has a loss report covering closed loops, sensor latency, transmissions, mimic joints, contact law, covariance and controller assumptions. Round trips compare physical meaning and mapped IDs. *BASE:* HAS and is stronger (B§12.5: URDF and MJCF from day one, in-house XML reader, CL-M mapping). ASTRA adds the xacro policy and export-side loss items.

**2.8 Worked substitution and patch format (A§4.4).** An 8 kg cart, 0.06 m loaded wheel radius, 1.2 N·m at each of two driven front shafts: 40 N ideal tread force; at 0.075 m, 32 N. At a 0.012 m lip the geometry improves; the test decides which effect wins.

```yaml
parent: cart-a@sha256:<parent>
operations:
  - {op: set, path: /families/drive-wheel/loaded_radius, value: 75, unit: mm}
  - {op: derive, target: /families/drive-wheel/inertia, from: tread_and_hub_geometry}
constraints:
  locked: [motor_part, battery_part, chassis_envelope, payload, task]
  require: [axle_clearance, current_limit, mounting_fit]
```

Rules: recompute the settled equilibrium per design (a robot initialized with wheels inside the floor invalidates the pair); a buildable cart that stalls stays a failed trial. *Quasi-static oracle:* for a rigid wheel of radius r at a sharp lip h < r under axle load W, the lever arm is x = √(2rh − h²); a pure axle couple must supply W·x; a pure horizontal push must supply W·x/(r − h). The couple arm rises from 36.0 to 40.7 mm while the push/load ratio falls from 0.750 to 0.646. *BASE:* WEAKER. BASE has typed edits with symmetry effects (B§12.2) but no patch document with `parent`, `derive`, `locked` and `require`, and no settle-per-design rule. ASTRA has no edit taxonomy, inverses, blame or bisect; BASE's lineage (B§22.5) is stronger.

**2.9 Versioning and invalidation (A§3, A§10.1).** `design.patch` takes an expected parent, typed operations and an idempotency key, and returns a new immutable version, a structural and parameter diff, and the *invalidated derived assets*. A stale parent returns `E_STALE_PARENT`. Schema migration reads the old object, writes a new one with migration provenance, and keeps old replay possible with its worker. *BASE:* HAS content-addressed lineage; LACKS a returned invalidation set and a migration rule.

## 3. Mathematics: geometry, dynamics, compiling algebra into kernels

**3.1 Conventions and state space (A§5.1).** Q = SE(3) × ∏ Q_i with joint factors a circle, interval or line. Limits cut a feasible subset; loop closures are level sets; the regular part is a manifold where the constraint Jacobian has constant rank, and singular poses, unilateral contacts and mode changes need a **stratified** description. State also includes motor, battery, thermal, contact-memory, estimator and controller coordinates. T_AB maps B coordinates into A; body perturbations act on the right; twists are angular-then-linear, wrenches torque-then-force; V_A = Ad_{T_AB} V_B and F_A = Ad_{T_AB}^{−T} F_B, so F_AᵀV_A = F_BᵀV_B. A device struct-of-arrays is a storage layout with a stated lift/project map to `fs-ga::Se3`. Test sets: tiny angles, translations near the origin, rotations approaching π from both sides, sign-equivalent quaternions. A derivative query at a chart cut requests another chart or receives a **typed refusal**. *BASE:* HAS (B§9, C-01, C-02), and avoids chart cuts by design (Cayley, unit-complex revolutes). ASTRA's stratification language and chart-cut refusal are additions.

**3.2 A FrankenSim defect found (A§5.1).** The pinned `fs-mbd` planar drive: start at heading 32 rad, wheel speeds 1 and 1 + 6·10⁻¹³ m/s, track 0.5 m, 400 steps of 1/400 s. Both wheels advance but the owner returns **zero translation**; the true one-second result is about (0.83422336, 0.55142668) m. Cause: tiny heading increments round away before the subtraction of trigonometric values. Independent formula: Δp = v·Δt·sinc(δ/2)·(cos(θ + δ/2), sin(θ + δ/2)) with δ = ω·Δt and sinc(0) = 1; a unit-speed half turn through +π gives the chord (0, 2/π) m. W04 tests exact straight travel, near-zero curvature, wrapped and unwrapped headings, and incremental versus one-shot integration. *BASE:* LACKS. BASE cites `planar_drive` as the SE(2) kinematics foundation for C-07 without qualification. *Weakness:* unverified by me; the mechanism is plausible (ulp(32) ≈ 7·10⁻¹⁵ exceeds the 3·10⁻¹⁵ step).

**3.3 Lie algebra as executable mechanics (A§5.2).** T(q) = ∏ exp(Ŝ_i q_i)·M; tree evaluation shares prefixes; Jacobian columns are transported screws. "A single reversed adjoint should fail at least three independent fixtures." Smooth motion: M(q)·v̇ + h(q, v) = B(q)·u + J(q)ᵀf + f_ext, q̇ = 𝒯(q)·v. Use ABA and RNEA in production; build a dense mass matrix only for independent checks, never one per world. Conservation claims name the quantity, symmetry, boundary conditions, integrator and tolerance; group structure and symplecticity are separate properties with separate tests. *BASE:* HAS and is deeper (C-04, C-05). Note the tension: BASE's batched step *does* materialize a dense mass matrix per world (B§14.3 stage 6–8, CRBA + Cholesky), which ASTRA advises against.

**3.4 A numerical witness reproducible on paper (A§5.3).** Planar 2R, lengths 0.4 m and 0.3 m, angles 0 and π/2, axes +z. Tool point (0.4, 0.3) m. J = [[−0.3, −0.3], [0.4, 0.0]] m/rad. Tool force (10, 0) N gives both joint torques −3 N·m; rates (0.2, −0.1) rad/s give tool velocity (−0.03, 0.08) m/s; both power computations give −0.3 W. For a space screw column (ω_i, v_i) the point-velocity column at p is v_i + ω_i × p; pair the space Jacobian with the wrench [p × F, F] about the origin, and the point Jacobian with F. **Taking the lower three rows of a space screw Jacobian fails this fixture.** Compile the same part graph into a symbolic expression, a CPU operator and a device kernel. *BASE:* LACKS a named paper-checkable fixture of this kind (G0 laws are random property tests). Adopt as the first M0 fixture.

**3.5 Port-Hamiltonian composition (A§5.4).** ẋ = (J(x) − R(x))·∇H(x) + G(x)·u, y = G(x)ᵀ∇H(x), J = −Jᵀ, R ⪰ 0; energy rate uᵀy − ∇HᵀR∇H. Interconnection through a Dirac structure; transformer port for gearing. DC actuator: L·di/dt = V − R·i − k_e·ω, τ = k_t·i, rotor inertia, driver current limit, one thermal capacity/resistance pair. Separate motoring from regenerative and dissipative braking; the driver decides whether recovered energy reaches the battery, heats a shunt or is clipped. Series elastic actuators add spring energy with separate shaft and output positions. Heat stored in a modeled thermal capacity is *stored energy*, and counting it again as a loss creates a false defect. Record the budget per mechanism, per episode and **at the earliest offending event**. *BASE:* HAS (C-12, B§13, B§23.4), with a fuller actuator ladder. ASTRA adds the braking-mode distinction, the heat double-count trap and first-offending-interface localization.

**3.6 Finite groups and broken symmetry (A§5.5).** Compute candidate automorphisms using graph colours (part type, side-specific limits, gear direction, material) and verify each generator on transforms, inertia and channels. Under orthogonal P a polar vector maps by P and an axial vector by det(P)·P, so a mirrored leg may need an encoder sign change; reflections are not in SE(3). **Intersect the candidate group with the stabilizers of payload, gravity, boundary conditions, task, observations and current contact mode** before reducing a calculation. For stochastic augmentation a distribution-preserving action may pair two *different* worlds; exact reduction inside one world needs invariance of that world. Isotypic projector P_λ = d_λ·|G|⁻¹·Σ_g conj(χ_λ(g))·ρ(g); an equivariant *nonlinear* map need not decouple.
- *Two-latch fixture:* two identical latches must close exactly one. At a reflection-fixed observation a deterministic equivariant controller must issue matching commands, and both matching commands fail; a controller drawing one choice uniformly is equivariant *in law*. "A failure of tied-policy search excludes only that policy class."
- Compare an equivariant policy conditioned on transformed terrain, an augmented ordinary policy and an unaugmented baseline; a quadruped crossing a one-sided slippery patch must be allowed asymmetric actions.
*BASE:* HAS detection, representations and equivariance (C-09, A-03, BET-07). LACKS the stabilizer intersection, the pathwise-versus-in-law distinction and the latch counterexample, each of which is a correctness condition for BASE's equivariant policies.

**3.7 Hybrid automata, event derivatives, gait stability (A§5.6).** A contact mode has active inequalities, bilateral constraints, a smooth flow, guards and resets. Events: touchdown/liftoff, stick/slip, joint-limit impact, wheel-leg deployment, electrical protection, keyed by stable geometry and clock identity. Simultaneous events use a coupled solve (forcing an order can change outgoing velocity and a gait's basin). **Saltation matrix** for a transverse guard g(x) = 0 with reset R: Ξ = DR + (f⁺ − DR·f⁻)·Dg / (Dg·f⁻). Record chart, guard margin, event identity and the transversality denominator. Near grazing, ambiguous simultaneity, changing active sets or frictional degeneracy, **refuse an ordinary gradient** and return the offending state and directions; fixed-mode derivative, one-sided estimate, generalized derivative and smoothed surrogate each carry their own label. Poincaré section at a repeatable foot event; compose tangent transports and saltations over one cycle; remove phase and group drift; Floquet multipliers probe *local* stability only. *BASE:* LACKS. BASE's fast tiers do not locate events (B§14.6), gradients through contact are deferred to M6, and D-8 has no derivative-validity labels.

**3.8 A research program with an economic use for each theorem (A§5.7).** Eight rows, each with the agent's question, an executable artifact and the *condition that retires the optimization*.

**3.9 Symbolic and formal compilation (A§5.8).** Six steps.

## 4. Contact, terrain interaction, solver orchestration

**4.1 One transaction per accepted physics interval (A§6.1).**
1. Read committed state, pending actions and external forces; find the next clock boundary and a trial step; keep the active-set warm start and persistent friction state.
2. Broad phase on **swept bounds**; narrow phase yields feature pairs, normal, witnesses, material pair, signed gap and *error*; self-collision exclusions come from actual adjacency and stay inspectable.
3. Locate first impacts by continuous queries or conservative advancement; split at an event or **refuse progress at the refinement limit**.
4. Advance to the pre-impact time; evaluate all event rows on that common state; resolve the coupled impulse once per independent island; dynamic props take reaction impulses; a moving prescribed surface supplies boundary work.
5. Invalidate witnesses, redetect, advance the rest; check clocks, loads, limits, residuals, work balance, path admission and event count. Test: a ballistic drop with known impact time, outgoing velocity and remaining flight.
6. **Publish atomically at a fence.** A failed candidate is invisible to the controller; bounded retries restore *all* state including warm starts, queues and noise state; a failed final attempt ends with a numerical failure code.
*Why:* the controller must never see a half-step, and tunnelling must be a detected refusal. *BASE:* WEAKER on semantics. BASE's fast tiers are fixed-step with a speculative margin and no event location (B§14.6, B§15.2), audited by the referee on sampled windows. BASE has no commit fence, no retry-restoration rule and no numerical-failure-versus-physical-failure distinction at step level. *Weakness:* ASTRA never says how this transaction batches on a GPU; adaptive splitting conflicts with BASE's lockstep static launch graph.

**4.2 Refinement law for random inputs (A§6.1).** A random input over an interval must be consistent under step splitting. For a scalar Brownian driver with stored increment S over duration h, draw the midpoint increment as S/2 + √(h/4)·Z and set the second to S minus the first; store or reproducibly address the interval tree across retries and checkpoints. Redrawing a rejected increment biases the law: for a fair sign, keeping positives and redrawing negatives once raises P(positive) to ¾. Test split/rejoin, step rejection and device migration on the same noise path. *BASE:* LACKS. Counter-based streams keyed by step (B§27.4) are not refinement-consistent if the step ever changes.

**4.3 Laws and units (A§6.1).** Frictionless inelastic impact 0 ≤ p_n ⊥ v_n⁺ ≥ 0; Newton restitution with recorded multi-contact applicability; Coulomb disk of radius μ·p_n with maximum dissipation. Impulses are N·s and forces are N; one threshold applied to both is dimensionally wrong. *BASE:* HAS (C-06), with a convex compliant fast law.

**4.4 Coupled constraints (A§6.1).** W = J·M⁻¹·Jᵀ in tree coordinates. With independent bilateral rows A: P = M⁻¹ − M⁻¹Aᵀ(A·M⁻¹·Aᵀ)⁻¹A·M⁻¹ and W = J·P·Jᵀ. For a moving bilateral A·v⁺ = b, first correct v_f by M⁻¹Aᵀ(A·M⁻¹·Aᵀ)⁻¹(b − A·v_f), then add P·Jᵀp.
- *Tied-sliders fixture:* two tied 1 kg sliders reaching a wall at 1 m/s need a 2 N·s wall impulse; applying an isolated 1 N·s and then imposing the tie leaves them moving *into* the wall at 0.5 m/s.
- Redundant contacts admit several impulse distributions: compare observable post-event motion, total impulse and work; never infer a pressure map from one resultant wrench; patch contacts define centre of pressure, torsional capacity and quadrature.
*BASE:* WEAKER. Closures are compliant equality rows (B§14.6); there is no indeterminacy rule except the Painlevé row (B§15.7).

**4.5 Migrating contact witnesses (A§6.2).** The inspected sustained path (`articulated_contacts/step/sustained.rs`) assumes fixed material witnesses and frame; rolling around a sharp lip changes both. Build an explicit flat-to-edge-to-top transition, localize witness pairs with a consistent world contact point at touching, and transport or reset tangential memory under the chosen friction law. `tri_wheel_cluster.rs` supplies finite-riser geometry only; advancing a torque-driven wheel is a separate dynamics deliverable. *BASE:* LACKS this finding. It bears directly on BASE's M1 referee rollouts over "planes and primitive obstacles".

**4.6 Regimes (A§6.2).**

| Regime | Initial implementation | Higher fidelity and transfer experiment |
|---|---|---|
| Wheel on hard floor | Loaded round collider, motor torque, normal reaction, combined slip | Fit longitudinal, lateral and rolling-resistance curves at several loads; transfer to a withheld load |
| Foot on floor | Convex sole or declared points; compliant or rigid unilateral law | Measured load-deflection, tangential response, rocker geometry; vary cadence |
| Skid steer and tracks | Distributed belt-ground patches with belt speed and yaw scrub | Link-resolved belt, idler and tension where obstacles demand; cross-check turning radius, sinkage, work |
| Loose terrain | Parameterized bed with validity range for pressure, slip, sinkage | Drawbar pull, rut depth, compaction on an independent bed |
| Soft pad or tire | Lumped compliance and dissipative ports | FrankenSim material/solid coupling on a patch; held-out indentation |
| Closed loop or wheel-leg switch | Tree plus bilateral rows and unilateral contacts | Constraint rank, assembly branch and response across a singularity |
| Grasp | Finite friction cones, moving counterpart, lift test | Slip wrench and tactile uncertainty with varied mass and off-centre load |
| Wet or greasy surface | Spatially varying calibrated friction distribution | Repeated sled or wheel tests recording material, wetness, temperature, cleaning |

*BASE:* HAS a comparable ladder (B§15.3–15.6) with named models (Bekker–Wong, Janosi–Hanamoto, resistive force theory, brush/Fiala, elliptic cones) that ASTRA omits. ASTRA adds the transfer-experiment column and the grasp and closed-loop rows.

**4.7 Contact capacity (A§6.2).** Expose limits per solver and revision (`MAX_CONTACTS = 21` in the sustained solver; other paths differ). Detect overflow at compile time for static maxima and again at runtime. Options: a documented patch model with a qualification fixture, a larger admitted owner solve, or a named capacity refusal. "Silently removing over-cap contacts biases the exact robots the gym is meant to compare." *BASE:* HAS (fixed capacity, `Degraded`, B§14.3). ASTRA adds the *bias* argument: tracked robots overflow where point feet finish (risk row in A§16).

**4.8 Calibration and convergence (A§6.3).** Declare physical and numerical parameters separately ("a smaller time step must not silently stiffen a fitted foot spring"). Refine time step, geometry LOD and solver residual separately, then jointly on hard cases. Compare integral and event quantities (peak impulse, contact time, path, electric energy, slip, terminal class); for decorrelating nonsmooth trajectories compare event distributions and design rankings. Penetration is an error in rigid geometry and a state in a compliant model. Standard set before enabling a backend profile: sphere drop, frictional incline, moving belt, two-foot landing. *BASE:* HAS the fidelity ledger and dt-sensitivity detector (B§14.5, B§19.6), which are more systematic; ASTRA's physical/numerical parameter separation is the missing rule.

## 6. Sensing and time

**6.1 Definition (A§8).** A sensor maps a *history* of physical states and a calibrated stochastic process to a timestamped observation with frame, units, covariance, validity mask and quality flag. The gym cannot implement a camera by asking the viewer for its latest frame. *BASE:* HAS (B§17.1, GATE-SENS-03).

**6.2 Instrument models (A§8.1).**

| Sensor | Geometry and measurement | Perturbations and first independent check |
|---|---|---|
| Encoder | Angle, quantization, orientation, velocity window | Wraparound, backlash, sampling delay; known tick count |
| IMU | Angular velocity; specific force with lever-arm angular acceleration and centripetal terms | Bias random walk, scale, misalignment, saturation; at rest reads opposite gravity; free fall reads zero; spinning offset mount |
| Motor current, temperature, battery | Driver and thermal states through calibrated readout | ADC clipping, lag; RL step response, thermal cooldown |
| Foot switch, force/torque | Finite-area sole or sensor-frame wrench; **accumulate continuous wrench over the exposure, add impact impulses once, divide by exposure** | Hysteresis, drift, bandwidth, coadjoint shift; dead weight, known offset torque |
| RGB camera | Pinhole/distorted rays, exposure interval, radiometry, per-frame transforms | Blur, rolling shutter, glare, shot/read noise; checkerboard reprojection, moving bar |
| Depth/RGB-D | Ray length versus optical z, intrinsics, registration | Grazing, near plane, occlusion, specular/transparent flags; plane at known angle |
| LiDAR | Per-beam pose and time, range/intensity convention | Dropout, motion distortion, quantization; analytic sphere, moving plane |
| Tactile array | Finite taxel footprints, normal/shear saturation | Aliasing, hysteresis; resultant versus taxel integral |
| Wheel odometry | Encoder displacement conditional on rolling | Circular arc on dry floor, deliberate slip on wet tile |

IMU formula: a_P = a_O + α × r + ω × (ω × r), specific force R_WSᵀ(a_P − g). A freely falling sphere spinning at 5 rad/s with a 0.10 m perpendicular offset reads 2.5 m/s² radially inward. Use the pinned `prepare_point_motion`, `point_motion` and `specific_acceleration_world` APIs and test that gravity is applied exactly once for prescribed and floating bases. Noise streams are keyed by logical sensor, episode, sample and component; a missing depth return carries a mask and reason. *BASE:* WEAKER. BASE lists the proprioceptive and ray sensors with noise, delay and rate (B§17.2–17.3) but defers RGB to M5 as [F], has no rolling shutter, exposure integration, tactile array, impulse-in-exposure rule or lever-arm fixture.

**6.3 Clock contract and causality (A§8.2).** Integer simulation times and **rational periods with a deterministic phase accumulator**. Seven distinct instants: emission, exposure start, exposure end, capture timestamp, delivery time, decision tick, actuator effective time. 400 Hz physics, 100 Hz IMU and 30 Hz policy coexist "without rounding the policy to every thirteenth physics step"; the scheduler inserts a substep, an interpolation with declared error, or a declared sample-and-hold; every held value exposes its *age*.
- **Boundary order at time t:** commit physical state; close exposures ending at t; enqueue samples; deliver packets with delivery time ≤ t; evaluate the controller; latch a zero-delay command for the following open interval.
- Half-open window convention for impulses: a 0.2 N·s impact in one 10 ms exposure contributes 20 N to its average and 0 to the adjacent exposure.
- An out-of-order arrival may update a buffered estimator's future outputs, but prior actor decisions and the observation actually delivered at each decision are preserved.
- A camera straddling an impact samples the segmented pose history; a linear blend across a velocity reset fabricates blur and inertial acceleration.
- Checkpoints include scheduled callbacks, pending packets and action queues; test a checkpoint just after shutter open, after a dropped packet and before a controller update; precompute a latency bound per task and report budget exhaustion if history buffers cannot cover the exposure window.
*BASE:* WEAKER. BASE has integer ticks of a rational step with sub-schedules as *integer ratios of the physics tick* (B§9, B§14.4) and "noise, delay and rate" per sensor. It has no delivery-versus-capture distinction, ordering rule, age field or checkpointed packet queue. This is the semantic base for everything in §12 below.

**6.4 Estimation on groups (A§8.3).** Truth, measurements, belief and policy observations live in separate namespaces with declared access. Invariant filtering with a stated left/right error and covariance transform; biases, delays and uncertain contact add terms, so *evaluate* log-linearity. Position and yaw are gauge freedoms under proprioception plus gravity; verify the unobservable subspace analytically and by finite perturbation; augment with contact points on touchdown, marginalize on liftoff, downweight slipping contacts. Compare normalized innovations, covariance coverage and aligned drift against a conventional EKF on identical packets; "an estimator that reports small uncertainty while drifting is a distinct failure".
- **Gauge rule for scoring:** for a metric gravity-referenced estimator permit one translation and yaw per trajectory. A fitted scale hides error entirely (a 2 m estimate of a 1 m motion has zero residual after a factor of ½).
*BASE:* HAS the InEKF and privileged-versus-estimated reporting (B§18.2). LACKS the gauge-alignment rule, the EKF comparator and out-of-sequence handling.

## 7. Controllers, tasks, the gym API, learning

**7.1 Inspectable baselines (A§9.1).** Per morphology: an initial controller, a next control experiment and required evidence. Differential drive (SE(2) body-error tracking with current-saturated wheel loops), Ackermann, tracked (skid-steer with slip estimate; then torque allocation minimizing scrub energy), quadruped (scheduled crawl, task-space foot placement, stance force allocation; then whole-body inverse dynamics plus learned residual), hexapod/octopod (phase-oscillator network; then a symmetry-reduced gait family and a disabled-leg adaptation), humanoid (standing balance and supported weight shift before walking), wheel-leg (explicit drive/stand/step mode graph with readiness guards), mobile manipulation. **7.2 Gym interface (A§9.2).** A proposed **Python binding** following the Farama five-result contract (`studio.make(task=…, design=…, profile="reference")`, `reset(seed, options)`, `step` → `obs, reward, terminated, truncated, info`); the native worker stays the stepping authority. Spaces carry shape, dtype, channel IDs, units, frame, mask and sample age; normalization is versioned and invertible; non-finite actions are refused before state mutation; proposed and applied actions are both logged; **the final observation is preserved before any slot resets**. Termination covers success, failure and an intrinsic mission deadline; truncation is an external collection limit and carries the pre-reset observation for bootstrapping. Vector operation: explicit reset masks, logical world IDs, per-world seeds, recurrent hidden state; **default explicit reset**; dual-device batches reassemble in caller order; invalid physics is a study error excluded from policy updates but retained in benchmark and failure counts; a fall is a valid transition. *BASE:* CONFLICTS in two places. NONGOAL-05 rules out Python; and B§19.1 specifies masked *automatic* reset returning post-reset observations, which loses the terminal observation needed for truncation bootstrapping.

**7.3 POMDP, rewards, splits (A§9.3).** A task is a partially observable stochastic hybrid system. Rewards integrate running terms over simulated time and count event penalties once, so changing controller rate does not double reward per metre; evaluation metrics stay in physical units. An asymmetric critic may use privileged state under a training-only schema; freeze the actor schema and verify it runs with those channels absent. **Causal test:** perturb future terrain, hidden friction and delayed measurements independently; histories with identical delivered observations, past actions and policy random draws must yield the same command. *BASE:* HAS declarative task terms with representations (B§19.2), which ASTRA lacks. LACKS time-aware reward integration and the causal test.

**7.4 PPO correctness rules (A§9.3).**
- Separate GAE masks for value bootstrap and trajectory continuation. A true 8 s deadline with terminal reward 0 gives target 0; an external cut at the same instant with V = 10 and γ = 0.99 gives 9.9; if both flags occur, termination controls.
- Include time remaining in the actor input for a fully observed finite-horizon task, or declare the clock hidden.
- Fix a physical discount γ(Δt) = exp(−β·Δt) across control periods; scale trace decay by time.
- Freeze behaviour-policy weights and the observation normalizer during collection.
- **Action law:** compute ratios for the same random variable in collection and learning. Either store the sampled latent command with both densities followed by a deterministic limiter, or treat the applied clipped action with endpoint point masses. Clipping unit-variance Gaussians at +1 with means 0 and 1 gives an endpoint ratio 3.15149; ordinary densities at +1 give 1.64872.
*BASE:* LACKS all five (B§19.3 says "PPO with GAE, value normalization and an adaptive step size").

**7.5 Three defects in the suite's only PPO (A§9.3).** At FrankenSim `483d09c682f2`, executable calls to `fs_g1_train::ppo_update` found: (1) for a negative advantage and clip width 0.2 the update follows the ratio below 0.8 and clips above 1.2, the reverse of the clipped surrogate (finite differences of the loss in log σ at ratios 0.5, 1, 2 give 0, −0.5, −1; the owner gave −0.25, −0.5, 0); (2) for a critic output of 2 with stored value and return 0, the gradient into the shared critic bias was 0 where the squared-error objective gives 2; (3) concatenating two independently reset one-step episodes made the frozen policy's second ratio 1.582459 instead of 1. BASE knows only that the exported checkpoint has an all-zero policy head (B§19.4). *Evidence:* `followups/R1_ppo.rs` and `R1_ppo_native.py` build against the pinned commit; not run by me.

**7.6 Learning program (A§9.3).** Start with a small MLP and PPO *against the geometric baseline*; residual policies around a torque-limited baseline before end-to-end; randomize friction, mass/COM, delay, gains, sensor corruption and layout; hold out complete buildings and material conditions; a curriculum changes only training distributions and logs its schedule; report time to a target success rate and evaluation at matched compute ("more rollouts with an easier sensor model do not establish a win"). *BASE:* HAS PPO, SAC, distillation, behaviour cloning from the baseline, equivariant networks and exploitation detectors (B§19.3, B§19.6), which is broader.

**7.7 Joint search over body and control (A§9.4).** The outer loop proposes a typed edit, the inner loop fits or trains a controller under a fixed budget. **Two comparisons:** a shared controller isolates the body change; then each controller is retuned with equal resources to compare best systems. Track total simulation, optimization, training and compilation time. A candidate inheriting weights declares its warm start and gets a matched transfer baseline. Use tangent gradients for continuous parameters and discrete or derivative-free proposals for topology, foothold order and regime changes. A multi-objective archive keeps feasible non-dominated designs across energy, success, mass, thermal load and clearance, with intervals or *incomparable* verdicts. LACKS the shared-versus-retuned distinction, warm-start disclosure and holdout retirement.

**9.10 A native result that changes the placement rule (A§11.6).** The docking boundary classifier ran as a real Metal command buffer on the M5 Ultra and as a CUDA kernel on each physical 4090, with synchronization, readback and independent integer checking.
- Inputs are integer ticks of 2⁻²⁸; exact feasibility is 4E < U + 2²⁷. Two 65,536-row grids (dense near the boundary; more widely spaced), each with 1,820 exact ties and 34,590 positives.
- Raw float32 sign of the residual: 452 false inclusions and 23,438 false exclusions on the near grid; 110 and 4,779 on the spaced grid, identical on every device.
- **Guarded float32** defers to exact arithmetic when the absolute residual is at most 2⁻²¹ (the bound comes from the actual conversion/addition sequence: total error ≤ 5·2⁻²⁵). It decided 0/65,536 rows directly on the near grid and 58,254/65,536 on the spaced grid, with zero mistakes after fallback.
- Warm medians, near/spaced, µs: M5 CPU exact integer 33.75/35.33; M5 Metal guarded 288.5/308.75 (GPU-active only 6.9/12.7); trj CPU 780.6/423.4; 4090 device 0 1,660/1,363; device 1 1,248/1,631; dual 2,555/4,392.
- Follow-up: the exact integer predicate directly on the GPU (uint32 on Metal, int32 on CUDA) returned all 131,072 labels with zero fallback, still slower end to end than host integer.
- **Lesson:** "first choose a representation that preserves strict inequalities, then place it according to where the data and consumer already reside." Keep cheap exact facets on the host; for a device-resident pipeline test a fused exact predicate and the cost of emitting only ambiguous cases.

**10.7 Turning a simulation result into a physical prediction (A§12.3).**
1. Acquire a measured rig (one actuator, a ramp, a material pair, a known obstacle, an instrumented cart) with source, uncertainty, environment, calibration and acquisition rights.
2. Separate calibration from validation by hardware, condition or day. Fit an **affine offset-and-skew clock** from independent marks bracketing the trial; one pulse fixes only one combination. At 100 ppm, clocks coincident at start differ by 0.8 ms after 8 s. Fitting the offset to the crossing being scored erases the crossing-time error.

4. Publish a frozen prediction with interval and scoring rule; compare to retained measurements; a refit opens a new prediction version.
5. Feed discrepancy into future study intervals; a falsified ranking narrows the domain and becomes a regression.

**11.2 The registered first A/B (A§13.2).** Question: for the fixed motor and current-limited cart, does the 75 mm wheel improve loaded threshold delivery over 60 mm?
- **Cart:** front-wheel drive, four wheels; axles at x = ±0.16 m, wheel centres y = ±0.12 m; body box 0.40 × 0.20 × 0.08 m centred 50 mm above the axle line; 5 kg chassis, 2.2 kg bolted payload (0.18 × 0.14 × 0.08 m), four 0.2 kg cylindrical wheels 30 mm wide. - **Drive:** per front wheel a 24 V motor, k_t = 0.2 N·m/A, k_e = 0.2 V·s/rad, R = 1 Ω, L = 10 mH, ±6 A, gear ratio 1, shaft viscous damping 0.002 N·m·s/rad. At 100 Hz command wheel rate 0.30 m/s ÷ loaded radius; current command 2 A·s/rad on rate error, clipped. - **World and rules:** sill x ∈ [0, 0.10] m, height 0.012 m, sharp or 2 mm fillet; start stationary, front axle 0.5 m from lip, settled; μ = 0.8 nominal; g = 9.81. Success: the whole envelope clears x = 0.10 m and holds upright (roll and pitch ≤ 5°) for 0.5 s with no chassis strike, within 8 s. Limits: 35° roll/pitch, forbidden body/sill impact, current limit. Stall: saturated command and < 2 mm advance over 0.5 s.
- **Energy reporting:** mean energy conditional on completion *and* total energy of all attempts divided by completions (A: 10 J success + 20 J failure versus B: two 12 J successes gives 10 versus 12 and 30 versus 12 J).
- **Development batch:** 64 conditions, master seed 17, counter-based named streams: friction U[0.35, 0.95], payload fore-aft offset U[−0.04, 0.04] m, heading U[−2°, 2°], fair sharp/rounded. The 64-row input table is recorded before either design runs.
- **Rule:** effect (b − a)/n from discordant counts; two-sided 97.5% exact Clopper–Pearson intervals on B-only and A-only probabilities, opposite endpoints subtracted, giving ≥ 95% simultaneous coverage. Promote B if the lower endpoint > +5 points and hard feasibility holds; practical tie if the interval is inside [−5, +5]; inferiority if the upper endpoint < −5; otherwise inconclusive.
- **Pre-analysis of the rule:** exact enumeration shows *no* outcome at n = 64 can establish a tie (perfect concordance gives [−0.0662, +0.0662]); promotion with zero A-only needs ≥ 15 B-only; a tie first becomes reachable at n = 86 and only for (0, 0) among 3,828 pairs; with 5% B-only and 5% A-only the chance of a tie verdict is 0.9⁸⁶ = 0.0116%. So the 64 are a development batch and the holdout is sized prospectively. An alternative standalone equivalence test bounds the difference by the total discordance probability: zero discordances in 64 gives a one-sided 95% bound 1 − 0.05^(1/64) = 0.04573.
- **Pilot findings:** in a planar pilot of 156 design-condition rows, 62 passed the planar scorer and failed the quasi-static screen, 7 passed both, 87 failed both (agreement 94/156). Changing only the winding feedforward from R·i_ref to R·i changed 24/156 labels (60 mm: 8/78 → 18/78; 75 mm: 61/78 → 67/78). A sampled-data analysis explains it: for the 75 mm wheel with 0.0002 kg·m² added reflected inertia (total 0.00107890625 kg·m²), holding the current target 10 ms gives a one-tick spectral radius 1.4820 with target-current feedforward and 0.9207 with measured-current feedforward; an instantaneous-current approximation gives 2.7075 for both and misses the stable case.
- **Mechanism controls:** ideal flat-rolling force slope 2·k_t·K_ω/r² falls from 222.22 to 142.22 N/(m/s); set B's gain to 3.125 A·s/rad to match slopes; cross reflected inertia with control cadence in a registered 2×2.
*BASE:* LACKS a registered experiment. **11.3 Companion: quadruped on a split-grip landing (A§13.2).** A 12-actuator quadruped, one pinned crawl controller; sole A 80 × 40 mm versus sole B 80 × 70 mm, mass and inertia matched by an insert. ## 12. Inverse mission design (A§18)

ASTRA's centre of gravity. BASE has nothing equivalent; every item below is **LACKS** unless noted.

### 12.1 The user contract (A§18.1)

The unit of design is a **mission query**: admissible design grammar, part and fabrication tolerances, world family, observation interface, policy class, horizon, success and hard-loss predicates, and the *quantifiers that relate them*. The studio compiles the query into analytic exclusion, witness search, counterexample generation, measurements and selectively expensive forward simulation. "The gym is the execution engine for experiments chosen by the query."

Flow: {mission, world uncertainties, observations} + {parts, allowable site changes, fabrication limits} → **causal design game** → {exact or conservative family bounds; FrankenSim trajectories on CPU, CUDA or Metal → controller witness or counterexample} → **independent certificate checker** → admitted and excluded cells, plus unresolved cells with competing explanations → design the next probe or edit → back to the game.

| Query | Mathematical output | Use |
|---|---|---|
| `mission.synthesize` | Inner and outer feasible sets over named parameters and topologies, witness controllers, unresolved cells | Choose from a whole family of wheels, legs, transmissions, sensors |
| `mission.refute` | Scoped impossibility bound, or a witness defeating a specific design/controller | Stop an unproductive policy search; ask for the smallest change that relaxes the binding constraint |
| `mission.distinguish` | Smallest admissible intervention or instrument separating alternatives with different mission decisions | Decide whether to measure, move a mount or fund more simulation |
| `world.separate` | Executable, physically admissible world pair where a design ordering or diagnosis changes | Ship the exposing terrain or interior feature as a regression |
| `skill.transport` | Interface map and local policy with bounded error, or a counterexample | Reuse a skill on another morphology; retrain only named modes |
| `result.revalidate` | Surviving certificates, invalidated regions, required reruns and their cost | Change a motor or tolerance without redoing the qualified part |

Request schema:

```yaml
query: mission.synthesize/v1
design_domain: modular-carrier/catalog-1
mission: delivery-and-placement/v1
observations: actor/encoders-imu-and-finite-depth
free_parameters: [design]
quantifiers: [exists_causal_policy_per_design, forall_admitted_worlds, forall_admitted_executions]
independent_randomness: none
uncertainty: bounded-friction-payload-and-clock/v1
hard_constraints: [fits_loaded_door, payload_supported, driver_limits, goal_before_deadline]
objective: minimize_declared_part_cost
response: [inner_region, outer_region, policy_witnesses, exclusions, unresolved_cells, cost_bounds, candidate_cost_gap, next_test]
```

The body is a free output parameter of a set comprehension; a point query binds it; an existence query returns a Boolean or `unknown` with a witness or refutation of matching scope.

Example: the least expensive modular carrier that moves a fragile box from a rack across a wet strip onto a counter. Four choices change the answer: whether the controller sees a surface label; whether the policy can use earlier slip; whether the payload can be weighed first; whether a different policy may be trained per body. The studio can also return the minimum alteration of body, sensor *or world*: "a cheaper ramp strip, a different axle ratio and a better sensor become competing, testable engineering decisions."

**Chance constraints.** Name the population, the event and the confidence level. Preserve the joint law across stages or allocate failure budgets that sum to the allowance. Among 20 equally likely worlds two stages each pass in 19: if the failed worlds differ only 18/20 missions pass, if they coincide 19/20; independent stages give 0.95²; if each stage has *conditional* success ≥ 0.95 at every history reaching it, the product is a lower bound. A worst-case bound over a material interval differs from a probability over manufactured units. "The checker rejects evidence for the easier quantifier order." Reusing a simulation prefix after an intervention must pass the fork rules (§10.3).

### 12.2 A semantics that survives optimization (A§18.2)

- D: disjoint union of parameter spaces for typed assembly graphs, quotiented only by admitted interface-preserving isomorphisms.
- W: nonempty declared set of world conditions (geometry, physics, hidden parameters, initial-state uncertainty), scope fixed *before* testing candidates; reject an empty or inconsistent mission domain at admission.
- Π_Y: causal policies on the history of channel Y. T(d, π, w): maximal admitted executions. A(τ): Boolean acceptance predicate.

**Robust design family:** F = { d ∈ D : ∃π ∈ Π_Y ∀w ∈ W, T(d, π, w) ≠ ∅ ∧ ∀τ ∈ T(d, π, w), A(τ) }.

Rules attached to the definition:
- Each execution must progress to the horizon or a declared terminal outcome. Deadlock, Zeno behaviour and undefined dynamics cannot earn success.
- A numerical solver failure leaves the verdict **unknown** unless independent evidence establishes physical failure or impossibility.
- Strict, non-strict and equality atoms are evaluated with their declared comparators. At U = ¾, ε = 5/16 the docking residual is exactly zero and the strict predicate fails. Conversely on 0 < w ≤ 1 every realization has w > 0 though the infimum is 0; a uniform positive lower bound is a separately requestable robustness margin.
- In set-valued contact, a stick/slip fork with any failing admissible branch invalidates a universal success certificate.
- **The public answer carries I ⊆ F ⊆ O** with topology IDs, coordinate charts, units, parameter boxes and assumptions. Empty I means no certified witness so far; empty O excludes the family under the declared model; O ∖ I is work still to do.
- Index a design-dependent policy by the **known nominal build**; hidden as-built tolerances stay in the world until a calibration observation reveals them. Otherwise one certifies an unavailable choice. Record whether a cell shares one policy or has a constructively selectable policy per known design.
- An ordinary rollout can refute a *particular* controller; excluding a design under ∃π needs an argument covering every admitted controller, and a failed training run does not discharge it.

**Four proof rules.**
1. *Necessary-condition exclusion.* Relax controller and dynamics (any contact force in an outer wrench cone, any torque under an upper envelope). Infeasibility of the relaxation eliminates every covered realization. Record the set inclusions and the dual separating vector. Infeasible sample points do not eliminate their cell.
2. *Constructive inclusion.* One causal controller, admissible contact schedule, event guards and a sound reachable tube or exact witness for the whole cell; check actuator bounds, material domains and the mission predicate over the enclosure; branch conservatively at uncertain mode boundaries or return unknown; use the high-fidelity owner to hunt counterexamples.
3. *Monotonic inheritance or symmetry.* Move a verdict across a cell only under the conditions for that verdict. For exclusion transport the relaxation and the violating witness. For inclusion require a checked refinement preserving disturbances, causal information, realizable policies, mission outputs and all branches. Enlarging a convex set of contact forces admits more loads statically; broadening a physical sole may create a swing collision; the first cannot certify the second.
4. *Exact partitions and composition.* A union of proved inner cells is inner; to remove a cell E from O prove E ∩ F = ∅ (disjointness from known inner cells proves nothing). A mission contract composes with a subtask only when the first's guaranteed end set lies in the second's entry set with matching clocks, uncertainty dependencies and state memory. "Composition of two individually successful videos proves no such inclusion."

**Arithmetic and checking.** Interval/affine bounds with outward rounding; checked LP duals; a certificate can be *proposed* in low precision on CUDA or Metal, rationally reconstructed or enclosed, and checked on CPU; condition numbers, residual bounds, domain versions and strict/weak inequalities are checker inputs; sum-of-squares bounds with checked residual on polynomial subdomains; proof assistants for reusable *rules and translations*, never per wheel/terrain pair.

**Owners to probe.** `fs-sos` (polynomial models, SOS programs, interval verification), `fs-regime` (π-group basis, scaling maps, model admission), `fs-voi` (ranking-aware opportunity loss, unknown-resolution proposals), `fs-eproc`, `fs-checker` (checks packages outside the stepping process). The robotics-specific work is the mapping from causal mission and morphology to sound small subproblems and the cross-check back. Every mapping has a deliberately invalid fixture. **A downstream checker must reject an unknown proof kind or a changed quantifier even when artifact hashes are consistent.**

*BASE touchpoints:* GPUs-propose-referee-disposes (B§14.5) is the same shape for trajectories; BASE's `Certified` class (B§10.2) covers kernel identities only; BASE lists `fs-sos` and `fs-eproc` and never mentions `fs-voi`, `fs-regime` or `fs-checker`. *Weakness:* constructive inclusion over a contact-rich cell needs sound reachable tubes, which ASTRA does not have; the pilots are all scalar or static.

### 12.3 Design–world duality and minimal counterexamples (A§18.3)

Given feasible rivals d_A, d_B, search a physically admitted family for a world where the predicted preference changes with a practically important margin; "the smallest such change is often more informative than the maximum simulated reward" (one edge radius; a short compliant mat under load; a joint layout/optical/friction condition near a turn). "Small" is a lexicographic edit count in authored units, then normalized physical distance. Priors stay distinct from admissibility. Compile temporal goals into monitors on signed clearance, work, support, sensor age and completion time; freeze hard limits separately from shaping rewards.

**Loop:** propose a design → search for violating environments → reproduce the violation in the canonical owner → minimize the violating scene → update the admissible region. Carry *two* experiments through the loop, including the counterfactual edit that removes the effect. A shrinking trajectory whose failure mechanism changes gets a new event classification. A scene rewrite declares which of geometry, material, optics, clocks and actors it changes (moving a light alters depth dropout without altering friction; wetness may affect both). Give scenario-based baselines (Scenic) the same generator and monitors. *BASE:* LACKS adversarial world search; B§19.6's exploitation detectors perturb numerics, not worlds.

### 12.4 When a better body cannot rescue a blind policy (A§18.4)

Question: can more training on the present sensors ever satisfy the mission? Build an **observation indistinguishability witness**: two admissible latent states needing disjoint successful actions, with fixed probe actions, time, histories and policy information. For equal priors and a fixed experiment with distributions P, Q, the best distinguishing probability is (1 + TV(P, Q))/2, which caps success. With active probing, bound over all permitted probe strategies or label the bound as experiment-specific.

**Pilot P03.** Two payload classes needing disjoint final forces [2, 4] and [7, 9] N; a binary probe correct with probability 0.75. Exhaustive enumeration: blind 0.5; three independent reads 27/32; five 459/512; seven 3807/4096 (passes 90%). With one common fault bit shared across reads, accuracy stays 0.75 even after nine reads. A distinct 95% modality passes in one read. An independent audit: stopping at vote gap two reaches 90% with 3.2 expected reads and unbounded horizon; the chance of still waiting after six reads is 27/512; forcing a guess then gives 225/256 < 90%. So price delay and enforce the deadline for every sensing policy.

**Three engineering answers to a perceptual ambiguity:** extract information (load-sensitive wrist), move to acquire it (camera placement), or change the mechanics so the information is unnecessary (compliant passive gripper). Compare all three against a calibrated forcemeter and an optimal finite-belief controller; hold out common-mode faults and occluded placements.

**A body can remove the need for a sensor.** A displacement-driven jaw with series spring K closes by x mm on one of two elastic objects of stiffness 1 and 4 N/mm. F_j = x/(1/K + 1/k_j). With c = 1/K and stroke ≤ 6 mm, one command works on both classes exactly when max{2(c+1), 7(c+¼)} ≤ x ≤ min{4(c+1), 9(c+¼), 6}, an exact polyhedral family in (c, x). K = 4 N/mm, x = 4 mm gives 3.2 N and 8 N. Stiffness must be ≥ 28/17 N/mm at the 6 mm cap (stiffer object gets 7 N, softer 56/15 N); relaxing stroke reveals K ≥ 4/3 N/mm. "A conventional impedance engineer given these same equations can design the same jaw." Breaking the stiffness/grip correlation (same stiffness in both classes) defeats the passive jaw. *Evidence:* `mor/repro/P03-*`, claim C004 VERIFIED; arithmetic rechecked.

### 12.5 Transfer control by a physical interface (A§18.5)

Represent a skill at the task boundary by observable state, action/wrench interface, reachable predecessor and terminal sets, clock and environment assumptions. Seek a relation R(x_A, x_B) and a causal refinement map from abstract commands to target efforts: every admitted initial target state relates to an abstract state compatible with its observable history; for each abstract command the interface selects one target command using information available before disturbances; for every target disturbance and successor there is an allowed related abstract successor (an alternating simulation). **A target with successors {stable, fall} cannot refine an abstract stable-only transition by selecting its stable branch.** Approximate relations carry error and timing budgets small enough to preserve acceptance. Tray example: match tray pose, velocity, allowable contact wrench and acceleration limits; port only the stabilization objective when the target's reachable wrench tube covers the request; at the ramp crest return the contact mode, requested wrench, attainable set and a rerunnable counterexample. Three treatments at equal compute and source data: from scratch, a cross-morphology conditioned policy with full transfer learning, and interface-based transfer with limited adaptation. *Weakness:* no pilot.

### 12.6 Physics across design families on CUDA and Metal (A§18.6)

Batch many related *designs*, not only copies of one. Pack by joint topology, shared rigid subtrees, sensor graph, active contact mode and layout; continuous parameters in columns; motion subspaces as shared constants where homogeneous. **Segment a diverging batch at the first guard whose sign is ambiguous.** Exact common-subexpression sharing across designs requires identical inputs and rounding; reusing a *nearby* trajectory needs its own error certificate (smooth phases: local tangent metric, residual enclosure, horizon; guards: transversality margin, event-order separation, bounded reset map and event-time bound). Around grazing, redundant contacts or uncertain mode sequences fork to separate owner solves. Each native device must complete the closed loop on its own before a hybrid profile claims acceleration; proof-queue capacity and transfer time count toward decision time; "a fair comparator also caches graphs, factors and compiled kernels."

**Scaling limit.** If fraction f of matched wall time improves by r and the method adds overhead h, speedup ≤ 1/(1 − f + f/r + h). Infinite acceleration of 85% cannot reach 10×. With f = 0.97, r = 40, h = 0.02 the ceiling is about 13.5×. Measure the three terms on the *strong baseline's* critical path. "Never multiply a pruning ratio by a GPU speedup measured on work already removed." *BASE:* WEAKER. BASE buckets worlds by one `ModelId`; design sweeps would recompile per design.

### 12.7 A continuous morphology family with an exact answer (A§18.7)

A robot carries 400 N on four point feet at (±a, ±b); the centre of mass ranges over a rectangle of half-dimensions 150 mm × 75 mm; each foot delivers any independently commanded normal reaction in [0, 160] N; a = 1/3 m. **Minimum half-width b = 3/14 m.** At the positive corner the (+,+) foot must carry at least 90 + 15/b N; at the boundary the forces are (160, 130, 110, 0) N; reflections cover other corners and convexity the interior. At b = 0.20 m the foot needs 165 N. The boundary has zero reserve on two constraints.

**Generalization.** Template points q_i, feet p_i = A·q_i + d, load W, first moment P; set B = A⁻¹, e = −B·d. Then Σf_i = W and Σq_i·f_i = B·P + e·W. With 0 ≤ f_i ≤ c_i these are *linear in inverse geometry, ratings and vertex forces* when the mission vertices (W, P) are design-independent. Project the lifted polyhedron onto (B, e, c), or write the wrench zonotope with generators (1, q_i) and emit paired support inequalities per non-zero cross product of two generators and each mission vertex: at most 2·V·C(m, 2) rows for m contacts and V load vertices. Precedents: Bretl and Lall; Orsolino et al.

**Convexity can fail.** Feet at (±1 − e, ±1) m, each capped at 0.5 N, load W at the origin: the positive-x pair must supply W(1 + e)/2. Designs (e, W) = (0, 1.9) and (0.9, 1) each need 0.95 N and are feasible; their midpoint needs 841/800 N from a pair capped at 1 N. A convex hull through the two witnesses admits an infeasible body.

**Pilot P01.** Two exact formulations agreed on 11,520/11,520 body-load cases; the checker reconstructed 2,254 feasible allocations; 114/2,304 bodies cover the whole mission; HiGHS agreed on 102/102 spot checks. **A lifted robust LP and the projected formulation each reached the optimum in one solve**, so the specialized method ties. A passive equal-spring counterexample at b = ¼ m: active allocation (155, 135, 105, 5) N is fine; the passive suspension produces (175, 115, 85, 25) N. "The typed certificate must state whether the controller can realize the assumed load sharing and which load observations arrive in time." Use the lifted LP first; earn a specialized kernel through repeated changed queries with real timings. *BASE:* WEAKER. A-08 computes static-stability margins for *one* design. *Evidence:* claims C001, C002 VERIFIED. The pilot notes also record that a weak comparator (support polygon plus total capacity) accepted 1,596 bodies the exact model rejects, which is a ready-made negative control for A-08.

### 12.8 Let the robot design the instrument that would change its own design (A§18.8)

Two materials can produce the same force history at one pad radius and prefer opposite grippers at mission dwell; fitting a richer curve at that radius cannot choose the hardware. Give the studio a **grammar of experiments** beside the grammar of bodies: fixture compliance, pad radius, sensor position, command waveform, exposure time, preload. Compile an experiment through the same power, frame, observation and contact interfaces as a production body; return an executable simulated experiment, a bill of fixture parts and a measurement contract.

**Algorithm.** Keep the set of compatible physical mechanisms; partition them by the design decision they imply; choose the least costly realizable intervention whose possible readings separate incompatible decisions over admitted nuisance intervals; where observation sets still overlap return two witness mechanisms with opposing design margins; when mechanisms agree on the choice, skip identification; always admit testing the target directly.

**Pilot P02.** At a one-second handover the compact pad supports 29.66 N under both nominal laws; the broad pad supports 24.72 N with intrinsic relaxation and 41.15 N with radius-squared relaxation. A probe synthesized for three admitted laws (twice the reference radius, sampled at 125 ms) chose correctly in 675/675 in-class cases; **a fourth, delayed law followed the same early trace and reversed all 225 held-out decisions**. A programmed expert comparator tied the generator; the direct comparator (measure the other pad at mission dwell) was right in 900/900. The early procedure cut incremental probe time 3.33× on admitted cases at a modeled 0.25 s setup cost.

**Family consequence.** For a 75 N pull with additive independent pads, the minimum certified mass changes from three compact pads (300 g) to two broad pads (240 g) when the law changes. Additivity can fail (a common pressure regulator, coupled deformation), and wrench balance can fail even for independent pads: two pads at ±s with a 75 N pull at offset e carry 37.5(1 ± e/s) N; at e/s = 0.15 one needs 43.125 N, above the broad-pad upper bound (about 42.152 N) though the lower bounds sum to about 80.304 N. An audit found a permitted reading (q = 0.18, τ = 0.9 s, −0.02 read error) dropping the three-compact bound to 73.79 N. *Evidence:* claim C003 VERIFIED, C005 PARTIALLY_SUPPORTED. *Weakness:* artificial scalar laws and stipulated loads.

### 12.9 Design the robot, the facility and the handoff together (A§18.9)

**Brownfield logistics commission.** Inputs: a partial 3D survey of a stockroom, retail aisle and commercial kitchen; a catalog of body modules; permissible room changes; pack temperatures; delivery windows. Bottlenecks: a shared doorway and an unloading counter. Output: a Pareto set over body cost, facility-change cost, energy per delivered item, worst admitted delivery time and route availability after one module or charger drops out. Answers may be one modified carrier, two simpler robots with a handoff, a threshold retrofit, or a finding that every allowed alternative fails.

1. **Compile a surveyed site into possible worlds.** Register scans and CAD to a gravity frame; carry clearance, door swing, movable racks, friction, lighting, clock uncertainty and material provenance separately; attach actionable residuals (the one doorway width on which two solutions disagree).
2. **Compose mission stages across robots.** Each approach, latch, carry, handoff and recharge exports entry and exit sets, occupancy intervals, available observations, resource budgets and load-wrench limits. Two robots cannot spend the same reserve charge, use the doorway in incompatible intervals or both count the payload support. Search the **timed discrete schedule as a master problem** with continuous FrankenSim subproblems producing feasible witnesses and sound infeasibility cuts; a timed-out search leaves its candidate open. Give each actuator a named decision maker with its own history. *Fixture:* A sees the payload bit and B must choose a matching latch before observing A; a pooled-history planner succeeds on both bits, every deterministic local choice for B fails on one, and delivering the bit by commitment restores success.
3. **A priced world-edit grammar.** Removable ramp, sensor fiducial, docking pose, wheel or sole swap, repositioned handoff surface, each with installation time, access, floor availability, calibration, tolerances and maintenance. "Editing the floor and editing the robot enter the *same* budget." Report a lower bound, feasible alternatives and the remaining optimality gap.
4. **Operation over time.** Tire/track wear, changing traction, motor thermal reserve, battery sag, cleaning cycles; replay a hot restart and the loss of a charger at a handoff.
5. **Earn difficult matter one decision at a time.** Sloshing tote, hanging cable, compliant carton: start with rigid ballast, a damped pendulum and a single compliant contact; promote fluid, rod or textile coupling only where a held-out ranking changes.
6. **Return actionable counterfactuals.** Cheapest repair (or an infimum bound and a candidate's gap) under each change budget, the minimal obstruction for excluded alternatives, the smallest site survey that settles a tie, and a dispatchable simulated acceptance mission per survivor.

**Acceptance fixture:** two carriers, one counter, one door, two material states, one handoff. Enumerate the discrete schedules; hide a protruding payload corner, common loss of traction, skewed handoff clock and a supply change; require withdrawal of affected claims and a minimized failing scenario. Expand only after the fixture discriminates at least two feasible strategies and recovers each seeded failure. *Weakness:* by far the largest scope in either plan, with no pilot beyond the handoff bit and the two-finger bus check.

### 12.10 Can the first control input buy information for the last one? (A§18.10)

**Model.** Three one-second ticks, x₀ = v₀ = 0, acceleration g·u_k, hidden fixed g ∈ {1, 2}, piecewise-constant abs(u_k) ≤ U, target (x₃, v₃) = (1, 0). The only informative packet is the first velocity reading, arriving either before the second command or after the third is committed.

**Witness.** u₀ = ¼. An on-time packet identifies g = 4·v₁; then u₁ = 1/g − ½ and u₂ = −u₀ − u₁: sequences (¼, ½, −¾) and (¼, 0, −¼) reach (1, 0) exactly. With a late packet a causal controller issues one vector in both worlds and terminal position scales by g, so it cannot equal 1 in both; private randomization does not help. "The first action also acts as a probe."

**Pilot P05 (exact family).** With p = u₀ the terminal equations force u₁ = 1/g − 2p and u₂ = p − 1/g. Intersecting bounds for both worlds: 1 − U ≤ p ≤ (U + ½)/2 for U ∈ [½, 1]. Readings centred at p and 2p with additive error in [−ε, +ε] must be disjoint because the required next commands differ by ½. Maximizing separation gives **ε < (U + ½)/4**, equality excluded. At U = ¾: p = ¼ admits ε < 1/8; p = 5/8 admits ε < 5/16, a 2.5× larger tolerable sensor error on the same actuator. At equality both worlds can report 15/16 while requiring −¼ and −¾. An independently formulated scenario-tree LP comparator (17 actuator bounds × 33 error levels) matched 561/561 cells (344 admissible, 217 excluded, nine exact boundary cases) using 51 LP solves; all 561 late-packet cases are excluded.

**Hidden manufacturing tolerance reverses it.** Admit a third gain 33/32. At U = ¾, ε = 1/64 the reading (65/64)·p is possible for g = 1 and 33/32 for every first command, so both worlds receive the same remaining commands; final positions are c and 33c/32, giving a minimum worst error 1/65 m. Under the amendment **all 34,590 nominally feasible labels on each native grid reverse**. Rule: bind gain support, delivery deadline, error units and target tolerance to the classifier's eligibility. *Evidence:* `mor/repro/P04-*`, `P05-*`, `followups/docking_support.py` (Z3); derivation rechecked by hand. *Weakness:* a scalar toy; the plan says "no product or device timing follows".

### 12.11 Use geometric phase to invent locomotion (A§18.11)

Ask for the *least costly periodic shape change* giving a specified displacement with zero net yaw that fits a doorway. Pose g ∈ SE(2), shape r; on a qualified no-slip fixed-rank quasistatic stratum derive or learn g⁻¹ġ = −A(r)·ṙ. Start with two shape variables and one contractible loop; integrate ordered body twists for the holonomy; use connection curvature to propose small loops; keep group ordering for large loops. Contact-mode transitions need hybrid resets and fresh rank checks: "a loop in shape space that crosses slip or lift-off cannot borrow its old connection." - *Skid-steer fixture:* at fore and aft axles ±a, exact lateral no-slip needs v_y + a·ω = 0 and v_y − a·ω = 0, forcing ω = 0; yaw needs a separately qualified slip model.
- *Accessibility fixture:* with ẋ = u ∈ [0, 1], rank one still cannot reach negative x from zero; a finite mission needs the integrated witness.

### 12.12 What a portable certificate contains (A§18.12)

Readable on a machine with neither the agent nor a GPU. Exact rationals as reduced integer pairs with positive denominator, or outward-rounded intervals with declared implementation and precision. **Fields:** query bytes; unit, frame and clock definitions; ordered ports; model and actuator assumptions; plant and policy class digests; variable chart and cell bounds; quantifier order; horizon; proof kind; witness payload; checker build; expected verdict. Proof rules reject missing side conditions; the independently reviewable primitive equations travel in the pack ("a proof about the wrong translation of a contact law remains a physical error").

**Specimen for 12.7.** Feet ordered [++, +−, −+, −−], half-length 1/3 m, half-width 3/14 m, four 160 N capacities, 400 N weight, four horizontal first moments P = (Σx_i·f_i, Σy_i·f_i) = (±60, ±30) N·m. In right-handed +z-up axes the support torque is (P_y, −P_x, 0), so P = (60, 30) with forces (160, 130, 110, 0) gives torque (30, −60, 0) N·m. **Reject a packet that passes (60, 30) directly as the torque.** The checker recomputes vertical force and both torque components, checks caps, validates convex coverage and checks the information available to the allocator. Mutations that must cause withdrawal: swapped foot ordering with unchanged forces, an unreported positive force floor, a passive authority tag.

**Minimum claims.** Give the incumbent cost and a checked matching lower bound. Strict feasible sets can have an unattained infimum: at ε = 5/16, repair by raising U needs U > ¾, with no smallest increase on a continuous catalog; return the open threshold, a feasible priced candidate and its gap. Report an unresolved set's probability mass only under a supplied weighting. *BASE:* WEAKER. `K-<name>.cert` binds an identity to a kernel hash (B§10.4); no certificate format for design or mission claims.

### 12.13 Prove a replacement improves a decision even when neither robot has a guarantee (A§18.13)

"Can replacing this sole cause a formerly successful delivery to fail?" For two fixed causal controllers define a *regression* as a shared world input where A succeeds and B fails. Build the **product of the two systems driven by the same exogenous scene, payload and clock law** and ask whether the terminal pair (1, 0) is reachable. Unreachability over an enclosure of every admitted joint execution proves dominance on the cell; a concrete paired trace reaching (1, 0) is a counterexample; an outer enclosure intersecting (1, 0) triggers witness search or unknown. Check joint coverage: the diagonal pairs (0, 0), (1, 1) project onto both full marginal outcome sets yet hide (1, 0) when internal branch choices vary independently. Couple only declared shared inputs.
- *Example:* surface parameter z ∈ [0, 1]; A completes when z ≥ 3/5, B when z ≥ 2/5. Neither is guaranteed, yet the replacement loses nothing and adds [2/5, 3/5) (gain 1/5 under a uniform law).
- **Compile shared inputs at physical coordinates:** two tires on different paths need not receive equal friction samples at corresponding ticks; use one space-indexed material field and each robot's actual contact point; shared latent lighting produces different residuals once cameras diverge.
- Emit both per-design absolute hard-limit verdicts and the paired verdict; a relative zero-loss assertion does not establish that either meets the mission.
- Challenger: a conventional reachability tool (Flow*) on the same product model.
*BASE:* WEAKER. `eval compare` pairs by world address and gives a statistical verdict (B§22.4). Pairing by address shares *seeds*, not space-indexed fields, which is exactly the trap ASTRA identifies.

### 12.14 How much must the factory tell a shared controller? (A§18.14)

Ask for the **minimum number of distinct calibration labels** that lets one controller serve all admitted variants and payloads by a commitment deadline. A late label has zero value for a committed decision.
- *Encoder premise:* if the factory measures an unknown build, require an encoder from available station records to tags. With records {left, shared} for A and {shared, right} for B and opposite required commands, both builds can yield `shared`, so no number of tags suffices.
- *Colouring algorithm:* for a fixed observation-identical prefix let K_s be the commands that work for every payload and tolerance of variant s. Variants can share a label exactly when their K_s have a common point. Build the hypergraph whose edges are inclusion-minimal collections with empty intersection; the least number of labels is the least number of colours with no monochromatic edge. A colouring plus one command per colour certifies the upper bound; impossibility with one fewer proves minimality. For convex sets in dimension m, Helly bounds a minimal obstruction by m + 1; hidden contact modes can make sets non-convex.
- *One label map across histories:* the factory commits before later history is known. With variants A, B, C and three readings requiring opposite bits for AB, BC, CA in turn, two labels suffice at each reading but a fixed map needs three.
- *Worked fixture:* commands (x, y) ∈ [0, 1]²; variants require x ≥ 2/3, y ≥ 2/3, x + y ≤ 1. Every pair intersects, the triple does not; two labels suffice ((2/3, 2/3) shared; (0, 0) for the third); one is impossible. **Pairwise compatibility alone would have authorized the wrong shared controller.** Z3 returned UNSAT for one label and SAT for two.
- With only inner and outer command sets, return lower and upper label counts and the one measurement that narrows the gap.
*Weakness:* ASTRA concedes "the set extraction from physical contact is the open research problem"; this idea drew the widest reviewer disagreement (380 versus 690) and its author withdrew any advantage over SMT.

### 12.15 Computing with symmetry at the instant of contact (A§18.15)

Symmetry saves work only while it commutes with events. For group element h, pre/post states x⁻, x⁺ and transversal event e with saltation S_e, a consistent relabelling must give **D h(x⁺)·S_e(x⁻) = S_{h·e}(h·x⁻)·D h(x⁻)**. Test: reflect a four-foot landing and exchange the left/right sole laws; transforming a one-sided perturbation before or after impact must predict the same change in tray roll and ankle load. Repeat with asymmetric payload, unequal packet latency, a grazing toe and two simultaneous contacts. A small guard-crossing speed makes the single-event saltation unreliable; a new event order makes the correspondence ambiguous (keep both continuations, split the class or run full owner trajectories). Even a passing check transports a *local* derivative to a corresponding event; block-reducing one nominal trajectory needs a symmetry fixing its state, history, parameters and event. A sliding impact and its mirror can obey the identity while a normal-speed perturbation changes tangential speed: keep that cross term. "A change of symmetry may itself locate the physical decision boundary."

**Monotone co-design as the system-level complement.** Compose component feasibility relations ordered by delivered function and resources (payload for a shift requires torque, electrical supply and heat rejection; battery adds mass that feeds back into torque). In the monotone fragment, compile the feedback as a least fixed point over resource antichains and compare against a conventional monotone co-design solver; state order, continuity, bounds and convergence. If gearing trades a larger static moment for a blocked swing or a new contact mode, keep separate cells or dispatch the original mechanics. "Do not force the plant into a monotone budget model." *BASE:* HAS the monotone co-design fixed point (C-12, A-10, T-12, GB-03) as a first-class analysis, stronger than ASTRA's mention. LACKS the commuting event identity (C-09/T-10 test step equivariance only on smooth kernels).

**13.2 Claim 1: engineering throughput (A§19.2).**
- *Clock:* starts when the engineer or agent receives the mission and permitted inputs; ends when an independent checker accepts the first correct answer with all requested scope and precision. - *Ceiling:* if the candidate misses a fraction q of deadlines, the ratio is at most 1/q; 12% unfinished caps it at 25/3 ≈ 8.33×.
- *Correctness gates:* a dangerously wrong accepted claim fails immediately; a correct `unknown` is a complete answer only where the question asks whether the evidence identifies the choice, and only with the required witness. "Never improve the time score by lowering the bar for what counts as accepted." Every submitted mathematical assertion is replayed by the independent exact checker; **one false certificate disqualifies that arm from the scoped claim**; a truthful unknown counts against coverage where a definitive answer is required.
- *Campaign:* four strata (body envelope; sensing/material; cross-body skill; facility redesign), each with 12 development missions and an initial 24 disjoint held-out mission families; final sample size fixed before opening the holdout by pilot dispersion and a power calculation. A shared family, site or material batch is a dependence link; "twenty-four rows sharing one site are one site replicate." Preregister the resampling unit, horizon and paired cluster interval.

For paired completion and useful coverage, simultaneous one-sided 95% lower bounds on candidate-minus-baseline differences above the negative of a prespecified non-inferiority margin. For rare binary failures use an interval valid at zero counts: zero events in 24 units still has a one-sided 95% upper bound of about 11.7%; a bootstrap of 24 zeros would report zero width.

Warm campaigns use predeclared edit sequences with identical reusable inputs and cache budgets; amortize one-time authoring over 1, 10 and 100 amendments; keep failed amendments in the sequence; report the **crossover reuse count**. Publish the fastest qualifying baseline, all arms and raw pairings; a per-case oracle ensemble is labelled as an extra lower bound.

**13.5 What the pilots already ruled out, and the kill rules (A§19.4).**
- *Pusher study.* Ten guarded one-axis plants, y = max(0, g·u − d). One query allows a command per known build gain; the other needs one command for the whole family. On g ∈ [½, 2], u ∈ [0, 2], d ∈ [0, ¼], required y ∈ [¾, 5/4], every design has an admissible command and no single command works for all: a **permanent quantifier-order regression for the public interface**. A guarded inverse and an exact robust projection both returned accepted sets on 20/20 queries; six negative mutations were rejected; independent Z3 found no discrepancy and caught a truncated region. Measured composed/specialized median ratio: **1.345× warm, 1.088× cold. The speed gate failed.** A follow-up measured about 576 µs of shared checking and serialization, roughly 94% of the specialized warm batch, so a zero-cost solver would have reached only about 1.46×. The bundle's audit goes further: raw-plant Z3 quantifier elimination produced the family answer directly for 8 of 12 queries, and the audit recommends that "future locks should compute this ceiling before execution and refuse a speed test whose ceiling is below 10×".
- *Kill rules.* (a) Time a real amended-mission workflow before writing a specialized CUDA or Metal family solver. (b) **If the unremovable cost already exceeds one tenth of the strongest baseline's time, a tenfold improvement requires changing another stage or changing the claim.** (c) "If the rival can obtain the same checking scope and similar turnaround from a short robust program, use it in the studio and spend the research budget on the first mission it cannot resolve." (d) One false reused verdict kills that reuse rule (Brenner report). (e) A matched reducer reaching the same witnessed answer at comparable cost kills the new-query or tenfold claim on that family.

Preserve the *joint* time-dependent bus contract.
- **Refutation logic.** A successful rollout against one disturbance cannot refute "every controller has some failing disturbance"; that needs one body and causal controller succeeding for every admitted disturbance. The pilot was restricted to *uniform failure* cells, where a single validated success disproves the certificate, with a preregistered 20% ceiling on the unresolved fraction under a declared measure.
