## Appendix F. Upstream asks

**The rule.** Sibling repositories are read-only to this program (§33.8, §37.8). A need is filed as a bead in the
sibling's own tracker (BD-037) and recorded in `registries/asks.toml` with five things: the request, a priority, the
interim posture here, the switch-over rule, and one reproducible failing fixture. No change to a sibling is ever
scheduled as a bead of this project, no milestone depends on an ask landing, and no local patch stands in for one. A
defect found in a sibling becomes an admission test here and an ask there, in that order: the admission test records
what the pinned commit does, and the ask describes what is wanted.

Asks are additive: a new mode, entry point or type, never a change to existing behaviour (DESIGN, following the rule
FrankenSim's own extension plans set for upstream work). The priority states the value of the ask to this project. It
is not a schedule and carries no expectation about when a sibling acts. The interim posture is what FrankenRobotics
does until the ask lands. The switch-over rule is what must be re-run when it does; a pin then advances through the
compatibility train of §33.8 (move the pin, write a new receipt, rerun the admission and parity gates, relock).

Third-party gaps are not asks. The `cudarc` bindings for graph capture and asynchronous pools (OPEN-SPARK-4) are
confirmed or refuted at INT-CUDA-01, and the annex binds the driver directly where a binding is missing.

Identifiers FD-FSIM-01 to -09, FD-FT-01 to -03, FD-FSYM-01 to -05, FD-FLN-01, -02 and FD-ASUP-01 keep their earlier
meaning. FD-FSIM-10 to -16, FD-FNP-01, FD-FSQL-01, FD-FMCP-01, FD-FTUI-01 and FD-FKER-01 are the asks of §33.8.
FD-FSIM-17 to -30, FD-FDGR-01 and FD-FSS-01 number the requests that subsystem chapters raised without a number.
FD-FSIM-31 to -33, FD-FTX-01 and FD-F3D-01 are the asks that follow from the coupling note of §33.12 and the
foundation facts of §33.17.

### H.1 Marks

| P | Read from the primary text: a PDF converted to text, a raw file at a release tag, or a raw documentation page |
| S | Reported through a summary: the page was read through a summarizing fetch tool, and quotes are short for that reason |
| F | Fetched during planning; the record does not say whether the text was raw or summarized. Treated as S |
| R | A search-engine summary only; the page was not opened |
| M | Recalled, not re-read |
| U | Cited with no mark recorded |

Where two records disagree the weaker mark is kept, except that a source re-read by the independent audits is P for
the figures those audits quote. Only P sources may be cited by a gate without a further reading; every other mark is
a reading task that the gate's bead performs first.

```rust
/// A Lie group with two retractions. Its laws are G0 property tests (§13.8), not comments.
pub trait LieGroup: Copy {
    type Algebra: LieAlgebra;
    const DIM: usize;
    fn identity() -> Self;
    fn compose(self, rhs: Self) -> Self;
    fn inverse(self) -> Self;
    fn exp(x: Self::Algebra) -> Self;              // deterministic elementary functions
    fn log(self) -> Self::Algebra;
    fn cay(x: Self::Algebra) -> Self;              // +, −, ×, ÷, √ only
    fn cay_inv(self) -> Self::Algebra;
    fn adjoint(self) -> <Self::Algebra as LieAlgebra>::Operator;   // Ad_g
}

pub trait LieAlgebra: Copy {
    type Dual: Copy;                               // 𝔤*: momenta, wrenches
    type Operator;                                 // linear maps on 𝔤
    fn bracket(self, rhs: Self) -> Self;
    fn ad(self) -> Self::Operator;
    fn coad(self, mu: Self::Dual) -> Self::Dual;   // ad*_x μ = (ad_x)ᵀ μ, no minus sign (§11.2)
    fn pair(self, mu: Self::Dual) -> Power;        // ⟨μ, x⟩, in watts
}

/// A joint: a product of one-parameter subgroups of SE(3) given by a screw basis (C-01, T-11).
pub struct JointSubgroup { class: HerveClass, screws: ScrewBasis, closed_under_bracket: bool }

/// `a_from_b`. Composition type-checks: Transform<A,B> * Transform<B,C> = Transform<A,C>.
pub struct Transform<A: Frame, B: Frame> { motor: fs_ga::Se3, _frames: PhantomData<(A, B)> }
pub struct TwistIn<F: Frame>  { xi: fs_ga::Twist,  _f: PhantomData<F> }
pub struct WrenchIn<F: Frame> { w:  fs_ga::Wrench, _f: PhantomData<F> }

/// Three maps, three types, so a wrench is never moved by the twist map (§11.2, §13.3).
pub struct TwistMap<A: Frame, B: Frame>(Transform<A, B>);          // Ad_g: a twist in b to a twist in a
pub struct WrenchPushforward<A: Frame, B: Frame>(Transform<A, B>); // Ad_g⁻ᵀ: a wrench in b to a wrench in a
pub struct WrenchPullback<A: Frame, B: Frame>(Transform<A, B>);    // Ad_gᵀ: a wrench in a to a wrench in b

/// A symmetric cone, by its Jordan algebra. Instances: the nonnegative orthant, the three-dimensional
/// friction cone, and the four-dimensional cone (normal, two tangential, spin) of §18.
pub trait Cone {
    type Point;
    fn jordan(a: &Self::Point, b: &Self::Point) -> Self::Point;
    fn spectral(a: &Self::Point) -> Spectrum;
    fn project(a: &Self::Point) -> Self::Point;    // T-07: P(x) ∈ 𝒦, P(x) − x ∈ 𝒦*, ⟨P(x), P(x) − x⟩ = 0
    fn barrier(a: &Self::Point) -> f64;
}

/// A convex contact potential whose negative gradient is the impulse (C-06).
pub trait ContactLaw { fn potential(&self, vc: ContactVelocity, p: &InterfaceCard) -> ConvexTerm; }

/// What a free tree limb presents to its parent at a mechanical port, at one instant (§14.6).
/// Positive semidefinite, never guaranteed definite: it cannot be inverted at the port.
pub struct LimbPortPacket { inertia: SymPsd6, bias: WrenchIn<PortFrame> }
```

### I.2 The claim product and evidence

```rust
/// The four evidence classes of §12. Combination takes the minimum.
pub enum EvidenceClass { Estimated, Tested, Certified, Proved }   // Ord: Estimated < Tested < Certified < Proved

/// Exactly one of the seven claims of §8.
pub enum ClaimKind { Proof, KnownAnswer, Parity, Fidelity, DesignComparison, Reality, Performance }

/// A typed leaf: evidence for one claim kind K. Its class is set only by the checker that produced it,
/// and no constructor of Evidence<Proof> exists outside frob-lemma (GATE-LEMMA-06).
pub struct Evidence<K> {
    class: EvidenceClass,             // private
    scope: Scope,                     // model, tier, domain, quantifier prefix
    assumptions: AssumptionSet,       // each with its polarity (C-18)
    receipts: Vec<ReceiptId>,         // certificate hashes, checker identities, study receipts
    flags: NoAuthorization,
    kind: PhantomData<K>,
}

/// What a result asserts, how strongly, about what, and that it authorizes nothing. Owned by frob-core;
/// carried in every output envelope (§32) and read from every bundle by frob-verify (§12).
pub struct ClaimProduct {
    kind: ClaimKind,
    class: EvidenceClass,             // minimum over inputs; no setter
    weakest: InputRef,                // the input that set the class: content hash and field path
    scope: Scope,                     // design family, world family, quantifier order, horizon, validity region
    tier: Tier,                       // lowest physics tier among the inputs
    determinism: DetClass,            // weakest of D0..D4 among the inputs
    reality: RealityScope,            // NoClaim, or the calibrated family a band was issued for
    conditions: FlagSet,              // union over inputs: tier-sensitive, controller-sensitive, model-conditional
    inputs: Vec<InputRef>,            // every consumed artifact, each with its own claim product
    authorization: NoAuthorization,
}

impl ClaimProduct {
    /// The only way to build a product from parts. Class, tier and determinism take the weakest; scope takes

}
```

```rust
    /// Admit iff T_ub + E_drive + E_ext + E_stored + E_reserve ≤ W_abs, as integers at the declared scale.
    pub fn admits(&self, speed_reading: Qty) -> bool;
    /// (W_abs − T_ub − E_ext − E_stored − E_reserve) / P_max.
    pub fn longest_cutoff_delay(&self, speed_reading: Qty) -> Qty;

/// A runtime shield: a stage of the environment after the policy and before the actuators (§22.12).

    rows: Vec<BarrierRow>,             // written on a template of 2 to 12 states
```

## Appendix J. Verb registry

The registry is `registries/verbs.toml`, owned by `frob-verbs`. The CLI, the daemon protocol, the MCP tool
definitions, the schemas, the refusal table and `robot-docs` are generated from it, so the surfaces cannot drift
(GATE-TETHER-02 diffs the served `tools/list` against it). Kinds: `read` returns stored or cheaply computed facts and
changes nothing; `run` spends compute, takes an idempotency key and a budget, accepts the bounded synchronous wait
(`sync_wait_ms`) and otherwise returns a job handle with exit code 8; `mutate` creates or changes a named object in the
caller's namespace and takes an idempotency key and an expected parent; `admin` cancels, stops, evicts or deletes and
needs a capability scope.

### J.1 One entry

```toml
[[verb]]
name = "design.check"
cluster = "design"
kind = "read"
tier = "S"
capabilities = ["design:read"]
input_schema = "frob.design.check.in/1"
output_schema = "frob.design.check.out/1"
refusals = ["FROB-REF-101", "FROB-REF-104", "FROB-REF-107", "FROB-REF-110"]
idempotent = true
cost_model = "static: under 2 s for template-sized designs"
first_milestone = "M1"
task_clusters = ["author", "places"]
examples = ["frob design check quad-a --json"]
```

A `run` verb adds its per-surface wait default (wait to completion on the CLI; 5,000 ms on MCP, at most 30,000). No
verb has a second spelling (J.4). The MCP tool name is the verb name with `.` and `-` replaced by `_`
(`telemetry.inspect-pixel` becomes `telemetry_inspect_pixel`); no registry name contains an underscore, and a lint
checks that the map is one-to-one (§32.12.3).

static stability, the baseline controller, every rollout and every whole-robot certificate.

**The answer by hand.** Order the feet [++, +−, −+, −−] at (±1/u, ±1/v). With α = P_x·u/4 and β = P_y·v/4, every
allocation that balances force and both moments is

  f = (W/4 + α + β + t,  W/4 + α − β − t,  W/4 − α + β − t,  W/4 − α − β + t)

for one free scalar t. At the vertex P = (16, 12) N·m, W/4 = 40 N, α = 20 N and β = 3v N, so
f = (60 + 3v + t, 60 − 3v − t, 20 + 3v − t, 20 − 3v + t). The last foot cannot pull: f₋₋ ≥ 0 forces t ≥ 3v − 20, and
then f₊₊ ≥ 40 + 6v. Both `rating` and `knee-hold` bound f₊₊ from above, by 88 N and by r·τ_c/λ = 40·r N. Taking
t = 3v − 20 gives f = (40 + 6v, 80 − 6v, 40, 0), which is the witness family, affine in v. The same holds at the other
three vertices by the two mirrors. Hence:

  a design (v, r) is feasible  ⟺  40 + 6v ≤ min(88, 40·r)  ⟺  v ≤ 8 and r ≥ 1 + 3v/20.

The narrowest feasible body has v = 8, a half-width of 1/8 m, and needs r ≥ 11/5. At v = 8, r = 11/5 and P = (16, 12)
the forces are (88, 32, 40, 0) N: they sum to 160 N, give Σ xᵢ·fᵢ = (1/5)·(88 + 32 − 40 − 0) = 16 N·m and
Σ yᵢ·fᵢ = (1/8)·(88 − 32 + 40 − 0) = 12 N·m, and the knee torque is (1/10)·88 = 8.8 N·m against 2.2·4 = 8.8 N·m. In
right-handed axes with +z upward the support torque is Σ rᵢ × (0, 0, fᵢ) = (P_y, −P_x, 0) = (12, −16, 0) N·m; a packet
that passes (16, 12) directly as the torque must be rejected. The exclusion has a dual witness: with y = (0, ½, ½) on
the three balance equations, yᵀA = (1, 0, 0, −1), so f₊₊ − f₋₋ = 40 + 6v on every balanced allocation, while
f₊₊ − f₋₋ ≤ min(88, 40·r) on every admissible one.

What the session shows, as rules and not as illustrations.

1. **Seven tools at a time.** The agent changes focus eight times and never sees more than seven task tools and three
   base tools. Focus changes what is listed, not what is permitted: the token's scopes are fixed at the first call.
2. **Inner and outer sets are different answers.** The inner set holds the cells with a constructive witness; the
