# Codex review of the Claude Code and AGY idea slates

2026-11-21 · FrankenRobotics plan v0.2 · 60 ideas scored

## Judgment

**Fund the matched decision benchmark, paired referee estimation, and checked search over discrete part catalogs first.** Pilot bounded interventions, ragged cohorts, and a single-link synthesis loop separately. Those bets remove identifiable work or produce decisions the agent can act on. They are testable before committing to a universal controller or a single cross-platform kernel that everything else needs.

The strongest detailed proposal is **CC #4, paired multilevel estimation (891)**. It attacks an expense the product’s evidence promise creates and can be falsified by replaying paired values before building its scheduler. The strongest AGY idea is **#10, Pareto antichains over part catalogs (854)**, from outside its top five. Among AGY’s detailed proposals, **#4, the structural link loop (805)** has the clearest distinctive output, as a bounded finalist lane.

### Scoring and comparison

I score the proposals as submitted, including their dependencies, acceptance criteria and claims. I give credit for a narrower fallback where it preserves meaningful user value. Practical design leverage, differentiation from a strong incumbent, feasibility on the stated hardware, and evidence and maintenance burden all affect the score. A 900+ item is ready to anchor the program or justify a tightly scoped prototype. 800–899 means a first-priority bet with a named uncertainty. 650–799 means prototype a bounded version or stage behind prerequisites. 400–649 means retain a mechanism or defer the package. Below 400 means cut it from this program in its proposed form.

A 10× verdict distinguishes a plausible contributor to tenfold **time from brief to accepted design and controller** from a stage-local speedup or a benchmark that makes the outcome measurable. Compare matched held-out tasks, hardware, quality, fallbacks and error budgets. Give the incumbent native batching, warm starts or MPC, and the same independent adjudication where supported. Include setup, failed or unresolved briefs, CPU and GPU time, compile/cache misses, and amortized campaigns. Report fabrication readiness separately because it changes the acceptance contract. The scores are source-grounded judgments. The throughput and latency arithmetic below is derived from the proposals’ assumptions.

## Claude Code · detailed proposals

### CC #1 · Ragged simulation cohorts · 817/1000

**Assessment.** Make per-world model identity and bounded execution shapes architectural decisions now. Model tables indexed by immutable slot generations, fixed depth schedules, and topology buckets put the cost where it belongs. A failed throughput bet still gives a usable same-topology cohort. Splitting model and world identity also lets the same design compete on multiple common scenes with a small number of replicates. C-01’s screw bases help share arithmetic, although the compiler still needs correct coordinate maps, order and derivatives for product joints.

For proof, compare 1, 4, 16 and 32 simultaneous replicas per design against exact-topology caching, tuned homogeneous launch graphs, and Newton’s supported heterogeneous paths. Use mixed legged and wheel workloads with the same contact and observation requirements. Score distinct candidates evaluated per second, including compile and refill, with the same downstream qualification. Weight bucket waste by actual contact factorization cost. Preserve logical seed and replay identity across refill, device migration and slot reuse. The slate’s worked 25 designs/s is a **homogeneous ceiling** of 2M/80,000. Its own 0.6× ragged target gives 15 designs/s before policy, uploads and adjudication. Newton already groups articulated entities by world and supports some heterogeneous workloads and device-side shape variants. MJX recompiles when structural NumPy fields change and batches runtime array fields. [Newton worlds](https://newton-physics.github.io/newton/latest/concepts/worlds.html) · [MJX model layout](https://mujoco.readthedocs.io/en/stable/mjx.html)

**10× / strongest objection.** Yes, as infrastructure for broad searches with few replicas per candidate. Padded dense solves and contact divergence can erase utilization gains, while tuned Newton and shape-bucketed baseline runs shrink the denominator.

### CC #2 · Sampling MPC inside each design’s batch · 739/1000

**Assessment.** Prototype this as a day-one controller option and possible teacher. The separation of planner and execution configurations is valuable. Its own-model planner makes failed trials interpretable, and the specified coarse horizon gives a real compute lever. DIAL-MPC demonstrates full-order sampling for a real quadruped and simulated humanoid examples. It supplies an incumbent implementation as well as motivation. Start with the same two or three morphology families, share task costs and state information, and compare against the native implementation and model-based synthesis. Test novel contact sequences and held-out task geometries. Measure per-family rank reversals near the selection cutoff, after charging solver calls and compile time. A 5 m flat-ground pass is a useful smoke gate.

The slate budgets about 512,000 planning substeps per simulated world-second. At 5M matched planning steps/s that is about 0.102 GPU-seconds per world-second before other work. Saturation, scope-equivalent costs and reliable progress on a novel body all need measurement. The torque and contact model in the slower tier can also change which actions the same planner selects. Be explicit about comparing frozen control on both tiers versus replanning separately for each model. [DIAL-MPC paper and demonstrations](https://lecar-lab.github.io/dial-mpc/)

**10× / strongest objection.** Conditional as a controller option within a larger loop. A strong incumbent can already run DIAL-MPC, and a fixed-horizon planner with finite samples can rank easy-to-plan designs above better embodiments.

### CC #3 · Family policy taught by MPC · 724/1000

**Assessment.** Shared role-local policies with a typed edit map could turn a series of sibling designs into a single learning problem. The value is rapid candidate triage, preferably with per-family acceptance and abstention, then independent confirmation. GENBOT supports the cross-embodiment premise and makes this a competitive area. Its training evidence comes from a different teacher and embodiment distribution. Swap in one measured specialist and one MPC teacher for a narrow edit family before paying for DAgger across thousands of bodies. Include failures that the student visits but the teacher cannot rescue. Run parent-checkpoint, modular-transfer and no-training baselines with matched access to data. Charge amortization against a competing trained family policy as well as against MPC. [Embodiment scaling paper](https://arxiv.org/html/2505.05753v1) · [Shared modular policies](https://proceedings.mlr.press/v119/huang20d.html)

Tying weights by orbit and sharing a message-passing architecture gives permutation structure under corresponding transformations of graph inputs and outputs. It leaves rotations, reflections, signs and action transforms to be checked. Raw parent IDs as positional features can break even relabeling symmetry. For selection, whole-corpus Kendall τ can hide wrong rankings among the strongest few designs. Measure top-k recall and regret on unseen edit and morphology classes. Preserve candidate merit and controller qualification as separate observations and retain cases sent to specialist training in the time denominator.

**10× / strongest objection.** Yes for repeated, in-distribution evaluation campaigns if teachers and transfer work after amortization. Shared controller error can systematically discard superior designs, and a high global rank correlation can conceal that failure at the selection boundary.

### CC #4 · Paired multilevel referee estimation · 891/1000

**Assessment.** This is the best immediate leverage bet. The proposal identifies a quantity the project pays to estimate, a real variance-reduction mechanism, and existing `fs-uq` allocation and execution code. Start with two levels against paired referee-only racing and a two-level control variate with a frozen or predictably fitted coefficient. Add the intermediate CPU tier only when its measured residual variance and cost improve interval width per core-second. Measure each pair’s *design contrast*, including binary failures and a bounded energy-per-distance score with a declared rule for stalled episodes. Run the protocol on held-out difficult scenarios and near ties. The agent should see the confidence interval, effective cost and unresolved side of the decision. [Giles, Multilevel Monte Carlo methods](https://people.maths.ox.ac.uk/gilesm/files/na_15.pdf)

The scalar shortcut needs correction. At ρ = 0.95, a two-level control variate with a sufficiently precise cheap mean and the optimal coefficient leaves `1 − ρ² = 0.0975` of the expensive outcome variance. The proposed unit-coefficient correction has variance `σH² + σL² − 2ρσHσL`. Correlation can be high and that correction can still be expensive. Neither ratio is an anytime-valid wall-clock forecast. Include costs of the cheap path, pilots, bounded or conditionally sub-Gaussian sequence assumptions, and the treatment of multiple searched challengers. Use shared randomness for each coupled pair and a declared sampling law. A 1 s segment from a GPU state measures a conditional segment discrepancy. Keep it out of a full-episode promotion calculation unless the product explicitly proves a valid reconstruction. A referee outcome also remains a simulator outcome.

**10× / strongest objection.** Yes, directly on referee cost for decisions with small paired residuals. Close design contrasts, rare failures and contact-regime reversals can make residuals too large even when absolute episode metrics look strongly correlated.

### CC #5 · Counterfactual failure probes · 841/1000

**Assessment.** The strongest agent-facing idea in CC’s detailed slate. A short paired replay tells an agent which experiment to try next, then independent full-run comparisons decide permanent edits. Preserve that reporting boundary. Start with explicit temporary changes to a driver cap, a friction card or a command. Include an unchanged replay control, a true planted defect, a downstream symptom and an edit that cannot reuse the prefix. Give an incumbent checkpoint/restore and the same candidate interventions and racing budget. Measure top-three repair recall and resolved time to repair, including the full confirmation. Use uncertainty and absolute opportunity payoffs before adding the coalition analysis. Exact Shapley computation over a finite experiment grid assigns credit under its chosen value function and candidate set. Unique physical attribution requires additional assumptions and interventions. [MuJoCo reproducibility and warm-start state](https://mujoco.readthedocs.io/en/stable/computation.html)

A changed body state needs an admissibility check even when joint coordinates match. Regearing changes reflected inertia, power and internal motor coordinates. A shifted mount can turn a valid foot placement into penetration. Each transport needs its own validation beyond unchanged-control replay. Favor temporary interventions, rebuild derived and incompatible solver or controller state, and send global edits through a reset. The 10,240-branch example assumes cheap control. Active sampling MPC inside every branch can dominate diagnostic cost.

**10× / strongest objection.** Plausible on late failures with many admissible repairs, especially in agent turns. Mid-run rescue is conditional on a state the edited robot might never reach, so it can rank permanent edits in the wrong order.

## AGY · detailed proposals

### AGY #1 · Whole-robot SRAM kernel and symbolic sparse solve · 521/1000

**Assessment.** Prototype localized fusion and measure a structure-aware solver on the same numerical step. Keep the heterogeneous model-table contract independent, as in CC #1. On-chip residency for a small fixed robot is a credible experiment. A byte count is only a capacity sketch. Live ranges, spilling, instruction cache, synchronization, contact searches, scene field traffic and actual warp residency determine throughput. On Ada, 100 KB per SM and up to 99 KB per block coexist with register limits and a 48-warp ceiling. For example, eight 5.6 KB worlds use roughly 45 KB for an eight-warp block before extra scratch, so the SRAM envelope alone permits at most two such blocks per SM. That is at most 16 of 48 warps for that mapping before registers. Read the Metal limit from the device and profile real shader occupancy. The suite’s piano example is a contact-free persistent kernel with an all-blocks-resident constraint. It demonstrates a dialect and synchronization pattern. Articulated collision, contacts and nested sampling have different resource limits. [NVIDIA Ada tuning guide](https://docs.nvidia.com/cuda/ada-tuning-guide/index.html) · [Apple threadgroup memory API](https://developer.apple.com/documentation/metal/mtldevice/maxthreadgroupmemorylength) · [Piano kernel](../../../../frankensim/apps/instrument-lab/render-gpu-piano/src/kernel.h)

Tree sparsity can pay for tree-local contacts. Cross-branch self-contact, loop closures and moving fixtures insert extra Jacobian support and can create fill. Count realistic worst cases and charge dense fallback, including whether a shared-memory allocation for that fallback depresses occupancy for every world. Specialization by `TopologyId` also means a new arbitrary topology needs recompilation or a generic path. Optional parts under one finite supergraph demonstrate compile reuse within that supergraph. The proposed 200 KB of global traffic per substep is a profiling hypothesis. Compare a fused collision/solve or solve/integration block against a tuned unfused baseline with launch graphs, identical solver tolerances, mixed scenes and realistic contact tails. Obtain one measured Pareto improvement before making M2 control and debugging depend on this.

**10× / strongest objection.** Stage-local potential in a narrow kernel regime. The 20–30M figure rests on an unprofiled traffic model and a residency estimate that omits the same topology, contact and scratch variation it promises to absorb.

### AGY #2 · IFT contact adjoints · 665/1000

**Assessment.** Keep a fixed-regime derivative pilot. For a smooth residual with a nonsingular converged Hessian, a transpose solve and residual pullback are the right computation. It can give agents valuable local margin sensitivity across dozens of parameters, which is a stronger first consumer than SHAC. The final Newton factor may be at the *previous* iterate. A fixed four-iteration step with line search and warm start may not have converged. Its derivative generally differs from the exact-root implicit derivative. Require a residual and conditioning check and recompute or reuse a factor at the right point. Every checkpoint recomputation and residual pullback belongs in the cost. Stored factors, antithetic evaluations and mode changes can dominate the advertised triangular solve.

Backward-only regularization is a surrogate gradient. Name its target, and verify a proposed step’s actual held-out improvement. For isolated transverse events, FrankenSim’s `fs-time::hybrid_sensitivity` helps with event time and reset derivatives, with explicit refusals for competing or changing sequences. `fs-adjoint::ift` uses a matrix-free transpose solve and supplies a useful pattern. The GPU articulated residual and its pullback are new. Dojo already uses implicit differentiation for contact, and Open-DiffLoco reports SHAC quadruped results on MJX. Compare the planned IFT path against these precedents where applicable, paired finite-difference or SPSA baselines, and MJX-JAX AD. Keep the evaluation local until contact changes, geometry gradients and switched control are validated. The pseudo-inertia cone preserves the admitted mass-moment property. It leaves mount geometry and manufacturability to other constraints. [Dojo](https://arxiv.org/abs/2203.00806) · [SHAC](https://arxiv.org/abs/2204.07137) · [Open-DiffLoco](https://arxiv.org/abs/2608.02069) · [FrankenSim hybrid sensitivity](../../../../frankensim/crates/fs-time/src/hybrid_sensitivity.rs) · [FrankenSim IFT source](../../../../frankensim/crates/fs-adjoint/src/ift.rs)

**10× / strongest objection.** Plausible for accepted local continuous design steps with many parameters. Most useful directions in contact-rich design may change contact regimes, where a cheap derivative of a converged smooth surrogate is a poor guide to the realized finite-step outcome.

### AGY #3 · Universal full-order GPU DIAL-MPC and IFT shooting · 429/1000

**Assessment.** The 512-total-trajectory example uses 102,400 planning steps per tick, or 51.2M per 10 s controlled episode. At the proposal’s unmeasured 25M steps/s that is 2.048 s for one episode, before reductions, the second round’s synchronization, execution physics, IFT, sensing or input movement. Sixteen such episodes consume 819.2M steps and take at least **32.768 s for that batch** under the same optimistic throughput assumption. About 2.05 s is the amortized cost per episode. Neither instantaneous occupancy nor one dispatch removes the work. A 20 ms real-time tick for all 16 would require 81.92M planning steps/s before additional work. If the two annealing rounds select the next distribution using a global reduction over candidate blocks, they require a safe grid rendezvous or separate launches. Requiring full-resolution dynamics in every planner sample discards a credible cost lever.

DIAL-MPC is evidence for tested embodiments and tasks. Novel hybrid modes, actuator and contact discontinuities, wide action spaces and long maneuvers change proposal quality. Use CC #2’s cheaper planning configuration with a class prior where it helps, stable diagnostics, and an independent evaluation with native DIAL-MPC. Set the target to time to a reliable screen under a fixed decision budget. Keep IFT polishing an independently measured option. [DIAL-MPC](https://lecar-lab.github.io/dial-mpc/)

**10× / strongest objection.** Unlikely as proposed. Full-resolution nested rollouts consume an enormous fixed workload, and both performance and ranking claims depend on #1’s unmeasured speed and a universal sampling assumption.

### AGY #4 · Dynamics-to-structural-link synthesis and GD&T · 805/1000

**Assessment.** The most distinctive AGY feature. Ship a narrow finalist workflow that takes typed mounting faces, a few scoped multiaxial load histories, a documented material and process, and returns a sized solid, independent verification and revised inertias. The result gives an agent a real tradeoff among mass, stiffness and task margin. The sibling source backs an SDF topology optimization lane, structural/fatigue methods, process rules, statistical tolerance allocation and faceted STEP. End-to-end process qualification remains separate work. Use a conservative hollow-section link baseline, a permanent mounting/bearing region and an independent mesh and stress test. After updating inertia and geometry, rerun the task, regenerate loads, and check for loosened margins or non-convergence. Asymmetric payloads can break equal loading among nominally symmetric links. Transform and union relevant load histories before merging any problems.

A port wrench needs a mechanically defensible load distribution at the actual connection. Peaks assembled from different times are not a fatigue spectrum. Impacts, bolted interfaces, buckling, load transfer and process variability can govern real yield. `fs-toleralloc::allocate` optimizes against a variance budget and declared sensitivities. Worst-case motion and assembled fit under switched contacts require separate analysis. Require a separately valid tolerance stack check, and scope any result to design verification under named loads and process assumptions. Faceted STEP round-trip is interchange evidence. Time the loop against scripted CAD/FEA and beam sizing at equal constraints. The original MOR excludes physical robots, so full build readiness belongs in a separately scored output class. [3-D topology optimization source](../../../../frankensim/crates/fs-topopt/src/sdf3.rs) · [Fatigue source](../../../../frankensim/crates/fs-solid/src/fatigue.rs) · [Tolerance allocator](../../../../frankensim/crates/fs-toleralloc/src/lib.rs) · [Faceted STEP source](../../../../frankensim/crates/fs-io/src/step_faceted_export.rs)

**10× / strongest objection.** Yes for a new bounded structural iteration workflow, conditional on beating competent CAD/FEA automation. Load history, interface stress and production tolerance validity are the hard integration work, and module availability or a sealed file cannot establish fabrication readiness.

### AGY #5 · 50 ms causal proof and automatic exploit quarantine · 442/1000

**Assessment.** Preserve unchanged replay controls, scoped intervention receipts, and provisional numerical sensitivity flags. Follow CC #5’s full-run handoff. The stated statistic, survival under an intervention conditional on the selected failures, measures rescue effectiveness in those simulator states. Two individually effective fixes can mask the same upstream defect, while two jointly needed fixes can look unimportant alone. CRN can reduce variance. It leaves scenario uncertainty and selection effects in place. Changing foot radius or inertias may require contact projection and resetting dependent state. Changing step size also changes controller and sensor scheduling, warm starts, and what it means to couple a disturbance stream across time. Bind disturbances to physical time or explicitly coupled increments. A mutated state needs an independent admissibility check even when unchanged replay is bit-identical. An h/2 reversal is a sensitivity observation. An authoritative contact or policy decision requires separate evidence.

The 307,200-step arithmetic gives 12.3 ms of physics at the conjectured 25M steps/s. It excludes half-step extras, copy and dispatch costs, adaptive control, second bursts and adjudication. The nominal CPU referee at 0.2× real time requires about six core-seconds for **one** 1.2 s branch. Unified memory can reduce copies and still leaves that solve on the critical path if synchronous. Separate the latency of a user-invoked diagnostic from the time to a referee-backed result. Compare both against cached, checkpointed incumbent interventions. [MuJoCo snapshot limits](https://mujoco.readthedocs.io/en/stable/computation.html) · [Genesis parallel evaluation and training](https://genesis-world.readthedocs.io/en/latest/user_guide/policy_training/multi_gpu.html)

**10× / strongest objection.** Possible for selected diagnostic latency, unsupported for the proposed causal certainty or exploit assurance. A deterministic branch from a selected failing state can produce a real rescue and a wrong diagnosis at the same time.

## What survives the comparison

1. **Measure decisions before optimizing phases.** CC #25 is the load-bearing experiment. The two strong pipeline baselines should include competitive topology/co-design search, tuned control, native batched variants and cached replay, followed by common adjudication. An internal referee-only claim can be reported alongside it. Avoid multiplying phase speedups. They often remove the same work, and shared phases still bound total time. [Co-design Gym](https://arxiv.org/abs/2610.02366) · [MuJoCo Playground](https://arxiv.org/abs/2502.08844) · [Isaac Lab multi-asset workflow](https://isaac-sim.github.io/IsaacLab/main/source/how-to/multi_asset_spawning.html)
2. **Spend the first implementation effort on reversible wedges.** Pair full-episode referee contrasts, compile one small catalog with independently checked bounds, and make model slot identity and replay semantics stable. Use these to tell whether heterogeneous batches, transferred control or estimator allocation actually eliminate the expensive work.
3. **Promote narrow mechanism wins in isolation.** Keep stage fusion, fixed-regime sensitivities, class-scoped MPC, structural finalists and late-failure probes on separate gates. If one fails, keep the plan’s existing reference and fallback lanes available. The portfolio has a credible route to a 10× decision benchmark once those costs and qualification rates are measured.
