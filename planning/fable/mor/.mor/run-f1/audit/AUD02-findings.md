# AUD02 findings: rival capabilities, hardware envelopes, transferable mechanisms, rejections

Run `f1`. Audit written 2026-11-22T01:11:21Z. Auditor: independent, no part in writing the claims.

Batch: the four index groups hold 58 claims. 40 were audited, chosen for how much they would change the plan; 18 stay AUDIT_PENDING and are listed below. Machine-readable records: `AUD02-rival-hardware-transfer.jsonl` in this directory.

## How the checks were done

- Incumbent claims were checked in the incumbents' own files at release tags, fetched raw and searched for the quoted sentence: MuJoCo and MuJoCo Warp 4.0.1 (PyPI, 2026-11-11), Newton 1.8.0 (changelog date 2026-11-12), Warp 1.19.0, Isaac Lab 3.0.0 (PyPI, 2026-10-19), Isaac Sim 6.2.0 documentation, Genesis 1.4.7, Drake 1.58.0, ManiSkill 3.0.1. No summarizing fetch stands between a quote in the records and its source, except where a record says so.
- Papers were read as PDF text or as the arXiv abstract page; each record says which.
- Arithmetic was redone from the stated inputs.
- Nothing was run on an incumbent simulator. The only executions were a Metal device query on this Mac and the arithmetic. A capability 'documented' here is documented, not demonstrated.
- Where a search found nothing, the record says absence of evidence. It is not evidence that an incumbent lacks the feature.

## Differentiators the plan may still claim, and exactly how to word them

Each wording is the most the audited evidence supports. Conditions in brackets must appear with the claim until the named gate has passed.

1. **CPU replay of a GPU world (GOAL-10; C018, C020).** 'Any world can be re-run alone on the CPU from its address. Where a device reaches determinism class D1, the CPU run matches the GPU run bit for bit. Incumbents document bitwise replay only for the same batch on the same GPU.' [Hypothesis until GATE-SPARK-01 and GATE-SPARK-02 pass; add a test that a world's trajectory does not depend on the batch it ran in.]
2. **Derived kernels with a disagreement record (N1; C026).** 'Kernel arithmetic is derived once and emitted for a CPU reference, CUDA and Metal, and the measured cross-backend disagreement is stored per kernel. Compiling one kernel source for several backends is prior art (Warp, Genesis).'
3. **Kernel certificates (N5, GOAL-17; C023).** 'Named kernels carry offline-checkable certificates of algebraic identities. We found no incumbent engine that does this. The certificates say nothing about floating-point results.' [Value unproven until BET-11.]
4. **Promotion discipline (N3; C027).** 'A fast-tier result stays provisional until it has been re-evaluated on a higher tier and the difference recorded. Engines with several solvers or back ends exist; we found none with a promotion rule.'
5. **Static analyses as verbs (N2, BET-05; C029).** 'The first shipped suite of pre-simulation design analyses callable by an agent. Nothing in an incumbent's engine prevents it from adding them.'
6. **Synthesized baseline controller (GOAL-13; C032).** 'A controller is synthesized from the model in seconds for each morphology class, with no per-robot cost tuning.' [Conditional on BET-06.] Do not say 'no training needed'.
7. **Energy ledger (GOAL-11; C030).** 'A per-actuator and per-contact energy balance that closes to a stated residual. Incumbents expose the inputs; MuJoCo documents that it does not account for constraint energy.' [Only once the residual is measured.]
8. **Agent surface (GOAL-18; C034).** 'Every verb carries a compute budget, provenance and a typed refusal.' MCP access to a simulator is prior art.
9. **Paired design comparison (N4, GOAL-15; C028).** 'Published anytime-valid tests, applied to paired design comparisons on common world addresses.' Cite arXiv 2603.13616 and arXiv 2503.10966.
10. **Metal tier (BET-09; C024, C065).** 'Measured quadruped throughput on an M5 Ultra, reported against Genesis on Metal on the same machine and against one RTX 4090.' A number, not a first.
11. **Mixed-topology batches (C019, C022, C048).** Only as two measured numbers against Newton with Kamino or Steel on trj: distinct designs times steps per second, and time from an edit to the first GPU step. Kamino's published 86 k samples/s for a mixed Ant batch is the baseline to beat.
12. **Scenes (GOAL-06; C033).** 'Seven interior archetypes from one grammar system, including manufacturing plants and commercial kitchens, for which we found no generator.'
13. **The composition (C025).** 'One design identity and one evidence ledger across static analysis, simulation tiers, statistics and solid mechanics.' A hypothesis whose only test is the end-to-end benchmark against a composed incumbent baseline.

## Differentiators the plan must withdraw

1. **Deterministic GPU replay as such.** Newton 1.8.0 and Isaac Lab 3.0.0 on PhysX document opt-in bitwise run-to-run determinism (C018). The section 1.1 sentence 'A world that fails on the GPU cannot be replayed anywhere else' does not describe them.
2. **'The CPU version is a different code base' (section 1.1, GPU row).** Warp compiles one kernel source for CPU and CUDA, and MuJoCo Warp runs on its CPU device (C026).
3. **Different robot topologies in one GPU batch, as a capability.** ManiSkill 3.0.1 and two Newton 1.8.0 solvers document it (C019).
4. **The combination of mixed topologies, determinism and articulated contact, as an incumbent gap.** Newton's SolverSteel documents all three (C021, rejected).
5. **Electrical and thermal actuator modelling (GOAL-12).** MuJoCo's dcmotor has it on CPU and, in MuJoCo Warp 4.0.1, on GPU (C031). Parity, not novelty.
6. **'No training needed' for baseline control.** Sampling MPC already does this for incumbents, on a CPU with about 30 samples (C032).
7. **Anytime-valid comparison as a novelty of the field (N4 as worded).** Published for robot policy comparison (C028).
8. **One kernel source for several backends (the implied part of N1) and simulation on several tiers (the implied part of N3).** Both are prior art (C026, C027).
9. **Apple-GPU support as a first.** Genesis 1.4.7 lowers kernels to Metal (C024).
10. **Interior scenes for homes, kitchens, retail stores and warehouses as a novelty.** Generators or builders exist for all four (C033).
11. **An agent interface to a simulator as such.** Isaac Sim ships one for lookup and a community server drives the simulator (C034).
12. **Section 28.1's context note and humanoid target.** 'No absolute RTX 4090 figure for the leading GPU simulators was found' should be replaced by MuJoCo Warp's nightly figures (2.55 M G1 steps/s at 8,192 worlds on an RTX 6000 Ada), against which 'at least 500 k' is not parity (C064, C092).
13. **Any tenfold claim resting on per-step throughput, on sampling control as the evaluator, or on a published tenfold in time to a qualified design.** None is supported (C057, C064, C086, C092, C041).
